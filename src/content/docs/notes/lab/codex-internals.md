> Codex CLI 0.163.0의 세션 기록(`~/.codex/sessions/*.jsonl`)을 분석하고, `gpt-6-luna`로 원샷 실험을 한 번 돌려 확인한 내용입니다. [Claude Code 보고서](../claude-code-internals/)와 같은 과제로 비교했습니다.

## 한 줄 요약

**Codex는 도구를 셸 하나로 줄이고, 안전은 OS 샌드박스에 맡기는 구조입니다.** 그 덕분에 컨텍스트가 가볍고 빠릅니다.

## 구조

**1. 고정 지시문은 앞에, 바뀌는 정보는 메시지로**

18KB짜리 기본 지시문은 세션 내내 고정입니다. 작업 폴더, 권한, 스킬 목록, 날짜처럼 바뀌는 정보는 대화 메시지로 따로 넣습니다. 출처는 메시지의 역할로 나눕니다. 하네스의 규칙은 `developer`, 환경 정보는 `user` 역할입니다.

**2. 과거는 고치지 않고 덧붙인다**

모델을 바꾸거나 작업을 중단해도 앞의 내용을 수정하지 않습니다. 대신 "모델이 바뀌었다", "이전 턴은 중단됐다" 같은 메시지를 뒤에 추가합니다.

**3. 도구는 사실상 하나**

파일 읽기, 검색, 테스트 실행, 파일 수정이 전부 `exec`이라는 도구 하나를 거칩니다. 실제로 긴 세션에서도 호출 96번 중 96번이 이 도구였습니다.

**4. 안전은 OS 샌드박스가 담당**

허용된 폴더 밖에 쓰기, 네트워크 접근, 하위 프로세스 생성을 운영체제 수준에서 막습니다. 실험 중에는 테스트 실행이 막히자 Codex가 스스로 우회 옵션을 찾아냈습니다.

**5. 압축할 때 사용자의 말은 원문 그대로 보존**

대화가 길어지면 이력을 요약하는데, 사용자가 한 말만큼은 원문을 따로 남깁니다.

## 왜 이런 구조인가

- **캐시를 살리려고.** 앞부분이 매번 똑같아야 이전 계산을 재사용할 수 있습니다. 그래서 바뀌는 정보는 뒤로 보냅니다. 실험에서 새 세션의 첫 요청부터 캐시에 맞았고, 전체 입력의 93%가 캐시에서 처리됐습니다.
- **기록을 남기려고.** 과거를 덮어쓰지 않으면 모델이 "언제 무엇이 바뀌었는지" 흐름을 그대로 볼 수 있습니다.
- **컨텍스트를 가볍게 하려고.** 도구가 하나뿐이라 시작 컨텍스트가 약 17K 토큰입니다. Claude Code 서브에이전트(약 33K)의 절반입니다.
- **도구가 단순한 만큼 안전장치는 OS로.** 셸에서는 무엇이든 할 수 있으니, 도구별로 규칙을 두는 대신 실행 환경 자체를 가둡니다.
- **요약해도 지시가 흐려지지 않게.** 요약은 손실이 생기기 마련이라, 가장 중요한 사용자 지시만큼은 원문으로 지킵니다.

## Claude Code와 무엇이 다른가

두 도구의 바탕은 같습니다. **캐시를 극대화하고 기록을 보존한다**는 원칙입니다. 차이는 컨텍스트를 아끼는 방법에 있습니다.

- **Codex:** 도구를 **줄여서** 아낍니다. 안전은 OS 샌드박스가 맡습니다.
- **Claude Code:** 도구를 많이 두되 **필요할 때 불러오고**, 큰 작업은 **서브에이전트로 격리해서** 아낍니다. 안전은 도구별 권한 규칙이 맡습니다.

## 실험에서 본 것

같은 과제(프롬프트 캐시 시뮬레이터 구현)를 두 에이전트에게 원샷으로 맡겼습니다.

Codex는 85초 만에 끝냈고 테스트도 모두 통과했습니다. 하지만 결과에는 함정이 있었습니다. 시뮬레이터가 대화 이력을 한 번도 캐시에 맞히지 못했는데, 히트율 지표를 요청 단위로 세는 바람에 95%로 보고됐습니다. 토큰 기준 실제 히트율은 16%입니다. Claude Code 서브에이전트는 114초가 걸렸지만, 같은 함정을 발견해 고쳤고 그 이유도 보고했습니다.

정리하면 Codex는 **빠르고 가벼웠고**, 결과 검증은 Claude 쪽이 더 꼼꼼했습니다. 다만 실험은 한 번뿐이고, 경량 모델(`gpt-6-luna`)을 쓴 영향도 섞여 있습니다.
