## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **폰 노이만 아키텍처(Von Neumann Architecture)**: CPU와 주기억장치 간에 단일 시스템 버스를 공유하여 명령어 인출과 데이터 접근을 시분할 순차 처리하는 컴퓨터 구조로, 하드웨어 구성이 단순하고 주소 공간 활용 유연성이 높으나 버스 경합 병목을 유발하는 기본 컴퓨터 아키텍처.
- **하버드 아키텍처(Harvard Architecture)**: 명령어 메모리/버스와 데이터 메모리/버스를 물리적으로 분리하여 동시 병렬 접근을 지원하는 컴퓨터 구조로, 폰 노이만 병목을 제거하되 배선 복잡도와 메모리 분할 비효율을 수반하는 고성능 컴퓨터 아키텍처.

</details>

- 정의/개념: 프로세서와 주기억장치 간 명령어 및 데이터를 전달하는 **컴퓨터 시스템 아키텍처**에서, 단일 공유 버스 기반의 **폰 노이만 아키텍처** 및 독립 분리 버스 기반의 **하버드 아키텍처**로 대별되는 프로세서-메모리 연결 체계
- 배경/필요성: 단일 시스템 버스 환경에서 명령어 인출(Fetch)과 데이터 접근(Load/Store) 간 버스 점유 경합으로 인한 **폰 노이만 병목**이 발생하여, 코어 연산 지연 해소와 파이프라인 연속 구동을 위한 내부 캐시 계층 분리 구조 필요성 대두

#### 한줄 요약
- 폰 노이만은 단일 공유 버스로 공간 유연성을 확보하고, 하버드는 분리된 전용 버스로 동시 병렬 접근 성능을 확보한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **수정 하버드 아키텍처(Modified Harvard Architecture)**: 프로세서 코어 내부(L1 캐시)는 명령어(I-Cache)와 데이터(D-Cache)로 분리하고, 외부 하위 메모리는 단일 통합 공간으로 공유하여 성능과 공간 효율을 절충한 컴퓨터 구조.
- **폰 노이만 병목(Von Neumann Bottleneck)**: CPU 고속 연산 장치와 저속 시스템 버스 간 전송 속도 격차로 인해 명령어 인출과 데이터 접근이 직렬화되어 전체 성능이 저하되는 현상.
- **명령어 인출(Instruction Fetch)**: 프로그램 카운터(PC)가 가리키는 주소에서 실행할 명령어를 CPU 내부 레지스터로 읽어오는 파이프라인 첫 단계.

</details>

- 단일 시스템 버스 환경에서 발생하는 **폰 노이만 병목**으로 인해 명령어 인출과 데이터 처리가 시분할 직렬화되어 버스 대역폭 제한 발생
- 명령어와 데이터 전용 버스를 물리적으로 분리하여 동시 병렬 접근을 지원하는 **하버드 아키텍처** 기반 버스 대역폭 확보
- 코어 내부 L1 계층은 I/D 분리 구조를 취하고 외부 주기억장치는 단일 메모리를 공유하는 **수정 하버드 아키텍처** 절충형 구조 채택

#### 한줄 요약
- 공유 버스는 저장 공간 유연성이 높지만 직렬화 병목이 발생하고, 분리 버스는 동시 처리 속도가 빠르지만 회로 복잡도가 증가하는 상충 관계를 갖는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 캐시(Instruction Cache, I-Cache)**: CPU 코어 내부에 위치하여 명령어 인출 전용 대역폭을 제공하고 데이터 접근과의 버스 경합을 차단하는 고속 캐시.
- **데이터 캐시(Data Cache, D-Cache)**: CPU 코어 내부에 위치하여 데이터 읽기/쓰기 전용 대역폭을 제공하는 고속 캐시.
- **통합 메모리(Unified Memory)**: 프로그램 코드와 실행 데이터가 동일한 물리적 주소 공간과 메모리 채널을 공유하는 단일 주기억장치(DRAM) 계층.

</details>

```text
[수정 하버드 아키텍처]
  │
  ├─ [CPU 코어 (하버드 구조)]
  │     ├─ [L1 I-Cache] (명령어 전용 대역폭)
  │     └─ [L1 D-Cache] (데이터 전용 대역폭)
  │
  └─ [외부 시스템 (폰 노이만 구조)]
        ├─ [버스 중재기] (캐시 미스 경합 중재)
        └─ [통합 메모리] (코드·데이터 단일 DRAM)
```

선의 의미: 코어 내부(하버드 분리 캐시)와 외부(폰 노이만 통합 메모리)의 계층 구조를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 통합 메모리·공유 버스 | 프로그램 코드와 데이터를 단일 주소 공간에서 관리하며 시분할 **순차 전송** 담당 |
| 분리 메모리·전용 버스 | 명령어 버스와 데이터 버스의 독립 물리 배선을 통한 **동시 병렬 접근** 보장 |
| 분리 L1 캐시 (I/D) | 코어 내부 폰 노이만 병목을 해소하고 독립 대역폭을 제공하는 **계층 분리** 수행 |
| 버스 중재기 | L1 캐시 미스 발생 시 하위 통합 메모리 접근 버스를 제어하는 **경합 중재** 수행 |

#### 한줄 요약
- 현대 CPU는 코어 내부에서는 하버드 방식으로 동시 접근 대역폭을 확보하고, 외부 메모리는 폰 노이만 방식으로 공간 유연성을 확보하는 수정 하버드 구조를 사용한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **파이프라인 스톨(Pipeline Stall)**: 버스 경합이나 메모리 인출 지연으로 인해 파이프라인 단계가 다음 명령어를 실행하지 못하고 일시 중단되는 대기 상태.
- **클록 버블(Bubble)**: 파이프라인 스톨 발생 시 유효 연산 없이 클록 사이클만 낭비되는 무연산(NOP) 공백 구간.

</details>

```text
[메모리 참조 요구 경로] (진행 ①→④, L1 적중 시 무지연 동시 완료, 미스 시 하위 인출)
  │
  ├─ [파이프라인 제어 유닛] (① 메모리 접근 요구 및 주소 송출)
  │
  ├─ [L1 I-Cache·L1 D-Cache] (② 수정 하버드 구조에서 독립 읽기 동시 병렬 조회)
  │
  ├─ [버스 중재기] (③ 폰 노이만 구조에서 명령어 인출·데이터 접근 시분할 순차 중재)
  │
  └─ [통합 메모리] (④ L1 미스·버스 경합 시 하위 인출 및 파이프라인 지연 클록 삽입)
```

분기 결과: 폰 노이만은 단일 버스 경합으로 파이프라인 스톨이 발생하며, 수정 하버드는 L1 캐시 적중 시 명령어 인출과 데이터 접근이 동시 병렬 완료된다

#### 한줄 요약
- 메모리 참조 요구 발생 시 수정 하버드 구조는 L1 I/D 분리 캐시를 통해 동시 접근을 지원하며, 미스 시에만 하위 통합 메모리로 내려간다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **순수 하버드 아키텍처(Pure Harvard Architecture)**: 명령어와 데이터의 물리적 메모리 장치 및 버스가 완전히 독립되어 메모리 공간 공유가 없는 고정 구조(DSP, 신호 처리 프로세서에서 활용).

</details>

| 컴퓨터 아키텍처 | 폰 노이만 아키텍처 | 수정 하버드 아키텍처 | 순수 하버드 아키텍처 |
|:---|:---|:---|:---|
| 적용 기준 | **제어 회로 단순화** 및 공간 유연성 요구 | **범용 고성능 컴퓨팅** 및 OS 지원 요구 | **고정 신호 처리** 및 결정론적 지연 보장 |
| 핵심 특징 | 단일 주소 공간 및 **공유 시스템 버스** | 내부 분리 L1 캐시와 **외부 통합 메모리** | 코드·데이터 전용 분리 버스 및 **독립 메모리** |
| 한계 | 버스 점유 경합에 따른 **폰 노이만 병목** | I/D 캐시 간 데이터 불일치 및 동기화 비용 | 메모리 공간 분할 고정으로 자원 낭비 발생 |

#### 한줄 요약
- 단순 제어에는 폰 노이만, 고정 신호 처리에는 하버드가 적합하며, 범용 OS 컴퓨팅에는 캐시 계층을 절충한 수정 하버드가 최적의 선택이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **직접 메모리 접근(Direct Memory Access, DMA)**: CPU 개입 없이 주변장치가 주기억장치에 데이터를 직접 전송하여 버스 효율을 높이는 하드웨어 제어 기법.
- **버스 스누핑(Bus Snooping)**: 캐시 제어기가 시스템 버스 상의 메모리 트랜잭션을 감시하여 캐시 일관성 상태를 유지하는 하드웨어 메커니즘.
- **자기 수정 코드(Self-Modifying Code)**: 실행 중 데이터 영역에서 동적으로 생성하거나 수정한 기계어 코드를 메모리에 기록한 후 실행하는 코드 패턴.
- **캐시 유지보수(Cache Maintenance)**: I-Cache와 D-Cache 간 데이터 불일치를 방지하기 위해 캐시 플러시(Flush) 및 무효화(Invalidate)를 수행하는 일관성 제어 동작.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단일 버스 공유 시 명령어 인출과 데이터 접근 간 파이프라인 스톨 누적 | 코어 내부 **L1 I-Cache** 및 **D-Cache** 분리 계층 적용 | 코어 레벨 폰 노이만 병목 해소 및 클록당 명령어 처리율(IPC) 향상 |
| DMA 컨트롤러의 직접 메모리 갱신에 따른 캐시 일관성 불일치 결함 | 버스 스누핑(Bus Snooping) 및 **D-Cache 무효화** 적용 | 메모리-캐시 간 데이터 일관성 보장 및 오동작 방지 |
| 동적 코드 생성(JIT) 시 D-Cache에 기록된 신규 코드의 미반영 위험 | D-Cache Clean 후 **I-Cache Invalidate** 동기화 수행 | 런타임 생성 기계어의 정확한 인출 및 실행 무결성 확보 |

#### 한줄 요약
- 수정 하버드 아키텍처 채택 시 고속 병렬 처리가 가능해지나, DMA 및 동적 코드 생성 환경에서는 I/D 캐시 간 일관성 유지보수 설계가 필수적이다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **메모리 벽(Memory Wall)**: 프로세서 연산 속도와 메모리 접근 속도의 격차가 세대마다 벌어져 메모리 대역폭이 시스템 성능 병목으로 고착되는 현상.
- **프로세싱 인 메모리(Processing-In-Memory, PIM)**: 연산 로직을 메모리 다이 내부에 배치하여 데이터 이동 없이 메모리 내에서 직접 연산을 수행하는 아키텍처.
- **컴퓨트 익스프레스 링크(Compute Express Link, CXL)**: CPU·가속기·메모리 간 캐시 일관성을 유지하면서 대역폭을 확장하는 PCIe 기반 개방형 인터커넥트 프로토콜.

</details>

- 코어 내부 하버드 분리 캐시와 외부 폰 노이만 통합 메모리를 결합한 수정 하버드 구조가 주류 표준으로 확립되었으며, 차세대 AI·이기종 연산 환경에서는 **메모리 벽** 해소를 위해 **PIM** 및 **CXL** 기반의 분산 메모리 풀링 및 계층 융합 아키텍처로 진화하는 추세
- 고속 병렬 처리와 동적 코드 최적화 구현 시 DMA 및 자기 수정 코드로 인한 캐시 불일치 위험을 방지하기 위해, 하드웨어 스누핑 오버헤드와 캐시 플러시 빈도 간 트레이드오프를 통제하는 정밀한 캐시 동기화 인터벌 및 일관성 제어 설계 체계 구축

#### 한줄 요약
- 수정 하버드 아키텍처는 PIM·CXL 기반 이기종 메모리 계층으로 진화 중이며, 고성능 연산 환경에서는 캐시 일관성 오버헤드 통제와 메모리 동기화 최적화 기준 정립
