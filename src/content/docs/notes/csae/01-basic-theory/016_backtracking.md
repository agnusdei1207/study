## 답안 골격
```text
[백트래킹] ◀━━ 머리: Ⅶ 내 의견 (동적 휴리스틱 분기 우선순위와 병렬 가지치기 결합)
 ┃
 ┣━ Ⅰ 개요 ───── 지수 시간 완전 탐색 한계 → 상태 공간 트리 탐색 중 유망하지 않은 경로를 조기 차단(Pruning)
 ┣━ Ⅱ 원리 ───── 상태 공간 트리(State Space Tree) · 깊이 우선 탐색(DFS) · 유망성 검사(Promising) · 가지치기(Pruning)
 ┣━ Ⅲ 구조 ───── 루트 상태 → 유망성 판단 조건문 → 부적합 시 이전 부모 노드로 역추적(Backtrack)
 ┣━ Ⅳ 흐름 ───── ① 노드 방문 → ② 제약조건 적합성 평가 → ③ 유망 시 자식 재귀 확장 / 비유망 시 즉시 반환
 ┣━ Ⅴ 비교 ───── 백트래킹 vs 완전 탐색(Brute-force) vs 분기 한정법(Branch and Bound)
 ┗━ Ⅵ 실무 ───── N-Queen 배치 · SAT 솔버(DPLL) · 정수 계획법 및 컴파일러 레지스터 할당
```
- 필수 키워드: 상태 공간 트리 · 유망성(Promising) · 가지치기(Pruning) · 깊이 우선 탐색(DFS) · 역추적
- 배점 전략: 10점 = Ⅰ 개요 → Ⅱ 가지치기 원리 도해 → Ⅲ 유망성 판정 흐름 → Ⅴ 분기 한정법과의 비교

## 한 줄 본질
- 모든 경우의 수를 무차별 대입하는 전수 조사의 파멸적 시간 복잡도($O(n!)$)를 해소 → 해가 될 가능성이 없는 하위 트리를 유망성 검사로 조기 절단(가지치기) → 탐색 시간 대폭 단축 / 최악의 경우 지수 시간 잔존

## 핵심 그림
```text
                  [ 루트 노드 ]
                 /      |      \
              [A]      [B]      [C]
             /   \      |
          [D]    [E]   [F]  <-- [유망성 검사(Promising Check) 실패]
          / \          / \       (Pruning: 하위 노드 탐색 즉시 중단)
        [G] [H]       X   X      ===> 부모 노드로 Backtrack
                    (가지치기)
```

## 핵심 통찰
- 백트래킹의 핵심은 "얼마나 빨리 막다른 골목임을 알아채고 뒤로 물러서는가(Pruning)"에 달려 있으며, 가지치기 조건의 강도에 따라 실제 연산량이 수천 배 차이 남
- DFS 기반으로 동작하므로 현재 경로 상의 상태만 기억하면 되어 메모리 소비량은 트리 깊이에 비례($O(h)$)하여 매우 경제적임
- 분기 한정법(Branch and Bound)이 너비 우선(BFS) 또는 우선순위 큐를 사용하여 최적화 문제의 상한/하한을 따지는 반면, 백트래킹은 DFS를 사용하여 결정 문제(Decision Problem)의 만족해를 찾는 데 특화됨

## 이웃 토픽과 구분
- 백트래킹 vs 분기 한정법:
| 비교 항목 | 백트래킹 (Backtracking) | 분기 한정법 (Branch and Bound) |
|---|---|---|
| 탐색 방식 | 깊이 우선 탐색 (DFS) 기반 | 너비 우선(BFS) 또는 Best-First 기반 |
| 적용 영역 | 만족 가능성 문제 (해의 존재 여부) | 최적화 문제 (최대/최소 비용 탐색) |
| 가지치기 기준 | 제약조건 위배 시 즉시 절단 | 목적함수의 하한/상한(Bound) 비교 절단 |
| 메모리 소비 | $O(h)$ (트리 높이 비례, 적음) | $O(B^d)$ (활성 큐 관리로 메모리 부담 큼) |

## 문제·원인·대책
- 적용 상황: 대규모 제약 만족 문제(CSP) 및 자동화 배차 계획 시스템
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 특정 분기에서 최악의 지수 탐색 발생 | 상태 공간 트리 전면에서 잘못된 선택을 하여 비유망한 거대 서브트리를 뒤늦게 순회 | 잔여 선택지가 가장 적은 변수부터 탐색하는 MRV(Minimum Remaining Values) 휴리스틱 적용 | 조기 실패 유도로 탐색 공간 축소 |
| 깊은 재귀로 인한 스택 오버플로 위험 | 문제 규모 증가에 따른 재귀 콜 스택 누적 | 명시적 루프와 비트마스크(Bitmask) 기반 상태 압축 백트래킹 구현 | 스택 메모리 절감 및 비트 연산 가속 |

## 이렇게 출제된다
- 제122회 1교시: "백트래킹(Backtracking) 알고리즘의 원리, 상태공간트리와 가지치기(Pruning)" → 요구 포인트: 상태공간트리 구조, 유망성(Promising) 판정 개념, 완전 탐색과의 차이 및 대표 사례

## 내 의견
- [동적 휴리스틱 분기 우선순위와 병렬 가지치기 결합] 백트래킹을 순수 정적 순서로 탐색하면 문제에 따라 탐색 트리가 기형적으로 팽창하여 시스템이 무응답 상태에 빠짐 → 나라면: 도메인 제약조건 전파(Constraint Propagation)를 통해 후보군을 사전 제거(Forward Checking)하고, 멀티코어 환경에서 유망한 상위 분기들을 독립 스레드로 분할 탐색하여 최초 해 발견 시 타 스레드를 즉시 인터럽트하는 병렬 포트폴리오 기법 적용
