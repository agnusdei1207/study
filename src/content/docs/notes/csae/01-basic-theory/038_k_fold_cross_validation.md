## 답안 골격
```text
[K-Fold 교차 검증] ◀━━ 머리: Ⅶ 내 의견 (스케일러·인코더의 폴드 내부 파이프라인 격리로 데이터 누수 원천 차단)
 ┃
 ┣━ Ⅰ 개요 ───── 단일 분할(Holdout)의 데이터 편향·과소평가 한계 → 데이터를 K개 분할하여 전수 교차 검증
 ┣━ Ⅱ 특징 ───── 데이터 활용 극대화 · 분산 감소 · 계산 복잡도 K배 증가 · 일반화 오차 신뢰성 확보
 ┣━ Ⅲ 구조 ───── 전체 데이터셋 → K개 균등 Fold 분할(K-1개 학습용, 1개 검증용) → K회 라운드 로빈
 ┣━ Ⅳ 흐름 ───── ① 데이터 셔플/분할 → ② k번째 Fold 검증 지정 → ③ K-1개 학습 및 검증 → ④ 평균 성능 도출
 ┣━ Ⅴ 비교 ───── Holdout vs K-Fold vs Stratified K-Fold vs LOOCV (표본 수와 클래스 균형 기준)
 ┗━ Ⅵ 실무 ───── 데이터 누수(Data Leakage) / 클래스 불균형 왜곡 / 시계열 데이터의 미래 정보 참조 위험
```
- 필수 키워드: 리샘플링 · Fold 분할 · 라운드 로빈 · 계층별 K-Fold(Stratified) · 데이터 누수(Data Leakage) · 일반화 오차
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ K개 분할 개념도 → Ⅴ 교차 검증 기법 비교 / 25점 = Ⅰ~Ⅶ 전개, Ⅳ 회차별 학습·검증 절차와 Ⅵ 데이터 누수 방지 파이프라인
- 기출: 122회 3교시 `k-fold Cross Validation 기법과 머신러닝 평가방법` → Ⅲ·Ⅳ, 128회 4교시 `교차검증(Cross Validation)` → Ⅰ~Ⅵ

## 한 줄 본질
- 고정된 학습/검증 분할은 데이터 우연성에 따른 평가 편향과 데이터 낭비 유발 → 데이터를 K개 부분집합으로 나누어 매 회차 검증셋을 바꿔가며 K번 반복 평가 후 평균 산출 → 모델의 일반화 성능 검증 신뢰도 확보 / K배의 학습 시간 소요

## 핵심 그림
```text
전체 데이터셋 (Total Dataset, N개 샘플)
Fold 1        Fold 2        Fold 3        ...   Fold K
[ 검증(Val) ] [ 학습(Train)] [ 학습(Train)] ...   [ 학습(Train)] -> 성능 1
[ 학습(Train)] [ 검증(Val) ] [ 학습(Train)] ...   [ 학습(Train)] -> 성능 2
[ 학습(Train)] [ 학습(Train)] [ 검증(Val) ] ...   [ 학습(Train)] -> 성능 3
...
[ 학습(Train)] [ 학습(Train)] [ 학습(Train)] ...   [ 검증(Val) ] -> 성능 K
-----------------------------------------------------------------
최종 평가 점수 = (성능 1 + 성능 2 + ... + 성능 K) / K (산술 평균)
```

## 핵심 용어
- 계층별 K-Fold(Stratified K-Fold): 분류 문제에서 타깃 라벨의 클래스 비율이 각 폴드마다 원본 데이터셋과 동일한 비율로 유지되도록 층화 추출하는 검증 기법
- 데이터 누수(Data Leakage): 전처리나 특징 추출 단계에서 검증 폴드의 정보가 학습 폴드로 흘러 들어가 검증 점수가 비정상적으로 낙관되는 현상
- LOOCV(Leave-One-Out Cross-Validation): 폴드 수 $K$를 전체 표본 수 $N$과 동일하게 설정하여 한 번에 단 1개의 표본만 검증에 사용하는 극단적 형태의 교차 검증

## 핵심 통찰
- 교차 검증은 모델을 '학습'시키는 알고리즘이 아니라 모델의 '일반화 오차'를 통계적으로 측정하는 프로토콜임 → 최종 실서비스 배포 시에는 전수 데이터를 다시 사용하여 단일 최종 모델을 재학습해야 함
- 데이터가 적을수록 K-Fold의 가치가 커지지만, 수백만 건 이상의 대규모 데이터셋에서는 Holdout 분할만으로도 표본 오차가 충분히 작아지므로 K-Fold의 연산 비용이 비효율적임
- 시계열 데이터에 무작위 셔플 기반 K-Fold를 적용하면 미래 시점의 데이터로 과거 시점을 예측하는 미래 참조 누수가 발생 → 시간 축 순서를 엄격히 유지하는 TimeSeriesSplit을 적용해야 함

## 이웃 토픽과 구분
- K-Fold vs 부트스트랩: K-Fold = 비복원 균등 분할로 모든 데이터가 정확히 1번씩 검증셋으로 쓰임 / 부트스트랩 = 복원추출을 통해 생성된 표본 밖 데이터(OOB)로 검증 수행

## 문제·원인·대책
- 적용 상황: 신용카드 이상 거래(FDS) 탐지 분류 모델 검증
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 검증 점수는 높으나 운영 배포 후 사기 탐지 실패 | 극단적 불균형 데이터에서 단순 무작위 분할로 특정 검증 폴드에 사기 건수 전무 | 타깃 클래스 분포를 폴드마다 균등 유지하는 계층별(Stratified) K-Fold 채택 | 소수 클래스 검증 왜곡 방지 |
| 교차 검증 점수와 실운영 성능 간 괴리 | 데이터 스케일링을 교차 검증 분할 전에 전체 데이터셋에 일괄 적용(누수) | Scikit-learn Pipeline 객체로 전처리를 각 폴드 루프 안으로 격리 | 미학습 데이터에 대한 순수 평가 보장 |

## 내 의견
- [전처리 누수를 방치한 형식적 K-Fold 관행] 실무 개발팀 다수가 결측치 대체나 정규화를 전체 데이터셋에 먼저 수행한 후 K-Fold로 교차 검증을 돌려 검증 점수를 과대 포장하는 심각한 안티패턴이 만연함 → 나라면: CI 파이프라인의 모델 검증 테스트에 '전처리-모델 단일 파이프라인 캡슐화' 정적 분석 룰을 적용하고, 검증 폴드의 데이터 통계량이 학습 파이프라인의 적합(Fit) 단계에 절대 유입되지 않도록 파이프라인 객체 사용을 배포 게이트 조건으로 강제
