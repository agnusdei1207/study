## 답안 골격
```text
[동적 계획법] ◀━━ 머리: Ⅶ 내 의견 (메모리 폭증 억제를 위한 슬라이딩 윈도우 공간 압축 기법 결합)
 ┃
 ┣━ Ⅰ 개요 ───── 재귀적 중복 계산 한계 → 하위 문제의 해를 테이블에 저장·재사용하는 최적화 패러다임
 ┣━ Ⅱ 성립 ───── 최적 부분 구조(Optimal Substructure) · 중복 부분 문제(Overlapping Subproblems)
 ┣━ Ⅲ 구조 ───── 탑다운(Top-down, 메모이제이션) vs 바텀업(Bottom-up, 타뷸레이션)
 ┣━ Ⅳ 흐름 ───── 점화식(Recurrence Relation) 수립 → 기저 사례(Base Case) 설정 → 테이블 채우기
 ┣━ Ⅴ 비교 ───── 동적 계획법(DP) vs 분할 정복(D&C) vs 탐욕 알고리즘(Greedy)
 ┗━ Ⅵ 실무 ───── 벨만-포드 라우팅 · 편집 거리(Levenshtein) · 배낭 문제(Knapsack)
```
- 필수 키워드: 최적 부분 구조 · 중복 부분 문제 · 메모이제이션(Memoization) · 타뷸레이션(Tabulation) · 점화식
- 배점 전략: 10점 = Ⅰ 개요 → Ⅱ 2대 성립 조건 → Ⅲ 구현 방식 비교(탑다운 vs 바텀업) → Ⅴ 알고리즘 패러다임 비교

## 한 줄 본질
- 동일한 하위 문제가 반복 계산되는 지수 시간($O(2^n)$) 낭비 해결 → 하위 문제의 해를 저장하고 재사용하여 다항 시간($O(n)$ 또는 $O(n^2)$)으로 단축 → 연산 속도 급상승 / 캐시 테이블 메모리 공간 소비

## 핵심 그림
```text
[단순 재귀: 중복 계산 폭증]              [동적 계획법: 해 재사용]
            f(4)                                   f(4)
          /      \                               /      \
       f(3)       f(2)                        f(3)      [Look up]
      /    \     /    \                      /    \
    f(2)  f(1)  f(1)  f(0)                 f(2)   f(1)
   (중복 연산 지수적 증가)                    |
                                     [ DP Table ]
                                     +---+---+---+---+---+
                                     | 0 | 1 | 2 | 3 | 4 |
                                     +---+---+---+---+---+
                                     | 0 | 1 | 1 | 2 | 3 |
                                     +---+---+---+---+---+
```

## 핵심 통찰
- DP 적용을 위한 핵심 전제는 "부분 문제의 최적해가 전체 문제의 최적해를 구성하는 최적 부분 구조"와 "하위 문제들이 서로 독립적이지 않고 계속 겹치는 중복 부분 문제"임
- 분할 정복은 하위 문제들이 독립적(예: 병합 정렬)이라 겹치지 않으므로 결과를 저장할 필요가 없지만, DP는 동일한 하위 문제가 거듭 호출되므로 메모리가 필수적임
- 탑다운 방식은 필요한 상태만 계산하므로 유리할 수 있으나 재귀 스택 오버플로 위험이 있고, 바텀업 방식은 모든 테이블을 순차 계산하므로 캐시 지역성이 우수함

## 이웃 토픽과 구분
- 동적 계획법 vs 분할 정복 vs 탐욕법:
| 비교 항목 | 동적 계획법 (DP) | 분할 정복 (D&C) | 탐욕법 (Greedy) |
|---|---|---|---|
| 하위 문제 성격 | 중복되는 부분 문제 | 서로 독립적인 부분 문제 | 매 단계 국소적 최적 선택 |
| 최적해 보장 | 항상 보장 (전수 조사 기반 최적화) | 항상 보장 | 매트로이드 구조 등 특정 조건에서만 보장 |
| 계산 방식 | 이전 계산 결과 저장 재사용 | 하위 결과 재귀 병합 | 역추적(Backtracking) 없음 |

## 문제·원인·대책
- 적용 상황: 대규모 문자열 유사도 분석 및 서열 정렬 엔진
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 상태 공간 폭증으로 인한 메모리 고갈 | 2차원 DP 테이블 크기가 $O(N \times M)$으로 확장되어 RAM 한계 초과 | 직전 행의 결과만 참조하는 슬라이딩 윈도우(Sliding Window) 1차원 배열 압축 | 공간 복잡도 $O(M)$ 축소 |
| 탑다운 DP 재귀 깊이 초과 발생 | 입력 크기 증가로 콜 스택 프레임 누적 한도 초과 | 루프 기반의 바텀업 타뷸레이션(Tabulation) 방식으로 전면 전환 | 스택 오버플로 원천 방지 |

## 내 의견
- [메모리 폭증 억제를 위한 슬라이딩 윈도우 공간 압축 기법 결합] 2차원 이상의 고차원 DP를 실제 상용 시스템에 배포할 때 점화식 의존성을 분석하지 않고 전체 테이블을 할당하면 Out-Of-Memory 장애가 유발됨 → 나라면: 점화식이 직전 $k$개 상태에만 의존하는 마르코프 성질을 가질 경우 모듈러 연산($i \pmod k$) 기반의 롤링 배열(Rolling Array) 기법을 강제 적용하여 공간 복잡도를 차원 단위로 압축
