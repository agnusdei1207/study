## 답안 골격
```text
[정렬 알고리즘] ◀━━ 머리: Ⅶ 내 의견 (최악 방어와 캐시 지역성을 결합한 하이브리드 Introsort 채택)
 ┃
 ┣━ Ⅰ 개요 ───── 순서화 비용 한계 → 키(Key) 기준 데이터 정렬, 비교 정렬의 이론적 하한선 $\Omega(n \log n)$
 ┣━ Ⅱ 특성 ───── 시간 복잡도(최선/평균/최악) · 공간 복잡도(In-place 여부) · 안정 정렬(Stability)
 ┣━ Ⅲ 구조 ───── 퀵(피벗 분할) · 병합(분할-재귀 병합) · 힙(완전 이진 트리 최대/최소 힙)
 ┣━ Ⅳ 흐름 ───── 퀵 정렬 파티셔닝(Lomuto/Hoare) 및 피벗 좌우 분할 재귀 흐름
 ┣━ Ⅴ 비교 ───── 퀵 정렬 vs 병합 정렬 vs 힙 정렬 vs 버블 정렬 종합 비교표
 ┗━ Ⅵ 실무 ───── 퀵 정렬 최악 $O(n^2)$ 피벗 편향 회피(Median-of-three) · Timsort / Introsort 채용
```
- 필수 키워드: 분할 정복(Divide & Conquer) · 안정 정렬(Stable Sort) · 제자리 정렬(In-place) · 피벗(Pivot) · 힙트리(Heap)
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 핵심 알고리즘별 메커니즘 도해 → Ⅴ 종합 비교표(시간/공간/안정성)

## 한 줄 본질
- 원소 간 비교 기반 정렬은 결정 트리 상 $\Omega(n \log n)$의 수학적 한계가 존재 → 피벗 분할(퀵), 추가 메모리 병합(병합), 힙 구조(힙)로 분할 처리 → 평균 연산 고속화 / 최악 시간 및 추가 메모리 상충

## 핵심 그림
```text
[정렬 대상 배열: N개 원소]
         |
         +-------------------+-------------------+
         |                   |                   |
   [ 퀵 정렬 ]          [ 병합 정렬 ]        [ 힙 정렬 ]
         |                   |                   |
 피벗(Pivot) 기준 분할   반으로 균등 분할      완전 이진 트리 구성
 [Left] Pivot [Right]   [Left]    [Right]     (최대 힙: O(n))
         |                   |                   |
  제자리 교환 분할       정렬 후 추가 공간 병합   루트 추출 및 Heapify
  (In-place, O(1))       (추가 메모리: O(n))     (제자리 정렬: O(1))
         |                   |                   |
  평균 O(n log n)        보장 O(n log n)     보장 O(n log n)
  최악 O(n^2, 편향)      안정 정렬(Stable)   불안정 정렬
```

## 핵심 통찰
- 퀵 정렬이 병합·힙보다 평균적으로 가장 빠른 이유는 내부 루프가 단순하고 순차 메모리 접근으로 인한 CPU 캐시 적중률(Cache Locality)이 극히 높기 때문임
- 병합 정렬은 어떤 입력에도 $O(n \log n)$과 안정성(동일 키의 원래 순서 유지)을 보장하지만, $O(n)$의 추가 메모리 할당과 복사 오버헤드가 발생함
- 힙 정렬은 추가 메모리 없이 $O(n \log n)$을 보장하나, 힙 탐색 시 인덱스가 $2i, 2i+1$로 뛰어넘어 캐시 미스가 빈번하게 일어남

## 이웃 토픽과 구분
- 퀵 정렬 vs 힙 정렬 vs 병합 정렬 종합 비교:
| 비교 항목 | 퀵 정렬 (Quick) | 병합 정렬 (Merge) | 힙 정렬 (Heap) | 버블 정렬 (Bubble) |
|---|---|---|---|---|
| 평균 시간 | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ |
| 최악 시간 | $O(n^2)$ (이미 정렬/역정렬) | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ |
| 공간 복잡도 | $O(\log n)$ (재귀 스택) | $O(n)$ (추가 버퍼) | $O(1)$ (제자리) | $O(1)$ (제자리) |
| 안정성 | 불안정(Unstable) | 안정(Stable) | 불안정(Unstable) | 안정(Stable) |

## 문제·원인·대책
- 적용 상황: 대규모 실시간 데이터베이스 인덱싱 및 쿼리 정렬
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 이미 정렬된 데이터 입력 시 퀵 정렬 성능 급락 | 고정 피벗(첫 원소/끝 원소) 선택으로 분할이 불균형하게 치우쳐 $O(n^2)$ 퇴보 | 삼분위 중간값(Median-of-three) 피벗 선택 또는 무작위 피벗팅 적용 | 분할 균형 유지 및 최악 회피 |
| 대용량 정렬 시 Out-Of-Memory 발생 | 병합 정렬의 $O(n)$ 추가 버퍼 할당이 메모리 한계를 초과 | 제자리 힙 정렬 또는 외장 병합 정렬(External Merge Sort) 전환 | 메모리 오버헤드 억제 |

## 내 의견
- [최악 방어와 캐시 지역성을 결합한 하이브리드 Introsort 채택] 단일 알고리즘만 고집하면 퀵 정렬의 최악 $O(n^2)$ 파멸적 지연이나 병합 정렬의 메모리 폭증 위험에 노출됨 → 나라면: 기본적으로 퀵 정렬로 고속 처리하다가 재귀 깊이가 $2 \log n$을 초과하면 힙 정렬로 전환하여 $O(n \log n)$을 엄격히 보장하고, 작은 부분 배열($n < 16$)에는 삽입 정렬을 적용하는 Introsort를 시스템 표준 정렬 엔진으로 채택
