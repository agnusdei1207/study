## 한 줄 본질
- 데이터가 물리적으로 여러 지리적 노드에 흩어져 있는 복잡성 → 분산 DBMS 엔진이 분할·복제·위치 정보를 내부에서 자동 해석 → 사용자는 단일 로컬 DB처럼 단순 쿼리 가능 / 네트워크 지연과 분산 장애 처리 비용 은닉 한계

## 핵심 그림
```text
[분산 데이터베이스 6대 투명성 구조]

                  [사용자 / 애플리케이션]
                  SELECT * FROM CUSTOMER; (단일 테이블로 인식)
                            │
   ┌────────────────────────┼────────────────────────┐
   ▼                        ▼                        ▼
[ 위치 투명성 ]          [ 분할 투명성 ]          [ 복제 투명성 ]

  있는지 몰라도 됨         쪼개져 있어도 모름       있어도 단일 뷰 제공
   │                        │                        │
   ├────────────────────────┼────────────────────────┤
   ▼                        ▼                        ▼
[ 병행 투명성 ]          [ 장애 투명성 ]          [ 지역사상 투명성 ]
- 다중 트랜잭션이 동시   - 특정 노드가 죽어도     - 로컬 DBMS 이름 체계와
  수행되어도 일관성 보장   대체 노드로 자동 전환    무관하게 표준 질의
```

## 핵심 용어
- 위치 투명성(Location Transparency): 데이터가 물리적으로 어느 서버 노드에 저장되어 있는지 접근 주소(IP, 호스트)를 명시하지 않고 논리적 명칭만으로 접근 가능한 성질
- 분할 투명성(Fragmentation Transparency): 하나의 논리적 릴레이션이 수평 또는 수직으로 여러 조각(Fragment)으로 나뉘어 각기 다른 노드에 분산되어도, 사용자는 하나의 테이블로 보고 질의할 수 있는 성질

## 핵심 통찰
- 투명성은 '개발자의 편의'를 위한 것이지만 '공짜'가 아님 → 위치와 복제를 완벽히 은닉하려다 보면 네트워크 왕복 지연(RTT)이 발생해 쿼리가 비정상적으로 느려짐
- 복제 투명성은 CAP 이론의 일관성-가용성 상충과 직결됨 → 복제본 간의 일관성을 즉각 보장(동기 복제)하면 쓰기 속도가 급감하고 가용성이 떨어지므로, 현대 분산 DB는 최종 일관성(Eventual Consistency)으로 투명성을 완화
- 투명성을 구현하는 핵심 기술적 엔진은 '글로벌 데이터 카탈로그(GDD)'임 → 카탈로그가 모든 조각의 위치와 복제 상태를 실시간으로 알고 있어야 올바른 쿼리 트리 분할 가능

## 딸려 나오는 하위 토픽
| 하위 토픽 | 상위 구조 속 위치 | 한 줄 |
|---|---|---|
| 글로벌 데이터 딕셔너리(GDD) | 분산 DB 메타데이터 저장소 | 모든 테이블 조각의 물리 노드 위치와 스키마 맵핑 정보를 전역 관리 |
| 분산 2단계 커밋 (2PC) | 병행/장애 투명성 구현체 | 분산 노드 간 트랜잭션 원자성을 보장하기 위해 코디네이터와 참가자 간 합의 수행 |

## 이웃 토픽과 구분
- 분산 데이터베이스 vs 연계(Federated) 데이터베이스: 분산 DB = 단일 논리 스키마 아래 완벽한 투명성 제공 / 연계 DB = 서로 다른 이기종 DB들이 자율성을 유지하며 인터페이스로 느슨하게 결합

## 문제·원인·대책
- 적용 상황: 글로벌 3개 대륙(서울, 프랑크푸르트, 버지니아) 리전 분산 DB 운영
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 단순 회원 조회 쿼리가 대륙 간 네트워크 RTT로 인해 500ms 이상 소요 | 분할/위치 투명성에만 의존해 쿼리가 해외 노드를 무분별하게 경유 | 위치 인지형 라우팅(Geo-Partitioning) 적용해 현지 노드 우선 조회 | 로컬 조회 지연시간 10ms 이하 단축 |
| 한 리전 노드 장애 시 전체 트랜잭션이 대기하며 멈춤 현상 | 장애 투명성 미흡 및 동기식 2PC의 블로킹 취약점 | Raft/Paxos 기반 분산 합의 알고리즘(Quorum Write) 도입 | 과반수 노드 생존 시 무중단 자동 페일오버 |

## 내 의견
- [추상화의 누수(Leaky Abstraction) 인식] 개발자가 완벽한 투명성을 믿고 로컬 RDBMS처럼 대량 조인 쿼리를 날려 네트워크 대역폭 고갈 사태 초래 → 나라면: 논리적 투명성은 유지하되, ORM 레벨에서 대륙 간 크로스 쿼리를 감지하면 경고를 발생시키고 로컬 캐시 레이어(Redis)를 전진 배치하는 '비용 인지형 분산 아키텍처' 수립
