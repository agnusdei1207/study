## 답안 골격
```text
[BCNF (Boyce-Codd Normal Form)] ◀━━ 머리: Ⅶ 내 의견 (후보키가 아닌 결정자 분해와 종속성 보존 손실 시 트리거를 통한 무결성 방어)
 ┃
 ┣━ Ⅰ 개요 ───── 제3정규형(3NF)을 만족하면서 릴레이션에 존재하는 모든 결정자(Determinant)가 반드시 후보키(Candidate Key)가 되도록 강제한 강력한 제3정규형
 ┣━ Ⅱ 특징 ───── 3NF의 예외적 이상현상 해결 · 결정자가 후보키가 아닌 함수종속 제거 · 무손실 분해 보장 · 함수 종속성 보존 손실(Loss) 가능성
 ┣━ Ⅲ 구조 ───── 규칙: 모든 자명하지 않은 $X \rightarrow Y$에 대해 $X$는 슈퍼키 ┃ 대표 사례: (학번, 과목 $\rightarrow$ 담당교수), (담당교수 $\rightarrow$ 과목)
 ┣━ Ⅳ 흐름 ───── ① 3NF 릴레이션 검토 → ② 복수의 겹치는 후보키에서 비후보키 결정자($X$) 식별 → ③ $R_1(X, Y)$과 $R_2(R-Y)$로 무손실 분해 → ④ BCNF 달성
 ┣━ Ⅴ 비교 ───── 제3정규형(3NF) vs BCNF (주부속성이면 용인 vs 주부속성 상관없이 무조건 후보키 강제)
 ┗━ Ⅵ 실무 ───── BCNF 분해 시 기존 함수적 종속성(FD)이 분실되어 두 테이블 조인 없이는 제약조건 검증 불가
```
- 필수 키워드: BCNF · 보이스-코드 정규형 · 결정자(Determinant) · 후보키(Candidate Key) · 슈퍼키 · 3NF 예외 · 무손실 분해 · 종속성 보존 손실
- 배점 전략: 10점 = Ⅰ → Ⅲ 수강 릴레이션(학번, 과목, 교수) 분해 도식 → Ⅴ 3NF vs BCNF 비교표 / 25점 = Ⅰ~Ⅶ, Ⅳ 함수 종속성 다이어그램 및 Ⅵ 종속성 보존 vs BCNF 달성의 트레이드오프
- 기출: 105회 `제3정규형(3NF)과 보이스-코드 정규형(BCNF)의 개념을 비교하고, 3NF는 만족하지만 BCNF를 위배하는 사례와 분해 과정을 설명하시오.` → Ⅰ 정의 + Ⅲ 위배 사례 도식 + Ⅳ 분해 절차 + Ⅴ 비교표

## 한 줄 본질
- 3NF를 만족해도 복수의 후보키가 겹칠 때 후보키가 아닌 속성이 결정자 노릇을 하면 갱신 이상 발생 → "모든 결정자는 후보키여야 한다"는 단일 규칙으로 분해 → 완벽한 함수종속 이상현상 제거 / 함수 종속성 보존이 깨질 수 있음

## 핵심 그림
```text
[3NF는 만족하지만 BCNF를 위배하는 전형적 사례 및 분해]

  [위배 릴레이션 R: (학번, 과목, 담당교수)]
  * 후보키: (학번, 과목)
  * FD 1: (학번, 과목) ──► 담당교수 (후보키에 종속, 3NF 만족!)
  * FD 2: 담당교수 ──────► 과목     (결정자 '담당교수'는 후보키가 아님! -> BCNF 위배!)

                        ┌───────────────────────────────┐
                        │ R (학번, 과목, 담당교수)      │
                        └──────────────┬────────────────┘
                                       │ 비후보키 결정자 '담당교수' 기준 분해!
          ┌────────────────────────────┴────────────────────────────┐
          ▼                                                         ▼
  ┌───────────────────────────────┐         ┌───────────────────────────────┐
  │ R1 (담당교수, 과목)           │         │ R2 (학번, 담당교수)           │
  │ - PK: 담당교수                │         │ - PK: (학번, 담당교수)        │
  │ - 모든 결정자가 후보키 (BCNF!)│         │ - 모든 결정자가 후보키 (BCNF!)│
  └───────────────────────────────┘         └───────────────────────────────┘
```

## 핵심 용어
- 결정자(Determinant): 다른 속성의 값을 고유하게 결정짓는 함수적 종속성($X \rightarrow Y$)의 좌변에 위치한 속성 집합($X$)
- 종속성 보존(Dependency Preservation): 릴레이션을 둘 이상으로 분해했을 때, 원래 릴레이션이 가지고 있던 모든 함수적 종속성이 분해된 릴레이션들의 종속성 합집합만으로 온전히 검증될 수 있는 성질

## 핵심 통찰
- 3NF의 정의는 "비주요 속성이 후보키에 기본적으로 종속되어야 한다"이므로, 우변($Y$)이 주속성(후보키의 일부)이면 좌변($X$)이 후보키가 아니어도 3NF는 통과시켜 버리는 맹점이 있음
- BCNF는 이 허점을 메우기 위해 "우변이 주속성이든 뭐든 상관없고, 화살표를 쏘는 좌변($X$)은 무조건 후보키여야만 한다"고 극단적으로 단순하고 엄격하게 정의한 것
- BCNF의 뼈아픈 대가는 '함수 종속성 보존 손실'임 → 위 그림에서 분해 후에는 `(학번, 과목)`이 한 테이블에 없으므로 한 학생이 한 과목을 중복 수강하는지 검증하려면 두 테이블을 매번 조인해야 하는 딜레마 발생

## 이웃 토픽과 구분
- 3NF vs BCNF: 3NF = 결정자가 후보키가 아니더라도 '종속되는 속성이 후보키의 일부(주속성)'이면 허용(종속성 100% 보존) / BCNF = 종속 속성의 성격과 무관하게 '모든 결정자는 반드시 후보키'여야만 함(종속성 보존 깨질 수 있음)

## 문제·원인·대책
- 적용 상황: 대학교 학사 정보 시스템의 수강 신청 및 교수 배정 데이터 모델링
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 특정 교수가 담당 과목을 변경할 때 해당 교수의 모든 학생 수강 레코드를 갱신해야 하는 수정 이상 | (학번, 과목, 교수) 테이블에서 '교수 $\rightarrow$ 과목' 종속성 방치 (BCNF 위배) | (교수, 과목) 테이블과 (학번, 교수) 테이블로 BCNF 무손실 분해 | 갱신 이상 완전 제거 및 교수-과목 매핑 단일화 |
| BCNF 분해 후 학생이 동일 과목을 2명의 교수에게 이중 수강 신청하는 부정 발생 | 분해로 인해 (학번, 과목) 복합 유일성 제약(FD 보존)이 깨짐 | 애플리케이션 수강 신청 서비스 로직 또는 DB 트리거에서 조인 검증 강제 | BCNF 달성과 비즈니스 제약 동시 확보 |

## 내 의견
- [종속성 보존과 BCNF 간의 실무적 우선순위 판단] 데이터 모델러가 BCNF라는 이름에 집착하여 무조건 분해했다가 업무 핵심 제약조건이 깨져 비즈니스 로직 버그를 양산하는 사례 빈발 → 나라면: 함수 종속성을 보존하는 것이 데이터 무결성에 더 결정적인 업무라면 무리하게 BCNF로 가지 않고 3NF 상태를 유지하되 복합 유니크 인덱스를 걸고, 갱신 이상이 더 치명적인 마스터 속성일 때만 선별적으로 BCNF 분해를 단행
