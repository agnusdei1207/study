```text
[데이터 품질관리] ◀━━ 머리: Ⅶ 내 의견 (일회성 정제 지양 → 실시간 데이터 프로파일링 및 DataOps 파이프라인 내재화)
 ┃
 ┣━ Ⅰ 개요 ───── Garbage In, Garbage Out 리스크 → 데이터 신뢰성 확보를 위한 지속적 관리 체계
 ┣━ Ⅱ 특징 ───── 비즈니스 관점 연계 · 지속적 모니터링 · 표준화 기반 · 데이터 생명주기 전반 관리
 ┣━ Ⅲ 구조 ───── 품질관리 조직 / 프로세스 / 품질 기준(표준) / 지원 도구(프로파일링·정제)
 ┣━ Ⅳ 흐름 ───── ① 대상 선정 → ② 품질 진단(프로파일링) → ③ 오류 분석 → ④ 정제 및 개선
 ┣━ Ⅴ 비교 ───── 데이터 값 품질(정확성·유효성) vs 데이터 구조 품질(정규화·표준화)
```

## 한 줄 본질
- 결측·이상·불일치 데이터로 인한 의사결정 및 AI 모델 왜곡 → 측정 지표와 프로파일링 도구로 오류를 상시 탐지·개선 → 고품질 데이터 자산 확보 / 지속적인 거버넌스 유지 관리 비용 수반

## 핵심 그림
```text
  [품질 기준] (표준도메인/업무규칙)
       │
       ▼
 [데이터 프로파일링] ──(이상 탐지)──> [오류 데이터 분석]
       ▲                                     │
       │                                     ▼
 [지속 모니터링] <──(표준화/규칙반영)── [데이터 정제/보정]
```

## 핵심 용어
- 데이터 프로파일링: 데이터 세트의 실제 값 분포, 패턴, 널(Null) 비율, 유일성을 통계적으로 스캔하여 데이터 현황을 파악하는 활동
- 완전성(Completeness): 데이터에 필요한 필수 항목이 누락(Null 또는 공백)되지 않고 온전히 존재하는 비율

## 핵심 통찰
- 품질관리는 사후 정제가 아니라 원천 입력 통제여야 함 → DB에 잘못 들어간 데이터를 배치로 고치는 비용은 입력 UI/API 단계에서 제약조건으로 막는 비용의 10배 이상
- 데이터 값만 맞다고 끝이 아님 → 표준 단어·용어·도메인이 일치해야 시스템 간 연계 시 조인 오류나 왜곡이 발생하지 않음
- AI 시대의 데이터 품질은 모델 성능을 결정짓는 핵심 상한 → 데이터 라벨링 오류 1%가 모델 추론 정확도를 수 %포인트 떨어뜨림

## 딸려 나오는 하위 토픽
| 하위 토픽 | 상위 구조 속 위치 | 한 줄 |
|---|---|---|
| DQI (Data Quality Index) | 품질 측정 지표 | 정확성, 완전성, 일관성, 유효성, 시의성 등 품질 평가 척도 |
| 공공데이터 품질인증 | 제도적 기반 | 공공기관의 데이터베이스 품질 관리 수준을 심사·인증하는 제도 |

## 이웃 토픽과 구분
- 데이터 품질관리(DQM) vs 데이터 거버넌스: 거버넌스 = 정책·조직·표준 등 최상위 통제 체계 / DQM = 거버넌스 하위에서 실제 데이터의 오류를 측정하고 개선하는 실행 프레임워크

## 문제·원인·대책
- 적용 상황: 금융 거래 원장 및 차세대 데이터 마이그레이션 프로젝트
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 시스템 간 고객 정보 불일치로 인한 거래 오류 | 원천 시스템마다 도메인 규격 및 코드 체계 상이 | 전사 메타데이터 관리 시스템 구축 및 마스터 데이터(MDM) 동기화 | 단일 고객 뷰(Single View) 확보 |
| 신규 기능 배포 후 분석계 배치 중단 | 운영계 DB 컬럼 타입 임의 변경 | CI/CD 파이프라인에 데이터 계약(Data Contract) 검증 자동화 | 스키마 변경 시 사전 경고 및 하위 호환성 유지 |
