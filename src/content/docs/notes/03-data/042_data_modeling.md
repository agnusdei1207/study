## 답안 골격
```text
[데이터 모델링] ◀━━ 머리: Ⅶ 내 의견 (개념·논리 모델의 비즈니스 규칙 추적성 확보 + 형상관리 자동화)
 ┃
 ┣━ Ⅰ 개요 ───── 복잡한 업무 요건과 실세계 데이터를 정형화된 DB 구조로 추상화·체계화하는 엔지니어링 과정
 ┣━ Ⅱ 특징 ───── 3단계 계층화(개념→논리→물리) · 단일 진실 공급원(SSOT) 지향 · 업무 규칙 반영 · 데이터 무결성 보장
 ┣━ Ⅲ 구조 ───── 엔터티(Entity) / 속성(Attribute) / 관계(Relationship) / 식별자(Identifier)
 ┣━ Ⅳ 흐름 ───── ① 개념 모델링(핵심 엔터티 도출) → ② 논리 모델링(정규화·M:N 해소) → ③ 물리 모델링(반정규화·인덱스·파티션)
 ┣━ Ⅴ 비교 ───── 논리 모델링 vs 물리 모델링 (DBMS 독립적 업무 구조화 vs DBMS 종속적 성능 최적화)
 ┗━ Ⅵ 실무 ───── M:N 직접 연결로 인한 매핑 불가 / 과도한 정규화에 따른 조인 부하 / 식별자 상속 남발
```
- 필수 키워드: 개념 모델링 · 논리 모델링 · 물리 모델링 · 엔터티 · 속성 · 관계 · 정규화 · 반정규화
- 배점 전략: 10점 = Ⅰ → Ⅳ 3단계 수직 흐름도 → Ⅴ 논리/물리 비교표 / 25점 = Ⅰ~Ⅶ, Ⅲ 3대 요소 매핑 및 Ⅳ 3단계 전환 상세
- 기출: 133회 4교시 4번 `RDBMS 적용 데이터 모델링` → Ⅳ 3단계 절차 및 Ⅴ 논리/물리 전환 기법

## 한 줄 본질
- 실세계 업무 규칙의 모호성과 복잡성 → 개념·논리·물리의 3단계 계층적 추상화 및 정규화 수행 → 비즈니스 무결성과 시스템 조회 성능의 최적 균형 달성

## 핵심 그림
```text
[데이터 모델링 3단계 계층 구조]

  현실 세계 (업무 요구사항)
      │
      ▼
 ┌───────────────┐
 │ 개념 모델링   │ : 주제 영역 정의, 핵심 엔터티(Core Entity) 도출, ERD 골격
 └───────┬───────┘
         ▼
 ┌───────────────┐
 │ 논리 모델링   │ : 정규화(1NF~BCNF), 식별자 정의, M:N 해소(매핑 테이블), 속성 정의
 └───────┬───────┘   * DBMS 독립적
         ▼
 ┌───────────────┐
 │ 물리 모델링   │ : 테이블·컬럼 변환, 데이터 타입, 인덱스·파티셔닝, 반정규화
 └───────────────┘   * 특정 DBMS 종속적
```

## 핵심 용어
- 주식별자(Primary Identifier): 엔터티 내 인스턴스를 고유하게 구분하며 불변성과 최소성을 만족하는 속성
- 관계 차수(Cardinality): 두 엔터티 간 관계에 참여하는 인스턴스의 수(1:1, 1:N, M:N)

## 핵심 통찰
- 논리 모델은 업무의 진실을 기록하고, 물리 모델은 컴퓨터의 한계를 수용함 → 논리 단계에서 성능을 핑계로 비정규화를 섞으면 업무 규칙이 오염되어 장기적 유지보수 불능
- M:N 관계는 논리 모델에서 반드시 교차(Associative) 엔터티로 분해되어야 RDBMS 물리 테이블로 전환 가능
- 식별 관계와 비식별 관계의 선택은 부모 변경 주기와 복합키 전파 비용에 따라 결정 → 깊은 식별 관계는 자식 테이블의 주키 폭증 초래

## 딸려 나오는 하위 토픽
| 하위 토픽 | 상위 구조 속 위치 | 한 줄 |
|---|---|---|
| 정규화(Normalization) | 논리 모델링의 핵심 활동 | 데이터 중복을 제거하여 삽입·삭제·갱신 이상을 원천 차단하는 단계적 분해 |
| 반정규화(Denormalization) | 물리 모델링의 성능 조정 | 잦은 조인으로 인한 디스크 I/O 병목 해소를 위해 의도적으로 중복·통합을 허용 |

## 이웃 토픽과 구분
- 데이터 모델링 vs 데이터 아키텍처: 데이터 모델링 = 개별 업무 도메인의 데이터 구조 설계 / 데이터 아키텍처 = 전사 데이터 거버넌스·표준·인프라 전반의 마스터 플랜

## 문제·원인·대책
- 적용 상황: 차세대 코어 뱅킹 계정계 데이터 모델링
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 특정 거래 조회 쿼리 시 10개 테이블 조인으로 타임아웃 | 논리 모델의 완벽한 3NF 구조를 물리 DB에 그대로 배포 | 통계·집계 컬럼 추가 및 이력 테이블 수평 파티셔닝 | 조인 횟수 감소로 쿼리 응답시간 80% 단축 |
| 주문 취소 시 고객의 잔여 마일리지 정합성 불일치 | 논리 모델링 단계에서 엔터티 간 무결성 비즈니스 규칙 누락 | 체크 제약조건 및 외래키 참조 무결성(FK), 도메인 규칙 정의 | 트랜잭션 단위 정합성 유지 |
