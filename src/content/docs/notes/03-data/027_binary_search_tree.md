## 답안 골격
```text
[트리·이진 탐색 트리] ◀━━ 머리: Ⅶ 내 의견 (BST 편향 한계 인정 → 자가 균형 트리(Red-Black/AVL) 또는 접두사 트리(Trie) 적용)
 ┃
 ┣━ Ⅰ 개요 ───── 비선형 계층 자료구조(트리)와 정렬된 탐색 구조(BST) → $O(\log n)$의 고속 탐색·삽입·삭제 지원
 ┣━ Ⅱ 특징 ───── 계층적 순서성 · 왼쪽 < 루트 < 오른쪽 속성 · 중위 순회 시 오름차순 정렬 · 편향 시 $O(n)$ 성능 저하
 ┣━ Ⅲ 구조 ───── 노드 구조(데이터, 좌/우 포인터) / 순회 방식(전위·중위·후위·레벨) / 자가 균형 트리(AVL, Red-Black)
 ┣━ Ⅳ 흐름 ───── ① 루트와 키 비교 → ② 작으면 좌측 서브트리 이동 → ③ 크면 우측 서브트리 이동 → ④ 일치 시 반환 (재귀/반복)
 ┣━ Ⅴ 비교 ───── 이진 탐색 트리(BST) vs 자가 균형 트리(AVL/Red-Black) vs B-Tree vs Trie(라우팅 테이블)
 ┗━ Ⅵ 실무 ───── 정렬된 데이터 순차 삽입 시 경사 트리(Skewed Tree) 퇴화 / 네트워크 라우팅 롱기스트 매칭 한계
```

## 한 줄 본질
- 노드의 좌우 대소 관계를 정렬하여 탐색 범위를 매 단계 절반으로 축소 → 평균 $O(\log n)$으로 빠른 데이터 검색과 갱신 보장 / 정렬된 데이터 입력 시 한쪽으로 치우쳐 $O(n)$ 선형 리스트로 퇴화하는 위험 상존

## 핵심 그림
```text
[이상적인 균형 BST vs 편향된 경사 트리]

      [균형 BST (O(log n))]                   [편향 트리 (O(n) 퇴화)]
             [ 50 ]                                  [ 10 ]
            /      \                                   \
        [ 30 ]    [ 70 ]                                [ 20 ]
        /    \    /    \                                  \
     [20]   [40][60]   [80]                                [ 30 ]
   (좌 < 루트 < 우 조건 만족)                                  \
                                                              [ 40 ]
                                                      (10,20,30,40 순차 삽입 시)
```

## 핵심 용어
- 경사 트리(Skewed Tree): 데이터가 오름차순이나 내림차순으로 정렬되어 들어와 한쪽 방향으로만 자식 노드가 생성되어 연결 리스트처럼 변질된 트리
- 최장 일치 접두사(LPM, Longest Prefix Match): IP 라우팅 테이블에서 패킷의 목적지 IP와 서브넷 마스크가 가장 길게 일치하는 경로를 탐색하는 알고리즘

## 핵심 통찰
- 단순 BST는 실무 시스템에서 그대로 쓰이지 않음 → 실무에서는 데이터가 정렬되어 유입되는 경우가 흔하므로 스스로 회전(Rotation)하여 균형을 맞추는 Red-Black 트리(Java HashMap, C++ STL map)를 기본 채택
- 디스크 기반 인덱스에는 BST 대신 B-Tree를 사용함 → BST는 노드당 자식이 2개라 트리의 높이가 높아 디스크 I/O가 잦지만, B-Tree는 수백 개의 자식을 두어 트리의 높이를 3~4 이내로 유지
- 네트워크 라우팅 테이블에서는 일반 BST 대신 1과 0 비트 단위로 분기하는 '트라이(Trie)' 또는 '패트리샤 트리(Radix Tree)'를 사용해 LPM 탐색 속도 극대화

## 딸려 나오는 하위 토픽
| 하위 토픽 | 상위 구조 속 위치 | 한 줄 |
|---|---|---|
| 트리 순회(Tree Traversal) | 트리 방문 알고리즘 | 전위(루트-좌-우), 중위(좌-루트-우, 오름차순), 후위(좌-우-루트), 레벨(너비우선) |
| Red-Black 트리 | 자가 균형 이진 탐색 트리 | 노드를 Black과 Red로 칠하고 회전하여 최장 경로가 최단 경로의 2배를 넘지 않게 제한 |

## 이웃 토픽과 구분
- 이진 탐색 트리(BST) vs 이진 힙(Binary Heap): BST = 좌 < 루트 < 우 정렬로 모든 원소 탐색용 / 이진 힙 = 부모가 자식보다 크거나 작은 구조로 최댓값/최솟값 즉시 추출(우선순위 큐)용

## 문제·원인·대책
- 적용 상황: 고속 코어 라우터의 수십만 개 라우팅 테이블 경로 탐색 (FIB)
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 라우팅 테이블 엔트리가 증가할 때마다 패킷 포워딩 지연시간 선형 급증 | 일반 BST 적용 시 최악 탐색 시간 $O(n)$ 및 비트 매칭 비효율 | 2진 접두사 트리(Binary Trie) 및 LC-Trie(레벨 압축 트라이) 적용 | 32비트 IPv4 기준 고정된 고속 LPM 탐색 보장 |
| 순차 증가하는 회원 ID를 BST에 넣었더니 검색 속도가 100배 저하 | 데이터 정렬 입력으로 인한 우경사 트리 퇴화 ($O(n)$화) | Red-Black 트리 또는 AVL 자가 균형 트리로 교체 | 최악의 경우에도 $O(\log n)$ 탐색 시간 보장 |

## 내 의견
- [자료구조의 이론과 시스템 구현의 괴리] 단순 BST 탐색 알고리즘만 암기하고 실제 네트워크 하드웨어의 TCAM(Ternary Content Addressable Memory)이나 Radix 트리 구현을 이해하지 못하는 답안 다수 → 나라면: 소프트웨어 라우팅 엔진에서는 압축 트라이(Radix)로 메모리 효율과 탐색 속도를 잡고, 고속 하드웨어 라우터에서는 $O(1)$의 병렬 탐색이 가능한 TCAM을 사용하는 2계층 아키텍처 관점으로 서술
