## 답안 골격
```text
[확장성 해싱] ◀━━ 머리: Ⅶ 내 의견 (디렉터리 2배 팽창에 따른 메모리 급증 모니터링 및 버킷 용량 튜닝)
 ┃
 ┣━ Ⅰ 개요 ───── 데이터 증가 시 전체 테이블 재해싱 없이 버킷을 동적으로 분할·확장하는 동적 해싱(Dynamic Hashing) 기법
 ┣━ Ⅱ 특징 ───── 디렉터리 기반 간접 참조 · 모조키(Pseudo Key) 비트 접두사 사용 · 국소적 버킷 분할 · 최대 2회 디스크 I/O 탐색
 ┣━ Ⅲ 구조 ───── 글로벌 깊이(Global Depth, $d$) / 디렉터리(Directory) / 로컬 깊이(Local Depth, $d'$) / 데이터 버킷(Bucket)
 ┣━ Ⅳ 흐름 ───── ① 키 해싱 모조키 생성 → ② $d$개 비트로 디렉터리 인덱싱 → ③ 버킷 오버플로우 발생 → ④ $d' < d$면 버킷만 분할, $d' = d$면 디렉터리 2배 확장
 ┣━ Ⅴ 비교 ───── 확장성 해싱 vs 선형 해싱 (디렉터리 사용/비트 접두사 분할 vs 디렉터리 없음/포인터 기반 순차 분할)
 ┗━ Ⅵ 실무 ───── 해시 충돌 집중 시 디렉터리 크기 지수적 폭증 / 비트 패턴 편향에 따른 메모리 낭비
```
- 필수 키워드: 동적 해싱 · 디렉터리 · 버킷(Bucket) · 글로벌 깊이(Global Depth) · 로컬 깊이(Local Depth) · 모조키(Pseudo Key) · 버킷 분할
- 배점 전략: 10점 = Ⅰ → Ⅲ 디렉터리-버킷 매핑 도식 → Ⅳ 오버플로우 분할 조건 / 25점 = Ⅰ~Ⅶ, Ⅳ 단계별 분할 과정 및 Ⅴ 선형 해싱 비교표
- 기출: 135회 4교시 1번 `확장성 해싱(Extendible Hashing) 기법` → Ⅰ 개념 + Ⅲ 구성요소 + Ⅳ 동작 메커니즘 및 분할 절차

## 한 줄 본질
- 정적 해싱의 오버플로우 체인 및 전수 재해싱(Rehashing) 병목 → 디렉터리와 버킷의 깊이($d, d'$)를 분리해 넘치는 버킷만 국소적으로 쪼개고 필요 시 디렉터리만 2배 확장 → 균일한 $O(1)$ 탐색 / 디렉터리 메모리 비용 수반

## 핵심 그림
```text
[확장성 해싱의 구조 및 버킷 분할]

  글로벌 깊이 (d = 2)
  ┌───────────┐
  │디렉터리(4)│
  ├───────────┤           로컬 깊이 (d')
  │ 00 ───────┼──────────> ┌───────┐ (d'=2)
  ├───────────┤            │ 버킷A │ [0010, 0011]
  │ 01 ───────┼──┐         └───────┘
  ├───────────┤  │
  │ 10 ───────┼──┼───────> ┌───────┐ (d'=1)  <-- 01과 11이 공유
  ├───────────┤  └────────>│ 버킷B │ [0101, 1100]
  │ 11 ───────┼───────────>└───────┘
  └───────────┘
   * 버킷 B가 넘칠 때 (d'=1 < d=2):
     디렉터리 확장 없이 버킷 B만 2개로 분할하고 로컬 깊이를 2로 증가!
   * 버킷 A가 넘칠 때 (d'=2 = d=2):
     글로벌 깊이를 3으로 늘려 디렉터리를 8개로 2배 확장 후 분할!
```

## 핵심 용어
- 글로벌 깊이(Global Depth, $d$): 디렉터리에서 버킷을 구별하기 위해 사용하는 해시 비트 수 ($2^d$개의 엔트리 존재)
- 로컬 깊이(Local Depth, $d'$): 개별 버킷에 저장된 레코드들이 공통으로 공유하는 해시 비트 수

## 핵심 통찰
- 버킷이 꽉 차서 넘쳤다고 무조건 전체 테이블을 건드리지 않음 → 로컬 깊이가 글로벌 깊이보다 작으면($d' < d$) 디렉터리는 가만히 두고 넘친 해당 버킷만 반으로 쪼개서 포인터만 재연결
- 디렉터리 확장은 오직 $d' = d$인 버킷이 넘칠 때만 발생하며, 이때 디렉터리 엔트리 수가 $2^d$에서 $2^{d+1}$로 정확히 2배 점프
- 디렉터리가 주기억장치(RAM)에 상주한다면 데이터 레코드는 단 1회의 디스크 I/O로 탐색 가능

## 딸려 나오는 하위 토픽
| 하위 토픽 | 상위 구조 속 위치 | 한 줄 |
|---|---|---|
| 선형 해싱(Linear Hashing) | 무디렉터리 동적 해싱 | 디렉터리 없이 분할 포인터를 순차적으로 이동시키며 버킷을 하나씩 선형 분할 |
| 모조키(Pseudo Key) | 해시 함수의 출력 비트열 | 원본 검색 키를 해시 함수에 통과시켜 얻은 고정 길이의 이진 비트열 |

## 이웃 토픽과 구분
- 확장성 해싱 vs B+Tree: 확장성 해싱 = 점 검색(Point Query)에 극도로 유리($O(1)$)하나 범위 검색(Range Scan) 불가 / B+Tree = 키 순서 정렬로 범위 검색에 탁월하나 점 검색 복잡도 $O(\log N)$

## 문제·원인·대책
- 적용 상황: 대규모 세션 스토어의 키-값 인메모리 색인
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 특정 해시 비트가 동일한 키들이 집중 유입되어 디렉터리 급팽창 | 해시 함수의 불균일 분포로 특정 버킷에만 충돌 누적 | 균등 분포 특성이 우수한 MurmurHash3 또는 Cryptographic Hash 적용 | 비트 분산 균등화로 비정상 디렉터리 확장 억제 |
| 글로벌 깊이 증가 시 디렉터리 메모리 점유 급증 | $2^d$로 지수 증가하는 디렉터리 테이블 구조 | 버킷 용량(Bucket Capacity)을 상향 조정하여 분할 임계값 완화 | 디렉터리 메모리 오버헤드 50% 절감 |

## 내 의견
- [디렉터리 팽창 폭탄에 대한 예방책 부재] 해시 충돌이 악의적으로 유발될 경우(HashDoS) 글로벌 깊이가 끝없이 올라가 메모리 고갈 장애 유발 → 나라면: 최대 글로벌 깊이 상한선($d_{max}$)을 시스템적으로 설정하고, 상한 도달 시 임시 오버플로우 체인 블록을 연결한 뒤 비동기 재분배를 트리거하도록 안전장치 설계
