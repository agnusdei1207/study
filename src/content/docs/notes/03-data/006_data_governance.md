## 답안 골격
```text
[데이터 거버넌스] ◀━━ 머리: Ⅶ 내 의견 (통제 중심 거버넌스 탈피 → 셀프서비스 지원형 데이터 메쉬 거버넌스 전환)
 ┃
 ┣━ Ⅰ 개요 ───── 데이터 사일로·보안 규제·품질 저하 대응 → 전사 데이터 자산의 통제·활용 체계
 ┣━ Ⅱ 특징 ───── 전사적 통일성 · 원칙/정책 기반 · 역할과 책임(R&R) 명확화 · 생애주기 관리
 ┣━ Ⅲ 구조 ───── 원칙(Principles) / 조직(Organization) / 프로세스(Process) / 기술·도구(IT)
 ┣━ Ⅳ 흐름 ───── ① 비전 및 원칙 수립 → ② 표준화 및 정책 정의 → ③ 조직 R&R 부여 → ④ 상시 운영 및 모니터링
 ┣━ Ⅴ 비교 ───── 전통적 IT 거버넌스 vs 데이터 거버넌스 vs 데이터 메쉬(Federated)
 ┗━ Ⅵ 실무 ───── 현업 부서 간 데이터 소유권 갈등 / 규제 준수(컴플라이언스) 부하 / 데이터 섀도우화
```
- 필수 키워드: DAMA-DMBOK · 데이터 스튜어드(Steward) · 메타데이터 · 마스터데이터(MDM) · 데이터 카탈로그 · R&R
- 배점 전략: 10점 = Ⅰ → Ⅲ 4대 구성요소 프레임워크 → Ⅵ 한 행 / 25점 = Ⅰ~Ⅶ, 앞 1/3에 Ⅲ 체계도 및 조직 R&R
- 기출: 130회 `데이터 거버넌스` → Ⅰ 개념 + Ⅲ 구성요소 + Ⅳ 절차 / 124회 `데이터 주권과 데이터 거버넌스 전략 방향` → Ⅵ 전략적 활용과 보안 통제

## 한 줄 본질
- 개별 부서별로 파편화된 데이터 사일로와 규제 위반 위험 → 정책·조직·프로세스·IT 도구의 전사적 통합 관리 체계 확립 → 데이터 신뢰성 확보 및 활용 효율화 / 현업의 자율성 축소 및 초기 통제 비용 발생

## 핵심 그림
```text
         [전사 비즈니스 전략 & 규제 컴플라이언스]
                           │
      ┌────────────────────┼────────────────────┐
      ▼                    ▼                    ▼
[정책 및 원칙]        [조직 및 R&R]         [프로세스]
- 표준 정책(단어/코드) - CDO / 위원회      - 수집/저장/폐기
- 보안/접근 통제       - Data Steward        - 변경 승인 절차
      └────────────────────┬────────────────────┘
                           │
                           ▼
          [기술 인프라 (메타데이터/MDM/카탈로그)]
```

## 핵심 용어
- Data Steward(데이터 스튜어드): 특정 비즈니스 도메인의 데이터 정의, 품질 기준 수립, 활용 승인 권한을 가진 현업 담당자
- 메타데이터 관리 시스템: 데이터 명칭, 포맷, 도메인 규칙, 테이블 간 관계 및 계보(Lineage) 정보를 통합 관리하는 저장소

## 핵심 통찰
- 데이터 거버넌스는 IT 부서의 프로젝트가 아님 → 현업 비즈니스 부서가 데이터 소유권(Ownership)을 갖지 않으면 등록된 메타데이터는 6개월 내 박제화
- 강력한 중앙 통제는 데이터 혁신을 지연시킴 → 중앙에서 모든 쿼리와 테이블 생성을 승인하려 들면 현업은 섀도우 IT(로컬 엑셀)로 이탈
- 거버넌스의 성공 지표는 '통제 건수'가 아니라 '데이터 탐색 시간 단축'이어야 함 → 카탈로그 검색 한 번으로 원하는 데이터의 위치, 신뢰도, 소유자를 즉시 찾을 수 있어야 함

## 딸려 나오는 하위 토픽
| 하위 토픽 | 상위 구조 속 위치 | 한 줄 |
|---|---|---|
| DAMA-DMBOK | 데이터 관리 표준 지식체계 | 데이터 아키텍처, 거버넌스, 품질 등 11개 지식 영역을 정의한 글로벌 표준 프레임워크 |
| 데이터 계보(Lineage) | 메타데이터 추적 도구 | 원천 시스템부터 최종 대시보드까지 데이터의 가공·이동 경로를 시각적으로 추적 |

## 이웃 토픽과 구분
- 데이터 거버넌스 vs 데이터 관리(Data Management): 거버넌스 = '무엇을, 누가, 어떤 규칙으로 할 것인가' 결정하는 통제권 / 관리는 = 그 규칙에 따라 실제로 인프라를 운영하고 ETL을 돌리는 실행 행위

## 문제·원인·대책
- 적용 상황: 금융 지주사 내 계열사 간 데이터 결합 및 통합 마케팅 플랫폼 구축
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 동일 고객에 대해 계열사마다 서로 다른 ID 및 명칭 사용 | 전사 통합 식별자 체계 및 마스터데이터 거버넌스 부재 | MDM(Master Data Management) 도입 및 골든 레코드(Golden Record) 생성 | 고객 단일 뷰 완성 |
| 규제 감사 시 개인정보 활용 근거 및 이동 경로 소명 불가 | 수동 파이프라인 관리로 인한 데이터 계보 부재 | 데이터 카탈로그 기반 자동 계보(Lineage) 추적기 구축 | 감사 대응 시간 단축 및 컴플라이언스 만족 |

## 이렇게 출제된다
- 제130회 1교시 4번: "데이터 거버넌스" → 요구 포인트: Ⅰ 개념 + Ⅲ 프레임워크 구성요소 + Ⅵ 실무 추진 전략
- 제124회 2교시 1번: "코로나-19(Covid-19)로 인한 언택트 시대의 데이터 주권 이슈와 데이터 거버넌스 전략 방향" → 요구 포인트: 데이터 주권 보호 및 활용 중심 거버넌스 체계

## 내 의견
- [중앙집권적 관료주의 거버넌스의 파산] 중앙 데이터 팀의 승인 병목으로 현업 분석이 2~3주씩 지연 → 나라면: 도메인 팀이 데이터 제품(Data Product)을 직접 생산·관리하고, 중앙 거버넌스 위원회는 보안·표준 정책의 자동화 가드레일만 제공하는 'Federated Computational Governance(연합 연산형 거버넌스)' 체계로 이행
