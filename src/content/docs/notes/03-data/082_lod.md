## 답안 골격
```text
[LOD (Linked Open Data)] ◀━━ 머리: Ⅶ 내 의견 (온톨로지 전면 구축 대신 도메인 핵심 엔티티 중심 5-Star 단계적 개방)
 ┃
 ┣━ Ⅰ 개요 ───── 웹상에 공개된 데이터를 단순히 다운로드하는 것을 넘어, URI와 RDF를 통해 개체 간 의미적 연결(Link)을 제공하는 개방형 시맨틱 데이터
 ┣━ Ⅱ 특징 ───── 4대 원칙(URI/HTTP/RDF·SPARQL/외부링크) · 5-Star 모델 · 기계 판독성(Machine-Readable) · 그래프 구조
 ┣━ Ⅲ 구조 ───── 식별 계층(URI/IRI) / 표현 계층(RDF 트리플) / 스키마 계층(RDFS, OWL) / 질의 계층(SPARQL 엔드포인트)
 ┣━ Ⅳ 흐름 ───── ① 대상 데이터 선정 → ② 식별체계(URI) 정의 → ③ 데이터 모델링(RDF/OWL) → ④ RDF 변환(Triplification) → ⑤ 링크 생성(외부 연결) → ⑥ 개방(SPARQL)
 ┣━ Ⅴ 비교 ───── 오픈 데이터 vs 링크드 오픈 데이터(LOD) (단순 파일 다운로드/단절된 사일로 vs 의미적 상호연결/그래프 질의)
 ┗━ Ⅵ 실무 ───── 링크 파손(Link Rot) / 온톨로지 구축 비용 과다 / 대규모 SPARQL 질의 성능 병목
```
- 필수 키워드: 시맨틱 웹 · 4대 원칙 · 5-Star 모델 · URI · RDF(트리플: 주어-서술어-목적어) · SPARQL · OWL
- 배점 전략: 10점 = Ⅰ → Ⅱ 4대 원칙 및 5-Star 모델 요약 → Ⅲ RDF 구조도 / 25점 = Ⅰ~Ⅶ, Ⅳ LOD 구축 6단계 및 Ⅵ 링크 무결성 유지 관리
- 기출: 122회 `Linked Open Data(LOD)의 개념, 4대 원칙, 5-Star 단계별 모델 및 구축 절차` → Ⅰ 개념 + Ⅱ 원칙/5-Star + Ⅳ 구축 절차

## 한 줄 본질
- 사일로화된 오픈 데이터의 상호 단절 및 기계 판독 불가 한계 → URI 식별자와 RDF 트리플 그래프를 기반으로 글로벌 웹 상의 데이터 간 의미 연결 → 지식 그래프 자동 탐색 / 온톨로지 구축 비용과 SPARQL 질의 지연

## 핵심 그림
```text
[LOD 5-Star 개방 모델 및 RDF 트리플 구조]

 [5-Star 모델]
  ★     : 웹상에 공개 (형식 무관, 예: PDF, JPG)
  ★★    : 구조화된 데이터로 제공 (예: Excel XLS)
  ★★★   : 비독점 개방형 포맷으로 제공 (예: CSV)
  ★★★★  : URI를 부여하여 식별 가능 (RDF, XML 표준)
  ★★★★★ : 다른 사람의 데이터와 의미적 링크 연결 (LOD 달성)

 [RDF 트리플 그래프 구조]
  ┌──────────────┐         predicate (서술어)          ┌──────────────┐
  │ Subject (주어)│ ─────────────────────────────────> │Object (목적어)│
  │  (ex: 저자)  │   ex: http://xmlns.com/foaf/0.1/   │  (ex: 책)    │
  └──────────────┘                                     └──────────────┘
         │                                                    │
         ▼ owl:sameAs                                         ▼
  [DBpedia URI]                                        [국립중앙도서관 URI]
```

## 핵심 용어
- RDF 트리플(Triple): 모든 지식을 주어(Subject), 서술어(Predicate), 목적어(Object)의 3요소 관계로 표현하는 W3C 시맨틱 웹 표준
- SPARQL: RDF 그래프 데이터베이스(트리플스토어)를 검색하기 위한 W3C 표준 질의 언어

## 핵심 통찰
- LOD의 가치는 '데이터 자체의 양'이 아니라 '연결(Linkage)'에서 발생함 → 고립된 100만 건 RDF보다 DBpedia, Wikidata의 외부 URI와 `owl:sameAs`로 단 1만 건 연결된 데이터가 시맨틱 추론에서 기하급수적 가치를 창출
- 5-Star 모델에서 3성(CSV)에서 4성(RDF)으로 넘어가는 진입 장벽이 가장 높음 → URI 체계 수립과 트리플 변환(Triplification)에 상당한 인력과 도구 비용 소요
- 공공 LOD의 가장 흔한 실패 요인은 '지속적 링크 관리 실패'임 → 외부 엔티티의 URI가 변경되거나 사라지면 시맨틱 그래프 탐색이 중간에 단절되는 댕글링 링크(Dangling Link) 발생

## 이웃 토픽과 구분
- 오픈 데이터 vs 링크드 오픈 데이터: 오픈 데이터 = 누구나 자유롭게 이용 가능한 원시 데이터(주로 CSV, JSON 다운로드) / LOD = 개방된 데이터에 W3C 시맨틱 기술을 적용해 다른 데이터와 글로벌하게 연결된 그래프 데이터

## 문제·원인·대책
- 적용 상황: 국가 공공데이터 포털의 지자체 문화관광 데이터 통합 연계
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 각 지자체별 동일 문화재 명칭이 달라 통합 검색 및 연계 분석 불가 | 독립적 DB 설계로 고유 ID가 사일로화되어 상호 참조 불가 | 국립중앙박물관 및 공공 URI 식별체계 도입 및 `owl:sameAs` 연결 | 단일 SPARQL 질의로 전국 연계 문화재 정보 일괄 탐색 |
| 외부 연계 기관의 시스템 개편 후 SPARQL 쿼리가 끊어지는 링크 파손 발생 | 외부 데이터셋 URI 변경에 대한 변경 감지 모니터링 부재 | 링크 무결성 검증 배치 스크립트 주기적 실행 및 영구 식별자(PURL) 사용 | 링크 생존율 99% 유지 및 댕글링 참조 자동 탐지 |

## 이렇게 출제된다
- 제122회: "시맨틱 웹의 핵심 기술인 LOD(Linked Open Data)의 개념과 팀 버너스 리의 4대 원칙, 그리고 데이터 개방의 5-Star 모델을 설명하시오." → 요구 포인트: Ⅰ LOD 정의 + Ⅱ 4대 원칙(URI, HTTP, RDF/SPARQL, 외부연결) + 5-Star 성숙도 모델 + Ⅲ RDF/SPARQL 아키텍처

## 내 의견
- [모든 데이터를 5-Star로 올리려는 욕심 배제] 처음부터 모든 기관 데이터를 RDF/OWL로 전면 변환하려다 프로젝트 기간과 예산이 소진되어 1회성 사업으로 끝나는 경우가 대다수 → 나라면: 기본 데이터는 3성(CSV, JSON API)으로 빠르게 개방하여 현업 활용도를 극대화하고, 기관 간 핵심 교차 식별자(사업자등록번호, 법정동코드 등)에 대해서만 우선적으로 URI를 부여해 단계적으로 5성으로 진화시키는 현실적 전략 채택
