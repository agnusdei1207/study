- 정형·반정형·비정형 데이터가 사내외 클라우드에 흩어져 단일 물리 저장소 적재가 물리적으로 불가능 → 시맨틱 가상화 계층을 두어 물리 저장소를 은닉하고 통합된 비즈니스 뷰를 제공 → 전사 데이터 사일로 해소 / 쿼리 복잡도 증가 시 성능 튜닝 난해

## 핵심 용어
- 시맨틱 레이어(Semantic Layer): 물리적 테이블과 컬럼의 복잡한 기술 명칭을 현업 비즈니스 용어(예: '당월 매출', '이탈 고객')로 추상화하여 비전문가도 쉽게 질의하게 돕는 논리 계층
- 데이터 패브릭(Data Fabric): 메타데이터와 지식 그래프를 활용하여 온프레미스와 멀티 클라우드 전반의 데이터를 자동 발견·연결·추천하는 지능형 데이터 아키텍처(LDW의 발전형)

## 핵심 통찰
- LDW는 기존의 물리적 DW나 데이터 레이크를 '대체'하는 것이 아니라 '포용'하는 상위 아키텍처임 → 이미 잘 돌고 있는 고성능 물리 DW는 그대로 두고, 새롭게 유입되는 빅데이터 레이크나 클라우드 SaaS를 가상화로 덧붙이는 것
- LDW 성공의 열쇠는 '시맨틱 레이어의 일관성'임 → 동일한 매출 계산식이 재무팀, 영업팀, 마케팅팀 쿼리에서 서로 다르게 해석되지 않도록 논리 뷰 레벨에서 비즈니스 로직을 중앙 집중화
- 최근의 LDW는 Trino 같은 오픈소스 분산 엔진과 Apache Iceberg 같은 오픈 테이블 포맷이 결합하여, 과거 상용 벤더의 한계를 넘어 엔터프라이즈 표준으로 안착

## 이웃 토픽과 구분
- 로지컬 DW vs 데이터 메시(Data Mesh): 로지컬 DW = 중앙 집중식 가상화 계층을 통해 전사 단일 뷰를 제공하는 '기술 및 아키텍처' 중심 접근 / 데이터 메시 = 도메인 팀별로 데이터 제품을 분산 소유하는 '조직 및 거버넌스' 중심 접근

## 문제·원인·대책
- 적용 상황: 글로벌 제조 기업의 10개 해외 법인 분산 데이터 통합 분석
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 법인별 소스 DB 간 날짜 및 통화 포맷 불일치로 집계 데이터 왜곡 | 가상화 계층의 공통 데이터 타입 변환 규칙 누락 | 시맨틱 레이어에서 ISO 표준 일시 및 통화 변환 함수 템플릿 강제 | 데이터 정합성 오류 제로화 |
| 특정 대시보드 새로고침 시 5개 대륙의 DB 노드로 동시 쿼리가 유입되어 네트워크 지연 | 가상화 계층의 결과 캐싱 부재 및 매 쿼리 실시간 원천 호출 | 자주 사용되는 집계 결과에 대해 인메모리 구체화 뷰(Materialized View) 자동 생성 | 대시보드 로딩 시간 30초에서 0.5초로 98% 단축 |
