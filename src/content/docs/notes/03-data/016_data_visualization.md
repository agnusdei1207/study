## 답안 골격
```text
[데이터 시각화] ◀━━ 머리: Ⅶ 내 의견 (화려한 차트 나열 지양 → 시각적 채널 인지 부하 최소화 및 액션 유도형 대시보드 구축)
 ┃
 ┣━ Ⅰ 개요 ───── 텍스트·수치 중심의 인지 한계 극복 → 그래픽 요소를 통해 패턴·트렌드·이상치를 직관적으로 전달
 ┣━ Ⅱ 특징 ───── 시각적 인지 채널 활용 · 패턴 즉시 식별(전주의적 속성) · 의사결정 속도 단축
 ┣━ Ⅲ 구조 ───── 시각화 프로세스(7단계) / 시각화 유형(시간·비교·공간·관계) / 시각적 인코딩(위치·길이·색상)
 ┣━ Ⅳ 흐름 ───── ① 데이터 획득 → ② 구조화(파싱) → ③ 필터링 → ④ 데이터 마이닝 → ⑤ 시각적 매핑 → ⑥ 렌더링 → ⑦ 상호작용
 ┣━ Ⅴ 비교 ───── 탐색적 시각화(EDA) vs 설명적 시각화(Storytelling)
 ┗━ Ⅵ 실무 ───── 차트 왜곡(축 조작으로 착시 유도) / 과도한 정보량으로 인한 인지 부하 / 반응형 렌더링 지연
```
- 필수 키워드: 벤 프라이(Ben Fry) 7단계 · 시각적 인코딩(Visual Encoding) · 전주의적 속성(Preattentive) · 탐색적 vs 설명적 · 왜곡 계수
- 배점 전략: 10점 = Ⅰ → Ⅲ 시각화 7단계 및 시각적 인코딩 순위 도식 → Ⅵ 한 행 / 25점 = Ⅰ~Ⅶ, 앞 1/3에 Ⅲ 프로세스 및 Ⅴ 시각화 기법 매핑
- 기출: 135회 `빅데이터 시각화` → Ⅲ 빅데이터 시각화 기술 및 절차 / 131회 `데이터 시각화` → Ⅰ 개념 + Ⅲ 원리 및 유형

## 한 줄 본질
- 표 형태의 수치 나열이 주는 높은 뇌 인지 부하 → 위치, 길이, 색상 등 인간의 시각적 인코딩 채널로 즉시 변환 → 숨겨진 비즈니스 인사이트 발견 촉진 / 축 왜곡 및 색상 오용으로 인한 사실 왜곡 위험 방지

## 핵심 그림
```text
[시각적 인코딩 채널의 정확도 순위 (Cleveland & McGill)]
 가장 정확  위치 (Position)        ──> 막대 차트, 산점도
    │       길이 (Length)          ──> 막대 차트
    │       각도/기울기 (Angle)    ──> 원형(파이) 차트
    │       면적 (Area)            ──> 버블 차트
    ▼       색상 채도/명도 (Color) ──> 히트맵
 덜 정확    부피 (Volume)          ──> 3D 차트 (인지 왜곡 극심, 지양)
```

## 핵심 용어
- 전주의적 속성(Preattentive Attribute): 주의를 기울여 생각하기 전에 인간의 뇌가 0.2초 이내에 무의식적으로 인지하는 시각적 특징(색상 차이, 크기, 길이, 방향 등)
- 왜곡 계수(Lie Factor): 에드워드 터프티(Edward Tufte)가 제시한 지표로, 그래픽에서 표시된 효과 크기를 데이터의 실제 효과 크기로 나눈 비율(1에 가까워야 진실함)

## 핵심 통찰
- 원형(Pie) 차트는 최악의 시각화 중 하나임 → 인간의 뇌는 각도나 면적의 차이를 비교하는 데 둔감하므로, 3개 이상의 항목을 비교할 때는 위치와 길이를 사용하는 막대(Bar) 차트가 압도적으로 정확함
- 3D 차트는 정보 전달을 방해하는 '차트정크(Chartjunk)'임 → 원근법으로 인해 뒤에 있는 큰 데이터가 앞의 작은 데이터보다 작게 왜곡되어 보임
- Y축의 기준점(Baseline)을 0이 아닌 값으로 자르면 작은 차이가 극적인 변화처럼 왜곡됨 → 진실된 정보 전달을 위해 막대 차트는 반드시 0에서 시작해야 함

## 딸려 나오는 하위 토픽
| 하위 토픽 | 상위 구조 속 위치 | 한 줄 |
|---|---|---|
| 앤스컴 콰르텟(Anscombe's Quartet) | 시각화 필요성 증명 | 평균·분산·상관계수가 완전히 동일하지만 시각화하면 전혀 다른 4개의 데이터셋 |
| 대화형 시각화 (Interactive) | 상호작용 기능 | 줌, 팬, 드릴다운, 브러싱 & 링킹을 통해 분석가가 능동적으로 데이터 탐색 |

## 이웃 토픽과 구분
- 탐색적 시각화(EDA) vs 설명적 시각화: 탐색적 = 분석가가 가설을 찾기 위해 데이터와 상호작용하는 과정 / 설명적 = 발견된 핵심 통찰을 의사결정권자에게 설득하기 위한 스토리텔링 대시보드

## 문제·원인·대책
- 적용 상황: 경영진 실시간 경영 지표(KPI) 모니터링 대시보드
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 한 화면에 20개 차트를 배치하여 핵심 지표 인지 실패 | 대시보드 설계 원칙 부재 및 정보 과부하 | 핵심 KPI 3~5개만 상단 카드 배치, 상세는 드릴다운 분리 | 의사결정 집중도 및 반응 속도 향상 |
| 수백만 건 빅데이터 렌더링 시 브라우저 프리징 | 웹 브라우저 DOM에 모든 점을 직접 렌더링 | 서버 사이드 데이터 집계 및 캔버스(WebGL)/타일링 렌더링 적용 | 초당 60프레임 무지연 렌더링 구현 |

## 내 의견
- [심미성에 치우친 왜곡 대시보드 만연] UI 디자이너가 그라데이션과 3D 효과를 남발해 데이터의 정량적 비교가 불가능한 시스템 양산 → 나라면: 에드워드 터프티의 '데이터-잉크 비율(Data-Ink Ratio)' 원칙을 스타일 가이드로 제정하고, 불필요한 장식(배경 격자, 3D)을 모두 제거한 미니멀리즘 차트 표준화 지침 수립
