## 답안 골격
```text
[기하 분포] ◀━━ 머리: Ⅶ 내 의견 (비기억성 속성을 활용한 네트워크 패킷 재전송(Backoff) 및 장애 대기 시간 최적화)
 ┃
 ┣━ Ⅰ 개요 ───── 독립적인 베르누이 시행 반복 시 → '첫 번째 성공'이 나타날 때까지의 시행 횟수를 모델링하는 이산확률분포
 ┣━ Ⅱ 특징 ───── 이산확률분포 중 유일한 비기억성(Memoryless) 보유 · 성공 확률 $p$ 단일 모수 · 지수적 감소 형태
 ┣━ Ⅲ 구조 ───── 확률질량함수: $P(X=x) = (1-p)^{x-1} p$ / 기댓값: $E(X) = \frac{1}{p}$ / 분산: $Var(X) = \frac{1-p}{p^2}$
 ┣━ Ⅳ 흐름 ───── ① 성공확률 $p$ 베르누이 시행 → ② 실패($1-p$) 연속 발생 → ③ $x$번째 첫 성공 달성 → ④ 확률값 계산
 ┣━ Ⅴ 비교 ───── 기하 분포 vs 베르누이 분포 vs 이항 분포 vs 음이항 분포
 ┗━ Ⅵ 실무 ───── 네트워크 패킷 재전송 횟수 산정 / 반도체 웨이퍼 첫 불량 검출 시점 / 결제 승인 재시도 제어
```
- 필수 키워드: 기하 분포 · 베르누이 시행 · 첫 번째 성공 · 비기억성(Memoryless Property) · $E(X)=1/p$ · 음이항 분포
- 배점 전략: 10점 = Ⅰ → Ⅲ PMF 수식 및 기댓값/분산 유도 도식 → Ⅵ 한 행 / 25점 = Ⅰ~Ⅶ, 앞 1/3에 Ⅲ 수식 도식 및 Ⅴ 베르누이 계열 4대 분포 비교표
- 기출: 130회 1교시 12번 `베르누이 분포와 기하 분포` → Ⅰ 두 분포 정의 + Ⅴ 관계 및 차이점 완결 비교

## 한 줄 본질
- 매번 독립적인 성공/실패 시험에서 최초로 성공할 때까지 걸리는 시도 횟수 → 성공 확률 $p$ 하나로 기댓값 $1/p$를 산출하는 이산확률 모형 → 시스템 장애 복구 및 재시도 회수 최적화 / 비기억성으로 인한 과거 이력 무시 한계

## 핵심 그림
```text
[기하 분포의 확률질량함수와 비기억성]

       P(X=x)
       p |  * (x=1, 첫 시도 성공)
         |  |
         |  *  * (x=2, 1회 실패 후 성공: (1-p)p)
         |  |  |  *
         |  |  |  |  *  * (시행 횟수 증가 시 지수적 감소)
         +──┴──┴──┴──┴──┴──> x (시행 횟수)
            1  2  3  4  5

 [비기억성 (Memoryless Property)]
  P(X > s + t | X > s) = P(X > t)
  (이미 s번 실패했더라도, 앞으로 t번 더 실패할 확률은 처음 시작할 때와 정확히 동일)
```

## 핵심 용어
- 비기억성(Memoryless Property): 과거에 얼마나 많이 실패했는지의 역사(기억)가 미래의 추가 실패 확률에 전혀 영향을 주지 않는 성질(이산분포 중 기하분포만 보유)
- 음이항 분포(Negative Binomial): '첫 번째' 성공이 아니라 '$r$번째 성공'이 나올 때까지의 시행 횟수를 다루는 기하분포의 일반화 모델

## 핵심 통찰
- 성공 확률이 $p=0.1$(10%)라면 첫 성공까지 평균 10번($1/p = 1/0.1 = 10$) 시도해야 함 → 시스템 재시도 정책 설계 시 최대 재시도 횟수(Max Retries) 산정의 수학적 근거
- 도박사의 오류(Gambler's Fallacy)를 수학적으로 증명함 → 동전을 던져 뒷면이 연속 10번 나왔더라도, 11번째에 앞면이 나올 확률은 여전히 0.5(비기억성)
- 연속확률분포의 '지수분포(Exponential Distribution)'와 쌍둥이 관계임 → 기하분포를 연속 시간으로 극한을 취하면 지수분포가 됨

## 딸려 나오는 하위 토픽
| 하위 토픽 | 상위 구조 속 위치 | 한 줄 |
|---|---|---|
| 지수분포(Exponential) | 연속형 대응 분포 | 첫 번째 사건이 발생할 때까지 걸리는 '대기 시간'을 모델링하는 연속확률분포 |
| 백오프(Exponential Backoff) | 네트워크 재전송 알고리즘 | 기하분포의 연속 실패 확률에 대응해 재전송 대기 시간을 지수적으로 증가시킴 |

## 이웃 토픽과 구분
- 기하 분포 vs 이항 분포: 이항 분포 = 시행 횟수 $n$이 고정되고 '성공 횟수'를 셀 때 / 기하 분포 = 성공 횟수 1회가 고정되고 '시행 횟수'를 셀 때

## 문제·원인·대책
- 적용 상황: MSA 마이크로서비스 간 HTTP API 호출 실패 시 재시도(Retry) 정책 수립

## 이렇게 출제된다
- 제130회 1교시 12번: "베르누이 분포(Bernoulli distribution)와 기하 분포(Geometric Distribution)" → 요구 포인트: 베르누이 시행 정의 + 기하분포 공식 및 비기억성 특징 완결 비교

## 내 의견
- [재시도 정책에서의 무한 대기 함정] 기하분포의 비기억성만 믿고 성공할 때까지 계속 재시도하다가 분산 트랜잭션 타임아웃으로 스레드 풀 고갈 → 나라면: 기하분포의 누적분포함수(CDF)를 계산해 누적 성공률이 99%에 달하는 임계 횟수(예: 3~5회)를 도출하고, 초과 시 즉시 서킷 브레이커(Circuit Breaker)를 오픈하여 장애 격리

## 찾아볼 것
- 기하분포의 CDF 수식인 $P(X \le x) = 1 - (1-p)^x$를 이용한 성공 확률 보장 시도 횟수 계산
