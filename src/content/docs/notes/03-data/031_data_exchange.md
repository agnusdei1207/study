## 답안 골격
```text
[데이터 거래소] ◀━━ 머리: Ⅶ 내 의견 (단순 파일 다운로드 탈피 → 데이터 안심구역 연계 안전한 연산 기반 데이터 거래)
 ┃
 ┣━ Ⅰ 개요 ───── 데이터 경제 활성화 및 유통 생태계 조성 → 공급자와 수요자 간 데이터 탐색·거래·결합 중개 플랫폼
 ┣━ Ⅱ 특징 ───── 양면 시장(Two-sided Market) 플랫폼 · 데이터 가치평가 및 품질인증 연계 · 안심 반출 보장
 ┣━ Ⅲ 구조 ───── 거래 플랫폼 계층 / 품질·가치평가 체계 / 결합·가공 환경(데이터 안심구역) / 법·제도(데이터산업법)
 ┣━ Ⅳ 흐름 ───── ① 상품 등록 및 심사 → ② 가치평가 및 가격 책정 → ③ 계약 및 결제 → ④ 안전한 전송/결합 환경 제공
 ┣━ Ⅴ 비교 ───── 금융데이터거래소 vs K-DATA 데이터스토어 vs 통신/유통 빅데이터 플랫폼
 ┗━ Ⅵ 실무 ───── 가격 산정 불투명성 / 원본 데이터 유출 및 재판매 위험 / 거래 유동성(Liquidity) 부족
```
- 필수 키워드: 데이터 거래소 · 데이터산업법 · 금융데이터거래소 · 가치평가 · 가명정보 결합 · 데이터 안심구역 · API 연동
- 배점 전략: 10점 = Ⅰ → Ⅲ 거래소 아키텍처 및 Ⅳ 거래 흐름도 → Ⅵ 한 행 / 25점 = Ⅰ~Ⅶ, 앞 1/3에 Ⅲ 4대 플랫폼 구성요소 및 유통 활성화 방안
- 기출: 132회 1교시 2번 `데이터 거래소` → Ⅰ 개념 + Ⅲ 구성요소 + Ⅵ 활성화 과제 / 127회 `데이터 커머스` → 비즈니스 모델

## 한 줄 본질
- 기업 간 데이터 직거래의 높은 탐색 비용과 신뢰 부족 문제 → 표준화된 카탈로그, 가치평가, 결제, 보안 전송을 중개하는 제도적 공인 플랫폼 → 데이터 유통 혁신 / 가격 산정 기준 부재와 원본 유출 우려로 인한 거래 침체 극복 필요

## 핵심 용어
- 데이터 안심구역(Data Clean Room): 미개방 원천 데이터를 외부로 유출하지 않고 폐쇄된 분석 환경 내에서 안전하게 가공·분석하여 결과 통계치만 반출하도록 지원하는 보안 구역
- 데이터 중개사(Data Broker): 거래소 내에서 수요자의 요구에 맞게 데이터를 탐색, 가공, 라이선스 협상을 대행하는 전문 중개 주체

## 핵심 통찰
- 데이터는 '한 번 주면 복제되어 돌아오지 않는' 특성이 있음 → 파일(CSV) 다운로드 방식의 1세대 거래소는 공급자의 기피로 실패함
- 따라서 현대 데이터 거래소는 '데이터 이동'이 아니라 '연산 이동(Compute-to-Data)' 방식으로 진화 → 데이터를 반출하지 않고 데이터 안심구역이나 API 형태로 접근 권한만 판매
- 데이터 가치평가와 품질인증이 거래소의 신뢰 기반임 → 사전에 품질(DQC)과 공인 가치가 매겨지지 않은 데이터는 레몬 마켓(Lemon Market)으로 전락

## 딸려 나오는 하위 토픽
| 하위 토픽 | 상위 구조 속 위치 | 한 줄 |
|---|---|---|
| 데이터산업법 제10조 | 제도적 기반 | 데이터 거래소의 법적 정의 및 데이터 거래 활성화 지원 시책의 근거 |
| 마이데이터 유통 | 거래 데이터 유형 | 정보주체의 전송요구권을 기반으로 한 금융·의료·통신 개인신용정보 유통 |

## 이웃 토픽과 구분
- 데이터 거래소 vs 오픈데이터 포털: 공공데이터포털 = 세금으로 구축된 공공데이터를 국민에게 무료 개방 / 데이터 거래소 = 민간/공공의 유료 데이터 상품을 화폐 가치로 유통하는 시장

## 문제·원인·대책
- 적용 상황: 금융데이터거래소(FinDX) 기반 이종 산업(카드사+통신사) 데이터 결합 거래
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 공급자가 원본 데이터 재판매 및 경쟁사 유출을 우려해 상품 등록 거부 | 데이터의 비소모성 및 무단 복제 위험 | 원본 반출 없는 폐쇄형 가명정보 분석 환경(안심구역) 강제 | 민감 원천 데이터 유출 100% 방지 |
| 상품 가격이 공급자 주관대로 책정되어 거래 체결 실패 | 시장 객관적 데이터 가치평가 산식 미적용 | 공인 데이터 가치평가 모델 연계 및 사용량 기반 종량제(API 쿼리당 과금) 도입 | 가격 투명성 및 거래 성사율 향상 |

## 이렇게 출제된다
- 제132회 1교시 2번: "데이터 거래소" → 요구 포인트: Ⅰ 개념 및 등장 배경 + Ⅲ 거래소 구성요소 및 기능 + Ⅵ 활성화 방안
- 제127회 4교시 2번: "데이터 커머스(Data Commerce)의 중요성이 점차 증대되고 있다.데이터 커머스에 대한" → 요구 포인트: 데이터 유통 비즈니스 모델

## 내 의견
- [공급자 중심 일방적 데이터 등록의 실패] 팔리지 않는 옛날 엑셀 파일만 잔뜩 올려놓고 거래 실적이 없는 전시성 거래소 다수 → 나라면: 수요자가 원하는 AI 학습 데이터 요구사항을 거래소에 먼저 역경매(Bounty) 방식으로 등록하고, 공급자가 맞춤형으로 데이터를 정제·제공하는 '수요 기반 데이터 거래 마켓플레이스'로 개편

## 찾아볼 것
