## 한 줄 본질
- 실세계 데이터 관계의 차수(1:1, 1:N, M:N) 다양성 → 1:1 연속 배치(선형)와 1:N/M:N 계층·망형 포인터 연결(비선형)로 추상화 → 데이터 성격에 최적화된 접근 속도 및 메모리 효율 확보

## 핵심 그림
```text
[선형 vs 비선형 자료구조 비교 구조도]

  [ 선형 자료구조 (1:1 관계, 일렬 배치) ]
   - 배열(Array)    : [10]─[20]─[30]─[40]  (연속 메모리, 인덱스 $O(1)$)
   - 연결리스트     : [Node|*]──>[Node|*]──>NULL (동적 크기, 포인터)
   - 스택/큐        : LIFO (스택), FIFO (큐)

  [ 비선형 자료구조 (1:N, M:N 다차원 관계) ]
   - 트리 (1:N 계층)             - 그래프 (M:N 네트워크)
          [Root]                        (A)─────(B)
          /    \                         │  \   / │
       [Node]  [Node]                    │   (C)  │
       /    \                            │        │
     [L]    [R]                         (D)───────┘
     (조직도, 파일시스템, B-Tree)       (소셜네트워크, 라우팅, 통신망)
```

## 핵심 용어
- 선형 자료구조(Linear Data Structure): 데이터 요소들이 순차적으로 나열되어 하나의 요소 뒤에 하나의 요소만 연결되는 1:1 관계의 구조
- 비선형 자료구조(Non-linear Data Structure): 데이터 요소들이 계층적(Hierarchical)이거나 그물망(Network) 형태로 연결되는 1:N 또는 M:N 관계의 구조

## 핵심 통찰
- 자료구조 선택의 핵심은 '데이터의 관계'와 '주요 연산 빈도'임 → 순서가 중요하고 끝단 삽입/삭제만 있다면 스택/큐, 임의 인덱스 접근이 빈번하면 배열이 최적
- 탐색 속도 극대화는 비선형 트리에서 완성됨 → 선형 배열의 순차 탐색은 $O(N)$이지만, 정렬된 비선형 이진 탐색 트리는 분할 정복으로 $O(\log N)$ 달성
- 메모리 지역성(Cache Locality) 관점에서는 포인터로 흩어진 연결리스트나 비선형 트리보다 연속된 메모리의 배열이 캐시 히트율 측면에서 압도적 우위

## 딸려 나오는 하위 토픽
| 하위 토픽 | 상위 구조 속 위치 | 한 줄 |
|---|---|---|
| 균형 이진 탐색 트리(AVL, Red-Black) | 트리의 편향 퇴화 방지 | 데이터 삽입/삭제 시 트리의 높이를 균형 있게 회전하여 최악의 경우에도 $O(\log N)$ 보장 |
| 인접 행렬 vs 인접 리스트 | 비선형 그래프의 메모리 표현 | 정점 간 연결을 2차원 배열($O(V^2)$)로 나타낼지, 연결리스트($O(V+E)$)로 나타낼지의 선택 |

## 이웃 토픽과 구분
- 트리 vs 그래프: 트리 = 사이클(Cycle)이 없고 방향성이 있는 1:N 계층 구조 / 그래프 = 사이클을 허용하고 루트 노드가 없는 복잡한 M:N 망형 구조

## 문제·원인·대책
- 적용 상황: 대규모 실시간 세션 접속자 관리 및 검색 엔진 구현
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 100만 사용자 목록에서 특정 사용자 검색 시 1초 이상 지연 | 선형 배열(Array)에서 순차 탐색($O(N)$) 수행 | 레드-블랙 트리(Red-Black Tree) 또는 해시 테이블 전환 | 검색 시간 $O(\log N)$ / $O(1)$로 단축 (수 마이크로초) |
| 연결리스트 사용 시 잦은 malloc으로 인한 메모리 단편화 및 캐시 미스 | 비연속 동적 노드 할당의 공간 오버헤드 | 고정 크기 블록 청크 기반의 선형 풀(Array-backed Pool)로 교체 | L1/L2 캐시 적중률 대폭 향상 및 처리량 3배 증가 |

## 이렇게 출제된다
- 제125회/131회: "선형 자료구조와 비선형 자료구조를 비교하여 설명하시오." → 요구 포인트: Ⅰ 선형/비선형 정의 + Ⅲ/Ⅳ 대표 자료구조 나열 + Ⅴ 시간/공간 복잡도 비교표 + 실무 선택 기준

## 내 의견
- [원론적 자료구조와 현대 하드웨어의 괴리] 알고리즘 이론상 연결리스트가 삽입 $O(1)$이라 하여 실무에 적용했으나 현대 CPU의 L1/L2 캐시 라인 프리페치(Prefetch) 특성 때문에 연속 메모리 배열이 훨씬 빠른 현상 빈번 → 나라면: 요소 개수가 작거나 캐시 효율이 중요한 구간은 Vector/Array를 최우선 고려하고, 계층 관계가 필연적인 경우에만 트리/그래프 채택

## 찾아볼 것
- B-Tree 계열 자료구조가 일반 이진 탐색 트리 대신 디스크 블록 크기에 맞춘 노드당 다중 키(M-way) 선형 배열을 채택한 이유
