## 큰 그림과 30초 인출

```text
[중앙부처·지자체·공공기관 업무/대국민 서비스]
                     │ 표준 API / 전산망 연계
                     ▼
┌────────────────────────────────────────────────────────┐
│               범정부 AI 공통기반 플랫폼                  │
│ ├─ 서비스 계층: 공공 업무비서, 코파일럿, 지능형 민원   │
│ ├─ 오케스트레이션: Model Gateway, Multi-Agent, RAG     │
│ ├─ 파운데이션 모델: LLM, sLLM, 국산 NPU 특화 모델      │
│ └─ 횡단 거버넌스: Guardrail, IAM, DLP, 로깅, 비용 최적화│
└────────────────────────────────────────────────────────┘
                     │ 안전한 데이터 파이프라인
                     ▼
[범정부 데이터 레이크 / 행정정보 공동이용망]
```

- 본질: 개별 행정·공공기관이 고비용 AI 인프라와 거대언어모델(LLM)을 독자 구축하지 않고, 공통의 모델·RAG·보안·검증 프레임워크를 공동 활용하는 클라우드 기반 국가 AI 공유 플랫폼
- 위치: `국가 AI 전략 → 범정부 AI 공통기반 → 기관별 행정 AI 서비스 → 신뢰성·보안 검증`
- 핵심: 부처 간 중복투자 원천 차단 + 공통 가드레일 기반 행정 신뢰성 확보 + 기관 데이터의 물리적·논리적 격리
- 통제: 환각(Hallucination) 억제를 위한 공공 RAG 표준화 및 사람 개입(Human-in-the-loop) 원칙 확립

## 예상문제

> 범정부 AI 공통기반의 도입 배경과 계층별 아키텍처를 설명하고, 환각 방지·데이터 보안·책임 소재(RACI) 관점의 거버넌스 통제 방안을 논하시오. (25점)

## Ⅰ. 공공 AX 촉진과 중복투자 방지를 위한 범정부 AI 공통기반 개요

- 정의: 중앙행정기관 및 지자체, 공공기관이 행정 업무와 대국민 서비스에 AI를 신속히 도입할 수 있도록 LLM API, 공공 RAG, 가드레일, 인프라를 표준화하여 제공하는 국가 공통 플랫폼
- 배경: 개별 기관의 자체 LLM 구축으로 인한 막대한 예산 낭비, 민간 파운데이션 모델 종속(Lock-in), 행정 데이터 유출 및 환각으로 인한 대국민 신뢰도 저하
- 목적: 공통 인프라·모델 재사용을 통한 구축 기간 단축 및 예산 절감, 강력한 공공 보안 가이드라인 준수, 신뢰할 수 있는 행정 서비스 구현

#### 한줄 요약
- 공공 부문의 AI 인프라와 모델 게이트웨이를 일원화하여 비용 효율성과 보안 통제력을 극대화한 플랫폼임

## Ⅱ. 5대 핵심 설계 원칙과 공공 가치

| 원칙 | 핵심 메커니즘 | 공공 행정 기여 |
|---|---|---|
| **공통화 및 분리** | 모델·게이트웨이·보안은 공통 제공, 기관 데이터·업무규칙은 격리 | 공통 자산 재사용 및 부처별 업무 독립성 보장 |
| **모델 중립성** | 특정 빅테크 모델 종속 탈피, 오픈소스 및 국산 sLLM 교체 수용 | 기술 주권 확보 및 상황별 비용·성능 최적화 |
| **데이터 주권·격리** | 공공 행정 데이터의 외부 학습 금지 및 기관 테넌트별 암호화 격리 | 공공 데이터 유출 방지 및 보안 컴플라이언스 준수 |
| **신뢰·환각 통제** | 공공 법령·지침 데이터 기반 RAG 검색 및 엄격한 가드레일 적용 | 오답·환각 차단 및 근거 중심 답변 생성 |
| **인간 중심 통제** | 고영향 행정 처분 시 최종 판단권자의 확인 및 이의제기 절차 마련 | Human-in-the-loop 기반 행정 책임성 확보 |

#### 한줄 요약
- 모델 중립성과 데이터 격리, 인간 감독을 바탕으로 공공 행정의 안전성과 자율성을 확보함

## Ⅲ. 범정부 AI 공통기반의 계층별 아키텍처

```text
[행정 사용자 (공무원)]        [대국민 서비스 채널]
           │                           │
           ▼                           ▼
┌────────────────────────────────────────────────────────┐
│ 1. 서비스 인터페이스: 행정비서 / 문서요약 / 민원 챗봇 │
├────────────────────────────────────────────────────────┤
│ 2. AI 오케스트레이션: Agent Workflow, 프롬프트 엔지니어링 │
│    └─ RAG 엔진: 공공문서 수집 → 청킹 → 임베딩 → 벡터검색│
├────────────────────────────────────────────────────────┤
│ 3. 모델 게이트웨이: 라우팅, 로드밸런싱, Fallback, 캐싱 │
│    ├─ 상용 대형 LLM API ├─ 온프레미스 sLLM ├─ NPU 특화 모델│
├────────────────────────────────────────────────────────┤
│ 4. 공통 플랫폼·인프라: 컨테이너(K8s), 국산 NPU/GPU 클러스터│
├────────────────────────────────────────────────────────┤
│ 5. 횡단 거버넌스: Guardrail / PII 필터 / 감사로그 / FinOps│
└────────────────────────────────────────────────────────┘
```

| 계층 | 주요 구성요소 | 핵심 역할 및 통제 기준 |
|---|---|---|
| **1. 서비스 계층** | 공공 포털, 모바일 행정 앱, OpenAPI | 업무별 UI/UX 제공, 최종 공무원 검토 화면 구현 |
| **2. 오케스트레이션** | LangChain/LlamaIndex 기반 워크플로우, RAG | 기관 보유 비정형 행정문서 색인, 근거 문서 기반 답변 합성 |
| **3. 모델 게이트웨이** | Unified Model Router, 토큰 관리자 | 질의 복잡도별 최적 모델 분기, 특정 벤더 장애 시 대체 라우팅 |
| **4. 인프라 계층** | 공공 클라우드 센터, 가속기 풀(GPU/NPU) | 멀티 테넌트 연산 자율 할당, 에너지 효율 최적화 |
| **5. 횡단 거버넌스** | 입력/출력 가드레일, 개인정보 마스킹, SIEM | 비윤리·적대적 프롬프트 차단, 전 질의·응답 불변 감사로그 기록 |

#### 한줄 요약
- 서비스부터 하드웨어까지 계층화하고, 전 영역에 가드레일과 감사로그를 관통시켜 보안을 통제함

## Ⅳ. 기관 서비스의 5단계 온보딩 및 운영 절차

```text
① 대상 업무 선정 → ② 데이터 준비·등급화 → ③ 공통기반 파이프라인 구성 → ④ 실증·평가·승인 → ⑤ 운영 및 모니터링
   └─ 적합성·ROI 분석   └─ 비식별화·임베딩      └─ 프롬프트·가드레일 설정      └─ 정확도·안전성 검증   └─ 드리프트·비용 감시
```

| 단계 | 주요 활동 내용 | 핵심 산출물 및 통제 기준 |
|---|---|---|
| **1. 대상 업무 선정** | 행정 수요 분석, 생성형 AI 적용 타당성 및 규칙 기반 자동화 대안 검토 | 업무 적합성 검토서 |
| **2. 데이터 등급화** | 기관 보유 법령·매뉴얼 수집, 개인정보·비밀 분리, 벡터 DB 적재 | 지식 데이터셋 및 보안 등급표 |
| **3. 파이프라인 연계** | 공통기반 API 연계, 시스템 프롬프트 작성, 도메인 가드레일 규칙 적용 | 서비스 설정 명세서 |
| **4. 검증 및 승인** | 환각 발생률, 편향성, 응답 지연 시간 시험 및 기관 보안책임자 승인 | 신뢰성 평가 보고서 |
| **5. 운영 및 감사** | 모델 드리프트 모니터링, 토큰 사용량(FinOps) 관리, 사후 정합성 점검 | 월간 운영 및 비용 분석서 |

#### 한줄 요약
- 사전 업무 선정부터 사후 드리프트 모니터링까지 단계별 검증을 거쳐 서비스 품질을 유지함

## Ⅴ. 자체 독자 구축 vs 범정부 공통기반 활용 비교

| 구분 | 기관별 독자 구축 | 범정부 AI 공통기반 활용 |
|---|---|---|
| **구축 비용** | 하드웨어·소프트웨어 중복 구매로 고비용 발생 | 공통 인프라·라이선스 공동 활용으로 TCO 대폭 절감 |
| **구축 기간** | 인프라 조달부터 서비스까지 장기간 소요 | 기 구축된 API 및 RAG 파이프라인으로 즉시 개발 가능 |
| **보안·신뢰 수준** | 기관 역량에 따른 보안 취약점 및 기준 편차 발생 | 국가 표준 보안 가이드라인 및 공통 가드레일 일괄 적용 |
| **기술 벤더 종속** | 선정된 특정 솔루션 및 클라우드사에 종속 심화 | 모델 게이트웨이를 통한 멀티 벤더·오픈소스 자유 전환 |
| **데이터 통제** | 기관 내부 서버 내 격리 용이 | 테넌트 격리 기술(VPC, IAM)로 기관별 데이터 완벽 보호 |
| **운영·유지보수** | 전문 인력 부족으로 모델 노후화 및 장애 위험 | 중앙 전문기관(NIA 등)의 지속적 플랫폼 고도화 및 지원 |

#### 한줄 요약
- 독자 구축 대비 비용·기간을 획기적으로 줄이면서 국가 표준 보안 체계를 즉시 수용할 수 있음

## Ⅵ. 공공 AI의 실무 위험과 거버넌스 통제

- 적용 상황: 대국민 복지 혜택 안내 및 세무·법령 상담에 범정부 AI 공통기반을 연계하는 프로젝트

| 위험 요인 | 발생 원인 | 공학적·관리적 해결 대책 | 기대 효과 |
|---|---|---|---|
| **행정 오류 (환각)** | 학습 데이터 외 최신 법령 누락 및 모델 추론 한계 | 공공 RAG 연계 의무화, 출처 문서 하이퍼링크 표시, 신뢰도 미달 시 거부 | 허위 정보 제공 방지 및 대국민 신뢰 확보 |
| **개인정보 침해** | 프롬프트 입력창을 통한 주민번호, 계좌 등 민감정보 유출 | 입력 단계에서 정규식·NER 기반 PII 자동 마스킹 및 DLP 연동 | 법령 위반 차단 및 개인정보보호 강화 |
| **프롬프트 인젝션** | 시스템 탈옥 프롬프트 주입으로 보안 지침 무력화 | Llama Guard 등 이중 가드레일 배치 및 시스템 프롬프트 암호화 | 비인가 데이터 접근 및 오남용 원천 차단 |
| **책임 소재 모호성** | AI 오답으로 인한 행정 손해 발생 시 책임 공백 | 플랫폼 제공자(기술)와 서비스 운영기관(내용) 간 RACI 매트릭스 확립 | 명확한 손해배상 및 행정 구제 체계 확립 |

#### 한줄 요약
- RAG 기반 근거 제시, 개인정보 마스킹, RACI 분담을 통해 공공 특유의 법적·기술적 위험을 통제함

## Ⅶ. 공통 인프라와 기관 책임의 조화를 위한 결론

- **[공통 기술 재사용과 행정 책임의 명확한 분리]**: 범정부 AI 공통기반은 기술적 도구와 안전망을 제공할 뿐이며, 국민에 대한 최종 행정 처분과 서비스 결과에 대한 책임은 해당 업무를 담당하는 기관에 있음
- 나라면: 기관 AI 사업 추진 시 `공통기반 표준 인터페이스 활용 준수 → 사전 PII 비식별화 파이프라인 구축 → 공무원 최종 검인(Human-in-the-loop) 절차의 시스템 강제화`를 과업지시서에 포함하여 기술과 제도의 정합성을 완성

#### 한줄 요약
- 플랫폼은 안전한 공통 엔진을 공급하고, 기관은 최종 산출물의 정확성과 행정 책임을 담보해야 함

## 1교시 10점 답안 발췌

### 1. 범정부 AI 공통기반의 정의
- 행정·공공기관이 거대언어모델(LLM), RAG 지식 검색, 보안 가드레일, 연산 인프라를 독자 구축 없이 표준 API로 공동 활용하는 클라우드 기반 국가 공공 AI 플랫폼

### 2. 계층별 참조 구조
```text
[공공 서비스] ──> [오케스트레이션 / RAG] ──> [Model Gateway] ──> [파운데이션 모델/인프라]
  (민원·행정)         (청킹·임베딩·가드레일)       (라우팅·캐싱)        (상용·sLLM, 국산 NPU)
```

| 영역 | 공통기반 플랫폼 제공 | 개별 이용기관 책임 |
|---|---|---|
| 기술·운영 | 모델 라우팅, 가드레일, K8s 인프라, 감사로그 | 업무 프롬프트, 도메인 지식 검증, 서비스 모니터링 |
| 법적·행정 | 플랫폼 보안 컴플라이언스 준수, 테넌트 격리 | 행정 처분 최종 승인, 개인정보 처리 동의, RACI 이행 |

### 3. 차별화 제언
- 독자 구축을 지양하고 공통기반을 채택하되, 환각 방지를 위한 RAG 출처 증명과 고영향 행정 행위에 대한 공무원 최종 검인 절차를 기술적으로 의무화해야 함
