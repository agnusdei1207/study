## 연관 키워드

- 범정부 AI 공통기반, 공공 AI, 초거대 AI, 파운데이션 모델, sLLM
- RAG, MLOps, AI 가드레일, 보안 게이트웨이, 국가정보자원관리원
- 공공 클라우드, GPU, NPU, 데이터 레이크, 상호운용성

## Ⅰ. 범정부 AI 공통기반의 개요

- 핵심 요약 : 부처별 중복 구축을 방지하고 민간 초거대 AI를 안전하게 공공에 활용하도록 중앙에서 통합 제공하는 지능형 정부 공통 플랫폼.
- 개념 : 개별 공공기관이 초거대 AI(Artificial Intelligence) 서비스를 각자 중복 구축하지 않도록, 공공 전반에서 공통으로 활용 가능한 AI 모델, 고성능 컴퓨팅 인프라, 데이터 파이프라인 및 개발 도구를 중앙에서 통합 제공하는 지능형 정부 공통 플랫폼.
- 배경 및 필요성 : 부처별 초거대 AI 도입 추진에 따른 중복 투자 및 예산 낭비 방지, 민감한 공공 데이터의 외부 유출 방지 및 상호운용성 확보 필요.
- 주요 목적 : 예산 절감, 민간 초거대 AI 모델의 안전한 공공 활용, 범정부 데이터 기반 지능형 행정 서비스 창출, 행정 업무 생산성 혁신.

## Ⅱ. 범정부 AI 공통기반의 특징 및 장점

- 핵심 요약 : **공통 모델·데이터·보안 계층**을 공유해 중복 투자를 줄이고 기관별 서비스 구축을 돕는다.
1. **공통 플랫폼** : 인증·모델 접근·운영 도구를 재사용해 기관별 구축 비용을 줄인다.
2. **RAG·MLOps 공유** : 검색·평가·배포 기반을 함께 제공해 서비스 개발 속도를 높인다.
3. **보안 게이트웨이** : 질의·응답의 민감 정보를 통제해 공공 데이터 유출 위험을 낮춘다.
4. **모델 선택 계층** : 업무와 보안 수준에 맞게 모델을 선택해 특정 공급자 의존을 줄인다.
5. **가속기 자원 공유** : 사용량을 통합 관리해 제한된 컴퓨팅 자원의 활용률을 높인다.

## Ⅲ. 범정부 AI 공통기반의 구조 (흐름)

- 핵심 요약 : 공공 서비스 계층에서 컴퓨팅 인프라 계층까지 5계층으로 구성된 스택형 아키텍처.
- 계층별 구성 및 데이터 흐름.

```text
[공공 서비스 계층]
   ── 범정부 지능형 행정 지원
   ── 대국민 정책 맞춤형 AI 서비스, 민원 자동화
   ── API(Application Programming Interface) 호출
        ↓
[AI 공통 플랫폼 계층]
   ── 프롬프트 엔지니어링
   ── RAG(Retrieval-Augmented Generation, 검색증강생성)
   ── MLOps(Machine Learning Operations), 보안/가드레일
        ↓
[파운데이션 모델 계층]
   ── 민간 초거대 AI (클로바X, 엑사원 등)
   ── 온프레미스 경량화 모델(sLLM)
        ↓
[공통 데이터 계층]
   ── 행정 지식 데이터베이스, 범정부 데이터 레이크
   ── 공공 마이데이터
        ↓
[컴퓨팅 인프라 계층]
   ── 국가정보자원관리원 공공 클라우드
   ── 고성능 GPU(Graphics Processing Unit) 및 NPU(Neural Processing Unit) 팜
```

```text
[AI 요청 처리 흐름]
사용자 질의
   ↓
보안 게이트웨이 (민감 정보 분류)
   ↓
RAG 검색 (행정 지식 DB)
   ↓
모델 라우터 (sLLM / 외부 LLM 선택)
   ↓
가드레일 (출력 필터링)
   ↓
응답 반환
```

- **AI 공통 플랫폼 계층** : 프롬프트 엔지니어링, 검색증강생성, MLOps, 보안·가드레일.
- **파운데이션 모델 계층** : 민간 초거대 AI와 온프레미스 경량화 모델(sLLM).
- **컴퓨팅 인프라 계층** : 국가정보자원관리원 공공 클라우드 고성능 가속기 팜.

## Ⅳ. 공통기반 방식과 부처별 개별 구축의 비교

- 핵심 요약 : 공통기반은 중복 투자 방지와 상호운용성 확보에 유리하고, 개별 구축은 부처 특화 요구 대응에 유리하다.
- 핵심 기술 요소.

| 핵심 기술 | 역할 및 기능 | 공공 적용 방안 |
|---|---|---|
| **RAG** (Retrieval-Augmented Generation, 검색증강생성) | 최신 공공 법령 및 지침 문서를 실시간 검색하여 LLM(Large Language Model) 환각(Hallucination) 방지 | 행정 포털 및 민원 지침서의 벡터 DB(Database) 임베딩 및 하이브리드 검색 |
| **AI 가드레일** (Guardrails) | 개인정보 필터링, 비윤리적·편향적 질의 차단, 보안 취약점 필터링 | 입출력 단계에서 주민번호, 계좌번호 등 비식별화 및 유해 표현 차단 |
| **MLOps 파이프라인** | 공공 데이터 기반의 파인튜닝, 모델 배포, 모니터링, 성능 드리프트 감지 | 모델 생명주기 관리 및 정기적인 행정 데이터 재학습 자동화 |
| **보안 게이트웨이** | 내부망과 외부 민간 LLM 연계 시 데이터 유출 방지 | 민감 정보는 내부 sLLM 처리, 일반 공개 정보는 외부 LLM 처리 라우팅 |

| 비교 항목 | 범정부 AI 공통기반 | 부처별 개별 구축 |
|---|---|---|
| 투자 효율 | 중복 투자 방지, 규모의 경제 | 부처별 중복 예산 발생 |
| 상호운용성 | 공통 API·데이터 모델로 연계 용이 | 포맷·정책 상이로 연계 어려움 |
| 보안 통제 | 중앙 집중형 가드레일·게이트웨이 | 부처별 보안 수준 편차 |
| 특화 요구 | 공통 서비스 중심, 개별 요구 제한 | 부처 특화 기능 구현 용이 |
| 장애 영향 | 단일 장애점(SPOF, Single Point of Failure) 리스크 | 영향 범위 부처 단위로 제한 |

## Ⅴ. 범정부 AI 공통기반의 한계와 방안

- 핵심 요약 : 기관 간 데이터 차이, 공통 플랫폼 장애, 모델 변화 속도를 분산·표준화 구조로 다룬다.

| 한계 | 방안 |
|---|---|
| 기관별 데이터 형식·권한이 달라 **상호운용성** 확보가 어려움 | 공통 메타데이터·API와 기관별 접근 정책을 정의 |
| 공통 플랫폼 장애가 여러 서비스로 번지는 **집중 위험** | 다중화·격리·우회 경로와 정기 복구 훈련 설계 |
| 특정 모델 고정 시 **기술 변화**를 반영하기 어려움 | 모델 교체 가능한 인터페이스와 공통 평가 기준 마련 |

## Ⅵ. 범정부 AI 공통기반에 대한 기술사적 제언

- 핵심 요약 : 망분리 환경 연계, 기계 판독성 혁신, 성과 측정 거버넌스 수립.
- 망분리 환경과 LLM 연계 아키텍처 수립 : 공공 내부 업무망의 보안성을 유지하면서 안전하게 외부 클라우드 AI를 활용할 수 있도록 보안 프록시 및 프라이빗 sLLM 하이브리드 구성.
- 공공 문서의 기계 판독성(Machine-Readability) 혁신 : 비정형 HWP(Hangul Word Processor) 문서를 표준 마크다운(Markdown) 및 구조화된 JSON(JavaScript Object Notation) 데이터로 자동 변환하는 파이프라인 구축이 RAG 성능의 핵심 전제조건.
- 성과 측정 및 공공 서비스 품질 모니터링 : AI 행정 서비스의 응답 정확도, 환각 발생률, 사용자 만족도를 실시간 측정하고 지속 개선하는 환류 거버넌스 수립.

## Ⅶ. 결론

- 핵심 요약 : 범정부 AI 공통기반은 부처별 중복 투자 방지와 민간 AI의 안전한 공공 활용을 위한 중앙 집중형 지능형 플랫폼 체계.
- 요약 : 범정부 AI 공통기반은 5계층 스택과 보안 게이트웨이·RAG·MLOps를 통해 공공 AI 서비스를 표준화·공유하는 체계.
- 시사점 : 데이터 상호운용성, 단일 장애점 대응, 모델 진화 수용성을 함께 관리해야 공공 AI 전환의 지속 가능성을 확보 가능.
