## 연관 키워드

- 범정부 AI 공통기반, 공공 AI, 초거대 AI, 파운데이션 모델, sLLM
- RAG, MLOps, AI 가드레일, 보안 게이트웨이, 국가정보자원관리원
- 공공 클라우드, GPU, NPU, 데이터 레이크, 상호운용성

## Ⅰ. 범정부 AI 공통기반의 개요

- 핵심 요약 : 부처별 중복 구축을 막고 민간 초거대 AI를 안전하게 공공에 쓰도록 중앙에서 통합 제공하는 정부 공통 AI 플랫폼.
- 개념 : 개별 공공기관이 초거대 AI(Artificial Intelligence) 서비스를 각자 중복 구축하지 않도록, AI 모델, 고성능 컴퓨팅 인프라, 데이터 파이프라인, 개발 도구를 중앙에서 통합 제공하는 **범정부 AI 공통기반**.
- 배경 및 필요성 : 부처별 공공 AI 도입에 따른 중복 투자와 예산 낭비를 막고, 민감한 공공 데이터가 외부로 유출되지 않게 하며, 시스템 간 상호운용성을 확보할 필요가 있음.
- 주요 목적 : 예산 절감, 민간 AI 모델의 안전한 공공 활용, 범정부 데이터 기반의 지능형 행정 서비스 창출, 행정 생산성 향상.
- 추진 현황 : 행정안전부와 과학기술정보통신부는 2025년 11월 24일 중앙·지방정부 내부망에서 민간 AI를 쓸 수 있는 서비스를 개시했음(보도 기준). 첫 서비스는 삼성SDS와 네이버클라우드의 AI 챗서비스이며, 인프라는 국가정보자원관리원 대구센터의 민관협력형 클라우드 공간에 구축됨. 2026년 3월부터 중앙·지방정부 전체로 이용 대상을 넓힐 계획이 보도됨.

## Ⅱ. 범정부 AI 공통기반의 특징 및 장점

- 핵심 요약 : 공통 모델, 데이터, 보안 계층을 공유해 중복 투자를 줄이고 기관별 서비스 구축을 빠르게 함.

1. 공통 플랫폼 : 인증, 모델 접근, 운영 도구를 재사용함 → 기관별 구축 비용 절감.
2. RAG와 MLOps 공유 : 검색, 평가, 배포 기반을 함께 제공함 → 서비스 개발 속도 향상.
3. 보안 게이트웨이 : 질의와 응답의 민감 정보를 통제함 → 공공 데이터 유출 위험 감소.
4. 모델 선택 계층 : 업무와 보안 수준에 맞는 모델을 고르게 함 → 특정 공급자 의존 완화.
5. 가속기 자원 공유 : 사용량을 통합 관리함 → 제한된 컴퓨팅 자원의 활용률 향상.

## Ⅲ. 범정부 AI 공통기반의 구조 (흐름)

- 핵심 요약 : 공공 서비스 계층에서 컴퓨팅 인프라 계층까지 쌓이는 스택형 구조와, 질의가 응답으로 바뀌는 처리 흐름.
- **RAG** (Retrieval-Augmented Generation, 검색증강생성) : 외부 문서를 검색해 답변 근거로 삼는 방식. 최신 법령과 지침을 반영하고 환각을 줄이는 데 쓰임.
- **가드레일** (AI Guardrails) : 입력과 출력의 개인정보, 유해 표현, 보안 취약 내용을 걸러내는 통제 장치.

```text
[공공 서비스 계층]
범정부 지능형 행정 지원, 민원 자동화
        ↓ API 호출
[AI 공통 플랫폼 계층]
프롬프트 관리, RAG, MLOps, 가드레일
        ↓
[파운데이션 모델 계층]
민간 초거대 AI, 온프레미스 sLLM
        ↓
[공통 데이터 계층]
행정 지식 DB, 범정부 데이터 레이크
        ↓
[컴퓨팅 인프라 계층]
국가정보자원관리원 공공 클라우드, GPU·NPU
```

```text
[AI 요청 처리 흐름]
사용자 질의
        ↓
보안 게이트웨이 (민감 정보 분류)
        ↓
RAG 검색 (행정 지식 DB)
        ↓
모델 라우터 (내부 sLLM / 외부 LLM 선택)
        ↓
가드레일 (출력 필터링)
        ↓
응답 반환
```

## Ⅳ. 공통기반 방식과 부처별 개별 구축의 비교

- 핵심 요약 : 공통기반은 중복 투자 방지와 상호운용성에 유리하고, 개별 구축은 부처 특화 요구에 유리함.

| 비교 항목 | 범정부 AI 공통기반 | 부처별 개별 구축 |
| --- | --- | --- |
| 투자 효율 | 중복 투자 방지, 규모의 경제 | 부처별 중복 예산 발생 |
| 상호운용성 | 공통 API와 데이터 모델로 연계 용이 | 포맷과 정책이 달라 연계 어려움 |
| 보안 통제 | 중앙 집중형 가드레일과 게이트웨이 | 부처별 보안 수준 편차 |
| 특화 요구 | 공통 서비스 중심이라 개별 요구 제한 | 부처 특화 기능 구현 용이 |
| 장애 영향 | 공통 플랫폼이 단일 장애점(SPOF, Single Point of Failure)이 될 위험 | 영향 범위가 부처 단위로 제한 |

| 핵심 기술 | 역할 | 공공 적용 방안 |
| --- | --- | --- |
| RAG | 최신 법령과 지침을 검색해 환각 방지 | 행정 포털과 민원 지침의 벡터 DB 임베딩과 하이브리드 검색 |
| AI 가드레일 | 개인정보 필터링, 유해 질의 차단 | 입출력 단계에서 주민번호 등 비식별화와 유해 표현 차단 |
| MLOps | 모델 배포, 모니터링, 성능 드리프트 감지 | 행정 데이터 재학습과 모델 생명주기 자동화 |
| 보안 게이트웨이 | 내부망과 외부 AI 연계 시 유출 방지 | 민감 정보는 내부 모델, 공개 정보는 외부 모델로 라우팅 |

## Ⅴ. 범정부 AI 공통기반의 한계와 방안

- 핵심 요약 : 기관 간 데이터 차이, 공통 플랫폼 장애, 모델 변화 속도를 표준화와 분산 구조로 다룸.

| 한계 | 대응 방안 |
| --- | --- |
| 기관별 데이터 형식과 권한이 달라 **상호운용성** 확보가 어려움 | 공통 메타데이터와 API를 정의하고 기관별 접근 정책을 명시 |
| 공통 플랫폼 장애가 여러 서비스로 번지는 **집중 위험** | 다중화, 격리, 우회 경로를 설계하고 정기 복구 훈련 실시 |
| 특정 모델에 고정되면 **기술 변화**를 반영하기 어려움 | 모델을 교체할 수 있는 인터페이스와 공통 평가 기준 마련 |

## Ⅵ. 범정부 AI 공통기반에 대한 기술사적 제언

- 핵심 요약 : 망분리 환경과 외부 AI의 연계 구조, 문서의 기계 판독성 확보, 성과 측정 거버넌스의 정비.

공공 내부망의 보안을 유지하면서 외부 클라우드 AI를 쓰려면 보안 프록시와 기관 내부의 소형 모델을 함께 두는 하이브리드 구성이 현실적이다. 민감 정보는 내부에서 처리하고 공개 정보만 외부 모델로 보내는 라우팅 기준을 먼저 정해야 한다.

공공 문서가 HWP처럼 구조화되지 않은 형식으로 남아 있으면 RAG의 검색 품질이 떨어진다. 문서를 Markdown이나 JSON 같은 기계 판독 형식으로 변환하는 파이프라인을 먼저 갖추는 것이 검색 성능의 전제가 된다.

AI 행정 서비스의 응답 정확도, 환각 발생률, 사용자 만족도를 정기적으로 측정하고 그 결과를 모델과 데이터 개선에 되돌려 넣는 환류 거버넌스가 필요하다. 측정 지표가 없으면 공통기반이 확산되어도 품질 문제를 알아채기 어렵다.

## Ⅶ. 결론

- 핵심 요약 : 범정부 AI 공통기반은 부처별 중복 투자를 줄이고 민간 AI를 안전하게 공공에 쓰게 하는 중앙 집중형 플랫폼.
- 시사점 : 데이터 상호운용성, 단일 장애점 대응, 모델 교체 수용성을 함께 관리해야 공공 AI 전환이 지속 가능함.
