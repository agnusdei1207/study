## 지식 로드맵 내 현재 위치

IT 전략·관리 → 업무연속성·재해복구 → **RTO·RPO**

## 30초 인출

- 본질: RTO·RPO는 장애 때 허용하는 서비스 중단 시간(RTO)과 데이터 손실 범위(RPO)를 업무별로 정한 복구 목표
- 메커니즘: BIA의 업무 영향 분석에서 RTO·RPO를 정하고, RTO는 대체 환경·전환 절차를, RPO는 백업·복제 주기를 결정
- 통찰: DR 구성을 마친 것만으로는 실제 복구 능력을 보장하지 못하므로 복구훈련의 RTO·RPO 실측과 미달 원인별 DR 구성 조정

<details>
<summary>핵심 용어</summary>

- **RTO(Recovery Time Objective)** : 업무 중단부터 서비스 재개까지 허용하는 최대 목표 시간
- **RPO(Recovery Point Objective)** : 장애 시점에서 거슬러 올라가 복구 데이터가 확보되어야 하는 시점, 곧 허용 데이터 손실 구간
- **BIA(Business Impact Analysis)** : 업무 중단과 데이터 손실의 영향을 분석해 복구 우선순위와 목표를 정하는 업무영향분석
- **MTPD(Maximum Tolerable Period of Disruption)** : 업무 중단이 조직에 수용 불가능한 피해로 번지기 전까지의 최대 허용 중단 기간. RTO의 상한
- **SLA(Service Level Agreement)** : 서비스 제공자와 이용자가 가용성·복구 등 서비스 수준을 합의한 협약
- **DR(Disaster Recovery)** : 중단된 정보시스템·데이터를 복구해 업무 재개를 지원하는 재해복구 활동
- **Pilot Light** : 핵심 데이터만 상시 복제하고 나머지 자원은 장애 때 기동하는 최소 대기형 DR 방식
- **Warm Standby** : 축소 규모의 복제 환경을 상시 가동해 두고 장애 때 확장·전환하는 DR 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. RTO·RPO의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **RTO** 와 **RPO** 는 장애 시 업무 재개까지 허용하는 시간과 허용하는 데이터 손실 시점을 업무별로 정한 복구 목표 |
| 목적 | 업무 중요도에 맞는 복구 수단·비용 수준의 결정 |

## Ⅱ. 시간과 데이터를 분리해 정하는 RTO·RPO의 특징

| 특징 | 의미 |
|---|---|
| 두 기준의 독립 | RTO는 서비스 재개 시각, RPO는 복구 데이터 시점의 기준. 한쪽 충족이 다른 쪽 충족을 뜻하지 않음 |
| BIA 산출물 | 업무 중단·데이터 손실 영향 분석 결과에 따른 업무별 차등 목표 |
| 설계·계약의 기준 | DR 방식·백업 주기의 설계 기준이자 SLA 복구 조항의 근거 |
| 실측 검증 대상 | 구성 완료가 아닌 복구훈련의 실제 재개 시간·복구 시점으로 달성 판정 |

## Ⅲ. BIA에서 복구 설계로 이어지는 RTO·RPO 설정 체계

### RTO·RPO 설정 체계

```text
BIA: 업무 중단·데이터 손실 영향 분석
    ↓
업무별 MTPD 산정
    ↓
RTO·RPO 설정 (RTO는 MTPD 이내)
    ↓
복구 수단 설계
    ├─ RTO 기준 → 대체 환경·전환 절차
    └─ RPO 기준 → 백업·복제 주기
    ↓
SLA 복구 조항 반영과 복구훈련 실측
```

### RTO·RPO 설정 확대: 장애 시점 기준의 두 구간

```text
마지막 복구 가능 데이터 시점
    ↓ RPO: 허용 데이터 손실 구간
장애 발생
    ↓ RTO: 허용 서비스 중단 구간
업무 서비스 재개
```

RPO는 장애 이전, RTO는 장애 이후의 구간. 빠른 전환으로 RTO를 충족해도 복제가 늦으면 RPO 미충족, 복제가 최신이어도 연계 서비스 복구가 늦으면 RTO 미충족

## Ⅳ. RTO·RPO 비교와 목표 수준별 DR 방식

### RTO와 RPO의 비교

| 구분 | RTO | RPO |
|---|---|---|
| 측정 구간 | 장애 이후 서비스 재개까지 | 장애 이전 마지막 복구 데이터까지 |
| 결정하는 설계 | 대체 환경의 대기 수준·전환 절차 | 백업·복제 방식과 주기 |
| 단축 수단 | 상시 가동 대체 환경·자동 전환 | 동기·비동기 복제, 백업 주기 단축 |
| 상위 기준 | MTPD 이내 | 업무가 감당할 수 있는 데이터 재입력·손실 범위 |

### 목표 수준에 따른 DR 방식

| DR 방식 | 평상시 대체 환경 | RTO·RPO 수준 | 비용 |
|---|---|---|---|
| Backup & Restore | 없음, 백업본만 보관 | 가장 김. RPO는 백업 주기에 좌우 | 가장 낮음 |
| **Pilot Light** | 핵심 데이터만 복제 | 자원 기동 시간만큼 RTO 발생 | 낮음 |
| **Warm Standby** | 축소 환경 상시 가동 | 확장·전환 시간만큼 RTO 발생 | 중간 |
| Active-Active | 복수 거점 동시 처리 | 가장 짧음 | 가장 높음 |

RTO·RPO가 짧을수록 상시 가동 자원과 복제 비용이 늘어나는 관계. 목표 수준이 DR 방식 선택의 판단축

## Ⅴ. RTO·RPO 적용의 한계와 방안

| 한계 | 방안 |
|---|---|
| 업무 영향 차이를 무시한 일률적 목표 설정 | BIA 결과에 따른 업무별 RTO·RPO 차등 설정 |
| 짧은 목표의 일괄 적용에 따른 DR 비용 급증 | MTPD가 짧은 핵심 업무만 Active-Active·Warm Standby, 그 외 업무는 Pilot Light·Backup & Restore 선택 |
| 빠른 전환 뒤 최신 데이터 미복구에 따른 RPO 미충족 | 복제 지연 감시와 전환 전 복구 데이터 시점 확인 |
| DR 구성 완료만으로 목표 달성 간주 | 외부 연계·데이터 정합성을 포함한 복구훈련의 RTO·RPO 실측 |

## Ⅵ. 제언

핵심 업무 복구훈련의 RTO·RPO 실측값을 목표 달성의 판정 기준으로 삼고, 미달 원인에 따른 DR 방식·복제 주기의 재조정

### 복구훈련 기반 목표 관리 흐름

```text
BIA 기준 핵심 업무 선정
    ↓
복구훈련: 업무 재개 시각·복구 데이터 시점 실측
    ↓
RTO·RPO 목표 대비 판정
    ├─ 충족 → SLA 복구 조항·훈련 주기 유지
    └─ 미달 → 원인별 조정 후 재훈련
```

### 미달 판정 확대: 원인별 조정 대상

```text
목표 미달
    ├─ RTO 초과 → 전환 자동화·대체 환경 대기 수준 상향
    └─ RPO 초과 → 복제 방식 변경·백업 주기 단축
```

### 선택 근거: 구성 기반 판정과의 비교

| 구분 | 구성 기반 판정 | 제언: 실측 기반 판정 |
|---|---|---|
| 달성 판단 근거 | DR 구성·복제 설정 완료 | 훈련의 업무 재개 시각·복구 데이터 시점 |
| 측정 범위 | 개별 시스템 기동 | 외부 연계·데이터 정합성을 포함한 업무 재개 |
| 미달 발견 시점 | 실제 장애 발생 후 | 정기 복구훈련 |
| 미달 시 처리 | 사고 후 사후 개선 | RTO·RPO 원인별 DR 구성 조정 후 재훈련 |
