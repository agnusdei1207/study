## 지식 로드맵 내 현재 위치

IT 전략·관리 → 업무연속성·재해복구 → **RTO·RPO**

## 30초 인출

- 본질: RTO(Recovery Time Objective)는 서비스 중단 후 재개까지 허용하는 시간이고, RPO(Recovery Point Objective)는 장애 시 허용하는 데이터 손실의 최대 범위
- 메커니즘: 업무영향분석(BIA) → 업무별 목표 설정 → 복구수단 설계 → 훈련·검증
- 판정 기준: 실측 복구시간·복구시점과 업무별 목표의 충족 여부

<details>
<summary>핵심 용어</summary>

- **RTO(Recovery Time Objective)** : 업무 중단부터 서비스 재개까지 허용하는 최대 목표시간
- **RPO(Recovery Point Objective)** : 장애 발생 시점과 복구 데이터의 기준시점 사이에 허용하는 최대 시간 간격
- **BIA(Business Impact Analysis)** : 업무 중단과 데이터 손실의 영향을 분석해 복구 우선순위·목표를 정하는 업무영향분석
- **BCP(Business Continuity Plan)** : 중단 상황에서 핵심 업무를 지속하거나 재개하기 위한 계획
- **DR(Disaster Recovery)** : 중단된 정보시스템·데이터를 복구해 업무 재개를 지원하는 활동

</details>

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **RTO** 는 중단부터 업무 재개까지 허용하는 시간, **RPO** 는 장애 시점에서 마지막 복구 가능 데이터까지 허용하는 시간 간격 |
| 목적 | 업무 중요도에 맞는 복구 수준·수단의 결정 |

### Ⅱ. 목표 수립·검증

업무·의존성 식별 → BIA → RTO·RPO 설정 → 복구수단 설계 → 훈련의 연결. **RTO**는 중단부터 업무 재개까지, **RPO**는 마지막 복구 데이터부터 장애 발생까지의 간격으로 검증

| 구분 | RTO | RPO |
|---|---|---|
| 기준 | 서비스 중단 허용시간 | 데이터 손실 허용 범위 |
| 확인 | 실제 서비스 재개까지 걸린 시간 | 복구 데이터의 기준시점·정합성 |
| 설계에 미치는 점 | 대체환경과 복구절차 | 백업·복제 주기와 복구시점 |

- 한 줄 제언: 업무별 복구 목표의 훈련 실측과 미달 원인 개선

## 2~4교시 25점 답안

## Ⅰ. 복구목표의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **RTO** 는 중단부터 업무 재개까지 허용하는 시간, **RPO** 는 장애 시점에서 마지막 복구 가능 데이터까지 허용하는 시간 간격 |
| 목적 | 업무 중요도에 맞는 복구 수준·수단의 결정 |

## Ⅱ. 수립·검증 흐름

```mermaid
flowchart LR
    A[핵심 업무·의존성 식별] --> B[BIA·복구 우선순위]
    B --> C[RTO·RPO 합의]
    C --> D[복구수단·절차 설계]
    D --> E[복구훈련·실측]
    E -->|미달 원인 개선| B
```

| 구분 | RTO | RPO |
|---|---|---|
| 기준 | 서비스 중단 허용시간 | 데이터 손실 허용 범위 |
| 확인 | 실제 서비스 재개까지 걸린 시간 | 복구 데이터의 기준시점·정합성 |
| 설계에 미치는 점 | 대체환경과 복구절차 | 백업·복제 주기와 복구시점 |

```mermaid
flowchart LR
    A[마지막 복구 가능 데이터] -->|"RPO: 허용 데이터 간격"| B[장애 발생·업무 중단]
    B -->|"RTO: 허용 중단시간"| C[업무 서비스 재개]
```

복구수단 선택 시 두 목표의 별도 검증. 빠른 전환에 따른 RTO 단축 가능성과 최신 데이터 미복구 시 RPO 미충족, 짧은 복제·백업 주기에도 애플리케이션·외부 연계 복구가 늦을 경우의 RTO 미충족

## Ⅲ. 적용 시 유의점

| 적용 시 쟁점 | 판단·검증 기준 |
|---|---|
| 업무별 목표 차이 | BIA로 중요도를 구분해 RTO·RPO를 차등 설정 |
| 목표와 비용의 균형 | 중단·데이터 손실 영향과 복제·대체환경 비용을 함께 비교 |
| 구성만으로 달성 단정 | 외부 의존성·전환·복귀·데이터 정합성을 포함해 시험 |
| 실측 목표 미달 | 절차·용량·복제 구성을 개선하고 재검증 |

## Ⅳ. 기술사적 제언 — 훈련 결과의 합격 판정

| 실측 항목 | 판정 방법 | 목표 미달 시 조치 |
|---|---|---|
| 장애부터 사용자 업무 재개까지의 시간 | 업무별 **RTO** 와 비교 | 전환 절차·대체환경 용량 개선 |
| 장애 시각과 복구 데이터의 기준시점 차이 | 업무별 **RPO** 와 비교 | 복제·백업 주기와 복구지점 재설계 |
| 복구 데이터의 정합성 | 거래·외부 연계 결과 확인 | 불일치 원인 수정 후 재시험 |

복구훈련에서 복구시간·데이터 손실을 각각 측정하고, 어느 한쪽이라도 목표 초과 시 해당 업무의 복구 설계를 재검증
