## Ⅰ. 프로젝트 관리 종합 체계의 개요

- 개념 : 프로젝트의 목표를 달성하기 위해 지식, 기술, 도구, 기법을 프로젝트 활동에 적용하는 총체적 관리 체계로, **PMBOK(Project Management Body of Knowledge) 7판**을 중심으로 전통적 프로세스 관리에서 '**원칙** (Principles)'과 '**가치 전달** (Value Delivery)' 중심으로 진화.
- 배경 및 필요성 : 디지털 불확실성 증대, 복합 시스템의 증가로 인해 엄격한 프로세스 준수만으로는 비즈니스 가치를 적시에 전달하기 어려운 한계 극복 필요.
- 주요 목적 : 비즈니스 가치 극대화, 프로젝트 3대 제약(범위, 일정, 원가)과 품질·위험의 균형 달성, 이해관계자 만족.

## Ⅱ. PMBOK 7판의 가치 전달 시스템 및 8대 성과 영역

```text
[가치 전달 시스템 (System for Value Delivery)] ── 거버넌스, 조직 환경, 정보 흐름을 통한 가치 창출
                      │
┌─────────────────────┴─────────────────────┐
│             PMBOK 7판 8대 성과 영역 (Performance Domains)             │
│  1. 이해관계자 (Stakeholders)      2. 팀 (Team)                      │
│  3. 개발 접근법 및 생애주기 (Dev Approach & Life Cycle)               │
│  4. 기획 (Planning)                5. 프로젝트 작업 (Project Work)    │
│  6. 납품 (Delivery)                7. 측정 (Measurement)             │
│  8. 불확실성 (Uncertainty)                                           │
└───────────────────────────────────────────────────────────────────┘
```

- **가치 전달 시스템 (System for Value Delivery)** : 거버넌스, 조직 환경, 정보 흐름을 통한 가치 창출.
- **8대 성과 영역 (Performance Domains)** : 이해관계자, 팀, 개발 접근법 및 생애주기, 기획, 프로젝트 작업, 납품, 측정, 불확실성.

## Ⅲ. PMBOK 6판과 7판의 패러다임 비교

| 비교 항목 | PMBOK 6판 | PMBOK 7판 |
|---|---|---|
| **중심 철학** | 프로세스 중심 (Process-based) | 원칙 중심 (Principle-based) 및 가치 전달 |
| **핵심 구조** | 5대 프로세스 그룹, 10대 지식 영역, 49개 프로세스 (ITTO, Inputs, Tools and Techniques, Outputs) | 12대 프로젝트 관리 원칙, 8대 성과 영역 (Performance Domains) |
| **개발 접근법** | 예측형(워터폴) 중심, 애자일은 부록으로 다룸 | 예측형, 적응형(애자일), 하이브리드를 동등하게 포용 |
| **성공의 기준** | 계획된 범위, 일정, 예산의 철저한 준수 | 비즈니스 결과물(Outcome)과 실질적 비즈니스 가치 실현 |

## Ⅳ. 프로젝트 관리 체계(PMBOK 등) 적용 시 주요 한계점 및 해결 방안

- 프로세스 중복 및 과도한 산출물 관리 오버헤드 :
  - 한계점 : 표준 지식 영역을 기계적으로 적용하여 실제 개발 진척보다 문서 작성과 보고 회의에 인력과 시간이 낭비되는 주객전도.
  - 해결 방안 : 프로젝트 규모와 복잡성에 맞춘 테일러링(Tailoring) 가이드라인 엄격 적용, 지라(Jira) 등 협업 도구 기반 산출물 자동화.
- 지식 영역 간 사일로(Silo) 현상 :
  - 한계점 : 범위, 일정, 원가, 품질, 리스크 관리가 개별 담당자별로 분절되어 상호 변경 영향도를 유기적으로 반영하지 못함.
  - 해결 방안 : 통합 변경 통제(Integrated Change Control) 체계 확립, 통합 관리(Integration Management) 중심의 PM 리더십 강화.
- 고객 요구의 동적 변화 대응 지연 :
  - 한계점 : 초기 계획 중심의 엄격한 베이스라인 통제로 인해 급변하는 비즈니스 환경과 사용자 피드백의 즉각적 수용 한계.
  - 해결 방안 : 워터폴의 구조적 안정성과 애자일의 민첩성을 결합한 하이브리드(Hybrid) 프로젝트 관리 프레임워크 구축.

## Ⅴ. 성공적인 프로젝트 관리를 위한 기술사적 제언

- 프로젝트 특성에 따른 맞춤형 테일러링(Tailoring) : 사업의 규모, 규제 환경, 요구사항 불확실성에 따라 워터폴, 스크럼, 칸반, 하이브리드 중 최적의 라이프사이클을 선별 적용.
- 산출물(Output) 중심에서 가치 결과물(Outcome) 중심으로 전환 : 단순히 기능이 구현되었는가가 아니라, 실제 비즈니스 문제 해결과 사용자 채택률에 집중하는 관리 지표 도입.
- 심리적 안정감과 서번트 리더십(Servant Leadership) 정착 : 통제와 감시 위주의 프로젝트 관리를 탈피하여, 팀원의 창의적 문제 해결을 돕고 장애물을 제거해주는 지원형 리더십 발휘.
