## 지식 로드맵 내 현재 위치
현재 위치: IT 전략·관리 → AI 프라이버시 리스크 관리 모델


## 30초 인출

- 본질: **AI 프라이버시 리스크 관리 모델** : AI의 개인정보 처리에서 위험을 식별하고 줄이는 절차.
- 메커니즘: AI 유형·용례 파악 → 리스크 식별 → 정성·정량 측정 → 비례적 안전조치, 환경 변화 시 반복.
- 통찰: 한계: 개인정보 위험을 모델 학습 단계에서만 점검 → 방안: 생애주기별 조치와 잔여위험 승인 책임을 기록

<details>
<summary>핵심 용어</summary>

- **AI 프라이버시 위험관리 모델** : AI 수명주기의 개인정보 처리 위험을 식별·평가·완화하는 관리 절차
- **PbD(Privacy by Design)** : 기획·설계 초기 단계부터 개인정보 보호 기능을 기본값으로 내재화하는 설계 원칙
- **PIA(Privacy Impact Assessment)** : 개인정보 처리가 정보주체에게 미치는 영향을 사전 분석하는 평가. 국내 법정 대상 여부는 별도 확인
- **DPIA(Data Protection Impact Assessment)** : 고위험 데이터 처리의 필요성·비례성·위험 경감 조치를 종합 평가하는 절차(GDPR 기준)
- **Differential Privacy(DP, 차등 프라이버시)** : 통계 결과에 제한된 무작위성을 더해 개인 한 명의 데이터 포함 여부가 결과에 미치는 영향을 제한하는 기법
- **Machine Unlearning** : 특정 학습자료의 영향을 줄이거나 제거하도록 모델을 조정하는 방법으로, 제거 범위와 효과는 구현·검증에 따라 달라짐
- **Membership Inference Attack** : 모델 출력 등 관측 가능한 정보를 이용해 특정 개인의 데이터가 학습집합에 포함되었는지 추론하는 공격 기법

- **RAG(Retrieval-Augmented Generation)** : 외부 자료를 검색해 생성 모델의 입력 맥락으로 제공하는 방식.

</details>

## 2~4교시 25점 답안

## Ⅰ. AI 프라이버시 위험관리 모델의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **AI 프라이버시 위험관리 모델** : AI 수명주기의 개인정보 처리 위험을 식별·평가·대응하는 관리 절차 |
| 목적 | 정보주체 권리 보호와 적법한 데이터 활용 지원 |

## Ⅱ. AI 프라이버시 위험관리의 특징

| 특징 | 검토 대상 |
|---|---|
| 수명주기 전반 | 수집·학습뿐 아니라 모델·입출력·변경·종료의 노출 |
| 맥락별 위험 | 이용 목적·정보 민감도·사용자·처리 환경 |
| 비례적 조치 | 위험 감소 효과와 데이터 유용성·잔여 위험의 비교 |

## Ⅲ. AI 프라이버시 위험관리 절차

```text
AI 유형·용례 파악 → 리스크 식별 → 정성·정량 측정
       → 리스크에 비례한 안전조치 → 환경 변화 시 반복
```

```text
기획·수집의 처리 목적 확인 → 전처리의 식별 단서 검토
                                  ↓
학습·평가의 정보 추출 시험 → 배포·운영의 입력·출력 통제
                                  ↓
변경·종료 때 삭제·재평가와 책임 기록
```

## Ⅳ. 프라이버시 위험 유형과 생애주기별 경감 관계

### 프라이버시 리스크 유형

| 영역 | 주요 위험 | 판단 관점 |
|---|---|---|
| 데이터 | 과잉수집·목적 외 이용·재식별 | 처리근거·최소처리·출처 |
| 모델 | 암기·추출·Membership Inference | 민감도·노출가능성 |
| 서비스 | Prompt·Output·RAG 개인정보 노출 | 권한·필터·사용맥락 |
| 권리 | 고지·열람·정정·삭제 곤란 | 권리행사 가능성 |
| 관리 | 개발자·제공자·이용자 책임 불명 | 역할·계약·증적 |

### 생애주기별 경감방안

> 보호기술 선정기준: 일률 적용이 아닌 처리목적·데이터 민감도·모델 구조·위험수준에 따른 조합.

| 단계 | 위험 | 경감방안 |
|---|---|---|
| 기획·수집 | 처리근거 부재·과잉수집 | **PbD** ·목적명확화·최소수집·위험에 따른 **PIA** 검토 |
| 전처리 | 식별자 잔존·재식별 | 가명처리·접근통제·합성데이터 검토 |
| 학습·평가 | 암기·추론·추출 | 데이터 정제·정규화·**Differential Privacy (DP)** 적용 검토·공격평가 |
| 배포·운영 | 입출력·**RAG** 개인정보 노출 | 권한검사·필터·로그·신고채널 |
| 변경·종료 | 삭제·책임 단절 | 재학습·**Machine Unlearning** 적용성 검토·증적 관리 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 공개정보의 무분별한 학습 | 출처·처리 근거·이용 맥락 검토 |
| 비정형정보 탐지 누락 | 탐지 결과의 표본 검수와 잔여 위험 평가 |
| 보호기술로 인한 성능저하 | 위험별 적용과 유용성·보호 수준 비교 |
| 삭제요청 이행 곤란 | 데이터·모델 계보와 재학습 전략 검토 |
| 공급망 책임 불명 | 역할·처리 조건·사고 통지의 계약 명시 |

## Ⅵ. 제언

정보주체 영향이 큰 사용사례부터 잔여 위험 수용 책임자를 지정하고 데이터·모델·목적 변경 시 재평가 조건 확정.

차등프라이버시·언러닝의 위치: 위험 완화를 위한 선택지이며 모든 처리에 적용되는 법정 의무는 아님.
