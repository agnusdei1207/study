## 지식 로드맵 내 현재 위치

IT 전략·관리 → AI 거버넌스·정책 → **AI 프라이버시 리스크 관리 모델**

## 30초 인출

- 본질: AI 프라이버시 리스크 관리 모델은 AI 개발·서비스에서 생기는 개인정보 위험을 찾아 줄이도록 개인정보보호위원회가 제시한 자율 관리 절차
- 메커니즘: AI 유형·용례 파악 → 유형별 리스크 식별 → 정성·정량 측정 → 리스크에 비례한 관리적·기술적 안전조치, CPO(개인정보 보호책임자) 주도
- 통찰: 서비스가 바뀌어도 안전조치가 그대로면 새 노출 경로를 놓치므로 용례 변경 시점마다의 리스크 재측정

<details>
<summary>핵심 용어</summary>

- **AI 프라이버시 리스크 관리 모델** : AI 생애주기에서 개인정보 위험을 식별·측정·경감하도록 개인정보보호위원회가 2024년 12월 제시한 안내 모델
- **CPO(Chief Privacy Officer, 개인정보 보호책임자)** : 조직의 개인정보 처리 업무를 총괄하고 AI 리스크 관리의 결정과 책임을 맡는 책임자
- **생성 AI** : 학습한 데이터를 바탕으로 글·이미지 등 새 콘텐츠를 만드는 AI
- **판별 AI** : 입력을 분류·예측해 판단 결과를 내는 AI
- **프라이버시 레드팀** : 공격자 관점에서 모델의 개인정보 유·노출 가능성을 시험하는 관리적 점검 활동
- **개인정보 영향평가(PIA, Privacy Impact Assessment)** : 개인정보 처리가 정보주체에게 미치는 영향을 사전에 분석·평가하는 절차
- **차분 프라이버시(Differential Privacy)** : 결과에 통제된 잡음을 더해 특정 개인의 포함 여부가 결과에 미치는 영향을 제한하는 기법
- **Membership Inference Attack** : 모델 출력을 이용해 특정 개인의 데이터가 학습에 쓰였는지 추론하는 공격

## 2~4교시 25점 답안

## Ⅰ. AI 프라이버시 리스크 관리 모델의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **AI 프라이버시 리스크 관리 모델** 은 AI 유형·용례별 개인정보 위험을 식별·측정하고 비례적 안전조치로 관리하는 자율 관리 절차 |
| 목적 | AI 개발·서비스의 개인정보 유·노출 위험 감소와 적법한 데이터 활용 |

## Ⅱ. 일반 개인정보 관리와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 용례 기반 판단 | 같은 기술도 유형·용례에 따라 다른 위험으로 평가 |
| 생애주기 구분 | 기획·개발 단계와 서비스 제공 단계의 위험 구분 |
| 비례적 조치 | 위험 수준에 맞춘 조치 선택. 모든 개별 조치의 일률 이행 요구 아님 |
| CPO 주도 | 위험 수용·조치 결정의 책임 주체로 CPO 역할 강조 |

## Ⅲ. 리스크 관리 체계와 경감 절차

### 리스크 관리 체계

```text
CPO 주도 리스크 관리
    │
    ├─ 대상 ── AI 유형(생성·판별)과 용례
    │
    ├─ 생애주기 ── 기획·개발 / 서비스 제공
    │
    └─ 안전조치
          ├─ 관리적 조치
          └─ 기술적 조치
```

### 안전조치 확대: 리스크 관리 4단계

```text
AI 유형·용례 파악
    ↓
유형별 리스크 식별
    ↓
정성·정량 리스크 측정
    ↓
리스크에 비례한 안전조치 선택
    ↓
용례·환경 변화 시 식별 단계로 복귀
```

## Ⅳ. 관리적·기술적 안전조치 비교

| 구분 | 관리적 조치 | 기술적 조치 |
|---|---|---|
| 예시 | 학습데이터 이력관리, 이용방침 수립, **프라이버시 레드팀** , **개인정보 영향평가** | 데이터 전처리, 모델 미세조정, 입출력 필터링, **차분 프라이버시** |
| 작동 위치 | 조직의 절차·책임·기록 | 데이터·모델·서비스 입출력 |
| 효과 범위 | 위험의 발견·책임 추적 | 유·노출 가능성의 직접 감소 |
| 대가 | 운영 인력·검토 시간 | 모델 성능·데이터 유용성 저하 가능 |

관리적 조치는 위험을 찾아 책임을 남기고, 기술적 조치는 발견된 노출 경로를 줄이는 관계로, 한쪽만으로는 잔여 위험의 판단 불가

## Ⅴ. AI 프라이버시 리스크 관리의 한계와 방안

| 한계 | 방안 |
|---|---|
| 서비스 출시 뒤 용례 추가로 새 노출 경로 발생 | 용례 변경 시 리스크 식별·측정 재수행 |
| 기술적 조치 적용에 따른 모델 성능 저하 | 위험 수준이 높은 용례에만 차분 프라이버시·필터링 선택 적용 |
| 학습데이터 출처 불명으로 삭제 요청 대응 곤란 | 학습데이터 이력관리로 출처·처리 근거 기록 |
| 조치 후 남은 위험의 수용 주체 불명확 | CPO의 잔여 위험 수용 결정과 근거 기록 |

## Ⅵ. 제언

CPO가 용례 변경을 재측정 시점으로 지정해, 서비스 제공 단계에서도 리스크 측정과 안전조치 선택을 반복

### 용례 변경 재측정 구조

```text
CPO
    │
    ├─ 서비스 부서 ── 용례 추가·변경 신고
    │
    ├─ 개발 조직 ── 레드팀 결과·측정값 제공
    │
    └─ 잔여 위험 수용 여부 결정과 기록
```

### CPO 결정 확대: 용례 변경 시 판정 흐름

```text
용례 변경 신고
    ↓
유·노출 경로 재식별과 레드팀 시험
    ↓
측정 결과 판정
    ├─ 허용 수준 초과 → 기술적 조치 추가 후 재시험
    └─ 허용 수준 이내 → 잔여 위험 수용 기록 후 출시
```

### 선택 근거: 개발 단계 일회성 점검과의 비교

| 구분 | 개발 단계 일회성 점검 | 제언: 용례 변경 시 재측정 |
|---|---|---|
| 측정 시점 | 출시 전 1회 | 출시 전과 각 용례 변경 시점 |
| 위험 수용 주체 | 개발 조직 | CPO |
| 새 노출 경로 대응 | 사고 후 확인 | 변경 신고 시 레드팀 시험 |
