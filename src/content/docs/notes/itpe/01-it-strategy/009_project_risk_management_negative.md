- 현재 위치: `01 정보 전략·관리 > 프로젝트 위험관리 > 부정적 위험 대응`

## 큰 그림과 30초 인출

```text
식별 → 정성평가 → 정량평가 → 대응계획 → 실행 → 감시
          │ P×I·긴급성      │
          ▼                 ▼
       우선순위      회피·완화·전가·수용·상향
                         │
              잔여·2차 위험·예비비
```

- 본질: **불확실한 사건이 목표에 미칠 위협을 사전에 식별·분석하고 적절한 대응과 책임·예비비를 준비하는 활동**
- 5대 위협 대응: 회피·완화·전가·수용·상향(Escalate)
- 암기: `회-완-전-수-상`

## 예상문제

> 프로젝트 위험관리 프로세스를 설명하고 부정적 위험의 5대 대응전략, 예비비 및 잔여·2차 위험 관리방안을 논하시오. (25점)

## Ⅰ. 불확실성을 선제 통제하는 프로젝트 위험관리 개요

- 정의: 프로젝트 위험관리는 불확실한 사건·조건이 범위·일정·원가·품질 등 목표에 미칠 영향을 식별·분석하고 대응·감시하는 활동
- 목적: 위협의 발생확률 또는 영향을 허용수준 이하로 낮추고 목표 달성 가능성 향상
- 필요성: Issue가 된 뒤 대응하면 선택 가능한 대안과 시간·예산이 줄어 손실이 커짐

## Ⅱ. 선제적·반복적·책임기반 위험관리 특징

| 특징 | 핵심 내용 | 산출물 |
|---|---|---|
| 선제성 | Issue 전 Trigger와 대응 준비 | Risk Register |
| 반복성 | 사업·외부환경 변화에 따라 재평가 | Review·Trend |
| 우선순위 | 확률·영향·긴급성·근접성 평가 | PI Matrix·Watchlist |
| 책임성 | Owner와 Action Owner 지정 | RACI·Due Date |
| 통합성 | 일정·원가·품질·조달·변경과 연계 | Reserve·Change |

## Ⅲ. 위험관리 프로세스와 핵심 산출물

| 프로세스 | 핵심 활동 | 산출물 |
|---|---|---|
| 계획 | 방법·범주·척도·허용도·보고주기 정의 | Risk Management Plan |
| 식별 | 원인-사건-영향 형태로 위협 도출 | Risk Register·RBS |
| 정성분석 | 확률·영향·긴급성·근접성 평가 | 우선순위·PI Matrix |
| 정량분석 | 목표 분포·민감도·시뮬레이션 | 일정·원가 위험범위 |
| 대응계획 | 전략·조치·Owner·예비비·Trigger | Response Plan |
| 대응실행 | 계획조치 수행·변경 반영 | Action 상태 |
| 감시 | 잔여·2차·신규 위험·효과 확인 | Review·Issue·교훈 |

```text
Risk Statement = 원인 때문에 → 위험사건이 발생하여 → 목표에 영향
```

## Ⅳ. 식별에서 감시까지의 운영절차

```text
① RBS·Workshop 식별 → ② P×I·긴급성 평가 → ③ 정량분석
 → ④ 전략·Owner·Trigger·예비비 → ⑤ 대응실행 → ⑥ 잔여·2차 위험 재평가
```

| 통제 | 핵심 질문 |
|---|---|
| Trigger | 어떤 조기징후에서 대응을 시작하는가 |
| Owner | 누가 위험을 감시하고 의사결정하는가 |
| Action | 누가 언제 어떤 조치를 완료하는가 |
| Reserve | 식별된 위험과 미식별 불확실성에 어떤 여유를 둘 것인가 |
| Escalation | 프로젝트 권한·범위를 넘으면 누구에게 상향하는가 |

## Ⅴ. 부정적 위험의 5대 대응전략 비교

| 전략 | 원리 | 적용 예 | 유의점 |
|---|---|---|---|
| 회피 | 원인을 제거하거나 계획을 변경 | 미성숙 기술 제외·범위 변경 | 기회·가치 손실 검토 |
| 완화 | 확률 또는 영향을 낮춤 | Prototype·이중화·추가시험 | 잔여위험 평가 |
| 전가 | 재무·수행 책임을 제3자와 계약 | 보험·보증·외주 | 위험 자체가 사라지는 것은 아님 |
| 수용 | 능동·수동으로 감수 | Contingency·Workaround | 허용권한·Trigger 명시 |
| 상향 | 프로젝트 밖 위험을 상위 권한에 이관 | 법·전사전략·Portfolio 위험 | 책임자·결정기한 추적 |

## Ⅵ. 위험대장을 의사결정 도구로 만드는 고려사항

| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 위험을 숨김 | 책임추궁 문화·성과평가 불이익 | No-blame Workshop·익명수집·조기보고 보상 | 식별률 향상 |
| 모호한 위험문장 | 원인·사건·영향 혼재 | Cause-Event-Impact 형식과 Trigger 명시 | 실행가능성 확보 |
| 대응 후 새 위험 발생 | 2차·잔여 위험 미평가 | 대응안 검토 시 Secondary·Residual 등록 | 부작용 통제 |
| 예비비 임의 사용 | 위험과 Reserve 근거 미연계 | Risk별 Contingency·사용권한·증적 관리 | 원가통제 |
| 위험대장 방치 | 일정·변경·Issue와 단절 | 정례 Review, Dashboard, Change/Issue 연계 | 현행성 유지 |

## Ⅶ. 위험대장을 조기경보와 실행계획으로 전환

- **[Trigger-Owner-Action-Reserve의 일체화]**: 확률·영향 점수만 기록하면 위험이 임박해도 행동과 의사결정이 시작되지 않음
- 나라면: 상위 위험마다 측정 가능한 Trigger, Risk Owner, 선제·비상조치, 필요 예비비와 상향기준을 정하고 Sprint/주간회의에서 변화량을 검토

#### 한줄 요약

- 위험관리의 완성은 목록 작성이 아니라 징후 발생 즉시 책임자와 자원이 움직이는 상태임

## 1교시 10점 답안 발췌

```text
식별 → P×I 평가 → 정량분석 → 대응 → 실행 → 잔여·2차 위험 감시
```

| 전략 | 의미 |
|---|---|
| 회피·완화 | 원인 제거 / 확률·영향 감소 |
| 전가·수용 | 제3자 책임 / 감수·예비비 |
| 상향 | 프로젝트 권한 밖 위험의 상위 이관 |

- 차별화: Risk별 Trigger-Owner-Action-Reserve를 묶어 조기경보와 실행을 보장
