## 연관 키워드

- 전사 아키텍처(EA), 정보기술 아키텍처(ITA), 업무·데이터·응용·기술 아키텍처, 참조모델, 현행·목표 아키텍처, 이행계획

## Ⅰ. EA·ITA의 개요

- 핵심 요약 : 조직의 전략·업무·정보기술 구조를 하나의 모형으로 정의·유지해 투자와 시스템의 정합성을 확보하는 전사 관점의 관리 체계.
- 개념 : **전사 아키텍처** (EA, Enterprise Architecture)는 기업·정부의 전략과 업무, 정보기술 구조를 통합적으로 정의·관리하는 전사 관점의 체계이며, **정보기술 아키텍처** (ITA, Information Technology Architecture)는 그 중 정보기술 영역의 구조를 다루는 관점.
- 배경 및 필요성 : 부서 단위 시스템 구축의 누적으로 정보 섬 (Information Silo, 부서 간 공유되지 않는 분리된 정보 환경)과 중복 투자·표준 부재가 발생하고 전략과 IT 실행의 어긋남이 상시화.
- 주요 목적 : 전략-업무-IT의 정합성 유지, 투자 효율화, 표준 기반 상호운용성과 중복 방지.

## Ⅱ. EA·ITA의 특징 및 장점

- 핵심 요약 : 네 관점 통합·현행-목표-이행 관리·참조모델·거버넌스가 전사 최적과 투자 정합성으로 연결.

1. 네 관점의 통합 시각 : **업무·데이터·응용·기술 아키텍처** (Business·Data·Application·Technology Architecture)를 상호 연결해 전사 구조와 의존성을 가시화 → 중복·복잡성의 구조적 식별.
2. 현행-목표-차이-이행 관리 : **현행·목표 아키텍처** (As-Is/To-Be Architecture)의 대비와 **이행계획** (Roadmap)으로 변화 경로를 관리 → 사업 투자의 전략 정합성 확보.
3. 참조모델·표준 운영 : **참조모델** (Reference Model, 전사 공통의 분류·구성 기준 모형)과 기술 표준으로 설계 일관성 확보 → 재사용·상호운용성 강화. 정부는 전자정부법에 근거해 업무·데이터·서비스·기술 참조모델을 범정부 공통 기준으로 운영.
4. 아키텍처 거버넌스 : **아키텍처 거버넌스** (Architecture Governance, 원칙·심의·예외 관리로 아키텍처 판단을 강제하는 운영 체계)로 투자·설계에 아키텍처 판단 반영 → 임시방편 설계와 기술부채 억제.

## Ⅲ. EA·ITA의 구조 (흐름)

- 핵심 요약 : 전략에서 기술로 이어지는 계층 구조와 현행화→목표→이행→심의→갱신의 운영 흐름으로 구성.
- 계층 구조 : 상위 전략·업무 관점이 하위 데이터·응용·기술 관점으로 전달되는 상하 정합 구조.
- 운영 흐름 : 모형의 수립에서 사업 반영, 변경에 따른 지속 갱신까지의 순환 운영.

```text
[ EA·ITA의 계층 구조 ]

전략·목표 (경영 비전)
    ↓
업무 아키텍처 : 기능·프로세스·조직
    ↓
데이터 아키텍처 : 데이터 주제·모델
    ↓
응용 아키텍처 : 기능·시스템 구성
    ↓
기술 아키텍처 : 플랫폼·표준·인프라
```

```text
[ 아키텍처 수립·운영 흐름 ]

현행 아키텍처 조사·모델링
    ↓
목표 아키텍처 설계
    ↓
차이 분석·이행계획 수립
    ↓
사업 투자·설계 심의 반영
    ↓
변경 관리·지속 갱신
```

## Ⅳ. 개별 시스템 단위 설계와 전사 아키텍처 기반 설계의 비교

- 핵심 요약 : 시스템별 부분 최적 설계에서 전사 최적의 구조 관리로 판단 단위가 이동하는 구조.

| 비교 축 | 개별 시스템 단위 설계 | 전사 아키텍처 기반 설계 |
| --- | --- | --- |
| 관점 범위 | 단일 시스템의 요구·기능 중심 | 전사 업무·데이터·기술의 통합 관점 |
| 투자 판단 | 시스템별 개별 승인 | 이행계획과 연계한 투자 조정 |
| 표준·재사용 | 시스템마다 상이한 기술 선택 | 공통 표준·참조모델 기반 재사용 |
| 중복 관리 | 중복 기능·데이터의 발견 곤란 | 중복·연계 공백의 사전 식별 |
| 변경 대응 | 시스템 단위 부분 수정 | 전사 영향 분석 후 계획적 변경 |

## Ⅴ. EA·ITA의 한계와 방안

- 핵심 요약 : 사문화·현행화 부담·거버넌스 형식화·예외 누적을 자동화와 심의 연계로 완화.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 모형 사문화 | 모형과 실제 자산의 어긋남 → 판단 신뢰 저하 | 변경 관리와 모형 갱신의 연동 | 현행화 지연 항목 수 |
| 현행화 부담 | 전사 조사·유지 비용 → 모형 품질 저하 | 자동 발견 도구·메타데이터 수집 체계 | 자동 수집 비율 |
| 거버넌스 형식화 | 심의가 문서 검토로 축소 → 투자 미반영 | 투자 심의·설계 검토 게이트와의 연계 | 아키텍처 반영 사업 비율 |
| 표준 예외 누적 | 예외 설계의 상시화 → 중복·기술부채 | 예외 근거·유효기간·철회 조건 관리 | 유효 예외 수 |

## Ⅵ. EA·ITA에 대한 기술사적 제언

- 핵심 요약 : 경영과 정보화 조직이 아키텍처를 투자·성과 관리와 결합한 경영 관리 수단으로 격상할 것.
- 경영진 : 전사 아키텍처 원칙을 경영 계획·투자 심사 기준에 명시해 사업 판단의 선행 조건화.
- 정보화 책임자 (CIO, Chief Information Officer) : 아키텍처 위원회를 통해 중복 투자·표준 준수·연계 설계를 사업 승인 조건으로 운영.
- 운영 조직 : 자동화 도구로 현행 아키텍처를 상시 갱신하고 범정부·업계 참조모델의 활용 확대.

## Ⅶ. 결론

- 핵심 요약 : EA·ITA는 개별 시스템을 넘어 전사 구조와 투자를 묶는 관리 언어.
- 현행화와 투자 심의의 연계가 유지될 때 아키텍처는 문서가 아닌 의사결정 자산으로 성립.
