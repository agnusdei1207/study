## 지식 로드맵 내 현재 위치

IT 전략·관리 → 프로젝트 관리·팀 역학 → **터크만 팀 발달 모델**

## 30초 인출

- 본질: 터크만 팀 발달 모델은 집단이 Forming, Storming, Norming, Performing 순서로 발달하고 마지막에 Adjourning으로 끝난다고 설명하는 모델
- 메커니즘: 각 단계를 구성원 사이의 관계(집단 구조)와 과업을 둘러싼 상호작용(과업 활동) 두 영역에서 보며, 탐색·의존 → 갈등 → 응집 → 기능적 역할 순으로 진행
- 통찰: Storming의 갈등을 다룰 기준이 없으면 Norming의 응집과 새 규범 형성이 늦어지므로, 킥오프 때 역할·의사결정 규칙을 합의하고 정기 회고에서 팀의 단계별 특징을 확인

<details>
<summary>핵심 용어</summary>

- **터크만 팀 발달 모델** : 집단이 시간에 따라 발달하는 순서를 집단 구조와 과업 활동 두 영역에서 단계별로 나타낸 모델
- **터크만 사다리 모델(Tuckman Ladder Model)** : 터크만 팀 발달 모델의 기출 표기. 팀이 단계를 밟아 올라가는 사다리로 표현
- **집단 구조(Group Structure)** : 구성원이 서로 행동하고 관계 맺는 대인관계의 양상
- **과업 활동(Task Activity)** : 당면한 과업과 관련된 상호작용의 내용
- **Forming** : 구성원이 서로를 탐색하고 의존하며 과업의 방향을 파악하는 단계
- **Storming** : 집단 내 갈등과 과업 요구에 대한 감정 반응이 나타나는 단계
- **Norming** : 집단 응집이 생기고 새 기준·새 역할을 받아들이며 관련 의견을 공개적으로 교환하는 단계
- **Performing** : 역할이 유연하고 기능적으로 작동해 과업의 해결책이 나오는 단계
- **Adjourning** : 1977년 터크만과 젠슨(Jensen)이 추가한 종결 단계. 분리에 대한 불안과 자기 평가가 나타남
- **PM(Project Manager)** : 프로젝트의 갈등 관리와 팀 구성을 책임지는 프로젝트 관리자

## 2~4교시 25점 답안

## Ⅰ. 터크만 팀 발달 모델의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **터크만 팀 발달 모델** 은 집단이 시간에 따라 발달하는 순서를 집단 구조와 과업 활동 두 영역에서 단계별로 나타낸 모델 |
| 목적 | 팀 발달 단계의 진단과 단계에 맞는 관리 조치 |

## Ⅱ. 문헌 검토에서 나온 단계 모델의 특징

| 특징 | 의미 |
|---|---|
| 문헌 검토 기반 | 1965년 논문이 치료집단·T-집단·자연집단·실험집단을 다룬 50편의 문헌에서 4단계 도출 |
| 두 영역 병행 | 집단 구조와 과업 활동을 나누어 단계별로 기술 |
| 순차적 단계 | Forming → Storming → Norming → Performing |
| 종결 단계 추가 | 1977년 터크만과 젠슨이 Adjourning을 다섯 번째 단계로 추가 |
| 단계 명칭 | Forming, Storming, Norming, Performing은 터크만이 붙인 용어 |

## Ⅲ. 팀 발달 단계의 체계

### 터크만 사다리: 5단계

```text
Adjourning  ── 종결: 분리·종료에 대한 불안, 자기 평가
    ↑
Performing  ── 기능적 역할, 과업 해결책 도출
    ↑
Norming     ── 응집, 새 기준·새 역할, 의견의 공개 교환
    ↑
Storming    ── 집단 내 갈등, 과업 요구에 대한 감정 반응
    ↑
Forming     ── 탐색과 의존, 과업 방향 파악
```

## Ⅳ. 단계별 집단 구조와 과업 활동의 비교

| 단계 | 집단 구조 (대인관계) | 과업 활동 |
|---|---|---|
| Forming | 탐색과 의존(Testing and dependence) | 과업 방향 파악(Orientation to the task) |
| Storming | 집단 내 갈등(Intragroup conflict) | 과업 요구에 대한 감정 반응(Emotional response to task demands) |
| Norming | 집단 응집이 생기고 새 기준·새 역할 채택 | 관련 해석·의견의 공개 교환 |
| Performing | 역할이 유연하고 기능적, 구조 문제 해소 | 대인관계 구조가 과업 수행의 도구, 해결책 도출 |
| Adjourning | 분리·종결에 대한 불안, 슬픔 | 자기 평가 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 소집단 연구 문헌에서 도출한 순서 모델이라 IT 프로젝트 팀의 단계 진입 시점을 일정으로 예측하는 기준이 아님 | 단계를 일정표에 고정하지 않고 정기 회고에서 팀이 보이는 단계의 특징을 확인해 조치 |
| Storming의 갈등을 다룰 기준이 없으면 Norming의 응집과 새 규범 형성 지연 | 킥오프 직후 역할·의사결정 규칙을 합의하고, 갈등 때 그 규칙으로 결정 |
| 프로젝트 도중 구성원 교체 시 관계·역할의 재정립 필요 | 신규 투입자에게 역할·규칙을 공유하고 방향·역할 확인 활동을 다시 수행 |

## Ⅵ. 제언

킥오프 때 역할·의사결정 규칙을 합의하고, 정기 회고에서 팀이 보이는 단계의 특징을 확인해 관리 조치를 조정

### 합의와 회고에 따른 관리 조치

```text
킥오프: 역할·의사결정 규칙 합의
    ↓
수행 중 정기 회고: 팀이 보이는 단계의 특징 확인
    ↓
단계의 특징에 맞춰 관리 조치 조정
    (예: 갈등 표출 → 합의한 규칙 적용)
```

### 갈등 처리 확대: Storming의 갈등 판단

```text
갈등 표출 (집단 내 갈등)
    ↓
합의한 의사결정 규칙으로 처리 가능한가?
    ├─ 예 → 규칙대로 결정하고 결과를 팀에 공유
    └─ 아니오 → 규칙을 보완해 재합의한 뒤 결정
```

| 구분 | 단계 진행에 맡김 | 제언: 규칙 합의와 회고 |
|---|---|---|
| 갈등 처리 기준 | 갈등 발생 뒤 사안별 협의 | 킥오프에서 합의한 규칙 |
| 단계 확인 | 관리자의 인상 | 정기 회고의 단계별 특징 대조 |
| 구성원 교체 | 팀이 자연스럽게 적응 | 역할·규칙 공유와 확인 활동 재수행 |
