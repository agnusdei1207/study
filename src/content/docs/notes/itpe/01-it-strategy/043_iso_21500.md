## 지식 로드맵 내 현재 위치

IT 전략·관리 → 프로젝트 거버넌스·표준 → **ISO 21500**

## 30초 인출

- 본질: ISO 21500은 프로젝트 관리의 개념과 39개 프로세스를 제시한 국제 지침 표준으로, 2012년판(Guidance on project management)이 프로세스 지침이고 2021년판은 맥락·개념 문서
- 메커니즘: 39개 프로세스를 5개 프로세스 그룹(Initiating·Planning·Implementing·Controlling·Closing)과 10개 주제 그룹(Integration·Stakeholder·Scope·Resource·Time·Cost·Risk·Quality·Procurement·Communication)의 교차표로 배치
- 통찰: 39개 프로세스는 모든 프로젝트에 균일하게 적용하는 대상이 아니므로 착수 시 적용할 프로세스와 엄격도를 계획서에 기록해 통제 기준으로 사용

<details>
<summary>핵심 용어</summary>

- **ISO 21500** : 프로젝트 관리의 개념과 프로세스에 관한 국제 지침 표준. 2012년 제1판은 프로젝트 관리 프로세스를 다루고, 2021년 제2판은 프로젝트·프로그램·포트폴리오 관리의 맥락과 개념을 다룸
- **ISO 21502** : 2021년판 ISO 21500이 프로세스 지침을 넘겨준 프로젝트 관리 지침 표준(2020년판)
- **Process group(프로세스 그룹)** : 프로세스를 프로젝트 관리 순서의 관점에서 묶은 5개 그룹
- **Subject group(주제 그룹)** : 프로세스를 관리 주제별로 묶은 10개 그룹
- **Tailoring(조정)** : 프로젝트나 단계에 맞춰 적용할 프로세스와 각 프로세스의 엄격도를 정하는 일. 표준은 프로젝트 관리자가 조직 정책에 따라 수행하도록 규정
- **Baseline(기준선)** : 프로젝트 성과를 감시·통제할 때 비교하는 기준
- **WBS(Work Breakdown Structure)** : 프로젝트 작업을 더 작고 관리 가능한 단위로 나누는 계층적 분해 틀. Planning 그룹의 프로세스 Create work breakdown structure가 작성

## 2~4교시 25점 답안

## Ⅰ. ISO 21500의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **ISO 21500** 은 조직 유형과 프로젝트 규모에 관계없이 쓰는 프로젝트 관리의 개념과 프로세스에 대한 국제 지침 표준 |
| 목적 | 프로젝트 관리 용어와 프로세스의 공통 기준 제공 |

## Ⅱ. 조정해서 쓰는 프로세스 지침이라는 특징

| 특징 | 의미 |
|---|---|
| 프로세스 중심 | 각 프로세스를 목적·설명·주요 입력·출력으로 기술 |
| 두 관점의 분류 | 하나의 프로세스를 **Process group** 과 **Subject group** 양쪽에 배치 |
| 산업 독립 | 적용 분야나 산업에 관계없이 적용 |
| 순서가 아닌 매핑 | 교차표는 시간 순서가 아니라 프로세스 그룹과 주제 그룹의 대응을 표시 |
| 조정 전제 | 프로세스를 모든 프로젝트에 균일하게 적용하지 않고 관리자가 프로세스와 엄격도를 조정 |
| 범위 한정 | 프로젝트 관리 프로세스만 다루고, 제품을 만드는 프로세스와 재무·물류 같은 지원 프로세스는 범위 밖 |

## Ⅲ. 프로세스 그룹과 주제 그룹 체계

### 프로세스 그룹 상호작용

```text
              Controlling
     (다른 모든 프로세스 그룹과 상호작용)
       ↕          ↕          ↕          ↕
Initiating → Planning → Implementing → Closing
```

| 프로세스 그룹 | 목적 |
|---|---|
| Initiating(착수) | 프로젝트나 단계를 시작하고 목표를 정의하며 프로젝트 관리자에게 진행 권한 부여 |
| Planning(기획) | 성과를 관리·측정할 기준선을 세울 만큼의 상세 계획 수립 |
| Implementing(이행) | 계획에 따라 프로젝트 관리 활동을 수행하고 산출물 제공을 지원 |
| Controlling(통제) | 계획 대비 성과를 감시·측정·통제하고 예방·교정 조치와 변경 요청 |
| Closing(종료) | 프로젝트나 단계의 종료를 공식 확정하고 교훈 도출 |

### 프로세스 배치 확대: 10개 주제 그룹 × 5개 프로세스 그룹, 총 39개 프로세스

| 주제 그룹 | Initiating | Planning | Implementing | Controlling | Closing |
|---|---|---|---|---|---|
| Integration(통합) | Develop project charter | Develop project plans | Direct project work | Control project work, Control changes | Close project phase or project, Collect lessons learned |
| Stakeholder(이해관계자) | Identify stakeholders | - | Manage stakeholders | - | - |
| Scope(범위) | - | Define scope, Create work breakdown structure, Define activities | - | Control scope | - |
| Resource(자원) | Establish project team | Estimate resources, Define project organization | Develop project team | Control resources, Manage project team | - |
| Time(시간) | - | Sequence activities, Estimate activity durations, Develop schedule | - | Control schedule | - |
| Cost(원가) | - | Estimate costs, Develop budget | - | Control costs | - |
| Risk(리스크) | - | Identify risks, Assess risks | Treat risks | Control risks | - |
| Quality(품질) | - | Plan quality | Perform quality assurance | Perform quality control | - |
| Procurement(조달) | - | Plan procurements | Select suppliers | Administer procurements | - |
| Communication(의사소통) | - | Plan communications | Distribute information | Manage communications | - |

## Ⅳ. ISO 21500의 판본 관계

| 구분 | ISO 21500:2012 | ISO 21500:2021 | ISO 21502:2020 |
|---|---|---|---|
| 제목 | Guidance on project management | Project, programme and portfolio management — Context and concepts | Project, programme and portfolio management — Guidance on project management |
| 다루는 내용 | 프로젝트 관리 개념과 39개 프로세스 | 프로젝트·프로그램·포트폴리오 관리의 조직 맥락과 개념, ISO/TC 258 표준 간 관계 | 프로젝트 관리 지침 |
| 프로세스 지침 | 본문에 포함 | 포함하지 않음 | 2012년판의 프로젝트 관리 지침을 이어받은 표준 |
| 판본 관계 | 2021년판이 대체 | ISO 21502:2020과 함께 제1판(2012년판)을 대체 | 2021년판이 프로젝트 관리 지침은 이 표준에 있다고 명시 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 39개 프로세스를 균일 적용하지 않는 전제라 프로젝트별로 빠지는 프로세스와 엄격도가 달라져 통제 기준이 모호 | 착수 시 프로세스별 적용 여부와 엄격도를 계획서에 기록 |
| 프로젝트 관리 프로세스만 다루므로 요구·설계·구현 같은 제품 프로세스의 산출물이 관리 프로세스와 분리 | Planning 그룹에서 제품 프로세스 산출물을 관리 프로세스의 입력·출력과 연결 |
| 프로세스 지침이 2012년판과 ISO 21502:2020으로 갈려 인용한 판본에 따라 내용이 달라짐 | 계획서와 감리·평가 기준에 인용 표준의 번호와 연도 명시 |

## Ⅵ. 제언

착수 시 Develop project charter·Develop project plans 단계에서의 프로세스 적용표 작성과 Controlling 그룹의 통제 기준 활용

### 적용표의 위치와 사용

```text
Initiating   Develop project charter    프로젝트 특성·제약 확인
    ↓
Planning     Develop project plans      적용표 작성: 프로세스별 적용 여부·엄격도
    ↓
Implementing 적용표에 따라 관리 활동 수행
    ↓
Controlling  Control project work       적용표를 기준으로 계획 대비 성과 통제
    ↓
Closing      Collect lessons learned    적용표의 과부족을 다음 프로젝트에 반영
```

### 적용표 한 행 확대: 프로세스 하나의 기록 항목

```text
프로세스 : Control changes (Integration × Controlling)
    ├─ 적용 여부 : 적용 / 생략(사유)
    ├─ 엄격도    : 변경 요청의 승인 단계·기록 범위
    ├─ 담당      : 프로젝트 관리자·승인권자
    └─ 입력·출력 : Project plans·Change requests → Approved changes·Change register
```

| 구분 | 프로세스 일괄 적용 | 제언: 적용표 기반 조정 |
|---|---|---|
| 적용 범위 결정 | 표준의 39개 전부 | 프로젝트 특성에 맞춘 프로세스 선택 |
| 통제 기준 | 담당자별 해석 | 계획서에 기록된 적용 여부와 엄격도 |
| 판본 | 명시 없음 | 인용 표준의 번호·연도 명시 |
