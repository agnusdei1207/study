## 지식 로드맵 내 현재 위치

IT 전략·관리 → 디지털 혁신·전략 → **디지털 트랜스포메이션(DX)**

## 30초 인출

- 본질: 디지털 전환(DX, Digital Transformation)은 기술 활용을 통해 고객가치와 조직의 일하는 방식을 바꾸는 경영 혁신
- 메커니즘: 현업 문제 정의 → MVP 가치 검증 → 제품화·확산 여부 판단
- 통찰: 한계: 기술 도입 건수만으로 고객·업무 가치 변화를 판단할 수 없음 → 방안: 현업 문제와 성과 기준을 먼저 정하고 MVP 결과에 따라 확산

<details>
<summary>핵심 용어</summary>

- **Digitization(전산화)** : 아날로그 정보를 디지털 데이터로 변환하는 것
- **Digitalization(디지털화)** : 디지털 기술로 기존 업무 수행방식을 개선하는 것
- **DX(Digital Transformation)** : 디지털 기술을 활용해 고객가치와 사업·운영 방식을 지속적으로 바꾸는 것
- **MVP(Minimum Viable Product)** : 핵심 가설을 검증할 수 있도록 최소 기능을 갖춘 제품
- **운영모델(Operating Model)** : 제품·업무·데이터·조직의 책임과 의사결정 방식을 연결해 고객가치를 전달하는 구조

</details>

## 2~4교시 25점 답안

## Ⅰ. DX의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **DX(디지털 전환)** 는 디지털 기술을 활용해 고객가치와 사업·운영 방식을 바꾸는 경영 혁신 |
| 목적 | 변화하는 환경에서 고객에게 새로운 가치 제공과 조직 성과 향상 |

## Ⅱ. DX의 특징

| 특징 | 의미 |
|---|---|
| 가치·운영 변화 | 기술 도입 수보다 고객 문제 해결과 업무 방식 변화 중시 |
| 대상의 선택 | 고객 접점·업무·제품·데이터·조직 중 문제와 연결된 범위 선정 |
| 단계적 확산 | 시범 성과와 운영 책임·데이터·예산을 확인한 범위부터 확대 |

## Ⅲ. 문제 정의부터 성과 검증·확산까지의 프로세스

```text
현업·고객 문제 정의 → 기준선·성과 목표 합의
          ↓
MVP 적용 → 고객·업무 지표 비교
          ↓
운영 책임·데이터·예산 확인 → 확대 또는 재설계
```

### MVP의 확대 판정 절차

```text
MVP 고객·업무 성과 ↔ 사전 기준선
    ├─ 효과 미달 → 과제 재설계
    └─ 효과 확인 → 운영 책임·데이터·보안·예산 검토
                         ↓ 준비 충족
              확대 후 효과 유지 여부 재측정
```

## Ⅳ. 전산화·디지털화·DX의 변화 범위 비교

| 구분 | 변화 대상 | 변화 결과 |
|---|---|---|
| 전산화 | 정보의 형태 | 아날로그 정보의 디지털 데이터 변환 |
| 디지털화 | 기존 업무 수행방식 | 디지털 기술을 통한 업무 개선 |
| DX | 고객가치·사업·조직의 운영방식 | 가치 제공·사업 수행방식의 변화 |

## Ⅴ. 추진의 한계와 방안

| 한계 | 방안 |
|---|---|
| 기술 중심 PoC 반복 | 해결할 문제와 확산 기준을 먼저 정하고 성과 확인 후 확대 |
| 현업 참여 부족 | 담당자·고객 요구를 과제 정의와 성과 측정에 반영 |
| 성과 측정 부재 | 도입 건수 대신 고객·업무 성과를 기준선과 비교 |
| 실험 후 운영 단절 | 운영 책임자·데이터 연계·예산·변경 권한을 정해 MVP 성과를 정착 |

## Ⅵ. 제언 — 실증 후 확대 판정

MVP 초기 수치만으로 전사 확대를 결정하지 않고, 운영 전환 뒤 고객·업무 성과가 유지된 범위까지 적용.
