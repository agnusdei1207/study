## 답안 골격
```text
[갈등관리] ◀━━ 머리: Ⅶ 내 의견 (근본 원인 데이터 기반 협력(Problem Solving) 전략 중심의 갈등 해결 체계 구축)
 ┃
 ┣━ Ⅰ 개요 ───── 프로젝트 참여자 간 이해관계 및 기술적 견해 충돌로 인한 납기 지연 방지 → 갈등의 긍정적 에너지 전환 관리
 ┣━ Ⅱ 특징 ───── 갈등의 필연성 인정 · 7대 주요 원인(일정/우선순위/자원 순) · 5대 해결 전략(토마스-킬만) · 상황별 최적 기법 적용
 ┣━ Ⅲ 구조 ───── 갈등 유발 요인(일정·우선순위·자원) ──> 갈등 성격 분석 ──> 5대 해결 전략(협력·타협·강요·회피·완화)
 ┣━ Ⅳ 흐름 ───── ① 갈등 징후 포착 → ② 근본 원인(Root Cause) 식별 → ③ 당사자 주장과 객관적 팩트 분리 → ④ 5대 전략 중 최적안 실행 → ⑤ 합의 문서화
 ┣━ Ⅴ 비교 ───── 5대 갈등 해결 전략 매트릭스 (협력 vs 타협 vs 강요 vs 회피 vs 완화 / 자신의 주장 vs 상대방 배려 축)
 ┗━ Ⅵ 실무 ───── 감정적 대립으로의 변질 / 표면적 완화(봉합) 후 재발 / PM의 일방적 강요로 인한 핵심 개발자 이탈
```
- 필수 키워드: 갈등 관리 · 7대 원인(일정/우선순위/자원) · 토마스-킬만(TKI) · 협력(Collaborating) · 타협(Compromising) · 강요(Forcing) · 회피(Avoiding) · 완화(Smoothing)
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 갈등의 7대 원인 순위 → Ⅴ 5대 해결 전략 2x2 매트릭스 / 25점 = Ⅰ~Ⅶ 전개, Ⅴ 전략별 적합 상황과 Ⅵ 실무 프로젝트 갈등 해결 시나리오 집중
- 기출: 136회 3교시 `IT 프로젝트 수행 시 PM의 입장에서 갈등 원인과 5대 해소 전략` → Ⅲ·Ⅳ·Ⅴ

## 한 줄 본질
- 서로 다른 부서와 외주 협력사 간의 일정 지연 책임 공방과 자원 배분 갈등을 방치할 경우 프로젝트 전체가 표류 → 갈등을 회피하지 않고 직면하여 원인을 객관화하고 협력(Win-Win) 및 타협을 통해 최적의 합의점을 도출 → 프로젝트 팀 결속력 강화 및 최적 솔루션 도출 / 미숙한 중재 시 감정 싸움으로 비화 위험

## 핵심 그림
```text
┌───────────────────────────────── [ 토마스-킬만 (TKI) 5대 갈등 해결 전략 매트릭스 ] ─────────────────────────────────┐
│                                                                                                                       │
│   자신의 주장성 (Assertiveness)                                                                                       │
│        ▲                                                                                                              │
│   높음 │  [ 강요 / 지시 (Forcing / Directing) ]              ★ [ 협력 / 문제해결 (Collaborating / Problem Solving) ] │
│        │  - Win - Lose                                         - Win - Win                                            │
│        │  - 비상 시, 긴급 의사결정 시 권한으로 밀어붙임         - 근본 원인을 파헤쳐 양측을 모두 만족시키는 최상 전략   │
│        │                                                                                                              │
│        │                          [ 타협 / 절충 (Compromising) ]                                                      │
│        │                          - Lose - Lose (or Win-Some Lose-Some)                                               │
│        │                          - 양측이 조금씩 양보하여 중간 합의점 도출                                            │
│        │                                                                                                              │
│   낮음 │  [ 회피 / 철회 (Avoiding / Withdrawing) ]           [ 완화 / 수용 (Smoothing / Accommodating) ]             │
│        │  - Lose - Lose                                         - Lose - Win                                           │
│        │  - 사소한 이슈이거나 감정이 격앙되었을 때 일단 후퇴    - 공통점을 강조하고 차이점을 축소해 관계를 우선시함    │
│        └──────────────────────────────────────────────────────────────────────────────────────────────────────────►   │
│        낮음 ◄────────────────────────────────────────────────────────────────────────────────────────► 높음           │
│                                           상대방에 대한 협조성 (Cooperativeness)                                      │
└───────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 핵심 용어
- 협력/문제해결(Collaborating / Problem Solving): 양측의 입장(Position) 뒤에 숨겨진 진정한 욕구(Interest)를 발견하여 양쪽 모두 승리하는 혁신적 제3의 대안을 찾는 가장 바람직한 갈등 해결 기법
- 갈등의 7대 원인: Thamhain & Wilemon 연구에 따른 프로젝트 갈등의 실제 원인 순위(1. 일정, 2. 우선순위, 3. 인력 자원, 4. 기술적 의견, 5. 행정 절차, 6. 원가, 7. 성격 차이)
- 완화/수용(Smoothing): 당장의 갈등 충돌을 막기 위해 팀의 화합을 강조하며 한쪽이 양보하는 방식이나, 근본 원인이 해결되지 않아 훗날 폭발할 위험 내포

## 핵심 통찰
- 통념과 달리 프로젝트 갈등의 가장 큰 원인은 '성격 차이(Personality)'가 아니라 '일정(Schedule)'과 '우선순위(Priority)'임 → 시스템과 프로세스의 모호성이 갈등을 유발함
- PM은 무조건적인 '협력(Win-Win)'만을 고집해서는 안 됨 → 서버 침해 사고나 납기일 하루 전 치명적 결함 발생 시에는 권한을 발동하는 '강요/지시(Forcing)'가 필수적임
- 갈등을 전혀 일으키지 않는 지나치게 조용한 팀은 혁신이 죽은 팀임 → 건강한 기술적 갈등(Task Conflict)은 권장하고, 인신공격성 감정 갈등(Relationship Conflict)만 조기에 잘라내야 함

## 딸려 나오는 하위 토픽

| 하위 토픽 | 상위 구조 속 위치 | 한 줄 (정의 → 메커니즘 → 구분축) |
|---|---|---|
| 프로젝트 갈등관리 전략 | Ⅳ 흐름 / 해결 절차 | 프로젝트 이해관계자 간 목표·일정·자원 불일치로 발생하는 갈등을 역U자형 성과 곡선 하에서 토마스-킬만의 5대 전략(협력, 타협, 경쟁, 수용, 회피)을 적용해 건설적 혁신 동력으로 전환하는 관리 기법 (갈등 무조건적 억압 vs 최적 수준 갈등 유도 및 협력적 해결) |

## 이웃 토픽과 구분
- 협력(Collaborating) vs 타협(Compromising): 협력 = 양보 없이 양측의 요구를 100% 만족시키는 새로운 아이디어를 창출(Win-Win) / 타협 = 양쪽이 모두 자신의 요구를 일부 포기하고 중간에서 타협(양보)

## 문제·원인·대책
- 사례: 136회 기출 인프라팀(보안을 위한 망분리 고수)과 개발팀(개발 생산성을 위한 외부 라이브러리 허용) 간의 3개월간의 극한 대립으로 개발이 올스톱된 사례
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 보안성과 개발 생산성 간의 대립으로 프로젝트 지연 | 양측이 각자의 입장(Position)만 주장하며 완화/타협 거부 | 협력(Collaborating) 기법 적용: 사내 프라이빗 패키지 미러(Nexus) 및 자동 악성코드 스캔 파이프라인 구축 | 보안 규제 준수와 개발 생산성 동시 확보 |
| PM의 일방적 강요로 핵심 아키텍트 퇴사 | 의사결정 근거 없는 위계에 의한 강요(Forcing) 남발 | 의사결정 기준표(가중치 매트릭스)를 사전에 공개하고 객관적 데이터 기반 결정 | 팀원 신뢰 유지 및 의사결정 수용성 제고 |

## 이렇게 출제된다
- 제136회 3교시 1번: "IT프로젝트 수행 시 PM은 프로젝트 내ㆍ외부의 다양한 갈등을 관리하고 해소하여야 한다. PM의 입장에서 갈등의 원인과 5대 해소 전략(협력, 타협, 강요, 회피, 완화)을 설명하시오." → 요구 포인트: Ⅲ 7대 갈등 원인 분석 + Ⅴ 토마스-킬만 5대 전략 개념 및 적용 시나리오

## 내 의견
- [감정적 충돌에서 객관적 사실 기반 아키텍처 결정 기록(ADR) 도입을 통한 갈등 예방] 팀 회의에서 목소리 큰 엔지니어의 의견으로 기술 스택이 결정되거나 뒤에서 험담하는 감정 싸움 빈발 → 나라면: 기술적 견해 대립 발생 시 '아키텍처 결정 기록(Architecture Decision Record, ADR)' 템플릿 작성을 의무화하여, 각 대안의 장단점, 트레이드오프, 벤치마크 실측 수치를 문서로만 대조하게 함으로써 인간 대 인간의 감정 갈등을 아이디어 대 아이디어의 생산적 토론으로 승화
