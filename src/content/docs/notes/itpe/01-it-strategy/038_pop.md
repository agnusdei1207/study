## 지식 로드맵 내 현재 위치

IT 전략·관리 → 제조 정보화·공급망 → **POP**

## 30초 인출

- 본질: POP(Point Of Production, 생산시점관리)는 공장의 기계·설비·작업자·작업에서 발생하는 생산 정보를 발생 시점에 직접 수집해 현장 관리자에게 제공하는 시스템
- 메커니즘: 생산계획·작업지시에 따라 현장 터미널·바코드·설비 신호로 실적·불량·설비 가동을 실시간 수집하고 집계·분석해 MES·ERP에 전달
- 통찰: 수기 입력은 지연과 오입력으로 실적의 정확성·실시간성이 떨어지고 설비마다 다른 인터페이스가 자동 수집의 걸림돌이므로 통신 가능한 설비부터 표준 통신(OPC UA)으로 자동 수집하고 실적은 작업지시 번호 기준으로 기록

<details>
<summary>핵심 용어</summary>

- **POP(Point Of Production)** : 생산 현장에서 발생하는 정보를 그 시점에 직접 읽어 들여 처리하고 현장 관리자에게 제공하는 생산시점관리 시스템
- **MES(Manufacturing Execution System)** : ISA-95 Level 3에서 ERP(Level 4)와 설비 제어(Level 0~2) 사이의 제조 운영을 관리하는 시스템
- **ERP(Enterprise Resource Planning)** : 생산계획·물류 등 기업 자원을 통합 관리하는 상위 업무 시스템. ISA-95 Level 4
- **PLC(Programmable Logic Controller)** : 설비를 감시·제어하는 제어 장치. ISA-95 Level 2에서 설비 신호의 원천
- **작업지시** : 생산계획을 현장 작업 단위로 내린 지시. POP 실적을 계획과 대조하는 기준
- **생산실적** : 작업지시에 대해 현장에서 실제로 생산한 수량과 불량·설비 가동 정보
- **재공품** : 생산 공정 안에서 아직 완성되지 않은 상태의 제품
- **OPC UA** : 센서·제어 시스템·MES·ERP 사이에서 인증·암호화·무결성 확인을 갖추고 데이터를 주고받는 플랫폼 독립 표준

## 2~4교시 25점 답안

## Ⅰ. POP의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **POP(Point Of Production)** 는 생산 현장의 설비·작업자·작업에서 발생하는 정보를 생산 시점에 직접 수집·처리해 현장 관리자에게 제공하는 시스템 |
| 목적 | 계획 대비 실적·불량·설비 가동 현황의 실시간 파악 |

## Ⅱ. 현장 정보를 발생 시점에 받는 POP의 특징

| 특징 | 의미 |
|---|---|
| 발생 시점 수집 | 기계·설비·작업자·작업에서 생산 정보를 직접 획득 |
| 실시간 처리 | 수집 즉시 집계·조회로 현장 관리자에게 제공 |
| 계획·지시 기반 | 생산계획과 작업지시에 대응해 실적 집계 |
| 관리 범위 | 생산진도·재공품·설비 가동·불량 등 현장 관리 정보 |

## Ⅲ. POP의 수집·처리 체계

### POP 수집·전달 체계

```text
ERP ── 생산계획
   ↓
MES ── 작업지시
   ↓
POP ── 현장 실적 수집·집계
   ↑            ↑
작업자 터미널   설비 (PLC 신호)
바코드 입력
   ↓
현장 관리자 조회 · MES·ERP 실적 전달
```

### 실적 수집 확대: 수집 지점별 처리 흐름

```text
작업지시 번호 확인
    ↓
수집 방식 판단
    ├─ 설비 통신 가능 → 설비 신호를 자동 수집 (수량·가동·비가동)
    └─ 통신 불가 → 작업자가 터미널에서 바코드 스캔·입력
    ↓
작업지시 번호에 실적·불량 매칭
    ↓
계획 대비 집계 → 현장 조회 · 상위 시스템 전달
```

## Ⅳ. ERP·MES·POP의 층위 비교

| 비교축 | ERP | MES | POP |
|---|---|---|---|
| 관리 대상 | 기업 계획·물류 (ISA-95 Level 4) | 제조 운영 (ISA-95 Level 3) | 현장에서 발생하는 생산 정보의 수집·조회 |
| 핵심 산출 | 생산계획 | 작업지시와 제조 운영 관리 | 실적·불량·설비 가동 데이터 |
| 시간 관점 | 계획 주기 | 생산 실행 | 발생 시점 |
| 데이터 방향 | 계획을 하향 | 지시를 하향, 실적을 상향 | 현장 데이터를 상향 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 수기·바코드 입력에 의존한 지점의 입력 지연과 오입력 | 통신 가능한 설비의 신호는 자동 수집으로 전환, 입력 지점은 작업지시 번호 바코드 스캔으로 한정 |
| 설비마다 다른 인터페이스로 연동 부담 증가 | 설비 데이터 교환에 플랫폼 독립 표준 OPC UA 적용 |
| 실적이 작업지시와 연결되지 않으면 계획 대비 분석 불가 | 모든 실적을 작업지시 번호 기준으로 기록 |

## Ⅵ. 제언

통신 가능한 설비부터 OPC UA 기반 자동 수집으로 전환하고, 수기 입력 지점은 작업지시 번호 바코드 스캔으로 한정해 실적의 정확성·실시간성 확보

### 수집 경로 전환 구조

```text
설비 (PLC) ── 신호 ──→ POP 서버 ←── 스캔 ── 작업자 터미널
              (OPC UA)              (작업지시 번호)
                        ↓
        작업지시 번호 기준 실적 기록 → MES·ERP 전달
```

### 전환 대상 선별 확대: 설비별 수집 방식 결정

```text
설비 단위 점검
    ├─ OPC UA 연동 가능 → 자동 수집 전환 (우선)
    └─ 연동 불가 → 작업자 바코드 스캔 유지
```

### 선택 근거: 전면 수기 집계와의 비교

| 구분 | 수기·개별 집계 | 제언: 자동 수집 우선 |
|---|---|---|
| 실적 확인 시점 | 입력 이후 | 발생 시점 |
| 설비 연동 방식 | 설비별 개별 인터페이스 | 플랫폼 독립 표준 OPC UA |
| 입력 오류 | 작업자 입력 전 구간 | 연동 불가 지점으로 한정 |
| 실적 기록 기준 | 집계 담당별 상이 | 작업지시 번호 |
