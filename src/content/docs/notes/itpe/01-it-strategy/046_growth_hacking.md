IT 전략·관리 → 데이터 기반 마케팅·성장전략 → **그로스 해킹**

## 30초 인출

- 본질: 그로스 해킹(Growth Hacking)은 빠른 실험과 데이터 분석으로 제품·서비스의 성장 지표를 반복 개선하는 방식이며, 용어는 2010년 Sean Ellis의 growth hacker 정의에서 유래
- 메커니즘: AARRR(Acquisition·Activation·Retention·Referral·Revenue) 단계별 전환율을 측정해 개선할 단계를 정하고 가설·실험(A/B 테스트)·분석·확산 또는 폐기를 반복
- 통찰: 추천(Referral)은 사용자가 만족한 뒤에 유도해야 하고 가입만으로 보상하면 실사용 없는 가입이 지표를 부풀리므로, 피추천인의 활성화(Activation) 확인 뒤 보상 지급

<summary>핵심 용어</summary>

- **그로스 해킹(Growth Hacking)** : 실험과 측정으로 성장을 반복 개선하는 방식. 마케팅과 제품·기술 역량을 함께 사용
- **Growth hacker** : Sean Ellis가 2010년 "성장이 진북(true north)인 사람. 하는 모든 일이 확장 가능한 성장에 미칠 잠재 효과로 검토되는 사람"이라고 정의
- **AARRR** : 사용자 여정을 Acquisition·Activation·Retention·Referral·Revenue 5단계로 나눠 측정하는 지표 체계. Dave McClure의 "Startup Metrics for Pirates"
- **Acquisition(획득)** : 사용자가 여러 채널에서 사이트로 유입
- **Activation(활성화)** : 첫 방문에서 사용자가 만족스러운 경험을 얻는 단계
- **Retention(유지)** : 사용자가 다시 방문하고 여러 번 사용
- **Referral(추천)** : 제품이 마음에 든 사용자가 다른 사람에게 추천
- **Revenue(수익)** : 사용자가 수익이 되는 행동을 수행
- **A/B 테스트(A/B testing)** : 두 가지 변형을 사용자에게 나눠 보여 주고 지표를 비교하는 실험

## 2~4교시 25점 답안

## Ⅰ. 그로스 해킹의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **그로스 해킹(Growth Hacking)** 은 빠른 실험과 데이터 분석으로 제품·서비스의 성장 지표를 반복 개선하는 방식 |
| 목적 | 사용자 획득·유지·수익 지표의 신속한 개선 |

## Ⅱ. 실험과 측정으로 성장을 개선하는 그로스 해킹의 특징

| 특징 | 의미 |
|---|---|
| 성장 최우선 | 모든 활동을 **확장 가능한 성장** 에 미칠 잠재 효과로 검토 |
| 실험 반복 | 빠른 실험, 분석 기반 측정, 효과가 확인된 것의 확산을 반복 |
| 단계별 측정 | **AARRR** 각 단계의 전환율(%)·규모(#)·비용($)을 측정 |
| 융합 역량 | 마케팅과 기술·제품 개선을 함께 수행하고 성장 요소를 제품 설계에 포함 |

## Ⅲ. 성장 실험 체계

### 단계 측정에서 실험 반복까지

```text
AARRR 단계별 전환율 측정
    Acquisition → Activation → Retention → Referral → Revenue
    ↓
개선할 단계 선정
    ↓
가설 수립 → 실험(A/B 테스트) → 결과 분석
    ↓
    ├─ 효과 확인 → 확산
    └─ 효과 없음 → 폐기 후 다음 가설
```

### 지표 확대: 단계별 측정 항목

```text
단계 하나
    ├─ 전환율(%) : 이전 단계 사용자 중 다음 행동에 도달한 비율
    ├─ 규모(#)   : 단계에 도달한 사용자 수
    └─ 비용($)   : 단계 도달에 든 비용
```

## Ⅳ. AARRR 5단계

| 단계 | 사용자 행동 |
|---|---|
| **Acquisition** | 여러 채널에서 사이트로 유입 |
| **Activation** | 첫 방문에서 만족스러운 경험 |
| **Retention** | 재방문과 반복 사용 |
| **Referral** | 제품이 마음에 들어 다른 사람에게 추천, 유도는 만족한 경험(10점 만점 평균 8점 이상) 뒤 |
| **Revenue** | 수익이 되는 행동 수행 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 만족한 사용 경험이 확인되기 전에 추천 실험을 하면 전환이 낮은 앞 단계를 두고 뒤 단계만 개선 | Activation 지표 충족 뒤에 Referral 실험 시작 |
| 가입만으로 보상하면 실사용 없는 가입도 성공으로 집계되어 지표 왜곡 | 성공 지표를 Activation 이후의 사용자 행동으로 정의하고 보상은 활성화 확인 뒤 지급 |

## Ⅵ. 제언

추천 보상의 지급 시점을 가입이 아닌 피추천인의 활성화 확인 뒤로 설정

### 추천 보상 지급 구조

```text
기존 사용자가 추천 링크 공유
    ↓
피추천인 가입 (Acquisition)
    ↓
피추천인 첫 사용 경험 완료 (Activation 기준)
    ├─ 미충족 → 보상 보류
    └─ 충족 → 추천인에게 보상 지급, Referral 전환으로 집계
```

### Activation 기준 확대: 활성화 판정 항목

```text
Activation 기준 (제품별로 정의)
    ├─ 핵심 기능의 사용 여부
    └─ 첫 사용 만족도 : McClure의 제시는 10점 만점 평균 8점 이상
```

| 구분 | 가입 시점 보상 | 제언: 활성화 확인 뒤 보상 |
|---|---|---|
| 보상 조건 | 가입 | 첫 사용 경험 완료 |
| 실사용 없는 가입 | 성공으로 집계 | 보상·전환 집계 제외 |
| 추천 시점 | 만족 여부와 무관 | 만족한 사용자 대상 |
