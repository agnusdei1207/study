## 지식 로드맵 내 현재 위치

IT 전략·관리 → 경영 전략·성과관리 → **BSC**

## 30초 인출

- 본질: BSC(Balanced Scorecard, 균형성과표)는 재무·고객·내부 프로세스·학습과 성장의 네 관점으로 전략 실행 성과를 관리하는 체계
- 메커니즘: 학습과 성장의 역량이 내부 프로세스를 개선하고, 고객 가치를 거쳐 재무 성과로 이어진다는 인과 가설을 지표로 측정
- 통찰: 검증하지 않은 인과 가정은 효과 없는 과제를 남기므로 선행·후행지표 쌍의 정기 검증과 과제 조정

<details>
<summary>핵심 용어</summary>

- **BSC(Balanced Scorecard)** : 재무·고객·내부 프로세스·학습과 성장의 네 관점으로 전략 목표와 성과지표를 연결하는 성과관리 체계
- **Strategy Map(전략체계도)** : 네 관점의 전략 목표 사이 인과관계를 화살표로 표현한 그림
- **선행지표(Leading Indicator)** : 교육 이수율·개발 리드타임처럼 미래 결과에 앞서 변하는 성과 동인 지표
- **후행지표(Lagging Indicator)** : 매출·영업이익률·고객 만족도처럼 활동의 최종 결과를 사후에 보여 주는 지표
- **KPI(Key Performance Indicator)** : 전략 목표의 달성 수준을 측정하는 핵심 성과지표
- **Target(목표치)** : KPI가 정해진 기간 안에 도달할 수준
- **Initiative(실행과제)** : 목표치 달성을 위해 예산·인력을 투입하는 구체적 과제
- **IT-BSC(IT Balanced Scorecard)** : 기업 공헌·사용자 지향·운영 우수성·미래 지향 관점으로 IT 조직의 성과를 측정하는 BSC의 IT 적용 모델(Van Grembergen·Van Bruggen, 1997)

## 2~4교시 25점 답안

## Ⅰ. BSC의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **BSC(Balanced Scorecard)** 는 재무·고객·내부 프로세스·학습과 성장의 네 관점으로 전략 목표와 성과지표를 연결하는 성과관리 체계 |
| 목적 | 재무 결과 편중의 보완과 전략 실행 성과의 균형 관리 |

## Ⅱ. 재무 지표 중심 평가와 구별되는 BSC의 특징

| 특징 | 의미 |
|---|---|
| 관점의 균형 | 재무·비재무 성과와 외부 고객·내부 프로세스의 동시 관리 |
| 시간의 균형 | 결과를 보여 주는 **후행지표** 와 원인을 보여 주는 **선행지표** 의 병행 |
| 인과 가설 | 관점 간 원인·결과 관계를 **Strategy Map** 으로 명시 |
| 전략과 실행 연결 | 전략 목표마다 KPI·목표치·실행과제의 묶음 관리 |

## Ⅲ. BSC 네 관점의 인과 구조와 전략 목표 구성

### BSC 네 관점의 인과 구조

```text
비전·전략
    ↓ 관점별 전략 목표로 전환
학습과 성장: 인적 역량·정보 자본·조직 문화
    ↓ 역량이 프로세스 개선을 견인
내부 프로세스: 운영·고객관리·혁신 프로세스
    ↓ 프로세스 개선이 고객 가치로 연결
고객: 만족·유지·신규 확보
    ↓ 고객 성과가 재무 결과로 연결
재무: 수익 성장·생산성 향상
```

### 전략 목표 확대: 목표·지표·실행과제 구성

```text
전략 목표 (예: 장애 복구 시간 단축)
    │
    ├─ KPI ── 선행지표·후행지표 한 쌍
    │
    ├─ Target ── 기간별 목표치
    │
    └─ Initiative ── 예산·인력을 투입하는 실행과제
```

## Ⅳ. BSC와 IT-BSC의 관점 비교, 선행·후행지표

### 일반 BSC와 IT-BSC의 관점 대응

| 일반 BSC 관점 | 관리 초점 | **IT-BSC** 관점 | 관리 초점 |
|---|---|---|---|
| 재무 | 수익 성장·원가 절감 | 기업 공헌(Corporate Contribution) | IT 투자의 사업 가치 기여 |
| 고객 | 고객 만족·유지 | 사용자 지향(User Orientation) | 현업 사용자의 IT 평가 |
| 내부 프로세스 | 핵심 업무 효율 | 운영 우수성(Operational Excellence) | 애플리케이션 개발·제공 프로세스 품질 |
| 학습과 성장 | 인력·정보 역량 | 미래 지향(Future Orientation) | 향후 서비스에 필요한 인력·기술 자원 준비 |

### 선행지표와 후행지표

| 구분 | 선행지표 | 후행지표 |
|---|---|---|
| 의미 | 결과에 앞서 변하는 성과 동인 | 활동의 최종 결과 |
| 예 | 운영 인력 교육 이수율, 자동화율 | 장애 복구 시간, 사용자 만족도 |
| 측정 시점 | 실행 중 수시 | 일정 기간 경과 후 |
| 쓰임 | 실행과제의 조기 조정 | 전략 목표의 달성 판정 |

두 지표를 한 쌍으로 두어야 관점 간 인과 가설의 성립 여부 확인 가능

## Ⅴ. BSC 운영의 한계와 방안

| 한계 | 방안 |
|---|---|
| 재무 후행지표 편중으로 원인 파악 지연 | 관점별 선행지표의 병행 측정 |
| 전략체계도의 인과관계를 검증 없이 가정 | 선행·후행지표 한 쌍의 기간별 변화 비교로 가설 점검 |
| 지표 과다로 전략 초점 분산 | 전략 목표별 소수 KPI 선정과 중복 지표 제거 |
| 보상 연동에 따른 목표치 하향·실적 왜곡 | 지표 산식·원천의 검증과 목표치 설정 근거 공개 |

## Ⅵ. 제언

전략체계도의 핵심 인과 가설 하나를 선행·후행지표 한 쌍으로 정기 검증하고, 그 결과에 따른 실행과제의 유지·수정

### 인과 가설 검증 책임 구조

```text
전략 성과 검토 회의
    │
    ├─ 전략 담당 조직 ── 검증할 핵심 인과 가설 선정
    │
    ├─ 지표 책임자 ── 선행·후행지표 측정
    │
    └─ 실행과제 책임자 ── 과제 유지·수정 실행
```

### 지표 책임자 역할 확대: 인과 가설 검증 절차

```text
선행지표 변화 확인 (예: 운영 인력 교육 이수율)
    ↓ 효과가 나타날 기간 경과
후행지표 변화 확인 (예: 장애 복구 시간)
    ↓
외부 요인·업무량 변화 검토
    ├─ 가설 지지 → 실행과제 유지·확대
    └─ 가설 불지지 → 지표 교체 또는 실행과제 수정
```

### 선택 근거: 지표 실적 관리와의 비교

| 구분 | 지표 실적 관리 | 제언: 인과 가설 검증 |
|---|---|---|
| 검토 대상 | KPI별 목표치 달성 여부 | 선행·후행지표 사이의 연결 |
| 목표 미달 시 조치 | 담당 부서 평가 하향 | 가설·실행과제의 수정 |
| 전략체계도의 역할 | 수립 시 한 번 작성 | 정기 검증 대상 |
| 지표 교체 근거 | 관행·평가 편의 | 가설 불지지 결과 |
