## 지식 로드맵 내 현재 위치

IT 전략·관리 → 디지털 혁신·전략 → **애자일 전환 전략**

## 30초 인출

- 본질: 애자일 전환 전략은 팀 단위의 애자일 방식을 조직 구조·예산·거버넌스까지 넓혀 가치를 빠르게 전달하는 조직 변화 계획
- 메커니즘: 가치흐름 단위로 팀을 묶고, 확장 방식으로 팀 간 계획을 맞추며, 프로젝트 예산을 가치흐름·제품 예산으로 전환
- 통찰: 예산과 승인이 프로젝트 단위로 남으면 팀만 바뀌고 전달 속도는 그대로이므로 가치흐름 단위 예산과 성과 검토 전환

<details>
<summary>핵심 용어</summary>

- **애자일 전환 전략** : 애자일 가치를 팀 운영에서 조직 구조·예산·거버넌스로 넓히는 조직 차원의 변화 계획
- **Agile Manifesto(애자일 선언)** : 개인과 상호작용, 작동하는 소프트웨어, 고객 협력, 변화 대응을 우선하는 2001년 선언
- **가치흐름(Value Stream)** : 고객 요구에서 가치 전달까지 이어지는 활동과 그 활동을 수행하는 사람·시스템의 묶음
- **SAFe(Scaled Agile Framework)** : 여러 팀을 ART 단위로 묶고 포트폴리오 예산까지 규정하는 대규모 애자일 확장 프레임워크
- **ART(Agile Release Train)** : SAFe에서 같은 가치흐름의 여러 애자일 팀이 공동 일정으로 계획·전달하는 팀 묶음
- **LeSS(Large-Scale Scrum)** : 하나의 제품 책임자·제품 백로그·완료 정의를 여러 팀이 공유하는 스크럼 확장 방식
- **린 예산(Lean Budgets)** : 프로젝트가 아닌 가치흐름에 예산을 배정하는 SAFe의 재무 거버넌스 방식

## 2~4교시 25점 답안

## Ⅰ. 애자일 전환 전략의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **애자일 전환 전략** 은 팀 단위의 애자일 방식을 조직 구조·예산·거버넌스로 넓히는 조직 차원의 변화 계획 |
| 목적 | 요구 변화에 대한 조직 대응 속도 향상과 고객 가치의 조기 전달 |

## Ⅱ. 팀 단위 애자일 도입과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 가치흐름 중심 조직 | 기능 부서 대신 고객 가치 전달 단위의 교차기능 팀 구성 |
| 팀 간 동기화 | 여러 팀의 공동 계획·통합 주기 운영 |
| 재무 거버넌스 변화 | 프로젝트 승인·예산의 가치흐름·제품 단위 배정 |
| 경영진 역할 변화 | 세부 과업 승인 대신 목표·우선순위와 제약의 설정 |

## Ⅲ. 애자일 전환 체계와 추진 절차

### 애자일 전환 체계

```text
애자일 전환 전략 ── 경영진 후원
    │
    ├─ 조직 구조 ── 가치흐름 단위 교차기능 팀
    │
    ├─ 확장 방식 ── 팀 간 공동 계획·통합 주기
    │
    ├─ 재무·거버넌스 ── 가치흐름 예산·성과 검토
    │
    └─ 팀 운영 ── 스크럼 등 팀 단위 방법
```

팀 운영의 세부 절차는 [스크럼](../02-software-engineering/025_scrum.md)에서 다루고, 이 체계는 그 위의 조직·재무 구조를 다룸

### 추진 절차 확대: 가치흐름 단위 단계적 전환

```text
고객 가치 기준 가치흐름 식별
    ↓
시범 가치흐름 선정과 교차기능 팀 구성
    ↓
확장 방식과 공동 계획 주기 적용
    ↓
가치흐름 예산 전환과 성과 검토
    ├─ 전달 속도·품질 개선 확인 → 다음 가치흐름 확대
    └─ 개선 미흡 → 팀 경계·의존성 재조정
```

## Ⅳ. 대규모 확장 방식의 비교

| 구분 | SAFe | LeSS |
|---|---|---|
| 기본 단위 | 가치흐름별 ART | 한 제품을 함께 만드는 여러 팀 |
| 제품 책임 | 팀별 Product Owner와 상위 제품 관리 | 하나의 Product Owner·Product Backlog |
| 예산·거버넌스 | 포트폴리오 단위 린 예산까지 규정 | 조직 설계 단순화 중심, 재무 규정 최소 |
| 적합 조건 | 여러 가치흐름·규제·포트폴리오 통제가 필요한 대규모 조직 | 단일 제품에 팀이 집중되고 조직 단순화가 가능한 경우 |

계획 주도 방식과의 선택 기준: 요구가 안정되고 계약·규제로 범위가 고정된 사업은 계획 주도, 요구 변동이 크고 빠른 피드백이 가치를 좌우하는 사업은 애자일 전환

## Ⅴ. 애자일 전환의 한계와 방안

| 한계 | 방안 |
|---|---|
| 팀만 애자일이고 예산·승인은 프로젝트 단위로 남음 | 가치흐름 단위 예산 배정과 정기 성과 검토 전환 |
| 기능 부서 간 인계로 팀 간 의존성 누적 | 가치흐름 단위 교차기능 팀 재구성 |
| 여러 가치흐름의 통제가 필요한 조직에 단순 확장 적용 | 포트폴리오 통제가 필요하면 SAFe 선택 |
| 단일 제품 조직에 과도한 프레임워크 도입 | 단일 제품·조직 단순화가 가능하면 LeSS 선택 |

## Ⅵ. 제언

시범 가치흐름부터 프로젝트 예산을 가치흐름 예산으로 바꾸고, 경영진은 과업 승인 대신 정기 성과 검토로 투자 방향을 조정

### 가치흐름 예산 책임 구조

```text
가치흐름 예산
    │
    ├─ 경영진 ── 가치흐름별 예산 한도·우선순위 결정
    │
    ├─ 가치흐름 책임자 ── 예산 안의 작업 우선순위 결정
    │
    └─ 교차기능 팀 ── 전달 결과와 성과 지표 보고
```

### 경영진 역할 확대: 정기 성과 검토 절차

```text
가치흐름별 전달 속도·고객 성과 보고
    ↓
목표 대비 성과 확인
    ├─ 목표 충족 → 예산 유지 또는 증액
    └─ 목표 미달 → 우선순위·예산 재배정
```

### 선택 근거: 프로젝트 단위 통제와의 비교

| 구분 | 프로젝트 단위 통제 | 제언: 가치흐름 예산·성과 검토 |
|---|---|---|
| 예산 배정 단위 | 개별 프로젝트 | 가치흐름·제품 |
| 경영진 개입 방식 | 과업·변경 건별 승인 | 정기 성과 검토와 예산 조정 |
| 변경 대응 | 재승인 후 반영 | 예산 한도 안에서 우선순위 조정 |
| 성과 판단 기준 | 일정·예산 준수 | 고객 성과와 전달 속도 |
