## 연관 키워드

- SW사업 대가산정, 소프트웨어 원가, 기능점수, Function Point
- 투입공수, M/M, 직접원가, 제경비, 기술료, 실비정액가산방식
- 공공 SW, ISMP, 유지관리 요율, 클라우드, AI

## Ⅰ. SW사업 대가산정의 개요

- 핵심 요약 : SW 생애주기 전반의 적정 비용을 공학적·통계적 기준으로 산정해 품질과 가격 신뢰를 확보하는 원가 체계.
- 개념 : 소프트웨어 원가에 해당하는 기획, 개발, 운영, 유지관리 비용을 공학적·통계적 기준에 따라 객관적으로 산정하는 **SW사업 대가산정** 절차.
- 배경 및 필요성 : 개발자의 경험이나 감에 기댄 가격 산정은 저가 수주, 잦은 과업 변경, 납품 품질 저하를 부른다. 이를 막기 위해 한국소프트웨어산업협회가 「SW사업 대가산정 가이드」를 발간해 산정 기준을 표준화해 왔음.
- 주요 목적 : 적정 개발 예산으로 SW 품질을 보장하고, 발주자와 수주자 사이의 가격 신뢰를 구축하며, SW의 적정 가치를 인정받는 시장을 정착시킴.

## Ⅱ. SW사업 대가산정의 특징 및 장점

- 핵심 요약 : 기능 규모와 비용 항목을 분리해 산정 근거를 제시함으로써 과업과 가격 협의를 돕는 구조.

1. **기능점수** (FP, Function Point) : 사용자 관점의 기능 규모를 측정함 → 구현 기술에 따른 편차 감소.
2. 단계별 산정 : 초기 간이 추정과 상세 설계 후 재산정을 구분함 → 불확실성 관리.
3. 원가 항목 분리 : 인건비, 경비, 제경비, 기술료를 나눔 → 견적의 투명성 향상.
4. 사업 유형 구분 : 개발, 유지관리, 상용 SW의 비용 구조에 맞는 기준 선택 → 과잉·과소 산정 방지.
5. 변경 근거 확보 : 기능 규모와 비용 가정을 기록함 → 과업 변경 시 재산정 근거 확보.

## Ⅲ. SW사업 대가산정의 구조 (흐름)

- 핵심 요약 : 데이터와 트랜잭션 기능을 측정해 보정 기능점수를 구하고, 단가와 원가 항목을 더해 최종 대가를 확정하는 흐름.
- 기능점수 산정에서 데이터 기능은 **내부논리파일** (ILF, Internal Logical File)과 **외부연계파일** (EIF, External Interface File)로, 트랜잭션 기능은 **외부입력** (EI, External Input), **외부출력** (EO, External Output), **외부조회** (EQ, External Inquiry)로 나뉜다.
- 최종 대가는 **실비정액가산방식** (직접원가와 제경비, 기술료를 합산하는 방식)으로 확정하며, 제경비 상향은 2022년 개정판에서 이루어졌다(협회 발표 기준. 기존 110~120%에서 크게 인상됨).

```text
[기능점수 산정 흐름]
1. 데이터 기능 측정 (ILF, EIF)
        +
2. 트랜잭션 기능 측정 (EI, EO, EQ)
        ↓
3. 미조정 기능점수(UFP, Unadjusted Function Point) 도출
        ↓
4. 보정계수 곱 적용
        ↓
5. 보정 FP x 기능점수당 단가
```

```text
[SW 개발비 원가 구성]
직접인건비
   + 직접경비
   + 제경비 (직접인건비 x 제경비율)
   + 기술료 ((인건비+제경비) x 기술료율)
   ↓
최종 사업 대가
```

## Ⅳ. 기능점수 방식과 투입공수 방식의 비교

- 핵심 요약 : 기능점수 방식은 객관성이 높아 공공 SW 사업의 기본 방식으로 쓰이고, 투입공수 방식은 기능 도출이 어려운 보조 수단에 머무름.
- **투입공수** (M/M, Man-Month) 방식은 인력과 기간으로 대가를 정하는 방식이며, 기능 도출이 어려운 경우의 보조 수단으로 쓰임.

```text
[산정 방식 선택 흐름]
사업 유형 확인
        ↓
기능 도출 가능? ── 예 ──→ 기능점수 방식
        ↓ 아니오
유지관리·R&D(Research and Development) 기획 ──→ 투입공수 방식 (보조)
```

| 비교 항목 | 기능점수 (Function Point) 방식 | 투입공수 (Man-Month) 방식 |
| --- | --- | --- |
| 산정 기준 | 요구되는 소프트웨어의 기능적 규모 | 투입 인력의 수와 기간 |
| 객관성 | 표준화된 기능 측정 규칙을 적용해 상대적으로 높음 | 생산성 차이가 반영되지 않아 과대 산정 여지가 있음 |
| 적용 단계 | 기획 단계의 간이법, 분석·설계 완료 후 정규법 | 기능 도출이 어려운 유지관리와 R&D 기획 등 보조 적용 |

## Ⅴ. SW사업 대가산정의 한계와 방안

- 핵심 요약 : FP 판정 차이, 신기술 비용 누락, 운영 대가의 불확실성을 근거 기록과 단계별 재산정으로 다룸.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| FP 산정 결과 차이 | 기능 경계 해석에 따라 **FP 산정 결과**가 달라짐 | 요구사항, 기능 목록, 판정 근거를 함께 검토하고 이견 조정 절차 마련 | FP 판정 일치율, 재산정 건수 |
| 신기술 비용 누락 | **AI·클라우드**의 데이터와 운영 비용이 기능 규모만으로 드러나지 않음 | 사업 유형에 맞는 별도 비용 항목을 식별하고 가이드 기준으로 산정 | 별도 비용 항목 식별률 |
| 유지관리 범위 모호 | 초기 견적에서 **유지관리 범위**가 모호해 운영비 분쟁 발생 | 서비스 수준, 변경 범위, 지원 수준을 명시하고 단계별로 재검토 | 변경 요청 건수, 운영비 정산 오차 |

## Ⅵ. SW사업 대가산정에 대한 기술사적 제언

- 핵심 요약 : 사후 정산 체계, 유지관리 요율의 현실화, 클라우드·AI 대가 기준의 정비.

ISMP(Information System Master Plan) 등 기획 단계의 간이 기능점수는 요구사항이 충분하지 않아 오차가 크므로, 상세 설계가 끝난 시점에 기능점수를 다시 산정해 계약 금액을 조정하는 사후 정산 방식을 제도화하는 것이 합리적이다. 이 방식을 쓰면 초기 저가 수주와 이후 과업 변경 분쟁을 함께 줄일 수 있다.

상용 SW의 유지관리 요율이 외산 제품에 비해 낮게 설정되면 공급자가 재투자하기 어려워진다. 요율을 원가와 시장 수준에 맞게 조정해야 품질 유지를 위한 재투자 구조가 만들어진다.

클라우드와 AI 서비스는 라이선스 중심의 기존 대가 기준으로 설명하기 어렵다. 구독형 과금이나 사용량 기반 과금 같은 새로운 과금 방식을 반영한 대가 가이드를 마련해야 발주자와 수주자가 같은 기준으로 협의할 수 있다.

## Ⅶ. 결론

- 핵심 요약 : SW사업 대가산정은 기능 규모 측정에 기반한 객관적 원가 산정 체계.
- 시사점 : 신기술 반영, 유지관리 요율의 현실화, 사후 정산을 함께 보완해야 대가 체계의 실효성이 유지됨.
