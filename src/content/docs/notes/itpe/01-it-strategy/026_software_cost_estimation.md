## 지식 로드맵 내 현재 위치

IT 전략·관리 → 공공 SW사업 관리 → **SW사업 대가산정**

## 30초 인출

- 본질: SW사업 대가산정은 SW사업의 적정 대가를 사업 유형에 맞는 기준으로 계산하는 활동
- 메커니즘: 기획·구현·운영 사업 유형에 따라 업무량·기능점수·요율·투입공수 중 산정 방식을 고르고 원가·직접경비·이윤을 합산
- 통찰: 총액 중심 산정은 과업 변경 때 분쟁을 부르므로 요구사항·기능·산정 내역 연결과 변경 기능만의 재산정

<details>
<summary>핵심 용어</summary>

- **SW사업 대가산정** : SW사업의 유형과 범위에 맞는 기준을 적용해 적정 사업 대가를 계산하는 활동
- **FP(Function Point, 기능점수)** : 사용자가 인식하는 기능의 규모를 수치로 나타낸 SW 규모 측정 단위
- **ILF(Internal Logical File, 내부논리파일)** : 측정 대상 시스템이 직접 유지·관리하는 논리 데이터 묶음
- **EIF(External Interface File, 외부연계파일)** : 측정 대상 시스템이 참조만 하고 다른 시스템이 유지·관리하는 논리 데이터 묶음
- **EI(External Input, 외부입력)** : 경계 밖 데이터를 받아 내부논리파일을 갱신하는 처리 기능
- **EO(External Output, 외부출력)** : 계산·파생 정보를 경계 밖으로 내보내는 기능
- **EQ(External Inquiry, 외부조회)** : 계산·파생 없이 저장 정보를 경계 밖으로 보여 주는 조회 기능
- **보정계수** : 규모·연계 복잡성·성능·운영 환경 등 사업 특성을 개발원가에 반영하는 조정값
- **투입공수(M/M, Man-Month)** : 투입 인력의 등급별 인원과 기간을 곱한 작업량 단위
- **요율제** : 유지관리 대상 SW의 개발비에 유지관리 난이도 요율을 곱해 유지관리비를 정하는 방식
- **RFP(Request for Proposal)** : 발주기관이 과업 범위·요구사항·평가 기준을 제시하는 제안요청서
- **과업심의위원회** : 「소프트웨어 진흥법」 제50조에 따라 국가기관등이 설치해 SW사업의 과업내용 확정과 과업내용 변경에 따른 계약금액·계약기간 조정을 심의하는 위원회

## 2~4교시 25점 답안

## Ⅰ. SW사업 대가산정의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **SW사업 대가산정** 은 SW사업의 유형·범위에 맞는 기준으로 적정 사업 대가를 계산하는 활동 |
| 목적 | 사업비 산출 근거의 명확화와 적정 대가 지급 |

## Ⅱ. 사업 유형과 근거 기록을 중시하는 대가산정의 특징

| 특징 | 의미 |
|---|---|
| 사업 유형별 방식 | 기획·구현·운영 단계의 업무 성격에 따른 산정 방식 구분 |
| 규모 기반 산정 | 개발사업의 투입 인력이 아닌 사용자 기능 규모 기준 |
| 근거의 문서화 | 측정 범위·가정·단가·보정 내역의 발주 문서 연결 |
| 변경 영향 반영 | 계약 후 과업 변경에 따른 비용·일정 재산정 |

## Ⅲ. 사업 유형별 대가산정 체계와 SW개발비 산정 절차

### 사업 유형별 대가산정 체계

```text
SW사업 대가산정
    │
    ├─ SW기획 ── 정보전략계획 등: 업무량 또는 투입공수
    │
    ├─ SW구현 ── 기능점수, 적용 예외 사업은 투입공수
    │
    └─ SW운영
          ├─ 유지관리: 요율제 또는 투입공수
          └─ 운영: 투입공수
```

개발·운영 통합사업은 개발비의 기능점수 산정과 운영·유지관리비의 투입공수 산정 뒤 합산(2025년 개정판)

### SW구현 확대: 기능점수 기반 SW개발비 산정 절차

```text
측정 범위·애플리케이션 경계 설정
    ↓
데이터 기능(ILF·EIF)과 트랜잭션 기능(EI·EO·EQ) 식별
    ↓
기능점수 × 기능점수당 단가 × 보정계수 → 개발원가
    ↓
개발원가 + 직접경비 + 이윤 → SW개발비
```

## Ⅳ. 기능점수 방식과 투입공수 방식의 비교

| 구분 | **기능점수(FP)** 방식 | **투입공수** 방식 |
|---|---|---|
| 측정 대상 | 사용자 관점의 기능 규모 | 인력 등급별 투입 인원과 기간 |
| 적합 사업 | 요구사항이 구체화된 SW개발 | 기능 식별이 어려운 기획·컨설팅·운영과 기능점수 적용 예외 사업 |
| 산정 근거 | 기능 목록과 기능 유형별 점수 | 작업 항목별 투입 인력·기간 |
| 변경 시 재산정 | 추가·삭제·변경 기능의 점수 재측정 | 변경 작업의 투입 인력·기간 재추정 |

같은 사업 안에서도 기능 식별 가능 여부에 따른 방식 구분

## Ⅴ. 대가산정의 한계와 방안

| 한계 | 방안 |
|---|---|
| 요구사항이 구체화되지 않은 과업의 기능점수 산정으로 규모 오차 발생 | 요구 확정 범위만 기능점수 방식, 기능 식별이 어려운 과업은 투입공수 방식 선택 |
| 요구 범위와 기능점수 측정 범위의 불일치 | 요구사항 목록과 기능 목록의 대조와 제외 항목·산정 가정의 기록 |
| 계약 후 과업 변경의 비용·일정 영향 누락 | 변경 기능의 점수 재측정과 과업심의위원회 심의 대상 여부 확인 |
| 개발·운영 통합사업의 단일 방식 산정 | 개발비의 기능점수 산정과 운영·유지관리비의 투입공수 산정 후 합산 |

## Ⅵ. 제언

발주 단계부터 요구사항·기능 목록·산정 내역을 하나로 연결하고, 과업 변경 때 같은 목록에서 변경 기능만 재산정하는 방식으로의 전환

### 산정 근거의 연결 구조

```text
요구사항 목록(RFP)
    │
    ├─ 기능 목록 ── 요구사항별 기능 유형·점수
    │
    └─ 산정 내역 ── 단가·보정계수·제외 항목·가정
```

### 기능 목록 활용 확대: 과업 변경 재산정 절차

```text
과업 변경 요청
    ↓
변경 요구사항의 기능 목록 추가·삭제 반영
    ↓
변경 기능점수와 비용·일정 영향 산정
    ↓
과업심의위원회 심의 대상 확인 → 계약 변경 반영
```

### 선택 근거: 총액 중심 산정과의 비교

| 구분 | 총액 중심 산정 | 제언: 기능 목록 연결 산정 |
|---|---|---|
| 산정 근거 보관 | 총액과 요약 내역 | 요구사항별 기능 목록과 산정 내역 |
| 변경 시 재산정 | 협의에 의한 총액 조정 | 변경 기능만의 점수 재측정 |
| 분쟁 시 판단 근거 | 과업 해석의 차이 | 기능 목록의 변경 전후 대조 |
