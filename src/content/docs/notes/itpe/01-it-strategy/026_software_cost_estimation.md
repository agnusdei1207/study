## 연관 키워드

- SW사업 대가산정, 소프트웨어 원가, 기능점수, Function Point
- 투입공수, M/M, 직접원가, 제경비, 기술료, 실비정액가산방식
- 공공 SW, ISMP, 유지관리 요율, 클라우드, AI

## Ⅰ. SW사업 대가산정의 개요

- 핵심 요약 : SW 생애주기 전반의 적정 비용을 공학적·통계적 기준으로 산정하여 품질과 가격 신뢰를 확보하는 원가 체계.
- 개념 : 소프트웨어의 기획, 개발, 운영 및 유지관리 등 생애주기 전반에 소요되는 적정 비용을 공학적·통계적 기준에 의해 객관적으로 산정하는 체계적인 원가 산정 절차.
- 배경 및 필요성 : 개발자의 감이나 주관적 경험에 의존한 가격 산정으로 인한 저가 수주, 잦은 과업 변경, 납품 품질 저하 및 개발 생태계 황폐화를 방지하기 위해 한국인공지능·소프트웨어산업협회의 「SW사업 대가산정 가이드」 표준화.
- 주요 목적 : 적정 개발 예산 확보를 통한 SW(Software) 품질 보장, 발주자와 수주자 간의 투명한 가격 신뢰 구축, 소프트웨어 제값 주기 정착.

## Ⅱ. SW사업 대가산정의 특징

- 핵심 요약 : 기능 규모 기반 산정, 공공 SW 의무 적용, 생애주기 비용 포괄, 간이·정규법 단계 구분을 특징으로 하는 원가 체계.
1. 기능점수(Function Point, FP) 기반의 객관적 규모 측정.
2. 공공 SW 개발 사업의 원칙적 의무 적용.
3. 기획·분석·설계 단계별 간이법·정규법 구분.
4. 직접원가·제경비·기술료의 실비정액가산방식 적용.
5. 유지관리 요율 및 상용 SW 대가 기준 병행.

## Ⅲ. SW사업 대가산정의 구조 (흐름)

- 핵심 요약 : 데이터·트랜잭션 기능 측정에서 보정 기능점수 도출 및 단가 적용으로 이어지는 FP 산정 흐름과 원가 구성.
- 기능점수 기반 개발비 산정 프레임워크.

```text
1. 데이터 기능 측정
   ── 내부논리파일(ILF, Internal Logical File)
   ── 외부연계파일(EIF, External Interface File)
   ── 식별 및 복잡도 판정
          +
2. 트랜잭션 기능 측정
   ── 외부입력(EI, External Input)
   ── 외부출력(EO, External Output)
   ── 외부조회(EQ, External Inquiry)
   ── 식별 및 복잡도 판정
          ↓
3. 미조정 기능점수(UFP, Unadjusted Function Point) 도출
   ── 데이터 기능점수 합 + 트랜잭션 기능점수 합
          ↓
4. 보정계수 산정
   ── 규모·연계복잡도·성능요구·다중사이트 등
      보정계수 곱
          ↓
5. 보정 기능점수 도출 및 단가 적용
   ── (보정 FP x 기능점수당 단가 = 최종 개발원가)
```

```text
[SW 개발비 원가 구성]
직접인건비
   + 직접경비
   + 제경비 (직접인건비 x 제경비율)
   + 기술료 ((직접인건비+제경비) x 기술료율)
   ↓
최종 사업 대가
```

- 직접원가와 제경비 : 실비정액가산방식으로 직접인건비 + 직접경비 + 제경비(직접인건비에 제경비율 곱) + 기술료((직접인건비+제경비)에 기술료율 곱)를 합산하여 최종 사업 대가 확정. 제경비율은 가이드 개정으로 110~120%에서 144~154%로 인상됨.

## Ⅳ. 기능점수 방식과 투입공수 방식의 비교

- 핵심 요약 : FP 방식은 객관성과 공공 적용 의무, M/M 방식은 예외적·보조적 적용에 국한된다.
- 비교 대상 및 선택 기준.

```text
[산정 방식 선택 흐름]
사업 유형 확인
   ↓
공공 SW 개발 사업? ── 예 ──→ FP 방식 (원칙)
   ↓ 아니오
기능 도출 가능? ── 예 ──→ FP 방식
   ↓ 아니오
유지관리/R&D 기획 ──→ M/M 방식 (예외)
```

| 비교 항목 | 기능점수 (Function Point) 방식 | 투입공수 (Man-Month) 방식 |
|---|---|---|
| 산정 기준 | 사용자가 요구하는 소프트웨어의 기능적 규모 (논리적 크기) | 프로젝트에 투입될 인력의 수와 기간 (헤드카운트) |
| 객관성 및 신뢰도 | 높음 (표준화된 기능 측정 규칙 적용) | 낮음 (생산성 차이 미반영, 부풀리기 용이) |
| 적용 단계 | 기획 단계(간이법), 분석/설계 완료 단계(정규법) | 기능 도출이 불가능한 단순 유지관리, R&D 기획 등 예외적 적용 |
| 정책적 지위 | 공공 SW 개발 사업의 원칙적 의무 적용 방식 | 원칙적 적용 금지 (소프트웨어 진흥법상 제한) |

## Ⅴ. SW사업 대가산정의 장점과 한계

- 핵심 요약 : 객관적 예산 확보와 품질 보장의 장점, 산정 복잡성과 신기술 미반영의 한계.
- 장점
  1. 적정 개발 예산 확보로 SW 품질 보장.
  2. 발주자·수주자 간 투명한 가격 신뢰 구축.
  3. 주관적 가격 산정으로 인한 저가 수주 방지.
- 한계점 1 : 기능점수(FP) 산정의 복잡성 및 주관적 개입
  - 한계점 : 기능 도출 시 산정자의 숙련도에 따라 데이터 기능과 트랜잭션 기능 분할 결과가 달라져 발주사-사업자 간 분쟁 빈발.
  - 해결 방안 : 코드 및 설계서 기반 자동 기능점수 측정 도구 도입, 공공 SW 대가산정 가이드라인의 모호 조항 정밀화.
- 한계점 2 : 신기술(AI, 클라우드, 빅데이터) 산정 기준의 미비
  - 한계점 : 전통적 화면/테이블 중심의 FP 모델로는 프롬프트 엔지니어링, RAG(Retrieval-Augmented Generation) 파이프라인, MLOps(Machine Learning Operations) 구축 비용을 정확히 반영 불가.
  - 해결 방안 : AI 서비스 전용 대가산정 모델(데이터 정제량, 파라미터 튜닝 공수 등) 신설 및 실투입공수(M/M) 방식과의 유연한 결합.
- 한계점 3 : 유지관리 요율의 현실적 한계
  - 한계점 : 개발비 대비 유지관리 대가 비율이 여전히 글로벌 표준 대비 낮아 SW 기업의 기술 투자 및 유지보수 품질 저하.
  - 해결 방안 : 상용 SW 유지관리 요율 단계적 법정 상향, 서비스 품질 기반 차등 요율제(SLA(Service Level Agreement) 연계) 확대.

## Ⅵ. SW사업 대가산정에 대한 기술사적 제언

- 핵심 요약 : 사후 정산제, 유지관리 요율 현실화, 클라우드·AI 대가체계 신설.
- 기획 단계 기능점수 간이법의 오차 보정 : 기획 시점(ISMP(Information System Master Plan) 등)에는 요구사항이 완전치 않으므로, 상세 설계 완료 시점에 기능점수를 재산정하여 계약 금액을 조정하는 사후 정산제(True-up) 제도화.
- 상용 SW 유지관리요율의 현실화 : 외산 SW 대비 턱없이 낮은 국내 상용 SW 유지관리요율을 글로벌 표준 수준으로 인상하여 재투자 선순환 구조 마련.
- 클라우드 및 AI 기반 SW 대가체계 신설 : 전통적 온프레미스 라이선스 중심 대가 기준을 탈피하여, SaaS(Software as a Service) 구독형 과금, AI 토큰 사용량 기반 과금 등 클라우드 네이티브 서비스 대가 가이드라인 수립.

## Ⅶ. 결론

- 핵심 요약 : SW사업 대가산정은 FP 기반 객관적 원가 산정으로 공공 SW의 품질과 가격 신뢰를 확보하는 체계.
- 요약 : SW사업 대가산정은 기능 규모 측정과 실비정액가산방식을 통해 적정 개발비를 산출하는 체계.
- 시사점 : 신기술 반영과 유지관리 요율 현실화, 사후 정산제를 통해 대가 체계의 실효성을 지속 보완 필요.
