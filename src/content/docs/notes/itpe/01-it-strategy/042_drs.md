## 지식 로드맵 내 현재 위치

IT 전략·관리 → IT 서비스 지속성·재해복구 → **DRS**

## 30초 인출

- 본질: DRS(Disaster Recovery System)는 재해로 중단된 정보시스템의 서비스를 신속히 복구해 업무 연속성을 유지하기 위한 시스템
- 메커니즘: 업무영향분석으로 RTO·RPO를 정하고, 그 목표를 만족하는 복구센터 방식을 선택해 평시에 데이터를 복제·소산하다가 재해 선포 뒤 대체 시스템으로 전환(Failover)하고 정상화 뒤 복귀(Failback)
- 통찰: 실시간 복제는 삭제·변조 같은 데이터 손상까지 복제하므로 복제형 재해복구시스템과 별도로 원격지 소산 백업의 병행

<details>
<summary>핵심 용어</summary>

- **DRS(Disaster Recovery System)** : 각종 재해로 정보시스템이 중단됐을 때 서비스를 신속하게 복구하고 업무 연속성을 유지하기 위해 구축한 시스템
- **BIA(Business Impact Analysis)** : 업무 중단이 조직에 미치는 영향과 허용 가능한 중단 시간을 분석하는 활동으로, 복구 목표의 근거
- **RTO(Recovery Time Objective)** : 복구 시간 목표. 행정기관 및 공공기관 정보시스템 안정성 고시는 재해 선포 시점부터 재해복구시스템 가동 뒤 핵심 기능의 정상 확인 시점까지로 규정
- **RPO(Recovery Point Objective)** : 복구 시점 목표. 장애 직전 어느 시점의 데이터까지 복구할지, 곧 감내하는 데이터 손실 범위
- **Mirrored Site(미러 사이트)** : 자동 실시간 미러링으로 주 센터와 모든 기술 요소가 동일한 완전 이중화 시설
- **Hot Site(핫 사이트)** : 시스템 요구를 지원하는 규모로 장비·기반 설비·지원 인력을 갖춘 시설
- **Warm Site(웜 사이트)** : 시스템 장비·소프트웨어·통신·전원의 일부 또는 전부를 갖춘 부분 구비 시설
- **Cold Site(콜드 사이트)** : 공간과 기반 설비(전력·통신 연결·환경 통제)만 갖춘 시설
- **Failover(전환)** : 운영 트래픽을 주 환경에서 복구 환경으로 돌리는 조치
- **Failback(복귀)** : 재해 해소 뒤 복구 환경의 워크로드를 원래 인프라로 되돌리는 조치
- **소산(원격지 소산)** : 운영 시스템과 같은 재해에 동시에 영향받지 않는 원격지 저장소에 백업 데이터를 주기적으로 보관하는 조치
- **실전환 훈련·모의훈련·도상 훈련** : 각각 운영 시스템을 중단하고 재해복구시스템으로 실제 서비스를 전환하는 훈련, 가상 상황에서 재해복구시스템을 가동해 점검하는 훈련, 시나리오 중심으로 절차와 역할을 서면·토의로 점검하는 훈련

</details>

## 2~4교시 25점 답안

## Ⅰ. DRS의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **DRS(Disaster Recovery System)** 는 재해로 중단된 정보시스템의 서비스를 신속히 복구해 업무 연속성을 유지하는 시스템 |
| 목적 | 재해 시 서비스 중단 시간과 데이터 손실의 목표 범위 내 억제 |

## Ⅱ. 복구 목표로 구축 방식을 정하는 DRS의 특징

| 특징 | 의미 |
|---|---|
| 목표 기반 구축 | **RTO(Recovery Time Objective)** 와 **RPO(Recovery Point Objective)** 를 먼저 정하고 그 목표를 만족하는 방식 선택 |
| 등급별 차등 | 공공 정보시스템은 등급에 따라 목표와 구축 방식을 구분 |
| 물리적 분리 | 주 시스템과 다른 데이터센터 또는 원격지에 대체 자원 확보 |
| 훈련으로 검증 | 구축만으로 복구를 보장하지 않고 재해복구훈련으로 목표 달성 확인 |

## Ⅲ. DRS 구축·운영 체계

### DRS 구축과 재해 대응 흐름

```text
업무영향분석(BIA): 업무별 허용 중단 시간·데이터 손실 파악
    ↓
복구 목표 설정: RTO·RPO
    ↓
복구센터 방식 선택: 미러·핫·웜·콜드
    ↓
평시 운영: 데이터 복제·백업·원격지 소산, 재해복구훈련
    ↓
재해 발생 → 재해 선포 → 대체 시스템으로 전환(Failover)
    ↓
주 시스템 정상화 → 원래 시스템으로 복귀(Failback)
```

### 재해 선포·복구 절차 확대: 공공 정보시스템 안정성 고시의 RTO 측정 구간

```text
재해상황 발생
    ↓
상황판단회의로 재해 선포 여부 판단 (긴박하면 회의 생략 가능)
    ↓
재해 선포 ─→ 행정안전부장관에게 신속 통보
    ↓
재해복구계획에 따라 재해복구시스템 가동
    ↓
핵심 기능 정상 확인

RTO = 재해 선포 시점 ~ 핵심 기능 정상 확인 시점
```

## Ⅳ. 복구센터 유형과 등급별 구축 방식

### 복구센터 유형별 준비 수준

| 유형 | 구성 | 비용 | 장비 | 통신 | 기동 소요 |
|---|---|---|---|---|---|
| **Mirrored Site** | 자동 실시간 미러링, 주 센터와 동일 | 가장 높음 | 완전 이중화 | 완전 이중화 | 사실상 100% 가용 보장 |
| **Hot Site** | 장비·기반 설비·지원 인력 구비 | 중간~높음 | 전체 | 전체 | 짧은 시간 |
| **Warm Site** | 장비·통신 일부 또는 전부 구비 | 중간 | 부분 | 부분~전체 | 중간 |
| **Cold Site** | 공간·전력·통신 연결·환경 통제만 구비 | 낮음 | 없음 | 없음 | 긴 시간 |

### 공공 정보시스템 등급별 재해복구 목표와 구축 방식

| 등급 | RTO | RPO | 구축 방식 예시 |
|---|---|---|---|
| A1 | 실시간~1시간 이내 | 0(실시간) | Active-Active (목표 충족 시 Active-Standby 가능) |
| A2 | 3~12시간 이내 | 수 분 | Active-Standby |
| A3 | 1~5일 이내 | 수 분 | 스토리지 DR |
| A4 | 3주 이내 | 1~7일 | 원격지 소산 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 실시간 복제가 삭제·변조 등 데이터 손상까지 대체 시스템에 복제 | 복제와 별개로 주기 백업을 원격지에 소산해 손상 이전 시점 확보 |
| 구축만 하고 전환한 적이 없으면 RTO 달성 여부의 확인 불가 | 등급별 재해복구훈련(A1·A2 실전환 훈련, A4 소산 데이터 복구 포함 도상훈련) 정기 실시 |
| 완전 이중화 방식은 비용이 가장 높아 전 시스템 적용의 어려움 | BIA로 업무별 RTO·RPO를 정해 등급에 맞는 방식으로 차등 구축 |

## Ⅵ. 제언

복제형 재해복구시스템과 원격지 소산 백업의 이중 경로 구성 및 경로별 복구 확인

### 이중 복구 경로 구성

```text
주 시스템
    ├─ 실시간·준실시간 복제 ─→ 재해복구시스템 : 시설·장비 중단 시 전환
    │
    └─ 주기 백업 ─→ 원격지 소산 백업 : 데이터 손상 시 손상 이전 시점 복구
```

### 장애 유형별 복구 경로 선택

```text
장애 발생
    ├─ 시설·장비 중단 → 재해복구시스템 가동 → RTO 안에 핵심 기능 정상 확인
    │
    └─ 데이터 손상 확인 → 복제 중단 → 소산 백업에서 손상 이전 시점 복구 → RPO 확인
```

| 구분 | 복제형 DR 단독 | 제언: 복제형 DR + 소산 백업 |
|---|---|---|
| 시설·장비 중단 | 대체 시스템으로 전환 | 동일 |
| 데이터 손상 | 손상 데이터도 대체 시스템에 반영 | 소산 백업의 손상 이전 시점으로 복구 |
| 복구 시점 선택 | 최신 시점 하나 | 백업 주기 안에서 선택 |
| 검증 | 전환 훈련 | 전환 훈련과 소산 데이터 복구 훈련 |
