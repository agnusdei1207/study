## 연관 키워드

- 소프트웨어 비용 산정, 코드 라인 수(LOC), 기능점수(FP), COCOMO
- 전문가 판단·경험칙, 유사 실적 추정, 생산성, 산정 가정, 3점 추정

## Ⅰ. 소프트웨어 비용 산정의 개요

- 핵심 요약 : 소프트웨어의 규모·복잡도·생산성 근거로 투입공수·비용·기간을 추정하고 근거를 문서화하는 활동.
- 개념 : **소프트웨어 비용 산정** (Software Cost Estimation)은 요구 범위와 규모 측정치를 입력으로 노력·비용·기간을 체계적으로 추정하는 활동이다.
- 배경 및 필요성 : 초기 요구가 불완전하고 기능 규모·팀 생산성 편차가 커서, 경험에만 의존하면 예산 초과와 일정 지연·계약 분쟁이 반복되는 구조.
- 주요 목적 : 검증 가능한 근거에 따른 예산·일정 수립과 자원 배분의 합리화, 발주자와 수행자 간 추정 신뢰의 확보.

## Ⅱ. 소프트웨어 비용 산정의 특징 및 장점

- 핵심 요약 : 규모 측정 기반 추정·기법 교차검증·가정 명시·실적 환류가 추정 신뢰성과 근거 투명성으로 연결되는 구조.

1. 규모 기반 추정 : 코드 라인 수나 기능 규모 측정치를 입력으로 노력을 추정 → 산정 근거의 재현성과 검증 가능성 확보.
2. **기능점수** (FP, Function Point) 측정 : 외부입력·외부출력·외부조회·내부논리파일·외부인터페이스파일의 다섯 유형에 복잡도 가중치를 적용해 사용자 관점 규모를 산출 → 개발 언어에 종속되지 않는 비교 가능한 규모 기준 확보.
3. **COCOMO** (Constructive Cost Model) 적용 : 원시코드 규모를 입력해 노력을 비선형 지수 함수 형태로 추정하는 모수 모형 → 조직형·반분리형·내장형 등 프로젝트 특성에 따른 정량 추정 확보.
4. 다중 기법 교차검증 : 모형 추정에 전문가 판단과 유사 실적 추정을 병행 → 단일 기법의 편향 완화 효과.
5. 불확실성의 정량화 : **3점 추정** (낙관·중립·비관치의 가중 평균)과 구간 제시, 산정 가정·제외 범위 문서화 → 예산 리스크의 사전 관리 효과.

## Ⅲ. 소프트웨어 비용 산정의 구조 (흐름)

- 핵심 요약 : 요구·범위 정의 → 규모 측정 → 모형·단가 적용 → 불확실성 조정 → 승인·실적 환류의 절차 구조.
- **코드 라인 수** (LOC, Line of Code)는 원시코드의 물리적 라인 수로 규모를 측정하는 단위이며, 생산성은 규모당 투입공수(MM, Man-Month)로 표현.

```text
[ 비용 산정 절차 ]

요구·범위 정의
    ↓
규모 측정 (LOC·FP)
    ↓
모형·단가 적용
    ↓
불확실성·위험 조정
    ↓
승인·실적 환류
```

```text
[ 규모 기반 모형의 추정 구조 ]

규모 측정치 (코드·기능)
    ↓
노력 모형 적용 (COCOMO)
    ↓
투입공수 산출
    ↓
기간·비용 환산
```

## Ⅳ. 소프트웨어 비용 산정의 전문가 판단 추정과 모형 기반 산정의 비교

- 핵심 요약 : 경험·직관에 의존하는 전문가 판단·경험칙 추정과 달리, 규모 측정과 모형식에 기반한 산정은 재현성과 검증 가능성이 높음.

| 비교 축 | 전문가 판단·경험칙 추정 | 모형·규모 기반 산정(LOC·FP·COCOMO) |
| --- | --- | --- |
| 산정 근거 | 경험·직관·관행 계수 | 규모 측정치·모형식·생산성 자료 |
| 재현성·검증 | 근거가 개인에 의존해 재현 어려움 | 가정·식의 공유로 재현·검증 가능 |
| 적용 시점 | 요구 초기·자료 부족 단계 | 규모 산정이 가능한 단계 이후 |
| 편향 통제 | 개인 편향의 통제 어려움 | 유사 실적·독립검토로 완화 |
| 결과 형태 | 단일 값 중심 | 구간·시나리오 제시 가능 |

- 선택 기준 : 요구 초기·자료 부족 단계는 전문가 판단(필요 시 **델파이 기법**(여러 전문가의 반복 익명 의견 수렴), Delphi Technique)으로 방향을 잡고, 규모가 식별되는 단계에서 모형 기반 산정으로 정밀화하는 절차가 적합.

| 구분 | LOC | FP | COCOMO |
| --- | --- | --- | --- |
| 측정 대상 | 원시코드 라인 수 | 사용자 기능 5유형·복잡도 | 규모(KLOC)에서 노력 추정 |
| 강점 | 측정·자동화 용이 | 언어 비종속·사용자 기능 기준 | 규모와 노력 관계의 정량화 |
| 한계 | 개발 전 예측 곤란·언어 의존 | 가중치 주관성 존재 | 자체 실적 기반 계수 보정 필요 |

## Ⅴ. 소프트웨어 비용 산정의 한계와 방안

- 핵심 요약 : 요구 불확실성은 구간 추정으로, 낙관 편향은 독립검토로, 모형·유사 실적 오적용은 자체 실적 보정으로 바로잡는 원칙.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 초기 요구 불확실 | 범위 미확정 → 추정 오차·예산 변경 반복 | 산정 가정·제외 범위 명시와 구간 추정 | 추정 대비 실적 오차율 |
| 낙관 편향 | 일정·영업 압박 → 위험 누락·최소치 추정 | 3점 추정과 독립 산정 검토 시행 | 예산 초과율 |
| 모형 계수 부적합 | 타 조직 계수의 무단 적용 → 생산성 오판 | 자체 실적 데이터 축적·계수 보정 | 계수 보정 주기 |
| 유사 실적 오적용 | 기술·팀·도메인 차이 무시 → 근거 왜곡 | 비교 사업 선정 근거·보정 요인 기록 | 추정-실적 편차 |

## Ⅵ. 소프트웨어 비용 산정에 대한 기술사적 제언

- 핵심 요약 : 조직 산정 표준·독립 검토 제도·산정 전문 인력 체계로 비용 산정을 개인 기량이 아닌 조직 역량으로 내재화하는 방향.
- 표준 체계 : 조직이 산정 지침·생산성 데이터베이스를 표준으로 정비해 프로젝트별 산정 기준의 일관성 확보.
- 거버넌스 : 발주자·수행자가 산정 기준·제외 범위·변경 조건을 계약서에 명시하고, 독립 검토 절차를 예산 승인의 전제로 운영.
- 인력 체계 : 산정 전문 교육·인증을 갖춘 인력을 확보해 기법별 적용 품질과 실적 환류를 전담 운영.

## Ⅶ. 결론

- 핵심 요약 : 소프트웨어 비용 산정은 규모·복잡도·생산성의 검증 가능한 근거로 노력·비용·기간을 추정하는 활동.
- 산정 가정의 명시와 실적 환류가 추정 오차와 계약 분쟁 축소의 열쇠임.
