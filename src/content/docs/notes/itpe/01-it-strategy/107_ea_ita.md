## 핵심 용어
- EAMS(Enterprise Architecture Management System): 전사 아키텍처 정보(BA, DA, AA, TA)와 참조모델을 통합 저장하고, 신규 사업 추진 시 아키텍처 적합성을 온라인으로 검토·승인하는 전산 관리 시스템
- TRM(Technical Reference Model): 서비스 구현에 필요한 하드웨어, 운영체제, 네트워크, 미들웨어 등 요소 기술 표준을 분류하고 버전 수명주기를 관리하는 기술 참조 모델
- 자크만 프레임워크(Zachman Framework): 관점(소유자, 설계자, 개발자 등)과 초점(무엇을, 어떻게, 어디서, 누가, 언제, 왜)의 6×6 매트릭스로 전사 아키텍처를 정의한 고전적 EA 메타 모델

## 핵심 통찰
- EA가 실패하는 이유는 '너무 크고 무겁기 때문'임 → 수백 페이지짜리 워드 문서로 작성된 아키텍처 청사진은 작성 완료되는 순간 이미 구시대의 유물이 되며, 현업 개발자는 아무도 열어보지 않음
- 중복 투자 방지의 최종 병기임 → 공공기관에서 매번 새로운 로그인 모듈과 본인인증 시스템을 개별 발주하는 낭비를 범정부 EA(GEA) 참조모델(ARM) 기반 공통 컴포넌트로 막을 수 있음
- 현대의 EA는 '마이크로서비스 카탈로그'로 변모해야 함 → 정적 다이어그램 대신 실시간으로 동작하는 API 게이트웨이 라우팅 테이블과 서비스 메시(Service Mesh) 토폴로지 맵이 곧 살아있는 현대적 EA임

## 이웃 토픽과 구분
- EA vs ISP(정보전략계획): ISP = 3~5년 단위의 전략 과제와 투자 로드맵을 도출하는 기획 활동 / EA = 조직의 현행(As-Is)과 목표(To-Be) 시스템의 구체적 청사진을 상시 유지보수하는 거버넌스 체계

## 문제·원인·대책
- 적용 상황: 정부 산하 공공기관들의 유사 데이터베이스 중복 구축 방지
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 5개 유관 기관이 각자 수억 원을 들여 동일한 기업 정보 DB를 개별 구축 | 기관 간 아키텍처 정보 공유 부재 및 사일로 행정 | 범정부 EA 기반 데이터 참조모델(DRM) 적용 및 연계 공유 의무화 | 중복 구축 예산 40억 원 절감 |
| 신규 프로젝트가 전사 보안 표준에 어긋나는 오픈소스를 무단 채택 | 아키텍처 관리체계 및 사전 검토 절차 형식화 | 프로젝트 기획/발주 시 EAMS 아키텍처 적합성 검토 승인 게이트웨이 강제 | 전사 보안 표준 준수율 100% 달성 |
