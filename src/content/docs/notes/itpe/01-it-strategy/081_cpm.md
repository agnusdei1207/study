## 30초 인출

- 본질: CPM은 확정 활동기간과 작업 선후관계로 최장 경로를 찾아 프로젝트 최단 완료기간과 일정 여유를 계산하는 기법.
- 메커니즘: 전진계산(ES/EF, 합류 시 Max) → 역진계산(LS/LF, 분기 시 Min) → 총여유(TF=LS-ES) 산출 → **주공정선** 판정.
- 통찰: 한계: 작업 기간만 합산하면 선후행 의존과 여유를 놓침 → 방안: 일정 단축 전 주공정선 비용 구배와 인접 경로 여유를 재계산

<details>
<summary>핵심 용어</summary>

- **CPM(Critical Path Method)** : 확정 활동기간과 작업 선후관계로 프로젝트의 최단 완료기간과 여유시간을 계산하는 기법
- **Critical Path(주공정선)** : 프로젝트 시작부터 종료까지 가장 긴 경로로서 전체 최단 완료 기간을 결정하는 임계 경로
- **Forward Pass(전진 계산)** : 시작 노드부터 순방향으로 조기착수일(ES)과 조기완료일(EF)을 계산하는 과정
- **Backward Pass(역진 계산)** : 종료 노드부터 역방향으로 늦은완료일(LF)과 늦은착수일(LS)을 계산하는 과정
- **Total Float(총 여유)** : 프로젝트 전체 준공일을 지연시키지 않고 특정 작업이 가질 수 있는 최대 허용 여유 시간($LS - ES$)
- **Free Float(자유 여유)** : 직후 후속 작업의 조기착수일(ES)을 지연시키지 않고 가질 수 있는 여유 시간
- **Cost Slope(비용 구배)** : 일정 단축(Crashing) 시 공기 1일 단축당 소요되는 추가 비용의 비율($\Delta Cost / \Delta Time$)
- **AON(Activity-on-Node)** : 네트워크의 각 노드에 작업을 표시하고 선후관계를 화살표로 나타내는 공정 네트워크 표현

## 2~4교시 25점 답안

## Ⅰ. CPM의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **CPM(Critical Path Method)** 은 확정 활동기간과 작업 간 선후관계로 최장 경로를 찾아 프로젝트 최단 완료기간과 일정 여유를 계산하는 기법 |
| 목적 | 최단 완료기간 산정 · 일정 병목 식별 · 납기 단축 대안 비교 |

## Ⅱ. CPM의 특징

| 특징 | 일정 판단상 의미 |
|---|---|
| 선후행 네트워크 | 작업기간 합계가 아닌 가장 긴 의존 경로가 완료일 결정 |
| 전진·역진 계산 | 합류는 최댓값, 분기는 최솟값으로 시점 계산 |
| 단축 후 재판정 | 한 경로를 줄이면 다른 경로가 주공정선이 될 수 있음 |

## Ⅲ. 공정 네트워크 체계와 여유시간 계산 프로세스

```text
활동·기간·의존관계 → AON 네트워크
                        ├→ 전진 계산 ES·EF ─┐
                        └→ 역진 계산 LS·LF ─┴→ TF·주공정선
                                                 ↓
                                      단축안 적용·네트워크 재계산
```

### 합류·분기 시점의 계산

```text
전진: 선행 A의 EF ─┐
                   ├→ 후속 C의 ES = max(선행 EF) + 1
       선행 B의 EF ─┘
역진: 후속 D의 LS ─┐
                   ├→ 선행 C의 LF = min(후속 LS) - 1
       후속 E의 LS ─┘
```

- **Critical Path** : 네트워크 최장 경로로 프로젝트 최단 완료기간을 결정하며 제약조건에 따라 총 여유는 양수·0·음수 가능

## Ⅳ. AON 계산식과 일정 단축 대안 비교

### AON 노드의 값과 여유시간 공식

| 조기착수 ES | 작업기간 D | 조기완료 EF |
|---|---|---|
| 늦은착수 LS | 총여유 TF | 늦은완료 LF |

위 노드는 작업의 조기·늦은 시점과 총여유를 표현. 아래 계산식은 시작일과 완료일을 모두 포함하는 일 단위 관례.

| 구분 | 계산 공식 (일 단위) | 핵심 규칙 및 판정 |
|---|---|---|
| **전진 계산 (ES, EF)** | $EF = ES + D - 1$<br>$ES_{next} = \max(EF_{prev}) + 1$ | **합류(Merge)** 지점에서는 선행 작업의 EF 중 **최대값** 취합 |
| **역진 계산 (LS, LF)** | $LS = LF - D + 1$<br>$LF_{prev} = \min(LS_{next}) - 1$ | **분기(Burst)** 지점에서는 후속 작업의 LS 중 **최소값** 취합 |
| **총 여유 (Total Float)** | $TF = LS - ES = LF - EF$ | 전체 완공일 또는 일정 제약을 위반하지 않는 최대 여유 |
| **자유 여유 (Free Float)** | $FF = \min(ES_{next}) - EF - 1$ | 직후 후속 작업의 조기착수(ES)를 지연시키지 않는 고유 여유 |

### 일정 단축 대안과 비용·위험 비교

> 비용 투입에 따른 크래싱의 기간 단축과 선후행 작업을 겹쳐 수행하는 패스트트래킹의 재작업 위험.

| 비교 항목 | 크래싱 (Crashing, 공정 압축) | 패스트트래킹 (Fast Tracking, 공정 첩행) |
|---|---|---|
| **핵심 방식** | 주공정선 작업에 **추가 자원(인력, 장비) 투입** | 순차적 선후행 작업을 **동시에 병행 수행** |
| **트레이드오프** | **추가 비용 발생 (Cost Trade-off)** | **품질 리스크 및 재작업 증가 (Risk Trade-off)** |
| **대상 선정 기준** | 주공정선 상에서 **비용 구배(Cost Slope)** 가 가장 낮은 작업 | 선후행 의존도가 낮고 인터페이스 분리가 가능한 작업 |
| **대표 사례** | 야간 특근, 핵심 개발자 추가 투입 | 상세 설계 완료 전 코딩 착수, 단위 시험 병행 |
| **한계 및 주의점** | 브룩스의 법칙(지연된 프로젝트에 인력 투입 시 지연 가중) | 설계 변경 발생 시 기개발 소스 폐기 및 대규모 재작업 |

## Ⅴ. 한계와 방안

> 일정 단축 시 함께 검토할 주공정선 변화·자원 충돌·재작업, 단축 후 네트워크 재계산.

| 한계 | 방안 |
|---|---|
| **주공정선 전이** | 단축 후 전진·역진 재계산으로 신규 병목 식별 |
| **자원 충돌** | 자원 평준화·가용성 검토로 실행 가능한 일정 확보 |
| **재작업 증가** | 병행 가능 범위·인터페이스 선확정으로 패스트트래킹 위험 완화 |

## Ⅵ. 제언 — 제한된 비용으로 납기 단축안 선정

주공정·준주공정의 여유를 확인한 뒤 후보 작업별 비용 구배와 재작업 위험을 비교하고, 실제 완료일이 줄어드는지 네트워크를 다시 계산한다.
