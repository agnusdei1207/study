## 답안 골격
```text
[CPM] ◀━━ 머리: Ⅶ 내 의견 (주공정선 중심 일정 단축 시 비용 경합을 최소화하는 Crashing과 리스크를 통제하는 Fast Tracking의 최적 조합 실행)
 ┃
 ┣━ Ⅰ 개요 ───── 프로젝트 네트워크 상에서 여유시간(Float)이 전혀 없어 지연 시 전체 납기를 지연시키는 최장 경로(주공정선) 산출 기법
 ┣━ Ⅱ 특징 ───── 결정론적(단일 기간) 추정 · 전진/역진 계산 · 총 여유(Total Float = 0) · 프로젝트 최단 완료 기간 결정
 ┣━ Ⅲ 구조 ───── 전진 계산(ES, EF) ↔ 역진 계산(LS, LF) ↔ 여유시간 산출(TF = LS - ES = LF - EF) ↔ 주공정선(Critical Path)
 ┣━ Ⅳ 흐름 ───── ① 액티비티 정의 및 선후행 관계 설정 → ② 전진계산(조기완료일) → ③ 역진계산(늦은완료일) → ④ 주공정선 식별 및 단축(Crashing/Fast Tracking)
 ┣━ Ⅴ 비교 ───── CPM vs PERT vs CCPM (결정론적 단일시간 vs 확률적 3점추정(베타분포) vs 제약이론(TOC) 버퍼 관리)
 ┗━ Ⅵ 실무 ───── 주공정선 작업에만 집중하다 준주공정선(Sub-critical) 지연으로 주공정 전이 / 무리한 병행진행(Fast Tracking)으로 재작업 폭증
```

## 한 줄 본질
- 수백 개의 작업 중 어떤 작업이 늦어지면 전체 오픈일이 밀리는지 파악하지 못해 엉뚱한 작업에 인력을 쏟아붓는 병목 극복 → 전진 및 역진 계산을 통해 여유시간이 0인 최장 경로(Critical Path)를 도출하고 자원을 집중 투입 → 최단 납기 달성 및 일정 통제 / 작업 소요 기간의 확률적 변동성 미반영

## 핵심 그림
```text
┌───────────────────────── [ CPM 네트워크 계산 및 주공정선 식별 체계 ] ─────────────────────────┐
│                                                                                             │
│  [ 액티비티 노드 표기법 (AON) ]              [ 네트워크 전진/역진 계산 공식 ]               │
│  ┌──────────┬──────────┬──────────┐          1. 전진 계산 (Forward Pass) -> 조기 일정       │
│  │ 조기착수 │ 작업기간 │ 조기완료 │             $EF = ES + Duration - 1$                    │
│  │   (ES)   │   (D)    │   (EF)   │             $ES_{next} = \max(EF_{prev}) + 1$           │
│  ├──────────┼──────────┼──────────┤          2. 역진 계산 (Backward Pass) -> 늦은 일정      │

│                                                                                             │

│                     ┌───────────┐                                                           │
│           ┌────────►│ 작업 B (3)├────────┐                                                  │
│           │         │ TF = 2    │        │                                                  │
│     ┌─────┴─────┐   └───────────┘   ┌────▼──────┐   ┌───────────┐                           │
│     │ 작업 A (2)│                   │ 작업 D (4)├──►│ 작업 E (1)│ ──> [ 프로젝트 완료 (11일) ]│
│     │ (CP)TF = 0├───►┌───────────┐──►(CP)TF = 0 │   │ (CP)TF = 0│                           │
│     └───────────┘    │ 작업 C (4)│  └───────────┘   └───────────┘                           │
│                      │ (CP)TF = 0│                                                          │
│                      └───────────┘                                                          │
│  * 주공정선 (Critical Path): A -> C -> D -> E (총 11일, 여유시간 TF = 0)                    │
```

## 핵심 용어
- 총 여유(Total Float) vs 자유 여유(Free Float): 총 여유 = 전체 프로젝트 완료일을 지연시키지 않고 가질 수 있는 여유시간($LF - EF$) / 자유 여유 = 후속 작업의 조기착수일(ES)을 지연시키지 않고 가질 수 있는 여유시간
- 비용 구배(Cost Slope): 작업 기간을 1단위 단축할 때 추가로 소요되는 비용으로, $\frac{\text{특급비용} - \text{정상비용}}{\text{정상기간} - \text{특급기간}}$으로 계산되며 Crashing 대상 선정의 기준임

## 핵심 통찰
- 주공정선(Critical Path)은 프로젝트에서 '시간이 가장 오래 걸리는 경로'이지만 역설적으로 '프로젝트를 끝낼 수 있는 최단 기간'을 의미함
- 일정을 단축할 때는 반드시 '주공정선 상의 작업'만 줄여야 함 → 여유시간이 있는 작업 B를 단축하는 것은 돈만 낭비하고 전체 납기는 1초도 줄이지 못함
- 공정 압축(Fast Tracking)의 위험: 선행 작업이 끝나기 전에 후행 작업을 병행하면 재작업(Rework) 확률이 급증하여 오히려 일정이 더 지연될 수 있음

## 이웃 토픽과 구분
- CPM vs PERT: CPM = 과거 경험이 있어 소요 기간이 확실한 프로젝트에 '단일 결정론적 시간' 적용 / PERT = 연구개발처럼 불확실한 프로젝트에 낙관치·최빈치·비관치의 '3점 추정 확률분포' 적용

## 문제·원인·대책
- 적용 상황: 금융 차세대 오픈 D-60일 시점 일정 지연 위기 대응
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| Crashing으로 주공정 작업 단축 후 다른 경로가 새 주공정선이 되어 재지연 | 네트워크 경로 간 여유시간 차이가 1~2일 미만인 준주공정선 간과 | 전체 경로 민감도 분석 및 다중 경로 동시 단축 전략 수립 | 돌발적 주공정 전이 방지 |
| 패스트트래킹(Fast Tracking) 적용 후 설계 변경으로 재코딩 폭증 | 요구사항 미동결 상태에서 무리한 조기 개발 착수 | 인터페이스 정의서 우선 동결 및 모의 객체(Mock) 기반 병행 개발 | 재작업률 50% 이상 감소 |
