## 큰 그림과 30초 인출

```text
[프로젝트 작업 분할 (WBS 작업 패키지)]
          │
          ▼
┌────────────────── [CPM 네트워크 전진/역진 계산] ──────────────────┐
│  1. 전진 계산 (Forward Pass)  : 조기 일정 도출 (ES, EF)            │
│  2. 역진 계산 (Backward Pass) : 늦은 일정 도출 (LS, LF)            │
│  3. 여유시간 계산 (Float)     : TF = LS - ES = LF - EF             │
│  4. 주공정선 식별             : Total Float = 0 인 최장 경로       │
└────────────────────────────────────────────────────────────────────┘
          │
          ▼
[일정 단축 기법 (Crashing: 공수투입 / Fast Tracking: 병행수행) 실행]
```

- 본질: 프로젝트 네트워크 상에서 작업 간의 의존 관계와 단일 확정적 소요 기간을 바탕으로 전진 및 역진 계산을 수행하여, 여유시간(Total Float)이 0인 가장 긴 경로(주공정선)를 식별하고 프로젝트의 최단 완료 기간을 결정하는 결정론적 공정 관리 기법
- 위치: `액티비티 정의 → 순서 배열(AON) → 소요 기간 산정 → CPM 주공정선 계산 → 공정 압축`
- 핵심: 이전 KPC 기출 빈출, AON 노드 표기법, 전진/역진 계산 공식, 여유시간(TF, FF), 공정압축법(Crashing, Fast Tracking)
- 실무: 주공정 전이(Sub-critical path) 방지, 비용구배(Cost Slope) 기반 크래싱, CCPM 버퍼 관리 연계

## 예상문제

> 프로젝트 일정 관리에서 임계경로법(CPM)의 개념, AON 네트워크 표기법 및 전진·역진 계산 절차, 여유시간(Total Float, Free Float) 산출 공식, 공정 압축 기법(Crashing, Fast Tracking)의 장단점 및 유의사항을 설명하시오. (25점)

## Ⅰ. 프로젝트 최단 완료 기간의 수학적 결정선, CPM의 개요

- 정의: 프로젝트를 구성하는 작업들의 선후행 관계를 네트워크 도표(AON)로 작성하고, 작업 소요 시간을 결정론적(단일 수치)으로 산정하여 여유시간이 없는 최장 경로인 주공정선(Critical Path)을 찾아내는 일정 분석 기법
- 등장 배경: 복잡한 대규모 프로젝트에서 납기 지연 요소를 사전에 파악하기 어려움, 한정된 자원을 전체 작업에 비효율적으로 분산 투입하는 낭비 극복 필요
- 핵심 목적: 프로젝트 전체 납기를 결정짓는 병목 작업의 사전 식별, 납기 준수를 위한 핵심 작업 집중 통제, 공정 압축 시 최소 비용 단축 경로 선정

#### 한줄 요약
- 네트워크 전진·역진 계산을 통해 여유시간이 0인 최장 경로를 도출하여 납기를 통제함

## Ⅱ. CPM의 4대 핵심 원리 및 공학적 특징

| 원리/특징 | 세부 내용 | 통제 및 기대 효과 |
|---|---|---|
| **결정론적 단일 추정** | 작업 기간의 불확실성을 배제하고 축적된 경험 기반 단일 확정 기간 부여 | 계산의 단순성 및 공정 통제의 명확성 확보 |
| **전진 계산 (Forward Pass)**| 시작 노드부터 종료 노드까지 순방향으로 조기착수일(ES)과 조기완료일(EF) 산출 | 프로젝트의 이론상 최단 완료 시점 계산 |
| **역진 계산 (Backward Pass)**| 종료 노드부터 시작 노드까지 역방향으로 늦은완료일(LF)과 늦은착수일(LS) 산출 | 납기를 맞추기 위한 작업별 최종 한계 시점 도출 |
| **총 여유 제로 (TF = 0)** | 주공정선 상의 모든 작업은 여유시간이 0이므로 하루만 지연되어도 전체 지연 | 일정 리스크가 가장 높은 작업군 집중 관리 |

#### 한줄 요약
- 단일 확정 기간, 전진·역진 계산, 총 여유 0의 주공정선 도출을 특징으로 함

## Ⅲ. AON 노드 표기법 및 주공정선 계산 구조

```text
[AON 노드 표준 표기법]
┌──────────────┬──────────────┬──────────────┐
│ 조기착수(ES) │ 작업기간(D)  │ 조기완료(EF) │
├──────────────┼──────────────┼──────────────┤
│ 늦은착수(LS) │ 총 여유(TF)  │ 늦은완료(LF) │
└──────────────┴──────────────┴──────────────┘

[프로젝트 네트워크 예시]
                ┌───────────┐
      ┌────────►│ 작업 B (3)├────────┐
      │         │ TF = 2    │        │
┌─────┴─────┐   └───────────┘   ┌────▼──────┐   ┌───────────┐
│ 작업 A (2)│                   │ 작업 D (4)├──►│ 작업 E (1)│ ──> [프로젝트 완료: 11일]
│ TF = 0    ├───►┌───────────┐──► TF = 0    │   │ TF = 0    │
└───────────┘    │ 작업 C (4)│  └───────────┘   └───────────┘
                 │ TF = 0    │
                 └───────────┘
* 주공정선 (Critical Path): A ──> C ──> D ──> E (총 기간 11일, 여유시간 TF = 0)
```

| 계산 구분 | 적용 공식 (일 단위 산출 기준) | 핵심 계산 규칙 |
|---|---|---|
| **전진 계산 (ES, EF)** | $EF = ES + Duration - 1$<br>$ES_{next} = \max(EF_{prev}) + 1$ | 합류(Merge) 지점에서는 선행 작업의 EF 중 가장 큰(최대) 값을 선택 |
| **역진 계산 (LS, LF)** | $LS = LF - Duration + 1$<br>$LF_{prev} = \min(LS_{next}) - 1$ | 분기(Burst) 지점에서는 후행 작업의 LS 중 가장 작은(최소) 값을 선택 |
| **총 여유 (Total Float)**| $TF = LS - ES = LF - EF$ | 전체 프로젝트 완료일을 지연시키지 않고 작업이 가질 수 있는 최대 여유 |
| **자유 여유 (Free Float)**| $FF = \min(ES_{next}) - EF - 1$ | 후속 작업의 조기착수일(ES)을 지연시키지 않고 가질 수 있는 고유 여유 |

#### 한줄 요약
- AON 노드 기반 전진/역진 계산을 수행하며 합류는 최대값, 분기는 최소값을 적용함

## Ⅳ. CPM 일정 분석 및 주공정선 관리 4단계 절차

```text
① 액티비티 정의 및 배열 → ② 전진 계산 (ES, EF 산출) → ③ 역진 계산 (LS, LF 산출) → ④ 주공정선 확정 및 통제
   └─ WBS / 선후행 관계 설정      └─ 프로젝트 완료일 도출       └─ 여유시간(Float) 도출       └─ Crashing / Fast Tracking
```

| 단계 | 주요 수행 내용 | 핵심 산출물 및 기준 |
|---|---|---|
| **1. 선후행 배열** | WBS 패키지 세분화, FS/SS/FF/SF 연관 관계 및 선행 작업 식별 | 네트워크 다이어그램 (AON) |
| **2. 전진 계산** | 시작 작업(ES=1)부터 순차 가산하여 프로젝트 총 소요 기간 및 마일스톤 산출 | 조기 일정 계획서 |
| **3. 역진 계산** | 목표 완료일부터 역산하여 각 작업별 허용 가능한 늦은 착수/완료일 계산 | 늦은 일정 계획서, Float 계산표 |
| **4. 주공정 통제** | 여유시간이 0인 주공정선을 확정하고, 일정 지연 발생 시 공정 압축 실행 | 주공정선 관리 대장, 공정 압축안 |

#### 한줄 요약
- 선후행 배열, 전진 계산, 역진 계산, 주공정선 확정 및 통제 순으로 진행됨

## Ⅴ. 일정 단축 기법 비교: 크래싱(Crashing) vs 패스트트래킹(Fast Tracking)

| 비교 항목 | 크래싱 (Crashing, 공정 압축) | 패스트트래킹 (Fast Tracking, 공정 첩행) |
|---|---|---|
| **핵심 개념** | 주공정선 상의 작업에 추가 자원을 투입하여 기간 단축 | 순차적으로 수행해야 할 선후행 작업을 병행하여 동시 진행 |
| **주요 수단** | 초과 근무, 고급 인력 추가 투입, 특급 장비 투입 | 선행 설계 완료 전 조기 코딩 착수, 단위 개발 병행 |
| **트레이드오프**| **비용 증가 (Cost Trade-off)** | **리스크 및 재작업 증가 (Risk Trade-off)** |
| **단축 대상 선정**| 주공정선 상에서 **비용 구배(Cost Slope)**가 가장 낮은 작업 | 선후행 의존도가 낮고 인터페이스 분리가 가능한 작업 |
| **단점/한계** | 수확 체감의 법칙 및 브룩스의 법칙(인력 추가 시 지연) | 설계 변경 시 대규모 소스코드 폐기 및 재작업 발생 |

#### 한줄 요약
- 크래싱은 돈을 써서 줄이고, 패스트트래킹은 위험을 감수하고 병행하여 줄임

## Ⅵ. 실무 적용 시 왜곡 요인 및 통제 대책

- 적용 상황: 대형 차세대 코어뱅킹 시스템 구축 프로젝트의 일정 지연 및 크리티컬 패스 통제

| 문제점 | 발생 원인 | 공학적·제도적 해결 대책 | 기대 효과 |
|---|---|---|---|
| **준주공정선의 돌발적 주공정 전이** | 주공정만 단축하다가 여유시간 1~2일인 다른 경로가 새 주공정선으로 변경 | 네트워크 전체 경로 민감도 분석 및 다중 경로 동시 단축 전략 수립 | 돌발 납기 지연 차단 |
| **비-주공정 작업에 자원 투입 낭비** | 여유시간(Float)이 존재하는 작업에 인력을 추가 투입 | 반드시 총 여유가 0인 주공정선 작업에만 크래싱 자원 집중 배정 | 일정 단축 예산 낭비 원천 방지 |
| **패스트트래킹 후 대규모 재작업** | 요구사항 미동결 상태에서 개발을 병행하여 인터페이스 변경 발생 | 인터페이스 규격 우선 동결 및 모의 객체(Mock API) 기반 병행 개발 | 재작업률 감소 및 병행 일정 준수 |
| **파킨슨 법칙에 의한 여유시간 낭비** | 작업자가 여유시간을 인지하고 마감일까지 작업을 지연시킴 | CCPM 제약이론 연계, 개별 여유시간을 통합 프로젝트 버퍼로 회수 | 프로젝트 실질 완공 기간 단축 |

#### 한줄 요약
- 다중 경로 모니터링, 주공정선 집중 투자, Mock API 활용, CCPM 버퍼 통합으로 통제함

## Ⅶ. CCPM 버퍼 관리를 결합한 하이브리드 일정 관리 중심의 결론

- **[결정론적 계산의 한계를 극복하는 통합 버퍼 관제]**: 인간의 본성인 학생 증후군(Student Syndrome)으로 인해 CPM 상의 여유시간은 현업에서 소진되므로, 버퍼를 중앙 통제해야 함
- 나라면: CPM으로 주공정선을 산출하되, 개별 작업의 안전 여유를 축소하여 프로젝트 맨 끝에 '프로젝트 버퍼(Project Buffer)'로 일원화 배치하고, 버퍼 소진율을 3색(녹/황/적) 대시보드로 관제하는 하이브리드 일정 거버넌스를 구축

#### 한줄 요약
- CPM의 수학적 엄밀성과 CCPM의 행동과학적 버퍼 관리를 결합하여 적기 납기를 완성함

## 1교시 10점 답안 발췌

### 1. CPM(Critical Path Method)의 정의
- 프로젝트 네트워크 상에서 작업 간의 의존 관계와 단일 확정 기간을 바탕으로 전진·역진 계산을 수행하여 총 여유시간(Total Float)이 0인 최장 경로(주공정선)를 도출하고 프로젝트 최단 완료 기간을 결정하는 일정 관리 기법

### 2. AON 노드 표기 및 전진/역진 계산식
```text
[AON 노드]  ES | Duration | EF      전진 계산: EF = ES + D - 1 (합류 시 최대값)
           LS | Float    | LF      역진 계산: LS = LF - D + 1 (분기 시 최소값)
                                   총 여유  : TF = LS - ES = LF - EF (CP: TF = 0)
```

### 3. 차별화 제언
- 주공정 단축 시 비용 구배(Cost Slope)가 가장 낮은 작업을 크래싱 대상으로 선정해야 하며, 준주공정선(Sub-critical path)의 전이 리스크를 상시 모니터링해야 함
