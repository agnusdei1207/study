## 연관 키워드

- 클라우드 전환 감리, 공유책임모델, 데이터 이관 정합성, 보안설계, FinOps, 출구전략

## Ⅰ. 클라우드 전환사업 감리의 개요

- 핵심 요약 : 클라우드 전환 사업의 책임 분장·보안·이관·비용·회수 가능성을 제3자 관점에서 증거로 검증하는 감리.
- 개념 : **클라우드 전환 감리**는 온프레미스에서 클라우드로의 전환 사업에서 전환 계획·목표 아키텍처·보안·데이터 이관·비용·운영 준비를 사업 수행자와 분리된 독립 관점에서 점검하는 활동.
- 배경 및 필요성 : 정부·기업의 클라우드 우선 전환 확대 속에서 전환은 자산 이전이 아니라 책임 분담·설정·과금 모델의 변경이며, 설정 오류·비용 통제 실패·공급자 종속 같은 클라우드 특유 위험은 기존 개발 감리 기준으로 식별이 곤란.
- 주요 목적 : 전환 후의 보안·성능·비용·회수 가능성이 목표 수준을 충족하는지 확인해 전환 실패와 사후 분쟁 방지.

## Ⅱ. 클라우드 전환사업 감리의 특징 및 장점

- 핵심 요약 : 책임·설정·이관·비용·출구의 클라우드 특화 쟁점을 증거 기반으로 검증해 전환 실효성을 확보.

1. 공유책임모델 검증 : **공유책임모델** (Shared Responsibility Model, 클라우드 사업자와 이용 조직이 보안 책임을 나누는 모델)에 따른 서비스 모델별 책임 분장과 실제 통제 주체 확인 → 책임 공백과 보안 누락 방지.
2. 설정 기반 보안 점검 : 목표 **보안설계** (보안 요구를 클라우드 구성으로 구현하기 위한 설계)가 계정·**IAM** (Identity and Access Management, 접근 권한 관리)·암호화·로그 설정으로 구현됐는지 증거 확인 → 설정 오류 기반 침해 사고 차단.
3. 데이터 이관 정합성 검증 : **데이터 이관 정합성** (이관 전후 데이터의 일치성)에 대한 전후 대사와 전환 시험 결과 확인 → 이관 손실·불일치 방지.
4. 비용 운영 검증 : **FinOps** (Cloud Financial Operations, 클라우드 비용의 계획·모니터링·최적화 체계) 관점의 태깅·예산·사용량 증거 확인 → 과도한 과금 구조 방지.
5. 종속성·회수 검증 : **출구전략** (Exit Strategy, 공급자 변경·온프레미스 복귀 계획)과 이식성 시험 결과 확인 → 공급자 종속 리스크의 사전 관리.

## Ⅲ. 클라우드 전환사업 감리의 구조 (흐름)

- 핵심 요약 : 전환의 계획→설계→이관→운영 단계마다 증거 기반 점검을 배치한 감리 절차와 사업자·이용 조직의 책임 구조로 구성.
- 감리 절차 : 전환 단계마다 문서·설정·시험 결과의 증거를 확인하고 지적 사항의 개선을 재검증하는 절차.
- 책임 구조 : 공유책임모델에 따라 인프라는 사업자, 설정·계정·데이터는 이용 조직이 통제하는 구조.

```text
[ 클라우드 전환 감리 수행 흐름 ]

전환 계획·목표 아키텍처 검토
    ↓
책임 분장·보안설계 검증
    ↓
데이터 이관·시험 증거 점검
    ↓
비용·운영·출구 준비 확인
    ↓
지적·개선 조치 재검증
```

```text
[ 공유책임모델의 책임 구조 ]

클라우드 사업자
   물리 인프라·가상화 계층 보호
    ↓
이용 조직
   설정·계정·접근 권한·데이터 보호
    ↓
공동 관리 영역
   로그 기록·취약점 점검·사고 대응
```

## Ⅳ. 온프레미스 개발 사업 감리와 클라우드 전환 감리의 비교

- 핵심 요약 : 개발 산출물 중심의 감리에서 설정·운영·비용·회수 가능성 중심의 감리로 점검 기준이 이동.

| 비교 축 | 온프레미스 개발 사업 감리 | 클라우드 전환 감리 |
| --- | --- | --- |
| 점검 대상 | 요구사항·설계·시험·인도물 | 전환 설계·설정·이관·사용량·종속성 |
| 보안 관점 | 내부 경계·시스템 권한 중심 | 공유책임·설정·IAM·로그 증거 중심 |
| 자산·비용 | 고정 자산과 개발 원가 | 사용량 기반 과금·태깅·예산 통제 |
| 회수·이전 | 시스템 인수·유지보수 계약 | 이식성 시험과 출구전략 |
| 감리원 지식 | 개발 생애주기·기술 표준 | 클라우드 서비스 모델·과금·보안 설정 |

## Ⅴ. 클라우드 전환사업 감리의 한계와 방안

- 핵심 요약 : 책임 오해·설정 오류·불일치·비용 증가를 분장표·설정 점검·대사·예산 통제로 완화.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 책임 분장 오해 | 사업자 보호 가정 → 이용 조직 영역 통제 누락 | 서비스 모델별 책임 분장표와 설정 증거 대조 | 통제 미이행 항목 수 |
| 보안설정 오류 | 기본값 의존·권한 과다 부여 → 침해 사고 | 최소권한·암호화·로그 보존 기준 설정 점검 | 권한 과다 계정 수 |
| 데이터 불일치 | 변환·누락 → 업무 오류와 신뢰 하락 | 이관 전후 대사와 전환 시험 재현 검증 | 대사 불일치 건수 |
| 비용·종속성 증가 | 무계획 사용·전용 기능 의존 → 이전 곤란 | 태깅·예산 경보와 이식성 시험 운영 | 예산 초과율, 이전 시험 통과율 |

## Ⅵ. 클라우드 전환사업 감리에 대한 기술사적 제언

- 핵심 요약 : 발주기관과 감리기관이 클라우드 전환 감리의 표준 점검 체계와 자동 증거 수집을 제도화할 것.
- 발주기관 : 전환 사업 계약에 책임 분장표·보안 기준·출구 조항을 필수 문서로 지정.
- 감리기관 : **CSPM** (Cloud Security Posture Management, 클라우드 보안 설정 자동 점검 도구) 결과를 증거로 활용하는 표준 절차 운영.
- 정책 부문 : 전환 감리 지침에 클라우드 특화 점검 항목과 감리원 역량 기준을 표준화.

## Ⅶ. 결론

- 핵심 요약 : 클라우드 전환 감리는 책임·설정·이관·비용·회수 가능성의 증거로 전환의 실효성을 판정하는 활동.
- 전환의 성패는 자산 이전이 아니라 책임·설정·비용 통제의 이전 여부에 달리는 구조.
