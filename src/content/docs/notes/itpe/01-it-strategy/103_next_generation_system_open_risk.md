## 지식 로드맵 내 현재 위치

IT 전략·관리 → 프로젝트 위험관리 → **차세대 시스템 오픈 리스크**

## 30초 인출

- 본질: 새로 구축한 시스템을 운영에 전환해 가동하는 시점(오픈)에 데이터·연계·성능 문제로 업무가 멈추거나 혼란해질 위험. 실무 용어이며 기술 개념은 컷오버(Cutover)
- 메커니즘: 계획·리허설로 전환 순서와 원복 절차를 검증하고, 전환 실행 뒤 사전에 정한 기준으로 Go/No-Go를 판정해 기준 미달이면 원복(Rollback) 또는 수정 후 전진
- 통찰: 문제가 생긴 뒤 원인을 분석하고 협의하면 중단이 길어지고 새 거래가 쌓여 원복도 어려워지므로 원복 트리거·결정 시한·결정권자를 오픈 전에 확정하고 원복 훈련으로 소요시간을 실측

<details>
<summary>핵심 용어</summary>

- **차세대 시스템 오픈 리스크** : 신규 구축 시스템의 운영 전환·가동 시점에 데이터·연계·성능 문제로 업무가 중단되는 위험. 표준 용어가 아닌 실무 용어
- **컷오버(Cutover)** : 기존 환경의 사용자와 트래픽을 새 환경으로 넘겨 새 시스템을 가동하는 전환 활동
- **런북(Cutover Runbook)** : 전환 활동의 순서, 계획 시작·종료 시각, 담당자를 기록해 전환팀이 진행을 추적하는 문서
- **Go/No-Go** : 사전에 정의한 기준으로 전환을 진행할지 중단할지 결정하는 관문
- **원복(Rollback)** : 전환이 실패했을 때 사용자와 트래픽을 기존 환경으로 되돌리는 절차. 새 환경에 새 데이터가 쌓였으면 데이터 복원이 함께 필요
- **수정 후 전진(Fix Forward)** : 원복하지 않고 새 환경에서 문제를 고쳐 전환을 이어 가는 선택
- **CDC(Change Data Capture)** : 원천 데이터의 변경 내역을 포착해 다른 저장소에 재생·동기화하는 방식. 원복 때 스냅숏 이후의 변경분 손실을 줄임
- **전환창(Downtime Window)** : 전환을 위해 할당한 서비스 중단 허용 시간

## 2~4교시 25점 답안

## Ⅰ. 차세대 시스템 오픈 리스크의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **차세대 시스템 오픈 리스크** 는 신규 시스템의 운영 전환·가동 시점에 데이터·연계·성능 문제로 업무가 중단되는 위험 |
| 목적 | 전환 실패의 업무 영향 최소화와 원복 결정의 적시성 확보 |

## Ⅱ. 전환 시점에 집중되는 오픈 리스크의 특징

| 특징 | 의미 |
|---|---|
| 짧은 **전환창** 에 작업 집중 | 데이터 동기화·경로 전환·검증이 할당된 중단 시간 안에 수행되며 초과 시 매출·신뢰에 영향 |
| 사전 시험의 한계 | 다른 시스템과의 의존성 때문에 운영에서 일어날 모든 시나리오를 시험할 수 없음 |
| 시간에 따른 원복 난이도 상승 | 새 환경에 거래가 쌓이면 원복에 데이터 복원이 필요 |
| 기술·업무 부문의 공동 준비 | 시험 완결성, 모니터링, 이해관계자의 지원 체계 이해까지 함께 점검 |

## Ⅲ. 전환 단계 체계와 원복 방식

### 오픈 리스크 관리 단계

```text
전환 계획 ── 전환창·의존성·시험 계획·원복 절차
    ↓
리허설·원복 훈련 ── 전환 순서와 원복 소요시간 검증
    ↓
운영 준비 점검 ── 시험 완결성·모니터링·이해관계자 준비
    ↓
전환 실행: 입력 동결 → 최종 백업 → 최종 데이터 동기화 → 경로 전환 → 검증
    ↓
Go/No-Go
    ├─ 기준 충족 → 전환 완료
    └─ 기준 미달 → 원복 또는 수정 후 전진
```

### 원복 확대: 새 데이터 발생 여부에 따른 방식

```text
원복 결정
    ├─ 새 환경에 새 데이터 없음 → 기존 환경 재가동, 경로 재전환
    └─ 새 환경에 새 거래 발생 → 데이터 복원 필요
          ├─ 기존 환경으로의 복제본을 유지해 그 복제본으로 원복
          ├─ 신·구 두 저장소에 동시 기록
          └─ 백업 복원 ── 복원 소요시간을 사전 시험으로 실측
```

## Ⅳ. 일괄 전환·단계적 전환·기능 단위 점진 교체의 비교

| 비교축 | 일괄 전환(All-at-once) | 단계적 전환(Phased) | 점진 교체 |
|---|---|---|---|
| 전환 방식 | 한 번의 절체로 전체 사용자와 트래픽 이동 | 정해진 기간 동안 일부 트래픽부터 점진 이동 | 기능 단위로 신 시스템에 교체, 앞단 중계 계층이 요청 분배 |
| 원복 | 원복을 부르는 시점과 주체가 핵심 | 일부 트래픽만 옮겨 원복이 빠르고 단순 | 구 시스템 객체를 제거하기 전까지 원복 가능 |
| 부담 | 사전 성능·회귀 시험 확대 | 복잡하고 시간 소요 | 신·구 시스템의 공존과 중계 계층 관리 |
| 적합 조건 | 데이터 원천과 애플리케이션 사이 지연을 견디지 못하는 경우 | 업무상 중요한 운영 시스템, 트래픽을 나누어 보낼 수 있는 구조 | 요청 가로채기가 가능하고 구 시스템을 오래 병행할 수 있는 경우 |

## Ⅴ. 오픈 리스크 관리의 한계와 방안

| 한계 | 방안 |
|---|---|
| 운영에서만 드러나는 시나리오는 사전 시험으로 확인할 수 없음 | 시험하지 못한 시나리오의 위험·식별 방법·대응을 전환 계획에 문서화 |
| 문제 원인 분석이 길어져 중단이 연장 | 문제 식별·원인 분석·Go/No-Go 결정의 시간 제한 설정 |
| 새 거래가 쌓인 뒤의 원복은 데이터 복원이 필요 | 변경분 재생 방식을 정하고 백업 복원 시간을 사전 시험으로 실측 |
| 일괄 전환에서 실패 영향이 전 업무로 확산 | 트래픽·기능을 나눌 수 있는 업무는 단계적 전환 선택 |

## Ⅵ. 제언

오픈 전에 원복 트리거·결정 시한·결정권자를 확정하고, 원복 훈련으로 실측한 소요시간을 기준으로 결정 시한을 설정

### 원복 결정 구조

```text
원복 결정 규칙
    │
    ├─ 트리거 ── 사전 정의한 기준 충족 시 원복 개시
    │
    ├─ 시한 ── 원인 분석·Go/No-Go 결정의 제한 시간
    │
    └─ 결정권자 ── 수정 후 전진과 원복 중 선택
```

### 시한 확대: 원복 훈련 기반 결정 시한 설정

```text
원복 훈련으로 원복 소요시간 실측
    ↓
전환창에서 원복 소요시간을 제외해 결정 시한 산정
    ↓
결정 시한 공지
    ↓
시한 내 Go/No-Go 결정
    ├─ 문제·해결 경로를 시한 내 설명 가능 → 수정 후 전진
    └─ 설명 불가 → 원복 개시
```

### 선택 근거: 문제 발생 후 협의와의 비교

| 구분 | 문제 발생 후 협의 | 제언: 사전 확정 규칙 |
|---|---|---|
| 판단 기준 | 장애 상황에서 논의 | 오픈 전 합의한 트리거 |
| 결정 시점 | 원인 분석이 끝날 때까지 지연 | 제한 시간 안 |
| 원복 소요시간 | 불명확 | 원복 훈련으로 실측 |
| 결정 주체 | 불명확 | 지정한 결정권자 |
