## 큰 그림과 30초 인출

```text
┌───────────────── [차세대 오픈 단계별 리스크 통제 체계] ─────────────────┐
│                                                                        │
│   [ 오픈 전 (D-30 ~ D-1) ]                                             │
│   - 데이터 모의이행(Dry-Run) 반복 수행 및 소요시간 실측                │
│   - 전사 통합 리허설, 임계 부하 테스트, 대외기관 연계 점검              │
│   - 롤백(Rollback) 시나리오 수립 및 마지노선(Drop-dead Time) 확정       │
│                               │                                        │
│                               ▼                                        │
│   [ 오픈 당일 (D-Day 컷오버) ]                                         │
│   - 구 시스템 데이터 추출·변환·적재(ETL) 및 데이터 대사 검증           │
│   - Go/No-Go 의사결정 게이트 ──▶ [치명 결함 발생 시 즉시 롤백 가동]    │
│                               │                                        │
│                               ▼ [Go 승인]                              │
│   [ 오픈 후 (D+1 ~ D+30) ]                                             │
│   - 종합상황실(War-Room) 가동, 실시간 APM 모니터링, 비상 핫픽스 체계  │
└────────────────────────────────────────────────────────────────────────┘
```

- 본질: 대규모 차세대 시스템 구축 후 구 시스템에서 신 시스템으로 전환(Cut-over)하는 과정에서 발생하는 데이터 정합성 왜곡, 대용량 트랜잭션 병목, 대내외 연계 단절 등의 치명적 오픈 장애를 예방하고 통제하는 전사 리스크 엔지니어링 체계
- 위치: `구축 및 통합 테스트 → [모의이행·리허설] → [컷오버(Cut-over)] → [Go/No-Go 판정] → 안정화 및 워룸 운영`
- 핵심: 제129회 KPC 모의고사 기출, 컷오버(Cut-over) 계획, 데이터 모의이행(Dry-Run), 롤백 마지노선(Drop-dead Time), Go/No-Go 의사결정 체계, 종합상황실 운영
- 실무: 이행 시간 초과 대비 병렬 ETL 적용, 데이터 검증 스크립트 자동화, 정치적 오픈 강행 차단 및 객관적 판정 지표 준수

## 예상문제

> 금융·공공 등 대규모 차세대 시스템 전환(Big-Bang Cut-over) 시 발생할 수 있는 주요 오픈 리스크의 유형, 오픈 전·중·후 단계별 리스크 통제 및 검증 방안, 비상시 롤백(Rollback) 시나리오와 Go/No-Go 의사결정 기준을 설명하시오. (10점/25점)

## Ⅰ. 대규모 IT 전환의 사활을 거는 분수령, 오픈 리스크의 개요

- 정의: 차세대 정보시스템의 정식 가동(Go-Live) 시점에 구 시스템의 업무, 데이터, 인프라를 신 시스템으로 일괄 전환하는 컷오버 과정에서 비즈니스 중단, 데이터 유실, 성능 장애가 발생할 위험
- 배경: 단일 시점에 전사 업무를 전환하는 빅뱅(Big-Bang) 방식 선호로 인해 복합 리스크(데이터 이행 지연, 인터페이스 오류, 현업 업무 미숙)가 동시 다발적으로 분출
- 목적: 객관적인 단계별 검증 게이트웨이 구축, 불가역적 시점(Point of No Return) 이전의 안전한 롤백 경로 확보, 무장애 안정 가동 및 비즈니스 연속성(BCP) 담보

#### 한줄 요약
- 구 시스템에서 신 시스템으로의 전환 과정에서 발생하는 총체적 장애 위험과 통제 체계임

## Ⅱ. 차세대 오픈의 3대 핵심 리스크 영역 및 특징

| 리스크 영역 | 주요 발생 원인 | 구체적 장애 양상 | 영향도 |
|---|---|---|---|
| **데이터 이행 리스크** | 레거시 데이터 비표준, 매핑 오류, 대용량 데이터 ETL 시간 지연 | 잔액 불일치, 고객 정보 누락, 이행 시간 초과로 오픈 지연 | 치명적 (금융/결제 마비) |
| **시스템 성능 리스크** | 부하 테스트 미흡, 비효율적 DB 인덱스, 대용량 트랜잭션 락 | 오픈 첫날 CPU 100% 폭주, 응답 지연, 세션 풀 고갈 | 매우 높음 (서비스 전면 지연) |
| **대내외 연계 리스크** | 외부 금융망/유관기관 프로토콜 불일치, 방화벽 포트 미오픈 | 결제 연동 실패, 공동 인증서 통신 단절, 대외 배치 누락 | 높음 (업무 파행) |
| **사용자 숙련도 리스크** | 현업 화면 변경 적응 미숙, 예외 처리 프로세스 교육 부족 | 창구 업무 지연, 고객 불만 폭주, 단순 조작 오류 연발 | 중간 (대고객 서비스 질 저하) |

#### 한줄 요약
- 데이터 정합성, 시스템 성능, 대내외 연계, 현업 숙련도의 4대 리스크가 복합 발생함

## Ⅲ. 컷오버(Cut-over) 타임라인 및 롤백 아키텍처

```text
┌─────────────────────── [컷오버 타임라인 (Cut-over Timeline)] ───────────────────────┐
│                                                                                       │
│  금요일 18:00            토요일 12:00          일요일 12:00         일요일 18:00      │
│  [레거시 거래 중단] ──▶ [데이터 추출·적재] ──▶ [데이터 정합성 대사] ──▶ [Go/No-Go 판정]   │
│                                                                      │                │
│                                                 ┌────────────────────┴────────┐       │
│                                                 ▼                             ▼       │
│                                          [Go 승인: 배포]               [No-Go: 롤백]   │
│                                                 │                             │       │
│                                                 ▼                             ▼       │
│                                          월요일 09:00 오픈             월요일 09:00   │
│                                          (신규 차세대 가동)            (구 레거시 복원)│
│                                                                                       │
│  ※ 롤백 마지노선(Drop-dead Time): 일요일 18:00 (이후 레거시 복구 물리적 불가)        │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

| 구성 요소 | 주요 역할 및 통제 기준 | 위험 통제 메커니즘 |
|---|---|---|
| **데이터 모의이행 (Dry-Run)** | 본 이행과 동일한 환경에서 3회 이상 사전 반복 수행 | 단계별 실측 소요시간 산출 및 ETL 튜닝 |
| **정합성 자동 대사 도구** | 원천 DB와 목표 DB의 테이블 건수, 주요 금액 합계 자동 비교 | 불일치 레코드 즉각 탐지 및 격리 |
| **롤백 마지노선 (Drop-dead Time)** | 구 시스템 복구를 위해 소요되는 최소 시간을 역산하여 정한 한계 시각 | 마지노선 도달 시 미해결 결함 존재 시 즉각 No-Go |
| **종합상황실 (War-Room)** | 경영진, PMO, 감리, 인프라, 애플리케이션, 협력사 전원 집결 | 단일 지휘 체계 구축 및 즉각 의사결정 |

#### 한줄 요약
- 엄격한 롤백 마지노선과 데이터 정합성 검증 게이트웨이를 기반으로 전환을 통제함

## Ⅳ. 오픈 전·중·후 단계별 리스크 관리 절차

```text
[1단계: 오픈 전 검증] ──→ [2단계: 컷오버 수행] ──→ [3단계: Go/No-Go 판정] ──→ [4단계: 안정화 운영]
- 3회 이상 모의이행      - 레거시 데이터 백업    - 정량적 판정 지표 체크  - 워룸 24시간 모니터링
- 롤백 시나리오 검증     - 병렬 ETL 파이프라인   - 마지노선 이전 의결     - 긴급 핫픽스 배포 체계
```

| 단계 | 수행 주체 | 상세 활동 내용 | 통제 기준 및 산출물 |
|---|---|---|---|
| **1. 오픈 전 (D-30 ~ D-1)** | PMO 및 전사 TFT | 데이터 모의이행(Dry-Run), 전사 통합 업무 리허설, 극한 부하 테스트 수행 | 모의이행 결과서, 롤백 매뉴얼 |
| **2. 오픈 당일 (D-Day)** | 컷오버 이행팀 | 기존 시스템 셧다운, 최종 데이터 백업, 마이그레이션 ETL 실행, 네트워크 절체 | 컷오버 체크리스트, 진행 현황판 |
| **3. Go/No-Go 판정** | 의사결정 위원회 | 데이터 일치율, 핵심 업무 기능 정상 동작 여부, 외부 인터페이스 개통 확인 | Go/No-Go 의결서 |
| **4. 오픈 후 (D+1 ~ D+30)** | 비상 운영 대응팀 | 종합상황실 24시간 가동, 실시간 트랜잭션 및 리소스 모니터링, 신속 장애 조치 | 일일 종합 장애 현황판 |

#### 한줄 요약
- 사전 모의이행, 컷오버 및 백업, 객관적 판정, 종합상황실 안정화의 4단계로 전개함

## Ⅴ. 빅뱅(Big-Bang) 오픈 vs 단계적(Phased) 오픈 비교

| 비교 항목 | 빅뱅(Big-Bang) 오픈 | 단계적(Phased) 오픈 |
|---|---|---|
| **전환 방식** | 전 업무 및 모듈을 일 특정 시점에 일괄 동시 전환 | 업무 도메인별(여신→수신 등) 또는 채널별 순차 전환 |
| **데이터 이행 복잡도** | 단 1회의 대규모 이행으로 인터페이스 이중화 불필요 | 장기간 구 시스템과 신 시스템 간 데이터 동기화 유지 필수 |
| **오픈 리스크 수준** | **매우 높음** (실패 시 전사 업무 전면 중단) | **낮음** (장애 발생 시 해당 모듈로 피해 국소화) |
| **비용 및 기간** | 단기 집중 투입으로 상대적 비용 절감 | 장기 프로젝트화 및 이중 시스템 운영 유지비용 발생 |
| **적용 권장 환경** | 업무 간 결합도가 극도로 높은 핵심 금융 코어뱅킹 | 모듈 간 결합도가 낮고 점진적 확장이 가능한 플랫폼 |

#### 한줄 요약
- 빅뱅은 이행 구조가 단순하나 위험이 크며, 단계적 오픈은 위험이 낮으나 동기화 비용이 큼

## Ⅵ. 실무 고려사항 및 대책

- 적용 상황: 대형 금융기관 코어뱅킹 차세대 시스템 일괄 빅뱅 오픈

| 문제점 | 발생 원인 | 공학적·제도적 해결 대책 | 기대 효과 |
|---|---|---|---|
| **이행 시간(Cut-over Window) 초과** | 비효율적 인덱스 및 대용량 테이블 단일 스레드 적재로 인한 ETL 지연 | 병렬 ETL 파이프라인 구성, 불필요 인덱스 사전 Drop 후 적재 완료 후 일괄 재생성 | 이행 소요시간 대폭 단축 및 공기 준수 |
| **데이터 대사 불일치 및 거래 마비** | 원천 데이터의 널(Null) 값 예외 처리 미흡 및 코드 매핑 규칙 오류 | 사전 모의이행 기반 데이터 정제 및 체크섬(Checksum)/금액 합계 대사 스크립트 자동화 | 데이터 무결성 보장 및 잔액 오차 원천 차단 |
| **경영진의 정치적 오픈 강행** | 대외 공표 일정 및 지체상금 부담으로 인해 치명 결함 미해결 상태에서 강행 | 객관적 정량 지표(결함 해결률, 정합성 100%) 미달 시 자동으로 No-Go가 의결되는 거버넌스 수립 | 전산 대란 및 최고경영진 법적 책임 방지 |

#### 한줄 요약
- 병렬 ETL, 자동 대사 스크립트, 객관적 No-Go 거버넌스로 오픈 리스크를 통제해야 함

## Ⅶ. 결론 및 기술사적 제언

- [핵심 통찰]: 차세대 오픈 당일 가장 위험한 인물은 "어떻게든 밤새워서 해결하겠다"고 장담하는 엔지니어와 "약속된 날짜에 무조건 열어야 한다"고 압박하는 경영진임. 오픈의 성공은 얼마나 잘 오픈하느냐가 아니라 '언제 안전하게 물러설 것인가(Rollback)'를 아는 결단력에 달려 있음.
- 나라면: 감리법인, 외부 PMO, 정보보안최고책임자(CISO)가 참여하는 독립적 '오픈 판정 위원회'를 구성하고, [일요일 18시 롤백 마지노선 도달 시 핵심 거래 결함 잔존 시 자동 No-Go 집행]을 이사회 의결 조항으로 명문화하여 감정적·정치적 개입을 원천 배제하는 시스템적 세이프가드를 구축하겠음.

#### 한줄 요약
- 독립 판정 위원회와 자동 롤백 세이프가드로 정치적 강행을 막고 시스템 안전을 지켜야 함

## 1교시 10점 답안 발췌

### 1. 정의 및 핵심 개념
- 차세대 시스템 오픈 리스크는 신규 시스템 가동 시점에 데이터 이행, 대용량 트랜잭션, 대내외 연계 과정에서 발생하는 복합 장애 위험을 통제하고 비즈니스 연속성을 담보하는 프로젝트 관리 체계임.

### 2. 핵심 메커니즘 / 체계
```text
[오픈 전: 모의이행 3회 실측] ──→ [컷오버: 병렬 ETL] ──→ [판정: 롤백 마지노선 준수] ──→ [워룸 안정화]
```
- 사전 모의이행을 통해 소요시간을 검증하고, 객관적 Go/No-Go 기준과 드롭데드 타임(Drop-dead Time)을 기반으로 비상 롤백 체계를 확립함.

### 3. 차별화 제언
- 정치적 강행을 차단하기 위해 데이터 대사 자동 검증률 100%와 핵심 결함 제로를 전제 조건으로 하는 '독립적 Go/No-Go 품질 게이트'를 구축해야 함.
