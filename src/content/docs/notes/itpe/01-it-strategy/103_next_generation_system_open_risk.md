## 지식 로드맵 내 현재 위치

IT 전략·관리 → 프로젝트 위험관리 → **차세대 시스템 오픈 리스크**

## 30초 인출

- 본질: 차세대 시스템 오픈 리스크는 기존 시스템을 새 시스템으로 바꿔 가동하는 전환 시점에 데이터·연계·성능 문제로 업무가 멈출 위험
- 메커니즘: 리허설로 전환 절차와 복구 절차를 검증하고, 전환 당일 사전에 합의한 기준으로 개통 또는 원복을 판정
- 통찰: 개통 당일에 원복을 논의하면 복구 시각을 넘기므로 개통 판정 기준과 원복 한계시각의 사전 확정

<details>
<summary>핵심 용어</summary>

- **차세대 시스템 오픈 리스크** : 신 시스템 전환·가동 시점에 데이터 불일치·연계 단절·성능 저하로 업무가 중단될 위험
- **Cut-over(전환)** : 기존 시스템의 데이터·연계·이용자를 새 시스템으로 최종 이관하고 가동하는 절차
- **Go/No-Go** : 사전 판정 기준에 따라 새 시스템의 개통 진행 또는 중단을 결정하는 의사결정 관문
- **Rollback(원복)** : 전환 실패 시 시스템과 데이터를 전환 전의 정상 상태로 되돌리는 복구 절차
- **PoNR(Point of No Return, 원복 한계시각)** : 이 시각 이후에는 새 시스템의 거래가 쌓여 원복이 사실상 불가능해지는 시점. 표준 정의가 아닌 전환(cutover) 실무 용어로, AWS 전환 지침의 사전 정의 기준에 따른 원복 체크포인트와 대응
- **리허설(모의 전환)** : 실제 전환과 같은 순서·규모로 이관·검증·원복을 미리 수행하는 시험

## 2~4교시 25점 답안

## Ⅰ. 차세대 시스템 오픈 리스크의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **차세대 시스템 오픈 리스크** 는 신 시스템 전환·가동 시점에 데이터·연계·성능 문제로 업무가 중단될 위험 |
| 목적 | 전환 실패의 업무 영향 최소화와 개통·원복의 적시 결정 |

## Ⅱ. 전환 시점에 집중되는 오픈 리스크의 특징

| 특징 | 의미 |
|---|---|
| 짧은 전환창 집중 | 데이터 이관·연계 전환·이용자 유입이 제한된 시간에 동시 발생 |
| 시간에 따른 복구 제약 | 새 시스템 거래가 쌓일수록 원복 비용 증가, **PoNR** 이후 원복 곤란 |
| 기술·업무 합동 판정 | 기술 검증 결과와 현업 업무 지속 가능성의 동시 판단 |

## Ⅲ. 전환 단계별 관리 체계

### 오픈 리스크 관리 단계

```text
전환 계획 ── 범위·순서·의존성·책임
    ↓
리허설 ── 이관·대사·성능·원복 검증
    ↓
전환 실행 ── 업무 동결·백업·이관·절체
    ↓
Go/No-Go 판정
    ├─ 기준 충족 → 개통·안정화 감시
    └─ 기준 미달 → Rollback 실행
```

### Go/No-Go 판정 확대: 판정 기준과 원복 시한

```text
전환 실행 결과 수집
    ↓
데이터 대사 ── 건수·금액·참조 무결성
    ↓
업무 시험 ── 핵심 거래의 처음부터 끝까지 수행
    ↓
PoNR 이전 여부 확인
    ├─ 이전 → 기준 미달 시 Rollback 가능
    └─ 경과 → 원복 대신 현장 수정·비상 업무
```

## Ⅳ. 일괄 전환과 단계적 전환의 비교

| 구분 | 일괄 전환(Big-Bang) | 단계적 전환(Phased) |
|---|---|---|
| 전환 방식 | 전 업무 동시 절체 | 업무·채널별 순차 절체 |
| 실패 영향 | 전 업무에 집중 | 전환한 영역으로 한정 |
| 부담 | 짧은 전환창의 높은 판정 압박 | 신·구 병행 운영과 데이터 동기화 |
| 적합 조건 | 업무 간 결합이 강해 분리 불가 | 업무 영역을 독립적으로 분리 가능 |

## Ⅴ. 오픈 리스크 관리의 한계와 방안

| 한계 | 방안 |
|---|---|
| 업무 간 결합이 약한데도 일괄 전환해 실패 영향 집중 | 분리 가능한 업무는 단계적 전환 선택 |
| 단계적 전환 중 신·구 데이터 불일치 | 병행 기간의 동기화 대상·대사 주기 확정 |
| 리허설이 운영 규모·순서와 달라 문제 미발견 | 운영 데이터 규모·실제 순서로 리허설 반복 |
| 판정 기준·권한 미정으로 일정 압박 속 개통 강행 | 개통 판정 기준과 결정권자의 사전 승인 |
| 원복 가능 시각을 모른 채 판정 지연 | 원복 소요시간을 역산한 PoNR 확정 |

## Ⅵ. 제언

전환 전 개통 판정 기준과 PoNR을 확정하고, 현업·기술 책임자가 함께 판정하는 구조의 수립

### 개통 판정 책임 구조

```text
Go/No-Go 판정
    │
    ├─ 현업 책임자 ── 핵심 업무 수행 가능 여부
    │
    ├─ 기술 책임자 ── 대사·성능·연계 결과
    │
    └─ 최종 결정권자 ── 개통·원복 결정과 기록
```

### 최종 결정권자 확대: 판정 시한(PoNR) 설정 절차

```text
Rollback 소요시간 실측(리허설)
    ↓
업무 재개 목표 시각에서 소요시간 역산
    ↓
PoNR 확정과 판정 시한 공지
    ↓
판정 시한 내 Go/No-Go 결정
```

### 선택 근거: 당일 판단과의 비교

| 구분 | 당일 상황 판단 | 제언: 기준·PoNR 사전 확정 |
|---|---|---|
| 판정 기준 | 문제 발생 후 협의 | 리허설 결과로 사전 합의 |
| 판정 주체 | 기술 조직 중심 | 현업·기술 합동, 결정권자 확정 |
| 원복 시한 | 불명확 | 원복 소요시간 역산 PoNR |
| 기준 미달 시 | 개통 강행 가능성 | PoNR 이전 원복 |
