## 지식 로드맵 내 현재 위치
현재 위치: IT 전략·관리 → 차세대 시스템 오픈 리스크


## 30초 인출

- 본질: **차세대 시스템 오픈 리스크** 는 구 시스템에서 신 시스템으로 전환할 때 데이터·연계·성능 문제로 업무가 중단될 위험
- 메커니즘: 전환 절차의 사전 검증과 합의한 기준·복구 가능 시간에 따른 개통 또는 중단 결정
- 통찰: 한계: 개통 시 기능 시험만으로 대량 이용·장애를 검증하기 어려움 → 방안: 복구 시간·데이터 변경 가능성을 고려해 개통 중단 시점을 미리 설정

<details>
<summary>핵심 용어</summary>

- **차세대 시스템 오픈 리스크** : 신 시스템 전환 중 업무 중단이나 데이터 불일치를 일으킬 수 있는 위험
- **Cut-over** : 기존 시스템을 신규 차세대 시스템으로 데이터·연계·트래픽을 최종 이관·가동하는 전환 절차
- **Go/No-Go** : 체크리스트 검증 결과를 바탕으로 신규 시스템 가동 지속 또는 중단·원복을 판정하는 의사결정 관문
- **Rollback** : 전환 실패 시 시스템과 데이터를 검증된 이전 정상 상태로 되돌리는 복원 절차
- **RACI(Responsible, Accountable, Consulted, Informed)** : 활동별 수행·최종책임·협의·공유 역할을 구분하는 책임 배정표
- **E2E(End-to-End)** : 시스템 구성요소를 개별적으로가 아니라 업무 시작부터 완료까지 연결해 확인하는 시험 관점

</details>

## 2~4교시 25점 답안

## Ⅰ. 차세대 시스템 오픈 리스크 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **차세대 시스템 오픈 리스크** 는 신 시스템 전환 중 데이터·연계·성능 문제로 인한 업무 중단 위험 |
| 목적 | 전환 실패의 업무 영향 최소화와 안전한 개통·중단 결정 |

## Ⅱ. 차세대 시스템 오픈 리스크의 특징

| 특징 | 의미 |
|---|---|
| 전환 시점 집중 | 데이터·연계·이용자 트래픽이 짧은 전환창에 함께 이동 |
| 복구 시한 제약 | 데이터 변경과 업무 재개 시점에 따라 원복 가능 시간 변화 |
| 합동 판정 필요 | 기술 검증 결과와 현업의 업무 지속 가능성을 함께 판단 |

## Ⅲ. Cut-over 단계별 통제 체계

> 업무 동결·롤백 한계시각(Point of No Return)·종합 판정을 포함한 역산 일정의 관리

### 1. Cut-over 개통·복구 판정 흐름

```text
백업·이행 준비
    ↓
데이터 대사·연계 시험
    ↓
사전 합의한 개통 기준 판단
    ├─ 충족 → 개통
    └─ 미충족 → 중단·복구 절차 실행
```

복구 가능 시점은 사업별 데이터 변경 방식·업무 영향·복구시간을 바탕으로 설정. 특정 단일 산식의 일률 적용은 배제.

### 2. 단계별 통제 활동 및 산출물

| 단계 | 활동 | 산출 |
|---|---|---|
| 계획 | 범위·순서·의존성·책임 정의 | **Cut-over** 계획·RACI |
| 리허설 | 모의이행·대사·성능·복구 검증 | 리허설 결과·보완목록 |
| 실행 | 동결·백업·이행·절체·Smoke Test | 실행로그·대사결과 |
| 판정 | **Go/No-Go** · **Rollback** 결정 | 판정서·복구 승인 |
| 안정화 | 모니터링·장애·현업지원 | 상황보고·종료기준 |

## Ⅳ. Big-Bang과 Phased 전환 비교

| 기준 | Big-Bang | Phased |
|---|---|---|
| 전환 | 일괄 절체 | 업무·채널별 순차 절체 |
| 장점 | 이중운영·동기화 기간 최소화 | 영향 범위 분산 |
| 위험 | 실패 영향 집중 | 신·구 정합성·장기 이중운영 |
| 선택 | 강한 결합·단일 전환창 | 분리 가능한 도메인·점진 검증 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 일정 압박에 따른 강행 | 개통 전 판정기준과 결정 권한 승인 |
| 리허설과 운영환경 차이 | 운영 규모·순서·권한을 리허설에 재현 |
| 판정 증적 분산 | 통합 상황판과 단일 승인기록으로 판단 근거 보존 |
| 롤백 시간 부족 | 복구시간을 역산해 중단시점 설정 |
| 데이터 누락·불일치 | 건수·금액·참조무결성 대사 |
| 성능 저하·연계 단절 | 업무량 기반 부하 시험과 E2E 합동 시험 |
| 업무 절차 혼선 | 사용자 리허설과 비상업무 절차 마련 |
| 복구 실패 | 백업 복원·Rollback 리허설로 실행성 확인 |

## Ⅵ. 제언

- 개통 판정 전에 최신 거래의 복구 반영 방식과 원복 한계시각을 확정하고, 현업·기술 책임자가 같은 판정서에 승인
