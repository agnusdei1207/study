## 연관 키워드

- 프로그래머블 머니(Programmable Money), 스마트 컨트랙트(Smart Contract), AI 에이전트 결제
- CBDC(Central Bank Digital Currency, 중앙은행 디지털화폐), 스테이블코인(Stablecoin)
- M2M(Machine-to-Machine, 기계 간 거래), 마이크로 결제(Micro-payment), 프롬프트 주입(Prompt Injection)
- AML(Anti-Money Laundering, 자금세탁방지), KYC(Know Your Customer, 고객확인), DID(Decentralized Identifier, 탈중앙화 신원증명)
- 서킷 브레이커(Circuit Breaker), 멀티시그(Multi-Signature)

## Ⅰ. Programmable Money·AI Agent 결제의 개요

- 핵심 요약 : 화폐에 조건을 내장해 자동 집행하고, AI 에이전트가 사람의 건별 승인 없이 결제하는 차세대 디지털 금융 체계.
- 개념 : 화폐에 목적·기한·대상 같은 조건을 넣어 조건이 충족될 때만 집행되는 **프로그래머블 머니** (Programmable Money)와, 위임받은 한도 안에서 스스로 구매·결제를 수행하는 **AI** (Artificial Intelligence) 에이전트 결제를 결합한 금융 체계. 집행 조건은 **스마트 컨트랙트** (Smart Contract, 조건이 충족되면 자동 실행되는 프로그램 코드)로 구현된다.
- 배경 및 필요성 : 기존 카드·계좌이체 인프라는 건당 처리 비용과 사람의 승인 절차를 전제로 하므로, 기계 간 거래(M2M, Machine-to-Machine)처럼 소액·초단위로 반복되는 거래의 비용을 감당하기 어렵다. 이 비용을 줄이기 위해 화폐 자체가 조건을 집행하는 방식과 AI 에이전트의 자율 결제가 제기되었다. 2025년 이후 Google의 AP2(Agent Payments Protocol)와 Coinbase의 x402처럼 에이전트 결제 프로토콜이 공개되며 실험이 시작되었다. 국내에서는 한국은행이 **CBDC** (Central Bank Digital Currency, 중앙은행 디지털화폐)의 발행 시점을 정하지 않은 채 상업은행 예금토큰을 활용한 결제 실험(프로젝트 한강)을 진행 중이며, 1단계(2025년 4~6월)에는 7개 은행과 가맹점 1만 2천 곳에서 114,880건의 거래가 처리되었다.
- 주요 목적 : 소액 자동 결제 실현, 자금 사용 목적의 투명한 통제, 중개 비용을 줄인 실시간 정산.

## Ⅱ. Programmable Money·AI Agent 결제의 특징 및 장점

- 핵심 요약 : 화폐 내장 조건 집행과 에이전트 자율 결제가 결합되어 무인·초단위·실시간 정산이 가능한 금융 체계.

1. 조건부 집행 : 목적·기한·대상이 충족될 때만 지급 → 목적 외 자금 사용 억제.
2. 에이전트 자율 결제 : 위임된 한도와 권한 안에서 거래를 실행 → 기계 간 정산 자동화.
3. 마이크로 결제 : 소액·빈번한 API 이용료를 건별로 정산 → 중개 비용 부담 완화.
4. 거래 이력 추적 : 검증 가능한 기록을 남김 → 자금 흐름의 감사 가능성 향상.
5. 조건 미충족 처리 : 지급 보류와 환불 규칙을 사전에 정의 → 거래 상대방의 이행 위험 축소.

## Ⅲ. Programmable Money·AI Agent 결제의 구조 (흐름)

- 핵심 요약 : 구매 에이전트의 결제 의도가 스마트 컨트랙트 검증과 화폐 정산을 거쳐 판매 에이전트의 자원 개방으로 이어지는 흐름과, 이를 감싸는 가드레일 구조.
- **스테이블코인** (Stablecoin) : 법정화폐 등 특정 자산에 가치를 연동해 가격 변동을 줄인 디지털 화폐.
- **서킷 브레이커** (Circuit Breaker) : 이상 거래가 감지되면 자동 결제를 중단시키는 차단 장치.
- **멀티시그** (Multi-Signature) : 여러 서명 주체의 승인이 모여야 거래를 집행하는 방식.

```text
[구매자 AI 에이전트]
  시장 탐색, 서비스 선정
  결제 의도에 디지털 서명
      ↓
[스마트 컨트랙트 계층]
  조건 검증 : 데이터 수신과
  무결성 해시 일치 확인
      ↓ 조건 충족 시
[프로그래머블 화폐 인프라]
  CBDC 분산원장, 예금토큰,
  스테이블코인 지갑
      ↓ 자율 정산
[판매자 AI 에이전트]
  토큰 수령 확인 후 API 접근 허용
```

```text
[자금 안전 가드레일]
  일일 결제 한도 설정
      ↓
  고액 거래 : 멀티시그 승인
      ↓
  이상 거래 감지
     ├─ 자금 동결
     └─ 서킷 브레이커 발동 (결제 중단)
```

## Ⅳ. 전통적 전자화폐와 프로그래머블 머니의 비교

- 핵심 요약 : 중앙 서버 승인에 기대는 전통적 전자화폐와 화폐 내장 조건에 기대는 프로그래머블 머니의 차이.

| 비교 항목 | 전통적 전자화폐 (카드·간편결제·계좌이체) | 프로그래머블 머니 (CBDC·토큰화 예금) |
| --- | --- | --- |
| 통제 주체 | 중앙 서버와 금융사 승인 시스템 | 화폐 토큰에 내장된 스마트 컨트랙트 |
| 조건부 집행 | 외부 애플리케이션 로직으로 간접 구현 | 토큰에 목적·기한·대상을 직접 설정 |
| 결제 단위 | 건당 처리 비용 때문에 초소액 결제에 부담 | 소수점 단위 초소액 결제 설계 가능 |
| 거래 주체 | 사람의 인증(인증서, 생체인증) 중심 | 개인키를 가진 AI 에이전트·기계 포함 |

## Ⅴ. Programmable Money·AI Agent 결제의 한계와 방안

- 핵심 요약 : 무단 결제, 코드 결함, 책임 주체 불명확성을 거래 설계 단계에서 통제해야 한다.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 무단 결제 | 프롬프트 주입(Prompt Injection)이나 판단 오류로 위임 범위를 벗어난 결제 | 거래·일일 한도 설정, 고액 거래의 사람 승인, 서킷 브레이커 적용 | 한도 초과 시도 건수 |
| 스마트 컨트랙트 취약점 | 자동 집행 구조라 코드 결함이 곧 자금 손실로 이어짐 | 배포 전 코드 감사와 형식 검증, 긴급 중지·복구 절차 마련 | 감사 지적 건수, 중지 대응 시간 |
| 책임 주체 불명확 | 에이전트 거래에서 실소유자와 위임 관계 확인이 어려움 | 에이전트를 위임자 신원과 연결하고 KYC(Know Your Customer, 고객확인)·AML(Anti-Money Laundering, 자금세탁방지) 점검 및 감사 기록 유지 | 미식별 거래 비율 |

## Ⅵ. 안전한 AI 에이전트 결제 안착을 위한 기술사적 제언

- 핵심 요약 : 법제도, 신원 체계, 코드 검증의 세 축을 함께 정비해 자율 결제를 통제 가능한 인프라로 전환.

- 법제도 측면에서는 에이전트가 집행한 결제의 법적 주체와 책임 범위를 디지털자산 법제 논의에 포함하고, 금융당국의 규제 샌드박스를 통해 단계적으로 도입하는 방향이 필요하다. 국내 디지털자산 기본법은 2026년 9월 말 보도 기준 국회 심의 단계로 확인되므로, 이 논의에 에이전트 결제 조항을 반영할 시점이다.
- 신원 측면에서는 에이전트를 위임자의 신원에 연결하는 **DID** (Decentralized Identifier, 탈중앙화 신원증명) 기반 위임 체계를 표준화해야 사고 발생 시 책임 추적이 가능해진다.
- 검증 측면에서는 스마트 컨트랙트 감사를 배포 전 의무 절차로 두고, 사고 사례를 업계가 공유하는 체계를 마련해야 집행 코드의 결함이 대규모 손실로 번지는 것을 막을 수 있다.

## Ⅶ. 결론

- 핵심 요약 : 프로그래머블 머니와 AI 에이전트 결제는 조건 집행과 자율 결제를 결합한 금융 인프라이며, 위임 권한과 법적 책임의 설계가 확산의 관건.
- 시사점 : 자율 결제는 편의성보다 통제 가능성으로 평가해야 하며, 실험 결과와 사고 사례를 근거로 단계적으로 확산하는 것이 바람직하다.
