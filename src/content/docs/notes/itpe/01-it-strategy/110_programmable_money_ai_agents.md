## 30초 인출

- 본질: Programmable Money·AI Agent 결제는 코드로 정한 조건에 따라 결제를 자동 실행하고, AI 에이전트가 사용자에게 위임받은 한도 안에서 대신 결제하는 지급 방식
- 메커니즘: 사용자가 목적·한도·기간을 서명된 위임 기록(Mandate)으로 남기고, 결제 서비스가 에이전트의 결제 요청을 그 위임 범위와 대조해 승인·거부
- 통찰: 위임 근거 없는 에이전트 거래는 책임을 가릴 수 없으므로 서명된 위임 기록과 한도 밖 거래의 사람 승인

<summary>핵심 용어</summary>

- **Programmable Money·AI Agent 결제** : 조건부 결제 자동 실행과 사용자가 위임한 한도 안의 AI 에이전트 대리 결제를 결합한 지급 방식
- **Programmable Money** : 사용처·기간·상대방 같은 사용 조건을 화폐 자체에 붙인 디지털 화폐. 사용처가 제한된 바우처가 대표 예
- **Programmable Payment(조건부 결제)** : 화폐는 범용으로 두고 배송 확인 같은 조건이 충족될 때 결제 지시를 자동 실행하는 방식
- **AI Agent(Artificial Intelligence Agent)** : 사용자 목표를 받아 도구를 선택·호출하며 주어진 권한 안에서 여러 작업을 수행하는 소프트웨어
- **Mandate(위임 기록)** : 사용자가 에이전트에게 허용한 구매 의도·장바구니·결제 범위를 전자서명으로 남긴 증빙
- **AP2(Agent Payments Protocol)** : 의도·장바구니·결제 위임을 서명된 기록으로 연결해 에이전트 결제를 검증하게 하는 공개 결제 프로토콜
- **PSP(Payment Service Provider)** : 이용자·가맹점에 결제 승인·정산 서비스를 제공하는 결제 서비스 사업자

## 2~4교시 25점 답안

## Ⅰ. Programmable Money·AI Agent 결제의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **Programmable Money·AI Agent 결제** 는 코드로 정한 조건의 결제 자동 실행과 사용자가 위임한 한도 안의 AI 에이전트 대리 결제를 결합한 지급 방식 |
| 목적 | 반복·조건부 거래의 자동화와 대리 결제의 사용자 의도 일치 보장 |

## Ⅱ. 사람이 직접 하는 결제와 구별되는 AI Agent 결제의 특징

| 특징 | 의미 |
|---|---|
| 조건 기반 실행 | 배송 확인·금액 한도 같은 조건 충족 시 결제 지시의 자동 실행 |
| 제한적 권한 위임 | 사용자가 정한 목적·금액·수취인·기간 범위 안의 결제 |
| 사람 부재 거래 | 결제 순간에 사용자가 화면 앞에 없는 상태의 거래 발생 |
| 검증 가능한 기록 | 위임·주문·결제를 잇는 서명 기록으로 사후 책임 판단 |

## Ⅲ. AI Agent 결제 구조와 위임 대조 절차

### AI Agent 결제 참여자 구조

```text
AI Agent 결제 구조
    │
    ├─ 사용자 ── 목적·한도·기간 위임과 회수
    │
    ├─ AI Agent ── 상품 탐색·주문 구성·결제 요청
    │
    ├─ 가맹점 ── 주문 내역·가격 확정
    │
    └─ 결제 서비스(PSP) ── 위임 대조·인증·승인·정산
```

### 결제 서비스 확대: 위임 대조와 승인 절차

```text
사용자의 구매 의도 위임 서명
    ↓
에이전트의 주문 구성과 가맹점의 가격 확정
    ↓
결제 서비스의 위임 범위 대조
    ├─ 범위 이내 → 결제 실행·결과 기록
    ├─ 범위 초과 → 사용자 직접 승인 요청
    └─ 위임 없음·회수 → 결제 거부·사유 기록
```

**AP2** 는 구매 의도(Intent)·장바구니(Cart)·결제(Payment) 위임을 각각 서명된 **Mandate** 로 연결하는 공개 프로토콜 사례

## Ⅳ. Programmable Money와 Programmable Payment의 비교

| 구분 | **Programmable Money** | **Programmable Payment** |
|---|---|---|
| 조건이 붙는 대상 | 화폐 자체의 사용처·기간·상대방 | 결제 지시의 실행 조건 |
| 대표 예 | 사용처·기간이 제한된 바우처 | 배송 확인 후 대금 지급 |
| 화폐의 범용성 | 정한 범위 안에서만 사용 | 범용 화폐 유지, 실행 시점만 조건 |
| AI Agent 결제와의 관계 | 해당 화폐를 받는 곳만 거래 가능 | 위임 한도·조건을 결제 지시 단계에서 적용 |

## Ⅴ. AI Agent 결제의 한계와 방안

| 한계 | 방안 |
|---|---|
| 에이전트의 사용자 의도와 다른 상품·금액 선택 | 금액·수취인·품목 범위의 위임 서명과 결제 서비스의 범위 대조 |
| 위임 근거 부재로 오결제 책임 판단 곤란 | 의도·주문·결제 위임을 잇는 서명 기록의 보관 |
| 에이전트 자격정보 탈취에 따른 무단 결제 | 거래별 일회성 결제 토큰과 위임의 즉시 회수 수단 |
| 조건부 결제의 조건 충족 여부 분쟁 | 배송 확인 등 조건 판정 주체와 환급 절차의 사전 합의 |
| 사람 부재 상태의 반복 결제 오류 | 건별·누적 한도 설정과 한도 초과 시 사람 승인 전환 |

## Ⅵ. 제언

시범 적용 단계부터 결제 서비스에 서명된 위임 기록의 대조와 한도 밖 거래의 사람 승인 전환 기준을 함께 적용

### 위임 한도 관리 책임 구조

```text
위임 한도 관리
    │
    ├─ 사용자 ── 금액·수취인·기간 설정과 회수
    │
    ├─ 에이전트 운영자 ── 위임 범위 안의 요청만 생성
    │
    └─ 결제 서비스 ── 위임 대조·사람 승인 전환·기록
```

### 결제 서비스 역할 확대: 사람 승인 전환 판정

```text
에이전트 결제 요청 접수
    ↓
건별·누적 한도와 승인된 수취인 목록 대조
    ├─ 모두 충족 → 자동 결제와 위임 기록 연결
    └─ 하나라도 초과 → 사용자 직접 승인 후 기록
```

### 선택 근거: 결제수단 전체 위임과의 비교

| 구분 | 결제수단 전체 위임 | 제언: 한도 기반 위임 |
|---|---|---|
| 에이전트 권한 | 저장된 결제수단 전체 사용 | 금액·수취인·기간 안의 결제 |
| 한도 초과 거래 | 결제 후 발견 | 결제 전 사람 승인 |
| 분쟁 시 근거 | 에이전트 내부 로그 | 사용자가 서명한 위임 기록 |
| 권한 회수 | 결제수단 해지 | 위임 단위 즉시 회수 |
