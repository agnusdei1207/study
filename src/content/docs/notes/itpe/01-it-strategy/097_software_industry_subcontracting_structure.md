## 지식 로드맵 내 현재 위치

IT 전략·관리 → 공공 SW 사업 관리 → **공공 소프트웨어(SW) 사업 하도급 제한**

## 30초 인출

- 본질: 국가기관등과 계약한 소프트웨어사업자가 사업금액의 절반을 넘겨 하도급하거나 다단계로 다시 하도급하지 못하게 정한 소프트웨어 진흥법 제51조의 제도
- 메커니즘: 물품 구매금액을 뺀 사업금액의 50% 이내로 하도급하고, 예외 사업이 아니면 초과할 수 없으며, 재하도급은 법정 사유에서 한 번만 허용하고, 하도급·재하도급 전에 국가기관등의 승인
- 통찰: 승인은 계약서안과 수행 계획서로 이루어져 승인 뒤의 실제 수행 주체를 확인하기 어려우므로 승인받은 사업자에게 준수 실태 보고서를 요청해 승인 계획과 대조

<details>
<summary>핵심 용어</summary>

- **공공 소프트웨어(SW) 사업 하도급 제한** : 국가기관등이 발주하는 SW 사업의 하도급 비율·단계를 제한하고 사전 승인을 받게 한 소프트웨어 진흥법상 제도
- **국가기관등** : 국가기관, 지방자치단체, 국가·지방자치단체가 투자하거나 출연한 법인·단체 등으로서 대통령령으로 정하는 기관. 소프트웨어 진흥법의 사업 발주 주체
- **하도급** : 도급받은 소프트웨어사업을 다시 도급하려고 수급인이 다른 소프트웨어사업자와 체결하는 계약
- **수급인·하수급인** : 발주자로부터 소프트웨어사업을 도급받은 소프트웨어사업자와, 수급인으로부터 하도급받은 소프트웨어사업자
- **재하도급** : 하도급받은 소프트웨어사업자가 그 사업을 다시 하도급하는 것. 시행규칙이 붙인 명칭이며 법은 `다시 하도급`으로 표현
- **물품** : 상용소프트웨어를 포함한 구매 대상. 하도급 비율의 분모에서 구매금액을 제외
- **공동수급체** : 입찰자와 하수급인이 함께 입찰에 참여하는 형태. 국가기관등이 하도급 비율이 일정 이상일 때 참여를 요구할 수 있는 방식

## 2~4교시 25점 답안

## Ⅰ. 공공 SW 사업 하도급 제한의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **공공 소프트웨어(SW) 사업 하도급 제한** 은 국가기관등이 발주하는 SW 사업의 하도급 비율·단계를 제한하고 사전 승인을 받게 한 소프트웨어 진흥법상 제도 |
| 목적 | 하도급 비율 상한과 다단계 재하도급 금지를 통한 하도급 구조의 통제 |

## Ⅱ. 비율·단계·승인으로 하도급을 통제하는 제한의 특징

| 특징 | 의미 |
|---|---|
| 비율 상한 | 물품 구매금액을 제외한 SW 사업금액의 100분의 50 초과 하도급 금지 |
| 예외 사업 | 물품 설치·유지관리, 신기술·전문기술 사업은 초과 허용, 사업 전부의 하도급은 불가 |
| 단계 제한 | 하도급받은 사업자의 재하도급은 법정 사유에서만 허용, 재하도급받은 사업자의 추가 하도급 금지 |
| 사전 승인 | 하도급·재하도급 전 국가기관등의 장의 승인 |
| 관리·감독 의무 | 국가기관등의 장이 준수 여부를 지속 관리하고 위반 시 시정 요구 |

## Ⅲ. 하도급 단계 체계와 하도급 비율 판정

### 하도급 단계별 제한 체계

```text
국가기관등
    ↓ 도급
수급인 ─ 하도급: 물품 구매금액 제외 사업금액의 50% 이내 (사전 승인)
    ↓
하수급인 ─ 재하도급: 법정 사유에서만, 받은 금액의 50% 이내 (사전 승인)
    ↓
재하도급받은 사업자 ─ 추가 하도급 금지
```

### 하도급 비율 확대: 50% 초과 시 예외 판정

```text
하도급 비율 = 하도급 금액 ÷ (SW 사업금액 − 물품 구매금액)
    ├─ 50% 이하 → 사전 승인 신청
    └─ 50% 초과 → 물품 설치·유지관리 또는 시행령의 신기술·전문기술 사업인가
          ├─ 해당 없음 → 하도급 불가
          └─ 해당 → 그 사업의 하도급 허용, 사업 전부의 하도급은 불가
```

## Ⅳ. 하도급·재하도급·추가 하도급의 단계별 비교

| 구분 | 하도급 | 재하도급 | 추가 하도급 |
|---|---|---|---|
| 주체 | 수급인 | 하도급받은 사업자 | 재하도급받은 사업자 |
| 허용 | 원칙적 허용 | 원칙 금지, 법정 사유만 허용 | 금지 |
| 사유 | 제한 없음 | 신기술·전문기술이 필요한 경우, 상용소프트웨어 유지·관리의 기술 지원이 불가피한 경우 | 해당 없음 |
| 금액 한도 | 물품 제외 사업금액의 50% | 하도급받은 소프트웨어사업금액의 50% | 해당 없음 |
| 승인 | 사전 승인 | 사전 승인 | 해당 없음 |

## Ⅴ. 하도급 제한 운영의 한계와 방안

| 한계 | 방안 |
|---|---|
| 하도급 비율이 물품 구매금액의 구분에 따라 달라져 산정 근거가 모호 | 승인 신청 때 제출하는 하도급 금액 산출 명세서와 물품 구매 내역의 대조 |
| 예외 사업의 50% 초과 허용을 일반 허용으로 오해 | 신청서에 해당 예외 사업을 밝히고 사업 전부의 하도급 여부 확인 |
| 승인받은 하도급의 실제 수행이 승인 계획과 다름 | 승인받은 사업자에게 준수 실태 보고서를 요청해 대조하고 위반 시 시정 요구 |
| 발주기관이 하수급인을 계약 밖에서 파악하기 어려움 | 하도급 비율이 100분의 10 이상이면 입찰공고 때 공동수급체 참여 요구 |

## Ⅵ. 제언

승인 때 제출한 수행 계획서와 금액 명세서를 기준으로 착수 뒤 준수 실태 보고서를 요청해 대조하고, 불일치는 시정 요구로 연결

### 승인 계획과 이행의 대조 구조

```text
승인 시 제출: 계약서안·수행 계획서·금액 명세서
    ↓ 기준으로 고정
착수 뒤 준수 실태 보고서 요청
    ↓
승인 계획과 보고 내용의 대조
    ├─ 일치 → 관리·감독 계속
    └─ 불일치 → 시정 요구
```

### 대조 확대: 보고서 대조 항목

```text
준수 실태 보고서 대조
    │
    ├─ 계약 당사자 ── 승인받은 하수급인·재하도급자와의 일치
    │
    ├─ 계약 금액 ── 하도급 금액과 50% 한도
    │
    └─ 계약서 사본 ── 승인받은 계약서안과의 일치
```

### 선택 근거: 승인 시점 중심 관리와의 비교

| 구분 | 승인 시점 중심 관리 | 제언: 승인 계획 기준의 이행 대조 |
|---|---|---|
| 확인 시점 | 승인 신청 시 1회 | 승인 이후 이행 단계 |
| 확인 대상 | 계약서안·수행 계획서 | 승인 계획과 실제 계약·금액 |
| 위반 대응 | 사후 발견 | 시정 요구로 조기 대응 |
