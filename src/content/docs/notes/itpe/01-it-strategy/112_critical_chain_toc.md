## 큰 그림과 30초 인출

```text
┌───────────────── [전통 일정의 낭비 vs CCPM 버퍼 통합] ─────────────────┐
│                                                                        │
│   [전통적 방식: 개별 숨은 버퍼 낭비]                                   │
│   - 파킨슨 법칙(일정 채우기) + 학생 증후군(막판 몰아치기) ──▶ 공기 지연│
│                                                                        │
│   [CCPM 방식: 버퍼 중앙 집중 관리]                                     │
│   - 개별 액티비티 기간 50% 공격적 추정 (안전마진 전면 회수)            │
│   - 비임계 합류 지점 ──▶ [피딩 버퍼 (FB)] : 주공정 영향 차단           │
│   - 크리티컬 체인 끝 ──▶ [프로젝트 버퍼 (PB)] : 전체 납기 보장         │
│   - 병목 자원 투입 전 ─▶ [자원 버퍼 (RB)] : 자원 대기 지연 방지       │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────── [버퍼 소진율 관리 (3-Zone Management)] ─────────────┐
│  - 녹색 (Green Zone 0~33%)  : 정상 진행, 특별 조치 불필요              │
│  - 황색 (Yellow Zone 34~66%): 위험 감지, 원인 분석 및 대응 계획 수립    │
│  - 적색 (Red Zone 67~100%)  : 비상 개입, 자원 집중 투입 및 일정 만회   │
└────────────────────────────────────────────────────────────────────────┘
```

- 본질: 골드랫(Goldratt) 박사의 제약이론(TOC)을 프로젝트 관리에 적용하여, 개별 작업에 숨겨진 안전 마진을 50% 회수하고 자원 제약(Resource Constraints)을 반영한 가장 긴 경로(Critical Chain)를 식별한 뒤, 프로젝트 끝과 합류 지점에 버퍼(Buffer)를 집중 배치해 납기를 보장하는 일정 관리 패러다임
- 위치: `WBS 수립 → 50% 공기 추정 → 자원 종속성 분석(CC 도출) → 버퍼(PB/FB/RB) 배치 → 버퍼 소진율 신호등 관리`
- 핵심: 제약이론(TOC), 파킨슨 법칙(Parkinson's Law), 학생 증후군(Student Syndrome), 3대 버퍼(프로젝트 버퍼 PB, 피딩 버퍼 FB, 자원 버퍼 RB), 버퍼 소진율 신호등 관리
- 실무: 개발자의 공격적 일정(50%) 제출 거부감 완화, 개별 마감일 제거 및 버퍼 소진율 중심의 주간 진척 회의 운영

## 예상문제

> 전통적인 임계경로법(CPM)의 한계점과 이를 극복하기 위한 골드랫 박사의 제약이론(TOC) 기반 크리티컬 체인 프로젝트 관리(CCPM, Critical Chain Project Management)의 개념, 핵심 메커니즘, 3대 버퍼(PB, FB, RB)의 역할 및 버퍼 소진율 관리 방안을 설명하시오. (10점/25점)

## 딸려 나오는 하위 토픽

| 하위 토픽 | 핵심 내용 | 본문 답안 위치 |
|---|---|---|
| **CCPM 버퍼 관리 (Buffer Management)** | 개별 안전여유를 회수하여 프로젝트 버퍼(PB), 피딩 버퍼(FB), 자원 버퍼(RB)로 통합하고 신호등(3-Zone) 통제 | Ⅱ 특징, Ⅲ 구조 |
| **인간 행동적 일정 지연 요인** | 마감일까지 시간을 채우는 파킨슨 법칙과 마감 직전에야 착수하는 학생 증후군 | Ⅰ 개요, Ⅳ 흐름 |

## Ⅰ. 인간 행동 심리와 자원 제약을 극복하는 일정 공학, CCPM의 개요

- 정의: 엘리 골드랫(Eli Goldratt)의 제약이론(TOC, Theory of Constraints)을 프로젝트 관리에 접목하여, 작업 선후행 관계뿐만 아니라 자원 제약을 함께 고려해 크리티컬 체인을 도출하고 통합 버퍼를 통해 납기를 통제하는 일정 관리 기법
- 배경: 전통 CPM 방식에서 엔지니어들이 개별 작업마다 숨겨둔 안전 마진이 파킨슨 법칙과 학생 증후군으로 인해 낭비되어 전체 프로젝트는 만성적으로 지연되는 모순 극복
- 목적: 개별 마감일(Milestone)을 없애고 50% 확률의 공격적 일정 산정, 집약된 버퍼(Buffer) 관리를 통해 전체 프로젝트 납기를 단축하고 일정 통제력 극대화

#### 한줄 요약
- 자원 제약을 고려해 크리티컬 체인을 찾고 버퍼를 통합 관리하여 납기 지연을 방지하는 TOC 기반 기법임

## Ⅱ. 전통 CPM의 3대 인간 행동 병목 및 CCPM의 해결 원리

| 인간 행동 병목 | 개념 정의 및 현상 | CCPM의 해결 메커니즘 |
|---|---|---|
| **파킨슨 법칙**<br>(Parkinson's Law) | 어떤 일에 할당된 시간이 주어지면, 실제 소요 시간과 무관하게 그 시간을 모두 소진해 버리는 경향 | 개별 작업에서 숨겨진 안전 마진을 50% 강제 회수하여 타이트한 일정 부여 |
| **학생 증후군**<br>(Student Syndrome) | 시험 전날에야 벼락치기를 시작하듯, 마감일이 임박할 때까지 작업 착수를 미루는 심리 | 개별 작업 단위의 마감일을 폐지하고 완료 즉시 후행 작업에 바통 터치(릴레이 주자 원칙) |
| **자기완결적 지연 누적**<br>(Bad Multitasking) | 여러 프로젝트를 오가며 비효율적으로 작업 전환 오버헤드를 발생시켜 모든 프로젝트가 동시 지연 | 병목 자원에 대해 한 번에 하나의 작업만 집중하도록 자원 버퍼(RB) 및 우선순위 지정 |

#### 한줄 요약
- 파킨슨 법칙, 학생 증후군, 멀티태스킹 낭비를 개별 마진 회수와 통합 버퍼로 해결함

## Ⅲ. CCPM 크리티컬 체인 구조 및 3대 버퍼 배치도

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│              [ CCPM 네트워크 아키텍처 및 3대 버퍼 배치 구조 ]               │
│                                                                             │
│   [ 비임계 경로 (Non-Critical Path) ]                                       │
│   ┌─────────────┐     ┌─────────────┐     ┌────────────────┐                │
│   │ 액티비티 B1 │ ──▶ │ 액티비티 B2 │ ──▶ │ 피딩 버퍼 (FB) │────────┐       │
│   │  (50% 일정) │     │  (50% 일정) │     │(합류 지연 차단)│        │       │
│   └─────────────┘     └─────────────┘     └────────────────┘        │       │
│                                                                     ▼       │
│   [ 크리티컬 체인 (Critical Chain) : 선후행 의존성 + 자원 제약 반영 ]       │
│   ┌─────────────┐     ┌─────────────┐     ┌─────────────┐   ┌─────────────┐ │
│   │ 액티비티 A1 │ ──▶ │ 액티비티 A2 │ ──▶ │ 액티비티 A3 │──▶│프로젝트 버퍼│ │
│   │  (50% 일정) │     │  (50% 일정) │     │  (50% 일정) │   │ (PB, 총보장)│ │
│   └─────────────┘     └─────────────┘     └─────────────┘   └──────┬──────┘ │
│          ▲                   ▲                                     │        │
│   [자원 버퍼(RB)]     [자원 버퍼(RB)]                              ▼        │
│   (사전 투입 알림)    (사전 투입 알림)                      [ 프로젝트 완성 ]│
└─────────────────────────────────────────────────────────────────────────────┘
```

| 버퍼 종류 | 영문 명칭 | 배치 위치 및 역할 | 산정 및 운영 메커니즘 |
|---|---|---|---|
| **프로젝트 버퍼** | Project Buffer (PB) | 크리티컬 체인의 맨 마지막 끝에 배치 | 프로젝트 전체 납기를 보증하며, 전체 삭감된 안전마진의 50% 수준 배정 |
| **피딩 버퍼** | Feeding Buffer (FB) | 비임계 경로가 크리티컬 체인과 합류하는 지점에 배치 | 비임계 경로의 지연이 주공정(크리티컬 체인)을 침범하지 못하도록 방어 |
| **자원 버퍼** | Resource Buffer (RB) | 크리티컬 체인 작업에 자원이 투입되기 직전 시점에 배치 | 물리적 시간이 아닌 '알림(Warning) 신호'로, 핵심 인력/장비 사전 대기 유도 |

#### 한줄 요약
- 크리티컬 체인 끝의 PB, 비임계 합류점의 FB, 자원 사전 알림인 RB로 안전망을 구축함

## Ⅳ. CCPM 일정 수립 및 버퍼 관리 프로세스

```text
[1단계: 50% 추정] ──→ [2단계: 자원 평준화] ──→ [3단계: CC 및 버퍼 배치] ──→ [4단계: 신호등 통제]
- 개별 안전마진 회수   - 자원 경합 제거        - 주공정(CC) 확정          - 주간 버퍼 소진율 측정
- 성공 확률 50% 공기   - 자원 제약 반영        - PB, FB, RB 크기 산출     - 3-Zone 신호등 조치
```

| 단계 | 주요 활동 내용 | 적용 기법 및 관리 기준 |
|---|---|---|
| **1. 공격적 공기 산정** | 기존 80~90% 보증 일정을 50% 확률의 공격적 일정으로 단축 추정 | 50% Cut 법칙 |
| **2. 자원 종속성 분석** | 복수 작업에 동일 자원이 동시 투입되는 병목을 식별하고 자원 레벨링 수행 | 자원 제약 기반 네트워크 재배치 |
| **3. 크리티컬 체인 확정** | 선후행 관계와 자원 제약을 통틀어 가장 긴 경로 식별 및 버퍼(PB, FB) 삽입 | Root Square Error Method (RSEM) 또는 Cut & Paste |
| **4. 버퍼 소진율 신호등 관리** | 진척률 대비 버퍼 소진율을 3대 구역(Green, Yellow, Red)으로 분류하여 통제 | Buffer Management 3-Color Zone |

#### 버퍼 소진율 3대 구역 (3-Zone Management)
- **녹색 구역 (Green: 버퍼 소진율 0~33%)**: 계획된 안전 범위 내 진행, 조치 불필요
- **황색 구역 (Yellow: 버퍼 소진율 34~66%)**: 잠재 위험 경고, 지연 원인 분석 및 비상 대응책 마련
- **적색 구역 (Red: 버퍼 소진율 67~100%)**: 즉시 비상 개입, 자원 집중 투입 및 크래싱(Crashing) 집행

#### 한줄 요약
- 50% 공기 산정, 자원 제약 반영, 버퍼 배치, 3-Zone 신호등 관리의 4단계로 운영됨

## Ⅴ. 전통적 임계경로법(CPM) vs 크리티컬 체인(CCPM) 비교

| 비교 항목 | 전통적 임계경로법 (CPM) | 크리티컬 체인 프로젝트 관리 (CCPM) |
|---|---|---|
| **제약 요건 고려** | 작업 간 **논리적 선후행 의존성**만 고려 | 작업 간 논리적 의존성 + **자원 가용성(제약)** 동시 고려 |
| **공기 산정 기준** | 80~90% 달성 확률 (작업자별 숨은 마진 포함) | 50% 달성 확률 (공격적 추정, 마진 회수) |
| **버퍼 관리 방식** | 개별 작업마다 여유시간(Float/Slack) 분산 | 개별 마진 회수 후 프로젝트/합류점에 **집중 버퍼(PB/FB)** 운영 |
| **진척 통제 지표** | 개별 작업 마감일 준수율, EVM (SPI, CPI) | 크리티컬 체인 진척률 대비 **버퍼 소진율(Buffer Consumption)** |
| **지연 발생 원인** | 파킨슨 법칙, 학생 증후군으로 마진 소진 | 개별 마감일 폐지로 릴레이식 신속 전달 실현 |

#### 한줄 요약
- CPM은 논리적 선후행과 개별 마진 중심이며, CCPM은 자원 제약과 중앙 집중 버퍼 중심임

## Ⅵ. 실무 고려사항 및 대책

- 적용 상황: 대규모 공공 SI 및 복수 프로젝트(Multi-Project) 자원 공유 환경

| 문제점 | 발생 원인 | 공학적·제도적 해결 대책 | 기대 효과 |
|---|---|---|---|
| **개발자의 50% 공기 단축 저항** | 일정 미준수 시 인사상 불이익을 우려하여 기존의 부풀려진 공기 고수 | "개별 마감일 미준수는 문책하지 않으며 버퍼가 흡수한다"는 심리적 안전감 조직 문화 정립 | 정직하고 공격적인 일정 산출 유도 |
| **다중 프로젝트 간 자원 경합** | 핵심 아키텍트/DBA가 복수 프로젝트에 동시 투입되어 전 프로젝트 지연 | PMO 차원의 드럼-버퍼-로프(DBR) 기법 적용 및 전사 단일 우선순위 큐 운영 | 비효율적 멀티태스킹 근절 |
| **버퍼 소진율 관리 형식화** | 진척률 보고 시 버퍼 소진 현황을 누락하고 단순 태스크 완료율만 보고 | Jira 등 PM 도구와 연계한 실시간 버퍼 소진 트렌드 차트(Fever Chart) 시각화 | 프로젝트 위험의 선제적 조기 경보 |

#### 한줄 요약
- 심리적 안전감 보장, 전사 우선순위 큐(DBR) 적용, Fever Chart 시각화로 실무 문제를 해결해야 함

## Ⅶ. 결론 및 기술사적 제언

- [핵심 통찰]: 프로젝트가 지연되는 이유는 엔지니어가 게을러서가 아니라, 개별 작업마다 숨겨둔 안전 마진이 파킨슨 법칙과 학생 증후군이라는 인간 심리에 의해 녹아내리기 때문임. CCPM은 공학적 일정 계산을 넘어 '인간의 행동 양식을 교정한 프로젝트 관리 혁명'임.
- 나라면: 개별 작업자에게 마감일을 요구하지 않고 [남은 예상 작업 시간(Remaining Duration)]만을 매일 보고받겠음. 이를 바탕으로 프로젝트 관리 대시보드에 '피버 차트(Fever Chart)'를 실시간 렌더링하여, 버퍼 소진율이 황색 구역에 진입하는 순간 즉각 서브 엔지니어를 투입하는 '동적 버퍼 가드레일 체계'를 현장에 정착시키겠음.

#### 한줄 요약
- 남은 작업 시간 추적과 피버 차트 실시간 관리를 통해 납기 준수율을 획기적으로 개선해야 함

## 1교시 10점 답안 발췌

### 1. 정의 및 핵심 개념
- CCPM(Critical Chain Project Management)은 골드랫 박사의 제약이론(TOC)을 기반으로 자원 제약을 반영한 크리티컬 체인을 식별하고, 개별 안전마진을 회수하여 프로젝트 버퍼(PB)와 피딩 버퍼(FB)로 집중 관리하는 일정 통제 기법임.

### 2. 핵심 메커니즘 / 체계
```text
[50% 공격적 공기] ──▶ [자원 제약 반영 크리티컬 체인] ──▶ [3대 버퍼: PB / FB / RB] ──▶ [3-Zone 신호등 통제]
```
- 파킨슨 법칙과 학생 증후군을 차단하고, 버퍼 소진율(녹/황/적)을 바탕으로 선제적 프로젝트 통제를 집행함.

### 3. 차별화 제언
- 개별 마감일 문책을 폐지하여 릴레이식 개발 문화를 안착시키고, 전사 PMO 차원에서 드럼-버퍼-로프(DBR) 기반의 멀티 프로젝트 자원 병목 통제를 병행해야 함.
