## 연관 키워드

- CCPM(Critical Chain Project Management, 크리티컬 체인 프로젝트 관리), TOC(Theory of Constraints, 제약이론), 골드랫(Goldratt)
- CPM(Critical Path Method, 주공정법), PERT(Program Evaluation and Review Technique), 파킨슨의 법칙(Parkinson's Law), 학생 증후군(Student Syndrome)
- 프로젝트 버퍼(PB, Project Buffer), 피딩 버퍼(FB, Feeding Buffer), 자원 버퍼(RB, Resource Buffer)
- 버퍼 관리(Buffer Management), 피버 차트(Fever Chart), EVM(Earned Value Management, 획득가치 관리)
- SV(Schedule Variance), SPI(Schedule Performance Index), 멀티태스킹(Multitasking)

## Ⅰ. CCPM·TOC의 개요

- 핵심 요약 : 제약이론(TOC)을 일정 관리에 적용해 자원 제약을 반영하고, 안전 여유를 버퍼로 모아 관리하는 프로젝트 일정 기법.
- 개념 : 골드랫(Goldratt)의 제약이론(TOC, Theory of Constraints)을 프로젝트 일정 관리에 적용한 **크리티컬 체인 프로젝트 관리** (CCPM, Critical Chain Project Management). 작업 간 논리 관계와 자원 제약을 함께 고려해 가장 긴 제약 경로인 크리티컬 체인을 찾고, 개별 작업에 숨어 있던 안전 여유를 떼어내 프로젝트 말단과 합류 지점의 버퍼에 모아 관리한다.
- 배경 및 필요성 : 작업마다 안전 시간을 두는 CPM(Critical Path Method, 주공정법)과 PERT(Program Evaluation and Review Technique) 방식에서도 프로젝트가 자주 지연된다. 작업에 주어진 시간만큼 업무가 늘어나는 파킨슨의 법칙과, 마감 직전까지 시작을 미루는 학생 증후군이 여유를 흡수하기 때문이므로, 여유를 개별 작업에서 떼어 집중 관리할 방법이 필요해졌다.
- 주요 목적 : 프로젝트 납기 단축, 자원 충돌 방지, 버퍼 소진 추이에 따른 조기 지연 경보.

## Ⅱ. CCPM·TOC의 특징 및 장점

- 핵심 요약 : 자원 제약을 반영한 크리티컬 체인 설정, 안전 여유의 버퍼 집중, 인간 행동 편향의 보정이 결합된 일정 관리 방식.

1. 자원 제약 반영 : 작업 선후관계와 핵심 인력의 가용 시점을 함께 고려 → 자원 충돌로 인한 대기 감소.
2. 크리티컬 체인 식별 : 자원 의존성을 포함한 가장 긴 제약 경로를 찾아 관리 대상을 집중 → 납기에 영향을 주는 작업 우선 관리.
3. 프로젝트 버퍼(PB, Project Buffer) : 떼어낸 안전 여유를 프로젝트 끝에 모아 배치 → 전체 납기 보호.
4. 조기 인계 : 작업이 끝나면 즉시 다음 단계로 넘겨 여유 낭비를 막음 → 학생 증후군과 파킨슨의 법칙 영향 축소.
5. 버퍼 소진율 관리 : 진척 대비 남은 버퍼를 관찰 → 지연 징후에 대한 조기 대응.

## Ⅲ. CCPM·TOC의 구조 (흐름)

- 핵심 요약 : 안전 여유를 버퍼로 옮기고 크리티컬 체인을 식별한 뒤, 버퍼 소진율로 진척을 감시하는 흐름.
- **피딩 버퍼** (FB, Feeding Buffer) : 비주공정 경로가 크리티컬 체인과 합류하는 지점에 두는 버퍼.
- **자원 버퍼** (RB, Resource Buffer) : 핵심 자원이 다음 작업에 투입되기 전 확보 시점을 보장하는 버퍼.
- 파킨슨의 법칙(Parkinson's Law) : 작업에 주어진 시간만큼 업무가 늘어나는 현상.
- 학생 증후군(Student Syndrome) : 마감 직전까지 작업 착수를 미루는 행동 경향.

```text
[전통적 방식 : 여유의 분산과 낭비]
  작업마다 안전 여유를 개별 보유
          ↓
  파킨슨의 법칙, 학생 증후군
          ↓
  여유 흡수 후 프로젝트 지연
```

```text
[CCPM 방식 : 여유의 집중]
  작업 기간을 공격적으로 추정
          ↓
  깎아낸 여유를 모아 버퍼로 집중
     ├─ 프로젝트 버퍼 : 프로젝트 끝
     ├─ 피딩 버퍼 : 비주공정 합류 지점
     └─ 자원 버퍼 : 핵심 자원 경합 지점
```

```text
[버퍼 관리 모니터링]
  버퍼 소진율 측정
     ├─ 녹색 : 안전, 관리 유지
     ├─ 황색 : 주시, 대책 수립
     └─ 적색 : 즉각 시정 조치
          ↓
  피버 차트로 진척률과 함께 추적
```

## Ⅳ. CPM과 CCPM의 비교

- 핵심 요약 : 논리 의존관계만 고려하는 CPM과 자원 제약 및 버퍼 관리를 결합한 CCPM의 비교.

| 비교 항목 | CPM (Critical Path Method) | CCPM (Critical Chain Project Management) |
| --- | --- | --- |
| 경로 결정 기준 | 작업 간 논리적 선후 관계만 고려 | 선후 관계와 한정된 인적·물적 자원 제약을 함께 고려 |
| 안전 여유 | 각 작업에 분산 배치 | 작업에서 떼어내 프로젝트·피딩 버퍼로 통합 |
| 진척 관리 지표 | 계획 대비 완료율, EVM(Earned Value Management)의 SV(Schedule Variance)·SPI(Schedule Performance Index) | 버퍼 소진율과 공정 진척률의 대비 |
| 착수 방식 | 여유 시점 직전까지 시작을 늦추는 경향 | 선행 작업이 끝나면 즉시 착수 |

## Ⅴ. CCPM·TOC 적용의 한계와 방안

- 핵심 요약 : 버퍼에 대한 신뢰, 병목 자원의 경합, 잦은 요구 변경을 함께 관리해야 일정 예측력이 유지된다.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 개인 압박으로 인식 | 여유 제거가 개인 마감 압박으로 받아들여짐 | 버퍼를 팀 공동 자산으로 설명하고 전체 흐름으로 평가 | 버퍼 소진율 |
| 병목 자원 충돌 | 여러 프로젝트가 같은 핵심 인력을 요구 | 포트폴리오 단위 우선순위 설정, 병목 인력의 동시 작업 제한 | 자원 대기 시간 |
| 잦은 요구 변경 | 변경이 계획한 버퍼를 조기에 소진시킴 | 변경 영향에 따라 체인을 재산정하고 피버 차트로 감시 | 변경 건수, 버퍼 소진 속도 |

## Ⅵ. CCPM 버퍼 관리의 실무 적용을 위한 기술사적 제언

- 핵심 요약 : 버퍼 신호 체계, 멀티태스킹 제한, 비난 없는 문화의 세 요소로 CCPM을 조직 운영 방식으로 정착.

- 버퍼 소진율을 녹색, 황색, 적색의 3단계 신호로 나누어 운영하고, 황색 단계에서 대책을 수립하는 절차를 미리 정해 두는 것이 실무에서 유효하다.
- 여러 프로젝트에 인력을 나누어 배정하면 컨텍스트 스위칭 낭비가 커지므로, 핵심 인력은 단일 과업에 집중하도록 멀티태스킹을 제한하는 정책이 필요하다.
- 공격적 추정으로 개별 작업이 기한을 넘더라도 개인을 문책하지 않고 전체 버퍼 소진으로 평가하는 비난 없는 문화(Blameless Culture)가 있어야 한다. 이를 뒷받침하려면 **심리적 안전성** (psychological safety)을 팀 운영 기준으로 삼는 것이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : CCPM은 자원 제약을 반영하고 안전 여유를 버퍼로 집중 관리해 프로젝트 납기를 단축하는 기법이며, 조직 문화의 정착이 관건.
- 버퍼 신호 체계와 멀티태스킹 제한을 실무에 정착시키려면 개인 평가 방식과 팀 신뢰가 함께 바뀌어야 한다.
