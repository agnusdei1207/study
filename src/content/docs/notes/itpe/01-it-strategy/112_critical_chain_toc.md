## 지식 로드맵 내 현재 위치

IT 전략·관리 → 프로젝트 일정관리 → **CCPM·TOC**

## 30초 인출

- 본질: CCPM(Critical Chain Project Management)은 TOC(Theory of Constraints)를 프로젝트 관리에 적용해 자원 제약을 반영한 일정과 통합 버퍼로 납기를 지키는 기법
- 메커니즘: 자원 제약을 반영한 크리티컬 체인의 작업 추정에서 여유를 덜어내 프로젝트 버퍼로 모으고, 비크리티컬 작업이 합류하는 지점에 합류 버퍼를 두며, 버퍼 소진량으로 진행 상태를 판단
- 통찰: 작업별 여유를 없애면 지연이 버퍼 소진으로만 드러나므로, 남은 작업량 대비 남은 버퍼로 판정하는 소진 구간별 조치를 착수 전에 정의

<details>
<summary>핵심 용어</summary>

- **TOC(Theory of Constraints)** : 시스템의 성과를 제한하는 제약을 찾아 그 제약에 초점을 맞춰 개선하는 이론이며 Goldratt가 제시
- **제약(Constraint)** : 시스템이 목표 대비 더 높은 성과를 내지 못하게 막는 모든 것
- **CCPM(Critical Chain Project Management)** : TOC를 프로젝트 관리에 적용한 기법이며 Goldratt(1997)가 처음 소개
- **크리티컬 체인(Critical chain)** : 자원 제약을 반영해 평준화한 크리티컬 패스
- **프로젝트 버퍼(Project buffer)** : 크리티컬 체인 작업에서 덜어낸 여유의 일부를 프로젝트 일정 끝에 모은 통합 여유이며 납기 약속을 보호
- **합류 버퍼(Feeding buffer)** : 비크리티컬 작업 사슬이 크리티컬 체인의 작업에 합류하는 지점에 두는 집중 여유
- **자원 버퍼(Resource buffer)** : 크리티컬 체인 작업을 시작할 때 자원이 준비되도록 하는 알림·우선순위 조정이며 일정에 시간을 추가하지 않는 장치
- **50/50 추정** : 50% 확률로 일찍, 50% 확률로 늦게 끝나는 작업 기간 추정이며 전통적 95% 확률 추정의 절반 정도
- **학생 증후군(Student syndrome)·파킨슨 법칙(Parkinson's Law)** : 마지막 순간까지 착수를 미루는 경향과, 주어진 시간만큼 작업이 늘어나는 경향이며 개별 작업의 여유를 낭비시킴
- **버퍼 소진 차트(Buffer consumption chart)** : 남은 작업일수와 남은 버퍼를 비교해 프로젝트의 정시 완료 가능성을 녹·황·적 구간으로 보여 주는 지표

</details>

## 2~4교시 25점 답안

## Ⅰ. CCPM·TOC의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **TOC** 를 프로젝트에 적용해 자원 제약을 반영한 **크리티컬 체인** 과 통합 **버퍼** 로 일정 불확실성을 관리하는 **CCPM** |
| 목적 | 프로젝트 납기 준수율 향상과 기간 단축 |

## Ⅱ. 프로젝트 납기를 지키는 CCPM의 특징

| 특징 | 의미 |
|---|---|
| 자원 제약 반영 | 자원 평준화 뒤의 크리티컬 체인을 일정의 중심으로 관리 |
| 여유의 통합 | 개별 작업의 여유를 덜어내 프로젝트 버퍼로 모아 공동 사용 |
| 납기 중심 관리 | 개별 작업의 정시 완료보다 프로젝트의 정시 완료를 중시 |
| 집중 수행 | 멀티태스킹 대신 시작한 작업의 순차적 완료, 동시 진행 프로젝트 수 제한 |
| 가시적 지표 | 버퍼 소진량으로 프로젝트 상태를 객관적으로 표시 |

## Ⅲ. TOC와 CCPM의 체계

### TOC의 5단계 집중 절차

```text
1. 시스템의 제약 식별
    ↓
2. 제약의 활용 방법 결정
    ↓
3. 나머지 모든 것을 그 결정에 종속
    ↓
4. 제약의 격상
    ↓
5. 제약이 해소되면 1단계로 복귀 (관성이 새로운 제약이 되지 않도록 주의)
```

### CCPM 일정 구조 확대: 세 종류의 버퍼

```text
크리티컬 체인:   [작업 A] ─ [작업 B] ─ [작업 C] ─ [작업 D] ─ [프로젝트 버퍼]
                                        ↑
비크리티컬 사슬: [작업 E] ─ [작업 F] ─ [합류 버퍼]

자원 버퍼: 크리티컬 체인 작업 시작 전 자원 준비 알림 (일정에 시간을 더하지 않음)
```

## Ⅳ. 전통적 일정 관리와 CCPM의 비교

| 비교축 | 전통적 일정 관리 | CCPM |
|---|---|---|
| 작업 추정 | 95% 확률의 보수적 추정 | 50/50 추정 (기간이 절반 정도) |
| 여유의 위치 | 개별 작업에 분산되어 학생 증후군·파킨슨 법칙으로 낭비 | 덜어낸 여유의 약 절반을 프로젝트 버퍼로 통합 |
| 관리 초점 | 개별 작업의 정시 완료 | 프로젝트의 정시 완료 |
| 작업 수행 | 멀티태스킹, 프로젝트를 되도록 일찍 착수 | 순차 집중, 제약 자원 부하를 고려해 프로젝트 착수 시점 조정 |
| 진행 지표 | 작업 완료 여부 | 남은 작업일수 대비 남은 버퍼 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 버퍼 소진과 이슈의 투명한 공개가 필요하지만 비난을 우려하는 조직에서 숨겨지는 이슈 | 이슈 보고를 비난 없이 다루는 신뢰 환경을 먼저 조성 |
| 개인의 약속으로 바뀌어 작업 기간이 다시 부풀려지는 50/50 추정 | 관리 지표를 작업 완료에서 프로젝트 정시 완료로 전환 |
| 지연이 버퍼 소진으로만 드러나 소진 기준과 조치가 없을 때 생기는 대응 지연 | 버퍼 소진 구간별 조치를 착수 전에 정의하고 소진 차트로 공개 |

## Ⅵ. 제언

버퍼 소진 구간(녹·황·적)별 조치를 착수 전에 정의하고 소진 차트를 이해관계자에게 상시 공개

### 버퍼 소진 관리 체계

```text
남은 작업일수 vs 남은 버퍼 측정
    ↓
소진 차트의 구간 판정
    ↓
구간별 조치 실행
    ↓
소진 원인 기록 → 다음 프로젝트의 추정·실행 개선
```

### 구간 판정 확대: 조치 분기

```text
버퍼 소진 구간
    ├─ 녹 → 계획대로 진행, 관리자의 작업자 방해 없음
    ├─ 황 → 회복 계획 수립 (실행은 보류)
    └─ 적 → 회복 계획 실행 (프로젝트 네트워크 단축 기법 포함)
```

| 구분 | 작업별 납기 관리 | 제언: 버퍼 소진 구간별 관리 |
|---|---|---|
| 지연 인지 시점 | 개별 작업의 납기 초과 시 | 소진이 황 구간에 들어설 때 |
| 조치 기준 | 관리자 판단 | 착수 전에 정한 구간별 조치 |
| 다수 프로젝트 비교 | 프로젝트별 일정표 | 프로젝트별 소진 차트를 한 화면에 |
