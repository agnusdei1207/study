## 큰 그림과 30초 인출

```text
[시설·전력·통신 단일결함]
          │
          ▼ (공통원인 전파)
[장애구역 물리 격리] → [다중센터 액티브 분산] → [자동절체·데이터 정합] → [상시 불시 훈련]
    방화구획·독립인입         GSLB·멀티클라우드         불변백업·격리복구         RTO·RPO 실증
```

- 본질: 시설 사고가 공통 플랫폼과 대국민 행정서비스로 전파되는 공통원인 장애를 차단하고, 다중센터 기반으로 무중단 연속성을 보장하는 거버넌스 체계
- 위치: `위험관리(Risk) → BCP/DRS → 다중센터 아키텍처 → 모의훈련/환류`
- 핵심: 단일 데이터센터 내 물리적 설비 이중화 한계 극복 → 서비스 단위 다중화 및 능동 복구체계로 전환
- 지표: 가용성 백분율 중심 탈피 → 실제 복구목표시간(RTO)과 데이터손실목표(RPO) 준수 여부

## 예상문제

> 국가정보자원관리원 화재 사례를 계기로 부각된 공공 디지털서비스의 장애 전파 요인을 설명하고, 시설·인프라·애플리케이션·데이터·운영 관점의 회복탄력성(Resilience) 확보 방안을 논하시오. (25점)

## Ⅰ. 설비 보호에서 대국민 서비스 연속성으로, 회복탄력성 개요

- 정의: 데이터센터의 물리적 재난(화재·수해·정전) 발생 시 시설 격리와 다중 거점을 통해 핵심 행정서비스를 중단 없이 제공하거나 허용 시간 내 복원하는 디지털 역량
- 배경: 전산실 전력·배터리 화재가 소화약제 방출, 전원 차단, 공통 연계망 마비로 이어지며 단일 거점 인프라의 취약성 노출
- 목적: 장비 생존 중심의 소극적 복구에서 탈피하여 대국민 핵심 서비스의 무중단 제공 및 데이터 정합성 보장

#### 한줄 요약
- 단순 설비 이중화가 아닌, 서비스 계층 분산과 자동 절체로 단일 거점 붕괴에 대비하는 연속성 체계임

## Ⅱ. 화재 사고가 드러낸 공통원인 장애와 취약성

| 위험 영역 | 취약 요인 | 파급 메커니즘 |
|---|---|---|
| **시설·환경** | 배터리실·전산실 간 방화격벽 미흡 | 리튬이온 배터리 열폭주가 전산실 유독가스 및 전원 차단으로 전파 |
| **인프라** | 주·예비 전원 및 통신 인입 경로의 동일 관로 공유 | 화재 발생 시 A/B 전원 계통이 동시 단절되어 무정전전원공급(UPS) 무력화 |
| **플랫폼** | 공통 인증·연계 시스템의 단일 센터 집중 배치 | 개별 업무시스템이 생존해도 공통 게이트웨이 마비로 대국민 접속 불가 |
| **데이터** | 주 센터 내 동일 상면 근거리 백업 배치 | 센터 전체 접근 통제 시 백업 소산본 확보 및 복구 작업 지연 |
| **조직·운영** | 시스템 등급별 우선순위 및 절체 권한 부재 | 재난 선포 기준과 현장 절체 명령 체계 혼선으로 골든타임 상실 |

#### 한줄 요약
- 한 지점의 물리적 파괴가 연쇄적으로 논리 서비스를 마비시키는 단일 실패점(SPOF)의 실체적 발현임

## Ⅲ. 계층별 다중센터 회복탄력성 아키텍처

```text
[대국민 서비스 채널 / 정부 행정망]
               │
               ▼
[글로벌 트래픽 제어 (GSLB / DNS 라우팅)]
        ┌──────┴──────┐ (트래픽 분산 / 헬스체크)
        ▼             ▼
  [제1 거점 센터]   [제2 거점 센터]
   ├─ 웹/WAS (Active) ├─ 웹/WAS (Active)
   ├─ 공통 인증 모듈   ├─ 독립 인증 모듈
   └─ DB (Active)     └─ DB (Standby/Active)
        │             │
        └── 동기/비동기 복제 ──┘
               │
               ▼
 [제3 소산 센터: 에어갭(Air-Gap) 격리 불변 백업]
```

| 계층 | 핵심 구성요소 | 역할 및 통제 기준 |
|---|---|---|
| **접속 계층** | Anycast DNS, GSLB | 헬스체크 기반 장애 센터 트래픽 자동 우회 및 세션 분산 |
| **애플리케이션** | 컨테이너 오케스트레이션, MSA | 거점 간 무상태(Stateless) 인스턴스 신속 배포 및 부하 분산 |
| **공통 서비스** | 분산 IAM, 인증 중계 모듈 | 중앙 센터 의존성을 탈피하여 각 거점별 독립 인증 처리 |
| **데이터 계층** | 동기식 스토리지 복제, CDC | 근거리 센터 무손실 복제(RPO=0) 및 원거리 센터 비동기 복제 |
| **보존 계층** | 불변 스토리지(WORM), 에어갭 | 화재·랜섬웨어에 오염되지 않는 물리적 격리 원격 백업 |

#### 한줄 요약
- 애플리케이션 무상태화와 데이터 원격 복제를 결합해 센터 전체 상실에도 즉시 동작하는 구조를 확립함

## Ⅳ. 예방에서 실전 환류까지의 5단계 연속성 프로세스

```text
① 영향도 분석(BIA) → ② 다중화 설계 → ③ 자동 감지·전환 → ④ 정합성 검증 → ⑤ 불시 모의훈련
   └─ 등급별 RTO/RPO    └─ 설비·망 격리     └─ GSLB 자동절체     └─ 데이터 트랜잭션    └─ 취약점 개선환류
```

| 단계 | 주요 활동 내용 | 산출물 및 통제 기준 |
|---|---|---|
| **1. BIA 및 등급화** | 업무 영향도 분석을 통한 핵심 행정업무 식별 및 1~4등급 분류 | 시스템별 RTO·RPO 명세서 |
| **2. 다중 거점 설계** | 전력 인입 다중화, 배터리실 물리 차단, 다중 센터 분산 배치 | 재해복구 아키텍처 설계서 |
| **3. 장애 감지·절체** | 통합 관제 플랫폼 기반 실시간 상태 모니터링 및 자동 failover | 자동 절체 실행 절차서(SOP) |
| **4. 정합성 검증** | 데이터 복제 지연률 확인, 결손 트랜잭션 보정, 서비스 정합성 점검 | 데이터 무결성 검증 보고서 |
| **5. 실전 모의훈련** | 예고 없는 가상 재해 발생 훈련, 사용자 체감 서비스 복구 검증 | 모의훈련 결과 및 환류 계획서 |

#### 한줄 요약
- 서류상 계획에 머물지 않고 실제 재난 상황에서 자동 전환과 무결성 복구가 일어나는 순환 체계임

## Ⅴ. 설비 이중화 vs 서비스 다중화 비교

| 구분 | 단순 설비 이중화 (단일 센터) | 분산 서비스 다중화 (다중 센터) |
|---|---|---|
| **보호 대상** | 서버 부품, 전원 모듈, 망 회선 | 업무 트랜잭션, 대국민 디지털 서비스 |
| **장애 대응 범위** | 하드웨어 고장, 단일 랙 전원 단절 | 건물 전소, 전력망 상실, 광역 재난 |
| **핵심 기술** | Dual PSU, UPS 이중화, NIC 본딩 | GSLB, 스토리지 미러링, 클라우드 네이티브 |
| **데이터 상태** | 로컬 RAID, 공유 SAN 스토리지 | 원격지 동기/준동기 복제, 에어갭 백업 |
| **RTO / RPO** | 부품 교체 시간 소요, RTO 수시간 가능 | 실시간 자동 절체(RTO 분 단위), RPO 최소화 |
| **한계점** | 상면 화재·수해 시 전멸 위험 잔존 | 거점 간 통신 지연, 분산 트랜잭션 복잡성 |

#### 한줄 요약
- 설비 이중화가 장비 가동률을 지킨다면, 서비스 다중화는 기관의 생존과 국가 기능 연속성을 보장함

## Ⅵ. 산출물 단절 방지 및 실무 고려사항

- 적용 상황: 대규모 공공 정보자원을 다중 거점 클라우드 네이티브 환경으로 전환하고 재해복구 체계를 검증하는 경우

| 문제점 | 발생 원인 | 공학적 해결 대책 | 기대 효과 |
|---|---|---|---|
| **복구 목표 미달성** | 평시 모의훈련 부재 및 절체 매뉴얼과 실제 구성 불일치 | 카오스 엔지니어링 기반 상시 불시 절체 훈련 및 CMDB 자동 동기화 | 재난 발생 시 당황 없는 자동 절체 보장 |
| **원격 복제 성능 저하** | 센터 간 네트워크 대역폭 부족 및 장거리 지연 | 핵심 DB만 동기 복제하고 대용량 로그·첨부파일은 비동기 파이프라인 분리 | 주 센터 트랜잭션 병목 제거 |
| **공통 연계망 단절** | 개별 시스템만 복구되고 범정부 연계 게이트웨이 누락 | 공통 연계 엔진 및 행정망 인터페이스의 액티브-액티브 다중 거점화 | 대외 기관 연계 마비 방지 |
| **스플릿 브레인 발생** | 거점 간 쿼럼(Quorum) 구성 오류로 양 센터가 동시 쓰기 수행 | 제3 센터에 독립 쿼럼 위트니스(Witness) 배치 및 펜싱(Fencing) 통제 | 데이터 불일치 및 덮어쓰기 원천 차단 |

#### 한줄 요약
- 데이터 복제 방식 최적화와 독립 쿼럼 배치를 통해 네트워크 지연과 데이터 분할 위험을 통제해야 함

## Ⅶ. 실전 검증 중심의 기술사적 판단

- **[설비 중심 안전관리에서 데이터 흐름 추적성으로 전환]**: 방화벽과 배터리 구획 등 물리적 설비 안전은 기본이며, 상위 애플리케이션의 무상태화와 데이터 원격 복구 파이프라인이 끊기지 않는 논리적 복원력이 핵심임
- 나라면: 신규 시스템 구축 시 `1등급 행정서비스 지정 → 최소 2개 거점 액티브-액티브 분산 → 제3 거점 에어갭 백업 → 분기별 불시 트래픽 절체 실증`을 발주 RFP에 의무화하고 감리 검사기준에 명시

#### 한줄 요약
- 디지털 재난의 궁극적 안전장치는 완벽한 건물이 아니라, 언제든 한쪽을 버려도 서비스가 지속되는 분산 아키텍처임

## 1교시 10점 답안 발췌

### 1. 국가정보자원관리원 화재 대응의 본질
- 시설 차원의 사고가 전산망과 공통 플랫폼을 통해 전 공공서비스로 파급되는 공통원인 장애(Common Cause Failure)를 극복하기 위한 다중 거점 분산 및 무중단 연속성 보장 체계

### 2. 다중센터 회복탄력성 메커니즘
```text
[재해 발생] ──> [센서 감지] ──> [GSLB 트래픽 전환] ──> [Standby DB 승격] ──> [정합성 복구]
    화재            전력 단절       제2센터 우회              Split-Brain 방지       대국민 재개
```

| 통제 영역 | 핵심 기술 | 달성 목표 |
|---|---|---|
| 물리 격리 | 배터리실 별도 구획, 전원 인입 이원화 | 시설 화재의 전산실 전파 차단 |
| 트래픽 절체 | GSLB 헬스체크, Anycast 라우팅 | 센터 상실 시 수초 내 우회 |
| 데이터 보존 | 동기 복제, 제3센터 에어갭 WORM 스토리지 | 무손실 RPO=0 달성 및 위변조 방지 |

### 3. 차별화 제언
- 하드웨어 이중화에 의존하던 관행에서 벗어나 클라우드 네이티브 MSA 전환과 제3 거점 격리 백업을 정착시키고, 연 2회 이상의 불시 카오스 테스트로 실전 복구력을 입증해야 함
