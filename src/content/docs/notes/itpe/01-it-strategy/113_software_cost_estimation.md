## 지식 로드맵 내 현재 위치

IT 전략·관리 → 프로젝트 원가 관리 → **소프트웨어 비용 산정(Software Cost Estimation)**

## 30초 인출

- 본질: 소프트웨어 비용 산정은 개발에 드는 노력(공수)·기간·비용을 소프트웨어 규모와 사업 특성으로 추정하는 활동
- 메커니즘: 유사 사례·전문가 판단·WBS 합산·기능점수·COCOMO 같은 기법으로 규모와 노력을 추정하고, 인력 단가를 곱해 비용으로 환산
- 통찰: 초기 단일 추정값을 굳히면 범위 확정 후 차이가 커지므로 단계별 재추정과 가정·실적 차이 기록

<details>
<summary>핵심 용어</summary>

- **소프트웨어 비용 산정(Software Cost Estimation)** : 소프트웨어 개발에 필요한 노력·기간·비용을 규모와 사업 특성으로 추정하는 활동
- **유사 추정(Analogous Estimation)** : 규모·특성이 비슷한 과거 사업의 실적으로 전체 비용을 추정하는 하향식 기법
- **델파이(Delphi)** : 여러 전문가가 익명으로 추정과 의견 교환을 반복해 합의값을 찾는 전문가 판단 기법
- **WBS(Work Breakdown Structure)** : 사업 범위를 산출물 중심으로 계층 분해한 작업 구조. 작업별 노력을 합산하는 상향식 추정의 기반
- **FP(Function Point)** : 사용자 관점의 데이터·트랜잭션 기능으로 소프트웨어 규모를 측정하는 단위
- **ILF(Internal Logical File)** : 측정 대상 시스템이 유지·관리하는 논리 데이터 묶음
- **EIF(External Interface File)** : 다른 시스템이 유지하고 측정 대상은 참조만 하는 논리 데이터 묶음
- **EI(External Input)** : 경계 밖에서 들어와 내부 데이터를 변경하는 입력 기능
- **EO(External Output)** : 계산·파생 처리를 거쳐 경계 밖으로 내보내는 출력 기능
- **EQ(External Inquiry)** : 파생 처리 없이 데이터를 조회해 내보내는 조회 기능
- **COCOMO(Constructive Cost Model)** : 규모와 비용 동인을 산식에 넣어 개발 노력을 추정하는 Boehm의 비용 모형
- **PM(Person-Month)** : 한 사람이 한 달 동안 수행하는 작업량인 노력 단위

</details>

## 2~4교시 25점 답안

## Ⅰ. 소프트웨어 비용 산정의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **소프트웨어 비용 산정(Software Cost Estimation)** 은 소프트웨어 개발에 필요한 노력·기간·비용을 규모와 사업 특성으로 추정하는 활동 |
| 목적 | 예산·일정·계약 기준의 근거 마련과 범위 변경의 비용 영향 판단 |

## Ⅱ. 일반 원가 계산과 구별되는 SW 비용 산정의 특징

| 특징 | 의미 |
|---|---|
| 노력 중심 추정 | 비용 대부분이 인력의 노력이라 **PM** 단위의 규모·생산성 기반 추정 |
| 규모 측정 필요 | **FP** ·코드 라인 같은 규모 단위로 추정의 기준 설정 |
| 단계별 불확실성 감소 | 요구가 구체화될수록 추정 오차가 줄어 재추정 필요 |
| 조직 실적 보정 | 외부 모형 계수를 조직 실적으로 보정해야 정확도 확보 |

## Ⅲ. SW 비용 산정 절차와 기능점수 규모 측정

### SW 비용 산정 절차

```text
요구사항·범위·가정 정의
    ↓
규모 추정 ── 기능점수(FP) 또는 코드 라인
    ↓
노력 추정 ── 조직 생산성 또는 모형(COCOMO) 적용
    ↓
기간·비용 환산 ── 인력 계획·단가 적용
    ↓
실적 대비 차이 기록 ── 다음 추정의 보정 자료
```

### 규모 추정 확대: 기능점수 구성

```text
기능점수(FP)
    │
    ├─ 데이터 기능
    │     ├─ ILF ── 내부에서 유지하는 논리 데이터
    │     └─ EIF ── 외부 유지·참조 전용 데이터
    │
    └─ 트랜잭션 기능
          ├─ EI ── 내부 데이터를 바꾸는 입력
          ├─ EO ── 계산을 거친 출력
          └─ EQ ── 가공 없는 조회
```

## Ⅳ. 비용 산정 기법의 비교

| 기법 | 산정 근거 | 적합 시점 | 약점 |
|---|---|---|---|
| 전문가 판단· **델파이** | 전문가 경험의 합의 | 착수 전 개략 | 개인 편향 |
| **유사 추정** (하향식) | 비슷한 과거 사업 실적 | 기획 단계 | 유사 사례가 없으면 불가 |
| **WBS** 합산 (상향식) | 작업별 노력의 합계 | 설계 이후 | 작업 누락·중복 |
| 기능점수(FP) | 사용자 기능 규모 | 요구 확정 후 | 성능·보안 등 비기능 요구 반영 한계 |
| **COCOMO** | 규모와 비용 동인. 기본 모형은 조직형(Organic)·반분리형(Semi-detached)·내장형(Embedded) 유형별 계수 | 규모 추정 후 | 조직 실적 보정 필요 |

COCOMO Ⅱ의 노력 산식은 PM = A × Size^E × ΠEM (A: 생산성 상수, Size: 규모, E: 규모 경제를 반영하는 지수, EM: 비용 동인의 노력 승수). 국내 공공 SW사업의 대가 기준 적용은 별도 토픽인 SW사업 대가산정의 범위

## Ⅴ. SW 비용 산정의 한계와 방안

| 한계 | 방안 |
|---|---|
| 초기 단일 추정값의 계약 기준 고정으로 범위 확정 후 차이 확대 | 기획 단계는 유사 추정·델파이의 범위값, 요구 확정 후 기능점수로 재추정 |
| 전문가 판단의 개인 편향 | 델파이의 익명 반복 합의로 추정 편차 축소 |
| 기능점수에 드러나지 않는 비기능 요구의 노력 누락 | 성능·보안 요구의 별도 노력 산정과 보정 반영 |
| 외부 모형 계수의 조직 부적합 | 조직 실적 데이터로 COCOMO 상수·생산성 보정 |
| 추정 근거 미기록으로 범위 변경 시 재산정 곤란 | 규모·생산성·가정의 기준선 기록 |

## Ⅵ. 제언

사업 단계마다 정보 수준에 맞는 기법으로 재추정하고, 각 추정의 범위값·가정과 종료 후 실적 차이를 기록해 다음 추정을 보정

### 사업 단계별 재추정 흐름

```text
기획 ── 유사 추정·델파이의 범위값
    ↓ 요구사항 확정
분석 ── 기능점수 기반 재추정
    ↓ 설계 완료
설계 ── WBS 합산으로 상세 검증
    ↓ 사업 종료
종료 ── 추정 대비 실적 차이 기록
```

### 종료 단계 확대: 실적 기반 보정 절차

```text
추정 노력과 실적 노력 비교
    ↓
차이 원인 분류 ── 규모 오차·생산성 오차·범위 변경
    ↓
조직 생산성·모형 계수 갱신
    ↓
다음 사업 추정에 갱신 값 적용
```

### 선택 근거: 착수 시 단일 추정과의 비교

| 구분 | 착수 시 단일 추정 | 제언: 단계별 재추정 |
|---|---|---|
| 추정값 형태 | 하나의 금액 | 단계별 범위값 |
| 사용 기법 | 한 기법 고정 | 정보 수준에 맞는 기법 |
| 범위 변경 대응 | 사후 협상 | 기록된 가정 대비 재추정 |
| 실적 활용 | 미활용 | 조직 생산성·계수 보정 |
