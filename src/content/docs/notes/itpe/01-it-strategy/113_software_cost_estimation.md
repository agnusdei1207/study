## Ⅰ. 소프트웨어 비용 산정의 개요

- 개념 : 소프트웨어 프로젝트의 성공적 완수를 위해 요구되는 노력(Effort), 기간(Schedule), 인력 및 비용(Cost)을 공학적 알고리즘, 통계 모델, 또는 전문가 판단을 통해 사전에 정량적으로 예측하는 소프트웨어 공학 활동.
- 배경 및 필요성 : 부정확한 비용 산정은 저가 수주, 프로젝트 파행, 납기 지연, 품질 저하의 근본 원인이 되므로 계약과 프로젝트 관리의 객관적 기준선 확립 필수.
- 주요 목적 : 적정 예산 확보 및 가격 경쟁력 평가, 현실적인 일정 계획 수립, 자원 배분 최적화 및 프로젝트 원가 통제.

## Ⅱ. 소프트웨어 비용 산정 방법론의 분류 체계

```text
       ┌──────────────────────── 비용 산정 기법 ────────────────────────┐
       │                                                               │
  [하향식 산정 (Top-Down)]    ── 전문가 판단 기법, 델파이(Delphi) 기법
       │
  [상향식 산정 (Bottom-Up)]   ── WBS 작업 패키지별 산정, 원시 코드 라인 수(LOC) 기법
       │
  [수학적/모형적 산정 (Algorithmic)]
    - 기능점수 (FP, Function Point) ── 사용자 관점 논리적 기능 규모 측정 (국내 공공 표준)
    - COCOMO / COCOMO II             ── 시스템 규모 및 17개 노력 곱셈계수 기반 공수 산출
    - Putnam 모형 (Rayleigh-Norden)  ── 시간과 노력의 트레이드오프 관계(SLIM 도구)
       └───────────────────────────────────────────────────────────────┘
```

- **하향식 산정** (Top-Down) : 전문가 판단 기법, 델파이 기법.
- **상향식 산정** (Bottom-Up) : WBS 작업 패키지별 산정, 원시 코드 라인 수 기법.
- **기능점수** (FP) : 사용자 관점 논리적 기능 규모 측정, 국내 공공 표준.

## Ⅲ. 주요 비용 산정 모형의 비교 분석

| 산정 모형 | 산정 기준 | 핵심 산식 및 특징 | 장단점 |
|---|---|---|---|
| **LOC** (Source Lines of Code) | 소스코드 라인 수 | 노력(Effort) = 라인 수 x 라인당 생산성 | 직관적이나 언어 및 개발자 역량에 따라 편차 극심 |
| **COCOMO II** | 소스 라인(KSLOC) 또는 객체점수 | Effort = A x (Size)^B x M (B: 규모의 경제/불경제 계수) | 프로젝트 특성(17개 비용 동인) 반영 우수하나 초기 코드라인 추정 어려움 |
| 기능점수 (FP) | 사용자 요구 기능 (입출력, 파일) | 미조정 FP x 보정계수 x 단가 | 구현 기술에 독립적이며 기획 단계 적용 최적 (공공 표준) |
| **Putnam 모형** | 소프트웨어 생명주기 곡선 | Man-Years = S^3 / (C^3 x T^4) (기간 단축 시 비용 기하급수 증가) | 대형 프로젝트의 일정-비용 트레이드오프 분석에 탁월 |

## Ⅳ. 소프트웨어 비용 산정 시 주요 한계점 및 해결 방안

- 초기 요구사항 불확실성에 따른 '불확실성의 원추(Cone of Uncertainty)' :
  - 한계점 : 프로젝트 초기 기획 단계에서는 오차 범위가 최대 4배까지 벌어져 초기 산정 예산의 신뢰성 극히 취약.
  - 해결 방안 : 단계별 재산정(Re-estimation) 게이트웨이 의무화, 점진적 상세화(Rolling Wave)에 따른 예비비 탄력 운영.
- 정량적 산정 도구(COCOMO 등)의 파라미터 보정 난제 :
  - 한계점 : 노력 조정 인자(Cost Drivers)가 조직의 개발 생산성, 도메인 복잡도, 개발팀 역량에 따라 크게 좌우되어 주관성 개입.
  - 해결 방안 : 조직 내 축적된 역사적 프로젝트 데이터(Historical Data) 기반의 사내 맞춤형 비용 산정 회귀 모델 구축.
- 애자일 및 클라우드 네이티브 환경과의 패러다임 불일치 :
  - 한계점 : 전통적 FP/코드 라인 수(SLOC) 기준은 지속적 배포(CI/CD)와 반복형 스토리에 기반한 개발 원가 산정에 부적합.
  - 해결 방안 : 스토리 포인트(Story Point) 기반의 벨로시티(Velocity) 산정법 도입, 클라우드 운영비(Opex)를 포괄하는 TCO 산정 체계 구축.

## Ⅴ. 과학적 비용 산정을 위한 기술사적 제언

- 초기 불확실성 원뿔(Cone of Uncertainty) 관리 : 프로젝트 기획 초기에는 비용 추정 오차가 최대 4배(400%)에 달할 수 있음을 인정하고, 설계 완료 시점에 FP 정규법으로 재정산하는 단계별 정산제 도입.
- 비기능 요구사항(성능, 보안, 가용성)의 독립 대가 반영 : 기능점수가 주로 업무 트랜잭션에 집중되어 인프라 고도화나 MSA 분산 설계 노력을 과소평가하는 한계를 극복하기 위해 비기능 보정계수 현실화.
- 기능점수 간이법과 머신러닝 기반 견적 도구 융합 : 과거 완료 프로젝트의 아키텍처 속성과 실제 투입 비용 데이터를 학습한 ML 기반 예측 모델을 보조 지표로 활용하여 편향 제거.
