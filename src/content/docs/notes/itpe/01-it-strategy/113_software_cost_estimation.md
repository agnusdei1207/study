## 지식 로드맵 내 현재 위치

IT 전략·관리 → 프로젝트 관리·원가 → **소프트웨어 비용 산정(Software Cost Estimation)**

## 30초 인출

- 본질: 소프트웨어 비용 산정은 개발할 소프트웨어의 규모를 측정하고 그 규모로 노력(인력·기간)과 비용을 추정하는 활동
- 메커니즘: 규모(기능점수·SLOC)에서 노력(PM)을 추정하고 단가·일정으로 기간·비용 환산. 노력 추정은 유사·모수·상향식·전문가 판단 기법 중 정보 수준에 맞게 선택
- 통찰: 개념 단계의 규모·비용 불확실성이 최대 약 4배에 이르므로 착수 시 단일 금액 대신 범위 추정으로 시작하고, 정의 수준이 올라갈 때마다 재추정하며 종료 후 실적으로 계수를 보정

<details>
<summary>핵심 용어</summary>

- **소프트웨어 비용 산정(Software Cost Estimation)** : 소프트웨어 개발에 필요한 규모·노력·기간·비용을 추정하는 활동
- **SLOC(Source Lines of Code)** : 소스 코드의 줄 수로 나타내는 규모 단위. 천 줄 단위는 KSLOC
- **기능점수(FP, Function Point)** : 사용자 관점에서 소프트웨어가 제공하는 기능의 양으로 규모를 재는 단위. IFPUG(International Function Point Users Group) 방식은 ISO/IEC 20926:2009
- **ILF(Internal Logical File, 내부논리파일)** : 측정 대상 시스템의 경계 안에서 유지되는 논리 데이터 그룹
- **EIF(External Interface File, 외부연계파일)** : 경계 밖의 다른 시스템이 유지하고 측정 대상은 참조만 하는 논리 데이터 그룹
- **EI(External Input, 외부입력)** : 경계 밖에서 들어온 데이터·제어정보를 처리하는 단위 프로세스
- **EO(External Output, 외부출력)** : 계산·파생 데이터 생성 등 처리 로직을 거쳐 경계 밖으로 내보내는 단위 프로세스
- **EQ(External Inquiry, 외부조회)** : 계산·파생 데이터 없이 저장 데이터를 조회해 내보내는 단위 프로세스
- **COSMIC(Common Software Measurement International Consortium)** : 데이터 이동(Entry·Exit·Read·Write) 1건당 1 CFP(COSMIC Function Point)로 기능 규모를 재는 방식. ISO/IEC 19761:2011
- **SNAP(Software Non-Functional Assessment Process)** : 비기능 요구사항의 규모를 재는 IFPUG 방식. ISO/IEC/IEEE 32430:2025
- **COCOMO II(Constructive Cost Model II)** : 규모·규모 요인·비용 동인으로 개발 노력을 추정하는 Boehm 계열 모형
- **PM(Person-Month)** : 한 사람이 한 달 동안 수행하는 작업량인 노력 단위
- **EM(Effort Multiplier, 노력 승수)** : COCOMO II에서 인력·제품·플랫폼·프로젝트 특성에 따라 노력을 가감하는 비용 동인의 계수
- **BRAK(Breakage)** : 요구사항 변동으로 버려지는 코드 비율. 유효 규모를 키우는 COCOMO II 보정값
- **Wideband Delphi(광대역 델파이)** : 전문가가 익명으로 추정하고 편차가 큰 항목을 토론한 뒤 다시 추정하는 합의 기법
- **유사 추정(Analogous Estimating)** : 비슷한 과거 사업의 실적으로 추정하는 하향식 기법
- **모수 추정(Parametric Estimating)** : 규모 같은 변수와 비용의 통계적 관계로 추정하는 기법
- **상향식 추정(Bottom-up Estimating)** : 최하위 작업의 추정치를 합산해 전체를 추정하는 기법

</details>

## 2~4교시 25점 답안

## Ⅰ. 소프트웨어 비용 산정의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **소프트웨어 비용 산정(Software Cost Estimation)** 은 소프트웨어 개발에 필요한 규모·노력·기간·비용의 추정 활동 |
| 목적 | 예산·일정·계약 조건의 근거 마련 |

## Ⅱ. 규모에서 비용을 도출하는 소프트웨어 비용 산정의 특징

| 특징 | 의미 |
|---|---|
| 규모 기반 추정 | **SLOC** , **기능점수(FP)** 같은 규모 측정값에서 노력 도출 |
| 인력 노력 중심 | 노력 단위 **PM** 에 인력 단가를 반영한 비용 환산 |
| 초기 단계의 큰 불확실성 | 개념 단계에서 제품 규모를 약 4배 범위 이내로도 특정하기 어려움 (Boehm) |
| 점 추정이 아닌 범위 추정 | 입력 정보의 정의 수준에 따라 추정 범위 조정 (COCOMO II) |

## Ⅲ. 소프트웨어 비용 산정 절차와 핵심 산식

### 규모 → 노력 → 비용 산정 절차

```text
규모 산정 ── 기능점수(FP)·COSMIC·SLOC
    ↓
노력 산정 ── PM 추정 (COCOMO II·유사·상향식·전문가 판단)
    ↓
기간·비용 환산 ── 인력 계획·단가 적용
    ↓
가정·범위값 기록 ── 정의 수준이 오르면 재추정
```

### 규모 산정 확대: 기능점수(IFPUG) 구성

```text
기능점수(FP)
    │
    ├─ 데이터 기능
    │     ├─ ILF ── 경계 안에서 유지하는 논리 데이터
    │     └─ EIF ── 경계 밖에서 유지, 참조만 하는 논리 데이터
    │
    └─ 트랜잭션 기능
          ├─ EI ── 경계 밖에서 들어온 데이터의 처리
          ├─ EO ── 계산·파생 데이터를 거쳐 경계 밖으로 출력
          └─ EQ ── 계산·파생 없이 조회해 출력
```

### 노력 산정 확대: COCOMO II 노력 산식 구조

```text
규모 Size(KSLOC) ─┐
                  ├─→ 기준 노력 PM_nominal = A × Size^B
규모 지수 B ──────┘        B: 5개 규모 요인의 합으로 결정
                           (PREC·FLEX·RESL·TEAM·PMAT)
    ↓
노력 승수 EM 적용 ── PM = PM_nominal × ΠEM_i
    │                (Post-Architecture 17개, Early Design 7개)
    ↓
개발 기간 TDEV(개월) 산정
```

## Ⅳ. 규모 산정 방식과 노력 산정 기법의 비교

### 규모 산정 방식

| 방식 | 규모 단위 | 측정 기준 | 한계 |
|---|---|---|---|
| SLOC | KSLOC | 소스 코드의 줄 수 | 구현 언어에 따라 달라져 기능점수의 언어별 환산 필요 |
| **기능점수** (IFPUG) | FP | 사용자 관점의 데이터 기능·트랜잭션 기능 | 기능 규모만 측정하고 성능·보안 같은 비기능 요구는 대상 밖 |
| **COSMIC** | CFP | 기능 프로세스의 데이터 이동(Entry·Exit·Read·Write)마다 1 CFP | 데이터 이동 식별이 가능한 수준의 요구 상세화 필요 |

### 노력 산정 기법

| 기법 | 산정 근거 | 특성 |
|---|---|---|
| **유사 추정** | 비슷한 과거 사업 실적 | 하향식. 빠르지만 정확도 낮음 |
| **모수 추정** (COCOMO II) | 규모·비용 동인과 노력의 관계식 | 하향식. 유사 추정보다 정확 |
| **상향식 추정** | 최하위 작업별 추정치의 합산 | 시간이 들지만 정확도 높음 |
| **Wideband Delphi** 전문가 판단 | 전문가의 익명 추정과 편차 토론의 반복 | 자료가 부족한 초기에 활용 |

## Ⅴ. 소프트웨어 비용 산정의 한계와 방안

| 한계 | 방안 |
|---|---|
| 개념 단계의 규모 불확실성이 커서 단일 금액이 실제와 크게 벗어남 | 점 추정 대신 범위 추정으로 제시하고 정의 수준이 오를 때 재추정 |
| 기능점수가 비기능 요구의 노력을 담지 못함 | **SNAP** 으로 비기능 규모를 별도 측정해 기능점수와 병행 |
| 요구사항 변동으로 버려지는 작업이 규모에 미반영 | **BRAK** 로 유효 규모를 키워 보정 |
| 모형 계수가 다른 조직의 자료로 보정된 값(COCOMO II.1997은 83개 사업 자료) | 조직의 사업 실적으로 계수와 생산성 재보정 |
| 전문가 판단의 개인 편향 | Wideband Delphi의 익명 추정과 편차 토론 반복 |

## Ⅵ. 제언

착수 시 단일 금액 대신 범위 추정으로 시작하고, 요구사항이 구체화될 때마다 규모 산정 방식을 바꿔 재추정하며, 종료 후 실적과의 차이로 조직 계수를 보정

### 정의 수준에 따른 재추정 흐름

```text
개념 단계 ── 유사 추정·전문가 판단의 범위값
    ↓ 요구사항 상세화
기능 정의 후 ── 기능점수(또는 COSMIC) 규모로 모수 추정
    ↓ 설계·작업 분해
작업 정의 후 ── 상향식 추정으로 상세 검증
    ↓ 사업 종료
종료 ── 추정 대비 실적 기록
```

### 종료 단계 확대: 실적 기반 계수 보정

```text
추정 PM  vs  실적 PM
    ↓
차이 원인 분리 ── 규모 오차 · 요구 변동(BRAK) · 생산성 계수 오차
    ↓
조직 계수 갱신 → 다음 사업 추정에 적용
```

| 구분 | 착수 시 단일 추정 | 제언: 범위 추정과 단계별 재추정 |
|---|---|---|
| 추정값 형태 | 하나의 금액 | 정의 수준에 맞춘 범위 |
| 기법 선택 | 하나의 기법 고정 | 정보 수준에 맞는 기법 전환 |
| 요구 변동 대응 | 사후 협상 | BRAK로 유효 규모 보정 후 재추정 |
| 실적 활용 | 없음 | 조직 계수 재보정 |
