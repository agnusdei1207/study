## 연관 키워드

- 소프트웨어 비용 산정(Software Cost Estimation), 불확실성의 원추(Cone of Uncertainty)
- 하향식 산정(Top-Down), 상향식 산정(Bottom-Up), 알고리즘적 산정(Algorithmic)
- 기능점수(FP, Function Point), LOC(Lines of Code), COCOMO/COCOMO II
- Putnam 모형(Rayleigh-Norden), SLIM, WBS(Work Breakdown Structure)
- TCO(Total Cost of Ownership), Opex(Operating Expense), KSLOC
- 벨로시티(Velocity), 스토리 포인트(Story Point), 델파이 기법(Delphi)

## Ⅰ. 소프트웨어 비용 산정의 개요

- 핵심 요약 : 소프트웨어 프로젝트에 필요한 노력·기간·비용을 공학적 알고리즘, 통계 모델, 전문가 판단을 통해 사전 정량 예측하는 소프트웨어 공학 활동.
- 개념 : 소프트웨어 프로젝트의 성공적 완수를 위해 요구되는 노력(Effort), 기간(Schedule), 인력 및 비용(Cost)을 공학적 알고리즘, 통계 모델, 또는 전문가 판단을 통해 사전에 정량적으로 예측하는 소프트웨어 공학 활동.
- 배경 및 필요성 : 부정확한 비용 산정은 저가 수주, 프로젝트 파행, 납기 지연, 품질 저하의 근본 원인이 되므로 계약과 프로젝트 관리의 객관적 기준선 확립 필수.
- 주요 목적 : 적정 예산 확보 및 가격 경쟁력 평가, 현실적인 일정 계획 수립, 자원 배분 최적화 및 프로젝트 원가 통제.

## Ⅱ. 소프트웨어 비용 산정의 특징 및 장점

- 핵심 요약 : 산정 기법 분류와 모형 기반 정량 산정, 불확실성의 원추에 따른 신뢰도 변화.

1. **하향식·상향식·모형 산정** : 서로 다른 관점의 견적을 대조하여 단일 판단의 편향을 줄인다.
2. **FP·COCOMO 기반 정량화** : 기능 규모와 비용 동인을 수치화하여 예산 근거를 설명한다.
3. **WBS 단위 분해** : 작업 패키지별 노력과 일정을 추적하여 누락된 비용을 찾는다.
4. **조직 생산성 보정** : 과거 프로젝트 실적을 반영해 조직에 맞는 산정 정확도를 높인다.
5. **단계별 재산정** : 요구사항이 구체화될 때 기준선을 갱신하여 초기 불확실성에 대응한다.

## Ⅲ. 소프트웨어 비용 산정의 구조 (흐름)

- 핵심 요약 : 산정 기법 분류 체계와 모형 기반 산정 흐름.
- 소프트웨어 비용 산정 기법의 분류 체계.

```text
비용 산정 기법
   [하향식 산정 (Top-Down)]
   [상향식 산정 (Bottom-Up)]
   [수학적/모형적 산정 (Algorithmic)]
      기능점수 (FP, Function Point)
      COCOMO / COCOMO II
         시스템 규모 및 17개 노력 곱셈계수 기반
         공수 산출
      Putnam 모형 (Rayleigh-Norden)
         시간과 노력의 트레이드오프 관계
         (SLIM 도구)
```

```text
[비용 산정 프로세스 흐름]
   요구사항 분석
        │
        ├─ 규모 측정 (FP, LOC)
        │
        ├─ 비용 모형 선정
        │
        ├─ 파라미터 보정 (비용 동인)
        │
        └─ 노력·기간·비용 산출
               │
               └─ 단계별 재산정 (게이트웨이)
```

- 하향식 산정(Top-Down) : 전문가 판단 기법, 델파이 기법(Delphi).
- 상향식 산정(Bottom-Up) : WBS(Work Breakdown Structure) 작업 패키지별 산정, 원시 코드 라인 수 기법.
- 기능점수(FP, Function Point) : 사용자 관점 논리적 기능 규모 측정, 국내 공공 표준.

## Ⅳ. 주요 비용 산정 모형의 비교

- 핵심 요약 : LOC, COCOMO II, 기능점수, Putnam 모형의 산정 기준과 장단점 비교.
- 주요 비용 산정 모형의 대비.

| 산정 모형 | 산정 기준 | 핵심 산식 및 특징 | 장단점 |
|---|---|---|---|
| LOC (Lines of Code) | 소스코드 라인 수 | 노력(Effort) = 라인 수 × 라인당 생산성 | 직관적이나 언어 및 개발자 역량에 따라 편차 極심 |
| COCOMO II | 소스 라인(KSLOC) 또는 객체점수 | Effort = A × (Size)^B × M (B: 규모의 경제/불경제 계수) | 프로젝트 특성(17개 비용 동인) 반영 우수하나 초기 코드라인 추정 어려움 |
| 기능점수 (FP) | 사용자 요구 기능(입출력, 파일) | 미조정 FP × 보정계수 × 단가 | 구현 기술에 독립적이며 기획 단계 적용 최적(공공 표준) |
| Putnam 모형 | 소프트웨어 생명주기 곡선 | Man-Years = S^3 / (C^3 × T^4) (기간 단축 시 비용 기하급수 증가) | 대형 프로젝트의 일정-비용 트레이드오프 분석에 탁월 |

## Ⅴ. 소프트웨어 비용 산정의 한계와 방안

- 핵심 요약 : **초기 불확실성**, 비용 동인 보정, 반복 개발의 범위 변화를 재산정 체계로 다룬다.

| 한계 | 방안 |
|---|---|
| 초기 요구가 불명확하여 **견적 오차**가 큼 | 가정을 명시하고 설계·구현 단계마다 규모와 예산을 재산정 |
| **비용 동인**이 조직·도메인마다 달라 범용 모형의 정확도가 떨어짐 | 완료 프로젝트의 실제 공수·규모를 축적해 모형 계수를 보정 |
| 반복 개발과 클라우드 운영비가 초기 개발 견적에서 빠지기 쉬움 | 벨로시티·변경 범위를 추적하고 운영비를 포함한 **TCO**로 판단 |

## Ⅵ. 과학적 비용 산정을 위한 기술사적 제언

- 핵심 요약 : 단계별 정산제, 비기능 요구사항 대가 반영, 머신러닝 기반 견적 도구 융합.

- 초기 불확실성 원뿔(Cone of Uncertainty) 관리 : 프로젝트 기획 초기에는 비용 추정 오차가 최대 4배(400%)에 달할 수 있음을 인정하고 설계 완료 시점에 FP 정규법으로 재정산하는 단계별 정산제 도입.
- 비기능 요구사항(성능, 보안, 가용성)의 독립 대가 반영 : 기능점수가 주로 업무 트랜잭션에 집중되어 인프라 고도화나 MSA(Microservice Architecture) 분산 설계 노력을 과소평가하는 한계를 극복하기 위해 비기능 보정계수 현실화.
- 기능점수 간이법과 머신러닝(ML, Machine Learning) 기반 견적 도구 융합 : 과거 완료 프로젝트의 아키텍처 속성과 실제 투입 비용 데이터를 학습한 ML 기반 예측 모델을 보조 지표로 활용하여 편향 제거.

## Ⅶ. 결론

- 핵심 요약 : 소프트웨어 비용 산정은 산정 모형과 파라미터 기반 정량 예측 활동으로 단계별 재산정과 조직 데이터 기반 보정이 관건.
- 요약 : 소프트웨어 비용 산정은 프로젝트에 필요한 노력·기간·비용을 공학적 알고리즘, 통계 모델, 전문가 판단을 통해 사전 정량 예측하는 소프트웨어 공학 활동.
- 시사점 : 단계별 정산제 도입, 비기능 요구사항 대가 반영, 머신러닝 기반 견적 도구 융합을 통해 산정 정확도와 신뢰도 향상 필요.
