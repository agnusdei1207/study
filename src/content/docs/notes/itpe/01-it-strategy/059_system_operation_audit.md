## 연관 키워드

- 시스템 운영 감리
- 유지보수 감리
- 개발 감리
- SLA, Service Level Agreement, 서비스 수준 협약
- SLM, Service Level Management, 서비스 수준 관리
- APM, Application Performance Monitoring, 애플리케이션 성능 모니터링
- 형상관리
- 변경관리
- RTO, Recovery Time Objective, 복구 시간 목표
- 재해복구

## Ⅰ. 시스템 운영·유지보수 감리의 개요

- 핵심 요약 : 가동 중인 정보시스템의 서비스 품질, 가용성, 형상, 보안, SLA 준수 여부를 제3자 관점에서 점검하는 감리 활동.
- 개념 : 구축이 끝나 실제 가동 중인 정보시스템의 서비스 품질, 가용성, 성능, 형상관리, 보안, **서비스 수준 협약** (SLA, Service Level Agreement) 준수 여부를 독립된 관점에서 점검하는 **시스템 운영·유지보수 감리**.
- 배경 및 필요성 : 개발 단계에 비해 운영 단계는 지속적 통제가 부족해 노후화, 형상 불일치, 성능 저하, 보안 취약점이 누적되기 쉬우므로 선제적 점검이 필요하다.
- 주요 목적 : 서비스 수준 검증, 장애 예방과 신속 복구 체계 점검, 유지보수 대가의 적정성 평가.

## Ⅱ. 시스템 운영 감리의 특징 및 장점

- 핵심 요약 : 서비스 수준 관리, 복구 실측, 형상 점검, 용량 분석, 독립 검증을 결합해 운영 안정성을 확보하는 특성.

1. 서비스 수준 검증 : SLA와 장애 기록을 확인 → 사용자에게 약속한 서비스 수준의 실제 달성 여부 평가.
2. 복구 실측 : 백업 복원과 재해복구 훈련 결과를 확인 → 장애 대응 능력을 추정이 아닌 실제 결과로 검증.
3. 형상·변경 점검 : 운영 배포물과 승인 이력을 대조 → 무단 변경 위험 감소.
4. 성능·용량 분석 : 사용률과 병목을 점검 → 증설과 최적화의 근거 확보.
5. 독립적 판단 : 운영자의 자체 보고를 교차 검증 → 평가 결과의 신뢰도 향상.

## Ⅲ. 시스템 운영 감리의 구조 (흐름)

- 핵심 요약 : SLA, 장애, 형상, 용량의 네 가지 점검 영역을 중심으로 운영 감리가 수행되는 구조.
- 점검 영역 : 서비스 수준 관리(SLM, Service Level Management), 장애·재해복구 관리, 형상·변경 관리, 용량·성능 관리.

```text
[운영 감리 점검 영역]
  서비스 수준 관리 (SLM)
  장애 및 재해복구 관리
  형상 및 변경 관리
  용량 및 성능 관리
```

```text
감리 계획
   ↓
자료 수집
   ↓
현장 점검
   ↓
SLA·성능·형상 검증
   ↓
개선 권고 → 사후 확인
```

## Ⅳ. 개발 감리와 운영 감리의 비교

- 핵심 요약 : 개발 감리는 구축 중 품질을 점검하고, 운영 감리는 가동 중 서비스 안정성과 변경관리를 점검한다.

| 비교 항목 | 개발 감리 | 운영·유지보수 감리 |
| --- | --- | --- |
| 수행 시점 | 분석, 설계, 구현 등 개발 수행 중 | 시스템 오픈 후 가동 중 |
| 주 점검 대상 | 요구사항 반영도, 아키텍처 적합성, 테스트 결과 | 서비스 가용성, SLA 준수율, 변경관리, 장애 대응력 |
| 주요 산출물 | 분석·설계서, 테스트 결과서, 코드 품질 보고서 | SLA 보고서, 장애 일지, 형상 변경 이력, 용량 보고서 |
| 핵심 지향점 | 결함 없는 시스템의 적기 구축 | 무중단 운영과 지속적 개선 |

## Ⅴ. 시스템 운영 감리의 한계와 방안

- 핵심 요약 : 정기 점검의 공백, 자체 보고의 편향, 계약 이행 누락을 원천 기록과 지속 모니터링으로 보완한다.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 정기 감리는 특정 시점의 스냅샷만 확인 | 감리 사이 기간의 장애와 성능 저하를 놓침 | 주기별 **애플리케이션 성능 모니터링** (APM, Application Performance Monitoring)과 보안 로그, 장애 이력을 함께 분석 | 장애 탐지 시점 차이 |
| 운영자 자체 보고에 의존한 SLA 수치 | 산식과 제외 시간의 왜곡 가능성 | 원천 로그와 독립 모니터링으로 산식과 제외 시간 검증 | SLA 산정 오차 |
| 기술 상태만 점검 | 유지관리 계약 이행 문제를 놓침 | 과업 범위, 변경 이력, 성과와 대가 지급 근거를 함께 점검 | 과업 이행률 |

## Ⅵ. 운영 감리 실효성 확보에 대한 기술사적 제언

- 핵심 요약 : 형상과 배포의 일치 검증, 백업의 실제 복구 시험, 유지관리비의 투명성 감사를 제도화해야 감리가 실효성을 가진다.

1. 형상관리 서버의 최종 소스와 운영 서버에 실제 배포된 바이너리를 주기적으로 대조하는 기준선 감사를 정례화해야 한다. 감리 조직은 무작위 표본으로 해시 값을 비교해 임의 패치를 찾아낼 수 있어야 한다.
2. 백업 로그의 존재만 확인하는 형식적 감리에서 벗어나, 테스트 환경에서 실제 백업을 복원해 데이터 무결성과 복구 시간(RTO, Recovery Time Objective)을 측정하는 절차를 감리 기준에 넣어야 한다.
3. 유지관리 대가는 처리 티켓 수, 개선 개발 건수, 가용성 지표와 대조해 지급 적정성을 감사하는 것이 바람직하다. 이 대조 결과는 다음 계약의 성과 기준으로 이어져야 한다.

## Ⅶ. 결론

- 핵심 요약 : 시스템 운영·유지보수 감리는 가동 중 시스템의 안정성과 효율성을 확보하는 제3자 점검 체계.
- 감리의 가치는 점검 시점이 아닌 상시 모니터링과 독립 검증에서 나오므로 운영 단계의 지속성이 성패를 좌우한다.
