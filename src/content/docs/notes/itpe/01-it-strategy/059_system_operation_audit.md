## 30초 인출

- 본질: **시스템 운영·유지보수 감리** : 독립된 제3자가 운영·유지보수의 기준 준수 여부를 증거로 확인하는 활동.
- 메커니즘: 감리계획 → 원시 로그·티켓 수집 → 표본·재수행 검증 → 영향도 평가·보고 → 시정조치 이행확인.
- 통찰: 한계: 운영 실적 없이 계약 이행만 확인하면 실제 서비스 상태를 놓침 → 방안: 문서상 통제와 로그·티켓 표본을 대조

<summary>핵심 용어</summary>

- **시스템 운영·유지보수 감리** : 독립된 감리자가 운영·유지보수 기준과 통제 증적을 확인하는 활동
- **SLA(Service Level Agreement)** : 서비스 수준 목표와 측정·보고·위반 페널티를 규정한 계약 협약
- **ITSM(IT Service Management)** : IT 서비스의 기획·운영·개선을 지원하는 Best Practice 기반 관리 체계
- **SR(Service Request)** : 사용자에게 사전 정의된 서비스 조치를 요청하는 기록. 정보 제공·계정 권한 신청 등이 예시
- **RTO(Recovery Time Objective)** : 장애 발생 시 서비스 정상 가동까지 허용되는 최대 목표 복구 시간
- **RPO(Recovery Point Objective)** : 서비스 복원 시 데이터 유실을 감내할 수 있는 최대 목표 복구 시점
- **CAATs(Computer-Assisted Audit Techniques)** : 대용량 로그와 트랜잭션을 전산 도구로 추출·검증하는 컴퓨터 기반 감사 기법

## 2~4교시 25점 답안

## Ⅰ. **시스템 운영·유지보수 감리** 개요

> 운영·유지보수 감리는 체크리스트 확인이 아니라 통제가 실제 작동하고 결과가 추적되는지 증적으로 판단하는 활동임.



| 구분 | 핵심 |
|---|---|
| 정의 | **시스템 운영·유지보수 감리** : 독립 감리자가 운영·유지보수 기준 준수와 통제 실효성을 증적으로 확인하는 활동 |
| 목적 | 서비스 안정성·계약 이행 확인과 개선점 도출 |

## Ⅱ. 시스템 운영·유지보수 감리의 특징

| 특징 | 감리 판단 기준 |
|---|---|
| 독립된 증거 확인 | 계약·보고값과 원시 로그·티켓을 교차 검증 |
| 운영과 변경의 연결 | 서비스 장애와 이를 만든 변경·배포 이력을 추적 |
| 시정조치 재확인 | 지적사항의 이행 여부를 실제 운영 증적으로 재검증 |

## Ⅲ. 증적 기반 감리 체계와 절차

```text
계약·SLA·운영 기준 → 감리 범위와 표본 선정
       ↓                      ↓
운영 로그·티켓      변경 요청·시험·배포 기록
       └──────── 교차검증 ────────┘
              → 결과 평가 → 시정조치 확인
```

### 감리 수행 절차

```text
① 감리 계획·범위 확정
    ↓
② 운영·변경 원시증적 수집
    ↓
③ 기록·실제 상태 교차검증
    ↓
④ 결과 평가·보고
    ↓
⑤ 개선 조치 이행 확인
```

### 운영과 변경 증적의 연결

```text
SLA 저하 구간 → 장애 티켓 → 원시 로그
                         ↑
                변경 요청 → 승인 → 시험 → 배포
```

같은 시간대의 서비스 결과와 변경 이력을 연결해 장애 원인과 통제 누락을 구분한다.

## Ⅳ. 운영 감리와 유지보수 감리 비교·점검영역

### 운영 감리와 유지보수 감리 비교

| 기준 | 운영 감리 | 유지보수 감리 |
|---|---|---|
| 대상 | 운영기획·관제·지원·인프라 | 기능변경·추가·보완·폐기 |
| 초점 | 가용성·성능·보안·연속성 | 요구·변경·결함·형상·계약 |
| 증적 | **SLA** ·Log·Ticket·백업·훈련 | **SR** ·승인·Commit·시험·배포 |
| 시험 | 표본복원·장애기록 재수행 | 변경 추적·회귀시험·형상감사 |
| 결과 | 운영통제 개선 | 변경품질·과업이행 개선 |

### 핵심 점검영역

| 영역 | 점검사항 | 증적 |
|---|---|---|
| 서비스 | SLA·Incident·Problem·사용자지원 | SLA 보고·Ticket·RCA |
| 성능·용량 | 병목·추세·임계치·증설 | APM·용량계획 |
| 연속성 | 백업·복구·DR·**RTO** ·**RPO** | 복원기록·훈련결과 |
| 보안 | 계정·변경·취약점·Log | 권한목록·패치·감사로그 |
| 유지보수 | SR·영향분석·시험·배포·형상 | 승인·Commit·Test Result |
| 계약 | 범위·인력·성과·검수·변경 | 계약·작업내역·검수결과 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 문서와 실제 운영 불일치 | Log·설정·Ticket 교차대조로 증적 신뢰성 확인 |
| 백업 성공만 확인 | 격리환경 표본복원·복구시간 측정으로 복구 가능성 확인 |
| SLA 평균값의 장애 은폐 | 구간·서비스별 SLI 재계산으로 품질 왜곡 확인 |
| 구두 변경·무상과업 | SR-승인-Commit-배포 추적으로 범위·책임 명확화 |
| 운영계 시험 위험 | 사전 승인·격리·Rollback·관찰자로 서비스 영향 통제 |

## Ⅵ. 제언 — 위험기반 감리계획

서비스 중요도·변경 빈도·사고 이력으로 감리 우선순위를 정하고, 고위험 서비스의 원시 증적 표본과 시정조치 확인을 확대한다.
