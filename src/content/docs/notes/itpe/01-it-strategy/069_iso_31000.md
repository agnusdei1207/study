## 지식 로드맵 내 현재 위치

IT 전략·관리 → 위험관리 → **ISO 31000**

## 30초 인출

- 본질: ISO 31000은 어떤 조직이든 목표에 영향을 주는 불확실성을 관리하도록 원칙·프레임워크·프로세스를 제시하는 위험관리 국제 지침
- 메커니즘: 원칙이 관리 방향을 정하고, 프레임워크가 리더십 아래 위험관리를 조직에 통합하며, 프로세스가 개별 결정의 위험을 평가·처리
- 통찰: 부서마다 위험 기준이 달라 전사 비교가 불가능하므로 전사 공통 위험 기준과 잔여위험 수용 권한 확정

<details>
<summary>핵심 용어</summary>

- **ISO 31000** : 조직의 위험관리를 위한 원칙·프레임워크·프로세스를 제시하는 국제 지침. 현행판은 2018판
- **위험(Risk)** : 불확실성이 목표에 미치는 영향. 긍정적·부정적 편차를 모두 포함
- **위험 기준(Risk Criteria)** : 위험의 크기와 수용 가능성을 판단하기 위해 조직이 정한 기준
- **위험평가(Risk Assessment)** : 위험 식별·분석·평가를 묶은 과정
- **위험처리(Risk Treatment)** : 위험을 다룰 대안을 선택하고 실행하는 과정
- **잔여위험(Residual Risk)** : 위험처리 후에도 남아 있는 위험
- **리더십과 의지(Leadership and Commitment)** : 프레임워크의 중심으로, 최고경영진이 위험관리의 책임·권한·자원을 부여하는 요소
- **PMBOK(Project Management Body of Knowledge)** : PMI가 정리한 프로젝트관리 지식체계. 프로젝트 목표 단위의 위험관리 절차 포함
- **ISO/IEC 27005** : 정보보안 위험관리 지침. ISO 31000의 원칙을 정보보안 위험에 적용

## 2~4교시 25점 답안

## Ⅰ. ISO 31000의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **ISO 31000** 은 목표에 영향을 주는 불확실성을 관리하기 위한 원칙·프레임워크·프로세스의 국제 지침 |
| 목적 | 가치의 창출·보호와 목표 달성 가능성 향상 |

## Ⅱ. 분야별 위험관리와 구별되는 ISO 31000의 특징

| 특징 | 의미 |
|---|---|
| 범용성 | 조직 규모·업종·위험 유형과 무관한 적용 |
| 지침 성격 | 인증 요구사항이 아닌 가이드라인 |
| 경영 통합 | 전략·계획·보고 등 모든 경영 활동에의 위험관리 통합 |
| 긍정·부정 영향 포함 | 위협뿐 아니라 기회까지 목표 편차로 취급 |

## Ⅲ. 원칙·프레임워크·프로세스 체계와 위험관리 프로세스

### ISO 31000 3요소 체계

```text
ISO 31000
    │
    ├─ 원칙 ── 가치 창출·보호 중심의 8개 원칙
    │
    ├─ 프레임워크 ── 리더십과 의지 중심
    │     └─ 통합·설계·실행·평가·개선
    │
    └─ 프로세스 ── 개별 결정의 위험 평가·처리
```

원칙은 통합·구조화 및 포괄성·맞춤화·포용성·동적 대응·최선의 가용 정보·인적 및 문화적 요인·지속적 개선

### 프로세스 확대: 위험평가·처리 절차

```text
범위·상황·위험 기준 설정
    ↓
위험 식별 → 위험 분석 → 위험 평가
    ↓
위험처리 대안 선택·실행
    ↓
잔여위험을 위험 기준과 비교
    ├─ 수용 불가 → 추가 처리
    └─ 수용 가능 → 모니터링·검토
```

전 단계에 의사소통·협의, 모니터링·검토, 기록·보고 병행

## Ⅳ. 적용 범위에 따른 위험관리 체계 비교

| 구분 | ISO 31000 | 프로젝트 위험관리(PMBOK) | ISO/IEC 27005 |
|---|---|---|---|
| 적용 범위 | 조직 전체의 모든 위험 | 단일 프로젝트 목표 | 정보보안 위험 |
| 위험 기준 설정 | 조직 차원 | 프로젝트 차원 | ISMS 범위 차원 |
| 핵심 산출 | 위험관리 프레임워크·위험 기준 | 위험 등록부·대응 계획 | 보안 위험 처리 계획 |
| 관계 | 상위 공통 원칙 | ISO 31000 원칙의 프로젝트 적용 | ISO 31000 원칙의 보안 적용 |

## Ⅴ. ISO 31000 적용의 한계와 방안

| 한계 | 방안 |
|---|---|
| 부서·프로젝트별 **위험 기준** 차이로 전사 위험 비교 불가 | 영향·가능성 척도와 수용 한계의 전사 공통 위험 기준 확정 |
| **잔여위험** 수용 결정권의 불명확 | 위험 크기 구간별 수용 권한자 지정 |
| 연 1회 평가로 끝나는 형식적 운영 | 경영 결정 자료에 위험평가 결과 포함 |
| 지침 성격으로 인한 적용 수준 편차 | 프레임워크 평가 결과의 개선 과제화 |

## Ⅵ. 제언

전사 공통 위험 기준과 위험 크기별 잔여위험 수용 권한자를 먼저 정하고, 부서·프로젝트 위험을 이 기준으로 평가해 경영 결정 자료에 반영

### 전사 위험 기준의 적용 구조

```text
전사 위험 기준 (최고경영진 승인)
    │
    ├─ 척도 ── 영향·발생 가능성 등급
    │
    ├─ 수용 한계 ── 등급별 수용 가능 여부
    │
    └─ 수용 권한 ── 등급별 잔여위험 승인자
```

### 수용 권한 확대: 잔여위험 승인 흐름

```text
부서·프로젝트의 위험처리 후 잔여위험
    ↓
전사 척도로 등급 산정
    ↓
수용 한계 비교
    ├─ 한계 이내 → 해당 등급 권한자 승인
    └─ 한계 초과 → 추가 처리 또는 상위 보고
```

### 선택 근거: 부서별 자체 기준 운영과의 비교

| 구분 | 부서별 자체 기준 | 제언: 전사 공통 기준 |
|---|---|---|
| 위험 크기 비교 | 부서 간 비교 불가 | 같은 척도로 비교 |
| 잔여위험 승인 | 담당 부서 내 판단 | 등급별 지정 권한자 |
| 경영 결정 반영 | 부서 보고서에 한정 | 전사 위험 현황으로 집계 |
