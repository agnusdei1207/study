## 지식 로드맵 내 현재 위치

IT 전략·관리 → 위험관리 → **ISO 31000**

## 30초 인출

- 본질: ISO 31000은 조직이 모든 유형의 위험을 같은 방식으로 관리하도록 원칙·프레임워크·프로세스를 제시하는 국제 지침(Guidelines)
- 메커니즘: 원칙이 지향점을, 프레임워크가 조직 내 통합 기반을, 프로세스가 개별 위험의 처리 절차를 정하며, 프로세스는 범위·상황·기준 설정에서 위험 평가·처리로 이어지고 의사소통·협의와 모니터링·검토가 전 단계에 걸침
- 통찰: 위험 기준 없이 분석 결과만 나열하면 추가 조치 여부를 판단할 근거가 없으므로 범위·상황·기준 단계에서 목표 대비 위험 기준을 먼저 정의하고 위험 평가(Risk Evaluation) 단계의 비교 기준으로 사용

<details>
<summary>핵심 용어</summary>

- **ISO 31000** : 조직이 위험을 관리하는 원칙·프레임워크·프로세스를 담은 위험관리 지침. 현행 판본은 ISO 31000:2018(제2판)
- **위험(Risk)** : 목표에 미치는 불확실성의 영향. 기대와의 차이로서 긍정·부정·양쪽이 모두 가능하며 위협과 기회를 포함
- **위험 기준(Risk Criteria)** : 조직이 목표 대비 감수할 수 있거나 없는 위험의 양과 유형, 위험 수준의 중요도를 판단하는 기준
- **위험 평가(Risk Assessment)** : 위험 식별·위험 분석·위험 평가(Risk Evaluation)를 묶은 전체 과정. 위험 평가(Risk Evaluation)는 분석 결과를 위험 기준과 비교해 추가 조치 필요 지점을 정하는 단계
- **위험 처리(Risk Treatment)** : 위험을 다루는 옵션을 선택하고 이행하는 단계

</details>

## 2~4교시 25점 답안

## Ⅰ. ISO 31000의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **ISO 31000** 은 조직의 모든 활동에 적용되는 위험관리의 원칙·프레임워크·프로세스 지침 |
| 목적 | 가치의 창출과 보호, 목표 달성에 영향을 주는 불확실성의 관리 |

## Ⅱ. 산업·규모와 무관하게 적용되는 위험관리 지침의 특징

| 특징 | 의미 |
|---|---|
| 공통 접근 | 산업·분야에 한정되지 않고 모든 유형의 위험에 적용 |
| 위협과 기회를 포함하는 **위험(Risk)** | 목표에 미치는 불확실성의 영향, 기대와의 차이가 긍정·부정·양쪽 모두 가능 |
| 지침 형식 | 조직과 상황에 맞춰 조정해 적용하는 지침 |
| 의사결정에 통합 | 별도 부서 업무가 아니라 거버넌스와 모든 수준의 의사결정의 일부 |
| 반복 수행 | 프로세스는 순차로 표현되지만 실제로는 반복 |

## Ⅲ. 원칙·프레임워크·프로세스의 3층 체계

### ISO 31000 전체 구조

```text
원칙(Principles, 4절) ── 목적: 가치의 창출과 보호
    │  통합 · 구조화·포괄 · 맞춤 · 포용
    │  동적 · 최선의 가용 정보 · 인적·문화적 요소 · 지속적 개선
    │
프레임워크(Framework, 5절) ── 리더십과 의지 아래 조직에 위험관리를 내장
    │  통합 → 설계 → 실행 → 평가 → 개선
    │
프로세스(Process, 6절) ── 개별 활동·프로젝트의 위험을 다루는 절차
       범위·상황·기준 → 위험 평가 → 위험 처리
```

### 프로세스 확대: 6절의 절차와 전 단계 활동

```text
의사소통·협의 (6.2)  ◀─ 전 단계에 걸침 ─▶  모니터링·검토 (6.6)
                                            기록·보고 (6.7)
범위·상황·기준 설정 (6.3)
    ↓
위험 평가(Risk Assessment) (6.4)
    ├─ 위험 식별 (6.4.2)
    ├─ 위험 분석 (6.4.3)
    └─ 위험 평가(Risk Evaluation) (6.4.4): 분석 결과를 위험 기준과 비교
    ↓
위험 처리 (6.5): 옵션 선택 → 계획 수립·이행 → 남은 위험 확인
```

## Ⅳ. 원칙·프레임워크·프로세스의 층위 비교

| 비교축 | 원칙 | 프레임워크 | 프로세스 |
|---|---|---|---|
| 역할 | 효과적인 위험관리의 특성 제시 | 위험관리를 조직 활동과 의사결정에 통합 | 개별 위험의 식별부터 처리·감시까지 수행 |
| 적용 단위 | 조직 전체 | 조직 전체 | 전략·운영·프로그램·프로젝트 수준별 |
| 핵심 요소 | 8개 원칙 | 리더십·통합·설계·실행·평가·개선 | 의사소통·협의, 범위·상황·기준, **위험 평가(Risk Assessment)** , **위험 처리(Risk Treatment)** , 모니터링·검토, 기록·보고 |
| 책임 주체 | 프레임워크·프로세스 수립 때 고려하는 기반 | 최고경영진(위험관리 책임)과 감독 기구(감독 책임) | 위험 관리 권한과 책임을 가진 위험 소유자 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **위험 기준(Risk Criteria)** 없이 분석 결과를 등급만 매겨 평가 단계에서 추가 조치 여부를 판단할 근거 부재 | 범위·상황·기준 단계에서 감수할 위험의 양·유형과 결과·가능성의 측정 방식을 정의하고 정기 재검토 |
| 프로세스만 도입하고 프레임워크 통합이 없어 위험 분석·평가 결과가 의사결정에 미반영 | 어떤 결정을 언제 누가 내리는지 파악해 결정 절차에 위험 분석·평가 결과의 반영 지점 지정 |
| 위험 처리 뒤에도 남는 위험이 있고 처리 자체가 새 위험을 만들 수 있음 | 남은 위험을 기록하고 처리 계획에 모니터링·검토를 포함 |

## Ⅵ. 제언

범위·상황·기준 단계에서 목표에 연결한 위험 기준을 먼저 정의하고, 위험 평가(Risk Evaluation) 단계에서 분석 결과를 그 기준과 비교하는 순서의 고정

### 위험 기준에서 처리 판단까지의 흐름

```text
조직 목표
    ↓
위험 기준 정의 (6.3.4): 감수할 위험의 양·유형, 결과·가능성의 측정 방식
    ↓
위험 분석 결과 (6.4.3)
    ↓ 위험 기준과 비교
위험 평가(Risk Evaluation) 판정 (6.4.4)
    ↓
위험 처리 계획 (6.5)
```

### 위험 평가(Risk Evaluation) 판정 확대: 비교 결과별 후속 조치

```text
분석 결과와 위험 기준의 비교
    ├─ 추가 조치 없음
    ├─ 위험 처리 옵션 검토
    ├─ 위험 이해를 위한 추가 분석
    ├─ 기존 통제 유지
    └─ 목표 재검토
```

| 구분 | 분석 결과만 나열 | 제언: 위험 기준과 비교 |
|---|---|---|
| 조치 판단 근거 | 담당자의 경험 | 사전에 정한 위험 기준 |
| 기준 정의 시점 | 없음 또는 평가 후 | 프로세스 시작 단계 |
| 기준 변경 | 명시 절차 없음 | 기준을 동적으로 재검토 |
| 평가 결과 활용 | 보고서 보관 | 처리 계획 수립의 입력 |
