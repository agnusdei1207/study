## 연관 키워드

- ISP, Information Strategy Planning, 정보화전략계획
- EA, Enterprise Architecture, To-Be 아키텍처, 이행 로드맵, 전략적 정렬

## Ⅰ. ISP의 개요

- 핵심 요약 : **정보화전략계획** (ISP, Information Strategy Planning)은 경영 전략과 IT를 연계해 중장기 정보화 비전, 아키텍처, 이행 로드맵을 수립하는 전략 계획.
- 개념 : 기업이나 공공기관의 경영 전략과 비전을 달성하기 위해 비즈니스 전략과 IT를 **전략적 정렬** (Strategic Alignment)시키고, 중장기 정보화 비전과 정보시스템 아키텍처, 이행 로드맵을 수립하는 종합 전략 계획.
- 배경 및 필요성 : 부서별 분절적 정보화로 생기는 사일로(Silo) 현상, 중복 투자, 데이터 불일치를 해결하고 전사 관점의 일관된 IT 투자와 아키텍처 기준선을 마련할 필요가 있음.
- 주요 목적 : 경영 전략 중심의 IT 비전 정립, 현행(As-Is) 분석을 통한 격차(Gap) 식별, 목표(To-Be) 모델과 아키텍처 수립, 우선순위에 따른 연차별 실행 로드맵 도출.

## Ⅱ. ISP의 특징 및 장점

- 핵심 요약 : 전사 전략과 **엔터프라이즈 아키텍처** (EA, Enterprise Architecture)를 연결해 중복 투자를 줄이고 실행 가능한 이행 순서를 확보.

1. 전략적 정렬 : 경영 목표와 IT 과제를 연결 → 투자 판단의 전사 기준 확보.
2. EA 연계 : 업무, 데이터, 기술 구조를 함께 분석 → 부서별 사일로와 중복 투자 감소.
3. As-Is/To-Be 갭 분석 : 현행 문제와 목표 구조의 차이를 명시 → 개선 과제의 근거 확보.
4. 과제 우선순위화 : 전략적 중요도, 시급성, 실행 용이성을 평가 → 한정된 예산의 집중 투자 가능.
5. 이행 로드맵 : 중장기 목표를 연차별 사업에 연결 → 추진 일정과 투자 규모의 가시성 향상.

## Ⅲ. ISP의 구조 (흐름)

- 핵심 요약 : 환경과 현황 분석, 비전과 전략 수립, 목표 모델(To-Be) 설계, 이행 계획 수립의 4단계 흐름.

```text
[ ISP 추진 흐름 ]

1. 환경 및 현황 분석
   경영환경 분석, 현행 업무·IT·데이터 분석
         ↓
2. 비전 및 전략 수립
   정보화 비전, 핵심 성공요인 (CSF), KPI 도출
         ↓
3. 목표 모델 (To-Be)
   업무·응용·데이터·기술 아키텍처 설계
         ↓
4. 이행 계획 수립
   과제 도출, 우선순위 평가, 예산 산정, 로드맵 확정
```

```text
[ As-Is → To-Be 갭 분석 ]

As-Is (현행 아키텍처)
   ↓ 격차 (Gap) 식별
To-Be (목표 아키텍처)
   ↓ 개선 과제 도출
이행 로드맵 (연차별 과제)
```

- 경영환경 분석 기법 : 거시환경 분석인 PEST (Political, Economic, Social, Technological)와 전략 환경 분석인 3C (Company, Customer, Competitor)를 활용.
- 현행 분석 기법 : 가치사슬(Value Chain) 분석으로 주활동과 지원활동의 병목을 찾고, 현행 시스템의 기능과 기술 수명 주기를 평가.
- 목표 아키텍처 설계 : EA 프레임워크와 연계해 상호운용성, 표준화, 데이터 통합 체계를 설계.

## Ⅳ. ISP 과제 도출 및 우선순위 평가의 비교

- 핵심 요약 : 전략적 중요도, 실행 용이성, 시급성의 3관점 평가와 과제 분류 체계로 이행 순서 결정.

| 평가 관점 | 평가 지표 | 평가 방법 |
| --- | --- | --- |
| 전략적 중요도 | 경영 목표 기여도, 업무 효율성, 파급 효과 | 경영진 설문, AHP (Analytic Hierarchy Process) |
| 실행 용이성 | 기술적 실현 가능성, 투자 비용, 조직 수용성 | 공수와 예산 산정, 인프라 준비도 점검 |
| 시급성 | 법적 규제 준수, 시스템 노후화, 보안 리스크 | 마일스톤 제약 분석, 자산 감가상각 연수 분석 |

| 과제 분류 | 조건 | 이행 방향 |
| --- | --- | --- |
| Quick-Win | 중요도와 실행 용이성이 모두 높음 | 단기간에 즉시 실행 |
| Strategic | 중요도는 높으나 실행 난도가 높음 | 기반 준비 후 핵심 과제로 중기 추진 |
| Long-term | 중요도는 있으나 시급성이 낮음 | 장기 로드맵에 배치하고 주기적 재평가 |
| Drop | 중요도와 실행 용이성이 모두 낮음 | 폐기 또는 보류 |

## Ⅴ. ISP의 한계와 방안

- 핵심 요약 : 계획의 진부화, 현업 참여 부족, 실현 가능성 미검증을 정기 갱신, 공동 책임, 사전 검증으로 통제.

| 한계 | 원인·영향 | 대응 방안 |
| --- | --- | --- |
| 전략 진부화 | 수립 기간 중 시장과 기술 환경이 변해 계획의 우선순위가 어긋남 | 분기별 **롤링 플랜** (Rolling Plan)으로 로드맵을 갱신하고 단기 실행 과제를 우선 검증 |
| 현업 참여 부족 | IT 부서와 외부 컨설턴트 중심 수립 시 실행 주체의 책임감과 예산 연계 약화 | 현업 책임자를 전담 조직에 포함하고 사업 핵심성과지표 (KPI, Key Performance Indicator)와 과제를 연결 |
| 목표 아키텍처의 실현성 부족 | 개념 설계만으로는 레거시 연동, 데이터 이행, 비용을 검증하기 어려움 | 핵심 과제의 개념검증 (PoC, Proof of Concept)을 수행하고 정보시스템 마스터플랜 (ISMP, Information System Master Plan)과 조기 연계 |

## Ⅵ. ISP에 대한 기술사적 제언

- 핵심 요약 : 현업 참여, 구축 사업과의 연속성, 디지털 전환과 클라우드·AI 전략의 내재화.
- 계획 수립을 IT 부서가 아닌 비즈니스 이해관계자가 주도하도록 인터뷰와 워크숍을 설계해 실행 주체의 책임감을 확보하는 것이 중요하다.
- ISP에서 도출된 이행 과제는 개별 구축 단위의 ISMP와 제안요청서 (RFP, Request for Proposal)로 자연스럽게 구체화되도록 과제 명세를 상세화해야 한다.
- 전통적인 시스템 통합 중심의 계획에서 벗어나, 클라우드 네이티브 구조, 데이터 레이크하우스, AI 확산 체계를 포함한 미래 지향적 전략으로 갱신할 필요가 있다.

## Ⅶ. 결론

- 핵심 요약 : ISP는 경영 전략과 IT를 정렬해 전사 정보화 비전, 아키텍처, 이행 로드맵을 수립하는 종합 전략 계획.
- 시사점 : 롤링 플랜과 ISMP 연계로 환경 변화와 실현 타당성 문제를 완화하는 것이 실행력 확보의 핵심.
