## 전체 로드맵 내 현재 위치

```text
▶ 01 정보 전략·관리 ─→ 02 SW공학·프로젝트 ─→ 03 데이터
          │
          └─→ 04 컴퓨터시스템 ─→ 05 네트워크 ─→ 06 보안
                                     │
                                     └─→ 07 AI·신기술
전 영역 준거 ───────────────────────────→ 08 법·정책
```

- 현재 위치: `01 정보 전략·관리 > 프로젝트 범위관리 > WBS`

## 큰 그림과 30초 인출

```text
[프로젝트 목표]
   ├─ [인도물 A]
   │    ├─ 작업패키지 A1
   │    └─ 작업패키지 A2
   └─ [인도물 B]
        └─ 작업패키지 B1
             │
       일정·원가·책임·통제계정
```

- 본질: **프로젝트 전체 범위를 관리 가능한 인도물과 작업패키지로 계층 분해한 범위 구조**
- 원칙: 100% Rule, 상호배타성, 인도물 중심, 적정 통제수준
- 구성: WBS + WBS Dictionary + Scope Baseline

## 예상문제

> WBS의 개념과 작성원칙, 구성요소 및 작성절차를 설명하고 범위·일정·원가 통합관리와 애자일 환경의 적용방안을 논하시오. (25점)

## Ⅰ. 프로젝트 범위를 계층화하는 WBS 개요

- 정의: WBS는 프로젝트 목표 달성에 필요한 전체 범위를 인도물 중심으로 작업패키지까지 계층 분해한 구조
- 목적: 범위 누락·중복을 방지하고 일정·원가·자원·책임 산정의 공통 기준 제공
- 필요성: 활동목록만으로는 전체 인도물 포함 여부와 변경이 어떤 일정·원가에 영향을 주는지 추적하기 어려움

## Ⅱ. 완전성과 통제 가능성을 보장하는 작성원칙

| 원칙 | 핵심 내용 | 판정 질문 |
|---|---|---|
| 100% Rule | 상위 범위는 직계 하위 범위의 합 | 전체 범위가 빠짐없이 포함됐는가 |
| 상호배타성 | 작업패키지 간 범위 중복 방지 | 같은 산출물이 이중 집계되는가 |
| 인도물 중심 | 해야 할 행동보다 완료결과 표현 | 완료를 객관적으로 검수 가능한가 |
| 적정 분해 | 추정·배정·통제가 가능한 수준 | 지나치게 크거나 세밀하지 않은가 |
| 추적 가능성 | 요구·산출물·일정·원가·책임 연결 | 변경 영향이 추적되는가 |

## Ⅲ. WBS·Dictionary·기준선의 구성

| 구성요소 | 내용 | 활용 |
|---|---|---|
| WBS Element | 프로젝트·단계·인도물·작업패키지 계층 | 범위 구조·코드 |
| Work Package | 최하위 관리단위 | 일정·원가·책임 추정 |
| Control Account | 범위·일정·원가 통합 통제지점 | 성과측정·EVM |
| WBS Dictionary | 설명·경계·완료기준·책임·가정 | 모호성·중복 제거 |
| Scope Baseline | Scope Statement+WBS+Dictionary | 변경통제 기준 |

```text
요구사항 → 인도물 → Work Package → Activity
              │            │            │
            검수기준     원가·책임      일정·자원
```

## Ⅳ. 범위에서 기준선까지의 WBS 작성절차

```text
① 범위·요구·인도물 검토 → ② 최상위 분해기준 선택 → ③ 하위 인도물 분해
 → ④ Work Package 판정 → ⑤ WBS Code·Dictionary 작성 → ⑥ 100%·중복 검증 → ⑦ 기준선 승인
```

| 단계 | 핵심 활동 | 완료 기준 |
|---|---|---|
| 식별 | 제품·서비스·결과 인도물 도출 | 요구사항과 인도물 연결 |
| 분해 | 관리 가능한 하위 범위로 반복 분할 | 추정·책임·검수가 가능 |
| 명세 | 경계·산출물·완료기준·가정 기술 | Dictionary로 해석 일치 |
| 검증 | 100%·중복·외부작업·관리작업 확인 | 누락·중복 제거 |
| 승인 | 범위 기준선과 변경절차 확정 | 공식 통제 기준 확보 |

## Ⅴ. WBS·PBS·OBS 및 전통형·애자일 적용 비교

| 구분 | WBS | PBS | OBS |
|---|---|---|---|
| 분해대상 | 프로젝트 전체 범위 | 제품 구성품 | 수행 조직·책임 |
| 최하위 | Work Package | Component | 조직단위 |
| 연결 | 일정·원가·책임 기준 | 제품범위 검증 | 책임 배정 |

| 전통형 | 애자일·하이브리드 |
|---|---|
| 기준선 WBS를 상세 분해 | Release/Epic 수준 WBS와 Backlog 연결 |
| 변경위원회로 Scope 통제 | 우선순위 조정하되 목표·예산 경계 통제 |
| Activity는 Schedule에서 관리 | Story·Task는 Iteration에서 상세화 |

## Ⅵ. WBS의 과소·과대 분해를 막는 고려사항

| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 범위 누락 | 기능만 분해하고 전환·교육·관리 제외 | 인도물·생명주기·외부조달 Checklist 검증 | 전체 범위 확보 |
| 중복 원가 | 조직별로 같은 산출물을 중복 편성 | 산출물 Owner와 경계·인수조건 명시 | 이중계상 방지 |
| 과도한 세분화 | 획일적 시간 규칙 적용 | 위험·복잡도·보고주기 기준으로 분해 | 관리비용 절감 |
| WBS와 일정 단절 | Work Package와 Activity ID 불연계 | Code 기반 Schedule·Cost·RACI 연동 | 통합 변경영향 분석 |
| 애자일 Scope Creep | Backlog 추가를 기준선 변경과 분리 | Epic/Release 예산경계와 Trade-off 규칙 | 가치와 통제 균형 |

## Ⅶ. WBS를 정적 목차가 아닌 통합 기준선으로 운영

- **[요구-인도물-WP-일정-원가-책임 추적성]**: WBS를 착수 문서로만 두면 실제 Backlog·일정·원가 변경이 범위 기준선과 분리됨
- 나라면: WBS Code를 요구사항·Schedule·Cost·RACI·검수기준의 공통키로 사용하고 변경 시 영향도와 대체 범위를 함께 승인

#### 한줄 요약

- WBS의 완성은 잘게 나눈 그림이 아니라 모든 범위가 일정·원가·책임·검수에 연결된 상태임

## 1교시 10점 답안 발췌

```text
프로젝트 → 인도물 → Work Package → Activity
                     └─ Dictionary·일정·원가·책임
```

| 원칙 | 핵심 |
|---|---|
| 100% | 상위는 하위 범위의 합 |
| 상호배타 | 중복 범위·원가 방지 |
| 적정분해 | 추정·배정·검수 가능한 수준 |

- 차별화: WBS Code를 요구·일정·원가·RACI·검수의 공통키로 사용
