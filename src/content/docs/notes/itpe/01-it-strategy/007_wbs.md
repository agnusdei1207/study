## 연관 키워드

- WBS, Work Breakdown Structure, 작업 분류 체계
- 100% Rule, Work Package, WBS Dictionary, Scope Baseline, MECE

## Ⅰ. WBS의 개요

- 핵심 요약 : 프로젝트 전체 범위를 계층적으로 분할하여 일정·비용 산정의 기본 단위를 제공하는 작업 분류 체계.
- 개념 : 프로젝트 목표를 달성하고 필요한 인도물을 산출하기 위해 프로젝트 전체 범위를 계층적으로 분할한 작업 분류 체계 (**WBS**, Work Breakdown Structure).
- 배경 및 필요성 : 대형 프로젝트의 복잡성으로 인해 전체 범위 파악이 어렵고 일정/비용 누락이 발생하는 문제를 방지하기 위해 체계적인 범위 정의 기준선 (Scope Baseline) 필요.
- 주요 목적 : 전체 범위의 가시화, 일정 및 원가 산정의 기본 단위 제공, 작업 패키지별 책임자 할당, 범위 변경 통제의 기준선 확립.

## Ⅱ. WBS의 특징 및 장점

- 핵심 요약 : **100% 규칙**과 인도물 중심 분할로 범위 누락을 줄이고 산정·책임·변경 통제의 기준을 만든다.
1. **100% 규칙** : 상위 범위를 하위 요소가 빠짐없이 구성하도록 확인해 누락·중복을 줄인다.
2. **인도물 중심 분할** : 완료 가능한 결과물로 범위를 나누어 검수 기준을 명확히 한다.
3. **작업 패키지** : 일정·원가를 추정할 수 있는 단위까지 분해해 담당자와 공수를 배정한다.
4. **WBS 사전** : 작업 범위·인수 기준·책임자를 기록해 이해관계자의 해석 차이를 줄인다.
5. **범위 기준선** : WBS와 사전을 변경 통제의 기준으로 사용해 무단 범위 확대를 감지한다.

## Ⅲ. WBS의 구조 (흐름)

- 핵심 요약 : 프로젝트 전체→단계·인도물→하위 작업군→작업 패키지로 이어지는 4레벨 계층 구조.

```text
[ WBS 계층 구조 ]
Level 1 : 프로젝트 전체
   ── (Project Title)
      ↓ 분할
Level 2 : 단계·주요 인도물
   ── (Phase / Deliverable)
      ↓ 분할
Level 3 : 하위 작업군
   ── (Sub-deliverable)
      ↓ 분할
Level 4 : 작업 패키지 (Work Package)
   ── 관리의 최하위 단위
```

```text
[ Scope Baseline 구성 흐름 ]
프로젝트 범위 기술서
   ↓
WBS (트리 다이어그램)
   ↓
WBS Dictionary (사전)
   ↓
범위 기준선 (Scope Baseline) 확립
```

- 프로젝트 범위 기술서 : 프로젝트 목표, 주요 인도물, 가정사항, 제약조건 명시.
- WBS : 작업과 인도물을 계층 구조로 시각화한 트리 다이어그램.
- WBS 사전 (Dictionary) : WBS 각 코드별 세부 작업 내용, 담당자, 승인 기준, 마일스톤, 연관 산출물 상세 기술.

## Ⅳ. WBS와 애자일 백로그의 비교

- 핵심 요약 : WBS는 정적 범위 기준선, 애자일 백로그는 점진적 요구 변화 수용이라는 관리 방식 차이.

```text
[ 전통 WBS ] ── 정적 범위 기준선
       ↕ 하이브리드 연계
[ 애자일 백로그 ] ── Epic → Feature → Story
```

| 비교 항목 | WBS (전통) | 애자일 백로그 |
|---|---|---|
| 관리 단위 | 작업 패키지 (Work Package) | Epic / Feature / Story |
| 범위 변경 | 통합 변경 통제 (Integrated Change Control) | 백로그 우선순위 재조정 |
| 일정 산정 | CPM 기반 고정 일정 | 스프린트 단위 반복 |
| 적합 환경 | 요구사항 고정 대형 프로젝트 | 요구사항 진화 반복 개발 |
| 추적 방식 | 진척률·원가 코드 추적 | 번다운·번다운 차트 |

## Ⅴ. WBS의 한계와 방안

- 핵심 요약 : 범위 누락·분할 수준·변경 빈도를 관리해야 WBS가 실제 기준선으로 기능한다.

| 한계 | 방안 |
|---|---|
| 비기능·이행 작업이 빠지면 **100% 규칙**이 깨짐 | 인도물 목록과 요구사항 추적표를 대조해 누락·중복 점검 |
| 작업 패키지가 너무 크거나 작으면 **산정·진척 추적** 왜곡 | 책임자와 완료 기준을 정할 수 있는 수준으로 분해하고 주기적으로 조정 |
| 요구가 자주 바뀌면 정적 WBS의 **유지 비용** 증가 | 상위 인도물은 유지하고 하위 작업은 **점진적 상세화**와 백로그로 갱신 |

## Ⅵ. WBS에 대한 기술사적 제언

- 핵심 요약 : 인도물 중심 분할, 형상관리·변경 통제 연계, 애자일 하이브리드 융합.
- 인도물 (Deliverable) 중심의 분할 : 단순한 액티비티 (동사형) 나열이 아닌 구체적인 결과물 (명사형 인도물) 중심으로 분할하여 완료 여부의 객관적 판정 보장.
- 형상관리 및 변경 통제 연계 : 프로젝트 진행 중 발생하는 범위 추가/변경 요청은 반드시 통합 변경 통제 (Integrated Change Control) 절차를 거쳐 WBS와 WBS 사전에 동기화.
- 애자일 에픽/스토리 백로그와의 융합 : 대규모 하이브리드 프로젝트에서는 상위 레벨은 WBS로 거버넌스를 통제하고, 작업 패키지 레벨은 스프린트 백로그로 분할하여 기민성 확보.

## Ⅶ. 결론

- 핵심 요약 : WBS는 프로젝트 범위를 계층 분할하여 산정·책임 할당·변경 통제의 기준선을 제공하는 체계.
- 요약 : 100% Rule과 Work Package, WBS Dictionary를 통해 범위 누락 없이 일정·원가 관리를 지원.
- 시사점 : 애자일 환경에서는 Rolling Wave Planning과 하이브리드 연계로 정적 WBS의 한계를 보완.
