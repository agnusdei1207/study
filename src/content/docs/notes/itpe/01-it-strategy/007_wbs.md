## 지식 로드맵 내 현재 위치

IT 전략·관리 → 프로젝트 관리 → **WBS**

## 30초 인출

- 본질: WBS(Work Breakdown Structure)는 프로젝트 범위 전체를 산출물 중심의 계층으로 나누어 일정·비용·책임을 붙일 수 있는 작업 단위까지 세분한 구조
- 메커니즘: 범위 기술서·요구사항 문서에서 산출물을 분할(Decomposition)하고, 각 단계의 하위 요소 합이 상위 요소의 작업 전체와 같도록(100% 규칙) 작업 패키지까지 내린 뒤 WBS 사전으로 요소별 내용을 정의
- 통찰: 요구사항에 없는 작업이 섞이거나 요구사항의 작업이 빠지면 일정·비용 산정이 함께 어긋나므로 WBS 요소와 요구사항의 교차 대조로 누락과 범위 밖 작업을 확정 전에 식별

<details>
<summary>핵심 용어</summary>

- **WBS(Work Breakdown Structure)** : 프로젝트 범위 전체를 산출물 중심으로 계층 분할한 구조
- **분할(Decomposition)** : 산출물을 더 작고 관리 가능한 구성요소로 세분하는 기법
- **100% 규칙** : 하위 요소 작업의 합이 상위 요소의 작업 전체와 같고 프로젝트 범위 밖의 작업은 없어야 한다는 WBS 작성 원칙
- **작업 패키지(Work Package)** : WBS 최하위 요소로 일정 수립·비용 추정·감시·통제의 대상이 되는 작업 단위
- **계획 패키지(Planning Package)** : 아직 작업 패키지로 정의할 수 없는 먼 미래의 작업을 요약 수준으로 묶은 단위
- **통제 계정(Control Account)** : WBS 요소와 담당 조직이 만나는 지점에서 범위·비용·일정을 추적하는 관리 통제점
- **WBS 사전(WBS Dictionary)** : WBS 각 요소의 코드·작업 내용·산출물·담당 조직·마일스톤을 정의한 문서
- **범위 기준선(Scope Baseline)** : 승인된 범위 기술서와 WBS, WBS 사전으로 이루어진 범위 통제의 비교 기준
- **교차 대조표(Cross-Reference Matrix)** : 요구사항 문서의 항목과 WBS 요소를 두 축으로 놓고 대응을 표시해 대응 없는 요소와 항목을 찾는 표 (NASA WBS 핸드북의 용어)

## 2~4교시 25점 답안

## Ⅰ. WBS의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **WBS(Work Breakdown Structure)** 는 프로젝트 수행에 필요한 작업 전체를 산출물 중심으로 계층 분할한 구조 |
| 목적 | 범위의 누락·중복 방지와 일정·비용·책임 배정의 기준 마련 |

## Ⅱ. 관리 기준이 되는 WBS의 특징

| 특징 | 의미 |
|---|---|
| 산출물 중심 | 작업 수행 방법이 아니라 만들어질 제품·문서 같은 결과물로 분할 |
| **100% 규칙** | 하위 요소의 합이 상위 요소 작업 전체와 일치, 범위 밖 작업 배제 |
| 상호 배타 | 하나의 작업이 둘 이상의 WBS 요소에 배정되지 않도록 요소 경계 구분 |
| 계층·코드 | 요소마다 명확한 제목과 번호 체계를 부여해 하위 실적이 상위로 집계 |

## Ⅲ. WBS 작성 절차와 분할 구조

### WBS 작성 방법

```text
범위 기술서·요구사항 문서 확인
    ↓
분할(Decomposition): 프로젝트 → 주요 산출물 → 하위 산출물
    ├─ 각 단계에서 하위 요소 합 = 상위 요소 작업 전체 (100% 규칙)
    └─ 요소마다 코드 부여
    ↓
관리 가능한 수준에서 분할 종료
    ├─ 근시일 작업 → 작업 패키지
    └─ 먼 미래 작업 → 계획 패키지(요약 수준 유지)
    ↓
WBS 사전 작성: 코드·작업 내용·산출물·담당 조직·마일스톤
    ↓
범위 기준선 승인: 범위 기술서 + WBS + WBS 사전
```

### 분할 확대: 산출물 계층과 100% 규칙 검증 (정보시스템 구축 사례)

```text
1. 정보시스템 구축 프로젝트
    │
    ├─ 1.1 요구분석·설계 산출물
    ├─ 1.2 응용소프트웨어
    │      ├─ 1.2.1 업무 모듈 A
    │      └─ 1.2.2 업무 모듈 B
    ├─ 1.3 인프라
    ├─ 1.4 시험·이행
    └─ 1.5 프로젝트 관리
```

- 1.1~1.5 의 합이 프로젝트 전체 작업, 1.2.1과 1.2.2의 합이 1.2 전체
- 프로젝트 관리 작업도 별도 요소로 포함해 누락 방지

## Ⅳ. WBS 요소의 층위 구분

| 층위 | 정의 | 관리 대상 | 정의 상세도 |
|---|---|---|---|
| 프로젝트 | WBS 최상위 요소로 프로젝트 전체 | 총 범위 | 범위 기술서 수준 |
| 주요 산출물 요소 | 프로젝트를 이루는 큰 제품·기능 단위 | 산출물별 집계 | 요소 목적·경계 |
| **통제 계정(Control Account)** | 담당 조직에 관리 책임을 맡기는 지점 | 범위·비용·일정 통합 추적 | 담당·예산 단위 |
| **작업 패키지(Work Package)** | 통제 계정 아래 근시일 작업 단위 | 일정·비용 추정·감시 | 작업 내용·산출물·마일스톤 |
| **계획 패키지(Planning Package)** | 통제 계정 안의 먼 미래 작업 묶음 | 상위 수준의 예산 배정 | 요약 수준 |

- 분할 깊이는 통제 계정 수준을 최소로 하고, 그 아래는 관리에 필요한 만큼만 세분
- WBS 사전은 하위 요소일수록 상세하게 기술

## Ⅴ. WBS 작성의 한계와 방안

| 한계 | 방안 |
|---|---|
| 요구사항의 작업이 WBS에 없어 일정·비용에 미반영 | 요구사항 항목과 WBS 요소의 교차 대조로 대응 없는 항목 식별 |
| 요구사항에 없는 작업이 WBS에 포함되어 범위 밖 비용 발생 | 교차 대조표에서 대응 요구사항이 없는 요소를 제거하거나 요구사항으로 정식 추가 |
| 둘 이상의 요소에 걸친 작업으로 책임과 산정이 중복 | WBS 사전에 요소별 작업 범위와 인터페이스를 명시해 경계 확정 |
| 먼 미래 작업까지 세분해 정보 확정 후 잦은 수정 | 근시일 작업만 작업 패키지로 정의하고 나머지는 계획 패키지로 유지 후 구체화 |
| 범위 변경이 WBS와 WBS 사전에 부분 반영 | WBS 사전을 기준선 문서로 관리하고 변경 승인 시 함께 갱신 |

## Ⅵ. 제언

WBS 확정 전 요구사항과 WBS 요소의 교차 대조를 범위 기준선 승인의 선행 조건으로 설정

### 교차 대조가 들어가는 위치

```text
요구사항 문서 ──────┐
                    ├─ 교차 대조 ── 범위 기준선 승인 ── 일정·비용 산정
WBS + WBS 사전 ─────┘      │
                           └─ 미대응 항목 → 요구사항·WBS 보완 후 재대조
```

### 교차 대조표 확대: 누락과 범위 밖 작업의 판별

```text
             WBS 1.1  WBS 1.2.1  WBS 1.2.2  WBS 1.3
요구 R1        X
요구 R2                 X
요구 R3                                        X
요구 R4        (대응 요소 없음) → 누락: WBS 요소 추가
WBS 1.2.2 열에 대응 요구 없음  → 범위 밖 작업: 제거 또는 요구사항 추가
```

- 요구 행 기준으로 대응 요소가 없으면 누락, WBS 요소 열 기준으로 대응 요구가 없으면 범위 밖 작업

### 선택 근거: WBS 단독 검토와의 비교

| 구분 | WBS 단독 검토 | 제언: 요구사항 교차 대조 |
|---|---|---|
| 확인 기준 | WBS 내부의 계층·번호 | 요구사항 항목과 WBS 요소의 대응 |
| 누락 발견 | 산정·수행 단계 | 범위 기준선 승인 전 |
| 범위 밖 작업 | 발견 수단 없음 | 대응 요구가 없는 요소로 식별 |
