## 연관 키워드

- WBS, Work Breakdown Structure, 작업 분류 체계
- 100% Rule, Work Package, WBS Dictionary, Scope Baseline, MECE

## Ⅰ. WBS의 개요

- 핵심 요약 : **작업 분류 체계** (WBS, Work Breakdown Structure)는 프로젝트 전체 범위를 계층적으로 분할해 일정과 비용 산정의 기본 단위를 제공하는 체계.
- 개념 : 프로젝트 목표를 달성하고 필요한 인도물을 산출하기 위해 프로젝트 전체 범위를 계층적으로 분할한 작업 분류 체계.
- 배경 및 필요성 : 대형 프로젝트는 전체 범위 파악이 어렵고 일정과 비용이 누락되기 쉬워, 체계적인 **범위 기준선** (Scope Baseline)이 필요.
- 주요 목적 : 전체 범위의 가시화, 일정과 원가 산정의 기본 단위 제공, 작업 패키지별 책임자 할당, 범위 변경 통제의 기준선 확립.

## Ⅱ. WBS의 특징 및 장점

- 핵심 요약 : **100% 규칙** (100% Rule)과 인도물 중심 분할로 범위 누락을 줄이고, 산정, 책임, 변경 통제의 기준을 만드는 체계.

1. **100% 규칙** (100% Rule) : 상위 범위를 하위 요소가 빠짐없이 구성하도록 확인해 누락을 줄임. 하위 요소가 서로 겹치지 않도록 **MECE** (Mutually Exclusive and Collectively Exhaustive, 상호 배타적이고 전체 포괄적인 원칙)를 함께 적용해 중복도 줄임.
2. 인도물 중심 분할 : 완료 가능한 결과물 단위로 범위를 나누어 검수 기준을 명확히 함.
3. **작업 패키지** (Work Package) : 일정과 원가를 추정할 수 있는 단위까지 분해해 담당자와 공수를 배정.
4. **WBS 사전** (WBS Dictionary) : 작업 범위, 인수 기준, 책임자를 기록해 이해관계자의 해석 차이를 줄임.
5. 범위 기준선 : WBS와 사전을 변경 통제의 기준으로 사용해 무단 범위 확대를 감지.

## Ⅲ. WBS의 구조 (흐름)

- 핵심 요약 : 프로젝트 전체에서 단계와 인도물, 하위 작업군을 거쳐 작업 패키지까지 내려가는 4레벨 계층 구조.

```text
[ WBS 계층 구조 ]

Level 1 : 프로젝트 전체
         ↓ 분할
Level 2 : 단계·주요 인도물
         ↓ 분할
Level 3 : 하위 작업군 (하위 인도물)
         ↓ 분할
Level 4 : 작업 패키지
   ── 관리의 최하위 단위
```

```text
[ 범위 기준선 구성 흐름 ]

프로젝트 범위 기술서
   ↓
WBS (트리 다이어그램)
   ↓
WBS 사전 (코드별 상세 기술)
   ↓
범위 기준선 확립
```

- 프로젝트 범위 기술서 : 프로젝트 목표, 주요 인도물, 가정 사항, 제약 조건을 명시.
- WBS : 작업과 인도물을 계층 구조로 시각화한 트리 다이어그램.
- WBS 사전 : 각 WBS 코드별 세부 작업 내용, 담당자, 승인 기준, 마일스톤, 연관 산출물을 상세 기술.

## Ⅳ. WBS와 애자일 백로그의 비교

- 핵심 요약 : WBS는 정적 범위 기준선, 애자일 백로그는 점진적 요구 변화를 수용하는 관리 방식이라는 차이.

```text
[ 전통 WBS ] ── 정적 범위 기준선
       ↕ 하이브리드 연계
[ 애자일 백로그 ] ── 에픽 → 피처 → 스토리
```

| 비교 항목 | WBS (전통 방식) | 애자일 백로그 |
| --- | --- | --- |
| 관리 단위 | 작업 패키지 | 에픽 (Epic), 피처 (Feature), 스토리 (Story) |
| 범위 변경 | **통합 변경 통제** (Integrated Change Control) | 백로그 우선순위 재조정 |
| 일정 산정 | **임계 경로법** (CPM, Critical Path Method) 기반 고정 일정 | 스프린트 단위 반복 |
| 적합 환경 | 요구사항이 고정된 대형 프로젝트 | 요구사항이 진화하는 반복 개발 |
| 추적 방식 | 진척률과 원가 코드 추적 | 번다운 차트 (Burndown Chart) |

## Ⅴ. WBS의 한계와 방안

- 핵심 요약 : 범위 누락, 분할 수준, 변경 빈도를 관리해야 WBS가 실제 기준선으로 기능.

| 한계 | 원인·영향 | 대응 방안 |
| --- | --- | --- |
| 비기능 및 이행 작업 누락 | 누락되면 100% 규칙이 깨져 일정과 원가가 과소 산정됨 | 인도물 목록과 요구사항 추적표를 대조해 누락과 중복 점검 |
| 작업 패키지의 과대 또는 과소 분해 | 산정과 진척 추적이 왜곡되어 관리 정확도 저하 | 책임자와 완료 기준을 정할 수 있는 수준으로 분해하고 주기적으로 조정 |
| 잦은 요구 변경 | 정적 WBS를 자주 고쳐야 해 유지 비용 증가 | 상위 인도물은 유지하고 하위 작업은 **단계적 상세화** (Rolling Wave Planning)와 백로그로 갱신 |

## Ⅵ. WBS에 대한 기술사적 제언

- 핵심 요약 : 인도물 중심 분할, 형상관리와 변경 통제 연계, 애자일 하이브리드 융합.
- 동사형 액티비티 나열이 아닌 완료 여부를 객관적으로 판정할 수 있는 명사형 인도물 기준 분할.
- 프로젝트 중 발생하는 범위 추가와 변경 요청의 **통합 변경 통제** (Integrated Change Control) 절차를 통한 WBS와 WBS 사전 동기화.
- 대규모 하이브리드 프로젝트에서 상위 레벨 WBS 관리와 작업 패키지 수준 스프린트 백로그 분할을 통한 거버넌스와 기민성 확보.

## Ⅶ. 결론

- 핵심 요약 : WBS는 프로젝트 범위를 계층 분할해 산정, 책임 할당, 변경 통제의 기준선을 제공하는 체계.
- 시사점 : 애자일 환경에서는 단계적 상세화와 하이브리드 연계로 정적 WBS의 한계를 보완하는 것이 필요.
