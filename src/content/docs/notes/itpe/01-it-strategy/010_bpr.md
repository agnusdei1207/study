## 큰 그림과 30초 인출

```text
As-Is: 고객 → 부서A → 대기 → 부서B → 재입력 → 부서C
                         │ 근본적 재검토
                         ▼
To-Be: 고객 → [End-to-End Process Owner + IT/AI] → 결과
        비전 → 대상 → 진단 → 재설계 → 구현·정착
```

- 본질: **고객가치와 성과의 극적 향상을 위해 핵심 업무프로세스를 근본적·급진적으로 재설계하는 경영혁신**
- 4대 특성: 근본적, 급진적, 극적, 프로세스 중심
- 암기: `비-대-진-설-정` = 비전 → 대상 → 진단 → 설계 → 정착

## 예상문제

> BPR의 개념과 특징, 수행절차를 설명하고 PI·ISP와 비교한 후 AI 기반 BPR의 기대효과와 고려사항을 논하시오. (25점)

## Ⅰ. 고객가치 중심의 급진적 프로세스 재설계, BPR 개요

- 정의: BPR은 비용·품질·서비스·속도 등 핵심 성과를 비약적으로 개선하기 위해 기존 업무의 전제와 경계를 근본적으로 재검토하고 End-to-End 프로세스를 급진적으로 재설계하는 활동
- 목적: 기능조직 간 인계·대기·중복·재작업을 제거하고 고객가치 흐름과 책임을 일원화
- 필요성: 기존 절차를 그대로 자동화하면 비효율이 빠르게 반복될 뿐 조직·데이터·의사결정 단절은 남음

## Ⅱ. BPR의 4대 특징과 성공원칙

| 특징 | 핵심 질문 | 실행 의미 |
|---|---|---|
| 근본적 | 왜 이 일을 하고 왜 이 방식인가 | 가정·규칙·통제의 필요성 재검토 |
| 급진적 | 기존 구조를 얼마나 재구성할 것인가 | 부서 경계·직무·권한 재설계 |
| 극적 | 점진개선으로 부족한 성과격차인가 | 비용·품질·속도·서비스의 비약 |
| 프로세스 중심 | 고객가치를 누가 끝까지 책임지는가 | End-to-End Owner·성과지표 |

- 성공원칙: 경영진 후원, 명확한 Case for Change, 현업 참여, IT Enabler, 변화관리, 성과책임

## Ⅲ. 전략·프로세스·조직·IT·성과의 BPR 구성

```text
[전략·고객가치]
       ↓
[End-to-End Process] ──▶ [조직·역할·권한]
       │                         │
       └──── [Data·IT·AI] ──────┘
                    ↓
          비용·품질·속도·서비스 KPI
```

| 구성 | 핵심 내용 | 산출물 |
|---|---|---|
| 전략·고객 | 혁신목표·고객 Journey·성과격차 | 비전·KPI |
| 프로세스 | As-Is 문제·To-Be 가치흐름 | Process Map·업무규칙 |
| 조직 | Owner·직무·권한·성과책임 | R&R·운영모델 |
| IT·데이터 | 통합·자동화·의사결정 Enabler | 요구·Architecture |
| 변화·성과 | 역량·소통·전환·KPI 관리 | 변화계획·성과대시보드 |

## Ⅳ. 비전에서 정착까지의 BPR 수행절차

```text
① 혁신비전·KPI → ② 대상 Process 선정 → ③ As-Is·Root Cause
 → ④ Zero-base To-Be 설계 → ⑤ 조직·IT·통제 상세화
 → ⑥ Pilot·전환 → ⑦ 성과측정·정착
```

| 단계 | 핵심 질문 | 통과 기준 |
|---|---|---|
| 비전·선정 | 왜 지금 어떤 프로세스를 바꾸는가 | 고객·전략·성과격차 명확 |
| 진단 | 가치 없는 대기·인계·재작업 원인은 무엇인가 | 증거기반 Bottleneck |
| 재설계 | 제거·통합·병렬화·자동화할 것은 무엇인가 | To-Be와 통제·예외 |
| 구현 | 조직·데이터·시스템이 함께 바뀌는가 | Owner·요건·전환계획 |
| 정착 | 성과와 행동이 지속되는가 | KPI·교육·Feedback |

## Ⅴ. BPR·PI·ISP 비교

| 구분 | BPR | PI | ISP |
|---|---|---|---|
| 목적 | 핵심 프로세스 급진 재설계 | 기존 프로세스의 지속·점진 개선 | 정보화 비전·과제·로드맵 수립 |
| 출발 | 고객가치·성과격차 | 운영문제·낭비 | 경영전략·IT 현황 |
| 변화폭 | 근본적·급진적 | 점진적·반복적 | 전략·Portfolio 중심 |
| 산출물 | To-Be Process·조직·KPI | 개선안·표준업무 | 목표모델·과제·이행계획 |
| 관계 | To-Be 업무가 IT 요구를 만든다 | BPR 이후 지속개선 | BPR 결과를 정보화과제로 구체화 가능 |

## Ⅵ. AI 기반 BPR의 효과와 위험 통제

| 문제·기회 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 비효율을 그대로 자동화 | Tool 도입이 목표, As-Is 폐기 부족 | 제거→단순화→통합 후 자동화 | 불필요 업무 제거 |
| AI 오판으로 권리침해 | 의사결정 위임·설명·감독 미설계 | 위험등급·Human Gate·이의제기·로그 | 책임 있는 자동화 |
| 예외 처리 실패 | 정상경로만 설계 | 예외유형·Fallback·수동대체·중단권한 | 운영 회복력 확보 |
| 현업 저항·우회절차 | 역할·평가·역량 변화 미관리 | Process Owner·Co-design·교육·KPI 정렬 | 정착률 향상 |
| 성과 착시 | 처리시간만 측정 | 고객결과·품질·오류·통제비용 KPI 병행 | 순효과 검증 |

## Ⅶ. 자동화보다 프로세스 폐기와 책임 재설계를 우선

- **[Eliminate-Simplify-Integrate-Automate 순서]**: AI Agent를 기존 승인·재입력 단계 위에 얹으면 복잡성과 책임공백만 커짐
- 나라면: 고객가치 없는 단계를 먼저 제거·통합하고 AI가 판단하는 구간에는 Human Gate·이의제기·감사로그를 설계한 뒤 Pilot 성과로 단계 확산

#### 한줄 요약

- BPR의 완성은 자동화율이 아니라 고객가치 흐름과 책임이 단순해지고 성과가 지속되는 상태임

## 1교시 10점 답안 발췌

```text
As-Is 진단 → 제거·통합·병렬화 → To-Be Process → 조직·IT → 정착
```

| 4대 특성 | 의미 |
|---|---|
| 근본적·급진적 | 가정과 기존 구조를 원점 재검토 |
| 극적 | 비용·품질·속도·서비스의 비약적 개선 |
| 프로세스 중심 | 부서가 아닌 End-to-End 고객가치 책임 |

- 차별화: `Eliminate→Simplify→Integrate→Automate` 후 AI 구간에 사람 감독·이의제기·로그 설계
