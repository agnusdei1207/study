## 30초 인출

- 본질: BPR(Business Process Reengineering)은 비용·품질·서비스·속도의 극적 향상을 위해 업무 프로세스를 근본부터 다시 설계하는 경영 혁신 기법
- 메커니즘: 성과 목표를 정하고 현행 프로세스를 분석한 뒤, 불필요한 활동의 제거·통합을 거친 목표 프로세스에 정보기술을 적용
- 통찰: 기존 절차를 그대로 자동화하면 낭비까지 빨라지므로 자동화 전 활동별 제거·통합 판정과 Process Owner의 종단 성과 책임

<details>
<summary>핵심 용어</summary>

- **BPR(Business Process Reengineering)** : 비용·품질·서비스·속도의 극적 향상을 위해 업무 프로세스를 근본적으로 재고하고 급진적으로 재설계하는 경영 혁신 기법
- **CPI(Continuous Process Improvement)** : 현행 프로세스를 유지하면서 단계적으로 성과를 높이는 지속적 개선 방식. BPR과 변화 폭으로 구별
- **E2E(End-to-End) 프로세스** : 고객 요청부터 결과 제공까지 부서 경계를 넘어 이어지는 업무 전체 흐름
- **Process Owner(프로세스 책임자)** : 부서를 넘어 E2E 프로세스 전체의 성과와 변경을 책임지는 관리자
- **As-Is·To-Be** : 현행 프로세스와 재설계 후 목표 프로세스

## 2~4교시 25점 답안

## Ⅰ. BPR의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **BPR(Business Process Reengineering)** 은 비용·품질·서비스·속도의 극적 향상을 위해 업무 프로세스를 근본적으로 재고하고 급진적으로 재설계하는 경영 혁신 기법 |
| 목적 | 고객가치 중심의 업무 흐름 재편과 핵심 성과의 비약적 향상 |

## Ⅱ. Hammer·Champy 정의의 네 가지 특징

| 특징 | 의미 |
|---|---|
| 근본적(Fundamental) | 현행 업무의 존재 이유부터 재검토 |
| 급진적(Radical) | 기존 구조의 보완이 아닌 새로운 방식의 설계 |
| 극적(Dramatic) | 소폭 개선이 아닌 핵심 성과의 비약적 향상 |
| 프로세스(Process) | 부서·기능이 아닌 **E2E 프로세스** 단위의 설계 |

## Ⅲ. BPR 수행 절차와 재설계 방식

### BPR 수행 절차

```text
비전·성과 목표 설정
    ↓
대상 프로세스 선정 ── 성과 격차·고객 영향 기준
    ↓
As-Is 분석 ── 대기·중복·재작업 식별
    ↓
To-Be 재설계
    ↓
정보기술 적용·조직 전환
    ↓
성과 측정
    └─ 목표 미달 → To-Be 재설계로 환류
```

### To-Be 재설계 확대: 활동 재구성 순서

```text
As-Is 활동 목록
    ↓
고객가치 기여 여부 판정
    ├─ 기여 없음 → 제거
    └─ 기여 있음
          ↓
    부서 간 인계·중복 확인 → 통합·병렬화
          ↓
    의사결정 지점의 현장 이양
          ↓
    남은 활동의 정보기술 자동화
```

Hammer(1990)의 원칙인 `자동화하지 말고 없애라(Don't Automate, Obliterate)`의 반영 순서

## Ⅳ. 업무 개선 방식의 비교

| 구분 | 현행 절차 자동화 | CPI(지속적 개선) | BPR |
|---|---|---|---|
| 변화 대상 | 기존 활동의 수행 수단 | 기존 프로세스의 일부 단계 | E2E 프로세스 전체 |
| 변화 폭 | 절차 유지 | 단계적·부분적 | 근본적·급진적 |
| 적합 상황 | 절차가 이미 효율적인 업무 | 성과 격차가 작은 업무 | 성과 격차가 크고 부서 간 인계가 많은 핵심 업무 |
| 주요 위험 | 비효율 절차의 고속화 | 구조적 문제의 방치 | 조직 저항·전환 실패 |

### AI 기반 BPR의 도입 효과

| 효과 | 내용 |
|---|---|
| 현행 진단 | 프로세스 마이닝 등 로그 분석에 의한 As-Is 병목·중복의 신속한 식별 |
| 처리 자동화 | 반복 판단의 자동 처리와 예외 건의 사람 판단 집중으로 처리 시간·오류 감소 |
| 재설계 검증 | 시뮬레이션 기반 To-Be 효과 사전 확인 |

## Ⅴ. BPR 적용의 한계와 방안

| 한계 | 방안 |
|---|---|
| 기존 절차를 그대로 자동화해 낭비까지 고속화 | 자동화 전 고객가치 기준의 활동별 제거·통합 판정 |
| 전사 동시 급진 변화로 전환 실패·조직 저항 | 성과 격차가 큰 핵심 프로세스에만 BPR, 나머지는 CPI 적용 |
| 부서별 부분 최적화로 E2E 성과 책임 단절 | Process Owner 지정과 E2E 성과 지표 부여 |
| AI 기반 자동 판단의 오류·편향 | 고위험 판단의 사람 승인 단계와 판단 근거 기록 유지 |

## Ⅵ. 제언

핵심 프로세스의 자동화 전 활동별 제거·통합 판정 선행과 Process Owner의 E2E 성과 책임 부여

### 재설계 선행 구조

```text
핵심 E2E 프로세스
    │
    ├─ Process Owner ── E2E 성과 지표와 재설계 결정권
    │
    ├─ 활동 판정 ── 제거·통합·유지
    │
    └─ 정보기술 적용 ── 유지 판정 활동만 자동화
```

### 활동 판정 확대: 판정 결과별 처리

```text
As-Is 활동
    ↓
Process Owner의 고객가치 기여 판정
    ├─ 기여 없음 → 제거
    ├─ 타 부서 활동과 중복 → 통합 후 재판정
    └─ 기여 있음·중복 없음 → 자동화 대상 확정
                                ↓
                        E2E 성과 지표로 효과 측정
```

### 선택 근거: 현행 절차 자동화와의 비교

| 구분 | 현행 절차 자동화 | 제언: 판정 선행 재설계 |
|---|---|---|
| 자동화 대상 | 현행 전체 활동 | 제거·통합 후 남은 활동 |
| 성과 측정 단위 | 부서별 처리 시간 | E2E 처리 시간·오류·고객 결과 |
| 변경 결정 주체 | 부서별 담당자 | Process Owner |
| 낭비 활동 처리 | 자동화로 유지 | 설계 단계에서 제거 |
