## 지식 로드맵 내 현재 위치

IT 전략·관리 → 프로세스 혁신 → **BPR**

## 30초 인출

- 본질: BPR(Business Process Reengineering)은 성과를 획기적으로 높이기 위해 업무 프로세스를 근본부터 다시 생각하고 급진적으로 재설계하는 경영 기법
- 메커니즘: 재설계할 프로세스를 정하고 현행 프로세스를 이해·측정한 뒤, 단계를 제거·결합하고 IT 활용 방안을 찾아 새 프로세스의 시제품을 만들어 검증
- 통찰: 현행 프로세스를 그대로 두고 IT만 얹으면 기존 결함이 자동화되므로 IT 도입 전에 프로세스를 측정해 단계별 제거·통합·유지를 판정하고 남는 단계에만 적용

<details>
<summary>핵심 용어</summary>

- **BPR(Business Process Reengineering)** : 비용·품질·서비스·속도 같은 핵심 성과의 획기적 개선을 위해 업무 프로세스를 근본부터 재설계하는 기법 (Hammer와 Champy, 1993)
- **프로세스(Process)** : 가치를 만들어 내는 관련 업무들의 묶음 (예: 주문 처리, 채용, 신제품 개발)
- **BPR 네 가지 핵심어** : 근본적(Fundamental)·급진적(Radical)·획기적(Dramatic)·프로세스(Processes)
- **Business Process Redesign** : Davenport와 Short(1990)가 IT를 활용한 프로세스 재설계에 붙인 이름
- **PI(Process Innovation)** : Davenport(1993)가 프로세스 혁신을 가리킨 표현(Business Process Innovation)
- **지속 개선(TQM)** : 기존 프로세스를 점진적으로 개선하는 품질경영 접근으로 BPR과 대비되는 방식
- **IT 레버(IT Lever)** : 프로세스를 근본적으로 바꿀 수 있는 IT의 능력 (Davenport와 Short의 5단계 중 4단계)

## 2~4교시 25점 답안

## Ⅰ. BPR의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **BPR(Business Process Reengineering)** 은 핵심 성과의 획기적 개선을 위해 업무 프로세스를 근본적으로 다시 생각하고 급진적으로 재설계하는 기법 |
| 목적 | 비용·품질·서비스·속도의 비약적 향상 |

## Ⅱ. 점진 개선과 구별되는 BPR의 특징

| 핵심어 | 의미 |
|---|---|
| **근본적(Fundamental)** | 현행 업무 방식과 그 전제까지 되묻는 접근 |
| **급진적(Radical)** | 기존 프로세스의 보완이 아니라 새로 설계하는 재구성 |
| **획기적(Dramatic)** | 점진적 향상이 아니라 성과의 도약을 목표 |
| **프로세스(Process)** | 부서 기능이 아니라 가치를 만드는 관련 업무의 묶음이 개선 단위 |

## Ⅲ. BPR 수행 절차와 현행 프로세스 분석

### 프로세스 재설계 5단계 (Davenport와 Short)

```text
① 사업 비전과 프로세스 목표 수립
    ↓
② 재설계할 프로세스 선정
    ↓
③ 현행 프로세스의 이해와 측정
    ↓
④ IT 레버 식별
    ↓
⑤ 새 프로세스의 시제품 설계·구축
```

### 현행 프로세스 분석 확대: 기술 적용 전의 단계 판정

```text
현행 프로세스 단계 도출 (③)
    ↓
단계별 가치 기여 판정
    ├─ 가치 기여 없음 → 제거
    ├─ 다른 단계와 결합 가능 → 통합
    └─ 필요한 단계 → 유지
    ↓
남은 프로세스에서 IT 레버 식별 (④)
```

## Ⅳ. BPR과 지속 개선(TQM)의 비교

| 비교축 | 지속 개선(TQM) | BPR |
|---|---|---|
| 변화 수준 | 점진적 | 급진적 |
| 출발점 | 기존 프로세스 | 백지 상태 |
| 범위 | 기능 내부의 좁은 범위 | 기능을 가로지르는 넓은 범위 |
| 추진 방식 | 상향식 | 하향식 |
| 위험 | 보통 | 높음 |
| 핵심 동인 | 통계적 관리 | 정보기술 |

## Ⅴ. BPR의 한계와 방안

| 한계 | 방안 |
|---|---|
| 획기적 개선이라는 목표에 비교할 현행 성과 수치가 없어 효과 판정 곤란 | 재설계 전 현행 프로세스를 측정해 개선 목표의 기준선 확보 |
| 급진적 재설계의 전면 적용 실패 시 업무 전체에 미치는 영향 | 새 프로세스의 시제품을 제한 범위에서 검증한 뒤 확대 |
| 기능을 가로지르는 재설계에서 부서 간 이해 충돌 | 최고경영진 주도의 기능 횡단 추진 |
| 현행 프로세스를 두고 IT만 도입해 기존 결함 유지 | IT 도입 전 프로세스 단계의 제거·통합 판정 선행 |

## Ⅵ. 제언

AI 등 기술을 도입하기 전에 현행 프로세스를 측정하고 단계별 제거·통합·유지를 판정한 뒤 남는 단계에 시범 적용해 성과를 확인한 후 확산

### 기술 도입 순서

```text
현행 프로세스 측정
    ↓
단계별 제거·통합·유지 판정
    ↓
남는 단계에 기술 시범 적용
    ↓
측정 성과를 기준선과 비교
    ├─ 개선 목표 달성 → 확산
    └─ 미달 → 프로세스 재설계 후 재시범
```

### 시범 적용 확대: 기준선 대비 판정

```text
현행 성과(기준선) ─┐
                    ├─ 비교 ── 비용·품질·서비스·속도의 변화
시범 적용 성과 ────┘
```

### 선택 근거: 기존 프로세스에 IT를 얹는 방식과의 비교

| 구분 | 기존 프로세스에 IT 적용 | 제언: 측정·판정 후 적용 |
|---|---|---|
| 출발점 | 현행 단계 전부 | 가치 기여가 확인된 단계 |
| 효과 판단 | 도입 여부 중심 | 현행 기준선 대비 성과 |
| 결함 처리 | 자동화되어 유지 | 제거·통합으로 해소 |
