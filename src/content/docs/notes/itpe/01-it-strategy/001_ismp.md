```text
▶ 01 정보 전략·관리 ─→ 02 SW공학·프로젝트 ─→ 03 데이터
          │
          └─→ 04 컴퓨터시스템 ─→ 05 네트워크 ─→ 06 보안
                                     │
                                     └─→ 07 AI·신기술
전 영역 준거 ───────────────────────────→ 08 법·정책
```

- 현재 위치: `01 정보 전략·관리 > 정보화 기획·발주 > ISMP`

```text
[경영·정책 목표]
       │

                                      │
                                      ▼
              ┌──────────── ISMP ────────────┐
              │ 착수 → 방향 → 요건 → 구조 → 이행 │
              │                  └─ 계획·분리발주 │
              │                     예산·RFP     │
              └──────────────────────────────┘
                                      │
                                      ▼
                         [조달·구축사업 기준선]
```

- 본질: **특정 정보시스템**의 업무·기술 요건을 기능점수 산정이 가능한 수준까지 구체화하고, 예산과 제안요청서(RFP)를 만드는 실행 계획
- 위치: `IT 투자기획 → ISP/ISMP → RFP·예산 → 조달·구축`
- 암기: `착-방-요-구-이` = 착수 → 방향 → 요건 → 구조 → 이행
- 구분: ISP는 `과제 선정`, ISMP는 `구축 기준선`

## 예상문제

> ISMP의 개념과 방법론 체계를 설명하고, ISP와의 차이 및 성공적인 구축사업 연계를 위한 고려사항을 논하시오. (25점)

## Ⅰ. 특정 구축사업의 발주 기준선, ISMP 개요

- 정의: **ISMP(Information System Master Plan)**는 특정 정보시스템 구축사업의 업무·정보기술 현황과 요구사항을 분석하고, 기능점수 도출이 가능한 수준으로 기능·기술·비기능 요건을 상세화하여 구축전략과 이행계획을 수립하는 활동
- 목적: 모호한 사업구상을 **요건·아키텍처·예산·RFP**로 연결하여 구축 범위, 비용, 일정의 견적 가능성 확보
- 필요성: 요구사항 상세화 없이 구축사업을 발주하면 사업자별 견적 전제가 달라지고, 계약 후 과업 변경과 예산 분쟁으로 전이

#### 한줄 요약

- ISMP는 무엇을 구축할지 정하는 문서가 아니라, 정해진 시스템을 발주 가능한 수준으로 구체화하는 계획임

## Ⅱ. 상세성·일관성·실행성을 확보하는 ISMP 특징

| 특징 | 핵심 내용 | 구축사업 기여 |
|---|---|---|
| **대상 구체성** | 기관 전체가 아닌 특정 정보시스템의 범위·사용자·연계 대상 정의 | 사업 경계 확정 |
| **요건 상세성** | 업무·기술·비기능·프로젝트지원 요건을 구현·검수 가능한 수준으로 기술 | 요구 기준선 확보 |
| **산출물 추적성** | 업무요건 → 시스템요건 → 아키텍처 → 기능점수 → RFP 연결 | 누락·불일치 식별 |
| **조달 실행성** | 구축계획·분리발주·예산·RFP까지 한 흐름으로 수립 | 예산 요구와 발주 연계 |
| **대안 검토성** | 클라우드 등 디지털서비스 도입·전환을 우선 검토 | 구축방식 선택 근거 확보 |

#### 한줄 요약

- ISMP의 품질은 문서량이 아니라 요건이 예산과 RFP까지 끊기지 않고 이어지는지로 판정함

## Ⅲ. 방향·요건·구조·이행의 ISMP 구성

```text
[정보시스템 방향]
       │ 범위·목표·사용자
       ▼
[업무·정보기술 요건]
       │ 기능·기술·비기능 요건
       ▼
[정보시스템 구조]
       │ 아키텍처·요건 간 연관성
       ▼
[구축사업 이행]
       ├─ 구축계획·추진체계·일정
       ├─ 분리발주 가능성·예산
       └─ 제안요청서(RFP)
```

선의 의미: 상위 사업방향이 하위 요건·구조·조달 산출물의 기준으로 구체화되는 추적 관계

| 구성 영역 | 핵심 활동 | 대표 산출물 |
|---|---|---|
| **추진 방향** | 전략 검토, 추진 범위·목표·사용자 정의 | 추진 범위 및 방향 정의서 |
| **요건 분석** | 업무·정보기술 현황 분석, 업무·기술 요건 도출 | 업무·정보기술 요건 |
| **구조·요건 정의** | 아키텍처 정의, 요건 간 이행 연관성 분석 | 정보시스템 요건 기술서 |
| **이행방안** | 구축계획, 분리발주, 예산, RFP 작성 | 구축계획·예산·RFP |

#### 한줄 요약

- 방향이 요건을 제한하고, 요건이 구조와 규모를 만들며, 그 결과가 예산과 RFP의 근거가 됨

## Ⅳ. 착수에서 구축사업 이행까지의 5단계 방법론

```text
① 프로젝트 착수·참여자 결정
   └─ 지원조직·수행조직·프로젝트 계획
                ↓
② 정보시스템 방향성 수립
   └─ 전략 검토·벤치마킹·범위/목표 정의
                ↓
③ 업무·정보기술 요건 분석
   └─ 현황 분석·업무요건·기술요건 도출
                ↓
④ 정보시스템 구조·요건 정의
   └─ 아키텍처·이행 연관성·요건 기술서
                ↓
⑤ 구축사업 이행방안 수립
   └─ 구축계획 → 분리발주 → 예산 → RFP
```

| 주요 활동 | 수행 내용 | 판정 산출물 |
|---|---|---|
| **추진 범위·방향 정의** | 구축 범위, 사용자 그룹, 추진 목표 정의 | 범위·방향 정의서 |
| **업무요건 분석** | 업무 프로세스의 기능·서비스 요구 도출 | 업무요건 목록 |
| **정보기술요건 분석** | 응용·데이터·기술기반 제약과 요구 도출 | 정보기술요건 목록 |
| **아키텍처 정의** | 요건을 수용할 목표 정보시스템 구조 설계 | 목표 아키텍처 |
| **요건 간 이행 연관성 분석** | 선후관계·의존성·중복·누락 확인 | 요건 연관성 분석 결과 |
| **요건 기술서 작성** | 구현·검수 가능한 상세 요건과 추적관계 명세 | 정보시스템 요건 기술서 |
| **예산 수립** | 기능점수와 HW·SW·서비스 비용으로 사업비 산정 | 정보시스템 구축 예산 |

#### 한줄 요약

- 다섯 단계는 전략을 다시 만드는 절차가 아니라, 범위와 요건을 구조·예산·RFP로 점차 구체화하는 흐름임

## Ⅴ. 전략계획과 구축계획을 가르는 ISP·ISMP 비교

| 구분 | ISP | ISMP | 기관 중장기 정보화계획 |
|---|---|---|---|
| **목적** | 정보화 비전·전략과 이행과제 도출 | 특정 시스템 구축사업 구체화 | 기관의 법정·정책상 중장기 정보화 방향 수립 |
| **대상 범위** | 조직·업무 전반 | 단일 정보시스템 구축사업 | 기관 전체 정보화 사업·운영 |
| **핵심 질문** | 무엇을 왜 추진할 것인가 | 무엇을 어느 범위·비용으로 구축할 것인가 | 기관은 중장기적으로 무엇을 추진할 것인가 |
| **상세 수준** | 목표모델·과제·통합 이행계획 | 상세 요건·아키텍처·기능점수·예산 | 정책목표·추진과제·연차별 계획 |
| **대표 산출물** | 정보화 과제 포트폴리오·로드맵 | 요건 기술서·구축계획·예산·RFP | 기관 중장기 정보화계획 |
| **선택 기준** | 구축 대상·범위가 아직 구체화되지 않은 경우 | 구축 대상이 정해져 상세화가 필요한 경우 | 기관 차원의 정기적 계획 수립이 필요한 경우 |

- 적용 판단: 하나의 단위 시스템 구축에는 ISP와 ISMP를 중복 수행하지 않고, 구축사업의 사전 준비도와 필요한 상세 수준에 따라 하나를 선택

#### 한줄 요약

- ISP는 투자할 과제를 정하고, ISMP는 정해진 과제를 발주 가능한 구축사업으로 바꿈

## Ⅵ. 산출물 간 단절을 막는 실무 고려사항 및 대책

- 적용 상황: 중앙관서가 특정 정보시스템의 구축·재구축 예산을 요구하기 전에 ISMP를 수립하는 경우

| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 구축 중 **요구사항 변경** 반복 | 현업 요구와 요건 기술서·RFP 간 추적관계 단절 | 업무요건-시스템요건-아키텍처-RFP 추적표 검토 | 누락·상충 요건의 발주 전 식별 |
| **예산과 사업범위** 불일치 | 요건 상세도 부족 또는 기능점수·장비 규모 산정 근거 누락 | 기능점수와 HW·SW·서비스 비용을 RFP 요구사항과 대조 | 산정 범위와 계약 범위 일치 |
| **분리발주** 대상 누락·특정 제품 종속 | 대안조사와 분리발주 가능성 평가 부족 | 제품 중립 요건 작성과 분리발주 평가 결과 명시 | 경쟁 가능한 조달구조 확보 |
| **클라우드 전환** 판단 불명확 | 현행 운영조건·비용·연계·보안 제약 분석 부족 | 디지털서비스 우선 검토와 적용·불가 사유를 비용과 함께 제시 | 구축방식 선택의 설명 가능성 확보 |
| 최종산출물 **검토 반려** | 기본 구성 누락 또는 요건·예산·RFP 간 불일치 | 제출 전 기본 구성과 상호 추적성 자체점검 | 예산 검토의 재작업 감소 |

#### 한줄 요약

- 실무 실패는 개별 산출물이 없어서보다 산출물 사이의 범위와 근거가 맞지 않아 발생함

## Ⅶ. 문서 완성보다 추적성을 보장하는 결론

- **[요건-예산-RFP 추적성으로 과업 변경 선제 통제]**: ISMP 산출물이 많아도 업무요건과 아키텍처·기능점수·예산·RFP가 끊기면 구축사업의 기준선이 되지 못함
- 나라면: 최종산출물 검토 전에 `업무요건 → 시스템요건 → 아키텍처 → 기능점수 → RFP`를 표본 추적하고, 불일치 항목의 책임자·보완기한을 확정한 뒤 예산 요구 진행

#### 한줄 요약

- ISMP의 완성 기준은 보고서 제출이 아니라 같은 사업범위가 요건부터 계약문서까지 일관되게 추적되는 상태임

## 1교시 10점 답안 발췌

### 1. ISMP 정의

- 특정 정보시스템 구축사업의 업무·기술 요건을 기능점수 산정 수준으로 상세화하여 구축전략·예산·RFP를 수립하는 실행 계획

### 2. ISMP 방법론 체계

```text
착수 → 방향 → 요건 → 구조 → 이행
                         ├─ 구축계획·분리발주
                         └─ 예산·RFP
```

| 단계 | 핵심 산출물 |
|---|---|
| 방향·요건 | 범위·방향 정의서, 업무·기술 요건 |
| 구조·요건 | 아키텍처, 정보시스템 요건 기술서 |
| 이행방안 | 구축계획, 예산, RFP |

### 3. 차별화 제언

- ISP는 정보화 과제를 선정하고 ISMP는 특정 과제를 발주 가능한 수준으로 구체화
- `요건 → 아키텍처 → 기능점수 → 예산 → RFP` 추적성 검토로 과업 변경과 예산 불일치 선제 통제
