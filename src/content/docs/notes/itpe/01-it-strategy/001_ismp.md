## 지식 로드맵 내 현재 위치

IT 전략·관리 → 정보화 기획·발주 → **ISMP**

## 30초 인출

- 본질: ISMP(Information System Master Plan)는 이미 선정한 정보화 사업의 요구사항·구조·예산을 발주 가능한 수준으로 구체화하는 계획
- 메커니즘: 업무·정보기술 요구 분석에서 구조·요건 정의, 이행계획·소요예산을 도출하고 RTM으로 요구사항의 반영 위치 추적
- 통찰: 요구사항과 규모 산정·RFP를 따로 작성하면 누락과 과업 변경이 생기므로 RFP 확정 전 요구사항 ID 단위의 RTM 연결 확인

<details>
<summary>핵심 용어</summary>

- **ISMP(Information System Master Plan)** : 특정 정보시스템 구축 사업의 요구사항·구조·이행계획·소요예산을 기능점수 산정이 가능한 수준까지 구체화한 발주 기준 계획
- **ISP(Information Strategy Planning)** : 조직의 비전과 현황을 바탕으로 정보화 방향과 투자 과제·우선순위를 정하는 중장기 전략 계획
- **Baseline(기준선)** : 승인 뒤 변경 통제의 비교 기준이 되는 범위·요구사항·비용의 확정본
- **RTM(Requirements Traceability Matrix)** : 요구사항을 설계·규모 산정·RFP·검수 조건과 양방향으로 연결해 누락과 과잉 반영을 찾는 추적표
- **FP(Function Point)** : 사용자에게 제공되는 논리적 기능의 양으로 소프트웨어 규모를 측정하는 단위
- **RFP(Request for Proposal)** : 발주자가 구축 범위·요구사항·평가 기준·계약 조건을 제시해 제안을 요청하는 문서
- **비기능 요구사항** : 기능 외에 성능·보안·품질처럼 시스템이 충족해야 할 조건

## 2~4교시 25점 답안

## Ⅰ. ISMP의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **ISMP(Information System Master Plan)** 는 선정된 정보시스템 구축 사업의 요구사항·구조·예산을 발주 가능한 수준으로 구체화하는 계획 |
| 목적 | 발주 범위와 예산 근거의 명확화, 구축 단계의 과업 변경 감소 |

## Ⅱ. 발주 기준을 만드는 ISMP의 특징

| 특징 | 의미 |
|---|---|
| 특정 사업 단위 | 전사 과제가 아닌 이미 선정된 한 구축 사업의 상세화 |
| 규모 산정 가능한 상세도 | 기능별 입출력·처리 절차까지 기술해 **FP(Function Point)** 도출 가능 |
| 측정 가능한 요구 | 성능·보안 같은 **비기능 요구사항** 의 측정 지표·검수 조건 포함 |
| 추적 가능한 산출물 | 요구사항에서 구조·예산·RFP까지의 연결 관리 |

## Ⅲ. ISMP 수립 절차와 요구사항 상세화

### ISMP 수립 절차

```text
추진 범위·목표 설정
    ↓
업무·정보기술 현황과 요구 분석
    ↓
정보시스템 구조·요건 정의
    ↓
구축 이행계획 수립
    ↓
연도·항목별 소요예산 산정과 RFP 작성 지원
```

### 구조·요건 정의 확대: 요구사항 유형과 검증 기준

```text
정보시스템 구조·요건 정의
    │
    ├─ 기능 요구사항 ── 입출력·처리 절차, FP 산정 근거
    │
    ├─ 기술·비기능 요구사항 ── 성능·보안·품질의 측정 지표
    │
    └─ 사업 지원 요구사항 ── 교육·데이터 이행·유지관리
```

요구사항마다 식별 ID를 부여하고 **RTM(Requirements Traceability Matrix)** 으로 구조·예산·RFP의 반영 위치를 기록하는 방식

## Ⅳ. ISP와 ISMP의 범위 비교

| 비교축 | ISP | ISMP |
|---|---|---|
| 목적 | 정보화 과제·투자 우선순위 선정 | 발주 범위·예산 **기준선(Baseline)** 확정 |
| 대상 범위 | 조직 전체 업무와 정보화 방향 | 선정된 특정 정보시스템 구축 사업 |
| 요구 상세도 | 과제 수준의 개념 요구 | 기능별 입출력·처리 절차와 측정 가능한 비기능 요구 |
| 핵심 산출물 | 정보화 과제 목록·우선순위·로드맵 | 요건 정의서·목표 구조·이행계획·소요예산·**RFP** 초안 |

ISP의 과제 수준 요구가 ISMP의 상세 요구로 넘어가는 경계에서 상세화가 부족하면, 구축 단계에서 요구가 새로 정의되는 과업 변경의 발생 지점

## Ⅴ. ISMP 수립의 한계와 방안

| 한계 | 방안 |
|---|---|
| ISP 수준의 개념 요구만으로 발주해 구축 중 과업 변경 발생 | 기능 요구의 입출력·처리 절차까지 ISMP 단계의 상세화 |
| 요구사항과 FP·예산의 연결 근거 부재로 예산 과소·과다 산정 | 요구사항 ID별 FP와 인프라 비용 산정 근거의 기록 |
| 비기능 요구의 측정 기준 부재로 검수 분쟁 발생 | 성능·보안 요구마다 측정 지표와 검수 조건 명시 |
| 요구사항 변경의 설계·예산·RFP 부분 반영 | RTM으로 변경 요구사항에 연결된 산출물의 영향 일괄 확인 |

## Ⅵ. 제언

RFP 확정 전 요구사항 ID 단위의 RTM 연결 확인을 발주의 선행 조건으로 설정

### RTM 연결 구조

```text
요구사항 ID
    │
    ├─ 목표 구조의 구성요소
    │
    ├─ FP·소요예산 산정 근거
    │
    └─ RFP 요구사항·검수 조건
```

### RFP 확정 전 연결 확인 절차

```text
요구사항 ID별 연결 산출물 대조
    ↓
누락·과잉·측정 기준 미정 항목 식별
    ↓
발주 판정
    ├─ 미결 항목 존재 → 요건 보완 또는 해당 범위 분리 발주
    └─ 연결 확인 → RFP 확정과 발주
```

### 선택 근거: 문서별 검토와의 비교

| 구분 | 문서별 개별 검토 | 제언: RTM 기반 사전 확인 |
|---|---|---|
| 확인 단위 | 요건 정의서·예산서·RFP 각각 | 요구사항 ID 하나에 연결된 전체 산출물 |
| 누락 발견 시점 | 구축·검수 단계 | RFP 확정 전 |
| 미결 요구 처리 | 발주 후 과업 변경 | 요건 보완 또는 발주 범위 분리 |
