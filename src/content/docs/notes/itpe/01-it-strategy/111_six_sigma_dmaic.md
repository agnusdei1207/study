## 답안 골격
```text
[6시그마(Six Sigma) DMAIC] ◀━━ 머리: Ⅶ 내 의견 (통계적 무결함 DMAIC 기법과 낭비 제거 린(Lean)을 결합한 린-6시그마 IT 운영 자동화)
 ┃
 ┣━ Ⅰ 개요 ───── 주관적 품질 관리와 반복 결함의 악순환 차단 → 100만 개당 3.4개 결함(3.4 DPMO)을 지향하는 데이터 기반 품질 혁신 방법론
 ┣━ Ⅱ 특징 ───── 통계적 정량화(정규분포 6σ) · 고객 관점의 CTQ 도출 · 과학적 5단계 로드맵(DMAIC) · 벨트(Belt) 자격 기반 전문가 조직
 ┣━ Ⅲ 구조 ───── DMAIC 5단계 (Define 정의 ➔ Measure 측정 ➔ Analyze 분석 ➔ Improve 개선 ➔ Control 관리)
 ┣━ Ⅳ 흐름 ───── ① CTQ 및 VOC 정의 → ② 공정능력(Cpk) 측정 → ③ 근본 원인 통계 분석(ANOVA/회귀) → ④ 개선안 실행(실험계획법) → ⑤ 관리도 통제
 ┣━ Ⅴ 비교 ───── 6시그마(Six Sigma) vs 린(Lean) (통계적 변동(Variation) 최소화 vs 프로세스 낭비(Waste) 및 대기 시간 제거)
 ┗━ Ⅵ 실무 ───── 과도한 통계 분석 도구 집착으로 인한 실행 지연 / 소프트웨어 개발의 창의적 특성 무시 / 형식적 서류 작업화
```
- 필수 키워드: 6시그마 · DMAIC · 3.4 DPMO · CTQ(핵심품질특성) · 공정능력지수(Cpk) · 관리도(Control Chart) · 린-6시그마(Lean Six Sigma)
- 기출: 이전 KPC(86, 90회) `품질 혁신 방법론인 6시그마의 개념, 통계적 의미(3.4 DPMO) 및 프로세스 개선 로드맵인 DMAIC 단계별 핵심 도구와 활동` → Ⅰ·Ⅲ·Ⅳ·Ⅴ

## 한 줄 본질
- 모든 프로세스 결함의 근본 원인을 '변동(Variation)'으로 보고 통계적 데이터를 바탕으로 100만 번의 실행 중 불량 발생을 3.4회 이하(99.99966% 무결함)로 억제하는 5단계(DMAIC) 체계적 혁신 방법론 → 데이터 기반의 객관적 프로세스 품질 보장 / 과도한 측정 오버헤드 및 소프트웨어 비정형 업무에의 획일적 적용 한계

## 핵심 용어
- 3.4 DPMO(Defects Per Million Opportunities): 프로세스 평균이 중심에서 $\pm 1.5\sigma$ 이동한다고 가정했을 때 100만 번의 기회 중 결함이 3.4개만 발생하는 6시그마 수준의 수학적 품질 규격
- CTQ(Critical To Quality): 고객의 요구사항(VOC)을 구체적이고 측정 가능한 프로세스 품질 특성으로 변환한 핵심 지표(예: "응답이 빨라야 함" ➔ "API 응답 지연 200ms 이하")
- 공정능력지수(Cpk): 고객이 요구하는 규격 상·하한선 대비 실제 프로세스 산포와 평균의 치우침을 반영하여 공정이 규격을 만족시킬 능력을 나타내는 통계 지표

## 핵심 통찰
- 변동(Variation)이 품질의 진짜 적임 → 평균 응답 속도가 0.5초라도 어떤 요청은 10초씩 걸린다면 사용자는 시스템을 '불량'으로 인식하므로, 평균을 줄이기보다 산포(표준편차)를 줄이는 것이 6시그마의 핵심임
- 데이터 없는 개선은 '개인의 의견'일 뿐임 → "서버가 느린 것 같다"는 직관 대신, Minitab이나 파이썬 통계 패키지로 회귀분석을 돌려 가비지 컬렉션(GC) 주기와 지연시간 간의 유의미한 P-value(0.05 미만)를 입증해야 함
- 린(Lean)과 6시그마는 상호 보완재임 → 린으로 불필요한 결재 단계와 대기 낭비를 신속히 잘라내고, 남아있는 핵심 공정의 품질 변동은 6시그마의 DMAIC로 정밀 타격하는 '린-6시그마'가 IT 운영의 정석임

## 이웃 토픽과 구분
- 6시그마 vs TQM(전사적 품질관리): TQM = 전사원의 참여를 독려하는 철학적·문화적 품질 운동 / 6시그마 = 통계적 데이터와 전담 전문가(블랙벨트) 중심의 계량적 문제 해결 프로젝트
