## 지식 로드맵 내 현재 위치

IT 전략·관리 → IT 자원·비용 관리 → **FinOps**

## 30초 인출

- 본질: FinOps는 엔지니어링·재무·비즈니스 팀이 협업해 클라우드 등 기술 지출의 비즈니스 가치를 높이고 사용 비용의 책임을 분명히 하는 운영 프레임워크이자 문화적 실천
- 메커니즘: 사용량·비용을 팀·제품별로 배분해 보이게 하고, 단위 비용 같은 가치 지표로 판단한 뒤, 사용량과 요금을 최적화하는 활동을 조직 차원에서 지속 운영
- 통찰: 비용이 소유 팀에 배분되지 않으면 사용 책임과 최적화가 실행되지 않으므로 계정 구조·태그·공유 비용 규칙으로 배분 커버리지를 먼저 확보한 뒤 단위 비용으로 최적화 대상을 판단

<details>
<summary>핵심 용어</summary>

- **FinOps** : 엔지니어링·재무·비즈니스 팀의 협업으로 기술의 비즈니스 가치를 극대화하고, 시의적절한 데이터 기반 의사결정과 재무적 책임을 만드는 운영 프레임워크이자 문화적 실천 (FinOps Foundation)
- **FinOps 프레임워크(FinOps Framework)** : 원칙·도메인·역량(Capability)·범위(Scope)·페르소나로 FinOps 실천을 구조화한 틀
- **도메인(Domain)** : 비용·사용 이해, 비즈니스 가치 정량화, 사용·비용 최적화, FinOps 실천 관리의 네 영역
- **배분(Allocation)** : 계정·태그·라벨 같은 메타데이터로 사용량과 비용을 팀·프로젝트에 귀속하는 역량
- **쇼백(Showback)·차지백(Chargeback)** : 팀에 비용을 투명하게 보여 주는 방식과 팀의 기술 소비분을 실제로 청구하는 방식
- **단위 경제성(Unit Economics)** : 총 기술 지출을 비즈니스 지표로 나눈 단위 비용으로 지출과 창출 가치를 연결하는 역량
- **사용 최적화(Usage Optimization)** : 자원을 적정하게 선택·규모 조정하고 필요할 때만 가동해 활용도를 높이는 역량
- **요금 최적화(Rate Optimization)** : 사용하는 자원에 지불하는 단가를 관리하는 역량
- **약정 할인(Commitment Discount)** : 1~3년 단위로 용량이나 지출을 미리 약정해 요금을 낮추는 방식
- **FOCUS(FinOps Open Cost and Usage Specification)** : 클라우드·SaaS·데이터센터 등 여러 공급자의 청구 데이터를 표준 형식으로 정규화하는 오픈 규격

</details>

## 2~4교시 25점 답안

## Ⅰ. FinOps의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **FinOps** 는 엔지니어링·재무·비즈니스 팀의 협업으로 기술 지출의 비즈니스 가치를 극대화하는 운영 프레임워크·문화적 실천 |
| 목적 | 기술 지출의 가치 극대화와 사용 비용의 재무적 책임 확립 |

## Ⅱ. 협업과 사용 주체의 책임이 중심인 FinOps의 특징

| 원칙 | 의미 |
|---|---|
| 팀 간 협업 | 재무·기술·제품·경영진이 함께 기술 비용 관리 |
| 비즈니스 가치 기반 결정 | 단위 경제성과 가치 지표로 비용·품질·속도 사이의 균형 판단 |
| 사용 주체의 책임 | 엔지니어가 설계부터 운영까지 자기 사용량의 비용 책임 |
| 접근 가능하고 시의적절하며 정확한 데이터 | 비용 데이터를 확보 즉시 처리·공유 |
| 중앙의 지원 | 전담 FinOps 기능이 모범 사례 전파와 요금·약정의 대규모 최적화 |
| 클라우드 변동비 활용 | 소비 기반 과금을 활용한 고정 예측이 아닌 유연한 용량 계획 |

## Ⅲ. FinOps 프레임워크의 도메인과 비용 배분

### FinOps 프레임워크의 네 도메인

```text
FinOps 프레임워크
    │
    ├─ 비용·사용 이해(Understand Usage & Cost)
    │      데이터 수집, 배분, 리포팅·분석, 이상 관리
    │
    ├─ 비즈니스 가치 정량화(Quantify Business Value)
    │      계획·추정, 예측, 예산, KPI·벤치마킹, 단위 경제성
    │
    ├─ 사용·비용 최적화(Optimize Usage & Cost)
    │      아키텍처·워크로드 배치, 사용 최적화, 요금 최적화
    │
    └─ FinOps 실천 관리(Manage the FinOps Practice)
           경영진 전략 정렬, 거버넌스·정책·위험, 교육, 청구·차지백
```

### 비용·사용 이해 확대: 배분(Allocation)

```text
청구 데이터: 사용량과 비용
    ↓
배분: 계정·태그·라벨 등 메타데이터로 팀·프로젝트에 귀속
    ├─ 계정 구조와 계층 ── 비용 센터·사업 단위로 매핑
    ├─ 태그·메타데이터 ── 자원의 소속 식별
    └─ 공유 비용 ── 고정 배분·비례 배분·대리 지표
    ↓
쇼백(팀에 비용 공개) 또는 차지백(팀에 소비분 청구)
```

## Ⅳ. 사용 최적화와 요금 최적화의 비교

| 비교축 | 사용 최적화(Usage Optimization) | 요금 최적화(Rate Optimization) |
|---|---|---|
| 대상 | 자원의 선택·규모·가동 시간·구성·활용도 | 자원에 지불하는 단가 |
| 주 담당 | 엔지니어링이 1차 책임, FinOps 담당자가 지원 | FinOps·엔지니어링·재무·조달의 협업 |
| 방법 | 적정 규모화, 필요 시 가동(스케줄링), 유휴 자원 제거, 스케일링, 서비스 현대화 | 약정 할인, 예약 인스턴스, 절감 플랜(Savings Plans), 스팟 인스턴스, 협상 할인 |
| 판단 기준 | 적정 규모·필요 시 가동·높은 활용도 | 약정 활용도(Commitment Utilization), 유효 절감률(Effective Savings Rate), 약정 할인 낭비 |
| 상호 관계 | 자원 사용량 변화가 약정 필요량에 영향 | 사용량이 줄면 미사용 약정 낭비 발생 |

## Ⅴ. FinOps 운영의 한계와 방안

| 한계 | 방안 |
|---|---|
| 태그 누락과 공유 자원으로 비용이 팀에 귀속되지 않아 사용 책임 불명 | 계정 구조·태그 정책 정립, 공유 비용은 고정·비례·대리 지표 규칙 적용 |
| 비용 총액만으로 증가가 사업 성장 때문인지 낭비인지 판단 불가 | 총 기술 지출을 비즈니스 지표로 나눈 단위 비용 관리 |
| 사용량 감소 전 약정 구매로 미사용 약정 낭비 | 사용 최적화 결과를 반영해 약정 규모를 정하고 약정 활용도 점검 |
| 공급자마다 청구 데이터 형식이 달라 통합 분석 곤란 | FOCUS 형식으로 청구 데이터 정규화 |

## Ⅵ. 제언

배분 커버리지를 먼저 확보하고, 배분된 비용에 단위 비용을 적용해 최적화 대상의 우선순위를 판단

### 배분에서 최적화까지의 순서

```text
비용 항목의 소유 팀 매핑 (배분 커버리지 확인)
    ↓
팀·제품별 단위 비용 산정
    ↓
단위 비용이 높거나 증가한 대상 선정
    ↓
사용 최적화 → 남은 사용량 기준의 요금 최적화
```

### 배분 확대: 소유 팀을 정할 수 없는 비용의 처리

```text
비용 항목
    ├─ 계정·태그로 소유 팀 식별 → 해당 팀에 귀속
    ├─ 여러 팀이 함께 사용 → 공유 비용 규칙(고정·비례·대리 지표)
    └─ 완전 배분에 비용이 과다 → 규칙에 따른 근사 배분 허용
```

### 선택 근거: 총액 중심 관리와의 비교

| 구분 | 총액 중심 관리 | 제언: 배분 후 단위 비용 관리 |
|---|---|---|
| 판단 단위 | 조직 전체 청구 총액 | 팀·제품별 단위 비용 |
| 책임 소재 | 불분명 | 소유 팀 |
| 증가 원인 해석 | 사업 성장과 낭비 구분 불가 | 단위 비용 변화로 구분 |
