## 지식 로드맵 내 현재 위치

IT 전략·관리 → 클라우드 전략·재무 → **FinOps**

## 30초 인출

- 본질: FinOps는 엔지니어링·재무·사업 조직이 함께 클라우드 등 기술 비용을 사업 가치 기준으로 관리하는 운영 프레임워크이자 조직 문화
- 메커니즘: Inform에서 비용을 서비스별로 가시화하고, Optimize에서 사용량·요금 대안을 고르며, Operate에서 실행·재측정하는 반복 주기
- 통찰: 한계: 총비용 절감 목표가 서비스 성장까지 억제 → 방안: 서비스 단위비용을 판단 기준으로 삼고 엔지니어링 팀에 조치 책임 부여

<details>
<summary>핵심 용어</summary>

- **FinOps** : 엔지니어링·재무·사업 조직의 협업으로 기술 비용의 책임을 나누고 사업 가치를 높이는 운영 프레임워크이자 조직 문화
- **Inform(가시화)** : 사용량·비용을 서비스·조직에 배부하고 예산·예측·단위비용을 공유하는 단계
- **Optimize(최적화)** : 사용량 절감과 요금 할인 대안을 비교해 개선 조치를 고르는 단계
- **Operate(운영)** : 선택한 조치의 실행과 정책 적용, 결과 재측정을 수행하는 단계
- **단위 경제성(Unit Economics)** : 거래 1건·활성 사용자 1명처럼 사업 산출 단위당 기술 비용으로 효율을 판단하는 지표
- **Rightsizing(규모 조정)** : 실제 부하에 맞춘 인스턴스 크기·사양의 조정
- **약정 할인(Commitment-based Discount)** : 일정 기간 사용량이나 금액을 약정하고 단가를 낮추는 요금제. 예약 인스턴스·Savings Plans 등
- **ITFM(IT Financial Management)** : IT 예산·비용의 계획·집행·배부·보고를 담당하는 재무관리 활동

## 2~4교시 25점 답안

## Ⅰ. FinOps의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **FinOps** 는 엔지니어링·재무·사업 조직의 협업으로 기술 비용 책임을 나누고 사업 가치를 높이는 운영 프레임워크 |
| 목적 | 기술 사용의 사업 가치 극대화와 시의적절한 데이터 기반 비용 의사결정 |

## Ⅱ. 연간 예산 관리와 구별되는 FinOps의 특징

| 특징 | 의미 |
|---|---|
| 공동 책임 | 사용량을 만드는 엔지니어링이 비용 책임까지 공유 |
| 가변 비용 활용 | 사용량에 따라 바뀌는 클라우드 비용의 수시 조정 |
| 사업 가치 기준 | 총비용보다 사업 산출 단위당 비용으로 판단 |
| 중앙 지원·분산 실행 | 중앙 FinOps 기능의 데이터·정책 제공과 각 팀의 직접 조치 |

## Ⅲ. FinOps 운영 체계와 반복 주기

### FinOps 운영 체계

```text
FinOps ── 기술 사용의 사업 가치 극대화
    │
    ├─ 참여 조직
    │     ├─ 엔지니어링 ── 사용량·아키텍처 결정
    │     ├─ 재무 ── 예산·예측·비용 배부
    │     └─ 사업 ── 서비스 가치·우선순위 결정
    │
    ├─ 중앙 FinOps 기능 ── 비용 데이터·정책·도구 제공
    │
    └─ 반복 주기 ── Inform·Optimize·Operate
```

FinOps Foundation은 적용 범위를 퍼블릭 클라우드에서 SaaS·데이터센터·AI 등 기술 비용 전반으로 확장

### 반복 주기 확대: Inform·Optimize·Operate

```text
Inform: 서비스별 비용 배부와 단위비용 가시화
    ↓
Optimize: 사용량 절감·요금 할인 대안 선택
    ↓
Operate: 조치 실행·정책 적용·결과 재측정
    ↓
재측정 결과를 다음 Inform의 기준선으로 반영
```

## Ⅳ. 최적화 대안 비교와 ITFM과의 관계

### 사용량 최적화와 요금 최적화

| 구분 | 사용량 최적화 | 요금 최적화 |
|---|---|---|
| 줄이는 대상 | 사용하는 자원의 양 | 같은 사용량의 단가 |
| 대표 수단 | **Rightsizing** ·유휴 자원 삭제·운영 시간 조정 | **약정 할인** ·스팟 인스턴스 |
| 조치 주체 | 엔지니어링 팀 | 중앙 FinOps 기능·재무 |
| 적합 조건 | 과다 할당·유휴 자원 존재 | 안정적으로 유지되는 기저 사용량 |
| 실패 위험 | 과도한 축소에 따른 성능 저하 | 사용량 감소 시 미사용 약정 비용 |

### ITFM과 FinOps 비교

| 구분 | ITFM | FinOps |
|---|---|---|
| 관리 주기 | 연간·분기 예산 | 사용량 변화에 따른 수시 조정 |
| 책임 주체 | 재무·구매 조직 | 엔지니어링·재무·사업 공동 |
| 판단 기준 | 예산 대비 집행률 | 사업 산출 단위당 비용 |

## Ⅴ. FinOps 적용의 한계와 방안

| 한계 | 방안 |
|---|---|
| 태그 누락·공유 자원으로 비용 귀속 불가 | 계정·태그 기준 배부 규칙과 미배부 비용 책임자 지정 |
| 변동 워크로드의 약정 선구매로 미사용 약정 발생 | 기저 사용량만 약정 할인, 변동분은 사용량 최적화로 대응 |
| 총비용 절감 목표의 서비스 성장 억제 | 거래당·사용자당 **단위 경제성** 지표로 효율 판단 |
| 분석 결과의 미실행 | 최적화 과제의 엔지니어링 작업 목록 등록과 담당자 지정 |

## Ⅵ. 제언

총비용 대신 서비스 단위비용을 판단 기준으로 삼고, 엔지니어링 팀의 비용 조치 책임 지정

### 서비스 단위비용 책임 구조

```text
서비스 단위비용 관리
    │
    ├─ 사업 ── 산출 단위 정의와 목표 단위비용
    │
    ├─ 엔지니어링 ── 사용량·아키텍처 조치
    │
    └─ 중앙 FinOps 기능·재무 ── 배부 데이터·약정 계약 관리
```

### 엔지니어링 조치 확대: 단위비용 초과 서비스 처리 절차

```text
서비스별 단위비용 추이 확인
    ↓
목표 초과 서비스 선정
    ↓
원인별 대안 선택
    ├─ 과다 할당·유휴 자원 → 규모 조정·삭제
    └─ 안정적 기저 사용량 → 약정 할인 요청
    ↓
단위비용·응답시간 재측정
```

### 선택 근거: 총비용 절감 중심 관리와의 비교

| 구분 | 총비용 절감 중심 | 제언: 단위비용 기준 |
|---|---|---|
| 판단 지표 | 월별 총 청구액 | 거래·사용자당 비용 |
| 서비스 성장 시 해석 | 비용 증가를 문제로 판단 | 단위비용 유지 시 정상 증가 |
| 조치 주체 | 재무·구매 조직 | 사용량을 만드는 엔지니어링 팀 |
| 성능 영향 확인 | 절감액만 확인 | 단위비용과 응답시간 함께 확인 |
