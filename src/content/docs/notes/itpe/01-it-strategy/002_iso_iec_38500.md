- 본질: **ISO/IEC 38500**은 IT 운영 방법이 아니라 거버넌스 기구가 IT 사용을 판단·감독하는 원칙 표준
- 메커니즘: **EDM(Evaluate, Direct and Monitor)** 순환으로 상황을 평가하고 방향을 지시하며 성과를 모니터링

<summary>핵심 용어</summary>

- **EDM(Evaluate, Direct and Monitor)**: 평가·지시·모니터링 결과를 다음 평가에 환류하는 IT 거버넌스 순환
- **Governing Body**: 조직의 IT 사용 방향과 감독에 최종 책임을 지는 거버넌스 기구
- **ISO 37000**: ISO/IEC 38500:2024가 원칙과 성과 체계를 정렬한 조직 거버넌스 지침
- **Feedback Loop**: 모니터링 결과를 다음 평가의 근거로 되돌리는 폐루프 통제

</details>

## 예상문제

> ISO/IEC 38500:2024의 개념과 EDM 모델을 설명하고, 거버넌스와 경영관리의 역할, 거버넌스 원칙·프레임워크, 적용 문제점과 대응책을 제시하시오. (25점)

## Ⅰ. IT 사용의 판단 책임을 정립하는 ISO/IEC 38500

> ISO/IEC 38500은 IT 부서의 운영 절차가 아니라 거버넌스 기구의 판단 기준이며, 권한은 위임해도 최종 책임은 이전되지 않음

- 정의: 조직의 IT 사용을 위한 **거버넌스 원칙·모델·프레임워크**를 제시하는 국제표준
- 목적: 조직 목적 정렬 · 책임 있는 IT 사용 · 성과·준수 감독

## Ⅱ. EDM 순환과 거버넌스·경영관리의 역할

> 거버넌스 기구의 EDM은 경영관리의 실행을 대신하지 않고, 실행 방향과 허용 범위를 정한 뒤 결과를 다시 평가함

| 구분 | 거버넌스 기구 | 경영관리층 |
|---|---|---|
| 책임 | IT 사용의 최종 판단·감독 | 위임받은 자원·프로세스 운영 |
| 행위 | **Evaluate · Direct · Monitor** | Plan · Build · Run |
| 증적 | 의사결정 근거 · 위임 기준 · 감독 결과 | 계획 · 구축·운영 결과 · 성과 보고 |

## Ⅲ. 11개 원칙과 6개 거버넌스 프레임워크 요소

> 11개 원칙은 판단의 관점을, 6개 프레임워크 요소는 그 판단을 조직 안에서 작동시키는 통제 구조를 제공함

### 1. ISO 37000 기반 11개 원칙

| 원칙 | 판단 초점 | 원칙 | 판단 초점 |
|---|---|---|---|
| **Purpose** | IT 사용의 조직 목적 정렬 | **Value Model** | 가치 창출 방식 명확화 |
| **Strategy** | 전략과 IT 방향 연결 | **Oversight** | 성과·기대 충족 감독 |
| **Accountability** | 위임 권한의 책임 추적 | **Stakeholder Engagement** | 이해관계자 요구 반영 |
| **Leadership** | 윤리적 리더십과 조직문화 | **Data and Decisions** | 데이터 기반 의사결정 |
| **Risk Governance** | 불확실성과 전략 위험 통제 | **Social Responsibility** | 사회적 기대와 투명성 |
| **Viability and Performance over Time** | 장기 생존성과 성과 유지 |  |  |

### 2. IT 거버넌스 프레임워크 6요소

| 요소 | 역할 | 확인사항 |
|---|---|---|
| **Direction** | IT 사용 방향 정렬 | 조직 목표·외부 요구 반영 여부 |
| **Capability** | 필요한 디지털 역량 확보 | 역량 식별·조정·관리 여부 |
| **Policy** | IT 사용·관리 경계 설정 | 전략 결정을 정책으로 전환했는가 |
| **Delegation** | 권한·책임 위임 | 위임 범위와 감독 기준이 명확한가 |
| **Performance** | 기대성과 설정·모니터링 | 성과 기준과 개선 환류가 있는가 |
| **Accountability** | 책임·준수 입증 | 의사결정자와 증적을 추적할 수 있는가 |

## Ⅳ. ISO/IEC 38500 적용 문제점·대응책

> 선언적 원칙을 의사결정 증적과 측정 가능한 감독 기준으로 전환해야 거버넌스가 회의체 운영에 머물지 않음

| 위험 | 대책 | 효과 |
|---|---|---|
| IT 의사결정의 실무부서 편중 | 투자·위험 의사결정권 명문화 | 책임 소재 추적 |
| 운영지표 중심 성과 보고 | 조직 목적·가치·위험 지표 연결 | 가치 중심 감독 |
| 위임 후 감독 공백 | 정기 보고·예외 상향 기준 설정 | 잔여위험 조기 노출 |

## Ⅴ. 의사결정 환류 중심의 기술사적 제언

> 거버넌스 성숙도는 회의체 수가 아니라 판단 근거·위임·감독 결과가 하나의 Feedback Loop로 이어지는가로 판정함

### 학습자 통찰 메모 — 답안 밖

- `[핵심 통찰]`: ISO/IEC 38500의 핵심은 IT 의사결정을 경영진에게 떠넘기는 것이 아니라, 누가 어떤 근거로 판단했고 결과를 어떻게 다시 평가했는지 책임의 고리를 닫는 데 있음.
- `나라면`: 주요 IT 투자마다 목적·결정권자·허용위험·감독지표를 한 장에 묶고, Monitor 결과를 다음 Evaluate 안건의 필수 입력으로 사용하겠음.
