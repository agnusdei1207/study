## 지식 로드맵 내 현재 위치

IT 전략·관리 → 전략적 사고·문제 구조화 → **MECE**

## 30초 인출

- 본질: MECE(Mutually Exclusive, Collectively Exhaustive)는 항목을 서로 겹치지 않고 빠짐없이 나누는 분류 원칙으로, Barbara Minto가 McKinsey 재직 중 고안
- 메커니즘: 핵심 질문 하나에 대해 기준 축 하나로 가지를 나누고 겹침(ME)과 누락(CE)을 검사해 이슈 트리로 전개
- 통찰: MECE를 통과해도 질문과 무관한 가지가 남고 강제한 상호배제가 실제를 왜곡하므로, 가지마다 질문에 답하는 이유와 의도한 겹침을 기록해 검토

<details>
<summary>핵심 용어</summary>

- **MECE(Mutually Exclusive, Collectively Exhaustive)** : 서로 배타적이고 전체를 포괄하도록 항목을 부분집합으로 나누는 원칙
- **ME(Mutually Exclusive, 상호배타)** : 한 항목이 하나의 그룹에만 속해 그룹끼리 겹치지 않는 성질
- **CE(Collectively Exhaustive, 전체 포괄)** : 모든 항목이 어느 한 그룹에는 속해 빠지는 항목이 없는 성질
- **이슈 트리(Issue tree, 로직 트리 Logic tree)** : 핵심 질문을 왼쪽에 두고 구성 요소로 나눠 오른쪽으로 세부화하는 그래프형 분해도
- **진단 트리(Diagnostic tree, Why tree)** : "왜"에 답하도록 가능한 원인을 분해하는 이슈 트리
- **해결 트리(Solution tree, How tree)** : "어떻게"에 답하도록 대안적 접근을 분해하는 이슈 트리
- **피라미드 원칙(Pyramid Principle)** : 하나의 요점 아래 아이디어를 피라미드로 조직하는 Barbara Minto의 사고·글쓰기 방법론. 그룹 안의 아이디어는 논리적으로 같은 종류이고 논리적 순서여야 한다고 규정

## 2~4교시 25점 답안

## Ⅰ. MECE의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **MECE(Mutually Exclusive, Collectively Exhaustive)** 는 항목을 서로 겹치지 않고 빠짐없이 나누는 분류 원칙 |
| 목적 | 문제 분해에서 중복과 누락 방지 |

## Ⅱ. 겹침과 누락을 기준으로 판정하는 MECE의 특징

| 특징 | 의미 | 예 |
|---|---|---|
| **ME** | 한 항목은 하나의 그룹에만 소속 | 출생 연도별 분류: 한 사람은 한 해에만 소속 |
| **CE** | 모든 항목이 어느 그룹에 소속 | 출생 연도별 분류: 모든 사람이 어느 한 해에 소속 |
| 기준의 단일성 | 그룹은 논리적으로 같은 종류여야 하며 기준이 섞이면 판정 불가 | 국적별 분류: 복수 국적자와 무국적자 때문에 MECE 실패 |

## Ⅲ. MECE 분해 체계

### 이슈 트리로 보는 MECE 분해

```text
응답 시간이 느린 이유는?  ← 핵심 질문 (Why)
    ├─ 클라이언트 구간
    ├─ 네트워크 구간
    └─ 서버 구간
         ├─ 애플리케이션 처리
         ├─ 데이터베이스 처리
         └─ 그 밖의 서버 자원 대기
```

### 검사 확대: 한 단계 분해의 검토 절차

```text
기준 축 하나로 하위 항목 나열
    ↓
겹침 검사: 한 항목이 두 가지에 동시에 속하는가
    ├─ 그렇다 → 기준 재정의 또는 겹침 허용 사유 기록
    ↓
누락 검사: 어느 가지에도 속하지 않는 항목이 있는가
    ├─ 그렇다 → 가지 추가
    ↓
관련성 검사: 가지가 핵심 질문에 답하는가
    ├─ 아니다 → 가지 삭제
    ↓
다음 단계 분해
```

## Ⅳ. 이슈 트리의 종류

| 비교축 | 진단 트리(Why tree) | 해결 트리(How tree) |
|---|---|---|
| 답하는 질문 | 왜 이런 문제가 생겼는가 | 어떻게 해결할 것인가 |
| 가지의 의미 | 가능한 원인 | 대안적 접근 |
| ME 검사 대상 | 원인 후보 사이의 중복 | 대안 사이의 중복 |
| CE 검사 대상 | 빠진 원인 | 빠진 대안 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| MECE는 질문과 무관한 항목을 배제하지 못해 겹침·누락이 없어도 쓸모없는 가지가 포함 | 분해 전에 왜 또는 어떻게 중 핵심 질문 하나를 확정하고 가지마다 그 질문에 답하는 이유 확인 |
| 상호배제를 강제하면 실제 대상을 왜곡하고, 해법에는 유익한 중복이 필요한 경우도 존재 | 의도한 겹침은 예외로 표시하고 사유 기록, 겹침이 크면 기준 축 변경 |

## Ⅵ. 제언

가지마다 기준 축·질문과의 관계·겹침 여부를 기록하는 이슈 트리 작성

### 가지 하나의 기록 단위

```text
가지 하나
    ├─ 기준 축      : 형제 가지가 공유하는 분해 기준 1개
    ├─ 질문과의 관계 : 핵심 질문에 답하는 이유
    ├─ 겹침         : 없음 / 허용(사유)
    └─ 누락 확인    : 남은 항목의 처리(가지 추가 또는 '그 밖의' 가지)
```

| 구분 | 겹침·누락만 검사 | 제언: 기록 기반 검토 |
|---|---|---|
| 검토 대상 | 가지의 형식 | 가지의 형식과 질문과의 관련성 |
| 무관한 가지 | 통과 | 답하는 이유가 없으면 삭제 |
| 겹치는 항목 | 오류로 제거 | 유익하면 사유와 함께 허용 |
