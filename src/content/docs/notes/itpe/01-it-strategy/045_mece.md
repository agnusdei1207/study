## 30초 인출

- 본질: MECE(Mutually Exclusive, Collectively Exhaustive)는 대상을 서로 겹치지 않고 빠짐없이 나누는 문제 구조화 원칙
- 메커니즘: 전체 범위를 정하고 한 계층에 하나의 분할축으로 나눈 뒤, 항목 간 겹침(ME)과 합계의 전체 포괄(CE)을 검증
- 통찰: 한 계층에 분할축을 섞으면 겉보기엔 빠짐없어도 중복·누락이 숨으므로 계층별 분할축의 명시와 실제 사례를 이용한 반례 검증

<details>
<summary>핵심 용어</summary>

- **MECE(Mutually Exclusive, Collectively Exhaustive)** : 대상을 서로 겹치지 않게 나누고 합하면 전체를 빠짐없이 포괄하게 만드는 구조화 원칙
- **ME(Mutually Exclusive)** : 같은 계층의 항목끼리 의미·범위가 겹치지 않는 상호 배타 상태
- **CE(Collectively Exhaustive)** : 같은 계층 항목의 합이 상위 범위 전체를 포괄하는 완전 포괄 상태
- **분할축** : 대상을 나누는 단일 기준. 예: 시간 단계·구성요소·이해관계자
- **Issue Tree** : 핵심 질문을 분할축에 따라 하위 논점·원인으로 나눈 계층 트리
- **WBS(Work Breakdown Structure)** : 프로젝트 범위를 인도물 중심의 작업 단위로 계층 분해한 구조
- **100% Rule** : 하위 요소의 합이 상위 요소 범위의 100%와 같아야 한다는 WBS 분해 원칙

</details>

## 2~4교시 25점 답안

## Ⅰ. MECE의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **MECE(Mutually Exclusive, Collectively Exhaustive)** 는 하나의 분할축으로 대상을 중복 없이 빠짐없이 나누는 문제 구조화 원칙 |
| 목적 | 분석·과제 목록의 중복 작업과 검토 누락 방지 |

## Ⅱ. 단순 목록 작성과 구별되는 MECE의 특징

| 특징 | 의미 |
|---|---|
| 경계 우선 | 나누기 전에 전체 범위의 시작과 끝을 확정 |
| 단일 분할축 | 같은 계층의 항목은 같은 기준으로 분리 |
| 같은 추상 수준 | 형제 항목의 크기·수준을 맞춤 |
| 검증 가능성 | 교집합인 **ME** 와 합집합인 **CE** 로 결과를 확인 |

## Ⅲ. MECE 구조화 절차와 검증 판정

### MECE 구조화 절차

```text
핵심 질문·전체 범위 정의
    ↓
계층별 분할축 선택
    ↓
같은 추상 수준으로 항목 분해
    ↓
ME·CE 검증
    ↓
의사결정·책임 가능한 수준에서 분해 중단
```

### ME·CE 검증 확대: 판정 분기

```text
분해한 항목 목록
    ↓
항목끼리 겹치는 사례가 있는가 (ME)
    ├─ 있음 → 분할축 혼용 여부 확인 후 재분할
    └─ 없음
        ↓
    어느 항목에도 속하지 않는 사례가 있는가 (CE)
        ├─ 있음 → 경계·항목 보완
        └─ 없음 → 확정
```

## Ⅳ. 분할 방식 비교

| 분할 방식 | 분할축 | 적합 조건 | 예 |
|---|---|---|---|
| 이분법 | A와 A 아님 | 경계가 분명한 속성 판단 | 내부·외부, 정형·비정형 |
| 프로세스 | 시간·단계 | 순서가 있는 업무·생애주기 | 기획 → 구축 → 운영 |
| 구성요소 | 구조·기능 | 시스템·조직 구조 분석 | 애플리케이션·데이터·인프라 |
| 이해관계자 | 역할·대상 | 요구·영향이 대상별로 다른 경우 | 고객·운영자·규제기관 |
| 검증된 프레임워크 | 이미 정의된 관점 | 외부 환경·전략 분석 | PEST·3C·SWOT |

## Ⅴ. MECE 적용의 한계와 방안

| 한계 | 방안 |
|---|---|
| 한 계층에 단계·조직·기능 기준을 섞어 항목 중복 | 계층마다 분할축을 하나로 명시하고, 순서 있는 업무는 프로세스 분할 선택 |
| 경계가 모호한 대상에 이분법을 적용해 기타 항목 비대 | 기타 항목의 사례를 분석해 구성요소·이해관계자 분할로 전환 |
| 형식적 완전성을 위한 과도한 세분화 | 책임자 지정·의사결정이 가능한 수준에서 분해 중단 |
| 작성자 머릿속 기준으로만 검증한 가짜 완전성 | 실제 업무 사례·데이터를 반례로 넣어 재검증 |

## Ⅵ. 제언

분해 전에 전체 범위와 계층별 분할축을 기록하고, 실제 업무 사례를 반례로 넣어 중복·누락을 확인한 뒤 구조를 확정

### 구조화 기록 구성

```text
구조화 기록
    │
    ├─ 전체 범위 ── 포함·제외 기준
    │
    ├─ 계층별 분할축 ── 계층당 하나의 기준
    │
    └─ 검증 사례 ── 실제 업무·데이터의 반례
```

### 검증 사례 확대: 반례 대입 절차

```text
실제 업무 사례 수집
    ↓
사례별 소속 항목 배정
    ├─ 두 항목에 속함 → 분할축 재검토
    ├─ 어느 항목에도 없음 → 범위·항목 보완
    └─ 한 항목에만 속함 → 다음 사례 대입
    ↓
전 사례 배정 완료 후 구조 확정
```

### 선택 근거: 작성자 판단 중심 구조화와의 비교

| 구분 | 작성자 판단 중심 | 제언: 기록·반례 기반 |
|---|---|---|
| 분할 기준 | 암묵적 | 계층별로 명시 |
| 검증 방법 | 목록 검토 | 실제 사례의 대입 |
| 누락 발견 시점 | 실행 단계 | 구조 확정 전 |
| 기타 항목 처리 | 방치 | 사례 분석 후 분할축 조정 |
