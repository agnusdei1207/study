## 지식 로드맵 내 현재 위치

IT 전략·관리 → 시스템 사고·의사결정 → **인과루프다이어그램(Causal Loop Diagram)**

## 30초 인출

- 본질: 인과루프다이어그램(CLD)은 변수 사이의 인과 방향과 되먹임 고리를 화살표와 극성으로 그린 시스템 사고 도구
- 메커니즘: 변수 간 링크에 같은 방향(+)·반대 방향(−) 극성을 붙이고, 닫힌 고리의 음(−) 링크가 0개·짝수면 강화(R), 홀수면 균형(B) 루프로 판정
- 통찰: 지연된 효과를 무효로 오판하면 대책을 과잉 투입하므로 개입 전 지연 기간과 확인 시점 확정

<details>
<summary>핵심 용어</summary>

- **인과루프다이어그램(Causal Loop Diagram)** : 변수 간 인과 방향·극성과 되먹임 고리를 표현하는 정성적 시스템 모델. 약칭 CLD
- **극성(Polarity)** : 원인이 늘 때 결과도 늘면 `+`, 결과가 줄면 `−`로 표시하는 링크의 방향성
- **강화 루프(Reinforcing Loop, R)** : 한 바퀴 돈 변화가 처음 변화를 더 키우는 되먹임 고리
- **균형 루프(Balancing Loop, B)** : 한 바퀴 돈 변화가 처음 변화를 억제해 목표 쪽으로 되돌리는 되먹임 고리
- **지연(Delay)** : 원인 변화가 결과 변수에 나타나기까지 걸리는 시간
- **BOT(Behavior Over Time)** : 핵심 변수가 시간에 따라 변해 온 추세 그래프
- **Stock·Flow 모델** : 누적량(Stock)과 유입·유출률(Flow)을 수식으로 표현해 시뮬레이션하는 시스템 다이내믹스의 정량 모델

## 2~4교시 25점 답안

## Ⅰ. 인과루프다이어그램의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **인과루프다이어그램(Causal Loop Diagram)** 은 변수 간 인과 방향·극성과 되먹임 고리를 표현하는 정성적 시스템 모델 |
| 목적 | 반복되는 문제의 순환 구조 파악과 개입 효과의 사전 검토 |

## Ⅱ. 선형 원인 분석과 구별되는 CLD의 특징

| 특징 | 의미 |
|---|---|
| 순환 인과 | 한 변수의 변화가 연결을 따라 다시 자신에게 돌아오는 구조 |
| 극성 표기 | 링크마다 같은 방향 `+`·반대 방향 `−`의 **극성** 표시 |
| 지연 표현 | 원인과 결과 사이의 시간 차이를 **지연** 으로 별도 표시 |
| 정성 모델 | 인과 가설의 공유 도구. 정량 예측은 **Stock·Flow 모델** 의 역할 |

## Ⅲ. CLD 작성 절차와 루프 극성 판정

### CLD 작성 절차

```text
문제 정의와 시간 추세(BOT) 관찰
    ↓
핵심 변수 도출 ── 증감 가능한 명사형
    ↓
변수 간 인과 링크와 극성(+/−) 표시
    ↓
닫힌 고리의 루프 극성(R/B) 판정·지연 표시
    ↓
관찰 자료로 가설 검증·개입 지점 선정
```

### 루프 극성 판정 확대: 음(−) 링크 개수 규칙

```text
닫힌 고리 안의 음(−) 링크 개수 확인
    ├─ 0개 또는 짝수 → 강화 루프(R): 변화 증폭
    └─ 홀수 → 균형 루프(B): 목표 방향 수렴
```

## Ⅳ. 강화 루프와 균형 루프의 비교

| 기준 | **강화 루프** (R) | **균형 루프** (B) |
|---|---|---|
| 음(−) 링크 수 | 0개 또는 짝수 | 홀수 |
| 시스템 행동 | 변화의 증폭(성장·붕괴) | 목표 방향 수렴 |
| 지연이 있을 때 | 증폭의 체감 지연 | 목표 주변의 진동·과잉 대응 |
| IT 프로젝트 사례 | 일정 압박의 재작업 악순환 | 잔존 결함에 따른 검토 강화 |

### IT 프로젝트 사례의 R·B 루프

```text
R1 강화 루프 (음 링크 0개)
일정 압박 ─(+)→ 결함 유입 ─(+)→ 재작업
재작업 ─(+)→ 일정 압박

B1 균형 루프 (음 링크 1개)
잔존 결함 ─(+)→ 검토 강화
검토 강화 ─(−, 지연)→ 잔존 결함
```

## Ⅴ. CLD 적용의 한계와 방안

| 한계 | 방안 |
|---|---|
| 균형 루프의 지연 무시로 대책의 중복·과잉 투입 | 링크의 지연 표시와 효과 확인 시점의 사전 설정 |
| 상관관계의 인과관계 오인 | 관찰 자료·현업 인터뷰로 인과 가설 교차 검증 |
| 변수·경계 과다로 핵심 루프 식별 곤란 | 문제 추세를 설명하는 핵심 루프만 남기고 분석 경계 명시 |
| 모호한 변수명으로 극성 판정 오류 | 증감 가능한 명사형 변수명 사용 |
| 정성 모델의 정량 예측 오용 | 정량 예측이 필요하면 Stock·Flow 모델로 확장 |

## Ⅵ. 제언

균형 루프에 개입하기 전 효과 지연 기간과 확인 시점을 정하고, 그 시점의 결과 변수로 추가 대책 여부를 판단

### 개입 효과 확인 구조

```text
균형 루프 개입 계획
    │
    ├─ 개입 변수 ── 조치 내용·투입 시점
    │
    ├─ 지연 기간 ── 효과가 나타날 예상 기간
    │
    └─ 결과 변수 ── 확인 시점의 측정값
```

### 결과 변수 확대: 확인 시점의 판단 절차

```text
예상 지연 기간 경과
    ↓
결과 변수의 추세 확인
    ├─ 목표 방향 변화 → 기존 대책 유지
    ├─ 변화 없음 → 인과 가설·지연 기간 재검토
    └─ 과잉 변화 → 대책 강도 축소
```

### 선택 근거: 즉시 효과를 기대하는 대응과의 비교

| 구분 | 즉시 효과 기대 대응 | 제언: 지연 반영 대응 |
|---|---|---|
| 효과 판단 시점 | 조치 직후 | 예상 지연 기간 경과 후 |
| 효과 미확인 시 조치 | 대책 추가 투입 | 인과 가설·지연 기간 재검토 |
| 결과 변수 행동 | 과잉 대응에 따른 진동 | 목표 방향 수렴 |
