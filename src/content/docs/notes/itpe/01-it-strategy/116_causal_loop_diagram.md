## 지식 로드맵 내 현재 위치

IT 전략·관리 → 프로젝트 관리·시스템 사고 → **인과루프다이어그램(Causal Loop Diagram)**

## 30초 인출

- 본질: 인과루프다이어그램은 변수 사이의 원인·결과를 화살표로 잇고 피드백 루프의 종류를 표시해, 시스템이 그런 동작을 보이는 이유에 대한 가설을 그리는 지도
- 메커니즘: 링크마다 +·− 극성을 붙이고 루프를 한 바퀴 돌며 음(−) 링크 수가 짝수(0 포함)면 강화(R), 홀수면 균형(B)으로 판정
- 통찰: 인력 추가 같은 단기 대응은 목표를 좇는 균형 루프 옆에 생산성 저하의 부작용 루프를 만들어 효과가 상쇄될 수 있으므로 결정 전에 두 루프를 함께 그려 극성으로 판정하고 정량 판단은 시뮬레이션으로 이어감

<details>
<summary>핵심 용어</summary>

- **인과루프다이어그램(Causal Loop Diagram, CLD)** : 변수를 인과 링크로 잇고 극성과 루프 식별자를 붙여 시스템의 피드백 구조를 나타내는 지도
- **시스템 다이내믹스(System Dynamics)** : 피드백과 축적으로 복잡한 시스템의 시간에 따른 동작을 이해하고 컴퓨터 시뮬레이션으로 검증하는 방법
- **링크 극성(Link Polarity)** : 다른 조건이 같을 때 원인 변수의 증가에 결과 변수가 같은 방향(+)이나 반대 방향(−)으로 움직이는 관계
- **강화 루프(Reinforcing Loop, R)** : 한 바퀴 돈 피드백이 처음 변화를 키우는 루프. 양(+)의 루프
- **균형 루프(Balancing Loop, B)** : 한 바퀴 돈 피드백이 처음 변화를 상쇄하는 루프. 음(−)의 루프이며 목표(원하는 상태)를 가짐
- **지연(Delay)** : 원인의 변화가 결과에 나타나기까지의 시간 지체
- **동적 가설(Dynamic Hypothesis)** : 문제가 왜 발생했는지를 시스템 내부 구조로 설명하는 작업 이론
- **Stock(수준)과 Flow(변화율)** : Stock은 시스템의 상태를 나타내는 축적량, Flow는 그 상태가 변하는 속도
- **정책 저항(Policy Resistance)** : 개입이 시스템의 반응 때문에 지연·희석·무력화되는 경향

</details>

## 2~4교시 25점 답안

## Ⅰ. 인과루프다이어그램의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **인과루프다이어그램(Causal Loop Diagram, CLD)** 은 변수 간 인과 링크와 피드백 루프의 종류를 표시한 시스템 구조도 |
| 목적 | 문제를 일으키는 피드백 구조에 대한 동적 가설의 표현과 공유 |

## Ⅱ. 피드백 구조를 보여 주는 인과루프다이어그램의 특징

| 특징 | 의미 |
|---|---|
| 인과 링크 중심 | 상관이 아닌 실제 원인·결과 관계만 화살표로 표시 |
| 극성 표기 | 링크마다 +·−로 변화의 방향 관계 명시 |
| 루프 유형 식별 | 루프를 **강화 루프** 와 **균형 루프** 로 구분해 시스템 동작의 원인 파악 |
| 정성적 지도 | 수식이 아닌 구조와 방향을 표현하고 이후 시뮬레이션의 출발점으로 활용 |

## Ⅲ. 표기법과 작성 절차

### 시스템 다이내믹스 모델링에서의 CLD 위치

```text
1. 문제 정의(Problem Articulation, 경계 선택)
    ↓
2. 동적 가설(Dynamic Hypothesis) ◀ CLD 작성
    ↓
3. 수식화(Formulation) ── Stock·Flow 모델
    ↓
4. 검증(Testing)
    ↓
5. 정책 수립과 평가(Policy Formulation & Evaluation)
   (전 과정 반복)
```

### 표기법 확대: 링크 극성과 루프 판정

```text
X ──(+)──→ Y   X 증가 → Y가 원래보다 증가 (같은 방향)
X ──(−)──→ Y   X 증가 → Y가 원래보다 감소 (반대 방향)
X ──‖──→ Y     원인과 결과 사이의 지연(Delay) 표시

루프 판정 : 루프 한 바퀴에서 센 음(−) 링크의 수
            짝수(0 포함) → R 강화     홀수 → B 균형
```

```text
완료 작업 ──(−)──→ 필요 인력 ──(+)──→ 투입 인력
   ↑                                    │
  (+)                                  (+)
   │                                    ↓
   └───────────── 작업 속도 ←───────────┘
              B : 음(−) 링크 1개 → 균형
```

## Ⅳ. 강화 루프와 균형 루프의 비교, CLD와 Stock-Flow 모델의 비교

### 루프 유형 비교

| 비교축 | 강화 루프(R) | 균형 루프(B) |
|---|---|---|
| 판정 | 음(−) 링크가 짝수(0 포함) | 음(−) 링크가 홀수 |
| 피드백 효과 | 처음 변화를 강화 | 처음 변화를 상쇄 |
| 목표 | 없음. 변화를 증폭 | 원하는 상태와 실제 상태를 비교해 조정 |
| 프로젝트 예시 | 투입 인력 → 생산성 → 필요 인력 (Ⅵ) | 완료 작업 → 필요 인력 → 투입 인력 → 작업 속도 |

### 도구 층위 비교

| 비교축 | CLD (정성 도구) | Stock-Flow 모델 (정량 도구) |
|---|---|---|
| 표현 대상 | 변수 간 인과와 루프 유형 | Stock과 Flow를 수식으로 연결 |
| 산출 | 동적 가설·구조 이해 | 시간에 따른 값의 시뮬레이션·민감도 분석 |
| 한계 | Stock·Flow 미구분, 변화의 크기·시간 불명 | 수식화한 가정의 검증 필요 |

## Ⅴ. 인과루프다이어그램의 한계와 방안

| 한계 | 방안 |
|---|---|
| 상관을 인과로 넣으면 그릇된 정책 판단 유발 | 링크마다 실제 인과의 근거를 확인하고 상관만 있는 관계 제외 |
| 링크의 극성이 모호하면 경로가 여럿 존재 | 두 변수 사이 경로를 세분화해 극성이 분명해질 때까지 변수 분해 |
| 균형 루프의 목표가 그려지지 않아 조정 기준 불명확 | 원하는 상태(목표)를 변수로 명시 |
| 세부가 과하면 복잡해지고 부족하면 논리 불명확 | 논리를 파악할 수 있는 수준의 구조만 추가 |
| 크기·시간 파악 불가로 루프 간 우세 판단 불가 | 지연을 표시하고 Stock-Flow 모델로 수식화해 시뮬레이션 |

## Ⅵ. 제언

인력 추가 같은 단기 대응을 결정하기 전에, 목표를 좇는 균형 루프와 그 대응이 만드는 부작용 강화 루프를 CLD로 함께 그려 극성으로 판정하고 크기는 시뮬레이션으로 확인

### 인력 추가 대응의 균형 루프와 부작용 루프

```text
   ┌──────────────(−)───────────────────┐
   ↓                                    │
필요 인력 ──(+)──→ 투입 인력 ──(−)──→ 생산성
   ↑                  │                 │
  (−)                (+)               (+)
   │                  ↓                 │
완료 작업 ←──(+)── 작업 속도 ←──────────┘
B : 완료 작업 → 필요 인력 → 투입 인력 → 작업 속도 (음 1개, 균형)
R : 투입 인력 → 생산성 → 필요 인력 (음 2개, 강화)
```

### 결정 절차 확대: 부작용 루프 검토와 정량 확인

```text
단기 대응안(인력 추가) 제시
    ↓
목표를 좇는 균형 루프 작성
    ↓
대응이 바꾸는 다른 변수(생산성) 탐색 → 부작용 루프 작성
    ↓
루프별 극성 판정과 지연 표시
    ↓
Stock-Flow 모델 시뮬레이션으로 크기 확인 → 대응안 결정
```

| 구분 | 균형 루프만 반영한 결정 | 제언: 부작용 루프까지 함께 판정 |
|---|---|---|
| 검토 대상 | 인력 추가의 작업 속도 증가 | 인력 추가의 생산성 저하 경로 포함 |
| 판정 기준 | 목표와의 차이 | 루프별 극성과 지연 |
| 크기 판단 | 직관 | Stock-Flow 시뮬레이션 |
