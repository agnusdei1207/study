## 연관 키워드

- 액티브-액티브 이중화, 동기·비동기 복제, 펜싱, RTO·RPO
- 스토리지 재해복구(DR), 국정자원 후속 조치

## Ⅰ. 액티브-액티브 이중화와 스토리지 DR의 개요

- 핵심 요약 : 복수 센터의 동시 처리·복제 구성과 재해 시 데이터 회복 체계의 결합으로 서비스 연속성 확보.
- 개념 : **액티브-액티브 이중화** (Active-Active)는 둘 이상의 센터가 평상시 동시에 업무를 처리하며 데이터를 상호 복제하는 가용성 구성이고, **재해복구** (DR, Disaster Recovery)는 재해·대형 장애 시 업무와 데이터를 대체 환경에서 회복하는 체계.
- 배경 및 필요성 : 단일 센터 의존 구조는 화재 같은 물리 재해에서 서비스 전면 중단·데이터 손실 위험이 있음(2025년 국가정보자원관리원 대전센터 화재 사례).
- 주요 목적 : 업무별 **복구목표시간** (RTO, Recovery Time Objective)·**복구목표시점** (RPO, Recovery Point Objective)의 충족과 사이트 전면 장애 상황에서의 서비스 지속·데이터 정합성 유지.

## Ⅱ. 액티브-액티브 이중화와 스토리지 DR의 특징 및 장점

- 핵심 요약 : 동시 처리, 데이터 복제, 펜싱, 트래픽 전환, 재동기화가 가용성과 정합성을 함께 높임.

1. 동시 처리 : 복수 센터가 트래픽을 분담 처리 → 일부 센터 상실 시에도 서비스 지속.
2. 데이터 복제 : 동기 복제는 쓰기 시점 일치로 손실 최소화, 비동기 복제는 전송 지연을 감수하고 성능 확보 → 업무별 데이터 손실 허용 수준의 관리.
3. 펜싱·쿼럼 : **펜싱** (Fencing)으로 단절된 센터의 쓰기를 차단하고 다수 합의(쿼럼, Quorum)로 정상 센터를 판정 → 분할뇌(양쪽 동시 쓰기) 방지.
4. 트래픽 전환 : 글로벌 로드밸런싱·DNS 전환으로 사용자 요청을 건전 센터로 이동 → 전환 시간 단축.
5. 복구 후 재동기화 : 복귀 센터의 데이터 검증·재합류 → 서비스 정합성 회복.

## Ⅲ. 액티브-액티브 이중화와 스토리지 DR의 구조 (흐름)

- 핵심 요약 : 동시 운영 → 복제 → 장애 판정·격리 → 전환 → 재동기화의 운영 흐름과 사고 후 후속 조치 흐름.

```text
센터 A (동시 처리)  ↔  센터 B (동시 처리)
   ↓
스토리지 복제 (동기·비동기)
   ↓
장애 감지 → 펜싱
   ↓
트래픽 전환
   ↓
데이터 검증·재동기화
```

- 국정자원 후속 조치 : 2025년 국가정보자원관리원 화재 이후 국가인공지능전략위원회의 「AI 정부 인프라 거버넌스·혁신 추진방향」(2026년 2월)이 시스템 유형별 복구 목표(국가 핵심 시스템 실시간~1시간 이내 등), 대전센터 시스템 대상 DR 우선 구축(134개), 민간 클라우드 기반 DR 선도 사업, 데이터센터 안전기준 강화를 후속 조치로 확정.

```text
사고 원인 분석
   ↓
시스템 유형별 복구 목표 설정
   ↓
DR 우선 구축·클라우드 DR 시범
   ↓
데이터 등급별 저장소 분리
   ↓
정기 복구시험·안전기준 강화
```

## Ⅳ. 액티브-액티브 이중화와 액티브-패시브 이중화의 비교

- 핵심 요약 : 액티브-액티브는 동시 처리로 전환 시간을 줄이고, 액티브-패시브는 대기 구성으로 비용 효율을 높임.

| 비교 축 | 액티브-액티브 이중화 | 액티브-패시브 이중화 |
| --- | --- | --- |
| 운영 상태 | 복수 센터 평상시 동시 처리 | 주센터 처리·대기 센터는 전환 시 승격 |
| 자원 활용 | 대기 자원 없이 동시 활용 | 대기 자원의 상시 유휴 |
| 전환 시간 | 일부 트래픽이 이미 건전 센터 처리 → 단축 | 승격·동기화 절차 소요 |
| 정합성 위험 | 분할뇌·동시 쓰기 충돌 | 승격 시점의 복제 지연 데이터 |
| 구축·운영 비용 | 높음(정합성 관리 부담) | 상대적으로 낮음 |
| 적합한 업무 | 짧은 RTO·고가용성 업무 | 비용 효율 중심의 재해복구 업무 |

## Ⅴ. 액티브-액티브 이중화와 스토리지 DR의 한계와 방안

- 핵심 요약 : 분할뇌, 복제 지연, 전환 실패, 운영 복잡성을 설계·감시·훈련으로 일대일 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 분할뇌 | 센터 간 통신 단절로 양쪽 쓰기 허용 → 데이터 충돌 | 쿼럼·펜싱·단일 쓰기 권한 설계 | 중복 쓰기 사고 건수 |
| 복제 지연·불일치 | 비동기 복제·장거리 전송 → 손실 확대 | 업무별 복제 모드·지연 감시 | 복제 지연 시간 |
| 전환 실패 | 의존 서비스·DNS 설정 누락 → RTO 초과 | 시나리오별 전환 절차·실전 훈련 | 복구시험 성공률 |
| 운영 복잡성 | 다중 센터·정합성 관리 부담 → 인력 의존 | 표준 절차 문서화·자동화 | 장애 조치 소요 시간 |

## Ⅵ. 액티브-액티브 이중화와 스토리지 DR에 대한 제언

- 핵심 요약 : 복구 목표의 제도화, 데이터 등급별 인프라 전환, 회복 탄력성 검증으로 국정자원 DR 체계를 상위 수준에서 완성.

1. 국가인공지능전략위원회·행정안전부 : 시스템 유형별 복구 목표 기준의 제도화와 국정자원 DR 구축 이행 점검.
2. 국가정보자원관리원 : 기밀·민감·공개 데이터의 저장소 분리 운용과 민간 클라우드 DR 병행 체계로의 전환.
3. 감사·점검 주체 : 사고 후속 조치 이행률과 복구시험 결과의 정기 공개로 회복 탄력성 검증.

## Ⅶ. 결론

- 핵심 요약 : 액티브-액티브 이중화와 스토리지 DR은 서비스 연속성과 데이터 보전의 아키텍처적 전제.
- 회복 역량은 구축 선언이 아니라 반복 시험과 사고 후속 조치의 이행으로 완성.
