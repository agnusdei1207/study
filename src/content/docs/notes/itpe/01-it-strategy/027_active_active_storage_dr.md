## 지식 로드맵 내 현재 위치

IT 전략·관리 → 재해복구·서비스 연속성 → **액티브-액티브 이중화와 스토리지 DR**

## 30초 인출

- 본질: 액티브-액티브 스토리지 DR은 두 거점이 평상시 함께 서비스하며 데이터를 서로 복제해, 한 거점 장애 때 남은 거점이 업무를 이어받는 재해복구 구성
- 메커니즘: GSLB의 요청 분산, 거점 간 동기·비동기 복제, 쿼럼 중재의 쓰기 주체 판정 후 장애 거점 격리와 트래픽 전환
- 통찰: 두 거점을 갖춘 것만으로는 목표 충족을 알 수 없으므로 업무별 RTO·RPO에 따른 방식 선택과 절체 시험

<details>
<summary>핵심 용어</summary>

- **액티브-액티브 스토리지 DR** : 둘 이상의 거점이 평상시 함께 요청을 처리하고 거점 간 데이터 복제로 한 거점 장애 때 업무를 이어 가는 재해복구 구성
- **액티브-패시브(Active-Passive)** : 주 거점만 요청을 처리하고 대기 거점은 장애 전환 뒤에야 요청을 받는 구성
- **파일럿 라이트(Pilot Light)** : 데이터 복제와 핵심 기반만 복구 거점에 상시 가동하고 애플리케이션 서버는 전환 때 기동·확장하는 재해복구 방식
- **GSLB(Global Server Load Balancing)** : 여러 거점의 상태와 정책에 따라 사용자 요청을 분산하거나 정상 거점으로 전환하는 부하 분산 기능
- **동기 복제(Synchronous Replication)** : 원격 거점 저장을 확인한 뒤 호스트에 쓰기 완료를 응답하는 복제 방식
- **비동기 복제(Asynchronous Replication)** : 로컬 저장 뒤 먼저 완료를 응답하고 원격 거점에는 뒤이어 반영하는 복제 방식
- **RTO(Recovery Time Objective)** : 장애 뒤 업무를 목표 수준으로 재개하기까지 허용하는 시간 목표
- **RPO(Recovery Point Objective)** : 장애 때 되돌아갈 수 있는 데이터 시점의 목표, 곧 허용 데이터 손실 범위
- **스플릿 브레인(Split-Brain)** : 거점 간 통신 단절 뒤 두 거점이 동시에 쓰기 주체로 동작해 데이터가 서로 달라지는 상태
- **쿼럼 중재(Quorum Witness)** : 제3의 판정자가 다수결로 정상 동작할 거점을 정하는 기능
- **I/O 펜싱(I/O Fencing)** : 쓰기 주체에서 제외된 거점의 스토리지 쓰기를 차단하는 보호 기능

## 2~4교시 25점 답안

## Ⅰ. 액티브-액티브 스토리지 DR의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **액티브-액티브 스토리지 DR** 은 둘 이상의 거점이 평상시 함께 요청을 처리하고 거점 간 데이터 복제로 장애 시 업무를 이어 가는 재해복구 구성 |
| 목적 | 거점 장애 때 서비스 중단 시간과 데이터 손실의 최소화 |

## Ⅱ. 대기 거점 없이 함께 처리하는 액티브-액티브의 특징

| 특징 | 의미 |
|---|---|
| 복수 거점 동시 처리 | 장애 전에도 두 거점이 요청을 처리해 별도 기동 절차 없음 |
| 트래픽·데이터 분리 | 사용자 요청 전환과 저장 데이터 정합성의 별도 보장 |
| 쓰기 주체 통제 | 통신 단절 때 한 거점만 쓰기를 계속하도록 하는 중재 필요 |
| 논리 오류 전파 | 삭제·손상도 즉시 복제되어 시점 백업이 별도로 필요 |

## Ⅲ. 액티브-액티브 스토리지 DR의 구성과 복제·중재 동작

### 액티브-액티브 스토리지 DR 구성

```text
액티브-액티브 스토리지 DR
    │
    ├─ 트래픽 계층 ── GSLB: 거점 상태별 요청 분산·전환
    │
    ├─ 서비스 계층 ── 거점 A·B 애플리케이션의 동시 처리
    │
    ├─ 데이터 계층 ── 거점 간 스토리지 복제(동기·비동기)
    │
    └─ 중재 계층 ── 쿼럼 중재: 통신 단절 때 쓰기 주체 판정
```

### 데이터 계층 확대: 동기·비동기 복제의 쓰기 응답 순서

```text
동기 복제
    호스트 쓰기 → 로컬 저장 → 원격 저장
    원격 저장 확인 → 호스트 완료 응답

비동기 복제
    호스트 쓰기 → 로컬 저장 → 호스트 완료 응답
    로컬 → 원격 후속 반영
```

동기 복제는 원격 왕복 지연만큼 쓰기 응답이 늦어져 거점 간 거리에 제약, 비동기 복제는 응답이 빠르나 미반영 구간만큼 데이터 손실 가능

### 중재 계층 확대: 거점 간 통신 단절 처리

```text
거점 간 복제 링크 단절
    ↓
쿼럼 중재의 거점 상태 판정
    ├─ 쿼럼 확보 거점 → 단일 쓰기 주체로 서비스 지속
    └─ 쿼럼 상실 거점 → I/O 펜싱으로 쓰기 차단
    ↓
GSLB의 쓰기 주체 거점으로 요청 전환
```

## Ⅳ. 액티브-액티브·액티브-패시브·파일럿 라이트의 비교

| 구분 | 액티브-액티브 | **액티브-패시브** | **파일럿 라이트** |
|---|---|---|---|
| 평상시 복구 거점 | 요청을 함께 처리 | 전체 구성 대기, 요청 미처리 | 데이터 복제·핵심 기반만 가동 |
| 장애 시 조치 | 장애 거점의 트래픽 제외 | 대기 거점으로 트래픽 전환 | 애플리케이션 서버 기동·확장 후 전환 |
| 전환 시간(RTO) | 가장 짧음 | 중간 | 가장 김 |
| 비용·운영 부담 | 두 거점 상시 운영과 쓰기 정합성 통제로 가장 큼 | 대기 자원 유지 비용 | 최소 자원 유지로 가장 작음 |

데이터 손실(RPO)은 세 방식 모두 구성 방식보다 복제 방식과 복제 지연에 좌우

## Ⅴ. 액티브-액티브 스토리지 DR의 한계와 방안

| 한계 | 방안 |
|---|---|
| 짧은 RTO가 필요 없는 업무까지 액티브-액티브 적용으로 비용·정합성 부담 증가 | 전환 시간이 가장 짧아야 하는 업무만 액티브-액티브, 나머지는 RTO에 맞춰 액티브-패시브·파일럿 라이트 선택 |
| 비동기 복제 지연 중 장애로 데이터 손실 | 손실 불허 업무의 회선 지연 허용 거리 내 동기 복제, 그 외 업무의 복제 지연 RPO 기준 감시 |
| 거점 간 통신 단절에 따른 **스플릿 브레인** | 제3 위치의 **쿼럼 중재** 와 **I/O 펜싱** 의 단절 시나리오 시험 |
| 남은 거점의 전체 부하 미수용 | 한 거점 상실 기준의 용량 확보와 업무 우선순위 설정 |
| 논리 오류·랜섬웨어의 복제본 전파 | 복제와 분리된 시점 백업의 보존과 복원 시험 |

## Ⅵ. 제언

구성·복제 방식을 제품 기능이 아닌 업무별 RTO·RPO로 고르고, 한 거점 상실 절체 시험의 실측으로 목표 달성을 확인하는 설계 순서의 확립

### 업무 목표 기반 DR 방식 선택 절차

```text
업무별 RTO·RPO 확정
    ↓
RTO 기준 구성 방식 선택
    (액티브-액티브·액티브-패시브·파일럿 라이트)
    ↓
RPO 기준 복제 방식 선택: 동기·비동기
    ↓
한 거점 상실 절체 시험
    ├─ 목표 충족 → 운영 기준 확정
    └─ 목표 미달 → 구성·복제 방식 재선택
```

### 절체 시험 확대: 한 거점 상실 시험 항목

```text
한 거점 상실 절체 시험
    │
    ├─ 전환 시간 ── 업무 재개까지의 실측값과 RTO 대조
    ├─ 데이터 시점 ── 마지막 복제 반영 시점과 RPO 대조
    ├─ 쓰기 주체 ── 쿼럼 판정과 I/O 펜싱 동작
    └─ 잔존 용량 ── 남은 거점의 전체 부하 처리
```

### 선택 근거: 거점 구성 우선 설계와의 비교

| 구분 | 거점 구성 우선 설계 | 제언: 업무 목표 우선 설계 |
|---|---|---|
| 구성 방식 결정 근거 | 가용성 기대와 제품 기능 | 업무별 RTO |
| 복제 방식 결정 근거 | 제품 기본 설정 | 업무별 RPO와 회선 지연 |
| 목표 달성 확인 | 구축 뒤 기능 점검 | 한 거점 상실 절체 시험의 실측 |
