## Ⅰ. 액티브-액티브 이중화와 스토리지 DR의 개요

- 핵심 요약 : **액티브-액티브 이중화** (Active-Active)는 둘 이상의 센터가 동시에 서비스를 처리하고 데이터를 복제하며, **스토리지 DR** (Disaster Recovery)은 장애 시 데이터를 대체 환경에서 복구하는 구성.
- 개념 : 액티브-액티브 이중화와 스토리지 DR은 둘 이상의 센터가 동시에 서비스를 처리하고 데이터를 복제하며, 장애 시 데이터를 대체 환경에서 복구하는 구성.
- 배경 및 필요성 : 짧은 복구시간이 필요한 서비스라도 동기·비동기 복제, 네트워크 분리, 운영 절차에 따라 실제 복구 성과가 달라짐.
- 주요 목적 : 업무별 **RTO** (Recovery Time Objective)·**RPO** (Recovery Point Objective)를 충족하고 사이트 장애 시 서비스·데이터 정합성 확보.

## Ⅱ. 액티브-액티브 이중화와 스토리지 DR의 특징 및 장점

- 핵심 요약 : 동시 처리, 데이터 복제, 장애 감지·펜싱, 트래픽 전환, 복구 후 재동기화가 가용성과 정합성을 함께 높임.

1. 동시 처리 : 복수 센터가 평상시 트래픽을 분담 처리 → 단일 센터 장애 시에도 서비스 지속.
2. 데이터 복제 : 동기·비동기 방식으로 데이터를 센터 간 복제 → RPO에 맞는 데이터 손실 제어.
3. 장애 감지·펜싱 : **펜싱** (Fencing)으로 단절된 센터의 쓰기를 차단 → 분할뇌로 인한 중복 쓰기 방지.
4. 트래픽 전환 : DNS·로드밸런서·글로벌 트래픽 관리로 사용자 요청을 건전 센터로 전환 → RTO 단축.
5. 복구 후 재동기화 : 장애 센터 복귀 시 데이터 차이를 조정하고 재합류 → 서비스 정합성 복원.

## Ⅲ. 액티브-액티브 이중화와 스토리지 DR의 구조 (흐름)

- 핵심 요약 : 업무 목표 설정 → 센터·복제 방식 설계 → 정상 동시 운영 → 장애 판정·격리 → 서비스 전환 → 데이터 검증·복귀.

```text
업무 목표 설정
   ↓
센터·복제 방식 설계
   ↓
정상 동시 운영
   ↓
장애 판정·격리
   ↓
서비스 전환
   ↓
데이터 검증·복귀
```

- 핵심 구조 : 동시 처리, 데이터 복제, 장애 감지·펜싱, 트래픽 전환, 복구 후 재동기화.

```text
센터 A 처리·복제 ↔ 센터 B 처리·복제
   ↓
단절 감지 → 펜싱 → 트래픽 전환 → 데이터 검증
```

## Ⅳ. 액티브-패시브 DR과 액티브-액티브 이중화의 비교

- 핵심 요약 : 액티브-패시브는 주센터 처리·대기센터 승격, 액티브-액티브는 복수 센터 평상시 동시 처리.

| 비교 기준 | 액티브-패시브 DR | 액티브-액티브 이중화와 스토리지 DR |
| --- | --- | --- |
| 운영 상태 | 주센터가 처리, 대기센터는 장애 때 승격 | 복수 센터가 평상시 동시 처리 |
| 자원 활용 | 대기 자원 유휴 | 자원 동시 활용 |
| 전환 시간 | 승격·데이터 동기화 시간 필요 | 일부 트래픽은 이미 건전 센터 처리 |
| 정합성 위험 | 승격 시 데이터 지연 | 분할뇌·동시 쓰기 충돌 |
| 적합한 업무 | 비용 효율적 복구가 필요한 업무 | 고가용성·짧은 RTO가 필요한 업무 |

## Ⅴ. 액티브-액티브 이중화와 스토리지 DR의 한계와 방안

- 핵심 요약 : 분할뇌·데이터 불일치·전환 실패; 쿼럼·펜싱·복제모드·실전 훈련으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 분할뇌 | 센터 간 통신 단절로 양쪽이 쓰기 허용 | 쿼럼·펜싱·단일 쓰기 권한 설계 | 중복 쓰기 사고 |
| 데이터 불일치 | 비동기 복제 지연·충돌 | 업무별 복제모드·정합성 규칙·재조정 절차 | 복제지연·불일치율 |
| 전환 실패 | DNS·네트워크·의존서비스 누락 | 시나리오별 자동·수동 절차와 실전 훈련 | 복구시험 성공률 |
| 운영 복잡성 | 복수 센터 운영·동기화 부담 | Runbook·자동화·정기 훈련 | MTTR·훈련 조치완료율 |

## Ⅵ. 액티브-액티브 이중화와 스토리지 DR에 대한 제언

- 핵심 요약 : 업무·IT 책임자는 업무별 RTO·RPO와 데이터 손실 허용을 정하고, 운영팀은 센터 단절·복귀를 포함한 전환훈련을 반복.

1. 업무·IT 책임자 : 업무별 RTO·RPO와 데이터 손실 허용을 정하고 복제모드·전환 조건을 승인.
2. 운영팀 : 쿼럼·펜싱·단일 쓰기 권한 설계; 중복 쓰기 사고·복제지연·불일치율·복구시험 성공률 지표를 정기 검토하고 미달 원인·시정조치·잔여위험 기록.
3. 감사·검증 : 센터 단절·복귀를 포함한 실전 훈련과 데이터 검증 절차를 반복.

## Ⅶ. 액티브-액티브 이중화와 스토리지 DR의 결론

- 핵심 요약 : 액티브-액티브 이중화는 둘 이상의 센터가 동시에 서비스를 처리하고 데이터를 복제하며, 스토리지 DR은 장애 시 데이터를 대체 환경에서 복구하는 구성.
- 시사점 : 액티브-액티브는 가용성을 높이는 아키텍처이며, 정합성·운영 통제가 복구목표 달성의 전제.
