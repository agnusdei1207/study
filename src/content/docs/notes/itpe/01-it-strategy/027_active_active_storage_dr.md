## Ⅰ. 액티브-액티브 이중화와 스토리지 DR의 개요

- 핵심 요약 : 지리적으로 분리된 양 센터가 동시에 트래픽을 처리하며 재해 시 RTO·RPO를 최소화하도록 설계하는 고가용 재해복구 체계.
- 개념 : 지리적으로 분리된 두 개 이상의 데이터센터에 동일한 애플리케이션과 스토리지 클러스터를 구축하여, 양 센터가 동시에 트래픽을 처리하면서 한 센터 재해 발생 시 복구시간목표(RTO, Recovery Time Objective)와 복구시점목표(RPO, Recovery Point Objective)를 최소화하도록 서비스를 설계하는 고가용 재해복구 체계(DR, Disaster Recovery).
- 배경 및 필요성 : 데이터센터 화재, 전력 공급 중단 등으로 인한 국가 핵심 행정망 및 금융 서비스 마비 사태 이후, 대기 센터로의 수동 전환(Hot Site) 한계를 극복하는 실시간 이중화 요구 대두.
- 주요 목적 : 서비스 무중단 연속성 보장(Zero Downtime), 데이터 손실 원천 차단(Zero Data Loss), 양 센터 자원 동시 활용을 통한 인프라 효율 극대화.

## Ⅱ. 액티브-액티브 스토리지 DR의 특징

- 핵심 요약 : 양방향 동기 복제, 쿼럼 기반 분할 뇌 방지, GSLB 부하 분산, 거리 제약 관리를 특징으로 하는 고가용 체계.
1. 양 센터 동시 활성화 및 부하 분산 처리.
2. 동기식 스토리지 미러링을 통한 RPO=0 목표.
3. 제3 센터 쿼럼(Quorum) 기반 스플릿 브레인 방지.
4. GSLB(Global Server Load Balancing) 기반 트래픽 라우팅.
5. 거리 제약(RTT, Round-Trip Time)에 따른 지연 관리.

## Ⅲ. 액티브-액티브 스토리지 DR의 구조 (흐름)

- 핵심 요약 : 양 센터 동기 복제와 제3 센터 쿼럼으로 구성된 이중화 구조와 장애 시 페일오버 흐름.
- 센터 구성 및 복제 흐름.

```text
센터 A (Active) <── 동기 복제 ──> 센터 B (Active)
   ── 공통 구성: GSLB(Global Server Load Balancing)
   ── 웹/WAS(Web Application Server) 애플리케이션 클러스터
   ── 스토리지 가상화 노드 (Mirror)
        │
        ↓
   제3 센터 쿼럼(Quorum)
```

```text
[장애 시 페일오버 흐름]
센터 A 장애 감지
   ↓
쿼럼 투표 (센터 B 과반 확보)
   ↓
센터 A 쓰기 차단 (Split-Brain 방지)
   ↓
센터 B 단독 서비스 지속
   ↓
센터 A 복구 후 재동기화
```

- **동기식 복제**(Synchronous Mirroring) : 스토리지 쓰기 요청 발생 시 양 센터 스토리지에 모두 커밋이 완료되어야 호스트에 응답을 반환하여 RPO=0 달성.
- **제3 센터 쿼럼**(Quorum Witness) : 양 센터 간 네트워크 단절 시 양쪽 모두 활성화되어 데이터가 오염되는 분할 뇌(Split-Brain) 현상을 방지하기 위해 중립적 제3 사이트에서 투표권 행사.

## Ⅳ. 액티브-스탠바이와 액티브-액티브의 비교

- 핵심 요약 : 액티브-스탠바이는 비용·구축 용이성, 액티브-액티브는 동시 처리·무중단 목표에 각각 유리하다.
- 비교 대상 및 선택 기준.

```text
[DR 방식 선택 흐름]
RTO/RPO 요구 수준 확인
   ↓
Zero Downtime 필수? ── 예 ──→ 액티브-액티브
   ↓ 아니오
비용·거리 제약 ──→ 액티브-스탠바이 (Hot/Cold Site)
```

| 비교 항목 | 액티브-스탠바이 (Active-Standby) | 액티브-액티브 (Active-Active) |
|---|---|---|
| 서비스 처리 방식 | 주 센터 단독 처리, 대기 센터는 유휴 상태 | 양 센터가 동시에 부하 분산 처리 |
| **RTO** (복구 시간) | 수십 분 ~ 수 시간 (장애 감지, DNS(Domain Name System) 전환, 기동) | 장애 탐지·라우팅·세션 복구 조건에 따라 결정 |
| **RPO** (복구 시점) | 수 분 ~ 수 시간 (비동기 복제 시 손실 발생) | 정상 동기 커밋한 쓰기는 무손실을 목표로 하되 장애 범위 확인 |
| 복잡도 및 구축비용 | 중간 수준 | 매우 높음 (스토리지 가상화, 전용 광선로, GSLB) |
| 거리 제약 | 비동기 복제 적용 시 거리 제약 없음 | 네트워크 지연(RTT, Round-Trip Time)으로 인해 통상 50~100km 이내 제약 |

- 액티브-액티브 구성만으로 RTO/RPO가 자동으로 0이 되는 것은 아님. 장애 탐지, 쿼럼, 복제 방식 및 세션 전환을 함께 검증. [AWS 다중 사이트 재해복구 안내](https://aws.amazon.com/blogs/architecture/disaster-recovery-dr-architecture-on-aws-part-iv-multi-site-active-active/).

## Ⅴ. 액티브-액티브 스토리지 DR의 장점과 한계

- 핵심 요약 : 무중단·무손실 목표와 자원 효율의 장점, 스플릿 브레인·지연·비용의 한계.
- 장점
  1. 양 센터 동시 처리로 자원 활용 효율 극대화.
  2. 동기 복제 기반 데이터 손실 최소화 목표.
  3. 장애 시 서비스 전환 시간 단축 가능성.
- 한계점 1 : 스플릿 브레인(Split-Brain) 및 데이터 불일치 위험
  - 한계점 : 양 센터 간 복제 링크 단절 시 두 스토리지 노드가 독립적으로 쓰기 작업을 허용하여 데이터 비동기화 및 덮어쓰기 발생.
  - 해결 방안 : 제3의 독립 사이트에 쿼럼(Quorum)/증인(Witness) 서버 배치, 다수결 기반 자동 락(Lock) 및 페일오버 결정.
- 한계점 2 : 네트워크 지연(Latency)에 따른 트랜잭션 성능 저하
  - 한계점 : 스토리지 블록 단위의 양방향 동기식 미러링으로 인해 센터 간 거리(RTT, Round-Trip Time)에 정비례하여 I/O 대기시간 급증.
  - 해결 방안 : 센터 간 전용 고속 DWDM(Dense Wavelength Division Multiplexing) 광선로 구축, 지연시간 최소화(RTT 최소화) 보장, 스토리지 캐시 최적화.
- 한계점 3 : 인프라 이중 구축 및 라이선스에 따른 막대한 비용
  - 한계점 : 동일한 고사양 하드웨어 및 솔루션 라이선스를 양 센터에 중복 구매해야 하므로 예산 부담 극심.
  - 해결 방안 : 미션 크리티컬 핵심 DB(Database) 스토리지에만 한정 적용, 일반 업무는 비동기 복제 및 클라우드 DR(Disaster Recovery) 혼용 하이브리드 구성.

## Ⅵ. 액티브-액티브 DR 구축을 위한 기술사적 제언

- 핵심 요약 : 레이턴시 관리, 3센터 쿼럼 필수화, 하이브리드 DR 모델 구축.
- 거리 제약에 따른 네트워크 레이턴시 관리 : 동기식 복제로 인한 트랜잭션 지연을 최소화하기 위해 DWDM 전용 광선로를 확보하고 왕복 지연시간(RTT)을 허용 범위 이내로 통제.
- 스플릿 브레인 방지를 위한 3센터 쿼럼 필수화 : 네트워크 분절 발생 시 양 센터가 독립적으로 쓰기를 수행하여 발생하는 데이터 불일치를 원천 차단하기 위해 반드시 제3의 독립 사이트에 쿼럼 노드 배치.
- 3센터 하이브리드 DR 모델 구축 : 근거리 센터 A-B는 액티브-액티브(동기식)로 구축하여 낮은 RTO/RPO를 목표로 검증하고, 원거리(수백 km 이상) 센터 C를 비동기식으로 연계하여 광역 재해에 대비하되 비동기 복제 지연과 복구 시간을 별도로 평가.

## Ⅶ. 결론

- 핵심 요약 : 액티브-액티브 스토리지 DR은 양 센터 동시 처리와 동기 복제로 고가용성을 추구하는 체계.
- 요약 : 액티브-액티브 스토리지 DR은 동기 복제·쿼럼·GSLB를 통해 무중단 서비스와 데이터 무손실을 목표로 하는 체계.
- 시사점 : 장애 탐지·쿼럼·복제 방식을 함께 검증하고, 거리·비용 제약에 따라 하이브리드 DR 모델로 적용 범위를 조정 필요.
