## Ⅰ. 액티브-액티브 이중화와 스토리지 DR의 개요

- 핵심 요약 : 액티브-액티브 이중화는 둘 이상의 센터가 동시에 서비스를 처리하고 데이터를 복제하며, 스토리지 DR(Disaster Recovery)은 장애 시 데이터를 대체 환경에서 복구하는 구성.
- 개념 : 액티브-액티브 이중화는 둘 이상의 센터가 동시에 서비스를 처리하고 데이터를 복제하며, 스토리지 DR(Disaster Recovery)은 장애 시 데이터를 대체 환경에서 복구하는 구성.
- 배경 및 필요성 : 짧은 복구시간이 필요한 서비스라도 동기·비동기 복제, 네트워크 분리, 운영 절차에 따라 실제 복구 성과가 달라짐.
- 주요 목적 : 업무별 RTO·RPO를 충족하고 사이트 장애 시 서비스·데이터 정합성 확보.

## Ⅱ. 액티브-액티브 이중화와 스토리지 DR의 특징 및 장점

- 핵심 요약 : 동시 처리, 데이터 복제, 장애 감지·펜싱, 트래픽 전환, 복구 후 재동기화.

1. 동시 처리, 데이터 복제, 장애 감지·펜싱, 트래픽 전환, 복구 후 재동기화 → 업무별 RTO·RPO를 충족하고 사이트 장애 시 서비스·데이터 정합성 확보.
2. 액티브-액티브는 가용성을 높이는 아키텍처이며, 정합성·운영 통제가 복구목표 달성의 전제.
3. 업무·IT 책임자는 업무별 RTO·RPO와 데이터 손실 허용을 정하고, 운영팀은 센터 단절·복귀를 포함한 전환훈련을 반복.

## Ⅲ. 액티브-액티브 이중화와 스토리지 DR의 구조 (흐름)

- 핵심 요약 : 업무 목표 설정 → 센터·복제 방식 설계 → 정상 동시 운영 → 장애 판정·격리 → 서비스 전환 → 데이터 검증·복귀.

```text
업무 목표 설정
  ↓
센터·복제 방식 설계
  ↓
정상 동시 운영
  ↓
장애 판정·격리
  ↓
서비스 전환
  ↓
데이터 검증·복귀
```

- 핵심 구조 : 동시 처리, 데이터 복제, 장애 감지·펜싱, 트래픽 전환, 복구 후 재동기화.

```text
센터 A 처리·복제 ↔ 센터 B 처리·복제
  ↓
단절 감지 → 펜싱 → 트래픽 전환 → 데이터 검증
```

## Ⅴ. 액티브-액티브 이중화와 스토리지 DR의 한계와 방안

- 핵심 요약 : 주요 한계는 분할뇌·데이터 불일치·전환 실패이며, 원인별 대응과 관리지표의 연계가 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |

| 분할뇌 | 센터 간 통신 단절로 양쪽이 쓰기 허용 | 쿼럼·펜싱·단일 쓰기 권한 설계 | 중복 쓰기 사고 |
| 데이터 불일치 | 비동기 복제 지연·충돌 | 업무별 복제모드·정합성 규칙·재조정 절차 | 복제지연·불일치율 |
