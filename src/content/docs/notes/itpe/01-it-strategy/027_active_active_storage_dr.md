## 지식 로드맵 내 현재 위치

지식 위치: IT 전략·관리 → 재해복구·서비스 연속성 → **액티브-액티브 이중화와 스토리지 DR**

## 30초 인출

- 본질: 액티브-액티브 이중화는 둘 이상의 거점이 평상시 함께 서비스를 처리하는 가용성 구조. 데이터 복제와 장애 절체 방식의 별도 설계.
- 메커니즘: 정상 거점 간 트래픽 분산과 스토리지 복제, 장애 시 단일 쓰기 주체·복구 가능성 확인 후 트래픽 전환.
- 핵심: 업무별 **RPO**·지연 조건에 맞춘 동기·비동기 복제 선택, 실제 절체 시험을 통한 데이터 정합성·잔여 용량·복구시간 확인.

<details>
<summary>핵심 용어</summary>

- **액티브-액티브 스토리지 DR**: 둘 이상의 거점이 서비스를 함께 처리하고, 원격 데이터 복제와 장애 절체를 통해 업무 연속성을 지원하는 구성
- **액티브-액티브(Active-Active)**: 둘 이상의 거점이 평상시 동시에 서비스 요청을 처리하는 구성
- **스토리지 DR(Disaster Recovery)**: 재해 때 데이터를 복구하고 서비스를 재개하도록 원격 복제·복구 절차를 마련하는 것
- **GSLB(Global Server Load Balancing)**: 복수 거점의 상태와 정책을 바탕으로 사용자 요청을 분산하거나 다른 거점으로 유도하는 기능
- **동기 복제(Synchronous Replication)**: 원격 저장 반영을 확인한 후 쓰기 완료를 응답하는 복제 방식
- **비동기 복제(Asynchronous Replication)**: 로컬 쓰기 완료를 먼저 응답하고 원격 반영을 뒤이어 수행하는 복제 방식
- **RPO(Recovery Point Objective)**: 장애 시 허용할 수 있는 데이터 복구 시점의 목표
- **스플릿 브레인(Split-Brain)**: 통신 단절 뒤 복수 거점이 동시에 쓰기 주체로 동작해 데이터 정합성을 해칠 수 있는 상태
- **쿼럼 중재(Quorum Witness)**: 구성된 다수결·중재 정책으로 클러스터의 정상 동작 주체를 결정하는 기능

</details>

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **액티브-액티브 스토리지 DR**은 둘 이상의 거점이 서비스를 함께 처리하고 원격 데이터 복제·장애 절체로 업무 연속성을 지원하는 구성 |
| 목적 | 업무별 목표에 맞춘 장애 시 서비스 중단·데이터 손실 감소 |

### Ⅱ. 거점·트래픽·복제 관계

```text
사용자 요청
    ↓
GSLB
    ├→ 거점 A 서비스·스토리지
    └→ 거점 B 서비스·스토리지

거점 A ⇄ 거점 B: 설정된 데이터 복제
쿼럼 중재 ── 두 거점의 상태 판정
```

**복제와 절체 통제**

- **동기 복제**: 원격 저장 반영 확인 후 쓰기 완료 응답. 완료 응답된 쓰기의 원격 보장을 목표로 하며 실제 보장은 스토리지 구성·장애 처리에 좌우.
- **비동기 복제**: 로컬 응답 우선에 따른 장애 시 마지막 원격 반영 이후 데이터의 유실 가능성.
- **스플릿 브레인** 방지: 중재·펜싱 정책에 따른 단일 쓰기 주체 제한과 승격 후 데이터 정합성 확인.

제언: 업무별 RPO·복구시간·쓰기 지연 요구의 설정과 해당 조건에서의 절체 시험.

## 2~4교시 25점 답안

## Ⅰ. 액티브-액티브 스토리지 DR의 개요

| 구분 | 핵심 |
|---|---|

| 목적 | 업무별 목표에 맞춘 장애 시 서비스 중단·데이터 손실 감소 |

## Ⅱ. 거점·트래픽·복제 관계

```text
사용자 요청
    ↓
GSLB
```

그림의 참조 관계와 애플리케이션·스토리지 제품 구성·업무 정합성 요건에 따른 실제 동시 요청 범위·복제 방향·중재 방식 결정.

## Ⅲ. 동기·비동기 복제 비교

동기 복제의 원격 저장 확인 후 호스트 완료 응답, 비동기 복제의 로컬 저장 우선 응답 후 원격 반영.

```text
동기 복제
  호스트 → 로컬 → 원격 저장
  원격 완료 → 로컬 → 호스트 응답

비동기 복제
  호스트 → 로컬 저장 → 호스트 응답
  로컬 → 원격에 후속 반영
```

| 기준 | 동기 복제 | 비동기 복제 |
|---|---|---|
| 완료 응답 | 원격 반영 확인 후 응답 | 로컬 반영 후 먼저 응답 |
| 장애 시 데이터 | 완료 응답된 쓰기의 원격 반영을 목표로 하나, 장애·제품별 보장 조건 확인 필요 | 마지막 원격 반영 이후 쓰기의 손실 가능성 있음 |
| 지연 영향 | 원격 응답 지연이 쓰기 응답시간에 반영될 수 있음 | 로컬 우선 응답으로 쓰기 지연을 줄일 수 있음 |
| 적합 조건 | 업무가 요구하는 데이터 손실 목표와 회선 지연을 함께 충족할 때 | 허용 가능한 복제 지연·데이터 손실 목표를 충족할 때 |

## Ⅳ. 서비스 절체와 데이터 복구의 구분

| 구분 | 서비스 절체 | 데이터 복구 |
|---|---|---|
| 목적 | 사용자의 요청을 정상 거점으로 전달 | 장애 전후 데이터의 정합 상태를 확인하고 필요한 시점으로 복구 |
| 주요 수단 | GSLB 정책, 애플리케이션 가용성·상태 확인 | 복제 상태, 일관성 검사, 백업·복구 절차 |
| 확인 결과 | 서비스 접근 가능 여부 | 데이터 손실 범위와 업무 적용 가능 여부 |

트래픽 변경만으로 데이터 안전성을 보장할 수 없으므로 서비스 상태·저장 데이터 상태의 개별 검증.

## Ⅴ. 주요 실패 위험과 통제

| 위험 | 통제 | 검증 항목 |
|---|---|---|
| 거점 간 통신 단절에 따른 복수 쓰기 주체 발생 | 쿼럼 정책·**I/O 펜싱**에 따른 쓰기 권한 제한과 격리 상태 확인 | 단일 쓰기 주체·펜싱 동작 |
| 비동기 복제 지연 중 장애 | 업무별 **RPO** 기준의 복제 지연 감시와 초과 시 복구 의사결정 | 복제 지연·손실 범위 |
| 잔존 거점의 장애 거점 부하 미수용 | 거점 상실 시나리오별 용량·부하 우선순위 검증 | CPU·저장·네트워크 여유 |
| 논리 오류·랜섬웨어의 복제본 전파 | 운영 복제와 분리된 백업 보존·복원 시험 | 백업 격리·복원 가능성 |
