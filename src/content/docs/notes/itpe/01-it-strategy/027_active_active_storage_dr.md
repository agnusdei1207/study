## 해당 토픽 큰 그림과 30초 인출

```text
        [GSLB·Traffic Manager]
          ┌──────┴──────┐
       [Region A]    [Region B]

          Witness·Backup·DR Test
```

- 인출어: `동시서비스`, `장애격리`, `복제=Sync/Async`, `Split-Brain=Quorum`, `목표=검증된 RTO/RPO`

## 예상문제

> 다중지역 액티브-액티브와 스토리지 DR의 구성·데이터 동기화 방식을 설명하고, 스플릿 브레인·지연·정합성·운영복잡도 대응방안을 제시하시오. (25점)

## Ⅰ. 다중지역 동시가동 기반 DR 개요

**액티브-액티브 DR**은 둘 이상의 장애영역이 평상시에도 서비스를 처리하다 한쪽 장애 시 잔여 영역이 서비스를 계속 제공하는 구조다. 스토리지 DR은 데이터를 다른 장애영역에 복제·보호하는 수단이며, 이것만으로 애플리케이션·인증·연계까지 자동 복구되는 것은 아니다.

## Ⅱ. 설계원칙과 선결조건

| 원칙 | 설명 |
|---|---|
| 장애영역 독립 | 전력·망·관리·배포·사람의 공통실패 최소화 |
| 업무기반 목표 | 업무별 RTO·RPO·용량·일관성 요구로 방식 선택 |
| 상태 분리 | 세션·파일·DB 상태와 외부연계의 지역 의존성 제거 |
| 일관성 명시 | 강한 일관성·최종 일관성·충돌규칙을 업무별 합의 |
| 운영 검증 | 자동절체뿐 아니라 복귀·데이터 검증·업무 확인 수행 |

## Ⅲ. 계층별 참조구조

```text
[사용자·기관연계]
       │
[DNS/GSLB·Health Check]
  ┌────┴─────────────┐
  ▼                  ▼
[지역 A]           [지역 B]
App/API            App/API
Cache/Queue        Cache/Queue
DB/Storage ─────── DB/Storage
  │   동기·비동기·로그복제  │
  └──── [Witness/Quorum] ───┘
           │
   [격리백업·제3 복구영역]
```

## Ⅳ. 데이터 동기화와 절체흐름

```text
정상 분산처리 → 장애 탐지 → 쓰기권한 판정 → 트래픽 격리·전환
      → 데이터 정합성 확인 → 용량 확장 → 원인복구 → 재동기화·복귀
```

| 동기화 | 동작 | 장점 | 유의점 |
|---|---|---|---|
| 동기 복제 | 원격 반영 확인 후 커밋 | 데이터 손실 최소화 | 거리·회선 지연이 거래에 영향 |
| 비동기 복제 | 로컬 커밋 후 전송 | 성능·원거리 유리 | 전송 지연만큼 손실 가능 |
| 로그·CDC | 변경로그를 순서대로 전달 | 이기종·선택 복제 | 순서·중복·재처리 설계 |
| 애플리케이션 이중쓰기 | 앱이 복수 저장소 기록 | 업무별 제어 가능 | 부분실패·충돌·멱등성 복잡 |

## Ⅴ. Active-Active와 Active-Standby 비교

| 비교축 | Active-Active | Active-Standby |
|---|---|---|
| 평시 | 복수 지역 서비스 처리 | 주 지역 처리, 대기 지역 준비 |
| 자원활용 | 높음 | 대기자원 활용 제한 가능 |
| 전환 | 트래픽 재분배 중심 | 대기계 기동·승격 필요 |
| 데이터 | 다중쓰기·일관성 복잡 | 단일쓰기 구조가 비교적 단순 |
| 운영난도 | 높음 | 상대적으로 낮음 |
| 적합성 | 짧은 RTO, 변동부하, 지역분산 | 비용·복잡도 제약, 명확한 복구절차 |

## Ⅵ. 주요 실패모드와 통제

| 실패모드 | 원인 | 통제·검증 |
|---|---|---|
| 스플릿 브레인 | 지역 간 통신단절 후 양쪽 쓰기 | Quorum·Witness, Fencing, 단일 쓰기권한 |
| 복제지연·데이터 손실 | 회선·부하·비동기 적체 | 지연 모니터링, RPO 경보, 격리백업 |
| 연쇄장애 | 오류 데이터·배포가 동시 확산 | 점진배포, 논리오류 복원점, 변경격리 |
| 잔여용량 부족 | 장애 후 한 지역이 전체부하 수용 불가 | N-1 용량시험·우선순위·부하차단 |
| 자동절체 오판 | 불완전한 헬스체크 | 다계층 신호·지연·수동개입 기준 |
| 복귀 실패 | 재동기화·충돌절차 부재 | Failback 런북과 정합성 검증 |

## Ⅶ. 기술명이 아니라 검증된 서비스 복구가 기준인 결론

Active-Active가 모든 시스템의 정답은 아니다. BIA가 요구한 RTO·RPO와 데이터 일관성, 비용·운영역량을 기준으로 동기·비동기 및 Active-Standby를 조합하고 **센터상실·통신분할·논리오류·복귀**까지 시험해야 한다.

## 1교시 10점 답안 발췌

```text
정의: 복수 장애영역이 평시 동시 서비스하고 장애 시 잔여영역이 계속 처리
구조: GSLB → 지역 A/B 앱·데이터 → 복제·Quorum → 격리백업
복제: Sync=손실 최소·지연 부담 / Async=원거리·성능 유리·RPO 발생
위험: Split-Brain, 복제지연, 연쇄오류, 잔여용량, 절체오판, 복귀실패
검증: N-1 부하, 실제 RTO/RPO, 정합성, Failover·Failback 훈련
```
