## 지식 로드맵 내 현재 위치

IT 전략·관리 → IT 조직·역량 운영 → **전문성의 민주화**

## 30초 인출

- 본질: 전문성의 민주화는 오랜 훈련 없이도 현업 담당자가 데이터 분석·앱 개발·설계·전문 지식을 쓸 수 있도록 도구 접근을 넓히는 기술 추세
- 메커니즘: 로우코드·노코드·AI 보조 도구가 전문 작업의 장벽을 낮추고, 현업이 직접 해결책을 만들며, CoE·IT 조직이 표준·데이터·보안 기준으로 지원·통제
- 통찰: 검증되지 않은 앱이 핵심 업무로 퍼지므로 영향 범위에 따라 운영 책임을 넘기는 승격 기준 설정

<details>
<summary>핵심 용어</summary>

- **전문성의 민주화(Democratization of Expertise)** : 기술·업무 전문성을 오랜 훈련이나 큰 비용 없이 쓸 수 있도록 도구 접근을 넓히는 추세. Gartner 2020 전략 기술 동향의 하나
- **시민 개발자(Citizen Developer)** : 전문 개발자가 아니면서 조직이 승인한 도구로 업무용 앱·자동화를 만드는 현업 담당자
- **LCNC(Low-Code/No-Code)** : 적은 코드 또는 코드 없이 화면 구성·설정으로 앱과 자동화를 만드는 개발 방식
- **CoE(Center of Excellence)** : 현업의 도구 활용을 위해 표준·교육·지원·통제 기준을 제공하는 전담 조직
- **Shadow IT** : IT 조직의 승인·관리 밖에서 현업이 도입하거나 만든 시스템
- **가드레일(Guardrail)** : 허용 도구·데이터·커넥터처럼 현업의 자율 제작 범위를 미리 정한 경계

</details>

## 2~4교시 25점 답안

## Ⅰ. 전문성의 민주화의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **전문성의 민주화(Democratization of Expertise)** 는 기술·업무 전문성을 오랜 훈련 없이 쓸 수 있도록 현업의 도구 접근을 넓히는 기술 추세 |
| 목적 | 현업의 문제 해결 속도 향상과 전문 인력의 반복 요청 처리 부담 감소 |

## Ⅱ. 전문 인력 중심 수행과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 접근 장벽 완화 | 코딩·통계·설계 훈련 없이 도구로 전문 작업 일부 수행 |
| 도구 기반 | LCNC·셀프서비스 BI·AI 보조 도구가 전문 지식을 대신 수행 |
| 현업 주도 | 업무를 가장 잘 아는 담당자가 직접 해결책 제작 |
| 통제 필요 | 제작 주체 분산에 따른 품질·보안·운영 책임의 기준 필요 |

## Ⅲ. 민주화 적용 영역과 시민 개발 앱의 운영 흐름

### 전문성의 민주화 적용 영역

```text
전문성의 민주화
    │
    ├─ 데이터·분석 ── 셀프서비스 BI·시민 데이터 과학자
    │
    ├─ 개발 ── AI 보조 코드 생성, 개발자 생산성
    │
    ├─ 설계 ── LCNC로 현업이 앱·자동화 제작
    │
    └─ 지식 ── 전문가 시스템의 비전문가 판단 보조
```

Gartner(2020)가 제시한 네 영역 구분이며, 조직 도입에서 파급이 가장 큰 영역은 현업이 직접 운영 시스템을 만드는 설계 영역

### 설계 영역 확대: 시민 개발 앱의 운영 흐름

```text
현업의 업무 문제 정의
    ↓
승인된 LCNC 도구·데이터로 앱 제작
    ↓
앱 목록 등록과 소유자 지정
    ↓
이용 범위·데이터 민감도 확인
    ├─ 개인·팀 업무 → 현업 운영 유지
    └─ 전사·대외·민감 데이터 → 전문 조직 검토
```

## Ⅳ. 시민 개발 운영 모델의 비교

| 구분 | 전면 개방 | 중앙 통제 | CoE 기반 가드레일 |
|---|---|---|---|
| 제작 권한 | 누구나 제한 없이 | IT 조직 승인 건만 | 허용 범위 안에서 자율 |
| 속도 | 가장 빠름 | 가장 느림 | 범위 안에서 빠름 |
| 위험 | Shadow IT·데이터 유출 | 현업 요구 적체·우회 도입 | 기준 설계·운영 부담 |
| 적합한 상황 | 민감 데이터가 없는 실험 단계 | 규제·보안 요구가 매우 높은 업무 | 대부분 조직의 확산 단계 |

전면 개방과 중앙 통제의 중간에서 허용 범위를 미리 정하고 그 밖의 건만 검토하는 방식이 CoE 기반 가드레일

## Ⅴ. 전문성의 민주화 도입의 한계와 방안

| 한계 | 방안 |
|---|---|
| 승인되지 않은 앱·외부 연동의 **Shadow IT** 확산 | 실험 단계 이후 CoE 기반 가드레일 선택과 허용 커넥터 관리 |
| 검증되지 않은 분석 결과의 의사결정 사용 | 데이터 출처·산식의 명시와 공유 전 검증 책임자 지정 |
| 제작자 이탈 뒤 유지 불가 | 앱 목록 등록 시 소유자·대리 소유자·문서 필수화 |
| 개인용 앱의 전사 확산에 따른 운영 공백 | 이용 범위·데이터 민감도에 따른 전문 조직 운영 이관 |

## Ⅵ. 제언

현업 제작 앱을 이용 범위와 데이터 민감도로 판정해, 기준을 넘으면 운영 책임을 전문 조직으로 옮기는 승격 기준 설정

### 영향 범위별 운영 책임 구조

```text
시민 개발 앱의 운영 책임
    │
    ├─ 현업 소유자 ── 개인·팀 범위 앱의 운영
    │
    ├─ CoE ── 가드레일·앱 목록·승격 판정
    │
    └─ IT·보안 조직 ── 승격된 앱의 운영·보안·복구
```

### CoE 확대: 승격 판정 절차

```text
앱 목록의 이용자 수·데이터 민감도 점검
    ↓
승격 기준 초과 여부
    ├─ 미초과 → 현업 운영 유지, 정기 재점검
    └─ 초과 → 보안·성능·복구 검토
          ↓
       IT·보안 조직으로 운영 이관
```

### 선택 근거: 제작 승인 중심 통제와의 비교

| 구분 | 제작 승인 중심 통제 | 제언: 영향 범위 기반 승격 |
|---|---|---|
| 통제 시점 | 제작 전 일괄 승인 | 제작은 가드레일 안에서 자율, 확산 시 판정 |
| 판단 기준 | 요청 부서·도구 종류 | 이용 범위·데이터 민감도 |
| 현업 속도 | 승인 대기로 저하 | 개인·팀 범위는 즉시 |
| 운영 책임 | 불명확 | 승격 시 전문 조직으로 이관 |
