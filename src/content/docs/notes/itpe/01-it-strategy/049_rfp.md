## 연관 키워드

- RFP, Request for Proposal, 제안요청서, 제안평가, 협상계약, 공공 SW, 평가기준, 과업지시서

## Ⅰ. RFP의 개요

- 핵심 요약 : RFP(Request for Proposal)는 사업 요구와 평가 기준을 명시해 공급자 제안을 요청하는 문서.
- 개념 : RFP(Request for Proposal)는 발주자가 사업 목적·요구사항·제약·평가 기준을 명시해 공급자의 제안서를 요청하는 문서.
- 배경 및 필요성 : 요구사항이 불명확하면 제안 비교와 계약 협상이 어려워 사업 실패 위험이 커짐.
- 주요 목적 : 공정한 경쟁과 명확한 계약 기반으로 적합한 공급자를 선정.

## Ⅱ. RFP의 특징 및 장점

- 핵심 요약 : 요구사항 명시, 평가 기준 투명성, 제안 비교, 협상 기반, 리스크 감소가 조달 품질을 높임.

1. 요구사항 명시 : 목적·범위·기능·비기능 요구를 문서화 → 공급자 이해 일치.
2. 평가 기준 투명성 : 정량·정성 평가 항목과 가중치 공개 → 공정 경쟁과 이의 최소화.
3. 제안 비교 : 동일 기준으로 제안서를 비교 → 최적 공급자 선정.
4. 협상 계약 기반 : 제안서와 협상을 통해 계약 조건 확정 → 리스크 배분 명확화.
5. 변경 관리 기반 : 요구사항 추적 매트릭스로 변경 영향 관리 → 범위 creep 방지.

## Ⅲ. RFP의 구조 (흐름)

- 핵심 요약 : 사업 배경 → 요구사항 → 제안 조건 → 평가 기준 → 계약·관리로 이어지는 문서·절차 구조.

```text
사업 배경·목적
   ↓
요구사항 정의
   ↓
제안 조건·일정
   ↓
평가 기준·방법
   ↓
계약·변경 관리
```

```text
RFP 발행 → 제안서 접수 → 평가·협상 → 계약 체결 → 사업 수행
```

- 핵심 구성 : 사업 개요, 요구사항, 제안 조건, 평가 기준, 계약·관리.

## Ⅳ. RFP와 RFQ의 비교

- 핵심 요약 : RFP는 제안·해결책 요청, RFQ는 가격·규격 견적 요청으로 목적과 평가가 다름.

| 비교 축 | RFP | RFQ |
| --- | --- | --- |
| 목적 | 해결책·제안 요청 | 가격·규격 견적 요청 |
| 평가 | 기술·가격·수행 능력 종합 | 가격·납기 중심 |
| 복잡도 | 높음 | 낮음 |
| 사용 시점 | 복잡·불확실 사업 | 표준·반복 조달 |

## Ⅴ. RFP의 한계와 방안

- 핵심 요약 : 과도한 요구, 평가 주관성, 변경 비용이 주요 한계이며 원인별 대응과 관리지표 연계가 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 과도한 요구 | 모든 기능을 요구 → 비용·일정 증가 | MoSCoW 우선순위 적용 | 요구사항 수 |
| 평가 주관성 | 정성 평가 편향 | 루브릭·복수 평가자 | 평가 일관성 |
| 변경 비용 | 계약 후 변경 비용 과다 | 변경 관리 절차·예비비 | 변경 요청 건수 |
| 공급자 종속 | 특정 기술에 종속 | 표준·오픈 인터페이스 요구 | 종속성 점수 |

## Ⅵ. RFP에 대한 기술사적 제언

- 핵심 요약 : 발주자는 RFP를 사업 가치와 요구사항 추적으로 설계하고, 평가·협상·변경 관리를 일관되게 운영.

- 거버넌스 : 평가위원회와 이해충돌 관리 절차를 명확히 함.
- 품질 : 요구사항 추적 매트릭스와 수용 기준을 RFP에 포함.
- 계약 : SLA·패널티·변경 절차를 계약에 명시.

## Ⅶ. 결론

- 핵심 요약 : RFP는 사업 요구와 평가 기준을 명시해 적합한 공급자를 선정하는 조달 문서임.
- 시사점 : 요구사항·평가·변경을 일관되게 관리해야 RFP가 사업 성공의 기반이 됨.
