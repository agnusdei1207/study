## 지식 로드맵 내 현재 위치

IT 전략·관리 → 공공 정보화·조달관리 → **제안요청서(RFP)**

## 30초 인출

- 본질: RFP(Request for Proposal)는 발주자가 사업 목적·범위·요구사항·평가 기준·계약 조건을 제시해 공급자의 제안을 받는 제안요청서
- 메커니즘: 요구사항마다 식별 ID와 인수 기준을 붙여 RFP에 명시하고, 같은 ID로 제안 평가·계약·검수를 판단
- 통찰: 요구사항과 평가·인수 기준이 따로 놀면 평가와 검수가 어긋나므로 요구사항 ID 기준의 평가·인수 기준 연결

<details>
<summary>핵심 용어</summary>

- **RFP(Request for Proposal)** : 발주자가 사업 목적·요구사항·평가 기준·계약 조건을 정해 공급자에게 해결 방안과 가격의 제안을 요청하는 문서
- **RFI(Request for Information)** : 사업 기획 단계에서 시장의 기술 대안·공급 역량 정보를 수집하는 정보 요청서
- **RFQ(Request for Quotation)** : 규격·수량이 확정된 품목이나 서비스의 가격·납기 견적을 요청하는 견적 요청서
- **인수 기준(Acceptance Criteria)** : 인도물이 요구사항을 충족했는지 판정하는 측정 조건과 판정값
- **요구사항 ID** : 요구사항 하나를 평가·계약·시험·검수 문서에서 같은 대상으로 식별하는 고유 번호. 분류 코드와 일련번호의 조합(예: SFR-001)

</details>

## 2~4교시 25점 답안

## Ⅰ. 제안요청서(RFP)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **RFP(Request for Proposal)** 는 발주자가 사업 목적·범위·요구사항·평가 기준·계약 조건을 제시해 공급자의 해결 방안과 가격 제안을 요청하는 문서 |
| 목적 | 같은 조건에서의 제안 비교와 계약·검수 판단 기준의 사전 확정 |

## Ⅱ. 조달 문서로서 RFP의 특징

| 특징 | 의미 |
|---|---|
| 공급자 공통 조건 | 범위·평가 기준·제출 형식의 모든 제안자 동일 공개 |
| 검증 가능한 요구사항 | 요구사항별 식별 ID와 측정 가능한 판정 조건 |
| 계약의 기준 문서 | 협상·과업 변경·검수 때 참조하는 발주자 요구의 원본 |

## Ⅲ. RFP의 구성과 요구사항 작성 절차

### RFP 구성 체계

```text
제안요청서(RFP)
    │
    ├─ 사업 개요 ── 배경·목적·범위·기간·예산
    │
    ├─ 요구사항 ── 유형별 요구사항과 인수 기준
    │
    ├─ 제안 안내 ── 참가 자격·일정·제안서 형식
    │
    ├─ 평가 기준 ── 평가항목·배점·증빙
    │
    └─ 계약 조건 ── 산출물·검수·변경·보안·하자
```

### 요구사항 확대: 요구사항 작성 절차

```text
업무·기술 요구 도출
    ↓
유형 분류와 요구사항 ID 부여
(11개 분류 코드: SFR-001 형식)
    ↓
요구사항별 인수 기준 작성
    ↓
업무·기술·조달 담당자의 공동 검토
    ├─ 측정 불가·특정 제품 지정 → 문구 보완
    └─ 검토 완료 → RFP 확정·공고
```

| 분류 | 코드 | 분류 | 코드 |
|---|---|---|---|
| 시스템 장비 구성 | ECR | 테스트 | TER |
| 기능 | SFR | 보안 | SER |
| 성능 | PER | 품질 | QUR |
| 인터페이스 | SIR | 제약사항 | COR |
| 데이터 | DAR | 프로젝트 관리 | PMR |
| 프로젝트 지원 | PSR | | |

## Ⅳ. RFI·RFP·RFQ의 선택 기준

| 구분 | RFI | RFP | RFQ |
|---|---|---|---|
| 적용 조건 | 문제·시장 대안 탐색 단계 | 요구사항·평가 기준 정의 완료 | 규격·수량 확정 |
| 요청 내용 | 기술 대안·공급 역량 정보 | 해결 방안·수행 계획·가격 | 가격·납기 견적 |
| 선정 근거 | 선정 없이 RFP 작성에 반영 | 기술·가격 종합 평가 | 가격·조건 비교 |
| 대표 활용 | 신기술 도입 사업의 기획 | 정보시스템 구축·운영 사업 | 표준 장비·소프트웨어 구매 |

## Ⅴ. RFP 작성의 한계와 방안

| 한계 | 방안 |
|---|---|
| 시장 대안을 모른 채 규격을 정해 경쟁 제한 | RFI 선행 선택: 기술 대안·공급 역량 수집 후 RFP 작성 |
| 규격이 확정된 표준품까지 제안 평가로 조달 | RFQ 선택: 견적·납기 비교 조달 |
| "적정한", "신속한"처럼 측정할 수 없는 요구 문구 | 측정 조건·판정값을 담은 **인수 기준(Acceptance Criteria)** 작성 |
| 불필요한 특정 제품·기술 지정 | 기능·성능 기준 기술과 동등 제품 허용 |
| 평가항목과 요구사항의 별도 작성 | **요구사항 ID** 별 평가항목·증빙 매핑 |

## Ⅵ. 제언

요구사항 ID를 기준으로 평가항목과 인수 기준을 함께 작성해 제안 평가와 검수가 같은 요구사항을 판단하도록 설정

### 요구사항 ID 기준의 연결 구조

```text
요구사항 ID
    │
    ├─ 평가항목 ── 제안서의 충족 방안·증빙
    │
    ├─ 계약 과업 ── 협상 결과의 과업 내용
    │
    └─ 인수 기준 ── 시험·검수의 판정값
```

### 인수 기준 확대: 작성 판정 절차

```text
요구사항 문장 검토
    ↓
측정 조건·판정값 존재 여부 확인
    ├─ 없음 → 측정 환경·방법·판정값 보완
    └─ 있음 → 같은 ID로 평가항목·검수 시험 등록
```

### 선택 근거: 문서별 작성과의 비교

| 구분 | 문서별 작성 | 제언: 요구사항 ID 기준 작성 |
|---|---|---|
| 평가 기준 | 일반 역량·방법론 중심 항목 | 요구사항별 충족 방안·증빙 |
| 검수 기준 | 이행 단계에서 별도 협의 | 공고 시점의 인수 기준 |
| 분쟁 시 판단 근거 | 문서마다 다른 표현 | 같은 ID의 요구·평가·검수 기록 |

## 출제 이력과 검증 출처

- 제132~140회 공식 문제지에 RFP 직접 문항 없음
- 인접 문항: 제133회 3교시 5번 소프트웨어 요구공학(요구사항 명세서 포함)
- 소프트웨어 진흥법 제44조(소프트웨어사업의 과업 범위) — 법률 제20476호, 2025.4.23. 시행
- 소프트웨어사업 계약 및 관리감독에 관한 지침 — 과학기술정보통신부고시 제2023-15호, 2023.5.15. 시행
- NIPA, 소프트웨어사업 요구사항 분석·적용 가이드: 표 Ⅱ-9 상세 요구사항 11개 분류(ECR·SFR·PER·SIR·DAR·TER·SER·QUR·COR·PMR·PSR)
