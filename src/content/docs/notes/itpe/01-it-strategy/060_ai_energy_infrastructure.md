## 지식 로드맵 내 현재 위치

IT 전략·관리 → 디지털 인프라 정책 → **AI 에너지 인프라**

## 30초 인출

- 본질: AI 에너지 인프라는 AI 데이터센터의 고밀도 GPU 연산에 필요한 전력을 공급하고 그 발열을 제거하는 전원·배전·냉각·계측 설비와 운영 체계
- 메커니즘: 전력 계통·전력구매계약에서 받은 전력이 수배전·UPS를 거쳐 GPU 랙에 공급되고, 발생한 열을 공랭·수랭 냉각이 제거하며, 계측값으로 용량·효율을 관리
- 통찰: 전력과 냉각을 따로 검토하면 GPU를 가동하지 못하므로 부지 확정 전 전력·냉각·용수의 동시 판정

<details>
<summary>핵심 용어</summary>

- **AI 에너지 인프라** : AI 데이터센터의 전력 공급·배전·냉각·계측을 담당하는 설비와 이를 관리하는 운영 체계
- **PUE(Power Usage Effectiveness)** : 데이터센터 전체 투입 전력을 IT 장비 소비 전력으로 나눈 전력 효율 지표. 1에 가까울수록 효율적
- **WUE(Water Usage Effectiveness)** : 데이터센터 연간 물 사용량을 IT 장비 에너지 사용량으로 나눈 수자원 효율 지표
- **PPA(Power Purchase Agreement)** : 발전 사업자와 전력 수요자가 공급 기간·가격·조건을 약정하는 전력구매계약
- **UPS(Uninterruptible Power Supply)** : 정전·전압 변동 시 배터리로 전력을 이어 공급하는 무정전 전원장치
- **D2C(Direct-to-Chip) 냉각** : 칩 위에 냉각판을 붙여 냉각수로 열을 직접 빼내는 수랭 방식
- **액침 냉각(Immersion Cooling)** : 서버를 비전도성 유체에 담가 열을 제거하는 냉각 방식
- **BESS(Battery Energy Storage System)** : 전력을 저장했다가 피크·비상 시 방전하는 배터리 에너지 저장 시스템

## 2~4교시 25점 답안

## Ⅰ. AI 에너지 인프라의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **AI 에너지 인프라** 는 AI 데이터센터의 고밀도 연산 부하에 전력을 공급하고 발열을 제거하는 전원·배전·냉각·계측 설비와 운영 체계 |
| 목적 | AI 연산 용량의 안정적 가동과 전력·용수·탄소 부담의 관리 |

## Ⅱ. 기존 데이터센터와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 고밀도 랙 | GPU 랙당 전력·발열이 커서 기존 공랭 설계의 한계 초과 가능 |
| 급변하는 부하 | 학습 작업 시작·종료에 따른 전력 사용량의 큰 변동 |
| 전력·냉각 공동 제약 | 전력과 냉각 중 먼저 바닥나는 쪽이 증설 한계를 결정 |
| 입지 의존 | 계통 접속 가능 시점·용수·기후가 설계 선택을 좌우 |

## Ⅲ. 전력·냉각 구성 체계와 전력·열 흐름

### AI 에너지 인프라 구성 체계

```text
AI 에너지 인프라
    │
    ├─ 전원 ── 전력 계통·PPA·BESS
    │
    ├─ 배전 ── 변전·UPS·비상발전기
    │
    ├─ IT 부하 ── GPU 서버·네트워크·스토리지
    │
    ├─ 냉각 ── 공랭·D2C·액침
    │
    └─ 계측·관제 ── 전력·온도 계측과 PUE·WUE 관리
```

### 전력·열 흐름 확대: 공급에서 열 제거까지

```text
전력 계통·PPA
    ↓ 수전
변전·UPS 배전
    ↓ 전력 공급
GPU 랙 연산
    ↓ 발열
냉각 설비의 열 제거
    ↓ 계측값
용량·효율 판단과 증설 결정
```

## Ⅳ. 냉각 방식의 비교

| 구분 | 공랭 | D2C 수랭 | 액침 냉각 |
|---|---|---|---|
| 열 제거 방식 | 공기 대류 | 칩 냉각판의 냉각수 | 비전도성 유체에 장비 침지 |
| 적합 랙 밀도 | 저·중밀도 | 고밀도 GPU 랙 | 초고밀도 |
| 기존 설비 활용 | 기존 전산실 그대로 | 기존 랙에 배관 추가 | 전용 탱크 필요 |
| 주요 위험 | 국소 과열·팬 전력 | 누수·배관·수질 관리 | 유체·부품 호환성·정비 |

## Ⅴ. AI 에너지 인프라 구축의 한계와 방안

| 한계 | 방안 |
|---|---|
| 계통 접속 지연으로 준공 후 가동 불가 | 부지 확정 전 계통 사업자와 공급 가능 시점 확인 |
| 공랭으로 고밀도 GPU 랙 발열 제거 불가 | 고밀도 랙은 D2C 수랭 선택, 저밀도 영역은 공랭 유지 |
| 전력·냉각 용량을 따로 설계해 한쪽이 먼저 한계 도달 | 랙 밀도 기준으로 전력·냉각 용량의 동시 산정 |
| 학습 부하 급변에 따른 전력 품질 저하 | **BESS** 와 작업 스케줄링으로 부하 변동 완화 |
| 용수·탄소 부담의 증가 | **PUE** ·**WUE** 계측과 **PPA** 를 통한 전원 구성 관리 |

## Ⅵ. 제언

부지 확정 전 전력 공급 시점과 냉각·용수 조건을 같은 기준으로 판정하고, 판정을 통과한 용량만큼 단계 증설

### 입지·용량 동시 판정 구조

```text
단계별 GPU 증설 용량
    │
    ├─ 전력 ── 계통 접속 가능 시점·용량
    │
    ├─ 냉각 ── 랙 밀도별 냉각 방식
    │
    └─ 용수 ── 냉각 방식별 물 사용 가능량
```

### 판정 확대: 단계 증설 결정 흐름

```text
다음 단계 증설 용량 산정
    ↓
전력·냉각·용수 조건 동시 확인
    ├─ 하나라도 미충족 → 증설 규모 축소 또는 시점 조정
    └─ 모두 충족 → 설비 발주와 통합 가동 시험
    ↓
가동 후 계측값의 다음 단계 반영
```

### 선택 근거: 설비별 분리 설계와의 비교

| 구분 | 설비별 분리 설계 | 제언: 입지·용량 동시 판정 |
|---|---|---|
| 판단 시점 | 부지 확정 후 설비별 설계 | 부지 확정 전 |
| 증설 기준 | 수요 예측 전체 용량 | 전력·냉각·용수 충족 용량 |
| 제약 발견 시점 | 준공·가동 단계 | 증설 결정 단계 |
