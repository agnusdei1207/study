## 연관 키워드

- 디자인 씽킹(Design Thinking), 사용자 중심, 공감
- 아이디에이션, 프로토타이핑, 테스트, 더블 다이아몬드

## Ⅰ. 디자인 씽킹의 개요

- 핵심 요약 : 사용자에 대한 이해에서 출발해 문제를 재정의하고 해결책을 반복 검증하는 사용자 중심 혁신 방법론.
- 개념 : **디자인 씽킹** (Design Thinking)은 사용자의 행동과 맥락에 대한 깊은 이해에서 출발해 문제를 재정의하고, 대안 생성과 시제품 시험의 반복으로 해결책을 다듬는 사용자 중심 혁신 방법론.
- 배경 및 필요성 : 기술·기능 중심 개발은 사용자 가치와의 괴리로 시장 실패 위험이 크고, 문제 정의의 오류가 후반 개발 비용을 증대시키는 구조이므로 조기 검증 절차 필요.
- 주요 목적 : 사용자 가치에 부합하는 해결책의 조기 검증과 혁신 실패 비용의 축소.

## Ⅱ. 디자인 씽킹의 특징 및 장점

- 핵심 요약 : 공감부터 테스트까지의 단계 반복이 숨은 니즈 발견과 실패 비용 절감으로 이어짐.

1. 사용자 관찰 출발 : **공감** (Empathize, 관찰·인터뷰로 사용자의 상황과 감정을 몰입해 이해하는 활동)으로 명시되지 않은 니즈 포착 → 기능 나열식 요구 수집의 한계 보완.
2. 문제의 명료화 : 조사 결과를 **문제 재정의** (Define, 조사 결과를 해결할 문제로 명확히 서술하는 활동) 문장으로 압축 → 팀 전체의 자원 집중 기준 확보.
3. 발산·수렴 사고 : **아이디에이션** (Ideation, 다수의 대안을 발산적으로 생성한 뒤 기준으로 걸러내는 단계)으로 대안 다양성과 실현 가능성의 균형 확보.
4. 저비용 시제품 : **프로토타이핑** (Prototyping, 종이 모형·목업 등 최소 비용으로 아이디어를 구체화하는 활동)으로 시험 대상 조기 확보 → 내부 합의 소요 단축.
5. 조기 검증 : **테스트** (Test, 사용자의 반응을 관찰해 가설을 확인하는 활동)로 후단 개발 투입 전 방향 수정 → 실패 비용 절감.

## Ⅲ. 디자인 씽킹의 구조 (흐름)

- 핵심 요약 : 5단계의 순환 프로세스와 발산·수렴의 이중 반복 구조로 구성.

```text
[ 5단계 프로세스 ]

공감 (Empathize)
   ↓
정의 (Define)
   ↓
아이디에이션 (Ideate)
   ↓
프로토타이핑 (Prototype)
   ↓
테스트 (Test)
   ↓
학습 결과를 공감·정의 단계로 환류
```

```text
[ 더블 다이아몬드 : 발산과 수렴의 반복 ]

문제를 넓게 탐색 (발산)
   ↓
문제를 좁혀 정의 (수렴)
   ↓
해결책을 넓게 생성 (발산)
   ↓
해결책을 좁혀 전달 (수렴)
```

- 운영 원칙 : 단계 간 순차 이행보다 학습 결과에 따른 반복 이동을 전제로 운영.

## Ⅳ. 디자인 씽킹과 애널리틱스의 비교

- 핵심 요약 : 사용자 관찰 기반의 문제 재정의 방법과 축적 데이터 기반의 분석 방법이 상보 관계를 형성.

| 비교 축 | 디자인 씽킹 | 애널리틱스 (Analytics) |
| --- | --- | --- |
| 출발점 | 사용자 관찰·맥락 이해 | 축적 데이터·가설 검정 |
| 문제 유형 | 정의되지 않은 문제의 재정의 | 정의된 문제의 최적화 |
| 방법 | 인터뷰·시제품·반복 시험 | 통계 분석·모형·지표 |
| 산출물 | 문제 정의·시제품·컨셉 | 인사이트·예측·대시보드 |
| 적합 영역 | 신규 서비스·혁신 초기 | 운영 개선·성과 관리 |

## Ⅴ. 디자인 씽킹의 한계와 방안

- 핵심 요약 : 표본 편향·실현성 간과·형식화·성과 측정 부재를 절차와 지표로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 조사 표본 편향 | 소수 의견의 과대 반영 → 방향 오류 | 대표 사용자 선정·정량 조사 병행 | 조사 대상 다양성 |
| 실현성 간과 | 시제품과 운영 환경의 괴리 → 개발 단계 좌초 | 기술·비용 제약의 조기 검토 | 구현 전환율 |
| 워크숍 형식화 | 일회성 행사로 종결 → 지속 개선 부재 | 실제 개발 프로세스와의 연계 의무화 | 후속 과제 수 |
| 성과 측정 부재 | 효과가 지표로 확인되지 않음 → 투자 정당화 곤란 | 문제 정의 시 개선 지표 동시 설정 | 지표 설정률 |

## Ⅵ. 디자인 씽킹에 대한 기술사적 제언

- 핵심 요약 : 사용자 조사와 시제품 검증을 신규 서비스 기획의 표준 절차로 제도화 필요.
- 조직 : 최고정보책임자(CIO, Chief Information Officer) 산하에 디자이너·개발자·도메인 전문가의 혼합팀과 사용자 리서치 지원 기능 구성.
- 절차 : 신규 서비스 기획 단계에 사용자 관찰 결과와 시제품 검증 기록의 제출 의무화.
- 인프라 : 리서치 도구와 시제품 제작 환경을 사내 공통 자원으로 운영.

## Ⅶ. 결론

- 핵심 요약 : 디자인 씽킹은 사용자 가치에서 출발해 문제와 해결책을 반복 검증하는 혁신 절차.
- 데이터 분석과 결합할 때 문제 정의의 깊이와 검증의 객관성을 함께 확보함.
