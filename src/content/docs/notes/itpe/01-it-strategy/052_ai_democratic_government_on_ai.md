## 큰 그림과 30초 인출

```text
[신청주의 행정 한계 및 업무 과중]
          │
          ▼
┌────────────────── [AI 민주정부 / 온AI 3대 계층] ──────────────────┐
│  1. 대국민 서비스 계층: 국민 맞춤형 '혜택알리미', AI 민원 비서     │
│  2. 공무원 업무 계층  : 온AI 워크스페이스 (기안문 요약, 정책 시뮬)│
│  3. 공통 기반 인프라  : 범정부 공통 AI 플랫폼, 공공 특화 sLLM/RAG│
└───────────────────────────────────────────────────────────────────┘
          │
          ▼
[다층 보안 체계(MLS) 연계 → 복지 사각지대 해소 및 선제적 지능 행정]
```

- 본질: 국민이 직접 혜택을 찾아 신청하지 않아도 AI가 알아서 필요한 공공 서비스를 선제 제공하고, 공무원의 문서 작성과 정책 결정을 인공지능이 보조하는 '전 공공 행정의 AI 일상화(On-AI)' 국가 체계
- 위치: `전자정부(전산화) → 디지털플랫폼정부(데이터 연계) → AI 민주정부(온AI 내재화)`
- 핵심: 온AI(On-AI), 혜택알리미, 공공 특화 sLLM, 행정 RAG, 다층 보안 체계(MLS)
- 실무: 행정망 보안 격리 준수, 환각(Hallucination) 방지 법령 검증, 인간 개입(Human-in-the-loop)

## 예상문제

> 공공 행정의 생산성 혁신과 대국민 맞춤형 복지 서비스 제공을 위한 'AI 민주정부(온AI)'의 비전, 핵심 아키텍처 계층, 공공 특화 sLLM 및 RAG 기반 구현 방안, 망분리 개선(MLS) 연계 보안 대책을 설명하시오. (25점)

## Ⅰ. 신청주의 행정의 극복과 지능형 공공 혁신, AI 민주정부 개요

- 정의: 정부의 모든 행정 시스템 및 대국민 서비스 접점에 인공지능을 기본 내재화(On-AI)하여, 국민에게는 맞춤형 혜택을 선제 제공하고 공무원에게는 초지능 업무 보조를 지원하는 차세대 정부 모델
- 등장 배경: 정보 비대칭으로 인한 복지 사각지대 발생, 공무원의 단순 반복 서류 작업 과중, 생성형 AI 기술 성숙 및 디지털플랫폼정부(DPG) 발전
- 핵심 목적: "찾아가는 선제적 행정" 구현, 공공 데이터 기반의 과학적 정책 수립, 행정 오류 감소 및 대국민 행정 만족도 극대화

#### 한줄 요약
- 공공 행정 전반에 AI를 기본 내재화하여 선제적 대국민 서비스를 실현하는 지능형 정부임

## Ⅱ. 전자정부 vs 디지털플랫폼정부(DPG) vs AI 민주정부(온AI) 비교

| 비교 항목 | 전자정부 (e-Government) | 디지털플랫폼정부 (DPG) | AI 민주정부 (On-AI Government) |
|---|---|---|---|
| **행정 패러다임** | 오프라인 문서의 디지털 전산화 | 부처 간 데이터 칸막이 해소 및 연계 | 전 행정 프로세스에 AI 상시 내재화 |
| **서비스 제공 방식**| 국민의 직접 방문 및 온라인 신청주의 | 통합 포털 기반의 원스톱 서비스 | 알아서 찾아주는 선제적 맞춤형 서비스 |
| **핵심 기술** | 웹 포털, RDBMS, PKI 공인인증서 | 클라우드 네이티브, 오픈 API, 데이터 댐 | 생성형 AI, 공공 특화 sLLM, 행정 RAG |
| **의사결정 방식** | 담당 공무원의 직관 및 서류 검토 | 부처 간 정량 데이터 결합 및 분석 | AI 정책 시뮬레이션 및 데이터 과학 검증 |
| **대표 서비스** | 전자민원(정부24), 나라장터 | 공공 마이데이터, 복지멤버십 | 국민 비서 혜택알리미, AI 지능형 민원 |

#### 한줄 요약
- 단순 전산화(전자정부)와 데이터 연계(DPG)를 넘어 AI 지능형 능동 행정으로 진화함

## Ⅲ. AI 민주정부(온AI) 3대 계층 아키텍처

```text
┌───────────────── [1. 대국민 선제적 서비스 계층] ─────────────────┐
│  - 국민 맞춤형 혜택알리미, 24/365 AI 민원 상담관, 위기가구 조기 발굴  │
└──────────────────────────────────▲────────────────────────────────┘
                                   │ 민관 융합 API 및 마이데이터 연계
┌───────────────── [2. 공무원 온AI 워크스페이스 계층] ──────────────┐
│  - 기안문/보도자료 초안 생성, 법령·판례 검색 RAG, 정책 시뮬레이터   │
└──────────────────────────────────▲────────────────────────────────┘
                                   │ 안전한 행정망 연계 인터페이스
┌───────────────── [3. 범정부 AI 공통 인프라 계층] ────────────────┐
│  ├─ 공공 특화 경량 거대언어모델 (행정 문서 파인튜닝 sLLM)         │
│  ├─ 행정 RAG 지식베이스 (국가법령, 행정규칙, 지침 벡터 DB)        │
│  ├─ 다층 보안 체계 (MLS: 기밀/민감/공개 데이터 등급별 보안 통제) │
│  └─ 개인정보 보호 필터 (주민등록번호 마스킹, 가명화 파이프라인)   │
└───────────────────────────────────────────────────────────────────┘
```

| 구성 계층 | 핵심 기능 | 구현 기술 및 표준 |
|---|---|---|
| **대국민 서비스 계층** | 신청 전 복지 혜택 추천, AI 기반 복합 민원 처리 | 대화형 인터페이스, 공공 마이데이터 연동 |
| **온AI 워크스페이스** | 행정 문서 자동 요약, 공문 초안 작성, 법령 질의응답 | 행정 온나라 시스템 플러그인, 프롬프트 템플릿 |
| **공공 특화 sLLM** | 공공 행정 용어 및 표준 공문 서식에 특화된 경량 모델 | 파인튜닝(PEFT/LoRA), 국산 오픈소스 모델 |
| **행정 RAG 지식베이스** | 법령, 훈령, 조례 등 공공 원문 근거 기반 검색 증강 | 벡터 데이터베이스, 시맨틱 하이브리드 검색 |
| **다층 보안 체계(MLS)** | 데이터 중요도에 따라 상용 클라우드와 폐쇄망 차등 격리 | 국정원 MLS 가이드라인, 망연계 솔루션 |

#### 한줄 요약
- 대국민 서비스, 공무원 업무 보조, 공통 AI 인프라의 3계층으로 구성됨

## Ⅳ. 온AI 공공 행정 서비스 구현 4단계 절차

```text
① 공공 데이터 정제 및 벡터화 → ② 도메인 sLLM/RAG 구축 → ③ 온나라 시스템 인라인 연동 → ④ 대국민 서비스 배포
   └─ 법령·공문서 가명처리       └─ 프라이빗 지식베이스       └─ 공무원 업무 보조 검증         └─ 혜택알리미 모바일 연계
```

| 단계 | 주요 수행 내용 | 핵심 산출물 및 기준 |
|---|---|---|
| **1. 데이터 준비** | 비정형 행정 문서 수집, 개인식별정보(PII) 비식별 조치, 임베딩 벡터화 | 공공 벡터 데이터베이스 |
| **2. 모델 구축** | 행정 특화 sLLM 파인튜닝, RAG 검색 파이프라인 연계 및 환각 억제 테스트 | 검증된 공공 파운데이션 모델 |
| **3. 행정망 연계** | 온나라 전자결재 및 공문서 편집기에 AI 어시스턴트 플러그인 연동 | 업무용 AI 워크스페이스 |
| **4. 서비스 배포** | 혜택알리미 등 대국민 플랫폼 연동 및 실시간 모니터링 체계 가동 | 대국민 지능형 서비스 포털 |

#### 한줄 요약
- 데이터 가명화 및 벡터화, sLLM 구축, 업무망 연동, 대국민 배포 순으로 진행함

## Ⅴ. 공공 폐쇄망 구축형(On-premise sLLM) vs 상용 클라우드 LLM 비교

| 비교 항목 | 공공 폐쇄망 구축형 (sLLM) | 상용 클라우드 연계형 (Public LLM) |
|---|---|---|
| **보안성** | 행정망 내부 격리로 기밀 및 개인정보 유출 원천 차단 | 데이터 외부 전송 위험 존재, API 보안 통제 필수 |
| **망분리 규제** | 기존 국가정보원 물리적 망분리 규정 완벽 준수 | 다층 보안 체계(MLS) 적용 시 공개/민감 데이터만 활용 가능 |
| **모델 성능** | 특정 행정 도메인에는 강력하나 범용 상식 추론 한계 | 최신 초거대 파라미터 기반의 압도적 범용 추론 능력 |
| **구축 비용** | 초기 GPU 서버 도입 및 인프라 구축 비용 발생 | 토큰 사용량 기반 종량제 과금으로 초기 비용 저렴 |
| **적용 영역** | 비공개 기안문 작성, 내부 감사, 기밀 정책 수립 | 대국민 민원 안내, 공개 정책 요약, 다국어 번역 |

#### 한줄 요약
- 기밀 업무는 폐쇄망 sLLM을 활용하고, 공개 대민 서비스는 상용 클라우드를 활용함

## Ⅵ. 실무 추진 시 장애 요인 및 통제 대책

- 적용 상황: 중앙행정기관 및 지자체 공통 온AI 행정 지원 시스템 구축

| 문제점 | 발생 원인 | 공학적·제도적 해결 대책 | 기대 효과 |
|---|---|---|---|
| **행정 기밀 외부 유출 위험** | 외부 상용 LLM API 호출 시 공문서 본문 데이터 유출 | 행정망 내 프라이빗 sLLM 구축 및 데이터 마스킹 게이트웨이 의무화 | 국가 행정 데이터 보안 완벽 보장 |
| **환각(Hallucination)에 의한 오처분** | LLM의 통계적 확률 생성 특성으로 인한 거짓 법령 인용 | 법령 조항 원문 임베딩 기반 RAG 구축 및 원본 출처 각주 강제화 | 행정 처분의 법적 신뢰성 확보 |
| **알고리즘 편향에 따른 복지 누락** | 과거 수혜자 데이터의 편향 학습으로 신규 취약계층 소외 | 설명가능한 AI(XAI) 판정 근거 제시 및 인간 검인(Human-in-the-loop) 의무화 | 공공 복지 처분의 공정성 담보 |
| **물리적 망분리로 인한 신기술 차단** | 일률적인 인터넷 차단으로 인해 최신 AI 모델 접근 불가 | 국가정보원 다층 보안 체계(MLS) 기반 데이터 등급별 차등 접근 허용 | 보안과 AI 혁신의 조화 달성 |

#### 한줄 요약
- 프라이빗 sLLM, 행정 RAG, Human-in-the-loop, MLS 보안 적용으로 위험을 통제함

## Ⅶ. 인간 최종 책임(Human-in-the-loop) 중심의 결론

- **[AI는 보조자, 법적 책임은 인간 공무원에게 귀속]**: 온AI 정부에서 AI가 작성한 기안문이나 복지 판정 추천은 초안일 뿐이며, 행정 처분의 법적 책임은 최종 결재권자인 공무원에게 귀속되어야 함
- 나라면: 공공 행정 시스템에 `모든 AI 생성 문서에 프롬프트 버전 및 원천 법령 메타데이터 자동 날인 → 공무원 최종 검토 서명 필수화 → 생성 이력 영구 감사 추적` 체계를 구축하여 행정 무결성을 수호

#### 한줄 요약
- AI의 보조 기능과 인간 공무원의 최종 책임을 결합하여 투명한 지능 행정을 완성함

## 1교시 10점 답안 발췌

### 1. AI 민주정부 / 온AI의 정의
- 공공 행정 업무 전반에 AI를 기본 내재화(On-AI)하여 공무원의 정책 기획을 보조하고, 국민에게는 복지 혜택과 민원 서비스를 알아서 선제 공급하는 차세대 지능형 정부 모델

### 2. 온AI 핵심 3대 계층 구조
```text
[대국민 서비스] ──> 국민 맞춤형 '혜택알리미' + 24/365 AI 민원 비서
       │
[공무원 업무]   ──> 온AI 워크스페이스 (기안 요약, 법령 RAG, 시뮬레이션)
       │
[공통 인프라]   ──> 행정 sLLM + 법령 벡터 지식베이스 + 다층 보안(MLS)
```

### 3. 차별화 제언
- 행정 환각 방지를 위해 법령 원문 RAG 파이프라인을 구축하고, 국정원 MLS 가이드라인에 맞춘 기밀/공개 데이터 분리 및 '인간 최종 검인(Human-in-the-loop)' 원칙을 제도화해야 함
