## 연관 키워드

- DRS(Disaster Recovery System), 재해복구, DR센터
- RTO, RPO, 미러·핫·웜·콜드 사이트, 구축 형태, 액티브-액티브, BCP

## Ⅰ. DRS의 개요

- 핵심 요약 : 재해·중대 장애로 주 데이터센터 이용이 불가능할 때 대체 인프라에서 IT 서비스와 데이터를 복구하는 체계.
- 개념 : 천재지변·화재·사이버 공격 등 재해로 주 정보시스템이 중단될 때, 지리적으로 분리된 **DR센터**(재해복구 전용 대체 센터)의 인프라·백업·복제 자산으로 시스템과 데이터를 복구하는 기술·절차의 체계인 **재해복구시스템**(DRS, Disaster Recovery System).
- 배경 및 필요성 : 데이터센터의 단일화 구성에서는 지역 재해 시 서비스 장기 중단·데이터 손실이 현실화되고, 개인정보 보호 법제가 재해 대비 내부 관리계획 수립을 요구.
- 주요 목적 : 재해 상황에서도 허용 최대 중단 시간인 **RTO**(Recovery Time Objective)와 허용 최대 데이터 손실 시점인 **RPO**(Recovery Point Objective) 안에서 우선 서비스·데이터의 복구로 업무연속성 계획(BCP, Business Continuity Planning)의 기술 실행 기반 확보.

## Ⅱ. DRS의 특징 및 장점

- 핵심 요약 : 복구 목표의 정량화, 사이트 유형의 단계화, 구축 형태의 선택이 비용 대비 복구 역량을 최적화.

1. 복구 목표의 정량화 : 업무영향 분석으로 RTO·RPO를 산정 → 투자 규모와 복구 우선순위의 합리적 결정.
2. 복구 수준별 사이트 유형 : 실시간 동기화의 **미러 사이트**(주·대체 센터가 동시에 서비스하는 최상위 수준), 대기 전환의 **핫 사이트**(동일 수준 구성을 대기시켜 수 시간 내 전환), 부분 보유의 **웜 사이트**(중요 데이터만 부분 보유), 최소 구성의 **콜드 사이트**(공간·전력 중심 확보)로 단계화 → 업무 중요도별 비용 최적화.
3. 구축 형태의 선택지 : 규모·보안 요건에 따라 **독자 구축**(단일 기관의 자체 운영)·**공동 구축**(복수 기관의 공동 출자·이용)·**아웃소싱 구축**(전문 업체 위탁) 중 선택 → 초기 투자 부담의 완화.
4. 데이터의 이중 확보 : 동기·비동기 복제와 백업의 조합 → 재해 후에도 손실 범위를 RPO 안에서 통제.
5. 복구 절차의 문서화·훈련 : 복구 순서·담당·점검표의 문서화와 정기 리허설 → 실제 재해 시 목표 달성 가능성 제고.

## Ⅲ. DRS의 구조 (흐름)

- 핵심 요약 : 사이트 유형 선택 → 구축·복제 → 재해 선언 → 전환·복구 → 검증·복귀의 생애주기.

- 대체 센터의 복구 수준 단계 : 등급이 낮아질수록 비용은 줄고 복구 시간은 길어짐.

```text
미러 사이트 (동시 서비스, 즉시 전환)
   ↓ 등급 하향
핫 사이트 (대기 상태, 수 시간 내 전환)
   ↓
웜 사이트 (부분 구성, 수일 내 복구)
   ↓
콜드 사이트 (공간·전력 중심, 수주 이상)
   ↓
백업 매체 원격지 보관 (복원에 최장 시간)
```

- 재해복구 운영 흐름 : 평시 준비와 재해 시 전환의 구분.

```text
평시 : 주센터 → DR센터 복제·백업
   ↓
재해 발생·복구 선언
   ↓
DR센터 인프라·데이터 복구
   ↓
서비스 전환·검증
   ↓
원센터 복구·재동기화·복귀
```

## Ⅳ. DRS와 액티브-액티브 고가용 구성의 비교

- 핵심 요약 : DRS는 지역 재해를 가정한 복구 중심 구성, 액티브-액티브 고가용 구성은 장비·노드 장애를 가정한 무중단 서비스 중심 구성.

- **액티브-액티브**(Active-Active, 전 노드가 동시에 서비스하는 이중화)은 같은 장소 안의 고가용성 구성이라는 점에서 DRS의 대안이자 보완 대상.

| 비교 축 | DRS | 액티브-액티브 고가용 구성 |
| --- | --- | --- |
| 가정 장애 범위 | 데이터센터·지역 단위 재해 | 장비·노드 단위 장애 |
| 인프라 배치 | 지리적으로 원거리 분리 | 동일·인접 센터 내 이중화 |
| 평시 서비스 | 주센터 단독 서비스·복제 | 전 노드의 동시 서비스 |
| 전환 목표 | RTO·RPO 안의 복구 | 사용자 인지 없는 전환 |
| 비용 성격 | 대기 인프라 유지 비용 | 상시 가동 인프라 비용 |
| 관리 초점 | 복구 절차·훈련·검증 | 부하 분산·용량·동기화 지연 |

- 미러 사이트는 주·대체 센터의 실시간 동시 서비스 구성으로 재해복구와 고가용의 성격을 겸비.

## Ⅴ. DRS의 한계와 방안

- 핵심 요약 : 복원 실패, 동일 위험 영역, 랜섬웨어 오염, 절차 공백을 원인별 대응과 지표로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 복원 실패 | 백업 무결성 미검증 → 복원 불가 | 격리 환경의 정기 복원 시험 | 복원 시험 성공률 |
| 동일 위험 영역 | 주·DR센터의 전력·통신·입지 공유 → 동시 피해 | 입지·전력·회선의 분리 점검 | 공통 장애 요인 수 |
| 랜섬웨어 오염 | 복제·백업까지 암호화 → 복구원 상실 | 불변 백업·오프라인·네트워크 분리 보관 | 복원 가능 백업 비율 |
| 절차 공백 | 담당·순서 미문서화 → 전환 혼선 | 복구 절차서·정기 리허설 | 리허설 목표 달성률 |

## Ⅵ. DRS에 대한 기술사적 제언

- 핵심 요약 : 정보시스템 운영 책임 조직의 DR 거버넌스와 표준 참조 구성으로 복구 역량의 제도화.
- 거버넌스 : CIO(최고정보책임자) 직속 DR 운영 회의를 두어 RTO·RPO 합의와 투자 우선순위 결정.
- 아키텍처 : 클라우드 DR·자동화 전환을 표준 참조 구성으로 정의해 전사 확산.
- 제도 : RTO·RPO 미달 시 투자 재산정 규정을 두고 경영진 보고 체계 운영.

## Ⅶ. 결론

- 핵심 요약 : DRS는 대체 인프라의 보유가 아니라 목표 시간 안의 복구 가능성을 입증하는 체계.
- RTO·RPO 합의와 정기 검증이 갖춰질 때 재해복구 투자가 실제 회복력으로 전환.
