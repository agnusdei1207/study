## 지식 로드맵 내 현재 위치

IT 전략·관리 → IT 운영전략·소싱 거버넌스 → **IT 아웃소싱**

## 30초 인출

- 본질: IT 아웃소싱(IT Outsourcing)은 IT 기능의 일부 또는 전부를 외부 공급자가 수행하도록 위탁하는 조달 방식
- 메커니즘: 위탁 범위(전면 또는 선택적)를 정하고, 계약 문서에 준수 요구·역할·SLA를 명시한 뒤, 위탁 기간 내내 공급자의 준수를 모니터링
- 통찰: 공급자가 구현과 통제를 쥐고 있어도 위험 관리 책임은 위탁자에게 남으므로, 위탁 범위를 필요한 활동으로 좁히고 계약에 보호조치와 감독 방법을 명시해 위탁 기간 내내 점검

<details>
<summary>핵심 용어</summary>

- **IT 아웃소싱(IT Outsourcing)** : IT 기능을 외부 공급자에게 위탁해 수행시키는 조달 방식. 정보기술 아웃소싱(ITO, Information Technology Outsourcing)으로도 표기
- **BPO(Business Process Outsourcing)** : 특정 업무 프로세스의 운영과 책임을 외부 공급자에게 위탁하는 방식. IT 기능 위탁인 ITO와 위탁 대상이 다름
- **전면 아웃소싱(Total Outsourcing)** : IT 조직의 인력·시설·하드웨어 임대·소프트웨어 라이선스를 외부 공급자에게 이전하는 방식
- **선택적 소싱(Selective Sourcing)** : 특정 활동만 골라 짧은 기간의 계약으로 위탁하는 방식
- **SLA(Service Level Agreement)** : 공급자가 지켜야 할 성과 기대치, 측정 가능한 결과, 미준수 시 조치를 정한 서비스 수준 계약
- **외부 시스템 서비스(External System Services)** : 외부 공급자가 제공하고 위탁 조직이 구현과 통제 효과 평가를 직접 통제할 수 없는 서비스
- **위탁자·수탁자** : 개인정보 처리 업무를 맡기는 개인정보처리자와 그 업무를 맡아 처리하는 자. 개인정보 보호법이 정한 호칭

## 2~4교시 25점 답안

## Ⅰ. IT 아웃소싱의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **IT 아웃소싱(IT Outsourcing)** 은 IT 기능의 일부 또는 전부를 외부 공급자가 수행하도록 위탁하는 조달 방식 |
| 목적 | 필요한 IT 기능의 외부 수행 확보와 위탁 위험의 관리 |

## Ⅱ. 통제가 간접적인 IT 아웃소싱의 특징

| 특징 | 의미 |
|---|---|
| 간접 통제 | 구현과 통제 효과의 평가를 위탁 조직이 직접 통제하지 못함 |
| 책임의 잔존 | 외부 서비스 이용의 위험 관리 책임은 위탁 조직에 존속 |
| **SLA** 기반 계약 | 신뢰 관계의 근거와 성과 기대치를 문서로 관리 |

## Ⅲ. IT 아웃소싱 수행 체계

### 위탁 수행 절차

```text
위탁 범위 결정: 전면 아웃소싱 또는 선택적 소싱
    ↓
계약 문서화
    ├─ 공급자의 보안·개인정보 요구 준수
    ├─ 위탁 조직의 감독 역할·책임
    └─ SLA: 성과 기대치·측정 결과·미준수 시 조치
    ↓
공급자의 업무 수행
    ↓
지속 모니터링: 통제 준수 점검
```

### 계약·감독 확대: 개인정보 처리 업무 위탁

```text
개인정보 처리 업무의 위탁 (개인정보 보호법 제26조)
    │
    ├─ 문서화(제1항) ── 목적 외 처리 금지 · 기술적·관리적 보호조치 · 안전한 관리를 위한 대통령령 사항
    ├─ 공개(제2항) ── 위탁 업무 내용과 수탁자
    └─ 감독(제4항) ── 수탁자 교육 · 처리 현황 점검
```

## Ⅳ. 위탁 범위에 따른 소싱 유형 비교

| 구분 | **전면 아웃소싱** | **선택적 소싱** |
|---|---|---|
| 위탁 범위 | IT 인력·시설·하드웨어 임대·소프트웨어 라이선스 전체 | 특정 활동 |
| 계약 기간 | 7~10년 | 5년 미만 |
| 위험 | 전면 위탁에 따른 위험 | 전면 위탁의 위험을 줄이며 고객 요구 충족 |

## Ⅴ. IT 아웃소싱의 한계와 방안

| 한계 | 방안 |
|---|---|
| 공급자가 구현과 통제를 쥐어 위탁 조직의 직접 확인 불가 | 계약에 보안·개인정보 요구의 준수를 명시하고 준수 여부의 지속 모니터링 |
| 위탁 후에도 위험 관리 책임이 남아 감독 주체 불분명 | 위탁 조직의 감독 역할·책임의 문서화 |
| 개인정보 처리 위탁 시 수탁자 측 유출 | 위탁 문서에 목적 외 처리 금지·보호조치 명시, 수탁자 교육과 처리 현황 점검 |
| 전면 위탁·장기 계약으로 위탁 범위와 위험이 함께 커짐 | 필요한 활동만 짧은 기간으로 위탁하는 **선택적 소싱** 적용 |

## Ⅵ. 제언

위탁 범위를 필요한 활동으로 좁히고, 계약에 보호조치와 감독 방법을 명시해 위탁 기간 내내 준수를 점검

### 위탁자·수탁자의 책임 분담

```text
위탁 조직(발주자)                     공급자(수탁자)
 ├─ 위험 관리 책임: 위탁 후에도 유지     ├─ 계약된 보호조치의 구현
 ├─ 위탁 범위·요구사항 결정             └─ 준수 증빙 제출
 └─ 준수 감독·점검
              계약 문서(SLA 포함)로 연결
```

### 감독 확대: 준수 점검과 미준수 조치

```text
계약된 보호조치·SLA 지표
    ↓
정기 점검: 공급자의 준수 증빙 확인
    ├─ 충족 → 위탁 유지
    └─ 미충족 → SLA에 정한 조치·시정 요구 → 재점검
```

| 구분 | 전면·일괄 위탁 | 제언: 범위 한정 위탁과 지속 감독 |
|---|---|---|
| 위탁 대상 | IT 기능 전체 | 필요한 활동 |
| 통제 확인 방식 | 계약 체결 시점의 확인 | 위탁 기간 내내 모니터링 |
| 미준수 시 | 사후 분쟁 | SLA에 정한 조치와 재점검 |

## 출제 이력과 검증 출처

- 제132~140회 Q-net 공식 문제지에서 IT 아웃소싱을 직접 묻는 문항은 확인되지 않음
- M. Lacity, L. Willcocks, D. Feeny, "The Value of Selective IT Sourcing", *Sloan Management Review* (1996년 봄호) — 전면 아웃소싱·선택적 소싱
- NIST SP 800-53 Rev. 5 통제 SA-9 External System Services (Rev 5.2.0 카탈로그) — 간접 통제·책임 잔존·SLA·지속 모니터링
- 개인정보 보호법(법률 제21445호, 2026.3.10. 일부개정, 2026.9.11. 시행) 제26조
