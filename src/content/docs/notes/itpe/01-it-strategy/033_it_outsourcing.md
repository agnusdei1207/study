## 큰 그림과 30초 인출

```text
[경영 및 IT 전략] ──> [Make or Buy 의사결정]
                             │ (전략 중요도 vs 내부 역량)
                             ▼
 ┌─────────────── [아웃소싱 생명주기 (ISO 37500)] ───────────────┐
 │ ① 전략 수립 ──> ② 공급자 선정 ──> ③ 인수인계·전환 ──> ④ 운영·SLA 거버넌스 │
 └───────────────────────────────┬───────────────────────────────┘
                                 │ 계약 만료 / 재소싱
                                 ▼
                     [⑤ Exit Plan (탈출 전략 / 인소싱)]
```

- 본질: 기업의 핵심 역량 집중과 비용 절감, IT 유연성 확보를 위해 IT 업무(개발, 인프라, 운영 등)의 일부 또는 전부를 외부 전문 기업에 위탁하여 수행하는 전략적 소싱 기법
- 위치: `경영전략 → 소싱 포트폴리오 분석(Make or Buy) → RFP/계약(SLA) → 전환(Transition) → 운영 거버넌스 → Exit Plan`
- 핵심: 개발·운영은 위탁하더라도 IT 거버넌스, 아키텍처 기준선, 데이터 보안 및 최종 법적 책임은 발주사에 잔존(Retained Org)
- 표준: ISO 37500:2014 (Guidance on Outsourcing) 및 SIAM(Service Integration and Management)

## 예상문제

> IT 아웃소싱의 의사결정 모델(Make or Buy)과 ISO 37500 기반 생명주기 단계를 설명하고, 공급자 종속(Lock-in) 및 내부 역량 공동화(Hollowing out) 방지를 위한 SLA 거버넌스와 출구 전략(Exit Strategy)을 논하시오. (25점)

## Ⅰ. 핵심 역량 집중과 유연성 확보, IT 아웃소싱 개요

- 정의: 조직 내부에서 수행하던 정보시스템의 기획, 개발, 운영, 유지보수, 인프라 관리 등의 IT 활동을 외부 전문 업체와의 계약을 통해 위탁·조달하는 경영 방식
- 배경: 급변하는 신기술(클라우드, AI) 내재화 한계, 고정비 성격의 IT 인건비를 변동비화하려는 재무적 요구, 전문 서비스 품질 확보 필요성
- 목적: 비즈니스 핵심 역량에 자원 집중, 운영 효율화 및 비용 최적화, 최신 기술 도입 기간 단축

#### 한줄 요약
- 단순 인력 파견을 넘어 성과와 책임을 계약으로 규정하여 외부 전문성을 활용하는 전략적 소싱임

## Ⅱ. IT 소싱 의사결정 모델 (Make or Buy 매트릭스)

```text
[전략적 중요도]
      ▲
      │ [스마트 소싱 / 코소싱]             [인소싱 (Internal / Make)]
  높음│ - 경쟁 우위 지원 기술                - 기업 고유의 핵심 비즈니스 로직
      │ - 내부 통제하에 외부 전문인력 결합     - 아키텍처, IT 거버넌스, 데이터 주권
      ├────────────────────────────────────┼────────────────────────────────────
      │ [단순 외주 (Commodity Buy)]        [선택적 / 관리형 아웃소싱 (Buy)]
  낮음│ - 단순 코딩, 데이터 입력               - 표준 인프라 운영, PC 유지보수
      │ - 최저가 입찰, 유연한 계약            - 전문 서비스 기업에 위탁, SLA 통제
      └────────────────────────────────────┴────────────────────────────────────>
                   낮음                                 높음 [내부 기술·운영 역량]
```

| 소싱 유형 | 개념 정의 | 주 적용 영역 | 장점 및 위험 통제 |
|---|---|---|---|
| **전체 아웃소싱 (Total)** | 전산실 전체 업무 및 인프라를 단일 벤더에 일괄 위탁 | 대규모 그룹사 SI, 레거시 시스템 운영 | 규모의 경제 실현 / 벤더 종속(Lock-in) 위험 높음 |
| **선택적 아웃소싱 (Selective)** | 인프라, 네트워크, 보안 등 영역별 최고 벤더(Best-of-breed) 분할 위탁 | 클라우드 인프라, SOC 보안관제 | 전문성 극대화 / 벤더 간 인터페이스 관리 복잡 |
| **코소싱 (Co-Sourcing)** | 발주사 인력과 외주사 인력이 단일 팀으로 공동 프로젝트 수행 | 신기술 도입(AI, MSA), 차세대 구축 | 내부 인력 기술 이전 촉진 / 책임 소재 모호성 방지 |
| **BPO (Business Process)** | IT뿐 아니라 콜센터, 인사, 회계 등 비즈니스 프로세스 자체를 위탁 | 고객상담센터, 급여 정산 업무 | 비핵심 업무 완전 분리 / 업무 통제력 약화 주의 |

#### 한줄 요약
- 전략적 중요도가 높고 역량이 풍부하면 인소싱, 중요도는 높으나 역량이 부족하면 코소싱을 적용함

## Ⅲ. ISO 37500 기반 IT 아웃소싱 생명주기 4단계 아키텍처

```text
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  1. 전략 수립   │ ──> │  2. 선정·계약   │ ──> │  3. 이행·전환   │ ──> │  4. 운영·거버넌스│
│ (Strategy)      │     │ (Procurement)   │     │ (Transition)    │     │ (Governance)    │
└─────────────────┘     └─────────────────┘     └─────────────────┘     └─────────────────┘
 ├─ 소싱 타당성 분석     ├─ RFI/RFP 발행         ├─ 자산·지식 인수인계    ├─ SLA 성과 모니터링
 ├─ 대상 업무 확정       ├─ 제안서 평가          ├─ 병행 운영(Dual-run)   ├─ 서비스 크레딧 적용
 └─ 잔존조직(RO) 설계    └─ SLA/OLA 계약 체결    └─ 인수 서명(Sign-off)   └─ Exit Plan 갱신
```

| 생명주기 단계 | 주요 수행 내용 | 핵심 산출물 및 기준 |
|---|---|---|
| **1. 전략 수립** | 비즈니스 적합성 검토, TCO 분석, 잔존 조직(Retained Organization) 역할 정의 | 아웃소싱 전략 기획서 |
| **2. 공급자 선정**| RFP 배포, 제안서 기술평가, 현장 실사, 법적 계약 및 SLA 지표 확정 | RFP, 제안평가표, SLA 계약서 |
| **3. 전환(Transition)**| As-Is 업무 지식 이전(KT), 자산 양도, 시스템 접근 권한 이관, 병행 운영 | 업무 인수인계서, 전환 완료 보고서 |
| **4. 운영 및 평가**| 정기 운영 회의체 가동, 변경 관리, 서비스 수준 측정, 분쟁 해결, 재소싱 평가 | 월간 SLA 보고서, 출구 전략서(Exit Plan) |

#### 한줄 요약
- 전략 수립부터 선정, 전환, 운영 거버넌스로 이어지며 전 과정에 출구 전략이 동반되어야 함

## Ⅳ. 아웃소싱 운영의 핵심: 이중 거버넌스 체계

```text
[발주사 잔존 조직 (Retained Org)] <─── 전략 위원회 (반기/연간: 방향성, 계약 개정) ───> [공급사 경영진]
                 │                                                                        │
[발주사 IT 운영팀]                 <─── 전술 위원회 (월간: SLA 달성도, 비용, 변경심의) ───> [공급사 PMO]
                 │                                                                        │
[발주사 서비스 데스크]             <─── 운영 회의체 (주간/일일: 장애 조치, 티켓 현황)  ───> [공급사 작업조직]
```

| 통제 영역 | 세부 관리 메커니즘 | 통제 산출물 |
|---|---|---|
| **서비스 수준 (SLA)** | 가용성, 장애 복구시간(MTTR), 처리율 지표 모니터링 및 미달 시 위약금 부과 | SLA 달성도 보고서, 패널티 청구서 |
| **운영 레벨 (OLA)** | 공급사 내부 하위 부서 및 협력업체 간의 납기·품질 기준선 통제 | OLA(Operation Level Agreement) 계약서 |
| **변경 관리 (Change)** | 시스템 수정, 인프라 증설 등 과업 변경 시 엄격한 심의 및 비용 승인 | 변경요청서(CR), 영향도 분석서 |
| **데이터 및 보안** | 개인정보 처리 위탁 계약, 정기 보안 감사, 퇴사자 계정 즉시 회수 | 보안 서약서, 개인정보 위수탁 점검표 |

#### 한줄 요약
- 전략-전술-운영의 3단계 협의체와 SLA/OLA 계약을 통해 일상적 업무와 품질을 통제함

## Ⅴ. 전통적 아웃소싱 vs 멀티소싱(SIAM) vs 클라우드 관리형 서비스(MSP) 비교

| 비교 항목 | 전통적 아웃소싱 (Single ITO) | 멀티소싱 (SIAM 기반) | 클라우드 관리형 서비스 (MSP) |
|---|---|---|---|
| **소싱 구조** | 단일 대형 SI 기업에 전산실 통위탁 | 영역별 전문 벤더 다수 + 통합 관리자(SIAM) | 퍼블릭 클라우드 인프라 전문 운영 위탁 |
| **책임 소재** | 단일 주사업자가 전적 책임 | SIAM 조직이 다중 벤더 간 핑퐁 조정 | CSP(인프라)와 MSP(운영)의 공동 책임 모델 |
| **유연성/민첩성**| 계약 변경이 어렵고 기술 혁신 지연 | 우수 벤더 수시 교체 가능, 최신 기술 수용 | 클라우드 네이티브 도구 기반 고도의 자동화 |
| **관리 복잡도**| 상대적으로 낮음 (단일 창구) | 매우 높음 (벤더 간 의존성 및 인터페이스 통제) | 클라우드 API 및 FinOps 비용 최적화 통제 요구 |
| **주 위험 요인**| 벤더 종속(Lock-in), 역량 공동화 | 벤더 간 책임 전가, SIAM 역량 부족 | 클라우드 보안 설정 오류, 비용 폭증(Bill Shock) |

#### 한줄 요약
- 단일 위탁의 락인 위험을 피하기 위해 SIAM 멀티소싱과 전문 MSP 모델로 진화하고 있음

## Ⅵ. 실무 실패 요인과 공학적 통제 방안

- 적용 상황: 대규모 공공 및 금융 차세대 시스템 아웃소싱 운영 위탁 사업

| 실패 요인 | 발생 원인 | 공학적·관리적 해결 대책 | 기대 효과 |
|---|---|---|---|
| **내부 역량 공동화 (Hollowing out)** | 모든 기술 검토를 외주사에 일임하여 내부 기술 판단력 상실 | 아키텍처, 데이터 모델, 보안 등 핵심 기능은 잔존 조직(RO) 전담 | 기술 주권 유지 및 공급사 견제력 확보 |
| **벤더 종속 (Vendor Lock-in)** | 공급자 고유(Proprietary) 프레임워크 사용 및 독점적 지식 점유 | 표준 오픈소스 및 클라우드 네이티브 기술 채택, 산출물 형상관리 의무화 | 계약 만료 시 타 사업자로의 교체 용이 |
| **출구 전략(Exit Plan) 부재** | 계약 종료 시 인수인계 비협조로 인한 업무 마비 우려 | 계약서에 종료 지원 조항 명시 및 업무 인수인계 기간 비용 지급 의무화 | 분쟁 없는 원활한 재소싱/인소싱 전환 |
| **SLA의 부분 최적화 (수박 현상)** | 겉으로는 지표 달성(녹색)이나 사용자는 불만족(적색) | 단순 가용성 외에 사용자 체감 만족도(XLA: eXperience Level Agreement) 병행 | 진정한 고객 중심 서비스 품질 개선 |

#### 한줄 요약
- 잔존 조직(RO)의 핵심 기술 점유, XLA 도입, 계약서상 Exit Plan 의무화로 벤더 종속을 방지함

## Ⅶ. 잔존 조직의 거버넌스 역량 중심의 결론

- **[개발·운영은 위탁해도 통제권은 위탁할 수 없다]**: IT 아웃소싱의 궁극적 성패는 외주 개발사의 규모가 아니라, 공급사를 지휘하고 통제하는 발주사 내부 잔존 조직(Retained Organization)의 아키텍처 역량과 거버넌스 수준에 달려 있음
- 나라면: 아웃소싱 제안요청서 작성 시 `ISO 37500 표준 준수 요구 → 잔존 조직 전담 인력의 형상 변경 승인권 명시 → 6개월 전 출구 전략(Exit Strategy) 상세 이행 계획서 제출 의무화`를 조달 조건에 삽입하여 조직의 가역성을 확보

#### 한줄 요약
- 아웃소싱은 통제를 포기하는 것이 아니라 고도화된 거버넌스로 외부 역량을 지휘하는 경영 기술임

## 1교시 10점 답안 발췌

### 1. IT 아웃소싱의 정의
- 기업의 핵심 비즈니스 집중과 비용 최적화를 위해 IT 업무의 일부 또는 전부를 외부 전문 기업에 위탁하여 계약 및 SLA 기반으로 운영하는 전략적 소싱 관리 체계

### 2. Make or Buy 의사결정 모델 및 생명주기
```text
[Make or Buy 판단] ──> [1. 전략 수립] ──> [2. 선정·계약] ──> [3. 이행·전환] ──> [4. 운영 거버넌스]
(중요도 vs 내부역량)      (잔존조직 설계)       (SLA/OLA 체결)       (지식이전/KT)       (SLA 통제/Exit Plan)
```

| 구분 | 주요 특징 | 핵심 통제 요소 |
|---|---|---|
| 전체 아웃소싱 | 전산 인프라 및 운영 일괄 위탁 | 벤더 종속(Lock-in) 방지 대책, Exit Strategy |
| 선택적 아웃소싱 | 보안, 인프라, 앱 등 기능별 분할 위탁 | 벤더 간 책임 분계점 관리, SIAM(통합관리) |
| 코소싱 (Co-Sourcing) | 내부 인력과 외부 인력의 원팀 협업 | 내부 인력 기술 내재화, 공동 지식 자산화 |

### 3. 차별화 제언
- 지표는 만족하나 사용자가 불만족하는 '수박 SLA(Watermelon SLA)'를 방지하기 위해 사용자 경험 지표(XLA)를 도입하고, 계약 초기부터 철저한 출구 전략(Exit Plan)을 수립해야 함
