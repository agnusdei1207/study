## 지식 로드맵 내 현재 위치

IT 전략·관리 → IT 운영전략·소싱 거버넌스 → **IT 아웃소싱**

## 30초 인출

- 본질: IT 아웃소싱은 IT 업무의 일부를 외부 공급자에게 계약으로 맡기고 발주 조직이 성과·위험 책임을 유지하는 소싱 방식
- 메커니즘: Make or Buy로 위탁 범위를 정하고, 공급자 선정·전환·서비스 운영을 거쳐 종료 시 다음 공급자나 내부 조직으로 이전
- 통찰: 종료 조건 없이 계약하면 공급자 교체가 사실상 막히므로 계약 단계에서 잔존조직의 데이터·문서 인도와 권한 회수 조건 확정

<details>
<summary>핵심 용어</summary>

- **IT 아웃소싱** : IT 업무의 일부를 외부 공급자에게 계약으로 맡기고 성과·위험을 관리하는 소싱 방식
- **Make or Buy** : 업무를 내부에서 수행할지 외부에서 조달할지 전략·역량·위험·비용으로 판단하는 의사결정
- **SLA(Service Level Agreement)** : 서비스 수준 목표와 측정·보고·위반 시 조치를 정한 합의
- **잔존조직(RO, Retained Organization)** : 위탁 후에도 발주 조직 안에 남겨 두는 전략·아키텍처·계약 관리 조직
- **SIAM(Service Integration and Management)** : 복수 공급자의 서비스를 하나의 통합 기능이 조정·관리하는 운영 모델
- **Exit Plan** : 계약 종료나 공급자 교체 때 데이터·문서·지식·권한을 이전하는 계획

</details>

## 2~4교시 25점 답안

## Ⅰ. IT 아웃소싱의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **IT 아웃소싱** 은 IT 업무의 일부를 외부 공급자에게 계약으로 맡기고 발주 조직이 성과·위험 책임을 유지하는 소싱 방식 |
| 목적 | 외부 전문 역량의 활용과 IT 서비스 비용·품질의 개선 |

## Ⅱ. 내부 운영과 구별되는 IT 아웃소싱의 특징

| 특징 | 의미 |
|---|---|
| 계약 기반 관리 | 지시가 아닌 계약·**SLA** 를 통한 공급자 성과 관리 |
| 책임의 비위임 | 업무 수행은 위탁해도 성과·보안·규제 책임은 발주 조직에 잔존 |
| 공급자 의존 | 위탁 기간이 길수록 공급자의 지식·자산에 대한 의존 증가 |
| 전환 비용 | 착수·종료 시 데이터·문서·지식 이전에 드는 비용과 위험 |

## Ⅲ. 아웃소싱 수명주기와 책임 체계

### 아웃소싱 수명주기

```text
소싱 전략 분석: 위탁 대상·목표 결정
    ↓
착수·선정: 요구사항·공급자·계약 확정
    ↓
전환: 서비스·인력·지식 인수
    ↓
가치 제공: SLA 기반 운영·성과 관리
    ↓
종료·재소싱: Exit Plan에 따른 이전
```

앞의 네 단계는 ISO 37500의 아웃소싱 수명주기 구분, 마지막 단계는 계약 종료 시의 이전 활동

### 가치 제공 확대: 발주 조직과 공급자의 성과 관리 흐름

```text
잔존조직: 서비스 목표·SLA·보안 요구 승인
    ↓
공급자: 서비스 운영과 측정 자료 보고
    ↓
잔존조직: SLA 대비 성과 검토
    ├─ 목표 충족 → 운영 지속
    └─ 목표 미달 → 개선 요구·계약상 조치
```

## Ⅳ. Make or Buy 판단과 공급 구조 비교

### Make or Buy 판단 기준

| 판단 기준 | 내부 수행이 유리한 조건 | 외부 위탁이 유리한 조건 |
|---|---|---|
| 전략 중요도 | 차별화·핵심 통제와 직결 | 표준화된 비핵심 서비스 |
| 내부 역량 | 보유 역량의 유지·강화 필요 | 전문 역량의 단기 확보 필요 |
| 위험·통제 | 데이터·보안·규제 통제의 직접 수행 필요 | 계약·감사로 통제 가능 |
| 경제성 | 내부 구축·유지 비용이 더 낮음 | 전체 수명주기 비용·품질이 더 유리 |

### 공급 구조

| 구조 | 운영 방식 | 적합한 조건 |
|---|---|---|
| 단일 공급자 | 한 공급자가 여러 서비스 담당 | 서비스 간 연계가 크고 관리 창구 단순화 필요 |
| 다중 공급자 | 서비스 영역별 공급자 분리 | 영역별 전문성과 공급자 경쟁 필요 |
| **SIAM** | 통합 기능이 복수 공급자 조정 | 공급자 수가 많고 서비스 간 연계 장애가 잦음 |

## Ⅴ. IT 아웃소싱의 한계와 방안

| 한계 | 방안 |
|---|---|
| 핵심 업무 위탁에 따른 통제력 약화 | 전략 중요도·통제 필요가 높은 업무는 내부 수행, 표준 서비스만 외부 위탁 |
| 단일 공급자 의존에 따른 교체 곤란 | 교체 가능성이 중요한 영역은 다중 공급자 구조와 계약상 **Exit Plan** 병행 |
| 다중 공급자 간 책임 경계의 공백 | 공급자 수와 연계 장애가 많으면 **SIAM** 으로 통합 책임 지정 |
| 발주 조직의 기술·계약 역량 약화 | **잔존조직(RO)** 의 아키텍처·보안·계약 관리 역할 유지 |
| 가동률 중심 SLA와 업무 품질의 차이 | SLA에 업무 결과 지표와 측정·보고 기준 연결 |

## Ⅵ. 제언

계약 단계에서 잔존조직이 데이터·문서 인도, 권한 회수, 지식 이전의 종료 조건을 확정해 공급자 교체 가능성 확보

### 공급자 교체 가능성 확보 구조

```text
공급자 교체 가능성 확보
    │
    ├─ 잔존조직 ── 종료 조건 승인과 인수 검증
    │
    ├─ 공급자 ── 구성정보·데이터·문서의 인도 의무
    │
    └─ 계약 ── Exit Plan·인수 기준·권한 회수 조항
```

### 잔존조직 확대: 종료·재소싱 이전 절차

```text
종료 통지와 Exit Plan 발동
    ↓
구성정보·데이터·문서 인수와 완전성 확인
    ↓
공급자 접근 권한 회수와 지식 이전
    ↓
신규 공급자 또는 내부 조직의 병행 운영 후 인수 완료
```

### 선택 근거: 운영 성과 중심 계약과의 비교

| 구분 | 운영 성과 중심 계약 | 제언: 교체 가능성 중심 계약 |
|---|---|---|
| 종료 조건 확정 시점 | 종료 통지 후 협의 | 계약 체결 시 |
| 데이터·문서 인도 | 공급자 협조에 의존 | 인도 대상·형식·기한의 계약 명시 |
| 인수 검증 주체 | 신규 공급자 | 잔존조직 |
| 교체 비용 파악 시점 | 교체 결정 이후 | 계약 단계 |

## 출제 이력과 검증 출처

- 제132~140회 공식 문제지에 IT 아웃소싱 단독 문항 없음
- ISO 37500:2014 Guidance on outsourcing
- ISO/IEC 20000-1:2018 Service management system requirements
