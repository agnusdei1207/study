## 연관 키워드

- 클라우드 전환 감리 (Cloud Migration Audit), 온프레미스 (On-Premise)
- IaaS(Infrastructure as a Service), PaaS(Platform as a Service), SaaS(Software as a Service)
- 7R 전략, TCO(Total Cost of Ownership), FinOps
- MSA(Microservice Architecture), VPC(Virtual Private Cloud), IAM(Identity and Access Management)
- RTO(Recovery Time Objective), RPO(Recovery Point Objective), DR(Disaster Recovery)
- CSAP(Cloud Service Security Assurance Program), IaC(Infrastructure as Code)
- Rightsizing, 절체(Cutover), SLA(Service Level Agreement)

## Ⅰ. 클라우드 전환 감리의 개요

- 핵심 요약 : 온프레미스 정보시스템을 클라우드로 옮기는 사업을 독립된 제3자 관점에서 단계별로 점검하는 전문 감리 활동.
- 개념 : 기존 **온프레미스** (On-Premise) 환경의 정보시스템을 **IaaS** (Infrastructure as a Service), **PaaS** (Platform as a Service), **SaaS** (Software as a Service) 등의 클라우드 환경으로 이전·전환하는 사업에 대해, 기획·설계·이관·시험·운영의 안정성을 발주자와 수행자로부터 독립된 감리인이 점검하는 활동(**클라우드 전환 감리**, Cloud Migration Audit).
- 배경 및 필요성 : 2025년 9월 대전 국가정보자원관리원 화재로 정부 정보시스템 96개가 전소되면서 공공 부문의 클라우드 전환과 재해복구 체계 점검이 중요해졌고, 2026년 3월 과학기술관계장관회의에서 행정·공공 정보시스템을 2030년까지 클라우드 기반으로 전환하는 방향이 확정되었다(정부 발표 기준). 대규모 이전이 진행될수록 설계 부실, 보안 취약점, 비용 증가, 서비스 중단을 사전에 통제할 필요가 커진다.
- 주요 목적 : 아키텍처 적합성 검증, 데이터 무결성 확보, **클라우드서비스 보안인증** (CSAP, Cloud Service Security Assurance Program) 준수 확인, 전환 후 성능과 비용의 최적화.

## Ⅱ. 클라우드 전환 감리의 특징 및 장점

- 핵심 요약 : 단계별 독립 검증과 클라우드 고유 통제 점검으로 전환 위험을 조기에 발견하고 운영 안정성을 높인다.

1. 독립 제3자 검증 : 발주자와 수행자에서 분리된 감리인이 증거를 직접 확인 → 판단의 객관성 확보.
2. 단계별 점검 : 기획, 설계, 이관, 시험, 운영 산출물을 이어서 확인 → 결함의 조기 발견.
3. 클라우드 네이티브 점검 : VPC, IAM, 컨테이너, IaC 설정을 검증 → 구성 오류와 보안 위험 감소.
4. 책임공유모델 적용 : CSP와 이용 기관의 통제 책임을 나누어 점검 → 감리 사각지대 축소.
5. 운영 지표 연계 : SLA, RTO·RPO와 비용 지표를 검증 → 전환 후 안정성과 효율성 확인.

## Ⅲ. 클라우드 전환 감리의 구조 (흐름)

- 핵심 요약 : 분석·기획에서 완료·운영까지 5단계로 이어지는 점검 흐름과 단계별 핵심 점검 항목.
- 클라우드 전환 감리는 단계마다 산출물을 확인하고 다음 단계로 넘긴다.

```text
[1. 분석·기획 단계]
  전환 대상 선별 타당성 (7R 전략)
  CSP 선정 기준, TCO·FinOps 산정
          ↓
[2. 설계 단계]
  MSA·컨테이너 설계, VPC 네트워크
  IAM 권한, RTO·RPO 기반 DR 설계
          ↓
[3. 이관·구현 단계]
  데이터 이관 도구 검증, 실시간 동기화
  소스코드 변환(PaaS화) 검증
          ↓
[4. 시험·전환 단계]
  대규모 부하 테스트 (성능)
  절체(Cutover) 리허설, 모의해킹·보안 진단
          ↓
[5. 완료·운영 단계]
  SLA 검증, 클라우드 운영 거버넌스
  비용 최적화 (Rightsizing) 확인
```

- **7R 전략** (Rehost, Replatform, Refactor 등 전환 유형을 선택하는 기준): 분석·기획 단계에서 대상 시스템별 전환 방식의 타당성을 점검하는 기준.
- **Rightsizing** (자원 규모를 실제 사용량에 맞추는 조정): 완료·운영 단계에서 과다 프로비저닝을 찾아내는 비용 최적화 확인 항목.

```text
[ 감리 점검 영역 ]
  인프라 ── VPC 분리, 스케일링 정책, IaC 코드
          ↓
  데이터베이스 ── 매니지드 DB 전환, 정합성
          ↓
  보안성 ── 책임공유모델, IAM 최소 권한, CSAP
          ↓
  성능·비용 ── 오토스케일링, FinOps 유휴 자원
```

## Ⅳ. 온프레미스 감리와 클라우드 전환 감리의 비교

- 핵심 요약 : 물리 인프라 중심의 기존 감리와 가상화·자동화 중심의 클라우드 전환 감리의 점검 대상이 달라진다.

| 점검 영역 | 전통적 온프레미스 감리 | 클라우드 전환 감리 |
| --- | --- | --- |
| 인프라 점검 | 물리 서버와 스토리지 사양, 랙 배치, 공조와 전력 | 가상 인스턴스 스케일링, VPC 네트워크 분리, IaC 코드 검증 |
| 데이터베이스 | 단일 대형 RDBMS 정규화와 백업 스케줄 | 매니지드 DB 전환 적합성, 분산 DB 정합성, 멀티 리전 복제 |
| 보안성 점검 | 물리적 망분리, 방화벽 장비 점검 | 책임공유모델, IAM 최소 권한, CSAP 준수 |
| 성능 및 비용 | 피크 타임 기준 하드웨어 증설 용량 산정 | 오토스케일링 동작 검증, FinOps 기반 유휴 자원 최적화 |

## Ⅴ. 클라우드 전환 감리의 한계와 방안

- 핵심 요약 : 점검 기준, 책임 경계, 비용 가시성의 부족을 검증 기준과 운영 증거로 보완한다.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| VPC·IAM·IaC 설정 위험 누락 | 물리 인프라 중심 기준으로 VPC, IAM, IaC의 설정 위험을 놓칠 수 있음 | 클라우드 네이티브 체크리스트와 실제 설정·코드 검증을 감리 기준에 반영 | 체크리스트 점검률, 설정 결함 건수 |
| 책임공유모델 경계 모호 | **책임공유모델** (Shared Responsibility Model)의 경계가 모호해 통제 공백 발생 | 서비스 모델별 책임 매트릭스를 확정하고, CSP 인증 자료와 이용 기관 설정을 각각 확인 | 책임 매트릭스 확정률 |
| 비용 가시성 부족 | 기능과 보안 위주 점검만으로는 과다 프로비저닝과 운영비 증가를 발견하기 어려움 | 자원 사용량, 오토스케일링, Rightsizing 지표를 운영 단계까지 추적 | Rightsizing 지표, 과다 프로비저닝 건수 |

## Ⅵ. 클라우드 전환 감리 고도화를 위한 기술사적 제언

- 핵심 요약 : 책임공유모델 기준으로 감리 범위를 명확히 하고, 벤더 종속을 점검하며, 보안 규제 준수를 실제 설정으로 확인하는 것이 핵심이다.

1. 책임공유모델 기준 감리 범위 확정 : CSP가 책임지는 하부 인프라와 이용 기관이 관리해야 하는 OS, 데이터, 애플리케이션 보안의 경계를 감리 계획 단계에서 나누어 감사 공백을 막는다.
2. 벤더 종속 방지와 이식성 점검 : 특정 CSP의 전용 서비스에 과도하게 묶이지 않도록, 컨테이너 기반 구조와 멀티 클라우드 이식 가능성을 설계 단계에서 확인한다.
3. 보안 규제 준수의 실측 : 개발·스테이징·운영 환경의 계정 분리, 관리자 콘솔의 MFA(Multi-Factor Authentication) 적용, 암호화 키 관리 서비스인 KMS(Key Management Service)의 저장·전송 암호화 적용 여부를 설정 자료로 전수 확인한다.

## Ⅶ. 결론

- 핵심 요약 : 클라우드 전환 감리는 5단계 점검 흐름과 클라우드 네이티브 기준으로 독립 제3자 검증을 수행하는 활동이다.
- 시사점 : 클라우드는 기술 전환이면서 통제 책임의 재배분이므로, 감리는 설계와 설정의 증거에 근거해 책임 경계와 비용을 함께 확인해야 한다.
