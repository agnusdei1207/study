## 한 줄 본질
- 온프레미스 시스템을 클라우드로 마이그레이션할 때 발생하는 보안 취약점, 아키텍처 비효율, 성능 저하, 예산 초과를 방지하기 위해 클라우드 네이티브 적합성, CSAP 규제, 데이터 무결성, 비용 최적화를 생애주기별로 독립 검증하는 전문 감리 활동 → 안정적 클라우드 안착 및 서비스 연속성 확보 / 레거시 종속성과 클라우드 CSP 종속(Lock-in) 간의 절충

## 핵심 용어
- 6R 마이그레이션 전략: 가트너와 AWS가 정의한 클라우드 전환 6가지 전략(Rehost 단순 이전, Replatform 플랫폼 최적화, Refactor 네이티브 재설계, Repurchase SaaS 구매, Retain 유지, Retire 폐기)
- CSAP(Cloud Security Assurance Program): 국가·공공기관에 안전성과 신뢰성이 검증된 민간 클라우드 서비스를 공급하기 위해 한국인터넷진흥원(KISA)이 운영하는 공공 클라우드 보안인증 제도
- 클라우드 공유 책임 모델(Shared Responsibility Model): 클라우드 인프라 자체의 보안(Security of the Cloud)은 CSP가 담당하고, 클라우드 내부 데이터·애플리케이션·IAM 보안(Security in the Cloud)은 이용 기관이 담당하는 책임 분계 체계

## 핵심 통찰
- 단순 Rehost(Lift-and-Shift)는 클라우드 실패의 지름길임 → 감리원은 사업자가 레거시 VM을 그대로 클라우드로 복사만 하고 있는지 점검해야 하며, 관리형 서비스(PaaS)나 컨테이너를 도입하지 않으면 온프레미스보다 비용이 2배 더 나옴
- IAM 권한 관리가 클라우드 보안 감리의 90%임 → 방화벽 IP가 아닌 IAM 계정 및 역할(Role)이 새로운 보안 경계선이므로, 루트 계정 사용 금지, MFA 강제, 임시 자격증명(STS) 사용 여부를 전수 점검해야 함
- 오토스케일링(Auto-scaling) 임계치는 부하 테스트로 증명되어야 함 → 설정만 해두고 실제 인스턴스 기동에 5분 이상 걸려 서비스가 먼저 뻗는 사례가 빈번하므로, 스케일아웃 기동 시간과 웜업(Warm-up) 풀 설계를 감리해야 함

## 이웃 토픽과 구분
- 클라우드 전환 감리 vs 시스템 개발 감리: 개발 감리 = 코드 품질, 화면 기능, 데이터베이스 정규화 검증 / 전환 감리 = 분산 인프라 아키텍처, 데이터 이행 정합성, 네트워크 지연, 클라우드 보안 및 비용 거버넌스 검증

## 문제·원인·대책
- 적용 상황: 공공 행정 포털 및 대민 서비스 민간 클라우드 이전 감리
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 클라우드 전환 후 월간 사용료가 예상 견적보다 300% 폭증 | 온프레미스 기준 오버스펙 프로비저닝 및 미사용 자원 방치 | 설계/구축 감리 단계에서 FinOps 라이트사이징(Right-sizing) 및 미사용 리소스 자동 종료 검증 | 클라우드 월 청구액 50% 절감 |
| 클라우드 스토리지(S3) 설정 오류로 대민 개인정보 인터넷 노출 | CSP 기본 보안 설정 간과 및 버킷 퍼블릭 오픈 방치 | 이행 단계 감리 시 클라우드 보안태세관리(CSPM) 도구를 통한 인프라 보안 취약점 전수 스캔 | 보안 컴플라이언스 100% 충족 |

## 이렇게 출제된다
- 제134회 4교시 5번: "클라우드 전환 사업의 단계별 감리 방법과 검토 항목에 대하여 설명하시오." → 요구 포인트: Ⅰ 전환 감리의 필요성 및 특징 + Ⅲ 기획-설계-이행-시험 4단계별 감리 프레임워크 + Ⅳ 단계별 핵심 검토항목(6R, CSAP, 데이터이행, 부하시험) 매트릭스
