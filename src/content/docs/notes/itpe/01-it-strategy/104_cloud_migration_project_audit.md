## 지식 로드맵 내 현재 위치

IT 전략·관리 → 정보시스템 감리 → **클라우드 전환사업 감리**

## 30초 인출

- 본질: 클라우드 전환사업 감리는 기존 시스템을 클라우드로 옮기는 사업의 계획·설계·이행 결과가 과업 요구에 맞는지 독립적으로 점검하는 감리
- 메커니즘: 요구정의·설계·종료 단계 감리 시점마다 전환 방식의 적합성, 클라우드 사업자와 기관의 책임 경계, 이관 데이터와 운영 준비를 점검
- 통찰: 사업자와 기관의 책임 경계가 빠지면 운영 공백이 생기므로 설계단계 감리의 공유책임 매트릭스 점검

<details>
<summary>핵심 용어</summary>

- **클라우드 전환사업 감리** : 기존 정보시스템의 클라우드 이전·재구축 사업을 감리기준의 단계별 시점에 따라 독립적으로 점검하는 감리
- **CSP(Cloud Service Provider)** : 컴퓨팅 자원과 서비스를 제공하는 클라우드 사업자
- **공유책임 모델(Shared Responsibility Model)** : 서비스 모델(IaaS·PaaS·SaaS)에 따라 CSP와 이용기관이 나누어 지는 보안·운영 책임의 구분
- **공유책임 매트릭스** : 통제 항목별로 CSP와 이용기관 중 수행 주체를 표로 지정한 책임 배정 산출물
- **CSAP(Cloud Security Assurance Program)** : 공공기관이 이용할 민간 클라우드 서비스의 보안 수준을 인증하는 클라우드 보안인증
- **Rehost·Replatform·Refactor** : 구조 변경 없이 이전, 일부 관리형 서비스로 교체, 클라우드 네이티브로 재설계하는 전환 방식
- **데이터 대사** : 원천 시스템과 목표 시스템의 데이터 건수·금액·무결성을 비교해 이관 누락·오류를 찾는 확인 작업

## 2~4교시 25점 답안

## Ⅰ. 클라우드 전환사업 감리의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **클라우드 전환사업 감리** 는 기존 시스템의 클라우드 이전·재구축 사업을 감리 시점별로 독립 점검하는 감리 |
| 목적 | 전환 방식 오류·책임 공백·이관 결함의 개통 전 발견 |

## Ⅱ. 구축 감리와 구별되는 클라우드 전환사업 감리의 특징

| 특징 | 의미 |
|---|---|
| 전환 방식별 점검 | 시스템별 전환 방식에 따라 검토할 증적 차별화 |
| 책임 경계 점검 | **CSP** 와 이용기관의 보안·운영 책임 구분의 설계 반영 여부 |
| 이관·운영 준비 점검 | 데이터 이관 결과와 관제·비용·복구의 운영 준비 확인 |

## Ⅲ. 감리 시점별 점검 체계

### 단계별 감리 방법과 검토 항목

```text
요구정의단계 ── 전환 대상 분류·전환 방식·보안 요건
    ↓
설계단계 ── 목표 구성·공유책임·복구·연계 설계
    ↓
종료단계 ── 데이터 대사·전환 리허설·운영 이관
```

감리 시점은 「정보시스템 감리기준」의 3단계 감리(요구정의·설계·종료)를 따르고, 클라우드 고유 항목은 각 시점의 검토 항목으로 추가

### 설계단계 확대: 책임 경계 검토 방법

```text
서비스 모델 확인 ── IaaS·PaaS·SaaS
    ↓
통제 항목별 수행 주체 지정 여부
    ↓
CSP 담당 항목 ── 계약·CSAP 인증 범위 대조
    ↓
기관 담당 항목 ── 설계서·운영 절차 반영 대조
    ↓
미지정·중복 항목의 개선 권고
```

## Ⅳ. 전환 방식별 감리 검토 초점의 비교

| 전환 방식 | 적합 조건 | 감리 검토 초점 |
|---|---|---|
| Rehost | 구조 변경 없이 빠른 이전 필요 | 호환성·성능 재현, 기존 결함의 그대로 이전 여부 |
| Replatform | 일부 구성요소만 관리형 서비스로 교체 | 교체 구성요소의 기능 호환과 운영 책임 이동 |
| Refactor | 확장성·배포 속도 개선이 핵심 요구 | 분산 구조 설계·운영 역량·전환 기간 위험 |
| 현행 유지·폐기 | 규제·기술 제약 또는 업무 종료 | 제외 사유와 연계 시스템 영향 |

## Ⅴ. 클라우드 전환사업 감리의 한계와 방안

| 한계 | 방안 |
|---|---|
| 요구와 무관한 일괄 Rehost로 기존 성능·구조 문제 이전 | 요구정의단계에서 시스템별 전환 방식 선택 근거 점검 |
| Refactor 대상의 운영 역량 미검토로 개통 후 장애 대응 곤란 | 설계단계에서 운영 조직의 역량·관제 설계 점검 |
| 서비스 모델별 책임 경계 미지정으로 보안 통제 공백 | 공유책임 매트릭스와 설계서·계약의 대조 |
| 이관 데이터 누락·불일치의 개통 후 발견 | 종료단계 전 **데이터 대사** 결과와 리허설 증적 확인 |
| 구축 완료 후 비용·관제 담당 부재 | 운영 이관 계획의 책임자·비용 관리 기준 점검 |

## Ⅵ. 제언

설계단계 감리에서 공유책임 매트릭스를 우선 점검 항목으로 지정하고 미지정 통제의 개통 전 해소 확인

### 공유책임 매트릭스 점검 구조

```text
공유책임 매트릭스
    │
    ├─ CSP 담당 ── 서비스 모델별 하위 계층(물리·가상화)
    │
    ├─ 이용기관 담당 ── 데이터·접근 권한·응용 설정
    │
    └─ 미지정·중복 항목 ── 감리 지적과 해소 대상
```

### 미지정 항목 확대: 해소 확인 절차

```text
설계단계 감리의 미지정 항목 지적
    ↓
수행 주체 지정과 설계서·계약 반영
    ↓
종료단계 감리의 반영 증적 확인
    ├─ 미반영 → 개통 전 보완 요구
    └─ 반영 → 운영 이관 계획 연결
```

### 선택 근거: 종료단계 일괄 확인과의 비교

| 구분 | 종료단계 일괄 확인 | 제언: 설계단계 우선 점검 |
|---|---|---|
| 책임 공백 발견 시점 | 구축 완료 후 | 설계 확정 전 |
| 보완 비용 | 재구성·계약 변경 | 설계서·계약 문구 수정 |
| 확인 근거 | 운영 결과 | 매트릭스와 설계서·계약 대조 |
