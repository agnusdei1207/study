## 지식 로드맵 내 현재 위치

IT 전략·관리 → 정보시스템 감리 → **클라우드 전환사업 감리**

## 30초 인출

- 본질: 클라우드 전환사업 감리는 운영 중인 정보시스템을 G-클라우드나 민간 클라우드로 옮기는 사업을, 발주자·사업자와 이해관계가 없는 감리법인이 과업 이행 관점에서 점검하는 활동
- 메커니즘: 단계감리(요구정의·설계·종료)가 사업자의 대비표로 과업 반영을 점검하고 시정조치를 확인하며, 전환사업 검토항목(전환계획 수립 및 준비·전환·서비스 안정화의 3단계 22개)이 점검 내용을 채움
- 통찰: 단계감리는 산출물 제출 시점에 열려 데이터 이관 실행 구간이 점검 밖에 놓이고 이관 실패에는 되돌릴 수단이 필요하므로, 위험도가 높은 전환은 상주감리를 추가해 이관 착수 전 보안성 검토 이행·SLA 확정·원상복구 방안을 확인

<details>
<summary>핵심 용어</summary>

- **클라우드 전환사업** : 국가기관이 구축·운영 중인 정보시스템을 G-클라우드 또는 민간 클라우드로 이관하는 사업
- **G-클라우드** : 정부가 국가기관에 제공하는 클라우드 인프라이며, 전환 시 애플리케이션 변경 없이 인프라 자원을 옮기는 것이 전제
- **민간 클라우드** : 민간 사업자가 제공하는 클라우드 서비스이며, 전환 대상이 인프라에서 애플리케이션까지 확대되는 서비스
- **CSP(Cloud Service Provider)** : 클라우드 서비스를 직접 제공하는 사업자
- **MSP(Managed Service Provider)** : CSP의 클라우드 서비스를 이용기관 대신 도입·운영·관리하는 사업자
- **SLA(Service Level Agreement)** : 서비스 수준의 지표와 목표를 정하고 미달 시 조치를 약정하는 서비스 수준 협약
- **보안성 검토** : 정보화사업의 보안대책이 적절한지 사업 계획 단계(사업 공고 전)에 평가하는 절차
- **nTOPS** : G-클라우드 전환 시 계정 발급·방화벽 포트 허용 등의 작업을 요청하는 통합운영관리시스템
- **정보시스템 감리** : 발주자·사업자의 이해관계로부터 독립된 자가 정보시스템의 구축·운영 사항을 종합적으로 점검하고 문제점을 개선하도록 하는 활동
- **3단계감리·2단계감리** : 요구정의·설계·종료 단계에서 실시하는 감리와, 그중 요구정의 단계를 생략한 감리
- **상주감리** : 사업 현장에 상주하거나 주기적으로 투입되는 감리원이 위험요소·산출물 검토와 자문을 수행하는 감리
- **대비표** : 사업자가 산출물이 계약상 과업내용을 세부항목별로 반영했는지 확인할 수 있게 작성해 발주자 확인 뒤 감리법인에 제출하는 표

## 2~4교시 25점 답안

## Ⅰ. 클라우드 전환사업 감리의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **클라우드 전환사업** 의 과업 이행을 제3자 관점에서 점검하고 문제점의 개선을 유도하는 **정보시스템 감리** |
| 목적 | 전환에 따른 업무 중단·데이터 훼손·보안 위험의 사전 식별과 시정 |

## Ⅱ. 이관 실행 구간의 공백이 생기는 클라우드 전환사업 감리의 특징

| 특징 | 의미 |
|---|---|
| 독립된 제3자 점검 | 발주자·사업자와 이해관계가 없는 감리법인이 수행하고 사업자는 감리 결과를 반영 |
| 단계감리 방식 | 요구정의·설계·종료 단계에서 산출물 제출 뒤 과업 반영 여부를 점검 |
| 세 가지 전환의 동시 진행 | 시스템뿐 아니라 데이터와 서비스 환경이 함께 바뀌는 전환 |
| 제공자 의존 | G-클라우드 기관 또는 민간 CSP·MSP의 일정과 협조에 맞춘 구축·테스트 |
| 사업 유형별 점검가이드 | 클라우드 계획수립·서비스 활용·전환 사업마다 별도 점검항목 |

## Ⅲ. 클라우드 전환사업의 단계별 감리 체계

### 3단계감리의 점검 시점과 대상

```text
요구정의 단계
    요구사항정의서가 계약문서의 과업내용을 반영했는가
        ↓
설계 단계
    설계 산출물이 과업내용을 반영했는가
    대비표가 세부 검사항목별 적합·부적합 판정이 가능한 수준인가
        ↓
    (데이터 이관·전환 실행 구간: 정해진 단계감리 점검 시점 사이)
        ↓
종료 단계
    검사 전 세부 검사항목별 과업 이행 여부를 적합·부적합으로 판정
```

### 한 단계의 감리 방법 확대: 대비표 기반 점검

```text
감리법인: 감리계획서 제출 (일정·인력·감리범위·점검항목)
    ↓
사업자: 대비표 작성 → 발주자 확인 → 감리법인 제출
    ↓
감리법인: 점검 → 감리수행결과보고서 제출
    ↓
사업자: 시정조치 수행 → 감리법인 제출
    ↓
감리법인: 시정조치 확인 → 시정조치확인보고서 제출
```

## Ⅳ. 클라우드 전환사업의 단계별 검토항목

| 단계 | 공통 검토항목 | G-클라우드 전환 고유 | 민간 클라우드 전환 고유 |
|---|---|---|---|
| 전환계획 수립 및 준비 | 전환 가능성, 이해관계자 요구·영향도, 시스템 구성·사용량, 구축·테스트 계획, 상용 SW·IP 변경 영향 | nTOPS 계정 신청, 방화벽 포트 허용 신청 | 전환방식·사업방식, 전환비용·이용료, 보안성 검토, SLA 작성, 발주방식·제공자 선정, 계약체결 |
| 전환 | AP 수정·SW 이관, 연계시스템 변경, 이용환경 구축, 보안 취약점 점검, 데이터 이관, 통합테스트 | 좌동 | 좌동 |
| 서비스 안정화 | 안정화를 위한 AP·상용 SW 기술지원 | 좌동 | 좌동 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 단계감리가 산출물 제출 시점에만 열려 생기는 데이터 이관 실행 구간의 점검 공백 | 위험도·난이도가 높은 전환은 단계감리에 상주감리를 추가해 사업 진행 중 위험요소 확인 |
| 사업비 20억원 미만 또는 사업기간 6개월 미만은 2단계감리로 요구정의 감리가 생략되어 발주자가 요구사항정의서의 과업 반영을 직접 점검 | 발주자가 전환계획 수립 및 준비 단계의 검토항목(전환방식·보안성 검토·SLA)을 점검표로 사용 |
| 서버·스토리지·데이터를 이용기관이 직접 관리하기 어려운 빌려 쓰는 서비스 | SLA에 서비스수준 지표·평가 방법을 계약으로 명시하고 서비스 종료 시 이용정보의 반환·파기 조건 확인 |

## Ⅵ. 제언

위험도가 높은 전환에 상주감리를 추가하고, 데이터 이관 착수 전 보안성 검토 이행·SLA 확정·원상복구 방안을 관문으로 확인

### 관문 배치

```text
설계 단계 감리
    ↓
상주감리(추가): 사업 진행 중 위험요소 사전 파악
    ↓
[관문] 이관 착수 전 확인
    ├─ 보안성 검토 이행
    ├─ SLA·계약 확정
    └─ 원상복구 방안·리허설
    ↓
데이터 이관 → 통합테스트
    ↓
종료 단계 감리
```

### 관문 확대: 이관 착수 판정

```text
보안성 검토를 이행했고 SLA가 확정됐는가
    ├─ 아니오 → 보완 뒤 재확인
    └─ 예
         ↓
전환 시나리오에 원상복구 방안이 있고 리허설·검증을 마쳤는가
    ├─ 아니오 → 보완 뒤 재확인
    └─ 예
         ↓
이관 전 완전백업 확인 → 데이터 이관 착수
```

| 구분 | 단계감리만 실시 | 제언: 상주감리 추가와 관문 확인 |
|---|---|---|
| 점검 시점 | 요구정의·설계·종료 단계 | 단계감리 사이의 이관 실행 구간 포함 |
| 원상복구 방안 | 이관 결과를 종료 단계에서 과업 이행 여부로 확인 | 이관 착수 전 시나리오·리허설로 확인 |
| 보안성 검토·SLA | 산출물 제출 시 서류 확인 | 이관 착수 전 이행·확정 여부 확인 |
