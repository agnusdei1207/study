## 지식 로드맵 내 현재 위치

IT 전략·관리 → 경영 정보시스템 → **PLM**

## 30초 인출

- 본질: PLM은 제품의 기획·설계·생산·서비스·폐기까지 제품 정의 데이터와 변경 이력을 한곳에서 관리하는 제품 생애주기 관리 체계
- 메커니즘: 승인된 설계 BOM(EBOM)을 변경 지시(ECO)로만 바꾸고, 이를 제조 BOM(MBOM)으로 전개해 ERP·MES에 배포
- 통찰: 설계 변경이 승인돼도 효력 시점이 없으면 현장이 구버전 BOM으로 생산하므로 ECO마다 효력 시점 지정과 ERP·MES 반영 확인

<details>
<summary>핵심 용어</summary>

- **PLM(Product Lifecycle Management)** : 제품의 기획·설계·생산·서비스·폐기 정보를 연결해 관리하는 제품 생애주기 관리 체계
- **BOM(Bill of Materials)** : 제품을 구성하는 부품의 목록·수량·조립 계층을 나타낸 자재명세서
- **EBOM(Engineering Bill of Materials)** : 설계 기능 관점으로 부품 구조를 정의한 설계 BOM
- **MBOM(Manufacturing Bill of Materials)** : 공정·조립 순서 관점으로 투입 자재를 정의한 제조 BOM
- **ECO(Engineering Change Order)** : 설계 변경의 영향·효력 시점을 검토·승인해 실행을 지시하는 변경 지시
- **효력 시점(Effectivity)** : 변경된 BOM이 적용되기 시작하는 날짜·제조번호·로트 기준
- **ERP(Enterprise Resource Planning)** : 구매·자재·원가·생산계획 등 전사 자원을 관리하는 시스템
- **MES(Manufacturing Execution System)** : 작업지시와 생산 현장 실적을 관리하는 시스템

</details>

## 2~4교시 25점 답안

## Ⅰ. PLM의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **PLM(Product Lifecycle Management)** 은 제품의 기획부터 폐기까지 제품 정의 데이터와 변경 이력을 연결해 관리하는 체계 |
| 목적 | 설계 변경 누락과 구버전 생산의 방지 |

## Ⅱ. 문서 관리와 구별되는 PLM의 특징

| 특징 | 의미 |
|---|---|
| 형상 기준선 관리 | 승인된 BOM·도면의 변경 지시 없는 수정 금지 |
| 생애주기 전 구간 연결 | 설계 데이터의 생산·서비스 단계까지 추적 |
| 구조 전개 | 같은 제품의 설계 구조와 제조 구조의 대응 관리 |
| 시스템 간 배포 | 제품 정의의 ERP 계획·MES 실행 전달 |

## Ⅲ. PLM 구성 체계와 설계 변경 프로세스

### PLM 제품 데이터 흐름 체계

```text
제품 요구·기획
    ↓
PLM ── 승인 EBOM·도면·ECO 이력
    ↓ MBOM 전개
ERP ── 자재 소요·구매·원가
    ↓ 작업지시
MES ── 공정 실행·실적·품질
    ↓
서비스 이력 → PLM 설계 개선에 반영
```

### ECO 확대: 설계 변경 처리 절차

```text
변경 요청 (결함·원가·고객 요구)
    ↓
영향 분석 ── 부품·재고·재공품·서비스 부품
    ↓
ECO 승인과 효력 시점 지정
    ↓
EBOM 개정 → MBOM 반영
    ↓
ERP·MES 배포와 현장 버전 확인
```

## Ⅳ. EBOM과 MBOM의 관점 비교

| 구분 | EBOM | MBOM |
|---|---|---|
| 관점 | 설계 기능 구조 | 공정·조립 순서 |
| 작성 주체 | 설계 부서 | 생산기술 부서 |
| 포함 항목 | 부품·모듈·형상 | 부품과 공정 투입 자재·반제품 |
| 사용 시스템 | PLM | PLM에서 전개해 ERP·MES 사용 |

## Ⅴ. PLM 적용의 한계와 방안

| 한계 | 방안 |
|---|---|
| EBOM 변경의 MBOM 반영 누락 | EBOM·MBOM 부품 대응표로 변경 시 미반영 항목 확인 |
| **효력 시점** 미지정으로 신·구 BOM 혼재 생산 | ECO 승인 시 날짜·로트 기준 효력 시점 필수 지정 |
| 부서별 품목 코드 중복 | 품목 식별 규칙과 품목 소유자의 확정 |
| PLM·ERP·MES 간 변경 반영 시차 | ECO 승인 시점의 배포와 시스템별 반영 확인 |

## Ⅵ. 제언

ECO 승인 시 효력 시점을 필수로 지정하고, 효력 시점 전까지 ERP·MES의 BOM 버전 반영을 확인해 확인 전에는 작업지시 보류

### ECO 효력 관리 구조

```text
ECO
    │
    ├─ 효력 시점 ── 날짜·로트·제조번호 기준
    │
    ├─ 영향 범위 ── 재고·재공품·서비스 부품 처리
    │
    └─ 반영 대상 ── MBOM·ERP 품목·MES 작업 기준
```

### 반영 대상 확대: 효력 시점 전 반영 확인

```text
효력 시점 도래 전 점검
    ↓
MBOM·ERP·MES의 BOM 버전 대조
    ├─ 불일치 → 해당 제품 작업지시 보류, 반영 보완
    └─ 일치 → 신규 BOM 기준 작업지시 발행
```

### 선택 근거: 승인 즉시 배포 방식과의 비교

| 구분 | 승인 즉시 배포 | 제언: 효력 시점 기반 반영 |
|---|---|---|
| 적용 시점 | 시스템마다 반영되는 시점 | 지정한 날짜·로트 |
| 재고·재공품 처리 | 사후 판단 | ECO 승인 시 사전 결정 |
| 구버전 생산 방지 | 현장 확인에 의존 | 버전 불일치 시 작업지시 보류 |
