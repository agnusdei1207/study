## 연관 키워드

- ERP (Enterprise Resource Planning, 전사적 자원관리), 전사적 자원관리
- MRP I (Material Requirements Planning), MRP II (Manufacturing Resource Planning)
- ERP II, Cloud ERP, 구축형 ERP (On-Premise), SaaS (Software as a Service)
- PI (Process Innovation), BPR (Business Process Reengineering), RTE (Real-Time Enterprise)
- CapEx (Capital Expenditure), OpEx (Operating Expenditure), Fit-to-Standard
- ETL (Extract, Transform, Load), OLTP (Online Transaction Processing), OLAP (Online Analytical Processing)

## Ⅰ. ERP의 개요

- 핵심 요약 : 전사 비즈니스 프로세스를 단일 통합 DB 기반으로 실시간 연계·관리하는 전사 시스템.
- 개념 : 생산, 구매, 영업, 회계, 인사 등 경영 활동 전반의 업무 프로세스를 하나의 통합 데이터베이스 위에서 실시간으로 연계·관리하는 **전사적 자원관리** (ERP, Enterprise Resource Planning) 시스템.
- 배경 및 필요성 : 부서별 개별 시스템에서 데이터가 중복·불일치하고 전사 경영 지표 파악이 늦어지는 문제를 해결하고, 표준 업무 프로세스를 내재화해 **실시간 경영** (RTE, Real-Time Enterprise)을 구현할 필요가 대두.
- 주요 목적 : 업무 프로세스의 표준화와 통합, 실시간 정보 공유에 따른 의사결정 신속화, 결산 주기 단축, 자원 낭비 최소화.

## Ⅱ. ERP의 특징 및 장점

- 핵심 요약 : 단일 통합 DB, 실시간 정보 공유, 표준 프로세스 내재화, 모듈형 구조가 데이터 정확성과 의사결정 속도로 이어지는 시스템.

1. 통합 데이터 : 부서별 기준정보를 하나로 연결 → 중복 입력과 데이터 불일치 감소.
2. 실시간 정보 공유 : 거래 발생이 전사 지표에 바로 반영 → 결산과 의사결정 속도 향상.
3. 표준 프로세스 : 공통 업무 규칙을 적용 → 지역과 부서 간 처리 차이 감소.
4. 모듈형 연계 : 재무·생산·구매·영업 정보를 잇는 구조 → 자원 흐름을 한눈에 파악.
5. **PI·BPR** 선행 : 패키지 도입 전 업무를 정비 → 불필요한 커스터마이징 감소.

## Ⅲ. ERP의 구조 (흐름)

- 핵심 요약 : MRP I에서 MRP II, ERP, ERP II, 클라우드 ERP로 이어지는 역사적 발전 흐름과 단일 DB 중심의 모듈 구조.
- **MRP I** (Material Requirements Planning, 자재소요계획) : 원자재와 부품의 소요량과 발주 시점 계산.
- **MRP II** (Manufacturing Resource Planning, 제조자원계획) : 자재뿐 아니라 설비, 자금, 인력 등 제조 자원 전반을 통합 관리.
- **ERP II** (확장형 ERP) : 공급망관리(**SCM**)와 고객관계관리(**CRM**), 제품수명주기관리(**PLM**) 등 외부 연계로 확장.
- **클라우드 ERP** (Cloud ERP) : 클라우드 **SaaS** 기반, 인메모리 DB, AI 기반 예측과 자동화를 결합.

```text
[ 1970년대 : MRP I ]
  자재 소요량과 발주 시점 계산
          ↓
[ 1980년대 : MRP II ]
  설비·자금·인력까지 제조 자원 통합
          ↓
[ 1990년대 : ERP ]
  회계·인사·영업·구매 전 영역 통합
          ↓
[ 2000년대 이후 : ERP II ]
  공급망과 고객 관계로 외부 연계 확장
          ↓
[ 현재 : 클라우드 ERP ]
  SaaS, 인메모리 DB, AI 기반 자동화
```

```text
[ ERP 모듈 구조 ]

재무 · 인사 · 생산 · 구매 · 영업
          ↓
[ 단일 통합 DB (Single Database) ]
```

## Ⅳ. 구축형 ERP와 클라우드 SaaS ERP의 비교

- 핵심 요약 : 자체 인프라와 대규모 커스터마이징에 기댄 구축형과 표준 프로세스·구독 기반의 클라우드 SaaS형을 대비.

| 비교 항목 | 구축형 ERP (On-Premise) | 클라우드 SaaS ERP |
| --- | --- | --- |
| 인프라와 배포 | 사내 전산실 서버를 직접 구축·운영 | **CSP** (Cloud Service Provider) 인프라 위의 멀티 테넌트 서비스 |
| 커스터마이징 | 고유 프로세스에 맞춘 소스 수정이 많음 | 표준 베스트 프랙티스 준수, **API** (Application Programming Interface) 기반 확장 |
| 업그레이드 | 대규모 비용과 긴 프로젝트 기간 필요 | 벤더가 정기적으로 무중단 업그레이드 |
| 비용 구조 | 초기 **CapEx** (Capital Expenditure) 투자와 유지보수료 | 구독 기반 **OpEx** (Operating Expenditure) 지출 |

## Ⅴ. ERP의 한계와 방안

- 핵심 요약 : 과도한 커스터마이징, 기준정보 이관 오류, 불명확한 투자 효과를 표준 적합성과 모의 이행, 성과 지표로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 과도한 커스터마이징 | 고유 방식 수정이 누적되어 업그레이드가 어려워짐 | **Fit-to-Standard** (표준 프로세스에 맞추는 원칙)을 우선하고 확장은 코어 밖에서 구현 | 커스터마이징 건수 |
| 부정확한 기준정보 이관 | 중복·불일치 데이터가 결산과 재고 오류를 유발 | 데이터 정제와 반복 모의 이행, 대사 수행 | 데이터 정합률 |
| 불명확한 투자 효과 | 구축비 대비 성과를 측정하지 않아 **ROI** 판단이 어려움 | 결산 소요 기간과 재고 정확도 등 도입 전후 지표 측정 | 결산 소요 기간 |

## Ⅵ. ERP 구축 및 고도화에 대한 기술사적 제언

- 핵심 요약 : 업무 표준 선행, 2계층 구조, 인메모리 실시간 분석을 결합해 ERP를 실시간 경영의 기반으로 확립.

1. 업무 표준 선행 : 고유 업무 방식을 고집하지 않고 **PI**와 **BPR**로 표준 프로세스에 업무를 먼저 맞춰 커스터마이징을 줄인다.
2. 투-티어 ERP (Two-Tier ERP) : 본사는 대형 ERP로 전사 재무 통제를 맡고, 해외 법인이나 자회사는 클라우드 ERP로 유연성을 확보한다.
3. 인메모리 실시간 분석 : **OLTP** (Online Transaction Processing)와 **OLAP** (Online Analytical Processing)를 한 DB에서 처리해 데이터 복제 과정인 **ETL** (Extract, Transform, Load)을 줄이고 실시간 결산을 지원한다.

## Ⅶ. 결론

- 핵심 요약 : ERP는 경영 활동 전반을 단일 통합 DB로 실시간 연계하는 전사적 자원관리 시스템.
- 시사점 : Fit-to-Standard 원칙과 데이터 정제, 성과 측정을 함께 갖춰야 구축 효과와 업그레이드 지속성이 확보됨.
