## 연관 키워드

- ERP (Enterprise Resource Planning, 전사적 자원관리)
- MRP I (Material Requirements Planning, 자재소요계획), MRP II (Manufacturing Resource Planning, 제조자원계획)
- ERP II (확장형 ERP), Cloud ERP (클라우드 ERP)
- On-Premise (구축형), SaaS (Software as a Service)
- RTE (Real-Time Enterprise, 실시간 경영), BPR (Business Process Reengineering)
- PI (Process Innovation), CapEx (Capital Expenditure), OpEx (Operating Expenditure)
- BTP (Business Technology Platform), ETL (Extract, Transform, Load)
- OLTP (Online Transaction Processing), OLAP (Online Analytical Processing)
- CBO (Custom Business Object), Fit-to-Standard

## Ⅰ. ERP의 개요

- 핵심 요약 : 전사 비즈니스 프로세스를 단일 통합 DB 기반으로 실시간 연계·관리하는 전사적 자원관리 시스템.
- 개념 : 기업의 생산, 구매, 영업, 회계, 인사 등 경영 활동 전반의 비즈니스 프로세스를 단일의 통합된 데이터베이스를 기반으로 실시간 연계·관리하여 전사적 자원 활용을 최적화하는 전사적 자원관리 시스템 (ERP, Enterprise Resource Planning).
- 배경 및 필요성 : 부서별 개별 시스템 운영으로 인한 데이터 중복 및 불일치, 전사 경영 지표 파악의 지연을 극복하고, 글로벌 베스트 프랙티스 프로세스를 내재화하여 실시간 경영 (RTE, Real-Time Enterprise)을 구현할 필요성 대두.
- 주요 목적 : 전사 업무 프로세스 표준화 및 통합, 실시간 정보 공유를 통한 의사결정 신속화, 결산 주기 단축, 자원 낭비 최소화.

## Ⅱ. ERP의 특징

- 핵심 요약 : 단일 통합 DB, 실시간 정보 공유, 베스트 프랙티스 내재화, 모듈형 구조를 특징으로 하는 전사 시스템.
1. 단일 통합 데이터베이스 (Single DB) : 전사 프로세스 데이터의 일관성 확보.
2. 실시간 정보 공유 (RTE) : 의사결정 신속화 및 결산 주기 단축.
3. 베스트 프랙티스 내재화 : 글로벌 표준 프로세스 적용.
4. 모듈형 구조 : 재무·인사·생산·구매·영업 등 기능별 모듈 연계.
5. BPR (Business Process Reengineering) / PI (Process Innovation) 선행 : 구축 전 업무 프로세스 재설계.
6. 확장성 (ERP II) : SCM(Supply Chain Management), CRM(Customer Relationship Management), PLM(Product Lifecycle Management) 등 외부 연계.

## Ⅲ. ERP의 구조 (흐름)

- 핵심 요약 : MRP I→MRP II→ERP→ERP II→Cloud ERP로 이어지는 역사적 발전 흐름.
- ERP 역사적 발전 과정 및 모듈 구조.

```text
[ 1970년대 : MRP I (자재소요계획) ]
   Material Requirements Planning
          ↓
[ 1980년대 : MRP II (제조자원계획) ]
   Manufacturing Resource Planning
          ↓
[ 1990년대 : ERP (전사적자원관리) ]
   회계·인사·영업·구매 전 영역 통합 DB화
          ↓
[ 2000년대 이후 : 확장형 ERP (ERP II) ]
          ↓
[ 현재 : 지능형 클라우드 ERP (Cloud ERP) ]
   클라우드 SaaS, 인메모리 DB, AI 기반 예측/자동화
```

```text
[ ERP 핵심 모듈 구조 ]
재무(FI) ↔ 인사(HR) ↔ 생산(PP) ↔ 구매(MM) ↔ 영업(SD)
            │
            └── 단일 통합 DB (Single Database)
```

- **MRP I** (자재소요계획) : 원자재 및 부품의 소요량과 발주 시점 계산.
- **MRP II** (제조자원계획) : 자재뿐 아니라 설비, 자금, 인력 등 제조 전반의 자원 통합 관리.
- **ERP II** (확장형 ERP) : SCM, CRM, PLM 등 외부 공급망 및 고객 관계와의 연계 확장.
- **Cloud ERP** : 클라우드 SaaS, 인메모리 DB(SAP S/4HANA), AI(Artificial Intelligence) 기반 예측/자동화.

## Ⅳ. 구축형 ERP와 클라우드 SaaS ERP의 비교

- 핵심 요약 : 자체 인프라·커스터마이징의 구축형과 표준·구독·자동 업그레이드의 클라우드 대비.
- 구축형과 클라우드 ERP의 대비 구조.

```text
[ 구축형 ERP ] 사내 서버 · CapEx · 과도한 커스터마이징
        ↕
[ 클라우드 SaaS ERP ] CSP 인프라 · OpEx · 표준 프로세스
```

| 비교 항목 | 구축형 ERP (On-Premise) | 클라우드 SaaS ERP |
|---|---|---|
| 인프라 및 배포 | 사내 전산실 서버 구축, 자체 운영 | CSP(Cloud Service Provider) 클라우드 인프라, 멀티 테넌트 SaaS 서비스 |
| 커스터마이징 | 기업 고유 프로세스에 맞춘 방대한 소스코드 수정 | 표준 베스트 프랙티스 준수, API(Application Programming Interface) 기반 확장 |
| 업그레이드 | 대규모 비용과 수개월의 프로젝트 소요 | 벤더의 정기적 자동 무중단 업그레이드 |
| 비용 구조 | 초기 대규모 CapEx(Capital Expenditure) 투자 + 연간 유지보수료 | 월/연 단위 OpEx(Operating Expenditure) 구독료 (사용자/트랜잭션 기반) |

## Ⅴ. ERP의 장점과 한계

- 핵심 요약 : 프로세스 표준화·실시간 의사결정의 장점, 과도한 커스터마이징·데이터 이행·ROI 불투명의 한계.
- 장점
  1. 전사 업무 프로세스 표준화 및 통합.
  2. 실시간 정보 공유를 통한 의사결정 신속화.
  3. 결산 주기 단축 및 자원 낭비 최소화.
  4. 글로벌 베스트 프랙티스 내재화.
- 한계점 1 : 과도한 커스터마이징(CBO)으로 인한 업그레이드 단절
  - 한계점 : 기업 고유의 관행적 업무 방식을 수용하기 위해 패키지 표준을 과도하게 수정하여 향후 클라우드 버전 업그레이드 불가.
  - 해결 방안 : 표준 프로세스(Fit-to-Standard) 원칙 엄수, BTP(Business Technology Platform) 등 코어 외곽 개발(Side-by-Side Extensibility) 적용.
- 한계점 2 : 현업 부서의 데이터 이행(Data Migration) 오류
  - 한계점 : 레거시 시스템의 부정확한 기준정보(Master Data)가 정제 없이 이관되어 시스템 오픈 초기 결산 마비 및 데이터 불일치 발생.
  - 해결 방안 : 데이터 프로파일링 기반 정제 작업 선행, 다회차 모의 데이터 이행(Mock Migration) 검증 의무화.
- 한계점 3 : 막대한 도입 비용 대비 실질 비즈니스 ROI(Return on Investment) 불투명
  - 한계점 : 수백억 원의 구축비가 소요되나 단순 업무 전산화에 그치고 경영 의사결정 속도 개선 효과 미흡.
  - 해결 방안 : 구축 후 실시간 데이터 분석(Embedded Analytics) 연계, 비즈니스 프로세스 자동화(RPA(Robotic Process Automation)/AI)와 결합한 성과 가시화.

## Ⅵ. ERP 구축 및 고도화에 대한 기술사적 제언

- 핵심 요약 : PI·BPR 선행, 투-티어 ERP, 인메모리 실시간 분석 확립.
- 과도한 커스터마이징 지양 및 BPR·PI 선행 : 고유 업무 방식 고집으로 인한 과도한 커스터마이징은 향후 업그레이드 불가와 시스템 부실을 초래하므로, ERP 표준 프로세스에 업무를 맞추는 PI·BPR 선행.
- 투-티어 ERP(Two-Tier ERP) 전략 도입 : 본사는 전사 거버넌스와 재무 통제를 위해 대형 글로벌 ERP(Tier 1)를 운영하고, 해외 법인이나 자회사는 유연하고 경제적인 클라우드 ERP(Tier 2)를 적용하는 유연한 아키텍처.
- 인메모리 컴퓨팅 및 실시간 분석(Embedded Analytics) : 데이터 복제(ETL) 없이 트랜잭션 처리(OLTP)와 실시간 다차원 분석(OLAP)을 단일 DB에서 처리하는 인메모리 아키텍처를 도입하여 초고속 실시간 결산 실현.

## Ⅶ. 결론

- 핵심 요약 : ERP는 전사 프로세스 통합과 실시간 경영을 위한 핵심 인프라로 PI·데이터 이행·ROI 관리가 성공 요인.
- 요약 : ERP는 기업 경영 활동 전반을 단일 통합 DB 기반으로 실시간 연계·관리하는 전사적 자원관리 시스템.
- 시사점 : Fit-to-Standard 원칙, 데이터 정제·모의 이행, Embedded Analytics 연계를 통해 구축 효과와 업그레이드 지속성 확보 필요.
