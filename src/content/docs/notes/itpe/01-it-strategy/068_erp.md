## 지식 로드맵 내 현재 위치

IT 전략·관리 → 경영 정보시스템 → **ERP(Enterprise Resource Planning)**

## 30초 인출

- 본질: ERP는 재무·구매·생산·영업·인사 업무를 하나의 공통 데이터와 통합 모듈로 처리하는 전사 자원관리 시스템
- 메커니즘: 품목·거래처·계정 기준정보를 공유하고, 주문·구매·생산 거래가 발생하는 즉시 재고·원가·회계에 자동 반영
- 통찰: 기준정보가 어긋나면 한 번의 입력 오류가 재고·원가·회계로 동시에 퍼지므로 오픈 전 대표 거래의 끝단 회계 반영까지의 대사

<details>
<summary>핵심 용어</summary>

- **ERP(Enterprise Resource Planning)** : 전사 업무의 거래와 자원계획을 공통 데이터와 통합 모듈로 처리하는 정보시스템
- **기준정보(Master Data)** : 품목·거래처·계정처럼 여러 거래가 공통으로 참조하는 기본 데이터
- **MRP(Material Requirements Planning)** : 생산계획과 BOM으로 자재 필요량과 조달 시점을 계산하는 계획 기능
- **BOM(Bill of Materials)** : 제품을 구성하는 부품과 수량·구조를 나타낸 자재명세서
- **O2C(Order to Cash)** : 고객 주문부터 출하·청구·수금까지 이어지는 판매 거래 흐름
- **P2P(Procure to Pay)** : 구매 요청부터 발주·입고·대금 지급까지 이어지는 구매 거래 흐름
- **Fit-Gap 분석** : 패키지 표준 기능과 현행 업무 요구의 적합·차이를 판정하는 분석
- **Clean Core** : ERP 표준 코어의 직접 수정을 피하고 확장 기능을 분리해 업그레이드를 쉽게 하는 접근

## 2~4교시 25점 답안

## Ⅰ. ERP의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **ERP(Enterprise Resource Planning)** 는 전사 업무의 거래와 자원계획을 공통 데이터와 통합 모듈로 처리하는 정보시스템 |
| 목적 | 부서 간 중복 입력 제거와 경영 실적의 적시 파악 |

## Ⅱ. 부서별 개별 시스템과 구별되는 ERP의 특징

| 특징 | 의미 |
|---|---|
| 단일 기준정보 | 품목·거래처·계정의 전사 공통 정의 |
| 거래의 실시간 통합 | 물류 거래 발생 즉시 재고·원가·회계 반영 |
| 표준 프로세스 내장 | 패키지에 담긴 업무 절차의 적용 |
| 모듈 간 연계 | 판매·구매·생산·재무 모듈의 같은 원장 공유 |

## Ⅲ. ERP 구성 체계와 거래 반영 흐름

### ERP 모듈 구성 체계

```text
ERP 공통 기준정보 ── 품목·거래처·계정·조직
    │
    ├─ 판매·물류 모듈 ── 주문·출하·청구
    ├─ 구매·자재 모듈 ── 발주·입고·재고
    ├─ 생산 모듈 ── MRP·작업지시·실적
    ├─ 재무·관리회계 모듈 ── 원장·원가·결산
    └─ 인사 모듈 ── 인력·급여
```

### 거래 반영 확대: O2C·P2P의 회계 반영 흐름

```text
O2C: 판매 주문 → 출하 → 재고 감소
    ↓
매출·매출채권 전표 자동 생성

P2P: 구매 요청 → 발주 → 입고 → 재고 증가
    ↓
매입채무 전표 자동 생성

두 전표 → 재무 원장·원가 자동 집계
```

## Ⅳ. ERP 구축 방식의 비교

| 구분 | 표준 적용(Fit to Standard) | 맞춤 개발(Customization) | 코어 외부 확장(Clean Core) |
|---|---|---|---|
| 업무 절차 | 패키지 표준에 업무를 맞춤 | 현행 업무에 패키지를 맞춤 | 표준 코어 유지, 차별 기능만 외부 개발 |
| 도입 기간 | 짧음 | 길어짐 | 중간 |
| 업그레이드 부담 | 낮음 | 높음 | 낮음 |
| 적합 조건 | 업계 공통 업무 | 법규·경쟁력상 고유 업무 | 고유 업무가 일부인 경우 |

## Ⅴ. ERP 도입의 한계와 방안

| 한계 | 방안 |
|---|---|
| 현행 업무를 그대로 옮기려는 과도한 맞춤 개발 | **Fit-Gap 분석** 후 공통 업무는 표준 적용, 고유 업무만 코어 외부 확장 |
| 부서별 품목·거래처 코드 불일치 | **기준정보** 소유자와 코드 부여 규칙의 전사 확정 |
| 한 입력 오류의 재고·원가·회계 동시 전파 | 오픈 전 대표 O2C·P2P 거래의 회계 반영 대사 |
| 표준 절차와 기존 업무 방식의 충돌 | 프로세스 책임자 지정과 BPR 병행 |

## Ⅵ. 제언

오픈 전 대표 O2C·P2P 거래를 주문부터 회계 전표까지 수행해 기준정보와 재고·원가·회계 반영을 대사하고, 차이가 남은 거래의 오픈 보류

### 오픈 전 대사 대상 구조

```text
대표 거래 대사
    │
    ├─ 기준정보 ── 품목·거래처·계정 코드 일치
    │
    ├─ 물류 결과 ── 재고 수량·위치 반영
    │
    └─ 회계 결과 ── 전표·원가·채권채무 반영
```

### 회계 결과 확대: 오픈 판정 절차

```text
대표 O2C·P2P 거래 끝단까지 수행
    ↓
예상 전표·원가와 실제 결과 대조
    ├─ 차이 발생 → 원인 거래·기준정보 수정 후 재수행
    └─ 차이 없음 → 해당 거래 유형 오픈 승인
```

### 선택 근거: 모듈별 단위 시험과의 비교

| 구분 | 모듈별 단위 시험 | 제언: 끝단 대사 시험 |
|---|---|---|
| 시험 범위 | 모듈 기능 단위 | 주문부터 회계 전표까지 |
| 발견 오류 | 화면·기능 오류 | 모듈 간 반영 누락·기준정보 불일치 |
| 오픈 판단 근거 | 기능 시험 통과율 | 거래 유형별 회계 결과 일치 |
