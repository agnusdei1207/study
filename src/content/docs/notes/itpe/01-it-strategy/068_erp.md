## 30초 인출

- 본질: 재무·인사·구매·생산·영업을 공통 데이터와 표준 프로세스로 통합하는 전사 자원관리 시스템
- 메커니즘: 수요·주문 접수 → 자재(MRP)·생산·인력 통합계획 → 업무 실행(구매·생산·출하) → 회계·원가 자동 반영
- 판정 기준: 기준정보(MDM) 불일치율 <= 1% 및 O2C/P2P 트랜잭션 전표 100% 대사 일치

<details>
<summary>핵심 용어</summary>

- ERP(Enterprise Resource Planning): 공통 데이터로 전사 업무를 연결함 → 부서별 최적화보다 전사 프로세스 정합성이 우선임
- MRP(Material Requirements Planning): 생산계획을 품목별 소요량·시점으로 전개함 → 정확한 품목구성·재고가 전제임
- Single Source of Truth: 같은 거래를 하나의 신뢰 원천에서 공유함 → 기준정보와 입력 통제가 무너지면 오류도 전사로 확산됨

</details>

## 예상문제

> 가치사슬 관점에서 ERP·SCM·MES·CRM을 비교하고, ERP 도입 위험과 대응책을 설명하시오. **(미출제 예상·25점)**

## Ⅰ. 전사 프로세스·데이터 통합 시스템, ERP

> ERP는 공통 데이터베이스를 중심으로 핵심 업무를 연결하며, 도입 성패는 기능 수보다 표준 프로세스와 기준정보의 정합성으로 판정함.

- 정의: 재무·인사·구매·생산·영업의 거래와 자원계획을 **공통 데이터베이스**와 **통합 모듈**로 처리하는 전사 정보시스템
- 목적: 부서 간 중복 입력 제거 · 전사 자원 배분 · 경영실적 적시 파악
- 특징: **프로세스 통합** · **기준정보 공유** · 모듈 간 거래정보 연계

## Ⅱ. 계획에서 실적 반영까지 이어지는 ERP 동작 구조

> ERP는 판매·재고 정보를 자원계획으로 바꾸고 실행 거래를 재무·원가 실적으로 되돌리며, 계획과 실적의 폐루프가 끊기면 통합 효과가 사라짐.

```mermaid
flowchart TD
    S1["① 수요·기준정보<br/>주문·재고·BOM·거래처 정합성 확인<br/>(산출: 판매계획 · Master Data)"]
    S2["② 통합 자원계획<br/>MRP 전개 · 생산능력 · 인력 · 자금 소요 동기화<br/>(산출: 구매요청 · 생산계획 · 자금계획)"]
    S3["③ 업무 실행<br/>발주 · 입고 · 생산실적 · 출하 · 수금 처리<br/>(산출: 재고수불부 · 거래전표)"]
    S4["④ 회계·성과 환류<br/>실시간 원가반영 · 채권채무 결산 · 경영 KPI<br/>(산출: 재무제표 · 손익계산서)"]

    S1 --> S2 --> S3 --> S4
```

## Ⅲ. 가치사슬 관점의 ERP·SCM·MES·CRM 비교

> 네 시스템은 경쟁 관계가 아니라 공급망·전사 자원·생산현장·고객 접점을 맡는 보완 관계이며, 경계는 관리 대상과 의사결정 시간범위로 구분함.

```mermaid
flowchart TD
    subgraph SCM["SCM (공급망)"]
        direction TB
        SC1["협력사 공급망 · 수요/공급 계획 · 조달/물류"]
    end

    subgraph ERP["ERP (전사적 자원관리 - Single Source of Truth)"]
        direction TB
        E1["자재소요계획(MRP) · 생산/재무/인사/회계 통합"]
        E2["기준정보 관리(MDM): 품목(BOM), 거래처, 계정"]
        E3["실시간 원가결산 및 경영진 대시보드"]
    end

    subgraph CRM["CRM (고객관계)"]
        direction TB
        CR1["고객접점 · 영업기회 파이프라인 · 마케팅/CS"]
    end

    subgraph MES["MES (제조실행)"]
        direction TB
        M1["공정/설비/품질 제어 · 실시간 작업실적/불량률 회신"]
    end

    SCM -->|자재조달/납기| ERP
    CRM -->|수요/주문정보| ERP
    ERP -->|작업지시| MES
    MES -->|공정실적/수불| ERP
```

| 구분 | ERP | SCM | MES | CRM |
|---|---|---|---|---|
| 대상 | 전사 자원·거래 | 공급자~고객 물류·정보·자금 | 생산현장 작업·설비·품질 | 잠재·기존 고객 접점 |
| 역할 | 계획·실행·회계 통합 | 수요·공급·조달·물류 조정 | 작업지시 실행·실적 수집 | 마케팅·영업·서비스 관계 관리 |
| 시간범위 | 계획~결산 | 중장기 계획~주문이행 | 실시간 현장 실행 | 고객 생애주기 |

- 연계: SCM 수요·공급계획 → ERP 자원·거래계획 → MES 작업지시·실적 → ERP 원가·재고 반영
- 연계: CRM 수요·주문·서비스 정보 ↔ ERP 판매·출하·청구 정보

## Ⅳ. 문제점·대응책

> 기존 업무를 그대로 맞춤 개발하면 통합 기준이 다시 분열되므로, 프로세스 표준화와 데이터 통제를 먼저 확정한 뒤 예외만 제한적으로 확장해야 함.

| 위험 | 대책 | 효과 |
|---|---|---|
| 부서별 프로세스 충돌 | **BPR(Business Process Reengineering)** · 프로세스 책임자 지정 | 전사 업무 흐름 일관성 |
| 기준정보 불일치 | **MDM(Master Data Management)** · 데이터 소유자·검증 규칙 운영 | 계획·회계 오류 전파 차단 |
| 과도한 맞춤 개발 | **Fit-Gap 분석** · 표준 기능 우선·예외 승인 | 업그레이드 복잡도 감소 |

## Ⅴ. 표준 프로세스·데이터 품질 중심 도입

> ERP의 가치는 패키지 설치가 아니라 계획·실행·회계가 같은 데이터 의미를 공유할 때 발생하므로, 오픈 판정도 기능 완료보다 업무·데이터 통합 검증에 둬야 함.

### 학습자 통찰 메모 — 답안 밖

- [핵심 통찰]: ERP는 모든 주변 시스템을 대체하는 거대 시스템이 아니다. 전사 거래와 자원계획의 기준축을 맡고 SCM·MES·CRM의 전문 기능과 경계를 분명히 할 때 데이터 중복이 줄어든다.
- 나라면: 핵심 가치사슬 한 구간을 먼저 선정해 표준 프로세스와 기준정보를 정제하고, 계획부터 회계 반영까지 대사한 뒤 단계적으로 범위를 넓히겠다.

### 실전 답안용 기술사적 제언

- **판정 기준 (Trigger)**: 기준정보(MDM) 중복·불일치율 > 3% 또는 Fit-Gap 분석 시 커스터마이징(Customizing) 비율이 20%를 초과할 시 프로젝트 위험 판정.
- **대응 방안 (Action)**: 글로벌 표준 프로세스(Best Practice) 수용을 원칙으로 BPR을 선행하고, 예외 개발은 비즈니스 차별화 영역에 한해 아키텍처 위원회 승인을 의무화함.
- **검증 체계 (Verification)**: 주문(Order)부터 결산(Close)까지 전 구간(O2C, P2P) 트랜잭션 수량·단가·전표의 100% 대사 검증(End-to-End Reconciliation)을 통과해야 오픈 승인.
- **기대 효과 (Impact)**: 결산 주기 단축(월 10일 → 3일 이내), 재고 회전율 30% 개선, ERP 업그레이드 및 클라우드(SaaS) 전환 비용의 획기적 절감을 달성함.

```mermaid
flowchart TD
    P1["현행 한계<br/>부서별 데이터 사일로 · 과도한 맞춤개발(Customizing) · 결산 지연"] --> P2["개선 대안<br/>BPR 기반 표준 프로세스 수용 · MDM 기준정보 정제 · O2C/P2P 전수 대사"]
    P2 --> P3{"검증 판정<br/>MDM 불일치율 <= 1% & 커스터마이징 비율 <= 20%?"}
    P3 -->|달성| P4["실행 효과<br/>결산 주기 단축(월 3일 이내) · 재고회전율 30% 개선 · 클라우드 SaaS 전환"]
    P3 -->|미달| P5["보완 조치<br/>아키텍처 위원회(ARB) 소집 및 예외개발 기능 표준 롤백"]
```

## 1교시 10점 답안 발췌

### 1. 정의·목적

- 정의: **ERP(Enterprise Resource Planning)**는 재무·인사·구매·생산·영업의 거래와 자원계획을 공통 데이터베이스와 통합 모듈로 처리하는 전사 정보시스템
- 목적: 부서 간 중복 입력 제거 · 전사 자원 배분 · 경영실적 적시 파악

### 2. 가치사슬 연계 아키텍처

### 3. 핵심 통제

- 연계: **SCM(Supply Chain Management)** 수요계획 → ERP 자원계획 → **MES(Manufacturing Execution System)** 실행실적 → ERP 원가·재고 반영
- 판단: **CRM(Customer Relationship Management)**의 고객 정보까지 연계하되 시스템별 책임과 기준정보 소유권 분리
