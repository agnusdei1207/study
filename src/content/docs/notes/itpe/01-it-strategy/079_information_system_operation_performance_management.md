## 연관 키워드

- 정보시스템 운영 성과관리 (Information System Operation Performance Management)
- 비용 효율성 (Cost Efficiency), 업무 기여도 (Business Contribution)
- 2x2 매트릭스 (유지·고도화 / 활성화·재검토 / 통폐합·폐기 / 개선·효율화)
- MAU (Monthly Active Users, 월간 활성 사용자 수)
- MTBF (Mean Time Between Failures, 평균 장애 간격)
- MTTR (Mean Time to Repair, 평균 수리 시간)
- APM (Application Performance Monitoring)
- ITAM (IT Asset Management, IT 자산 관리)
- 레거시 (Legacy), 시스템 통폐합 (Consolidation)
- 클라우드 네이티브 (Cloud Native), 행정안전부 성과관리 지침

## Ⅰ. 정보시스템 운영 성과관리의 개요

- 핵심 요약 : 가동 중인 정보시스템의 운영 비용 대비 업무 기여도·이용도·서비스 품질을 종합 측정·평가하여 유지·고도화·통폐합·폐기를 결정하는 사후 성과관리 체계.
- 개념 : 가동 중인 공공 및 기업의 정보시스템에 대해 투입된 운영 비용 대비 업무 기여도, 이용도, 서비스 품질을 종합 측정·평가하여 시스템의 유지, 기능 고도화, 재구축 또는 폐기를 합리적으로 결정하는 사후 성과관리 체계.
- 배경 및 필요성 : 정보시스템의 양적 팽창에 따른 운영·유지보수 예산 급증, 사용성이 낮거나 기능이 중복된 레거시 시스템 방치로 인한 예산 낭비를 차단하기 위해 행정안전부 성과관리 지침 표준화.
- 주요 목적 : 정보자원 운영 효율화, 시스템 통폐합 및 구조조정 판단 근거 확보, 정보화 예산의 선택과 집중.

## Ⅱ. 정보시스템 운영 성과관리의 특징 및 장점

- 핵심 요약 : 비용 효율성·업무 기여도 2축 매트릭스와 4대 평가 부문 지표를 특징으로 하는 사후 평가 체계.
1. **비용·업무 기여도 2축** : 운영비와 실제 가치를 함께 보고 투자 우선순위를 정한다.
2. **4사분면 판정** : 유지·활성화·통폐합·개선의 후보를 구분해 후속 조치를 구체화한다.
3. **이용·품질 지표** : 접속·거래·장애 기록으로 현장의 사용성과 안정성을 확인한다.
4. **운영 후 평가** : 구축 완료가 아닌 실제 이용 결과를 기준으로 성과를 판단한다.
5. **예산 환류** : 측정 결과를 차기 투자·개선 계획에 반영해 방치 시스템을 줄인다.

## Ⅲ. 정보시스템 운영 성과관리의 구조 (흐름)

- 핵심 요약 : 2축 매트릭스 4사분면 판정과 4대 평가 부문 지표 체계.
- 2축 매트릭스 및 측정 지표 흐름.

```text
[ 비용 효율성 \ 업무 기여도 매트릭스 ]
                기여도 낮음          기여도 높음
효율성 높음   2사분면 : 활성화/재검토   1사분면 : 유지 및 고도화
효율성 낮음   3사분면 : 통폐합/폐기 검토  4사분면 : 개선/효율화
```

```text
[ 4대 평가 부문 지표 흐름 ]
비용 효율성 (Cost)
   연간 유지관리비, 인프라 운영비, 사용자 1인당 운영비
        ↓
업무 적합성 (Value)
   업무 프로세스 지원율, 데이터 정확도, 시스템 완성도
        ↓
서비스 이용도 (Usage)
   MAU, 트랜잭션 건수, 로그인 빈도
        ↓
품질 및 기술 (Quality)
   가용률, MTBF, MTTR, 보안 취약점
```

- **1사분면 (유지 및 고도화)** : 비용 대비 효과 우수, 지속적 유지관리·기능 확장.
- **2사분면 (활성화/재검토)** : 비용은 적으나 이용률 저조, 사용률 제고 방안 수립.
- **3사분면 (통폐합/폐기 검토)** : 비용도 높고 기여도도 낮음, 폐기 또는 타 시스템 흡수.
- **4사분면 (개선/효율화)** : 기여도는 높으나 운영 비용 과다, 개선 필요.
- **MAU** (Monthly Active Users, 월간 활성 사용자 수) : 서비스 이용도 측정.
- **MTBF** (Mean Time Between Failures, 평균 장애 간격) / **MTTR** (Mean Time to Repair, 평균 수리 시간) : 품질 측정.

## Ⅳ. 운영 성과 측정 지표 비교

- 핵심 요약 : 평가 부문별 세부 측정 지표와 측정 방법 비교.
- 평가 부문별 지표 비교.

```text
[ 정량 지표 ] 로그·회계 데이터 기반
        ↕
[ 정성 지표 ] 설문·감사 기반
```

| 평가 부문 | 세부 측정 지표 | 측정 방법 |
|---|---|---|
| 비용 효율성 관점 (Cost) | 연간 유지관리비, 인프라 운영비, 사용자 1인당 운영비 | 회계 결산 데이터 및 자원 사용량 분석 |
| 업무 적합성 관점 (Value) | 업무 프로세스 지원율, 데이터 정확도, 시스템 완성도 | 현업 담당자 설문, 기능 활용률 감사 |
| 서비스 이용도 관점 (Usage) | 월간 활성 사용자 수(MAU), 트랜잭션 건수, 로그인 빈도 | 시스템 접속 및 트랜잭션 로그 분석 |
| 품질 및 기술적 관점 (Quality) | 가용률, 평균 장애 간격(MTBF)·평균 수리 시간(MTTR), 보안 취약점 | APM(Application Performance Monitoring) 모니터링 로그, 보안 취약점 점검 결과 |

## Ⅴ. 정보시스템 운영 성과관리의 한계와 방안

- 핵심 요약 : 비용 편향, 공통 원가 배부, 평가 후 조치 누락을 서비스 가치와 책임 있는 환류로 해결한다.

| 한계 | 방안 |
|---|---|
| 비용만 보면 낮은 이용량의 **공공 필수 서비스**를 과소평가 | 시민 편익·법정 기능·대체 가능성을 함께 검토 |
| 공통 인프라 비용의 **시스템별 배분**이 어려움 | ITAM·사용량 기준의 배부 규칙을 정의하고 가정 공개 |
| 평가 보고서만 작성하면 **개선 조치**가 실행되지 않음 | 조치 책임자·예산·기한과 후속 성과 확인 주기 지정 |

## Ⅵ. 운영 성과관리 실효성 확보에 대한 기술사적 제언

- 핵심 요약 : 로그 기반 자동 측정, 예산 편성 법적 연계, 폐기 프로세스 표준화.
- 로그 데이터 기반의 정량 측정 자동화 : 주관적 설문 평가의 한계를 극복하기 위해 실제 시스템 트랜잭션 로그, API(Application Programming Interface) 호출 횟수, 접속 빈도를 실시간 수집하는 자동 평가 체계 구축.
- 평가 결과와 차기년도 예산 편성의 법적 연계 : 성과 평가 결과 폐기 또는 통폐합 판정을 받은 시스템에 대해 운영 예산 자동 삭감 및 클라우드 공통 플랫폼으로의 전환 강제.
- 레거시 시스템 폐기(Retirement) 프로세스 표준화 : 시스템 폐기 시 기존 보존 데이터의 아카이빙, 법적 보존 연한 준수, 연계 시스템 인터페이스 영향 분석을 표준 매뉴얼에 따라 안전하게 수행.

## Ⅶ. 결론

- 핵심 요약 : 운영 성과관리는 비용·기여도·이용도·품질 측정으로 시스템 유지·통폐합·폐기를 합리화하는 사후 체계.
- 요약 : 정보시스템 운영 성과관리는 가동 중인 정보시스템의 운영 비용 대비 업무 기여도·이용도·서비스 품질을 종합 측정·평가하여 유지·고도화·통폐합·폐기를 결정하는 사후 성과관리 체계.
- 시사점 : 로그 기반 자동 측정, ITAM 원가 연동, 예산 편성 법적 연계, 폐기 프로세스 표준화를 통해 성과관리의 실효성과 예산 효율성 확보 필요.
