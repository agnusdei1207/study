## 연관 키워드

- 정보시스템 운영 성과관리 (Information System Operation Performance Management)
- 비용 효율성 (Cost Efficiency), 업무 기여도 (Business Contribution)
- 2x2 매트릭스 (유지·고도화 / 활성화·재검토 / 통폐합·폐기 / 개선·효율화)
- MAU (Monthly Active Users), MTBF (Mean Time Between Failures), MTTR (Mean Time to Repair)
- APM (Application Performance Monitoring), ITAM (IT Asset Management)
- 레거시 (Legacy), 시스템 통폐합 (Consolidation)

## Ⅰ. 정보시스템 운영 성과관리의 개요

- 핵심 요약 : 가동 중인 정보시스템의 운영 비용 대비 업무 기여도·이용도·서비스 품질을 측정해 유지·고도화·통폐합·폐기를 정하는 사후 성과관리 체계
- 개념 : **정보시스템 운영 성과관리** (Information System Operation Performance Management)는 가동 중인 공공 및 기업 정보시스템에 투입된 운영 비용 대비 업무 기여도, 이용도, 서비스 품질을 종합 측정·평가하여 유지, 고도화, 재구축 또는 폐기를 합리적으로 결정하는 사후 관리 체계
- 배경 및 필요성 : 정보시스템이 양적으로 늘면서 운영·유지보수 예산이 함께 커지는데, 이용률이 낮거나 기능이 중복된 **레거시 시스템** (Legacy System)이 방치되면 예산 낭비가 누적되므로, 판단 기준을 표준화한 정부 정보화 성과관리 지침이 필요
- 주요 목적 : 정보자원 운영 효율화, 시스템 통폐합과 구조조정 판단 근거 확보, 정보화 예산의 선택과 집중

## Ⅱ. 정보시스템 운영 성과관리의 특징 및 장점

- 핵심 요약 : 비용 효율성과 업무 기여도의 2축 매트릭스와 4대 평가 부문 지표로 운영 후 성과를 판단하는 사후 평가 체계

1. **비용·업무 기여도 2축** : 운영비와 실제 가치를 함께 보아 투자 우선순위를 정한다 → 비용 대비 효과가 낮은 시스템의 조기 식별
2. **4사분면 판정** : 유지, 활성화, 통폐합, 개선 후보를 구분한다 → 시스템별 후속 조치의 구체화
3. **이용·품질 지표** : 접속, 거래, 장애 기록으로 사용성과 안정성을 확인한다 → 현장 기준의 객관적 근거 확보
4. **운영 후 평가** : 구축 완료가 아니라 실제 이용 결과를 기준으로 성과를 판단한다 → 방치 시스템의 누락 방지
5. **예산 환류** : 측정 결과를 차기 투자와 개선 계획에 반영한다 → 정보화 예산의 효율 제고

## Ⅲ. 정보시스템 운영 성과관리의 구조 (흐름)

- 핵심 요약 : 2축 매트릭스의 4사분면 판정과 4대 평가 부문 지표의 단계적 측정 흐름

```text
[ 비용 효율성 × 업무 기여도 ]
                기여도 낮음     기여도 높음
효율성 높음     2사분면         1사분면
효율성 낮음     3사분면         4사분면
```

- 1사분면 (유지 및 고도화) : 비용 대비 효과가 우수해 지속적인 유지관리와 기능 확장 대상
- 2사분면 (활성화/재검토) : 비용은 적으나 이용률이 낮아 사용률 제고 방안 수립 대상
- 3사분면 (통폐합/폐기 검토) : 비용은 높고 기여도는 낮아 폐기 또는 타 시스템 흡수 대상
- 4사분면 (개선/효율화) : 기여도는 높으나 운영 비용이 과다해 효율화 개선 대상
- **월간 활성 사용자 수** (MAU, Monthly Active Users) : 서비스 이용도 측정 지표
- **평균 장애 간격** (MTBF, Mean Time Between Failures)과 **평균 수리 시간** (MTTR, Mean Time to Repair) : 품질 측정 지표

```text
[ 4대 평가 부문 지표 흐름 ]
비용 효율성 (Cost)
   연간 유지관리비, 사용자 1인당 운영비
        ↓
업무 적합성 (Value)
   업무 프로세스 지원율, 데이터 정확도
        ↓
서비스 이용도 (Usage)
   MAU, 트랜잭션 건수, 로그인 빈도
        ↓
품질 및 기술 (Quality)
   가용률, MTBF, MTTR, 보안 취약점
```

## Ⅳ. 운영 성과 측정 지표의 비교

- 핵심 요약 : 평가 부문별로 지표와 측정 방법이 다르며, 로그·회계 데이터의 정량 지표와 설문·감사의 정성 지표를 함께 사용

| 평가 부문 | 세부 측정 지표 | 측정 방법 |
| --- | --- | --- |
| 비용 효율성 (Cost) | 연간 유지관리비, 인프라 운영비, 사용자 1인당 운영비 | 회계 결산 데이터와 자원 사용량 분석 |
| 업무 적합성 (Value) | 업무 프로세스 지원율, 데이터 정확도, 시스템 완성도 | 현업 담당자 설문, 기능 활용률 감사 |
| 서비스 이용도 (Usage) | MAU, 트랜잭션 건수, 로그인 빈도 | 접속 및 트랜잭션 로그 분석 |
| 품질 및 기술 (Quality) | 가용률, MTBF, MTTR, 보안 취약점 | **응용 성능 모니터링** (APM, Application Performance Monitoring) 로그, 보안 취약점 점검 결과 |

## Ⅴ. 정보시스템 운영 성과관리의 한계와 방안

- 핵심 요약 : 비용 편향, 공통 원가 배부, 평가 후 조치 누락을 서비스 가치 관점과 책임 있는 환류로 보완

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 비용만 보면 이용량이 적은 **공공 필수 서비스**가 과소평가됨 | 이용 건수 중심 판정으로 시민 편익과 법정 기능이 누락 | 시민 편익, 법정 기능, 대체 가능성을 함께 검토 | 대체 가능성 검토 완료율 |
| 공통 인프라 비용의 시스템별 배분 곤란 | 배부 기준 부재로 시스템 간 원가가 왜곡 | **IT 자산 관리** (ITAM, IT Asset Management) 데이터와 사용량 기준의 배부 규칙을 정하고 가정을 공개 | 배부 기준 공개율 |
| 평가 보고서만 작성되고 개선 조치는 미실행 | 조치 주체가 없어 평가 결과가 환류되지 않음 | 조치 책임자, 예산, 기한을 지정하고 후속 성과를 확인하는 주기 운영 | 개선 조치 완료율 |

## Ⅵ. 운영 성과관리 실효성 확보에 대한 기술사적 제언

- 핵심 요약 : 로그 기반 자동 측정, 평가와 예산의 연계, 폐기 절차의 표준화로 성과관리의 실효성을 확보

1. 로그 기반 정량 측정 : 주관적 설문의 한계를 줄이려면 트랜잭션 로그와 **응용 프로그램 인터페이스** (API, Application Programming Interface) 호출 횟수, 접속 빈도를 수집해 지표를 자동 산출하는 체계로 옮겨 가야 한다
2. 평가와 예산의 연계 : 폐기 또는 통폐합 판정을 차기년도 예산 심의 기준으로 명시하면, 평가 결과가 실제 예산 조정과 클라우드 공통 플랫폼 전환으로 이어질 수 있다
3. 폐기 절차의 표준화 : 레거시 시스템의 폐기는 보존 데이터의 아카이빙, 법정 보존 기간 준수, 연계 인터페이스 영향 분석을 포함한 표준 절차로 수행해야 한다

## Ⅶ. 결론

- 핵심 요약 : 운영 성과관리는 비용·기여도·이용도·품질을 측정해 시스템의 유지와 폐기를 합리화하는 사후 체계
- 시사점 : 자동 측정과 ITAM 원가 연동, 예산 연계가 갖춰져야 성과관리가 실제 예산 효율로 이어진다
