## 큰 그림과 30초 인출

```text
[운영 중인 공공·기업 정보시스템]
          │
          ▼
┌────────────────── [2차원 운영 성과측정 모델] ──────────────────┐
│  [업무 관점 (업무 적합성)]      │  [비용 관점 (비용 효율성)]      │
│  - 사용도 (접속 건수, MAU)      │  - 유지보수비 적정성 (FP 대비) │
│  - 목적 부합도 (법정 업무 기여) │  - 운영 인프라 비용 적정성     │
│  - 사용자 만족도                │                                │
└─────────────────────────────────┴────────────────────────────────┘
          │
          ▼
┌────────────────── [4대 의사결정 판정 매트릭스] ────────────────┐
│  1. 유지 (Maintain)             : 업무 기여도 높음, 비용 적정    │
│  2. 기능개선/재개발 (Enhance)   : 업무 기여도 높음, 비용 과다    │
│  3. 폐기/통폐합 (Retire)        : 업무 기여도 낮음, 비용 적정    │
│  4. 운영효율화/폐기 (Terminate) : 업무 기여도 낮음, 비용 과다    │
└─────────────────────────────────────────────────────────────────┘
```

- 본질: 가동 중인 정보시스템의 지속적 운영 타당성을 '비용 관점(비용 적정도)'과 '업무 관점(업무 기여도)' 2개 축으로 매년 계량 평가하여 유지, 기능개선, 재개발, 폐기(통폐합) 여부를 객관적으로 결정하는 성과 평가 및 거버넌스 체계
- 위치: `시스템 운영 → 성과측정 지표 수집 → 2차원 매트릭스 진단 → 의사결정(유지/개선/재개발/폐기) → 예산 반영`
- 핵심: 제121회 KPC 기출, 행정안전부 정보시스템 운영 성과관리 지침, 2차원 매트릭스 4대 판정 유형
- 실무: 유령/좀비 시스템 퇴출, 클라우드 전환 대상 식별, 데이터 아카이빙 후 폐기

## 예상문제

> 행정안전부 '정보시스템 운영 성과관리 지침'에 따른 성과측정의 개념, 비용 관점 및 업무 관점의 측정 지표, 2차원 매트릭스 기반 4대 의사결정(유지, 기능개선, 재개발, 폐기) 판단 기준과 실무 적용 방안을 설명하시오. (25점)

## 딸려 나오는 하위 토픽

| 하위 토픽 | 핵심 내용 | 본문 답안 위치 |
|---|---|---|
| **정보시스템 운영 성과측정 모델** | 비용 적정도와 업무 기여도 2개 축으로 계량화하여 4분면 매트릭스 진단 수행 | Ⅱ 원리, Ⅲ 매트릭스 |
| **시스템 폐기 및 데이터 아카이빙** | 저이용 시스템 폐기 시 법정 보존 원장 데이터의 안전한 클라우드 콜드 스토리지 이관 | Ⅳ 절차, Ⅵ 실무 대책 |

## Ⅰ. IT 예산 효율화와 시스템 합리화의 출발점, 개요

- 정의: 운영 중인 정보시스템을 대상으로 투입 비용 대비 운영 효율성과 비즈니스 기여도를 정량적으로 측정하여 시스템의 유지, 기능개선, 재개발, 폐기 여부를 체계적으로 결정하는 사후 평가 관리 제도
- 법적 근거: 전자정부법 제56조(정보시스템의 운영성과 관리) 및 행정안전부 정보시스템 운영 성과관리 지침
- 추진 목적: 이용률 저조 및 중복 투자된 '좀비 시스템' 퇴출, 한정된 IT 운영 예산의 전략적 재배분, 시스템 현대화(클라우드 전환 등) 투자 우선순위 결정

#### 한줄 요약
- 비용 적정도와 업무 기여도를 측정하여 시스템의 존속·개선·폐기를 판정하는 제도임

## Ⅱ. 성과측정 2대 평가 관점 및 세부 측정 지표

| 평가 관점 | 세부 측정 항목 | 정량 측정 지표 및 산식 | 비고 |
|---|---|---|---|
| **비용 관점 (Cost)** | **유지관리비 적정도** | `소프트웨어 사업 대가산정 가이드 기준 대비 실제 계약액 비율` | 비용 과다 여부 검증 |
| **비용 관점 (Cost)** | **운영비용 효율성** | 시스템 규모(FP) 대비 인프라 자원(CPU, 스토리지) 소비량 | 클라우드 전환성 판단 |
| **업무 관점 (Business)**| **시스템 이용도** | 고유 접속자 수(MAU), 일평균 트랜잭션 건수, 페이지 뷰 | 실질 활용률 검증 |
| **업무 관점 (Business)**| **업무 기여도** | 해당 부서의 고유 핵심 업무 및 법정 의무 지원 비율 | 대체 불가능성 평가 |
| **업무 관점 (Business)**| **사용자 만족도** | 내·외부 사용자를 대상으로 한 주기적 정량 설문 점수 | 서비스 체감 품질 |

#### 한줄 요약
- 비용 관점(유지보수비/운영비)과 업무 관점(이용도/기여도/만족도)의 2대 축으로 측정함

## Ⅲ. 2차원 의사결정 매트릭스 구조 및 4대 판정 유형

```text
(업무 관점: 업무 기여도, 이용도)
 높음 ▲
      │
      │ ┌─────────────────────────────┬─────────────────────────────┐
      │ │      [ 1. 유지 (Maintain) ] │    [ 2. 기능개선 / 재개발 ] │
      │ │ - 높은 업무 기여도          │ - 높은 업무 기여도          │
      │ │ - 적정한 유지비용           │ - 과도한 유지비용           │
      │ │ ──> 현행 최적 운영 상태 유지│ ──> 아키텍처 개선, 클라우드 │
      │ │                             │     네이티브 재개발 추진    │
      │ ├─────────────────────────────┼─────────────────────────────┤
      │ │  [ 3. 폐기 / 통폐합 (Retire)│   [ 4. 운영효율화 / 폐기 ]  │
      │ │ - 낮은 업무 기여도 (저이용) │ - 낮은 업무 기여도          │
      │ │ - 적정한 유지비용           │ - 과도한 유지비용           │
      │ │ ──> 타 시스템 흡수 통합 또는│ ──> 긴급 비용 절감 검토 후  │
      │ │     서비스 종료(Shut down)  │     우선적 시스템 폐기 추진 │
      │ └─────────────────────────────┴─────────────────────────────┘
      └────────────────────────────────────────────────────────► 낮음 (비용 과다)
     적정 (비용 낮음)              (비용 관점: 유지보수비 적정도)
```

| 판정 유형 | 매트릭스 영역 | 핵심 판정 사유 | 실무 추진 조치 |
|---|---|---|---|
| **유지 (Maintain)** | 업무 높음 / 비용 적정 | 업무 기여도가 우수하고 운영 비용이 적정 수준인 이상적 상태 | 현행 운영 SLA 유지 및 안정적 보안 패치 |
| **기능개선 / 재개발** | 업무 높음 / 비용 과다 | 중요 시스템이나 노후화로 인해 유지보수 비용이 과다하게 소요 | 클라우드 전환, MSA 재설계, 전면 재개발 |
| **폐기 / 통폐합** | 업무 낮음 / 비용 적정 | 이용률이 미미하여 시스템의 비즈니스 존속 가치가 상실됨 | 데이터 아카이빙 후 서비스 종료 및 타 시스템 통합 |
| **운영효율화 / 폐기** | 업무 낮음 / 비용 과다 | 이용자도 없으면서 막대한 인프라 비용을 소모하는 최악 상태 | 즉각적 자원 회수, 운영 예산 삭감 및 최우선 폐기 |

#### 한줄 요약
- 2차원 매트릭스를 통해 유지, 개선/재개발, 통폐합, 폐기의 4대 명확한 방향을 도출함

## Ⅳ. 정보시스템 운영 성과관리 4단계 추진 절차

```text
① 성과측정 계획 수립 → ② 데이터 수집 및 실사 → ③ 종합 점수 산출 및 매핑 → ④ 심의 의결 및 예산 반영
   └─ 대상 시스템 선정       └─ 로그 분석 및 비용 검증     └─ 2차원 매트릭스 위치 확정   └─ 차년도 예산 삭감/증액
```

| 단계 | 주요 수행 내용 | 핵심 산출물 및 기준 |
|---|---|---|
| **1. 계획 수립** | 전 부서 운영 시스템 인벤토리 조사, 성과측정 대상 시스템 확정 | 성과측정 추진계획서 |
| **2. 데이터 수집** | 웹 로그, APM 지표, 유지보수 계약서, 인프라 비용 데이터 실측 | 지표별 원천 증빙 자료, 설문지 |
| **3. 점수 산출** | 표준 산식에 따른 비용 점수 및 업무 점수 환산 후 매트릭스 배치 | 성과측정 결과 종합 보고서 |
| **4. 심의 및 조치** | 정보화심의위원회 상정, 폐기/재개발 의결 후 차년도 예산에 반영 | 심의 의결서, 예산 조정 내역서 |

#### 한줄 요약
- 계획 수립, 데이터 수집, 점수 매핑, 심의 및 예산 반영 순으로 추진함

## Ⅴ. 정보시스템 개발 감리 vs 운영 성과관리 비교

| 비교 항목 | 정보시스템 개발 감리 | 정보시스템 운영 성과관리 |
|---|---|---|
| **수행 시점** | 시스템 구축(개발) 수명주기 단계 | 시스템 오픈 후 운영 수명주기 단계 (연 1회 정기) |
| **주요 목적** | 요구사항 명세 일치성 및 SW 공학 품질 검증 | 시스템의 비즈니스 존재 가치 및 비용 대비 효익 검증 |
| **핵심 기준** | 사업수행계획서, 제안요청서, 아키텍처 설계서 | 운영 성과관리 지침, 유지관리 대가 기준, 실제 이용도 |
| **결과 조치** | 시정 조치 요구 (적합/부적합 판정) | 시스템 유지, 기능개선, 재개발, 폐기 의사결정 |
| **법적 근거** | 전자정부법 제57조 (정보시스템 감리) | 전자정부법 제56조 (운영성과 관리) |

#### 한줄 요약
- 개발 감리는 품질 적합성을, 운영 성과관리는 경제적 존속 가치를 평가함

## Ⅵ. 실무 적용 시 장애 요인 및 통제 대책

- 적용 상황: 중앙행정기관 및 공공기관 150개 대민·행정 정보시스템 전수 성과평가

| 문제점 | 발생 원인 | 공학적·제도적 해결 대책 | 기대 효과 |
|---|---|---|---|
| **로그 조작을 통한 이용률 부풀리기** | 매크로 호출 및 단순 페이지 뷰(PV) 카운트로 사용도 왜곡 | 고유 사용자(MAU) 및 본인인증 세션 기반 실사용 트래픽 실측 | 허위 트래픽 필터링 및 객관성 확보 |
| **부서 이기주의에 따른 폐기 저항** | 시스템 폐기 시 과거 구축 성과 부정으로 인식되어 존치 주장 | 자진 통폐합 시 신규 정보화 사업 예산 우선 배정 인센티브 부여 | 자발적 구조조정 및 갈등 완화 |
| **폐기 시스템 데이터 영구 유실 우려** | 법정 보존 기한이 남은 원장 데이터의 보관 대책 부재 | 폐기 전 데이터 정제 후 클라우드 콜드 스토리지(Cold Storage) 아카이빙 | 법적 컴플라이언스 준수 및 인프라 비용 절감 |
| **수작업 평가에 따른 행정 부담** | 매년 수백 개 시스템의 실적을 엑셀로 취합하느라 오류 발생 | APM 및 API 게이트웨이 연계 상시 자동 성과 수집 포털 구축 | 평가 행정 비용 절감 및 상시 모니터링 |

#### 한줄 요약
- 실사용자 인증 기반 실측, 폐기 인센티브, 콜드 스토리지 이관, 자동화 포털로 대응함

## Ⅶ. 상시 자동화 관제와 클라우드 전환 연계 중심의 결론

- **[연례 서류 조사를 탈피한 상시 API 기반 성과 관제화]**: 운영 성과관리는 1년에 한 번 공문을 보내 엑셀로 취합하는 행정 행사에 머무르지 않고, 클라우드 관제 지표와 실시간 연동되어야 함
- 나라면: 클라우드 통합 관제 센터와 연계하여 `최근 수개월간 트래픽 및 DB 호출이 기준치 미달인 시스템을 '좀비 후보군'으로 자동 태깅 → 2차원 매트릭스 자동 산출 후 주관 부서에 소명 요구서 자동 발송 → 소명 실패 시 차년도 유지보수비 자동 삭감` 파이프라인을 구축

#### 한줄 요약
- 상시 관제 지표와 예산 배분을 연동하여 지속 가능한 정보시스템 다이어트를 완성함

## 1교시 10점 답안 발췌

### 1. 정보시스템 운영 성과관리의 정의
- 전자정부법 제56조에 의거, 운영 중인 정보시스템의 지속 운영 타당성을 '비용 적정도'와 '업무 기여도' 관점에서 계량 평가하여 유지, 기능개선, 재개발, 폐기를 결정하는 성과 거버넌스

### 2. 운영 성과관리 2차원 매트릭스 판정 체계
```text
(업무 관점: 이용도, 기여도)
  높음 ┼────── [유지] ──────┼── [기능개선/재개발] ──
       │ (업무 우수, 비용 적정)│ (업무 우수, 비용 과다)
  낮음 ┼── [폐기/통폐합] ───┼── [운영효율화/폐기] ──
       │ (업무 저조, 비용 적정)│ (업무 저조, 비용 과다)
       └─────────────────────┴─────────────────────►
       적정                               비용 과다 (비용 관점)
```

### 3. 차별화 제언
- 서류 평가 왜곡을 방지하기 위해 실 사용자 인증 기반 MAU를 측정하고, 폐기 결정 시스템의 법정 보존 데이터는 클라우드 콜드 스토리지로 안전하게 아카이빙해야 함

## 출제 이력과 검증 출처

- 제121회 KPC 1교시: 전자정부 정보시스템 운영 성과관리 지침에 따른 성과측정 및 판단 기준
- 제110회 2교시: 공공 정보시스템 운영 유지보수 효율화 방안
- [행정안전부, 정보시스템 운영 성과관리 지침 (행정안전부 고시 제2023-57호)](https://www.mois.go.kr)
- [한국지능정보사회진흥원(NIA), 공공 정보시스템 운영 성과관리 실무 매뉴얼](https://www.nia.or.kr)
