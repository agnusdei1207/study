## 연관 키워드

- ITSM, IT Service Management, ITIL, SLA, SLM, 인시던트·문제·변경 관리, CMDB, 서비스 데스크

## Ⅰ. ITSM의 개요

- 핵심 요약 : ITSM(IT Service Management)은 IT 서비스의 계획·설계·전환·운영·개선을 프로세스 중심으로 관리하는 체계.
- 개념 : ITSM(IT Service Management)은 IT 서비스의 계획·설계·전환·운영·개선을 프로세스 중심으로 관리하는 체계.
- 배경 및 필요성 : IT를 기술 중심이 아닌 서비스 중심으로 운영하지 않으면 장애 대응·비용·품질이 파편화됨.
- 주요 목적 : 고객 가치와 비즈니스 성과에 맞는 IT 서비스를 안정적으로 제공하고 지속 개선.

## Ⅱ. ITSM의 특징 및 장점

- 핵심 요약 : ITIL 기반 라이프사이클, SLA·SLM, 인시던트·문제·변경 관리, CMDB, 서비스 데스크가 서비스 품질을 높임.

1. 서비스 라이프사이클 : 전략·설계·전환·운영·지속개선의 단계를 순환 → 서비스 품질의 체계적 관리.
2. SLA·SLM : 서비스 수준 목표와 측정·보고를 정의 → 고객 기대와 IT 성과의 정렬.
3. 인시던트·문제·변경 관리 : 장애 복구, 근본원인 제거, 변경 승인을 분리 운영 → 반복 장애와 위험 감소.
4. CMDB·구성관리 : IT 자산·구성 요소와 관계를 기록 → 영향도 분석과 변경 위험 평가 지원.
5. 서비스 데스크 : 단일 접점으로 요청·장애를 접수·추적 → 사용자 경험과 투명성 향상.

## Ⅲ. ITSM의 구조 (흐름)

- 핵심 요약 : 서비스 전략 → 설계 → 전환 → 운영 → 지속개선의 순환과, 각 단계의 프로세스·도구 연계.

```text
서비스 전략
   ↓
서비스 설계
   ↓
서비스 전환
   ↓
서비스 운영
   ↓
지속적 개선
   ↺ (전략으로 환류)
```

```text
요청·장애 접수 → 분류·우선순위 → 처리·복구 → 종료·만족도 → 지식·개선
```

- 핵심 구성 : SLA, 인시던트, 문제, 변경, 릴리스, 구성관리, 지식관리, 서비스 데스크.

## Ⅳ. ITSM과 ITIL의 비교

- 핵심 요약 : ITSM은 관리 대상(서비스 관리), ITIL은 구현 프레임워크(모범 사례)로 역할이 다름.

| 비교 축 | ITSM | ITIL |
| --- | --- | --- |
| 정의 | IT 서비스 관리 체계 | IT 서비스 관리 모범 사례 프레임워크 |
| 초점 | 조직의 서비스 관리 목표 | 프로세스·역할·기법 제공 |
| 범위 | 정책·조직·도구 포함 | 프레임워크와 가이드 |
| 관계 | 목표 | 구현 수단 |

## Ⅴ. ITSM의 한계와 방안

- 핵심 요약 : 프로세스 과잉, 도구 중심 운영, SLA 형식화가 주요 한계이며 원인별 대응과 관리지표 연계가 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 프로세스 과잉 | ITIL 절차를 그대로 도입 | 조직 규모에 맞춘 Tailoring | 프로세스 준수율 |
| 도구 중심 운영 | 티켓 시스템이 목적화 | 서비스 가치 중심 KPI 설정 | 고객 만족도 |
| SLA 형식화 | 측정만 하고 개선 없음 | SLM 리뷰와 개선 과제 연계 | SLA 달성률·개선 건수 |
| 저항·문화 | 현장의 변화 저항 | 교육·챔피언·점진 도입 | 교육 이수율 |

## Ⅵ. ITSM에 대한 기술사적 제언

- 핵심 요약 : CIO는 ITSM을 서비스 가치 중심으로 정착시키고, SLA·CMDB·자동화를 연계해 운영 효율을 높임.

- 거버넌스 : 서비스 오너를 지정하고 서비스 카탈로그를 공개.
- 자동화 : 셀프서비스·챗봇·RPA로 요청 처리를 자동화.
- 측정 : 비즈니스 KPI와 IT KPI를 연계한 대시보드 운영.

## Ⅶ. 결론

- 핵심 요약 : ITSM은 IT를 기술 운영이 아닌 서비스 관리로 전환하는 운영체계임.
- 시사점 : SLA와 CMDB를 기반으로 지속 개선 루프를 돌려야 서비스 품질이 유지됨.
