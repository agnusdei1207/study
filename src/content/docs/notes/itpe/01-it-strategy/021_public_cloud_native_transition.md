## 연관 키워드

- 공공 클라우드 네이티브, Cloud Native, MSA
- 컨테이너, K8s, CI/CD, DevOps, Lift & Shift, CSAP

## Ⅰ. 공공부문 클라우드 네이티브 전환의 개요

- 핵심 요약 : 설계 단계부터 클라우드 장점을 극대화하는 MSA·컨테이너·CI/CD·데브옵스 기반 행정 혁신 전략.
- 개념 : 공공 정보시스템을 **단순 인프라 이전** (Lift & Shift) 방식이 아닌, 설계 단계부터 클라우드의 장점을 극대화할 수 있도록 **마이크로서비스 아키텍처** (MSA, Microservice Architecture), 컨테이너, CI(Continuous Integration)/CD(Continuous Delivery), 데브옵스를 적용하여 전환하는 **행정 혁신 전략**.
- 배경 및 필요성 : 대국민 서비스 장애(행정망 먹통 사태 등) 재발 방지, 트래픽 폭증 시 신속한 자동 확장(오토스케일링) 필요성, 레거시 모놀리식 시스템의 노후화 및 유지보수 한계 극복.
- 주요 목적 : 무중단 대국민 서비스 구현, 개발·배포 주기 획기적 단축, 장애 격리 및 시스템 복원력 확보, 클라우드 자원 활용 효율화.

## Ⅱ. 클라우드 네이티브의 특징 및 장점

- 핵심 요약 : MSA·컨테이너·CI/CD·선언적 API의 4대 기술 요소.

1. **마이크로서비스(MSA)** : 기능별 독립 배포·확장으로 변경의 영향 범위를 줄인다.
2. **컨테이너·Kubernetes** : 실행 환경을 표준화하고 수요에 맞게 자원을 탄력적으로 배치한다.
3. **CI/CD·DevOps** : 자동 시험·배포와 개발·운영 협업으로 출시 주기와 수작업 오류를 줄인다.
4. **선언적 API·GitOps** : 인프라 목표 상태와 변경 이력을 코드로 관리해 재현성과 감사 가능성을 높인다.

## Ⅲ. 공공 클라우드 네이티브의 구조 (흐름)

- 핵심 요약 : 4대 기술 요소와 전환 흐름.
- 클라우드 네이티브의 4대 핵심 기술 요소.

```text
[ 클라우드 네이티브 4대 요소 ]
클라우드 네이티브
   [Microservices (MSA)]
      ── 독립적 배포와 확장이 가능한 작은 단위 서비스 분할
   [Containers & K8s(Kubernetes)]
      ── 환경 일관성 및 경량 가상화를 위한
         컨테이너 오케스트레이션
   [CI/CD & DevOps]
      ── 지속적 통합·배포 자동화 파이프라인
      ── 개발-운영 협업
   [Declarative APIs & GitOps]
      ── 코드로 관리하는 인프라
         (IaC, Infrastructure as Code) 및 선언적 상태 동기화
```

```text
[ 공공 전환 흐름 ]
레거시 모놀리식 시스템
        ↓ Strangler Fig 패턴
대국민 접점 서비스 분리
        ↓ 컨테이너화·MSA
CI/CD 파이프라인 구축
        ↓
무중단·오토스케일링 서비스
```

## Ⅳ. 단순 이전(Lift & Shift)과 클라우드 네이티브의 비교

- 핵심 요약 : VM 단위 수동 확장·모놀리식 구조의 단순 이전에서 MSA·파드 단위 오토스케일링의 네이티브로 전환.

```text
[ Lift & Shift → Cloud Native 전환 ]
VM 단위 수동 확장 / 모놀리식
        ↓
파드 단위 오토스케일링 / MSA
```

| 비교 항목 | 단순 이전 (Lift & Shift) | 클라우드 네이티브 (Cloud Native) |
|---|---|---|
| 시스템 아키텍처 | 단일 모놀리식(Monolithic) 구조 유지 | 도메인 주도 설계(DDD, Domain-Driven Design) 기반 마이크로서비스(MSA) |
| 배포 및 확장 | VM(Virtual Machine) 단위 수동/느린 확장, 정기 배포 시 서비스 중단 | 파드(Pod) 단위 초 단위 오토스케일링, 무중단 카나리 배포 |
| 장애 영향도 | 한 모듈 장애 시 전체 시스템 다운 | 장애 격리(Fault Isolation), 서킷 브레이커 적용 |
| 데이터베이스 | 단일 통합 대용량 RDBMS(Relational Database Management System) (SPOF(Single Point of Failure) 존재) | 서비스별 독립 DB (Database per Service), 분산 트랜잭션 |
| 공공 조달 체계 | 기존 서버/스토리지 구매 규격 적용 | PaaS(Platform as a Service) 기반 클라우드 서비스 이용료 계약 및 사용량 과금 |

## Ⅴ. 공공 클라우드 네이티브 전환의 한계와 방안

- 핵심 요약 : 보안 요건, 단순 이전의 비효율, 운영 역량 부족을 대상별 전환 설계로 관리한다.

| 한계 | 방안 |
|---|---|
| 공공 데이터·서비스의 **보안 요건**을 일률적 구성으로 해결하기 어려움 | 데이터 등급과 적용 지침에 맞춰 접근 통제·인증·감사 설계 검증 |
| **Lift & Shift**만으로는 탄력성과 비용 효과를 얻기 어려움 | 서비스별 적합성을 평가해 필요한 부분부터 리팩토링·자동 확장 적용 |
| 발주 기관의 **운영 역량** 부족과 특정 공급자 의존 위험 | 표준 인터페이스·운영 지식 이전·계약상 이식성 요건 마련 |

## Ⅵ. 공공 클라우드 네이티브 전환에 대한 기술사적 제언

- 핵심 요약 : Strangler Fig 전환, 분산 데이터 정합성, 보안·규제 정비.
- 점진적 전환 전략(Strangler Fig 패턴) 적용 : 대규모 공공시스템의 빅뱅 전환 위험을 방지하기 위해 대국민 접점 및 트래픽 변동이 심한 서비스부터 순차적으로 분리 전환.
- 분산 데이터 정합성 보장 방안 수립 : MSA 전환에 따라 분리된 DB 간 정합성을 위해 2단계 커밋(2PC, Two-Phase Commit) 대신 사가 패턴(Saga Pattern) 및 이벤트 기반 아키텍처(Kafka 등) 도입.
- 보안 및 규제 기준의 합리적 정비 : 클라우드 보안인증제(CSAP, Cloud Security Assurance Program) 등급제 세분화에 맞추어 국가 중요 데이터의 망분리 규제를 완화하고, 제로 트러스트(Zero Trust) 및 서비스 메시·상호 TLS(mTLS, mutual TLS) 기반 보안 아키텍처 적용.

## Ⅶ. 결론

- 핵심 요약 : 공공 클라우드 네이티브 전환은 MSA·컨테이너·CI/CD 기반 행정 혁신.
- 요약 : 공공부문 클라우드 네이티브 전환은 설계 단계부터 MSA·컨테이너·CI/CD·데브옵스를 적용하는 행정 혁신 전략.
- 시사점 : 망분리 규제 합리화와 분산 데이터 정합성 확보가 전환 성공의 핵심.
