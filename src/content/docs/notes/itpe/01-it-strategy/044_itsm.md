## Ⅰ. ITSM의 개요

- **개념** : IT 조직이 비즈니스 요구에 부합하는 고품질의 IT 서비스를 고객에게 효과적으로 제공하고 관리하기 위해 사람, 프로세스, 정보기술을 최적화하는 서비스 중심의 IT 관리 체계(IT Service Management).
- **배경 및 필요성** : 전통적인 하드웨어/인프라 중심의 기술 지향적 관리 한계를 탈피하여, 비즈니스 가치 창출과 사용자 만족을 지향하는 고객 중심의 서비스 관리 패러다임 요구.
- **주요 목적** : IT 서비스 품질 향상, IT 운영 비용 절감(TCO 감축), SLA 준수를 통한 고객 만족도 제고, 비즈니스와 IT의 전략적 정렬.

## Ⅱ. ITIL v4의 서비스 가치 시스템(SVS) 및 가치 사슬(SVC)

```text
[기회/수요 (Opportunity/Demand)]
              │
              ▼
┌────────────────── 서비스 가치 시스템 (SVS) ──────────────────┐
│  - 기본 원칙 (Guiding Principles)                           │
│  - 거버넌스 (Governance)                                     │
│  - 서비스 가치 사슬 (Service Value Chain, SVC):             │
│    [계획(Plan)] ─ [개선(Improve)] ─ [참여(Engage)]           │
│    [설계/전환(Design/Transition)] ─ [획득/구축(Obtain/Build)]│
│    [제공/지원(Deliver/Support)]                              │
│  - 실천 관행 (Practices): 일반/서비스/기술 관리 관행         │
│  - 지속적 개선 (Continual Improvement)                       │
└──────────────────────────────┬───────────────────────────────┘
                               │
                               ▼
                        [가치 실현 (Value)]
```

## Ⅲ. ITSM 핵심 운영 프로세스 비교

| 프로세스 | 핵심 목적 | 주요 활동 및 특징 |
|---|---|---|
| 인시던트 관리 (Incident) | 서비스 중단 시 정상 서비스로의 최단 시간 내 복구 | 서비스 데스크 접수, 임시 조치(Workaround), 긴급 복구 |
| 문제 관리 (Problem) | 인시던트의 근본 원인을 분석하여 재발 방지 | 근본 원인 분석(RCA), 알려진 오류(Known Error) DB 등록 |
| 변경 관리 (Change) | 서비스 중단 위험을 최소화하면서 안전하게 변경 수행 | 변경자문위원회(CAB), 영향도 평가, 롤백 계획 수립 |
| 서비스 수준 관리 (SLM) | 고객과 합의된 서비스 품질(SLA) 협약 및 모니터링 | SLA/OLA 체결, 서비스 달성도 측정 및 서비스 개선 계획 |

## Ⅳ. ITSM 구축 및 운영 시 주요 한계점 및 해결 방안

- **프로세스 관료주의화 및 신속성 저하** :
  - **한계점** : 엄격한 변경 관리(CAB 승인) 및 절차 준수로 인해 경미한 패치나 배포에도 수일이 소요되어 비즈니스 민첩성 저해.
  - **해결 방안** : 표준 변경(Standard Change)의 사전 승인 자동화, 데브옵스 CI/CD 파이프라인과 ITSM 티켓팅의 API 자동 연동.
- **도구(Tool) 도입 중심의 왜곡된 운영** :
  - **한계점** : 조직 문화와 인력 역량 혁신 없이 값비싼 외산 솔루션(ServiceNow 등) 도입에만 치중하여 메뉴만 복잡해지고 활용도 저하.
  - **해결 방안** : 조직 성숙도에 맞춘 핵심 프로세스(인시던트, 장애, 변경) 단계적 롤아웃, 지속적 서비스 개선(CSI) 워크숍 정례화.
- **CMDB(구성관리DB)의 데이터 최신성 상실** :
  - **한계점** : 클라우드 인프라의 동적 생성/삭제 환경에서 수동 입력 위주 CMDB는 즉각 실제 형상과 불일치 발생.
  - **해결 방안** : 에이전트리스 자동 검색(Auto-Discovery) 도구 도입, 클라우드 인프라 프로비저닝 시 CMDB 실시간 자동 업데이트 구현.

## Ⅴ. 현대적 ITSM 진화를 위한 기술사적 제언

- **AIOps 기반의 장애 예방 및 인시던트 자동화** : 인프라 및 애플리케이션 로그를 AI 머신러닝으로 실시간 분석하여 장애 징후를 사전에 감지하고 자가 치유(Self-Healing) 스크립트 실행.
- **데브옵스(DevOps) 파이프라인과 변경 관리의 통합** : 과거 승인 대기로 인한 릴리즈 지연을 해소하기 위해, 자동화된 테스트를 통과한 표준 변경(Standard Change)은 승인 절차 없이 파이프라인에서 즉시 배포되도록 간소화.
- **사용자 경험(XLA) 중심의 지표 고도화** : 시스템 가용률 99.9% 같은 기술적 SLA 달성에 안주하지 않고, 실제 사용자가 체감하는 만족도와 비즈니스 생산성을 측정하는 경험 수준 협약(XLA, Experience Level Agreement) 도입.
