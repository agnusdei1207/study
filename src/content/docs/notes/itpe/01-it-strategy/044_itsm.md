## 지식 로드맵 내 현재 위치

IT 전략·관리 → IT 서비스 관리·운영 거버넌스 → **ITSM**

## 30초 인출

- 본질: ITSM(IT Service Management)은 IT 서비스가 합의한 요구를 충족하고 고객·사용자·조직에 가치를 주도록 서비스의 계획·설계·전환·제공·개선을 관리하는 체계로, 요구사항 국제표준이 ISO/IEC 20000-1:2018
- 메커니즘: 서비스 관리 시스템(SMS)을 10개 절로 구성하고, 8절 운영에서 서비스 포트폴리오·관계와 합의·공급과 수요·설계 구축 전환·해결과 이행·서비스 보증의 프로세스를 요구
- 통찰: 변경 요청·서비스 설계·릴리스 수락 기준·구성 정보·서비스 카탈로그가 소절별로 따로 기록되어 변경 뒤 서로 어긋날 수 있으므로 변경 요청 단위의 연결과 릴리스 수락 기준을 전환 승인 조건으로 사용

<details>
<summary>핵심 용어</summary>

- **ITSM(IT Service Management)** : IT 서비스의 계획·설계·전환·제공·개선을 관리하는 활동과 체계
- **SMS(Service Management System)** : 서비스 관리를 수립·구현·유지·지속 개선하기 위해 조직이 갖추는 관리 체계. ISO/IEC 20000-1이 요구사항을 규정
- **ISO/IEC 20000-1:2018** : 서비스 관리 시스템의 요구사항 표준. 10개 절로 구성
- **Annex SL(고수준 구조)** : ISO 경영시스템 표준이 공통으로 따르는 절 구조. 4 조직 상황부터 10 개선까지의 절 순서
- **ITIL(Information Technology Infrastructure Library)** : IT 서비스 관리 활동을 위한 모범 사례의 프레임워크
- **RFC(Request for Change, 변경 요청)** : 서비스나 구성 요소의 변경을 요청한 기록. ISO/IEC 20000-1 8.5.1.2가 기록을 요구
- **Service catalogue(서비스 카탈로그)** : 조직이 제공하는 서비스를 정리한 문서. 8.2.4에서 관리
- **Configuration information(구성 정보)** : 서비스 구성 요소의 구성을 기록한 정보. 8.2.6에서 관리
- **Release acceptance criteria(릴리스 수락 기준)** : 릴리스를 운영에 넘기기 전에 충족해야 할 기준. 8.5.3에서 요구

</details>

## 2~4교시 25점 답안

## Ⅰ. ITSM의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **ITSM(IT Service Management)** 은 IT 서비스의 계획·설계·전환·제공·개선을 관리하는 활동과 체계 |
| 목적 | 합의한 요구를 충족하는 서비스로 고객·사용자·조직에 가치 제공 |

## Ⅱ. 서비스 수명주기를 요구사항으로 규정하는 ISO/IEC 20000-1의 특징

| 특징 | 의미 |
|---|---|
| 서비스 수명주기 관리 | **SMS(Service Management System)** 가 계획·설계·전환·제공·개선 전체를 지원 |
| 요구사항 표준 | 20000-1은 수립·구현·유지·지속 개선의 요구사항을 규정하고, 적용 지침은 20000-2가 별도 제공 |
| 공통 절 구조 | **Annex SL** 을 따라 다른 경영시스템 표준(ISO/IEC 27001·ISO 9001 등)과 절 구조 정렬 |
| 운영 절 집중 | 프로세스는 8절 운영에 모여 있고 7개 소절로 구분 |
| 구조·용어 미규정 | 표준이 SMS의 구조와 구성 요소 명칭은 규정하지 않아 조직이 자체 프로세스와 대응 |

## Ⅲ. 서비스 관리 시스템 체계

### SMS 구성: 10개 절

```text
ISO/IEC 20000-1:2018
    ├─ 1~3  범위 · 인용 표준 · 용어와 정의
    ├─ 4    조직 상황
    ├─ 5    리더십
    ├─ 6    기획
    ├─ 7    SMS 지원
    ├─ 8    SMS 운영  ← 서비스 프로세스가 모인 절
    ├─ 9    성과 평가
    └─ 10   개선
```

### 운영 절 확대: 8절의 7개 소절과 프로세스

```text
8 SMS 운영
    ├─ 8.1 운영 기획과 통제
    ├─ 8.2 서비스 포트폴리오 ── 서비스 제공·서비스 계획·서비스 수명주기 관련 당사자 통제·서비스 카탈로그 관리·자산 관리·구성 관리
    ├─ 8.3 관계와 합의 ─────── 비즈니스 관계 관리·서비스 수준 관리·공급자 관리
    ├─ 8.4 공급과 수요 ─────── 서비스 예산·회계, 수요 관리, 용량 관리
    ├─ 8.5 서비스 설계·구축·전환 ─ 변경 관리·서비스 설계·릴리스와 배포 관리
    ├─ 8.6 해결과 이행 ─────── 인시던트 관리·서비스 요청 관리·문제 관리
    └─ 8.7 서비스 보증 ─────── 서비스 가용성 관리·서비스 연속성 관리·정보보안 관리
```

## Ⅳ. 서비스 설계·구축·전환 요구와 ITIL과의 관계

### 8.5 서비스 설계·구축·전환의 요구 기록

| 소절 | 활동 | 요구하는 문서·기록 |
|---|---|---|
| 8.5.1 | 변경 관리 | 변경 관리 정책, **RFC(Request for Change)** 기록 |
| 8.5.2 | 신규·변경 서비스의 설계 | 신규·변경 서비스의 설계 문서 |
| 8.5.3 | 릴리스와 배포 관리 | **릴리스 수락 기준(Release acceptance criteria)** |

### ISO/IEC 20000-1과 ITIL의 층위 비교

| 비교축 | ISO/IEC 20000-1:2018 | ITIL |
|---|---|---|
| 성격 | 서비스 관리 시스템의 요구사항 표준 | IT 서비스 관리 활동을 위한 모범 사례 프레임워크 |
| 활용 | 요구사항 충족을 심사하는 기준(심사·인증 기관 요구사항은 20000-6) | 조직이 서비스 관리 방식을 설계할 때 참고 |
| 구성 | Annex SL의 10개 절, 프로세스는 8절 | ITIL 4는 조직과 사람·정보와 기술·파트너와 공급자·가치 흐름과 프로세스의 4개 차원 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 변경 요청·서비스 설계·릴리스 수락 기준·구성 정보·서비스 카탈로그가 소절별로 따로 기록되어 변경 뒤 서로 불일치 | 변경 요청 번호를 기준으로 설계·구성 정보·카탈로그 갱신 내역을 연결해 기록 |
| 표준이 SMS 구조와 용어를 규정하지 않아 조직의 프로세스 이름과 범위가 조항과 어긋남 | 조직 프로세스와 8절 조항의 대응표 작성 |

## Ⅵ. 제언

변경 요청 단위의 설계·구성 정보·서비스 카탈로그 연결과, 서비스 보증 요구를 포함한 릴리스 수락 기준의 전환 승인 조건 지정

### 변경 요청 중심 연결 구조

```text
RFC 번호
    ├─ 서비스 설계 (8.5.2)
    ├─ 릴리스 수락 기준 (8.5.3) ← 가용성·연속성·정보보안 요구 (8.7)
    ├─ 구성 정보 (8.2.6)
    └─ 서비스 카탈로그 (8.2.4)
```

### 릴리스 수락 기준 확대: 전환 승인 절차

```text
RFC 기록
    ↓
설계·구성 정보·카탈로그 갱신안 작성
    ↓
릴리스 수락 기준 충족 확인 (가용성·연속성·정보보안 포함)
    ├─ 미충족 → 설계 수정 또는 릴리스 보류
    └─ 충족 → 릴리스·배포 → 구성 정보·카탈로그 반영 확인
```

| 구분 | 기록별 개별 관리 | 제언: RFC 단위 연결 |
|---|---|---|
| 확인 단위 | 설계 문서·구성 정보·카탈로그 각각 | RFC 하나에 연결된 전체 기록 |
| 릴리스 수락 기준 항목 | 서비스 보증 요구의 포함 여부 미정 | 가용성·연속성·정보보안 요구 포함 |
| 불일치 발견 시점 | 운영 중 장애·감사 | 릴리스 전 |

## 출제 이력과 검증 출처

- 제133회 2교시 3번: ISO/IEC 20000에서 제시하는 기준을 중심으로, 정보기술 서비스 관리체계(ITSM)의 개념 설명과 서비스 설계 및 구축, 전환을 위한 활동
- ISO/IEC 20000-1:2018 Service management system requirements — 서비스 관리 시스템 요구사항, 절 구조, 8절 운영의 소절
- ISO/IEC 20000-2·20000-6 — 적용 지침, 심사·인증 기관 요구사항
- 4개 차원: ITIL 4 Foundation 공식 과정 소개(PeopleCert)
