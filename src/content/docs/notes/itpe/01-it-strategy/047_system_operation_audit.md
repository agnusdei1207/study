## 연관 키워드

- 시스템 운영 감리, 유지보수 감리, IT 감사, SLA, SLM, 변경 관리, 보안 감사, 운영 투명성

## Ⅰ. 시스템 운영·유지보수 감리의 개요

- 핵심 요약 : 시스템 운영·유지보수 감리는 운영 체계와 유지보수 품질을 독립적으로 점검하는 활동.
- 개념 : 시스템 운영·유지보수 감리(System Operation Audit)는 정보시스템의 운영·유지보수 과정이 계약·표준·보안 요구에 부합하는지 점검하는 활동.
- 배경 및 필요성 : 개발 완료 후 운영 단계에서 SLA 미달·보안 취약·변경 미통제가 발생해 서비스 품질이 저하됨.
- 주요 목적 : 운영 투명성과 서비스 품질을 확보하고 리스크를 사전에 발견·개선.

## Ⅱ. 시스템 운영·유지보수 감리의 특징 및 장점

- 핵심 요약 : SLA 점검, 변경 관리, 보안 감사, 운영 효율, 지식 관리가 운영 품질을 높임.

1. SLA 점검 : 가용성·응답시간·복구시간을 측정·평가 → 서비스 수준 준수 확인.
2. 변경 관리 : 변경 요청·승인·테스트·배포 절차 점검 → 무단 변경과 장애 위험 감소.
3. 보안 감사 : 접근통제·암호화·로그·취약점 점검 → 개인정보·시스템 보호.
4. 운영 효율 : 자원 사용률·자동화·장애 반복 분석 → 비용 절감과 안정성 향상.
5. 지식 관리 : 운영 문서·런북·인수인계 점검 → 담당자 의존도 감소.

## Ⅲ. 시스템 운영·유지보수 감리의 구조 (흐름)

- 핵심 요약 : 감리 계획 → 자료 수집 → 운영·보안 점검 → 리스크 평가 → 보고·개선.

```text
감리 계획 수립
   ↓
자료 수집·인터뷰
   ↓
운영·보안 점검
   ↓
리스크 평가
   ↓
보고서·개선 조치
```

```text
SLA 점검 → 변경 관리 → 보안 감사 → 효율 분석 → 지식 관리
```

- 핵심 구성 : SLA, 변경, 보안, 운영 효율, 지식 관리.

## Ⅳ. 시스템 운영·유지보수 감리와 개발 감리의 비교

- 핵심 요약 : 개발 감리는 구축 품질, 운영 감리는 서비스 품질과 통제에 초점.

| 비교 축 | 개발 감리 | 운영·유지보수 감리 |
| --- | --- | --- |
| 시점 | 구축 단계 | 운영 단계 |
| 초점 | 요구·설계·구현 품질 | SLA·보안·변경·효율 |
| 산출물 | 구축 적합성 보고 | 운영 개선·리스크 보고 |
| 관계 | 전단계 | 후단계·지속 |

## Ⅴ. 시스템 운영·유지보수 감리의 한계와 방안

- 핵심 요약 : 점검 형식화, 운영 지표 부족, 개선 미이행이 주요 한계이며 원인별 대응과 관리지표 연계가 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 점검 형식화 | 체크리스트만 수행 | 리스크 기반 심층 점검 | 심층 점검 건수 |
| 운영 지표 부족 | SLA 측정 미비 | 모니터링·대시보드 구축 | SLA 측정률 |
| 개선 미이행 | 조치 추적 부재 | 시정조치 추적·보고 | 조치 이행률 |
| 범위 제한 | 운영 일부만 점검 | 전 영역·공급자 포함 | 점검 커버리지 |

## Ⅵ. 시스템 운영·유지보수 감리에 대한 기술사적 제언

- 핵심 요약 : CIO는 운영 감리를 SLA·보안·변경·효율 통합 점검으로 정례화.

- 거버넌스 : 감리 주기와 책임을 계약에 명시.
- 기술 : 모니터링·로그·CMDB를 감리 증거로 활용.
- 운영 : 시정조치 추적과 재감리를 정례화.

## Ⅶ. 결론

- 핵심 요약 : 시스템 운영·유지보수 감리는 운영 품질과 통제를 검증하는 활동임.
- 시사점 : SLA·보안·변경을 지속 점검해야 서비스 품질이 유지됨.
