## 연관 키워드

- 시스템 운영·유지보수 감리, SLA, 변경 관리
- 장애 관리, 재해복구, 시정조치

## Ⅰ. 시스템 운영·유지보수 감리의 개요

- 핵심 요약 : 시스템 운영·유지보수 감리는 가동 중인 정보시스템의 운영 통제와 유지보수 품질을 독립적으로 검증하는 활동.
- 개념 : **시스템 운영·유지보수 감리**는 구축이 완료되어 가동 중인 정보시스템의 운영·유지보수 과정이 계약·기준·보안 요구에 부합하는지 확인하고 시정·개선을 요구하는 독립적 점검 활동.
- 배경 및 필요성 : 구축 감리가 완료 시점의 품질만 검증하는 반면, 운영 단계에서는 서비스 수준 미달·무단 변경·보안 취약·용역 계약 부실이 누적되어 별도의 점검 체계 필요.
- 주요 목적 : 서비스 품질·보안·투자 효율의 지속 확보와 운영 리스크의 사전 발견.

## Ⅱ. 시스템 운영·유지보수 감리의 특징 및 장점

- 핵심 요약 : 서비스 수준·변경·장애·보안·계약의 다섯 통제 점검이 운영 품질 유지로 연결.

1. 서비스 수준 검증 : **SLA** (Service Level Agreement, 서비스 수준 협약)의 가용성·응답시간·복구시간 실적 대비 측정 → 계약 준수의 객관적 확인.
2. 변경 통제 점검 : **변경 관리**(변경 요청부터 승인·테스트·반영까지의 절차)의 이력과 승인 적정성 확인 → 무단 변경과 장애 재발 방지.
3. 장애·복구 관리 : **장애 관리**(장애 기록·원인 분석·재발 방지)의 실태와 **재해복구** (Disaster Recovery) 체계·훈련 점검 → 서비스 연속성 유지.
4. 보안 통제 검증 : 접근통제·권한·로그·취약점 조치 상태 확인 → 침해 사고의 사전 예방.
5. 계약·자원 적정성 : 유지보수 용역의 인력·비용·라이선스 규모의 적정성 검토 → 운영비 낭비 방지.

## Ⅲ. 시스템 운영·유지보수 감리의 구조 (흐름)

- 핵심 요약 : 계획에서 시정조치 추적까지의 감리 주기와 점검 영역으로 구성.

```text
감리 계획·범위 수립
   ↓
자료·증거 수집 (실적·로그·인터뷰)
   ↓
운영·보안 통제 점검
   ↓
리스크 평가·감리 의견 도출
   ↓
보고·시정조치 추적
```

```text
[ 점검 영역 ]

서비스 수준 : SLA 실적
변경·장애 : 이력과 재발 방지
보안 : 접근통제·취약점 조치
계약·자원 : 인력·비용·라이선스
```

## Ⅳ. 운영·유지보수 감리와 구축 감리의 비교

- 핵심 요약 : 구축 감리가 개발 시점의 품질을 검증하면 운영·유지보수 감리는 가동 시점의 통제와 서비스 수준을 검증.

| 비교 축 | 운영·유지보수 감리 | 구축 감리 |
| --- | --- | --- |
| 시점 | 안정화·운영 단계 | 기획~개발·시험 단계 |
| 검증 대상 | 서비스 수준·변경·장애·보안 통제 | 요구사항·설계·구현·시험 품질 |
| 판단 기준 | SLA·운영 절차·보안 기준 | 추진계획·기술기준·설계 문서 |
| 대표 지적 사항 | SLA 미달·무단 변경·계약 부실 | 설계 오류·일정 지연·결함 |
| 결과 활용 | 지속 개선·시정조치 | 인수·완료 판단 |

## Ⅴ. 시스템 운영·유지보수 감리의 한계와 방안

- 핵심 요약 : 형식화·실적 부재·조치 미이행·자료 의존의 한계를 리스크 기반 감리로 보완 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 형식적 점검 | 체크리스트 위주 수행 → 실질 리스크 누락 | 리스크 기반 감리 계획과 표본 심층 검증 | 심층 점검 항목 비율 |
| 운영 실적 부재 | SLA 측정 체계 미비 → 판단 근거 부족 | 모니터링·측정 자동화와 실적 보고 | SLA 측정 항목 커버리지 |
| **시정조치** (감리 지적에 대한 바로잡음 조치) 미이행 | 조치 추적 부재 → 반복 지적 | 조치 계획·기한·재검토 절차 운영 | 조치 완료율 |
| 용역 자료 의존 | 자체 제출 자료만 검토 → 객관성 저하 | 로그·시스템 설정 등 원천 자료 대조 | 원천 자료 검증 비율 |

## Ⅵ. 시스템 운영·유지보수 감리에 대한 기술사적 제언

- 핵심 요약 : 감리 제도를 계약·규정에 상시화하고 증거 자료를 표준화해 객관성을 높임.

- 거버넌스 : 감리 주기·범위·책임을 운영 계약과 내부 규정에 명시.
- 증거 표준 : 모니터링 데이터·구성관리 데이터베이스·로그를 감리 증거로 표준화.
- 역량 : 감리인의 운영·보안·계약 역량 교육과 감리 결과 공유 체계 운영.

## Ⅶ. 결론

- 핵심 요약 : 시스템 운영·유지보수 감리는 완료된 시스템의 품질을 가동 기간 내내 지키는 통제 장치임.
- 구축 감리와의 연계로 시스템 생애주기 전체의 품질 보증이 완성.
