## 답안 골격
```text
[정보시스템 감리] ◀━━ 머리: Ⅶ 내 의견 (형식적 체크리스트를 넘어선 정량적 취약점·결함 실측 기반 감리 혁신)
 ┃
 ┣━ Ⅰ 개요 ───── 정보시스템 구축의 복잡성 증가로 인한 품질 불량 및 예산 낭비 방지 → 제3자 독립적 종합 점검 제도화
 ┣━ Ⅱ 특징 ───── 법적 강제(전자정부법 제57조) · 독립성 보장 · 3단계 의무 감리 · 시정조치 이행 확인
 ┣━ Ⅲ 구조 ───── 감리 발주자 ↔ 피감리인(구축사업자) ↔ 감리법인 3자 구도 및 3단계 감리(요구정의·설계·종료)
 ┣━ Ⅳ 흐름 ───── ① 예비조사/계획서 작성 → ② 착수회의 → ③ 현장감리(문서·테스트 점검) → ④ 종료회의/보고서 통보 → ⑤ 시정조치 확인
 ┣━ Ⅴ 비교 ───── 3단계 감리 vs 상주감리 / 정보시스템 감리 vs 회계감사 vs PMO
 ┗━ Ⅵ 실무 ───── 종료 감리 시점의 시간 부족 / 지적사항에 대한 사업자의 형식적 조치 / 신기술(클라우드·AI) 점검 한계
```
- 필수 키워드: 전자정부법 제57조 · 독립성 · 3단계 감리(요구정의·설계·종료) · 기본점검표 · 시정조치 확인 · 감리보고서
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 3단계 감리 체계도 → Ⅳ 현장감리 절차 / 25점 = Ⅰ~Ⅶ 전개, Ⅲ 점검 프레임워크와 Ⅵ 신기술(AI/클라우드) 감리 실무 집중
- 기출: 129회 1교시 `정보시스템 감리기준 고시 기준 현장감리 활동 및 PMO 비교` → Ⅳ·Ⅴ, 136회 2교시 `감리와 PMO를 활용한 사업관리` → Ⅴ, 137회 3교시 `시스템 운영 및 유지보수 감리` → Ⅲ·Ⅵ

## 한 줄 본질
- 발주자의 전문성 부족과 구축사업자의 편의주의로 인한 납기 지연, 품질 결함, 보안 취약점 은폐 위험 발생 → 공인된 전문 감리법인이 독립된 제3자의 시각에서 정보시스템 구축 전 과정을 종합 점검하고 시정을 권고 → 정보시스템의 품질·안전성·효율성 확보 / 감리 지적에 따른 사업자의 행정 부담 증가

## 핵심 그림
```text
┌───────────────────────────────── [ 3단계 의무 감리 체계 ] ─────────────────────────────────┐
│                                                                                             │
│  [ 1단계: 요구정의 감리 ]          [ 2단계: 설계 감리 ]             [ 3단계: 종료 감리 ]     │
│  - 사업 착수 후 30% 시점          - 중간 단계(설계 완료 60%)       - 사업 종료 30일 전       │
│  - 요구사항 명확성/추적성          - 아키텍처 타당성/보안설계       - 시험 결과 검증/운영전환 │
│  - 과업 범위 일치성 점검          - DB 정규화/인터페이스 설계      - 최종 산출물 완성도 확인 │
└─────────────────────────────────────────────────────────────────────────────────────────────┘
                                                │
┌───────────────────────────────────────────────┴─────────────────────────────────────────────┐
│                                [ 현장감리 표준 5단계 절차 ]                                  │
│ ① 예비조사/감리계획서 ──> ② 착수회의 ──> ③ 현장점검(인터뷰/실측) ──> ④ 종료회의 ──> ⑤ 조치확인│
└─────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 핵심 용어
- 3단계 감리: 전자정부법상 총사업비 일정 규모 이상 정보화사업에서 의무적으로 수행해야 하는 3개 시점(요구정의 단계, 설계 단계, 종료 단계)의 정기 감리
- 시정조치 확인: 감리보고서에 명시된 '개선권고' 사항에 대해 피감리인이 시정조치를 완료했는지 감리원이 현장에서 증빙을 직접 재검증하는 절차

## 핵심 통찰
- 감리의 가치는 종료 단계의 서류 검사에 있는 것이 아니라 '요구정의 감리'에서 과업 누락과 범위 갈등을 사전 봉쇄하는 데 있음
- 설계 감리에서 보안 및 아키텍처 결함을 발견하지 못하면, 종료 감리 시점에는 시스템 구조를 뜯어고칠 시간적 여유가 없어 부실 시스템이 그대로 오픈됨
- 최근 클라우드 네이티브 및 AI 도입 사업의 경우 전통적인 정적 문서 중심 감리 방식으로는 컨테이너 취약점이나 AI 편향성을 전혀 걸러내지 못함

## 이웃 토픽과 구분
- 정보시스템 감리 vs PMO: 감리 = 법률에 근거한 독립적 제3자로서 특정 시점에 투입되어 적합성을 판정(Audit) / PMO = 발주자 편에서 상주하며 일상적 공정과 품질을 직접 이끄는 실행 조력자(Management)

## 문제·원인·대책
- 사례: 137회 기출 차세대 행정망 오픈 직후 대규모 인증 마비 사태 발생(종료 감리를 통과했음에도 비기능 부하 테스트 미검증으로 장애 유발)
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 종료 감리 통과 후 실운영 대규모 성능 장애 | 문서 위주 확인 및 실제 부하 스트레스 테스트 결과 검증 부재 | 감리 기준에 성능 모니터링 실측 데이터 검증 및 임계 부하 테스트 참관 의무화 | 성능 병목 사전 조기 차단 |
| 지적사항에 대한 서류상 조치 완료 후 방치 | 피감리인의 형식적 보고서 수정 및 실질 소스코드 반영 미흡 | 소스코드 정적 분석 도구 및 자동화 빌드 리포트 기반 조치 확인 제도화 | 실제 결함 수정 이행률 담보 |

## 이렇게 출제된다
- 제129회 1교시 4번: "정보시스템 감리기준 고시(2021-4호, 2021.1.19)에 의거한 현장감리의 활동, 작업내용을 기술하고 PMO와의 차이점을 설명하시오." → 요구 포인트: Ⅳ 현장감리 5단계 작업내용 + Ⅴ 감리 vs PMO 비교
- 제136회 2교시 2번: "정보시스템 구축 사업의 성공적인 수행을 위해 정보시스템 감리와 PMO(전자정부사업관리위탁)를 활용하여 사업관리를 수행하고 있다. 이 제도의 역할과 상호 연계 방안을 설명하시오." → 요구 포인트: Ⅲ 3단계 감리 + Ⅴ 감리-PMO 역할 매트릭스
- 제137회 3교시 2번: "정보시스템 감리의 시스템 운영 및 유지보수 감리에 대하여 설명하시오." → 요구 포인트: Ⅲ 운영감리 점검영역(SLA, 장애예방, 용량관리, 변경통제)

## 내 의견
- [문서 위주 감리에서 코드 및 인프라 실측 자동화 감리로의 패러다임 전환] 감리원들이 수천 쪽의 화면설계서와 테이블명세서 오탈자만 잡다가 오픈 후 치명적 SQL 인젝션이나 성능 지연 장애를 놓치는 사례 만연 → 나라면: 클라우드 배포 파이프라인(CI/CD)과 소스코드 정적 분석기(SonarQube), 부하 테스트 도구(JMeter) 실행 로그를 감리원이 직접 추출하여 판정하는 '테크니컬 코드 감리 가이드라인'을 수립하고 감리 보고서에 실측 증거 첨부를 강제
