## 큰 그림과 30초 인출

```text
[감리발주기관] ── 계약·지원 ──▶ [감리법인]
      │                              │ 독립 점검·개선
      └── 사업관리 ─▶ [피감리인] ◀──┘
                         │
계획 → 예비조사 → 현장감리 → 보고 → 시정조치·확인
```

- 본질: **독립된 제3자가 정보시스템 구축·운영을 종합 점검하고 문제 개선을 지원하는 품질·안전 통제**
- 법적 축: 전자정부법 제57조, 시행령, 정보시스템 감리기준
- 암기: `계-예-현-보-조` = 계획 → 예비조사 → 현장 → 보고 → 조치확인

## 예상문제

> 정보시스템 감리의 개념과 법적 근거, 수행체계 및 절차를 설명하고 PMO와의 차이 및 AI·클라우드 사업 감리 고려사항을 논하시오. (25점)

## Ⅰ. 독립적 제3자 점검을 통한 정보시스템 감리 개요

- 정의: 정보시스템 감리는 발주기관과 피감리인의 이해관계로부터 독립된 자가 정보시스템의 효율성·안전성 확보를 위해 구축·운영 사항을 종합 점검하고 개선하도록 하는 활동
- 목적: 요구·사업관리·아키텍처·데이터·보안·시험·운영전환의 결함을 조기에 식별하고 시정
- 법적 근거: 행정기관 등의 일정 기준 정보시스템은 전자정부법 제57조와 하위 법령·감리기준에 따라 감리 수행

## Ⅱ. 정보시스템 감리의 핵심 특징

| 특징 | 핵심 내용 | 실무 의미 |
|---|---|---|
| 독립성 | 발주기관·피감리인 이해관계에서 독립 | 객관적 판단·간섭 배제 |
| 전문성 | 등록 감리법인과 자격·경력 인력 | 영역별 전문 점검 |
| 증거기반 | 문서·인터뷰·관찰·시험·실측 | 재현 가능한 지적 |
| 예방·개선 | 종료검사뿐 아니라 수행 중 결함 조기 발견 | 재작업·실패비용 감소 |
| 이행확인 | 개선권고에 대한 조치와 증빙 확인 | 지적의 실효성 확보 |

## Ⅲ. 발주기관·피감리인·감리법인의 3자 체계

| 주체 | 역할 | 독립성·책임 |
|---|---|---|
| 감리발주기관 | 범위·계약·자료·수행지원·결과조치 | 업무개입 없이 감리환경 보장 |
| 피감리인 | 사업수행·산출물·설명·시정조치 | 사실자료 제공·개선 이행 |
| 감리법인 | 계획·점검·증거·판정·개선권고·확인 | 이해상충 방지·성실보고 |

```text
점검영역: 사업관리 / 요구사항 / 아키텍처·응용 / DB·데이터 / 보안 / 시험·운영
점검관점: 절차 적정성 / 산출물 완전성·일관성 / 구현·시험 증거 / 위험·개선
```

- 감리 시점과 범위는 사업 유형·규모·위험과 감리계약·계획에 따라 정하며 획일적인 수치·시점으로 단정하지 않음

## Ⅳ. 계획에서 조치확인까지의 감리 절차

```text
① 감리계약·범위 → ② 예비조사·감리계획 → ③ 착수회의
 → ④ 현장감리·증거수집 → ⑤ 종료회의·보고서 → ⑥ 시정조치 → ⑦ 조치확인
```

| 단계 | 핵심 활동 | 산출물 |
|---|---|---|
| 계획 | 사업·위험·표준 분석, 점검항목·인력·일정 확정 | 감리계획서 |
| 현장 | 인터뷰·문서대조·표본·시험·실측 | 점검기록·증거 |
| 판정 | 사실-기준-영향-원인-개선방향 정리 | 감리보고서 |
| 조치 | 책임자·기한·방안 확정·이행 | 시정조치계획·결과 |
| 확인 | 조치 증거와 잔여위험 재검토 | 조치확인 결과 |

## Ⅴ. 정보시스템 감리와 PMO 비교

| 구분 | 정보시스템 감리 | PMO/전자정부사업관리 |
|---|---|---|
| 목적 | 독립 점검·문제 개선 | 발주기관의 상시 사업관리 지원 |
| 시점 | 계획된 감리 시점의 독립 평가 | 사업 전 과정 상시 참여 |
| 관계 | 제3자 독립성 핵심 | 발주자 관점 관리대행 |
| 활동 | 증거수집·판정·개선권고·확인 | 일정·범위·위험·의사결정 지원 |
| 산출물 | 감리계획·보고·조치확인 | 관리계획·현황·이슈·의사결정자료 |
| 보완관계 | PMO 활동도 객관적으로 점검 가능 | 감리 지적을 일상관리로 이행 |

## Ⅵ. 문서 확인을 실증 점검으로 바꾸는 고려사항

| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 종료단계 중대결함 발견 | 요구·설계 시점 조기점검 부족 | 위험기반 감리시점·핵심 기준선 점검 | 재작업 비용 감소 |
| 형식적 조치완료 | 문구수정만 확인 | 재시험·로그·코드·설정·운영증적 확인 | 실질 결함 제거 |
| AI 품질 누락 | 기능·정확도만 점검 | 데이터계보·편향·안전·설명·모니터링 증적 | AI 위험 통제 |
| 클라우드 책임 공백 | CSP·MSP·개발사 경계 불명확 | 공유책임·IaC·보안설정·복구시험 점검 | 운영가능성 확보 |
| DevSecOps 변화 미반영 | 문서기준과 Pipeline 불일치 | Repository·CI/CD·SBOM·시험결과 표본 실측 | 현행 구현 검증 |

## Ⅶ. 체크리스트보다 위험과 증거를 추적하는 감리로 전환

- **[요구-구현-시험-운영 증거의 표본 추적]**: 산출물 존재 여부만 확인하면 실제 시스템과 문서의 불일치를 발견하지 못함
- 나라면: 고위험 요구를 선정해 요구사항부터 설계·코드·시험·배포·운영로그까지 표본 추적하고, 지적사항은 재시험 증거와 잔여위험 승인으로 종료

#### 한줄 요약

- 감리의 완성은 보고서 발행이 아니라 중대위험이 증거로 확인되고 개선되어 운영 가능한 상태임

## 1교시 10점 답안 발췌

```text
발주기관 ↔ 감리법인(독립 점검) ↔ 피감리인
계획 → 예비조사 → 현장감리 → 보고 → 시정조치·확인
```

| 감리 | PMO |
|---|---|
| 독립적 평가·개선권고 | 발주자 관점 상시 사업관리 |
| 증거·판정·조치확인 | 범위·일정·위험·의사결정 지원 |

- 차별화: 요구-설계-코드-시험-운영로그의 표본 추적으로 문서와 구현의 일치 검증

## 출제 이력과 검증 출처

- 제136·137회 공식 문제지: 감리·PMO 및 운영 감리 관련 출제
- 제123·125·129·131회 KPC 키워드 대응 이력
- 현행 검증 기준일: 2026-09-20
- [국가법령정보센터, 전자정부법 제57조](https://www.law.go.kr/법령/전자정부법)
- [국가법령정보센터, 정보시스템 감리기준](https://www.law.go.kr/행정규칙/정보시스템감리기준)
- 확인한 감리기준: 행정안전부고시 제2024-53호, 2024-06-27 시행
