## 연관 키워드

- A/B 테스트, 대조군, 실험군, 가설 검정, p-value, 통계적 유의성
- 전환율, CVR, 표본 크기, 제1종 오류, 제2종 오류
- 피처 플래그, 카나리 릴리스, 멀티암드 밴딧, MAB

## Ⅰ. A/B 테스트의 개요

- 핵심 요약 : 무작위로 나눈 사용자 집단에 변형을 노출하고 통계 검정으로 지표 개선을 확인하는 데이터 주도 실험 기법.
- 개념 : 기존 버전인 대조군과 새 버전인 실험군을 **무작위 배정**으로 나누어 노출한 뒤, 목표 지표의 차이를 가설 검정으로 비교하는 **A/B 테스트** (A/B Testing) 기법.
- 배경 및 필요성 : 직관에 근거한 배포는 효과 없는 기능에 개발·운영 비용을 쓰고 기존 지표를 훼손할 위험을 낳으므로, 실제 사용자 행동을 같은 조건에서 비교하는 실험 계층이 필요함.
- 주요 목적 : 전환율(CVR, Conversion Rate) 향상, 이탈률 감소, 기능 변경 위험 최소화, 비즈니스 가설의 신속한 검증.

## Ⅱ. A/B 테스트의 특징 및 장점

- 핵심 요약 : 무작위 배정과 사전 정의 지표가 직관 의존 판단을 줄이고 배포 위험을 낮춘다.

1. 무작위 배정 : 사용자 특성이 두 집단에 고르게 섞여 → 두 집단의 차이를 변형의 효과로 해석할 수 있음.
2. 사전 가설·표본 설계 : 성공 지표, 관찰 기간, 표본 크기를 시작 전에 정함 → 결과를 보고 기준을 바꾸는 해석 오류 차단.
3. 통계적 유의성 검토 : 효과 크기와 불확실성을 함께 봄 → 우연한 차이를 실제 효과로 착각하는 배포 판단 방지.
4. 제한적 노출 : 일부 사용자에게 먼저 노출 → 전체 배포 전에 부작용을 적은 비용으로 확인.
5. 핵심·안전 지표 병행 : 전환율과 함께 오류율·이탈률을 관찰 → 부작용을 함께 탐지.

## Ⅲ. A/B 테스트의 구조 (흐름)

- 핵심 요약 : 문제 정의에서 배포 또는 롤백까지 6단계로 이어지는 가설 검증 순환.

```text
[A/B 테스트 수행 흐름]

1. 문제 정의
   지표 저하 구간 식별
        ↓
2. 가설 수립
   "변경 시 클릭률이 오른다"
        ↓
3. 실험 설계
   귀무·대립 가설, 표본 크기
        ↓
4. 무작위 트래픽 분할
   해싱 기반 고정 비율 분할
        ↓
5. 데이터 수집·분석
   통계적 유의성 검정
        ↓
6. 배포 또는 롤백
```

```text
[트래픽 분할 구조]

전체 사용자
   ↓ 무작위 해싱
   50% → 대조군 A (기존 버전)
   50% → 실험군 B (신규 버전)
        ↓
이벤트 로깅 → 통계 분석 → 의사결정
```

- 판정 기준 : 사전에 정한 유의수준(예: p-value 0.05) 미만이면 B안을 배포하고, 귀무가설을 기각하지 못하면 현행을 유지하거나 롤백함.

## Ⅳ. A/B 테스트와 카나리 릴리스·MAB의 비교

- 핵심 요약 : 가설 검증, 점진 배포, 실시간 최적화라는 세 목적이 실험 방식의 선택 기준이 됨.

```text
[실험·배포 방식 선택 흐름]
가설 검증이 목적인가?
   ↓ 예 → A/B 테스트
   ↓ 아니오
위험을 줄인 점진 배포인가?
   ↓ 예 → 카나리 릴리스
   ↓ 아니오
실시간 성과 최적화인가?
   ↓ 예 → 멀티암드 밴딧 (MAB)
```

| 비교 항목 | A/B 테스트 | 카나리 릴리스 | 멀티암드 밴딧 (MAB, Multi-Armed Bandit) |
| --- | --- | --- | --- |
| 주요 목적 | 가설 검증과 지표 비교 | 신기능의 점진적·안전 배포 | 성과 좋은 대안에 트래픽 실시간 배분 |
| 트래픽 비율 | 고정 비율 (예: 50:50) | 소량에서 단계적으로 확대 | 성과에 따라 동적으로 변화 |
| 의사결정 시점 | 실험 종료 후 일괄 판단 | 모니터링 기반 단계 확대 | 실시간 자동 조정 |
| 기회비용 | 성과 낮은 대안에 계속 노출 | 제한적 | 상대적으로 적음 |

- **멀티암드 밴딧** (MAB) : 실험 도중에도 성과가 좋은 대안에 트래픽을 더 배분하는 방식으로, 확정 판단보다 손실 최소화에 초점을 둠.

## Ⅴ. A/B 테스트의 한계와 방안

- 핵심 요약 : 거짓 양성·거짓 음성, 조기 종료, 일시적 반응을 실험 설계 단계에서 통제함.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **제1종 오류** (Type I Error) | 실제 효과가 없는데 유의하다고 판정 → 효과 없는 변경을 배포 | 유의수준을 사전에 정하고 다중 비교를 보정 | 유의수준, 거짓 양성률 |
| **제2종 오류** (Type II Error) | 표본 부족으로 실제 효과를 놓침 → 좋은 변경을 버림 | 최소 검출 효과와 검정력에 맞춰 표본 크기 산정 | 검정력, 표본 크기 적정성 |
| 조기 종료와 신기 효과 | 중간 결과로 실험을 끝내거나 일시적 반응을 성과로 오인 | 사전 정한 종료 조건과 충분한 관찰 기간 준수 | 실험 기간 준수율, 조기 종료 건수 |

## Ⅵ. A/B 테스트 인프라 구축을 위한 기술사적 제언

- 핵심 요약 : 피처 플래그와 자동 분석 파이프라인을 갖추고 멀티암드 밴딧을 병행하여 실험 속도와 신뢰성을 함께 확보.

1. **피처 플래그** (Feature Flag) 체계 내재화 : 애플리케이션을 재배포하지 않고 기능 노출 여부와 대상 트래픽 비율을 제어하는 공통 인프라를 두어, 실험과 롤백을 같은 도구로 처리하는 것이 바람직하다.
2. 분석 파이프라인 자동화 : 이벤트 로깅에서 실시간 집계, 유의성 판정까지 자동화하면 결과 공유가 빨라져 실험 주기가 짧아진다.
3. 멀티암드 밴딧 병행 : 고정 비율 노출의 기회비용을 줄이려면 MAB 방식을 함께 쓰되, 확정 판단이 필요한 기능은 A/B 테스트로 남겨 두는 역할 분담이 필요하다.

## Ⅶ. 결론

- 핵심 요약 : A/B 테스트는 무작위 분할과 통계적 가설 검정으로 변경 효과를 과학적으로 검증하는 실험 체계.
- 시사점 : 통계 오류 통제와 충분한 관찰 기간을 전제로 할 때 실험 신뢰성과 배포 속도가 함께 확보됨.
