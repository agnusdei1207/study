## 연관 키워드

- A/B 테스트, 실험군, 대조군, 가설 검정, p-value
- 전환율, CVR, 통계적 유의성, 표본 크기, 피처 플래그
- 카나리 릴리스, 멀티암드 밴딧, MAB

## Ⅰ. A/B 테스트의 개요

- 핵심 요약 : 두 가지 이상의 변형을 무작위 사용자 집단에 노출하여 통계적 가설 검정으로 목표 지표 개선을 검증하는 데이터 주도형 실험 기법.
- 개념 : 디지털 서비스에서 두 가지 이상의 변형(기존 대조군 A vs 새로운 실험군 B)을 실제 사용자 집단에게 무작위(Random)로 분할 노출하고, 통계적 가설 검정을 통해 어떤 버전이 목표 지표를 더 유의미하게 개선하는지 검증하는 데이터 주도형 실험 기법.
- 배경 및 필요성 : 최고위층의 직관이나 주관적 의견(HiPPO, Highest Paid Person's Opinion)에 의한 의사결정 한계를 탈피하고, 실제 사용자 행동 데이터를 기반으로 서비스 개선의 효과성을 과학적으로 입증 필요.
- 주요 목적 : 전환율(CVR, Conversion Rate) 향상, 고객 이탈률 감소, 기능 변경의 위험성 최소화, 신속한 비즈니스 가설 검증.

## Ⅱ. A/B 테스트의 특징 및 장점

- 핵심 요약 : **무작위 배정**과 사전 정의한 지표로 변경의 효과를 비교해 직관에 의존한 판단을 줄인다.
1. **대조군·실험군 무작위 배정** : 사용자 구성 차이를 줄여 효과 비교의 신뢰도를 높인다.
2. **사전 가설·표본 설계** : 성공 지표와 관찰 기간을 먼저 정해 우연한 결과 해석을 줄인다.
3. **통계적 검정** : 효과 크기와 불확실성을 함께 검토해 배포 판단의 근거를 만든다.
4. **제한적 노출** : 전체 배포 전 일부 사용자에게 실험해 변경 위험을 줄인다.
5. **핵심·안전 지표 병행** : 전환율뿐 아니라 오류·이탈을 확인해 부작용을 탐지한다.

## Ⅲ. A/B 테스트의 구조 (흐름)

- 핵심 요약 : 문제 정의→가설 수립→실험 설계→트래픽 분할→데이터 분석→배포/롤백의 6단계 흐름.
- 수행 프로세스 및 가설 검정 체계.

```text
1. 비즈니스 문제 정의
   ── 전환율 저하, 장바구니 이탈 등 핵심 지표 분석
        ↓
2. 가설 수립
   ── "버튼 색상을 녹색으로 바꾸면 클릭률이
      5% 상승할 것이다"
        ↓
3. 실험 설계 및 샘플링
   ── 귀무가설/대립가설 설정
   ── 표본 크기(Sample Size) 및 실험 기간 산정
        ↓
4. 무작위 트래픽 분할
   ── 사용자 해싱(Hashing) 기반
      50:50 또는 카나리 트래픽 분할
        ↓
5. 데이터 수집 및 분석
   ── 통계적 유의성 검정
      (p-value < 0.05, 신뢰수준 95%)
        ↓
6. 배포 또는 롤백
   ── 유의미한 B안 전체 배포
   ── 귀무가설 채택 시 롤백
```

```text
[트래픽 분할 구조]
전체 사용자
   ├─ 50% ──→ 대조군 A (기존 버전)
   └─ 50% ──→ 실험군 B (신규 버전)
        ↓
   이벤트 로깅 → 통계 분석 → 의사결정
```

- **통계적 유의성** : p-value 기준으로 검정하여 B안 배포 또는 롤백 결정.
- **무작위 트래픽 분할** : 사용자 해싱(Hashing) 기반 50:50 또는 카나리 트래픽 분할.

## Ⅳ. A/B 테스트와 카나리 릴리스·MAB의 비교

- 핵심 요약 : A/B 테스트는 가설 검증, 카나리 릴리스는 점진 배포, MAB는 실시간 트래픽 최적화에 각각 초점.
- 비교 대상 및 선택 기준.

```text
[실험/배포 방식 선택 흐름]
목적 확인
   ↓
가설 검증 필요? ── 예 ──→ A/B 테스트
   ↓ 아니오
위험 최소 배포? ── 예 ──→ 카나리 릴리스
   ↓ 아니오
실시간 최적화? ── 예 ──→ MAB(Multi-Armed Bandit)
```

| 비교 항목 | A/B 테스트 | 카나리 릴리스 | MAB (Multi-Armed Bandit) |
|---|---|---|---|
| 주요 목적 | 가설 검증 및 지표 비교 | 신기능의 점진적·안전 배포 | 성과 좋은 대안에 실시간 트래픽 배분 |
| 트래픽 비율 | 고정 비율(예: 50:50) | 소량 트래픽부터 점진 확대 | 동적으로 변화 |
| 의사결정 시점 | 실험 종료 후 일괄 판단 | 모니터링 기반 단계 확대 | 실시간 자동 조정 |
| 기회비용 | 성과 낮은 대안에 지속 노출 | 제한적 | 최소화 |

## Ⅴ. A/B 테스트의 한계와 방안

- 핵심 요약 : **거짓 양성·음성**, 조기 종료, 일시적 신기 효과를 실험 설계에서 통제한다.

| 한계 | 방안 |
|---|---|
| 실제 효과가 없는데 유의하다고 판단하는 **제1종 오류** | 유의수준을 사전 정하고 다중 비교를 보정 |
| 표본이 부족해 실제 효과를 놓치는 **제2종 오류** | 최소 검출 효과와 검정력에 맞춰 표본 크기 산정 |
| 중간 결과만 보고 종료하거나 **신기 효과**를 성과로 오인 | 사전 정한 종료 조건과 충분한 관찰 기간 준수 |

## Ⅵ. A/B 테스트 인프라 구축을 위한 기술사적 제언

- 핵심 요약 : 피처 플래그 내재화, 데이터 파이프라인 자동화, MAB 병행.
- 피처 플래그(Feature Flag) 시스템 내재화 : 애플리케이션 코드 재배포 없이 실시간으로 특정 기능의 노출 여부와 대상 트래픽 비율을 즉각 제어할 수 있는 피처 토글 체계 구축.
- 데이터 분석 파이프라인의 자동화 : 사용자 이벤트 로깅부터 실시간 집계, 통계적 유의성 판정까지 자동화된 대시보드를 구축하여 빠른 의사결정 지원.
- 멀티암드 밴딧(Multi-Armed Bandit, MAB) 알고리즘 병행 : 고정 비율 노출 방식의 기회비용(성과가 낮은 대안에 트래픽이 계속 노출되는 동안의 사용자 손실)을 줄이기 위해, 성과가 좋은 대안에 실시간으로 트래픽을 더 많이 배분하는 MAB 기법 도입.

## Ⅶ. 결론

- 핵심 요약 : A/B 테스트는 무작위 분할과 통계적 가설 검정으로 서비스 개선을 과학적으로 검증하는 실험 체계.
- 요약 : A/B 테스트는 문제 정의부터 배포/롤백까지의 6단계 흐름으로 가설을 검증하는 체계.
- 시사점 : 통계적 오류 통제와 충분한 관찰 기간, 피처 플래그·자동화 파이프라인을 통해 실험 신뢰성과 속도를 함께 확보 필요.
