## 연관 키워드

- SLA, Service Level Agreement, 서비스 수준 협약서
- SLI, SLO, OLA, UC, XLA, Error Budget, APM

## Ⅰ. SLA의 개요

- 핵심 요약 : IT 서비스 제공자와 고객이 서비스 품질 수준, 측정 지표, 책임과 보상을 문서로 정한 **서비스 수준 협약서** (SLA, Service Level Agreement).
- 개념 : IT 서비스 제공자와 고객(발주자) 사이에 제공될 서비스의 품질 수준, 측정 지표, 책임, 미달 시의 보상 체계를 명확히 문서화해 체결하는 협약.
- 배경 및 필요성 : IT 아웃소싱 (ITO, IT Outsourcing)과 클라우드 도입이 늘면서 정성적 서비스 제공 방식에 따른 분쟁이 생겨, 정량화된 지표로 객관적 성과 평가와 계약 이행을 보장할 필요 증가.
- 주요 목적 : 서비스 기대 수준의 명확화, 측정 가능한 품질 지표(SLI, SLO) 확립, 장애 시 신속한 복구와 페널티, 인센티브 체계를 통한 품질 향상.

## Ⅱ. SLA의 특징 및 장점

- 핵심 요약 : 측정, 목표, 계약의 세 계층(SLI, SLO, SLA)으로 서비스 기대 수준과 책임을 명확히 하는 체계.

1. **서비스 수준 지표** (SLI, Service Level Indicator) : 가용률과 응답 시간을 측정 → 품질 논의를 객관적 데이터에 기반.
2. **서비스 수준 목표** (SLO, Service Level Objective) : SLI의 목표 범위를 합의 → 운영팀과 고객의 기대 수준 정렬.
3. SLA의 계약 조건화 : 목표 미달 시 보상과 조치 조건을 계약에 명시 → 장애 대응 책임과 분쟁 기준 명확화.
4. **오류 예산** (Error Budget) : 허용 장애 범위를 운영과 배포 의사결정에 반영 → 안정성과 변경 속도의 균형 확보.
5. 애플리케이션 성능 관리 (APM, Application Performance Monitoring) 자동 측정 : 동일한 수집 기준으로 품질을 기록 → 장애 시간 산정의 신뢰성 향상.

## Ⅲ. SLA의 구조 (흐름)

- 핵심 요약 : SLI, SLO, SLA로 이어지는 측정과 계약의 계층 구조, 그리고 OLA와 UC가 이를 하부에서 지원하는 구조.

```text
[ SLI → SLO → SLA 연계 ]

SLI (서비스 수준 지표)
   ── 서비스 품질의 정량 측정값
   ── 예: 가용률, 응답 시간
         ↓
SLO (서비스 수준 목표)
   ── SLI에 대해 합의된 목표 수준
         ↓
SLA (서비스 수준 협약)
   ── SLO 미달 시 보상, 위약 조건 명시
```

```text
[ SLA를 떠받치는 하부 계약 ]

SLA (고객과의 협약)
   ↑ 하부 지원 (Underpinning)
사내 지원 조직 협약
외부 협력업체 계약
```

- 운영 수준 협약 (OLA, Operational Level Agreement) : IT 서비스 제공자와 사내 지원 조직(네트워크, DB 등) 사이의 협약.
- 하부 계약 (UC, Underpinning Contract) : IT 서비스 제공자와 외부 협력업체(하드웨어 벤더, 클라우드 서비스 제공자 등) 사이의 계약.

## Ⅳ. SLA와 OLA 및 UC의 비교

- 핵심 요약 : SLA는 외부 고객, OLA는 사내 부서, UC는 외부 협력업체를 대상으로 하는 주체와 목적의 차이.

| 협약 구분 | 주체 | 목적 및 역할 |
| --- | --- | --- |
| SLA (Service Level Agreement) | IT 서비스 제공자와 외부 고객, 발주자 | 대외적 서비스 품질 보장과 비즈니스 계약 |
| OLA (Operational Level Agreement) | IT 서비스 제공자와 사내 지원 조직 | SLA 목표 달성을 위한 사내 협력 |
| UC (Underpinning Contract) | IT 서비스 제공자와 외부 협력업체 (CSP, Cloud Service Provider 등) | 하부 인프라와 서드파티 서비스의 품질 보장 |

- SLA의 실질적 달성은 사내 부서 간 OLA와 외부 벤더의 UC가 뒷받침될 때 가능.

## Ⅴ. SLA의 한계와 방안

- 핵심 요약 : 계약 지표와 체감 품질의 괴리, 측정 분쟁, 목표 경직성을 경험 지표, 공동 측정, 주기적 개정으로 해소.

| 한계 | 원인·영향 | 대응 방안 |
| --- | --- | --- |
| **수박 신드롬** (Watermelon Effect) | 가용률 목표는 달성해도 사용자는 지연과 오류를 체감 | 사용자 경험 수준 협약 (XLA, Experience Level Agreement) 지표와 실제 사용자 측정을 결합 |
| 측정값 분쟁 | 장애 시작과 종료 시각, 측정 지점의 정의가 달라 보상 해석이 충돌 | 애플리케이션 성능 관리 (APM) 수집 범위, 제외 시간, 산정식을 계약에 명시하고 공동 검증 |
| 목표의 경직화 | 계약 체결 후 트래픽과 아키텍처가 변해 기존 SLO의 적합성 저하 | 정기 검토와 개정 조항, 서비스 특성별 동적 임계치 운영 |

## Ⅵ. SLA에 대한 기술사적 제언

- 핵심 요약 : 오류 예산 도입, 사용자 중심 지표 설계, 클라우드 면책 조항 검토.
- 사이트 신뢰성 엔지니어링 (SRE, Site Reliability Engineering) 관점에서 100% 가용성을 고집하기보다, 허용된 중단 시간을 기능 배포와 테스트에 활용하는 합리적 운영 방식 도입.
- 사용자 체감 관점 지표 중심의 SLI 정의와 자동화된 APM 도구 수집을 통한 측정값 신뢰성 확보.
- 서비스형 인프라 (IaaS, Infrastructure as a Service), 서비스형 플랫폼 (PaaS, Platform as a Service), 서비스형 소프트웨어 (SaaS, Software as a Service) 도입 시 CSP가 제시하는 기본 SLA의 면책 조항 검토와 재해복구 체계 보완 설계.

## Ⅶ. 결론

- 핵심 요약 : SLA는 정량 지표, 보상 체계, OLA와 UC 연계를 통해 IT 서비스 품질을 계약으로 보장하는 협약서.
- 시사점 : 사용자 체감 품질을 측정하는 XLA와 오류 예산을 함께 운영해야 품질과 혁신 속도의 균형 확보.
