## 지식 로드맵 내 현재 위치

IT 전략·관리 → IT 서비스 관리 → **SLA**

## 30초 인출

- 본질: SLA(Service Level Agreement)는 서비스 제공자와 고객이 서비스의 수준과 책임, 목표 미달 시 결과를 합의한 서비스 수준 협약
- 메커니즘: 사용자가 체감하는 품질을 SLI로 측정하고 목표값인 SLO와 대조하며, 내부 조직 간 OLA가 그 목표를 구간별로 뒷받침
- 통찰: 구간별 목표를 각각 채워도 직렬로 이어진 사용자 목표에는 미달할 수 있으므로 사용자 기준 SLO에서 구간 목표를 역산해 배분

<details>
<summary>핵심 용어</summary>

- **SLA(Service Level Agreement)** : 서비스 제공자와 고객 사이에 서비스의 특정 측면을 규정한 협약. 통상 구속력 있는 계약
- **SLI(Service Level Indicator)** : 요청 지연, 오류율, 처리량, 가용성처럼 제공 서비스 수준의 한 측면을 정량으로 정의한 측정값
- **SLO(Service Level Objective)** : SLI로 측정하는 서비스 수준의 목표값 또는 목표 범위
- **에러 예산(Error Budget)** : SLO를 어기는 것을 허용하는 비율. 100% 달성을 요구하지 않는 SLO 설정 방식
- **OLA(Operational Level Agreement)** : SLA를 뒷받침하도록 내부 지원 조직 사이의 책임과 서비스 제공 절차·시한을 정한 협약
- **RTO(Recovery Time Objective)** : 중단 뒤 업무 프로세스를 복구해야 하는 목표 시간과 서비스 수준
- **RPO(Recovery Point Objective)** : IT 서비스에서 트랜잭션 데이터 손실을 허용하는 최대 시간 간격
- **MTBF(Mean Time Between Failures)** : 장애와 장애 사이의 평균 시간
- **MTTR(Mean Time To Repair)** : 장애 발생부터 수리·복구까지 걸린 평균 시간. Recovery 의미로도 사용

## 2~4교시 25점 답안

## Ⅰ. SLA의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **SLA(Service Level Agreement)** 는 서비스 제공자와 고객 사이에 서비스의 특정 측면을 규정한 협약 |
| 목적 | 서비스 수준의 사전 합의와 목표 달성·미달의 결과 명시 |

## Ⅱ. 목표와 결과를 함께 정하는 SLA의 특징

| 특징 | 의미 |
|---|---|
| 측정 가능한 목표 | **SLI** 로 측정하고 **SLO** 로 목표값 표현 |
| 결과의 명시 | SLO를 지키거나 못 지킨 결과를 계약에 포함. 결과가 없으면 SLO에 해당 |
| 사용자 관점 지표 | 추적 가능한 모든 지표가 아닌 사용자가 원하는 몇 가지 지표의 선택 |
| 완전 달성 비요구 | SLO 100% 달성 대신 허용 비율인 **에러 예산** 을 둠 |
| 지원 협약의 뒷받침 | 내부 지원 조직 사이의 **OLA** 가 SLA 달성을 뒷받침 |

## Ⅲ. SLA의 구성과 수립·관리 절차

### SLA 구성요소

```text
SLA
    │
    ├─ 서비스 정의 ── 서비스 유형
    │
    ├─ 성능 지표 ── 신뢰성·응답성 목표
    │
    ├─ 모니터링·보고 ── 감시 방법과 보고 체계
    │
    ├─ 이슈 보고 절차 ── 연락처와 보고 경로
    │
    ├─ 대응·해결 시한 ── 조사 시작과 해결 기한
    │
    └─ 위반 시 결과 ── 계약 해지 권리, 환불 등
```

### SLA 관리 절차

```text
SLA 정의: 서비스 수준 지표와 목표의 기본 구성
    ↓
협상: 제공자와 고객의 목표 합의
    ↓
모니터링: SLI 측정과 보고
    ↓
위반 탐지: SLO 미달 확인
    ↓
집행: 위반 시 결과의 적용
```

## Ⅳ. SLI·SLO·SLA와 SLA·OLA, 영역별 지표

### SLI·SLO·SLA의 구분

| 구분 | 내용 | 예 |
|---|---|---|
| SLI | 서비스 수준의 한 측면을 정량으로 정의한 측정값 | 성공 응답 수 대 유효 요청 수의 비율 |
| SLO | SLI로 측정하는 목표값 또는 범위 | 성공률의 하한 |
| SLA | SLO와 이를 지키거나 못 지킨 결과를 담은 계약 | 미달 시 환불 |

### SLA와 OLA의 구분

| 비교축 | SLA | OLA |
|---|---|---|
| 당사자 | 서비스 제공자와 고객 | 제공자 내부의 지원 조직 |
| 정하는 내용 | 고객에게 약속하는 서비스 수준 | 내부 지원 조직의 책임과 서비스 제공 절차·시한 |
| 관계 | 고객에 대한 약속 | SLA 달성을 뒷받침하는 기반 |

### 영역별 지표와 복구 목표

| 영역 | 평가지표 | 측정 |
|---|---|---|
| 하드웨어 | uptime, MTBF, MTTR | 장애·가동 시간 기록의 집계 |
| 소프트웨어 | 요청 지연, 오류율, 처리량 | 성공·실패 요청 기록의 비율 |
| 네트워크 | 처리량, 지터, uptime | 정기 측정과 모니터링 |
| 복구 | RTO(복구 목표 시간), RPO(허용 데이터 손실 시점 간격) | 복구 훈련의 실측 |

## Ⅴ. SLA 적용의 한계와 방안

| 한계 | 방안 |
|---|---|
| 서버 가동 같은 제공자 관점 지표가 사용자의 체감과 어긋남 | 사용자 요청의 성공 비율·지연을 SLI로 선택 |
| 직렬로 이어진 구간의 가용도가 곱으로 낮아져 구간 목표를 각각 채워도 사용자 목표 미달 | 사용자 기준 SLO에서 구간별 허용 실패량을 역산해 OLA와 외부 공급자 계약에 배분 |
| 100% 달성을 전제한 목표가 비현실적이어서 위반이 상시화 | 에러 예산으로 허용 실패 비율을 명시 |
| 계약 RTO·RPO가 실제 복구 능력과 차이 | 복구 훈련에서 재개 시간과 복구 데이터 시점의 실측 |

## Ⅵ. 제언

사용자 기준 SLO를 먼저 정하고, 그 목표에서 내부 OLA와 외부 공급자 계약의 구간 목표를 역산해 배분

### SLO 역산 배분 구조

```text
사용자 기준 SLO ── 성공률·지연
    ↓  구간별 허용 실패량 배분
내부 구간 목표 ── OLA로 정한 지원 조직
    ↓  외부 의존 구간 분리
외부 공급자 구간 목표 ── 계약으로 정한 목표
```

### 배분 확대: SLO 미달 시 책임 구간 확인

```text
SLI 측정값의 SLO 미달
    ↓
장애 이력의 구간별 소요 대조
    ↓
배분 목표를 초과한 구간 확인
    ├─ 내부 구간 → OLA 기준 개선 과제 지정
    └─ 외부 구간 → 공급자 계약 조치 요구
```

| 구분 | 구간별 개별 목표 | 제언: 사용자 SLO 역산 |
|---|---|---|
| 목표 설정 기준 | 각 구간의 현행 역량 | 사용자 요청의 성공률·지연 |
| 구간 목표 충족의 의미 | 사용자 목표 달성과 무관 | 사용자 목표 달성의 선행 조건 |
| SLO 미달 시 책임 | 구간별 충족 주장으로 불명확 | 배분 목표 초과 구간이 확정 |
