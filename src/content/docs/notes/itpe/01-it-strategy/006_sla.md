## 지식 로드맵 내 현재 위치

IT 전략·관리 → IT 서비스 관리 → **SLA**

## 30초 인출

- 본질: SLA(Service Level Agreement)는 서비스 제공자와 고객이 서비스 범위·목표 수준·측정 방법·책임을 미리 합의한 협약
- 메커니즘: 대고객 SLO를 SLI로 측정하고, 내부 OLA와 외부 UC가 그 목표를 구간별로 나눠 지원
- 통찰: 구간 목표를 모두 채워도 사용자 목표는 미달할 수 있으므로 사용자 기준 SLO에서 역산한 구간 목표 배분

<details>
<summary>핵심 용어</summary>

- **SLA(Service Level Agreement)** : 서비스 제공자와 고객이 서비스 범위·목표 수준·측정 방법·책임을 합의한 협약
- **SLI(Service Level Indicator)** : 거래 성공률·응답시간처럼 서비스 품질을 실제로 측정하는 지표
- **SLO(Service Level Objective)** : SLI가 도달해야 할 목표 값. 예: 월간 거래 성공률 99.9%
- **OLA(Operational Level Agreement)** : SLA 이행을 위해 제공자 내부 조직 간에 맺는 지원 수준 협약
- **UC(Underpinning Contract)** : SLA 이행에 필요한 서비스를 외부 공급자에게서 조달하는 계약
- **RTO(Recovery Time Objective)** : 장애 후 서비스 재개까지 허용하는 목표 시간
- **RPO(Recovery Point Objective)** : 복구 시 되돌아갈 데이터 시점으로 표현한 허용 데이터 손실 범위
- **MTTR(Mean Time To Restore)** : 실제 장애에서 복구까지 걸린 평균 시간. 사전 목표인 RTO와 구별되는 운영 실적
- **워터멜론 효과(Watermelon Effect)** : 보고 지표는 정상(초록)이나 사용자 체감 품질은 장애(빨강)인 측정 괴리

## 2~4교시 25점 답안

## Ⅰ. SLA의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **SLA(Service Level Agreement)** 는 서비스 제공자와 고객이 서비스 범위·목표 수준·측정 방법·책임을 합의한 협약 |
| 목적 | 기대 서비스 수준의 사전 합의와 달성 여부의 객관적 판단 |

## Ⅱ. 측정 가능한 합의라는 SLA의 특징

| 특징 | 의미 |
|---|---|
| 고객·제공자 쌍방 합의 | 제공자 단독 목표가 아닌 고객 요구에 기반한 서비스 수준 |
| 측정 가능성 | **SLI** 와 **SLO** 로 표현한 목표와 측정 방법의 명시 |
| 책임 연쇄 | 대고객 목표를 받치는 내부 **OLA** 와 외부 **UC** 의 지원 책임 |
| 지속 관리 | 실측·보고·검토 결과에 따른 목표와 운영의 주기적 조정 |

## Ⅲ. SLA 구성 체계와 수립 절차

### SLA 구성 체계

```text
SLA ── 고객과 제공자의 서비스 수준 협약
    │
    ├─ 서비스 정의 ── 대상 서비스·범위·운영 시간
    │
    ├─ 서비스 수준 ── SLI·SLO(가용률·응답시간·RTO·RPO)
    │
    ├─ 측정·보고 ── 측정 방법·주기·보고 체계
    │
    ├─ 책임·예외 ── 역할·면책 조건·위반 시 조치
    │
    └─ 지원 협약
          ├─ OLA ── 내부 조직의 지원 수준
          └─ UC ── 외부 공급자의 계약 수준
```

### 서비스 수준 확대: SLI·SLO 수립 절차

```text
고객 업무와 대상 서비스 정의
    ↓
사용자 관점 SLI 선정
    ↓
현행 실측 기반 SLO 합의
    ↓
OLA·UC 지원 수준 정렬
    ↓
측정·보고·주기적 검토
    └─ 목표 미달·업무 변화 → SLO 재합의
```

## Ⅳ. SLA·OLA·UC의 관계와 지표 구분

### SLA·OLA·UC의 범위 비교

| 구분 | SLA | OLA | UC |
|---|---|---|---|
| 당사자 | 고객과 서비스 제공자 | 제공자 내부 조직 간 | 제공자와 외부 공급자 |
| 목표 대상 | 고객이 이용하는 서비스 | 내부 지원 구간(DB·네트워크 운영 등) | 외부 조달 구간(클라우드·회선 등) |
| 성격 | 대고객 서비스 수준 약속 | 내부 운영 합의 | 법적 계약 |

### 목표·실적 지표의 구분

| 구분 | 목표 지표 | 실적 지표 |
|---|---|---|
| 서비스 품질 | SLO(거래 성공률 목표) | SLI(실측 거래 성공률) |
| 장애 복구 | **RTO** (허용 복구 시간) | **MTTR** (실제 평균 복구 시간) |
| 데이터 보호 | **RPO** (허용 손실 시점) | 복구 데이터의 실제 시점·정합성 |

SLA는 고객 서비스 전체, OLA·UC는 그 일부 구간을 다루는 범위 차이. 구간 목표가 대고객 목표에서 나오지 않으면 구간별 충족과 서비스 미달이 동시에 발생하는 구조

## Ⅴ. SLA 적용의 한계와 방안

| 한계 | 방안 |
|---|---|
| 서버 가동률은 정상이나 사용자 거래는 실패하는 **워터멜론 효과** | 사용자 거래 성공률·응답시간의 SLI 채택 |
| OLA·UC 구간 목표를 모두 충족해도 SLA 목표 미달 | 대고객 SLO에서 구간별 허용 시간·실패량의 역산 배분 |
| 계약상 RTO·RPO와 실제 복구 능력의 차이 | 복구 훈련에서 재개 시간·복구 데이터 시점의 실측 |
| 측정 주체와 기준의 불일치로 인한 결과 분쟁 | 측정 도구·산식·제외 조건의 SLA 명시 |

## Ⅵ. 제언

사용자 거래 기준 SLO를 먼저 정하고, 그 목표에서 OLA·UC 구간 목표를 역산하는 목표 배분 체계의 선행 구축

### SLO 역산 배분 구조

```text
대고객 SLO ── 월간 거래 성공률·응답시간
    ↓ 구간별 허용 실패량·시간 배분
OLA 구간 목표 ── 애플리케이션·DB·내부 네트워크
    ↓ 외부 의존 구간 분리
UC 구간 목표 ── 클라우드 인프라·통신 회선
```

### 배분 확대: SLO 미달 시 책임 구간 판정

```text
월간 SLI 실측의 SLO 미달
    ↓
장애 이력의 구간별 소요 시간 대조
    ↓
배분 목표 초과 구간 확인
    ├─ OLA 구간 → 내부 운영 개선 과제 지정
    └─ UC 구간 → 계약 조치와 공급자 개선 요구
```

### 선택 근거: 구간별 개별 목표와의 비교

| 구분 | 구간별 개별 목표 | 제언: 대고객 SLO 역산 |
|---|---|---|
| 목표 설정 기준 | 각 조직·공급자의 현행 역량 | 사용자 거래 성공률·응답시간 |
| 구간 목표 충족의 의미 | 대고객 목표 달성과 무관 | 대고객 목표 달성의 선행 조건 |
| SLO 미달 시 책임 판단 | 구간별 충족 주장으로 책임 불명확 | 배분 목표 초과 구간의 책임 확정 |
