## 전체 로드맵 내 현재 위치

```text
▶ 01 정보 전략·관리 ─→ 02 SW공학·프로젝트 ─→ 03 데이터
          │
          └─→ 04 컴퓨터시스템 ─→ 05 네트워크 ─→ 06 보안
                                     │
                                     └─→ 07 AI·신기술
전 영역 준거 ───────────────────────────→ 08 법·정책
```

- 현재 위치: `01 정보 전략·관리 > IT 서비스관리 > SLA`

## 큰 그림과 30초 인출

```text
고객 요구 → SLI 측정지표 → SLO 목표수준 → SLA 계약
                                      │
                           ┌──────────┴──────────┐
                           ▼                     ▼
                       OLA 내부협약          UC 외부계약
                           └──────── 모니터링·개선 ─┘
```

- 본질: **고객과 제공자가 서비스 항목·측정방법·목표수준·책임·보상을 합의한 서비스 수준 협약**
- 암기: `지-목-약` = SLI 지표 → SLO 목표 → SLA 약정
- 연계: 고객 SLA는 내부 OLA와 외부 공급자 UC로 뒷받침

## 예상문제

> SLA의 개념과 구성요소, 수립·운영절차를 설명하고 SLI·SLO·SLA 및 SLA·OLA·UC의 관계와 실무 고려사항을 논하시오. (25점)

## Ⅰ. 서비스 기대수준을 계약으로 명확화하는 SLA 개요

- 정의: SLA는 서비스 제공자와 고객이 서비스 범위, 품질지표, 목표수준, 측정·보고, 책임, 미달 시 조치를 합의한 문서
- 목적: 모호한 품질 기대를 측정 가능한 기준으로 전환하여 서비스 성과·비용·책임을 객관적으로 관리
- 필요성: 측정 기준과 제외조건이 없으면 같은 장애를 두고 고객과 제공자의 가용성·책임 판단이 달라짐

## Ⅱ. 측정·합의·연계·개선 중심의 SLA 특징

| 특징 | 핵심 내용 | 유의점 |
|---|---|---|
| 측정 가능성 | 산식·Source·주기·구간 명시 | 평균값만으로 체감품질 은폐 금지 |
| 상호 합의 | 업무 중요도·비용·위험의 균형 | 일방적 목표 강제 방지 |
| 책임 연계 | Owner·보고·Escalation·보상 정의 | 장애 원인별 책임경계 |
| 하위계약 정렬 | OLA·UC가 SLA 목표를 지원 | 공급망 목표 불일치 방지 |
| 지속 개선 | Review·Problem·목표 조정 | 계약 후 방치 금지 |

## Ⅲ. SLA 구성요소와 3계층 협약체계

| 구성요소 | 핵심 내용 |
|---|---|
| 서비스 정의 | 대상·사용자·시간·중요도·제외범위 |
| SLI/SLO | 가용성·지연·성공률·복구 등 지표와 목표 |
| 측정·보고 | 산식·데이터원·측정구간·검증·보고주기 |
| 책임·절차 | 장애통지·복구·Escalation·변경·Review |
| 보상·개선 | Service Credit·개선계획·반복위반 조치 |

```text
[고객] ←──── SLA ────→ [서비스 제공자]
                           ├─ OLA → 내부 App·DB·NW·보안팀
                           └─ UC  → Cloud·회선·장비 공급자
```

## Ⅳ. 업무 요구에서 지속 개선까지의 SLA 절차

```text
① 서비스·업무영향 식별 → ② SLI·산식·Source 정의 → ③ SLO·비용 합의
 → ④ OLA·UC 정렬 → ⑤ SLA 체결 → ⑥ 측정·보고·위반처리 → ⑦ Review·개선
```

| 단계 | 핵심 질문 | 산출물 |
|---|---|---|
| 분석 | 중단·지연이 업무에 미치는 영향은 무엇인가 | 서비스 Catalog·등급 |
| 설계 | 사용자가 체감하는 품질을 어떻게 측정하는가 | SLI·산식·Source |
| 합의 | 어느 목표를 어느 비용과 책임으로 보장하는가 | SLO·SLA·OLA·UC |
| 운영 | 위반을 어떻게 판정·통지·복구하는가 | 대시보드·보고·조치 |
| 개선 | 반복 실패의 원인과 목표를 어떻게 조정하는가 | Service Improvement Plan |

## Ⅴ. SLI·SLO·SLA 및 SLA·OLA·UC 비교

| 구분 | SLI | SLO | SLA |
|---|---|---|---|
| 의미 | 실제 측정지표 | 달성할 목표수준 | 고객과의 공식 약정 |
| 예 | 성공률·p95 지연 | 목표범위·기간 | 책임·보상 포함 계약 |
| 관계 | 측정값 | SLI의 목표 | SLO 중 계약한 수준 |

| 구분 | SLA | OLA | UC |
|---|---|---|---|
| 상대 | 고객-제공자 | 내부 지원조직 간 | 제공자-외부 공급자 |
| 목적 | 고객 서비스 보장 | 내부 책임·지원수준 | 외부 의존성 보장 |
| 정렬 | 최상위 목표 | SLA보다 충분히 엄격 | SLA 실패를 유발하지 않게 Back-to-back |

## Ⅵ. 체감품질과 책임을 왜곡하지 않는 고려사항

| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 지표는 달성했으나 고객 불만 | 평균 가용성·응답시간만 측정 | 핵심 사용자 Journey·성공률·백분위 지연 SLI | 체감품질 반영 |
| 목표 상향에 비용 급증 | 업무영향 없는 고가용성 일괄 요구 | 서비스 등급·오류예산·비용-위험 분석 | 적정 목표 합의 |
| 공급자 책임 공백 | SLA와 OLA·UC 기준 불일치 | 산식·시간대·제외조건·책임을 Back-to-back 정렬 | End-to-End 책임 확보 |
| 장애 제외 남용 | 계획정지·Force Majeure 범위 모호 | 제외조건·승인·증적·상한 명시 | 측정 신뢰성 확보 |
| Credit로 종료 | 보상만 있고 원인 제거 없음 | 반복위반 Problem 관리·개선계획·해지조건 | 재발 방지 |

## Ⅶ. 계약지표를 사용자 가치와 개선체계로 전환하는 결론

- **[사용자 Journey SLI와 오류예산 기반 운영]**: 인프라 가동률만 높아도 로그인·결제 같은 핵심 기능이 실패하면 서비스 가치는 달성되지 않음
- 나라면: 핵심 Journey별 성공률·지연·복구 SLI를 정하고 SLO의 미달 여유를 오류예산으로 운영하여 변경속도와 안정성을 함께 통제

#### 한줄 요약

- SLA의 완성은 Credit 정산이 아니라 고객이 체감하는 품질을 측정하고 반복 실패를 개선하는 상태임

## 1교시 10점 답안 발췌

```text
고객 요구 → SLI 지표 → SLO 목표 → SLA 계약
                                 ├─ OLA 내부협약
                                 └─ UC 외부계약
```

| 항목 | 필수 정의 |
|---|---|
| 지표 | 산식·Source·측정주기·구간 |
| 목표 | 업무영향·비용·허용위험 기반 SLO |
| 운영 | 보고·위반·복구·보상·개선 |

- 차별화: 핵심 Journey SLI와 오류예산으로 체감품질·변경속도를 함께 통제
