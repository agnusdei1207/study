## 연관 키워드

- 디자인 씽킹 (Design Thinking), 공감 (Empathy), d.school 5단계
- 더블 다이아몬드 (Double Diamond), POV (Point of View), 프로토타이핑
- Lean UX, MVP (Minimum Viable Product), 빠른 실패 (Fail Fast)

## Ⅰ. 디자인 씽킹의 개요

- 핵심 요약 : 사용자 공감과 빠른 프로토타이핑으로 혁신적 솔루션을 도출하는 인간 중심 문제 해결 방법론.
- 개념 : 디자이너의 감수성과 문제 해결 방식을 적용하여, 사용자의 잠재적 요구를 깊이 공감하고 (Empathy), 문제를 인간 중심으로 재정의하며, 신속한 프로토타이핑과 반복 테스트를 통해 혁신적 솔루션을 도출하는 창의적 문제 해결 방법론.
- 배경 및 필요성 : 공급자 중심의 기술 지향적 개발로 인한 시장 실패를 극복하고, 고객조차 언어로 표현하지 못하는 미충족 잠재 니즈 (Unmet Needs)를 발굴하여 차별화된 고객 경험 제공 필요.
- 주요 목적 : 고객 중심 혁신, 비즈니스 타당성과 기술적 실현 가능성의 조화, 빠른 실패 (Fail Fast)를 통한 개발 리스크 최소화.

## Ⅱ. 디자인 씽킹의 특징 및 장점

- 핵심 요약 : 인간 중심·가추적 사고·발산과 수렴·빠른 실패를 특징으로 하는 창의적 문제 해결.
1. **사용자 공감** : 관찰·인터뷰로 숨은 문제를 찾아 공급자 관점의 오판을 줄인다.
2. **문제 재정의** : 수집한 맥락을 POV로 정리해 해결할 대상을 분명히 한다.
3. **발산과 수렴** : 여러 대안을 탐색한 뒤 기준에 따라 선택해 성급한 단일 해법을 피한다.
4. **빠른 프로토타이핑** : 저비용 시작품으로 아이디어를 구체화해 개발 위험을 줄인다.
5. **반복 테스트** : 실제 사용자 반응을 반영해 가치와 사용성을 높인다.

## Ⅲ. 디자인 씽킹의 구조 (흐름)

- 핵심 요약 : d.school 5단계 (Empathize→Define→Ideate→Prototype→Test)와 더블 다이아몬드 반복 구조.
- 스탠포드 d.school 5단계 프로세스와 더블 다이아몬드 모델.

```text
[ 스탠포드 d.school 5단계 프로세스 ]
1. Empathize (공감)
        ↓
2. Define (정의)
        ↓
3. Ideate (아이디어)
        ↓
4. Prototype (시작품)
        ↓
5. Test (테스트) ──┐
        ↑          │
        └──────────┘  (이전 단계로 반복 환류)
```

```text
[ 더블 다이아몬드 (Double Diamond) 모델 ]
문제 영역 : 발산(공감) → 수렴(정의)
        ↓
솔루션 영역 : 발산(아이디어) → 수렴(프로토타입/테스트)
        ↓
혁신적 솔루션 도출
```

- Empathize (공감) : 사용자 관찰, 인터뷰, 감정 이입을 통해 숨겨진 페인포인트 발굴.
- Define (정의) : 공감 데이터를 분석하여 인간 중심의 관점 (POV, Point of View) 수립.
- Ideate (아이디어) : 브레인스토밍, 발산적 사고를 통해 다양한 창의적 대안 도출.
- Prototype (시작품) : 아이디어를 구체화하기 위한 신속하고 저렴한 프로토타입 제작.
- Test (테스트) : 사용자 대상 프로토타입 검증 및 피드백 수렴 후 이전 단계로 반복 환류.
- 더블 다이아몬드 (Double Diamond) 모델 : 문제 영역에서의 발산과 수렴 (공감-정의) → 솔루션 영역에서의 발산과 수렴 (아이디어-프로토타입/테스트)의 반복 구조.

## Ⅳ. 전통적 분석적 사고와의 비교

- 핵심 요약 : 과거 데이터·연역적 분석 중심에서 사용자 관찰·가추적 사고·빠른 프로토타이핑 중심으로의 전환.
- 전통적 분석적 사고와 디자인 씽킹의 대비 구조.

```text
[ 전통적 분석적 사고 ] 데이터·연역 → 완제품 일괄 개발
        ↓ 전환
[ 디자인 씽킹 ] 사용자 관찰·가추적 → 빠른 프로토타이핑
```

| 비교 항목 | 전통적 분석적 사고 | 디자인 씽킹 |
|---|---|---|
| 사고의 출발점 | 과거의 데이터 및 기존 시스템의 문제점 | 사용자의 감정, 행동, 일상 관찰 (인간 중심) |
| 접근 방식 | 연역적·귀납적 논리 분석 (수렴적) | 가추적 (Abductive) 사고, "만약 ~라면?" (발산과 수렴) |
| 해결책 도출 | 완전한 계획 수립 후 완제품 일괄 개발 | 신속한 종이/목업 프로토타이핑을 통한 빠른 피드백 |
| 실패에 대한 태도 | 실패는 회피해야 할 프로젝트 결함 | 실패는 학습과 개선을 위한 조기 피드백 기회 |

## Ⅴ. 디자인 씽킹의 한계와 방안

- 핵심 요약 : 기술·사업성 검증, 실행 연결, 학습 문화가 빠지면 워크숍 결과가 가치로 이어지지 않는다.

| 한계 | 방안 |
|---|---|
| 공감에만 집중하면 **실현 가능성·경제성**을 놓침 | 초기부터 개발·운영·재무 담당자가 제약과 비용을 함께 검토 |
| 결과가 **일회성 워크숍**으로 끝날 수 있음 | 프로토타입 검증 결과를 사용자 스토리·백로그로 연결 |
| 실패를 벌하면 **반복 실험**이 위축됨 | 검증 실패의 학습 내용을 기록하고 다음 가설에 반영 |

## Ⅵ. 디자인 씽킹에 대한 기술사적 제언

- 핵심 요약 : Lean UX 연계, 실전 프로토타이핑 도구, 심리적 안전감 기반 협업 문화.
- 애자일 및 린 스타트업과의 유기적 결합 (Lean UX) : 디자인 씽킹 (문제 발견) → 린 스타트업 (MVP, Minimum Viable Product 가설 검증) → 애자일 (스프린트 개발)의 연계 파이프라인 구축.
- 실전 프로토타이핑 도구 활용 : 피그마 (Figma) 등 인터랙티브 UI (User Interface) 목업 도구를 활용하여 비즈니스 분석 단계에서 실제 사용자 테스트를 수행함으로써 요구사항 재작업 비용 획기적 절감.
- 심리적 안전감 기반의 협업 문화 조성 : 어떤 엉뚱한 아이디어라도 비판하지 않는 'Yes, and...' 브레인스토밍 규칙을 조직 내에 정착시켜 진정한 창의적 파괴 장려.

## Ⅶ. 결론

- 핵심 요약 : 디자인 씽킹은 사용자 공감과 빠른 프로토타이핑으로 혁신을 이끄는 방법론이나 기술적 실현성과 조직 문화 뒷받침 필요.
- 요약 : 디자인 씽킹은 사용자의 잠재적 요구를 공감하고 빠른 프로토타이핑과 반복 테스트로 혁신적 솔루션을 도출하는 인간 중심 방법론.
- 시사점 : 애자일·린 스타트업과의 연계 파이프라인과 실전 프로토타이핑 도구, 실패 용인 문화를 갖추어 IT 프로젝트에 내재화 필요.
