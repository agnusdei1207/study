## Ⅰ. 디자인 씽킹의 개요

- 핵심 요약 : 사용자 공감과 신속한 프로토타이핑으로 혁신적 솔루션을 도출하는 인간 중심 문제 해결 방법론.
- 개념 : 디자이너의 문제 해결 방식을 전 과정에 적용해, 사용자의 잠재 요구를 **공감** (Empathy)으로 파악하고 문제를 인간 중심으로 재정의한 뒤, 프로토타이핑과 반복 테스트로 솔루션을 도출하는 **디자인 씽킹** (Design Thinking).
- 배경 및 필요성 : 공급자 중심의 기술 지향 개발로 인한 시장 실패를 줄이고, 고객도 말로 표현하지 못하는 **미충족 니즈** (Unmet Needs)를 발굴해 차별화된 고객 경험을 제공할 필요가 있음.
- 주요 목적 : 사용자 바람직성 (Desirability), 기술 실현 가능성 (Feasibility), 비즈니스 지속 가능성 (Viability)의 균형 확보, 고객 중심 혁신, **빠른 실패** (Fail Fast)를 통한 개발 리스크 최소화.

## Ⅱ. 디자인 씽킹의 특징 및 장점

- 핵심 요약 : 인간 중심 관찰, 문제 재정의, 가추적 사고, 발산과 수렴, 빠른 프로토타이핑이 저비용 조기 검증과 혁신 확률 향상으로 이어지는 체계.

1. 사용자 공감 : 관찰과 인터뷰로 드러나지 않는 니즈를 포착 → 공급자 관점의 오판과 요구사항 재작업 감소.
2. **POV** (Point of View, 사용자 관점의 문제 진술) 기반 문제 재정의 : 공감 데이터를 사용자 관점의 문제 진술로 압축 → 해결 대상과 설계 방향의 명확화.
3. **가추적 사고** (Abductive Thinking) : "만약 ~라면?" 가설로 기존 데이터에 없는 대안을 탐색 → 혁신 가능성 확대.
4. 발산과 수렴 : 다양한 대안을 넓게 탐색한 뒤 명확한 기준으로 좁힘 → 성급한 단일 해법 편향 방지.
5. **프로토타이핑** (Prototyping) : 저비용 시작품으로 아이디어를 조기 구체화 → 후반부 결함 수정 비용 절감.
6. 반복 테스트 : 실사용자 피드백을 환류해 가치와 사용성을 지속 향상.

## Ⅲ. 디자인 씽킹의 구조 (흐름)

- 핵심 요약 : 5단계 프로세스가 피드백을 따라 되돌아가는 반복 구조와, 문제 영역과 솔루션 영역에서 발산과 수렴이 번갈아 일어나는 더블 다이아몬드 구조의 이중 구조.
- **d.school 5단계** (Empathize, Define, Ideate, Prototype, Test) : 스탠퍼드 대학 디자인스쿨 (d.school)의 프로세스로, 테스트 결과에 따라 이전 단계로 환류.
- **더블 다이아몬드** (Double Diamond) : 영국 디자인 카운슬 (Design Council)이 제시한 모델로, 문제 영역과 솔루션 영역에서 발산과 수렴을 반복.

```text
[ d.school 5단계 ]

공감 (Empathize)
       ↓
정의 (Define)
       ↓
아이디어 (Ideate)
       ↓
시작품 (Prototype)
       ↓
테스트 (Test)
       ↑ 사용자 피드백으로 이전 단계 환류
```

```text
[ 더블 다이아몬드 ]

문제 영역 · 발산 : 맥락 탐색 (공감)
       ↓
문제 영역 · 수렴 : 문제 정의 (POV)
       ↓
솔루션 영역 · 발산 : 대안 생성 (아이디어)
       ↓
솔루션 영역 · 수렴 : 시작품·테스트
       ↓
혁신적 솔루션 도출
```

- 공감 : 사용자 관찰, 인터뷰, 감정 이입을 통해 숨겨진 페인 포인트 (Pain Point)를 발굴.
- 정의 : 공감 데이터 분석을 통해 인간 중심의 문제 관점을 수립.
- 아이디어 : 브레인스토밍과 발산적 사고로 다양한 대안을 도출.
- 시작품 : 아이디어를 구체화하기 위해 신속하고 저비용인 프로토타입을 제작.
- 테스트 : 사용자 대상 검증과 피드백을 수렴한 뒤 이전 단계로 환류.

## Ⅳ. 전통적 분석적 사고와의 비교

- 핵심 요약 : 과거 데이터와 연역 중심의 분석적 사고에서, 사용자 관찰과 가추적 사고, 신속 프로토타이핑 중심으로 전환.

| 비교 항목 | 전통적 분석적 사고 | 디자인 씽킹 |
|---|---|---|
| 사고의 출발점 | 과거의 데이터와 기존 시스템의 문제점 | 사용자의 감정, 행동, 일상 관찰 (인간 중심) |
| 추론 방식 | 연역적·귀납적 논리 분석 (수렴적) | 가추적 사고, "만약 ~라면?"에 기반한 발산과 수렴 |
| 해결책 도출 | 완전한 계획 수립 후 완제품 일괄 개발 | 종이·목업 등 저비용 프로토타이핑과 빠른 피드백 |
| 실패에 대한 태도 | 회피 대상인 프로젝트 결함 | 학습과 개선을 위한 조기 피드백 기회 |
| 평가 기준 | 기술 사양과 일정 준수 | 사용자 가치와 경험 개선 |

## Ⅴ. 디자인 씽킹의 한계와 방안

- 핵심 요약 : 실현 가능성 검토 누락, 일회성 워크숍, 실패 처벌 문화를 공동 검토, 백로그 연결, 학습 기록으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 실현 가능성·경제성 검토 누락 | 아이디어가 사용자 바람직성에 치우쳐 기술·비용 제약 미반영 | 초기부터 개발·운영·재무 담당자가 제약과 비용을 공동 검토 | 사업 타당성 평가 통과율 |
| 일회성 워크숍 종결 | 산출물이 실행 체계와 단절되어 가치 전환 실패 | 프로토타입 검증 결과를 사용자 스토리와 백로그로 전환 | 백로그 반영률 |
| 실패 처벌 문화 | 반복 실험 위축과 조직 학습 정체 | 검증 실패의 학습 내용을 기록하고 다음 가설에 반영 | 가설 검증 주기, 재실험률 |

## Ⅵ. 디자인 씽킹에 대한 기술사적 제언

- 핵심 요약 : Lean UX 연계 파이프라인, 실전 프로토타이핑 도구 활용, 심리적 안전성 기반 협업 문화를 정착.

1. **Lean UX** 연계 파이프라인 : 디자인 씽킹으로 문제를 발견하고, 린 스타트업의 **최소 기능 제품** (MVP, Minimum Viable Product)으로 가설을 검증한 뒤, 애자일 스프린트로 개발하는 흐름을 구축하는 것이 바람직하다.
2. 실전 프로토타이핑 도구 활용 : 피그마 (Figma) 등 인터랙티브 UI 목업 도구로 요구사항 분석 단계에서 실사용자 테스트를 먼저 수행해, 요구사항 재작업 비용을 줄여야 한다.
3. **심리적 안전성** (psychological safety) 기반 협업 문화 : 비판을 금지하고 아이디어를 확장하는 'Yes, and...' 브레인스토밍 규칙을 정착시켜 혁신을 장려해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 디자인 씽킹은 사용자 공감과 신속한 프로토타이핑으로 혁신을 이끄는 인간 중심 방법론이며, 기술 실현성과 조직 문화의 뒷받침이 필요함.
- 발견과 검증을 개발 파이프라인에 연결하고 실패를 학습으로 기록하는 문화를 갖출 때 IT 프로젝트에 내재화할 수 있음.
