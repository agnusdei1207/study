## 연관 키워드

- **디자인 씽킹(Design Thinking)**, **공감(Empathy)**, **d.school 5단계**
- **더블 다이아몬드(Double Diamond)**, **POV(Point of View)**, **프로토타이핑(Prototyping)**
- **가추적 사고(Abductive Thinking)**, **Lean UX**, **MVP(Minimum Viable Product)**, **빠른 실패(Fail Fast)**

## Ⅰ. 디자인 씽킹의 개요

- 핵심 요약 : **사용자 공감**과 신속한 **프로토타이핑**으로 혁신적 솔루션을 도출하는 인간 중심 문제 해결 방법론.
- 개념 : 디자이너의 감수성과 문제 해결 방식을 전 과정에 적용하여, 사용자의 잠재적 요구를 깊이 **공감**(Empathy)하고 문제를 인간 중심으로 재정의한 뒤 신속한 프로토타이핑과 반복 테스트로 혁신적 솔루션을 도출하는 창의적 문제 해결 방법론.
- 배경 및 필요성 : 공급자 중심의 기술 지향적 개발로 인한 시장 실패를 극복하고, 고객조차 언어로 표현하지 못하는 **미충족 잠재 니즈**(Unmet Needs)를 발굴하여 차별화된 고객 경험 제공 필요.
- 주요 목적 : 사용자 바람직성 (Desirability)·기술 실현 가능성 (Feasibility)·비즈니스 지속 가능성 (Viability)의 균형, **고객 중심 혁신**, **빠른 실패**(Fail Fast)를 통한 개발 리스크 최소화.

## Ⅱ. 디자인 씽킹의 특징 및 장점

- 핵심 요약 : 인간 중심·가추적 사고·발산과 수렴·빠른 실패가 **저비용 조기 검증**과 **혁신 확률 제고**로 연결되는 창의적 문제 해결 체계.
1. **사용자 공감(Empathy)** : 관찰·인터뷰로 드러나지 않는 니즈를 포착하여 공급자 관점 오판과 요구사항 재작업 최소화.
2. **문제 재정의(POV)** : 공감 데이터를 인간 중심 관점으로 압축하여 해결 대상과 설계 방향의 명확화.
3. **가추적 사고(Abductive Thinking)** : "만약 ~라면?" 가설로 기존 데이터에 없는 대안을 탐색하여 혁신 가능성 확대.
4. **발산과 수렴** : 다양한 대안 탐색 후 명확한 기준으로 좁혀 성급한 단일 해법 편향 방지.
5. **신속 프로토타이핑(Prototyping)** : 저비용 시작품으로 아이디어를 조기 구체화하여 후반부 결함 수정 비용 절감.
6. **반복 테스트** : 실사용자 피드백 환류를 통한 가치와 사용성의 지속 향상.

## Ⅲ. 디자인 씽킹의 구조 (흐름)

- 핵심 요약 : **d.school 5단계** (Empathize→Define→Ideate→Prototype→Test)와 **더블 다이아몬드** 발산·수렴 반복 구조.
- 스탠퍼드 대학 디자인스쿨 (d.school) 5단계 프로세스와 영국 디자인 카운슬 (Design Council)의 더블 다이아몬드 모델.

```text
[ Stanford d.school 5-Stage Process ]

+-----------+
| Empathize |<--------------------------------+
+-----------+                                 |
       |                                      |
       v                                      |
+-----------+                                 |
|   Define  |                                 |
+-----------+                                 |
       |            반복 환류 (Iterate)        |
       v                                      |
+-----------+                                 |
|   Ideate  |                                 |
+-----------+                                 |
       |                                      |
       v                                      |
+-----------+                                 |
| Prototype |                                 |
+-----------+                                 |
       |                                      |
       v                                      |
+-----------+    사용자 피드백                 |
|    Test   |---------------------------------+
+-----------+
```

```text
[ Double Diamond Model ]

+--------------------------+
| 문제 영역 · 발산 (탐색)   |
| Empathize : 맥락 탐색    |
+--------------------------+
             |
             v
+--------------------------+
| 문제 영역 · 수렴 (정의)   |
| Define : POV 수립        |
+--------------------------+
             |
             v
+--------------------------+
| 솔루션 영역 · 발산        |
| Ideate : 대안 생성       |
+--------------------------+
             |
             v
+--------------------------+
| 솔루션 영역 · 수렴        |
| Prototype · Test         |
+--------------------------+
             |
             v
      혁신적 솔루션 도출
```

- Empathize (공감) : 사용자 관찰, 인터뷰, 감정 이입을 통한 숨겨진 페인포인트 (Pain Point) 발굴.
- Define (정의) : 공감 데이터 분석을 통한 인간 중심의 문제 관점 (POV, Point of View) 수립.
- Ideate (아이디어) : 브레인스토밍과 발산적 사고를 통한 다양한 창의적 대안 도출.
- Prototype (시작품) : 아이디어 구체화를 위한 신속·저비용 프로토타입 제작.
- Test (테스트) : 사용자 대상 검증과 피드백 수렴 후 이전 단계 환류.
- 더블 다이아몬드 (Double Diamond) : 문제 영역의 발산·수렴 (공감-정의)과 솔루션 영역의 발산·수렴 (아이디어-시작품/테스트)의 반복 구조.

## Ⅳ. 전통적 분석적 사고와의 비교

- 핵심 요약 : 과거 데이터·연역 중심의 **분석적 사고**에서 사용자 관찰·**가추적 사고**·신속 프로토타이핑 중심으로의 전환.
- 전통적 분석적 사고와 디자인 씽킹의 대비 구조.

```text
[ 전통적 분석적 사고 ] 데이터·연역 → 완제품 일괄 개발
        ↓ 전환
[ 디자인 씽킹 ] 사용자 관찰·가추적 → 신속 프로토타이핑
```

| 비교 항목 | 전통적 분석적 사고 | 디자인 씽킹 |
|---|---|---|
| 사고의 출발점 | 과거의 데이터 및 기존 시스템의 문제점 | 사용자의 감정, 행동, 일상 관찰 (인간 중심) |
| 추론 방식 | 연역적·귀납적 논리 분석 (수렴적) | 가추적 (Abductive) 사고, "만약 ~라면?" (발산과 수렴) |
| 해결책 도출 | 완전한 계획 수립 후 완제품 일괄 개발 | 종이·목업 등 저비용 프로토타이핑과 빠른 피드백 |
| 실패에 대한 태도 | 회피 대상인 프로젝트 결함 | 학습과 개선을 위한 조기 피드백 기회 |
| 평가 기준 | 기술 사양과 일정 준수 | 사용자 가치와 경험 개선 |

## Ⅴ. 디자인 씽킹의 한계와 방안

- 핵심 요약 : **실현 가능성 검토 누락**, **일회성 워크숍**, **실패 처벌 문화**를 공동 검토, 백로그 연결, 학습 기록으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 실현 가능성·경제성 검토 누락 | 아이디어가 사용자 바람직성에 치우쳐 기술·비용 제약 미반영 | 초기부터 개발·운영·재무 담당자의 제약과 비용 공동 검토 | 사업 타당성 평가 통과율 |
| 일회성 워크숍 종결 | 산출물이 실행 체계와 단절되어 가치 전환 실패 | 프로토타입 검증 결과의 사용자 스토리·백로그 전환 | 백로그 반영률 |
| 실패 처벌 문화 | 반복 실험 위축과 조직 학습 정체 | 검증 실패의 학습 내용 기록과 다음 가설 반영 | 가설 검증 주기, 재실험률 |

## Ⅵ. 디자인 씽킹에 대한 기술사적 제언

- 핵심 요약 : **Lean UX 연계**, **실전 프로토타이핑 도구**, **심리적 안전성 (psychological safety) 기반 협업 문화** 정착.
- 애자일·린 스타트업과의 유기적 결합 (Lean UX) : 디자인 씽킹 (문제 발견) → 린 스타트업의 MVP (Minimum Viable Product) 가설 검증 → 애자일 (스프린트 개발)로 이어지는 연계 파이프라인 구축.
- 실전 프로토타이핑 도구 활용 : 피그마 (Figma) 등 인터랙티브 UI (User Interface) 목업 도구로 요구사항 분석 단계에서 실사용자 테스트 선행 수행, 요구사항 재작업 비용 절감.
- 심리적 안전성 (psychological safety) 기반의 협업 문화 조성 : 비판 금지와 아이디어 확장의 'Yes, and...' 브레인스토밍 규칙 정착을 통한 혁신 장려.

## Ⅶ. 결론

- 핵심 요약 : **디자인 씽킹**은 사용자 공감과 신속 프로토타이핑으로 혁신을 이끄는 인간 중심 방법론, 기술 실현성과 조직 문화 뒷받침 필요.
- 요약 : 사용자의 잠재 니즈 공감과 빠른 프로토타이핑·반복 테스트를 통한 혁신적 솔루션 도출 방법론.
- 시사점 : Lean UX 연계 파이프라인, 실전 프로토타이핑 도구, 실패 용인 문화를 갖춘 IT 프로젝트 내재화 필요.
