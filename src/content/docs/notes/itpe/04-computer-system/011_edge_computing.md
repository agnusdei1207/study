## Ⅰ. 엣지 컴퓨팅(Edge Computing)의 개요

- 개념 : 중앙 집중형 클라우드 데이터센터로 모든 데이터를 전송하지 않고, 데이터가 생성되는 사용자 단말, IoT(Internet of Things) 센서, 기지국 등 **네트워크 말단** (Edge)에서 데이터를 실시간 수집, 처리, 분석하는 분산 컴퓨팅 아키텍처.
- 배경 및 필요성 : 자율주행, 스마트 팩토리, 원격 의료 등 **초저지연** (Ultra-Low Latency)과 대규모 데이터 스트리밍 처리가 요구되는 환경에서 중앙 클라우드의 네트워크 대역폭 포화와 지연 한계를 극복하기 위해 대두됨.
- 핵심 목적 : 네트워크 전송 지연시간의 밀리초(ms) 단위 단축, 백본망 트래픽 부하 경감, 민감 개인정보의 로컬 처리를 통한 프라이버시 및 보안 강화.

## Ⅱ. 엣지 컴퓨팅(Edge Computing)의 핵심 아키텍처 및 동작 메커니즘

엣지 컴퓨팅은 디바이스 엣지, 온프레미스/기지국 엣지(MEC, Multi-access Edge Computing), 중앙 클라우드로 이어지는 계층형 분산 처리 토폴로지를 구성함.

```text
[ 엣지 컴퓨팅 계층형 처리 토폴로지 ]

+---------------------------------------------------------------+
| Central Cloud (중앙 클라우드: AWS, Azure, GCP IDC)             |
|   - 글로벌 빅데이터 분석, 파운데이션 모델 학습, 장기 데이터 보관   |
+---------------------------------------------------------------+
                                ▲
                                │ 메타데이터 및 집계 결과 (WAN)
                                ▼
+---------------------------------------------------------------+
| Near Edge / MEC (통신사 기지국, 5G 코어망, 지역 거점 IDC)     |
|   - 지역 단위 캐싱, 실시간 비디오 스트리밍 트랜스코딩         |
+---------------------------------------------------------------+
                                ▲
                                │ 서브 밀리초 통신 (5G URLLC)
                                ▼
+---------------------------------------------------------------+
| Far Edge / On-Premise Gateway (스마트팩토리, 자율주행 차량)   |
|   - K3s/KubeEdge 기반 실시간 추론 제어, 데이터 필터링        |
+---------------------------------------------------------------+
                                ▲
                                │ Fieldbus / BLE / Zigbee / Wi-Fi
                                ▼
+---------------------------------------------------------------+
| Device Edge / IoT Sensor (카메라, 로봇 암, 스마트 센서)       |
|   - 원시 센서 데이터 수집 및 온디바이스 NPU 1차 경량 판정    |
+---------------------------------------------------------------+
```

- **데이터 선별(Data Triage)** : 현장에서 실시간 처리가 필요한 데이터는 엣지에서 즉시 판정하고, 통계 및 모델 재학습용 데이터만 압축하여 중앙으로 전송.
- **MEC(Multi-access Edge Computing)** : 통신사 기지국 및 라우팅 경로에 가상화 인프라를 배치하여 무선 구간 왕복 지연시간(RTT, Round-Trip Time)을 5ms 이하로 단축.
- **엣지 컨테이너 오케스트레이션** : KubeEdge, K3s, OpenYurt 등을 활용하여 중앙 클라우드에서 수만 개의 분산 엣지 노드로 앱 배포 일괄 통제.
- **오프라인 자율 생존성** : 중앙 클라우드와의 백홀(Backhaul) 네트워크 단절 시에도 엣지 로컬 노드가 독립적으로 비즈니스 로직 정상 수행.

## Ⅲ. 엣지 컴퓨팅(Edge Computing)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 중앙 클라우드 컴퓨팅 | 포그 컴퓨팅 (Fog) | 엣지 컴퓨팅 (Edge) |
|---|---|---|---|
| **처리 위치** | 수백 km 이상 원격 하이퍼스케일 IDC(Internet Data Center) | 로컬 LAN(Local Area Network) 또는 엔터프라이즈 게이트웨이 | 데이터가 생성되는 단말 및 인접 기기 |
| **응답 지연(RTT)** | 수십~수백 ms (네트워크 변동성) | 10~50 ms 수준 | 1~10 ms 이하 (실시간 보장) |
| **컴퓨팅 파워** | 무제한에 가까운 확장성 (HPC(High-Performance Computing)/GPU(Graphics Processing Unit)) | 중간 수준의 서버 클러스터 | 제한된 임베디드 SoC(System on a Chip) 및 가속기 |
| **네트워크 의존도** | 인터넷 WAN(Wide Area Network) 상시 연결 필수 | 로컬 네트워크 의존 | 간헐적 오프라인 상태에서도 자율 가동 |
| **보안 및 규제** | 데이터 중앙 집중화에 따른 유출 위험 | 엔터프라이즈 경계 내 1차 방어 | 민감 데이터의 로컬 격리 및 주권 준수 |

- 엣지 컴퓨팅은 클라우드를 대체하는 것이 아니라, 실시간 처리는 엣지, 대규모 배치 분석 및 AI(Artificial Intelligence) 모델 학습은 중앙 클라우드가 담당하는 상호 보완적 아키텍처임.

## Ⅳ. 엣지 컴퓨팅(Edge Computing)의 주요 한계점 및 해결 방안

- 분산 엣지 기기의 물리적 취약성 및 보안 관리 한계 :
  - 한계점 : 원격지, 도로변, 공장 현장에 노출된 엣지 장비는 물리적 탈취, 펌웨어 변조, 무단 접속 공격에 매우 취약함.
  - 해결 방안 : 하드웨어 기반 보안 칩(TPM 2.0 / Secure Element) 내장, 제로 트러스트(Zero Trust) 상호 mTLS 인증, 디스크 암호화(LUKS) 적용.
- 하드웨어 자원 제약 및 배터리·발열 병목 :
  - 한계점 : 엣지 노드는 전력, 방열, 메모리 크기(수 GB 수준)가 극도로 제한되어 복잡한 거대 AI 모델 구동 불가.
  - 해결 방안 : AI 모델 양자화(INT8/INT4), 프루닝(Pruning), 지식 증류(Knowledge Distillation) 및 초경량 런타임(TensorRT-Edge, ONNX) 탑재.
- 대규모 분산 노드 관리 및 무선 **펌웨어(OTA, Over-the-Air)** 업데이트 난제 :
  - 한계점 : 수만 대의 이종 엣지 디바이스에 대한 소프트웨어 배포 실패 및 네트워크 단절 시 벽돌(Bricking) 현상 발생 리스크.
  - 해결 방안 : A/B 듀얼 파티션 기반 안전한 OTA 롤백 시스템, GitOps 선언적 엣지 배포 파이프라인 수립.

## Ⅴ. 엣지 컴퓨팅(Edge Computing) 적용 및 발전을 위한 기술사적 제언

- 5G/6G **특화망(이음5G)** 과의 융합 : 스마트팩토리 및 항만 물류 현장에서 전용 5G 무선망과 MEC 엣지 컴퓨팅을 결합하여 무선 제어의 실시간성과 보안성 동시 확보.
- 엣지 AI 컴파일러 표준화 역량 확보 : 다양한 엣지 실리콘(ARM, RISC-V, 전용 NPU(Neural Processing Unit))을 아우르는 TVM 등 개방형 컴파일러 기반 소프트웨어 추상화 계층 확립 필요.
- 클라우드-엣지 일체형 거버넌스 프레임워크 구축 : 인프라 배포, 로그 수집, 보안 패치가 단일 통제면(Single Control Plane)에서 제어되도록 플랫폼 엔지니어링 추진 권장.
