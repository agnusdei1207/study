## 2~4교시 25점 답안

## Ⅰ. 엣지 컴퓨팅의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **엣지 컴퓨팅 (Edge Computing)** 은 데이터 발생원 가까이에서 계산·저장·서비스를 수행하는 분산 컴퓨팅 방식 |
| 목적 | 원격 왕복 지연과 불필요한 데이터 전송 감소 |

## Ⅱ. 엣지 컴퓨팅의 특징

| 특징 | 의미 |
|---|---|
| 현장 근접 처리 | 원격 왕복 지연과 전송량 축소 |
| 제한 자원 | 노드별 연산·저장 한도에 맞춘 기능 배치 |
| 분산 운영 | 장소별 배포·장애·모델 품질 관리 필요 |

## Ⅲ. 계층 구조와 처리 흐름

```text
디바이스 ──원시 데이터──→ 엣지 노드(선별·추론)
   ↑ 현장 제어                  │ 요약·예외 데이터
   └───────────────────────────┘          ↓
                        코어 클라우드(집계·모델 학습)
                                  │ 검증된 모델 갱신
                                  └────────→ 엣지 노드
```

| 계층 | 주요 역할 |
|---|---|
| 디바이스 | 센서 데이터 생성, 현장 기기 제어 |
| 엣지 노드 | 실시간 필터링·추론, 로컬 캐시 |
| 코어 클라우드 | 대규모 데이터 집계, 모델 학습 |

**현장 모델 품질의 환류**

```text
엣지 추론 → 오류·예외 표본 감지 → 중앙 검증·재학습
    ↑                                  ↓
현장별 지연·정확도 확인 ← 단계 배포·롤백 기준
```

## Ⅳ. 클라우드 컴퓨팅과 비교

| 비교축 | 엣지 컴퓨팅 | 클라우드 컴퓨팅 |
|---|---|---|
| 처리 위치 | 단말·게이트웨이·기지국 인근 | 원격 데이터센터 |
| 응답 특성 | 짧은 왕복 경로 | 네트워크 왕복 지연 존재 |
| 자원 규모 | 제한적·분산 | 대규모·중앙 집중 |
| 데이터 처리 | 필요한 데이터 선별·현장 처리 | 장기 저장·집계·대규모 분석 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 분산 노드의 배포·유지보수 부담 | 중앙 관리와 단계적 원격 배포·롤백 적용 |
| 현장 장비의 제한된 연산·저장 자원 | 지연 요구와 자원 한계에 맞춰 추론·전처리 범위 조정 |
| 네트워크 단절 시 서비스 영향 | 필수 현장 기능을 엣지에서 지속하도록 설계 |
| 현장 환경 변화로 추론 정확도 저하 | 예외 표본을 중앙 검증하고 모델을 단계적으로 재배포 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
원격 엣지 디바이스의 제한된 컴퓨팅 자원을 고려하여 K3s/MicroK8s 기반 경량 오케스트레이션을 적용하고, 단절 상태에서도 자율 구동되는 오프라인 퍼스트(Offline-First) 동기화 아키텍처 필수.

### 2. 아키텍처 및 상세 메커니즘
```text
[ 단말 / IoT 센서 디바이스 계층 ] ──(초저지연 무선 통신: 5G/Wi-Fi 6)──>
                 │
                 ▼
┌────────────────────────────────────────────────────────┐
│ [ 엣지 노드 (Edge Node / MEC) ]                        │
│   - 실시간 데이터 필터링 & 노이즈 제거                 │
│   - 온디바이스 경량 AI 추론 (10ms 이내 실시간 제어)    │
│   - 로컬 데이터 암호화 & 비식별화 처리                 │
│   - 로컬 캐시 및 단절 시 자율 로컬 제어               │
└────────────────┬───────────────────────────────────────┘
                 │ (요약/집계 데이터 및 이상 이벤트만 백본 전송)
                 ▼
┌────────────────────────────────────────────────────────┐
│ [ 중앙 집중형 클라우드 (Central Cloud) ]               │
│   - 전사 빅데이터 분석 & 대규모 AI 모델 재학습         │
│   - 엣지 디바이스 원격 펌웨어 배포 및 통합 정책 제어  │
└────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 비교 축 | 엣지 컴퓨팅 (Edge Computing) | 클라우드 컴퓨팅 (Central Cloud) | 포그 컴퓨팅 (Fog Computing) |
|---|---|---|---|
| **연산 위치** | 데이터 발생 소스 말단 (기지국, 게이트웨이) | 원격 대규모 중앙 집중식 데이터센터 | 엣지와 클라우드 사이 로컬 LAN/게이트웨이 |
| **응답 지연 (Latency)**| 초저지연 (수 밀리초, < 5ms) | 상대적 고지연 (수십~수백 밀리초) | 저지연 (수십 밀리초 이내) |
| **대역폭 소비** | 매우 적음 (현장 정제 후 요약본만 전송) | 높음 (모든 로우 데이터 백본 전송) | 중간 수준 |
| **프라이버시** | 우수 (민감 데이터 현장 유지/비식별) | 민감 데이터 전송에 따른 침해 우려 | 로컬 네트워크 내 통제 |
| **주요 적용 사례** | 자율주행, 스마트팩토리 로봇 제어 | 대규모 모델 학습, ERP, 통계 분석 | 스마트 시티 관제, 분산 빌딩 제어 |
