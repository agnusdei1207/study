## 연관 키워드

- 랙스케일 AI 시스템(Rack-scale AI System), GB200 NVL72, GB300 NVL72, 가속 노드
- NVLink, NVLink 스위치, 스케일업, 단일 NVLink 도메인
- 직접 칩 액체 냉각(DLC, Direct-to-Chip Liquid Cooling), CDU(Cooling Distribution Unit), PUE(Power Usage Effectiveness)
- 텐서 병렬화(Tensor Parallelism), 장애 도메인(Fault Domain), 버스바(Busbar)

## Ⅰ. 랙스케일 AI 시스템의 개요

- 핵심 요약 : 랙 한 개를 하나의 가속 노드처럼 묶어 랙 내부 GPU 통신을 고대역폭 패브릭으로 처리하는 AI(Artificial Intelligence) 인프라 구성 방식.
- 개념 : **랙스케일 AI 시스템** (Rack-scale AI System)은 서버 한 대 단위가 아니라 랙 전체를 기준으로 GPU(Graphics Processing Unit)와 CPU(Central Processing Unit), 고속 스위치 패브릭, 전력 공급과 액체 냉각 설비를 함께 설계해 하나의 대형 가속기처럼 운용하는 **스케일업** (Scale-up) 구성.
- 배경 및 필요성 : 거대언어모델의 학습과 추론은 GPU 사이의 통신 대역폭에 크게 좌우되는데, 서버 사이를 외부 네트워크로 잇는 방식은 대역폭과 지연 면에서 한계가 있음. 그래서 랙 안의 연결을 외부 네트워크가 아닌 내부 패브릭으로 바꾸는 필요가 생김.
- 주요 목적 : 랙 내부 GPU 간 고대역폭 통신 확보, 대규모 모델의 병렬 처리 효율 향상, 고밀도 전력과 냉각 문제를 설계 단계에서 함께 해결.

## Ⅱ. 랙스케일 AI 시스템의 특징 및 장점

- 핵심 요약 : 내부 고속 패브릭, 큰 GPU 풀, 직접 액체 냉각이 통신 효율과 전력 효율로 이어지는 구조.

1. 고속 스위치 패브릭 : 연산 트레이와 **NVLink** 스위치 트레이를 후면 구리 배선으로 연결 → 광 모듈 없이 랙 내부 통신을 구성해 전력과 지연 부담 감소.
2. GPU 풀링 : 72개 GPU를 하나의 NVLink 도메인으로 묶어 소프트웨어에는 큰 단일 GPU처럼 보이게 함 → 텐서 병렬화에서 GPU 간 통신 제약 완화.
3. 대역폭 : NVLink 5 기준 GPU당 1.8TB/s, 시스템 전체 약 130TB/s 수준(NVIDIA 발표치) → 모델을 나눠 계산할 때 통신 대기 시간 감소.
4. 직접 칩 액체 냉각(DLC, Direct-to-Chip Liquid Cooling) : 발열이 큰 칩에 냉각판을 직접 붙여 열을 제거 → 공랭으로는 감당하기 어려운 고밀도 랙을 운용하고 데이터센터 효율 지표인 PUE(Power Usage Effectiveness) 개선.

## Ⅲ. 랙스케일 AI 시스템의 구조 (흐름)

- 핵심 요약 : 연산 트레이와 스위치 트레이가 후면 패브릭으로 묶이고, 전력과 냉각이 랙 단위로 공급되는 구조.
- **CDU** (Cooling Distribution Unit) : 냉각수를 순환시키고 열을 교환해 칩의 열을 건물 설비로 넘기는 냉각 분배 장치.

```text
[ 랙 구성 계층 ]

랙 1개 (단일 가속 노드)
   ↓
연산 트레이 18개 (GPU 72 · CPU 36)
   ↓ 후면 구리 백플레인
NVLink 스위치 트레이 9개
   ↓
GPU 72개 단일 NVLink 도메인
```

```text
[ 전력·냉각 흐름 ]

버스바로 고밀도 전력 공급
   ↓
GPU·CPU 발열
   ↓
냉각판에서 직접 액체 냉각
   ↓
CDU가 냉각수 순환과 열교환
   ↓
데이터센터 냉각 설비로 열 배출
```

## Ⅳ. 랙스케일 AI 시스템과 기존 서버 노드의 비교

- 핵심 요약 : 랙 단위 통합 구성은 GPU 간 통신 대역폭과 랙당 전력 밀도를 높이는 대신, 전력과 냉각 인프라 요구를 함께 키우는 구도.

| 비교 축 | GB200 NVL72 (Blackwell) | GB300 NVL72 (Blackwell Ultra) | HGX H100 (8-GPU 노드) |
| --- | --- | --- | --- |
| GPU·CPU 구성 | GPU 72개, Grace CPU 36개 | GPU 72개 (Blackwell Ultra) 기반 후속 구성 | 노드당 Hopper GPU 8개 |
| GPU 간 인터커넥트 | NVLink 5, GPU당 1.8TB/s | NVLink 5 계열 | NVLink 4, GPU당 900GB/s, 노드 내부 |
| GPU 메모리 | HBM3E 계열 | HBM3E 계열, 용량 확대 | HBM3 계열 |
| 냉각 방식 | 전면 액체 냉각 | 전면 액체 냉각 | 공랭 중심, 구성에 따라 수랭 선택 |
| 랙당 전력 수준 | 120kW급 | 120kW급 이상 | 랙 기준으로 상대적으로 낮음 |

- 선택 기준 : 모델 규모와 GPU 간 통신 요구가 큰지, 기존 데이터센터의 전력과 냉각 여유가 있는지를 함께 보고 노드형과 랙형을 고름.

## Ⅴ. 랙스케일 AI 시스템의 한계와 방안

- 핵심 요약 : 고밀도 전력, 냉각수 누수와 펌프 장애, 랙 중량을 배전 재설계, 이중화, 하중 보강으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 고밀도 전력 공급 | 랙당 전력이 기존 상용 데이터센터의 설계 범위를 크게 넘어 수전·배전 용량 부족 | 고전압 직류 배전과 버스바 방식 도입, 모듈형 전력 분할 배치 | 랙별 전력 사용률, 배전 여유율 |
| 냉각수 누수와 펌프 단일 장애점 | 누수는 고가 장비 손상으로 이어지고, 순환 펌프 고장은 열 과부하와 가동 중단 유발 | 누수 감지·차단 체계, 펌프와 CDU의 이중화 및 제어 로직 설계 | 누수 감지 건수, 냉각 온도 편차 |
| 랙 중량과 설치 하중 | 랙 무게가 기존 바닥의 하중 기준을 넘어 설치와 운반에 제약 | 하중 해석에 따른 바닥 보강, 설치 경로 사전 점검 | 바닥 하중 여유율, 설치 소요 기간 |

## Ⅵ. 랙스케일 AI 시스템에 대한 기술사적 제언

- 핵심 요약 : 인프라 선행 진단, 장애 격리 설계, 고밀도 설비 기준의 제도화가 함께 가야 랙스케일 도입의 효과가 확보됨.
- 데이터센터 사업자는 도입에 앞서 변전 설비, 냉각 배관, 바닥 하중을 진단하고 단계적 개조 계획을 세우면 설비 투자의 낭비를 줄일 수 있다.
- 운영 조직은 랙 전체가 하나의 NVLink 도메인으로 묶이므로, 장애가 랙 단위로 번지지 않도록 장애 도메인(Fault Domain)을 나누는 격리 설계와 체크포인트 주기 관리를 함께 마련해야 한다.
- 정책 측면에서는 고밀도 AI 데이터센터의 전력과 냉각 기준을 설비 인허가 단계에 반영하고, 전력 계통 운영 기관과의 협의 절차를 정해 두는 것이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : 랙스케일 AI 시스템은 랙 전체를 하나의 가속 노드로 묶어 GPU 통신 병목을 줄이는 인프라 구성.
- 시사점 : AI 연산 경쟁의 축이 칩 성능에서 전력·냉각·설치 조건까지 포함한 인프라 설계 역량으로 옮겨가고 있음.
