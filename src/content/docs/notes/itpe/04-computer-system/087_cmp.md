## 30초 인출

- 본질: **클라우드 관리 플랫폼 (Cloud Management Platform, CMP)은** 클라우드 자원·서비스를 조회·통제·자동화하는 관리 도구의 집합
- 메커니즘: 운영자 요청 → 관리 정책·워크플로 → 공급자 API·관리 인터페이스 → 자원 변경·상태·비용을 통합 조회

- 통찰: 한계: 공급자별 권한·정책 차이로 동일 요청의 실행 결과가 어긋남 → 방안: 공통 승인·감사 기준과 제공자별 실패 동작을 API 실행 경로에 연결

<details>
<summary>핵심 용어</summary>

- **클라우드 관리 플랫폼 (Cloud Management Platform, CMP)** : 클라우드 자원·서비스의 운영·관리 기능을 제공하는 플랫폼; 범위와 기능은 제품·환경별로 다름
- **클라우드 관리 브로커 (Cloud Management Broker)** : 소비자와 클라우드 제공자 사이에서 서비스 관리·연계 기능을 수행하는 역할
- **프로비저닝 (Provisioning)** : 요청·정책에 따라 클라우드 자원을 생성·설정하는 작업
- **FinOps (Cloud Financial Management)** : 기술·재무·업무 조직이 클라우드 사용·비용을 함께 관리하는 실천 분야
- **RBAC (Role-Based Access Control)** : 역할에 따라 사용자 권한을 부여하는 접근통제 방식
</details>

## 2~4교시 25점 답안

## Ⅰ. CMP의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **클라우드 관리 플랫폼 (Cloud Management Platform, CMP)은** 클라우드 자원·서비스의 조회·설정·운영을 지원하는 관리 기능의 집합 |
| 목적 | 관리 업무의 가시성·일관성·자동화를 지원하는 것 |

## Ⅱ. 관리 평면 통합의 특징

| 특징 | 의미 |
|---|---|
| 공통 카탈로그 | 승인된 자원 유형·설정을 요청 화면으로 제공 |
| 정책 자동화 | 권한·예산·승인을 확인한 뒤 공급자 API 호출 |
| 운영 가시성 | 자산·상태·성능·비용·감사를 업무 기준으로 모음 |

## Ⅲ. CMP 요청·실행·환류 체계

```text
업무 자원 요청 → 카탈로그·권한·예산·승인 검증
                              ↓
CMP 워크플로 → 공급자별 어댑터·API → 클라우드 자원 생성·변경
     ↑                                      ↓
반납·개선 결정 ← 자산·상태·사용량·비용·정책 위반 수집
```

공통 요청이라도 공급자별 API·자원 모델이 달라 미지원 기능, 호출 실패, 재시도·되돌리기를 워크플로에서 정의해야 한다.

## Ⅳ. 통합 관리 영역과 검증 기준의 관계

| 영역 | CMP 기능 | 검증 기준 |
|---|---|---|
| 자원 생명주기 | 생성·변경·반납 자동화 | 자산 누락·종료 비용 |
| 계정·권한 | 최소 권한·승인·비상 접근 | 권한 차이·자격증명 노출 |
| 비용 | 계정·태그·업무별 사용량 분석 | 비용 귀속률·미분류 자원 |
| 정책·감사 | 구성 위반 탐지·작업 기록 | 예외 기록·로그 완전성 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 공급자별 API·기능 차이를 공통 모델이 모두 표현하지 못함 | 공통 관리 대상과 고유 기능을 구분하고 미지원·실패 동작을 명시 |
| CMP에 관리자 권한이 집중돼 자격증명 침해 영향이 커짐 | 관리 ID 분리·최소 권한·비밀정보 회전·행위 감사와 비상 경로 검증 |
| 소유 태그·비용 분류가 제각각이면 단일 화면으로도 통합 운영 곤란 | 공통 자원 분류·소유자·승인·비용 규칙을 먼저 정의 |

## Ⅵ. 제언 — 소규모 업무군에서 전체 생명주기 검증

공통 자원 분류와 권한 기준을 먼저 정하고 한 업무군에서 요청·승인·생성·변경·반납·비용 대사를 끝까지 시험한 뒤 관리 범위를 넓힌다.
