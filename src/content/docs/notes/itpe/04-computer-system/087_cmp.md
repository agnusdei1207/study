## 한 줄 본질
- 기업이 AWS, Azure, 온프레미스 가상화를 혼용하면서 계정 파편화, 자원 낭비, 보안 정책 불일치가 발생함 → 이기종 클라우드 API를 단일 대시보드로 통합 추상화하여 셀프 프로비저닝, 비용 분석, 규제 준수를 중앙 통제 → 운영 표준화 및 클라우드 TCO 절감 / CSP 고유 신기술 지원 지연 발생

## 핵심 용어
- Single Pane of Glass: 서로 다른 퍼블릭/프라이빗 클라우드의 인프라 현황, 비용, 경보를 단 하나의 통합 유리창(화면)에서 조망하는 단일 인터페이스
- FinOps(Financial Operations): 클라우드 지출에 대한 재무적 가시성을 확보하고, 개발팀과 재무팀이 협업하여 유휴 자원 삭제 및 비용을 최적화하는 문화이자 실천 방법
- API 지연(API Lag): AWS나 Azure가 출시한 최신 클라우드 서비스를 CMP 제조사가 플랫폼에 지원할 때까지 수개월의 시차가 발생하는 구조적 한계

## 핵심 통찰
- CMP는 '기술의 문제'가 아니라 '조직의 거버넌스 문제'임 → 개발팀이 제각각 법인카드로 클라우드 서버를 띄우는 섀도우 IT(Shadow IT)를 방지하고, 회사의 보안 정책과 예산 한도 안에서 자원을 신청하게 만드는 관료주의와 민첩성의 절충선임
- 최고 공통 분모(Highest Common Denominator)의 함정에 빠짐 → 여러 클라우드의 공통점만 뽑아 추상화하면 가장 평범한 가상머신(VM)밖에 띄우지 못하고, 각 CSP의 강력한 최신 PaaS나 AI 서비스는 쓰기 어려워짐
- 비용 절감(FinOps)이 CMP 도입의 가장 강력한 ROI임 → 사용하지 않는 개발계 VM을 주말에 자동 정지시키고, 과다 스펙으로 프로비저닝된 인스턴스를 줄이는(Rightsizing) 기능만으로 라이선스 비용을 상쇄함

## 이웃 토픽과 구분
- CMP vs APM(Application Performance Monitoring): CMP = 인프라 자원 프로비저닝, 비용, 이기종 클라우드 거버넌스 관리 / APM = 실행 중인 소프트웨어 애플리케이션의 트랜잭션, 에러, 응답 지연 모니터링

## 문제·원인·대책
- 적용 상황: 멀티 클라우드 환경에서 소유자와 용도가 불명확한 자원이 누적되어 예산 통제가 어려워지는 상황
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 개발팀 퇴사 후 방치된 유휴 VM/스토리지로 인해 클라우드 비용 매월 누수 | 자원 소유자 추적 불가 및 프로비저닝 후 회수 프로세스 부재 | CMP 필수 태깅(Owner, Project) 정책 강제 및 자동 수명주기(TTL) 설정 | 미사용 자원 7일 경과 시 자동 회수로 비용 25% 즉각 절감 |
| 개발자가 CSP 콘솔에서 임의로 인스턴스를 띄워 방화벽 포트 무단 개방 | 일관된 보안 거버넌스 미적용 및 단일 통제점 부재 | CMP 셀프 카탈로그를 통한 자원 생성 의무화 및 보안 템플릿 강제 | 사전 승인된 보안 아키텍처 기반 인프라 배포 100% 보장 |

## 내 의견
- [CSP 전용 CMP를 지양하고 오픈소스 IaC 엔진 기반의 경량 CMP 구축] 거대 상용 CMP 솔루션은 도입 비용이 수억 원에 달하고 커스터마이징이 극도로 어려움 → 나라면: 백엔드는 Terraform과 OpenTofu, ArgoCD를 기반으로 파이프라인을 단일화하고, 프론트엔드는 Spotify Backstage 기반의 내부 개발자 플랫폼(IDP)을 구축하여 개발자에게는 셀프서비스의 자유를, 인프라팀에게는 정책 기반 코드(OPA)를 통한 완벽한 멀티 클라우드 통제권 확보
