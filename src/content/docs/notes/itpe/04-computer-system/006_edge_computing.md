## 연관 키워드
- 엣지 컴퓨팅, 데이터 지역성, 저지연, 엣지 게이트웨이, 오프라인 동작

## Ⅰ. 엣지 컴퓨팅의 개요
- 핵심 요약 : 엣지 컴퓨팅은 데이터 발생 지점 가까이에서 처리해 지연과 중앙 전송 의존을 줄이는 분산 방식.
- 개념 : **엣지 컴퓨팅**(Edge Computing)은 기기·현장 게이트웨이·지역 노드에서 데이터를 수집·처리·저장.
- 배경 및 필요성 : 실시간 제어, 대량 센서 전송 비용, 간헐 연결과 데이터 지역성 요구.
- 주요 목적 : 즉시 처리는 현장에, 장기 분석은 중앙에 배치.

## Ⅱ. 특성 및 장점
- 핵심 요약 : 현장 추론과 필터링이 응답시간·백홀 대역폭을 줄이고 제한적 오프라인 동작을 지원.
- 로컬 처리 → 네트워크 왕복 감소.
- 원천 데이터 요약 → 전송량 감소.
- 현장 제어 유지 → 중앙 연결 장애 시 핵심 기능 지속 가능.
- 노드 분산으로 보안·패치·자원 관리는 복잡.

## Ⅲ. 계층 흐름
- 핵심 요약 : 장치·엣지·클라우드가 시간 민감도와 집계 범위에 따라 처리 책임을 나눔.
```text
센서·현장 장치
  ↓ 수집·필터·즉시 제어
엣지 게이트웨이·지역 노드
  ↓ 요약 전송
클라우드 분석·학습
  ↓ 모델·정책 갱신
엣지 적용·현장 확인
```
```text
즉시 제어 → 장치·엣지
지역 집계 → 엣지 센터
전역 학습 → 클라우드
```

## Ⅳ. 엣지와 클라우드 비교
- 핵심 요약 : 엣지는 낮은 지연, 클라우드는 대규모 탄력 연산과 중앙 관리를 제공.
| 비교 축 | 엣지 | 클라우드 |
| --- | --- | --- |
| 위치 | 데이터 발생원 인접 | 중앙·지역 데이터센터 |
| 연결 | 단절 시 로컬 처리 가능 | WAN 연결 영향 |
| 자원 | 제한적·분산 | 탄력적·대규모 |
| 운영 | 현장 관리 부담 | 중앙 자동화 유리 |

## Ⅴ. 한계와 방안
- 핵심 요약 : 물리적 노출·패치 편차·동기화 문제를 기기 신뢰와 원격 수명주기 관리로 통제.
| 한계 | 원인·영향 | 대응 |
| --- | --- | --- |
| 기기 변조 | 현장 접근 가능 | 보안 부팅·인증·원격 폐기 |
| 패치 편차 | 노드 분산 | 서명 OTA·준수 감시 |
| 동기화 충돌 | 오프라인 후 재연결 | 이벤트 ID·멱등 처리 |
| 자원 부족 | 전력·메모리 한계 | 자원 예산·경량 모델 |

## Ⅵ. 도입 제언
- 핵심 요약 : 기업은 지연·연결 요구가 뚜렷한 업무부터 엣지 배치하고 중앙 관리 기능을 함께 구축.
- 플랫폼팀은 기기 신원, 서명 업데이트, 로그, 안전한 오프라인 동작을 표준화.

## Ⅶ. 결론
- 핵심 요약 : 엣지는 클라우드를 대체하지 않고 데이터 발생 지점에 일부 처리를 분산하는 구조.
- 업무별 데이터·지연 요구로 현장과 중앙의 책임 경계를 정함.
