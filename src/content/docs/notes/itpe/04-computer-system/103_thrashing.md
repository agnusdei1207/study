## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 스래싱

## 30초 인출

- 본질: 프로세스가 실행에 필요한 최소한의 메모리 프레임을 확보하지 못함
- 메커니즘: 실제 프로그램 연산 시간보다 디스크에서 페이지를 스왑인/아웃하는 I/O 시간이 압도적으로 많아져 CPU가 멈춤

## 핵심 용어

- 다중 프로그래밍 정도(MPD: Multiprogramming Degree): 주기억장치에 동시에 적재되어 실행 대기 중인 활성 프로세스의 총 수
- 워킹셋(Working Set): 프로세스가 일정 시간(윈도우 $\Delta$) 동안 자주 참조하는 페이지들의 집합으로, 이 집합 전체가 메모리에 상주해야 스래싱이 발생하지 않음
- PFF(Page Fault Frequency): 페이지 부재 발생 주기를 측정하여 상한선 초과 시 프레임을 추가 할당하고 하한선 미만 시 프레임을 회수하는 적응형 메모리 관리 기법

### Ⅱ. 핵심 특성

- 운영체제의 치명적인 오판이 스래싱을 부름 → CPU 사용률이 떨어지면 OS 스케줄러는 "할 일이 없구나"라고 착각하여 큐에서 새 프로세스를 메모리에 더 집어넣음(MPD 증가) → 이로 인해 기존 프로세스의 프레임이 더 뺏기며 시스템이 완전히 마비되는 악순환에 빠짐
- 국소성(Locality)의 붕괴 → 프로그램의 시간/공간 지역성이 깨지거나 배열을 행/열 반대로 잘못 순회하는 루프가 돌면 한 번 접근할 때마다 페이지 부재가 터져 스래싱을 유발함
- 현대 클라우드에서는 OOM Killer가 조기 차단함 → 스래싱으로 시스템 전체가 좀비 상태에 빠지는 것을 막기 위해 최신 리눅스 커널은 스왑 한도에 도달하면 메모리를 가장 많이 먹는 프로세스를 즉각 강제 종료(SIGKILL)시키는 극약 처방을 씀

### Ⅲ. 관련 개념과 구분

- 스래싱 vs 단편화: 스래싱 = 프로세스들의 메모리 요구량 총합이 물리 메모리를 초과하여 발생하는 I/O 병목 현상 / 단편화 = 빈 메모리 공간이 자잘하게 쪼개져 있어 할당이 불가능한 배치 공간 비효율

### Ⅳ. 적용 문제와 대응

- 사례: 126회 기출 및 야간 배치 작업 동시 실행으로 인한 데이터베이스 서버 무응답 장애
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 야간 배치 프로그램 수십 개 동시 기동 후 서버 명령 입력 불가(무응답) | 과도한 프로세스 동시 실행으로 스왑 공간 포화 및 스래싱 발생 | 스케줄러 동시 실행 수(MPD) 제한 및 우선순위 큐 분리 | 프로세스별 최소 워킹셋 보장 및 스래싱 원천 방지 |
| 컨테이너 호스트에서 특정 파드가 메모리를 과점하여 이웃 파드까지 정체 | 메모리 상한선(Limit) 미설정으로 인한 커널 스왑 경합 | 쿠버네티스 자원 Limit 설정 및 `vm.swappiness` 0 또는 낮은 값 조정 | 메모리 초과 컨테이너만 격리 차단하여 노드 전체 스래싱 방지 |

### Ⅴ. 기술사적 제언

|---|---|
