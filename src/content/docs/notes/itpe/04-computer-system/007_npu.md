## 큰 그림과 30초 인출

- 본질: 신경망 Tensor 연산과 데이터 이동을 함께 최적화한 Domain-Specific Accelerator
- 메커니즘: Model Compile·Quantization → On-chip Buffer 재사용 → MAC Array 병렬 실행
- 산출: 정확도 제약 아래 지연·처리량·에너지 효율을 개선하며 Operator 지원 범위가 실효 성능을 결정

<details><summary>핵심 용어</summary>

- `NPU(Neural Processing Unit)`: 신경망 연산·데이터 이동 특화 가속기 → 모델·컴파일러 호환성이 성능을 가름
- `MAC(Multiply-Accumulate)`: 곱셈·누산 병렬 연산 → Tensor 처리량의 핵심
- `NoC(Network on Chip)`: 연산기와 On-chip Memory 연결 → 데이터 공급 병목을 통제
- `Quantization`: 저정밀 표현으로 변환 → 효율과 정확도를 교환

</details>

## 예상문제

> NPU의 개념과 구조, AI 추론 처리 절차를 설명하고 CPU·GPU 등과 비교하여 도입 고려사항을 제시하시오.

## Ⅰ. 개요 ───── 정의·필요성

> NPU 성능은 연산량보다 데이터 재사용과 Operator Mapping의 종단 경로로 판정함.

- 정의: **Tensor 연산**, **MAC 병렬성**, **On-chip Memory**를 결합한 신경망 Domain-Specific Accelerator
- 목적: 데이터 이동과 범용 제어 오버헤드 축소 → AI 추론 지연·에너지 제약 충족

## Ⅱ. 특징 ───── 연산·메모리·정밀도 최적화

| 특징 | 구현 관점 | 효과 |
|---|---|---|
| 병렬 MAC | 행렬·텐서 연산 배열 | 높은 연산 병렬성 |
| 데이터 재사용 | 온칩 SRAM·버퍼·타일링 | 외부 메모리 이동 감소 |
| 저정밀 연산 | INT8 등 모델별 정밀도 | 처리량·에너지 효율 개선 가능 |
| 그래프 실행 | 연산 융합·스케줄링 | 중간 데이터 이동 축소 |
| SW/HW 결합 | 컴파일러·런타임·드라이버 | 모델을 실제 하드웨어에 매핑 |

## Ⅲ. 구조 ───── 데이터 경로 중심 배치

```text
Host CPU ─Command→ [Scheduler/Controller]
  │                        │
  └─Model/Input→ [DMA] → [On-chip Buffer]
                              ⇅
                  [Interconnect / NoC]
                     ⇙      ↓      ⇘
                [MAC PE] [Vector] [Activation]
                     └──────┬──────┘
                            ▼
                       Output Buffer
```

| 구성 | 역할 | 답안 키워드 |
|---|---|---|
| PE/MAC Array | 곱셈·누산 병렬 처리 | Tensor Compute |
| On-chip Buffer | 가중치·활성값 재사용 | Data Locality |
| Interconnect | PE·메모리 간 전달 | Bandwidth |
| DMA/Controller | 외부 메모리 전송·실행 제어 | Data Movement |
| Compiler/Runtime | 연산 지원 여부·배치·스케줄 | Operator Mapping |

## Ⅳ. 동작 ───── 모델 변환부터 실측까지

```text
① 모델 내보내기 → ② 그래프 최적화 → ③ 정밀도 결정·보정
 → ④ 지원 연산 매핑 → ⑤ 메모리·타일 스케줄
 → ⑥ NPU 실행/미지원 연산 대체 → ⑦ 정확도·성능 프로파일
```

- 판정: 컴파일 성공이 아니라 실제 데이터에서 정확도·지연·처리량·전력을 함께 측정

## Ⅴ. 비교 ───── CPU·GPU·NPU·TPU

| 구분 | CPU | GPU | NPU | TPU |
|---|---|---|---|---|
| 지향 | 범용·제어 중심 | 대규모 병렬 처리 | 신경망 특화 | 특정 업체의 텐서 가속기 계열 |
| 유연성 | 높음 | 높음 | 지원 연산에 좌우 | 세대·환경에 좌우 |
| 강점 | 분기·OS·전처리 | 학습·범용 병렬 | 전력·지연 제약 추론 | 대규모 텐서 처리 |
| 유의 | 병렬 AI 효율 | 전력·메모리 | 컴파일러·연산 커버리지 | 생태계·배포 조건 |

> NPU와 TPU의 명칭·범위는 제품별로 다르므로 고정된 회로 구조로 일반화하지 않는다.

## Ⅵ. 고려 ───── 정확도 제약 아래 전 구간 검증

| 문제 | 원인 | 대응 | 검증 |
|---|---|---|---|
| 정확도 저하 | 양자화·연산 치환 | 대표 데이터 보정, 혼합 정밀도 | 기준 모델 대비 품질 |
| 성능 미달 | 메모리 대역폭·Host 왕복 | 연산 융합, 배치·타일 조정 | 종단 지연·처리량 |
| 대체 실행 증가 | 미지원 Operator | 모델 재구성, 지원표 확인 | NPU 실행 비율 |
| 열·전력 제한 | 지속 부하 Throttling | 전력 모드·냉각·부하 제어 | 지속 성능·에너지 |
| 종속성 | 전용 컴파일러·포맷 | 중간 표현·추상 계층·Exit Plan | 이식 시험 |
| 모델 보호 | 펌웨어·모델 공급망 | 서명·암호화·보안 업데이트 | 무결성·취약점 |

## Ⅶ. 모델·컴파일러·런타임 공동 최적화

> TOPS가 아니라 목표 모델의 실행 커버리지와 종단 품질로 NPU 적합성을 판정함.

### 학습자 통찰 메모 — 답안 밖
- `[핵심 통찰]`: 연산기가 빨라도 Weight와 Activation을 계속 외부 메모리에서 가져오면 이점이 사라진다.
- `나라면`: 대표 모델을 먼저 Compile해 미지원 Operator와 정확도 손실을 확인한 뒤 장비를 선정하겠다.

### 실전 답안용 기술사적 제언
- 판정: Operator Coverage·정확도·종단 지연 동시 충족
- 대안: 대표 모델 Benchmark와 혼합 정밀도 Pilot
- 검증: 지속 부하의 성능·전력·Fallback 비율 측정
- 효과: 사양 중심 과잉 도입과 성능 착시 제거
