## 연관 키워드

- NPU(Neural Processing Unit), 텐서(Tensor), 시스톨릭 어레이(Systolic Array), MAC(Multiply-Accumulate)
- 온칩 SRAM(Static Random-Access Memory), 데이터 재사용, 혼합 정밀도(Mixed-Precision), 양자화(Quantization)
- 온디바이스 AI(On-Device AI), 연산자 호환성, CPU·GPU·NPU 비교, 이종 컴퓨팅(Heterogeneous Computing)

## Ⅰ. NPU의 개요

- 핵심 요약 : 텐서 연산과 데이터 재사용에 특화해 인공지능(AI, Artificial Intelligence) 추론의 전력당 처리량을 높이는 전용 프로세서.
- 개념 : 딥러닝의 핵심 연산인 다차원 배열 **텐서** (Tensor)의 행렬 곱셈(GEMM, General Matrix Multiply)과 곱셈-누산(MAC, Multiply-Accumulate)을 저전력으로 가속하도록 설계된 AI 전용 프로세서 (**NPU**, Neural Processing Unit).
- 배경 및 필요성 : 순차 제어에 최적화된 중앙처리장치(CPU, Central Processing Unit)와 그래픽 파이프라인에서 출발한 그래픽 처리 장치(GPU, Graphics Processing Unit)는 AI 추론에 필요한 전력당 연산 성능을 맞추기 어렵고, 메모리 대역폭 한계도 뚜렷하므로 엣지 기기와 데이터센터 모두에서 AI 연산에 특화된 구조가 요구됨.
- 주요 목적 : 행렬 연산의 병렬화, 온칩 메모리를 통한 데이터 재사용, 지원 정밀도에 맞춘 추론 가속으로 전력 효율을 확보하는 것.

## Ⅱ. NPU의 특징 및 장점

- 핵심 요약 : 행렬 연산 특화, 온칩 데이터 재사용, 저정밀도 처리가 결합되어 전력당 성능을 높이는 구조.

1. MAC 병렬화 : 곱셈기와 누산기를 배열로 배치 → 합성곱과 행렬 곱의 처리량 증가.
2. 온칩 데이터 재사용 : 가중치와 활성화 값을 온칩 버퍼에 머물게 함 → 외부 메모리 접근 감소와 에너지 소모 절감.
3. 저정밀도 연산 : INT8, FP8 등 낮은 정밀도 형식을 워크로드에 맞춰 사용 → 메모리 사용량과 지연 감소. 다만 모델별 정확도 검증이 전제됨.

## Ⅲ. NPU의 구조 및 동작 원리

- 핵심 요약 : 호스트 인터페이스, 온칩 버퍼, 연산 배열, 후처리, 출력의 순서로 텐서가 흐르는 파이프라인 구조.
- **시스톨릭 어레이** (Systolic Array) : 각 연산 셀이 데이터를 이웃 셀로 직접 전달하여 레지스터와 메모리 접근 횟수를 줄이는 MAC 배열.
- **온칩 SRAM 버퍼** (SRAM, Static Random-Access Memory) : 가중치와 활성화 데이터를 칩 내부에 상주시켜 반복 연산에 재사용.
- 양자화 엔진 : FP32 대신 저정밀도 포맷으로 연산하여 연산량과 메모리 대역폭 요구를 낮춤.
- 후처리 파이프라인 : 활성화 함수, 풀링, 정규화를 메인 연산 직후에 한 번의 흐름으로 처리.

```text
[ NPU 데이터 처리 흐름 ]

호스트 인터페이스 (시스템 버스)
   ↓
온칩 버퍼 (가중치·활성화 상주)
   ↓
MAC 배열 (시스톨릭 어레이)
   ↓
후처리 (활성화 함수·풀링·양자화)
   ↓
출력 버퍼 → 외부 메모리
```

```text
[ 타일 단위 연산 반복 ]

외부 메모리 → 온칩 버퍼 (타일 적재)
   ↓
MAC 배열 연산 (타일 단위)
   ↓
중간 결과를 온칩에 유지
   ↓
다음 타일 연산 (재사용)
   ↓
최종 결과 활성화·양자화 → 출력
```

## Ⅳ. CPU·GPU·NPU 비교

- 핵심 요약 : CPU는 복잡한 제어, GPU는 범용 병렬 연산, NPU는 지원 모델의 텐서 연산 효율에 강점.

| 비교 항목 | CPU | GPU | NPU |
| --- | --- | --- | --- |
| 설계 철학 | 복잡한 제어 로직과 순차 처리 최적화 | 대규모 병렬 연산 중심의 범용 가속 | 딥러닝 텐서·행렬 연산 전용 하드웨어 |
| 연산 구조 | 범용 제어·연산 코어 | 대규모 병렬 코어와 행렬 연산 유닛 | 전용 MAC 배열과 온칩 데이터 경로 |
| 에너지 효율 | 워크로드에 따라 차이 큼 | 병렬 처리 효율이 높음 | 지원 모델과 정밀도에서 전력당 추론 성능이 높음 |
| 연산 정밀도 | FP64, FP32, INT32 등 범용 정밀도 | FP32, FP16, BF16 등 혼합 정밀도 | INT8, FP8 등 저정밀도 특화 |
| 소프트웨어 스택 | 표준 컴파일러와 범용 런타임 | 벤더별 컴파일러와 런타임 | 장치별 컴파일러와 런타임, 프레임워크 연동 |

- NPU는 특정 모델 구조(합성곱 신경망(CNN, Convolutional Neural Network), 트랜스포머(Transformer))에서 GPU보다 높은 전력 효율을 보이나, 새로운 연산자가 등장했을 때의 하드웨어 유연성은 상대적으로 낮음.

## Ⅴ. NPU의 한계와 방안

- 핵심 요약 : 연산자 호환성, 메모리 병목, 양자화 정확도 문제를 소프트웨어 최적화와 모델 검증으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 연산자 호환성 부족 | 비표준 레이어가 NPU에서 실행되지 않아 CPU로 폴백되며 성능이 크게 하락 | TVM 등 개방형 컴파일러 기반 툴체인 활용, 미지원 연산자 대체 | NPU 가속 연산 비율, 폴백 연산 비율 |
| 메모리 용량·대역폭 병목 | 대규모 언어 모델(LLM, Large Language Model)의 파라미터가 온칩 메모리를 넘어 연산 장치의 가동률 저하 | 외부 메모리 대역폭 확장, 메모리 근처 연산 구조인 PIM(Processing-In-Memory) 검토 | 연산 장치 가동률, 메모리 대역폭 사용률 |
| 양자화에 따른 정확도 손실 | 저정밀도 변환 시 추론이나 번역 같은 민감 작업의 품질 저하 | 양자화 인식 훈련(QAT, Quantization-Aware Training), 민감 레이어의 혼합 정밀도 유지 | 작업별 정확도 차이 |

## Ⅵ. NPU의 적용 제언

- 핵심 요약 : 대상 모델의 연산자 지원률, 실측 지연, 전력당 성능을 기준으로 CPU와 GPU와 역할을 나누는 방향.

- 온디바이스 AI는 스마트폰, 차량, 로봇처럼 배터리와 발열 제약이 큰 기기에서 수요가 커서, 하드웨어와 모델 구조를 함께 설계하는 공동 설계(Co-design)가 경쟁력의 핵심이 됨.
- 특정 벤더의 개발 환경에 종속되지 않도록 개방형 컴파일러와 드라이버 생태계를 지원하고, 주요 딥러닝 프레임워크와의 연동을 표준 기능으로 확보하는 전략이 장기 운영에 유리함.
- 데이터센터 추론에서는 GPU와 NPU의 모델 호환성, 실제 처리량, 메모리 용량, 총소유비용(TCO, Total Cost of Ownership)을 실측한 뒤 적합한 워크로드부터 배치하는 방식이 현실적임.

## Ⅶ. 결론

- 핵심 요약 : NPU의 가치는 지원 모델에서 실측한 전력당 성능으로 판단해야 하며, 메모리, 연산자, 정밀도의 제약을 함께 검증해야 함.
- 범용 제어는 CPU, 유연한 병렬 처리와 대규모 학습은 GPU, 반복적인 텐서 추론은 NPU에 배치하는 이종 컴퓨팅 구조가 합리적임.
