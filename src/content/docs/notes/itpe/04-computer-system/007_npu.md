## 답안 골격
```text
[NPU] ◀━━ 머리: Ⅶ 내 의견 (온디바이스 경량화 모델과 결합한 프라이버시 보존형 NPU 인프라 설계)
 ┃
 ┣━ Ⅰ 개요 ───── CPU 직렬 처리 및 GPU 전력 소모 한계 → 딥러닝 행렬 연산 특화 고효율 하드웨어
 ┣━ Ⅱ 특징 ───── 저전력·고효율(TOPS/W) · 대규모 MAC 병렬화 · 시스톨릭 어레이 · 온디바이스 최적화
 ┣━ Ⅲ 구조 ───── MAC(곱셈-누적) 어레이 · 가중치 버퍼(SRAM) · 활성화 함수 가속기 · 양자화 엔진
 ┣━ Ⅳ 흐름 ───── ① 모델 양자화(INT8/INT4) → ② 가중치 메모리 로딩 → ③ 데이터 스트리밍 연산 → ④ 추론 결과 산출
 ┣━ Ⅴ 비교 ───── CPU vs GPU vs NPU vs TPU
 ┗━ Ⅵ 실무 ───── 전용 툴체인 파편화 / 비표준 연산자 지원 한계 / 발열 및 메모리 대역폭 제약
```
- 필수 키워드: MAC(Multiply-Accumulate) · 시스톨릭 어레이(Systolic Array) · TOPS/W · 온디바이스 AI · 양자화(Quantization)
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ MAC 어레이 구조도 → Ⅴ 프로세서 비교표 / 25점 = Ⅰ~Ⅶ 전개, Ⅳ 컴파일/양자화 흐름과 Ⅵ 온디바이스 배포 고려사항
- 기출: 미출제. 예상: 1교시 "NPU의 개념과 아키텍처 특징" 또는 2교시 "온디바이스 AI 확산에 따른 NPU의 기술요소 및 기존 GPU 대비 차별점"

## 한 줄 본질
- CPU의 폰 노이만 구조 병목 및 GPU의 막대한 전력 소모(수백 Watt) 한계 → 딥러닝 추론의 핵심인 행렬 곱셈·누적(MAC) 연산을 파이프라인화된 전용 하드웨어 회로로 집적 → 와트당 연산력(TOPS/W) 극대화 및 스마트폰·PC 온디바이스 AI 구현 / 하드웨어 고정 회로 특성상 새로운 AI 구조에 대한 프로그래밍 유연성 저하

## 핵심 그림
```text
[ 입력 활성화 데이터 (Activation) ] ───> +-----------------------------------+
                                         |         NPU Core 아키텍처         |
[ 모델 가중치 (Weights) ] ────────────> |  +-----------------------------+  |
                                         |  |  On-Chip SRAM 가중치 버퍼   |  |
                                         |  +--------------+--------------+  |
                                         |                 │                 |
                                         |  +--------------v--------------+  |
                                         |  | Systolic Array (MAC Units)  |  |
                                         |  |  [MAC] ──> [MAC] ──> [MAC]  |  |
                                         |  |    │         │         │    |  |
                                         |  |  [MAC] ──> [MAC] ──> [MAC]  |  |
                                         |  +--------------+--------------+  |
```

## 핵심 용어
- 시스톨릭 어레이(Systolic Array): 심장 박동처럼 규칙적인 클록에 맞춰 데이터를 인접 연산 장치(MAC) 간에 직접 전달함으로써 메인 메모리 접근 횟수를 극적으로 줄이는 구조
- TOPS/W(Tera Operations Per Second per Watt): 1와트의 소비전력당 처리할 수 있는 테라 연산 수로, 모바일/에지 프로세서의 에너지 효율성을 나타내는 핵심 척도

## 핵심 통찰
- GPU는 대규모 부동소수점(FP32/FP16) 그래픽스 렌더링용 범용 코어의 집합이지만, NPU는 행렬 내적 연산기만 남기고 캐시와 제어 로직을 걷어낸 초경량 도메인 특화 아키텍처(DSA)임
- NPU 성능의 승패는 실리콘 다이 면적보다 '컴파일러 툴체인'에서 결정됨 → PyTorch나 ONNX 모델을 전용 NPU 명령어 및 INT8 저정밀도 연산으로 양자화·변환해 주는 소프트웨어 스택이 완성되지 않으면 하드웨어가 무용지물화
- 클라우드 GPU 서버 대비 네트워크 지연 제로, 통신 비용 제로, 프라이버시 데이터의 단말 내 완결 처리를 가능케 하는 온디바이스 AI의 물리적 핵심 동력

## 이웃 토픽과 구분
- NPU vs GPU: GPU = 유연한 프로그래밍(CUDA)과 높은 메모리 대역폭 기반의 대규모 병렬 학습·추론 범용기 / NPU = 딥러닝 연산에만 회로를 고정한 저전력 고효율 추론 특화 프로세서

## 문제·원인·대책
- 사례: 모바일 단말에서 LLM 및 온디바이스 비전 모델 구동 시 스로틀링(Throttling) 및 메모리 부족
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 배터리 급소모 및 발열로 인한 클록 다운(스로틀링) | FP16 고정밀 연산으로 인한 과도한 연산량과 메모리 I/O | PTQ(Post-Training Quantization) 및 INT4 가중치 양자화 적용 | 연산량 75% 절감 및 발열 억제로 연속 추론 안정화 |
| 최신 AI 모델(MoE, State Space Model) 구동 실패 | NPU 고정 하드웨어가 미지원하는 신규 활성화 함수/연산자 등장 | CPU/GPU 폴백(Fallback) 하이브리드 실행 엔진 구성 | 모델 실행 호환성 확보 및 지원 연산자 점진 확장 |

## 내 의견
- [NPU 생태계 파편화 해소를 위한 개방형 런타임 표준 수립] 제조사(퀄컴, 애플, 삼성, 인텔)마다 전용 툴체인(QNN, CoreML, ONE-DN)이 달라 개발자가 모델을 칩별로 재최적화하는 막대한 공수 발생 → 나라면: 애플리케이션 계층과 NPU 하드웨어 사이에 ONNX Runtime 또는 ExecuTorch 같은 오픈소스 런타임 표준 어댑터를 단일 인터페이스로 채택하고, 컴파일 타임에 백엔드 하드웨어를 자동 감지하여 최적 NPU 가속기로 매핑하는 CI/CD 파이프라인 구성
