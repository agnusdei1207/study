## Ⅰ. NPU(Neural Processing Unit)의 개요

- 핵심 요약 : **텐서 연산**과 **데이터 재사용**에 특화해 AI 추론의 처리량·전력 효율을 높이는 프로세서.
- 개념 : 딥러닝 알고리즘의 핵심 연산인 **다차원 텐서** (Tensor)의 대규모 **행렬 곱셈(GEMM: General Matrix Multiply)** 및 **누적(MAC: Multiply-Accumulate)** 연산을 초고속·저전력으로 가속하기 위해 특화 설계된 NPU(Neural Processing Unit), 즉 AI(Artificial Intelligence) 전용 프로세서.
- 배경 및 필요성 : 범용 순차 연산 중심의 CPU(Central Processing Unit)와 그래픽 파이프라인 레거시를 지닌 GPU(Graphics Processing Unit)는 막대한 소비 전력(TDP)과 메모리 대역폭 한계(Memory Wall)를 가지므로, 엣지 기기 및 데이터센터에서 AI 워크로드 전성비(TOPS/W)를 극대화할 전용 실리콘 아키텍처가 요구됨.
- 핵심 목적 : 행렬 연산의 병렬화, 온칩 SRAM(Static Random-Access Memory)을 통한 데이터 재사용, 지원 정밀도에 맞춘 AI 추론 가속. 학습 지원 여부는 제품별 아키텍처에 따라 다름.

## Ⅱ. NPU의 특징 및 장점

- 핵심 요약 : **행렬 연산 특화**, **온칩 데이터 재사용**, **저정밀도 처리**가 전력당 성능을 높임.

1. **MAC 병렬화** : 다수의 곱셈·누산기를 배열로 구성해 합성곱·행렬곱의 처리량을 높임.
2. **데이터 지역성** : 가중치와 활성화를 온칩 버퍼에서 재사용해 외부 메모리 왕복을 줄이고 에너지 소모를 절감.
3. **혼합 정밀도** : 지원하는 INT8·FP8 등 형식을 워크로드에 맞춰 사용해 메모리 사용량과 지연을 줄임. 정확도 검증 필요.

## Ⅲ. NPU의 구조 및 동작 원리

- 핵심 요약 : **호스트 인터페이스 → 온칩 버퍼 → 연산 배열 → 후처리 → 출력** 순으로 텐서를 처리.

NPU(Neural Processing Unit)는 대규모 MAC(Multiply-Accumulate) 배열을 하드웨어 파이프라인으로 연결한 시스톨릭 어레이(Systolic Array)와 대용량 온칩 버퍼를 바탕으로, 메모리 접근을 최소화하면서 텐서 데이터를 물결처럼 흘려보내며 연산함.

```text
[ NPU 내부 아키텍처 및 데이터 흐름 ]

+---------------------------------------------------------------+
| NPU Host Interface (PCIe / CXL / AXI Bus)                     |
+---------------------------------------------------------------+
                                │
                                ▼
+---------------------------------------------------------------+
| Global On-Chip Buffer / Scratchpad SRAM (대용량 저지연 캐시)   |
+---------------------------------------------------------------+
       │ (Weight Stream)                │ (Activation Stream)
       ▼                                ▼
+---------------------------------------------------------------+
| 2D Systolic Array (MAC Units Grid)                            |
|                                                               |
|   [MAC] ──> [MAC] ──> [MAC] ──> [MAC] ...                     |
|     │         │         │         │                           |
|     ▼         ▼         ▼         ▼                           |
|   [MAC] ──> [MAC] ──> [MAC] ──> [MAC] ...                     |
|                                                               |
|   * 데이터 재사용: Weight Stationary / Output Stationary      |
+---------------------------------------------------------------+
                                │
                                ▼
+---------------------------------------------------------------+
| Post-Processing Unit: Activation (ReLU/GELU), Pooling, Quant  |
+---------------------------------------------------------------+
                                │
                                ▼
+---------------------------------------------------------------+
| Output Buffer / Direct Memory Access (DMA Engine)             |
+---------------------------------------------------------------+
```

- **시스톨릭 어레이(Systolic Array)** : 각 연산 셀(MAC)이 데이터를 이웃 셀로 직접 전달하여 레지스터 및 메모리 접근 횟수를 획기적으로 감축.
- **온칩 SRAM 버퍼링** : 가중치(Weight)와 활성화(Feature Map) 데이터를 고속 온칩 버퍼에 상주시킨 채 반복 연산 수행.
- **저정밀도 양자화 엔진** : FP32 연산 대신 INT8, FP8, INT4 등 저정밀도 포맷을 지원하여 연산량 및 메모리 대역폭 요구량 절감.
- **후처리 하드웨어 파이프라인** : 활성화 함수(GELU(Gaussian Error Linear Unit), SiLU), 풀링, 정규화(LayerNorm)를 메인 파이프라인 직후에 단일 패스로 처리.

```text
외부 메모리 ──DMA──> 온칩 버퍼 ──타일 공급──> MAC 배열
                       ▲                         │
                       └────── 중간 결과 재사용 ──┘
                                                 │
                                                 ▼
                                          활성화·양자화 → 출력
```

## Ⅳ. CPU·GPU·NPU 비교

- 핵심 요약 : **CPU는 제어**, **GPU는 범용 병렬 연산**, **NPU는 지원 모델의 텐서 연산 효율**에 강점.

| 비교 항목 | CPU | GPU | NPU |
|---|---|---|---|
| **설계 철학** | 복잡한 제어 로직, 순차 처리 최적화 | 그래픽 셰이딩 기반 대규모 SIMT(Single Instruction, Multiple Threads) 병렬화 | 딥러닝 텐서/행렬 연산 전용 하드웨어 가속 |
| **코어 구조** | 범용 제어·연산 코어 | 대규모 병렬 연산 코어와 행렬 연산 유닛 | 전용 MAC 배열과 온칩 데이터 경로; 구현별 차이 |
| **에너지 효율** | 워크로드에 따라 다름 | 높은 병렬 처리 효율 | 지원 모델·정밀도에서 높은 전력당 추론 성능 |
| **연산 정밀도** | FP64, FP32, INT32 등 범용 정밀도 | FP32, FP16, TF32, FP8 혼합 정밀도 | INT8, INT4, FP8, BF16 특화 저정밀도 |
| **소프트웨어 스택** | x86/ARM 표준 컴파일러, C/C++ | CUDA·ROCm 등 GPU별 컴파일러·런타임 | 장치별 컴파일러·런타임, ONNX Runtime·MLIR 등 연동 가능 |

- NPU는 특정 모델 구조(CNN, Transformer)에 대해 GPU 대비 높은 전성비를 발휘하나, 새로운 알고리즘 연산자가 등장했을 때의 하드웨어 유연성은 상대적으로 낮음.

## Ⅴ. NPU의 한계와 방안

- 핵심 요약 : **연산자 호환성**, **메모리 병목**, **양자화 정확도**를 소프트웨어 최적화와 모델 검증으로 대응.

- 범용 연산자 지원 부족 및 프레임워크 호환성 격차 :
  - 한계점 : 비표준 레이어나 커스텀 활성화 함수 사용 시 NPU 가속이 불가하여 CPU로 폴백(Fallback)되며 심각한 성능 저하 초래.
  - 해결 방안 : TVM, OpenVINO, ONNX Runtime, MLIR 등 오픈 컴파일러 생태계를 지원하는 범용 소프트웨어 툴체인 구축.
- 대규모 **언어모델(LLM, Large Language Model)** 서빙 시 메모리 용량 및 대역폭 병목 :
  - 한계점 : 수십억 파라미터 이상 LLM 구동 시 온칩 메모리 한계로 인해 외부 DRAM(Dynamic Random-Access Memory)/HBM(High Bandwidth Memory) 병목이 발생하여 MAC 유닛 가동률 저하.
  - 해결 방안 : HBM3/HBM4 및 CXL(Compute Express Link) 인터페이스 연계, PIM(Processing-In-Memory) 및 PNM(Processing-Near-Memory) 기술을 융합한 이종 메모리 아키텍처 도입.
- **양자화** (Quantization)에 따른 모델 정확도 손실 :
  - 한계점 : INT4/INT8로 무리하게 경량화 시 특정 민감 태스크(추론, 고정밀 번역)에서 모델 출력 품질 저하 발생.
  - 해결 방안 : 양자화 인식 훈련(QAT: Quantization-Aware Training) 및 혼합 정밀도(Mixed-Precision: 중요 레이어는 FP16 유지) 기법 적용.

## Ⅵ. NPU 적용 제언

- 핵심 요약 : 대상 모델의 **연산자 지원률·실측 지연·전력당 성능**을 기준으로 CPU·GPU와 역할을 분담.

- **온디바이스(On-Device)** AI 시장 선점 : 스마트폰, 자율주행, 로보틱스 분야에서 배터리 소모와 발열을 억제하는 고효율 엣지 NPU 채택은 필수적이므로 하드웨어-알고리즘 코디자인(Co-design) 추진 필요.
- 개방형 AI 소프트웨어 스택 생태계 육성 : 엔비디아 CUDA 종속성을 극복하기 위해 파이토치(PyTorch)와 긴밀히 통합되는 드라이버 및 컴파일러 표준화 역량 확보 시급.
- **HPC**(High-Performance Computing) 데이터센터 추론 인프라 검토 : GPU와 NPU의 모델 호환성, 실제 처리량, 메모리 용량, 총소유비용을 측정해 적합한 추론 워크로드부터 배치.

## Ⅶ. 결론

- 핵심 요약 : **NPU의 가치는 지원 모델에서의 실측 전력당 성능**으로 판단해야 하며, 메모리·연산자·정밀도 제약을 함께 검증해야 함.
- 범용 제어와 예외 처리는 CPU, 유연한 병렬 처리와 학습은 GPU, 반복적인 텐서 추론은 NPU에 배치하는 이종 컴퓨팅 접근이 적절함.
