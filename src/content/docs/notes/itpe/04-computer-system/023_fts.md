## 연관 키워드

- FTS, Fault Tolerance, redundancy, failover, 장애도메인, RTO, RPO

## Ⅰ. 결함허용시스템의 개요

- 핵심 요약 : 결함허용시스템은 하드웨어·소프트웨어 구성요소에 장애가 발생해도 중복·오류검출·복구기법으로 서비스를 지속하거나 허용된 수준으로 회복하는 시스템.
- 개념 : 결함허용시스템은 하드웨어·소프트웨어 구성요소에 장애가 발생해도 중복·오류검출·복구기법으로 서비스를 지속하거나 허용된 수준으로 회복하는 시스템.
- 배경 및 필요성 : 온라인 거래·제어 등 중단과 데이터 손실의 비용이 큰 업무에서 단일 장애점 제거 필요.
- 주요 목적 : 장애 발생 시 서비스 연속성·데이터 무결성·복구목표 달성.

## Ⅱ. 결함허용시스템의 특징 및 장점

- 핵심 요약 : 중복 구성: 이중화 자원·경로 제공 → 구성요소 장애 수용; 오류 검출·격리: 헬스체크·체크포인트 → 오류 전파 억제; 전환·복구: 장애조치·재시작·롤백 → 서비스 복원시간 단축.

1. 중복 구성: 이중화 자원·경로 제공 → 구성요소 장애 수용
2. 오류 검출·격리: 헬스체크·체크포인트 → 오류 전파 억제
3. 전환·복구: 장애조치·재시작·롤백 → 서비스 복원시간 단축

## Ⅲ. 결함허용시스템의 구조 (흐름)

- 핵심 요약 : 가용성·장애 허용수준 정의 → 장애모드·영향 분석 → 중복·감지·격리 구조 설계 → 전환·복구·데이터 대사 구현 → 장애주입·복구훈련.

```text
가용성·장애 허용수준 정의
  ↓
장애모드·영향 분석
  ↓
중복·감지·격리 구조 설계
  ↓
전환·복구·데이터 대사 구현
  ↓
장애주입·복구훈련
```

- 핵심 구성 : 요청 → 주노드·복제노드 처리

```text
요청 → 주노드·복제노드 처리
장애 감지 → 격리·전환 → 상태·데이터 검증 → 서비스 복귀
```

## Ⅳ. 비교: 결함허용 설계 / 백업·복구 중심 설계

- 핵심 요약 : 장애 중 서비스 기준 — 결함허용 설계: 중복·전환으로 지속 처리; 백업·복구 중심 설계: 복구 완료까지 서비스 중단 가능.

| 비교 기준 | 결함허용 설계 | 백업·복구 중심 설계 |
| --- | --- | --- |
| 장애 중 서비스 | 중복·전환으로 지속 처리 | 복구 완료까지 서비스 중단 가능 |
| 데이터 시점 | 동기복제로 손실을 줄일 수 있음 | 백업주기 이후 변경분 손실 가능 |
| 운영비용 | 상시 중복·동기화 자원 필요 | 예비환경·복구절차 중심 |

## Ⅴ. 결함허용시스템의 한계와 방안

- 핵심 요약 : 공통원인 고장·분할 뇌 등의 위험을 원인에 맞게 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 공통원인 고장 | 중복노드가 같은 전원·망·리전에 위치 | 장애도메인과 의존 서비스 분산 | 공통 장애점 수 |
| 분할 뇌 | 양측 노드가 주 노드라고 판단해 쓰기 충돌 | quorum·fencing·리더 선출 검증 | 복제 불일치 |
| 미시험 전환 | 장애조치·재합류 중 데이터 손상 | 정기 장애주입·복구 리허설 | RTO·RPO 달성률 |

## Ⅵ. 결함허용시스템의 제언

- 핵심 요약 : SRE와 서비스 책임자는 업무등급별 RTO/RPO·가용성 목표를 정하고 자동 전환뿐 아니라 분할 뇌·재합류·백업복원 시나리오를 훈련.
- 실행 제안 : SRE팀은 정기 장애주입으로 전원·네트워크·복제노드 실패 후 정상 복귀까지의 절차를 검증하고 훈련 결과를 런북에 반영.

## Ⅶ. 결함허용시스템의 결론

- 핵심 요약 : 결함허용은 장애를 없애는 일이 아니라 실패를 예상해 서비스와 데이터를 통제된 수준으로 유지·복구하는 설계 원칙.
- 시사점 : 복구 가능한 서비스는 이중화 토폴로지만으로 보장되지 않으며 장애감지·데이터 정합성·사람의 운영절차까지 검증 대상.
