## 답안 골격
```text
[SJF] ◀━━ 머리: Ⅶ 내 의견 (지수 평활법 기반 CPU 버스트 예측과 에이징(Aging)을 결합한 기아 방지형 SJF 설계)
 ┃
 ┣━ Ⅰ 개요 ───── FCFS의 호위 효과로 인한 평균 대기시간 증가 → 다음 CPU 버스트가 가장 짧은 프로세스 우선 할당
 ┣━ Ⅱ 특징 ───── 최소 평균 대기시간 보장(수학적 최적) · 비선점 vs 선점(SRTF) · 긴 작업 기아(Starvation)
 ┣━ Ⅲ 구조 ───── 준비 큐(버스트 시간 오름차순 정렬) + 과거 버스트 이력 테이블 + 지수 평활 예측기
 ┣━ Ⅳ 흐름 ───── ① 프로세스 도착 → ② 과거 이력 기반 다음 CPU 버스트 시간 예측($\tau_{n+1}$) → ③ 큐 정렬 → ④ 최소 작업 디스패칭
 ┣━ Ⅴ 비교 ───── 비선점 SJF vs 선점 SJF(SRTF) vs FCFS vs HRRN(에이징 반영)
 ┗━ Ⅵ 실무 ───── 미래 CPU 버스트 시간의 사전 인지 불가능 / 긴 프로세스의 무한 기아 / 잦은 선점 오버헤드
```
- 필수 키워드: 최단 작업 우선 · 최소 평균 대기시간 · SRTF(Shortest Remaining Time First) · 지수 평활법 · 기아 현상 · 에이징(Aging)
- 기출: 137회 3교시 `운영체제 스케줄링 기법 (SJF 및 SRTF 알고리즘 동작 메커니즘과 평가)`

## 한 줄 본질
- 선착순(FCFS) 스케줄링 시 긴 작업이 CPU를 독점하여 짧은 작업들의 대기 시간이 폭증하는 호위 효과 → 다음 실행할 CPU 버스트 시간이 가장 짧은 프로세스에게 CPU를 먼저 할당 → 주어진 프로세스 집합에 대해 수학적으로 증명된 '최소 평균 대기 시간' 달성 / 미래의 CPU 실행 시간을 사전에 정확히 알 수 없고 긴 작업의 기아 현상 발생

## 핵심 그림
```text
[ 프로세스 도착: P1(버스트 8ms, 0ms 도착), P2(버스트 4ms, 1ms 도착), P3(버스트 2ms, 2ms 도착) ]

1. 비선점 SJF (Non-preemptive): P1이 이미 CPU를 잡았으므로 끝날 때까지 대기
   | P1 (8ms 실행: 0~8)          | P3 (2ms: 8~10) | P2 (4ms: 10~14) |
   0                            8               10                14

2. 선점 SJF = SRTF (Shortest Remaining Time First): 더 짧은 작업 도착 시 즉시 선점!
   | P1 | P2 | P3 (2ms: 2~4) | P2 잔여 (3ms: 4~7) | P1 잔여 (7ms: 7~14) |
   0    1    2              4                    7                     14
   * 1ms 시점에 P2 도착(잔여: P1 7ms vs P2 4ms -> P2 선점)
   * 2ms 시점에 P3 도착(잔여: P2 3ms vs P3 2ms -> P3 선점)
```

## 핵심 용어
- SRTF(Shortest Remaining Time First): 선점형(Preemptive) SJF 알고리즘으로, 새로운 프로세스가 준비 큐에 도착했을 때 현재 실행 중인 프로세스의 잔여 시간보다 새 프로세스의 버스트 시간이 더 짧으면 CPU를 즉시 빼앗는 방식
- 지수 평활법(Exponential Smoothing): 미래의 CPU 버스트 시간을 예측하기 위해 최근 실제 실행 시간($t_n$)과 과거 예측치($\tau_n$)를 가중치 $\alpha$로 결합하는 공식 ($\tau_{n+1} = \alpha t_n + (1-\alpha)\tau_n$)
- HRRN(Highest Response Ratio Next): SJF의 기아 현상을 해결하기 위해 대기 시간($W$)과 서비스 시간($S$)을 결합하여 우선순위( $\frac{W+S}{S}$ )를 계산하는 비선점 스케줄링

## 핵심 통찰
- SJF는 단기 CPU 스케줄링 알고리즘 중 '평균 대기 시간(Average Waiting Time)을 최소화한다'는 측면에서 최적(Optimal)임이 수학적으로 증명되어 있음
- 그러나 범용 OS 단기 스케줄러로 직접 쓸 수 없는 치명적 약점이 있음 → 사용자가 코드를 돌리기 전에 해당 프로그램이 몇 밀리초 동안 CPU를 쓸지 알 수 없기 때문(할팅 문제의 변형)
- 따라서 장기 스케줄러(배치 작업 큐)처럼 사용자가 예상 실행 시간을 작업 카드에 적어내는 배치 시스템이나, 쿠버네티스 배치 잡(Job) 스케줄링의 우선순위 정렬 원리로 주로 응용됨

## 이웃 토픽과 구분
- 비선점 SJF vs SRTF(선점 SJF): 비선점 SJF = 일단 CPU를 잡으면 완료까지 유지 / SRTF = 더 짧은 잔여 시간을 가진 프로세스가 도착하면 즉시 문맥 교환으로 선점(평균 대기시간은 더 단축되나 오버헤드 증가)

## 문제·원인·대책
- 사례: 137회 기출 배치 처리 서버에서 긴 작업이 며칠 동안 실행되지 못하고 큐에 잔류하는 장애
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 대용량 데이터 정산 배치 작업이 짧은 웹 요청들에 밀려 무한 대기 (기아 상태) | 순수 SJF/SRTF 스케줄러의 짧은 작업 우선 편향 | 에이징(Aging) 기법 및 HRRN(대기 시간 반영) 스케줄러 도입 | 대기 시간이 길어질수록 우선순위가 자동 상승하여 실행 보장 |
| SRTF 환경에서 빈번한 짧은 프로세스 유입으로 문맥 교환 오버헤드 급증 | 잔여 시간 차이가 미세함에도 즉시 선점 발생 | 선점 임계치(Threshold) 설정 (잔여 시간 차이가 일정 수준 이상일 때만 선점) | 불필요한 문맥 교환 방지 및 CPU 순수 연산율 유지 |
