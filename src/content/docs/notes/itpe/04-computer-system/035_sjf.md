## 연관 키워드

- SJF(Shortest Job First), 비선점형 SJF, 선점형 SRTF(Shortest Remaining Time First)
- CPU 버스트 시간(CPU Burst Time), 평균 대기 시간(Average Waiting Time), 호송 효과(Convoy Effect)
- FCFS(First-Come First-Served), HRRN(Highest Response Ratio Next), 기아(Starvation), 에이징(Aging)
- 지수 평활법(Exponential Smoothing), MLFQ(Multi-Level Feedback Queue), CFS, vruntime

## Ⅰ. SJF 스케줄링의 개요

- 핵심 요약 : **SJF** (Shortest Job First)는 CPU (Central Processing Unit) 버스트 시간이 가장 짧은 프로세스를 먼저 실행해 평균 대기 시간을 최소화하는 스케줄링 알고리즘.
- 개념 : CPU 버스트 시간이 가장 짧은 프로세스에 CPU를 우선 할당하여, 모든 프로세스의 **평균 대기 시간** (Average Waiting Time)을 최소로 만드는 스케줄링 방식.
- 배경 및 필요성 : 도착 순서대로 처리하는 **FCFS** (First-Come First-Served)에서는 긴 작업 뒤에 짧은 작업들이 줄지어 기다리는 **호송 효과** (Convoy Effect)가 발생하므로, 짧은 작업을 앞세우는 기준 필요.
- 주요 목적 : 평균 대기 시간 최소화, 짧은 작업의 빠른 반환으로 처리량과 사용자 반응성 향상.

## Ⅱ. SJF 스케줄링의 특징 및 장점

- 핵심 요약 : 짧은 작업 우선이라는 단일 기준이 평균 대기 시간 최소화로 이어지며, 선점과 예측 기법으로 현실 환경에 맞춰 확장.

1. 최소 평균 대기 시간 : 주어진 작업 집합에서 짧은 작업을 먼저 처리 → 대기 시간의 총합이 다른 비선점 순서보다 작아짐.
2. **SRTF** (Shortest Remaining Time First) : 선점형 SJF로, 새 프로세스가 도착하면 남은 버스트 시간을 비교해 더 짧으면 즉시 선점 → 짧은 작업의 응답 지연 감소.
3. **지수 평활법** (Exponential Smoothing) : 미래 버스트 시간을 알 수 없으므로 최근 실제 실행 시간과 이전 예측치를 가중 평균하여 다음 버스트를 추정 → 예측 기반 SJF의 실용화.
4. 호송 효과 방지 : 긴 작업 하나가 여러 짧은 작업을 막는 상황을 줄여 준비 큐의 병목 완화.

## Ⅲ. SJF 스케줄링의 구조 및 동작 메커니즘

- 핵심 요약 : 비선점형은 실행 중인 작업을 끝까지 두고, 선점형 SRTF는 도착마다 CPU를 재배정하며, 두 방식 모두 다음 버스트를 예측해 기준으로 사용.

```text
[ 비선점형 SJF : 실행 순서 ]

P1 실행 (0ms 시작, 8ms 소요)
   ↓
P3 실행 (8ms 시작, 2ms 소요)
   ↓
P2 실행 (10ms 시작, 4ms 소요)
```

```text
[ 선점형 SRTF : 실행 순서 ]

0ms : P1 실행 (남은 8ms)
   ↓ 1ms : P2 도착 (4ms < 남은 7ms)
P2 선점 실행
   ↓ 2ms : P3 도착 (2ms < 남은 3ms)
P3 선점 실행, 4ms에 완료
   ↓
P2 재개 (남은 3ms), 7ms에 완료
   ↓
P1 재개 (남은 7ms), 14ms에 완료
```

- 예시의 평균 대기 시간 : 비선점형은 P1(0ms 도착, 8ms), P2(1ms, 4ms), P3(2ms, 2ms) 기준 약 5ms, SRTF는 약 2.67ms로 계산되어 선점이 대기 시간을 줄임.
- 다음 버스트 예측 :

```text
[ 지수 평활법 : 다음 CPU 버스트 예측 ]

tau_{n+1} = alpha*t_n + (1-alpha)*tau_n
   ↓
alpha : 최근 실측 가중치 (0~1)
t_n : 실제 버스트, tau_n : 이전 예측치
```

## Ⅳ. SJF 스케줄링의 비교

- 핵심 요약 : 선점 여부, 기준, 기아 위험, 오버헤드가 알고리즘마다 달라 환경에 맞는 변형을 고름.

| 비교 항목 | FCFS | 비선점형 SJF | 선점형 SRTF | HRRN (Highest Response Ratio Next) |
| --- | --- | --- | --- | --- |
| 선점 여부 | 비선점 | 비선점 | 선점 | 비선점 |
| 스케줄링 기준 | 도착 순서 | 전체 CPU 버스트 시간 | 남은 CPU 시간 | 응답률 (W + S) / S |
| 평균 대기 시간 | 호송 효과로 길어짐 | 짧음 | 이론상 가장 짧음 | 대기 시간 반영으로 양호 |
| 기아 위험 | 없음 | 긴 작업 기아 가능 | 긴 작업 기아 심각 | 에이징으로 방지 |
| 오버헤드 | 매우 낮음 | 버스트 예측 비용 | 잦은 문맥 교환 | 우선순위 재계산 비용 |

- 여기서 W는 대기 시간, S는 예상 실행 시간이다.
- 선택 기준 : 버스트 예측이 가능한지, 기아를 허용할 수 있는지, 문맥 교환 비용이 감당 가능한지에 따라 비선점형, SRTF, HRRN을 고름.

## Ⅴ. SJF 스케줄링의 한계와 방안

- 핵심 요약 : 기아, 예측 부정확, 선점 오버헤드를 HRRN, 다단계 피드백 큐(MLFQ, Multi-Level Feedback Queue), 최소 실행 시간 보장으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 긴 작업의 기아 (Starvation) | 짧은 작업이 계속 도착하면 긴 작업이 CPU를 영구히 배정받지 못함 | 대기 시간이 길수록 우선순위를 높이는 HRRN 채택, 에이징 적용 | 최대 대기 시간, 작업별 대기 편차 |
| 미래 버스트 시간 예측의 불확실성 | 사용자 입력과 분기에 따라 버스트가 변해 지수 평활 예측과 실제 시간이 어긋남 | 사전 지식 없이 CPU 집약도와 I/O 특성을 학습하는 MLFQ로 대체 | 예측 오차, 큐 이동 빈도 |
| SRTF의 문맥 교환 오버헤드 | 아주 짧은 작업이 계속 들어올 때마다 선점과 문맥 교환이 발생해 유효 CPU 연산 비율 하락 | 최소 실행 보장 시간(Minimum Granularity)을 두어 일정 시간 선점 유예 | 문맥 교환 횟수, CPU 유효 사용률 |

## Ⅵ. SJF 스케줄링에 대한 기술사적 제언

- 핵심 요약 : 작업 크기를 알 수 있는 배치 환경에는 SJF 기준을, 공유 환경에는 학습형 큐와 에이징을 결합하는 방향이 현실적.

1. 배치 처리 플랫폼 운영 조직이 작업 제출 시 예상 실행 시간 메타데이터를 받아 짧은 작업 우선 정책을 검토하고, 긴 작업에는 대기 상한을 두어 기아 방지.
2. 서버리스 플랫폼 개발 조직이 실행 시간이 짧은 이벤트 핸들러를 별도 동시성 풀로 라우팅하여 긴 함수가 전체 풀을 막는 병목을 차단.
3. 커널 및 런타임 개발 조직이 실행 이력 기반의 예측과 공정성 지표를 함께 쓰는 설계를 채택. 리눅스 CFS (Completely Fair Scheduler)는 실행량이 적은 쪽을 먼저 고르는 vruntime 기준을 쓰며, 짧은 작업 우선과 목적은 다르지만 실행량 기준이라는 점에서 개념적으로 닿아 있음.

## Ⅶ. 결론

- 핵심 요약 : SJF는 평균 대기 시간을 최소화하는 기준이지만, 버스트 예측 불확실성과 기아 위험을 함께 관리해야 하는 알고리즘.
- 시사점 : 이론적 최적 기준을 그대로 쓰기보다 예측 정확도와 기아 방지 장치를 갖춘 변형으로 적용할 때 실제 성능 이득을 얻을 수 있음.
