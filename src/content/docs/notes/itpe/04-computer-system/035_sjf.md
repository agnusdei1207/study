## Ⅰ. SJF(Shortest Job First) 스케줄링의 개요

- 개념 : **CPU 버스트 시간(Burst Time)** 이 가장 짧은 프로세스에게 CPU를 우선적으로 할당하여, 시스템 내 모든 프로세스의 **평균 대기 시간(Average Waiting Time)** 을 수학적으로 최소화하는 최적화 CPU 스케줄링 알고리즘.
- 배경 및 필요성 : 도착 순서대로 처리하는 **FCFS(First-Come First-Served)** 방식에서 긴 작업 뒤에 짧은 작업들이 지연되어 대기 시간이 폭증하는 호송 효과(Convoy Effect)를 제거하기 위해 고안됨.
- 핵심 목적 : 평균 대기 시간의 이론적 극소화, 짧은 작업의 빠른 처리(반환 시간 단축)를 통한 시스템 처리량 및 사용자 반응성 극대화.

## Ⅱ. SJF(Shortest Job First) 스케줄링의 핵심 아키텍처 및 동작 메커니즘

SJF는 실행 중인 프로세스를 중단시키지 않는 **비선점형 SJF** 와, 남은 시간이 더 짧은 작업이 도착하면 즉시 CPU를 선점하는 선점형 SJF(SRTF)로 구분되며 지수 평활법으로 미래 실행 시간을 예측함.

```text
[ 비선점형 SJF vs 선점형 SRTF 실행 간트 차트 비교 ]

프로세스 도착 및 버스트: P1(도착 0ms, 8ms), P2(도착 1ms, 4ms), P3(도착 2ms, 2ms)

1. 비선점형 SJF (Non-preemptive):
  0ms         8ms        10ms      14ms
  +-----------+----------+---------+
  | P1 (8ms)  | P3 (2ms) | P2 (4ms)|
  +-----------+----------+---------+
  * P1 실행 중 도착한 P2, P3는 P1이 끝날 때까지 대기

2. 선점형 SRTF (Shortest Remaining Time First):
  0ms 1ms 2ms   4ms        7ms                 14ms
  +---+---+-----+----------+-------------------+
  |P1 |P2 | P3  | P2 (3ms) | P1 (남은 7ms)     |
  +---+---+-----+----------+-------------------+
   │   ^ P3(2ms) 도착(2ms): P2의 남은 3ms보다 짧으므로 P3가 즉시 선점!
   │ P2(4ms) 도착(1ms): P1의 남은 7ms보다 짧으므로 P2가 선점!

3. 차기 CPU 버스트 시간 지수 평활법(Exponential Smoothing) 예측 공식:
   tau_{n+1} = alpha * t_n + (1 - alpha) * tau_n  (0 <= alpha <= 1)
```

- **최소 평균 대기 시간 보장** : 임의의 주어진 프로세스 집합에 대해 최단 작업을 먼저 처리함으로써 대기 시간의 합을 수학적으로 최소화.
- **SRTF (선점형 SJF)** : 새로운 프로세스 도착 시 남은 버스트 시간을 비교하여 현재 작업보다 짧으면 즉각 선점(Preemption) 수행.
- **지수 평활법 (Exponential Smoothing)** : 미래의 실제 버스트 시간을 알 수 없으므로 과거의 최근 실행 이력(`t_n`)과 이전 예측치(`tau_n`)에 가중치(`alpha`)를 두어 다음 버스트 시간(`tau_{n+1}`)을 추정.
- **호송 효과(Convoy Effect) 방지** : 긴 작업에 의해 다수의 짧은 작업들이 블로킹되는 병목을 원천 차단.

## Ⅲ. SJF(Shortest Job First) 스케줄링의 세부 구성 요소 및 비교 분석

| 비교 항목 | FCFS | 비선점형 SJF | 선점형 SRTF | HRRN (에이징 결합) |
|---|---|---|---|---|
| **선점 여부** | 비선점형 | 비선점형 | 선점형 | 비선점형 |
| **스케줄링 기준**| 준비 큐 도착 순서 | 총 CPU 버스트 시간 | 남은 CPU 잔여 시간 | 응답률 (W + S) / S |
| **평균 대기시간**| 매우 긺 (호송 효과) | 최소 수준 달성 | 이론상 최단 대기시간 | 대기시간 고려로 우수 |
| **기아 발생 여부**| 기아 없음 | 긴 작업 기아 발생 위험 | 긴 작업 기아 발생 심각 | 기아 완벽 방지 (Aging) |
| **오버헤드** | 극소 | 버스트 시간 예측 부하 | 잦은 문맥 교환 오버헤드 | 우선순위 재계산 부하 |

- SJF는 이상적인 최적 스케줄링 이론이나 미래 버스트 시간을 정확히 예측할 수 없는 현실적 한계로 인해, 현대 OS는 에이징을 결합한 HRRN이나 다단계 피드백 큐(MLFQ)로 변형 적용함.

## Ⅳ. SJF(Shortest Job First) 스케줄링의 주요 한계점 및 해결 방안

- 긴 버스트 시간을 가진 작업의 무한 **대기(기아 현상, Starvation)** :
  - 한계점 : 짧은 작업들이 지속적으로 준비 큐에 도착할 경우 실행 시간이 긴 대형 일괄 작업은 영구히 CPU를 배정받지 못함.
  - 해결 방안 : 대기 시간(W)이 길어질수록 우선순위를 높여주는 HRRN(Highest Response Ratio Next: `(W + S) / S`) 스케줄링 채택.
- 미래의 **CPU** 버스트 시간을 사전에 정확히 알 수 없음 :
  - 한계점 : 런타임 사용자 입력 및 분기에 따라 버스트 시간이 동적으로 변하므로 지수 평활법 예측치와 실제 실행 시간의 괴리 발생.
  - 해결 방안 : 사전 지식 없이도 CPU 집약도와 I/O 특성을 런타임에 동적으로 학습하여 큐를 이동시키는 MLFQ(다단계 피드백 큐)로 대체.
- **선점형(SRTF)** 적용 시 빈번한 문맥 교환 오버헤드 :
  - 한계점 : 아주 미세하게 짧은 작업이 계속 인입될 때마다 캐시를 비우고 디스패칭을 수행하여 실제 CPU 유효 연산율 급락.
  - 해결 방안 : 최소 실행 보장 시간(Minimum Granularity)을 설정하여 일정 시간 동안은 선점을 유예하는 완충 장치 적용.

## Ⅴ. SJF(Shortest Job First) 스케줄링 적용 및 발전을 위한 기술사적 제언

- **배치(Batch)** 작업 스케줄러에서의 실무적 활용 : 하둡, 스파크, 슬럼(Slurm) 등 빅데이터/HPC 일괄 작업 환경에서 작업 크기 메타데이터를 기반으로 SJF를 적용하여 클러스터 처리량 극대화.
- 클라우드 서버리스 **FaaS** 스케줄링 접목 : 실행 시간이 짧은 가벼운 이벤트 핸들러를 우선 배치하여 전체 동시성 풀의 병목을 방지하는 라우팅 정책 수립 권장.
- 현대 리눅스 **CFS** 와의 철학적 융합 이해 : CFS의 가상 실행 시간(vruntime) 개념은 적게 실행된(짧은) 프로세스에게 먼저 CPU를 주는 SJF의 공정성 진화형 모델임을 아키텍처에 반영.
