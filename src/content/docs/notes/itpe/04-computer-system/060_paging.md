## Ⅰ. 페이징(Paging)의 개요

- 개념 : 가상 주소 공간(Virtual Address Space)을 고정된 크기의 블록인 **페이지(Page)** 로 나누고, 물리 메모리(DRAM)를 동일한 크기의 블록인 **프레임(Frame)** 으로 나누어, 프로세스의 메모리를 물리 메모리의 불연속적인 빈 프레임 어디에든 유연하게 사상(Mapping)하여 실행할 수 있도록 지원하는 운영체제 가상 메모리 관리 표준 기술.
- 배경 및 필요성 : 초기 가변 분할 및 세그멘테이션 기법에서 발생하던 심각한 **외부 단편화(External Fragmentation)** 와 메모리 압축의 높은 오버헤드를 근원적으로 제거하기 위해 개발됨.
- 핵심 목적 : 외부 단편화의 완전한 제거, 불연속 물리 메모리 적재를 통한 메모리 활용률 극대화, **요구 페이징(Demand Paging)** 및 공유 메모리 라이브러리 지원.

## Ⅱ. 페이징(Paging)의 핵심 아키텍처 및 동작 메커니즘

페이징은 CPU가 생성한 가상 주소 `<페이지 번호(p), 변위(d)>`를 MMU의 페이지 테이블과 TLB를 통해 물리 주소 `<프레임 번호(f), 변위(d)>`로 변환하며, 64비트 환경에서는 4단계/5단계 다단계 페이지 테이블로 동작함.

```text
[ 페이징 가상 주소 변환 및 다단계 페이지 테이블 ]

가상 주소 (Virtual Address: 48-bit Canonical)
+-----------+-----------+-----------+-----------+----------------+
| PML4 (9b) | PDP (9b)  | PD (9b)   | PT (9b)   | Offset (12-bit)|
+-----------+-----------+-----------+-----------+----------------+
      │
      ▼ (CR3 레지스터 참조)
[PML4 Table] ──> [PDP Table] ──> [Page Directory] ──> [Page Table]
                                                            │
                                                            ▼ PTE 확인
+---------------------------------------------------------------+
| Page Table Entry (PTE: 64-bit 플래그 구조체)                  |
|  - Physical Frame Number (PFN) : 물리 프레임 시작 주소        |
|  - Present / Valid Bit (P)     : 메모리 적재 여부 (0: Page Fault)|
|  - Read/Write Bit (R/W)        : 읽기 전용 vs 쓰기 허용       |
|  - User/Supervisor Bit (U/S)   : 유저 모드 접근 권한          |
|  - Dirty Bit (D) / Accessed (A): 페이지 수정/참조 여부        |
|  - No-Execute Bit (NX)         : 코드 실행 방지 (보안)        |
+---------------------------------------------------------------+
      │
      ▼ 물리 주소 조립: PFN + Offset
+---------------------------------------------------------------+
| 물리 메모리 (DRAM: 4KB 고정 프레임에 직접 접근)               |
+---------------------------------------------------------------+
```

- **고정 분할 매핑** : 가상 페이지와 물리 프레임의 크기를 동일하게(표준 4KB) 설정하여, 물리 메모리의 어떤 빈 프레임이든 즉시 페이지를 할당 가능.
- **주소 변환 공식** : 가상 주소의 페이지 오프셋(`d: 12비트`)은 변환 없이 물리 주소의 오프셋으로 그대로 유지되고, 페이지 번호(`p`)만 프레임 번호(`f`)로 치환.
- **다단계 페이지 테이블 (Multi-level Paging)** : 거대한 64비트 주소 공간의 페이지 테이블 전체를 메모리에 올리지 않고, 실제 사용 중인 주소 영역의 페이지만 계층형 트리로 희소(Sparse) 할당.
- **TLB 주소 변환 가속** : MMU 내부의 고속 SRAM 캐시인 TLB에 최근 변환 엔트리를 캐싱하여 4단계 메모리 참조 오버헤드를 1클럭 수준으로 단축.

## Ⅲ. 페이징(Paging)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 기본 페이징 (4KB Page) | 대용량 페이지 (Huge Page: 2MB) | 초대용량 페이지 (1GB Page) |
|---|---|---|---|
| **페이지 크기** | 4,096 Bytes (12-bit 오프셋) | 2,097,152 Bytes (21-bit 오프셋)| 1,073,741,824 Bytes (30-bit) |
| **페이지 테이블 계층** | 4단계 워크 (PML4->PDP->PD->PT) | 3단계 워크 (PT 생략, PD 직결) | 2단계 워크 (PD/PT 생략) |
| **TLB 커버리지** | 낮음 (512 엔트리 = 2MB 커버) | 매우 높음 (512 엔트리 = 1GB)| 극대화 (수백 GB 메모리 커버)|
| **내부 단편화** | 극소 (최대 4KB 미만) | 커질 수 있음 (최대 2MB 미만) | 큼 (GB 단위 메모리 낭비 가능) |
| **주 권장 워크로드** | 일반 프로세스, 마이크로서비스 | JVM 대형 힙, PostgreSQL DB | 초대형 HPC, KVM 가상화 호스트|

- 페이징은 외부 단편화를 완벽히 해결했으나 페이지 테이블 자체의 메모리 소비와 TLB 미스 페널티가 존재하므로 워크로드별 페이지 크기 선정이 핵심임.

## Ⅳ. 페이징(Paging)의 주요 한계점 및 해결 방안

- 페이지의 마지막 블록 내 잔여 공간으로 인한 내부 단편화 :
  - 한계점 : 프로세스가 5KB를 요구할 경우 2개 페이지(8KB)가 할당되어 3KB의 내부 공간이 낭비되는 비효율 발생.
  - 해결 방안 : 페이지 크기를 4KB로 작게 유지하고 커널 및 애플리케이션 레벨 슬랩(Slab) 메모리 풀을 연계하여 미세 할당.
- 다단계 페이지 테이블 워크에 따른 심각한 메모리 지연 :
  - 한계점 : TLB 미스 발생 시 물리 주소 하나를 얻기 위해 메인 메모리를 4회 연속 접근해야 하므로 연산 성능 급락.
  - 해결 방안 : 하드웨어 2계층 TLB(L1/L2 TLB) 고도화, Huge Pages(2MB/1GB) 적용을 통한 TLB 미스율 대폭 감축.
- 가상화 환경에서의 2차원 **페이징(Two-Dimensional Paging)** 오버헤드 :
  - 한계점 : 게스트 가상 주소 -> 게스트 물리 주소 -> 호스트 물리 주소로 변환 시 최대 24회의 메모리 참조 발생.
  - 해결 방안 : CPU 하드웨어 가상화 지원(Intel EPT / AMD NPT) 활성화 및 호스트 레벨 Huge Page 바인딩.

## Ⅴ. 페이징(Paging) 적용 및 발전을 위한 기술사적 제언

- 데이터베이스 및 인메모리 캐시의 **Static HugePages** 적용 의무화 : Linux Transparent Huge Pages(THP)의 백그라운드 압축 지연을 끄고(`madvise`), 오라클/PostgreSQL에 사전 고정 2MB 페이지 할당 필수.
- **W^X(Write XOR Execute)** 보안 정책의 하드웨어 강제 : 악성코드 쉘코드 실행을 차단하기 위해 PTE의 NX(No-Execute) 비트와 Read/Write 비트를 엄격 분리 관리.
- 메모리 **압축(zRAM)** 을 통한 가상 페이징 효율화 : 모바일 및 엣지 환경에서 디스크 스왑 대신 RAM 일부를 LZ4 알고리즘으로 압축하여 가용 페이지 수를 2배 이상 확보하는 아키텍처 적용.
