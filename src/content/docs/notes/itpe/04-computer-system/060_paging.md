## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 페이징

## 30초 인출

- 본질: 가변 크기로 프로세스를 적재하면 외부 단편화로 메모리가 낭비됨
- 메커니즘: 가상 메모리를 고정 크기 '페이지', 물리 메모리를 동일 크기 '프레임'으로 쪼개어 물리 메모리의 빈자리에 비연속적으로 분산 적재

## 핵심 용어

- 페이지(Page) / 프레임(Frame): 가상 주소 공간을 나눈 고정 크기 블록을 '페이지', 실제 물리 RAM을 동일 크기로 나눈 블록을 '프레임'(기본 4KB)이라 칭함
- TLB(Translation Lookaside Buffer): 가상 주소(VPN)에서 물리 주소(PFN)로의 변환 결과를 최근 참조 이력 기반으로 보관하는 MMU 내부의 초고속 하드웨어 캐시
- 내부 단편화(Internal Fragmentation): 페이지 크기(예: 4KB)보다 작은 데이터(예: 100바이트)를 할당하여 남은 3996바이트가 낭비되는 현상

## 2~4교시 25점 답안

### Ⅰ. 핵심 구조와 작동

```text
[ 하드웨어 페이징 주소 변환 및 TLB 캐시 구조 ]

CPU 발생 논리 주소: [ 가상 페이지 번호 (p) | 오프셋 (d) ]
                             │                 │
                             ├───────+         │
                             │       │         │
                             v       v         │
              [ TLB 고속 캐시 조회 ]           │
             +---------+---------+             │
             | Page(p) |Frame(f) |             │
             +---------+---------+             │
             |   0x01  |  0x5A   |             │
             +---------+---------+             │
                             │                 │
              +──────────────┴──────────────+  │
          TLB Hit!                      TLB Miss!
              │                             │
              │                             v
              │              [ 다단계 페이지 테이블 탐색 (DRAM 접근) ]
              │              (CR3 -> PGD -> PUD -> PMD -> PTE)
              │                             │
              v                             v
       [ 프레임 번호 f ] <───────────────────┘
              │
              v (주소 결합: f || d)
       [ 실제 물리 메모리 주소 (DRAM) ] <──────┘
```

### Ⅱ. 핵심 특성

- 페이징의 본질은 '주소 공간의 비연속화'임 → 프로세스 관점에서는 0번지부터 4GB까지 완벽하게 연속된 메모리를 보는 것처럼 속이고, 실제 물리 RAM에서는 조각조각 빈 프레임마다 던져 넣어 외부 단편화를 0으로 만듦
- 페이징은 메모리 접근 속도를 반토막 낼 뻔했음 → 데이터 1개를 읽으려면 페이지 테이블을 읽기 위해 1번, 실제 데이터를 읽기 위해 1번, 총 2번의 DRAM 접근이 필요함 → 이를 1사이클로 되돌려 놓은 구원투수가 바로 'TLB' 캐시임
- 64비트 환경에서는 4단계(4-Level) 페이징이 기본임 → 64비트 전체를 단일 페이지 테이블로 만들면 테이블 크기만 수백만 GB에 달하므로, 트리 구조로 쪼개어 실제로 사용하는 영역의 페이지만 계층적으로 생성함

### Ⅲ. 관련 개념과 구분

- 페이징 vs 세그먼테이션: 페이징 = 하드웨어 관점, 고정 크기(4KB), 내부 단편화 존재, 물리적 주소 분할 / 세그먼테이션 = 사용자/프로그래머 관점, 가변 크기, 외부 단편화 존재, 논리적 의미 분할

### Ⅳ. 적용 문제와 대응

- 사례: 131회 기출 및 1TB 메모리를 탑재한 Redis 인메모리 DB에서 메모리 접근 속도 저하 및 CPU 지연
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 수백 GB 대규모 메모리 DB 순회 시 TLB 미스율 급증으로 CPU Stall 발생 | 4KB 기본 페이지 사용 시 페이지 테이블 엔트리(PTE) 수가 수천만 개로 폭증 | 리눅스 HugePage(2MB 또는 1GB 페이지) 설정 활성화 | TLB 엔트리 1개가 커버하는 메모리 범위 500배 확장 |
| Fork 기반 스냅샷 저장 시 순간적인 메모리 사용량 2배 폭증 | 부모와 자식 프로세스가 전체 메모리 페이지를 통째로 복제 시도 | 지연 할당 및 Copy-on-Write(CoW) 기법 적용 | 쓰기 발생 전까지 물리 페이지를 읽기 전용으로 공유 |

| 문제 | 해결 방안 |
