## 연관 키워드

- 페이징(Paging), 페이지(Page), 프레임(Frame), 페이지 테이블(Page Table), PTE(Page Table Entry)
- TLB(Translation Lookaside Buffer), 다단계 페이지 테이블(Multi-level Page Table), 요구 페이징(Demand Paging)
- 내부 단편화(Internal Fragmentation), 외부 단편화(External Fragmentation), 대용량 페이지(Huge Page)
- 2차원 페이징(Two-Dimensional Paging), EPT(Extended Page Tables), W^X, zRAM

## Ⅰ. 페이징(Paging)의 개요

- 핵심 요약 : **페이징**은 가상 주소 공간과 물리 메모리를 같은 크기의 블록으로 나누어 불연속 적재를 허용하는 가상 메모리 표준 기법.
- 개념 : 가상 주소 공간을 고정 크기 블록인 **페이지** (Page)로, 물리 메모리(DRAM, Dynamic Random-Access Memory)를 같은 크기의 블록인 **프레임** (Frame)으로 나누고, 페이지를 빈 프레임 어디에나 사상(Mapping)하는 운영체제 기법.
- 배경 및 필요성 : 가변 분할 방식은 **외부 단편화** (External Fragmentation)로 큰 연속 공간을 찾지 못하는 비용을 치르고, 이를 메우려면 메모리 압축(Compaction)의 복사 비용까지 부담해야 함. 블록 크기를 통일하면 연속 공간 요구가 사라져 이 비용을 근원적으로 없앨 수 있어 도입됨.
- 주요 목적 : 외부 단편화 제거, 불연속 적재를 통한 메모리 활용률 향상, **요구 페이징** (Demand Paging)과 공유 라이브러리 지원.

## Ⅱ. 페이징(Paging)의 특징 및 장점

- 핵심 요약 : 고정 크기 매핑, 오프셋 유지 변환, 다단계 테이블, TLB 캐싱이 맞물려 외부 단편화 없이 메모리 활용을 높이는 구조.

1. 고정 크기 매핑 : 페이지와 프레임의 크기를 같게 두어 x86-64 기본 4KB 단위 → 빈 프레임 아무 곳에나 즉시 배치 가능 → 외부 단편화 제거.
2. 오프셋 유지 변환 : 가상 주소의 페이지 번호(p)만 프레임 번호(f)로 바꾸고 오프셋(d)은 그대로 둠 → 변환 로직이 단순해 하드웨어가 빠르게 처리.
3. **다단계 페이지 테이블** (Multi-level Page Table) : 실제 사용 중인 주소 영역의 테이블만 계층 트리로 할당 → 64비트 주소 공간에서도 테이블 메모리 소비를 줄임.
4. **TLB** (Translation Lookaside Buffer) : 최근 변환 결과를 메모리 관리 장치(MMU, Memory Management Unit) 내부 고속 캐시에 보관 → 적중 시 테이블 조회를 생략하여 변환 지연 감소.

## Ⅲ. 페이징(Paging)의 구조 및 동작 메커니즘

- 핵심 요약 : 가상 주소를 다단계 테이블로 따라가 **PTE**(Page Table Entry)에서 프레임 번호를 얻고 오프셋을 붙여 물리 주소를 조립하는 흐름.

```text
[ 가상 주소 → 물리 주소 변환 ]

가상 주소 <p, d>
      ↓
TLB 조회
   적중 → PTE 즉시 획득
   미스 → 다단계 페이지 테이블 워크
      ↓
PTE의 Present 비트 확인
   0 → 페이지 폴트 (운영체제가 페이지 적재)
   1 → 프레임 번호 f 획득
      ↓
물리 주소 = <f, d>
```

```text
[ 4단계 페이지 테이블 워크 (x86-64) ]

가상 주소 (48비트 유효)
PML4 9 | PDP 9 | PD 9 | PT 9 | Offset 12
      ↓
CR3 → PML4 → PDP → PD → PT
      ↓
PTE (프레임 번호 + 권한 비트)
      ↓
물리 주소 = 프레임 + Offset
```

PTE의 주요 필드는 다음과 같음.

1. 프레임 번호 (PFN, Physical Frame Number) : 물리 프레임의 시작 주소.
2. Present 비트 : 0이면 메모리에 없어 페이지 폴트 발생.
3. R/W 비트, U/S 비트 : 쓰기 허용과 사용자 모드 접근 권한.
4. Dirty·Accessed 비트 : 수정 여부와 참조 여부로 페이지 교체 판단에 활용.
5. NX 비트 (No-Execute) : 데이터 영역의 코드 실행을 하드웨어에서 차단.

## Ⅳ. 페이징(Paging)의 비교

- 핵심 요약 : 페이지 크기를 키우면 TLB 커버리지와 테이블 워크 지연은 줄고 **내부 단편화**는 늘어나는 상충 관계로, 워크로드에 맞춰 크기를 고름.

| 비교 항목 | 기본 페이지 (4KB) | **대용량 페이지** (Huge Page, 2MB) | 초대용량 페이지 (1GB) |
| --- | --- | --- | --- |
| 페이지 크기 | 4KB (12비트 오프셋) | 2MB (21비트 오프셋) | 1GB (30비트 오프셋) |
| 테이블 워크 단계 (x86-64) | 4단계 (PML4→PDP→PD→PT) | 3단계 (PT 생략) | 2단계 (PD·PT 생략) |
| TLB 커버리지 (512 엔트리 기준) | 2MB | 1GB | 512GB |
| 내부 단편화 | 작음 | 커질 수 있음 | 큼 |
| 주 워크로드 | 일반 프로세스, 소규모 객체가 많은 서버 | 대형 힙을 쓰는 JVM(Java Virtual Machine), 대형 데이터베이스(DB, Database)의 공유 버퍼 | 대용량 메모리를 쓰는 고성능 컴퓨팅(HPC, High-Performance Computing), 가상화 호스트 |

- 페이징은 외부 단편화를 해결했으나 페이지 테이블 자체의 메모리 소비와 TLB 미스 비용이 남으므로, 페이지 크기 선정이 설계의 핵심 변수가 됨.

## Ⅴ. 페이징(Paging)의 한계와 방안

- 핵심 요약 : 내부 단편화, 다단계 테이블 워크 지연, 가상화 환경의 **2차원 페이징** 오버헤드를 슬랩 할당, 대용량 페이지, 하드웨어 보조 변환으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 내부 단편화 | 마지막 페이지의 잔여 공간 낭비 (예: 5KB 요구에 8KB 할당) | 기본 페이지 크기 유지, 커널과 응용의 슬랩(Slab) 할당기로 소형 객체 미세 할당 | 메모리 낭비율 |
| 테이블 워크 지연 | TLB 미스 때마다 테이블 단계만큼 메모리 접근이 누적 | TLB 용량 확대, 대용량 페이지 적용으로 TLB 미스율 감소 | TLB 미스율 |
| 2차원 페이징(Two-Dimensional Paging) 오버헤드 | 게스트 가상 → 게스트 물리 → 호스트 물리의 이중 변환으로 메모리 참조가 최대 24회 | **EPT** (Extended Page Tables, Intel) 또는 NPT (Nested Page Tables, AMD) 하드웨어 지원 활성화, 호스트 대용량 페이지 바인딩 | 가상머신 메모리 접근 지연, 변환 미스율 |

- 4단계 게스트 워크와 4단계 호스트 워크가 겹치면 최대 24회의 참조가 생기는 계산이 이 표의 근거임.

## Ⅵ. 페이징(Paging)의 적용 제언

- 핵심 요약 : 인메모리 데이터 시스템에는 대용량 페이지를 미리 고정하고, 실행 권한은 W^X로 하드웨어 차원에서 나누며, 메모리가 부족한 환경은 압축 스왑을 보조로 쓰는 방향.

1. 데이터베이스 운영 조직은 버퍼 캐시와 인메모리 캐시가 쓰는 메모리를 정적 대용량 페이지(Static HugePages)로 미리 확보한다. 투명 대용량 페이지(THP, Transparent Huge Pages)의 백그라운드 병합과 분할이 만드는 지연을 피하기 위함이다.
2. 보안 조직은 **W^X** (Write XOR Execute) 정책을 NX 비트와 R/W 비트로 하드웨어에서 강제하고, 빌드 단계에서 쓰기 가능 섹션과 실행 가능 섹션이 한 페이지에 섞이지 않도록 검증한다.
3. 메모리 여유가 부족한 엣지 서버와 개발 서버는 **zRAM** (압축 RAM 기반 스왑 장치)을 디스크 스왑 앞단에 두되, 압축에 쓰이는 CPU(Central Processing Unit) 비용을 함께 모니터링한다.

## Ⅶ. 결론

- 핵심 요약 : 페이징은 고정 크기 블록 매핑으로 외부 단편화를 없애는 가상 메모리의 표준이며, 테이블 메모리와 TLB 미스 비용의 관리가 설계의 핵심.
- 페이지 크기와 테이블 깊이는 워크로드에 맞춰 조정하는 튜닝 변수이므로, 페이징은 고정된 규격이 아니라 운영 지표로 조정하는 기법으로 다뤄야 한다.
