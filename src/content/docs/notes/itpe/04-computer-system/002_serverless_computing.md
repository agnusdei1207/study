## 연관 키워드
- 서버리스 컴퓨팅, FaaS(Function as a Service), 이벤트 트리거, 콜드 스타트, 자동 확장

## Ⅰ. 서버리스 컴퓨팅의 개요
- 핵심 요약 : 서버리스는 실행 인프라 관리를 제공자에 맡기고 이벤트 기반 코드 실행에 집중하는 클라우드 모델.
- 개념 : **서버리스 컴퓨팅**(Serverless Computing)은 제공자가 서버 프로비저닝과 확장을 관리하고 요청·이벤트에 따라 실행환경을 제공하는 방식.
- 배경 및 필요성 : 변동 트래픽을 감당할 서버 용량 계획과 유휴 자원 운영 부담.
- 주요 목적 : 인프라 운영을 줄이고 수요에 따라 컴퓨팅 자원을 소비.

## Ⅱ. 특성 및 장점
- 핵심 요약 : 호출 단위 과금과 자동 확장이 이벤트형 워크로드의 유휴 비용을 줄임.
- FaaS는 함수 단위로 실행 → 기능별 확장과 사용량 과금.
- 관리형 서비스는 인증·저장소·메시징 운영을 위임 → 인프라 관리 부담 감소.
- 실행환경 교체를 전제로 외부에 상태 저장 → 수평 확장 용이.
- 실행시간·메모리·동시성 한도는 제공자별로 확인.

## Ⅲ. 실행 흐름
- 핵심 요약 : 트리거가 함수를 호출하면 플랫폼이 실행환경을 배치·확장하고 결과를 수집.
```text
이벤트 → API·큐·저장소 트리거
  ↓
함수 실행환경 할당
  ↓ 입력 처리·외부 서비스 호출
결과·로그 → 실행환경 축소
```
```text
요청 증가 → 동시 실행 증가
요청 감소 → 실행 수 축소
첫 실행 → 콜드 스타트 가능
```
- 재시도는 중복 호출을 만들 수 있으므로 멱등성·타임아웃·오류 큐가 필요.

## Ⅳ. 서버리스와 컨테이너 비교
- 핵심 요약 : 운영 책임과 장기 실행·런타임 제어 요구로 실행 모델을 선택.
| 비교 축 | 서버리스 함수 | 컨테이너 |
| --- | --- | --- |
| 운영 | 제공자 관리 | 팀이 클러스터·런타임 관리 |
| 단위 | 호출·이벤트 | 장기 실행 서비스·작업 |
| 적합 | 불규칙 단기 처리 | 상시·세밀한 환경 제어 |

## Ⅴ. 한계와 방안
- 핵심 요약 : 콜드 스타트, 상태, 실행 제한, 비용 변동은 실제 부하 검증으로 관리.
| 한계 | 원인·영향 | 대응 |
| --- | --- | --- |
| 초기 지연 | 콜드 스타트 | 초기화 최소화·경로 분리 |
| 상태 손실 | 인스턴스 교체 | 외부 저장·멱등 처리 |
| 실행 한도 | 장기 작업 제한 | 큐 분할·컨테이너 전환 |
| 비용·종속 | 호출량·관리형 API | 경보·대체 경로·비용 분석 |

## Ⅵ. 도입 제언
- 핵심 요약 : 플랫폼팀은 이벤트 계약·권한·관측·오류 처리 표준을 제공.
- 업무팀은 재시도·동시성·비밀정보 관리와 제공자 한도를 부하 시험으로 확인.

## Ⅶ. 결론
- 핵심 요약 : 서버리스는 서버의 부재가 아니라 인프라 운영을 추상화한 이벤트 중심 실행 모델.
- 운영 편익과 실행 제약·종속 비용을 함께 고려해야 적절한 도입 가능.
