## 연관 키워드

- 캐시 일관성(Cache Coherence), MESI(Modified, Exclusive, Shared, Invalid), MOESI(Modified, Owned, Exclusive, Shared, Invalid)
- 스누핑(Snooping) 프로토콜, 디렉터리 기반 프로토콜(Directory-based Protocol)
- 쓰기 무효화(Write-Invalidate), 쓰기 갱신(Write-Update), 거짓 공유(False Sharing), 패딩(Padding)
- SMP(Symmetric Multiprocessing), NUMA(Non-Uniform Memory Access)

## Ⅰ. 캐시 일관성의 개요

- 핵심 요약 : **캐시 일관성** (Cache Coherence)은 코어별 캐시에 존재하는 동일 메모리 블록 복사본의 값 일치를 프로토콜로 보장하는 메커니즘.
- 개념 : 각 코어가 전용 캐시를 두는 **대칭형 멀티프로세서** (SMP, Symmetric Multiprocessing) 환경에서 같은 주소의 여러 복사본이 서로 다른 값을 지니는 상황을 막는 상태 관리 규칙.
- 배경 및 필요성 : 쓰기 시점에 메모리를 함께 갱신하지 않는 쓰기 정책에서 한 코어의 수정이 타 코어 캐시에 반영되지 않아 판독 결과가 어긋나는 문제.
- 주요 목적 : 공유 메모리의 단일 관점 보장, 쓰기 충돌의 하드웨어적 해소, 코어 수 증가에 대응하는 확장성 확보.

## Ⅱ. 캐시 일관성의 특징 및 장점

- 핵심 요약 : 상태 기계와 감시·추적 방식의 조합이 쓰기 충돌을 하드웨어에서 정리해 소프트웨어 부담을 제거함.

1. **MESI** (Modified, Exclusive, Shared, Invalid) 프로토콜 : 캐시 라인을 수정·독점·공유·무효의 네 상태로 관리하는 상태 기계 → 복사본 성질 구분으로 불필요한 메모리 트래픽 절감 효과.
2. 쓰기 정책 : **쓰기 무효화** (Write-Invalidate)는 타 복사본을 무효화한 뒤 독점 수정, **쓰기 갱신** (Write-Update)은 모든 복사본에 변경값을 즉시 반영 → 무효화 방식이 배타적 접근 구현에 유리한 구조.
3. **스누핑** (Snooping) 프로토콜 : 각 캐시 제어기가 공유 매체의 트랜잭션을 감시해 자기 복사본 상태를 갱신하는 방식 → 별도 추적 구조 없이 낮은 지연 구현 효과.
4. **디렉터리 기반 프로토콜** (Directory-based Protocol) : 메모리 블록별 복사본 보유 코어 목록을 디렉터리가 관리하는 방식 → 필요한 코어에만 메시지 전달로 확장성 확보.
5. **MOESI** (Modified, Owned, Exclusive, Shared, Invalid) 프로토콜 : 소유 상태를 추가해 수정값을 메모리 기록 없이 타 캐시와 공유 → 메모리 쓰기 감소 효과.

## Ⅲ. 캐시 일관성의 구조 (흐름)

- 핵심 요약 : 쓰기가 복사본의 상태 전이를 유발하며, 스누핑 방식은 버스 감시로 무효화를 수행함.

```text
[ MESI 상태 전이의 핵심 경로 ]

I (무효)
   ↓ 자신의 읽기 요청
E (독점) 또는 S (공유)
   ↓ 자신의 쓰기
M (수정)
   ↓ 타 코어의 읽기
S (공유) : 메모리 반영 후 전환
   ↓ 타 코어의 쓰기
I (무효)
```

```text
[ 스누핑 기반 무효화 흐름 ]

코어 A : 쓰기 요청 발행
   ↓
버스에 무효화 신호 방송
   ↓
각 캐시 제어기의 트랜잭션 감시
   ↓
보유 코어의 복사본 I 전환
   ↓
코어 A의 독점 수정 진행
```

- 상태 정의 : M은 메모리와 불일치하는 유일 복사본, E는 메모리와 일치하는 유일 복사본, S는 복수 캐시의 판독 전용 복사본, I는 접근 시 미스가 발생하는 무효 복사본.
- 구성요소 : 캐시 라인별 상태 비트, 상태 전이 규칙, 복사본 변경 통지 채널(버스 감시 또는 디렉터리 조회)로 구성.

## Ⅳ. 스누핑 방식과 디렉터리 기반 방식의 비교

- 핵심 요약 : 스누핑은 소규모 구성에서 단순하고 빠르며, 디렉터리 기반은 대규모 구성에서 확장성을 확보.

| 비교 항목 | 스누핑 방식 | 디렉터리 기반 방식 |
| --- | --- | --- |
| 통신 구조 | 공유 매체 방송과 전체 감시 | 디렉터리 조회 후 지정 통지 |
| 적합 규모 | 소규모 멀티코어 | 대규모 코어·소켓 구성 |
| 대역폭 소비 | 코어 수에 비례해 증가 | 대상 코어 한정으로 절감 |
| 상태 추적 위치 | 각 캐시 제어기 | 중앙·분산 디렉터리 |
| 하드웨어 부담 | 제어기가 단순 | 블록별 보유 목록 저장 필요 |

- 선택 기준 : 코어 수와 상호 연결 구조, 감시 트래픽의 감수 범위에 따라 방식을 선택하며, 대규모 **NUMA** (Non-Uniform Memory Access) 서버는 디렉터리 방식이 일반적.

## Ⅴ. 캐시 일관성의 한계와 방안

- 핵심 요약 : 거짓 공유, 감시 트래픽 포화, 상태 전이의 복잡성을 데이터 배치, 프로토콜 전환, 형식 검증으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **거짓 공유** (False Sharing) | 무관한 변수의 동일 라인 배치 → 쓰기마다 타 코어 복사본 무효화 | 변수 배치의 **패딩** (Padding)과 정렬로 라인 분리 | 무효화 횟수, 캐시 미스율 |
| 감시 트래픽의 포화 | 방송 구조의 대역폭 한계 → 코어 확장 시 성능 저하 | 디렉터리 방식 전환, 보유 목록 기반의 감시 범위 축소 | 매체 사용률, 코어당 트래픽 |
| 상태 전이의 복잡성 | 프로토콜 조합의 경우의 수 → 검증 비용 증가 | 표준 프로토콜 채택과 형식 검증 도구 적용 | 전이 오류 검출 건수 |

## Ⅵ. 캐시 일관성에 대한 기술사적 제언

- 핵심 요약 : 데이터 배치 규칙, 프로토콜 선택 기준, 프로토콜 검증 절차를 조직 표준으로 정착하는 방향.

1. 고성능 소프트웨어 개발 조직이 공유 자료구조의 캐시 라인 정렬과 라인 분리 규칙을 코딩 표준에 포함해 거짓 공유를 설계 단계에서 차단.
2. 플랫폼 아키텍처 조직이 코어 규모별 프로토콜 선택 기준을 시스템 설계 문서로 정리해 감시 트래픽 리스크의 사전 관리.
3. 검증 조직이 상태 전이 모델의 형식 검증 절차를 칩·시스템 개발 과정에 도입해 프로토콜 결함의 조기 발견.

## Ⅶ. 결론

- 핵심 요약 : 캐시 일관성은 상태 기계 프로토콜로 다중 코어의 복사본 정합성을 보장하는 하드웨어 체계.
- 시사점 : 프로토콜 선택과 데이터 배치가 함께 이루어질 때 정합성과 확장성이 동시에 확보되는 구조.
