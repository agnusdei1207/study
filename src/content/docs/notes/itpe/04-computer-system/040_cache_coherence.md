## 연관 키워드

- 캐시 일관성(Cache Coherence), MESI, MOESI, 스누핑(Snooping), 디렉터리 기반 프로토콜(Directory-based Protocol)
- 거짓 공유(False Sharing), 패딩(Padding), 스누프 필터(Snoop Filter)
- SMP(Symmetric Multiprocessing), NUMA(Non-Uniform Memory Access), CXL(Compute Express Link)
- 릴리즈 일관성(Release Consistency), 메모리 오더링(Memory Ordering), 락프리(Lock-Free)

## Ⅰ. 캐시 일관성의 개요

- 핵심 요약 : **캐시 일관성** (Cache Coherence)은 멀티코어 시스템에서 코어마다 가진 캐시 복사본이 서로 어긋나지 않도록 하드웨어가 보장하는 메커니즘.
- 개념 : **대칭형 멀티프로세서** (SMP, Symmetric Multiprocessing)나 멀티코어에서 각 프로세서가 자기 전용 캐시(L1, L2)를 가질 때, 같은 메인 메모리 주소의 복사본들이 서로 다른 값으로 남지 않도록 항상 최신의 유효한 데이터를 공유하게 하는 하드웨어 규칙.
- 배경 및 필요성 : 여러 코어가 같은 공유 변수를 읽고 쓰면, 지연 쓰기 (Write-back) 정책 때문에 한 코어의 갱신이 다른 코어의 캐시에 즉시 보이지 않아 연산 결과가 틀어지므로, 이를 막는 하드웨어 규칙 필요.
- 주요 목적 : 메모리에 대한 단일 관점(Single-view) 보장, 하드웨어 수준의 데이터 정합성 유지, 코어 수 증가에 따른 확장성과 병렬 프로그램의 신뢰성 확보.

## Ⅱ. 캐시 일관성의 특징 및 장점

- 핵심 요약 : 상태 머신과 감시 방식의 조합이 쓰기 충돌을 하드웨어에서 정리하여, 소프트웨어가 캐시 상태를 직접 관리할 필요 없음.

1. **MESI** 상태 머신 (Modified, Exclusive, Shared, Invalid) : 수정, 독점, 공유, 무효 네 상태를 캐시 라인마다 관리 → 복사본의 성격을 구분해 불필요한 메모리 접근을 줄임.
2. **스누핑** (Snooping) 프로토콜 : 모든 캐시 제어기가 공유 버스를 감시하다가 다른 코어의 쓰기 신호를 보면 자기 복사본을 무효화 → 구현이 단순하고 지연이 짧음.
3. **디렉터리 기반 프로토콜** (Directory-based Protocol) : 메모리 블록마다 복사본을 가진 코어 목록을 두고 필요한 코어에만 점대점 메시지를 보냄 → 대규모 NUMA (Non-Uniform Memory Access) 환경에서 브로드캐스트 부담 감소.
4. **MOESI** (Modified, Owned, Exclusive, Shared, Invalid) : Owned(소유) 상태를 추가하여 메모리에 기록하지 않고도 수정된 데이터를 다른 캐시와 공유 → 메모리 쓰기 횟수 감소.

## Ⅲ. 캐시 일관성의 구조 및 동작 메커니즘

- 핵심 요약 : 쓰기가 발생하면 복사본을 무효화하는 신호가 나가고, 그 전달 경로가 버스 브로드캐스트인지 디렉터리 조회인지에 따라 두 방식으로 나뉨.

```text
[ MESI 상태 전이 : 핵심 경로 ]

Invalid --로컬 쓰기--> Modified
   ↓ 다른 코어 읽기 요청 (메모리 반영)
Shared
   ↓ 다른 코어 쓰기 요청
Invalid
```

```text
[ 스누핑 방식 ]

코어 A 쓰기
   ↓ 버스에 무효화 신호 브로드캐스트
모든 캐시 제어기가 감시 (Snoop)
   ↓
해당 라인의 복사본 무효화
```

```text
[ 디렉터리 기반 방식 ]

코어 A 쓰기 요청
   ↓ 디렉터리 조회
복사본 보유 코어 목록 확인
   ↓ 점대점 메시지
보유 코어의 복사본만 무효화
```

- M은 메모리와 불일치하는 유일한 복사본, E는 메모리와 일치하는 유일한 복사본, S는 여러 캐시에 존재하는 읽기 전용 복사본, I는 읽으면 캐시 미스가 나는 무효 상태.

## Ⅳ. 캐시 일관성 방식의 비교

- 핵심 요약 : 스누핑은 소규모에서 빠르고 단순하며, 디렉터리 기반은 코어 수가 많은 환경에서 확장성을 확보.

| 비교 항목 | 스누핑 방식 (Snooping) | 디렉터리 기반 방식 (Directory-based) |
| --- | --- | --- |
| 통신 메커니즘 | 공용 버스 브로드캐스트 | 디렉터리 조회 후 점대점 메시지 |
| 적합 규모 | 소규모 멀티코어, 일반 PC와 소형 서버 | 대규모 분산 공유 메모리, NUMA 대형 서버 |
| 상호 연결 | 공유 버스 또는 크로스바 스위치 | 메시, 링, 토러스 같은 고속 인터커넥트 |
| 대역폭 확장성 | 코어 증가 시 버스 포화 | 디렉터리 분산으로 확장성 우수 |
| 하드웨어 부담 | 캐시 제어기가 단순, 추가 메모리 불필요 | 블록마다 공유 상태 비트맵 저장 필요 |

- 선택 기준 : 코어 수와 인터커넥트 구조에 따라 버스 기반 감시를 쓸지, 디렉터리로 추적 범위를 줄일지 결정.
- 현대 다중 소켓 서버와 CXL (Compute Express Link) 기반 구성에서는 디렉터리 기반 방식이 주로 쓰임.

## Ⅴ. 캐시 일관성의 한계와 방안

- 핵심 요약 : 거짓 공유, 버스 포화, 가속기와의 일관성 단절을 데이터 배치, 디렉터리 전환, CXL 일관성 인터커넥트로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **거짓 공유** (False Sharing) | 서로 무관한 변수가 같은 캐시 라인에 있어 한쪽 쓰기가 다른 코어의 복사본을 계속 무효화 | 정렬 (Alignment)과 패딩 (Padding)으로 스레드별 변수를 서로 다른 캐시 라인에 분리 | 캐시 미스율, 무효화 횟수 |
| 스누핑 브로드캐스트의 버스 포화 | 코어 수가 늘수록 무효화 신호가 공용 버스를 점유해 실제 데이터 전송 대역폭 잠식 | 디렉터리 기반 프로토콜로 전환, LLC (Last-Level Cache)에 스누프 필터 (Snoop Filter)를 두어 불필요한 감시 감소 | 버스 사용률, 코어당 대역폭 |
| 이종 가속기와의 일관성 단절 | GPU (Graphics Processing Unit), NPU (Neural Processing Unit), CXL 장치가 별도 경로로 연결되어 소프트웨어 동기화에 지연 발생 | CXL.cache와 CXL.mem 기반의 하드웨어 일관성 인터커넥트 도입 | 가속기 간 동기화 지연 |

## Ⅵ. 캐시 일관성에 대한 기술사적 제언

- 핵심 요약 : 하드웨어 일관성에 기대는 설계와 소프트웨어 메모리 모델 이해를 함께 갖추어, 병렬 코드의 성능과 정합성을 동시에 확보하는 방향.

1. 고성능 라이브러리 개발 조직이 공유 카운터와 락프리 자료구조에 캐시 라인 정렬을 기본 규칙으로 적용하여 거짓 공유를 설계 단계에서 차단.
2. 시스템 아키텍처 조직이 이종 컴퓨팅 플랫폼을 설계할 때 CXL 기반의 CPU와 가속기 간 하드웨어 일관성을 기준 아키텍처로 채택하여 소프트웨어 동기화 부담을 줄임.
3. 개발 교육 조직이 C++ 메모리 오더링 (memory_order_relaxed, acquire/release) 등 릴리즈 일관성 모델을 사내 가이드로 제공하여, 정확성 없이 성능만 높이는 최적화를 방지.

## Ⅶ. 결론

- 핵심 요약 : 캐시 일관성은 MESI 상태 머신과 스누핑 또는 디렉터리 프로토콜로 멀티코어의 데이터 정합성을 하드웨어에서 보장하는 장치.
- 시사점 : 하드웨어가 정합성을 지키더라도 거짓 공유와 대역폭 한계는 소프트웨어 배치와 구조 선택으로 줄여야 하므로, 일관성 비용을 설계 단계에서 함께 고려할 필요.
