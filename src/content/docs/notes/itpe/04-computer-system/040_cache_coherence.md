## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 캐시 일관성

## 30초 인출

- 본질: 멀티코어 프로세서에서 각 코어가 독립된 L1/L2 캐시를 가질 때, 동일한 메인 메모리 변수를 각자 캐싱한 후 한 코어가 값을 수정하면 다른 코어의 캐시 데이터가 구버전으로 전락하는 불일치 현상
- 메커니즘: 하드웨어 버스 스누핑(MESI) 또는 분산 디렉터리를 통해 쓰기 발생 시 타 캐시 라인을 즉각 무효화(Invalidate)

## 핵심 용어

- 스누핑(Snooping): 모든 코어가 공유 메모리 버스를 상시 엿듣고(Snoop) 감시하다가, 타 코어가 자신이 가진 캐시 주소에 쓰기를 시도하면 자신의 캐시 라인을 스스로 '무효화(Invalid)'시키는 방식
- 디렉터리 기반(Directory-based): 공유 버스가 없는 대규모 분산 메모리(NUMA) 환경에서, 각 메모리 블록이 현재 어느 코어들의 캐시에 복제되어 있는지 중앙 디렉터리 테이블에 기록해 두고 필요한 노드에만 점대점(Point-to-point) 메시지를 보내는 방식
- 거짓 공유(False Sharing): 서로 다른 스레드가 독립적인 서로 다른 변수를 수정함에도, 두 변수가 우연히 동일한 64바이트 캐시 라인에 인접해 있어 불필요한 캐시 무효화가 반복되어 성능이 붕괴하는 현상

## 1교시 10점 답안

### Ⅰ. 정의·목적

- 정의: 캐시 일관성은/는 하드웨어 버스 스누핑(MESI) 또는 분산 디렉터리를 통해 쓰기 발생 시 타 캐시 라인을 즉각 무효화(Invalidate) 방식이다.
- 목적: 데이터 일관성 완벽 보장에 기여한다.

### Ⅱ. 핵심 구조와 작동

```text

             v                                                        │
      +──────────────+         PrWr (로컬 쓰기)          +──────────────+
      |  Shared (S)  | ───────────────────────────────> | Modified (M)  |
      |  (읽기 전용   | <─────────────────────────────── | (수정됨: 유일 |
      |   다중 공유) |   BusRd (타 코어가 읽기 요청)     |  더티 라인)  |
      +──────────────+                                   +──────────────+
             ▲                                                  │
             │ PrRd (로컬 읽기)                                 │ PrWr / BusRdX
             │                                                  v
      +──────────────+                                   +──────────────+
      | Exclusive (E)|                                   |  Invalid (I) |
      | (단독 클린)  | ──(BusRdX: 타 코어 쓰기 브로드캐스트)──> | (무효화됨:   |
      +──────────────+                                   |  사용 불가)  |
                                                         +──────────────+
```

```text
      +──────────────+                                   |  사용 불가)  |
                                                         +──────────────+
```

### Ⅱ. 핵심 특성

- 캐시 일관성은 프로그래머가 코드로 맞추는 것이 아니라 'CPU 하드웨어가 100% 자동으로 맞추는 것'임 → 프로그래머는 일관성을 의심할 필요가 없으나, 하드웨어가 일관성을 맞추느라 버스에 무효화 트래픽을 쏟아붓는 비용을 인식해야 함
- 코어 수가 8~16개 수준인 일반 CPU는 브로드캐스트 버스 기반의 '스누핑(MESI)'으로 충분하지만, 수십~수백 개 코어를 가진 서버용 대규모 CPU(Xeon, EPYC)에서는 브로드캐스트 폭풍을 피하기 위해 '디렉터리 기반' 프로토콜이 필수적임
- 멀티스레드 성능 병목의 숨겨진 주범은 '거짓 공유'임 → 코어 간 변수가 겹치지 않아도 64바이트 단위 캐시 라인을 공유하면 매 쓰기마다 상대 코어의 L1 캐시가 날아가 L3/RAM 접근 패널티 발생

### Ⅲ. 관련 개념과 구분

- 스누핑 vs 디렉터리 기반: 스누핑 = 공유 버스 브로드캐스트 방식(소규모 코어, 구현 단순, 대역폭 한계) / 디렉터리 기반 = 상태 디렉터리 기반 점대점 유니캐스트 방식(대규모 NUMA 서버, 대역폭 보존, 디렉터리 메모리 오버헤드)

### Ⅳ. 적용 문제와 대응

- 사례: 137회 기출 멀티코어 고성능 연산 서버에서 코어 수를 늘렸음에도 처리량이 오히려 감소하는 현상
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 멀티스레드 배열 합산 연산 시 코어 증가에 따라 성능이 역주행 | 스레드별 집계 변수가 동일 캐시 라인(64Byte)에 밀집 (거짓 공유: False Sharing) | 변수 간 64바이트 캐시 라인 패딩(Padding / `@Contended`) 적용 | 각 스레드 변수를 독립 캐시 라인으로 격리하여 버스 트래픽 제로화 |
| 수백 개 코어 환경에서 스누핑 브로드캐스트로 인한 인터커넥트 버스 포화 | 스누핑 방식의 노드 확장성($O(N^2)$) 한계 | 디렉터리 기반 일관성 프로토콜(Directory-based Coherence) 채택 | 필요한 노드에만 무효화 메시지 전송으로 대역폭 90% 보존 |
