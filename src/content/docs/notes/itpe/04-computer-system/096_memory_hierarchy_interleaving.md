## Ⅰ. 메모리 계층과 메모리 인터리빙의 개요

- 개념 : 속도, 용량, 가격의 트레이드오프 관계를 최적화하기 위해 레지스터부터 스토리지까지 피라미드 구조로 구성한 **메모리 계층** (Memory Hierarchy) 과, 주기억장치를 다수의 독립된 메모리 뱅크(Bank)로 분할하고 주소를 번갈아 배치하여 동시 접근을 가능하게 하는 **메모리 인터리빙** (Memory Interleaving) 기술.
- 배경 및 필요성 : CPU(Central Processing Unit)의 초고속 연산 클록(GHz)과 메인 메모리(DRAM, Dynamic Random-Access Memory)의 상대적으로 느린 접근 속도 사이의 격차(메모리 벽)를 극복하고, 프로그램의 참조 지역성(Locality)을 활용하여 **평균 메모리 접근 시간** (AMAT, Average Memory Access Time)을 최소화하기 위해 필수적임.
- 핵심 목적 : 고비용 초고속 메모리와 저비용 대용량 메모리의 조화를 통한 경제성 확보, 메모리 버스 대역폭 포화 및 **뱅크 충돌** (Bank Conflict) 완화.

## Ⅱ. 메모리 계층 및 인터리빙 동작 메커니즘

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 컴퓨터 시스템 메모리 계층 구조 및 저위 인터리빙 원리 ]              │
│                                                                        │
│   [ 레지스터 (Registers) ]         ─ 0.5ns, 수 KB, CPU 내부            │
│          ▼                                                             │
│   [ L1 / L2 / L3 캐시 메모리 ]     ─ 1~10ns, 수십 MB, SRAM             │
│          ▼ (지역성: Temporal & Spatial Locality 활용)                  │
│   [ 메인 메모리 (Main Memory) ]    ─ 50~100ns, 수십~수백 GB, DRAM       │
│          ▼                                                             │
│   [ 보조기억장치 (SSD / HDD) ]     ─ 수십 μs ~ 수 ms, TB~PB급, 플래시/디스크│
│                                                                        │
│   ─── [ 저위 인터리빙 (Low-Order Interleaving) 주소 분할 구조 ] ─────  │
│                                                                        │
│   주소 버스: [ 상위 주소 비트: 모듈 내 블록 주소 ] [ 하위 2비트: 뱅크 번호 ]│
│                                                     │                  │
│                    ┌──────────┬──────────┬──────────┴──────────┐       │
│                    ▼          ▼          ▼                     ▼       │
│                [Bank 0]   [Bank 1]   [Bank 2]              [Bank 3]    │
│                Addr: 0    Addr: 1    Addr: 2               Addr: 3     │
│                Addr: 4    Addr: 5    Addr: 6               Addr: 7     │
│                Addr: 8    Addr: 9    Addr: 10              Addr: 11    │
│                -> 연속된 주소를 4개 뱅크에 파이프라인 동시 전송 가능    │
└────────────────────────────────────────────────────────────────────────┘
```

- **참조의 지역성** (Locality of Reference) : **시간 지역성** (최근 참조된 항목이 곧 재참조됨)과 **공간 지역성** (참조된 항목의 인접 항목이 곧 참조됨)을 활용하여 상위 캐시에 적중(Hit)되도록 유도.
- **저위 인터리빙** (Low-Order Interleaving) : 주소의 최하위 비트를 뱅크 번호로 사용하여 연속된 주소의 데이터들을 서로 다른 뱅크에 교차 배치함으로써, 메모리 사이클 시간(Cycle Time) 동안 여러 뱅크에서 데이터를 파이프라인 방식으로 동시 인출.

## Ⅲ. 고위 인터리빙과 저위 인터리빙 비교 분석

| 비교 항목 | 고위 인터리빙 (High-Order Interleaving) | 저위 인터리빙 (Low-Order Interleaving) |
| :--- | :--- | :--- |
| **뱅크 선택 비트** | 주소의 최상위 비트 (MSB, Most Significant Bit) 사용 | 주소의 최하위 비트 (LSB, Least Significant Bit) 사용 |
| **데이터 배치 형태** | 특정 모듈에 연속된 주소 블록 전체가 적재 | 연속된 주소가 각 뱅크에 순차적으로 교차 분산 |
| 주요 목적 | 독립된 프로그램 또는 모듈 단위의 메모리 확장 | 연속 데이터 블록의 초고속 병렬/파이프라인 접근 |
| **동시 접근 특성** | 서로 다른 모듈에 접근할 때만 병렬성 발생 | 순차 주소 접근 시 뱅크 동시 접근 가속 |
| **장애 영향** | 특정 뱅크 고장 시 해당 메모리 영역만 격리 | 특정 뱅크 고장 시 전 시스템 메모리 주소 파편화 |
| 적용 영역 | 다중 처리기 시스템의 분할 메모리 | 고성능 CPU의 메인 메모리 채널, 캐시 메모리 |

## Ⅳ. 메모리 계층 및 인터리빙의 주요 한계점 및 해결 방안

- 뱅크 충돌(Bank Conflict)로 인한 파이프라인 지연 :
  - 한계점 : 스트라이드(Stride) 접근 패턴이 뱅크 수의 배수일 경우 동일 뱅크로만 요청이 몰려 인터리빙 이점이 완전히 상실되고 대기 발생.
  - 해결 방안 : 소수(Prime Number) 기반 모듈러 인터리빙 적용, 의사 랜덤(Pseudo-Random) 해시 인터리빙 또는 캐시 라인 패딩 기법 적용.
- DRAM 리프레시(Refresh) 동작에 따른 접근 블로킹 :
  - 한계점 : 셀 커패시터 전하 누설을 방지하기 위한 주기적 리프레시 동작 중에는 해당 뱅크의 읽기/쓰기가 차단되어 지연 스파이크 발생.
  - 해결 방안 : 전체 뱅크를 한 번에 리프레시하지 않고 뱅크별로 순차 진행하는 Per-Bank Refresh(PBR) 기술 도입.
- 메모리 버스 신호 무결성 저하 및 배선 한계 :
  - 한계점 : 메모리 채널과 뱅크 수를 물리적으로 늘릴수록 메인보드 트레이스 배선 복잡도와 크로스토크(Crosstalk) 노이즈 급증.
  - 해결 방안 : 직렬 패킷 기반 인터페이스를 제공하는 CXL(Compute Express Link) 메모리 확장 모듈 도입.

## Ⅴ. 컴퓨터 시스템 구조 최적화를 위한 기술사적 제언

- CXL 기반 메모리 풀링 및 계층 확장 아키텍처 수립 : 물리적 마더보드 슬롯의 한계를 넘어 CXL 2.0/3.0 스위치를 통해 대규모 DRAM 풀을 분리 구성하고, OS(Operating System) 계층에서 CXL 메모리를 NUMA(Non-Uniform Memory Access) 노드로 인식시켜 핫/콜드 데이터 계층화를 자동화해야 함.
- 소프트웨어 레벨의 캐시 및 NUMA 친화적 코드 최적화 : 하드웨어 인터리빙과 캐시 계층을 최대한 활용할 수 있도록 개발 단계에서 데이터 구조를 캐시 라인(64바이트) 크기에 정렬(Alignment)하고, CPU 코어 선호도(Affinity) 바인딩을 통해 크로스 노드 메모리 트래픽을 원천 차단할 것을 제언함.
