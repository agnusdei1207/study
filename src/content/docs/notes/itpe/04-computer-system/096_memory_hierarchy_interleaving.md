## 답안 골격
```text
[메모리 계층·인터리빙] ◀━━ 머리: Ⅶ 내 의견 (메모리 계층 피라미드와 다중 뱅크 인터리빙을 통한 폰 노이만 병목(Memory Wall) 돌파)
 ┃
 ┣━ Ⅰ 개요 ───── CPU 연산 속도와 주기억장치 접근 속도 간의 격차(Memory Wall) 심화 → 계층적 메모리 배치 및 메모리 인터리빙으로 대역폭 극대화
 ┣━ Ⅱ 특징 ───── 속도-용량-비용의 트레이드오프 · 참조의 지역성(시간/공간) 활용 · 독립 뱅크 병렬 접근 · 파이프라인식 데이터 전송
 ┣━ Ⅲ 구조 ───── 레지스터 + 캐시(L1/L2/L3) + 주기억장치(DRAM 뱅크 분할) + 보조기억장치(SSD/HDD) + 인터리빙 제어기
 ┣━ Ⅳ 흐름 ───── ① 주소 버스 신호 수신 → ② 주소 디코딩(하위/상위 비트로 뱅크 선택) → ③ 복수 뱅크 동시 활성화 → ④ 버스 다중화 전송
 ┣━ Ⅴ 비교 ───── 상위 인터리빙(High-order: 모듈 분할) vs 하위 인터리빙(Low-order: 연속 주소 분산)
 ┗━ Ⅵ 실무 ───── 뱅크 충돌(Bank Conflict)로 인한 지연 / 단일 뱅크 편중 접근 / 메모리 채널 비대칭 구성(Flex Mode)
```
- 필수 키워드: 메모리 계층 구조 · 메모리 인터리빙 · 뱅크(Bank) · 하위 인터리빙 · 상위 인터리빙 · 뱅크 충돌 · Memory Wall
- 기출: 128회 1교시 11번 `메모리 인터리빙(Memory Interleaving)` 단답형 출제

## 한 줄 본질
- CPU는 기가헤르츠로 달리는데 DRAM은 수십 나노초 대기 상태에 갇힘 → 피라미드형 메모리 계층으로 접근 빈도를 완충하고, DRAM을 여러 독립 뱅크로 쪼개어 연속 주소를 번갈아 읽는 인터리빙을 적용 → 메모리 실효 대역폭 N배 확장 / 동일 뱅크에 접근이 겹치는 뱅크 충돌 시 대기 지연 발생

## 핵심 용어
- 메모리 벽(Memory Wall): 프로세서의 연산 속도 발전 추세에 비해 메모리 버스 대역폭 및 레이턴시 개선 속도가 현저히 느려 시스템 전체 성능이 메모리에서 병목되는 현상
- 하위 인터리빙(Low-Order Interleaving): 주소의 최하위 비트들을 이용해 뱅크를 선택함으로써, 연속된 메모리 주소가 서로 다른 뱅크에 할당되어 순차 읽기 시 N개 뱅크를 동시 병렬 가동하는 방식
- 뱅크 충돌(Bank Conflict): 이미 활성화되어 프리차지(Precharge) 사이클을 거치는 특정 뱅크에 다른 요청이 연속 접근하여 대기 지연이 발생하는 현상

## 핵심 통찰
- 하위 인터리빙은 '프로그램의 공간 지역성'을 극대화함 → 명령어 파이프라인이나 배열 순회는 연속된 메모리 번지를 차례로 읽으므로, 하위 인터리빙을 적용하면 뱅크 0, 1, 2, 3을 사이클마다 순차 트리거하여 메모리 접근 지연을 파이프라이닝으로 완전히 은닉함
- 상위 인터리빙은 '독립 시스템 분할'에 쓰임 → 상위 비트로 모듈을 가르면 주소 블록별로 뱅크가 고정되므로 한 모듈에 고장이 나도 다른 모듈이 살아남는 결함 감내(Fault Tolerance) 시스템에 적합함
- 다중 채널(Multi-Channel)과 인터리빙의 융합 → 메인보드에 램을 2개, 4개 짝수로 꽂아야 하는 물리적 이유가 바로 메모리 컨트롤러의 채널 및 랭크(Rank) 인터리빙을 활성화하여 128비트, 256비트 전송 버스를 구축하기 위함임

## 이웃 토픽과 구분
- 하위 인터리빙 vs 상위 인터리빙: 하위 인터리빙 = 주소 하위 비트로 뱅크 분할, 연속 데이터 병렬 접근, 고속화 목적 / 상위 인터리빙 = 주소 상위 비트로 모듈 분할, 모듈 단위 결함 격리 및 다중 처리기 확장 목적

## 문제·원인·대책
- 사례: 128회 기출 및 과학 계산 시뮬레이션에서 2의 제곱수 보폭(Stride) 배열 접근 시 성능 급락 현상
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 특정 크기 행렬의 열(Column) 방향 순회 시 처리 속도가 80% 저하 | 순회 간격이 뱅크 수의 배수와 일치하여 특정 뱅크에만 접근 집중(뱅크 충돌) | 소수(Prime Number) 뱅크 구성 또는 캐시 블로킹(Tiling) 알고리즘 적용 | 뱅크 간 접근 부하 균등 분산으로 메모리 버스 대역폭 100% 회복 |
| 서버 메모리 증설 후 메모리 실효 대역폭이 기존보다 감소 | 서로 다른 용량·속도의 메모리를 장착하여 단일 채널 모드로 강등 | 동일 규격(용량/클럭/타이밍) 모듈을 짝수 슬롯에 대칭 장착(Dual-Channel) | 메모리 인터리빙 및 128비트 대역폭 정상 활성화 |

## 이렇게 출제된다
- 제128회 1교시 11번: "메모리 인터리빙(Memory Interleaving)" → 요구 포인트: Ⅰ 메모리 인터리빙의 개념 및 목적 + Ⅲ 상위/하위 인터리빙 주소 매핑 메커니즘 + Ⅴ 유형별 장단점 비교표
