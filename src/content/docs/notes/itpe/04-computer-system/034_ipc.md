## 연관 키워드

- 프로세스 간 통신(IPC, Inter-Process Communication), 공유 메모리(Shared Memory), 메시지 전달(Message Passing)
- 파이프(Pipe), 명명 파이프(Named Pipe), 메시지 큐(Message Queue), 유닉스 도메인 소켓(UDS, Unix Domain Socket)
- 세마포어(Semaphore), 뮤텍스(Mutex), 시그널(Signal), 경쟁 상태(Race Condition)
- 제로 카피(Zero-Copy), 데이터 무결성, 커널 버퍼

## Ⅰ. 프로세스 간 통신의 개요

- 핵심 요약 : **프로세스 간 통신** (IPC, Inter-Process Communication)은 주소 공간이 분리된 프로세스들이 커널이 제공하는 채널로 데이터를 교환하고 동작을 맞추는 메커니즘.
- 개념 : 각자 독립된 가상 주소 공간에서 실행되는 프로세스 사이의 데이터 전달과 실행 순서 조율을 커널이 지원하는 통신 수단의 총칭.
- 배경 및 필요성 : 운영체제가 한 프로세스의 메모리를 다른 프로세스가 직접 참조하지 못하도록 격리하는 만큼, 안전한 협업을 위한 공식 채널의 확보 필요.
- 주요 목적 : 데이터 공유, 실행 흐름의 동기화, 메모리 격리 원칙의 유지라는 세 목표의 동시 충족.

## Ⅱ. 프로세스 간 통신의 특징 및 장점

- 핵심 요약 : 커널 개입 여부를 기준으로 공유 메모리 방식과 메시지 전달 방식이 나뉘며, 속도와 안전성의 교환 관계로 장점이 형성됨.

1. **공유 메모리** (Shared Memory) 방식 : 두 프로세스가 같은 물리 메모리 영역을 자기 주소 공간에 매핑해 커널 개입 없이 직접 읽고 쓰는 방식 → 복사 비용 제거로 대용량 데이터 전달에 유리한 속도 확보.
2. **메시지 전달** (Message Passing) 방식 : send와 recv 시스템 콜로 커널 버퍼를 경유해 데이터를 주고받는 방식 → 커널의 중재로 안전성과 구현 단순성 확보.
3. **파이프** (Pipe) : 단방향 바이트 스트림 채널로, 부모·자식 프로세스용 익명 파이프와 무관한 프로세스 간 **명명 파이프** (Named Pipe)로 구분 → 명령 연결 같은 단순 흐름 구성에 적합.
4. **메시지 큐** (Message Queue) : 커널이 관리하는 큐에 메시지 단위를 적재해 비동기로 송수신하는 수단 → 송수신 시점 분리로 결합도 감소 효과.
5. **유닉스 도메인 소켓** (UDS, Unix Domain Socket) : 소켓 인터페이스를 유지하되 같은 호스트 안에서만 동작하는 채널 → 네트워크 스택 우회로 로컬 통신 속도 향상.
6. **시그널** (Signal) : 이벤트 발생을 프로세스에 통지하는 비동기 알림 수단 → 별도 데이터 채널 없이 제어 메시지 전달 가능.
7. 동기화 수단 : **세마포어** (Semaphore)와 **뮤텍스** (Mutex)로 공유 자원 접근을 제어 → **경쟁 상태** (Race Condition) 차단과 데이터 무결성 확보.

## Ⅲ. 프로세스 간 통신의 구조 (흐름)

- 핵심 요약 : 공유 메모리 모델은 커널을 우회하는 직접 참조 구조, 메시지 전달 모델은 커널 버퍼를 경유하는 이중 복사 구조.

```text
[ 공유 메모리 모델의 구조 ]

프로세스 A (영역 매핑)
   ↓ 직접 접근
공유 물리 메모리 영역
   ↓ 직접 접근
프로세스 B (영역 매핑)
   ↓
세마포어·뮤텍스로 순서 제어
```

```text
[ 메시지 전달 모델의 구조 ]

프로세스 A : send 시스템 콜
   ↓ 1차 복사
커널 버퍼 (파이프·큐·소켓)
   ↓ 2차 복사
프로세스 B : recv 시스템 콜
```

- 구성요소 : 통신 채널(파이프·큐·소켓·공유 영역), 접근 동기화 수단(세마포어·뮤텍스), 커널 개입 계층(시스템 콜·버퍼 관리)으로 구성.
- 공유 메모리 모델은 복사 없는 **제로 카피** (Zero-Copy)에 가까운 전송이 가능하나 동기화 책임이 사용자 코드에 있고, 메시지 전달 모델은 복사 비용 대신 커널 주도의 격리와 순서 관리 효과.

## Ⅳ. 프로세스 간 통신 수단의 비교

- 핵심 요약 : 데이터 단위, 방향성, 동기화 부담, 통신 범위에 따라 수단별 적용 영역이 구분됨.

| 비교 항목 | 파이프 | 메시지 큐 | 공유 메모리 | UDS | 시그널 |
| --- | --- | --- | --- | --- | --- |
| 데이터 단위 | 바이트 스트림 | 메시지 단위 | 메모리 직접 참조 | 바이트 스트림 | 신호 번호 |
| 방향성 | 단방향 | 양방향 | 양방향 | 양방향 | 단방향 통지 |
| 동기화 부담 | 커널의 블로킹 | 큐 연산 단위 | 사용자가 직접 구현 | 커널 내부 처리 | 핸들러 등록 |
| 전송 성능 | 커널 복사 1회 | 커널 복사 1회 | 복사 없음 | 네트워크 스택 생략 | 데이터 전달 불가 |
| 적합 용도 | 명령 연결 | 제어 메시지 교환 | 대용량 데이터 | 로컬 클라이언트·서버 | 이벤트 통지 |

- 선택 기준 : 대용량 전송과 지연 최소화가 우선이면 공유 메모리, 구현 단순성과 안전성이 우선이면 메시지 큐나 UDS, 제어 통지는 시그널로 구분해 선택.

## Ⅴ. 프로세스 간 통신의 한계와 방안

- 핵심 요약 : 동기화 실패, 복사 부담, 채널 용량 한계를 락 설계, 전송 방식 전환, 비동기 처리로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 공유 자원의 경쟁 상태 | 접근 순서 제어 실패 → 데이터 훼손과 재현 어려운 장애 | 세마포어·뮤텍스로 임계 구역 보호, 락 획득 순서 표준화 | 락 대기 시간, 무결성 위반 건수 |
| 복사에 따른 성능 부담 | 커널 버퍼 경유의 2회 복사 → 대용량 전송 시 지연 증가 | 대용량 데이터의 공유 메모리 전환, 매핑 기반 전송 적용 | 전송 지연 시간, 복사 발생량 |
| 채널 용량과 블로킹 | 수신 지연 시 큐 포화로 송신자 대기 → 처리 흐름 정체 | 비동기 송수신과 백프레셔 정책 설계, 큐 크기 상한 관리 | 큐 점유율, 송신 대기 시간 |

## Ⅵ. 프로세스 간 통신에 대한 기술사적 제언

- 핵심 요약 : 통신 수단의 선택 기준, 공유 메모리 동기화 규칙, 로컬 채널 표준을 조직 차원에서 정착하는 방향.

1. 플랫폼 개발 조직이 데이터 크기와 지연 요구에 따른 IPC 수단 선택 기준을 아키텍처 가이드로 정해 모듈 간 인터페이스 설계의 일관성 확보.
2. 시스템 개발 조직이 공유 메모리 사용 모듈에 락 획득 순서와 정리 절차를 설계 문서로 요구하고, 코드 검토 항목에 반영해 동기화 결함 예방.
3. 인프라 운영 조직이 같은 호스트의 프로세스·컨테이너 간 통신에 UDS 채널을 표준으로 배포해 네트워크 경유 부담의 제거.

## Ⅶ. 결론

- 핵심 요약 : IPC는 메모리 격리 원칙을 유지하면서 프로세스 협업을 가능하게 하는 커널 수준 통신 체계.
- 시사점 : 속도와 안전성의 교환 관계를 데이터 특성에 맞게 설계할 때 격리와 효율이 동시에 확보되는 구조.
