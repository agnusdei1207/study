- 통찰: 한계: 가속기 처리량이 높아도 이동·동기화 비용이 이득을 지울 수 있음 → 방안: 전체 작업 시간으로 오프로드 경계를 결정한다.

<details>
<summary>핵심 용어</summary>

- **하이브리드 컴퓨팅(Hybrid Computing)** : 서로 다른 연산 구조를 연계해 한 작업을 처리하는 컴퓨팅 방식
- **CPU (Central Processing Unit)** : 범용 명령 실행·제어에 쓰이는 프로세서
- **GPU (Graphics Processing Unit)** : 대량 병렬 계산을 지원하는 프로세서
- **QPU (Quantum Processing Unit)** : 큐비트 연산을 수행하는 양자 처리 장치
- **오프로드(Offload)** : 특정 계산을 호스트에서 가속기로 전달해 수행하는 과정

</details>

## 2~4교시 25점 답안

### Ⅰ. 하이브리드 컴퓨팅의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **하이브리드 컴퓨팅은** 서로 다른 연산기를 하나의 작업 흐름에서 결합하는 방식 |
| 목적 | 작업 특성에 맞는 연산 자원을 활용하고 연산 결과를 통합 |

### Ⅱ. 하이브리드 컴퓨팅의 특징

| 특징 | 의미 |
|---|---|
| 이종 연산 | CPU 제어와 GPU·NPU·QPU 등 특화 연산을 결합 |
| 작업 분할 | 모든 단계를 같은 장치에서 실행하지 않음 |
| 데이터 의존 | 전송·동기화·정확도 관리가 실제 성능을 좌우 |

### Ⅲ. 실행 체계·프로세스

**핵심 연산 체계**

```text
응용 작업 → 호스트 CPU(분할·제어·전처리)
              ├─ 범용·순차 작업 → CPU 실행
              └─ 병렬·특화 작업 → 런타임/연결 → GPU·NPU·QPU
                                         ↓ 결과·상태 회수
                          호스트 동기화·검증·결과 통합
```

**하위 메커니즘: 오프로드 경계 선택**

```text
후보 커널 식별 → 전송·실행·동기화 시간 예측
             → 작은 작업은 CPU 유지 / 큰 작업은 가속기로 전달
             → 결과 정확도 확인 → 종단 간 시간 재측정·경계 조정
```

### Ⅳ. 연산기별 역할 비교

| 연산기 | 주로 맡는 작업 | 경계 조건 |
|---|---|---|
| CPU | 제어 흐름·작은 순차 작업 | 범용성 높으나 대량 병렬 계산에 제약 |
| GPU·NPU | 병렬 수치·AI 연산 | 데이터 전송과 모델·커널 호환성 |
| QPU | 지원되는 양자 회로 실행 | 측정·반복 실행과 고전 연계 비용 |

### Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 데이터 이동·동기화 비용이 계산 이득을 상쇄 | 종단 간 성능 측정으로 작업 크기·분할 경계 조정 |
| 수치 정밀도나 확률적 결과가 장치별로 다름 | 기준 구현과 정확도·분산 비교 |
| 런타임·장치별 API에 종속 | 추상화 인터페이스와 CPU 대체 경로 시험 |

### Ⅵ. 제언

가속기 단독 처리량은 전체 업무 속도를 설명하지 못한다. **대표 작업의 전처리·전송·실행·통합 시간을 먼저 분해해 측정**하고 오프로드 구간을 정한 뒤 정확도와 대체 실행 경로까지 검증해야 한다.
