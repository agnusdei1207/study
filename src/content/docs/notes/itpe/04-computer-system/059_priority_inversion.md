## 연관 키워드

- 우선순위 역전(Priority Inversion), 블로킹(Blocking), 선점(Preemption), 실시간 운영체제(RTOS)
- 우선순위 상속 프로토콜(PIP), 우선순위 올림 프로토콜(PCP), 뮤텍스(Mutex), 세마포어(Semaphore)
- 교착상태(Deadlock), 락 프리(Lock-Free), RCU(Read-Copy-Update), RMA(Rate Monotonic Analysis)

## Ⅰ. 우선순위 역전의 개요

- 핵심 요약 : 저순위 태스크가 보유한 자원을 고순위 태스크가 대기하는 동안 무관한 중순위 태스크의 선점으로 고순위 실행이 지연되는 **우선순위 역전** (Priority Inversion) 현상.
- 개념 : 선점형 우선순위 스케줄링에서 고순위 태스크가 저순위 태스크의 공유 자원 락을 기다리는 **블로킹** (Blocking) 상태에 머무는 사이, 자원과 무관한 중순위 태스크가 저순위 태스크를 선점하여 결과적으로 고순위 태스크의 실행이 뒤로 밀리는 스케줄링 현상.
- 배경 및 필요성 : 고순위 태스크의 대기 시간이 중순위 태스크의 실행 길이에 따라 상한 없이 늘어나는 비용이 발생. 마감시간 준수가 필수인 실시간 운영체제(RTOS, Real-Time Operating System) 기반 제어 시스템에서 이 지연은 곧 시스템 장애로 이어지며, 1997년 화성 패스파인더(Mars Pathfinder) 탐사선의 반복 재부팅 사례가 이 현상을 널리 알린 계기.
- 주요 목적 : 실시간 태스크의 마감시간 준수 보장, 우선순위 상속과 우선순위 올림 프로토콜을 통한 블로킹 지연 상한의 통제.

## Ⅱ. 우선순위 역전의 특징 및 장점

- 핵심 요약 : 발생 조건의 명확한 정의와 PIP·PCP 기반의 블로킹 상한 통제가 실시간 설계의 예측 가능성을 만드는 구조.

1. 발생 시나리오의 3개 태스크 구조 : 저순위의 락 획득, 고순위의 락 대기, 무관한 중순위의 선점이라는 조건의 조합 → 역전은 락 설계와 스케줄링의 결합부에서 생기는 구조적 현상.
2. 무한 블로킹 위험 : 중순위 태스크의 유입이 계속되면 고순위 태스크의 지연이 상한 없이 증가 → 최악 응답시간의 보장이 불가능한 상태.
3. **우선순위 상속 프로토콜** (PIP, Priority Inheritance Protocol) : 락을 보유한 저순위 태스크에 대기 중인 최고 순위를 일시 상속 → 중순위 선점 차단으로 저순위 태스크의 조기 락 해제, 고순위 블로킹 단축.
4. **우선순위 올림 프로토콜** (PCP, Priority Ceiling Protocol) : 자원마다 접근 가능한 최고 순위(Ceiling)를 사전 정의하고 락 획득 즉시 해당 순위로 승격 → 블로킹이 임계 구역 한 번 분량으로 제한되고 **교착상태** (Deadlock)까지 예방.

## Ⅲ. 우선순위 역전의 구조 (흐름)

- 핵심 요약 : 고·중·저 3개 태스크의 락 경합에서 역전이 시작되고, PIP는 순위의 동적 상속으로, PCP는 사전 상한 부여로 해소하는 흐름.

```text
[ 우선순위 역전 발생 순서 ]

1. 저순위 L이 공유 자원 락 획득
      ↓
2. 고순위 H가 같은 락 요청 후 대기
      ↓
3. 무관한 중순위 M이 L을 선점
      ↓
4. 락 해제 불가로 H 무기한 대기
```

```text
[ PIP 적용 후의 실행 흐름 ]

1. L이 대기 중인 H의 순위 상속
      ↓
2. M이 승격된 L을 선점 불가
      ↓
3. L이 임계 구역 실행 후 락 해제
      ↓
4. H가 락 획득 후 실행 재개
```

- 구성요소 : 상호 배제 락으로 보호되는 공유 자원, 우선순위가 서로 다른 세 태스크, 선점형 스케줄러로 구성되며 역전은 세 요소의 상호작용 결과.
- PCP의 차이 : PIP가 대기 발생 후 순위를 상속하는 사후 대응인 반면, PCP는 락 획득 시점에 자원의 Ceiling 순위로 미리 승격하는 사전 예방 방식.

## Ⅳ. 기본 스케줄링과 PIP·PCP의 비교

- 핵심 요약 : 기본 우선순위 스케줄링은 역전에 무방비이고, PIP는 동적 상속으로, PCP는 사전 승격으로 역전과 교착상태까지 통제.

| 비교 항목 | 기본 우선순위 스케줄링 | PIP | PCP |
| --- | --- | --- | --- |
| 역전 방지 | 발생 (무방비) | 방지 (동적 상속) | 방지 (사전 승격) |
| 승격 시점 | 없음 | 고순위 태스크의 락 대기 발생 시 | 자원 락 획득 즉시 |
| 승격 기준 값 | 없음 | 대기 중 최고 순위 태스크의 값 | 자원에 사전 정의된 Ceiling 값 |
| 교착상태 | 발생 가능 | 연쇄 상속 시 발생 가능 | 원천 예방 |
| 블로킹 상한 | 무제한 (비결정적) | 다중 자원 대기 시 누적 | 임계 구역 한 번 분량 |

- 선택 기준 : 구현 단순성이 우선이면 PIP를, 교착상태 예방과 블로킹 상한 보장이 우선이면 PCP를 택하는 판단 기준.

## Ⅴ. 우선순위 역전의 한계와 방안

- 핵심 요약 : 상속 체인의 교착, 신호용 동기화 도구의 소유자 불명확성, 임계 구역 장기 점유를 상한 프로토콜·뮤텍스·비차단 자료구조로 대응하는 원칙.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| PIP의 연쇄 블로킹 | 여러 자원의 교차 점유로 상속 체인이 얽혀 환형 대기·교착상태 발생 | PCP 또는 즉시 우선순위 올림(Immediate Priority Ceiling) 적용 | 교착 감지 건수, 최대 블로킹 시간 |
| 소유자 불명확 동기화 | **세마포어** (Semaphore)는 신호 전달용이라 락 소유 태스크를 특정할 수 없어 상속 불가 | 상호 배제에는 소유자가 명확한 **뮤텍스** (Mutex) 사용, 우선순위 상속 옵션 활성화 | 상속 옵션 적용률 |
| 임계 구역 장기 점유 | 락 보유 중 블로킹 시스템 콜·긴 연산 수행으로 상속으로도 고순위 지연 | 임계 구역 내 블로킹 호출 금지, **락 프리** (Lock-Free) 큐와 **RCU** (Read-Copy-Update) 검토 | 임계 구역 최대 점유 시간 |

## Ⅵ. 우선순위 역전에 대한 기술사적 제언

- 핵심 요약 : 플랫폼 선정 기준, 설계 단계 분석, 운영 중 감지의 3단계 체계로 역전 관리를 일회성 버그 수정이 아닌 상시 역량으로 내재화하는 방향.

1. 임베디드 플랫폼 조직은 RTOS 도입 검토 때 동기화 프리미티브의 우선순위 프로토콜 지원 여부를 선정 기준으로 문서화하고, 커널 설정을 코드형 구성으로 표준화한다.
2. 실시간 설계 조직은 **RMA** (Rate Monotonic Analysis)의 응답시간 산식에 블로킹 항을 상수로 반영하여, 설계 단계에서 마감시간 준수 여부를 수학적으로 검증하는 절차를 운영한다.
3. 품질·검증 조직은 태스크별 응답시간 트레이싱을 상시 계측 체계로 구축하여, 고순위 태스크의 비정상 대기라는 역전 징후를 운영 환경에서 조기 탐지한다.

## Ⅶ. 결론

- 핵심 요약 : 우선순위 역전은 저순위 자원 점유와 중순위 선점의 결합으로 고순위 태스크가 지연되는 현상이며, 블로킹 상한의 통제가 실시간 설계의 기본 요건.
- 역전의 근원은 스케줄러가 아닌 공유 자원 설계에 있으므로, 락 설계와 응답시간 분석을 한 흐름으로 묶는 접근이 요구되는 분야.
