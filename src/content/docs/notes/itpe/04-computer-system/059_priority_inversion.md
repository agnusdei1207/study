## 연관 키워드

- 우선순위 역전(Priority Inversion), 블로킹(Blocking), 선점(Preemption), 실시간 운영체제(RTOS)
- 우선순위 상속 프로토콜(PIP), 우선순위 올림 프로토콜(PCP), 즉시 우선순위 올림(Immediate Priority Ceiling)
- 뮤텍스(Mutex), 세마포어(Semaphore), 교착상태(Deadlock), RCU(Read-Copy-Update)
- 화성 패스파인더(Mars Pathfinder), RMA(Rate Monotonic Analysis)

## Ⅰ. 우선순위 역전(Priority Inversion)의 개요

- 핵심 요약 : **우선순위 역전**은 저순위 태스크가 쥔 자원을 고순위 태스크가 기다리는 동안 중순위 태스크가 끼어들어 고순위 실행이 지연되는 현상.
- 개념 : 선점형 우선순위 스케줄링 환경에서 고순위 태스크가 저순위 태스크의 공유 자원 락을 기다리며 **블로킹**(Blocking) 상태에 머무는 동안, 자원과 무관한 중순위 태스크가 저순위 태스크를 선점해 실행되어 결과적으로 고순위 태스크가 역으로 밀리는 스케줄링 현상.
- 배경 및 필요성 : 고순위 태스크의 대기 시간이 중순위 태스크의 실행 길이에 따라 상한 없이 늘어나는 비용이 생기고, 엄격한 마감시간을 지켜야 하는 실시간 운영체제(RTOS, Real-Time Operating System) 기반 제어 시스템에서는 이 지연이 곧 시스템 장애가 됨. 1997년 **화성 패스파인더**(Mars Pathfinder) 탐사선이 잦은 시스템 리셋을 겪은 사례가 이 현상을 널리 알린 계기가 되었고, 이후 블로킹 시간의 상한을 프로토콜로 묶는 연구가 이어짐.
- 주요 목적 : 실시간 태스크의 마감시간 준수 보장, **우선순위 상속**(PIP, Priority Inheritance Protocol)과 **우선순위 올림**(PCP, Priority Ceiling Protocol)으로 블로킹 지연의 상한 통제.

## Ⅱ. 우선순위 역전(Priority Inversion)의 특징 및 장점

- 핵심 요약 : 역전이 발생하는 조건을 명확히 하고, PIP와 PCP로 블로킹 지연의 상한을 묶는 것이 핵심 특성.

1. 발생 시나리오 : 저순위 L이 락을 획득 → 고순위 H가 같은 락을 요청하고 블로킹 → 무관한 중순위 M이 L을 선점 → L이 락을 풀지 못해 H가 무기한 대기.
2. 무한 블로킹 위험 : M과 같은 중간 순위의 태스크가 계속 유입되면 H의 지연이 상한 없이 늘어남 → 최악 응답시간을 보장할 수 없음.
3. 우선순위 상속 (PIP) : 락을 보유한 저순위 태스크에 그 락을 기다리는 최고 순위를 일시적으로 물려줌 → 중순위 태스크의 선점이 차단되어 L이 빨리 락을 풀고 H의 블로킹이 짧아짐.
4. 우선순위 올림 (PCP) : 각 자원에 접근하는 태스크 중 최고 순위(Ceiling)를 미리 정해 두고 락 획득 즉시 그 순위로 올림 → 블로킹이 임계 구역 한 번 분량으로 제한되고 **교착상태**(Deadlock)도 예방.

## Ⅲ. 우선순위 역전(Priority Inversion)의 구조 및 동작 메커니즘

- 핵심 요약 : 고·중·저 3개 태스크의 락 경합에서 역전이 시작되고, PIP는 순위를 동적으로 상속시키며 PCP는 자원에 상한 순위를 미리 부여하여 해결.

```text
[ 우선순위 역전 발생 순서 ]

1. Task L이 공유 자원의 락 획득
      ↓
2. Task H가 같은 락을 요청하고 대기
      ↓
3. Task M이 L을 선점하여 실행 점유
      ↓
4. L이 락을 풀지 못해 H는 무기한 대기
```

```text
[ 우선순위 상속(PIP) 적용 후 ]

1. L이 대기 중인 H의 순위를 상속
      ↓
2. M은 승격된 L을 선점하지 못함
      ↓
3. L이 임계 구역 실행 후 락 해제
      ↓
4. H가 락을 얻어 정상 실행
```

- PCP는 락을 잡는 즉시 L을 자원의 Ceiling 순위로 올리므로 같은 효과를 대기 상황이 생기기 전에 보장함.

## Ⅳ. 우선순위 역전(Priority Inversion)의 비교

- 핵심 요약 : 기본 스케줄링은 역전에 무방비이고, PIP는 동적 승격으로, PCP는 사전 상한으로 역전과 블로킹을 통제.

| 비교 항목 | 기본 우선순위 스케줄링 | 우선순위 상속 프로토콜 (PIP) | 우선순위 올림 프로토콜 (PCP) |
| --- | --- | --- | --- |
| 역전 방지 여부 | 발생 (무방비) | 방지 (동적 승격) | 방지 (사전 상한) |
| 승격 시점 | 없음 | 고순위 태스크가 락을 기다릴 때 | 자원 락 획득 즉시 |
| 승격 순위 값 | 없음 | 대기 중인 최고 순위 태스크의 값 | 자원에 사전 정의된 Ceiling 값 |
| 교착상태 | 발생 가능 | 연쇄 상속 시 발생 가능 | 원천 예방 |
| 블로킹 상한 | 무제한 (비결정적) | 다중 락 대기 시 블로킹 누적 | 임계 구역 한 번 분량 |

- 선택 기준 : PIP는 구현이 단순하지만 연쇄 블로킹 위험이 있고, PCP는 교착상태까지 막지만 자원별 최고 순위를 사전에 분석해야 함.

## Ⅴ. 우선순위 역전(Priority Inversion)의 한계와 방안

- 핵심 요약 : PIP의 연쇄 교착, 세마포어의 소유자 추적 불가, 임계 구역 장기 점유를 PCP, 뮤텍스, 비차단 자료구조로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| PIP 환경의 연쇄 블로킹과 교착상태 | 여러 자원을 교차 점유하면 상속 체인이 얽혀 환형 대기 발생 | PCP 또는 **즉시 우선순위 올림**(Immediate Priority Ceiling) 적용 | 교착 감지 건수, 최대 블로킹 시간 |
| **세마포어**(Semaphore)의 소유자 추적 불가 | 카운팅 세마포어는 신호 전달용이라 락을 소유한 태스크를 특정하지 못해 상속 불가 | 상호 배제에는 소유자가 명확한 **뮤텍스**(Mutex)를 사용하고 우선순위 상속 옵션 활성화 | 뮤텍스 적용률 |
| 임계 구역 장기 점유 | 락을 쥔 채 I/O나 긴 연산을 수행하여 상속을 적용해도 고순위 태스크 지연 | 임계 구역 내 블로킹 시스템 콜 금지, 락 프리(Lock-Free) 큐와 **RCU**(Read-Copy-Update) 검토 | 임계 구역 최대 점유 시간 |

## Ⅵ. 우선순위 역전(Priority Inversion)의 적용 제언

- 핵심 요약 : 안전 필수 차량 소프트웨어는 PCP를, 범용 POSIX 환경은 PIP 옵션을, 주기 태스크는 응답시간 분석으로 블로킹 항을 증명하는 방향.

1. 차량 전장 소프트웨어 개발 조직은 **AUTOSAR**(Automotive Open System Architecture) 기반 운영체제(OS, Operating System)의 자원 락에 우선순위 올림 프로토콜을 적용하고, 기능안전 요구사항인 ISO 26262 검토 때 블로킹 상한을 근거로 제시한다.
2. POSIX(Portable Operating System Interface) 멀티스레드 시스템 개발팀은 뮤텍스 생성 시 `pthread_mutexattr_setprotocol`로 `PTHREAD_PRIO_INHERIT`을 지정했는지 코드 리뷰 항목으로 점검한다.
3. 주기 태스크를 운용하는 임베디드 조직은 **RMA**(Rate Monotonic Analysis)에 블로킹 항을 포함하여 최악 응답시간을 설계 단계에서 검증한다.

## Ⅶ. 결론

- 핵심 요약 : 우선순위 역전은 저순위 자원 점유와 중순위 선점이 겹쳐 고순위 태스크를 지연시키는 현상이며, 블로킹 상한의 통제가 실시간 설계의 기본 요건.
- 역전은 공유 자원 설계에서 비롯되므로, 락 설계와 임계 구역 관리를 스케줄링 설계와 함께 다루어야 한다.
