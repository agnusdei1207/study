## 연관 키워드

- IPC, Inter-Process Communication, 파이프, 메시지큐, 공유메모리, 소켓, 세마포어

## Ⅰ. 프로세스 간 통신의 개요

- 핵심 요약 : IPC는 독립 프로세스 간 데이터 교환과 동기화를 제공하는 운영체제 통신 메커니즘.
- 개념 : IPC는 독립 프로세스 간 데이터 교환과 동기화를 제공하는 운영체제 통신 메커니즘.
- 배경 및 필요성 : 프로세스는 주소공간을 분리해 직접 메모리를 공유할 수 없으므로 협력·명령·데이터 전달 경로 필요.
- 주요 목적 : 프로세스 간 안전한 메시지 전달과 자원 동기화.

## Ⅱ. 프로세스 간 통신의 특징 및 장점

- 핵심 요약 : 파이프·FIFO: 바이트 스트림 전달 → 로컬 단방향·양방향 연결; 메시지큐·소켓: 메시지 경계·네트워크 통신 → 비동기·분산 통신; 공유메모리+세마포어: 복사비용 감소 → 동기화·경쟁조건 관리 필수.

1. 파이프·FIFO: 바이트 스트림 전달 → 로컬 단방향·양방향 연결
2. 메시지큐·소켓: 메시지 경계·네트워크 통신 → 비동기·분산 통신
3. 공유메모리+세마포어: 복사비용 감소 → 동기화·경쟁조건 관리 필수

## Ⅲ. 프로세스 간 통신의 구조 (흐름)

- 핵심 요약 : 통신범위·데이터량 정의 → IPC 방식·프로토콜 선택 → 권한·버퍼·동기화 구현 → 오류·재연결·종료 처리 → 경합·지연 부하시험.

```text
통신범위·데이터량 정의
  ↓
IPC 방식·프로토콜 선택
  ↓
권한·버퍼·동기화 구현
  ↓
오류·재연결·종료 처리
  ↓
경합·지연 부하시험
```

- 핵심 구성 : 프로세스 A → IPC 채널(파이프/큐/소켓) → 프로세스 B

```text
프로세스 A → IPC 채널(파이프/큐/소켓) → 프로세스 B
공유메모리 방식: A·B → 공유영역 + 세마포어
```

## Ⅳ. 비교: 공유메모리 / 메시지 전달 IPC

- 핵심 요약 : 데이터 이동 기준 — 공유메모리: 공유영역 접근으로 복사 적음; 메시지 전달 IPC: 커널·네트워크를 통해 메시지 복사.

| 비교 기준 | 공유메모리 | 메시지 전달 IPC |
| --- | --- | --- |
| 데이터 이동 | 공유영역 접근으로 복사 적음 | 커널·네트워크를 통해 메시지 복사 |
| 동기화 | 락·세마포어를 직접 설계 | 큐·소켓의 전달경계가 일부 동기화 제공 |
| 적합성 | 대용량 로컬 데이터·낮은 지연 | 격리·프로토콜 명확성·원격 통신 |

## Ⅴ. 프로세스 간 통신의 한계와 방안

- 핵심 요약 : 경쟁조건·교착·정지 등의 위험을 원인에 맞게 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 경쟁조건 | 공유데이터 동시 수정으로 손상 | 뮤텍스·세마포어·원자연산·불변식 적용 | 경쟁조건 오류 |
| 교착·정지 | 락 순서·프로세스 비정상 종료 | 락 순서 규칙·타임아웃·소유자복구 설계 | 대기시간 |
| 버퍼 고갈·역압 | 생산자가 소비자보다 빨라 큐 증가 | bounded queue·drop/block 정책·역압 적용 | 큐 깊이·drop율 |

## Ⅵ. 프로세스 간 통신의 제언

- 핵심 요약 : 시스템 설계자는 로컬/원격 범위·메시지 크기·지연·고장 격리 요구에 맞춰 IPC를 선택하고 프로토콜 버전·권한·역압·종료규칙을 명시.
- 실행 제안 : 개발팀은 IPC 계약에 메시지 크기·순서·타임아웃·재시도·종료 신호를 정의하고 버전 호환시험을 자동화.

## Ⅶ. 프로세스 간 통신의 결론

- 핵심 요약 : IPC 방식은 데이터 복사·동기화·결합도·통신범위에서 서로 다른 절충을 제공.
- 시사점 : 공유메모리는 빠르지만 동기화 책임이 응용에 집중되므로 단순성·격리성이 중요한 경우 메시지 전달이 유리할 수 있음.
