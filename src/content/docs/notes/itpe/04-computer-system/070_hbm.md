## 연관 키워드

- HBM, High Bandwidth Memory, TSV, 실리콘 인터포저, 베이스 다이, 2.5D 패키징
- 마이크로 범프, 채널 분할, 메모리 벽, KGD, 하이브리드 본딩, GDDR

## Ⅰ. HBM의 개요

- 핵심 요약 : D램 다이를 수직으로 쌓아 연산 칩 곁에 붙여 넓은 버스로 초고대역폭을 내는 적층형 메모리.
- 개념 : 여러 장의 **D램** (DRAM, Dynamic Random-Access Memory) 다이를 **실리콘 관통 전극** (TSV, Through-Silicon Via)으로 수직 연결해 적층하고, **실리콘 인터포저** (Silicon Interposer) 위에서 그래픽 처리 장치(GPU, Graphics Processing Unit)나 신경망 처리 장치(NPU, Neural Processing Unit)와 같은 패키지 안에 근접 배치하는 **고대역폭 메모리** (HBM, High Bandwidth Memory).
- 배경 및 필요성 : AI 가속기의 연산 성능이 메모리 공급 능력을 앞지르면서 **메모리 벽** (Memory Wall) 현상으로 연산 유닛이 데이터 대기에 묶임. 기존 평면형 그래픽 메모리의 좁은 버스로는 요구 대역폭을 맞추기 어려움.
- 주요 목적 : 버스 폭 확대와 신호 경로 최단화로 대역폭을 확보하면서 비트당 전송 에너지를 낮추는 것.

## Ⅱ. HBM의 특징 및 장점

- 핵심 요약 : TSV 적층, 인터포저 근접 배치, 채널 분할이 대역폭과 에너지 효율을 동시에 높이는 구조.

1. 수직 적층 연결 : 다이를 얇게 연마해 TSV로 수직 배선 구성 → 수천 개 신호선의 최단 경로로 전송 지연·에너지 감소.
2. 근접 배치 패키징 : 연산 칩과 HBM을 패키지 기판 위 **2.5D 패키징** (2.5D Packaging)으로 나란히 올림 → 긴 기판 배선 없이 초고속 신호 전달이 가능한 근접 통신 확보.
3. 채널 분할 구조 : 스택 내부를 독립 입출력 채널로 나눔 → 병렬 접근을 통한 유효 대역폭 확대.
4. 폭 우선 인터페이스 : 신호 속도를 완만히 유지하면서 버스 폭으로 대역폭 확보 → 고속 신호에 수반되는 전력·노이즈 부담 완화.

## Ⅲ. HBM의 구조 (흐름)

- 핵심 요약 : D램 다이 적층, 인터페이스를 담당하는 베이스 다이, 인터포저, 기판으로 이어지는 단면 구조.
- 구성 요소 : 상층 D램 다이, 인터페이스 로직을 맡는 **베이스 다이** (Base Die), 다이 간 연결의 **마이크로 범프** (Microbump), 인터포저, 패키지 기판.

```text
[ HBM 스택 단면 구조 ]

상단 D램 다이
        ↓ TSV 수직 배선
중간 D램 다이 (다수 적층)
        ↓ TSV
베이스 다이 (인터페이스 로직)
        ↓ 마이크로 범프
실리콘 인터포저 (미세 배선)
        ↓ 범프 접합
패키지 기판
```

```text
[ 연산 칩과의 데이터 경로 ]

GPU·NPU 코어 (연산 유닛)
        ↓ 인터포저 배선 (넓은 버스)
베이스 다이 입출력 인터페이스
        ↓ TSV
적층 D램 셀 어레이 (데이터 저장)
```

## Ⅳ. HBM과 GDDR의 비교

- 핵심 요약 : 버스 폭 중심의 적층 구조와 신호 속도 중심의 평면 구조가 대역폭·용량·전력에서 서로 다른 특성을 만드는 구조.
- 선택 기준 : 대역폭 요구량, 패키지 면적·열 예산, 보드 설계 자유도를 기준으로 메모리 방식을 고른다.

| 비교 항목 | HBM | **GDDR** (Graphics Double Data Rate) |
| :--- | :--- | :--- |
| 구조 | 다이 적층 + 인터포저 근접 배치 | 단일 다이 + 보드 직접 실장 |
| 버스 폭 | 스택당 1,024비트급의 넓은 버스 | 칩당 좁은 버스 (32비트) |
| 대역폭 확보 방식 | 버스 폭 확대 중심 | 핀 속도 상승 중심 |
| 신호 특성 | 완만한 핀 속도, 짧은 경로 | 높은 핀 속도, 긴 배선 |
| 전력 효율 | 비트당 전송 에너지 낮음 | 동일 대역폭 기준 상대적으로 높음 |
| 용량 확장 | 적층 단수와 스택 수로 확장 | 칩 수와 용량 밀도로 확장 |
| 주요 적용 | AI 가속기, HPC(High Performance Computing) | 그래픽 카드, 게임 콘솔 |

## Ⅴ. HBM의 한계와 방안

- 핵심 요약 : 적층 발열, 수율·비용 부담, 선진 패키징 공정 의존을 열 관리, 양품 다이 선별, 공정 다변화로 일대일 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| 적층 구조의 발열 | 적층 중앙·상부 다이의 열 배출 경로가 좁아 접합 온도 상승과 성능 제한 발생 | 열전도성 몰디드 언더필 적용, 구리 직접 접합의 **하이브리드 본딩** (Hybrid Bonding) 검토 | 접합 온도, 열 제한 발생 빈도 |
| 수율 저하와 높은 단가 | 적층 중 단일 다이 불량도 전체 스택 폐기로 이어짐 | 적층 전 **양품 다이** (KGD, Known Good Die) 전수 검사, 온다이 오류 정정 회로와 여분 전극 설계 | 적층 수율, 검사 통과율 |
| 선진 패키징 공정 의존 | 인터포저 기반 2.5D 공정이 소수 파운드리에 집중되어 공급 탄력성 제약 | 인터포저 분할 브리지 등의 대체 패키징 병행 검토, 공급처 다변화 계약 | 공급 계약 다변화율 |

## Ⅵ. HBM에 대한 기술사적 제언

- 핵심 요약 : 메모리·파운드리 공동 설계, 연산 근접 아키텍처 로드맵, 열·공급 리스크 관리를 AI 인프라 전략에 통합.

1. 공동 설계 협력 : 반도체 설계 조직은 메모리·파운드리 기업 협의체 참여를 통한 베이스 다이 인터페이스 표준 방향의 조기 반영.
2. 연산 근접 로드맵 : 시스템 아키텍트는 메모리 내 연산을 수행하는 **PIM** (Processing-In-Memory) 계열 기술을 로드맵에 두되 소프트웨어 인터페이스 표준화 여부를 도입 판단 기준으로 설정.
3. 열·공급 리스크 관리 : 데이터센터 운영 조직은 고적층 메모리 가속기의 열 설계 전력(TDP, Thermal Design Power)의 냉각 용량 계획 반영과 공급처 다변화 계약 병행.

## Ⅶ. 결론

- 핵심 요약 : HBM은 TSV 적층과 인터포저 근접 배치로 메모리 벽을 완화하는 AI 시대의 핵심 메모리.
- 발열·수율·공정 의존이라는 제약의 관리 수준이 대역폭 경쟁의 실질 성패를 결정.
