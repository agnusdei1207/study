## Ⅰ. 세그멘테이션(Segmentation)의 개요

- 개념 : 프로세스의 가상 주소 공간을 컴퓨터 하드웨어 관점의 균일한 고정 크기 블록으로 나누지 않고, 프로그래머 관점의 **논리적 의미 단위**인 세그먼트(Segment: 함수, 서브루틴, 배열, 스택, 심볼 테이블 등)에 따라 서로 다른 크기를 갖는 가변 블록 단위로 분할하여 관리하는 가상 메모리 기법.
- 배경 및 필요성 : 고정 분할 방식의 비효율성과 프로그램 모듈 간의 논리적 공유 및 보호(Protection)의 어려움을 해결하고, 함수 단위의 모듈화 프로그래밍 철학을 시스템 메모리 구조에 직접 반영하기 위해 제안됨.
- 핵심 목적 : 논리적 모듈 단위의 완벽한 메모리 **보호(Protection)** 및 **공유(Sharing)** 실현, 동적 자료구조 크기 변화에 대한 유연한 대응, 프로그래머 관점의 주소 공간 직관화.

## Ⅱ. 세그멘테이션(Segmentation)의 핵심 아키텍처 및 동작 메커니즘

세그멘테이션은 2차원 논리 주소 `<세그먼트 번호(s), 변위(d)>`를 세그먼트 테이블(기준점 Base, 한계값 Limit)을 통해 물리 주소로 변환하며, Limit 초과 시 **하드웨어 트랩** (Trap)을 발생시킴.

```text
[ 세그멘테이션 주소 변환 및 하드웨어 보호 메커니즘 ]

CPU 논리 주소: [ 세그먼트 번호 (s) | 변위 (Offset: d) ]
                     │                     │
                     ▼                     │
+------------------------------------+     │
| Segment Table (세그먼트 테이블)    |     │
| +-------+------------+-----------+ |     │
| | seg_id| Limit (길이)| Base (기준)| |     │
| +-------+------------+-----------+ |     │
| |   0   |   1000     |   2000    | |     │
| |   1   |    400     |   6000    | |     │  Limit 검사
| +-------+------------+-----------+ |     │
+------------------------------------+     │
      │              │                     │
      │              ▼                     │
      │        [ Limit (길이) ] <──────────┤ (d < Limit 검증)
      │                                    │
      │                           ┌────────┴────────┐
      │                           ▼ (d >= Limit)    ▼ (d < Limit: 정상)
      │                      [ Trap: 메모리 침범! ]  │
      ▼                     (Segmentation Fault)    │
+─────────────+                                     │
| Base (기준) | ────────────────── + ───────────────┘
+─────────────+                    │
                                   ▼ 물리 주소 계산: Base + d
+---------------------------------------------------------------+
| 물리 메모리 (DRAM: 실제 시작 주소 2000 + d 로 직접 접근)      |
+---------------------------------------------------------------+
```

- **2차원 논리 주소** : 사용자가 바라보는 주소는 세그먼트 이름/번호(`s`)와 세그먼트 시작점으로부터의 변위(`d`)로 구성.
- **세그먼트 테이블 (Segment Table)** : 각 세그먼트의 물리 메모리 시작 위치인 `Base`와 세그먼트의 최대 허용 길이인 `Limit` 정보를 보관.
- **하드웨어 보호 검증** : 변위 `d`가 해당 세그먼트의 길이 `Limit`를 초과하는지 하드웨어 MMU(Memory Management Unit)가 매 접근마다 비교하여, 초과 시 즉각 세그멘테이션 폴트(Trap) 발생.
- **권한 비트 기반 보호** : 세그먼트 테이블 엔트리마다 Read, Write, Execute 권한 비트를 두어 코드 세그먼트의 쓰기나 데이터 세그먼트의 실행을 원천 차단.

## Ⅲ. 세그멘테이션(Segmentation)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 페이징 (Paging) | 세그멘테이션 (Segmentation) | 페이징-세그멘테이션 결합 (Paged) |
|---|---|---|---|
| **분할 기준** | 물리적 고정 크기 (4KB, 2MB) | 논리적 가변 크기 (함수, 데이터 단위)| 논리적 세그먼트 내부를 페이지로 분할 |
| **프로그래머 인지**| 전혀 인지 못함 (OS(Operating System) 투명성) | 직접 인지 (2차원 주소 지정) | 논리 세그먼트 기반, 물리 페이징 |
| **단편화 문제** | 내부 단편화 발생 (외부 없음) | 외부 단편화 발생 (내부 없음) | 내부 단편화 미세 발생 (외부 해결) |
| **모듈 공유/보호** | 페이지 단위 매핑으로 부자연스러움| 세그먼트 단위로 완벽하고 직관적| 세그먼트 단위 보호 + 페이지 단위 할당 |
| **현대 구현** | x86-64 롱 모드의 지배적 표준 | 현대 64비트 아키텍처에서 쇠퇴 | 인텔 x86 보호 모드(과거 및 특수 OS) |

- 순수 세그멘테이션은 외부 단편화(자투리 메모리 낭비) 문제로 인해 현대 64비트 OS에서는 폐기되었으며, 세그먼트 보호 철학은 페이징의 PTE(Page Table Entry) 권한 비트로 흡수됨.

## Ⅳ. 세그멘테이션(Segmentation)의 주요 한계점 및 해결 방안

- 가변 크기 할당에 따른 심각한 **외부 단편화(External Fragmentation)** :
  - 한계점 : 서로 다른 크기의 세그먼트가 생성과 소멸을 반복하면서 메모리 사이에 수많은 작은 빈 공간이 생겨 대형 세그먼트 적재 불가.
  - 해결 방안 : 메모리 압축(Compaction) 수행 또는 세그먼트를 내부적으로 고정 크기 페이지로 쪼개는 페이지드 세그멘테이션(Paged Segmentation) 채택.
- 동적 **메모리 배치 탐색(First-fit, Best-fit)** 오버헤드 :
  - 한계점 : 새로운 세그먼트를 적재할 때마다 유휴 메모리 리스트를 순회 탐색해야 하므로 할당 지연 발생.
  - 해결 방안 : 버디 시스템(Buddy System) 도입 또는 현대 페이징 메모리 관리 체계로 완전 전환.
- **x86-64** 64비트 아키텍처에서의 하드웨어 세그멘테이션 미지원 :
  - 한계점 : 현대 x86-64 롱 모드(Long Mode)에서는 세그먼트 레지스터(CS, DS, ES, SS)의 Base/Limit 검사가 하드웨어적으로 비활성화됨(플랫 메모리 모델).
  - 해결 방안 : 페이지 테이블 엔트리(PTE)의 권한 비트(R/W, User/Supervisor, NX 비트)를 활용하여 논리적 격리 및 보안 대체.

## Ⅴ. 세그멘테이션(Segmentation) 적용 및 발전을 위한 기술사적 제언

- 모듈 단위 권한 분리 철학의 계승 : 세그멘테이션이 추구했던 '최소 권한의 원칙(PoLP, Principle of Least Privilege)'을 현대 소프트웨어 아키텍처의 마이크로서비스 및 컨테이너 격리 설계에 반영.
- W^X (Write XOR Execute) 보안 규칙 준수 : 메모리 세그먼트에 쓰기 권한과 실행 권한을 동시에 부여하지 않는 보안 원칙을 컴파일러 및 링커 옵션에 강제 적용.
- **웹어셈블리(Wasm, WebAssembly)** 샌드박스의 논리적 세그멘테이션 원리 활용 : 최신 브라우저 및 서버리스 런타임에서 Wasm 모듈의 선형 메모리(Linear Memory) 경계 격리에 세그멘테이션 사상 재적용 권장.
