## 연관 키워드

- 세그멘테이션(Segmentation), 세그먼트(Segment), 세그먼트 테이블(Segment Table), 2차원 논리 주소
- Base·Limit, 트랩(Trap), 외부 단편화(External Fragmentation), 페이징(Paging)
- 페이지드 세그멘테이션(Paged Segmentation), 버디 시스템(Buddy System), W^X, 최소 권한 원칙(PoLP)

## Ⅰ. 세그멘테이션(Segmentation)의 개요

- 핵심 요약 : 프로그램의 논리 모듈 단위마다 가변 크기 블록을 두어 모듈 단위의 보호와 공유를 실현하는 **세그멘테이션**(Segmentation) 기법.
- 개념 : 프로세스의 가상 주소 공간을 함수·배열·스택 등 프로그래머가 보는 논리 단위인 **세그먼트** (Segment)로 나누어 관리하는 메모리 관리 기법.
- 배경 및 필요성 : 연속 메모리 할당은 프로그램 모듈의 경계와 물리 경계가 일치하지 않아 모듈별 보호와 공유를 하드웨어가 강제하기 어려운 비용을 낳음. 이 비용을 줄이려고 주소 공간을 논리 단위로 나누는 방식이 제안되었고, 가변 크기 할당의 대가로 **외부 단편화** (External Fragmentation)가 생김.
- 주요 목적 : 세그먼트 단위의 보호(Protection)와 공유(Sharing) 실현, 동적으로 커지는 자료구조에 대한 유연한 대응, 프로그래머 관점의 주소 공간 직관화.

## Ⅱ. 세그멘테이션(Segmentation)의 특징 및 장점

- 핵심 요약 : 2차원 논리 주소, 세그먼트 테이블, 하드웨어 경계 검사, 권한 비트가 맞물려 모듈 단위 보호와 공유를 달성하는 구조.

1. **2차원 논리 주소** (세그먼트 번호 s와 변위 d의 쌍) : 주소가 모듈 구조를 그대로 드러냄 → 접근 대상을 세그먼트 단위로 지정하므로 구조 파악과 디버깅이 쉬움.
2. **세그먼트 테이블** (Segment Table) : 세그먼트마다 **Base·Limit**(Base는 물리 시작 위치, Limit은 최대 길이)을 보관 → 세그먼트가 연속 영역 하나로 매핑되어 변환이 단순하고, 같은 엔트리를 여러 프로세스가 가리켜 공유가 가능.
3. **하드웨어 경계 검사** : 변위 d가 Limit 이상이면 **MMU** (Memory Management Unit, 메모리 관리 장치)가 **트랩** (Trap)을 발생 → 다른 모듈 영역의 침범을 접근 시점에 차단.
4. 권한 비트 : 엔트리마다 읽기(R)·쓰기(W)·실행(X) 권한을 지정 → 코드 영역의 쓰기와 데이터 영역의 실행을 막아 보안 사고 면적을 줄임.

## Ⅲ. 세그멘테이션(Segmentation)의 구조 및 동작 메커니즘

- 핵심 요약 : 논리 주소 `<s, d>`를 세그먼트 테이블의 Base와 Limit으로 검사·변환하고, Limit을 넘으면 트랩으로 중단하는 흐름.

```text
[ 세그먼트 주소 변환 흐름 ]

논리 주소 <s, d>
      ↓
세그먼트 테이블[s] 조회
      ↓
d < Limit 검사
      ↓ 예
물리 주소 = Base + d
      ↓
물리 메모리 접근
```

```text
[ 세그먼트 테이블 예시 ]

s=0  Base 2000  Limit 1000
s=1  Base 6000  Limit 400

<1, 300> → 6000 + 300 = 6300   정상
<1, 500> → 500 >= 400          트랩
```

- 변위 d가 Limit 이상이면 세그멘테이션 폴트(Segmentation Fault)로 실행이 중단됨. 위 예시에서 `<1, 500>`은 물리 주소 6500을 가리킬 수 있으나, 세그먼트 길이 400을 넘으므로 인접 영역을 읽기 전에 차단됨.

## Ⅳ. 세그멘테이션(Segmentation)의 비교

- 핵심 요약 : **페이징**(Paging)은 물리 기준의 고정 분할이고 세그멘테이션은 논리 기준의 가변 분할이며, 현대 64비트 환경은 페이징 중심으로 수렴.

| 비교 항목 | 페이징 (Paging) | 세그멘테이션 (Segmentation) | **페이지드 세그멘테이션** (Paged Segmentation) |
| --- | --- | --- | --- |
| 분할 기준 | 물리 기준의 고정 크기 페이지 | 논리 기준의 가변 크기 세그먼트 | 세그먼트를 다시 고정 크기 페이지로 분할 |
| 프로그래머 인지 | 주소 구조를 의식하지 않음 | 2차원 주소로 직접 인지 | 세그먼트 단위 논리, 페이지 단위 할당 |
| 단편화 | 내부 단편화 | 외부 단편화 | 외부 단편화 감소, 내부 단편화 일부 |
| 보호·공유 단위 | 페이지 | 세그먼트 | 세그먼트 단위 보호와 페이지 단위 관리 |
| 현대 구현 | x86-64 롱 모드의 표준 방식 | 64비트 평면 모델에서 검사 비활성화 | IA-32 보호 모드에서 세그먼트 변환 뒤 페이징 적용 |

- 순수 세그멘테이션은 외부 단편화 때문에 운영체제(OS, Operating System)의 주류에서 밀려났고, 보호 기능은 **PTE** (Page Table Entry, 페이지 테이블 엔트리)의 권한 비트로 옮겨 감.
- 선택 기준 : 모듈 경계의 보호와 공유가 핵심인지, 단편화를 피하는 것이 핵심인지에 따라 분할 기준을 정함.

## Ⅴ. 세그멘테이션(Segmentation)의 한계와 방안

- 핵심 요약 : 외부 단편화, 빈 공간 탐색 지연, 64비트 평면 모델의 검사 생략을 압축·버디 시스템·PTE 권한 비트로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 외부 단편화 | 세그먼트 생성과 소멸이 반복되어 빈 공간이 흩어지고, 큰 세그먼트 적재 실패 | 메모리 압축(Compaction) 또는 페이지드 세그멘테이션 채택 | 최대 연속 빈 영역 크기 |
| 빈 공간 탐색 지연 | 최초 적합(First-fit)·최적 적합(Best-fit) 탐색으로 할당마다 지연 | **버디 시스템** (Buddy System) 도입 또는 페이징 체계로 전환 | 세그먼트 할당 지연 시간 |
| 64비트 평면 모델의 검사 생략 | 롱 모드에서 CS·DS·ES·SS 레지스터의 Base·Limit 검사가 무력화 | PTE의 R/W, U/S, NX(No-Execute) 비트로 논리 격리를 대체 | 권한 위반 예외 건수 |

## Ⅵ. 세그멘테이션(Segmentation)의 적용 제언

- 핵심 요약 : 세그먼트의 권한 분리 철학을 컨테이너 권한 설계, 빌드 검증, 샌드박스 경계에 이어 쓰는 방향.

1. 마이크로서비스와 컨테이너 운영 조직은 **최소 권한 원칙** (PoLP, Principle of Least Privilege)을 기준으로 서비스마다 필요한 파일과 네트워크 권한만 부여하도록 배포 정책을 강제한다.
2. 빌드 조직은 **W^X** (Write XOR Execute) 정책을 컴파일러와 링커 단계에서 검증하여, 같은 메모리 영역에 쓰기와 실행이 동시에 허용되지 않도록 한다.
3. 웹 플랫폼 개발팀은 **Wasm** (WebAssembly)의 선형 메모리 경계 검사를 신뢰 경계 설계의 기준으로 삼아 호스트 함수 접근을 최소화한다.

## Ⅶ. 결론

- 핵심 요약 : 세그멘테이션은 논리 모듈 단위의 보호와 공유를 구현한 기법이며, 그 격리 철학은 현재 페이징의 권한 비트와 샌드박스 설계에 남아 있음.
- 외부 단편화와 64비트 평면 모델의 한계로 페이징이 표준이 되었으나, 논리 단위로 경계를 긋는 발상은 여전히 권한 분리 설계의 출발점이다.
