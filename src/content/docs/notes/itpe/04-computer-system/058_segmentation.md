## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 세그먼테이션

## 30초 인출

- 본질: 메모리를 일률적인 크기로 자르면 코드나 함수 같은 논리적 단위의 경계가 잘려 권한 제어와 공유가 복잡해짐
- 메커니즘: 코드, 데이터, 스택 등 프로그래머 관점의 논리적 모듈 단위(가변 크기)로 분할하여 매핑

## 핵심 용어

- Base(기준 주소): 세그먼트가 물리 메모리에 적재된 시작 물리 주소
- Limit(한계 크기): 해당 세그먼트의 유효한 길이로, 변위(d)가 이 크기를 넘어서면 불법 접근으로 판단하여 하드웨어 트랩(Trap) 발생
- 외부 단편화(External Fragmentation): 세그먼트들이 할당과 해제를 반복하면서 메모리 사이사이에 작은 유휴 공간들이 조각나, 총 여유 공간은 충분함에도 새 세그먼트를 적재하지 못하는 현상

## 2~4교시 25점 답안

### Ⅰ. 핵심 구조와 작동

```text
[ 세그먼테이션 하드웨어 주소 변환 및 Limit 보호 검사 ]

CPU 발생 논리 주소: [ 세그먼트 번호 (s) | 변위 / 오프셋 (d) ]
                             │                   │
                             v                   │
           세그먼트 테이블 (Segment Table)        │
           +----+------------+------------+      │
           | s  | 한계(Limit)| 기준(Base) |      │
           +----+------------+------------+      │
           | 0  |    1000    |   0x2000   |      │
           | 1  |    0400    |   0x5000   |      │
           +----+─────┬──────+─────┬──────+      │
                      │            │             │
                      v            │             v
           [ d < Limit 검사? ] <───┼─────────────┘
                      │            │             │
        +─────────────┴─────+      │             │
     Yes│                 No│ (Trap: Seg Fault!) │
        v                   │                    │
    [ 기준(Base) + 변위(d) 덧셈 ] <──────────────┘
                │
                v
       [ 실제 물리 메모리 주소 ]
```

### Ⅱ. 핵심 특성

- 세그먼테이션은 '보호와 공유'의 최강자임 → 함수 단위(예: 표준 C 라이브러리 `printf`)로 세그먼트를 정의하면 해당 세그먼트에 '읽기+실행' 권한만 딱 부여하여 여러 프로세스가 물리 메모리 1개만 안전하게 공유할 수 있음
- 순수 세그먼테이션이 사장된 이유는 '외부 단편화의 악몽' 때문임 → 프로세스가 떴다 죽을 때마다 물리 메모리에 구멍이 숭숭 뚫려 주기적으로 전체 메모리를 복사해 밀어붙이는 압축(Compaction)을 해야 하며, 이는 엄청난 CPU 정지를 유발함
- 현대 x86-64 아키텍처는 세그먼테이션을 사실상 우회함 → 64비트 롱 모드(Long Mode)에서는 CS, DS, ES, SS 세그먼트 레지스터의 Base를 강제로 0으로 고정(Flat Memory Model)하고, 메모리 관리를 전적으로 '페이징'에 위임함

### Ⅲ. 관련 개념과 구분

- 세그먼테이션 vs 페이징: 세그먼테이션 = 논리적 의미 단위, 가변 크기, 외부 단편화 발생, 보호·공유 우수 / 페이징 = 물리적 프레임 단위, 고정 크기(4KB), 내부 단편화 발생, 메모리 활용 극대화

### Ⅳ. 적용 문제와 대응

- 사례: 131회 기출 및 임베디드 OS 환경에서 세그먼트 반복 동적 로딩 중 외부 단편화로 인한 프로세스 기동 불가 장애
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 메모리 잔여 용량이 50MB인데 10MB 크기 세그먼트 할당 실패 | 세그먼트 해제 후 자투리 공간들이 불연속적으로 쪼개짐(외부 단편화) | 최초 적합(First-Fit) 대신 버디 시스템(Buddy System) 또는 슬랩 할당자 적용 | 단편화 최소화 및 할당 속도 개선 |
| 프로그램 비정상 포인터 연산 시 `Segmentation Fault (core dumped)` 종료 | 변위(d)가 세그먼트 테이블의 Limit 필드를 초과하거나 권한 위반 | 커널 MMU 트랩 발생 및 시그널(SIGSEGV) 처리 핸들러 디버깅 연계 | 다른 프로세스 메모리 영역 침범 원천 차단 |

### Ⅴ. 기술사적 제언

| 문제 | 해결 방안 |
|---|---|
| 적용 환경에서 발생하는 핵심 제약 | 기존 대책을 적용하고 핵심 운영 지표를 확인해 개선한다. |

## 출제 이력과 검증 출처

- 제131회 3교시 5번: "운영체제 메모리 관리 기법 중 페이징 기법과 세그먼테이션 기법의 개념을 설명하고, 두 기법을 비교하시오." → 요구 포인트: Ⅰ 세그먼테이션의 개념 및 필요성 + Ⅲ 주소 변환 메커니즘과 세그먼트 테이블 구조도 + Ⅴ 페이징과의 핵심 비교표 및 단편화 이슈
