## 연관 키워드
- 오토스케일링, 수평 확장, 수직 확장, 메트릭, 쿨다운, 용량 계획

## Ⅰ. 오토스케일링의 개요
- 핵심 요약 : 오토스케일링은 관측 지표와 정책에 따라 컴퓨팅 자원을 자동 증감하는 용량 관리 기능.
- 개념 : **오토스케일링**(Auto Scaling)은 수요 변화에 맞춰 인스턴스·Pod·노드 수를 조정하는 자동화.
- 배경 및 필요성 : 정적 용량은 피크 시 부족하거나 유휴 비용을 초래.
- 목적 : 서비스 목표를 유지하면서 자원 사용량과 비용을 조절.

## Ⅱ. 유형과 장점
- 핵심 요약 : 수평·수직·예측 확장은 서로 다른 용량 병목과 조정 시간을 다룸.
- 수평 확장 : 인스턴스 수 증가·감소 → 처리량 확장과 장애 분산.
- 수직 확장 : 인스턴스 CPU·메모리 증감 → 단일 작업 용량 개선, 재시작 영향 가능.
- 메트릭 기반 : CPU, 요청률, 큐 길이, 지연 등으로 정책 발동.
- 예측 기반 : 주기성·예측치를 사용하나 급변 수요에서는 오차 가능.

## Ⅲ. 제어 흐름
- 핵심 요약 : 메트릭 수집·정책 판단·용량 변경 후 안정화와 쿨다운으로 반복 진동을 억제.
```text
수요·메트릭 관측
  ↓ 임계치·목표값 평가
정책 결정: 확장 / 축소 / 유지
  ↓ 자원 프로비저닝·등록
헬스 확인·로드밸런서 편입
```
```text
지연 상승 → 확장
  ↓ 기동·워밍업 시간
용량 안정화 → 축소 대기
  ↓
쿨다운 후 재평가
```

## Ⅳ. 확장 방식 비교
- 핵심 요약 : 무상태 워크로드는 수평 확장에 적합하고 상태 결합 작업은 분할·외부화가 선행.
| 비교 축 | 수평 | 수직 |
| --- | --- | --- |
| 변경 | 인스턴스 수 | 인스턴스 크기 |
| 가용성 | 분산 가능 | 재시작·단일 노드 의존 가능 |
| 한계 | 상태 공유·기동 시간 | 최대 사양·수직 확장 비용 |
| 적합 | 무상태 웹·작업자 | 단일 노드 DB·레거시 |

## Ⅴ. 한계와 방안
- 핵심 요약 : 지연 기동·잘못된 지표·확장 진동과 최대치 초과를 제어.
| 한계 | 원인·영향 | 대응 |
| --- | --- | --- |
| 늦은 확장 | 기동시간이 급증보다 늦음 | 예비 용량·선행 확장 |
| 진동 | 임계치 근처 반복 | 쿨다운·히스테리시스 |
| 부적절 지표 | CPU와 실제 포화 불일치 | 큐·지연·동시성 지표 활용 |
| 무한 비용 | 상한 부재 | 최소·최대 수량·예산 경보 |

## Ⅵ. 운영 제언
- 핵심 요약 : 플랫폼 운영자는 사용자 지연 SLO를 확장 메트릭으로 연결하고 상한·축소 안전조건을 설정.
- 부하 시험에서 기동 지연, 데이터 연결, 로드밸런서 등록 및 종료 드레이닝을 검증.

## Ⅶ. 결론
- 핵심 요약 : 오토스케일링은 수요에 맞춰 용량을 자동 조정하는 제어 루프.
- 올바른 신호와 워크로드 확장 가능성이 비용·성능 효과를 결정.
