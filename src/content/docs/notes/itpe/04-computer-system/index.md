## 8과목 전체 지도와 현재 위치

```text
[01 IT 전략] ── [02 SW 공학] ── [03 데이터] ── [04 시스템 ◀ 현재 과목]
      │                 │               │                    │
      └──────────── 가치·요구·정보·처리 기반 ───────────────┘
                                                                │
                                                                ▼
[08 법·정책] ── [06 보안] ───── [05 네트워크] ── [07 AI·디지털]
 규범·책임         신뢰 경계             연결·전송          지능·서비스 확장
```

- 04 시스템은 **데이터를 실행하는 계산 자원과 운영 기반**을 설명하며, 네트워크·보안·AI 서비스가 올라가는 공통 하부 구조
- 앞 과목 연결: SW의 실행 단위와 데이터의 저장 요구를 CPU·메모리·스토리지·OS가 구현
- 뒤 과목 연결: 네트워크 연결, 보안 통제, AI 가속·클라우드 서비스의 성능·가용성 기반 제공

## 04 컴퓨터 시스템 확대 지도

```text
                         [컴퓨터 시스템]
                                │
            ┌───────────────────┼───────────────────┐
            ▼                   ▼                   ▼
      [컴퓨터구조]          [운영체제]          [인프라·클라우드]
 CPU·GPU·NPU·TPU       프로세스·스레드       가상화·컨테이너
 메모리 계층·캐시       동기화·교착상태        K8s·서버리스
 병렬처리·Flynn         스케줄링·가상메모리    HA·DR·스토리지
            │                   │                   │
            └──────────────┬────┴──────────────┬────┘
                           ▼                   ▼
                    [성능·신뢰성]        [AI·차세대 인프라]
                  병목·튜닝·가용성      HBM·CXL·칩렛·액체냉각
                           │                   │
                           └──────────┬────────┘
                                      ▼
                         [서비스 수준·비용·에너지 최적화]
```

- 관통 질문: **명령과 데이터를 어디서 처리하고, 자원을 누가 배분하며, 장애와 병목을 어떻게 통제하는가?**
- 답안 흐름: `구조 → 동작 → 자원관리 → 병목·장애 → 대안·트레이드오프`
- 이미지 원전: memories의 `07-computer-architecture-system.png`, `08-operating-system.png`, `00-model-answer-flynn-classification.png`

## 30초 인출

```text
구조: CPU ↔ Cache ↔ Memory ↔ Storage
             │
OS: Process → Scheduling → Synchronization → Virtual Memory
             │
추상화: VM → Container → Kubernetes → Serverless
             │
운영: HA·FTS → DR → Observability·Auto Scaling
             │
확장: GPU·NPU·TPU ↔ HBM·CXL·Chiplet ↔ Cooling·Power
```

## 답안 작성 좌표

| 문제 유형 | 우선 시각화 | 실제 답안 전개 |
|---|---|---|
| 구조·구성 | 계층 구조도, 블록도 | 정의 → 특징 → 구조·구성요소 → 동작 → 비교 → 고려 → 결론 |
| 알고리즘·절차 | 상태 전이도, 순서도 | 정의 → 전제 → 자료구조 → 절차 → 계산·판정 → 한계 → 결론 |
| 비교·선정 | 동일 기준 비교표 | 개요 → 공통 목적 → 구조·동작 차이 → 적용 기준 → 의사결정 |
| 장애·성능 | 병목 흐름도, 문제-원인-대책표 | 현상 → 원인 → 탐지 → 제어 → 검증지표 → 재발방지 |

> `답안 골격`만 외우지 않는다. 각 토픽에서 **Ⅰ~Ⅶ 실제 답안**, **1교시 10점 발췌**, **검증 출처**까지 직접 써 본다.

## 학습 단계와 우선 학습 순서

| 학습 단계 | 누적 범위 | 04과목 적용 원칙 |
|---|---:|---|
| **A·기초** | 필독 약 670개 | 정의·구조·동작·대표 비교를 10점 답안으로 완성 |
| **B·핵심** | 누적 약 1,200개 | Ⅰ~Ⅶ 25점 답안과 문제-원인-대책까지 확장 |
| **C·전체** | 누적 약 2,400개 | 최신·인접 토픽과 융합 논점까지 연결 |

> 학습 단계 A/B/C는 기존 토픽 우선순위 등급 A/B/C와 의미가 다르다. 현재 개별 노트의 단계 근거가 확정되지 않았으므로 배지를 자동 추정하지 않고, 기존 `기출/미출·우선순위` 메타를 유지한다.

아래 순서는 과목 큰 그림을 빠르게 잡기 위한 경로이며, 개별 노트의 학습 단계 판정은 아니다.

## 로드맵 활용 원칙

- 컴퓨터구조·OS의 고전 개념은 **기초**라도 최신 인프라 답안의 원리 근거로 사용한다.
- **코어**는 단독 25점 답안과 타 영역 융합 답안까지 준비하고, **기초**는 10점 정의·구조·비교를 우선 완성한다.
- 이미지의 과거 출제빈도 `상·중·하`는 역사 자료일 뿐 공식 출제확률이 아니다.
- 최신 규격·제품 수치·정책은 작성일 기준 1차 출처로 재검증하고, 검증하지 않은 성능 배수는 쓰지 않는다.
