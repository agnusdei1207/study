## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 백필

## 30초 인출

- 본질: 우선순위 FCFS 스케줄링은 앞선 대형 작업이 100개 노드를 모으는 동안 노드 90개가 멍하니 노는 극심한 자원 낭비를 유발함
- 메커니즘: 선두 작업의 목표 시작 시각을 침범하지 않고 그 전에 끝날 소형 작업을 유휴 공간에 끼워 넣어(Backfill) 즉시 실행

## 핵심 용어

- 섀도우 타임(Shadow Time): 선두 대기 작업이 요구하는 모든 자원이 확보되어 실행을 시작할 수 있도록 계산된 미래의 확정 예약 시점
- EASY 백필링(Extensible Argonne Scheduling System): 큐의 맨 앞에 있는 최우선 작업 1개에 대해서만 섀도우 타임을 보장하고, 나머지 뒤쪽 작업들의 시작 시간을 늦추더라도 백필을 과감하게 허용하는 고효율 기법
- Walltime: 사용자가 작업을 제출할 때 선언하는 최대 허용 실행 시간으로, 이 시간을 초과하면 스케줄러가 작업을 강제 종료함

### Ⅱ. 핵심 특성

- 백필링의 성패는 '사용자의 정직함'에 달려 있음 → 스케줄러는 사용자가 적어낸 Walltime을 100% 믿고 빈 공간에 들어갈지 판정하므로, 5분 걸릴 작업을 24시간으로 적어내면 백필 슬롯에 들어가지 못하고 큐에 갇히게 됨
- FCFS와 성능의 절충선 → 엄격한 FCFS는 대형 작업을 위해 자원을 모으느라(Drain) 시스템 활용률이 40%대로 폭락하지만, 백필링을 도입하면 대형 작업의 대기 시간을 늘리지 않으면서도 활용률을 85% 이상으로 끌어올림
- 데이터 파이프라인(Airflow)에서의 백필 개념 확장 → HPC의 자원 스케줄링뿐 아니라 데이터 엔지니어링에서는 과거 누락된 기간의 파이프라인 데이터를 소급하여 재실행하는 '과거 데이터 재적재(Historical Backfill)' 의미로도 통용됨

### Ⅲ. 관련 개념과 구분

- 백필링 vs 선점(Preemption): 백필링 = 비선점형, 앞선 작업의 시작 시점을 침범하지 않는 범위 내에서 빈 틈새에 배치 / 선점 = 우선순위가 높은 작업이 도착하면 실행 중인 작업을 중단/퇴거시키고 자원을 강탈

### Ⅳ. 적용 문제와 대응

- 적용 상황: 대규모 GPU 클러스터에서 작업 간 빈 자원이 생겨 전체 활용률이 낮아지는 상황
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 거대 LLM 학습 작업 대기 중 수백 개의 GPU 노드가 빈 채로 방치 | 단순 FCFS 드레인(Drain) 방식으로 인한 대규모 자원 유휴화 | Slurm 스케줄러의 EASY 백필링 알고리즘 활성화 | 대형 작업 지연 없이 클러스터 가동률 88%로 즉각 향상 |
| 소형 작업들이 유휴 슬롯을 계속 백필하여 선두 대형 작업의 실행이 무한 연기 | 보수적 백필링 대신 과도한 완화 정책으로 섀도우 타임 침범 발생 | 선두 작업 예약 시점 절대 보호 락 및 기아 방지 가중치 부여 | 최우선 대형 작업의 기아 상태(Starvation) 원천 차단 |
