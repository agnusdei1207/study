## 답안 골격
```text
[백필] ◀━━ 머리: Ⅶ 내 의견 (EASY 백필링과 슬롯 예측 모델을 결합한 HPC 클러스터 자원 활용률 극대화 및 지연 보장)
 ┃
 ┣━ Ⅰ 개요 ───── 대형 작업의 자원 예약 대기 시 유휴 슬롯 낭비 발생 → 예약된 시작 시간을 지연시키지 않는 소형 작업을 빈 슬롯에 선행 실행
 ┣━ Ⅱ 특징 ───── 선두 작업 예약 시간 보장 · 유휴 자원 단편화 완화 · 클러스터 활용률 극대화 · 작업 실행 시간(Walltime) 추정 의존
 ┣━ Ⅲ 구조 ───── 작업 큐(우선순위 FIFO) + 자원 예약 테이블(Shadow Time) + 백필 스케줄러 + 노드 할당기
 ┣━ Ⅳ 흐름 ───── ① 대형 작업 자원 부족으로 대기 → ② 자원 해제 시점 계산 및 시작 시간 예약 → ③ 대기 큐의 소형 작업 탐색 → ④ 예약 시점 전 완료 작업 즉시 실행
 ┣━ Ⅴ 비교 ───── EASY 백필링(선두 작업만 예약 보장) vs 보수적 백필링(Conservative: 모든 대기 작업 예약 보장)
 ┗━ Ⅵ 실무 ───── 사용자의 실행 시간(Walltime) 과대 추정으로 인한 백필 실패 / 악의적 소형 작업 독점 / 기아 상태(Starvation)
```

## 한 줄 본질
- 우선순위 FCFS 스케줄링은 앞선 대형 작업이 100개 노드를 모으는 동안 노드 90개가 멍하니 노는 극심한 자원 낭비를 유발함 → 선두 작업의 목표 시작 시각을 침범하지 않고 그 전에 끝날 소형 작업을 유휴 공간에 끼워 넣어(Backfill) 즉시 실행 → 클러스터 가동률 대폭 향상 / 사용자의 작업 소요시간 추정 부정확 시 스케줄 교란

## 핵심 그림
```text
[ 시간-자원 2차원 공간에서의 백필링(Backfilling) 동작 메커니즘 ]

노드 자원 (Node Count)
     ▲
100  │┌───────────────────┐
     ││   실행 중인 작업  │
     ││     (Job Running) │
 60  │└─────────┬─────────┘      ┌─────────────────────────────────────┐
     │          │                │ 선두 대형 작업 (Job 1: 100개 노드 필요) │
     │          │                │ * 시작 예약 시각: T2 (Shadow Time)   │
 40  │          │   [유휴 공간]  └─────────────────────────────────────┘
     │          │  * 백필 실행!  │
     │          │ ┌────────────┐ │
     │          │ │ 백필 작업  │ │
  0  └──────────┴─┴────────────┴─┴─────────────────────────────────────> 시간 (Time)
                T0            T1 T2
    [ T0~T2 사이 남는 40개 노드에, T2 이전에 끝나는(T1) 소형 작업을 끼워 넣어 즉시 가동! ]
```

## 핵심 용어
- 섀도우 타임(Shadow Time): 선두 대기 작업이 요구하는 모든 자원이 확보되어 실행을 시작할 수 있도록 계산된 미래의 확정 예약 시점
- EASY 백필링(Extensible Argonne Scheduling System): 큐의 맨 앞에 있는 최우선 작업 1개에 대해서만 섀도우 타임을 보장하고, 나머지 뒤쪽 작업들의 시작 시간을 늦추더라도 백필을 과감하게 허용하는 고효율 기법
- Walltime: 사용자가 작업을 제출할 때 선언하는 최대 허용 실행 시간으로, 이 시간을 초과하면 스케줄러가 작업을 강제 종료함

## 핵심 통찰
- 백필링의 성패는 '사용자의 정직함'에 달려 있음 → 스케줄러는 사용자가 적어낸 Walltime을 100% 믿고 빈 공간에 들어갈지 판정하므로, 5분 걸릴 작업을 24시간으로 적어내면 백필 슬롯에 들어가지 못하고 큐에 갇히게 됨
- FCFS와 성능의 절충선 → 엄격한 FCFS는 대형 작업을 위해 자원을 모으느라(Drain) 시스템 활용률이 40%대로 폭락하지만, 백필링을 도입하면 대형 작업의 대기 시간을 늘리지 않으면서도 활용률을 85% 이상으로 끌어올림
- 데이터 파이프라인(Airflow)에서의 백필 개념 확장 → HPC의 자원 스케줄링뿐 아니라 데이터 엔지니어링에서는 과거 누락된 기간의 파이프라인 데이터를 소급하여 재실행하는 '과거 데이터 재적재(Historical Backfill)' 의미로도 통용됨

## 이웃 토픽과 구분
- 백필링 vs 선점(Preemption): 백필링 = 비선점형, 앞선 작업의 시작 시점을 침범하지 않는 범위 내에서 빈 틈새에 배치 / 선점 = 우선순위가 높은 작업이 도착하면 실행 중인 작업을 중단/퇴거시키고 자원을 강탈
