## 연관 키워드

- 백필(Backfill), 재처리(Reprocessing), 지연 도착 데이터(Late Data), 자원 단편화(Fragmentation)
- 멱등성(Idempotency), 업서트(Upsert), 파티션 덮어쓰기, 원자적 파티션 교체(Atomic Overwrite)
- EASY 백필(EASY Backfill), 보수적 백필(Conservative Backfill), 예약 시각, 기아(Starvation)
- 다운스트림 의존성(Cascade Dependency), Walltime, 레이크하우스(Lakehouse), dbt

## Ⅰ. 백필의 개요

- 핵심 요약 : **백필** (Backfill)은 과거 데이터를 소급 재처리하는 데이터 엔지니어링 기법과, 유휴 자원에 소형 작업을 끼워 넣는 HPC(High-Performance Computing) 스케줄링 기법을 아우르는 용어.
- 개념 : (1) 파이프라인 로직 수정, 소스 데이터 오류 정정, 지연 데이터 유입 등으로 과거 시점의 데이터를 다시 계산해 적재하는 **재처리** (Reprocessing) 작업, (2) 우선순위가 높은 대형 작업의 시작 시각을 늦추지 않는 범위에서 유휴 노드에 소형 작업을 실행하는 자원 스케줄링 기법.
- 배경 및 필요성 : 배치와 스트리밍 파이프라인에서는 **지연 도착 데이터** (Late Data)와 비즈니스 규칙 변경으로 과거 구간을 다시 적재해야 하며, 대규모 클러스터에서는 **자원 단편화** (Fragmentation)로 노드가 유휴 상태로 남는 문제가 생김.
- 주요 목적 : 과거 데이터의 정합성 회복, 클러스터 자원 활용률 향상, 작업 대기 시간 단축.

## Ⅱ. 백필의 특징 및 장점

- 핵심 요약 : 멱등성으로 재실행의 안전성을 확보하고, EASY 백필로 유휴 자원을 활용해 두 영역 모두에서 비용과 리스크를 낮추는 구조.

1. **멱등성** (Idempotency) : 같은 파라미터와 시간 범위로 여러 번 재실행해도 결과가 같도록 파티션 덮어쓰기나 **업서트** (Upsert/Merge) 패턴을 강제 → 재시도 시 중복 적재 위험 제거.
2. **원자적 파티션 교체** (Atomic Overwrite) : 파티션 단위로 임시 적재한 뒤 한 번에 교체 → 읽기 중단과 부분 반영을 막아 서빙 중에도 무중단 갱신.
3. **EASY 백필** (EASY, Extensible Argonne Scheduling System) : 최우선 작업의 예약 시각을 기준으로 자원을 미리 잡아 두고, 그 이전에 끝나는 작은 작업만 유휴 슬롯에 배치 → 클러스터 활용률 향상.

## Ⅲ. 백필의 구조 (흐름)

- 핵심 요약 : 데이터 파이프라인에서는 파티션 멱등 덮어쓰기, HPC에서는 예약 기반 EASY 백필이 각각의 동작 원리.

```text
[ 1. 데이터 파이프라인 백필 ]

과거 날짜 범위 백필 요청
      ↓
오케스트레이터가 과거 실행 인스턴스 생성
      ↓
파티션별 임시 적재
      ↓
원자적 파티션 교체 (Atomic Overwrite)
```

```text
[ 2. EASY 백필 스케줄링 ]

가용 노드 2개, 대기 큐 확인
      ↓
Job 1 (최우선, 8노드) 예약 시각 계산
      ↓
Job 2 (2노드, 30분) 종료가 예약 전 → 승인
      ↓
Job 3 (2노드, 2시간) 예약 침범 → 대기
```

## Ⅳ. 백필의 비교

- 핵심 요약 : 데이터 파이프라인은 재적재 범위, 잡 스케줄링은 예약 보장 수준에 따라 기법을 고름.

| 도메인 | 기법 | 핵심 메커니즘 | 주요 장점 | 고려 사항 |
| --- | --- | --- | --- | --- |
| 데이터 파이프라인 | 전체 재적재 (Full Refresh) | 대상 테이블을 비우고 전체를 다시 계산 | 로직이 단순하고 정합성 보장 | 연산 비용과 소요 시간이 큼 |
| 데이터 파이프라인 | 파티션 백필 (Partitioned Backfill) | 날짜·시간 파티션 단위로 필요한 구간만 덮어쓰기 | 비용 효율적이며 서빙 영향 최소화 | 파티션 간 집계 정합성 관리 필요 |
| 잡 스케줄링 | 보수적 백필 (Conservative Backfill) | 대기 중인 모든 작업의 예약 시각을 보장 | 후순위 작업의 기아(Starvation) 방지 | 백필 기회가 줄어듦 |
| 잡 스케줄링 | EASY 백필 | 최우선 작업의 예약 시각만 보장 | 활용률 극대화, 구현이 단순 | 후순위 작업의 기아 가능성 |

## Ⅴ. 백필의 한계와 방안

- 핵심 요약 : 원천 자원 고갈, 다운스트림 전파 오류, Walltime 과소 선언을 청크 제한, 자동 하위 재실행, 타임아웃 정책으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 원천 DB·파이프라인 자원 고갈 | 과거 대용량 조회가 운영 DB의 커넥션과 CPU를 점유해 서비스 장애 유발 | 배치 청크 크기 제한, 읽기 전용 복제본 지정, 야간 시간대 분할 실행 | 커넥션 사용률, 청크 처리 시간 |
| 다운스트림 전파 오류 | 원천 테이블만 백필하고 파생 마트를 갱신하지 않아 **다운스트림 의존성** (Cascade Dependency) 불일치 발생 | 데이터 리니지 기반의 하위 자동 재실행, 예를 들어 data build tool(dbt) 활용 | 불일치 건수, 재실행 누락률 |
| Walltime 과소 선언 | 사용자가 실행 시간을 짧게 선언해 승인을 받으면 최우선 대형 작업의 시작이 지연 | 선언 시간을 넘기면 작업을 강제 종료하는 타임아웃 정책 적용 | 강제 종료 건수, 예약 지연 시간 |

## Ⅵ. 백필의 적용 제언

- 핵심 요약 : 멱등성을 파이프라인 설계 초기부터 내재화하고, 트랜잭션을 지원하는 테이블 형식으로 백필의 원자성을 확보하는 것이 바람직함.
- 설계 원칙 : 파이프라인이 현재 시각을 참조하지 않고 실행 기준 시점으로 파티션을 덮어쓰도록 표준화해 재실행 결과를 항상 같게 만듦.
- 저장 계층 : Apache Iceberg나 Delta Lake 같은 레이크하우스 테이블 형식을 채택해 백필 도중 실패하면 자동 롤백되고 읽기 일관성이 유지되도록 함.

## Ⅶ. 결론

- 핵심 요약 : 백필은 소급 재처리와 자원 스케줄링을 잇는 기법으로, 멱등성과 EASY 백필이 핵심임.
- 시사점 : 자원 고갈, 전파 오류, 실행 시간 왜곡을 통제할 때에만 백필이 데이터 정합성과 자원 효율을 함께 지킴.
