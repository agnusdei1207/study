## Ⅰ. 결함허용시스템(FTS)의 개요

- 핵심 요약 : **FTS**는 결함 감지·마스킹·복구 메커니즘으로 시스템 중단 없이 정상 기능을 지속 수행하는 고신뢰성 시스템.
- 개념 : 시스템의 일부 하드웨어나 소프트웨어 컴포넌트에 **결함(Fault)** 이 발생하더라도 시스템 전체가 중단되거나 오작동하지 않고, 설계된 정상 기능을 지속적으로 수행할 수 있도록 결함 감지, 격리, 마스킹 및 복구 메커니즘을 내장한 고신뢰성 결함허용시스템(FTS, Fault-Tolerant System).
- 배경 및 필요성 : 항공우주, 원자력 발전, 철도 신호 제어, 금융 코어 뱅킹 등 1초의 오작동이나 다운타임도 인명 피해나 천문학적 재난으로 이어지는 미션 크리티컬 환경에서 완전한 무결성을 보장하기 위해 고안됨.
- 핵심 목적 : 오류의 **시스템 장애(Failure)** 전파 원천 차단, 결함 마스킹을 통한 무중단 고가용성 보장, **시스템 신뢰도(Reliability)** 및 **안전성(Safety)** 극대화.

## Ⅱ. 결함허용시스템(FTS)의 특징 및 장점

- 핵심 요약 : **결함 마스킹·락스텝·격리·복구**로 무중단 신뢰성 확보.
1. **결함 마스킹 (Fault Masking)** : 결함이 발생한 즉시 외부 시스템으로 전달되지 않도록 TMR과 같은 하드웨어 투표 회로를 통해 오류를 상쇄.
2. **하드웨어 락스텝 (Lockstep Dual/Triple Core)** : 복수의 CPU(Central Processing Unit) 코어가 동일한 클록 사이클에 동일한 명령어를 실행하고, 매 사이클마다 비교기(Comparator)가 결과를 대조.
3. **결함 격리 (Fault Confinement)** : 결함이 확인된 노드나 보드를 전기적·논리적으로 차단하여 건전한 부품으로의 오염 확산 방지.
4. **전진/후진 복구 (Forward / Backward Recovery)** : 체크포인트 기반으로 과거 정상 상태로 되돌리는 후진 복구와, 롤포워드 및 보상 트랜잭션을 적용하는 전진 복구 적용.

## Ⅲ. 결함허용시스템(FTS)의 구조 및 동작 메커니즘

- 핵심 요약 : **TMR 3중 모듈 + Voter + 락스텝**으로 결함 마스킹.
- FTS는 '결함(Fault) -> 오류(Error) -> 장애(Failure)'로 이어지는 연쇄 고리를 차단하기 위해 **3중 모듈 중복** (TMR, Triple Modular Redundancy)과 다수결 투표기(Voter), 그리고 하드웨어 락스텝(Lockstep) 아키텍처로 동작함.

```text
[ 결함허용 3중 모듈 중복(TMR) 및 단계별 방어 체계 ]

  [결함(Fault)] ──> [오류(Error)] ──> [장애(Failure)]
  (잠재적 원인)     (비정상 상태)     (서비스 전면 중단)
        │                 │                  │
        ▼                 ▼                  ▼
  [결함 방지/회피]  [결함 마스킹/감지]  [결함 격리 및 복구]

[ 하드웨어 TMR (Triple Modular Redundancy) 아키텍처 ]

+-------------------------------+
| Module A (동일 입력 신호)     | ──+
+-------------------------------+   │
                                    │
+-------------------------------+   │     +--------------------+     +-------------+
| Module B (동일 입력 신호)     | ──┼───> | Voter (다수결 회로)| ──> | 최종 출력   |
+-------------------------------+   │     | (2-out-of-3 판정)  |     | (정상 보장) |
                                    │     +--------------------+     +-------------+
+-------------------------------+   │
| Module C (결함 발생: 오류 출력)| ──+
+-------------------------------+
  * Module C에서 에러가 발생해도 Voter가 A와 B의 다수결을 채택하여 에러를 즉각 마스킹
```

## Ⅳ. 결함허용시스템(FTS)의 비교

- 핵심 요약 : **HA·FTS·DR** 목적·다운타임·구현·비용·RPO 비교.

| 비교 항목 | 고가용성 시스템 (HA, High Availability) | 결함허용시스템 (FTS) | 재해복구 시스템 (DR, Disaster Recovery) |
|---|---|---|---|
| 설계 목적 | 연간 다운타임 최소화 (99.999%) | 단 1초의 중단이나 오작동도 불허 | 지진, 화재 등 광역 재난 복구 |
| 장애 시 다운타임 | 수 초 ~ 수십 초 (페일오버 소요) | 0초 (Zero Downtime, 순간 지속) | 수십 분 ~ 수 시간 (RTO) |
| 구현 방식 | Active-Standby / Active-Active 클러스터링 | TMR, Lockstep 하드웨어 다중화 | 원격지 백업 센터 및 데이터 복제 |
| 비용 및 복잡도 | 중간 (상용 서버 및 소프트웨어 활용) | 매우 높음 (특수 제작 하드웨어) | 인프라 이중 구축으로 높음 |
| 데이터 손실 (RPO, Recovery Point Objective) | 미세 유실 가능 (비동기 복제 시) | 완전 무손실 (RPO = 0) | 복제 주기에 따라 수 분~수 시간 |

- HA는 장애 발생 후 Standby로 전환되는 '인계' 방식이지만, FTS는 장애 순간에도 결함을 실시간 마스킹하여 프로세스가 중단 없이 계속 연산하는 '동시 존속' 방식임.

## Ⅴ. 결함허용시스템(FTS)의 한계와 방안

- 핵심 요약 : **공통 원인 결함·Voter SPOF·비용**을 NVP·트라이플리케이트 보터·선별 적용으로 대응.

- **공통 원인 결함** (Common-Cause Failure)으로 인한 동시 붕괴 :
  - 한계점 : 동일한 소프트웨어 버그나 펌웨어 설계 결함이 존재하는 경우, 하드웨어를 3중화하더라도 모든 모듈이 동시에 동일한 에러를 발생시켜 투표 무력화.
  - 해결 방안 : N-버전 프로그래밍(NVP, N-Version Programming: 독립된 팀이 서로 다른 언어와 알고리즘으로 작성) 및 이종 OS(Operating System)/하드웨어 조합 도입.
- **투표기(Voter)** 자체의 단일 장애점(SPOF, Single Point of Failure) 리스크 :
  - 한계점 : 다수결을 판정하는 보터 회로 자체에 결함이 발생할 경우 전체 시스템 출력이 정지되거나 오염.
  - 해결 방안 : 투표기 자체를 3중화하는 트라이플리케이트 보터(Triplicated Voter) 아키텍처 및 자가 검사형(Self-checking) 논리 회로 설계.
- 하드웨어 대규모 중복 투자에 따른 막대한 비용 및 전력 :
  - 한계점 : 동일 연산을 위해 다수의 장비와 전력이 투입되어 민간 일반 비즈니스 적용 시 경제적 타당성 결여.
  - 해결 방안 : 가상화 기반 마이크로 락스텝(Micro-lockstep) 기술 도입 및 미션 크리티컬 핵심 프로세스에 한해 선별적 FTS 적용.

## Ⅵ. 결함허용시스템(FTS) 적용 제언

- 핵심 요약 : **ASIL/DO-178C·카오스 엔지니어링·Software-Defined FTS**.
- 자율주행/UAM 안전 표준 연계 : ISO 26262 ASIL-D, DO-178C 인증 충족 락스텝 FTS 의무 내재화.
- 카오스 엔지니어링 : SEU·전원 차단 주입으로 마스킹 실효성 검증.
- Software-Defined FTS : Raft/Paxos 분산 합의 기반 소프트웨어 계층 FTS.

## Ⅶ. 결론

- 핵심 요약 : FTS는 **결함 마스킹과 무중단 연산**으로 미션 크리티컬 신뢰성을 보장하나 공통 원인 결함·비용 관리가 필수.
- FTS는 TMR·락스텝·Voter로 결함을 실시간 마스킹하여 무중단 고신뢰성을 보장하지만, 공통 원인 결함·Voter SPOF·막대한 비용 리스크를 NVP·트라이플리케이트 보터·선별 적용으로 관리해야 함.
- 답안에는 결함→오류→장애 연쇄 차단, TMR 구조, HA/FTS/DR 비교, 한계·대응, ASIL/DO-178C·카오스·Software-Defined FTS 제언을 연결.
