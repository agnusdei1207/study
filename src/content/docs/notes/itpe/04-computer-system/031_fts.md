## 연관 키워드

- 결함허용시스템(FTS, Fault-Tolerant System), 결함(Fault), 오류(Error), 장애(Failure), 결함 마스킹(Fault Masking)
- TMR(Triple Modular Redundancy), 투표기(Voter), 락스텝(Lockstep), 결함 격리(Fault Confinement), 전진·후진 복구
- 공통 원인 결함(Common-Cause Failure), NVP(N-Version Programming), SPOF(Single Point of Failure), HA, DR, RPO(Recovery Point Objective)

## Ⅰ. 결함허용시스템의 개요

- 핵심 요약 : 구성요소에 결함이 생겨도 감지와 마스킹, 복구로 서비스 연속성을 지키는 고신뢰 시스템.
- 개념 : **결함허용시스템** (FTS, Fault-Tolerant System)은 하드웨어나 소프트웨어 구성요소의 **결함** (Fault, 잠재적 원인)이 비정상 상태인 **오류** (Error)가 되고, 다시 **장애** (Failure, 서비스 중단)로 번지지 않도록 감지, 격리, 마스킹, 복구 기능을 내장한 시스템.
- 배경 및 필요성 : 항공우주, 원자력, 철도 신호, 금융 코어 시스템처럼 짧은 중단이나 오작동도 인명과 사회적 피해로 이어지는 미션 크리티컬 환경에서 완전한 무결성이 요구됨.
- 주요 목적 : 결함에서 오류, 장애로 이어지는 연쇄를 끊고 중단 없는 가용성과 신뢰도, 안전성을 동시에 확보.

## Ⅱ. 결함허용시스템의 특징 및 장점

- 핵심 요약 : 다수결 상쇄, 동기 실행 비교, 격리, 복구가 결합되어 결함 발생 순간에도 서비스가 계속되는 구조.

1. **결함 마스킹** (Fault Masking) : 다중화된 모듈의 출력을 다수결로 채택해 틀린 값을 상쇄 → 오류가 외부로 전달되지 않고 서비스가 계속됨.
2. **락스텝** (Lockstep) : 복수의 CPU(Central Processing Unit) 코어가 같은 클록에 같은 명령을 실행하고 비교기가 매 사이클 결과를 대조 → 불일치의 즉시 감지.
3. **결함 격리** (Fault Confinement) : 결함이 확인된 노드나 보드를 전기적·논리적으로 차단 → 건전한 부분으로의 오염 확산 방지.
4. **전진·후진 복구** (Forward/Backward Recovery) : 체크포인트로 정상 시점에 되돌리는 후진 복구와 보상 트랜잭션으로 이어가는 전진 복구를 상황에 맞게 적용 → 중단 시간 최소화.

## Ⅲ. 결함허용시스템의 구조 (흐름)

- 핵심 요약 : 결함에서 오류, 장애로 이어지는 연쇄를 다중화 모듈의 다수결 구조로 끊는 방식.
- **TMR** (Triple Modular Redundancy, 3중 모듈 중복) : 동일 기능 모듈 세 개를 두고 다수결로 출력을 결정하는 대표적 마스킹 구조.
- **투표기** (Voter) : 모듈 출력 중 두 개 이상이 일치하는 값을 채택하는 다수결 판정 회로.

```text
[ 결함 연쇄와 차단 지점 ]

결함 (Fault, 잠재적 원인)
   ↓ 감지와 마스킹으로 차단
오류 (Error, 비정상 상태)
   ↓ 격리와 복구로 차단
장애 (Failure, 서비스 중단)
```

```text
[ TMR 다수결 마스킹 ]

모듈 A, B, C의 출력
   ↓
투표기 (2-of-3 다수결 판정)
   ↓
일부 모듈의 오류 출력 상쇄
   ↓
정상 값의 최종 출력 유지
```

## Ⅳ. HA와 FTS, DR의 비교

- 핵심 요약 : 고가용성, 결함허용, 재해복구는 목적과 중단 허용 수준, 구현 방식이 달라 대체가 아닌 보완 관계.

| 비교 항목 | 고가용성 (HA, High Availability) | 결함허용시스템 (FTS) | 재해복구 (DR, Disaster Recovery) |
| --- | --- | --- | --- |
| 설계 목적 | 연간 다운타임 최소화 | 순간의 중단·오작동도 불허 | 광역 재난 이후의 복구 |
| 장애 시 동작 | 페일오버(Failover)로 짧은 중단 | 마스킹으로 연속 수행 | 복구 목표 시간 내 전환 |
| 구현 방식 | Active-Standby 클러스터링 | TMR, 락스텝 하드웨어 다중화 | 원격지 백업 센터와 복제 |
| 비용 수준 | 중간 | 매우 높음 | 인프라 이중 구축으로 높음 |
| 데이터 손실 한도 | 비동기 복제 시 유실 가능 | 무손실 목표 | **RPO** (Recovery Point Objective) 기준 |

- 선택 기준 : 일반 업무는 HA, 인명과 거래 무결성이 걸린 핵심 기능은 FTS, 재난 대비는 DR로 구분해 계층적으로 적용하는 구성이 합리적.

## Ⅴ. 결함허용시스템의 한계와 방안

- 핵심 요약 : 동시 결함, 판정 회로 취약점, 중복 비용을 설계 다양화, 판정기 이중화, 선별 적용으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **공통 원인 결함** (Common-Cause Failure) | 같은 소프트웨어 결함을 공유하면 다중화해도 동일 오류로 투표가 무력화 | **NVP** (N-Version Programming, 독립 개발 버전 병행)와 이종 하드웨어 조합 | 버전 간 출력 불일치율 |
| 투표기의 **SPOF** (Single Point of Failure) | 판정 회로 고장이 전체 출력 정지나 오염으로 직결 | 투표기의 자가 검사 논리와 다중화 구조 | 투표기 자가 진단 결과 |
| 중복 구성의 비용과 전력 | 동일 연산의 반복 수행으로 일반 업무에 경제성 저하 | 미션 크리티컬 기능에만 선별 적용, 나머지는 HA 병행 | 단위 서비스당 장비 비용 |

## Ⅵ. 결함허용시스템에 대한 기술사적 제언

- 핵심 요약 : 안전 규격 연계, 장애 주입 검증, 소프트웨어 기반 대안 탐색으로 FTS를 실효성 있는 안전 체계로 정착.

1. 자율주행과 항공 분야 개발 조직은 기능 안전 표준인 IEC 61508 계열 규격과 자동차 ISO 26262의 **ASIL** (Automotive Safety Integrity Level), 항공 소프트웨어 인증 기준 **DO-178C**를 요구사항 단계에 반영해 결함허용 구조를 인증 대상으로 설계한다.
2. 운영 조직은 **카오스 엔지니어링** (Chaos Engineering)으로 결함 주입 시험을 상시화해 마스킹과 격리가 실제 동작하는지 주기적으로 검증한다.
3. 플랫폼 연구팀은 Raft, Paxos 같은 분산 합의 알고리즘을 활용한 소프트웨어 기반 결함허용을 검토해 하드웨어 중복 의존을 낮춘다.

## Ⅶ. 결론

- 핵심 요약 : 결함허용시스템은 다중화와 다수결 마스킹으로 결함의 연쇄를 끊어 무중단 고신뢰성을 확보하는 체계.
- 결함의 동시 발생 가능성과 비용이 적용 범위를 정하므로 핵심 기능 중심의 설계 판단이 중요.
