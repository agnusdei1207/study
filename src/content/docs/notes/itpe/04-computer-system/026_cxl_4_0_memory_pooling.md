## 연관 키워드

- CXL(Compute Express Link), CXL 4.0, PCIe, 캐시 일관성(Cache Coherency), CXL.io, CXL.cache, CXL.mem
- 메모리 풀링(Memory Pooling), 메모리 공유(Memory Sharing), 패브릭 스위치(Fabric Switch), 멀티헤드 장치(Multi-Headed Device)
- 분해형 아키텍처(Disaggregated Architecture), 스트랜디드 메모리(Stranded Memory), 번들 포트(Bundled Port)
- 계층형 메모리(Tiered Memory), CXL-IDE(Integrity and Data Encryption), NUMA(Non-Uniform Memory Access)

## Ⅰ. CXL 메모리 풀링의 개요

- 핵심 요약 : PCIe 기반 캐시 일관성 인터커넥트로 서버 경계 너머의 메모리를 하나의 풀로 묶어 활용률을 높이는 분해형 아키텍처 기술.
- 개념 : **CXL** (Compute Express Link)은 PCIe(Peripheral Component Interconnect Express) 물리 계층 위에서 CPU와 메모리 장치, 가속기 사이의 **캐시 일관성** (Cache Coherency)과 바이트 단위 접근을 보장하는 인터커넥트 표준이며, 이를 통해 여러 서버의 메모리를 동적으로 묶어 나눠 쓰는 방식이 **메모리 풀링** (Memory Pooling).
- 배경 및 필요성 : 생성형 AI로 메모리 수요가 급증했으나 소켓당 메모리 채널 수에는 물리적 한계가 있고, 서버마다 쓰이지 않고 남는 **스트랜디드 메모리** (Stranded Memory)가 누적되어 메모리를 서버 밖의 공유 자원으로 전환하는 **분해형 아키텍처** (Disaggregated Architecture)가 필요해짐.
- 주요 목적 : 서버 간 메모리 경계 제거, 메모리 활용률 제고와 설비 투자 절감, CXL 4.0 세대에서 랙을 넘는 풀 범위 확장.

## Ⅱ. CXL 메모리 풀링의 특징 및 장점

- 핵심 요약 : 세 프로토콜의 역할 분담과 스위치 기반 풀링, 세대별 패브릭 확장이 메모리 활용률과 데이터 이동 효율을 함께 높이는 구조.

1. **CXL.io** : 장치 검색, 구성, DMA(Direct Memory Access), 인터럽트를 담당하는 입출력 프로토콜 → 기존 PCIe 소프트웨어 생태계를 그대로 재사용.
2. **CXL.cache** : 가속기가 호스트 메모리를 자신의 캐시처럼 사용하도록 지원 → 호스트와 가속기 사이 데이터 복사 감소.
3. **CXL.mem** : 호스트가 메모리 장치의 영역을 일반 로드·스토어 명령으로 접근 → 응용 코드 변경 없는 메모리 확장.
4. 풀링과 공유의 구분 : 풀링은 스위치가 DRAM(Dynamic Random-Access Memory) 영역을 호스트별로 분할 할당하는 방식이고, **메모리 공유** (Memory Sharing)는 여러 호스트가 같은 영역을 캐시 일관성을 유지한 채 동시 접근 → 워크로드에 맞는 자원 모델 선택 가능.
5. CXL 4.0 세대 확장 : 2025년 공개된 CXL 4.0은 PCIe 7.0 계열 물리 계층으로 회선 속도를 128 GT/s까지 높이고, **번들 포트** (Bundled Port)로 여러 링크를 묶어 랙을 넘는 풀 구성 지원 → 기존 수준의 지연을 유지한 채 풀 용량과 범위 확대.

## Ⅲ. CXL 메모리 풀링의 구조 (흐름)

- 핵심 요약 : 스위치 계층과 멀티헤드 장치를 통해 여러 호스트가 하나의 메모리 풀에 연결되는 계층 구조.
- **패브릭 스위치** (Fabric Switch) : 호스트 포트와 장치 포트를 연결해 메모리 영역을 호스트별로 배분하는 네트워크 요소.
- **멀티헤드 장치** (Multi-Headed Device) : 하나의 메모리 장치가 여러 호스트 포트를 두고 공유 영역을 제공하는 장치 형태. 메모리 전용 장치는 Type 3로 분류됨.

```text
[ 메모리 풀링 구조 ]

복수의 호스트 CPU
   ↓ CXL 링크
패브릭 스위치 (영역 배분)
   ↓
메모리 풀 (Type 3 장치군)
   ↓
DRAM 영역의 할당과 회수
```

```text
[ 메모리 공유 흐름 ]

호스트 A가 풀 영역에 데이터 기록
   ↓
하드웨어 캐시 일관성 유지
   ↓
호스트 B가 같은 주소를 읽기
   ↓
복사 없이 데이터 즉시 사용
```

## Ⅳ. CXL 세대 간의 비교

- 핵심 요약 : CXL 2.0, 3.x, 4.0은 물리 계층 속도와 토폴로지 범위, 메모리 접근 방식이 세대별로 확장된 관계.

| 비교 항목 | CXL 2.0 | CXL 3.x | CXL 4.0 |
| --- | --- | --- | --- |
| 물리 계층 | PCIe 5.0 (32 GT/s) | PCIe 6.0 (64 GT/s) | PCIe 7.0 계열 (128 GT/s) |
| 토폴로지 | 스위치 도입, 랙 내 풀링 | 다단 스위치와 멀티헤드 장치 | 번들 포트 기반 랙 간 확장 |
| 메모리 접근 | 분할 할당(풀링) 중심 | 다수 호스트 간 일관성 공유 | 공유 범위 확대와 메모리 신뢰성 기능 강화 |
| 주요 용도 | 서버 메모리 용량 확장 | 랙 단위 동적 메모리 풀 | 랙을 넘는 AI 메모리 패브릭 |

- 선택 기준 : 단일 서버 용량 확장은 CXL 2.0 장치, 다중 호스트 공유와 랙 단위 풀링은 CXL 3.x, 랙 간 규모의 AI 메모리 패브릭은 CXL 4.0을 검토하는 방식으로 세대를 고름.

## Ⅴ. CXL 메모리 풀링의 한계와 방안

- 핵심 요약 : 원격 메모리 지연, 공유 풀의 보안 격리, 소프트웨어 성숙도를 계층형 메모리, 암호화, NUMA 인지 할당으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 원격 메모리 접근 지연 | 링크와 스위치를 거치며 로컬 DRAM보다 지연이 길어짐 → 메모리 집약 워크로드 성능 저하 | **계층형 메모리** (Tiered Memory) 구성, 리눅스 DAMON(Data Access MONitor) 기반 접근 빈도 식별과 데이터 배치 | 접근 지연, 계층 간 이동 빈도 |
| 공유 풀의 보안과 격리 | 여러 호스트와 가상머신이 같은 풀을 사용하며 데이터 오염과 정보 노출 위험 | **CXL-IDE** (Integrity and Data Encryption) 적용, 영역 단위 접근 제어 | 접근 위반 탐지 건수 |
| 소프트웨어 성숙도 부족 | 기존 응용이 단일 **NUMA** (Non-Uniform Memory Access) 구조를 가정해 풀 메모리를 효율적으로 사용하지 못함 | NUMA 인지형 할당 정책과 커널 메모리 관리 기능의 지속 추적 적용 | 할당 실패율, 응용 적용률 |

## Ⅵ. CXL 메모리 풀링에 대한 기술사적 제언

- 핵심 요약 : 응용 설계, 자원 계획, 전환 대비 시험 환경을 단계적으로 묶어 메모리 풀링을 데이터센터 운영 모델로 정착.

1. AI 추론 플랫폼 조직은 **KV 캐시** (Key-Value Cache)를 CXL 공유 풀에 상주시켜 여러 추론 인스턴스가 복사 없이 같은 캐시를 참조하는 구조를 설계한다.
2. 데이터센터 운영 조직은 서버별 과다 탑재 메모리의 풀 이전과 회수율 관리를 자원 계획 절차에 포함해 설비 투자 증가를 억제한다.
3. 인프라 조직은 세대 전환에 대비한 스위치와 광 연결 시험 환경을 선구축해 표준 세대가 바뀔 때 전환 비용을 낮춘다.

## Ⅶ. 결론

- 핵심 요약 : CXL 메모리 풀링은 메모리를 서버 내부 자원이 아닌 공유 자원으로 다루게 만드는 분해형 아키텍처의 핵심 축.
- 지연과 보안, 소프트웨어 지원이 함께 정비될 때 풀링 도입의 효과가 안정적으로 나타남.
