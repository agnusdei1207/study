## Ⅰ. NAS(Network-Attached Storage)의 개요

- 핵심 요약 : **NAS**는 TCP/IP 이더넷 기반 파일 수준 공유 스토리지로 이기종 OS 간 파일 공유와 중앙 관리를 제공.
- 개념 : 표준 TCP(Transmission Control Protocol)/IP(Internet Protocol) 이더넷(Ethernet) 네트워크를 기반으로 여러 이기종 클라이언트 시스템에 **파일 수준** (File-Level)의 데이터 입출력과 공유 스토리지를 제공하는 전용 파일 서버 스토리지 시스템.
- 배경 및 필요성 : 서버마다 스토리지가 종속되어 공유가 불가능하던 **DAS** (Direct-Attached Storage)의 데이터 고립(Silo) 문제를 해결하고, 부서 간 비정형 문서 및 미디어 파일의 중앙 집중식 협업 및 공유 요구 증대에 따라 널리 보급됨.
- 핵심 목적 : **표준 파일 공유 프로토콜** (NFS, Network File System; SMB, Server Message Block; CIFS, Common Internet File System)을 통한 이기종 OS(Operating System) 간 파일 공유, 파일 단위 권한 제어(POSIX, Portable Operating System Interface / ACL(Access Control List)), 스토리지 관리 일원화를 통한 TCO(Total Cost of Ownership) 절감.

## Ⅱ. NAS(Network-Attached Storage)의 특징 및 장점

- 핵심 요약 : **파일 수준 I/O 추상화·파일 락킹·NFS/SMB 프로토콜**.
1. **파일 수준 I/O 추상화** : 클라이언트는 블록 오프셋을 알 필요 없이 파일 경로(Pathname), 파일명, 바이트 오프셋(Read/Write) 단위의 RPC(Remote Procedure Call) 명령어로 데이터를 요청하고, 파일 시스템 관리는 NAS(Network-Attached Storage) 컨트롤러가 전담.
2. **파일 락킹 및 동시성 제어** : **NFS Network Lock Manager(NLM)** 또는 **SMB Opportunistic Locks** (Oplocks)를 통해 다중 클라이언트 간의 동시 파일 쓰기 충돌을 방지하고 캐시 일관성 유지.

## Ⅲ. NAS(Network-Attached Storage)의 구조 및 동작 메커니즘

- 핵심 요약 : **클라이언트 NFS/SMB → NAS 컨트롤러(프로토콜 데몬·파일시스템·RAID) → 물리 디스크**.
- NAS는 표준 TCP/IP 이더넷 기반으로 파일 수준 I/O를 제공하며, NAS 컨트롤러가 프로토콜 데몬과 파일 시스템, 볼륨 관리, 데이터 보호를 전담함.

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ NAS (Network-Attached Storage) 계층 및 I/O 프로토콜 스택 ]           │
│                                                                        │
│   [ Linux/UNIX 클라이언트 ]              [ Windows 클라이언트 ]        │
│   - VFS (Virtual File System)            - Windows I/O Manager         │
│   - NFS Client Driver                    - SMB/CIFS Client Driver      │
│   └───────────────────┬──────────────────┴───────────────────┘         │
│                       │ IP Network (Ethernet, TCP/UDP)                 │
│                       ▼                                                │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ [ NAS 스토리지 컨트롤러 (Dedicated Appliance) ]                │   │
│   │  - 네트워크 계층: NIC / 10G/25G/100G 이더넷 인터페이스         │   │
│   │  - 프로토콜 데몬: NFS Server (v3/v4.1), SMB Server (v2/v3)    │   │
│   │  - 공유 파일 시스템: ZFS, WAFL, XFS (메타데이터 및 파일 락 제어)│   │
│   │  - 볼륨 관리 및 데이터 보호: 소프트웨어/하드웨어 RAID, 스냅샷  │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   │ 블록 I/O (SAS, SATA, NVMe)         │
│                                   ▼                                    │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ [ 물리적 스토리지 디스크 풀 (HDD / SSD / NVMe 드라이브) ]      │   │
│   └────────────────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────────────────┘
```

## Ⅳ. NAS(Network-Attached Storage)의 비교

- 핵심 요약 : **NAS·SAN·DAS** 액세스 레벨·네트워크·프로토콜·파일시스템 위치·성능·적합 업무 비교.

| 비교 항목 | NAS (Network-Attached Storage) | SAN (Storage Area Network) | DAS (Direct-Attached Storage) |
| :--- | :--- | :--- | :--- |
| 액세스 레벨 | 파일 레벨 (File-Level, NFS/SMB) | 블록 레벨 (Block-Level, SCSI/NVMe) | 블록 레벨 (Block-Level, PCIe/SAS) |
| 네트워크 매체 | 범용 이더넷 (TCP/IP Network) | 전용 파이버 채널(FC) 또는 IP-SAN | 호스트 직접 연결 버스 (SAS/SATA(Serial Advanced Technology Attachment)/PCIe(Peripheral Component Interconnect Express)) |
| 전송 프로토콜 | NFS, SMB/CIFS | FCP, iSCSI, NVMe(Non-Volatile Memory Express)-oF | SAS, SATA, NVMe |
| 파일시스템 위치 | NAS 스토리지 컨트롤러 내부 | 각 호스트 서버 내부 | 각 호스트 서버 내부 |
| 성능 및 지연 | 네트워크 프로토콜 스택으로 지연 존재 | 초저지연, 대규모 고성능 I/O 최적화 | 최고 속도, 단일 서버 초저지연 |
| 주요 적합 업무 | 비정형 문서 공유, 미디어 협업, CMS | 대규모 RDBMS(Relational Database Management System), 가상화 데이터스토어 | 단일 고성능 DB(Database), 백업 테이프, 로컬 캐시 |

## Ⅴ. NAS(Network-Attached Storage)의 한계와 방안

- 핵심 요약 : **컨트롤러 병목/SPOF·TCP/IP 오버헤드·NFS 보안**을 스케일아웃·RDMA·NFS v4로 대응.

- 중앙 집중식 컨트롤러의 메타데이터 병목 및 단일 **장애점(SPOF, Single Point of Failure)** :
  - 한계점 : 단일/이중화 컨트롤러 기반 스케일업(Scale-Up) NAS는 수억 개의 파일 생성 시 메타데이터 갱신 락(Lock)으로 인해 I/O 급감.
  - 해결 방안 : 분산 메타데이터 서버를 탑재하고 노드 증설에 따라 선형 확장되는 스케일아웃 NAS(Dell Isilon, CephFS, GlusterFS) 도입.
- **TCP/IP** 프로토콜 스택 오버헤드로 인한 고성능 AI(Artificial Intelligence)/빅데이터 처리 한계 :
  - 한계점 : 대용량 AI 학습 데이터 로딩 시 커널 모드 스위칭과 패킷 복사 오버헤드로 인해 GPU(Graphics Processing Unit) I/O 기아 현상(I/O Starvation) 유발.
  - 해결 방안 : RDMA(Remote Direct Memory Access) 기반의 NFS(NFS over RoCE / NFSoRDMA) 적용 및 병렬 파일 시스템(pNFS, Lustre, GPFS) 도입.
- **NFS v3**의 약한 보안 및 이기종 간 권한 매핑 오류 :
  - 한계점 : IP 기반 인증에 의존하는 레거시 환경에서 UID/GID 위조 가능 및 Windows(ACL)-Linux(POSIX) 간 권한 불일치.
  - 해결 방안 : Kerberos 암호화 인증을 지원하는 NFS v4.1/v4.2 전면 전환 및 LDAP(Lightweight Directory Access Protocol)/Active Directory 통합 신원 관리 연계.

## Ⅵ. NAS(Network-Attached Storage) 적용 제언

- 핵심 요약 : **스케일아웃 NAS·GPUDirect Storage·오브젝트 티어링**.
- AI 및 비정형 데이터 처리를 위한 고성능 스케일아웃 NAS 전략 : 올플래시 NVMe 스케일아웃 NAS를 데이터 레이크 엔트리 저장소로 채택, GPUDirect Storage 연계.
- 오브젝트 스토리지(S3)와의 하이브리드 연계 : 고성능 협업/트랜잭션 파일은 NAS, 콜드 데이터는 ILM 자동 티어링.

## Ⅶ. 결론

- 핵심 요약 : NAS는 **TCP/IP 기반 파일 수준 공유 스토리지**로 이기종 OS 간 협업과 중앙 관리를 실현하나 컨트롤러 병목·TCP/IP 오버헤드·보안 리스크 관리가 필수.
- NAS는 TCP/IP 기반 파일 수준 공유 스토리지로 이기종 OS 간 협업과 중앙 관리를 실현하지만, 컨트롤러 병목·TCP/IP 오버헤드·NFS 보안 리스크를 스케일아웃·RDMA·NFS v4로 관리해야 함.
- 답안에는 NAS/SAN/DAS 비교, 프로토콜 스택, 한계·대응, 스케일아웃 NAS·GPUDirect·오브젝트 티어링 제언을 연결.
