```text
[NAS] ◀━━ 머리: Ⅶ 내 의견 (스케일아웃 분산 파일 시스템 기반 NAS 고도화 및 NVMe-oF를 통한 네트워크 병목 극복)
 ┃
 ┣━ Ⅰ 개요 ───── 서버 직결 스토리지(DAS)의 파일 공유 한계 → 표준 이더넷 LAN 망에 직결되어 파일 레벨 공유를 제공하는 전용 저장 장치
 ┣━ Ⅱ 특징 ───── 파일 레벨 I/O(File-level) · 표준 LAN 인프라(TCP/IP) 활용 · 이기종 OS 파일 공유 · 파일 락(Lock) 관리
 ┣━ Ⅲ 구조 ───── 전용 OS/컨트롤러 + 파일 공유 프로토콜(NFS/SMB/CIFS) + 로컬 파일 시스템 + 디스크 어레이(RAID)
 ┣━ Ⅳ 흐름 ───── ① 클라이언트 파일 접근 요청 → ② RPC/SMB 패킷 캡슐화 → ③ NAS 컨트롤러 파일 시스템 디코딩 → ④ 디스크 블록 읽기
 ┣━ Ⅴ 비교 ───── NAS vs SAN vs DAS (스토리지 3대 아키텍처 비교)
 ┗━ Ⅵ 실무 ───── 일반 업무용 LAN 대역폭 잠식 / 메타데이터 병목으로 인한 수백만 소형 파일 처리 지연 / 파일 잠금 충돌
```

## 한 줄 본질
- 서버마다 디스크를 따로 달면 다른 서버와 문서를 공유하기 어렵고 백업이 파편화됨 → 표준 LAN 네트워크에 파일 공유 전용 컨트롤러를 물려 여러 이기종 서버가 동시에 디렉토리를 마운트하도록 지원 → 손쉬운 파일 공유 및 설치 편의성 / 네트워크 트래픽 혼잡 시 I/O 지연 발생

## 핵심 용어
- NFS(Network File System): 유닉스/리눅스 환경에서 네트워크를 통해 원격 호스트의 디렉토리를 로컬 파일 시스템처럼 마운트해 사용하는 분산 파일 프로토콜
- SMB/CIFS(Server Message Block): 윈도우 환경에서 파일, 프린터, 시리얼 포트 등을 공유하기 위해 사용하는 통신 프로토콜
- 스케일아웃 NAS(Scale-Out NAS): 단일 컨트롤러의 성능 한계를 극복하기 위해 여러 대의 NAS 노드를 클러스터로 묶어 단일 네임스페이스(Single Namespace)로 용량과 성능을 선형 확장하는 시스템

## 핵심 통찰
- NAS는 '외장 하드가 아니라 파일 서버'임 → SAN처럼 블록(LBA)을 던져주는 것이 아니라, NAS 내부의 CPU와 OS가 직접 파일 시스템을 관리하고 클라이언트에게는 디렉토리와 파일 추상화만 보여줌
- 일반 LAN 망을 공유하면 재앙이 됨 → 대용량 파일 복사나 백업이 돌면 사내 ERP와 인터넷 웹서핑까지 패킷 손실이 발생하므로, 반드시 스토리지 전용 VLAN을 분리하거나 전용 10GbE/25GbE 격리망을 구축해야 함
- 소형 파일(Small File) 수백만 개는 NAS의 쥐약임 → 파일 1개를 읽을 때마다 메타데이터(inode, 권한, 수정일)를 조회하는 네트워크 RPC 왕복이 수십 번 발생하므로, 대규모 AI 데이터셋 학습 시 순수 NAS는 극심한 병목을 유발함

## 이웃 토픽과 구분
- NAS vs SAN: NAS = 파일 레벨(File-level), 표준 이더넷/IP, 저비용, 공용 문서/홈 디렉토리용 / SAN = 블록 레벨(Block-level), 전용 파이버 채널(FC), 고비용 초고속, 엔터프라이즈 DB/가상화용
