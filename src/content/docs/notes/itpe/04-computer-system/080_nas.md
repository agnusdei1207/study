## 연관 키워드

- NAS, Network-Attached Storage, 파일 수준 접근, NFS, SMB, 파일 잠금
- DAS, SAN, RAID, 스케일아웃, SPOF, RDMA, Kerberos

## Ⅰ. NAS의 개요

- 핵심 요약 : TCP/IP 이더넷에 연결되어 파일 수준 공유 서비스를 제공하는 독립형 파일 서버 스토리지.
- 개념 : 범용 이더넷 네트워크에 연결되어 이기종 클라이언트에 **파일 수준 접근** (File-Level Access)과 공유 공간을 제공하는 **네트워크 연결 스토리지** (NAS, Network-Attached Storage).
- 배경 및 필요성 : 서버 내장 디스크나 **직접 연결 스토리지** (DAS, Direct-Attached Storage)는 데이터가 장비별로 고립되어 부서 간 공유가 어려움. 문서·미디어 협업 수요가 커지면서 공유 기능을 갖춘 독립 장비로 저장을 중앙화할 필요가 생김.
- 주요 목적 : 표준 파일 공유 프로토콜로 이기종 운영체제 간 공유를 실현하고, 파일 단위 권한 관리와 저장 관리를 일원화하는 것.

## Ⅱ. NAS의 특징 및 장점

- 핵심 요약 : 서버 측 파일 시스템 해석과 파일 잠금의 결합으로 클라이언트 부담 없는 안전한 공유를 제공하는 구조.

1. 원격 파일 호출 : 경로·파일명 단위의 파일 수준 접근으로 요청하고 파일 시스템 해석은 컨트롤러가 전담 → 클라이언트 구현 부담 최소화.
2. 충돌 제어 : 다중 클라이언트의 동시 쓰기 충돌을 막는 **파일 잠금** (File Locking) → 공동 편집 데이터의 무결성 유지.
3. 이기종 프로토콜 지원 : 유닉스 계열의 **NFS** (Network File System)와 윈도우 계열의 **SMB** (Server Message Block) 동시 제공 → 운영체제에 관계없는 단일 저장소 활용.
4. 자체 데이터 보호 : 여러 디스크에 중복 기록하는 **RAID** (Redundant Array of Independent Disks)와 스냅샷 내장 → 디스크 장애 시 데이터 보존.

## Ⅲ. NAS의 구조 (흐름)

- 핵심 요약 : 파일 요청이 프로토콜 계층, 파일 시스템, 볼륨 관리를 거쳐 물리 디스크의 블록 입출력으로 변환되는 구조.
- 구성 요소 : NFS·SMB를 해석하는 프로토콜 데몬, 메타데이터와 잠금을 관리하는 파일 시스템 계층, RAID·스냅샷을 수행하는 볼륨 관리 계층.

```text
[ 파일 요청 처리 경로 ]

클라이언트 (유닉스: NFS / 윈도우: SMB)
        ↓ IP 네트워크 (이더넷)
NAS 컨트롤러 (프로토콜 해석)
        ↓
파일 시스템 (메타데이터·파일 잠금)
        ↓
볼륨 관리 (RAID·스냅샷)
        ↓ 블록 입출력
물리 디스크
```

```text
[ 파일 해석 위치의 차이 ]

NAS    : 컨트롤러가 파일 경로를 해석
블록형 : 호스트 서버가 파일을 해석
직결형 : 서버가 내장 디스크를 직접 접근
```

## Ⅳ. NAS와 SAN·DAS의 비교

- 핵심 요약 : 파일 시스템을 어디서 해석하느냐에 따라 NAS와 **스토리지 영역 네트워크** (SAN, Storage Area Network), DAS의 성능·공유 특성이 갈리는 구조.
- 선택 기준 : 공유 필요성, 지연 민감도, 업무의 파일·블록 단위 성격을 기준으로 방식을 고른다.

| 비교 항목 | NAS | SAN | DAS |
| :--- | :--- | :--- | :--- |
| 접근 수준 | 파일 수준 (NFS·SMB) | 블록 수준 | 블록 수준 |
| 연결 매체 | 범용 이더넷 (TCP/IP) | 파이버 채널(FC, Fibre Channel)·IP 블록 네트워크 | 호스트 내부 버스 |
| 파일 시스템 위치 | NAS 컨트롤러 내부 | 각 호스트 서버 내부 | 각 호스트 서버 내부 |
| 성능 특성 | 프로토콜 스택 지연 존재 | 저지연 고성능 입출력 | 단일 서버 기준 최소 지연 |
| 공유 기능 | 다수 클라이언트 동시 공유 | 공유 파일 시스템 구성 시 가능 | 단일 서버 전용 |
| 적합 업무 | 문서·미디어 협업, 콘텐츠 관리 | 대형 데이터베이스, 가상화 스토어 | 단일 서버의 로컬 저장 |

## Ⅴ. NAS의 한계와 방안

- 핵심 요약 : 컨트롤러 병목, TCP/IP 오버헤드, 인증·권한 체계의 취약성을 스케일아웃, 고속 전송, 통합 인증으로 일대일 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| 컨트롤러 병목과 **단일 장애점** (SPOF, Single Point of Failure) | 파일 수 증가에 따른 메타데이터 잠금 경합으로 처리량 급감, 컨트롤러 장애 시 전체 공유 중단 | 분산 메타데이터 구조의 **스케일아웃** (Scale-Out, 노드 추가로 용량·성능을 늘리는 확장 방식) NAS 도입, 컨트롤러 이중화 | 메타데이터 지연, 노드별 처리량 |
| TCP/IP 스택 오버헤드 | 커널 경유 패킷 처리가 CPU 부담과 지연을 늘려 대용량 전송 효율 저하 | **RDMA** (Remote Direct Memory Access) 기반 전송 적용, 병렬 분산 파일 시스템 도입 | 대용량 전송 처리량 |
| 인증·권한 체계의 취약성 | 클라이언트 신뢰 기반의 구형 인증은 사용자 식별 위조가 가능하고 OS별 권한 체계가 어긋남 | **Kerberos** (네트워크 인증 프로토콜) 기반 인증을 지원하는 최신 NFS 버전 전환, 디렉터리 서비스 연계 통합 인증 | 인증 방식 전환율, 권한 오류 건수 |

## Ⅵ. NAS에 대한 기술사적 제언

- 핵심 요약 : AI 데이터 진입점으로의 역할 확대, 저장 계층화 운영, 이관 절차의 단계화로 NAS 운영을 고도화.

1. AI 데이터 진입점 : 데이터 플랫폼 조직은 올플래시 스케일아웃 NAS의 학습·분석 데이터 진입 저장소 지정과 GPU 직접 스토리지 접근 연계로 입력 경로 단축.
2. 계층화 운영 : IT 운영 조직은 접근 빈도 기반 계층화 정책으로 활성 파일과 장기 보관 데이터의 자동 이동 체계 구축.
3. 단계적 이관 : 인프라 전환 조직은 파일 공유 장비 교체 시 파일럿 구간의 권한 매핑 검증 선행 후 단계적 이관 절차의 표준화.

## Ⅶ. 결론

- 핵심 요약 : NAS는 파일 수준 공유로 이기종 환경의 협업과 중앙 관리를 실현하는 스토리지 방식.
- 컨트롤러 구조와 네트워크 효율이 성능의 상한이므로 워크로드에 맞는 확장 구조 선택이 핵심 과제.
