## Ⅰ. NAS(Network-Attached Storage)의 개요

- **개념** : 표준 TCP/IP 이더넷(Ethernet) 네트워크를 기반으로 여러 이기종 클라이언트 시스템에 파일 수준(File-Level)의 데이터 입출력과 공유 스토리지를 제공하는 전용 파일 서버 스토리지 시스템.
- **배경 및 필요성** : 서버마다 스토리지가 종속되어 공유가 불가능하던 DAS(Direct-Attached Storage)의 데이터 고립(Silo) 문제를 해결하고, 부서 간 비정형 문서 및 미디어 파일의 중앙 집중식 협업 및 공유 요구 증대에 따라 널리 보급됨.
- **핵심 목적** : 표준 파일 공유 프로토콜(NFS, SMB/CIFS)을 통한 이기종 OS 간 파일 공유, 파일 단위 권한 제어(POSIX/ACL), 스토리지 관리 일원화를 통한 TCO 절감.

## Ⅱ. NAS의 핵심 아키텍처 및 I/O 동작 메커니즘

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ NAS (Network-Attached Storage) 계층 및 I/O 프로토콜 스택 ]           │
│                                                                        │
│   [ Linux/UNIX 클라이언트 ]              [ Windows 클라이언트 ]        │
│   - VFS (Virtual File System)            - Windows I/O Manager         │
│   - NFS Client Driver                    - SMB/CIFS Client Driver      │
│   └───────────────────┬──────────────────┴───────────────────┘         │
│                       │ IP Network (Ethernet, TCP/UDP)                 │
│                       ▼                                                │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ [ NAS 스토리지 컨트롤러 (Dedicated Appliance) ]                │   │
│   │  - 네트워크 계층: NIC / 10G/25G/100G 이더넷 인터페이스         │   │
│   │  - 프로토콜 데몬: NFS Server (v3/v4.1), SMB Server (v2/v3)    │   │
│   │  - 공유 파일 시스템: ZFS, WAFL, XFS (메타데이터 및 파일 락 제어)│   │
│   │  - 볼륨 관리 및 데이터 보호: 소프트웨어/하드웨어 RAID, 스냅샷  │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   │ 블록 I/O (SAS, SATA, NVMe)         │
│                                   ▼                                    │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ [ 물리적 스토리지 디스크 풀 (HDD / SSD / NVMe 드라이브) ]      │   │
│   └────────────────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────────────────┘
```

- **파일 수준 I/O 추상화** : 클라이언트는 블록 오프셋을 알 필요 없이 파일 경로(Pathname), 파일명, 바이트 오프셋(Read/Write) 단위의 RPC 명령어로 데이터를 요청하고, 파일 시스템 관리는 NAS 컨트롤러가 전담.
- **파일 락킹 및 동시성 제어** : NFS Network Lock Manager(NLM) 또는 SMB Opportunistic Locks(Oplocks)를 통해 다중 클라이언트 간의 동시 파일 쓰기 충돌을 방지하고 캐시 일관성 유지.

## Ⅲ. 엔터프라이즈 스토리지 아키텍처(NAS vs SAN vs DAS) 비교 분석

| 비교 항목 | NAS (Network-Attached Storage) | SAN (Storage Area Network) | DAS (Direct-Attached Storage) |
| :--- | :--- | :--- | :--- |
| **액세스 레벨** | **파일 레벨 (File-Level, NFS/SMB)** | **블록 레벨 (Block-Level, SCSI/NVMe)**| **블록 레벨 (Block-Level, PCIe/SAS)**|
| **네트워크 매체** | 범용 이더넷 (TCP/IP Network) | 전용 파이버 채널(FC) 또는 IP-SAN | 호스트 직접 연결 버스 (SAS/SATA/PCIe)|
| **전송 프로토콜** | NFS, SMB/CIFS | FCP, iSCSI, NVMe-oF | SAS, SATA, NVMe |
| **파일시스템 위치** | **NAS 스토리지 컨트롤러 내부** | **각 호스트 서버 내부** | **각 호스트 서버 내부** |
| **성능 및 지연** | 네트워크 프로토콜 스택으로 지연 존재 | 초저지연, 대규모 고성능 I/O 최적화 | 최고 속도, 단일 서버 초저지연 |
| **주요 적합 업무** | 비정형 문서 공유, 미디어 협업, CMS | 대규모 RDBMS, 가상화 데이터스토어 | 단일 고성능 DB, 백업 테이프, 로컬 캐시|

## Ⅳ. NAS의 주요 한계점 및 해결 방안

- **중앙 집중식 컨트롤러의 메타데이터 병목 및 단일 장애점(SPOF)** :
  - **한계점** : 단일/이중화 컨트롤러 기반 스케일업(Scale-Up) NAS는 수억 개의 파일 생성 시 메타데이터 갱신 락(Lock)으로 인해 I/O 급감.
  - **해결 방안** : 분산 메타데이터 서버를 탑재하고 노드 증설에 따라 선형 확장되는 스케일아웃 NAS(Dell Isilon, CephFS, GlusterFS) 도입.
- **TCP/IP 프로토콜 스택 오버헤드로 인한 고성능 AI/빅데이터 처리 한계** :
  - **한계점** : 대용량 AI 학습 데이터 로딩 시 커널 모드 스위칭과 패킷 복사 오버헤드로 인해 GPU I/O 기아 현상(I/O Starvation) 유발.
  - **해결 방안** : RDMA 기반의 NFS(NFS over RoCE / NFSoRDMA) 적용 및 병렬 파일 시스템(pNFS, Lustre, GPFS) 도입.
- **NFS v3의 약한 보안 및 이기종 간 권한 매핑 오류** :
  - **한계점** : IP 기반 인증에 의존하는 레거시 환경에서 UID/GID 위조 가능 및 Windows(ACL)-Linux(POSIX) 간 권한 불일치.
  - **해결 방안** : Kerberos 암호화 인증을 지원하는 NFS v4.1/v4.2 전면 전환 및 LDAP/Active Directory 통합 신원 관리 연계.

## Ⅴ. 현대 데이터 아키텍처 환경에서의 기술사적 제언

- **AI 및 비정형 데이터 처리를 위한 고성능 스케일아웃 NAS 전략** : 생성형 AI 학습 데이터셋이 페타바이트(PB) 단위로 증가함에 따라 올플래시(All-Flash NVMe) 스케일아웃 NAS를 데이터 레이크(Data Lake)의 엔트리 저장소로 채택하고, GPUDirect Storage(GDS) 연계를 통해 CPU 개입 없는 스토리지-GPU 직접 DMA 전송을 구현해야 함.
- **오브젝트 스토리지(S3)와의 하이브리드 연계** : 고성능 협업 및 트랜잭션 파일은 NAS에 상주시키고, 장기 보관용 콜드 데이터는 수명주기 관리 정책(ILM)을 통해 저비용 오브젝트 스토리지로 자동 티어링(Auto-Tiering)하는 데이터 수명주기 통합 거버넌스를 수립할 것을 제언함.
