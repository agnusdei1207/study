## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → NAS

## 30초 인출

- 본질: 서버마다 디스크를 따로 달면 다른 서버와 문서를 공유하기 어렵고 백업이 파편화됨
- 메커니즘: 표준 LAN 네트워크에 파일 공유 전용 컨트롤러를 물려 여러 이기종 서버가 동시에 디렉토리를 마운트하도록 지원

## 핵심 용어

- NFS(Network File System): 유닉스/리눅스 환경에서 네트워크를 통해 원격 호스트의 디렉토리를 로컬 파일 시스템처럼 마운트해 사용하는 분산 파일 프로토콜
- SMB/CIFS(Server Message Block): 윈도우 환경에서 파일, 프린터, 시리얼 포트 등을 공유하기 위해 사용하는 통신 프로토콜
- 스케일아웃 NAS(Scale-Out NAS): 단일 컨트롤러의 성능 한계를 극복하기 위해 여러 대의 NAS 노드를 클러스터로 묶어 단일 네임스페이스(Single Namespace)로 용량과 성능을 선형 확장하는 시스템

## 1교시 10점 답안

### Ⅰ. 정의·목적

- 정의: NAS은/는 표준 LAN 네트워크에 파일 공유 전용 컨트롤러를 물려 여러 이기종 서버가 동시에 디렉토리를 마운트하도록 지원 방식이다.
- 목적: 손쉬운 파일 공유 및 설치 편의성에 기여한다.

### Ⅱ. 핵심 구조와 작동

```text
[ NAS 파일 레벨 네트워크 스토리지 아키텍처 ]

[ Windows 클라이언트 ]     [ Linux / Unix 서버 ]     [ Mac 클라이언트 ]
         │                           │                        │
         v (SMB / CIFS 프로토콜)      v (NFS 프로토콜)         v (SMB 프로토콜)
+─────────────────────────────────────────────────────────────────────+
| 표준 이더넷 스위치 망 (Standard IP / Ethernet LAN Infrastructure)    |
+──────────────────────────────────┬──────────────────────────────────+
                                   │
                                   v (파일 레벨 요청: Read /data/file.txt)
+─────────────────────────────────────────────────────────────────────+
| NAS 스토리지 시스템 (Network Attached Storage Appliance)            |
|                                                                     |
|  [ 네트워크 인터페이스 (NIC) & 프로토콜 엔진 (NFS/SMB 데몬) ]       |
|                                                                     |
|  [ 파일 시스템 계층 (ZFS / Btrfs / Ext4 / WAFL) ]                   |
|   - 디렉토리 계층, 권한(ACL), 파일 잠금(Locking), 메타데이터 관리   |
|                                                                     |
|  [ 스토리지 컨트롤러 & RAID 볼륨 (SATA/SAS/NVMe SSD) ]              |
+─────────────────────────────────────────────────────────────────────+
```

### Ⅱ. 핵심 특성

- NAS는 '외장 하드가 아니라 파일 서버'임 → SAN처럼 블록(LBA)을 던져주는 것이 아니라, NAS 내부의 CPU와 OS가 직접 파일 시스템을 관리하고 클라이언트에게는 디렉토리와 파일 추상화만 보여줌
- 일반 LAN 망을 공유하면 재앙이 됨 → 대용량 파일 복사나 백업이 돌면 사내 ERP와 인터넷 웹서핑까지 패킷 손실이 발생하므로, 반드시 스토리지 전용 VLAN을 분리하거나 전용 10GbE/25GbE 격리망을 구축해야 함
- 소형 파일(Small File) 수백만 개는 NAS의 쥐약임 → 파일 1개를 읽을 때마다 메타데이터(inode, 권한, 수정일)를 조회하는 네트워크 RPC 왕복이 수십 번 발생하므로, 대규모 AI 데이터셋 학습 시 순수 NAS는 극심한 병목을 유발함

### Ⅲ. 관련 개념과 구분

- NAS vs SAN: NAS = 파일 레벨(File-level), 표준 이더넷/IP, 저비용, 공용 문서/홈 디렉토리용 / SAN = 블록 레벨(Block-level), 전용 파이버 채널(FC), 고비용 초고속, 엔터프라이즈 DB/가상화용

### Ⅳ. 적용 문제와 대응

- 사례: 122회 기출 및 AI 딥러닝 이미지 학습 서버에서 수천만 장의 소형 이미지 로딩 시 GPU 연산 유휴(Stall) 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 수천만 개 미세 이미지 파일 로딩 시 NAS 컨트롤러 CPU 점유율 100% | 파일 오픈/클로즈에 따른 메타데이터 RPC 왕복 지연 폭증 | 소형 파일들을 대용량 Tar/TFRecord/Parquet 단일 파일로 패키징 | 메타데이터 조회 횟수 99% 절감 및 순차 읽기 처리량 확보 |
| 사내 랜섬웨어 감염 시 NAS 공유 폴더 내 모든 백업 문서 동시 암호화 | 윈도우 공유 권한(쓰기 권한) 탈취로 네트워크 드라이브 오염 | NAS 볼륨 불변 스냅샷(Immutable Snapshot / WORM 기능) 적용 | 감염 시 1초 만에 랜섬웨어 침해 이전 시점으로 무손실 롤백 |
