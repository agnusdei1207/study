## 연관 키워드

- 컨테이너, 이미지, 레지스트리, 네임스페이스, cgroups, OCI, 오케스트레이션

## Ⅰ. 컨테이너의 개요

- 핵심 요약 : 컨테이너는 호스트 OS 커널을 공유하면서 프로세스·파일시스템·네트워크를 격리해 실행하는 경량 가상화 환경.
- 개념 : 컨테이너는 호스트 OS 커널을 공유하면서 프로세스·파일시스템·네트워크를 격리해 실행하는 경량 가상화 환경.
- 배경 및 필요성 : 애플리케이션과 의존성을 표준 이미지로 패키징해 개발·시험·운영 환경 차이를 줄일 필요.
- 주요 목적 : 이식 가능한 배포 단위와 자원효율적인 프로세스 격리 제공.

## Ⅱ. 컨테이너의 특징 및 장점

- 핵심 요약 : 이미지 계층: 불변 템플릿 재사용 → 빌드·배포 일관성; 커널 공유: VM보다 가벼운 격리 → 기동·자원 효율; 네임스페이스·cgroups: 프로세스·네트워크 분리와 자원제어 → 다중 워크로드 운영.

1. 이미지 계층: 불변 템플릿 재사용 → 빌드·배포 일관성
2. 커널 공유: VM보다 가벼운 격리 → 기동·자원 효율
3. 네임스페이스·cgroups: 프로세스·네트워크 분리와 자원제어 → 다중 워크로드 운영

## Ⅲ. 컨테이너의 구조 (흐름)

- 핵심 요약 : Dockerfile·빌드 정의 → 이미지 빌드·취약점 검사 → 서명·레지스트리 배포 → 런타임이 격리·자원한도 적용 → 오케스트레이터가 배치·복구.

```text
Dockerfile·빌드 정의
  ↓
이미지 빌드·취약점 검사
  ↓
서명·레지스트리 배포
  ↓
런타임이 격리·자원한도 적용
  ↓
오케스트레이터가 배치·복구
```

- 핵심 구성 : 소스·의존성 → 이미지 빌드·서명 → 레지스트리 → 런타임 격리 컨테이너

```text
소스·의존성 → 이미지 빌드·서명 → 레지스트리 → 런타임 격리 컨테이너
오케스트레이터 → 스케줄·재시작·확장
```

## Ⅳ. 비교: 컨테이너 / 가상머신(VM)

- 핵심 요약 : 격리 경계 기준 — 컨테이너: 프로세스·네임스페이스, 호스트 커널 공유; 가상머신(VM): 하이퍼바이저가 게스트 OS 격리.

| 비교 기준 | 컨테이너 | 가상머신(VM) |
| --- | --- | --- |
| 격리 경계 | 프로세스·네임스페이스, 호스트 커널 공유 | 하이퍼바이저가 게스트 OS 격리 |
| 자원·기동 | 상대적으로 가볍고 빠른 시작 | 게스트 OS 포함으로 상대적 오버헤드 |
| 커널 보안 | 호스트 커널 취약점 영향 가능 | 게스트 OS 경계가 추가되나 하이퍼바이저도 관리 필요 |

## Ⅴ. 컨테이너의 한계와 방안

- 핵심 요약 : 권한 과다·이미지 공급망 등의 위험을 원인에 맞게 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 권한 과다 | root·특권 컨테이너가 호스트 위험 확대 | 최소권한·rootless·seccomp·읽기전용 FS 적용 | 특권 컨테이너 비율 |
| 이미지 공급망 | 취약 라이브러리·악성 베이스 이미지 포함 | 신뢰 레지스트리·SBOM·서명·취약점 게이트 | 미조치 CVE |
| 상태 저장 혼동 | 컨테이너 재생성 시 로컬 데이터 손실 | 외부 영속볼륨·백업·복구시험 설계 | 복구 성공률 |

## Ⅵ. 컨테이너의 제언

- 핵심 요약 : 플랫폼팀은 최소권한 기본 이미지·서명된 레지스트리·자원한도 정책을 표준화하고 개발팀은 이미지 취약점과 런타임 권한을 배포 전에 검증.
- 실행 제안 : 플랫폼 운영팀은 이미지 생성부터 배포까지 SBOM·서명 검증을 자동화하고 특권 컨테이너 예외를 승인·만료 관리.

## Ⅶ. 컨테이너의 결론

- 핵심 요약 : 컨테이너는 OS 수준 격리·패키징 기술이지 VM과 동일한 커널 격리나 완전한 보안 경계를 자동 제공하지 않음.
- 시사점 : 이미지 불변성과 런타임 격리의 장점은 공급망·권한·저장소 운영을 함께 통제할 때 안전한 배포로 이어짐.
