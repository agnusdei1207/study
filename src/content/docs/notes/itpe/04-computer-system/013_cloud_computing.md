## 연관 키워드

- 클라우드 컴퓨팅(Cloud Computing), NIST(National Institute of Standards and Technology), 5대 필수 특성
- 주문형 셀프서비스(On-Demand Self-Service), 광대역 네트워크 접근(Broad Network Access), 자원 풀링(Resource Pooling), 신속한 탄력성(Rapid Elasticity), 측정 가능한 서비스(Measured Service)
- 서비스 모델(IaaS · PaaS · SaaS), 배포 모델(퍼블릭 · 프라이빗 · 하이브리드 · 커뮤니티), 공유 책임 모델(Shared Responsibility Model), 벤더 종속(Vendor Lock-in)

## Ⅰ. 클라우드 컴퓨팅의 개요

- 핵심 요약 : 컴퓨팅 자원을 네트워크로 주문형 제공받아 사용량만큼 지불하는 정보기술 이용 방식의 전환.
- 개념 : **클라우드 컴퓨팅** (Cloud Computing)은 구성 가능한 컴퓨팅 자원의 공유 풀에 대해 최소한의 관리 노력과 제공업체 개입으로 어디서나 주문형 네트워크 접근을 가능하게 하는 모델. 미국 국립표준기술원(NIST, National Institute of Standards and Technology)이 5대 필수 특성과 서비스·배포 모델로 정의함.
- 배경 및 필요성 : 온프레미스 인프라는 막대한 초기 투자인 자본 지출(CAPEX, Capital Expenditure)과 긴 조달 주기, 피크 대비 유휴 자원 낭비를 수반하므로 필요한 시점에 필요한 만큼 쓰는 자원 이용 방식이 요구됨.
- 주요 목적 : 자원의 신속한 탄력적 확보, 운영 지출(OPEX, Operating Expenditure) 중심의 재무 구조 전환, 서비스 출시 기간의 단축.

## Ⅱ. 클라우드 컴퓨팅의 특징 및 장점

- 핵심 요약 : NIST가 정의한 5대 필수 특성이 탄력성과 비용 투명성이라는 장점으로 연결되는 자원 이용 구조.

1. 주문형 셀프서비스 : 웹 콘솔과 API(Application Programming Interface)로 사람의 개입 없이 자원을 즉시 확보하는 **주문형 셀프서비스** (On-Demand Self-Service) → 조달 대기 시간의 제거.
2. 광대역 네트워크 접근 : 표준 네트워크로 이기종 단말에서 접근하는 **광대역 네트워크 접근** (Broad Network Access) → 장소·기기 제약 없는 이용.
3. 자원 풀링 : 다수 이용자가 물리 자원을 공유하고 논리적으로 격리하는 **자원 풀링** (Resource Pooling) → 설비 활용률의 향상.
4. 신속한 탄력성 : 수요에 따라 자원을 자동 확장·축소하는 **신속한 탄력성** (Rapid Elasticity) → 피크 대응과 유휴 비용 절감의 동시 확보.
5. 측정 가능한 서비스 : 사용량을 계측해 종량 과금하는 **측정 가능한 서비스** (Measured Service) → 비용 투명성의 확보.

## Ⅲ. 클라우드 컴퓨팅의 구조 (흐름)

- 핵심 요약 : 5대 필수 특성을 기반으로 서비스 모델 3종과 배포 모델 4종이 계층적으로 구성된 구조.

1. **서비스형 인프라** (IaaS, Infrastructure as a Service) : 가상 서버, 스토리지, 네트워크 자원을 제공.
2. **서비스형 플랫폼** (PaaS, Platform as a Service) : 애플리케이션 실행 런타임과 개발 도구 환경을 제공.
3. **서비스형 소프트웨어** (SaaS, Software as a Service) : 완성된 애플리케이션을 접속 형태로 제공.
4. 배포 모델 : 퍼블릭, 프라이빗, 하이브리드, 커뮤니티의 네 가지로 구분.

```text
[ 서비스 모델의 계층 구조 ]

IaaS (인프라 자원 제공)
   ↓ 운영체제 · 런타임 관리 이관
PaaS (실행 플랫폼 제공)
   ↓ 애플리케이션 운영 이관
SaaS (완성 소프트웨어 제공)
```

```text
[ 배포 모델 분류 ]

클라우드 배포 모델
   ├─ 퍼블릭 : 다수 이용자와 인프라 공유
   ├─ 프라이빗 : 단일 조직 전용 운영
   ├─ 하이브리드 : 퍼블릭과 프라이빗 연동
   └─ 커뮤니티 : 공동 목적 조직의 공유
```

## Ⅳ. 클라우드 컴퓨팅의 서비스 모델 비교

- 핵심 요약 : 상위 계층일수록 관리 편의가 커지는 대신 통제권과 커스터마이징 유연성이 줄어드는 상충 관계.

| 서비스 계층 | 고객 관리 범위 | 제공업체 관리 범위 | 적합 용도 |
| --- | --- | --- | --- |
| IaaS | 애플리케이션, 데이터, 런타임, 운영체제 | 가상화, 서버·스토리지·네트워크 하드웨어 | 기존 환경의 이전, 세부 제어 필요 시 |
| PaaS | 애플리케이션 코드, 데이터 | 런타임, 운영체제, 미들웨어, 하드웨어 | 개발 생산성 중심의 신규 개발 |
| SaaS | 사용 설정, 접근 권한, 입력 데이터 | 애플리케이션 전반과 하부 인프라 | 공통 업무 기능의 즉시 이용 |

- 선택 기준 : 세부 제어와 이관성이 중요하면 IaaS, 개발 속도가 중요하면 PaaS, 표준 업무 기능의 빠른 도입은 SaaS를 선택하고 데이터 위치 요건을 함께 검토하는 방식이 일반적.

## Ⅴ. 클라우드 컴퓨팅의 한계와 방안

- 핵심 요약 : 비용 관리 난이도, 책임 경계의 오인, 벤더 종속을 비용 거버넌스, 책임 매트릭스, 개방형 표준으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 비용 관리의 난이도 | 손쉬운 프로비저닝이 미사용 자원의 방치로 이어짐 | 자원 태깅 표준화, 예산 알림, 약정 할인과 온디맨드의 조합 | 미사용 자원 비율 |
| **공유 책임 모델** (Shared Responsibility Model)의 오인 | 제공업체가 전 보안을 담당한다는 오해 → 설정 미비로 인한 유출 | 계층별 책임 경계의 문서화, 보안 설정 점검의 자동화 | 설정 오류 건수 |
| **벤더 종속** (Vendor Lock-in) | 독자 형식의 서비스 의존 → 전환 비용 증가와 데이터 주권(Data Sovereignty) 제약 | 개방형 표준 기반 패키징, 데이터 위치 정책의 수립 | 이식 가능 워크로드 비율 |

## Ⅵ. 클라우드 컴퓨팅에 대한 기술사적 제언

- 핵심 요약 : 워크로드 적합성 평가, 비용 운영 조직, 인력 역량 체계를 축으로 도입 성숙도를 높이는 방향.

- 전사 아키텍처 조직은 워크로드별 클라우드 적합성 평가를 수행해 이관·유지·재설계 대상을 구분하는 단계적 전환 로드맵을 수립.
- 재무·운영 조직은 태깅·예산·할인 약정을 통합 관리하는 FinOps(클라우드 비용 운영 방법론) 기능을 상시 조직으로 운영.
- 인력 관리 조직은 개발자와 운영자를 대상으로 책임 경계와 비용 구조를 다루는 교육 체계를 정기 과정으로 편성.

## Ⅶ. 결론

- 핵심 요약 : 클라우드 컴퓨팅은 자원을 소유에서 주문형 이용으로 전환시킨 정보기술 패러다임.
- 비용·책임·이식성의 관리 체계가 갖춰질 때 민첩성과 효율의 가치가 실현됨.
