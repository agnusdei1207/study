## 지식 로드맵 내 현재 위치

지식 위치: 컴퓨터 시스템 → 컴퓨팅 자원 제공 모델 → **클라우드 컴퓨팅**

## 30초 인출

- 본질: **클라우드 컴퓨팅 (Cloud Computing)** 은 공유 컴퓨팅 자원을 네트워크로 주문형 제공하고 신속히 할당·회수하는 모델
- 메커니즘: 이용자 요청 → 공급자 자원 풀에서 할당 → 사용량 측정·관리
- 통찰: 네트워크를 통해 가상화된 IT 자원을 온디맨드로 신속하게 프로비저닝하고 사용량 기반으로 과금하는 공유 풀 컴퓨팅 모델임.

<details>
<summary>핵심 용어</summary>

- **온디맨드 셀프서비스** : 공급자 직원의 개별 개입 없이 이용자가 필요한 자원을 직접 요청하는 특성
- **자원 풀링** : 여러 이용자에게 물리·가상 자원을 공유 풀에서 동적으로 배분하는 특성
- **탄력성** : 수요에 맞춰 자원을 빠르게 늘리거나 줄일 수 있는 특성
- **NIST (National Institute of Standards and Technology)** : 미국의 측정·표준·기술 연구기관으로, SP 800-145에 클라우드 컴퓨팅 정의를 제시.
- **클라우드 컴퓨팅 (Cloud Computing)** : 공유 컴퓨팅 자원을 네트워크로 주문형 제공하고 신속히 할당·회수하는 모델.
- **IaaS (Infrastructure as a Service)** : 이용자가 운영체제와 애플리케이션을 관리하며 서버·스토리지·네트워크 자원을 제공받는 서비스 모델.
- **PaaS (Platform as a Service)** : 이용자가 애플리케이션을 배포하고 공급자가 실행 플랫폼을 관리하는 서비스 모델.
- **SaaS (Software as a Service)** : 공급자가 운영하는 애플리케이션을 네트워크를 통해 이용하는 서비스 모델.
- **공유 책임** : 서비스 모델과 계약에 따라 공급자와 이용자의 보안·운영 책임이 나뉘는 관계
- **API (Application Programming Interface)** : 소프트웨어 구성요소가 기능·데이터를 요청하고 응답하는 호출 규약.

</details>

## 2~4교시 25점 답안

## Ⅰ. 클라우드 컴퓨팅의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **클라우드 컴퓨팅 (Cloud Computing)** 은 공유 컴퓨팅 자원을 네트워크로 주문형 제공하고 신속히 할당·회수하는 모델 |
| 목적 | 수요 변화에 맞춘 자원 확보와 사용량 관리 |

## Ⅱ. 클라우드 컴퓨팅의 다섯 가지 특징

| 특성 | 의미 |
|---|---|
| 온디맨드 셀프서비스 | 이용자가 공급자 직원의 개별 개입 없이 자원을 요청 |
| 광범위한 네트워크 접근 | 표준 방식으로 여러 단말에서 서비스에 접근 |
| 자원 풀링 | 공유 자원을 여러 이용자에게 동적으로 배분 |
| 신속한 탄력성 | 수요에 맞춰 자원을 빠르게 확장·축소 |
| 측정 가능한 서비스 | 자원 사용량을 측정·관리·보고 |

## Ⅲ. 주문형 자원 제공과 계층별 책임 체계

```text
이용자 셀프서비스 → 네트워크 접근 → 공유 자원 풀
                                         │ 수요에 따른 탄력적 할당·회수
                                         ↓
                                   사용량 측정·보고
```

```text
업무가 직접 관리할 계층 결정
  ├─ OS·애플리케이션 운영 → IaaS
  ├─ 애플리케이션 배포 중심 → PaaS
  └─ 완성된 애플리케이션 이용 → SaaS
선택한 모델 → 계약·설정별 데이터·접근 책임 확인
```

## Ⅳ. 서비스·배포 모델 비교와 통제 관계

### 서비스 모델과 통제 범위

| 모델 | 이용자가 제어하는 범위 | 공급자가 제공하는 범위 |
|---|---|---|
| IaaS | 운영체제·스토리지·배포 애플리케이션 등 | 컴퓨팅·저장·네트워크 인프라 |
| PaaS | 배포한 애플리케이션과 일부 호스팅 설정 | 실행 플랫폼과 기반 인프라 |
| SaaS | 제한된 애플리케이션 설정 | 애플리케이션과 기반 인프라 |

공통 이용자 책임: 서비스 모델과 무관한 데이터 보호·접근권한의 계약 및 설정 관리.

### 배포 모델과 선택 기준

| 모델 | 구분 기준 | 선택 시 확인할 점 |
|---|---|---|
| 프라이빗 | 특정 조직 전용 | 운영 주체와 독점 사용 범위 |
| 커뮤니티 | 공동 관심사가 있는 조직 집단 전용 | 공동 정책과 운영 책임 |
| 퍼블릭 | 일반 이용자에게 개방 | 데이터·접근·규제 요건 |
| 하이브리드 | 둘 이상의 서로 다른 클라우드를 결합 | 데이터·애플리케이션의 이동·연계 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 자원 사용량을 파악하지 못해 비용이 늘어남 | 자원 소유자·용도 태그와 사용량 보고를 연결하고 유휴 자원을 회수 |
| 보안 책임을 공급자에게 모두 맡겼다고 오해함 | 서비스별 계약·관리 콘솔에서 공급자와 이용자의 통제 범위를 확인하고 접근권한을 점검 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
NIST 5-4-3 참조 모델에 따라 CSP와의 공유 책임 모델(Shared Responsibility Model)을 식별하고, 클라우드 자원 거버넌스 및 장애 복구(DR) 체계를 초기 단계부터 수립 필요.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ NIST 클라우드 컴퓨팅 5-4-3 참조 모델 구조 ]                          │
│                                                                        │
│ [ 5대 필수 특징 ]                                                      │
│  1. 주문형 셀프서비스   2. 광대역 네트워크 접근  3. 리소스 풀링        │
│  4. 신속한 탄력성       5. 측정 가능한 서비스(종량제)                  │
├────────────────────────────────────────────────────────────────────────┤
│ [ 4대 배포 모델 ]                                                      │
│  - 퍼블릭 (Public)    - 프라이빗 (Private)                             │
│  - 하이브리드 (Hybrid) - 커뮤니티 (Community)                          │
├────────────────────────────────────────────────────────────────────────┤
│ [ 3대 서비스 모델 및 공유 책임 모델 ]                                  │
│  - IaaS : 하드웨어/가상화는 CSP 책임, OS/미들웨어/앱은 고객 책임       │
│  - PaaS : 하드웨어/OS/런타임은 CSP 책임, 앱/데이터는 고객 책임        │
│  - SaaS : 인프라/플랫폼/앱 전 계층 CSP 관리, 계정/데이터만 고객 책임  │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 클라우드 서비스 모델 | 고객 관리 영역 | CSP 관리 영역 | 주요 고객 가치 | 대표 서비스 사례 |
|---|---|---|---|---|
| **IaaS (Infrastructure)** | OS, 미들웨어, 런타임, 앱, 데이터 | 서버 하드웨어, 스토리지, 네트워크, 가상화 | 최대의 인프라 제어권 | AWS EC2, Azure VM |
| **PaaS (Platform)** | 애플리케이션 코드, 비즈니스 데이터 | OS, 런타임, 웹서버, DB엔진, 하드웨어 | 개발 생산성 극대화 | Google App Engine, Heroku |
| **SaaS (Software)** | 사용자 계정 관리, 접근 권한, 데이터 | 소프트웨어 전 계층 (코드, DB, 인프라) | 설치 없는 즉시 업무 활용 | Microsoft 365, Salesforce |
