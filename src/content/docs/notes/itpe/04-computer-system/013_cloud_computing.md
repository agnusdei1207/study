## 지식 로드맵 내 현재 위치

지식 위치: 컴퓨터 시스템 → 컴퓨팅 자원 제공 모델 → **클라우드 컴퓨팅**

## 30초 인출

- 본질: **클라우드 컴퓨팅** 은 공유된 컴퓨팅 자원을 네트워크로 필요할 때 제공받고 사용량을 측정하는 방식이다.
- 메커니즘: 이용자가 자원을 직접 요청하면 공급자가 공유 자원 풀에서 빠르게 할당·회수하고 사용량을 계량한다.

<details>
<summary>핵심 용어</summary>

- **온디맨드 셀프서비스** : 공급자 직원의 개별 개입 없이 이용자가 필요한 자원을 직접 요청하는 특성
- **자원 풀링** : 여러 이용자에게 물리·가상 자원을 공유 풀에서 동적으로 배분하는 특성
- **탄력성** : 수요에 맞춰 자원을 빠르게 늘리거나 줄일 수 있는 특성
- **IaaS** : 이용자가 운영체제와 애플리케이션을 관리하며 서버·스토리지·네트워크 자원을 제공받는 모델
- **PaaS** : 이용자가 애플리케이션을 배포하고 공급자가 실행 플랫폼을 관리하는 모델
- **SaaS** : 공급자가 제공하는 애플리케이션을 이용자가 사용하는 모델
- **공유 책임** : 서비스 모델과 계약에 따라 공급자와 이용자의 보안·운영 책임이 나뉘는 관계

</details>

## 1교시 10점 답안

### Ⅰ. 정의·목적

- 정의: **클라우드 컴퓨팅** 은 공유된 컴퓨팅 자원을 네트워크에서 주문형으로 제공하고 빠르게 할당·회수하는 모델이다.
- 목적: 수요 변화에 맞춰 자원을 확보하고 이용량을 관리한다.

### Ⅱ. NIST의 다섯 가지 핵심 특성

| 핵심 특성 | 자원 제공 방식 |
|---|---|
| 온디맨드 셀프서비스 | 이용자가 직접 자원 요청 |
| 광범위한 네트워크 접근 | 여러 단말에서 네트워크로 접근 |
| 자원 풀링 | 공유 자원을 동적으로 배분 |
| 신속한 탄력성 | 수요에 따라 자원 확장·축소 |
| 측정 가능한 서비스 | 사용량을 계량·관리 |

### Ⅲ. 서비스 모델별 이용자 통제 범위

| 모델 | 공급자가 제공하는 범위 | 이용자가 관리하는 핵심 |
|---|---|---|
| IaaS | 컴퓨팅·저장·네트워크 자원 | 운영체제·애플리케이션 |
| PaaS | 애플리케이션 실행 플랫폼 | 배포한 애플리케이션 |
| SaaS | 사용 가능한 애플리케이션 | 이용 설정·데이터 사용 |

제언: 서비스 모델을 선택할 때 필요한 제어권과 보안 책임 범위를 함께 확인한다.

## 2~4교시 25점 답안

## Ⅰ. 클라우드 컴퓨팅의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 공유 자원을 네트워크에서 주문형으로 제공하고 빠르게 할당·회수하는 모델 |
| 목적 | 수요 변화에 따른 자원 확보와 사용량 관리 |

## Ⅱ. NIST의 다섯 가지 핵심 특성

| 특성 | 의미 |
|---|---|
| 온디맨드 셀프서비스 | 이용자가 공급자 직원의 개별 개입 없이 자원을 요청 |
| 광범위한 네트워크 접근 | 표준 방식으로 여러 단말에서 서비스에 접근 |
| 자원 풀링 | 공유 자원을 여러 이용자에게 동적으로 배분 |
| 신속한 탄력성 | 수요에 맞춰 자원을 빠르게 확장·축소 |
| 측정 가능한 서비스 | 자원 사용량을 측정·관리·보고 |

## Ⅲ. 서비스 모델과 통제 범위

| 모델 | 이용자가 제어하는 범위 | 공급자가 제공하는 범위 |
|---|---|---|
| IaaS | 운영체제·스토리지·배포 애플리케이션 등 | 컴퓨팅·저장·네트워크 인프라 |
| PaaS | 배포한 애플리케이션과 일부 호스팅 설정 | 실행 플랫폼과 기반 인프라 |
| SaaS | 제한된 애플리케이션 설정 | 애플리케이션과 기반 인프라 |

데이터 보호·접근권한 등은 어느 모델에서도 계약과 설정을 확인해야 한다. SaaS라고 해서 이용자 책임이 없어지는 것은 아니다.

## Ⅳ. 배포 모델과 선택 기준

| 모델 | 구분 기준 | 선택 시 확인할 점 |
|---|---|---|
| 프라이빗 | 특정 조직 전용 | 운영 주체와 독점 사용 범위 |
| 커뮤니티 | 공동 관심사가 있는 조직 집단 전용 | 공동 정책과 운영 책임 |
| 퍼블릭 | 일반 이용자에게 개방 | 데이터·접근·규제 요건 |
| 하이브리드 | 둘 이상의 서로 다른 클라우드를 결합 | 데이터·애플리케이션의 이동·연계 |

## Ⅴ. 운영상 문제와 해결 방안

| 문제 | 해결 방안 |
|---|---|
| 자원 사용량을 파악하지 못해 비용이 늘어남 | 자원 소유자·용도 태그와 사용량 보고를 연결하고 유휴 자원을 회수 |
| 보안 책임을 공급자에게 모두 맡겼다고 오해함 | 서비스별 계약·관리 콘솔에서 공급자와 이용자의 통제 범위를 확인하고 접근권한을 점검 |
