## 연관 키워드

- 클라우드 컴퓨팅(Cloud Computing), NIST(National Institute of Standards and Technology), 5대 필수 특성, 주문형 셀프서비스(On-Demand Self-Service)
- 서비스 모델(IaaS, PaaS, SaaS), 배포 모델(퍼블릭, 프라이빗, 하이브리드, 커뮤니티), 탄력성(Elasticity), 종량 과금
- 공유 책임 모델(Shared Responsibility Model), 벤더 종속(Vendor Lock-in), 최소 권한 원칙(PoLP), 클라우드 보안 태세 관리(CSPM), CAPEX, OPEX

## Ⅰ. 클라우드 컴퓨팅의 개요

- 핵심 요약 : **클라우드 컴퓨팅**은 정보기술(IT, Information Technology) 자원을 인터넷으로 주문형 제공받아 사용량만큼 지불하는 분산 컴퓨팅 방식.
- 개념 : 컴퓨팅, 스토리지, 데이터베이스, 네트워크, 소프트웨어 등 IT 자원을 자체 소유하지 않고 인터넷을 통해 주문형(On-Demand)으로 제공받아 사용량에 따라 비용을 지불하는 방식.
- 배경 및 필요성 : 온프레미스 인프라는 막대한 자본 지출(CAPEX, Capital Expenditure), 긴 조달 주기, 피크 대비 유휴 자원 낭비를 수반해 디지털 전환의 민첩성을 떨어뜨림.
- 주요 목적 : 자원의 신속한 탄력적 프로비저닝, 운영 지출(OPEX, Operating Expenditure) 중심의 재무 구조 전환, 글로벌 서비스의 빠른 배포.

## Ⅱ. 클라우드 컴퓨팅의 특징 및 장점

- 핵심 요약 : 미국 국립표준기술원(NIST, National Institute of Standards and Technology)이 정의한 5대 필수 특성이 탄력성과 측정 가능한 과금으로 이어져 IT 자원을 필요한 만큼 제공하는 구조.

1. **주문형 셀프서비스** (On-Demand Self-Service) : 웹 콘솔이나 API(Application Programming Interface)로 사람의 개입 없이 자원을 즉시 프로비저닝 → 조달 대기 시간 제거.
2. **광대역 네트워크 접근** (Broad Network Access) : 표준 네트워크를 통해 다양한 단말에서 접근 → 장소와 기기에 구애받지 않는 서비스 제공.
3. **자원 풀링** (Resource Pooling) : 멀티테넌트 방식으로 물리 자원을 공유하고 논리적으로 격리하여 동적으로 재할당 → 설비 활용률 향상.
4. **신속한 탄력성** (Rapid Elasticity) : 워크로드 변화에 맞춰 자원을 자동으로 확장하고 축소 → 피크 대응과 유휴 비용 절감을 동시에 확보.
5. **측정 가능한 서비스** (Measured Service) : 사용량을 계측해 종량 과금 → 사용한 만큼만 비용을 지불하여 비용 투명성 확보.

## Ⅲ. 클라우드 컴퓨팅의 구조 및 동작 메커니즘

- 핵심 요약 : 5대 필수 특성을 기반으로 3대 서비스 모델과 4대 배포 모델이 계층적으로 구성된 참조 아키텍처.
- **서비스 모델** (Service Models) : 서비스형 소프트웨어(SaaS, Software as a Service), 서비스형 플랫폼(PaaS, Platform as a Service), 서비스형 인프라(IaaS, Infrastructure as a Service)로 구분.
- **배포 모델** (Deployment Models) : 퍼블릭, 프라이빗, 하이브리드, 커뮤니티의 네 가지 형태로 구분.

```text
[ 서비스 모델 : 고객 관리 범위 축소 ]

IaaS (가상 서버·스토리지·네트워크)
   ↓ 운영체제와 런타임을 제공업체에 위임
PaaS (개발 런타임·데이터베이스 환경)
   ↓ 애플리케이션까지 위임
SaaS (완제품 소프트웨어, 웹 접속)
```

```text
[ 배포 모델 분류 ]

클라우드 배포 모델
   ├─ 퍼블릭 : 제공업체 인프라를 다수 고객이 공유
   ├─ 프라이빗 : 단일 조직 전용으로 운영
   ├─ 하이브리드 : 퍼블릭과 프라이빗을 연동
   ├─ 커뮤니티 : 공동 목적의 집단이 공유
```

## Ⅳ. 클라우드 컴퓨팅의 비교

- 핵심 요약 : 서비스 모델의 상위 계층일수록 관리 편의가 커지는 대신 통제권과 커스터마이징 유연성이 줄어드는 상충 관계.

| 서비스 계층 | 고객 관리 범위 | 제공업체 관리 범위 | 대표 예시 |
| --- | --- | --- | --- |
| IaaS | 애플리케이션, 데이터, 런타임, 미들웨어, 운영체제(OS, Operating System) | 가상화, 서버 하드웨어, 스토리지, 데이터센터 네트워크 | AWS EC2, Azure VM |
| PaaS | 애플리케이션 코드, 비즈니스 데이터 | 런타임 환경, 운영체제 패치, 미들웨어, 서버 하드웨어 | Heroku, Cloud Run |
| SaaS | 사용자 계정 접근 제어, 데이터 입력과 설정 | 애플리케이션 전체, 플랫폼, 인프라, 백업 | Google Workspace, Slack |
| 서버리스 (FaaS, Function as a Service) | 개별 함수 코드, 트리거 이벤트 매핑 | 가상 머신 인스턴스, 스케일링, 서버 전반 | AWS Lambda, Cloud Functions |

## Ⅴ. 클라우드 컴퓨팅의 한계와 방안

- 핵심 요약 : 비용 예측 실패, 공유 책임 모델의 오인, 벤더 종속과 데이터 주권 문제를 비용 관리 체계, 보안 태세 관리, 개방형 표준으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 비용 예측의 어려움 | 프로비저닝이 쉬워 미사용 자원이 방치되거나 과대 사양이 선택되어 온프레미스보다 비용이 초과 | 태깅 의무화, FinOps(Finance와 DevOps의 합성어, 클라우드 재무 운영) 체계, 약정 할인과 스팟 인스턴스 조합 | 미사용 자원 비율, 태그 준수율 |
| 공유 책임 모델(Shared Responsibility Model) 오인 | 제공업체가 모든 보안을 책임진다고 오인해 공개 저장소 노출과 과도한 권한으로 유출 발생 | 클라우드 보안 태세 관리(CSPM, Cloud Security Posture Management) 도입, 최소 권한 원칙(PoLP, Principle of Least Privilege) 적용, 파이프라인 내 보안 점검 자동화 | 공개 설정 자원 수, 과권한 계정 수 |
| 벤더 종속(Vendor Lock-in)과 데이터 주권(Data Sovereignty) | 독점 API와 데이터베이스 사용으로 전환이 어렵고, 국가 규제 요건을 위반할 위험 | 컨테이너 등 개방형 표준 기반 패키징, 데이터 위치를 통제하는 아키텍처 설계, 멀티클라우드 전략 검토 | 이식 가능 워크로드 비율, 규제 점검 결과 |

## Ⅵ. 클라우드 컴퓨팅의 적용 제언

- 핵심 요약 : 클라우드 네이티브 현대화, 단위 비용 관리, 가용 영역 기반 재해 복구를 기준으로 도입 범위를 정하는 방향.

- 기존 시스템을 그대로 옮기는 리프트 앤 시프트(Lift-and-Shift)보다, 컨테이너와 지속적 통합·배포(CI/CD, Continuous Integration/Continuous Delivery)를 전제로 구조를 바꾸는 클라우드 네이티브 현대화를 우선 검토하는 것이 장기 비용에 유리함.
- 비용은 총액보다 **단위 경제학** (Unit Economics) 지표, 즉 거래 한 건이나 사용자 한 명당 비용으로 관리해야 사업 성장과 비용의 관계를 판단할 수 있음.
- 재해 복구는 가용 영역(AZ, Availability Zone) 간 다중 구성을 기본으로 하고, 미션 크리티컬 워크로드에만 리전 간 액티브-액티브 구성을 적용하는 것이 비용 대비 효과가 큼.

## Ⅶ. 결론

- 핵심 요약 : 클라우드 컴퓨팅은 주문형으로 탄력 제공되는 IT 자원을 사용량 기반으로 이용하여 민첩성과 재무 유연성을 얻는 방식.
- 비용, 보안 책임, 벤더 종속의 세 리스크를 하나의 관리 체계로 묶어 다룰 때 이 가치가 유지됨.
