## 연관 키워드
- 클라우드 컴퓨팅, IaaS, PaaS, SaaS, 가상화, 온디맨드 자원

## Ⅰ. 클라우드 컴퓨팅의 개요
- 핵심 요약 : 클라우드 컴퓨팅은 네트워크를 통해 공유 컴퓨팅 자원을 필요에 따라 신속하게 제공·회수하는 서비스 모델.
- 개념 : **클라우드 컴퓨팅**(Cloud Computing)은 공용 네트워크로 구성 가능한 자원 풀에 편리한 온디맨드 접근을 제공하는 모델.
- 배경 및 필요성 : 자체 설비의 선투자·용량 증설 시간·운영 부담 완화 필요.
- 목적 : 탄력적 자원 공급과 서비스 제공 속도 향상.

## Ⅱ. 핵심 특성
- 핵심 요약 : 자원 풀·탄력성·측정 서비스가 사용량 중심 운영을 가능하게 함.
- 온디맨드 셀프서비스 : 사용자 요청에 따라 자원 프로비저닝.
- 광범위 네트워크 접근 : 표준 네트워크를 통해 단말에서 사용.
- 자원 풀링·탄력성 : 다중 사용자 수요에 따라 자원 할당·회수.
- 측정 서비스 : 사용량 관측과 과금 근거 제공.

## Ⅲ. 서비스 모델 흐름
- 핵심 요약 : 사업자는 인프라부터 애플리케이션까지 계층별로 관리 책임을 제공.
```text
물리 자원·가상화
  ↓
IaaS: VM·네트워크·저장소
  ↓
PaaS: 런타임·개발 플랫폼
  ↓
SaaS: 완성 애플리케이션
```
```text
요청 → 자원 할당 → 사용량 측정
                  ↓
              확장·회수
```

## Ⅳ. 서비스 모델 비교
- 핵심 요약 : 상위 서비스 모델일수록 제공자 관리 범위가 넓고 고객 제어 범위가 줄어듦.
| 비교 축 | IaaS | PaaS | SaaS |
| --- | --- | --- | --- |
| 고객 관리 | OS·앱·데이터 | 앱·데이터 | 설정·데이터 사용 |
| 제공자 관리 | 가상화·하드웨어 | 런타임 포함 | 애플리케이션 포함 |
| 적합 | 인프라 제어 필요 | 앱 개발 집중 | 완성 기능 사용 |

## Ⅴ. 한계와 방안
- 핵심 요약 : 비용 가시성·보안 책임·종속성은 계약과 아키텍처로 관리.
| 한계 | 원인·영향 | 대응 |
| --- | --- | --- |
| 비용 급증 | 자동 확장·유휴 자원 | 예산·태그·이상 사용 경보 |
| 책임 혼동 | 공유 책임 모델 | 계층별 책임표·통제 점검 |
| 공급자 종속 | 고유 API·데이터 포맷 | 이식 비용 평가·표준 인터페이스 |
| 데이터 규제 | 저장 지역·접근 통제 | 데이터 분류·지역 배치 정책 |

## Ⅵ. 도입 제언
- 핵심 요약 : 조직은 애플리케이션 요구·데이터 민감도·비용 모델을 기준으로 서비스 모델과 배치 형태를 선택.
- 보안·재해복구·비용 최적화를 함께 설계하고 실제 복구와 사용량을 지속 검토.

## Ⅶ. 결론
- 핵심 요약 : 클라우드는 자원을 서비스화해 신속하고 탄력적으로 제공하는 컴퓨팅 운영 모델.
- 기술 도입보다 책임 공유와 경제성·거버넌스가 성과를 좌우.
