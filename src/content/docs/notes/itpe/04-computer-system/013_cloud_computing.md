## 지식 로드맵 내 현재 위치

지식 위치: 컴퓨터 시스템 → 컴퓨팅 자원 제공 모델 → **클라우드 컴퓨팅**

## 30초 인출

- 본질: **클라우드 컴퓨팅 (Cloud Computing)** 은 공유 컴퓨팅 자원을 네트워크로 주문형 제공하고 신속히 할당·회수하는 모델
- 메커니즘: 이용자 요청 → 공급자 자원 풀에서 할당 → 사용량 측정·관리

<details>
<summary>핵심 용어</summary>

- **온디맨드 셀프서비스** : 공급자 직원의 개별 개입 없이 이용자가 필요한 자원을 직접 요청하는 특성
- **자원 풀링** : 여러 이용자에게 물리·가상 자원을 공유 풀에서 동적으로 배분하는 특성
- **탄력성** : 수요에 맞춰 자원을 빠르게 늘리거나 줄일 수 있는 특성
- **NIST (National Institute of Standards and Technology)** : 미국의 측정·표준·기술 연구기관으로, SP 800-145에 클라우드 컴퓨팅 정의를 제시.
- **클라우드 컴퓨팅 (Cloud Computing)** : 공유 컴퓨팅 자원을 네트워크로 주문형 제공하고 신속히 할당·회수하는 모델.
- **IaaS (Infrastructure as a Service)** : 이용자가 운영체제와 애플리케이션을 관리하며 서버·스토리지·네트워크 자원을 제공받는 서비스 모델.
- **PaaS (Platform as a Service)** : 이용자가 애플리케이션을 배포하고 공급자가 실행 플랫폼을 관리하는 서비스 모델.
- **SaaS (Software as a Service)** : 공급자가 운영하는 애플리케이션을 네트워크를 통해 이용하는 서비스 모델.
- **공유 책임** : 서비스 모델과 계약에 따라 공급자와 이용자의 보안·운영 책임이 나뉘는 관계
- **API (Application Programming Interface)** : 소프트웨어 구성요소가 기능·데이터를 요청하고 응답하는 호출 규약.

| 특성 | 의미 |
|---|---|
| 온디맨드 셀프서비스 | 이용자가 공급자 직원의 개별 개입 없이 자원을 요청 |

## Ⅲ. 서비스 모델과 통제 범위

| 모델 | 이용자가 제어하는 범위 | 공급자가 제공하는 범위 |
|---|---|---|
| IaaS | 운영체제·스토리지·배포 애플리케이션 등 | 컴퓨팅·저장·네트워크 인프라 |
| PaaS | 배포한 애플리케이션과 일부 호스팅 설정 | 실행 플랫폼과 기반 인프라 |
| SaaS | 제한된 애플리케이션 설정 | 애플리케이션과 기반 인프라 |

공통 이용자 책임: 서비스 모델과 무관한 데이터 보호·접근권한의 계약 및 설정 관리.

## Ⅳ. 배포 모델과 선택 기준

| 모델 | 구분 기준 | 선택 시 확인할 점 |

| 커뮤니티 | 공동 관심사가 있는 조직 집단 전용 | 공동 정책과 운영 책임 |

## Ⅴ. 운영 한계와 대응

| 한계 | 대응 |
|---|---|
| 자원 사용량을 파악하지 못해 비용이 늘어남 | 자원 소유자·용도 태그와 사용량 보고를 연결하고 유휴 자원을 회수 |
| 보안 책임을 공급자에게 모두 맡겼다고 오해함 | 서비스별 계약·관리 콘솔에서 공급자와 이용자의 통제 범위를 확인하고 접근권한을 점검 |

| 한계 | 해결 방안 |
|---|---|
