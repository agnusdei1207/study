## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 클라우드 컴퓨팅

## 30초 인출

- 본질: 서버 조달에 수 주~수 개월이 소요되는 물리 인프라 구축의 경직성과 막대한 초기 자본 투자(CapEx)
- 메커니즘: 인터넷 기반의 대규모 가상화 풀에서 컴퓨팅·스토리지·네트워크를 주문형(On-demand)으로 즉시 할당받고 사용량만큼만 지불(OpEx)

## 핵심 용어

- 주문형 셀프서비스(On-demand Self-service): 사용자가 CSP 담당자와의 인적 상호작용 없이 웹 콘솔이나 API를 통해 필요할 때 서버·스토리지 자원을 즉시 프로비저닝하는 특성
- 공유 책임 모델(Shared Responsibility Model): 클라우드 보안에 있어 물리 보안과 인프라는 CSP가 책임지고, 게스트 OS, 데이터, 애플리케이션 보안은 고객이 분담하는 보안 책임 체계

### Ⅱ. 핵심 특성

- 클라우드의 본질은 '남의 컴퓨터를 빌려 쓰는 것'이 아니라 '인프라를 코드로 다루는 소프트웨어적 민첩성(Agility)'에 있음 → 레거시 서버를 그대로 클라우드 VM으로 옮기는 단순 Lift-and-Shift는 비용만 30% 이상 증가
- 클라우드 전환 후 기업이 겪는 가장 큰 위기는 '비용 충격'임 → 개발자가 리소스를 클릭 한 번으로 무제한 띄울 수 있어 방치된 유휴 자원으로 인한 월말 요금 폭탄이 일상화되므로 FinOps 조직과 자동 태깅 거버넌스가 필수
- 보안 사고의 95% 이상은 CSP 결함이 아닌 '고객의 잘못된 설정(Misconfiguration)'에서 발생함 → 공개된 S3 버킷, 루트 계정 키 유출 등 고객 책임 영역에 대한 지속적 보안 감시(CSPM) 필요

### Ⅲ. 관련 개념과 구분

- IaaS vs PaaS: IaaS = OS와 네트워크를 직접 제어하는 가상 인프라 / PaaS = 개발자가 코드와 데이터만 올리면 실행 환경 전체를 플랫폼이 알아서 관리

### Ⅳ. 적용 문제와 대응

- 사례: 139회 기출 클라우드 컴퓨팅 도입 후 인프라 비용 폭증 및 고객 데이터 유출 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 개발/테스트용 고성능 GPU 및 VM 미반납으로 월 클라우드 비용 2배 급증 | 자원 소유권 불투명 및 유휴 자원 자동 회수 체계 부재 | FinOps 도입, 필수 태그 정책 강제 및 야간/주말 미사용 인스턴스 자동 셧다운 스크립트 적용 | 클라우드 낭비 비용 30% 이상 즉각 절감 |
| 클라우드 관리자 API 키가 깃허브 공개 저장소에 유출되어 계정 피탈 | 코드 내 하드코딩된 자격증명 및 다중인증(MFA) 미적용 | 비밀키 관리 솔루션(Vault) 연동, IAM Role 기반 임시 토큰 사용, Git 시크릿 스캐닝 강제 | 자격증명 노출 원천 차단 |
