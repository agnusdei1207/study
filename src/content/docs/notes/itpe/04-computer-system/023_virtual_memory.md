## 연관 키워드

- 가상 메모리(Virtual Memory), 가상 주소 공간, MMU, 페이지 테이블, TLB
- 페이징(Paging), 세그멘테이션(Segmentation), 요구 페이징(Demand Paging), 페이지 폴트(Page Fault)
- 지역성(Locality), 스래싱(Thrashing), 워킹 셋(Working Set), 대용량 페이지(Huge Page)
- EPT, KPTI, ASLR, CXL 메모리 풀

## Ⅰ. 가상 메모리의 개요

- 핵심 요약 : 물리 메모리를 추상화해 프로세스마다 독립적인 대형 주소 공간을 제공하는 운영체제 기법.
- 개념 : 각 프로세스에 물리 메모리와 분리된 연속적 **가상 주소 공간** (Virtual Address Space)을 부여하고, 실행 시점에 물리 주소로 변환해 사용하게 하는 운영체제의 **가상 메모리** (Virtual Memory) 기법.
- 배경 및 필요성 : 물리 메모리 용량을 초과하는 프로그램 실행 불가 문제와, 다중 프로세스의 메모리 영역 침범·재배치 문제를 주소 계층의 분리로 해결할 필요가 발생한 배경.
- 주요 목적 : 프로세스 간 메모리 격리와 보호, 물리 용량 한계의 극복, 필요 시점 적재에 따른 메모리 이용 효율 향상.

## Ⅱ. 가상 메모리의 특징 및 장점

- 핵심 요약 : 주소 변환 하드웨어, 변환 캐시, 요구 적재가 격리성과 효율을 동시에 제공하는 구조.

1. **MMU** (Memory Management Unit, 메모리 관리 장치) : CPU의 가상 주소를 **페이지 테이블** (Page Table, 가상·물리 페이지의 대응표)로 물리 주소에 매핑 → 프로그램이 물리 배치와 무관하게 컴파일·실행되는 효과.
2. **TLB** (Translation Lookaside Buffer, 변환 캐시) : 최근 변환 결과를 고속 저장소에 보관 → 페이지 테이블 반복 참조 지연의 대폭 절감.
3. **요구 페이징** (Demand Paging) : 실행에 필요한 페이지만 물리 메모리에 적재 → 프로그램 시작 시간 단축과 메모리 점유 축소.
4. **지역성** (Locality, 접근 집중 경향) : 시간적·공간적 지역성에 따른 필요 페이지 예측 → 작은 물리 메모리로 큰 주소 공간 운영.
5. 보호와 공유 : 페이지별 접근 권한 비트 부여와 동일 라이브러리 페이지의 프로세스 간 공유 → 메모리 보호 강화와 물리 프레임 절약.

## Ⅲ. 가상 메모리의 구조 (흐름)

- 핵심 요약 : TLB 적중 여부에 따라 변환 경로가 갈리고, 부재 시 계층적 처리로 이어지는 흐름.
- **페이지 폴트** (Page Fault, 미적재 페이지 접근 시의 예외) : 디스크 적재를 수반하는 인터럽트로, 발생 빈도가 성능의 핵심 변수.
- 가상 페이지 번호(VPN, Virtual Page Number)와 물리 프레임 번호의 대응 관계가 변환의 기본 단위.

```text
[ 주소 변환 경로 ]

가상 주소 발행 (페이지 번호 + 변위값)
        ↓
TLB 조회
        ↓
적중 → 물리 프레임 번호 획득
        ↓
미적중 → 페이지 테이블 단계 순회
        ↓
물리 주소 조합 후 메모리 접근
```

```text
[ 페이지 폴트 처리 흐름 ]

접근 대상 페이지의 미적재 확인
        ↓
운영체제로의 폴트 트랩 전달
        ↓
스왑 영역에서 대상 페이지 탐색
        ↓
빈 프레임 적재 후 테이블 갱신
        ↓
중단된 명령 재실행
```

## Ⅳ. 페이징과 세그멘테이션의 비교

- 핵심 요약 : 고정 단위의 **페이징** (Paging)과 논리 단위의 **세그멘테이션** (Segmentation)이 단편화·보호 관점에서 절충 관계를 이루는 구조.

| 비교 항목 | 페이징 | 세그멘테이션 |
| --- | --- | --- |
| 분할 단위 | 고정 크기 페이지 | 함수·배열 같은 논리 단위 |
| 주소 구조 | 페이지 번호 + 변위값 | 세그먼트 번호 + 변위값 |
| 단편화 | 내부 단편화 발생 | 외부 단편화 발생 |
| 공유·보호 | 페이지 단위 권한 관리 | 논리 모듈 단위 공유 용이 |
| 현대 채택 | 대부분 시스템의 기본 방식 | 순수 형태는 쇠퇴, 혼합형 존재 |

- 선택 기준 : 할당 관리의 단순성과 교체 효율에는 페이징이, 논리 구조 기반 보호에는 세그멘테이션이 유리한 판단 축.
- 현대 시스템은 페이징을 근간으로 하되, TLB 커버리지 확대를 위해 일반 페이지보다 큰 **대용량 페이지** (Huge Page)를 병용하는 구성이 보편적.

## Ⅴ. 가상 메모리의 한계와 방안

- 핵심 요약 : 스래싱, 변환 지연, 가상화 중첩 비용을 워킹 셋 관리, 대형 페이지, 하드웨어 지원으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **스래싱** (Thrashing, 페이지 교체 I/O에 처리가 잠식되는 상태) | 프로세스 메모리가 **워킹 셋** (Working Set, 자주 참조되는 페이지 집합) 미만으로 축소 → 부재 급증 | 워킹 셋 기반 다중 프로그래밍도 조절, 압축 스왑 기법(zRAM 등) 운영 | 페이지 폴트 빈도 |
| 다단계 테이블 변환 지연 | 64비트 공간의 다층 테이블 순회 비용 누적 | 대용량 페이지로 TLB 커버리지 확대 | TLB 미스율 |
| 가상화의 2단 변환 | 게스트·호스트 주소의 중첩 변환 부하 | Intel EPT(Extended Page Table), AMD NPT(Nested Page Table) 지원 활성화 | VM 메모리 지연 |

## Ⅵ. 가상 메모리에 대한 기술사적 제언

- 핵심 요약 : 페이지 크기 튜닝, 메모리 계층 확장, 커널 보안 설정 점검을 공통 운영 기준으로 정비하는 방향.
- 데이터베이스 운영 조직은 대용량 페이지를 사전 고정 할당하고, 투명 대용량 페이지(THP, Transparent Huge Pages)의 지연 영향을 실측해 설정 기준을 문서화하는 절차 운영 필요.
- 플랫폼 조직은 CXL(Compute Express Link) 기반 메모리 풀을 가상 메모리 계층의 하위 티어로 편입하는 용량 확장 로드맵 검토 필요.
- 보안 조직은 커널 페이지 테이블 격리인 KPTI(Kernel Page Table Isolation)와 주소 배치 무작위화인 ASLR(Address Space Layout Randomization)의 적용 상태를 상시 점검 체계로 관리 필요.

## Ⅶ. 결론

- 핵심 요약 : 가상 메모리는 격리·보호·용량 확장을 동시에 제공하는 운영체제의 핵심 추상화 계층.
- 변환 캐시 적중률과 부재 빈도가 체감 성능을 결정하므로, 주소 체계와 용량 계획의 통합 관리가 유지 조건.
