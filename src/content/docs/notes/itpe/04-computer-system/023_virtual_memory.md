## 연관 키워드
- 가상 메모리, 페이지, 페이지 테이블, TLB, 페이지 폴트, 스와핑

## Ⅰ. 가상 메모리의 개요
- 핵심 요약 : 가상 메모리는 각 프로세스에 독립 주소 공간을 제공하고 가상 주소를 물리 메모리로 변환하는 메모리 관리 기법.
- 개념 : **가상 메모리**(Virtual Memory)는 주소 변환과 페이지 매핑으로 프로세스 메모리를 물리 RAM 및 보조 저장소와 분리.
- 배경 및 필요성 : 물리 메모리보다 큰 주소 공간, 프로세스 격리, 제한된 RAM의 효율적 사용 요구.
- 목적 : 메모리 추상화와 보호, 필요한 페이지의 온디맨드 적재.

## Ⅱ. 구조와 장점
- 핵심 요약 : 페이지 테이블·TLB·페이지 폴트 처리로 주소 공간과 물리 프레임을 관리.
- 가상 주소 공간은 페이지, RAM은 프레임으로 분할.
- 페이지 테이블은 가상 페이지와 프레임·권한 매핑 유지.
- TLB(Translation Lookaside Buffer)는 최근 변환 캐시 → 주소 변환 지연 감소.
- 요구 페이징은 참조된 페이지를 필요 시 적재 → 초기 로딩량 감소.

## Ⅲ. 주소 변환 및 폴트 흐름
- 핵심 요약 : 주소 변환 캐시 미스 시 테이블을 확인하고 미적재 페이지는 운영체제가 적재.
```text
가상 주소
  ↓ TLB 검색
페이지 테이블 확인
  ↓ 매핑 유효
물리 주소 → 메모리 접근
```
```text
페이지 폴트
  ↓ 접근권한 검사
빈 프레임 확보·필요 시 교체
  ↓ 디스크에서 페이지 적재
테이블 갱신·명령 재실행
```

## Ⅳ. 페이지 관리 비교
- 핵심 요약 : 페이지 교체 정책과 스와핑은 메모리 압박과 접근 지역성에 따라 성능 영향.
| 기법 | 기준 | 장점·주의 |
| --- | --- | --- |
| FIFO | 가장 먼저 적재 | 단순·Belady 이상 가능 |
| LRU | 가장 오래 미사용 | 지역성 반영·정확 구현 비용 |
| Clock | 참조 비트 순환 | LRU 근사·낮은 비용 |
| 스와핑 | 페이지를 저장장치로 이동 | RAM 확보·큰 지연 |

## Ⅴ. 한계와 방안
- 핵심 요약 : 페이지 폴트 폭증과 TLB 미스, 스와핑은 처리량을 급격히 낮출 수 있음.
| 한계 | 원인·영향 | 대응 |
| --- | --- | --- |
| Thrashing | working set이 RAM 초과 | 동시 실행·메모리 압력 조절 |
| TLB 미스 | 주소 변환 반복 | 지역성 개선·페이지 크기 검토 |
| 페이지 폴트 | 잘못된 접근·미적재 | 접근 패턴·권한 원인 진단 |
| 스와핑 지연 | 느린 보조 저장소 | 메모리 증설·작업 집약도 조정 |

## Ⅵ. 운영 제언
- 핵심 요약 : 운영체제·플랫폼 담당자는 RSS, major faults, swap, TLB 및 working set을 함께 관측.
- 지연 민감 시스템은 스왑 의존을 피하고 메모리 상한과 OOM 정책을 명확히 설정.

## Ⅶ. 결론
- 핵심 요약 : 가상 메모리는 주소 공간 추상화와 격리, 물리 메모리 관리의 기반.
- 주소 변환 캐시와 페이지 적재 정책이 실제 성능을 좌우.
