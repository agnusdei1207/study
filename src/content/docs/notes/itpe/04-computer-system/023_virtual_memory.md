## 연관 키워드

- 가상 메모리(Virtual Memory), 가상 주소 공간, MMU, TLB, 페이지 테이블, 요구 페이징(Demand Paging)
- 페이지 부재(Page Fault), 페이징, 세그멘테이션, 스래싱(Thrashing), 워킹 셋(Working Set)
- 대용량 페이지(Huge Page), EPT, NPT, CXL, KPTI, ASLR

## Ⅰ. 가상 메모리(Virtual Memory)의 개요

- 핵심 요약 : 보조기억장치를 주소 공간으로 확장해 프로세스마다 독립적인 대용량 논리 주소 공간을 제공하는 OS 메모리 관리 기법.
- 개념 : 물리 메인 메모리(DRAM, Dynamic Random-Access Memory)의 용량 한계를 넘고 다중 프로그래밍의 메모리 보호를 위해, 보조기억장치를 확장 공간으로 삼아 각 프로세스에 독립적이고 연속적인 **가상 주소 공간** (Virtual Address Space)을 제공하는 운영체제의 **가상 메모리** (Virtual Memory) 기법.
- 배경 및 필요성 : 물리 메모리보다 큰 프로그램을 실행할 수 없던 초기 제약과, 여러 프로세스가 물리 메모리를 직접 공유하면서 생긴 메모리 침범과 **재배치** (Relocation, 프로그램 주소의 물리 위치 변환) 문제 때문에 주소 체계를 분리하는 계층이 요구됨.
- 핵심 목적 : 물리 메모리 크기 제약 극복, 프로세스 간 메모리 격리와 보호, 요구 페이징을 통한 메모리 적재 효율 향상.

## Ⅱ. 가상 메모리(Virtual Memory)의 특징 및 장점

- 핵심 요약 : MMU 주소 변환, TLB 캐싱, 요구 페이징이 결합되어 대용량 격리와 메모리 효율을 동시에 확보하는 구조.

1. **MMU** (Memory Management Unit, 메모리 관리 장치) : CPU가 낸 가상 주소를 페이지 테이블로 물리 주소에 매핑하는 하드웨어 → 프로그램이 물리 배치를 알 필요 없이 실행됨.
2. **TLB** (Translation Lookaside Buffer, 주소 변환 캐시) : 최근 쓰인 가상-물리 매핑을 고속 캐시에 보관 → 페이지 테이블을 반복 참조하는 지연을 줄임.
3. **요구 페이징** (Demand Paging) : 실행 중 실제로 참조되는 페이지만 물리 메모리에 적재 → 메모리 사용량과 프로그램 시작 지연 감소.
4. **페이지 부재** (Page Fault, 유효 비트 0일 때 발생하는 인터럽트) : 요청 페이지가 메모리에 없으면 OS가 스왑 영역에서 빈 프레임으로 적재하고 테이블을 갱신 → 필요한 페이지만 불러오는 처리 흐름.

## Ⅲ. 가상 메모리(Virtual Memory)의 구조 및 동작 메커니즘

- 핵심 요약 : 가상 페이지 번호가 TLB와 페이지 테이블을 거쳐 물리 프레임 번호로 바뀌고, 부재가 있을 때만 스왑 영역에서 DRAM으로 적재되는 흐름.
- 가상 페이지 번호(VPN, Virtual Page Number)와 물리 프레임 번호(PFN, Physical Frame Number)의 변환이 핵심이며, TLB 적중 여부에 따라 변환 경로가 갈림.

```text
[ 주소 변환 흐름 ]

가상 주소 (VPN + 오프셋)
        ↓
TLB 조회
        ↓ 적중 시 PFN 즉시 반환
        ↓ 실패 시 페이지 테이블 워크
유효 비트 1 → PFN 반환
유효 비트 0 → 페이지 부재 인터럽트
        ↓
물리 주소 (PFN + 오프셋) → DRAM 접근
```

```text
[ 페이지 부재 처리 ]

유효 비트 0 (페이지 부재)
        ↓
OS 커널 인터럽트 처리
        ↓
스왑 영역에서 빈 프레임으로 적재
        ↓
페이지 테이블 갱신 후 명령 재실행
```

## Ⅳ. 가상 메모리(Virtual Memory)의 비교

- 핵심 요약 : 페이징, 세그멘테이션, 두 방식의 혼합이 분할 단위와 단편화, 주소 구조에서 서로 다른 절충점을 가지는 구조.

| 비교 항목 | 페이징 (Paging) | 세그멘테이션 (Segmentation) | 혼합 방식 |
| --- | --- | --- | --- |
| 분할 단위 | 고정 크기 블록 | 함수, 배열, 스택 같은 논리 단위 | 세그먼트를 고정 크기 페이지로 분할 |
| 단편화 | 내부 단편화 발생, 외부 단편화 없음 | 외부 단편화 발생, 내부 단편화 없음 | 내부 단편화가 미세하게 발생 |
| 주소 구조 | 페이지 번호와 오프셋 | 세그먼트 번호와 오프셋 | 세그먼트 번호, 페이지 번호, 오프셋 |
| 공유와 보호 | 페이지 단위 보호 비트 부여로 관리가 복잡 | 논리 모듈 단위로 공유와 보호가 쉬움 | 세그먼트 수준 보호와 페이지 수준 할당 |
| 현대 구현 | x86-64 등 현대 OS의 주류 | 64비트 전환 이후 쇠퇴 | 일부 운영체제에서 채택 |

- 현대 시스템은 균일한 할당과 관리 단순성을 주는 페이징을 근간으로 하고, 거대 메모리 환경에서는 일반 페이지보다 큰 단위의 **대용량 페이지** (Huge Page)를 병용함.

## Ⅴ. 가상 메모리(Virtual Memory)의 한계와 방안

- 핵심 요약 : 스래싱, 다단계 테이블의 변환 지연, 가상화 환경의 중첩 변환 비용을 워킹 셋 관리, 대용량 페이지, 하드웨어 중첩 페이징으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **스래싱** (Thrashing, 페이지 교체 I/O에 CPU가 묶이는 상태) | 프로세스 메모리가 **워킹 셋** (Working Set, 일정 기간 참조되는 페이지 집합) 미만으로 떨어져 시스템이 마비 | 워킹 셋 모델 또는 PFF(Page Fault Frequency, 페이지 부재 빈도) 기반으로 다중 프로그래밍 정도(DoM, Degree of Multiprogramming) 조절, 압축 메모리 스왑(zRAM) 도입 | 페이지 부재 빈도, 스왑 I/O 비율 |
| 다단계 페이지 테이블 지연 | 64비트 주소 공간에서 4~5단계 테이블 워크가 필요해 메모리 접근이 느려짐 | 대용량 페이지 도입으로 TLB 적용 범위 확대 | TLB 미스율 |
| 가상화의 2단계 주소 변환 | 게스트 가상 주소, 게스트 물리 주소, 호스트 물리 주소로 이어지는 중첩 변환(Two-dimensional Paging)으로 VM 성능 저하 | Intel EPT(Extended Page Table), AMD NPT(Nested Page Table) 하드웨어 중첩 페이징 활성화, SR-IOV 메모리 패스스루 | VM 메모리 접근 지연 |

## Ⅵ. 가상 메모리(Virtual Memory)에 대한 기술사적 제언

- 핵심 요약 : 대용량 페이지 튜닝, 메모리 계층의 확장, 커널 보안 설정의 상시 점검을 묶어 가상 메모리를 성능과 보안의 공통 기반으로 관리.
- 대용량 데이터베이스 운영자는 대용량 페이지를 미리 정적으로 할당하고, 투명 대용량 페이지(THP, Transparent Huge Pages)의 압축 지연이 응답 시간을 흔드는지 측정해 설정을 정하는 것이 바람직하다.
- 메모리 용량 확장이 필요한 플랫폼은 CXL(Compute Express Link) 기반 메모리 풀을 가상 메모리 계층의 하위 티어로 편입해 DRAM 증설 비용을 나누는 방향을 검토해야 한다.
- 보안 조직은 커널 페이지 테이블 격리(KPTI, Kernel Page Table Isolation)와 주소 공간 배치 무작위화(ASLR, Address Space Layout Randomization)의 적용 상태를 상시 점검하고, 변경 이력을 보안 기준의 일부로 관리해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 가상 메모리는 프로세스별 대용량 격리 주소 공간을 제공하는 OS의 핵심 기법으로, 스래싱과 변환 오버헤드 관리가 필수.
- 시사점 : 변환 경로의 캐시 적중률과 페이지 부재 빈도가 체감 성능을 좌우하므로, 주소 체계 설계와 메모리 용량 계획을 함께 보아야 함.
