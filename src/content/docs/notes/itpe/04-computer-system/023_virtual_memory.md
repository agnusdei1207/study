## 30초 인출

- 본질: **가상 메모리 (Virtual Memory)** 는 프로세스마다 독립된 주소 공간을 제공하고 필요한 부분을 물리 메모리에 연결하는 메모리 관리 방식
- 메커니즘: **MMU (Memory Management Unit)** 의 주소 변환 → **TLB (Translation Lookaside Buffer)** 우선 조회 → 미스 때 페이지 테이블 확인 → 미적재 페이지는 운영체제 처리
- 통찰: 물리 메모리 크기의 한계를 극복하고 프로세스 간 메모리 보호를 달성하기 위해 가상 주소 공간과 페이징 기반 요구 메모리 기법을 제공 체계화.

<summary>핵심 용어</summary>

- **가상 메모리 (Virtual Memory)** : 프로세스의 가상 주소 공간을 물리 메모리와 연결해 관리하는 메모리 기능.
- **CPU (Central Processing Unit)** : 프로그램 명령을 실행하는 중앙 처리 장치.
- **가상 주소** : 프로그램이 사용하는 주소로, 물리 메모리 위치와 일치하지 않을 수 있음.
- **MMU (Memory Management Unit)** : 가상 주소를 물리 주소로 변환하고 접근 권한을 확인하는 하드웨어
- **페이지 테이블** : 가상 페이지와 물리 프레임의 대응 및 권한 정보를 담는 자료구조
- **TLB (Translation Lookaside Buffer)** : 최근 주소 변환 결과를 저장해 페이지 테이블 탐색을 줄이는 캐시
- **TLB 미스** : 변환 결과가 TLB에 없어 페이지 테이블을 확인해야 하는 상태
- **페이지 부재(Page Fault)** : 접근한 가상 페이지의 매핑이 없거나 현재 물리 메모리에 준비되지 않아 운영체제 처리가 필요한 사건
- **스래싱** : 필요한 페이지가 메모리에 충분히 남지 못해 교체·입출력이 반복되는 상태

## 2~4교시 25점 답안

## Ⅰ. 가상 메모리의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **가상 메모리 (Virtual Memory)** 는 프로세스의 가상 주소 공간을 물리 메모리와 연결해 관리하는 메모리 기능 |
| 목적 | 프로세스별 주소 공간 분리와 필요한 부분의 선택적 적재 |

## Ⅱ. 가상 메모리의 특징

| 특징 | 의미 |
|---|---|
| 주소 공간 분리 | 프로세스마다 독립된 가상 주소·권한 제공 |
| 선택적 적재 | 실제 접근하는 페이지를 물리 메모리에 연결 |
| 변환 캐시 | TLB로 반복 페이지 테이블 탐색 비용 축소 |

## Ⅲ. 주소 변환과 페이지 부재 처리

```text
CPU 가상 주소 → MMU·TLB ──적중────────────→ 물리 프레임 접근
                    └──미스→ 페이지 테이블 ├→ 유효 매핑 → TLB 갱신
                                         └→ 미적재 → OS의 페이지 부재 처리
```

TLB 미스와 페이지 부재는 다른 사건. 페이지 테이블에 유효한 매핑이 있으면 주소 변환 후 실행 재개.

### 페이지 부재의 처리

페이지 부재 시 주소 및 접근 권한을 검사하고, 유효할 경우 필요한 페이지를 메모리에 적재 및 생성하여 페이지 테이블을 갱신한 뒤 명령 재실행. 파일 매핑 여부에 따라 파일 읽기 또는 제로 채움이 수반되며 모든 부재가 단순 스왑 I/O는 아님에 유의.

```text
페이지 부재 → 주소·권한 검사
  ├─ 무효 접근 → 프로세스에 오류 통지
  └─ 유효 접근 → 페이지 적재·생성 → 매핑·TLB 갱신 → 명령 재시도
```

## Ⅳ. TLB 미스·페이지 부재·스래싱 비교

| 현상 | 직접 원인 | 구별 기준 |
|---|---|---|
| TLB 미스 증가 | 변환 캐시가 작업 주소 범위를 충분히 담지 못함 | 지역성·페이지 크기와 TLB 지표 대조 |
| 페이지 부재 증가 | 미적재·교체된 페이지 접근 | 부재 유형과 적재 비용 확인 |
| 스래싱 | 활성 작업집합에 비해 물리 메모리 부족 | 메모리 압박·교체 입출력 확인 |

큰 페이지는 TLB 범위를 넓힐 수 있지만 메모리 사용량과 페이지 부재 비용도 바뀔 수 있는 선택지. 일괄 적용보다 워크로드별 검토 필요.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 모든 프로세스에 큰 페이지를 적용해 메모리 낭비 | 워크로드별 TLB 미스·페이지 부재·메모리 압박을 측정해 이득이 확인된 범위부터 적용 |
| 페이지 부재를 모두 스왑 병목으로 오인 | 유효 매핑·파일 적재·새 페이지 생성 원인을 구분해 조정 |
| 활성 작업집합이 물리 메모리보다 커 스래싱 | 동시 실행량·메모리 용량·교체 입출력을 함께 조정 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
페이지 테이블 워크(Page Table Walk)로 인한 메모리 참조 지연을 최소화하기 위해 HugePage(2MB/1GB)를 활성화하고, 국소성(Locality) 기반의 워킹셋 알고리즘으로 스래싱 차단.

### 2. 아키텍처 및 상세 메커니즘
```text
[ CPU 가상 주소 (Virtual Address) ] ───(가상 페이지 번호 VPN + 변위 Offset)───┐
                                                                               │
                                                                               ▼
                                                               ┌──────────────────────────────┐
                                                               │ [ TLB (변환 색인 버퍼) 검색 ] │
                                                               └──────────────┬───────────────┘
                                                                              │
                                      ┌───────────────────────────────────────┴───────────────────────┐
                                      │ 적중 (Hit)                                                    │ 미스 (Miss)
                                      ▼                                                               ▼
                     ┌─────────────────────────────────┐                            ┌───────────────────────────────────┐
                     │ 물리 프레임 번호(PFN) 즉시 획득 │                            │ 다단계 페이지 테이블 워크 (Memory) │
                     └────────────────┬────────────────┘                            └─────────────────┬─────────────────┘
                                      │                                                               │
                                      │                             ┌─────────────────────────────────┴───────────────────┐
                                      │                             │ 유효 비트 Valid = 1                                 │ 유효 비트 Valid = 0
                                      │                             ▼                                                     ▼
                                      │                   [ TLB 갱신 후 주소 변환 ]                             [ 페이지 부재 (Page Fault) ]
                                      │                                                                                   │
                                      │                                                                                   ▼
                                      │                                                                         [ OS 디스크 스왑인 처리 ]
                                      ▼                                                                                   │
                     [ 물리 메모리(DRAM) 실제 접근 완료 ] <───────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 구분 항목 | TLB 미스 (TLB Miss) | 페이지 부재 (Page Fault) |
|---|---|---|
| **발생 위치** | 하드웨어 MMU 캐시 내부 | 가상 메모리 관리 서브시스템 (OS 레벨) |
| **원인** | TLB 내에 가상-물리 주소 매핑 엔트리 부재 | 참조한 페이지가 물리 메모리(DRAM)에 부재 (스왑 영역 존재) |
| **처리 주체** | 하드웨어 MMU (또는 OS TLB 핸들러) | OS 커널 페이지 부재 인터럽트 핸들러 (디스크 I/O 수반) |
| **소요 시간** | 수 나노초 ($\sim$ 수십 ns, 메모리 참조 몇 회) | 수 밀리초 ($\sim$ 수 ms, 디스크 헤드 탐색 및 읽기) |
| **성능 영향** | 경미한 수준의 CPU 파이프라인 지연 | 심각한 프로세스 블로킹 및 스래싱(Thrashing) 위험 |
