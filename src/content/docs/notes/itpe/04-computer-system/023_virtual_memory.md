## 지식 로드맵 내 현재 위치

지식 위치: 컴퓨터 시스템 → 운영체제 메모리 관리 → **가상 메모리**

## 30초 인출

- 본질: **가상 메모리** 는 프로세스마다 독립된 주소 공간을 제공하고 필요한 부분을 물리 메모리에 연결하는 방식이다.
- 메커니즘: MMU가 TLB와 페이지 테이블로 가상 주소를 물리 주소에 매핑한다. 아직 적재되지 않은 페이지에 접근하면 운영체제가 페이지 부재를 처리한다.

<details>
<summary>핵심 용어</summary>

- **가상 주소** : 프로그램이 사용하는 주소. 물리 메모리의 위치와 직접 같지 않다.
- **MMU** : 가상 주소를 물리 주소로 변환하고 접근 권한을 확인하는 하드웨어
- **페이지 테이블** : 가상 페이지와 물리 프레임의 대응 및 권한 정보를 담는 자료구조
- **TLB** : 최근 주소 변환 결과를 저장해 페이지 테이블 탐색을 줄이는 캐시
- **TLB 미스** : 변환 결과가 TLB에 없어 페이지 테이블을 확인해야 하는 상태
- **페이지 부재(Page Fault)** : 접근한 가상 페이지의 매핑이 없거나 현재 물리 메모리에 준비되지 않아 운영체제 처리가 필요한 사건
- **스래싱** : 필요한 페이지가 메모리에 충분히 남지 못해 교체·입출력이 반복되는 상태

</details>

## 1교시 10점 답안

### 1. 정의·목적

- 정의: **가상 메모리** 는 프로세스의 가상 주소를 물리 메모리와 연결해 사용하는 메모리 관리 방식이다.
- 목적: 주소 공간을 분리하고 필요한 페이지만 적재해 메모리를 활용한다.

### 2. 주소 변환과 분기

```mermaid
flowchart TD
    VA["CPU의 가상 주소"] --> TLB["TLB 조회"]
    TLB -->|"적중"| PA["물리 주소로 접근"]
    TLB -->|"미스"| TABLE["페이지 테이블 확인"]
    TABLE -->|"유효한 매핑"| PA
    TABLE -->|"미적재·매핑 없음"| FAULT["페이지 부재 처리"]
```

### 3. 두 사건의 차이

| 사건 | 뜻 | 결과 |
|---|---|---|
| TLB 미스 | 변환 캐시에 항목이 없음 | 페이지 테이블 확인 |
| 페이지 부재 | 필요한 페이지가 준비되지 않음 | 운영체제의 적재·매핑 또는 접근 오류 처리 |

제언: 주소 변환 비용과 실제 페이지 부재 횟수를 구분해 성능 저하의 원인을 찾는다.

## 2~4교시 25점 답안

## Ⅰ. 가상 메모리의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 프로세스의 가상 주소를 물리 메모리와 연결해 사용하는 메모리 관리 방식 |
| 목적 | 주소 공간 분리와 필요한 페이지의 선택적 적재 |

## Ⅱ. MMU의 주소 변환

```mermaid
flowchart TD
    VA["CPU의 가상 주소"] --> TLB["TLB 조회"]
    TLB -->|"적중"| PA["물리 주소로 접근"]
    TLB -->|"미스"| TABLE["페이지 테이블 확인"]
    TABLE -->|"유효한 매핑"| PA
    TABLE -->|"미적재·매핑 없음"| FAULT["페이지 부재 처리"]
```

TLB 미스가 곧 페이지 부재는 아니다. 페이지 테이블에 유효한 매핑이 있으면 주소 변환을 마치고 실행을 이어 간다.

## Ⅲ. 페이지 부재의 처리

```mermaid
flowchart TD
    FAULT["페이지 부재 발생"] --> VALID["주소·접근 권한 확인"]
    VALID -->|"잘못된 접근"| ERROR["접근 오류 처리"]
    VALID -->|"유효한 접근"| LOAD["필요한 페이지 적재·생성"]
    LOAD --> UPDATE["페이지 테이블 갱신"]
    UPDATE --> RETRY["명령 재시도"]
```

유효한 접근이라도 페이지를 디스크에서 읽는지, 새 페이지를 생성하는지는 매핑 방식과 상태에 따라 다르다. 모든 페이지 부재가 스왑 읽기는 아니다.

## Ⅳ. 성능 저하 원인의 구별

| 현상 | 직접 원인 | 확인할 대응 |
|---|---|---|
| TLB 미스 증가 | 변환 캐시가 작업 주소 범위를 충분히 담지 못함 | 접근 지역성·페이지 크기와 실제 측정치 검토 |
| 페이지 부재 증가 | 아직 매핑되지 않았거나 메모리에서 밀려난 페이지 접근 | 부재 유형과 적재 비용 확인 |
| 스래싱 | 활성 작업집합에 비해 물리 메모리 부족 | 메모리 압박·교체 입출력·동시 실행량 조정 |

큰 페이지는 TLB 범위를 넓힐 수 있지만 메모리 사용량과 페이지 부재 비용도 바꿀 수 있어 일괄 처방이 아니다.

## Ⅴ. 원인별 성능 개선 제언

| 문제 | 해결 방안 |
|---|---|
| TLB 미스를 페이지 부재로 오인해 스왑만 조정 | TLB 미스와 페이지 부재를 따로 측정하고 접근 패턴·페이지 크기를 검토 |
| 물리 메모리 부족으로 페이지 교체가 반복 | 활성 작업집합과 교체 입출력을 확인해 동시 실행량이나 메모리 용량을 조정 |
