## Ⅰ. 가상 메모리(Virtual Memory)의 개요

- 개념 : 물리적 메인 메모리(DRAM, Dynamic Random-Access Memory)의 용량 한계를 극복하고 멀티프로그래밍 환경의 메모리 보호를 위해, 보조기억장치(스토리지)를 주소 공간으로 확장하여 각 프로세스마다 독립적이고 연속적인 대용량의 논리적 **가상 주소 공간** (Virtual Address Space)을 제공하는 운영체제의 메모리 관리 기법.
- 배경 및 필요성 : 초기 컴퓨터는 물리 메모리보다 큰 프로그램을 실행할 수 없었으며, 다중 프로세스가 물리 메모리를 직접 공유함에 따라 메모리 침범 및 **주소 재배치(Relocation)** 난제가 발생하여 이를 해결하기 위해 고안됨.
- 핵심 목적 : 물리 메모리 크기 제약 극복, 프로세스 간 메모리 완전 격리 및 보안 보호, 요구 페이징(Demand Paging)을 통한 메모리 적재 효율 극대화.

## Ⅱ. 가상 메모리(Virtual Memory)의 핵심 아키텍처 및 동작 메커니즘

가상 메모리는 프로세스의 가상 주소를 **MMU** (Memory Management Unit)와 **페이지 테이블**을 통해 물리 주소로 실시간 변환하며, TLB(Translation Lookaside Buffer)를 통해 변환 지연을 하드웨어적으로 가속함.

```text
[ 가상 주소 -> 물리 주소 변환 및 페이징 메커니즘 ]

+---------------------------------------------------------------+
| CPU (가상 주소 생성) : [ 가상 페이지 번호 (VPN) | 오프셋 (Offset) ]   |
+---------------------------------------------------------------+
                                │
                                ▼
+---------------------------------------------------------------+
| MMU 내 TLB (Translation Lookaside Buffer: 고속 캐시)           |
+---------------------------------------------------------------+
         │                                              │
  [TLB Hit: 프레임 즉시 반환]                   [TLB Miss: 페이지테이블 워크]
         │                                              │
         │                                              ▼
         │             +------------------------------------------------+
         │             | Multi-Level Page Table (CR3 레지스터 참조)     |
         │             |  - Valid Bit == 1 : PFN(물리 프레임 번호) 반환 |
         │             |  - Valid Bit == 0 : Page Fault 인터럽트 발생  |
         │             +------------------------------------------------+
         │                                              │
         │                                              ▼ (디스크 I/O)
         │                               +------------------------------+
         │                               | Swap Space (스토리지 스왑 영역)|
         │                               +------------------------------+
         ▼                                              │
+-------------------------------------------------------▼-------+
| 물리 메모리 (DRAM) : [ 물리 프레임 번호 (PFN) | 오프셋 (Offset) ]      |
+---------------------------------------------------------------+
```

- **주소 변환(MMU Translation)** : CPU(Central Processing Unit)가 생성한 가상 주소(Virtual Address)를 하드웨어 MMU가 페이지 테이블을 참조하여 물리 주소(Physical Address)로 매핑.
- **TLB (고속 주소 변환 캐시)** : 최근 사용된 가상-물리 주소 매핑 엔트리를 SRAM(Static Random-Access Memory)에 캐싱하여 페이지 테이블 2회 참조 지연을 1클럭 수준으로 단축.
- **요구 페이징(Demand Paging)** : 프로그램 전체를 한 번에 메모리에 올리지 않고, 실행 중 실제로 참조되는 페이지만 물리 메모리에 적재.
- **페이지 부재(Page Fault) 루틴** : 요청 페이지가 메모리에 없을 때(Valid bit=0) OS(Operating System) 커널이 디스크 스왑 영역에서 해당 페이지를 빈 프레임으로 로드하고 테이블 갱신.

## Ⅲ. 가상 메모리(Virtual Memory)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 페이징 (Paging) | 세그멘테이션 (Segmentation) | 세그멘테이션-페이징 혼합 |
|---|---|---|---|
| **분할 단위** | 고정 크기 블록 (예: 4KB, 2MB) | 논리적 의미 단위 (함수, 배열, 스택) | 세그먼트를 고정 크기 페이지로 분할 |
| **단편화 문제** | 내부 단편화 발생 (외부 단편화 없음) | 외부 단편화 발생 (내부 단편화 없음) | 내부 단편화 미세 발생 |
| **주소 구조** | 1차원 주소 (페이지 번호 + 오프셋) | 2차원 주소 (세그먼트 번호 + 오프셋) | 세그먼트 번호 + 페이지 번호 + 오프셋 |
| **공유 및 보호** | 페이지 단위 보호 비트 부여 (복잡) | 논리적 모듈 단위로 공유/보호 매우 용이 | 세그먼트 레벨 보호 + 페이지 레벨 할당 |
| **현대 구현** | x86-64 등 현대 OS의 지배적 표준 | 현대 아키텍처에서 64비트 전환 시 쇠퇴 | 리눅스 커널 등 실제 운영체제 채택 |

- 현대 시스템은 균일한 메모리 할당과 관리 단순성을 제공하는 페이징 아키텍처를 근간으로 하며, 거대 메모리 환경을 위해 대용량 페이지(Huge Page) 기술을 병용함.

## Ⅳ. 가상 메모리(Virtual Memory)의 주요 한계점 및 해결 방안

- 페이지 부재 빈발에 따른 **스래싱(Thrashing)** 발생 :
  - 한계점 : 동시 실행 프로세스 수가 과도하여 각 프로세스에 할당된 메모리가 워킹셋(Working Set) 미만으로 떨어질 때, CPU가 페이지 교체 디스크 I/O에만 매달려 시스템 마비.
  - 해결 방안 : 워킹셋 모델 또는 PFF(Page Fault Frequency) 알고리즘을 통한 다중 프로그래밍 정도(DoM, Degree of Multiprogramming) 동적 조절 및 zRAM 압축 스왑 도입.
- 다단계 페이지 테이블 참조에 따른 메모리 지연 오버헤드 :
  - 한계점 : 64비트 주소 공간 지원을 위해 4단계~5단계 페이지 테이블 워크(Page Table Walk)를 수행해야 하므로 메모리 접근 속도 대폭 저하.
  - 해결 방안 : 대용량 페이지(Huge Pages: 2MB, 1GB) 도입을 통해 TLB 커버리지를 비약적으로 확대하고 TLB 미스율 최소화.
- 클라우드 가상화 환경의 2단계 주소 변환 오버헤드 :
  - 한계점 : 게스트 가상 주소 -> 게스트 물리 주소 -> 호스트 물리 주소로 이어지는 중첩 변환(Two-dimensional Paging)으로 인한 VM(Virtual Machine) 성능 저하.
  - 해결 방안 : 하드웨어 중첩 페이징 지원(Intel EPT, AMD NPT) 활성화 및 SR-IOV 메모리 패스스루 적용.

## Ⅴ. 가상 메모리(Virtual Memory) 적용 및 발전을 위한 기술사적 제언

- 초대형 데이터베이스 **HugeTLB** 튜닝 의무화 : 오라클, PostgreSQL, Redis 등 대규모 인메모리 DB(Database) 운영 시 Transparent Huge Pages(THP)의 압축 지연을 방지하고 명시적 Static HugePages 할당 권장.
- **CXL**(Compute Express Link) 기반 이종 메모리 풀링과의 융합 : 가상 메모리 계층을 로컬 DRAM을 넘어 CXL.mem 버스 기반의 원격 공유 메모리 풀까지 확장하는 티어링 아키텍처 도입 준비 필요.
- 보안 **메모리 격리(ASLR, Address Space Layout Randomization & KPTI, Kernel Page-Table Isolation)** 강화 : Meltdown 취약점 등 사이드 채널 공격을 차단하기 위해 커널 페이지 테이블 격리(KPTI)와 주소 공간 무작위화(ASLR)의 무결성 상시 점검 필수.
