## 연관 키워드

- DAS(Direct-Attached Storage), NAS(Network-Attached Storage), SAN(Storage Area Network)
- 블록 I/O, 파일 공유, HBA(Host Bus Adapter), FC(Fibre Channel), iSCSI, LUN(Logical Unit Number)
- NFS(Network File System), SMB(Server Message Block), 스토리지 가상화

## Ⅰ. 스토리지 접속 유형(DAS·NAS·SAN)의 개요

- 핵심 요약 : 서버와 저장소의 연결 구조와 전송 단위에 따라 성능·공유성·비용이 갈리는 3대 스토리지 아키텍처.
- 개념 : 서버와 저장 장치를 연결하는 방식에 따라 스토리지 환경을 분류하는 체계로, 직결형 **DAS** (Direct-Attached Storage), 파일 공유형 **NAS** (Network-Attached Storage), 전용 네트워크형 **SAN** (Storage Area Network)으로 구분.
- 배경 및 필요성 : 데이터 급증과 서버 가상화 확산으로 서버 내장 디스크만으로 용량·공유·가용성 수요를 감당하기 곤란.
- 주요 목적 : 업무 특성에 맞는 접속 구조 선택으로 성능·확장성·총소유비용의 균형 확보.

## Ⅱ. DAS·NAS·SAN의 특징 및 장점

- 핵심 요약 : 직결의 단순성, 이더넷 파일 공유의 접근성, 전용 네트워크 블록 전송의 고성능이 각 장점으로 연결.

1. DAS : 서버와 저장소를 전용 케이블로 직결하고 서버가 저장소를 독점 → 구성의 단순성과 최저 수준의 지연·비용.
2. NAS : 일반 이더넷 위에서 파일 프로토콜로 접근하는 전용 파일 서버 → 이기종 클라이언트 간 파일 공유와 신속한 도입.
3. SAN : 전용 스위치 네트워크로 블록 I/O를 전송 → 고성능·저지연과 서버 풀 전체의 볼륨 공유, 백업 트래픽의 분리 효과.

## Ⅲ. DAS·NAS·SAN의 구조 (흐름)

- 핵심 요약 : 직결 구조에서 공유형 파일 서버, 전용 네트워크 블록 전송으로 접속 구조가 분화·고도화되는 흐름.

```text
[ 스토리지 접속 구조의 분화 ]

DAS : 서버-저장소 직결 (1:1)
   ↓ 공유·확장 요구
NAS : 이더넷 위 파일 공유 (N:N)
   ↓ 대용량·저지연 요구
SAN : 전용 네트워크 블록 전송
```

```text
[ SAN의 블록 공유 구조 ]

다수 서버 (전용 어댑터 장착)
   ↓ 전용 네트워크 전송
SAN 스위치 (파이버 패브릭)
   ↓
스토리지 어레이 (볼륨 분할 할당)
```

- DAS 구성요소 : 서버의 기본 저장 인터페이스와 직결 케이블, 외장 디스크 인클로저의 단순 구성.
- NAS 구성요소 : 파일 서비스를 전담하는 NAS 헤드, 디스크 어레이, **NFS** (Network File System)·**SMB** (Server Message Block) 파일 프로토콜 스택.
- SAN 구성요소 : 서버 측 **HBA** (Host Bus Adapter, 스토리지 전용 어댑터), SAN 스위치, **FC** (Fibre Channel)·**iSCSI** (Internet Small Computer Systems Interface) 전송 프로토콜, **LUN** (Logical Unit Number, 어레이를 논리 분할한 볼륨 단위) 매핑 체계.

## Ⅳ. DAS·NAS·SAN의 비교

- 핵심 요약 : 단순·저비용(DAS), 파일 공유(NAS), 고성능 블록 공유(SAN)의 상보적 구도.

| 비교 축 | DAS | NAS | SAN |
| --- | --- | --- | --- |
| 접속 방식 | 서버 직결 케이블 | 일반 이더넷 | 전용 스위치 네트워크 |
| 전송 단위 | 블록 I/O | 파일 | 블록 I/O |
| 대표 프로토콜 | 직결 버스 인터페이스 | NFS, SMB | FC, iSCSI |
| 성능·지연 | 단일 서버 기준 최저 지연 | 이더넷 대역폭 의존 | 고성능·저지연 |
| 공유성 | 없음 (서버 전용) | 높음 (이기종 파일 공유) | 볼륨 단위 공유 |
| 확장성 | 서버 단위에서 정체 | 노드 증설로 확장 | 대규모 확장 용이 |
| 비용 | 가장 낮음 | 중간 | 가장 높음 |
| 적합 유스케이스 | 단일 서버 업무·로컬 저장 | 문서·미디어 공유, 홈 디렉터리 | DB·가상화·핵심 업무 시스템 |

- 선택 기준 : 단순성과 비용이 우선이면 DAS, 이기종 파일 공유가 핵심이면 NAS, 고성능 블록 I/O와 서버 풀 운영이면 SAN을 우선 검토.

## Ⅴ. 스토리지 운영의 한계와 방안

- 핵심 요약 : DAS의 확장·공유 한계, NAS의 대역폭 경합, SAN의 구축 부담을 전환 기준·트래픽 분리·단계적 확장으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| DAS의 공유·확장 한계 | 서버 종속 저장으로 유휴 용량 편차와 분산 백업 누적 | 업무 성장 시점의 NAS·SAN 전환 기준 정책화와 통합 백업 체계 수용 | 백업 커버리지율 |
| NAS의 대역폭 경합 | 공용 이더넷 공유로 대량 I/O 시 지연 증가 | 전용 VLAN(Virtual Local Area Network) 분리와 대용량 회선 확보, 백업 트래픽 분리 | 대역폭 사용률, 지연 시간 |
| SAN의 구축·운영 부담 | 전용 장비와 전문 인력으로 초기 비용·난이도 상승 | iSCSI 기반 저비용 진입 후 FC로 단계 확장, 스토리지 가상화 통합 관리 | 장비 이중화율, 운영 인력 의존도 |

## Ⅵ. 스토리지 아키텍처 운영에 대한 기술사적 제언

- 핵심 요약 : 업무 등급별 접속 방식 표준, 통합 관리 체계, 단계적 전환 로드맵의 병행 추진.
- 아키텍처 조직 : 업무 등급별 접속 방식 매핑 표준을 정의해 신규 시스템 설계 심의의 기준으로 채택.
- 운영 조직 : DAS·NAS·SAN을 단일 콘솔에서 관리하는 스토리지 가상화·통합 관리 체계로 자산 시야 통합.
- 기획 조직 : 데이터 성장 전망에 맞춘 단계적 전환 로드맵과 투자 계획 수립.

## Ⅶ. 결론

- 핵심 요약 : DAS·NAS·SAN은 접속 구조와 전송 단위가 다른 상보적 스토리지 아키텍처임.
- 공유 범위·성능 요구·비용 제약의 판별이 접속 구조 선택의 출발점.
