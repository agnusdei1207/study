## 연관 키워드

- CXL(Compute Express Link), PCIe(Peripheral Component Interconnect Express), 캐시 일관성(Cache Coherency)
- CXL.io, CXL.cache, CXL.mem, Type 1, Type 2, Type 3, 제로 카피(Zero-Copy)
- 분해형 데이터센터(Disaggregated Data Center), 메모리 풀링(Memory Pooling), 계층형 메모리(Tiered Memory)
- NUMA(Non-Uniform Memory Access), HMAT(Heterogeneous Memory Attribute Table)

## Ⅰ. CXL의 개요

- 핵심 요약 : PCIe(Peripheral Component Interconnect Express) 물리 계층 위에서 **캐시 일관성** (Cache Coherency)을 하드웨어로 보장하여 이종 장치 간 메모리 공유를 가능하게 하는 개방형 인터커넥트 표준 **CXL** (Compute Express Link).
- 개념 : CPU(Central Processing Unit), GPU(Graphics Processing Unit), NPU(Neural Processing Unit), 메모리 확장기 같은 이종 장치를 고속·저지연으로 연결하면서 캐시 일관성을 하드웨어 수준에서 유지하는 상호연결 표준.
- 배경 및 필요성 : 가속기 확산으로 장치와 호스트 간 데이터 복사 비용이 증가했고, 기존 PCIe 방식은 호스트와 장치 메모리가 분리되어 일관성 유지를 소프트웨어가 부담하는 구조. 소켓당 메모리 용량 한계도 새로운 메모리 확장 계층의 필요성을 높임.
- 주요 목적 : 장치 간 **제로 카피** (Zero-Copy) 데이터 공유, 서버 메모리 용량·대역폭의 확장, **분해형 데이터센터** (Disaggregated Data Center) 실현.

## Ⅱ. CXL의 특징 및 장점

- 핵심 요약 : 입출력·캐시·메모리의 3개 프로토콜이 하나의 인터커넥트에서 역할을 나누어, PCIe 자산 호환성과 메모리 공유를 동시에 제공하는 구조.

1. **CXL.io** : PCIe와 호환되는 프로토콜로 장치 탐색·초기화·설정과 DMA(Direct Memory Access)를 담당 → 기존 PCIe 소프트웨어 스택의 그대로 재사용.
2. **CXL.cache** : 가속기·스마트NIC(Network Interface Card)이 호스트 메모리를 캐싱하며 일관성 유지 → 장치-호스트 간 데이터 복사 감소.
3. **CXL.mem** : 호스트 CPU가 장치 측 메모리를 자신의 주소 공간으로 인식하여 로드·저장(Load/Store) 명령으로 접근 → 블록 전송이 아닌 바이트 단위 직접 접근.
4. **메모리 풀링** (Memory Pooling) : 여러 서버가 스위치를 통해 공유 메모리 장치를 나누어 사용 → 서버별 유휴 메모리 회수로 전체 활용률 향상.

## Ⅲ. CXL의 구조 (흐름)

- 핵심 요약 : CXL.io·CXL.cache·CXL.mem의 프로토콜 조합으로 장치를 Type 1~3으로 분류하고, 스위치를 중심으로 한 토폴로지로 확장하는 구조.

```text
[ CXL 프로토콜 스택 ]

CXL.io    CXL.cache    CXL.mem
(입출력)   (캐시 일관성)  (메모리 접근)
      ↓
PCIe 물리 계층(PHY) 재사용
      ↓
CPU · 가속기 · 메모리 장치
```

```text
[ 장치 유형별 프로토콜 조합 ]

Type 1 : CXL.io + CXL.cache
         → 스마트NIC 등
Type 2 : CXL.io + CXL.cache + CXL.mem
         → GPU·NPU 등 가속기
Type 3 : CXL.io + CXL.mem
         → 메모리 확장기·버퍼 칩
```

- 구성요소 : CXL.io는 모든 장치의 공통 기반이고, CXL.cache는 장치가 호스트 메모리를 캐싱할 때, CXL.mem은 호스트가 장치 메모리에 접근할 때 사용되는 프로토콜.
- 토폴로지 : CPU와 장치의 직결 방식에서 출발하여 단일 스위치를 거친 풀링 구성, CXL 3.0 이상의 다단 스위치·패브릭 확장으로 발전하는 단계 구조.
- 유형 구분 : Type 2는 호스트와 가속기가 서로의 메모리를 대등하게 공유하는 유형이고, Type 3은 호스트의 메모리 용량을 늘리는 확장기 유형.

## Ⅳ. CXL과 PCIe·NVLink의 비교

- 핵심 요약 : 개방형 표준이면서 캐시 일관성과 바이트 단위 메모리 접근을 제공하는 점이 PCIe 대비 CXL의 차별점이자 NVLink와의 공통점.

| 비교 항목 | 전통적 PCIe | CXL | NVLink |
| --- | --- | --- | --- |
| 캐시 일관성 | 미지원 (소프트웨어 동기화) | 하드웨어 보장 | 하드웨어 지원 |
| 메모리 접근 단위 | 블록·DMA 전송 (복사 수반) | 바이트 단위 Load/Store | 바이트 단위 직접 접근 |
| 표준 성격 | PCI-SIG(PCI Special Interest Group) 개방형 표준 | 업계 컨소시엄 개방형 표준 | NVIDIA 자사 규격 |
| 적용 범위 | 주변 장치 입출력 | CPU·가속기·메모리 공유 | 자사 GPU 간 연결 중심 |
| 토폴로지 확장 | 계층형 스위치 | 스위치·멀티티어 패브릭 | 자사 클러스터 구성 |

- 선택 기준 : 다 벤더 장치 혼용과 메모리 공유가 목표면 CXL을, 단일 벤더 GPU 클러스터의 극대 대역폭이 목표면 자사 인터커넥트를 택하는 판단 기준.

## Ⅴ. CXL의 한계와 방안

- 핵심 요약 : 접근 지연 증가, 컨트롤러 전력·발열, 메모리 위치 인지 부족을 데이터 배치 전략·저전력 설계·성능 정보 연동으로 대응하는 원칙.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 메모리 접근 지연 증가 | PCIe 경유 경로로 로컬 DRAM(Dynamic Random-Access Memory)보다 지연이 김 | 자주 쓰는 데이터는 로컬에, 드문 데이터는 CXL에 두는 **계층형 메모리** (Tiered Memory) 배치 | 계층별 접근 지연, 로컬 적중률 |
| 컨트롤러 전력·발열 | 메모리 모듈 내 고속 인터페이스 컨트롤러가 추가 열원으로 작동 | 저전력 SerDes(Serializer/Deserializer) 설계와 섀시 방열 설계 | 모듈 온도, 모듈당 전력 |
| **NUMA** (Non-Uniform Memory Access) 인지 부족 | 기존 운영체제와 미들웨어는 동적으로 결합되는 풀링 메모리의 위치를 반영하지 못함 | 커널의 **HMAT** (Heterogeneous Memory Attribute Table) 성능 정보와 메모리 배치 정책 연동 | 원격 노드 접근 비율 |

## Ⅵ. CXL에 대한 기술사적 제언

- 핵심 요약 : 조달 기준의 표준 적합성 강제, 관측 체계의 계층별 가시화, 산업 생태계의 표준 참여 지원으로 CXL 도입 기반을 넓히는 방향.

1. 인프라 기획 조직은 서버·장치 조달 기준에 CXL 컨소시엄 적합성과 CPU·펌웨어·운영체제 스택의 지원 범위 검증을 필수 항목으로 반영한다.
2. 플랫폼 운영 조직은 메모리 계층별 지연·적중률을 관측 도구 스택에 포함하여, 계층 배치 정책의 효과를 데이터로 검증하는 체계를 둔다.
3. 산업·정책 주체는 국내 메모리·서버 기업의 CXL 표준 컨소시엄 참여와 메모리 모듈 제품군 확대를 지원하는 정책을 설계한다.

## Ⅶ. 결론

- 핵심 요약 : CXL은 PCIe 기반에서 캐시 일관성을 하드웨어로 보장하여 이종 장치의 메모리 공유와 분해형 데이터센터를 여는 표준 인터커넥트.
- 지연·전력·소프트웨어 인지라는 비용을 데이터 배치 정책의 성숙도로 관리해야 하는 기술.
