## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 클라우드 인프라 아키텍처

## 30초 인출

- 본질: 서버·스토리지·네트워크 하드웨어가 물리적으로 분리되어 수동 할당되던 병목
- 메커니즘: 소프트웨어 정의 기술(SDDC)로 모든 자원을 추상화하고 API 기반으로 통합 제어

## 핵심 용어

- SDDC(Software-Defined Data Center): 데이터센터의 서버, 스토리지, 네트워크, 보안 등 모든 인프라 자원을 소프트웨어로 가상화하고 정책 기반으로 자동 제어하는 아키텍처
- CMP(Cloud Management Platform): 이기종 가상화 자원과 멀티 클라우드를 단일 창구에서 프로비저닝, 과금, 상태 감시를 수행하는 상위 관리 소프트웨어
- 오버레이 네트워크(Overlay Network): 기존 물리 네트워크(Underlay) 위에 VxLAN, NVGRE 등의 터널링을 구성하여 L2 가상 네트워크를 유연하게 확장하는 기술

### Ⅱ. 핵심 특성

- 하드웨어 가상화와 클라우드 인프라의 결정적 차이는 '셀프서비스 자동화'임 → 단순 가상머신(VM) 생성은 가상화에 불과하며, 사용자가 API를 통해 네트워크와 스토리지를 포함한 완전한 환경을 즉시 배포할 수 있어야 클라우드 인프라 아키텍처임
- 물리 네트워크(Underlay)의 안정성이 가상 네트워크(Overlay)의 성능 한계를 결정함 → 컨트롤 플레인이 소프트웨어로 추상화되더라도 패킷을 실어나르는 물리적 스위치 패브릭의 논블로킹(Non-blocking) 대역폭이 뒷받침되지 않으면 네트워크 병목이 전 계층으로 전파됨
- 멀티 테넌시 격리는 연산보다 I/O(네트워크 및 디스크)에서 무너짐 → CPU/메모리는 하이퍼바이저가 엄격히 분할하지만, 공유 버스와 물리 NIC 대역폭을 특정 테넌트가 독점하면 Noisy Neighbor 장애 발생

### Ⅲ. 관련 개념과 구분

- 가상화(Virtualization) vs 클라우드 인프라(Cloud Infrastructure): 가상화 = 단일 물리 서버의 자원 분할 기술(도구) / 클라우드 인프라 = 분산된 가상 자원을 풀링하여 풀 라이프사이클을 온디맨드 자동화하는 시스템 체계(아키텍처)

### Ⅳ. 적용 문제와 대응

- 적용 상황: 대규모 엔터프라이즈의 프라이빗 클라우드 인프라 구축 및 운영
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 특정 테넌트의 대규모 배치 작업 시 다른 테넌트의 웹 트랜잭션 응답 지연 | 공유 스토리지 및 네트워크 대역폭 경합(Noisy Neighbor) | SR-IOV 및 SDN 기반 전용 대역폭 QoS 하드 제한 적용 | 테넌트 간 성능 간섭 억제 및 SLA 보장 |
| CMP 제어 컨트롤러 장애 발생 시 전체 클라우드 프로비저닝 마비 | 컨트롤 플레인의 단일 인스턴스 구성 및 결합도 과다 | etcd 및 3노드 액티브-액티브 클러스터링 분산 제어 | 관리 평면 SPOF 제거 및 99.99% 가용성 유지 |
| 물리 노드 추가 시 이종 칩셋 간 가상머신 라이브 마이그레이션 실패 | CPU 세대 간 명령어 셋(AVX, SSE) 불일치 | 하이퍼바이저 EVC(Enhanced vMotion Compatibility) 모드 적용 | 이종 x86 노드 간 무중단 워크로드 재배치 보장 |
