## 30초 인출

- 본질: 클라우드 인프라는 컴퓨팅·저장·네트워크 자원을 추상화해 온디맨드로 제공하는 구조
- 메커니즘: 물리 자원을 풀링하고 제어 평면이 정책에 따라 테넌트별 논리 자원을 배치·회수
- 통찰: 한계: 공유 자원의 경합과 추상화된 병목이 테넌트 품질을 흔듦 → 방안: 배치 시 격리·할당량을 강제하고 하부 용량까지 관측한다.

<details>
<summary>핵심 용어</summary>

- **클라우드 인프라(Cloud Infrastructure)** : 클라우드 서비스의 컴퓨팅·저장·네트워크 자원과 관리 기능
- **가상화(Virtualization)** : 물리 자원을 논리 자원으로 추상화·분할하는 기술
- **SDDC (Software-Defined Data Center)** : 데이터센터 자원을 소프트웨어 기반으로 추상화·관리하는 아키텍처 접근
- **CMP (Cloud Management Platform)** : 클라우드 자원 요청·관리·운영을 지원하는 관리 플랫폼
- **오버레이 네트워크(Overlay Network)** : 기존 네트워크 위에 논리 네트워크를 구성하는 방식

## 2~4교시 25점 답안

### Ⅰ. 클라우드 인프라 아키텍처의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **클라우드 인프라 아키텍처는** 컴퓨팅·저장·네트워크 자원을 추상화해 온디맨드로 제공하는 구조 |
| 목적 | 자원 프로비저닝과 운영의 표준화·자동화 |

### Ⅱ. 클라우드 인프라의 특징

| 특징 | 설계 의미 |
|---|---|
| 자원 풀링 | 물리 설비를 공용 풀로 묶고 테넌트에는 논리 자원을 할당 |
| 탄력적 셀프서비스 | API 요청에 따라 자원을 생성·확장·회수 |
| 멀티테넌시 | 공유 설비 위에서 권한·네트워크·저장소 경계를 분리 |
| 계량 운영 | 사용량·성능을 수집해 용량과 비용을 조정 |

### Ⅲ. 인프라 체계·프로세스

**핵심 아키텍처**

```text
테넌트·API → 제어 평면(인증·정책·배치·수명주기)
                    ↓ 정책에 맞는 논리 자원 생성
           가상화·오버레이(분할·격리)
                    ↓
           물리 서버·저장소·네트워크 풀
                    └─ 사용량·성능·장애 → 관측 → 제어 평면
```

**하위 메커니즘: 테넌트 자원 할당·회수**

```text
요청 → 신원·할당량 확인 → 배치 후보의 용량·격리 검사
     → 논리 컴퓨팅·네트워크·저장소 생성 → 사용량 계량
     → 확장 또는 회수 → 잔여 자원 풀에 반환
```

### Ⅳ. 멀티테넌시 격리 영역 비교

| 영역 | 격리 수단 | 검증 지표 |
|---|---|---|
| 컴퓨팅 | 가상 머신·컨테이너 경계, 할당량 | CPU·메모리 경합, 지연 |
| 네트워크 | 논리 네트워크·보안 정책 | 테넌트 간 도달성, 대역폭 |
| 저장소 | 볼륨 권한·암호화·용량 제한 | 접근 권한, I/O 지연 |
| 제어 평면 | 역할 권한·감사·고가용성 | 권한 오용, API 가용성 |

### Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 제어 평면 장애 시 신규 배치·변경이 중단 | 제어 평면 다중화와 복구 절차를 별도 검증 |
| 공유 물리 자원 경합으로 테넌트 품질 저하 | 할당량·QoS를 배치 정책에 반영하고 테넌트별 지연 관측 |
| 논리 자원 지표만 보면 물리 병목을 놓침 | 하부 네트워크·저장소 지표를 논리 자원과 연결해 추적 |

### Ⅵ. 제언

자원 생성의 자동화만 확대하면 공유 설비의 경합과 숨은 병목이 서비스 품질로 전이된다. 따라서 **테넌트별 격리·할당량을 배치 승인 조건으로 먼저 고정**하고, 논리 자원과 물리 설비의 지표를 연결해 확장·회수 결정을 검증해야 한다.
