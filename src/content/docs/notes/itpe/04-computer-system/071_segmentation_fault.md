## 연관 키워드

- 세그멘테이션 오류(Segmentation Fault, SIGSEGV), 메모리 보호(Memory Protection), Fail-Fast, 코어 덤프(Core Dump)
- MMU(Memory Management Unit), 페이지 테이블 엔트리(PTE, Page Table Entry), 페이지 폴트(Page Fault), 가상 메모리
- 널 포인터(Null Pointer), 스택 오버플로(Stack Overflow), 버퍼 오버런(Buffer Overrun), 해제 후 사용(Use-After-Free)
- ASan(AddressSanitizer), UBSan(UndefinedBehaviorSanitizer), 시그널 핸들러(Signal Handler)

## Ⅰ. 세그멘테이션 오류의 개요

- 핵심 요약 : 허용되지 않은 메모리 접근을 하드웨어와 커널이 차단해 프로세스를 즉시 중단시키는 메모리 보호 예외.
- 개념 : 프로세스가 할당받지 않은 주소를 참조하거나 허용되지 않은 권한으로 접근할 때 MMU와 커널이 발생시키는 **세그멘테이션 오류** (Segmentation Fault)로, 프로세스에 SIGSEGV(시그널 번호 11)를 보내 비정상 종료시킴.
- 배경 및 필요성 : 여러 프로세스가 같은 물리 메모리를 나눠 쓰는 환경에서 한 프로세스의 잘못된 쓰기가 다른 프로세스나 커널을 오염시키면 피해가 커지므로, 하드웨어 기반의 메모리 보호가 기본 장치로 필요해짐.
- 주요 목적 : 프로세스 간 메모리 침범 차단, 커널과 중요 데이터 보호, 결함 발생 즉시 중단하는 **Fail-Fast** 원칙 구현과 코어 덤프를 통한 원인 분석 근거 확보.

## Ⅱ. 세그멘테이션 오류의 특징 및 장점

- 핵심 요약 : 하드웨어 검사, 커널 판정, 시그널 전달의 단계별 검증이 결함을 조기에 드러내고 정상 동작과 구분하는 구조.

1. **페이지 테이블 엔트리** (PTE, Page Table Entry) 기반 검증 : MMU(Memory Management Unit)가 가상 주소를 변환할 때 존재(Present) 비트와 읽기·쓰기·실행 권한 비트를 확인 → 위반 시 즉시 예외 발생 → 잘못된 접근이 실행 시점에 바로 드러남.
2. **페이지 폴트** (Page Fault) 기반 커널 판정 : 커널의 페이지 폴트 핸들러가 주소가 프로세스의 유효 영역인지 확인하고 요구 페이징이나 스택 확장 같은 정상 경우를 가려냄 → 유효하지 않은 접근만 SIGSEGV로 종료시켜 불필요한 중단 방지.
3. 코어 덤프 : 종료 시점의 메모리와 레지스터 상태를 파일로 남김 → 사후 분석의 근거 제공.

## Ⅲ. 세그멘테이션 오류의 구조 (흐름)

- 핵심 요약 : 명령의 메모리 접근이 MMU 검사에서 막히면 페이지 폴트, 커널 판정, SIGSEGV 전달을 거쳐 종료되는 흐름.

```text
[ 세그멘테이션 오류 발생 흐름 ]

CPU 명령의 가상 주소 접근
   ↓
MMU 주소 변환 (페이지 테이블 탐색)
   ↓
존재·권한 비트 위반 → 페이지 폴트 예외
   ↓
커널 핸들러가 유효 영역 여부 판정
   ↓
유효하지 않음 → SIGSEGV 전달
   ↓
프로세스 종료 및 코어 덤프 기록
```

```text
[ 페이지 폴트 판정 분기 ]

페이지 폴트 발생
   ↓
커널이 유효 영역 여부 확인
   ↓
(정상) 페이지 할당 또는 스택 확장 후 명령 재실행
   ↓
(비정상) SIGSEGV 전달 → 프로세스 종료
```

## Ⅳ. 세그멘테이션 오류의 원인별 비교

- 핵심 요약 : 널 포인터, 읽기 전용 영역 쓰기, 스택 오버플로, 버퍼 오버런, 해제 후 사용은 발생 원리가 달라 예방과 검출 수단을 원인별로 나눠 적용해야 하는 구도.

| 원인 분류 | 대표 코드 패턴 | 발생 원리 | 예방·검출 수단 |
| --- | --- | --- | --- |
| 널 포인터 역참조 | `int *p = NULL; *p = 10;` | 0번지 부근의 매핑되지 않은 주소 접근 | 포인터 유효성 검사, 옵셔널 타입 |
| 읽기 전용 영역 쓰기 | `char *s = "hello"; s[0] = 'H';` | 읽기 전용 텍스트 영역에 쓰기 권한 위반 | `const` 지정, 정적 분석 |
| 스택 오버플로 | 종료 조건 없는 무한 재귀 | 스택 끝의 가드 영역 침범 | 재귀 깊이 제한, 스택 보호 컴파일 옵션 |
| 버퍼 오버런 | 배열 경계를 넘는 쓰기 | 할당 영역을 벗어나 다른 페이지 침범 | 경계 검사, AddressSanitizer(ASan) |
| 해제 후 사용 (Use-After-Free) | `free(p); p->data = 100;` | 해제된 주소의 매핑이 사라지면 오류, 남아 있으면 조용한 오염 | 해제 후 포인터 무효화, 메모리 검사 도구 |

## Ⅴ. 세그멘테이션 오류의 한계와 방안

- 핵심 요약 : 원인과 크래시의 시차, 코어 덤프 부담, 시그널 핸들러의 안전성 문제를 검사 도구, 덤프 설정, 최소 핸들러로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 원인과 크래시의 시차 (잠재 오염) | 메모리 오염 후 한참 뒤 다른 코드에서 SIGSEGV가 발생해 근본 원인 추적 곤란 | 디버그 빌드에 AddressSanitizer(ASan)와 UndefinedBehaviorSanitizer(UBSan)를 상시 적용해 오염 시점의 콜스택 출력 | 결함 원인 규명 소요 시간 |
| 코어 덤프 용량과 디스크 I/O 부담 | 대용량 메모리를 쓰는 서버 프로세스의 덤프가 디스크를 고갈시켜 연속 장애 유발 | 덤프 압축, 필요한 메모리 영역만 기록하도록 덤프 필터 설정, 덤프 수집기 연동 | 덤프 크기, 디스크 사용률 |
| 시그널 핸들러의 안전성 | 핸들러에서 비동기 안전하지 않은 함수를 호출하면 교착 상태 발생 | 핸들러는 저수준 쓰기 호출 등 최소 기능만 사용하고 기본 덤프 동작 유지 | 핸들러 교착 발생 건수 |

## Ⅵ. 세그멘테이션 오류 예방에 대한 기술사적 제언

- 핵심 요약 : 빌드 파이프라인의 검사 관문, 메모리 안전 언어로의 점진 전환, 장애 증적 관리가 결합되어야 결함을 근절에 가깝게 줄일 수 있음.
- 개발 조직은 컴파일 보호 옵션과 정적 분석을 빌드 파이프라인의 필수 관문으로 두어, 경고가 남은 코드가 배포되지 않도록 하는 방식이 현실적이다.
- 시스템의 핵심 모듈은 메모리 안전성을 언어 차원에서 보장하는 언어로 점진적으로 옮기고, 기존 코드는 경계 검사를 강화하며 함께 관리하는 전환 로드맵을 세우는 것이 좋다.
- 운영 조직은 코어 덤프 수집과 분석을 장애 대응 절차에 포함해, 재발 건을 결함 유형별로 모아 개발팀의 품질 개선 과제로 되돌리는 체계를 두어야 한다.

## Ⅶ. 결론

- 핵심 요약 : 세그멘테이션 오류는 MMU와 커널이 잘못된 메모리 접근을 즉시 차단하는 보호 장치임.
- 시사점 : 하드웨어 보호만으로 결함이 사라지지 않으므로, 빌드·검사·운영 단계의 증적 관리를 함께 설계해야 결함의 비용이 줄어듦.
