## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 세그먼테이션 오류

## 30초 인출

- 본질: 프로세스가 허용되지 않은 메모리 영역(NULL 주소, 커널 구역, 할당 범위 밖)을 읽거나 쓰려고 시도함
- 메커니즘: 하드웨어 MMU가 예외를 감지하여 커널에 트랩을 걸고 커널이 프로세스에 SIGSEGV 시그널을 보내 즉시 강제 종료시킴

## 핵심 용어

- SIGSEGV: POSIX 운영체제에서 세그먼테이션 위반(Segmentation Violation) 시 프로세스에 전달되는 11번 시그널
- VMA(Virtual Memory Area): 리눅스 커널 내부에서 프로세스가 합법적으로 접근할 수 있는 연속된 가상 메모리 구역(권한 r/w/x 포함)을 관리하는 자료구조
- 코어 덤프(Core Dump): 프로세스가 비정상 종료되는 순간의 메모리 상태, 레지스터 값, 호출 스택(Call Stack)을 디스크 파일로 박제해 두는 디버깅 파일

## 1교시 10점 답안

### Ⅰ. 정의·목적

- 정의: 세그먼테이션 오류은/는 하드웨어 MMU가 예외를 감지하여 커널에 트랩을 걸고 커널이 프로세스에 SIGSEGV 시그널을 보내 즉시 강제 종료시킴 방식이다.
- 목적: 시스템 무결성 및 타 프로세스 오염 방지에 기여한다.

### Ⅱ. 핵심 구조와 작동

```text
[ 세그먼테이션 오류 발생 원인 및 커널 처리 메커니즘 ]

[ 사용자 프로그램 실행 ]
  *ptr = 0;  (ptr == 0x0, 널 포인터 역참조!)
     │
     v (CPU 명령 실행: 0x0 번지에 쓰기 시도)
+─────────────────────────────────────────────────────────────+
| 하드웨어 MMU (Memory Management Unit)                       |
|   1. 0x0 번지 가상 주소 변환 시도                            |
|   2. 페이지 테이블 엔트리(PTE) Present 비트 0 확인          |
|   3. CPU Page Fault (#PF) 예외(Exception) 발생               |
+─────────────────────────────┬───────────────────────────────+
                              │
                              v (커널 모드 전환)
+─────────────────────────────────────────────────────────────+
| 리눅스 커널 (do_page_fault)                                 |
|   1. 프로세스 VMA 리스트에서 0x0 주소 검색                   |
|   2. 할당되지 않은 미매핑 주소(Bad Area) 판정                |
|   3. 프로세스에 SIGSEGV (Signal 11) 전달                    |
+─────────────────────────────┬───────────────────────────────+
                              │
                              v
[ 프로세스 종료 및 core.dump 파일 디스크 저장 (Segmentation Fault) ]
```

## 2~4교시 25점 답안

### Ⅰ. 핵심 구조와 작동

```text
[ 세그먼테이션 오류 발생 원인 및 커널 처리 메커니즘 ]

[ 사용자 프로그램 실행 ]
  *ptr = 0;  (ptr == 0x0, 널 포인터 역참조!)
     │
     v (CPU 명령 실행: 0x0 번지에 쓰기 시도)
+─────────────────────────────────────────────────────────────+
| 하드웨어 MMU (Memory Management Unit)                       |
|   1. 0x0 번지 가상 주소 변환 시도                            |
|   2. 페이지 테이블 엔트리(PTE) Present 비트 0 확인          |
|   3. CPU Page Fault (#PF) 예외(Exception) 발생               |
+─────────────────────────────┬───────────────────────────────+
                              │
                              v (커널 모드 전환)
+─────────────────────────────────────────────────────────────+
| 리눅스 커널 (do_page_fault)                                 |
|   1. 프로세스 VMA 리스트에서 0x0 주소 검색                   |
|   2. 할당되지 않은 미매핑 주소(Bad Area) 판정                |
|   3. 프로세스에 SIGSEGV (Signal 11) 전달                    |
+─────────────────────────────┬───────────────────────────────+
                              │
                              v
[ 프로세스 종료 및 core.dump 파일 디스크 저장 (Segmentation Fault) ]
```

### Ⅱ. 핵심 특성

- 세그먼테이션 오류의 80%는 '0번지(NULL)'를 찔러서 생김 → 초기화되지 않은 포인터나 객체 생성 실패 후 반환된 NULL 포인터를 검증 없이 역참조(`*ptr`)할 때 발생함
- 읽기 전용 영역에 쓰려고 해도 세그먼테이션 오류임 → 주소는 유효하지만 코드 영역(Text)이나 문자열 리터럴(`char *s = "abc"; s[0]='z';`)을 덮어쓰려 하면 MMU 권한 위반으로 즉시 SIGSEGV가 터짐
- 시그널 핸들러로 SIGSEGV를 잡아서 살리는 것은 금물임 → 오류가 난 시점에 이미 메모리 포인터나 스택이 회복 불가능하게 망가진 상태이므로, 핸들러에서 억지로 리턴하면 무한 루프에 빠지거나 더 큰 데이터 파괴를 일으킴

### Ⅲ. 관련 개념과 구분

- 세그먼테이션 오류(SIGSEGV) vs 버스 오류(SIGBUS): 세그먼테이션 오류 = 논리적으로 존재하지 않는 가상 주소나 권한 위반 접근 / 버스 오류 = 가상 주소는 맞으나 물리 메모리 정렬(Alignment)이 안 맞거나 mmap 파일이 물리적으로 잘려나간 경우

### Ⅳ. 적용 문제와 대응

- 사례: 136회 기출 및 대국민 포털 서버에서 간헐적 Segfault 발생으로 웹 서버 프로세스 다운 사태
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 프로덕션 환경에서 Segfault 발생 후 원인 추적 불가능 상태로 프로세스 종료 | OS 커널의 코어 덤프 파일 생성 제한(`ulimit -c 0`) 설정 | `ulimit -c unlimited` 활성화 및 GDB 백트레이스(`bt`) 분석 체계화 | 충돌 시점의 소스코드 라인 및 변수 상태 즉각 규명 |
| C 라이브러리 함수 호출 시 널 포인터 전달로 인한 빈번한 크래시 | 함수의 반환값이나 입력 포인터의 유효성 검사 누락 | 포인터 사용 전 방어적 NULL 체크 매크로 및 정적 분석기(SonarQube) 도입 | 널 역참조 취약점 100% 사전 차단 |
