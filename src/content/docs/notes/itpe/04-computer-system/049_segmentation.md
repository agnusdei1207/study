## 연관 키워드

- 세그멘테이션(Segmentation), 세그먼트(Segment), 세그먼트 테이블(Segment Table), 2차원 논리 주소
- Base·Limit, MMU, 세그먼트 폴트(Segmentation Fault), 페이징(Paging)
- 페이지드 세그멘테이션(Paged Segmentation), 버디 시스템(Buddy System), 최소 권한 원칙(PoLP), W^X

## Ⅰ. 세그멘테이션의 개요

- 핵심 요약 : 프로그램을 논리 모듈 단위의 가변 크기 블록으로 분할하여 모듈 단위 보호와 공유를 실현하는 **세그멘테이션** (Segmentation) 기법.
- 개념 : 프로세스의 주소 공간을 함수, 배열, 스택처럼 프로그래머가 인식하는 논리 단위인 **세그먼트** (Segment)로 나누어 적재·관리하는 메모리 관리 기법.
- 배경 및 필요성 : 연속 할당 방식은 프로그램 모듈의 논리 경계와 물리 메모리 경계가 일치하지 않아 모듈별 보호와 공유를 하드웨어가 강제하기 어려운 구조. 주소 공간을 논리 단위로 가르는 방식이 이 문제의 해법으로 제안된 배경.
- 주요 목적 : 세그먼트 단위 보호(Protection)와 공유(Sharing)의 실현, 실행 중 크기가 변하는 자료구조의 유연한 수용, 프로그래머 관점 주소 공간의 직관화.

## Ⅱ. 세그멘테이션의 특징 및 장점

- 핵심 요약 : 2차원 논리 주소와 세그먼트 테이블, 하드웨어 경계 검사가 맞물려 모듈 단위 보호·공유라는 장점을 만드는 구조.

1. **2차원 논리 주소** (세그먼트 번호 s와 변위 d의 쌍) : 주소 체계가 프로그램 구조를 그대로 반영 → 구조 파악과 디버깅이 쉬움.
2. **세그먼트 테이블** (Segment Table) : 세그먼트마다 **Base·Limit**(Base는 물리 시작 주소, Limit은 최대 길이)를 보관 → 세그먼트가 연속 영역 하나에 매핑되어 변환이 단순하고, 엔트리 공유만으로 세그먼트 단위 공유 가능.
3. 하드웨어 경계 검사 : 변위 d가 Limit 이상이면 **MMU** (Memory Management Unit)가 트랩(Trap)을 발생 → 다른 모듈 영역의 침범을 접근 시점에 차단.
4. 권한 비트 : 엔트리마다 읽기(R)·쓰기(W)·실행(X) 권한을 지정 → 코드 영역 쓰기와 데이터 영역 실행 차단으로 보안 노출 면적 축소.

## Ⅲ. 세그멘테이션의 구조 (흐름)

- 핵심 요약 : 논리 주소 <s, d>를 세그먼트 테이블의 Base·Limit으로 검사·변환하고, Limit 초과 접근은 트랩으로 차단하는 흐름.

```text
[ 세그먼트 주소 변환 흐름 ]

CPU 발행 논리 주소 <s, d>
      ↓
세그먼트 테이블[s] 조회
   (Base·Limit·권한 비트)
      ↓
MMU의 경계·권한 검사
      ↓
물리 주소 = Base + d
      ↓
물리 메모리 접근
```

```text
[ Limit 초과 접근의 차단 ]

접근 요청 <1, 500>
세그먼트 1의 Limit = 400
      ↓
변위 500이 Limit 이상
      ↓
경계 검사 실패 → 트랩 발생
      ↓
운영체제의 폴트 처리 루틴
```

- 구성요소 : 논리 주소는 세그먼트 선택자 s와 변위 d로 구성되고, 세그먼트 테이블은 세그먼트별 시작 위치·길이·권한을 보관하며, MMU는 접근마다 검사를 수행하는 하드웨어.
- 변환 예시 : 세그먼트 1의 Base가 6000이면 <1, 300>은 6300으로 변환되는 정상 접근이고, <1, 500>은 **세그먼트 폴트** (Segmentation Fault)로 처리되는 차단 대상 접근.

## Ⅳ. 세그멘테이션과 페이징의 비교

- 핵심 요약 : 세그멘테이션은 논리 기준의 가변 분할, **페이징** (Paging)은 물리 기준의 고정 분할이며, 페이지드 세그멘테이션은 두 방식의 절충안.

| 비교 항목 | 세그멘테이션 | 페이징 | 페이지드 세그멘테이션 |
| --- | --- | --- | --- |
| 분할 기준 | 논리 단위의 가변 크기 | 물리 단위의 고정 크기 | 세그먼트를 페이지로 재분할 |
| 주소 구조 | 2차원 <s, d> | 1차원 <p, d> | 3차원 <s, p, d> |
| 프로그래머 가시성 | 세그먼트 구조를 인지 | 분할을 인지하지 않음 | 세그먼트만 인지 |
| 보호·공유 단위 | 세그먼트 | 페이지 | 세그먼트(논리)·페이지(할당) |
| 대표 구현 | IA-32 보호 모드 | x86-64 롱 모드 표준 | IA-32의 세그먼트 변환 후 페이징 |

- 선택 기준 : 모듈 경계의 보호와 공유가 설계의 핵심이면 세그멘테이션 계열을, 단순한 변환 구조와 확장성이 핵심이면 페이징을 택하는 판단 기준.

## Ⅴ. 세그멘테이션의 한계와 방안

- 핵심 요약 : 가변 분할의 빈 공간 문제와 할당 탐색 지연, 64비트 환경의 검사 생략을 분할 방식 전환·버디 시스템·페이지 권한 비트로 대응하는 원칙.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 빈 공간의 흩어짐 | 가변 크기 할당의 대가로 적재·해제 반복 시 큰 연속 영역 확보 실패 | 메모리 압축(Compaction) 또는 페이지드 세그멘테이션 전환 | 최대 연속 빈 영역 크기 |
| 할당 탐색 지연 | 최초 적합(First-fit)·최적 적합(Best-fit)이 할당마다 빈 공간 목록을 훑음 | **버디 시스템** (Buddy System)으로 2의 거듭제곱 단위 분할·병합 | 세그먼트 할당 지연 시간 |
| 64비트 환경의 검사 생략 | x86-64 롱 모드에서 세그먼트 레지스터의 Base·Limit 검사가 무력화 | 페이지 테이블 엔트리의 R/W·U/S·NX(No-Execute) 비트로 격리 대체 | 권한 위반 예외 건수 |

## Ⅵ. 세그멘테이션에 대한 기술사적 제언

- 핵심 요약 : 세그먼트의 논리 분리 철학을 프로세스 메모리를 넘어 서비스 권한 설계, 빌드 검증, 실행 환경 경계로 확장하는 방향.

1. 플랫폼 보안 조직은 **최소 권한 원칙** (PoLP, Principle of Least Privilege)을 배포 정책에 반영하여, 세그먼트 권한 분리와 같은 논리로 서비스별 필요 권한만 부여하는 체계를 강제한다.
2. 개발 도구 조직은 **W^X** (Write XOR Execute) 정책을 컴파일·링크 단계 검증 항목으로 두어, 같은 메모리 페이지에 쓰기와 실행 권한의 공존을 빌드 파이프라인에서 차단한다.
3. 응용 개발 조직은 **Wasm** (WebAssembly)의 선형 메모리 경계 검사를 신뢰 경계 설계의 표준 패턴으로 채택하여, 외부 코드에 응용 계층의 격리를 제공한다.

## Ⅶ. 결론

- 핵심 요약 : 세그멘테이션은 논리 모듈 단위 분할로 보호와 공유를 실현한 기법이며, 주소 변환 구조보다 논리 경계를 긋는 설계 철학이 후대에 계승됨.
- 하드웨어 주류는 페이징으로 이동했으나, 논리 단위 격리의 발상은 권한 비트와 샌드박스 설계에 그대로 남아 있는 상태.
