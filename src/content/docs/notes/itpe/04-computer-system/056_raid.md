## 연관 키워드

- RAID, 스트라이핑, 미러링, 패리티, 내결함성, 핫 스페어, 리빌드
- 쓰기 페널티, RAID 0, RAID 1, RAID 5, RAID 6, RAID 10, 에라저 코딩

## Ⅰ. RAID의 개요

- 핵심 요약 : 다수의 디스크를 하나의 논리 볼륨으로 구성하여 입출력 성능과 데이터 신뢰성을 동시에 높이는 디스크 가상화 기술.
- 개념 : 여러 대의 디스크를 묶어 하나의 논리 스토리지로 구성하고, 데이터의 분산·복제·복구 정보 조합으로 성능과 **내결함성** (Fault Tolerance, 일부 장애 발생 시에도 서비스를 유지하는 성질)을 확보하는 **RAID** (Redundant Array of Independent Disks) 기술.
- 배경 및 필요성 : 단일 대형 디스크는 전송 성능의 한계와 단일 장애점 문제가 있어, 여러 대의 디스크를 결합해 성능과 신뢰성을 함께 확보하는 구성이 요구됨.
- 주요 목적 : 병렬 입출력에 따른 대역폭 확보, 디스크 장애 시의 데이터 보존과 서비스 연속성 보장.

## Ⅱ. RAID의 특징 및 장점

- 핵심 요약 : 스트라이핑, 미러링, 패리티, 핫 스페어의 네 기법이 성능과 복구 능력을 각각 담당하는 구조.

1. **스트라이핑** (Striping) : 연속 데이터를 블록 단위로 나눠 여러 디스크에 분산 기록 → 동시 입출력에 따른 대역폭 향상.
2. **미러링** (Mirroring) : 동일 데이터를 복제 저장 → 장애 디스크의 즉시 대체 가능한 신뢰성 확보, 용량 효율 절반의 비용.
3. **패리티** (Parity) : 데이터 블록들의 배타적 논리합으로 복구 정보를 계산·저장 → 장애 디스크 내용의 연산 복원, 미러링 대비 높은 용량 효율.
4. **핫 스페어** (Hot Spare) : 예비 디스크를 상시 대기시키고 장애 감지 시 자동 교체 → **리빌드** (Rebuild, 장애 디스크 데이터의 재구성)를 백그라운드로 수행하는 대응 공백 최소화.

## Ⅲ. RAID의 구조 (흐름)

- 핵심 요약 : 레벨마다 스트라이핑·미러링·패리티의 조합과 데이터 배치가 다르며, 그 차이가 성능과 결함 허용 범위를 결정함.
- 배치 원리 : 패리티는 행마다 다른 디스크로 순환 배치하여 특정 디스크의 쓰기 편중을 방지하고, Ap = A1 ⊕ A2 ⊕ A3 형태의 배타적 논리합으로 복원에 사용함.

```text
[ RAID 0 : 블록 분산 배치 ]

A1 → 디스크 0
A2 → 디스크 1
A3 → 디스크 0
A4 → 디스크 1
```

```text
[ RAID 5 : 패리티 분산 배치 ]

디스크   0    1    2    3
행 1    A1   A2   A3   Ap
행 2    B1   B2   Bp   B3
행 3    C1   Cp   C2   C3
```

```text
[ RAID 10 : 미러링 + 스트라이핑 ]

A1 → 디스크 0 + 디스크 1 (미러 쌍)
   ↓
A2 → 디스크 2 + 디스크 3 (미러 쌍)
```

## Ⅳ. RAID 레벨의 비교

- 핵심 요약 : 레벨에 따라 최소 디스크 수, 용량 효율, 결함 허용 범위, 쓰기 특성이 달라 업무 특성에 맞춘 선택이 필요함.

| RAID 레벨 | 최소 디스크 | 용량 효율 | 결함 허용 | 입출력 특성 | 주 적용 업무 |
| --- | --- | --- | --- | --- | --- |
| RAID 0 | 2대 | 100% | 없음 | 읽기·쓰기 모두 우수 | 임시 작업 공간 |
| RAID 1 | 2대 | 50% | 1대 | 읽기 우수, 쓰기 복제 비용 | 부팅 디스크, 로그 볼륨 |
| RAID 5 | 3대 | (N-1)/N | 1대 | 읽기 우수, 쓰기 페널티 | 파일 서버, 백업 스토리지 |
| RAID 6 | 4대 | (N-2)/N | 2대 동시 | 읽기 우수, 쓰기 페널티 큼 | 대용량 디스크 어레이 |
| RAID 10 | 4대 | 50% | 미러 쌍당 1대 | 읽기·쓰기 모두 우수 | 쓰기 지연에 민감한 데이터베이스 |

- N은 어레이를 구성하는 전체 디스크 수임.
- 선택 기준 : 쓰기 지연이 거래 처리량을 좌우하면 RAID 10, 용량 효율과 2대 동시 장애 대비가 함께 필요하면 RAID 6을 기준으로 삼음.

## Ⅴ. RAID의 한계와 방안

- 핵심 요약 : 재구축 중 추가 고장, 쓰기 페널티, 소프트웨어 RAID의 병목을 이중 패리티, 쓰기 캐시, 전용 처리 구조로 일대일 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 리빌드 중 추가 고장 | 대용량 디스크의 재구축 장시간화 → 재구축 부하와 읽기 오류의 중첩 시 볼륨 손실 | **RAID 6** (이중 패리티로 2대 동시 고장 허용) 전환, **패트롤 읽기** (Patrol Read, 잠재 오류의 주기적 사전 검사) 운영 | 재구축 소요 시간, 잠재 섹터 오류 건수 |
| **쓰기 페널티** (Write Penalty) | 블록 수정 시 기존 데이터와 패리티의 읽기·재계산·재기록 → 쓰기 성능 저하 | 비휘발성 쓰기 캐시와 Write-Back 방식의 적용 | 쓰기 지연 시간, 캐시 적중률 |
| 소프트웨어 RAID의 병목 | 고속 SSD 환경에서 호스트 CPU의 연산·인터럽트 부담 → 성능 상한 도달 | 하드웨어 RAID 컨트롤러, SPDK(Storage Performance Development Kit) 같은 사용자 공간 스토리지 스택 검토 | 초당 입출력 수, CPU 부하율 |

## Ⅵ. RAID에 대한 기술사적 제언

- 핵심 요약 : 볼륨 등급 정책, 분산 저장 전환, 예방 정비의 세 축으로 디스크 장애를 사후 복구가 아닌 관리 대상으로 전환하는 방향.

1. 스토리지 운영 조직 : 데이터 중요도와 지연 민감도에 따라 볼륨 등급을 나누고 등급별 RAID 레벨을 정하는 조직 표준이 바람직함.
2. 클라우드 플랫폼 조직 : 대규모 오브젝트 스토리지는 **에라저 코딩** (Erasure Coding, 데이터와 복구 조각을 여러 장비에 분산 저장하는 부호화 방식) 전환을 로드맵에 두는 방안이 유효함.
3. 장비 운영 조직 : 디스크 자체 진단 정보(S.M.A.R.T. 값)와 핫 스페어 가용 상태를 주기 점검 항목으로 두어 교체 시점을 사전에 결정하는 체계가 필요함.

## Ⅶ. 결론

- 핵심 요약 : RAID는 스트라이핑·미러링·패리티의 조합으로 디스크의 성능과 내결함성을 함께 높이는 기반 기술.
- 레벨 선택은 용량 효율과 쓰기 성능의 균형 문제이므로 업무별 쓰기 패턴의 정의가 선행 조건임.
