## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → RAID

## 30초 인출

- 본질: 단일 하드 드라이브는 물리적 마모로 인한 고장 시 데이터가 영구 유실되고 I/O 대역폭이 제한됨
- 메커니즘: 복수의 디스크에 데이터를 스트라이핑으로 쪼개어 병렬 전송하고 패리티 블록을 분산 저장

## 핵심 용어

- 스트라이핑(Striping): 연속된 데이터를 일정 크기(블록/청크)로 나누어 여러 디스크에 번갈아 가며 분산 저장함으로써 I/O를 병렬화하는 기법
- 쓰기 페널티(Write Penalty): RAID 5에서 단 1블록의 데이터를 갱신할 때, 기존 데이터와 패리티를 읽고 새 패리티를 계산하여 다시 쓰는 과정에서 2번의 읽기와 2번의 쓰기(총 4회 I/O)가 발생하는 현상
- URE(Unrecoverable Read Error): 디스크 리빌딩 중 수십 테라바이트의 섹터를 전수 읽기하는 과정에서 배드 섹터로 인해 읽기가 영구 실패하는 오류

## 2~4교시 25점 답안

### Ⅰ. 핵심 구조와 작동

```text
[ 주요 RAID 레벨별 데이터 및 패리티 배치 구조 ]

RAID 0 (스트라이핑)      RAID 1 (미러링)         RAID 5 (분산 패리티)     RAID 6 (이중 패리티)
 [Disk0]  [Disk1]       [Disk0]  [Disk1]       [Disk0] [Disk1] [Disk2]   [Disk0] [Disk1] [Disk2] [Disk3]
  | A1 |   | A2 |        | A1 |   | A1 |        | A1 |  | A2 |  | Ap |    | A1 |  | A2 |  | Ap |  | Aq |
  | A3 |   | A4 |        | A2 |   | A2 |        | B1 |  | Bp |  | B2 |    | B1 |  | Bp |  | Bq |  | B2 |
  | A5 |   | A6 |        | A3 |   | A3 |        | Cp |  | C1 |  | C2 |    | Cp |  | Cq |  | C1 |  | C2 |
 (속도 최고, 복구불가)   (완전복제, 용량 50%)    (1개 장애극복, N-1용량)   (2개 장애극복, N-2용량)
```

### Ⅱ. 핵심 특성

- RAID 5는 10TB 이상 대용량 디스크 시대에 사실상 사망 선고를 받음 → 디스크 1개가 깨져 새 디스크로 리빌딩하는 수십 시간 동안 남은 디스크들에 극심한 I/O 스트레스가 가해져 URE나 2차 디스크 사망이 발생하면 볼륨 전체가 파괴되기 때문임
- 쓰기 성능이 극도로 중요한 DB에는 무조건 RAID 10(1+0)임 → RAID 5/6는 쓰기 페널티(4회/6회 I/O) 때문에 랜덤 쓰기 성능이 급락하지만, RAID 10은 미러링 기반이라 쓰기 페널티가 2회에 불과하고 리빌딩도 1:1 단순 복사로 끝남
- RAID는 결코 백업이 아님 → 운영자의 실수로 `rm -rf`를 치거나 랜섬웨어에 감염되면 미러링과 패리티 메커니즘을 타고 즉시 모든 디스크에 파괴가 동기화되므로, 논리적 보호는 별도 스냅샷과 오프사이트 백업으로만 가능함

### Ⅲ. 관련 개념과 구분

- RAID vs 이레이저 코딩(Erasure Coding): RAID = 서버/스토리지 내부의 디스크 컨트롤러 단위 하드웨어 결함 극복 / 이레이저 코딩 = 분산 오브젝트 스토리지(Ceph, S3) 환경에서 네트워크로 연결된 서버/랙 단위 결함 극복

### Ⅳ. 적용 문제와 대응

- 사례: 120회 기출 및 16TB HDD 기반 RAID 5 스토리지 리빌딩 중 2차 디스크 불량으로 데이터 완전 유실 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| RAID 5 볼륨 리빌딩 진행 중 70% 시점에서 URE 발생으로 볼륨 파괴 | 대용량 드라이브 리빌드 중 비트 에러율 한계 도달 및 잔여 디스크 과부하 | RAID 6(이중 패리티) 표준 채택 및 예비 디스크(Hot Spare) 상시 가동 | 디스크 2개 동시 결함 시에도 데이터 영구 무손실 |
| RAID 컨트롤러 캐시 미반영 상태에서 정전 시 데이터 불일치(Write Hole) | 전원 공급 차단 시 캐시 메모리의 패리티 갱신 분실 | BBU(Battery Backup Unit) 또는 플래시 기반 캐시 보호 모듈(FBWC) 장착 | 전원 복구 후 비휘발성 캐시로부터 트랜잭션 정상 플러시 |

### Ⅴ. 기술사적 제언

| 문제 | 해결 방안 |
|---|---|
| 적용 환경에서 발생하는 핵심 제약 | 기존 대책을 적용하고 핵심 운영 지표를 확인해 개선한다. |
