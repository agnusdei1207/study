## 연관 키워드

- RAID, 스트라이핑, 미러링, 패리티, 핫 스페어, 리빌드, 쓰기 페널티
- RAID 5, RAID 6, RAID 10, 에라저 코딩, Patrol Read, SPDK

## Ⅰ. RAID(Redundant Array of Independent Disks)의 개요

- 핵심 요약 : **RAID** (Redundant Array of Independent Disks)는 다수 디스크를 하나의 논리 볼륨으로 묶어 스트라이핑, 미러링, 패리티로 성능과 내결함성을 함께 높이는 디스크 가상화 기술.
- 개념 : 여러 대의 디스크를 묶어 하나의 논리 스토리지로 구성하고, 데이터를 나눠 저장하는 **스트라이핑** (Striping, 블록 단위로 여러 디스크에 분산 기록), 같은 데이터를 복제하는 **미러링** (Mirroring), 배타적 논리합 연산으로 복구 정보를 만드는 **패리티** (Parity)를 조합하여 입출력 성능과 **내결함성** (Fault Tolerance, 일부 구성 요소가 고장 나도 서비스를 유지하는 성질)을 높이는 기술. 대상 디스크는 하드디스크(HDD, Hard Disk Drive)나 솔리드 스테이트 드라이브(SSD, Solid-State Drive)임.
- 배경 및 필요성 : 단일 대형 디스크는 속도에 한계가 있고 한 대의 고장이 곧 데이터 손실로 이어져 운영 비용과 위험이 큼. 이를 해소하기 위해 저가의 디스크를 묶어 성능과 신뢰성을 함께 확보하는 방식이 1988년 버클리 대학 연구진에 의해 제안됨 (SLED, Single Large Expensive Disk 대안).
- 핵심 목적 : 병렬 입출력으로 대역폭 확보, 디스크 장애 시에도 서비스 연속성과 데이터 무손실 보장.

## Ⅱ. RAID(Redundant Array of Independent Disks)의 특징 및 장점

- 핵심 요약 : 스트라이핑, 미러링, 패리티, 핫 스페어 네 기법이 성능과 복구 능력을 각각 담당하는 구조.

1. 스트라이핑 : 연속된 데이터를 블록 단위로 나눠 여러 디스크에 번갈아 기록 → 동시 입출력이 가능해 대역폭 향상.
2. 미러링 : 동일한 데이터를 두 대 이상에 복제 → 디스크 장애 시 즉시 대체 가능한 신뢰성 확보, 대신 용량 효율 저하.
3. 패리티 : `P = D1 ⊕ D2 ⊕ D3` 형태로 배타적 논리합(XOR, Exclusive OR) 값을 계산하고, 장애 디스크의 내용을 나머지 데이터와 패리티의 XOR로 복원 → 미러링보다 높은 용량 효율로 내결함성 확보.
4. 핫 스페어(Hot Spare) : 장애 디스크를 감지하면 예비 디스크로 즉시 대체하여 재구축(리빌드, Rebuild)을 백그라운드에서 수행 → 장애 대응 공백 최소화.

## Ⅲ. RAID(Redundant Array of Independent Disks)의 구조 및 동작 메커니즘

- 핵심 요약 : 레벨별로 스트라이핑, 미러링, 패리티를 다르게 조합한 데이터 배치 방식의 차이가 성능과 결함 허용 범위를 결정함.
- RAID 0은 성능만, RAID 1은 신뢰성만 추구하며, RAID 5와 6은 패리티로 용량 효율을 확보하고, RAID 10은 미러와 스트라이핑을 중첩함.

```text
[ RAID 0 : 블록을 번갈아 분산 ]

A1 → 디스크 0
A2 → 디스크 1
A3 → 디스크 0
A4 → 디스크 1
(1대 고장 시 전체 데이터 손실)
```

```text
[ RAID 1 : 같은 블록을 복제 ]

A1 → 디스크 0 + 디스크 1
A2 → 디스크 0 + 디스크 1
(1대 고장 시 나머지 디스크로 서비스 유지)
```

```text
[ RAID 5 : 패리티 분산 배치 ]

디스크   0    1    2    3
행 1    A1   A2   A3   Ap
행 2    B1   B2   Bp   B3
행 3    C1   Cp   C2   C3

Ap = A1 ⊕ A2 ⊕ A3
```

```text
[ RAID 10 : 미러 쌍을 스트라이핑 ]

미러 쌍 1  디스크 0 ↔ 디스크 1  (A1 복제)
   ↓ 스트라이핑
미러 쌍 2  디스크 2 ↔ 디스크 3  (A2 복제)
```

## Ⅳ. RAID(Redundant Array of Independent Disks)의 비교

- 핵심 요약 : 레벨에 따라 최소 디스크 수, 용량 효율, 결함 허용 범위, 성능 특성이 달라 업무 특성에 맞춘 선택이 필요함.

| RAID 레벨 | 최소 디스크 수 | 용량 효율 | 결함 허용 | 읽기·쓰기 특성 | 주 적용 업무 |
| --- | --- | --- | --- | --- | --- |
| RAID 0 | 2대 | 100% (N) | 없음 | 성능 우수, 장애 내성 없음 | 임시 작업 공간 |
| RAID 1 | 2대 | 50% (N/2) | 1대 | 읽기 우수, 쓰기는 복제 비용 발생 | 운영체제 부팅 디스크, 로그 볼륨 |
| RAID 5 | 3대 | (N-1)/N | 1대 | 읽기 우수, 쓰기 페널티 발생 | 일반 파일 서버, 백업 스토리지 |
| RAID 6 | 4대 | (N-2)/N | 2대 동시 | 읽기 우수, 쓰기 페널티 큼 | 대용량 디스크 어레이 |
| RAID 10 | 4대 | 50% (N/2) | 미러 쌍마다 1대 | 읽기·쓰기 모두 우수 | 쓰기 지연에 민감한 데이터베이스 |

- N은 어레이를 구성하는 전체 디스크 수임.
- 선택 기준 : 쓰기 지연이 거래 처리량을 좌우하면 RAID 10을, 용량 효율과 2대 동시 장애 대비가 함께 필요하면 RAID 6을 기준으로 삼음.

## Ⅴ. RAID(Redundant Array of Independent Disks)의 한계와 방안

- 핵심 요약 : 재구축 중 추가 고장, 쓰기 페널티, SSD 환경의 CPU 병목을 이중 패리티, 쓰기 캐시, 고성능 스토리지 구조로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| RAID 5 리빌드 중 추가 고장 | 대용량 디스크의 재구축에 장시간이 걸리고, 재구축 부하나 재구축 중 읽기 오류(URE, Unrecoverable Read Error)가 겹치면 전체 볼륨 손실 | RAID 6으로 전환, 정기 **패트롤 읽기** (Patrol Read)로 잠재 오류 사전 검출 | 재구축 소요 시간, 잠재 섹터 오류 건수 |
| **쓰기 페널티** (Write Penalty) | 단일 블록 수정에도 기존 데이터와 패리티 읽기, 새 패리티 계산과 쓰기가 추가되어 쓰기 성능 저하 | 비휘발성 쓰기 캐시와 Write-Back 캐싱 모드 적용 | 쓰기 지연 시간, 쓰기 캐시 사용률 |
| 고속 SSD 환경의 CPU 병목 | 비휘발성 메모리 익스프레스(NVMe, Non-Volatile Memory Express) SSD에 레거시 컨트롤러나 단일 스레드 소프트웨어 RAID를 적용하면 CPU 인터럽트 병목 발생 | 네트워크 기반 NVMe-oF(NVMe over Fabrics) 구조, SPDK(Storage Performance Development Kit) 활용, Ceph·ZFS 같은 소프트웨어 정의 스토리지 도입 | 초당 입출력 수, CPU 인터럽트 부하 |

## Ⅵ. RAID(Redundant Array of Independent Disks)의 기술사적 제언

- 핵심 요약 : 볼륨 등급별 RAID 정책, 오브젝트 스토리지의 에라저 코딩 전환, 예방 정비 체계를 묶어 디스크 장애를 사후 복구가 아닌 관리 대상으로 전환.

1. 볼륨 등급별 정책 : 데이터 중요도와 지연 민감도에 따라 볼륨 등급을 나누고, 등급마다 RAID 레벨을 정하는 조직 표준을 두는 것이 바람직함.
2. 에라저 코딩 전환 : 대규모 클라우드 오브젝트 스토리지는 디스크 어레이 대신 RS(Reed-Solomon) 계열 에라저 코딩(Erasure Coding)으로 데이터와 복구 조각을 여러 장비에 나누는 방식을 검토함.
3. 예방 정비 체계 : 핫 스페어의 가용 상태를 주기적으로 점검하고, S.M.A.R.T.(Self-Monitoring, Analysis and Reporting Technology)의 배드 섹터 증가 추이로 교체 시점을 미리 정하는 운영이 필요함.

## Ⅶ. 결론

- 핵심 요약 : RAID는 스트라이핑, 미러링, 패리티의 조합으로 디스크의 성능과 내결함성을 높이는 기반 기술이며, 재구축과 쓰기 비용의 관리가 핵심 과제임.
- 시사점 : 레벨 선택은 용량 효율과 쓰기 성능의 트레이드오프이므로, 업무별 쓰기 패턴과 장애 허용 기준을 먼저 정의하는 것이 선행되어야 함.
