## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 상호연결망

## 30초 인출

- 본질: 노드 수가 늘어날수록 단순 버스(Bus)는 대역폭 고갈로 마비됨
- 메커니즘: 노드들을 2차원/3차원 격자, 큐브, 다단계 스위치 트리로 체계적으로 연결하여 데이터 전송 경로를 다중화

## 핵심 용어

- 네트워크 지름(Diameter): 네트워크 내의 임의의 두 노드 간 최단 경로들 중 가장 긴 홉(Hop) 수로, 시스템의 최악 전송 지연을 결정하는 척도
- 이등분 대역폭(Bisection Bandwidth): 네트워크를 노드 수가 같은 두 개의 부분으로 양분했을 때 두 영역을 연결하는 링크들의 총 통신 용량으로, 글로벌 통신 성능의 핵심 지표
- 웜홀 라우팅(Wormhole Routing): 패킷을 작은 플릿(Flit: Flow Control Unit) 단위로 쪼개어, 전체 패킷이 도착하길 기다리지 않고 헤더 플릿이 도착하는 즉시 다음 노드로 밀어내는 초저지연 스위칭 기법

## 1교시 10점 답안

### Ⅰ. 정의·목적

- 정의: 상호연결망은/는 노드들을 2차원/3차원 격자, 큐브, 다단계 스위치 트리로 체계적으로 연결하여 데이터 전송 경로를 다중화 방식이다.
- 목적: 노드 간 홉 수 단축 및 양분 대역폭 대폭 확장에 기여한다.

## 2~4교시 25점 답안

### Ⅰ. 핵심 구조와 작동

```text
[ 상호연결망의 대표 토폴로지(Topology) 구조 비교 ]

1. 메쉬 (2D Mesh)            2. 2D 토러스 (2D Torus)         3. 펫 트리 (Fat-Tree)
   (끝단 개방)                  (끝단 순환 랩어라운드)           (상위로 갈수록 링크 대역폭 확장)
   O ─── O ─── O               ┌─── O ─── O ─── O ───┐               [ Root Switch ]
   │     │     │               │    │     │     │    │               /      │      \
   O ─── O ─── O               │    O ─── O ─── O    │       [ Spine ]   [ Spine ]   [ Spine ]
   │     │     │               │    │     │     │    │        /   \       /   \       /   \
   O ─── O ─── O               └─── O ─── O ─── O ───┘      [Leaf] [Leaf] [Leaf] [Leaf] ...
  - 지름: 2*(N-1)             - 지름: N (지름 절반 감소)      - Non-blocking 전송 보장
```

### Ⅱ. 핵심 특성

- 완벽한 크로스바(Crossbar)는 존재할 수 없음 → 모든 노드가 1:1로 직접 연결되는 크로스바 스위치는 이상적이지만 비용이 $O(N^2)$으로 폭증하므로, 수천 노드 환경에서는 $O(N \log N)$의 복잡도를 가진 Fat-Tree나 다차원 Torus로 타협하는 것이 필수적임
- 토러스의 랩어라운드(Wrap-around) 링크가 지름을 반토막 냄 → 일반 메쉬는 모서리 노드 간 통신 시 먼 길을 돌아가야 하지만, 양 끝단을 둥글게 이어 도넛 형태로 만들면 최대 홉 수가 절반으로 줄어듦
- 최신 AI 슈퍼컴퓨터의 승자는 Fat-Tree임 → 엔비디아 슈퍼POD 및 대규모 GPU 클러스터는 노드 간 All-to-All 통신 시 병목이 발생하지 않도록 상위 코어 스위치로 갈수록 링크를 굵게 묶는 무폐색(Non-blocking) Fat-Tree 토폴로지를 글로벌 표준으로 채택함

### Ⅲ. 관련 개념과 구분

- 상호연결망 vs LAN/WAN: 상호연결망 = 수 미터~수 센티미터 이내 초고속 초저지연(나노초 단위) 내부 병렬 처리 패브릭 / LAN/WAN = 수십 미터~수천 킬로미터 범위의 표준 IP 패킷 라우팅망

### Ⅳ. 적용 문제와 대응

- 사례: 125회 기출 및 1024 노드 병렬 시뮬레이션 중 패킷 버퍼 정체로 인한 라우터 데드락 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 순환 경로에서 패킷들이 서로의 버퍼 해제를 기다리며 통신이 영구 정지 | 웜홀 라우팅 환경에서의 순환 의존성(Routing Deadlock) 발생 | 차원 순서 라우팅(Dimension-Order: X-Y 라우팅) 및 가상 채널 적용 | 라우팅 경로의 사이클 원천 제거로 통신 무교착 보장 |
| 코어 스위치 구간의 트래픽 집중으로 인한 패킷 드롭 및 지연 폭증 | 불균형한 오버서브스크립션(Over-subscription) 설계 | 1:1 무폐색(Non-blocking) Fat-Tree 토폴로지 구축 | 노드 간 동시 최대 대역폭 보장 및 지연 시간 80% 단축 |

### Ⅴ. 기술사적 제언

| 문제 | 해결 방안 |
|---|---|
| 적용 환경에서 발생하는 핵심 제약 | 기존 대책을 적용하고 핵심 운영 지표를 확인해 개선한다. |
