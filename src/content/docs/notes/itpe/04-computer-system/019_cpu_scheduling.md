## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → CPU 스케줄링

## 30초 인출

- 본질: 단일/다중 CPU 코어를 둘러싼 다수 프로세스의 점유 경쟁 및 I/O 대기로 인한 CPU 유휴(Idle) 낭비
- 메커니즘: 시스템 목표(처리량, 응답 시간, 반환 시간)에 맞춰 준비 큐의 프로세스 중 최적 대상을 선별해 CPU를 할당

## 핵심 용어

- 디스패처(Dispatcher): CPU 스케줄러가 선택한 프로세스에게 실제로 CPU 제어권을 넘겨주는 커널 모듈로, 문맥 교환, 유저 모드 전환, PC 레지스터 복구를 수행
- 다단계 피드백 큐(MLFQ: Multi-Level Feedback Queue): 프로세스의 CPU 버스트 특성에 따라 우선순위가 다른 여러 큐 사이를 동적으로 이동시키는 적응형 스케줄링 기법
- CFS(Completely Fair Scheduler): 리눅스 표준 스케줄러로, 가상 런타임(vruntime)을 기반으로 레드블랙트리(Red-Black Tree)를 구성하여 가장 덜 실행된 프로세스에 CPU를 균등 배분

## 1교시 10점 답안

### 정의·목적

- 정의: CPU 스케줄링은/는 시스템 목표(처리량, 응답 시간, 반환 시간)에 맞춰 준비 큐의 프로세스 중 최적 대상을 선별해 CPU를 할당 방식이다.
- 목적: CPU 이용률 극대화 및 대화형 응답성 보장에 기여한다.

### 핵심 구조와 작동

```text
[ New ] ──(장기 스케줄러: 메모리 적재)──> [ Ready Queue (준비 큐) ]
                                                    │
                                           (단기 스케줄러 & 디스패처)
                                                    │
                                                    v
                     [ Terminated ] <── [ Running (CPU 실행) ]
                                          │            ▲
                      (I/O 요청: Blocked) │            │ (타임 퀀텀 만료: 선점)
                                          v            │
                                    [ Waiting Queue ] ─┘ (I/O 완료)
```

## 2~4교시 25점 답안

### Ⅰ. 핵심 구조와 작동

```text
[ New ] ──(장기 스케줄러: 메모리 적재)──> [ Ready Queue (준비 큐) ]
                                                    │
                                           (단기 스케줄러 & 디스패처)
                                                    │
                                                    v
                     [ Terminated ] <── [ Running (CPU 실행) ]
                                          │            ▲
                      (I/O 요청: Blocked) │            │ (타임 퀀텀 만료: 선점)
                                          v            │
                                    [ Waiting Queue ] ─┘ (I/O 완료)
```

### Ⅱ. 핵심 특성

- 완벽한 만능 스케줄러는 존재하지 않으며 항상 트레이드오프임 → SJF(Shortest Job First)는 수학적으로 '최소 평균 대기 시간'을 보장하지만, 미래의 CPU 버스트 시간을 알 수 없어 실무 적용 불가
- 시분할 시스템의 핵심인 라운드 로빈(RR)에서 타임 슬라이스(Time Quantum) 크기 설정이 성능을 좌우 → 너무 크면 FCFS로 퇴보하여 호위 효과 발생, 너무 작으면 문맥 교환 오버헤드가 CPU 사이클을 잠식
- 현대 OS(Linux)는 고정 우선순위 대신 CPU를 덜 사용한 대화형(I/O 바운드) 프로세스에 우선순위 보너스를 주어 사용자 체감 응답성을 극대화하도록 설계됨

### Ⅲ. 관련 개념과 구분

- 선점(Preemptive) vs 비선점(Non-preemptive): 선점 = 실행 중인 프로세스로부터 강제로 CPU를 빼앗을 수 있음(현대 OS 표준, 응답성 우수) / 비선점 = 프로세스가 스스로 CPU를 반납하거나 I/O를 만날 때까지 보장(문맥 교환 적음, 독점 위험)

### Ⅳ. 적용 문제와 대응

- 사례: 137회 기출 실시간 대화형 서비스와 대규모 배치 연산 동시 구동 시 응답 지연 및 기아 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 우선순위가 낮은 백그라운드 배치 프로세스가 수 시간 동안 CPU를 할당받지 못함 | 정적 우선순위 스케줄링으로 인한 기아 현상(Starvation) | 에이징(Aging) 기법 적용 (대기 시간에 비례하여 우선순위 점진 승격) | 모든 프로세스의 유한 시간 내 실행 보장 |
| 컨테이너 CPU 제한(Limit) 도달 시 웹 응답 지연 10배 폭증 | 리눅스 CFS의 CPU 대역폭 제어(Quota/Period)에 의한 스로틀링(Throttling) | 타임 슬라이스(Period) 주기 단축 및 버스트(Burst) 할당 설정 활성화 | 순간 트래픽 폭주 시 불필요한 스로틀링 완화 |

### Ⅴ. 기술사적 제언

| 문제 | 해결 방안 |
|---|---|
| 적용 환경에서 발생하는 핵심 제약 | 기존 대책을 적용하고 핵심 운영 지표를 확인해 개선한다. |
