## 연관 키워드

- CPU 스케줄링(CPU Scheduling), 준비 큐(Ready Queue), 디스패처(Dispatcher), 문맥 교환
- 선점형 스케줄링, 비선점형 스케줄링, 타임 슬라이스(Time Slice), CPU·I/O 버스트
- 평가 기준, CPU 이용률, 처리량, 반환 시간, 대기 시간, 응답 시간
- 기아 현상(Starvation), 에이징(Aging), 호송 효과(Convoy Effect)

## Ⅰ. CPU 스케줄링의 개요

- 핵심 요약 : CPU 코어보다 많은 실행 대상 프로세스에 한정된 CPU를 규칙에 따라 배분하는 운영체제의 핵심 기능.
- 개념 : 준비 큐에서 대기하는 프로세스 가운데 누구에게 CPU를 언제, 얼마나 부여할지 결정하는 운영체제 커널의 자원 배분 기능인 **CPU 스케줄링** (CPU Scheduling).
- 배경 및 필요성 : 시분할 환경에서는 실행 대기 프로세스 수가 CPU 코어 수를 웃돌아, 배분 규칙이 없으면 유휴 시간과 응답 지연이 누적되는 상황.
- 주요 목적 : 평가 기준인 CPU 이용률과 처리량의 극대화, 반환 시간·대기 시간·응답 시간의 최소화, **기아 현상** (Starvation, 우선순위가 낮은 프로세스의 무기한 대기) 방지에 따른 공정성 확보.

## Ⅱ. CPU 스케줄링의 특징 및 장점

- 핵심 요약 : 문맥 교환, 디스패처, 시간 분할, 워크로드 특성 판단이 결합되어 공정하고 빠른 CPU 배분을 실현하는 구조.

1. **문맥 교환** (Context Switch) : 실행 중 프로세스의 레지스터·프로그램 카운터를 PCB(Process Control Block)에 저장하고 다음 프로세스의 문맥을 복원하는 절차 → 다중 프로세스의 동시 실행 환경 제공.
2. **디스패처** (Dispatcher) : 스케줄러가 선택한 프로세스에 CPU 제어권을 실제로 넘기는 커널 모듈 → 전환 소요 시간의 최소화가 응답성 확보의 전제 조건.
3. **타임 슬라이스** (Time Slice, 연속 점유 허용 시간) : 정해진 시간 경과 후 CPU를 강제 반환하는 시분할 단위 → 대화형 작업의 빠른 응답 확보.
4. **CPU 버스트와 I/O 버스트** (Burst) : 프로세스가 연산 구간과 입출력 대기 구간을 번갈아 수행하는 특성 → 두 유형 작업의 혼합 배분으로 전체 처리 효율 향상.

## Ⅲ. CPU 스케줄링의 구조 (흐름)

- 핵심 요약 : 준비 큐 대기 → 스케줄러 선택 → 디스패처 전환 → 실행 → 재진입의 순환 구조.

```text
[ 스케줄링 순환 흐름 ]

생성 프로세스의 준비 큐 진입
        ↓
스케줄러 : 실행 대상 선택
        ↓
디스패처 : 문맥 교환 수행
        ↓
CPU 코어에서 프로세스 실행
        ↓
타임 슬라이스 종료·I/O 대기
        ↓
준비 큐 또는 대기 큐로 복귀
```

```text
[ 스케줄링 결정 시점 ]

1. 실행 → 대기 : I/O 요청 시
2. 실행 → 준비 : 타이머 인터럽트 시
3. 대기 → 준비 : I/O 완료 시
4. 실행 → 종료 : 프로세스 종료 시
```

- 1·4번은 CPU 강제 회수 없이도 발생하는 전환 시점이고, 2·3번은 회수 여부 판단이 필요한 시점.

## Ⅳ. 선점형과 비선점형 스케줄링의 비교

- 핵심 요약 : CPU 회수 방식의 차이가 응답성·오버헤드·공정성에서 서로 다른 절충점을 만드는 **선점형 스케줄링** (Preemptive Scheduling)과 **비선점형 스케줄링** (Non-preemptive Scheduling)의 구조.

| 비교 축 | 선점형 스케줄링 | 비선점형 스케줄링 |
| --- | --- | --- |
| CPU 회수 | 타이머·높은 우선순위 도착 시 강제 회수 | 종료·I/O 대기 시 자발적 반납 |
| 응답성 | 높음, 대화형·실시간에 적합 | 낮음, 긴 작업이 후속 요청을 지연 |
| 전환 빈도 | 문맥 교환이 잦아 오버헤드 증가 | 전환이 적어 오버헤드 절약 |
| 공정성 제어 | 우선순위 기반 제어 가능 | 도착 순서·작업 길이 의존 |
| 대표 기법 | 라운드 로빈(Round Robin), SRTF(Shortest Remaining Time First), MLFQ(Multilevel Feedback Queue), CFS(Completely Fair Scheduler) | FCFS(First-Come, First-Served), SJF(Shortest Job First) |
| 적합 환경 | 시분할·실시간·사용자 인터페이스 | 일괄 처리 중심 계산 |

- 선택 기준 : 응답 시간이 성패를 가르는 대화형 서비스에는 선점형이, 계산 완결성과 전환 비용 최소화가 중요한 일괄 처리에는 비선점형이 유리한 판단 기준.

## Ⅴ. CPU 스케줄링의 한계와 방안

- 핵심 요약 : 기아 현상, 호송 효과, 전환 오버헤드를 에이징, 시간 분할 정책, 전환 최소화 설계로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 기아 현상 | 우선순위 기준에서 낮은 프로세스의 대기 누적 → 응답 보장 상실 | **에이징** (Aging, 대기 시간에 비례한 우선순위 점진 상향) 적용 | 최대 대기 시간 |
| **호송 효과** (Convoy Effect, 선행 긴 작업이 후속 작업 전체를 늦추는 지연) | 긴 연산 작업이 큐 앞자리에 머물며 나머지 요청이 일제 지연 | 시간 분할 기반 선점 정책으로 짧은 작업의 조기 실행 보장 | 평균 대기 시간 |
| 전환 오버헤드 | 지나치게 짧은 타임 슬라이스가 전환 비용 비중을 확대 | 슬라이스 하한 설정, 스레드 병합·배치 튜닝 | 초당 문맥 교환 횟수 |

## Ⅵ. CPU 스케줄링에 대한 기술사적 제언

- 핵심 요약 : 워크로드 분류 기준, 측정 기반 튜닝 절차, 가상화 환경 자원 정책을 운영 표준으로 정비하는 방향.
- 서비스 운영 조직은 응답 지연 민감도에 따라 워크로드를 대화형·처리량 중심·후순위 작업으로 분류하고, 클래스별 스케줄링 정책을 문서화하는 기준 수립 필요.
- 성능 엔지니어링 조직은 이용률·처리량·대기 시간 지표를 상시 수집하고, 커널 업데이트와 설정 변경 전후의 벤치마크 비교 검증 절차 운영 필요.
- 플랫폼 운영 조직은 컨테이너의 CPU 요청량과 상한값을 애플리케이션 특성에 맞게 산정하고, 경합이 잦은 워크로드를 노드 단위로 분리하는 배치 정책 수립 필요.

## Ⅶ. 결론

- 핵심 요약 : CPU 스케줄링은 이용률·처리량·응답성의 균형을 만드는 운영체제의 핵심 자원 배분 기능.
- 최적 알고리즘은 워크로드에 따라 달라지므로, 측정 지표 기반의 정책 선택과 조정이 스케줄링 품질의 결정 조건.
