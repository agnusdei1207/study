## 연관 키워드

- CPU 스케줄링(CPU Scheduling), 준비 큐(Ready Queue), 디스패처(Dispatcher), 선점형·비선점형 스케줄링
- FCFS, SJF, SRTF, 라운드 로빈(Round Robin), MLFQ, CFS, 타임 퀀텀(Time Quantum)
- 기아 현상(Starvation), 에이징(Aging), 호송 효과(Convoy Effect), 문맥 교환
- EAS, NUMA, big.LITTLE, CFS Quota, CPU 핀닝(Pinning)

## Ⅰ. CPU 스케줄링(CPU Scheduling)의 개요

- 핵심 요약 : 한정된 CPU를 준비 큐의 프로세스에 공정하고 효율적으로 배분해 이용률과 처리량을 높이는 운영체제 기능.
- 개념 : 다중 프로그래밍 환경에서 한정된 CPU(Central Processing Unit)를 **준비 큐** (Ready Queue, 실행을 기다리는 프로세스의 대기열)에 있는 프로세스나 스레드에 배분하는 순서와 시간 할당량을 정하는 운영체제 커널 기능인 **CPU 스케줄링** (CPU Scheduling).
- 배경 및 필요성 : 실행 가능한 프로세스가 CPU 코어보다 훨씬 많은 시분할 환경에서는 CPU 유휴 시간이 쌓여 자원 낭비와 응답 지연이 생기므로, 배분 규칙을 커널이 체계적으로 관리하는 계층이 필요함.
- 주요 목적 : CPU 이용률과 처리량의 극대화, 반환 시간과 대기 시간의 최소화, **기아 현상** (Starvation, 특정 프로세스가 무기한 대기하는 상태) 방지를 통한 공정성 확보.

## Ⅱ. CPU 스케줄링(CPU Scheduling)의 특징 및 장점

- 핵심 요약 : 선점 여부, 디스패처, 가중치 기반 공정 선택이 결합되어 공정하고 효율적인 CPU 배분을 만드는 구조.

1. **선점형 스케줄링** (Preemptive Scheduling) : 타이머 인터럽트나 높은 우선순위 프로세스 등장 시 OS가 CPU를 강제로 회수 → 응답성과 공정성 확보. 라운드 로빈, SRTF(Shortest Remaining Time First), MLFQ(Multilevel Feedback Queue), CFS가 여기에 속함.
2. **비선점형 스케줄링** (Non-preemptive Scheduling) : 프로세스가 I/O 요청이나 종료로 스스로 CPU를 내놓을 때까지 점유 → 문맥 교환 횟수가 적으나 긴 작업이 뒤를 막는 호송 효과 발생 가능. FCFS(First-Come, First-Served), SJF(Shortest Job First)가 대표적임.
3. **디스패처** (Dispatcher) : 스케줄러가 고른 프로세스에 실제 CPU 제어권을 넘기는 모듈 → 문맥 교환 지연 시간을 줄이는 것이 핵심 설계 목표.
4. **CFS** (Completely Fair Scheduler, 완전 공정 스케줄러) : nice 값에 따른 가중치를 부여하고 가상 실행 시간(vruntime)이 가장 작은 태스크를 레드-블랙 트리에서 O(log N)으로 선택 → 가중치 기준의 공정한 CPU 배분.

## Ⅲ. CPU 스케줄링(CPU Scheduling)의 구조 및 동작 메커니즘

- 핵심 요약 : 준비 큐에서 스케줄러가 프로세스를 고르고, 디스패처가 문맥을 전환해 CPU 코어에서 실행하는 순환 흐름.
- 단기 스케줄러가 준비 큐에서 다음 프로세스를 고르면 디스패처가 기존 문맥을 저장하고 새 문맥을 복원함. 현대 리눅스는 가상 실행 시간 기반의 CFS 알고리즘을 사용함.

```text
[ CPU 스케줄링 기본 흐름 ]

준비 큐 (Ready Queue)
        ↓
단기 스케줄러 (알고리즘 선택)
        ↓
디스패처 (문맥 저장·복원)
        ↓
CPU 코어 (프로세스 실행)
```

```text
[ 실행 후 재진입 경로 ]

CPU 코어 실행 중
        ↓
I/O 요청 또는 타이머 인터럽트
        ↓
대기 큐 또는 준비 큐로 재진입
        ↓
다음 선택 주기에 다시 디스패치
```

## Ⅳ. CPU 스케줄링(CPU Scheduling)의 비교

- 핵심 요약 : FCFS, SJF, SRTF, RR, MLFQ, CFS가 선점 여부와 공정성 기준에서 서로 다른 절충점을 가지는 구조.

| 스케줄링 알고리즘 | 선점 여부 | 핵심 메커니즘 | 장점과 단점 |
| --- | --- | --- | --- |
| FCFS | 비선점 | 준비 큐에 도착한 순서대로 할당 | 단순하나 긴 작업에 의한 호송 효과 발생 |
| SJF | 비선점 | CPU 버스트가 가장 짧은 프로세스 우선 | 평균 대기 시간이 짧으나 긴 프로세스의 기아 유발 |
| SRTF | 선점 | 남은 버스트가 더 짧은 프로세스 도착 시 선점 | 반응성이 높으나 잦은 문맥 교환 부담 |
| 라운드 로빈 | 선점 | 고정된 타임 퀀텀 동안 순환 실행 | 공정하고 대화형에 적합하나 퀀텀 튜닝 필요 |
| MLFQ | 선점 | 다단계 큐 사이를 작업 특성에 따라 이동 | 사전 정보 없이 적응하나 구현이 복잡함 |
| CFS | 선점 | 레드-블랙 트리 기반 가상 실행 시간 추적 | 가중치 기준 공정성이 높고 현대 리눅스 표준 |

- 선택 기준 : 단일 최적 알고리즘은 없으므로, 처리량이 중요한 서버 워크로드와 응답 시간이 중요한 데스크톱·모바일 환경을 나누어 튜닝하는 것이 현실적임.

## Ⅴ. CPU 스케줄링(CPU Scheduling)의 한계와 방안

- 핵심 요약 : 타임 퀀텀 딜레마, 기아 현상, 이기종 코어와 NUMA 불균형을 적응형 튜닝, 에이징, 에너지 인지 배치로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 타임 퀀텀 설정 딜레마 | 퀀텀이 작으면 문맥 교환 오버헤드가 급증, 크면 FCFS처럼 변질되어 대화형 응답 저하 | 부하에 따라 퀀텀을 조절하는 적응형 스케줄링, 프로세서 친화도(Affinity) 유지 | 문맥 교환 횟수, 응답 시간 |
| 기아 현상 | 짧은 작업이 계속 유입되면 긴 작업이 무기한 대기 | **에이징** (Aging, 대기 시간에 비례해 우선순위를 점진적으로 승격) 적용 | 최대 대기 시간 |
| 이기종 코어와 NUMA 불균형 | big.LITTLE 구조의 성능 코어와 효율 코어 간 성능 격차, 원격 메모리 접근 지연 | **EAS** (Energy Aware Scheduling, 에너지 인지 스케줄링) 적용, NUMA 노드의 로컬 메모리 인지형 배치 | 코어별 부하 편차, 원격 메모리 접근 비율 |

## Ⅵ. CPU 스케줄링(CPU Scheduling)에 대한 기술사적 제언

- 핵심 요약 : 컨테이너 쿼터, 코어 핀닝, 이기종 오케스트레이터를 워크로드 성격에 맞게 나누어 적용하는 운영 체계.
- 컨테이너 기반 서비스 운영자는 CPU Limit에 도달할 때 생기는 CFS Quota 스로틀링을 모니터링하고, 자원 사이징은 CPU Request를 중심으로 설계하는 편이 바람직하다.
- 초저지연 패킷 처리나 거래 시스템을 맡은 팀은 커널 부팅 옵션 isolcpus로 코어를 일반 스케줄링에서 떼어 내고, 핵심 스레드를 전용 코어에 고정하는 CPU 핀닝(Pinning)을 적용해야 한다.
- AI와 HPC 클러스터를 여러 팀이 함께 쓸 때는 Slurm, Ray 같은 이기종 오케스트레이터로 작업 큐를 통합 관리하는 체계를 두는 것이 효과적이다.

## Ⅶ. 결론

- 핵심 요약 : CPU 스케줄링은 공정하고 효율적인 CPU 배분으로 이용률, 처리량, 응답 시간의 균형을 맞추는 커널 기능.
- 시사점 : 단일 최적 알고리즘이 없으므로, 워크로드 특성과 자원 격리 방식을 함께 설계해야 스케줄링 효과가 나타남.
