## 연관 키워드
- CPU 스케줄링, 선점, 비선점, 문맥 교환, 응답시간, 기아

## Ⅰ. CPU 스케줄링의 개요
- 핵심 요약 : CPU 스케줄링은 준비 상태 프로세스 중 다음 실행 대상을 선택해 CPU 이용과 응답성을 조정하는 운영체제 기능.
- 개념 : **CPU 스케줄링**(CPU Scheduling)은 실행 가능 프로세스·스레드에 프로세서를 배분하는 정책과 알고리즘.
- 배경 및 필요성 : 다중 작업의 CPU 요청이 동시 발생해 공정하고 효율적인 실행 순서 필요.
- 목적 : 처리량·대기시간·응답시간·공정성 요구 간 균형.

## Ⅱ. 유형 및 기준
- 핵심 요약 : 선점 여부와 선택 기준이 스케줄러의 반응성과 공정성을 결정.
- 비선점은 실행 중인 작업을 완료·대기까지 유지 → 전환이 적으나 긴 작업이 지연 유발.
- 선점은 타이머·우선순위로 실행 중단 → 응답성 개선, 문맥 교환 비용 발생.
- 지표는 CPU 이용률·처리량·대기시간·반환시간·응답시간·기아 여부.

## Ⅲ. 스케줄링 흐름
- 핵심 요약 : 디스패처가 정책에 따라 작업을 선택하고 문맥을 전환.
```text
실행 중 작업
  ↓ 선점·종료·I/O 대기
준비 큐
  ↓ 스케줄러 선택
디스패처·문맥 교환
  ↓
CPU 실행
```
```text
타이머 인터럽트
  ↓ 실행시간·우선순위 판단
현재 문맥 저장
  ↓ 다음 작업 문맥 복원
실행 재개
```

## Ⅳ. 알고리즘 비교
- 핵심 요약 : 작업시간 사전 정보와 상호작용 응답 요구로 알고리즘을 선택.
| 알고리즘 | 선택 기준 | 장점·주의 |
| --- | --- | --- |
| FCFS | 도착 순 | 단순, convoy effect |
| SJF | 짧은 실행시간 | 평균 대기 감소, 길이 예측 필요 |
| Round Robin | 시간 할당량 순환 | 응답성, 문맥 교환 비용 |
| Priority | 우선순위 | 중요도 반영, 기아 위험 |

## Ⅴ. 한계와 방안
- 핵심 요약 : 기아·부하 편중·선점 비용을 노화·할당량 조정·실측으로 통제.
| 한계 | 원인·영향 | 대응 |
| --- | --- | --- |
| 기아 | 낮은 우선순위가 계속 대기 | aging·최대 대기 정책 |
| 문맥 교환 과다 | 시간 할당량 과소 | 대화형 요구와 전환비용 균형 |
| 실행시간 예측 오류 | SJF 효율 저하 | 예측 오차 관찰·다른 정책 검토 |

## Ⅵ. 운영 제언
- 핵심 요약 : 운영체제 설계자는 워크로드 유형별 지표를 정의하고 최악 응답시간과 공정성을 함께 검증.
- 실시간 시스템은 평균 성능만이 아니라 데드라인 충족률과 우선순위 역전 대응을 확인.

## Ⅶ. 결론
- 핵심 요약 : CPU 스케줄링 정책은 대기열에서 실행 순서를 결정해 시스템 반응성과 처리 효율에 영향.
- 워크로드와 목표 지표가 알고리즘 선택의 기준.
