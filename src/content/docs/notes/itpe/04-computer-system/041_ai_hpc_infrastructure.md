## 30초 인출

- 본질: 수천억 파라미터 기반 초거대 AI 모델의 분산 학습 시 발생하는 극심한 연산량, 노드 간 통신 지연 및 스토리지 피딩 병목
- 메커니즘: 수천 개의 최신 GPU 가속기를 NVLink 및 400G+ InfiniBand 패브릭으로 묶고 NVMe 병렬 파일시스템과 액체냉각을 통합 구축

## 핵심 용어

- GPUDirect RDMA: 분산 서버 간 GPU 통신 시, 호스트 CPU 메모리를 경유하지 않고 원격 GPU 메모리끼리 네트워크 카드(NIC)를 통해 직접 데이터를 교환하는 제로 카피 기술
- 팻 트리(Fat-Tree): 상위 스위치 계층으로 갈수록 대역폭을 두껍게(Fat) 배분하여 어떤 노드 쌍 간에도 대역폭 병목 없이 100% 논블로킹(Non-blocking) 양방향 전송을 보장하는 네트워크 구조
- 스트래글러(Straggler): 대규모 분산 학습 동기화(All-Reduce) 시, 단 하나의 노드나 네트워크 케이블 결함으로 속도가 느려져 나머지 수천 개 GPU 전체가 연산을 멈추고 대기하게 만드는 지연 유발 노드

### Ⅱ. 핵심 특성

- AI 인프라의 최종 성능은 GPU 개수보다 '인터커넥트 패브릭 대역폭'에서 결정됨 → GPU 연산 속도가 아무리 빨라도 가중치 동기화 통신 속도가 받쳐주지 못하면 GPU 사용률(GPU Utilization)이 30% 이하로 급락
- 전통적 고성능 컴퓨팅(HPC)은 기상/물리 시뮬레이션을 위한 'FP64 고정밀 배정밀도 연산'에 집중했으나, AI 슈퍼컴퓨팅은 행렬 곱셈을 위한 'FP8/FP16 저정밀도 초병렬 처리량'에 100% 최적화됨
- 수천 개 GPU 클러스터에서는 칩 결함이 매일 발생하므로, 장애 노드를 수 초 내에 격리하고 직전 체크포인트부터 즉각 재개하는 '내결함성 오케스트레이션(Fault-Tolerant Slurm/K8s)'이 인프라의 핵심 소프트웨어 자산임

### Ⅲ. 관련 개념과 구분

- 전통 HPC vs AI 슈퍼컴퓨팅: 전통 HPC = CPU 중심, FP64 고정밀 연산, MPI 분산 메모리 / AI 슈퍼컴퓨팅 = GPU/가속기 중심, FP16/FP8 혼합 정밀도 행렬 연산, 텐서 통신 패브릭(NCCL)

### Ⅳ. 적용 문제와 대응

- 사례: 140회 기출 1,024개 GPU 클러스터 분산 학습 시 빈번한 노드 멈춤으로 인한 훈련 정체
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 특정 광케이블 미세 불량으로 전체 GPU 클러스터의 올리듀스 통신 지연 폭증 | 단일 스트래글러(Straggler) 노드의 병목이 전체 분산 락 유발 | 실시간 NCCL 헬스체크 및 슬로우 노드 자동 축출(Auto-Drain) 메커니즘 | 통신 지연 억제 및 클러스터 전체 연산 동기화 회복 |
| 모델 체크포인트 저장 시 수십 분간 GPU 연산 중단으로 전력 낭비 | 스토리지 I/O 병목 및 CPU 메모리 경유 복사 지연 | GPUDirect Storage(GDS) 및 비동기 분산 체크포인팅 적용 | 덤프 시간 80% 단축 및 GPU 연산 유휴 최소화 |
