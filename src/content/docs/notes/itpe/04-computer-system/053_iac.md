## Ⅰ. 코드형 인프라(IaC)의 개요

- **개념** : 서버, 네트워크, 스토리지, 데이터베이스 등 IT 인프라 자원을 데이터센터 엔지니어가 수동 콘솔 조작으로 프로비저닝하지 않고, 버전 관리가 가능한 기계 판독형 코드(Configuration Code)로 정의하고 자동화 도구를 통해 배포 및 관리하는 클라우드 엔지니어링 패러다임.
- **배경 및 필요성** : 수작업 인프라 구축의 휴먼 에러(설정 오류), 느린 프로비저닝 속도, 운영-개발 환경 간의 구성 불일치(Configuration Drift), 그리고 인프라 변경 이력 추적 불가의 문제를 해결하기 위해 DevOps의 핵심으로 탄생함.
- **핵심 목적** : 인프라 프로비저닝의 완전 자동화 및 초고속화, 멱등성(Idempotency)을 통한 환경 재현성 100% 보장, GitOps 기반의 변경 감사 및 거버넌스 확립.

## Ⅱ. 코드형 인프라(IaC)의 핵심 아키텍처 및 동작 메커니즘

IaC는 목표 상태를 기술하는 '선언적(Declarative)' 방식과 실행 절차를 나열하는 '명령적(Imperative)' 방식으로 대별되며, 상태 파일(State File)을 통해 실제 인프라와의 정합성을 수렴(Reconciliation)함.

```text
[ 선언적 IaC (Terraform) 실행 파이프라인 및 상태 동기화 ]

[인프라 엔지니어] ──> [Git Repository (코드 커밋: main.tf, vpc.tf)]
                            │
                            ▼ CI/CD Webhook 트리거
+---------------------------------------------------------------+
| IaC Execution Engine (Terraform Cloud / Atlantis / Pipeline)  |
|                                                               |
|  1. terraform plan (코드와 현재 State 파일 비교 및 차이 분석)  |
|     - Desired State (선언된 코드) vs Actual State (클라우드 실물) |
|     - Plan: 2 to add, 1 to change, 0 to destroy               |
|                                                               |
|  2. Policy as Code (OPA / Sentinel: 보안 및 규정 자동 검증)   |
|                                                               |
|  3. terraform apply (API 호출을 통한 실제 인프라 프로비저닝)  |
+---------------------------------------------------------------+
         │                                              │
         ▼ (HTTPS Cloud API 호출)                       ▼ (State 갱신)
+-------------------------------+              +----------------+
| Target Cloud (AWS, Azure, GCP)|              | Remote State   |
| - VPC, Subnet, EC2, RDS 생성  |              | (S3 + DynamoDB |
+-------------------------------+              |  Locking 보장) |
                                               +----------------+
```

- **선언적 접근법 (Declarative)** : 엔지니어는 인프라의 최종 목표 상태(Desired State)만 정의하고, 도구가 현재 상태와의 차이를 계산하여 자동 수렴(Terraform, CloudFormation).
- **명령적 접근법 (Imperative)** : 원하는 상태에 도달하기 위한 단계별 실행 명령과 절차를 순차적으로 스크립트 작성(Ansible, Shell Script, AWS CLI).
- **멱등성 (Idempotency)** : 동일한 IaC 코드를 한 번 실행하든 수백 번 반복 실행하든 항상 동일한 최종 인프라 상태가 보장되는 특성.
- **상태 관리 (State Management)** : 테라폼 등의 도구는 프로비저닝된 리소스의 실제 매핑 정보를 담은 원격 State 파일을 유지하여 변경 사항을 정확히 추적.

## Ⅲ. 코드형 인프라(IaC)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 선언적 IaC (Terraform 등) | 명령적 IaC (Ansible 등) | 모던 코드형 (CDK / Pulumi) |
|---|---|---|---|
| **작성 언어** | HCL (HashiCorp Config Lang), YAML| YAML, Python 스크립트 | 범용 프로그래밍 언어 (TS, Python, Go)|
| **상태 관리** | State 파일을 명시적 유지 (엄격함) | 별도 State 없음 (대상 호스트 쿼리)| 백엔드 State 유지 |
| **주 적용 영역** | 클라우드 기초 인프라(VPC, K8s, DB) | OS 내부 설정 관리, 패키지 설치 | 복잡한 조건문/반복문 인프라 추상화 |
| **드리프트 감지** | Plan 단계에서 실시간 감지 가능 | 플레이북 재실행 시 감지 | 배포 엔진을 통한 감지 |
| **재사용성** | 모듈(Module) 단위 공유 | 롤(Role) 및 플레이북 단위 공유 | 표준 클래스/라이브러리 패키징(npm) |

- 최근 엔터프라이즈는 인프라 프로비저닝은 선언적 도구(Terraform)로 수행하고, VM 내부 소프트웨어 구성은 명령적 도구(Ansible)로 분업 결합함.

## Ⅳ. 코드형 인프라(IaC)의 주요 한계점 및 해결 방안

- **원격 상태 파일(State File) 충돌 및 민감 정보 노출** :
  - **한계점** : 다수 엔지니어가 동시 배포 시 State 파일이 손상되거나, 평문 State 파일 내 DB 비밀번호/API 키가 노출되는 보안 위험.
  - **해결 방안** : 원격 백엔드(S3 버킷) 암호화 저장, DynamoDB 기반 분산 State Locking 강제, HashiCorp Vault 연동을 통한 동적 시크릿 주입.
- **콘솔 직접 수정으로 인한 인프라 드리프트(Drift)** :
  - **한계점** : 비상 상황 시 AWS 콘솔에서 수동으로 보안그룹을 변경하여 코드와 실운영 인프라 상태가 불일치하는 현상 발생.
  - **해결 방안** : 주기적인 드리프트 감지 파이프라인(Terraform Plan 스케줄러) 운영, 콘솔 쓰기 권한을 원천 박탈하는 IAM 정책 수립.
- **거대 모듈화에 따른 실행 지연 및 파괴적 재생성(Blast Radius)** :
  - **한계점** : 단일 리포지토리에 모든 리소스를 정의할 경우 작은 수정에도 전체 State를 스캔하여 실행이 수십 분 걸리고 의도치 않은 삭제 위험.
  - **해결 방안** : 인프라 계층 분리(네트워크, 데이터, 컴퓨팅 분리), 상태 파일 격리(State Isolation), 리소스 삭제 방지(`prevent_destroy`) 설정.

## Ⅴ. 코드형 인프라(IaC) 적용 및 발전을 위한 기술사적 제언

- **정책형 코드(Policy as Code: PaC) 전사 게이트웨이화** : 보안 가이드라인(S3 퍼블릭 차단, 암호화 의무 등)을 OPA(Open Policy Agent) 코드로 정의하여 배포 파이프라인에서 자동 차단.
- **GitOps 기반 인프라 배포 거버넌스(Atlantis/Terraform Cloud)** : PR(Pull Request) 생성 시 plan 결과를 댓글로 자동 출력하고, 승인(Approve) 후에만 apply가 실행되는 감사 체계 구축.
- **모던 클라우드 개발 키트(AWS CDK / Pulumi) 역량 내재화** : HCL의 문법적 한계를 넘어 타입 안정성과 객체 지향 추상화를 지원하는 코드형 인프라 도입 검토 권장.
