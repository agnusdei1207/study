## 연관 키워드

- GPU(Graphics Processing Unit), SIMD, SIMT, GPGPU, SM, 워프(Warp), 텐서 코어(Tensor Core)
- 공유 메모리, HBM, 메모리 벽(Memory Wall), 워프 다이버전스(Warp Divergence), FlashAttention
- NVLink, InfiniBand, MIG, CUDA, 커널 퓨전(Kernel Fusion), 액체 냉각

## Ⅰ. GPU(Graphics Processing Unit)의 개요

- 핵심 요약 : 수천 개의 연산 유닛을 병렬로 배치해 대량의 행렬과 벡터 연산을 처리하는 SIMD·SIMT 기반 가속 프로세서.
- 개념 : 수천 개 이상의 단순한 산술 논리 연산 장치(ALU, Arithmetic Logic Unit)를 병렬로 배치해 대량의 행렬과 벡터 데이터를 고속으로 처리하도록 설계된 **GPU** (Graphics Processing Unit, 그래픽 처리 장치) 가속 프로세서. 동일 명령을 여러 데이터에 적용하는 **SIMD** (Single Instruction Multiple Data) 방식과, 여러 스레드가 한 명령을 함께 실행하는 **SIMT** (Single Instruction Multiple Threads) 방식을 함께 사용함.
- 배경 및 필요성 : 3D 그래픽의 픽셀 병렬 처리를 위해 발전했으나, 딥러닝과 과학 계산이 대규모 행렬 연산 중심이라는 것이 드러나며 **GPGPU** (General-Purpose computing on Graphics Processing Units, 범용 GPU 연산)의 핵심 하드웨어로 자리잡음. 연산량이 늘어날수록 병렬 처리 능력과 메모리 대역폭을 함께 확보하는 계층이 요구됨.
- 주요 목적 : 대용량 데이터의 병렬 처리량 극대화, **HBM** (High Bandwidth Memory, 고대역폭 메모리)을 통한 메모리 대역폭 병목 완화, 생성형 AI 모델의 학습과 추론 시간 단축.

## Ⅱ. GPU(Graphics Processing Unit)의 특징 및 장점

- 핵심 요약 : SM 단위의 집약 구조, 워프 단위 실행, 텐서 코어, 고대역폭 메모리가 결합되어 대규모 병렬 연산을 가속하는 구조.

1. **SM** (Streaming Multiprocessor, 스트리밍 멀티프로세서) : 다수의 ALU, 텐서 코어, 공유 메모리, 워프 스케줄러를 묶은 독립 연산 엔진 → 블록 단위 복제로 GPU 전체 연산 능력 확장.
2. **워프** (Warp, SIMT 실행의 스레드 묶음) : 32개 스레드가 하나의 묶음으로 같은 명령을 서로 다른 데이터에 동시에 실행 → 명령 디코딩 비용을 여러 스레드가 나눠 부담.
3. **텐서 코어** (Tensor Core, 행렬 곱 전용 유닛) : 행렬 곱 누적 연산(GEMM, General Matrix Multiply, D = A × B + C)을 하드웨어 수준에서 한 번에 처리 → 딥러닝 연산 가속.
4. **공유 메모리** (Shared Memory, SM 내 온칩 고속 메모리) : 같은 SM 안의 스레드가 공유하는 프로그래머블 고속 메모리 → 외부 메모리 접근 횟수를 줄여 지연 완화.

## Ⅲ. GPU(Graphics Processing Unit)의 구조 및 동작 메커니즘

- 핵심 요약 : HBM에서 L2 캐시를 거쳐 SM으로 데이터가 흐르고, SM 안에서 워프 스케줄러가 명령을 배분하는 계층 구조.
- GPU는 수십에서 수백 개의 SM이 공유 L2 캐시와 고대역폭 메모리를 나누어 쓰는 구조이며, 워프 묶음 단위로 명령을 병렬 실행함.

```text
[ GPU 메모리 계층 ]

HBM (전역 메모리, 고대역폭)
        ↓
L2 캐시 (전 SM 공유)
        ↓
SM (스트리밍 멀티프로세서)
        ↓
공유 메모리 · 레지스터 (SM 내부)
```

```text
[ SM 내부 실행 흐름 ]

워프 스케줄러 (명령 선택)
        ↓
워프 (스레드 32개 묶음)
        ↓
FP32 코어 또는 텐서 코어 실행
        ↓
결과를 레지스터·공유 메모리에 기록
```

## Ⅳ. GPU(Graphics Processing Unit)의 비교

- 핵심 요약 : CPU, GPU, 딥러닝 전용 가속기가 설계 목적과 코어 구성, 메모리 기술에서 대비되는 구조.

| 비교 항목 | CPU(Central Processing Unit) | GPU | TPU(Tensor Processing Unit) / NPU(Neural Processing Unit) |
| --- | --- | --- | --- |
| 설계 목적 | 복잡한 제어 로직과 낮은 지연의 순차 처리 | 대규모 단순 병렬 연산의 처리량 극대화 | 딥러닝 텐서 연산 전용 가속 |
| 코어 구성 | 수에서 수십 개의 고성능 코어 | 수천에서 수만 개의 소형 SIMT 코어 | 대규모 행렬 연산 배열 |
| 캐시 전략 | 계층형 대용량 캐시로 지연 은폐 | 작은 캐시, 많은 스레드로 지연 은폐 | 온칩 대용량 스크래치패드 메모리 |
| 메모리 기술 | DDR(Double Data Rate) 계열 범용 메모리 | GDDR(Graphics Double Data Rate) 계열, HBM | HBM 등 고대역폭 메모리 |
| 적합 워크로드 | OS 커널, DB 트랜잭션, 분기가 많은 로직 | 딥러닝 학습·추론, 그래픽, 과학 시뮬레이션 | 특정 딥러닝 모델의 고정 연산 |

- 선택 기준 : 대규모 병렬 연산에서는 GPU가 강점을 보이나 전력과 발열이 커서, 도입 시 냉각과 인터커넥트 설계를 함께 고려해야 함.

## Ⅴ. GPU(Graphics Processing Unit)의 한계와 방안

- 핵심 요약 : 메모리 벽, 워프 다이버전스, 발열 문제를 데이터 재사용 기법, 분기 없는 코드 설계, 액체 냉각으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **메모리 벽** (Memory Wall, 연산 속도와 메모리 대역폭의 격차) | 연산 속도에 비해 HBM에서 데이터를 가져오는 속도가 느려 텐서 코어가 유휴 상태로 대기 | **FlashAttention** (SRAM 재사용을 극대화하는 어텐션 계산 기법), 커널 퓨전(Kernel Fusion) 적용 | 연산 유닛 유휴 시간 비율 |
| **워프 다이버전스** (Warp Divergence, 워프 내 분기 경로 상이) | 같은 워프의 스레드가 분기에서 서로 다른 경로를 타면 나머지 경로 동안 스레드가 비활성화되어 성능 급락 | 분기 없는 코드 설계, 데이터 정렬로 같은 분기를 타도록 유도 | 워프 활성 스레드 비율 |
| 고집적 발열과 전력 | 단일 칩 전력이 크게 올라 공랭으로는 한계 온도 제어가 어려워 스로틀링 발생 | Direct-to-Chip 액체 냉각 도입, 랙 단위 전력 공급 구조 재설계 | 칩 온도, 스로틀링 발생 빈도 |

## Ⅵ. GPU(Graphics Processing Unit)에 대한 기술사적 제언

- 핵심 요약 : 인터커넥트 토폴로지, 자원 분할, 소프트웨어 이식성을 함께 설계해 GPU 인프라를 특정 기술에 묶이지 않는 운영 역량으로 내재화.
- 대규모 학습 클러스터를 설계하는 조직은 GPU 간 NVLink와 노드 간 InfiniBand 또는 RoCE 네트워크를 레일 단위로 나누는 토폴로지를 설계하고, 집합 통신 성능을 실측해 기준으로 삼아야 한다.
- 여러 팀이 GPU 한 장을 나누어 쓰는 환경에서는 **MIG** (Multi-Instance GPU, 다중 인스턴스 GPU) 분할로 자원 낭비와 간섭을 줄이는 운영 정책을 두는 것이 바람직하다.
- CUDA(Compute Unified Device Architecture)에 대한 종속을 줄이려는 조직은 Triton, PyTorch 컴파일 경로, ROCm 같은 대안 소프트웨어 스택을 주기적으로 평가해 이식성 기준을 세워야 한다.

## Ⅶ. 결론

- 핵심 요약 : GPU는 SM, 텐서 코어, HBM을 갖춘 대규모 병렬 연산 가속기로, 메모리 벽과 발열 관리가 운영의 핵심.
- 시사점 : 실질 처리량은 연산 성능보다 데이터 공급과 냉각에 좌우되므로, 인터커넥트와 열 설계를 함께 설계하는 것이 전제 조건임.
