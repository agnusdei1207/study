## Ⅰ. GPU(Graphics Processing Unit)의 개요

- 개념 : 수천 개 이상의 단순하고 집약적인 **산술 논리 연산 장치** (ALU)를 병렬 배치하여, 대량의 행렬 및 벡터 데이터를 고속 처리하도록 설계된 **SIMD(Single Instruction Multiple Data)** 및 **SIMT(Single Instruction Multiple Threads)** 기반 가속 프로세서.
- 배경 및 필요성 : 3D 그래픽 렌더링 파이프라인의 픽셀 병렬 처리를 위해 개발되었으나, 딥러닝 인공지능과 과학 계산 워크로드가 대규모 행렬 연산 중심임이 입증되면서 **범용 GPU(GPGPU)** 컴퓨팅의 핵심 실리콘으로 진화함.
- 핵심 목적 : 초대용량 데이터의 극단적 병렬 연산 처리량 극대화, 테라바이트급 **고대역폭 메모리(HBM)** 인터페이스를 통한 메모리 벽 돌파, 생성형 AI 모델의 학습 및 추론 시간 단축.

## Ⅱ. GPU(Graphics Processing Unit)의 핵심 아키텍처 및 동작 메커니즘

GPU 아키텍처는 수십~수백 개의 스트리밍 멀티프로세서(SM: Streaming Multiprocessor)와 이들이 공유하는 L2 캐시 및 고대역 메모리로 구성되며, 하드웨어 스레드 묶음인 **워프(Warp)** 단위로 명령어를 병렬 실행함.

```text
[ 현대 GPU (NVIDIA Hopper / Blackwell) 아키텍처 ]

+---------------------------------------------------------------+
| Global Memory: HBM3e / HBM4 (수 TB/s 초고대역폭)              |
+---------------------------------------------------------------+
                                │
                                ▼
+---------------------------------------------------------------+
| Shared High-Speed L2 Cache & NVLink 5 Interconnect Fabric     |
+---------------------------------------------------------------+
                                │
        ┌───────────────────────┼───────────────────────┐
        ▼                       ▼                       ▼
+---------------------------------------------------------------+
| Streaming Multiprocessor (SM)                                 |
|                                                               |
|  [Warp Scheduler & Dispatch Unit (4개 서브코어)]              |
|                                                               |
|  +---------------------+  +---------------------------------+ |
|  | FP32 / INT32 Cores  |  | Tensor Cores (4세대 / 5세대)    | |
|  | (표준 병렬 연산)    |  | (FP16/BF16/FP8/FP4 행렬 가속)   | |
|  +---------------------+  +---------------------------------+ |
|                                                               |
|  +----------------------------------------------------------+ |
|  | 228KB Shared Memory / L1 Data Cache (극저지연 스크래치패드) | |
|  +----------------------------------------------------------+ |
|  | Register File (스레드별 대용량 물리 레지스터 풀)          | |
+---------------------------------------------------------------+
```

- **스트리밍 멀티프로세서(SM)** : 다수의 ALU, 텐서 코어, 공유 메모리, 워프 스케줄러를 집약한 GPU의 독립적 핵심 연산 엔진.
- **SIMT(Single Instruction Multiple Threads)** : 32개의 스레드가 '워프(Warp)'라는 단일 묶음으로 동일한 명령어를 서로 다른 데이터에 대해 병렬 실행.
- **텐서 코어(Tensor Core)** : 딥러닝 GEMM(D = A × B + C) 연산을 클럭 사이클당 하드웨어 레벨에서 한 번에 수행하는 전용 유닛(FP8/FP4 정밀도 지원).
- **공유 메모리(Shared Memory)** : 동일 SM 내 스레드들이 데이터를 메모리 접근 지연 없이 공유할 수 있는 프로그래머블 초고속 온칩 SRAM.

## Ⅲ. GPU(Graphics Processing Unit)의 세부 구성 요소 및 비교 분석

| 비교 항목 | CPU (중앙처리장치) | GPU (그래픽처리장치) | TPU / NPU (전용 가속기) |
|---|---|---|---|
| **설계 목적** | 복잡한 제어 로직, 낮은 지연시간 순차 처리 | 대규모 단순 병렬 데이터 연산 처리량 극대화 | 딥러닝 텐서 곱셈 전용 ASIC 가속 |
| **코어 아키텍처** | 소수(수~수십 개)의 거대한 고성능 코어 | 수천~수만 개의 소형 SIMD/SIMT 코어 | 대규모 시스톨릭 어레이 MAC 그리드 |
| **캐시 메모리** | 대용량 계층형 캐시(L1/L2/L3)로 지연 은폐 | 작은 캐시, 대규모 스레드로 메모리 지연 은폐 | 온칩 대용량 스크래치패드 SRAM |
| **메모리 기술** | DDR4 / DDR5 (수십~수백 GB/s) | GDDR6X / HBM3e / HBM4 (수 TB/s) | HBM 인터페이스 직접 통합 |
| **적합 워크로드** | OS 커널, DB 트랜잭션, 분기 많은 로직 | 딥러닝 학습/추론, 그래픽스, 과학 시뮬레이션 | 딥러닝 모델 전용 고정 연산 가속 |

- GPU는 대규모 병렬 연산의 절대 강자이나 높은 소비 전력과 발열, 그리고 메모리 대역폭 의존도가 심하여 인프라 레벨의 냉각 및 인터커넥트 지원이 필수적임.

## Ⅳ. GPU(Graphics Processing Unit)의 주요 한계점 및 해결 방안

- **메모리 벽(Memory Wall)** 현상과 대역폭 병목 :
  - 한계점 : 연산 속도에 비해 외부 메모리(HBM)에서 데이터를 읽어오는 속도가 느려 텐서 코어가 유휴 상태(Idle)로 대기하는 현상 발생.
  - 해결 방안 : FlashAttention 기법 도입(SRAM 재사용 극대화), 커널 퓨전(Kernel Fusion), FP8/FP4 양자화를 통한 데이터 전송량 감축.
- **워프 다이버전스** (Warp Divergence)에 따른 성능 저하 :
  - 한계점 : 동일 워프 내의 32개 스레드가 `if-else` 분기에서 서로 다른 경로를 실행할 경우, 실행되지 않는 경로 동안 나머지 스레드가 비활성화되어 성능 급락.
  - 해결 방안 : 분기 없는 알고리즘(Branchless Code) 설계, 데이터 정렬을 통한 동일 분기 실행 유도.
- **초고집적 발열(TDP 700W~1000W+)** 및 전력 소모 :
  - 한계점 : 단일 칩 소비 전력이 1000W를 돌파하며 전통적인 공랭식 쿨러로는 한계 온도(Thermal Throttling) 제어 불가.
  - 해결 방안 : Direct-to-Chip(D2C) 액체 냉각 도입, 랙 단위 직류(DC) 전력 버스바 인프라 전환.

## Ⅴ. GPU(Graphics Processing Unit) 적용 및 발전을 위한 기술사적 제언

- GPU **클러스터 인터커넥트(NVLink & InfiniBand)** 설계 : 초대형 모델의 분산 학습 효율을 보장하기 위해 노드 내 NVLink 5 및 노드 간 RoCE v2/인피니밴드 레일 최적화 토폴로지 구축 필수.
- GPU 가상화 및 **파티셔닝(MIG)** 최적화 : 개발 및 경량 추론 환경에서 고가 GPU의 자원 낭비를 방지하기 위해 하드웨어 레벨 다중 인스턴스 GPU(MIG) 분할 운영 권장.
- **CUDA** 생태계 대안 소프트웨어 스택 탐색 : 특정 벤더 종속을 완화하기 위해 Triton, PyTorch 2.0 Inductor, ROCm 등 오픈 소프트웨어 컴파일러 역량 강화 필요.
