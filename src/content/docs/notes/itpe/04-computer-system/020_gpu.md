## 연관 키워드

- GPU(Graphics Processing Unit), ALU, SIMD, SIMT, GPGPU, 워프(Warp)
- SM(Streaming Multiprocessor), 텐서 코어(Tensor Core), 공유 메모리(Shared Memory)
- 지연 은폐(Latency Hiding), HBM, 메모리 벽(Memory Wall), 워프 다이버전스(Warp Divergence)
- CUDA, NVLink, MIG, 커널 퓨전(Kernel Fusion), 액체 냉각

## Ⅰ. GPU의 개요

- 핵심 요약 : 수천 개의 단순 연산 유닛으로 대규모 병렬 연산을 처리하는 그래픽·AI 가속 프로세서.
- 개념 : 단순 산술 논리 회로인 **ALU** (Arithmetic Logic Unit)를 수천~수만 개 병렬 배치해, 같은 명령을 여러 데이터에 동시 적용하는 **SIMD** (Single Instruction, Multiple Data) 방식으로 행렬·벡터 연산을 고속 처리하는 **GPU** (Graphics Processing Unit, 그래픽 처리 장치).
- 배경 및 필요성 : 3D 그래픽의 정점·픽셀 병렬 계산 목적으로 성장한 뒤, 딥러닝 학습·추론의 본질이 대규모 행렬 곱이라는 점이 부각되며 범용 병렬 연산인 **GPGPU** (General-Purpose computing on Graphics Processing Units) 수요로 확장된 배경.
- 주요 목적 : 대규모 병렬 처리량의 극대화, 고대역폭 메모리로 인한 데이터 공급 지연 완화, 학습·추론 소요 시간의 단축.

## Ⅱ. GPU의 특징 및 장점

- 핵심 요약 : SIMT 실행, SM 집약 구조, 전용 회로, 메모리 대역폭이 처리량 극대화로 연결되는 구조.

1. **SIMT** (Single Instruction, Multiple Threads) : 여러 스레드가 하나의 명령 스트림을 서로 다른 데이터로 함께 실행하는 방식 → 소수 제어 회로로 다수 유닛을 구동하는 전력 효율·밀도 향상.
2. **SM** (Streaming Multiprocessor, 연산 엔진 블록) : ALU 그룹과 스케줄러, **공유 메모리** (Shared Memory, 블록 단위 온칩 고속 저장소)를 결합한 복제 단위 → 블록 수에 비례한 칩 전체 연산 능력 확장.
3. **워프** (Warp, 32개 스레드의 동시 실행 묶음) : 묶음 전체가 하나의 명령을 공유 실행 → 명령 인출·디코딩 비용의 분담 효과.
4. **지연 은폐** (Latency Hiding) : 메모리 대기 중인 스레드 대신 준비된 다른 스레드를 즉시 투입 → 낮은 클럭에서도 유닛 가동률 유지.
5. **HBM** (High Bandwidth Memory, 고대역폭 메모리) : 칩 인접 적층 구조의 초고속 메모리 → 대량 피연산자의 동시 공급으로 연산 유닛 가동률 확보.

## Ⅲ. GPU의 구조 (흐름)

- 핵심 요약 : 스레드 위계가 워프 단위로 SM에 배치되고, HBM에서 레지스터까지의 데이터 공급 경로가 계층을 이루는 구조.
- **CUDA** (Compute Unified Device Architecture, GPU 병렬 컴퓨팅 플랫폼)의 실행 모델은 그리드·블록·스레드의 위계를 따름.

```text
[ CUDA 실행 위계 ]

그리드 (커널 실행 전체)
        ↓
블록 (SM에 할당되는 단위)
        ↓
워프 : 스레드 32개 묶음
        ↓
스레드 (최소 실행 단위)
```

```text
[ GPU 메모리 계층 ]

HBM (전역 메모리)
        ↓
L2 캐시 (전체 SM 공유)
        ↓
공유 메모리 (블록 내 공유)
        ↓
레지스터 (스레드 전용)
```

## Ⅳ. GPU의 비교

- 핵심 요약 : CPU·GPU·딥러닝 전용 가속기가 설계 목적과 연산 구조, 메모리 전략에서 대비되는 구조.

| 비교 항목 | CPU(Central Processing Unit) | GPU | TPU(Tensor Processing Unit)·NPU(Neural Processing Unit) |
| --- | --- | --- | --- |
| 설계 목적 | 낮은 지연의 순차·제어 처리 | 대규모 병렬 처리량 극대화 | 신경망 연산 전용 최적화 |
| 연산 유닛 | 소수의 고성능 복잡 코어 | 수천~수만 개 단순 유닛 | 행렬 연산 배열 |
| 캐시 전략 | 대용량 계층 캐시 | 소형 캐시와 다중 스레드 은폐 | 온칩 스크래치패드 |
| 메모리 | DDR(Double Data Rate) 계열 범용 | GDDR(Graphics Double Data Rate)·HBM | HBM 중심 |
| 적합 워크로드 | 트랜잭션·분기 로직·OS | 학습·추론·시뮬레이션·렌더링 | 고정 모델의 대량 추론 |

- 선택 기준 : 워크로드의 병렬성, 배분 유연성, 전력·냉각 여건을 함께 검토해 가속기를 선정하는 절차 필요.

## Ⅴ. GPU의 한계와 방안

- 핵심 요약 : 메모리 벽, 워프 다이버전스, 전력·발열의 한계를 데이터 재사용, 분기 최소화, 냉각 고도화로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **메모리 벽** (Memory Wall, 연산 속도와 메모리 공급 속도의 격차) | 연산 유닛이 피연산자 대기로 유휴 상태가 되어 실질 처리량 저하 | **커널 퓨전** (Kernel Fusion, 인접 연산의 단일 실행 병합)과 FlashAttention 같은 메모리 재사용 기법 | 유닛 가동률 |
| **워프 다이버전스** (Warp Divergence, 묶음 내 스레드의 분기 경로 분열) | 병렬 실행이 순차화되어 비활성 스레드 증가 | 분기 최소화 커널 설계, 데이터 정렬 재배치 | 활성 스레드 비율 |
| 전력·발열 집중 | 높은 집적도로 인한 온도 상승과 클럭 조정 발생 | 액체 냉각 도입, 랙 단위 전력 설계 재정비 | 칩 온도, 조정 발생 빈도 |

## Ⅵ. GPU에 대한 기술사적 제언

- 핵심 요약 : 인터커넥트 설계, 자원 분할 운영, 소프트웨어 이식성 확보를 GPU 인프라 표준으로 정비하는 방향.
- 대규모 학습 플랫폼 조직은 GPU 간 직결 링크인 **NVLink**와 노드 간 고속 네트워크의 위상을 통신 패턴에 맞춰 설계하고, 집합 통신 성능 실측 기준 운영 필요.
- 다수 팀의 공용 환경에서는 카드 단위 물리 분할 기술인 **MIG** (Multi-Instance GPU)로 가속기 자원을 격리 배분하는 운영 정책 수립 필요.
- 조달·아키텍처 조직은 CUDA 생태계 종속을 줄이기 위해 대안 소프트웨어 스택의 이식성을 주기 평가하는 절차 마련 필요.

## Ⅶ. 결론

- 핵심 요약 : GPU는 대규모 병렬 연산의 표준 가속기로, 데이터 공급과 열 관리가 체감 성능의 결정 요인.
- 연산 스펙보다 메모리·인터커넥트·냉각의 균형 설계가 실제 클러스터 처리량을 좌우하는 시사점.
