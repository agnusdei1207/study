## 연관 키워드

- HA(High Availability), 고가용성, 가용성, MTBF, MTTR, SLA, SPOF
- 이중화(Redundancy), 고가용성 클러스터, 페일오버(Failover), 페일백(Failback)
- 하트비트(Heartbeat), VIP(Virtual IP), 쿼럼(Quorum), 펜싱(Fencing)
- 콜드 스탠바이, 웜 스탠바이, 핫 스탠바이, RAID, VRRP, 네트워크 이중화

## Ⅰ. HA의 개요

- 핵심 요약 : 장애 발생에도 서비스 중단을 최소화해 목표 가용성을 달성하는 시스템 설계·운영 기법.
- 개념 : 구성 요소의 고장이 서비스 전면 중단으로 이어지지 않도록 여벌 자원과 자동 전환 구조를 갖추고, 사전에 정한 **SLA** (Service Level Agreement, 서비스 수준 협약)의 가용성 목표를 달성하도록 설계하는 **HA** (High Availability, 고가용성) 엔지니어링 기법.
- 배경 및 필요성 : 금융·통신·전자상거래 시스템의 24시간 연속 운영 요구가 높아지는 가운데, 단일 요소 고장이 서비스 전체를 멈추게 하는 **SPOF** (Single Point of Failure, 단일 장애점) 제거가 필수 과제가 된 배경.
- 주요 목적 : 연간·월간 허용 다운타임 목표의 달성, 장애 감지부터 전환까지의 자동화, 계획된 작업 중에도의 서비스 연속성 확보.

## Ⅱ. HA의 특징 및 장점

- 핵심 요약 : 가용성 측정 체계, 이중화, 클러스터 전환이 고장 간격 확대와 복구 시간 단축으로 연결되는 구조.

1. 가용성 측정 체계 : **가용성** (Availability, 정상 가동 시간의 비율)은 평균 고장 간격 시간과 평균 복구 시간으로 산정하는 지표 → 개선 축이 고장 예방과 복구 단축의 둘로 명확해지는 효과.
   - **MTBF** (Mean Time Between Failures, 평균 고장 간격 시간) : 두 고장 사이의 평균 정상 가동 시간.
   - **MTTR** (Mean Time To Repair, 평균 복구 시간) : 고장 감지부터 복구 완료까지의 평균 소요 시간.
   - 산정식 : 가용성(%) = MTBF ÷ (MTBF + MTTR) × 100.
2. **이중화** (Redundancy, 여벌 구성 요소의 병행 배치) : 서버·전원·네트워크 경로·저장장치를 여러 벌로 구성 → 한 요소의 고장에도 서비스 지속.
3. **고가용성 클러스터** (HA Cluster) : 복수 서버를 하나의 논리 서비스 단위로 묶고 상호 감시 → 노드 단위 고장을 서비스 단위로 흡수.
4. **페일오버** (Failover, 자동 장애 전환) : 감시 신호 상실 시 대기 노드가 서비스 자원을 인계 → 사람 개입 없는 분 단위 이하 복구.

## Ⅲ. HA의 구조 (흐름)

- 핵심 요약 : 감시 → 판정 → 자원 인계 → 복귀의 전환 수명 주기와 계층별 이중화의 조합 구조.
- **하트비트** (Heartbeat, 노드 간 생존 확인 신호) : 전용 감시 경로로 주기 신호를 주고받아 고장을 자동 판정하는 기반.
- **VIP** (Virtual IP, 노드 간에 인계되는 서비스 대표 접속 주소) : 클라이언트 접속 정보 변경 없는 전환을 가능하게 하는 장치.

```text
[ 페일오버 수명 주기 ]

Active 노드의 서비스 제공
        ↓
하트비트 감시 (전용 경로 헬스체크)
        ↓
장애 판정 : 연속 무응답 확인
        ↓
Standby 노드의 VIP 인계·승격
        ↓
원인 제거 후 페일백으로 복귀
```

```text
[ 시스템 계층별 이중화 ]

서버 : 클러스터 노드 2대 이상
        ↓
네트워크 : 이중 스위치·이중 링크
        ↓
저장장치 : RAID 미러링·복제
        ↓
전원 : 이중 계통과 UPS
```

## Ⅳ. HA의 비교

- 핵심 요약 : 이중화 대상별 수단과 대기 노드 방식의 차이가 비용과 전환 속도의 절충 관계를 이루는 구조.

| 이중화 대상 | 대표 수단 | 특징 | 전환 속도 |
| --- | --- | --- | --- |
| 서버 | HA 클러스터, 페일오버 | 노드 고장을 서비스 단위로 흡수 | 빠름 |
| 네트워크 | 이중 스위치, VRRP(Virtual Router Redundancy Protocol) | 경로·장비 고장을 게이트웨이 인계로 흡수 | 매우 빠름 |
| 저장장치 | RAID(Redundant Array of Independent Disks) 미러링 | 디스크 고장 시 데이터 접근 유지 | 즉시 |
| 전원 | 이중 전원 계통, UPS(Uninterruptible Power Supply) | 전원 계통 장애의 흡수 | 즉시 |

| 대기 노드 방식 | 예비 노드 상태 | 전환 소요 | 자원 비용 |
| --- | --- | --- | --- |
| **콜드 스탠바이** (Cold Standby) | 전원 차단 상태로 보관 | 가장 김 (기동 필요) | 최소 |
| **웜 스탠바이** (Warm Standby) | OS 기동·서비스 중지 | 중간 (프로세스 기동) | 중간 |
| **핫 스탠바이** (Hot Standby) | 서비스 준비 완료 상태 | 짧음 (자원 인계만) | 높음 |
| **액티브-액티브** (Active-Active) | 전 노드가 동시 서비스 | 사실상 즉시 (부하 재분산) | 높음 |

- 선택 기준 : 허용 중단 시간과 예비 자원 비용의 균형점에서 대기 방식을 고르고, 서비스별 목표 가용성에 따라 이중화 범위를 조정하는 판단 절차 필요.

## Ⅴ. HA의 한계와 방안

- 핵심 요약 : 여벌 비용, 감시 오판, 전환 시 세션 유실을 자원 공유, 정족수 판정, 세션 외부화로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 예비 자원의 비용 부담 | 대기 노드의 상시 유휴 유지에 따른 투자 낭비 | 개발·검증 환경과의 공유 전환, 수요 기반 대기 자원 운영 | 자원 이용률 |
| 감시 오판에 의한 **스플릿 브레인** (Split-Brain, 다중 노드의 동시 주도) | 감시 경로 단절을 상대 고장으로 오판 → 공유 데이터의 동시 기록 훼손 | 과반수 **쿼럼** (Quorum, 주도권 판정 정족수)과 **펜싱** (Fencing, 장애 노드의 공유 자원 접근 차단) 적용 | 이중 주도 발생 건수 |
| 전환 순간의 세션 상실 | 절체 중 로그인 세션과 처리 중 요청의 소멸 | 세션 저장소의 외부 분리, 클라이언트 재시도 설계 | 전환 중 오류 요청 비율 |

## Ⅵ. HA에 대한 기술사적 제언

- 핵심 요약 : 가용성 목표의 서비스 등급화, 전환 훈련 상시화, 감시 체계 통합을 HA 운영 표준으로 정비하는 방향.
- 서비스 기획 조직은 업무 중요도별로 목표 가용성 수치와 허용 다운타임을 등급화하고, 등급에 따라 이중화 수준을 차등 적용하는 기준 수립 필요.
- 운영 조직은 실제 절체 훈련을 정기 수행해 페일오버·페일백 절차와 소요 시간을 검증하고, 결과를 운영 문서로 갱신하는 절차 운영 필요.
- 통합 감시 조직은 서버·네트워크·저장소 감시 신호를 한 콘솔에서 수집해 장애 판정 기준을 일원화하는 체계 구축 필요.

## Ⅶ. 결론

- 핵심 요약 : HA는 SPOF 제거와 자동 전환으로 목표 가용성을 달성하는 이중화 설계·운영 기법.
- 구성만으로 가용성이 보장되지 않으므로, 측정 공식과 전환 훈련을 통한 설계 효과의 입증이 성립 조건.
