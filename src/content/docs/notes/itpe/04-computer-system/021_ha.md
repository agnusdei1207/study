## Ⅰ. HA(High Availability)의 개요

- 개념 : 정보통신 시스템의 구성 요소에 장애가 발생하더라도 서비스의 중단 시간을 최소화하고, 사전에 정의된 서비스 수준 협약(SLA, 예: 99.999% 'Five Nines') 이상으로 지속적인 정상 운영 상태를 유지하도록 설계된 **고가용성** 인프라 엔지니어링 기법.
- 배경 및 필요성 : 전자상거래, 금융 결제, 클라우드 플랫폼 등 현대 24/7 미션 크리티컬 비즈니스에서 시스템 다운타임은 막대한 재무적 손실과 브랜드 신뢰도 추락으로 직결되므로 **단일 장애점** (SPOF)을 제거하기 위해 필수적으로 도입됨.
- 핵심 목적 : 단일 장애점의 원천 제거, **평균 고장 간격(MTBF)** 극대화 및 **평균 복구 시간(MTTR)** 최소화, 장애 감지 및 페일오버(Failover)의 완전 자동화 달성.

## Ⅱ. HA(High Availability)의 핵심 아키텍처 및 동작 메커니즘

HA 아키텍처는 중복성(Redundancy), 장애 감지(Heartbeat), 자동 인계(Failover), 그리고 데이터 정합성 보장 메커니즘을 핵심 축으로 구성됨.

```text
[ HA 클러스터링 및 페일오버 아키텍처 ]

[클라이언트 요청 트래픽]
          │
          ▼
+---------------------------------------------------------------+
| 부하 분산 계층 (L4/L7 Load Balancer / Anycast VIP 이중화)       |
+---------------------------------------------------------------+
          │                                           │
          ▼ (Active Path)                             ▼ (Standby Path)
+---------------------------+               +---------------------------+
| Active Node (주 노드)     |  Heartbeat    | Standby Node (예비 노드)  |
| - 서비스 정상 처리        | <───────────> | - 헬스체크 및 쿼럼 감시   |
| - 데이터 갱신 및 복제 송신|  (이중 사설망)| - 장애 시 자동 Takeover   |
+---------------------------+               +---------------------------+
              │                                           │
              ▼                                           ▼
+-----------------------------------------------------------------------+
| 공유 스토리지 (SAN / NAS) 또는 동기식 데이터 복제 (DRBD / Mirroring)   |
|   - Split-Brain 방지: STONITH (Shoot The Other Node In The Head)      |
|   - 쿼럼 디스크 / 증인 서버 (Witness Node) 기반 정합성 판정           |
+-----------------------------------------------------------------------+
```

- **이중화 구성(Redundancy)** : 서버, 네트워크 카드(NIC 본딩), 전원공급장치(PSU), 스위치 등 모든 하드웨어를 다중화하여 단일 장애점(SPOF) 제거.
- **하트비트 감시(Heartbeat)** : 클러스터 노드 간 독립된 전용 사설망을 통해 주기적으로 헬스체크 신호를 교환하여 상대방 생존 여부 실시간 확인.
- **자동 장애 조치(Failover)** : Active 노드 무응답 감지 시 Standby 노드가 가상 IP(VIP)를 인계받아 서비스를 무중단 승계.
- **하드웨어 격리(STONITH / Fencing)** : 장애 노드가 공유 디스크를 계속 쓰지 못하도록 전원 관리 모듈(IPMI/iLO)을 통해 강제 리셋하여 데이터 오염 차단.

## Ⅲ. HA(High Availability)의 세부 구성 요소 및 비교 분석

| HA 구성 토폴로지 | 동작 메커니즘 | 자원 효율성 | 페일오버 소요시간 (RTO) |
|---|---|---|---|
| **Active-Active** | 모든 노드가 실시간 트래픽을 분산 처리 | 매우 높음 (100% 자원 활용) | 수 초 이하 (즉시 트래픽 재분산) |
| **Active-Standby (Hot)** | 주 노드가 서비스, 예비 노드는 가동 대기 | 중간 (50% 자원 유휴 상태) | 수 초 ~ 수십 초 (VIP 인계) |
| **Active-Standby (Warm)** | 예비 노드는 부팅 상태이나 앱은 미기동 | 낮음 | 수 분 소요 (프로세스 기동 필요) |
| **Active-Standby (Cold)** | 예비 노드가 전원 오프 상태로 보관 | 매우 낮음 | 수십 분 이상 (하드웨어 부팅 필요) |

- Active-Active는 성능과 RTO 측면에서 최상이나 데이터 동시 쓰기 정합성 및 세션 클러스터링 난이도가 높고, Active-Standby는 구성이 비교적 단순하나 자원 낭비가 발생함.

## Ⅳ. HA(High Availability)의 주요 한계점 및 해결 방안

- **스플릿 브레인(Split-Brain)** 현상과 데이터 파괴 위험 :
  - 한계점 : 하트비트 네트워크 단절 시 양쪽 노드가 모두 상대를 죽은 것으로 오판하여 동시에 Active 상태로 승격되고 공유 데이터를 동시 쓰기하여 데이터 영구 훼손.
  - 해결 방안 : 3대 이상의 홀수 노드 구성 기반 쿼럼(Quorum) 알고리즘 도입, 외부 증인(Witness) 서버 연계, IPMI 기반 STONITH 하드웨어 펜싱 강제화.
- 동기식 복제 시 쓰기 **지연(Latency)** 증가 :
  - 한계점 : 양 노드 간 데이터 정합성을 위해 2-Phase Commit 또는 동기식 I/O 수행 시 네트워크 RTT에 의한 애플리케이션 트랜잭션 응답 지연.
  - 해결 방안 : 초고속 저지연 전용선 DCI 구축, 반동기식(Semi-Synchronous) 복제 또는 Raft 합의 기반 비동기 파이프라인 최적화.
- 페일오버 순간의 세션 단절 및 **인플라이트(In-flight)** 유실 :
  - 한계점 : 노드 절체 시 기존 접속자의 로그인 세션 및 처리 중이던 인메모리 트랜잭션이 유실되어 사용자 에러 발생.
  - 해결 방안 : 분산 인메모리 캐시(Redis Cluster)를 통한 세션 외부화, 클라이언트 재시도(Retry) 및 멱등성(Idempotency) 로직 설계.

## Ⅴ. HA(High Availability) 적용 및 발전을 위한 기술사적 제언

- **카오스 엔지니어링** (Chaos Engineering)을 통한 상시 검증 : 넷플릭스 카오스 몽키처럼 운영 환경에서 임의의 노드 전원 차단 테스트를 정기 수행하여 페일오버 자동화의 실효성 입증 필수.
- SRE 관점의 **에러 버짓(Error Budget)** 거버넌스 연계 : 무조건적인 Five Nines(99.999%) 추구로 인한 개발 속도 저하를 방지하고 가용성 목표와 배포 혁신 간의 균형 유지.
- 클라우드 **멀티 가용영역(Multi-AZ)** 기본 적용 : 단일 데이터센터 내 이중화를 넘어 물리적으로 전력망과 네트워크가 격리된 복수 가용영역 간의 HA 배포를 표준 아키텍처로 수립.
