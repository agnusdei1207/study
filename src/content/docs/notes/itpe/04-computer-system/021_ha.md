## 연관 키워드

- HA(High Availability), SLA, SPOF, MTBF, MTTR, RTO
- 이중화, 하트비트(Heartbeat), 페일오버(Failover), STONITH, 펜싱(Fencing), 쿼럼(Quorum)
- 스플릿 브레인(Split-Brain), 액티브-액티브, 액티브-스탠바이, 세션 외부화
- 카오스 엔지니어링(Chaos Engineering), 에러 버짓(Error Budget), Multi-AZ

## Ⅰ. HA(High Availability)의 개요

- 핵심 요약 : 구성 요소에 장애가 나도 중단 시간을 최소화하고 SLA 이상의 연속 운영을 보장하는 인프라 기법.
- 개념 : 정보통신 시스템의 구성 요소에 장애가 발생하더라도 서비스 중단 시간을 줄이고, 사전에 정한 **SLA** (Service Level Agreement, 서비스 수준 협약) 이상으로 정상 운영을 유지하도록 설계된 **HA** (High Availability, 고가용성) 인프라 엔지니어링 기법.
- 배경 및 필요성 : 금융 결제와 전자상거래처럼 24시간 서비스하는 시스템은 다운타임이 곧 재무 손실과 신뢰 하락으로 이어지므로, 단일 장애가 전체 서비스를 멈추게 하는 **SPOF** (Single Point of Failure, 단일 장애점) 위험을 없애는 계층이 필수적임.
- 핵심 목적 : SPOF 제거, **MTBF** (Mean Time Between Failures, 평균 고장 간격)의 확대와 **MTTR** (Mean Time to Repair, 평균 복구 시간)의 단축, 장애 감지와 전환의 자동화.

## Ⅱ. HA(High Availability)의 특징 및 장점

- 핵심 요약 : 이중화, 하트비트 감시, 자동 페일오버, 강제 차단이 결합되어 SPOF를 제거하고 데이터 오염을 막는 구조.

1. **이중화** (Redundancy, 구성 요소의 다중 배치) : 서버, NIC 본딩, 전원공급장치, 스위치를 여러 벌 두어 단일 장애점 제거 → 특정 부품 고장에도 서비스 유지.
2. **하트비트** (Heartbeat, 노드 간 생존 신호) : 전용 사설망으로 주기적인 헬스체크 신호를 주고받아 상대 노드 생존을 감시 → 장애를 빠르게 감지.
3. **페일오버** (Failover, 자동 장애 조치) : Active 노드가 무응답이면 Standby 노드가 가상 IP(VIP, Virtual IP)를 넘겨받아 서비스를 승계 → 사용자 입장에서 무중단 전환.
4. **STONITH** (Shoot The Other Node In The Head, 장애 노드 강제 차단) : 장애 노드를 전원 관리 모듈로 강제 리셋해 공유 디스크 쓰기를 막는 펜싱 방식 → 데이터 오염 차단.

## Ⅲ. HA(High Availability)의 구조 및 동작 메커니즘

- 핵심 요약 : 부하 분산 계층 아래 Active와 Standby가 하트비트로 서로를 감시하고, 공유 스토리지와 펜싱이 데이터 정합성을 지키는 계층 구조.

```text
[ HA 클러스터 구조 ]

클라이언트 요청
        ↓
부하 분산 계층 (VIP 이중화)
        ↓
Active 노드 ↔ Standby 노드 (하트비트)
        ↓
공유 스토리지 또는 동기 데이터 복제
```

```text
[ 장애 전환 흐름 ]

Active 노드 하트비트 무응답
        ↓
Standby 노드가 쿼럼 확인
        ↓
장애 노드 펜싱 (STONITH)
        ↓
VIP 인계 후 Standby를 Active로 승격
```

- **쿼럼** (Quorum, 과반수 합의로 주도권을 정하는 정족수) : 노드 수의 과반이 동의해야 Active 승격을 허용하는 기준으로, 네트워크가 갈렸을 때 한쪽만 주도권을 갖게 함.
- 증인(Witness) 서버나 쿼럼 디스크는 짝수 노드 구성에서 투표를 보완하는 장치로 쓰임.

## Ⅳ. HA(High Availability)의 비교

- 핵심 요약 : 모든 노드가 트래픽을 나눠 처리하는 액티브-액티브와, 예비 노드의 준비 상태에 따라 나뉘는 액티브-스탠바이 토폴로지의 절충 구조.
- 페일오버 소요 시간의 척도는 **RTO** (Recovery Time Objective, 목표 복구 시간)이며, 예비 노드의 준비 수준이 낮아질수록 RTO가 길어짐.

| HA 구성 토폴로지 | 동작 메커니즘 | 자원 효율성 | RTO 수준 |
| --- | --- | --- | --- |
| 액티브-액티브 | 모든 노드가 실시간 트래픽을 분산 처리 | 매우 높음 | 매우 짧음 (트래픽 즉시 재분산) |
| 액티브-스탠바이 (Hot) | 주 노드가 서비스, 예비 노드는 가동 대기 | 중간 (예비 자원 유휴) | 짧음 (VIP 인계) |
| 액티브-스탠바이 (Warm) | 예비 노드는 부팅 상태이나 애플리케이션 미기동 | 낮음 | 보통 (프로세스 기동 필요) |
| 액티브-스탠바이 (Cold) | 예비 노드가 전원 꺼진 상태로 보관 | 매우 낮음 | 가장 길음 (하드웨어 부팅 필요) |

- 선택 기준 : 액티브-액티브는 RTO가 가장 짧으나 데이터 동시 쓰기 정합성과 세션 클러스터링의 난도가 높고, 액티브-스탠바이는 구성이 단순한 대신 자원 낭비가 생기므로 서비스 특성에 따라 고름.

## Ⅴ. HA(High Availability)의 한계와 방안

- 핵심 요약 : 스플릿 브레인, 동기 복제 지연, 세션 유실의 세 한계를 쿼럼과 펜싱, 준동기 복제, 외부 세션 저장소로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **스플릿 브레인** (Split-Brain, 두 노드가 동시에 Active 상태) | 하트비트 단절을 상대 장애로 오판해 양쪽이 승격되고, 공유 데이터를 동시에 써서 훼손 | 홀수 노드 구성의 쿼럼 알고리즘, 외부 증인 서버, IPMI(Intelligent Platform Management Interface) 기반 STONITH 강제 | 이중 Active 발생 건수 |
| 동기 복제의 쓰기 지연 | 2단계 커밋(Two-Phase Commit)이나 동기 I/O가 왕복 지연(RTT, Round-Trip Time)을 그대로 떠안음 | 저지연 전용 광 연결 구축, 반동기식(Semi-synchronous) 복제 적용 | 트랜잭션 응답 시간, RTT |
| 전환 순간의 세션 단절 | 노드 절체 때 로그인 세션과 처리 중 트랜잭션(In-flight)이 사라져 사용자 오류 발생 | 세션 외부화(세션을 Redis Cluster 같은 외부 캐시로 분리), 클라이언트 재시도와 멱등성(Idempotency) 설계 | 전환 중 실패 요청 비율 |

## Ⅵ. HA(High Availability)에 대한 기술사적 제언

- 핵심 요약 : 장애 주입 검증, 가용성 예산 관리, 가용 영역 분산을 묶어 HA를 설계 문서가 아닌 운영 실적으로 입증하는 체계.
- 운영 조직은 정기적으로 임의 노드의 전원을 차단하는 **카오스 엔지니어링** (Chaos Engineering, 장애 주입 실험)을 수행해, 페일오버 설계가 실제 장애에서도 동작하는지 증명해야 한다.
- 서비스 책임자는 SRE(Site Reliability Engineering) 조직의 **에러 버짓** (Error Budget, 허용 장애 예산)을 가용성 목표와 배포 속도 사이의 조정 수단으로 삼는 편이 바람직하다.
- 클라우드 기반 시스템은 물리적으로 격리된 가용 영역(AZ, Availability Zone)에 걸쳐 배포하는 **Multi-AZ** 구성을 기본값으로 두고, 영역 단위 장애 시나리오를 설계 기준에 포함해야 한다.

## Ⅶ. 결론

- 핵심 요약 : HA는 SPOF 제거와 자동 페일오버로 SLA 이상의 연속 운영을 보장하는 인프라 기법.
- 시사점 : 전환 기능 자체보다 스플릿 브레인과 세션 유실을 어떻게 막는지가 실질 가용성을 결정하므로, 설계 단계에서 실패 시나리오를 함께 검증해야 함.
