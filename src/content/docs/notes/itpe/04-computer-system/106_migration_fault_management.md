## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 정보시스템 운영 → 운영환경 전환 장애관리

## 30초 인출

- 본질: 운영환경 전환 장애관리는 서비스·데이터를 새 환경으로 옮길 때 실패 영향을 통제하는 활동
- 메커니즘: 리허설 → 최종 동기화·정합성 대조 → Go/No-Go → 트래픽 절체 → 안정화·원복 판단
- 통찰: 한계: 리허설 성공만으로 실제 부하·데이터 변화의 장애를 막기 어려움 → 방안: 쓰기 경계·중단 기준·원복 가능 시점을 실제 전환 조건에서 시험

<details>
<summary>핵심 용어</summary>

- **컷오버(Cutover)** : 기존 운영에서 신규 운영환경으로 서비스와 처리를 전환하는 절차
- **Go/No-Go** : 사전 합의 기준에 따라 전환을 진행하거나 중단하는 결정
- **CDC (Change Data Capture)** : 데이터 변경을 식별해 다른 시스템에 전달하는 방식
- **롤백(Rollback)** : 실패 시 계획된 이전 운영상태로 복구하는 절차
- **병행 운영(Parallel Run)** : 기존·신규 시스템 결과를 일정 기간 비교하는 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. 운영환경 전환 장애관리의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **운영환경 전환 장애관리는** 서비스·데이터를 새 환경으로 옮길 때 실패 영향을 통제하는 활동 |
| 목적 | 서비스 연속성과 데이터 정합성, 복구 가능성 확보 |

## Ⅱ. 운영환경 전환 장애관리의 특징

| 특징 | 장애 통제 의미 |
|---|---|
| 시간 제한된 상태 전환 | 허용 중단시간과 Go/No-Go 결정 시점이 필요 |
| 데이터와 트래픽의 동시 이동 | 최종 동기화·단일 쓰기 권한·사용자 요청 경로를 함께 맞춰야 함 |
| 되돌림 가능 범위의 변화 | 신규 환경에 쓰기가 시작되면 단순 트래픽 원복만으로 데이터가 되돌아가지 않음 |

## Ⅲ. 전환 준비·절체·안정화 체계와 장애 분기 프로세스

```text
전환 범위·책임·시간창·원복 기준 확정
          ↓ 리허설·대용량 데이터 검증
최종 동기화 → 데이터·기능 대조 → Go/No-Go
                                  ├─ No-Go → 기존 운영 유지·원인 조치
                                  └─ Go → 쓰기 경계 고정·트래픽 절체
                                               ↓
                                     안정화 감시·장애 시 복구 판단
```

### 최종 동기화와 쓰기 권한 전환

```text
기존 환경 쓰기 → CDC·증분 적용 → 신규 환경 대조
                    ↓ 미반영 변경 0 또는 허용 범위 확인
기존 쓰기 중지 → 신규 쓰기 시작 → 단일 쓰기 권한 확인
                    ├─ 장애 전 원복 가능 시점 → 기존 환경 복구
                    └─ 신규 쓰기 후 장애 → 역동기화·손실 범위 판단
```

리허설에서는 데이터 건수뿐 아니라 업무 합계·대표 기능·복구 소요시간을 실제 전환 시나리오와 비교한다.

## Ⅳ. 전환 방식별 장애 영향 비교

| 방식 | 장점 | 핵심 장애 통제 |
|---|---|---|
| 일괄 절체 | 전환 경계가 명확 | 중단시간·원복 경로를 집중 검증 |
| 단계적 전환 | 범위를 나눠 영향 제한 | 신·구 환경 공존 중 호출·데이터 경계 관리 |
| 병행 운영 | 두 환경 결과를 비교 가능 | 쓰기 주체·결과 차이·종료 기준 합의 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 실제 데이터량·부하가 리허설과 달라 전환시간 초과 | 대표 데이터·동시 부하로 소요시간을 측정하고 중단 기준 설정 |
| 양쪽 시스템 쓰기로 데이터 차이 발생 | 전환 구간별 쓰기 주체와 CDC 방향을 명시하고 정합성 대조 |
| 신규 쓰기 후 단순 원복으로 변경 소실 | 원복 가능 시점과 역동기화·손실 허용 범위를 사전 시험 |
| 현장 판단 지연으로 장애 확대 | Go/No-Go 시간·책임자·관측 지표를 미리 합의 |

## Ⅵ. 제언

리허설 성공만으로 실제 전환의 데이터 변화와 부하를 보장할 수 없다. 최종 동기화·단일 쓰기 경계·원복 가능 시점을 한 시나리오로 시험하고, Go/No-Go 기준을 충족한 경우에만 트래픽을 절체한다.
