## 답안 골격
```text
[프로세스 메모리 영역] ◀━━ 머리: Ⅶ 내 의견 (스택·힙 경계 보호를 위한 ASLR과 가상 메모리 보호 비트 강화)
 ┃
 ┣━ Ⅰ 개요 ───── 단일 연속 메모리의 오염 위험 → 목적별 가상 주소 공간(Code·Data·Heap·Stack) 분할 관리
 ┣━ Ⅱ 특징 ───── 고정/동적 크기 분리 · 상하 대칭 확장(Heap↑, Stack↓) · 읽기/쓰기/실행(RWX) 권한 제어
 ┣━ Ⅲ 구조 ───── 코드(Text) + 데이터(GVAR/BSS) + 힙(Heap) + 스택(Stack) + 커널 영역
 ┣━ Ⅳ 흐름 ───── ① ELF 로더 로딩 → ② 정적 영역(Text/Data) 매핑 → ③ 런타임 동적 할당(brk/mmap) → ④ 함수 프레임 push/pop
 ┣━ Ⅴ 비교 ───── 힙(Heap) vs 스택(Stack)
 ┗━ Ⅵ 실무 ───── 스택 오버플로우 / 힙 단편화 및 메모리 누수 / 버퍼 오버플로우 공격
```
- 필수 키워드: 가상 주소 공간 · 코드(Text) · 데이터(Data/BSS) · 힙(Heap) · 스택(Stack) · ASLR · 권한 제어(RWX)
- 기출: 138회 2교시 6번 `운영체제 메모리 4가지 주요 영역의 역할, 특징, 동작 메커니즘` 논술형 출제

## 한 줄 본질
- 프로그램의 정적 실행 코드와 동적 가변 데이터를 뒤섞어 배치하면 주소 침범과 보안 침해가 발생함 → 가상 메모리 공간을 코드(읽기전용)·데이터(정적변수)·힙(동적할당)·스택(함수컨텍스트)으로 나누고 상하 대칭으로 마주 보며 확장 → 메모리 공간 효율화 및 상호 오염 격리 / 경계 침범 시 세그멘테이션 폴트 및 오버플로우 발생

## 핵심 그림
```text
[ 32/64비트 가상 메모리 주소 공간 배치도 ]

    높은 주소 (0xFFFFFFFF)
    +---------------------------------------+
    |           커널 영역 (Kernel Space)    |  OS 전용 공간 (User 모드 접근 금지)
    +---------------------------------------+
    |           스택 영역 (Stack)           |  지역변수, 매개변수, 복귀주소 (ESP/RSP)
    |                  │                    |  (높은 주소 -> 낮은 주소로 하향 확장: ↓)
    |                  v                    |
    |                                       |
    |                  ^                    |
    |                  │                    |  (낮은 주소 -> 높은 주소로 상향 확장: ↑)
    |           힙 영역 (Heap)              |  malloc()/new 동적 할당 공간 (brk/mmap)
    +---------------------------------------+
    |           BSS 영역 (Uninitialized)    |  초기화되지 않은 전역/정적 변수 (0 초기화)
    +---------------------------------------+
    |           데이터 영역 (Data)          |  초기화된 전역/정적 변수
    +---------------------------------------+
    |           코드/텍스트 영역 (Code)     |  실행 명령어 기계어 (Read-Only)
    +---------------------------------------+
    낮은 주소 (0x00000000)
```

## 핵심 용어
- BSS(Block Started by Symbol): 초기화되지 않은 전역 및 정적 변수를 저장하는 영역으로, 바이너리 파일 크기를 줄이기 위해 실행 시 커널이 0으로 일괄 초기화
- brk / sbrk: 프로세스 데이터 세그먼트(힙 영역)의 끝 주소를 나타내는 프로그램 브레이크를 이동시켜 힙 크기를 확장/축소하는 시스템 콜
- ASLR(Address Space Layout Randomization): 프로그램 실행 시 스택, 힙, 라이브러리 적재 주소를 난수화하여 메모리 주소 예측 공격을 차단하는 보안 기술

## 핵심 통찰
- 스택과 힙을 마주 보게 설계한 이유는 '공간 낭비의 최소화'임 → 둘 중 어느 것이 얼마나 커질지 컴파일 타임에는 알 수 없으므로 가운데 빈 공간을 공유하여 한쪽이 커지면 다른 쪽 여유 공간을 쓰도록 배려한 구조임
- 메모리 영역마다 CPU의 캐시 친화도가 극단적으로 갈림 → 스택은 상단(Top) 부근만 집중 접근하므로 L1/L2 캐시 적중률이 99%에 달하지만, 힙은 파편화될 경우 포인터 추적(Pointer Chasing)으로 인한 캐시 미스가 빈발함
- 현대 OS는 메모리 실행 방지(DEP / NX bit)를 기본 적용함 → 스택과 힙 영역에는 쓰기(W) 권한만 주고 실행(X) 권한을 박탈하여, 쉘코드가 스택에 주입되어도 실행되지 못하도록 하드웨어 레벨에서 차단함

## 이웃 토픽과 구분
- 스택 vs 힙: 스택 = 컴파일러 자동 관리, 함수 호출/복귀와 생명주기 일치, 초고속 할당, 크기 제한 / 힙 = 프로그래머 수동(또는 GC) 관리, 런타임 가변 크기 할당, 상대적 느린 속도, 단편화 위험

## 문제·원인·대책
- 사례: 138회 기출 및 C/C++ 기반 네트워크 데몬에서 스택 버퍼 오버플로우를 악용한 원격 코드 실행(RCE) 침해
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 스택 오버플로우로 복귀 주소(RET) 변조 및 쉘코드 실행 | 사용자 입력 길이를 검증하지 않는 함수(`strcpy`, `gets`) 사용 | 컴파일 시 Stack Canary 삽입 및 NX(No-Execute) 비트 활성화 | 복귀 주소 오염 감지 시 프로세스 즉시 강제 종료 |
| 장기 실행 서버에서 메모리 사용량 지속 증가로 OOM 발생 | 힙에 `malloc()`으로 할당한 메모리를 `free()`하지 않는 누수 | 정적 분석(SonarQube) 및 런타임 툴(Valgrind, ASan) 검증 파이프라인 연계 | 누수 지점 사전 탐지 및 자동 메모리 해제 보장 |

## 이렇게 출제된다
- 제138회 2교시 6번: "프로그램 실행 시 운영체제는 메모리를 4가지 주요 영역으로 나누어 할당 및 관리한다. 각 영역의 역할과 특징 그리고 영역 간 동작 메커니즘에 대하여 다음 내용을 설명하시오." → 요구 포인트: Ⅰ 가상 메모리 공간 분할 이유 + Ⅲ 4대 영역(Code, Data, Heap, Stack)별 권한 및 역할 + Ⅳ 힙과 스택의 런타임 상호 동작 및 보안 기법

## 내 의견
- [안전한 언어 전환과 컴파일러 레벨 보호 기법 기본 내재화] C/C++ 기반의 수동 메모리 관리는 아무리 숙련된 개발자라도 휴먼 에러로 인한 취약점(Use-After-Free, Double Free)을 원천 방지하기 어려움 → 나라면: 시스템 핵심 데몬 개발 시 소유권 기반으로 메모리 안전성을 컴파일 타임에 보장하는 Rust 언어를 우선 채택하고, 레거시 C 프로젝트는 GCC의 `-fstack-protector-all`, `-D_FORTIFY_SOURCE=2` 옵션을 CI/CD 빌드 규칙에 강제 적용하여 런타임 취약점 전면 방어
