## 지식 로드맵 내 현재 위치

지식 위치: 컴퓨터 시스템 → 클라우드 운영·통제 → **소버린 클라우드**

## 30초 인출

- 본질: **소버린 클라우드 (Sovereign Cloud)** 는 데이터·운영·기술에 대한 통제권을 요구 수준에 맞춰 확보한 클라우드 운영 방식
- 메커니즘: 적용 법률·데이터 위치·접근권한·운영 주체·암호화 키·공급망별 확인과 계약·기술 통제
- 통찰: 데이터의 저장 위치와 운영 통제권을 특정 국가의 법적 관할권 내에 완전히 귀속시켜 디지털 주권과 규제 컴플라이언스를 확보 체계화.

<details>
<summary>핵심 용어</summary>

- **데이터 레지던시** : 데이터가 저장·처리되는 지리적 위치에 관한 요구
- **소버린 클라우드 (Sovereign Cloud)** : 적용 관할과 업무 요구에 맞는 데이터·운영·기술 통제권을 확보하는 클라우드 운영 방식.
- **관할권** : 데이터·서비스·공급자에게 어떤 법률과 정부 권한이 적용되는지에 관한 문제
- **운영 통제권** : 누가 시스템에 접근하고 장애 대응·변경을 수행할 수 있는지 결정하는 권한
- **고객 관리 키** : 고객이 암호화 키의 생성·보관·사용 정책을 관리하는 방식. 공급자의 실제 접근 가능 범위는 구현과 계약에 따른 확인 사항.
- **CSAP (Cloud Security Assurance Program)** : 국내 공공부문 클라우드 서비스의 보안성을 평가·인증하는 제도이며, 소버린 클라우드 전체 요건과는 별개.

</details>

## 2~4교시 25점 답안

## Ⅰ. 소버린 클라우드의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **소버린 클라우드 (Sovereign Cloud)** 는 데이터·운영·기술에 대한 통제권을 적용 관할과 업무 요구에 맞춰 확보하는 클라우드 운영 방식 |
| 목적 | 중요 데이터·서비스의 통제권과 운영 연속성 확보 |

## Ⅱ. 소버린 클라우드의 특징

| 평가 범위 | 확인할 대상 |
|---|---|
| 법적 관할 | 공급자·서비스·데이터에 적용될 법률과 접근 요청 처리 절차 |
| 데이터 | 저장·처리·백업 위치와 이전 경로 |
| 운영 | 관리자 원격 접근, 장애 대응, 하도급 운영 주체 |
| 기술 | 키 통제, 구성요소의 교체·이전 가능성, 공급망 의존성 |

적용 원칙: 관할·계약·업무별 통제 요구의 차이. 모든 서비스에 동일한 국내 저장·자국민 운영·특정 키 제품을 요구하는 보편 의무는 아님.

## Ⅲ. 요구별 통제와 검증 체계

```text
업무별 법률·계약 요구
       ├→ 데이터: 저장·처리·백업·이전 위치
       ├→ 운영: 관리자·하도급자 접근과 장애 대응
       └→ 기술: 키 통제·구성요소·공급망 의존
                    ↓
              요구별 증거·운영 기록 확인
```

```text
국내 저장 확인 → 관리자 원격 접근 경로·권한 확인
                         ↓
                 계약상 승인 조건과 실제 로그 대조
                         ↓
                 사고 대응·퇴출 절차 시험
```

## Ⅳ. 인접 개념 비교와 검증 증거의 관계

| 개념 | 주된 범위 | 주권 판단에 남는 것 |
|---|---|---|
| 데이터 레지던시 | 데이터의 저장 위치 | 법적 관할·원격 접근·운영 주체 |
| 프라이빗 클라우드 | 자원의 전용 사용 주체 | 공급망·키·관할 통제 |
| 소버린 클라우드 | 필요한 통제권의 확보 | 요구 수준별 증거와 지속 운영 |

### 도입 시 검증과 운영

| 확인 시점 | 검증할 증거 |
|---|---|
| 계약·설계 | 데이터 위치, 운영 주체, 접근 권한, 하도급 조건 |
| 운영 | 관리자 접속 기록, 키 사용 이력, 변경·장애 처리 기록 |
| 전환·종료 | 데이터 반출·삭제와 대체 환경으로 이전할 수 있는지 |

인증 활용 기준: **CSAP (Cloud Security Assurance Program)** 등 보안인증의 적용 대상·인증 범위 확인. 단일 인증만으로 모든 주권 요구가 충족된다고 단정하지 않음.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 국내 저장만 확인하고 원격 관리자 접근을 놓침 | 실제 관리자 권한·접속 경로와 사고 시 접근 절차를 계약·로그로 검증 |
| 특정 공급자에 의존해 운영 이전이 어려움 | 데이터 반출·삭제와 핵심 구성의 이전 절차를 사전에 시험 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
해외 클라우드 사업자의 클라우드 액트(CLOUD Act) 적용을 원천 차단하기 위해 데이터 거주성(Residency), 운영 주권, 기술적 주권을 독립 평가하고 국산 CSP와 하이브리드 연계.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 소버린 클라우드 (Sovereign Cloud) 3대 주권 통제 프레임워크 ]         │
│                                                                        │
│ 1. 데이터 주권 (Data Sovereignty)                                      │
│    - 데이터 저장 위치(Data Residency)를 자국 영토 내로 법적 한정       │
│    - 국외 반출 통제 및 자국 개인정보보호법/안보 규정 100% 준수          │
│                                                                        │
│ 2. 운영 주권 (Operational Sovereignty)                                 │
│    - 클라우드 인프라 운영 요원의 신원 검증 및 자국민 한정              │
│    - 해외 본사의 원격 백도어 접속 및 기술 지원 차단                   │
│                                                                        │
│ 3. 기술/암호 주권 (Technical & Software Sovereignty)                   │
│    - 외부 CSP가 복호화할 수 없는 고객 자체 암호화 키 관리 (HYOK/BYOK) │
│    - 오픈소스 기반 오픈 스택 기술로 벤더 종속 배제                     │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 주권 통제 축 | 핵심 요구사항 | 기술적 구현 방안 | 미충족 시 리스크 |
|---|---|---|---|
| **데이터 거주성 (Residency)** | 모든 원천 데이터 및 백업의 국내 물리 보관 | 로컬 전용 데이터센터 리전 격리 | 해외 법원 영장에 의한 데이터 강제 압수 |
| **접근 통제권 (Access)** | 해외 CSP 엔지니어의 비인가 접근 원천 차단 | 무신뢰(Zero Trust) 권한 관리, PAM | 내부자 위협 및 국가 기밀 유출 |
| **암호화 통제권 (Key Mgmt)** | 암호화 마스터 키의 온프레미스 단독 보관 | HSM 기반 HYOK (Hold Your Own Key) | 클라우드 사업자에 의한 데이터 임의 복호화 |
| **이식성 (Portability)** | 유사시 타 인프라로의 중단 없는 이전 보장 | 컨테이너 표준화(K8s), 오픈 클라우드 스택 | 벤더 락인 및 외교적 제재 시 서비스 중단 |

## 출제 이력과 검증 출처

- European Union General Data Protection Regulation (GDPR) Chapter V
- ENISA (European Union Agency for Cybersecurity) - Cloud Security and Sovereignty
- 과학기술정보통신부 국가 클라우드 보안인증제도(CSAP) 등급제 가이드라인
