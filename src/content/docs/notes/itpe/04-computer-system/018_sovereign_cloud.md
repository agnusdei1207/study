지식 위치: 컴퓨터 시스템 → 클라우드 운영·통제 → **소버린 클라우드**

## 30초 인출

- 본질: **소버린 클라우드 (Sovereign Cloud)** 는 데이터·운영·기술에 대한 통제권을 요구 수준에 맞춰 확보한 클라우드 운영 방식
- 메커니즘: 적용 법률·데이터 위치·접근권한·운영 주체·암호화 키·공급망별 확인과 계약·기술 통제

<details>
<summary>핵심 용어</summary>

- **데이터 레지던시** : 데이터가 저장·처리되는 지리적 위치에 관한 요구
- **소버린 클라우드 (Sovereign Cloud)** : 적용 관할과 업무 요구에 맞는 데이터·운영·기술 통제권을 확보하는 클라우드 운영 방식.
- **관할권** : 데이터·서비스·공급자에게 어떤 법률과 정부 권한이 적용되는지에 관한 문제
- **운영 통제권** : 누가 시스템에 접근하고 장애 대응·변경을 수행할 수 있는지 결정하는 권한
- **고객 관리 키** : 고객이 암호화 키의 생성·보관·사용 정책을 관리하는 방식. 공급자의 실제 접근 가능 범위는 구현과 계약에 따른 확인 사항.
- **CSAP (Cloud Security Assurance Program)** : 국내 공공부문 클라우드 서비스의 보안성을 평가·인증하는 제도이며, 소버린 클라우드 전체 요건과는 별개.

</details>

| 범위 | 핵심 질문 |

제언: 민감도와 적용 규정에 맞는 통제 수준을 정하고 공급자의 실제 접근 경로를 검증

## 2~4교시 25점 답안

## Ⅰ. 소버린 클라우드의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **소버린 클라우드 (Sovereign Cloud)** 는 데이터·운영·기술에 대한 통제권을 적용 관할과 업무 요구에 맞춰 확보하는 클라우드 운영 방식 |
| 목적 | 중요 데이터·서비스의 통제권과 운영 연속성 확보 |

## Ⅱ. 주권 요구를 판단하는 범위

| 평가 범위 | 확인할 대상 |
|---|---|
| 법적 관할 | 공급자·서비스·데이터에 적용될 법률과 접근 요청 처리 절차 |
| 데이터 | 저장·처리·백업 위치와 이전 경로 |
| 운영 | 관리자 원격 접근, 장애 대응, 하도급 운영 주체 |
| 기술 | 키 통제, 구성요소의 교체·이전 가능성, 공급망 의존성 |

적용 원칙: 관할·계약·업무별 통제 요구의 차이. 모든 서비스에 동일한 국내 저장·자국민 운영·특정 키 제품을 요구하는 보편 의무는 아님.

## Ⅲ. 인접 개념과의 차이

| 개념 | 중심 질문 | 주권 판단에 남는 것 |
|---|---|---|
| 데이터 레지던시 | 어디에 데이터가 있는가 | 법적 관할·원격 접근·운영 주체 |
| 프라이빗 클라우드 | 누가 자원을 전용으로 쓰는가 | 공급망·키·관할 통제 |
| 소버린 클라우드 | 필요한 통제권이 확보되는가 | 요구 수준별 증거와 지속 운영 |

## Ⅳ. 도입 시 검증과 운영

| 확인 시점 | 검증할 증거 |
|---|---|
| 계약·설계 | 데이터 위치, 운영 주체, 접근 권한, 하도급 조건 |
| 운영 | 관리자 접속 기록, 키 사용 이력, 변경·장애 처리 기록 |
| 전환·종료 | 데이터 반출·삭제와 대체 환경으로 이전할 수 있는지 |

인증 활용 기준: **CSAP (Cloud Security Assurance Program)** 등 보안인증의 적용 대상·인증 범위 확인. 단일 인증만으로 모든 주권 요구가 충족된다고 단정하지 않음.

## Ⅴ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 국내 저장만 확인하고 원격 관리자 접근을 놓침 | 실제 관리자 권한·접속 경로와 사고 시 접근 절차를 계약·로그로 검증 |
| 특정 공급자에 의존해 운영 이전이 어려움 | 데이터 반출·삭제와 핵심 구성의 이전 절차를 사전에 시험 |
