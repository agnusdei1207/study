## 연관 키워드

- 소버린 클라우드(Sovereign Cloud), 데이터 주권, 운영 주권, 기술 주권, 데이터 레지던시
- HYOK, HSM, 기밀 컴퓨팅, CLOUD Act, GDPR, 동형 암호, 연합 학습, 티어링, 소버린 AI

## Ⅰ. 소버린 클라우드(Sovereign Cloud)의 개요

- 핵심 요약 : 데이터·운영·기술 주권을 자국 관할 아래 두어 역외 법령에 의한 접근을 차단하는 클라우드 아키텍처.
- 개념 : 클라우드 이용 국가의 법률과 거버넌스 요건을 준수하기 위해, 데이터의 저장 위치뿐 아니라 인프라, 소프트웨어 스택, 암호화 키 통제권, 현지 운영 인력까지 해당 국가의 배타적 관할 아래 두는 **소버린 클라우드** (Sovereign Cloud, 주권 클라우드).
- 배경 및 필요성 : 미국의 **클라우드법** (CLOUD Act, 역외 데이터 제출 법령)처럼 외국 법령이 국내 데이터에 미치는 영향이 커지면서 국가 전략 데이터의 유출 위험이 누적되고, 이 위험을 낮추는 통제 수단이 필요해짐. EU는 GDPR(General Data Protection Regulation)과 디지털 주권 정책을 함께 추진하며 같은 방향의 요구를 보여 줌.
- 주요 목적 : 외국 정부의 부당한 데이터 접근 차단, 핵심 인프라의 기술 자립도 확보, 공공·금융 망분리 등 자국 규제 요건에 맞는 클라우드 환경 구현.

## Ⅱ. 소버린 클라우드(Sovereign Cloud)의 특징 및 장점

- 핵심 요약 : 데이터·운영·기술의 3대 주권과 기밀 컴퓨팅이 결합되어 외부 접근을 차단하는 구조.

1. **데이터 주권** (Data Sovereignty) : 고객 데이터와 메타데이터를 국경 안에 보관하고, 고객 자신이 키를 보유하는 **HYOK** (Hold Your Own Key, 고객 보유 키) 방식을 적용 → 외국 기관이 키 없이 데이터를 열람할 수 없게 됨.
2. **운영 주권** (Operational Sovereignty) : 보안 인가를 받은 현지 인력에게만 운영 권한을 주고, 본사의 원격 접근을 통제·감사 → 비상 시에도 현지에서 독립 운영 가능.
3. **기밀 컴퓨팅** (Confidential Computing) : 하드웨어 기반 보안 엔클레이브(Intel SGX, AMD SEV 등)로 처리 중인 데이터까지 메모리 수준에서 암호화 → 인프라 운영자로부터 데이터 보호 강화.
4. **기술 주권** (Technical Sovereignty) : 쿠버네티스, 리눅스 같은 오픈소스 표준 스택으로 구성 → 특정 공급자 종속을 피하고 자체 유지보수 가능.

## Ⅲ. 소버린 클라우드(Sovereign Cloud)의 구조 및 동작 메커니즘

- 핵심 요약 : 관할권 아래 3대 주권이 놓이고, 그 밑에서 기밀 컴퓨팅과 하드웨어 보안 모듈(HSM, Hardware Security Module)이 보안 인프라를 받치는 계층 구조.

```text
[ 소버린 클라우드 계층 구조 ]

국가 관할 거버넌스와 법규
        ↓
데이터 주권 · 운영 주권 · 기술 주권
        ↓
기밀 컴퓨팅 · HSM 보안 인프라
        ↓
고객 관리 키로 보호되는 워크로드
```

```text
[ 키 통제 흐름 (HYOK) ]

고객 전용 HSM에 키 보관
        ↓
국내 리전에 암호화 데이터 저장
        ↓
처리 요청 시 키 사용을 고객이 승인
        ↓
기밀 컴퓨팅 엔클레이브에서 처리
```

## Ⅳ. 소버린 클라우드(Sovereign Cloud)의 비교

- 핵심 요약 : 글로벌 퍼블릭, 소버린, 레거시 프라이빗이 데이터 위치와 키 통제권에서 갈리는 구조.

| 비교 항목 | 글로벌 퍼블릭 클라우드 | 소버린 클라우드 | 레거시 프라이빗 클라우드 |
| --- | --- | --- | --- |
| 데이터 레지던시 | 글로벌 분산 리전, 해외 이전 가능 | 자국 영토 내 데이터센터로 제한 | 자체 전산실 또는 지정 IDC |
| 운영 주체 | 글로벌 공급자 엔지니어링 조직 | 현지 인가 인력 또는 현지 파트너 | 사내 IT 운영팀 또는 국내 SI 파트너 |
| 암호화 키 통제 | 공급자 관리형 키 또는 공유 HSM | 고객 전용 하드웨어 키 격리 (HYOK) | 자체 HSM 직접 소유 |
| 적용 법령 | 역외 관할 법령 적용 가능 | 자국 법령만 배타적 적용 | 자국 법령만 적용 |
| 최신 서비스 도입 | 최신 AI·PaaS 즉시 배포 | 주권 검증 후 선별 배포로 지연 | 자체 개발 또는 레거시 솔루션 한정 |

- 선택 기준 : 데이터 민감도와 규제 강도에 따라 보호 등급을 나누고, 등급별로 퍼블릭과 소버린 계층을 배치하는 방식이 현실적임.

## Ⅴ. 소버린 클라우드(Sovereign Cloud)의 한계와 방안

- 핵심 요약 : 서비스 도입 지연, 운영 단가 상승, 국경 간 데이터 연계 저하의 세 한계를 협력 모델, 데이터 티어링, 동형 암호로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 최신 서비스 도입 지연 | 현지화와 주권 인증 심사로 글로벌 AI·PaaS 반영이 늦어짐 | 글로벌 공급자와 현지 사업자의 합작 모델 활용 | 신규 서비스 반영 지연 기간 |
| 운영 단가 상승 | 독립 인프라, 전용 HSM, 현지 인력 채용 비용 증가 | 데이터 민감도별 **티어링** (Tiering, 등급별 차등 적용) 정책으로 최고 등급 데이터에만 적용 | 등급별 워크로드 비율, 단위 운영 비용 |
| 국경 간 데이터 연계 저하 | 이전 규제로 해외 지사·파트너와의 협업 지연 | **동형 암호** (Homomorphic Encryption, 암호문 상태 연산)와 **연합 학습** (Federated Learning, 데이터를 두고 모델만 이동)으로 원본 반출 없이 분석 | 원본 반출 건수, 분석 완료 주기 |

## Ⅵ. 소버린 클라우드(Sovereign Cloud)에 대한 기술사적 제언

- 핵심 요약 : 소버린 AI 기반 설계, 망분리 규제와의 정합성, 국내 사업자 협력을 묶어 소버린 클라우드를 국가 디지털 기반으로 내재화.
- 공공·금융기관이 **소버린 AI** (Sovereign AI, 국가 언어와 법제를 반영한 AI 역량)를 구축할 때는 학습·추론 파이프라인 전체를 소버린 클라우드 위에 두도록 기준을 세워야 한다.
- 망분리 관련 규제가 정비되는 흐름에서는 기밀 컴퓨팅 기반 환경을 소버린 클라우드 인증 기준에 포함시켜 공공 시스템 전환의 판단 기준을 표준화하는 편이 바람직하다.
- 국내 클라우드 사업자와 통신사는 주권 요건을 충족하는 공동 서비스를 만들며 기술 자립도를 높이고, 정부는 이 과정의 인증과 조달 제도를 뒷받침해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 소버린 클라우드는 데이터·운영·기술 주권을 자국 관할에 두어 역외 법령 접근을 차단하는 클라우드 모델.
- 시사점 : 최신 서비스 지연과 비용 상승을 감수하는 대신 통제력을 얻는 모델이므로, 데이터 등급에 따라 적용 범위를 나누는 설계가 성패를 가름.
