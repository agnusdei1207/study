## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 스토리지 가상화

## 30초 인출

- 본질: 서로 다른 제조사의 외장 스토리지를 따로 운영하면 특정 장비는 용량이 부족하고 다른 장비는 남아도는 파편화가 발생함
- 메커니즘: 여러 물리 스토리지를 소프트웨어 계층에서 단일 거대 가상 풀(Pool)로 묶어 호스트에 논리 볼륨을 동적 할당

## 핵심 용어

- 씬 프로비저닝(Thin Provisioning): 가상 볼륨 생성 시 실제 물리 디스크를 미리 할당하지 않고, 애플리케이션이 실제로 데이터를 기록할 때만 물리 블록을 실시간 동적 할당하는 기술
- 인밴드(In-Band) 가상화: 호스트와 물리 스토리지 사이의 데이터 경로 상에 가상화 장비가 직접 위치하여 모든 I/O와 메타데이터를 직접 제어하는 방식
- 아웃오브밴드(Out-of-Band) 가상화: 제어 경로(메타데이터)와 실제 데이터 전송 경로를 분리하여, 호스트가 메타데이터 서버로부터 주소만 받고 실제 I/O는 스토리지와 직접 수행하는 방식

## 2~4교시 25점 답안

### Ⅰ. 핵심 구조와 작동

```text
[ 스토리지 가상화 3대 구현 위치 및 추상화 구조 ]

(1) 호스트 기반 (LVM)      (2) 네트워크/스위치 기반 (SAN Appliance)  (3) 어레이 기반
 [ Host (OS) ]               [ Host ]            [ Host ]              [ Host ]
 +─────────────+                 │                   │                     │
 | LVM 가상화  |                 v (가상 LUN 요청)   v                     v
 +──────┬──────+            +───────────────────────────+             +─────────+
        │                   | 가상화 엔진 (SAN 스위치)  |             | 스토리지|
        v                   | - In-Band: 데이터 직접 통과 |             | 어레이  |
 [이종 물리 스토리지]        | - Out-of-Band: 메타데이터만|             | 내부    |
                            +─────────────┬─────────────+             | 가상화  |
                                          v (물리 블록 매핑)          +────┬────+
                            [ 물리 스토리지 A | B | C (Pool) ]             v
```

### Ⅱ. 핵심 특성

- 스토리지 가상화의 꽃은 '무중단 마이그레이션'임 → 노후화된 스토리지를 신규 스토리지로 교체할 때 서비스를 내리지 않고도 가상 볼륨 매핑만 슬그머니 변경하여 백그라운드 데이터 복제를 수행함
- 가상화가 없으면 디스크 낭비율이 60%에 달함 → '혹시 몰라서' 넉넉하게 할당해 둔 팻 프로비저닝(Thick) 공간을 씬 프로비저닝으로 회수하여 스토리지 구매 예산을 절반 이하로 줄임
- 현대의 스토리지 가상화는 곧 'SDS(Software-Defined Storage)'임 → 비싼 전용 하드웨어 SAN 스토리지 대신 범용 x86 서버들에 Ceph, vSAN을 깔아 분산 스토리지 풀로 묶는 소프트웨어 중심 패러다임으로 완전 전환됨

### Ⅲ. 관련 개념과 구분

- 서버 가상화 vs 스토리지 가상화: 서버 가상화 = 하이퍼바이저가 CPU/RAM을 가상머신 단위로 분할 / 스토리지 가상화 = 컨트롤러/소프트웨어가 이기종 물리 블록 디스크들을 단일 LUN 풀로 통합

### Ⅳ. 적용 문제와 대응

- 사례: 134회 기출 및 대규모 엔터프라이즈 환경에서 이기종 스토리지 통합 가상화 적용 후 I/O 지연 현상 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 대용량 트랜잭션 DB 구동 시 인밴드 가상화 어플라이언스에서 I/O 병목 | 모든 데이터 패킷이 중앙 가상화 컨트롤러를 통과하며 레이턴시 누적 | 고성능 DB는 아웃오브밴드 가상화 적용 또는 NVMe-oF 직결 바이패스 | 데이터 전송 지연 시간 마이크로초 단위 단축 |
| 씬 프로비저닝 초과 할당(Over-Commit) 상태에서 물리 디스크 풀 급격한 고갈 | 실제 데이터 증가율 모니터링 부재로 물리 풀 여유 공간 0% 도달 | 스토리지 용량 80% 도달 시 자동 경보 및 스토리지 풀 자동 확장(Auto-tiering) | 스토리지 I/O 동결 및 시스템 다운 사태 사전 예방 |
