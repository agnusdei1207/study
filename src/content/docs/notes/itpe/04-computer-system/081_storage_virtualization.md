## 연관 키워드

- 스토리지 가상화, Storage Virtualization, 가상 스토리지 풀, 씬 프로비저닝, 자동 계층화
- 인밴드, 아웃오브밴드, LUN, 호스트·네트워크·어레이 기반, MPIO, SDS

## Ⅰ. 스토리지 가상화의 개요

- 핵심 요약 : 이기종 물리 스토리지를 논리 풀로 묶어 중앙에서 할당과 이전을 관리하는 추상화 기술.
- 개념 : 벤더가 다른 디스크 어레이의 물리 용량을 논리 계층으로 추상화해 단일 **가상 스토리지 풀** (Virtual Storage Pool)로 통합하고 호스트에 논리 볼륨으로 제공하는 **스토리지 가상화** (Storage Virtualization).
- 배경 및 필요성 : 장비 단위로 고립된 스토리지는 일부는 포화되고 일부는 유휴 상태로 남아 활용률이 낮음. 장비 교체·데이터 이전 시 서비스 중단이 따라와 총소유비용(TCO, Total Cost of Ownership)을 높임.
- 주요 목적 : 용량 통합으로 활용률을 높이고, **씬 프로비저닝** (Thin Provisioning, 사용량에 따라 용량을 실제 할당하는 방식)과 **자동 계층화** (Auto-Tiering, 접근 빈도에 따라 저장 계층을 옮기는 기능)로 효율을 극대화하는 것.

## Ⅱ. 스토리지 가상화의 특징 및 장점

- 핵심 요약 : 제어 정보의 통과 위치에 따라 캐시·보안의 일관성과 데이터 경로 성능의 균형점이 달라지는 구조.

1. 경유형 구성 : 데이터와 제어 정보가 모두 가상화 엔진을 통과하는 **인밴드 가상화** (In-Band Virtualization) → 캐시·보안 기능의 일괄 적용이 가능하나 엔진이 병목과 장애 집중점이 될 수 있음.
2. 분리형 구성 : 메타데이터 조회만 별도 서버가 담당하고 데이터는 호스트와 스토리지가 직접 전송하는 **아웃오브밴드 가상화** (Out-of-Band Virtualization) → 데이터 경로의 병목이 적으나 호스트 에이전트 설치가 필요.

## Ⅲ. 스토리지 가상화의 구조 (흐름)

- 핵심 요약 : 가상화 기능을 두는 구현 계층(호스트·네트워크·어레이)과 제어 정보의 경로로 구조를 설명하는 틀.
- 구현 계층 : 서버 볼륨 관리자를 쓰는 **호스트 기반 가상화** (Host-Based Virtualization), 네트워크 장비에서 수행하는 **네트워크 기반 가상화** (Network-Based Virtualization), 어레이 컨트롤러가 수행하는 **어레이 기반 가상화** (Array-Based Virtualization). 논리 볼륨은 **논리 유닛 번호** (LUN, Logical Unit Number)로 호스트에 노출됨.

```text
[ 구현 3계층 구조 ]

호스트 기반 (서버 볼륨 관리자)
        ↓ 블록 입출력 요청
네트워크 기반 (스토리지 네트워크·가상화 장치)
        ↓ 물리 입출력 변환
어레이 기반 (컨트롤러 펌웨어)
```

```text
[ 제어 정보의 경로 차이 ]

인밴드 :
  호스트 → 가상화 엔진 → 스토리지
아웃오브밴드 :
  호스트 → 스토리지 (데이터 직통)
  호스트 → 메타데이터 서버 (제어)
```

## Ⅳ. 구현 계층 방식의 비교

- 핵심 요약 : 가상화 기능의 구현 위치에 따라 호스트 부하, 이기종 지원 범위, 활용 가능한 기능이 달라지는 구조.
- 선택 기준 : 이기종 장비의 범위, 서버 자원 여유, 하부 장비 고유 기능의 살림 필요성을 기준으로 계층을 고른다.

| 비교 항목 | 호스트 기반 | 네트워크 기반 | 어레이 기반 |
| :--- | :--- | :--- | :--- |
| 구현 위치 | 각 서버의 볼륨 관리자 | 스토리지 네트워크·독립 가상화 장치 | 메인 어레이 컨트롤러 펌웨어 |
| 대표 기술 | Linux LVM(Logical Volume Manager) | 스토리지 가상화 전용 장치(예: IBM SAN Volume Controller) | 어레이 내장 가상화 펌웨어 |
| 이기종 지원 | 호스트 OS 지원 범위 내 | 대부분의 SAN 스토리지 | 인증된 타사 어레이에 한정 |
| 호스트 부하 | 서버 CPU·메모리 자원 점유 | 없음 | 없음 |
| 주요 강점 | 추가 하드웨어 구매 부담 없음 | 중앙 집중식 단일 뷰 관리 | 컨트롤러 캐시 성능의 최대 활용 |

## Ⅴ. 스토리지 가상화의 한계와 방안

- 핵심 요약 : 중앙 엔진의 병목과 장애 집중, 하부 장비 기능의 제한, 매핑 메타데이터 손상을 다중화, 대체 기능, 메타데이터 보호로 일대일 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| 중앙 엔진의 병목과 단일 장애점 | 전사 트래픽이 인밴드 엔진 하나에 몰리면 지연 증가, 엔진 장애 시 연결 서비스 전체 중단 | 액티브-액티브 구성의 다중 노드 엔진, 다중 경로 입출력 (**MPIO**, Multipath I/O) 기반 페일오버 | 경로별 지연, 페일오버 전환 시간 |
| 하부 장비 고유 기능의 제한 | 어레이 자체의 하드웨어 가속(스냅샷, 원격 복제)이 상위 공통 계층에 묶여 사용이 제한됨 | 가상화 계층의 벤더 독립 스냅샷·**지속적 데이터 보호** (CDP, Continuous Data Protection) 엔진 사용 | 기능 사용률, 복구 시점 충족률 |
| **매핑 메타데이터 손상** | 논리-물리 주소 매핑 테이블 훼손 시 물리 블록 식별 불가로 전사 볼륨 붕괴 위험 | 메타데이터 3중 미러링, 주기적 백업과 트랜잭션 저널링 | 메타데이터 무결성 점검 결과, 복원 성공률 |

## Ⅵ. 스토리지 가상화에 대한 기술사적 제언

- 핵심 요약 : 소프트웨어 정의 전환, 컨테이너 연동, 고속 계층 설계로 스토리지 가상화를 하드웨어 교체 주기와 분리된 운영 체계로 정착.

1. 소프트웨어 정의 전환 : 신규 인프라 담당 조직은 장비별 가상화 대신 **소프트웨어 정의 스토리지** (SDS, Software-Defined Storage) 기반 풀 구성으로 하드웨어 교체 주기와 무관한 확장 체계 구축.
2. 컨테이너 연동 : 컨테이너 플랫폼 조직은 **컨테이너 스토리지 인터페이스** (CSI, Container Storage Interface) 기반 볼륨 자동 생성·연결과 플랫폼·스토리지 조직 공동의 정책 정의.
3. 고속 계층 설계 : 고성능 구간 설계 조직은 **NVMe over Fabrics** (NVMe-oF) 연결과 다중 경로 설계의 병행으로 고속 계층 가용성 확보.

## Ⅶ. 결론

- 핵심 요약 : 스토리지 가상화는 이기종 물리 스토리지의 논리 풀 통합으로 활용률과 무중단 이전을 실현하는 인프라 기술.
- 중앙 경로의 이중화와 매핑 메타데이터 보호 수준이 도입 효과의 안정성을 좌우.
