<summary>핵심 용어</summary>

- **스토리지 가상화 (Storage Virtualization)** : 물리 저장 자원을 논리 저장 공간으로 추상화하는 기술
- **논리 볼륨 (Logical Volume)** : 하나 이상의 물리 저장 영역을 논리적으로 묶어 호스트에 제공한 저장 단위
- **씬 프로비저닝 (Thin Provisioning)** : 논리 용량을 미리 크게 할당해 보여주되 물리 용량은 실제 사용에 따라 할당하는 방식
- **스냅샷 (Snapshot)** : 특정 시점의 데이터 상태를 복구·참조하기 위해 보존하는 논리 이미지
- **스토리지 풀 (Storage Pool)** : 가상 볼륨을 제공하기 위해 물리 저장 용량을 묶은 자원 집합
</details>

## 2~4교시 25점 답안

## Ⅰ. 스토리지 가상화의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **스토리지 가상화 (Storage Virtualization)는** 여러 물리 저장 자원을 논리 자원으로 추상화해 호스트에 제공하는 기술 |
| 목적 | 물리 장치와 호스트 간 결합을 낮추고 용량·보호·운영을 통합 관리하는 것 |

## Ⅱ. 물리 자원과 논리 자원을 분리하는 특징

| 특징 | 의미 |
|---|---|
| 주소 추상화 | 호스트의 논리 주소를 실제 물리 위치에 매핑 |
| 자원 풀링 | 여러 장치의 용량을 정책별로 묶어 제공 |
| 정책 적용 | 논리 자원별 용량·보호·성능·접근 기준을 따로 관리 |

## Ⅲ. 자원 제공과 호스트 I/O 처리 체계

```text
디스크·플래시 → 스토리지 풀 → 가상화 계층 → 논리 볼륨·네임스페이스 → 호스트
                      용량·보호 정책   주소·경로 매핑               ↓ I/O 논리 주소
물리 장치 ← 물리 위치 조회 ← 가상화 매핑 ←──────────────────────┘
```

논리 볼륨을 제공할 때 물리 상태를 확인하고 풀을 구성한 뒤 호스트 접근 권한과 다중 경로를 매핑한다. 이후 I/O마다 논리 주소를 물리 위치로 변환하며 복제·스냅샷의 쓰기 순서를 관리한다.

## Ⅳ. 가상화 방식과 보호 기능의 관계

| 방식·기능 | 목적 | 운영 확인 |
|---|---|---|
| 블록 가상화 | 물리 블록을 논리 볼륨으로 매핑 | LUN·호스트 경로·파일시스템 |
| 파일 가상화 | 파일시스템의 이름 공간 통합 | 경로 이동·권한·파일 잠금 |
| 씬 프로비저닝 | 논리 용량과 실제 할당량 분리 | 풀 여유·임계치 경보 |
| 스냅샷 | 특정 시점의 상태 참조 | 별도 백업·격리를 대체하지 않는지 |
| 복제 | 다른 장애영역에 사본 유지 | 지연·일관성·전환 시험 |
| 계층화 | 데이터 특성별 매체 배치 | 이동 정책·성능 변동 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 씬 할당량이 실제 풀 용량을 넘으면 쓰기가 실패할 수 있음 | 실제 사용량·성장률·복제 공간을 포함해 임계치 경보와 증설 절차 운영 |
| 추상화 계층 때문에 장애 원인과 성능 병목을 추적하기 어려움 | 논리·물리 매핑, 경로, 지연 지표를 한 흐름으로 관측하고 장애 훈련 수행 |
| 가상 용량만으로 보호 수준을 판단하면 실제 복구 능력을 과대평가 | 장애영역과 복구 시험 결과를 용량 계획에 함께 반영 |

## Ⅵ. 제언 — 물리 여유와 복구 가능성부터 검증

먼저 논리 할당량과 실제 풀 사용량·복제 공간을 함께 측정해 쓰기 실패 위험을 판정하고, 장애영역별 복구 시험으로 보호 정책의 효과를 확인한다.
