## 연관 키워드
- 은행가 알고리즘, 교착상태 회피, 안전 상태, Available, Allocation, Need

## Ⅰ. 은행가 알고리즘의 개요
- 핵심 요약 : 은행가 알고리즘은 요청을 임시 할당한 뒤 안전 순서가 존재할 때만 승인하는 교착 회피 기법.
- 개념 : **은행가 알고리즘**(Banker's Algorithm)은 최대 자원 요구량을 사전에 알고 있다는 가정 아래, 현재 가용량으로 모든 프로세스를 완료할 순서가 존재하는지 검사.
- 배경 및 필요성 : 선점이 곤란한 자원에서 교착 상태로 이어질 할당을 사전에 제한할 필요.
- 주요 목적 : 자원 이용을 허용하면서 안전 상태를 유지하는 요청 승인.

## Ⅱ. 자료와 안전성 원리
- 핵심 요약 : 가용량·할당량·최대 요구량으로 Need를 계산해 완료 가능 순서를 찾음.
- Available은 미할당 자원, Allocation은 현재 할당, Max는 최대 요구량이며 Need = Max - Allocation.
- 프로세스는 Need ≤ Work일 때 완료 가능하고, 완료 시 Allocation이 반환된다고 가정해 Work를 늘림.
- 안전 상태는 모든 프로세스를 끝낼 순서가 하나 이상 존재하는 상태.

## Ⅲ. 안전성 검사 흐름
- 핵심 요약 : 요청을 임시 반영해 안전 순서를 검사하고 안전할 때만 확정.
```text
Request ≤ Need·Available 검사
  ↓ 임시 할당으로 상태 갱신
Work = Available, Finish = false
  ↓ Work로 완료 가능한 프로세스 선택
Work += Allocation, Finish = true 반복
  ↓ 모두 완료 가능하면 승인, 아니면 롤백
```
```text
P1 완료 → 자원 반환 → P3 완료
   ↑                         ↓
P2 완료 ← 자원 반환 ← 안전 순서
```
- Available보다 큰 요청은 대기. 자원 수량과 최대 요구량이 명확한 제한 자원에 적합.

## Ⅳ. 교착 처리 방식 비교
- 핵심 요약 : 은행가 알고리즘은 최대 요구량을 전제로 요청마다 안전성을 확인.
| 비교 축 | 예방 | 회피(은행가) | 탐지·회복 |
| --- | --- | --- | --- |
| 시점 | 필요조건 제거 | 승인 전 검사 | 발생 후 탐지 |
| 사전 정보 | 정책 제약 | 최대 요구량 | 할당·대기 관계 |
| 위험 | 이용률 저하 | 검사 비용 | 회복 손실 |

## Ⅴ. 한계와 방안
- 핵심 요약 : 최대 요구량의 불확실성과 검사 비용은 적용 범위 제한 및 공정성 정책으로 완화.
| 한계 | 원인·영향 | 대응 |
| --- | --- | --- |
| Max를 알기 어려움 | 요청이 동적으로 변함 | 상한이 명확한 자원에 적용 |
| 반복 검사 비용 | 요청 승인 지연 | 배치 검사·효율 자료구조 |
| 기아 | 특정 요청 반복 지연 | 공정성 큐·대기시간 상한 |

## Ⅵ. 적용 제언
- 핵심 요약 : 자원 관리자는 최대 요구량 계약이 명확한 자원 풀에서 안전성과 대기 공정성을 함께 평가.
- 동적 클라우드 자원은 예약·회수 정책과 결합해 알고리즘의 정적 수량 가정을 검증.

## Ⅶ. 결론
- 핵심 요약 : 은행가 알고리즘은 안전 상태를 유지할 수 있는 요청만 승인하는 교착 회피 기법.
- 최대 요구량을 사전에 알 수 있는 제한 자원 배분에서 예측 가능한 판단에 적합.
