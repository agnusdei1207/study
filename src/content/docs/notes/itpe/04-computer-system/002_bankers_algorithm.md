## 연관 키워드

- 은행가 알고리즘(Banker's Algorithm), 교착상태 회피(Deadlock Avoidance), 안전 상태(Safe State), 안전 순서열(Safe Sequence)
- 최대 요구량(Max), 할당량(Allocation), 필요량(Need), 가용량(Available)
- 시험 할당, 안전성 검사, 자원 할당 그래프, 교착상태 4대 조건

## Ⅰ. 은행가 알고리즘의 개요

- 핵심 요약 : **교착상태 회피** (Deadlock Avoidance) 방식의 하나로, 할당 후에도 **안전 상태**가 유지될 때만 자원 요청을 승인하는 알고리즘.
- 개념 : 다중 인스턴스 자원 환경에서 자원 요청을 가상으로 할당한 뒤, 모든 프로세스가 끝까지 실행될 수 있는 **안전 순서열** (Safe Sequence)이 존재할 때만 실제 할당하는 방법 (**은행가 알고리즘**, Banker's Algorithm).
- 배경 및 필요성 : 자원 할당 그래프는 자원 인스턴스가 하나인 경우에 적합하므로, 자원 종류마다 여러 인스턴스가 있는 환경에서는 프로세스별 **최대 요구량** (Max)과 현재 **가용량** (Available)을 수치로 비교하는 검증 방식이 필요함.
- 주요 목적 : 승인 이후에도 모든 프로세스의 완료 순서가 보장되도록 하여 교착상태를 사전에 차단하고, 자원 이용률을 유지하는 것.

## Ⅱ. 은행가 알고리즘의 특징 및 장점

- 핵심 요약 : 시험 할당과 안전성 검사를 결합해 다중 인스턴스 자원의 교착상태를 요청 시점에 회피하는 방식.

1. 다중 자원 벡터 검사 : 자원 종류별 Available, Max, Allocation, Need 벡터를 함께 계산 → 단일 인스턴스 기법으로 다루기 어려운 다중 인스턴스 환경까지 적용 범위 확장.
2. 안전 순서열 기반 승인 : 요청량이 가용량과 잔여 필요량 이내여도 완료 순서가 없으면 거절 → 불안전 상태 진입이 차단되어 교착상태 가능성 제거.
3. 동적 상태 판정 : 요청 시점의 실제 상태로 판정 → 자원 요청 순서를 미리 고정하지 않아도 되어 자원 활용의 유연성 확보.

## Ⅲ. 은행가 알고리즘의 구조 및 동작 원리

- 핵심 요약 : 요청 검증, 시험 할당, 안전성 검사, 승인 또는 원복의 네 단계로 진행되는 판정 흐름.

| 요소 | 차원 | 정의 및 역할 |
| --- | --- | --- |
| Available | 자원 종류 수 m | 유형별 즉시 할당 가능 수량 벡터 |
| Max | n × m | 프로세스별 완료 시점까지의 최대 요구량 행렬 |
| Allocation | n × m | 프로세스별 현재 할당량 행렬 |
| Need | n × m | Need = Max − Allocation, 잔여 필요량 행렬 |
| Work / Finish | m / n | 안전성 검사 중 임시 가용량과 완료 여부 |

1. 요청 검증 : Request_i ≤ Need_i (선언된 최대치 이내) 및 Request_i ≤ Available (가용량 이내)를 동시에 확인.
2. **시험 할당** (Trial Allocation) : Available, Allocation, Need를 임시 갱신하여 할당된 가상 상태를 만듦.
3. 안전성 검사 : 모든 프로세스가 완료될 수 있는 순서를 탐색하여 안전 여부 판정.
4. 승인 또는 원복 : 안전하면 실제 할당을 승인하고, 불안전하면 시험 할당을 되돌린 뒤 프로세스를 대기 상태로 전환.

```text
[ 자원 요청 처리 흐름 ]

프로세스 Pi의 자원 요청
   ↓
요청 검증 (Request ≤ Need, ≤ Available)
   ↓
시험 할당 (가상 상태 갱신)
   ↓
안전성 검사 (안전 순서열 탐색)
   ├─ 순서열 존재 → 실제 할당 승인
   ├─ 순서열 부재 → 원복 후 Pi 대기
```

```text
[ 안전성 검사 절차 ]

Work ← Available, Finish[i] ← false
   ↓
Need[i] ≤ Work 를 만족하는 Pi 탐색
   ↓
Work ← Work + Allocation[i]
Finish[i] ← true
   ↓
더 이상 탐색되지 않을 때까지 반복
   ↓
모든 Finish[i] = true → 안전 상태
```

## Ⅳ. 은행가 알고리즘의 비교

- 핵심 요약 : 예방은 교착상태 조건을 설계 단계에서 차단하고, 회피는 할당마다 안전성을 검사하며, 탐지·회복은 발생 후에 대응하는 차이.

| 구분 | 예방 (Prevention) | 회피 (Avoidance, 은행가 알고리즘) | 탐지·회복 (Detection/Recovery) |
| --- | --- | --- | --- |
| 판단 시점 | 자원 사용 규칙 설계 시 | 요청마다 할당 전 | 교착상태 발생 후 |
| 핵심 수단 | 교착상태 4대 조건 중 하나를 차단 | 안전 순서열 존재 여부 확인 | 대기 그래프 탐지, 선점 또는 프로세스 종료 |
| 장점 | 교착상태 원천 차단 | 안전한 범위에서 자원 활용도 확보 | 최대 요구량 사전 선언 불필요 |
| 한계 | 자원 활용도 저하, 기아 가능 | 최대 요구량 선언 필요, 검사 비용 발생 | 탐지 지연, 복구 비용 발생 |

- 은행가 알고리즘은 상호 배제, 점유 대기, 비선점, 순환 대기로 이루어진 교착상태 4대 조건을 설계 단계에서 깨는 예방 기법과 달리 할당 시점마다 상태를 추적하므로 자원 활용률이 높음. 대신 안전성 검사의 시간 복잡도가 O(m × n²)에 달해 연산 부담이 따름.

## Ⅴ. 은행가 알고리즘의 한계와 방안

- 핵심 요약 : 최대 요구량의 사전 선언, 검사 비용, 동적 구성 변화의 세 제약을 자원 상한, 할당 단위, 런타임 제어로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 최대 요구량 사전 선언의 어려움 | 실행 전 최대 사용량을 정확히 예측하기 어려워 과다 선언 시 활용도 저하 | 쿠버네티스의 자원 요청(requests)과 상한(limits)을 명시해 상한을 제어하고 실사용 기반으로 조정 | 요청 대비 실사용률 |
| 안전성 검사 비용 | 요청마다 O(m × n²) 검사를 수행해 프로세스가 많을 때 CPU(Central Processing Unit) 부담 증가 | 자원을 풀 단위 블록으로 할당하거나 타임아웃 기반 탐지·회복 방식으로 전환 | 요청당 검사 소요 시간 |
| 동적 구성 변화 | 프로세스 수나 자원 종류가 바뀌면 행렬 전체를 재구성해야 하여 클라우드 적용에 제약 | 오케스트레이터의 쿼터 제어와 자원 격리를 결합해 변화 폭을 상한 안으로 제한 | 쿼터 초과 발생 건수 |

## Ⅵ. 은행가 알고리즘의 적용 제언

- 핵심 요약 : 자원 상한을 명시할 수 있는 플랫폼에서는 승인 제어의 설계 사상으로 활용하고, 운영 환경에서는 관측과 복구 체계와 결합하는 방향.

- 자원 상한을 명시할 수 있는 플랫폼에서는 은행가 알고리즘의 보수적 승인 사상을 클러스터 수준의 승인 정책과 가용량 기반 스케줄링 설계에 반영하는 방향이 바람직함.
- 런타임 교착상태를 완전히 막기 어려운 분산 환경에서는 자원 고갈을 의도적으로 주입하는 카오스 엔지니어링(Chaos Engineering)으로 회로 차단기와 재시도 정책의 실효성을 검증하는 체계가 필요함.
- 자원 사용량 관측 지표를 운영 대시보드에 상시 노출하여 과다 선언을 줄이고, 실측치를 근거로 상한을 조정하는 거버넌스를 세우는 것이 실질적인 출발점이 됨.

## Ⅶ. 결론

- 핵심 요약 : 은행가 알고리즘은 다중 자원 할당의 안전성을 판정하는 교착상태 회피 기법으로, 안전 순서열의 존재를 승인 조건으로 삼는 체계.
- 안전 상태는 교착상태가 없다는 뜻보다 강한 조건으로, 모든 프로세스가 완료될 순서의 존재를 의미하므로 최대 요구량 선언과 검사 비용을 감안한 적용이 전제됨.
