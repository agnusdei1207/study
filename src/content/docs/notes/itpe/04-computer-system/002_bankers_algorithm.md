## 연관 키워드

- 은행가 알고리즘(Banker's Algorithm), 교착상태 회피(Deadlock Avoidance), 안전 상태(Safe State), 안전 순서열(Safe Sequence)
- 가용량(Available), 최대 요구량(Max), 할당량(Allocation), 필요량(Need), 시험 할당(Trial Allocation)
- 교착상태 4대 조건, 교착상태 예방(Prevention), 탐지·회복(Detection & Recovery), 승인 제어(Admission Control)

## Ⅰ. 은행가 알고리즘의 개요

- 핵심 요약 : 자원 요청을 가상으로 반영한 상태에서 안전성을 검증하고, 안전할 때만 할당을 승인하는 교착상태 회피 기법.
- 개념 : 다익스트라(Dijkstra)가 제안한 **은행가 알고리즘** (Banker's Algorithm)은 **교착상태 회피** (Deadlock Avoidance) 기법의 하나로, 프로세스의 자원 요청을 임시로 반영한 시스템 상태에서 모든 프로세스의 완료 가능성을 확인한 뒤 할당 여부를 결정하는 방식.
- 배경 및 필요성 : **교착상태 예방** (Prevention)은 상호 배제, 점유와 대기, 비선점, 순환 대기라는 교착상태 4대 조건 중 하나를 구조적으로 제거하는 방식이지만 자원 활용률이 크게 저하되므로, 활용률을 유지하면서 교착상태를 막는 정밀한 판정 수단이 필요함.
- 주요 목적 : 승인 이후에도 시스템이 **안전 상태** (Safe State)에 머무르게 하여 교착상태의 발생 가능성을 사전에 차단하고, 자원 활용률과의 균형을 확보하는 것.

## Ⅱ. 은행가 알고리즘의 특징 및 장점

- 핵심 요약 : 시험 할당과 안전성 검사의 결합이 교착상태의 원천 차단과 자원 활용의 균형이라는 장점으로 연결되는 판정 체계.

1. 시험 할당 기반 판정 : 요청을 실제 반영하기 전 가상 상태에서 안전성 검사를 먼저 수행하는 **시험 할당** (Trial Allocation) → 불안전 상태로의 전환이 차단되어 교착상태가 발생하지 않음.
2. 다중 인스턴스 지원 : 자원 종류별 수량을 벡터와 행렬로 관리 → 자원 유형마다 인스턴스가 여러 개인 실제 환경에도 적용 가능.
3. 상태 기반 동적 판정 : 요청 시점의 실제 상태로 승인 여부를 결정 → 자원 요청 순서를 미리 강제하지 않아 활용의 유연성 확보.
4. 수학적 완료 보장 : 모든 프로세스가 완료 가능한 실행 순서인 **안전 순서열** (Safe Sequence)의 존재를 승인 조건으로 삼음 → 불확실한 미래 요구에도 완료 가능성이 이론적으로 보장됨.

## Ⅲ. 은행가 알고리즘의 구조 (흐름)

- 핵심 요약 : 자원 상태를 벡터와 행렬로 관리하고, 요청 검증 → 시험 할당 → 안전성 검사 → 승인·대기의 단계로 판정하는 흐름.

1. **가용량** (Available) : 자원 종류별로 즉시 할당 가능한 수량의 벡터.
2. **최대 요구량** (Max) : 각 프로세스가 완료까지 요구할 최대 수량의 행렬.
3. **할당량** (Allocation) : 각 프로세스가 현재 점유 중인 수량의 행렬.
4. **필요량** (Need) : Need = Max − Allocation으로 정의되는 잔여 수량의 행렬.

```text
[ 자원 요청 판정 흐름 ]

프로세스 Pi의 자원 요청
   ↓
요청 검증 (요청 ≤ Need, 요청 ≤ Available)
   ↓
시험 할당 (가상 상태 갱신)
   ↓
안전성 검사 (안전 순서열 탐색)
   ↓
안전이면 승인, 아니면 원복 후 대기
```

```text
[ 안전성 검사 절차 ]

Work ← Available, Finish 전체 ← false
   ↓
Need ≤ Work 프로세스 탐색
   ↓
Work += Allocation, Finish[i] = true
   ↓
탐색 대상이 없을 때까지 반복
   ↓
전체 Finish = true → 안전 상태 판정
```

## Ⅳ. 은행가 알고리즘과 교착상태 처리 기법의 비교

- 핵심 요약 : 예방은 조건 제거, 회피는 할당 전 상태 검증, 탐지·회복은 발생 후 대응으로 판단 시점과 비용 구조가 갈림.

| 비교 축 | 교착상태 예방 | 교착상태 회피 (은행가 알고리즘) | 탐지·회복 (Detection & Recovery) |
| --- | --- | --- | --- |
| 판단 시점 | 시스템 설계 단계 | 자원 요청 시점마다 | 발생 후 주기적 검사 |
| 핵심 수단 | 4대 조건 중 하나의 구조적 제거 | 안전 순서열 존재 여부 판정 | 대기 그래프 탐색, 선점·프로세스 종료 |
| 최대 요구량 선언 | 불필요 | 사전 선언이 전제 | 불필요 |
| 장점 | 교착상태의 원천 차단 | 활용률과 안전성의 균형 | 선언 부담이 없고 구현 제약이 적음 |
| 한계 | 활용률 저하, 기아 가능성 | 검사 비용과 선언 부담 | 회복 비용과 서비스 지연 |

- 선택 기준 : 최대 요구량을 정확히 예측할 수 있는 배치·제어 시스템은 회피를, 일반 목적 운영체제처럼 예측이 어려운 환경은 탐지·회복을, 안전이 최우선인 시스템은 예방을 우선 검토하는 방식으로 판단.

## Ⅴ. 은행가 알고리즘의 한계와 방안

- 핵심 요약 : 사전 선언, 고정 구성, 검사 비용의 세 제약을 상한 관리, 재초기화 절차, 검사 범위 조정으로 완화.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 최대 요구량의 사전 선언 | 실행 전 최대 사용량 예측이 어렵고 과다 선언 시 활용률 저하 | 워크로드별 자원 상한을 명시하고 실측 기반으로 재조정 | 선언 대비 실사용 비율 |
| 고정된 프로세스·자원 구성 | 프로세스나 자원 종류가 바뀌면 행렬 전체의 재구성 필요 | 구성 변경 시 상태를 다시 선언하는 재초기화 절차 표준화 | 재초기화 발생 횟수 |
| 안전성 검사 비용 | 검사에 O(m × n²)의 연산이 요구되어 프로세스 증가 시 부담 | 자원을 블록 단위로 묶어 검사 횟수를 줄이고 핵심 구간에만 적용 | 요청당 검사 소요 시간 |

## Ⅵ. 은행가 알고리즘에 대한 기술사적 제언

- 핵심 요약 : 안전성 판정의 사상을 현대 자원 관리 체계의 승인 제어 설계 원리로 이식하는 방향.

- 운영체제·미들웨어 개발 조직은 **승인 제어** (Admission Control) 관점을 커넥션 풀, 자원 쿼터, 예약 기반 스케줄링 설계에 반영하여 과부하 상황의 자원 고갈을 사전에 차단하는 방안을 검토.
- 플랫폼 운영 조직은 자원 사용량의 상한 명세 문화를 정착시키고, 실측 데이터로 상한을 상시 보정하는 거버넌스를 구축하여 선언 정보의 신뢰도를 유지.
- 연구·표준화 기관은 다중 자원 안전성 판정 이론의 분산·동적 환경 확장과 경량 검사 기법의 검증을 지속하여 이론과 실무의 간극을 줄이는 노력이 필요함.

## Ⅶ. 결론

- 핵심 요약 : 은행가 알고리즘은 안전 순서열의 존재를 승인 조건으로 삼아 교착상태를 이론적으로 차단하는 회피 기법.
- 완벽한 사전 선언이 어려운 실무 환경에서도 그 판정 사상은 승인 제어와 자원 상한 관리의 설계 원리로 유효.
