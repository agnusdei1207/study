## 큰 그림과 30초 인출

```text
교착상태 처리
├─ 예방: 4대 필요조건 중 하나 제거 ── 자원 이용률 저하
├─ 회피: 안전상태 유지 ───────────── 은행가 알고리즘
├─ 탐지·복구: 허용 후 사이클 탐지 ── 종료·선점·롤백
└─ 무시: 발생 가능성과 처리비용 비교 ─ 타조 알고리즘

Requestᵢ ≤ Needᵢ, Requestᵢ ≤ Available
             │
             ▼
        [가상 할당]
             │
     안전 순서열 존재?
        ├─ Yes → 승인
        └─ No  → 롤백·대기
```

- 본질: **요청을 먼저 가상 반영한 뒤 모든 프로세스가 끝나는 안전 순서열을 찾을 수 있을 때만 실제 할당**
- 자료구조: `Available`, `Max`, `Allocation`, `Need = Max - Allocation`
- 구분: **불안전 상태는 교착상태가 아니지만, 교착상태로 진행할 가능성을 배제할 수 없는 상태**

## 예상문제

> 교착상태 회피를 위한 은행가 알고리즘의 개념과 자료구조, 자원 요청 및 안전성 판정 절차를 설명하고 적용 한계를 제시하시오. (25점)

## Ⅰ. 안전 순서열로 교착상태를 회피하는 은행가 알고리즘 개요

- 정의: **은행가 알고리즘**은 각 프로세스의 최대 자원 요구량을 사전에 알고 있다는 전제에서, 자원 요청을 가상 할당한 후 **안전상태**가 유지되는 요청만 승인하는 교착상태 회피 기법
- 목적: 필요조건을 강제로 제거하는 예방보다 자원 이용률을 높이면서, 실제 교착상태에 들어가기 전에 위험한 할당을 차단
- 전제: 프로세스 수와 자원 종류가 고정되고, 각 프로세스가 선언한 최대 요구량과 할당받은 자원을 유한 시간 내 반환

| 구분 | 의미 | 판정 결과 |
|---|---|---|
| **안전상태** | 모든 프로세스가 완료 가능한 안전 순서열 존재 | 자원 요청 승인 가능 |
| **불안전상태** | 안전 순서열을 찾지 못함 | 교착 위험 때문에 요청 보류 |
| **교착상태** | 프로세스가 서로 보유 자원을 기다리며 진행 불가 | 종료·선점·롤백 등 복구 필요 |

## Ⅱ. 사전 최대량과 보수적 승인에 기반한 특징

| 특징 | 메커니즘 | 효과·제약 |
|---|---|---|
| **동적 회피** | 요청 시점마다 가상 할당 후 안전성 검사 | 실행 중 위험 할당 차단 |
| **다중 인스턴스 지원** | 벡터·행렬로 자원 종류별 수량 계산 | 자원 인스턴스가 여러 개인 환경 처리 |
| **안전 순서열 보장** | `Needᵢ ≤ Work` 프로세스를 반복 탐색 | 모든 프로세스 완료 가능성 확인 |
| **보수적 자원 운용** | 불안전 상태도 승인하지 않음 | 교착 회피 대신 대기·이용률 저하 가능 |
| **사전 정보 의존** | `Max`를 실행 전에 선언 | 동적 워크로드에는 적용 곤란 |

## Ⅲ. 가용량·최대량·할당량·잔여량의 자료구조

```text
                    자원 종류 m개
                 R1      R2      ... Rm
Available[m]   [가용]  [가용]        [가용]

프로세스 n개       Max[n,m]                 Allocation[n,m]
P1             [최대 요구량]              [현재 할당량]
P2             [최대 요구량]              [현재 할당량]
...
Pn

                    Need[n,m] = Max[n,m] - Allocation[n,m]
```

| 자료구조 | 크기 | 책임 |
|---|---:|---|
| **Available** | `m` | 즉시 할당 가능한 자원별 잔여 수량 |
| **Max** | `n × m` | 프로세스별 최대 자원 요구량 |
| **Allocation** | `n × m` | 현재 프로세스별 할당 수량 |
| **Need** | `n × m` | 완료까지 추가로 필요한 수량 |
| **Finish** | `n` | 안전성 검사 중 완료 가능 여부 |

## Ⅳ. 요청 검증에서 승인·롤백까지의 동작 절차

```text
[Requestᵢ 발생]
       │
       ├─ Requestᵢ > Needᵢ ──────▶ 오류: 최대 선언량 초과
       │
       ├─ Requestᵢ > Available ───▶ 대기: 현재 자원 부족
       │
       ▼
[가상 할당]
Available  -= Requestᵢ
Allocationᵢ += Requestᵢ
Needᵢ      -= Requestᵢ
       │
       ▼
[안전성 검사: Work=Available, Finish=false]
       │ Needⱼ ≤ Work인 Pⱼ 탐색
       ├─ 발견 → Work += Allocationⱼ, Finishⱼ=true, 반복
       └─ 미발견
              │
       모든 Finish=true?
       ├─ Yes → 안전 순서열 확정, 실제 승인
       └─ No  → 가상 할당 원복, 요청 프로세스 대기
```

- 판정 핵심: 비교와 덧셈은 자원별 원소 단위로 수행하며, 하나라도 부족하면 해당 프로세스는 현재 완료 가능 후보가 아님
- 안전 순서열은 유일할 필요가 없고, **한 개 이상 존재**하면 안전상태로 판정

## Ⅴ. 단일·다중 자원 환경의 회피 기법 비교

| 구분 | 자원 할당 그래프 기반 회피 | 은행가 알고리즘 | 교착상태 탐지 |
|---|---|---|---|
| 자원 인스턴스 | 종류별 단일 인스턴스 중심 | 종류별 다중 인스턴스 | 단일·다중 가능 |
| 핵심 정보 | 요청·할당 간선 | `Available·Max·Allocation·Need` | 현재 요청·할당 상태 |
| 판단 시점 | 할당 전 | 할당 전 가상 시뮬레이션 | 할당 후 주기적 탐지 |
| 판단 기준 | 사이클이 생기지 않는 상태 | 안전 순서열 존재 | 대기 그래프·행렬의 교착 집합 |
| 대가 | 그래프 관리 | 최대량 선언·반복 계산 | 복구를 위한 종료·롤백 비용 |

## Ⅵ. 동적 시스템 적용의 한계와 보완방안

| 문제 | 원인 | 대책 | 기대 효과 |
|---|---|---|---|
| **Max 산정 불가** | 입력·트래픽에 따라 실행 중 요구량 변동 | 워크로드별 **Quota·Limit**와 정적 자원 풀 설정 | 상한을 명시해 과다 할당 방지 |
| **판정 오버헤드** | 요청마다 프로세스·자원 행렬 반복 검사 | 적용 대상을 고신뢰·제한 자원 영역으로 한정 | 비용 대비 회피 효과 확보 |
| **기아 가능성** | 불안전 판정을 반복 받은 요청의 장기 대기 | 대기 시간 기반 우선순위 상승·예약량 부여 | 공정성과 완료 가능성 향상 |
| **잘못된 최대량** | 과대 선언은 이용률 저하, 과소 선언은 요청 오류 | 실측 사용량 모니터링과 상한 재조정 | 안전성과 자원 효율 균형 |

- 적용 판단: 범용 OS 전체에 일률 적용하기보다, 최대량을 통제할 수 있는 임베디드·배치·테넌트 자원 풀에서 선택 적용
- 검증 지표: 요청 대기시간, 자원 이용률, 불안전 판정률, 최대량 초과 횟수를 함께 관찰

## Ⅶ. 안전성 보장과 자원 활용률을 함께 보는 결론

- 은행가 알고리즘의 채점 핵심은 `Need = Max - Allocation` 계산 자체가 아니라, **가상 할당 → 안전 순서열 검증 → 승인 또는 롤백**의 통제 구조
- 실무에서는 최대 요구량을 신뢰할 수 있는 경계부터 정하고, 보수적 승인으로 인한 대기와 이용률 저하를 측정해 적용 범위를 조정해야 함

## 1교시 10점 답안 발췌

### 1. 정의

- 프로세스별 최대 요구량을 기준으로 요청을 가상 할당하고, 모든 프로세스가 완료 가능한 **안전 순서열**이 존재할 때만 승인하는 교착상태 회피 알고리즘

### 2. 자료구조와 판정

```text
Need = Max - Allocation
Request ≤ Need, Request ≤ Available
              ↓
          가상 할당
              ↓
     Needᵢ ≤ Work 반복 검사
        ├─ 안전 순서열 존재 → 승인
        └─ 미존재          → 롤백·대기
```

| 자료구조 | 의미 |
|---|---|
| Available | 현재 가용 자원 |
| Max | 프로세스별 최대 요구량 |
| Allocation | 현재 할당량 |
| Need | 추가 필요량 |

### 3. 한계

- 최대 요구량 사전 선언과 반복 안전성 검사 때문에 요구량이 계속 변하는 범용 시스템에는 적용이 제한됨
