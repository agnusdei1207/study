## 30초 인출

- 본질: **DAS (Direct-Attached Storage)는** 네트워크 스토리지 서비스 계층을 거치지 않고 서버에 직접 연결해 쓰는 저장장치 구성
- 메커니즘: 서버 I/O 요청 → 로컬 또는 직접 연결된 장치 → 서버 운영체제·파일시스템이 저장을 관리
- 통찰: 한계: 저장장치가 서버에 묶여 장애 시 다른 호스트의 접근이 어려움 → 방안: 데이터 중요도별 백업·복제와 대체 호스트 복구 시간을 시험

<details>
<summary>핵심 용어</summary>

- **DAS (Direct-Attached Storage)** : 서버에 직접 연결해 해당 서버가 주로 사용하는 저장장치 구성
- **HBA (Host Bus Adapter)** : 서버와 저장장치 인터페이스 사이의 연결을 제공하는 어댑터
- **SATA (Serial ATA)** : 저장장치 연결에 쓰이는 직렬 인터페이스 규격
- **SAS (Serial Attached SCSI)** : 서버·엔터프라이즈 저장장치 연결에 쓰이는 직렬 SCSI 인터페이스
- **NVMe (Non-Volatile Memory Express)** : PCI Express 기반 비휘발성 저장장치 접근 프로토콜 계열
</details>

## 2~4교시 25점 답안

## Ⅰ. DAS의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **DAS (Direct-Attached Storage)는** 서버에 직접 연결되어 서버 운영체제가 접근·관리하는 저장장치 구성 |
| 목적 | 서버에 필요한 저장 용량과 I/O를 별도 스토리지 네트워크 계층 없이 제공하는 것 |

## Ⅱ. 서버 직접 연결의 특징

| 특징 | 의미 |
|---|---|
| 호스트 중심 | 운영체제의 드라이버·블록 계층·파일시스템이 장치를 관리 |
| 직접 I/O | 별도 스토리지 네트워크 서비스를 거치지 않는 단순한 접근 경로 |
| 장애 결합 | 서버가 멈추면 장치가 정상이어도 응용의 데이터 접근이 중단될 수 있음 |

## Ⅲ. 호스트와 직접 연결 장치의 I/O 체계

```text
응용 → 파일시스템 → 서버 OS·블록 계층 → HBA/컨트롤러 → SATA·SAS·NVMe 장치
 ↑                                                                    │
 └────────────── I/O 완료·데이터 반환 ←────────────────────────────────┘
```

서버의 장치 드라이버가 연결 인터페이스를 통해 블록을 읽고 쓰며, 로컬 RAID를 쓰더라도 별도 장애영역의 백업·복제는 따로 설계한다.

## Ⅳ. DAS·NAS·SAN 연결과 적용 비교

| 구분 | DAS | NAS | SAN |
|---|---|---|---|
| 연결·접근 | 서버 직접 연결·블록 | 네트워크 파일 서비스 | 스토리지 패브릭·블록 |
| 공유 | 기본적으로 서버 중심 | 다중 사용자 파일 공유 | 다중 호스트 접근 시 파일시스템 조정 필요 |
| 관리 지점 | 서버와 장치 | NAS 파일 서비스 | 패브릭·어레이·호스트 |
| 적용 판단 | 단일 서버 로컬 I/O, 독립 업무 | 파일 공유·중앙 관리 | 여러 서버의 블록 저장 요구 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 특정 서버에 묶여 서버 장애 시 다른 호스트의 즉시 접근이 어려움 | 중요도별 복제·백업과 대체 호스트 연결·복구 시간을 시험 |
| 서버별 용량·보호 정책이 달라지고 증설 시 장치별 작업이 필요 | 공통 모니터링·백업 기준과 중앙 인벤토리로 용량·장애 관리 |
| 연결 비용만 보고 선택하면 공유·확장·복구 요구를 뒤늦게 발견 | 데이터 중요도·공유 범위·복구 목표·증설 주기로 NAS·SAN과 총 운영비 비교 |

## Ⅵ. 제언 — 서버 장애 시 데이터 접근부터 확인

단일 서버의 I/O 경로 이점보다 복구 요구가 우선인 업무는 대체 호스트에서 데이터가 열리는지 시험하고, 그 결과로 DAS 유지 또는 공유 스토리지 전환을 결정한다.
