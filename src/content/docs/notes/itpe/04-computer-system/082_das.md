## 답안 골격
```text
[DAS] ◀━━ 머리: Ⅶ 내 의견 (초고속 NVMe SSD 직결을 통한 극한 성능 확보와 소프트웨어 분산 복제를 결합한 최신 DAS 아키텍처 재조명)
 ┃
 ┣━ Ⅰ 개요 ───── 네트워크 스위치 없이 전용 케이블(SATA/SAS/PCIe)로 서버 본체에 직접 연결되는 전통적 저장 장치
 ┣━ Ⅱ 특징 ───── 전용 채널 직결 · 네트워크 오버헤드 0 · 단순한 구성 및 저비용 · 서버 간 공유 불가(사일로화)
 ┣━ Ⅲ 구조 ───── 호스트 버스 어댑터(HBA) + 전용 인터페이스 케이블(SAS/PCIe/NVMe) + 디스크 인클로저(JBOD/RAID)
 ┣━ Ⅳ 흐름 ───── ① 애플리케이션 I/O 요청 → ② 로컬 블록 드라이버 처리 → ③ HBA/PCIe 버스 전송 → ④ 로컬 디스크 헤드 기록
 ┣━ Ⅴ 비교 ───── DAS vs NAS vs SAN (스토리지 3대 접속 방식 비교)
 ┗━ Ⅵ 실무 ───── 용량 확장(Scalability) 한계 / 서버 다운 시 스토리지 접근 불가(SPOF) / 비효율적 디스크 고립
```
- 필수 키워드: DAS · 직접 연결 · HBA · SAS/SATA/NVMe · 네트워크 지연 제로 · 공유 불가 · Hadoop/Cassandra
- 기출: 122회 1교시 7번 `DAS, NAS, SAN 비교` 단답형 출제

## 한 줄 본질
- 네트워크를 거치면 패킷 변환과 스위치 전송 지연이 발생함 → 서버 메인보드의 로컬 버스(PCIe/SAS)에 디스크를 전용 케이블로 1:1 직결하여 지연시간을 마이크로초 단위로 극소화 → 최고의 단일 I/O 성능 및 저비용 구축 / 다른 서버와의 데이터 공유 불가 및 물리적 확장성 한계

## 핵심 그림
```text
[ DAS 직접 연결 스토리지 구조 및 서버 간 사일로화 ]

[ 서버 A (Web Server) ]                 [ 서버 B (DB Server) ]
         │                                       │
         v (내부 PCIe 버스 / SAS HBA)            v (내부 PCIe 버스 / SAS HBA)
+─────────────────────────+             +─────────────────────────+
| DAS 스토리지 A          |             | DAS 스토리지 B          |
| (전용 디스크 인클로저)  |             | (전용 디스크 인클로저)  |
| - 여유 공간: 90% (낭비!) |             | - 여유 공간: 0% (부족!) |
+─────────────────────────+             +─────────────────────────+
(서버 B는 용량이 모자라지만, 서버 A의 남는 DAS 디스크를 가져다 쓸 수 없음: 사일로 현상)
```

## 핵심 용어
- HBA(Host Bus Adapter): 서버의 메인보드 버스(PCIe)와 외장 스토리지 케이블(SAS/FC) 사이에서 물리적 신호와 통신 프로토콜을 변환해 주는 전용 확장 카드
- JBOD(Just a Bunch of Disks): RAID 컨트롤러의 복잡한 패리티나 미러링 없이 여러 디스크를 물리적인 개별 드라이브들의 단순 묶음으로 사용하는 구성
- NVMe-oF(NVMe over Fabrics): DAS의 최고 장점인 초고속 로컬 NVMe 프로토콜을 이더넷이나 인피니밴드 패브릭 망으로 확장하여 네트워크 스토리지화하는 현대 기술

## 핵심 통찰
- DAS는 '과거의 유물'이 아니라 빅데이터와 AI에서 '부활'함 → 과거에는 데이터 공유가 안 되어 SAN/NAS에 밀렸으나, 하둡(HDFS), 카산드라, 카프카 같은 현대 분산 시스템은 소프트웨어가 노드 간 복제를 알아서 하므로, 비싼 SAN 대신 초고속 로컬 NVMe DAS를 선호함
- 네트워크 오버헤드가 제로(Zero)임 → TCP/IP 스택이나 파이버 채널 스위치를 거치지 않고 CPU와 PCIe 레인으로 직결되므로 레이턴시가 10마이크로초 미만으로 극도로 낮음
- 케이블 길이의 한계가 곧 시스템의 한계임 → 외장 SAS 케이블은 2~5미터 이상 멀어질 수 없어 같은 전산실 랙 내부에서만 연결이 가능하므로 원격지 이원화가 불가능함

## 이웃 토픽과 구분
- DAS vs SAN: DAS = 서버 전용 버스에 1:1 직결(공유 불가, 저비용 초고속, 단일 장애점) / SAN = 광 스위치 패브릭 네트워크로 수십 대 서버가 블록 스토리지를 공유(고가, 유연한 확장, 고가용성)

## 문제·원인·대책
- 사례: 122회 기출 및 단일 서버 장애로 서버에 직결된 DAS 데이터베이스 전체가 서비스 중단된 장애
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 호스트 서버 메인보드 고장 시 직결된 DAS 스토리지 접근 불가(SPOF) | 서버와 스토리지가 1:1로 결합되어 있어 페일오버 불가 | 분산 파일 시스템(HDFS/Ceph) 적용 및 데이터 3중화 복제 | 단일 서버/디스크 사망 시에도 타 노드에서 무중단 서비스 |
| 서버 간 스토리지 용량 불균형으로 디스크 추가 구매 비용 증가 | 서버 A의 빈 DAS 공간을 서버 B에 할당할 수 없는 물리적 사일로화 | NVMe-oF 기반의 스토리지 디스애그리게이션(Disaggregation) 도입 | 로컬 DAS급 지연시간 유지하며 스토리지 풀 공유 실현 |

## 이렇게 출제된다
- 제122회 1교시 7번: "DAS(Direct Attached Storage), NAS(Network Attached Storage), SAN(Storage Area Network)" → 요구 포인트: Ⅰ DAS의 개념 및 물리 연결 특성 + Ⅲ SAS/PCIe 직결 아키텍처 도식 + Ⅴ DAS vs NAS vs SAN 3대 스토리지 종합 비교표

## 내 의견
