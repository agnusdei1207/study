## 연관 키워드

- DAS(Direct-Attached Storage), 내장형 DAS, 외장형 DAS, JBOD, HBA(Host Bus Adapter)
- SATA, SAS, NVMe, PCIe, 듀얼 포트
- 자원 고립, SPOF(Single Point of Failure), SDS(Software-Defined Storage), NVMe-oF, SAN(Storage Area Network)

## Ⅰ. DAS(Direct-Attached Storage)의 개요

- 핵심 요약 : **DAS** (Direct-Attached Storage)는 네트워크 스위치 없이 서버에 전용 인터페이스로 직접 연결되어, 짧은 경로로 낮은 지연의 블록 입출력을 제공하는 방식.
- 개념 : SAN(Storage Area Network) 같은 스토리지 전송 네트워크를 거치지 않고, SATA(Serial Advanced Technology Attachment), SAS(Serial Attached SCSI), PCIe(Peripheral Component Interconnect Express) 등 전용 케이블로 서버에 1:1로 연결되는 블록 스토리지 구성.
- 배경 및 필요성 : 스토리지 네트워크 인프라의 도입 비용과 구성 복잡도가 부담스러운 환경에서, 단일 서버가 네트워크 오버헤드 없이 높은 입출력 성능을 얻어야 하는 수요가 존재함.
- 주요 목적 : 네트워크 프로토콜 부담이 없는 낮은 지연의 I/O 확보, 구성의 단순화, 서버 단위의 독립적인 저장 공간 확보.

## Ⅱ. DAS(Direct-Attached Storage)의 특징 및 장점

- 핵심 요약 : 내장형과 외장형으로 나뉘는 연결 형태가 전용 경로 기반의 성능과 구성 단순성으로 이어지는 방식.

1. **내장형 DAS** (Internal DAS) : 서버 샤시의 드라이브 베이에 디스크를 직접 장착하여 CPU와 메모리에 가장 짧은 경로로 접근 → 지연 최소화와 설치 단순화.
2. **외장형 DAS** (External DAS) : 외장 HBA와 케이블로 JBOD(Just a Bunch Of Disks) 인클로저를 연결 → 서버를 교체하지 않고 용량을 확장.
3. 전용 인터페이스 직결 : 스위치 홉 없이 호스트 버스로 블록 명령을 전달 → 네트워크 패킷 처리 부담 제거와 예측 가능한 지연.

## Ⅲ. DAS(Direct-Attached Storage)의 구조 및 동작 메커니즘

- 핵심 요약 : 서버 HBA 또는 RAID 컨트롤러에서 내장 베이 또는 외장 인클로저의 디스크로 이어지는 단일 경로 구조.
- **HBA** (Host Bus Adapter) : 서버에 장착되어 호스트 버스 프로토콜과 디스크 인터페이스를 중개하는 어댑터 카드.
- **RAID** (Redundant Array of Independent Disks) 컨트롤러 : 여러 디스크를 묶어 성능이나 중복성을 제공하는 컨트롤러로, 내장형 DAS에서 자주 쓰임.

```text
[ DAS 데이터 경로 ]

애플리케이션
      ↓
운영체제 I/O 스택 · 파일시스템
      ↓
HBA 또는 RAID 컨트롤러 (PCIe 슬롯)
      ↓
내장 드라이브 베이 또는 외장 케이블
```

```text
[ 연결 형태 구분 ]

서버 HBA (PCIe)
   ├─ 내장 : 서버 샤시 드라이브 베이
   └─ 외장 : 외장 케이블 → JBOD 인클로저
```

## Ⅳ. DAS(Direct-Attached Storage)의 비교

- 핵심 요약 : SATA·SAS·NVMe는 프로토콜, 속도, 큐 구조, 포트 구성, 적용처에서 용도별로 갈리는 세 가지 DAS 인터페이스.

| 비교 항목 | SATA (Serial ATA) | SAS (Serial Attached SCSI) | NVMe (Non-Volatile Memory Express) |
| :--- | :--- | :--- | :--- |
| 프로토콜 기반 | ATA 명령 세트 | SCSI 명령 세트 | PCIe 기반 비휘발성 메모리 전용 프로토콜 |
| 대표 인터페이스 속도 | 6 Gbps (약 550 MB/s) | 12 Gbps (SAS-3) 이상 | PCIe x4 기준 약 8 GB/s (Gen 4), 약 16 GB/s (Gen 5) |
| 큐 구조 | 단일 큐, 큐 깊이 32 (NCQ 기준) | 단일/다중 큐, 디바이스당 큐 깊이 254 | 최대 64K개 큐, 큐당 최대 64K 명령 |
| 포트 구성 | 단일 포트 | 듀얼 포트 지원으로 HA 구성 가능 | PCIe 연결, 멀티 큐로 병렬 처리 |
| 주요 적용처 | 보급형 PC, 대용량 백업용 HDD | 엔터프라이즈 미션 크리티컬 서버 | 고성능 AI·빅데이터, 인메모리 DB |

## Ⅴ. DAS(Direct-Attached Storage)의 한계와 방안

- 핵심 요약 : 자원 고립, 서버 장애 취약성, 연결 거리 제한을 SDS 풀링, 듀얼 포트 HA, NVMe-oF로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| **자원 고립** (Storage Silo) | 디스크가 특정 서버에 고착되어 다른 서버의 여유 용량을 쓸 수 없음 → 전체 용량 활용률 저하 | 서버 풀 전체를 하나의 가상 볼륨으로 묶는 SDS(Software-Defined Storage), 또는 HDFS·Ceph 같은 분산 파일시스템 구성 | 서버별 용량 활용률 |
| **SPOF** (Single Point of Failure) 노출 | 호스트 서버의 메인보드나 CPU가 고장 나면 디스크가 정상이어도 데이터 접근 불가 → 서비스 중단 | 듀얼 포트 SAS 드라이브를 두 서버의 HBA에 교차 연결하는 HA(High Availability) 클러스터 구성 | 페일오버 소요 시간 |
| 케이블 거리 제한 | SAS·PCIe 케이블의 신호 감쇠로 연결 거리가 수 미터 이내로 제한 → 데이터센터 단위 확장 불가 | PCIe 명령을 이더넷·InfiniBand 패브릭으로 확장하는 NVMe-oF(NVMe over Fabrics) 도입 | 원격 접근 지연 |

## Ⅵ. DAS(Direct-Attached Storage)에 대한 기술사적 제언

- 핵심 요약 : 로컬 NVMe의 성능을 살리되, 풀링과 복제로 DAS의 고립과 장애 취약성을 보완하는 하이브리드 설계.

1. 지연에 민감한 캐시와 임시 데이터는 로컬 NVMe DAS에 두고, 영속 데이터는 소프트웨어 복제로 여러 노드에 나누어 보관하는 계층 구조를 검토.
2. 서버 간 용량 편차를 줄이기 위해 인프라 운영 조직이 노드별 로컬 디스크를 공유 풀로 묶는 SDS 계층을 표준 아키텍처로 채택.
3. CXL(Compute Express Link) 등 저지연 연결 기술의 표준 동향을 주기적으로 점검하여, 저장 계층과 메모리 계층의 경계 변화에 대비하는 체계 마련.

## Ⅶ. 결론

- 핵심 요약 : DAS는 전용 인터페이스 직접 연결로 낮은 지연을 얻는 대신 자원 고립과 SPOF 리스크를 함께 떠안는 구성.
- 시사점 : 단일 서버의 성능과 단순성이 중요한 구간에서 유효하며, 확장성과 가용성이 요구되는 구간은 SDS와 HA 구성으로 보완해야 함.
