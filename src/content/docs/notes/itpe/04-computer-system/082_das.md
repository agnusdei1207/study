## Ⅰ. DAS(Direct-Attached Storage)의 개요

- 개념 : 별도의 전용 스토리지 전송 네트워크 스위치(SAN 스위치나 IP 라우터)를 거치지 않고, **전용 인터페이스 케이블(SATA, SAS, PCIe/NVMe)** 을 통해 개별 서버나 워크스테이션에 직접 일대일(1:1)로 연결되는 전용 블록 스토리지 아키텍처.
- 배경 및 필요성 : 스토리지 네트워크 인프라 도입 비용이 부담스럽거나, 네트워크 지연 없이 최단 버스 대역폭을 통해 단일 서버의 극단적인 입출력 속도와 단순한 구성을 달성해야 하는 환경에서 사용됨.
- 핵심 목적 : 네트워크 프로토콜 오버헤드 없는 **초저지연 I/O** 보장, 시스템 구성의 단순화 및 경제적인 전용 데이터 저장소 구축.

## Ⅱ. DAS의 핵심 연결 아키텍처 및 버스 통신 메커니즘

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ DAS (Direct-Attached Storage) 내부 및 외장형 연결 아키텍처 ]        │
│                                                                        │
│   [ 서버 호스트 (Server Host System) ]                                 │
│    - 운영체제 I/O 스택 및 파일시스템 (XFS / ext4 / NTFS)               │
│    - HBA (Host Bus Adapter) / RAID 컨트롤러 카드                       │
│    - PCIe 슬롯 (x4 / x8 / x16)                                         │
│          │                                          │                  │
│          │ Internal Bus (내장형 DAS)                │ External Cable   │
│          ▼                                          ▼ (외장형 JBOD)    │
│   ┌─────────────────────────────┐        ┌─────────────────────────┐   │
│   │ 서버 샤시 내부 드라이브 베이│        │ 외장 스토리지 인클로저  │   │
│   │ (SATA / SAS / NVMe SSDs)    │        │ (SAS JBOD / Expansion) │   │
│   └─────────────────────────────┘        └─────────────────────────┘   │
└────────────────────────────────────────────────────────────────────────┘
```

- **내장형 DAS(Internal DAS)** : 서버 메인보드의 온보드 컨트롤러나 PCIe 슬롯에 장착된 드라이브 베이에 디스크를 직접 탑재하여 CPU-메모리와 최단 거리 통신.
- **외장형 DAS(External DAS)** : 외장 SAS HBA 및 mini-SAS HD 케이블을 통해 서버 외부에 위치한 디스크 드라이브 인클로저(JBOD, Just a Bunch Of Disks)를 직접 연결하여 용량 확장.

## Ⅲ. 주요 스토리지 인터페이스 기술(SATA vs SAS vs NVMe) 비교 분석

| 비교 항목 | SATA (Serial ATA) | SAS (Serial Attached SCSI) | NVMe (Non-Volatile Memory Express) |
| :--- | :--- | :--- | :--- |
| **프로토콜 표준** | ATA/ATAPI 패킷 | SCSI 명령 세트 기반 | PCIe 기반 NVM 전용 프로토콜 |
| **최대 인터페이스 속도**| 6 Gbps (약 550 MB/s) | 12 Gbps / 24 Gbps | Gen 4: 8 GB/s, Gen 5: 16 GB/s (x4) |
| **큐(Queue) 구조** | 단일 큐, 큐 깊이(QD) 32 | 단일/다중 큐, 큐 깊이 254 | 최대 64,000개 큐, 큐당 64,000 명령 |
| **신호 전송 방식** | 반이중(Half-Duplex) | 전이중(Full-Duplex), 듀얼 포트 | 전이중(Full-Duplex), 멀티채널 병렬 |
| **주요 적용처** | 보급형 PC, 대용량 백업용 SATA HDD| 엔터프라이즈 미션크리티컬 서버 | 고성능 AI/빅데이터, 인메모리 DB |

## Ⅳ. DAS의 주요 한계점 및 해결 방안

- 스토리지 **자원 고립(Storage Silo)** 과 낮은 공간 활용률 :
  - 한계점 : 스토리지가 특정 단일 서버에 물리적으로 고착되어 있어, 특정 서버의 디스크가 가득 차도 다른 서버의 빈 디스크를 공유 불가.
  - 해결 방안 : 서버 풀 간의 가상 공유 볼륨을 형성하는 소프트웨어 정의 스토리지(SDS) 또는 하둡 HDFS/Ceph 분산 파일시스템 구성.
- 서버 장애 시 스토리지 접근 **불가(SPOF 리스크)** :
  - 한계점 : 스토리지 자체는 정상이더라도 연결된 호스트 서버의 메인보드나 CPU 고장 시 저장된 데이터에 즉시 접근 불가능.
  - 해결 방안 : 듀얼 포트 SAS 드라이브를 활용하여 2대의 서버 HBA를 동일 외장 JBOD에 교차 연결하는 고가용성(HA Cluster) 구성.
- 물리적 케이블 거리 제한 및 확장성 한계 :
  - 한계점 : SAS 및 PCIe 케이블의 물리적 신호 감쇠로 인해 연결 거리가 수 미터(1~5m) 이내로 제한되어 데이터센터 단위 확장 불가.
  - 해결 방안 : 이더넷/인피니밴드 네트워크 패브릭을 통해 PCIe 버스를 네트워크로 확장하는 NVMe-oF(NVMe over Fabrics) 도입.

## Ⅴ. 현대 인프라 아키텍처 관점에서의 기술사적 제언

- 하이퍼스케일러의 초고속 DAS 부활과 **디스애그리게이션(Disaggregation)** : 클라우드 빅데이터(빅쿼리, 카프카) 및 AI 학습 환경에서는 네트워크 스토리지의 레이턴시 한계를 극복하기 위해 로컬 초고속 NVMe DAS 인스턴스를 적극 활용하되, 장애에 대비한 소프트웨어적 복제본(Replication Factor 3)을 상위 계층에서 강제해야 함.
- **CXL(Compute Express Link)** 기반 풀드 스토리지(Pooled Storage) 연계 : 서버 섀시 내부에 갇힌 DAS의 한계를 넘어서기 위해 CXL 3.0 스위치를 통해 여러 호스트가 PCIe 속도로 저지연 공유할 수 있는 풀드 디스애그리게이티드 스토리지 아키텍처로의 전환을 준비할 것을 제언함.
