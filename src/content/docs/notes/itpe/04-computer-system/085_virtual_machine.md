## 연관 키워드

- 가상머신(Virtual Machine, VM), 하이퍼바이저(Hypervisor), 가상 하드웨어, 게스트 OS(Guest OS)
- vCPU, vNIC(Virtual Network Interface Card), 가상 디스크, VT-x, EPT(Extended Page Tables)
- 라이프사이클, 템플릿, 스냅샷(Snapshot), 라이브 마이그레이션(Live Migration)
- 자원 중복, VM 스프롤(VM Sprawl), 컨테이너(Container)

## Ⅰ. 가상머신의 개요

- 핵심 요약 : **가상머신** (Virtual Machine, VM)은 물리 하드웨어를 소프트웨어로 추상화하여 독립된 운영체제 실행 환경을 제공하는 컴퓨팅 단위.
- 개념 : **하이퍼바이저** (Hypervisor)가 물리 서버의 CPU·메모리·스토리지·네트워크를 추상화하여, 각자 **게스트 OS** (Guest OS)를 가진 독립 실행 환경을 만드는 방식.
- 배경 및 필요성 : 서버 한 대에 단일 업무만 배치하는 전통 방식의 낮은 자원 이용률, 증설 지연, 상면·전력 낭비의 해소 필요.
- 주요 목적 : 서버 통합에 따른 비용 절감, OS 수준의 강한 격리, 신속한 프로비저닝과 무중단 자원 이동.

## Ⅱ. 가상머신의 특징 및 장점

- 핵심 요약 : 가상 하드웨어 추상화와 하드웨어 지원 가상화, 라이프사이클 관리 기능이 유연성과 가용성으로 이어지는 구조.

1. 가상 하드웨어 추상화 : vCPU, 가상 메모리, vNIC(Virtual Network Interface Card), 가상 디스크를 소프트웨어로 정의 → 물리 하드웨어와 무관한 이식 가능한 실행 환경 효과.
2. 하드웨어 지원 가상화 : Intel VT-x(Intel Virtualization Technology)의 루트·비루트 모드 분리와 EPT(Extended Page Tables)의 이중 주소 변환 → 특권 명령 처리 부담 감소 효과.
3. 라이프사이클 관리 : 템플릿 기반 복제와 스냅샷(Snapshot)으로 생성·복원·폐기의 단계 관리 → 신속 프로비저닝과 빠른 롤백 효과.
4. **라이브 마이그레이션** (Live Migration) : 실행 중인 VM의 메모리와 장치 상태를 다른 호스트로 이전 → 무중단 정비와 장애 대비 가용성 효과.

## Ⅲ. 가상머신의 구조 (흐름)

- 핵심 요약 : 게스트 OS가 가상 하드웨어를 보고, 하이퍼바이저가 이를 물리 자원에 매핑하는 계층 구조.
- 가상 하드웨어 : vCPU·가상 메모리·vNIC·가상 디스크로 구성되는 소프트웨어적 장치 추상화.

```text
[ VM 추상화 계층 ]

게스트 VM (게스트 OS + 애플리케이션) × N
      ↓
가상 하드웨어 (vCPU · 메모리 · vNIC · 디스크)
      ↓
하이퍼바이저 (자원 스케줄링 · 격리)
      ↓
물리 하드웨어 (CPU · 메모리 · 네트워크 · 디스크)
```

```text
[ 라이브 마이그레이션 단계 ]

1. 예비 복사 (메모리 페이지의 반복 전송)
      ↓
2. 짧은 실행 정지 (최종 상태 확정)
      ↓
3. 잔여 상태 전송 (CPU 레지스터 · 장치 상태)
      ↓
4. 대상 호스트에서 실행 재개
```

## Ⅳ. 가상머신과 컨테이너의 비교

- 핵심 요약 : VM은 하드웨어 수준의 강한 격리를, 컨테이너(Container)는 커널 공유에 따른 가벼운 기동을 택한 상보적 구조.

| 비교 축 | 가상머신 | 컨테이너 |
| :--- | :--- | :--- |
| 가상화 수준 | 하드웨어 추상화 | OS 커널 수준 격리 |
| 게스트 OS | VM마다 독립 게스트 OS 필요 | 호스트 커널 공유 |
| 격리 강도 | 하드웨어 수준의 강한 격리 | 프로세스 수준의 논리적 격리 |
| 기동 속도 | OS 부팅 필요로 느림 | 프로세스 기동 수준으로 빠름 |
| 자원 부담 | 게스트 OS만큼 중복 점유 | 낮은 오버헤드, 높은 집적도 |
| 적합 영역 | 이종 OS, 강한 격리, 레거시 업무 | 마이크로서비스, CI/CD(Continuous Integration/Continuous Delivery) 파이프라인 |

- 선택 기준 :
  1. 다른 OS·커널의 실행과 강한 격리가 필요하면 VM
  2. 배포 속도와 자원 효율이 우선이면 컨테이너
  3. 두 기술은 대체 관계가 아닌 계층적 병행이 일반적

## Ⅴ. 가상머신의 한계와 방안

- 핵심 요약 : 자원 중복과 I/O 오버헤드, 관리되지 않는 VM 증가를 메모리 병합, 장치 직접 할당, 수명주기 정책으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| **자원 중복** | VM마다 커널·시스템 데몬의 중복 적재 → 메모리·디스크 낭비 | KSM(Kernel Samepage Merging)의 페이지 병합, 씬 프로비저닝(Thin Provisioning) 적용 | 호스트 메모리 활용률 |
| I/O 가상화 오버헤드 | 가상 장치의 에뮬레이션 경로 부담 → 처리율 저하 | Virtio 반가상화 드라이버, SR-IOV(Single Root I/O Virtualization)의 장치 직접 할당 | VM별 I/O 지연 시간 |
| **VM 스프롤** (VM Sprawl) | 방치 VM의 누적 → 자원·라이선스 비용 잠식 | 수명주기 관리 플랫폼의 TTL(Time to Live) 만료 정책과 생성 승인 절차 | 미사용 VM 비율 |

## Ⅵ. 가상머신에 대한 기술사적 제언

- 핵심 요약 : 격리와 기동 속도의 결합, 수명주기의 코드화, 무중단 정비의 자동화가 필요.

1. 플랫폼 조직은 다중 테넌트 영역에 Firecracker 같은 마이크로VM을 검토하여 하드웨어 수준 격리와 컨테이너급 기동 속도의 결합 방안 평가.
2. 인프라 운영 조직은 VM 생성·변경·폐기를 IaC(Infrastructure as Code)로 기술하고 승인을 코드 리뷰에 연계하는 수명주기 관리 체계 구축.
3. 정비 계획 조직은 라이브 마이그레이션 자동화와 정기 패치 일정을 결합한 무중단 정비 체계 운영.

## Ⅶ. 결론

- 핵심 요약 : 가상머신은 하드웨어 추상화로 격리·이식성·무중단 이동을 실현하는 컴퓨팅 단위.
- 시사점 : 강한 격리와 이종 환경 지원이 필요한 영역의 기본 단위로서, 컨테이너와의 역할 구분이 효율의 전제.
