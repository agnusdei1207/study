## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 가상머신

## 30초 인출

- 본질: 하나의 서버에 1개의 OS만 띄우면 자원 활용률이 저조하고 이기종 OS 앱을 함께 띄울 수 없음
- 메커니즘: 하이퍼바이저가 가상 하드웨어를 생성하고 그 위에 완전한 독립 커널을 가진 게스트 OS를 통째로 구동

## 핵심 용어

- 라이브 마이그레이션(Live Migration): 실행 중인 가상머신의 메모리 페이지와 CPU 상태를 네트워크를 통해 다른 물리 서버로 무중단(서비스 다운타임 수십 밀리초 이내) 이전하는 기술
- vCPU(Virtual CPU): 하이퍼바이저가 게스트 OS에 제공하는 가상 프로세서로, 물리 CPU 코어의 하이퍼스레딩 스레드에 1:1 또는 시분할 오버커밋(Overcommit) 매핑됨
- MicroVM: 대형 가상머신의 느린 부팅과 무거운 메모리를 극복하기 위해 레거시 하드웨어 에뮬레이션을 전면 제거하고 5ms 부팅을 구현한 초경량 가상머신(AWS Firecracker)

### Ⅱ. 핵심 특성

- 가상머신의 진정한 무기는 '보안 격리'임 → 컨테이너는 호스트 리눅스 커널을 공유하므로 커널 익스플로잇 취약점이 터지면 옆 컨테이너가 털리지만, 가상머신은 하드웨어 링(Ring) 레벨에서 완전히 분리되어 있어 멀티테넌트 퍼블릭 클라우드의 필수 불가결한 기본 단위임
- OS 중복의 비효율성을 안고 감 → 가상머신 100대를 띄우면 100개의 윈도우/리눅스 커널이 동일한 파일과 프로세스를 메모리에 중복 로드하여 기가바이트 단위의 RAM이 낭비됨
- 스냅샷과 롤백의 절대적 안정성 → 운영체제 전체 상태(디스크+RAM)를 단 1초 만에 스냅샷으로 박제할 수 있어, 위험한 시스템 업그레이드 실패 시 즉각 원상 복구할 수 있는 엔터프라이즈 신뢰성을 제공함

### Ⅲ. 관련 개념과 구분

- 가상머신 vs 컨테이너: 가상머신 = 하드웨어 에뮬레이션, 독립 커널, GB 단위 크기, 완벽한 격리 / 컨테이너 = OS 커널 프로세스 격리(cgroups/namespace), 공유 커널, MB 단위 크기, 빠른 기동

### Ⅳ. 적용 문제와 대응

- 사례: 120회 기출 및 단일 물리 호스트 내 다수 VM 구동 중 특정 VM의 I/O 폭증으로 이웃 VM 성능 저하(Noisy Neighbor)
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 특정 VM의 CPU/디스크 점유로 동일 호스트 내 이웃 VM 응답 지연 | 하이퍼바이저 스케줄러의 자원 상한선 미설정(Overcommit 경합) | CPU 고정(CPU Pinning) 및 가상화 I/O 스케줄러(cgroups blkio) 한도 제한 | VM 간 자원 간섭 완벽 격리 및 일관된 성능 보장 |
| 수백 개 가상머신 스케일아웃 시 스토리지 용량 고갈 및 기동 지연 | VM마다 수십 GB의 OS 기본 이미지(ISO) 중복 설치 | 씬 프로비저닝(Thin) 및 연결 복제(Linked Clone / CoW) 기법 적용 | 스토리지 점유율 80% 절감 및 수초 내 VM 복제 배포 |

### Ⅴ. 기술사적 제언

| 문제 | 해결 방안 |
|---|---|
| 적용 환경에서 발생하는 핵심 제약 | 기존 대책을 적용하고 핵심 운영 지표를 확인해 개선한다. |

## 출제 이력과 검증 출처

- 제120회 2교시 4번: "가상머신(Virtual Machine)과 컨테이너(Container)를 비교하여 설명하시오." → 요구 포인트: Ⅰ 가상머신과 컨테이너의 개념 정의 + Ⅲ 계층 구조도 및 가상화 경계 비교 + Ⅴ 자원 효율성, 기동 속도, 보안 격리성 등 다차원 비교표
