## 연관 키워드

- 디스크 스케줄링(Disk Scheduling), 탐색 시간(Seek Time), 회전 지연(Rotational Latency)
- FCFS, SSTF, SCAN, C-SCAN, LOOK, 엘리베이터 알고리즘
- 기아 현상(Starvation), 응답 시간 편차, HDD, SSD, NVMe
- none, mq-deadline, BFQ, blk-mq, WAL, IOPS

## Ⅰ. 디스크 스케줄링의 개요

- 핵심 요약 : 대기 중인 디스크 요청의 처리 순서를 재배열해 기계적 접근 시간을 줄이는 알고리즘.
- 개념 : 블록 저장장치에 동시 도착한 여러 I/O 요청의 처리 순서를 정해 헤드 이동을 최소화하는 **디스크 스케줄링** (Disk Scheduling) 알고리즘군.
- 배경 및 필요성 : **HDD** (Hard Disk Drive, 자기 디스크 저장장치)의 접근 시간은 헤드 이동인 **탐색 시간** (Seek Time)과 대상 섹터 도달 대기인 **회전 지연** (Rotational Latency)이 지배 → 도착 순서 처리 시 불필요한 왕복 이동으로 병목 누적.
- 주요 목적 : 탐색 거리 최소화에 따른 처리량 향상, 요청별 응답 시간 편차의 축소, 특정 트랙 요청의 **기아 현상** (Starvation) 방지.

## Ⅱ. 디스크 스케줄링의 특징 및 장점

- 핵심 요약 : 정렬 기준의 차이가 처리량과 공정성의 절충으로 나타나는 알고리즘군의 구조.

1. **FCFS** (First-Come, First-Served) : 도착 순서대로 처리 → 구현이 단순하고 공정하나 탐색 거리가 길어지는 한계.
2. **SSTF** (Shortest Seek Time First) : 현재 헤드에서 가장 가까운 요청 우선 처리 → 평균 탐색 거리의 축소 효과.
3. **SCAN** (엘리베이터 알고리즘, 빗 방향 왕복 주사 방식) : 헤드가 한 방향으로 진행하며 경로상의 모든 요청을 처리하고 끝에서 방향 전환 → 대기 상한이 존재하는 공정성 확보.
4. **C-SCAN** (Circular SCAN) : 한 방향으로만 서비스하고 반대편 시작점으로 즉시 복귀 → 트랙 위치와 무관한 균등 대기 시간 확보.
5. **LOOK** 및 C-LOOK : 요청이 존재하는 최외곽 트랙에서 방향을 바꾸는 개선 방식 → 끝단까지의 불필요 이동 제거 효과.

## Ⅲ. 디스크 스케줄링의 구조 (흐름)

- 핵심 요약 : 헤드 위치·방향을 기준으로 대기 큐를 재정렬하는 과정이며, 표준 예제에서 알고리즘별 경로가 갈리는 구조.
- 표준 예제 조건 : 헤드 53, 요청 트랙 98, 183, 37, 122, 14, 124, 65, 67, 실린더 범위 0~199.

```text
[ SSTF 처리 순서 ]

53 (현재 헤드)
        ↓
65 → 67 → 37 → 14
        ↓
98 → 122 → 124 → 183
```

```text
[ SCAN 처리 순서 ]

53에서 바깥 방향으로 진행
65 → 67 → 98 → 122 → 124 → 183
        ↓
199 도달 후 방향 전환
        ↓
37 → 14 (처리 종료)
```

- C-SCAN은 199 도달 후 0으로 복귀해 14 → 37 순으로 처리하는 방식.
- LOOK은 끝단 199 대신 요청 최외곽 183에서 방향을 바꾸는 변형.

## Ⅳ. 디스크 스케줄링의 비교

- 핵심 요약 : 헤드 이동 패턴에 따른 처리량·공정성·기아 위험의 절충과 플래시 장치에서의 방식 전환이 핵심 구조.

| 알고리즘 | 헤드 이동 패턴 | 탐색 효율 | 공정성 | 기아 위험 |
| --- | --- | --- | --- | --- |
| FCFS | 도착 순서 | 낮음 | 높음 | 없음 |
| SSTF | 최근접 요청 우선 | 높음 | 중앙 트랙 편중 | 높음 |
| SCAN | 왕복 주사 | 높음 | 중간 (끝단 지연) | 낮음 |
| C-SCAN | 단방향 주사·복귀 | 높음 | 균등 | 없음 |
| LOOK·C-LOOK | 요청 범위 내 주사 | 최적화 | 우수 | 없음 |
| none·기한 계열 (플래시) | 정렬 없이 병합·기한 관리 | 병렬성 활용 | 정책에 따름 | 제어됨 |

- 선택 기준 : 기계 헤드가 있는 HDD에는 SCAN 계열이, 탐색 자체가 없는 **SSD** (Solid State Drive)에는 정렬 비용을 없애는 방식이 유리한 판단 축.

## Ⅴ. 디스크 스케줄링의 한계와 방안

- 핵심 요약 : 플래시 부적합, 테넌트 간섭, 쓰기 지연 문제를 스케줄러 교체, 대역폭 제어, 기한 관리로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 플래시 장치 부적합 | SSD·NVMe(Non-Volatile Memory Express) 환경에서 정렬은 이득 없이 CPU 비용만 발생 | 정렬 생략형 none 스케줄러의 하드웨어 큐 직결 적용 | 요청당 CPU 사용량 |
| 가상화 환경 간섭 | 동일 장치 공유 테넌트의 I/O 경합으로 대역폭 고갈 | BFQ(Budget Fair Queueing)의 공정 배분, 테넌트별 IOPS(Input/Output Operations Per Second) 상한 제어 | 테넌트별 지연 편차 |
| 쓰기 지연 누적 | 탐색 우선 정렬에서 로그 쓰기가 후순위로 밀려 커밋 지연 | 요청 만료 시간 기반의 mq-deadline 스케줄러 적용 | 커밋 지연 시간 |

## Ⅵ. 디스크 스케줄링에 대한 기술사적 제언

- 핵심 요약 : 장치별 스케줄러 표준, 다중 큐 계층 정비, 비동기 I/O 확대를 저장 성능 운영 기준으로 정비하는 방향.
- 스토리지 운영 조직은 미디어 특성별 기본 스케줄러를 정책 문서로 고정하고, 다중 큐 계층인 blk-mq(Multi-Queue Block I/O Layer) 설정을 배포 표준에 포함하는 기준 수립 필요.
- 플랫폼 조직은 WAL(Write-Ahead Log, 사전 로그 기록) 의존 서비스의 커밋 지연을 모니터링하고 기한 기반 정책 대상을 주기 재점검하는 절차 운영 필요.
- 애플리케이션 조직은 시스템 호출 비용을 줄이는 비동기 I/O 인터페이스 도입 검토로 커널 경계 오버헤드를 낮추는 방향 필요.

## Ⅶ. 결론

- 핵심 요약 : 디스크 스케줄링은 기계적 탐색 최소화 알고리즘으로, 저장 매체 특성에 맞는 선택이 전제 조건.
- HDD에서는 SCAN 계열 정렬의 가치가, 플래시에서는 정렬 제거의 가치가 성능을 결정하는 시사점.
