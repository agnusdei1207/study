- 디스크 스케줄링(Disk Scheduling), 탐색 시간(Seek Time), 회전 지연(Rotational Latency), I/O 병목(I/O Bottleneck)

## Ⅰ. 디스크 스케줄링(Disk Scheduling)의 개요

- 핵심 요약 : 다중 I/O 요청의 탐색 시간과 회전 지연을 줄여 디스크 처리량을 높이는 I/O 대기열 정렬 알고리즘.
- 개념 : 기계식 하드디스크(HDD, Hard Disk Drive) 같은 블록 저장장치에 다중 I/O 요청이 들어왔을 때, 헤드의 기계적 이동 거리를 줄여 **탐색 시간** (Seek Time, 헤드가 목표 트랙까지 이동하는 시간)과 **회전 지연** (Rotational Latency, 목표 섹터가 헤드 아래 올 때까지의 대기 시간)을 최소화하는 **디스크 스케줄링** (Disk Scheduling) 알고리즘.
- 배경 및 필요성 : CPU와 전자식 메모리에 비해 기계식 디스크의 물리적 접근 속도가 현격히 느려, 요청을 도착 순서대로만 처리하면 **I/O 병목** (I/O Bottleneck)이 누적되므로 요청 순서를 재정렬하는 계층이 필요함.
- 핵심 목적 : 헤드의 불필요한 왕복 이동 방지, 단위 시간당 I/O 처리량 극대화, **기아 현상** (Starvation, 특정 요청의 무기한 대기) 방지를 통한 공정성 확보.

## Ⅱ. 디스크 스케줄링(Disk Scheduling)의 특징 및 장점

- 핵심 요약 : FCFS, SSTF, SCAN, C-SCAN, LOOK이 탐색 거리와 공정성 사이에서 서로 다른 균형을 잡는 구조.

1. **FCFS** (First-Come, First-Served, 도착 순서 처리) : 가장 단순하고 공정하나 헤드가 크게 오가 탐색 거리가 길어짐.
2. **SSTF** (Shortest Seek Time First, 최단 탐색 우선) : 현재 헤드에서 가장 가까운 요청을 먼저 처리 → 처리량이 높으나 외곽 트랙 요청의 기아 발생 가능.
3. **SCAN** (엘리베이터 알고리즘) : 헤드가 한쪽 끝에서 반대쪽 끝으로 이동하며 경로상의 요청을 처리하고 끝에서 방향을 바꿈 → 탐색 거리와 기아 위험의 균형.
4. **C-SCAN** (Circular SCAN, 원형 주사) : 한 방향으로만 처리하고 끝에서 시작점으로 빠르게 복귀 → 트랙 위치에 따른 응답 시간 편차 축소.
5. **LOOK / C-LOOK** : 디스크 끝까지 가지 않고 요청이 있는 마지막 트랙에서 방향을 바꾸거나 복귀 → 불필요한 이동 제거.

## Ⅲ. 디스크 스케줄링(Disk Scheduling)의 구조 및 동작 메커니즘

- 핵심 요약 : 헤드 위치와 탐색 방향을 기준으로 대기 큐를 재정렬하는 과정이며, 현대 리눅스는 다중 큐 구조로 진화함.
- 현대 리눅스는 **다중 큐 블록 계층** (blk-mq, Multi-Queue Block Layer)을 사용해 여러 하드웨어 큐를 병렬로 다루며, 플래시 저장장치에는 전용 스케줄러를 적용함.

```text
[ 예시 조건 ]

헤드 위치 : 53
요청 트랙 : 98, 183, 37, 122,
          14, 124, 65, 67
```

```text
[ SSTF 처리 순서 ]

53 (현재 헤드)
        ↓
65 → 67 → 37 → 14
        ↓
98 → 122 → 124 → 183
```

```text
[ SCAN 처리 순서 ]

53 (현재 헤드, 바깥 방향 시작)
        ↓
65 → 67 → 98 → 122 → 124 → 183
        ↓ (끝점 도달 후 방향 반전)
37 → 14
```

```text
[ C-SCAN 처리 순서 ]

53 (현재 헤드, 바깥 방향 시작)
        ↓
65 → 67 → 98 → 122 → 124 → 183
        ↓ (요청 없이 시작점으로 복귀)
14 → 37
```

## Ⅳ. 디스크 스케줄링(Disk Scheduling)의 비교

- 핵심 요약 : 탐색 효율, 공정성, 기아 가능성의 세 축에서 기계식 디스크 알고리즘과 NVMe 같은 플래시 환경의 방식이 갈리는 구조.

| 스케줄링 알고리즘 | 헤드 이동 패턴 | 처리량·탐색 효율 | 공정성 | 기아 가능성 |
| --- | --- | --- | --- | --- |
| FCFS | 요청 도착 순서 | 낮음 | 도착 순으로 공정 | 없음 |
| SSTF | 현재 위치에서 최단 거리 | 높음 | 중앙 트랙에 치우침 | 높음 (원거리 트랙) |
| SCAN | 양방향 왕복 주사 | 높음 | 보통 (가장자리 지연) | 낮음 |
| C-SCAN | 단방향 주사 후 복귀 | 높음 | 균등함 | 없음 |
| LOOK / C-LOOK | 요청 범위 내 주사 | 최적화됨 | 우수 | 없음 |
| none (플래시 장치) | 정렬 없이 병합 후 전달 | 장치 병렬성 활용 | 공정 | 없음 |

- 선택 기준 : NVMe(Non-Volatile Memory Express) SSD처럼 기계적 탐색과 회전이 없는 장치에서는 탐색 정렬이 이득 없이 CPU만 쓰므로, none 또는 mq-deadline을 기본으로 두는 것이 현실적임.

## Ⅴ. 디스크 스케줄링(Disk Scheduling)의 한계와 방안

- 핵심 요약 : 플래시와의 패러다임 불일치, 가상화 환경의 간섭, 쓰기 데드라인 미보장을 none 스케줄러, 대역폭 제어, 만료 시간 기반 스케줄러로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 플래시 저장장치와의 패러다임 불일치 | 물리 헤드가 없는 SSD에서 SCAN류 정렬은 탐색 이득 없이 CPU 사이클만 소모 | blk-mq에서 I/O 스케줄러를 none으로 설정해 하드웨어 병렬 큐로 직접 전달 | 요청당 CPU 사용량, 처리량 |
| **Noisy Neighbor** (간섭, 같은 디스크를 쓰는 테넌트 간 I/O 경합) | 한 가상머신의 과도한 요청이 다른 가상머신의 대역폭을 고갈시킴 | BFQ(Budget Fair Queueing) 스케줄러 또는 cgroups v2의 io.weight, io.max로 테넌트별 대역폭과 IOPS(Input/Output Operations Per Second) 상한 보장 | 테넌트별 지연 편차, IOPS 사용률 |
| 쓰기 데드라인 미보장 | 탐색 거리 중심 정렬에서 WAL(Write-Ahead Log) 같은 쓰기 요청이 뒤로 밀려 커밋 지연 발생 | 요청별 만료 시간을 관리하는 mq-deadline 스케줄러로 기아 차단 | 커밋 지연 시간, 데드라인 초과 건수 |

## Ⅵ. 디스크 스케줄링(Disk Scheduling)에 대한 기술사적 제언

- 핵심 요약 : 장치 특성에 맞는 쓰기 정책, 계층별 스케줄러 기준, 비동기 I/O 전환을 묶어 저장장치 성능을 운영 기준으로 관리.
- 저장 체계를 설계하는 조직은 **ZNS** (Zoned Namespace, 구역 단위 쓰기를 강제하는 SSD 인터페이스)를 도입할 때 커널 I/O 경로가 구역 쓰기 규칙을 따르도록 맞추고, 쓰기 증폭(Write Amplification)을 줄여 장치 수명을 관리해야 한다.
- 스토리지 티어별로 스케줄러를 나누는 방식이 현실적이다. NVMe 계층은 none, HDD 계층은 mq-deadline 또는 bfq로 운영하고, 그 기준을 문서로 고정하는 것이 바람직하다.
- I/O 집약 애플리케이션은 시스템 호출 횟수를 줄이는 io_uring 같은 비동기 I/O 인터페이스로 전환을 검토해, 커널 경계를 넘는 비용을 줄여야 한다.

## Ⅶ. 결론

- 핵심 요약 : 디스크 스케줄링은 HDD의 탐색 시간을 줄여 처리량을 높이는 정렬 알고리즘이며, SSD 시대에는 none과 mq-deadline이 표준적 선택.
- 시사점 : 장치 특성을 무시한 스케줄러 선택은 정렬 비용만 남기므로, 스토리지 계층별 기준을 함께 설계해야 함.
