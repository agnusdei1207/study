## 답안 골격
```text
[디스크 스케줄링] ◀━━ 머리: Ⅶ 내 의견 (NVMe SSD 특성에 맞춘 전통적 엘리베이터 스케줄러 폐기 및 None/Kyber 스케줄러 전환)
 ┃
 ┣━ Ⅰ 개요 ───── 기계식 HDD의 물리적 헤드 이동(탐색 시간) 병목 → 헤드 이동 거리 최소화 알고리즘
 ┣━ Ⅱ 특징 ───── 탐색 시간(Seek Time) 최소화 · 회전 지연 시간 단축 · 기아 방지 · 처리량 극대화
 ┣━ Ⅲ 구조 ───── 디스크 큐(I/O Request Queue) + 실린더 번호 + 읽기/쓰기 헤드 + 디스크 컨트롤러
 ┣━ Ⅳ 흐름 ───── ① I/O 요청 수신 → ② 요청 실린더 위치 정렬 → ③ 스케줄링 기법 적용 → ④ 헤드 이동 및 섹터 읽기/쓰기
 ┣━ Ⅴ 비교 ───── FCFS vs SSTF vs SCAN(엘리베이터) vs C-SCAN vs LOOK vs C-LOOK
 ┗━ Ⅵ 실무 ───── SSTF의 바깥쪽 트랙 기아(Starvation) / SSD 환경에서 HDD 스케줄러 오적용 / 플래시 마모도
```
- 필수 키워드: 탐색 시간(Seek Time) · 회전 지연(Rotational Latency) · SSTF · SCAN(엘리베이터) · C-SCAN · NVMe None 스케줄러
- 기출: 137회 3교시 `운영체제 스케줄링 기법(디스크 I/O 스케줄링 알고리즘 및 특징)`

## 한 줄 본질
- 기계식 하드디스크(HDD)에서 데이터를 읽을 때 가장 큰 지연을 유발하는 기계적 헤드 이동 시간(Seek Time, 수 ms) → I/O 요청들의 실린더 번호를 재정렬하여 헤드의 이동 거리를 최소화하는 순서로 처리 → 전체 디스크 I/O 처리량 극대화 및 지연 단축 / 최단 탐색 우선(SSTF) 시 가장자리 트랙 요청의 무한 기아 현상 발생

## 핵심 그림
```text
[ 트랙/실린더 번호:  0 <───────────────────────── 50 (현재 헤드) ─────────────────────────> 100 ]

1. SSTF (최단 탐색 우선): 현재 위치(50)에서 가장 가까운 트랙 우선 방문 ──> 가장자리(0, 100) 기아 위험!
2. SCAN (엘리베이터):    한쪽 끝(100)까지 가면서 서비스 ──> 방향 전환 후 반대 끝(0)으로 가며 서비스
3. C-SCAN (원형 SCAN):   한쪽 끝(100)으로 가며 서비스 ──> 끝 도달 시 반대편(0)으로 서비스 없이 급속 이동
                         (모든 트랙에 균등한 대기 시간 제공)
4. LOOK / C-LOOK:        끝(0, 100)까지 가지 않고, 마지막 요청이 있는 트랙까지만 이동 후 반전
```

## 핵심 용어
- 탐색 시간(Seek Time): 디스크 암(Arm)이 지정된 데이터가 위치한 트랙(실린더)까지 기계적으로 이동하는 데 걸리는 시간(전체 디스크 I/O 지연의 60~80% 차지)
- SSTF(Shortest Seek Time First): 현재 헤드 위치에서 가장 적은 헤드 이동 거리를 필요로 하는 요청을 다음 처리 대상으로 선택하는 기법(평균 응답성은 좋으나 기아 유발)
- C-SCAN(Circular SCAN): 헤드가 단일 방향으로만 이동하면서 요청을 서비스하고, 끝에 도달하면 즉시 시작 트랙으로 이동하여 서비스함으로써 실린더 간 대기 시간의 불공평성을 해소한 기법

## 핵심 통찰
- 디스크 I/O 지연 = 탐색 시간(Seek Time) + 회전 지연(Rotational Latency) + 데이터 전송 시간(Transfer Time) 중 '탐색 시간'을 줄이는 것이 디스크 스케줄링의 알파이자 오메가임
- SCAN 알고리즘은 건물의 엘리베이터 동작과 완벽히 일치하여 '엘리베이터 알고리즘'으로 불리며, 기아를 방지하면서도 높은 처리량을 보장해 오랫동안 OS 표준으로 군림
- 그러나 물리적 회전 헤드가 없는 플래시 메모리(SSD) 및 NVMe 환경에서는 탐색 시간(Seek Time) 자체가 0임 → 전통적 SCAN/CFQ 스케줄러는 불필요한 CPU 정렬 오버헤드만 유발하므로 리눅스는 `none` 또는 지연시간 중심의 `kyber`, `mq-deadline`을 표준으로 사용

## 이웃 토픽과 구분
- SCAN vs C-SCAN: SCAN = 왕복하면서 양방향 모두 서비스(중앙 트랙이 양끝 트랙보다 2배 자주 서비스되는 불공평 발생) / C-SCAN = 편도만 서비스하고 되돌아올 때는 쉬어감(모든 트랙에 균등한 대기 시간 보장)

## 문제·원인·대책
- 사례: 137회 기출 고속 트랜잭션 시스템에서 SSD 도입 후 예상외의 CPU 사용률 증가 및 디스크 큐 병목
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 플래시 NVMe SSD 장착 서버에서 I/O 처리량이 사양에 미달 | 커널의 전통적 HDD용 엘리베이터 스케줄러(BFQ/CFQ) 활성화로 인한 CPU 병목 | I/O 엘리베이터 스케줄러를 `none` 또는 `mq-deadline`으로 변경 | 불필요한 소프트웨어 정렬 제거 및 NVMe 하드웨어 멀티큐 100% 활용 |
| HDD 기반 대용량 로그 수집기에서 간헐적 로그 유실 | 대량 순차 쓰기 중 SSTF 스케줄러의 가장자리 트랙 요청 기아(Starvation) | C-LOOK 또는 마감시간(Deadline) 스케줄러 적용 | 최대 대기 시간 한도(Deadline) 강제로 공평성 보장 |

## 이렇게 출제된다
- 제137회 3교시 1번: "운영체제 스케줄링 기법에 대한 각 내용을 설명하시오." → 요구 포인트: Ⅰ 디스크 I/O 성능 요소(Seek, Latency) + Ⅴ 스케줄링 알고리즘 5종(FCFS, SSTF, SCAN, C-SCAN, LOOK) 비교 및 동작 시뮬레이션
