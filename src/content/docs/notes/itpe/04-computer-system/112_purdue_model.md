```text
[퍼듀 모델] ◀━━ 머리: Ⅶ 내 의견 (IDMZ 중심 단방향 데이터 전송과 OT 제로 트러스트 마이크로 세그멘테이션 결합)
 ┃
 ┣━ Ⅰ 개요 ───── IT-OT 융합에 따른 외부 사이버 위협의 생산 공정 침투 위험 → 기능·통제 수준별 계층 분리 참조 모델
 ┣━ Ⅱ 특징 ───── 계층별 기능 분리(Level 0~5) · 계층 간 직접 통신 차단 · 산업용 DMZ(IDMZ) 완충 · 가용성 및 안전성 최우선
 ┣━ Ⅲ 구조 ───── OT 영역(L0 물리공정·L1 기초제어·L2 감시제어·L3 공장운영) + L3.5 IDMZ + IT 영역(L4 기업망·L5 클라우드)
 ┣━ Ⅳ 흐름 ───── ① L0 센서 신호 수집 → ② L1 PLC 제어 연산 → ③ L2 HMI 감시/L3 MES 집계 → ④ L3.5 IDMZ 경유 복제 → ⑤ L4 ERP 전송
 ┣━ Ⅴ 비교 ───── 전통 계층형 퍼듀 모델 vs 제로 트러스트 OT 아키텍처 vs IIoT 엣지-클라우드 직결 모델
 ┗━ Ⅵ 실무 ───── L3.5 우회 원격 유지보수 통로 개방 / 레거시 PLC 평문 프로토콜(Modbus) 도청 / IT-OT 보안 패치 주기 충돌
```
- 필수 키워드: 퍼듀 모델(Purdue Model) · ISA-95 · IEC 62443 · OT/ICS 보안 · Level 0~5 · IDMZ(산업용 DMZ) · PLC/SCADA
- 기출: 125회 2교시 `스마트 팩토리 산업제어시스템 보안 및 퍼듀 참조 모델` 출제

## 한 줄 본질
- 제조 설비와 공정 제어망(OT)이 외부 인터넷망(IT)과 직접 연결되어 발생하는 해킹 및 설비 정지 위험을 방지하기 위해 물리 공정(L0)부터 전사망(L5)까지 6단계로 계층을 분리하고 IDMZ(L3.5)를 통해 데이터를 안전하게 완충 교환하는 산업 제어 참조 모델

## 핵심 그림
```text
[ 퍼듀 참조 모델(ISA-95) 계층 구조 및 IDMZ 배치 ]

[ IT 영역 ]
 Level 5: 외부망 / 클라우드 (Cloud, B2B 파트너 연계)
    │
 Level 4: 전사 기업망 (ERP, SCM, 이메일, 사내 업무망)
════╪═══════════════════════════════════════════════════════ (경계 방화벽)
[ 완충 ]
 Level 3.5: 산업용 DMZ (IDMZ)
    │        - 패치 관리 서버(WSUS), 데이터 다이오드 / 미러 Historian
    │        - 원격 접속 점프 호스트(Jump Host), 프록시
════╪═══════════════════════════════════════════════════════ (내부 방화벽)
[ OT 영역 ]
 Level 3: 공장 운영 관리 (MES, 공정 데이터베이스 Historian)
    │
 Level 2: 감시 및 감독 제어 (HMI, SCADA 엔지니어링 워크스테이션)
    │
 Level 1: 기본 제어 (PLC, DCS, RTU, 안전 제어 장치 SIS)
    │
 Level 0: 물리 공정 (센서, 액추에이터, 모터, 로봇 암, 밸브)
```

## 핵심 용어
- IDMZ(Industrial Demilitarized Zone, Level 3.5): IT 네트워크(Level 4)와 OT 네트워크(Level 3) 사이에 위치하여 직접적인 트래픽 흐름을 원천 차단하고 프록시 및 미러링 서비스를 제공하는 보안 완충 영역
- PLC(Programmable Logic Controller): 현장의 센서 신호를 입력받아 기계 공정을 실시간(Real-time) 제어하는 산업용 특수 제어 컴퓨터
- ISA-95 / IEC 62443: 기업 업무 시스템과 제어 시스템의 통합 표준(ISA-95) 및 산업 자동화 제어 시스템 사이버 보안 표준(IEC 62443)

## 핵심 통찰
- 퍼듀 모델의 핵심 철학은 '단계를 건너뛰는 통신 금지'임 → Level 4의 ERP 시스템이 Level 1의 PLC나 Level 2의 HMI에 직접 IP 패킷을 보낼 수 없으며, 모든 상향 데이터는 Level 3 MES와 Level 3.5 IDMZ의 레플리카 DB를 거쳐야만 안전성이 유지됨
- 가용성(Availability)과 기밀성(Confidentiality)의 우선순위 역전 → 일반 IT 환경은 CIA(기밀성-무결성-가용성) 순서지만, OT 퍼듀 모델 환경은 AIC(가용성-무결성-기밀성) 및 작업자 안전(Safety)이 최우선이므로 오작동을 유발할 수 있는 실시간 패치나 셧다운 조치가 금기시됨
- IIoT와 클라우드 분석의 도입으로 퍼듀 모델의 경계가 무너지고 있음 → 현장 센서(Level 0) 데이터를 클라우드로 직결하려는 스마트 팩토리 요구가 증가함에 따라, 계층을 완전히 허무는 대신 엣지 게이트웨이에 제로 트러스트(ZTA) 마이크로 세그멘테이션을 결합하는 방식으로 진화함

## 이웃 토픽과 구분
- 퍼듀 모델(Purdue Model) vs OSI 7 계층: OSI 7 계층 = 네트워크 통신 프로토콜의 논리적 기능 분할 체계 / 퍼듀 모델 = 산업 제어 시스템의 역할, 기능 및 보안 통제 수준에 따른 인프라 계층 분할 체계

## 문제·원인·대책
- 적용 상황: 석유화학 또는 자동차 제조 공장의 IT-OT 융합 및 보안 고도화
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 외부 협력업체의 원격 PC가 악성코드에 감염되어 OT 공정망으로 랜섬웨어 전파 | 협력업체 원격 접속용 VPN이 Level 2/3 제어망으로 직접 연결됨 | Level 3.5 IDMZ 내 점프 호스트 구축 및 다중 인증(MFA), 세션 녹화 강제 | 원격 접속 단말의 제어망 직접 접근 차단 |
| Level 1 PLC 장비의 펌웨어 변조 및 비인가 제어 명령(Stuxnet 유사 공격) 주입 | Modbus 등 레거시 산업용 프로토콜의 인증 및 암호화 부재 | OT 전용 보안 스위치 기반 마이크로 세그멘테이션 및 이상 제어 명령 DPI 차단 | 비인가 제어 명령 패킷 탐지 및 즉시 격리 |
| 전사 ERP와 공장 MES 간 데이터 연계 시 대역폭 포화로 인한 제어 지연 | IT 망의 대용량 트래픽이 OT 내부망으로 유입 | 물리적 일방향 데이터 전송 장치(단방향 데이터 다이오드) 설치 | OT에서 IT로의 단방향 전송 보장 및 역방향 공격 원천 차단 |

## 이렇게 출제된다
- 제125회 2교시: "스마트 팩토리 구현을 위한 산업제어시스템(ICS)의 퍼듀 참조 모델(Purdue Model)의 계층별 구성 요소와 특징을 설명하고, 안전한 IT-OT 연계를 위한 보안 대책을 설명하시오." → 요구 포인트: Ⅰ 퍼듀 모델의 정의 + Ⅲ Level 0~5 계층 구조도 + Ⅵ IDMZ 구축 및 IT-OT 연계 보안 통제

## 내 의견
- [IT-OT 통합 보안 관제를 위한 IDMZ 내 단방향 데이터 다이오드와 OT 전용 NDR 도입] 계층 격리만으로는 USB 유입이나 승인된 단말을 통한 악성코드 전파를 막을 수 없음 → 나라면: 공정 제어 데이터를 상위 IT 망으로 전달할 때는 물리적 송수신 분리 기술인 '데이터 다이오드'를 배치하여 역방향 침투 경로를 물리적으로 봉쇄하고, Level 2~3 스위치 미러 포트에 OT 전용 네트워크 탐지 및 대응(NDR) 센서를 설치하여 Modbus/DNP3 등 산업용 프로토콜의 이상 패킷을 실시간 탐지하는 가시성 확보 체계 구축
