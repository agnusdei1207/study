## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 하이퍼바이저

## 30초 인출

- 본질: 서버 1대에 OS 1개만 설치하면 CPU/메모리 사용률이 10~20%에 머물고 인프라가 낭비됨
- 메커니즘: 하드웨어와 OS 사이에 가상머신 모니터(VMM) 계층을 두어 물리 자원을 가상 머신(VM) 단위로 시분할/공간분할 분배

## 핵심 용어

- VMM(Virtual Machine Monitor): 하이퍼바이저의 핵심 컴포넌트로, 물리 자원을 가상화하고 게스트 OS 간의 메모리 및 CPU 접근을 중재하는 관리 소프트웨어
- VM-Exit / VM-Entry: 인텔 VT-x 환경에서 게스트 OS가 비루트(Non-Root) 모드에서 특권 명령을 내릴 때 하이퍼바이저(Root 모드)로 제어권이 넘어가는 것을 VM-Exit, 처리 후 게스트로 복귀하는 것을 VM-Entry라 부름
- 전가상화(Full Virtualization) vs 반가상화(Para-virtualization): 전가상화 = 게스트 OS 수정 없이 바이너리 변환/하드웨어 가속으로 구동 / 반가상화 = 게스트 OS의 커널을 수정하여 하이퍼바이저에 Hypercall을 직접 호출

```text
 +─────────────────────────────+                +─────────────────────────────+

 |   하이퍼바이저 (Type 1)      |                |   하이퍼바이저 (Type 2)      |
 |   (ESXi, Xen, KVM, Hyper-V) |                |   (VirtualBox, Workstation) |
```

```text
                                                +─────────────────────────────+
                                                (개발자 PC, 테스트, 편리한 설치)
```

### Ⅱ. 핵심 특성

- 하이퍼바이저의 최대 성능 적은 'VM-Exit'임 → 게스트 OS가 특권 명령을 칠 때마다 하이퍼바이저로 컨텍스트 스위칭이 일어나며 수백~수천 사이클이 증발함 → 인텔 VT-x/AMD-V 등 하드웨어 지원 가상화와 확장 페이지 테이블(EPT/NPT)이 도입되어 이 비용을 극소화함
- KVM은 Type 1인가 Type 2인가? → KVM은 표준 리눅스 커널을 하이퍼바이저로 전환시키는 커널 모듈이므로 리눅스 자체가 베어메탈 하이퍼바이저로 동작하는 'Type 1'에 해당함
- 컨테이너의 등장이 하이퍼바이저를 죽이지 못함 → 컨테이너는 OS 커널을 공유하므로 멀티테넌트 환경에서 보안 격리가 취약하지만, 하이퍼바이저는 하드웨어 수준의 메모리/CPU 링(Ring) 격리를 제공하므로 클라우드 IaaS의 근본 뼈대로 영구 존속함

### Ⅲ. 관련 개념과 구분

- 하이퍼바이저(VM) vs 컨테이너(Docker): 하이퍼바이저 = 독립된 게스트 OS 커널 구동, 완벽한 보안 격리, 무거운 이미지(GB 단위), 상대적 느린 기동 / 컨테이너 = 호스트 커널 공유, 프로세스 수준 격리, 초경량(MB 단위), 밀리초 기동

### Ⅳ. 적용 문제와 대응

- 사례: 122회 기출 및 금융권 가상화 클러스터에서 10Gbps 대용량 트래픽 수용 시 패킷 손실 장애
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 네트워크 집약적 VM에서 가상 브리지(vSwitch) 병목으로 패킷 드랍 | 가상 NIC 에뮬레이션과 CPU 인터럽트 처리로 인한 소프트웨어 지연 | SR-IOV(Single Root I/O Virtualization) 및 PCIe 패스스루 적용 | 하이퍼바이저를 우회하여 물리 NIC와 VM 직결(베어메탈급 99% 속도) |
| 클라우드 멀티테넌트 환경에서 가상화 이스케이프(Escape) 침해 위험 | 게스트 OS에서 하이퍼바이저 커널 취약점(QEMU 결함 등)을 찔러 호스트 권한 탈취 | MicroVM 경량 가상화(AWS Firecracker) 도입 및 최소 권한 샌드박싱 | 부팅 5ms 유지 및 공격 표면(Attack Surface) 최소화 |

### Ⅴ. 기술사적 제언
