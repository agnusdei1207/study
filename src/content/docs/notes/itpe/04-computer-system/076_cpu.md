## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → CPU

## 30초 인출

- 본질: 메모리로부터 프로그램 명령어를 순차적으로 가져와 해석하고 실행하는 범용 직렬 처리 엔진
- 메커니즘: 대용량 캐시와 복잡한 분기 예측, 비순차 실행(Out-of-Order) 하드웨어를 집적하여 단일 명령어 지연 시간 극소화 / 대규모 병렬 데이터 처리 시 코어 수 부족으로 처리량 한계

## 핵심 용어

- 비순차 실행(OoOE, Out-of-Order Execution): 이전 명령어의 메모리 데이터 인출이 지연될 때, 뒤따르는 의존성 없는 명령어를 먼저 실행하여 CPU 파이프라인 낭비를 막는 기법
- 분기 예측(Branch Prediction): `if`문 등의 조건문 분기 방향을 사전에 통계적으로 예측하여, 파이프라인이 멈추지 않고 선제적으로 명령어를 실행하도록 돕는 하드웨어 유닛
- 명령어 파이프라인(Instruction Pipeline): 하나의 명령어를 여러 단계(Fetch-Decode-Execute-Mem-WB)로 나누어 여러 명령어를 중첩(Overlap) 실행하는 기법

## 1교시 10점 답안

### Ⅰ. 정의·목적

- 정의: CPU는 프로그램 명령어를 가져와 해석하고 실행하는 범용 프로세서다.
- 목적: 다양한 제어 흐름과 순차 처리에 맞춰 프로그램을 실행한다.

### Ⅱ. 핵심 구조와 작동

|                 CPU (Central Processing Unit)                 |
|                                                               |

                                v

### Ⅱ. 핵심 특성

- CPU의 실리콘 다이 대부분은 '연산기(ALU)'가 아님 → 다이 면적의 70% 이상이 L2/L3 캐시 SRAM과 분기 예측기, 명령어 재정렬 버퍼(ROB) 등 '지연시간을 줄이기 위한 보조 장치'로 채워져 있음
- 직렬 성능의 끝판왕이자 복잡도의 정점임 → 단일 스레드를 최대한 빠르게 끝내는 데 모든 공학적 역량이 집중되어 있으므로, OS 커널, 트랜잭션 DB, 복잡한 비즈니스 로직 제어에는 CPU를 대체할 하드웨어가 없음
- 무어의 법칙과 클록 주파수 증가는 끝남 → 5GHz 이상에서는 발열과 누설 전류 때문에 주파수를 올리지 못하므로, 멀티코어화와 전용 가속기(NPU, 암호화 가속기)를 SoC에 내장하는 방향으로 진화함

### Ⅲ. 관련 개념과 구분

- CPU vs GPU: CPU = 소수의 강력한 코어, 복잡한 제어 로직, 큰 캐시, 낮은 지연(Latency 지향) / GPU = 수천 개의 단순한 코어, 단순한 제어 로직, 작은 캐시, 높은 처리량(Throughput 지향)

### Ⅳ. 적용 문제와 대응

- 사례: 120회 기출 및 고성능 서버에서 분기 예측 실패(Branch Misprediction)로 인한 파이프라인 플러시 성능 저하
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 정렬되지 않은 배열의 조건문 순회 시 연산 속도가 3배 이상 저하 | 불규칙한 분기 패턴으로 하드웨어 분기 예측 실패 및 파이프라인 전면 비우기(Flush) 발생 | 조건 분기문(`if`)을 비트 연산 또는 삼항 조건 이동(`cmov`) 명령어로 치환 | 분기 예측 실패 원천 제거 및 파이프라인 연속성 유지 |
| 멀티코어 환경에서 코어 수 증가에 따른 캐시 일관성 버스 경합 | 각 코어의 L1/L2 캐시 간 스눕(Snoop) 트래픽 폭증 | 디렉토리 기반 일관성 프로토콜 및 코어별 로컬 NUMA 메모리 바인딩 | 확장성 저해 없는 코어 선형 확장성 확보 |

### Ⅴ. 기술사적 제언

| 문제 | 해결 방안 |
|---|---|
