## 연관 키워드

- Active-Active, 재해복구(DR, Disaster Recovery), RTO(Recovery Time Objective), RPO(Recovery Point Objective)
- 리전(Region), GSLB(Global Server Load Balancing), Anycast, 쿼럼(Quorum), CRDT(Conflict-free Replicated Data Types)
- 스플릿 브레인(Split-Brain), 무상태(Stateless), 비즈니스 연속성(BCP, Business Continuity Plan), 카오스 엔지니어링

## Ⅰ. 다중지역 동시 가동 재해복구 시스템의 개요

- 핵심 요약 : 복수 리전이 트래픽을 동시에 처리해 리전 장애 시 전환 시간과 데이터 손실을 줄이는 재해복구 구조.
- 개념 : 지리적으로 떨어진 두 개 이상의 리전에 같은 서비스와 데이터 계층을 상시 가동하고 모든 리전이 요청을 나눠 처리하는 **재해복구** (DR, Disaster Recovery) 방식으로, Active-Active 구성이라고도 함.
- 배경 및 필요성 : 단일 리전에 장애가 나면 대기 자원을 띄우거나 백업을 복원하는 동안 서비스가 중단되는 비용이 커지며, 중단 허용 시간이 짧은 금융·공공 업무에서는 이 비용을 감당하기 어려움.
- 주요 목적 : 리전 단위 재해에서도 업무를 이어 가는 비즈니스 연속성 확보, 목표 복구 시간(RTO, Recovery Time Objective)과 목표 복구 시점(RPO, Recovery Point Objective)의 최소화.

## Ⅱ. 다중지역 동시 가동 재해복구 시스템의 특징 및 장점

- 핵심 요약 : 전역 트래픽 분산, 리전 간 데이터 정합성 제어, 무상태 구성이 무중단 절체와 응답 지연 감소로 이어지는 구조.

1. 전역 트래픽 분산 : **GSLB** (Global Server Load Balancing)와 Anycast 라우팅으로 사용자를 가까운 정상 리전에 배분 → 응답 지연 감소와 장애 리전의 자동 격리.
2. 리전 간 데이터 정합성 : 합의 알고리즘(Paxos, Raft) 기반 분산 데이터베이스로 쓰기 순서를 보장하거나, 충돌 없이 병합되는 **CRDT** (Conflict-free Replicated Data Types)를 적용 → 양방향 쓰기에서도 데이터가 어긋나지 않도록 통제.
3. 무상태 애플리케이션 : 세션 상태를 리전 밖으로 분리 → 어느 리전으로 절체되어도 사용자가 재로그인 없이 업무를 이어 감.

## Ⅲ. 다중지역 동시 가동 재해복구 시스템의 구조 (흐름)

- 핵심 요약 : 전역 라우팅 계층 아래에서 두 리전이 동시에 처리하고, 리전 사이 복제가 정합성을 맞추는 구조.
- **Anycast** : 같은 IP 주소를 여러 리전이 광고하여 네트워크가 가장 가까운 정상 리전으로 경로를 잡는 라우팅 방식.

```text
[ 전역 트래픽 계층 ]

사용자 요청
   ↓
GSLB · Anycast (리전 헬스체크 기반)
   ↓
리전 A / 리전 B (동시 처리)
```

```text
[ 리전 간 데이터 복제 ]

리전 A 쓰기 요청
   ↓
로컬 쓰기 + 쿼럼 합의 확인
   ↓
리전 B로 복제 전파
   ↓
충돌 시 CRDT 또는 우선순위 규칙으로 병합
```

## Ⅳ. 다중지역 동시 가동 재해복구 방식의 비교

- 핵심 요약 : 상시 동시 가동, 대기 가동, 최소 가동, 백업 복원 방식은 복구 목표와 비용이 서로 반비례하는 구도.

| 비교 축 | Active-Active (동시 가동) | Warm Standby (축소 대기) | Pilot Light (최소 가동) | Backup & Restore (백업 복원) |
| --- | --- | --- | --- | --- |
| 운영 방식 | 모든 리전이 트래픽을 상시 처리 | 축소 규모의 대기 리전을 복제 상태로 유지 | 핵심 구성요소만 가동하고 나머지는 중지 | 백업본만 보관, 필요 시 복원 |
| 복구 시점 (RPO) | 동기 복제 시 손실 최소, 비동기 복제는 손실 가능 | 비동기 복제 범위만큼 손실 가능 | 복제된 데이터 시점 기준 손실 | 마지막 백업 시점 기준 손실 |
| 복구 시간 (RTO) | 자동 절체로 가장 짧음 | 대기 자원 확장 후 절체 | 자원 기동이 필요해 중간 이상 | 복원 시간만큼 길어짐 |
| 데이터 정합성 | 분산 합의와 충돌 해소 필수 | 단방향 복제 중심 | 단방향 복제 중심 | 복원 시점 기준 |
| 비용과 복잡도 | 가장 높음 | 중간 | 낮음 ~ 중간 | 가장 낮음 |

- 선택 기준 : 업무가 허용하는 중단 시간과 데이터 손실 범위를 먼저 정하고, 그 목표를 만족하는 가장 낮은 비용의 방식을 고름.
- 유의 사항 : RTO와 RPO는 복제 방식, 네트워크 분할, 합의 구성에 따라 실제 값이 달라지므로 방식의 이름만으로 무중단이나 무손실을 보장하지 않음.

## Ⅴ. 다중지역 동시 가동 재해복구 시스템의 한계와 방안

- 핵심 요약 : 리전 간 지연, 양방향 쓰기 충돌, 상태 저장 서비스의 절체 단절, 상시 비용을 계층화와 무상태 설계로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 리전 간 지연과 동기 복제의 상충 | 리전 거리에 따른 왕복 지연으로 동기 커밋 처리량 저하 | 데이터 중요도별 계층화: 핵심 거래는 쿼럼 기반 동기 커밋, 조회·로그는 비동기 복제 | 커밋 지연 시간, 처리량 |
| 네트워크 분할 시 양방향 쓰기 충돌 (스플릿 브레인) | 리전 간 연결이 끊기면 양쪽이 독립 갱신해 데이터 불일치 발생 | 제3 리전에 쿼럼 감시 노드 배치, 과반 쪽에만 쓰기 권한 부여, CRDT 병합 | 파티션 발생 횟수, 불일치 건수 |
| 상태 저장 서비스의 절체 단절 | 세션이 리전에 묶이면 절체 후 대량 재로그인 발생 | 무상태 설계, 토큰 기반 세션 관리, 리전 간 분산 캐시 | 절체 후 세션 실패율 |
| 상시 가동에 따른 비용 증가 | 모든 리전에 실질 용량을 상시 확보해야 함 | 트래픽 기반 자동 확장, 리전별 용량 계획 수립 | 리전 유휴 용량 비율 |

## Ⅵ. 다중지역 동시 가동 재해복구에 대한 기술사적 제언

- 핵심 요약 : 업무 등급에 따른 선택 적용, 규정 사전 검토, 장애 주입 훈련을 갖추면 다중지역 구조의 실효성이 확보됨.
- 금융·공공 기관이 업무를 중요도별로 등급화하여 동시 가동 방식을 핵심 거래 시스템에만 적용하면, 비용과 복구 목표를 함께 맞출 수 있다.
- 리전 간 데이터 복제가 국외 리전을 포함하는 경우 개인정보와 데이터 주권 규정을 설계 단계에서 함께 검토하는 절차를 두어야 법적 제약으로 인한 재설계를 줄일 수 있다.
- 카오스 엔지니어링(Chaos Engineering)으로 장애를 의도적으로 주입하는 시험을 재해 훈련 체계에 편입하고, 훈련 결과를 목표 복구 시간과 시점의 달성 여부로 평가하면 구성의 실효성을 계속 확인할 수 있다.

## Ⅶ. 결론

- 핵심 요약 : 다중지역 동시 가동 재해복구는 전역 트래픽 분산과 데이터 정합성 제어를 결합해 복구 목표를 가장 짧게 맞추는 구조.
- 시사점 : 지연·충돌·세션 관리 비용이 함께 커지므로, 업무 중요도에 따라 선택적으로 도입하는 설계가 현실적인 선택.
