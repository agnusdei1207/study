## 연관 키워드

- 메모리 인터리빙, 메모리 뱅크, 하위 인터리빙, 상위 인터리빙, 뱅크 파이프라인, 버스트 전송
- 멀티채널, 뱅크 충돌, Stride, XOR 해시, 칩킬, 대칭 구성

## Ⅰ. 메모리 인터리빙의 개요

- 핵심 요약 : 주기억장치를 독립된 뱅크로 나누고 주소를 분산 배치하여 동시 접근으로 실질 대역폭을 높이는 하드웨어 기법.
- 개념 : DRAM(Dynamic Random-Access Memory)을 독립적으로 동작 가능한 다수의 **메모리 뱅크** (Memory Bank, 독립 접근이 가능한 메모리 모듈 단위)로 구성하고 연속 주소를 뱅크에 분산 배치하여 병렬 접근을 가능하게 하는 **메모리 인터리빙** (Memory Interleaving) 기법.
- 배경 및 필요성 : DRAM은 한 뱅크에서 행 활성화와 프리차지 사이에 대기 사이클이 생겨 연속 접근 시 처리 장치가 대기 → 여러 뱅크를 시간차로 구동하는 구조의 필요.
- 주요 목적 : 메모리 버스 대역폭의 실질 확대, 뱅크 대기 시간의 은폐, 처리 장치 요구량의 충족.

## Ⅱ. 메모리 인터리빙의 특징 및 장점

- 핵심 요약 : 뱅크 선택 비트의 위치와 뱅크 파이프라인, 버스트 전송의 결합이 병렬성과 대역폭 확장으로 이어지는 구조.

1. **하위 인터리빙** (Low-Order Interleaving) : 주소의 하위 비트로 뱅크를 선택해 연속 주소를 뱅크에 순환 배치 → 연속 접근의 병렬성 극대화.
2. **상위 인터리빙** (High-Order Interleaving) : 상위 비트로 뱅크를 선택해 연속 블록을 한 뱅크에 배치 → 뱅크 단위 장애의 격리와 모듈 단위 확장에 유리.
3. **뱅크 파이프라인** : 한 뱅크의 행 활성화·프리차지 동안 다른 뱅크에서 데이터 전송 → 접근 지연의 겹침 처리에 따른 유효 지연 은폐.
4. **버스트 전송** (Burst Transfer, 한 주소 지정으로 연속 데이터를 전송하는 방식)과의 결합 : 버스트의 각 데이터 조각을 서로 다른 뱅크에서 준비 → 연속 데이터 요구의 지연 단축.
5. **멀티채널** (Multi-channel) : 독립 채널의 동시 구동 → 채널 수에 비례하는 대역폭 확장.

## Ⅲ. 메모리 인터리빙의 구조 (흐름)

- 핵심 요약 : 주소의 하위 비트를 뱅크 선택자로 사용하는 배치와, 뱅크들이 시간차로 응답하는 파이프라인 전송이 핵심 동작.
- 배치 원리 : 하위 인터리빙에서 주소 하위 비트가 뱅크 번호를, 나머지 상위 비트가 뱅크 내 위치를 가리키므로 연속 주소가 자동으로 뱅크에 분산됨.

```text
[ 하위 인터리빙의 주소 분해 ]

주소 = 상위 비트 (뱅크 내 위치)
       + 하위 비트 (뱅크 선택)
   ↓
하위 비트 00 → 뱅크 0
하위 비트 01 → 뱅크 1
하위 비트 10 → 뱅크 2
하위 비트 11 → 뱅크 3
```

```text
[ 뱅크별 시간차 파이프라인 ]

클록 1  뱅크 0 : 주소 0 출력
   ↓
클록 2  뱅크 1 : 주소 1 출력
   ↓
클록 3  뱅크 2 : 주소 2 출력
   ↓
클록 4  뱅크 3 : 주소 3 출력
```

## Ⅳ. 하위 인터리빙과 상위 인터리빙의 비교

- 핵심 요약 : 하위 인터리빙은 연속 접근의 병렬성, 상위 인터리빙은 뱅크 격리에 강점이 있어 목적에 따라 선택·결합함.

| 비교 축 | 하위 인터리빙 | 상위 인터리빙 |
| --- | --- | --- |
| 뱅크 선택 비트 | 주소의 하위 비트 | 주소의 상위 비트 |
| 연속 주소 배치 | 인접 주소가 서로 다른 뱅크 | 인접 블록이 같은 뱅크 |
| 연속 접근 성능 | 병렬화로 우수 | 한 뱅크 집중으로 저하 |
| 뱅크 장애 영향 | 전체 매핑 붕괴로 광범위 | 장애 뱅크 구간으로 국소화 |
| 주 적용 영역 | 범용 CPU·GPU의 주기억장치 | 장애 격리 중심 구성 |

- 선택 기준 : 연속 접근 성능이 중요하면 하위 인터리빙, 부분 장애의 격리가 중요하면 상위 인터리빙을 기준으로 삼고, 대역폭은 멀티채널과 결합해 확보함.

## Ⅴ. 메모리 인터리빙의 한계와 방안

- 핵심 요약 : 뱅크 충돌, 뱅크 장애, 비대칭 모듈 구성을 주소 해시, 고급 오류 정정, 구성 규칙으로 일대일 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **뱅크 충돌** (Bank Conflict) | 접근 간격(Stride)이 뱅크 수의 배수 → 접근이 한 뱅크에 집중되어 직렬화 | **XOR 해시** (XOR Hashing, 주소 비트를 조합해 뱅크를 배정하는 방식) 적용, 뱅크 수의 소수 구성, 루프 패딩 | 뱅크별 접근 편중도, 뱅크 대기 사이클 |
| 뱅크·칩 장애 | 하위 인터리빙에서 칩 하나의 고장이 연속 주소 전반의 영향으로 확대 | **칩킬** (Chipkill, 칩 단위 다중 비트 오류를 정정하는 기술)을 지원하는 ECC(Error-Correcting Code, 오류 정정 코드) 메모리 컨트롤러 채택 | 정정 가능 오류 건수 |
| 비대칭 모듈 구성 | 용량·속도가 다른 모듈의 혼용 → 멀티채널 동작 해제 | 채널별 **대칭 구성** (동일 용량·속도 모듈의 균등 장착) 규칙 준수 | 채널 구성 상태, 측정 대역폭 |

## Ⅵ. 메모리 인터리빙에 대한 기술사적 제언

- 핵심 요약 : 채널 대칭 설계, 접근 패턴 지침, 구성 검증의 세 축으로 메모리 병렬성을 하드웨어 구성과 소프트웨어 설계 양쪽에서 확보.

1. 인프라 설계 조직 : 서버 증설 계획을 채널 단위 대칭 구성으로 표준화하고 장비 규격서에 반영하는 절차가 바람직함.
2. 개발 조직 : 성능 민감 모듈의 배열 접근 패턴 점검 지침을 알고리즘 설계 기준에 포함하여 뱅크 충돌을 소프트웨어 단계에서 줄이는 방안이 필요함.
3. 검증 조직 : 도입 시점의 메모리 대역폭 벤치마크를 검수 항목으로 두어 설계 대역폭의 실현 여부를 확인하는 체계가 유효함.

## Ⅶ. 결론

- 핵심 요약 : 메모리 인터리빙은 뱅크 분산 배치로 병렬 접근을 실현해 대역폭을 높이는 하드웨어 기반 기법.
- 대역폭은 뱅크 구성과 접근 패턴이 일치할 때 실현되므로 양측의 설계 검토가 성능의 조건임.
