```text
 ┃
 ┣━ Ⅰ 개요 ───── 단일 GPU VRAM 용량 및 연산 능력 한계 극복 → 복수의 GPU에 모델 파라미터와 데이터를 분할하여 초거대 AI 신경망을 병렬 학습
 ┣━ Ⅱ 특징 ───── 데이터 병렬화(DP/DDP) · 모델 병렬화(텐서/파이프라인) · 제로 중복 최적화(ZeRO/FSDP) · 통신-연산 중첩(Overlapping)
 ┣━ Ⅲ 구조 ───── 데이터 분할(Data Split) + 텐서 병렬화(Megatron-LM) + 파이프라인 병렬화(GPipe) + 집단 통신(All-Reduce/All-Gather)
 ┣━ Ⅳ 흐름 ───── ① 순전파(Forward: 마이크로배치) → ② 역전파(Backward: 그래디언트 계산) → ③ 올리듀스(All-Reduce) 동기화 → ④ 옵티마이저 가중치 갱신
 ┣━ Ⅴ 비교 ───── 데이터 병렬화(DDP) vs 텐서 병렬화(TP) vs 파이프라인 병렬화(PP) vs FSDP(Fully Sharded)
 ┗━ Ⅵ 실무 ───── 파이프라인 버블(Bubble)로 인한 GPU 유휴 / 통신 오버헤드로 인한 확장비(Scaling Efficiency) 저하 / 그래디언트 폭발 및 발산
```

## 한 줄 본질
- 수백억 파라미터 모델 가중치와 옵티마이저 상태가 테라바이트급 메모리를 요구하여 단일 기기 학습이 불가함 → 배치 데이터를 쪼개거나(DP) 모델 레이어를 가로/세로로 쪼개어(TP/PP) 수천 대의 GPU에 분산 실행 후 그래디언트를 동기화 → 초대형 AI 모델 학습 실현 / GPU 간 All-Reduce 통신 병목과 파이프라인 버블 발생

## 핵심 그림
```text
[ 멀티 GPU 분산학습의 3대 병렬화 기법 개념 비교 ]

1. 데이터 병렬화 (Data Parallelism: DDP)
   - 모델 전체를 각 GPU에 복제, 배치 데이터만 분할 입력
   [ Data Batch 1 ] ──> [ GPU 0 (전체 모델) ] ──┐ (All-Reduce 그래디언트 동기화)
   [ Data Batch 2 ] ──> [ GPU 1 (전체 모델) ] ──┴──> 모든 GPU 동일 가중치 갱신

2. 텐서 병렬화 (Tensor Parallelism: TP / intra-layer)
   - 단일 레이어의 거대 행렬 곱셈을 쪼개어 동시 계산
   [ Input X ] ──> [ GPU 0: 가중치 W의 앞쪽 절반 ] ──┐ (All-Gather / Reduce-Scatter)
               ──> [ GPU 1: 가중치 W의 뒤쪽 절반 ] ──┴──> [ 레이어 최종 출력 ]

3. 파이프라인 병렬화 (Pipeline Parallelism: PP / inter-layer)
   - 모델의 연속된 레이어들을 GPU별로 순차 배치
   [ Input ] ──> [ GPU 0: 레이어 1~8 ] ──> [ GPU 1: 레이어 9~16 ] ──> [ Loss 계산 ]
```

## 핵심 용어
- ZeRO(Zero Redundancy Optimizer): 데이터 병렬화 환경에서 모든 GPU가 동일하게 들고 있던 옵티마이저 상태(ZeRO-1), 그래디언트(ZeRO-2), 파라미터(ZeRO-3)를 샤딩하여 메모리 낭비를 제로화하는 딥스피드(DeepSpeed) 기술
- FSDP(Fully Sharded Data Parallel): 파이토치(PyTorch) 표준에 내장된 ZeRO-3 스타일의 분산 학습 프레임워크로, 순전파/역전파에 필요한 순간에만 파라미터를 All-Gather로 모으고 즉시 해제
- 3D 병렬화(3D Parallelism): 초거대 모델 학습을 위해 데이터 병렬화(DP), 텐서 병렬화(TP), 파이프라인 병렬화(PP)를 격자 형태로 동시에 융합 적용하는 아키텍처

## 핵심 통찰
- 모델 크기별로 병렬화 선택이 달라짐 → 모델이 단일 GPU 메모리에 들어가면 DDP가 통신 비용 대비 가장 효율적이지만, 모델이 100B를 넘어가면 노드 내부는 초고속 NVLink로 텐서 병렬화(TP)를 묶고 노드 간은 파이프라인 병렬화(PP)와 DP/ZeRO를 조합해야 함
- 텐서 병렬화는 통신 빈도가 극도로 높음 → 행렬 연산마다 All-Reduce가 발생하므로 대역폭이 900GB/s 이상인 동일 서버 내 NVLink 환경에서만 구동해야 하며, 일반 네트워크를 통과하면 극심한 통신 지연에 빠짐
- 파이프라인 병렬화의 최대 적은 '버블(Bubble)'임 → 앞선 GPU의 계산이 끝나야 뒤쪽 GPU가 일을 시작하므로 유휴 시간이 발생하며, 이를 줄이기 위해 입력을 수십 개의 마이크로배치(Micro-batch)로 쪼개어 1F1B(One-Forward-One-Backward) 스케줄링으로 채워야 함

## 이웃 토픽과 구분
- DDP vs FSDP: DDP = 모든 GPU가 모델 파라미터를 통째로 중복 보관, 학습 속도 빠름 / FSDP = 파라미터와 옵티마이저를 GPU들에 1/N로 분할 보관하여 메모리 75% 절감, 통신 비용 약간 증가

## 문제·원인·대책
- 사례: 134회 기출 및 70B LLM 분산학습 중 GPU 메모리 OOM(Out of Memory) 및 통신 정체로 인한 학습 정지
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| Adam 옵티마이저 상태 메모리 폭증으로 파라미터 적재 직후 OOM 발생 | 옵티마이저가 모델 파라미터의 8~16배 메모리를 요구하여 발생 | ZeRO-Stage 3 / PyTorch FSDP 도입을 통한 파라미터 샤딩 | GPU당 메모리 사용량 70% 감소로 거대 모델 학습 가능 |
| 파이프라인 병렬화 구간에서 GPU 절반이 대기 상태로 머무는 버블 발생 | 배치 단위 순차 파이프라인 대기 시간 누적 | 1F1B 인터리브드 파이프라인 스케줄링 및 마이크로배치 증설 | 파이프라인 버블 비율을 10% 미만으로 억제하여 하드웨어 활용률 극대화 |
