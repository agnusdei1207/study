## 30초 인출

- 본질: **TPU (Tensor Processing Unit)** 는 머신러닝의 행렬 연산을 가속하도록 설계된 전용 칩
- 메커니즘: **XLA (Accelerated Linear Algebra)** 컴파일 → **MXU (Matrix Multiplication Unit)** 시스톨릭 배열의 곱셈·누산
- 통찰: 구글이 딥러닝 텐서 연산 가속을 위해 설계한 전용 ASIC으로, 대규모 2D 시스톨릭 어레이와 커스텀 bfloat16 포맷을 통해 초고효율 행렬 곱셈을 수행 가속화.

<details>
<summary>핵심 용어</summary>

- **TPU (Tensor Processing Unit)** : Google이 머신러닝 연산을 가속하기 위해 설계한 ASIC (Application-Specific Integrated Circuit)
- **MXU (Matrix Multiplication Unit)** : TPU에서 행렬 곱셈·누산을 수행하는 연산 장치
- **시스톨릭 배열** : 이웃 연산기 사이로 데이터와 부분합을 전달해 행렬 연산에 재사용하는 구조
- **XLA (Accelerated Linear Algebra)** : 모델 연산 그래프를 TPU 실행 코드로 컴파일하는 컴파일러 도구
- **HBM (High Bandwidth Memory)** : 가속기 가까이 배치해 높은 대역폭으로 데이터를 공급하는 메모리
- **GPU (Graphics Processing Unit)** : 그래픽·범용 병렬 연산을 수행하는 프로세서
- **bfloat16 (Brain Floating Point 16)** : 16비트 중 지수부를 넓게 두어 부동소수점 범위를 확보하는 수 표현 형식

</details>

## 2~4교시 25점 답안

## Ⅰ. TPU의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **TPU (Tensor Processing Unit)** 는 머신러닝의 행렬 연산을 가속하도록 설계된 전용 칩 |
| 목적 | 적합한 모델의 행렬 연산 처리량 향상 |

## Ⅱ. TPU의 특징

| 특징 | 의미 |
|---|---|
| 행렬 연산 특화 | MXU의 곱셈·누산 배열에 적합한 텐서 작업 가속 |
| 컴파일 실행 | XLA의 그래프·형상 최적화가 성능에 영향 |
| 데이터 공급 의존 | HBM·입력 파이프라인이 연산기 활용률 좌우 |

## Ⅲ. XLA와 MXU 중심의 실행 구조

```text
모델 그래프 → XLA(융합·배치) → TPU 실행
                                  │
HBM의 입력·가중치 ──────────────→ MXU 배열
                                  │ 이웃 연산기 간 재사용·누산
                                  └→ 결과 메모리
```

MXU 배열 크기와 칩 구성의 세대별 차이. 특정 세대의 수치를 TPU 전체의 고정 구조로 일반화하지 않음.

### 시스톨릭 배열의 작동과 제약

| 관점 | 핵심 |
|---|---|
| 데이터 이동 | 인접 연산기 사이로 입력과 부분합을 전달해 재사용 |
| 계산 | 다수 곱셈·누산을 행렬 형태로 병렬 수행 |
| 활용률 | 작은 행렬이나 비행렬 연산이 많으면 MXU 활용률이 낮아질 수 있음 |
| 컴파일 | 텐서 형상이 자주 바뀌면 재컴파일·패딩 비용을 확인해야 함 |

```text
입력 텐서 형상 변화
   ├─ 기존 컴파일 형상 활용 → MXU 실행
   └─ 새 형상 → 재컴파일·패딩 가능 → 실행 지연 증가
                  ↓ 입력 길이 구간화의 비용·효과 비교
```

## Ⅳ. TPU와 GPU의 적용 비교

| 기준 | TPU | **GPU (Graphics Processing Unit)** |
|---|---|---|
| 강점 | 큰 행렬 연산과 XLA 최적화 | 다양한 병렬 연산·도구 생태계 |
| 적용 판단 | 모델의 행렬 비중·텐서 형상·지원 프레임워크 확인 | 연산 다양성·개발 도구·배포 환경 확인 |
| 주의점 | 컴파일·데이터 공급 병목 확인 | 커널·메모리 이동 병목 확인 |

장치 이름만으로 처리량이나 비용 우위를 단정하기 어려운 한계. 실제 모델·배치·입력 크기를 이용한 비교.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 텐서 형상이 계속 바뀌어 컴파일 비용 증가 | 입력 길이를 적절한 구간으로 묶고 재컴파일 횟수와 패딩 비용을 함께 측정 |
| 데이터 공급이 느려 MXU가 쉬는 시간 증가 | 입력 파이프라인을 프로파일링해 읽기·전처리 병목을 줄임 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
시스톨릭 어레이의 데이터 재사용성을 극대화하기 위해 배치 크기를 정수 배로 정렬하고, XLA 컴파일러를 통한 연산자 융합(Operator Fusion)과 ICI(Inter-Core Interconnect) 광 토러스 패브릭 구성.

### 2. 아키텍처 및 상세 메커니즘
```text
[ 호스트 CPU (명령 전달) ] ──(PCIe / CXL)──> [ TPU 가속기 칩 (ASIC) ]
                                                   │
┌──────────────────────────────────────────────────┴─────────────────────────────────────┐
│ [ TPU v4 / v5p 코어 아키텍처 ]                                                         │
│                                                                                        │
│   ┌───────────────────────────┐     ┌──────────────────────────────────────────────┐   │
│   │ 초고대역폭 HBM3 메모리    │<───>│ 2차원 시스톨릭 어레이 (128x128 MXU)          │   │
│   │ (가중치 및 데이터 공급)   │     │  - 레지스터 파일 간 직접 데이터 전달(재사용) │   │
│   └───────────────────────────┘     │  - 메모리 읽기/쓰기 대역폭 병목 원천 제거    │   │
│                                     └──────────────────────┬───────────────────────┘   │
│                                                            │                           │
│   ┌────────────────────────────────────────────────────────▼───────────────────────┐   │
│   │ 벡터 처리 유닛 (VPU) : 활성화 함수(ReLU, GeLU) 및 소프트맥스/정규화 전용 가속 │   │
│   └────────────────────────────────────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────┬─────────────────────────────────────┘
                                                   │
  [ 광학 회선 교환기 (OCS: Optical Circuit Switch) 토러스 패브릭 (수천 칩 초대형 포드) ]
```

### 3. 기술 유형 및 비교 평가
| TPU 세대 | 연산 성능 (TFLOPS) | 메모리 사양 | 인터커넥트 패브릭 | 주요 특징 및 타깃 워크로드 |
|---|---|---|---|---|
| **TPU v1** | 92 TOPS (INT8) | 8GB DDR3 (34 GB/s) | PCIe Gen3 | 순수 데이터센터 추론 가속 전용 |
| **TPU v3** | 420 TFLOPS (bfloat16) | 32GB HBM2 (900 GB/s)| 2D 토러스 (수랭식 쿨링) | 딥러닝 대규모 모델 분산 학습 |
| **TPU v4** | 275 TFLOPS (bfloat16) | 32GB HBM2e (1.2 TB/s)| 3D 토러스 (OCS 광스위치) | 초대형 언어모델(LLM) 학습 포드 |
| **TPU v5p** | 459 TFLOPS (bfloat16) | 95GB HBM3 (2.7 TB/s)| ICI 4,800Gbps 3D 토러스 | 차세대 파운데이션 모델 초거대 포드 |
