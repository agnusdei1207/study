## 30초 인출

- 본질: 범용 부동소수점(FP32/FP64) 코어와 그래픽스 파이프라인을 유지하는 GPU의 실리콘 면적 및 전력 비효율
- 메커니즘: 딥러닝의 핵심인 대규모 행렬 곱셈을 2D 시스톨릭 어레이(MXU) 회로에 고정하고 전용 컴파일러(XLA)로 제어하는 도메인 특화 ASIC

## 핵심 용어

- MXU(Matrix Multiply Unit): 128x128 크기의 2차원 시스톨릭 어레이로, 데이터를 메모리에서 반복해서 읽지 않고 인접 연산기로 직접 넘겨 전력과 지연시간을 획기적으로 줄인 TPU의 핵심 연산기
- Bfloat16(Brain Floating Point 16): FP32와 동일한 8비트 지수부(Exponent)를 유지하여 넓은 동적 범위를 보장하면서, 가수부(Mantissa)를 7비트로 줄여 메모리 대역폭을 절반으로 줄인 AI 특화 데이터 포맷
- XLA(Accelerated Linear Algebra): 텐서플로/파이토치 연산 그래프를 분석하여 텐서 크기와 연산 순서를 TPU 하드웨어에 완벽히 정렬된 기계어로 사전 컴파일(AOT)하는 도메인 특화 컴파일러

## 1교시 10점 답안

### 정의·목적

- 정의: TPU은/는 딥러닝의 핵심인 대규모 행렬 곱셈을 2D 시스톨릭 어레이(MXU) 회로에 고정하고 전용 컴파일러(XLA)로 제어하는 도메인 특화 ASIC 방식이다.
- 목적: 초고밀도 연산 처리량과 와트당 가성비 극대화에 기여한다.

### 핵심 구조와 작동

```text
[ XLA 컴파일러 (고정 그래프 최적화) ] ──> [ TPU v4/v5 Core ]
                                                  │
+─────────────────────────────────────────────────┼───────────────────────────────+
|                         TPU 코어 아키텍처        │                               |
|                                                 v                               |
|  +---------------------------------------------------------------------------+  |
|  |             Matrix Multiply Unit (MXU: 128x128 Systolic Array)            |  |
|  |  - 가중치를 레지스터에 정적 유지                                          |  |
|  |  - 활성화 데이터를 좌측에서 우측으로, 부분합을 위에서 아래로 흐르게 연산   |  |
|  |  - 클록당 16,384개의 곱셈-누적(MAC) 수행                                  |  |
|  +---------------------------------------------------------------------------+  |
|                                       │                                         |
|  +------------------------------------v--------------------------------------+  |
|  |  Vector Processing Unit (VPU: 활성화 함수, 정규화, 소프트맥스 연산)        |  |
|  +------------------------------------+--------------------------------------+  |
|                                       │                                         |
|  +------------------------------------v--------------------------------------+  |
|  |  고대역폭 메모리 (HBM) & 인터코어 인터커넥트 (ICI: 4.8Tbps 3D 토러스 망)   |  |
|  +---------------------------------------------------------------------------+  |
+─────────────────────────────────────────────────────────────────────────────────+
```

## 2~4교시 25점 답안

### Ⅰ. 핵심 구조와 작동

```text
[ XLA 컴파일러 (고정 그래프 최적화) ] ──> [ TPU v4/v5 Core ]
                                                  │
+─────────────────────────────────────────────────┼───────────────────────────────+
|                         TPU 코어 아키텍처        │                               |
|                                                 v                               |
|  +---------------------------------------------------------------------------+  |
|  |             Matrix Multiply Unit (MXU: 128x128 Systolic Array)            |  |
|  |  - 가중치를 레지스터에 정적 유지                                          |  |
|  |  - 활성화 데이터를 좌측에서 우측으로, 부분합을 위에서 아래로 흐르게 연산   |  |
|  |  - 클록당 16,384개의 곱셈-누적(MAC) 수행                                  |  |
|  +---------------------------------------------------------------------------+  |
|                                       │                                         |
|  +------------------------------------v--------------------------------------+  |
|  |  Vector Processing Unit (VPU: 활성화 함수, 정규화, 소프트맥스 연산)        |  |
|  +------------------------------------+--------------------------------------+  |
|                                       │                                         |
|  +------------------------------------v--------------------------------------+  |
|  |  고대역폭 메모리 (HBM) & 인터코어 인터커넥트 (ICI: 4.8Tbps 3D 토러스 망)   |  |
|  +---------------------------------------------------------------------------+  |
+─────────────────────────────────────────────────────────────────────────────────+
```

### Ⅱ. 핵심 특성

- GPU는 유연한 SIMT 스레드 프로그래밍이 장점이지만 명령어 디코더와 캐시 관리에 많은 트랜지스터를 낭비함 → TPU는 캐시와 분기 예측기를 전면 배제하고 트랜지스터의 대부분을 순수 행렬 연산기(MXU)에 쏟아부음
- TPU 대규모 확장의 핵심은 '광 회선 스위치(OCS: Optical Circuit Switch)'임 → 전자 스위치 없이 거울(MEMS Mirror)을 움직여 빛 파장 자체를 재지향함으로써 수천 개 TPU를 토폴로지 변경 가능한 3D 토러스 망으로 직접 연결
- 정적 그래프 연산에 극도로 최적화되어 있으므로 파이썬 동적 제어문(`if/while`)이 잦은 모델에서는 CPU-TPU 간 빈번한 동기화로 성능이 급락하므로 고정 텐서 크기 패딩(Padding)이 강제됨

### Ⅲ. 관련 개념과 구분

- TPU vs GPU: TPU = 고정 행렬곱에 특화된 시스톨릭 ASIC (구글 GCP 전용, Bfloat16 개척) / GPU = CUDA를 통한 범용 프로그래밍이 가능한 사실상 업계 표준 가속기 (NVIDIA 독점 생태계)

### Ⅳ. 적용 문제와 대응

- 사례: 138회 기출 PyTorch 기반 대규모 LLM을 TPU 팟에서 학습 시 속도 저하 및 컴파일 지연
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 배치마다 텐서 크기가 가변적일 때 XLA 재컴파일(Re-compilation) 루프로 인한 정체 | 고정 텐서 형태를 요구하는 XLA 컴파일러 특성 미준수 | 최대 시퀀스 길이 기준 정적 버킷팅(Bucketing) 및 패딩(Padding) 강제 | 그래프 재컴파일 방지 및 연속 처리량 달성 |
| 수천 개 TPU 클러스터 학습 중 단일 칩 고장으로 전체 학습 중단 | 대규모 분산 팟(Pod) 환경의 칩 고장 빈도 증가 | OCS(광 회선 스위치) 기반 불량 칩 동적 바이패스 및 3D 토러스 재구성 | 팟 전체 재기동 없는 무중단 연속 학습 보장 |
