## 연관 키워드

- TPU(Tensor Processing Unit), ASIC, 텐서(Tensor), 시스톨릭 어레이(Systolic Array)
- MXU, MAC(Multiply-Accumulate), BF16, HBM, ICI, OCS, Pod, 3D 토러스
- XLA, JAX, TCO, 클라우드 종속(Lock-in), 온프레미스 제약

## Ⅰ. TPU의 개요

- 핵심 요약 : 딥러닝 행렬 연산 전용으로 설계된 ASIC 기반 AI 가속 프로세서.
- 개념 : 신경망의 기본 데이터 구조인 **텐서** (Tensor, 다차원 배열) 연산에 최적화되도록 구글이 개발한 **ASIC** (Application-Specific Integrated Circuit, 특정 용도 전용 집적회로) 형태의 **TPU** (Tensor Processing Unit, 텐서 처리 장치).
- 배경 및 필요성 : 대규모 언어 모델 시대의 행렬 곱 연산량이 폭증하는 가운데, 범용 GPU의 그래픽 설계 유산과 특정 소프트웨어 생태계 의존을 벗어난 자체 최적화 인프라 필요성이 커진 배경.
- 주요 목적 : 행렬 곱·누산 연산의 전력 효율 극대화, 수천 개 칩 규모 클러스터로의 확장성 확보, 학습·추론 파이프라인 처리 시간의 단축.

## Ⅱ. TPU의 특징 및 장점

- 핵심 요약 : 시스톨릭 어레이, 저정밀 산술, 칩 간 전용 연결, 광 스위치가 전력 효율과 확장성으로 연결되는 구조.

1. **시스톨릭 어레이** (Systolic Array, 데이터가 셀 사이를 박동처럼 흐르는 연산 배열) : 행렬 데이터를 셀 단위로 밀어내며 곱셈을 연쇄 수행 → 메모리 왕복 없는 연속 계산으로 전력 효율 향상.
2. **MXU** (Matrix Multiply Unit, 행렬 곱 유닛) : 2차원 배열에서 **MAC** (Multiply-Accumulate, 곱셈·누산) 연산을 대량 병렬 수행 → 전력당 행렬 처리량 확보.
3. **BF16** (Brain Floating Point 16, 16비트 부동소수점 형식) : 지수부 폭을 유지한 저정밀 표현 → 학습 안정성 유지와 메모리·연산량 절감.
4. **ICI** (Inter-Chip Interconnect, 칩 간 전용 연결망) : 범용 네트워크 계층을 거치지 않는 직결 링크 → 칩 간 통신 지연·전력의 최소화.
5. **OCS** (Optical Circuit Switch, 광 회로 스위치) : 광 스위치로 칩 연결 위상을 소프트웨어 재구성 → 장애 칩 우회와 작업별 맞춤 토폴로지 제공.

## Ⅲ. TPU의 구조 (흐름)

- 핵심 요약 : 칩 내부의 MXU·HBM 구성이 전용 연결망과 격자 위상으로 묶여 Pod 단위 확장으로 이어지는 계층 구조.
- **HBM** (High Bandwidth Memory, 고대역폭 메모리) : 행렬 피연산자를 MXU에 연속 공급하는 칩 인접 저장 계층.
- **3D 토러스** (3D Torus, 축 방향 이웃과 맞닿는 격자 위상) : 한 방향 링크 고장 시에도 이웃 경로의 우회를 가능하게 하는 연결 구조.
- **XLA** (Accelerated Linear Algebra, 선형대수 가속 컴파일러) : 모델 연산 그래프를 TPU 명령으로 변환하는 소프트웨어 계층.

```text
[ TPU 칩 구성 ]

HBM (고대역폭 메모리)
        ↓
벡터 유닛 · 스칼라 유닛
        ↓
MXU (시스톨릭 어레이)
```

```text
[ 클러스터 확장 구조 ]

칩 : MXU + HBM
        ↓
직결 연결 : ICI 링크
        ↓
위상 : 3D 토러스 격자
        ↓
Pod : OCS로 재구성되는 대규모 묶음
        ↓
작업 단위 가용 슬라이스 할당
```

## Ⅳ. TPU의 비교

- 핵심 요약 : TPU·GPU·CPU가 연산 유닛, 확장 방식, 소프트웨어 계층에서 전문화 수준이 다른 구조.

| 비교 항목 | TPU | GPU | 범용 CPU(Central Processing Unit) |
| --- | --- | --- | --- |
| 하드웨어 성격 | 텐서 연산 전용 ASIC | 범용 병렬 가속기 | 순차·제어 중심 프로세서 |
| 핵심 연산 유닛 | 시스톨릭 어레이 (MXU) | 다수 범용 코어와 텐서 코어 | 복잡 명령 범용 코어 |
| 확장 방식 | ICI·3D 토러스·OCS 기반 Pod | 노드 간 고속망 클러스터 | 범용 네트워크 클러스터 |
| 소프트웨어 계층 | XLA 컴파일 경로 중심 | CUDA(Compute Unified Device Architecture) 등 광범위 생태계 | 표준 컴파일러·라이브러리 |
| 도입 형태 | 클라우드 임대 중심 | 온프레미스·클라우드 모두 | 보편적 도입 |

- 선택 기준 : 워크로드의 모델 고정성, 필요 규모, 이식성 요구, 조달 방식을 함께 평가해 가속기를 선정하는 절차 필요.

## Ⅴ. TPU의 한계와 방안

- 핵심 요약 : 클라우드 종속, 컴파일러 의존, 대규모 장애 파급을 이식성 확보, 연산자 표준화, 광 우회로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **클라우드 종속** (Lock-in, 특정 사업자 인프라의 고착) | 특정 클라우드 임대 중심 제공으로 이전·하이브리드 구성 제약 | JAX, PyTorch/XLA 같은 공통 프레임워크로 이기종 전환 가능성 유지 | 이기종 재실행 성공률 |
| 컴파일러 병목 | 커스텀 연산자가 최적화 대상에서 벗어나 전송 병목 유발 | 표준 연산자 중심 재작성, 프로파일링 기반 병목 제거 | 호스트-장치 전송 비율 |
| Pod 단위 장애 파급 | 대규모 학습 작업이 단일 링크·칩 고장에 일제 중단 위험 | OCS 우회와 슬라이스 자동 재할당, 주기적 체크포인트 저장 | 복구 소요 시간 |

## Ⅵ. TPU에 대한 기술사적 제언

- 핵심 요약 : 이식성 검증, 구간별 비용 최적화, 인터커넥트 로드맵 추적을 AI 인프라 전략으로 내재화하는 방향.
- AI 개발 조직은 대규모 분산 학습 코드를 이기종 가속기에서 정기 검증해 종속 위험을 낮추는 이식성 기준 운영 필요.
- 인프라 재무 조직은 학습과 추론 구간별로 **TCO** (Total Cost of Ownership, 총소유비용)를 산정하고 구간별 최적 가속기를 배치하는 절차 수립 필요.
- 인프라 엔지니어링 조직은 광 스위치·직결망 기술의 발전 로드맵을 추적해 차기 클러스터 설계에 반영하는 절차 마련 필요.

## Ⅶ. 결론

- 핵심 요약 : TPU는 텐서 연산 전문화로 전력 효율과 대규모 확장성을 얻는 ASIC 기반 가속기.
- 칩 성능만큼 이식성과 장애 복원력이 도입 가치를 결정하는 평가 변수로 작동하는 시사점.
