## 연관 키워드

- TPU(Tensor Processing Unit), ASIC, 텐서(Tensor), 시스톨릭 어레이(Systolic Array), Pod
- MXU, BF16, ICI, OCS, 3D 토러스(3D Torus), VPU
- XLA, JAX, GCP(Google Cloud Platform), TCO, 클라우드 종속(Lock-in)

## Ⅰ. TPU(Tensor Processing Unit)의 개요

- 핵심 요약 : 딥러닝 텐서 연산을 가속하도록 설계된 ASIC 기반 AI 전용 프로세서로, 시스톨릭 어레이와 전용 칩 간 연결망이 핵심인 구조.
- 개념 : 구글이 대규모 딥러닝 **텐서** (Tensor, 다차원 배열 데이터) 연산과 신경망 학습·추론을 가속하기 위해 독자 개발한 **ASIC** (Application-Specific Integrated Circuit, 특정 용도 집적회로) 기반의 AI 전용 프로세서인 **TPU** (Tensor Processing Unit, 텐서 처리 장치).
- 배경 및 필요성 : 범용 GPU의 그래픽 설계 유산과 특정 소프트웨어 생태계에 대한 의존을 줄이고, 초대형 언어 모델과 추천 시스템의 연산을 자체 클라우드 인프라에서 효율적으로 처리할 필요가 커져 등장함.
- 핵심 목적 : 행렬 곱을 대량으로 처리하는 **시스톨릭 어레이** (Systolic Array, 데이터가 인접 연산 셀을 박동하듯 통과하는 배열 구조) 기반 연산 극대화, 전용 칩 간 연결과 광 스위치로 수천 칩 규모의 **Pod** (칩 묶음으로 구성된 대규모 클러스터 단위) 확장성 확보.

## Ⅱ. TPU(Tensor Processing Unit)의 특징 및 장점

- 핵심 요약 : 행렬 연산 유닛, 저정밀 표현, 전용 칩 간 연결, 광 회로 스위치가 결합되어 대규모 텐서 연산의 전력 효율과 확장성을 높이는 구조.

1. **MXU** (Matrix Multiply Unit, 행렬 곱 유닛) : 2차원 시스톨릭 어레이에서 곱셈-누적(MAC, Multiply-Accumulate) 연산을 대량으로 병렬 처리 → 전력당 행렬 연산 처리량 확보.
2. **BF16** (Brain Floating Point 16, 16비트 부동소수점) : FP32와 같은 지수부 비트 수를 유지해 FP16보다 넓은 값 범위를 확보 → 학습 중 오버플로와 언더플로 위험 감소.
3. **ICI** (Inter-Chip Interconnect, 칩 간 전용 연결망) : 칩 사이를 범용 네트워크 프로토콜 계층을 거치지 않고 직접 잇는 고속 링크 → 칩 간 통신 지연 최소화.
4. **OCS** (Optical Circuit Switch, 광 회로 스위치) : 광 스위치로 Pod 내부 토폴로지를 소프트웨어 방식으로 재구성 → 장애 칩 격리와 작업별 맞춤 연결 제공.

## Ⅲ. TPU(Tensor Processing Unit)의 구조 및 동작 메커니즘

- 핵심 요약 : 칩 내부의 MXU, VPU, 스칼라 유닛과 HBM이 한 칩을 이루고, ICI와 OCS가 칩들을 3차원 격자 형태로 묶는 계층 구조.
- 칩 내부 구성요소는 행렬 곱을 맡는 MXU, 활성화 함수와 요소별 연산을 맡는 VPU, 제어와 주소 계산을 맡는 스칼라 유닛으로 나뉨.
- **3D 토러스** (3D Torus, 각 칩이 격자의 축 방향 이웃과 연결되는 위상 구조) : Pod 내 칩 연결의 기본 형태로, 특정 방향 링크가 끊겨도 우회 경로를 찾을 수 있는 기반이 됨.

```text
[ TPU 칩 구성 ]

MXU · VPU · 스칼라 유닛 (칩 내부)
        ↕
HBM (고대역폭 메모리)
        ↕
ICI (칩 간 전용 연결)
```

```text
[ Pod 연결 구조 ]

칩 단위 : MXU와 HBM 결합
        ↓
칩 간 : ICI 기반 3D 토러스
        ↓
Pod 단위 : OCS 광 스위치로 재구성
        ↓
작업별 가용 슬라이스 할당
```

## Ⅳ. TPU(Tensor Processing Unit)의 비교

- 핵심 요약 : TPU, GPU, 범용 서버 CPU가 하드웨어 유형과 인터커넥트, 소프트웨어 툴체인에서 서로 다른 전문성을 갖는 구조.

| 비교 항목 | Google TPU | NVIDIA GPU | 범용 서버 CPU |
| --- | --- | --- | --- |
| 하드웨어 유형 | 딥러닝 텐서 전용 ASIC | 대규모 병렬 GPGPU 가속기 | 범용 마이크로프로세서 |
| 주요 연산 코어 | 대규모 시스톨릭 어레이 (MXU) | 스트리밍 멀티프로세서와 텐서 코어 | 벡터 명령어 기반 범용 코어 |
| 인터커넥트 | 전용 ICI와 OCS, 3D 토러스 | NVLink 등 고속 GPU 연결과 노드 간 고속망 | PCIe(Peripheral Component Interconnect Express) 등 범용 연결 |
| 확장 단위 | 3D 토러스 기반 Pod 단위 | 노드 간 고속망으로 묶은 대규모 클러스터 | 범용 네트워크 기반 노드 클러스터 |
| 소프트웨어 툴체인 | **XLA** (Accelerated Linear Algebra, 선형대수 가속 컴파일러) | CUDA, TensorRT, Triton | 표준 C/C++, OpenMP |

- 선택 기준 : TPU는 구글 클라우드 중심으로 제공되어 온프레미스 도입 선택지가 제한적이므로, 클라우드 종속 허용 범위와 이식성 요구를 함께 따져 채택해야 함.

## Ⅴ. TPU(Tensor Processing Unit)의 한계와 방안

- 핵심 요약 : 클라우드 종속(Lock-in), 컴파일러 병목, Pod 단위 장애 파급을 공통 프레임워크, 연산자 표준화, 광 스위치 우회로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **GCP** (Google Cloud Platform, 구글 클라우드 플랫폼) 종속 | 구글 클라우드에서만 임대할 수 있어 하이브리드 인프라 구축이 제약됨 | JAX, PyTorch/XLA 같은 공통 프레임워크로 작성해 GPU와 TPU 간 전환성 유지 | 이기종 재실행 성공률 |
| XLA 컴파일러 병목 | 최적화되지 않은 커스텀 연산자가 호스트와 TPU 사이의 잦은 텐서 복사를 유발 | 벡터화된 표준 연산자로 재작성해 융합(Fusion)이 가능하게 하고, 컴파일러 프로파일링 수행 | 호스트-장치 간 데이터 전송 시간 비율 |
| Pod 단위 장애 파급 | 3D 토러스에서 한 링크나 칩 장애가 대규모 학습 파이프라인 전체를 멈출 위험 | OCS로 불량 칩을 우회하고 가용 슬라이스로 자동 재배치 | 장애 후 복구 소요 시간, 학습 재시작 횟수 |

## Ⅵ. TPU(Tensor Processing Unit)에 대한 기술사적 제언

- 핵심 요약 : 프레임워크 이식성, 학습과 추론의 비용 분리, 광 인터커넥트 추적을 묶어 특정 가속기에 묶이지 않는 AI 인프라 역량을 확보.
- AI 조직은 학습과 추론 인프라를 가속기별로 나누어 **TCO** (Total Cost of Ownership, 총소유비용)를 구간별로 최적화하는 편이 바람직하다. 학습은 대규모 Pod에, 추론은 비용 효율이 높은 가속기에 두는 식이다.
- 모델 개발 조직은 JAX와 Flax 같은 프레임워크로 병렬화 역량을 내재화하고, 대규모 분산 학습 코드를 이기종 가속기에서도 검증해 특정 클라우드에 묶이지 않도록 해야 한다.
- 광 네트워킹 기술은 인터커넥트 병목의 위치를 바꾸므로, 인프라 조직은 OCS와 광 연결 기술의 로드맵을 주기적으로 추적해 차세대 Pod 설계에 반영해야 한다.

## Ⅶ. 결론

- 핵심 요약 : TPU는 ASIC 기반 텐서 가속기로서 MXU, BF16, ICI, OCS가 강점이며, 클라우드 종속과 컴파일러 병목 관리가 필수.
- 시사점 : 칩 성능보다 소프트웨어 이식성과 Pod 단위 장애 대응 능력이 실제 가치를 좌우하므로, 도입 시 두 요소를 함께 평가하는 것이 중요함.
