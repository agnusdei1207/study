## 연관 키워드

- DAS(Direct-Attached Storage), 내장형 DAS, 외장형 DAS, JBOD(Just a Bunch Of Disks)
- HBA(Host Bus Adapter), SATA, SAS, NVMe, RAID(Redundant Array of Independent Disks)
- 자원 고립, SPOF(Single Point of Failure), SDS(Software-Defined Storage), NVMe-oF(NVMe over Fabrics)

## Ⅰ. DAS의 개요

- 핵심 요약 : **DAS** (Direct-Attached Storage)는 스토리지 네트워크를 거치지 않고 서버에 전용 인터페이스로 직결되어 낮은 지연의 블록 입출력을 제공하는 저장 방식.
- 개념 : SATA(Serial Advanced Technology Attachment), SAS(Serial Attached SCSI), NVMe(Non-Volatile Memory Express) 같은 전용 인터페이스로 스토리지를 서버 1:1로 연결하는 블록 스토리지 구성.
- 배경 및 필요성 : 스토리지 전용 네트워크의 구축 비용과 복잡도 없이, 단일 서버가 네트워크 오버헤드 없이 높은 입출력 성능을 확보할 수단이 필요.
- 주요 목적 : 짧은 데이터 경로에 따른 낮은 지연 확보, 구성의 단순화, 서버 단위의 독립적 저장 공간 운영.

## Ⅱ. DAS의 특징 및 장점

- 핵심 요약 : 서버 직결 구조가 전용 경로의 성능과 구성 단순성으로 이어지며, 연결 형태는 내장형과 외장형으로 갈림.

1. **내장형 DAS** : 서버 섀시의 드라이브 베이에 디스크를 직접 장착해 호스트 버스까지의 경로가 가장 짧음 → 지연 최소화와 설치 단순화 효과.
2. **외장형 DAS** : 외장 HBA(Host Bus Adapter)와 전용 케이블로 JBOD(Just a Bunch Of Disks) 인클로저를 연결 → 서버 교체 없는 용량 확장 효과.
3. 전용 경로 직결 : 스위치 홉과 프로토콜 변환 없이 블록 명령을 호스트 버스로 전달 → 예측 가능한 낮은 지연 효과.
4. 서버 종속 구조 : 디스크 자원이 단일 서버에 귀속되어 접근 통제와 관리 포인트가 단순 → 소규모 환경의 운영 부담 감소 효과.

## Ⅲ. DAS의 구조 (흐름)

- 핵심 요약 : 애플리케이션의 입출력 요청이 **RAID** (Redundant Array of Independent Disks) 컨트롤러를 거쳐 직결 디스크로 향하는 단일 경로 구조.
- RAID 컨트롤러 : 여러 디스크를 묶어 성능과 중복성을 제공하며, 내장형 DAS에서 디스크 운영을 담당하는 서버 내 장치.

```text
[ DAS 데이터 경로 ]

애플리케이션 I/O 요청
      ↓
운영체제 I/O 스택 (파일시스템)
      ↓
HBA 또는 RAID 컨트롤러
      ↓
내장 드라이브 베이 · 외장 JBOD
```

```text
[ DAS 연결 형태 분기 ]

서버 (HBA · RAID 컨트롤러)
      ↓ 분기
내장형 : 섀시 드라이브 베이 직결
외장형 : 전용 케이블 → JBOD 인클로저
```

## Ⅳ. DAS와 NAS·SAN의 비교

- 핵심 요약 : DAS는 서버 직결의 최저 지연과 단순 구성을, NAS(Network-Attached Storage)는 파일 공유를, SAN(Storage Area Network)은 블록 공유 네트워크를 담당하는 상보적 구조.

| 비교 축 | DAS | NAS | SAN |
| :--- | :--- | :--- | :--- |
| 연결 구조 | 서버 1:1 전용 인터페이스 | 범용 이더넷 LAN | 스토리지 전용 네트워크 |
| 전송 단위 | 블록 | 파일 | 블록 |
| 자원 공유 | 불가 (서버 종속) | 다수 클라이언트 공유 | 다수 서버의 LUN(Logical Unit Number) 공유 |
| 지연과 비용 | 최저 지연, 낮은 비용 | 프로토콜 오버헤드, 중간 | 낮은 지연, 높은 비용 |

- 선택 기준 :
  1. 단일 서버의 고성능과 단순 구성이 우선이면 DAS
  2. 부서 단위의 파일 공유가 목적이면 NAS
  3. 다수 서버의 블록 공유와 고가용성이 요구되면 SAN

## Ⅴ. DAS의 한계와 방안

- 핵심 요약 : 자원 고립과 서버 장애 취약성, 연결 거리 제한을 저장 자원 풀링, 이중 경로, 패브릭 확장 기술로 보완하는 체계.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| **자원 고립** (Storage Silo) | 디스크가 서버에 고착되어 타 서버의 여유 용량 활용 불가 → 전체 활용률 저하 | 노드별 로컬 디스크를 가상 풀로 통합하는 SDS(Software-Defined Storage) 구성 | 서버별 용량 활용률 |
| **SPOF** (Single Point of Failure) 노출 | 호스트 서버 고장 시 정상 디스크도 접근 불가 → 서비스 중단 | 듀얼 포트 SAS를 두 서버의 HBA에 교차 연결한 HA(High Availability) 구성 | 페일오버 소요 시간 |
| 확장 한계 | SAS 케이블의 신호 감쇠로 수 미터 이내 연결에 머묾 → 데이터센터 규모 확장 곤란 | NVMe 명령을 이더넷·InfiniBand 패브릭으로 확장하는 NVMe-oF(NVMe over Fabrics) 적용 | 원격 접근 지연 |

## Ⅵ. DAS에 대한 기술사적 제언

- 핵심 요약 : 로컬 DAS의 성능과 통합 스토리지의 확장성을 결합한 계층화 표준 아키텍처의 정립 필요.

1. 인프라 운영 조직은 지연에 민감한 캐시·임시 데이터를 로컬 NVMe DAS에 두고 영속 데이터를 복제 계층에 두는 이중 계층 아키텍처를 표준 문서로 정립.
2. 조달·표준 부서는 서버 표준 사양에 SAS 듀얼 포트와 NVMe 슬롯 수를 명시하여 이중 경로 확장 가능성을 구매 단계에서 확보.
3. 기술 전략 조직은 CXL(Compute Express Link) 같은 저지연 상호연결 표준의 동향 점검 체계를 두어 저장 계층 경계의 변화에 대비.

## Ⅶ. 결론

- 핵심 요약 : DAS는 전용 인터페이스 직결로 낮은 지연과 단순 구성을 제공하는 대신 자원 고립과 장애 취약성을 내포하는 저장 방식.
- 시사점 : 단일 서버 성능이 우선인 구간에서 유효하며, 공유와 가용성 요구가 커질수록 통합 스토리지 계층과의 병행 설계가 필요.
