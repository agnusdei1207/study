## 30초 인출

- 본질: 토러스는 메시의 각 차원 끝 노드를 랩어라운드 링크로 연결한 상호연결 토폴로지
- 메커니즘: 각 행·열의 양 끝을 연결해 최단 경로가 경계를 넘어 순환하도록 함
- 통찰: 한계: 홉 감소 효과가 있어도 긴 물리 배선과 링크 혼잡이 이득을 상쇄할 수 있음 → 방안: 목표 통신행렬로 경로·혼잡·배선 비용을 함께 검증한다.

<details>
<summary>핵심 용어</summary>

- **토러스(Torus)** : 격자 각 차원의 양 끝 노드를 순환 연결한 네트워크 토폴로지
- **랩어라운드 링크(Wrap-around Link)** : 격자 경계의 노드들을 이어 주는 링크
- **메시(Mesh)** : 노드를 격자 형태로 연결하되 경계 끝은 연결하지 않은 토폴로지
- **네트워크 지름(Diameter)** : 두 노드 사이 최단 경로 길이 중 최댓값

</details>

## 2~4교시 25점 답안

### Ⅰ. 토러스의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **토러스는** 메시의 각 차원 끝 노드를 랩어라운드 링크로 연결한 상호연결 토폴로지 |
| 목적 | 경계 노드 간 추가 경로를 제공해 병렬 노드 통신을 지원 |

### Ⅱ. 토러스의 특징

| 특징 | 영향 |
|---|---|
| 경계 순환 | 메시의 가장자리 노드도 반대쪽 경계로 이동 가능 |
| 균일한 논리 차수 | 같은 차원의 노드가 대체로 동일한 연결 구조를 가짐 |
| 추가 물리 링크 | 통신 경로는 늘지만 배치·배선 비용도 증가 |

### Ⅲ. 연결 체계·경로 프로세스

**핵심 2차원 토러스 구조: 각 행·열의 끝을 다시 연결**

```text
        A ─ B ─ C       A ↔ C: 행 랩어라운드
        │   │   │
        D ─ E ─ F       D ↔ F: 행 랩어라운드
        │   │   │
        G ─ H ─ I       G ↔ I: 행 랩어라운드
        A↔G B↔H C↔I: 열 랩어라운드
```

**하위 메커니즘: 목적지까지의 방향 선택**

```text
현재 노드·목적지 좌표
  → 차원별 일반 방향 거리와 랩어라운드 거리 계산
  → 더 짧고 혼잡이 낮은 허용 경로 선택
  → 교착 회피 라우팅 규칙에 따라 다음 홉 전송
```

### Ⅳ. 메시와 토러스 비교

| 기준 | 메시 | 토러스 |
|---|---|---|
| 경계 연결 | 열림 | 행·열 경계의 순환 링크 추가 |
| 최단 홉 | 경계 간 먼 경로 발생 | 일부 경계 간 경로 단축 |
| 구현 비용 | 상대적으로 단순 | 긴 링크·배치·라우팅 검증 필요 |
| 평가 지표 | 지름·차수·이분 대역폭·실측 혼잡을 같은 조건에서 비교 | 지름·차수·이분 대역폭·실측 혼잡을 같은 조건에서 비교 |

### Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 랩어라운드 링크가 물리적으로 길어짐 | 보드·캐비닛 배치와 링크 길이를 함께 최적화 |
| 순환 경로가 채널 의존성·교착을 만들 수 있음 | 교착 회피 라우팅과 가상 채널을 검증 |
| 특정 통신 패턴에 트래픽이 집중 | 실제 통신행렬로 링크 부하와 대체 경로 시험 |

### Ⅵ. 제언

랩어라운드 링크가 최단 홉을 줄여도 물리 링크 지연과 혼잡까지 줄인다고 단정할 수 없다. **목표 응용의 통신행렬을 먼저 측정**한 뒤 메시·토러스의 홉 수, 링크 부하, 배선 비용을 같은 규모에서 비교해 채택해야 한다.
