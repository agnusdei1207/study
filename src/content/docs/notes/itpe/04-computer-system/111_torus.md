## Ⅰ. 토러스(Torus)의 개요

- **개념** : 격자(Grid/Mesh) 형태의 정적 상호연결망 토폴로지에서 가장자리(Boundary)에 위치한 노드들을 반대편 가장자리 노드들과 랩어라운드(Wrap-around) 링크로 직접 연결하여, 모든 노드가 물리적·논리적으로 동일한 연결 차수(Degree)와 대칭성을 갖도록 설계한 $k$-ary $n$-cube 계열의 고성능 컴퓨터 상호연결망 토폴로지.
- **배경 및 필요성** : 전통적 2D/3D 메시(Mesh) 구조는 경계 노드의 연결 차수가 낮아 트래픽이 중앙 노드로 집중되고 네트워크 직경(Diameter)이 커지는 병목이 발생하므로, 슈퍼컴퓨터와 대규모 병렬 클러스터에서 직경을 절반으로 줄이고 대칭적 통신을 달성하기 위해 고안됨.
- **핵심 목적** : 네트워크 직경(Diameter) 단축, 코너/경계 노드의 비대칭 병목 해소, 경로 다중화를 통한 내고장성(Fault-Tolerance) 및 이등분 대역폭(Bisection Bandwidth) 극대화.

## Ⅱ. 토러스의 핵심 아키텍처 및 랩어라운드 라우팅 메커니즘

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 2D 토러스 (2D-Torus: 4x4) 랩어라운드 루프 및 라우팅 구조 ]          │
│                                                                        │
│     ┌────────────────────────────────────────────────────────────┐     │
│     │            Wrap-around Link (X축 양 끝단 순환 연결)         │     │
│     ▼                                                            ▼     │
│   ( 0,0 ) <───> ( 0,1 ) <───> ( 0,2 ) <───> ( 0,3 ) <───────────┘     │
│     ▲             ▲             ▲             ▲                        │
│     │             │             │             │                        │
│     ▼             ▼             ▼             ▼                        │
│   ( 1,0 ) <───> ( 1,1 ) <───> ( 1,2 ) <───> ( 1,3 )                   │
│     ▲             ▲             ▲             ▲                        │
│     │             │             │             │                        │
│     ▼             ▼             ▼             ▼                        │
│   ( 2,0 ) <───> ( 2,1 ) <───> ( 2,2 ) <───> ( 2,3 )                   │
│     ▲             ▲             ▲             ▲                        │
│     │             │             │             │                        │
│     ▼             ▼             ▼             ▼                        │
│ ┌─> ( 3,0 ) <───> ( 3,1 ) <───> ( 3,2 ) <───> ( 3,3 ) <─┐             │
│ │   ▲                                         ▲       │             │
│ │   └─────────────────────────────────────────┴───────┘             │
│ │            Wrap-around Link (Y축 양 끝단 순환 연결)                 │
│ └───────────────────────────────────────────────────────────────────┘
```

- **네트워크 직경 단축 원리** : $k 	imes k$ 2D 메시의 직경은 $2(k - 1)$이지만, 양 끝단을 연결한 2D 토러스의 직경은 $2 	imes \lfloor k/2 floor$로 약 절반으로 축소되어 최대 통신 지연 시간 대폭 감소.
- **모든 노드의 완전 대칭성** : 모서리나 벽이 없으므로 특정 노드가 트래픽 핫스팟이 되지 않고, 클러스터 내부의 모든 컴퓨팅 노드가 정확히 동일한 $2n$ (2D 토러스는 4, 3D 토러스는 6)개의 포트를 사용하여 라우팅 수행.

## Ⅲ. 주요 상호연결망 토폴로지 비교 분석 (토러스 vs 메시 vs 팻트리)

| 비교 항목 | 토러스 (Torus: 2D/3D) | 메시 (Mesh: 2D/3D) | 팻 트리 (Fat-Tree) |
| :--- | :--- | :--- | :--- |
| **연결 방식** | **메시에 랩어라운드 루프 결합** | 직교 격자형 점대점 연결 | 다단계 트리 스위칭 구조 |
| **네트워크 직경** | **$n 	imes \lfloor k/2 floor$ (짧음)** | $n 	imes (k - 1)$ (상대적 김) | $2 \log_k (N/2)$ (로그 스케일) |
| **노드 대칭성** | **완전 대칭 (모든 노드 차수 동일)** | 비대칭 (경계/코너 노드 차수 부족) | 계층형 구조 (리프와 스파인 분리) |
| **케이블 배선 길이** | 양 끝단 연결선이 길어 배선 복잡 | 인접 노드 간 최단 배선 (단순) | 대규모 광케이블 트랜시버 소모 |
| **데드락 방지 난도**| 순환 루프로 인해 **가상 채널(VC) 필수**| 단순 차원 순서 라우팅(DOR)으로 해결| 스위치 레벨 라우팅으로 데드락 없음 |
| **대표 적용처** | 일본 후가쿠(Tofu 6D), IBM BlueGene | 온칩 네트워크 (NoC), 엣지 가속기 | 엔비디아 슈퍼POD, 대형 AI 클러스터 |

## Ⅳ. 토러스 토폴로지의 주요 한계점 및 해결 방안

- **순환 루프로 인한 라우팅 데드락(Routing Deadlock) 취약성** :
  - **한계점** : 링 형태의 랩어라운드 연결로 인해 패킷 버퍼가 원형 대기(Circular Wait) 상태에 빠지기 쉬워 네트워크 영구 마비 위험.
  - **해결 방안** : 물리 링크를 다수의 가상 채널(VC0, VC1)로 분할하고, 랩어라운드 링크 통과 시 가상 채널을 전환하는 가상 채널 기반 회피 기법 적용.
- **물리적 긴 케이블(Long Wrap-around Cable) 배선 및 신호 지연** :
  - **한계점** : 랙의 양 끝단 노드를 연결하는 물리 케이블 길이가 매우 길어져 신호 감쇠 및 배선 혼잡 발생.
  - **해결 방안** : 폴디드 토러스(Folded Torus) 배선 기법 적용, 노드를 물리적으로 엇갈리게 지그재그 배치하여 최대 케이블 길이를 일정하게 균일화.
- **단일 노드 장애 시 링 단절 및 우회 경로 복잡성** :
  - **한계점** : 1개 노드 고장 시 해당 축의 순환 링이 끊어져 직경이 급증하고 라우팅 알고리즘 복잡도 증가.
  - **해결 방안** : 6차원 메시/토러스 구조를 채택한 Tofu 인터커넥트처럼 차원을 다중화(3D 토러스 + 3D 메시)하여 결함 노드 동적 바이패스.

## Ⅴ. 초고성능 컴퓨팅 아키텍처를 위한 기술사적 제언

- **다차원 토러스(6D Torus)와 이기종 가속기 패브릭 융합** : 일본 슈퍼컴퓨터 후가쿠(Fugaku)의 성공 사례처럼, 초거대 AI 클러스터 구축 시 단순 팻 트리의 스위치 비용 폭증을 방지하기 위해 랙 내부 및 근거리 랙 간에는 3D~6D 폴디드 토러스 인터커넥트를 적용하는 하이브리드 토폴로지를 검토해야 함.
- **하드웨어 기반 라우팅 칩셋 및 통신-연산 중첩(Overlap) 최적화** : 토러스 구조의 홉(Hop) 지연 시간을 최소화하기 위해 전용 통신 프로세서를 호스트 CPU와 완전 분리하고, MPI AllReduce 집단 통신을 라우터 하드웨어 내부에서 직접 감축 연산(In-Network Computing)하는 아키텍처를 수립할 것을 제언함.
