## 연관 키워드

- 토러스(Torus), k-ary n-cube, 랩어라운드(Wrap-around) 링크
- 노드 차수(Degree), 네트워크 지름(Diameter), 이등분 대역폭(Bisection Bandwidth)
- 대칭성(Symmetry), 가상 채널(Virtual Channel), 데이트라인(Dateline) 기법
- 폴디드 토러스(Folded Torus), 후가쿠(Fugaku) Tofu 인터커넥트, 메시(Mesh)

## Ⅰ. 토러스의 개요

- 핵심 요약 : 격자 구조의 양끝 노드를 서로 연결해 모든 노드가 같은 연결 조건을 갖게 만든 상호연결망 토폴로지.
- 개념 : n차원 격자에서 각 차원의 양끝 노드를 **랩어라운드** (Wrap-around) 링크로 연결한 **토러스** (Torus) 토폴로지로, 각 차원에 k개 노드를 두는 구조가 **k-ary n-cube**로 공식화됨.
- 배경 및 필요성 : 메시(Mesh) 구조는 경계 노드의 연결 수가 적어 경계가 병목이 되고 최대 통신 거리가 길어지므로, 대규모 병렬 시스템의 균등 통신 요구를 충족할 구조가 필요.
- 주요 목적 : 최대 홉 수의 축소, 노드 간 통신 조건의 균등화, 우회 경로 확보를 통한 내고장성(Fault-Tolerance) 향상.

## Ⅱ. 토러스의 특징 및 장점

- 핵심 요약 : 랩어라운드 링크가 지름 축소와 완전 대칭을 동시에 실현해 균등 지연과 우회 통신이라는 장점으로 이어지는 구조.

1. 균일 노드 차수 : n차원 토러스의 모든 노드 차수(Degree)는 2n → 라우터 설계가 균일해지고 특정 노드 핫스팟이 줄어드는 효과.
2. 지름 축소 : k-ary n-cube의 네트워크 지름(Diameter)은 n×⌊k/2⌋로 메시의 n×(k−1)보다 짧음 → 최악 통신 지연 감소 효과.
3. 이등분 대역폭 확보 : 네트워크를 두 영역으로 나누는 절단면의 **이등분 대역폭** (Bisection Bandwidth)이 랩어라운드 링크로 보강 → 분할 정복식 병렬 처리의 통신 병목 완화 효과.
4. 경로 다중화 : 순환 구조 덕분에 두 노드 사이에 여러 최단·준최단 경로 존재 → 링크 고장 시 우회로 통신 유지 효과.
5. 확장의 규칙성 : 차원을 늘리면 노드당 링크가 2씩 증가하는 예측 가능한 구조 → 대규모 시스템의 설계·배선 계획 단순화 효과.

## Ⅲ. 토러스의 구조 (흐름)

- 핵심 요약 : 1차원 링을 기본 단위로 차원을 쌓아 올리는 방식으로 구성되며 각 차원의 링이 노드 차수를 2씩 추가함.

```text
[ 1차원 링 구조 (k = 4) ]

(0) ─ (1) ─ (2) ─ (3)
  :_________________:
   랩어라운드 연결 구간
```

```text
[ 차원 확장에 따른 구조 ]

1차원 : 링, 노드 차수 2
   ↓
2차원 : 행 링 + 열 링, 차수 4
   ↓
3차원 : 세 축 링 결합, 차수 6
   ↓
n차원 : 차수 2n, 노드 수 k^n
```

- k-ary n-cube는 총 k^n개 노드를 n차원 격자에 배열하고 각 차원에서 순환 배열을 이룸.
- 후가쿠(Fugaku)는 6차원 토러스 형태의 Tofu 인터커넥트로 노드를 연결해 높은 차원으로 짧은 지름과 많은 우회 경로를 함께 확보함.

## Ⅳ. 토러스와 메시·하이퍼큐브의 비교

- 핵심 요약 : 랩어라운드 여부가 지름과 대칭성을 가르고 차수 증가 방식이 확장 비용을 가름.

| 비교 축 | 토러스 | 메시 | 하이퍼큐브 |
| :--- | :--- | :--- | :--- |
| 연결 방식 | 격자에 랩어라운드 결합 | 격자 (경계 미연결) | 2^d 노드의 d차원 상호연결 |
| 노드 차수 | 2n 균일 | 경계에 따라 상이 | d (노드 수의 로그) |
| 네트워크 지름 | n×⌊k/2⌋ | n×(k−1) | log₂N |
| 대칭성 | 완전 대칭 | 비대칭 | 완전 대칭 |
| 데드락 회피 | 순환 경로라 가상 채널 필요 | 차원 순서 라우팅으로 회피 용이 | 반사 코드 라우팅 적용 |
| 적용 사례 | 후가쿠 Tofu, Blue Gene 3D 토러스 | 온칩 네트워크(NoC) | 초기 연구용 병렬기 |

- 선택 기준 :
  1. 균등 지연과 우회성이 중요하면 토러스.
  2. 배선 단순성과 부분 확장이 중요하면 메시.
  3. 노드 수 대비 짧은 지름이 필요하면 고차원 구조 검토.

## Ⅴ. 토러스의 한계와 방안

- 핵심 요약 : 순환 구조의 데드락, 긴 랩어라운드 배선, 노드 장애 시 링 단절을 가상 채널, 폴디드 배선, 다차원 우회로 일대일 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| 라우팅 데드락 | 링 위 패킷 버퍼의 원형 대기 → 네트워크 정지 | **가상 채널** (Virtual Channel) 분할과 데이트라인(Dateline) 기법 적용 | 데드락 발생 건수 |
| 긴 랩어라운드 배선 | 양끝을 잇는 케이블의 신호 감쇠 → 배선 혼잡 | **폴디드 토러스** (Folded Torus) 배선으로 링크 길이 균일화 | 최대 링크 배선 길이 |
| 노드 장애 시 단절 | 해당 축 순환의 차단 → 지름 급증과 우회 복잡화 | 다차원 경로 활용과 고장 노드 우회 테이블 갱신 | 장애 후 평균 홉 수 증가율 |

## Ⅵ. 토러스에 대한 기술사적 제언

- 핵심 요약 : 통신 거리별로 토폴로지를 나눠 쓰고 통신과 연산을 겹치는 하드웨어 구조를 함께 설계하는 방향.
- 설계 : HPC(High-Performance Computing) 시스템 설계 조직이 근거리 구간은 토러스, 원거리 구간은 트리 기반 스위칭으로 잇는 하이브리드 구성을 평가.
- 하드웨어 : 인터커넥트 설계 조직이 집단 통신 일부를 라우터 내부에서 처리하는 망 내부 연산(In-Network Computing) 구조를 반영.
- 검증 : 라우팅 알고리즘 개발 조직이 데드락 회피 설계를 트래픽 시뮬레이션으로 검증한 뒤 적용.

## Ⅶ. 결론

- 핵심 요약 : 토러스는 랩어라운드로 지름 축소와 완전 대칭을 얻는 대신 데드락 회피와 배선 설계를 요구하는 토폴로지.
- 시사점 : 토폴로지 선택은 규모, 배선 비용, 라우팅 복잡도를 함께 저울질하는 설계 판단이 됨.
