## 연관 키워드

- 토러스(Torus), 메시(Mesh), 팻 트리(Fat-Tree), 랩어라운드(Wrap-around) 링크
- 네트워크 직경(Diameter), 이등분 대역폭(Bisection Bandwidth), 노드 대칭성
- 라우팅 데드락(Routing Deadlock), 가상 채널(VC), 폴디드 토러스(Folded Torus)
- 후가쿠(Fugaku), Tofu 인터커넥트, 망 내부 연산(In-Network Computing)

## Ⅰ. 토러스(Torus)의 개요

- 핵심 요약 : 격자의 가장자리 노드를 반대편 가장자리와 직접 연결해 모든 노드의 차수와 통신 특성을 대칭으로 만든 상호연결망 토폴로지.
- 개념 : 격자(Grid/Mesh) 구조에서 경계에 있는 노드들을 반대편 경계 노드와 **랩어라운드** (Wrap-around) 링크로 연결하여, 모든 노드가 같은 연결 차수를 갖도록 설계한 **토러스** (Torus, k-ary n-cube 계열의 고성능 상호연결망 토폴로지).
- 배경 및 필요성 : 일반 2D·3D **메시** (Mesh)는 경계 노드의 연결 차수가 낮아 트래픽이 중앙으로 몰리고 **네트워크 직경** (Diameter)이 커지는 병목이 있어, 대규모 병렬 시스템에서 이를 줄이기 위해 토러스가 쓰임.
- 주요 목적 : 네트워크 직경 단축, 경계 노드의 병목 해소, 경로 다중화를 통한 **내고장성** (Fault-Tolerance) 확보, **이등분 대역폭** (Bisection Bandwidth) 극대화.

## Ⅱ. 토러스의 핵심 아키텍처와 특징

- 핵심 요약 : 랩어라운드 링크가 직경과 대칭성을 함께 개선하지만, 순환 구조가 라우팅 설계의 부담을 키우는 구조.

1. 직경 단축 : 양 끝을 잇는 링크로 최대 홉 수가 절반 가까이 줄어듦 → 최대 통신 지연이 감소.
2. 노드 대칭성 : 모서리나 경계가 없어 모든 노드가 같은 포트 수를 사용 → 특정 노드가 핫스팟이 되는 현상이 줄어듦.
3. 경로 다중화 : 두 노드 사이에 여러 경로가 존재 → 링크나 노드 고장 시 우회 경로로 통신을 이어갈 수 있음.

## Ⅲ. 토러스의 구조와 랩어라운드 동작

- 핵심 요약 : 행과 열마다 양 끝 노드를 잇는 링이 반복되어 모든 노드가 같은 구조에 놓이는 격자형 구조.

```text
[ 1차원 링 구조 (k = 4) ]

(0) ── (1) ── (2) ── (3)
 :______________________:
   랩어라운드 링크 (0과 3 직접 연결)
```

- $k \times k$ 2D 메시의 직경은 $2(k-1)$이지만, 2D 토러스의 직경은 $2 \lfloor k/2 \rfloor$로 약 절반이 되며, 각 노드는 2D에서 4개, 3D에서 6개의 포트를 사용함.

## Ⅳ. 토러스와 메시, 팻 트리의 비교 분석

- 핵심 요약 : 토러스는 메시에 랩어라운드를 더해 직경과 대칭성을 얻는 대신 데드락 회피와 배선 길이라는 비용을 치르는 구조.

| 비교 항목 | 토러스 (Torus, 2D/3D) | 메시 (Mesh, 2D/3D) | 팻 트리 (Fat-Tree) |
| :--- | :--- | :--- | :--- |
| 연결 방식 | 메시에 랩어라운드 링크를 결합 | 직교 격자형 점대점 연결 | 다단계 트리 스위칭 구조 |
| 네트워크 직경 | n × ⌊k/2⌋ (짧음) | n × (k-1) (상대적으로 김) | 로그 규모로 증가 |
| 노드 대칭성 | 완전 대칭 (모든 노드 차수 동일) | 비대칭 (경계와 코너 노드의 차수 부족) | 계층 구조 (리프와 스파인 분리) |
| 배선 길이 | 양 끝을 잇는 링크가 길어 배선 복잡 | 인접 노드 간 짧은 배선 | 대규모 광케이블과 트랜시버 다수 필요 |
| 데드락 회피 | 순환 구조로 가상 채널(VC, Virtual Channel) 필요 | 차원 순서 라우팅(DOR, Dimension-Order Routing)으로 해결 | 상향-하향 라우팅으로 회피가 상대적으로 용이 |
| 적용 사례 | 후가쿠(Fugaku)의 6차원 Tofu, IBM Blue Gene의 3D 토러스 | 온칩 네트워크(NoC, Network-on-Chip) | 대규모 AI 클러스터의 데이터센터 네트워크 |

## Ⅴ. 토러스 토폴로지의 한계와 방안

- 핵심 요약 : 순환 루프에 따른 데드락, 긴 배선, 노드 장애 시 링 단절을 가상 채널, 폴디드 배선, 다차원화로 각각 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| 라우팅 데드락 | 링 구조에서 패킷 버퍼가 원형 대기 상태에 빠져 네트워크가 멈춤 | 물리 링크를 여러 가상 채널로 나누고, 랩어라운드 통과 시 채널을 전환하는 데이트라인(Dateline) 기법 적용 | 데드락 발생 건수, 채널별 버퍼 점유율 |
| 긴 랩어라운드 케이블 | 양 끝 노드를 잇는 물리 케이블이 길어 신호 감쇠와 배선 혼잡 발생 | 폴디드 토러스(Folded Torus) 배선으로 노드를 엇갈려 배치, 링크 길이를 균일화 | 링크별 최대 배선 길이 |
| 노드 장애 시 링 단절 | 한 노드가 고장 나면 해당 축의 순환이 끊겨 직경이 급증하고 우회 경로가 복잡해짐 | 차원을 다중화한 구조(3D 토러스와 3D 메시 결합)로 고장 노드 우회 | 고장 후 평균 홉 수 증가율 |

## Ⅵ. 초고성능 컴퓨팅 아키텍처에 대한 기술사적 제언

- 핵심 요약 : 대규모 AI 클러스터에서는 토러스와 팻 트리를 용도별로 섞은 하이브리드 토폴로지와, 통신과 연산을 겹치는 하드웨어 지원을 검토하는 방향.

근거리 구간에는 3D에서 6D에 이르는 폴디드 토러스 인터커넥트를 적용하고, 원거리 구간은 팻 트리로 연결하는 하이브리드 구성을 검토할 만하다. 단순 팻 트리만으로 확장하면 스위치 수와 광 트랜시버 비용이 빠르게 늘어나므로, 홉 지연이 중요한 구간에 토러스를 두는 방식이 비용 측면에서 유리할 수 있다. 통신 프로세서를 호스트 CPU(Central Processing Unit)와 분리하고 MPI(Message Passing Interface)의 집단 통신 일부를 라우터 하드웨어에서 처리하는 망 내부 연산(In-Network Computing) 구조를 설계 단계에서 함께 고려하는 것이 좋다.

```text
[ 하이브리드 토폴로지 적용 흐름 ]

랙 내부·근거리 랙 간 : 폴디드 토러스
   ↓
원거리 랙 간 : 팻 트리
   ↓
집단 통신 : 라우터 내부 연산 검토
```

## Ⅶ. 결론

- 핵심 요약 : 토러스는 랩어라운드 링크로 직경과 대칭성을 얻는 토폴로지이며, 그 대가로 데드락 회피와 배선 설계가 필수가 됨.
- 시사점 : 토러스의 이점은 라우팅 설계와 배선 제약이 함께 해결될 때 살아나므로, 토폴로지 선택 시 규모별 비용과 장애 대응을 함께 평가해야 함.
