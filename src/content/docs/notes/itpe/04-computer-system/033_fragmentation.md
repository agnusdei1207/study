## Ⅰ. 메모리 단편화(Fragmentation)의 개요

- **개념** : 기억장치(물리 메모리 또는 가상 메모리) 내에 할당 가능한 총 유휴 용량은 충분함에도 불구하고, 메모리가 비효율적인 크기의 조각들로 파편화되어 있어 새로운 프로세스나 동적 객체에 연속적인 주소 공간을 할당하지 못하는 현상.
- **배경 및 필요성** : 가변 크기의 프로세스가 메모리에 빈번하게 적재(Load)되고 해제(Free)되는 동적 메모리 할당 환경에서, 고정 분할 방식의 내부 낭비와 가변 분할 방식의 외부 조각 발생으로 인한 메모리 고갈 문제를 해결하기 위해 분석됨.
- **핵심 목적** : 메모리 공간 이용률 극대화, 할당 및 해제 시의 검색 지연 최소화, 페이징 및 슬랩(Slab) 할당자를 통한 단편화 제어.

## Ⅱ. 메모리 단편화(Fragmentation)의 핵심 아키텍처 및 동작 메커니즘

메모리 단편화는 할당 블록 내부의 미사용 공간인 '내부 단편화'와 할당 블록 사이의 자투리 공간인 '외부 단편화'로 분류되며, 버디 시스템(Buddy System)과 압축(Compaction)으로 해결함.

```text
[ 내부 단편화 vs 외부 단편화 메커니즘 ]

1. 내부 단편화 (Internal Fragmentation: 고정 분할 / 페이징)
+-----------------------+-----------------------+
| 할당된 4KB 프레임     | 할당된 4KB 프레임     |
| [실제 데이터 2.5KB]  | [실제 데이터 1.2KB]  |
| (낭비 공간: 1.5KB)    | (낭비 공간: 2.8KB)    |
+-----------------------+-----------------------+
  * 할당 단위(블록 크기)가 프로세스 요구량보다 커서 내부 낭비 발생

2. 외부 단편화 (External Fragmentation: 가변 분할 / 세그멘테이션)
+-----------+---------+-----------+---------+-----------+
| Process A | (빈공간)| Process B | (빈공간)| Process C |
| (점유 중) | (10MB)  | (점유 중) | (15MB)  | (점유 중) |
+-----------+---------+-----------+---------+-----------+
  * 총 유휴 메모리는 25MB(10+15)이나, 20MB 요구 프로세스 적재 불가!
  
3. 해결 메커니즘: 압축(Compaction) 및 버디 시스템(Buddy Memory)
+-----------+-----------+-----------+-------------------+
| Process A | Process B | Process C | 연속된 빈 공간    |
| (밀어붙이기 완료)     |           | (25MB 단일 블록)  |
+-----------+-----------+-----------+-------------------+
```

- **내부 단편화 (Internal Fragmentation)** : 메모리 할당 단위가 고정되어 있을 때, 프로세스가 요구한 크기보다 큰 블록이 할당되어 블록 내부에 남는 자투리 공간 낭비.
- **외부 단편화 (External Fragmentation)** : 프로세스들의 할당과 해제가 반복되면서 남아있는 유휴 메모리의 총합은 충분하나, 작은 조각들로 분산되어 연속 공간 요구를 충족하지 못하는 현상.
- **동적 메모리 배치 기법** : 최초 적합(First-Fit), 최적 적합(Best-Fit), 최악 적합(Worst-Fit) 알고리즘을 통한 가변 메모리 탐색.
- **페이징(Paging)에 의한 해결** : 가상 메모리 기법을 적용하여 물리 메모리를 불연속적인 고정 프레임으로 분할함으로써 외부 단편화를 근원적으로 제거.

## Ⅲ. 메모리 단편화(Fragmentation)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 내부 단편화 (Internal) | 외부 단편화 (External) |
|---|---|---|
| **발생 원인** | 고정 크기 분할(Fixed Partition), 페이징(Paging) | 가변 크기 분할(Variable Partition), 세그멘테이션 |
| **낭비 공간 위치** | 할당된 메모리 블록 '내부' 잔여 공간 | 할당된 메모리 블록들 '사이'의 유휴 조각들 |
| **해결 기법** | 슬랩 할당자(Slab Allocator), 적정 페이지 크기(4KB) 선정 | 페이징 가상메모리 전환, 압축(Compaction), 버디 시스템 |
| **성능 오버헤드** | 메모리 탐색 빠름, 공간 낭비 발생 | 공간 검색 오버헤드(Best-fit 등) 및 재배치 부하 |
| **OS 대응 사례** | 리눅스 커널의 kmalloc 슬랩 캐시 풀 | 리눅스 버디 할당자의 2^N 거듭제곱 병합/분할 |

- 현대 OS는 페이지 단위 할당(외부 단편화 해결)과 커널 객체 단위 슬랩 할당자(내부 단편화 해결)를 2계층으로 결합하여 단편화를 극복함.

## Ⅳ. 메모리 단편화(Fragmentation)의 주요 한계점 및 해결 방안

- **대용량 페이지(Huge Page) 도입 시 내부 단편화 급증** :
  - **한계점** : TLB 미스를 줄이기 위해 2MB 또는 1GB 단위 Huge Page를 사용할 경우 작은 크기의 프로세스에서 수백 MB 이상의 메모리 내부 낭비 초래.
  - **해결 방안** : 워크로드 특성에 따라 JVM 힙 및 DB 버퍼풀 등 대규모 연속 메모리 요구 프로세스에만 명시적 Huge Page 바인딩.
- **메모리 압축(Compaction) 시 프로세스 중단 및 I/O 오버헤드** :
  - **한계점** : 외부 단편화를 해소하기 위해 실행 중인 프로세스를 이동시키고 주소를 재배치할 때 심각한 CPU 점유 및 일시 정지(Stop-the-World) 발생.
  - **해결 방안** : 물리적 압축 대신 MMU 가상 주소 테이블의 포인터 매핑만 수정하여 불연속 물리 프레임을 논리적 연속으로 투명 제공.
- **장기 가동(Long-running) 서버의 힙 메모리 파편화** :
  - **한계점** : C/C++ 서버 애플리케이션에서 수개월 운영 시 힙 공간이 파편화되어 전체 메모리는 여유 있으나 신규 `malloc()` 실패 발생.
  - **해결 방안** : glibc 기본 할당자 대신 고성능 멀티스레드 및 파편화 방지 할당자(jemalloc, tcmalloc) 라이브러리 링크.

## Ⅴ. 메모리 단편화(Fragmentation) 적용 및 발전을 위한 기술사적 제언

- **현대 JVM 가비지 컬렉터의 동시성 압축(ZGC/Shenandoah) 활용** : 수백 GB의 대용량 힙 메모리에서도 단편화 압축을 밀리초 이하의 STW로 수행하는 ZGC 적극 도입 권장.
- **Cgroups v2 메모리 임계치 및 회수(Reclaim) 모니터링** : 컨테이너 환경에서 단편화로 인한 조기 OOM-Kill을 방지하기 위해 커널 메모리 압력 지표(PSI) 상시 감시 체계 수립.
- **임베디드 및 고신뢰성 시스템의 정적 메모리 풀링** : 동적 할당의 비결정성을 배제하기 위해 부팅 시점에 객체 풀을 사전 할당하는 메모리 거버넌스 준수 필수.
