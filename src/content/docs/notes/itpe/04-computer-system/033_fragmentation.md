## 답안 골격
```text
[단편화] ◀━━ 머리: Ⅶ 내 의견 (페이징 기반 외부 단편화 원천 제거와 슬랩 할당자를 통한 내부 단편화 최소화)
 ┃
 ┣━ Ⅰ 개요 ───── 동적 메모리 할당·해제 반복에 따른 사용 불가 빈 공간 누적 → 메모리 자원 낭비 현상
 ┣━ Ⅱ 특징 ───── 내부 단편화(할당 블록 내 낭비) vs 외부 단편화(블록 사이 자투리 공간 낭비)
 ┣━ Ⅲ 구조 ───── 고정 분할(Fixed Partition) vs 가변 분할(Variable Partition) / 슬랩 할당자(Slab) / 버디 시스템
 ┣━ Ⅳ 흐름 ───── ① 메모리 요청 → ② 최초/최적/최악 적합 탐색 → ③ 자투리 공간 잔존 → ④ 통합(Coalescing)/압축(Compaction)
 ┣━ Ⅴ 비교 ───── 내부 단편화 vs 외부 단편화 / 페이징 vs 세그멘테이션의 단편화 특성
 ┗━ Ⅵ 실무 ───── 가상 메모리 페이징 도입 / 메모리 압축(Compaction)의 I/O 비용 / 버디 시스템(Buddy System)
```

- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 내부 vs 외부 단편화 도식 → Ⅴ 단편화 유형 비교표 / 25점 = Ⅰ~Ⅶ 전개, Ⅳ 버디 시스템 분할/병합 알고리즘과 Ⅵ OS 커널 슬랩 캐시 동작
- 기출: 139회 4교시 `가상메모리 및 메모리 관리 기법(단편화 원인과 해결방안)`

## 한 줄 본질
- 프로세스의 메모리 할당과 해제가 비규칙적으로 반복되면서 총 잔여 메모리는 충분함에도 불구하고 연속된 공간이 없어 새 메모리를 할당하지 못하는 자원 고갈 현상 → 페이징(고정 분할)으로 외부 단편화를 없애고 버디 시스템 및 슬랩 할당자(Slab)로 내부 단편화를 최소화 → 메모리 집적도 극대화 / 주소 변환 복잡도 및 메모리 압축 시 시스템 멈춤 비용

## 핵심 그림
```text
[ 1. 내부 단편화 (Internal Fragmentation) - 고정 분할 / 페이징 ]
+─────────────────────────────────────────────────────────────+
|  할당된 고정 페이지 프레임 (4KB)                           |
|  +-------------------------------------+-----------------+  |
|  | 실제 사용 데이터 (3KB)              | 낭비 공간 (1KB) |  | ──> 프로세스 내부 낭비
|  +-------------------------------------+-----------------+  |
+─────────────────────────────────────────────────────────────+

[ 2. 외부 단편화 (External Fragmentation) - 가변 분할 / 세그멘테이션 ]
+─────────────────────────────────────────────────────────────+
|  [점유 20MB]  │ [빈공간 5MB] │  [점유 30MB]  │ [빈공간 7MB] |
+───────────────┴──────────────┴───────────────┴──────────────+
  * 총 가용 메모리: 5MB + 7MB = 12MB
  * 신규 프로세스 10MB 할당 요청 시:
    연속된 10MB 공간이 없으므로 할당 실패 (외부 단편화 발생!)
```

## 핵심 용어
- 내부 단편화(Internal Fragmentation): 고정된 크기의 블록(예: 4KB 페이지)을 할당할 때, 프로세스가 요구한 크기가 블록보다 작아서 블록 내부에 남아서 버려지는 빈 공간
- 외부 단편화(External Fragmentation): 메모리가 동적으로 할당·해제되면서 작은 자투리 빈 공간들이 흩어져 있어, 총 가용 메모리는 충분하지만 연속적인 공간이 부족해 프로세스를 적재하지 못하는 현상
- 버디 시스템(Buddy System): 메모리를 2의 거듭제곱($2^n$) 단위로 쪼개어 할당하고, 인접한 동일 크기의 짝(Buddy)이 모두 비어 있으면 즉시 하나로 병합(Coalescing)하는 외부 단편화 억제 알고리즘

## 핵심 통찰
- 외부 단편화는 '가상 메모리 페이징 기법'의 등장으로 사용자 영역에서는 사실상 해결됨 → 물리 메모리가 불연속하게 흩어져 있어도 MMU 페이지 테이블 매핑을 통해 가상 공간에서는 완벽히 연속된 메모리로 인식하기 때문
- 그러나 OS 커널 영역(디바이스 드라이버, 네트워크 패킷 버퍼)은 하드웨어 DMA(Direct Memory Access)를 위해 물리적으로 연속된 메모리가 반드시 필요함 → 따라서 커널은 버디 시스템과 슬랩 할당자(Slab Allocator: 동일 크기 객체 캐시 풀)를 통해 외부 및 내부 단편화를 철저히 방어
- 메모리 압축(Compaction / Garbage Collection)은 흩어진 공간을 한쪽으로 몰아 외부 단편화를 해결하지만, 메모리 블록을 통째로 복사하는 동안 CPU가 멈추는(Stop-the-World) 치명적 오버헤드를 유발

## 이웃 토픽과 구분
- 내부 단편화 vs 외부 단편화: 내부 단편화 = 할당된 블록 '안'에서 낭비(페이징 특성, 작은 페이지 크기로 완화) / 외부 단편화 = 할당된 블록들 '사이'에서 낭비(세그멘테이션 특성, 페이징 도입으로 해결)

## 문제·원인·대책
- 사례: 139회 기출 장기 운영 리눅스 서버에서 물리 메모리가 20GB 남아있음에도 커널 DMA 버퍼 할당 실패
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 네트워크 카드(NIC) 점보 프레임 수신용 연속 물리 메모리 할당 실패 | 장기 운용으로 인한 커널 영역의 심각한 외부 단편화 | CMA(Contiguous Memory Allocator) 사전 예약 풀 구성 및 백그라운드 컴팩션 | 부팅 시 연속 물리 영역 선확보로 DMA 버퍼 보장 |
| 소형 자료구조 수백만 개 생성 시 내부 단편화로 인한 메모리 고갈 | 기본 할당자(malloc)의 최소 청크 패딩 및 정렬 오버헤드 | 전용 슬랩/슬롭(SLAB/SLUB) 할당자 및 메모리 풀(jemalloc) 도입 | 객체 크기별 맞춤 할당으로 내부 낭비율 5% 이내 억제 |
