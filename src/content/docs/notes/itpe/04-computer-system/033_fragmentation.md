## 연관 키워드

- 메모리 단편화(Fragmentation), 내부 단편화(Internal Fragmentation), 외부 단편화(External Fragmentation)
- 고정 분할, 가변 분할, 최초 적합(First-Fit), 최적 적합(Best-Fit), 최악 적합(Worst-Fit)
- 페이징(Paging), 버디 시스템(Buddy System), 슬랩 할당자(Slab Allocator), 압축(Compaction)
- Huge Page, TLB, MMU, ZGC, PSI, jemalloc

## Ⅰ. 메모리 단편화의 개요

- 핵심 요약 : **메모리 단편화** (Fragmentation)는 유휴 용량의 총합은 충분하지만 조각난 공간 때문에 연속 할당이 불가능해지는 현상.
- 개념 : 주기억장치 안의 유휴 공간이 총량으로는 충분하나 작은 조각으로 흩어져 있어, 새 프로세스나 동적 객체에 연속된 주소 공간을 주지 못하는 상태.
- 배경 및 필요성 : 크기가 제각각인 프로세스가 적재와 해제를 반복하는 동적 메모리 할당 환경에서, 고정 분할의 내부 낭비와 가변 분할의 외부 조각이 누적되어 메모리 이용률이 떨어지므로 발생 원인을 나누어 제어할 필요가 생김.
- 주요 목적 : 메모리 이용률 극대화, 할당과 해제 시 탐색 지연 최소화, 프레임 단위 할당과 객체 캐시 풀을 활용한 단편화 제어.

## Ⅱ. 메모리 단편화의 특징 및 장점

- 핵심 요약 : 낭비가 블록 안에서 생기는지 블록 사이에서 생기는지를 구분해 기법을 달리 적용하는 것이 제어의 출발점.

1. **내부 단편화** (Internal Fragmentation) : 할당 단위가 고정되어 요구량보다 큰 블록이 잡히면서 블록 안에 자투리 공간이 남음 → 할당 단위를 워크로드에 맞게 고르면 낭비 규모를 줄일 수 있음.
2. **외부 단편화** (External Fragmentation) : 할당과 해제가 반복되며 유휴 공간이 흩어져 전체 용량은 충분해도 연속 요구를 만족하지 못함 → 연속 배치를 요구하지 않는 구조로 해결 가능.
3. 동적 배치 기법 : 최초 적합(First-Fit), 최적 적합(Best-Fit), 최악 적합(Worst-Fit) 중 하나로 빈 구역을 고름 → 탐색 비용과 남는 조각 크기 사이의 균형 조정.
4. **페이징** (Paging) : 물리 메모리를 고정 크기 프레임으로 나누어 불연속 배치를 허용함 → 외부 단편화를 구조적으로 없애며, 프레임 내부의 낭비는 남음.

## Ⅲ. 메모리 단편화의 구조 및 동작 메커니즘

- 핵심 요약 : 내부 단편화는 블록 안에서, 외부 단편화는 블록 사이에서 생기며 압축·버디 시스템·슬랩 할당자로 각각 다룸.

```text
[ 내부 단편화 : 블록 안의 낭비 ]

4KB 프레임 할당
   ↓
실제 데이터 1.2KB 사용
   ↓
나머지 2.8KB는 블록 내부에서 낭비
```

```text
[ 외부 단편화 : 블록 사이의 조각 ]

프로세스 A (점유 중)
   ↓
빈 공간 10MB
   ↓
프로세스 B (점유 중)
   ↓
빈 공간 15MB
   ↓
합계 25MB지만 연속 20MB 요구 불가
```

- **압축** (Compaction) : 점유 중인 블록을 한쪽으로 밀어 빈 공간을 하나로 합치는 방식으로, 외부 단편화를 직접 해소하는 방식.
- **버디 시스템** (Buddy System) : 메모리를 2의 거듭제곱 크기 블록으로 나누고 짝이 되는 빈 블록을 병합하여 외부 조각을 줄임.
- **슬랩 할당자** (Slab Allocator) : 커널 객체 크기별 캐시 풀을 미리 만들어 두어 객체 할당에서 생기는 내부 낭비를 줄임.
- 운영체제의 2계층 구조 : 페이지 단위 할당은 외부 단편화를, 커널 객체 단위 슬랩 할당은 내부 단편화를 나누어 담당.

## Ⅳ. 메모리 단편화의 비교

- 핵심 요약 : 내부와 외부 단편화는 원인과 낭비 위치가 달라 해결 기법과 성능 부담도 달라짐.

| 비교 항목 | 내부 단편화 (Internal) | 외부 단편화 (External) |
| --- | --- | --- |
| 발생 원인 | 고정 크기 분할, 페이징 | 가변 크기 분할, 세그멘테이션 |
| 낭비 공간 위치 | 할당된 블록 내부의 잔여 공간 | 할당된 블록들 사이의 유휴 조각 |
| 대표 해결 기법 | 슬랩 할당자, 적정 페이지 크기 선정 | 페이징 기반 가상 메모리, 압축, 버디 시스템 |
| 성능 부담 | 탐색은 빠르나 공간 낭비 발생 | 빈 공간 탐색 비용과 재배치 부하 |
| 대응 사례 | 리눅스 커널 kmalloc의 슬랩 캐시 | 리눅스 버디 할당자의 2의 거듭제곱 병합 |

- 선택 기준 : 할당 단위의 크기가 요구 크기와 얼마나 맞는지, 재배치 비용을 감당할 수 있는지에 따라 기법을 고름.

## Ⅴ. 메모리 단편화의 한계와 방안

- 핵심 요약 : 대용량 페이지의 내부 낭비, 압축 중 정지, 장기 가동 서버의 힙 파편화를 워크로드별 설정으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| Huge Page 사용 시 내부 낭비 | TLB (Translation Lookaside Buffer) 미스를 줄이려 대용량 페이지를 쓰면 작은 프로세스에서 큰 블록이 낭비됨 | 대규모 연속 메모리를 쓰는 프로세스(JVM (Java Virtual Machine) 힙, DB (Database) 버퍼풀)에만 명시적으로 바인딩 | 프로세스별 할당 대비 실사용 비율 |
| 압축 중 실행 정지 | 프로세스를 이동하고 주소를 재배치하면서 CPU 점유와 일시 정지가 발생 | 물리 이동 대신 MMU (Memory Management Unit)의 매핑 테이블만 갱신해 논리적 연속성 제공 | 정지 시간, 압축 빈도 |
| 장기 가동 서버의 힙 파편화 | C/C++ 서버에서 할당과 해제가 반복되어 전체 여유는 있어도 malloc 실패 발생 | 파편화를 줄이도록 설계된 jemalloc, tcmalloc 같은 할당자 링크 | 힙 단편화율, malloc 실패 횟수 |

## Ⅵ. 메모리 단편화에 대한 기술사적 제언

- 핵심 요약 : 메모리 압력의 상시 관측, 동시성 압축 런타임, 정적 풀링을 조합해 단편화를 운영 지표로 관리하는 체계로 발전.

1. 플랫폼 조직이 Cgroups v2의 **PSI** (Pressure Stall Information)를 수집해 메모리 압력을 상시 감시하고, 임계치 도달 시 워크로드를 분산하는 자동 대응 체계를 구축.
2. 애플리케이션 설계 단계에서 힙 압축을 동시에 수행하는 ZGC나 Shenandoah 같은 가비지 컬렉터를 검토하여 압축에 따른 정지 시간을 짧게 유지.
3. 임베디드와 고신뢰성 장비는 요구 메모리를 기동 시점에 정적 풀로 확보하여 동적 할당의 시간 편차를 배제하는 설계를 채택.

## Ⅶ. 결론

- 핵심 요약 : 메모리 단편화는 블록 안팎의 낭비로 나타나는 자원 관리 문제이며, 페이징·버디·슬랩·압축의 조합으로 제어.
- 시사점 : 단편화를 완전히 없애는 대상이 아니라 할당 단위와 재배치 비용 사이의 균형으로 보고 설계할 때 이용률 저하를 억제 가능.
