## 연관 키워드

- 멀티 리전 Active-Active, 재해복구(DR, Disaster Recovery), 리전(Region), RTO(Recovery Time Objective), RPO(Recovery Point Objective)
- Anycast, 셀 기반 아키텍처(Cell-Based Architecture), 분산 합의(Consensus), CRDT(Conflict-Free Replicated Data Type)
- 쓰기 충돌(Write Conflict), LWW(Last-Write-Wins), 서킷 브레이커(Circuit Breaker), RTT(Round-Trip Time), 2PC(Two-Phase Commit)

## Ⅰ. 멀티 리전 Active-Active 재해복구의 개요

- 핵심 요약 : 둘 이상의 지역 거점이 실트래픽을 동시에 처리하여 한 거점의 전면 중단에도 서비스와 데이터를 지키는 **멀티 리전 Active-Active** 구조의 재해복구(DR, Disaster Recovery) 아키텍처.
- 개념 : 지리적으로 분리된 둘 이상의 클라우드 **리전** (Region)에 애플리케이션과 데이터 계층을 상시 가동하고 모든 리전이 대고객 트래픽을 나눠 처리하도록 구성한 아키텍처. 리전 단위 장애를 전제로 **RTO** (Recovery Time Objective, 목표 복구 시간)와 **RPO** (Recovery Point Objective, 목표 복구 시점)를 설계 목표로 삼음.
- 배경 및 필요성 : 리전 전체의 정전·재난 사고는 드물지만 피해 규모가 크고, 평시 대기형 구성은 전환 중단 시간과 복제 지연분 손실이라는 비용을 수반. 중단 비용이 큰 글로벌·금융 서비스에서 동시 가동 구조의 필요성 제기.
- 주요 목적 : RTO·RPO의 최소화, 리전 간 부하 분산을 통한 사용자 체감 응답 시간 단축, 평시 자원의 실가동 활용.

## Ⅱ. 멀티 리전 Active-Active 재해복구의 특징 및 장점

- 핵심 요약 : 근접 라우팅과 셀 단위 쓰기 집중, 분산 합의·충돌 병합의 결합으로 여러 리전의 동시 쓰기에서도 정합성을 유지하는 구조.

1. **Anycast** 라우팅 : 동일 주소를 여러 리전에서 광고하고 헬스 체크 실패 리전의 경로 광고를 거둠 → 사용자를 가까운 정상 리전으로 유도, 장애 리전 유입의 자동 차단.
2. **셀 기반 아키텍처** (Cell-Based Architecture) : 고객 식별자 같은 샤드 키로 홈 리전을 지정해 쓰기를 한 리전에 집중 → 원거리 동시 쓰기의 원천 감소.
3. **분산 합의** (Consensus) 기반 데이터베이스 : Raft·Paxos 같은 합의 알고리즘을 리전 간으로 확장해 과반 확인 후 커밋 → 정상 커밋 쓰기의 무손실 목표 달성.
4. **CRDT** (Conflict-Free Replicated Data Type, 무충돌 복제 데이터 타입) : 동시 수정을 정해진 병합 규칙으로 자동 수렴 → 최종 일관성 데이터의 충돌 처리를 응용 로직에서 분리.

## Ⅲ. 멀티 리전 Active-Active 재해복구의 구조 (흐름)

- 핵심 요약 : 요청은 글로벌 라우팅으로 리전에 분배되고, 각 리전의 로컬 처리 결과는 복제 계층의 합의·병합으로 정합성을 맞추는 구조.

```text
[ 요청 처리 흐름 ]

글로벌 사용자
      ↓
Anycast · 글로벌 로드 밸런서
      ↓ 지연 기반 분배
리전 A (서울)   리전 B (도쿄)
      ↓               ↓
리전별 로컬 서비스 처리
```

```text
[ 데이터 복제와 충돌 해소 ]

리전 A의 로컬 커밋
      ↓
합의(Raft·Paxos) 또는 비동기 복제
      ↓
리전 B 복제본 반영
      ↓
동시 수정 발생 시 병합 규칙 적용
```

- 구성요소 : 글로벌 라우팅 계층, 리전별 서비스·캐시 계층, 리전 간 복제를 담당하는 데이터 계층으로 구성되며, 복제 방식의 선택이 RPO를 결정.
- 정합성 트레이드오프 : 리전 간 합의 커밋은 왕복 지연이 쓰기 응답에 포함되므로, 지연 허용 데이터와 무손실 데이터의 구분 설계가 전제.

## Ⅳ. 복제·정합성 방식의 비교

- 핵심 요약 : 합의 기반 다중 라이터, 단일 라이터 비동기 복제, CRDT 기반 최종 일관성이 RPO·지연·충돌 처리에서 서로 다른 선택지.

| 비교 항목 | 합의 기반 다중 라이터 | 단일 라이터 비동기 복제 | CRDT 기반 최종 일관성 |
| --- | --- | --- | --- |
| 커밋 기준 | 과반 리전 확인 후 커밋 | 기본 리전 커밋 후 복제 | 로컬 커밋 후 백그라운드 병합 |
| RPO | 커밋 쓰기 무손실 목표 | 복제 지연분 손실 가능 | 병합 규칙으로 수렴 |
| 쓰기 지연 | 리전 간 **RTT** (Round-Trip Time) 포함 | 낮음 | 낮음 (로컬 커밋) |
| 충돌 처리 | 직렬화로 원천 방지 | 발생하지 않음 | **LWW** (Last-Write-Wins) 등 규칙 병합 |
| 적합 데이터 | 계좌·결제 등 핵심 데이터 | 읽기 중심 서비스 | 카운터·협업 편집 등 병합 가능 데이터 |

- 선택 기준 : 데이터별 무손실 요구가 높으면 합의 기반을, 읽기 확장이 목적이면 단일 라이터 복제를, 병합 가능한 데이터는 CRDT를 택하는 판단 기준.

## Ⅴ. 멀티 리전 Active-Active 재해복구의 한계와 방안

- 핵심 요약 : 원거리 지연, 동시 수정 분기, 장애 전파를 쓰기 소유권 분할·병합 규칙·과부하 차단으로 대응하는 원칙.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 리전 간 왕복 지연 | 원거리 리전 간 모든 쓰기에 **2PC** (Two-Phase Commit)를 적용하면 응답 지연이 급증 | 데이터 소유권을 홈 리전에 두는 로컬 쓰기, 타 리전은 비동기 복제·읽기 복제본 활용 | 리전 간 복제 지연, 응답 시간 분포 |
| **쓰기 충돌** (Write Conflict) | 두 리전의 동시 수정으로 분기 발생, 수렴 실패 | 시계 오차를 감안한 LWW 규칙, 핵심 데이터의 CRDT 구조 설계 | 충돌 감지 건수, 병합 실패율 |
| **연쇄 붕괴** (Cascading Failure) | 한 리전 중단 시 잔여 리전이 전체 트래픽을 떠안아 포화·동반 중단 | **서킷 브레이커** (Circuit Breaker) 차단과 전환 감당용 여유 용량(Headroom) 확보 | 리전별 가동률, 서킷 개방 횟수 |

## Ⅵ. 멀티 리전 Active-Active 재해복구에 대한 기술사적 제언

- 핵심 요약 : 서비스 등급별 복구 목표의 계층화, 데이터 정합성 요구의 설계 초기 확정, 표준 참조 아키텍처의 코드화로 구현 품질을 확보하는 방향.

1. 아키텍처 심의 조직은 서비스 중요도 등급별 RTO·RPO 목표표를 수립하고, 등급에 따라 Active-Active와 대기형 구성의 선택 기준을 설계 문서로 표준화한다.
2. 데이터 설계 조직은 엔티티별 정합성 요구(무손실·최종 일관성)를 스키마 설계 단계에서 확정하고, 분류 기준을 데이터 카탈로그에 등록하는 절차를 운영한다.
3. 플랫폼 조직은 글로벌 라우팅·헬스 체크·리전 격리 구성을 코드형 인프라(IaC, Infrastructure as Code) 템플릿으로 표준 참조 아키텍처화한다.

## Ⅶ. 결론

- 핵심 요약 : 멀티 리전 Active-Active는 라우팅·쓰기 집중·합의·병합의 조합으로 RTO와 RPO를 최소화하는 최상위 가용성 구조.
- 모든 시스템의 기본값이 아니라 중단 비용이 복제 비용을 초과하는 핵심 데이터와 업무에 정당화되는 설계 선택.
