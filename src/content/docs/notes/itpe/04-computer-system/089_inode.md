컴퓨터 시스템 및 네트워크 → 파일시스템 → 파일 메타데이터와 데이터 연결

## 30초 인출

- 본질: **inode (Index Node)는** Unix 계열 파일시스템에서 파일 객체의 메타데이터와 데이터 위치 정보를 관리하는 자료구조
- 메커니즘: 디렉터리 이름 → inode 번호 → inode 메타데이터·데이터 블록 참조

- 통찰: 한계: 데이터 용량에 여유가 있어도 inode가 고갈되면 새 파일 생성 실패 → 방안: 파일 수·inode 사용량과 블록 용량을 함께 감시

<details>
<summary>핵심 용어</summary>

- **inode (Index Node)** : 파일의 유형·권한·소유자·크기·시간·데이터 블록 정보를 저장하는 파일시스템 자료구조
- **디렉터리 엔트리 (Directory Entry)** : 파일 이름과 해당 파일시스템 내 inode 번호를 연결하는 디렉터리의 항목
- **하드 링크 (Hard Link)** : 같은 inode를 가리키는 추가 디렉터리 엔트리
- **심볼릭 링크 (Symbolic Link)** : 대상 경로명을 내용으로 저장하는 별도 파일 객체
- **링크 수 (Link Count)** : inode를 참조하는 디렉터리 링크 수를 나타내는 메타데이터 값

## 2~4교시 25점 답안

## Ⅰ. inode의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **inode (Index Node)는** 파일시스템에서 파일 객체의 메타데이터와 데이터 위치 정보를 관리하는 자료구조 |
| 목적 | 파일 이름 공간과 파일 객체·데이터 저장 위치를 분리해 파일을 관리하는 것 |

## Ⅱ. 이름과 파일 객체를 분리하는 특징

| 특징 | 의미 |
|---|---|
| 이름 분리 | 파일 이름은 디렉터리 엔트리, 객체 메타데이터는 inode에 저장 |
| 객체 식별 | 유형·권한·소유자·크기·시간·링크 수를 inode로 관리 |
| 내용 참조 | inode가 데이터 블록 또는 extent의 위치를 참조 |

## Ⅲ. 경로 탐색과 파일 내용 접근 체계

```text
경로명 → 디렉터리 엔트리(이름·inode 번호)
                     ↓
          inode(메타데이터·블록 참조)
                     ↓
             파일 데이터 블록
```

경로의 각 디렉터리를 차례로 탐색해 마지막 inode를 찾는다. 이름을 삭제하면 엔트리와 링크 수가 바뀌며, 링크가 없고 열린 참조도 해제된 뒤 실제 공간을 회수할 수 있다.

## Ⅳ. 하드 링크와 심볼릭 링크의 관계

| 구분 | 하드 링크 | 심볼릭 링크 |
|---|---|---|
| 참조 | 같은 파일시스템의 동일 inode | 대상 경로명을 담은 별도 inode |
| 이름 삭제 | 다른 하드 링크가 남으면 객체 유지 | 링크만 삭제되며 대상은 별도 |
| 경계 | 일반적으로 파일시스템 경계를 넘지 않음 | 다른 파일시스템 경로도 가리킬 수 있음 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 데이터 블록에 여유가 있어도 inode 부족으로 새 파일 생성 제한 | 파일 수·inode 사용량·디렉터리 증가를 용량과 함께 감시 |
| 이름·inode·블록 중 손상 위치에 따라 증상이 달라짐 | 엔트리·메타데이터·블록 참조를 파일시스템 도구로 점검하고 백업 기반 복구 |
| 경로만 보면 하드 링크·삭제 후 열린 파일의 실제 상태를 놓침 | inode 식별자·링크 수·열린 참조를 함께 수집 |

## Ⅵ. 제언 — 장애 시 경로와 inode를 함께 추적

파일 생성 실패나 미회수 용량이 보이면 디스크 사용량뿐 아니라 inode 사용량·링크 수·열린 참조를 먼저 확인하는 진단 절차를 둔다.
