## Ⅰ. 프로세스 동기화 기법의 개요

- 개념 : 멀티프로세스 및 멀티스레드 환경에서 둘 이상의 실행 흐름이 공유 자원(메모리 변수, 파일, I/O 장치 등)에 동시 접근할 때, 데이터의 일관성(Consistency)과 무결성을 유지하고 **경쟁 상태** (Race Condition)를 방지하기 위해 프로세스 간 실행 순서를 조정하고 **임계 영역** (Critical Section) 진입을 직렬화하는 운영체제 동시성 제어 기법.
- 배경 및 필요성 : 병렬 실행으로 인해 **원자성** (Atomicity)이 보장되지 않는 다중 명령어 구간에 동시 진입할 경우 데이터 왜곡, **무한 대기** (Deadlock), **기아 상태** (Starvation) 등 치명적 결함이 발생함.
- 핵심 목적 : 임계 영역 3대 요구조건(상호 배제, 진행, 한정 대기)의 완벽한 충족, 자원 접근 동기화 및 시스템 신뢰성 보장.

## Ⅱ. 3대 동기화 메커니즘(뮤텍스, 세마포어, 모니터)의 핵심 아키텍처

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 프로세스 동기화 3대 핵심 기법 동작 메커니즘 ]                       │
│                                                                        │
│   [ 1. 뮤텍스 (Mutex: Mutual Exclusion Object) ]                       │
│    - 소유권(Ownership) 개념이 있는 바이너리 키(Key) 방식              │
│    - Lock을 획득(Acquire)한 바로 그 스레드만 해제(Release) 가능       │
│    - 스레드 A: lock() ──> [임계 영역 실행] ──> unlock()               │
│                                                                        │
│   [ 2. 계수 세마포어 (Counting Semaphore: Dijkstra 고안) ]             │
│    - 소유권 없음 (카운터 $S$로 가용 자원 수 관리)                      │
│    - P 연산 (wait / sem_wait): 자원 차감($S--$), $S < 0$이면 대기 큐 진입│
│    - V 연산 (signal / sem_post): 자원 반환($S++$), 대기 프로세스 깨움 │
│    * 신호 전달(Signaling) 메커니즘으로 생산자-소비자 패턴 구현         │
│                                                                        │
│   [ 3. 모니터 (Monitor: 고수준 동기화 추상화 구조) ]                   │
│    ┌──────────────────────────────────────────────────────────┐        │
│    │ 공유 변수 및 상태 데이터 (외부 직접 접근 절대 금지)     │        │
│    ├──────────────────────────────────────────────────────────┤        │
│    │ 동기화 프로시저: 한 번에 단 1개의 스레드만 진입 허용    │        │
│    │  - 조건 변수 (Condition Variables: x, y)                 │        │
│    │    * x.wait() : 조건 미충족 시 락을 풀고 조건 큐에서 대기│        │
│    │    * x.signal(): 대기 중인 다른 스레드를 깨움 (Mesa/Hoare)│       │
│    └──────────────────────────────────────────────────────────┘        │
└────────────────────────────────────────────────────────────────────────┘
```

- 임계 영역(Critical Section)의 3대 필수 요건 :
  - **상호 배제** (Mutual Exclusion) : 한 프로세스가 임계 영역에서 실행 중이면 다른 프로세스는 절대 진입할 수 없음.
  - **진행** (Progress) : 임계 영역에 진입한 프로세스가 없을 때 진입하고자 하는 후보 프로세스들만 경쟁에 참여하며 무한 연기 불가.
  - **한정 대기** (Bounded Waiting) : 프로세스가 임계 영역 진입을 요청한 후 허가될 때까지 다른 프로세스의 진입 횟수에 상한이 있어야 함(기아 방지).

## Ⅲ. 뮤텍스, 세마포어, 모니터 비교 분석

| 비교 항목 | 뮤텍스 (Mutex) | 세마포어 (Semaphore) | 모니터 (Monitor) |
| :--- | :--- | :--- | :--- |
| **추상화 수준** | 운영체제 커널/하드웨어 객체 | 운영체제 정수형 동기화 변수 | 고수준 프로그래밍 언어 구조물 |
| **자원 개수** | 단 1개 자원 (이진 락) | 1개(Binary) 또는 다수(Counting)| 언어 클래스/객체 단위 캡슐화 |
| **소유권** (Ownership)| 반드시 락을 건 스레드가 해제| 소유권 없음 (A가 잠그고 B가 해제 가능)| 모니터 락을 획득한 진입 스레드 |
| **주요 용도** | 단일 임계 영역 상호 배제 | 다중 자원 풀 제어, 순서 동기화 | 안전한 객체 상태 동기화 (Java 등)|
| **동작 함수** | `acquire()`, `release()` | `P() / wait()`, `V() / signal()`| `synchronized`, `wait()`, `notify()`|
| **인간 실수 위험** | 상대적으로 적음 | P/V 순서 뒤바뀜 시 데드락 유발 | 컴파일러가 상호 배제를 자동 보장 |

## Ⅳ. 동기화 기법 적용 시 주요 문제점 및 해결 방안

- 우선순위 역전(Priority Inversion) 현상 :
  - 한계점 : 낮은 우선순위 작업 L이 락을 쥐고 있는 동안 중간 우선순위 작업 M이 선점하여, 높은 우선순위 작업 H가 L을 기다리며 무한 지연(화성 탐사선 패스파인더 실제 사고).
  - 해결 방안 : 우선순위 상속(Priority Inheritance: 락을 쥔 L의 우선순위를 H 수준으로 일시 승격) 또는 우선순위 올림(Priority Ceiling) 프로토콜 적용.
- 부적절한 락 순서로 인한 상호 교착상태(Deadlock) :
  - 한계점 : 스레드 1이 락 A를 쥐고 B를 대기, 스레드 2가 락 B를 쥐고 A를 대기하여 순환 대기(Circular Wait) 발생.
  - 해결 방안 : 모든 락에 전역 순서(Lock Ordering)를 부여하여 오름차순으로만 획득 강제, 락 획득 타임아웃(`tryLock()`) 적용.
- 모니터의 조건 신호 의미론(Mesa vs Hoare) 불일치 :
  - 한계점 : `signal()` 발생 시 대기 스레드가 깨어났으나 즉시 실행되지 못하고 준비 큐로 이동(Mesa 방식)할 경우 조건이 다시 거짓으로 바뀔 수 있음.
  - 해결 방안 : 조건 검사를 단일 `if`문 대신 `while` 루프(`while (!condition) { wait(); }`)로 작성하여 재검증 강제.

## Ⅴ. 안전한 동시성 프로그래밍을 위한 기술사적 제언

- 고수준 모니터 및 락프리(Lock-Free) 원자적 연산 우선 채택 : 실무 개발에서 프로그래머의 실수로 데드락을 유발하기 쉬운 저수준 세마포어 직접 조작을 지양하고, 언어 차원의 모니터 구조(Java `ReentrantLock`, `ConcurrentHashMap`)나 하드웨어 CAS(Compare and Swap) 명령어 기반의 원자적 변수(`AtomicInteger`)를 표준으로 채택해야 함.
- 동시성 정적 검증 및 런타임 레이스 디텍터 필수화 : 코드 리뷰 단계에서 락 점유 범위를 최소화(Fine-Grained Locking)하고, 빌드 파이프라인에 ThreadSanitizer(TSan)를 연계하여 런타임 동기화 누락 및 데이터 레이스를 사전에 자동 검출할 것을 제언함.
