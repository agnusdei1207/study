## Ⅰ. 간헐적 컴퓨팅(Intermittent Computing)의 개요

- 핵심 요약 : **간헐적 컴퓨팅**은 에너지 하베스팅 환경에서 전원 상실에도 상태를 보존하여 작업을 완수하는 배터리리스 컴퓨팅 패러다임.
- 개념 : 배터리 없이 태양광, RF(Radio Frequency), 진동, 열 등 주변 환경에서 에너지를 **수확(Energy Harvesting)** 하여 작동하는 극초저전력 사물인터넷(IoT, Internet of Things) 장치가 에너지 고갈로 인해 빈번한 **전원 상실** (Power Failure)과 재부팅을 겪는 상황에서도, 연산 상태를 안전하게 보존하고 전원 복구 시 이전 지점부터 작업을 성공적으로 완수해 나가는 차세대 컴퓨팅 패러다임.
- 배경 및 필요성 : 화학 배터리의 물리적 부피, 교체 주기, 환경 오염 한계로 인해 접근 불가능한 극한 환경(인체 삽입형 의료 기기, 스마트 빌딩 매립 센서, 우주 탐사 큐브위성 등)에서 배터리 없는 자율 영구 동작 요구 급증.
- 핵심 목적 : 에너지 하베스팅의 간헐적(Intermittent) 전력 환경에서 연산의 **전진 진행(Forward Progress)** 보장, **비휘발성 메모리(NVM)** 기반 상태 일관성 유지 및 전력 장애 복원력 확보.

## Ⅱ. 간헐적 컴퓨팅(Intermittent Computing)의 특징 및 장점

- 핵심 요약 : **체크포인팅·태스크 기반 모델**로 전원 상실에도 상태 보존.
1. **체크포인팅(Checkpointing)** : 전압 강하 인터럽트 발생 시 또는 코드의 특정 지점에서 레지스터와 프로그램 카운터(PC, Personal Computer), 휘발성 메모리 상태를 FRAM 등 비휘발성 메모리에 원자적으로 백업.
2. **태스크 기반 모델(Task-Based Programming)** : 프로그램을 원자적으로 실행 가능한 작은 태스크 단위의 방향성 비순환 그래프(DAG, Directed Acyclic Graph)로 분할하여, 태스크 완료 시에만 입출력 상태를 커밋하여 멱등성(Idempotency) 보장.

## Ⅲ. 간헐적 컴퓨팅(Intermittent Computing)의 구조 및 동작 메커니즘

- 핵심 요약 : **충전 → 복원 → 연산 → 체크포인팅 → 전원 상실 → 재충전** 루프.
- 간헐적 컴퓨팅은 에너지 하베스터 → PMU → MCU/NVM → 체크포인팅 → 전원 상실 → 재충전의 루프로 동작함.

```text
[ 간헐적 컴퓨팅 시스템 구조 및 전원 장애 복구 수명주기 ]

   [ 환경 에너지 하베스터 (Solar / RF / Piezo) ]
                     │ 에너지 충전 (Energy Accumulation)
                     ▼
   [ 전력 관리 회로 (Power Management Unit & 커패시터) ]
                     │ 임계 전압 도달 (V_on) / 전원 상실 임계치 (V_off)
                     ▼
   ┌────────────────────────────────────────────────────────────────┐
   │ [ 간헐적 컴퓨팅 프로세서 (MCU + NVM) ]                         │
   │                                                                │
   │  (1) 전원 켜짐 (V > V_on) ──> 이전 체크포인트/태스크 상태 복원 │
   │            │                                                   │
   │            ▼                                                   │
   │  (2) 연산 수행 (Task Execution in SRAM)                        │
   │            │                                                   │
   │            ▼                                                   │
   │  (3) 체크포인팅 (Checkpointing to NVM: FRAM/MRAM)             │
   │      - 레지스터, 스택, 전역 변수 원자적 커밋                   │
   │            │                                                   │
   │            ▼                                                   │
   │  (4) 전원 상실 (Power Crash! V < V_off)                        │
   │      - 휘발성 SRAM 데이터 소멸, NVM 데이터 무결성 보존         │
   │            │                                                   │
   │            └──── 에너지 재충전 ────> (1)로 루프 (Forward Progress)│
   └────────────────────────────────────────────────────────────────┘
```

## Ⅳ. 간헐적 컴퓨팅(Intermittent Computing)의 비교

- 핵심 요약 : **체크포인팅 vs 태스크 기반** 복구 지점·NVM 쓰기·I/O·개발자 부담 비교.

| 비교 항목 | 체크포인팅 기반 (Reactive/Periodic) | 태스크 기반 모델 (Task-Based DAG) |
| :--- | :--- | :--- |
| 동작 원리 | 전압 강하 감지 시 또는 일정 주기마다 전체 메모리 스냅샷 NVM 기록 | 프로그램을 멱등성을 가진 작은 함수 단위로 쪼개어 단계별 커밋 |
| 대표 시스템 | QuickRecall, Mementos, Hibernus | Alpaca, Mayfly, Coala, InK |
| 복구 지점 | 가장 최근 성공한 체크포인트 위치 | 중단된 현재 태스크의 시작 지점 |
| NVM 쓰기 오버헤드 | 전체 시스템 컨텍스트 저장으로 에너지 소모 큼 | 태스크의 입력/출력 변수만 선택적 기록하여 에너지 절감 |
| I/O 및 사이드이펙트 | 외부 센서 I/O 재실행 시 중복 센싱 오류 발생 가능 | 채널 기반 데이터 전달로 사이드 이펙트 원천 제어 |
| 개발자 부담 | 투명한 자동화 지원으로 개발자 개입 적음 | 프로그램을 DAG 태스크 구조로 재설계해야 하는 부담 |

## Ⅴ. 간헐적 컴퓨팅(Intermittent Computing)의 한계와 방안

- 핵심 요약 : **사이드 이펙트 재실행·무한 재부팅 루프·시간 소실**을 저널링·태스크 세분화·RTC로 대응.

- **사이드 이펙트(Side-Effect)** 재실행으로 인한 데이터 불일치(WAR 오류) :
  - 한계점 : 전원 복구 후 중단된 구간을 재실행할 때, 이미 갱신된 비휘발성 전역 변수를 다시 읽어 연산 오류(Write-After-Read 충돌) 유발.
  - 해결 방안 : 메모리 롤백 저널링(Undo-Redo Logging) 적용, 컴파일러 단계의 정적 분석을 통한 멱등 구간 식별 및 변수 버전 관리(Multi-versioning).
- 에너지 충전량 부족에 따른 무한 재부팅 **루프(Livelock)** :
  - 한계점 : 단일 체크포인트 저장 또는 단일 태스크를 완료하는 데 필요한 최소 에너지가 커패시터 충전 용량보다 커서 영원히 전진하지 못함.
  - 해결 방안 : 태스크 세분화(Sub-tasking), 적응형 동적 체크포인팅(전력 유입량에 따라 태스크 경계 동적 분할), 초저전력 커패시터 사이징 최적화.
- **시간 소실** (Time Disruption)과 타이머 연속성 단절 :
  - 한계점 : 전원이 꺼져 있는 동안 하드웨어 클록이 정지하여 시스템이 경과 시간을 인지하지 못하고 센서 시계열 데이터 타임스탬프 왜곡.
  - 해결 방안 : 잔여 전하 방전 속도로 시간을 추정하는 과도 시간 측정 회로(Transient RTC) 또는 초저전력 하베스팅 구동 RTC 탑재.

## Ⅵ. 간헐적 컴퓨팅(Intermittent Computing) 적용 제언

- 핵심 요약 : **FRAM/MRAM MCU·배터리리스 IoT 표준**.
- 비휘발성 메모리(FRAM/MRAM) 기반 올인원 MCU 생태계 선점.
- 탄소 제로 그린 IoT 및 우주·국방 인프라 표준화 : 배터리리스 기기 표준 규격 선제 제정.

## Ⅶ. 결론

- 핵심 요약 : 간헐적 컴퓨팅은 **에너지 하베스팅 환경의 전진 진행 보장**을 위해 체크포인팅·태스크 기반·FRAM으로 상태를 보존하나 사이드 이펙트·루프·시간 소실 리스크 관리가 필수.
- 간헐적 컴퓨팅은 에너지 하베스팅 환경에서 전진 진행을 보장하기 위해 체크포인팅·태스크 기반·FRAM으로 상태를 보존하지만, 사이드 이펙트·무한 루프·시간 소실 리스크를 저널링·태스크 세분화·RTC로 관리해야 함.
- 답안에는 체크포인팅/태스크 기반 비교, 4단계 수명주기, 한계·대응, FRAM/MRAM·그린 IoT 제언을 연결. (PC(Personal Computer)는 프로그램 카운터(PC, Program Counter)의 약자로 본문에서는 프로그램 카운터로 통일.)
