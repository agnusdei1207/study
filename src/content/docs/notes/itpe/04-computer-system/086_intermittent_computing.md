## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 인터미턴트 컴퓨팅

## 30초 인출

- 본질: 배터리를 넣을 수 없는 초소형 IoT 센서는 주변 환경에서 에너지를 수확하지만 전력이 수시로 끊겨 프로그램이 처음부터 무한 재부팅되는 문제가 발생함
- 메커니즘: 전원 차단 직전의 연산 상태를 비휘발성 메모리(FRAM)에 체크포인트로 백업하고 전원 복구 시 그 자리부터 즉시 이어 실행

## 핵심 용어

- 에너지 하베스팅(Energy Harvesting): 태양광, 실내 조명, 진동, 체온, RF 전파 등 주변 환경에서 버려지는 미세 에너지를 수확해 전기에너지로 변환하는 기술
- FRAM(Ferroelectric RAM): D램 수준의 고속 쓰기가 가능하면서도 전원이 꺼져도 데이터가 보존되는 강유전체 기반 초저전력 비휘발성 메모리
- 멱등적 실행(Idempotent Execution): 전원 차단으로 인해 동일한 코드 블록이 여러 번 재실행되더라도 메모리 상태가 오염되지 않고 동일한 결과를 보장하는 성질

```text
   │ / (충전 대기)   [CheckPoint!]\/ (충전 대기)   [CheckPoint!]\
```


### Ⅱ. 핵심 특성

- 배터리(Chemical Battery)는 사물인터넷의 가장 큰 적임 → 수명(2~3년)이 짧아 수백만 개의 스마트 시티 센서 배터리를 교체하는 것은 불가능하며 폭발 위험과 환경 오염을 초래하므로 '배터리리스(Battery-less)'가 필수적임
- 단순 재부팅은 '무한 루프'에 갇힘 → 작업 실행 시간이 수확한 에너지 버퍼(슈퍼커패시터) 방전 시간보다 길면, 영원히 작업을 끝내지 못하고 1단계에서 뻗었다가 다시 1단계로 부팅하는 '재부팅 감옥'에 갇힘 → 작업을 작게 쪼개는 테스크 분할이 핵심임
- 비휘발성 메모리(NVM)만 쓴다고 해결되지 않음 → 비휘발성 메모리에 데이터를 쓰던 도중 전원이 나가면 이전 데이터와 새 데이터가 섞여 메모리 일관성이 파괴되므로, 저널링이나 섀도 페이징 같은 트랜잭션 보호가 필요함

### Ⅲ. 관련 개념과 구분

- 저전력 슬립(Duty Cycling) vs 인터미턴트 컴퓨팅: 저전력 슬립 = 배터리가 항상 전원을 공급하며 MCU가 주기적으로 슬립 모드에 들어감 / 인터미턴트 = 전원 자체가 0V로 완전히 끊어지며 에너지 충전 시에만 간헐적 기동

### Ⅳ. 적용 문제와 대응

- 사례: 134회 기출 및 체내 삽입형 의료 센서에서 전력 수확 불안정으로 인한 데이터 수집 루프 정지 장애
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 전원 차단과 재부팅 반복 시 공유 변수 값이 오염(Write-After-Read 해저드) | 전원 복구 후 이전 체크포인트로 롤백되었으나 NVM의 공유 변수는 이미 갱신된 상태 | 정적 분석 컴파일러(Mayfly, Coati) 기반 멱등성 영역 자동 분할 | 재실행 시에도 메모리 무결성 100% 보존 |
| 체크포인트 생성 자체에 전력을 다 써서 실제 비즈니스 연산 진척 불가 | 전원 차단 시점마다 레지스터와 RAM 전체를 무조건 NVM에 덤프 | 변경된(Dirty) 페이지만 부분 저장하는 증분(Incremental) 체크포인팅 | 체크포인트 소요 시간 및 전력 70% 절감 |

### Ⅴ. 기술사적 제언

| 문제 | 해결 방안 |
|---|---|
| 적용 환경에서 발생하는 핵심 제약 | 기존 대책을 적용하고 핵심 운영 지표를 확인해 개선한다. |
