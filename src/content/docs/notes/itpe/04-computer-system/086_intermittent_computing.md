## 연관 키워드

- 간헐적 컴퓨팅(Intermittent Computing), 에너지 하베스팅(Energy Harvesting), 전진 진행

## Ⅰ. 간헐적 컴퓨팅(Intermittent Computing)의 개요

- 핵심 요약 : **간헐적 컴퓨팅** (Intermittent Computing)은 에너지 하베스팅 환경에서 전원이 반복적으로 끊겨도 상태를 보존하여 작업을 완료하는 배터리리스 컴퓨팅 방식.
- 개념 : 배터리 없이 태양광, RF(Radio Frequency), 진동, 열 등 주변 환경의 에너지를 **에너지 하베스팅** (Energy Harvesting)으로 모아 동작하는 초저전력 IoT(Internet of Things) 장치가, 잦은 전원 상실과 재부팅 속에서도 연산 상태를 보존하고 복구 후 중단 지점부터 작업을 이어가는 방식.
- 배경 및 필요성 : 화학 배터리의 부피, 교체 주기, 폐기 문제 때문에 인체 삽입형 의료 기기, 매립형 센서, 접근이 어려운 우주 장비처럼 배터리 교체가 현실적이지 않은 환경의 수요가 늘어남.
- 주요 목적 : 불안정한 전력 환경에서도 **전진 진행** (Forward Progress)을 보장하고, **비휘발성 메모리** (NVM, Non-Volatile Memory)로 상태 일관성을 유지하며, 전력 장애에 대한 복원력을 확보.

## Ⅱ. 간헐적 컴퓨팅(Intermittent Computing)의 특징 및 장점

- 핵심 요약 : 체크포인팅과 태스크 기반 모델이 전원 상실 시점에도 진행 상태를 일관되게 남기는 두 가지 방식.

1. **체크포인팅** (Checkpointing) : 전압이 임계치 아래로 떨어지기 전이나 프로그램의 정해진 지점에서 레지스터, 프로그램 카운터(PC, Program Counter), 휘발성 메모리 상태를 FRAM(Ferroelectric Random-Access Memory) 같은 NVM에 원자적으로 백업 → 재부팅 후 마지막 저장 지점부터 재개.
2. **태스크 기반 모델** (Task-Based Programming) : 프로그램을 원자적으로 실행되는 작은 태스크 단위의 DAG(Directed Acyclic Graph)로 분할하고, 태스크가 끝날 때만 입출력 상태를 커밋 → 중간에 전원이 끊겨 태스크를 처음부터 다시 실행해도 결과가 같은 **멱등성** (Idempotency) 확보.

## Ⅲ. 간헐적 컴퓨팅(Intermittent Computing)의 구조 및 동작 메커니즘

- 핵심 요약 : 하베스터의 충전, 전압 임계치에 따른 복원과 연산, 체크포인팅, 전원 상실이 맞물려 반복되는 루프 구조.

```text
[ 간헐적 컴퓨팅 동작 루프 ]

에너지 하베스터 (태양광 · RF · 진동)
      ↓ 에너지 축적
PMU(Power Management Unit) · 커패시터
      ↓ 전압이 V_on 도달
상태 복원 (NVM에서 마지막 체크포인트 로드)
      ↓
연산 수행 (SRAM 태스크)
      ↓
체크포인팅 (레지스터 · 스택 · 전역 변수 커밋)
      ↓ 전압이 V_off 이하로 하강
전원 상실 → 재충전 후 복원 단계로 복귀
```

```text
[ 태스크 기반 실행 흐름 ]

태스크 A 실행 → 출력 변수 커밋 (NVM)
      ↓
태스크 B 실행 (입력은 채널에서 읽기)
      ↓ 전원 상실 시
태스크 B 시작 지점부터 재실행 (멱등)
```

## Ⅳ. 간헐적 컴퓨팅(Intermittent Computing)의 비교

- 핵심 요약 : 체크포인팅은 자동화와 투명성을, 태스크 기반 모델은 쓰기 에너지 절감과 사이드 이펙트 통제를 얻는 대신 개발 부담을 지는 구조.

| 비교 항목 | 체크포인팅 기반 (Reactive/Periodic) | 태스크 기반 모델 (Task-Based DAG) |
| :--- | :--- | :--- |
| 동작 원리 | 전압 강하 감지 시 또는 주기마다 상태 스냅샷을 NVM에 기록 | 프로그램을 멱등 태스크로 나누고 태스크 단위로 커밋 |
| 대표 연구 시스템 | Mementos, Hibernus | Alpaca, Mayfly, InK |
| 복구 지점 | 가장 최근 성공한 체크포인트 | 중단된 태스크의 시작 지점 |
| NVM 쓰기 비용 | 전체 컨텍스트 저장으로 쓰기 에너지 큼 | 입출력 변수만 선택 기록하여 쓰기 에너지 절감 |
| I/O 및 사이드 이펙트 | 재실행 시 외부 센서 I/O가 중복되어 오류 가능 | 채널 기반 데이터 전달로 사이드 이펙트를 통제 |
| 개발자 부담 | 자동화 지원으로 개발자 개입이 적음 | 프로그램을 DAG 태스크 구조로 재설계해야 함 |

## Ⅴ. 간헐적 컴퓨팅(Intermittent Computing)의 한계와 방안

- 핵심 요약 : 사이드 이펙트 재실행, 무한 재부팅 루프, 시간 소실을 저널링, 태스크 세분화, 저전력 RTC로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| **사이드 이펙트** (Side-Effect) 재실행 오류 | 재개 구간에서 이미 갱신된 비휘발성 전역 변수를 다시 읽어 연산이 어긋남 (WAR(Write-After-Read) 충돌) | 메모리 변경을 되돌리는 Undo-Redo 저널링 적용, 컴파일러 정적 분석으로 멱등 구간 식별 | 재실행 후 결과 일치율 |
| **무한 재부팅 루프** (Non-Termination) | 체크포인트 저장이나 태스크 하나를 끝내는 데 필요한 에너지가 커패시터 용량보다 커서 진행이 불가능 | 태스크 세분화, 전력 유입량에 따라 경계를 바꾸는 적응형 체크포인팅, 커패시터 용량 최적화 | 재부팅당 완료 태스크 수 |
| **시간 소실** (Time Disruption) | 전원이 꺼진 동안 하드웨어 클록이 멈춰 경과 시간을 알 수 없어 센서 데이터의 타임스탬프가 왜곡 | 잔여 전하의 방전 속도로 경과 시간을 추정하는 회로, 또는 초저전력 RTC(Real-Time Clock) 탑재 | 타임스탬프 오차 |

## Ⅵ. 간헐적 컴퓨팅(Intermittent Computing)에 대한 기술사적 제언

- 핵심 요약 : 비휘발성 메모리 기반 MCU와 배터리리스 기기 규격을 함께 갖추어 간헐적 컴퓨팅을 연구 단계에서 산업 표준으로 정착.

1. 반도체 조직은 FRAM이나 MRAM(Magnetoresistive Random-Access Memory)을 내장한 MCU(Microcontroller Unit) 제품군을 로드맵의 중심에 두고, 체크포인팅과 태스크 실행을 지원하는 런타임 소프트웨어를 함께 제공하여 개발자의 재설계 부담을 낮추는 방향을 검토.
2. 에너지 하베스팅 기기를 대량으로 배치하는 분야에서는 표준화 기관과 업계가 전원 상실에 대비한 상태 보존 방식과 시간 복원 요건을 규격으로 정의하여, 기기 간 호환성과 검증 기준을 마련하는 것이 바람직.

## Ⅶ. 결론

- 핵심 요약 : 간헐적 컴퓨팅은 체크포인팅, 태스크 기반 모델, 비휘발성 메모리로 전진 진행을 보장하지만, 사이드 이펙트·무한 루프·시간 소실 리스크를 함께 관리해야 하는 방식.
- 시사점 : 배터리 교체가 불가능한 환경에서 장기 자율 동작을 가능하게 하는 기반이며, 전원 상실을 전제로 한 상태 모델을 설계 단계에서 정의하는 것이 신뢰성의 핵심.
