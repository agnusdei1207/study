## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 에너지 수확형 단말 → 전원 단절을 고려한 실행

## 30초 인출

- 본질: **간헐적 컴퓨팅 (Intermittent Computing)은** 에너지 수확 등으로 전원이 반복 단절되는 장치에서 작업을 나눠 보존·재개하는 실행 방식
- 메커니즘: 에너지 확보 → 작업 실행 → 전력 부족 전 상태 보존 또는 일관된 작업 경계 도달 → 재충전 후 안전하게 재개
- 통찰: 배터리 없이 주변 환경 에너지(태양광, RF, 진동)를 수확하여 동작하는 극저전력 IoT 장치에서 잦은 정전 발생 시 비휘발성 메모리 체크포인팅으로 연산 연속성을 보장 체계화.

<details>
<summary>핵심 용어</summary>

- **간헐적 컴퓨팅 (Intermittent Computing)** : 불안정한 전원·에너지 수확 환경에서 실행 중단과 재개를 고려하는 컴퓨팅 방식
- **에너지 수확 (Energy Harvesting)** : 빛·진동·열 등 주변 에너지를 전기 에너지로 변환해 사용하는 기술
- **체크포인트 (Checkpoint)** : 중단 뒤 실행을 재개할 수 있도록 필요한 프로그램 상태를 보존하는 지점
- **영속 메모리 (Non-Volatile Memory)** : 전원이 끊겨도 저장 내용을 유지하는 메모리
- **원자적 작업 (Atomic Task)** : 중단·재실행 시 부분 효과가 노출되지 않도록 실행 경계를 설계한 작업 단위
</details>

## 2~4교시 25점 답안

## Ⅰ. 간헐적 컴퓨팅의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **간헐적 컴퓨팅 (Intermittent Computing)은** 실행 중 전원 중단이 가능한 환경에서 작업 상태 보존과 재개를 고려하는 컴퓨팅 방식 |
| 목적 | 배터리·상시 전원에 의존하기 어려운 단말이 불연속적인 에너지 공급 중에도 계산을 진전시키는 것 |

## Ⅱ. 전원 단절을 전제로 하는 실행 특징

| 특징 | 의미 |
|---|---|
| 불연속 전력 | 수확원·축전 소자의 상태에 따라 계산 시간이 달라짐 |
| 영속 상태 | 전원 소실 뒤에도 체크포인트나 완료된 작업 결과를 보존 |
| 재실행 가능성 | 중단 지점에 따라 같은 입력·작업이 다시 처리될 수 있음 |

## Ⅲ. 에너지 수확·상태 보존·재개 체계

```text
빛·열·진동 → 수확기·축전 소자 → MCU 작업 실행
                                    ├→ 완료 경계: 영속 상태 커밋
                                    └→ 전력 부족: 체크포인트 또는 중단
전원 복귀 → 영속 상태 복원 → 미완료 입력 확인 → 안전한 경계부터 재개
```

외부 통신 및 센싱 입력의 재실행 시 중복 방지를 위해 입력 식별자와 트랜잭션 커밋을 분리 관리. 가용 에너지 범위 내에서 완료 가능한 원자적 태스크 단위 분할 필수.

## Ⅳ. 상태 보존 방식과 정확성 조건 비교

| 방식·조건 | 작동 원리 | 검토 사항 |
|---|---|---|
| 체크포인트 | 실행 상태를 저장해 재부팅 후 복원 | 저장 에너지·빈도·재실행량 |
| 태스크 기반 | 완료된 작업 단위의 결과를 영속 반영 | 작업 분할·원자성·외부 부작용 |
| 응용 의미 기반 | 필요한 중간 상태와 입력만 선택 보존 | 응용별 정확성 검증 |
| 재실행 안전성 | 같은 작업 반복 시 중복 효과 방지 | 요청 식별자·멱등 처리 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 잦은 체크포인트는 저장 비용을 늘리고 드문 저장은 재실행량 증가 | 실제 수확·중단 패턴으로 주기와 작업 크기를 측정·조정 |
| 외부 시스템에 비가역 효과를 남긴 뒤 중단하면 재실행 때 중복 가능 | 요청 식별자·멱등성·커밋 경계로 입력과 외부 효과 조정 |
| 완료율만 보면 에너지 비용·결과 일관성 악화를 놓침 | 완료율·재실행량·저장 에너지·결과 무결성을 함께 측정 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
전원 차단 직전 전압 강하를 감지하여 핵심 레지스터와 프로그램 카운터를 FRAM/MRAM에 원자적으로 저장(JIT Checkpointing)하고, I/O 연산의 멱등성(Idempotency)을 설계.

### 2. 아키텍처 및 상세 메커니즘
```text
[ 에너지 하베스팅 (태양광/RF/진동) ] ──> [ 커패시터 에너지 충전 ]
                                               │
                                               ▼
┌────────────────────────────────────────────────────────┐
│ 전원 공급 개시 (V_on 도달) ──> 이전 체크포인트 복원 후 실행│
│                                                        │
│ [ 에너지 고갈 위기 (V_warn 임계치 감지) ]               │
│   1. 즉시 외부 인터럽트 발생                           │
│   2. CPU 레지스터 및 콜 스택을 FRAM/ReRAM에 즉시 백업  │
│   3. 전원 차단 (V_off 도달 및 시스템 정지)             │
│                                                        │
│ [ 에너지 재충전 (V_on 재도달) ]                        │
│   1. 비휘발성 메모리로부터 레지스터 상태 복원          │
│   2. 중단된 지점부터 연산 재개 (Forward Progress 달성)  │
└────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 체크포인팅 방식 | 동작 원리 | 체크포인트 오버헤드 | 에너지 활용 효율 |
|---|---|---|---|
| **정적 체크포인팅 (Static)** | 프로그래머나 컴파일러가 루프/함수 진입점에 코드 삽입 | 고정된 주기적 오버헤드 발생 | 정전 전까지 에너지가 남아도 조기 체크포인트 낭비 |
| **적시 체크포인팅 (Just-In-Time)**| 커패시터 전압 모니터링으로 전원 고갈 직전에만 캡처 | 평상시 런타임 오버헤드 0 | 전압 감지 회로 정밀도 및 초고속 비휘발성 쓰기 필수 |
| **작업 기반 (Task-Based)** | 시스템을 멱등성을 갖는 작은 원자적 태스크 단위로 분할 | 태스크 완료 시에만 상태 커밋 | 태스크 실행 도중 정전 시 해당 태스크 전체 재실행 |
