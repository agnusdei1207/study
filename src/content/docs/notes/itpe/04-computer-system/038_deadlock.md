## Ⅰ. 교착상태(Deadlock)의 개요

- 개념 : 다중 프로그래밍 또는 분산 환경에서 두 개 이상의 프로세스나 스레드가 서로 다른 프로세스가 점유하고 있는 **비선점 자원** 을 무한정 기다리며, 결과적으로 관련된 모든 프로세스의 실행이 영구적으로 멈추어 있는 시스템 마비 상태.
- 배경 및 필요성 : 한정된 자원을 다중 작업이 동시 공유하는 시분할 시스템에서 상호 배제와 비선점 조건이 결합될 때 발생하는 자원 할당 경쟁 문제를 규명하고 시스템 신뢰성을 보장하기 위해 연구됨.
- 핵심 목적 : 교착상태 발생 4대 필요조건 차단, 자원 할당 시 안전 상태 유지, 교착상태 발생 시 실시간 탐지 및 자원 선점을 통한 신속한 시스템 회복.

## Ⅱ. 교착상태(Deadlock)의 핵심 아키텍처 및 동작 메커니즘

교착상태는 코프만(Coffman) 4대 조건이 동시에 성립할 때만 발생하며, 자원 할당 그래프(RAG)의 환형 사이클 유무로 판정됨.

```text
[ 교착상태 코프만 4대 조건 및 자원 할당 그래프(RAG) ]

[코프만 4대 필요조건]
+---------------------------------------------------------------+
| 1. 상호 배제 (Mutual Exclusion) : 한 번에 한 프로세스만 자원 점유  |
| 2. 점유와 대기 (Hold & Wait)    : 자원을 쥔 채 다른 자원을 추가 대기|
| 3. 비선점 (No Preemption)       : 타 프로세스의 자원을 강제 회수 불가|
| 4. 환형 대기 (Circular Wait)    : 자원 대기 관계가 원형 루프를 형성 |
+---------------------------------------------------------------+
                                │ (4가지 모두 동시 성립 시)
                                ▼
+---------------------------------------------------------------+
| 자원 할당 그래프 (RAG: Resource Allocation Graph) 사이클      |
|                                                               |
|        [Resource R1] ────── 할당 ──────> (Process P1)         |
|              ▲                                 │              |
|              │                               대기             |
|             대기                               │              |
|              │                                 ▼              |
|        (Process P2) <────── 할당 ────── [Resource R2]         |
|                                                               |
|   * 자원 R1, R2가 단일 인스턴스일 때 사이클 존재 = 100% Deadlock!|
+---------------------------------------------------------------+
                                │
                                ▼
+---------------------------------------------------------------+
| 4대 처리 기법: 예방(Prevention), 회피(Avoidance),               |
|                탐지(Detection), 회복(Recovery) / 타조(Ostrich)|
+---------------------------------------------------------------+
```

- **상호 배제 (Mutual Exclusion)** : 자원은 한 번에 한 프로세스만 독점 사용할 수 있어야 함.
- **점유와 대기 (Hold and Wait)** : 최소한 하나의 자원을 점유한 채로 다른 프로세스가 보유한 자원을 추가 획득 대기.
- **비선점 (No Preemption)** : 프로세스가 사용 중인 자원은 작업이 끝나 자발적으로 반환하기 전까지 강제로 빼앗을 수 없음.
- **환형 대기 (Circular Wait)** : 대기 프로세스 간에 원형 체인(`P0 -> P1 -> ... -> Pn -> P0`)이 형성되어 순환 대기.
- **자원 할당 그래프 (RAG)** : 프로세스 노드와 자원 노드 간의 할당/요청 간선으로 교착을 시각화(단일 자원 시 사이클은 교착의 필요충분조건).

## Ⅲ. 교착상태(Deadlock)의 세부 구성 요소 및 비교 분석

| 교착상태 처리 기법 | 핵심 동작 메커니즘 | 자원 이용률 | 구현 복잡도 및 오버헤드 |
|---|---|---|---|
| **예방 (Prevention)** | 4대 조건 중 최소 하나를 사전에 원천 차단 | 매우 낮음 (자원 낭비 극심) | 낮음 (정적 규칙 강제) |
| **회피 (Avoidance)** | 자원 요청 시 안전 상태(Safe State) 동적 검사 (은행가) | 중간 | 높음 (사전 최대치 선언 요구) |
| **탐지 (Detection)** | 주기적으로 대기 그래프 탐색하여 사이클 감지 | 높음 | 중간 (주기적 탐지 알고리즘 실행) |
| **회복 (Recovery)** | 교착 프로세스 강제 종료 또는 자원 강제 선점 | 높음 | 프로세스 롤백 및 재실행 비용 |
| **무시 (타조 알고리즘)** | 교착 빈도가 극히 낮다고 가정하고 아무 조치 안 함 | 최고 | 오버헤드 0 (현대 범용 OS 채택) |

- 현대 리눅스/윈도우 등 범용 OS는 성능 저하를 방지하기 위해 타조 알고리즘을 기본 채택하며, 데이터베이스 및 분산 시스템은 탐지/회복 기법을 구현함.

## Ⅳ. 교착상태(Deadlock)의 주요 한계점 및 해결 방안

- **예방(Prevention)** 기법 적용 시 극단적인 시스템 자원 낭비 :
  - 한계점 : 점유대기 방지를 위해 모든 자원을 일괄 사전 할당하거나 환형대기 방지를 위해 순서대로만 요청 시 자원 이용률 급락.
  - 해결 방안 : 자원 잠금 단위를 극도로 세분화하는 미세 락(Fine-grained Locking) 및 타임아웃 기반 자동 잠금 해제(Try-Lock) 도입.
- **분산 환경(MSA, 멀티 DB)** 에서의 글로벌 교착상태 탐지 난제 :
  - 한계점 : 네트워크로 분리된 수십 개의 마이크로서비스 간에 분산 트랜잭션 락이 얽힐 경우 중앙화된 그래프 추적 불가.
  - 해결 방안 : Chandy-Misra-Haas 분산 에지 추적 알고리즘 적용, 분산 락(Redis Redlock)의 TTL(Time-To-Live) 만료 기반 자동 롤백.
- 교착 프로세스 강제 종료 시 데이터 불일치 위험 :
  - 한계점 : 트랜잭션 처리 도중 프로세스를 강제 Kill할 경우 공유 메모리나 DB 레코드가 부분 갱신 상태로 방치되어 오염.
  - 해결 방안 : WAL(Write-Ahead Logging) 기반의 원자적 트랜잭션 롤백, 사가(Saga) 패턴의 보상 트랜잭션 파이프라인 자동 실행.

## Ⅴ. 교착상태(Deadlock) 적용 및 발전을 위한 기술사적 제언

- 데이터베이스 교착상태 자동 감지 및 재시도 프레임워크 구축 : RDBMS는 교착 감지기(Wait-For Graph)가 비용이 적은 트랜잭션을 Victim으로 선정하여 롤백하므로 애플리케이션 레벨의 지수 백오프(Exponential Backoff) 재시도 로직 필수 구현.
- 트랜잭션 자원 획득 순서의 전사 표준화 : 복수 테이블이나 키를 동시 수정할 때 자원 ID의 오름차순으로 락을 획득하도록 코딩 표준을 수립하여 환형 대기 조건 사전 예방.
- 분산 락 거버넌스 수립 : 분산 캐시 기반 락 획득 시 반드시 락 유지 상한선(Lease Time)을 명시하고, 비즈니스 처리 시간 초과 시 락 연장(Watchdog) 메커니즘 연계 권장.
