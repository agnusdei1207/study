## 연관 키워드

- 교착상태(Deadlock), 코프만 4대 조건(Coffman Conditions), 상호 배제, 점유와 대기, 비선점, 환형 대기
- 자원 할당 그래프(RAG, Resource Allocation Graph), 안전 상태(Safe State), 은행가 알고리즘(Banker's Algorithm)
- 예방, 회피, 탐지, 회복, 타조 알고리즘(Ostrich Algorithm)
- 미세 락(Fine-grained Locking), Try-Lock, 분산 락, Chandy-Misra-Haas, 사가(Saga), WAL

## Ⅰ. 교착상태의 개요

- 핵심 요약 : **교착상태** (Deadlock)는 자원을 서로 기다리는 프로세스들이 영구히 멈춰 있는 시스템 마비 상태이며, 예방·회피·탐지·회복으로 대응.
- 개념 : 둘 이상의 프로세스나 스레드가 상대방이 점유한 자원을 무한정 기다려, 관련된 모든 실행이 영구히 멈춘 상태.
- 배경 및 필요성 : 한정된 자원을 여러 작업이 공유하는 시분할 시스템에서 상호 배제와 비선점이 결합되면 자원 경쟁으로 교착이 생기므로, 발생 조건을 규명하고 신뢰성을 확보할 필요가 있음.
- 주요 목적 : 교착 발생 조건의 차단, 자원 할당 시 안전 상태 유지, 교착 발생 시 탐지와 자원 선점을 통한 신속한 회복.

## Ⅱ. 교착상태의 특징 및 장점

- 핵심 요약 : 교착은 **코프만 4대 조건** (Coffman Conditions)이 동시에 성립할 때만 생기므로, 조건 중 하나만 끊어도 발생을 막을 수 있음.

1. **상호 배제** (Mutual Exclusion) : 자원을 한 번에 한 프로세스만 독점 사용 → 공유 가능한 자원으로 바꾸면 조건 해소.
2. **점유와 대기** (Hold and Wait) : 자원을 쥔 채 다른 자원을 추가로 기다림 → 필요한 자원을 한꺼번에 요청하면 조건 해소.
3. **비선점** (No Preemption) : 사용 중인 자원을 강제로 빼앗을 수 없음 → 선점을 허용하면 대기 관계가 풀림.
4. **환형 대기** (Circular Wait) : 프로세스 사이에 원형 대기 사슬이 형성 → 자원 번호 순서로만 요청하면 사슬이 만들어지지 않음.

## Ⅲ. 교착상태의 구조 및 동작 메커니즘

- 핵심 요약 : 4대 조건이 동시에 성립하고 자원 할당 그래프에 사이클이 있을 때 교착이 판정되며, 이후 처리 기법을 고름.

```text
[ 교착 발생 조건 ]

상호 배제 + 점유와 대기
   ↓
비선점
   ↓
환형 대기 (4가지 동시 성립 시)
   ↓
교착상태 발생
```

```text
[ 단일 인스턴스 자원의 교착 사이클 ]

P1 이 R1 점유
   ↓ P1 이 R2 요청
P2 가 R2 점유
   ↓ P2 가 R1 요청
P1 과 P2 가 서로 대기 → 사이클 형성
```

- **자원 할당 그래프** (RAG, Resource Allocation Graph) : 프로세스와 자원을 노드로, 할당과 요청을 간선으로 그린 그래프이며, 자원이 단일 인스턴스일 때 사이클 존재가 곧 교착 판정.
- 다중 인스턴스 자원에서는 사이클이 있어도 여유 인스턴스가 있을 수 있어 사이클 존재만으로 교착을 단정하지 않음.

## Ⅳ. 교착상태 처리 기법의 비교

- 핵심 요약 : 예방은 확실하지만 자원 낭비가 크고, 회피와 탐지는 정밀하지만 계산 비용이 들며, 범용 OS는 타조 알고리즘을 쓰는 경우가 많음.

| 처리 기법 | 핵심 동작 | 자원 이용률 | 구현 복잡도와 오버헤드 |
| --- | --- | --- | --- |
| 예방 (Prevention) | 4대 조건 중 하나를 구조적으로 차단 | 낮음 | 낮음, 정적 규칙 강제 |
| 회피 (Avoidance) | 자원 요청 시 안전 상태를 검사 (은행가 알고리즘) | 중간 | 높음, 최대 요구량 사전 선언 필요 |
| 탐지 (Detection) | 대기 그래프를 주기적으로 탐색해 사이클 감지 | 높음 | 중간, 주기적 탐색 비용 |
| 회복 (Recovery) | 교착 프로세스 강제 종료 또는 자원 선점 | 높음 | 롤백과 재실행 비용 |
| 무시 (타조 알고리즘) | 교착 빈도가 낮다고 보고 별도 조치 없음 | 최고 | 추가 오버헤드 없음 |

- 선택 기준 : 교착 비용이 치명적인지, 자원 낭비를 감당할 수 있는지, 프로세스를 중단하고 롤백할 수 있는지에 따라 기법을 고름.
- 현대 범용 OS는 성능을 우선하여 타조 알고리즘을 기본으로 두고, 데이터베이스와 분산 시스템은 탐지와 회복을 구현하는 경우가 많음.

## Ⅴ. 교착상태의 한계와 방안

- 핵심 요약 : 예방의 자원 낭비, 분산 환경의 탐지 난제, 강제 종료 후 데이터 불일치를 세분화된 락, 분산 추적, 보상 트랜잭션으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 예방 기법의 자원 낭비 | 점유 대기를 막으려 자원을 일괄 선할당하거나 순서 요청을 강제하면 이용률 급락 | 잠금 단위를 세분화한 미세 락 (Fine-grained Locking), 타임아웃 기반 Try-Lock으로 자동 해제 | 자원 이용률, 락 대기 시간 |
| 분산 환경의 전역 교착 탐지 난제 | 여러 서비스와 DB에 걸친 락이 얽히면 중앙 그래프로 추적하기 어려움 | Chandy-Misra-Haas 분산 에지 추적 알고리즘 적용, 분산 락에 만료 시간 (TTL, Time-To-Live) 설정 | 탐지 지연, 락 만료 후 재시도율 |
| 강제 종료에 따른 데이터 불일치 | 트랜잭션 도중 프로세스를 종료하면 레코드가 부분 갱신 상태로 남음 | WAL (Write-Ahead Logging) 기반 원자적 롤백, 사가 (Saga) 패턴의 보상 트랜잭션 실행 | 보상 트랜잭션 실패 건수 |

## Ⅵ. 교착상태에 대한 기술사적 제언

- 핵심 요약 : 교착 감지와 재시도 체계, 자원 획득 순서 표준, 분산 락 운영 규칙을 함께 갖추어 교착을 상시 관리 가능한 수준으로 낮추는 방향.

1. 데이터베이스 운영 조직이 교착을 감지하면 희생자 (Victim) 트랜잭션을 골라 롤백하고 지수 백오프로 재시도하는 프레임워크를 공통 모듈로 제공.
2. 개발 표준 조직이 트랜잭션에서 여러 자원을 잠글 때 자원 식별자 오름차순으로 획득하는 규칙을 사내 코딩 표준에 명시하여 환형 대기를 설계 단계에서 차단.
3. 플랫폼 조직이 분산 락에 임대 시간 (Lease)과 자동 연장 장치를 두고, 임대 만료 정책을 장애 대응 절차와 함께 문서화하여 운영 정책으로 관리.

## Ⅶ. 결론

- 핵심 요약 : 교착상태는 코프만 4대 조건이 동시에 성립할 때 생기는 시스템 마비이며, 조건 차단과 사이클 판정으로 대응.
- 시사점 : 교착은 완전히 제거하기보다 발생 조건을 설계로 끊고 남은 교착을 빠르게 감지하여 복구하는 체계로 관리할 때 신뢰성 확보.
