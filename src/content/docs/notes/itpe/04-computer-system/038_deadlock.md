## 연관 키워드

- 교착상태, 상호배제, 점유대기, 비선점, 환형대기, 예방·회피·탐지

## Ⅰ. 교착상태의 개요

- 핵심 요약 : 교착상태는 둘 이상의 프로세스가 서로 상대가 보유한 자원을 기다려 영구적으로 진행하지 못하는 상태.
- 개념 : 교착상태는 둘 이상의 프로세스가 서로 상대가 보유한 자원을 기다려 영구적으로 진행하지 못하는 상태.
- 배경 및 필요성 : 경쟁 자원을 여러 순서로 점유할 때 순환 대기로 시스템 진행 정지.
- 주요 목적 : 교착을 예방·회피하거나 탐지·복구해 시스템 진행성 확보.

## Ⅱ. 교착상태의 특징 및 장점

- 핵심 요약 : Coffman 4조건: 상호배제·점유대기·비선점·환형대기 동시 성립; 예방: 조건 하나를 제거 → 교착 가능성 제거, 자원 이용률 제약; 회피: 안전상태 유지, 은행원 알고리즘 → 최대요구량 사전 필요.

1. Coffman 4조건: 상호배제·점유대기·비선점·환형대기 동시 성립
2. 예방: 조건 하나를 제거 → 교착 가능성 제거, 자원 이용률 제약
3. 회피: 안전상태 유지, 은행원 알고리즘 → 최대요구량 사전 필요

## Ⅲ. 교착상태의 구조 (흐름)

- 핵심 요약 : 자원요구·점유 추적 → 예방·회피·탐지 정책 선택 → 대기·할당 그래프 검사 → 순환·불안전상태 탐지 → 프로세스 종료·자원 회수·재시작.

```text
자원요구·점유 추적
  ↓
예방·회피·탐지 정책 선택
  ↓
대기·할당 그래프 검사
  ↓
순환·불안전상태 탐지
  ↓
프로세스 종료·자원 회수·재시작
```

- 핵심 구성 : P1 holds R1 → waits R2

```text
P1 holds R1 → waits R2
P2 holds R2 → waits R1
환형 대기 → 교착, 한 프로세스 종료·자원회수로 해소
```

## Ⅳ. 비교: 교착상태 / 기아 상태

- 핵심 요약 : 원인 기준 — 교착상태: 자원 획득의 순환대기; 기아 상태: 우선순위 낮은 작업의 반복적인 지연.

| 비교 기준 | 교착상태 | 기아 상태 |
| --- | --- | --- |
| 원인 | 자원 획득의 순환대기 | 우선순위 낮은 작업의 반복적인 지연 |
| 진행가능성 | 관련 프로세스가 영구 대기 | 다른 프로세스는 진행할 수 있음 |
| 대응 | 예방·회피·탐지와 복구 | aging·공정 스케줄링 |

## Ⅴ. 교착상태의 한계와 방안

- 핵심 요약 : 4조건 동시 충족·탐지 지연 등의 위험을 원인에 맞게 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 4조건 동시 충족 | 모든 Coffman 조건이 만족되어 순환대기 | 자원 전역순서·필요 자원 일괄요청 등 예방 | 순환 대기 수 |
| 탐지 지연 | 주기적 검사 사이에 업무 스레드 정지 지속 | 대기시간 임계치·대기 그래프 모니터링 | 교착 탐지시간 |
| 복구 부작용 | 피해 프로세스 종료가 부분 갱신·데이터 손실 | 체크포인트·트랜잭션 롤백·피해자 선택기준 | 복구 후 오류 |

## Ⅵ. 교착상태의 제언

- 핵심 요약 : OS·DB 운영자는 자원 획득 순서를 표준화하고 대기그래프 기반 탐지·피해자 우선순위·롤백·재시작을 운영 런북과 부하시험에 포함.
- 실행 제안 : 커널·DB 운영자는 락 획득 순서 위반과 대기 그래프 순환을 부하 환경에서 재현하고 안전한 피해자 선택·재시작을 시험.

## Ⅶ. 교착상태의 결론

- 핵심 요약 : 교착상태는 네 가지 필요조건이 동시에 성립하는 진행성 실패이며 예방·회피·탐지 중 시스템 요구에 맞는 정책 선택 필요.
- 시사점 : 자원 사용률만 최대화하기보다 안전상태·응답성·복구 가능성을 함께 고려해야 교착의 업무 피해를 줄일 수 있음.
