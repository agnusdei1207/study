## 연관 키워드

- 교착상태(Deadlock), 코프만 조건(Coffman Conditions), 상호 배제(Mutual Exclusion)
- 점유와 대기(Hold and Wait), 비선점(No Preemption), 환형 대기(Circular Wait)
- 자원 할당 그래프(Resource Allocation Graph), 안전 상태(Safe State), 은행가 알고리즘(Banker's Algorithm)
- 예방(Prevention), 회피(Avoidance), 탐지(Detection), 회복(Recovery), 타조 알고리즘(Ostrich Algorithm)

## Ⅰ. 교착상태의 개요

- 핵심 요약 : **교착상태** (Deadlock)는 여러 프로세스가 서로가 점유한 자원을 무한히 기다려 어떤 프로세스도 진행하지 못하는 상태.
- 개념 : 둘 이상의 프로세스가 보유한 자원을 놓지 않은 채 상대의 자원을 대기해, 대기 사슬이 영구히 풀리지 않는 병행 처리의 비정상 상태.
- 배경 및 필요성 : 한정된 자원을 병행 프로세스가 공유하는 환경에서 자원 요청 순서가 얽히면 대기 사슬이 형성되므로, 발생 조건의 규명과 대응 체계 필요.
- 주요 목적 : 발생 조건의 차단, 자원 할당의 안전성 유지, 발생 교착의 조기 탐지와 신속한 회복.

## Ⅱ. 교착상태의 특징 및 장점

- 핵심 요약 : 교착은 **코프만 조건** (Coffman Conditions) 네 가지가 동시에 성립할 때만 발생하므로, 조건 하나의 차단이 곧 예방 수단.

1. **상호 배제** (Mutual Exclusion) : 자원을 한 시점에 한 프로세스만 사용하는 성질 → 자원의 공유 가능 전환으로 조건 해소 효과.
2. **점유와 대기** (Hold and Wait) : 자원을 보유한 상태로 추가 자원을 기다리는 성질 → 필요 자원의 일괄 요청으로 조건 해소 효과.
3. **비선점** (No Preemption) : 사용 중 자원을 강제로 회수할 수 없는 성질 → 선점 허용으로 대기 관계 해제 효과.
4. **환형 대기** (Circular Wait) : 대기 관계가 원형 사슬을 이루는 성질 → 자원 유형별 번호 순서로만 요청하면 사슬 형성 차단 효과.

## Ⅲ. 교착상태의 구조 (흐름)

- 핵심 요약 : 네 조건의 동시 성립으로 대기 사이클이 형성되며, 자원 할당 그래프의 사이클 판정이 교착 여부 확인의 기준.

```text
[ 교착 성립 조건의 결합 ]

상호 배제 + 점유와 대기
   ↓
비선점
   ↓
환형 대기 (네 조건 동시 성립)
   ↓
대기 사이클 형성
   ↓
교착상태 발생
```

```text
[ 두 프로세스의 대기 사이클 예시 ]

P1 : R1 보유
   ↓ R2 추가 요청
P2 : R2 보유
   ↓ R1 추가 요청
P1과 P2의 상호 대기
   ↓
사이클 = 교착 판정 근거
```

- **자원 할당 그래프** (Resource Allocation Graph) : 프로세스와 자원을 노드로, 보유와 요청을 간선으로 표현한 그래프 → 단일 인스턴스 자원 환경에서 사이클 존재가 곧 교착 판정.
- 다중 인스턴스 자원 환경에서는 사이클이 있어도 여유 인스턴스로 진행이 가능하므로, **안전 상태** (Safe State) 판별이 교착 판정의 보조 기준.
- 구성요소 : 프로세스·자원 노드, 보유 간선, 요청 간선, 사이클 검사 절차로 구성.

## Ⅳ. 교착상태 처리 기법의 비교

- 핵심 요약 : 예방은 확실하나 이용률이 낮고, 회피·탐지는 정밀하나 정보·계산 부담이 있으며, 무시는 오버헤드가 없는 대신 수동 복구 부담.

| 처리 기법 | 핵심 동작 | 자원 이용률 | 적용 부담 |
| --- | --- | --- | --- |
| **예방** (Prevention) | 발생 조건 하나를 구조적으로 차단 | 낮음 | 규칙 강제가 단순 |
| **회피** (Avoidance) | 할당마다 **은행가 알고리즘** (Banker's Algorithm, 안전 상태 검사) 적용 | 중간 | 최대 요구량 사전 선언 필요 |
| **탐지** (Detection) | 대기 그래프의 주기적 사이클 검사 | 높음 | 탐색 주기 설계 필요 |
| **회복** (Recovery) | 프로세스 종료 또는 자원 선점으로 해제 | 높음 | 롤백·재실행 비용 |
| 무시 (**타조 알고리즘**, Ostrich Algorithm) | 발생 가능성을 낮게 보고 별도 대응 없음 | 최고 | 장애 시 수동 복구 부담 |

- 선택 기준 : 교착 발생 시 피해의 심각성, 자원 낭비의 감수 범위, 프로세스 중단·롤백 가능성에 따라 기법 조합을 선택.
- 범용 운영체제는 성능 중심으로 무시 정책을 쓰는 경우가 많고, 데이터베이스는 탐지와 회복을 결합하는 경향.

## Ⅴ. 교착상태의 한계와 방안

- 핵심 요약 : 예방의 이용률 저하, 회피의 사전 정보 부담, 회복 시 일관성 훼손을 잠금 최소화, 동적 보정, 트랜잭션 회복으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 예방의 자원 이용률 저하 | 일괄 선할당·요청 순서 강제 → 유휴 자원 증가 | 잠금 범위의 최소화, 요청 순서 규칙의 자동 검증 도구 적용 | 자원 이용률, 대기 시간 |
| 회피의 사전 정보 부담 | 최대 요구량 선언의 어려움 → 검사 정확도 저하 | 요구 패턴 관측으로 선언치 보정, 탐지 기법 병행 | 안전 검사 오류율 |
| 회복 시 일관성 훼손 | 진행 중 작업의 강제 종료 → 부분 갱신 상태 잔류 | 트랜잭션 롤백과 체크포인트 회복 절차 결합 | 회복 소요 시간, 재시도 성공률 |

## Ⅵ. 교착상태에 대한 기술사적 제언

- 핵심 요약 : 설계 단계 규칙화, 회복 절차의 공통화, 운영 지표화를 통해 교착을 상시 관리 대상으로 전환하는 방향.

1. 개발 표준 조직이 자원 획득 순서 규칙과 락 사용 지침을 코딩 표준에 명시해 환형 대기를 설계 단계에서 차단.
2. 데이터베이스 운영 조직이 교착 희생자 선정과 재시도 로직을 공통 프레임워크로 제공해 회복 절차의 일관성 확보.
3. 플랫폼 운영 조직이 교착 발생 건수와 탐지 지연을 서비스 품질 지표로 수집해 대응 체계의 실효성 점검.

## Ⅶ. 결론

- 핵심 요약 : 교착상태는 네 성립 조건의 결합으로 생기는 병행 처리의 대표적 마비 상태.
- 시사점 : 조건 차단과 사이클 판정, 발생 후 신속한 회복의 조합이 시스템 신뢰성 확보의 기본 구조.
