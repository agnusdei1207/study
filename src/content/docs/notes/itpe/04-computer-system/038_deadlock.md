## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 교착상태

## 30초 인출

- 본질: 두 개 이상의 프로세스가 각자 점유한 자원을 놓지 않은 채 상대방이 점유한 자원을 무한정 대기함으로써 시스템 전체 진행이 영구 중단되는 현상
- 메커니즘: 4대 조건 중 하나를 깨는 예방(Prevention), 안전 순서열을 검사하는 회피(Avoidance), 사이클을 감지해 프로세스를 희생시키는 탐지/회복으로 대응 / 자원 이용률 저하 또는 롤백 트랜잭션 손실 발생

## 핵심 용어

- 자원 할당 그래프(RAG: Resource Allocation Graph): 프로세스 노드($P$)와 자원 노드($R$) 간의 요청 간선 및 할당 간선으로 구성된 방향성 그래프(단일 자원 환경에서 사이클 존재 = 교착상태)
- 라이브락(Livelock): 프로세스들이 블로킹 상태는 아니지만, 상호 양보나 상태 변경만 무한히 반복하면서 실질적인 작업 진행을 전혀 하지 못하는 '활동성 상실' 현상
- 희생자 선정(Victim Selection): 교착상태 회복 단계에서 시스템 전체 손실을 최소화하기 위해 강제 종료하거나 롤백시킬 프로세스를 비용 기준(우선순위, 진행률)으로 선택하는 과정

## 1교시 10점 답안

### 정의·목적

- 정의: 교착상태는 프로세스들이 점유한 자원을 서로 기다려 진행하지 못하는 상태다.
- 목적: 교착상태를 예방·회피하거나 탐지 후 회복해 시스템 정지를 줄인다.

### 핵심 구조와 작동

```text
[ 교착상태 발생 4대 필요조건의 순환 구조 ]

   +──────────────────+                   +──────────────────+
   |  상호 배제       |                   |  점유 대기       |
   | (Mutual Exclusion)                   | (Hold and Wait)  |
   | : 1번에 1개만 점유 |                   | : 자원 쥔채 대기 |
   +────────┬─────────+                   +────────┬─────────+
            │                                      │
            └──────────────────┬───────────────────┘
                               v (4대 조건 동시 충족 시 데드락 발생)
            ┌──────────────────┴───────────────────┐
            │                                      │
   +────────┴─────────+                   +────────┴─────────+
   |  비선점          |                   |  환형 대기       |
   | (Non-preemption) |                   | (Circular Wait)  |
   | : 강제 회수 불가 |                   | : 순환 고리 형성 |
   +──────────────────+                   +──────────────────+

[ 자원 할당 그래프 (Resource Allocation Graph: Deadlock Cycle) ]
  (P1) ──(요청)──> [R1] ──(할당)──> (P2)
   ▲                                  │
   └────────(할당)── [R2] <──(요청)───┘  <── RAG에 사이클 형성!
```

## 2~4교시 25점 답안

### Ⅰ. 핵심 구조와 작동

```text
[ 교착상태 발생 4대 필요조건의 순환 구조 ]

   +──────────────────+                   +──────────────────+
   |  상호 배제       |                   |  점유 대기       |
   | (Mutual Exclusion)                   | (Hold and Wait)  |
   | : 1번에 1개만 점유 |                   | : 자원 쥔채 대기 |
   +────────┬─────────+                   +────────┬─────────+
            │                                      │
            └──────────────────┬───────────────────┘
                               v (4대 조건 동시 충족 시 데드락 발생)
            ┌──────────────────┴───────────────────┐
            │                                      │
   +────────┴─────────+                   +────────┴─────────+
   |  비선점          |                   |  환형 대기       |
   | (Non-preemption) |                   | (Circular Wait)  |
   | : 강제 회수 불가 |                   | : 순환 고리 형성 |
   +──────────────────+                   +──────────────────+

[ 자원 할당 그래프 (Resource Allocation Graph: Deadlock Cycle) ]
  (P1) ──(요청)──> [R1] ──(할당)──> (P2)
   ▲                                  │
   └────────(할당)── [R2] <──(요청)───┘  <── RAG에 사이클 형성!
```

### Ⅱ. 핵심 특성

- 4대 조건(상호배제, 점유대기, 비선점, 환형대기)은 '동시 충족'되어야만 데드락이 성립하므로, 이 중 단 하나만 깨부수면 예방(Prevention)이 가능함
- 그러나 상호배제를 깨는 것(공유 가능화)은 데이터 오염 때문에 불가능하고, 점유대기를 깨는 것(모든 자원 일괄 요청)이나 비선점을 깨는 것은 자원 낭비가 극심함 → 실무에서 가장 유일하게 구현 가능한 예방책은 '자원에 고유 번호를 매기고 항상 오름차순으로만 락을 요청하게 하는 환형대기 부정(Lock Ordering)'임
- 대부분의 범용 OS(Windows, Linux)는 회피나 예방 오버헤드가 너무 커서 교착상태를 무시하는 타조 알고리즘(Ostrich Algorithm)을 택하고 있으며, RDBMS만이 대기 그래프(Wait-for Graph)를 백그라운드로 스캔하여 데드락을 적극 탐지함

### Ⅲ. 관련 개념과 구분

- 교착상태(Deadlock) vs 기아상태(Starvation): 교착상태 = 락을 쥐고 맞물려 영원히 진행 불가능(CPU 0%) / 기아상태 = 우선순위가 낮아 CPU를 배정받지 못하는 상태(언젠가 자원이 풀리면 실행 가능)

### Ⅳ. 적용 문제와 대응

| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 트랜잭션 A(계좌1->계좌2)와 B(계좌2->계좌1)가 동시 실행되며 영구 대기 | 자원 획득 순서 비표준화로 인한 환형 대기(Circular Wait) 발생 | 계좌 ID 기준 오름차순 정렬 락 획득 강제 (Lock Ordering) | 환형 대기 조건 원천 차단으로 데드락 100% 예방 |
