## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 정보시스템 장애 예방·운영 전환

## 30초 인출

- 본질: 수년간 개발한 신규 정보시스템을 실제 운영 환경으로 교체하는 컷오버(Cutover) 순간의 데이터 누락, 인터페이스 불일치, 성능 저하로 인한 대형 전산 참사 방지
- 메커니즘: 정위치 모의 훈련(리허설)과 분 단위 런북(Runbook), 명확한 Go/No-Go 판정 기준을 통해 단계적으로 전환하고 비상 시 즉시 원복

## 핵심 용어

- 컷오버(Cutover): 기존 레거시 정보시스템의 운영을 중단하고 신규 개발된 정보시스템으로 데이터와 트랜잭션을 완전히 이관하여 정식 가동으로 전환하는 작업
- Go/No-Go 회의: 데이터 전환율, 정합성 검증 결과, 대외 인터페이스 테스트 결과를 종합하여 신규 오픈(Go)을 진행할 것인지, 기존 레거시로 즉시 롤백(No-Go)할 것인지 결정하는 최고 의사결정 관문
- 병행 운영(Parallel Run): 일정 기간 동안 구 시스템과 신 시스템을 동시에 가동하여 동일한 데이터를 입력하고 두 시스템의 결과값을 100% 대조하여 무결성을 검증한 후 전환하는 방식

### Ⅱ. 핵심 특성

- 운영 전환 실패의 80%는 '데이터 전환(Data Migration) 정합성'에서 발생함 → 코드 버그는 오픈 후 패치가 가능하지만, 계좌 잔액이나 고객 데이터의 누락/왜곡은 금융감독원 고발 및 비즈니스 즉사로 이어짐
- 전환 성공의 열쇠는 '실제 데이터와 동일한 볼륨으로 수행하는 최소 3회 이상의 모의 전환(리허설)'임 → 1차(단위 기능), 2차(풀타임 시뮬레이션), 3차(예고 없는 돌발 장애 롤백 훈련)를 거쳐 소요 시간을 분 단위로 예측 가능하게 만들어야 함
- 'No-Go 데드라인(Dead-line Time)'은 절대 타협할 수 없는 마지노선임 → "1시간만 더 주면 될 것 같다"는 희망 회로에 매달리다 롤백 골든타임을 놓치면 월요일 아침 전국 전산망 마비로 직결됨

### Ⅲ. 관련 개념과 구분

- 빅뱅 전환 vs 단계별 전환: 빅뱅 = 주말 동안 전체 업무를 일괄 전환(비용 저렴, 위험도 최고) / 단계별 = 모듈별·지점별로 순차 오픈(위험 분산, 연동 인터페이스 이중 구축 비용 발생)

### Ⅳ. 적용 문제와 대응

- 사례: 129회 기출 공공 행정망 및 금융 차세대 시스템 컷오버 후 접속 폭주로 서비스 전면 마비
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 오픈 당일 예상치 못한 배치 시간 초과(Batch Window 오버런)로 영업 시작 불가 | 모의 훈련 시 샘플 데이터로만 테스트하여 실 데이터 규모 미반영 | 운영 데이터 100% 전수 복제 기반의 실전 리허설 및 병렬 ETL 파티셔닝 | 배치 전환 소요 시간 50% 단축 |
| 전환 직후 신규 DB와 기존 대외기관 전문 규격 불일치로 금융 결제 실패 | 대외 연계 기관과의 엔드-투-엔드(E2E) 통합 연동 테스트 미흡 | 오픈 2주 전 대외 전산망 통합 리허설 및 전문 변환 어댑터 사전 검증 | 대외 거래 오류율 0% 달성 |

## 출제 이력과 검증 출처

- 제122회 2교시: "정보시스템 구축 사업에서 성공적인 운영 전환(Cutover)을 위한 전환 방식 3가지(빅뱅, 단계적, 병행)와 사전 준비 활동을 설명하시오." → 요구 포인트: Ⅲ 전환 방식 비교 + Ⅳ 리허설 및 Go/No-Go 절차
- 제129회 1교시: "정보시스템 오픈 시 장애 예방을 위한 컷오버 롤백(Rollback) 계획 수립 시 고려사항을 설명하시오." → 요구 포인트: 롤백 마지노선 타임테이블 및 데이터 복원 전략
