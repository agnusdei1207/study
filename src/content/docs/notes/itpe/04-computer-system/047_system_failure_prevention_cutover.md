## 연관 키워드

- 운영 전환(Cutover), 런북(Runbook), 리허설(Rehearsal), CDC(Change Data Capture)
- 역CDC(Reverse CDC), Go/No-Go 판정, 롤백(Rollback), 정합성 검증
- 빅뱅·단계적·병행 전환, 블루-그린 배포, 카나리 배포, 워룸(War Room), 하이퍼케어(Hypercare)

## Ⅰ. 시스템 장애 예방·운영 전환의 개요

- 핵심 요약 : 기존 시스템에서 신규 시스템으로 업무를 넘기는 절차에서 다운타임, 데이터 정합성, 롤백 능력을 통제하는 이행 전략.
- 개념 : 차세대 시스템 구축이나 클라우드 이전 완료 후 기존 시스템에서 신규 시스템으로 서비스를 넘기는 **운영 전환** (Cutover) 절차와 사전 장애 예방 검증 체계.
- 배경 및 필요성 : 대형 시스템의 개시 당일에 데이터 불일치, 성능 저하, 롤백 불능이 겹치면 서비스 전면 마비로 이어짐. 전환은 일회성 실행이므로 사전 검증과 되돌림 경로의 설계가 필수.
- 주요 목적 : 개시 창구 내 작업 완료, 데이터 이관 정합성의 입증, 비상 시 제한 시간 안의 **롤백** (Rollback) 능력 확보.

## Ⅱ. 시스템 장애 예방·운영 전환의 특징 및 장점

- 핵심 요약 : 분 단위 작업표, 반복 모의 전환, 실시간 변경 동기화, 판정 게이트가 맞물려 이행 리스크를 단계별로 통제.

1. **런북** (Runbook) : 이행 작업을 분 단위 작업표로 쪼개 작업자·검증자·선행 관계를 정의 → 누락과 지연의 사전 발견.
2. **리허설** (Rehearsal) : 운영 규모와 같은 환경에서 실제 데이터로 모의 전환을 반복 수행 → 작업 시간 예측 정확도와 절차 숙련도 향상.
3. **CDC** (Change Data Capture, 변경 데이터 캡처) : 기준 시점 데이터를 사전 적재하고 변경분만 실시간 복제 → 서비스 중단 시간의 최소화.
4. Go/No-Go 판정 : 마감 시각까지 필수 검증 항목의 통과를 개시 조건으로 설정 → 무리한 강행의 차단.
5. 롤백 설계 : 되돌림 절차와 소요 시간을 개시 전에 확정 → 이행 실패 시 기존 서비스의 신속 복원.

## Ⅲ. 시스템 장애 예방·운영 전환의 구조 (흐름)

- 핵심 요약 : 사전 준비부터 판정까지의 4단계와 판정 이후 개시·롤백 분기로 구성되는 절차.

```text
[ 운영 전환 4단계 ]

1. 사전 준비 (런북·리허설·사전 적재)
        ↓
2. 본 컷오버 (거래 차단·CDC 동기화)
        ↓
3. 정합성 검증 (건수·금액 대사)
        ↓
4. Go/No-Go 판정
```

```text
[ 판정 이후 분기 ]

Go/No-Go 판정
   ├─ Go → 신규 절체 → 역CDC 가동
   └─ No-Go → 즉시 롤백 → 원상 복구
```

- 개시가 결정되더라도 신규 시스템의 거래를 기존 시스템으로 되돌리는 **역CDC** (Reverse CDC)가 상시 가동되어야 이후에도 되돌림 경로가 유지됨.

## Ⅳ. 전환 전략 유형의 비교

- 핵심 요약 : 빅뱅, 단계적, 병행, 블루-그린은 다운타임, 롤백 용이성, 비용에서 서로 다른 절충을 보임.

| 전환 전략 | 이행 방식 | 다운타임 | 롤백 용이성 | 비용 |
| --- | --- | --- | --- | --- |
| **빅뱅 전환** (Big-Bang) | 지정일 일괄 전환 | 김 | 어려움 | 낮음 |
| **단계적 전환** (Phased) | 업무·지역별 순차 전환 | 짧게 분할 | 부분 가능 | 중간 |
| **병행 운영** (Parallel) | 신구 동시 처리·결과 대조 | 없음 | 용이 | 높음 |
| **블루-그린 배포** (Blue-Green) | 동등 환경 준비 후 트래픽 일시 전환 | 최소 | 즉시 | 높음 |

- 선택 기준 : 업무의 정지 허용 한계와 데이터 검증 요구, 이중 인프라 비용을 함께 따져 전략을 고름. 금융 원장 계열은 CDC 기반 준병행 검증을 결합한 전략, 마이크로서비스 계열은 블루-그린·카나리 배포가 일반적.

## Ⅴ. 시스템 장애 예방·운영 전환의 한계와 방안

- 핵심 요약 : 작업 시간 초과, 역이관 불능, 개시 후 성능 저하를 사전 처리, 역방향 복제, 실트래픽 시험으로 일대일 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 작업 시간 초과 | 인덱스 재생성 등이 예정보다 길어져 개시 시각 지연 | 사전 병렬 처리, CDC 사전 동기화, 마감 시각 준수 | 리허설 대비 실측 차이 |
| 역이관 불능 | 신규 거래가 기존 시스템에 반영되지 않아 롤백 불가 | 역CDC 파이프라인의 상시 가동·검증 | 역방향 복제 지연 |
| 개시 후 성능 저하 | 실트래픽에서 실행 계획 변화·락 경합 발생 | 트래픽 미러링 부하 시험, 주요 쿼리 실행 계획 고정 | 응답 시간 분포 |

## Ⅵ. 시스템 장애 예방·운영 전환에 대한 기술사적 제언

- 핵심 요약 : 지휘 체계의 일원화, 안정화 기간의 계획화, 점진 절체의 기본화로 개시 이후의 위험을 흡수하는 방향.

1. 전환 본부는 현업·인프라·응용 담당이 한 공간에서 지표를 공유하는 워룸(War Room)을 운영하고, 개시·롤백 결정권을 일원화.
2. 운영 조직은 개시 후 미세 튜닝과 데이터 보정을 맡는 하이퍼케어(Hypercare) 기간과 종료 기준을 전환 계획에 명시.
3. 클라우드 전환은 카나리 배포(Canary Deployment)로 소량 트래픽부터 가중치를 올리는 단계 절체를 기본 설계에 포함.

## Ⅶ. 결론

- 핵심 요약 : 운영 전환은 검증된 절차와 되돌림 경로가 결합된 이행 공학.
- 전환의 성패는 개시 시점의 속도보다 롤백 경로의 확보 여부가 결정하므로 되돌림 설계가 계획의 중심.
