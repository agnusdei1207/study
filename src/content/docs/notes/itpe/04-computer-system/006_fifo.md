 ┃
 ┣━ Ⅰ 개요 ───── 복잡한 큐잉 스케줄링 오버헤드 → 도착 순서 기반의 직관적 O(1) 처리 기제
 ┣━ Ⅱ 특징 ───── 선입선출 · 비선점성 · 구현 단순성 · 공평성(기아 방지) · 호위 효과

 ┣━ Ⅳ 흐름 ───── ① 패킷/작업 도착 → ② Tail 버퍼 삽입(Enqueue) → ③ Head에서 디큐(Dequeue) → ④ 서비스 처리
 ┣━ Ⅴ 비교 ───── FIFO vs WFQ(가중치 공평 큐잉) / FCFS vs SJF(CPU 스케줄링) / FIFO vs LRU(페이지 교체)

## 한 줄 본질
- 우선순위 산정 및 재정렬에 따른 스케줄러 연산 오버헤드 → 먼저 도착한 데이터나 작업을 먼저 처리하는 단순 선입선출 큐 구조 채택 → 구현 복잡도 O(1) 및 기아 상태 원천 방지 / 앞선 긴 작업으로 인한 호위 효과(Convoy Effect) 및 긴급 트래픽 지연 발생

## 핵심 그림
```text
[ 패킷/작업 진입 ]                                      [ 서비스 처리 ]
  (Tail: Enqueue)                                         (Head: Dequeue)
        │                                                       ^
        v                                                       │
  +------------+------------+------------+------------+---------+--+
  | Packet 4   | Packet 3   | Packet 2   | Packet 1 (Long Task)|
  | (단기/긴급)| (단기 작업)| (단기 작업)| [CPU/대역폭 독점 점유] |
  +------------+------------+------------+------------+------------+
                                               │
                                               v
        * 호위 효과(Convoy Effect) 발생:
          뒤따르는 짧은 패킷(2, 3, 4)의 대기 시간이 급증하여 평균 반환 시간 저하
```

## 핵심 용어
- 호위 효과(Convoy Effect): 수행 시간이 매우 긴 작업이 CPU나 대역폭을 독점하여 뒤에 도착한 수많은 짧은 작업들이 불필요하게 대기하는 현상
- 벨레이디의 모순(Belady's Anomaly): FIFO 페이지 교체 알고리즘에서 프로세스에 할당된 페이지 프레임 수를 늘렸음에도 불구하고 페이지 부재(Page Fault)가 오히려 증가하는 기현상

## 핵심 통찰
- FIFO는 모든 주체에게 '순서상의 공평성'을 제공하지만, '작업 크기나 중요도에 따른 공평성'은 완전히 무시함 → VoIP나 자율주행 제어 패킷처럼 지연에 민감한 트래픽도 대용량 파일 다운로드 패킷 뒤에 갇힘
- 네트워크 큐잉에서 FIFO는 버퍼가 가득 차면 뒤에 오는 패킷을 무조건 버리는 테일 드롭(Tail Drop)과 결합되어 TCP 글로벌 동기화(Global Synchronization) 장애를 야기
- CPU 스케줄링(FCFS)에서는 작업 크기 편차가 클 때 최악의 평균 대기 시간을 기록하므로 시분할(Round Robin)과 반드시 결합되어야 함

## 이웃 토픽과 구분
- FIFO vs WFQ: FIFO = 패킷의 종류와 무관하게 도착 순서대로 단일 큐 처리 / WFQ = 트래픽 플로우별로 큐를 분리하고 가중치를 부여하여 대역폭 차등 보장
