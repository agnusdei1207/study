<details>
<summary>핵심 용어</summary>

- **하드웨어 규모산정(Hardware Sizing)** : 시스템 요구 부하와 성능목표에 맞는 하드웨어 용량을 추정하는 과정
- **TPS (Transactions Per Second)** : 초당 처리 트랜잭션 수
- **피크 부하(Peak Load)** : 특정 시간대에 집중되는 최대 또는 설계 부하
- **벤치마크(Benchmark)** : 정의된 부하·조건으로 시스템 성능을 측정하는 시험
- **용량계획(Capacity Planning)** : 현재·예상 수요에 맞춰 자원 용량을 계획·조정하는 활동

## 2~4교시 25점 답안

### Ⅰ. 하드웨어 규모산정의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **하드웨어 규모산정은** 시스템 부하와 성능목표에 맞는 하드웨어 용량을 추정하는 과정 |
| 목적 | 성능·확장성과 비용 사이에서 적정 용량 결정 |

### Ⅱ. 규모산정의 특징

| 특징 | 의미 |
|---|---|
| 업무 기반 | 사용자 수보다 실제 거래 유형·동시성과 처리 패턴이 중요 |
| 성능 목표 연계 | 처리량뿐 아니라 응답시간·가용성 목표를 함께 충족 |
| 반복 보정 | 추정치와 벤치마크·운영 관측의 차이를 계속 수정 |

### Ⅲ. 규모산정 체계·프로세스

**핵심 산정 프레임**

```text
업무 시나리오·동시성·피크·성장·SLO
           → 부하 모델 → CPU·메모리·저장·네트워크 추정
           → 목표 구성에서 대표 부하 시험
           → 병목·여유 분석 → 가정 보정 → 용량 확정·증설 계획
```

**하위 메커니즘: 병목 기반 재산정**

```text
대표 거래 실행 → TPS·지연 분포·자원 사용률 측정
              → 포화 자원 식별 → 해당 자원 또는 분산 구조 조정
              → 동일 조건 재시험 → 피크 여유와 증설 임계값 확정
```

### Ⅳ. 자원별 산정·검증 비교

| 자원 | 산정 입력 | 검증 지표 |
|---|---|---|
| CPU | 거래당 연산량·피크 동시성 | 사용률·큐 대기·처리량 |
| 메모리 | 작업 집합·캐시·세션 수 | 압박·스와핑·캐시 적중 |
| 저장 | 데이터 증가·I/O 패턴 | 용량·IOPS·지연 |
| 네트워크 | 요청·응답 크기·동서 트래픽 | 대역폭·패킷 손실·지연 |

### Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 평균 부하만 보면 피크 병목을 누락 | 업무별 피크·동시성 분포를 모델에 반영 |
| 단일 서버 성능이 분산 구성으로 선형 확장되지 않음 | 목표 아키텍처에서 종단 간 시험 |
| 벤치마크가 실제 거래·데이터와 다름 | 부하 대표성·시험 조건·병목을 기록해 재시험 |
| 성장률 예측이 운영 중 달라짐 | 사용량 임계값과 단계별 증설 절차 수립 |

### Ⅵ. 제언

최초 산정치는 미래 부하와 분산 병목을 확정하지 못한다. **대표 거래의 피크 부하 시험으로 초기 용량을 정하고**, 운영 지표가 검증된 임계값에 접근하면 단계적으로 증설하는 체계를 설계해야 한다.
