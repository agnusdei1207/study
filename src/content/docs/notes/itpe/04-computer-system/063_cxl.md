## 연관 키워드

- CXL(Compute Express Link), PCIe(Peripheral Component Interconnect Express), 캐시 일관성(Cache Coherency), 제로 카피(Zero-Copy), 분해형 데이터센터(Disaggregated Data Center), 메모리 풀링(Memory Pooling)
- CXL.io, CXL.cache, CXL.mem, Type 1, Type 2, Type 3
- 계층형 메모리(Tiered Memory), HMAT(Heterogeneous Memory Attribute Table), NVLink, KV 캐시(Key-Value Cache), Stranded 메모리(Stranded Memory)

## Ⅰ. CXL (Compute Express Link)의 개요

- 핵심 요약 : **CXL**(Compute Express Link)은 PCIe(Peripheral Component Interconnect Express) 기반에서 캐시 일관성을 하드웨어로 보장하여, 이종 장치가 메모리를 공유하고 풀링하도록 하는 개방형 표준.
- 개념 : CPU(Central Processing Unit), GPU(Graphics Processing Unit), NPU(Neural Processing Unit), 메모리 확장기 등 이종 프로세서와 가속기를 고속·저지연으로 연결하면서 **캐시 일관성**(Cache Coherency)을 하드웨어 수준에서 유지하는 PCIe 물리 계층 기반의 상호연결 표준.
- 배경 및 필요성 : 가속기가 늘면서 장치와 호스트 사이에서 데이터를 복사해 주고받는 비용이 커졌고, 기존 PCIe 방식은 장치와 호스트 메모리가 분리되어 있어 캐시 일관성을 소프트웨어로 맞춰야 함. 또한 CPU 소켓당 장착할 수 있는 메모리 용량에 한계가 있어 메모리를 키우는 새로운 계층이 필요해졌으며, 이에 2019년 인텔 주도의 업계 컨소시엄이 규격을 발표함.
- 주요 목적 : 장치 간 **제로 카피**(Zero-Copy) 방식의 데이터 공유, 서버 메모리 용량과 대역폭의 확장, **분해형 데이터센터**(Disaggregated Data Center) 구현.

## Ⅱ. CXL (Compute Express Link)의 특징 및 장점

- 핵심 요약 : 세 개의 프로토콜이 입출력, 캐시, 메모리 접근을 하나의 인터커넥트에서 나눠 처리하므로, 기존 PCIe 생태계를 유지하면서 메모리 공유를 얻는 구조.

1. **CXL.io** : PCIe와 호환되는 프로토콜로 장치 탐색, 초기화, 설정과 DMA(Direct Memory Access) 같은 기본 입출력을 담당 → 기존 PCIe 소프트웨어 자산을 그대로 활용.
2. **CXL.cache** : 가속기나 스마트NIC(Network Interface Card)가 호스트 메인 메모리를 캐싱하면서 일관성을 유지 → 장치와 호스트 사이의 데이터 복사가 줄어듦.
3. **CXL.mem** : 호스트 CPU가 확장 메모리를 일반 메모리 주소 공간으로 인식하여 로드와 저장(Load/Store) 명령으로 직접 접근 → 블록 단위 전송 없이 바이트 단위로 접근.
4. **메모리 풀링** (Memory Pooling) : 여러 서버가 CXL 스위치를 통해 메모리 장치를 공유 풀로 나누어 씀 → 서버마다 남는 메모리를 회수하여 전체 활용률 향상.

## Ⅲ. CXL (Compute Express Link)의 구조 및 동작 메커니즘

- 핵심 요약 : 세 가지 프로토콜 위에서 장치를 Type 1, Type 2, Type 3으로 나누고, 장치 역할에 맞는 프로토콜 조합으로 동작.

```text
[ CXL 프로토콜 스택 ]

CXL.io     : 장치 탐색, 초기화, DMA
CXL.cache  : 장치가 호스트 메모리를 캐싱
CXL.mem    : 호스트의 장치 메모리 직접 접근
```

```text
[ 장치 유형별 프로토콜 조합 ]

Type 1  CXL.io + CXL.cache
        → 스마트NIC 등
Type 2  CXL.io + CXL.cache + CXL.mem
        → GPU, NPU 등 가속기
Type 3  CXL.io + CXL.mem
        → CXL 메모리 확장기
```

- Type 2는 가속기와 호스트가 서로의 메모리를 대등하게 공유하고, Type 3은 호스트 CPU가 CXL 컨트롤러를 거쳐 DDR(Double Data Rate) 메모리를 늘리는 장치로 쓰임.

## Ⅳ. CXL (Compute Express Link)의 비교

- 핵심 요약 : 개방형 표준이면서도 **NVLink**와 같은 자사 인터커넥트 수준의 캐시 일관성과 직접 접근을 제공하는 점이 CXL의 차별점.

| 비교 항목 | 전통적 PCIe (PCIe 5.0/6.0) | CXL (Compute Express Link) | NVLink (NVIDIA 자사 인터커넥트) |
| --- | --- | --- | --- |
| 캐시 일관성 | 미지원 (소프트웨어로 동기화) | 하드웨어로 보장 | 하드웨어로 지원 |
| 메모리 접근 단위 | 블록·DMA 단위 전송 (복사 비용 발생) | 바이트 단위 직접 접근 (Load/Store) | 바이트 단위 직접 접근 |
| 표준 성격 | PCI-SIG(PCI Special Interest Group) 개방형 표준 | 개방형 업계 표준 | NVIDIA 자사 인터커넥트 |
| 적용 범위 | 주변 장치 입출력 확장 | CPU, GPU, NPU, 메모리 풀링 | NVIDIA GPU 간 연결 중심 |
| 메모리 공유 | 호스트와 장치 메모리 분리 | 풀링된 공유 메모리 공간 | GPU 클러스터 내 공유 |

- 선택 기준 : 여러 벤더의 CPU, 가속기, 메모리를 섞어 쓰는 구성이면 CXL을, 단일 벤더 GPU 클러스터의 최대 대역폭이 목표면 자사 인터커넥트를 택하는 것이 일반적임.

## Ⅴ. CXL (Compute Express Link)의 한계와 방안

- 핵심 요약 : 지연 증가, 컨트롤러 전력과 발열, NUMA(Non-Uniform Memory Access) 최적화 한계를 **계층형 메모리**(Tiered Memory) 배치, 저전력 설계, **HMAT**(Heterogeneous Memory Attribute Table) 기반 정책으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 메모리 접근 지연 증가 | 로컬 메모리(DRAM, Dynamic Random-Access Memory)에 비해 PCIe 경로를 거쳐 접근하므로 지연이 더 김 | 자주 쓰는 데이터는 로컬 DRAM, 드물게 쓰는 데이터는 CXL 메모리에 두는 계층형 배치 | 계층별 접근 지연, 핫 데이터의 로컬 적중률 |
| 컨트롤러 전력과 발열 | CXL 메모리 모듈 내부의 고속 인터페이스 컨트롤러가 추가 열과 전력을 만듦 | 저전력 SerDes(Serializer/Deserializer, 직렬화·역직렬화) 설계, 섀시 내 방열과 공기 흐름 설계 | 모듈 온도, 모듈당 전력 소비 |
| NUMA 최적화 한계 | 기존 운영체제(OS, Operating System)와 미들웨어는 고정된 NUMA 노드만 인지하여 동적으로 붙는 풀링 메모리를 잘 배치하지 못함 | 커널의 HMAT 성능 정보를 활용한 메모리 티어링 정책 연동 | NUMA 원격 접근 비율 |

```text
[ 계층형 메모리 배치 ]

CPU
  ↓
로컬 DRAM   : 자주 접근하는 핫 데이터
CXL 메모리  : 드물게 접근하는 콜드 데이터
```

## Ⅵ. CXL (Compute Express Link)의 적용 제언

- 핵심 요약 : 생성형 인공지능(AI, Artificial Intelligence) 추론의 **KV 캐시**(Key-Value Cache)를 CXL 메모리 풀로 넓히고, 유휴 메모리를 풀링으로 회수하며, 국내 메모리 모듈의 표준 참여를 함께 추진하는 방향.

1. AI 서비스 운영 조직은 KV 캐시(추론 중 생성되는 키와 값의 저장 공간)를 CXL 메모리 풀에 분산 배치하여, GPU 메모리만으로는 부족한 동시 처리 세션을 수용한다.
2. 클라우드 인프라 조직은 서버마다 묶여 쓰이지 못하는 **Stranded 메모리**(유휴 메모리)를 CXL 스위치 기반 풀링으로 회수하여 메모리 가동률을 높인다.
3. 반도체 기업과 정부 연구기관은 국내 메모리 기업의 CXL 메모리 모듈(예: 삼성전자 CMM-D)을 국제 표준 활동과 소프트웨어 생태계에 연결하여 시장 참여 기반을 넓힌다.

## Ⅶ. 결론

- 핵심 요약 : CXL은 PCIe 기반 캐시 일관성 인터커넥트로 이종 장치 간 메모리 공유와 분해형 데이터센터를 가능하게 하는 표준.
- 지연과 전력, NUMA 최적화라는 비용을 계층형 메모리 설계로 감수하는 기술이므로, 도입 효과는 워크로드별 데이터 배치 정책의 성숙도에 달려 있다.
