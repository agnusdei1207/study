## Ⅰ. CXL (Compute Express Link)의 개요

- **개념** : CPU, GPU, NPU, 메모리 확장기(Memory Expander) 등 이종 프로세서와 가속기 간의 고속, 초저지연 상호연결을 지원하고, 캐시 일관성(Cache Coherency) 및 메모리 공유를 하드웨어 레벨에서 보장하는 PCIe 물리 계층 기반의 차세대 개방형 인터커넥트 표준 기술.
- **배경 및 필요성** : AI 및 빅데이터 환경에서 가속기 장치들이 급증했으나 전통적 PCIe 인터페이스의 높은 지연시간과 캐시 불일치, 그리고 CPU 소켓당 메모리 확장 한계(Memory Wall)를 극복하기 위해 인텔, 삼성, SK하이닉스 등 글로벌 컨소시엄에 의해 제안됨.
- **핵심 목적** : 이종 가속기 간 제로 카피(Zero-Copy) 데이터 공유, 서버 메모리 용량 및 대역폭의 한계 없는 확장, 분해형(Disaggregated) 데이터센터 아키텍처 실현.

## Ⅱ. CXL (Compute Express Link)의 핵심 아키텍처 및 동작 메커니즘

CXL은 통신 특성에 따라 CXL.io, CXL.cache, CXL.mem의 3대 하위 프로토콜로 구성되며, 장치의 역할에 따라 Type 1, Type 2, Type 3의 3가지 디바이스 유형으로 분류됨.

```text
[ CXL 3대 프로토콜 및 디바이스 유형 아키텍처 ]

+---------------------------------------------------------------+
| CXL Sub-Protocols (CXL 3대 프로토콜 스택)                     |
|  1. CXL.io    : 장치 검색, 초기화, DMA, 인터럽트 (PCIe 표준 호환) |
|  2. CXL.cache : 가속기가 호스트 CPU 메모리를 저지연 캐싱       |
|  3. CXL.mem   : 호스트 CPU가 가속기/확장 메모리를 직접 Load/Store |
+---------------------------------------------------------------+
                                │
        ┌───────────────────────┼───────────────────────┐
        ▼                       ▼                       ▼
+-------------------+   +-------------------+   +-------------------+
| Type 1 Device     |   | Type 2 Device     |   | Type 3 Device     |
| (스마트NIC / DPU) |   | (GPU, AI 가속기)  |   | (CXL 메모리 확장기)|
+-------------------+   +-------------------+   +-------------------+
| 프로토콜:         |   | 프로토콜:         |   | 프로토콜:         |
| CXL.io + CXL.cache|   | CXL.io + CXL.cache|   | CXL.io + CXL.mem  |
|                   |   |        + CXL.mem  |   |                   |
| 가속기가 호스트의 |   | 가속기와 호스트가 |   | 호스트 CPU가 CXL  |
| 메모리를 캐싱하여 |   | 서로의 메모리를   |   | 컨트롤러를 통해   |
| 고속 패킷 처리    |   | 대등하게 공유     |   | DDR5 메모리 확장  |
+-------------------+   +-------------------+   +-------------------+
```

- **CXL.io** : PCIe와 완벽히 호환되는 프로토콜로 디바이스 발견, 구성, 레지스터 접근, 가상화 및 표준 I/O 담당.
- **CXL.cache** : DPU나 스마트NIC 같은 주변 장치가 호스트 메인 메모리를 극저지연으로 캐싱하고 캐시 일관성 유지.
- **CXL.mem** : 호스트 CPU 프로세서가 외부 CXL 확장 카드의 DRAM을 표준 메모리 주소 공간으로 인식하여 바이트 단위(Load/Store)로 직접 접근.
- **Type 3 메모리 확장기** : 서버의 DIMM 슬롯이 꽉 차더라도 PCIe 슬롯에 CXL 메모리 카드를 장착하여 서버당 메모리 용량을 테라바이트급으로 무제한 증설.

## Ⅲ. CXL (Compute Express Link)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 전통적 PCIe (PCIe 5.0/6.0) | CXL (Compute Express Link) | NVLink (NVIDIA 독점) |
|---|---|---|---|
| **캐시 일관성** | **지원 안 함 (소프트웨어 동기화)**| **하드웨어 캐시 일관성 보장** | 하드웨어 캐시 일관성 지원 |
| **메모리 접근 단위** | 블록/DMA 단위 (고비용 복사) | **바이트 단위 직접 접근 (Load/Store)**| 바이트 단위 직접 접근 |
| **표준화 여부** | PCI-SIG 개방형 산업 표준 | **글로벌 개방형 표준 컨소시엄** | 엔비디아 독점 비표준 인터페이스 |
| **적용 범위** | 단순 I/O 확장 장치 | **CPU, GPU, NPU, 메모리 풀링** | 자사 GPU 및 CPU 간 상호연결 국한 |
| **메모리 공유** | 호스트-디바이스 간 메모리 분리 | **단일 주소 공간으로 메모리 풀링** | GPU 클러스터 내 공유 |

- CXL은 특정 벤더 종속이 없는 오픈 표준이면서도 NVLink 수준의 캐시 일관성과 직접 메모리 접근을 제공하여 차세대 데이터센터의 핵심 버스로 자리 잡음.

## Ⅳ. CXL (Compute Express Link)의 주요 한계점 및 해결 방안

- **로컬 DRAM 대비 PCIe 버스 경유에 따른 지연시간(Latency) 증가** :
  - **한계점** : CPU 직결 로컬 DDR5(수십 ns)에 비해 CXL 메모리는 PCIe 컨트롤러를 거치므로 50~100ns의 추가 레이턴시 발생.
  - **해결 방안** : 계층형 메모리(Tiered Memory) 아키텍처 구축, 빈번히 접근하는 핫 데이터는 로컬 DRAM, 콜드 데이터는 CXL 메모리로 자동 분산.
- **CXL 전용 컨트롤러 칩셋의 전력 소비 및 발열** :
  - **한계점** : CXL 메모리 모듈(E3.S / CMM) 내부에 고속 인터페이스 컨트롤러가 탑재되어 추가적인 열과 전력 발생.
  - **해결 방안** : 첨단 저전력 SerDes 설계 적용 및 서버 섀시 내 특수 방열판/공기 흡입 가이드 설계.
- **기존 운영체제 및 미들웨어의 NUMA 최적화 한계** :
  - **한계점** : 기존 소프트웨어는 CPU 소켓별 고정 NUMA 노드만 인지하며, 동적으로 연결되는 CXL 풀링 메모리를 효율적으로 스케줄링하지 못함.
  - **해결 방안** : 리눅스 커널의 HMAT(Heterogeneous Memory Attribute Table) 기반 성능 티어링 및 메모리 티어링 데몬(DAMON) 연동.

## Ⅴ. CXL (Compute Express Link) 적용 및 발전을 위한 기술사적 제언

- **생성형 AI LLM 인메모리 서빙을 위한 CXL 채택** : 수백 GB에 달하는 가중치와 KV 캐시를 고가의 GPU HBM 대신 가성비가 뛰어난 CXL DRAM 풀에 분산 배치하여 서빙 TCO 50% 절감.
- **클라우드 데이터센터 스트랜디드(Stranded) 메모리 회수** : 서버 간 고립되어 낭비되던 유휴 메모리를 CXL 패브릭 스위치로 풀링하여 데이터센터 전체 메모리 가동률 극대화.
- **K-반도체의 CXL 메모리 모듈(CMM-D) 글로벌 표준 주도** : 삼성전자와 SK하이닉스가 주도하는 CXL DRAM 생태계와 국내 서버/SW 생태계를 긴밀히 결합하는 산학연 얼라이언스 구축 권장.
