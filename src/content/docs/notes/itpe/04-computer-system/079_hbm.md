## Ⅰ. HBM(High Bandwidth Memory)의 개요

- 개념 : 여러 개의 D램(DRAM) 칩을 수직으로 적층한 후 **관통 전극(TSV, Through-Silicon Via)** 기술로 물리적으로 연결하고, **실리콘 인터포저(Silicon Interposer)** 를 통해 GPU/NPU와 동일 패키지 내에서 1,024비트 이상의 초광대역 버스로 통신하는 초고속 3차원 적층 메모리 표준(JEDEC 표준).
- 배경 및 필요성 : 대규모 **거대언어모델(LLM)** 과 딥러닝 연산에서 프로세서의 연산 능력 발전 속도에 비해 기존 GDDR/DDR 메모리의 좁은 버스 폭(32비트/64비트)과 인터페이스 속도 한계로 인해 발생하는 **메모리 벽(Memory Wall)** 현상을 해결하기 위해 개발.
- 핵심 목적 : TB/s 단위의 초고대역폭 달성, 패키지 실장 면적의 획기적 축소, **단위 대역폭당 전력 소모(pJ/bit)** 최소화.

## Ⅱ. HBM의 3D 적층 아키텍처 및 2.5D 패키징 메커니즘

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ HBM 및 2.5D 어드밴스드 패키징(CoWoS) 단면 구조 ]                     │
│                                                                        │
│   ┌────────────────────────┐      ┌────────────────────────────────┐   │
│   │   AI 가속기 로직 다이  │      │ HBM 3차원 적층 큐브 (DRAM x N) │   │
│   │   (GPU / NPU Core)     │      │ ┌────────────────────────────┐ │   │
│   │                        │      │ │ DRAM Die #4                │ │   │
│   │                        │      │ ├────────────────────────────┤ │   │
│   │                        │      │ │ DRAM Die #3 (TSV 수직 관통) │ │   │
│   │                        │      │ ├────────────────────────────┤ │   │
│   │                        │      │ │ DRAM Die #2                │ │   │
│   │                        │      │ ├────────────────────────────┤ │   │
│   │                        │      │ │ DRAM Die #1                │ │   │
│   │                        │      │ ├────────────────────────────┤ │   │
│   │                        │      │ │ 베이스 로직 다이 (Base Die)│ │   │
│   └───────────┬────────────┘      └───────────────┬────────────────┘   │
│               │ Microbumps (마이크로 범프)        │                    │
│   ════════════╧═══════════════════════════════════╧═════════════════   │
│   [ 초미세 실리콘 인터포저 (Silicon Interposer: 1024-bit+ 초광대역 배선) ] │

│               │ C4 Bumps                                               │
│   ┌───────────┴────────────────────────────────────────────────────┐   │
```

- **TSV(실리콘 관통 전극) 및 마이크로 범프** : 와이어 본딩 대신 칩 두께를 마이크론 단위로 연마하고 구멍을 뚫어 구리 전극을 통과시킴으로써 수천 개의 신호선을 수직으로 최단 거리 연결.
- **실리콘 인터포저 기반 2.5D 패키징** : GPU와 HBM을 유기 기판 위에 직접 올리지 않고, 반도체 노광 공정으로 제조된 초미세 실리콘 인터포저 위에 나란히 올려 1,024비트의 초광대역 병렬 인터페이스 구현.

## Ⅲ. HBM 세대별 진화 및 GDDR5/6과의 기술 사양 비교

| 비교 항목 | HBM2E | HBM3 | HBM3E | HBM4 (차세대) | GDDR6 (비교군) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **스택당 핀 속도** | 3.2 ~ 3.6 Gbps | 6.4 ~ 8.4 Gbps | 9.2 ~ 9.6 Gbps | 10+ Gbps 이상 | 16 ~ 20 Gbps |
| **I/O 버스 폭** | 1,024 bit | 1,024 bit | 1,024 bit | 2,048 bit (2배 확장)| 32 bit |
| **스택당 대역폭** | 410 ~ 460 GB/s | 819 GB/s ~ 1.0 TB/s| 1.18 ~ 1.23 TB/s | 1.6 ~ 2.0+ TB/s | 64 ~ 80 GB/s |
| **적층 단수** | 8단 / 12단 | 8단 / 12단 | 12단 / 16단 | 12단 / 16단 | 단일 평면(1-Die) |
| **베이스 다이 제조** | 범용 레거시 공정 | 파운드리 공정 진입 | 고도화 파운드리 공정 | 선단 파운드리 로직 공정(TSMC/선단)| 해당 없음 |
| **주요 패키징 기술** | TC-NCF / MR-MUF | Advanced MR-MUF / NCF| 어드밴스드 MR-MUF / NCF | 하이브리드 본딩 (Cu-Cu 접합) | 표준 유기 BGA |

## Ⅳ. HBM의 주요 기술적 한계점 및 해결 방안

- 초고밀도 적층에 따른 발열 집중 및 **방열 한계(Thermal Throttling)** :
  - 한계점 : 12단~16단 수직 적층 시 중앙 및 상부 다이의 열이 외부로 방출되지 못해 접합 온도(Tj) 상승 및 D램 데이터 리프레시 주기 폭증.
  - 해결 방안 : 열전도도가 우수한 에폭시 몰딩 언더필을 적용하는 어드밴스드 MR-MUF(Mass Reflow Molded Underfill) 적용 및 범프를 없애고 구리와 산화막을 직접 접합하는 Cu-Cu 하이브리드 본딩(Hybrid Bonding) 도입.
- 제조 공정 난도 극대화로 인한 수율 저하 및 초고가 비용 :
  - 한계점 : 수십 번의 TSV 펀칭, 칩 연마(Thinning), 다층 적층 중 단 하나의 다이만 결함이 발생해도 큐브 전체를 폐기하는 'Known Good Die(KGD)' 문제로 가격 폭등.
  - 해결 방안 : 온다이 에러 정정 코드(On-Die ECC) 강화, 여분의 리던던시(Redundancy) TSV 채널 설계 및 패키징 전 KGD 전수 검사 장비 고도화.
- 2.5D 인터포저 크기 한계에 따른 **GPU** 패키지 확장 병목 :
  - 한계점 : 최신 GPU에 HBM 8개를 실장할 경우 실리콘 인터포저 크기가 레티클(Reticle Limit, 약 858mm²) 한계를 크게 초과하여 패키징 수율 급감.
  - 해결 방안 : TSMC CoWoS-L 등 인터포저 분할 브리지 패키징 적용 또는 유기 재배선층(RDL) 기반 인터포저 대체 기술 채용.

## Ⅴ. AI 반도체 생태계 주도를 위한 기술사적 제언

- **HBM4** 베이스 다이 파운드리 협력 생태계 구축 : HBM4부터는 베이스 다이에 파운드리 선단 로직 공정(3nm/5nm)이 적용되고 호스트 GPU와 직접 결합되므로, 전통적 메모리 제조 역량을 넘어 글로벌 파운드리(TSMC 등) 및 팹리스와의 설계 초기 단계부터의 밀착 협업 아키텍처가 필수적임.
- **PIM(Processing-In-Memory)** 기술과의 융합 가속 : 단순한 고대역폭 메모리 전송을 넘어 D램 내부 연산 유닛을 통합하여 메모리 내부에서 AI 연산을 직접 수행하는 HBM-PIM 기술의 실용화와 소프트웨어 런타임 표준화를 선제적으로 확보할 것을 제언함.
