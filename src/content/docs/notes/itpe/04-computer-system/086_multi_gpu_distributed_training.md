## 연관 키워드

- 분산 학습(Distributed Training), 데이터 병렬화(Data Parallelism), 텐서 병렬화(Tensor Parallelism)
- 파이프라인 병렬화(Pipeline Parallelism), 전문가 병렬화(Expert Parallelism), 3D 병렬화(3D Parallelism)
- AllReduce, All-Gather, DDP(Distributed Data Parallel), FSDP(Fully Sharded Data Parallel), ZeRO(Zero Redundancy Optimizer)
- MoE(Mixture of Experts), 1F1B(One Forward One Backward), 파이프라인 버블(Pipeline Bubble), 혼합 정밀도(Mixed Precision)

## Ⅰ. 멀티 GPU 분산학습의 개요

- 핵심 요약 : 다수 GPU에 모델과 데이터를 나누어 병렬 연산하고 통신으로 결과를 결합하는 학습 소프트웨어 기술.
- 개념 : 모델 파라미터와 학습 데이터를 여러 GPU(Graphics Processing Unit)에 분할 배치하고 집단 통신으로 연산 결과를 결합해 학습 시간을 단축하는 **분산 학습** (Distributed Training) 기술.
- 배경 및 필요성 : 대규모 언어 모델(LLM, Large Language Model)은 파라미터와 옵티마이저 상태가 단일 GPU 메모리를 초과하고 학습 기간도 실용 범위를 넘음. 병렬화 전략이 필수가 됨.
- 주요 목적 : 메모리 부족 극복, 통신 최소화에 따른 학습 가속, 장애에 견디는 긴 학습 수행 체계 확보.

## Ⅱ. 멀티 GPU 분산학습의 특징 및 장점

- 핵심 요약 : 병렬화 축의 조합과 중복 상태의 분할이 메모리 한계와 통신 비용을 동시에 다루는 소프트웨어 구조.

1. **3D 병렬화** (3D Parallelism, 세 병렬화 축의 조합 배치) : 노드 내 고속 구간에 **텐서 병렬화** (Tensor Parallelism, 레이어 내부 가중치를 나누는 방식), 노드 간 구간에 **파이프라인 병렬화** (Pipeline Parallelism, 계층을 단계로 나누는 방식), 전체 확장에 **데이터 병렬화** (Data Parallelism, 배치를 나누는 방식)를 배치 → 통신 특성에 맞는 축 배치로 비용 절감과 확장성 확보.
2. **ZeRO** (Zero Redundancy Optimizer, 데이터 병렬화에서 중복 보관되는 학습 상태를 분할 저장하는 기법) : 옵티마이저 상태·그래디언트·파라미터를 단계적으로 나눠 저장 → GPU당 메모리 사용 감소로 더 큰 모델의 학습이 가능함.

## Ⅲ. 멀티 GPU 분산학습의 구조 (흐름)

- 핵심 요약 : 데이터 병렬화는 스텝마다 그래디언트를 집단 통신으로 동기화하고, 파이프라인 병렬화는 단계 경계에서만 데이터를 넘김.
- 대표 구현 : **DDP** (Distributed Data Parallel, 복제본별 학습 후 그래디언트를 동기화하는 데이터 병렬화 구현)와 **FSDP** (Fully Sharded Data Parallel, 파라미터까지 분할 저장하는 데이터 병렬화 구현)가 있으며, **AllReduce** (모든 장치의 값을 모아 연산한 결과를 전체에 재배포하는 집단 통신)로 그래디언트 평균을 맞춤.

```text
[ 데이터 병렬화의 1스텝 흐름 ]

배치를 GPU 수만큼 분할
      ↓
각 GPU가 순전파·역전파 수행
      ↓
AllReduce로 그래디언트 평균화
      ↓
모든 GPU가 동일하게 갱신
```

```text
[ 병렬화 축별 통신 발생 위치 ]

데이터 병렬화 : 스텝당 1회 동기화
      ↓
텐서 병렬화 : 레이어 내부마다 통신
      ↓
파이프라인 병렬화 : 경계에서만 전달
```

- 이 통신 위치 차이가 병렬 축 배치의 판단 기준이 되며, **전문가 병렬화** (Expert Parallelism, 전문가 네트워크를 장치에 분산 배치하는 방식)는 **MoE** (Mixture of Experts, 입력별로 일부 전문가 네트워크만 활성화하는 모델 구조)의 라우팅 결과에 따라 전문가를 서로 다른 GPU에 배치함.

## Ⅳ. 분산학습 병렬화 방식의 비교

- 핵심 요약 : 분할 대상과 통신 빈도가 방식마다 달라 인터커넥트 수준에 맞춰 조합을 선택함.
- 비교 대상은 데이터·텐서·파이프라인 병렬화이며, 분할 대상, 주요 통신, 통신 빈도, 적정 배치 위치가 선택 축임.

| 비교 축 | 데이터 병렬화 | 텐서 병렬화 | 파이프라인 병렬화 |
| :--- | :--- | :--- | :--- |
| 분할 대상 | 입력 배치 | 레이어 내부 가중치 행렬 | 레이어 묶음(단계) |
| 주요 통신 | AllReduce, All-Gather | 집단 통신이 레이어마다 발생 | 인접 단계 간 송수신 |
| 통신 빈도 | 스텝당 1회 | 매우 높음 | 경계에서만 |
| 적정 배치 | 노드 간 확장 구간 | 노드 내 고속 연결 구간 | 노드 간·랙 간 연결 구간 |
| 주요 한계 | 복제본이 메모리에 들어야 함 | 통신 오버헤드 | 유휴 구간 발생 |

- 선택 기준 : 모델이 메모리 안이면 데이터 병렬화, 단일 레이어가 크면 텐서 병렬화, 계층이 많고 노드 간 연결이 느리면 파이프라인 병렬화를 기준으로 삼음.

## Ⅴ. 멀티 GPU 분산학습의 한계와 방안

- 핵심 요약 : 통신 병목, 파이프라인 유휴 구간, 장애 롤백 손실을 저정밀 연산, 스케줄링, 체크포인트로 일대일 대응함.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| 규모 확대에 따른 통신 병목 | 그래디언트 동기화 시간이 연산 시간을 초과해 가속률 저하 | **혼합 정밀도** (Mixed Precision, 주요 연산을 낮은 비트 폭으로 수행하는 기법), 그래디언트 누적, 통신·연산 중첩 | 통신 대비 연산 비율 |
| **파이프라인 버블** (Pipeline Bubble, 단계 간 대기로 생기는 유휴 구간) | 앞 단계 연산을 기다리는 동안 GPU가 놀음 | **1F1B** (One Forward One Backward, 순전파와 역전파를 교대 수행하는 스케줄링 기법) 방식으로 유휴 축소 | GPU 가동률 |
| 장애에 따른 학습 롤백 손실 | 한 노드 중단으로 진행 전체가 초기화 | 비동기 체크포인트 저장, 예비 노드로 이어 수행하는 탄력적 학습 | 체크포인트 복구 시간 |

## Ⅵ. 멀티 GPU 분산학습에 대한 기술사적 제언

- 핵심 요약 : 병렬화 전략의 의사결정 기준 표준화와 학습 재현·장애 관리 절차의 제도화 방향.
- AI 플랫폼 부서는 모델 규모와 인프라 등급별 병렬화 조합을 의사결정표로 정해 프로젝트마다 같은 기준으로 전략을 선택하게 해야 함.
- 개발 조직은 학습 설정과 체크포인트 메타데이터를 버전 관리 체계에 넣어 장애 복구와 실험 재현이 같은 절차로 이루어지게 해야 함.
- 기획 부서는 학습 기간 목표와 장애 허용 손실을 서비스 수준 협약(SLA, Service Level Agreement)으로 연결해 자원 투입 규모를 비용 관점에서 판단해야 함.

## Ⅶ. 결론

- 핵심 요약 : 분산 학습은 병렬화 축 조합과 집단 통신 최적화로 단일 장치 한계를 넘는 학습 소프트웨어 기술.
- 통신 발생 위치의 이해가 병렬화 설계의 출발점이며 대규모 모델 학습의 실현 조건임.
