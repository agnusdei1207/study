## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 리틀 엔디언

## 30초 인출

- 본질: 2바이트 이상의 데이터를 다룰 때 숫자의 상위 바이트와 하위 바이트 중 어디를 먼저 메모리에 둘지 결정해야 함
- 메커니즘: 최하위 바이트(LSB)부터 낮은 메모리 번지에 순서대로 적재하여 산술 연산 시 캐리(올림수) 전파를 즉각 처리

## 핵심 용어

- LSB(Least Significant Byte): 16진수 데이터에서 수학적 가중치(자릿수)가 가장 작은 최하위 1바이트(위 예시의 0x78)
- 호스트 바이트 순서(Host Byte Order): 특정 컴퓨터 CPU 아키텍처(x86, ARM 등)가 내부 메모리와 레지스터에서 데이터를 다룰 때 사용하는 고유 정렬 방식
- htonl / ntohl: Host to Network Long / Network to Host Long의 약어로, 소켓 통신 시 호스트 바이트 순서(리틀)와 네트워크 바이트 순서(빅)를 상호 변환해주는 C 표준 함수

## 1교시 10점 답안

### Ⅰ. 정의·목적

- 정의: 리틀 엔디언은/는 최하위 바이트(LSB)부터 낮은 메모리 번지에 순서대로 적재하여 산술 연산 시 캐리(올림수) 전파를 즉각 처리 방식이다.
- 목적: ALU 연산 회로 단순화에 기여한다.

### Ⅱ. 핵심 구조와 작동

```text
[ 4바이트 정수 값 0x12345678 의 메모리 주소 배치 비교 ]

데이터: 0x12 34 56 78  (최상위 바이트 MSB: 0x12,  최하위 바이트 LSB: 0x78)

메모리 번지:         0x100       0x101       0x102       0x103
                   (낮은 주소) ──────────────────────> (높은 주소)
+────────────────+───────────+───────────+───────────+───────────+
| 리틀 엔디언     |   0x78    |   0x56    |   0x34    |   0x12    |  (LSB가 최저 번지에 저장)
| (x86, ARM 호스트)|  (LSB)    |           |           |  (MSB)    |  * 하위 형변환 시 주소 0x100 유지!
+────────────────+───────────+───────────+───────────+───────────+
| 빅 엔디언       |   0x12    |   0x34    |   0x56    |   0x78    |  (MSB가 최저 번지에 저장)
| (네트워크, TCP) |  (MSB)    |           |           |  (LSB)    |  * 사람이 읽는 순서와 일치
+────────────────+───────────+───────────+───────────+───────────+
```

## 2~4교시 25점 답안

### Ⅰ. 핵심 구조와 작동

```text
[ 4바이트 정수 값 0x12345678 의 메모리 주소 배치 비교 ]

데이터: 0x12 34 56 78  (최상위 바이트 MSB: 0x12,  최하위 바이트 LSB: 0x78)

메모리 번지:         0x100       0x101       0x102       0x103
                   (낮은 주소) ──────────────────────> (높은 주소)
+────────────────+───────────+───────────+───────────+───────────+
| 리틀 엔디언     |   0x78    |   0x56    |   0x34    |   0x12    |  (LSB가 최저 번지에 저장)
| (x86, ARM 호스트)|  (LSB)    |           |           |  (MSB)    |  * 하위 형변환 시 주소 0x100 유지!
+────────────────+───────────+───────────+───────────+───────────+
| 빅 엔디언       |   0x12    |   0x34    |   0x56    |   0x78    |  (MSB가 최저 번지에 저장)
| (네트워크, TCP) |  (MSB)    |           |           |  (LSB)    |  * 사람이 읽는 순서와 일치
+────────────────+───────────+───────────+───────────+───────────+
```

### Ⅱ. 핵심 특성

- 리틀 엔디언은 하드웨어 연산의 효율성을 극대화한 구조임 → 덧셈은 항상 1의 자리(LSB)부터 시작하여 올림수(Carry)가 상위로 올라가므로, 메모리 주소를 0번지부터 1씩 증가시키면서 읽는 즉시 ALU 연산기에 밀어 넣을 수 있어 CPU 파이프라인 지연이 없음
- 데이터 타입 축소(Type Casting)에서 주소 변환이 필요 없음 → 4바이트 정수 `int`를 1바이트 `char`로 강제 캐스팅할 때 메모리 포인터 주소를 변경하지 않고 그냥 0x100 번지만 읽으면 정확히 0x78이 반환됨
- 네트워크와 파일 포맷에서는 빅 엔디언과의 충돌이 필연적임 → TCP/IP 표준 헤더는 빅 엔디언이므로, 전 세계 대다수의 x86/ARM 리틀 엔디언 기기는 패킷을 보낼 때마다 바이트 스왑(Byte Swap) 연산을 거쳐야 함

### Ⅲ. 관련 개념과 구분

- 리틀 엔디언 vs 빅 엔디언: 리틀 엔디언 = LSB부터 저장, x86/ARM 표준, 연산 및 형변환 유리 / 빅 엔디언 = MSB부터 저장, TCP/IP 네트워크 표준, 직관적 가독성 및 대소 비교 유리

### Ⅳ. 적용 문제와 대응

- 사례: 126회 기출 및 리눅스 x86 클라이언트와 레거시 메인프레임 간 소켓 통신 시 패킷 필드 해석 오류
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 소켓 통신으로 전송한 정수형 주문 금액 100이 수신 측에서 16억 등 엉뚱한 값으로 변환 | 호스트 바이트 순서(리틀 엔디언) 그대로 네트워크에 전송 | 송신 시 `htonl()`, 수신 시 `ntohl()` 변환 함수 강제 | 기종 독립적인 표준 네트워크 바이트 순서(빅 엔디언) 통신 보장 |
| C/C++ 구조체 메모리를 바이트 단위로 직렬화하여 파일 저장 후 다른 OS에서 크래시 | 구조체 패딩(Padding) 및 CPU 엔디언 차이에 따른 직렬화 결함 | Protocol Buffers, FlatBuffers 등 엔디언 중립 직렬화 포맷 도입 | 아키텍처 차이에 따른 바이트 왜곡 원천 차단 |
