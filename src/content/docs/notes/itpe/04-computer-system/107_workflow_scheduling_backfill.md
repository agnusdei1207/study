## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 작업 자동화 → 워크플로 스케줄링과 데이터 백필

## 30초 인출

- 본질: 워크플로 스케줄링은 태스크 의존성과 자원 조건에 따라 실행 순서·시점을 정하는 기능
- 메커니즘: DAG 선행조건 확인 → 자원·우선순위 배치 → 태스크 실행·상태 기록; 백필은 과거 논리 구간을 같은 흐름으로 재실행
- 통찰: 한계: 과거 구간 재처리가 현행 작업과 자원을 경쟁하고 결과를 중복 반영할 수 있음 → 방안: 백필 실행 창·병렬도·멱등 쓰기와 검증 게이트 설정

<details>
<summary>핵심 용어</summary>

- **DAG (Directed Acyclic Graph)** : 태스크 간 선후 관계를 순환 없이 표현한 방향 그래프
- **워크플로 스케줄링(Workflow Scheduling)** : 의존성·자원·실행 조건에 따라 태스크를 배치하는 과정
- **데이터 백필(Data Backfill)** : 과거 데이터 구간을 지정해 워크플로를 재실행하는 작업
- **메이크스팬(Makespan)** : 워크플로 시작부터 최종 태스크 완료까지의 경과시간

</details>

## 2~4교시 25점 답안

## Ⅰ. 워크플로 스케줄링·백필의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **워크플로 스케줄링·데이터 백필은** 의존성에 따라 태스크를 배치하고 과거 데이터 구간을 재처리하는 기능 |
| 목적 | 작업 흐름을 자동 실행하고 데이터 누락·변경을 보정 |

## Ⅱ. 워크플로 스케줄링·백필의 특징

| 특징 | 운영상 의미 |
|---|---|
| DAG 의존성 | 선행 태스크의 완료·실패 상태가 후속 실행 가능 여부를 결정 |
| 논리 구간 | 현행 일정과 과거 구간 재처리의 대상 시점을 구분 |
| 반복 실행 위험 | 재시도·백필에서 동일 구간 결과의 중복 쓰기와 외부 부작용 통제 필요 |

## Ⅲ. DAG 실행·상태 관리 체계와 백필 프로세스

```text
일정·논리 구간 → 스케줄러 ─선행 조건 확인→ 실행 가능 태스크
                                        ↓ 자원·우선순위 배치
                                      워커 실행
                                        ↓
                             성공·실패·재시도 상태 기록
                                        ↓
                              후속 태스크 실행 판단
```

### 과거 구간 백필의 실행·반영 분기

```text
과거 구간·워크플로 버전 지정 → 해당 DAG 인스턴스 생성
                                 ↓
                    현행 작업과 자원·우선순위 분리
                                 ↓
                      태스크 재실행·멱등 쓰기
                                 ↓
                 건수·업무 결과 일치? ─예→ 결과 반영
                                     └아니요→ 격리·재처리
```

백필 완료 상태만으로 업무 정합성을 보장하지 않는다. 논리 구간·시간대·워크플로 버전을 기록하고 결과를 검증한다.

## Ⅳ. 정기 실행·재시도·백필의 관계 비교

| 구분 | 실행 대상 | 주요 통제 |
|---|---|---|
| 정기 실행 | 새 논리 구간 | 일정·의존성·지연 감시 |
| 재시도 | 실패한 태스크·동일 구간 | 재시도 횟수·멱등성·외부 부작용 |
| 백필 | 지정한 과거 구간 | 현행 작업과 자원 경쟁·버전·결과 대조 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 동시 백필이 현행 작업의 자원을 압박 | 실행 창·병렬도·우선순위·자원 할당량 제한 |
| 재실행이 외부 부작용과 결과를 중복 생성 | 멱등 키·쓰기 경계·재시도 정책으로 중복 반영 방지 |
| 시간대·버전 차이로 과거 구간 의미 혼선 | 논리 구간·시간대·워크플로 버전을 기록하고 재현 가능성 확인 |
| 완료 상태만 보고 업무 정합성 오판 | 재처리 전후 계보·건수·업무 지표를 검증 게이트로 비교 |

## Ⅵ. 제언

백필은 현행 작업과 자원을 경쟁하고 결과를 중복 반영할 수 있다. 우선 누락 구간의 범위·버전을 고정한 뒤 제한된 실행 창과 병렬도로 멱등 재처리하고, 업무 결과 대조를 통과한 것만 반영한다.
