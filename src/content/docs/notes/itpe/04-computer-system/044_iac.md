## 연관 키워드

- 코드형 인프라, IaC, 선언적 접근법, 명령적 접근법, 멱등성, 상태 파일, 구성 드리프트
- 상태 잠금, Policy as Code, GitOps, Blast Radius, 모듈, Terraform, Ansible

## Ⅰ. 코드형 인프라(IaC)의 개요

- 핵심 요약 : 인프라 자원을 버전 관리되는 코드로 정의하고 자동화 도구로 배포하여 재현성과 변경 감사를 확보하는 방법론.
- 개념 : 서버·네트워크·스토리지 같은 인프라 자원의 정의와 구성, 배포를 수동 콘솔 조작 대신 기계 판독형 코드로 수행하는 **코드형 인프라** (IaC, Infrastructure as Code) 방법론.
- 배경 및 필요성 : 수작업 구축은 설정 오류와 느린 프로비저닝을 낳고, 코드와 실제 인프라의 불일치인 **구성 드리프트** (Configuration Drift)가 방치되어 장애 원인 규명 비용이 커짐.
- 주요 목적 : 프로비저닝의 자동화와 신속화, 멱등성 기반의 환경 재현, 코드 리뷰와 형상 관리에 따른 변경 감사 체계의 확립.

## Ⅱ. 코드형 인프라(IaC)의 특징 및 장점

- 핵심 요약 : 선언과 명령의 두 작성 방식, 멱등성, 상태 관리, 형상 관리 연동이 자동화와 재현성, 거버넌스로 이어지는 구조.

1. **선언적 접근법** (Declarative Approach) : 최종 목표 상태만 기술하면 도구가 현재 상태와의 차이를 계산해 수렴 → 절차 작성 부담 감소와 변경 계산의 자동화.
2. **명령적 접근법** (Imperative Approach) : 목표 상태에 도달하는 단계별 명령을 기술 → 세부 절차에 대한 통제력 확보, OS 내부 구성에 적합.
3. **멱등성** (Idempotency) : 같은 코드를 몇 번 실행해도 최종 상태가 동일 → 재실행 안전성과 환경 재현성 확보.
4. **상태 관리** (State Management) : 코드로 만든 리소스와 실제 리소스의 대응 정보를 **상태 파일** (State File)로 보관 → 변경 영향 범위의 정확한 추적.
5. 형상 관리 연동 : 인프라 코드를 Git 저장소로 관리 → 변경 이력 추적, 동료 검토, 특정 시점 복원의 효과.

## Ⅲ. 코드형 인프라(IaC)의 구조 (흐름)

- 핵심 요약 : Git 커밋에서 시작해 계획 산출, 정책 검증, 적용, 상태 갱신으로 이어지는 수렴 파이프라인이 표준 흐름.
- **Policy as Code** (보안·규정 정책을 코드로 작성해 배포 전에 자동 검증하는 방식) : 계획과 적용 단계 사이에서 위반 설정의 반영을 차단함.

```text
[ 선언적 IaC 실행 파이프라인 ]

Git 저장소의 코드 커밋
   ↓ 파이프라인 트리거
plan : 코드와 상태 파일 비교
   ↓
정책 검증 (Policy as Code)
   ↓
apply : 클라우드 API 호출
   ↓
상태 파일 갱신 (잠금 적용)
```

```text
[ 구성 드리프트의 발생과 감지 ]

콘솔에서의 수동 변경
   ↓
코드와 실제 인프라 불일치
   ↓
정기 plan 실행으로 차이 탐지
   ↓
코드 반영 또는 실제 인프라 원복
```

## Ⅳ. 선언적 접근과 명령적 접근의 비교

- 핵심 요약 : 선언적 도구는 자원 프로비저닝에, 명령적 도구는 OS 내부 구성에 강점이 있어 역할 분담 결합이 일반적임.

| 비교 축 | 선언적 (Terraform 등) | 명령적 (Ansible 등) | 범용 언어 기반 (Pulumi 등) |
| --- | --- | --- | --- |
| 작성 내용 | 목표 상태의 선언 | 단계별 실행 명령 | 범용 언어로 기술한 상태 |
| 상태 관리 | 상태 파일의 명시적 유지 | 대상 호스트 조회 기반 | 백엔드에 상태 유지 |
| 주 적용 영역 | 클라우드 자원 프로비저닝 | OS 내부 설정, 패키지 설치 | 조건·반복이 많은 대규모 구성 |
| 드리프트 감지 | plan 단계의 차이 비교 | 플레이북 재실행 시점 | 배포 엔진의 비교 결과 |
| 재사용 단위 | 모듈(Module) | 역할(Role), 플레이북 | 라이브러리 패키지 |

- 선택 기준 : 자원 생성은 선언적 도구로, 자원 안의 소프트웨어 구성은 명령적 도구로 나누는 분업 결합을 기준으로 삼음.

## Ⅴ. 코드형 인프라(IaC)의 한계와 방안

- 핵심 요약 : 상태 파일 충돌과 비밀 노출, 드리프트, 변경 영향 범위 확대를 잠금, 감지 주기, 상태 분리로 일대일 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 상태 파일 충돌과 비밀 노출 | 동시 실행으로 상태 손상, 평문 상태 파일에 인증 정보 노출 | 원격 백엔드 암호화 저장, **상태 잠금** (State Locking, 동시 변경 차단), 비밀 관리 도구 연동 | 잠금 충돌 건수, 평문 비밀 검출 건수 |
| 구성 드리프트 | 장애 대응 중의 콘솔 수동 변경 → 코드와 운영 상태 불일치 | 정기 plan 기반 감지, 콘솔 쓰기 권한 제한 | 드리프트 탐지 건수 |
| **Blast Radius** (변경 한 번이 미치는 영향 범위) | 모든 리소스를 한 상태에 배치 → 실행 지연과 광범위 오류 위험 | 네트워크·데이터·컴퓨팅 계층별 상태 분리, 삭제 방지 설정 | 상태당 리소스 수 |

## Ⅵ. 코드형 인프라(IaC)에 대한 기술사적 제언

- 핵심 요약 : 정책 자동 검증, 승인 기반 배포 거버넌스, 모듈 표준화의 세 축으로 인프라 변경을 통제 가능한 개발 흐름에 편입하는 방향.

1. 정책 게이트웨이 : 보안 조직이 OPA(Open Policy Agent)로 보안 기준을 코드화하고 파이프라인 배포 단계에서 위반을 자동 차단하는 체계가 바람직함.
2. 승인 기반 배포 : 인프라 운영 조직이 풀 리퀘스트에 plan 결과를 기록하고 승인 후에만 적용되는 GitOps 운영 기준을 두는 방식이 필요함.
3. 모듈 거버넌스 : 플랫폼 조직이 검증된 모듈을 사내 카탈로그로 제공하여 표준 아키텍처의 재사용을 유도하는 제도가 유효함.

## Ⅶ. 결론

- 핵심 요약 : 코드형 인프라는 선언과 자동화로 재현성과 감사 가능성을 확보하는 인프라 운영 방식.
- 코드화의 효과는 상태 보호와 드리프트 통제, 승인 체계가 갖춰질 때 지속됨.
