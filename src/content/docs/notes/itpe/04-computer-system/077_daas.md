## 연관 키워드

- DaaS, Desktop as a Service, 구독형 가상 데스크톱, 연결 브로커, 골든 이미지
- 프로필 분리, 디스플레이 스트리밍, 멀티 세션, vGPU, CapEx, OpEx, FinOps

## Ⅰ. DaaS의 개요

- 핵심 요약 : 클라우드 제공자가 구독형 가상 데스크톱을 대신 구축·운영해 주는 관리형 서비스.
- 개념 : 클라우드 서비스 제공자(CSP, Cloud Service Provider)가 호스트 서버 위의 사용자별 가상 데스크톱을 운영하고 단말은 화면 전송만 받는 **서비스형 데스크톱** (DaaS, Desktop as a Service).
- 배경 및 필요성 : 원격 근무와 BYOD(Bring Your Own Device) 확산으로 단말이 분산되면서 업무 데이터가 단말에 남는 유출 위험이 커짐. 데스크톱 환경을 중앙의 클라우드에 두고 화면만 내려보내는 구독형 모델이 대안으로 부상.
- 주요 목적 : 초기 설비 투자인 **자본 지출** (CapEx, Capital Expenditure)을 사용량 기반 **운영 지출** (OpEx, Operating Expenditure)로 전환하고, 데이터를 중앙에 보관해 단말 분실·유출 위험을 낮추는 것.

## Ⅱ. DaaS의 특징 및 장점

- 핵심 요약 : 화면 스트리밍, 이미지 일괄 관리, 탄력 증설, 제공자 측 운영이 결합된 구독형 관리 서비스 구조.

1. 화면 전송 방식 : 서버에서 렌더링한 화면 프레임만 암호화 채널로 보내고 단말은 입력 이벤트만 반환하는 **디스플레이 스트리밍** (Display Streaming) → 파일의 단말 저장 없는 업무 수행으로 유출 경로 축소.
2. 이미지 일괄 관리 : 공통 업무 환경을 무상태 기본 이미지로 유지하는 **골든 이미지** (Golden Image) → 패치와 배포를 이미지 한 곳에서 처리하는 운영 효율.
3. 개인화 분리 : 접속 시 개인 설정과 데이터를 결합하는 **프로필 분리** (Profile Separation) → 이미지 교체 후에도 개인 환경이 유지되는 사용자 경험 보장.
4. 공동 호스팅 : 하나의 호스트 운영체제를 여러 사용자가 동시에 쓰는 **멀티 세션** (Multi-Session) → 사용자당 자원 비용 절감과 증설 용이성 확보.

## Ⅲ. DaaS의 구조 (흐름)

- 핵심 요약 : 단말, 제어 평면, 데스크톱 호스트, 프로필 스토리지가 인증 후 세션을 맺는 계층 구조.
- 구성 요소 : 다요소 인증(MFA, Multi-Factor Authentication)을 수행하는 접근 게이트웨이, 세션 배분을 담당하는 **연결 브로커** (Connection Broker), 가상 데스크톱과 가상 GPU(vGPU, Virtual GPU)를 구동하는 호스트 풀, 개인화 정보를 담는 프로필 스토리지.

```text
[ 접속 세션 수립 흐름 ]

단말 (PC·태블릿·신클라이언트)
        ↓ 인증·단말 상태 점검
접근 게이트웨이 (MFA·정책 검사)
        ↓ 세션 요청
연결 브로커 (호스트 풀 배분)
        ↓ 데스크톱 할당
호스트 (가상 데스크톱·vGPU)
        ↓ 화면 프레임 전송
단말 렌더링 (입력은 역방향 전달)
```

```text
[ 이미지와 프로필의 분리 ]

골든 이미지 (무상태 기본 환경)
        ↓ 접속 시 결합
프로필 컨테이너 (개인 설정·데이터)
        ↓
사용자별 가상 데스크톱 환경 완성
```

## Ⅳ. DaaS와 온프레미스 VDI의 비교

- 핵심 요약 : 온프레미스 **가상 데스크톱 인프라** (VDI, Virtual Desktop Infrastructure)와 클라우드 DaaS는 인프라 소유 주체와 비용 구조, 확장 속도가 달라 적용 조건이 갈리는 구조.
- 선택 기준 : 사용자 규모의 변동성, 데이터 주권·규제 요건, 운영 인력 규모를 기준으로 두 방식을 구분.

| 비교 항목 | 온프레미스 VDI | 클라우드 DaaS |
| :--- | :--- | :--- |
| 인프라 소유 | 기업의 서버·스토리지·브로커 직접 운영 | CSP의 인프라·플랫폼 운영 대행 |
| 비용 구조 | 초기 투자와 고정 유지비 중심 | 사용자·시간 단위 구독 과금 |
| 증설 속도 | 하드웨어 조달 주기에 종속 | 콘솔에서 즉시 데스크톱 추가 |
| 패치·가용성 | 자체 패치와 재해 복구 설계 필요 | 제공자 측 자동 패치·고가용성 활용 |
| 데이터 위치 | 사내 데이터센터 내 확정 | 클라우드 리전 선택에 따름 |
| 적합 조건 | 고정 규모·데이터 사내 유지 요구 | 원격·변동 규모·빠른 배포 요구 |

## Ⅴ. DaaS의 한계와 방안

- 핵심 요약 : 네트워크 품질 의존, 그래픽 워크로드 비용, 장기 사용 시 비용 역전을 적응형 프로토콜, 선별 가속, 사용 주기 관리로 일대일 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| 네트워크 품질 의존 | 지연·손실 증가 시 화면 끊김과 입력 지연으로 업무 품질 저하 | 적응형 스트리밍 프로토콜 채택, 거점의 전용선·엣지 접속점 활용 | 입력 지연, 세션 품질 등급 |
| 그래픽 워크로드 비용 | 설계·영상 작업의 vGPU 상시 할당 시 구독료 급증 | 그래픽 작업자만 vGPU 프로파일 선별 배정, 유휴 세션 자동 종료 | vGPU 사용률, 세션 가동률 |
| 장기 사용 시 비용 역전 | 시간 과금과 데이터 송신료 누적으로 총소유비용(TCO, Total Cost of Ownership) 상승 | 야간·주말 자원 자동 반납, 멀티 세션 집적도 상향, **FinOps** (Cloud Financial Operations) 기반 비용 점검 | 사용자당 월 비용 |

## Ⅵ. DaaS에 대한 기술사적 제언

- 핵심 요약 : 제로 트러스트 접속 체계, 구독 자산의 수명주기 관리, 워크로드별 배치 기준으로 DaaS를 표준 업무 인프라로 정착.

1. 접속 보안 체계 : 보안 조직은 **제로 트러스트** (Zero Trust) 원칙 위에서 단말 건전성·사용자 위험도 확인 후의 세션 허용과 클립보드·로컬 드라이브 전송의 정책 통제.
2. 구독 자산 관리 : IT 운영 조직은 데스크톱 수·프로파일·라이선스의 수명주기를 자산 관리 체계에 등록하고 미사용 구독의 월 단위 회수 절차 운영.
3. 워크로드별 배치 기준 : 아키텍처 조직은 일반 업무는 멀티 세션 풀, 고성능 요구는 전용 vGPU 워크스테이션으로 구분 배치하는 설계 기준 수립.

## Ⅶ. 결론

- 핵심 요약 : DaaS는 구독형 관리 가상 데스크톱으로 초기 투자 부담과 데이터 유출 위험을 동시에 낮추는 서비스 모델.
- 네트워크 조건, 워크로드 특성, 구독 기간의 비용 구조 검토가 적용 판단의 전제 조건.
