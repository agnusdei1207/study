## 연관 키워드

- DaaS, Desktop as a Service, VDI, 연결 브로커, 디스플레이 스트리밍, 프로필 분리
- vGPU, 제로 트러스트, 멀티 세션, 디앨로케이션, SD-WAN, FinOps, TCO

## Ⅰ. DaaS의 개요

- 핵심 요약 : 가상 데스크톱을 클라우드에서 구독 방식으로 제공하여 단말과 업무 데이터를 분리하는 관리형 서비스.
- 개념 : 클라우드 인프라에 사용자별 가상 데스크톱(OS(Operating System), 애플리케이션, 데이터 환경)을 호스팅하고, 개인용 컴퓨터(PC, Personal Computer), 태블릿, 신클라이언트 같은 단말이 네트워크로 원격 접속하도록 제공하는 **서비스형 데스크톱** (DaaS, Desktop as a Service).
- 배경 및 필요성 : 온프레미스에 **가상 데스크톱 인프라** (VDI, Virtual Desktop Infrastructure)를 구축하면 서버·스토리지·연결 브로커를 직접 들여야 하므로 초기 투자와 운영 부담이 큼. 원격 근무가 늘면서 단말 분산에 따른 데이터 유출 우려가 커졌고, 이를 막으려면 **제로 트러스트** (Zero Trust) 기반의 중앙 집중 보안이 필요해짐 → 인프라 소유 부담을 클라우드 운영 모델로 옮기는 방향.
- 주요 목적 : 초기 구축 비용을 **자본 지출** (CapEx, Capital Expenditure)에서 **운영 지출** (OpEx, Operating Expenditure)으로 전환하고, 데스크톱을 신속히 제공하며, 기업 데이터를 중앙에 두어 단말 유출을 줄이는 것.

## Ⅱ. DaaS의 특징 및 장점

- 핵심 요약 : 화면만 전송하는 스트리밍과 사용자 프로필 분리로 데이터는 중앙에 두고 원격 작업 경험을 제공하는 구조.

1. **디스플레이 스트리밍** (Display Streaming) : 서버에서 렌더링한 화면 프레임만 압축·암호화해 단말로 보내고, 단말은 키보드·마우스 입력만 서버로 전달 → 업무 파일이 단말에 내려받아지지 않아 유출 위험 감소.
2. **사용자 프로필 분리** (User Profile Separation) : 무상태 골든 이미지 기반 가상 데스크톱에 접속할 때 네트워크 프로필 컨테이너를 마운트 → 개인 설정과 데이터 영속성을 유지하면서 이미지는 일괄 관리 가능.

## Ⅲ. DaaS의 구조 (흐름)

- 핵심 요약 : 단말, 제어 평면, 데이터 평면, 공유 스토리지의 계층으로 접속과 실행을 나누는 구조.
- 구성 요소 : 다요소 인증(MFA, Multi-Factor Authentication)과 SSO(Single Sign-On)를 담당하는 접근 게이트웨이, 세션을 가용 자원으로 배분하는 **연결 브로커** (Connection Broker), 가상 머신과 **가상 GPU** (vGPU, Virtual GPU)를 제공하는 데이터 평면, 프로필 컨테이너를 담는 공유 스토리지.

```text
[ DaaS 계층 구조 ]

단말 (PC·태블릿·신클라이언트)
   ↓ 암호화 원격 접속 채널
제어 평면 (인증·연결 브로커·이미지)
   ↓ 디스플레이 스트리밍 프로토콜
데이터 평면 (가상 데스크톱·vGPU)
   ↓ 프로필 마운트
공유 스토리지 (프로필 컨테이너)
```

```text
[ 접속 처리 순서 ]

사용자 인증 (MFA·SSO)
   ↓ 단말 보안 상태 확인
연결 브로커: 세션 라우팅
   ↓
무상태 가상 데스크톱 할당
   ↓
프로필 마운트 후 화면 스트리밍
```

## Ⅳ. DaaS의 비교

- 핵심 요약 : 온프레미스 VDI와 클라우드 DaaS는 인프라 소유 주체와 비용 구조, 확장 방식이 달라 적용 조건이 갈리는 구조.
- 선택 기준 : 사용 기간과 사용자 규모에 따른 비용 구조, 데이터 규제 요건, 그래픽 부하 수준에 따라 두 방식을 가른다.

| 비교 항목 | 온프레미스 VDI | 클라우드 DaaS |
| :--- | :--- | :--- |
| 인프라 소유·관리 | 기업이 서버, 스토리지, 네트워크, 라이선스를 직접 구축·운영 | 클라우드 서비스 제공자(CSP, Cloud Service Provider)가 인프라 전체 관리 |
| 비용 모델 | 초기 설비 투자와 고정 유지보수비 중심 | 사용자당 월 또는 시간 단위 구독 과금 |
| 확장과 배포 | 하드웨어 조달 기간만큼 지연, 확장에 한계 | 클라우드 콘솔에서 가상 데스크톱을 즉시 증설 |
| 업데이트와 가용성 | 펌웨어, 하이퍼바이저 패치와 재해 복구를 자체 수행 | 제공자 측 고가용성 구조와 자동 패치 활용 |
| 네트워크 의존도 | 사내망 중심, 외부 접속은 VPN(Virtual Private Network) 게이트웨이 경유 | 공용 인터넷과 전용 회선 기반 접속 |

## Ⅴ. DaaS의 한계와 방안

- 핵심 요약 : 네트워크 품질, 그래픽 집약 작업, 장기 사용 시 비용 역전을 적응형 프로토콜, 역할별 vGPU, 자동 종료 정책으로 대응하는 구조.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| 네트워크 지연과 패킷 손실 | 지연이나 대역폭 변동이 커지면 화면 끊김과 입력 지연 발생 → 생산성 저하 | 적응형 UDP(User Datagram Protocol) 기반 스트리밍 프로토콜 적용(예: PCoIP, Blast Extreme, Citrix HDX), 엣지 게이트웨이 배치 | 입력 지연, 세션 품질 지표 |
| 그래픽 집약 작업 | CAD(Computer-Aided Design), 3D 렌더링, 영상 편집은 범용 가상 머신(VM, Virtual Machine)에서 실행이 어렵고, vGPU 인스턴스를 상시 할당하면 비용 급증 | 역할별 vGPU 프로파일을 그래픽 작업자에게만 선별 배정하고 유휴 시 자동 종료 | vGPU 사용률, 인스턴스 가동률 |
| 장기 고정 사용 시 비용 역전 | 시간 과금과 데이터 송신료가 누적되어 **총소유비용** (TCO, Total Cost of Ownership)이 온프레미스보다 높아짐 | 야간과 주말 자동 **디앨로케이션** (Deallocation), 멀티 세션 OS로 단일 VM의 사용자 집적도 향상, **FinOps** (Cloud Financial Operations) 체계로 비용 점검 | 사용자당 월 비용, 가동 대비 사용률 |

## Ⅵ. DaaS에 대한 기술사적 제언

- 핵심 요약 : 제로 트러스트 접속 정책, 전용 네트워크 경로, 역할별 가상 워크스테이션을 묶어 DaaS를 하이브리드 업무 환경의 기본 인프라로 정착.

1. 원격 근무가 많은 조직은 DaaS 접속을 제로 트러스트 원칙 위에 두고, 단말 상태와 사용자 위험도를 확인한 뒤에만 세션을 허용하며, 클립보드와 로컬 드라이브 전송은 정책으로 제한하는 것이 바람직하다.
2. 지역 거점이 여럿인 기업은 **SD-WAN** (Software-Defined Wide Area Network) 기반의 전용 경로로 세션 트래픽을 우선 처리해 지연 편차를 줄이고, 장애 대비는 **업무 연속성 계획** (BCP, Business Continuity Planning)과 연동하는 것이 필요하다.
3. 3D 설계나 AI 개발 인력에게는 역할별 vGPU 가상 워크스테이션을 표준 이미지로 두고, 일반 업무 인력은 멀티 세션 환경으로 수용하여 성능과 비용을 함께 관리하는 편이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : DaaS는 클라우드 구독형 가상 데스크톱으로 초기 비용 부담과 데이터 유출 위험을 함께 낮추는 관리형 서비스.
- 네트워크 품질, 그래픽 부하, 장기 비용 조건을 워크로드별로 점검해 DaaS와 온프레미스 VDI를 나누어 적용하는 기준이 필요함.
