## 연관 키워드

- 임계 구역(Critical Section), 상호 배제(Mutual Exclusion), 진행(Progress), 한정 대기(Bounded Waiting)
- 뮤텍스(Mutex), 세마포어(Semaphore), P·V 연산, 모니터(Monitor), 조건 변수(Condition Variable)
- 원자적 명령어(Atomic Instruction), CAS(Compare-And-Swap), 스핀락(Spinlock), 우선순위 상속(Priority Inheritance)

## Ⅰ. 프로세스 동기화 기법의 개요

- 핵심 요약 : 공유 자원 접근 구간의 진입과 해제를 통제하는 운영체제의 동기화 도구 체계.
- 개념 : 병렬 실행 환경에서 공유 자원에 접근하는 코드 구간인 **임계 구역** (Critical Section)에 한 번에 하나의 실행 흐름만 진입하도록 잠금과 신호를 제공하는 운영체제 도구 체계.
- 배경 및 필요성 : 다중 코어 환경에서 여러 흐름이 공유 변수 갱신을 뒤섞어 실행하면 갱신 손실로 결과가 실행 순서에 따라 달라지므로, 접근 통제 장치가 필수.
- 주요 목적 : 임계 구역 해법의 세 요구조건 충족과 실행 순서 제어를 통한 데이터 일관성 확보.

임계 구역 해법이 갖추어야 할 세 요구조건은 다음과 같음.

1. **상호 배제** (Mutual Exclusion) : 한 흐름이 임계 구역 안에 있는 동안 다른 흐름의 진입을 원천 차단.
2. **진행** (Progress) : 임계 구역이 비어 있으면 진입을 원하는 흐름만 후보가 되고, 선택이 무한히 지연되지 않음.
3. **한정 대기** (Bounded Waiting) : 진입 요청 이후 자기 차례까지 다른 흐름의 진입 횟수에 상한이 존재.

## Ⅱ. 프로세스 동기화 기법의 특징 및 장점

- 핵심 요약 : 소프트웨어 해법에서 언어 수준 캡슐화로 갈수록 추상화가 높아져 실수 여지가 줄어드는 다층 도구 체계.

1. 소프트웨어 해법 : **Peterson 알고리즘** (두 흐름이 플래그와 차례 변수를 주고받으며 진입권을 양보하는 알고리즘)으로 세 요구조건을 만족 → 하드웨어 지원 없이 동기화 원리를 검증하는 이론적 기반.
2. 하드웨어 해법 : **원자적 명령어** (Atomic Instruction, 중단 없이 한 번에 수행되는 명령어)인 **Test-and-Set** (검사와 설정을 한 번에 수행)과 **CAS** (Compare-And-Swap, 기대값과 현재값이 일치할 때만 교체)로 플래그 검사와 변경을 일괄 처리 → 잠금 구현의 성능 기반 확보.
3. **뮤텍스** (Mutex, Mutual Exclusion Object) : 획득한 흐름만 반납할 수 있는 소유권형 잠금 → 단일 임계 구역 보호와 오반납 방지.
4. **세마포어** (Semaphore) : 정수 카운터로 가용 자원 수를 표현하고 **P·V 연산** (P는 감소·대기, V는 증가·신호의 원자적 연산 쌍)으로 제어 → 자원 풀 관리와 실행 순서 지정.
5. **모니터** (Monitor) : 공유 데이터와 프로시저를 한 객체로 묶고 동시 진입을 언어 차원에서 차단하는 구조 → **조건 변수** (Condition Variable, 조건 충족까지의 대기와 신호를 주고받는 장치)와 결합해 조건부 대기의 구조화와 실수 감소.
6. **스핀락** (Spinlock) : 잠금 획득까지 반복 검사하며 대기하는 방식 → 문맥 전환 비용 없이 극단적으로 짧은 구간의 대기 처리.

## Ⅲ. 프로세스 동기화 기법의 구조 (흐름)

- 핵심 요약 : 획득·실행·해제의 공통 골격 위에서 카운터(세마포어)와 캡슐화(모니터)로 차별화되는 구조.

```text
[ 동기화 도구의 추상화 수준 ]

Peterson 알고리즘 (소프트웨어 해법)
   ↓ 원자성 보장 필요
원자적 명령어 (Test-and-Set, CAS)
   ↓ 커널 동기화 객체
뮤텍스·세마포어
   ↓ 언어 수준 캡슐화
모니터 + 조건 변수
```

```text
[ 세마포어 P·V 연산 흐름 ]

P(S) : 카운터 S 감소
   ↓ S < 0이면 대기 큐 진입
임계 구역 또는 자원 사용
   ↓
V(S) : 카운터 S 증가
   ↓ 대기 흐름 한 개 재개
```

- 뮤텍스 구성요소 : 잠금 상태 플래그, 소유자 식별자, 대기 큐로 구성되며 획득(lock)과 해제(release) 연산으로만 상태 변화가 발생.
- 모니터 구성요소 : 공유 데이터, 진입 프로시저 집합, 조건 변수와 대기 큐로 구성되고 진입 상호 배제는 컴파일러와 런타임이 보장.

## Ⅳ. 뮤텍스·세마포어·모니터의 비교

- 핵심 요약 : 소유권 잠금(뮤텍스), 자원 수 신호(세마포어), 객체 캡슐화(모니터)의 상보적 구분.

| 비교 축 | 뮤텍스 | 세마포어 | 모니터 |
| --- | --- | --- | --- |
| 추상화 수준 | 운영체제 동기화 객체 | 운영체제 카운터 변수 | 프로그래밍 언어 구조 |
| 보호 단위 | 잠금 하나 | 자원 N개의 가용 수 | 객체 내부 상태 전체 |
| 소유권 | 획득한 흐름만 해제 | 없음 (신호 교환 자유) | 진입한 흐름이 반납 |
| 주요 연산 | lock, unlock | P(wait), V(signal) | 진입, wait, signal |
| 적합 용도 | 단일 임계 구역 보호 | 자원 풀 제어, 순서 동기화 | 조건부 대기가 있는 객체 |
| 실수 위험 | 낮음 | P·V 순서 어긋남에 취약 | 낮음 (런타임 보장) |

- 선택 기준 : 보호 대상이 단일 구간이면 뮤텍스, 가용 자원 수나 실행 순서 제어가 필요하면 세마포어, 상태와 조건 대기가 한 객체에 얽히면 모니터 우선.

## Ⅴ. 프로세스 동기화 기법의 한계와 방안

- 핵심 요약 : 우선순위 역전, 대기 낭비, 락 경합을 상속 프로토콜·블로킹 전환·잠금 분할로 일대일 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **우선순위 역전** (Priority Inversion) | 낮은 순위 흐름이 잠금을 쥔 채 선점되어 높은 순위 흐름이 지연 | **우선순위 상속** (Priority Inheritance, 잠금 보유자를 대기자 순위로 일시 승격) 또는 우선순위 상한 프로토콜 적용 | 락 대기 시간 |
| **바쁜 대기** (Busy Waiting) | 반복 검사 대기가 CPU를 점유 → 처리 능력 낭비 | 긴 대기는 블로킹 방식 세마포어로 전환, 스핀락은 극단적으로 짧은 구간에 한정 | 대기 CPU 점유율 |
| 락 경합 병목 | 하나의 잠금에 요청이 몰려 처리량이 대기 시간으로 제한 | 잠금 단위 분할과 CAS 기반 잠금 없는(Lock-free) 자료구조 도입 | 락 경합율, 처리량 |

## Ⅵ. 프로세스 동기화 기법에 대한 기술사적 제언

- 핵심 요약 : 저수준 잠금 직접 조작을 줄이고 언어 수준 추상화와 자동 검출 도구를 표준 체계로 내재화하는 방향.
- 개발 조직 : 원시 세마포어 조작 대신 언어 제공 모니터형 구조와 원자적 변수를 표준 코딩 규칙의 기본 선택지로 지정.
- 품질 조직 : 잠금 보유 범위 최소화를 코드 리뷰의 정식 항목으로 두고 레이스 검출기를 빌드 파이프라인에 상시 연동.
- 아키텍처 조직 : 잠금 획득 순서 규칙과 타임아웃 정책을 전사 설계 표준으로 문서화해 설계 단계부터 적용.

## Ⅶ. 결론

- 핵심 요약 : 뮤텍스·세마포어·모니터는 상호 배제를 서로 다른 추상화 수준에서 구현하는 상보적 도구 체계임.
- 보호 대상의 자원 수·소유권·조건 대기 요구 판별이 동기화 설계의 출발점.
