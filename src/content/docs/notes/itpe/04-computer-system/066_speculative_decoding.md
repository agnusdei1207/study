## 연관 키워드

- 추측 디코딩, Speculative Decoding, 드래프트 모델, 타깃 모델, 거부 샘플링
- 자기회귀 디코딩, 승인율, 보정 토큰, 자가 추측, 배치 포화, 무손실 가속

## Ⅰ. 추측 디코딩의 개요

- 핵심 요약 : 소형 모델의 다중 토큰 제안을 대형 모델이 한 번에 검증해 출력 분포를 보존하면서 생성 속도를 높이는 추론 가속 기법.
- 개념 : 소형 **드래프트 모델** (Draft Model, 후보 토큰을 미리 제안하는 보조 모델)의 제안을 대형 **타깃 모델** (Target Model, 최종 출력의 기준이 되는 원 모델)이 한 번의 순전파로 검증하는 **추측 디코딩** (Speculative Decoding) 방식.
- 배경 및 필요성 : 대형 언어 모델(LLM, Large Language Model)의 **자기회귀 디코딩** (Autoregressive Decoding, 토큰을 하나씩 순서대로 생성하는 방식)은 토큰당 모델 가중치 전체를 메모리에서 읽어야 하므로 고대역폭 메모리(HBM, High Bandwidth Memory) 대역폭에 병목이 걸리고 그래픽 처리 장치(GPU, Graphics Processing Unit)의 연산 유닛이 유휴 상태로 남음.
- 주요 목적 : 한 번의 순전파로 여러 토큰을 확정해 응답 지연을 줄이고, 출력 분포는 타깃 모델과 동일하게 유지하는 무손실 가속의 실현.

## Ⅱ. 추측 디코딩의 특징 및 장점

- 핵심 요약 : 제안, 병렬 검증, 확률적 채택의 결합이 무손실 가속이라는 장점으로 연결되는 구조.

1. 다중 토큰 제안 : 가중치가 작은 드래프트 모델이 K개 토큰을 연속 생성 → 타깃 모델의 순차 호출 횟수 감소.
2. 병렬 검증 : 인과적 어텐션 마스크(Causal Attention Mask)로 제안 위치 전체를 한 번의 순전파에서 평가 → 연산 병렬성 활용에 따른 토큰당 비용 절감.
3. 확률적 채택 : 타깃 분포 확률이 드래프트 분포 확률 이상이면 제안을 채택하고, 낮으면 확률 비율로 기각하는 **거부 샘플링** (Rejection Sampling) → 최종 출력 분포의 타깃 모델 일치 보장.
4. 기각 보상 : 첫 기각 지점에서 타깃 분포의 잔여 확률로 **보정 토큰** (Adjusted Token)을 다시 샘플링 → 기각이 있어도 주기마다 최소 한 개 토큰의 진행 보장.

## Ⅲ. 추측 디코딩의 구조 (흐름)

- 핵심 요약 : 드래프트 제안, 타깃 검증, 앞 위치부터의 채택·기각, 보정 토큰 확정의 주기 반복 구조.
- 구성 요소 : 후보를 만드는 드래프트 모델, 위치별 확률을 내는 타깃 모델, 채택 여부를 정하는 샘플링 검증기, 기각 지점을 메우는 보정 샘플러.

```text
[ 추측 디코딩 반복 주기 ]

현재 문맥 (프롬프트 + 확정 토큰)
        ↓
드래프트 모델 : K개 토큰 연속 제안
        ↓
타깃 모델 : K개 위치 확률 병렬 계산
        ↓
앞 위치부터 채택 여부 판정
        ↓
첫 기각 지점에서 보정 토큰 샘플링
        ↓
확정 토큰 병합 후 다음 주기 진행
```

```text
[ 검증 예시 (K = 3) ]

제안 : t1  t2  t3
        ↓
t1 채택 → t2 기각 (t3 폐기)
        ↓
t2 위치에서 보정 토큰 t2' 확정
        ↓
1회 순전파로 2개 토큰 진행
```

## Ⅳ. 드래프트 제안 방식의 비교

- 핵심 요약 : 드래프트의 출처에 따라 추가 메모리, 구현 난도, 승인율의 트레이드오프가 달라지는 구조.
- 선택 기준 : 여유 메모리 용량, 드래프트 모델 별도 학습 가능 여부, 목표 지연 수준을 기준으로 방식을 고른다.

| 구분 | 드래프트 출처 | 장점 | 트레이드오프 |
| :--- | :--- | :--- | :--- |
| 독립 드래프트 모델 | 동일 계열의 소형 별도 모델 | 구현이 직관적이고 범용 적용 가능 | 드래프트 가중치의 추가 메모리 상주 |
| **자가 추측** (Self-Speculative) | 타깃 모델의 일부 레이어 생략 | 추가 모델 로딩 불필요 | 중간 표현 품질에 따른 **승인율** (Acceptance Rate) 변동 |
| 멀티 헤드 방식 (Medusa) | 출력단의 다중 예측 헤드 | 단일 모델로 다중 후보 생성 | 헤드 학습용 파인튜닝 필요 |
| 특징 수준 예측 (EAGLE) | 히든 특징 위의 한 단계 예측 | 문맥 반영이 깊어 승인율 향상 | 검증 마스크 구성의 복잡도 증가 |

## Ⅴ. 추측 디코딩의 한계와 방안

- 핵심 요약 : 승인율 저하, 동시 요청 급증 시의 효율 역전, 메모리 부담을 다중 경로 검증, 동적 전환, 경량화로 일대일 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| 승인율 저하 | 코드 생성처럼 예측이 어려운 작업에서 드래프트가 빗나가 검증 비용만 증가 | 다중 후보를 트리 구조로 검증하는 확장 방식, 도메인 특화 드래프트 모델 교체 | 승인율, 완성 토큰당 소요 시간 |
| 동시 요청 급증 시 효율 역전 | 동시성 증가로 GPU가 연산 한계에 도달한 **배치 포화** (Batch Saturation) 상태에서는 검증용 추가 연산이 처리량 감소로 돌아옴 | 부하 수준에 따라 추측 디코딩과 표준 디코딩을 전환하는 운영 정책 | 처리량, 요청 대기 시간 |
| 드래프트 가중치의 메모리 부담 | 제한된 VRAM(Video Random-Access Memory)에 두 모델 상주로 배치 크기 축소 | 드래프트 모델의 저비트 양자화, 가중치를 공유하는 자가 추측 방식 채택 | 메모리 점유율, 배치 크기 |

## Ⅵ. 추측 디코딩에 대한 기술사적 제언

- 핵심 요약 : 추론 엔진 표준 기능화, 도메인 기반 드래프트 자산 관리, 모델 버전 거버넌스의 세 축으로 운영 체계 구축.

1. 표준 기능화 : LLM 서빙 플랫폼 운영 조직은 추론 엔진(vLLM, TensorRT-LLM)의 추측 디코딩 기능을 배포 표준 설정에 포함하고 워크로드별 활성화 기준의 설정 관리.
2. 드래프트 자산 선정 : 모델 개발 조직은 사내 도메인 데이터로 학습한 소형 모델과 범용 소형 모델의 승인율 비교 측정을 드래프트 모델 선정 절차의 기준으로 운영.
3. 버전 거버넌스 : 모델 자산 관리 조직은 드래프트·타깃 모델 쌍의 버전 호환성을 모델 레지스트리로 관리해 일방 교체에 따른 승인율 급락 예방.

## Ⅶ. 결론

- 핵심 요약 : 추측 디코딩은 소형 드래프트의 제안과 대형 타깃의 병렬 검증으로 무손실 추론 가속을 실현하는 기법.
- 가속 효과의 크기는 승인율과 배치 부하 조건이 결정하므로 워크로드 측정에 근거한 적용 판단이 필요.
