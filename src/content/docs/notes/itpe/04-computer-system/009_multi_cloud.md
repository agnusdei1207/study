## 연관 키워드
- 멀티클라우드, CSP, 이식성, 데이터 중력, 공급자 종속, 통합 거버넌스

## Ⅰ. 멀티클라우드의 개요
- 핵심 요약 : 멀티클라우드는 둘 이상의 클라우드 사업자를 목적에 맞게 함께 사용하는 전략.
- 개념 : **멀티클라우드**(Multi-Cloud)는 조직이 복수의 CSP(Cloud Service Provider)를 활용해 워크로드를 배치·운영하는 모델.
- 배경 및 필요성 : 사업자별 서비스·지역·규제·가용성 차이가 단일 제공자만으로 요구를 충족하기 어려운 상황.
- 주요 목적 : 선택권, 특화 서비스 활용, 공급자 집중 완화.

## Ⅱ. 특성 및 효과
- 핵심 요약 : 서비스별 최적 선택은 유연성을 높이지만 운영 체계와 데이터 위치를 분산.
- 워크로드별 배치 : 서비스 특성·규제에 맞는 제공자 선택 → 요구 적합성.
- 조달 선택권 : 가격과 조건 비교 → 협상력 가능성.
- 장애 대안 : 특정 영역의 대체 환경 확보 → 복구 선택지.
- 계정·정책·로그 모델 차이가 운영 복잡성으로 전환.

## Ⅲ. 관리 흐름
- 핵심 요약 : 공통 정책 아래 워크로드 위치와 데이터 이동, 운영 책임을 관리.
```text
요구·규제 분류
  ↓ 배치 기준·사업자 선택
CSP별 ID·네트워크·보안 정책
  ↓ 워크로드 실행·관측
통합 비용·복구 검증
```
```text
요구 분석 → 클라우드 배치
              ↓
데이터 반출료·지연 평가
              ↓
복구 훈련·책임 확인
```

## Ⅳ. 멀티클라우드와 하이브리드 비교
- 핵심 요약 : 멀티클라우드는 복수 CSP, 하이브리드는 공용 클라우드와 사설환경의 연결.
| 비교 축 | 멀티클라우드 | 하이브리드 |
| --- | --- | --- |
| 구성 | 2개 이상 CSP | 공용+사설 환경 |
| 동기 | 서비스 선택·집중 분산 | 기존 시스템 연계 |
| 과제 | 운영 정책 차이 | 연결·신원·데이터 통합 |

## Ⅴ. 한계와 방안
- 핵심 요약 : 데이터 이동비와 인력·도구 비용을 포함한 전체 비용 평가 필요.
| 한계 | 원인·영향 | 대응 |
| --- | --- | --- |
| 운영 복잡성 | API·로그·IAM 차이 | 공통 IaC·정책·관측 |
| 데이터 비용 | 반출료·지연·대역폭 | 데이터 중력 포함 TCO 분석 |
| 보안 편차 | 키·권한·감사 차이 | 공통 최소 통제·검증 |
| 복구 허상 | 타 환경에서 미검증 | 실제 복구 훈련 |

## Ⅵ. 도입 제언
- 핵심 요약 : CIO와 플랫폼팀은 다중 제공자의 명확한 사업 근거와 운영 역량을 먼저 확인.
- 고유 API 사용은 이식 비용과 복구 불가 위험을 승인하고, 공통 ID·정책·IaC는 표준화.

## Ⅶ. 결론
- 핵심 요약 : 멀티클라우드는 선택권을 주지만 자동으로 이식성과 복원력을 보장하지 않는 전략.
- 통합 거버넌스와 목적별 배치가 기대 효과의 전제.
