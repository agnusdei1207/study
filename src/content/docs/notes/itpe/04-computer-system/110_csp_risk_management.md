## 연관 키워드

- CSP 리스크 관리, 제3자 리스크 관리(TPRM, Third-Party Risk Management), 집중 위험(Concentration Risk)
- 벤더 락인(Vendor Lock-in), 전환 비용(Switching Cost), 출구 전략(Exit Strategy)
- DORA(Digital Operational Resilience Act), CLOUD Act, 데이터 주권, HYOK(Hold Your Own Key)
- SLA(Service Level Agreement), 감사권(Right to Audit), 보안 인증(ISO/IEC 27001, SOC 2), 멀티 클라우드, 비즈니스 연속성(BCP)

## Ⅰ. CSP 리스크 관리의 개요

- 핵심 요약 : 클라우드 서비스 제공자에 대한 의존에서 비롯되는 운영·기술·법적·재무 위험을 제3자 리스크 관리 방식으로 통제하는 거버넌스 활동.
- 개념 : **CSP** (Cloud Service Provider, 클라우드 서비스 제공자)의 장애, 보안 사고, 정책·단가 일방 변경, 서비스 종료 같은 제3자 의존 위험을 식별·평가·완화·감시하는 활동으로 제3자 리스크 관리인 **TPRM** (Third-Party Risk Management)의 클라우드 특화 영역.
- 배경 및 필요성 : 소수 대형 CSP로 업무가 집중되며 단일 CSP 장애가 산업 전반으로 번지는 집중 위험이 커지고, 유럽의 DORA(Digital Operational Resilience Act) 같은 디지털 운영 복원력 규제와 국외 데이터 법 집행 이슈가 동시에 대두.
- 주요 목적 : 공급망 종속의 가시화, **벤더 락인** (Vendor Lock-in) 전환 비용의 사전 산정, 비즈니스 연속성 계획(BCP, Business Continuity Plan)과 출구 가능성의 상시 확보.

## Ⅱ. CSP 리스크 관리의 특징 및 장점

- 핵심 요약 : 공급망 시야, 종속성 측정, 계약 통제, 규제 대응, 인증 평가의 다섯 축이 제3자 의존 위험을 관리 가능한 상태로 바꾸는 원리.

1. 공급망 시야 확보 : CSP 자체의 하위 공급자와 리전 인프라 의존까지 평가 → 상위 공급망 장애를 사전에 식별하는 효과.
2. 종속성 측정 : 독점 API 사용 비율, 데이터 형식 종속, 전환 시 재작업 범위를 산정 → 락인 상태를 정량 판단하는 효과.
3. 계약 통제 : SLA(Service Level Agreement), 감사권, 데이터 반환, 출구 조항을 계약서에 명시 → 사후 분쟁이 아닌 사전 통제가 가능해지는 효과.
4. 규제 대응 : DORA의 제3자 공급자 관리 요건, CLOUD Act(Clarifying Lawful Overseas Use of Data Act) 같은 국외 법 집행 시나리오를 평가 → 규제 충돌 위험을 사전에 줄이는 효과.
5. 보안·컴플라이언스 평가 : CSP 보안 인증(ISO/IEC 27001, SOC 2)과 규제 대응 계획을 선정·갱신 기준으로 평가 → 인증 만료와 감사 결과를 상시 추적하는 효과.

## Ⅲ. CSP 리스크 관리의 구조 (흐름)

- 핵심 요약 : 선정 평가에서 해지·출구까지 CSP 관계의 생애주기 전반을 순환 통제하는 구조.

```text
[ CSP 리스크 관리 생애주기 ]

선정 평가 : 보안·재무·규제 적합성
   ↓
계약 체결 : SLA·감사권·출구 조항
   ↓
운영 감시 : 인증 갱신·장애 이력
   ↓
해지·출구 : 데이터 반환과 이전 검증
```

```text
[ 집중 위험의 전파 경로 ]

다수 업무의 단일 CSP 편중
   ↓
CSP 핵심 기능 장애 발생
   ↓
의존 업무 전반의 동시 중단
   ↓
산업 연계까지 확대되는 영향
```

- 집중 위험(Concentration Risk)은 특정 CSP나 리전에 업무가 몰려 한 지점의 장애가 전체로 번지는 위험을 뜻함.
- 출구 전략(Exit Strategy)은 데이터 추출 절차, 이전 목표 시간, 병행 운영 기간을 계약 단계부터 문서화하는 활동을 말함.

## Ⅳ. CSP 리스크 대응 전략의 비교

- 핵심 요약 : 단일 CSP 심화, 하이브리드 분산, 멀티 클라우드는 종속 완화 효과와 운영 비용이 반비례하므로 위험 허용도 기준으로 선택.

| 비교 축 | 단일 CSP 심화 | 하이브리드 분산 | 멀티 클라우드 |
| :--- | :--- | :--- | :--- |
| 종속 수준 | 높음 | 중간 (핵심은 내부 통제) | 낮음 |
| 전환 비용 | 높음 (재구축 규모 큼) | 중간 | 낮음에서 중간 (이식성 유지) |
| 장애 대응력 | 리전 내 구성에 한정 | 내부 인프라로 연속성 확보 | 타 CSP로 우회 가능 |
| 규제 대응 | CSP 정책 의존 | 데이터 위치 직접 지정 | 지역 요건별 배치 |
| 운영 복잡도 | 낮음 | 높음 (연계 관리) | 매우 높음 (인력·도구 분산) |

- 선택 기준 :
  1. 규제 대상 데이터는 내부 통제 구간을 두는 하이브리드.
  2. 글로벌 장애 대비와 가격 협상력이 중요하면 멀티 클라우드.
  3. 운영 역량이 제한적이면 단일 CSP를 유지하되 출구 조건을 문서화.

## Ⅴ. CSP 리스크 관리의 한계와 방안

- 핵심 요약 : 보상 비대칭, 국외 법 집행, 전환 비용 과소 평가를 계약 보강, 키 관리, 전환 시뮬레이션으로 일대일 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| SLA 보상의 비대칭 | 배상이 이용료 크레딧 수준 → 매출 손실 미보전 | 맞춤 가용성 협약, 장애 입증 책임 명문화, 보험 병행 | 보상 대비 실손실 비율 |
| 국외 법 집행 위험 | 해외 사법 명령으로 데이터 제출 가능성 → 데이터 주권 침해 | **HYOK** (Hold Your Own Key) 등 고객 보유 키 암호화 | 고객 보유 키 적용 비율 |
| 전환 비용 과소 평가 | 데이터 송신 요금·재작업 누적 → 출구 실행 지연 | 표준 기술 스택 유지와 전환 비용 시뮬레이션 | 산출된 전환 비용 추이 |

## Ⅵ. CSP 리스크 관리에 대한 기술사적 제언

- 핵심 요약 : 감사와 출구 훈련을 제도화하고 이식 가능한 기술 스택을 기본값으로 삼는 거버넌스 방향.
- 제도 : 조달 주관 조직이 계약서에 감사권(Right to Audit)과 하위 공급자 공시 의무를 명시하고 이를 심사 항목으로 고정.
- 훈련 : 리스크 관리 조직이 CSP 전면 단절을 가정한 복구 훈련과 타 플랫폼 복원 시뮬레이션을 정기 수행.
- 아키텍처 : 개발 조직이 컨테이너 표준과 오픈소스 호환 데이터베이스를 기본값으로 채택해 이식성을 유지.

## Ⅶ. 결론

- 핵심 요약 : CSP 리스크 관리는 제3자 의존 위험을 계약과 아키텍처, 훈련으로 함께 통제하는 거버넌스 활동.
- 시사점 : 관리의 실효성은 출구 전략을 실제로 검증해 본 경험에서 나옴.
