## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 클라우드 거버넌스 → CSP 리스크 관리

## 30초 인출

- 본질: CSP 리스크 관리는 클라우드 제공자 의존에서 생기는 운영·보안·계약·출구 위험을 통제하는 활동
- 메커니즘: 선정→계약→운영→종료 단계마다 책임·연속성·반출 기준을 정하고 증거로 재평가
- 통찰: 한계: 선정 시점의 보증자료와 계약만으로 장애·종료 시 복구를 보장할 수 없음 → 방안: 중요 업무의 반출·복구를 주기적으로 실증한다.

<details>
<summary>핵심 용어</summary>

- **CSP (Cloud Service Provider)** : 클라우드 서비스를 제공·운영하는 사업자
- **CSP 리스크 관리(CSP Risk Management)** : 제공자·서비스 의존에서 생기는 위험을 식별·평가·대응하는 관리 활동
- **공동 책임 모델(Shared Responsibility Model)** : 제공자와 이용자가 보안·운영 통제를 분담하는 원칙
- **출구 전략(Exit Strategy)** : 서비스 종료·전환 시 데이터와 업무를 다른 환경으로 옮기는 계획
- **데이터 주권(Data Sovereignty)** : 데이터의 저장·처리가 관할권·법률과 맺는 관계

</details>

## 2~4교시 25점 답안

### Ⅰ. CSP 리스크 관리의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **CSP 리스크 관리는** 제공자·서비스 의존에서 생기는 위험을 식별·평가·대응하는 활동 |
| 목적 | 서비스 연속성·정보 보호·전환 가능성 확보 |

### Ⅱ. CSP 리스크의 특징

| 특징 | 관리상 의미 |
|---|---|
| 제3자 의존 | 장애·변경·지원 수준을 이용자가 단독 통제하기 어려움 |
| 공동 책임 | 제공자 보증과 이용자의 계정·구성 통제가 함께 필요 |
| 종료 시 집중 위험 | 데이터 반출량·형식·시간이 전환 가능성을 좌우 |

### Ⅲ. 리스크 관리 체계·프로세스

**핵심 수명주기**

```text
선정(적합성·보증) → 계약(책임·SLA·반출)
         → 운영(계정·장애·비용 감시) → 재평가
         → 갱신 또는 종료(반출·삭제·전환 확인)
                           └──── 위험 평가 갱신 → 선정·계약
```

**하위 메커니즘: 중요 업무의 종료·전환 검증**

```text
데이터·API 의존 목록화 → 반출 형식·권한 확인 → 시험 반출
        → 대체 환경에서 복구·업무 검증 → 소요 시간·손실량 측정
        → 계약의 지원·삭제 확인 조건 보완
```

### Ⅳ. 리스크 영역별 검증 비교

| 영역 | 핵심 위험 | 확인할 증거 |
|---|---|---|
| 연속성 | 장애·성능 저하 | 복구 시험 결과·장애 통지 기록 |
| 보안 | 권한 오용·구성 오류 | 책임 매트릭스·설정 점검·로그 |
| 계약·비용 | 서비스 변경·요금 급증 | 변경 통지·사용량·요금 명세 |
| 데이터·출구 | 관할권 요구·반출 지연 | 위치·보존 조건과 시험 반출 결과 |

### Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| SLA 보상만으로 업무 중단 손실을 회복하기 어려움 | 자체 복구목표·대체 경로를 설계하고 복구 시험 |
| 제공자 인증이 이용자 설정의 안전을 보장하지 않음 | 계정·워크로드·데이터 통제를 별도로 점검 |
| 계약상 출구 조항만으로 전환 시간이 확정되지 않음 | 실제 반출·복원으로 형식·시간·비용을 측정 |

### Ⅵ. 제언

제공자 보증과 SLA는 실제 업무 복구 시간을 대신 증명하지 못한다. **업무 중요도 순으로 종료·전환 시험을 먼저 실시**하고, 측정된 반출 시간과 데이터 손실을 근거로 계약 조건과 대체 경로를 갱신해야 한다.
