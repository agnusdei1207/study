## 30초 인출

- 본질: 다양한 제조사의 이종 모바일 칩셋 위에서 애플리케이션을 안전하고 독립적으로 실행하기 위해 리눅스 커널 위에 하드웨어 추상화 계층(HAL)과 AOT/JIT 혼합 런타임(ART), 바인더 IPC를 모듈형으로 적층한 오픈소스 모바일 운영체제
- 메커니즘: 다양한 제조사의 이종 모바일 칩셋 위에서 애플리케이션을 안전하고 독립적으로 실행하기 위해 리눅스 커널 위에 하드웨어 추상화 계층(HAL)과 AOT/JIT 혼합 런타임(ART), 바인더 IPC를 모듈형으로 적층한 오픈소스 모바일 운영체제

## 핵심 용어

- Zygote: 시스템 부팅 시 공통 시스템 라이브러리와 프레임워크 클래스를 미리 메모리에 적재해 두고, 새 앱 기동 요청 시 `fork()`하여 메모리를 복사-공유(Copy-on-Write)하는 모체 프로세스
- 바인더(Binder) IPC: 리눅스 커널 드라이버를 통해 단 한 번의 메모리 복사(`mmap`)로 프로세스 간 대용량 데이터를 고속 전송하고 호출자의 UID/PID를 검증하는 안드로이드 핵심 통신 기제
- HAL(Hardware Abstraction Layer): 디바이스 드라이버를 사용자 공간(User Space)의 표준 라이브러리로 분리하여 하드웨어 제조사가 커널(GPL) 소스 코드를 공개하지 않고도 자체 IP를 보호할 수 있게 만든 계층

### Ⅱ. 핵심 특성

- 안드로이드의 보안 격리는 OS 수준의 'UID 기반 리눅스 샌드박스'임 → 가상머신 수준의 격리에 의존하지 않고, 앱마다 고유한 리눅스 사용자 ID(UID)를 부여하여 다른 앱의 파일 디렉터리와 메모리에 시스템 레벨에서 원천적으로 접근하지 못하게 차단함
- 런타임 컴파일의 진화(Dalvik JIT → ART AOT → 하이브리드) → 과거 Dalvik은 실행 시마다 JIT로 컴파일하여 버벅거렸고, 초기 ART는 앱 설치 시 100% AOT로 컴파일하여 설치 시간과 저장 공간이 폭증했음. 현행 안드로이드는 평상시 JIT로 구동하면서 자주 쓰이는 코드만 프로파일링하여 기기가 유휴 충전 중일 때 AOT로 백그라운드 최적화하는 절충안 달성
- 바인더(Binder) IPC의 한계 용량 1MB → 앱 간 데이터 전달(Intent) 시 메모리를 공유하지 못하고 바인더 버퍼를 거치므로, 고해상도 비트맵이나 대형 리스트를 Bundle에 넣어 넘기면 `TransactionTooLargeException`이 발생하며 앱이 강제 종료됨

### Ⅲ. 관련 개념과 구분

- 표준 JVM vs 안드로이드 ART: 표준 JVM = 스택 기반(Stack-based) 구조로 바이트코드 명령어 수가 많음 / ART = 레지스터 기반(Register-based) DEX 코드를 실행하여 명령어 수를 줄이고 모바일 CPU 레지스터를 직접 활용하여 전력 소모를 절감
