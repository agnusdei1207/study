## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 클라우드 컴퓨팅 → 클라우드 서비스 모델

## 30초 인출

- 본질: 클라우드 서비스 모델은 서비스 제공자와 이용자 사이의 관리 책임 범위를 구분
- 메커니즘: IaaS→PaaS→SaaS로 갈수록 제공자의 관리 계층이 넓어지고 이용자의 운영 범위가 줄어듦
- 통찰: 한계: 모델 명칭만으로 실제 보안 책임을 확정할 수 없음 → 방안: 서비스별 계약·설정 범위를 책임 매트릭스로 검증한다.

<details>
<summary>핵심 용어</summary>

- **클라우드 서비스 모델(Cloud Service Model)** : 제공자와 이용자 사이의 자원·관리 책임을 구분하는 클라우드 제공 방식
- **IaaS (Infrastructure as a Service)** : 가상 컴퓨팅·저장·네트워크 기반을 제공하는 서비스 모델
- **PaaS (Platform as a Service)** : 응용 프로그램 개발·실행 플랫폼을 제공하는 서비스 모델
- **SaaS (Software as a Service)** : 이용자가 응용 프로그램을 서비스로 사용하는 모델
- **공동 책임 모델(Shared Responsibility Model)** : 보안·운영 책임을 제공자와 이용자 사이에 나누는 원칙

</details>

## 2~4교시 25점 답안

### Ⅰ. 클라우드 서비스 모델의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **클라우드 서비스 모델은** 제공자와 이용자 사이의 자원·관리 책임을 구분하는 제공 방식 |
| 목적 | 필요한 기술 계층을 서비스로 이용하고 책임 범위를 명확히 함 |

### Ⅱ. 서비스 모델의 특징

| 특징 | 의미 |
|---|---|
| 관리 범위의 단계성 | 인프라만 제공하는 IaaS부터 응용까지 제공하는 SaaS로 확장 |
| 통제권과 운영 부담의 교환 | 이용자 제어 범위가 넓을수록 직접 패치·운영 책임도 커짐 |
| 서비스별 책임 차이 | 같은 모델이라도 계약·구성 기능에 따라 실제 통제 경계가 달라짐 |

### Ⅲ. 제공·책임 체계와 선택 프로세스

**핵심 책임 계층**

```text
계층:          인프라 │ OS·런타임 │ 응용 │ 데이터·계정
IaaS 관리:     제공자 │     이용자      │ 이용자 │ 이용자
PaaS 관리:     제공자 │     제공자      │ 이용자 │ 이용자
SaaS 관리:     제공자 │     제공자      │ 제공자 │ 이용자
                   ↑ 서비스 계약·구성별 책임 경계 확인
```

**하위 메커니즘: 모델 선정과 책임 검증**

```text
업무·규제 요구 → 직접 제어할 계층 결정 → 운영 역량·비용 비교
              → 모델 선택 → 계약·설정별 책임 매트릭스 확정
              → 계정·데이터 통제 시험 → 운영 중 재검토
```

### Ⅳ. 모델별 적합성 비교

| 모델 | 적합한 요구 | 주의할 종속성 |
|---|---|---|
| IaaS | OS·네트워크 구성의 세밀한 제어 | 운영 인력과 패치 부담 |
| PaaS | 응용 개발·배포에 집중 | 런타임·API 이식성 |
| SaaS | 표준 업무 기능을 빠르게 이용 | 데이터 반출·설정 기능 제한 |

### Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 모델 이름만으로 책임 경계가 확정되지 않음 | 계약·서비스 설정을 근거로 통제 항목별 담당자를 지정 |
| 상위 모델에서도 계정·데이터 위험이 남음 | 이용자 영역의 권한·암호화·백업 통제를 시험 |
| 플랫폼 API·데이터 형식에 종속될 수 있음 | 이전 경로와 데이터 반출 절차를 도입 전에 검증 |

### Ⅵ. 제언

상위 서비스 모델의 운영 편의만 기준으로 선택하면 책임 공백과 데이터 종속을 뒤늦게 발견한다. **업무별 필수 제어 계층을 먼저 정하고**, 모델 선택 시 책임 매트릭스와 데이터 반출 시험을 계약·설계의 승인 조건으로 삼아야 한다.
