## 연관 키워드

- 클라우드 컴퓨팅 서비스 모델, IaaS(Infrastructure as a Service), PaaS(Platform as a Service), SaaS(Software as a Service)
- 공유 책임 모델(Shared Responsibility Model), 관리 책임 분계점, 책임 분담표
- SLA(Service Level Agreement), 서비스 크레딧(Service Credit), 가용률
- NIST SP 800-145, 컴플라이언스 상속, 데이터 반환, 감사권(Right to Audit)

## Ⅰ. 클라우드 컴퓨팅 서비스 모델의 개요

- 핵심 요약 : 고객과 클라우드 서비스 제공자 사이의 관리 책임 위임 수준에 따라 인프라·플랫폼·소프트웨어 형태로 구분되는 제공 모델 체계.
- 개념 : 미국 국립표준기술연구원(NIST, National Institute of Standards and Technology)의 **SP 800-145**가 정의한 분류로, **IaaS** (Infrastructure as a Service), **PaaS** (Platform as a Service), **SaaS** (Software as a Service)의 세 모델이 관리 대상 계층을 달리하는 제공 방식.
- 배경 및 필요성 : 서버부터 애플리케이션까지 전 계층을 자체 운영하던 구조에서 핵심 업무 집중을 위해 관리를 위임하면서, 어디까지 위임하고 어디를 남길지의 경계 정의가 핵심 쟁점으로 등장.
- 주요 목적 : 책임 공백과 중복의 제거, 위임 수준에 맞는 계약과 보증 체계 수립, 비핵심 운영 부담의 이양.

## Ⅱ. 클라우드 컴퓨팅 서비스 모델의 특징 및 장점

- 핵심 요약 : 모델이 상위로 갈수록 CSP 관리 범위가 넓어지고 고객 책임이 줄어드는 비례 구조가 운영 부담 경감으로 이어지는 원리.

1. 계층별 위임 구조 : IaaS는 하드웨어·가상화를 CSP가 담당하고 OS 이상은 고객이 담당 → 제어 자유도를 유지하며 물리 관리 부담만 제거하는 효과.
2. 상위 모델로의 위임 확대 : PaaS는 런타임·미들웨어까지, SaaS는 애플리케이션까지 CSP가 관리 → 고객이 코드·데이터·설정에만 집중하는 효과.
3. **공유 책임 모델** (Shared Responsibility Model) : 보안을 클라우드 자체의 보안과 클라우드 안의 보안으로 구분 → 보안 통제의 누락 지점을 사전에 드러내는 효과.
4. **SLA** (Service Level Agreement) 계약화 : 가용률과 장애 보고, 보상 절차를 문서로 보증 → 서비스 수준의 객관적 판정 근거 확보 효과.
5. **컴플라이언스 상속** : CSP가 취득한 보안 인증의 통제 항목 일부를 고객 통제 범위로 인정받는 구조 → 인증 심사의 중복 부담을 줄이는 효과.

## Ⅲ. 클라우드 컴퓨팅 서비스 모델의 구조 (흐름)

- 핵심 요약 : 온프레미스에서 SaaS로 갈수록 CSP 관리 계층이 위로 확대되고, 계약은 수준 정의부터 보상·검토 주기로 순환되는 구조.

```text
[ 모델별 관리 책임 위임 ]

온프레미스 : 전 계층 고객 관리
   ↓
IaaS : 하드웨어·가상화만 CSP 관리
   ↓
PaaS : 런타임·미들웨어까지 CSP 관리
   ↓
SaaS : 애플리케이션까지 CSP 관리
```

```text
[ SLA 관리 주기 ]

요구 수준 정의와 계약 명시
   ↓
가용률·장애 시간 측정
   ↓
미달 시 서비스 크레딧 보상
   ↓
정기 검토로 수준 재조정
```

- **서비스 크레딧** (Service Credit) : SLA 미달 시 이용료 일부를 차감·환급하는 형태의 계약상 보상 수단.
- 관리 책임 분계점은 모델마다 다르므로 계약서에 책임 분담표를 부속서로 붙여 각 통제 항목의 담당 주체를 고정하는 관행이 표준으로 통용됨.

## Ⅳ. 서비스 모델별 책임 분담의 비교

- 핵심 요약 : 계층이 올라갈수록 고객 책임이 줄고 CSP 책임이 넓어지며, 데이터와 접근 통제는 모든 모델에서 고객 책임으로 남음.

| 통제 항목 (계층) | IaaS | PaaS | SaaS |
| :--- | :--- | :--- | :--- |
| 데이터와 접근 권한 | 고객 | 고객 | 고객 |
| 애플리케이션 설정·계정 | 고객 | 고객 | 고객 |
| 런타임·미들웨어 | 고객 | CSP | CSP |
| OS 패치·취약점 관리 | 고객 | CSP | CSP |
| 가상화 계층 | CSP | CSP | CSP |
| 물리 서버·스토리지·네트워크 | CSP | CSP | CSP |

- 선택 기준 :
  1. OS 수준 제어와 커스터마이징이 필요하면 IaaS.
  2. 개발 생산성이 우선이면 PaaS.
  3. 표준 업무 기능이면 SaaS로 위임.
  4. 어느 모델이든 데이터 분류와 접근 통제는 고객이 유지.

## Ⅴ. 클라우드 컴퓨팅 서비스 모델의 한계와 방안

- 핵심 요약 : 보상 비대칭, 책임 공백, 데이터 반환 절차 미비를 맞춤 협약, 책임 경계 문서 확정, 계약 조항 명시로 일대일 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| SLA 보상의 비대칭 | 배상이 서비스 크레딧 수준 → 실손실 미보전 | 맞춤형 가용성 협약과 사이버 보험 병행 | 보상 대비 실손실 비율 |
| 책임 공백 지대 | 경계 오해로 패치·설정 통제 누락 → 침해 경로 생성 | 모델별 책임 분담표를 계약 부속서로 확정·연간 점검 | 미할당 통제 항목 수 |
| 데이터 반환 절차 미비 | 해지 시 인도 형식·기한 미정 → 시스템 이전 지연 | 계약서에 반환 형식·기한·보조 포맷 명시 | 데이터 반환 소요 시간 |

## Ⅵ. 클라우드 컴퓨팅 서비스 모델에 대한 기술사적 제언

- 핵심 요약 : 모델 선택을 조달 표준과 인력 역량 체계에 연동해 계약 이후 운영까지 책임이 이어지게 하는 방향.
- 조달 : 구매·조달 조직이 표준 계약 템플릿에 SLA 측정 방법과 감사권(Right to Audit) 조항을 필수 항목으로 고정.
- 보안 : 보안 조직이 CSP 보안 인증(ISO/IEC 27001 등) 심사를 선정 절차에 포함해 컴플라이언스 상속 범위를 사전 확인.
- 운영 : 인프라 운영 조직이 모델별 남는 고객 책임(OS 패치, 계정 관리 등)을 역량 체계와 담당 매핑 문서에 명시.

## Ⅶ. 결론

- 핵심 요약 : 서비스 모델 선택은 기술 선택이 아니라 관리 책임의 위임 수준을 정하는 계약 행위.
- 시사점 : 책임 분담표와 SLA 문서가 실질적 안전판이므로 도입 전에 보안·운영 조직이 함께 경계를 승인해야 함.
