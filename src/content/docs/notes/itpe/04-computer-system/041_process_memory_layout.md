## 연관 키워드

- 프로세스 메모리 구조, 가상 주소 공간, 텍스트 세그먼트, 데이터 세그먼트, BSS, 힙(Heap), 스택(Stack)
- 스택 프레임, 성장 방향, 가드 페이지, 버퍼 오버플로우, 스택 카나리, ASLR

## Ⅰ. 프로세스 메모리 영역의 개요

- 핵심 요약 : 가상 주소 공간을 역할별 세그먼트로 분할 배치하여 코드 보호, 동적 확장, 오류 격리를 동시에 확보하는 배치 체계.
- 개념 : 운영체제가 프로세스마다 독립적으로 부여하는 **가상 주소 공간** (Virtual Address Space, 프로세스별 독립 주소 범위)을 명령어·데이터·동적 할당·함수 호출 영역으로 분할 배치한 구조이며, 이를 **프로세스 메모리 구조** (Process Memory Layout)라 부름. 실행 파일 형식인 **ELF** (Executable and Linkable Format)의 세그먼트 정보를 로더가 따라 적재하면서 배치가 완성됨.
- 배경 및 필요성 : 명령어와 데이터가 한 공간에 섞이면 코드 변조와 이웃 영역 침범이 쉬워지고, 실행 전에 크기를 알 수 없는 데이터를 고정 배치로는 수용할 수 없어 영역별 권한과 성장 방향의 분리가 필요해짐.
- 주요 목적 : 영역별 접근 권한 분리에 따른 코드 보호, 실행 중 크기가 변하는 데이터의 수용, 영역 간 침범 오류의 조기 격리.

## Ⅱ. 프로세스 메모리 영역의 특징 및 장점

- 핵심 요약 : 다섯 세그먼트가 저장 대상과 수명, 성장 방향, 권한을 달리하는 설계가 보호와 확장, 격리 효과로 이어지는 구조.

1. **텍스트 세그먼트** (Text Segment, 코드 영역) : 기계어 명령어를 읽기·실행 전용으로 적재 → 코드 변조 차단과 다수 프로세스 간 코드 공유의 효과.
2. **데이터 세그먼트** (Data Segment) : 초기값이 명시된 전역·static 변수를 적재 시 기록 → 프로그램 시작 전 초기 상태 보장.
3. **BSS 세그먼트** (Block Started by Symbol) : 초기값 없는 전역·static 변수를 배치하고 로더가 0으로 초기화 → 값 기록 생략에 따른 실행 파일 크기 절감.
4. **힙** (Heap) : `malloc()`·`new` 등 런타임 요청에 따라 하위 주소에서 상위 주소로 성장 → 실행 중에야 크기가 정해지는 자료구조 수용.
5. **스택** (Stack) : 함수 호출마다 **스택 프레임** (Stack Frame, 지역 변수와 복귀 주소의 호출 단위)을 쌓고 상위 주소에서 하위 주소로 성장 → 후입선출 기반의 신속한 호출·반환 처리.

## Ⅲ. 프로세스 메모리 영역의 구조 (흐름)

- 핵심 요약 : 하위 주소의 고정 영역에서 상위 주소의 커널 영역까지, 힙과 스택이 빈 공간을 사이에 두고 마주 보고 자라는 레이아웃.
- 구성요소 : 고정 크기 영역(텍스트, 데이터, BSS)은 적재 시점에 크기가 확정되고, 가변 크기 영역(힙, 스택)은 실행 중 성장하며 남은 빈 영역을 나눠 사용함.

```text
[ 가상 주소 공간 배치 (하위 → 상위 주소) ]

텍스트 세그먼트 (기계어)
   ↓
데이터 세그먼트 (초기화된 전역 변수)
   ↓
BSS (초기값 없는 전역 변수)
   ↓
힙 (동적 할당, 상위로 성장)
   ↓
빈 영역 (가용 공간)
   ↓
스택 (하위로 성장)
   ↓
커널 공간 (사용자 모드 접근 차단)
```

```text
[ 가변 영역의 성장 방향 ]

힙      하위 주소 → 상위 방향 성장
스택    상위 주소 → 하위 방향 성장
   ↓
서로를 향한 성장의 수렴
   ↓
빈 영역 소진 시 충돌 지점
```

- **가드 페이지** (Guard Page) : 스택 한계 지점에 두는 접근 차단 페이지로, 경계를 넘는 접근을 페이지 폴트로 감지하여 스택 확장 또는 오류 처리로 연결하는 장치.

## Ⅳ. 프로세스 메모리 영역의 비교

- 핵심 요약 : 세그먼트마다 할당 시점, 해제 시점, 권한, 저장 데이터가 달라 데이터 수명에 따른 배치 판단이 필요함.

| 세그먼트 | 할당 시점 | 해제 시점 | 접근 권한 | 저장 데이터 |
| --- | --- | --- | --- | --- |
| 텍스트 | 적재 시 | 프로세스 종료 시 | 읽기·실행 | 기계어, 리터럴 상수 |
| 데이터 | 적재 시 | 프로세스 종료 시 | 읽기·쓰기 | 초기화된 전역·static 변수 |
| BSS | 적재 시 | 프로세스 종료 시 | 읽기·쓰기 | 초기값 없는 전역·static 변수 |
| 힙 | 런타임 할당 요청 | 해제 함수 또는 GC(Garbage Collection) | 읽기·쓰기 | 동적 객체, 런타임 버퍼 |
| 스택 | 함수 호출 시 | 함수 반환 시 | 읽기·쓰기 | 지역 변수, 매개변수, 복귀 주소 |

- 선택 기준 : 수명이 프로세스 전체인 데이터는 데이터·BSS 세그먼트에, 함수 단위 수명인 데이터는 스택에, 실행 중 크기가 정해지는 데이터는 힙에 배치하는 기준으로 구분함.

## Ⅴ. 프로세스 메모리 영역의 한계와 방안

- 핵심 요약 : 버퍼 오버플로우, 가변 영역 충돌, 메모리 누수를 컴파일러 보호 기법, 가드 페이지, 정적·동적 분석으로 일대일 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **버퍼 오버플로우** (Buffer Overflow, 입력이 할당 경계를 넘어 인접 영역을 덮어쓰는 취약점) | 스택의 복귀 주소 변조 → 임의 코드 실행 | **스택 카나리** (Stack Canary, 복귀 주소 앞 무작위 값의 검증), **DEP** (Data Execution Prevention)와 NX(No-eXecute) 비트로 스택 실행 차단, **ASLR** (Address Space Layout Randomization)로 주소 무작위화 | 보호 옵션 적용률, 침범 탐지 건수 |
| 가변 영역 성장 충돌 | 힙과 스택이 빈 영역을 모두 소진 → 할당 실패와 비정상 종료 | 가드 페이지 감시, 재귀 깊이와 할당 상한 설정 | 가용 빈 영역 크기, 할당 실패 건수 |
| 메모리 누수 | 해제 누락으로 힙 점유 누적 → 장기 운영 프로세스의 자원 고갈 | Sanitizer 계열 분석 도구로 빌드 단계에서 검증 | 힙 사용량 추이, 누수 탐지 건수 |

## Ⅵ. 프로세스 메모리 영역에 대한 기술사적 제언

- 핵심 요약 : 빌드 파이프라인, 보안 운영, 개발 조직의 세 주체가 메모리 보호를 설계와 운영 단계에 내재화하는 방향.

1. 빌드 파이프라인 운영 조직 : 컴파일러의 스택 보호 옵션과 링커의 재배치 보호 옵션을 전사 빌드 기본값으로 고정하여 소스별 누락을 구조적으로 차단하는 제도가 필요함.
2. 보안 운영 조직 : 서버 기준선 점검 항목에 주소 무작위화 활성 여부를 포함하고 점검 결과를 정기 보고하는 체계가 바람직함.
3. 개발 조직 : 보안 민감 모듈의 메모리 안전 언어 적용 범위를 기술 로드맵에 두어 언어 수준의 예방력을 확보하는 방안이 유효함.

## Ⅶ. 결론

- 핵심 요약 : 프로세스 메모리 영역은 세그먼트 분할로 보호·확장·격리를 함께 실현하는 실행 환경의 기반 설계.
- 세그먼트 배치의 이해는 메모리 관련 결함의 원인 규명과 보호 기법 선정의 출발점임.
