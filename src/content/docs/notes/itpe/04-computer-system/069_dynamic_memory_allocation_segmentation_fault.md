## 한 줄 본질
- 컴파일 시점에 크기를 알 수 없는 데이터를 처리하기 위해 런타임에 힙 영역을 동적으로 할당받아 쓰지만, 할당 범위를 벗어나거나 해제된 주소를 역참조하면 MMU가 하드웨어 트랩을 발생시켜 프로세스를 강제 종료(SIGSEGV)함 → 유연한 메모리 활용 / 메모리 오염 방지를 위한 엄격한 OS 보호 메커니즘

## 핵심 그림
```text
[ 동적 메모리 할당 및 세그멘테이션 폴트 발생 시퀀스 ]

[ 애플리케이션 (User Space) ]
  1. ptr = malloc(100);  ───> [ 힙 관리자: ptmalloc / jemalloc ]
                                     │ (가용 청크 분할 반환)
  2. ptr[105] = 'A'; (경계 초과 쓰기!) ┘
  3. ptr[99999] = 'Z'; (할당되지 않은 VMA 접근 시도!)
        │
        v (CPU가 논리 주소 참조)
  +─────────────────────────────────────────────────────────────+
  | 하드웨어 MMU (Memory Management Unit)                       |
  |  - 페이지 테이블 조회: 해당 가상 주소에 매핑된 프레임 없음! |
  |  - VMA 권한 검사: 읽기 전용 구역 쓰기 또는 비인가 접근!     |
  +─────────────────────────────┬───────────────────────────────+
                                │ 4. 하드웨어 트랩 (Trap) 발생
                                v
  +─────────────────────────────────────────────────────────────+
  | OS 커널 (Kernel Space)                                      |
  |  - do_page_fault() 핸들러 실행                              |
  |  - 잘못된 주소 접근 판정 -> SIGSEGV 시그널 생성             |
  +─────────────────────────────┬───────────────────────────────+
                                │ 5. 프로세스에 SIGSEGV 전달
                                v
  [ 프로세스 비정상 종료: Segmentation Fault (Core Dumped) ]
```

## 핵심 용어
- brk / mmap: 소용량 힙 할당(128KB 미만)은 `brk`로 힙 끝을 늘려 재사용하고, 대용량 할당은 `mmap`으로 익명 메모리 페이지를 직접 매핑
- 허상 포인터(Dangling Pointer): `free()`로 메모리를 이미 해제했음에도 해당 메모리 주소를 그대로 가리키고 있는 무효 포인터
- 이중 해제(Double Free): 이미 반납된 동일한 메모리 주소에 대해 `free()`를 두 번 호출하여 힙 메타데이터를 오염시키는 치명적 취약점

## 핵심 통찰
- 세그멘테이션 폴트는 '버그가 아니라 축복'임 → 프로세스가 다른 프로세스의 영역이나 커널 메모리를 조용히 덮어쓰지 못하도록 MMU가 즉각 사형 선고를 내려 데이터 오염의 확산을 방지하는 하드웨어 방어선임
- 경계를 1바이트 넘는다고 바로 폴트가 나지 않음 → 힙 할당자는 메모리를 워드(8/16바이트) 단위로 정렬하고 페이지는 4KB 단위이므로, 경계를 조금 넘어가도 같은 유효 페이지 내부라면 폴트 없이 데이터만 조용히 깨지다가 훨씬 뒤에 알 수 없는 크래시를 유발함
- 현대 메모리 풀은 멀티스레드 락 경합을 회피함 → ptmalloc은 CPU 코어 수에 비례하여 아레나(Arena)를 분리하고, jemalloc/tcmalloc은 스레드 로컬 캐시를 두어 동적 할당 시 글로벌 뮤텍스 경합을 제거함

## 이웃 토픽과 구분
- 세그멘테이션 폴트 vs 버스 에러(Bus Error): 세그멘테이션 폴트 = MMU가 인식하지 못하거나 권한이 없는 가상 주소 접근(소프트웨어/논리적 오류) / 버스 에러 = 물리 메모리 정렬(Alignment) 위반이나 존재하지 않는 물리 주소 접근(하드웨어적 오류)

| 고성능 통신 서버가 불특정 시점에 Segmentation Fault로 크래시 | 다른 스레드가 이미 `free()`한 객체 포인터를 참조(Use-After-Free) | `std::shared_ptr` 및 `std::weak_ptr` 활용 객체 수명 관리 | 참조 카운트 기반 안전한 소멸 보장 |
