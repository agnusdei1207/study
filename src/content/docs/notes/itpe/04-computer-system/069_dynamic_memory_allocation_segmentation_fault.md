## 연관 키워드

- 동적 메모리 할당(Dynamic Memory Allocation), 힙(Heap), 세그멘테이션 오류(Segmentation Fault, SIGSEGV), MMU(Memory Management Unit)
- 프리 리스트(Free List), brk/sbrk, mmap, 페이지 폴트(Page Fault)
- 댕글링 포인터(Dangling Pointer), UAF(Use-After-Free), 이중 해제(Double Free), 힙 오버플로(Heap Overflow), 메모리 누수(Memory Leak)
- 단편화(Fragmentation), TLSF(Two-Level Segregated Fit), AddressSanitizer

## Ⅰ. 동적 메모리 할당과 세그멘테이션 오류의 개요

- 핵심 요약 : 런타임에 힙 메모리를 할당하고 해제하는 동적 할당과, 잘못된 메모리 접근을 차단하는 세그멘테이션 오류가 맞물린 메모리 관리 구조.
- 개념 : 프로그램 실행 중 힙 영역에 필요한 크기만큼 메모리를 할당하고 반환하는 **동적 메모리 할당** (Dynamic Memory Allocation)과, 유효하지 않은 주소 참조나 권한 위반이 발생할 때 운영체제가 프로세스를 종료시키는 **세그멘테이션 오류** (Segmentation Fault, SIGSEGV) 현상.
- 배경 및 필요성 : 크기를 컴파일 시점에 정할 수 없는 데이터를 다루려면 동적 할당이 필수이나, C·C++처럼 메모리를 직접 관리하는 언어에서는 해제 누락이나 잘못된 참조가 시스템 충돌과 보안 취약점으로 이어지는 비용이 생김.
- 주요 목적 : 힙 단편화 억제, 가상 메모리 접근 통제, 메모리 무결성 보장을 통한 시스템 안정성 확보.

## Ⅱ. 동적 메모리 할당과 세그멘테이션 오류의 특징 및 장점

- 핵심 요약 : 할당자의 블록 관리와 하드웨어의 접근 검사가 결합되어 메모리 낭비를 줄이고 잘못된 접근을 즉시 차단하는 구조.

1. **프리 리스트** (Free List) 기반 할당 : 작은 블록은 `brk()`·`sbrk()`로 힙 상단을 늘린 뒤 할당자가 해제된 블록을 목록으로 관리하며 재사용, 큰 블록은 `mmap()`으로 페이지 단위 익명 매핑을 직접 받음 → 반복 할당·해제 비용 절감과 큰 블록의 단편화 감소.
2. **페이지 폴트** (Page Fault) 기반 접근 검사 : MMU(Memory Management Unit)가 가상 주소를 물리 주소로 바꾸는 과정에서 매핑되지 않은 주소나 읽기·쓰기·실행 권한 위반을 발견 → 예외를 커널에 넘기고 프로세스를 즉시 중단 → 잘못된 접근이 다른 데이터를 오염시키기 전에 차단.

## Ⅲ. 동적 메모리 할당과 세그멘테이션 오류의 구조 (흐름)

- 핵심 요약 : 할당은 힙 확장과 블록 재사용으로 이루어지고, 잘못된 접근은 MMU 예외를 거쳐 SIGSEGV로 종료되는 두 갈래 흐름.

```text
[ 동적 할당 흐름 ]

malloc() 호출
   ↓
할당자가 프리 리스트 탐색
   ↓
맞는 블록이 있으면 분할 후 반환
   ↓
없으면 brk()·mmap()으로 힙 확장
```

```text
[ 세그멘테이션 오류 발생 흐름 ]

잘못된 주소 참조 (NULL, 해제 후 접근)
   ↓
MMU 주소 변환 실패 또는 권한 위반
   ↓
페이지 폴트 예외 → 커널 핸들러
   ↓
SIGSEGV(11) 전달 → 프로세스 종료
```

## Ⅳ. 동적 메모리 결함 유형의 비교

- 핵심 요약 : 댕글링 포인터, UAF, 이중 해제, 힙 오버플로, 메모리 누수는 원인과 영향이 다르므로 유형별 탐지 수단을 달리 두어야 하는 구도.

| 결함 유형 | 발생 원인 | 영향·취약점 | 감지·대응 |
| --- | --- | --- | --- |
| **댕글링 포인터** (Dangling Pointer) | 해제 후 포인터를 비우지 않고 재참조 | 데이터 오염, 예측하기 어려운 세그멘테이션 오류 | 해제 직후 포인터 초기화, 스마트 포인터 |
| **UAF** (Use-After-Free) | 해제된 블록에 새 객체가 할당된 뒤 옛 포인터로 접근 | 임의 코드 실행, 권한 상승 공격으로 이어질 수 있음 | AddressSanitizer, 해제 메모리 격리 |
| **이중 해제** (Double Free) | 이미 반환된 주소를 다시 `free()` 호출 | 힙 메타데이터 오염 | 해제 후 포인터 무효화, 안전 래퍼 함수 |
| **힙 오버플로** (Heap Overflow) | 할당 블록의 경계를 넘는 쓰기 | 인접 데이터·메타데이터 침범, 취약점 악용 | 경계 검사 함수 사용, 스택 카나리 보호 |
| **메모리 누수** (Memory Leak) | 할당 후 해제 누락으로 가용 메모리 고갈 | 장기 운영 시 시스템 성능 저하와 강제 종료 | Valgrind Memcheck, 정적 분석 도구 |

## Ⅴ. 동적 메모리 할당과 세그멘테이션 오류의 한계와 방안

- 핵심 요약 : 단편화, 할당 지연의 비결정성, 결함의 늦은 발현을 할당자 선택과 검사 도구 의무화로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 힙 단편화 | 크기가 다른 블록을 반복 할당·해제 → 총량은 남아 있어도 연속 공간 부족으로 할당 실패 | 크기 클래스별 슬랩 할당자, 스레드별 아레나를 쓰는 고성능 할당자(jemalloc, TCMalloc) | 단편화율, 할당 실패 건수 |
| 비결정적 할당 지연 | 빈 블록 탐색과 락 경합으로 최악 실행 시간(WCET, Worst-Case Execution Time) 예측 곤란 | 상수 시간 할당을 보장하는 TLSF(Two-Level Segregated Fit) 할당자, 정적 메모리 풀로 사전 할당 | WCET 측정치, 할당 지연 편차 |
| 결함의 늦은 발현 | 오염 발생 시점과 크래시 시점 사이의 시차로 근본 원인 추적 곤란 | CI 파이프라인에 AddressSanitizer 적용, 코어 덤프 자동 분석 | 결함 재현 소요 시간, 결함 발견 단계 |

## Ⅵ. 동적 메모리 할당과 세그멘테이션 오류에 대한 기술사적 제언

- 핵심 요약 : 메모리 안전 언어로의 점진적 전환과 다층 방어 체계를 함께 갖추면 메모리 결함에 따른 위험을 구조적으로 줄일 수 있음.
- 신규 시스템은 메모리 안전성을 언어 차원에서 보장하는 Rust 등을 우선 검토하고, 기존 C·C++ 자산은 결함 빈도가 높은 핵심 모듈부터 단계적으로 옮기는 전환 계획을 세우는 것이 현실적이다.
- 기존 C·C++ 코드에는 빌드 단계의 AddressSanitizer와 정적 분석을 의무화하고, 운영 환경에서는 주소 공간 배치 무작위화(ASLR, Address Space Layout Randomization)와 쓰기·실행 권한 분리(W^X, Write XOR Execute) 같은 보호 기능을 기본으로 켜 두는 다층 방어를 조직 표준으로 정하는 것이 좋다.
- 보안 조직은 메모리 결함을 취약점 등급과 함께 집계해 개발팀에 되돌려 주고, 이를 개발 절차의 품질 지표로 관리하여 재발을 줄이는 운영을 권한다.

## Ⅶ. 결론

- 핵심 요약 : 동적 메모리 할당은 런타임 유연성을 주는 대신 해제와 접근 오류의 위험을 안고, 세그멘테이션 오류는 그 오류를 빠르게 드러내는 보호 장치임.
- 시사점 : 메모리 안전성은 언어, 검사 도구, 운영 보호 기능을 겹쳐 확보해야 하는 과제이며, 세 층위가 함께 작동할 때 결함이 실제 사고로 이어지는 비율이 낮아짐.
