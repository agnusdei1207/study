## 답안 골격
```text
[SAN] ◀━━ 머리: Ⅶ 내 의견 (초고속 NVMe-oF 프로토콜 전환과 조닝/LUN 마스킹 표준화를 통한 미션 크리티컬 DB I/O 보장)
 ┃
 ┣━ Ⅰ 개요 ───── 일반 LAN 트래픽과의 경합 및 파일 레벨 지연 극복 → 광채널(FC) 기반 전용 고속 블록 스토리지 전송 네트워크
 ┣━ Ⅱ 특징 ───── 블록 레벨 I/O(Block-level) · 광채널(FC/FCoE) 초저지연 · 무손실(Lossless) 패브릭 · 고비용 엔터프라이즈급
 ┣━ Ⅲ 구조 ───── 호스트 서버(FC HBA) + SAN 광 스위치 패브릭 + 엔터프라이즈 스토리지 어레이 + 관리 콘솔
 ┣━ Ⅳ 흐름 ───── ① 호스트 OS SCSI/NVMe 블록 명령 생성 → ② FC 프레임 캡슐화 → ③ SAN 스위치 무손실 전송 → ④ 스토리지 LUN 기록
 ┣━ Ⅴ 비교 ───── FC-SAN vs IP-SAN(iSCSI) vs FCoE vs NAS
 ┗━ Ⅵ 실무 ───── 조닝(Zoning) 오류로 인한 비인가 접근 / LUN 마스킹 누락 / 광 트랜시버 및 HBA 고장 페일오버(Multipathing)
```
- 필수 키워드: SAN · 블록 레벨 I/O · 파이버 채널(FC) · 광 스위치 패브릭 · iSCSI · 조닝(Zoning) · LUN 마스킹 · 멀티패싱
- 기출: 122회 1교시 7번 `DAS, NAS, SAN 비교` 단답형 출제

## 한 줄 본질
- 일반 이더넷 LAN 망에서 스토리지를 전송하면 패킷 유실과 지연(Jitter)으로 핵심 DB 트랜잭션이 손상됨 → 파이버 채널(FC) 광 스위치 전용망을 구축하여 서버에 외장 디스크를 물리적 로컬 블록(Raw Disk)처럼 직결 제공 → 마이크로초 단위 초저지연 및 99.999% 무손실 전송 / 고가의 전용 하드웨어 및 운영 전문성 요구

## 핵심 그림
```text
[ 이중화된 이중 패브릭(Dual Fabric) 엔터프라이즈 SAN 아키텍처 ]

[ 호스트 서버 (DB / 가상화 클러스터) ]
  ├── HBA Port 1 ─────────────────────────┐
  └── HBA Port 2 ──────────────────┐      │
                                   │      │ (광 케이블 직결: 32G/64G FC)
                                   v      v
+──────────────────────────────────+  +──────────────────────────────────+
| SAN Fabric A (Primary 광 스위치) |  | SAN Fabric B (Secondary 광 스위치)|
|  - 하드웨어 포트 조닝 (Zoning)   |  |  - 하드웨어 포트 조닝 (Zoning)   |
|  - 무손실 크레딧 기반 흐름 제어  |  |  - 무손실 크레딧 기반 흐름 제어  |
+─────────────────┬────────────────+  +─────────────────┬────────────────+
                  │                                     │
                  v                                     v
+────────────────────────────────────────────────────────────────────────+
| 엔터프라이즈 스토리지 어레이 (Dual Controller)                        |
|  - LUN 0 (OS 부팅 볼륨) / LUN 1 (Oracle Datafile) / LUN 2 (로그)       |
|  - LUN 마스킹 (인가된 서버의 WWN만 볼륨 접근 허용)                     |
+────────────────────────────────────────────────────────────────────────+
```

## 핵심 용어
- LUN(Logical Unit Number): 스토리지 어레이 내부의 RAID 디스크 볼륨을 논리적으로 분할하여 호스트 서버에 개별 드라이브로 인식시키는 번호
- 조닝(Zoning): SAN 스위치 내부에서 특정 HBA 포트와 특정 스토리지 포트만 통신할 수 있도록 논리적인 가상 경로를 격리하는 패브릭 보안 기술
- LUN 마스킹(LUN Masking): 스토리지 컨트롤러 레벨에서 특정 서버의 고유 하드웨어 주소(WWN: World Wide Name)에만 지정된 LUN을 보여주고 나머지는 숨기는 접근 제어
- MPIO(Multipath I/O): 서버와 스토리지 간의 복수 광케이블 경로 중 하나가 단절되어도 무중단으로 다른 경로로 우회하고 부하를 분산하는 다중 경로 소프트웨어

## 핵심 통찰
- 호스트 OS는 SAN을 '외장 하드가 아니라 로컬 하드'로 인식함 → NAS는 네트워크 공유 폴더라고 알지만, SAN은 메인보드에 꽂힌 C드라이브, D드라이브(Raw Device)로 완전히 속아 넘어가므로 고성능 데이터베이스 파일 시스템 포맷이 가능함
- 파이버 채널의 핵심은 '버퍼 크레딧 기반의 무손실(Lossless)'임 → TCP/IP처럼 패킷을 일단 던지고 넘치면 버리는 게 아니라, 수신 측 스위치에 빈 버퍼가 있을 때만 신호를 보내므로 패킷 재전송 지연이 0%임
- 단일 패브릭 구성은 재앙임 → 광 스위치 펌웨어 업데이트나 광 케이블 단선에 대비해 스위치와 HBA 카드를 완전히 독립된 A망/B망(Dual Fabric)으로 이중화하는 것이 엔터프라이즈 표준임

## 이웃 토픽과 구분
- SAN vs NAS: SAN = 블록 레벨(Block-level), 전용 광케이블/iSCSI, 호스트가 파일 시스템 포맷 직접 수행, DB용 / NAS = 파일 레벨(File-level), 표준 LAN(NFS/SMB), 스토리지가 파일 시스템 관리, 일반 파일 공유용

## 문제·원인·대책
- 사례: 122회 기출 및 핵심 금융 결제 DB에서 SAN 스위치 포트 플래핑으로 인한 볼륨 I/O 행(Hang) 장애
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 광 케이블 노후화로 신호 감쇄 발생 시 전체 SAN 패브릭 성능 저하(Slow Drain) | 불량 포트의 크레딧 반환 지연으로 스위치 버퍼가 가득 차 전체 패브릭으로 정체 전파 | FEC(Forward Error Correction) 활성화 및 Slow Drain 자동 격리(Port Fencing) | 불량 포트 즉각 차단으로 정상 포트 무손실 통신 보호 |
| 신규 서버 증설 시 기존 운영 DB의 LUN 볼륨이 임의 마운트되어 데이터 덮어쓰기 | SAN 스위치 조닝 및 스토리지 LUN 마스킹 미적용(Default Zone 개방) | WWN 기반의 단일 개시자 조닝(Single Initiator Zoning) 강제 적용 | 서버 간 스토리지 접근 완벽 격리 |

## 이렇게 출제된다
- 제122회 1교시 7번: "DAS(Direct Attached Storage), NAS(Network Attached Storage), SAN(Storage Area Network)" → 요구 포인트: Ⅰ SAN의 개념 및 블록 레벨 초저지연 특성 + Ⅲ 이중 패브릭(Dual Fabric) 구성도 + Ⅴ DAS/NAS 대비 성능 및 확장성 비교

## 내 의견
- [레거시 FC-SAN의 NVMe-oF(RoCEv2) 전환을 통한 클라우드 엔터프라이즈 스토리지 혁신] 고가의 독점적인 32G/64G 파이버 채널 하드웨어는 클라우드 네이티브 환경에서 비용과 민첩성의 한계에 부딪힘 → 나라면: 미션 크리티컬 코어 트랜잭션 DB는 초고속 무손실 RoCEv2(RDMA over Converged Ethernet) 기반의 NVMe-oF IP-SAN 아키텍처로 전환하여, 표준 100GbE 이더넷 스위치 위에서 기존 파이버 채널보다 3배 이상 빠르고 비용은 절반 이하인 차세대 고성능 블록 스토리지 패브릭 구축
