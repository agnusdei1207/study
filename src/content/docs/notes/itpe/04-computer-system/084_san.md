## 연관 키워드

- SAN(Storage Area Network), FC-SAN, IP-SAN, iSCSI, NVMe-oF
- FC(Fibre Channel), B2B 크레딧, 조닝(Zoning), LUN 매스킹(LUN Masking), WWPN
- 이중 패브릭, Slow Drain, FPIN, 클러스터 파일시스템

## Ⅰ. SAN(Storage Area Network)의 개요

- 핵심 요약 : **SAN** (Storage Area Network)은 서버와 스토리지를 잇는 전용 고속 블록 I/O 네트워크로, 무손실 전송과 LUN 공유, HA/DR 기반을 제공하는 구조.
- 개념 : 다수의 서버와 고성능 스토리지 시스템이 대용량 블록 데이터를 고속으로 주고받기 위해, 범용 LAN(Local Area Network)과 물리적·논리적으로 분리하여 구축한 스토리지 전용 전송 네트워크.
- 배경 및 필요성 : 업무 트래픽과 스토리지 데이터가 같은 이더넷을 공유하면 혼잡과 패킷 손실이 생기고, DAS(Direct-Attached Storage)는 스토리지가 서버에 종속되어 공유가 어려우므로, 이를 함께 해소할 무손실 고속 전송망이 요구됨.
- 주요 목적 : 무손실 블록 전송, LUN(Logical Unit Number)의 서버 간 공유와 통합, 미션 크리티컬 DB의 HA(High Availability)와 DR(Disaster Recovery) 기반 마련.

## Ⅱ. SAN(Storage Area Network)의 특징 및 장점

- 핵심 요약 : 무손실 흐름 제어와 이중 접근 제어가 데이터 안정성과 보안으로 이어지는 구조.

1. **B2B 크레딧** (Buffer-to-Buffer Credit) 기반 흐름 제어 : 수신 측 버퍼에 여유가 있을 때만 송신 측에 크레딧을 부여 → 패킷 드롭과 재전송 오버헤드를 원천적으로 차단.
2. **조닝** (Zoning)과 **LUN 매스킹** (LUN Masking)의 2단계 접근 제어 : 패브릭 스위치에서 WWPN(World Wide Port Name) 단위로 통신 그룹을 격리하고, 스토리지 어레이에서 승인된 호스트 HBA(Host Bus Adapter)에만 LUN을 매핑 → 두 계층의 통제로 노출 범위 축소.

## Ⅲ. SAN(Storage Area Network)의 구조 및 동작 메커니즘

- 핵심 요약 : FC(Fibre Channel) HBA에서 이중 패브릭 스위치를 거쳐 스토리지 어레이의 LUN까지 이어지는 무손실 블록 경로.
- FC(Fibre Channel) 패브릭 : FC 스위치들로 구성되어 노드 간 경로를 제공하는 상호 연결 구조.
- 이중 패브릭(Fabric A/B) : 독립된 두 스위치 집합으로 경로를 이중화하여, 한쪽 패브릭 장애 시 다른 쪽으로 I/O를 전환.

```text
[ FC-SAN 데이터 경로 ]

서버 호스트 (FC HBA, 이중 포트)
      ↓ 광케이블
FC 패브릭 A / B (이중 구성)
  - 조닝으로 WWPN 단위 그룹 분리
  - B2B 크레딧 기반 무손실 전송
      ↓
스토리지 어레이 (대상 포트 WWPN)
  - LUN 매스킹으로 승인된 HBA에만 매핑
```

```text
[ 2단계 접근 제어 ]

1단계 : 패브릭 스위치 → 조닝 (포트/WWPN)
      ↓ 통과한 트래픽만
2단계 : 스토리지 어레이 → LUN 매스킹
      ↓
승인된 호스트의 LUN에만 I/O 허용
```

## Ⅳ. SAN(Storage Area Network)의 비교

- 핵심 요약 : FC-SAN, IP-SAN, NVMe-oF는 전송 매체와 프로토콜, 지연, 비용에서 갈리며 워크로드 요구에 따라 선택.

| 비교 항목 | FC-SAN (Fibre Channel) | IP-SAN (iSCSI) | NVMe-oF (NVMe over Fabrics) |
| :--- | :--- | :--- | :--- |
| 전송 매체 | 전용 광케이블과 FC 스위치 | 표준 이더넷 케이블과 스위치 | RDMA 지원 이더넷(RoCE(RDMA over Converged Ethernet) v2), InfiniBand, TCP/IP |
| 프로토콜 스택 | FCP (SCSI over FC) | iSCSI(Internet Small Computer Systems Interface), SCSI over TCP/IP | NVMe over RDMA(Remote Direct Memory Access) 또는 NVMe over TCP |
| 전송 속도 | 16G, 32G, 64G FC 세대 | 10G, 25G, 100G 이더넷 | 100G 이상 이더넷 또는 InfiniBand |
| 지연 특성 | 낮은 지연과 무손실 전송 | TCP 스택 처리로 상대적으로 높은 지연 | RDMA 사용 시 매우 낮은 지연 |
| 구축 비용 | 높음 (전용 HBA와 FC 스위치) | 낮음 (기존 이더넷 장비 활용) | 중간 이상 (RDMA 지원 NIC 필요) |
| 주요 적용 | 금융권 코어뱅킹, 대규모 DB 클러스터 | 중소 규모 가상화, 백업 타깃 | 초고성능 AI 분산 학습, 고속 캐시 풀 |

## Ⅴ. SAN(Storage Area Network)의 한계와 방안

- 핵심 요약 : 구축 비용, 패브릭 혼잡 전파, 블록 공유의 한계를 이더넷 기반 전환, 혼잡 감지, 클러스터 파일시스템으로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| FC-SAN **구축 비용** 및 전문 인력 부담 | 전용 광케이블, FC 스위치, HBA 단가가 높고 패브릭 운영에 전문 역량 필요 → 도입 장벽 상승 | 기존 100GbE 이더넷 자산을 활용하는 RoCE v2 기반 IP-SAN 또는 NVMe-oF로 전환 | 단위 성능당 인프라 비용 |
| **Slow Drain** (슬로우 드레인) | 특정 포트의 응답 지연으로 B2B 크레딧 반환이 늦어지면 상위 스위치 버퍼가 고갈되어 혼잡이 패브릭 전체로 확산 | FPIN(Fabric Performance Impact Notification) 기반으로 혼잡 포트를 자동 감지하고 속도를 동적으로 격리 | 포트별 크레딧 대기 시간 |
| 블록 공유의 한계 | 순수 블록 LUN을 여러 호스트가 동시에 마운트하면 파일시스템 메타데이터가 손상될 수 있어 파일 단위 공유가 어려움 | 클러스터 파일시스템(GFS2, OCFS2, VMFS) 적용, 또는 NAS(Network-Attached Storage) 게이트웨이를 결합한 통합 스토리지 구성 | 메타데이터 일관성 점검 결과 |

## Ⅵ. SAN(Storage Area Network)에 대한 기술사적 제언

- 핵심 요약 : FC-SAN 자산을 이더넷 기반 NVMe-oF로 단계 전환하고, 이중 패브릭의 장애 전환을 상시 검증하는 운영 체계.

1. 기존 FC-SAN 자산의 교체 주기에 맞춰 RoCE 기반 NVMe-oF 전환 로드맵을 세우되, 지연 요구가 큰 올플래시 업무부터 옮기는 것이 현실적.
2. 이중 패브릭은 설계만으로 가용성이 보장되지 않으므로, 운영 조직이 정기적으로 한쪽 패브릭을 의도적으로 차단하고 MPIO(Multipath I/O)의 절체 결과를 기록하는 검증 절차를 정착.

## Ⅶ. 결론

- 핵심 요약 : SAN은 무손실 블록 전송과 LUN 공유, HA/DR을 제공하는 스토리지 전용 네트워크이나, 구축 비용과 Slow Drain 리스크를 함께 관리해야 하는 구조.
- 시사점 : 미션 크리티컬 블록 워크로드에서는 여전히 강점이 크며, 전환 여부는 기존 자산과 업무별 지연 요구를 기준으로 결정해야 함.
