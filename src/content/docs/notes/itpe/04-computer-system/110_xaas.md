## 연관 키워드

- XaaS(Everything as a Service), 구독 경제, 서비타이제이션(Servitization)
- 서비스형 인프라(IaaS), 서비스형 플랫폼(PaaS), 서비스형 소프트웨어(SaaS)
- SECaaS, DRaaS, AIaaS, RaaS, MaaS, 컴포저블 아키텍처
- SLA, FinOps, 데이터 계약(Data Contract), CASB

## Ⅰ. XaaS의 개요

- 핵심 요약 : 클라우드의 서비스형 모델을 IT 전 영역과 산업 자산으로 확장해, 소유 대신 구독으로 제공하는 체계.
- 개념 : 인프라·플랫폼·소프트웨어의 서비스화 모델을 출발점으로, 모든 정보기술 자원과 산업 자산을 구독형 서비스로 제공하는 **XaaS** (Everything as a Service, 모든 것의 서비스화) 체계.
- 배경 및 필요성 : 하드웨어 구축의 **초기 자본 지출** (CapEx, Capital Expenditure) 부담, 기술 교체 주기 단축, 소유보다 활용을 중시하는 구독 경제 확산.
- 주요 목적 : 비용 구조의 운영 지출 전환, API(Application Programming Interface) 조합을 통한 서비스 출시 속도 향상.

## Ⅱ. XaaS의 특징 및 장점

- 핵심 요약 : 구독형 과금과 API 조합성, 운영 책임 이전이 초기 투자 부담 감소와 출시 속도 향상으로 이어지는 구조.

1. 구독·사용량 과금 : 사용한 만큼만 지불 → 초기 투자 부담과 유휴 자원 손실 감소.
2. API 기반 조합성 : 기능을 표준 API로 노출 → 공급자 서비스를 블록처럼 조합해 출시 기간 단축.
3. 운영 책임의 이전 : **서비스 수준 협약** (SLA, Service Level Agreement)으로 가용성·성능 책임을 공급자에게 이전 → 이용자 조직의 운영 부담 경감.
4. 서비타이제이션 : **서비타이제이션** (Servitization, 제품 판매를 가동 상태 기반 서비스 과금으로 전환) → 제조사 수익 모델 다변화와 운영 데이터 확보.

## Ⅲ. XaaS의 구조 (흐름)

- 핵심 요약 : 클라우드 3대 모델에서 기능·산업 영역으로 확장되는 유형 분류와 도입·운영 절차.

1. **서비스형 인프라** (IaaS, Infrastructure as a Service) : 서버·네트워크·스토리지의 임대.
2. **서비스형 플랫폼** (PaaS, Platform as a Service) : 실행 환경과 개발 도구의 제공.
3. **서비스형 소프트웨어** (SaaS, Software as a Service) : 완성 애플리케이션의 구독 이용.

- 기능·산업 확장 유형 :
  1. 보안 서비스화 (SECaaS, Security as a Service) : 클라우드 기반 보안 관제.
  2. 재해복구 서비스화 (DRaaS, Disaster Recovery as a Service) : 백업·비상 가동 위탁.
  3. AI 자원 서비스화 (AIaaS, Artificial Intelligence as a Service) : 학습·추론 자원 대여.
  4. 로봇·이동수단 서비스화 (RaaS·MaaS) : 로봇(Robot as a Service)과 이동 수단(Mobility as a Service)의 구독.

```text
[ XaaS 유형 확장 구조 ]

클라우드 3대 모델
  인프라·플랫폼·소프트웨어
     ↓ 기능 영역 확장
보안·재해복구·AI·백엔드
     ↓ 산업 융합 확장
로봇·모빌리티·에너지
```

```text
[ XaaS 도입·운영 흐름 ]

요건 정의 (기능·보안·비용)
     ↓
공급자 선정 (SLA·계약)
     ↓
API 연동과 계정 연계
     ↓
사용량 계측과 과금 관리
     ↓
갱신·해지와 데이터 반환
```

- 컴포저블 아키텍처 : **컴포저블 아키텍처** (Composable Architecture, API로 패키징된 기능을 조합해 서비스를 구성하는 설계 방식)로 내부 개발을 최소화하고 외부 서비스를 조합하는 접근.

## Ⅳ. XaaS 구독과 자체 구축의 비교

- 핵심 요약 : 구독은 초기 부담과 운영 책임을 덜어주지만 장기 비용과 데이터 통제에서 자체 구축과 차이가 남.

| 비교 축 | XaaS 구독 | 자체 구축 (온프레미스) |
| :--- | :--- | :--- |
| 초기 비용 | 도입 즉시 사용, 선투자 없음 | 하드웨어·라이선스 선투자 |
| 비용 성격 | 사용량 기반 운영 지출 | 고정 비용 중심 |
| 확장 속도 | 계정·용량 단위 즉시 증설 | 조달·구축 주기 필요 |
| 운영 책임 | 공급자 (SLA 기준) | 이용자 조직 |
| 장기 비용 | 누적 구독료 상승 가능 | 감가상각 후 유지 비용 |
| 데이터 통제 | 공급자 환경 위탁 | 내부 환경 직접 통제 |

- 선택 기준 : 데이터 민감도, 사용 빈도, 장기 누적 비용을 기준으로 자체 보유와 구독을 구분하고, 운영 책임의 분담 범위로 유형을 선택하는 기준.

## Ⅴ. XaaS의 한계와 방안

- 핵심 요약 : 장기 비용 역전, 외부 장애 연쇄, 데이터 통제 상실이 주요 한계이며 비용 추적, 장애 격리, 보안 계약으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| 장기 구독 비용 역전 | 누적 구독료가 자체 구축 비용을 상회 → TCO(Total Cost of Ownership) 악화 | 서비스별 단위 비용 추적, 저사용 서비스 해지와 핵심 워크로드 내재화 | 서비스별 단위 비용 |
| 외부 장애의 연쇄 전파 | 인증·결제 API 장애가 전사 업무 중단으로 확산 | 서킷 브레이커 패턴, 장애 시 캐시 응답으로 서비스 지속 설계 | 외부 호출 실패율, 복구 시간 |
| 데이터 통제 상실 | 공급자 분산과 독점 포맷 → 유출·이전 제약 | **CASB** (Cloud Access Security Broker) 도입, 종단간 암호화, 데이터 계약 명시 | 데이터 분류 준수율 |

## Ⅵ. XaaS에 대한 기술사적 제언

- 핵심 요약 : 도입 거버넌스, 비용 관리 조직, 제조업의 서비스 전환 로드맵이 XaaS 활용의 상위 과제.

1. 정보시스템 부서는 도입 전에 SLA 가용성 기준, 데이터 소유권, 해지 시 반환·파기를 규정한 **데이터 계약** (Data Contract) 표준을 심사 체계로 운영해야 한다.
2. 재무와 IT 운영은 구독 포트폴리오의 투자 대비 효과를 정기 평가하는 FinOps 전담 체계를 두어 도입·해지 권한을 일원화해야 한다.
3. 제조 기업은 IoT 센서와 예측 정비를 결합한 구독형 서비스 전환 로드맵을 수립해 제품 수명주기 전체를 서비스로 제공해야 한다.

## Ⅶ. 결론

- 핵심 요약 : XaaS는 자산의 소유를 구독 관계로 바꾸는 아키텍처이자 비즈니스 방식.
- 시사점 : 조합의 민첩성이 커질수록 공급자 의존도 함께 커지는 구조라는 점이 관리 포인트가 됨.
