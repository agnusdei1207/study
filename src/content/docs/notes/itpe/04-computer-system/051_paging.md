## 연관 키워드

- 페이징(Paging), 페이지(Page), 프레임(Frame), 페이지 테이블(Page Table), PTE(Page Table Entry)
- TLB(Translation Lookaside Buffer), 다단계 페이지 테이블(Multi-level Page Table), 페이지 폴트(Page Fault)
- 요구 페이징(Demand Paging), 대용량 페이지(Huge Page), 내부 단편화(Internal Fragmentation), EPT(Extended Page Tables)

## Ⅰ. 페이징의 개요

- 핵심 요약 : 가상 주소 공간과 물리 메모리를 같은 크기의 블록으로 나누어 불연속 적재를 허용하는 **페이징** (Paging) 기법.
- 개념 : 가상 주소 공간을 고정 크기의 **페이지** (Page)로, 물리 메모리를 같은 크기의 **프레임** (Frame)으로 나누고, 페이지를 빈 프레임 어디에나 사상(Mapping)하는 메모리 관리 기법.
- 배경 및 필요성 : 가변 분할 방식은 빈 공간이 흩어져 큰 연속 영역 확보가 어렵고, 이를 메우는 압축(Compaction)에는 복사 비용이 따름. 블록 크기의 통일로 연속 할당 요구 자체를 없애는 구조가 이 비용의 근원적 해법.
- 주요 목적 : 연속 공간 요구의 제거를 통한 메모리 활용률 향상, **요구 페이징** (Demand Paging)과 공유 라이브러리 같은 고급 기능의 기반 제공.

## Ⅱ. 페이징의 특징 및 장점

- 핵심 요약 : 고정 크기 매핑과 오프셋 불변 변환, 다단계 테이블, TLB 캐싱이 맞물려 외부 단편화 없이 빠른 주소 변환을 제공하는 구조.

1. 고정 크기 분할 : 페이지와 프레임을 같은 크기(x86-64 기본 4KB)로 통일 → 빈 프레임 어디든 즉시 배치 가능, 빈 공간 흩어짐의 원천 제거.
2. 오프셋 불변 변환 : 가상 주소의 페이지 번호 p만 프레임 번호 f로 치환하고 변위 d는 그대로 유지 → 변환 로직의 단순화로 하드웨어 고속 처리.
3. **다단계 페이지 테이블** (Multi-level Page Table) : 실제 사용 영역의 테이블만 계층 트리로 할당 → 64비트 주소 공간에서도 테이블 메모리 소비 절감.
4. **TLB** (Translation Lookaside Buffer) : 최근 변환 결과를 메모리 관리 장치(MMU, Memory Management Unit) 내부 캐시에 보관 → 적중 시 테이블 조회 생략으로 변환 지연 감소.

## Ⅲ. 페이징의 구조 (흐름)

- 핵심 요약 : TLB 조회와 다단계 테이블 워크로 프레임 번호를 얻고, 메모리에 없는 페이지는 페이지 폴트 절차로 적재하는 흐름.

```text
[ 가상 주소 → 물리 주소 변환 ]

가상 주소 <p, d>
      ↓
TLB 조회
   적중 → 프레임 번호 즉시 획득
   미스 → 페이지 테이블 워크
      ↓
PTE의 존재 비트 확인
   1 → 물리 주소 = <f, d>
   0 → 페이지 폴트 절차 진입
```

```text
[ 페이지 폴트 처리 절차 ]

폴트 발생 → 커널의 폴트 처리기 진입
      ↓
접근 적법성 판별
      ↓
디스크에서 페이지를 빈 프레임에 적재
      ↓
PTE 갱신 (프레임 번호·존재 비트)
      ↓
폴트 명령 재실행
```

- 구성요소 : 페이지 테이블은 페이지 번호를 프레임 번호로 연결하는 표이고, 각 항목인 **PTE** (Page Table Entry)는 프레임 번호와 제어 비트를 보관하며, x86-64는 최상위 테이블 위치를 CR3 레지스터에 저장하는 구조.
- PTE의 주요 비트 : 존재(Present) 비트, 읽기·쓰기(R/W) 비트, 사용자·감독자(U/S) 비트, 참조·수정(Accessed·Dirty) 비트, 실행 금지(NX, No-Execute) 비트.

## Ⅳ. 페이징의 비교

- 핵심 요약 : 페이지 크기의 확대는 TLB 커버리지와 테이블 워크를 줄이는 대신 **내부 단편화** (Internal Fragmentation)를 키우는 상충 관계이며, **대용량 페이지** (Huge Page)는 이 상충의 절충 수단.

| 비교 항목 | 기본 페이지 4KB | 대용량 페이지 2MB | 초대용량 페이지 1GB |
| --- | --- | --- | --- |
| 테이블 워크 단계 (x86-64) | 4단계 | 3단계 (PT 생략) | 2단계 (PD·PT 생략) |
| TLB 커버리지 (512항목 기준) | 2MB | 1GB | 512GB |
| 내부 단편화 | 작음 | 커질 수 있음 | 큼 |
| 적용 부담 | 기본값으로 무부담 | 크기 정렬·사전 예약 필요 | 워크로드 제약이 큼 |
| 주요 용도 | 일반 프로세스 | 대형 힙·데이터베이스 버퍼 | 대용량 메모리 호스트 |

- 선택 기준 : 작은 객체가 많은 워크로드는 기본 페이지를, 대형 힙과 순차 접근이 많은 워크로드는 대용량 페이지를 택하는 판단 기준.

## Ⅴ. 페이징의 한계와 방안

- 핵심 요약 : 페이지 단위 할당의 낭비, 테이블 워크 지연, 가상화의 이중 주소 변환 비용을 미세 할당·페이지 크기 정책·하드웨어 보조 변환으로 대응하는 원칙.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 내부 단편화 | 페이지 단위 할당의 잔여 공간이 낭비 (예: 5KB 요구에 8KB 점유) | 기본 페이지 유지, 커널·응용의 슬랩(Slab) 할당기로 소형 객체 미세 관리 | 메모리 낭비율 |
| 테이블 워크 지연 | TLB 미스 때마다 테이블 단계 수만큼 메모리 접근 누적 | 대용량 페이지 적용으로 워크 단계·미스 동시 축소 | TLB 미스율 |
| 가상화의 2차원 변환 비용 | 게스트 가상→게스트 물리→호스트 물리의 이중 변환으로 접근 지연 | **EPT** (Extended Page Tables, Intel)·NPT(Nested Page Tables, AMD) 하드웨어 지원 활성화 | 변환 미스율, 접근 지연 |

## Ⅵ. 페이징에 대한 기술사적 제언

- 핵심 요약 : 워크로드별 페이지 크기 정책의 선제 설계, 권한 비트 기반 실행 통제의 표준화, 메모리 성능 이벤트의 상시 관측을 제안하는 방향.

1. 데이터 플랫폼 운영 조직은 버퍼 캐시가 쓰는 대형 메모리를 정적 대용량 페이지로 사전 확보하고, 투명 대용량 페이지(THP, Transparent Huge Pages)의 백그라운드 병합이 만드는 지연 변수를 배포 기준에서 배제한다.
2. 보안 조직은 NX 비트와 **W^X** (Write XOR Execute) 정책을 배포 표준으로 반영하여, 쓰기 가능 영역과 실행 가능 영역의 분리를 빌드·배포 단계에서 검증한다.
3. 성능 운영 조직은 페이지 폴트 발생률과 TLB 정지 시간을 상시 관측 체계에 포함하고, 페이지 크기 정책 변경 전후를 동일 지표로 비교 검증하는 절차를 둔다.

## Ⅶ. 결론

- 핵심 요약 : 페이징은 고정 크기 블록 매핑으로 연속 할당 문제를 없앤 메모리 관리의 표준이며, 테이블 메모리와 변환 지연 관리가 설계의 핵심 변수.
- 페이지 크기와 테이블 깊이는 고정 규격이 아닌 운영 지표로 조정하는 튜닝 대상이라는 관점이 필요한 기법.
