## Ⅰ. 추측 디코딩(Speculative Decoding)의 개요

- 핵심 요약 : **추측 디코딩**은 소형 드래프트 모델이 K개 토큰을 사전 생성하고 대형 타깃 모델이 1회 순전파로 병렬 검증하여 무손실 추론 가속을 달성하는 기법.
- 개념 : 대형 언어 모델(LLM, Large Language Model)의 **자기회귀(Autoregressive)** 생성 추론 시, 소형 경량 **드래프트 모델(Draft Model)** 이 여러 개의 연속 토큰을 고속으로 사전 추측 생성하고, 대형 **타깃 모델(Target Model)** 이 이를 단 한 번의 순전파(Forward Pass)로 병렬 검증하여 토큰 생성 처리량을 비약적으로 향상시키는 무손실 추론 가속 기법.
- 배경 및 필요성 : LLM 추론은 이전 토큰을 기반으로 다음 토큰 1개를 생성할 때마다 수십~수백 GB의 전체 가중치 파라미터를 HBM(High Bandwidth Memory)에서 GPU(Graphics Processing Unit) 코어로 로딩해야 하는 **메모리 대역폭 집약적(Memory-Bound)** 병목에 직면함.
- 핵심 목적 : 모델의 출력 품질과 확률 분포 손실(Lossless) 없이 **월클록(Wall-Clock)** 추론 지연 시간 단축 및 GPU 자원 활용률 극대화.

## Ⅱ. 추측 디코딩(Speculative Decoding)의 특징 및 장점

- 핵심 요약 : **드래프트 생성·단일 순전파 검증·무손실 샘플링**으로 추론 가속.
1. **초고속 토큰 추측(Drafting)** : 메모리 풋프린트가 작은 소형 모델을 사용하여 $K$ 개의 미래 토큰 후보를 적은 지연으로 빠르게 생성.
2. **병렬 검증 및 무손실 샘플링(Verifying)** : 타깃 모델은 인과적 어텐션 마스크(Causal Attention Mask)를 활용해 $K$ 개 토큰을 1회의 순전파로 동시 평가하며, 수학적으로 타깃 모델의 원래 분포와 완전히 일치하도록 보장하는 거부 샘플링(Rejection Sampling) 수행.

## Ⅲ. 추측 디코딩(Speculative Decoding)의 구조 및 동작 메커니즘

- 핵심 요약 : **드래프트 생성 → 타깃 단일 순전파 검증 → 거부 샘플링 → 보정 토큰**.
- 추측 디코딩은 소형 드래프트 모델이 K개 토큰을 사전 생성하고, 대형 타깃 모델이 이를 1회 순전파로 병렬 검증한 뒤 거부 샘플링으로 보정 토큰을 샘플링하여 무손실 추론 가속을 달성함.

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 추측 디코딩 (Speculative Decoding) 동작 파이프라인 ]                │
│                                                                        │
│  입력 프롬프트 ──> [ 소형 드래프트 모델 (예: LLaMA-7B) ]               │
│                     │ 저지연 K개 연속 토큰 초고속 생성 (Memory-Light)   │
│                     ▼                                                  │
│              후보 토큰 시퀀스: [y₁, y₂, y₃, y₄]                          │
│                     │                                                  │
│                     ▼                                                  │
│  단일 순전파 검증 ──> [ 대형 타깃 모델 (예: LLaMA-70B) ]               │
│                     │ 4개 토큰을 배치 병렬 검증 (Compute-Bound 전환)    │
│                     ▼                                                  │
│              타깃 모델 확률 계산: [P(y₁), P(y₂), P(y₃), P(y₄)]          │
│                     │                                                  │
│                     ▼                                                  │
│  [ 수정된 거부 샘플링 (Modified Rejection Sampling) 검증 ]             │
│   - y₁ 승인! -> y₂ 승인! -> y₃ 거절!                                   │
│   - 거절된 y₃ 위치에서 타깃 모델이 보정 토큰 y₃' 즉시 샘플링          │
│                     │                                                  │
│                     ▼                                                  │
│  최종 출력 토큰: [y₁, y₂, y₃'] (1회 타깃 포워드로 3개 토큰 확정!)      │
└────────────────────────────────────────────────────────────────────────┘
```

## Ⅳ. 추측 디코딩(Speculative Decoding)의 비교

- 핵심 요약 : **독립 드래프트·자가 드래프트·멀티 헤드·트리 기반** 구현 방식 비교.

| 방식 구분 | 동작 아키텍처 | 장점 | 트레이드오프 및 한계점 |
| :--- | :--- | :--- | :--- |
| 독립 드래프트 모델 (Standard Speculative) | 동일 계열의 소형 독립 모델 페어링 (예: 70B & 8B) | 구현이 직관적이며 범용 적용 가능 | 드래프트 모델을 위한 별도 GPU VRAM(Video Random-Access Memory) 점유 |
| 자가 드래프트 (Self-Speculative / Layer Skip) | 타깃 모델의 중간 레이어를 건너뛰고 조기 종료(Early Exit) | 추가 모델 로딩 불필요, VRAM 절감 | 중간 표현 품질 저하 시 승인율 급감 |
| 멀티 헤드 추측 (Medusa) | 타깃 모델 최종 출력단에 여러 개의 추가 디코딩 헤드 부착 | 단일 모델 내 트리 구조 추측 가능 | 별도의 파인튜닝 학습 과정 필요 |
| 트리 기반 검증 (EAGLE) | 토큰 시퀀스 대신 트리(Tree) 구조로 다중 경로 동시 추측 | 토큰 승인율(Acceptance Rate) 극대화 | 어텐션 마스크 복잡도 증가 |

## Ⅴ. 추측 디코딩(Speculative Decoding)의 한계와 방안

- 핵심 요약 : **승인율 저하·배치 포화 역전·메모리 복잡성**을 트리 검증·동적 스위칭·양자화로 대응.

- 드래프트 모델과 타깃 모델 간 **승인율(Acceptance Rate)** 저하 :
  - 한계점 : 코딩, 수학 등 정밀 논리 태스크나 창의적 글쓰기에서 드래프트 모델의 예측이 빗나가면 승인율이 크게 낮아져 떨어져 검증 오버헤드만 발생.
  - 해결 방안 : 트리 기반 추측(EAGLE, Sequoia)을 통해 여러 경로를 동시 검증하여 채택 확률 향상, 도메인별 특화 경량 드래프트 모델 적용.
- 다중 사용자 **동시 접속(High Batch)** 환경에서의 효율 역전 :
  - 한계점 : 서빙 배치가 충분히 커지면 GPU가 이미 Compute-Bound 상태에 도달하므로 추측 디코딩의 병렬 검증이 오히려 전체 처리량(Throughput) 저하 초래.
  - 해결 방안 : 동적 적응형 스위칭(Dynamic Speculation) 도입으로 동시 요청 수가 적을 때는 추측 디코딩 활성화, 배치 포화 시 표준 자기회귀 디코딩으로 자동 전환.
- 이종 모델 유지에 따른 인프라 메모리 및 관리 복잡성 :
  - 한계점 : 타깃 모델 외에 드래프트 모델을 VRAM에 상주시켜야 하므로 엣지 디바이스나 메모리 제한 환경에서 배포 제약.
  - 해결 방안 : 드래프트 모델의 FP4/INT4 극단적 양자화, 단일 가중치를 공유하는 자가 추측(Self-Speculative) 기법 채택.

## Ⅵ. 추측 디코딩(Speculative Decoding) 적용 제언

- 핵심 요약 : **vLLM/TensorRT-LLM 통합·도메인 특화 SLM 드래프트**.
- LLM 서빙 엔진의 풀스택 통합 가속화 : vLLM/TensorRT-LLM/TGI와 PagedAttention/Chunked Prefill 결합으로 비용 50% 절감.
- 도메인 특화 SLM 기반 드래프트 모델 파이프라인 구축 : 사내 도메인 코퍼스로 sLLM 드래프트, 승인율 80%+.

## Ⅶ. 결론

- 핵심 요약 : 추측 디코딩은 **소형 드래프트 + 대형 타깃 단일 순전파 검증**으로 무손실 추론 가속을 달성하나 승인율·배치 포화·메모리 복잡성 리스크 관리가 필수.
- 추측 디코딩은 소형 드래프트 모델이 K개 토큰을 사전 생성하고 대형 타깃 모델이 1회 순전파로 병렬 검증하여 무손실 추론 가속을 달성하지만, 승인율 저하·배치 포화 역전·메모리 복잡성 리스크를 트리 검증·동적 스위칭·양자화로 관리해야 함.
- 답안에는 드래프트/검증 파이프라인, 4대 구현 방식 비교, 한계·대응, vLLM 통합·도메인 SLM 제언을 연결.
