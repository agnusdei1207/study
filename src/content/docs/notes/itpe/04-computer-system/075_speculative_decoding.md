## 연관 키워드

- 추측 디코딩, Speculative Decoding, 드래프트 모델, 타깃 모델, 자기회귀 디코딩
- 거부 샘플링, 보정 토큰, 승인율, 자가 추측, 트리 기반 검증, 배치 포화

## Ⅰ. 추측 디코딩의 개요

- 핵심 요약 : 소형 모델이 여러 토큰을 미리 제안하고 대형 모델이 한 번에 검증하여, 출력 분포를 바꾸지 않고 추론을 가속하는 기법.
- 개념 : 대형 언어 모델(LLM, Large Language Model)의 토큰 단위 순차 생성을 줄이기 위해, 소형 **드래프트 모델** (Draft Model)이 후보 토큰을 여러 개 제안하고 **타깃 모델** (Target Model)이 이를 병렬로 검증하는 **추측 디코딩** (Speculative Decoding).
- 배경 및 필요성 : 기존 **자기회귀 디코딩** (Autoregressive Decoding)은 토큰 하나를 만들 때마다 전체 가중치를 **고대역폭 메모리** (HBM, High Bandwidth Memory)에서 **그래픽 처리 장치** (GPU, Graphics Processing Unit)로 읽어야 하므로 메모리 대역폭에 묶여 연산 자원이 놀게 됨. 한 번의 순전파로 여러 토큰을 검증할 수 있으면 이 병목을 완화할 수 있음.
- 주요 목적 : 출력 품질 손실 없이 실제 응답 완료까지의 경과 시간(Wall-Clock Time)을 줄이고 GPU 활용률을 높이는 것.

## Ⅱ. 추측 디코딩의 특징 및 장점

- 핵심 요약 : 드래프트 생성, 병렬 검증, 거부 샘플링이 결합되어 무손실 가속으로 이어지는 구조.

1. 드래프트 생성 : 메모리 점유가 작은 드래프트 모델이 K개 토큰을 빠르게 제안 → 타깃 모델의 순차 호출 횟수 감소.
2. 병렬 검증 : 타깃 모델이 제안된 K개 위치를 인과적 어텐션 마스크(Causal Attention Mask)로 한 번의 순전파에서 함께 평가 → 연산 병렬성을 활용해 토큰당 비용 절감.
3. **거부 샘플링** (Rejection Sampling) : 타깃 모델의 확률 분포를 기준으로 제안 토큰을 채택하거나 기각하는 확률적 검사 → 최종 출력 분포가 타깃 모델과 일치하여 무손실 보장.

## Ⅲ. 추측 디코딩의 구조 (흐름)

- 핵심 요약 : 드래프트 제안, 타깃 단일 순전파 검증, 거부 샘플링, 보정 토큰 확정의 네 단계를 반복하는 흐름.
- 구성 요소 : 제안 토큰 시퀀스, 위치별 타깃 확률 분포, 기각 지점에서 다시 뽑는 **보정 토큰** (Adjusted Token).

```text
[ 추측 디코딩 1회 반복 ]

현재 문맥 (입력 프롬프트)
        ↓
드래프트 모델: K개 토큰 제안
        ↓
타깃 모델: K개 위치 확률 병렬 계산
        ↓
거부 샘플링: 앞에서부터 채택 또는 기각
        ↓
기각 지점에서 보정 토큰 샘플링
        ↓
채택 토큰과 보정 토큰 확정
```

```text
[ 검증 예시 (K = 4) ]

제안: y1  y2  y3  y4
        ↓
y1 채택 → y2 채택 → y3 기각 (y4 폐기)
        ↓
y3 위치에서 보정 토큰 y3' 샘플링
        ↓
확정: y1  y2  y3'  (타깃 1회 순전파로 3개)
```

## Ⅳ. 추측 디코딩의 비교

- 핵심 요약 : 드래프트 토큰의 출처와 제안 구조에 따라 구현 난도, 메모리 부담, 승인율이 달라지는 구조.
- 선택 기준 : 추가 VRAM(Video Random-Access Memory) 여유, 드래프트 모델 학습 가능 여부, 목표 승인율에 따라 방식을 고른다.

| 구분 | 드래프트 출처 | 장점 | 트레이드오프 |
| :--- | :--- | :--- | :--- |
| 독립 드래프트 모델 | 같은 계열의 소형 별도 모델 | 구현이 직관적이고 범용 적용 가능 | 드래프트 모델 상주를 위한 추가 VRAM 점유 |
| 자가 추측 (Self-Speculative) | 타깃 모델의 중간 레이어를 건너뛰는 조기 종료 | 추가 모델 로딩 불필요 | 중간 표현 품질이 낮으면 승인율 급감 |
| 멀티 헤드 추측 (Medusa) | 타깃 모델 출력단에 추가 디코딩 헤드 부착 | 단일 모델 안에서 다중 후보 제안 | 헤드 학습을 위한 추가 파인튜닝 필요 |
| 트리 기반 검증 (EAGLE) | 토큰 시퀀스 대신 트리 구조로 다중 경로 제안 | 승인 가능한 경로 선택 폭이 넓어 승인율 향상 | 어텐션 마스크 구성 복잡도 증가 |

## Ⅴ. 추측 디코딩의 한계와 방안

- 핵심 요약 : 승인율 저하, 고부하 배치에서의 효율 역전, 드래프트 모델의 메모리 부담을 트리 검증, 동적 스위칭, 양자화로 대응하는 구조.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| 승인율 저하 | 정밀 논리 작업이나 창의적 글쓰기에서 드래프트 예측이 빗나가 검증 비용만 증가 | 여러 경로를 동시에 검증하는 트리 기반 추측 적용, 도메인 특화 드래프트 모델 사용 | 승인율, 토큰당 검증 비용 |
| 고부하 배치에서의 효율 역전 | 동시 요청이 늘어 GPU가 연산 바운드 상태가 되면 추가 검증 연산이 **배치 포화** 상황에서 처리량을 떨어뜨림 | 요청 부하가 낮을 때만 추측을 켜고, 배치가 포화되면 표준 자기회귀 디코딩으로 전환하는 동적 스위칭 | 처리량, 요청 대기 시간 |
| 드래프트 모델의 메모리 부담 | 타깃 외에 드래프트 가중치를 VRAM에 상주시켜 엣지나 메모리 제약 환경에 배포 제약 | 드래프트 모델의 저비트 양자화, 가중치를 공유하는 자가 추측 방식 채택 | VRAM 사용량, 메모리 여유율 |

## Ⅵ. 추측 디코딩에 대한 기술사적 제언

- 핵심 요약 : 추측 디코딩을 서빙 엔진의 기본 기능으로 편입하고, 도메인 데이터 기반의 드래프트 모델로 승인율을 관리하는 운영 체계.

1. LLM 서빙 플랫폼은 vLLM, TensorRT-LLM 같은 추론 엔진의 추측 디코딩 기능을 표준 설정으로 채택하고, 부하 수준에 따라 켜고 끄는 정책을 운영 계층에서 관리하는 것이 바람직하다.
2. 드래프트 모델은 범용 소형 모델보다 사내 도메인 데이터로 맞춘 소형 언어 모델이 승인율 측면에서 유리할 가능성이 있으므로, 도메인별 승인율을 측정한 뒤 드래프트 모델을 선정하는 절차를 두는 것이 필요하다.

## Ⅶ. 결론

- 핵심 요약 : 추측 디코딩은 소형 드래프트와 대형 타깃의 병렬 검증으로 무손실 추론 가속을 구현하는 기법.
- 가속 효과가 승인율과 배치 부하에 좌우되므로, 적용 여부는 워크로드의 부하 조건을 기준으로 판단해야 함.
