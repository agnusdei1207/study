## 연관 키워드

- SaaS, Software as a Service, 멀티테넌시, 구독형, SLA, 데이터 격리

## Ⅰ. SaaS의 개요

- 핵심 요약 : SaaS는 공급자가 클라우드에서 애플리케이션을 운영하고 고객이 네트워크를 통해 구독·서비스 형태로 사용하는 클라우드 서비스 모델.
- 개념 : SaaS는 공급자가 클라우드에서 애플리케이션을 운영하고 고객이 네트워크를 통해 구독·서비스 형태로 사용하는 클라우드 서비스 모델.
- 배경 및 필요성 : 고객별 설치·패치·인프라 운영 부담을 공급자 운영으로 전환할 필요.
- 주요 목적 : 서비스 접근성과 업데이트 편의 제공 및 고객의 IT 운영부담 축소.

## Ⅱ. SaaS의 특징 및 장점

- 핵심 요약 : 서비스 운영형: 공급자가 애플리케이션·인프라 운영 → 고객은 사용·설정 중심; 멀티테넌시: 자원 공유·테넌트 격리 → 규모의 경제와 격리책임; 구독·SLA: 지속적 서비스·지원 계약 → 가용성·데이터처리 약속 명문화.

1. 서비스 운영형: 공급자가 애플리케이션·인프라 운영 → 고객은 사용·설정 중심
2. 멀티테넌시: 자원 공유·테넌트 격리 → 규모의 경제와 격리책임
3. 구독·SLA: 지속적 서비스·지원 계약 → 가용성·데이터처리 약속 명문화

## Ⅲ. SaaS의 구조 (흐름)

- 핵심 요약 : 서비스·데이터 요구 분석 → 공급자·SLA·보안 실사 → 테넌트·계정·SSO 설정 → 데이터 이전·통합·운영 → 계약종료·데이터 반출·삭제.

```text
서비스·데이터 요구 분석
  ↓
공급자·SLA·보안 실사
  ↓
테넌트·계정·SSO 설정
  ↓
데이터 이전·통합·운영
  ↓
계약종료·데이터 반출·삭제
```

- 핵심 구성 : 고객 사용자 → 인터넷/API → SaaS 애플리케이션

```text
고객 사용자 → 인터넷/API → SaaS 애플리케이션
공급자: 앱·런타임·인프라 운영
고객: 계정·설정·사용자·데이터 통제 일부
```

## Ⅳ. 비교: SaaS / 온프레미스 패키지 소프트웨어

- 핵심 요약 : 운영 책임 기준 — SaaS: 공급자가 앱·플랫폼 운영·업데이트; 온프레미스 패키지 소프트웨어: 고객이 설치·패치·인프라 운영.

| 비교 기준 | SaaS | 온프레미스 패키지 소프트웨어 |
| --- | --- | --- |
| 운영 책임 | 공급자가 앱·플랫폼 운영·업데이트 | 고객이 설치·패치·인프라 운영 |
| 비용 구조 | 구독·사용량·서비스 계약 | 라이선스·인프라·운영비 선투자 |
| 통제·이식성 | 공급자 변경·장애·데이터 반출 의존 | 내부 통제 가능하나 운영책임 증가 |

## Ⅴ. SaaS의 한계와 방안

- 핵심 요약 : 공급자 종속·종료·테넌트 격리 실패 등의 위험을 원인에 맞게 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 공급자 종속·종료 | 데이터 형식·API 종속으로 이관 곤란 | 반출 형식·삭제증명·전환지원·종료조건 계약 | 이관시험시간 |
| 테넌트 격리 실패 | 공유환경 오류가 타 고객 정보 노출 | 인증·권한·테넌트 경계 침투시험 | 격리 결함 |
| SLA·규제 불일치 | 장애·데이터 위치·하위처리자 정보 부족 | 가용성·통지·감사·위치·하위처리 조건 실사 | SLA 위반·감사결함 |

## Ⅵ. SaaS의 제언

- 핵심 요약 : 구매·보안 담당자는 계약 전 데이터 소유권·처리위치·하위처리자·사고통지·SLA·종료 시 반출과 삭제 증거를 검토.
- 실행 제안 : 구매·보안팀은 공급자 변경을 가정한 데이터 반출·계정 회수·삭제증명 시나리오를 계약 갱신 전에 확인.

## Ⅶ. SaaS의 결론

- 핵심 요약 : SaaS의 편의성은 공급자 위탁운영과 고객 통제의 경계를 바꾸며 위험·계약·출구전략을 동반.
- 시사점 : SaaS 도입은 기능 비교뿐 아니라 데이터 생애주기와 공급자 종료 시 업무연속성까지 계약·설계에 포함.
