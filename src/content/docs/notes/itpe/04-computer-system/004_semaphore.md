## 전체 로드맵 내 현재 위치

```text
[01 IT 전략] → [02 SW 공학] → [03 데이터] → [▶ 04 컴퓨터 시스템]
      → [05 네트워크] → [06 보안] → [07 최신기술] → [08 법규·정책]
```

과목 내 현재 키워드: 04 컴퓨터 시스템 → 세마포어

## 큰 그림과 30초 인출

```text
공유자원 동시 접근 → Race Condition
             │
             ▼
      [Semaphore S]
      wait(P) / signal(V)
       │              │
 S>0: 진입       자원 반납·깨움
 S=0: 대기큐 ─────────┘

Binary(0/1): 상호배제·신호
Counting(n): 동종 자원 n개 제한
```

- 본질: **원자적 카운터와 대기 큐로 공유자원 동시 사용량과 실행 순서를 통제**
- 구분: 뮤텍스는 소유권 기반 잠금, 세마포어는 허가증 개수·신호 기반 동기화
- 위험: wait/signal 순서 오류, signal 누락, 우선순위 역전, 공정성 부재

## 예상문제

> 운영체제 프로세스 동기화 기법인 세마포어의 구조와 동작 원리를 설명하고, 뮤텍스·모니터와 비교한 후 실무 고려사항을 제시하시오. (25점)

## Ⅰ. 원자적 허가증으로 임계구역을 통제하는 세마포어 개요

- 정의: **세마포어**는 정수 카운터와 원자적 `wait(P)`·`signal(V)` 연산으로 공유자원의 가용 수와 프로세스 실행 순서를 제어하는 동기화 기법
- 목적: 둘 이상의 실행 흐름이 공유 상태를 동시에 변경할 때 발생하는 경쟁상태를 방지하고, 한정 자원 접근 수를 제한
- 조건: 카운터 확인·변경과 대기·깨움 전환은 분리되지 않는 원자 연산이어야 함

## Ⅱ. 이진·카운팅과 블록-깨움의 특징

| 특징 | 메커니즘 | 활용 |
|---|---|---|
| **이진 세마포어** | 값이 0 또는 1 | 상호배제, 사건 통지 |
| **카운팅 세마포어** | 0 이상 자원 수 관리 | 연결 풀·버퍼 슬롯 제한 |
| **원자적 P/V** | 카운터 감소·증가를 불가분 실행 | 검사-변경 간 경쟁 방지 |
| **블록-깨움** | 허가증 부족 시 대기 큐, 반환 시 깨움 | 긴 대기에서 CPU 낭비 감소 |
| **비소유권** | 획득자와 해제자가 달라도 가능 | 실행 흐름 간 신호 전달 가능 |

## Ⅲ. 카운터·대기 큐·원자 연산의 구조

```text
                 +----------------------+
wait(P) ───────▶ | Semaphore            | ───────▶ 임계구역
                 | S: 가용 허가증 수    |
                 | Queue: 대기 프로세스 |
signal(V) ◀───── | atomic wait/signal   |
                 +----------┬-----------+
                            │ S 부족
                            ▼
                     [Blocked Queue]
```

| 구성요소 | 책임 |
|---|---|
| **카운터 S** | 현재 획득 가능한 허가증 수 표현 |
| **대기 큐** | 즉시 진입하지 못한 프로세스 보관 |
| **wait(P)** | 허가증 획득 또는 대기 상태 전환 |
| **signal(V)** | 허가증 반환 또는 대기 프로세스 깨움 |
| **원자성 보장 장치** | 하드웨어 원자 명령·커널 임계구역으로 연산 직렬화 |

## Ⅳ. wait에서 임계구역 진입·반납까지의 동작

```text
[Process wait(S)]
        │
        ├─ 허가증 있음 → S 감소 → 임계구역 실행
        │                              │
        │                              ▼
        │                         signal(S)
        │                              │
        └─ 허가증 없음 → 대기 큐 ──────┘
                               대기자 있으면 Wakeup
```

- 구현 정책에 따라 카운터의 음수 표현 여부와 깨울 대기자 선택 방식은 달라질 수 있으나, **원자적 획득·대기·반환** 의미는 동일
- 짧은 커널 임계구역은 스핀 방식, 긴 대기는 블록 방식이 유리하며 문맥교환 비용과 대기시간을 함께 판단

## Ⅴ. 세마포어·뮤텍스·모니터 비교

| 기준 | 세마포어 | 뮤텍스 | 모니터 |
|---|---|---|---|
| 추상화 | 카운터·신호 | 소유권 기반 잠금 | 공유상태와 조건변수의 캡슐화 |
| 동시 접근 수 | 이진 또는 N개 | 1개 | 모니터 진입 1개 |
| 소유권 | 없음 | 획득 스레드가 해제 | 언어·런타임이 진입 통제 |
| 순서 동기화 | 직접 가능 | 별도 조건변수 필요 | 조건변수로 제공 |
| 오류 위험 | P/V 누락·순서 오류 | 이중 해제·잠금 순서 | 상대적으로 낮으나 조건 사용 주의 |
| 선택 | 자원 수 제한·신호 | 단일 공유자원 보호 | 복잡한 공유상태를 고수준 캡슐화 |

## Ⅵ. 교착·기아·우선순위 역전의 통제방안

| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| **교착상태** | 여러 세마포어의 획득 순서 불일치 | 전역 잠금 순서, 타임아웃, 다중 획득 최소화 | 순환대기 차단 |
| **허가증 누수** | 예외 경로에서 signal 누락 | 구조적 정리 구문·스코프 가드 사용 | 모든 종료 경로에서 반환 |
| **기아** | 비공정 대기자 선택 | FIFO·공정 큐, 대기시간 모니터링 | 장기 대기 완화 |
| **우선순위 역전** | 저우선순위 보유자가 고우선순위 작업 차단 | 우선순위 상속·상한 프로토콜 | 실시간 마감 위반 방지 |
| **과도한 경합** | 임계구역이 크거나 공유 범위가 넓음 | 락 분할, 불변·메시지 전달 구조 | 대기시간·직렬화 감소 |

- 검증: 경쟁 탐지 도구, 부하·장시간 테스트, 잠금 대기시간·대기 큐 길이·타임아웃 건수를 함께 관찰
- 설계 원칙: 저수준 세마포어를 직접 흩어 쓰기보다 동시성 컬렉션·모니터·채널 등 의도가 드러나는 상위 추상화 우선

## Ⅶ. 동기화 정확성과 운영 관측성을 함께 확보하는 결론

- 세마포어는 단순 카운터가 아니라 **원자 연산·대기 큐·깨움 정책**이 결합된 동기화 통제점
- 자원 수 제한에는 카운팅 세마포어, 소유권 잠금에는 뮤텍스, 복합 상태에는 모니터를 선택하고 잠금 순서와 대기 지표를 운영 기준으로 관리해야 함

## 1교시 10점 답안 발췌

### 1. 정의

- 정수 카운터와 원자적 `wait(P)`·`signal(V)` 연산으로 공유자원 접근 수와 프로세스 실행 순서를 제어하는 동기화 기법

### 2. 동작

```text
wait(P): 허가증 있으면 감소·진입 / 없으면 Block
                         ↓
                     Critical Section
                         ↓
signal(V): 허가증 반환 / 대기자 Wakeup
```

### 3. 비교 핵심

| 세마포어 | 뮤텍스 | 모니터 |
|---|---|---|
| 비소유권·N개 허가증 | 소유권·단일 잠금 | 공유상태·조건변수 캡슐화 |
