## 연관 키워드

- SAN(Storage Area Network), FC-SAN, IP-SAN, iSCSI(Internet Small Computer Systems Interface)
- FC(Fibre Channel), 패브릭(Fabric), B2B 크레딧(Buffer-to-Buffer Credit)
- 조닝(Zoning), LUN 매스킹(LUN Masking), WWPN(World Wide Port Name), 이중 패브릭
- NVMe-oF(NVMe over Fabrics), 클러스터 파일시스템(Cluster File System)

## Ⅰ. SAN의 개요

- 핵심 요약 : **SAN** (Storage Area Network)은 서버와 스토리지를 잇는 스토리지 전용 고속 블록 전송 네트워크.
- 개념 : 다수의 서버와 고성능 스토리지가 블록 단위 데이터를 고속으로 주고받도록 범용 LAN(Local Area Network)과 분리하여 구축한 전용 전송망과 그 접근 통제 구조.
- 배경 및 필요성 : 업무 트래픽과 저장 트래픽의 공유에 따른 혼잡, DAS(Direct-Attached Storage)의 서버 종속성에 따른 공유 불가 문제의 동시 해소 필요.
- 주요 목적 : 무손실 블록 전송, LUN(Logical Unit Number)의 서버 간 공유를 통한 스토리지 통합, 미션 크리티컬 업무의 HA(High Availability)·DR(Disaster Recovery) 기반 확보.

## Ⅱ. SAN의 특징 및 장점

- 핵심 요약 : 무손실 흐름 제어와 이중화 경로, 2단계 접근 통제가 데이터 안정성과 보안으로 이어지는 구조.

1. **FC 패브릭** (Fibre Channel Fabric) 기반 무손실 전송 : 수신 버퍼 여유에 따라 송신을 허가하는 **B2B 크레딧** (Buffer-to-Buffer Credit) 흐름 제어 → 프레임 드롭과 재전송 부담의 원천 차단 효과.
2. **iSCSI** (Internet Small Computer Systems Interface) 기반 IP-SAN : 표준 이더넷 위에서 SCSI 블록 명령을 터널링 → 기존 네트워크 자산 활용의 도입 비용 절감 효과.
3. **조닝** (Zoning)과 **LUN 매스킹** (LUN Masking)의 2단계 접근 통제 : 패브릭 스위치의 WWPN(World Wide Port Name) 단위 격리와 어레이의 호스트별 LUN 매핑 → 노출 범위 최소화 효과.
4. **이중 패브릭** : 독립된 두 스위치 집합으로 경로 분리 → 한쪽 패브릭 장애 시에도 I/O 지속의 가용성 확보 효과.

## Ⅲ. SAN의 구조 (흐름)

- 핵심 요약 : 서버의 FC HBA에서 이중 패브릭 스위치를 거쳐 스토리지 어레이의 LUN까지 이어지는 무손실 블록 경로.
- **HBA** (Host Bus Adapter) : 서버에 장착되어 FC 패브릭에 접속하는 호스트 버스 어댑터.
- 스토리지 어레이 : 여러 디스크를 통합 관리하며 LUN 단위로 서버에 볼륨을 제공하는 장치.

```text
[ FC-SAN 데이터 경로 ]

서버 (FC HBA)
      ↓ 광케이블
FC 패브릭 A · B (이중 스위치 구성)
      ↓ 무손실 전송 (B2B 크레딧)
스토리지 어레이 (대상 포트)
      ↓ LUN 매핑
서버에 블록 볼륨 제공
```

```text
[ 2단계 접근 통제 흐름 ]

1단계 조닝 : 패브릭의 WWPN 그룹 격리
      ↓ 통과한 트래픽만
2단계 LUN 매스킹 : 어레이의 호스트별 매핑
      ↓
승인된 호스트의 LUN 접근만 허용
```

## Ⅳ. FC-SAN과 IP-SAN·NVMe-oF의 비교

- 핵심 요약 : FC-SAN의 무손실 안정성, IP-SAN의 경제성, NVMe-oF(NVMe over Fabrics)의 저지연이 각각 다른 요구에 대응하는 선택지.

| 비교 축 | FC-SAN | IP-SAN(iSCSI) | NVMe-oF |
| :--- | :--- | :--- | :--- |
| 전송 기반 | FC 전용 광 스위치 | 표준 이더넷 | RDMA(Remote Direct Memory Access) 지원 네트워크 |
| 프로토콜 | FCP(SCSI over FC) | SCSI over TCP/IP | NVMe over RDMA·TCP |
| 지연 특성 | 낮음, 무손실 | TCP 처리로 상대적으로 높음 | 매우 낮음 |
| 구축 비용 | 높음 | 낮음 | 중간 이상 |
| 적용 업무 | 코어뱅킹, 대형 DB 클러스터 | 중소 규모 가상화, 백업 | 플래시 풀, 분산 학습 |

- 선택 기준 :
  1. 검증된 무손실 안정성이 최우선이면 FC-SAN
  2. 기존 이더넷 자산의 활용이 전제이면 IP-SAN
  3. 플래시 성능의 극대화가 요구되면 NVMe-oF

## Ⅴ. SAN의 한계와 방안

- 핵심 요약 : 구축 비용과 패브릭 혼잡 전파, 블록 방식의 공유 한계를 전송 기술 전환, 혼잡 감지, 클러스터 파일시스템으로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| 구축 비용 부담 | FC 스위치·HBA·광케이블 단가와 전문 운영 역량의 요구 → 도입 장벽 상승 | 이더넷 자산 재사용이 가능한 IP-SAN·NVMe-oF로의 단계 전환 | 단위 성능당 인프라 비용 |
| **Slow Drain** 혼잡 전파 | 특정 포트 응답 지연의 크레딧 반환 지체 → 상위 버퍼 고갈이 패브릭 전체로 확산 | FPIN(Fabric Performance Impact Notification) 기반 혼잡 포트 감지와 격리 | 포트별 크레딧 대기 시간 |
| 파일 공유의 한계 | 블록 LUN의 다중 호스트 동시 마운트 시 파일시스템 정합성 훼손 위험 | 클러스터 파일시스템(GFS2·OCFS2·VMFS) 적용 | 메타데이터 정합성 점검 결과 |

## Ⅵ. SAN에 대한 기술사적 제언

- 핵심 요약 : 이더넷 기반 전송으로의 단계 전환 로드맵과 이중화·접근 통제의 상시 검증 체계가 필요.

1. 인프라 전략 조직은 FC 자산의 교체 주기에 맞춰 지연 요구가 큰 올플래시 업무부터 NVMe-oF로 옮기는 단계 전환 로드맵 수립.
2. 운영 조직은 한쪽 패브릭을 의도적으로 차단하고 절체를 확인하는 정기 검증 절차를 정기 정비 일정에 포함.
3. 보안 거버넌스 조직은 조닝·LUN 매스킹 설정 변경의 승인 흐름과 주기 감사 체계 운영.

## Ⅶ. 결론

- 핵심 요약 : SAN은 무손실 블록 전송과 LUN 공유, 이중 패브릭의 가용성으로 미션 크리티컬 업무를 지탱하는 스토리지 전용 네트워크.
- 시사점 : 전송 기술의 선택은 안정성·비용·성능 요구의 균형으로 결정되며, 업무별 지연 요구가 기준이 됨.
