## 연관 키워드

- 백필(Backfill), 배치 스케줄러(Batch Scheduler), 예약 시각(Reservation), 월타임(Walltime)
- 자원 단편화(Fragmentation), EASY 백필(EASY Backfill), 보수적 백필(Conservative Backfill)
- 기아(Starvation), 노화(Aging), 대기 큐(Queue), 클러스터 활용률(Utilization)

## Ⅰ. 백필의 개요

- 핵심 요약 : **백필** (Backfill)은 선두 대형 작업의 시작을 지연시키지 않는 조건에서 유휴 노드에 소형 작업을 끼워 넣는 배치 스케줄링 기법.
- 개념 : **배치 스케줄러** (Batch Scheduler)가 우선순위 순서대로 자원을 배치할 때 남는 유휴 자원을 채우는 보조 스케줄링 수단. 선두 작업의 **예약 시각** (Reservation)을 미리 계산해 두고, 그 예약을 침범하지 않는 작업만 즉시 실행.
- 배경 및 필요성 : HPC(High-Performance Computing) 클러스터는 작업이 요구하는 노드를 통째로 확보해야 시작하므로, 대형 작업의 대기 동안 작은 유휴 자원 블록이 남는 **자원 단편화** (Fragmentation)와 활용률 저하가 발생함.
- 주요 목적 : 대형 작업의 대기 순서를 지키면서 클러스터 활용률과 작업 처리량을 동시에 높이는 것.

## Ⅱ. 백필의 특징 및 장점

- 핵심 요약 : 예약 기반 판정과 월타임 선언이 결합되어 활용률 향상과 선두 작업 보호를 동시에 달성하는 구조.

1. 예약 기반 판정(Reservation-Based Decision) : 선두 작업의 시작 가능 시각을 자원 수급 조건으로 미리 계산 → 백필 승인의 판정 근거 확보 효과.
2. **월타임** (Walltime, 사용자가 선언하는 작업의 최대 실행 시간) 기반 판정 : 선언된 실행 시간으로 후보 작업이 예약 전에 끝나는지 추정 → 예약 침범 없이 유휴 자원을 채우는 활용률 향상 효과.
3. 선두 작업 보호(Head-of-Queue Protection) : 승인 조건에 선두 작업의 예약 시각 불변을 포함 → 순서 역전 상황에서도 공정성을 지키는 신뢰 효과.
4. 대기 큐 순회(Queue Scan) : 백필 단계에서 대기 큐를 순회하며 끼워 넣을 작업을 선별 → 순서 배치만 쓸 때보다 처리량이 증가하는 효과.

## Ⅲ. 백필의 구조 (흐름)

- 핵심 요약 : 메인 스케줄링이 순서대로 자원을 배치하고 남는 공간에서 백필 단계가 큐를 순회해 작업을 채우는 2단계 구조.
- 정책 유형 : 최선두 작업 하나의 예약만 보장하는 **EASY 백필** (EASY, Extensible Argonne Scheduling System)과 대기 중 전체 작업의 예약을 보장하는 **보수적 백필** (Conservative Backfill)이 대표적임.

```text
[ 배치 스케줄러의 2단계 흐름 ]

작업 제출 → 대기 큐 등록
      ↓
메인 스케줄링 (우선순위 순 배치)
      ↓
배치 실패 작업의 예약 시각 계산
      ↓
백필 단계 (대기 큐 순회)
      ↓
예약을 침범하지 않는 작업 즉시 실행
```

```text
[ 백필 승인 판정 흐름 ]

후보 작업의 종료 예상 시각 산출
      ↓
선두 작업의 예약 시각과 비교
      ↓
예약 전 종료 → 승인과 자원 할당
      ↓
예약 침범 → 대기 큐로 복귀
```

- 구성요소 : 대기 큐, 자원 가용 관리자, 예약 계산기, 백필 정책 플러그인의 네 요소로 구성되며, SLURM(Simple Linux Utility for Resource Management)은 sched/backfill 플러그인 형태로 정책을 분리해 제공함.

## Ⅳ. EASY 백필과 보수적 백필의 비교

- 핵심 요약 : 예약을 보장하는 작업 범위에 따라 활용률과 대기 공정성이 반대 방향으로 움직임.

| 비교 항목 | 백필 없음 (순서 배치만) | EASY 백필 | 보수적 백필 |
| --- | --- | --- | --- |
| 예약 보장 범위 | 예약 개념 없음 | 최선두 작업 하나만 보장 | 대기 중 전체 작업 보장 |
| 백필 기회 | 없음 | 많음 | 적음 |
| 클러스터 활용률 | 낮음 | 높음 | 중간 수준 |
| **기아** (Starvation) 위험 | 낮음 | 후순위 장시간 작업에 존재 | 낮음 |
| 구현·운영 복잡도 | 단순 | 단순한 편 | 예약 목록 관리 필요 |

- 선택 기준 : 활용률 극대화가 우선이면 EASY 백필, 대기 순서의 공정성이 서비스 요건이면 보수적 백필을 채택하고, 두 정책의 운영 지표를 주기적으로 비교해 조정.

## Ⅴ. 백필의 한계와 방안

- 핵심 요약 : 월타임 과소 선언, 노드 수 단편화, 후순위 작업 기아를 선언 정책, 가변 자원, 노화 정책으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 월타임 과소 선언 | 승인을 위해 실행 시간을 짧게 신고 → 실제 초과 시 강제 종료와 예약 신뢰도 훼손 | 선언 상한 정책과 초과 시 강제 종료 타임아웃 적용, 과거 실측 시간 기반의 기본값 제공 | 강제 종료 건수, 선언 대비 실측 비율 |
| 노드 수 단편화 | 요구 노드 수가 작은 작업만 백필 통과 → 대형 작업의 대기 시간 편차 확대 | 가변 노드 수 작업 허용, 노드 수 구간별 대기 시간 모니터링 | 구간별 평균 대기 시간 |
| 후순위 작업 기아 | EASY 백필에서 장시간 대형 작업이 예약 침범으로 반복 밀림 | 대기 시간에 따라 우선순위를 높이는 **노화** (Aging) 정책과 최대 대기 상한 운영 | 최대 대기 시간 |

## Ⅵ. 백필에 대한 기술사적 제언

- 핵심 요약 : 정책 거버넌스, 지표 체계, 서비스 합의의 세 축으로 백필을 클러스터 운영 표준으로 내재화할 필요.
- 정책 거버넌스 : 인프라 운영 조직이 백필 정책과 우선순위 가중치를 정기 검토하는 스케줄링 정책 협의체를 운영.
- 지표 체계 : 운영 자동화 조직이 활용률, 예약 지연 시간, 백필 승인률을 대시보드로 상시 수집해 정책 조정의 근거로 사용.
- 서비스 합의 : 서비스 운영 조직이 작업 유형별 목표 대기 시간을 SLA(Service Level Agreement)로 정의하고 이용자에게 공개.

## Ⅶ. 결론

- 핵심 요약 : 백필은 예약 시각을 지키는 조건 아래 유휴 자원을 채우는 배치 스케줄링의 표준 보조 기법임.
- 시사점 : 월타임 선언의 신뢰와 기아 통제가 함께 전제될 때 활용률과 공정성이 동시에 확보됨.
