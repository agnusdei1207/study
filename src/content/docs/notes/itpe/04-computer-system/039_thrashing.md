## 연관 키워드

- 스래싱(Thrashing), 다중 프로그래밍 정도(DoM, Degree of Multiprogramming), 페이지 부재(Page Fault)
- CPU 이용률, 스와핑(Swapping), 지역성(Locality)
- 워킹셋(Working Set), PFF(Page Fault Frequency), 중기 스케줄러(Medium-Term Scheduler)

## Ⅰ. 스래싱의 개요

- 핵심 요약 : **스래싱** (Thrashing)은 다중 프로그래밍 정도의 과다 투입으로 페이지 교체 작업이 유효 연산보다 많아지는 가상 메모리 이론의 비정상 상태.
- 개념 : **다중 프로그래밍 정도** (DoM, Degree of Multiprogramming)가 메모리 수용 능력을 넘으면 프로세스당 할당 프레임이 참조 집합을 담지 못해 **페이지 부재** (Page Fault)가 빈번해지고, 부재 처리 시간이 유효 처리 시간을 초과하는 상태.
- 배경 및 필요성 : 요구 페이징 환경에서 CPU (Central Processing Unit) 이용률이 낮으면 프로세스를 추가 투입하는 정책이 일반적이며, 이 정책이 메모리 포화와 만나면 이용률이 오히려 급락하는 역설의 설명 필요.
- 주요 목적 : 스래싱 유발 임계점의 이론적 규명, 적정 다중 프로그래밍 정도의 산출 근거 확보, 프로세스별 최소 프레임 보장 원리의 정립.

## Ⅱ. 스래싱의 특징 및 장점

- 핵심 요약 : 프레임 부족이 지역성 붕괴와 부재 폭증, 스와핑 병목, 이용률 하락의 연쇄로 이어지는 구조가 이론적 특징.

1. 임계점의 존재 : DoM이 커질수록 CPU 이용률이 상승하다가 메모리 포화 지점을 넘으면 급락하는 관계 → 적정 투입 수준의 이론적 근거 제공.
2. 지역성 붕괴 : **지역성** (Locality)으로 정의되는 실행 중 참조 집합이 프레임 부족으로 메모리에 유지되지 못함 → 부재가 예외적 사건에서 일상적 사건으로 전환되는 악화 효과.
3. 부재 처리의 지배 : 페이지 인·아웃의 **스와핑** (Swapping) 시간이 프로세서 연산 시간을 압도 → 시스템 처리량의 붕괴 효과.
4. 피드백 악순환 : 이용률 하락을 프로세스 부족으로 해석해 투입을 늘리는 정책이 부족을 심화 → 자원 관리 정책 설계의 교훈 효과.

## Ⅲ. 스래싱의 구조 (흐름)

- 핵심 요약 : DoM 증가, 프레임 부족, 부재 폭증, 이용률 하락, 추가 투입의 폐쇄 루프가 스래싱의 이론적 구조.

```text
[ 스래싱의 악순환 루프 ]

DoM의 과도한 증가
   ↓
프로세스당 프레임 부족
   ↓
페이지 부재의 급증
   ↓
스와핑 트래픽의 포화
   ↓
CPU 이용률의 급락
   ↓
투입 프로세스 추가 (루프 반복)
```

```text
[ CPU 이용률과 DoM의 관계 ]

CPU 이용률
    ↑
    |         * 임계점
    |      *     *
    |    *         *
    |  *             *
    +------------------→ DoM
     정상 구역    스래싱 구역
```

- 구성요소 : 참조 스트림, 프레임 할당 정책, 페이지 교체 정책, 부재율의 네 요소로 스래싱 분석 체계 구성.
- **워킹셋** (Working Set) 모델 : 시간 윈도우 안에 참조된 페이지 집합을 프로세스 실행의 최소 상주 요건으로 정의하는 이론 모델 → 워킹셋 합이 물리 프레임을 초과하는 순간이 스래싱 진입 판정 기준.
- **PFF** (Page Fault Frequency) 제어 : 부재율의 상·하한 임계치로 프레임을 증감하는 피드백 제어 이론 → 부재율 관점의 스래싱 억제 기준 제공.

## Ⅳ. 워킹셋 모델과 PFF 기법의 비교

- 핵심 요약 : 워킹셋은 지역성 가정의 사전 보장 이론, PFF는 부재 관측의 사후 교정 이론으로 제어 시점과 근거가 구분됨.

| 비교 항목 | 워킹셋 모델 | PFF 기법 |
| --- | --- | --- |
| 이론 기반 | 지역성에 따른 참조 집합 가정 | 부재 발생 간격의 관측 |
| 제어 방식 | 최소 상주 집합의 사전 보장 | 임계치 대비 사후 증감 |
| 판정 정보 | 참조 윈도우의 페이지 수 | 부재율의 상·하한 |
| 장점 | 스래싱 진입 전 차단의 이론적 근거 | 구현이 단순하고 오버헤드가 낮음 |
| 한계 | 윈도우 크기 산정과 추적 비용 | 부재 발생 후 대응하는 시차 |

- 선택 기준 : 지역성 정보의 신뢰도와 구현 비용, 대응 시차의 허용 범위에 따라 이론 모델과 피드백 기법을 선택.

## Ⅴ. 스래싱의 한계와 방안

- 핵심 요약 : 윈도우 산정의 어려움, 투입 제어 수단의 부재, 부재율 편차의 미반영을 근사 알고리즘, 중기 스케줄러, 차등 할당으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 워킹셋 윈도우 산정의 어려움 | 윈도우 과대 시 메모리 낭비, 과소 시 집합 절단 → 부재 재증가 | 참조 비트 기반 근사 알고리즘 적용, 윈도우의 주기적 재조정 | 부재율, 회수 프레임 수 |
| DoM 제어 수단의 부재 | 이용률 하락 대응이 투입 확대로 고정 → 악순환 지속 | **중기 스케줄러** (Medium-Term Scheduler, 투입 프로세스 수를 조절하는 스케줄러)가 과잉 프로세스를 스와핑 아웃해 투입 수준 조절 | 투입 프로세스 수, 스와핑량 |
| 부재율 편차의 미반영 | 프로세스별 지역성 차이를 균등 할당이 무시 → 특정 프로세스 집중 부재 | 워킹셋·PFF 피드백의 결합으로 프로세스별 차등 할당 | 프로세스별 부재율 편차 |

## Ⅵ. 스래싱에 대한 기술사적 제언

- 핵심 요약 : 이용률 단독 판단의 지양, 프레임 할당 정책의 이론 반영, 임계점의 실증 축적을 설계 원칙으로 제안.

1. 운영체제 설계 조직이 CPU 이용률과 부재율을 동시 관측 조건으로 두어, 이용률 하락 시 투입 확대가 아닌 DoM 조절을 기본 대응으로 정책화.
2. 시스템 소프트웨어 개발 조직이 워킹셋 근사와 부재율 임계치를 결합한 프레임 할당 정책을 스케줄러 설계 표준에 반영.
3. 시험·검증 조직이 다양한 워크로드의 참조 패턴 시험으로 임계점 산출 근거를 축적해 이론 모델의 실증 기반 확보.

## Ⅶ. 결론

- 핵심 요약 : 스래싱은 다중 프로그래밍 정도와 메모리 수용 능력의 불균형에서 생기는 이론적 마비 상태.
- 시사점 : 부재율과 이용률의 관계 규명이 적정 투입 수준 결정의 이론적 토대가 되는 구조.
