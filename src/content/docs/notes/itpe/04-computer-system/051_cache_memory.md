## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 캐시 메모리

## 30초 인출

- 본질: 초고속 CPU에 비해 느린 DRAM 접근 지연(수백 사이클)으로 인한 성능 병목
- 메커니즘: 참조 국소성(Locality)에 기반해 최근 접근 및 인접 데이터를 고속 SRAM 블록 단위로 복제 유지

## 핵심 용어

- AMAT(Average Memory Access Time): 평균 메모리 접근 시간 = $Hit\_Time + (Miss\_Rate \times Miss\_Penalty)$
- 캐시 라인(Cache Line): 캐시와 주기억장치 간에 한 번에 전송되는 데이터의 기본 전송 단위(통상 64바이트)
- False Sharing(거짓 공유): 서로 다른 CPU 코어가 동일한 캐시 라인에 위치한 서로 다른 변수를 갱신할 때 불필요한 캐시 무효화와 버스 트래픽이 폭증하는 현상

### Ⅱ. 핵심 특성

- 캐시는 물리적 크기가 커질수록 느려짐 → L1 캐시를 32KB~64KB 수준으로 극도로 작게 유지하는 이유는 1사이클 내에 주소 디코딩과 신호 전파를 완료하기 위한 물리적 제약 때문임
- 캐시는 '국소성(Locality)'이 존재할 때만 승리함 → 배열 순회(순차 접근)는 공간적 국소성이 100%여서 L1 캐시 적중률이 99%에 달하지만, 무작위 링크드 리스트 순회는 매번 DRAM을 찔러 캐시 계층 전체가 무용지물이 됨
- 쓰기 정책(Write Policy)은 신뢰성과 성능의 교환임 → Write-Through는 DRAM에 즉시 반영하여 일관성이 높지만 쓰기 지연이 크고, Write-Back은 캐시에만 쓰고 나중에 내보내어 빠르지만 전원 차단 시 데이터 유실 위험이 있음

### Ⅲ. 관련 개념과 구분

- 직접 매핑 vs 세트 연관 매핑: 직접 매핑 = 주소마다 들어갈 세트가 오직 1개로 하드웨어가 단순하고 빠르나 충돌 미스 빈발 / 세트 연관 매핑 = n개의 슬롯을 제공하여 충돌을 대폭 완화하되 비교기 증가로 복잡도 상승

### Ⅳ. 적용 문제와 대응

- 사례: 137회 기출 및 멀티스레드 고빈도 거래(HFT) 엔진에서 멀티코어 성능 저하 장애
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 멀티스레드 환경에서 CPU 코어 수 증가 시 처리량이 오히려 급감 | 서로 다른 스레드가 독립 변수를 쓰지만 두 변수가 같은 64B 캐시 라인에 인접(False Sharing) | 변수 간 64바이트 캐시 라인 정렬(Align) 패딩(`alignas(64)`) 적용 | 코어 간 캐시 라인 무효화 간섭 원천 차단 |
| 대규모 배열 순회 시 캐시 미스 폭증으로 CPU 연산 유휴(Stall) 발생 | 행 우선(Row-Major) 언어(C/C++)에서 열 우선(Column) 순서로 메모리 비순차 접근 | 루프 타일링(Loop Tiling) 및 순차적 메모리 레이아웃(SoA: Struct of Arrays) 채택 | 공간적 국소성 극대화로 하드웨어 프리페처(Prefetcher) 적중 유도 |
