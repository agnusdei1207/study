## 연관 키워드

- VDI(Virtual Desktop Infrastructure), 씬 클라이언트(Thin Client), 접속 브로커(Connection Broker)
- 골든 이미지(Golden Image), 인스턴트 클론(Instant Clone), 전용 풀과 유동 풀
- 원격 디스플레이 프로토콜, 부트 스톰(Boot Storm), 입력 랙(Input Lag), vGPU
- DaaS(Desktop as a Service), TCO(Total Cost of Ownership), 망분리, 제로 트러스트(Zero Trust)

## Ⅰ. VDI의 개요

- 핵심 요약 : **VDI** (Virtual Desktop Infrastructure)는 데스크톱 환경을 중앙 데이터센터의 가상머신에서 실행하고 씬 클라이언트 등으로 접속하게 하는 엔드포인트 가상화 기술.
- 개념 : 사용자의 운영체제, 애플리케이션, 데이터를 개인 PC (Personal Computer)가 아닌 중앙 데이터센터의 하이퍼바이저 가상머신(VM, Virtual Machine)에서 호스팅하고, 사용자는 **씬 클라이언트** (Thin Client)나 모바일 기기에서 화면 전송 프로토콜로 접속하는 인프라.
- 배경 및 필요성 : 단말 PC를 통한 기업 데이터 유출, 재택근무 확산에 따른 원격 업무 보안 요구, 다수 PC의 유지보수 비용 부담이 겹치면서 도입 증가. 망분리 규제를 지켜야 하는 조직에서는 데이터가 단말에 남지 않는 구조 필요.
- 주요 목적 : 데이터를 중앙에 두어 유출 경로를 줄이고, 재택 및 스마트워크 환경을 구현하며, 데스크톱 배포와 운영체제 패치 관리를 단순화.

## Ⅱ. VDI의 특징 및 장점

- 핵심 요약 : 접속 브로커, 골든 이미지, 인스턴트 클론, 원격 프로토콜이 맞물려 중앙에서 많은 데스크톱을 일관되게 관리.

1. **접속 브로커** (Connection Broker) : 사용자 인증과 권한을 확인하고 유휴 데스크톱 풀에서 VM을 골라 세션을 연결 → 사용자와 가상 데스크톱의 매핑을 중앙에서 통제.
2. **골든 이미지** (Golden Image) : 표준 운영체제 (OS, Operating System), 보안 소프트웨어, 공통 업무 앱을 담은 마스터 이미지를 원본으로 삼아 VM을 복제 → 환경을 하나로 맞춰 패치와 점검 범위를 단순화.
3. **인스턴트 클론** (Instant Clone) : 마스터 VM의 메모리와 디스크 상태를 공유해 부팅 과정을 생략하고 신규 데스크톱을 빠르게 배포 → 대규모 증설과 초기화 시간을 줄임.
4. 원격 디스플레이 프로토콜 : PCoIP, VMware Blast, Citrix HDX 같은 방식이 화면 변화량만 압축해 전송 → 저대역 환경에서도 데스크톱 사용 가능.
5. 전용 풀과 유동 풀 : 사용자 전용 VM을 고정하거나, 로그아웃 시 초기화되는 VM을 여러 사용자가 돌려 씀 → 보안 수준과 자원 활용도 사이에서 선택.

## Ⅲ. VDI의 구조 및 동작 메커니즘

- 핵심 요약 : 씬 클라이언트에서 접속 브로커를 거쳐 VM 풀에 연결되고, 프로파일 저장소와 디스플레이 프로토콜이 세션을 뒷받침.

```text
[ VDI 접속 흐름 ]

사용자 단말 (씬 클라이언트·노트북)
   ↓ 암호화된 접속 게이트웨이 경유
접속 브로커 : 인증, 권한 확인, VM 배정
   ↓
가상 데스크톱 풀 (하이퍼바이저 클러스터)
   ↓
원격 디스플레이 프로토콜로 화면 전송
```

```text
[ 골든 이미지와 VM 풀 ]

골든 이미지 (OS + 공통 앱)
   ↓ 인스턴트 클론 또는 링크드 클론
사용자별 VM 1, VM 2, VM 3 ...
   ↓
개인 설정·문서 (프로파일) 별도 동기화
```

- 구성 : 접속 브로커, 가상 데스크톱 풀, 원격 디스플레이 프로토콜, 사용자 프로파일 관리 계층으로 나뉨.

## Ⅳ. VDI의 비교

- 핵심 요약 : 물리 PC, VDI, DaaS (Desktop as a Service)는 컴퓨팅 위치와 투자 구조가 달라 보안, 비용, 네트워크 의존도의 균형이 달라짐.

| 비교 항목 | 전통적 물리 PC | VDI | DaaS (Desktop as a Service) |
| --- | --- | --- | --- |
| 컴퓨팅 위치 | 사용자 책상의 로컬 PC | 자체 데이터센터 하이퍼바이저 | 클라우드 서비스 제공자의 인프라 |
| 데이터 보안 | 로컬 저장으로 유출 위험 | 중앙 저장으로 외부 반출 통제 | 중앙 클라우드 집중 관리 |
| 초기 투자 | PC 구매 비용이 분산 | 서버, 스토리지, 라이선스로 초기 부담 큼 | 초기 투자 부담이 낮고 구독형 비용 중심 |
| 운영 주체 | 현장 방문 중심 유지보수 | 사내 전산팀이 서버와 하이퍼바이저 관리 | 제공자가 인프라를 담당 |
| 네트워크 의존 | 오프라인에서도 동작 | 단절 시 접속 불가 | 단절 시 접속 불가 |

- 선택 기준 : 데이터의 외부 반출 규제 수준, 자체 인프라 운영 역량, 네트워크 품질에 따라 온프레미스 VDI와 DaaS 중 하나를 고름.

## Ⅴ. VDI의 한계와 방안

- 핵심 요약 : 동시 부팅 병목, 원격 입력 지연, 누적 TCO를 스토리지 고속화, GPU 가상화, 구독형 전환으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 부트 스톰 (Boot Storm) | 출근 시각에 다수 사용자가 동시에 부팅·로그인하여 스토리지 읽기 I/O 폭증 | 올플래시 NVMe (Non-Volatile Memory Express) 스토리지 도입, 인스턴트 클론 사전 워밍업, 접속 시각 분산 정책 | 동시 로그인 피크 시 응답 시간, 스토리지 읽기 지연 |
| 입력 랙 (Input Lag) | 원격 전송 지연으로 마우스 반응이 늦고 고화질 영상이 끊김 | vGPU (Virtual GPU) 가상화로 그래픽 처리를 하드웨어에서 수행, 네트워크 상태에 따라 전송 방식을 조절하는 적응형 프로토콜 사용 | 입력 지연 시간, 프레임 손실률 |
| 누적 TCO (Total Cost of Ownership) 부담 | 서버, 스토리지, 하이퍼바이저, 소프트웨어 라이선스 비용이 PC 대비 경제성을 떨어뜨림 | DaaS 구독형 전환, 라이선스 부담이 낮은 리눅스 기반 VDI 또는 세션 기반 SBC (Server-Based Computing) 혼용 | 데스크톱 1대당 연간 비용 |

## Ⅵ. VDI에 대한 기술사적 제언

- 핵심 요약 : 접근 통제를 단말 상태 검증과 조건부 인증으로 옮기고, 망분리 정책과 맞춰 VDI를 고도화하는 방향이 적절.

1. 보안 조직이 단말 상태 검증 (Posture Check)과 다중 인증을 결합한 조건부 접근을 제로 트러스트 원칙에 따라 적용하여, 내부망에 있어도 접속 권한을 매번 확인.
2. 정보보호 조직이 망분리 규제의 변화에 맞춰 망연계 구간의 감사 통제를 강화하고, 논리적 망분리 구조를 VDI 설계의 기준으로 정리.
3. 인프라 조직이 CAD (Computer-Aided Design)나 인공지능(AI, Artificial Intelligence) 개발처럼 그래픽과 연산 자원이 많이 필요한 업무에 vGPU 기반 가상 워크스테이션을 표준으로 제공.

## Ⅶ. 결론

- 핵심 요약 : VDI는 데스크톱을 중앙 VM에서 실행해 데이터 유출을 줄이고 관리 효율을 높이는 엔드포인트 가상화 인프라.
- 시사점 : 부트 스톰, 입력 지연, 누적 비용은 구조적으로 따라오는 과제이므로, 도입 시점부터 스토리지와 네트워크 용량 계획과 DaaS 전환 경로를 함께 설계할 필요.
