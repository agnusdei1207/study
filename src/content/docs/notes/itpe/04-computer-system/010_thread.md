## 연관 키워드

- 스레드(Thread), 프로세스(Process), 경량 프로세스(LWP, Lightweight Process), 문맥 교환(Context Switching)
- 스레드 제어 블록(TCB, Thread Control Block), 매핑 모델(1:1, M:1, M:N), 코루틴(Coroutine), 가상 스레드(Virtual Thread)
- 경쟁 상태(Race Condition), 임계 구역(Critical Section), 교착상태(Deadlock), 뮤텍스(Mutex), 세마포어(Semaphore), 스레드 풀(Thread Pool)

## Ⅰ. 스레드의 개요

- 핵심 요약 : **스레드**는 프로세스 내 실행 흐름의 최소 단위로, 자원을 공유하며 병렬 처리량을 높이는 경량 실행 단위.
- 개념 : 하나의 **프로세스** (Process) 안에서 독립적으로 실행되는 흐름의 최소 단위로, 코드·데이터·힙 같은 주소 공간을 같은 프로세스의 다른 스레드와 공유하고 레지스터 집합과 스택만 독립적으로 가지는 실행 단위 (스레드, Thread). 같은 개념을 경량 프로세스(LWP, Lightweight Process)라고도 부름.
- 배경 및 필요성 : 프로세스는 독립된 주소 공간을 가지므로 생성 비용이 크고 주소 공간 교체로 인한 전환 비용이 높으며, 프로세스 간 통신(IPC, Inter-Process Communication)도 번거로움. 멀티코어의 병렬성을 저비용으로 활용하기 위해 스레드가 도입됨.
- 주요 목적 : 생성과 스케줄링 오버헤드 축소, 메모리 공유를 통한 빠른 데이터 교환, 멀티코어 하드웨어의 병렬 처리량 극대화.

## Ⅱ. 스레드의 특징 및 장점

- 핵심 요약 : 자원 공유, 독립 실행, 경량 문맥 교환이 결합되어 병렬 처리의 비용을 낮추는 구조.

1. 자원 공유 : 같은 프로세스의 스레드는 코드, 데이터, 힙, 열린 파일 등을 공유 → 메모리 중복 할당을 피하고 데이터를 바로 참조.
2. 독립 실행 : 스레드마다 프로그램 카운터, 레지스터 집합, 스택을 가짐 → 각 스레드가 독립된 함수 호출 흐름을 추적하며 실행.
3. 경량 문맥 교환 : 같은 프로세스 내 전환에서는 주소 공간을 바꾸지 않아 전환 비용이 낮음 → 잦은 전환이 있어도 CPU(Central Processing Unit) 효율 유지.

## Ⅲ. 스레드의 구조 및 동작 메커니즘

- 핵심 요약 : 공유 영역과 스레드별 독립 영역을 구분하고, 커널 스레드와 사용자 스레드의 매핑 모델에 따라 동작이 달라지는 구조.
- **스레드 제어 블록** (TCB, Thread Control Block) : 스레드의 상태, 우선순위, 레지스터 값 등을 보관하는 스레드별 관리 정보.
- 매핑 모델 : 사용자 스레드와 커널 스레드를 대응시키는 방식으로, 1:1, M:1, M:N 모델로 나뉨.
- 1:1 모델은 사용자 스레드 하나가 커널 스레드 하나에 대응하여 커널이 직접 스케줄링하고, Linux의 pthread가 대표적임.
- M:1 모델은 여러 사용자 스레드를 커널 스레드 하나가 묶어 실행하는 방식으로, 그린 스레드(Green Thread)가 대표적임.
- M:N 모델은 다수의 사용자 스레드를 여러 커널 스레드에 분배하며, Go 고루틴과 **가상 스레드**(Virtual Thread)가 이 방식에 속함.

```text
[ 프로세스 내 스레드 구조 ]

프로세스 주소 공간 (공유 영역)
  코드 · 데이터 · 힙 · 열린 파일
   ↓ 각 스레드가 접근
스레드 1 / 스레드 2 / 스레드 3
  (각자 프로그램 카운터·레지스터·스택·TCB)
   ↓ 커널 스케줄링
CPU 코어 0 / 코어 1 / 코어 2
```

```text
[ 매핑 모델 ]

1:1   사용자 스레드 1개 ↔ 커널 스레드 1개
M:1   사용자 스레드 여러 개 ↔ 커널 스레드 1개
M:N   사용자 스레드 여러 개 ↔ 커널 스레드 여러 개
```

## Ⅳ. 스레드의 비교

- 핵심 요약 : 프로세스, 스레드, 코루틴은 메모리 공간, 문맥 교환 비용, 통신 방식, 장애 파급 범위에서 차이가 남.

| 비교 항목 | 프로세스 (Process) | 스레드 (Thread) | 코루틴 / 가상 스레드 |
| --- | --- | --- | --- |
| 정의 | 운영체제(OS, Operating System) 자원 할당의 기본 단위 | CPU 스케줄링과 실행의 최소 단위 | 사용자 공간에서 스케줄링되는 경량 실행 단위 |
| 메모리 공간 | 독립된 주소 공간 | 프로세스 주소 공간을 공유, 스택만 독립 | 사용자 힙에 스택 프레임을 동적 할당 |
| 문맥 교환 비용 | 큼, 주소 공간과 페이지 테이블 교체 | 작음, 레지스터와 스택 포인터 교체 | 매우 작음, 커널 진입 없이 전환 |
| 통신 방식 | IPC(파이프, 소켓, 공유 메모리) | 전역 변수와 힙을 직접 참조 | 채널 또는 메모리 직접 참조 |
| 장애 파급 | 한 프로세스의 장애가 다른 프로세스에 영향 없음 | 한 스레드의 메모리 오염이 프로세스 전체에 영향 | 애플리케이션 수준에서 예외 전파 제어 가능 |

## Ⅴ. 스레드의 한계와 방안

- 핵심 요약 : 경쟁 상태, 스레드 폭증, 교착상태와 우선순위 역전을 동기화, 풀, 타임아웃 설계로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **경쟁 상태** (Race Condition) | 여러 스레드가 임계 구역에 동기화 없이 접근해 데이터 불일치 발생 | 뮤텍스, 세마포어, CAS(Compare-And-Swap) 기반 원자적 연산, 락 프리 자료구조 | 락 경합률, 데이터 불일치 검출 건수 |
| 스레드 폭증 | 요청당 스레드 모델에서 동시 접속이 늘면 스택 메모리 고갈과 스케줄링 부하 발생 | 스레드 풀 적용, 비동기 논블로킹 입출력(I/O, Input/Output), 가상 스레드 도입 | 활성 스레드 수, 메모리 사용량 |
| **교착상태** (Deadlock)와 우선순위 역전 | 복수 락의 교차 획득, 실시간 스케줄링에서 낮은 우선순위 스레드가 높은 스레드를 막아 영구 대기 발생 | 락 획득 순서 규칙, 타임아웃 락, 우선순위 상속 프로토콜 | 락 대기 시간, 타임아웃 발생 건수 |

## Ⅵ. 스레드의 적용 제언

- 핵심 요약 : 가상 스레드 전환, 공유 상태 축소, 풀 사이징을 함께 적용해 동시성 효율을 높이는 방향.

- I/O 대기가 많은 서버는 고정 크기 스레드 풀을 무조건 키우기보다, 가상 스레드나 비동기 논블로킹 I/O를 검토하는 것이 적절함. 가상 스레드는 런타임의 지원 여부를 먼저 확인한 뒤 점진적으로 도입하는 것이 안전함.
- 공유 상태를 줄이는 것이 근본 대책이므로 불변 객체(Immutability) 설계를 기본 원칙으로 삼고, 동기화가 꼭 필요한 구간만 락으로 좁히는 것이 바람직함.
- 풀 크기는 CPU 집약 작업과 I/O 집약 작업을 나누어 산정하고, 실제 대기 시간과 처리 시간을 측정해 조정하는 방식이 실효성이 높음.

## Ⅶ. 결론

- 핵심 요약 : 스레드는 프로세스 자원을 공유하는 경량 실행 단위로 병렬 처리 효율을 높이지만, 공유 상태가 낳는 동기화 위험을 함께 관리해야 함.
- 동기화 설계가 병렬성의 이득을 실제 성능으로 바꾸는 조건이므로, 공유 범위를 최소화하고 풀과 가상 스레드로 자원 폭증을 억제하는 것이 핵심임.
