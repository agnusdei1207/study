## 연관 키워드

- 스레드(Thread), 프로세스(Process), 문맥 교환(Context Switching), 스레드 제어 블록(TCB, Thread Control Block)
- 매핑 모델(1:1, M:1, M:N), 코루틴(Coroutine), 가상 스레드(Virtual Thread), 스레드 풀(Thread Pool)
- 경쟁 상태(Race Condition), 임계 구역(Critical Section), 교착상태(Deadlock), 뮤텍스(Mutex), 세마포어(Semaphore), 암달의 법칙(Amdahl's Law)

## Ⅰ. 스레드의 개요

- 핵심 요약 : 프로세스 내부의 자원을 공유하며 독립 실행되는 최소 실행 단위로, 병렬 처리의 비용을 낮추는 체계.
- 개념 : **스레드** (Thread)는 하나의 **프로세스** (Process) 안에서 독립적으로 실행되는 실행 흐름의 최소 단위. 같은 프로세스의 스레드들은 코드, 데이터, 힙, 열린 파일을 공유하고 프로그램 카운터, 레지스터 집합, 스택만 독립적으로 보유함.
- 배경 및 필요성 : 프로세스는 독립된 주소 공간으로 인해 생성과 전환 비용이 크고, 프로세스 간 통신(IPC, Inter-Process Communication)도 별도의 메커니즘을 요구하므로 멀티코어의 병렬성을 저비용으로 활용할 수단이 필요함.
- 주요 목적 : 생성·전환 오버헤드의 축소, 공유 메모리 기반의 빠른 데이터 교환, 멀티코어 처리량의 극대화.

## Ⅱ. 스레드의 특징 및 장점

- 핵심 요약 : 자원 공유와 경량 전환이 병렬 처리 비용의 절감이라는 장점으로 연결되는 구조.

1. 자원 공유 : 같은 프로세스의 주소 공간을 공유 → 메모리 중복 할당을 피하고 데이터를 직접 참조하여 교환 비용 절감.
2. 독립 실행 : 스레드마다 프로그램 카운터, 레지스터, 스택을 보유 → 각자 독립된 함수 호출 경로를 수행.
3. 경량 문맥 교환 : 전환 시 주소 공간의 교체가 없고 레지스터와 스택 포인터만 교체하는 **문맥 교환** (Context Switching) → 전환 비용 최소화와 CPU(Central Processing Unit) 활용 효율 유지.
4. 병렬 실행 : 복수의 스레드를 여러 코어에 분배 → 멀티코어 하드웨어의 처리량 활용.

## Ⅲ. 스레드의 구조 (흐름)

- 핵심 요약 : 공유 영역과 스레드별 독립 영역으로 구성되고, 사용자 스레드와 커널 스레드의 매핑 모델에 따라 스케줄링이 달라짐.

1. **스레드 제어 블록** (TCB, Thread Control Block) : 상태, 우선순위, 레지스터 값 같은 스레드별 관리 정보.
2. 1:1 모델 : 사용자 스레드 하나가 커널 스레드 하나에 대응하며 커널이 직접 스케줄링 → 현대 운영체제(OS, Operating System)의 표준 방식.
3. M:1 모델 : 여러 사용자 스레드를 커널 스레드 하나에 묶어 사용자 수준 라이브러리가 스케줄링 → 초기 자바의 그린 스레드(Green Thread)가 사례.
4. M:N 모델 : 다수의 사용자 스레드를 여러 커널 스레드에 분배 → Go의 고루틴(Goroutine), 자바의 **가상 스레드** (Virtual Thread)가 사례.

```text
[ 프로세스 내 스레드 구조 ]

프로세스 공유 영역 (코드 · 데이터 · 힙 · 파일)
   ↓ 모든 스레드가 접근
스레드별 독립 영역 (카운터 · 레지스터 · 스택)
   ↓
커널 스케줄링에 따른 코어 병렬 실행
```

```text
[ 사용자 · 커널 스레드 매핑 모델 ]

1:1   사용자 1개 ↔ 커널 1개 (커널 직접 스케줄링)
M:1   사용자 다수 ↔ 커널 1개 (사용자 라이브러리)
M:N   사용자 다수 ↔ 커널 다수 (혼합 스케줄링)
```

## Ⅳ. 프로세스·스레드·코루틴의 비교

- 핵심 요약 : 프로세스, 스레드, **코루틴** (Coroutine)은 메모리 공간, 전환 비용, 통신 방식, 장애 파급 범위에서 차이가 나는 세 가지 실행 단위.

| 비교 항목 | 프로세스 | 스레드 | 코루틴 |
| --- | --- | --- | --- |
| 정의 | 자원 소유의 기본 단위 | 실행과 스케줄링의 최소 단위 | 사용자 공간에서 전환되는 경량 실행 단위 |
| 메모리 공간 | 독립된 주소 공간 | 주소 공간 공유, 스택만 독립 | 사용자 힙에 실행 문맥 저장 |
| 전환 비용 | 큼 (주소 공간 교체) | 작음 (레지스터·스택 교체) | 매우 작음 (커널 진입 없음) |
| 통신 방식 | 파이프, 소켓, 공유 메모리 등의 IPC | 공유 변수의 직접 참조 | 채널 또는 메모리 직접 참조 |
| 장애 파급 | 다른 프로세스에 영향 없음 | 하나의 오염이 프로세스 전체에 파급 | 애플리케이션 수준의 예외 처리 범위 |

- 선택 기준 : 격리가 필요한 기능은 프로세스로, 병렬 연산과 자원 공유는 스레드로, 대량의 대기 중 입출력 작업은 코루틴·가상 스레드로 배치하는 방식으로 판단.
- 비교 설명 : 세 단위는 배타적으로 선택하는 것이 아니라 서비스의 구성 요소별로 혼용하는 것이 일반적임.

## Ⅴ. 스레드의 한계와 방안

- 핵심 요약 : 경쟁 상태, 스레드 폭증, 교착상태, 순차 병목을 동기화, 풀, 락 규칙, 병렬화 설계로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **경쟁 상태** (Race Condition) | 여러 스레드가 동기화 없이 **임계 구역** (Critical Section)에 접근 → 데이터 불일치 | **뮤텍스** (Mutex)와 **세마포어** (Semaphore), 원자적 연산, 락 프리 자료구조 | 락 경합률 |
| 스레드 폭증 | 요청당 스레드 모델에서 동시 접속 증가 → 메모리 고갈과 스케줄링 부하 | **스레드 풀** (Thread Pool)로 상한 관리, 비동기 논블로킹 입출력(I/O, Input/Output) | 활성 스레드 수 |
| **교착상태** (Deadlock) · 우선순위 역전 | 복수 락의 교차 획득, 낮은 우선순위 스레드의 높은 스레드 차단 | 락 획득 순서 규칙, 타임아웃 락, 우선순위 상속 프로토콜 | 락 대기 시간 |
| 순차 병목 | **암달의 법칙** (Amdahl's Law)에 따라 순차 구간이 병렬 성능의 상한을 제한 | 알고리즘 개선으로 순차 구간 축소, 작업 분할 단위의 재설계 | 병렬화 효율 |

## Ⅵ. 스레드에 대한 기술사적 제언

- 핵심 요약 : 동시성 표준, 풀 관리 절차, 검증 게이트를 조직 체계로 정착시켜 동시성 품질을 높이는 방향.

- 개발 조직은 공유 가변 상태의 최소화와 불변 객체 우선을 동시성 코딩 표준으로 제정하고 정적 분석 도구로 검증하는 체계를 운영.
- 플랫폼 운영 조직은 스레드·커넥션 풀의 상한 정책을 수립하고 부하 테스트 기반의 풀 크기 산정 절차를 표준화.
- 품질 관리 조직은 교착상태 탐지 도구와 동시성 부하 테스트를 릴리스 게이트에 포함하여 동시성 결함의 조기 발견을 제도화.

## Ⅶ. 결론

- 핵심 요약 : 스레드는 프로세스 자원을 공유하는 경량 실행 단위로 병렬 처리의 효율을 높이는 기반.
- 공유로 인한 동기화 위험의 관리 수준이 병렬화 이득의 실현 여부를 결정함.
