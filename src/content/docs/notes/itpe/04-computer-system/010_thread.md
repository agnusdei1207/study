## 연관 키워드
- 스레드, 프로세스, 실행 문맥, 프로그램 카운터, 공유 주소 공간, 동기화

## Ⅰ. 스레드의 개요
- 핵심 요약 : 스레드는 프로세스 자원을 공유하며 독립 실행 문맥을 지닌 스케줄링 단위.
- 개념 : **스레드**(Thread)는 PC·레지스터·스택을 갖고 프로세스 내 코드·힙·열린 자원을 공유하는 실행 흐름.
- 배경 및 필요성 : 병렬 처리와 응답성 향상, 작업 간 데이터 공유 요구.
- 주요 목적 : 하나의 프로세스 안에서 복수 실행 흐름 지원.

## Ⅱ. 구조 및 장점
- 핵심 요약 : 실행 상태는 스레드별로 분리하고 주소 공간은 공유해 가벼운 동시성을 제공.
- 스레드별 PC·레지스터·스택 → 독립 제어 흐름.
- 프로세스 자원 공유 → 프로세스 간 통신보다 데이터 교환이 간단.
- 한 스레드의 I/O 대기 동안 다른 스레드 수행 → 응답성 향상 가능.
- 공유 상태 접근 시 데이터 경쟁과 동기화 필요.

## Ⅲ. 프로세스 내 구성
- 핵심 요약 : 스케줄러는 스레드 문맥을 저장·복원하고 같은 프로세스 스레드에 공통 주소 공간을 제공.
```text
프로세스: 코드 · 전역 · 힙 · 열린 자원
          ↙                  ↘
스레드 A                   스레드 B
PC·레지스터·스택            PC·레지스터·스택
```
```text
A 실행 → 문맥 저장
          ↓ 스케줄링
B 문맥 복원 → 실행
          ↓ 선점·인터럽트
B 상태 저장
```

## Ⅳ. 프로세스와 스레드 비교
- 핵심 요약 : 프로세스는 보호·자원 소유 단위, 스레드는 내부 실행 흐름.
| 비교 축 | 프로세스 | 스레드 |
| --- | --- | --- |
| 주소 공간 | 분리 | 프로세스 내부 공유 |
| 통신 | IPC 필요 | 공유 메모리 가능 |
| 전환 | 주소 공간 전환 가능 | 실행 문맥 중심 |
| 장애 | 비교적 격리 | 손상 시 프로세스 전체 영향 |

## Ⅴ. 한계와 방안
- 핵심 요약 : 데이터 경쟁·교착·과도한 스레드는 명시적 동기화와 실행 제한으로 관리.
| 한계 | 원인·영향 | 대응 |
| --- | --- | --- |
| 경쟁 조건 | 동시 수정 | 잠금·원자 연산·불변성 |
| 교착 | 상호 잠금 대기 | 잠금 순서·시간제한 |
| 과다 생성 | 전환·스택 비용 | 제한된 스레드 풀 |

## Ⅵ. 구현 제언
- 핵심 요약 : 개발자는 병렬 실행 이득보다 공유 상태와 장애 격리 요구를 먼저 설계.
- 풀 크기는 CPU·I/O 특성으로 조정하고 예외·취소·종료 정책을 정의.

## Ⅶ. 결론
- 핵심 요약 : 스레드는 경량 동시 실행 단위이며 공유 자원 안전성이 설계 핵심.
- 작업 특성에 따라 스레드·프로세스·비동기 방식을 선택.
