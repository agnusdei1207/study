## 답안 골격
```text
[데이터베이스 표준화지침] ◀━━ 머리: Ⅶ 내 의견 (전사 메타데이터 관리 시스템 연계와 CI/CD 스키마 린팅을 통한 표준 강제)
 ┃
 ┣━ Ⅰ 개요 ───── 정보시스템 간 데이터 연계와 품질을 보장하기 위해 데이터 명칭, 도메인, 코드, 모델링 규칙을 규격화하여 전사 배포하는 공식 표준 지침
 ┣━ Ⅱ 특징 ───── 행정안전부 공공데이터 표준화 관리 매뉴얼 기반 · 데이터 중복 및 의미 왜곡 원천 차단 · 유지보수 비용 절감 · 상호운용성 보장
 ┣━ Ⅲ 구조 ───── 4대 표준화 영역: 표준 단어(Standard Word) / 표준 도메인(Standard Domain) / 표준 용어(Standard Term) / 표준 코드(Standard Code)
 ┣━ Ⅳ 흐름 ───── ① 현행 데이터 용어·코드 수집 → ② 표준 단어 사전 정의(동음이의어/이음동의어 정비) → ③ 표준 도메인 및 용어 조합 규칙 수립 → ④ 표준 승인 및 메타시스템 반영 → ⑤ 정기 표준 준수율 점검
 ┣━ Ⅴ 비교 ───── 표준 단어 vs 표준 도메인 vs 표준 용어 vs 표준 코드
 ┗━ Ⅵ 실무 ───── 개발 단계에서 표준 승인 절차 우회로 인한 임의 약어 컬럼 생성 / 동일 코드의 기관별 코드값 상이
```

## 한 줄 본질
- 개발자마다 컬럼명(예: `CUST_ID`, `USER_NO`, `MBR_CD`)과 데이터 타입을 제각각 사용하여 데이터 통합과 쿼리가 마비됨 → 표준 단어·용어·도메인·코드를 사전 정의하고 조합하여 물리 컬럼명을 자동 생성 → 전사 데이터 일관성 100% 확보 / 개발 초기 표준 승인 지연 발생

## 핵심 그림
```text

  │  표준 단어 사전  │           │  표준 도메인 사전│

  │  - 번호 (NO)     │           │    VARCHAR(20)   │
  └────────┬─────────┘           └────────┬─────────┘
           │ 단어 조합                    │ 물리 속성 매핑
           ▼                              ▼

           │ 유효값 범위 제한
```

## 핵심 용어
- 표준 단어(Standard Word): 데이터 명칭에 사용할 최소 단위의 명사로, 동음이의어(단어는 같으나 뜻이 다름)와 이음동의어(뜻은 같으나 단어가 다름)를 정비하여 1단어 1의미 원칙 적용
- 표준 도메인(Standard Domain): 속성에 허용되는 데이터 타입, 길이, 허용 범위(Null 여부, 제약조건)를 그룹화하여 일관된 물리 데이터 타입을 부여하는 기준

## 핵심 통찰
- 표준화 지침이 실패하는 가장 큰 이유는 '엑셀 문서로만 존재하기 때문'임 → 표준 용어 사전을 엑셀 파일로 서버에 올려두면 개발자들은 바쁘다는 핑계로 보지 않고 마음대로 컬럼명을 지음
- 따라서 표준화의 핵심은 '단어의 조합 규칙(Syntax)'임 → `표준 용어 = 표준 단어 1 + 표준 단어 2 + ... + 표준 도메인 분류어(끝 단어)` 공식을 강제하여 끝 단어만 보고도 데이터 타입이 자동 결정되도록 해야 함
- 메타데이터 관리 시스템(MDR)을 구축하여, 새로운 테이블을 생성할 때 사전 승인된 표준 용어가 아니면 DDL 생성이 원천 차단되도록 파이프라인 레벨에서 통제해야 함

## 이웃 토픽과 구분
- 표준 용어 vs 표준 도메인: 표준 용어 = 구체적인 업무적 의미를 가진 개별 속성의 이름(예: `주문금액`, `고객번호`) / 표준 도메인 = 여러 속성이 공통으로 공유할 수 있는 데이터의 형식적 규격(예: `금액 도메인: NUMBER(15,2)`, `번호 도메인: VARCHAR(20)`)

## 문제·원인·대책
- 적용 상황: 대규모 공공 행정 데이터베이스 통합 구축 사업
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| A 기관은 `USER_ID`, B 기관은 `MBR_NO`로 명명하여 기관 간 데이터 연계 조인 불가 | 표준화 지침 부재 및 기관별 임의 약어 남발 | 범정부 표준 단어·용어 사전을 적용하여 `CUST_NO`로 물리명 단일화 | 데이터 연계 매핑 공수 90% 절감 |
| 동일한 '주민등록번호' 속성에 대해 어떤 테이블은 VARCHAR(13), 어떤 테이블은 CHAR(14) 적용 | 표준 도메인 체계 미준수로 인한 데이터 타입 불일치 | '주민번호 도메인: VARCHAR(13)'을 일괄 지정하여 모든 관련 컬럼 타입 강제 | 데이터 타입 변환 에러 제로화 |
