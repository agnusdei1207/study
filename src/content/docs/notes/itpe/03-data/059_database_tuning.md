## 연관 키워드
- DB 튜닝, 실행계획, 인덱스, 통계정보, 버퍼풀, 잠금, 성능기준선

### Ⅰ. 데이터베이스 튜닝의 개요

- 핵심 요약 : 측정된 병목을 실행계획·스키마·인덱스·쿼리·자원 설정에서 찾아 성능목표에 맞게 개선하는 과정.
- 개념 : 측정된 병목을 실행계획·스키마·인덱스·쿼리·자원 설정에서 찾아 성능목표에 맞게 개선하는 과정(**데이터베이스 튜닝**, Database Tuning).
- 배경 및 필요성 : 응답지연·처리량·경합이 업무 SLO와 운영비용에 영향.
- 주요 목적 : DB 자원·구조·질의 경로의 효율과 안정성 향상.

### Ⅱ. 데이터베이스 튜닝의 특징 및 장점

- 핵심 요약 : 측정 우선·계획 분석·회귀 통제는 데이터베이스 튜닝의 핵심 요소.

1. 측정 우선 : 기준선·부하·대기 이벤트 확인 → 원인 기반 개선.
2. 계획 분석 : 실제 실행계획·통계 확인 → 스캔·조인·정렬 병목 파악.
3. 회귀 통제 : 변경 전후 동일 부하 재현 → 성능·정합성 확인.

### Ⅲ. 데이터베이스 튜닝의 구조 (흐름)

- 핵심 요약 : SLO·기준선 설정 → 상위 쿼리·대기·자원 수집 → 실행계획·통계·스키마 분석 → 한 번에 한 변경 적용 → 부하·회귀시험·관측.

```text
SLO·기준선 설정
   ↓
상위 쿼리·대기·자원 수집
   ↓
실행계획·통계·스키마 분석
   ↓
한 번에 한 변경 적용
   ↓
부하·회귀시험·관측
```

```text
[ 쿼리 처리 흐 ]
요청 → 쿼리 → 옵티마이저 계획 → I/O·CPU·잠금 → 지연·대기 측정 → 병목 개선
```

### Ⅳ. 쿼리 튜닝과 하드웨어 증설 비교

- 핵심 요약 : 효과 기준 — 쿼리 튜닝: 불필요 연산·I/O 감소; 하드웨어 증설: 용량부족 해소·처리량 확장.

| 비교 항목 | 쿼리 튜닝 | 하드웨어 증설 |
|---|---|---|
| 개선대상 | SQL·실행계획·인덱스·통계 | CPU·메모리·스토리지 용량 |
| 효과 | 불필요 연산·I/O 감소 | 용량부족 해소·처리량 확장 |
| 한계 | 쿼리·모델 복잡성 존재 | 비효율·경합이 남으면 비용만 증가 |

### Ⅴ. 데이터베이스 튜닝의 한계와 방안

- 핵심 요약 : 추측 튜닝·과도한 인덱스 등 주요 위험을 원인에 맞는 통제로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 추측 튜닝 | 측정 없이 파라미터 변경해 악화 | 성능 기준선·대기 원인·부하 재현 확보 | SLO 변화 |
| 과도한 인덱스 | 읽기만 보고 쓰기·캐시 비용 간과 | 읽기·쓰기·저장 영향 동시 비교 | 인덱스 비용 |
| 캐시·통계 부정확 | 표본 데이터·운영 데이터 차이로 결과 왜곡 | 대표 데이터·동시성·콜드/웜 캐시 시험 | p95·오류율 |

### Ⅵ. 데이터베이스 튜닝에 대한 기술사적 제언

- 핵심 요약 : DBA는 실제 쿼리와 실행 계획을 근거로 인덱스를 설계하고 변경 전후 읽기·쓰기·저장 비용을 모두 비교할 필요가 있다.
- 실행 제안 : DBA는 대표 데이터·동시성·캐시상태를 포함한 기준 부하를 재현해 계획 변경 전후 SLO와 롤백 조건을 기록할 필요가 있다.

### Ⅶ. 결론

- 핵심 요약 : 튜닝은 설정값을 많이 바꾸는 일이 아니라 측정으로 병목을 좁혀 작은 변경을 검증하는 성능개선 루프임.
- 시사점 : 성능개선은 대표 부하의 동일 기준선과 변경 후 회귀검증을 통해서만 확인 가능함.
