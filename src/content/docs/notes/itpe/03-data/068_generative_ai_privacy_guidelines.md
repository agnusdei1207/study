## 연관 키워드

- 생성형 AI, 대규모 언어모델(LLM), Privacy by Design, PII(개인식별정보)
- 차분 프라이버시(Differential Privacy), 머신 언러닝(Machine Unlearning), RAG, Zero Data Retention
- 프롬프트 인젝션(Prompt Injection), 가드레일(Guardrails)

## Ⅰ. 생성형 AI 개인정보보호의 개요

- 핵심 요약 : 생성형 AI의 학습부터 서비스까지 전 단계에 프라이버시 원칙을 적용해 개인정보 노출을 통제하는 체계.
- 개념 : 생성형 AI (Generative AI)가 대규모 언어모델(LLM, Large Language Model)을 학습하고 응답을 생성하는 과정에서 개인정보가 암기·재현·유출되지 않도록 통제하는 개인정보보호 영역.
- 배경 및 필요성 : 학습 데이터 범위 확대로 개인정보 사전 필터링 비용 증가, 가중치 학습 정보의 선택 삭제 곤란에 따른 사후 구제 비용 증가. 수집 단계부터의 계층적 통제 필요. 개인정보보호위원회 2025년 8월 6일 「생성형 인공지능(AI) 개발·활용을 위한 개인정보 처리 안내서」 공개, 생애주기별 최소 안전조치 제시(발표 기준).
- 주요 목적 : 동의 없는 개인정보의 학습·암기·출력 누출을 막고, 정보주체의 열람·삭제 권리를 기술적으로 보장.

## Ⅱ. 생성형 AI 개인정보보호의 특징 및 장점

- 핵심 요약 : 단계별 통제와 기술적 보호 장치가 결합해 학습 전 차단과 사후 대응을 동시에 가능하게 하는 구조.

1. Privacy by Design (설계 단계부터 개인정보 보호를 내재화하는 원칙) : 기획 시점에 보호 요건을 반영 → 사후 수정 비용 감소.
2. PII 탐지 (개인식별정보, Personally Identifiable Information) : 정규식과 개체명 인식으로 민감 정보를 찾아 마스킹 또는 가명처리 → 학습 데이터의 노출 위험 축소.
3. 차분 프라이버시 (Differential Privacy, 개별 데이터의 영향을 잡음으로 가려 특정인 식별 가능성을 제한하는 기법) : 학습 과정에 잡음을 더함 → 암기 위험 감소.
4. 가드레일 (Guardrails, 입력과 출력을 규칙으로 검사하는 안전 장치) : 입력 프롬프트를 필터링해 프롬프트 인젝션 (Prompt Injection, 악성 지시문으로 모델의 원래 지시를 무력화하는 공격)을 막고 출력을 마스킹 → 서비스 단계 유출 감소.
5. 머신 언러닝 (Machine Unlearning, 학습된 모델에서 특정 데이터의 영향을 제거하는 기법) : 정보주체의 삭제 요청에 대응 → 권리 행사 경로 확보.
6. RAG (Retrieval-Augmented Generation, 외부 문서를 검색해 응답에 결합하는 방식) : 민감 정보를 가중치 대신 권한 기반 저장소에 두어 삭제와 접근 통제를 용이하게 함.

## Ⅲ. 생성형 AI 개인정보보호의 구조 (흐름)

- 핵심 요약 : 기획~서비스 운영 4단계 구분, 단계별 위협 차단 라이프사이클 통제 흐름.
- 개인정보보호위원회 안내서의 개발·활용 생애주기 4단계 및 단계별 최소 안전조치 제시. 아래는 학습 흐름 기준 정리 구분.

```text
[ 생성형 AI 개인정보보호 4단계 ]

[1] 목적 설정·개인정보 영향평가
         ↓
[2] 수집·학습: PII 탐지, 가명처리
         ↓
[3] 모델 튜닝: 차분 프라이버시
         ↓
[4] 서비스·운영: 가드레일, 삭제 대응
```

## Ⅳ. 단계별 위협·대응 비교

- 핵심 요약 : 수집·학습·입력·출력 단계마다 위협이 달라 대응 수단도 단계별로 분리해야 함.

| 단계 | 주요 위협 | 대응 방안 |
| --- | --- | --- |
| 데이터 수집 | 개인정보 무단 수집 | 개인식별정보 탐지·마스킹, 수집 출처의 적법 근거 검토 |
| 모델 학습 | 학습 데이터 암기·재현 | 차분 프라이버시 적용, 합성 데이터 활용 |
| 프롬프트 입력 | 기밀·개인정보 입력 | 입력 필터링, 입력 데이터의 학습 제외 설정 |
| 출력·서비스 | 프롬프트 인젝션, 응답을 통한 유출 | 가드레일 적용, 출력 마스킹 |

## Ⅴ. 생성형 AI 개인정보보호의 한계와 방안

- 핵심 요약 : 학습 데이터 암기, 프롬프트 인젝션, 삭제권 행사의 한계를 차분 프라이버시·가드레일·RAG 전환으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 학습 데이터 암기 | 웹 수집 데이터의 개인정보가 가중치에 남아 응답으로 재현 | 개인식별정보 전처리, 차분 프라이버시 적용 | 개인정보 탐지율, 재현 테스트 통과율 |
| 프롬프트 인젝션 | 악성 지시문으로 시스템 지시와 내부 데이터가 노출 | 입력·출력 가드레일, 출력 마스킹 | 차단율 |
| 삭제권 행사 | 가중치에 녹아든 정보는 선택 삭제가 곤란 | 머신 언러닝(SISA(Sharded, Isolated, Sliced, and Aggregated) 방식 등), 민감 데이터의 RAG 전환 | 삭제 요청 처리 기간 |

```text
[ 삭제 요청 처리 경로 ]

가중치에 학습된 정보
         ↓
재학습 또는 언러닝 필요 (비용 큼)

RAG 저장소의 문서
         ↓
원본 레코드 삭제로 즉시 처리
```

## Ⅵ. 생성형 AI 개인정보보호에 대한 기술사적 제언

- 핵심 요약 : 계약 조건, 아키텍처, 조직 참여 세 축 결합을 통한 안전한 생성형 AI 도입.

1. 계약 측면 : 외부 생성형 AI 서비스 이용 시 Zero Data Retention (ZDR, 입력 데이터를 저장하거나 학습에 쓰지 않는 조건) 계약 명시, 제공자 확인 범위 내 신뢰 관리.
2. 아키텍처 측면 : 민감 데이터의 가중치 미포함, 권한 기반 검색 제공을 통한 삭제·접근 통제의 시스템 단위 수행.
3. 조직 측면 : 개인정보 보호책임자의 기획 단계 참여, 개인정보 영향평가 결과의 개발 체크리스트 반영.

## Ⅶ. 결론

- 핵심 요약 : 생성형 AI 개인정보보호는 라이프사이클 전 단계 통제와 RAG·머신 언러닝 결합으로 완성되는 체계.
- 시사점 : 학습 단계 노출 위험의 완전 제거 곤란, 설계·운영·계약 전반 다층 통제의 기본 전제.
