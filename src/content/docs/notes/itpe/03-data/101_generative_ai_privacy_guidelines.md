## Ⅰ. 생성형 AI 확산에 따른 개인정보보호의 개요

### 가. 생성형 AI 개인정보 침해의 특수성
- 방대한 웹 크롤링 데이터 및 사용자 프롬프트 입력을 학습 데이터로 활용하는 **거대언어모델** (LLM)과 **멀티모달 AI** 의 특성상, 정보주체의 동의 없는 **개인정보** (PII) 무단 학습, 모델 가중치(Weight) 내 **개인정보 암기** (Memorization), 그리고 추론 단계에서의 프라이버시 누출 위험이 전례 없이 증대됨.

### 나. 개인정보보호위원회의 생성형 AI 프라이버시 가이드라인
- 기획, 학습 데이터 수집, 모델 개발 및 파인튜닝, 서비스 배포 등 AI 전 라이프사이클에 걸친 **프라이버시 바이 디자인** (Privacy by Design) 원칙 준수 의무화.

## Ⅱ. AI 생명주기별 개인정보 침해 위험 및 안전조치 프레임워크

### 가. 4단계 AI 라이프사이클 통제 매트릭스

```text
[ 생성형 AI 개인정보보호 4단계 관리 체계 ]
[1단계: 기획·설계]    : 개인정보 영향평가(PIA), 데이터 처리 적법 근거(정당한 이익) 검토
          |
[2단계: 수집·학습]    : 웹 스크래핑 데이터 내 PII 사전 탐지, 가명처리, 비식별 필터링
          |
[3단계: 모델 튜닝]    : 차분 프라이버시(DP-SGD), 파인튜닝 데이터 엄격 격리
          |
[4단계: 서비스·운영]  : 프롬프트 필터링, 출력 Guardrails, 정보주체의 삭제권(잊힐 권리) 보장
```

| 단계 | 주요 프라이버시 위협 요소 | 필수 기술적·관리적 안전조치 |
| :--- | :--- | :--- |
| **데이터 수집** | 웹 스크래핑 시 주민등록번호, 계좌번호, 민감정보(사상, 건강) 무단 수집 | AI 기반 PII 마스킹(NER, 정규식), 저작권/로봇 배제 표준(robots.txt) 준수 |
| **모델 학습** | 암기 효과(Memorization)로 인해 원천 개인정보가 모델 가중치에 각인 | **차분 프라이버시** (DP-SGD) 적용, 과적합 방지, **합성 데이터** (Synthetic Data) 활용 |
| **프롬프트 입력** | 임직원이 기업 기밀, 고객 개인정보를 챗봇 프롬프트에 직접 입력 | 입력 게이트웨이(Data Loss Prevention, DLP)를 통한 PII 탐지 및 차단, 옵트아웃(Opt-out) 설정 |
| **출력 및 서빙** | 적대적 프롬프트 주입(Prompt Injection), 탈옥(Jailbreak)을 통한 개인정보 유출 | **출력 가드레일** (NeMo Guardrails), 사후 생성 텍스트 PII 마스킹 |

## Ⅲ. 머신 언러닝(Machine Unlearning)과 정보주체의 권리 행사

### 가. 모델 내 개인정보 삭제(잊힐 권리)의 공학적 난제
- 정보주체가 "내 개인정보를 AI 모델에서 지워달라"고 요구할 때, 전통적 DB는 `DELETE` 한 줄로 끝나지만, 수천억 개 파라미터에 분산 압축된 가중치에서 특정 개인의 정보를 선택적으로 제거하는 것은 모델 전체 재학습(수십억 원 소요) 없이는 사실상 불가능함.

### 나. 머신 언러닝(Machine Unlearning)의 핵심 접근법
- **정확한 언러닝 (Exact Unlearning)** : 모델을 여러 샤드(SISA: Sharded, Isolated, Sliced, Aggregated)로 분할 학습하여 삭제 요청 시 해당 샤드만 선별 재학습.
- **근사 언러닝 (Approximate Unlearning)** : 영향도 함수(Influence Function)나 경사도 반전(Gradient Ascent)을 활용하여 해당 데이터가 기여한 파라미터 변화량을 역방향으로 감쇄.

## Ⅳ. 생성형 AI 개인정보보호의 주요 한계점 및 해결 방안

- **사전학습** (Pre-training) 단계의 대규모 웹 크롤링 데이터 내 민감정보 무단 학습 :
  - 한계점 : 방대한 비정형 텍스트에 포함된 주민등록번호, 계좌번호 등 개인식별정보(PII)를 완벽히 필터링하지 못해 모델 파라미터 내 기억화(Memorization) 발생.
  - 해결 방안 : 정규표현식 및 개체명 인식(NER) 기반 실시간 비식별화/가명화 전처리 파이프라인 구축, 차분 프라이버시(Differential Privacy) 기법을 학습 단계에 적용.
- **프롬프트 주입** (Prompt Injection) 및 **멤버십 추론 공격** (Membership Inference Attack) 취약 :
  - 한계점 : 적대적 프롬프트 공격을 통해 LLM 내부의 학습 데이터 복원(Extraction Attack) 및 개인정보 유출 리스크 상존.
  - 해결 방안 : 입력/출력 게이트웨이에 가드레일(NeMo Guardrails, Llama Guard) 배치, 실시간 출력 마스킹 및 민감 정보 탐지 필터 운영.
- 정보주체의 삭제권 행사에 대한 머신 언러닝(Machine Unlearning)의 기술적 한계 :
  - 한계점 : 모델 가중치에 분산 저장된 특정 개인정보를 모델 전체 재학습 없이 선택적으로 망각시키는 기술의 연산 비용 및 모델 성능 훼손 난제.
  - 해결 방안 : 체크포인트 기반 영향 함수(Influence Function) 추정 언러닝 기법 도입, RAG(검색 증강 생성) 아키텍처로 전환하여 민감 데이터는 외부 벡터 DB에서 즉시 삭제 통제.

## Ⅴ. 엔터프라이즈 AI 도입을 위한 실무 제언

- LLM 제공사와의 엔터프라이즈 제휴 계약(Zero Data Retention) : 임직원이 사용하는 생성형 AI 서비스(ChatGPT Enterprise, Claude Enterprise) 도입 시 사용자의 입력 프롬프트와 사내 문서가 LLM의 후속 학습 데이터로 사용되지 않도록 **Zero Data Retention** (ZDR) 계약 조항을 반드시 명문화해야 함.
- **RAG** 기반 아키텍처로의 전환 : 사내 민감 데이터를 LLM 모델 자체에 파인튜닝(가중치 각인)하지 말고, 권한 기반(RBAC) 벡터 검색을 거쳐 인메모리 프롬프트로만 일시 공급하는 RAG 구조를 채택함으로써 데이터 폐기 및 접근 통제를 데이터베이스 계층에서 엄격히 통제할 것을 제언함.
