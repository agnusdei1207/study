## 연관 키워드

**Text2SQL**, **스키마 링킹(Schema Linking)**, **Few-Shot**, **자가 교정(Self-Correction)**, **시맨틱 레이어(Semantic Layer)**, **데이터 민주화**, **LLM**

## Ⅰ. 개요

- 핵심 요약 : **Text2SQL**은 자연어 질문을 SQL 쿼리로 자동 변환하는 LLM 기반 데이터 접근 기술.
- 목적 : 비전문가도 데이터에 직접 질의하여 분석 가능 (데이터 민주화).
- 배경 : SQL·스키마 지식 장벽으로 데이터 접근 제한 → 자연어 인터페이스 필요.
- 특징 : 스키마 링킹, Few-Shot, 자가 교정, 시맨틱 레이어.

## Ⅱ. 특징 및 장점

- 핵심 요약 : **스키마 링킹·Few-Shot·자가 교정**으로 정확한 SQL 생성.
- **자연어 인터페이스** : SQL 지식 없이 데이터 질의.
- **스키마 링킹** : 자연어 단어를 테이블·컬럼·외래키에 매핑.
- **Few-Shot RAG** : 유사 과거 (질문, SQL) 쌍 주입으로 정확도 향상.
- **자가 교정** : 실행 에러 시 LLM 재시도로 성공률 극대화.
- **데이터 민주화** : 전사 데이터 접근성 확대.

## Ⅲ. 파이프라인 흐름

- 핵심 요약 : **질문 → 스키마 링킹 → 프롬프트 → LLM → 검증 → 실행**.
- 파이프라인 6단계 : 질문 입력, 스키마 링킹, 프롬프트 구성(DDL+Few-Shot), LLM 추론, SQL 검증·자가 교정, DBMS 실행·시각화.

```text
[ Text2SQL 파이프라인 ]

[자연어 질문]
   |
   v
[스키마 링킹] 관련 테이블/컬럼/외래키 추출
   |
   v
[프롬프트 구성] DDL + Few-Shot + 도메인 규칙
   |
   v
[LLM 추론] SQL 생성
   |
   v
[SQL 검증·자가 교정] 구문 검사 + Dry-Run
   |
   v
[DBMS 실행 및 결과 시각화]
```

## Ⅳ. 구성 요소 비교

- 핵심 요약 : **스키마 링킹·Few-Shot·자가 교정·구문 검증** 역할 비교.

| 구성 요소 | 메커니즘 | 해결 과제 |
|---|---|---|
| 스키마 링킹 | 자연어 단어를 DB 컬럼에 의미론적 매핑 | "VIP 매출" → ORDERS.TOTAL_PRICE |
| Few-Shot RAG | 유사 과거 (질문,SQL) 쌍 벡터 검색 주입 | 복합 조인·비즈니스 로직 가이드 |
| 구문 검증 | sqlglot/ANTLR로 문법 오류 사전 차단 | 컴파일 에러 없는 SQL |
| 자가 교정 | 실행 에러 메시지를 LLM에 재주입 | 1회 실패 시 자동 수정 |

## Ⅴ. 한계와 방안

- 핵심 요약 : **스키마 규모·보안·자원 폭주**를 프루닝·권한·가드레일로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 스키마 규모 | 수천 테이블을 프롬프트에 담기 불가 | 스키마 프루닝으로 관련 5~10개 테이블만 추출 | 정확도 (Execution Accuracy) |
| 보안·쿼리 파괴 | DDL/DML 실행·SQL Injection 위험 | 읽기 전용 계정, AST 검사로 DDL/DML 차단 | 보안 사고 0건 |
| 자원 폭주 | 잘못된 SQL의 카테시안 곱으로 DB 고갈 | 자원 상한선(Guardrail), 실행계획 검증 | 쿼리 실행 시간 |

## Ⅵ. 기술사적 제언

- 핵심 요약 : **시맨틱 레이어·가드레일·권한 분리**로 안전한 데이터 민주화.
- 시맨틱 레이어 : dbt/Cube.js로 컬럼 비즈니스 명칭·계산 공식·동의어 표준화.
- 가드레일 : 행 수·실행 시간·스캔량 제한 + 실행계획 검증.
- 권한 분리 : Text2SQL 전용 읽기 전용 계정.

- 답안에는 파이프라인, 구성 요소, 한계·대응, 보안 가드레일을 연결.
