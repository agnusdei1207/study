## 연관 키워드

- 시계열 이상탐지(Time Series Anomaly Detection), 점·문맥·집단 이상, 스트림 처리(Stream Processing)
- 슬라이딩 윈도우(Sliding Window), 동적 임계값(Dynamic Threshold), 오경보(False Alarm), 드리프트(Drift)

## Ⅰ. 시계열 실시간 이상탐지의 개요

- 핵심 요약 : 시간에 따라 들어오는 데이터에서 정상 패턴을 벗어난 값을 찾아내 즉시 판정하는 기술.
- 개념 : 시간 순서로 관측되는 데이터에서 정상 패턴과 다른 값을 찾아내는 **시계열 이상탐지** (Time Series Anomaly Detection) 기술.
- 배경 및 필요성 : 장애·사기·설비 이상을 사후에 발견하면 피해가 커지므로, 데이터가 들어오는 즉시 판정하는 실시간 탐지 계층이 필요.
- 주요 목적 : 서버·네트워크 지표, 금융 거래, 산업 센서 데이터에서 이상을 조기에 발견해 대응 시간을 줄임.

## Ⅱ. 시계열 이상탐지의 특징 및 장점

- 핵심 요약 : 시간 문맥과 정상 패턴의 변화를 고려하면 고정 임계값으로 놓치는 이상까지 탐지할 수 있음.

1. **점 이상** (Point Anomaly) : 한 시점의 값이 주변과 크게 다름 → 단발성 급변 감지.
2. **문맥 이상** (Contextual Anomaly) : 값 자체는 흔해도 시간과 조건에 비춰 비정상 → 시간대별 기준선으로 탐지.
3. **집단 이상** (Collective Anomaly) : 개별 값은 정상 범위여도 시퀀스 전체 패턴이 비정상 → 구간 단위 탐지.
4. **스트림 처리** (Stream Processing) : 윈도우와 온라인 알고리즘으로 데이터 도착 즉시 점수화 → 지연 없는 판단.

## Ⅲ. 실시간 탐지 처리 흐름

- 핵심 요약 : 수집, 정제와 윈도우 처리, 기준선과 이상 점수, 경보와 피드백이 이어지는 운영 흐름.

```text
[메트릭·이벤트 수집]
          ↓
[시간 정렬·결측·중복 처리]
          ↓
[윈도우 특징·정상 기준선]
          ↓
[규칙·통계·ML 이상 점수]
          ↓
[경보 억제·우선순위 지정]
          ↓
[운영자 조치·피드백]
```

- **슬라이딩 윈도우** (Sliding Window) : 최근 일정 구간을 계속 이동하며 집계하는 방식으로, 실시간 특징 계산의 기본 단위가 된다.
- 데이터 지연과 시간대·계절성을 반영해 기준선을 구성하고, 탐지 결과를 실제 운영 조치와 연결한다.
- 탐지 점수와 경보 정책을 분리해, 민감도를 바꿔도 탐지 모델 전체를 다시 만들 필요가 없게 한다.

## Ⅳ. 알고리즘 비교

- 핵심 요약 : 단순하고 빠른 기법부터 복잡한 모델까지, 데이터 특성과 지연 허용치에 맞춰 선택.

| 기법 | 장점 | 한계·유의점 |
| --- | --- | --- |
| 고정 임계값 | 단순하고 설명이 쉬움 | 계절·추세 변화에 취약 |
| EWMA(Exponentially Weighted Moving Average)·이동 통계 | 계산이 가볍고 최근 변화 반영 | 복잡한 패턴은 놓칠 수 있음 |
| 계절 기준선·잔차 | 반복 패턴과 추세 반영 | 기준선 학습과 갱신 필요 |
| Isolation Forest 등 | 다변량 이상 점수 산출에 활용 | 파라미터와 분포 변화에 민감 |
| 시퀀스 오토인코더(Autoencoder) | 비선형 시계열 패턴 학습 가능 | 학습·추론 비용, 설명과 검증 부담 |

## Ⅴ. 실시간 이상탐지의 한계와 방안

- 핵심 요약 : 오경보, 처리 지연, 정답 라벨 부족, 정상 패턴 변화가 실시간 탐지의 주요 운영 문제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 정상 변동의 오탐 | 고정 임계값이 요일·시간대 변동을 반영하지 못해 오경보 누적 | **동적 임계값** (Dynamic Threshold)을 시간대·요일별 기준선과 지속 시간 조건으로 적용 | 오경보율 |
| 고빈도 입력 지연 | 대량 입력에서 점수 계산이 밀려 탐지가 늦어짐 | 윈도우 집계·샘플링·경량 점수화, 백로그 감시 | 탐지 지연 시간, 백로그 길이 |
| 라벨 부족 | 이상 사례가 드물어 탐지 결과를 검증하기 어려움 | 운영자 피드백과 사고 후 분석을 모아 검증 데이터 축적 | 확인된 이상 건수 |
| 정상 패턴 변화(**드리프트**, Drift) | 입력 분포가 바뀌어 기준선이 낡음 → 탐지 성능 저하 | 오차 분포와 입력 변화 감시, 검증된 기준선·모델로 갱신 | 오차 분포 변화량 |

```text
[고정 임계값 경보]
          ↓ 계절·추세 미반영
[정상 변동의 오탐 누적]
          ↓
[시간대별 동적 기준선 적용]
```

## Ⅵ. 기술사적 제언

- 핵심 요약 : 탐지 성능과 경보 품질을 함께 측정해 알림 피로를 줄이는 방향.
- 정밀도와 재현율뿐 아니라 탐지 지연, 경보 건수, 조치까지 걸린 시간을 함께 관찰한다.
- 중복·상관 경보를 묶고, 심각도와 서비스 영향을 기준으로 우선순위를 매긴다.
- 자동 조치는 영향 범위를 제한하고, 승인·취소·사후 감사 기능을 함께 둔다.

## Ⅶ. 결론

- 핵심 요약 : 실시간 이상탐지는 시간 문맥, 탐지 지연, 오경보 관리를 함께 설계해야 운영 가치가 있음.
- 시사점 : 운영자 피드백을 기준선과 임계값 개선에 되돌려 넣는 순환이 탐지 품질을 지속적으로 높인다.
