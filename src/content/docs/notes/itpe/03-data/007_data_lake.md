## 연관 키워드
- 데이터 레이크, 원천 형식, 스키마 온 리드, 메타데이터, 데이터 늪

### Ⅰ. 데이터 레이크의 개요

- 핵심 요약 : 데이터 레이크는 다양한 형식의 원천 데이터를 대규모로 저장하고 활용 시점에 해석·변환하는 데이터 저장 아키텍처.
- 개념 : 다양한 형식의 원천 데이터를 대규모로 저장하고 활용 시점에 해석·변환하는 데이터 저장 아키텍처(**데이터 레이크**, Data Lake).
- 배경 및 필요성 : 정형·반정형·비정형 데이터를 원형에 가깝게 보존하고 후속 분석 요구에 유연하게 대응할 필요.
- 주요 목적 : 원천 보존과 분석 재사용성을 확보하며 데이터 탐색 비용 감소.

### Ⅱ. 데이터 레이크의 특징 및 장점

- 핵심 요약 : 원천 형식 수용·스키마 온 리드·저장·컴퓨트 분리는 다양한 형식의 데이터를 대규모로 저장하고 활용 시점에 해석하는 데이터 레이크 설계 방식.

1. 원천 형식 수용 : 정형·로그·미디어를 수집 → 다양한 분석 활용.
2. 스키마 온 리드 : 조회 시 구조·의미 적용 → 적재 전 변환 부담 감소.
3. 저장·컴퓨트 분리 : 저비용 객체 저장소와 엔진 결합 → 규모별 자원 확장.

### Ⅲ. 데이터 레이크의 구조 (흐름)

- 핵심 요약 : 원천 수집 → 영역별 원본 보존 → 카탈로그·계보 부여 → 품질·접근 통제 → 목적별 변환·분석.

```text
원천 수집
  ↓
영역별 원본 보존
  ↓
카탈로그·계보 부여
  ↓
품질·접근 통제
  ↓
목적별 변환·분석
```

```text
수집영역 → 원본(raw) → 정제(curated) → 제공(serve)
    ↓           ↓ 메타데이터·계보·권한 전 계층 적용
```

### Ⅳ. 데이터 레이크와 데이터 웨어하우스 비교

- 핵심 요약 : 스키마 적용 기준 — 데이터 레이크: 읽을 때 해석하는 스키마 온 리드; 데이터 웨어하우스: 적재 시 정의하는 스키마 온 라이트.

| 비교 축 | 데이터 레이크 | 데이터 웨어하우스 |
|---|---|---|
| 저장 데이터 | 다양한 원형·정형·비정형 | 주제별 정제·통합된 정형 데이터 |
| 스키마 적용 | 읽을 때 해석하는 스키마 온 리드 | 적재 시 정의하는 스키마 온 라이트 |
| 주요 활용 | 탐색·데이터과학·원천 재처리 | 정형 BI·일관된 KPI |

### Ⅴ. 데이터 레이크의 한계와 방안

- 핵심 요약 : 데이터 늪·접근·개인정보 위험 등 실제 위험을 원인에 맞는 통제와 지표로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 데이터 늪 | 카탈로그·품질·소유자 없으면 탐색 불가 | 카탈로그·계보·책임자·품질 게이트 운영 | 미분류 자산률 |
| 접근·개인정보 위험 | 원시데이터가 넓게 축적되어 오남용 가능 | 분류·최소권한·마스킹·보존기간 적용 | 비인가 접근 |
| 비용 누수 | 중복·저활용 데이터와 스캔성 쿼리 비용 증가 | 수명주기 계층화·중복제거·쿼리 비용관측 | 저장·쿼리 비용 |

### Ⅵ. 데이터 레이크에 대한 제언

- 핵심 요약 : 데이터 플랫폼 조직은 레이크를 영역·카탈로그·권한·보존 정책이 있는 관리형 제품으로 구축하고 분석 사용자 셀프서비스를 통제된 방식으로 제공.

- 실행 제안 : 플랫폼팀은 raw·정제·제공 영역별 카탈로그·접근정책·보존기간을 자동화하고 미분류 데이터 적재를 제한.

### Ⅶ. 결론

- 핵심 요약 : 데이터 레이크의 유연성은 메타데이터와 책임 있는 운영이 있을 때만 분석 재사용성으로 이어짐.
- 시사점 : 원천 저장의 유연성은 카탈로그·계보·품질·권한이 갖춰질 때 재사용 가능한 데이터 기반으로 작동.
