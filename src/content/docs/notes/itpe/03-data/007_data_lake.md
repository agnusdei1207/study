## 연관 키워드

- 데이터 레이크(Data Lake), 데이터 웨어하우스(DW, Data Warehouse), Schema-on-Read, ELT(Extract, Load, Transform)
- 메달리온 아키텍처(Medallion Architecture), 오픈 테이블 포맷(Open Table Format), ACID, 레이크하우스(Lakehouse)
- 데이터 스웜프(Data Swamp), 소형 파일 문제(Small File Problem), FinOps

## Ⅰ. 데이터 레이크의 개요

- 핵심 요약 : 모든 형태의 원본 데이터를 변환 없이 저비용으로 통합 보관하는 중앙 집중식 저장소.
- 개념 : 정형·반정형·비정형 데이터를 원래 포맷 그대로 객체 스토리지에 적재하고 분석 시점에 구조를 해석하는 **데이터 레이크** (Data Lake).
- 배경 및 필요성 : 데이터 웨어하우스(DW, Data Warehouse)의 정형 중심 구조와 높은 저장 단가로 원본 대량 보관이 곤란하고, 머신러닝·탐색 분석이 원본 데이터를 요구.
- 주요 목적 : **Schema-on-Read** (읽는 시점에 스키마를 적용하는 방식) 기반의 저비용·대용량 통합 저장 기반 구축.

## Ⅱ. 데이터 레이크의 특징 및 장점

- 핵심 요약 : 읽기 시점 스키마, 원본 선적재, 전 유형 수용, 오픈 포맷 신뢰성 보완의 저장 구조.

1. Schema-on-Read : 저장 시점의 스키마 강제 없음 → 적재 속도와 탐색 유연성 확보.
2. 선적재 **ELT** (Extract, Load, Transform) : 원본 우선 적재 후 필요 시점의 변환 → 재가공 자유도와 감사 추적.
3. 전 유형 수용 : 로그·이미지·영상·문서의 단일 저장소 통합 → 데이터 사일로 해소.
4. 경제성 : 저단가 객체 스토리지 기반의 수평 확장 → 대용량 보관 비용 절감.
5. 신뢰성 보완 : **오픈 테이블 포맷** (Open Table Format, 파일 위에 테이블 기능을 부여하는 포맷)의 **ACID** (Atomicity, Consistency, Isolation, Durability) 트랜잭션과 타임 트래블(과거 버전 조회) 제공 → 레이크의 트랜잭션 신뢰성 확보.

## Ⅲ. 데이터 레이크의 구조 (흐름)

- 핵심 요약 : 원본에서 서빙까지 품질을 단계적으로 높이는 3계층 구조와 기술 스택의 분층.

```text
[ 메달리온 아키텍처 ]

Bronze (Raw) : 원본 적재·감사 기반
   ↓ 정제·검증
Silver (Cleansed) : 표준화된 테이블
   ↓ 집계·모델링
Gold (Curated) : 비즈니스 서빙 계층
```

```text
[ 기술 스택의 3계층 ]

스토리지 : 객체 스토리지
   ↓
테이블 포맷 : Iceberg, Delta Lake, Hudi
   ↓
처리 엔진 : Spark, Trino
```

- **메달리온 아키텍처** (Medallion Architecture, 원본·정제·큐레이션 3단계로 품질을 단계적으로 높이는 레이크 설계 패턴)의 계층 구성요소 :
  1. Bronze : 추가 전용(Append-only) 원본 존으로 데이터 엔지니어가 감사·재처리에 사용.
  2. Silver : 결측·중복 정제와 스키마 검증 존으로 데이터 과학자의 분석 입력.
  3. Gold : 비즈니스 집계와 차원 모델 존으로 분석가·임원의 보고 서빙.

## Ⅳ. 데이터 웨어하우스·데이터 레이크·레이크하우스의 비교

- 핵심 요약 : 쓰기 시점 스키마(DW), 읽기 시점 스키마(레이크), 양쪽 수요의 통합(레이크하우스) 구도.

| 비교 축 | DW | 데이터 레이크 | 레이크하우스 |
| --- | --- | --- | --- |
| 스키마 적용 시점 | 쓰기 시점(Schema-on-Write) | 읽기 시점(Schema-on-Read) | 읽기 시점과 포맷 수준 검증 |
| 적재 방식 | ETL(Extract, Transform, Load) 정제 후 적재 | ELT 원본 선적재 | ELT와 ACID 트랜잭션 |
| 데이터 유형 | 정형 중심 | 전 유형 | 전 유형과 큐레이션 계층 |
| 강점 | 신뢰성·분석 성능 | 유연성·경제성 | 두 강점의 통합 |
| 적합 용도 | 표준 리포팅·정형 분석 | 탐색 분석·원본 보관 | 단일 플랫폼 통합 분석 |

- 선택 기준 : 엄격한 무결성과 표준 보고는 DW, 원본 보존·탐색은 데이터 레이크, 양쪽 수요의 단일 플랫폼 처리는 **레이크하우스** (Lakehouse) 우선.

## Ⅴ. 데이터 레이크의 한계와 방안

- 핵심 요약 : 스웜프 변질, 소형 파일, 쓰기 충돌, 비용 증가를 카탈로그·컴팩션·오픈 포맷·수명주기 정책으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **데이터 스웜프** (Data Swamp, 관리 부재로 찾고 쓸 수 없게 변질된 레이크) | 무분별 적재·메타데이터 부재 → 위치·정합성 상실 | 적재 시 카탈로그 자동 등록과 계층 승격 검증 의무화 | 카탈로그 등록률 |
| **소형 파일 문제** (Small File Problem) | 실시간 인입으로 파일 수 급증 → 메타 부하·스캔 지연 | 주기적 컴팩션(파일 병합)과 포맷의 자동 병합 기능 활용 | 파일당 평균 크기 |
| 동시 쓰기 충돌 | 트랜잭션 보장 부재 → 불완전 파일 잔류 | ACID 지원 오픈 테이블 포맷과 스냅샷 격리 도입 | 쓰기 충돌 건수 |
| 저장 비용 증가 | 보존 규칙 부재로 콜드 데이터 방치 | 수명주기 정책의 계층 이동과 압축 포맷 표준화 | 저장 단가, 콜드 데이터 비율 |

## Ⅵ. 데이터 레이크 발전에 대한 기술사적 제언

- 핵심 요약 : 레이크하우스 전환, 세밀한 접근 제어, 비용 운영 체계의 병행 설계.
- 아키텍처 조직 : DW 신뢰성과 레이크 경제성을 결합한 레이크하우스 전환을 데이터 플랫폼 로드맵에 반영.
- 보안 조직 : 객체 단위를 넘어 행·열 수준 접근 제어 정책으로 컴플라이언스 리스크 사전 차단.
- 운영 조직 : 비용 가시화와 스캔량 최적화를 상시 수행하는 **FinOps** (클라우드 비용의 가시화·최적화 운영 체계) 활동을 도입 단계부터 설계.

## Ⅶ. 결론

- 핵심 요약 : 데이터 레이크는 Schema-on-Read 기반의 경제적 통합 저장소이며 거버넌스가 생명력의 조건임.
- 신뢰성 보완 기술과 비용 관리를 갖춘 레이크만이 분석과 AI의 원본 기반으로 정착함.
