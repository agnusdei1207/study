## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터 유통 → **데이터 커머스**

## 30초 인출

- 본질: 데이터 커머스는 데이터를 상품·서비스로 구성해 거래하고 이용 조건을 관리하는 활동
- 메커니즘: 생산자가 권리·품질·갱신 기준을 확인해 상품 카탈로그에 등록하면 이용자가 검색·평가한 뒤 목적·범위·기간을 계약하고, 파일·API·분석환경으로 제공받아 이용기록·정산·종료 조건까지 관리
- 통찰: 데이터 거래는 파일 전달로 끝나지 않고 이용 조건이 핵심이므로 계약 조건을 계정·권한·API 범위·반출 승인 같은 기술 통제로 옮기고 계약 종료 시 접근 권한을 회수

<details>
<summary>핵심 용어</summary>

- **데이터 커머스** : 데이터를 상품화해 거래하는 활동
- **데이터 상품** : 데이터에 메타데이터·품질·권리·이용 조건을 갖춘 거래 대상
- **DaaS(Data as a Service)** : API 등으로 데이터를 서비스 형태로 제공
- **표준계약서** : 데이터 거래 조건을 유형별로 정리한 계약서 양식
- **데이터 안심구역** : 원본 반출 없이 통제된 환경에서 분석하는 공간
- **결합전문기관** : 가명정보의 결합을 수행하도록 지정된 기관

## 2~4교시 25점 답안

## Ⅰ. 데이터 커머스의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터 커머스** 는 데이터를 상품·서비스로 구성해 거래하고 이용 조건을 관리하는 활동 |
| 목적 | 생산자의 가치 회수와 이용자의 데이터 활용 촉진 |

## Ⅱ. 특징

| 특징 | 거래상 의미 |
|---|---|
| 무형 자산의 조건부 이용 | 이용 목적·범위·기간·재제공 조건이 핵심 |
| 품질과 출처의 가치 | 설명·갱신·품질·권리 정보가 평가와 가격에 영향 |
| 제공 채널의 다양성 | 파일·API·제한된 분석환경에 따라 통제가 달라짐 |

## Ⅲ. 거래 절차와 이용 통제

```text
생산자 데이터 → 권리·품질·갱신 기준 확인 → 상품 카탈로그
   ↓ 검색·평가
이용자 요청 → 목적·범위·기간 계약 → 파일/API/분석환경 제공 → 이용기록·정산·종료
```

```text
계약(이용자·목적·기간·재제공·반출) → 계정·권한·API 범위·반출 승인 → 이용기록
계약 변경·종료 시 → 권한 갱신·접근 회수·이행 확인
```

## Ⅳ. 거래 유형

과학기술정보통신부 데이터 표준계약서의 분류.

| 유형 | 내용 | 운영 초점 |
|---|---|---|
| 데이터 제공형 | 보유자가 상대방에게 기존 데이터를 제공 | 이용범위·갱신·재제공 조건 |
| 데이터 창출형 | 당사자 협력으로 새 데이터를 생성 | 산출물 권리·비용·책임 배분 |
| 데이터 가공서비스형 | 데이터를 정제·분석해 결과 제공 | 입력자료 보호·산출물 검수 |
| 데이터 중개거래형 | 플랫폼이 제공자와 이용자 사이를 중개 | 플랫폼 역할·수수료·분쟁 처리 |

제공 채널(파일·DaaS API·안심구역)은 거래 유형이나 법적 권한을 정하지 않으며, 서로 다른 개인정보처리자 간 가명정보 결합은 결합전문기관이 수행하고 반출에는 법에서 정한 승인이 필요하므로 일반 데이터 거래와 분리해 관리.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 계약마다 조건이 달라 이행 확인 곤란 | 표준계약 항목을 카탈로그와 연결, 승인 조건을 접근정책·이용기록에 반영 |
| 출처·품질·갱신 주기 불명확 | 상품 설명에 출처·품질 기준·갱신 주기·책임 주체 기록 |
| 제공 종료 후 접근 권한 잔존 | 계약 만료·변경 이벤트와 권한 회수 확인 연결 |

## Ⅵ. 제언

표준계약 항목을 상품 카탈로그와 접근 정책에 연결해 계약의 이행을 시스템으로 확인

```text
상품 등록(권리·품질) → 표준계약 → 접근 정책 자동 적용 → 이용기록 → 종료 시 권한 회수
```

| 구분 | 파일 전달 후 종료 | 제언: 계약-통제 연계 |
|---|---|---|
| 이용 범위 | 확인 곤란 | 권한·기록으로 확인 |
| 종료 | 권한 잔존 | 자동 회수 |
