## 지식 로드맵 내 현재 위치

데이터베이스 → 데이터 경제·거래 → 데이터 커머스

## 30초 인출

- 본질: **데이터 커머스는** 데이터를 상품이나 서비스로 만들어 거래하고 활용하는 활동
- 메커니즘: 생산자 → 상품화·거래 → 이용자, 각 단계에서 이용 조건과 보호 조치 관리
- 통찰: 한계: 계약마다 목적·재제공·보관 조건이 다르게 쓰이면 이행 확인이 어려움 → 방안: 표준계약 항목을 카탈로그와 연결하고 승인 조건을 접근정책·이용기록에 반영

- **데이터 커머스(Data Commerce)** : 데이터를 상품·서비스로 구성해 거래하고 이용 조건을 관리하는 활동
- **Data as a Service (DaaS)** : 데이터 자체 또는 데이터 처리 결과를 서비스 형태로 제공하는 방식
- **데이터 안심구역** : 반출이 제한된 데이터와 분석환경을 제공해 안전한 데이터 활용을 지원하는 공간
- **가명정보 결합** : 서로 다른 개인정보처리자의 가명정보를 법정 목적과 절차에 따라 전문기관이 결합하는 처리

## 2~4교시 25점 답안

## Ⅰ. 데이터 커머스의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터 커머스** 는 데이터를 상품·서비스로 구성해 거래하고 이용 조건을 관리하는 활동 |
| 목적 | 데이터 생산자의 가치 회수와 이용자의 데이터 활용 촉진 |

## Ⅱ. 데이터 커머스의 특징

| 특징 | 거래상 의미 |
|---|---|
| 무형 자산의 조건부 이용 | 소유물 전달보다 이용 목적·범위·기간·재제공 조건이 핵심 |
| 품질과 출처의 가치 | 데이터 설명·갱신·품질·권리 정보가 평가와 가격에 영향 |
| 제공 채널의 다양성 | 파일·API·제한된 분석환경에 따라 접근·기록·반출 통제가 달라짐 |

## Ⅲ. 데이터 상품화·계약·제공 체계와 이용 통제 프로세스

```text
생산자 데이터 → 권리·품질·갱신 기준 확인 → 상품 카탈로그
                                          ↓ 검색·평가
이용자 요청 → 목적·범위·기간 계약 → 파일/API/분석환경 제공
                                          ↓
                             이용기록·정산·종료 조건 확인
```

### 계약 조건을 기술 통제로 옮기는 하위 흐름

```text
계약: 이용자·목적·기간·재제공·반출 조건
          ↓ 항목별 접근정책으로 매핑
계정·권한·API 범위·반출 승인 → 이용기록
          ↓ 계약 변경·종료 시
       권한 갱신·접근 회수·이행 확인
```

파일 전달만으로 거래가 끝나지 않는다. 권리 확인부터 종료 조건까지 계약과 시스템 기록을 연결한다.

## Ⅳ. 거래 유형과 제공 방식의 비교

| 유형 | 거래 당사자·내용 | 운영상 초점 |
|---|---|---|
| 데이터 제공형 | 보유자가 이용자에게 기존 데이터를 제공 | 이용범위·갱신·재제공 조건 |
| 데이터 창출형 | 당사자 협력으로 새 데이터 생성 | 산출물 권리·비용·책임 배분 |
| 가공서비스형 | 데이터를 정제·분석해 결과 제공 | 입력자료 보호·산출물 검수 |
| 중개거래형 | 플랫폼이 제공자와 이용자 간 거래를 중개 | 플랫폼 역할·수수료·분쟁 처리 |

제공 채널은 파일 전달, DaaS API, 데이터 안심구역 등으로 구성 가능하며, 채널 자체가 거래유형이나 법적 권한을 정하지는 않음.

서로 다른 개인정보처리자 간 가명정보 결합은 지정 전문기관이 수행하며, 결합 결과의 외부 반출에는 법에서 정한 처리와 승인이 필요하다. 일반 데이터 거래의 제공 채널과 구분한다.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 계약마다 목적·재제공·보관 조건이 다르게 쓰이면 이행 확인이 어려움 | 표준계약 항목을 카탈로그와 연결하고 승인 조건을 접근정책·이용기록에 반영 |
| 출처·품질·갱신 주기가 불명확해 이용 가치 판단 곤란 | 상품 설명에 데이터 출처·품질 기준·갱신 주기와 책임 주체 기록 |
| 제공 종료 뒤 접근 권한이 남음 | 계약 만료·변경 이벤트와 권한 회수·자료 처리 확인을 연결 |

## Ⅵ. 제언

계약 조건이 상품 설명과 실제 접근 권한에서 어긋나면 이행 확인이 어렵다. 이용 목적·기간·재제공·반출 조건을 먼저 표준 항목으로 정하고 카탈로그·권한정책·이용기록에 같은 식별자로 연결한다.
