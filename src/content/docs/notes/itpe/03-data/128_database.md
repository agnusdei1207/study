## 2~4교시 25점 답안

## Ⅰ. 데이터베이스의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터베이스** 는 여러 사용자가 함께 이용하도록 통합·저장·관리하는 운영 데이터의 집합 |
| 목적 | 데이터 중복·종속을 줄이고 일관된 데이터 공유와 관리를 지원 |

## Ⅱ. 데이터베이스의 기본 특징

| 특성 | 의미 |
|---|---|
| 실시간 접근성 | 질의에 대해 필요한 데이터를 적시에 제공 |
| 계속적 변화 | 삽입·삭제·갱신으로 현재 상태를 반영 |
| 동시 공유 | 여러 사용자·응용의 공동 이용을 지원 |
| 내용에 의한 참조 | 물리 주소 대신 데이터 값과 조건으로 검색 |

## Ⅲ. ANSI/SPARC 3단계 스키마 체계와 사상 메커니즘

```text
사용자·응용 A ─ 외부 스키마 A ┐
사용자·응용 B ─ 외부 스키마 B ┴─ 외부/개념 사상
                                   ↓
                         개념 스키마: 전체 논리 구조
                                   ↓ 개념/내부 사상
                         내부 스키마: 파일·인덱스·배치
                                   ↓
                              저장 데이터
```

| 계층 | 관점·정의 | 사상 관계 |
|---|---|---|
| 외부 스키마 | 사용자·응용별 데이터 뷰 | 개념 스키마와 외부/개념 사상 |
| 개념 스키마 | 조직 전체 데이터의 논리 구조·관계·제약 | 외부 및 내부 계층의 기준 |
| 내부 스키마 | 저장 파일·레코드·인덱스 등 물리 구조 | 개념 스키마와 개념/내부 사상 |

### 계층 변경을 사상에서 흡수하는 흐름

```text
개념 스키마 변경 → 외부/개념 사상·뷰 조정 → 응용 뷰 영향 축소
내부 스키마 변경 → 개념/내부 사상 조정 → 개념 구조 영향 축소
```

사상이 모든 변경을 자동으로 숨기지는 않는다. 관계·제약의 의미 변화는 외부 뷰와 응용의 호환성을 별도로 검증한다.

## Ⅳ. 논리적·물리적 데이터 독립성 비교

| 독립성 | 변경 계층 | 영향을 분리하는 계층 | 예시 |
|---|---|---|---|
| 논리적 | 개념 스키마 | 외부 스키마 | 논리 구조 변경을 사용자 뷰에 흡수 |
| 물리적 | 내부 스키마 | 개념 스키마 | 파일 배치·인덱스 변경을 논리 구조에 흡수 |

데이터 독립성은 변경이 전혀 전파되지 않는다는 보장이 아니라 상위 계층에 대한 종속을 줄이는 구조적 성질이다.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 개념·내부 스키마 변경이 응용에 직접 전파되면 변경 영향·장애 범위가 커짐 | 논리 모델·외부 뷰·물리 매핑을 함께 관리하고 의존성·호환성을 검증 |
| 사용자별 데이터 정의가 달라 공유 데이터의 의미가 어긋남 | 개념 스키마의 용어·관계·제약을 공통으로 관리하고 외부 뷰와 대응 확인 |
| 물리 성능 조정이 논리 구조 변경으로 이어짐 | 인덱스·저장 배치 변경을 개념/내부 사상 경계에서 검증 |

## Ⅵ. 제언

스키마 변경이 응용에 직접 전파되면 장애 범위가 커진다. 변경이 잦은 업무부터 개념 모델·외부 뷰·물리 매핑의 대응 관계를 기록하고, 변경 시 영향을 받는 뷰와 응용을 검증한다.
