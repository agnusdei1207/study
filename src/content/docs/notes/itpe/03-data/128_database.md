## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터베이스 기초 → **데이터베이스(파일 시스템 vs 데이터베이스)**

## 30초 인출

- 본질: 데이터베이스는 여러 사용자가 함께 이용하도록 통합·저장·관리하는 운영 데이터의 집합
- 메커니즘: ANSI/SPARC 3단계 스키마(외부·개념·내부)를 사상으로 연결해, 개념 스키마 변경은 외부 뷰에서, 내부 스키마 변경은 개념 스키마에서 흡수하는 논리적·물리적 데이터 독립성을 확보
- 통찰: 데이터 독립성은 변경이 전혀 전파되지 않는다는 보장이 아니라 상위 계층의 종속을 줄이는 구조이므로, 관계·제약의 의미가 바뀔 때는 외부 뷰와 응용의 호환성을 별도로 검증

<details>
<summary>핵심 용어</summary>

- **데이터베이스(Database)** : 여러 사용자가 공유하는 통합·저장된 운영 데이터의 집합
- **DBMS** : 데이터베이스를 정의·조작·관리하는 소프트웨어
- **외부·개념·내부 스키마** : 사용자별 뷰 / 조직 전체의 논리 구조 / 물리 저장 구조
- **사상(Mapping)** : 스키마 계층 사이의 대응 관계
- **논리적 데이터 독립성** : 개념 스키마 변경이 외부 스키마에 영향을 주지 않는 성질
- **물리적 데이터 독립성** : 내부 스키마 변경이 개념 스키마에 영향을 주지 않는 성질
- **파일 시스템** : 응용별로 파일을 직접 관리하는 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. 데이터베이스의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터베이스** 는 여러 사용자가 함께 이용하도록 통합·저장·관리하는 운영 데이터의 집합 |
| 목적 | 중복·종속을 줄이고 일관된 데이터 공유와 관리 지원 |

## Ⅱ. 특징

| 특성 | 의미 |
|---|---|
| 실시간 접근성 | 질의에 필요한 데이터를 적시에 제공 |
| 계속적 변화 | 삽입·삭제·갱신으로 현재 상태 반영 |
| 동시 공유 | 여러 사용자·응용의 공동 이용 |
| 내용에 의한 참조 | 물리 주소가 아닌 값과 조건으로 검색 |

| 비교 | 파일 시스템 | 데이터베이스 |
|---|---|---|
| 데이터 정의 | 응용별로 파일 구조를 직접 관리 | 스키마로 중앙 관리 |
| 중복·종속 | 응용마다 중복, 구조 변경 시 응용 수정 | 중복 감소, 데이터 독립성 |
| 공유·동시성 | 응용별 제어 | DBMS가 동시성·무결성·복구 제공 |

## Ⅲ. ANSI/SPARC 3단계 스키마

```text
사용자·응용 A ─ 외부 스키마 A ┐
사용자·응용 B ─ 외부 스키마 B ┴ 외부/개념 사상
                                ↓
                  개념 스키마: 전체 논리 구조
                                ↓ 개념/내부 사상
                  내부 스키마: 파일·인덱스·배치 → 저장 데이터
```

| 계층 | 관점 | 사상 |
|---|---|---|
| 외부 스키마 | 사용자·응용별 뷰 | 개념 스키마와 외부/개념 사상 |
| 개념 스키마 | 조직 전체의 논리 구조·관계·제약 | 외부·내부 계층의 기준 |
| 내부 스키마 | 저장 파일·레코드·인덱스 | 개념 스키마와 개념/내부 사상 |

## Ⅳ. 논리적·물리적 데이터 독립성

```text
개념 스키마 변경 → 외부/개념 사상·뷰 조정 → 응용 뷰 영향 축소
내부 스키마 변경 → 개념/내부 사상 조정 → 개념 구조 영향 축소
```

| 독립성 | 변경 계층 | 영향을 분리하는 계층 | 예 |
|---|---|---|---|
| 논리적 | 개념 스키마 | 외부 스키마 | 논리 구조 변경을 사용자 뷰에 흡수 |
| 물리적 | 내부 스키마 | 개념 스키마 | 파일 배치·인덱스 변경을 논리 구조에 흡수 |

사상이 모든 변경을 자동으로 숨기지는 않으며 관계·제약의 의미 변화는 뷰와 응용의 호환성을 별도로 검증.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 스키마 변경이 응용에 직접 전파되어 영향 범위 확대 | 논리 모델·외부 뷰·물리 매핑을 함께 관리하고 의존성·호환성 검증 |
| 사용자별 데이터 정의가 달라 의미 불일치 | 개념 스키마의 용어·관계·제약을 공통 관리, 외부 뷰와 대응 확인 |
| 물리 성능 조정이 논리 구조 변경으로 이어짐 | 인덱스·저장 배치 변경을 개념/내부 사상 경계에서 검증 |

## Ⅵ. 제언

응용은 외부 뷰를 통해 접근하게 하고 물리 변경은 사상 계층에서 흡수하며, 의미가 바뀌는 변경은 호환성 시험을 거침

```text
응용 → 외부 뷰 → (사상) → 개념 스키마 → (사상) → 내부 스키마, 변경 시 호환성 시험
```

| 구분 | 응용의 직접 파일·테이블 접근 | 제언: 뷰·사상 경유 |
|---|---|---|
| 변경 영향 | 응용 전반 | 계층 내 흡수 |
| 의미 변경 | 발견 지연 | 호환성 시험 |
