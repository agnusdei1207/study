## 답안 골격
```text
[필터링] ◀━━ 머리: Ⅶ 내 의견 (협업 필터링의 콜드 스타트 극복을 위해 콘텐츠 기반 필터링 결합 하이브리드 추천 구축)
 ┃
 ┣━ Ⅰ 개요 ───── 방대한 데이터 집합에서 노이즈를 제거하고 사용자의 선호나 특정 조건에 부합하는 가치 있는 정보만 선별·추출하는 기법
 ┣━ Ⅱ 특징 ───── 정보 과부하(Information Overload) 해소 · 추천 시스템의 핵심 기제 · 사용자 맞춤형 개인화 · 희소성 문제 수반
 ┣━ Ⅲ 구조 ───── 협업 필터링(사용자 기반, 아이템 기반, 잠재 요인) / 콘텐츠 기반 필터링(속성 프로파일) / 하이브리드 필터링
 ┣━ Ⅳ 흐름 ───── ① 사용자 행동(평점·클릭) 수집 → ② 상호작용 행렬 구축 → ③ 유사도(코사인·피어슨) 계산 또는 행렬 분해(SVD) → ④ Top-N 추천 아이템 필터링
 ┣━ Ⅴ 비교 ───── 협업 필터링 vs 콘텐츠 기반 필터링 (사용자 간 유사 행동 기반/우연한 발견 vs 아이템 고유 속성 기반/콜드스타트 강함)
 ┗━ Ⅵ 실무 ───── 신규 사용자/아이템 유입 시 콜드 스타트(Cold Start) / 사용자-아이템 평점 행렬의 극단적 희소성(Sparsity)
```
- 필수 키워드: 협업 필터링(Collaborative Filtering) · 콘텐츠 기반 필터링(CBF) · 콜드 스타트(Cold Start) · 희소성(Sparsity) · 행렬 분해(Matrix Factorization) · SVD · 코사인 유사도
- 기출: 139회 4교시 1번 `빅데이터 분석기법 중 클러스터링, 필터링, 이상치 탐지` → Ⅰ 개념 + Ⅲ 추천/필터링 기법 유형 + Ⅴ 비교

## 한 줄 본질
- 수억 개의 상품·콘텐츠 속 정보 과부하 한계 → 사용자 행동 이력 유사도(협업) 및 메타데이터 속성 일치도(콘텐츠)를 기반으로 개인화 후보군 압축 추출 → 맞춤형 탐색 비용 최소화 / 신규 유저 콜드스타트 발생

## 핵심 그림
```text
[필터링 기법 양대 산맥과 하이브리드 구조]

 [ 협업 필터링 (Collaborative Filtering) ]
   - 사용자 기반: 나와 취향이 비슷한 "다른 사용자"가 좋아한 아이템 추천
   - 아이템 기반: 내가 좋아한 아이템과 "함께 소비된 아이템" 추천
   * 데이터: User-Item 평점 행렬 (A, B 둘 다 영화 X, Y를 좋아함 -> A가 본 Z를 B에게 추천)

 [ 콘텐츠 기반 필터링 (Content-based Filtering) ]
   - 아이템의 "텍스트/장르/감독" 등 메타 속성 분석 (TF-IDF, 임베딩)
   * 데이터: Item-Feature 프로파일 (SF 영화를 자주 본 유저에게 신작 SF 추천)

 ┌────────────────────────────────────────────────────────┐
 │ 하이브리드 필터링 (Hybrid Filtering)                   │
 │ : 신규 유저는 콘텐츠 기반으로 추천(Cold Start 극복)    │
 │   -> 행동 로그 축적 시 협업 필터링/행렬분해로 전환!    │
 └────────────────────────────────────────────────────────┘
```

## 핵심 용어
- 콜드 스타트(Cold Start): 신규 사용자나 신규 등록된 아이템은 이전 상호작용 이력(평점, 클릭)이 전혀 없어 협업 필터링 추천을 생성할 수 없는 근본적 문제
- 행렬 분해(Matrix Factorization): 거대하고 희소한 사용자-아이템 평점 행렬 $R$을 저차원의 사용자 잠재 요인 행렬 $P$와 아이템 잠재 요인 행렬 $Q$의 곱($R \approx P \times Q^T$)으로 분해하는 기법

## 핵심 통찰
- 협업 필터링은 '아이템의 내용을 전혀 몰라도' 훌륭한 추천을 만듦 → 음악 장르나 악기를 분석하지 않아도 듣는 사람들의 겹침 패턴만으로 취향 저격 가능
- 그러나 '필터 버블(Filter Bubble)'에 갇히는 부작용 초래 → 사용자가 좋아했던 것과 유사한 것만 계속 필터링해 주다 보면 새로운 장르에 대한 탐색 기회가 박탈됨
- 따라서 실무 추천 아키텍처는 1단계 가벼운 필터링(Retrieval, 수십만 개에서 수백 개로 압축)과 2단계 딥러닝 정밀 순위화(Ranking, 수백 개를 클릭 확률 순 정렬)의 2-Stage 구조로 동작

## 딸려 나오는 하위 토픽
| 하위 토픽 | 상위 구조 속 위치 | 한 줄 |
|---|---|---|
| SVD / ALS (교차최소제곱) | 행렬 분해 기반 협업 필터링 | 희소 행렬의 빈칸(미시청)을 예측하기 위해 잠재 요인을 번갈아 최적화하는 분산 알고리즘 |
| 블룸 필터(Bloom Filter) | 대규모 데이터 원천 필터링 | 해시 함수와 비트 배열을 이용해 원소가 집합에 속하는지 초고속으로 판별하는 확률적 자료구조 |

## 이웃 토픽과 구분
- 사용자 기반(User-based) vs 아이템 기반(Item-based): 사용자 기반 = 사용자가 늘어날수록 유사도 계산량 급증 / 아이템 기반 = 아이템 간 관계는 상대적으로 정적이어서 사전 계산(Pre-computing) 가능하므로 실무에서 압도적 선호

## 문제·원인·대책
- 적용 상황: 신규 론칭 OTT 스트리밍 서비스의 개인화 추천
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 신규 가입자에게 추천 콘텐츠를 표시하지 못해 첫날 이탈률 40% 도달 | 평점 데이터 부재에 따른 협업 필터링의 콜드 스타트(Cold Start) | 온보딩 시 선호 장르/배우 설문 기반 콘텐츠 기반 필터링 즉시 제공 | 신규 사용자 첫 주 리텐션 35% 개선 |
| 전체 영화의 99.9%가 비어있는 극단적 희소 행렬로 유사도 왜곡 | 롱테일(Long-tail) 비인기 영화의 평점 결핍 | Implicit Feedback(시청 시간, 클릭) 활용 및 ALS 행렬 분해 적용 | 추천 커버리지 및 정밀도 동시 향상 |
