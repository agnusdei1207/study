## 큰 그림과 30초 인출

```text
              [업무 목적·품질정책]
                       │
                       ▼
 [표준·규칙] ──▶ [측정·진단] ──▶ [개선·통제]
 용어·도메인       Profiling       Cleansing
 업무규칙          DQI·Threshold   원인 제거
      ▲                 │              │
      └─────────────────┴──── [모니터링] ──┘
                              │
                        [신뢰 가능한 데이터]
```

- 본질: **업무에 적합한 품질기준을 정의하고 데이터 생명주기에서 측정·개선·통제하는 지속적 관리체계**
- 암기: `정-기-측-분-개-감` = 정책 → 기준 → 측정 → 분석 → 개선 → 감시
- 판단축: 정확성·완전성·일관성·유효성·적시성·유일성
- 구분: 거버넌스는 의사결정권과 책임, 품질관리는 데이터 오류의 측정과 개선

## 예상문제

> 데이터 품질관리의 개념과 관리체계, 품질지표 및 수행절차를 설명하고 지속 가능한 품질관리를 위한 고려사항을 논하시오. (25점)

## Ⅰ. 데이터 신뢰성을 생명주기에서 보장하는 품질관리 개요

- 정의: **데이터 품질관리(DQM)**는 데이터가 업무 목적과 사용자 요구에 적합하도록 정책·표준·조직·프로세스·도구를 통해 품질을 계획, 측정, 개선, 통제하는 활동
- 목적: 업무 오류·규제 위험·분석 왜곡을 줄이고 데이터 활용의 신뢰도 확보
- 필요성: 원천의 오류가 연계·DW·AI 학습데이터로 전파되면 사후 정제만으로 원인과 재발을 통제하기 어려움

#### 한줄 요약

- 데이터 품질은 절대적 정확성이 아니라 정해진 업무 목적에 사용할 수 있는 적합성(Fitness for Use)으로 판정함

## Ⅱ. 업무 기준과 지속 개선을 결합한 품질관리 특징

| 특징 | 핵심 내용 | 관리 효과 |
|---|---|---|
| **업무 목적성** | 중요 데이터와 품질 목표를 업무 영향도에 따라 선정 | 비용 대비 효과 집중 |
| **측정 가능성** | 품질지표·산식·임계치·측정주기 정의 | 객관적 상태 판정 |
| **전 생명주기성** | 생성·수집·저장·연계·활용·폐기 단계 통제 | 오류 전파 차단 |
| **예방 중심성** | 입력 제약·표준·데이터 계약으로 원천 오류 방지 | 반복 정제 비용 감소 |
| **지속 개선성** | 측정→원인→개선→재측정의 폐루프 운영 | 재발 방지와 품질 추세 관리 |

#### 한줄 요약

- 품질관리는 일회성 정제사업이 아니라 오류가 생기는 규칙·프로세스·소유권을 고치는 운영활동임

## Ⅲ. 조직·기준·프로세스·도구의 데이터 품질관리 체계

```text
[조직·책임]
 CDO/위원회 ─ Data Owner ─ Data Steward
       │              │
       ▼              ▼
[정책·표준] ───▶ [품질 프로세스] ◀─── [지원도구]
 용어·도메인       계획·측정·개선        Profiling
 업무규칙          변경·이슈·성과         Cleansing
       └──────────────┬──────────────────┘
                      ▼
                [품질지표·성과]
```

| 구성요소 | 핵심 역할 | 대표 산출물 |
|---|---|---|
| **조직·책임** | 품질 의사결정, 데이터 소유·관리·실행 책임 배분 | R&R·협의체·에스컬레이션 |
| **정책·표준** | 중요 데이터, 품질원칙, 용어·도메인·업무규칙 정의 | 품질정책·표준·규칙집 |
| **프로세스** | 측정, 이슈, 개선, 변경, 성과관리 | 진단·개선계획·이슈대장 |
| **도구** | 프로파일링·규칙검증·정제·모니터링 자동화 | 품질 대시보드·오류목록 |

#### 한줄 요약

- 품질도구만 도입해서는 책임과 기준이 없고, 정책만 수립해서는 실제 오류가 측정·개선되지 않음

## Ⅳ. 기준 정의에서 재발 방지까지의 품질관리 절차

```text
① 대상·목표 선정
   └─ 중요 데이터·업무 영향·품질 목표
          ↓
② 품질기준·지표 정의
   └─ 규칙·산식·임계치·주기·책임자
          ↓
③ 프로파일링·측정
   └─ 값 분포·NULL·중복·패턴·참조관계
          ↓
④ 오류·근본원인 분석
   └─ 입력·연계·변경·표준·프로세스 원인
          ↓
⑤ 정제·프로세스 개선
   └─ 데이터 보정 + 입력/연계 통제 변경
          ↓
⑥ 재측정·모니터링
   └─ 효과·추세·재발·성과 검증
```

| 품질차원 | 판정 질문 | 예시 측정 관점 |
|---|---|---|
| **정확성** | 실제·기준값과 맞는가 | 기준원천 대조 오류율 |
| **완전성** | 필수 값이 존재하는가 | 필수항목 누락률 |
| **일관성** | 시스템·시점 간 모순이 없는가 | 원천-대상 불일치율 |
| **유효성** | 형식·도메인·업무규칙을 지키는가 | 규칙 위반률 |
| **적시성** | 필요한 시점까지 최신 상태인가 | 갱신 SLA 준수율 |
| **유일성** | 같은 실체가 중복되지 않는가 | 중복 레코드 비율 |

#### 한줄 요약

- 품질지표는 이름만 열거하지 않고 산식·임계치·측정주기·책임자를 함께 정의해야 통제가 됨

## Ⅴ. 거버넌스·표준화·MDM·품질관리 비교

| 구분 | 데이터 거버넌스 | 데이터 표준화 | MDM | 데이터 품질관리 |
|---|---|---|---|---|
| **핵심 질문** | 누가 어떤 원칙으로 결정하는가 | 같은 의미와 형식을 쓰는가 | 핵심 실체의 기준값은 무엇인가 | 업무에 쓸 수 있는 품질인가 |
| **대상** | 조직 전체 데이터 의사결정 | 용어·단어·도메인·코드 | 고객·상품 등 마스터 | 값·구조·프로세스·서비스 |
| **주요 활동** | 정책·책임·위원회·성과 | 정의·등록·변경·준수 | 식별·통합·동기화 | 측정·원인분석·정제·예방 |
| **대표 산출물** | 정책·R&R·로드맵 | 표준사전·도메인 | Golden Record | 지표·진단·개선계획 |
| **관계** | 상위 통제체계 | 품질 규칙의 기준 | 중요 데이터 일관성 수단 | 품질을 검증·개선하는 실행체계 |

#### 한줄 요약

- 거버넌스가 책임을 정하고 표준·MDM이 기준을 제공하면 품질관리가 그 기준의 준수와 효과를 측정함

## Ⅵ. 사후 정제를 예방 통제로 바꾸는 실무 고려사항

| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 같은 오류의 **반복 발생** | 값만 정제하고 입력·업무 원인 미개선 | 근본원인 분류, UI·API·업무규칙 개선 | 오류 재발 방지 |
| 시스템 간 **기준 불일치** | 용어·도메인·코드·마스터의 분산 관리 | 표준사전·MDM·참조데이터 동기화 | 연계·집계 일관성 확보 |
| 스키마 변경 후 **파이프라인 장애** | 생산자-소비자 간 변경계약 부재 | 데이터 계약·호환성 검증·계보 기반 영향분석 | 변경 오류의 배포 전 탐지 |
| 지표가 좋아도 **업무 불만 지속** | 기술지표와 업무 중요도·사용자 요구 단절 | Critical Data Element 선정, 업무 영향 기반 가중 | 품질투자의 우선순위 확보 |
| AI 결과의 **신뢰 저하** | 라벨·대표성·계보·편향 통제 부족 | 학습데이터 품질기준, 버전·계보·분포 변화 감시 | 재현성과 모델 위험 통제 |

#### 한줄 요약

- 정제 자동화보다 중요한 것은 오류가 데이터 파이프라인에 들어오기 전에 계약·제약·표준으로 막는 것임

## Ⅶ. 품질을 제품의 운영 SLO로 관리하는 결론

- **[Data Product별 Owner와 품질 SLO의 내재화]**: 중앙 품질팀이 모든 오류를 사후 정제하면 원천 업무의 책임이 약해지고 데이터 규모 증가를 따라가지 못함
- 나라면: 중요 데이터 제품마다 Owner·Steward를 지정하고 정확성·완전성·적시성 SLO를 데이터 계약과 배포 파이프라인에 연결하여, 위반 시 원인 시스템과 개선기한이 자동 추적되게 운영

#### 한줄 요약

- 지속 가능한 데이터 품질은 보고서 점수가 아니라 생산자가 품질기준을 지키고 소비자가 신뢰 수준을 확인할 수 있는 상태임

## 1교시 10점 답안 발췌

### 1. 정의

- 데이터 품질관리는 데이터가 업무 목적에 적합하도록 정책·표준·조직·프로세스·도구로 품질을 계획·측정·개선·통제하는 활동

### 2. 체계와 절차

```text
조직·책임 + 정책·표준 + 프로세스 + 도구
                  ↓
대상 → 기준 → 측정 → 원인 → 개선 → 감시
```

| 품질차원 | 핵심 판정 |
|---|---|
| 정확성·완전성 | 기준값과 일치하고 필수 값이 존재하는가 |
| 일관성·유효성 | 시스템 간 모순 없이 규칙을 지키는가 |
| 적시성·유일성 | 필요한 시점에 최신이며 중복이 없는가 |

### 3. 차별화 제언

- 중요 데이터의 품질 SLO를 데이터 계약·CI/CD 검증에 연결하여 사후 정제를 원천 예방 통제로 전환
