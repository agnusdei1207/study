## 지식 로드맵 내 현재 위치

지식 위치: 자료처리·데이터 → 데이터 거버넌스 → **데이터 품질관리**

## 30초 인출

- 본질: **데이터 품질관리는** 데이터가 업무 목적에 맞게 쓰이도록 품질 기준을 정하고 오류를 측정·개선하는 지속적 관리 활동
- 메커니즘: 중요한 데이터 선정 → 품질 기준·책임 지정 → 측정·원인 분석 → 원천·처리 과정 개선 → 재측정
- 통찰: 사후 정제에 의존하지 않고 원천 시스템 입력 및 연계 파이프라인 단계에서 오류를 차단하는 Shift-Left 품질 거버넌스 구축 필요

<details>
<summary>핵심 용어</summary>

- **DQM(Data Quality Management)** : 업무 목적에 맞는 데이터 품질을 정의·측정·개선하는 관리 활동
- **품질 차원** : 정확성·완전성·일관성·유효성·적시성·유일성 등 품질을 판단하는 관점
- **정확성** : 데이터 값이 실제 대상·업무 사실과 맞는 정도
- **완전성** : 필요한 값이 빠지지 않은 정도
- **일관성** : 같은 사실을 나타내는 값·규칙이 서로 모순되지 않는 정도
- **유효성** : 값이 형식·범위·업무 규칙을 충족하는 정도
- **적시성** : 필요한 시점에 최신 데이터를 이용할 수 있는 정도
- **유일성** : 동일한 대상이 불필요하게 중복되지 않은 정도
- **CDE(Critical Data Element)** : 업무 영향이 커서 우선 관리하는 핵심 데이터 항목
- **데이터 프로파일링** : 값의 분포·누락·중복·형식 등을 분석해 데이터 상태를 파악하는 활동

</details>

## 2~4교시 25점 답안

## Ⅰ. 데이터 품질관리의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터 품질관리는** 데이터가 업무 목적에 맞게 쓰이도록 품질 기준을 정하고 오류를 측정·개선하는 지속적 관리 활동 |
| 목적 | 데이터 오류로 인한 업무·분석 왜곡 감소와 신뢰할 수 있는 활용 |

## Ⅱ. 데이터 품질관리의 특징

| 특징 | 의미 |
|---|---|
| 업무 목적 기준 | 사용처에 맞는 품질 차원·허용 수준 선정 |
| 원인 중심 개선 | 오류 위치뿐 아니라 입력·변환 원인 추적 |
| 반복 측정 | 수정 후 같은 규칙으로 재측정·추세 확인 |

## Ⅲ. 품질관리 체계와 개선 절차

```text
업무 목적·핵심 데이터(CDE)
    ↓ 정책·표준: 품질 차원·허용 기준
책임 조직: 소유자·오류 조치 담당
    ↓ 도구: 프로파일링·규칙 검사
진단·원인 개선·재측정 프로세스
```

### 진단과 개선 흐름

```text
핵심 데이터·품질 기준 선정
    ↓ 프로파일링·규칙 검사
원천·변환 단계의 오류 원인 분석
    ↓ 오류 수정·발생 원인 개선
재측정·추세 확인
```

## Ⅳ. 품질 차원과 관리 요소의 관계

```text
업무 목적 → 관리할 품질 차원 선택 → 차원별 규칙·측정값 정의
                                     ↓
원천·업무 사실 대조 ─ 정확성 ─┐
필수값·형식·범위 검사 ─ 완전성·유효성 ├→ 오류 위치와 원인 식별
시스템 간 값·갱신 시점 비교 ─ 일관성·적시성 ┘
```

| 차원 | 측정 예 | 오류 예 |
|---|---|---|
| 정확성 | 원천·업무 사실과 대조 | 잘못된 주소 |
| 완전성 | 필수값 누락률 | 고객 식별값 누락 |
| 일관성 | 시스템·항목 간 값 비교 | 서로 다른 상태 코드 |
| 유효성 | 형식·범위·업무 규칙 검사 | 허용 범위 밖 날짜 |
| 적시성 | 발생·갱신 시점의 차이 | 늦게 반영된 주문 |
| 유일성 | 동일 개체의 중복률 | 중복 고객 레코드 |

차원은 평가 목적에 맞게 선택하며, 모든 조직이 동일한 여섯 차원을 의무적으로 쓰는 것은 아님.

### 관리 요소

| 구성 | 역할 |
|---|---|
| 정책·표준 | 품질 기준, 데이터 정의, 허용 수준 |
| 책임 조직 | 데이터 소유자·관리자와 오류 조치 주체 |
| 프로세스 | 진단·개선·재측정·변경관리 |
| 도구 | 프로파일링, 규칙 검사, 품질 지표 |

| 오류 위치 | 개선 방향 |
|---|---|
| 입력·수집 | 입력 검증·기준정보 정비 |
| 변환·연계 | 매핑 규칙·스키마 변경 통제 |
| 이용·분석 | 지표 정의·조회 조건 일치 |

**우선순위와 예방**

| 판단 | 적용 방안 |
|---|---|
| 업무 영향 | 의사결정·법정 보고·고객 서비스에 쓰이는 **CDE** 우선 |
| 오류 빈도 | 반복 오류의 원천 시스템·업무 절차 개선 |
| 변경 위험 | 데이터 생산자·소비자 사이의 스키마·품질 기준 합의 |

**Data Contract** 같은 생산자·소비자 합의는 예방 수단 중 하나이며 데이터 품질관리 전체와 동일하지 않음.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 오류 건수만 줄이고 업무 영향은 남음 | 업무 영향·사용처를 반영해 관리 항목 선정 |
| 분석 저장소에서만 반복 정제 | 원천 입력·변환 규칙까지 원인 추적 |
| 담당 조직이 불명확함 | 항목별 책임자와 조치·승인 절차 지정 |

## Ⅵ. 제언

업무 영향도가 높은 핵심 데이터 요소(CDE)를 중심으로 데이터 유입 지점부터 자동화된 검증 규칙을 적용하고 오류 발생 즉시 원천 담당자에게 피드백하는 무결성 체계 구축.

### Shift-Left 기반 데이터 품질관리 체계

```text
[원천 데이터 생성] ──► [입력 유효성 검증] ──► [ETL 파이프라인]
                             │                     │
                             ▼ (오류 즉시 차단)    ▼ (정합성 규칙 검사)
[데이터 레이크/DW] ◄── [품질 인증 완료] ◄── [Steward 자동 피드백]
```

### 선택 근거: 제언: Shift-Left 품질관리

| 구분 | 사후 정제 방식 | 제언: Shift-Left 품질관리 |
|---|---|---|
| 통제 시점 | DW/마트 적재 후 배치 정제 | 원천 생성 및 연계 파이프라인 즉시 검증 |
| 비용 구조 | 오류 전파로 정제 비용 급증 | 사전 차단을 통한 품질 비용 최소화 |
| 관리 주체 | 데이터 분석가/엔지니어 | 데이터 생산자 및 Data Steward |
