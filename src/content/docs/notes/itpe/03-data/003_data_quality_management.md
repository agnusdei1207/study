## 연관 키워드

- 데이터 품질관리(DQM), 데이터 프로파일링, PDCA, 1-10-100 규칙, 데이터 품질 지수(DQI)
- 정확성·완전성·일관성·최신성·유효성·유일성, Shift-Left, Data Observability, Data Steward

## Ⅰ. 데이터 품질관리의 개요

- 핵심 요약 : 데이터 전 수명주기에 걸쳐 품질을 지속적으로 확보·개선하는 체계적 관리 활동.
- 개념 : 비즈니스 목적 달성을 위해 데이터의 생성·저장·가공·유통·폐기 전 구간에서 정확성·완전성·일관성 등을 지속 확보하고 개선하는 활동인 **데이터 품질관리** (DQM, Data Quality Management).
- 배경 및 필요성 :
  1. 입력 단계 검증 부재, 레거시 연계 인터페이스 불일치, 스키마 변경 시 영향도 평가 누락 등 품질 저하 원인이 상존함.
  2. 오류를 늦게 발견할수록 수습 비용이 커진다는 **1-10-100 규칙** (Rule of Ten)에 따라 사전 예방이 유리함.
  3. 인공지능(AI, Artificial Intelligence)·머신러닝(ML, Machine Learning) 모델이 불량 데이터를 학습하면 성능이 떨어지는 Garbage In, Garbage Out 현상을 막아야 함.
- 주요 목적 : 데이터 기반 의사결정의 신뢰성을 확보하고 데이터 거버넌스의 핵심 기반을 구축.

## Ⅱ. 데이터 품질관리의 특징 및 장점

- 핵심 요약 : 값·구조 품질의 이원 관리, 6대 품질 지표 기반 정량 진단, PDCA 순환이 맞물린 상시 관리 체계.

1. 전 수명주기 관리 : 생성부터 폐기까지 품질을 지속 보증 → 사후 발견 오류의 누적 감소.
2. 이원화된 관리 대상 : 값 품질(업무 규칙 검증, **데이터 프로파일링**과 결함 정제)과 구조 품질(표준 메타데이터 준수, 논리·물리 모델 검증)을 분리 관리 → 결함 원인별 조치의 정밀화.
3. 정량 지표 체계 : DAMA(Data Management Association)와 DMBOK(Data Management Body of Knowledge) 기준의 6대 품질 지표로 측정 → 품질 수준의 객관적 비교와 추세 관리 가능.
4. **PDCA** (Plan-Do-Check-Act) 순환 : 계획·수행·측정·개선을 반복 → 품질 수준의 지속 향상.
5. 파이프라인 자동화 : ETL(Extract, Transform, Load)과 ELT(Extract, Load, Transform)의 중간 품질 게이트로 자동 검증 → 불량 데이터의 하위 적재 차단.

## Ⅲ. 데이터 품질관리의 구조 (흐름)

- 핵심 요약 : 거버넌스 정책 아래 값·구조 품질관리와 PDCA 프로세스가 놓이고, 파이프라인에는 품질 게이트가 배치되는 흐름.

```text
[ 데이터 품질관리 프레임워크 ]

 데이터 거버넌스 정책
          ↓
 데이터 값 품질관리 (업무 규칙, 프로파일링)
 데이터 구조 품질관리 (표준 메타, 모델 검증)
          ↓
 PDCA 관리 프로세스 (계획→수행→측정→개선)
```

```text
[ 파이프라인 품질 검증 흐름 ]

 원천 시스템
      ↓
 인입 (검증: 스키마 계약)
      ↓
 프로파일링 엔진
      ↓
 품질 게이트 (실패 시 알림·격리)
      ↓
 타깃 저장소 적재
```

- PDCA 생애주기 프로세스 :
  1. Plan(계획) : 핵심 데이터 요소(CDE, Critical Data Element) 식별, 데이터 표준 및 품질 SLA(Service Level Agreement) 정의.
  2. Do(수행) : 데이터 프로파일링 실행과 업무 규칙 기반 자동 검증 로직 가동.
  3. Check(측정·평가) : 데이터 품질 지수(DQI, Data Quality Index) 산출과 결함 원인 분석(Root Cause Analysis).
  4. Act(정제·개선) : 오류 데이터의 수동·자동 정제(Cleansing)와 원천 인터페이스·파이프라인 결함의 영구 조치.

| 품질 지표 | 세부 정의 | 진단 및 검증 방식 |
|---|---|---|
| 정확성(Accuracy) | 실세계 값 또는 원천 데이터와의 일치 여부 | 원천 서류 대조, 형식 규칙(Regex) 검증 |
| 완전성(Completeness) | 필수 속성값의 결측치(Null, 공백) 부재 비율 | Null 비율 프로파일링, 필수 컬럼 제약 확인 |
| 일관성(Consistency) | 동일 데이터의 여러 테이블·시스템 간 충돌 없는 일치 | 외래키 무결성, 상호 참조 정합성 쿼리 |
| 최신성(Timeliness) | 업무 발생 시점과 DB 반영 시점 사이 지연의 허용 범위 | 최종 갱신 타임스탬프, 배치 주기 점검 |
| 유효성(Validity) | 도메인, 코드, 포맷, 범위 등 사전 정의 규칙 충족 | 코드 테이블 대조, 체크 제약조건(Check Constraint) |
| 유일성(Uniqueness) | 동일 식별자 레코드의 중복 저장 부재 | 기본키·유니크 키 제약, 중복 레코드 집계 |

## Ⅳ. 전통적 DQM과 현대적 DQM의 비교

- 핵심 요약 : 사후 배치·정적 규칙 중심의 전통적 방식에서 실시간·동적 학습 중심의 옵저버빌리티 체계로 전환.

| 비교 축 | 전통적 DQM | 현대적 DQM (Data Observability 연계) |
|---|---|---|
| 검증 시점 | ETL 완료 후 배치 기반 사후 검증 | 파이프라인 인입 구간의 Shift-Left 사전 검증 |
| 탐지 방식 | 담당자 주관의 정적 Rule-base 검증 | 통계·머신러닝 기반 동적 임계치 자동 학습 |
| 탐지 대상 | 정형 테이블 중심 | 다변량 이상치, 텍스트·이미지 등 비정형 데이터 포함 |
| 실패 대응 | 적재 이후의 사후 조치 | 하위 적재 차단과 DLQ(Dead Letter Queue) 격리 |

- 선택 기준 : 검증 대상이 정형 테이블 중심인지, 파이프라인 실시간 인입이 필요한지에 따라 두 방식의 적용 범위를 정함.

## Ⅴ. 데이터 품질관리의 한계와 방안

- 핵심 요약 : 사후 적발식 검증, 정적 규칙, 소유권 불명확을 사전 검증·동적 탐지·데이터 스튜어드 체계로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 사후 적발식 검증 | ETL 후 배치 프로파일링으로 불량 데이터가 이미 분석·대시보드에 전파 | Shift-Left 품질 게이트웨이(Great Expectations, Soda) 구축, 검증 실패 시 파이프라인 차단 및 DLQ 격리 | 불량 데이터 전파 건수, 검증 실패 차단율 |
| 정적 규칙 기반 탐지 한계 | 주관적 Rule-base 의존으로 추세 변화·다변량 이상치·비정형 품질 저하 탐지 불가 | 통계적 공정 관리(SPC, Statistical Process Control)와 데이터 옵저버빌리티 엔진 도입, 동적 임계치 자동 학습 | 이상 징후 탐지 리드타임 |
| 데이터 소유권 불명확 | 운영팀·현업 생산자·분석가 간 책임 소재 모호로 근본 원인 해결 지연 | 도메인별 Data Product Owner와 Data Steward 명문화, 품질 SLA에 인센티브·페널티 연계 | 결함 조치 소요 기간 |

## Ⅵ. 데이터 품질 관리체계 정착을 위한 기술사적 제언

- 핵심 요약 : 현업 데이터 오너십 부여, DataOps 기반 상시 검증, 품질 지표와 경영 KPI(Key Performance Indicator)의 연계.
- 품질 책임을 IT 개발 부서에만 두지 않고, 원천 데이터를 생성하는 현업 부서에 데이터 스튜어드 역할을 지정하는 방향이 필요함.
- 일회성 감사 대신 CI(Continuous Integration)/CD(Continuous Delivery) 파이프라인에 검증 도구를 단위 테스트처럼 편입한 상시 감시 체계를 구축하는 것이 바람직함.
- 품질 수준을 경영진 대시보드와 담당자 성과 지표에 직접 연결하여 전사 데이터 거버넌스 문화를 조성함.

## Ⅶ. 결론

- 핵심 요약 : 데이터 품질관리는 PDCA와 자동화 품질 게이트로 구현하는 전사적 상시 품질 체계.
- 시사점 : 조직(Data Steward), 프로세스(PDCA), 도구(Data Observability)의 세 축을 함께 정비해야 실효성이 확보됨.
