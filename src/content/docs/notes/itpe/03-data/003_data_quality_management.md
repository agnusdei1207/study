## 지식 로드맵 내 현재 위치

지식 위치: 자료처리·데이터 → 데이터 거버넌스 → **데이터 품질관리**

## 30초 인출

- 본질: **데이터 품질관리**는 데이터가 업무 목적에 맞게 쓰이도록 품질 기준을 정하고 오류를 측정·개선하는 지속적 관리 활동
- 메커니즘: 중요한 데이터 선정 → 품질 기준·책임 지정 → 측정·원인 분석 → 원천·처리 과정 개선 → 재측정

<details>
<summary>핵심 용어</summary>

- **DQM(Data Quality Management)** : 업무 목적에 맞는 데이터 품질을 정의·측정·개선하는 관리 활동
- **품질 차원** : 정확성·완전성·일관성·유효성·적시성·유일성 등 품질을 판단하는 관점
- **정확성** : 데이터 값이 실제 대상·업무 사실과 맞는 정도
- **완전성** : 필요한 값이 빠지지 않은 정도
- **일관성** : 같은 사실을 나타내는 값·규칙이 서로 모순되지 않는 정도
- **유효성** : 값이 형식·범위·업무 규칙을 충족하는 정도
- **적시성** : 필요한 시점에 최신 데이터를 이용할 수 있는 정도
- **유일성** : 동일한 대상이 불필요하게 중복되지 않은 정도
- **CDE(Critical Data Element)** : 업무 영향이 커서 우선 관리하는 핵심 데이터 항목
- **데이터 프로파일링** : 값의 분포·누락·중복·형식 등을 분석해 데이터 상태를 파악하는 활동

</details>

## 1교시 10점 답안

### Ⅰ. 데이터 품질관리의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터 품질관리**는 데이터가 업무 목적에 맞게 쓰이도록 품질 기준을 정하고 오류를 측정·개선하는 지속적 관리 활동 |
| 목적 | 데이터 오류로 인한 업무·분석 왜곡 감소와 신뢰할 수 있는 활용 |

### Ⅱ. 주요 품질 차원

| 차원 | 확인할 내용 |
|---|---|
| 정확성·완전성 | 실제 값과 맞는가, 필요한 값이 있는가 |
| 일관성·유효성 | 값 사이에 모순이 없는가, 규칙을 지키는가 |
| 적시성·유일성 | 제때 갱신되는가, 불필요한 중복이 없는가 |

### Ⅲ. 관리 흐름

```text
핵심 데이터·품질 기준 선정
            ↓
프로파일링·규칙 검사
            ↓
원천·변환 단계의 오류 원인 분석
            ↓
오류 수정·발생 원인 개선
            ↓
재측정·추세 확인
```

- 제언: 모든 항목에 같은 기준을 적용하기보다 업무 영향이 큰 데이터부터 관리.

## 2~4교시 25점 답안

## Ⅰ. 데이터 품질관리의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터 품질관리**는 데이터가 업무 목적에 맞게 쓰이도록 품질 기준을 정하고 오류를 측정·개선하는 지속적 관리 활동 |
| 목적 | 데이터 오류로 인한 업무·분석 왜곡 감소와 신뢰할 수 있는 활용 |

## Ⅱ. 품질 차원과 측정

| 차원 | 측정 예 | 오류 예 |
|---|---|---|
| 정확성 | 원천·업무 사실과 대조 | 잘못된 주소 |
| 완전성 | 필수값 누락률 | 고객 식별값 누락 |
| 일관성 | 시스템·항목 간 값 비교 | 서로 다른 상태 코드 |
| 유효성 | 형식·범위·업무 규칙 검사 | 허용 범위 밖 날짜 |
| 적시성 | 발생·갱신 시점의 차이 | 늦게 반영된 주문 |
| 유일성 | 동일 개체의 중복률 | 중복 고객 레코드 |

차원은 평가 목적에 맞게 선택하며, 모든 조직이 동일한 여섯 차원을 의무적으로 쓰는 것은 아님.

## Ⅲ. 관리 체계

| 구성 | 역할 |
|---|---|
| 정책·표준 | 품질 기준, 데이터 정의, 허용 수준 |
| 책임 조직 | 데이터 소유자·관리자와 오류 조치 주체 |
| 프로세스 | 진단·개선·재측정·변경관리 |
| 도구 | 프로파일링, 규칙 검사, 품질 지표 |

## Ⅳ. 진단과 개선 흐름

```text
핵심 데이터·품질 기준 선정
            ↓
프로파일링·규칙 검사
            ↓
원천·변환 단계의 오류 원인 분석
            ↓
오류 수정·발생 원인 개선
            ↓
재측정·추세 확인
```

| 오류 위치 | 개선 방향 |
|---|---|
| 입력·수집 | 입력 검증·기준정보 정비 |
| 변환·연계 | 매핑 규칙·스키마 변경 통제 |
| 이용·분석 | 지표 정의·조회 조건 일치 |

## Ⅴ. 우선순위와 예방

| 판단 | 적용 방안 |
|---|---|
| 업무 영향 | 의사결정·법정 보고·고객 서비스에 쓰이는 **CDE** 우선 |
| 오류 빈도 | 반복 오류의 원천 시스템·업무 절차 개선 |
| 변경 위험 | 데이터 생산자·소비자 사이의 스키마·품질 기준 합의 |

**Data Contract** 같은 생산자·소비자 합의는 예방 수단 중 하나이며 데이터 품질관리 전체와 동일하지 않음.

## Ⅵ. 한계와 대응

| 한계 | 대응 방안 |
|---|---|
| 오류 건수만 줄이고 업무 영향은 남음 | 업무 영향·사용처를 반영해 관리 항목 선정 |
| 분석 저장소에서만 반복 정제 | 원천 입력·변환 규칙까지 원인 추적 |
| 담당 조직이 불명확함 | 항목별 책임자와 조치·승인 절차 지정 |

## Ⅶ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 분석 단계에서만 오류를 발견해 원천 수정 전에 여러 소비 시스템으로 확산 | 핵심 데이터 항목 하나를 선정해 생산 시스템의 배포·연계 지점에서 품질 규칙을 검사하고, 위반 시 담당자에게 되돌리는 절차부터 적용 |
