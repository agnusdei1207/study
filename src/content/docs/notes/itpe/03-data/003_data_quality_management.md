## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터 관리 → **데이터 품질관리**

## 30초 인출

- 본질: 데이터 품질관리는 업무 목적에 맞는 데이터 품질 기준을 정하고 측정·개선하는 지속적인 관리 활동
- 메커니즘: 품질 기준과 핵심 데이터를 정의하고 프로파일링과 규칙 검사로 진단해 원인을 개선하고 다시 측정하는 순환
- 통찰: 오류를 사후에 정제하면 같은 오류가 되풀이되므로 발생 원인이 되는 입력·연계 단계에 검증 규칙을 넣어 오류를 앞 단계에서 차단

<details>
<summary>핵심 용어</summary>

- **데이터 품질관리(DQM)** : 데이터 품질을 정의·측정·개선하는 관리 활동
- **품질 차원** : 정확성·완전성·일관성·유효성·적시성·유일성 등 품질을 나누어 보는 기준
- **핵심 데이터 요소(CDE)** : 업무 영향이 커서 우선 관리하는 데이터 항목
- **데이터 프로파일링** : 값의 분포·누락·중복 등을 분석해 실태를 파악하는 활동
- **품질 규칙** : 값이 만족해야 하는 형식·범위·업무 조건

</details>

## 2~4교시 25점 답안

## Ⅰ. 데이터 품질관리의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터 품질관리** 는 업무 목적에 맞는 품질 기준을 정하고 측정·개선하는 관리 활동 |
| 목적 | 신뢰할 수 있는 데이터의 확보와 데이터 기반 의사결정의 정확성 |

## Ⅱ. 특징

| 특징 | 의미 |
|---|---|
| 목적 적합성 | 업무 목적에 따른 품질 기준 |
| 지속 관리 | 일회성 정제가 아닌 순환 |
| 원인 중심 | 오류 원인 단계의 개선 |

## Ⅲ. 품질 차원과 관리 순환

### 품질 차원

| 차원 | 의미 |
|---|---|
| 정확성 | 값이 실제 사실과 일치 |
| 완전성 | 필요한 값이 빠지지 않음 |
| 일관성 | 같은 사실의 값이 서로 모순되지 않음 |
| 유효성 | 형식·범위·업무 규칙을 충족 |
| 적시성 | 필요한 시점에 최신 데이터 이용 |
| 유일성 | 같은 대상의 중복이 없음 |

### 관리 순환

```text
   ┌→ 기준·핵심 데이터 정의
   │        ↓
   │   진단(프로파일링·규칙 검사)
   │        ↓
   │   원인 분석 → 개선(입력·연계 단계 검증)
   │        ↓
   └── 재측정·모니터링
```

## Ⅳ. 사후 정제와 사전 예방 방식의 비교

| 구분 | 사후 정제 | 사전 예방(발생 단계 통제) |
|---|---|---|
| 대응 시점 | 오류 발생 후 | 입력·연계 시점 |
| 재발 | 반복 | 감소 |
| 비용 | 반복 발생 | 규칙 구축 후 감소 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 모든 데이터를 같은 수준으로 관리해 비용 과다 | 핵심 데이터 요소를 선정해 우선 관리 |
| 정제해도 같은 오류가 반복 | 입력·연계 단계에 검증 규칙 적용 |
| 품질 기준의 부서별 상이 | 공통 품질 기준과 책임자 지정 |

## Ⅵ. 제언

핵심 데이터 요소부터 품질 규칙을 정하고 오류가 생기는 입력·연계 단계에서 검증해 차단

```text
핵심 데이터 요소 선정 → 품질 규칙 정의 → 입력·연계 단계에서 검증 → 위반 건 격리·수정
```

| 구분 | 사후 정제 | 제언: 발생 단계 검증 |
|---|---|---|
| 오류 유입 | 계속 | 차단 |
| 대상 | 전체 | 핵심 데이터 우선 |

## 출제 이력과 검증 출처

- 제132~140회 정보관리기술사 공식 문제지에서 데이터 품질관리 일반을 직접 묻는 문항 없음. AI 학습용 데이터 품질관리는 별도 토픽에서 다룸
