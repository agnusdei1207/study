## Ⅰ. NoSQL의 개요

- 핵심 요약 : NoSQL(Not Only SQL)은 관계형 테이블·고정 스키마에 한정되지 않는 비관계형 데이터 저장·처리 시스템 계열.
- 개념 : NoSQL(Not Only SQL)은 관계형 테이블·고정 스키마에 한정되지 않는 비관계형 데이터 저장·처리 시스템 계열.
- 배경 및 필요성 : 대규모·분산·반정형 데이터와 빠른 스키마 변화에 대한 요구.
- 주요 목적 : 데이터 접근 패턴에 맞는 수평 확장성과 유연한 모델 제공.

## Ⅱ. NoSQL의 특징 및 장점

- 핵심 요약 : 유연한 스키마: 문서·키 구조의 변화 흡수 → 진화하는 데이터 수용; 수평 확장: 샤딩·복제로 노드 추가 → 대규모 처리량 확장; 모델 다양성: 키값·문서·컬럼패밀리·그래프 선택 → 질의 특성에 적합.

1. 유연한 스키마: 문서·키 구조의 변화 흡수 → 진화하는 데이터 수용
2. 수평 확장: 샤딩·복제로 노드 추가 → 대규모 처리량 확장
3. 모델 다양성: 키값·문서·컬럼패밀리·그래프 선택 → 질의 특성에 적합

## Ⅲ. NoSQL의 구조 (흐름)

- 핵심 요약 : 요구·접근패턴 분석 → 데이터 모델 선택 → 파티션·복제 설계 → 일관성·장애 모델 설정 → 성능·복구 검증.

```text
요구·접근패턴 분석
  ↓
데이터 모델 선택
  ↓
파티션·복제 설계
  ↓
일관성·장애 모델 설정
  ↓
성능·복구 검증
```

- 핵심 구성 : 키값 → 세션·캐시

```text
키값 → 세션·캐시
문서 → 콘텐츠·프로필
컬럼패밀리 → 시계열·대규모 쓰기
그래프 → 관계 탐색
```

## Ⅳ. 비교: 관계형 DB / NoSQL

- 핵심 요약 : 트랜잭션·일관성 기준 — 관계형 DB: 강한 제약·조인에 강함; NoSQL: 제품별 일관성·트랜잭션 범위 확인.

| 비교 기준 | 관계형 DB | NoSQL |
| --- | --- | --- |
| 스키마·질의 | 정규화 테이블·SQL·조인 | 모델별 스키마·API·제한된 조인 |
| 트랜잭션·일관성 | 강한 제약·조인에 강함 | 제품별 일관성·트랜잭션 범위 확인 |

## Ⅴ. NoSQL의 한계와 방안

- 핵심 요약 : 조인·제약 제한·일관성 모델 차이 등 실제 위험을 원인에 맞는 통제와 지표로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 조인·제약 제한 | 복잡한 관계 질의가 어려움 | 관계형 저장소와 역할 분리·중복 모델링 검토 | 질의 지연 |
| 일관성 모델 차이 | 복제 지연·최종 일관성으로 오래된 값 관찰 가능 | 요구별 일관성 수준·읽기 보장 명세 | 오래된 값 읽기 비율 |
| 운영 종속 | 제품별 파티션·쿼리 언어·복구 방식 상이 | 개방 형식·이관 절차·장애복구 훈련 | 복구시간·이관비용 |

## Ⅵ. NoSQL의 제언

- 핵심 요약 : 데이터 아키텍트는 용어의 유행보다 키·질의·트랜잭션 요구를 기준으로 저장소를 선정하고 관계형 DB와의 일관성 경계를 명시.
- 실행 제안 : 데이터 플랫폼팀은 대표 질의·일관성 요구별 벤치마크를 수행하고 복제 지연과 복구 결과를 승인 기준에 반영.

## Ⅶ. NoSQL의 결론

- 핵심 요약 : NoSQL은 단일 대체 기술이 아닌 분산 데이터 모델의 선택지이며, 접근패턴과 일관성 요구에 맞춘 설계가 핵심.
- 시사점 : 저장소 선택은 분산 확장성만이 아니라 질의 패턴·트랜잭션 경계·장애 시 일관성 요구를 기준으로 판단.
