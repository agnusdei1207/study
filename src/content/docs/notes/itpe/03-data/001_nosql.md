## 30초 인출

- 본질: NoSQL(Not Only SQL)은 키·문서·컬럼 패밀리·그래프 등 관계형 테이블 이외의 데이터 모델로 저장·조회하는 데이터베이스 계열
- 메커니즘: 조회·갱신 패턴에 맞는 데이터 모델 선택 → 모델에 맞는 분할·복제·일관성 수준 설계 → 대표 질의·장애 시험으로 검증
- 통찰: 데이터 모델만 먼저 정하면 실제 질의·일관성 요구와 어긋나는 재설계 비용이 발생하므로 대표 조회·갱신 패턴의 사전 분석과 부하 시험 기반의 모델 선택

<details>
<summary>핵심 용어</summary>

- **NoSQL(Not Only SQL)** : 관계형 테이블 외의 키·문서·컬럼 패밀리·그래프 모델로 데이터를 저장·조회하는 데이터베이스 계열
- **Key-Value(키·값)** : 고유 키로 값을 직접 조회하는 모델로, 세션·캐시처럼 단순 키 조회가 중심인 데이터의 저장 수단
- **Document(문서)** : JSON과 유사한 문서 단위에 속성을 묶어 저장하고 문서 내 필드 조회를 지원하는 모델
- **Column Family Database(컬럼 패밀리 데이터베이스)** : 행 키와 컬럼 패밀리 단위로 희소한 대량 데이터를 저장·분산 쓰기하는 모델(Wide-Column)
- **Graph(그래프)** : 노드와 간선으로 개체와 관계를 저장하고 연결 순회 질의를 지원하는 모델
- **BASE(Basically Available, Soft state, Eventual consistency)** : 가용성과 최종 일관성을 우선하는 분산 설계 특성으로, 제품·설정별 보장 수준의 확인 대상
- **Sharding(샤딩)** : 하나의 데이터 집합을 샤드 키 기준으로 여러 노드에 나누어 저장·처리하는 수평 확장 방식
- **Replication(복제)** : 동일 데이터의 사본을 여러 노드에 유지해 가용성·읽기 성능을 높이는 방식

## 2~4교시 25점 답안

## Ⅰ. NoSQL의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **NoSQL** 은 키·문서·컬럼 패밀리·그래프 등 관계형 테이블 이외의 데이터 모델로 저장·조회하는 데이터베이스 계열 |
| 목적 | 고정 스키마·관계 조인의 제약을 피한 대규모 데이터의 분산 저장·조회와 유연한 스키마 운영 |

## Ⅱ. NoSQL의 핵심 특징

| 특징 | 의미 |
|---|---|
| 유연한 스키마 | 문서·행별로 구조가 달라도 저장 가능한 가변 구조 |
| 접근 패턴 중심 설계 | 정규화보다 함께 읽는 단위(aggregate) 중심의 데이터 구성 |
| 수평 확장 전제 | 샤딩·복제를 구조에 내장한 노드 추가 방식의 확장 |
| 일관성 수준의 선택 | 제품·설정에 따라 강한 일관성~최종 일관성의 범위 지정 |

## Ⅲ. NoSQL 선택·모델링 절차

### 조회 패턴 기반 모델링 흐름

```text
업무 요구·데이터 특성 분석
    ↓
대표 조회·갱신 패턴 정의
    ├─ 키 단일 조회 → Key-Value
    ├─ 문서 단위 조회·가변 속성 → Document
    ├─ 희소한 대량 속성·대량 쓰기 → Column Family
    └─ 관계 순회 탐색 → Graph
    ↓
데이터 경계·키(분할 기준)·복제 정책 설계
    ↓
대표 질의·장애 시험으로 모델·설정 검증
```

모델링의 출발점이 정규화된 스키마가 아니라 질의 패턴이라는 점이 관계형 설계와의 구별점. 질의에 필요한 데이터를 한 읽기 단위로 모으는 방향으로 구성.

### Key-Value·문서·컬럼 패밀리·그래프의 관계

```text
단순 키 조회(Key-Value)
    └─ 값 내부 구조화·필드 조회 필요 → Document
              └─ 행 단위 대량 희소 속성·분산 쓰기 → Column Family
관계 탐색이 주 업무 → Graph(별도 계열)
```

## Ⅳ. 데이터 모델 유형·관계형 데이터베이스 비교

| 모델 | 기본 구조 | 강점 | 대표 활용 |
|---|---|---|---|
| **Key-Value** | 키 → 값 | 단순·고속 키 조회 | 세션·캐시·순위표 |
| **Document** | 문서(JSON 유사) | 가변 속성과 문서 단위 조회 | 상품·콘텐츠 관리 |
| **Column Family** | 행 키 → 컬럼 패밀리 | 희소 데이터·대량 분산 쓰기 | 시계열 로그·센서 데이터 |
| **Graph** | 노드·간선 | 다단계 관계 탐색 | 추천·부정 거래 탐지 |

| 비교축 | 관계형 DBMS | NoSQL |
|---|---|---|
| 데이터 구조 | 고정 스키마·테이블·조인 | 유연 스키마·모델별 구조 |
| 질의 방식 | SQL·복합 조건 질의 | 모델별 API·키·문서 기반 조회 |
| 트랜잭션 | ACID 중심 | 문서·키 단위 제한적 보장 후 확장 |
| 확장 방식 | 주로 수직 확장·복제 | 샤딩 기반 수평 확장 전제 |

관계형과 NoSQL은 배타적 선택이 아닌 업무별 조합이므로 데이터 소유·동기화 책임의 명시가 전제.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 모델 선택과 실제 질의의 불일치로 재설계 비용 발생 | 대표 조회·갱신 패턴의 사전 분석과 부하 시험 기반 채택 |
| 샤드 키 편중에 따른 핫스팟·전체 샤드 조회 | 키 분포 측정 후 분할 기준 조정과 라우팅 효율 점검 |
| 복제 지연·최종 일관성에 따른 오래된 값 조회 | 업무별 읽기 보장 수준 정의와 일관성 설정 검증 |
| 조인·다건 트랜잭션 부족에 따른 응용 보완 코드 증가 | 트랜잭션 요구 업무는 관계형과의 역할 분담 설계 |

## Ⅵ. 제언

대표 조회·갱신 패턴과 일관성 요구를 먼저 확정하고, 후보 모델의 부하·장애 시험 결과로 데이터 모델과 분할·복제 설정의 채택

### 모델 선정 검증 절차

```text
대표 질의·갱신·데이터량 정의
    ↓
후보 모델별 시험 데이터 적재
    ↓
조회 지연·쓰기 처리량·일관성 관찰
    ├─ 기준 충족 → 모델·설정 확정
    └─ 미충족 → 모델 교체 또는 키·설정 조정
    ↓
장애 시나리오 시험 후 운영 전환
```

### 샤드 키 결정 확대: 분할 기준 판정

```text
후보 키 선정
    ↓
키 분포·증가 패턴 측정
    ├─ 편중 낮음·조건 포함 조회 → 채택
    └─ 편중 높음 → 해시 분산·복합 키 재검토
```

### 선택 근거: 모델 선정 기준 비교

| 구분 | 스키마 우선 설계 | 제언: 질의 패턴 우선 설계 |
|---|---|---|
| 설계 출발점 | 정규화된 데이터 구조 | 대표 조회·갱신 패턴 |
| 조정 비용 | 질의 변경 시 조인·색인 재설계 | 읽기 단위 중심이라 질의 변경 흡수 용이 |
| 확장 판단 | 이후 분할 설계로 별도 진행 | 키·분할 정책을 설계 초기에 함께 결정 |
