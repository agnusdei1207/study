## 연관 키워드

- 데이터베이스(Database), DBMS(Database Management System), 3단계 스키마(ANSI/SPARC), 데이터 독립성
- ACID, MVCC, RBAC, 샤딩(Sharding), NewSQL, CQRS, 폴리글랏 퍼시스턴스(Polyglot Persistence)
- 객체-관계 임피던스 불일치, 메타데이터 관리, 데이터 계보(Lineage)

## Ⅰ. 데이터베이스의 개요

- 핵심 요약 : 조직의 업무 수행에 필요한 데이터를 통합, 저장, 운영, 공유하도록 구조화한 영속적 데이터 저장소.
- 개념 : 여러 응용 시스템과 다수 사용자가 함께 쓰도록 구조화된 상호 관련 데이터의 집합 (**데이터베이스**, Database). 이를 생성·관리하는 소프트웨어는 **데이터베이스 관리 시스템** (DBMS, Database Management System)이라 함.
- 배경 및 필요성 : 파일 시스템 기반 관리는 데이터 중복, 종속성, 불일치를 낳아 관리 비용과 오류 가능성을 키우므로, 조직 전체 데이터를 일관되게 보장하는 통합 관리 체계가 필요함.
- 주요 목적 : 데이터 중복 최소화, 응용 프로그램과 저장 구조의 분리 보장, 동시 공유 접근 제공, 무결성과 보안성 유지.

데이터베이스의 4대 본질 특성은 다음과 같다.

1. **통합된 데이터** (Integrated Data) : 같은 데이터의 불필요한 중복을 배제.
2. **저장된 데이터** (Stored Data) : 컴퓨터가 접근 가능한 매체에 영속 저장.
3. **운영 데이터** (Operational Data) : 조직의 고유 업무 수행에 필수인 데이터.
4. **공용 데이터** (Shared Data) : 여러 사용자와 응용 프로그램이 동시에 공유.

## Ⅱ. 데이터베이스의 특징 및 장점

- 핵심 요약 : 저장 구조 분리, 동시성 제어, 장애 회복, 보안성이 파일 시스템과 구별되는 체계적 관리 능력을 만듦.

1. **데이터 독립성** (Data Independence, 저장 구조와 응용 프로그램을 분리하는 특성) : **3단계 스키마** (ANSI/SPARC 3-Schema, 외부·개념·내부 스키마로 나누는 구조)로 물리적·논리적 독립성을 보장 → 저장 구조 변경 시 응용 프로그램 수정을 최소화.
2. **동시성 제어** : 락(Lock)과 **다중 버전 동시성 제어** (MVCC, Multi-Version Concurrency Control) 메커니즘으로 동시 트랜잭션의 일관성 유지 → 다중 사용자 환경의 정합성 확보.
3. **장애 회복** : **ACID** (Atomicity, Consistency, Isolation, Durability) 속성으로 원자성, 일관성, 고립성, 영속성을 보장 → 장애 시 트랜잭션 단위의 정확한 복구 가능.
4. **보안성** : 사용자 인증과 **역할 기반 접근 제어** (RBAC, Role-Based Access Control), 암호화를 결합 → 테이블과 컬럼 단위의 접근 통제.

## Ⅲ. 데이터베이스의 구조 (흐름)

- 핵심 요약 : 외부, 개념, 내부의 3단계 스키마를 거치며 사용자 뷰가 물리 저장 구조로 변환되는 단계적 추상화.
- 외부 스키마 : 사용자별로 필요한 부분만 보여주는 뷰.
- 개념 스키마 : 전사 논리 구조를 정의하며 ERD(Entity-Relationship Diagram)와 테이블 구조로 표현.
- 내부 스키마 : 인덱스, 파티션, 블록 등 물리 저장 구조를 정의.

```text
[ ANSI/SPARC 3단계 구조 ]

외부 스키마 (사용자별 뷰)
      ↓ 논리적 독립성
개념 스키마 (전사 논리 구조)
      ↓ 물리적 독립성
내부 스키마 (저장·인덱스 구조)
      ↓
디스크 (파일, 블록, 페이지)
```

```text
[ DBMS 질의 처리 흐름 ]

응용 프로그램 → SQL 질의
      ↓
질의 처리기 (파싱·최적화)
      ↓
실행 엔진 → 버퍼 관리자
      ↓
스토리지 관리자 → 디스크
```

## Ⅳ. 파일 시스템과의 비교

- 핵심 요약 : 파일 시스템 대비 DBMS는 중복 제거, 독립성, 동시성 제어, 장애 회복에서 체계적 관리 능력이 우위.

| 비교 항목 | 파일 시스템 | 데이터베이스 관리 시스템 (DBMS) |
| :--- | :--- | :--- |
| 데이터 중복 | 부서별 중복 저장으로 일관성 훼손 | 단일 저장 지점으로 중복 배제 |
| 데이터 독립성 | 파일 구조 변경 시 응용 프로그램 수정 필요 | 3단계 스키마로 독립성 보장 |
| 동시성 제어 | 파일 단위 잠금으로 제한적 | 트랜잭션 단위의 세밀한 제어 |
| 장애 회복 | 백업과 복원에 의존 | 로그 기반 회복과 시점 복구(Point-in-time Recovery) 가능 |
| 보안 | 운영체제(OS, Operating System) 수준 파일 권한만 제공 | 테이블과 컬럼 단위 접근 제어 |
| 질의 언어 | 없음 (응용 프로그램 코드로 처리) | SQL(Structured Query Language) 선언적 질의 |

- 선택 기준 : 데이터 공유, 무결성, 동시 접근 요구가 있으면 DBMS, 단일 사용자의 단순 로그 저장이면 파일 시스템을 검토.

## Ⅴ. 데이터베이스의 장점과 한계

- 핵심 요약 : 일관성과 보안성은 우수하지만 단일 노드 확장성과 객체-관계 간 불일치가 한계.

1. 데이터 일관성과 무결성 보장 : 중복 최소화와 제약 조건으로 정합성 유지.
2. 데이터 독립성 : 응용 프로그램과 저장 구조의 결합도 완화.
3. 동시 공유 접근 : 다수 사용자와 응용 프로그램의 동시 접근 지원.
4. 장애 회복과 보안 : 트랜잭션 로그 기반 회복과 세분화된 접근 제어.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| 단일 노드 수직 확장 한계 | 초대규모 데이터에서 하드웨어 스펙이 한계에 도달 | **샤딩** (Sharding, 키 기준으로 데이터를 여러 노드에 분산), **NewSQL** (분산 SQL 데이터베이스로의 전환), **CQRS** (Command Query Responsibility Segregation, 명령과 조회 책임의 분리) | 노드별 처리량, 샤드 불균형률 |
| 객체-관계 임피던스 불일치 (Object-Relational Impedance Mismatch) | 객체지향 모델과 관계형 모델의 구조 차이로 매핑 비용 증가 | 도메인 주도 설계(DDD, Domain-Driven Design) 기반 바운디드 컨텍스트 수립, **폴리글랏 퍼시스턴스** (Polyglot Persistence, 용도별로 저장소를 나누는 방식) 적용 | 매핑 코드 비중, 변경 영향 범위 |
| 스키마 침식과 기술 부채 | 빠른 출시로 비정규화와 미사용 테이블이 누적 | 메타데이터 저장소(MDR, Metadata Repository)와 데이터 카탈로그의 정례 관리, 데이터 계보(Lineage) 추적 도구 도입 | 미사용 테이블 비율 |

## Ⅵ. 데이터베이스에 대한 기술사적 제언

- 핵심 요약 : 다중 저장소 전략을 기본으로 삼고 클라우드 관리형 서비스로 전환하는 것이 현대 데이터 아키텍처의 출발점.

1. 다중 저장소 전략 : 모든 워크로드를 단일 RDBMS(Relational Database Management System)에 맡기면 성능 병목이 생기므로, 트랜잭션, 고속 캐싱, 전문 검색, AI(Artificial Intelligence) 벡터 검색을 용도에 맞는 저장소로 나눌 필요.
2. 관리형 전환 : 설치와 운영에 드는 엔지니어링 자원을 줄이기 위해 자동 백업, 다중 가용 영역 기반 장애 조치, 자동 확장을 제공하는 클라우드 관리형 데이터베이스(PaaS, Platform as a Service)를 우선 검토할 필요.

```text
[ 현대 다중 저장소 아키텍처 ]

트랜잭션 처리 → PostgreSQL, MySQL
고속 캐싱     → Redis, Memcached
전문 검색     → Elasticsearch
AI 벡터 검색  → Milvus, Qdrant
문서 저장     → MongoDB
```

## Ⅶ. 결론

- 핵심 요약 : 데이터베이스는 3단계 스키마와 ACID 기반으로 데이터 독립성과 일관성을 보장하는 조직 데이터의 핵심 인프라.
- 시사점 : 단일 DBMS로 모든 워크로드를 감당하기 어려워진 환경에서는 메타데이터와 거버넌스를 함께 갖추는 것이 데이터 자산화의 핵심 과제.
