## 연관 키워드

- OLAP(Online Analytical Processing), OLTP(Online Transaction Processing), 데이터 웨어하우스(DW, Data Warehouse), 다차원 큐브, 차원, 측정값
- ETL(Extract, Transform, Load), 롤업(Roll-up), 드릴다운(Drill-down), 슬라이싱(Slicing), 다이싱(Dicing), 피보팅(Pivoting)

## Ⅰ. OLAP의 개요

- 핵심 요약 : 통합 데이터를 복수의 분석 축으로 배열해 관점을 바꾸어 가며 대화식으로 분석하는 의사결정 지원 기술.
- 개념 : **데이터 웨어하우스**(DW, Data Warehouse)에 통합된 데이터를 다차원 구조로 배열하고 복수의 분석 축을 교차 조회하는 분석 처리 기술(**OLAP**, Online Analytical Processing).
- 배경 및 필요성 : 단건 트랜잭션 처리에 최적화된 **OLTP**(Online Transaction Processing) 운영 시스템으로는 전사 추세 파악에 필요한 대규모 집계와 다차원 조회를 감당하기 어려움.
- 주요 목적 : 시간, 지역, 제품 같은 복수 축의 교차 분석으로 경영진과 분석가의 전략적 의사결정 지원.

## Ⅱ. OLAP의 특징 및 장점

- 핵심 요약 : 다차원 모델, 사전 집계, 대화식 연산의 결합이 분석 응답성과 의사결정 품질로 이어지는 구조.

1. 다차원 모델 : 분석 관점인 **차원**(Dimension)과 집계 수치인 **측정값**(Measure)으로 데이터를 배열 → 좌표 지정만으로 복수 관점의 교차 조회 수행.
2. 다차원 큐브 : 차원 조합별 집계를 미리 계산해 보관하는 **다차원 큐브**(Cube) → 질의 시점의 재계산 없이 즉시 응답.
3. 읽기 위주 워크로드 : 주기적 배치 적재와 빈번한 조회를 전제로 설계 → 분석 질의의 예측 가능한 응답성 확보.
4. 대화식 연산 : 큐브 대상의 계층 이동, 단면 추출, 관점 회전 연산 지원 → 요약에서 세부까지 단계적 추적 가능.

## Ⅲ. OLAP의 구조 (흐름)

- 핵심 요약 : 원천 데이터가 추출·변환·적재 과정을 거쳐 통합 저장된 뒤 큐브로 집계되고, 분석 도구의 다차원 연산으로 소비되는 흐름.
- 구성요소 : 운영 시스템(원천), **ETL**(Extract, Transform, Load, 추출·변환·적재), 데이터 웨어하우스(통합 저장소), OLAP 서버(큐브 관리), 분석 도구(사용자 접점)의 다섯 계층.

```text
[OLAP 분석 흐름]
운영 시스템 (OLTP)
   ↓ 원천 데이터 발생
ETL (추출·변환·적재)
   ↓ 주기적 적재
데이터 웨어하우스 (DW)
   ↓
OLAP 서버 (다차원 큐브)
   ↓
분석 도구 (대화식 질의)
```

- 큐브 연산은 계층 이동, 단면 추출, 관점 회전의 세 부류로 구분되며, 다섯 연산의 동작은 다음 표와 같음.

| 연산 | 동작 메커니즘 | 적용 사례 |
| :--- | :--- | :--- |
| **롤업**(Roll-up) | 세부 계층을 상위 계층으로 집계하여 요약 | 일별 매출을 월별·연간 매출로 집계 |
| **드릴다운**(Drill-down) | 요약된 집계를 하위 계층으로 세분화 | 전국 매출을 시·도별로 파고들기 |
| **슬라이싱**(Slicing) | 한 차원의 값을 고정해 2차원 단면을 추출 | 전체 데이터에서 특정 연도만 추출 |
| **다이싱**(Dicing) | 복수 차원의 조건으로 하위 큐브를 적출 | 특정 지역·분기·품목 조합만 추출 |
| **피보팅**(Pivoting) | 행과 열의 차원을 맞바꿔 관점을 재배치 | 행(지역)·열(분기)의 자리 교체 |

```text
[계층 이동 연산]
일별 매출 (최하위 세부)
   ↓ 롤업 (상위 집계)
월별 매출
   ↓ 롤업
연간 매출
   ↑ 드릴다운 (하위 세분화)
```

## Ⅳ. OLTP와 OLAP의 비교

- 핵심 요약 : 업무 처리 목적의 OLTP와 분석 목적의 OLAP을 목적·데이터 구조 기준으로 분리 배치하는 것이 기준.

| 비교 항목 | OLTP (Online Transaction Processing) | OLAP (Online Analytical Processing) |
| :--- | :--- | :--- |
| 시스템 목적 | 일상 업무 트랜잭션의 정확·신속한 처리 | 전략적 의사결정을 위한 다차원 분석 |
| 데이터 구조 | 정규화된 관계형 모델, 중복 최소화 | 역정규화된 다차원 모델, 집계 중심 |
| 주요 질의 | 소수 레코드의 단건 입력·수정·조회 | 대규모 집계와 복합 조건 조회 |
| 처리 특성 | 동시성 제어와 무결성 중시 | 읽기 위주, 주기적 일괄 적재 |
| 이용자 | 현업 담당자, 업무 화면 | 경영진, 데이터 분석가 |

- 선택 기준 :
  1. 현업 업무 처리와 무결성 확보가 목적이면 OLTP 체계, 추세·비교·시뮬레이션 분석이 목적이면 OLAP 체계로 분리.
  2. 하나의 시스템에서 두 질의의 혼용은 자원 경쟁을 유발하므로, 운영 계층과 분석 계층의 분리 설계를 원칙으로 삼음.

## Ⅴ. OLAP의 한계와 방안

- 핵심 요약 : 다차원 신속 분석이라는 이점 이면에 큐브 폭발, 적재 지연, 집계 병목이 공존하므로 원인별 대응 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| **큐브 폭발**(Cube Explosion) | 차원·계층 증가로 사전 집계 조합이 급증 → 저장 공간 고갈 | 조회 빈도가 높은 상위 수준만 선별 집계하는 부분 사전 집계 적용 | 큐브 저장 용량, 집계 적중률 |
| 적재 지연 | 야간 배치 주기로 최신 데이터가 큐브에 늦게 반영 | 분석 주기별 적재 시간대 분리, 짧은 주기의 증분 적재 도입 | 데이터 반영 지연 시간 |
| 집계 질의 병목 | 팩트 테이블과 차원 테이블의 반복 조인이 입출력 병목 유발 | 요약 테이블과 인덱스·파티션 설계로 조인 범위 축소 | 질의 응답 시간 |

## Ⅵ. OLAP에 대한 기술사적 제언

- 핵심 요약 : 차원 설계의 표준화와 분석 품질의 상시 측정 체계로 OLAP을 조직의 분석 인프라로 내재화하는 방향.

1. 데이터 아키텍처 조직은 분석 요구를 차원·측정값 정의서로 표준화하고, 큐브에 반영할 차원과 집계 수준을 질의 로그 기반으로 선정하는 절차 운영.
2. 데이터 플랫폼 조직은 집계 적중률과 질의 응답 시간을 대시보드로 상시 추적하고, 목표 응답 시간 초과 시 집계 수준의 재조정 수행.
3. 내부 감사 조직은 경영 보고 수치의 원천과 산출 기준을 문서화하여 분석 결과의 재현 가능성을 점검.

## Ⅶ. 결론

- 핵심 요약 : OLAP은 운영 처리와 분석 처리를 분리한 분석 전용 계층으로서 다차원 의사결정 지원의 표준 기반.
- 시사점 : 차원·측정값 설계와 큐브 연산 체계의 완비가 대규모 데이터에서 일관된 분석 품질의 전제.
