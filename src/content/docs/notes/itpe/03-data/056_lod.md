## 연관 키워드
- LOD, RDF, URI, HTTP, RDF Schema, SPARQL, 5-star

### Ⅰ. 링크드 오픈 데이터의 개요

- 핵심 요약 : 개방 라이선스의 구조화 데이터를 웹 표준 URI와 RDF 링크로 공개해 다른 데이터와 연결·재사용하도록 하는 방식.
- 개념 : 개방 라이선스의 구조화 데이터를 웹 표준 URI와 RDF 링크로 공개해 다른 데이터와 연결·재사용하도록 하는 방식(**링크드 오픈 데이터**, Linked Open Data).
- 배경 및 필요성 : 기관별 폐쇄된 데이터셋은 검색·결합·기계처리·출처 추적이 어려움.
- 주요 목적 : 재사용 가능한 개방 데이터의 식별·연결·상호운용성 향상.
- 특징 : URI 식별·RDF 표현·링크, 개방 라이선스·HTTP 접근.

### Ⅱ. 링크드 오픈 데이터의 특징 및 장점

- 핵심 요약 : URI 식별·RDF 표현·링크·개방 라이선스·HTTP 접근은 LOD의 핵심 요소.

1. URI 식별 : 개체에 지속 식별자 부여 → 참조 가능.
2. RDF 표현·링크 : 주어-술어-목적어와 외부 URI 연결 → 그래프 통합.
3. 개방 라이선스·HTTP 접근 : 이용조건·웹 조회 제공 → 재사용성.

### Ⅲ. 링크드 오픈 데이터의 구조 (흐름)

- 핵심 요약 : 데이터·개체 선정 → 권리·개인정보 검토 → URI·RDF·어휘·링크 설계 → 기계판독형 공개·SPARQL/API → 링크 유효성·품질·갱신 관리.

```text
데이터·개체 선정
   ↓
권리·개인정보 검토
   ↓
URI·RDF·어휘·링크 설계
   ↓
기계판독형 공개·SPARQL/API
   ↓
링크 유효성·품질·갱신 관리
```

```text
원천 데이터 → URI/RDF 표현 → HTTP 공개 → 외부 URI 링크 → 연계 데이터 그래프
```

### Ⅳ. CSV 공개 데이터와 링크드 오픈 데이터 비교

- 핵심 요약 : 연계 기준 — CSV 공개 데이터: 파일 다운로드·별도 매핑; 링크드 오픈 데이터: 링크로 외부 데이터와 의미 연결.

| 비교 기준 | CSV 공개 데이터 | 링크드 오픈 데이터 |
|---|---|---|
| 표현 | 행·열 구조 중심 | RDF 그래프와 웹 URI 식별 |
| 연계 | 파일 다운로드·별도 매핑 | 링크로 외부 데이터와 의미 연결 |
| 활용요건 | 기계판독성·라이선스 | 기계판독성+URI·링크·공개권리 |

### Ⅴ. 링크드 오픈 데이터의 한계와 방안

- 핵심 요약 : 깨진 URI·링크·어휘 불일치 등 주요 위험을 원인에 맞는 통제로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 깨진 URI·링크 | 주소 변경·대상 소멸로 연결 단절 | 영구식별자 정책·링크 검증·리다이렉트 | 링크 유효율 |
| 어휘 불일치 | 서로 다른 RDF 클래스·속성 사용 | 표준 어휘 재사용·매핑·정의 공개 | 어휘 재사용률 |
| 공개 위험 | 개인정보·권리 제한 데이터 노출 | 공개 전 법적·비식별·라이선스 검토 | 재식별·권리 사고 |

### Ⅵ. 링크드 오픈 데이터에 대한 기술사적 제언

- 핵심 요약 : 공공데이터 책임자는 공개 가치·라이선스·식별자 수명·메타데이터·갱신 책임을 함께 지정하고 링크 품질을 지속 검증할 필요가 있다.
- 실행 제안 : 공공데이터 담당자는 URI 영속성·라이선스·외부 링크 유효성·기계판독성을 공개 전후 자동 점검할 필요가 있다.

### Ⅶ. 결론

- 핵심 요약 : LOD는 공개만으로 완성되지 않으며 지속 URI·명확한 라이선스·의미 링크·기계처리 품질이 결합되어야 함.
- 시사점 : 개방성과 연결성은 명확한 이용권리·지속 URI·기계처리 가능한 관계의 품질에 좌우됨.
