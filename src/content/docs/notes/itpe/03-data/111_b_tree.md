## 지식 로드맵 내 현재 위치

자료처리·데이터 → 인덱스 구조 → **B-Tree·B+Tree**

## 30초 인출

- 본질: B-Tree는 한 노드에 여러 키를 두는 균형 탐색 트리이고, B+Tree는 탐색 키를 내부 노드에, 데이터 항목을 연결된 리프에 모아 범위 순회를 지원하는 인덱스 구조
- 메커니즘: 페이지 하나에 여러 키·자식 포인터를 두어 높이를 낮추고, 삽입·삭제 시 분할·재분배·병합으로 모든 리프의 깊이를 같게 유지하며, B+Tree는 리프 연결로 범위를 순회
- 통찰: 내부 노드에 데이터를 두지 않으면 팬아웃이 커져 높이가 낮아지고 범위 검색이 리프 순회로 끝나지만, 실제 성능은 페이지 크기·키 길이·DBMS 구현에 좌우되므로 실행계획과 대표 부하로 확인

<details>
<summary>핵심 용어</summary>

- **B-Tree** : 여러 키를 한 노드에 두고 리프 깊이가 같은 균형 트리
- **B+Tree** : 데이터 항목을 리프에 모으고 리프끼리 연결한 B-Tree 변형
- **차수(Order) M** : 노드가 가질 수 있는 최대 자식 수
- **팬아웃(Fan-out)** : 한 노드가 가리키는 자식 수
- **분할·병합·재분배** : 노드가 넘치거나 부족할 때 균형을 유지하는 연산
- **리프 순차 연결** : 리프 노드끼리 연결해 범위를 순회하는 구조

</details>

## 2~4교시 25점 답안

## Ⅰ. B-Tree·B+Tree의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **B-Tree** 는 여러 키를 한 노드에 둔 균형 탐색 트리, **B+Tree** 는 데이터 항목을 리프에 모아 범위 순회를 지원하는 구조 |
| 목적 | 페이지 단위 탐색과 범위 검색을 효율화하고 갱신 시 균형 유지 |

## Ⅱ. 특징

| 특징 | 의미 |
|---|---|
| 다진 분기 | 페이지 하나에 여러 키·자식 포인터를 두어 높이를 낮춤 |
| 같은 리프 깊이 | 분할·재분배·병합으로 균형 유지 |
| B+Tree 리프 집중 | 내부 분기 키로 리프를 찾고 정렬된 리프에서 범위 순회 |

차수 M인 B-Tree의 조건: 루트는 (자식이 있으면) 최소 2개 자식, 루트 외 내부 노드는 최소 ⌈M/2⌉개 자식, 모든 노드는 최대 M−1개 키, 모든 리프는 같은 깊이.

## Ⅲ. 구조와 연산

```text
            [ 20 | 50 ]                  ← 내부 노드(분기 키)
          /      |      \
   [10]        [30 | 40]      [60 | 80]   ← 내부 노드
   /   \       /  |   \       /  |   \
[5,8]→[12]→[25]→[35]→[45]→[55]→[70]      ← 리프(연결, B+Tree)
BETWEEN 25 AND 55 → 25 리프를 찾은 뒤 연결을 따라 55까지 순회
```

- 삽입: 리프가 넘치면 분할하고 중간 키를 부모로 올림
- 삭제: 키가 부족하면 형제에서 재분배하거나 병합

## Ⅳ. B-Tree와 B+Tree 비교

| 항목 | B-Tree | B+Tree |
|---|---|---|
| 데이터 저장 위치 | 내부 노드·리프에 둘 수 있음 | 리프에 둠(형태는 DBMS 구현에 따름) |
| 팬아웃 | 페이지 크기·키·연관 데이터 표현에 좌우 | 내부에 데이터를 두지 않아 커질 수 있음 |
| 단건 검색 | 키 위치에 따라 경로 길이가 다름 | 리프까지 탐색, 비용은 높이에 좌우 |
| 범위 검색 | 구현에 따라 순회 비용 | 리프 연결을 활용해 효율적 |
| DBMS 적용 | 용어·구현이 제품마다 다름 | 다수 DBMS가 내부 분기 키·리프 구조 활용 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 트리 이름만으로 성능을 단정 | 실행계획·인덱스 통계·대표 부하로 비교 |
| 무작위 삽입으로 분할·쓰기 비용 증가 | 삽입 분포와 페이지 통계를 측정해 키·인덱스 전략 조정 |
| 저효용 인덱스 남발로 쓰기·저장 비용 증가 | 대표 질의 계획과 갱신 비용을 비교해 중복 인덱스 정리 |

## Ⅵ. 제언

범위 검색이 많은 디스크 기반 인덱스에는 B+Tree 계열을 사용하고, 실제 성능은 실행계획과 부하로 확인

```text
동등·범위 검색 인덱스 → B+Tree 계열 → 실행계획·통계 확인 → 중복 인덱스 정리
```

| 구분 | 이진 탐색 트리 | 제언: B+Tree 인덱스 |
|---|---|---|
| 높이 | 큼 | 팬아웃으로 낮음 |
| 범위 검색 | 순회 복잡 | 리프 연결 순회 |
