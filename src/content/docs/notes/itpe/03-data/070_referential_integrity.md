## 연관 키워드

**참조 무결성**, **기본키**, **외래키**, **고아 레코드**, **ON DELETE**, **제약조건**, **트랜잭션**

## Ⅰ. 개요

- 핵심 요약 : **참조 무결성**은 외래키가 유효한 부모 키를 참조하도록 데이터 관계의 일관성을 보장하는 제약이다.
- 구성 : 부모 릴레이션의 후보키 또는 기본키를 자식 릴레이션의 외래키가 참조한다.
- 목적 : 존재하지 않는 부모를 참조하는 고아 레코드와 잘못된 관계 데이터를 방지한다.

## Ⅱ. 특징 및 장점

- 핵심 요약 : **DBMS가 관계 규칙을 선언적으로 검증**해 응용 프로그램 간 데이터 불일치를 줄인다.
- **중앙 일관성** : 여러 응용 경로에서 발생하는 입력을 동일한 제약조건으로 검사한다.
- **연산 보호** : 자식 삽입·갱신과 부모 삭제·키 변경 시 지정된 규칙을 적용한다.
- **명시적 삭제 정책** : RESTRICT, CASCADE, SET NULL 등으로 관계 변경 동작을 정의한다.
- 제약조건 검증은 오버헤드가 발생할 수 있으나, 이를 이유로 무조건 비활성화하는 것은 위험하다.

## Ⅲ. 참조 무결성 검증 흐름

- 핵심 요약 : **자식의 외래키 쓰기와 부모 키 변경**에서 데이터베이스가 관계 조건을 확인한다.

```text
[자식 행 INSERT·UPDATE]
          ▼
[외래키 값 확인]
   ├─ 부모 키 존재 → 반영
   └─ 부모 키 없음 → 거부
[부모 행 DELETE·키 UPDATE]
          ▼
[참조 중인 자식 확인]
          ▼
[RESTRICT·CASCADE·SET NULL 등 적용]
```

- 적용 가능한 동작과 지연 검증 방식은 DBMS와 스키마 정의에 따라 확인한다.
- 부모 키 변경 시 참조 중인 자식의 동작을 명시적으로 설계한다.

## Ⅳ. 참조 동작 비교

- 핵심 요약 : **업무상 관계 의미와 삭제·갱신 정책**을 기준으로 동작을 선택한다.

| 동작 | 참조 중인 부모 삭제·갱신 시 | 적합성 검토 |
|---|---|---|
| RESTRICT / NO ACTION | 관련 행이 남아 있으면 작업 거부 | 자식 데이터 보존이 중요한 경우 |
| CASCADE | 자식 외래키 변경 또는 연쇄 삭제 | 생명주기를 부모와 공유하는 데이터 |
| SET NULL | 자식 외래키를 NULL로 변경 | 관계 해제 후 자식 보존이 가능한 경우 |
| SET DEFAULT | 자식 외래키를 기본값으로 설정 | 유효한 기본 부모 행이 있는 경우 |

- `NO ACTION`과 `RESTRICT`의 검증 시점·동작은 제품별 차이를 확인한다. SET NULL은 컬럼의 NULL 허용성과 함께 설계한다.

## Ⅴ. 한계와 방안

- 핵심 요약 : **검증 비용·대량 연쇄 작업·분산 경계**를 데이터베이스 제품과 업무 구조에 맞춰 통제한다.
- **부모 변경 시 부하** → 참조 키 인덱스와 실행계획을 확인하고 트랜잭션 크기를 관리한다.
- **CASCADE 오용** → 삭제 영향 범위를 검토하고 제한된 배치·소프트 삭제 등 대안을 평가한다.
- **샤드 간 참조** → 데이터 배치·서비스 경계를 고려하고 무결성 확인과 보정 절차를 설계한다.
- **제약조건 없는 서비스** → 쓰기 경로 검증, 정기 고아 데이터 탐지, 정정·감사 절차를 함께 둔다.

```text
제약 검증 부담 → 인덱스·트랜잭션 점검
연쇄 삭제 위험 → 영향 분석·삭제 정책    → 일관된 관계 데이터
분산 참조 한계 → 보정·감사 절차
```

## Ⅵ. 기술사적 제언

- 핵심 요약 : **무결성 규칙을 DB와 서비스 경계에 명확히 배치**하고 예외 경로를 감시한다.
- 단일 데이터베이스 안에서는 가능한 경우 선언적 제약조건을 우선 검토한다.
- 서비스 간 비동기 관계는 이벤트 재처리, 멱등성, 대사·보정 작업을 함께 설계한다.
- 외래키 비활성화는 부하 측정과 일관성 대안, 복구 방안을 검증한 뒤 제한적으로 결정한다.

## Ⅶ. 결론

- 핵심 요약 : 참조 무결성은 부모·자식 관계를 보호하는 기본 제약이며 **정책 선택과 운영 영향 검토**가 함께 필요하다.
- 답안에는 외래키 검증 시점과 참조 동작을 비교하고, 인덱스·CASCADE·분산 환경의 대응을 연결한다.
- 참고 : [PostgreSQL 공식 제약조건 문서](https://www.postgresql.org/docs/current/ddl-constraints.html).
