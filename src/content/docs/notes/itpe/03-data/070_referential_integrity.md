## 연관 키워드
- 참조 무결성, 외래키, 기본키, 카디널리티, 무결성 제약, 데이터 일관성

### Ⅰ. 참조 무결성의 개요

- 핵심 요약 : 데이터베이스가 허용되는 값과 관계만 저장하도록 보장하는 관계형 데이터 제약.
- 개념 : 외래키 값이 참조 대상 키와 일치하거나 NULL 허용 규칙을 만족하도록 보장하는 관계형 데이터 제약(**참조 무결성**, Referential Integrity).
- 배경 및 필요성 : 부모 삭제·키 변경·동시 입력으로 고아 행과 업무 관계 불일치 발생.
- 주요 목적 : 테이블 간 참조관계의 유효성을 DB 경계에서 보장.

### Ⅱ. 참조 무결성의 특징 및 장점

- 핵심 요약 : 외래키·참조 동작·검사 시점은 테이블 간 참조관계의 유효성을 보장하는 관계형 데이터 제약 구성요소.

1. 외래키 : 자식-부모 키 관계 명시 → 존재하지 않는 참조 차단.
2. 참조 동작 : RESTRICT·CASCADE·SET NULL 선택 → 삭제·변경 의미 정의.
3. 검사 시점 : 즉시·지연 제약 → 트랜잭션 내 상태 허용 제어.

### Ⅲ. 참조 무결성의 구조 (흐름)

- 핵심 요약 : PK·FK 관계 정의 → NULL·삭제·갱신 동작 결정 → 제약 적용·기존 고아 데이터 정리 → 부모·자식 동시성 시험 → 위반·성능 모니터링.

```text
PK·FK 관계 정의
   ↓
NULL·삭제·갱신 동작 결정
   ↓
제약 적용·기존 고아 데이터 정리
   ↓
부모·자식 동시성 시험
   ↓
위반·성능 모니터링
```

```text
부모(기본키) ← 외래키 참조 — 자식
부모 삭제 시 RESTRICT / CASCADE / SET NULL 정책
```

### Ⅳ. 외래키 제약과 애플리케이션 참조검사 비교

- 핵심 요약 : 동시성 기준 — 외래키 제약: 경쟁 삽입·삭제에도 제약 유지; 애플리케이션 참조검사: 검증 후 변경 사이 경합 가능.

| 비교 기준 | 외래키 제약 | 애플리케이션 참조검사 |
|---|---|---|
| 검사 보장 | DBMS가 모든 쓰기에서 원자적으로 검사 | 모든 호출·배치 코드가 정확히 검사해야 함 |
| 동시성 | 경쟁 삽입·삭제에도 제약 유지 | 검증 후 변경 사이 경합 가능 |

### Ⅴ. 참조 무결성의 한계와 방안

- 핵심 요약 : 삭제정책 불명확·레거시 고아행 등 주요 위험을 원인에 맞는 통제로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 삭제정책 불명확 | CASCADE가 예상 밖 대량 삭제 유발 | 업무별 RESTRICT·CASCADE·SET NULL 명시 | 연쇄 삭제 건수 |
| 레거시 고아행 | 기존 데이터로 FK 추가 실패 | 사전 탐지·정정·단계적 제약 적용 | 고아 행 수 |
| 성능·잠금 | FK 검사 시 부모·자식 인덱스·잠금 비용 | 외래키 인덱스·삭제·적재 부하 검증 | 쓰기 지연·잠금 |

### Ⅵ. 참조 무결성에 대한 제언

- 핵심 요약 : DB 설계자는 참조 수명주기와 삭제 전파를 도메인 담당자와 합의하고 제약조건·인덱스·마이그레이션을 같은 변경으로 관리할 필요가 있다.
- 실행 제안 : DBA와 업무 담당자는 부모 삭제·키 변경 정책을 승인하고 고아행 정리 이후 FK를 단계적으로 활성화하는 것이 바람직함.

### Ⅶ. 결론

- 핵심 요약 : 참조 무결성은 단순 FK 선언을 넘어 부모·자식 데이터의 생성·변경·삭제 정책을 명확히 하는 계약임.
- 시사점 : 외래키와 삭제 정책은 데이터 수명주기·보존의무·참조 시스템 경계를 함께 반영해야 함.
