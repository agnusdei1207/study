## 지식 로드맵 내 현재 위치

자료처리·데이터 → 무결성 제약 → **참조 무결성**

## 30초 인출

- 본질: 참조 무결성은 외래키 값이 참조 대상 테이블의 유효한 키를 가리키도록 보장하는 제약
- 메커니즘: 자식 행을 삽입·수정할 때 부모 키의 존재를 검사하고, 부모 행을 삭제·수정할 때 참조하는 자식이 있으면 RESTRICT·NO ACTION으로 거부하거나 CASCADE·SET NULL·SET DEFAULT로 자식을 처리
- 통찰: CASCADE는 한 번의 삭제가 많은 자식 행을 연쇄 변경할 수 있으므로 업무의 생명주기에 맞는 참조 동작을 고르고, 분리된 저장소 사이에는 DB 제약 대신 별도의 정합성 통제가 필요

<details>
<summary>핵심 용어</summary>

- **참조 무결성(Referential Integrity)** : 외래키가 유효한 부모 키를 가리키도록 하는 제약
- **외래키(Foreign Key)** : 다른 테이블의 키를 참조하는 속성
- **RESTRICT·NO ACTION** : 참조하는 자식이 있으면 부모 변경을 거부(NO ACTION은 검사 시점이 지연될 수 있음)
- **CASCADE** : 부모 삭제·수정을 자식 행에 전파
- **SET NULL·SET DEFAULT** : 자식의 외래키를 NULL·기본값으로 설정
- **지연 제약(Deferrable)** : 트랜잭션 끝까지 제약 검사를 미루는 기능

</details>

## 2~4교시 25점 답안

## Ⅰ. 참조 무결성의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **참조 무결성** 은 외래키 값이 참조 대상의 유효한 키를 가리키도록 보장하는 제약 |
| 목적 | 테이블 간 연결에서 유효하지 않은 참조의 저장 방지 |

## Ⅱ. 특징

| 특징 | 제약 의미 |
|---|---|
| 자식 참조 검증 | FK 값은 존재하는 부모 키를 가리켜야 함 |
| 부모 변경 통제 | 삭제·키 수정 시 자식 행 처리 규칙 적용 |
| 생명주기 의존 | NULL·연쇄·거부 정책을 업무 관계에 맞게 선택 |

## Ⅲ. 검사 흐름

```text
자식 INSERT·FK 수정 → 부모 키 존재 검사 ─ 없으면 거부 / 있으면 저장
부모 DELETE·키 수정 → 참조 자식 확인
      ├ RESTRICT·NO ACTION → 위반이면 거부
      └ CASCADE·SET NULL·SET DEFAULT → 자식 처리 후 제약 재검사
```

- 외래키는 부모의 기본키 또는 DBMS가 허용하는 고유 키를 참조
- FK가 NULL일 수 있는지는 NOT NULL 등 별도 제약과 DBMS 규칙으로 결정

## Ⅳ. 참조 동작 유형과 설계 조건

| 동작 | 부모 삭제 시 | 고려사항 |
|---|---|---|
| RESTRICT | 참조 행이 있으면 거부 | 즉시 제한 |
| NO ACTION | 검사 시점에 위반이면 거부 | 지연 제약에서는 RESTRICT와 시점 차이 |
| CASCADE | 자식 행 연쇄 삭제 | 자식의 생명주기가 부모에 종속될 때 |
| SET NULL | 자식 FK를 NULL로 설정 | FK 열이 NULL 허용이어야 함 |
| SET DEFAULT | 자식 FK를 기본값으로 설정 | 기본값도 참조 제약을 만족해야 함 |

동작의 지원 범위와 세부 의미는 DBMS별로 확인.

| 설계 항목 | 판단 기준 |
|---|---|
| 참조 키 | 기본키·적절한 고유 키 |
| NULL 허용 | 관계 선택성·미지정 허용 여부 |
| 인덱스 | 부모 변경 시 자식 검색 비용을 위한 FK 인덱스 |
| 분산 데이터 | DB 제약의 적용 범위와 서비스 간 관계 관리 책임 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| CASCADE가 다수 자식 행을 함께 변경 | 영향 범위 확인, 트랜잭션·권한·감사 정책과 조합 |
| DBMS별 동작·지연 검사 차이 | 목표 DBMS 문서와 실제 스키마로 검증 |
| 분리된 저장소 간 FK 적용 곤란 | 업무 이벤트·애플리케이션 검증·정합성 대사 |
| 참조 동작이 업무 정책과 불일치 | 엔터티 생명주기 시나리오를 DDL 제약과 시험에 반영 |

## Ⅵ. 제언

엔터티의 생명주기에 맞게 참조 동작을 정하고 FK에 인덱스를 두며, 저장소가 분리되면 별도 정합성 통제를 설계

```text
관계 선택성·생명주기 분석 → 참조 동작 선택 → FK 인덱스 → 시나리오 시험 → 분산 시 대사
```

| 구분 | 제약 없이 애플리케이션 검증만 | 제언: DB 제약 + 필요 시 대사 |
|---|---|---|
| 무결성 | 누락 시 고아 행 | DB가 보장 |
| 분산 저장소 | 통제 곤란 | 별도 대사 |
