## 연관 키워드
- 키, 기본키, 후보키, 대체키, 외래키, 슈퍼키

### Ⅰ. 키(Key)의 개요

- 핵심 요약 : 데이터베이스 테이블에서 각 행을 유일하게 식별하는 속성 또는 속성 집합.
- 개념 : 데이터베이스 테이블에서 각 행을 유일하게 식별하는 속성 또는 속성 집합(**키**, Key).
- 배경 및 필요성 : 데이터 중복을 방지하고, 테이블 간 관계를 정의하기 위해 키가 필요함.
- 주요 목적 : 데이터의 무결성을 보장하고, 테이블 간의 관계를 정의.

### Ⅱ. 키의 특징 및 장점

- 핵심 요약 : 기본키, 후보키, 대체키, 외래키, 슈퍼키 등 다양한 종류의 키가 있음.

1. 기본키(Primary Key) : 각 행을 유일하게 식별하는 키. NULL 값을 가질 수 없으며, 중복될 수 없음.
2. 후보키(Candidate Key) : 기본키가 될 수 있는 속성 집합. 유일성과 최소성을 만족해야 함.
3. 대체키(Alternate Key) : 후보키 중 기본키로 선택되지 않은 키.
4. 외래키(Foreign Key) : 다른 테이블의 기본키를 참조하는 속성. 참조 무결성을 보장함.
5. 슈퍼키(Super Key) : 유일성을 만족하는 속성 집합. 후보키의 상위 개념.

### Ⅲ. 키의 구조 (흐름)

- 핵심 요약 : 데이터 모델링 단계에서 엔티티 간의 관계를 정의하고, 기본키와 외래키를 설정하는 과정.

```text
[ 키 설계 프로세스 ]

엔티티 정의
   ↓
속성 정의
   ↓
기본키 선택
   ↓
외래키 정의
   ↓
무결성 제약 조건 정의
```

```text
[ 키 관계 예시 ]

고객 테이블
- 고객기본키(PK)
- 고객명
- 전화번호

주문 테이블
- 주문기본키(PK)
- 주문일자
- 고객외래키(FK) → 고객 테이블의 고객기본키 참조
```

### Ⅳ. 키의 종류 비교

- 핵심 요약 : 기본키, 후보키, 대체키, 외래키, 슈퍼키의 특성과 용도가 다름.

| 비교 항목 | 기본키 | 후보키 | 대체키 | 외래키 | 슈퍼키 |
|---|---|---|---|---|---|
| 정의 | 기본 식별자 | 기본키 후보 | 후보키 중 미선택 | 참조 관계 정의 | 유일성을 만족하는 속성 집합 |
| NULL 허용 여부 | 불가능 | 가능 | 가능 | NULL 허용 가능 | 가능 |
| 중복 허용 여부 | 불가능 | 불가능 | 불가능 | 중복 가능 | 중복 가능 |
| 수 | 테이블당 하나 | 하나 이상 | 하나 이상 | 다수 가능 | 다수 가능 |

### Ⅴ. 키의 한계와 방안

- 핵심 요약 : 키 설계 시 자연 키와 대리 키의 선택, 합성 키의 사용, 외래키 제약 조건 정의 등을 고려해야 함.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 자연キー의 변경 가능성 | 자연 키가 변경되면 관련된 모든 테이블의 데이터를 수정해야 함 | 대리 키를 사용하여 기본 키를 구성 | 키 변경 건수 |
| 복합 키의 복잡성 | 복합 키를 사용하면 조인 및 인덱스 관리가 복잡해짐 | 단일 대리 키를 사용하고, 복합 키는 대체 키로 관리 | 조인 성능 |
| 외래키 제약 위반 | 참조 무결성 위반 시 데이터 정합성 문제 발생 | 외래 키 제약 조건을 정의하고, 참조 무결성 검사 수행 | 외래 키 위반 건수 |

### Ⅵ. 키 설계에 대한 기술사적 제언

- 핵심 요약 : 데이터 모델링 시 키 설계는 데이터 무결성과 성능에 직접적인 영향을 미치므로, 신중한 설계가 필요함.
- 실행 제언 : 데이터 모델링 시 기본 키와 외래 키를 명확히 정의하고, 참조 무결성 제약 조건을 정의하여 데이터 일관성을 보장해야 함.

### Ⅶ. 결론

- 핵심 요약 : 키는 데이터베이스에서 데이터의 무결성과 참조 관계를 보장하는 중요한 요소임.
- 시사점 : 키 설계는 데이터베이스 설계의 기초가 되므로, 신중하게 설계해야 함.
