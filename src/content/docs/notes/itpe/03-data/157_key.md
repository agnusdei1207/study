## 연관 키워드

**키(Key)**, **슈퍼키/후보키/기본키/대체키/외래키**, **유일성·최소성**, **자연키/인조키**, **Surrogate Key**, **UUID v7/TSID**

## Ⅰ. 개요

- 핵심 요약 : **키**는 릴레이션 튜플을 고유 식별하거나 참조 무결성을 강제하는 속성 집합.
- 목적 : 개체 무결성·참조 무결성 보장.
- 배경 : 릴레이션 내 튜플 구분 및 테이블 간 관계 필요.
- 특징 : 유일성·최소성, 5대 키 분류, 자연키/인조키.

## Ⅱ. 특징 및 장점

- 핵심 요약 : **유일성·최소성**으로 고유 식별과 참조 무결성 확보.
- **슈퍼키** : 유일성만 만족 (최소성 X).
- **후보키** : 유일성+최소성.
- **기본키** : 후보키 중 대표 (NOT NULL, 인덱스).
- **대체키** : 나머지 후보키 (Unique Index).
- **외래키** : 다른 릴레이션 PK 참조.

## Ⅲ. 키 계층 흐름

- 핵심 요약 : **슈퍼키 ⊃ 후보키 ⊃ {기본키, 대체키}**, 외래키는 참조.
- 자연키 vs 인조키 트레이드오프.

```text
[ 키 계층 ]

[슈퍼키] (유일성)
   +---> [후보키] (유일성+최소성)
            +---> [기본키] (대표, NOT NULL)
            +---> [대체키] (보조, Unique)
[외래키] : 다른 릴레이션 기본키 참조
```

```text
[ 자연키 vs 인조키 ]

자연키 : 비즈니스 고유 속성 (주민번호), 변경 영향 큼
인조키 : 시스템 채번 (Auto Increment, UUID), 조인 빠름
```

## Ⅳ. 5대 키 비교

- 핵심 요약 : **유일성·최소성·NULL·정의** 비교.

| 키 | 유일성 | 최소성 | NULL | 정의 |
|---|---|---|---|---|
| 슈퍼키 | 만족 | 미만족 | 허용 | 유일 식별 가능한 모든 속성 집합 |
| 후보키 | 만족 | 만족 | 불허 | 기본키 자격을 갖춘 속성 집합 |
| 기본키 | 만족 | 만족 | 불허 | 대표 주식별자 (개체 무결성) |
| 대체키 | 만족 | 만족 | 불허 | 남은 보조 키 (Unique Index) |
| 외래키 | 미만족 | 미만족 | 허용 | 참조 무결성 강제 |

## Ⅴ. 한계와 방안

- 핵심 요약 : **자연키 변경·UUID 인덱스 단편화·복합키 비대화**를 인조키·순차 UUID·대체키로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 자연키 변경 파급 | 법령 변경 시 전사 DDL 수정 | 대리키 PK + 자연키 Unique | 마이그레이션 비용 |
| UUID v4 인덱스 단편화 | 무작위 삽입으로 페이지 분할 폭증 | UUID v7/ULID/TSID (시간 순) | 인덱스 단편화율 |
| 복합키 비대화 | 4~5개 속성 PK로 보조 인덱스 팽창 | 단일 대리키 + 결합 Unique | 인덱스 크기 |

## Ⅵ. 기술사적 제언

- 핵심 요약 : **대리키 PK + 자연키 Unique + 순차 UUID**.
- 모든 테이블 PK는 단일 정수형 대리키.
- 자연키는 복합 대체키(Unique Index)로 중복 방지.
- 분산 환경 UUID v7/TSID 채택.

## Ⅶ. 결론

- 핵심 요약 : 키는 **유일성·최소성** 기반 식별자로 대리키·순차 UUID가 현대 표준.
- 답안에는 5대 키, 유일성/최소성, 자연키/인조키, 한계·대응을 연결.
