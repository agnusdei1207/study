## 답안 골격
```text
[데이터 마이그레이션 · 정합성] ◀━━ 머리: Ⅶ 내 의견 (CDC 기반 무중단 이관과 해시 체크섬·건수 자동 대사 파이프라인)
 ┃
 ┣━ Ⅰ 개요 ───── 레거시 시스템의 데이터를 신규 시스템의 스키마와 환경으로 변환·이관하고 원천과 대상 간의 데이터 일치성(정합성)을 100% 검증하는 체계
 ┣━ Ⅱ 특징 ───── 빅뱅 vs 단계적 전환 · ETL 변환 룰 검증 · 다운타임 최소화 · 자동화된 사후 대사(Reconciliation) 필수
 ┣━ Ⅲ 구조 ───── 이관 절차: 매핑 정의 / 사전 정제(Cleansing) / 초기 적재(Bulk) / CDC 동기화 / 사후 검증(Validation)
 ┣━ Ⅳ 흐름 ───── ① 이관 대상 매핑 및 룰 정의 → ② 모의 이관(3회 이상 반복 리허설) → ③ 본 이관 초기 적재 → ④ CDC 기반 증분 동기화 → ⑤ 정합성 검증 후 절체(Cut-over)
 ┣━ Ⅴ 비교 ───── 빅뱅 마이그레이션 vs 단계적(CDC 무중단) 마이그레이션
 ┗━ Ⅵ 실무 ───── 오픈 당일 정합성 불일치로 롤백 / 이관 스크립트 실행 시간 초과로 정해진 점검 시간(Downtime) 위반
```
- 필수 키워드: 데이터 마이그레이션 · 데이터 정합성 · CDC(Change Data Capture) · ETL 매핑 · 컷오버(Cut-over) · 대사(Reconciliation) · 해시 체크섬 · 롤백 플랜
- 배점 전략: 10점 = Ⅰ → Ⅲ 마이그레이션 5단계 절차도 → Ⅴ 빅뱅 vs 단계적 이관 비교 / 25점 = Ⅰ~Ⅶ, Ⅳ 무중단 CDC 컷오버 시퀀스 도식 및 Ⅵ 3단계 정합성 검증 기법(건수, 금액합, 해시)
- 기출: 128회 `차세대 시스템 구축 시 데이터 마이그레이션 절차와 데이터 정합성 검증 방안을 설명하시오.` → Ⅰ 정의 + Ⅲ 이관 단계 + Ⅳ 검증 절차 + Ⅵ 컷오버 및 비상 롤백 방안

## 한 줄 본질
- 서로 다른 스키마와 DBMS 간 대규모 데이터 이관 시 데이터 누락·변형 및 장시간 다운타임 발생 위험 → 초기 대량 적재 후 CDC로 실시간 변경분을 맞추고 체크섬으로 100% 검증 → 무중단 무결성 이관 달성 / 변환 룰 복잡도 및 리허설 비용 발생

## 핵심 그림
```text
[무중단 데이터 마이그레이션 및 실시간 정합성 검증 파이프라인]

  [레거시 원천 DB]                                    [타겟 신규 DB]
  ┌──────────────┐     1. 초기 대량 적재 (Bulk Load)   ┌──────────────┐
  │  Legacy DB   │───────────────────────────────────►│   Target DB  │
  └──────┬───────┘                                    └──────▲───────┘
         │ 트랜잭션 로그                                     │
         ▼                                                   │
  ┌──────────────┐     2. 실시간 증분 동기화 (CDC)           │
  │ CDC 솔루션   │───────────────────────────────────────────┘
  │ (Debezium)   │     3. 정합성 대사 (Reconciliation)
  └──────────────┘    ┌───────────────────────────────────────────────┐
                      │ - 1차: 총 레코드 건수 대사 (Count Match)      │
                      │ - 2차: 핵심 비즈니스 수치 합계 (Sum Check)   │
                      │ - 3차: SHA-256 로우 해시 1:1 대조 (Hash Match)│
                      └───────────────────────────────────────────────┘
```

## 핵심 용어
- CDC(Change Data Capture): 데이터베이스의 트랜잭션 로그(Redo Log 등)를 실시간 감지하여 변경된 데이터(INSERT, UPDATE, DELETE)만 추출해 타겟 시스템으로 복제하는 기술
- 컷오버(Cut-over): 기존 운영 시스템을 공식 종료하고 신규 시스템으로 트래픽을 완전히 전환하는 최종 이관 실행 시점

## 핵심 통찰
- 마이그레이션의 성패는 '이관 당일'이 아니라 '사전 모의 훈련(Rehearsal)' 횟수에서 결정됨 → 최소 3회 이상 전체 실데이터를 대상으로 리허설을 돌려 정확한 소요 시간을 분 단위로 측정해야 컷오버 실패를 막을 수 있음
- 정합성 검증을 단순 '총 건수(Count)'로만 때우면 재앙이 됨 → 레거시에서 1,000만 건, 타겟에서 1,000만 건으로 건수가 맞아도 내부 속성값이나 외래키 관계가 뒤틀려 있는 경우가 허다하므로 반드시 핵심 금액 필드의 합계(Sum)와 행 단위 해시 비교(Hash)를 병행해야 함
- 컷오버 계획서에는 반드시 '이관 취소 및 롤백 마지노선 시각(Go/No-Go Decision Point)'이 명시되어 있어야 함

## 이웃 토픽과 구분
- 데이터 마이그레이션 vs 데이터 복제: 마이그레이션 = 스키마 구조 변경, 데이터 정제, 비즈니스 룰 변환을 동반하여 '다른 환경으로 영구 이전'하는 일회성 프로젝트 / 복제 = 동일하거나 유사한 스키마 구조로 '실시간 동기화 상태를 상시 유지'하는 운영 인프라

## 문제·원인·대책
- 적용 상황: 금융 코어 뱅킹 차세대 전환 사업의 계좌 원장 데이터 마이그레이션
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 원천 시스템의 비표준 날짜(`0000-00-00`) 데이터로 인해 타겟 DB 적재 시 파싱 예외 발생 | 사전 데이터 프로파일링 부재 및 예외 데이터 정제 룰 누락 | 이관 전 프로파일링으로 비표준 데이터 식별 후 기본값 매핑 규칙 선적용 | 적재 에러율 0% 달성 |
| 1억 건 테이블 대사 시 네트워크 I/O 병목으로 검증에만 12시간 소요 | 네트워크를 통해 모든 행을 1:1로 전송하며 비교 | 소스와 타겟 양쪽에서 블록 단위 MD5/SHA256 해시를 계산해 해시값만 비교 | 대사 시간 12시간에서 20분으로 95% 단축 |

## 내 의견
- [수작업 SQL 대사의 한계] 엑셀로 건수를 적어가며 수작업 쿼리로 정합성을 맞추다가 야간 컷오버 시 사람이 실수하여 결손 데이터를 놓치는 사고 빈발 → 나라면: 오픈소스 정합성 검증 엔진(Datafold 등)을 도입하여 테이블 간 차이점(Diff)을 행 단위로 자동 리포팅하고, 불일치율 0% 달성 시에만 승인 버튼이 활성화되는 컷오버 자동화 게이트웨이 구축
