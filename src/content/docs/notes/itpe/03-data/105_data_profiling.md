## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터 품질 → **데이터 프로파일링**

## 30초 인출

- 본질: 데이터 프로파일링은 실제 데이터의 구조·내용·관계를 분석해 품질 특성과 결함을 파악하는 활동
- 메커니즘: 대상과 시점을 정한 뒤 컬럼(결측·형식·분포), 테이블(키 유일성·중복 행), 테이블 간(참조·고아 행)을 측정하고 이상 후보를 업무 규칙·계보와 대조해 정제하거나 예외로 규칙화한 뒤 같은 기준으로 재측정
- 통찰: 통계적 이상이 곧 오류는 아니므로 도메인 담당자의 확인을 거쳐 정제하고, 전수 스캔은 운영 부하가 되므로 표본·증분·복제본과 민감정보 마스킹으로 측정 방식을 설계

<details>
<summary>핵심 용어</summary>

- **데이터 프로파일링(Data Profiling)** : 데이터의 구조·내용·관계를 분석해 품질 특성을 파악하는 활동
- **컬럼 프로파일링** : 자료형·형식·결측·고유값·분포·범위 분석
- **테이블 프로파일링** : 키 후보의 유일성·중복 행·속성 규칙 분석
- **관계 프로파일링** : 테이블 간 참조값·연결률·고아 행 분석
- **고아 행(Orphan Row)** : 참조할 부모가 없는 자식 행
- **데이터 계보(Lineage)** : 데이터의 출처와 변환 경로

</details>

## 2~4교시 25점 답안

## Ⅰ. 데이터 프로파일링의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터 프로파일링** 은 실제 데이터의 구조·내용·관계를 분석해 품질 특성을 파악하는 활동 |
| 목적 | 결함과 특성을 가시화해 정제·통합·이관 의사결정 지원 |

## Ⅱ. 특징

| 특징 | 관찰 단위 | 해석 조건 |
|---|---|---|
| 실제 값 기반 | 열의 분포·결측·형식 | 정의 문서와 실제 데이터의 차이 확인 |
| 관계 확인 | 키·참조·교차 항목 | 단일 열 통계로 발견하기 어려운 결함 식별 |
| 반복 측정 | 시점별 품질 지표 | 정제·이관 뒤 변화 추적 |

## Ⅲ. 수행 절차

```text
대상·시점·업무 정의 확정
 ├ 컬럼: 결측·형식·분포
 ├ 테이블: 키 유일성·행 중복·속성 규칙
 └ 테이블 간: 참조키·연결률·고아 행
        ↓ 이상 후보를 업무 규칙·계보와 대조
담당자 확인 → 오류 정제 / 정상 예외는 규칙화
        ↓ 같은 기준으로 재측정·추이 확인
```

## Ⅳ. 분석 유형과 운영 고려

| 분석 단위 | 확인 항목 | 예 |
|---|---|---|
| 컬럼 | 자료형·포맷·결측·고유값·분포·범위 | 허용 코드·날짜 범위 |
| 테이블 | 키 유일성·중복 행·속성 규칙 | 주문일과 출고일의 선후 |
| 테이블 간 | 참조값·연결률·고아 행 | 주문의 고객키와 고객 마스터 |

| 고려사항 | 적용 |
|---|---|
| 대상 범위 | 목적·데이터량·시간에 따라 전수·표본·증분 선택 |
| 접근 부하 | 복제본·배치 시간·자원 한도 설계 |
| 민감정보 | 원문 수집·노출 최소화, 접근권한·마스킹 |
| 업무 해석 | 통계 이상을 곧바로 오류로 판단하지 않고 담당자가 예외·원인 검토 |
| 변경 관리 | 규칙·코드·데이터 시점·결과 기록으로 재현성 유지 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 분포 이상만으로 정상 희귀값을 오류로 수정 | 정의·계보·업무 규칙과 대조, 담당자 확인 후 정제 |
| 전수 스캔이 운영 DB 성능 저하 | 표본·증분·복제본 선택, 실행 자원 제한 |
| 결과에 민감 원문 노출 | 집계·마스킹 중심 보고, 권한 분리 |

## Ⅵ. 제언

이관·통합 전에 프로파일링으로 결함 후보를 찾고 담당자 확인을 거쳐 정제 규칙을 확정한 뒤 정기 재측정

```text
프로파일링 → 후보 → 담당자 확인 → 정제·예외 규칙 → 정기 재측정(품질 추이)
```

| 구분 | 정의 문서만 신뢰 | 제언: 실제 데이터 측정 |
|---|---|---|
| 결함 발견 | 이관 후 | 이관 전 |
| 정제 | 통계 이상 일괄 수정 | 담당자 확인 |
