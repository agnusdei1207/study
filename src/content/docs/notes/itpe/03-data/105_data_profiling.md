## 답안 골격
```text
[데이터 프로파일링 (Data Profiling)] ◀━━ 머리: Ⅶ 내 의견 (ETL 파이프라인 전단 자동 프로파일링과 메타데이터 동기화)
 ┃
 ┣━ Ⅰ 개요 ───── 원천 데이터의 구조, 값의 분포, 결측치, 무결성 제약조건 위배 여부를 분석 통계 기법으로 자동 검증하는 데이터 품질 진단 기법
 ┣━ Ⅱ 특징 ───── 메타데이터 실측 검증 · 비침습적 읽기 전용 분석 · 데이터 마이그레이션 필수 선행 · 품질 개선 기준점 제시
 ┣━ Ⅲ 구조 ───── 열 프로파일링(Column: 타입, 결측률, 카디널리티) / 다중열 프로파일링(Cross-Column: 함수종속, 상관관계) / 테이블 간 프로파일링(Cross-Table: 외래키, 고아 데이터)
 ┣━ Ⅳ 흐름 ───── ① 대상 테이블 선정 → ② 규칙 기반 통계 수집(값 범위, 패턴, 공백) → ③ 비즈니스 룰 대비 이상치 식별 → ④ 품질 보고서 발행 및 정제 룰 수립
 ┣━ Ⅴ 비교 ───── 데이터 프로파일링 vs 데이터 감사(Audit) vs 데이터 정제(Cleansing)
 ┗━ Ⅵ 실무 ───── 수억 건 데이터 프로파일링 시 운영 DB CPU 마비 / 정의서에는 NOT NULL이나 실제 값의 30%가 빈 문자열
```
- 필수 키워드: 데이터 프로파일링 · 열 프로파일링 · 구조 분석 · 값 분석 · 관계 분석 · 고아 레코드(Orphan Data) · 카디널리티 · 데이터 품질관리(DQM)
- 배점 전략: 10점 = Ⅰ → Ⅲ 3단계 프로파일링 기법 매핑표 → Ⅴ 품질 활동 간 비교 / 25점 = Ⅰ~Ⅶ, Ⅳ 실행 절차 및 Ⅵ 대용량 DB 비침습적 프로파일링 방안
- 기출: 128회 `데이터 품질 관리를 위한 데이터 프로파일링 기법과 분석 단계` → Ⅰ 정의 + Ⅲ 3대 기법(열, 다중열, 관계) + Ⅳ 분석 단계 + Ⅵ 실무 적용

## 한 줄 본질
- 문서(테이블 정의서)와 실제 DB 내부 적재 데이터 사이의 괴리로 인한 정합성 파탄 위험 → 소스 데이터를 직접 스캔하여 통계적 패턴·결측률·관계 불일치를 정량 측정 → 정확한 데이터 실태 파악 / 대용량 스캔 비용 수반

## 핵심 용어
- 카디널리티(Cardinality): 특정 속성(열) 내에서 중복을 제외한 고유한 값(Distinct Value)의 절대적인 개수
- 고아 데이터(Orphan Record): 부모 테이블의 기본키가 이미 삭제되었거나 존재하지 않는데도 외래키로 여전히 참조하고 있는 유효하지 않은 자식 데이터

## 핵심 통찰
- 설계 문서와 실제 데이터는 99% 확률로 불일치함 → 테이블 정의서에 `주민번호, NOT NULL, 13자리`로 되어 있어도 프로파일링을 돌려보면 `000000-0000000`이나 공백이 20%를 차지하는 경우가 다반사
- 마이그레이션 프로젝트에서 프로파일링을 생략하고 ETL 코드를 짜면, 오픈 당일 데이터 타입 변환 에러와 참조 무결성 위배로 적재가 전면 중단됨
- 프로파일링은 전체 데이터를 스캔해야 하므로 운영 중인 트랜잭션 DB에서 직접 돌리면 락과 I/O 부하로 서비스 장애를 일으킴 → 반드시 Read Replica나 스테이징 백업본에서 실행

## 이웃 토픽과 구분
- 데이터 프로파일링 vs 데이터 정제(Cleansing): 프로파일링 = 데이터의 현재 상태와 품질 결함을 '진단·측정'하는 활동(의사의 청진기) / 정제 = 발견된 결함 데이터를 규칙에 따라 실제로 '수정·삭제·변환'하는 활동(치료 및 수술)

## 문제·원인·대책
- 적용 상황: 차세대 차세대 시스템 구축을 위한 레거시 DB 데이터 마이그레이션 프로젝트
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 타겟 신규 시스템 적재 시 외래키 제약조건 위반으로 배치 전면 중단 | 레거시 DB에 FK 선언이 누락되어 수만 건의 고아 레코드 적재 방치 | 이관 전 테이블 간 프로파일링(Cross-Table)을 선행하여 미참조 데이터 사전 추출 | 고아 데이터 사전 정제 규칙 적용으로 무결성 100% 확보 |
| 주소 컬럼에 우편번호, 지번, 도로명 등이 규칙 없이 뒤섞여 파싱 실패 | 데이터 입력 표준 포맷 부재 및 정규표현식 검증 누락 | 패턴 프로파일링(Pattern Analysis)을 수행하여 입력 패턴 클러스터링 | 패턴별 정규화 파서 자동 생성 및 파싱 성공률 98% 달성 |

## 이렇게 출제된다

## 내 의견
- [일회성 이벤트성 프로파일링의 한계] 프로젝트 오픈 직전에만 한 번 프로파일링을 돌리고 이후에는 방치하여 6개월 만에 DB가 다시 쓰레기 데이터로 오염되는 사례 다수 → 나라면: Great Expectations나 dbt test 같은 자동화 도구를 데이터 파이프라인에 통합해, 매일 새벽 적재되는 데이터에 대해 결측률·범위·패턴 검증을 자동으로 실행하고 슬랙으로 품질 이상을 통보하는 지속적 프로파일링(Continuous Profiling) 체계 구축
