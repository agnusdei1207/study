## 연관 키워드

- 데이터 프로파일링

## Ⅰ. 데이터 프로파일링의 개요

- 핵심 요약 : 데이터의 구조·내용·품질을 자동 분석하여 메타데이터와 품질 지표를 도출하는 데이터 이해의 선행 프로세스.
- 개념 : 데이터베이스, 파일, 스트림 등 원시 데이터 소스를 대상으로 열 단위 통계(널 비율, 고유값 수, 최소/최대/평균, 값 분포), 행 단위 패턴, 테이블 간 관계(외래키 후보, 중복 키) 등을 자동 수집·분석하여 데이터의 실체적 특성을 메타데이터화하는 프로세스.
- 배경 및 필요성 : 문서화되지 않은 레거시 시스템, 인수합병(M&A) 데이터 통합, 데이터 레이크 적재 전 품질 진단, 데이터 거버넌스 기준선(Baseline) 수립 시 데이터 실태 파악 필수.
- 주요 목적 : 데이터 품질 현황 정량화, 이상치·규칙 위반 조기 탐지, downstream 파이프라인 설계 위한 메타데이터 확보.

## Ⅱ. 데이터 프로파일링의 특징

- 핵심 요약 : 열·행·테이블·교차 테이블 4단계 분석과 통계·패턴·관계 3대 분석 축이 결합된 자동 진단 체계.

1. 열 프로파일링(Column Profiling) : 단일 컬럼의 자료형, 널 비율, 고유값 수, 최빈값, 최소/최대/평균, 히스토그램, 패턴(정규식 매칭) 분석.
2. 행 프로파일링(Row Profiling) : 레코드 단위 완전성, 중복 행, 비즈니스 룰 위반 여부 검증.
3. 테이블 프로파일링(Table Profiling) : 행 수, 키 후보 식별, 인덱스 후보, 파티션 키 적합성 분석.
4. 교차 열/테이블 프로파일링 : 함수적 종속성(Functional Dependency), 외래키 관계 추론, 테이블 간 중복/참조 무결성 분석.
5. 자동화·반복성 : 스케줄링 기반 주기적 프로파일링으로 데이터 드리프트(Data Drift) 감지.

## Ⅲ. 데이터 프로파일링의 구조 (흐름)

- 핵심 요약 : 소스 연결, 샘플링, 통계 수집, 패턴 마이닝, 리포트 생성의 순차 파이프라인.
- 데이터 프로파일링 파이프라인.

```text
[ 데이터 프로파일링 파이프라인 ]
[ 1. 소스 연결 ] -> JDBC, 파일, 클라우드 스토리지, 스트림 커넥터
    │
    ▼
[ 2. 샘플링 전략 ] -> 전수 조사(Full Scan) vs 통계적 샘플링(Bernoulli, Reservoir)
    │
    ▼
[ 3. 통계 수집 엔진 ]
    ├─ 열 통계: Null%, Distinct%, Min/Max/Avg, Histogram, Top-K
    ├─ 패턴: Regex 매칭, 데이터 타입 추론, 도메인 값 매핑
    └─ 관계: FK 후보, FD(Functional Dependency) 탐지
    │
    ▼
[ 4. 품질 룰 평가 ] -> 정의된 룰(완전성, 유일성, 유효성, 일관성) 자동 적용
    │
    ▼
[ 5. 리포트·메타데이터 출력 ]
    - 프로파일 리포트(HTML/JSON), 데이터 카탈로그 등록, 품질 대시보드 연계
```

- 열 프로파일링 지표 상세.

```text
[ 열 프로파일링 핵심 지표 ]
기본 통계     : Count, Null Count, Null %, Distinct Count, Distinct %
수치형 지표   : Min, Max, Mean, Median, StdDev, Quantiles (25/50/75%)
문자열 지표   : Min Length, Max Length, Avg Length, Pattern 분포
분포 분석     : Histogram (등폭/등빈도), Top-K 빈도값, 하위 값 분포
패턴 분석     : Regex 매칭률, 데이터 타입 추론 신뢰도, 의미적 도메인 매핑
```

## Ⅳ. 수동 분석과 자동 프로파일링의 비교

- 핵심 요약 : 샘플링 기반 수작업에서 전수 자동화로, 주관적 판단에서 정량 지표 기반으로 전환.

| 비교 항목 | 수동 데이터 분석(Excel, SQL) | 자동 데이터 프로파일링 도구 |
|---|---|---|
| 분석 범위 | 샘플링 기반 제한적 조사 | 전수 조사(Full Scan) 또는 대표성 보장 샘플링 |
| 분석 속도 | 수시간~수일 (인적 노력) | 수분~수시간 (병렬 분산 처리) |
| 지표 일관성 | 분석자별 편차 발생 | 표준화된 지표 정의로 일관성 보장 |
| 패턴 탐지 | 정규식 수작업 작성 | 자동 패턴 마이닝(Regex 추론, 도메인 인식) |
| 관계 분석 | 조인 쿼리 수작업 | FK 후보 자동 추론, FD(함수적 종속) 자동 탐지 |
| 이력 관리 | 버전 관리 어려움 | 실행 이력, 드리프트 감지, 시계열 비교 내장 |

## Ⅴ. 데이터 프로파일링의 장점과 한계

- 핵심 요약 : 데이터 실체 파악 자동화의 장점, 계산 비용과 의미적 맥락 부재의 한계.
- 장점
  1. 대용량 데이터의 구조·품질을 수작업 없이 정량 지표로 신속 파악.
  2. 데이터 거버넌스 기준선(Baseline) 수립과 지속적 모니터링 기반 제공.
  3. ETL/ELT 파이프라인 설계 시 변환 로직, 예외 처리, 파티션 전략 수립의 근거 확보.
- 한계점 1 : 대용량 데이터 전수 조사 시 계산 리소스·시간 부담
  - 한계점 : 페타바이트급 테이블 전수 프로파일링 시 클러스터 리소스 점유 장시간, 운영 워크로드 경합.
  - 해결 방안 : 계층적 샘플링(Stratified Sampling), 증분 프로파일링(Incremental Profiling), 컬럼 프루닝(Column Pruning)으로 필수 컬럼만 선별 분석.
- 한계점 2 : 통계적 지표만으로는 비즈니스 의미적 품질 판단 불가
  - 한계점 : 널 비율 0%, 고유값 100%라도 비즈니스 룰(예: '주문일자 > 배송일자') 위반 여부는 프로파일링만으로 미탐지.
  - 해결 방안 : 프로파일링 지표 + 비즈니스 룰 엔진(규칙 기반 검증) 결합, 도메인 전문가 리뷰 루프 필수화.
- 한계점 3 : 비정형·반정형 데이터(로그, JSON, 텍스트) 프로파일링 한계
  - 한계점 : 스키마리스(Schema-less) 데이터에서 중첩 구조, 배열, 가변 스키마 분석 시 도구 지원 제한적.
  - 해결 방안 : 스키마 추론(Schema Inference) 후 평탄화(Flattening) 적용, 반정형 전용 프로파일러(예: JSON Profiler) 활용.

## Ⅵ. 데이터 프로파일링에 대한 기술사적 제언

- 핵심 요약 : DataOps 파이프라인 내 프로파일링 게이트 의무화와 데이터 카탈로그 연계 자동화 필요.
- DataOps 파이프라인 내 프로파일링 품질 게이트 의무화 : 소스 적재(Landing), 스테이징(Staging), 타겟(Target) 각 단계에서 자동 프로파일링 실행, 임계치(Null% > 5%, Distinct% < 1% 등) 초과 시 파이프라인 중단 및 알림 발송하는 품질 게이트(Quality Gate) 체계 구축 필요.
- 데이터 카탈로그(Data Catalog)와 프로파일링 메타데이터 자동 연계 : 프로파일링 실행 결과를 데이터 카탈로그(Apache Atlas, DataHub, OpenMetadata)의 테이블/컬럼 메타데이터에 자동 업데이트하여 '최신 프로파일 = 현재 데이터 상태' 동기화 유지 필요.
- 의미적 프로파일링(Semantic Profiling) 고도화 : 통계적 지표를 넘어 온톨로지(Ontology), 지식 그래프(Knowledge Graph) 기반 의미적 도메인 자동 태깅(예: '주민등록번호', '이메일', '카드번호')으로 민감 데이터 탐지·마스킹 자동화 필요.

## Ⅶ. 결론

- 핵심 요약 : 데이터 프로파일링은 데이터 이해의 자동화된 진단 체계로 파이프라인 게이트와 카탈로그 연계가 실효성의 관건.
- 요약 : 데이터의 구조·내용·관계를 통계·패턴·관계 분석으로 자동 진단하여 메타데이터와 품질 지표를 산출하는 선행 프로세스.
- 시사점 : 파이프라인 내 품질 게이트 의무화, 카탈로그 자동 동기화, 의미적 프로파일링 고도화의 3요소가 데이터 신뢰도 확보의 완성.
