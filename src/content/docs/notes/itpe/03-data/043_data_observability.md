## 연관 키워드
- 데이터 옵저버빌리티, 신선도, 볼륨, 스키마, 분포, 계보(Lineage), 인시던트(Incident)

### Ⅰ. 데이터 옵저버빌리티의 개요

- 핵심 요약 : 데이터 파이프라인과 데이터셋의 상태·이상·영향을 로그·메타데이터·계보·품질지표를 활용해 관측하는 운영 역량.
- 개념 : 로그·메타데이터·계보·품질지표를 활용해 데이터 파이프라인과 데이터셋의 상태·이상·영향을 관측하는 운영 역량(**데이터 옵저버빌리티**, Data Observability).
- 배경 및 필요성 : 파이프라인 성공 로그만으로는 잘못된 값·누락·지연이 소비자에게 전파되는 문제를 조기 발견하기 어려움.
- 주요 목적 : 데이터 장애의 탐지·원인 분석·영향 추적 시간 단축.

### Ⅱ. 데이터 옵저버빌리티의 특징 및 장점

- 핵심 요약 : 신선도·볼륨·스키마·분포·계보·영향의 4축이 통계·패턴·관계 분석을 담당하는 자동 진단 체계.

1. **신선도·볼륨** : 지연·레코드 급변 탐지 → 파이프라인 이상 포착.
2. **스키마·분포** : 계약·통계 변화 감지 → 조용한 데이터 손상 탐지.
3. **계보·영향** : 원천부터 소비까지 연결 → 영향받는 대시보드·모델 파악.
4. 자동화와 반복 실행 : 스케줄링으로 주기 실행하여 **데이터 드리프트**(Data Drift, 시간 흐름에 따른 데이터 분포의 변화)를 감지 → 품질 변화를 조기에 발견.

```text
[ 데이터 프로파일링 분석 계층 ]
열 프로파일링 (컬럼 단위)
   ↓
행 프로파일링 (레코드 단위)
   ↓
테이블 프로파일링 (구조 단위)
   ↓
교차 프로파일링 (테이블 간 관계)
```

### Ⅲ. 데이터 옵저버빌리티의 구조 (흐름)

- 핵심 요약 : 소스 연결 → 데이터 품질인증, 소스 연결·샘플링, 통계 수집, 품질 룰 평가, 리포트·메타데이터 출력의 순차 파이프라인.

```text
[ 데이터 옵저버빌리티 파이프라인 ]
[1] 소스 연결
   DB, 파일, 클라우드 스토리지, 스트림
          ↓
[2] 샘플링 전략
  전수 조사 또는 통계적 샘플링
          ↓
[3] 통계 수집 엔진
  열 통계, 패턴 추론, 관계 탐지
          ↓
[4] 품질 룰 평가
  완전성·유일성·유효성·일관성 검사
          ↓
[5] 리포트·메타데이터 출력
  프로파일 리포트, 카탈로그 등록
```

- 열 프로파일링의 지표는 기본 통계(개수, 널 개수·비율, 고유값 수), 수치형 지표(최소·최대·평균·사분위수), 문자열 지표(길이 분포), 분포 분석(히스토그램, 상위 빈도값), 패턴 분석(정규식 매칭률, 자료형 추론)으로 나뉜다.

### Ⅳ. 수동 분석과 자동 프로파일링의 비교

- 핵심 요약 : 샘플링 기반 수작업에서 전수 자동화로, 분석자 판단에서 정량 지표 기반으로 전환.

| 비교 기준 | 수동 데이터 분석(엑셀, SQL) | 자동 데이터 프로파일링 도구 |
|---|---|---|
| 분석 범위 | 샘플 기반의 제한적 조사 | 전수 조사 또는 대표성을 갖춘 샘플링 |
| 분석 속도 | 인력 투입에 따라 긴 시간 소요 | 병렬 처리로 짧은 주기 반복 가능 |
| 지표 일관성 | 분석자별 편차 발생 | 표준화된 지표 정의로 일관성 확보 |
| 패턴 탐지 | 정규식을 수작업으로 작성 | 패턴과 자료형을 자동 추론 |
| 관계 분석 | 조인 쿼리를 수작업으로 작성 | 외래키 후보와 함수적 종속성 자동 탐지 |
| 이력 관리 | 버전 관리 곤란 | 실행 이력과 드리프트 비교 내장 |

### Ⅴ. 데이터 옵저버빌리티의 한계와 방안

- 핵심 요약 : 대용량 연산 부담, 의미적 품질 판단 불가, 반정형 데이터 지원 한계를 샘플링·룰 엔진·스키마 추론으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 대용량 전수 조사 부담 | 대형 테이블 전수 분석으로 클러스터 자원 점유, 운영 작업과 경합 | **계층적 샘플링**(Stratified Sampling), **증분 프로파일링**(Incremental Profiling), 필수 컬럼만 선별 분석 | 프로파일링 소요 시간, 자원 사용률 |
| 의미적 품질 판단 불가 | 널 비율이 0%이고 고유값이 100%여도 업무 규칙 위반은 통계로 드러나지 않음 | 프로파일링 지표와 업무 규칙 엔진 결합, 도메인 전문가 검토 | 규칙 위반 건수 |
| 반정형·비정형 데이터 | 스키마가 없는 로그, JSON, 텍스트에서 중첩 구조 분석 도구 지원이 제한적 | 스키마 추론 후 평탄화(Flattening), 반정형 데이터 전용 프로파일러 활용 | 스키마 추론 성공률 |

### Ⅵ. 데이터 옵저버빌리티에 대한 기술사적 제언

- 핵심 요약 : 파이프라인에 품질 게이트를 의무화하고 카탈로그와 자동 연계하여 프로파일링을 일회성 분석이 아닌 상시 통제 수단으로 만드는 방향이 바람직함.
- 데이터 적재의 각 단계에서 자동 프로파일링을 실행하고, 임계치를 넘으면 파이프라인을 멈추고 담당자에게 알리는 **품질 게이트**(Quality Gate)를 **데이터 옵저버빌리티**(DataOps, 데이터 파이프라인의 자동화와 품질 관리를 결합한 운영 방식) 체계 안에 두는 것이 바람직함.
- 프로파일링 결과는 **데이터 카탈로그**(Data Catalog)의 테이블과 컬럼 메타데이터에 자동 반영되어 카탈로그가 현재의 데이터 상태를 보여 주도록 연계하는 것이 바람직함.
- 의미적 프로파일링(**Semantic Profiling**)을 도입해 주민등록번호, 이메일, 카드번호 같은 민감 데이터를 도메인 기준으로 자동 태깅하면 마스킹 정책을 일관되게 적용할 수 있다.

### Ⅶ. 결론

- 핵심 요약 : 데이터 옵저버빌리티는 데이터 파이프라인과 데이터셋의 상태·이상·영향을 로그·메타데이터·계보·품질지표를 활용해 관측하는 운영 역량.
- 시사점 : 데이터 품질인증은 데이터 자산의 공신력을 입증하는 공인 기준이나, 인증 이후의 상시 품질 거버넌스와 결합되어야 실효성을 가짐.
