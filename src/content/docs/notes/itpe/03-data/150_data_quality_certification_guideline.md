## 지식 로드맵 내 현재 위치

지식 위치: 자료처리·데이터 → 데이터 품질관리 → **데이터 품질인증**

## 30초 인출

- 본질: **데이터 품질인증**은 신청 대상 데이터의 품질을 법령상 기준에 따라 지정 인증기관이 평가하는 제도
- 메커니즘: 인증 대상 선택 → 내용·구조·관리체계에 해당하는 기준으로 심사 → 인증 결과 확인

<details>
<summary>핵심 용어</summary>

- **데이터 품질인증(Data Quality Certification)** : 신청 대상 데이터의 품질을 법정 기준에 따라 인증기관이 평가하는 제도
- **완전성** : 필요한 데이터 값의 누락 여부를 보는 품질 특성
- **유효성** : 값이 정해진 형식·범위·규칙을 따르는지 보는 품질 특성
- **정확성** : 값이 확인 가능한 실제 사실이나 기준과 일치하는지 보는 품질 특성
- **일관성** : 데이터 구조의 정의·관계·표현이 서로 충돌하지 않는지 보는 품질 특성
- **유용성** : 데이터가 이용 목적에 적합한지 보는 품질 특성
- **접근성** : 권한 있는 이용자가 필요한 데이터에 접근할 수 있는지 보는 품질 특성

</details>

### Ⅰ. 데이터 품질인증의 개요

| 항목 | 핵심 서술 내용 |
|:---|:---|

- **10점 제언**: 인증에 사용한 품질기준을 운영 중 점검 규칙과 개선 이력에 연결.

### Ⅱ. 데이터 품질인증의 대상과 기준

flowchart TB

### 핵심 관계

| **관리체계** | 유용성·접근성 | 데이터를 목적에 맞게 활용하고 필요한 사용자가 접근할 수 있는지 확인 |

---

## 2~4교시 25점 답안

### Ⅰ. 데이터 품질인증 제도의 개요 및 법적 근거

| 구분 | 핵심 |
|---|---|
| **정의** | **데이터 품질인증**은 신청 대상 데이터의 품질을 법령이 정한 기준으로 평가하는 제도 |
| **목적** | 데이터의 품질을 확인해 이용·관리 판단의 신뢰성 확보 |

- **추진 배경**:
  - 서로 다른 기관과 업무에서 생산·유통되는 데이터 품질을 확인할 법령상 기준과 인증 절차의 필요
- **법적 근거**:
  - **데이터산업법 제20조 (데이터 품질관리 등)**: 과학기술정보통신부장관은 관계 부처와 협의해 품질인증 등 품질관리 사업을 추진할 수 있고, 인증기관을 지정할 수 있음. 지정 기관은 법정 품질기준에 따라 신청 건을 인증.
- **핵심 가치**:
  - 신청 데이터의 품질 특성을 확인하고 품질관리 개선에 활용

### Ⅱ. 법적 근거와 인증 대상

데이터산업법 제20조는 데이터 품질관리 사업과 인증기관 지정의 근거를 둔다. 시행령 제20조의5는 인증 대상을 데이터 내용·구조·관리체계 등으로 구분하고 대상별 품질기준을 정한다.

```mermaid
flowchart TB
    A[데이터산업법 제20조<br/>품질관리·인증기관 근거] --- B[시행령 제20조의5<br/>인증 대상별 품질기준]
    B --- C[내용<br/>완전성·유효성·정확성]
    B --- D[구조<br/>일관성]
    B --- E[관리체계<br/>유용성·접근성]
```

| 대상 | 품질기준 | 확인 질문 |
|---|---|---|
| **데이터 내용** | 완전성·유효성·정확성 | 필요한 값이 있고, 허용 범위에 맞으며, 실제 사실·기준과 일치하는가 |
| **데이터 구조** | 일관성 | 항목·관계·표현의 정의가 서로 충돌하지 않는가 |
| **데이터 관리체계** | 유용성·접근성 | 이용 목적에 맞고 필요한 이용자가 접근할 수 있는가 |

### Ⅲ. 신청·심사·인증의 관계

신청 대상과 기준을 정해 자료를 제출하면 인증기관이 해당 기준으로 심사하고 결과를 통지하는 구조.

```mermaid
flowchart TB
    A[신청자<br/>대상·설명자료 제출] --> B[지정 인증기관<br/>대상별 기준으로 심사]
    B --> C{추가 확인}
    C -->|필요| D[자료 보완·현장 확인]
    D --> B
    C -->|심사 완료| E[인증 결과 통지]
```

인증 절차의 세부 서식·방법·유효기간은 현행 법령과 소관 고시를 확인. 이 도해는 신청과 심사의 핵심 관계를 요약한 것으로 모든 법정 절차의 순서를 재현한 것은 아님.

### Ⅳ. 인증 기준의 운영 적용

인증 당시의 평가 결과는 운영 중 새로 유입되는 데이터의 품질을 자동으로 보장하지 않음. 대상별 기준을 실제 점검 규칙에 연결하고, 위반 결과와 조치 이력을 관리.

```mermaid
flowchart TB
    A[인증 대상별 품질기준] --> B[원천·적재 데이터 점검 규칙]
    B --> C[위반 탐지·담당자 확인]
    C --> D[원인 수정·재점검]
    D --> E[품질 추이와 개선 이력]
```

| 한계 | 대응 |
|---|---|
| 인증 시점 이후 데이터 내용·구조가 변경될 수 있음 | 유입·변경 시 완전성·유효성·정확성·일관성 점검 |
| 기준은 있으나 오류를 수정할 담당과 이력이 불분명할 수 있음 | 항목별 책임자와 조치 기한을 정하고 재점검 결과 기록 |

### Ⅴ. 기술사적 제언

| 우선 제언 | 실행·확인 |
|---|---|
| 인증 대상·기준을 운영 규칙에 연결 | 데이터 변경 시 점검 규칙도 함께 갱신 |
| 인증 이후 품질 변화를 관찰 | 기준별 점검 결과와 개선 이력을 주기적으로 확인 |
