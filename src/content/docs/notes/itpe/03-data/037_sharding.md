## 연관 키워드
- 샤딩, 파티션 키, 해시·범위 샤딩, 라우팅, 리밸런싱, 핫 스팟

### Ⅰ. 샤딩의 개요

- 핵심 요약 : 샤딩은 논리 데이터 집합을 키 기준으로 여러 DB 노드에 수평 분산하는 기법.
- 개념 : 논리 데이터 집합을 키 기준으로 여러 DB 노드에 수평 분산하는 기법(**샤딩**, Sharding).
- 배경 및 필요성 : 단일 DB 노드가 저장량·쓰기 처리량·가용성 한계에 도달.
- 주요 목적 : 노드 추가로 데이터 용량과 처리량을 수평 확장.

### Ⅱ. 샤딩의 특징 및 장점

- 핵심 요약 : 해시 샤딩·범위 샤딩·샤드 라우팅은 데이터 분산과 쿼리 비용 통제를 지원하는 샤딩 방식.

1. 해시 샤딩 : 균등 분산 → 범위 질의 효율은 낮음.
2. 범위 샤딩 : 키 순서 보존 → 편향·핫 샤드 가능.
3. 샤드 라우팅 : 키를 노드로 매핑 → 교차 샤드 질의 비용 통제.

### Ⅲ. 샤딩의 구조 (흐름)

- 핵심 요약 : 키·분포·접근 패턴 분석 → 샤드 키·분할 전략 결정 → 라우터·분산 인덱스 구성 → 노드 추가·데이터 재배치 → 복구·재 균형·교차 샤드 시험.

```text
키·분포·접근 패턴 분석
  ↓
샤드 키·분할 전략 결정
  ↓
라우터·분산 인덱스 구성
  ↓
노드 추가·데이터 재배치
  ↓
복구·재 균형·교차 샤드 시험
```

```text
키 → 샤드 맵 → 노드 배치
조회 키 → 라우터 → 관련 샤드
교차 키 질의 → 다중 샤드 병렬·결과 병합
```

### Ⅳ. 샤딩과 단일 노드 파티셔닝 비교

- 핵심 요약 : 운영 복잡도 기준 — 샤딩: 라우팅·복제·분산 트랜잭션 관리; 단일 노드 파티셔닝: DBMS가 물리·논리 파티션 관리.

| 비교 축 | 샤딩 | 단일 노드 파티셔닝 |
|---|---|---|
| 분산 단위 | 여러 DB 노드에 데이터 배치 | 한 DBMS 내부 테이블 파티션 |
| 운영 복잡도 | 라우팅·복제·분산 트랜잭션 관리 | DBMS가 물리·논리 파티션 관리 |

### Ⅴ. 샤딩의 한계와 방안

- 핵심 요약 : 핫 샤드·교차 샤드 비용 등 주요 위험을 원인에 맞는 통제로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 핫 샤드 | 키 분포가 편향되어 한 노드 과부하 | 키 카디널리티·트래픽 측정, 재 분할 계획 | 노드 부하 편차 |
| 교차 샤드 비용 | 조인·정렬·트랜잭션이 네트워크 통신 필요 | 주요 질의를 샤드 키에 정렬·집계 모델 분리 | 교차 샤드 비율 |
| 리밸런싱 위험 | 노드 추가·장애 시 대량 이동과 가용성 저하 | 온라인 재 배치·체크포인트·복구 리허설 | 재 배치 시간·오류 |

### Ⅵ. 샤딩에 대한 제언

- 핵심 요약 : 아키텍트는 단일 DB 최적화와 파티셔닝을 먼저 평가하고 샤딩 채택 시 샤드 키 변경·분산 트랜잭션·복구 전략을 제품 설계에 포함.

- 실행 제안 : 설계 위원회는 샤드 키 변경·노드 장애·교차 샤드 트랜잭션을 포함한 재 분배 시나리오와 롤백 계획 승인.

### Ⅶ. 결론

- 핵심 요약 : 샤딩의 수평 확장은 키 선택과 분산 질의의 복잡성을 함께 수반하므로 워크로드 근거가 선행되어야 함.
- 시사점 : 샤딩은 데이터 분할보다 라우팅·교차 샤드 일관성·온라인 재 배치의 운영 설계가 성패를 좌우.
