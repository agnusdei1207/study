## 연관 키워드

- 데이터 모델링(Data Modeling), 개념적 모델링, 논리적 모델링, 물리적 모델링, 3층 스키마
- 엔티티(Entity), 속성(Attribute), 관계(Relationship), 식별자(Identifier), 정규화(Normalization), 반정규화(Denormalization)

## Ⅰ. 데이터 모델링의 개요

- 핵심 요약 : 현실 업무의 데이터와 규칙을 단계적으로 추상화해 데이터베이스 구조로 형상화하는 설계 활동.
- 개념 : 업무 대상과 규칙을 추상화·단순화·명확화의 원칙으로 형식화해 데이터베이스 구축의 청사진을 만드는 **데이터 모델링**(Data Modeling) 활동.
- 배경 및 필요성 : 자연어 요구사항은 모호하고 해석이 갈리므로, 이해관계자 전체가 공유하는 표준화된 표현 체계 필요.
- 주요 목적 : 업무 요구사항의 완전한 반영, 데이터 중복 최소화, 변경에 유연한 구조의 확립.

## Ⅱ. 데이터 모델링의 특징 및 장점

- 핵심 요약 : 추상화 원칙, 규칙의 구조 반영, 단계별 전개가 의사소통 효율과 데이터 품질로 이어지는 설계 체계.

1. 추상화 원칙 : 복잡한 현실 업무를 핵심 요소 중심으로 단순화 → 이해관계자 공통의 모델 확보와 소통 비용 절감.
2. 규칙의 구조 반영 : 엔티티 간 관계와 식별자 체계로 업무 규칙을 명시 → 규칙에 어긋나는 데이터 입력의 구조적 차단.
3. 중복 최소화 : 동일 사실의 단일 관리 구조 → 갱신 이상과 데이터 불일치의 예방.
4. 단계별 전개 : 추상도가 높은 단계에서 구현 단계로 점진 구체화 → 현업 합의와 기술 검증의 분리 수행.
5. 변경 대응력 : 업무 변화 시 해당 부분의 국소 수정 → 유지보수 비용과 영향 범위 축소.

## Ⅲ. 데이터 모델링의 구조 (흐름)

- 핵심 요약 : 업무 요구사항이 개념적, 논리적, 물리적 모델링을 거쳐 물리 데이터베이스로 구체화되는 3단계 흐름.
- 구성요소 : **엔티티**(Entity, 관리 대상 객체), **속성**(Attribute, 엔티티가 지닌 성질), **관계**(Relationship, 엔티티 간 의미적 연관), **식별자**(Identifier, 인스턴스 구분 속성).
- 단계별 정의 : 업무 관점의 **개념적 모델링**(Conceptual Modeling), 구조 완전성 중심의 **논리적 모델링**(Logical Modeling), 구현 최적화 중심의 **물리적 모델링**(Physical Modeling).
- 논리적 모델링의 대표 산출물은 개체-관계 다이어그램(ERD, Entity-Relationship Diagram).
- **정규화**(Normalization, 중복 제거를 위한 스키마 분해)는 논리적 모델링에서 수행하고, 조회 성능 목적의 **반정규화**(Denormalization, 의도적 중복 허용)는 물리적 모델링에서 선별 적용.

```text
[데이터 모델링 3단계]
업무 요구사항 분석
   ↓
개념적 모델링 (핵심 엔티티·관계 도출)
   ↓
논리적 모델링 (속성·식별자 정의)
   ↓
물리적 모델링 (테이블·타입·인덱스)
   ↓
물리 데이터베이스 구축
```

- 사용자 관점, 전사 논리 구조, 물리 저장 구조를 분리하는 **3층 스키마**(3-Level Schema) 구조로 응용과 저장 기술의 독립성 확보.

```text
[3층 스키마 구조]
외부 스키마 (사용자별 뷰)
   ↓ 논리적 독립성
개념 스키마 (전사 논리 구조)
   ↓ 물리적 독립성
내부 스키마 (물리 저장 구조)
```

- 데이터 모델은 구조 표현 방식에 따라 계층형, 네트워크형, 관계형, 객체지향형 모델로 분류되며, 관계형 모델이 현재의 표준 구조.

## Ⅳ. 개념적·논리적·물리적 모델링의 비교

- 핵심 요약 : 추상도, 산출물, 참여자가 단계별로 다르므로 각 단계의 역할 구분 수행이 기준.

| 구분 | 개념적 모델링 | 논리적 모델링 | 물리적 모델링 |
| :--- | :--- | :--- | :--- |
| 수행 목적 | 업무 범위와 핵심 개체 정의 | 데이터 구조와 규칙의 완전성 확보 | 저장 구조의 성능 최적화 |
| 주요 산출물 | 핵심 엔티티와 관계 정의 | ERD, 정규화된 논리 스키마 | 테이블 정의서, 인덱스 설계서 |
| 식별자 표현 | 개념 식별 수준 | 주식별자·외래식별자 확정 | 기본키·외래키의 물리 명칭 |
| DBMS 종속성 | 독립 | 독립 | 종속 |
| 주요 참여자 | 현업 담당자, 경영진 | 데이터 모델러, 개발자 | DBA(Database Administrator), 개발자 |

- 선택 기준 :
  1. 현업 합의가 목적이면 개념 모델 수준에서 검토 종료, 시스템 구현이 목적이면 논리·물리 단계까지 전개.
  2. DBMS 교체 가능성이 있는 환경은 논리 모델을 독립 자산으로 유지하고 물리 모델만 교체 대상으로 관리.

## Ⅴ. 데이터 모델링의 한계와 방안

- 핵심 요약 : 업무 규칙의 구조화라는 이점 이면에 요구사항 왜곡, 최신성 상실, 성능 미고려, 근거 소실의 위험 존재.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| 요구사항 누락·왜곡 | 현업 암묵 지식의 모델 변환 과정 손실 | 도메인 전문가 참여 검토 회의의 정례화 | 요구사항 재작업 건수 |
| 최신성 유지 실패 | 업무 변화에 모델 갱신이 뒤처짐 | 모델과 실제 스키마의 일치 점검 절차 운영 | 모델·스키마 불일치 건수 |
| 성능 미고려 설계 | 논리 완전성만 추구해 물리 부하 발생 | 접근 경로·트래픽 추정 기반의 물리 검토 병행 | 질의 응답 시간 |
| 설계 근거 소실 | 인원 이탈 시 결정 배경의 단절 | 모델 버전 관리와 설계 결정 사항 기록 | 문서 갱신 주기 |

## Ⅵ. 데이터 모델링에 대한 기술사적 제언

- 핵심 요약 : 모델을 일회성 산출물이 아닌 전사 데이터 자산으로 관리하는 거버넌스 체계로의 전환.

1. 데이터 관리 조직은 전사 데이터 표준과 모델링 가이드를 제정하고 신규 시스템 구축 시 표준 준수를 사전 검토 항목으로 지정.
2. 개발 조직은 논리 모델과 물리 구현의 대응 관계를 매핑 문서로 유지해 스키마 변경의 영향 분석 기반 확보.
3. 데이터 아키텍처 조직은 시스템 간 중복 엔티티의 주기적 식별과 마스터 데이터 통합 방안의 수립 주체 역할 수행.

## Ⅶ. 결론

- 핵심 요약 : 데이터 모델링은 업무 본질을 데이터 구조로 옮기는 설계 활동이며 단계별 역할 분리가 품질의 전제.
- 시사점 : 개념·논리·물리의 구분 수행과 모델의 지속 관리가 변경에 강한 데이터 기반 확립.
