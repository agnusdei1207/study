## 연관 키워드
- 개념·논리·물리 모델, 개체, 속성, 관계, 키, 함수 종속

### Ⅰ. 데이터 모델링의 개요

- 핵심 요약 : 데이터 모델링은 업무의 데이터 개념·관계·제약을 추상화해 논리 구조와 구현 스키마로 변환하는 설계 활동.
- 개념 : 업무의 데이터 개념·관계·제약을 추상화해 논리 구조와 구현 스키마로 변환하는 설계 활동(**데이터 모델링**, Data Modeling).
- 배경 및 필요성 : 요구와 DB 구현을 바로 연결하면 용어 충돌·중복·무결성 누락이 발생.
- 주요 목적 : 업무 의미를 일관된 구조·제약·저장 설계로 구체화.

### Ⅱ. 데이터 모델링의 특징 및 장점

- 핵심 요약 : 개념 모델·논리 모델·물리 모델은 업무 합의와 DBMS 독립 구조·플랫폼 성능·운영을 지원하는 데이터 모델링 단계.

1. 개념 모델 : 업무 개체·관계 중심 → 이해 관계자 합의.
2. 논리 모델 : 속성·키·정규화·제약 → DBMS 독립 구조.
3. 물리 모델 : 자료형·인덱스·파티션 → 플랫폼 성능·운영 반영.

### Ⅲ. 데이터 모델링의 구조 (흐름)

- 핵심 요약 : 업무 규칙·용어 수집 → 개체·관계·카디널리티 정의 → 키·속성·함수 종속 분석 → 논리 스키마 정규화 → DBMS별 물리 구조·DDL 구현.

```text
업무 규칙·용어 수집
  ↓
개체·관계·카디널리티 정의
  ↓
키·속성·함수 종속 분석
  ↓
논리 스키마 정규화
  ↓
DBMS별 물리 구조·DDL 구현
```

```text
업무 규칙 → 개념 ER 모델 → 논리 관계 모델 → 물리 DB 스키마
```

### Ⅳ. 논리 데이터 모델과 물리 데이터 모델 비교

- 핵심 요약 : 주요 관심 기준 — 논리 데이터 모델: 업무 의미·키·정규형; 물리 데이터 모델: 성능·저장·운영·접근 경로.

| 비교 축 | 논리 데이터 모델 | 물리 데이터 모델 |
|---|---|---|
| 기술 종속 | DBMS 독립적 구조·제약 | 특정 DBMS 자료형·인덱스·저장 방식 |
| 주요 관심 | 업무 의미·키·정규형 | 성능·저장·운영·접근 경로 |

### Ⅴ. 데이터 모델링의 한계와 방안

- 핵심 요약 : 업무 규칙 누락·과도한 비 정규화 등 주요 위험을 원인에 맞는 통제로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 업무 규칙 누락 | 모델이 실제 데이터 의미를 반영하지 못함 | 현업 검토·예시 데이터·규칙 추적 | 요구-모델 불일치 |
| 과도한 비 정규화 | 관계·중복에 따른 갱신 이상 | 함수 종속·정규화 검토 후 근거 있는 절충 | 중복·이상 건수 |
| 모델-구현 괴리 | 물리 변경 후 문서 미갱신 | DDL 비교·버전 관리·변경 승인 연결 | 모델 불일치 |

### Ⅵ. 데이터 모델링에 대한 제언

- 핵심 요약 : 데이터 아키텍트는 용어·업무 규칙에서 키와 물리 설계까지 추적 링크를 유지하고 모델 변경을 데이터 계약·마이그레이션 검토와 연계.

- 실행 제안 : 모델 관리자는 개념-논리-물리 모델과 DDL 간 변경 영향 링크를 유지하고 배포 전 무손실성·성능을 승인.

### Ⅶ. 결론

- 핵심 요약 : 좋은 데이터 모델은 현실을 모두 복제하는 그림이 아니라 업무에서 중요한 의미·제약을 명료하게 표현하는 계약.
- 시사점 : 개념·논리·물리 모델을 추적 가능하게 유지하면 업무 변경의 스키마·마이그레이션 영향 파악에 유리.
