## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터 품질·운영 → **데이터 관측가능성(Data Observability)**

## 30초 인출

- 본질: 데이터 관측가능성은 메타데이터와 데이터 검사로 데이터의 상태와 이상 원인을 파악하는 운영 능력
- 메커니즘: 출력 데이터셋의 신선도·볼륨·스키마·분포를 기준선과 비교해 이상을 감지하고, 계보로 원천·작업과 하류 소비 업무의 영향 범위를 추적해 소유자가 조치
- 통찰: 작업이 정상 종료해도 결과 데이터는 틀릴 수 있으므로 작업 모니터링과 별도로 데이터 자체의 기준선과 규칙을 두고, 계보와 소유자를 연결해 영향 범위를 빠르게 좁힘

<details>
<summary>핵심 용어</summary>

- **데이터 관측가능성(Data Observability)** : 데이터의 상태와 이상 원인을 파악하는 운영 능력
- **신선도(Freshness)** : 데이터가 제때 도착·갱신되었는지의 정도
- **볼륨(Volume)** : 데이터의 건수·크기
- **스키마 변경** : 필드·자료형 변화
- **분포(Distribution)** : 값의 통계·결측 상태
- **계보(Lineage)** : 데이터의 입력·작업·출력 관계
- **기준선(Baseline)** : 정상 범위로 삼는 기준

</details>

## 2~4교시 25점 답안

## Ⅰ. 데이터 관측가능성의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터 관측가능성** 은 메타데이터와 데이터 검사로 데이터 상태와 이상 원인을 파악하는 운영 능력 |
| 목적 | 데이터 품질 이상과 하류 소비자 영향을 조기에 발견 |

## Ⅱ. 특징

| 특징 | 운영 의미 |
|---|---|
| 결과 데이터 관찰 | 작업 성공과 별도로 신선도·건수·스키마·분포 확인 |
| 계보 기반 영향 분석 | 이상 데이터의 원천·변환·소비 업무 연결 |
| 기준선·책임 연결 | 정상 범위와 소유자를 정해 경보·조치 |

## Ⅲ. 관측 차원과 분석 흐름

```text
원천 → 처리 작업 → 출력 데이터셋 → 리포트·서비스
                        ↑
      신선도·볼륨·스키마·분포 검사 → 이상 감지 → 계보로 하류 영향 추적 → 소유자 조치
```

| 관점 | 확인 정보 | 예시 |
|---|---|---|
| 신선도 | 도착·갱신 시점 | 배치 지연 |
| 볼륨 | 건수·크기 | 예상보다 적은 적재량 |
| 스키마 | 필드·자료형 | 필드명 변경 |
| 분포 | 값의 통계·결측 | 특정 코드값 급증 |
| 계보 | 입력·작업·출력 관계 | 영향받은 대시보드 추적 |

다섯 관점은 관측 항목을 정리하는 대표적 실무 분류이며 모든 구현의 고정 표준은 아님.

## Ⅳ. 작업 모니터링과의 비교

| 구분 | 작업 모니터링 | 데이터 관측가능성 |
|---|---|---|
| 관찰 대상 | 작업 실행·자원 상태 | 데이터 상태·품질·계보 |
| 질문 | 작업이 실행되었는가 | 결과 데이터가 기대한 상태인가, 영향 범위는 어디인가 |
| 한계 | 정상 종료만으로 정확성 확인 불가 | 규칙·기준선·계보가 불완전하면 원인 설명 제약 |
| 보완 | 품질 검사 추가 | 업무 규칙·책임자·영향 분석 절차 연계 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 정상 종료한 파이프라인의 결과 오류가 늦게 발견 | 기준선과 규칙 검사 적용 |
| 검사 결과와 소비 업무 분리로 영향 범위 추적 지연 | 핵심 흐름의 소유자·품질 규칙·계보 연결, 장애 사례로 추적 시험 |

## Ⅵ. 제언

핵심 데이터 흐름부터 관측 차원별 기준선과 소유자를 정하고 계보로 영향 범위를 자동 추적

```text
핵심 데이터셋 선정 → 관측 차원별 기준선 → 이상 경보 → 계보로 영향 추적 → 소유자 조치
```

| 구분 | 작업 모니터링만 | 제언: 데이터 관측 병행 |
|---|---|---|
| 탐지 | 실행 실패만 | 데이터 이상까지 |
| 영향 파악 | 수작업 | 계보로 추적 |
