## 연관 키워드

- 파일 시스템, File System
- 연속 할당, 연결 할당, 색인 할당
- i-node, 저널링, XFS, Direct I/O, 익스텐트

## Ⅰ. 파일 시스템 데이터 관리의 개요

- 핵심 요약 : **파일 시스템**(File System)은 운영체제가 보조기억장치의 블록을 파일 단위로 할당·관리하여 데이터를 영속화하는 소프트웨어 계층.
- 개념 : 보조기억장치 위에 파일과 디렉터리의 이름, 위치, 속성을 구조화하여 데이터를 저장·조회·보호하는 운영체제 계층.
- 배경 및 필요성 : DBMS(Database Management System)의 데이터 파일도 결국 파일 시스템 위에 저장되므로, 물리 저장 계층의 성능과 무결성이 상위 시스템 전체의 신뢰도를 좌우함.
- 주요 목적 : 데이터 영속성, 접근 제어, 무결성 확보.

## Ⅱ. 파일 시스템의 특징 및 장점

- 핵심 요약 : 블록 할당 방식과 i-node, 저널링이 결합되어 접근 성능과 장애 후 무결성을 함께 확보하는 구조.

1. **연속 할당** (Contiguous Allocation) : 파일 블록을 연속 배치 → 순차 I/O 성능 극대화, 외부 단편화 발생.
2. **연결 할당** (Linked Allocation) : 블록마다 다음 블록 포인터 보유 → 외부 단편화 해소, 직접 접근 불가.
3. **색인 할당** (Indexed Allocation) : 인덱스 블록이 전체 포인터 보유 → 직접 접근과 순차 접근 모두 고속.
4. **i-node** : 파일 메타데이터와 다계층 블록 포인터를 담은 색인 구조 → 파일 크기에 따라 포인터 계층 확장.
5. **저널링** (Journaling) : 변경 내역을 로그에 먼저 기록 → 비정상 종료 후 빠른 복구와 메타데이터 무결성 확보.

## Ⅲ. 파일 시스템의 구조 (흐름)

- 핵심 요약 : 3대 블록 할당 방식의 구조 차이와, 쓰기 요청이 저널을 거쳐 데이터 블록에 반영되는 흐름.

```text
[ 3대 블록 할당 방식 ]

연속 할당 : 블록 1, 2, 3, 4 연속 배치
   ↓
연결 할당 : 블록마다 다음 블록 포인터
   ↓
색인 할당 : 인덱스 블록이 포인터 집중 보유
```

```text
[ i-node 다계층 포인터 ]

i-node (메타데이터 + 포인터)
   ↓
직접 블록 (소형 파일)
   ↓
단일 간접 → 이중 간접 → 삼중 간접
   ↓
대용량 파일의 데이터 블록
```

```text
[ 쓰기 요청의 저널링 흐름 ]

쓰기 요청 수신
   ↓
저널(로그)에 변경 내역 기록
   ↓
데이터 블록과 i-node 반영
   ↓
커밋 표시 후 저널 정리
```

## Ⅳ. 할당 방식의 비교

- 핵심 요약 : 순차 I/O 성능, 단편화, 직접 접근 가능 여부로 3대 할당 방식을 비교하며, 현대 파일 시스템은 색인 할당을 기본으로 채택.

| 비교 항목 | 연속 할당 | 연결 할당 | 색인 할당 |
| --- | --- | --- | --- |
| 순차 I/O | 극대 | 중간 | 고속 |
| 직접 접근 | 가능 | 불가 | 가능 |
| 단편화 | 외부 단편화 심각 | 없음 | 없음 |
| 대표 사용 예 | 제한적 사용 | FAT(File Allocation Table) | Ext4 등 현대 파일 시스템 |

## Ⅴ. 파일 시스템의 한계와 방안

- 핵심 요약 : 단편화, 비정상 종료 시 메타데이터 불일치, 소용량 파일 과다의 한계를 익스텐트, 저널링, 인덱싱으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 단편화와 I/O 성능 간 트레이드오프 | 연속 할당의 외부 단편화, 연결·색인 포인터 오버헤드 | **익스텐트**(Extent) 기반 할당, 주기적 조각 모음 | I/O 지연 시간 |
| 크래시 시 메타데이터 불일치 | 비정상 종료로 고아 블록과 파일 손상 발생 | 저널링 적용, CoW(Copy-on-Write) 기반 파일 시스템 검토 | 복구 소요 시간 |
| 소용량 파일 과다로 i-node 고갈 | i-node 소진, 디렉터리 조회 병목 | 디렉터리 해시 인덱스(dir_index), 아카이빙 | i-node 사용률 |

## Ⅵ. 파일 시스템에 대한 기술사적 제언

- 핵심 요약 : DBMS 데이터 파일은 저널링 기반 고병렬 파일 시스템과 **Direct I/O**를 조합해 이중 버퍼링 없이 저장하는 구성이 바람직함.
- DBMS 데이터 파일을 저장하는 볼륨은 병렬 I/O 처리와 저널링 지연이 작은 **XFS** 같은 파일 시스템을 기준으로 선정하는 것이 바람직하다.
- DBMS가 자체 버퍼 캐시를 운용하는 경우 O_DIRECT 방식의 Direct I/O를 적용해 운영체제 페이지 캐시와의 이중 버퍼링을 피하는 것이 좋다.
- 대용량 데이터 파일은 익스텐트 기반 할당을 유지해 단편화를 억제하고, 스토리지 설계 표준에 파일 시스템 선택 기준과 I/O 지연 지표를 함께 명시하는 것이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : 파일 시스템은 블록 할당, i-node, 저널링의 조합으로 데이터 영속성과 무결성을 확보하는 저장 계층.
- DBMS 성능은 상위 질의 최적화뿐 아니라 이 물리 계층의 설계에도 좌우되므로, 두 계층을 함께 설계해야 한다.
