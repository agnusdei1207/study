## 30초 인출

- 본질: 파일 시스템 데이터 관리는 파일·디렉터리와 저장 공간을 조직하고 경로·속성·권한에 따라 데이터를 읽고 쓰게 하는 운영체제의 관리 기능
- 메커니즘: 경로명을 이름 해석으로 파일 메타데이터에 연결하고 블록 매핑으로 저장 블록에 접근하며, 파일 내부의 레코드 조직은 순차·직접·색인 순차 방식으로 설계
- 통찰: 파일 시스템은 파일 단위 저장이 강점이고 레코드 간 관계·제약·트랜잭션은 응용이나 DBMS의 몫이므로, 원본은 파일·객체 저장소에 두고 업무 관계·권한은 DBMS로 관리하되 둘 사이의 참조 정합성을 검사

## 2~4교시 25점 답안

## Ⅰ. 파일 시스템 데이터 관리의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **파일 시스템 데이터 관리** 는 파일·디렉터리와 저장 공간을 조직하고 경로·속성·권한으로 데이터를 읽고 쓰게 하는 운영체제 기능 |
| 목적 | 응용이 물리 위치를 직접 다루지 않고 파일 단위로 데이터 이용 |

## Ⅱ. 특징

| 특징 | 의미 |
|---|---|
| 파일·경로 추상화 | 물리 블록 주소 대신 이름으로 접근 |
| 메타데이터 관리 | 크기·권한·위치·시각 유지 |
| 레코드 의미 분리 | 파일 내부의 레코드·관계·제약은 응용 또는 DBMS가 관리 |

## Ⅲ. 경로 해석과 입출력

```text
경로명 → 이름 해석 → 파일 메타데이터 → 블록 매핑 → 저장 블록
                         └ 권한·크기 확인 ── 결과·오류 반환
```

| 구성 | 역할 |
|---|---|
| 디렉터리·경로 | 이름과 위치 조직 |
| 메타데이터 | 크기·권한·저장 블록 관리 |
| 입출력 인터페이스 | 열기·읽기·쓰기·닫기 |

## Ⅳ. 파일 조직 방식과 DBMS 비교

| 조직 방식 | 접근 | 적합 | 한계 |
|---|---|---|---|
| 순차 | 순서대로 처리 | 일괄 처리 | 임의 레코드 검색 비용 |
| 직접 | 키·주소 계산 | 키 중심 조회 | 충돌·배치 관리 |
| 색인 순차 | 색인으로 찾고 순차 접근 | 검색과 순차 처리 혼용 | 색인·오버플로 관리 |

위 표는 파일 내부 레코드 설계이며 모든 파일 시스템이 세 방식 중 하나로 구현된다는 뜻은 아님.

| 관점 | 파일 시스템 | DBMS |
|---|---|---|
| 관리 단위 | 파일·디렉터리·바이트 | 테이블·레코드·스키마 |
| 데이터 의미 | 응용이 형식을 해석 | 데이터 모델·질의 언어로 정의 |
| 관계·제약 | 응용 설계에 의존 | 키·제약 기능 제공 |
| 동시 변경·회복 | 파일 시스템·응용 구현에 의존 | 트랜잭션·동시성·회복 제공 |

파일 시스템도 권한·동시 접근·저널링 기능이 있으므로 동시성·복구가 전혀 없다고 일반화하지 않음.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 경로·메타데이터만으로 레코드 제약·트랜잭션 보장 곤란 | 원본은 파일 저장소, 업무 관계·권한은 DBMS에서 관리하고 연결 무결성 검사 |
| 파일 삭제·복원 후 DB 참조가 낡아짐 | 파일 식별자·메타데이터 연결을 대조하고 삭제·복원 시나리오 시험 |

## Ⅵ. 제언

대용량 원본은 파일·객체 저장소에 두고 검색·관계·권한은 메타데이터 DBMS로 관리

```text
문서·영상 원본 → 파일·객체 저장소 / 조건 질의·관계·제약 → DBMS / 둘의 참조 정합성 검사
```

| 구분 | 파일만으로 관리 | 제언: 파일 + 메타데이터 DB |
|---|---|---|
| 검색·관계 | 응용이 구현 | DBMS 질의 |
| 참조 정합성 | 미검증 | 정기 대조 |
