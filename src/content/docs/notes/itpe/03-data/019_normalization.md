## 연관 키워드
- 정규화, 함수 종속, 1NF, 2NF, 3NF, BCNF, 갱신 이상

### Ⅰ. 정규화의 개요

- 핵심 요약 : 관계형 데이터베이스 정규화는 함수 종속과 키 관계를 기준으로 릴레이션을 분해해 중복과 삽입·수정·삭제 이상을 줄이는 과정.
-概念 : 함수 종속과 키 관계를 기준으로 릴레이션을 분해해 중복과 삽입·수정·삭제 이상을 줄이는 과정(**정규화**, Normalization).
- 배경 및 필요성 : 한 테이블에 여러 사실을 섞으면 중복 저장과 갱신 이상이 발생.
- 주요 목적 : 데이터 무결성과 유지보수성을 갖춘 논리 스키마 설계.

### Ⅱ. 정규화의 특징 및 장점

- 핵심 요약 : 1NF·2NF·3NF/BCNF는 원자값 제거·완전 함수 종속·이행 종속 제거를 위한 데이터베이스 설계 방식.

1. 1NF : 원자값·반복그룹 제거 → 관계형 연산 가능.
2. 2NF : 후보키 일부에 대한 부분 함수 종속 제거 → 완전 함수 종속.
3. 3NF/BCNF : 비키의 이행 종속·결정자 문제 제거 → 중복·이상 감소.

### Ⅲ. 정규화의 구조 (흐름)

- 핵심 요약 : 속성·후보키 파악 → 함수 종속 도출 → 정규형 위반 확인 → 무손실 분해 → 종속성 보존 검토.

```text
속성·후보키 파악
  ↓
함수 종속 도출
  ↓
정규형 위반 확인
  ↓
무손실 분해
  ↓
종속성 보존 검토
```

```text
비정규 릴레이션
  ↓ 원자값·반복 제거 → 1NF
  ↓ 부분 함수 종속 제거 → 2NF
  ↓ 이행 종속 제거 → 3NF
  ↓ 모든 결정자 후보키 → BCNF
```

### Ⅳ. 3NF와 BCNF 비교

- 핵심 요약 : 분해 결과 기준 — 3NF: 종속성 보존 가능한 설계가 많음; BCNF: 무손실 분해라도 종속성 보존 어려울 수 있음.

| 비교 축 | 3NF | BCNF |
|---|---|---|
| 결정자 조건 | 비주요 속성의 결정자 종속 제한 | 모든 비자명 함수 종속 결정자는 후보키 |
| 분해 결과 | 종속성 보존 가능한 설계가 많음 | 무손실 분해라도 종속성 보존 어려울 수 있음 |

### Ⅴ. 정규화의 한계와 방안

- 핵심 요약 : 함수 종속 오판·과도한 조인 등 실제 위험을 원인에 맞는 통제와 지표로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 함수 종속 오판 | 업무 규칙을 잘못 파악하면 분해가 부정확 | 업무 규칙·키 정의를 현업 검증 | 무손실성·종속성 보존 |
| 과도한 조인 | 분해로 조회 경로와 조인 비용 증가 | 워크로드 측정 후 제한적 반정규화 검토 | 조회 지연 |
| 키 누락 | 잘못된 후보키 가정이 중복·이상 잔존 | 후보키와 대체키·NULL 정책 검토 | 중복률·이상 사례 |

### Ⅵ. 정규화에 대한 제언

- 핵심 요약 : 데이터 모델러는 업무 함수 종속과 후보키를 현업과 검증하고, 정규형 목표와 조회·갱신 워크로드의 절충을 문서화.

- 실행 제안 : 모델러는 후보키·함수 종속을 업무 담당자와 검증하고 분해의 무손실성과 종속성 보존을 확인.

### Ⅶ. 결론

- 핵심 요약 : 정규화의 기준은 표를 잘게 나누는 것이 아니라 함수 종속을 바탕으로 무손실성·종속성 보존을 확보하는 것.
- 시사점 : 정규형의 고도화보다 업무 종속성의 정확한 파악과 무손실 분해가 모델 품질을 결정.
