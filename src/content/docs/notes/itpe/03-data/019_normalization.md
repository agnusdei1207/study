## 연관 키워드

- 정규화(Normalization), 함수적 종속성(FD, Functional Dependency), 이상 현상(Anomaly)
- 제1정규형(1NF), 제2정규형(2NF), 제3정규형(3NF), BCNF(Boyce-Codd Normal Form)
- 부분 함수 종속, 이행 함수 종속, 무손실 분해(Lossless Decomposition), 종속성 보존(Dependency Preservation), 슈퍼키(Superkey)

## Ⅰ. 정규화의 개요

- 핵심 요약 : 속성 간 종속 관계에 따라 테이블을 단계적으로 분해해 중복과 이상 현상을 제거하는 설계 절차.
- 개념 : 속성 간의 **함수적 종속성**(FD, Functional Dependency)을 근거로 하나의 테이블을 여러 테이블로 분해하여 데이터 중복을 최소화하는 관계형 설계 절차 (**정규화**, Normalization).
- 배경 및 필요성 : 하나의 테이블에 여러 주제의 속성을 섞어 두면 같은 값이 반복 저장되고 일부 행만 갱신되는 불일치가 누적. 이 비용의 구조적 통제를 위해 E. F. Codd가 관계 모델과 함께 정규형 이론을 제시.
- 주요 목적 : 삽입·삭제·수정 **이상 현상**(Anomaly, 데이터 조작 시 발생하는 불일치·손실)을 제거한 논리 데이터 모델의 확보.

## Ⅱ. 정규화의 특징 및 장점

- 핵심 요약 : 종속성 기반의 단계적 분해 원리가 중복 제거와 일관성 확보, 구조 안정성으로 이어지는 설계 체계.

1. 종속성 기반 분해 : 결정자와 종속 속성의 관계를 기준으로 테이블을 나눔 → 중복 저장 감소와 값 일관성 확보 효과.
2. 무손실 분해 : 분해된 테이블의 조인으로 원래 데이터가 그대로 복원 (**무손실 분해**, Lossless Decomposition) → 정보 손실 없는 구조 변경 효과.
3. 종속성 보존 : 분해 후에도 원래의 종속 제약을 개별 테이블에서 검증 (**종속성 보존**, Dependency Preservation) → 무결성 검사 비용 통제 효과.
4. 단계적 정규형 : 위반 유형을 한 단계에 하나씩 제거하는 순차 구조 → 설계 기준의 명확성 효과.
5. 확장 안정성 : 종속 구조의 명시화로 요구사항 변경 시 영향 범위 파악 용이 → 스키마 진화 비용 절감 효과.

## Ⅲ. 정규화의 구조 (흐름)

- 핵심 요약 : 비정규 릴레이션에서 BCNF까지 정규형을 한 단계씩 거치며 종속 위반을 제거하는 흐름.

```text
[ 정규화 단계 흐름 ]

비정규 릴레이션
      ↓  반복 그룹 제거, 원자값 구성
제1정규형 (1NF)
      ↓  부분 함수 종속 제거
제2정규형 (2NF)
      ↓  이행 함수 종속 제거
제3정규형 (3NF)
      ↓  결정자를 모두 슈퍼키로 제한
BCNF (Boyce-Codd Normal Form)
```

- 제1정규형(1NF, First Normal Form) : 모든 속성의 값을 원자값으로 구성하고 반복 그룹을 행으로 분리.
- 제2정규형(2NF, Second Normal Form) : 복합키 일부에만 종속하는 **부분 함수 종속**을 별도 테이블로 분리.
- 제3정규형(3NF, Third Normal Form) : 일반 속성이 다른 일반 속성에 거쳐 종속하는 **이행 함수 종속**을 제거.
- BCNF : 비사소한 함수 종속의 결정자를 모두 **슈퍼키**(Superkey, 행을 유일하게 식별하는 속성 집합)로 제한.

```text
[ 정규화가 제거하는 3대 이상 현상 ]

삽입 이상 : 새 행 입력에 불필요한 값까지 요구
삭제 이상 : 행 삭제 시 유효 정보까지 소실
수정 이상 : 중복 값의 부분 갱신으로 불일치 발생
```

## Ⅳ. 정규형 단계별 비교

- 핵심 요약 : 정규형마다 위반 조건과 변환 조치, 해결 문제가 다르므로 낮은 단계부터 순서대로 적용.

| 정규형 | 위반 조건 | 변환 조치 | 해결되는 문제 |
| --- | --- | --- | --- |
| 1NF | 다중값·복합값이 한 컬럼에 저장 | 반복 그룹의 행 분리, 원자값화 | 다중값의 검색·갱신 불가 |
| 2NF | 복합키 일부에만 종속하는 속성 존재 | 부분 종속 속성의 별도 테이블 분리 | 복합키 일부만 알 때의 삽입·삭제 이상 |
| 3NF | 일반 속성 간의 이행 종속 존재 | 이행 종속 속성의 별도 테이블 분리 | 일반 속성 갱신 시의 수정 이상 |
| BCNF | 결정자가 슈퍼키가 아닌 종속 존재 | 슈퍼키가 아닌 결정자 중심의 분해 | 후보키가 겹치는 테이블의 잔여 이상 |

- 적용 기준 : 기본 설계는 3NF 수준으로 두는 것이 통상적 기준.
- 적용 기준 : 후보키가 여러 개인 테이블은 BCNF 위반 여부를 추가 점검하는 기준.
- 적용 기준 : 모든 분해는 무손실 분해를 전제로 하고 종속성 보존 가능 여부를 함께 확인하는 기준.

## Ⅴ. 정규화의 한계와 방안

- 핵심 요약 : 조인 부하, 종속성 보존 실패, 스키마 경직성이 한계이며 선별적 반정규화와 절충 설계로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 조회 시 조인 부하 | 과도한 분해 → 단순 조회의 조인 수 증가와 응답 지연 | 조회 병목 테이블의 선별적 반정규화, 읽기 캐시 계층 | 조인 수, 응답 시간 |
| BCNF 분해 시 종속성 보존 실패 | 일부 종속 제약의 단일 테이블 검증 불가 → 무결성 검사 부담 | 종속성 보존이 필수인 영역의 3NF 절충 | 무결성 위반 건수 |
| 스키마 경직성 | 엄격한 제약 구조 → 요구사항 변경 시 다수 테이블 수정 | 반정형 속성의 분리 저장, 주제영역별 모델 계층화 | 스키마 변경 소요 시간 |

## Ⅵ. 정규화에 대한 기술사적 제언

- 핵심 요약 : 업무 영역별 정규화 수준의 구분과 정규화 준수 기준의 조직 표준화 필요.
- 영역 구분 : 데이터 아키텍처 조직이 트랜잭션 영역은 3NF 이상, 분석 영역은 별도 모델 기준을 적용하는 이원 체계 운영.
- 표준 제정 : 설계 조직이 정규형 점검 체크리스트와 용어 표준을 설계 가이드로 제정·배포.
- 품질 검증 : 품질 조직이 설계 단계별 정규화 준수 여부를 리뷰 절차로 검증하는 체계 운영.

## Ⅶ. 결론

- 핵심 요약 : 정규화는 이상 현상 없는 데이터 구조를 만드는 관계형 설계의 이론적 기반.
- 시사점 : 3NF 기본 설계와 업무별 조정이 정규화 이론의 실무 적용 표준.
