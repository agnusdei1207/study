## 연관 키워드

- 정규화(Normalization), 함수적 종속성(FD, Functional Dependency), 이상 현상(Anomaly), 무손실 분해(Lossless Decomposition), 종속성 보존(Dependency Preservation), 반정규화
- 제1정규형(1NF), 제2정규형(2NF), 제3정규형(3NF), BCNF(Boyce-Codd Normal Form), 슈퍼키(Superkey), 완전 함수 종속, 이행 함수 종속

## Ⅰ. 정규화의 개요

- 핵심 요약 : 함수적 종속성에 따라 테이블을 나눠 중복을 줄이고 이상 현상을 막는 관계형 설계 절차.
- 개념 : 릴레이션 속성 사이의 **함수적 종속성** (FD, Functional Dependency)에 근거해 테이블을 논리적으로 분해하여 데이터 중복을 줄이고 이상 현상을 막는 관계형 설계 절차인 **정규화**(Normalization).
- 배경 및 필요성 : 여러 사실을 한 테이블에 섞어 두면 같은 정보가 반복 저장되고, 일부 행만 고쳐지는 불일치가 생겨 데이터 품질 비용이 누적된다. 이 비용을 구조적으로 막기 위해 E. F. Codd가 관계 모델과 함께 정규형 이론을 제시하였다.
- 주요 목적 : **무손실 분해**(Lossless Decomposition)와 **종속성 보존**(Dependency Preservation)을 지키면서 이상 현상이 없는 논리 데이터 모델을 확보.

## Ⅱ. 정규화의 특징

- 핵심 요약 : 종속성 기반의 단계적 분해가 중복 제거와 이상 현상 방지로 이어지는 설계 원리.

1. 종속성 기반 분해 : 결정자와 종속 속성을 기준으로 테이블을 나눔 → 중복 저장 감소와 값 일관성 확보.
2. 무손실 분해 : 분해한 테이블을 조인하면 원래 데이터를 그대로 복원 → 구조를 바꾸어도 정보 손실 없음.
3. 종속성 보존 : 분해 후에도 원래의 종속 제약을 검증할 수 있음 → 무결성 검사 비용 증가 방지.
4. 단계적 정규형 : 제1정규형(1NF, First Normal Form)부터 BCNF(Boyce-Codd Normal Form)까지 위반 유형을 하나씩 제거 → 단계별 설계 기준이 명확.

## Ⅲ. 정규화의 구조 (흐름)

- 핵심 요약 : 비정규 릴레이션에서 BCNF까지 종속 위반을 한 단계씩 제거하는 분해 흐름.

```text
[ 정규화 단계 흐름 ]
비정규 릴레이션
        ↓  반복 그룹 분리, 원자값 구성
제1정규형 (1NF)
        ↓  부분 함수 종속 제거
제2정규형 (2NF)
        ↓  이행 함수 종속 제거
제3정규형 (3NF)
        ↓  비사소한 종속의 결정자를 슈퍼키로
BCNF
```

- 정규화가 제거하는 대상은 **3대 이상 현상**(삽입·삭제·수정 이상)이다.

```text
[ 3대 이상 현상 ]
삽입 이상 : 새 행 입력에 불필요한 값을 함께 요구
삭제 이상 : 한 행 삭제로 다른 유효 정보까지 소실
수정 이상 : 중복 값 일부만 고쳐져 불일치 발생
```

- 고차 정규형은 비사소한 **다치 종속성**(MVD, Multivalued Dependency)을 제거하는 제4정규형(4NF, Fourth Normal Form)과 조인 종속성(JD, Join Dependency)을 제거하는 제5정규형(5NF, Fifth Normal Form)으로 확장된다.
- 릴레이션 R을 R1, R2로 나눌 때 공통 속성이 R1 또는 R2의 슈퍼키이면 정보를 잃지 않는 분해가 성립한다.

## Ⅳ. 정규형 단계별 비교

- 핵심 요약 : 정규형마다 위반 조건과 제거 대상이 달라 낮은 단계부터 순서대로 적용.

| 정규형 | 위반 조건 | 변환 조치 | 해결되는 문제 |
| --- | --- | --- | --- |
| 1NF | 한 컬럼에 다중값이나 복합값이 들어감 | 반복 그룹을 행으로 분리하고 모든 값을 원자값으로 구성 | 다중값으로 인한 검색·갱신 불가 |
| 2NF | 복합 기본키의 일부에만 종속되는 속성 존재 (부분 함수 종속) | 부분 종속 속성을 별도 테이블로 분리 | 복합키 일부만 알 때의 삽입·삭제 이상 |
| 3NF | 기본키가 아닌 속성이 다른 일반 속성에 종속 (이행 함수 종속) | 이행 종속 속성을 별도 테이블로 분리 | 일반 속성 갱신 시 발생하는 수정 이상 |
| BCNF | 비사소한 함수 종속의 결정자가 슈퍼키가 아님 | 슈퍼키가 아닌 결정자 중심으로 무손실 분해 | 후보키가 여러 개 겹칠 때 남는 잔여 이상 |

## Ⅴ. 정규화의 장점과 한계

- 핵심 요약 : 이상 현상 방지와 일관성 확보가 장점이며, 조인 부하와 종속성 보존 실패, 스키마 경직성이 한계.

- 장점
  1. 삽입·삭제·수정 이상 현상의 원천 방지.
  2. 중복 제거를 통한 데이터 일관성과 저장 효율 확보.
  3. 종속 구조가 명확해 스키마 확장 시 영향 범위 파악 용이.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 다중 조인에 따른 조회 성능 저하 | 과도한 분해로 단순 조회에도 조인 수 증가, 응답 지연 | 조회 빈도가 높은 핵심 트랜잭션에 한해 선별적 반정규화, 읽기 캐시 계층 도입 | 조인 수, 응답 시간 |
| BCNF 분해 시 종속성 보존 실패 | 일부 종속 관계를 한 테이블에서 검증할 수 없어 무결성 검사가 무거워짐 | 종속성 보존이 필수인 영역은 3NF로 절충하고 애플리케이션 트랜잭션 로직으로 보완 | 무결성 위반 건수 |
| 스키마 경직성 | 엄격한 참조 제약으로 요구사항 변경 때 다수 테이블의 DDL 수정 필요 | 반정형 속성은 JSON(JavaScript Object Notation) 컬럼으로 분리, 목적별 저장소를 병행하는 Polyglot Persistence 적용 | 스키마 변경 소요 기간 |

## Ⅵ. 정규화에 대한 기술사적 제언

- 핵심 요약 : 트랜잭션 시스템과 분석 시스템의 정규화 수준을 구분하고, 반정규화는 측정된 병목에만 적용.

트랜잭션 정합성이 우선인 OLTP(Online Transaction Processing) 영역은 BCNF 또는 3NF까지 엄격히 정규화하고, 대량 집계가 중심인 OLAP(Online Analytical Processing) 영역은 스타 스키마처럼 의도적으로 역정규화한 구조를 택하는 편이 맞다. 두 영역을 같은 기준으로 설계하면 한쪽에서 성능이 무너지거나 정합성이 깨진다.

설계의 기본값은 3NF로 두고, 실행 계획과 조인 횟수로 병목이 확인된 테이블에만 반정규화를 적용한다. 반정규화로 중복된 컬럼은 원본과 동기화하는 갱신 로직을 함께 설계해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 정규화는 데이터 무결성의 이론적 기반이며, 성능과의 균형을 함께 판단해야 하는 설계 원칙.
- 시사점 : 3NF를 기본 설계로 두고 워크로드에 따라 선별적으로 반정규화하는 방식이 정규화 이론을 실무에 맞게 적용하는 길임.
