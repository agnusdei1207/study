## 지식 로드맵 내 현재 위치
```text
데이터베이스 → 논리 데이터 모델 → 정규화
```

## 큰 그림과 30초 인출
```text
[비정규 릴레이션] → 1NF 원자값 → 2NF 부분종속 제거
                   → 3NF 이행종속 제거 → BCNF 결정자=후보키
                                   ↓
                         무손실 조인·종속성 보존
```
- 본질: **함수적 종속성에 따라 릴레이션을 무손실 분해해 중복과 삽입·갱신·삭제 이상을 줄이는 설계 과정**
- 암기: `원-부-이-결` = 원자값 → 부분종속 → 이행종속 → 결정자

## 예상문제
> 정규화의 목적과 이상현상을 설명하고 1NF~BCNF 과정, 무손실 조인·종속성 보존 및 반정규화와의 관계를 논하시오. (25점)

## Ⅰ. 하나의 사실을 한 곳에 두는 정규화 개요
- 정의: 속성 간 함수적 종속성을 분석해 릴레이션을 더 작은 관계로 분해하는 논리 모델링 기법
- 목적: 데이터 중복과 삽입·갱신·삭제 이상 제거, 무결성·변경성 향상
- 원칙: 분해 후 원래 정보를 복원할 수 있는 무손실 조인과 제약 검증 가능한 종속성 보존

## Ⅱ. 이상현상과 함수적 종속성
| 이상 | 현상 | 원인 |
|---|---|---|
| 삽입 | 다른 사실 없이는 새 사실 입력 불가 | 여러 주제 혼재 |
| 갱신 | 동일 사실을 여러 행에서 수정 | 중복 저장 |
| 삭제 | 한 사실 삭제가 다른 사실 손실 | 생명주기 결합 |
| 함수종속 | $X→Y$: X가 Y를 유일 결정 | 정규형 판정 기준 |

## Ⅲ. 정규형 단계
| 정규형 | 제거 대상 | 분해 기준 |
|---|---|---|
| 1NF | 반복집합·비원자값 | 모든 속성을 원자값으로 |
| 2NF | 후보키 일부에 대한 부분종속 | 완전 함수종속 |
| 3NF | 비키 속성 간 이행종속 | 비키는 키에만 종속 |
| BCNF | 후보키 아닌 결정자 | 모든 결정자는 후보키 |

## Ⅳ. 정규화 수행 절차
```text
업무규칙·키 식별 → 함수종속성 도출 → 이상현상 확인
 → 1NF → 2NF → 3NF/BCNF 분해 → 무손실·종속성 보존 검증
```
| 검증 | 질문 |
|---|---|
| 무손실 조인 | 자연조인으로 원 릴레이션을 정확히 복원하는가 |
| 종속성 보존 | 분해된 관계만으로 제약을 검사할 수 있는가 |
| 키 보존 | 식별자와 참조 관계가 명확한가 |

## Ⅴ. 정규화와 반정규화 비교
| 구분 | 정규화 | 반정규화 |
|---|---|---|
| 목적 | 중복·이상 제거 | 읽기 성능 향상 |
| 단계 | 논리 모델 기준 | 물리 모델 최적화 |
| 구조 | 분해·참조 | 통합·중복·사전집계 |
| 비용 | 조인 증가 가능 | 갱신·정합성 비용 증가 |

## Ⅵ. 실무 고려사항
| 문제 | 원인 | 대책 |
|---|---|---|
| 과도한 분해 | 모든 종속을 기계 적용 | Aggregate·접근패턴과 균형 |
| 제약 누락 | 문서만 정규화 | PK·FK·UNIQUE·CHECK 구현 |
| 조회 병목 | 다중 조인·집계 | Index·SQL 튜닝 후 제한적 반정규화 |
| 이력 혼재 | 현재·과거 사실 동시 저장 | 시간·생명주기 기준 분리 |

## Ⅶ. 논리적 진실과 물리적 성능을 분리하는 결론
- 정규화 모델을 데이터 의미와 무결성의 기준선으로 유지
- 성능 최적화는 실행계획과 부하 측정 후 물리 계층에서 통제하고 원천·동기화 책임을 명시

## 1교시 10점 답안 발췌
```text
1NF 원자값 → 2NF 부분종속 제거 → 3NF 이행종속 제거
 → BCNF 모든 결정자는 후보키
검증: 무손실 조인 + 종속성 보존
```
