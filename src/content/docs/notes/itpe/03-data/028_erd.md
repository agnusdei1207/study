## 연관 키워드
- ERD, 개체, 속성, 관계, 카디널리티, 선택성, 식별자

### Ⅰ. 개체-관계 다이어그램의 개요

- 핵심 요약 : ERD는 업무 데이터의 개체·속성·관계와 카디널리티를 개념·논리 수준에서 표현하는 데이터 모델.
- 개념 : 업무 데이터의 개체·속성·관계와 카디널리티를 개념·논리 수준에서 표현하는 데이터 모델(**개체-관계 다이어그램**, Entity-Relationship Diagram).
- 배경 및 필요성 : 요구를 테이블로 바로 구현하면 업무 의미·관계·필수성 누락과 중복이 생김.
- 주요 목적 : 데이터 구조와 업무 규칙을 이해 관계자 간 합의하고 관계형 스키마 설계 근거 제공.

### Ⅱ. 개체-관계 다이어그램의 특징 및 장점

- 핵심 요약 : 개체·관계·카디널리티·키·속성은 업무 데이터를 이해 관계자 간 합의하고 관계형 스키마를 설계하는 ERD 요소.

1. 개체 : 독립 식별 가능한 업무 대상 정의 → 데이터 범위 명확화.
2. 관계·카디널리티 : 1:1·1:N·M:N과 선택성 표현 → 참여 규칙 가시화.
3. 키·속성 : 식별자·업무 속성 정의 → 논리 스키마 설계 기반.

### Ⅲ. 개체-관계 다이어그램의 구조 (흐름)

- 핵심 요약 : 업무 명사·규칙 추출 → 개체·속성 정의 → 관계·카디널리티 설정 → 키·정규화 → 검토·논리 모델 변환.

```text
업무 명사·규칙 추출
  ↓
개체·속성 정의
  ↓
관계·카디널리티 설정
  ↓
키·정규화
  ↓
검토·논리 모델 변환
```

```text
고객 (1) ─── 주문 (N)
고객 ID       주문 ID
이름           고객 ID(FK)
               주문 일시
```

### Ⅳ. 개념 ERD와 논리 ERD 비교

- 핵심 요약 : DBMS 종속성 기준 — 개념 ERD: DBMS 독립적; 논리 ERD: DBMS 구현 특성 반영 가능.

| 비교 축 | 개념 ERD | 논리 ERD |
|---|---|---|
| 표현 | 업무 개념·핵심 관계 | 키·속성·정규화·상세 카디널리티 |
| DBMS 종속성 | DBMS 독립적 | DBMS 구현 특성 반영 가능 |

### Ⅴ. 개체-관계 다이어그램의 한계와 방안

- 핵심 요약 : 다중성 오해·속성·개체 혼동 등 실제 위험을 원인에 맞는 통제와 지표로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 다중성 오해 | 선택 관계·최소/최대 카디널리티 표현 누락 | 관계별 참여 최소·최대와 업무 예시 검증 | 모델 불일치 |
| 속성·개체 혼동 | 다치·복합 속성 또는 관계 속성이 잘못 배치 | 키·함수 종속·관계 속성 기준 검토 | 정규화 위반 |
| 모델 노후화 | 업무·스키마 변경 후 ERD 미갱신 | 모델 저장소·DDL 비교·변경 승인 연결 | 모델-DB 차이 |

### Ⅵ. 개체-관계 다이어그램에 대한 제언

- 핵심 요약 : 데이터 모델러는 업무 용어 사전과 ERD를 함께 관리하고 주요 관계마다 최소·최대 참여 사례를 검증한 뒤 물리 모델로 전환.

- 실행 제안 : 모델러는 관계별 선택성·최대 카디널리티 사례를 업무와 검토하고 승인된 모델을 스키마 변경의 기준으로 관리.

### Ⅶ. 결론

- 핵심 요약 : ERD는 표 그림이 아니라 업무 개체와 관계 제약을 합의하는 모델이며 업무 변경과 함께 진화해야 함.
- 시사점 : ERD의 핵심 가치는 관계와 필수성에 관한 업무 규칙을 구현 전에 합의하는 데 있음.
