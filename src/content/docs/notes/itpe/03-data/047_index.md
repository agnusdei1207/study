## 연관 키워드

## Ⅰ. 인덱스의 개요

- 핵심 요약 : 인덱스는 검색 키와 레코드 위치를 보조 구조에 저장해 테이블 스캔을 줄이는 접근경로.
- 개념 : 인덱스는 검색 키와 레코드 위치를 보조 구조에 저장해 테이블 스캔을 줄이는 접근경로.
- 배경 및 필요성 : 대용량 테이블에서 반복적인 조건검색·정렬·조인이 전체 스캔 비용을 유발.
- 주요 목적 : 읽기 지연과 데이터 접근 비용 감소.

## Ⅱ. 인덱스의 특징 및 장점

- 핵심 요약 : B+Tree: 정렬·범위검색·정렬 지원 → 범용 접근; 해시: 동등검색에 효율 → 범위 탐색 부적합; 복합·커버링: 필터 순서·포함열 설계 → 테이블 접근 감소.

1. B+Tree: 정렬·범위검색·정렬 지원 → 범용 접근
2. 해시: 동등검색에 효율 → 범위 탐색 부적합
3. 복합·커버링: 필터 순서·포함열 설계 → 테이블 접근 감소

## Ⅲ. 인덱스의 구조 (흐름)

- 핵심 요약 : 쿼리·실행계획 분석 → 선택도·정렬·조인 조건 식별 → 인덱스 후보 생성·순서 설계 → 부하 비교·중복 인덱스 제거 → 통계·사용률 지속 점검.

```text
쿼리·실행계획 분석
  ↓
선택도·정렬·조인 조건 식별
  ↓
인덱스 후보 생성·순서 설계
  ↓
부하 비교·중복 인덱스 제거
  ↓
통계·사용률 지속 점검
```

- 핵심 구성 : SQL → 옵티마이저·통계 → 인덱스 탐색 → 행 위치 접근

```text
SQL → 옵티마이저·통계 → 인덱스 탐색 → 행 위치 접근
쓰기 시 → 인덱스 유지·페이지 분할
```

## Ⅳ. 비교: B+Tree 인덱스 / 테이블 전체 스캔

- 핵심 요약 : 쓰기·저장비용 기준 — B+Tree 인덱스: 인덱스 갱신·저장공간 필요; 테이블 전체 스캔: 보조 인덱스 유지비 없음.

| 비교 기준 | B+Tree 인덱스 | 테이블 전체 스캔 |
| --- | --- | --- |
| 읽기 비용 | 키 탐색 후 일부 페이지 접근 | 전체 페이지 순차 확인 |
| 쓰기·저장비용 | 인덱스 갱신·저장공간 필요 | 보조 인덱스 유지비 없음 |

- 핵심 요약 : 과다 인덱스·잘못된 열 순서 등 주요 위험을 원인에 맞는 통제로 관리.

## Ⅵ. 인덱스의 제언

- 핵심 요약 : DBA는 실제 쿼리와 실행계획을 근거로 인덱스를 설계하고 변경 전후 읽기·쓰기·저장 비용을 모두 비교.
- 실행 제안 : DBA는 상위 SQL 실행계획을 기반으로 한 인덱스씩 변경하고 쓰기부하·저장량·쿼리 지연 회귀를 함께 점검.

## Ⅶ. 인덱스의 결론

- 핵심 요약 : 인덱스는 조회를 빠르게 하는 무료 복사본이 아니라 쓰기와 저장 비용을 지불해 접근경로를 사전 구축하는 구조.
- 시사점 : 쿼리 워크로드가 변하면 최적 인덱스도 변하므로 사용량과 실행계획을 반복 관측.
