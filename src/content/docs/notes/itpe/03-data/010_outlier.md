## 연관 키워드

- 이상치(Outlier), 이상치 탐지(Outlier Detection), IQR, Z-Score, 마할라노비스 거리(Mahalanobis Distance)
- LOF, Isolation Forest, AutoEncoder, 윈저라이징(Winsorizing), FDS

## Ⅰ. 이상치의 개요

- 핵심 요약 : 일반적 분포와 패턴에서 현저히 벗어난 관측치로, 오류일 수도 핵심 신호일 수도 있는 값.
- 개념 : 대부분의 관측치가 따르는 분포나 패턴에서 현저히 벗어나, 다른 메커니즘으로 생성되었을 것으로 의심되는 극단적·이례적 데이터 값인 **이상치** (Outlier).
- 배경 및 필요성 :
  1. 평균과 분산 왜곡 : 이상치 하나로 표본 평균이 치우치고 표준편차가 과대 추정됨.
  2. 선형 모델 파괴 : 최소제곱법(OLS, Ordinary Least Squares) 회귀에서 잔차가 큰 이상치의 레버리지(Leverage)가 회귀선 기울기를 왜곡함.
  3. 거리 기반 알고리즘 저하 : K-Means와 K-최근접 이웃(KNN, K-Nearest Neighbors) 등 유클리디안 거리 기반 모델의 군집 중심이나 판정이 왜곡됨.
- 주요 목적 : 입력 오타나 센서 결함 같은 측정 오류와, 사기나 침해 사고 같은 핵심 신호를 구분해 적절히 처리하는 것.

## Ⅱ. 이상치의 특징 및 처리 원칙

- 핵심 요약 : 오류와 신호의 이중적 성격 아래 4대 범주의 탐지 기법을 쓰고, 처리 방법은 발생 원인에 따라 달리 고르는 구조.

1. 이중적 성격 : 단순 측정 오류일 수도 있고, 비즈니스 관점에서 가장 중요한 통찰을 담은 신호일 수도 있음.
2. 통계·모델 영향 : 평균과 분산 왜곡, 회귀선 왜곡, 거리 기반 알고리즘 성능 저하를 유발.
3. 탐지 기법의 4대 범주 : 통계적 기법(Z-Score, 사분위수 범위(IQR, Interquartile Range)), 거리 기반 기법, 밀도 기반 기법(LOF, Local Outlier Factor), 머신러닝·딥러닝 기법(Isolation Forest, AutoEncoder).
4. 처리 전략의 원인 의존성 : 발생 원인 분석 결과에 따라 삭제·대체·클리핑·변환·보존 중에서 선택.

```text
[ 이상치 탐지 방법론 4대 범주 ]

 통계적 기법
   Z-Score, IQR 사분위수
 거리 기반 기법
   KNN 거리, 이웃과의 평균 거리
 밀도 기반 기법
   LOF (국소 밀도 비율 비교)
 머신러닝·딥러닝 기법
   Isolation Forest, AutoEncoder
```

## Ⅲ. 이상치 탐지·처리의 구조 (흐름)

- 핵심 요약 : 이상치를 식별한 뒤 발생 원인을 분석하고, 그 결과에 따라 처리 전략을 고르는 의사결정 흐름.

```text
[ 이상치 처리 의사결정 ]

 이상치 식별 → 발생 원인 분석
          ↓
 단순 오류 (오타, 센서 고장)
   → 삭제 또는 대체
 자연적 극단값 (VIP 매출)
   → 윈저라이징 또는 로그 변환
 탐지 자체가 목적 (FDS)
   → 라벨링 후 탐지 모델 특징으로 보존
```

- 이상치 처리 4대 전략 :
  1. 삭제(Trimming/Deletion) : 데이터 오류가 명백하거나 극소수일 때 해당 행을 제거.
  2. 대체(Imputation) : 중위수, 최빈값, 또는 KNN·회귀 모델로 추정한 값으로 대체.
  3. **윈저라이징** (Winsorizing) : 상위 1%를 넘는 값은 99 백분위수로, 하위 1% 미만 값은 1 백분위수로 잘라내는 클리핑.
  4. 변수 변환(Transformation) : 로그, 제곱근, Box-Cox 변환으로 왜도를 줄이고 정규성을 확보.

## Ⅳ. 이상치 탐지 기법의 비교

- 핵심 요약 : 단변량 통계의 간편성에서 딥러닝의 비선형 탐지까지, 데이터 특성에 따라 기법을 고르는 구조.

| 분류 | 대표 기법 | 핵심 판정 메커니즘 | 장점 및 적용 환경 | 단점 및 한계 |
|---|---|---|---|---|
| 단변량 통계 | IQR(Interquartile Range) 기법 | Q1 − 1.5×IQR 미만 또는 Q3 + 1.5×IQR 초과 (IQR = Q3 − Q1) | 정규분포 가정이 필요 없는 직관적 방식 | 변수 간 상관관계를 반영하지 못함 |
| 단변량 통계 | Z-Score / Modified Z | Z = (x − μ) / σ의 절댓값이 3 이상이면 판정, 중위수 기반 MAD(Median Absolute Deviation) 활용 권장 | 계산이 간편하고 표준 정규분포에 기반 | 이상치가 평균과 표준편차를 왜곡하는 마스킹 효과, 정규분포 가정 필요 |
| 다변량 통계 | 마할라노비스 거리(Mahalanobis Distance) | 공분산 행렬 Σ를 반영한 거리 D² = (x−μ)ᵀ Σ⁻¹ (x−μ) | 변수 간 상관성을 고려한 다차원 거리 측정 | 다변량 정규성 가정 필요, 고차원에서 역행렬 계산이 불안정 |
| 밀도 기반 | LOF(Local Outlier Factor) | 주변 k-최근접 이웃의 국소 밀도 비율을 비교 | 밀도가 다른 군집이 섞인 데이터에서 강력 | 연산 복잡도가 높음(약 O(n²)) |
| 트리 기반 | Isolation Forest | 무작위 분할로 격리 트리를 만들고 고립 깊이(Path Length)를 측정 | 고립 깊이가 짧을수록 이상치로 판정, 대규모 고차원 데이터에 적합 | 트리 수와 샘플 크기 등 하이퍼파라미터 튜닝 필요 |
| 딥러닝 | AutoEncoder | 입력을 저차원으로 압축했다가 복원하며 재구성 오차(Reconstruction Error)를 측정 | 이미지·센서 로그 같은 비선형 고차원 데이터에 효과적 | 학습 비용이 높고 판정 근거가 불투명함 |

- 선택 기준 : 변수가 하나인지 여러 개인지, 분포 가정이 성립하는지, 실시간 처리가 필요한지에 따라 기법을 고름.

## Ⅴ. 이상치 탐지·처리의 한계와 방안

- 핵심 요약 : 다변량 이상치 탐지 실패, 희귀 정상 이벤트의 오탐, 스트림 환경의 연산 부하를 다차원 기법, 사람 검증 루프, 증분 모델로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 단변량 기법의 다변량 이상치 탐지 실패 | 각 변수는 정상 범위에 있어도 변수 간 관계상 이상한 조합을 IQR이나 Z-Score로는 찾지 못함 | 마할라노비스 거리, Isolation Forest, LOF 같은 다차원 거리·밀도 기반 알고리즘 적용 | 다변량 이상치 탐지율 |
| 희귀 정상 이벤트의 오탐 | FDS(Fraud Detection System)나 설비 장애처럼 드물지만 중요한 정상 특이치를 이상치로 오판해 삭제하면 모델이 오작동 | 도메인 전문가가 참여하는 사람 검증 루프(Human-in-the-loop), AutoEncoder 복원 오차 기반 점수화, 준지도 학습 | 오탐률, 검토 소요 시간 |
| 스트림 환경의 실시간 연산 부하 | 고차원 벡터에 LOF를 실시간 적용하면 연산량이 커져 버퍼 오버플로와 지연이 발생 | 슬라이딩 윈도우 기반 증분 모델(Half-Space Trees, RRCF(Robust Random Cut Forest)), Apache Flink 분산 파이프라인 | 탐지 지연 시간, 처리량 |

## Ⅵ. 이상치 관리에 대한 기술사적 제언

- 핵심 요약 : 도메인 전문가 협업, 이상치에 강건한 모델 채택, 스트리밍 기반 실시간 감지 체계.
- 통계적으로 이상치로 보이는 값이 새로운 핵심 고객군이나 신종 부정 거래 패턴일 수 있으므로, 자동 삭제 파이프라인을 적용하기 전에 업무 규칙 기반의 화이트리스트 검토를 거치는 것이 필요함.
- 이상치를 인위적으로 가공하기보다, XGBoost·LightGBM 같은 트리 계열이나 Huber 손실, L1 정규화 회귀처럼 이상치에 둔감한 모델을 택해 데이터 원형을 보존하는 것이 바람직함.
- 사후 배치 분석에 머무르지 않고 Apache Flink 같은 스트리밍 엔진에 Z-Score나 Isolation Forest 점수 산출 로직을 올려, 이상 발생 즉시 알림이나 차단이 이루어지도록 하는 것이 현실적임.

## Ⅶ. 결론

- 핵심 요약 : 이상치 관리는 기법 선택에 앞서 원인 판별과 도메인 검증이 선행되어야 하는 영역.
- 시사점 : 오탐을 막는 도메인 검증과 강건한 모델·실시간 감지를 함께 갖출 때 이상치가 자산이 됨.
