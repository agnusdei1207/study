## Ⅰ. 데이터 분석 및 품질에서의 이상치(Outlier) 개요

### 가. 이상치의 정의
- 데이터셋의 대부분의 관측치가 따르는 일반적인 분포나 패턴에서 현저하게 벗어나, 다른 메커니즘에 의해 생성된 것으로 의심되는 극단적이거나 이례적인 데이터 값.
- 단순한 측정 오류(입력 오타, 센서 결함)일 수도 있고, 사기(Fraud), 침해 사고, 희귀 질환 등 비즈니스 관점에서 가장 핵심적인 통찰을 내포하는 신호(Signal)일 수 있음.

### 나. 이상치가 통계 분석 및 머신러닝에 미치는 영향
- **평균 및 분산 왜곡** : 이상치 1개로 인해 표본 평균이 왜곡되고 표준편차가 과대 추정됨.
- **선형 모델 파괴** : OLS 회귀분석 시 잔차가 큰 이상치가 레버리지(Leverage)를 가질 경우 회귀선 전체의 기울기를 왜곡.
- **거리 기반 알고리즘 성능 저하** : K-Means, KNN 등 유클리디안 거리 기반 모델의 군집 중심 왜곡.

## Ⅱ. 이상치 탐지(Outlier Detection)의 핵심 기법 분류

### 가. 탐지 기법의 범주별 비교

```text
[ 이상치 탐지 방법론 분류 ]
+---------------------+---------------------+---------------------+---------------------+
| 통계적 기법         | 거리 기반 기법      | 밀도 기반 기법      | 머신러닝/딥러닝     |
+---------------------+---------------------+---------------------+---------------------+
| Z-Score, IQR 사분위 | KNN 거리 기반       | LOF (국소 이상치)   | Isolation Forest    |
| 정규분포 가정 기반  | 이웃과의 평균 거리  | 국소 밀도 비율 비교 | 고립 깊이 측정      |
+---------------------+---------------------+---------------------+---------------------+
```

| 분류 | 대표 기법 | 핵심 판정 메커니즘 | 장점 및 적용 환경 | 단점 및 한계 |
| :--- | :--- | :--- | :--- | :--- |
| **단변량 통계** | **IQR 기법** (Box-Plot) | $Q1 - 1.5 \times IQR$ 미만 또는 $Q3 + 1.5 \times IQR$ 초과 ($IQR = Q3 - Q1$) | 정규분포 가정 불필요, 비모수적 방식으로 직관적 | 다변량 간 상관관계 반영 불가 |
| **단변량 통계** | **Z-Score / Modified Z** | $Z = \frac{x - \mu}{\sigma}$, $|Z| \ge 3$ 판정 (중위수 기반 MAD 활용 권장) | 계산 간편, 표준 정규분포 기반 | 이상치 자체가 $\mu, \sigma$를 왜곡(Masking Effect), 정규분포 가정 필수 |
| **다변량 통계** | **마할라노비스 거리** | $D_M(x) = \sqrt{(x-\mu)^T \Sigma^{-1} (x-\mu)}$ (공분산 행렬 $\Sigma$ 반영) | 변수 간 상관성을 고려한 다차원 공간 거리 측정 | 다변량 정규성 가정 필요, 고차원에서 역행렬 계산 불안정 |
| **밀도 기반** | **LOF** (Local Outlier Factor) | 데이터 포인트 주변 $k$-최근접 이웃의 국소 밀도(Local Reachability Density) 비율 비교 | 밀도가 서로 다른 군집이 혼재된 복합 데이터셋에서 강력 | $O(n^2)$의 높은 연산 복잡도 |
| **트리 기반** | **Isolation Forest** | 데이터를 무작위 속성과 분할점으로 격리하는 트리를 구성하여 고립 깊이(Path Length) 측정 | 평균 깊이가 짧을수록 이상치 판정, $O(n \log n)$ 고속, 대규모 고차원에 최적 | 하이퍼파라미터(트리 수, 샘플 크기) 튜닝 필요 |
| **딥러닝** | **AutoEncoder** | 입력을 저차원으로 압축 후 복원할 때 발생하는 재구성 오차(Reconstruction Error) 측정 | 비선형 고차원(이미지, 센서 로그) 이상 탐지 탁월 | 모델 학습 비용 높음, 블랙박스 특성 |

## Ⅲ. 이상치 처리 전략 및 파이프라인

### 가. 이상치 처리의 4대 전략

```text
[ 이상치 처리 의사결정 트리 ]
이상치 식별 ---> 발생 원인 분석
                  |-- 단순 오류 (오타, 센서 고장) : [삭제(Deletion)] 또는 [대체(Imputation)]
                  |-- 자연적 극단값 (VIP 매출)   : [윈저라이징(Winsorizing)] or [로그 변환]
                  +-- 목적 자체가 이상탐지 (FDS)  : [라벨링 및 탐지 모델 특징으로 보존]
```

1. **삭제(Trimming / Deletion)** : 데이터 오류임이 명백하거나 전체 데이터 대비 극소수일 때 행 제거.
2. **대체(Imputation)** : 중위수(Median), 최빈값 또는 KNN/회귀 모델 기반 추정값으로 대체.
3. **윈저라이징(Winsorizing / Capping)** : 상위 1% 초과 값은 99 백분위수 값으로, 하위 1% 미만은 1 백분위수 값으로 클리핑.
4. **변수 변환(Transformation)** : 로그(Log), 제곱근(Square Root), Box-Cox 변환을 통해 왜도(Skewness)를 줄여 정규성 확보.

## Ⅳ. 이상치 다루기 실무 제언

- **도메인 전문가와의 협업 필수** : 통계적 이상치가 비즈니스에서는 핵심 신규 고객군이거나 신종 금융 사기 패턴일 수 있으므로, 자동 삭제 파이프라인 적용 전 반드시 업무 규칙에 따른 화이트리스트 검토 필요.
- **Robust 모델 알고리즘 채택** : 이상치를 인위적으로 가공하기보다, 이상치에 둔감한 비모수적 모델(Tree 계열인 XGBoost, LightGBM)이나 Huber Loss, L1 정규화 기반 회귀 모델을 채택하는 것이 데이터 원형 보존 측면에서 유리함.
- **스트리밍 파이프라인 내 실시간 감지** : 사후 배치 분석에 그치지 않고, Apache Flink 등 스트리밍 엔진에 Z-Score 및 Isolation Forest 점수 산출 로직을 탑재하여 이상치가 발생하는 즉시 알림 및 차단 조치를 취할 것을 제언함.
