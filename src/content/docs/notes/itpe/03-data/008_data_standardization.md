## 연관 키워드

- 데이터 표준화(Data Standardization), 표준 단어, 표준 용어, 표준 도메인, 표준 코드
- 동음이의어, 이음동의어, 메타데이터 관리 시스템(MDR, Metadata Repository)
- 변경 관리(RFC, Request for Change), 영향도 분석, 표준 검증 린터(Linter)

## Ⅰ. 데이터 표준화의 개요

- 핵심 요약 : 시스템 간 데이터의 명칭·정의·형식·규칙을 전사 표준으로 통일하는 관리 활동.
- 개념 : 분산 시스템과 업무에서 같은 의미의 데이터가 다르게 정의되지 않도록 명칭·형식·값 체계를 통일하고 전사 공유하는 활동인 **데이터 표준화** (Data Standardization).
- 배경 및 필요성 :
  1. 같은 고객 식별자가 시스템마다 상이해 전사 통합 분석이 곤란.
  2. 시스템 연계 때마다 타입 변환·코드 매핑 비용의 추가.
  3. 담당자 교체 시 컬럼 의미 파악에 드는 시간 비용 증가.
- 주요 목적 : 데이터 상호운용성 확보와 통합 분석·품질 관리의 기반 구축.

## Ⅱ. 데이터 표준화의 특징 및 장점

- 핵심 요약 : 4대 표준 요소의 계층 구조, 절차적 변경 통제, 자동 검증의 결합 체계.

1. 4대 표준 요소 : 표준 단어 → 표준 용어 → 표준 도메인 → 표준 코드의 상하 계층 → 최소 단위부터 유효값까지 일관성 확보.
2. 명칭·의미의 단일성 : **동음이의어** (같은 단어에 서로 다른 의미)와 **이음동의어** (다른 단어에 같은 의미)의 정비 → 전사 통합 조회와 매핑 비용 절감.
3. 절차적 변경 통제 : **변경 관리** (RFC, Request for Change) 심의와 **영향도 분석** (변경이 기 구축 테이블·인터페이스에 미치는 영향의 사전 검토)을 거친 표준 변경 → 기존 시스템의 갑작스러운 중단 방지.
4. 자동 검증 연계 : 모델링 도구와 배포 파이프라인에 **표준 검증 린터** (Linter, 명명·타입 규칙 위반을 자동 검사하는 도구) 탑재 → 사람 검토 의존 제거.

## Ⅲ. 데이터 표준화의 구조 (흐름)

- 핵심 요약 : 4대 요소의 정의 계층과 5단계 추진 절차, MDR 중심의 운영 구조.

```text
[ 4대 표준 요소의 계층 ]

표준 단어 (최소 의미 단위)
   ↓ 단어 조합
표준 용어 (업무 명칭)
   ↓ 물리 속성 매핑
표준 도메인 (타입·길이 틀)
   ↓ 유효값 제한
표준 코드 (값 집합)
```

```text
[ 표준화 추진 5단계 절차 ]

1. 대상 수집 (정의서·사전·명세)
   ↓
2. 현황 분석 (이의어 정비)
   ↓
3. 표준안 확정 (위원회 심의)
   ↓
4. 메타데이터 등록·배포
   ↓
5. 적용·사후 관리 (준수율 점검)
```

- 운영 구조 : 기존 시스템의 DDL(Data Definition Language)과 데이터 사전, 인터페이스 명세서를 표준화 대상으로 수집하고, **메타데이터 관리 시스템** (MDR, Metadata Repository)에 표준을 등록해 배포 → 단일 기준점 운영.

## Ⅳ. 4대 표준 요소의 비교

- 핵심 요약 : 최소 단위의 표준 단어에서 유효값 집합의 표준 코드까지 계층적 역할 분담.

| 표준 요소 | 정의 | 예시 | 관리 기준 |
| --- | --- | --- | --- |
| 표준 단어 | 분해 불가능한 최소 의미 단위 | 고객, 번호, 일자 | 영문 약어 부여·금칙어 관리 |
| 표준 용어 | 단어 조합의 업무 명칭 | 고객번호, 가입일자 | 약어 연결 규칙 준수 |
| 표준 도메인 | 타입·길이·범위의 물리 틀 | 금액, 여부, 일자 | DB별 타입 매핑 규칙 |
| 표준 코드 | 속성 값의 통일된 부호 집합 | 성별코드, 상태코드 | 체계 일련번호·유효 기간 관리 |

- 선택 기준 : 신규 데이터 요소는 4대 요소 계층 규칙의 엄격 적용, 기존 요소는 매핑 테이블 연결의 점진 편입.

## Ⅴ. 데이터 표준화의 한계와 방안

- 핵심 요약 : 레거시 충돌, 정의 합의 지연, 수작업 검증 누락을 점진 적용·계층화·자동 차단으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 레거시 일괄 적용의 충돌 | 기존 명명·코드 체계와 불일치 → 연계 프로그램 결함 | 신규 프로젝트 엄격 적용, 레거시는 매핑·변환 계층의 점진 편입 | 표준 준수율 |
| 핵심 개념 정의의 합의 지연 | 부서별 정의 차이로 용어 심의 장기화 | 전사 공통 표준과 도메인별 표준의 계층화 | 용어 승인 소요일 |
| 수작업 검증의 누락 | 설계자 대조 의존 → 미준수 명명 잔존 | 모델링 도구·배포 파이프라인에 린터 연동 배포 차단 | 미준수 배포 차단 건수 |

## Ⅵ. 전사 데이터 표준화 정착에 대한 기술사적 제언

- 핵심 요약 : 설계 시점 준수 유도, 신속한 승인 체계, 우선 적용 후 확산 전략.
- 개발 조직 : 모델링 도구에 MDR 연동 자동 완성을 기본 설정으로 배포해 설계 시점부터 준수 유도.
- 거버넌스 조직 : 표준 신청·승인의 처리 기한을 정해 신규 용어의 신속 수용 체계 운영.
- 추진 조직 : 신규·차세대 시스템 우선 적용 후 뷰·연계 계층으로 표준 명칭 확산.

## Ⅶ. 결론

- 핵심 요약 : 데이터 표준화는 4대 요소 정립과 자동 검증·점진 적용의 결합으로 완성되는 기반 활동임.
- 전사 합의된 표준과 자동 검증 체계가 함께 갖춰질 때 표준의 실효성이 확보됨.
