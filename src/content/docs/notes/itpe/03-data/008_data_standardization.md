## 지식 로드맵 내 현재 위치

<div class="itpe-topic-path" aria-label="지식 경로"><span>데이터 관리</span><span>표준·메타데이터</span><strong>데이터 표준화</strong></div>

## 큰 그림과 30초 인출

```text
[업무 의미] ─▶ 표준단어 조합 ─▶ 표준용어 ─▶ 속성·컬럼
                    │                │            │
                 분류어          표준도메인 ──────┘
                                   │ 타입·길이·형식·단위
[허용값 체계] ─────────────────▶ 표준코드
                                   │
             신청 → 검토 → 승인 → 배포 → 준수검증 → 변경
```

- 본질: **같은 의미는 같은 이름·정의·형식·값으로 표현하도록 전사 데이터 기준을 수립·적용·통제하는 활동**
- 4대 사전: 표준단어·표준용어·표준도메인·표준코드
- 암기: `단-용-도-코 / 신-검-승-배-준-변`
- 현행 주의: 공공 부문은 최신 지침·매뉴얼·공통표준 제·개정본을 기준일과 함께 확인

## 예상문제

> 데이터 표준화의 개념과 구성요소, 수립·적용 절차를 설명하고 공공 데이터베이스의 지속적인 표준 준수방안을 논하시오. (25점)

## Ⅰ. 데이터 의미와 형식을 일치시키는 표준화 개요

- 정의: 데이터 표준화는 조직의 데이터 명칭·정의·도메인·코드·표현규칙을 일관되게 정하고 시스템 설계·구축·운영에 적용하는 활동
- 목적: 동음이의어·이음동의어·타입·코드 불일치를 제거하여 통합·연계·품질·재사용 기반 확보
- 필요성: 동일 개념이 시스템마다 다른 이름과 형식으로 구현되면 인터페이스 변환, 집계 오류, 의미 왜곡이 반복됨

## Ⅱ. 의미·형식·값과 변경통제를 포괄하는 특징

| 특징 | 핵심 내용 | 효과 |
|---|---|---|
| 의미 일관성 | 용어 정의와 업무 개념 통일 | 분석·소통 오류 감소 |
| 구조 일관성 | 타입·길이·표현·단위 통일 | 연계·검증 자동화 |
| 값 일관성 | 공통코드·허용값 통제 | 집계·교환 정확성 |
| 전사 적용성 | 설계·구축·운영·개방에 공통 적용 | 재사용·상호운용성 |
| 지속 통제성 | 신청·검토·승인·배포·변경 이력관리 | 표준의 현행성 확보 |

## Ⅲ. 단어·용어·도메인·코드의 표준 구성요소

| 구성요소 | 정의 | 예시·핵심 관계 |
|---|---|---|
| 표준단어 | 더 분해하기 어려운 의미 단위와 명명 규칙 | 고객, 가입, 일자; 동의어·금칙어 관리 |
| 표준용어 | 표준단어를 규칙에 따라 조합한 업무 속성명 | 고객가입일자; 정의·영문명·분류어 |
| 표준도메인 | 값의 공통 특성에 따른 타입·길이·형식·단위 | 날짜시간, 금액, 수량, 전화번호 |
| 표준코드 | 정해진 의미와 허용값의 집합 | 상태코드, 지역코드; 코드값·명칭·유효기간 |

```text
고객 + 가입 + 일자 = 고객가입일자(표준용어)
                       └─ 분류어 '일자' → 날짜 도메인 → DATE/표현규칙
주문상태(표준용어) ──────────────▶ 주문상태코드(허용값·유효기간)
```

## Ⅳ. 데이터 표준의 수립·적용·운영 절차

```text
① 현황·비표준 분석 → ② 원칙·명명규칙 → ③ 단어·용어·도메인·코드 정의
 → ④ 검토·승인·사전 등록 → ⑤ 모델·DDL·인터페이스 적용
 → ⑥ 준수검증·비표준 매핑 → ⑦ 변경·영향·버전관리
```

| 단계 | 핵심 활동 | 산출물·통제 |
|---|---|---|
| 진단 | 기존 명칭·타입·코드·중복 분석 | 비표준 목록·영향도 |
| 정의 | 원칙과 4대 사전 수립 | 표준사전·명명규칙 |
| 적용 | 모델·테이블·API·메타데이터 매핑 | 표준 준수 모델·정의서 |
| 검증 | 설계·DDL·메타데이터 자동 대조 | 준수율·예외·보완계획 |
| 운영 | 신청·승인·배포·폐기·버전 통제 | 변경이력·영향분석 |

## Ⅴ. 데이터 표준화·모델링·품질관리·MDM 비교

| 구분 | 표준화 | 데이터 모델링 | 품질관리 | MDM |
|---|---|---|---|---|
| 질문 | 같은 의미·형식인가 | 업무 구조를 어떻게 표현하는가 | 업무에 쓸 품질인가 | 핵심 실체의 기준값은 무엇인가 |
| 대상 | 단어·용어·도메인·코드 | Entity·Relation·Attribute | 값·구조·프로세스 | 고객·상품 등 마스터 |
| 산출물 | 표준사전·규칙 | ERD·논리/물리모델 | 지표·오류·개선계획 | Golden Record·매핑 |
| 관계 | 모델·품질의 공통 기준 | 표준을 구조에 적용 | 표준 준수를 측정 | 표준화된 기준값을 동기화 |

## Ⅵ. 표준의 박제화를 막는 실무 고려사항

| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 신규 시스템이 비표준 생성 | 설계·DDL과 표준사전 분리 | 모델링·CI/CD에서 명칭·도메인·코드 자동검증 | 배포 전 차단 |
| 레거시 일괄개명 위험 | 인터페이스·프로그램 영향 미분석 | 논리표준-물리컬럼 매핑 후 위험기반 점진 전환 | 업무중단 방지 |
| 동음이의·이음동의 반복 | 정의·분류어·동의어 관리 부족 | 의미·사용문맥·동의어·금칙어와 Owner 등록 | 의미 충돌 감소 |
| 승인 병목 | 모든 요청을 중앙 수작업 검토 | 재사용 우선검색, SLA, 도메인 Steward 위임 | 민첩성과 일관성 균형 |
| 공통표준 개정 미반영 | 외부 기준 변경감시 부재 | 기준일·버전·차이분석·적용계획 관리 | 현행 준수 유지 |

## Ⅶ. 표준사전을 실행 가능한 정책으로 전환하는 결론

- **[표준-모델-DDL-API-메타데이터 추적성]**: 엑셀 표준사전만 관리하면 개발·변경 과정에서 비표준이 계속 유입됨
- 나라면: 표준을 API와 검증규칙으로 제공하고 모델·DDL·인터페이스 변경 시 자동 대조하며, 예외는 Owner·근거·만료일을 가진 정책으로 관리

#### 한줄 요약

- 표준화의 완성은 사전 발간이 아니라 모든 데이터 변경에서 표준 준수와 예외가 자동 추적되는 상태임

## 1교시 10점 답안 발췌

```text
표준단어 조합 → 표준용어 → 표준도메인(타입·길이·형식)
                              └─ 표준코드(허용값)
```

| 절차 | 핵심 |
|---|---|
| 수립 | 현황분석→원칙→4대 사전 |
| 적용 | 모델·DDL·API·메타데이터 매핑 |
| 운영 | 준수검증→변경·영향·버전관리 |

- 차별화: 표준을 CI/CD 검증규칙으로 제공하고 예외에 Owner·근거·만료일 부여
