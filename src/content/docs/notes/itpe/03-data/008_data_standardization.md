## 연관 키워드

- 데이터 표준, 용어사전, 코드체계, 메타데이터, 상호운용성

## Ⅰ. 데이터 표준화의 개요

- 핵심 요약 : 데이터 표준화는 데이터 요소의 의미·형식·코드·표현 규칙을 조직 간 일관되게 정의하고 적용하는 활동.
- 개념 : 데이터 표준화는 데이터 요소의 의미·형식·코드·표현 규칙을 조직 간 일관되게 정의하고 적용하는 활동.
- 배경 및 필요성 : 시스템마다 다른 명칭·단위·코드로 데이터 결합·교환·분석이 어려워지는 문제.
- 주요 목적 : 데이터 의미의 일관성과 시스템 간 상호운용성 확보.

## Ⅱ. 데이터 표준화의 특징 및 장점

- 핵심 요약 : 용어 표준: 같은 개념의 명칭·정의 통일 → 의미 혼선 감소; 형식·도메인: 길이·자료형·단위·허용값 규정 → 검증·교환 가능; 코드 표준: 분류 코드와 기준정보 통합 → 시스템 간 식별 일관성.

1. 용어 표준: 같은 개념의 명칭·정의 통일 → 의미 혼선 감소
2. 형식·도메인: 길이·자료형·단위·허용값 규정 → 검증·교환 가능
3. 코드 표준: 분류 코드와 기준정보 통합 → 시스템 간 식별 일관성

## Ⅲ. 데이터 표준화의 구조 (흐름)

- 핵심 요약 : 데이터 요소 식별 → 업무 정의·명명 → 형식·도메인·코드 정의 → 승인·카탈로그 등록 → 시스템 적용·변경관리.

```text
데이터 요소 식별
  ↓
업무 정의·명명
  ↓
형식·도메인·코드 정의
  ↓
승인·카탈로그 등록
  ↓
시스템 적용·변경관리
```

- 핵심 구성 : 업무 개념 → 표준 용어·정의

```text
업무 개념 → 표준 용어·정의
                 ↓
데이터 요소 → 형식·도메인·코드
                 ↓
DB 스키마·API·메시지 매핑
```

## Ⅳ. 비교: 전사 데이터 표준 / 시스템별 표준

- 핵심 요약 : 상호운용성 기준 — 전사 데이터 표준: 공통 용어·매핑으로 데이터 결합 촉진; 시스템별 표준: 국지 최적화에 그쳐 의미 변환 부담.

| 비교 기준 | 전사 데이터 표준 | 시스템별 표준 |
| --- | --- | --- |
| 정의 범위 | 조직 공통 의미·형식·코드 | 개별 시스템 내부 형식 |
| 상호운용성 | 공통 용어·매핑으로 데이터 결합 촉진 | 국지 최적화에 그쳐 의미 변환 부담 |

## Ⅴ. 데이터 표준화의 한계와 방안

- 핵심 요약 : 현업 정의 충돌·구현 미적용 등 실제 위험을 원인에 맞는 통제와 지표로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 현업 정의 충돌 | 부서별로 같은 용어를 다르게 사용 | 데이터위원회에서 의미·소유자·예외 합의 | 정의 충돌 건수 |
| 구현 미적용 | 표준 사전만 있고 DB·API에 반영되지 않음 | 스키마 검증·코드 생성·품질 룰로 자동화 | 표준 적용률 |
| 과도한 통일 | 업무 차이를 무시한 일괄 규격이 현장 부적합 | 공통 핵심과 도메인 확장 항목 분리 | 예외 승인·재작업률 |

## Ⅵ. 데이터 표준화의 제언

- 핵심 요약 : 데이터 아키텍트는 핵심 데이터 요소를 표준 사전에 등록하고 스키마·API 설계 검토와 변경 승인에 표준 준수를 내재화.
- 실행 제안 : 표준관리자는 신규 데이터 요소의 용어·단위·코드 변경을 검토하고 API·스키마 계약 검증을 배포 파이프라인에 적용.

## Ⅶ. 데이터 표준화의 결론

- 핵심 요약 : 표준화는 이름 맞추기가 아니라 데이터 의미·표현·책임을 일치시켜 상호운용성을 보장하는 기반.
- 시사점 : 의미·단위·코드의 합의와 실제 스키마·API 적용이 맞물려야 상호운용성 확보.
