## Ⅰ. 전사 데이터 상호운용성을 위한 데이터 표준화의 개요

### 가. 데이터 표준화의 정의
- **데이터 표준화** : 조직 내 분산된 정보시스템 간 데이터의 명칭, 정의, 형식, 규칙을 일관된 표준에 맞추어 통일하고 전사적으로 공유·관리하는 프로세스.
- 데이터 모델링, 데이터베이스 구축, 인터페이스 연계 시 동일한 의미의 데이터가 상이한 명칭이나 타입으로 분기되는 것을 방지함.

### 나. 데이터 표준화 부재 시 발생하는 주요 손실
- 데이터 중복 및 불일치 : 동일 고객을 의미하는 컬럼이 'CUST_NO', 'USER_ID', 'CUSTOMER_NUM' 등으로 혼용되어 전사 통합 분석 장애 초래.
- 인터페이스 변환 비용 폭증 : 시스템 간 연계 시마다 데이터 타입 변환(VARCHAR vs CHAR) 및 코드 매핑 로직 추가 필요.
- 유지보수 생산성 저하 : 개발자 교체 시 데이터베이스 컬럼의 실질 의미 파악에 막대한 시간 소요.

## Ⅱ. 데이터 표준화 체계의 4대 핵심 구성 요소

### 가. 데이터 표준 4대 요소 간의 계층 구조

```text
[ 데이터 표준 정의 흐름 ]
+---------------------+
|   1. 표준 단어      |  ---> 최소 의미 단위 (예: 고객, 번호, 일자)
+---------------------+
           | (단어 조합)
           v
+---------------------+
|   2. 표준 용어      |  ---> 비즈니스 명칭 (예: 고객번호 = 고객 + 번호)
+---------------------+
           | (도메인 매핑)
           v
+---------------------+
|   3. 표준 도메인    |  ---> 물리적 속성 그룹 (예: 식별번호_도메인 = VARCHAR(20))
+---------------------+
           | (값의 집합 제한)
           v
+---------------------+
|   4. 표준 코드      |  ---> 선택 가능한 유효값 집합 (예: 고객상태코드 = 01:정상, 02:휴면, 03:해지)
+---------------------+
```

| 표준 구성 요소 | 정의 및 작성 원칙 | 구체적 예시 | 관리 기준 |
| :--- | :--- | :--- | :--- |
| **표준 단어** | 더 이상 분해되지 않는 최소 의미 단위의 단어 정의 (동의어/유의어 정비, 금칙어 지정) | 고객(Customer), 번호(Number), 일자(Date) | 표준 영문 약어(3~4글자) 부여 (CUST, NO, DT) |
| **표준 용어** | 1개 이상의 표준 단어를 조합하여 업무적 의미를 표현한 명칭 | 고객번호(CUST_NO), 가입일자(JOIN_DT) | 영문 컬럼명은 조합된 표준 단어 약어의 언더스코어 연결 |
| **표준 도메인** | 속성의 물리적 타입, 길이, 허용 범위를 그룹화하여 표준화한 틀 | 금액_도메인: NUMBER(15,2), 여부_도메인: CHAR(1) | 데이터베이스별 데이터 타입 매핑 규칙 명시 |
| **표준 코드** | 특정 속성이 가질 수 있는 값의 목록을 통일하여 정의한 부호 집합 | 성별코드: M/F, 주문상태코드: 10/20/30 | 코드 체계 일련번호 부여, 유효 기간 관리 |

### 나. 표준화 절차 (표준화 5단계)
1. **표준화 대상 수집** : 기존 시스템의 DDL, 데이터 사전, 테이블 정의서, 인터페이스 명세서 추출.
2. **현황 분석 및 정비** : **동음이의어** (동일 단어 다른 의미) 및 **이음동의어** (다른 단어 동일 의미) 식별 정비.
3. **표준안 확정** : 표준 단어/용어/도메인/코드 정의서 작성 및 데이터 관리 위원회 심의 승인.
4. **전사 메타데이터 등록** : **메타데이터 관리 시스템** (MDR)에 전사 등록 및 사전 배포.
5. **적용 및 사후 관리** : 신규 프로젝트 모델링 시 표준 준수율 점검, 변경 관리 워크플로우 운영.

## Ⅲ. 데이터 표준 관리 시스템(MDR)과 변경 관리 거버넌스

### 가. 메타데이터 관리 시스템(MDR) 연계 흐름

```text
[ 개발 라이프사이클 내 표준 통제 ]
[데이터 모델러] ---> [MDR 시스템 검색] ---> [표준 용어 자동 완성]
                            |
                     (표준 미등록 시)
                            v
               [표준 신청 및 워크플로우 심의]
                            |
                   (승인 후 모델 반영)
                            v
               [CI/CD DDL 표준 준수 검증 (Linter)]
```

### 나. 변경 통제 절차
- **표준 변경 요청서** (RFC) 제출 $\rightarrow$ **영향도 분석** (Impact Analysis, 기 구축 테이블 및 인터페이스 영향 파악) $\rightarrow$ 거버넌스 위원회 심의 $\rightarrow$ 시스템 동기화 공지 및 일괄 적용.

## Ⅳ. 데이터 표준화 추진 시 주요 한계점 및 해결 방안

- 레거시 시스템의 이기종 표준 및 강제 적용 시 수정 비용 폭증 :
  - 한계점 : 수십 년간 축적된 레거시 시스템의 약어, 도메인, 코드 체계가 상이하여 신규 표준을 일괄 강제 시 연계 애플리케이션의 광범위한 재개발 및 결함 발생.
  - 해결 방안 : 표준 매핑 테이블 및 변환 어댑터(Adapter) 기반의 점진적 표준화 추진, 신규 및 차세대 프로젝트에 한해 신규 표준 엄격 적용(Strangler Fig 패턴).
- 다의어·동음이의어로 인한 비즈니스 도메인 간 합의 난항 :
  - 한계점 : '고객', '계좌' 등 핵심 엔티티가 부서(영업, 회계, 리스크)마다 정의와 유효 범위가 상이하여 전사 단일 표준 정의 합의 도달 지연.
  - 해결 방안 : 도메인 주도 설계(DDD)의 바운디드 컨텍스트(Bounded Context) 개념을 표준에 도입, 전사 공통 표준과 도메인별 표준을 계층화하여 수용.
- 데이터 표준 검증 자동화 파이프라인 부재 :
  - 한계점 : 모델 설계자가 수작업으로 표준 사전을 대조하여 표준 미준수 컬럼명 및 임의 약어 생성이 빈번히 발생, 사후 표준 준수율 저하.
  - 해결 방안 : ERD 도구(ERwin, DA#) 및 Git CI/CD 파이프라인에 표준 검증 린터(Linter)를 연동하여 표준 미준수 DDL 배포를 자동 차단.

## Ⅴ. 전사 데이터 표준화의 성공적 정착을 위한 제언

- 표준 준수율 강제와 자동화 : 모델러의 자발적 준수에 의존하지 않고, ERD 모델링 도구(ERwin, ER-Studio) 및 Git Hook과 연동하여 표준을 준수하지 않은 DDL 커밋을 원천 차단하는 CI 파이프라인 구성.
- 레거시 마이그레이션 전략 수립 : 기존 레거시 시스템의 물리 컬럼명을 일시에 전부 바꾸는 것은 막대한 리스크가 수반되므로, 신규 구축 차세대 시스템 우선 적용 후 뷰(View) 계층 또는 CDC 계층에서 표준 컬럼명으로 변환 노출하는 과도기 전략 채택.
- 지속적인 표준 거버넌스 운영 : 비즈니스 확장에 따라 새로운 신조어 및 기술 용어가 지속 발생하므로 표준 신청-승인 주기를 신속하게(SLA 24시간 이내) 처리할 수 있는 애자일 거버넌스 체계를 수립할 것을 제언함.
