```text
[데이터 표준화] ◀━━ 머리: Ⅶ 내 의견 (메타데이터 사전 구축을 넘어 형상관리·CI/CD 배포 파이프라인에 DDL 검증 강제)
 ┃
 ┣━ Ⅰ 개요 ───── 시스템별 용어·코드 중복 및 불일치 해소 → 전사 데이터 명칭·정의·형식 통일 활동
 ┣━ Ⅱ 특징 ───── 전사적 유일성 · 비즈니스 의미 일치 · 일관된 규칙성 · 지속적 통제 프로세스
 ┣━ Ⅲ 구조 ───── 표준 단어 사전 / 표준 도메인 사전 / 표준 용어 사전 / 표준 코드 사전
 ┣━ Ⅳ 흐름 ───── ① 표준화 요건 수집 → ② 단어·도메인·코드 정의 → ③ 표준 용어 조합 → ④ 검증 및 시스템 반영
 ┣━ Ⅴ 비교 ───── 표준 단어 vs 표준 도메인 vs 표준 용어 vs 표준 코드
 ┗━ Ⅵ 실무 ───── 이음동의어·동음이의어 범람 / 기 구축 레거시 DB 소급 적용 충돌 / 거버넌스 미준수
```
- 필수 키워드: 표준 단어 · 표준 도메인 · 표준 용어 · 표준 코드 · 공공데이터베이스 표준화 관리 매뉴얼 · 메타데이터 관리 시스템
- 배점 전략: 10점 = Ⅰ → Ⅲ 4대 표준 구성요소 도식 → Ⅵ 한 행 / 25점 = Ⅰ~Ⅶ, 앞 1/3에 Ⅲ 4대 표준요소 및 Ⅳ 표준 수립 절차
- 기출: 132회 `공공데이터베이스 표준화 관리 매뉴얼` → 공공 표준화 지침 기준 / 131회 `데이터 표준화 필요성과 기대효과` → Ⅰ 개요 + Ⅱ 필요성 및 기대효과 / 126회 `테이블 정의서 및 표준화 지침` → Ⅲ 표준 요소 반영 실무

## 한 줄 본질
- 개별 개발자의 자의적 명명으로 발생하는 동음이의어·이음동의어 왜곡 → 단어·도메인·코드 사전을 결합해 속성명과 물리 컬럼명을 단일 규칙으로 통제 → 시스템 간 무결성 및 연계 비용 절감 / 초기 표준 수립 부하 및 변경 절차 경직성 발생

## 핵심 그림
```text
[데이터 표준화 4대 구성요소의 조립 체계]

 [표준 단어 사전]        [표준 도메인 사전]        [표준 코드 사전]
 (고객, 번호, 일자)       (금액, 수량, 날짜타입)    (성별: M/F, 주문상태)
         │                       │                       │
         └───────────┬───────────┘                       │
                     ▼                                   ▼
             [표준 용어 사전] ───────────────────────────┘
             (고객_전화_번호, 주문_체결_일자)
                     │
                     ▼
             [물리 DB 컬럼명 매핑]
             (CUST_TEL_NO, ORD_CNCL_DT)
```

## 핵심 용어
- 표준 도메인(Standard Domain): 속성에 입력될 수 있는 값의 범위, 데이터 타입, 길이를 미리 그룹화하여 정의한 집합(예: 금액 도메인: NUMBER(15,2))
- 표준 용어(Standard Term): 표준 단어 사전의 단어들을 일정한 조합 규칙(수식어+수식어+분류어)에 따라 결합하여 업무적 의미를 확정한 속성 명칭

## 핵심 통찰
- 단어는 '분류어' 관리가 핵심임 → 용어의 맨 끝 단어(일자, 번호, 금액 등)가 반드시 표준 도메인과 1:1로 매핑되어야 물리 컬럼 타입이 자동으로 결정
- 표준화 없는 차세대 프로젝트는 100% 일정 지연 → 레거시 시스템마다 `고객ID`, `CUST_NO`, `USER_ID`, `고객번호`로 제각각이면 연계 인터페이스마다 변환 맵핑 테이블 작성에 수개월 낭비
- 행정안전부 '공공데이터베이스 표준화 관리 매뉴얼'은 공공 SW 감리의 필수 점검 기준 → 표준용어 사전 준수율이 감리 및 품질평가의 핵심 지표로 작동

## 딸려 나오는 하위 토픽
| 하위 토픽 | 상위 구조 속 위치 | 한 줄 |
|---|---|---|
| 이음동의어(Synonym) | 표준화 제거 대상 | 형태는 다르나 의미가 같은 단어(예: 고객, 거래처, 바이어)를 대표 단어로 단일화 |
| 동음이의어(Homonym) | 표준화 제거 대상 | 형태는 같으나 의미가 다른 단어(예: 수수료 - 은행 수수료 vs 중개 수수료)를 구분 |

## 이웃 토픽과 구분
- 데이터 표준화 vs 데이터 모델링: 표준화 = 데이터 명칭과 물리적 타입 규칙을 정하는 사전 작업 / 모델링 = 그 표준 용어들을 가지고 업무 엔티티와 관계(Relationship)를 설계하는 구조화 작업

## 문제·원인·대책
- 사례: 행정안전부 '공공데이터베이스 표준화 관리 매뉴얼(2023.04)' 준수 공공 정보화 사업
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 동일 의미의 날짜 컬럼이 시스템마다 `YYYYMMDD`, `VARCHAR(10)`, `TIMESTAMP` 혼용 | 표준 도메인 미준수 및 개별 개발자의 자의적 DDL 작성 | 메타데이터 관리 시스템을 통한 표준 도메인 승인 강제 | 데이터 연계 시 타입 변환 오류 제거 |
| 긴급 패치 시 메타 시스템을 우회하여 운영 DB에 비표준 컬럼 직접 생성 | 표준 변경 승인 절차의 번거로움과 형상 통제 부재 | DB 형상관리 도구(Liquibase 등)와 CI/CD 연동, 비표준 DDL 배포 자동 차단 | 메타데이터와 물리 DB 100% 일치 |

## 내 의견
- [사후 메타 역공학의 부실] 개발이 끝난 후 문서 작성용으로 메타 시스템에 용어를 거꾸로 밀어 넣는 부실 관행 빈발 → 나라면: ERD 모델링 도구와 메타데이터 시스템을 실시간 연동하여, 표준 사전에 등록되지 않은 단어로 작성된 속성은 물리 모델로 변환(Forward Engineering)되지 않도록 툴체인 게이트웨이 강제
