## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터 관리 → **데이터 표준화**

## 30초 인출

- 본질: 데이터 표준화는 데이터 항목의 명칭·의미·형식·허용값을 공통 규칙으로 정해 시스템 사이에서 같은 데이터가 같게 표현되도록 하는 활동
- 메커니즘: 표준 단어에서 표준 용어를 만들고 도메인과 표준 코드로 형식·값 범위를 정해 테이블 정의서와 데이터 모델에 반영하고 준수 여부를 점검
- 통찰: 표준을 만들어도 설계·개발 시 적용되지 않으면 이름과 형식이 다시 흩어지므로 데이터 모델링 단계에서 표준을 자동 검사해 준수하지 않으면 반영되지 않게 함

<details>
<summary>핵심 용어</summary>

- **데이터 표준화** : 데이터의 명칭·의미·형식·허용값을 공통 규칙으로 정하는 활동
- **표준 단어** : 데이터 이름을 이루는 기본 단위와 약어
- **표준 용어** : 업무 개념을 일관되게 나타내는 명칭과 정의
- **도메인** : 같은 성격의 데이터가 공유하는 형식·길이·값 범위 규칙
- **표준 코드** : 상태·분류 등을 공통 값으로 나타내는 코드 체계
- **테이블 정의서** : 테이블·컬럼의 이름·의미·형식·키·관계를 기록한 문서

</details>

## 2~4교시 25점 답안

## Ⅰ. 데이터 표준화의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터 표준화** 는 데이터 항목의 명칭·의미·형식·허용값을 공통 규칙으로 정하는 활동 |
| 목적 | 시스템 간 데이터의 일관성과 연계·품질 확보 |

## Ⅱ. 특징

| 특징 | 의미 |
|---|---|
| 공통 규칙 | 전사 또는 기관 단위의 통일 |
| 설계 시점 적용 | 모델링 단계에서 반영 |
| 지속 관리 | 표준의 제·개정과 준수 점검 |

## Ⅲ. 표준 체계와 적용 절차

### 표준 구성 요소

```text
표준 단어 ─→ 표준 용어 ─→ 도메인·표준 코드 ─→ 테이블 정의서·모델
(이름의 기본 단위)   (업무 개념 명칭)   (형식·값 범위)      (설계에 반영)
```

### 적용 절차

```text
표준 수립 → 데이터 모델링 시 표준 적용 → 표준 준수 검사 → 위반 수정 → 표준 개정
```

## Ⅳ. 표준 요소별 정리

| 요소 | 내용 | 예 |
|---|---|---|
| 표준 단어 | 이름의 기본 단위·약어 | 고객, 번호 |
| 표준 용어 | 단어를 조합한 업무 명칭 | 고객번호 |
| 도메인 | 형식·길이·값 범위 | 숫자 10자리 |
| 표준 코드 | 공통 값 체계 | 성별 코드 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 표준이 설계에 적용되지 않아 이름·형식 분산 | 모델링 도구에서 표준 준수 자동 검사 |
| 기존 시스템과의 표준 불일치 | 매핑 표를 두고 단계적 전환 |
| 표준 변경 시 반영 누락 | 표준 변경 이력과 영향 시스템 관리 |

## Ⅵ. 제언

데이터 모델링 단계에서 표준 준수를 자동 검사하고 위반은 반영되지 않게 통제

```text
모델 작성 → 표준 검사 ─ 위반 → 수정 요구
                       └ 준수 → 반영
```

| 구분 | 사후 점검 | 제언: 모델링 단계 검사 |
|---|---|---|
| 위반 발견 | 구축 후 | 설계 시 |
| 수정 비용 | 큼 | 작음 |
