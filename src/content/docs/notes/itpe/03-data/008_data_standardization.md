## 예상문제

> 전사 데이터 거버넌스 및 행정안전부 '공공데이터베이스 표준화 관리지침'에 따른 데이터 표준화의 개념, 4대 핵심 구성요소(단어, 용어, 도메인, 코드), 명명 규칙 및 테이블 정의서 작성 시 표준 매핑 방안을 설명하시오. (25점)

## Ⅰ. 데이터 상호운용성의 주춧돌, 데이터 표준화의 개요

> 데이터 표준화는 전사 데이터의 명칭·정의·형식·코드를 통일해 데이터 해석 왜곡을 방지하는 관리 활동임.

- 정의: 조직 내에서 사용하는 데이터의 명칭, 의미, 도메인, 규칙을 일관되게 정의하고, 이를 정보시스템 설계·구축·운영 및 공공데이터 개방 전반에 강제하는 엔지니어링 활동
- 배경: 부서별 독자적 개발로 인한 이음동의어(Synonym), 동음이의어(Homonym) 만연, 시스템 간 데이터 연계 시 막대한 ETL 매핑 비용 발생 및 통계 왜곡
- 목적: 데이터 명칭과 의미의 일관성(Semantic Consistency) 확보, 데이터 재사용성 증대, 공공 DB 표준화 지침 준수를 통한 범정부 데이터 개방 및 연계성 보장

## Ⅱ. 데이터 표준화 4대 핵심 구성요소 (단·용·도·코)

> 표준단어의 조합으로 표준용어를 만들고, 분류어에 표준도메인과 코드를 바인딩함.

  <div class="itpe-pipeline-node"><strong>표준단어</strong><div class="itpe-step-detail"><span>역할</span><span>최소 의미 단위</span></div></div>
  <div class="itpe-pipeline-arrow">+</div>

  <div class="itpe-pipeline-node"><strong>표준용어</strong><div class="itpe-step-detail"><span>산출</span><span>속성 · 컬럼명</span></div></div>
  <div class="itpe-pipeline-arrow">↔</div>
  <div class="itpe-pipeline-node"><strong>도메인·코드</strong><div class="itpe-step-detail"><span>통제</span><span>타입 · 허용값</span></div></div>
</div>

| 구성요소 | 정의 및 작성 규칙 | 실무 작성 예시 | 통제 규칙 |
|---|---|---|---|
| **표준단어 (Word)** | 더 이상 쪼갤 수 없는 데이터 명칭의 최소 의미 단위 | `고객`(CUST), `가입`(JOIN), `일자`(DT) | 한글 단어당 단일 영문 약어 부여, 동의어·금칙어 엄격 관리 |
| **표준용어 (Term)** | 2개 이상의 표준단어를 조합하여 업무적 의미를 부여한 명칭 | `고객가입일자` (CUST_JOIN_DT) | 마지막 단어는 반드시 '분류어'여야 하며, 분류어는 도메인과 1:1 매핑 |
| **표준도메인 (Domain)** | 속성에 입력될 수 있는 값의 데이터 타입, 길이, 허용 형식 | `날짜 도메인` (VARCHAR(8), YYYYMMDD) | 물리 DB 데이터 타입과 제약조건(Check 등)을 포괄 정의 |
| **표준코드 (Code)** | 선택 가능한 도메인 값들을 코드화하여 유일성과 일관성을 부여 | `회원상태코드` (01:정상, 02:휴면, 09:탈퇴) | 코드 ID, 코드값, 코드명, 사용 여부, 유효기간 필수 관리 |

## Ⅲ. 데이터 표준화 5단계 수립 및 통제 절차

> 현황 수집에서 원칙 정립, 4대 사전 정의, 모델 검증, 변경 관리로 순환 운영함.

| 단계 | 주요 활동 내용 | 핵심 산출물 및 통제 기준 |
|---|---|---|
| **1. 표준화 현황 진단** | 기존 DB 카탈로그, 테이블 정의서, 용어 사용 현황 수집 | 용어 중복 및 비표준 분석서 |
| **2. 표준화 원칙 수립** | 단어 조합 원칙, 영문 약어 부여 규칙(음절 축약 등), 금칙어 정의 | 데이터 표준화 지침서 |
| **3. 4대 표준사전 구축** | 표준단어, 표준용어, 표준도메인, 표준코드 사전 작성 및 승인 | 데이터 표준 사전 (엑셀/메타시스템) |
| **4. 데이터 모델 적용** | ERD 모델링 도구에 표준사전 연동, 논리/물리 속성명 자동 변환 | 표준 준수 논리/물리 ERD |
| **5. 변경 관리 및 준수 검증** | 표준 신청 $\to$ 심의 $\to$ 승인 워크플로우 운영, DDL 검증 자동화 | 표준 준수율 진단보고서 |

## Ⅳ. 물리 데이터 모델의 핵심 산출물: 테이블 정의서 구조 및 표준 매핑

> 테이블 정의서는 표준용어와 물리 DB 컬럼의 타입·제약을 1:1로 결합하는 공식 명세서임.

```text
[표준사전] 표준용어: 고객가입일자 (CUST_JOIN_DT, 도메인: 일자)
               │
               ▼  1:1 물리 매핑
[테이블 정의서] 컬럼ID: CUST_JOIN_DT | 컬럼한글: 고객가입일자 | Type: VARCHAR(8) | PK: N | Null: N
```

| 항목 | 기재 내용 및 표준 연계 기준 | 비고 |
|---|---|---|
| **테이블 물리명 / 논리명** | 주제영역 분류어와 표준단어 조합 (`TB_CUST_M` / `고객마스터`) | 전사 테이블 명명규칙 준수 |
| **컬럼 물리명 / 논리명** | 표준사전에 등록된 영문 약어 조합 및 한글 표준용어 매핑 | 임의 영문 약어 사용 금지 |
| **데이터 타입 및 길이** | 표준도메인에서 정의한 DBMS 물리 데이터 타입 (`VARCHAR(8)`, `NUMBER(10)`) | 도메인 타입 일치율 100% |
| **PK / FK / Nullable** | 기본키 여부, 외래키 참조 테이블 및 컬럼, 필수 입력 여부 | 무결성 제약조건 명시 |
| **기본값 (Default)** | 시스템 입력 누락 시 자동 지정될 기본값 (`SYSDATE`, `'01'`) | 비즈니스 기본 규칙 반영 |

## Ⅴ. 행정안전부 '공공데이터베이스 표준화 관리지침' 주요 요구사항

> 공공기관은 행정표준코드와 범정부 공통표준용어를 의무 준수하고 메타관리시스템에 등록해야 함.

| 요구 영역 | 세부 지침 내용 | 공공 정보화 사업 적용 방안 |
|---|---|---|
| **행정표준용어 준수** | 범정부 데이터 표준용어(행안부 고시) 우선 사용 의무화 | 신규 사업 시 공통표준용어사전 매핑 후 기관 고유 용어 정의 |
| **행정표준코드 적용** | 법정동코드, 행정기관코드, 성별 등 국가 표준코드 필수 적용 | 사설 코드 생성 금지, 연계 API 기반 실시간 코드 동기화 |
| **도메인 및 데이터 형식** | 날짜(YYYY-MM-DD), 시간(HH:MM:SS), 좌표계 등 공통 형식 준수 | 비정형 표현 배제 및 대국민 공공데이터 개방 호환성 확보 |
| **메타데이터 등록·현행화** | 범정부 메타데이터 관리시스템에 기관 DB 테이블 정의서 및 스키마 등록 | 사업 완료 감리 시 공공데이터 포털 메타 연계 일치율 검증 |

## Ⅵ. 실무 고려사항 및 장애 대책

> 비표준 레거시와의 충돌과 자의적 약어 생성을 메타관리 솔루션 기반 CI/CD 게이트로 방어함.

- 적용 상황: 대규모 공공 차세대 시스템 구축 시 수천 개 테이블 표준화 및 레거시 데이터 마이그레이션

| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| **비표준 물리 컬럼명 난립** | 개발자가 메타시스템 승인 없이 DDL 임의 작성 및 배포 | CI/CD 파이프라인에 DDL 표준 검증 Linter 연동 (비표준 시 배포 중단) | 배포 단계 표준 준수율 100% 강제 |
| **무리한 한글 음절 축약** | 단어당 약어 부여 시 모음 탈락 등 비직관적 약어 생성 | 공식 IT 표준 약어(ISO/IEC 및 공공 용어사전) 기반 약어 은행 사전 구축 | 개발자 코드 가독성 및 유지보수성 향상 |
| **레거시 컬럼 매핑 오류** | 레거시 단일 컬럼에 복합 속성(예: '주소+상세주소') 혼재 | 데이터 프로파일링 기반 속성 분화 및 원천 데이터 정제 선행 | 마이그레이션 정합성 확보 |

## Ⅶ. 결론 및 기술사적 제언

> 데이터 표준화는 단순한 명칭 통일이 아니라 데이터 메시와 AI 상호운용성을 여는 기반 인프라임.

### 학습자 통찰 메모 — 답안 밖

- `[핵심 통찰]`: 표준화의 핵심은 이름을 예쁘게 맞추는 것이 아니라 같은 의미가 같은 타입과 규칙으로 구현되게 하는 것이다.
- `나라면`: 표준사전을 설계도와 배포 파이프라인에 연결해 문서와 실제 DDL 사이의 드리프트를 지속 검출하겠다.

### 실전 답안용 기술사적 제언

- 판정: 표준용어·도메인과 테이블 정의서·DDL 간 Traceability가 유지되어야 표준 준수
- 대안: 표준 신청·심의·승인 Baseline과 DDL 정적 검증 Gate를 메타시스템에 통합
- 검증: 비표준 용어 수, 도메인 불일치율, 정의서-DB 스키마 일치율, 예외 만료 여부 측정
- 효과: 연계 변환비용과 의미 왜곡을 줄이고 공공데이터 상호운용성 확보

## 1교시 10점 답안 발췌

### 1. 정의 및 핵심 개념
- 데이터 표준화는 전사 데이터의 의미, 명칭, 도메인, 코드를 일관되게 규정하여 동음이의어와 이음동의어를 제거하고 상호운용성을 보장하는 거버넌스 활동임.

### 2. 핵심 메커니즘 / 체계
```text
[표준단어] + [분류어] ──▶ [표준용어] ──▶ [테이블 정의서 물리 컬럼]
                            │
              [표준도메인 / 표준코드]
```
- 행안부 '공공데이터베이스 표준화 관리지침'에 따라 공통표준용어 및 행정표준코드를 필수 준수함.

### 3. 적용 제언
- DDL 배포 파이프라인에 표준 Linter를 연동하여 비표준 컬럼의 배포를 원천 차단하고, 테이블 정의서와 메타데이터의 실시간 동기화를 달성해야 함.
