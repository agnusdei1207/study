## 연관 키워드

- 데이터 표준화, 표준 단어·용어·도메인·코드, 동음이의어·이음동의어, 메타데이터 관리 시스템(MDR)
- 변경 관리(RFC), 영향도 분석, 표준 검증 린터(Linter), 바운디드 컨텍스트, Strangler Fig 패턴

## Ⅰ. 데이터 표준화의 개요

- 핵심 요약 : 분산 시스템 간 데이터의 명칭·정의·형식·규칙을 전사 표준으로 통일하는 프로세스.
- 개념 : 조직 내 분산된 정보시스템 간 데이터의 명칭, 정의, 형식, 규칙을 일관된 표준에 맞추어 통일하고 전사적으로 공유·관리하는 프로세스.
- 배경 및 필요성 :
  1. 데이터 중복 및 불일치 : 동일 고객을 의미하는 컬럼의 CUST_NO, USER_ID, CUSTOMER_NUM 등 혼용으로 전사 통합 분석 장애.
  2. 인터페이스 변환 비용 폭증 : 시스템 간 연계 시마다 데이터 타입 변환(VARCHAR vs CHAR) 및 코드 매핑 로직 추가.
  3. 유지보수 생산성 저하 : 개발자 교체 시 데이터베이스 컬럼의 실질 의미 파악에 막대한 시간 소요.
- 주요 목적 : 데이터 모델링·데이터베이스 구축·인터페이스 연계에서 동일 의미 데이터의 상이한 명칭·타입 분기 방지 및 전사 상호운용성 확보.

## Ⅱ. 데이터 표준화의 특징

- 핵심 요약 : 4대 표준 요소의 계층 구조와 5단계 절차, 거버넌스 기반 변경 관리의 결합.

1. 4대 표준 요소 : 표준 단어, 표준 용어, 표준 도메인, 표준 코드의 계층적 구성.
2. 상호운용성 확보 : 시스템 간 데이터 명칭·정의·형식·규칙의 통일.
3. 5단계 추진 절차 : 대상 수집 → 현황 분석 → 표준안 확정 → 메타데이터 등록 → 적용·사후 관리.
4. 거버넌스 기반 변경 관리 : 표준 변경 요청서(RFC) 기반의 영향도 분석 및 위원회 심의.
5. 자동 검증 연계 : 모델링 도구·CI 파이프라인의 표준 준수 검증.

## Ⅲ. 데이터 표준화의 구조 (흐름)

- 핵심 요약 : 표준 단어→용어→도메인→코드의 정의 흐름과 MDR 중심의 개발 라이프사이클 표준 통제.

```text
[ 데이터 표준 정의 흐름 ]
 1. 표준 단어 : 최소 의미 단위 (예: 고객, 번호)
    │ (단어 조합)
    ▼
 2. 표준 용어 : 비즈니스 명칭 (예: 고객번호)
    │ (도메인 매핑)
    ▼
 3. 표준 도메인 : 물리적 속성 그룹 (예: 금액)
    │ (값의 집합 제한)
    ▼
 4. 표준 코드 : 유효값 집합 (예: 성별코드)
```

```text
[ 개발 라이프사이클 내 표준 통제 ]
 [데이터 모델러]
    │
    ▼
 [MDR 시스템 검색] → [표준 용어 자동 완성]
    │ (표준 미등록 시)
    ▼
 [표준 신청 및 워크플로우 심의]
    │ (승인 후 모델 반영)
    ▼
 [CI/CD DDL 표준 준수 검증 (Linter)]
```

- 표준화 5단계 절차 :
  1. 표준화 대상 수집 : 기존 시스템의 DDL(Data Definition Language), 데이터 사전, 테이블 정의서, 인터페이스 명세서 추출.
  2. 현황 분석 및 정비 : 동음이의어(동일 단어 다른 의미)와 이음동의어(다른 단어 동일 의미)의 식별 정비.
  3. 표준안 확정 : 표준 단어·용어·도메인·코드 정의서 작성 및 데이터 관리 위원회 심의 승인.
  4. 전사 메타데이터 등록 : 메타데이터 관리 시스템(MDR, Metadata Repository) 전사 등록 및 사전 배포.
  5. 적용 및 사후 관리 : 신규 프로젝트 모델링 시 표준 준수율 점검 및 변경 관리 워크플로우 운영.
- 변경 통제 절차 : 표준 변경 요청서(RFC, Request for Change) 제출 → 영향도 분석(Impact Analysis, 기 구축 테이블·인터페이스 영향 파악) → 거버넌스 위원회 심의 → 시스템 동기화 공지 및 일괄 적용.

## Ⅳ. 데이터 표준 4대 요소의 비교

- 핵심 요약 : 최소 단위의 표준 단어에서 유효값 집합의 표준 코드까지 계층적 구성.

| 표준 구성 요소 | 정의 및 작성 원칙 | 구체적 예시 | 관리 기준 |
|---|---|---|---|
| 표준 단어 | 더 이상 분해되지 않는 최소 의미 단위의 단어 정의(동의어·유의어 정비, 금칙어 지정) | 고객(Customer), 번호(Number), 일자(Date) | 표준 영문 약어 부여(CUST, NO, DT) |
| 표준 용어 | 1개 이상의 표준 단어 조합을 통한 업무적 의미 표현 | 고객번호(CUST_NO), 가입일자(JOIN_DT) | 영문 컬럼명은 조합된 표준 단어 약어의 언더스코어 연결 |
| 표준 도메인 | 속성의 물리적 타입, 길이, 허용 범위를 그룹화한 표준화 틀 | 금액_도메인 NUMBER(15,2), 여부_도메인 CHAR(1) | 데이터베이스별 데이터 타입 매핑 규칙 명시 |
| 표준 코드 | 특정 속성이 가질 수 있는 값 목록의 통일된 부호 집합 | 성별코드 M/F, 주문상태코드 10/20/30 | 코드 체계 일련번호 부여, 유효 기간 관리 |

## Ⅴ. 데이터 표준화의 장점과 한계

- 핵심 요약 : 상호운용성·비용 절감의 장점과 레거시 강제·도메인 합의·자동화 부재의 한계.

- 장점
  1. 전사 데이터 상호운용성 및 통합 분석 기반 확보.
  2. 인터페이스 변환 비용 절감.
  3. 유지보수 생산성 및 데이터 품질 향상.

- 한계점 1 : 레거시 시스템의 이기종 표준과 강제 적용 시 수정 비용 폭증
  - 한계점 : 수십 년간 축적된 레거시의 약어·도메인·코드 체계 상이로 신규 표준 일괄 강제 시 연계 애플리케이션의 광범위한 재개발 및 결함 발생.
  - 해결 방안 : 표준 매핑 테이블과 변환 어댑터(Adapter) 기반의 점진적 표준화 추진, 신규·차세대 프로젝트 한정의 신규 표준 엄격 적용(Strangler Fig 패턴).
- 한계점 2 : 다의어·동음이의어로 인한 비즈니스 도메인 간 합의 난항
  - 한계점 : 고객, 계좌 등 핵심 엔티티가 부서(영업, 회계, 리스크)마다 정의·유효 범위가 상이하여 전사 단일 표준 정의 합의 지연.
  - 해결 방안 : 도메인 주도 설계(DDD, Domain-Driven Design)의 바운디드 컨텍스트(Bounded Context) 개념의 표준 도입, 전사 공통 표준과 도메인별 표준의 계층화 수용.
- 한계점 3 : 데이터 표준 검증 자동화 파이프라인 부재
  - 한계점 : 모델 설계자의 수작업 표준 사전 대조 의존으로 미준수 컬럼명·임의 약어 생성 빈발 및 사후 표준 준수율 저하.
  - 해결 방안 : ERD(Entity-Relationship Diagram) 도구(ERwin, DA#)와 Git CI(Continuous Integration)/CD(Continuous Delivery) 파이프라인의 표준 검증 린터(Linter) 연동을 통한 미준수 DDL 배포 자동 차단.

## Ⅵ. 전사 데이터 표준화 정착을 위한 기술사적 제언

- 핵심 요약 : 표준 준수율 강제·자동화, 레거시 마이그레이션 과도기 전략, 애자일 거버넌스 운영.
- 표준 준수율 강제와 자동화 : 모델러의 자발적 준수 의존 탈피, ERD 모델링 도구(ERwin, ER-Studio)와 Git Hook 연동을 통한 미준수 DDL 커밋의 원천 차단 CI 파이프라인 구성.
- 레거시 마이그레이션 전략 수립 : 물리 컬럼명의 일시 전면 변경 리스크 회피, 신규 차세대 시스템 우선 적용 후 뷰(View) 계층 또는 CDC(Change Data Capture) 계층의 표준 컬럼명 변환 노출 과도기 전략 채택.
- 지속적인 표준 거버넌스 운영 : 비즈니스 확장에 따른 신조어·기술 용어의 지속 발생을 감안한 SLA(Service Level Agreement) 기반 신속 표준 신청-승인 주기의 애자일 거버넌스 체계 수립.

## Ⅶ. 결론

- 핵심 요약 : 데이터 표준화는 4대 표준 요소 정립과 자동 검증·점진적 적용의 결합이 성공 조건.
- 요약 : 표준 단어→용어→도메인→코드의 계층 정의와 MDR 중심 변경 통제 체계.
- 시사점 : 레거시 과도기 전략과 CI 기반 표준 검증 자동화를 통한 실효성 확보 필요.
