## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터 관리 → **마스터 데이터 관리(MDM)**

## 30초 인출

- 본질: 마스터 데이터 관리는 여러 업무가 공유하는 기준 정보(고객·제품 등)를 식별·관리해 일관되게 제공하는 관리 체계
- 메커니즘: 원천 기록을 모아 표준화하고 동일 개체를 매칭해 불확실한 사례는 스튜어드가 검토하며, 속성별 신뢰 원천과 충돌 규칙으로 골든 레코드를 만들어 소비 시스템에 배포·동기화
- 통찰: 한 번 통합해도 원천과 소비 시스템이 계속 변경되므로 책임자·식별 규칙·변경 배포 절차를 거버넌스로 정하고, 자동 매칭 범위를 제한해 잘못된 병합을 막음

<details>
<summary>핵심 용어</summary>

- **마스터 데이터(Master Data)** : 여러 업무가 공유하는 고객·제품·조직 같은 핵심 기준 정보
- **골든 레코드(Golden Record)** : 원천 기록을 조정해 만든 신뢰할 수 있는 단일 기준 레코드
- **데이터 스튜어드** : 담당 데이터의 정의·품질·변경을 실무에서 관리하는 담당자
- **Registry·Consolidated·Co-existence·Transactional** : MDM 구축 유형
- **매칭(Matching)** : 동일 개체를 가리키는 기록을 찾는 작업
- **CDC(Change Data Capture)** : 데이터베이스 변경을 감지해 다른 시스템에 전달하는 기법

</details>

## 2~4교시 25점 답안

## Ⅰ. MDM의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **마스터 데이터 관리** 는 조직의 공유 기준 정보를 식별·관리해 업무에 일관되게 제공하는 관리 체계 |
| 목적 | 시스템 간 기준 정보의 불일치·중복을 줄여 업무·분석의 신뢰성 확보 |

## Ⅱ. 특징

| 특징 | 대상·조건 | 관리 의미 |
|---|---|---|
| 공유 기준 | 여러 업무가 참조하는 개체 | 시스템별 표현을 연결 |
| 신뢰 원천 | 속성마다 권위 있는 생성·수정 주체 | 충돌 시 채택 기준 확보 |
| 지속 배포 | 변경 이력과 이용 시스템 | 통합 뒤에도 동기화 유지 |

## Ⅲ. 골든 레코드 생성과 배포 절차

```text
원천 기록 수집 → 용어·코드·형식 표준화
      ↓ 식별자·속성으로 동일 개체 후보 매칭
확실한 일치 / 불확실한 일치 → 스튜어드 검토
      ↓ 속성별 신뢰 원천·충돌 규칙 적용
골든 레코드·원천 연결 이력 관리
      ↓ 변경 이벤트·식별자 배포
소비 시스템 반영 → 동기화 실패 재처리
```

## Ⅳ. 구축 유형과 거버넌스

| 유형 | 허브의 역할 | 특성 | 적합 목적 |
|---|---|---|---|
| Registry | 원천 간 식별자 연결 | 원천이 주 저장 위치 | 시스템 간 식별·탐색 |
| Consolidated | 원천 기록을 모아 통합 뷰 제공 | 통합 데이터로 분석·조회 | 분석·보고 일관성 |
| Co-existence | 조정된 기준 정보를 허브·원천이 함께 관리 | 변경 연계·동기화 설계 필요 | 운영 시스템에 기준 정보 공유 |
| Transactional | 중앙에서 생성·변경 통제 | 중앙 변경을 원천에 배포 | 공통 기준의 중앙 운영 |

| 거버넌스 요소 | 확인 내용 |
|---|---|
| 데이터 책임 | 소유자·스튜어드의 결정·처리 권한 |
| 식별·중복 조정 | 일치 기준, 자동 조정 범위, 검토 대상 |
| 변경·배포 | 승인, 이벤트 전달, 실패 재처리, 동기화 상태 |
| 품질·감사 | 유효성 규칙, 출처·변경 이력, 오류 정정 경로 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 원천의 정의·소유권이 달라 병합 기준 지연 | 핵심 도메인부터 책임자·용어·식별 규칙 합의 |
| 유사 이름만으로 다른 개체를 병합하거나 같은 개체를 분리 | 자동 매칭 범위 제한, 불확실 사례는 스튜어드 검토 |
| 허브 변경 후 원천·소비 시스템의 불일치 | 변경 이력·배포 상태 추적, 실패 이벤트 재처리 |

## Ⅵ. 제언

핵심 도메인부터 책임자와 식별 규칙을 정하고, 목적에 맞는 구축 유형으로 단계적으로 확대

```text
핵심 도메인 선정 → 책임자·규칙 합의 → 유형 선택 → 골든 레코드 운영 → 배포 모니터링 → 도메인 확대
```

| 구분 | 일회성 통합 | 제언: 거버넌스 기반 지속 관리 |
|---|---|---|
| 동기화 | 시간이 지나며 불일치 | 변경 배포 추적 |
| 병합 오류 | 자동 병합 위험 | 불확실 사례 검토 |
