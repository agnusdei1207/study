## 연관 키워드

- 마스터 데이터 관리(MDM, Master Data Management), 마스터 데이터와 트랜잭션 데이터 비교, 4대 MDM 아키텍처 토폴로지, 매칭 및 머징 핵심 메커니즘, 장점, 한계점 및 해결 방안

## Ⅰ. 마스터 데이터 관리(MDM)의 개요

- 핵심 요약 : 기업의 핵심 비즈니스 엔티티에 대한 기준 데이터를 전사적으로 단일화하고 생명주기를 통제하여 단일 진실 공급원(SSOT: Single Source of Truth)을 보장하는 프로세스, 정책 및 통합 기술 아키텍처 체계

- 개념 : 기업의 비즈니스 프로세스 전반에 걸쳐 공유되는 핵심 비즈니스 엔티티(고객, 상품, 공급업체, 계정, 조직 등)의 기준 데이터를 전사적으로 단일화하고, 데이터의 생성·변경·폐기 전 생명주기를 일관되게 통제하는 체계

- 배경 및 필요성 : 부서별로 데이터를 개별 관리하면서 동일한 고객이나 상품에 대해 상이한 코드와 속성이 존재하는 데이터 중복과 불일치 문제가 발생. 이로 인한 업무 비효율과 의사결정 오류를 방지하기 위해 전사적 단일 뷰 구축이 필요한 체계

- 주요 목적 : 데이터의 정확성, 일관성, 유일성 확보를 통해 전사적 데이터 품질을 보장하고, 신뢰할 수 있는 기준 데이터를 제공하여 비즈니스 의사결정의 신뢰성을 극대화하는 체계

### 마스터 데이터와 트랜잭션 데이터 비교

| 비교 항목 | 마스터 데이터(Master Data) | 트랜잭션 데이터(Transactional Data) |
| :--- | :--- | :--- |
| 데이터 성격 | 비즈니스의 핵심 명사(Who, What, Where) | 비즈니스에서 발생하는 사건의 동사(Did What, When) |
| 구체적 예시 | 고객(Customer), 상품(Product), 거래처, 사원, 계정 | 주문(Order), 입출금(Payment), 배송로그, 통화내역 |
| 변경 빈도 | 상대적으로 낮음(안정적, 수명주기가 김) | 극도로 높음(초당 수천 건 지속 생성) |
| 데이터 볼륨 | 수만~수백만 건(관리 가능한 크기) | 수천만~수억 건(대규모 스트리밍/로그) |
| 관리의 핵심 | 정확성, 일관성, 유일성(중복 제거가 최우선) | 처리 속도(Throughput), 확장성, 트랜잭션 정합성 |

## Ⅱ. 마스터 데이터 관리(MDM)의 특징

- 핵심 요약 : 4대 아키텍처 모델(Registry, Consolidation, Coexistence, Transaction)을 기반으로 구현되며, 매칭 및 머징 엔진이 핵심 기능을 담당하는 데이터 통합 관리 체계

1. 중앙 집중식 관리 체계 : 전사 차원에서 마스터 데이터를 통합 관리하고 표준을 적용하여 데이터 일관성을 보장하는 체계

2. 생명주기 관리 체계 : 데이터의 생성, 변경, 폐기 전 과정을 일관되게 통제하고 이력을 관리하는 체계

3. 이종 시스템 통합 체계 : 레거시 시스템, 클라우드 서비스, 외부 데이터 소스 등 이기종 환경의 데이터를 통합하는 체계

4. 거버넌스 기반 체계 : 데이터 소유권, 표준 용어, 변경 승인 프로세스 등 조직적 거버넌스와 연동되는 체계

### 4대 MDM 아키텍처 토폴로지

```text
[ MDM 4대 아키텍처 토폴로지 ]
1. Registry (참조형)    : 원천 시스템 유지, 중앙에는 식별자 매핑 키(Cross-reference)만 보관
2. Consolidation (통합형): 원천 시스템에서 배치 수집하여 중앙에 골든 레코드 구축 (분석용)
3. Coexistence (공존형) : 중앙에서 골든 레코드 관리 및 원천 시스템으로 변경 전파 (운영/분석 혼합)
4. Transaction (트랜잭션): 모든 마스터 데이터 CUD(Create, Update, Delete)가 오직 중앙 MDM 허브에서만 발생
```

## Ⅲ. 마스터 데이터 관리(MDM)의 구조 (흐름)

- 핵심 요약 : 데이터 수집 → 표준화 → 매칭 → 머징 → 골든 레코드 생성 → 배포 및 동기화의 단계로 구성되는 마스터 데이터 통합 흐름

```text
[ MDM 데이터 통합 흐름 ]
[이종 시스템 데이터 인입]
        |
        v
[1. 데이터 표준화 & 주소 정제]
   - 코드 값 표준화, 중복 형식 통일
        |
        v
[2. 후보군 차단 (Blocking / Indexing)]
   - 유사한 우편번호, 성씨로 블록 묶어 비교 대상 축소
        |
        v
[3. 중복 판정 (Match Rule)]
   - 결정론적 룰 + 확률적 유사도
        |
        +---> [자동 병합 (Auto-Merge)]: 신뢰도 높음 → 단일 골든 레코드 생성
        |
        +---> [수동 검토 (Steward)]: 신뢰도 중간 → 데이터 스튜어드 승인
        |
        v
[4. 골든 레코드(Golden Record) 생성]
   - 생존 규칙(Survivorship Rule) 적용
        |
        v
[5. 원천 시스템 배포 및 동기화]
```

### 매칭 및 머징 핵심 메커니즘

```text
[ 매칭 엔진 처리 과정 ]
Blocking : 수백만 건 전체를 O(n^2) 비교할 수 없으므로, 유사한 우편번호나 성씨 등으로 블록을 묶어 비교 대상 축소
    |
    v
확률적 매칭 : 자로-윙클러(Jaro-Winkler), 레벤슈타인 거리를 적용하여 오타나 축약어를 동일 개체로 인식
    |
    v
생존 규칙 : 서로 다른 시스템의 컬럼 값이 충돌할 때 어떤 시스템의 값을 최종 채택할 것인가 결정
```

## Ⅳ. 4대 MDM 아키텍처 모델와의 비교

- 핵심 요약 : 4대 아키텍처는 원천 시스템 변경 수준과 중앙 허브의 통제력에 따라 구분되며, 각각 상이한 장단점과 적용 환경을 가지는 구현 체계

| 구현 모델 | 동작 방식 및 메커니즘 | 장점 | 트레이드오프 및 한계 |
| :--- | :--- | :--- | :--- |
| Registry(등록 모델) | 원천 시스템의 데이터는 그대로 두고, 중앙 허브에는 글로벌 식별자 매핑 인덱스만 유지 | 레거시 시스템 변경 불필요, 가장 빠르고 저비용 구축 | 원천 데이터의 실시간 불일치 정제 불가, 조회 시 분산 쿼리 필요 |
| Consolidation(통합 모델) | 원천 시스템에서 데이터를 일괄 수집하여 중앙 허브에서 중복 제거 및 단일 뷰 생성 | 분석 및 BI(Business Intelligence) 대시보드 관점에서 완벽한 전사 단일 뷰 제공 | 운영 시스템으로 역방향 동기화가 되지 않아 운영 단 불일치 잔존 |
| Coexistence(공존 모델) | 중앙 허브에서 골든 레코드를 생성·관리하고, 변경 사항을 원천 시스템들로 실시간 비동기 동기화 | 운영과 분석 데이터가 모두 최신 정합성 유지 | 분산 시스템 간 양방향 동기화 및 충돌 해결 복잡도 극상 |
| Transaction(중앙 트랜잭션) | 모든 마스터 데이터의 등록/수정/삭제를 오직 중앙 MDM 시스템에서만 수행하고 원천으로 단방향 배포 | 중앙 쓰기 통제로 정합성·거버넌스 관리 강화 | 레거시 시스템 전면 개편 필요, 초기 도입 비용 및 기간 막대 |

## Ⅴ. 마스터 데이터 관리(MDM)의 장점과 한계

- 핵심 요약 : 전사 데이터 일관성과 단일 뷰를 제공하나, 이종 시스템 간 매칭 난제와 조직 거버넌스 부재, 동기화 지연 문제가 존재하는 관리 체계

### 장점
1. 전사 단일 뷰 제공 : 부서별로 분산된 마스터 데이터를 통합하여 신뢰할 수 있는 단일 진실 공급원(SSOT)을 제공하는 체계

2. 데이터 품질 향상 : 중복 제거, 표준화, 유일성 검증을 통해 데이터의 정확성과 일관성을 극대화하는 체계

3. 의사결정 신뢰성 강화 : 정확한 기준 데이터를 기반으로 경영 분석과 의사결정의 신뢰성을 보장하는 체계

4. 규제 대응 체계 : 데이터 출처와 변경 이력을 추적하여 규제 감사와 컴플라이언스 요구사항을 충족하는 체계

### 한계점 및 해결 방안

- 이종 레거시 시스템 간 데이터 식별자 및 속성 충돌(Matching & Merging 난제)
  - 한계점 : 전사 시스템별로 상이한 고객/상품 코드 체계와 불완전한 속성값으로 인해 중복 판정(False Positive/Negative) 오류 및 골든 레코드(Golden Record) 왜곡이 발생하는 체계
  - 해결 방안 : 결정론적(Deterministic) 매칭과 확률적(Probabilistic) 매칭(Fellegi-Sunter 알고리즘) 하이브리드 적용, 수동 개입용 스튜어드십(Data Stewardship) 포털 구축

- 중앙 집중식 MDM 허브의 동기화 지연 및 단일 장애점(SPOF: Single Point of Failure)
  - 한계점 : 전사 시스템 간 실시간 동기화 시 네트워크 트래픽 부하 및 트랜잭션 지연 발생, 허브 장애 시 전사 업무 마비가 발생하는 체계
  - 해결 방안 : 중앙 허브와 로컬 캐시를 결합한 하이브리드 MDM 아키텍처 구성, 카프카(Kafka) 기반 실시간 이벤트 발행/구독(Pub/Sub) 비동기 전파 체계 구축

- 현업 부서 간 데이터 소유권(Data Ownership) 갈등 및 거버넌스 부재
  - 한계점 : 부서별 고유 이익에 따라 마스터 데이터 변경 권한과 표준화 규칙을 양보하지 않아 시스템 구축 후 데이터 정화 및 현행화가 방치되는 체계
  - 해결 방안 : C-Level 스폰서십 기반 데이터 거버넌스 위원회 설치, 부서별 데이터 스튜어드(Data Steward) R&R(Roles and Responsibilities) 명문화 및 KPI(Key Performance Indicator) 연계

## Ⅵ. 마스터 데이터 관리(MDM)에 대한 기술사적 제언

- 핵심 요언 : 조직 거버넌스 선행, 점진적 영역 확장, 데이터 스튜어드십 체계 구축을 통해 성공적인 전사 MDM 구축 체계를 완성할 필요

1. 기술 도입 전 조직 거버넌스(Data Governance) 선행 : MDM의 실패 원인 대부분은 기술이 아니라 부서 간의 이기주의와 표준 불일치이므로, 어떤 부서의 고객 코드를 마스터로 삼을지 조정할 수 있는 전사 데이터 거버넌스 위원회의 강력한 권한 부여가 최우선 전제 조건

2. 점진적(Phased) 영역 확장 전략 : 전사 모든 엔티티를 한 번에 MDM으로 통합하려는 빅뱅 방식은 실패 위험이 매우 크므로, 비즈니스 파급 효과가 가장 크고 중복이 극심한 고객 마스터(Customer MDM) 영역을 1단계로 선구축하여 성과를 입증한 후 상품, 계정 등으로 단계적 확대할 필요

3. 데이터 스튜어드십(Data Stewardship) 체계 구축 : 현업 부서별 데이터 스튜어드를 지정하고, 매칭 규칙과 생존 규칙(Survivorship Rule)을 지속적으로 개선하는 피드백 루프 체계 수립 필요

## Ⅶ. 결론

- 핵심 요약 : MDM은 전사 데이터 일관성과 단일 진실 공급원을 보장하는 핵심 관리 체계이나, 조직 거버넌스와 점진적 접근 없이는 성공하기 어려운 통합 체계

- 요약 : 마스터 데이터 관리는 고객, 상품, 공급업체 등 핵심 비즈니스 엔티티의 기준 데이터를 전사적으로 단일화하고 생명주기를 통제하는 프로세스, 정책, 기술 아키텍처의 통합 체계

- 시사점 : 디지털 전환 시대에 데이터 기반 의사결정이 중요해지면서 MDM은 선택이 아닌 필수 인프라로 자리잡았으며, 특히 AI(Artificial Intelligence) 모델의 학습 데이터 품질을 결정하는 핵심 체계로 그 중요성이 지속적으로 확대되는 추세
