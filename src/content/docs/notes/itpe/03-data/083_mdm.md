## 답안 골격
```text
[MDM (기준정보관리)] ◀━━ 머리: Ⅶ 내 의견 (중앙 집중형 고집 대신 이벤트 기반 CDC와 공존형 아키텍처로 현업 저항 최소화)
 ┃
 ┣━ Ⅰ 개요 ───── 기업 내 여러 시스템(ERP, CRM, SCM 등)에 분산된 핵심 기준 데이터(고객, 상품, 벤더 등)의 단일 신뢰 원천(SSOT)을 구축·관리하는 체계
 ┣━ Ⅱ 특징 ───── 단일 진실 공급원(SSOT) · 전사적 정합성 · 중복 제거(Deduplication) · 데이터 거버넌스 연계 · 골든 레코드(Golden Record) 생성
 ┣━ Ⅲ 구조 ───── 데이터 소스 계층 / MDM 허브 엔진(클렌징, 매칭/머징) / 골든 레코드 저장소 / 배포 및 연계 계층 / 거버넌스 포털
 ┣━ Ⅳ 흐름 ───── ① 원천 데이터 수집 → ② 데이터 프로파일링 및 표준화 → ③ 식별·매칭 규칙 적용 → ④ 머징 및 골든 레코드 생성 → ⑤ 원천 시스템 배포
 ┣━ Ⅴ 비교 ───── 레지스트리형 vs 통합형 vs 공존형 vs 트랜잭션형 (단순 매핑 색인 vs 다운스트림 분석용 vs 양방향 동기화 vs 허브 직접 생성)
 ┗━ Ⅵ 실무 ───── 시스템별 고객 코드 불일치 / 수동 병합 병목 / 부서 간 기준정보 관리 책임(Owner) 분쟁
```
- 필수 키워드: MDM · 마스터 데이터 · SSOT · 골든 레코드 · 클렌징 · 매칭 및 머징 · 거버넌스 · 배포 아키텍처
- 기출: 127회 `MDM(Master Data Management)의 필요성, 주요 구성요소 및 구축 유형 4가지를 설명하시오.` → Ⅰ 필요성 + Ⅲ 구성요소 + Ⅴ 4대 유형

## 한 줄 본질
- 시스템별 독자적 코드 발번으로 인한 데이터 사일로와 전사 정합성 왜곡 → 마스터 데이터를 수집·정제·매칭하여 유일한 골든 레코드를 생성하고 배포 → 단일 진실 공급원(SSOT) 확보 / 시스템 간 연계 복잡도 및 부서 간 주도권 갈등

## 핵심 그림
```text
[MDM 아키텍처 및 4대 구축 유형]

 ┌──────────┐ ┌──────────┐ ┌──────────┐
 │  ERP DB  │ │  CRM DB  │ │  SCM DB  │ (원천 시스템 계층)
 └────┬─────┘ └────┬─────┘ └────┬─────┘
      │ 수집       │ 수집       │ 수집
      ▼            ▼            ▼
 ┌─────────────────────────────────────────────────┐
 │                   MDM 허브 엔진                 │
 │  ┌──────────────┐ ┌──────────────┐ ┌──────────┐ │
 │  │ 표준화/클렌징│ │ 매칭/중복식별│ │ 머징 규칙│ │
 │  └──────────────┘ └──────────────┘ └──────────┘ │
 └────────────────────────┬────────────────────────┘
                          ▼
             ┌─────────────────────────┐
             │  골든 레코드 (SSOT)     │
             └────────────┬────────────┘
                          ▼ 배포 (API, CDC, 배치)
 ┌─────────────────────────────────────────────────┐
 │ 4대 구축 유형                                   │
 │ 1. Registry (참조형) : 허브는 ID 매핑 인덱스만 보유│
 │ 2. Consolidated(통합형): 원천→허브 일방향(분석용)│
 │ 3. Co-existence(공존형): 원천↔허브 양방향 동기화 │
 │ 4. Transaction (트랜잭션형): 허브에서 직접 생성/통제│
 └─────────────────────────────────────────────────┘
```

## 핵심 용어
- 골든 레코드(Golden Record): 여러 소스 시스템의 동일 엔티티 데이터 중 가장 신뢰도 높은 최신 속성값만을 병합(Merge)하여 만든 유일한 단일 마스터 레코드
- 매칭 및 머징(Matching & Merging): 서로 다른 식별자를 가진 복수의 레코드가 동일한 실체(Entity)인지를 유사도 알고리즘(Jaro-Winkler 등)으로 판별해 하나로 합치는 과정

## 핵심 통찰
- MDM 실패 원인의 80%는 기술이 아니라 '데이터 거버넌스와 부서 간 오너십 갈등'임 → 고객 정보의 주인이 영업부인지 마케팅부인지 정의하지 못하면 필드 우선순위 머징 규칙을 수립할 수 없음
- 처음부터 '트랜잭션형(중앙 집중 생성)'으로 가려 하면 기존 레거시 ERP/CRM의 업무 프로세스를 뜯어고쳐야 하므로 실패 확률이 극도로 높음
- 실무적으로 가장 안전한 경로는 '통합형(Consolidated)'으로 시작해 전사 골든 레코드 가시성을 먼저 확보한 뒤, '공존형(Co-existence)'으로 양방향 동기화 범위를 넓혀가는 단계적 진화임

## 이웃 토픽과 구분
- MDM vs DW(Data Warehouse): MDM = 현재 시점 기준 엔티티(고객, 상품)의 유일하고 정확한 정적 마스터 데이터 통제 / DW = 과거 이력을 포함한 대규모 트랜잭션 사실(Fact) 데이터의 분석 및 집계

## 문제·원인·대책
- 적용 상황: 글로벌 제조 그룹의 법인 간 통합 고객/공급망 관리
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 법인마다 동일 협력사에 코드를 다르게 발번해 전사 총 구매액 집계 불가 | 분산 ERP 체계에서 전사 기준정보 통합 통제 기제 부재 | 사업자등록번호 및 DUNS 번호 기반 매칭 엔진 연계 MDM 허브 구축 | 동일 협력사 자동 식별 및 글로벌 단가 통합 네고 달성 |
| 두 레코드 매칭 시 영업부 주소와 배송 주소 중 어떤 값을 골든 레코드에 넣을지 충돌 | 속성별 시스템 신뢰도(Trust Score) 규칙 미정의 | 속성별 시스템 우선순위 매트릭스 수립 및 미결 건 스튜어드 워크플로우 이관 | 데이터 정제 자동화율 95% 달성 및 예외 수기 승인 체계화 |

## 이렇게 출제된다
- 제127회: "기업 내 데이터 품질과 일관성을 보장하기 위한 MDM(Master Data Management)의 필요성, 주요 아키텍처 구성요소 및 4대 구축 유형을 비교 설명하시오." → 요구 포인트: 데이터 사일로 한계 + MDM 정의 + 3대 핵심 프로세스(클렌징/매칭/머징) + 4대 아키텍처(Registry, Consolidated, Co-existence, Transaction) 비교

## 내 의견
- [빅뱅 방식의 허브 도입 지양] 마스터 데이터를 일괄 중앙 통제하려다 현업 시스템의 수정 비용과 발번 지연으로 프로젝트가 좌초되는 사례 다수 → 나라면: 초기에는 이벤트 스트리밍(Kafka + Debezium CDC) 기반의 공존형 모델을 채택하여 레거시 시스템의 프로세스 수정을 0으로 만들고, 허브에서 비동기로 이상 데이터를 감지하여 알림을 주는 모니터링 중심 거버넌스로 시작
