## 연관 키워드

마스터 데이터 관리(MDM), 골든 레코드, 데이터 거버넌스, 중복 제거, 매칭·머징, 생존 규칙, MDM 아키텍처

## Ⅰ. 마스터 데이터 관리의 개요

- 핵심 요약 : 고객·상품·공급자 같은 핵심 엔티티의 기준 데이터를 전사 차원에서 관리하는 정책·조직·기술 체계.
- 개념 : **마스터 데이터 관리** (MDM, Master Data Management)는 여러 시스템에 흩어진 핵심 기준 데이터를 하나의 기준으로 정의하고 통합해 배포하는 관리 체계.
- 배경 및 필요성 : 부서별 코드와 속성이 달라 같은 엔티티의 중복과 불일치가 생기면, 업무 연계와 분석 결과의 신뢰성이 떨어짐.
- 주요 목적 : 신뢰할 수 있는 기준 정보를 정의하고, 생성부터 변경과 배포까지의 책임과 품질을 관리.

## Ⅱ. 마스터 데이터 관리의 특징 및 장점

- 핵심 요약 : 식별, 표준화, 중복 통합, 생명주기 관리를 통해 시스템 간 기준 정보의 일관성을 높이는 구조.

1. 전사 표준 : 공통 정의, 코드, 품질 규칙을 마련 → 부서 간 용어와 코드 해석 차이를 줄임.
2. **골든 레코드** (Golden Record) : 여러 원천의 정보를 매칭·정제해 하나의 통합된 기준 레코드를 만듦 → 시스템마다 다른 값을 쓰는 문제를 줄임.
3. 계보와 책임 : 원천 시스템, 변경 이력, 데이터 스튜어드의 책임을 추적 → 변경 원인과 담당자를 명확히 함.

- MDM은 중앙 DB에 데이터를 복사하는 작업이 아니라, **데이터 거버넌스** (Data Governance)와 운영 프로세스를 포함하는 체계다.

## Ⅲ. 매칭·머징과 배포 흐름

- 핵심 요약 : 원천 수집에서 표준화, 매칭, 생존 규칙 적용을 거쳐 골든 레코드를 배포하는 흐름.
- **매칭·머징** (Matching·Merging) : 같은 엔티티를 가리키는 원천 레코드를 짝짓고(매칭), 하나로 병합하는(머징) 과정.
- **생존 규칙** (Survivorship Rules) : 병합할 때 필드별로 어느 원천의 값을 남길지 정하는 기준으로, 권위 원천, 최신성, 승인 상태 등을 근거로 함.

```text
[원천 시스템 데이터 수집]
          ↓
[형식·코드 표준화]
          ↓
[후보군 구성·중복 매칭]
          ↓
[생존 규칙·승인 적용]
          ↓
[골든 레코드·원천 ID 연결]
          ↓
[시스템 배포·변경 감시]
```

```text
[매칭 후보 쌍의 신뢰도 산출]
          ↓
  확인된 일치 → 병합 후보
  낮은 신뢰도 → 스튜어드 검토
```

- 자동 병합은 매칭 신뢰도, 업무 위험, 감사 요건에 따라 제한하고, 불확실한 사례는 스튜어드 검토로 보낸다.

## Ⅳ. MDM 아키텍처 비교

- 핵심 요약 : 원천 시스템의 통제 수준과 중앙 데이터의 반영 방식에 따라 구성 유형을 고르는 기준.
- **MDM 아키텍처** (MDM Architecture) : 원천 시스템과 중앙 저장소가 기준 데이터를 나누어 갖는 방식을 정한 구성 유형.

| 유형 | 중앙 저장 내용·흐름 | 장점 | 고려사항 |
| --- | --- | --- | --- |
| **Registry** | 식별자 연결과 참조 정보 중심 | 원천 데이터 변경을 줄임 | 원천 조회와 데이터 품질에 의존 |
| **Consolidation** | 원천 데이터를 모아 통합 뷰 구성 | 분석용 단일 뷰에 적합 | 기준값을 원천으로 되돌려 보내지 않을 수 있음 |
| **Coexistence** | 중앙과 원천 간 생성·변경을 동기화 | 운영과 분석을 함께 지원 가능 | 충돌 해결과 동기화의 복잡성 |
| **Centralized** (Transactional) | 중앙에서 기준 데이터 변경을 통제 | 변경과 승인을 통일된 방식으로 통제 | 조직과 응용 연계의 변화 비용 |

## Ⅴ. 마스터 데이터 관리의 한계와 방안

- 핵심 요약 : 원천 간 식별 불일치, 소유권 갈등, 동기화 실패를 데이터와 조직 양쪽에서 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 오매칭·미매칭 | 규칙이 부정확하면 다른 대상을 합치거나 같은 대상을 중복 등록 | 결정론적 규칙과 확률적 규칙을 결합, 임계치별 표본 검수 | 오매칭률 |
| 필드 값 충돌 | 원천마다 같은 필드 값이 달라 기준값 결정이 어려움 | 생존 규칙과 권위 원천 정의, 예외를 담당자에게 배정 | 예외 처리 건수 |
| 현업 소유권 갈등 | 부서 간 변경 권한을 두고 다투어 정합성 저하 | 데이터 오너·스튜어드와 변경 승인 절차 명확화 | 승인 대기 시간 |
| 동기화 지연·장애 | 배포가 실패하면 원천과 중앙의 값이 어긋남 | 재처리·멱등성·대사 절차를 포함한 배포 방식 설계 | 불일치 건수, 반영 지연 시간 |

```text
중복·오매칭 → 규칙·표본 검수
값 충돌     → 권위 원천·승인
동기화 실패 → 재처리·대사
```

## Ⅵ. 마스터 데이터 관리에 대한 기술사적 제언

- 핵심 요약 : 거버넌스와 데이터 품질 책임을 먼저 정하고, 핵심 도메인부터 단계적으로 확장하는 도입 원칙.
- 고객이나 상품처럼 우선 도메인을 골라 품질 기준, 식별자 체계, 변경 책임, 배포 대상을 현업과 합의하는 과정이 선행되어야 한다.
- 중복률, 매칭 정확도, 변경 반영 시간, 정정 요청 건수를 성과 지표로 두어 도입 효과를 측정하는 것이 바람직하다.
- 골든 레코드와 원천 시스템의 역할을 분명히 나누어, MDM 도입이 모든 거래를 중앙으로 모아야 한다는 전제를 두지 않는 설계가 현실적이다.

## Ⅶ. 결론

- 핵심 요약 : MDM은 전사 기준 데이터의 품질, 책임, 변경을 관리하는 거버넌스 체계이며, 기술과 조직을 함께 설계해야 하는 과제.
- 아키텍처 유형의 차이, 매칭과 생존 규칙의 설계, 오매칭과 동기화 대응을 하나의 흐름으로 연결할 때 기준 정보의 일관성이 확보된다.
