## 연관 키워드

- MDM, 마스터 데이터, 골든레코드, 중복제거, 생존규칙, 데이터 거버넌스

## Ⅰ. 마스터 데이터 관리의 개요

- 핵심 요약 : MDM은 고객·제품·공급자 등 핵심 공유 엔터티의 식별·중복정리·표준화·배포를 조직적으로 관리하는 체계.
- 개념 : MDM은 고객·제품·공급자 등 핵심 공유 엔터티의 식별·중복정리·표준화·배포를 조직적으로 관리하는 체계.
- 배경 및 필요성 : 업무 시스템별 중복 식별자·속성 차이로 고객·제품의 단일한 관점과 정확한 연계가 어려움.
- 주요 목적 : 핵심 기준정보의 신뢰 가능한 식별·공유·변경관리.

## Ⅱ. 마스터 데이터 관리의 특징 및 장점

- 핵심 요약 : 식별·매칭: 레코드 중복 후보 연결 → 같은 실체 판별; 생존규칙: 충돌 속성의 신뢰 원천·우선순위 정의 → 골든레코드 생성; 배포·동기화: 소비 시스템에 변경 전달 → 업무 간 일관성 향상.

1. 식별·매칭: 레코드 중복 후보 연결 → 같은 실체 판별
2. 생존규칙: 충돌 속성의 신뢰 원천·우선순위 정의 → 골든레코드 생성
3. 배포·동기화: 소비 시스템에 변경 전달 → 업무 간 일관성 향상

## Ⅲ. 마스터 데이터 관리의 구조 (흐름)

- 핵심 요약 : 도메인·소유자 선정 → 식별자·매칭 규칙·원천 지정 → 정제·중복 병합·생존규칙 → 골든레코드 승인 → API·이벤트·배치 배포와 변경관리.

```text
도메인·소유자 선정
  ↓
식별자·매칭 규칙·원천 지정
  ↓
정제·중복 병합·생존규칙
  ↓
골든레코드 승인
  ↓
API·이벤트·배치 배포와 변경관리
```

- 핵심 구성 : 원천 레코드 → 매칭·중복판정 → 골든레코드 → 구독 시스템 배포 → 충돌·정정 피드백

```text
원천 레코드 → 매칭·중복판정 → 골든레코드 → 구독 시스템 배포 → 충돌·정정 피드백
```

## Ⅳ. 비교: MDM / 데이터 웨어하우스

- 핵심 요약 : 데이터 갱신 기준 — MDM: 운영계에 기준정보 배포·동기화; 데이터 웨어하우스: 분석 적재주기·과거 스냅샷.

| 비교 기준 | MDM | 데이터 웨어하우스 |
| --- | --- | --- |
| 목적 | 핵심 엔터티 원본·정체성 관리 | 분석용 이력 통합·질의 |
| 데이터 갱신 | 운영계에 기준정보 배포·동기화 | 분석 적재주기·과거 스냅샷 |
| 주요 결과 | 골든레코드·공유 식별자 | 차원·사실 데이터 |

## Ⅴ. 마스터 데이터 관리의 한계와 방안

- 핵심 요약 : 잘못된 병합·생존규칙 충돌 등 주요 위험을 원인에 맞는 통제로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 잘못된 병합 | 동명이인·유사 제품을 같은 실체로 결합 | 확률점수 임계치·사람 승인·분리 복구 | 오병합률 |
| 생존규칙 충돌 | 부서별 원천 신뢰·속성 우선순위 불일치 | 도메인 소유자 승인·속성별 출처 규칙 | 충돌 해결시간 |
| 배포 지연 | 골든레코드와 소비시스템 불일치 | API·이벤트 전달·재처리·정합성 대사 | 동기화 지연 |

## Ⅵ. 마스터 데이터 관리의 제언

- 핵심 요약 : 데이터 거버넌스위원회는 도메인별 소유자·골든레코드 권한·매칭 위험수준을 정의하고 변경 전파와 정정 이력 책임을 배정.
- 실행 제안 : 도메인 소유자는 매칭 임계치·속성별 신뢰 원천·골든레코드 정정권한을 승인하고 병합취소 경로 마련.

## Ⅶ. 마스터 데이터 관리의 결론

- 핵심 요약 : MDM은 중앙집중 DB 하나를 구축하는 일이 아니라 여러 시스템에서 핵심 실체의 정체성과 기준값을 일관되게 관리하는 운영모델.
- 시사점 : 골든레코드 신뢰는 자동매칭 정확도뿐 아니라 속성 출처·생존규칙·수정권한의 거버넌스에 의존.
