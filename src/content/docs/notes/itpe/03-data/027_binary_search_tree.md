## Ⅰ. 효율적 데이터 탐색을 위한 이진 탐색 트리(BST) 개요

### 가. 이진 탐색 트리(Binary Search Tree)의 정의
- 모든 노드가 최대 2개의 자식 노드를 가지는 **이진 트리** (Binary Tree) 구조에서, 모든 노드 $X$에 대해 왼쪽 서브트리의 모든 키값은 $X$보다 작고, 오른쪽 서브트리의 모든 키값은 $X$보다 크다 는 정렬 속성을 만족하는 계층형 자료구조.
- 정렬된 배열의 빠른 탐색 속도($O(\log n)$)와 연결 리스트의 빠른 삽입·삭제 장점을 결합하기 위해 고안됨.

### 나. 이진 탐색 트리의 핵심 연산 시간 복잡도
- **균형 상태(Balanced)** : 트리 높이 $h = \lfloor \log_2 n \rfloor$ 유지 시 탐색, 삽입, 삭제 모두 $O(\log n)$.
- **경사 상태(Skewed / 편향)** : 정렬된 데이터가 순차 삽입되어 한쪽으로 치우친 연결 리스트 형태가 될 경우 $O(n)$ 으로 퇴화.

## Ⅱ. 이진 탐색 트리의 연산 알고리즘 및 노드 삭제 메커니즘

### 가. 트리 순회(Traversal)와 정렬 속성
- **중위 순회(In-order Traversal: Left $\rightarrow$ Root $\rightarrow$ Right)** 수행 시, 트리에 저장된 모든 키값을 오름차순으로 정렬하여 정확히 획득 가능.

### 나. 노드 삭제(Delete)의 3가지 케이스

```text
[ BST 노드 삭제 3대 케이스 ]
Case 1: 자식이 없는 리프 노드   ---> 부모의 포인터를 NULL로 설정하고 메모리 해제
Case 2: 자식이 1개인 노드       ---> 삭제 노드의 자식을 자신의 부모 노드에 직접 연결
Case 3: 자식이 2개인 노드       ---> 오른쪽 서브트리의 최소값(Successor) 또는
                                     왼쪽 서브트리의 최대값(Predecessor)을 삭제 노드 위치로 복사 후 대체
```

```text
[ Case 3: 자식이 2개인 노드 삭제 예시 ]
       [50]                     [50]
      /    \                   /    \
   [30]    [70]   ===>      [40]    [70]   (Successor인 40으로 대체 후
   /  \    /  \             /       /  \    원래 40 노드 삭제)
 [20] [40] [60] [80]      [20]     [60] [80]
```

## Ⅲ. BST의 한계와 자가 균형 이진 탐색 트리(Self-Balancing BST)의 진화

### 가. 편향 트리 문제와 회전(Rotation) 메커니즘
- 편향(Degeneracy)을 방지하기 위해 삽입/삭제 시 트리의 균형 계수를 측정하고, 불균형 발생 시 **단일 회전** (LL, RR) 또는 **이중 회전** (LR, RL)을 수행하여 트리 높이를 $O(\log n)$으로 유지.

### 나. 자가 균형 BST 대표 알고리즘 비교

| 알고리즘 | 균형 조건 및 특성 | 장점 | 단점 및 실무 적용 |
| :--- | :--- | :--- | :--- |
| **AVL Tree** | 모든 노드에서 좌우 서브트리의 높이 차이(Balance Factor)가 $\le 1$ 유지 | 탐색 속도가 가장 빠름 (완전한 균형 보장) | 삽입/삭제 시 회전 연산이 빈번하여 쓰기 비용 큼 $\rightarrow$ 읽기 위주 룩업 테이블에 적합 |
| **Red-Black Tree** | 5가지 규칙(Root는 Black, No Double Red, Black-Height 동일 등) 유지 | 회전 수가 최대 2~3회로 제한되어 삽입/삭제 성능 우수 | AVL보다 높이가 약간 높아 탐색은 미세하게 느림 $\rightarrow$ C++ `std::map`, Java `TreeMap` 표준 |
| **Splay Tree** | 최근 접근한 노드를 회전을 통해 루트(Root)로 이동(Splaying) | 자주 참조되는 데이터 접근 속도 극대화(Locality) | 최악 시간 복잡도 $O(n)$ 발생 가능, 트리 형상이 동적 변동 |

## Ⅳ. 데이터베이스 및 시스템 소프트웨어 관점의 실무 제언

- 디스크 기반 저장소에서의 B-Tree 전환 : 메모리 기반 시스템에서는 캐시 친화적인 Red-Black Tree 등 자가 균형 BST가 효과적이나, 디스크 I/O가 개입하는 데이터베이스 인덱스에서는 블록(Page) 크기에 맞추어 하나의 노드가 수백 개의 자식을 갖는 다원 탐색 트리인 **B-Tree / B+Tree**로 확장해야 함.
- 동시성 환경에서의 로킹 오버헤드 완화 : 멀티스레드 환경에서 트리 노드를 갱신할 때 발생하는 락 경합을 방지하기 위해 락-프리(Lock-Free) Skip List 자료구조를 대안으로 검토할 것을 제언함.
