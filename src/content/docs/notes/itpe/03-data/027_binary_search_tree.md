## 연관 키워드

- 이진 탐색 트리(BST, Binary Search Tree), 정렬 속성, 중위 순회(In-order Traversal)
- 자가 균형(Self-Balancing), AVL 트리, Red-Black 트리, 회전(Rotation), Splay 트리
- B-Tree / B+Tree, 시간 복잡도 O(log n), 편향(Skewed) 트리, Skip List

## Ⅰ. 이진 탐색 트리의 개요

- 핵심 요약 : 정렬 속성을 이용해 탐색·삽입·삭제를 로그 시간에 수행하는 계층형 자료구조.
- 개념 : 각 노드가 최대 두 개의 자식을 가지는 이진 트리(Binary Tree)에서, 모든 노드의 왼쪽 서브트리 키는 그 노드보다 작고 오른쪽 서브트리 키는 그 노드보다 큰 정렬 속성을 만족하는 **이진 탐색 트리**(BST, Binary Search Tree).
- 배경 및 필요성 : 정렬 배열은 탐색이 빠르지만 삽입·삭제가 느리고, 연결 리스트는 그 반대다. 두 장점을 함께 얻으려는 요구에서 출발한다.
- 주요 목적 : 동적 집합에서 탐색, 삽입, 삭제 연산의 효율을 함께 확보하는 것.

## Ⅱ. 이진 탐색 트리의 특징

- 핵심 요약 : 정렬 속성과 중위 순회가 핵심이며, 시간 복잡도는 트리 균형 상태에 따라 달라진다.

1. 중위 순회 : 왼쪽, 루트, 오른쪽 순서로 방문하면 **중위 순회**(In-order Traversal) 결과가 키의 오름차순 → 정렬 데이터를 별도 정렬 없이 얻음.
2. 균형 상태 : 높이가 log n 수준으로 유지되면 탐색·삽입·삭제가 O(log n) → 대용량에서도 빠른 응답.
3. 편향 상태 : 정렬된 데이터를 순서대로 넣으면 한쪽으로 기운 연결 리스트 형태가 되어 O(n)으로 퇴화 → 균형 관리가 필수.
4. 삭제 분기 : 자식 수에 따라 리프, 자식 1개, 자식 2개의 세 경우로 나뉨 → 각 경우의 재연결 규칙을 따름.
5. **자가 균형**(Self-Balancing) 구조 : 삽입·삭제 때 회전(Rotation)으로 높이를 log n에 가깝게 유지 → 편향 문제 해결.

## Ⅲ. 이진 탐색 트리의 구조 (흐름)

- 핵심 요약 : 정렬 속성에 따른 탐색 경로와, 자식 수에 따른 삭제 3대 분기.

```text
[ 탐색 키 40 의 경로 ]
          [50]
        /      \
     [30]      [70]
     /   \     /   \
  [20]  [40] [60] [80]

50 : 40 < 50 이므로 왼쪽
30 : 40 > 30 이므로 오른쪽 → 40 발견
```

```text
[ 삭제 3대 경우 ]
Case 1 : 자식 없는 리프  → 부모 링크를 NULL로 바꾸고 해제
Case 2 : 자식 1개        → 그 자식을 부모에 직접 연결
Case 3 : 자식 2개        → 후속자(오른쪽 최소)나
                       선행자(왼쪽 최대)로 대체
```

- 중위 순회와 정렬 : 중위 순회로 얻은 키 순서가 곧 오름차순이므로, 정렬 속성이 유지되는지 점검하는 기준이 된다.

## Ⅳ. 자가 균형 BST 알고리즘의 비교

- 핵심 요약 : 균형을 얼마나 엄격히 유지하느냐에 따라 읽기 성능과 쓰기 비용이 상충하므로, 용도에 맞는 알고리즘을 고른다.

| 알고리즘 | 균형 조건 및 특성 | 장점 | 단점 및 실무 적용 |
| --- | --- | --- | --- |
| AVL 트리 | 모든 노드에서 좌우 서브트리 높이 차이 1 이하 유지 | 탐색 성능이 가장 안정적 | 삽입·삭제 때 회전이 잦아 쓰기 비용 증가, 읽기 중심 룩업에 적합 |
| Red-Black 트리 | 색상 규칙으로 루트부터 리프까지 검은 노드 수를 맞춤 | 회전 횟수가 적어 삽입·삭제에 강함 | AVL보다 높이가 커 탐색이 약간 느림, C++ std::map과 Java TreeMap의 표준 구현 |
| Splay 트리 | 접근한 노드를 회전으로 루트까지 올림(Splaying) | 최근 접근 데이터에 빠름(지역성) | 최악의 경우 O(n)이 될 수 있고 형태가 자주 바뀜 |

## Ⅴ. 이진 탐색 트리의 장점과 한계

- 핵심 요약 : 균형 유지 시 로그 시간 동적 연산이 장점이며, 편향 퇴화와 디스크 입출력, 동시성 경합이 한계.

- 장점
  1. 균형이 유지되면 탐색·삽입·삭제가 O(log n).
  2. 중위 순회로 정렬된 결과를 바로 얻음.
  3. 배열과 달리 크기를 동적으로 바꿀 수 있음.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 편향 퇴화 | 정렬 데이터의 순차 삽입으로 연결 리스트 형태가 되어 O(n) | 삽입·삭제 때 균형 계수를 점검하고 LL·RR 단일 회전, LR·RL 이중 회전 수행 | 트리 높이, 평균 탐색 깊이 |
| 디스크 기반 저장의 비효율 | 노드마다 디스크 블록을 읽어야 해서 입출력 비용이 큼 | 블록 크기에 맞춰 한 노드가 많은 자식을 가지는 B-Tree, B+Tree로 확장 | 페이지 읽기 횟수 |
| 동시성 환경의 락 경합 | 멀티스레드가 같은 노드를 갱신할 때 잠금 대기 발생 | 락 경합을 줄이는 Lock-Free Skip List 같은 구조 검토 | 잠금 대기 시간 |

## Ⅵ. 이진 탐색 트리에 대한 기술사적 제언

- 핵심 요약 : 저장 매체와 동시성 환경에 따라 자료구조를 달리 선택하는 것이 핵심.

메모리 기반 시스템에서는 자가 균형 이진 탐색 트리, 특히 Red-Black 트리처럼 삽입·삭제 비용이 낮은 구조가 적합하다. 디스크 기반 데이터베이스 인덱스는 블록 입출력을 줄이기 위해 B-Tree나 B+Tree를 쓰는 것이 기본이다. 여러 스레드가 같은 자료구조를 자주 갱신하는 환경에서는 락 경합을 줄이는 Skip List 계열을 함께 검토하는 편이 좋다.

## Ⅶ. 결론

- 핵심 요약 : 이진 탐색 트리는 정렬 기반 동적 탐색의 출발점이며, 균형 관리와 저장 매체 특성을 반영하는 것이 관건.
- 시사점 : 실무 인덱스는 B-Tree나 Skip List처럼 환경에 맞춘 변형 구조로 확장되는 것이 일반적임.
