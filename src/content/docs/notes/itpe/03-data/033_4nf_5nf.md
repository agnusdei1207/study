## 연관 키워드

- 제4정규형(4NF, Fourth Normal Form), 제5정규형(5NF, Fifth Normal Form), PJ/NF
- 다치 종속성(MVD, Multivalued Dependency), 조인 종속성(JD, Join Dependency)
- BCNF(Boyce-Codd Normal Form), 무손실 분해, 슈퍼키(Super Key), 가짜 튜플

## Ⅰ. 제4정규형·제5정규형의 개요

- 핵심 요약 : 함수적 종속성 이외의 다치 종속성과 조인 종속성을 제거하는 고차 정규화 이론.
- 개념 : **제4정규형** (4NF, Fourth Normal Form)은 **다치 종속성** (MVD, Multivalued Dependency)을 제거하고, **제5정규형** (5NF, Fifth Normal Form, PJ/NF)은 **조인 종속성** (JD, Join Dependency)을 제거하여 데이터 중복과 이상 현상을 없애는 정규형.
- 배경 및 필요성 : BCNF(Boyce-Codd Normal Form, 보이스-코드 정규형)를 만족해도 함수적 종속성(FD, Functional Dependency) 이외의 MVD와 JD가 남으면 불필요한 중복과 갱신 이상이 계속 발생.
- 주요 목적 : 고차 종속성을 제거하여 릴레이션의 데이터 무결성 확보.

## Ⅱ. 제4정규형·제5정규형의 특징 및 장점

- 핵심 요약 : MVD와 JD를 슈퍼키 조건과 무손실 분해로 다뤄 중복과 이상을 제거하는 원리.

1. 다치 종속성 (MVD) : X의 한 값에 대응하는 Y 값의 집합이 X에 의해서만 결정되고 나머지 속성 Z와 독립적일 때 성립(X ↠ Y 표기) → 독립된 다치 속성 조합의 중복을 분리해 저장량 절감.
2. 4NF 달성 조건 : 비사소한 MVD X ↠ Y가 있을 때 결정자 X가 **슈퍼키** (Super Key)여야 함 → 결정자 기준의 분해로 삽입·삭제 이상 방지.
3. 조인 종속성 (JD) : 릴레이션 R을 여러 프로젝션으로 분해한 뒤 자연 조인하면 원본이 **가짜 튜플** (Spurious Tuple) 없이 복원되는 **무손실 분해** 성질 → 분해 후에도 데이터 정합성 유지.
4. 5NF 판정 조건 : 모든 비사소한 JD에 대해 분해된 각 릴레이션이 R의 슈퍼키를 포함 → 3개 이상으로 분해해도 복원 보장을 판정.
5. **삼항 관계** (Ternary Relationship) 구조 : 2개 분해로는 원본을 복원할 수 없고 3개 이상을 동시에 분해해야 무손실이 성립 → 3자 간 복합 제약에서 생기는 중복 제거.

## Ⅲ. 제4정규형·제5정규형의 구조 (흐름)

- 핵심 요약 : 4NF는 독립된 다치 속성의 조합 중복을 두 프로젝션으로 나누고, 5NF는 3원 관계를 세 테이블로 동시에 나누는 구조.

```text
[ 4NF 위반: 개발자 스킬 ]
개발자    언어      자격증
김수석    Java      정보처리기사
김수석    Java      PMP
김수석    Python    정보처리기사
김수석    Python    PMP
   ↓ 무손실 분해
[개발자, 언어] + [개발자, 자격증]
```

```text
[ 5NF 분해: 공급자-부품-프로젝트 ]
(공급자, 부품, 프로젝트) 원본
   ↓ 3개 프로젝션으로 동시 분해
[공급자, 부품]
[부품, 프로젝트]
[공급자, 프로젝트]
   ↓ 자연 조인
원본 복원 (무손실)
```

- 4NF 위반의 문제점 : 김수석에게 새 언어 하나를 추가할 때 자격증 개수만큼 레코드를 삽입해야 하는 삽입 이상이 발생.
- 5NF 적용 대상 : 이진 관계로 나눠서는 원본을 복원할 수 없는 3원 관계로, 실제 업무에서는 드물게 나타남.

## Ⅳ. 제4정규형과 제5정규형의 비교

- 핵심 요약 : 제거 대상 종속성(MVD와 JD)과 필요한 분해 수가 두 정규형을 구분하는 기준.

| 비교 항목 | 제4정규형 (4NF) | 제5정규형 (5NF, PJ/NF) |
| :--- | :--- | :--- |
| 제거 대상 종속성 | 다치 종속성 (X ↠ Y) | 조인 종속성 (JD) |
| 달성 조건 | 비사소한 MVD의 결정자 X가 슈퍼키 | 모든 비사소한 JD에서 분해된 각 릴레이션이 R의 슈퍼키 포함 |
| 대표 위반 구조 | 독립된 다치 속성의 조합 중복 (개발자-언어-자격증) | 3원 관계의 복합 제약 (공급자-부품-프로젝트) |
| 필요 분해 수 | 2개 프로젝션 분해 | 3개 이상 프로젝션의 동시 분해 |
| 정규화 위계 | BCNF의 상위 확장 | 4NF의 상위 확장, 흔히 최종 정규형으로 일컬어짐 |

## Ⅴ. 제4정규형·제5정규형의 한계와 방안

- 핵심 요약 : 중복 제거와 이상 방지의 장점에 비해 종속성 식별, 분산 트랜잭션, 모델 이해도의 한계가 있어 통제가 필요.
- 장점 : 다치·조인 종속성에 기인한 중복을 완전히 제거하고 삽입·삭제·갱신 이상을 근원적으로 방지.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| 종속성 식별의 어려움 | MVD와 JD는 데이터 값으로 드러나지 않아 모델러의 주관에 의존하고 설계 오류 발생 | 함수 종속성 자동 검증 도구 활용, 독립된 이진 관계를 먼저 분해 | 정규화 검토 누락 건수 |
| 과도한 테이블 분할 | 3개 이상으로 나뉜 테이블에 한 번의 입력이 분산되어 트랜잭션과 조인 비용 증가 | 실무 기준을 BCNF 또는 3NF에 두고 뷰와 트리거로 제약 보완 | 조인 횟수, 쓰기 응답 시간 |
| 모델 파편화 | 파편화된 구조로 신규 인력이 데이터 흐름을 파악하기 어려워 생산성 저하와 결함 유발 | 정의서에 무손실 조인 관계를 명시, ORM(Object-Relational Mapping, 객체 관계 매핑)과 데이터 접근 계층으로 복잡도 추상화 | 신규 인력 적응 기간, 결함률 |

## Ⅵ. 제4정규형·제5정규형에 대한 기술사적 제언

- 핵심 요약 : 4NF와 5NF는 종속성이 실제로 확인된 도메인에 선별 적용하고, 일반 업무 모델은 BCNF와 3NF를 실무 표준으로 두는 방향.

1. 데이터 설계 조직은 업무 모델 전반을 BCNF 또는 3NF까지 정규화하는 것을 기본 표준으로 정하고, 4NF와 5NF는 MVD나 JD가 분석으로 확인된 도메인에만 적용해야 한다.
2. 모델러는 정규화 전에 종속성 분석 결과를 함수 종속성 검증 도구로 확인하고, 그 결과를 데이터 모델 정의서에 무손실 조인 관계와 함께 기록해야 한다.
3. 분할로 조인 비용이 과도해지는 특수 도메인에서는 관계형 데이터베이스 관리 시스템(RDBMS, Relational Database Management System)의 제약조건, 트리거, 애플리케이션 유효성 검증 계층으로 정합성을 보완하는 방안을 함께 검토해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 4NF와 5NF는 MVD와 JD를 제거하는 이론적 완결성을 갖추었으나, 실무에서는 종속성 특성에 따른 선별 적용이 타당함.
- 시사점 : 정규화 수준은 무결성과 조인 비용의 균형점에서 정해야 하므로, 고차 정규화는 종속성이 확인된 곳에서만 쓰는 것이 바람직함.
