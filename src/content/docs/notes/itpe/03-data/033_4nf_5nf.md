## 큰 그림과 30초 인출

```text
[BCNF 릴레이션 (모든 결정자가 후보키)]
        │ 함수적 종속성(FD) 기반 이상현상 제거 완료
        ▼
[다치 종속성 (MVD: A ↠ B | C) 식별]
        │ 독립적인 복수 다가 속성 공존 시 튜플 수 M × N 폭증
        ▼
[제4정규형 (4NF)] ─────── R1(A, B) 와 R2(A, C) 로 2개 분해
        │
        ▼ 순환적 3원 관계 및 조인 종속성 (JD: ⋈(R1, R2, R3)) 식별
[제5정규형 (5NF, PJ/NF)] ─── 2개로는 복원 불가, 3개 프로젝션으로 무손실 조인 분해
        │
        ▼ 궁극의 정규형 (후보키에 의한 조인 종속만 허용)
[실무 판단] ───────────── 조인 오버헤드로 인해 실무 3NF/BCNF 정착 후 제한 적용
```

- 본질: **함수적 종속성(FD)을 초과하여 발생하는 다치 종속(MVD)과 조인 종속(JD)을 제거함으로써, 튜플의 카테시안 곱 중복과 거짓 튜플(Spurious Tuple) 생성을 방지하는 고급 무손실 분해 정규형**
- 암기: `사-다 / 오-조` = 4NF는 다치 종속(MVD) 제거 / 5NF는 조인 종속(JD, PJ/NF) 제거
- 4NF 분해: $A \twoheadrightarrow B \mid C$ 일 때 $R_1(A, B)$와 $R_2(A, C)$의 2개 릴레이션으로 분해
- 5NF 분해: 2개 분해 시 정보 손실 발생, 3개 이상($R_1(A, B), R_2(B, C), R_3(A, C)$)으로 분해 후 자연 조인 시 원래 릴레이션 무손실 복원
- 주의: 정규화 수준이 높아질수록 조인 비용이 급증하므로, 실무에서는 OLTP 성능과 무결성 간의 트레이드오프 검토 필수

## 예상문제

> 관계형 데이터베이스 정규화 과정에서 제4정규형(4NF)과 제5정규형(5NF)의 개념을 다치 종속성(MVD) 및 조인 종속성(JD)과 연계하여 설명하고, 각각의 무손실 분해 절차 및 실무 적용 시 트레이드오프를 논하시오. (25점)

## Ⅰ. 함수적 종속성을 넘어선 데이터 무결성의 완성, 4NF·5NF 개요

- 정의: **4NF(제4정규형)**와 **5NF(제5정규형, PJ/NF)**는 BCNF(Boyce-Codd Normal Form)를 만족한 릴레이션에서 함수적 종속성(FD)으로 설명할 수 없는 다치 종속(MVD)과 조인 종속(JD)에 의한 데이터 중복 및 이상현상을 제거하는 고급 정규화 단계
- 목적: 독립적인 복수 다가 속성의 결합으로 인한 튜플 수 기하급수적 증가($M \times N$)를 방지하고, 다원 관계 분해 시 가짜 튜플(Spurious Tuple)이 생성되지 않는 무손실 조인 보장
- 필요성: BCNF를 만족하더라도 한 엔티티 내에 독립적인 다중값 관계가 공존하면 갱신 이상과 불필요한 저장 공간 낭비가 심각해지며, 3원 관계를 임의로 2개로 쪼갤 경우 데이터 왜곡이 발생함

#### 한줄 요약

- 4NF는 독립된 복수 다중값 속성 간의 튜플 곱을 없애고, 5NF는 3원 이상의 순환 관계를 손실 없이 쪼개는 궁극의 정규형임

## Ⅱ. 다치 종속(MVD)과 제4정규형(4NF) 메커니즘

```text
[다치 종속성 (Multivalued Dependency, A ↠ B)]
- 릴레이션 R(A, B, C)에서 A의 각 값에 대응되는 B의 값 집합이 C의 값과 독립적으로 결정되는 관계
- A ↠ B가 성립하면 반드시 대칭적으로 A ↠ C도 성립 (A ↠ B | C)
```

| 구분 | 비정규형 상태 (4NF 위배) | 4NF 정규화 후 (무손실 분해) |
|---|---|---|
| **릴레이션 구조** | `교수_정보 (교수ID, 담당과목, 취미)` | `교수_과목 (교수ID, 담당과목)`<br>`교수_취미 (교수ID, 취미)` |
| **속성 간 관계** | 교수ID $\twoheadrightarrow$ 담당과목, 교수ID $\twoheadrightarrow$ 취미 (서로 독립) | 두 개의 독립된 릴레이션으로 분리 ($R_1, R_2$) |
| **튜플 수 (예시)** | 교수 1명, 과목 3개, 취미 4개 $\rightarrow$ **12개 튜플** ($3 \times 4$) | $3 + 4 =$ **7개 튜플**로 데이터 용량 대폭 절감 |
| **이상 현상** | 취미 추가 시 해당 교수의 모든 과목 수만큼 튜플 반복 삽입 | 해당 취미 테이블에 단 1개 튜플만 독립 삽입 |

```text
[4NF 정의 요건]
- 릴레이션 R이 BCNF를 만족하고
- R에 존재하는 모든 비사소한(Non-trivial) 다치 종속 A ↠ B에 대해 A가 R의 슈퍼키(Super Key)이어야 함
- (사소한 다치 종속: B ⊆ A 이거나 A ∪ B = R 인 경우)
```

#### 한줄 요약

- 4NF는 하나의 결정자에 둘 이상의 독립된 다가 속성이 종속될 때 이를 별도 테이블로 쪼개어 카테시안 튜플 곱을 제거함

## Ⅲ. 조인 종속(JD)과 제5정규형(5NF, PJ/NF) 메커니즘

```text
[조인 종속성 (Join Dependency, ⋈(R1, R2, ..., Rn))]
- 릴레이션 R이 자신의 프로젝션(부분집합) R1, R2, ..., Rn으로 무손실 분해되어,
  다시 자연 조인(Natural Join)했을 때 원래의 R과 완벽히 일치하게 복원되는 성질
- 4NF는 조인 종속의 특수한 경우(n=2)이며, 5NF는 n ≥ 3 인 일반적 조인 종속을 다룸
```

| 구분 | 5NF 위배 상태 (3원 관계 결합) | 5NF 분해 후 (투영-조인 정규형) |
|---|---|---|
| **릴레이션 구조** | `개발_프로젝트 (개발자, 프로젝트, 사용기술)` | `R1 (개발자, 프로젝트)`<br>`R2 (프로젝트, 사용기술)`<br>`R3 (개발자, 사용기술)` |
| **비즈니스 규칙** | (개발자-프로젝트 참여), (프로젝트-기술 채택), (개발자-기술 보유) 3개 규칙이 상호 순환 제약 | 3개 프로젝션으로 무손실 분해하여 규칙 독립 보장 |
| **2개 분해 시 오류** | 임의로 2개로 쪼개 조인 시 원래 없던 **가짜 튜플(Spurious Tuple)** 생성 | 3개 테이블을 동시에 자연 조인해야만 원본 100% 복원 |
| **정규화 요건** | 복합키 전체가 주식별자이나 내부 순환 조인 종속 존재 | 릴레이션에 성립하는 모든 조인 종속의 구성요소가 후보키를 만족 |

```text
[5NF 정의 요건: Projection-Join Normal Form]
- 릴레이션 R이 4NF를 만족하고
- R에 존재하는 모든 비사소한 조인 종속 ⋈(R1, R2, ..., Rn)에 대해
  모든 R_i가 R의 후보키(Candidate Key)를 포함해야 함
```

#### 한줄 요약

- 5NF는 3개 이상의 속성이 얽힌 순환 종속 관계를 정보 손실이나 가짜 튜플 없이 3개 이상의 테이블로 분해하는 궁극의 정규형임

## Ⅳ. 4NF 및 5NF 정규화 단계별 수행 절차

```text
① BCNF 달성 (모든 함수적 종속성의 결정자가 후보키)
               ↓
② 다치 종속성(MVD) 식별 및 검증 (A ↠ B | C)
               ↓
③ 4NF 무손실 분해: R1(A, B) 와 R2(A, C)로 분리
               ↓
④ 3원 이상 조인 종속성(JD) 검토 (2개 분해 불가능 여부 판정)
               ↓
⑤ 5NF 무손실 분해: R1(A, B), R2(B, C), R3(A, C) 3개 프로젝션 분해
```

| 단계 | 입력 및 분석 | 핵심 활동 | 판정 산출물 |
|---|---|---|---|
| **1. BCNF 검증** | 3차 정규형 릴레이션 | 후보키가 아닌 결정자 존재 여부 전수 검사 | BCNF 완료 릴레이션 |
| **2. 다치 종속 분해 (4NF)** | BCNF 릴레이션 | 서로 연관 없는 다중값 속성 쌍($A \twoheadrightarrow B, A \twoheadrightarrow C$) 도출 | 2개 독립 릴레이션 ($R_1, R_2$) |
| **3. 조인 종속 검증 (5NF)** | 3개 이상의 복합키 릴레이션 | $R_1 \bowtie R_2$ 결과와 원래 $R$ 대조 (가짜 튜플 발생 여부 검증) | 순환 조인 종속성 식별 보고서 |
| **4. 투영 조인 분해 (5NF)** | 3원 순환 관계 스키마 | Fagin의 정리에 따라 $N$개 프로젝션 서브 릴레이션 생성 | 5NF(PJ/NF) 논리 스키마 |

#### 한줄 요약

- 정규화는 3NF $\rightarrow$ BCNF(결정자 정제) $\rightarrow$ 4NF(독립 다치 분해) $\rightarrow$ 5NF(순환 조인 분해) 순서로 심화됨

## Ⅴ. 정규화 4단계 비교: 3NF vs BCNF vs 4NF vs 5NF

| 비교 항목 | 3NF (제3정규형) | BCNF (보이스-코드) | 4NF (제4정규형) | 5NF (제5정규형, PJ/NF) |
|---|---|---|---|---|
| **제거 대상 종속** | 이행적 함수 종속 ($A \rightarrow B \rightarrow C$) | 일반 속성의 주식별자 결정 ($X \rightarrow Y$) | 다치 종속성 ($A \twoheadrightarrow B \mid C$) | 순환 조인 종속성 ($\bowtie(R_1, ..., R_n)$) |
| **종속성 유형** | 함수적 종속성 (FD) | 함수적 종속성 (FD) | 다치 종속성 (MVD) | 조인 종속성 (JD) |
| **분해 차수** | 2개 릴레이션 분해 | 2개 릴레이션 분해 | 2개 릴레이션 분해 | **3개 이상 릴레이션 분해** |
| **발생 빈도** | 매우 흔함 (필수 적용) | 간혹 발생 (복합키 환경) | 복수 다가 속성 시 발생 | 매우 희귀 (특수 3원 관계) |
| **실무 채택률** | **100% (산업계 표준)** | **90% 이상 채택** | **선택적 제한 적용** | **이론적 이해 중심 (거의 미적용)** |

#### 한줄 요약

- 3NF/BCNF는 1:1 함수 관계를, 4NF는 1:N 독립 다치 관계를, 5NF는 N:M:K 순환 결합 관계의 무결성을 보장함

## Ⅵ. 고급 정규형(4NF/5NF) 실무 적용 시 한계 및 엔지니어링 대책

| 문제 상황 | 근본 원인 | 실무 대응 방안 | 기대 효과 |
|---|---|---|---|
| **SELECT 쿼리 시 5~6중 조인으로 성능 급락** | 4NF/5NF 과도 적용으로 엔티티가 지나치게 파편화 | **반정규화(Denormalization)**: 빈번 조회 업무는 3NF 수준 유지, 교차 테이블 머지 | 조인 I/O 비용 절감 |
| **애플리케이션 DML 트랜잭션 복잡도 폭증** | 1건의 업무 등록을 위해 3~4개 분해 테이블에 동시 INSERT 필요 | 트랜잭션 경계 설정 및 DB 트리거 대신 도메인 서비스 계층에서 원자성 보장 | 데이터 불일치 차단 |
| **가짜 튜플(Spurious Tuple) 발생으로 왜곡 데이터 조회** | 조인 종속성을 고려하지 않고 임의로 2개 테이블로 쪼갠 후 재조인 | 5NF 원칙에 입각하여 3개 프로젝션 테이블로 분해하거나, 분해하지 않고 단일 테이블 유지 | 데이터 정합성 100% 보존 |
| **복잡한 비즈니스 룰 관리 오버헤드** | 5NF 조인 종속성 제약은 DBMS 선언적 DDL로 표현 불가 | CHECK 제약조건 또는 애플리케이션 유효성 검증 로직으로 비즈니스 불변식 강제 | 시스템 유지보수성 확보 |

#### 한줄 요약

- 실무에서는 조인 성능 저하를 방지하기 위해 3NF/BCNF를 기본으로 하고, 튜플 곱이 발생하는 다치 종속에 한해 4NF를 선별 적용함

## Ⅶ. 무결성과 성능의 최적 균형점을 찾는 기술사적 제언

- **[이론적 정규화의 극단 추구 경계와 BCNF 골든룰]**: 5NF는 관계 대수의 수학적 완성형이지만, RDBMS 물리 엔진에서 다중 조인은 막대한 CPU와 버퍼 캐시를 소모하므로 교조적 적용은 시스템 파탄을 부름
- 나라면:
  1. 엔터프라이즈 데이터 모델링 표준을 **BCNF 수준으로 확립**하되, '고객-보유쿠폰-관심사'처럼 독립적 다가 속성이 결합되어 카테시안 곱 튜플이 급증하는 경우에 한해 **4NF 교차 엔티티로 분리**
  2. 5NF 영역의 복잡한 3원 순환 제약은 무리한 테이블 분해 대신 단일 릴레이션에 복합 고유키(Composite Unique Key)와 애플리케이션 도메인 검증 로직을 결합하는 '실용적 정규화 전략'을 채택

#### 한줄 요약

- 정규화의 목적은 학술적 완벽성이 아니라 데이터 중복 최소화와 쿼리 성능 간의 실무적 최적 균형을 달성하는 것임

## 1교시 10점 답안 발췌

### 1. 4NF와 5NF의 정의

- **4NF(제4정규형)**: BCNF를 만족하며, 비사소한 다치 종속(MVD) $A \twoheadrightarrow B$가 존재할 때 $A$가 슈퍼키인 정규형 (독립 다치 속성의 2개 분해)
- **5NF(제5정규형, PJ/NF)**: 4NF를 만족하며, 모든 비사소한 조인 종속(JD)의 투영 릴레이션들이 후보키를 포함하는 정규형 (3원 순환 관계의 3개 무손실 분해)

### 2. 핵심 분해 메커니즘

```text
[4NF: 다치 종속(MVD) 해소]
R(교수, 과목, 취미) ──▶ R1(교수, 과목)  +  R2(교수, 취미)
(튜플 수: M × N ──▶ M + N 축소)

[5NF: 조인 종속(JD) 해소]
R(개발자, 프로젝트, 기술) ──▶ R1(개발자, 프로젝트) + R2(프로젝트, 기술) + R3(개발자, 기술)
(2개 분해 시 가짜 튜플 발생 ──▶ 3개 프로젝션으로 무손실 조인 복원)
```

| 구분 | 4NF (제4정규형) | 5NF (제5정규형, PJ/NF) |
|---|---|---|
| 제거 종속 | 다치 종속성 (MVD: $A \twoheadrightarrow B \mid C$) | 순환 조인 종속성 (JD: $\bowtie(R_1, R_2, R_3)$) |
| 분해 결과 | 2개의 서브 릴레이션 | 3개 이상의 프로젝션 릴레이션 |
| 실무 원칙 | 독립 다치 튜플 곱 발생 시 선별 적용 | 다중 조인 부하로 인해 실무에서는 제한 적용 |

### 3. 차별화 제언

- 조인 오버헤드를 통제하기 위해 **BCNF를 표준 목표**로 삼고, MVD 발생 시에만 4NF 분해를 수행하며, 5NF는 애플리케이션 제약조건으로 보완하는 실용적 아키텍처를 권고함

## 학습 체크

- [ ] 다치 종속(MVD)의 정의($A \twoheadrightarrow B$)와 대칭적 성질($A \twoheadrightarrow C$)을 설명할 수 있는가
- [ ] 4NF를 위배할 때 튜플 수가 $M \times N$으로 폭증하는 원리와 2개 분해 과정을 서술할 수 있는가
- [ ] 5NF(PJ/NF)에서 2개 분해 시 가짜 튜플(Spurious Tuple)이 발생하는 이유와 3개 분해 원리를 아는가
- [ ] 3NF, BCNF, 4NF, 5NF의 제거 대상 종속성 및 실무 채택 차이를 비교표로 작성할 수 있는가
- [ ] Ⅶ 결론에서 무결성과 다중 조인 성능 간의 트레이드오프 전략을 제시할 수 있는가
