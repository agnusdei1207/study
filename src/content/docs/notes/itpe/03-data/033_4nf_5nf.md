## 연관 키워드

- 제4정규형(4NF, Fourth Normal Form), 제5정규형(5NF, Fifth Normal Form)
- 다치 종속성(MVD, Multivalued Dependency), 조인 종속성(JD, Join Dependency)
- BCNF(Boyce-Codd Normal Form), 무손실 분해, 슈퍼키(Super Key)

## Ⅰ. 제4정규형·제5정규형의 개요

- 핵심 요약 : 함수적 종속성 이외의 다치·조인 종속성 제거를 위한 고차 정규화 이론.
- 개념 : 제4정규형(4NF, Fourth Normal Form)은 다치 종속성(MVD, Multivalued Dependency)을 제거하고, 제5정규형(5NF, Fifth Normal Form, PJNF(Projection-Join Normal Form))은 무손실 조인 종속성(JD, Join Dependency)을 제거하여 데이터 무결성을 달성하는 고차 정규화 이론.
- 배경 및 필요성 : 관계형 데이터 모델에서 BCNF(Boyce-Codd Normal Form, 보이스-코드 정규형) 달성 후에도 함수적 종속성(FD, Functional Dependency) 이외의 MVD·JD 잔존 시 불필요한 중복과 이상 현상 지속.
- 주요 목적 : 고차 종속성 제거를 통한 궁극적 데이터 무결성 확보.

## Ⅱ. 제4정규형·제5정규형의 특징

- 핵심 요약 : MVD·JD의 슈퍼키 조건 충족과 무손실 분해가 핵심 원리.

1. 다치 종속성(MVD) : $X$의 하나의 값에 대응하는 $Y$ 값 집합이 오직 $X$에 의해서만 결정되고 $Z$와 상호 독립일 때 성립, $X \twoheadrightarrow Y$ 표기.
2. 4NF 달성 조건 : 비사소한 다치 종속성 $X \twoheadrightarrow Y$ 성립 시 결정자 $X$의 릴레이션 $R$ 슈퍼키(Super Key) 요건 충족.
3. 조인 종속성(JD) : 릴레이션 $R$을 $n$개 프로젝션 $R_1, R_2, \dots, R_n$으로 분해 후 자연 조인 시 가짜 튜플(Spurious Tuple) 없이 완벽 복원, $JOIN(R_1, R_2, \dots, R_n) = R$.
4. 5NF 판정 조건 : 모든 비사소한 조인 종속성 $*(R_1, R_2, \dots, R_n)$에서 각 $R_i$가 $R$의 슈퍼키 포함.
5. 5NF 특유 구조 : 2개 분해로는 무손실 복원 불가, 3개 이상 동시 분해 시에만 가능한 삼항 관계(Ternary Relationship).

## Ⅲ. 제4정규형·제5정규형의 구조 (흐름)

- 핵심 요약 : MVD 중복 저장의 4NF 분해와 3원 관계의 5NF 3개 테이블 분해.

```text
[ 4NF 위반 릴레이션: 개발자스킬 (복합키: 개발자+프로그래밍언어+보유자격증) ]
  개발자   | 프로그래밍언어 | 보유자격증
  --------+----------------+------------
  김수석   | Java           | 정보처리기사
  김수석   | Java           | PMP
  김수석   | Python         | 정보처리기사  <-- 언어와 자격증 간 무관에도
  김수석   | Python         | PMP          <-- 모든 조합의 중복 저장 (MVD 발생)

  분해 결과 : [개발자, 프로그래밍언어] + [개발자, 보유자격증] 무손실 분해
```

```text
[ 3개 테이블 분해 예시: 공급자-부품-프로젝트 ]
원본: (공급자, 부품, 프로젝트) -> 3자 간 복합 순환 제약 존재
  ===> [공급자, 부품] JOIN [부품, 프로젝트] JOIN [공급자, 프로젝트]
```

- 4NF 위반의 문제점 : 개발자의 새 언어 1개 추가 시 자격증 개수만큼 $N$개 레코드 삽입의 삽입 이상 발생.
- 5NF 적용 대상 : 이진 관계로의 분해만으로 복원 불가, 3개 이상 동시 분해가 필요한 특수 삼항 관계.

## Ⅳ. 제4정규형과 제5정규형의 비교

- 핵심 요약 : 제거 대상 종속성(MVD vs JD)과 필요 분해 수의 차이.

| 비교 항목 | 제4정규형(4NF) | 제5정규형(5NF, PJNF) |
| :--- | :--- | :--- |
| 제거 대상 종속성 | 다치 종속성(MVD, $X \twoheadrightarrow Y$) | 조인 종속성(JD, $*(R_1, R_2, \dots, R_n)$) |
| 달성 조건 | 비사소 MVD의 결정자 $X$가 슈퍼키 | 모든 비사소 JD의 $R_i$가 슈퍼키 포함 |
| 대표 위반 구조 | 2개 독립 다치 속성의 조합 중복 저장(개발자-언어-자격증) | 3원 관계의 복합 순환 제약(공급자-부품-프로젝트) |
| 필요 분해 수 | 2개 프로젝션의 무손실 분해 | 3개 이상 프로젝션의 동시 분해 |
| 정규화 위계 | BCNF의 확장 | 4NF의 확장(이론상 최고 수준 정규형) |

## Ⅴ. 제4정규형·제5정규형의 장점과 한계

- 핵심 요약 : 중복 완전 제거·이상 방지의 장점과 식별 복잡도·성능·이해도 한계.
- 장점
  1. 다치·조인 종속성 기반 중복의 완전 제거.
  2. 삽입·삭제·갱신 이상의 근원적 방지.
- 한계점 1 : MVD·JD 식별의 극단적 인지 복잡도
  - 한계점 : 삼원(Ternary) 이상 조인 종속성의 육안·단순 쿼리 기반 식별 불가, 모델러 주관 의존 시 설계 오류 빈발.
  - 해결 방안 : 정형 수학적 함수 종속성 자동 검증 도구 활용, 도메인 엔티티의 독립적 이진 관계(Binary Relationship) 선제 분해.
- 한계점 2 : 테이블 과다 분할의 쓰기 원자성·성능 비용
  - 한계점 : 3개 이상 투영 테이블 분해 시 단일 비즈니스 입력의 다중 테이블 분산 트랜잭션 및 복합 조인 오버헤드 폭증.
  - 해결 방안 : 실용적 절충(Pragmatic Trade-off) 원칙의 3NF/BCNF 수준 동결, 뷰(View)·트리거 기반 제약 보완.
- 한계점 3 : 모델 파편화에 따른 유지보수 인력 이해도 부족
  - 한계점 : 극도로 파편화된 모델 구조로 신규 개발자의 데이터 흐름 직관적 파악 곤란, 생산성 저하·결함 유발.
  - 해결 방안 : 데이터 모델 정의서의 무손실 조인 보증 다이어그램 명시, ORM(Object-Relational Mapping)/데이터 접근 계층(Repository) 기반 복잡도 추상화.

## Ⅵ. 제4정규형·제5정규형에 대한 기술사적 제언

- 핵심 요약 : 비용 대비 효익 평가와 3NF/BCNF 실무 표준, 특수 도메인의 제약 보완.
- 비용 대비 효익 평가 : 이론적 완벽 무결성 대비 테이블 수 폭증, 단일 조회의 3~4중 조인 전환에 따른 성능 저하 검토.
- 실무 권장 설계 가이드 : 엔터프라이즈 RDBMS(Relational Database Management System) 모델링의 BCNF 또는 3NF 달성 기본 표준화, MVD·JD 존재 특수 도메인의 복합 체크 제약조건·트리거·애플리케이션 유효성 검증 계층 방어.

## Ⅶ. 결론

- 핵심 요약 : 4NF·5NF는 이론적 완성이나 실무에서는 종속성 특성에 따른 선별 적용이 타당.
- 요약 : MVD는 4NF, JD는 5NF로 제거하되 무손실 분해의 대가(조인 비용·복잡도) 평가 필요.
- 시사점 : 정규화 수준의 결정은 이론적 완결성과 운영 효율성의 균형점에서 수행.
