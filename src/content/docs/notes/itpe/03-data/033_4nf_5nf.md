 ┃
 ┣━ Ⅰ 개요 ───── 함수적 종속성(FD)을 넘어서는 다치 종속(MVD) 및 조인 종속(JD) 제거를 위한 고급 정규형
 ┣━ Ⅱ 특징 ───── BCNF 만족 전제 · 다치 종속(4NF) 및 조인 종속(5NF) 해소 · 무손실 조인 분해
 ┣━ Ⅲ 구조 ───── 제4정규형(4NF: 비사소한 다치 종속 배제) / 제5정규형(5NF, PJ/NF: 모든 조인 종속이 후보키)
 ┣━ Ⅳ 흐름 ───── ① BCNF 달성 → ② 다치 종속($A \rightarrow\rightarrow B | C$) 식별 → ③ 독립 릴레이션 2개 분해(4NF) → ④ 순환 3원 관계 조인 종속 해소(5NF)

 ┗━ Ⅵ 실무 ───── 조인 연산 폭증으로 인한 OLTP 성능 저하 / 복잡한 비즈니스 룰 관리 오버헤드

## 한 줄 본질
- 하나의 테이블에 둘 이상의 독립적인 다중값 속성이 공존할 때 생기는 튜플 폭증과 비가역적 조인 왜곡 → 다치 종속과 조인 종속을 제거하여 릴레이션을 독립적으로 무손실 분해 → 중복 제거 및 무결성 완성 / 조인 비용 급증으로 실무 제한적 적용

## 핵심 그림
```text
[4NF 다치 종속(MVD)과 5NF 조인 종속(JD)의 분해 구조]

 [4NF: 다치 종속(MVD) 해소]
  [교수 - 과목 - 취미] (독립적인 다치 속성 공존 -> 튜플 곱 발생)
           │
           ▼ (4NF 무손실 분해: A->->B, A->->C)
  [교수 - 과목]  과  [교수 - 취미]  로 분리

 [5NF: 조인 종속(JD) 해소]
  [개발자 - 프로젝트 - 기술] (3개 속성 간 순환 종속 존재)
           │
           ▼ (5NF 3개 투영 분해)
  [개발자-프로젝트], [프로젝트-기술], [개발자-기술] 3개로 분해
```

## 핵심 용어
- 다치 종속성(MVD, Multivalued Dependency, $A \rightarrow\rightarrow B$): $A$의 값 하나에 대해 $B$의 값 집합이 결정되고, 그 집합이 나머지 다른 속성($C$)과 무관하게 독립적인 경우
- 조인 종속성(JD, Join Dependency): 릴레이션을 여러 개의 부분 릴레이션으로 분해했다가 다시 자연 조인했을 때 원래 릴레이션과 완벽히 일치하게 복원되는 성질($\Join(R_1, R_2, ..., R_n)$)

## 핵심 통찰
- 실무 데이터 모델링은 99% 3NF나 BCNF에서 멈춤 → 4NF와 5NF는 개념적으로는 완벽하지만, 테이블이 지나치게 쪼개져 실무 쿼리 작성 시 5~6개 테이블을 조인해야 하므로 성능이 파탄남
- 4NF를 위배하면 데이터 중복이 곱하기($M \times N$)로 폭증함 → 교수 1명이 3개 과목을 가르치고 취미가 4개라면, 무려 $3 \times 4 = 12$개의 행이 생겨야 하므로 반드시 두 테이블로 분해해야 함
- 5NF(PJ/NF)는 '더 이상 조인 손실 없이 쪼갤 수 없는 궁극의 정규형'임 → 2개로는 분해할 수 없지만 3개 이상의 릴레이션으로 쪼개야만 원래 데이터가 보존되는 특수한 3원 관계를 다룸

## 딸려 나오는 하위 토픽
| 하위 토픽 | 상위 구조 속 위치 | 한 줄 |
|---|---|---|
| 사소한 다치 종속(Trivial MVD) | 4NF 예외 조건 | $A \rightarrow\rightarrow B$에서 $B \subseteq A$이거나 $A \cup B = R$인 당연한 종속 |
| 투영-조인 정규형 (PJ/NF) | 5NF의 정식 명칭 | Projection-Join Normal Form으로 모든 조인 종속이 후보키를 통해서만 성립하는 상태 |

## 이웃 토픽과 구분
- 4NF vs 5NF: 4NF = 2개의 독립적인 다치 속성을 2개의 테이블로 무손실 분해 / 5NF = 3개 이상의 속성이 얽힌 순환 종속을 3개 이상의 테이블로 무손실 분해

## 문제·원인·대책
- 적용 상황: 개발자의 프로젝트 참여 및 사용 기술 스택 관리 테이블 설계
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 개발자의 프로젝트 추가 시 보유 기술 개수만큼 튜플을 중복 삽입해야 함 | 프로젝트와 기술 간에 독립적인 다치 종속($A \rightarrow\rightarrow B, A \rightarrow\rightarrow C$) 방치 | 제4정규형(4NF) 적용: (개발자, 프로젝트)와 (개발자, 기술)로 분해 | 튜플 수 $M \times N$에서 $M + N$으로 축소 |
| 3개 테이블 분해 후 조인 시 원래 없던 가짜 튜플(Spurious Tuple) 생성 | 조인 종속성을 무시한 자의적 2개 테이블 분해 | 제5정규형(5NF) 적용: 3개의 프로젝션 테이블로 분해하여 무손실 조인 보장 | 데이터 왜곡 없이 완벽한 복원 |

## 이렇게 출제된다
- 제136회 1교시 4번: "제4정규형" → 요구 포인트: Ⅰ 정의 + 다치 종속(MVD) 개념 + 분해 전후 스키마 예시
- 제124회 1교시 8번: "데이터베이스 제5정규형" → 요구 포인트: Ⅰ 정의 + 조인 종속(JD) 개념 + 3원 관계 분해 및 한계

## 내 의견
- [교과서적 고급 정규형 맹신의 경계] 실무에서 5NF까지 테이블을 쪼개놓아 DBA와 개발자가 조인 복잡도를 감당하지 못해 프로젝트가 지연되는 현상 발생 → 나라면: 논리 모델링에서는 BCNF를 표준 목표로 잡고, 다치 종속이 명확한 경우에 한해 4NF 교차 엔티티로 분해하되 5NF는 스토리지·성능 관점에서 엄격히 제한 적용
