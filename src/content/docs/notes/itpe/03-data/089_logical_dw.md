## 연관 키워드

- 논리적 데이터 웨어하우스(Logical DW), 데이터 가상화(Data Virtualization), 제자리 질의(Query-in-place)
- 쿼리 푸시다운(Query Pushdown), 물리적 DW, ETL, CDC, 하이브리드 LDW

## Ⅰ. 논리적 데이터 웨어하우스의 개요

- 핵심 요약 : 데이터를 옮기지 않고 가상화로 분산 저장소를 논리적으로 묶어 조회하는 분석 아키텍처.
- 개념 : 가트너(Gartner)가 제시한 **논리적 데이터 웨어하우스** (Logical Data Warehouse, LDW, **데이터 가상화**로 이종 저장소를 복사 없이 하나의 DW처럼 질의하는 아키텍처).
- 배경 및 필요성 : 물리적 DW는 전사 데이터를 **ETL** (Extract, Transform, Load, 추출·변환·적재) 방식으로 복사해야 해서 파이프라인 개발과 운영 비용이 크고 실시간 반영이 어려움 → 데이터 이동 없이 원천을 직접 조회할 민첩한 환경이 필요함.
- 주요 목적 : 데이터 복제 최소화, 실시간 분석 제공, 신규 요구에 대한 대응 속도 향상.

## Ⅱ. 논리적 데이터 웨어하우스의 특징 및 장점

- 핵심 요약 : 데이터를 옮기지 않는 제자리 질의와 원천의 실시간 접근이 복제 비용 절감과 빠른 대응으로 이어지는 구조.

1. **제자리 질의** (Query-in-place, 원천 시스템에서 직접 질의를 실행하는 방식) : 물리적 복사본이 없어 스토리지와 적재 파이프라인 비용 절감.
2. 실시간 데이터 접근 : 배치 적재 주기에 묶이지 않고 원천의 현재 데이터를 조회 → 의사결정 시점의 지연 감소.
3. 민첩한 변경 대응 : 신규 컬럼이나 테이블이 생겨도 ETL 재개발 없이 논리 뷰만 수정 → 요구 반영 기간 단축.
4. **통합 메타데이터 카탈로그** (이종 저장소의 스키마, 위치, 비즈니스 정의를 하나의 디렉터리로 관리) : 데이터 탐색과 해석의 일관성 확보.

## Ⅲ. 논리적 데이터 웨어하우스의 구조 (흐름)

- 핵심 요약 : 소비, 가상화, 분산 저장소의 3계층 구조에서 단일 SQL(Structured Query Language) 질의가 원천별로 분해되어 병합되는 흐름.
- **비용 기반 옵티마이저** (CBO, Cost-Based Optimizer) : 비용 추정으로 가장 효율적인 질의 실행 계획을 고르는 구성 요소.
- 기술 계층별 주요 요소는 아래 표와 같다.

```text
[ LDW 3계층 구조 ]

소비 계층
 (분석 도구, SQL 분석, 머신러닝 파이프라인)
      ↓ 단일 SQL 인터페이스
가상화·의미 계층
 (논리 뷰, 카탈로그, 쿼리 분해)
      ↓
분산 저장소 계층
 (관계형 DW, 데이터 레이크, 스트림)
```

```text
[ 질의 실행 흐름 ]

사용자 SQL 질의
      ↓
가상화 엔진 (분해·계획 수립)
      ↓
원천별 하위 질의 실행
      ↓
인메모리 결과 병합
      ↓
통합 결과 반환
```

| 기술 계층 | 주요 기술 요소 | 핵심 기능 및 역할 |
| :--- | :--- | :--- |
| 데이터 가상화 | Denodo, Dremio, Trino(Presto) | 물리적 이동 없이 원천 DB(Database)로 질의를 분기 실행하고 중간 결과를 메모리에서 병합 |
| **쿼리 푸시다운** (Query Pushdown) | CBO(Cost-Based Optimizer) 기반 분산 옵티마이저 | 필터와 집계를 원천 엔진에 밀어 넣어 네트워크 전송량 최소화 |
| 통합 메타데이터 카탈로그 | DataHub, Apache Atlas | 스키마, 위치, 비즈니스 정의를 단일 디렉터리로 관리 |
| 인메모리 캐싱 계층 | Apache Arrow, Redis | 자주 조회되는 뷰의 실행 결과를 캐싱해 반복 질의 응답 가속 |

## Ⅳ. 물리적 데이터 웨어하우스와의 비교

- 핵심 요약 : 물리적 DW는 안정성과 성능, 논리적 DW는 실시간성과 민첩성에서 우위를 가지는 상보적 관계.
- 선택 기준 : 정합성과 고속 집계가 중요하면 물리적 DW, 실시간 조회와 빠른 변경 대응이 중요하면 논리적 DW를 우선 검토.

| 비교 항목 | 전통적 물리적 DW | 논리적 DW |
| :--- | :--- | :--- |
| 데이터 적재 | 배치 ETL로 중앙 저장소에 복사 적재 | 데이터 이동 없이 원천을 직접 질의 |
| 데이터 최신성 | 배치 주기에 따른 과거 시점 데이터 | 원천 시스템의 실시간 데이터 조회 |
| 신규 요구 대응 | ETL 재개발이 필요해 기간이 길어짐 | 논리 뷰 수정 중심으로 빠른 배포 |
| 원천 시스템 부하 | 배치 추출 시점에만 발생 | 가상화 조인이 운영 DB에 부하를 전가할 위험 |
| 데이터 일관성 | 단일 저장소로 관리 용이 | 원천 간 스키마 차이로 정합성 관리 필요 |

## Ⅴ. 논리적 데이터 웨어하우스의 장점과 한계

- 핵심 요약 : 실시간성과 민첩성이 우수하지만 원천 시스템 부하 전가와 쿼리 성능 오버헤드가 과제.

1. 데이터 이동 최소화 : ETL 파이프라인의 개발과 유지보수 비용 절감.
2. 실시간 분석 : 원천의 실시간 데이터에 직접 접근해 의사결정 속도 향상.
3. 민첩한 대응 체계 : 가상 뷰 수정만으로 신규 요구를 신속히 반영.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| :--- | :--- | :--- | :--- |
| 이종 소스 간 네트워크 I/O와 응답 지연 | 원천 간 전송량이 많아 응답이 느려짐 | 쿼리 푸시다운(필터와 집계를 원천 엔진에서 먼저 수행)의 극대화, 분산 가상화 캐시 구성 | 평균 응답 시간, 전송량 |
| 통합 시맨틱 뷰의 복잡성 | 원천 변경이 뷰에 즉시 반영되지 않아 메타데이터 불일치 발생 | **CDC** (Change Data Capture, 원천의 변경 데이터만 추출하는 기술) 기반 자동 동기화, 데이터 패브릭(Data Fabric) 기반 활성 메타데이터 연계 | 메타데이터 불일치 건수 |
| 분석 쿼리와 운영 쿼리의 자원 경합 | 분석 질의가 운영 트랜잭션 DB(OLTP, Online Transaction Processing)의 CPU와 I/O를 점유 | 운영 DB의 읽기 전용 복제본(Read Replica)을 가상화 질의 엔드포인트로 격리 | 운영 DB 응답 지연, 복제 지연 |

```text
[ LDW 성능 병목 지점 ]

가상화 엔진 부하  ← 복잡한 분산 조인 집중
네트워크 I/O     ← 원천 간 데이터 전송
원천 시스템 부하 ← 운영 DB에 분석 질의 전가
```

## Ⅵ. 논리적 데이터 웨어하우스에 대한 기술사적 제언

- 핵심 요약 : 운영 시스템 격리, 물리 적재와 가상화의 하이브리드 구성, CDC 기반 캐시 무효화가 성공적 구축의 핵심 조건.

1. 읽기 전용 복제본 연계 : 가상화 엔진이 운영 트랜잭션 DB에 무거운 조인을 직접 보내면 서비스 장애로 이어질 수 있으므로, 분석용 연결은 읽기 전용 복제본으로 격리하는 것이 기본 원칙으로 필요.
2. 하이브리드 구성 : 다차원 집계처럼 무거운 작업은 레이크하우스(Lakehouse)에 정형 마트를 미리 적재하고, 실시간성이 필요한 데이터만 가상화로 연합하는 구성 필요.
3. 캐시 무효화 체계 : 가상화 캐시가 원천 변경을 놓치지 않도록 변경 이벤트를 받아 해당 뷰 캐시를 즉시 무효화하는 체계 구현 필요.

## Ⅶ. 결론

- 핵심 요약 : 논리적 DW는 데이터를 복사하지 않고 실시간으로 통합 조회하는 아키텍처이며, 물리 DW를 대체하기보다 보완하는 위치에 있음.
- 시사점 : 원천 시스템 보호와 정합성 관리가 함께 뒷받침될 때 가상화의 민첩성이 실제 분석 가치로 이어짐.
