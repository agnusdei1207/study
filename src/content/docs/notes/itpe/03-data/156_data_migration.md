## 연관 키워드

- 데이터 마이그레이션, Data Migration
- 빅뱅 마이그레이션, 트리클 마이그레이션
- CDC(Change Data Capture), 스키마 매핑, 롤백
- 체크섬 검증, 멱등성, 하이퍼케어

## Ⅰ. 데이터 마이그레이션의 개요

- 핵심 요약 : 소스 시스템에서 타겟 시스템으로 데이터를 안전하고 완전하게 옮기는 **데이터 마이그레이션**(Data Migration)의 전 주기 엔지니어링 프로세스.
- 개념 : 레거시 시스템, 온프레미스 DB, 파일 시스템 등 소스에서 클라우드 DW, 신규 애플리케이션 DB, 데이터 레이크 등 타겟으로 스키마 변환, 정제, 검증을 동반하여 데이터를 이관하는 프로세스.
- 배경 및 필요성 : 클라우드 전환, 시스템 현대화, 기업 합병 통합, 규제 준수 요구에 따라 레거시를 벗어나 데이터 자산을 안전하게 이전할 필요.
- 주요 목적 : 데이터 손실 제로, 비즈니스 연속성 유지, 타겟 시스템에서의 데이터 품질 보장.

## Ⅱ. 데이터 마이그레이션의 특징 및 장점

- 핵심 요약 : 이관 방식 선택, CDC 기반 증분 동기화, 스키마 변환, 다층 검증, 롤백 계획이 결합된 마이그레이션 엔지니어링.

1. **빅뱅 마이그레이션**(Big Bang) 과 **트리클 마이그레이션**(Trickle) : 일괄 이관과 단계적 병행 이관, 그리고 그 혼합인 하이브리드 방식 중 선택.
2. **CDC**(Change Data Capture) 기반 증분 동기화 : 소스 변경분을 캡처하여 타겟에 반영 → 다운타임 최소화.
3. 스키마 매핑과 변환 : 데이터 타입, 코드 값, 계층 구조를 타겟 모델로 변환 → 논리와 물리 모델의 차이 해소.
4. 다층 데이터 검증 : 행 수, 체크섬, 샘플링, 비즈니스 룰 검증 → 이관 누락과 의미 불일치 조기 발견.
5. 롤백과 복구 계획 : 원상 복구 가능한 스냅샷과 백아웃 절차를 사전에 정의 → 실패 시 피해 범위 제한.

## Ⅲ. 데이터 마이그레이션의 구조 (흐름)

- 핵심 요약 : 평가에서 안정화까지 6단계로 이어지는 마이그레이션 생명주기와, CDC가 소스 변경을 타겟에 반영하는 증분 동기화 구조.

```text
[ 마이그레이션 생명주기 ]

1. 평가 : 소스·타겟 분석, 데이터 프로파일링
   ↓
2. 설계 : 이관 전략, 스키마 매핑, 검증 시나리오
   ↓
3. 구축 : ETL/ELT와 CDC 파이프라인 개발
   ↓
4. 검증 : 단위, 통합, 성능, 사용자 수용 테스트
   ↓
5. 전환 : 읽기 전용 전환, 최종 증분 동기화
   ↓
6. 안정화 : 하이퍼케어 기간 모니터링과 이슈 해결
```

```text
[ CDC 증분 동기화 구조 ]

소스 DB
   ↓  트랜잭션 로그 마이닝
CDC 커넥터 (Debezium 등)
   ↓
메시지 큐 (Kafka 등)
   ↓
스트림 처리 (스키마 변환, 정제, 보강)
   ↓
타겟 DB/DW : 멱등적 업서트(Upsert) 적용
```

## Ⅳ. 빅뱅 마이그레이션과 트리클 마이그레이션의 비교

- 핵심 요약 : 일괄 중단 방식과 단계적 병행 방식의 다운타임과 복잡도 트레이드오프.

| 비교 항목 | 빅뱅 마이그레이션 | 트리클 마이그레이션 |
| --- | --- | --- |
| 다운타임 | 장시간 중단 필요 | 최종 컷오버 시점에만 짧은 중단 |
| 복잡도 | 단일 이벤트로 상대적으로 단순 | CDC, 양방향 동기화, 충돌 해결로 복잡 |
| 리스크 | 실패 시 전면 롤백, 영향 범위 큼 | 단계별 검증과 부분 롤백 가능 |
| 자원 | 단기 집중 투입 | 장기 분산 투입, 병렬 운영 비용 발생 |
| 적합 상황 | 소규모, 다운타임 허용, 스키마 변경이 큰 경우 | 대규모, 상시 서비스, 무중단 요구 |

## Ⅴ. 데이터 마이그레이션의 한계와 방안

- 핵심 요약 : 데이터 손실과 불일치, 비즈니스 의미 차이, 숨은 의존성의 한계를 멱등 설계, 도메인 검증, 의존성 분석으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 데이터 손실과 불일치 | 대용량 이관 중 네트워크 장애, 타임아웃, 스키마 불일치로 행 유실과 중복 발생 | 멱등적 파이프라인 설계, 트랜잭션 경계 명확화, 행 단위 체크섬 검증, CDC 오프셋 관리 | 행 불일치율 |
| 비즈니스 로직 불일치 | 반올림, 코드 매핑 등 규칙 차이로 데이터는 옮겨졌으나 의미가 달라짐 | 도메인 전문가와 비즈니스 룰 매핑 문서화, 샘플링 기반 사용자 수용 테스트, 그림자 테이블 병렬 검증 | 검증 실패 건수 |
| 숨은 의존성 누락 | 문서화되지 않은 트리거, 저장 프로시저, 배치, 외부 인터페이스 | 정적 코드 분석, 런타임 추적, 의존성 매핑, 영향도 분석 | 미식별 의존성 건수 |

## Ⅵ. 데이터 마이그레이션에 대한 기술사적 제언

- 핵심 요약 : 빅뱅을 지양하고 CDC 기반 무중단 패턴을 표준으로 삼으며, 자동화된 검증 게이트와 전담 거버넌스 조직을 함께 두는 방향이 바람직함.
- 빅뱅 방식은 가능한 한 피하고, Debezium 같은 오픈소스 CDC 도구나 AWS DMS, Azure Database Migration Service 같은 클라우드 관리형 서비스를 활용한 트리클 또는 하이브리드 패턴을 전사 표준으로 정하는 것이 바람직하다.
- 행 수, 체크섬, 샘플링, 비즈니스 룰 검증을 파이프라인 단계별 게이트로 자동화하고 결과를 CI/CD 대시보드에 모아, 검증을 통과한 데이터만 운영 환경에 들어가도록 강제할 필요가 있다.
- 아키텍트, DBA, 도메인 전문가, QA로 구성된 마이그레이션 전담 조직을 평가부터 안정화까지 운영하고, 이슈 에스컬레이션과 롤백 판단 권한을 이 조직에 부여하는 것이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : 데이터 마이그레이션은 CDC 기반 증분 동기화와 다층 검증을 전제로 한 시스템 현대화의 핵심 관문.
- 성공의 조건은 이관 방식의 선택, 자동화된 검증, 롤백 기준의 사전 정의에 있으며, 이 세 가지를 프로젝트 초기에 확정해야 한다.
