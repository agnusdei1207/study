## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터 이관 → **데이터 이관(마이그레이션·정합성 검증)**

## 30초 인출

- 본질: 데이터 이관은 원천 데이터를 목표 시스템의 구조·규칙에 맞춰 옮기고 검증하는 활동
- 메커니즘: 계획·매핑 후 모의 이관으로 소요 시간과 롤백을 검증하고, 초기 적재와 변경분 동기화(CDC)로 옮긴 뒤 건수·집계·행 단위 값을 대사하고 승인 조건을 충족하면 쓰기 통제·최종 반영·접속 전환(컷오버)
- 통찰: 건수나 합계가 맞아도 상쇄되는 오류가 남고 초기 적재와 변경분의 기준 시점이 어긋나면 누락·중복이 생기므로, 스냅샷 시점과 로그 위치를 기록하고 핵심 키·값을 행 단위로 대사

<details>
<summary>핵심 용어</summary>

- **데이터 이관(Migration)** : 원천 데이터를 목표 시스템으로 옮기고 검증하는 활동
- **모의 이관** : 대표·예외 데이터로 리허설해 시간·병목·롤백을 검증하는 단계
- **CDC(Change Data Capture)** : 원천 변경분을 포착해 목표에 반영
- **컷오버(Cutover)** : 업무 접속을 목표 시스템으로 전환하는 시점
- **대사(Reconciliation)** : 원천과 목표의 건수·값을 비교해 일치를 확인
- **빅뱅·단계적·병렬 전환** : 일괄 / 업무 단위 순차 / 신구 동시 운영 전환

</details>

## 2~4교시 25점 답안

## Ⅰ. 데이터 이관의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터 이관** 은 원천 데이터를 목표 시스템의 구조·규칙에 맞춰 옮기고 검증하는 활동 |
| 목적 | 데이터 의미와 업무 연속성을 유지하며 안전하게 전환 |

## Ⅱ. 특징

| 특징 | 관리 의미 |
|---|---|
| 원천·목표 매핑 | 자료형·코드·업무 규칙의 변환 정의 |
| 시점 동기화 | 초기 적재와 이후 변경분의 기준점 연결 |
| 승인된 전환 | 정합성·시간·복귀 조건을 검증한 뒤 컷오버 |

## Ⅲ. 추진 단계와 컷오버

```text
계획·매핑 → 모의 이관 → 초기 적재 + CDC → 건수·값·규칙 대사 → 승인 조건 충족?
                                                    ├ 예 → 컷오버
                                                    └ 아니오 → 현행 유지·재시험
```

```text
원천 시점 S의 스냅샷 → 목표 초기 적재
S 이후 변경 로그 위치 → CDC → 목표 변경분 반영 → 지연·누락·중복 대사 후 절체
```

| 단계 | 핵심 활동 | 산출물 |
|---|---|---|
| 1. 이관 계획 | 원천 프로파일링, 범위·보관 정책·전환 창·복구 기준 | 이관 계획서, WBS, 역할 분담 |
| 2. 이관 설계 | 항목·변환 규칙 매핑, 코드·키·제약·검증 기준 | 매핑 정의서, 정제·대사 규칙서 |
| 3. 이관 개발 | 추출·변환·적재, 오류 재처리 | 이관 프로그램, 예외 로그 |
| 4. 모의 이관 | 대표·예외 데이터 리허설, 시간 실측, 병목 조정, 롤백 훈련 | 결과 보고서, 조치 내역, 튜닝서 |
| 5. 본 이관 | 초기 적재·CDC → 쓰기 통제 → 최종 반영 → 대사 → 승인 → 전환 | 이관 결과서, 대사 보고서, 전환 승인서 |

## Ⅳ. 전환 방식과 정합성 검증

| 비교 | 빅뱅 | 단계적 | 병렬 운영 |
|---|---|---|---|
| 전환 | 단일 컷오버 기간에 일괄 | 업무·지점 단위 순차 | 신구 시스템 동시 운영·비교 |
| 다운타임 | 전환 창에 집중 | 단계별 전환 창 | 최종 전환 창 필요 가능 |
| 위험 | 한 번의 실패가 전체 영향 | 신구 연계·정합성 관리 | 이중 운영·결과 불일치 처리 |
| 비용 | 일회성 집중 | 임시 연계·반복 전환 | 중복 인프라·검증 |
| 적합 | 업무 결합 높고 전환 창 확보 | 업무 경계 명확 | 병렬 결과 대조 중요 |

| 검증 계층 | 기법 | 한계 |
|---|---|---|
| 건수 대사 | 전체·조건별 COUNT | 누락·중복이 상쇄될 수 있어 단독 판정 불가 |
| 업무 집계 대사 | 금액·수량 합계 | 상쇄되는 개별 값 오류를 놓침 |
| 키·값 대사 | 정규화한 행의 키·값 비교 또는 해시 | 자료형·NULL·정렬·해시 충돌 고려 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 초기 적재와 변경분의 기준 시점 불일치로 누락·중복 | 스냅샷 시점·로그 위치를 기록하고 재처리·대사·롤백 포함 절체 검증 |
| 건수·합계는 맞아도 개별 행 값 오류 | 핵심 키·값의 행 단위 대사와 업무 규칙 검증 추가 |
| 병렬 운영에서 신구 결과 차이 미해결 | 불일치 처리 책임·정정 기준·최종 쓰기 경계를 사전 합의 |

## Ⅵ. 제언

모의 이관으로 시간·병목·롤백을 검증하고, 건수·집계·행 단위 대사를 모두 통과한 경우에만 컷오버

```text
모의 이관 반복 → 본 이관(초기+CDC) → 3단계 대사 → 승인 → 컷오버(복귀 조건 포함)
```

| 구분 | 건수 대사만 | 제언: 3단계 대사 |
|---|---|---|
| 오류 발견 | 상쇄 오류 놓침 | 행 단위까지 |
| 전환 | 사후 결함 | 승인 기준 통과 후 |
