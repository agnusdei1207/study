## 답안 골격
```text
[데이터 이관 (Data Migration)] ◀━━ 머리: Ⅶ 내 의견 (반복적 실전 모의 이관과 컷오버 롤백 마지노선 타임라인 수립)
 ┃
 ┣━ Ⅰ 개요 ───── 정보시스템 재구축 또는 클라우드 전환 시 기존 레거시 시스템의 데이터를 신규 시스템의 목표 스키마 구조로 변환·적재하는 전주기 공학 방법론
 ┣━ Ⅱ 특징 ───── 프로젝트 성공의 핵심 열쇠 · 추출(Extract)-변환(Transform)-적재(Load) · 이관 전략(빅뱅 vs 단계적) · 정합성 무결성 검증 필수
 ┣━ Ⅲ 구조 ───── 이관 계획(요건, 일정) / 이관 설계(매핑 정의서, 정제 룰) / 이관 개발(ETL 툴, 스크립트) / 이관 테스트(모의 이관) / 본 이관 및 검증
 ┣━ Ⅳ 흐름 ───── ① 원천 데이터 분석 및 프로파일링 → ② 매핑 정의서 작성 → ③ 변환 스크립트 개발 → ④ 1~3차 모의 이관 리허설 → ⑤ 본 이관(Cut-over) 및 대사 검증
 ┣━ Ⅴ 비교 ───── 빅뱅 이관(Big Bang) vs 단계적 이관(Phased) vs 병렬 운영 이관(Parallel)
 ┗━ Ⅵ 실무 ───── 본 이관 당일 예상 시간을 초과하여 컷오버 지연 / 예외 데이터로 인한 제약조건 위반 적재 실패
```
- 필수 키워드: 데이터 이관 · 매핑 정의서 · 모의 이관(Rehearsal) · 컷오버(Cut-over) · 빅뱅 이관 · 단계적 이관 · 데이터 정제(Cleansing) · 롤백 플랜(Rollback)
- 기출: 105회 `차세대 정보시스템 구축 시 데이터 이관(Data Migration)의 절차, 주요 활동 및 성공적인 이관을 위한 고려사항을 설명하시오.` → Ⅰ 정의 + Ⅲ 5단계 절차 + Ⅴ 전략 비교 + Ⅵ 성공 요건

## 한 줄 본질
- 서로 다른 업무 로직과 스키마 구조 간 데이터 이동 시 결손·변형 및 장시간 다운타임 발생 위험 → 체계적인 매핑 룰 수립과 반복적 실전 모의 이관을 통해 다운타임 내 완벽 적재 → 신규 시스템의 안전한 오픈 달성 / 변환 룰 검증 및 정제 공수 과다

## 핵심 용어
- 매핑 정의서(Mapping Specification): 원천 데이터의 테이블 및 컬럼 속성이 신규 시스템의 어떤 테이블 및 컬럼으로 어떻게 변환(코드 매핑, 산식 가공 등)되는지 1:1로 기술한 핵심 설계 산출물
- 모의 이관(Mock Migration / Rehearsal): 본 이관과 100% 동일한 인프라와 실데이터 환경에서 이관 스크립트를 실제로 돌려 소요 시간과 오류를 사전 도출하는 실전 리허설

## 핵심 통찰
- 시스템 오픈 당일 발생하는 장애의 80%는 애플리케이션 코드가 아니라 '데이터 이관 누락 및 정합성 오류' 때문임 → 아무리 프로그램을 잘 짰어도 기존 고객의 마일리지 데이터가 0원으로 이관되면 서비스 불가
- 모의 이관을 1회만 하고 본 이관에 들어가는 것은 '자살 행위'임 → 1차 모의(룰 검증), 2차 모의(성능 최적화 및 시간 단축), 3차 모의(실전 다운타임 내 완결 및 롤백 훈련)를 거쳐야 함
- 이관 전략을 짤 때 시스템 다운타임(예: 주말 48시간)이 충분하면 '빅뱅'이 비용상 유리하지만, 24시간 무중단이어야 한다면 CDC 기반의 '단계적/병렬 이관'을 선택해야 함

## 이웃 토픽과 구분
- 데이터 이관 vs 데이터 백업/복구: 데이터 이관 = 스키마 구조가 완전히 달라지는 환경으로 데이터를 '변환·가공'하여 이전 / 데이터 백업/복구 = 스키마 변경 없이 동일한 구조의 스토리지로 데이터를 '원형 그대로 사본 저장'

## 문제·원인·대책
- 적용 상황: 대규모 공공기관 차세대 시스템 통합 데이터 이관 프로젝트
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 본 이관 실행 30시간 경과 시점에도 50%만 적재되어 정해진 월요일 아침 오픈 위기 | 인덱스와 제약조건(PK, FK)을 켠 상태에서 대량 건별 INSERT 수행 | 적재 전 인덱스/제약조건 DISABLE, 다이렉트 패스(Direct-path) 적재 후 인덱스 병렬 재생성 | 이관 소요 시간 40시간에서 6시간으로 85% 단축 |
| 레거시의 '휴면 계정' 데이터가 신규 시스템의 필수 약관 제약에 걸려 이관 실패 | 신규 시스템의 업무 규칙과 레거시 데이터 간의 도메인 불일치 | 이관 전 클렌징 규칙 정의 및 휴면 데이터 전용 기본값 일괄 매핑 | 이관 적재 성공률 100% 달성 |

## 이렇게 출제된다
- 제105회: "차세대 정보시스템 구축 시 데이터 이관(Data Migration)의 추진 절차, 주요 활동 내용, 이관 방식(빅뱅 vs 단계적)의 비교 및 성공적인 이관을 위한 품질 보증 방안을 설명하시오." → 요구 포인트: 데이터 이관 5단계 생애주기 + 빅뱅 vs 단계적 비교표 + 모의 이관의 필요성 + 정합성 검증 및 롤백 플랜

## 내 의견
- [Go/No-Go 의사결정 시점의 문서화 강제] 본 이관 당일 예상치 못한 에러가 터졌음에도 담당자들의 미련으로 롤백 결정을 미루다가 월요일 아침 전체 대국민 서비스가 마비되는 참사 빈발 → 나라면: 컷오버 타임라인에 "일요일 18:00 시점에 정합성 검증률 95% 미달 시 무조건 원복한다"는 명문화된 'No-Go(롤백) 마지노선'을 설정하고, 롤백 스크립트 실행 권한을 PM에게 위임하는 비상 대응 거버넌스 확립
