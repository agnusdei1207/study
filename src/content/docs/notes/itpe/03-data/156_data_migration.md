## 지식 로드맵 내 현재 위치

<div class="itpe-topic-path" aria-label="지식 경로"><span>데이터베이스</span><span>데이터베이스 운영·마이그레이션</span><strong>데이터 이관 (Data Migration)</strong></div>

## 큰 그림과 30초 인출

```text
[데이터 이관 5단계 생명주기 및 컷오버(Cut-over) 롤백 마지노선 타임라인]

 [1. 계획 수립] ──► [2. 이관 설계] ──► [3. 이관 개발] ──► [4. 모의 이관] ──► [5. 본 이관]
  - 이관 범위       - 매핑 정의서      - ETL/CDC 스크립트  - 1차: 룰 정합성   - 컷오버 실행
  - 빅뱅/단계적      - 데이터 정제 규칙  - 병렬 벌크 로더     - 2차: 성능/튜닝   - 최종 대사검증
  - 다운타임 목표    - 정합성 검증 쿼리  - 예외 처리 루틴     - 3차: 실전 리허설  - Go/No-Go 판정

 ┌────────────────────────────────────────────────────────────────────────┐
 │ 컷오버 타임라인 (D-Day 금요일 20:00 ~ 일요일 18:00)                    │
 │  20:00        02:00          10:00          14:00 (Go/No-Go)   18:00   │
 │ ──┼─────────────┼──────────────┼──────────────┼──────────────────┼───► │
 │ 서비스차단    초기적재 완료    CDC 증분반영   정합성 검증 완료   시스템오픈  │
 │ (Downtime)   (Bulk Load)    (Catch-up)     [롤백 마지노선]               │
 └────────────────────────────────────────────────────────────────────────┘
```

- 본질: **차세대 시스템 구축, 클라우드 전환, DBMS 교체 시 레거시 시스템의 원천 데이터를 신규 목표 스키마 구조로 추출(Extract)·변환(Transform)·적재(Load)하고, 데이터 유실과 왜곡 없이 서비스 허용 다운타임 내에 정합성 검증과 컷오버(Cut-over)를 완결하는 데이터 엔지니어링 전주기 프레임워크**
- 암기: `계-설-개-모-본` (계획, 설계, 개발, 모의이관, 본이관) / `추-변-적-검` (추출, 변환, 적재, 검증) / `빅-단-병` (빅뱅, 단계적, 병렬)
- 판단축:
  - **빅뱅(Big-Bang)**: 주말/연휴 단일 컷오버 기간에 전량 일괄 이관, 구조 단순하고 비용 저렴하나 다운타임 길고 실패 시 리스크 극심
  - **단계적(Phased / CDC 기반)**: 업무 영역별 순차 이관 또는 CDC 기반 실시간 증분 동기화, 무중단/저위험 운영 가능하나 데이터 이중 관리 복잡
- 주의: 모의 이관(Rehearsal) 없는 본 이관은 금물이며, 컷오버 시점에는 반드시 복구 불가능 시점을 통제하는 **Go/No-Go 의사결정 마지노선(Point of No Return)**을 수립해야 함

## 예상문제

> 차세대 정보시스템 구축 및 클라우드 이전 프로젝트에서 성공적인 데이터 이관(Data Migration)을 위한 추진 절차 5단계와 주요 활동을 기술하고, 이관 방식(빅뱅 vs 단계적 vs 병렬)의 장단점 비교 및 데이터 정합성 검증 방안을 설명하시오. (25점)

## Ⅰ. 시스템 재구축의 성패를 좌우하는 데이터 이관 개요

#### 한줄 요약: 이기종 환경 간 비즈니스 로직과 스키마 변경을 수용하며 원천 데이터를 목표 DB로 무결하게 이동·검증하는 전주기 방법론

- **배경**: 시스템 오픈 당일 발생하는 장애의 80% 이상은 애플리케이션 코드가 아니라 데이터 매핑 오류, 제약조건 위반, 코드 변환 누락 등 데이터 이관 품질 문제에서 기인함
- **정의**: 레거시 DB에 축적된 트랜잭션 및 마스터 데이터를 신규 정보시스템의 데이터 모델에 부합하도록 정제·변환하여 목표 데이터베이스에 적재하는 일련의 엔지니어링 활동
- **핵심 목표**: 최소의 서비스 중단 시간(Downtime), 100% 무결성 및 정합성 보장, 실패 시 신속한 롤백(Rollback) 안정성 확보

## Ⅱ. 데이터 이관 5단계 추진 절차 및 단계별 산출물

#### 한줄 요약: 철저한 사전 분석과 3회 이상의 모의 이관(Rehearsal)을 거치는 단계별 표준 프로세스

```text
 [Step 1. 이관 계획] ──► [Step 2. 이관 설계] ──► [Step 3. 이관 개발]
   - 이관 범위 정의        - 소스-타겟 매핑정의서   - ETL/CDC 스크립트 작성
   - 일정 및 컷오버 전략   - 코드 변환 테이블       - 병렬 벌크 로더 개발
   - 자원 및 조직 구성     - 정제 규칙 정의서       - 데이터 검증 쿼리 개발
            │
            ▼
 [Step 4. 모의 이관] ──► [Step 5. 본 이관 및 검증]
   - 1차: 매핑/정제 검증   - 서비스 다운타임 선언 및 차단
   - 2차: 성능 및 시간실측 - 초기 벌크 + CDC 증분 반영
   - 3차: 실전 리허설/롤백 - 정합성 대사 -> Go/No-Go 판정 -> 서비스 오픈
```

| 이관 단계 | 주요 핵심 활동 (Activity) | 주요 산출물 (Deliverables) |
|:---|:---|:---|
| **1. 이관 계획** | 원천 DB 프로파일링, 이관 대상 테이블 확정, 보관 주기 기준 과거 데이터 퍼징(Purging) 및 아카이빙 전략 수립 | 데이터 이관 계획서, WBS, R&R 정의서 |
| **2. 이관 설계** | 소스-타겟 컬럼 1:1 매핑, 데이터 타입/길이 불일치 변환 룰 정의, 코드 매핑 테이블 작성, 무결성 제약조건 선/후 적용 설계 | 소스-타겟 매핑 정의서, 코드 변환 정의서, 정제 규칙서 |
| **3. 이관 개발** | ETL 툴(Informatica, DataStage) 또는 Python/SQL 기반 추출-변환 스크립트 개발, 병렬 처리(Parallel DML) 최적화 | 이관 프로그램 소스, 배치 스크립트, 예외 로그 테이블 |
| **4. 모의 이관** | 본 이관과 동일 사양 환경에서 실데이터 전건 대상 리허설 (최소 3회), 이관 소요 시간 실측, 병목 튜닝, 롤백 절차 검증 | 모의 이관 결과 보고서, 조치 내역서, 튜닝 보고서 |
| **5. 본 이관** | 서비스 차단 $\rightarrow$ 최종 백업 $\rightarrow$ 초기 벌크 적재 $\rightarrow$ CDC 증분 동기화 $\rightarrow$ 대사 검증 $\rightarrow$ Go 판정 $\rightarrow$ 오픈 | 본 이관 결과서, 데이터 대사 검증 보고서, 오픈 승인서 |

## Ⅲ. 데이터 이관 방식 비교: 빅뱅 vs 단계적 vs 병렬 운영

#### 한줄 요약: 시스템 다운타임 허용도와 리스크 수용성에 따른 전략적 이관 모델 선택

```text
 [1. 빅뱅 (Big-Bang)]          [2. 단계적 (Phased)]          [3. 병렬 운영 (Parallel)]
  Source ──(단일 컷오버)──► Target  Source ──► Target (업무 1)   Source ──► Target (동시운영)
  (전체 일괄 즉시 전환)             Source ──► Target (업무 2)   (양방향 동기화, 이중검증)
```

| 비교 항목 | 빅뱅 방식 (Big-Bang) | 단계적 방식 (Phased) | 병렬 운영 방식 (Parallel) |
|:---|:---|:---|:---|
| **전환 방식** | 지정된 단일 컷오버 기간(예: 주말)에 전 업무 일괄 전환 | 업무 단위(예: 여신, 수신, 카드) 또는 지점별 순차 전환 | 신·구 시스템을 일정 기간 동시 운영하며 실시간 비교 |
| **다운타임** | 상대적으로 김 (수 시간 ~ 수십 시간 전면 중단) | 짧음 (단위 업무별 최소 다운타임만 발생) | 거의 없음 (무중단 전환 가능) |
| **리스크 수준** | 극도로 높음 (본 이관 실패 시 전면 롤백 불가피) | 낮음 (문제 발생 시 해당 업무 단위만 격리 조치) | 최저 (오류 발견 시 구 시스템으로 즉시 복귀) |
| **비용 및 공수** | 낮음 (일회성 단기 집중 투입) | 중간 (인터페이스 및 임시 어댑터 개발 필요) | 매우 높음 (인프라 이중 운영, 실시간 양방향 CDC 구축) |
| **적용 권장** | 업무 간 결합도가 극도로 높고 다운타임 확보 가능한 시스템 | 모듈 간 독립성이 높고 대규모 시스템 (금융/대기업) | 24x365 무중단이 절대적인 미션 크리티컬 코어 시스템 |

## Ⅳ. 데이터 정제(Data Cleansing) 및 추출·적재(ETL) 최적화 기법

#### 한줄 요약: 불량 데이터를 원천 차단하고 수억 건 데이터를 제한된 다운타임 내 적재하기 위한 고속화 기법

### 1. 데이터 프로파일링 및 사전 정제 (Cleansing)
- **Null 및 기본값 정제**: 필수 컬럼(`NOT NULL`)에 공백이나 특수문자가 들어간 레거시 데이터 기본값 대체
- **데이터 포맷 정규화**: 전화번호(`010-1234-5678` vs `01012345678`), 날짜 포맷(`YYYYMMDD` vs `YYYY-MM-DD`) 표준화
- **고아 레코드(Orphan Record) 제거**: 부모 테이블이 삭제되었으나 자식 테이블에 남아 있는 참조 무결성 위반 데이터 사전 격리

### 2. 고속 적재(Bulk Load) 성능 튜닝
- **인덱스 및 제약조건 비활성화**: 데이터 적재 전 타겟 테이블의 인덱스를 `UNUSABLE` 처리하고 PK/FK 제약조건을 `DISABLE NOVALIDATE` 처리
- **Direct Path Insert 활용**: 버퍼 캐시를 거치지 않고 데이터 파일의 HWM(High Water Mark) 뒤에 직접 블록을 쓰는 `/*+ APPEND */` 힌트 및 `NOLOGGING` 옵션 적용
- **병렬 DML (Parallel DML)**: CPU 코어 수에 맞추어 `PARALLEL(8)` 등으로 분할 적재하여 처리 속도 5~10배 향상
- **적재 후 인덱스 일괄 재생성**: 적재 완료 후 `REBUILD NOLOGGING PARALLEL`로 인덱스 고속 재구축 후 제약조건 재검증

## Ⅴ. 데이터 정합성·무결성 3대 검증 체계

#### 한줄 요약: 단순 건수 비교부터 집계 대사, 행 단위 해시 체크섬 비교를 아우르는 다계층 검증

```text
 [1단계: 건수 대사 (Count)]  ──► [2단계: 금액/합계 대사 (Sum)] ──► [3단계: 행 해시 대사 (Hash)]
  - 소스 vs 타겟 총 건수        - 잔액 합계, 거래 총액            - 주요 컬럼 MD5/SHA256
  - 테이블별 레코드 수 일치      - 통계 집계치 1원 단위 대사       - 샘플링/전건 1:1 비교
```

| 검증 계층 | 검증 기법 및 산식 | 검증 내용 및 목적 | 오류 감지 수준 |
|:---|:---|:---|:---:|
| **1단계: 볼륨 검증** | `COUNT(*)` 및 조건별 건수 대사 | 원천 테이블과 목표 테이블 간 총 레코드 수 일치 확인 | 누락 데이터 발견 |
| **2단계: 값/통계 검증** | `SUM(금액)`, `AVG(단가)`, `MAX/MIN` | 주요 수치형 비즈니스 핵심 컬럼의 총합 일치 확인 | 변환 산식 오류 발견 |
| **3단계: 내용 정밀 검증** | `MD5/SHA256(col1 || col2 || ...)` 및 `MINUS / EXCEPT` 쿼리 | 원천 데이터와 목표 데이터를 표준 문자열로 결합 후 해시값 비교 | 컬럼 값 왜곡 정밀 적발 |

## Ⅵ. 실무 컷오버 장애 시나리오 및 트러블슈팅

#### 한줄 요약: 다운타임 지연, 제약조건 에러, 롤백 마지노선 판단 실패를 방지하는 실전 대책

| 장애 시나리오 | 발생 원인 | 현장 해결 및 예방 대책 |
|:---|:---|:---|
| **이관 시간 초과로 다운타임 위반** | 모의 이관 대비 본 이관 시 디스크 I/O 병목 또는 CDC 갭(Lag) 누적 | 테이블 단위 적재를 파티션 단위 병렬 적재로 세분화, 롤백 마지노선 이전 중단 판단 |
| **제약조건 활성화 에러** | 인덱스 재생성 후 FK 제약 활성화(`ENABLE`) 시 고아 레코드 발생으로 에러 | 예외 처리 테이블(`EXCEPTIONS TABLE`)을 지정하여 위반 행만 즉시 격리 후 오픈 진행 |
| **코드 매핑 누락으로 화면 깨짐** | 신규 시스템 공통코드에 등록되지 않은 레거시 레어 코드 유입 | 모의 이관 시 코드 프로파일링 전수 검증, 미매핑 코드는 임시 '기타(ETC)' 코드로 기본 처리 |

## Ⅶ. 기술사적 제언: CDC 기반 제로 다운타임(Zero-Downtime) 이관 아키텍처

#### 한줄 요약: 대규모 빅뱅 전환의 위험을 탈피하고 Debezium/Kafka CDC 기반 실시간 양방향 복제로 무중단 컷오버 달성

```text
 [CDC 기반 무중단 데이터 이관 아키텍처]
  [레거시 RDBMS] ──(Full Snapshot)──► [초기 벌크 적재] ──► [신규 타겟 DB]
        │ (트랜잭션 발생)                                        │
        ▼ (Redo/WAL 로그 캡처)                                   ▼
  [Debezium CDC] ──► [Apache Kafka] ──► [Kafka Connect Sink] ────┘ (실시간 동기화)
                                        │
  * 컷오버 D-Day: Kafka Lag이 0에 도달하는 순간 10초 만에 DNS/VIP 절체하여 무중단 오픈 완료
```

- **핵심 메커니즘**:
  1. 원천 DB가 정상 운영되는 동안 초기 풀 스냅샷(Full Snapshot)을 타겟 DB에 백그라운드로 적재
  2. 스냅샷 시점 이후 발생하는 모든 CUD 트랜잭션은 트랜잭션 로그(Redo Log, WAL)를 직접 읽는 CDC(Change Data Capture)로 Kafka 큐에 축적
  3. 타겟 DB에 실시간 재생(Replay)하여 시차(Lag)를 수 초 이내로 유지
  4. 컷오버 당일 원천 DB 쓰기를 수 초간 잠그고 최종 Lag을 0으로 만든 후 DNS/VIP만 신규 시스템으로 절체하여 **다운타임을 '수십 시간'에서 '수 분 이내'로 단축**

## 1교시 10점 답안 발췌

```text
1. 데이터 이관(Data Migration)의 정의
  - 차세대 구축 및 클라우드 전환 시 원천 데이터를 목표 스키마로 추출, 변환, 적재(ETL)하고 정합성을 검증하여 무결하게 이전하는 전주기 기술.

2. 데이터 이관 5단계 절차 및 검증 방안
  가. 5단계 절차:
    ① 계획(범위 확정) -> ② 설계(소스-타겟 매핑 정의서) -> ③ 개발(ETL/병렬 스크립트) -> ④ 모의 이관(3회 이상 리허설) -> ⑤ 본 이관(컷오버 및 Go/No-Go 판정)
  나. 정합성 3단계 검증:
    - 건수 대사(COUNT) -> 합계 대사(SUM/AVG) -> 내용 대사(해시 체크섬 및 MINUS 쿼리)

3. 컷오버 시 롤백 마지노선 수립
  - 허용 다운타임 내 정합성 검증 실패 시 복구 불가능 시점(Point of No Return) 이전에 신속한 롤백을 결단하는 Go/No-Go 기준 필수 확립.
```
