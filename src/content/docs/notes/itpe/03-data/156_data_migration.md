## 연관 키워드

- 데이터 마이그레이션

## Ⅰ. 데이터 마이그레이션의 개요

- 핵심 요약 : 소스 시스템에서 타겟 시스템으로 데이터를 안전하고 완전하게 이관하는 전 주기 엔지니어링 프로세스.
- 개념 : 레거시 시스템, 온프레미스 DB(Database), 파일 시스템 등 소스(Source)에서 클라우드 DW(Data Warehouse), 신규 애플리케이션 DB, 데이터 레이크(Lake) 등 타겟(Target)으로 스키마 변환, 데이터 정제, 검증을 동반하여 데이터를 이관하는 전 주기 엔지니어링 프로세스.
- 배경 및 필요성 : 클라우드 전환, 시스템 현대화(Modernization), M&A 통합, 규제 준수(Compliance) 대응을 위한 레거시 탈피와 데이터 자산의 안전한 이전 필요.
- 주요 목적 : 데이터 손실 제로(Zero Data Loss), 비즈니스 연속성 유지, 타겟 시스템에서의 데이터 품질 보장.

## Ⅱ. 데이터 마이그레이션의 특징

- 핵심 요약 : 이관 방식(빅뱅/트리클), CDC 기반 증분 동기화, 검증 자동화, 롤백 체계가 결합된 마이그레이션 엔지니어링.

1. 이관 전략 선택 : 빅뱅(Big Bang, 일괄 이관) vs 트리클(Trickle, 단계적/병렬 이관) vs 하이브리드 방식.
2. CDC(Change Data Capture) 기반 증분 동기화 : 소스 변경분을 실시간/배치로 캡처하여 타겟에 적용, 다운타임 최소화.
3. 스키마 매핑·변환 : 데이터 타입 매핑, 정규화/역정규화, 코드 값 변환, 계층 구조 평탄화 등 논리-물리 변환.
4. 데이터 품질 검증 : 행 수(Row Count), 체크섬(Checksum), 샘플링 검증, 비즈니스 룰 검증의 다층 검증 체계.
5. 롤백·복구 계획 : 마이그레이션 실패 시 원상 복구 가능한 스냅샷, 백아웃(Backout) 절차 사전 정의.

## Ⅲ. 데이터 마이그레이션의 구조 (흐름)

- 핵심 요약 : 평가·설계·구축·검증·전환·안정화의 6단계 마이그레이션 생명주기.
- 데이터 마이그레이션 6단계 생명주기.

```text
[ 데이터 마이그레이션 생명주기 ]
[ 1단계: 평가(Assessment) ]
  - 소스/타겟 시스템 분석, 데이터 프로파일링, 볼륨 추정, 리스크 식별
    │
    ▼
[ 2단계: 설계(Design) ]
  - 이관 전략 선정, 스키마 매핑 정의, CDC 아키텍처, 검증 시나리오 설계
    │
    ▼
[ 3단계: 구축(Build) ]
  - ETL/ELT 파이프라인 개발, CDC 파이프라인 구성, 검증 자동화 스크립트 구현
    │
    ▼
[ 4단계: 검증(Validation) ]
  - 단위 테스트, 통합 테스트, 성능 테스트, UAT(User Acceptance Test)
    │
    ▼
[ 5단계: 전환(Cutover) ]
  - 읽기 전용 전환, 최종 증분 동기화, DNS/연결 문자열 스위치, 스모크 테스트
    │
    ▼
[ 6단계: 안정화(Stabilization) ]
  - 하이퍼케어(Hypercare) 기간 모니터링, 잔여 이슈 해결, 롤백 기준 해제
```

- CDC 기반 증분 동기화 아키텍처.

```text
[ CDC 증분 동기화 구조 ]
[ 소스 DB ] -> [ CDC 커넥터 (Debezium, Attunity, Goldengate) ]
    │                                    │
    │        트랜잭션 로그(Transaction Log) 마이닝
    ▼                                    ▼
[ 메시지 큐 (Kafka, Kinesis) ] -> [ 스트림 처리 (Flink, Spark Streaming) ]
    │                                    │
    │         스키마 변환, 정제, 보강
    ▼                                    ▼
[ 타겟 DB / DW ] <- [ 멱등적 업서트(Upsert) 적용 ]
```

## Ⅳ. 빅뱅 마이그레이션과 트리클 마이그레이션의 비교

- 핵심 요약 : 일괄 중단 vs 단계적 병행의 다운타임-복잡도 트레이드오프.

| 비교 항목 | 빅뱅 마이그레이션(Big Bang) | 트리클 마이그레이션(Trickle/Phased) |
|---|---|---|
| 다운타임 | 장시간 중단 필요 (시간~일 단위) | 최소 중단 (초~분 단위, 최종 컷오버만) |
| 복잡도 | 상대적 단순 (단일 이벤트) | 높음 (CDC, 양방향 동기화, 충돌 해결) |
| 리스크 | 일괄 실패 시 전면 롤백, 영향 범위 큼 | 단계별 검증 가능, 부분 롤백 용이 |
| 리소스 | 단기 집중 투입 | 장기 분산 투입, 병렬 운영 비용 발생 |
| 적합 상황 | 소규모, 다운타임 허용, 스키마 변경 큼 | 대규모, 24/7 서비스, 제로 다운타임 요구 |

## Ⅴ. 데이터 마이그레이션의 장점과 한계

- 핵심 요약 : 클라우드 전환과 현대화 가속의 장점, 데이터 손실 위험과 검증 복잡도의 한계.
- 장점
  1. 레거시 기술 부채 해소와 클라우드 네이티브 아키텍처로의 전환 가속.
  2. 데이터 통합과 품질 개선 기회 확보 (마이그레이션 과정에서 정제·표준화 병행).
  3. 운영 비용 절감과 확장성·민첩성 향상.
- 한계점 1 : 데이터 손실·불일치 리스크
  - 한계점 : 대용량 이관 중 네트워크 장애, 타임아웃, 스키마 불일치로 행 유실, 중복, 변환 오류 발생.
  - 해결 방안 : 멱등적(Idempotent) 파이프라인 설계, 트랜잭션 경계 명확화, 체크섬(Checksum) 기반 행 단위 검증, CDC 오프셋(Offset) 관리.
- 한계점 2 : 비즈니스 로직 불일치로 인한 검증 실패
  - 한계점 : 소스와 타겟의 비즈니스 룰 차이(예: 반올림, 코드 매핑)로 데이터는 이관되었으나 비즈니스 의미 불일치.
  - 해결 방안 : 도메인 전문가 참여 비즈니스 룰 매핑 문서화, 샘플링 기반 비즈니스 검증(UAT) 필수화, 그림자 테이블(Shadow Table) 병렬 검증.
- 한계점 3 : 레거시 시스템 이해도 부족에 따른 숨은 의존성 누락
  - 한계점 : 문서화되지 않은 트리거, 저장 프로시저, 배치 잡, 외부 인터페이스 등 숨은 의존성으로 이관 후 장애 발생.
  - 해결 방안 : 정적 코드 분석, 런타임 트레이싱, 의존성 매핑 자동화 도구 활용, 영향도 분석(Impact Analysis) 철저 수행.

## Ⅵ. 데이터 마이그레이션에 대한 기술사적 제언

- 핵심 요약 : CDC 기반 제로 다운타임 패턴 표준화와 자동화된 검증 프레임워크 정착 필요.
- CDC(Change Data Capture) 기반 제로 다운타임 마이그레이션 패턴 표준화 : 빅뱅 방식 지양, Debezium 등 오픈소스 CDC 도구와 클라우드 매니지드 서비스(AWS DMS, Azure Database Migration Service)를 활용한 트리클/하이브리드 패턴을 전사 표준 마이그레이션 방법론으로 정착 필요.
- 자동화된 데이터 검증 프레임워크 구축 : 행 수, 체크섬, 샘플링, 비즈니스 룰 검증을 파이프라인 단계별 게이트(Gate)로 자동화하고, 검증 리포트를 CI/CD 대시보드에 통합하여 '검증된 데이터만 프로덕션 진입' 원칙 강제 필요.
- 마이그레이션 전용 거버넌스 조직(Migration Office) 운영 : 아키텍트, DBA(Database Administrator), 도메인 전문가, QA로 구성된 전담 조직이 평가부터 안정화까지 전 주기 책임지고, 이슈 에스컬레이션(Escalation)과 롤백 의사결정 권한 보유 필요.

## Ⅶ. 결론

- 핵심 요약 : 데이터 마이그레이션은 CDC 기반 증분 동기화와 다층 검증이 전제된 시스템 현대화의 핵심 관문.
- 요약 : 소스에서 타겟으로 스키마 변환, 정제, 검증을 동반하여 데이터를 이관하는 전 주기 프로세스로, 빅뱅 vs 트리클 전략 선택과 CDC 기반 다운타임 최소화가 핵심.
- 시사점 : CDC 표준 패턴, 자동화 검증 게이트, 마이그레이션 오피스 거버넌스, 롤백 기준 사전 정의의 4요소가 성공적 마이그레이션의 완성.
