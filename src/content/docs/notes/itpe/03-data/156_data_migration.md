## 지식 로드맵 내 현재 위치

데이터베이스 → 운영·엔지니어링 → 데이터 이관

## 30초 인출

- 본질: **데이터 이관은** 원천 자료를 목표 시스템의 구조·규칙으로 옮기고 정합성을 검증하는 활동
- 메커니즘: 매핑·모의 이관 뒤 스냅샷과 CDC 변경분을 적재하고 대사 결과로 컷오버를 판정
- 통찰: 한계: 초기 적재와 변경분 반영의 기준 시점이 어긋나면 누락·중복이 발생 → 방안: 스냅샷 시점과 로그 위치를 기록하고 재처리·대사·롤백을 포함한 절체를 검증

<details><summary>핵심 용어</summary>

- **데이터 이관 (Data Migration)** : 원천 데이터를 목표 시스템으로 옮기고 변환·검증하는 활동.
- **ETL (Extract, Transform, Load)** : 원천에서 추출한 데이터를 변환한 뒤 목표 저장소에 적재하는 처리 방식.
- **CDC (Change Data Capture)** : 데이터베이스 변경을 포착해 후속 시스템에 전달하는 방식.
- **소스-타깃 매핑 (Source-to-Target Mapping)** : 원천 항목과 목표 항목 및 변환 규칙의 대응 정의.
- **대사 (Reconciliation)** : 원천과 목표의 건수·값·업무 규칙 결과를 비교해 이관 완전성을 확인하는 절차.
- **컷오버 (Cutover)** : 서비스 사용 대상을 기존 시스템에서 목표 시스템으로 전환하는 시점·절차.
- **빅뱅 이관 (Big-Bang Migration)** : 정한 전환 시점에 대상 범위를 한꺼번에 전환하는 방식.
- **단계적 이관 (Phased Migration)** : 기능·데이터 범위를 나누어 순차 전환하는 방식.

</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|:---|:---|
| 정의 | 데이터 이관은 원천 데이터를 목표 시스템의 구조·규칙에 맞춰 옮기고 검증하는 활동 |
| 목적 | 데이터의 의미와 업무 연속성을 유지하며 목표 시스템으로 안전하게 전환 |

## Ⅱ. 데이터 이관의 특징

| 특징 | 관리 의미 |
|---|---|
| 원천·목표 매핑 | 자료형·코드·업무 규칙의 변환 정의 |
| 시점 동기화 | 초기 적재와 이후 변경분의 기준점 연결 |
| 승인된 전환 | 정합성·시간·복귀 조건을 검증한 뒤 컷오버 |

## Ⅲ. 대용량 데이터 이관·컷오버 프로세스

```text
계획·매핑 ──> 모의 이관 ──> 초기 적재 + CDC
                                     │
                            건수·값·규칙 대사
                                     │
                           승인 조건 충족?
                          /            \
                        예              아니오
                    컷오버       현행 유지·재시험
```

### 초기 적재와 CDC의 하위 동기화 관계

```text
원천 시점 S의 스냅샷 ─────────→ 목표 초기 적재
S 이후 변경 로그 위치 ── CDC ─→ 목표 변경분 반영
                                  ↓
                       지연·누락·중복 대사 후 절체
```

## Ⅳ. 전환 방식과 정합성 검증 비교

### 추진 단계

| 이관 단계 | 주요 핵심 활동 (Activity) | 주요 산출물 (Deliverables) |
|:---|:---|:---|
| **1. 이관 계획** | 원천 자료 프로파일링, 이관 범위·보관 정책·전환 창과 복구 기준 확정 | 데이터 이관 계획서, WBS, 역할 분담 |
| **2. 이관 설계** | 원천·목표 항목과 변환 규칙 매핑, 코드·키·제약 조건 및 검증 기준 정의 | 매핑 정의서, 정제·대사 규칙서 |
| **3. 이관 개발** | 추출·변환·적재와 오류 재처리 구현, 처리량 점검 | 이관 프로그램, 예외 로그 |
| **4. 모의 이관** | 대표·예외 데이터를 포함한 리허설, 소요 시간 실측, 병목 조정, 롤백 훈련 | 모의 이관 결과 보고서, 조치 내역서, 성능 튜닝서 |
| **5. 본 이관** | 초기 적재와 CDC 동기화 후 원천 쓰기 통제 $\rightarrow$ 최종 변경분 반영 $\rightarrow$ 대사 $\rightarrow$ 승인 $\rightarrow$ 접속 전환 | 이관 결과서, 대사 보고서, 전환 승인서 |

### 빅뱅·단계적·병렬 운영 비교

| 비교 항목 | 빅뱅 방식 (Big-Bang) | 단계적 방식 (Phased) | 병렬 운영 방식 (Parallel) |
|:---|:---|:---|:---|
| **전환 방식** | 지정된 단일 컷오버 기간(주말)에 전 업무 일괄 전환 | 업무 단위(여신, 수신 등) 또는 지점별 순차 전환 | 신·구 시스템을 일정 기간 동시 운영하며 실시간 비교 |
| **다운타임** | 전체 전환 창에 집중 | 단계별 전환 창 필요 | 비교 기간에도 최종 전환 창 필요 가능 |
| **리스크 수준** | 한 번의 실패가 전체에 영향 | 신·구 연계·정합성 관리 필요 | 이중 운영과 결과 불일치 처리 필요 |
| **비용 및 공수** | 일회성 집중 작업 | 임시 연계·반복 전환 | 중복 인프라·검증 부담 |
| **적용 검토** | 업무 결합이 높고 전환 창 확보 가능 | 업무별 경계가 명확 | 병렬 결과 대조가 중요 |

### 데이터 정합성·무결성 검증

| 검증 계층 | 검증 기법 및 쿼리 | 검증 내용 및 판정 기준 | 오류 감지 수준 |
|:---|:---|:---|:---:|
| **건수 대사** | 전체·조건별 `COUNT(*)` | 범위별 적재량 차이 | 누락·중복이 상쇄될 수 있어 단독 판정 불가 |
| **업무 집계 대사** | 주요 금액·수량 합계 | 변환·집계 오류 후보 | 상쇄되는 개별 값 오류는 놓칠 수 있음 |
| **키·값 대사** | 정규화한 행의 키·값 비교 또는 해시 | 개별 행의 불일치 | 자료형·NULL·정렬·해시 충돌 고려 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 초기 적재와 변경분 반영의 기준 시점이 어긋나면 누락·중복이 발생 | 스냅샷 시점과 로그 위치를 기록하고 재처리·대사·롤백을 포함한 절체를 검증 |
| 건수·합계가 맞아도 개별 행의 값 오류가 남음 | 핵심 키·값의 행 단위 대사와 업무 규칙 검증 추가 |
| 병렬 운영에서 신·구 결과 차이를 해결하지 못함 | 불일치 처리 책임·정정 기준·최종 쓰기 경계를 미리 합의 |

## Ⅵ. 제언

변경량이 큰 테이블부터 스냅샷·로그 기준점을 고정하고 행 단위 대사·재처리·복귀를 포함한 절체를 연습.
