## 연관 키워드
- 격리수준, Dirty Read, Non-repeatable Read, Phantom, MVCC, 직렬화 가능성

### Ⅰ. 트랜잭션 격리 수준의 개요

- 핵심 요약 : 격리수준은 동시 트랜잭션이 서로의 미완료·변경 데이터를 어느 정도 관찰할 수 있는지 정하는 동시성 보장 수준.
- 개념 : 동시 트랜잭션이 서로의 미완료·변경 데이터를 어느 정도 관찰할 수 있는지 정하는 동시성 보장 수준(**트랜잭션 격리 수준**, Transaction Isolation Level).
- 배경 및 필요성 : 완전 직렬화는 정확하지만 성능비용이 있고 낮은 격리는 이상 현상 위험을 높임.
- 주요 목적 : 업무 정합성과 처리량 요구에 맞는 동시 실행 허용범위 결정.

### Ⅱ. 트랜잭션 격리 수준의 특징 및 장점

- 핵심 요약 : Read Uncommitted·Read Committed·Repeatable Read·Serializable는 더티 읽기·반복 읽기·팬텀 읽기 등 이상 현상과 성능 사이의 균형을 조절하는 트랜잭션 격리 모델.

1. Read Uncommitted : 커밋 전 데이터 읽기 가능 → 더티 읽기 위험.
2. Read Committed : 커밋된 값만 읽음 → 반복 읽기 값은 달라질 수 있음.
3. Repeatable Read·Serializable : 보장 강화 → 팬텀·직렬화 충돌 및 대기 주의.

### Ⅲ. 트랜잭션 격리 수준의 구조 (흐름)

- 핵심 요약 : 업무 불변조건·이상 허용 정의 → DBMS 격리 의미 확인 → 수준·락·버전 전략 설정 → 경합시험 → 재시도·정합성 검증.

```text
업무 불변조건·이상 허용 정의
  ↓
DBMS 격리 의미 확인
  ↓
수준·락·버전 전략 설정
  ↓
경합시험
  ↓
재시도·정합성 검증
```

```text
낮은 격리: 높은 동시성·이상 현상 허용
Read Uncommitted → Read Committed
        → Repeatable Read → Serializable
높은 격리: 강한 보장·충돌/대기 증가
```

### Ⅳ. Read Committed와 Serializable 비교

- 핵심 요약 : 경합 대응 기준 — Read Committed: 일반적으로 충돌 적고 처리량 유리; Serializable: 충돌 중단·잠금·재시도로 처리량 저하 가능.

| 비교 축 | Read Committed | Serializable |
|---|---|---|
| 읽기 안정성 | 각 문장 시점 커밋 데이터 읽기 | 동시 실행 결과가 어떤 직렬 순서와 동등하도록 보장 |
| 경합 대응 | 일반적으로 충돌 적고 처리량 유리 | 충돌 중단·잠금·재시도로 처리량 저하 가능 |
| 이상 현상 | 반복 읽기 값 변경 가능 | 직렬화 가능하도록 직렬 실행 결과와 동일하게 보장 |

### Ⅴ. 트랜잭션 격리 수준의 한계와 방안

- 핵심 요약 : DBMS 구현 차이·재시도 누락 등 실제 위험을 원인에 맞는 통제와 지표로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| DBMS 구현 차이 | 같은 이름의 수준도 MVCC·범위잠금 동작 차이 | 벤더 문서·실제 동시성 테스트 확인 | 이상 재현 건수 |
| 재시도 누락 | 직렬화 실패·교착 오류를 업무 실패로 방치 | 멱등 요청·제한 재시도·백오프 구현 | 재시도 성공률 |
| 격리 과소설정 | 업무 불변조건이 경합으로 위반 | 원자 갱신·유일 제약·직렬화 필요성을 검토 | 불변조건 위반 |

### Ⅵ. 트랜잭션 격리 수준에 대한 제언

- 핵심 요약 : 서비스 설계자는 격리수준만으로 정확성을 가정하지 않고 DB 제약·원자 연산·재시도를 함께 설계하고 부하 중 경쟁 조건 시험.

- 실행 제안 : 서비스팀은 경쟁 업데이트·범위 조회 시나리오를 부하 테스트하고 충돌 중단 시 재시도가 멱등한지 점검.

### Ⅶ. 결론

- 핵심 요약 : 격리수준은 동시 실행의 이상과 비용 사이의 계약이며 제품별 구현과 업무 규칙을 함께 확인해야 함.
- 시사점 : 격리수준은 동시 실행에 대한 명시적 계약이며 DBMS별 실제 동작과 오류 재시도를 확인해야 함.
