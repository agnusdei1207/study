## 연관 키워드

- 고가용성, 장애도메인, 이중화, 장애조치, RTO, RPO, quorum

## Ⅰ. 고가용성 아키텍처의 개요

- 핵심 요약 : 고가용성 아키텍처는 장애 시에도 합의된 수준의 서비스를 지속·복구하도록 중복 구성·장애감지·전환 절차를 설계하는 체계.
- 개념 : 고가용성 아키텍처는 장애 시에도 합의된 수준의 서비스를 지속·복구하도록 중복 구성·장애감지·전환 절차를 설계하는 체계.
- 배경 및 필요성 : 단일 장애점·장애 복구 지연으로 업무 서비스 중단 및 데이터 손실 발생.
- 주요 목적 : 가용성 목표에 맞는 서비스 연속성과 복구능력 확보.

## Ⅱ. 고가용성 아키텍처의 특징 및 장점

- 핵심 요약 : 중복·격리: 노드·전원·네트워크 장애도메인 분리 → 공통원인 고장 완화; 감지·전환: 헬스체크·쿼럼·자동/수동 failover → 복구시간 단축; 복제·백업: 동기/비동기 복제와 복구 지점 설계 → RPO 통제.

1. 중복·격리: 노드·전원·네트워크 장애도메인 분리 → 공통원인 고장 완화
2. 감지·전환: 헬스체크·쿼럼·자동/수동 failover → 복구시간 단축
3. 복제·백업: 동기/비동기 복제와 복구 지점 설계 → RPO 통제

## Ⅲ. 고가용성 아키텍처의 구조 (흐름)

- 핵심 요약 : 가용성·RTO/RPO 정의 → 장애모드·장애도메인 분석 → 중복·복제·전환 설계 → 장애주입·복구훈련 → 실적·용량·런북 개선.

```text
가용성·RTO/RPO 정의
  ↓
장애모드·장애도메인 분석
  ↓
중복·복제·전환 설계
  ↓
장애주입·복구훈련
  ↓
실적·용량·런북 개선
```

- 핵심 구성 : 장애 감지 → 격리·리더 선출/전환 → 서비스 복구 → 데이터 정합성 확인 → 원인 개선

```text
장애 감지 → 격리·리더 선출/전환 → 서비스 복구 → 데이터 정합성 확인 → 원인 개선
```

## Ⅳ. 비교: 고가용성(HA) / 백업·재해복구(DR)

- 핵심 요약 : 수단 기준 — 고가용성(HA): 이중화·자동 전환·복제; 백업·재해복구(DR): 별도 지역 백업·복구 환경.

| 비교 기준 | 고가용성(HA) | 백업·재해복구(DR) |
| --- | --- | --- |
| 목표 | 단일 구성요소 장애 중 서비스 지속 | 사이트 재해·대규모 중단 후 복구 |
| 수단 | 이중화·자동 전환·복제 | 별도 지역 백업·복구 환경 |
| 측정 | 가용률·전환시간 | RTO·RPO·복구시험 |

## Ⅴ. 고가용성 아키텍처의 한계와 방안

- 핵심 요약 : 공통원인 장애·분할 뇌·데이터 손상 등 주요 위험을 원인에 맞는 통제로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 공통원인 장애 | 같은 전원·망·리전에 이중화 배치 | 장애도메인·리전 분리 및 의존성 점검 | 단일장애점 수 |
| 분할 뇌·데이터 손상 | 양측 노드가 동시에 리더로 동작 | quorum·fencing·일관성 검증 | 복제 불일치 |
| 미검증 복구 | 구성은 있으나 전환·복구 절차가 실패 | 정기 게임데이·복구 리허설·런북 관리 | RTO/RPO 달성률 |

## Ⅵ. 고가용성 아키텍처의 제언

- 핵심 요약 : 서비스 책임자는 업무별 가용성·RTO/RPO를 정의하고 구성도에 장애도메인·외부 의존성·전환 권한을 표시해 정기 실전훈련.
- 실행 제안 : 서비스 책임자는 전원·네트워크·리전 장애를 주입해 자동전환·데이터 정합성·RTO/RPO 달성 여부를 기록.

## Ⅶ. 고가용성 아키텍처의 결론

- 핵심 요약 : 고가용성은 장비 중복만이 아니라 장애격리·데이터 일관성·사람의 복구절차까지 검증하는 운영 역량.
- 시사점 : 가용성 목표는 아키텍처 수치보다 장애훈련에서 실제 달성한 복구시간·복구지점으로 판단.
