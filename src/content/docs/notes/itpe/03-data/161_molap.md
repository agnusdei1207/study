## 연관 키워드

- MOLAP, 다차원 큐브, 사전 집계, 큐브 폭발
- 희소성, ROLAP, HOLAP

## Ⅰ. MOLAP의 개요

- 핵심 요약 : 다차원 배열 큐브에 데이터를 미리 집계해 두어 분석 질의에 즉시 응답하는 OLAP 기술.
- 개념 : 데이터를 다차원 배열 구조의 큐브에 저장하고 차원 조합별 집계를 미리 계산해 두는 **MOLAP**(Multidimensional Online Analytical Processing, 다차원 온라인 분석 처리).
- 배경 및 필요성 : 관계형 OLAP(ROLAP, Relational Online Analytical Processing)은 구조적 질의 언어(SQL, Structured Query Language)로 집계를 실행 시점에 계산하므로, 대용량 집계에서 응답 지연이 커져 사전 집계 방식이 필요해짐.
- 주요 목적 : 여러 차원에 걸친 분석 질의를 배열 접근 수준(O(1))으로 빠르게 응답.

## Ⅱ. MOLAP의 특징 및 장점

- 핵심 요약 : 다차원 배열, 사전 집계, 조인 배제가 맞물려 조회 속도를 높이고, 희소성 압축으로 메모리 효율을 보완.

1. **다차원 큐브**(OLAP Cube, 차원 축으로 이루어진 집계 데이터 공간) : 시간, 지역, 상품 같은 차원을 배열 인덱스로 사용 → 좌표 계산만으로 셀에 직접 접근.
2. **사전 집계**(Pre-aggregation, 적재 시점에 차원 조합별 합계를 미리 계산) : 질의 시점의 계산을 없애 응답 시간을 일정하게 유지.
3. 조인 배제 : 여러 테이블을 조인하지 않고 배열 오프셋으로 값을 찾아 조인 비용을 제거.
4. **희소성 압축**(Sparsity Compression, 값이 없는 셀을 제외하고 저장) : CSR(Compressed Sparse Row)과 CSC(Compressed Sparse Column) 같은 희소 행렬 형식을 적용 → 빈 셀의 저장 공간 절감.
5. **HOLAP**(Hybrid Online Analytical Processing, 요약 큐브와 상세 관계형 데이터를 결합한 방식) : 인메모리 MOLAP과 ROLAP을 연계 → 요약 분석의 속도와 상세 추적을 함께 확보.

## Ⅲ. 큐브 구조와 처리 흐름

- 핵심 요약 : 적재 시 큐브에 사전 집계를 쌓고 조회 시 배열 좌표로 응답하는 흐름이며, 차원이 늘면 큐브가 기하급수로 커지는 구조.

```text
[ MOLAP 처리 흐름 ]

원천 데이터 (배치 적재)
   ↓
차원 조합별 사전 집계
   ↓
다차원 배열 큐브 저장
   ↓
질의 → 좌표 계산 → 셀 값 반환
```

```text
[ 큐브 폭발 ]

전체 셀 수 = C1 × C2 × ... × CD
(Ci : i번째 차원의 항목 수, D : 차원 수)
예) 항목 100개 × 10차원 = 10^20 셀
```

## Ⅳ. MOLAP과 ROLAP 비교

- 핵심 요약 : 저장 엔진, 집계 시점, 조회 속도, 확장성, 상세 추적의 다섯 축에서 두 방식이 대비됨.

| 비교 축 | MOLAP | ROLAP |
| --- | --- | --- |
| 저장 엔진 | 다차원 DB(MDDB, Multidimensional Database) 큐브 | 관계형 DB의 스타 스키마 |
| 집계 시점 | 적재 시 사전 집계 | 질의 시 SQL로 실시간 집계 |
| 조회 속도 | 배열 접근 기반으로 빠름 | 조인과 집계 복잡도에 따라 가변 |
| 확장성 | 큐브 크기가 메모리에 묶여 수십 GB 내외가 한계 | 관계형 DB 기반으로 대용량 확장에 유리 |
| 상세 추적 | 집계 단위 중심이며 원본 상세는 제약 | 로우 단위까지 드릴다운 가능 |

- 선택 기준 : 분석 질의가 반복적이고 차원과 집계 범위가 정해져 있으면 MOLAP, 상세 추적과 대용량 확장이 중요하면 ROLAP을 택함.

## Ⅴ. MOLAP의 한계와 방안

- 핵심 요약 : 큐브 폭발과 희소성은 차원 선택과 압축으로, 확장 한계는 HOLAP 구조로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 큐브 폭발 | 차원 수와 항목 수의 곱으로 셀 수가 기하급수 증가 | 희소 압축(CSR, CSC), 자주 쓰는 차원 조합만 사전 집계 | 큐브 크기 |
| 희소성 | 실제 값이 있는 셀이 전체의 일부에 그쳐 메모리 낭비 | 빈 셀 제거, 좌표만 저장 | 압축률 |
| 확장성 한계 | 큐브 크기가 메모리 용량에 묶여 대용량 처리가 어려움 | 관계형 저장소와 연계하는 HOLAP 구조, 인메모리 큐브 최적화 | 처리량 |

## Ⅵ. MOLAP에 대한 기술사적 제언

- 핵심 요약 : 인메모리 큐브와 관계형 상세 저장소를 결합하고, 질의 로그로 사전 집계 범위를 정하는 하이브리드 운영이 필요.
1. 질의 로그를 분석해 빈도가 높은 차원 조합만 사전 집계하는 방식(파레토 원칙 적용)으로 큐브 크기를 통제할 필요가 있다.
2. 고속 응답이 필요한 요약 분석은 인메모리 MOLAP 엔진(예: Microsoft VertiPaq)에, 상세 조회는 관계형 저장소에 맡기는 HOLAP 구조를 도입할 필요가 있다.
3. 질의 패턴이 바뀌면 사전 집계 범위를 주기적으로 재평가하는 운영 절차를 둘 필요가 있다.

## Ⅶ. 결론

- 핵심 요약 : MOLAP은 다차원 배열의 사전 집계로 빠른 분석을 얻는 기술이며, 큐브 폭발이 핵심 과제.
- 시사점 : 질의 패턴에 맞춘 집계 범위 설정과 HOLAP 결합이 대용량 분석 설계의 현실적 기준.
