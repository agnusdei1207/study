## 2~4교시 25점 답안

### 답안 골격
```text
[MOLAP (Multidimensional OLAP)] ◀━━ 머리: Ⅶ 내 의견 (사전 집계 기반 초고속 다차원 탐색과 큐브 폭발 방지를 위한 HOLAP 절충)
 ┃
 ┣━ Ⅰ 개요 ───── 데이터를 관계형 테이블이 아닌 다차원 배열(Multi-dimensional Array) 구조의 전용 큐브(Cube)에 사전 요약·적재하여 즉각적인 분석을 제공하는 OLAP
 ┣━ Ⅱ 특징 ───── 다차원 전용 스토리지(MDDB) 사용 · 사전 집계(Pre-aggregation)로 $O(1)$ 즉시 응답 · 5대 기본 연산 지원 · 차원 증가 시 큐브 폭발(Cube Explosion)
 ┣━ Ⅲ 구조 ───── 다차원 큐브(차원 축 + 교차점 측정값) ┃ 5대 연산(Roll-up, Drill-down, Slicing, Dicing, Pivoting)
 ┣━ Ⅳ 흐름 ───── ① DW 정형 데이터 추출 → ② 차원/측정값 모델링 → ③ 큐브 빌드(모든 차원 조합 사전 연산) → ④ 다차원 스토리지 적재 → ⑤ BI 다차원 슬라이싱 분석
 ┣━ Ⅴ 비교 ───── MOLAP vs ROLAP vs HOLAP (전용 다차원 큐브/초고속/용량제한 vs RDB 스타스키마/유연함/느림 vs 상위 MOLAP + 상세 ROLAP 절충)
 ┗━ Ⅵ 실무 ───── 차원 수 증가에 따른 큐브 크기 지수적 폭증(Cube Explosion) / 큐브 재생성(Rebuild) 야간 배치 지연
```
- 필수 키워드: MOLAP · 다차원 큐브(Cube) · ROLAP · HOLAP · 사전 집계(Pre-aggregation) · 롤업(Roll-up) · 드릴다운(Drill-down) · 슬라이싱/다이싱 · 큐브 폭발
- 기출: 114회 `온라인 분석 처리 기술인 OLAP의 3가지 유형(MOLAP, ROLAP, HOLAP)을 비교하고, MOLAP의 구조적 특징과 장단점을 설명하시오.` → Ⅰ 정의 + Ⅲ 큐브 구조 및 5대 연산 + Ⅴ 3대 OLAP 비교표 + Ⅵ 큐브 폭발 해결책

### 한 줄 본질
- 수억 건의 관계형 테이블을 런타임에 GROUP BY 조인하면 대화형 분석이 불가능할 정도로 느려짐 → 가능한 모든 차원 조합의 집계값을 다차원 큐브에 미리 계산해 두고 즉시 조회 → 서브세컨드 분석 보장 / 차원 추가 시 저장 공간 지수함수 폭증

### 핵심 그림
```text
[MOLAP 3차원 데이터 큐브(Cube) 구조 및 핵심 5대 연산]

                  [상품 차원 (Product)]
                     ┌───────┬───────┬───────┐
                    ╱       ╱       ╱       ╱│
                   ├───────┼───────┼───────┤ │
                  ╱       ╱       ╱       ╱│ │
                 ┌───────┬───────┬───────┐ │ │
  [지역 차원]    │       │ $350  │       │ │ │  [시간 차원 (Time)]
  (Region)       ├───────┼───────┼───────┤ │╱   - 1분기, 2분기, 3분기...
  - 서울, 부산...│       │       │       │ ╱
                 └───────┴───────┴───────┘
  ─────────────────────────────────────────────────────────────────
  [5대 핵심 OLAP 연산]
  1. Roll-up    : 소계에서 대계로 요약 (시/군/구 -> 시/도)
  2. Drill-down : 상위 요약에서 상세 데이터로 파고듦 (연도 -> 분기 -> 월)
  3. Slicing    : 다차원 큐브에서 특정 1개 차원의 단면을 자름 (예: 2026년 실적만)
  4. Dicing     : 두 개 이상의 차원에서 작은 부분 큐브를 추출
  5. Pivoting   : 보고서의 행과 열 축을 90도 회전하여 관점 전환
```

### 핵심 용어
- 큐브 폭발(Cube Explosion): 분석할 차원(Dimension)과 각 차원의 계층(Hierarchy)이 늘어남에 따라 사전 계산해야 할 조합의 수($\prod N_i$)가 지수함수적으로 증가하여 스토리지 용량을 초과하는 현상
- 희소성(Sparsity): 다차원 큐브의 수많은 셀(Cell) 조합 중 실제로 데이터(매출 실적)가 존재하는 유효 셀은 1% 미만이고 99%가 빈 공간(NULL)으로 낭비되는 특성

### 핵심 통찰
- MOLAP의 응답 속도가 빛처럼 빠른 이유는 '쿼리 시점에 계산을 아예 안 하기 때문'임 → 사용자가 대시보드를 열기 전날 밤 새벽 배치에서 수억 번의 덧셈을 미리 다 끝내놓고 메모리 큐브에 넣어둠
- 하지만 차원이 10개를 넘어가면 큐브 폭발이 일어나 원본 데이터가 10GB인데 큐브 용량은 10TB로 불어나는 수학적 재앙이 닥침
- 이를 해결하기 위해 현업에서는 상위 집계 20%만 MOLAP 큐브로 빠르게 띄우고, 드릴다운해서 들어가는 하위 80% 세부 원장은 관계형 RDB로 내려보내는 '하이브리드 OLAP(HOLAP)' 아키텍처를 채택

### 이웃 토픽과 구분
- MOLAP vs ROLAP: MOLAP = 다차원 배열 전용 스토리지(MDDB)를 써서 사전 집계하므로 초고속이나 확장성 한계 / ROLAP = 표준 관계형 DB(RDBMS)의 스타 스키마 위에서 동적 SQL로 집계하므로 유연하고 대용량 수용이 가능하나 쿼리 속도가 상대적으로 느림

### 이렇게 출제된다
- 제114회: "온라인 분석 처리(OLAP)의 주요 유형인 MOLAP, ROLAP, HOLAP의 개념과 특징을 비교 설명하고, MOLAP의 다차원 큐브 구조와 5가지 핵심 다차원 분석 연산을 기술하시오." → 요구 포인트: 3대 OLAP 비교표 + 3차원 큐브 도식 + 5대 연산(Roll-up, Drill-down, Slicing, Dicing, Pivoting) + 큐브 폭발 대책

### 내 의견
- [레거시 MOLAP 큐브에서 실시간 칼럼형 OLAP로의 진화] 과거 Cognos나 SSAS 시절의 무거운 사전 빌드형 MOLAP 큐브를 고집하다가 실시간 데이터 분석 요구를 맞추지 못하는 기술적 낙후 발생 → 나라면: ClickHouse, Apache Druid 같은 최신 컬럼 지향 실시간 OLAP 엔진을 도입하여, 사전 큐브 생성 없이도 수십억 건의 데이터를 수백 밀리초 내에 벡터화 연산(SIMD)으로 즉시 슬라이싱·다이싱하는 현대화된 분석 인프라 구축
