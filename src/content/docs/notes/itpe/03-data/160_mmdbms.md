## 연관 키워드

- MMDBMS, 메인 메모리 DBMS, 직접 포인터, T-Tree
- WAL, 체크포인팅, NVRAM, Tiered Storage
- DRDBMS, NUMA

## Ⅰ. 메인 메모리 DBMS의 개요

- 핵심 요약 : 데이터를 주기억장치(RAM, Random Access Memory)에 상주시켜 디스크 입출력 없이 질의를 처리하는 초고속 데이터베이스 관리 시스템.
- 개념 : 데이터 전체 또는 대부분을 주기억장치에 상주시켜 질의를 처리하는 **메인 메모리 DBMS**(MMDBMS, Main Memory Database Management System).
- 배경 및 필요성 : 디스크 기반 DBMS는 버퍼 관리와 디스크 입출력이 지연의 주된 요인이 되므로, 실시간 응답이 필요한 거래와 통신 처리에는 메모리 상주형 구조가 필요해짐.
- 주요 목적 : 디스크 입출력 병목을 구조적으로 제거해 마이크로초 단위 응답을 확보하고, 메모리 휘발성은 로그 기반 영속화와 체크포인팅으로 보완.

## Ⅱ. 메인 메모리 DBMS의 특징 및 장점

- 핵심 요약 : 직접 포인터, T-Tree, 로그 기록이 결합되어 입출력 없는 초고속 처리와 데이터 영속성을 함께 확보.

1. **직접 포인터**(Direct Pointer) : 인덱스가 레코드의 메모리 주소를 직접 가리킴 → ROWID 변환 없이 한 번의 참조로 접근.
2. **T-Tree**(메모리 상주 데이터용 인덱스 구조) : AVL 트리의 균형 구조와 B-Tree처럼 노드마다 여러 키를 담는 방식을 결합 → 메모리에서 빠른 탐색과 낮은 갱신 비용.
3. **WAL**(Write-Ahead Logging, 변경 내용을 데이터 반영 전에 로그로 먼저 기록하는 방식) : 변경분을 Redo 로그로 디스크에 순차 기록 → 정전 시 복구의 근거 확보.
4. **체크포인팅**(Checkpointing) : 메모리 상태를 주기적으로 디스크에 스냅샷으로 저장 → 복구 시 재적용할 로그 양 축소.
5. **비휘발성 메모리**(NVRAM, Non-Volatile Random Access Memory) : 전원이 끊겨도 내용을 유지하는 메모리 또는 정전 시 데이터를 보존하는 장치(예: NVDIMM(Non-Volatile Dual In-line Memory Module)) → 휘발성 유실 위험 완화.

## Ⅲ. 아키텍처 흐름

- 핵심 요약 : RAM 상주 처리와 로그·체크포인트 기반 디스크 영속화가 결합된 구조.
- 비교 대상 : 디스크 상주형 DBMS(DRDBMS, Disk-Resident DBMS)와 메인 메모리 DBMS.

```text
[ 디스크 기반 vs 메인 메모리 ]

DRDBMS
  애플리케이션 → 버퍼 풀
              → (미스 시) 디스크 입출력

MMDBMS
  애플리케이션 → RAM 직접 포인터 접근
```

```text
[ 영속성 확보 경로 ]

트랜잭션 변경
   ↓
RAM 갱신 + WAL 순차 기록
   ↓
커밋 응답
   ↓
백그라운드 체크포인트 (스냅샷)
```

## Ⅳ. DRDBMS와 MMDBMS 비교

- 핵심 요약 : 데이터 위치, 인덱스 참조, 버퍼 관리, 영속성, 응답 지연의 다섯 축에서 두 방식이 대비됨.

| 비교 축 | DRDBMS | MMDBMS |
| --- | --- | --- |
| 데이터 위치 | 디스크와 버퍼 풀 | RAM 상주 |
| 인덱스 참조 | ROWID로 디스크 위치 변환 | 메모리 주소 직접 참조 |
| 버퍼 관리 | 적재와 교체를 관리해야 함 | 별도의 버퍼 관리가 불필요 |
| 영속성 | 디스크 기록이 기본 | 로그, 체크포인트, 비휘발성 장치 |
| 응답 지연 | 밀리초 수준 | 마이크로초 수준 |

- 선택 기준 : 응답 시간이 핵심이고 데이터가 메모리에 들어갈 규모이면 MMDBMS, 대용량 데이터를 비용 효율로 저장해야 하면 DRDBMS를 택함.

## Ⅴ. 메인 메모리 DBMS의 한계와 방안

- 핵심 요약 : 휘발성, 용량과 비용, NUMA 병목을 비휘발성 메모리, 계층 저장, NUMA 인지 설계로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 휘발성 유실 | 정전이나 장애 시 메모리 내용 소실, 긴 복구 시간 | NVDIMM과 CXL(Compute Express Link) 기반 영속 메모리 활용, 체크포인트 주기 최적화 | 복구 시간 |
| 용량과 비용 | DRAM(Dynamic Random Access Memory) 단가가 높고, 데이터 증가 시 메모리 부족(OOM, Out of Memory) 장애 | 핫·콜드 데이터를 나누는 계층 저장(Tiered Storage), 압축 | 메모리 사용률 |
| NUMA(Non-Uniform Memory Access) 병목 | 다중 소켓 환경에서 원격 메모리 접근 지연 | NUMA 인지 메모리 할당, 스레드 고정, 캐시 친화적 자료구조 | 캐시 미스율 |

## Ⅵ. 메인 메모리 DBMS에 대한 기술사적 제언

- 핵심 요약 : 핫 데이터는 메모리에, 콜드 데이터는 디스크 기반 저장소에 두는 하이브리드 설계로 성능과 비용을 함께 맞출 것.
1. 업무 데이터를 접근 빈도에 따라 나누어, 응답 시간이 중요한 핫 데이터는 메인 메모리 DBMS에, 이력성 콜드 데이터는 디스크 기반 DB나 레이크하우스(Lakehouse)에 두는 구조를 설계할 필요가 있다.
2. 캐시 미스를 줄이기 위해 벡터화 실행(SIMD, Single Instruction Multiple Data)을 질의 엔진에 적용하고 데이터 메모리 정렬을 맞추는 최적화를 도입할 필요가 있다.
3. 비휘발성 메모리 같은 영속성 장치의 도입은 목표 복구 시간을 기준으로 판단할 필요가 있다.

## Ⅶ. 결론

- 핵심 요약 : 메인 메모리 DBMS는 RAM 상주와 로그, 체크포인트 기반 영속화로 초고속 처리를 얻는 방식이며, 휘발성, 용량, NUMA가 핵심 과제.
- 시사점 : 핵심 데이터에만 적용하는 하이브리드 설계가 현실적인 선택지임.
