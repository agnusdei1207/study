## Ⅰ. 디스크 I/O 병목의 근원적 극복, 메인 메모리 DBMS 개요

### 가. 메인 메모리 DBMS(MMDBMS / IMDB)의 정의
- 데이터베이스의 모든 데이터(테이블 및 인덱스)를 디스크가 아닌 **컴퓨터의 주기억장치(RAM)에 상주(In-Memory)시켜 운영** 함으로써, 디스크 I/O에 수반되는 기계적 헤드 이동과 버퍼 캐시 관리 오버헤드를 배제하고 마이크로초(µs) 단위의 초고속 트랜잭션 처리를 달성하는 데이터베이스 관리 시스템.

### 나. 전통적 디스크 기반 DBMS(DRDBMS)와의 아키텍처 비교

```text
[ DRDBMS vs MMDBMS 아키텍처 비교 ]
(A) 디스크 기반 DBMS (DRDBMS)
    [App] ---> [Buffer Pool (메모리 룩업)] ===(Cache Miss 시 디스크 I/O)===> [HDD/SSD]
    - 복잡한 버퍼 관리, 이중 페이징, 인덱스에 디스크 포인터(ROWID) 변환 필요

(B) 인메모리 DBMS (MMDBMS)
    [App] ---> [모든 데이터가 RAM에 직접 상주 (직접 메모리 포인터 접근)]
                   | (비동기 로깅 / 주기적 체크포인트 스냅샷만 디스크로)
                   v
               [Non-Volatile Disk / NVRAM (백업 및 영속성 보장용)]
```

## Ⅱ. MMDBMS의 핵심 최적화 기술 및 내부 구조

### 가. 직접 메모리 포인터(Direct Memory Pointer) 접근
- 디스크 기반 DB처럼 "블록 번호 + 슬롯 번호"로 구성된 ROWID를 디스크 주소 변환 테이블을 거쳐 물리 메모리로 변환하는 간접 계층이 전혀 없으며, **인덱스의 리프가 실제 데이터 레코드의 64비트 메모리 주소(Pointer)를 직접 가리켜 $O(1)$의 초고속 역참조** 수행.

### 나. T-Tree 인덱스 구조 (메모리 최적화 트리)

```text
[ T-Tree 노드 구조 ]
              [ 부모 노드 포인터 ]
              [ 좌/우 자식 포인터 ]
    +---------------------------------------+
    | 최소키 | 키1 | 키2 | ... | 키N | 최대키 |  <-- 하나의 노드에 정렬된 키 배열 보관
    +---------------------------------------+
- AVL Tree의 뛰어난 이진 탐색 균형성 + B-Tree의 높은 메모리 밀집도 결합
- 포인터 크기 오버헤드를 대폭 절감하고 메모리 단편화 최소화
```

## Ⅲ. MMDBMS의 영속성(Durability) 및 장애 복구 메커니즘

### 가. 휘발성(Volatility) 한계 극복을 위한 3대 영속성 보장 기술
1. **WAL (Write-Ahead Logging)** : 데이터 변경 시 메모리 갱신과 동시에 비휘발성 디스크(또는 초고속 NVMe)의 트랜잭션 로그 파일에 순차(Sequential) Redo 로그를 영구 기록.
2. **체크포인팅 (Fuzzy Checkpointing)** : 운영 트랜잭션을 중단하지 않고 백그라운드 스레드가 메모리 데이터베이스 전체의 일관된 스냅샷 덤프를 디스크에 정기 저장.
3. **비휘발성 메모리(NVRAM / NVDIMM) 활용** : 정전 시 슈퍼커패시터 전력으로 메모리 내용을 플래시로 긴급 백업하는 NVDIMM을 로그 버퍼로 사용하여 지연 시간 0 달성.

## Ⅳ. 금융 및 실시간 통신 시스템 적용 실무 제언

- **용량 한계와 하이브리드 티어링(Hybrid Tiering) 설계** : RAM은 디스크 대비 기가바이트당 비용이 수십 배 비싸므로, 모든 데이터를 메모리에 넣는 것은 비현실적임. 따라서 초고속 처리가 필수적인 핫 데이터(당일 거래 원장, 실시간 세션)는 MMDBMS(Redis, Altibase)에 두고, 콜드 데이터(과거 이력)는 디스크 RDBMS나 레이크하우스로 자동 티어링하는 하이브리드 아키텍처를 구축해야 함.
- **CPU 캐시 미스(Cache Miss) 최적화** : 현대 고속 MMDBMS의 진정한 병목은 메모리 버스 대역폭과 CPU L1/L2 캐시 미스이므로, 행 단위(Row-oriented) 저장이 아닌 컬럼 단위 벡터화 실행(SIMD) 및 메모리 정렬(Data Alignment)을 적용한 인메모리 엔진을 우선 검토할 것을 제언함.
