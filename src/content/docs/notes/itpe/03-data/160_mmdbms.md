## 30초 인출

- 본질: 메인 메모리 DBMS는 주 데이터를 메모리에 상주시켜 질의·갱신하는 DBMS
- 메커니즘: 질의·갱신을 메모리에서 처리해 저장장치 접근을 줄이고, 변경은 로그(커밋 이후 재생)와 체크포인트(복구 기준 상태)로 영속화하며 장애 후 체크포인트에 로그를 재실행해 복원
- 통찰: 메모리 상주만으로 내구성이 확보되지 않고 커밋 응답과 로그 안정 저장의 선후가 손실 범위를 정하므로, 업무 RPO에 맞춰 로그 영속화·복제 응답 조건을 정하고 체크포인트를 포함한 복구 시간을 시험

<details>
<summary>핵심 용어</summary>

- **MMDBMS** : 주 데이터를 메모리에 두고 처리하는 DBMS
- **디스크 중심 DBMS** : 영속 저장소가 주 저장 위치이고 메모리는 캐시·버퍼인 DBMS
- **로그(WAL 등)** : 변경 내용을 순서대로 안정 저장해 재실행하는 기록
- **체크포인트** : 복구의 기준이 되는 메모리 상태의 저장 시점
- **RPO** : 허용 데이터 손실 시점 차이
- **내구성 정책** : 커밋 응답 전 로그를 안정 저장하는지의 설정

</details>

## 2~4교시 25점 답안

## Ⅰ. 메인 메모리 DBMS의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **MMDBMS** 는 주 데이터를 메모리에 상주시켜 질의·갱신하는 DBMS |
| 목적 | 저장장치 접근을 줄여 응답 지연을 낮추고 요구한 복구 수준 확보 |

## Ⅱ. 특징

| 특징 | 설계 영향 |
|---|---|
| 메모리 상주 | 저장장치 접근 감소 |
| 별도 영속 경로 | 로그·체크포인트로 장애 후 복구 |
| 내구성 정책 의존 | 커밋 응답과 로그 저장의 선후가 손실 범위 결정 |

## Ⅲ. 처리와 복구

```text
메모리 상주 데이터 ─ 빠른 질의·갱신
   변경 ├ 로그: 커밋 이후 변경 재생 ┐
        └ 체크포인트: 복구 기준 상태 ┴→ 장애 후 상태 복원
```

```text
메모리 변경 → 로그 안정 저장 확인 → 커밋 응답 : 약속한 장애 범위의 내구성
메모리 변경 → 로그 확인 전 응답  → 장애 시 최근 변경 손실 가능
```

## Ⅳ. 디스크 중심 DBMS와 비교

| 비교 축 | 디스크 중심 | 메인 메모리 |
|---|---|---|
| 주 데이터 위치 | 영속 저장소, 메모리는 캐시 | 메모리 상주 |
| 접근 비용 | 캐시 적중과 I/O 영향 | 메모리 처리 비중이 큼 |
| 용량·비용 | 저장장치 중심 | 메모리 용량·비용 제약 |
| 장애 복구 | 로그·데이터 파일 | 로그·체크포인트 등 영속 경로 |

두 구조 모두 제품과 설정에 따라 메모리·디스크를 함께 활용할 수 있고 특정 인덱스·SQL 기능을 모든 MMDBMS의 필수 속성으로 단정하지 않음.

| 확인 항목 | 판단 |
|---|---|
| 로그 영속화 시점 | 커밋 응답과 실제 영속 저장의 선후 |
| 체크포인트 주기 | 재시작 시 재실행할 로그 범위와 복구 시간 |
| 복제 방식 | 복제 확인 시점·장애 범위에 따른 손실 가능성 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 메모리 용량·비용 제약 | 상주 데이터·인덱스 규모를 측정해 배치 결정 |
| 비내구성 설정에서 최근 커밋 손실 | 업무 RPO에 맞춰 로그 영속화·복제 응답 조건 선택 |
| 복구 시간이 예상보다 길어짐 | 체크포인트·로그 재실행을 포함한 복구 시험 |

## Ⅵ. 제언

지연 요구가 높은 데이터만 메모리에 상주시키고, 업무 RPO에 맞춰 내구성 설정과 복구 시간을 시험

```text
지연 민감 데이터 선별 → 상주 규모 산정 → 로그·체크포인트·복제 설정 → 복구 시간 시험
```

| 구분 | 전 데이터 메모리 상주·기본 설정 | 제언: 선별 상주 + 내구성 시험 |
|---|---|---|
| 비용 | 큼 | 필요한 데이터만 |
| 손실 | 설정 미확인 | RPO로 관리 |
