## 연관 키워드

- 팬텀 충돌

## Ⅰ. 팬텀 충돌의 개요

- 핵심 요약 : 범위 검색 결과 집합에 타 트랜잭션의 신규 삽입이 침투하여 유령 행이 출현하는 동시성 이상 현상.
- 개념 : 트랜잭션 $T_1$이 특정 검색 조건(술어, Predicate)을 만족하는 행 집합을 두 번 이상 읽을 때, 트랜잭션 $T_2$가 조건에 부합하는 새 행을 삽입하거나 기존 행을 조건 범위로 수정·편입시킨 후 커밋하여 $T_1$의 후속 조회에 이전에 없던 유령(Phantom) 행이 출현하는 현상.
- 배경 및 필요성 :
  1. 행 단위 잠금으로는 아직 존재하지 않는 미래 레코드를 잠글 수 없는 근본적 한계.
  2. 동일 조건의 재조회 결과 불일치에 따른 집계·정산 오류 방지 필요.
  3. 격리 수준과 동시성 처리량 간의 트레이드오프 관리 필요.
- 주요 목적 : 범위 조건 기반의 직렬 가능성 보장과 유령 행 차단.

## Ⅱ. 팬텀 충돌의 특징

- 핵심 요약 : 결과 집합의 행 개수 변동, 술어 단위 잠금의 한계, 갭 기반 구간 방어.

1. 결과 집합의 행 개수 변동 : 단일 행의 값 변경이 아닌 행의 출현·소멸에 의한 개수 변화.
2. 술어 단위 잠금의 한계 : 조건절 자체를 잠글 수 없어 미래 레코드의 삽입 차단 불가.
3. 갭 기반 구간 방어 : 인덱스 키 사이의 공백(갭)을 잠금으로써 삽입 지점의 선제 차단.
4. 격리 수준과의 연계 : 격리 수준에 따른 팬텀 발생 허용 여부의 차이.

## Ⅲ. 팬텀 충돌의 구조 (흐름)

- 핵심 요약 : 두 트랜잭션의 교차 타임라인과 넥스트 키 락의 갭 잠금 구조.

```text
[ 팬텀 충돌 발생 타임라인 ]
 T1 (급여 조회)                      T2 (신규 채용)
 -----------------------------------------------
 BEGIN;
 SELECT * FROM EMP
   WHERE dept='IT' AND sal>=5000;    (3명 반환)
                                     BEGIN;
                                     INSERT INTO EMP
                                       VALUES (104,'IT',6000);
                                     COMMIT;
 SELECT * FROM EMP
   WHERE dept='IT' AND sal>=5000;    (4명 반환 → 유령 행)
 COMMIT;
```

```text
[ 넥스트 키 락의 갭 잠금 구조 ]
인덱스 키: ... (10) --- [GAP 1] --- (20) --- [GAP 2] --- (30) ...
WHERE id BETWEEN 15 AND 25 조회 시
  키 20 레코드 락 + GAP 1 (10<id<20) + GAP 2 (20<id<=30) 모두 잠금
  → 타 트랜잭션의 id=18, id=22 삽입 대기
```

## Ⅳ. 팬텀 읽기와 비재현 판독의 비교

- 핵심 요약 : 행의 값 변경 대 행의 출현·소멸, 단일 행 잠금과 구간 잠금의 방어 범위 차이.

| 비교 항목 | 비재현 판독(Non-Repeatable Read) | 팬텀 읽기(Phantom Read) |
| :--- | :--- | :--- |
| 변동 대상 | 기존 단일 행의 값 | 결과 집합의 행 개수 |
| 유발 연산 | 기존 행의 UPDATE·DELETE | 조건 범위 내 INSERT·UPDATE |
| 방어 단위 | 행 단위 잠금 | 구간(갭) 잠금 |
| 전형 기법 | 공유락·레코드 락 | 넥스트 키 락·술어 잠금 |
| 직관적 예 | 재조회 시 급여 값 변경 | 재조회 시 신규 사원 추가 |

## Ⅴ. 팬텀 충돌 제어의 장점과 한계

- 핵심 요약 : 정합성 보장·직렬성 확보의 장점과 동시성 저하·구현 복잡성의 한계.

- 장점
  1. 범위 조건 기반 집계 결과의 일관성 보장.
  2. 유령 행에 의한 업무 오류와 정산 불일치 차단.
  3. 직렬 가능성 수준의 데이터 정합성 유지.

- 한계점 1 : 술어 잠금의 구현 불가와 동시성 저하
  - 한계점 : 조건절 자체를 잠금으로 설정하는 술어 잠금은 교집합 판별이 복잡해 상용 DBMS(Database Management System)에서 구현 불가, 넥스트 키 락은 불필요한 인접 키 삽입까지 대기시켜 동시성 저하.
  - 해결 방안 : 기본 격리는 READ COMMITTED 유지, 일관 집계가 필수인 배치에 한정해 스냅샷 격리 적용.
- 한계점 2 : 인덱스 부재 시 테이블 잠금 격상
  - 한계점 : 검색 조건 컬럼에 인덱스가 없으면 범위 잠금이 테이블 전체 잠금으로 확산(Lock Escalation)되어 동시 처리량 급락.
  - 해결 방안 : WHERE 조건 컬럼에 B-Tree 인덱스 필수 생성, 락 에스컬레이션 모니터링.
- 한계점 3 : SSI 환경의 충돌 롤백 비율 증가
  - 한계점 : MVCC 기반 SSI는 락 없는 고속 읽기를 지원하되, 충돌 빈발 시 트랜잭션 중단(Abort) 비율이 증가.
  - 해결 방안 : 경합 데이터 접근 순서의 표준화, 재시도 정책과 지수 백오프 적용.

## Ⅵ. 팬텀 충돌에 대한 기술사적 제언

- 핵심 요약 : 격리 수준의 선택적 적용, 인덱스 기반 범위 잠금 유지, 배치 집계의 스냅샷 격리.
- 격리 수준의 선택적 적용 : 시스템 전체를 SERIALIZABLE로 설정하는 맹목적 남용 지양, 기본은 READ COMMITTED 유지와 일관 집계 배치의 스냅샷 격리 활용.
- 인덱스 기반 범위 잠금 유지 : 범위 잠금이 테이블 잠금으로 확산하지 않도록 조건 컬럼의 B-Tree 인덱스 설계.
- 동시성과 정합성의 균형 : 락 경합이 집중되는 핫스팟 데이터의 접근 순서 표준화와 트랜잭션 최소화.

## Ⅶ. 결론

- 핵심 요약 : 팬텀 충돌은 구간 잠금과 격리 수준의 균형 설계로 통제하는 동시성 이상 현상.
- 요약 : 유령 행 출현 메커니즘과 비재현 판독과의 차이, 넥스트 키 락·SSI 방어 기법.
- 시사점 : 인덱스 설계와 격리 수준 선택을 통한 정합성·동시성의 최적화 필요.
