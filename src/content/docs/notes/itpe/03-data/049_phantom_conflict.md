## 연관 키워드

- 팬텀 충돌, 팬텀 읽기, 술어 잠금, 갭 잠금, 넥스트 키 락, 격리 수준, SSI

## Ⅰ. 팬텀 충돌의 개요

- 핵심 요약 : 범위 검색 결과 집합에 다른 트랜잭션의 신규 삽입이 끼어들어 유령 행이 나타나는 **팬텀 충돌** 현상.
- 개념 : 트랜잭션 $T_1$이 같은 검색 조건으로 행 집합을 두 번 이상 읽는 사이, $T_2$가 조건에 맞는 새 행을 삽입하거나 기존 행을 조건 범위로 수정해 커밋하면, $T_1$의 후속 조회에 이전에 없던 유령(Phantom) 행이 출현하는 현상.
- 배경 및 필요성 :
  1. 행 단위 잠금으로는 아직 존재하지 않는 미래 레코드를 잠글 수 없는 근본적 한계.
  2. 같은 조건의 재조회 결과가 달라져 집계·정산 오류가 생기는 것을 막을 필요.
  3. **격리 수준**과 동시성 처리량 사이의 트레이드오프 관리 필요.
- 주요 목적 : 범위 조건 기반의 직렬 가능성을 보장하고 유령 행을 차단.

## Ⅱ. 팬텀 충돌의 특징 및 장점

- 핵심 요약 : 결과 집합의 행 수가 변하는 동시성 이상 현상이며, 행 단위 잠금으로는 막을 수 없어 구간 단위 방어가 필요한 특성.

1. 결과 집합의 행 수 변동 : 단일 행의 값 변경이 아니라 행의 출현·소멸로 개수가 달라짐 → 집계 결과 불일치.
2. **술어 잠금** : 조건절 자체를 잠가 조건에 맞는 미래 레코드의 삽입을 막음 → 논리적으로는 정확하나 교집합 판별이 복잡해 구현이 까다로움.
3. **갭 잠금** : 인덱스 키 사이의 공백(갭)을 잠가 삽입 지점을 선제 차단 → 구간 단위 정합성 확보.
4. **넥스트 키 락** : 레코드 잠금과 앞쪽 갭 잠금을 합친 방식으로 구간 방어에 쓰이는 대표 기법 → 팬텀 차단과 동시에 인접 키 삽입까지 대기시키는 부작용.
5. 격리 수준과의 연계 : 격리 수준에 따라 팬텀 발생 허용 여부가 달라짐.

## Ⅲ. 팬텀 충돌의 구조 (흐름)

- 핵심 요약 : 두 트랜잭션의 교차 타임라인에서 신규 행이 끼어드는 과정과, 넥스트 키 락이 갭을 잠가 이를 막는 구조.

```text
[팬텀 충돌 발생 순서]
[T1] 조건 조회 (IT, 급여 5000 이상)
          ↓ 3명 반환
[T2] 신규 사원 INSERT 후 COMMIT
          ↓
[T1] 같은 조건 재조회
          ↓ 4명 반환 → 유령 행 출현
```

```text
[넥스트 키 락의 갭 잠금]
인덱스 키: 10 --[갭 1]-- 20 --[갭 2]-- 30
조회 범위 15~25
          ↓
키 20 레코드 + 갭 1 + 갭 2 잠금
          ↓
id 18, 22 삽입은 대기
```

## Ⅳ. 팬텀 읽기와 비재현 판독의 비교

- 핵심 요약 : **팬텀 읽기**는 행의 값 변경이 아니라 행의 출현·소멸이 문제이므로, 단일 행 잠금이 아닌 구간 잠금으로 방어.

| 비교 항목 | 비재현 판독 (Non-Repeatable Read) | 팬텀 읽기 (Phantom Read) |
| --- | --- | --- |
| 변동 대상 | 기존 단일 행의 값 | 결과 집합의 행 개수 |
| 유발 연산 | 기존 행의 UPDATE·DELETE | 조건 범위 내 INSERT·UPDATE |
| 방어 단위 | 행 단위 잠금 | 구간(갭) 잠금 |
| 전형 기법 | 공유 락·레코드 락 | 넥스트 키 락·술어 잠금 |
| 직관적 예 | 재조회 시 급여 값 변경 | 재조회 시 신규 사원 추가 |

## Ⅴ. 팬텀 충돌 제어의 한계와 방안

- 핵심 요약 : 정합성과 직렬성을 확보하는 장점 이면에 동시성 저하, 인덱스 부재에 따른 잠금 확산, 롤백 증가라는 한계.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 술어 잠금 구현의 어려움 | 조건 교집합 판별이 복잡해 범용 구현이 까다로움 | 기본 격리 수준을 유지하고 일관 집계가 필수인 배치에만 스냅샷 격리 적용 | 락 대기 시간 |
| 넥스트 키 락에 따른 동시성 저하 | 불필요한 인접 키 삽입까지 대기시킴 | 조건 컬럼 인덱스 설계로 잠금 범위 최소화 | 잠금 대기 건수 |
| 인덱스 부재 시 잠금 확산 | 범위 잠금이 테이블 전체 잠금으로 번지는 락 에스컬레이션(Lock Escalation) 발생 | WHERE 조건 컬럼에 B-Tree 인덱스 생성, 락 에스컬레이션 모니터링 | 락 에스컬레이션 발생 횟수 |
| 충돌 빈발 시 롤백 증가 | **직렬화 스냅샷 격리** (SSI, Serializable Snapshot Isolation)는 충돌이 잦으면 트랜잭션 중단 비율 증가 | 경합 데이터 접근 순서 표준화, 재시도 정책과 지수 백오프 적용 | 중단(Abort) 비율 |

## Ⅵ. 팬텀 충돌에 대한 기술사적 제언

- 핵심 요약 : 격리 수준을 선택적으로 적용하고, 인덱스 기반 범위 잠금을 유지하며, 배치 집계에만 스냅샷 격리를 쓰는 방식.
- 시스템 전체를 SERIALIZABLE로 설정하는 맹목적 남용은 피하고, 기본은 현행 격리 수준을 유지하되 일관된 집계가 필요한 배치에만 스냅샷 격리를 적용하는 것이 바람직하다.
- 범위 잠금이 테이블 잠금으로 번지지 않도록 조건 컬럼에 B-Tree 인덱스를 설계해 두어야 한다.
- 락 경합이 집중되는 핫스팟 데이터는 접근 순서를 표준화하고 트랜잭션을 짧게 유지해 동시성과 정합성의 균형을 맞춘다.

## Ⅶ. 결론

- 핵심 요약 : 팬텀 충돌은 구간 잠금과 격리 수준의 균형 설계로 통제하는 동시성 이상 현상.
- 시사점 : 인덱스 설계와 격리 수준 선택을 함께 최적화해야 정합성과 동시성을 동시에 확보할 수 있음.
