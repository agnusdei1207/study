## 연관 키워드
- 팬텀 읽기, 범위 검색, 직렬화 가능성, 범위 잠금, SSI, predicate lock

### Ⅰ. 팬텀 충돌의 개요

- 핵심 요약 : 팬텀 충돌은 동시 트랜잭션의 범위 조건에 새 행이 삽입·삭제되어 반복 질의 결과 집합이 달라지거나 직렬화 가능성을 위협하는 현상.
- 개념 : 동시 트랜잭션의 범위 조건에 새 행이 삽입·삭제되어 반복 질의 결과 집합이 달라지거나 직렬화 가능성을 위협하는 현상(**팬텀 충돌**, Phantom Conflict).
- 배경 및 필요성 : 행 잠금만으로는 아직 존재하지 않는 키 범위의 삽입을 막지 못함.
- 주요 목적 : 범위 기반 불변 조건과 직렬화 일관성 보장.

### Ⅱ. 팬텀 충돌의 특징 및 장점

- 핵심 요약 : 범위 조건·범위 잠금·SSI·직렬화 감지는 팬텀 충돌을 탐지하고 제어하는 메커니즘.

1. 범위 조건 : 동일 predicate 재조회에서 행 집합 변화 가능.
2. 범위 잠금 : 인덱스 키 구간 잠금 → 경쟁 삽입 차단.
3. SSI·직렬화 감지 : 위험한 의존성 탐지 후 트랜잭션 중단 가능.

### Ⅲ. 팬텀 충돌의 구조 (흐름)

- 핵심 요약 : T1 범위 조건 조회 → T2 조건에 맞는 신규 행 삽입·커밋 → T1 같은 조건 재조회 또는 직렬화 충돌 검출 → 격리 수준·DB 구현에 따라 대기·중단 처리.

```text
T1 범위 조건 조회
  ↓
T2 조건에 맞는 신규 행 삽입·커밋
  ↓
T1 같은 조건 재조회 또는 직렬화 충돌 검출
  ↓
격리 수준·DB 구현에 따라 대기·중단 처리
```

```text
T1: SELECT ... WHERE x BETWEEN a AND b
T2: INSERT x∈[a,b] → COMMIT
T1: 재조회 결과 변동 또는 serialization failure
```

### Ⅳ. 팬텀 읽기와 비 반복 읽기 비교

- 핵심 요약 : 방지 수단 기준 — 팬텀 읽기: 범위 잠금·직렬화·SSI 등; 비 반복 읽기: 행 잠금·MVCC 스냅샷 등.

| 비교 축 | 팬텀 읽기 | 비 반복 읽기 |
|---|---|---|
| 변화 대상 | 조건을 만족하는 행 집합 | 이미 읽은 특정 행의 값 |
| 방지 수단 | 범위 잠금·직렬화·SSI 등 | 행 잠금·MVCC 스냅샷 등 |

### Ⅴ. 팬텀 충돌의 한계와 방안

- 핵심 요약 : 격리 수준 오판·과도한 범위 잠금 등 주요 위험을 원인에 맞는 통제로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 격리 수준 오판 | 반복 읽기라는 이름이 팬텀 차단을 보장하지 않을 수 있음 | DBMS 공식 동작과 실제 격리 시험 확인 | 재현 건수 |
| 과도한 범위 잠금 | 넓은 범위 잠금으로 쓰기 경합 증가 | 적합 인덱스·좁은 predicate·적정 격리 수준 | 대기·교착률 |
| 직렬화 중단 미처리 | 충돌 후 재시도 없으면 업무 실패 | 멱등 재시도·백오프·트랜잭션 짧게 구성 | 재시도 성공률 |

### Ⅵ. 팬텀 충돌에 대한 제언

- 핵심 요약 : 애플리케이션 설계자는 범위 기반 업무 규칙을 식별해 DB 격리 수준·인덱스·재시도 정책으로 검증하고 DBMS별 동작을 테스트.

- 실행 제안 : DBA와 개발자는 실제 DBMS에서 범위 삽입 경쟁을 재현하고 직렬화 실패 재시도와 인덱스 계획 검증.

### Ⅶ. 결론

- 핵심 요약 : 팬텀 문제는 동일 행의 값 변경과 달리 조건을 만족하는 행 집합의 변화를 다루므로 범위 수준 제어 필요.
- 시사점 : 범위 조건의 직렬화 보장은 사용하는 DBMS의 격리 수준·인덱스·충돌 감지 방식으로 확인.
