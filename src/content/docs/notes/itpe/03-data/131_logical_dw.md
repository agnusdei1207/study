## 연관 키워드

- 논리적 데이터 웨어하우스(Logical DW)

## Ⅰ. 논리적 데이터 웨어하우스(Logical DW)의 개요

- 핵심 요약 : 전사 데이터를 단일 물리적 DW(Data Warehouse)로 이관하지 않고 데이터 가상화 기술로 분산 저장소를 논리적으로 통합 조회하는 현대 분석 아키텍처
- 개념 : 논리적 데이터 웨어하우스(Logical Data Warehouse, LDW)는 가트너(Gartner)가 제안한 아키텍처로, 전사 데이터를 단일 거대 물리적 DW로 물리 복사·이관(ETL, Extract, Transform, Load)하지 않고 데이터 가상화(Data Virtualization)와 분산 쿼리 페더레이션 기술을 활용하여 분산된 이종 저장소의 데이터를 논리적으로 단일한 DW처럼 통합 조회 가능하게 제공하는 현대적 분석 아키텍처
- 배경 : 전통적 물리적 DW는 전사 데이터 단일 저장소 적재를 위한 막대한 ETL 파이프라인 개발·유지보수 비용과 실시간 데이터 처리 불가, 스토리지 중복 비용 증가 등의 한계 존재
- 필요성 : 데이터 이동 없이 원천 시스템 실시간 데이터에 직접 접근하는 민첩한 분석 환경 필요성 대두
- 주요 목적 : 데이터 복제 최소화, 실시간 분석 가능, 신규 요구사항에 대한 신속한 대응체계 구축

## Ⅱ. 논리적 데이터 웨어하우스(Logical DW)의 특징

- 핵심 요약 : 데이터 이동 없는 제자리 질의(Query-in-place)와 실시간 데이터 접근, 민첩한 가상 뷰 변경이 물리적 DW와 구별되는 핵심 특성
- 특징 1 : 제자리 질의(Query-in-place) — 데이터를 이관하지 않고 원천 시스템에서 직접 쿼리 실행, 물리적 복사 없음(Zero-Copy)
- 특징 2 : 실시간 데이터 접근 — 원천 시스템의 현재 데이터에 직접 접근하여 배치 적재 주기(일/월)에 종속되지 않는 실시간 분석 제공
- 특징 3 : 민첩한 변경 대응 — 신규 컬럼·테이블 추가 시 ETL 재개발 없이 논리 가상 뷰(View) 수정만으로 신속 배포 가능
- 특징 4 : 통합 메타데이터 카탈로그 — 이종 저장소에 흩어진 데이터의 스키마, 위치, 비즈니스 정의를 단일 디렉토리로 관리

```text
[ Logical Data Warehouse (LDW) 아키텍처 ]
[소비자 계층]      : BI(Business Intelligence) 도구, SQL(Structured Query Language) 분석가, 머신러닝 파이프라인
                          ^
                          | (단일 가상 SQL 인터페이스)
[가상화/의미 계층] : [Data Virtualization & Semantic Layer]
                   - 통합 데이터 카탈로그, 논리 뷰(View), 분산 쿼리 푸시다운
                          |
[분산 저장소 계층] : +----+------------------+------------------+
                     |                      |                  |
                     v                      v                  v
              [기존 관계형 DW]       [데이터 레이크 (S3)]    [실시간 NoSQL(Not Only SQL)/Kafka]
              (정형 코어 원장)       (비정형/원천 대용량)   (초고속 스트리밍)
```

## Ⅲ. 논리적 데이터 웨어하우스(Logical DW)의 구조 (흐름)

- 핵심 요약 : 소비자-가상화-분산 저장소 3계층 구조로 단일 SQL 인터페이스를 통해 이종 저장소 통합 쿼리 수행

```text
[ 논리적 DW 쿼리 실행 흐름 ]
[사용자 SQL 쿼리] --> [가상화 엔진: 쿼리 분해 및 계획 수립]
                            |
            +---------------+---------------+
            |               |               |
            v               v               v
   [관계형 DW 쿼리]  [레이크 쿼리]   [실시간 쿼리]
            |               |               |
            +---------------+---------------+
                            |
                            v
                   [인메모리 결과 병합]
                            |
                            v
                    [통합 결과 반환]
```

| 기술 계층 | 주요 기술 요소 | 핵심 기능 및 역할 |
| :--- | :--- | :--- |
| 데이터 가상화 | Denodo, Dremio, Trino(Presto) | 물리적 데이터 이동 없이 원천 DB(Database)로 쿼리를 분기 실행하고 중간 결과 인메모리 병합 |
| 쿼리 푸시다운 | CBO(Cost-Based Optimizer) 분산 옵티마이저 | 필터 조건(WHERE) 및 집계를 원천 시스템 엔진에 직접 밀어 넣어 네트워크 전송량 극소화 |
| 통합 메타데이터 카탈로그 | DataHub, Apache Atlas | 이종 저장소에 흩어진 데이터의 스키마, 위치, 비즈니스 정의를 단일 디렉토리로 관리 |
| 인메모리 캐싱 계층 | Apache Arrow, Redis | 자주 조회되는 논리적 가상 뷰의 실행 결과를 캐싱하여 반복 질의 시 초고속 응답 보장 |

## Ⅳ. 물리적 데이터 웨어하우스(Physical DW)와의 비교

- 핵심 요약 : 물리적 DW는 안정성과 성능, 논리적 DW는 실시간성과 민첩성에서 각각 우위를 보유하는 상보적 관계

| 비교 항목 | 전통적 물리적 DW (Physical DW) | 논리적 DW (Logical DW) |
| :--- | :--- | :--- |
| 데이터 적재 방식 | 대규모 배치 ETL로 중앙 물리 스토리지에 복사 적재 | 데이터 이동 없음(Zero-Copy), 제자리 질의(Query-in-place) |
| 데이터 최신성 | 배치 주기(일/월)에 종속된 과거 시점 데이터 | 원천 시스템의 실시간(Real-time) 데이터 직접 조회 |
| 신규 요구사항 대응 | 신규 컬럼/테이블 추가 시 수개월 소요(ETL 재개발) | 논리 가상 뷰 수정만으로 수시간 내 신속 배포(Agile) |
| 원천 시스템 부하 | 원천 DB는 단순 배치 추출만 하므로 영향 적음 | 복잡한 가상화 조인 실행 시 원천 운영 DB에 I/O 부하 전가 위험 |
| 데이터 일관성 | 단일 저장소로 일관성 보장 용이 | 원천 시스템 간 스키마 차이로 정합성 관리 필요 |

## Ⅴ. 논리적 데이터 웨어하우스(Logical DW)의 장점과 한계

- 핵심 요약 : 실시간성과 민첩성이 우수하지만 원천 시스템 부하 전가와 쿼리 성능 오버헤드 존재
- 장점 :
  1. 데이터 이동 최소화 — ETL 파이프라인 개발·유지보수 비용 절감
  2. 실시간 분석 — 원천 시스템 실시간 데이터 직접 접근으로 의사결정 속도 향상
  3. 민첩한 대응체계 — 가상 뷰 수정만으로 신규 요구사항 신속 대응
- 한계점 :
  1. 이종 데이터 소스 간 실시간 연계 쿼리의 네트워크 I/O 및 응답 지연
     - 해결 방안 : 코스트 기반 쿼리 푸시다운(CBO Pushdown)을 통한 원천 시스템 연산 최대화, 분산 가상화 캐시 레이어 구성
  2. 통합 시맨틱 뷰의 복잡성 증가 및 메타데이터 정합성 유지 난제
     - 해결 방안 : 데이터 패브릭(Data Fabric) 기반 활성 메타데이터(Active Metadata) 연계, CDC(Change Data Capture) 기반 자동 동기화 파이프라인 구축
  3. 분석 쿼리와 OLTP(Online Transaction Processing) 운영 쿼리 간 자원 경합
     - 해결 방안 : 운영 DB의 읽기 전용 복제본(Read Replica)이나 CDC 기반 임시 스테이징 버퍼를 논리적 DW의 질의 엔드포인트로 격리 지정

```text
[ 논리적 DW 성능 병목 지점 ]
[가상화 엔진 부하] <-- 복잡한 분산 조인 집중
[네트워크 I/O]    <-- 원천 시스템 간 데이터 전송
[원천 시스템 부하] <-- 운영 DB에 분석 쿼리 직접 전가
```

## Ⅵ. 논리적 데이터 웨어하우스에 대한 기술사적 제언

- 핵심 요약 : 원천 시스템 부하 차단, 레이크하우스 하이브리드 결합, CDC 기반 캐시 무효화가 성공적 구축의 핵심
- 제언 1 : 원천 시스템 부하 차단용 읽기 전용 복제본(Read Replica) 연계 — LDW 가상화 엔진이 운영 트랜잭션 DB(OLTP)에 직접 무거운 조인 쿼리를 전달하여 서비스 장애를 유발하는 사고를 방지하기 위해, 가상화 엔진의 연결 엔드포인트를 운영 DB의 읽기 전용 복제본으로 강제 격리 필요
- 제언 2 : 레이크하우스(Lakehouse)와의 하이브리드 결합 — 모든 조회를 전적으로 가상화로 처리하면 복잡한 다차원 집계 시 네트워크 병목이 발생하므로, 정형 집계 마트는 Iceberg 기반 레이크하우스에 사전 적재하고 실시간성 요구 데이터만 가상화로 페더레이션하는 하이브리드 LDW 전략 채택 필요
- 제언 3 : CDC(Change Data Capture) 기반 캐시 무효화 체계 — 가상화 캐시가 원천 시스템 갱신 사항을 제때 반영하지 못하면 분석 데이터 불일치가 발생하므로, 이벤트 기반 캐시 제어 체계 구현 필요

## Ⅶ. 결론

- 핵심 요약 : 논리적 DW는 데이터 가상화를 통한 실시간 통합 분석 아키텍처이지만 원천 시스템 보호와 하이브리드 운영이 성공 핵심
- 요약 : 논리적 데이터 웨어하우스는 데이터 이동 없이 이종 저장소를 논리적으로 통합하는 가상화 기반 아키텍처로, 소비자-가상화-분산 저장소 3계층 구조로 구성되며 실시간성과 민첩성에서 물리적 DW 대비 우위
- 시사점 : 완전한 가상화만으로는 모든 분석 워크로드를 커버하기 어려우므로, 정형 집계는 물리적 적재(레이크하우스)와 실시간 조회는 가상화를 결합하는 하이브리드 전략이 실무에서 가장 효과적이며, 원천 운영 시스템 보호를 위한 읽기 복제본 격리와 CDC 기반 정합성 관리 체계가 필수
