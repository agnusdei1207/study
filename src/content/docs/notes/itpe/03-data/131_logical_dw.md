## Ⅰ. 물리적 데이터 통합의 한계를 극복하는 논리적 DW의 개요

### 가. 논리적 데이터 웨어하우스(Logical Data Warehouse, LDW)의 정의
- 가트너(Gartner)에 의해 제안된 아키텍처로, 전사 데이터를 단일한 거대 물리적 DW로 물리 복사·이관(ETL)하지 않고, **데이터 가상화(Data Virtualization), 분산 쿼리 페더레이션 기술을 활용하여 분산된 이종 저장소의 데이터를 논리적으로 단일한 DW처럼 통합 조회할 수 있도록 제공하는 현대적 분석 아키텍처**.

### 나. 전통적 물리적 DW의 병목 한계
- 전사 모든 데이터를 단일 DW에 적재하기 위한 막대한 ETL 파이프라인 개발 및 유지보수 비용.
- 실시간 데이터 처리 불가(배치 적재 지연) 및 스토리지 중복 비용 폭증.

## Ⅱ. 논리적 DW의 핵심 4대 구성 계층 및 아키텍처

```text
[ Logical Data Warehouse (LDW) 아키텍처 ]
[소비자 계층]      : BI 도구, SQL 분석가, 머신러닝 파이프라인
                          ^
                          | (단일 가상 SQL 인터페이스)
[가상화/의미 계층] : [Data Virtualization & Semantic Layer]
                   - 통합 데이터 카탈로그, 논리 뷰(View), 분산 쿼리 푸시다운
                          |
[분산 저장소 계층] : +----+------------------+------------------+
                     |                      |                  |
                     v                      v                  v
              [기존 관계형 DW]       [데이터 레이크 (S3)]    [실시간 NoSQL/Kafka]
              (정형 코어 원장)       (비정형/원천 대용량)   (초고속 스트리밍)
```

### 가. 핵심 기술 메커니즘 매트릭스

| 기술 계층 | 주요 기술 요소 | 핵심 기능 및 역할 |
| :--- | :--- | :--- |
| **데이터 가상화 (Data Virtualization)** | Denodo, Dremio, Trino(Presto) | 물리적 데이터 이동 없이 원천 DB로 쿼리를 분기 실행하고 중간 결과를 인메모리 병합 |
| **쿼리 푸시다운 (Predicate Pushdown)** | CBO 분산 옵티마이저 | 필터 조건(`WHERE`) 및 집계를 원천 시스템 엔진에 직접 밀어 넣어 네트워크 전송량 극소화 |
| **통합 메타데이터 카탈로그** | DataHub, Apache Atlas | 이종 저장소에 흩어진 데이터의 스키마, 위치, 비즈니스 정의를 단일 디렉토리로 관리 |
| **인메모리 캐싱 계층** | Apache Arrow, Redis | 자주 조회되는 논리적 가상 뷰의 실행 결과를 캐싱하여 반복 질의 시 초고속 응답 보장 |

## Ⅲ. 물리적 DW vs 논리적 DW의 비교 분석

| 비교 항목 | 전통적 물리적 DW (Physical DW) | 논리적 DW (Logical DW) |
| :--- | :--- | :--- |
| **데이터 적재 방식** | 대규모 배치 ETL로 중앙 물리 스토리지에 복사 적재 | **데이터 이동 없음 (Zero-Copy), 제자리 질의(Query-in-place)** |
| **데이터 최신성** | 배치 주기(일/월)에 종속된 과거 시점 데이터 | 원천 시스템의 **실시간(Real-time) 데이터 직접 조회** |
| **신규 요구사항 대응** | 신규 컬럼/테이블 추가 시 수개월 소요 (ETL 재개발) | 논리 가상 뷰 수정만으로 수시간 내 신속 배포 (Agile) |
| **원천 시스템 부하** | 원천 DB는 단순 배치 추출만 하므로 영향 적음 | 복잡한 가상화 조인 실행 시 **원천 운영 DB에 I/O 부하 전가 위험** |

---

## Ⅳ. 논리적 데이터 웨어하우스(Logical DW)의 주요 한계점 및 해결 방안

- **이종 데이터 소스 간 실시간 연계 쿼리의 네트워크 I/O 및 응답 지연** :
  - **한계점** : 물리적 데이터 이관 없이 가상화 레이어에서 실시간으로 RDBMS, NoSQL, 클라우드 스토리지에 분산 쿼리를 실행하므로 네트워크 병목 및 소스 시스템 과부하 초래.
  - **해결 방안** : 코스트 기반 쿼리 푸시다운(CBO Pushdown)을 통한 원천 시스템 연산 최대화, 빈번한 쿼리 결과를 메모리에 캐싱하는 분산 가상화 캐시 레이어 구성.
- **통합 시맨틱 뷰의 복잡성 증가 및 메타데이터 정합성 유지 난제** :
  - **한계점** : 각 원천 시스템의 스키마 변경이 발생할 때 논리적 가상화 뷰가 깨지거나 의미론적 데이터 매핑 오류가 발생하여 최종 분석 신뢰도 훼손.
  - **해결 방안** : 데이터 패브릭(Data Fabric) 기반 활성 메타데이터(Active Metadata) 연계, 소스 시스템 변경을 감지하여 가상화 카탈로그를 자동 동기화하는 CI/CD 파이프라인 구축.
- **대규모 다자간 동시 분석 시 분석 쿼리와 OLTP 운영 쿼리 간 자원 경합** :
  - **한계점** : 논리적 DW가 운영 트랜잭션 DB에 직접 질의를 전달함으로써 대규모 집계성 분석 트랜잭션이 운영 업무의 락(Lock) 및 CPU를 잠식.
  - **해결 방안** : 운영 DB의 읽기 전용 복제본(Read Replica)이나 변경 데이터 캡처(CDC) 기반 임시 스테이징 버퍼를 논리적 DW의 질의 엔드포인트로 격리 지정.

## Ⅴ. 엔터프라이즈 데이터 플랫폼 진화를 위한 실무 제언

- **원천 시스템 부하 차단용 읽기 전용 복제본(Read Replica) 연계** : LDW 가상화 엔진이 운영 트랜잭션 DB(OLTP)에 직접 무거운 조인 쿼리를 날려 서비스 장애를 유발하는 사고를 방지하기 위해, 가상화 엔진의 연결 엔드포인트를 운영 DB의 읽기 전용 복제본(Read Replica)으로 강제 격리해야 함.
- **레이크하우스(Lakehouse)와의 하이브리드 결합** : 모든 조회를 전적으로 가상화로 처리하면 복잡한 다차원 집계 시 네트워크 병목이 발생하므로, 정형 집계 마트는 Iceberg 기반 레이크하우스에 사전 적재하고, 실시간성 요구 데이터만 가상화로 페더레이션하는 **하이브리드 LDW** 전략을 채택할 것을 제언함.
