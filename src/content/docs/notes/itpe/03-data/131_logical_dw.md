## 30초 인출

- 본질: **로지컬 데이터 웨어하우스(Logical Data Warehouse, LDW)는** 여러 원천의 데이터를 논리적으로 통합해 이용하게 하는 분석 구조
- 메커니즘: 가상화·연합 질의 계층이 원천에 질의를 나누고 결과를 통합
- 통찰: 한계: 원천에 분산 질의를 반복하면 업무 부하·네트워크 지연이 커질 수 있음 → 방안: 질의 실행계획·원천 부하를 관측하고 반복 분석은 캐시·사전 적재와 비교

<details>
<summary>핵심 용어</summary>

- **Logical Data Warehouse (LDW)** : 분산된 원천 데이터에 논리적 통합 접근을 제공하는 분석 구조
- **데이터 가상화(Data Virtualization)** : 데이터를 별도 적재하지 않고 논리 뷰와 질의 계층으로 여러 원천을 조회하는 방식
- **연합 질의(Federated Query)** : 여러 데이터 원천에 질의를 실행하고 결과를 통합하는 처리
- **쿼리 푸시다운(Query Pushdown)** : 질의의 일부 연산을 데이터 원천에 위임해 처리하는 최적화
- **커넥터(Connector)** : 질의 엔진과 데이터 원천 사이의 연결·연산 위임 기능을 제공하는 구성요소

## 2~4교시 25점 답안

## Ⅰ. 로지컬 데이터 웨어하우스의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **로지컬 데이터 웨어하우스(LDW)** 는 분산된 원천 데이터를 논리적으로 통합해 이용하게 하는 분석 구조 |
| 목적 | 데이터 복제·연계 부담을 줄이고 여러 원천에 대한 통합 분석 지원 |

## Ⅱ. 로지컬 데이터 웨어하우스의 특징

| 특징 | 분석상 의미 |
|---|---|
| 논리 뷰 제공 | 원천 위치·형식 차이를 가린 통합 조회 관점 |
| 연합 실행 | 질의를 원천별로 나누고 일부 연산을 위임한 뒤 결과 조합 |
| 원천 의존 성능 | 원천 가용성·응답·네트워크·커넥터 지원이 전체 질의에 영향 |

## Ⅲ. 논리 뷰·연합 질의 체계와 푸시다운 프로세스

```text
분석가 질의 → 논리 뷰·메타데이터 → 연합 질의 엔진
                                      ↓ 원천별 계획 분해
           원천 A ← 커넥터 A     원천 B ← 커넥터 B
              └── 부분 결과 ────────┘
                       ↓ 연합 계층의 잔여 조인·집계
                    통합 결과 반환
```

### 연산 위임과 잔여 처리의 분기

```text
질의 연산(필터·열 선택·집계·조인)
           ↓ 커넥터·원천의 지원 확인
   ├─ 지원 → 원천에 위임 → 줄어든 행·열만 전송
   └─ 미지원 → 원천 결과 전송 → 연합 엔진에서 처리
           ↓
     실행계획·전송량·원천 부하 확인
```

실제 푸시다운 범위는 원천·커넥터·연산에 따라 다르므로 실행계획에서 위임 여부를 확인한다.

## Ⅳ. 물리적 DW와 로지컬 DW의 비교

| 관점 | 물리적 DW | 로지컬 DW |
|---|---|---|
| 데이터 위치 | 분석용 저장소에 사전 적재 | 원천에 두고 논리 뷰로 접근, 필요 시 캐시·부분 적재 |
| 응답 특성 | 적재 지연 대신 반복 질의 최적화 용이 | 최신 원천 접근 가능하지만 원천·네트워크 상태에 영향 |
| 관리 초점 | 적재 파이프라인·저장 비용 | 질의 계획·원천 부하·접근 제어 |

### 푸시다운 연산별 확인

| 연산 | 원천 위임 시 효과 | 적용 조건 |
|---|---|---|
| 필터 | 불필요한 행의 전송 감소 | 원천·커넥터가 조건 연산 지원 |
| 프로젝션 | 필요한 열만 읽고 반환 | 원천·커넥터의 열 선택 지원 |
| 집계·조인 | 중간 데이터 이동 및 엔진 처리량 감소 가능 | 함수·조인 조건·원천 위치 등 질의별 지원 |

동일 원천의 집계·조인도 지원 조건에 따라 위임 결과가 달라진다.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 원천에 분산 질의를 반복하면 업무 부하·네트워크 지연이 커질 수 있음 | 질의 실행계획·원천 부하를 관측하고 반복 분석은 캐시·사전 적재와 비교 |
| 커넥터가 연산을 위임하지 못해 데이터 이동 증가 | 실제 실행계획에서 위임 연산을 확인하고 지원 범위에 맞춰 질의·원천 조정 |
| 한 원천 장애가 통합 질의 전체에 전파 | 업무 중요도에 따라 결과 캐시·대체 경로·오류 처리 기준 설정 |

## Ⅵ. 제언

연합 질의가 원천에 반복 부하를 주면 논리 통합의 장점보다 지연이 커진다. 먼저 상위 반복 질의의 실행계획과 원천 부하를 측정하고, 푸시다운으로 줄지 않는 구간은 캐시·부분 적재와 비용을 비교한다.
