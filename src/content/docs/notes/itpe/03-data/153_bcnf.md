## 연관 키워드

- BCNF, Boyce-Codd Normal Form
- 3NF, 함수 종속, 결정자, 슈퍼키, 후보키
- 무손실 분해, 종속성 보존

## Ⅰ. BCNF의 개요

- 핵심 요약 : **BCNF**(Boyce-Codd Normal Form, 보이스-코드 정규형)는 3NF를 만족하면서도 중첩된 후보키로 생기는 이상 현상을 없애기 위해 모든 결정자가 슈퍼키이도록 요구하는 정규형.
- 개념 : 제3정규형(3NF)을 만족하는 릴레이션에서, 비사소한 **함수 종속**(Functional Dependency) X → Y의 결정자 X가 반드시 **슈퍼키**(Superkey)가 되도록 요구하는 정규화 기준. 1974년 레이먼드 보이스(Raymond Boyce)와 에드가 커드(E.F. Codd)가 제안하여 강한 제3정규형(Strong 3NF)으로도 불림.
- 배경 및 필요성 : 복수의 후보키가 속성을 공유하는 경우 3NF로는 삽입·삭제·수정 이상이 남으며, 이를 제거하면서도 무손실 분해를 보장할 필요.
- 주요 목적 : 모든 결정자가 후보키가 되도록 릴레이션을 분해하여 데이터 중복과 이상 현상을 차단.

## Ⅱ. BCNF의 특징 및 장점

- 핵심 요약 : 3NF보다 엄격한 결정자 조건을 두어 이상 현상을 줄이는 대신, 종속성 보존의 트레이드오프를 수반하는 정규형.

1. 엄격한 결정자 조건 : 모든 비사소한 함수 종속 X → Y에서 X가 슈퍼키여야 함 → 결정자 기준의 중복 원천 차단.
2. 3NF 포함 관계 : BCNF를 만족하면 3NF도 자동으로 만족하나, 그 역은 성립하지 않음.
3. 중첩 후보키 처리 : 후보키가 속성을 공유하는 경우에도 잔여 이상 현상을 제거.
4. 무손실 분해 : 공통 속성이 분해된 한 릴레이션의 키이면 무손실 분해가 보장됨 → 원본 복원 가능.
5. 종속성 보존 트레이드오프 : 모든 함수 종속을 보존하는 BCNF 분해는 불가능할 수 있음.

## Ⅲ. BCNF의 구조 (흐름)

- 핵심 요약 : 3NF 확인 후 BCNF 위반 종속성을 찾아 결정자 기준으로 분해하고, 무손실과 종속성 보존을 검증하는 순서.

```text
[ BCNF 정규화 프로세스 ]

1단계 : 3NF 만족 여부 확인
   ↓
2단계 : 결정자가 슈퍼키가 아닌 X → Y 탐지
   ↓
3단계 : X → Y 기준으로 R1(X, Y), R2 분해
   ↓
4단계 : 무손실 분해와 종속성 보존 검증
```

- 고전적 BCNF 위반 예시는 수강지도 릴레이션(학번, 과목, 담당교수)이다.

```text
[ 수강지도 함수 종속성 ]

FD1 : (학번, 과목) → 담당교수
FD2 : (학번, 담당교수) → 과목
FD3 : 담당교수 → 과목   (위반: 결정자가 키 아님)
```

```text
[ BCNF 분해 결과 ]

R1(담당교수, 과목) : FD3 보존, 담당교수가 키
R2(학번, 담당교수) : FD2 보존, 복합 키
FD1은 R1과 R2를 조인해야만 유도 가능
→ 종속성 보존 실패
```

## Ⅳ. 3NF와 BCNF의 비교

- 핵심 요약 : 비주요 속성 중심의 3NF에서 모든 결정자 중심의 BCNF로 정규화 기준이 강화되는 차이.

| 비교 항목 | 제3정규형(3NF) | BCNF |
| --- | --- | --- |
| 핵심 조건 | 비주요 속성의 이행적 함수 종속 제거 | 모든 결정자가 슈퍼키 |
| 중첩 후보키 처리 | 중첩 후보키 간 종속 허용, 이상 현상 일부 잔존 | 중첩 후보키 간 종속을 분해하여 이상 현상 제거 |
| 무손실 분해 | 항상 가능 | 항상 가능 |
| 종속성 보존 | 항상 가능 | 보장되지 않을 수 있음 |
| 실무 적용 | 표준 정규화 목표로 널리 사용 | 중첩 후보키가 있는 영역에 선별 적용 |

## Ⅴ. BCNF의 한계와 방안

- 핵심 요약 : 종속성 보존 실패, 과도한 분해에 따른 조인 비용, 설계 복잡도의 한계를 애플리케이션 보완과 물리 설계 기법으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 종속성 보존 불가 | 분해 후 원본 함수 종속을 릴레이션에서 직접 검사할 수 없음 | 3NF에서 멈추고 애플리케이션에서 무결성 보완, 또는 트리거·체크 제약으로 보완 | 무결성 위반 건수 |
| 과도한 분해로 조인 증가 | 다중 조인으로 질의 성능 저하 | 물리 설계 단계의 반정규화, 뷰, 머티리얼라이즈드 뷰 활용 | 질의 응답 시간 |
| 설계 복잡도와 오버엔지니어링 | 대부분 업무에 3NF로 충분하나 BCNF 강제 시 설계만 복잡해짐 | 중첩 후보키가 확인된 도메인에만 BCNF 적용 | 정규화 검토 대상 수 |

## Ⅵ. BCNF에 대한 기술사적 제언

- 핵심 요약 : 3NF를 기본 목표로 삼고 중첩 후보키가 있는 도메인에 BCNF를 선별 적용하며, 성능은 물리 설계로 보완하는 방향이 바람직함.
- 전사 데이터 모델링 표준은 3NF를 기본으로 삼고, 수강, 예약, 자원 할당처럼 후보키가 중첩되는 핵심 도메인에 한해 BCNF 위반 여부를 추가로 검증하는 것이 현실적이다.
- BCNF 분해로 종속성 보존이 깨진 함수 종속은 트리거나 체크 제약, 서비스 계층의 검증 로직으로 반드시 보완해야 데이터 정합성의 공백을 막을 수 있다.
- 논리 모델은 BCNF 수준까지 정규화하되, 물리 모델에서는 인덱싱, 파티셔닝, 머티리얼라이즈드 뷰로 조인 비용을 상쇄하는 하이브리드 설계가 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : BCNF는 중첩 후보키의 이상 현상을 제거하는 엄격한 정규형이나, 종속성 보존과 성능의 트레이드오프를 수반하므로 선별 적용이 핵심.
- 정규화 수준은 도메인의 후보키 구조에 따라 정하고, 분해로 깨진 제약은 애플리케이션 계층에서 보완하는 것이 실무의 기본 원칙이다.
