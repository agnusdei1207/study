## 연관 키워드

**동적 SQL(Dynamic SQL)**, **정적 SQL**, **하드 파싱(Hard Parsing)**, **소프트 파싱**, **바인드 변수**, **SQL Injection**, **MyBatis**, **Querydsl**

## Ⅰ. 개요

- 핵심 요약 : **동적 SQL**은 런타임에 조건에 따라 SQL 구조를 동적으로 생성·실행하는 기법.
- 목적 : 가변 검색 조건·다차원 필터링에 유연 대응.
- 배경 : 정적 SQL은 조건 조합마다 SQL 중복 급증 → 동적 생성 필요.
- 특징 : 정적 SQL과 대조, 하드/소프트 파싱, 바인드 변수, SQL Injection 위험.

## Ⅱ. 특징 및 장점

- 핵심 요약 : **런타임 유연성**과 **가변 조건 처리**가 핵심 장점.
- **유연성** : 사용자 입력·분기 로직에 따라 SQL 구조 동적 조립.
- **재사용성** : 하나의 템플릿으로 다중 조건 처리.
- **바인드 변수** : 파라미터 바인딩으로 재사용·보안 확보.
- **프레임워크 지원** : MyBatis, Querydsl 등 안전한 동적 쿼리.
- **성능** : 바인드 변수로 소프트 파싱 극대화.

## Ⅲ. 파싱 흐름

- 핵심 요약 : **라이브러리 캐시 검색 → 소프트/하드 파싱** 분기.
- 소프트 파싱 : 캐시 존재 시 실행 계획 재사용 (CPU 최소).
- 하드 파싱 : 신규 SQL 시 문법·권한·비용 계산 (CPU 폭증, 래치 경합).

```text
[ SQL 파싱 및 실행 계획 캐시 흐름 ]

[SQL 인입] ---> [SGA 라이브러리 캐시 검색]
                    |
         +----------+----------+
         |                     |
   (캐시 존재)            (캐시 없음)
         v                     v
   [소프트 파싱]          [하드 파싱]
   실행 계획 재사용        문법·권한·비용 계산
   CPU 최소              CPU 폭증·래치 경합
```

```text
[ 정적 vs 동적 SQL ]

정적 : 컴파일 시점 확정, 소프트 파싱 극대화, Injection 면역
동적 : 런타임 조립, 하드 파싱 위험, 유연성 최상
```

## Ⅳ. 정적 vs 동적 SQL 비교

- 핵심 요약 : **유연성 vs 성능·보안** 트레이드오프.

| 항목 | 정적 SQL | 동적 SQL |
|---|---|---|
| 구문 확정 시점 | 컴파일/빌드 시 | 런타임 |
| 파싱 비용 | 소프트 파싱 극대화 | 하드 파싱 가능 |
| 보안성 | Injection 면역 | 문자열 결합 시 취약 |
| 개발 유연성 | 조건 복잡 시 SQL 중복 | 가변 조건 최상 |

## Ⅴ. 한계와 방안

- 핵심 요약 : **하드 파싱·SQL Injection·플랜 불안정**을 바인드 변수·화이트리스트·모듈화로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 하드 파싱 고갈 | 문자열 결합으로 매번 신규 컴파일 | 바인드 변수(#{param}) 필수, 파라미터 쿼리 | 하드 파싱 비율 |
| SQL Injection | 사용자 입력 무검증 삽입 | 화이트리스트 검증, SAST 점검 | 취약점 0건 |
| 플랜 불안정 | 조건 조합 분기로 옵티마이저 혼란 | 정적 쿼리 모듈화, 힌트, Querydsl | 실행 계획 안정성 |

## Ⅵ. 기술사적 제언

- 핵심 요약 : **바인드 변수·화이트리스트·바인드 피킹 방어**로 안전·성능 확보.
- `#`(바인드) vs `$`(리터럴) 엄격 통제 : 값은 #{param}, 식별자만 ${} + 화이트리스트.
- 바인드 피킹 방어 : 편향 극심 조건은 정적 분기 쿼리로 분리.
- MyBatis/Querydsl로 타입 안전 동적 쿼리.

## Ⅶ. 결론

- 핵심 요약 : 동적 SQL은 **런타임 유연성**이 강점이나 바인드 변수·보안 통제가 필수.
- 답안에는 정적/동적 비교, 파싱 흐름, 한계·대응, 실무 통제를 연결.
