## 지식 로드맵 내 현재 위치

자료처리·데이터 → 분산 데이터베이스 → **분산 데이터베이스 투명성**

## 30초 인출

- 본질: 분산 데이터베이스 투명성은 여러 노드에 나뉘거나 복제된 데이터를 이용자가 분산 구조를 의식하지 않고 접근하게 하는 성질
- 메커니즘: 이용자는 글로벌 스키마로 질의하고 DBMS가 분할·위치·복제 정보를 참조해 필요한 조각과 노드, 읽을 사본을 정한 뒤 결과를 합쳐 반환
- 통찰: 투명성은 분산 비용과 장애를 없애지 않고 숨길 뿐이므로 실제 실행 계획·통신량·복제 지연을 확인하고 업무별로 필요한 투명성과 일관성 수준을 정함

<details>
<summary>핵심 용어</summary>

- **분산 데이터베이스(Distributed Database)** : 여러 노드에 배치된 데이터를 논리적으로 하나처럼 다루는 데이터베이스
- **분산 투명성(Distribution Transparency)** : 데이터의 분산 배치 세부를 이용자가 몰라도 되게 하는 성질
- **분할 투명성(Fragmentation Transparency)** : 데이터가 어떻게 조각났는지 몰라도 접근할 수 있는 성질
- **위치 투명성(Location Transparency)** : 데이터가 어느 노드에 있는지 몰라도 접근할 수 있는 성질
- **복제 투명성(Replication Transparency)** : 복제본의 존재·선택을 이용자가 직접 다루지 않아도 되는 성질
- **글로벌 스키마(Global Schema)** : 분산 데이터의 논리적 전체 구조를 표현한 스키마
- **분산 질의 처리** : 여러 노드에 작업을 보내고 결과를 합쳐 질의에 응답하는 처리

</details>

## 2~4교시 25점 답안

## Ⅰ. 분산 데이터베이스 투명성의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **분산 데이터베이스 투명성** 은 나뉘거나 복제된 데이터를 분산 구조의 세부 배치를 의식하지 않고 접근하게 하는 성질 |
| 목적 | 논리적 접근의 일관성 확보와 구조 변경 영향 감소 |

## Ⅱ. 특징

| 특징 | 의미 |
|---|---|
| 논리·물리 분리 | 이용자는 글로벌 스키마로 질의하고 DBMS가 물리 경로 결정 |
| 배치 정보 은닉 | 분할·위치·복제본 선택의 관리 부담 감소 |
| 분산 비용 잔존 | 통신량·복제 지연·부분 장애는 별도 검증 필요 |

## Ⅲ. 논리 질의의 처리 경로

```text
논리 질의
  ├ 분할 정보 참조 → 필요한 조각 결정
  ├ 위치 정보 참조 → 해당 노드로 요청
  └ 복제 정보 참조 → 읽을 사본 선택
노드별 결과 → DBMS가 합쳐 논리 결과 반환
```

## Ⅳ. 투명성 유형

| 유형 | 숨기는 정보 | 내부에서 필요한 처리 |
|---|---|---|
| 분할 투명성 | 데이터의 조각 구분 | 대상 조각 식별·결과 합침 |
| 위치 투명성 | 조각이 있는 노드 | 노드 라우팅 |
| 복제 투명성 | 복제본의 존재·선택 | 읽기 대상 선택·갱신 전파 |

분할·위치·복제는 서로 다른 관점이며, 문헌에 따라 병행·장애 투명성 등을 더해 분류하므로 문헌 기준을 밝혀 서술.

| 효과 | 절충 |
|---|---|
| 이용자의 물리 노드 의존 감소 | 내부 라우팅·메타데이터 관리 필요 |
| 배치 변경 영향 감소 | 노드 간 통신·질의 최적화 비용 |
| 복제본 선택 단순화 | 최신성·정합성 정책 확인 필요 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 투명성 때문에 느린 분산 질의가 숨겨짐 | 노드별 실행 계획·통신량 확인 |
| 복제본이 늘면 최신성도 보장된다고 가정 | 읽기·쓰기 일관성 수준 검증 |
| 노드 장애 시 완전한 결과를 기대 | 부분 실패·재시도·오류 정책 시험 |

## Ⅵ. 제언

업무별로 필요한 투명성과 일관성 수준을 정하고, 숨겨진 분산 비용을 계획 단계에서 관측

```text
업무별 일관성 요구 정의 → 투명성 범위 결정 → 실행 계획·복제 지연·장애 시험
```

| 구분 | 완전 투명성 강제 | 제언: 업무별 차등 |
|---|---|---|
| 성능 | 동기 복제로 지연 증가 | 결제는 강한 일관성, 로그는 완화 |
| 장애 | 단일 노드 장애의 파급 | 부분 실패 정책 적용 |
