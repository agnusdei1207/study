## 연관 키워드

- CAP 정리, PACELC 정리, 네트워크 분할(Network Partition)
- 일관성(Consistency), 가용성(Availability), 분할 내성(Partition Tolerance)
- 선형화 가능성(Linearizability), 최종 일관성(Eventual Consistency), 지연 시간(Latency), 멱등성(Idempotency)

## Ⅰ. CAP·PACELC의 개요

- 핵심 요약 : 네트워크 분할이 있을 때와 평상시에 일관성·가용성·지연의 선택 관계를 설명하는 분산 시스템 분석 틀.
- 개념 : **CAP 정리**(CAP Theorem)는 **네트워크 분할**(Network Partition)이 발생한 분산 시스템에서 **일관성**(Consistency), **가용성**(Availability), **분할 내성**(Partition Tolerance) 중 강한 일관성과 모든 정상 노드의 응답을 동시에 보장할 수 없다는 한계를 말한다. **PACELC 정리**는 여기에 평상시(Else)의 지연 시간과 일관성 절충을 더해, 분할 시에는 가용성(A)과 일관성(C) 중 무엇을, 평상시에는 지연(L)과 일관성(C) 중 무엇을 택할지 설명한다.
- 배경 및 필요성 : 지리적으로 분산된 노드 사이에서는 네트워크 분할이 언제든 일어날 수 있고, 일관성·가용성·지연의 절충을 제품 단위가 아닌 연산 단위로 판단해야 하는 실무 요구가 커졌다. 제품 이름만으로 분류하면 실제 보장 범위가 왜곡되는 문제도 있다.
- 주요 목적 : 분산 데이터 설계에서 보장 수준과 장애 시 동작을 명시적으로 결정.

## Ⅱ. CAP·PACELC의 특징 및 장점

- 핵심 요약 : 속성의 정확한 정의와, 분할 시와 평상시로 나뉘는 2단계 절충 구조가 결합된 분석 체계.

1. 일관성(Consistency) : 연산이 단일 최신 복사본에서 원자적으로 실행된 것처럼 보이는 **선형화 가능성**(Linearizability) → 읽기가 항상 최신 쓰기를 반영.
2. 가용성(Availability) : 장애가 없는 노드가 받은 요청이 응답으로 완료되는 것. 운영 지표인 가동률과는 구분된 이론적 정의 → 응답 보장 범위를 명확히 함.
3. 분할 내성(Partition Tolerance) : 메시지 손실과 단절 상황을 모델에 포함하는 조건 → 분산 시스템에서는 사실상 필수로 가정.
4. 평상시 절충 : 분할이 없는 구간에서도 복제와 합의 과정에서 일관성과 지연 시간이 상충 → 성능 설계의 기준.
5. 연산·설정 중심 판단 : 제품 단위가 아니라 읽기·쓰기 경로와 장애 조건별 보장 수준으로 판단 → 설계 근거가 구체화.

## Ⅲ. CAP·PACELC의 구조 (흐름)

- 핵심 요약 : 네트워크 분할 발생 여부로 분기한 뒤, 분할 시에는 일관성과 가용성 중 하나를, 평상시에는 지연과 일관성 중 하나를 택하는 의사결정 구조.

```text
[ PACELC 의사결정 흐름 ]

[네트워크 분할(P) 발생?]
     ↓ 예                  ↓ 아니오 (E)
[A 또는 C 선택]       [L 또는 C 선택]
 - PA: 가용성 우선      - EL: 지연 우선
 - PC: 일관성 우선      - EC: 일관성 우선
```

분할 시 PA는 오래된 값을 응답하고 PC는 쓰기를 제한하거나 대기시키며, 평상시 EL은 비동기 복제로 지연을 줄이고 EC는 동기 합의로 일관성을 택한다.

## Ⅳ. CAP와 PACELC의 비교

- 핵심 요약 : 분할 상황의 두 속성 절충만 다루는 CAP와, 평상시까지 포함해 네 가지 조합으로 설명하는 PACELC의 범위 차이.

```text
[ CAP와 PACELC의 범위 ]

CAP : 분할(P) 발생 시 A 또는 C 선택
         ↓ 평상시 범위 추가
PACELC : 분할 시 A·C + 평상시 L·C
```

| 비교 기준 | CAP 정리 | PACELC 정리 |
| --- | --- | --- |
| 구성 요소 | 일관성(C), 가용성(A), 분할 내성(P) | 분할 시 A 또는 C, 평상시 L(지연) 또는 C |
| 분석 범위 | 네트워크 분할 발생 시 | 분할 발생 시와 평상시 모두 |
| 절충 축 | 일관성 대 가용성 | 일관성 대 가용성, 일관성 대 지연 |
| 해석 주의 | 세 속성 중 정확히 둘을 고르는 규칙이 아님 | 제품 단위가 아니라 연산·설정 단위로 분류 |
| 실무 활용 | 장애 시 동작의 큰 그림 제공 | 평상시 성능과 장애 시 동작을 구체적으로 설계 |

## Ⅴ. CAP·PACELC의 한계와 방안

- 핵심 요약 : 제품 단위 단순 분류, 최종 일관성의 업무 오류, 평상시 시험으로 장애 동작을 검증하지 못하는 한계를 연산별 보장 검증으로 대응.

장점은 일관성·가용성·지연의 선택을 설정과 연산 단위로 명시할 수 있고, 장애 시 동작과 평상시 성능을 나누어 논의할 수 있다는 점이다.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 제품 단위의 단순 분류 | 특정 데이터베이스를 고정된 AP 또는 CP 제품으로 단정해 실제 읽기·쓰기 경로와 장애 조건을 간과 | 연산별 일관성 수준, 복제 계수, 커밋 조건을 확인해 보장 수준을 검증 | 연산별 보장 수준 확인 건수 |
| 최종 일관성의 업무 오류 | 잔액, 재고, 결제처럼 정합성이 필요한 연산에 **최종 일관성**(Eventual Consistency)을 적용해 중복 처리 발생 | 직렬화와 합의 설계, **멱등성**(Idempotency) 확보, 연산별 일관성 수준의 차등 적용 | 중복 처리 건수 |
| 평상시 시험과 장애 동작의 차이 | 정상 부하 시험만으로는 네트워크 분할 시의 동작과 복구, 충돌 처리를 검증하지 못함 | 정상 부하 시험과 네트워크 분할 시험을 병행하고 복구·충돌 처리를 검증 | 분할 시험 통과율 |

## Ⅵ. CAP·PACELC에 대한 기술사적 제언

- 핵심 요약 : 서비스별 허용 지연과 거부 요청 정책을 먼저 정하고, 실제 보장 수준은 시험으로 확인하는 설계 체계가 필요.

서비스마다 허용할 수 있는 지연 시간과 분할 시 거부할 요청의 범위, 장애 복구 정책을 먼저 문서로 정해 두고, 이를 복제와 합의 설정에 반영하는 것이 바람직하다. 그다음 연산 단위로 정상 부하 시험과 네트워크 분할 시험을 함께 수행해 설정대로 보장되는지 확인해야 한다. 이론적 분류는 제품을 고를 때 참고하는 틀로 쓰되, 실제 보장 수준은 설정과 시험 결과로 판단하는 운영이 필요하다.

## Ⅶ. 결론

- 핵심 요약 : CAP·PACELC는 분산 시스템의 보장 범위를 명시하는 분석 틀이며, 실제 보장은 연산별 설정과 시험으로 확인해야 함.
- 시사점 : 제품 이름이 아니라 연산과 설정, 장애 시험을 기준으로 보장 수준을 정하는 것이 분산 데이터 설계의 신뢰성 확보 조건이다.
