## 연관 키워드

- CAP·PACELC 정리 (CAP: Consistency, Availability, Partition Tolerance; PACELC: Partition: Availability/Consistency; Else: Latency/Consistency)

## Ⅰ. CAP·PACELC의 개요

- 핵심 요약 : 네트워크 분할과 평상시 운영 조건에서 일관성·가용성·지연의 선택 관계를 설명하는 CAP·PACELC 분석 틀.
- 개념 : CAP 정리는 네트워크 분할이 발생한 분산 시스템에서 강한 일관성과 모든 정상 노드의 요청 가용성을 동시에 보장할 수 없다는 한계이며, PACELC는 분할 시 가용성·일관성의 선택뿐 아니라 평상시 지연시간·일관성의 절충까지 설명하는 분석 틀.
- 배경 및 필요성 :
  1. 지리적으로 분산된 노드 간 네트워크 분할 가능성의 상시적 존재.
  2. 일관성과 가용성·지연의 트레이드오프를 설정·연산 단위로 판단해야 하는 실무 요구.
  3. 제품 단위의 단순 분류가 실제 보장 범위를 왜곡하는 문제.
- 주요 목적 : 분산 데이터 설계의 보장 수준과 장애 시 동작을 명시적으로 결정.

## Ⅱ. CAP·PACELC의 특징

- 핵심 요약 : 속성의 정확한 정의와 분할·평상시의 2단계 절충 구조.

1. 일관성(C) : 연산이 단일 최신 복사본에서 원자적으로 실행된 것처럼 보이는 선형화 가능성(Linearizability).
2. 가용성(A) : 장애가 없는 노드가 받은 요청이 응답으로 완료되는 이론적 정의(운영 지표의 가동률과 구분).
3. 분할 내성(P) : 통신 메시지 손실·단절 상황을 모델에 포함하는 조건.
4. 평상시 절충 : 분할이 없는 구간에서도 일관성과 지연의 절충이 존재.
5. 연산·설정 중심 : 제품이 아닌 읽기·쓰기 경로와 장애 조건별 보장 수준으로 판단.

## Ⅲ. CAP·PACELC의 구조 (흐름)

- 핵심 요약 : 네트워크 분할 발생 시의 일관성·가용성 분기와 평상시의 지연·일관성 절충 흐름.

                  |                  |
        [일관성(C) 유지]      [평상시: 지연 vs 일관성]
        - 일부 요청 대기·거부   - 복제·합의로 얻는 일관성과 지연의 절충

```

+---------------------+---------------------+
```

## Ⅳ. CAP와 PACELC의 비교

- 핵심 요약 : 분할 상황의 2속성 절충과 평상시까지 포함하는 4분할 절충의 범위 대조.

| 비교 항목 | CAP 정리 | PACELC 정리 |
| :--- | :--- | :--- |
| 구성 요소 | 일관성(C)·가용성(A)·분할 내성(P) | 분할 시 A/C, 평상시 L(지연)/C |
| 분석 범위 | 네트워크 분할 발생 시 | 분할 발생 시와 평상시 모두 |
| 절충 축 | 일관성 vs 가용성 | 일관성 vs 가용성·지연 |
| 해석 주의 | 세 속성 중 정확히 둘을 고르는 규칙이 아님 | 제품 단위가 아닌 연산·설정 단위의 분류 |
| 실무 활용 | 장애 시 동작의 큰 그림 제공 | 평상시 성능과 장애 시 동작의 구체적 설계 |

## Ⅴ. CAP·PACELC의 장점과 한계

- 핵심 요약 : 보장 범위의 명시화 장점과 단순 분류·최종 일관성 오류·정상/장애 차이의 한계.

- 장점
  1. 일관성·가용성·지연의 선택을 설정·연산 단위로 명시하는 설계 기준 제공.
  2. 장애 시 동작과 평상시 성능을 구분하여 아키텍처 논의 가능.
  3. 제품 단위의 오해를 지양하는 분석 틀로서의 활용.

- 한계점 1 : 제품 단위의 단순 분류
  - 한계점 : 특정 데이터베이스를 고정된 AP·CP 또는 PA/EC 제품으로 단정하여 실제 읽기·쓰기 경로와 장애 조건을 간과.
  - 해결 방안 : 연산별 일관성 수준·복제 계수·커밋 조건의 확인을 통한 보장 수준 검증.

- 한계점 2 : 최종 일관성의 업무 오류
  - 한계점 : 잔액·재고·중복 결제처럼 정합성이 필요한 연산에 최종 일관성(Eventual Consistency)을 적용하여 업무 오류 발생.
  - 해결 방안 : 직렬화·합의·멱등성 설계와 연산별 일관성 수준의 차등 적용.

- 한계점 3 : 평상시 성능과 장애 시 동작의 차이
  - 한계점 : 정상 부하 시험만으로 네트워크 분할 시 동작과 데이터 복구·충돌 처리를 검증하지 못함.
  - 해결 방안 : 정상 부하 시험과 네트워크 분할 시험의 병행, 데이터 복구·충돌 처리 검증.

## Ⅵ. CAP·PACELC에 대한 기술사적 제언

- 핵심 요약 : 허용 지연·거부 요청·복구 정책의 명시와 실제 보장 검증 중심의 설계 체계.

- 서비스별 허용 지연·거부 요청·장애 복구 정책의 명시 : 복제·합의 설정에 반영하는 보장 수준의 사전 정의.
- 연산·설정 단위의 보장 검증 : 정상 부하와 네트워크 분할 시험을 병행한 실제 보장 여부 확인.
- 이론적 분류의 참고 틀 활용 : 제품 선택의 참고 자료로 활용하고 실제 보장은 설정·연산·장애 시험 결과로 확인하는 운영.

## Ⅶ. 결론

- 핵심 요약 : CAP·PACELC는 분산 시스템의 보장 범위를 명시하는 분석 틀로서의 활용이 핵심.
- 요약 : 일관성·가용성·분할 내성의 정의와 분할·평상시의 2단계 절충, CAP와 PACELC의 범위 대조.
- 시사점 : 제품 단위 분류가 아닌 연산·설정·장애 시험 기반의 보장 수준 확인이 분산 데이터 설계의 신뢰성 확보 조건.
