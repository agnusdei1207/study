## 연관 키워드

- 반정규화(Denormalization), 역정규화, 데이터 중복, 테이블 병합, 테이블 분할, 파생 컬럼
- 다중 조인(Multi-way JOIN), 조회 성능, 데이터 정합성, CDC(Change Data Capture), CQRS(Command Query Responsibility Segregation), 트레이드오프

## Ⅰ. 반정규화의 개요

- 핵심 요약 : 성능 향상과 운영 단순화를 위해 정규화 원칙을 의도적으로 위배하는 데이터 모델링 기법.
- 개념 : 정규화된 데이터 모델에서 시스템의 성능 향상, 개발 및 운영의 단순화를 위해 의도적으로 정규화 원칙을 위배하여 데이터의 중복, 통합, 분리를 수행하는 데이터 모델링 기법, 반정규화(Denormalization).
- 배경 및 필요성 : 시스템 운영 중 복잡한 다중 조인(Multi-way JOIN)에 따른 쿼리 응답 지연, 대규모 배치 집계·실시간 대시보드 조회의 OLTP(Online Transaction Processing) 트랜잭션 성능 저해.
- 주요 목적 : 읽기 작업 성능(조회 속도)의 대폭 향상과 쓰기 오버헤드·무결성 훼손 위험 사이의 트레이드오프 관리.

## Ⅱ. 반정규화의 특징

- 핵심 요약 : 의도적 중복·통합·분리를 통한 읽기 성능 우선 전략과 3대 적용 대상, 최후의 수단 원칙.

1. 의도적 정규화 위배 : 데이터 중복, 통합, 분리를 성능 목적으로 수행.
2. 트레이드오프 구조 : 읽기 성능 향상 대비 쓰기(INSERT, UPDATE, DELETE) 오버헤드 및 데이터 무결성 훼손 위험 수반.
3. 3대 적용 대상 : 테이블 반정규화, 컬럼 반정규화, 관계 반정규화.
4. 최후의 수단(Last Resort) 원칙 : 인덱스 튜닝, 파티셔닝, 캐싱 등 대안 검토 후 적용.
5. 정합성 동기화 체계 수반 : 트리거 기반 실시간 동기화 또는 주기적 정합성 검증 배치 필요.

## Ⅲ. 반정규화의 구조 (흐름)

- 핵심 요약 : 대상 조사→대안 검토→적용의 3단계 추진 절차와 테이블·컬럼·관계 기법 체계.

```text
[ 반정규화 추진 절차 ]
[1단계: 반정규화 대상 조사]  ---> [2단계: 다른 방법 유도 검토]  ---> [3단계: 반정규화 적용]
 - 잦은 조인 쿼리 식별           - 인덱스 추가 및 튜닝            - 테이블 반정규화
 - 대량 데이터 범위 처리        - 클러스터링, 파티셔닝           - 컬럼 반정규화
 - 통계 및 집계 쿼리 빈도        - 응용프로그램 캐싱(Redis)       - 관계 반정규화
```

- 반정규화 3대 핵심 기법.

| 대상 구분 | 세부 기법 | 구체적 적용 방식 | 장점 및 위험 요인 |
|---|---|---|---|
| 테이블 반정규화 | 테이블 병합 | 1:1 관계 테이블 병합, 1:M 관계 테이블 통합 | 조인 제거로 조회 성능 극대화 / 데이터 중복 및 테이블 비대화 |
| 테이블 반정규화 | 테이블 분할 | 수직 분할(자주 쓰는 컬럼 분리), 수평 분할(파티셔닝) | I/O 경합 분산, 캐시 효율 증대 / 관리 복잡도 증가 |
| 테이블 반정규화 | 통계/이력 테이블 추가 | 일/월별 집계 테이블 사전 생성, 최근 이력 전용 테이블 | 실시간 집계 부하 원천 제거 / 원천 데이터 갱신 시 동기화 오버헤드 |
| 컬럼 반정규화 | 중복 컬럼 추가 | 조인 축소용 타 테이블 컬럼 복사 | 단일 테이블 단독 조회 가능 / UPDATE 시 양쪽 컬럼 일치 유지 필수 |
| 컬럼 반정규화 | 파생/계산 컬럼 추가 | 총금액, 할인율 등 연산 결과 사전 저장 | 런타임 계산 부하 배제 / 정합성 불일치 위험 |
| 관계 반정규화 | 중복 관계 추가 | 다단계 관계(A→B→C)의 단축 경로(A→C) 관계 선언 | 복합 조인 경로 단축 / 외래키 관계 유지 부담 |

## Ⅳ. 정규화와 반정규화의 비교

- 핵심 요약 : 무결성 지향의 정규화와 조회 성능 지향의 반정규화, 목적·I/O·저장 공간의 상충 관계.

```text
[ 정규화 vs 반정규화 상충 관계 ]
               정규화 (Normalization)            반정규화 (Denormalization)
  목적       : 데이터 무결성, 이상현상 배제        성능 향상, 조인 비용 제거
  I/O 특성   : 쓰기(CUD) 성능 우수, 읽기 부하       읽기(R) 성능 우수, 쓰기 부하
  저장 공간  : 중복 최소화로 스토리지 절감         데이터 중복으로 스토리지 증가
```

| 비교 항목 | 정규화 (Normalization) | 반정규화 (Denormalization) |
|---|---|---|
| 설계 목적 | 데이터 무결성, 이상 현상 배제 | 조회 성능 향상, 개발·운영 단순화 |
| 데이터 중복 | 최소화 (스토리지 절감) | 의도적 허용 (스토리지 증가) |
| I/O 특성 | 쓰기(CUD) 성능 우수, 읽기 시 다중 조인 부하 | 읽기(R) 성능 우수, 쓰기 시 동기화 부하 |
| 데이터 품질 관리 | 스키마 차원의 이상 현상 원천 방지 | 정합성 동기화 체계(트리거·배치) 필요 |
| 적용 시점 | 논리·물리 데이터 모델링 단계 | 성능 병목 입증 후 선별 적용 |

- 데이터 불일치 제어 방안 : 트리거(Trigger) 및 이벤트 기반 비동기 동기화를 통한 원천 변경 시 반정규화 대상 실시간 갱신, 주기적 정합성 검증 배치를 통한 원천과 집계 데이터 간 불일치 자동 비교·보정(Reconciliation).

## Ⅴ. 반정규화의 장점과 한계

- 핵심 요약 : 조회 성능 극대화·쿼리 단순화의 장점, 정합성 훼손·쓰기 성능 급락·유지보수 비용의 한계.
- 장점
  1. 조인 제거를 통한 조회 성능 극대화.
  2. 사전 집계 테이블을 통한 실시간 집계 부하 원천 제거.
  3. 단순화된 쿼리 구조를 통한 개발 생산성 향상.
- 한계점 1 : 데이터 중복에 따른 이상 현상(Anomaly) 및 정합성 훼손
  - 한계점 : 동일 데이터의 다수 테이블 분산 복제 상태에서 일부 테이블만 UPDATE되고 누락 발생 시 데이터 불일치(Data Inconsistency) 발생.
  - 해결 방안 : 트랜잭션 내 동기 갱신 보장 또는 비동기 CDC(Change Data Capture) 기반 정합성 보상 파이프라인 구축, 주기적 정합성 검증 배치 운영.
- 한계점 2 : 테이블 비대화 및 인덱스 오버헤드로 인한 쓰기(CUD, Create, Update, Delete) 성능 급락
  - 한계점 : 과도한 컬럼·테이블 통합 시 레코드 크기 증가로 디스크 I/O 증가, 추가 인덱스에 따른 INSERT/UPDATE 지연 심화.
  - 해결 방안 : 수평적·수직적 테이블 파티셔닝(Partitioning) 병행, 갱신 빈도와 조회 빈도 기준 수직 분할 및 부분 인덱스(Partial Index) 활용.
- 한계점 3 : 비즈니스 로직 복잡도 증가 및 시스템 유지보수 비용 증대
  - 한계점 : 데이터 모델이 제3정규형에서 벗어나면서 애플리케이션 계층 정합성 유지 로직 직접 구현에 따른 코드 복잡도 급증.
  - 해결 방안 : CQRS(Command Query Responsibility Segregation) 패턴 채택을 통한 쓰기 모델(정규화)과 조회 전용 모델(반정규화·캐시·Elasticsearch)의 물리적·논리적 격리.

## Ⅵ. 반정규화에 대한 기술사적 제언

- 핵심 요약 : 최후의 수단 원칙 준수와 메타데이터 기반 데이터 거버넌스 체계 구축.
- 반정규화는 최후의 수단(Last Resort) : 성능 이슈 발생 시 무조건적 착수 지양, 실행 계획(Explain Plan) 분석 기반 인덱스 튜닝, 파티셔닝, 쿼리 리팩토링, 인메모리 캐시(Redis) 적용의 선행 검토 필요.
- 데이터 거버넌스 및 메타데이터 기록 : 성능 목적 반정규화 대상 테이블·컬럼의 메타데이터 관리 시스템 명시를 통한 향후 유지보수 시 데이터 불일치 버그 방지 권장.

## Ⅶ. 결론

- 핵심 요약 : 반정규화는 조회 성능과 정합성 사이의 전략적 트레이드오프 기법이나, 절차적 통제가 수반되어야 하는 설계 활동.
- 요약 : 3단계 추진 절차와 테이블·컬럼·관계 기법을 통해 병목 지점에 선별 적용하는 성능 최적화 수행.
- 시사점 : CQRS·CDC 기반 정합성 관리와 메타데이터 거버넌스를 결합한 통제된 반정규화 운영 체계 구축 필요.
