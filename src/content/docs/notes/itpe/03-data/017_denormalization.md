## 연관 키워드

- 반정규화(Denormalization), 역정규화, 데이터 중복, 테이블 병합, 테이블 분할, 파생 컬럼
- 다중 조인(Multi-way JOIN), 조회 성능, 데이터 정합성, CDC(Change Data Capture), CQRS(Command Query Responsibility Segregation), 트레이드오프

## Ⅰ. 반정규화의 개요

- 핵심 요약 : 조회 성능과 운영 단순화를 위해 정규화 원칙을 의도적으로 어기는 데이터 모델링 기법.
- 개념 : 정규화된 모델에서 성능 향상과 개발·운영 단순화를 위해 데이터를 의도적으로 중복, 통합, 분리하는 데이터 모델링 기법 (**반정규화** (Denormalization), 역정규화라고도 함).
- 배경 및 필요성 : 다중 조인(Multi-way JOIN)이 많은 쿼리는 응답이 느려지고, 대규모 집계나 실시간 대시보드 조회가 거래 처리 중심의 OLTP(Online Transaction Processing) 성능을 떨어뜨림.
- 주요 목적 : 읽기 성능을 높이되, 쓰기 오버헤드와 무결성 훼손 위험 사이의 트레이드오프를 관리하는 것.

## Ⅱ. 반정규화의 특징

- 핵심 요약 : 의도적 중복, 통합, 분리로 읽기 성능을 얻되, 대안을 모두 검토한 뒤에만 적용하는 방식.

1. 의도적 정규화 위배 : 성능 목적으로 데이터를 중복, 통합, 분리함.
2. 트레이드오프 구조 : 읽기 성능은 좋아지지만 쓰기(INSERT, UPDATE, DELETE) 부담과 무결성 훼손 위험이 생김.
3. 3대 적용 대상 : 테이블, 컬럼, 관계 세 단위로 나누어 적용함.
4. **최후의 수단** (Last Resort) 원칙 : 인덱스 튜닝, 파티셔닝, 캐싱 같은 대안을 먼저 검토한 뒤 적용함.
5. 정합성 동기화 체계 수반 : 트리거 기반 실시간 동기화나 주기적 검증 배치가 함께 필요함.

## Ⅲ. 반정규화의 구조 (흐름)

- 핵심 요약 : 대상 조사, 대안 검토, 적용의 3단계 추진 절차와, 테이블·컬럼·관계 단위의 기법 체계.

```text
[ 반정규화 추진 절차 ]
1단계 : 대상 조사
  - 잦은 조인 쿼리 식별
  - 대량 범위 처리, 집계 쿼리 빈도 확인
      ↓
2단계 : 다른 방법 검토
  - 인덱스 추가와 튜닝
  - 클러스터링, 파티셔닝
  - 애플리케이션 캐싱
      ↓
3단계 : 반정규화 적용
  - 테이블 / 컬럼 / 관계 단위 기법 선택
```

| 대상 구분 | 세부 기법 | 적용 방식 | 장점 및 위험 요인 |
| --- | --- | --- | --- |
| 테이블 | 테이블 병합 | 1:1 관계 테이블 병합, 1:M 관계 테이블 통합 | 조인 제거로 조회 향상 / 데이터 중복과 테이블 비대화 |
| 테이블 | 테이블 분할 | 자주 쓰는 컬럼 분리(수직), 파티셔닝(수평) | 입출력(I/O, Input/Output) 경합 분산 / 관리 복잡도 증가 |
| 테이블 | 집계·이력 테이블 추가 | 일·월별 집계 테이블, 최근 이력 전용 테이블 | 실시간 집계 부하 제거 / 원천 갱신 시 동기화 부담 |
| 컬럼 | 중복 컬럼 추가 | 조인을 줄이려 타 테이블 컬럼 복사 | 단일 테이블 조회 가능 / 양쪽 값을 항상 일치시켜야 함 |
| 컬럼 | 파생 컬럼 추가 | 총금액, 할인율 같은 계산 결과 사전 저장 | 런타임 계산 부하 제거 / 정합성 불일치 위험 |
| 관계 | 중복 관계 추가 | 다단계 관계(A→B→C)에 단축 경로(A→C) 선언 | 복합 조인 경로 단축 / 외래키 관계 유지 부담 |

## Ⅳ. 정규화와 반정규화의 비교

- 핵심 요약 : 무결성을 지향하는 정규화와 조회 성능을 지향하는 반정규화는 목적, 입출력(I/O, Input/Output) 특성, 저장 공간에서 상충한다.

```text
[ 정규화 vs 반정규화 ]
목적
  정규화   : 무결성, 이상 현상 배제
  반정규화 : 조회 성능, 조인 비용 제거
I/O 특성
  정규화   : 쓰기 우수, 읽기 시 조인 부담
  반정규화 : 읽기 우수, 쓰기 시 동기화 부담
```

| 비교 항목 | 정규화 (Normalization) | 반정규화 (Denormalization) |
| --- | --- | --- |
| 설계 목적 | 데이터 무결성, 이상 현상 배제 | 조회 성능 향상, 개발·운영 단순화 |
| 데이터 중복 | 최소화하여 저장 공간 절약 | 의도적으로 허용하여 저장 공간 증가 |
| 적용 시점 | 논리·물리 모델링 단계 | 성능 병목을 입증한 뒤 선별 적용 |
| 품질 관리 | 스키마 차원에서 이상 현상을 원천 차단 | 트리거나 배치로 정합성 동기화 필요 |

- 불일치 제어 방안 : 트리거나 이벤트 기반 비동기 동기화로 원천 변경을 반정규화 데이터에 반영하고, 주기적 검증 배치로 원천과 집계 데이터의 차이를 찾아 보정한다.

## Ⅴ. 반정규화의 장점과 한계

- 핵심 요약 : 조회 성능과 쿼리 단순화라는 장점과 달리, 정합성 훼손, 쓰기 성능 저하, 유지보수 비용에서 한계를 가짐.

장점은 세 가지다.
1. 조인 제거를 통해 조회 성능을 크게 높임.
2. 사전 집계 테이블로 실시간 집계 부하를 없앰.
3. 단순해진 쿼리 구조로 개발 생산성이 올라감.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 정합성 훼손 | 같은 데이터가 여러 테이블에 복제되어 일부만 갱신되면 불일치가 생김 | 트랜잭션 내 동기 갱신, **CDC** (Change Data Capture) 기반 보상 파이프라인, 주기적 검증 배치 | 불일치 건수, 보정 소요 시간 |
| 쓰기 성능 저하 | 컬럼과 테이블이 커져 디스크 I/O가 늘고, 추가 인덱스로 INSERT와 UPDATE가 느려짐 | 수평·수직 파티셔닝 병행, 갱신 빈도 기준 수직 분할, 부분 인덱스(Partial Index) 활용 | 쓰기 지연 시간, 테이블 크기 |
| 유지보수 비용 증가 | 제3정규형에서 벗어나 애플리케이션이 정합성 로직을 직접 구현해 코드가 복잡해짐 | **CQRS** (Command Query Responsibility Segregation) 패턴으로 쓰기 모델(정규화)과 조회 모델(반정규화, 캐시)을 분리 | 변경 작업당 수정 파일 수, 장애 건수 |

## Ⅵ. 반정규화에 대한 기술사적 제언

- 핵심 요약 : 반정규화 여부를 감이 아닌 측정 결과로 결정하고, 적용 내역을 조직의 기록으로 남기는 통제 체계.
- 반정규화 대상은 실행 계획과 응답 시간 측정으로 병목을 입증한 뒤에만 승인하도록 절차를 두는 것이 바람직하다. 승인 없이 성능 문제를 이유로 테이블을 고치는 관행은 이후 원인 추적을 어렵게 만든다.
- 반정규화된 테이블과 컬럼의 원천, 갱신 주기, 담당 시스템을 메타데이터 저장소에 기록해 두어야 한다. 그래야 원천 스키마가 바뀔 때 파생 데이터의 불일치를 조기에 발견할 수 있다.

## Ⅶ. 결론

- 핵심 요약 : 반정규화는 조회 성능과 정합성 사이의 전략적 트레이드오프 기법이며, 절차적 통제가 함께 따라야 하는 설계 활동.
- 시사점 : 병목을 측정해 선별 적용하고, CQRS·CDC 기반 정합성 관리와 메타데이터 기록을 함께 갖출 때 운영 가능한 모델이 됨.
