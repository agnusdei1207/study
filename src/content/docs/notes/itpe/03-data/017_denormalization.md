## 연관 키워드

- 반정규화(Denormalization), 역정규화, 데이터 중복, 테이블 병합, 테이블 분할, 중복 컬럼, 파생 컬럼
- 조인(JOIN), 조회 성능, 데이터 정합성, 트리거(Trigger), 무결성, 트레이드오프, 최후의 수단(Last Resort)

## Ⅰ. 반정규화의 개요

- 핵심 요약 : 조회 성능과 운영 단순화를 위해 정규화 설계 원칙을 의도적으로 어기는 데이터 모델링 기법.
- 개념 : 정규화된 데이터 모델에서 성능 향상과 운영 단순화를 위해 데이터를 의도적으로 중복·통합·분리하는 기법 (**반정규화**, Denormalization), 역정규화라고도 부름.
- 배경 및 필요성 : 정규화된 스키마는 하나의 값을 얻기 위해 여러 테이블의 조인(JOIN)을 요구하므로, 대용량 집계와 실시간 조회가 많은 업무에서 응답 시간 병목이 발생.
- 주요 목적 : 읽기 성능과 쿼리 단순화를 확보하되, 정규형 위배로 재발하는 **이상 현상**(Anomaly, 삽입·삭제·수정 시의 데이터 불일치) 위험을 통제하는 것.

## Ⅱ. 반정규화의 특징 및 장점

- 핵심 요약 : 의도적 중복으로 조인을 제거해 읽기 성능을 얻는 대신, 정합성 관리 비용이라는 트레이드오프를 수반하는 설계 판단.

1. 의도적 중복 : 같은 속성을 여러 테이블에 두어 조인을 생략 → 응답 시간 단축 효과.
2. 사전 계산 : **파생 컬럼**(계산 결과의 사전 저장)과 집계 테이블로 연산을 미리 수행 → 런타임 연산 부하 제거 효과.
3. 구조 단순화 : 테이블 병합으로 조회 경로를 축소 → 개발 생산성과 유지보수성 향상 효과.
4. 대안 우선 원칙 : 인덱스 튜닝, 파티셔닝, 캐시 검토를 먼저 수행하는 **최후의 수단**(Last Resort) 원칙 → 불필요한 중복 도입 방지 효과.
5. 동기화 체계 수반 : 트리거(Trigger)나 배치로 원천과 사본의 정합성 유지 → 중복 데이터의 신뢰성 확보 효과.

## Ⅲ. 반정규화의 구조 (흐름)

- 핵심 요약 : 병목 측정, 대안 검토, 기법 선택, 정합성 관리 설계의 순차 절차와 테이블·컬럼·관계 단위의 기법 체계.

```text
[ 반정규화 적용 절차 ]

대상 조사 : 조인 다발 쿼리, 집계 쿼리 파악
        ↓
대안 검토 : 인덱스, 파티셔닝, 캐시
        ↓
기법 선택 : 테이블, 컬럼, 관계 단위
        ↓
정합성 관리 : 동기화 수단·검증 주기 설계
```

```text
[ 데이터 정합성 동기화 흐름 ]

원천 테이블 갱신
        ↓  트리거 또는 이벤트 발생
중복·파생 데이터 동기 갱신
        ↓  주기적 검증 배치 실행
불일치 검출 및 보정
```

- 테이블 단위 : 테이블 병합(1:1·1:M 관계 통합), 테이블 분할(수직·수평), 집계·이력 테이블 추가.
- 컬럼 단위 : **중복 컬럼**(타 테이블 속성의 복사)과 파생 컬럼의 추가.
- 관계 단위 : 다단계 경로를 잇는 중복 관계 선언으로 조인 경로 단축.

## Ⅳ. 정규화와 반정규화의 비교

- 핵심 요약 : 무결성 지향의 정규화와 조회 성능 지향의 반정규화는 상충하면서도 보완 관계에 있는 설계 선택.

| 비교 축 | 정규화(Normalization) | 반정규화(Denormalization) |
| --- | --- | --- |
| 설계 목적 | 이상 현상 제거, 무결성 확보 | 조회 성능 향상, 쿼리 단순화 |
| 데이터 중복 | 최소화로 저장 공간 절약 | 의도적 허용으로 저장 공간 증가 |
| 적용 시점 | 논리·물리 모델링 단계 | 성능 병목 입증 후 선별 적용 |
| 쓰기 부담 | 낮음 | 동기화 갱신으로 증가 |
| 품질 통제 | 스키마 차원의 이상 현상 원천 차단 | 트리거·배치 기반 정합성 검증 필요 |

- 선택 기준 : 기본 설계는 제3정규형(3NF, Third Normal Form) 수준의 정규화로 두는 것.
- 선택 기준 : 실행 계획과 응답 시간 측정으로 조회 병목이 입증된 대상에만 적용하는 것.
- 선택 기준 : 갱신 빈도가 높은 데이터는 중복 시 정합성 비용이 커서 제외하는 것.

## Ⅴ. 반정규화의 한계와 방안

- 핵심 요약 : 정합성 훼손, 쓰기 부담, 이상 현상 재발, 유지보수 비용이 한계이며 동기화 체계로 일대일 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 정합성 훼손 | 중복 데이터의 부분 갱신 → 값 불일치와 신뢰 하락 | 트랜잭션 내 동기 갱신, 주기적 검증 배치 운영 | 불일치 건수 |
| 쓰기 성능 저하 | 테이블 비대화와 갱신 대상 증가 → 쓰기 지연 | 갱신 빈도 기준 수직 분할, 인덱스 재검토 | 쓰기 지연 시간 |
| 이상 현상 재발 | 정규형 위배 구조의 재도입 → 삽입·삭제·수정 이상 | 적용 대상과 사유의 문서화, 주기적 재검토 | 이상 징후 건수 |
| 유지보수 비용 증가 | 정합성 로직의 애플리케이션 분산 → 변경 부담 증가 | 원천·사본 관계의 메타데이터 기록 | 변경 소요 시간 |

## Ⅵ. 반정규화에 대한 기술사적 제언

- 핵심 요약 : 반정규화를 감이 아닌 측정과 승인 절차로 통제하고, 적용 내역을 조직 자산으로 관리하는 체계.
- 설계 거버넌스 : 데이터 아키텍처 조직이 성능 측정 결과를 요건으로 하는 반정규화 승인 절차를 설계 표준에 명문화.
- 형상 연계 : 개발 조직이 원천 스키마 변경 시 반정규화 대상의 영향도를 형상 관리 체계로 점검.
- 자산화 : 운영 조직이 적용 내역과 사유를 조직 데이터 자산 목록으로 등록하고 주기적으로 재검토.

## Ⅶ. 결론

- 핵심 요약 : 반정규화는 정규화 이론 위에서 조회 성능을 얻는 전략적 트레이드오프 기법.
- 시사점 : 측정 기반 선별 적용과 정합성 동기화 체계가 함께할 때 실무적 효과를 발휘.
