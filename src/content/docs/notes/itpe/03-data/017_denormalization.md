## Ⅰ. 성능 최적화를 위한 반정규화(Denormalization)의 개요

### 가. 반정규화의 정의
- **반정규화** : 정규화된 데이터 모델에서 시스템의 성능 향상, 개발 및 운영의 단순화를 위해 의도적으로 정규화 원칙을 위배하여 데이터의 중복, 통합, 분리를 수행하는 데이터 모델링 기법.
- 읽기 작업의 성능(조회 속도)을 대폭 향상시키는 대신, 쓰기 작업(INSERT, UPDATE, DELETE) 시의 오버헤드와 데이터 무결성 훼손 위험을 수반하는 대표적인 **트레이드오프** 기법.

### 나. 반정규화의 적용 배경
- 데이터베이스 설계 후 시스템 운영 중 복잡한 **다중 조인** (Multi-way JOIN)으로 인한 쿼리 응답 지연 발생.
- 대규모 배치 집계나 실시간 대시보드 조회가 OLTP(Online Transaction Processing) 트랜잭션의 성능을 저해할 때.

## Ⅱ. 반정규화의 추진 절차 및 핵심 대상 분류

### 가. 반정규화 3단계 추진 절차

```text
[ 반정규화 추진 절차 ]
[1단계: 반정규화 대상 조사]  ---> [2단계: 다른 방법 유도 검토]  ---> [3단계: 반정규화 적용]
 - 잦은 조인 쿼리 식별           - 인덱스 추가 및 튜닝            - 테이블 반정규화
 - 대량 데이터 범위 처리        - 클러스터링, 파티셔닝           - 컬럼 반정규화
 - 통계 및 집계 쿼리 빈도        - 응용프로그램 캐싱(Redis)       - 관계 반정규화
```

### 나. 반정규화 3대 핵심 기법

| 대상 구분 | 세부 기법 | 구체적 적용 방식 | 장점 및 위험 요인 |
| :--- | :--- | :--- | :--- |
| **테이블 반정규화** | **테이블 병합** | 1:1 관계 테이블 병합, 1:M 관계 테이블 통합 | 조인 제거로 조회 성능 극대화 / 데이터 중복 및 테이블 비대화 |
| **테이블 반정규화** | **테이블 분할** | 수직 분할(자주 쓰는 컬럼 분리), 수평 분할(파티셔닝) | I/O 경합 분산, 캐시 효율 증대 / 관리 복잡도 증가 |
| **테이블 반정규화** | **통계/이력 테이블 추가** | 일/월별 집계 테이블 사전 생성, 최근 이력 전용 테이블 | 실시간 집계 부하 원천 제거 / 원천 데이터 갱신 시 동기화 오버헤드 |
| **컬럼 반정규화** | **중복 컬럼 추가** | 조인을 줄이기 위해 자주 조회되는 타 테이블 컬럼을 복사 | 단일 테이블 단독 조회 가능 / UPDATE 시 양쪽 컬럼 일치 유지 필수 |
| **컬럼 반정규화** | **파생/계산 컬럼 추가** | 총금액, 할인율 등 연산 결과를 컬럼에 미리 저장 | 런타임 계산 부하 배제 / 정합성 불일치 위험 |
| **관계 반정규화** | **중복 관계 추가** | 여러 단계를 거치는 관계(A $\rightarrow$ B $\rightarrow$ C)에서 단축 경로(A $\rightarrow$ C) 관계 선언 | 복합 조인 경로 단축 / 외래키 관계 유지 부담 |

## Ⅲ. 정규화 vs 반정규화 비교 분석 및 부작용 제어

### 가. 정규화와 반정규화의 기술적 트레이드오프

```text
[ 정규화 vs 반정규화 상충 관계 ]
               정규화 (Normalization)            반정규화 (Denormalization)
  목적       : 데이터 무결성, 이상현상 배제        성능 향상, 조인 비용 제거
  I/O 특성   : 쓰기(CUD) 성능 우수, 읽기 부하       읽기(R) 성능 우수, 쓰기 부하
  저장 공간  : 중복 최소화로 스토리지 절감         데이터 중복으로 스토리지 증가
```

### 나. 반정규화에 따른 데이터 불일치 제어 방안
- **트리거(Trigger) 및 이벤트 기반 비동기 동기화** : 원천 테이블 변경 시 반정규화 테이블/컬럼을 실시간 동기화.
- 주기적 데이터 정합성 검증 배치 : 매일 새벽 배치 작업을 통해 원천 테이블과 반정규화 집계 데이터 간의 불일치를 자동 비교하고 보정(Reconciliation).

## Ⅳ. 반정규화 적용 시 주요 한계점 및 해결 방안

- 데이터 중복에 따른 이상 현상(Anomaly) 및 정합성 훼손 :
  - 한계점 : 동일한 데이터가 다수 테이블에 분산 복제되어 특정 테이블만 UPDATE되고 다른 테이블이 누락될 경우 데이터 불일치(Data Inconsistency) 발생.
  - 해결 방안 : 트랜잭션 내 동기 갱신 보장 또는 비동기 CDC(Change Data Capture) 기반 정합성 보상 파이프라인 구축 및 주기적 정합성 검증 배치 운영.
- 테이블 비대화 및 인덱스 오버헤드로 인한 쓰기(CUD, Create, Update, Delete) 성능 급락 :
  - 한계점 : 조회 성능을 위해 컬럼과 테이블을 과도하게 통합하면 레코드 크기 증가로 디스크 I/O가 늘어나고 추가된 인덱스로 인해 INSERT/UPDATE 지연 심화.
  - 해결 방안 : 수평적/수직적 테이블 파티셔닝(Partitioning) 병행, 자주 갱신되는 컬럼과 조회가 빈번한 컬럼의 수직 분할 및 부분 인덱스(Partial Index) 활용.
- 비즈니스 로직 복잡도 증가 및 시스템 유지보수 비용 증대 :
  - 한계점 : 데이터 모델이 제3정규형을 벗어나면서 애플리케이션 계층에서 정합성 유지 로직을 직접 구현해야 하므로 코드 복잡도 급증.
  - 해결 방안 : CQRS(Command Query Responsibility Segregation) 패턴을 채택하여 쓰기 모델(정규화)과 조회 전용 모델(반정규화/캐시/Elasticsearch)을 물리적·논리적으로 격리.

## Ⅴ. 반정규화 수행을 위한 실무 제언

- 반정규화는 최후의 수단(Last Resort) : 성능 이슈 발생 시 무조건 반정규화부터 착수하지 말고, 실행 계획(Explain Plan) 분석을 통한 인덱스 튜닝, 파티셔닝, 쿼리 리팩토링, 인메모리 캐시(Redis) 적용을 먼저 검토해야 함.
- 데이터 거버넌스 및 메타데이터 기록 : 어떤 테이블과 컬럼이 성능 목적으로 반정규화되었는지 메타데이터 관리 시스템에 반드시 명시하여, 향후 시스템 유지보수 시 데이터 불일치 버그가 발생하는 것을 방지할 것을 제언함.
