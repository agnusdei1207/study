## 지식 로드맵 내 현재 위치
```text
데이터베이스 → 물리 데이터 모델 → 반정규화
```

## 큰 그림과 30초 인출
```text
[정규화 모델] → 측정된 조회 병목 → Index·SQL·Cache 우선 검토
                                ↓ 미해결
                  [테이블 통합·분할·중복 컬럼]
                                ↓
                    동기화·무결성·회귀 검증
```
- 본질: **정규화된 모델의 조회 성능을 높이기 위해 중복·통합·분할을 의도적으로 도입하는 물리 설계 기법**
- 원칙: 정규화 후 측정된 병목에만 적용하고 중복 데이터의 정합성 책임을 명시

## 예상문제
> 반정규화의 개념·유형·수행 절차를 설명하고 정규화와 비교하여 무결성 보완 방안을 논하시오. (25점)

## Ⅰ. 성능을 위한 통제된 중복, 반정규화 개요
- 정의: 조인·집계·I/O 비용을 줄이기 위해 정규화 구조를 의도적으로 중복·통합·분할하는 기법
- 목적: 읽기 지연과 복잡한 조인 감소, 반복 집계의 사전 계산
- 전제: 정규화 완료, 병목 측정, 다른 튜닝 대안 검토, 정합성 유지방안 확보

## Ⅱ. 적용 판단 기준
| 기준 | 적용 신호 | 확인 항목 |
|---|---|---|
| 접근 패턴 | 동일 조인·집계 반복 | 빈도·SLA·실행계획 |
| 읽기/쓰기 | 읽기 비중이 높음 | 갱신 비용·충돌 |
| 데이터 생명주기 | 함께 조회·변경 | 소유 원천·동기화 |
| 대안 | Index·SQL 개선 한계 | 비용 비교·회귀시험 |

## Ⅲ. 반정규화 3대 유형
| 유형 | 기법 | 효과 | 위험 |
|---|---|---|---|
| 테이블 | 병합·추가·수평/수직 분할 | 조인·I/O 감소 | 구조 복잡성 |
| 컬럼 | 중복·파생·이력 컬럼 | 계산·조인 제거 | 갱신 불일치 |
| 관계 | 중복 관계·집계 테이블 | 탐색·집계 단축 | 동기화 비용 |

## Ⅳ. 반정규화 수행 절차
```text
정규화 → 병목 측정 → SQL·Index·Cache 대안 비교 → 대상 선정
 → 중복 원천·동기화 설계 → 적용 → 성능·정합성·복구 검증
```
- 원천 필드를 하나로 지정하고 Trigger·CDC·Event·Batch 중 갱신 방식을 선택
- 장애·재처리 시 중복값을 재구성할 수 있어야 함

## Ⅴ. 정규화와 반정규화 비교
| 구분 | 정규화 | 반정규화 |
|---|---|---|
| 목적 | 중복 제거·무결성 | 조회 성능·단순 질의 |
| 구조 | 작은 관계로 분해 | 통합·중복·사전집계 |
| 읽기 | 조인 증가 가능 | 조인·계산 감소 |
| 쓰기 | 변경 지점 명확 | 다중 위치 동기화 |
| 관계 | 선행 기준 모델 | 측정 기반 물리 최적화 |

## Ⅵ. 무결성과 운영 고려사항
| 문제 | 원인 | 대책 |
|---|---|---|
| 중복값 불일치 | 갱신 경로 분산 | 원천 지정·트랜잭션/CDC·대사 |
| 성능개선 미미 | 추정만으로 적용 | 전후 실행계획·부하시험 |
| 재처리 불가 | 파생 규칙·이력 부재 | 재생 가능한 변환·감사로그 |
| 무분별한 확산 | 승인 기준 부재 | 모델 변경심의·Rollback 계획 |

## Ⅶ. 성능 이익보다 정합성 비용을 먼저 계산하는 결론
- 반정규화는 설계 실패의 은폐가 아니라 측정 근거가 있는 최후의 물리 최적화
- 성능 목표와 함께 동기화·복구·폐기 조건을 기준선으로 관리

## 1교시 10점 답안 발췌
```text
정규화 → 병목 측정 → 대안 검토 → 테이블/컬럼/관계 반정규화
        → 원천·동기화 → 성능·정합성 검증
```
| 이익 | 대가 |
|---|---|
| 조인·집계 감소 | 중복·갱신·복구 책임 증가 |
