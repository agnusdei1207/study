## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터 모델링 → **반정규화**

## 30초 인출

- 본질: 반정규화는 정규화한 테이블에 조회 성능을 위해 일부러 중복 컬럼이나 파생값을 두거나 테이블을 병합·분할하는 물리 설계 활동
- 메커니즘: 성능 문제를 진단해 인덱스·뷰 같은 다른 방법을 먼저 검토하고 그래도 필요한 경우에만 반정규화하며 중복 값의 정합성을 유지할 수단을 함께 마련
- 통찰: 반정규화는 조회를 빠르게 하는 대신 갱신 비용과 불일치 위험을 만들므로 측정한 성능 병목이 확인된 곳에만 적용하고 정합성 유지 방안을 함께 설계

<details>
<summary>핵심 용어</summary>

- **반정규화(Denormalization)** : 조회 성능을 위해 중복·파생 데이터를 허용하는 물리 설계
- **정규화(Normalization)** : 중복과 갱신 이상을 줄이도록 테이블을 분해하는 설계
- **중복 컬럼** : 조회를 위해 다른 테이블의 값을 함께 저장한 컬럼
- **파생·집계 컬럼** : 다른 값으로 계산해 미리 저장한 컬럼
- **갱신 이상** : 중복된 값의 일부만 바뀌어 불일치가 생기는 문제
- **정합성** : 여러 곳에 저장된 같은 사실이 서로 일치하는 성질

</details>

## 2~4교시 25점 답안

## Ⅰ. 반정규화의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **반정규화** 는 조회 성능을 위해 중복·파생 데이터를 허용하거나 테이블을 병합·분할하는 물리 설계 |
| 목적 | 조인 감소를 통한 조회 성능 개선 |

## Ⅱ. 정규화와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 성능 우선 | 조회 속도를 위한 중복 허용 |
| 대가 존재 | 갱신 비용·정합성 위험 증가 |
| 선택적 적용 | 병목이 확인된 곳에만 적용 |

## Ⅲ. 절차와 유형

### 반정규화 절차

```text
성능 병목 확인(느린 조회·조인)
        ↓
다른 방법 검토 (인덱스·뷰·쿼리 튜닝)
        ↓
반정규화 대상 선정 → 유형 선택 → 적용
        ↓
정합성 유지 방안 적용 → 성능 재측정
```

### 유형

| 구분 | 유형 | 내용 |
|---|---|---|
| 테이블 | 병합 | 자주 조인하는 테이블을 하나로 합침 |
| 테이블 | 분할(수직·수평) | 컬럼 또는 행을 나누어 조회 대상 축소 |
| 테이블 | 중복 테이블 | 집계·통계용 사본 테이블 추가 |
| 컬럼 | 중복 컬럼 | 조회에 필요한 값을 함께 저장 |
| 컬럼 | 파생 컬럼 | 계산 결과를 미리 저장 |
| 관계 | 중복 관계 | 경로가 긴 관계를 직접 연결 |

## Ⅳ. 고려사항

| 고려사항 | 내용 |
|---|---|
| 정합성 | 중복 값의 동시 갱신 방법(트리거·배치·응용 로직) |
| 갱신 성능 | 갱신 시 추가되는 작업량 |
| 저장 공간 | 중복 데이터 증가 |
| 대안 검토 | 인덱스·뷰·캐시 등 다른 방법의 선행 검토 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 중복 값의 불일치 | 갱신 경로를 한 곳으로 모으고 정기 검증 |
| 병목 근거 없이 반정규화 | 성능 측정으로 병목 확인 후 적용 |
| 갱신 성능 저하 | 조회·갱신 비율을 따져 적용 여부 결정 |

## Ⅵ. 제언

성능 측정으로 병목이 확인된 조회에만 반정규화하고, 정합성 유지 방안을 함께 설계해 적용 후 성능과 정합성을 검증

```text
병목 확인 ─ 인덱스·뷰로 해결 → 종료
          └ 해결 불가 → 반정규화 + 정합성 방안 → 성능·정합성 검증
```

| 구분 | 예상에 의한 반정규화 | 제언: 측정 기반 적용 |
|---|---|---|
| 적용 근거 | 추정 | 병목 측정 |
| 정합성 | 사후 문제 | 함께 설계 |
