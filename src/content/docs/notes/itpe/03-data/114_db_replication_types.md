## 연관 키워드

**복제(Replication)**, **동기/비동기/반동기**, **단일/다중/리더리스**, **SBR/RBR**, **Raft/Paxos**, **CRDT**, **RPO/RTO**

## Ⅰ. 개요

- 핵심 요약 : **데이터베이스 복제**는 Primary 데이터를 Secondary로 지속 복사·동기화하는 기술.
- 목적 : 무중단 가용성, 읽기 부하 분산, 지리적 지연 단축.
- 배경 : 단일 DB 장애·부하 한계 → 복제본으로 가용성·확장성 확보.
- 특징 : 동기화 시점(동기/비동기/반동기), 토폴로지(단일/다중/리더리스), 전송 계층(SBR/RBR).

## Ⅱ. 특징 및 장점

- 핵심 요약 : **3대 분류**로 동기화·토폴로지·전송 계층을 조합.
- **동기식** : 커밋 전 복제본 ACK 대기, 무손실, 지연 증가.
- **비동기식** : 커밋 후 백그라운드 복제, 빠른 응답, 유실 위험.
- **반동기식** : 최소 1개 노드 ACK 후 커밋, 균형.
- **단일 리더** : 충돌 없음, 쓰기 스케일아웃 불가.
- **다중/리더리스** : 쓰기 분산·강건, 충돌 해결 필요.

## Ⅲ. 동기화 메커니즘 흐름

- 핵심 요약 : **동기/비동기/반동기** 동기화 시점 비교.
- 토폴로지 : 단일 리더, 다중 리더, 리더리스.
- 전송 계층 : SBR(문장), RBR(행), Mixed.

```text
[ 복제 동기화 메커니즘 ]

(A) 동기식 : Primary -> Standby (ACK) -> Client Commit
   무손실 / 지연 증가

(B) 비동기식 : Primary -> Client Commit
   백그라운드 복제 -> Standby
   빠른 응답 / 유실 위험 (RPO>0)

(C) 반동기식 : 최소 1개 노드 ACK 후 커밋
   균형
```

```text
[ 토폴로지 비교 ]

단일 리더 : 충돌 없음, 쓰기 스케일아웃 불가
다중 리더 : 쓰기 분산, 충돌 해결 필요
리더리스 : 강건, 정합성 관리 필요
```

## Ⅳ. 토폴로지 비교

- 핵심 요약 : **충돌·스케일아웃·강건성** 트레이드오프.

| 항목 | 단일 리더 | 다중 리더 | 리더리스 |
|---|---|---|---|
| 쓰기 | 마스터 전담 | 복수 노드 | 클라이언트 직접 |
| 충돌 | 없음 | 발생 가능 | Quorum 관리 |
| 강건성 | 페일오버 필요 | 마스터 장애 무영향 | SPOF 부재 |
| 정합성 | 강함 | 충돌 해결 필요 | W+R>N 관리 |

## Ⅴ. 한계와 방안

- 핵심 요약 : **동기 지연·비동기 유실·충돌·스플릿 브레인**을 반동기·CRDT·합의 프로토콜로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 동기 지연 | 모든 복제본 ACK 대기로 처리량 급감 | 반동기 복제, Quorum 합의 | 쓰기 지연 |
| 비동기 유실 | 마스터 장애 시 미전송 데이터 유실 | 무손실 반동기, 공유 스토리지 | RPO |
| 다중 마스터 충돌 | 동시 갱신·네트워크 단절로 분기 | CRDT, 펜싱(STONITH) | 충돌 발생률 |
| SBR 비결정성 | NOW()/UUID() 등으로 노드 불일치 | RBR 또는 Mixed 전환 | 복제 정합성 |

## Ⅵ. 기술사적 제언

- 핵심 요약 : **복제 지연 방어·합의 프로토콜·CRDT**로 고신뢰 복제.
- stale read 방어 : Read-after-write 보장 (작성 직후 Primary 읽기).
- 스플릿 브레인 방지 : Raft/Paxos 합의 오케스트레이터 (Patroni).
- CRDT 적용 : 다중 마스터 충돌 없는 데이터 타입.

## Ⅶ. 결론

- 핵심 요약 : 복제는 **동기화·토폴로지·전송 계층** 조합으로 가용성·확장성 확보.
- 답안에는 3대 분류, 토폴로지 비교, 한계·대응, 실무 제언을 연결.
- 참고 : [PostgreSQL Replication](https://www.postgresql.org/docs/current/high-availability.html).
