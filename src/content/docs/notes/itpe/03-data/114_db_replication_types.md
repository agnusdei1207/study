## 지식 로드맵 내 현재 위치

자료처리·데이터 → 분산 데이터베이스 → **데이터베이스 복제 유형**

## 30초 인출

- 본질: 데이터베이스 복제는 원본의 변경을 복제 노드에 전달·반영해 사본을 유지하는 기술
- 메커니즘: 커밋 응답 시점에 따라 비동기(로컬 커밋만 확인)·반동기(지정 수의 수신 확인)·동기(지정 단계 확인)로 나뉘고, 장애 시 복제 위치를 확인해 기존 리더를 펜싱한 뒤 후보를 승격하고 나머지를 재동기화
- 통찰: 확인 대기를 늘릴수록 손실 위험은 줄지만 지연이 늘고, 비동기 지연은 쓰기 직후 오래된 값을 읽게 하므로 RPO 목표로 방식을 고르고 읽기 경로를 라우팅

<details>
<summary>핵심 용어</summary>

- **동기·비동기·반동기 복제** : 복제 확인까지 기다린 뒤 응답 / 기다리지 않고 응답 / 지정 수의 수신 확인 후 응답
- **복제 지연(Replication Lag)** : 원본 변경이 복제본에 반영되기까지의 시간 차
- **단일 쓰기·다중 쓰기 토폴로지** : 한 노드만 쓰기를 받는 구성 / 복수 노드가 쓰기를 받는 구성
- **펜싱(Fencing)** : 기존 리더의 쓰기 권한을 차단하는 조치
- **스플릿 브레인** : 단절된 양쪽이 각자 쓰기를 허용하는 상태
- **RPO** : 허용 데이터 손실 시점 차이

</details>

## 2~4교시 25점 답안

## Ⅰ. 데이터베이스 복제의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터베이스 복제** 는 원본의 변경을 복제 노드에 전달·반영하는 기술 |
| 목적 | 가용성·읽기 확장·복구 요구에 맞춰 사본을 유지하고 동기화 수준 선택 |

## Ⅱ. 특징

| 특징 | 의미 |
|---|---|
| 확인 시점 선택 | 커밋 응답 조건에 따라 지연·손실 범위가 달라짐 |
| 지연 존재 | 비동기 복제본은 오래된 값을 반환할 수 있음 |
| 토폴로지 선택 | 단일 쓰기는 승격, 다중 쓰기는 충돌 해결이 핵심 |

## Ⅲ. 유형 비교와 장애 승격

```text
Primary 변경·로그 기록
 ├ 비동기: 로컬 커밋 응답 → 나중에 Replica 반영
 ├ 반동기: 지정 수의 수신 확인 뒤 응답
 └ 동기: 설정된 복제 단계 확인 뒤 응답
        ↓ 장애 시
복제 위치·미반영 로그 확인 → 기존 리더 펜싱 → 후보 승격 → 나머지 재동기화
```

| 비교 | 동기 | 비동기 | 반동기 |
|---|---|---|---|
| 커밋 응답 조건 | 지정 복제 단계 확인 | 원본 로컬 커밋 | 제품별 지정 수의 수신 확인 |
| 장애 시 손실 | 확인 단계·승격 대상에 따라 평가 | 미전송 변경 손실 가능 | 확인·미확인 변경을 구분 |
| 응답 지연 | 원격 확인 대기 반영 | 원격 대기 없음 | 확인 복제본까지의 통신 지연 |
| 네트워크 단절 | 대기·실패 정책에 좌우 | 원본은 로컬 커밋 가능 | 대기·타임아웃·비동기 전환은 설정에 좌우 |

## Ⅳ. 토폴로지와 복제 지연

| 비교 | 단일 쓰기 노드 | 다중 쓰기 노드 |
|---|---|---|
| 쓰기 | 한 Primary가 수용 | 복수 노드가 수용 |
| 충돌 | 승격 시 기존 리더 차단 실패 점검 | 같은 데이터 동시 변경의 충돌 해결 필요 |
| 장애 조치 | 복제 위치 확인·후보 승격·펜싱 | 쓰기 노드 상태·충돌 정책 확인 |

```text
사용자 쓰기 → Primary 커밋 → Replica 적용 대기
        ↓ 곧바로 읽기
Replica 미반영 → 오래된 값 가능 → Primary로 라우팅 또는 커밋 위치 반영 확인 후 Replica 읽기
```

| 지연 원인 | 대응 |
|---|---|
| 쓰기량이 복제 적용량 초과 | 지연·대기열 계측, 부하·대상 용량 조정 |
| 갱신 직후 보조노드 읽기 | 원본 읽기 또는 읽기 시점 보장 기능 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 자동 승격도 미반영 로그·분기 쓰기를 낳을 수 있음 | 복제 확인 조건·펜싱·재동기화 절차를 장애 훈련으로 검증 |
| 비동기 지연으로 쓰기 직후 오래된 값 조회 | 세션 읽기를 Primary로 보내거나 반영 위치 확인 후 조회 |
| 반동기 타임아웃 시 보장 수준 변화 | 제품의 전환·실패 동작 확인, RPO 목표로 시험 |

정족수·감시자의 장애 판정만으로 기존 리더가 쓰기를 멈추는 것은 아니므로 승격 전 펜싱과 복구 후 재동기화를 함께 검증.

## Ⅵ. 제언

업무별 RPO로 복제 방식을 정하고, 읽기 경로와 승격 절차를 장애 훈련으로 검증

```text
RPO·지연 목표 → 동기/반동기/비동기 선택 → 읽기 라우팅 → 승격·펜싱 훈련
```

| 구분 | 일괄 비동기 | 제언: 업무별 방식 선택 |
|---|---|---|
| 손실 | 미전송 변경 손실 | RPO 기준 관리 |
| 읽기 | 오래된 값 노출 | 라우팅으로 보완 |
