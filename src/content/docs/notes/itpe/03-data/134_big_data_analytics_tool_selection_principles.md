## 연관 키워드

**빅데이터 도구 선정**, **워크로드 적합성**, **TCO(Total Cost of Ownership)**, **벤더 종속(Vendor Lock-in)**, **오버엔지니어링**, **PoC**

## Ⅰ. 개요

- 핵심 요약 : **빅데이터 분석 도구 선정**은 워크로드·규모·역량·TCO를 종합 평가해 최적 도구를 채택하는 의사결정.
- 목적 : 비즈니스 목표에 맞는 수집·저장·처리·분석·시각화 도구 선택.
- 배경 : 잘못된 선정 시 기술 부채·비용 폭증(화이트 엘리펀트).
- 특징 : 5대 평가 원칙, 워크로드별 엔진 매핑.

## Ⅱ. 특징 및 장점

- 핵심 요약 : **5대 원칙**으로 워크로드 적합성·확장성·생태계·사용성·TCO 평가.
- **워크로드 적합성** : 배치/스트리밍/대화식.
- **확장성·성능** : 페타바이트 수평 확장.
- **생태계·호환성** : 레거시·클라우드 연동.
- **사용성** : 표준 SQL, Python/R 지원.
- **TCO** : 라이선스·컴퓨팅·운영 인건비.

## Ⅲ. 선정 흐름

- 핵심 요약 : **워크로드 분류 → 5대 원칙 평가 → PoC → 채택**.
- 평가 영역 : 지연시간, SQL 지원, 탄력성, 보안/거버넌스, 커뮤니티.

```text
[ 빅데이터 도구 5대 선정 원칙 ]

1. 워크로드 적합성 : 배치/스트리밍/대화식
2. 확장성·성능     : 페타바이트 수평 확장
3. 생태계·호환성   : 레거시·클라우드 연동
4. 사용성·생산성   : 표준 SQL, Python/R
5. TCO             : 라이선스·컴퓨팅·운영
```

```text
[ 워크로드별 엔진 매핑 ]

배치 ETL       -> Apache Spark
실시간 스트림  -> Apache Flink
대화식 SQL     -> Trino/Starburst
실시간 OLAP    -> ClickHouse/Pinot
클라우드 DW    -> Snowflake/BigQuery
```

## Ⅳ. 워크로드별 엔진 비교

- 핵심 요약 : **워크로드 특성**에 따른 엔진 선택.

| 워크로드 | 데이터 특성 | 추천 엔진 | 강점 |
|---|---|---|---|
| 배치 ETL | TB~PB 일괄 변환 | Apache Spark | DAG 인메모리, 셔플 관리 |
| 실시간 스트림 | 밀리초 이벤트 감지 | Apache Flink | Event-Time, Exactly-once |
| 대화식 SQL | 수초 BI 질의 | Trino/Starburst | 인메모리 페더레이션 |
| 실시간 OLAP | 초당 수만 건 집계 | ClickHouse/Pinot | SIMD 벡터화 |
| 클라우드 DW | 전사 통합 분석 | Snowflake/BigQuery | 서버리스, 분리 |

## Ⅴ. 한계와 방안

- 핵심 요약 : **오버엔지니어링·호환성·벤더 종속**을 TCO 평가·PoC·개방형 아키텍처로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 오버엔지니어링 | 소규모 데이터에 분산 프레임워크 도입 | TCO 평가, DuckDB/Polars 우선 검토 | 인프라 비용 |
| 호환성 결여 | 보안·거버넌스 연동 간과 | PoC에 보안·BI 연계 필수 배점 | 배포 성공률 |
| 벤더 종속 | CSP 고유 서비스 과의존 | 표준 API(Arrow/Parquet/SQL), 추상화 | 이식성 |

## Ⅵ. 기술사적 제언

- 핵심 요약 : **실제 워크로드 PoC·Decoupled 아키텍처**로 안정적 선정.
- 실제 데이터 Top-5 쿼리 + 피크 데이터셋으로 스트레스 테스트.
- 스토리지-컴퓨팅 분리 : Parquet/Iceberg + 교체 가능 엔진.

## Ⅶ. 결론

- 핵심 요약 : 빅데이터 도구 선정은 **워크로드 적합성·TCO·개방성**이 핵심.
- 답안에는 5대 원칙, 워크로드 매핑, 한계·대응, PoC를 연결.
