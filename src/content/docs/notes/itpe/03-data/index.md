## 8과목 전체 로드맵과 현재 위치

```text
                         [IT 가치·성과]
                               ▲
                               │
 [01 IT경영전략] ─────▶ [02 SW공학·프로젝트] ─────▶ [08 법·정책]
         │                       │                         ▲
         │                       ▼                         │
         ├────────────▶ [03 데이터 ◀ 현재 과목] ──────────┤
         │                  │                             │
         │                  ├────▶ [07 AI·디지털서비스] ──┤
         │                  │                             │
         └────▶ [04 컴퓨터시스템] ─▶ [05 네트워크] ─▶ [06 보안]
```

- 전체 흐름: 전략이 사업과 시스템을 정하고, 데이터·컴퓨터시스템·네트워크가 서비스를 구현하며, 보안과 법·정책이 전 영역을 통제
- 현재 위치: **03 데이터**는 시스템이 생성한 사실을 신뢰 가능한 자산으로 관리하고 AI·의사결정에 공급하는 연결축
- 연계 과목: SW 설계의 데이터 모델, 시스템의 저장·처리 구조, 보안의 개인정보·접근통제, AI의 학습·평가 데이터로 확장

## 03 데이터 과목 확대 지도

```text
                         [데이터 가치 창출]
                                ▲
                                │ 의사결정·서비스·AI
┌─────────────── 데이터 생명주기 ───────────────┐
│                                                │
│ [① 설계] → [② 저장·처리] → [③ 운영·보호] → [④ 활용] │
│ 모델링      RDBMS·NoSQL      트랜잭션·튜닝      DW·BI  │
│ 정규화      분산DB·Vector DB HA·복제·보안       Mining │
│ 무결성      Index·자료구조    이관·관측가능성     AI·통계 │
│                                                │
└──────────────────────────────────────────────┘
           ▲                     ▲
           │ 기준·책임           │ 신뢰 확보
     [데이터 거버넌스] ── 표준화·MDM·품질관리 ──┘
```

선의 의미: 데이터는 설계에서 활용으로 이동하고, 거버넌스는 전 생명주기에 기준·책임·품질을 공급함

### 30초 인출

```text
설계  → 모델링·정규화·무결성
저장  → RDBMS·NoSQL·분산DB·자료구조·색인
운영  → 트랜잭션·동시성·튜닝·분할·복제·HA
관리  → 거버넌스·표준화·MDM·품질·이관
활용  → DW·Lake·Mining·시각화·통계·AI
```

- 본질: **정확히 설계한 데이터를 일관되게 저장·운영하고, 신뢰할 수 있는 분석과 의사결정으로 전환하는 과목**
- 답안 흐름: `데이터 발생 → 모델링 → 저장·처리 → 통제·품질 → 분석·활용`
- 기본 논리: `정합성 ↔ 가용성`, `정규화 ↔ 성능`, `정확성 ↔ 적시성`의 균형을 근거로 선택
- 학습단계: `A·기초(필독) → B·핵심(누적) → C·전체(완성)`의 확장 순서로 운영

### 학습단계와 누적 회독

| 단계 | 누적 규모 | 의미 | 현재 적용 |
|---|---:|---|---|
| **A·기초** | 약 670개 | 시험장에 반드시 가져갈 필독 기반 | 1회독: A 표시 |
| **B·핵심** | 약 1,200개 | 빈출·확장·교차 연결을 보강 | 2회독: A+B 표시 |
| **C·전체** | 약 2,400개 | 심화·파생까지 포함한 전체 체계 | 3회독: A+B+C 표시 |

- 약 2,400개 전체 키워드를 삭제·축약하지 않고 보존하며, 화면 필터로 회독 범위를 누적 확장
- 회독 필터는 배타적 분류가 아니라 `1회독 A ⊂ 2회독 A+B ⊂ 3회독 A+B+C`의 포함 관계로 동작
- 이 `A/B/C 학습단계`는 기존 토픽 우선순위 산정의 A/B/C 등급과 의미가 다르므로 문서·배지에서 혼용하지 않음
- 개별 노트 배지는 단계 매핑이 확정될 때까지 `기출·중요도` 등 검증된 정보만 표기

## 영역별 로드맵

| 영역 | 반드시 그릴 큰 그림 | 우선 학습 토픽 | 답안의 판단축 |
|---|---|---|---|
| **데이터 설계** | 개념→논리→물리 모델과 정규화 흐름 | 데이터 모델링, ERD, 정규화, 무결성 | 중복 최소화 vs 조회 성능 |
| **저장·처리** | RDBMS와 분산 저장소의 배치 | NoSQL, 분산 DB, CAP·PACELC, Vector DB | 일관성·가용성·지연시간 |
| **접근 구조** | 검색키→색인→데이터 페이지 | B/B+ Tree, Hash, 다차원 색인, HNSW·IVF | 탐색 성능 vs 갱신 비용 |
| **트랜잭션·운영** | Transaction→Lock/MVCC→Recovery | ACID, 동시성 제어, 격리 수준, 튜닝 | 정합성 vs 동시 처리량 |
| **분산·가용성** | Partition→Shard→Replica→Failover | 분할, 샤딩, 복제, HA | 확장성 vs 운영 복잡성 |
| **기업 데이터 관리** | 정책→표준→품질→MDM→활용 | 거버넌스, 표준화, 품질관리, MDM | 통제 수준 vs 활용 민첩성 |
| **분석 플랫폼** | Source→Ingest→Store→Process→Serve | DW, Lake, Big Data, Mining | 배치·실시간, Schema-on-write/read |
| **통계·분석** | 모집단→표본→추정/검정→해석 | 표본추출, 추정, 가설검정, 회귀, 군집 | 유의성·효과크기·일반화 |

## DB·자료구조·통계 통합 구조

```text
[DB 기본]
 독립성·Transaction·무결성·동시성·회복
      │
      ├──▶ [DB 설계] 모델링 → 정규화 → 물리 설계
      ├──▶ [DB 유형] RDBMS / NoSQL / 분산·인메모리·Vector
      └──▶ [DB 응용] Index·Join·Tuning·보안·HA
                         │
                         ▼
               [기업 데이터 관리]
              표준·품질·MDM·거버넌스
                         │
                         ▼
             [분석·통계·AI 학습 데이터]
       기술통계 → 추론통계 → Mining → 시각화
```

### 자료구조의 위치

```text
선형: Array → List → Stack/Queue
비선형: Tree → B/B+Tree·Heap → Graph
접근기법: Hash ───────────────▶ DB Index·Partition
```

- 자료구조는 독립 암기 영역이 아니라 **DB 접근 경로와 알고리즘 복잡도를 설명하는 기반**으로 연결
- B+Tree는 범위 검색과 순차 접근, Hash는 등가 검색, HNSW·IVF는 근사 최근접 벡터 검색에 배치

## 우선 학습 순서

```text
1주기 기반      2주기 운영       3주기 관리       4주기 분석
모델링          Transaction      Governance       Sampling
정규화          동시성·격리      표준·품질·MDM    추정·검정
무결성          Index·Tuning     이관·관측성      회귀·군집
   └────▶ NoSQL·분산DB·CAP ────▶ Lake·Vector DB ─▶ AI 활용
```

1. `NoSQL → CAP·PACELC → 분산 DB 투명성`으로 분산 저장 판단축 확보
2. `모델링 → 정규화 → 무결성 → 반정규화`로 설계와 성능의 균형 확보
3. `트랜잭션 → 동시성 제어 → 격리 수준`으로 일관성 메커니즘 연결
4. `거버넌스 → 표준화 → 품질관리 → MDM`으로 기업 관리체계 연결
5. `표본추출 → 추정 → 가설검정 → 회귀·군집`으로 통계 답안 흐름 확보

## 시험 답안 작성 규칙

| 위치 | 필수 내용 | 금지 |
|---|---|---|
| **상단** | 큰 그림, 30초 인출, 예상문제 | 목차만 제시하고 본문 생략 |
| **본문 Ⅰ~Ⅲ** | 정의·필요성, 특징, 구조·원리 | 정의의 동어반복 |
| **본문 Ⅳ~Ⅴ** | 절차·유형·비교표와 선택 기준 | 장단점의 무근거 나열 |
| **본문 Ⅵ~Ⅶ** | 문제-원인-대책-효과, 현장 제언 | 허구 사례·출처 없는 수치 |
| **하단** | 1교시 10점 발췌, 검증 출처, 체크, 연결 토픽 | 골격만 남기고 답안 종료 |

> 원본 로드맵의 `DB 기본→설계·유형·응용→기업 Data 관리`, 자료구조, AI·통계 분류를 현재 학습체계에 통합하였다. 레거시 제품명·출제빈도 표시는 개념 분류 참고용이며, 현재 표준·공식 출처와 우선순위 목록을 기준으로 답안을 갱신한다.
