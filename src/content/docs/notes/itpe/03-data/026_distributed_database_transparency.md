## 답안 골격
```text
[분산 데이터베이스 투명성] ◀━━ 머리: Ⅶ 내 의견 (단일 뷰 투명성을 유지하되 지연시간 인지형(PACELC) 분산 쿼리 플래너 최적화)
 ┃
 ┣━ Ⅰ 개요 ───── 지리적으로 분산된 다중 노드 환경 → 물리적 분산 복잡성을 시스템이 흡수해 단일 DB 인터페이스 제공
 ┣━ Ⅱ 특징 ───── 추상화 계층 제공 · 글로벌 트랜잭션 보장 · 네트워크 독립성 · 분산 질의 최적화
 ┣━ Ⅲ 구조 ───── 5대 투명성 (위치·분할·복제·병행·장애) + 분산 DBMS 아키텍처(GDD, 분산 트랜잭션 관리자)
 ┣━ Ⅳ 흐름 ───── ① 분산 질의 입력 → ② 쿼리 분해(Decomposition) → ③ 데이터 지역화(Localization) → ④ 글로벌 최적화 및 분산 실행
 ┣━ Ⅴ 비교 ───── 분산 질의 처리 단계 (단일 DB 쿼리 파싱 vs 분산 쿼리 분해 및 네트워크 비용 기반 최적화)
 ┗━ Ⅵ 실무 ───── 크로스 노드 조인으로 네트워크 대역폭 고갈 / 분산 데드락 / 2PC 코디네이터 단일 장애점
```
- 필수 키워드: 분산 투명성 · 글로벌 데이터 딕셔너리(GDD) · 데이터 지역화 · 세미 조인(Semi-Join) · 분산 트랜잭션 · PACELC
- 기출: 139회 1교시 7번 `분산 데이터베이스의 투명성` → 5대 투명성 / 132회 1교시 13번 `분산 데이터베이스의 5가지 투명성` → 개념 및 기술요소

## 한 줄 본질
- 네트워크 분산에 따른 데이터 파편화와 다중 복제 상태 → 글로벌 카탈로그와 분산 쿼리 플래너가 물리적 위치와 동기화를 자동 대행 → 개발자 생산성과 시스템 확장성 동시 달성 / 네트워크 분할 및 지연시간 증가 한계

## 핵심 그림
```text
[분산 쿼리 처리 단계와 투명성 매핑]

 [SQL 쿼리 (단일 테이블 질의)]
           │
           ▼
  [1. 쿼리 분해 (Decomposition)]  <── [분할/위치 투명성]
  - 전역 스키마 기반 정규화
           │
           ▼
  [2. 데이터 지역화 (Localization)]<── [복제/분할 투명성]
  - GDD 참조, 각 노드별 분할 쿼리 생성
           │
           ▼
  [3. 글로벌 최적화 (Optimization)]<── [네트워크 비용 최소화]
  - 데이터 전송량 감소 (Semi-Join 기법)
           │
           ▼
  [4. 분산 실행 (Distributed Exec)]<── [병행/장애 투명성]
  - 2PC 분산 커밋 및 자동 장애 복구
```

## 핵심 용어
- 세미 조인(Semi-Join): 두 분산 노드 간에 전체 테이블을 전송하지 않고 조인 키 컬럼만 먼저 전송하여 매칭되는 행만 걸러낸 뒤 최종 전송함으로써 네트워크 비용을 줄이는 최적화 기법
- 복제 투명성(Replication Transparency): 동일한 데이터가 가용성을 위해 3개 이상의 노드에 복제되어 있더라도, 사용자는 단 하나의 사본만 존재하는 것처럼 갱신하고 읽을 수 있는 성질

## 핵심 통찰
- 분산 DB에서 가장 비싼 자원은 CPU나 디스크가 아니라 '네트워크'임 → 분산 쿼리 최적화의 제1 목표는 디스크 I/O가 아니라 노드 간 데이터 전송량(바이트 수)의 최소화
- 분할 투명성(Fragmentation Transparency)을 달성하려면 수평 분할 조건(재건성, 완전성, 무연접성)이 수학적으로 충족되어야 함 → 합집합으로 원본이 복원되지 않으면 투명성 파괴
- 완벽한 병행 투명성(ACID)은 CAP 이론상 분할 내성(P) 발생 시 가용성을 포기하게 만듦 → Spanner처럼 원자시계(GPS/Atomic Clock)를 도입하지 않는 한 일반 분산 DB는 약한 일관성을 타협할 수밖에 없음

## 딸려 나오는 하위 토픽
| 하위 토픽 | 상위 구조 속 위치 | 한 줄 |
|---|---|---|
| 분할의 3대 조건 | 분할 투명성 수학적 전제 | 완전성(모든 튜플 포함), 재건성(합/조인으로 복원 가능), 무연접성(조각 간 중복 없음) |
| 글로벌 트랜잭션 관리자(GTM) | 병행/장애 투명성 통제 모듈 | 분산 노드들에 걸쳐 분산 트랜잭션 ID를 발급하고 2PC 합의를 주관 |

## 이웃 토픽과 구분
- 분산 DB 투명성 vs 클라우드 가상화 투명성: 분산 DB 투명성 = 데이터 논리 모델과 쿼리 실행의 물리 위치 은닉 / 가상화 투명성 = 물리 하드웨어 자원(CPU, 메모리, 스토리지)의 가상 머신 은닉

## 문제·원인·대책
- 적용 상황: 글로벌 금융 클라우드의 분산 코어 뱅킹 데이터베이스 구축
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 크로스 노드 조인 쿼리로 수십 GB 데이터가 네트워크를 타고 흘러 회선 대역폭 마비 | 복제/분할 투명성 뒤에 숨겨진 단순 중첩 루프 조인 실행 | 쿼리 플래너에 세미 조인(Semi-Join) 및 블룸 필터(Bloom Filter) 적용 | 네트워크 전송량 80% 이상 절감 |
| 트랜잭션 코디네이터 노드 다운 시 모든 참가자 노드가 락을 쥔 채 블로킹 | 2PC 프로토콜의 단일 장애점(SPOF) 한계 | 3PC(Three-Phase Commit) 또는 Raft 합의 기반 리더 자동 선출 적용 | 블로킹 없는 자동 트랜잭션 정리 |

## 이렇게 출제된다

- 제132회 1교시 13번: "분산 데이터베이스의 5가지 투명성" → 요구 포인트: 위치, 분할, 복제, 병행, 장애 투명성의 개념 및 실무 구현 방안

## 내 의견
- [투명성에 대한 맹신과 분산 시스템 장애] "DBMS가 알아서 다 해주겠지"라며 로컬 DB처럼 마이크로서비스 간에 분산 뷰를 남발하다 장애 연쇄 전파 → 나라면: 투명성에만 의존하지 않고, 서비스 도메인 경계(Bounded Context)에 따라 데이터베이스를 완전히 독립시키고 비동기 이벤트(Kafka)로 최종 일관성을 달성하는 아키텍처로 투명성의 오버헤드를 근본적으로 회피
