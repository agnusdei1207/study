## 연관 키워드

- 빅데이터

## Ⅰ. 빅데이터의 개요

- 핵심 요약 : 전통적 처리 용량을 초과하는 대규모·고속·다양한 데이터를 수집·저장·분석하여 가치를 창출하는 빅데이터(Big Data)의 개념과 플랫폼 체계.
- 개념 : 기존 RDBMS(Relational Database Management System)나 단일 컴퓨팅 인프라의 처리 용량을 초과하는 대규모, 고속 생성, 다양한 형태(정형·반정형·비정형)의 데이터 집합과 이를 수집·저장·관리·분석하여 가치를 창출하는 제반 정보기술.
- 배경 및 필요성 :
  1. 센서·로그·클릭스트림으로 대표되는 데이터 폭증과 실시간 유입.
  2. 단일 서버 중심의 수직 확장(Scale-Up) 한계와 비용 증가.
  3. 비정형 데이터의 활용 가치 부각과 예측 분석 수요 확대.
- 주요 목적 : 분산 저장·병렬 처리·실시간 분석을 통한 비즈니스 가치 창출.

## Ⅱ. 빅데이터의 특징

- 핵심 요약 : 규모·속도·다양성·정확성·가치의 5V 특성과 분산 처리 기반.

1. 규모(Volume) : 테라바이트(TB)에서 페타바이트(PB), 제타바이트(ZB)로 폭증하는 데이터 양.
2. 속도(Velocity) : 센서·금융 거래·클릭스트림의 밀리초 단위 실시간 유입.
3. 다양성(Variety) : JSON(JavaScript Object Notation)·XML(Extensible Markup Language)·로그·음성·영상 등 비정형 데이터 확산.
4. 정확성(Veracity) : 노이즈·결측치·편향 속 진실된 품질 확보 요구.
5. 가치(Value) : 방대한 데이터의 처리를 통한 비즈니스 ROI(Return on Investment) 창출 목표.

## Ⅲ. 빅데이터의 구조 (흐름)

- 핵심 요약 : 배치와 속도 계층의 이원화인 람다 아키텍처와 단일 스트림 처리인 카파 아키텍처의 비교 구조.

```text
[ 빅데이터 5V 프레임워크 ]
+---------------------+---------------------+---------------------+
| 1. 규모 (Volume)    | 2. 속도 (Velocity)  | 3. 다양성 (Variety) |
| - 테라~페타바이트급 | - 실시간 스트리밍   | - 텍스트, 영상, 로그|
+---------------------+---------------------+---------------------+
| 4. 정확성 (Veracity)                      | 5. 가치 (Value)     |
| - 노이즈 정제 및 데이터 신뢰성 확보       | - 비즈니스 혁신 및 경제적 수익 창출 |
+-------------------------------------------+---------------------+
```

```text
[ 람다 아키텍처 (Lambda) - 배치 계층과 속도 계층의 이원화 ]
[모든 데이터 유입] ---> [배치 계층 (Batch Layer - Hadoop)] ---> 완벽한 정확성 집계
                 ---> [속도 계층 (Speed Layer - Storm)]  ---> 실시간 근사 집계
                                |                              |
                                +--------------+---------------+
                                               v
                                    [서빙 계층 (Serving Layer)]
                                    - 두 계층의 결과를 통합 뷰 제공
```

```text
[ 카파 아키텍처 (Kappa) - 단일 스트림 처리로 통합 ]
[모든 데이터 유입] ---> [분산 로그 스트림 (Kafka)] ---> [단일 스트림 엔진 (Flink)] ---> [서빙 DB]
(과거 데이터 재처리가 필요하면 스트림의 오프셋을 과거로 되돌려 동일 코드로 재생산)
```

## Ⅳ. 람다 아키텍처와 카파 아키텍처의 비교

- 핵심 요약 : 정확성·실시간성의 이원 분리와 단일 스트림 통합의 설계 철학 및 복잡도 대조.

| 비교 항목 | 람다 아키텍처 (Lambda Architecture) | 카파 아키텍처 (Kappa Architecture) |
| :--- | :--- | :--- |
| 설계 철학 | 정확성은 배치로, 실시간성은 스트림으로 이원 분리 | 모든 것은 스트림 데이터라는 단일화 철학 |
| 코드 중복성 | 배치용 코드와 스트림용 코드의 이중 작성·유지보수 | 단일 스트림 처리 코드베이스로 실시간과 과거 재처리 수행 |
| 시스템 복잡도 | 두 계층 결과 병합으로 매우 높음 | 아키텍처 단순화와 운영 관리 용이 |
| 과거 재처리 | 배치 계층의 재수행으로 정확한 재계산 | 스트림 오프셋 되감기로 동일 코드 재생산 |
| 적합 환경 | 정확한 배치 집계와 별도 실시간 근사가 필요한 환경 | 단일 처리 로직과 단순 운영이 우선인 환경 |

## Ⅴ. 빅데이터의 장점과 한계

- 핵심 요약 : 대규모 데이터 활용과 실시간 분석의 장점, 데이터 늪·코드 이중화·비용 폭증의 한계.

- 장점
  1. 분산 저장·병렬 처리를 통한 대규모 데이터의 확장성.
  2. 실시간 스트리밍 분석에 의한 즉각적 의사결정 지원.
  3. 비정형 데이터 활용을 통한 새로운 인사이트 도출.

- 한계점 1 : 데이터 레이크의 관리 부실에 의한 데이터 늪(Data Swamp) 전락
  - 한계점 : 메타데이터 없이 정제되지 않은 원천 데이터가 무분별하게 적재되어 유효성·계보(Lineage)·소유권 파악 불가.
  - 해결 방안 : Apache Iceberg·Delta Lake 등 오픈 테이블 포맷(Open Table Format)의 ACID(Atomicity, Consistency, Isolation, Durability) 트랜잭션과 스키마 강제(Schema Enforcement), 데이터 카탈로그(Data Catalog) 자동화.

- 한계점 2 : 람다 아키텍처의 코드 이중화와 유지보수 복잡성
  - 한계점 : 동일 비즈니스 로직을 배치 계층과 실시간 서빙 계층에 중복 구현하여 로직 불일치와 디버깅 난항 발생.
  - 해결 방안 : Kafka·Flink 기반의 카파 아키텍처 단일화 또는 Apache Spark Structured Streaming의 단일 엔진 통합.

- 한계점 3 : 클라우드 자원 비효율에 의한 플랫폼 비용(TCO, Total Cost of Ownership) 폭증
  - 한계점 : 무제한 스케일아웃에 따른 유휴 클러스터 방치와 비효율적 분산 셔플(Shuffle)·파티셔닝 전략 부재로 비용 통제 불능.
  - 해결 방안 : 컴퓨팅-스토리지 분리(Disaggregated Architecture)·스팟 인스턴스 활용 오토스케일링·FinOps 관제 도구의 쿼리별 비용 추적.

## Ⅵ. 빅데이터에 대한 기술사적 제언

- 핵심 요약 : 레이크하우스 기반 아키텍처와 데이터·보안 거버넌스 동시 내재화 체계.

- 오픈 테이블 포맷 중심의 레이크하우스(Lakehouse) 채택 : 클라우드 객체 스토리지(S3) 위 Apache Iceberg·Delta Lake 기반의 ACID 트랜잭션과 분석 성능 동시 확보.
- 데이터 거버넌스와 보안 거버넌스의 내재화 : Apache Ranger·AWS(Amazon Web Services) Lake Formation 기반 테이블·행·열 단위 접근 제어의 초기 아키텍처 반영.
- 비용 관제(FinOps)의 상시 운영 : 쿼리별 비용 추적과 컴퓨팅-스토리지 분리 구조의 지속적 관리.

## Ⅶ. 결론

- 핵심 요약 : 5V 특성의 분산 처리와 레이크하우스 아키텍처의 결합으로 빅데이터 가치 창출 체계 완성.
- 요약 : 규모·속도·다양성·정확성·가치의 특성과 람다·카파 아키텍처의 선택, 데이터 늪과 비용 문제의 대응.
- 시사점 : 오픈 테이블 포맷과 거버넌스·보안 내재화가 빅데이터 플랫폼의 신뢰성과 비용 효율을 좌우하는 핵심.
