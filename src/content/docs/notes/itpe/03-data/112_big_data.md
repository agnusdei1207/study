- 필수 키워드: 빅데이터 · 5V(Volume, Velocity, Variety, Veracity, Value) · 분산 파일 시스템(HDFS) · 분산 컴퓨팅(Spark) · 데이터 레이크 · 스키마 온 리드
- 기출: 113회 `빅데이터의 5V 특성과 빅데이터 플랫폼 아키텍처의 구성요소 및 처리 기술` → Ⅰ 정의 + Ⅱ 5V + Ⅲ 아키텍처 구성요소 + Ⅵ 거버넌스

## 한 줄 본질
- 폭증하는 로그·비정형 데이터를 단일 RDBMS의 스케일업으로 감당 불가 → 저비용 범용 노드들을 분산 클러스터로 묶어 병렬 저장·연산하고 읽을 때 스키마를 부여(Schema-on-Read) → 페타바이트급 통찰 획득 / 데이터 관리 복잡도 급증

## 핵심 용어
- 스키마 온 리드(Schema-on-Read): 데이터를 저장할 때는 스키마를 강제하지 않고 원본 그대로 적재한 뒤, 데이터를 실제로 읽어서 분석하는 시점에 해석 스키마를 적용하는 기법
- 람다 아키텍처(Lambda Architecture): 실시간 스트림 처리 레이어(Speed Layer)와 대용량 배치 처리 레이어(Batch Layer)를 병렬로 운영하여 실시간성과 정확성을 동시에 만족시키는 아키텍처

## 핵심 통찰
- 빅데이터의 진정한 가치는 '크기(Volume)'가 아니라 '속도(Velocity)'와 '다양성(Variety)'에 있음 → 정형 데이터만 수 테라바이트 쌓아두는 것은 그냥 거대한 RDBMS일 뿐이며, 텍스트·로그·영상 등 비정형 데이터를 실시간 스트리밍으로 결합할 때 비로소 가치 창출
- 데이터 레이크에 카탈로그와 품질 관리(데이터 거버넌스)가 빠지면, 아무도 무슨 데이터가 있는지 모르는 '데이터 늪(Data Swamp)'으로 변질되어 인프라 비용만 낭비됨
- 최근 트렌드는 Hadoop 생태계의 복잡성을 벗어나, 클라우드 객체 스토리지(S3) 위에 Delta Lake/Iceberg 같은 오픈 테이블 포맷을 올린 '레이크하우스(Lakehouse)'로 단일화

## 이웃 토픽과 구분
- 빅데이터 플랫폼 vs 데이터웨어하우스(DW): 빅데이터 = 원천 비정형/반정형 데이터를 스키마 없이 날것(Raw)으로 보관하여 유연한 탐색 분석 수행 / DW = 정형 데이터를 사전에 정제·정규화(Schema-on-Write)하여 정형 경영 리포트(BI) 제공
