## 연관 키워드

- 함수적 종속성(FD), 결정자, 종속자
- 완전 함수 종속(FFD), 부분 함수 종속(PFD), 이행 함수 종속(TFD)
- Armstrong 공리, 폐포(Closure), 후보키, 정규화

## Ⅰ. 함수적 종속성의 개요

- 핵심 요약 : 한 속성 집합의 값이 다른 속성의 값을 유일하게 결정하는 관계를 기술해 정규화의 이론적 토대를 제공.
- 개념 : 릴레이션에서 속성 집합 X의 값이 같은 두 튜플은 Y의 값도 반드시 같을 때, Y는 X에 종속된다고 하며 X→Y로 표기하는 **함수적 종속성**(Functional Dependency, FD).
- 배경 및 필요성 : 한 릴레이션에 서로 다른 종속 관계가 섞이면 삽입, 갱신, 삭제 시 **이상 현상**(Anomaly, 데이터 모순이나 누락을 일으키는 설계 결함)이 발생하므로, 종속 관계를 기준으로 테이블을 분해해야 함.
- 주요 목적 : 종속 관계로 후보키를 도출하고 정규형 판정의 기준을 제공해 이상 현상을 제거.

## Ⅱ. 함수적 종속성의 특징 및 장점

- 핵심 요약 : 종속의 완전성 정도와 추론 공리로 정규형 판정과 후보키 도출을 체계화.

1. **완전 함수 종속**(FFD, Full Functional Dependency) : 결정자가 복합키 전체에 종속 → 2NF 조건을 충족하는지 판정하는 기준.
2. **부분 함수 종속**(PFD, Partial Functional Dependency) : 복합키의 일부에만 종속 → 2NF 위반으로 보고 테이블을 분리.
3. **이행 함수 종속**(TFD, Transitive Functional Dependency) : X→Y, Y→Z로 X가 Z를 간접 결정 → 3NF 위반으로 보고 테이블을 분리.
4. **Armstrong 공리**(Armstrong's Axioms) : 종속 집합에서 새로운 종속을 도출하는 6대 추론 규칙 → 종속 관계를 빠짐없이 계산.
5. **폐포**(Closure) : 속성 집합 X가 함수적으로 결정하는 모든 속성의 집합(X+) → 후보키 판정의 근거.

## Ⅲ. 종속 유형과 공리의 흐름

- 핵심 요약 : 종속을 완전, 부분, 이행의 3유형으로 나누어 정규형과 연결하고, Armstrong 공리로 전체 종속 집합을 확장.

```text
[ FD 3유형과 정규형 ]

완전 함수 종속 (FFD)
  판정 : 2NF 조건 충족
부분 함수 종속 (PFD)
  판정 : 2NF 위반, 테이블 분리
이행 함수 종속 (TFD)
  판정 : 3NF 위반, 테이블 분리
```

```text
[ 종속 예시 : 수강 릴레이션 ]

(학번, 과목) → 성적      FFD
(학번, 과목) → 학부      PFD (학번만으로 결정)
사번 → 부서코드 → 부서위치   TFD
```

```text
[ Armstrong 공리 (X, Y, Z는 속성 집합) ]

1. 반사 : Y⊆X이면 X→Y
2. 첨가 : X→Y이면 XZ→YZ
3. 이행 : X→Y, Y→Z이면 X→Z
4. 분해 : X→YZ이면 X→Y, X→Z
5. 결합 : X→Y, X→Z이면 X→YZ
6. 유사이행 : X→Y, WY→Z이면 WX→Z
```

## Ⅳ. 종속성 유형 비교

- 핵심 요약 : FFD, PFD, TFD는 정의와 예시, 정규형 판정 결과가 서로 대비되는 세 유형.

| 유형 | 정의 | 예시 | 정규형 판정 |
| --- | --- | --- | --- |
| FFD | 결정자가 복합키 전체에 종속 | (학번, 과목) → 성적 | 2NF 조건 충족 |
| PFD | 결정자가 복합키의 일부에 종속 | (학번, 과목) → 학부 | 2NF 위반 |
| TFD | 비키 속성을 거쳐 간접 종속 | 사번 → 부서코드 → 부서위치 | 3NF 위반 |

## Ⅴ. 함수적 종속성 분석의 한계와 방안

- 핵심 요약 : 종속 조합의 복잡도, 거짓 종속, 문서화 공백을 자동 발견 알고리즘, 교차 검증, 지속적 통합 검증으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 복잡도 | 속성이 많아지면 후보 종속 조합이 급증 | TANE, FastFDs 같은 자동 발견 알고리즘, 도메인 기준으로 대상 축소 | 발견 정확도 |
| 거짓 종속성 | 샘플 데이터의 우연한 일치로 실제 없는 종속이 발견 | 업무 규칙과 교차 검증, 대표성 있는 데이터 사용 | FD 정확도 |
| 관리 사각지대 | 종속 관계가 문서화되지 않아 설계 변경 시 이상 현상 재발 | 메타데이터 사전 관리, 지속적 통합(CI, Continuous Integration) 단계의 스키마 검증 | FD 문서화율 |

## Ⅵ. 함수적 종속성에 대한 기술사적 제언

- 핵심 요약 : 종속 관계를 설계 표준으로 명시하고, 반정규화로 생기는 새 종속을 통제하는 운영 원칙을 세우는 것이 중요.
1. 설계 단계에서 업무 규칙을 FD 집합으로 명시하고, 폐포 계산으로 후보키를 검증하는 절차를 표준화할 필요가 있다.
2. 성능을 위해 반정규화를 적용할 때는 새로 생긴 종속을 동기화 트리거와 무결성 검증으로 함께 관리할 필요가 있다.
3. 정규화 원칙과 반정규화 기준을 데이터 설계 지침으로 정리해 조직 전체가 같은 기준으로 판단하도록 할 필요가 있다.

## Ⅶ. 결론

- 핵심 요약 : 함수적 종속성은 정규화를 뒷받침하는 수학적 기준이며, 3유형과 Armstrong 공리가 설계 판단의 근거.
- 시사점 : 종속 관계를 명시적으로 기록한 설계가 이상 현상을 줄이는 기반이 됨.
