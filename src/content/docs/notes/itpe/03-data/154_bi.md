## 연관 키워드

- 비즈니스 인텔리전스 (BI, Business Intelligence)
- 데이터 민주화, 시맨틱 레이어, 셀프서비스 BI
- 임베디드 애널리틱스, 메트릭 스토어, 증강 분석

## Ⅰ. 비즈니스 인텔리전스(BI)의 개요

- 핵심 요약 : 기업 데이터를 수집·통합·분석하여 의사결정을 지원하는 **비즈니스 인텔리전스**(BI, Business Intelligence)의 기술·프로세스·시스템 총체.
- 개념 : 내부 운영 데이터와 외부 시장 데이터를 수집, 통합, 정제, 분석하여 보고서와 대시보드, 시각화 지표로 제공함으로써 경영진과 현업이 빠르고 정확하게 판단하도록 돕는 기술, 프로세스 및 시스템의 총체.
- 배경 및 필요성 : 데이터가 급증하는 환경에서 단순 적재를 넘어 인사이트 추출과 데이터 기반 의사결정 문화 정착이 필요.
- 주요 목적 : **데이터 민주화**(Data Democratization) 실현, 시각화를 통한 의사결정 속도 향상, **단일 진실 원천**(Single Source of Truth) 확보.

## Ⅱ. 비즈니스 인텔리전스(BI)의 특징 및 장점

- 핵심 요약 : IT 주도형 보고에서 현업 주도형 셀프서비스로 전환되며, 시맨틱 레이어와 인메모리 연산이 이를 뒷받침하는 구조.

1. 현업 탐색 : 현업 분석가가 IT 부서 도움 없이 데이터를 탐색하고 대시보드를 생성 → 보고서 대기 시간 단축.
2. **시맨틱 레이어**(Semantic Layer) : 비즈니스 용어로 데이터 자산을 매핑 → 기술적 복잡성을 숨겨 용어 해석 차이 감소.
3. **인메모리 연산**(In-Memory Computing) : 컬럼 기반 메모리 엔진으로 대용량 집계와 드릴다운 지원 → 탐색 응답 속도 향상.
4. **임베디드 애널리틱스**(Embedded Analytics) : BI 기능을 CRM, ERP 같은 업무 애플리케이션에 내재화 → 업무 전환 없이 인사이트 활용.
5. 거버넌스 통합 : 데이터 품질, 보안, 계보(Lineage)를 중앙에서 관리 → 분석 결과의 신뢰도 확보.

## Ⅲ. 비즈니스 인텔리전스(BI)의 구조 (흐름)

- 핵심 요약 : 요청 후 IT가 개발하던 전통 BI와, 시맨틱 레이어 위에서 현업이 직접 탐색하는 현대 셀프서비스 BI의 흐름 차이와 계층 구조.

```text
[ 전통적 BI (IT 주도형) ]

현업 요구사항 접수
   ↓
IT 부서 개발 (수개월 소요)
   ↓
고정된 정적 보고서 배포
```

```text
[ 현대 셀프서비스 BI (현업 주도형) ]

중앙 시맨틱 레이어 정의
   ↓
현업 분석가가 직접 탐색
   ↓
인터랙티브 대시보드 수 분 내 생성
```

```text
[ 모던 BI 아키텍처 계층 ]

소비 계층 : 대시보드, 리포트, 자연어 질의
   ↓
시맨틱 계층 : 용어 매핑, 지표 정의, 보안
   ↓
처리 계층 : 인메모리 연산, 쿼리 페더레이션
   ↓
저장 계층 : 클라우드 DW, 데이터 레이크하우스
```

## Ⅳ. 전통적 BI와 현대 셀프서비스 BI의 비교

- 핵심 요약 : 중앙 집중 개발에서 분산 셀프서비스로, 정적 보고서에서 인터랙티브 대시보드로 진화한 구조 차이.

| 비교 항목 | 전통적 BI | 모던 셀프서비스 BI |
| --- | --- | --- |
| 운영 주체 | 중앙 IT 개발 부서와 전담 리포팅 팀 | 비즈니스 현업 분석가 |
| 리포트 형태 | 정형 정적 보고서 | 드릴다운과 슬라이싱이 가능한 대화형 대시보드 |
| 데이터 소스 | 모델링된 온프레미스 EDW 단일 소스 | EDW, 클라우드 레이크하우스, 스프레드시트, 외부 API |
| 처리 구조 | 큐브 기반 사전 집계(MOLAP) | 인메모리 분산 연산과 쿼리 페더레이션 |
| 배포 주기 | 변경 요청 후 수 주 소요 | 현업 자율 생성으로 수 분에서 수 시간 |
| 거버넌스 | IT 중앙 통제 | 연합 거버넌스(중앙 표준과 현업 자율의 결합) |

## Ⅴ. 비즈니스 인텔리전스(BI)의 한계와 방안

- 핵심 요약 : 지표 정의의 혼선, 대용량 처리 비용, 하류로 전파되는 데이터 품질 결함을 지표 표준화와 품질 테스트로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 지표 혼란 | 부서별로 같은 용어를 다르게 정의하여 의사결정 혼선 | 중앙 시맨틱 레이어와 **메트릭 스토어**(Metrics Store)에서 지표를 표준 정의 | 지표 정의 일치율 |
| 대용량 인메모리 비용 증가 | 대용량 데이터를 전부 메모리에 적재하면 인프라 비용과 지연 증가 | 라이브 연결과 추출 모드 혼용, 컬럼·파티션 프루닝, DW 푸시다운 | 인프라 비용, 질의 지연 |
| 데이터 품질 결함의 하류 전파 | 상류 파이프라인 결함이 대시보드에 그대로 반영(GIGO) | 파이프라인 내 품질 테스트 자동화(Great Expectations, Soda 등), 신선도와 완전성 모니터링 | 데이터 신선도, 완전성 |

## Ⅵ. 비즈니스 인텔리전스(BI)에 대한 기술사적 제언

- 핵심 요약 : 메트릭 스토어 중심의 지표 거버넌스를 세우고 임베디드 애널리틱스와 증강 분석으로 BI의 활용 범위를 넓히는 방향이 바람직함.
- 개별 BI 도구마다 지표를 따로 정의하면 같은 지표가 도구마다 달라지므로, dbt Semantic Layer(MetricFlow)나 Cube 같은 독립 메트릭 계층에 지표를 코드로 정의하고 버전 관리하는 방식을 검토할 필요가 있다.
- 업무 시스템 안에서 인사이트를 바로 보여주는 임베디드 애널리틱스는 BI 포털 접속을 줄여 활용률을 높이므로, CRM과 ERP 등 핵심 업무 프로세스부터 적용 대상을 식별하는 것이 바람직하다.
- 자연어 질의와 자동 인사이트, 이상 탐지 같은 증강 분석 기능은 분석 진입 장벽을 낮추지만 결과를 검증하는 절차와 함께 도입해야 오해를 줄일 수 있다.

## Ⅶ. 결론

- 핵심 요약 : BI는 시맨틱 레이어 기반 셀프서비스와 연합 거버넌스가 결합된 데이터 민주화 플랫폼.
- 차세대 BI의 성숙도는 지표 거버넌스, 임베디드 확산, 증강 분석의 세 축에서 결정된다.
