```text
  [1. 원천 계층] ──► [2. 저장·가공 계층] ──► [3. 시맨틱 계층] ──► [4. 표출·소비 계층]
  - OLTP RDBMS        - DW (스타 스키마)      - 중앙 집중 메트릭 레이어   - 임원 KPI 대시보드
  - SaaS API          - Data Lakehouse        - 단일 진실원(SSOT) 정의    - 셀프서비스 (Tableau)
  - 실시간 로그       - Data Mart             - RBAC 권한 및 캐싱        - 생성형 Text-to-BI
```

- 본질: **기업 내외부에 축적된 대규모 데이터를 수집·정제·통합하여 다차원 분석 모델로 가공한 후, 경영진과 실무진이 직관적으로 이해할 수 있는 시각화 리포트와 대시보드로 제공하여 과학적 데이터 기반 의사결정(Data-Driven Decision Making)을 지원하는 기술 및 프로세스 체계**
- 암기: `원-저-시-소` (4계층: 원천, 저장, 시맨틱, 소비) / `전-셀-증` (발전 3단계: 전통적BI, 셀프서비스BI, 증강분석BI)
- 판단축:
  - **보고서 중심 BI**: 정형 보고서와 대시보드로 지표·현황을 전달.
  - **셀프서비스 BI**: 현업 사용자가 통제된 데이터와 도구로 직접 탐색·시각화.
  - **공통 기반**: 지표 정의, 접근권한, 데이터 품질과 계보를 관리해 일관된 해석 지원.
- 주의: BI 세대 구분과 도입 효과는 보편적 시간·성능 기준이 아니며, 제품과 조직의 운영 방식에 따라 달라짐.

## 2~4교시 25점 답안

### Ⅰ. 데이터 기반 의사결정을 위한 BI(Business Intelligence) 개요

#### 한줄 요약: 방대한 비즈니스 데이터를 수집·가공·시각화하여 경험과 감이 아닌 데이터에 기반한 의사결정을 지원하는 체계

- **추진 배경**:
  - 조직에 여러 업무 데이터가 축적되며, 이를 의사결정에 활용할 일관된 분석과 전달 방식의 필요
- **정의**:
  - 조직이 더 나은 비즈니스 의사결정을 내릴 수 있도록 지원하는 데이터 수집, 데이터 웨어하우징, 다차원 분석(OLAP), 시각화 대시보드, 보고서 생성 기술 및 방법론의 총칭
- **핵심 가치**:
  - 주요 지표와 분석 결과를 이용자가 이해하고 판단에 활용할 수 있도록 지원

### Ⅲ. BI의 세대별 발전 단계

#### 한줄 요약: IT 개발 의존의 1세대에서, 현업 중심의 2세대 셀프서비스를 거쳐, AI 증강 및 시맨틱 3세대로의 진화

| 발전 단계 | 제1세대: 전통적 BI | 제2세대: 셀프서비스 BI | 제3세대: 증강 분석 & 모던 BI |
|:---|:---|:---|:---|
| **운영 주체** | IT 부서 및 전담 엔지니어 | 현업 비즈니스 분석가 | 전사 구성원 (데이터 민주화) + AI 에이전트 |
| **핵심 도구** | Cognos, MicroStrategy, Oracle BI | Tableau, Power BI, Qlik | Looker, Apache Superset, dbt Semantic |
| **제공 방식** | 정적 월간/주간 종이·PDF 보고서 | 인터랙티브 시각화 대시보드 | 헤드리스 시맨틱 레이어, **Text-to-BI(대화형)** |
| **데이터 모델** | 스타/스노우플레이크 DW 스키마 | 데스크톱 인메모리 데이터 추출(.hyper) | 클라우드 레이크하우스 직접 푸시다운 |
| **주요 한계** | 개발 병목 (요청 후 배포까지 3주 소요) | **지표 사일로 (부서마다 다른 매출 계산)** | 시맨틱 레이어 정의 및 거버넌스 구축 비용 |

### Ⅳ. BI vs 비즈니스 분석(BA) vs 인공지능(AI/ML) 비교

#### 한줄 요약: "무슨 일이 일어났는가"의 기술적 분석(BI)에서, "왜 일어났고 무엇을 해야 하는가"의 처방적 분석(BA/AI)으로의 심화

| 비교 항목 | 비즈니스 인텔리전스 (BI) | 비즈니스 분석 (BA / Advanced Analytics) | 인공지능 / 머신러닝 (AI/ML) |
|:---|:---|:---|:---|
| **질문 관점** | **"무슨 일이 일어났는가?"** (What happened?) | **"왜 일어났으며, 무엇이 일어날 것인가?"** | **"어떻게 자율적으로 최적화할 것인가?"** |
| **분석 유형** | 기술적(Descriptive), 진단적(Diagnostic) | 예측적(Predictive), 처방적(Prescriptive) | 인지적(Cognitive), 생성적(Generative) |
| **시간 축** | 과거 및 현재 실적 데이터 | 미래 트렌드 예측 및 시나리오 시뮬레이션 | 실시간 자동 대응 및 추론 |
| **수학적 기법** | 집계, 필터, 다차원 롤업/드릴다운 | 회귀분석, 시계열 예측, 최적화 이론 | 딥러닝, 강화학습, 거대언어모델(LLM) |
| **최종 산출물** | 대시보드, 경영 KPI 리포트 | 예측 스코어, 이탈 확률, 가격 최적화 모델 | 자동화된 추천, 자연어 답변, 에이전트 행동 |

### Ⅴ. 지표 사일로(Metric Silo) 극복을 위한 시맨틱 레이어 전략

#### 한줄 요약: 대시보드 툴 내부에 박혀 있던 비즈니스 로직을 중앙 코드로 분리하여 '단일 진실원(SSOT)' 확립

```text
[지표 사일로 문제와 헤드리스 시맨틱 레이어(Metric Layer)의 해결]

  [문제: 지표 사일로 발생]
  - 마케팅팀 Tableau: 매출 = 주문금액 - 쿠폰할인 (반품 미반영)  ──► 100억 보고
  - 재무팀 Power BI  : 매출 = 입금완료금액 - 결제수수료 - 환불 ──► 85억 보고
  ==> 임원 회의에서 "도대체 우리 회사 진짜 매출이 얼마냐?" 충돌 발생!

  [해결: 헤드리스 시맨틱 레이어 표준화]
  - dbt Semantic Layer 또는 Cube.js에 "유효_매출액" 지표를 코드로 단일 정의
  - Tableau, Power BI, 사내 웹, LLM 챗봇 모두가 시맨틱 API를 호출
  ==> 모든 채널에서 1원 단위까지 100% 동일한 '단일 진실원(SSOT)' 보장!
```

1. **지표의 코드화 (Metrics-as-Code)**:
   - "월간 활성 유저(MAU)"의 기준(로그인 1회 이상, 체류 10초 이상 등)을 Git 버전 관리되는 YAML 파일로 정의.
2. **헤드리스(Headless) 아키텍처**:
   - 시맨틱 레이어가 특정 시각화 도구에 종속되지 않고 REST/GraphQL/SQL 인터페이스를 제공하여, Tableau든 파이썬이든 동일한 지표를 소비.
3. **대시보드 라이프사이클 거버넌스**:
   - 30일 이상 미조회 대시보드 자동 아카이빙 및 전사 공인 인증(Certified Dashboard) 뱃지 부여로 대시보드 난립 방지.

### Ⅵ. 차세대 트렌드: 생성형 AI 기반 대화형 BI (Text-to-BI)

#### 한줄 요약: 마우스 클릭 대시보드를 넘어, 자연어로 질문하면 즉시 차트와 요약을 생성하는 대화형 인텔리전스

- **동작 메커니즘**:
  - 사용자: *"지난달 서울 지역 20대 고객 중 이탈 위험이 가장 높은 상위 5개 상품군은?"*
  - LLM 에이전트: 시맨틱 레이어의 메타데이터를 참조하여 SQL 자동 생성 $\rightarrow$ DW 실행 $\rightarrow$ 차트 렌더링 및 핵심 요약 텍스트 브리핑.
- **성공 요건**:
  - LLM이 직접 원천 DB에 SQL을 던지면 할루시네이션(잘못된 테이블 조인) 위험이 크므로, 반드시 검증된 **시맨틱 모델(Semantic Model)** 위에서만 질의를 생성하도록 제약해야 함.

### Ⅶ. 기술사적 제언

### 학습자 통찰 메모 — 답안 밖

> **[핵심 통찰]**
> BI의 실패는 언제나 기술이 아닌 '거버넌스'에서 왔다. IT가 모든 리포트를 다 만들어주던 1세대는 속도가 느려 망했고, 현업에게 툴을 다 쥐어준 2세대는 부서마다 숫자가 달라 경영진이 데이터를 불신하며 망했다. 3세대 모던 BI의 핵심은 "지표의 정의는 IT/데이터 거버넌스 팀이 코드로 엄격히 통제하되(Semantic Layer), 지표의 탐색과 표현은 현업과 AI가 자유롭게 수행하는(Self-service & Text-to-BI) 권한의 분리"에 있다. 답안을 작성할 때 뻔한 Tableau 기능 나열을 피하고, '지표 사일로' 문제와 '헤드리스 시맨틱 레이어(Metric Layer)'를 중심축으로 풀어내야 기술사로서의 아키텍처 안목을 입증할 수 있다.

> **[나라면 이렇게 쓴다]**
> 1교시형이라면 4계층 참조 아키텍처(원천-저장-시맨틱-소비) SVG 다이어그램과 전통적 BI vs 셀프서비스 BI vs 증강 분석 3세대 비교표를 제시하겠다. 2교시형이라면 부서별 지표 불일치 시나리오(마케팅 vs 재무 매출 차이)를 실무 사례로 생생하게 제시하고, dbt Semantic Layer 기반의 Metrics-as-Code 구현 방안과 함께, LLM을 결합한 대화형 BI 도입 시 발생할 수 있는 할루시네이션을 시맨틱 가드레일로 방어하는 차세대 엔터프라이즈 BI 로드맵을 제언하겠다.

### 실전 답안용 기술사적 제언

- **판정**: 셀프서비스 BI 도입 후 부서별로 자의적인 계산식을 적용하여 전사 지표 불일치(Metric Silo)가 발생하고, 일회성 대시보드 난립으로 DW 쿼리 비용이 폭증함.
- **대응**: 지표 계산 로직을 대시보드에서 분리하여 중앙 집중식 헤드리스 시맨틱 레이어(Metrics-as-Code)를 구축하고, 전사 단일 진실원(SSOT)을 강제함.
- **검증**: 메트릭 정의 변경 시 CI/CD 파이프라인에서 데이터 테스트를 자동 수행하고, 대시보드 접근 로그를 분석하여 미사용 자산을 30일 주기로 자동 정리함.
- **효과**: 전사 경영 지표 일치율 100% 달성, 대시보드 개발 기간 3주에서 1일로 단축, DW 클라우드 스캔 비용 40% 절감.
