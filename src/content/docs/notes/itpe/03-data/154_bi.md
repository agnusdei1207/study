## 한 줄 본질
- 수억 건의 원천 트랜잭션 데이터에서 경영진이 직관적으로 이해할 수 있는 핵심 지표를 뽑아내기 어려움 → DW와 OLAP 다차원 모델로 요약하고 인터랙티브 대시보드로 시각화 → 신속한 데이터 기반 의사결정 지원 / 부서별 지표 왜곡 위험

## 핵심 용어
- 셀프서비스 BI(Self-Service BI): 현업 비즈니스 사용자가 IT 부서의 개발 지원 없이도 직접 직관적인 드래그 앤 드롭 도구를 사용하여 데이터를 탐색하고 대시보드를 생성하는 환경
- 메트릭 계층(Semantic/Metric Layer): "당월 유효 매출", "활성 유저 수" 같은 핵심 KPI 계산식을 코드로 단일 정의하여 모든 BI 도구가 동일한 계산 결과를 출력하게 돕는 중간 계층

## 핵심 통찰
- 전통적 BI는 'IT 부서의 외주 공장화'라는 병목에 갇혀 실패했음 → 현업이 리포트 하나 요청하면 IT팀이 SQL을 짜고 배포하는 데 3주가 걸려 이미 비즈니스 타이밍을 놓침
- Tableau, Power BI로 대표되는 '셀프서비스 BI'가 이를 해결했으나, 부서마다 자의적으로 지표를 계산하여 임원 보고 때 마케팅팀 매출과 재무팀 매출이 서로 다른 '지표의 바벨탑' 현상 유발
- 최근의 모던 BI 트렌드는 '중앙 집중식 시맨틱 레이어(Metric Layer)'를 두어 지표의 계산 공식은 IT가 엄격히 통제하고, 데이터의 탐색과 시각화는 현업이 자유롭게 수행하는 하이브리드 거버넌스로 수렴

## 이웃 토픽과 구분
- BI vs BA(Business Analytics): BI = "과거와 현재에 무슨 일이 일어났는가?(What happened?)"에 집중하는 기술적 분석 / BA = "앞으로 무슨 일이 일어날 것이며 어떻게 해야 하는가?(What will happen?)"에 집중하는 머신러닝 예측 및 최적화 분석

## 문제·원인·대책
- 적용 상황: 대형 유통 기업의 전사 모바일 실적 대시보드 구축
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 영업본부와 이커머스본부의 '월간 활성 고객 수(MAU)' 기준이 달라 경영진 혼선 | 각 본부 BI 대시보드마다 서로 다른 SQL 필터링 조건 작성 | 전사 공통 시맨틱 레이어(Metric Layer) 도입으로 MAU 정의 단일화 | 전사 단일 진실원(SSOT) 지표 100% 확립 |
| 대용량 데이터 조회 시 BI 대시보드 로딩에 2분 이상 소요되어 현업 외면 | 원천 데이터의 세부 트랜잭션 테이블을 직접 스캔하는 비효율 | 스타 스키마 기반 데이터 마트 구축 및 인메모리 사전 집계 큐브 적용 | 대시보드 새로고침 속도 2분에서 1초로 단축 |
