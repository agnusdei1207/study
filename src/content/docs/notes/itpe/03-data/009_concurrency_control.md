## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터베이스 → **동시성 제어(병행제어)**

## 30초 인출

- 본질: 동시성 제어는 여러 트랜잭션이 같은 데이터를 동시에 읽고 쓸 때 결과가 순차 실행과 같도록 조정해 일관성을 지키는 기법
- 메커니즘: 잠금으로 충돌하는 접근을 대기시키거나(2PL), 데이터의 여러 버전을 두어 읽기와 쓰기를 분리하거나(MVCC), 실행 후 충돌을 검사해 실패 시 재시도(OCC)
- 통찰: 잠금은 안전하지만 대기와 교착상태가 늘고 낙관적 방식은 충돌이 잦으면 재시도가 늘므로 쓰기 충돌 빈도를 기준으로 방식을 선택

<details>
<summary>핵심 용어</summary>

- **동시성 제어(Concurrency Control)** : 여러 트랜잭션의 동시 실행을 조정해 일관성을 지키는 기법
- **직렬가능성(Serializability)** : 동시 실행 결과가 어떤 직렬 실행 결과와 같은 성질
- **잠금(Lock)** : 충돌하는 접근을 제한하는 수단. 공유 잠금(읽기)과 배타 잠금(쓰기)
- **2PL(Two-Phase Locking)** : 잠금을 얻는 단계와 푸는 단계로 나누는 잠금 규칙
- **MVCC(Multi-Version Concurrency Control)** : 여러 버전을 두어 읽기가 쓰기를 막지 않게 하는 방식
- **OCC(Optimistic Concurrency Control)** : 충돌이 드물다고 보고 먼저 실행한 뒤 커밋 시 충돌을 검사하는 방식
- **교착상태(Deadlock)** : 트랜잭션들이 서로의 잠금을 기다려 진행하지 못하는 상태

</details>

## 2~4교시 25점 답안

## Ⅰ. 동시성 제어의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **동시성 제어** 는 동시 실행 트랜잭션이 순차 실행과 같은 결과를 내도록 조정하는 기법 |
| 목적 | 갱신 손실·읽기 이상 방지와 데이터 일관성 확보 |

## Ⅱ. 동시성 제어가 필요한 이유

| 문제 | 내용 |
|---|---|
| 갱신 손실 | 두 트랜잭션이 같은 값을 읽고 각각 덮어써 한쪽 결과 소실 |
| 오손 읽기 | 커밋되지 않은 값을 읽음 |
| 반복 불가능 읽기 | 같은 데이터를 다시 읽으면 값이 바뀜 |

## Ⅲ. 잠금 기반 제어

```text
T1: 잠금 획득 → 읽기·쓰기 → ····· 잠금 해제
T2:                 (같은 데이터 요청) 대기 ─→ 잠금 획득 → ...
2PL: 확장 단계(잠금만 획득) → 축소 단계(잠금만 해제)
```

## Ⅳ. 동시성 제어 방식의 비교

| 구분 | 2PL(잠금) | MVCC | OCC |
|---|---|---|---|
| 원리 | 충돌 접근을 대기 | 여러 버전 유지 | 실행 후 충돌 검사 |
| 읽기·쓰기 | 서로 대기 가능 | 읽기가 쓰기를 막지 않음 | 충돌 없으면 진행 |
| 문제 | 교착상태·대기 | 버전 저장·정리 비용 | 충돌 시 재시도 |
| 적합 조건 | 쓰기 충돌 잦음 | 읽기가 많은 환경 | 충돌이 드문 환경 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 잠금 대기와 교착상태 | 잠금 순서 통일, 대기 시간 제한, 교착 탐지 후 희생 트랜잭션 롤백 |
| 낙관적 방식의 잦은 재시도 | 충돌이 잦은 데이터는 잠금 방식 적용 |
| MVCC의 오래된 버전 누적 | 주기적 버전 정리 |

## Ⅵ. 제언

데이터별 쓰기 충돌 빈도를 확인해 충돌이 잦으면 잠금, 읽기가 많고 충돌이 드물면 MVCC나 낙관적 방식을 선택

```text
쓰기 충돌 빈도
    ├─ 높음 → 잠금(2PL)
    └─ 낮음 → MVCC · 낙관적 제어
```

| 구분 | 한 방식 일괄 적용 | 제언: 충돌 빈도별 선택 |
|---|---|---|
| 대기·재시도 | 한쪽 증가 | 균형 |
| 처리량 | 편차 | 향상 |
