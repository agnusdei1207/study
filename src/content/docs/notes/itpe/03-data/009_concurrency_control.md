## 연관 키워드

- 동시성 제어(Concurrency Control), 직렬 가능성(Serializability), 로킹(Locking), 2단계 잠금(2PL)
- 타임스탬프 순서화, 낙관적 병행 제어(OCC), 다중 버전 동시성 제어(MVCC), 교착상태(Deadlock), 격리 수준(Isolation Level)

## Ⅰ. 동시성 제어의 개요

- 핵심 요약 : 병행 실행되는 트랜잭션의 충돌 접근을 통제해 직렬 가능성과 처리량을 함께 확보하는 데이터베이스의 핵심 기능.
- 개념 : 여러 트랜잭션이 동일 데이터에 동시 접근할 때 실행 순서를 통제하여 일관성 훼손을 막는 기술인 **동시성 제어** (Concurrency Control).
- 배경 및 필요성 : 다중 사용자 환경의 병행 실행은 다음의 이상 현상을 낳는다.
  1. 갱신 분실(Lost Update) : 먼저 반영한 갱신이 뒤 갱신으로 덮여 소실.
  2. 모순성(Inconsistency) : 타 트랜잭션의 부분 갱신을 읽어 불일치 발생.
  3. 연쇄 복귀(Cascading Rollback) : 미확정 데이터를 읽은 트랜잭션의 동반 롤백.
  4. 비재현성(Unrepeatable Read) : 같은 데이터의 재조회 결과 변동.
- 주요 목적 : 병행 실행 결과를 순차 실행 결과와 동일하게 만드는 **직렬 가능성** (Serializability)의 보장.

## Ⅱ. 동시성 제어의 특징 및 장점

- 핵심 요약 : 사전 차단형(잠금·순서)과 사후 검증형(낙관·버전) 기법이 워크로드에 따라 상호 보완하는 구성.

1. **로킹** (Locking) : 접근 전 공유 락·배타 락의 획득으로 충돌 차단 → 오염 데이터의 확산 방지.
2. **2단계 잠금** (2PL, Two-Phase Locking) : 확장 단계와 축소 단계의 분리 → 잠금 순서에 따른 직렬 가능성 보장.
3. **타임스탬프 순서화** : 시작 시각 기준의 고정 순서 판정 → **교착상태** (Deadlock)의 원천 배제.
4. **낙관적 병행 제어** (OCC, Optimistic Concurrency Control) : 커밋 시점의 충돌 검증 → 충돌이 드문 읽기 위주 환경의 처리량 극대화.
5. **다중 버전 동시성 제어** (MVCC, Multi-Version Concurrency Control) : 갱신 시 새 버전 생성과 스냅샷 읽기 → 읽기와 쓰기의 상호 차단 제거.
6. **격리 수준** (Isolation Level) 조절 : 정합성 요구별 수준 선택 → 성능과 안전성의 균형 튜닝.

## Ⅲ. 동시성 제어의 구조 (흐름)

- 핵심 요약 : 로킹은 2단계 잠금의 확장·축소 구조, 낙관적 제어는 읽기→검증→기록 3단계로 동작.

```text
[ 2단계 잠금 (2PL)의 단계 구조 ]

확장 단계 (Growing)
  락 획득만 허용
        ↓
락 포인트 (Lock Point)
  락 보유 최대 시점
        ↓
축소 단계 (Shrinking)
  락 해제만 허용
```

```text
[ 낙관적 병행 제어의 3단계 ]

읽기 단계
  락 없이 작업, 변경 사본 보관
        ↓
검증 단계 (Validation)
  타 트랜잭션과의 충돌 확인
        ↓
기록 단계 (Write)
  통과 시 반영, 실패 시 재시작
```

- 락의 구분 : **공유 락** (Shared Lock)은 읽기 병행 허용, **배타 락** (Exclusive Lock)은 단독 접근 강제.
- 타임스탬프의 역할 : 시작 시각이 직렬 순서가 되며, 순서 위반 접근에는 중단 후 재시작을 부과.
- MVCC의 버전 관리 : 종료된 트랜잭션이 남긴 구버전은 주기적 청소 절차로 회수.

## Ⅳ. 동시성 제어 기법들의 비교

- 핵심 요약 : 충돌 빈도와 읽기·쓰기 비율, 교착상태 허용 여부가 기법 선택을 가름.

| 구분 | 로킹 (2PL) | 타임스탬프 순서화 | 낙관적 제어 (OCC) | 다중 버전 (MVCC) |
| --- | --- | --- | --- | --- |
| 제어 시점 | 접근 전 차단 | 접근 시 순서 판정 | 커밋 시 검증 | 버전 생성·스냅샷 읽기 |
| 직렬 순서 결정 | 락 획득 순서 | 부여된 시각 순서 | 검증 통과 순서 | 커밋 순서 |
| 교착상태 | 발생 가능 | 발생 없음 | 발생 없음 | 쓰기 충돌 시 발생 |
| 충돌 많은 환경 | 유리 | 재시작 폭주 | 불리 | 유리 |
| 읽기 위주 환경 | 락 대기 부담 | 양호 | 가장 유리 | 유리 |

- 선택 기준 :
  1. 워크로드의 충돌 빈도와 읽기·쓰기 비율 파악.
  2. 교착상태 감시·회수 비용의 허용 범위 검토.
  3. 사용 중인 DBMS(Database Management System)의 격리 수준과 기본 지원 기능 확인.

## Ⅴ. 동시성 제어의 한계와 방안

- 핵심 요약 : 교착상태·락 경합·재시작 폭주·버전 누적을 예방 정책과 회수 정책으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 교착상태 | 락 획득 순서의 교차 → 상호 대기와 처리 중단 | 획득 순서 표준화, **대기 그래프** (Wait-For Graph) 탐지 후 희생자 롤백 | 교착상태 발생 건수 |
| 락 경합 병목 | 핫스팟 데이터의 집중 접근 → 대기 증가 | 락 범위 최소화, 트랜잭션 길이 축소 | 락 대기 시간 |
| 타임스탬프 재시작 폭주 | 순서 위반의 반복 → 자원 낭비 | 충돌 집중 데이터에 잠금 기법 병행 | 재시작 횟수 |
| 버전 누적 | 장기 트랜잭션의 구버전 보유 → 저장 공간 팽창 | 실행 시간 임계치 관리, 구버전 청소 주기 튜닝 | 장기 트랜잭션 수 |

## Ⅵ. 동시성 제어에 대한 기술사적 제언

- 핵심 요약 : 격리 수준 표준, 트랜잭션 설계 규칙, 분산 잠금 도입 기준의 조직적 정립 필요.
- 표준화 : 데이터베이스 운영 조직이 업무 유형별 격리 수준 기준표를 수립해 서비스별 튜닝 원칙을 제도화.
- 설계 규칙 : 개발 가이드에 트랜잭션 경계 정의와 비동기 처리 원칙을 코딩 표준으로 명시.
- 확장 대응 : 분산 환경의 단일 노드 잠금 한계를 인지하고, 분산 잠금 체계의 도입 기준을 아키텍처 심의 절차에 반영.

## Ⅶ. 결론

- 핵심 요약 : 동시성 제어는 직렬 가능성 보장과 처리량 확보 사이의 균형 설계 기술.
- 워크로드 진단에 따른 기법과 격리 수준의 선택이 데이터 무결성과 서비스 성능을 함께 좌우함.
