## 연관 키워드
- 동시성 제어, 직렬가능성, 잠금, 타임스탬프, MVCC, 교착상태

### Ⅰ. 동시성 제어의 개요

- 핵심 요약 : 동시성 제어는 여러 트랜잭션이 동시에 실행되어도 격리성과 데이터 일관성을 만족하도록 연산 순서를 조정하는 DBMS 기능.
-概念 : 여러 트랜잭션이 동시에 실행되어도 격리성과 데이터 일관성을 만족하도록 연산 순서를 조정하는 DBMS 기능(**동시성 제어**, Concurrency Control).
- 배경 및 필요성 : 동시 접근에서 갱신 손실·더티 읽기 등 이상 현상과 데이터 경합이 발생.
- 주요 목적 : 정확성을 유지하면서 동시 처리량을 확보.

### Ⅱ. 동시성 제어의 특징 및 장점

- 핵심 요약 : 잠금 기반·타임스탬프·검증·MVCC는 충돌 연산을 통제하고 읽기와 쓰기를 분리하는 동시성 제어 방식.

1. 잠금 기반 : 공유·배타 잠금으로 충돌 연산 통제 → 직렬화 가능한 실행 지원.
2. 타임스탬프·검증 : 순서 또는 커밋 시 충돌 판정 → 잠금 대기 감소 가능.
3. MVCC : 버전 스냅샷으로 읽기와 쓰기 분리 → 읽기 경합 완화.

### Ⅲ. 동시성 제어의 구조 (흐름)

- 핵심 요약 : 트랜잭션 연산 요청 → 충돌·격리 규칙 확인 → 잠금/버전/검증 적용 → 커밋 또는 롤백 → 대기·충돌 해소.

```text
트랜잭션 연산 요청
  ↓
충돌·격리 규칙 확인
  ↓
잠금/버전/검증 적용
  ↓
커밋 또는 롤백
  ↓
대기·충돌 해소
```

```text
T1 read(x) ── 스냅샷 v1
T2 write(x) ─ 새 버전 v2 → commit
T1 read(x) ─ 격리수준에 따라 v1/v2 관찰
```

### Ⅳ. 2단계 잠금(2PL)과 MVCC 비교

- 핵심 요약 : 주요 위험 기준 — 2단계 잠금(2PL): 교착상태·대기·잠금 경합; MVCC: 버전 저장공간·오래된 스냅샷 정리 부담.

| 비교 축 | 2단계 잠금(2PL) | MVCC |
|---|---|---|
| 읽기 동작 | 잠금 해제 전 읽기·쓰기 대기 가능 | 스냅샷 버전 읽기로 읽기-쓰기 경합 완화 |
| 주요 위험 | 교착상태·대기·잠금 경합 | 버전 저장공간·오래된 스냅샷 정리 부담 |

### Ⅴ. 동시성 제어의 한계와 방안

- 핵심 요약 : 교착상태·장기 트랜잭션 등 실제 위험을 원인에 맞는 통제와 지표로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 교착상태 | 순환 대기 발생으로 트랜잭션 중단 | 잠금 순서 일관화·탐지 후 피해 트랜잭션 재시도 | 교착률 |
| 장기 트랜잭션 | 잠금 점유·MVCC 정리 지연으로 처리량 저하 | 짧은 트랜잭션·타임아웃·배치 분할 | 잠금 대기·버전 적체 |
| 격리수준 오해 | DB별 구현 차이로 기대한 이상 방지 실패 | 격리수준별 읽기/쓰기 현상과 벤더 동작 시험 | 재시도·정합성 오류율 |

### Ⅵ. 동시성 제어에 대한 제언

- 핵심 요약 : DB 설계자는 업무 불변조건과 허용 가능한 읽기 이상을 정의한 뒤 격리수준·인덱스·트랜잭션 크기를 부하시험으로 조정.

- 실행 제안 : DBA는 교착·직렬화 실패·잠금 대기 로그를 수집하고 업무별 멱등 재시도·격리수준 기준을 명문화.

### Ⅶ. 결론

- 핵심 요약 : 동시성 제어는 동시 실행을 단순 차단하는 것이 아니라 정확성·처리량·대기비용 사이의 보장 수준을 정하는 설계.
- 시사점 : 동시성 보장은 격리수준뿐 아니라 트랜잭션 설계·제약조건·재시도 정책을 함께 다뤄야 함.
