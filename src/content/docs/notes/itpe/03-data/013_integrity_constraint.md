## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터베이스 → **무결성 제약(데이터 무결성)**

## 30초 인출

- 본질: 무결성 제약은 데이터베이스에 저장되는 데이터가 항상 지켜야 할 규칙을 정해 잘못된 값과 관계가 저장되지 않도록 하는 조건
- 메커니즘: 개체 무결성(기본키 유일·NOT NULL), 참조 무결성(외래키), 도메인 무결성(형식·범위) 규칙을 데이터베이스가 삽입·수정·삭제 때마다 검사해 위반 시 거부
- 통찰: 응용 프로그램에서만 검사하면 다른 경로의 입력이 규칙을 우회하므로 데이터베이스 제약으로 정의하고 삭제·수정 시 자식 행의 처리 규칙을 명시

<details>
<summary>핵심 용어</summary>

- **무결성 제약(Integrity Constraint)** : 데이터 값과 관계가 지켜야 할 규칙
- **개체 무결성** : 기본키가 각 행을 유일하게 식별하며 NULL일 수 없는 규칙
- **참조 무결성** : 외래키가 존재하는 부모 행을 참조하거나 NULL인 규칙
- **도메인 무결성** : 컬럼 값이 정해진 형식·범위·허용값을 따르는 규칙
- **기본키(PRIMARY KEY)** : 행을 유일하게 식별하는 키
- **외래키(FOREIGN KEY)** : 다른 테이블의 키를 참조하는 컬럼
- **CHECK 제약** : 값이 조건을 만족하도록 검사하는 제약
- **ON DELETE CASCADE** : 부모 행 삭제 시 참조하는 자식 행도 삭제하는 규칙

</details>

## 2~4교시 25점 답안

## Ⅰ. 무결성 제약의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **무결성 제약** 은 데이터베이스의 데이터가 지켜야 할 규칙을 정해 잘못된 저장을 막는 조건 |
| 목적 | 데이터의 정확성과 일관성 유지 |

## Ⅱ. 특징

| 특징 | 의미 |
|---|---|
| 자동 검사 | 삽입·수정·삭제 때 데이터베이스가 검사 |
| 위반 시 거부 | 규칙에 어긋나면 변경 취소 |
| 경로 독립 | 어떤 응용에서 입력해도 적용 |

## Ⅲ. 유형과 사례

```text
        부모 테이블 부서(부서번호 PK)
                    ↑ 외래키 참조
        자식 테이블 사원(사원번호 PK, 부서번호 FK)

개체 무결성: 사원번호는 유일하고 NULL 불가
참조 무결성: 사원의 부서번호는 부서 테이블에 있는 값
도메인 무결성: 급여는 0 이상
```

## Ⅳ. 유형별 구현과 참조 무결성 옵션

### 유형별 구현

| 유형 | 규칙 | 구현 |
|---|---|---|
| 개체 무결성 | 기본키 유일·NOT NULL | PRIMARY KEY |
| 참조 무결성 | 외래키가 부모 값 참조 | FOREIGN KEY |
| 도메인 무결성 | 값의 형식·범위 | 데이터 타입, CHECK, NOT NULL |
| 고유 무결성 | 후보키 유일 | UNIQUE |

### 부모 행 삭제·수정 시 처리 옵션

| 옵션 | 동작 |
|---|---|
| RESTRICT(NO ACTION) | 자식이 있으면 삭제·수정 거부 |
| CASCADE | 자식 행도 함께 삭제·수정 |
| SET NULL | 자식의 외래키를 NULL로 변경 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 응용에서만 검사해 다른 경로에서 위반 | 데이터베이스 제약으로 정의 |
| CASCADE로 의도하지 않은 대량 삭제 | 업무에 맞는 옵션 선택과 삭제 전 영향 확인 |
| 대량 적재 시 제약 검사로 지연 | 적재 후 검증 등 절차 정의 |

## Ⅵ. 제언

핵심 규칙은 데이터베이스 제약으로 정의하고 부모 행 삭제·수정 때의 자식 처리 규칙을 업무에 맞게 명시

```text
규칙 식별 → 제약으로 정의(PK·FK·CHECK) → 삭제·수정 옵션 결정 → 위반 시험
```

| 구분 | 응용 코드 검사 | 제언: 데이터베이스 제약 |
|---|---|---|
| 우회 가능성 | 있음 | 없음 |
| 관리 위치 | 여러 응용 | 한 곳 |
