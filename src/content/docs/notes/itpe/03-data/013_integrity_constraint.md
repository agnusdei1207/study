## 연관 키워드

- 무결성 제약, 도메인, 개체 무결성, 참조 무결성, UNIQUE, CHECK

## Ⅰ. 무결성 제약의 개요

- 핵심 요약 : 무결성 제약은 데이터베이스가 허용되는 값과 관계만 저장하도록 강제하는 선언적 규칙.
- 개념 : 무결성 제약은 데이터베이스가 허용되는 값과 관계만 저장하도록 강제하는 선언적 규칙.
- 배경 및 필요성 : 애플리케이션의 검증 누락·동시 갱신으로 잘못된 값과 고아 참조가 저장될 수 있음.
- 주요 목적 : 데이터 정확성과 관계 일관성을 저장 시점에 보장.

## Ⅱ. 무결성 제약의 특징 및 장점

- 핵심 요약 : 도메인 제약: 자료형·범위·CHECK로 유효값 제한 → 잘못된 입력 차단; 개체 무결성: 기본키 NOT NULL·유일성 → 행 식별 보장; 참조 무결성: 외래키 참조 존재 강제 → 고아 레코드 방지.

1. 도메인 제약: 자료형·범위·CHECK로 유효값 제한 → 잘못된 입력 차단
2. 개체 무결성: 기본키 NOT NULL·유일성 → 행 식별 보장
3. 참조 무결성: 외래키 참조 존재 강제 → 고아 레코드 방지

## Ⅲ. 무결성 제약의 구조 (흐름)

- 핵심 요약 : 업무 규칙 식별 → 제약 유형·위반 동작 결정 → DDL 정의 → 트랜잭션·적재에서 검사 → 위반 모니터링.

```text
업무 규칙 식별
  ↓
제약 유형·위반 동작 결정
  ↓
DDL 정의
  ↓
트랜잭션·적재에서 검사
  ↓
위반 모니터링
```

- 핵심 구성 : INSERT/UPDATE/DELETE

```text
INSERT/UPDATE/DELETE
      ↓
NOT NULL·CHECK·UNIQUE·FK 검사
      ├ 만족 → 커밋
      └ 위반 → 거부·롤백·정책 처리
```

## Ⅳ. 비교: DB 제약조건 / 애플리케이션 검증

- 핵심 요약 : 동시성·우회 기준 — DB 제약조건: 경합에도 원자적 제약 보장; 애플리케이션 검증: 다중 서비스·배치에서 우회 가능.

| 비교 기준 | DB 제약조건 | 애플리케이션 검증 |
| --- | --- | --- |
| 집행 위치 | DBMS가 모든 쓰기 경로에서 검사 | 호출 경로별 코드에서 검사 |
| 동시성·우회 | 경합에도 원자적 제약 보장 | 다중 서비스·배치에서 우회 가능 |

## Ⅴ. 무결성 제약의 한계와 방안

- 핵심 요약 : 제약 없는 우회경로·업무규칙 위치 불명 등 실제 위험을 원인에 맞는 통제와 지표로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 제약 없는 우회경로 | 배치·ETL·관리자 작업이 규칙을 건너뜀 | 모든 쓰기 계정·적재경로와 권한 통제 | 우회 쓰기 건수 |
| 업무규칙 위치 불명 | DB와 앱 검증 규칙이 중복·불일치 | DB 불변조건과 애플리케이션 흐름의 책임 분리 | 규칙 불일치 |
| 대량 적재 성능 | 제약 검사·인덱스 비용 증가 | 검증 가능한 배치·적재 순서·실행계획 설계 | 적재시간·위반률 |

## Ⅵ. 무결성 제약의 제언

- 핵심 요약 : DBA와 업무 데이터 소유자는 불변조건은 가능한 한 DB 제약으로 강제하되 오류메시지·업무처리 흐름과 함께 설계.
- 실행 제안 : DBA는 참조·도메인 불변조건을 DDL에 선언하고 ETL·관리자 계정의 제약 우회 경로를 감사.

## Ⅶ. 무결성 제약의 결론

- 핵심 요약 : 무결성 제약은 데이터 품질을 사후 정제에 맡기지 않고 저장 경계에서 규칙 위반을 차단하는 통제.
- 시사점 : 데이터 정확성은 입력 화면 검증만으로 보장되지 않으며 모든 쓰기 경로의 제약 집행이 중요.
