## 답안 골격
```text
[CRUD 매트릭스] ◀━━ 머리: Ⅶ 내 의견 (CI 파이프라인에서 DDL/ORM과 비즈니스 로직 매핑 검증 도구로 자동화)
 ┃
 ┣━ Ⅰ 개요 ───── 업무 프로세스와 데이터 엔티티 간 상호 연관 관계(Create, Read, Update, Delete)를 2차원 표로 검증하는 분석 도구
 ┣━ Ⅱ 특징 ───── 업무/데이터 정합성 검증 · 모델링 누락 식별 · 트랜잭션 빈도 분석 · 프로세스 정의 완전성 확인
 ┣━ Ⅲ 구조 ───── 행(업무 프로세스) / 열(엔티티 타입) / 교차점(CRUD 작업 유형) / 트랜잭션 참조 무결성
 ┣━ Ⅳ 흐름 ───── ① 프로세스 목록 도출 → ② 엔티티 타입 목록 도출 → ③ 매트릭스 셀 채우기(C/R/U/D) → ④ 무결성 및 누락 검증(전수 C/R 확인)
 ┣━ Ⅴ 비교 ───── CRUD 매트릭스 vs 데이터 흐름도(DFD) (정적 연관성/행렬 검증 vs 동적 흐름/입출력 가시화)
 ┗━ Ⅵ 실무 ───── C 누락 엔티티(미생성 고아) / C 다중 프로세스(중복 생성 경합) / R 누락 프로세스(더미 엔티티)
```
- 필수 키워드: 업무 프로세스 · 엔티티 타입 · CRUD(Create/Read/Update/Delete) · 2차원 행렬 · 정합성 검증 · 단일 C 규칙
- 배점 전략: 10점 = Ⅰ → Ⅲ 매트릭스 도식 및 4대 검증 규칙 → Ⅵ 검증 실패 사례 / 25점 = Ⅰ~Ⅶ, Ⅳ 작성 4단계 및 Ⅵ 아키텍처 연계(서비스 분할 기준)
- 기출: 133회 1교시 `데이터모델링에서 CRUD 매트릭스를 사용하는 목적과 이를 표현하는 방법` → Ⅰ 목적 + Ⅲ 표현 형식(행/열/교차점) + 검증 규칙

## 한 줄 본질
- 프로세스와 데이터의 개별 설계로 인한 누락·불일치 병목 → 프로세스와 엔티티를 2차원 표에 매핑해 C/R/U/D 행위 전수 검사 → 모델링 정합성 및 누락 발견 / 업무 규모 확대 시 수동 작성 비용 급증

## 핵심 그림
```text
[CRUD 매트릭스 구성 및 검증 원칙]

            엔티티     [고객]    [주문]    [결제]    [배송]    검증 기준
프로세스
────────────────────────────────────────────────────────────────────
 1. 회원가입            C         -         -         -     (고객 생성)
 2. 주문신청            R         C         -         -     (주문 생성)
 3. 결제처리            R         U         C         -     (결제 생성)
 4. 배송지시            R         R         R         C     (배송 생성)
────────────────────────────────────────────────────────────────────
 검증(열 기준)        C,R       C,R,U     C,R       C     * 모든 엔티티는 최소
                                                           하나의 C와 R 필수!
 [핵심 검증 3원칙]
 1. 모든 엔티티는 반드시 최소 1개의 'C'와 1개의 'R'을 가져야 함 (미생성/미사용 방지)
 2. 엔티티 생성(C)은 가급적 1개의 프로세스만 담당 (중복 생성 및 정합성 충돌 방지)
 3. 모든 프로세스는 최소 1개 이상의 엔티티에 접근해야 함 (더미 프로세스 방지)
```

## 핵심 용어
- 단일 생성자 원칙(Single Creator Principle): 데이터 무결성 보장을 위해 특정 엔티티의 C(Create) 권한은 단 하나의 책임 프로세스에만 할당하는 규칙
- 고아 엔티티(Orphan Entity): 매트릭스 상에 C(Create)가 존재하지 않아 실제 운영에서 데이터가 인입되지 못하는 모델링 결함

## 핵심 통찰
- CRUD 매트릭스는 단순 정리 표가 아니라 '소프트웨어 아키텍처의 서비스 경계(Bounded Context) 분할 기준'임 → C와 U가 밀집된 프로세스와 엔티티를 묶으면 응집도 높은 마이크로서비스가 됨
- 매트릭스에서 U(Update)와 D(Delete)가 지나치게 많은 엔티티는 상태 전이(State Machine)가 복잡하다는 신호임 → 동시성 락 경합의 병목 지점으로 사전 식별 가능
- 프로젝트 후반 통합 테스트 단계에서 발견되는 "데이터 미생성 오류"의 90%는 분석 단계 CRUD 매트릭스 검증 누락에서 기인함

## 이웃 토픽과 구분
- CRUD 매트릭스 vs DFD: CRUD 매트릭스 = 어떤 프로세스가 어떤 데이터를 만드는지 정적 생성·사용 관계 검증 / DFD(Data Flow Diagram) = 프로세스 간 데이터가 어떤 순서와 흐름으로 이동하는지 동적 파이프라인 가시화

## 문제·원인·대책
- 적용 상황: 대규모 공공 차세대 차세대 ERP 구축 분석·설계 단계
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 특정 통계 테이블의 조회가 항상 빈 값으로 반환 | 데이터 모델링 단계에서 엔티티만 정의하고 C(생성) 프로세스 누락 | CRUD 매트릭스 열 검증(C 존재 여부) 전수 감사 수행 | 미생성 엔티티 전수 식별 및 배치 집계 프로세스 추가 |
| 주문 테이블에 대해 온라인 주문과 POS 주문이 서로 다른 로직으로 동시 Insert | C(생성) 권한이 복수 프로세스에 분산되어 비즈니스 규칙 파편화 | 단일 주문 접수 API로 통합하고 C 프로세스를 단일화 | 데이터 중복 인입 방지 및 일관된 검증 규칙 적용 |
