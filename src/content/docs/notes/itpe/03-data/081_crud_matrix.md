## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터 모델링 → **CRUD 매트릭스**

## 30초 인출

- 본질: CRUD 매트릭스는 업무 프로세스와 데이터 엔티티가 만나는 칸에 생성(C)·조회(R)·수정(U)·삭제(D)를 표시한 교차표
- 메커니즘: 프로세스를 행, 엔티티를 열에 두고 각 칸에 수행하는 조작을 채운 뒤, 빈 행·열과 조작의 편중을 살펴 요구사항·데이터 모델의 누락과 불일치를 찾음
- 통찰: 빈 칸이나 C·R 부재가 항상 결함은 아니고 표는 순서·조건·권한을 나타내지 못하므로, 예외 근거를 기록하고 DFD·시퀀스·업무 규칙과 함께 확인

<details>
<summary>핵심 용어</summary>

- **CRUD** : Create(생성)·Read(조회)·Update(수정)·Delete(삭제)
- **CRUD 매트릭스** : 프로세스 × 엔티티 교차표에 CRUD를 표기한 분석 도구
- **프로세스** : 분석 범위의 업무 기능
- **엔티티** : 관리 대상 데이터
- **DFD** : 데이터 흐름과 변환을 나타내는 다이어그램
- **데이터 모델** : 엔티티·속성·관계로 구성한 데이터 구조 모델

</details>

## 2~4교시 25점 답안

## Ⅰ. CRUD 매트릭스의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **CRUD 매트릭스** 는 업무 프로세스와 데이터 엔티티의 조작 관계를 행·열 교차표로 나타낸 분석 도구 |
| 목적 | 기능 요구와 데이터 모델 사이의 누락·불일치 조기 발견 |

## Ⅱ. 특징

| 특징 | 표현 | 읽는 방향 |
|---|---|---|
| 두 축의 교차 | 프로세스 × 엔티티 | 행은 기능의 데이터 사용, 열은 데이터의 생성·변경 책임 |
| 조작 표시 | C·R·U·D | 셀에서 실제 행위 확인 |
| 공백 발견 | 빈 행·열·셀 | 누락 가능성 확인 후 예외 근거 검토 |

## Ⅲ. 표현 방법과 작성 절차

| 프로세스 \ 엔티티 | 고객 | 주문 | 결제 |
|---|---|---|---|
| 회원 등록 | C | — | — |
| 주문 접수 | R | C | — |
| 결제 처리 | R | U | C |

| 단계 | 작성 내용 | 확인 관점 |
|---|---|---|
| 1. 프로세스 도출 | 업무 기능을 적절한 단위로 분해 | 세분화 수준의 일관성 |
| 2. 엔티티 도출 | 데이터 모델의 주요 엔티티 정리 | 정의·명칭의 모델과 일치 |
| 3. 행위 매핑 | 각 칸에 C/R/U/D 기입 | 요구사항·화면·인터페이스 근거 |
| 4. 교차 검토 | 공백·편중·중복 책임 검토 | 실제 예외와 미모델링 기능 |

## Ⅳ. 패턴별 분석

| 관찰 패턴 | 확인할 원인 | 후속 조치 |
|---|---|---|
| 행 전체 공백 | 외부 시스템·별도 인터페이스 처리 | 프로세스 정의·연계 범위 확인 |
| 열 전체 공백 | 엔티티의 실제 범위·참조 여부 | 모델 포함 근거·누락 기능 확인 |
| 생성(C) 집중 | 여러 프로세스가 같은 엔티티를 생성하는 이유 | 생성 책임·중복 방지 규칙 |
| 수정·삭제 집중 | 동시성·권한·이력 요구 | 트랜잭션·감사 요구와 대조 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 데이터 전달 순서·흐름을 표현하기 어려움 | DFD·시퀀스 모델 병행 |
| 권한·조건·트랜잭션 경계를 알기 어려움 | 업무 규칙·인터페이스 명세·데이터 모델과 교차 참조 |
| 빈 칸·C/R 부재가 항상 결함은 아님 | 배치·외부 연계·조회 전용 등 예외 근거 기록 |

## Ⅵ. 제언

모델링 단계마다 CRUD 매트릭스로 프로세스와 엔티티를 교차 검증하고 예외 근거를 함께 기록

```text
프로세스·엔티티 도출 → CRUD 표기 → 공백·편중 검토 → 모델 보완 → 변경 시 재검증
```

| 구분 | 모델만 검토 | 제언: CRUD 교차 검증 |
|---|---|---|
| 누락 발견 | 늦음 | 조기 |
| 책임 | 모호 | C·U 주체 명확 |
