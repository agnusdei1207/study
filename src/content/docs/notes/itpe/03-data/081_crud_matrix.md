## 지식 로드맵 내 현재 위치

데이터베이스 → 데이터 모델링·무결성 → CRUD 매트릭스

## 30초 인출

- 본질: CRUD 매트릭스는 업무 프로세스와 데이터 엔티티의 사용 관계를 교차표로 나타내는 분석 도구
- 메커니즘: 행은 프로세스, 열은 엔티티, 셀은 생성·조회·수정·삭제 행위를 표시하여 누락과 불일치를 검토
- 통찰: 한계: 요구 변경 뒤 매트릭스를 갱신하지 않으면 실제 설계와 조작 관계가 어긋남 → 방안: 요구사항·모델 변경 시 영향받는 행·열을 함께 갱신하고 검토 이력을 남김

<details>
<summary>핵심 용어</summary>

- **CRUD 매트릭스 (Create, Read, Update, Delete Matrix)** : 프로세스별 데이터 조작 관계를 행과 열의 교차표로 표현한 분석 도구
- **엔티티 (Entity)** : 업무에서 식별하고 관리하는 데이터 대상
- **데이터 흐름도 (Data Flow Diagram, DFD)** : 프로세스 사이의 데이터 이동과 변환을 나타내는 분석 도구

</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **CRUD 매트릭스는** 업무 프로세스와 데이터 엔티티의 조작 관계를 행·열 교차표로 나타낸 분석 도구 |
| 목적 | 기능 요구와 데이터 모델 간 누락·불일치의 조기 발견 |

## Ⅱ. CRUD 교차표의 특징

| 특징 | 표현 | 읽는 방향 |
|---|---|---|
| 두 축의 교차 | 프로세스 × 엔티티 | 행은 기능의 데이터 사용, 열은 데이터의 생성·변경 책임 |
| 조작의 표시 | C·R·U·D | 셀에서 기능과 데이터의 실제 행위를 확인 |
| 공백의 발견 | 빈 행·열·셀 | 누락 가능성을 찾되 예외 근거를 확인 |

## Ⅲ. 프로세스·엔티티 매핑과 정합성 검토 절차

```text
업무 프로세스 ── 행 ──┐
                       ├→ 프로세스 × 엔티티 교차 셀에 C/R/U/D 표기
데이터 엔티티 ─── 열 ──┘               ↓
                 행: 필요한 데이터 누락 확인
                 열: 생성·변경 책임과 이용 경로 확인
                       ↓
               요구사항·모델과 차이 검토
```

| 단계 | 작성 내용 | 확인 관점 |
|---|---|---|
| 1. 프로세스 도출 | 분석 범위의 업무 기능을 적절한 단위로 분해 | 행의 범위와 세분화 수준의 일관성 |
| 2. 엔티티 도출 | 데이터 모델의 주요 엔티티를 정리 | 엔티티 정의·명칭과 모델의 일치 |
| 3. 행위 매핑 | 각 프로세스가 각 엔티티에 수행하는 C/R/U/D 기입 | 요구사항·화면·인터페이스와의 근거 일치 |
| 4. 교차 검토 | 공백·행위 편중·중복 책임을 검토 | 실제 업무 예외와 미모델링 기능 확인 |

### 교차표의 핵심 시각화

| 프로세스 \ 엔티티 | 고객 | 주문 | 결제 |
|---|---:|---:|---:|
| 회원 등록 | C | — | — |
| 주문 접수 | R | C | — |
| 결제 처리 | R | U | C |

## Ⅳ. 공백·행위 편중 패턴과 정합성 분석 기준

| 관찰 패턴 | 확인할 원인 | 가능한 후속 조치 |
|---|---|---|
| 행 전체 공백 | 별도 인터페이스·외부 시스템의 데이터 처리 | 프로세스 정의·연계 범위 확인 |
| 열 전체 공백 | 엔티티의 실제 범위 포함·참조 여부 | 모델 포함 근거 또는 누락 기능 확인 |
| 생성 행위 집중 | 여러 프로세스의 동일 엔티티 생성 이유 | 생성 책임과 중복 데이터 방지 규칙 확인 |
| 변경·삭제 집중 | 동시성·권한·이력 요구의 설계 반영 | 트랜잭션·감사 요구사항과 대조 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 조작 여부만으로 데이터 전달 순서와 흐름을 표현하기 어려움 | 흐름·변환은 DFD나 시퀀스 모델과 함께 확인 |
| 셀 표기만으로 권한·조건·트랜잭션 경계를 알기 어려움 | 업무 규칙, 인터페이스 명세, 데이터 모델을 교차 참조 |
| 빈 셀이나 C/R 부재가 항상 결함을 뜻하지 않음 | 배치·외부 연계·조회 전용·보존 데이터 등 예외 근거 기록 |

## Ⅵ. 제언

**제언:** 요구·엔티티 모델 변경 승인 시 영향받는 행·열을 먼저 재검토하고, C 책임 변경은 중복 생성·권한 규칙까지 확인한다.
