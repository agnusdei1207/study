## 연관 키워드

CRUD 매트릭스, 업무 프로세스, 데이터 엔티티, 생성·조회·수정·삭제, 추적성, 영향도 분석, 데이터 소유권

## Ⅰ. CRUD 매트릭스의 개요

- 핵심 요약 : 업무 기능과 데이터 엔티티가 생성·조회·수정·삭제 중 어떤 관계를 맺는지 표로 나타낸 분석 도구.
- 개념 : **CRUD 매트릭스** (CRUD Matrix)는 행에 업무 기능, 열에 **데이터 엔티티** (Data Entity)를 두고, 교차점에 C(Create, 생성), R(Read, 조회), U(Update, 수정), D(Delete, 삭제)를 표시한 표.
- 배경 및 필요성 : 요구 기능이 많아지면 기능과 데이터 모델 사이에 누락과 중복이 생기고, 어떤 기능이 데이터를 바꾸는지 추적하기 어려워짐.
- 주요 목적 : 요구 기능과 데이터 모델의 누락·중복을 찾고, 기능과 데이터 사이의 **추적성** (Traceability)을 확보.

## Ⅱ. CRUD 매트릭스의 특징 및 장점

- 핵심 요약 : 프로세스와 데이터의 추적 관계를 한눈에 보여 분석·설계·테스트·변경관리를 지원하는 구조.

1. 완전성 점검 : 사용되지 않는 엔티티나 접근 경로가 불분명한 기능을 드러냄 → 요구 누락을 설계 초기에 발견.
2. 책임 가시화 : 기능별 생성·수정 주체를 드러내 **데이터 소유권** (Data Ownership) 논의의 근거를 제공 → 책임 공백 감소.
3. **영향도 분석** (Impact Analysis) : 엔티티가 바뀔 때 관련 기능을 찾는 기준 → 회귀 테스트 범위를 정하는 근거.

- CRUD 표는 관계를 요약할 뿐이므로, 상세한 조건·순서·권한은 별도 모델로 보완해야 한다.

```text
[주문 엔티티 변경 요청]
          ↓
[주문을 C·U하는 업무 기능 조회]
          ↓
[해당 기능의 회귀 테스트 범위 확정]
```

## Ⅲ. CRUD 매트릭스 작성 흐름

- 핵심 요약 : 업무 기능과 엔티티 목록을 정리하고 교차 관계를 검토해 추적성을 확보하는 절차.
- **업무 프로세스** (Business Process) : 사용자가 수행하는 업무 기능을 단위별로 묶은 행 항목.

```text
[업무 기능·시나리오 목록화]
          ↓
[데이터 엔티티 정의]
          ↓
[기능별 C·R·U·D 매핑]
          ↓
[누락·중복·소유권 검토]
          ↓
[요구사항·테스트·변경관리와 연계]
```

| 업무 기능 | 고객 | 주문 | 상품 | 결제 |
| --- | --- | --- | --- | --- |
| 회원 등록 | C |  |  |  |
| 상품 조회 |  |  | R |  |
| 주문·결제 | R | C | R | C |
| 취소·환불 | R | U |  | U |

## Ⅳ. 활용 관점 비교

- 핵심 요약 : CRUD 매트릭스는 요구사항, 데이터 구조, 운영 책임을 이어 주는 보조 산출물.

| 활용 단계 | 확인 내용 | 산출 효과 |
| --- | --- | --- |
| 요구 분석 | 기능별 데이터 생성·사용 여부 | 요구 누락 확인 |
| 데이터 설계 | 엔티티 생성·수정 주체 | 모델·소유권 검토 |
| 테스트 | 기능별 데이터 동작 | 통합 시나리오 도출 |
| 변경관리 | 변경 엔티티와 영향 기능 | 회귀 범위 추적 |

- 모든 엔티티가 반드시 C와 R을 가져야 한다는 고정 규칙은 도메인에 따라 맞지 않을 수 있다. 예를 들어 기준정보는 별도 관리 기능에서 생성될 수 있다.

## Ⅴ. CRUD 매트릭스의 한계와 방안

- 핵심 요약 : 정적 문서의 노후화, 흐름 표현의 한계, 대규모 매트릭스의 복잡성을 관리 절차로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 현행화 지연 | 요구·모델·코드가 바뀌어도 매트릭스가 갱신되지 않음 | 요구사항·모델·코드 변경 절차에 매트릭스 갱신 책임 포함 | 갱신 지연 일수 |
| 조건·순서 표현 부족 | C·R·U·D만으로는 분기 조건과 처리 순서를 나타내지 못함 | 시퀀스 다이어그램, 상태 모델 등 보완 산출물 병행 | 보완 산출물 연계율 |
| 대규모 매트릭스 복잡성 | 기능과 엔티티가 많아 읽기와 검토가 어려움 | 도메인·업무 영역별 분할, 주요 엔티티 우선 검토 | 영역별 검토 완료율 |
| 자동 추출의 오판 | 코드 분석 결과가 설계 의도와 어긋날 수 있음 | 코드 분석 결과를 설계 의도와 대조, 수작업 승인 절차 | 승인 반려 건수 |

```text
문서 노후화   → 변경 절차에 갱신 연결
흐름 표현 부족 → 보완 모델 병행      → 신뢰할 수 있는 추적성
자동 분석 오류 → 담당자 대조·승인
```

## Ⅵ. CRUD 매트릭스에 대한 기술사적 제언

- 핵심 요약 : CRUD 관계를 요구사항, 데이터 사전, 테스트와 연결해 활용 가능한 관리 정보로 만드는 운영 방향.
- 엔티티마다 생성·수정 권한과 기준 원천 시스템을 정해 두면, 여러 시스템이 같은 데이터를 중복 갱신하는 일을 줄일 수 있다.
- 데이터 사전과 모델링 도구를 같은 기준 저장소로 묶어, 엔티티 변경이 매트릭스에 반영되는 관리 체계를 검토하는 것이 바람직하다.
- 개인정보와 감사 대상 데이터는 삭제 정책과 보존 요구를 매트릭스에 별도로 표시해, 데이터 생명주기 관리가 기능 단위로 보이도록 해야 한다.

## Ⅶ. 결론

- 핵심 요약 : CRUD 매트릭스는 업무와 데이터의 관계를 추적하는 설계 도구이며, 상세 모델과 함께 쓰일 때 효과가 커지는 기법.
- 완전성·소유권 검토와 변경 영향 분석이 현행화 체계와 연결될 때, 매트릭스는 살아 있는 관리 정보가 된다.
