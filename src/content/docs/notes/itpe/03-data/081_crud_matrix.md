## 지식 로드맵 내 현재 위치

데이터베이스 → 데이터 모델링·무결성 → CRUD 매트릭스

## 30초 인출

- **본질**: CRUD 매트릭스는 업무 프로세스와 데이터 엔티티의 사용 관계를 교차표로 나타내는 분석 도구
- **메커니즘**: 행은 프로세스, 열은 엔티티, 셀은 생성·조회·수정·삭제 행위를 표시하여 누락과 불일치 검토

<details>
<summary>핵심 용어</summary>

- **CRUD 매트릭스 (Create, Read, Update, Delete Matrix)**: 프로세스별 데이터 조작 관계를 행과 열의 교차표로 표현한 분석 도구
- **엔티티 (Entity)**: 업무에서 식별하고 관리하는 데이터 대상
- **데이터 흐름도 (Data Flow Diagram, DFD)**: 프로세스 사이의 데이터 이동과 변환을 나타내는 분석 도구

</details>

> CRUD 매트릭스의 정의, 목적, 구성과 프로세스·데이터 간 정합성 점검 방법을 설명하시오. (예상)

---

## 1교시 10점 답안

### Ⅰ. CRUD 매트릭스의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **CRUD 매트릭스**는 업무 프로세스와 데이터 엔티티의 조작 관계를 행·열 교차표로 나타낸 분석 도구 |
| 목적 | 기능 요구와 데이터 모델 간 누락·불일치의 조기 발견 |

### Ⅱ. 행·열·셀의 대응

| 행 | 열 | 교차 셀 |
|---|---|---|
| 단위 업무 프로세스 | 데이터 엔티티 | C(Create), R(Read), U(Update), D(Delete) 수행 관계 |

### Ⅲ. 완전성 검토

| 점검 방향 | 확인 질문 | 해석 시 유의점 |
|---|---|---|
| 행 검토 | 업무 프로세스가 필요한 데이터를 다루는가 | 데이터 조작이 없는 프로세스도 업무상 유효할 수 있음 |
| 열 검토 | 엔티티를 생성·조회·변경·삭제하는 기능이 설명되는가 | C/R 부재는 검토 신호이지 자동 오류 판정은 아님 |
| 교차 셀 | 행위가 요구사항·데이터 모델과 일치하는가 | 복수 행위는 병기 등 프로젝트 표기 규칙으로 표현 |

**제언:** CRUD 표기 규칙과 예외 사유를 함께 기록해 요구 변경 때 다시 대조한다.

---

## 2~4교시 25점 답안

## Ⅰ. CRUD 매트릭스의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **CRUD 매트릭스**는 업무 프로세스와 데이터 엔티티의 조작 관계를 행·열 교차표로 나타낸 분석 도구 |
| 목적 | 기능 요구와 데이터 모델 간 누락·불일치의 조기 발견 |

## Ⅱ. 구성과 작성 순서

| 단계 | 작성 내용 | 확인 관점 |
|---|---|---|
| 1. 프로세스 도출 | 분석 범위의 업무 기능을 적절한 단위로 분해 | 행의 범위와 세분화 수준의 일관성 |
| 2. 엔티티 도출 | 데이터 모델의 주요 엔티티를 정리 | 엔티티 정의·명칭과 모델의 일치 |
| 3. 행위 매핑 | 각 프로세스가 각 엔티티에 수행하는 C/R/U/D 기입 | 요구사항·화면·인터페이스와의 근거 일치 |
| 4. 교차 검토 | 공백·행위 편중·중복 책임을 검토 | 실제 업무 예외와 미모델링 기능 확인 |

### 교차표의 핵심 시각화

| 프로세스 \ 엔티티 | 고객 | 주문 | 결제 |
|---|---:|---:|---:|
| 회원 등록 | C | — | — |
| 주문 접수 | R | C | — |
| 결제 처리 | R | U | C |

## Ⅲ. 정합성 분석 기준

| 관찰 패턴 | 검토 질문 | 가능한 후속 조치 |
|---|---|---|
| 행 전체 공백 | 이 프로세스의 데이터 처리가 별도 인터페이스·외부 시스템에 있는가 | 프로세스 정의·연계 범위 확인 |
| 열 전체 공백 | 엔티티가 실제 범위에 속하거나 참조되는가 | 모델 포함 근거 또는 누락 기능 확인 |
| 생성 행위 집중 | 여러 프로세스가 같은 엔티티를 생성하는 이유가 있는가 | 생성 책임과 중복 데이터 방지 규칙 확인 |
| 변경·삭제 집중 | 동시성·권한·이력 요구가 설계에 반영됐는가 | 트랜잭션·감사 요구사항과 대조 |

## Ⅳ. 분석 한계와 보완

| 한계 | 보완 |
|---|---|
| 조작 여부만으로 데이터 전달 순서와 흐름을 표현하기 어려움 | 흐름·변환은 DFD나 시퀀스 모델과 함께 확인 |
| 셀 표기만으로 권한·조건·트랜잭션 경계를 알기 어려움 | 업무 규칙, 인터페이스 명세, 데이터 모델을 교차 참조 |
| 빈 셀이나 C/R 부재가 항상 결함을 뜻하지 않음 | 배치·외부 연계·조회 전용·보존 데이터 등 예외 근거 기록 |

## Ⅴ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 분석 시 작성한 매트릭스가 요구 변경 뒤 실제 설계와 달라질 가능성 | 요구사항·데이터 모델 변경 시 영향받는 행과 열을 함께 갱신하고 리뷰 이력 관리 |

**제언:** 변경관리 절차에 매트릭스 재검토 시점을 포함해 분석 산출물과 설계 기준의 일치 유지.
