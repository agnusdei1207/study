## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터 웨어하우스 → **로지컬 데이터웨어하우스(LDW) 아키텍처**

## 30초 인출

- 본질: 로지컬 데이터웨어하우스는 여러 데이터 원천을 논리적으로 연결해 통합 분석을 지원하는 데이터 관리 구조
- 메커니즘: 원천을 커넥터·메타데이터로 논리 뷰와 시맨틱 계층에 연결해 업무 용어·정의·권한을 적용하고, 질의마다 연합 질의와 캐시·부분 적재 중 하나를 선택해 통합 결과를 제공
- 통찰: 질의가 성공해도 업무 용어와 원천 필드, 권한의 매핑이 틀리면 분석이 왜곡되므로 한 업무 도메인부터 용어·원천·권한을 정리해 확대하고 시맨틱 정의를 원천 변경과 함께 관리

- **데이터 패브릭** : 메타데이터·정책·자동화로 환경 전반의 데이터 접근을 조정하는 접근

## 2~4교시 25점 답안

## Ⅰ. 로지컬 데이터웨어하우스의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **LDW** 는 여러 원천을 논리적으로 연결해 통합 분석을 지원하는 데이터 관리 구조 |
| 목적 | 데이터 사일로와 중복 적재 부담을 줄이고 일관된 분석 접근 제공 |

## Ⅱ. 특징

| 특징 | 구축상 의미 |
|---|---|
| 논리적 통합 | 여러 원천을 한 관점에서 조회하되 모두 옮길 필요는 없음 |
| 업무 의미의 통일 | 원천별 이름·형식을 시맨틱 계층의 용어·정의와 연결 |
| 혼합 실행 | 실시간 연합 질의와 반복 분석용 캐시·부분 적재를 요구에 따라 선택 |

## Ⅲ. 계층 구조와 접근 절차

```text
원천 DB·파일·서비스 → 커넥터·메타데이터 → 논리 뷰·시맨틱 계층
                                              ↓ 권한·업무 정의 적용
분석가·보고서 ← 통합 결과 ← 연합 질의 / 캐시·부분 적재 선택
```

```text
업무 지표 정의 → 원천별 필드·코드 매핑 → 논리 뷰 → 접근 권한 적용
   ↓ 지표 소유자·계보·품질 확인 → 같은 뜻·같은 범위로 결과 검증
```

용어·권한 매핑에 오류가 있으면 질의가 성공해도 분석이 왜곡됨.

## Ⅳ. LDW 기능과 데이터 패브릭

| 기능 | 역할 | 설계 판단 |
|---|---|---|
| 가상화·연합 질의 | 분산 원천을 논리 뷰로 연결 | 원천 부하·커넥터 지원·질의 지연 |
| 시맨틱·카탈로그 | 업무 정의와 원천 메타데이터 연결 | 용어·계보·소유자 관리 |
| 물리 적재·캐시 | 반복 분석의 성능·가용성 지원 | 최신성·비용·운영 부하 비교 |

모든 데이터를 가상화·무복제하는 것이 목표는 아니며 빈번하고 무거운 질의는 물리 적재·캐시와 함께 검토.

| 구분 | 로지컬 DW | 데이터 패브릭 |
|---|---|---|
| 초점 | 분산 원천의 논리 통합·질의 | 환경 전반의 데이터 관리·접근 조정 |
| 기반 | 가상화·연합 질의·논리 모델 | 메타데이터·계보·정책·자동화 |
| 관계 | 통합 접근을 제공하는 구조 | LDW 기능을 포함하거나 다른 통합 방식과 결합 |
| 유의 | 원천별 성능·기능 차이와 부하 | 자동화 범위·메타데이터 품질·정책 일관성 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 전사 원천을 한 번에 연결해 용어·권한 차이로 부담 증가 | 한 도메인의 용어·원천·권한을 정리해 검증하며 확대 |
| 시맨틱 정의가 원천 변경을 따라가지 못함 | 지표·원천 필드·계보의 변경 영향과 소유자 함께 관리 |
| 연합 질의에 원천 부하·지연 집중 | 반복 분석은 캐시·부분 적재와 비교, 원천 부하 측정 |

## Ⅵ. 제언

한 업무 도메인에서 시맨틱 정의와 권한을 확정한 뒤 범위를 넓히고, 질의별로 연합·캐시를 선택

```text
도메인 선정 → 용어·원천·권한 매핑 → 질의별 연합/캐시 선택 → 변경 영향 관리 → 도메인 확대
```

| 구분 | 전사 일괄 연결 | 제언: 도메인별 확대 |
|---|---|---|
| 운영 부담 | 큼 | 단계적 |
| 정의 일관성 | 불일치 위험 | 도메인 내 확정 |
