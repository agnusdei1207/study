## 연관 키워드

- 옵티마이저, RBO/CBO, 실행 계획, 카디널리티, 선택도, 힌트, 히스토그램, 바인드 피킹

## Ⅰ. 옵티마이저의 개요

- 핵심 요약 : SQL을 받아 통계정보 기반으로 최적 실행 계획을 만드는 DBMS 핵심 엔진.
- 개념 : SQL의 처리 방법을 비용 기준으로 결정하는 DBMS 구성요소(**옵티마이저**, Optimizer).
- 배경 및 필요성 : 동일한 SQL도 접근 경로에 따라 성능 차이가 커서, **실행 계획** (Execution Plan, 데이터 접근 방식과 조인 순서를 정한 처리 절차)을 최적화할 필요가 있음.
- 주요 목적 : 사용자가 무엇(What)을 원하는지만 선언하면, 어떻게(How) 처리할지는 옵티마이저가 결정하도록 하는 것.
- 특징 : **RBO** (Rule-Based Optimizer, 규칙 기반 옵티마이저)에서 **CBO** (Cost-Based Optimizer, 비용 기반 옵티마이저)로 발전해 통계정보와 비용 모델을 활용.

```text
[ 옵티마이저의 위치 ]

SQL 입력
   ↓
옵티마이저 (통계정보·비용 모델)
   ↓
실행 계획 확정
   ↓
실행기 (데이터 접근 수행)
```

## Ⅱ. 옵티마이저의 특징 및 장점

- 핵심 요약 : CBO가 통계정보와 비용 모델로 데이터 규모에 맞는 계획을 만드는 구조.

1. 비용 기반 : I/O와 CPU 비용을 계산해 최적 경로를 선택 → 데이터 규모에 맞는 접근 방식 확보.
2. 통계 활용 : 테이블·인덱스·컬럼 통계로 **카디널리티** (Cardinality, 조건을 만족하는 예상 행 수)를 예측 → 계획 추정 정확도 향상.
3. 적응형 : 데이터 분포와 볼륨이 바뀌면 계획을 다시 산출 → 변화에 따른 성능 저하 완화.
4. 힌트 지원 : **힌트** (Hint, 개발자가 옵티마이저의 계획 선택을 유도하는 지시문) → 긴급 상황에서 계획을 강제할 수 있음.
5. 편향 반영 : **히스토그램** (Histogram, 컬럼 값의 분포를 구간별로 나타낸 통계) → 치우친 데이터 분포를 정밀하게 반영.

## Ⅲ. 옵티마이저의 내부 메커니즘 및 학습 흐름

- 핵심 요약 : 쿼리 변환, 비용 예측, 계획 생성의 3단계로 최적 실행 계획을 확정.
- **선택도** (Selectivity, 조건이 전체 행 중 차지하는 비율) : 균등 분포와 동등 조건을 가정하면 1/NDV(Number of Distinct Values)로 추정.
- 카디널리티 : 총 행 수 × 선택도로 계산하며, 이 값이 비용 예측의 입력이 됨.

```text
[ CBO 내부 처리 프로세스 ]

SQL 입력
   ↓
[1. 쿼리 변환기]
  서브쿼리 언네스팅, 뷰 머징, 조건절 푸시다운
   ↓
[2. 비용 예측기]
  카디널리티, 선택도, 비용(Cost) 계산
   ↓
[3. 계획 생성기]
  조인 순서·기법·인덱스 조합 탐색
   ↓
[최적 실행 계획 확정]
```

## Ⅳ. RBO와 CBO의 비교

- 핵심 요약 : 통계 활용, 비용 모델, 적응성 측면에서 CBO가 현행 표준.

| 항목 | RBO (규칙 기반) | CBO (비용 기반) |
| --- | --- | --- |
| 최적화 기준 | 우선순위 규칙 | I/O·CPU 비용 |
| 통계 활용 | 미사용 | 필수 |
| 인덱스 판단 | 규칙상 인덱스가 있으면 사용 | 비용에 따라 선택 |
| 현재 위상 | 레거시 (현행 RDBMS의 기본 방식 아님) | 현행 RDBMS 표준 |

- 바인드 피킹, 다중 조건의 추정 오차, 통계 부재는 CBO의 대표적 한계다.

## Ⅴ. 옵티마이저의 한계와 방안

- 핵심 요약 : 바인드 피킹, 비용 추정 오차, 통계 부재를 적응형 계획 관리, 확장 통계, 통계 수집 스케줄로 대응.
- **바인드 피킹** (Bind Peeking, 최초 파싱 때의 바인드 변수 값으로 계획을 만드는 동작) : 값 분포가 다른 후속 실행에서 비효율 계획이 재사용될 수 있음.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 바인드 피킹 | 최초 값 기준 계획이 캐시되어 후속 쿼리가 비효율 | ACS(Adaptive Cursor Sharing) 활성화, SPM(SQL Plan Management)으로 계획 고정 | 실행 계획 안정성 |
| 비용 추정 오차 | 컬럼 독립성 가정으로 다중 조건에서 오차 증폭 | 확장 통계, 동적 표본 추출, 힌트 유도 | 추정 행 수와 실제 행 수 차이 |
| 통계 부재 | DDL·배치 이후 통계 누락으로 최악의 계획 선택 | 증분 통계 수집, 심야 수집 스케줄, 통계 잠금 | 통계 수집 성공률 |

## Ⅵ. 옵티마이저에 대한 기술사적 제언

- 핵심 요약 : 힌트 의존을 줄이고 통계 관리와 히스토그램 전략을 갖춰 계획의 안정성을 확보하는 운영 원칙.

1. 힌트는 긴급 조치로 한정하고, 근본 원인은 통계 갱신과 인덱스 재설계로 해결하는 것이 바람직하다.
2. 값이 편향된 컬럼에는 히스토그램을 수집해 카디널리티 추정 오차를 줄여야 하며, 빈도형(Frequency)과 높이 균형형(Height-Balanced) 중 데이터 분포에 맞는 유형을 고른다.
3. 대량 배치 작업 직후 증분 통계 수집을 프로세스에 포함시켜, 통계 누락으로 생기는 최악의 계획을 예방할 필요가 있다.

## Ⅶ. 결론

- 핵심 요약 : 옵티마이저는 통계 기반 비용 최적화 엔진으로, CBO가 표준이며 통계 관리가 성능의 핵심임.
- 시사점 : RBO와 CBO의 차이, 내부 3단계 처리, 카디널리티와 선택도, 한계와 대응을 함께 이해해야 실행 계획 불안정을 진단할 수 있음.
