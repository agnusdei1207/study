## 지식 로드맵 내 현재 위치

자료처리·데이터 → 분산 데이터베이스 → **샤딩**

## 30초 인출

- 본질: 샤딩은 한 데이터 집합을 샤드 키에 따라 여러 노드에 나누어 저장·처리하는 수평 확장 방식
- 메커니즘: 라우터가 샤드 키로 대상 샤드를 정해 단일 샤드는 해당 노드에서, 키가 없는 질의는 복수 샤드에서 실행하고 결과를 통합하며, 편중이 생기면 재분배
- 통찰: 샤드 키가 부하 분포와 질의 경로를 좌우하므로 주요 질의에 키가 포함되고 편중이 적은 키를 선택하고, 가용성은 복제로 별도 확보

<details>
<summary>핵심 용어</summary>

- **샤딩(Sharding)** : 데이터를 여러 노드에 수평 분할해 저장하는 방식
- **샤드 키** : 행을 어느 샤드에 둘지 정하는 키
- **범위 샤딩·해시 샤딩** : 키의 연속 범위로 / 키의 해시 값으로 분할
- **라우터** : 샤드 키와 배치 정보로 질의를 해당 샤드에 전달하는 구성요소
- **팬아웃(Fan-out)** : 키 조건이 없어 여러 샤드에 질의를 보내는 것
- **핫스팟** : 특정 샤드에 요청이 몰리는 현상
- **재샤딩(Resharding)** : 데이터 성장·편중에 따라 샤드 배치를 다시 조정하는 것

</details>

## 2~4교시 25점 답안

## Ⅰ. 샤딩의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **샤딩** 은 한 데이터 집합을 여러 노드에 나누어 저장·처리하는 수평 확장 방식 |
| 목적 | 단일 노드의 저장·처리 한계를 분산해 용량 확장 |

## Ⅱ. 특징

| 특징 | 설계 영향 |
|---|---|
| 행 단위 수평 분할 | 샤드 키에 따라 다른 노드에 배치 |
| 조건부 단일 샤드 접근 | 키 조건이 없으면 팬아웃·병합 비용 발생 |
| 분할·복제 분리 | 용량 확장과 장애 가용성은 별도 설계 |

## Ⅲ. 질의 라우팅과 재분배

```text
클라이언트 질의 → 라우터 → 샤드 키로 대상 결정
                          ├ 단일 샤드 → 해당 노드 실행
                          └ 복수 샤드 → 분산 실행·결과 통합
```

```text
편중 감지 → 새 키 범위·배치 계획 → 데이터 이동 → 이동 중 정합성 확인 → 라우팅 정보 전환
```

| 구성요소 | 책임 |
|---|---|
| 샤드 키 | 분할·배치 기준 |
| 샤드 | 데이터 일부의 저장·처리 |
| 라우터 | 질의 전달 |
| 메타데이터 | 키 범위·샤드 배치 정보 관리 |
| 복제본(선택) | 가용성·읽기 처리 지원 |

## Ⅳ. 분할 방식 비교

| 방식 | 배치 원리 | 장점 | 주의점 |
|---|---|---|---|
| 범위 | 키의 연속 범위 | 범위 검색·순서 질의 유리 | 단조 증가 키·불균등 범위의 핫스팟 |
| 해시 | 키의 해시 값 | 편중 완화 | 범위 검색이 여러 샤드로 퍼짐 |

샤딩은 데이터를 나누는 방식이고 복제는 같은 데이터의 복사본을 두는 방식이며 실제 시스템은 둘을 함께 사용.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 키 편중·단조 증가로 핫스팟 | 키 빈도·증가성을 분석해 분할 기준 검토 |
| 키 없는 질의의 팬아웃 | 주요 질의에 샤드 키 포함, 통합 비용 측정 |
| 데이터 성장에 따른 재분배 | 이동량·운영 영향·복구를 포함한 재샤딩 계획 |
| 샤드 간 트랜잭션·조인 | 업무 경계를 고려해 데이터 배치 |

## Ⅵ. 제언

주요 질의 조건에 포함되고 분포가 고른 샤드 키를 선택하고, 재분배 절차와 복제를 함께 설계

```text
질의 패턴 분석 → 샤드 키 선정 → 배치 → 편중 모니터링 → 재분배
```

| 구분 | 임의 키 선택 | 제언: 질의 기반 키 선택 |
|---|---|---|
| 질의 | 팬아웃 빈발 | 단일 샤드 위주 |
| 부하 | 편중 | 분산 |
