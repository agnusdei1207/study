## 연관 키워드

- 샤딩, 수평 분할, 샤드 키, 핫스팟, 라우팅, 재분배, 분산 트랜잭션

## Ⅰ. 샤딩의 개요

- 핵심 요약 : **샤딩**은 데이터와 부하를 여러 독립 노드에 분산해 단일 노드의 저장·처리 한계를 넘어서는 확장 방식.
- 개념 : 행 단위로 데이터를 나누는 **수평 분할**로 만든 샤드(Shard)를 독립 노드에 배치하는 방식.
- 목적 : 데이터 저장량과 읽기·쓰기 부하를 여러 노드로 나누어 처리.
- 적용 조건 : 인덱스 튜닝, 캐싱, 읽기 복제본 등으로 요구 성능을 맞추기 어려울 때, 복잡성과 운영 비용을 감수하고 도입.

## Ⅱ. 샤딩의 특징 및 장점

- 핵심 요약 : 분산 저장과 병렬 처리로 확장성을 얻지만, **샤드 키** 선택이 성능과 운영 난도를 좌우하는 방식.

1. 수평 확장 : 노드를 추가해 저장·처리 용량을 늘림 → 데이터 증가에 맞춘 점진적 확장.
2. 병렬 처리 : 샤드별 쿼리를 동시에 수행 → 응답 시간 단축.
3. 장애 격리 : 장애 영향 범위를 해당 샤드로 제한 → 전체 장애 확산 완화. 다만 서비스 전체 가용성은 라우팅·복제·장애 조치 설계에 달림.
4. 샤드 키 의존성 : 접근 패턴에 맞지 않는 키는 데이터 편중과 다중 샤드 조회를 유발 → 키 설계가 성능을 결정.

## Ⅲ. 샤딩의 구조와 요청 흐름

- 핵심 요약 : 애플리케이션 요청을 **라우팅**으로 샤드에 전달하고, 결과를 병합해 반환하는 흐름.
- 키 결정 시 조회·갱신 패턴, 분포 편향, 확장과 재배치 비용, 조인 관계를 함께 고려.
- 함께 접근되는 주문과 주문상세처럼 연관 데이터는 같은 분할 기준을 검토하되, 특정 고객에 데이터가 쏠리지 않는지 확인.

```text
[애플리케이션 요청]
          ↓
[샤드 키 추출·라우팅]
          ↓
  키 단건 조회 → 대상 샤드 1개
  범위·집계 질의 → 관련 샤드 병렬 조회
          ↓
[결과 병합·반환]
          ↓
[지표·편중 감시]
```

```text
[순차 키 입력 (날짜 기준)]
          ↓
[최신 범위 샤드에 쓰기 집중]
          ↓
[핫스팟] 한 노드 과부하
```

**핫스팟** (Hotspot)은 특정 샤드에 요청이 몰려 해당 노드만 과부하되는 현상이며, 범위 기반 분할에서 순차 키를 쓸 때 쉽게 나타난다.

## Ⅳ. 분할 방식의 비교

- 핵심 요약 : 균등 분산, 범위 질의, 노드 증설 시 재배치량을 기준으로 분할 방식을 선택.

| 방식 | 원리 | 장점 | 유의점 |
| --- | --- | --- | --- |
| 해시 기반 | 키의 해시값으로 샤드 결정 | 데이터 분포를 고르게 만들기 쉬움 | 범위 검색 시 다수 샤드 접근 |
| 범위 기반 | 키 범위별로 배치 | 범위 질의와 기간별 관리에 유리 | 순차 입력 시 핫스팟 발생 |
| 디렉터리 기반 | 별도 매핑 정보로 위치 조회 | 유연한 이동과 배치 | 매핑 계층의 가용성·일관성 필요 |
| 일관 해싱 | 해시 링과 가상 노드로 배치 | 노드 변경 시 이동 범위 축소 | 균등성과 리밸런싱 운영 고려 |

## Ⅴ. 샤딩의 한계와 방안

- 핵심 요약 : 핫스팟, 다중 샤드 연산, **재분배** 위험은 키 설계와 운영 절차로 낮추고, 여러 샤드에 걸친 **분산 트랜잭션**은 가능한 한 피해야 함.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 키 편중 | 특정 샤드에 요청이 집중되어 해당 노드 과부하 | 키 분포와 노드별 부하 분석, 복합 키·버킷 등 대안을 부하 시험 | 샤드별 처리량 편차 |
| 교차 샤드 연산 | 여러 샤드에 걸친 갱신은 원자성 확보가 어려움 | 함께 쓰이는 데이터를 같은 샤드에 배치, 보상 처리 설계 | 교차 샤드 요청 비율 |
| 전역 집계·정렬 | 모든 샤드를 훑어야 해 지연 증가 | 사전 집계, 파티션 프루닝, 비동기 분석 저장소 활용 | 집계 질의 지연 |
| 재분배 중 정합성 위험 | 노드 추가·이동 중 데이터 불일치 발생 | 복제·검증·전환 순서 확정, 재시도와 롤백 시험 | 이동 후 검증 불일치 건수 |

## Ⅵ. 샤딩에 대한 기술사적 제언

- 핵심 요약 : 샤딩 전후의 성능과 운영 복잡성을 측정하며 단계적으로 전환하는 접근 필요.
- 샤딩은 운영 복잡도를 크게 높이므로, 인덱스, 파티셔닝, 캐시, 읽기 복제본 같은 덜 복잡한 대안을 먼저 검토하는 것이 바람직하다.
- 샤드별 지연, 처리량, 저장량, 오류율과 키 편중 지표를 상시 관찰하여 편중이 커지기 전에 키 재설계를 판단한다.
- 재샤딩은 온라인 복제, 데이터 검증, 트래픽 전환, 원복 경로를 포함한 변경 관리 절차로 수행한다.

## Ⅶ. 결론

- 핵심 요약 : 샤딩은 대규모 부하를 분산하는 확장 기법이며, 성패는 샤드 키, 질의 패턴, 재분배 운영에 달려 있음.
- 시사점 : 분할 방식별 장단점과 핫스팟, 교차 샤드 연산에 대한 대비를 함께 설계해야 무중단 전환이 가능함.
