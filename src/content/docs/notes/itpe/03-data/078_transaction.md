## 연관 키워드
- 트랜잭션, ACID, 원자성, 일관성, 격리성, 지속성, 커밋·롤백

### Ⅰ. 트랜잭션의 개요

- 핵심 요약 : 데이터베이스의 논리적 작업 단위로 성공 시 전체 반영하고 실패 시 원자적으로 취소하는 실행 경계.
- 개념 : 데이터베이스의 논리적 작업 단위로 성공 시 전체 반영하고 실패 시 원자적으로 취소하는 실행 경계(**트랜잭션**, Transaction).
- 배경 및 필요성 : 여러 읽기·쓰기 단계 중 일부만 반영되면 업무 불변조건과 데이터 일관성 훼손.
- 주요 목적 : 복수 연산을 신뢰 가능한 원자적 업무 단위로 처리.

### Ⅱ. 트랜잭션의 특징 및 장점

- 핵심 요약 : Atomicity·Consistency·Isolation·Durability는 데이터베이스의 논리적 작업 단위를 보장하는 속성.

1. Atomicity : 전체 성공 또는 전체 롤백 → 부분 반영 방지.
2. Consistency : 제약·업무 불변조건 보존 → 유효 상태 전이.
3. Isolation·Durability : 동시성 격리와 커밋 결과 영속화 → 장애 시 원자적 복구 가능.

### Ⅲ. 트랜잭션의 구조 (흐름)

- 핵심 요약 : BEGIN·트랜잭션 경계 진입 → 읽기·쓰기와 제약 검사 → 모두 성공 시 COMMIT → 오류 발생 시 ROLLBACK → 외부 부작용은 아웃박스·보상 처리.

```text
BEGIN·트랜잭션 경계 진입
   ↓
읽기·쓰기와 제약 검사
   ↓
모두 성공 시 COMMIT
   ↓
오류 발생 시 ROLLBACK
   ↓
외부 부작용은 아웃박스·보상 처리
```

```text
BEGIN → 연산·제약검사 → COMMIT
오류·충돌 → ROLLBACK
커밋 이후 외부 전달은 아웃박스 등으로 신뢰화
```

### Ⅳ. ACID 트랜잭션과 분산 사가 비교

- 핵심 요약 : 실패 처리 기준 — ACID 트랜잭션: 엔진 롤백·복구; 분산 사가: 보상작업·재시도·최종상태 관리.

| 비교 기준 | ACID 트랜잭션 | 분산 사가 |
|---|---|---|
| 범위 | 단일 DB 자원 내 원자성·격리 | 여러 서비스의 로컬 트랜잭션과 보상 |
| 실패 처리 | 엔진 롤백·복구 | 보상작업·재시도·최종상태 관리 |
| 일관성 | 강한 트랜잭션 보장이 가능 | 중간 상태·최종 일관성 허용 |

### Ⅴ. 트랜잭션의 한계와 방안

- 핵심 요약 : 장기 트랜잭션·외부 부작용 등 주요 위험을 원인에 맞는 통제로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 장기 트랜잭션 | 잠금·로그·자원 점유와 교착 증가 | 짧은 경계·분할·비동기 처리 | 잠금 대기·실행시간 |
| 외부 부작용 | 메일·결제는 DB 롤백에 포함되지 않음 | 아웃박스·멱등성·보상 트랜잭션 사용 | 중복·누락 이벤트 |
| 경계 오류 | 여러 업무 규칙을 일부만 묶어 부분 상태 발생 | 불변조건 단위 경계·경쟁시험 적용 | 업무 정합성 오류 |

### Ⅵ. 트랜잭션에 대한 기술사적 제언

- 핵심 요약 : 서비스 설계자는 트랜잭션을 불변조건에 맞는 최소 단위로 두고 외부 서비스 호출은 멱등성·아웃박스·보상정책으로 분리할 필요가 있다.
- 실행 제안 : 개발팀은 트랜잭션 불변조건과 외부 부작용 경계를 정의하고 아웃박스 이벤트의 중복·재처리 시나리오 점검할 필요가 있다.

### Ⅶ. 결론

- 핵심 요약 : ACID는 DB 트랜잭션의 보장 속성으로 분산 서비스 전체에 자동 확장되는 보장은 아님.
- 시사점 : 트랜잭션 보장은 단일 데이터베이스 경계를 넘어 외부 서비스에 자동 전파되지 않음.
