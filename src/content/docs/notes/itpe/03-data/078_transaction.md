## 지식 로드맵 내 현재 위치

자료처리·데이터 → 트랜잭션 동시성 → **트랜잭션(ACID)**

## 30초 인출

- 본질: 트랜잭션은 하나의 논리 작업을 전부 반영하거나 전부 취소하는 단위로 처리하는 데이터베이스 작업 묶음
- 메커니즘: 활성 → 부분 완료 → 커밋으로 진행하고 오류 시 실패 → 롤백하며, ACID(원자성·일관성·격리성·영속성)를 undo 정보·제약·잠금·MVCC·WAL 같은 수단으로 지원
- 통찰: ACID의 세부 보장 범위는 DBMS와 설정에 따라 달라지고 일관성은 제약조건만으로 보장되지 않으므로, 지켜야 할 업무 불변조건을 정의하고 격리·로그·복구 동작을 시험으로 확인

<details>
<summary>핵심 용어</summary>

- **트랜잭션(Transaction)** : 성공 또는 취소의 단위로 처리되는 작업 묶음
- **ACID** : 원자성·일관성·격리성·영속성의 네 속성
- **커밋·롤백** : 변경을 확정 / 변경을 취소
- **WAL(Write-Ahead Logging)** : 데이터 페이지를 기록하기 전에 로그를 안정 저장하는 원칙
- **REDO·UNDO** : 커밋된 변경의 재반영 / 미완료 변경의 취소
- **MVCC** : 여러 버전의 데이터를 두어 읽기와 쓰기의 충돌을 줄이는 동시성 제어
- **체크포인트** : 복구 시작 지점을 앞당기기 위해 메모리 변경을 디스크에 반영하는 시점

</details>

## 2~4교시 25점 답안

## Ⅰ. 트랜잭션의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **트랜잭션** 은 하나의 논리 작업을 성공 또는 취소 단위로 처리하는 작업 묶음 |
| 목적 | 동시 처리와 장애에도 데이터의 유효 상태 유지 |

## Ⅱ. 특징

| 특징 | 운영 의미 |
|---|---|
| 논리 작업 경계 | 여러 변경을 하나의 성공·취소 단위로 묶음 |
| 동시성 제어 | 격리 수준에 따라 다른 트랜잭션과의 간섭 제한 |
| 장애 후 상태 보존 | 로그·복구로 확정·미확정 변경 구분 |

## Ⅲ. 상태 전이와 복구

```text
활성 → 부분 완료 → 커밋(완료)
  │         │
  └── 오류 ─→ 실패 → 롤백(철회)
```

```text
WAL: 변경 내용의 로그를 안정 저장 → 데이터 페이지 기록
장애 후 로그 분석 ─ 커밋됐으나 미반영 → REDO
                  └ 미완료인데 반영됨 → UNDO
```

| 상태 | 의미 |
|---|---|
| 활성 | 연산 수행 중 |
| 부분 완료 | 마지막 연산 후 커밋 확정 전 |
| 완료 | 커밋 성공 |
| 실패 | 오류로 정상 완료 불가 |
| 철회 | 변경 취소 후 종료 또는 재시작 |

## Ⅳ. ACID 속성

| 속성 | 보장 의미 | 지원 요소 예 |
|---|---|---|
| 원자성(Atomicity) | 전체 반영 또는 전체 취소 | undo 정보·롤백 |
| 일관성(Consistency) | 전후로 유효 조건 유지 | 제약조건과 올바른 업무 로직 |
| 격리성(Isolation) | 동시 실행 간섭 통제 | 잠금·MVCC·격리 수준 |
| 영속성(Durability) | 커밋 결과 보존·장애 복구 | WAL·복구 로그·저장장치 설정 |

- 지원 요소는 대표 구현 예이며 세부 기법과 보장 범위는 DBMS와 설정에 따라 다름
- 일관성은 DB 제약만으로 모든 업무 규칙이 보장된다는 뜻이 아니며 트랜잭션 로직도 유효 조건을 지켜야 함
- 일부 DBMS는 커밋 확인 전 로그의 로컬 저장 또는 복제 완료를 요구하는 설정을 제공

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 높은 격리·긴 트랜잭션으로 동시성 저하 | 불변 조건을 지키는 범위에서 격리 수준·길이 조정 |
| 외부 서비스 호출로 장애·지연이 DB 작업까지 확산 | DB 트랜잭션과 외부 통신 경계를 구분하고 실패·재시도 설계 |
| 커밋 응답과 복제·저장 설정의 관계 누락 | 목표 장애 범위와 동기화 정책을 명시하고 복구 시험 |
| ACID 용어만 확인해 업무 불변조건 누락 | 보존할 업무 상태를 정의하고 동작 시험 |

## Ⅵ. 제언

업무 불변조건을 먼저 정의하고 그에 맞는 격리 수준·트랜잭션 경계·복구 목표를 정해 시험으로 확인

```text
불변조건 정의 → 격리 수준·경계 결정 → 로그·복제 설정 → 장애 복구 시험
```

| 구분 | ACID 용어만 확인 | 제언: 불변조건 기반 검증 |
|---|---|---|
| 일관성 | 제약에 의존 | 업무 규칙까지 확인 |
| 내구성 | 설정 오해 | 복구 시험 |
