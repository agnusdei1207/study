## 30초 인출

- 본질: 링크드 오픈 데이터는 공개 데이터를 웹 식별자로 서로 연결해 재사용을 돕는 데이터 공개 방식
- 메커니즘: HTTP URI로 대상을 식별·조회하고, RDF 관계와 외부 링크를 따라 관련 데이터를 발견
- 통찰: 데이터 사일로를 해소하고 웹 스케일의 의미적 연결을 달성하기 위해 W3C 5-Star 모델에 입각한 URI 식별체계 및 RDF/SPARQL 표준 연계 필수

<details>
<summary>핵심 용어</summary>

- **링크드 오픈 데이터 (Linked Open Data, LOD)** : 공개 데이터를 웹 식별자와 관계 링크로 연결해 발견·재사용할 수 있게 한 데이터
- **URI (Uniform Resource Identifier)** : 웹 자원이나 개념을 식별하는 문자열
- **HTTP (Hypertext Transfer Protocol)** : 웹에서 자원을 요청하고 응답을 전달하는 응용 계층 프로토콜
- **RDF (Resource Description Framework)** : 주어·서술어·목적어 관계로 데이터를 표현하는 그래프 데이터 모델
- **SPARQL Protocol and RDF Query Language (SPARQL)** : RDF 그래프를 질의하고 갱신하기 위한 표준 언어 계열
- **5-Star Open Data** : 데이터의 공개성·구조화·개방 형식·URI 식별·외부 연결 수준을 설명하는 단계 모델

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **링크드 오픈 데이터 (Linked Open Data, LOD)는** 공개 데이터를 웹 식별자와 관계 링크로 연결해 발견·재사용할 수 있게 한 데이터 |
| 목적 | 공개 데이터의 식별·탐색·결합을 지원하는 웹 오브 데이터 형성 |

## Ⅱ. 링크드 오픈 데이터의 특징

| 특징 | 데이터의 모습 | 활용 의미 |
|---|---|---|
| 개방성 | 이용 조건을 밝힌 공개 데이터 | 재사용 가능 범위 확인 |
| 식별성 | 항목마다 조회 가능한 URI | 같은 대상을 안정적으로 참조 |
| 연결성 | 다른 데이터의 URI를 관계로 연결 | 기관·분야를 넘는 탐색 |

## Ⅲ. URI 조회·RDF 설명·외부 링크의 발견 체계

```text
기관A의 HTTP URI
     ↓ 조회 → RDF 설명: (기관A, 관할지역, 지역B)
                         │                     │
                         └─ 관계의 목적어 URI ─┘
                                      ↓ HTTP 조회
                            지역B의 RDF 설명·추가 링크
```

| 순서 | 원칙 | 구현 의미 |
|---|---|---|
| 1 | URI로 대상을 이름 붙임 | 동일 대상의 참조 지점 제공 |
| 2 | HTTP URI 사용 | 웹에서 식별자 조회 가능 |
| 3 | 조회 시 유용한 정보 제공 | RDF 등 표준 표현으로 대상 설명 |
| 4 | 다른 URI로 연결 | 관련 데이터로 탐색 범위 확장 |

## Ⅳ. RDF 트리플과 5-Star 공개 수준

RDF는 대상 간 관계를 주어·서술어·목적어의 트리플로 표현하며, 여러 트리플이 방향성 그래프를 구성.

| 트리플 요소 | 예시 | 역할 |
|---|---|---|
| 주어 | `기관A` URI | 설명할 대상 |
| 서술어 | `관할지역` URI | 대상 사이의 관계 |
| 목적어 | `지역B` URI | 관계의 대상 또는 값 |

RDF 그래프 질의에는 SPARQL을 사용할 수 있으며, 질의 서비스 제공 방식과 개방 범위는 데이터 제공자의 설계 선택.

### 5-Star Open Data 모델

| 등급 | 개방 수준 |
|---|---|
| ★ | 웹에 공개 라이선스로 공개 |
| ★★ | 구조화된 기계 판독 데이터 제공 |
| ★★★ | 비독점 개방 형식으로 제공 |
| ★★★★ | 데이터 항목을 URI로 식별 |
| ★★★★★ | 외부 데이터와 링크해 맥락 제공 |

별 등급은 공개 데이터의 배포 성숙도를 설명하는 단계 모델이며, 모든 LOD 구축이 특정 파일 형식이나 질의 엔드포인트를 필수로 요구한다는 뜻은 아님.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| URI·관계 모델을 정하지 않으면 데이터 간 의미 연결이 어려움 | 기존 어휘를 재사용하고 식별·관계 정의를 문서화 |
| 외부 데이터 링크는 잘못되거나 끊길 수 있음 | 링크의 출처·신뢰도·유효성을 운영 과정에서 점검 |
| 공개만으로 품질·적법성·재사용성이 보장되지 않음 | 라이선스, 개인정보, 최신성, 데이터 품질을 별도 검토 |

## Ⅵ. 제언

공공/엔터프라이즈 데이터 개방 시 단순 파일 제공(CSV)을 넘어 온톨로지 매핑과 글로벌 고유 URI를 부여하여 시맨틱 웹 생태계와의 상호운용성 확보.

### W3C 5-Star LOD 발전 단계 및 구조

```text
★☆☆☆☆ (1 Star) : 웹상에 공개 (포맷 무관, PDF/이미지)
★★☆☆☆ (2 Star) : 구조화된 기계 판독 포맷 (Excel 등)
★★★☆☆ (3 Star) : 비독점 오픈 포맷 (CSV, XML, JSON)
★★★★☆ (4 Star) : W3C 오픈 표준 URI 식별자 및 RDF 트리플(Triple) 적용
★★★★★ (5 Star) : 타 데이터셋과의 외부 링크(Linked Data) 연결 확립
```

### 선택 근거: 제언: 5-Star 링크드 데이터 (LOD)

| 구분 | 단순 공공데이터 개방 (CSV) | 제언: 5-Star 링크드 데이터 (LOD) |
|---|---|---|
| 의미적 연계 | 이질적 시스템 간 데이터 결합 곤란 | 온톨로지(OWL/RDFS) 기반 의미적 자동 통합 |
| 질의 유연성 | 파일 다운로드 후 개별 분석 | SPARQL 엔드포인트를 통한 글로벌 분산 질의 |
| 데이터 가치 | 단순 개별 정보 자산에 머뭄 | 지식 그래프(Knowledge Graph) 형성으로 부가가치 극대화 |
