- 본질: **웹상에 공개된 공공 및 민간 데이터를 단순히 다운로드하는 고립된 파일 형태를 넘어, 웹 표준 식별자(URI)와 자원 기술 프레임워크(RDF) 및 온톨로지(OWL)를 기반으로 데이터 개체 간의 의미적(Semantic) 관계를 글로벌하게 상호 연결(Link)하여 기계가 스스로 지식을 탐색·추론할 수 있도록 개방한 분산 지식 그래프(Web of Data)**
- 암기: `유-에-알-링` (LOD 4대 원칙: URI 식별자 부여, HTTP 프로토콜 사용, 표준 RDF/SPARQL 제공, 외부 링크 연결) / `오-구-비-유-링` (5-Star 모델: 웹오픈, 구조화, 비독점포맷, URI/RDF, 링크연결)
- 판단축:
  - **오픈 데이터(Open Data)**: 누구나 접근 가능한 무료 데이터 파일(주로 CSV, JSON 다운로드)이나 기관별 데이터 사일로(Silo) 잔존
  - **링크드 오픈 데이터(LOD)**: 개방 데이터에 W3C 시맨틱 웹 표준을 적용하여 글로벌 DBpedia, Wikidata 등과 상호 연결된 거대한 글로벌 지식 네트워크
- 주의: 모든 데이터를 처음부터 5성(RDF/OWL)으로 전면 구축하려 하면 온톨로지 구축 비용과 SPARQL 질의 지연으로 프로젝트가 좌초되기 쉬우므로, 3성(REST API/JSON)으로 신속히 개방한 뒤 핵심 공통 식별자(법정동코드, 사업자번호 등)를 중심으로 단계적 5성 전환을 추진해야 함

## 예상문제

> 차세대 웹 기술인 시맨틱 웹(Semantic Web)의 실현 기제인 링크드 오픈 데이터(Linked Open Data, LOD)의 개념과 팀 버너스 리(Tim Berners-Lee)의 4대 원칙을 설명하고, 데이터 개방의 5-Star 모델 및 LOD 구축 6단계 절차를 기술하시오. (25점)

## Ⅰ. 데이터 사일로를 극복하는 LOD(Linked Open Data) 개요

#### 한줄 요약: 웹 문서(Web of Documents)를 넘어 데이터 개체 간의 의미적 연결을 지향하는 웹 오브 데이터(Web of Data)의 구현체

- **추진 배경**:
  - 기존 웹은 인간이 눈으로 읽는 HTML 문서 중심이어서 기계(컴퓨터)가 문서 속 데이터의 의미와 문맥을 이해하고 자동 가공하기 어려움
  - 공공데이터 포털에서 제공하는 수만 종의 CSV 파일들은 서로 다른 명명 규칙과 고유 코드를 사용하여 기관 간 데이터 융합 및 지능형 검색이 불가능한 '데이터 섬(Silo)'을 형성함
- **LOD의 정의**:
  - W3C의 시맨틱 웹 기술 표준(URI, RDF, OWL, SPARQL)을 활용하여, 웹에 공개된 오픈 데이터를 서로 링크하고 연결함으로써 기계 판독성과 데이터 상호운용성을 극대화한 개방형 연결 데이터

## Ⅱ. 팀 버너스 리(Tim Berners-Lee)의 LOD 4대 구축 원칙

#### 한줄 요약: 고유 식별자 URI 부여, HTTP 프로토콜 접근, 표준 RDF 및 SPARQL 제공, 타 데이터와의 외부 링크 연결

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                       LOD 4대 구축 원칙 (W3C Design Issues)                 │
└─────────────────────────────────────────────────────────────────────────────┘
  1. 명명 (Name)   ──▶ 모든 사물(개체, 개념)의 식별자로 전역 고유한 URI를 부여함
  2. 접근 (Access) ──▶ 사람들이 참조하고 기계가 검색할 수 있도록 HTTP URI를 사용함
  3. 표현 (Format) ──▶ URI로 접근 시 RDF, SPARQL 등의 표준 시맨틱 포맷으로 유용한 정보 제공
  4. 연결 (Link)   ──▶ 웹상의 더 많은 지식을 발견할 수 있도록 타 기관의 외부 URI 링크를 포함
```

### 1. 4대 원칙 상세 분석
1. **URI(Uniform Resource Identifier) 사용**: 현실 세계의 모든 대상(사람, 장소, 개념, 상품)에 전역적으로 유일한 웹 식별자를 부여
2. **HTTP URI 채택**: 단순 식별에 그치지 않고 웹 브라우저나 HTTP 클라이언트를 통해 실제 네트워크 역참조(Dereferencing)가 가능해야 함
3. **표준 RDF 및 SPARQL 제공**: HTTP 요청 수신 시 기계가 해석 가능한 RDF(XML, Turtle, JSON-LD) 데이터와 질의 인터페이스(SPARQL Endpoint)를 반환
4. **외부 링크(Link) 포함**: 자신이 정의한 데이터에만 갇히지 않고, 외부 지식 베이스(DBpedia, Geonames 등)의 URI를 관계선으로 명시하여 글로벌 웹으로 확장

## Ⅲ. 데이터 개방 성숙도를 나타내는 5-Star Open Data 모델

#### 한줄 요약: 1성(웹 공개)부터 5성(외부 데이터와 의미적 연결)까지 데이터의 기계 판독성과 개방성을 평가하는 성숙도 체계

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                     5-Star Open Data 성숙도 단계                            │
└─────────────────────────────────────────────────────────────────────────────┘
  ★      : 오픈 라이선스로 웹에 공개 (형식 무관: PDF, 스캔 이미지, HWP)
  ★★     : 기계 판독 가능한 구조화 데이터로 제공 (독점 포맷: MS Excel .xls)
  ★★★    : 비독점적 개방형 포맷으로 제공 (예: CSV, XML, JSON)
  ★★★★   : W3C 표준 URI를 부여하고 RDF 포맷으로 제공하여 식별 가능
  ★★★★★  : 다른 조직의 데이터와 링크(owl:sameAs 등)를 연결하여 맥락 제공 (LOD 완성)
```

| 등급 | 핵심 요건 | 대표 파일 형식 | 장점 | 단점 및 한계 |
|:---:|:---|:---|:---|:---|
| **1성 (★)** | 웹상에 공개된 데이터 | PDF, JPG, HWP | 누구나 열람 가능 | 데이터 가공 및 기계 판독 불가 |
| **2성 (★★)** | 구조화된 기계 판독 데이터 | Excel (XLS, XLSX) | 스프레드시트 연산 가능 | 특정 상용 소프트웨어(MS Office) 종속 |
| **3성 (★★★)** | 비독점 개방형 포맷 | CSV, TSV, JSON | 오픈소스 도구로 자유롭게 파싱 | 데이터의 의미나 개체 간 연결성 부재 |
| **4성 (★★★★)**| URI 부여 및 RDF 표준 적용 | RDF/XML, Turtle, JSON-LD| 개체 식별 및 기계 의미 해석 가능 | 외부 데이터와 단절된 독자적 RDF |
| **5성 (★★★★★)**| 외부 데이터와 의미적 링크 연결 | LOD (DBpedia 연계 RDF) | **글로벌 지식 그래프 탐색 및 추론**| 구축 및 지속적 링크 유지보수 비용 |

## Ⅳ. LOD의 핵심 기술 스택 및 RDF 트리플 그래프 구조

#### 한줄 요약: 식별(URI), 표현(RDF), 의미체계(RDFS/OWL), 질의(SPARQL)로 이어지는 W3C 시맨틱 웹 기술 스택

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                        LOD 핵심 기술 스택 계층                              │
└─────────────────────────────────────────────────────────────────────────────┘
  [질의 계층]       SPARQL (그래프 패턴 매칭 기반 질의 언어)
       │
  [스키마/온톨로지]  RDFS (RDF Schema), OWL (Web Ontology Language)
       │
  [데이터 모델]     RDF (Resource Description Framework - 주어/서술어/목적어)
       │
  [식별자/문법]     URI / IRI, XML, JSON-LD, Turtle, N-Triples
```

### 1. RDF 트리플(Triple) 모델
- 모든 데이터와 지식을 **주어(Subject) - 서술어(Predicate) - 목적어(Object)**의 3요소 관계로 분해하여 방향성 그래프(Directed Graph)로 표현
- 예: `<http://data.kr/person/101>` (주어) $\rightarrow$ `<http://xmlns.com/foaf/0.1/knows>` (서술어) $\rightarrow$ `<http://data.kr/person/102>` (목적어)

### 2. 온톨로지(OWL)와 `owl:sameAs`
- 서로 다른 기관에서 각자의 URI로 정의한 동일 개체(예: 서울대학교)를 `owl:sameAs` 프로퍼티로 연결함으로써, 분산된 데이터베이스를 가상으로 하나처럼 통합 추론 가능

## Ⅴ. 일반 오픈 데이터 vs 링크드 오픈 데이터(LOD) 심층 비교

#### 한줄 요약: 단절된 파일 다운로드와 글로벌하게 연결된 지식 그래프 질의 간의 패러다임 차이

```text
┌───────────────────────────────────┬───────────────────────────────────┐
│       일반 오픈 데이터 (Open Data) │   링크드 오픈 데이터 (LOD)        │
├───────────────────────────────────┼───────────────────────────────────┤
│ - 형태: 독립된 파일 (CSV, JSON)   │ - 형태: 거대한 글로벌 그래프 (RDF)│
│ - 식별: 파일 내부 고유 ID (사일로)│ - 식별: 전역 유일한 HTTP URI      │
│ - 연계: 조인(Join) 위해 수작업 정제│ - 연계: 링크 따라가기(Follow-Your-│
│                                   │   Nose)로 실시간 분산 탐색        │
│ - 질의: 개별 파일 다운로드 후 RDB │ - 질의: 웹상에서 직접 SPARQL 질의 │
└───────────────────────────────────┴───────────────────────────────────┘
```

| 비교 항목 | 일반 오픈 데이터 (Open Data) | 링크드 오픈 데이터 (LOD) |
|:---|:---|:---|
| **데이터 구조** | 테이블(2차원 표), 트리(JSON), 텍스트 | **방향성 레이블 그래프 (RDF Graph)** |
| **데이터 결합 방식** | 다운로드 후 사후 ETL 및 수작업 매핑 | **웹 표준 링크(`owl:sameAs`)를 통한 자동 연계** |
| **의미 해석 주체** | 사람 (문서와 메타데이터 정의서 해독) | **컴퓨터 (온톨로지 기반 기계 자동 추론)** |
| **데이터 통합성** | 데이터 사일로 잔존 (교차 검색 곤란) | 전 세계 데이터가 연결된 **웹 오브 데이터(Web of Data)** |
| **구축 및 유지비용**| 낮음 (기존 RDB에서 CSV 추출만으로 가능)| 높음 (URI 체계 수립, 온톨로지 모델링, 트리플 변환) |

## Ⅵ. LOD 구축 6단계 절차 및 링크 파손(Link Rot) 대응

#### 한줄 요약: 대상 선정부터 URI 설계, 온톨로지 모델링, 트리플 변환, 링크 생성, 개방·검증으로 이어지는 단계적 절차

```text
 [1단계: 데이터 선정]  ──▶ 연계 가치와 개방 효과가 높은 마스터 데이터(인물, 기관, 지리) 선정
          │
 [2단계: URI 체계 설계]──▶ 영구적이고 직관적인 HTTP URI 명명 규칙 수립 (PURL 활용)
          │
 [3단계: 온톨로지 모델링]──▶ FOAF, Dublin Core, SKOS 등 검증된 표준 어휘(Vocabulary) 재사용
          │
 [4단계: RDF 변환]     ──▶ RDB 데이터를 R2RML 도구를 통해 RDF 트리플로 자동 변환(Triplification)
          │
 [5단계: 링크 생성]    ──▶ Silk, LIMES 도구를 활용해 DBpedia, 국립중앙도서관 등과 동일 개체 연결
          │
 [6단계: 서비스 개방]  ──▶ SPARQL Endpoint 구축 및 Virtuoso 트리플스토어 배포, 링크 주기적 감사
```

- **링크 파손(Link Rot) 및 댕글링 링크(Dangling Link) 방지책**:
  - 외부 연계 기관의 도메인 변경이나 삭제로 인해 시맨틱 링크가 깨지는 현상 방지
  - 도메인에 독립적인 **영구 식별자(PURL, Persistent URI)**를 채택하고, 월간 링크 유효성 검사 배치 스크립트를 수행하여 깨진 링크 자동 리포팅

## Ⅶ. 데이터 아키텍트 관점의 지식 그래프 및 생성형 AI(GraphRAG) 제언

#### 한줄 요약: 생성형 AI의 환각(Hallucination)을 제어하기 위해 LOD 기반 지식 그래프를 RAG 엔진에 융합

- **"LOD의 화려한 부활: GraphRAG"**:
  - 시맨틱 웹은 한때 온톨로지 구축의 높은 비용으로 정체기를 겪었으나, 최근 **LLM(거대언어모델)과 결합된 GraphRAG**를 통해 핵심 기술로 재조명받고 있음
  - 단순 벡터 유사도 검색(Vector RAG)은 복잡한 다단계 관계(Multi-hop reasoning)를 추론하지 못하지만, LOD 기반 지식 그래프를 결합하면 "A 기업의 자회사가 생산한 B 부품의 공급망 리스크"를 정확한 팩트 기반으로 검색 가능
- **현실적인 단계적 5-Star 전환 전략**:
  - 처음부터 모든 원시 데이터를 5성으로 올리려는 무모한 시도를 배제
  - 대외 서비스 API는 3성(REST JSON)으로 신속히 개방하고, 기관 간 핵심 교차 식별자(사업자번호, 도로명주소 등)에 대해서만 우선적으로 URI를 부여해 5성으로 진화시키는 **실용적 시맨틱 아키텍처**를 수립해야 함

## 2교시 25점 답안 발췌

```text
[문제 3] 시맨틱 웹의 핵심 기술인 LOD(Linked Open Data)와 5-Star 모델

Ⅰ. 웹 오브 데이터(Web of Data)를 지향하는 LOD의 개요
 1. 배경: 사일로화된 개방 데이터의 상호 단절 극복 및 기계 판독 가능한 지식 연결 필요
 2. 정의: W3C 시맨틱 웹 표준(URI, RDF, SPARQL)을 적용하여 데이터 간 의미적 링크를 구축한 개방 데이터

Ⅱ. 팀 버너스 리의 LOD 4대 원칙 및 5-Star 모델
 1. 4대 구축 원칙: URI 식별자 부여 -> HTTP URI 접근 -> RDF/SPARQL 표준 제공 -> 외부 링크 연결
 2. 5-Star 데이터 개방 성숙도 모델
 ┌──────┬───────────────────────────────┬────────────────────────────────┐
 │ 등급 │           핵심 요건           │         대표 사례 및 포맷      │
 ├──────┼───────────────────────────────┼────────────────────────────────┤
 │ 1성  │ 웹상에 공개된 데이터          │ PDF, 스캔 이미지, HWP          │
 │ 2성  │ 구조화된 기계 판독 가능 포맷  │ MS Excel (.xls, .xlsx)         │
 │ 3성  │ 비독점적 개방형 포맷          │ CSV, XML, JSON                 │
 │ 4성  │ URI 식별자 부여 및 RDF 표현   │ RDF/XML, Turtle, JSON-LD       │
 │ 5성  │ 타 기관 데이터와 의미적 링크  │ LOD 달성 (owl:sameAs 연계)     │
 └──────┴───────────────────────────────┴────────────────────────────────┘

Ⅲ. LOD 핵심 기술 스택 및 구축 6단계 절차
 1. 핵심 기술: URI(전역 식별) + RDF(주어-서술어-목적어 트리플) + OWL(온톨로지) + SPARQL(그래프 질의)
 2. 6단계 절차: 대상선정 -> URI설계 -> 온톨로지모델링 -> RDF변환 -> 외부링크생성(Silk) -> SPARQL개방

Ⅳ. 실무 아키텍처 제언: GraphRAG 연동 및 단계적 5성 추진
 1. 생성형 AI 결합: LLM의 환각을 방지하고 다단계 추론을 가능케 하는 지식 그래프(GraphRAG) 엔진 구축
 2. 단계적 추진: 전체 데이터 3성(JSON) 우선 개방 후 핵심 식별자 중심의 선별적 5성 LOD 전환
```
