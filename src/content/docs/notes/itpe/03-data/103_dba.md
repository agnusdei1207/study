## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터 관리 조직 → **DA vs DBA**

## 30초 인출

- 본질: DA(데이터 아키텍트)는 업무 데이터의 의미·구조·표준을 설계하고, DBA는 DBMS 구현과 운영(성능·보안·백업복구)을 맡는 역할
- 메커니즘: DA가 개념·논리 모델과 표준 정의를 만들면 DBA가 물리 모델·DDL·권한으로 구현하고, 변경은 두 역할이 공동 검토하며 운영 성능·보안·장애 증거를 모델 기준선에 환류
- 통찰: 논리 모델과 실제 스키마의 변경 경로가 분리되면 정의·제약이 어긋나고 물리 최적화가 데이터 의미를 깰 수 있으므로 모델·DDL·승인·배포를 한 변경 건으로 관리

<details>
<summary>핵심 용어</summary>

- **DA(Data Architect)** : 업무 데이터의 의미·구조·표준을 설계하는 역할
- **DBA(Database Administrator)** : DBMS의 구현·운영·성능·보안·복구를 담당하는 역할
- **논리·물리 모델** : DBMS와 독립적인 구조 / 특정 DBMS의 구현 구조
- **DDL** : 스키마를 정의하는 SQL 문장
- **형상관리** : 모델·DDL의 변경 이력과 배포를 관리하는 활동
- **책임분계** : 관리형 서비스에서 공급자와 이용자의 책임 경계

</details>

## 2~4교시 25점 답안

## Ⅰ. DA·DBA의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **DA** 는 데이터 구조·표준 설계, **DBA** 는 데이터베이스 구현·운영 역할 |
| 목적 | 업무 데이터의 의미·품질을 유지하며 안전하고 효율적으로 저장·이용 지원 |

## Ⅱ. 특징

| 특징 | DA | DBA |
|---|---|---|
| 주된 관점 | 업무 데이터의 의미·표준 | DBMS 구현·운영 |
| 변경 시점 | 논리 모델·업무 규칙 검토 | 물리 구조·성능·복구 영향 검토 |
| 공동 책임 | 정의가 저장 구조에 반영되는지 확인 | 운영 변경이 데이터 의미를 깨지 않는지 확인 |

## Ⅲ. 협업 체계

```text
업무 요구·용어·품질 규칙
   ↓ DA: 개념·논리 모델, 표준 정의
논리 모델 ── 대응 확인 ── DBA: 물리 모델·DDL·권한
   ↓ 공동 변경 검토          ↓ 배포·복구 시험
모델 기준선 ← 차이·영향 환류 ← 운영 성능·보안·장애 증거
```

## Ⅳ. 책임 비교와 환경 변화

| 관점 | DA | DBA |
|---|---|---|
| 데이터 의미 | 용어·정의·관계·표준 정리 | 구현이 의미·제약을 유지하는지 확인 |
| 구조 | 개념·논리 구조와 규칙 | DBMS별 저장·접근 구조, 제약 구현 |
| 운영 요구 | 품질·계보·변경 요구 전달 | 성능·용량·접근통제·백업복구 |
| 의사결정 | 업무 모델·표준 변경 협의 | 물리 구조·운영 변경의 위험 공유 |

| 변화 | 역할 조정 |
|---|---|
| 관리형 DB가 인프라 작업 일부 제공 | DBA 업무가 책임분계·설정·접근통제·비용·복구 검증으로 이동 |
| 스키마 변경이 코드 배포와 연결 | DA 표준과 DBA 운영 조건을 버전관리·자동 검사에 반영 |
| 플랫폼·제품별 기능 다양 | 직급이 아니라 조직·계약의 책임 경계를 문서화 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 논리 모델과 실제 스키마의 변경 경로가 분리 | 모델·DDL·승인·배포를 같은 변경 건으로 형상관리 |
| 물리 최적화가 데이터 의미·품질 규칙을 훼손 | DA의 업무 제약과 DBA의 성능·복구 결과를 함께 승인 |
| 관리형 DB 사용 후 접근·복구 책임 불명확 | 공급자 책임분계 확인, 권한·백업 복원 시험 책임자 지정 |

## Ⅵ. 제언

모델·DDL·승인·배포를 하나의 변경 건으로 묶어 DA와 DBA가 공동 승인하고 운영 증거를 모델에 환류

```text
변경 요청 → DA(의미·표준) + DBA(성능·복구) 공동 승인 → DDL 배포 → 운영 증거 환류
```

| 구분 | 역할 분리 운영 | 제언: 공동 승인 |
|---|---|---|
| 스키마 정합 | 불일치 | 단일 변경 건 |
| 최적화 | 의미 훼손 위험 | 함께 검토 |
