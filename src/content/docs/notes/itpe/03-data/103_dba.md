## 연관 키워드

**DBA(Database Administrator)**, **DA vs DBA**, **HA/DR**, **FinOps**, **Database-as-Code**, **최소 권한(PoLP)**, **TDE**

## Ⅰ. 개요

- 핵심 요약 : **DBA**는 데이터베이스 설계·구축·운영·성능·보안·백업복구를 총괄하는 전문 엔지니어.
- 목적 : 데이터 무결성·가용성·신뢰성 지속 보장.
- 배경 : 클라우드 자동화로 전통 운영 업무 축소 → 고부가가치 역할로 전환.
- 특징 : 4대 직무 영역, DA와 R&R 구분, 클라우드 시대 진화.

## Ⅱ. 특징 및 장점

- 핵심 요약 : **4대 직무**로 구축·성능·가용성·보안을 종합 관리.
- **구축 및 모델링** : DDL 배포, 표준화, 용량 산정.
- **성능 최적화** : Slow Query 튜닝, 인덱스, 버퍼 풀.
- **가용성 및 DR** : HA 이중화, 백업·복구, RPO/RTO.
- **보안 및 감사** : RBAC, TDE 암호화, 접근 로그.
- **클라우드 적응** : DBaaS 자동화에 따른 역할 고도화.

## Ⅲ. 직무 영역 흐름

- 핵심 요약 : **모델링 → 성능 → 가용성 → 보안** 4축 관리.
- DA와 R&R 분리 : DA는 논리·비즈니스, DBA는 물리·운영.

```text
[ DBA 4대 직무 영역 ]

[1. 구축·모델링] DDL, 표준화, 용량 산정
        |
        v
[2. 성능 최적화] Slow Query, 인덱스, 버퍼 풀
        |
        v
[3. 가용성·DR] HA 이중화, 백업, RPO/RTO
        |
        v
[4. 보안·감사] RBAC, TDE, 접근 로그
```

## Ⅳ. DA vs DBA 비교

- 핵심 요약 : **논리·비즈니스(DA)** vs **물리·운영(DBA)**.

| 항목 | DA (Data Architect) | DBA |
|---|---|---|
| 관점 | 논리·비즈니스 | 물리·기술 운영 |
| 산출물 | ERD, 표준 사전 | DDL, 백업 정책, 튜닝 보고 |
| 정규화 | 3NF/BCNF 지향 | 선별적 반정규화 |
| 협업 | 논리 모델 확정 후 인계 | 인계받은 모델 물리 구현 |

## Ⅴ. 한계와 방안

- 핵심 요약 : **클라우드 자동화·CI/CD 병목·다종 DBMS**를 역할 전환·자동화·표준화로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 클라우드 자동화 | DBaaS로 전통 운영 가치 급락 | DataOps·FinOps·성능 엔지니어링으로 전환 | 역할 전환율 |
| CI/CD 병목 | DDL 수동 승인으로 민첩성 저해 | Flyway/Liquibase, CI 파이프라인 자동 검증 | 배포 리드타임 |
| 다종 DBMS | NoSQL·벡터 DB 등 파편화 | 표준화 가이드, 통합 옵저버빌리티, CoE | 지원 DBMS 수 |

## Ⅵ. 기술사적 제언

- 핵심 요약 : **Database-as-Code·FinOps·자동화**로 클라우드 시대 DBA 진화.
- Database-as-Code : DDL/DML을 Git PR·CI/CD로 자동 승인·배포.
- FinOps : IOPS·vCPU·스토리지 분석 후 Right-sizing, 콜드 데이터 아카이빙.
- 최소 권한·TDE·접근 로그로 보안 강화.

## Ⅶ. 결론

- 핵심 요약 : DBA는 **클라우드 시대 고부가가치 역할**로 진화하며 DataOps·FinOps·보안이 핵심.
