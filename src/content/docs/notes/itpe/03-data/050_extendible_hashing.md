## 30초 인출

- 본질: 확장성 해싱은 해시값의 앞쪽 비트로 디렉터리를 찾아 버킷에 접근하고, 넘친 버킷만 나누어 데이터 증가에 대응하는 동적 해시 구조
- 메커니즘: 키의 해시값 d비트로 디렉터리 엔트리를 찾아 버킷을 탐색하고, 버킷이 넘치면 로컬 깊이 < 글로벌 깊이일 때 포인터만 재배정해 분할하고 같으면 디렉터리를 두 배로 확장한 뒤 분할
- 통찰: 전체 파일을 재구성하지 않고 넘친 버킷만 국소 분할하지만, 해시값이 한 버킷에 몰리면 분할을 반복해도 충돌이 풀리지 않고 디렉터리만 커지므로 해시 함수와 키 분포를 점검

<details>
<summary>핵심 용어</summary>

- **확장성 해싱(Extendible Hashing)** : 디렉터리와 깊이로 버킷을 동적으로 늘리는 해시 파일 구조
- **디렉터리(Directory)** : 해시 비트로 버킷 포인터를 찾는 배열
- **버킷(Bucket)** : 레코드를 저장하는 디스크 블록 단위
- **글로벌 깊이** : 디렉터리가 사용하는 해시 비트 수
- **로컬 깊이** : 개별 버킷이 사용하는 해시 비트 수
- **오버플로우** : 버킷 용량을 넘겨 레코드를 저장하지 못하는 상태
- **선형 해싱** : 디렉터리 없이 정해진 순서로 버킷을 늘리는 동적 해싱

</details>

## 2~4교시 25점 답안

## Ⅰ. 확장성 해싱의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **확장성 해싱** 은 해시 비트로 디렉터리를 거쳐 버킷을 찾고 넘친 버킷을 국소 분할하는 동적 해시 구조 |
| 목적 | 전체 파일 재구성 없이 데이터 증가에 대응 |

## Ⅱ. 특징

| 특징 | 의미 |
|---|---|
| 디렉터리 간접 참조 | 해시 비트로 엔트리를 찾고 엔트리가 버킷을 지시 |
| 국소 분할 | 오버플로우가 난 버킷부터 분할 |
| 깊이별 확장 | 로컬 깊이와 글로벌 깊이가 같을 때 디렉터리 두 배 확장 |

## Ⅲ. 구성요소와 충돌회피(오버플로우 분할)

| 구성요소 | 적용 범위 | 의미 |
|---|---|---|
| 디렉터리 | 전체 | 해시 비트로 버킷 포인터 관리 |
| 글로벌 깊이 d | 디렉터리 전체 | 디렉터리 엔트리 수(2^d)를 결정하는 비트 수 |
| 로컬 깊이 d' | 개별 버킷 | 버킷이 사용하는 비트 수 |
| 버킷 | 개별 | 레코드 저장 단위 |

```text
검색 키 → 해시값 d비트 → 디렉터리 엔트리 → 버킷 탐색
                                          ↓ 오버플로우
로컬 깊이 d' < d: 버킷 분할·포인터 재배정 (디렉터리 크기 유지)
로컬 깊이 d' = d: 디렉터리 두 배 확장 → 버킷 분할
```

분할은 추가 해시 비트 하나로 기존 레코드를 새 버킷과 나누는 방식이며, 같은 해시값의 키가 한 버킷에 계속 모이면 분할만으로 충돌이 풀리지 않음.

## Ⅳ. 선형 해싱과의 비교

| 비교축 | 확장성 해싱 | 선형 해싱 |
|---|---|---|
| 분할 기준 | 오버플로우가 난 버킷 | 분할 포인터가 가리키는 버킷 |
| 주소 관리 | 디렉터리와 깊이 | 분할 단계와 해시 함수, 디렉터리 불필요 |
| 확장 양상 | 글로벌 깊이 증가 시 디렉터리 두 배 | 정해진 순서로 버킷 추가 |
| 주요 고려 | 디렉터리 공간·분할 편향 | 분할 지연 중 오버플로우 체인 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 편향된 해시값으로 특정 버킷만 반복 분할 | 키 분포·충돌률로 해시 함수 적합성 확인 |
| 글로벌 깊이 증가로 디렉터리 급증 | 버킷·디렉터리 사용량을 함께 측정 |

## Ⅵ. 제언

키 분포가 고른 해시 함수를 선택하고, 디렉터리 크기와 버킷 충전율을 함께 모니터링

```text
키 분포 확인 → 해시 함수 선택 → 분할·디렉터리 확장 모니터링 → 편향 시 해시 재검토
```

| 구분 | 정적 해시 | 제언: 확장성 해싱 |
|---|---|---|
| 데이터 증가 | 전체 재구성 | 국소 분할 |
| 공간 | 예약 필요 | 디렉터리 추가 |
