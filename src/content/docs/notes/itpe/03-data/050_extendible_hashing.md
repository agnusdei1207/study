## 연관 키워드

- 확장성 해싱, 동적 해싱, 전역 깊이, 지역 깊이, 버킷 분할, 선형 해싱, CAS

## Ⅰ. 확장성 해싱의 개요

- 핵심 요약 : 디렉토리와 버킷을 동적으로 분할·병합해 해시 테이블 크기를 유연하게 확장하는 **확장성 해싱**.
- 개념 : 삽입과 삭제에 따라 디렉토리 구조와 버킷 수를 동적으로 조정해 해시 테이블 크기를 늘리거나 줄이는 **동적 해싱** 기법.
- 배경 및 필요성 :
  1. 정적 해싱의 고정 버킷 수로 인해 오버플로우 체이닝 탐색 비용이 급증.
  2. 데이터 규모가 변해도 디스크 입출력(I/O, Input/Output) 횟수를 일정하게 유지할 필요.
  3. 삽입·삭제 빈도가 높은 가변 데이터 환경의 성능 요구.
- 주요 목적 : 레코드 검색을 디스크 접근 최대 2회로 보장하고 오버플로우를 최소화.

## Ⅱ. 확장성 해싱의 특징 및 장점

- 핵심 요약 : 디렉토리 기반의 깊이 관리와 버킷 단위 분할·병합으로 검색 I/O를 최대 2회로 묶는 구조.

1. 디렉토리 기반 구조 : 해시값 접두사와 버킷을 잇는 디렉토리를 유지 → 주소 계산으로 버킷을 즉시 찾음.
2. **전역 깊이**와 **지역 깊이** : 디렉토리 크기를 정하는 비트 수와 버킷별 구분 비트 수를 분리 관리 → 분할 영향 범위를 버킷 단위로 한정.
3. **버킷 분할**·병합 : 오버플로우 시 버킷을 나누고 여유가 생기면 병합 → 크기를 데이터 양에 맞춰 조정.
4. 최대 2회 I/O 검색 : 디렉토리 접근 1회와 버킷 접근 1회로 검색 완료 → 검색 비용 예측 가능.
5. 디렉토리 지수 확장 : 전역 깊이가 1 증가할 때마다 디렉토리 엔트리 수가 2배로 늘어남 → 메모리 부담의 원인.

## Ⅲ. 확장성 해싱의 구조 (흐름)

- 핵심 요약 : 디렉토리가 해시 접두사를 버킷에 매핑하고, 버킷 오버플로우 시 지역 깊이와 전역 깊이의 비교로 분할 방식이 정해지는 구조.

```text
[확장성 해싱 구조 (전역 깊이 d=2)]
  디렉토리 00 → [버킷 A] (지역 깊이 2)
  디렉토리 01 → [버킷 B] (지역 깊이 2)
  디렉토리 10 → [버킷 C] (지역 깊이 1)
  디렉토리 11 → [버킷 C] (10·11 공동 참조)
```

```text
[버킷 분할 의사결정]
버킷 오버플로우 발생
          ↓
지역 깊이 < 전역 깊이 ?
  - 예 : 버킷만 2개로 분할 (지역 깊이 +1)
  - 아니오 : 디렉토리 2배 확장 후 버킷 분할
```

## Ⅳ. 확장성 해싱과 선형 해싱의 비교

- 핵심 요약 : 디렉토리 필요 여부와 확장 방식이 달라 메모리 오버헤드와 검색 I/O에서 차이가 나는 **선형 해싱**과 구분해야 함.

| 비교 항목 | 확장성 해싱 (Extendible Hashing) | 선형 해싱 (Linear Hashing) |
| --- | --- | --- |
| 디렉토리 필요 여부 | 필수 | 불필요 |
| 확장 방식 | 전역 깊이 증가 시 디렉토리 2배 급증 | 버킷을 순차적으로 하나씩 점진 확장 |
| 오버플로우 처리 | 버킷 분할로 해결 | 임시 오버플로우 페이지 연결 후 분할 |
| 메모리 오버헤드 | 디렉토리 확장 시 부담 가능 | 매우 적음 |
| 검색 I/O | 디렉토리 + 버킷 2회 | 디렉토리 없이 1~2회 |

## Ⅴ. 확장성 해싱의 한계와 방안

- 핵심 요약 : 검색 I/O 최소화와 동적 확장의 장점 이면에 디렉토리 폭증, 이중 I/O, 동시성 락 경합이라는 한계.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 디렉토리 지수 폭증 | 해시 충돌이 특정 버킷에 몰리면 지역·전역 깊이가 함께 커져 디렉토리 엔트리가 2^d로 증가 | 균등 분산 해시 함수 채택, 필요 시 디렉토리가 없는 선형 해싱 전환 검토 | 디렉토리 크기, 버킷 분포 편차 |
| 디렉토리 이중 I/O | 디렉토리가 메모리를 넘어 디스크에 있으면 디렉토리 참조와 버킷 접근 두 번의 I/O 발생 | 디렉토리 계층 압축, 버퍼 풀에 디렉토리 페이지 고정(Pin) | 디렉토리 캐시 적중률 |
| 동시성 디렉토리 락 경합 | 디렉토리 재할당과 포인터 갱신 중 배타적 쓰기 락으로 처리량 급감 | **CAS** (Compare-And-Swap) 기반 원자적 포인터 교체, 버킷 단위 래치 분리 | 락 대기 시간 |

## Ⅵ. 확장성 해싱에 대한 기술사적 제언

- 핵심 요약 : 디렉토리의 메모리 상주, 해시 키 분포의 균등화, 동시성 제어의 세분화로 운영 안정성을 확보하는 방식.
- 2회 I/O의 장점을 유지하려면 디렉토리를 RAM(Random-Access Memory)에 상주시켜 관리하는 것이 바람직하다.
- 해시 함수가 특정 비트 접두사에 편향되면 디렉토리만 비대해지므로, 균등 분포를 보이는 해시 함수를 적용해야 한다.
- 디렉토리 전체를 잠그는 대신 버킷 단위 래치와 원자적 포인터 교환을 병행 도입해 동시 처리량을 지킨다.

## Ⅶ. 결론

- 핵심 요약 : 확장성 해싱은 디렉토리 관리와 깊이 제어가 성패를 좌우하는 동적 해싱 기법.
- 시사점 : 해시 함수의 균등성, 디렉토리 메모리 관리, 동시성 제어의 균형 설계가 함께 이뤄져야 함.
