## 연관 키워드

- 확장성 해싱

## Ⅰ. 확장성 해싱의 개요

- 핵심 요약 : 디렉토리와 버킷의 동적 분할·병합으로 해시 테이블 크기를 유연하게 확장하는 동적 해싱 기법.
- 개념 : 대용량 데이터베이스 파일에서 데이터의 삽입과 삭제에 따라 디렉토리 구조와 버킷 수를 동적으로 분할·병합함으로써 해시 테이블의 크기를 유연하게 확장하는 동적 해싱(Dynamic Hashing) 기법.
- 배경 및 필요성 :
  1. 정적 해싱의 고정 버킷 수에 따른 오버플로우 체이닝 탐색 비용 급증.
  2. 데이터 규모 변화에 따른 디스크 I/O 횟수의 일정 유지 필요.
  3. 삽입·삭제 빈도가 높은 가변 데이터 환경의 성능 요구.
- 주요 목적 : 최대 2회 디스크 접근($O(1)$)으로 레코드 검색 보장과 오버플로우 최소화.

## Ⅱ. 확장성 해싱의 특징

- 핵심 요약 : 디렉토리 기반의 전역·지역 깊이 관리, 버킷 단위 분할·병합, 최대 2회 I/O의 검색 보장.

1. 디렉토리 기반 구조 : 해시값 접두사와 버킷을 연결하는 디렉토리의 유지.
2. 전역 깊이와 지역 깊이 : 디렉토리 크기 결정 비트 수와 버킷별 구분 비트 수의 분리.
3. 버킷 단위 분할·병합 : 오버플로우 시 버킷 분할, 공간 여유 시 병합으로 크기 유동 관리.
4. 최대 2회 I/O 검색 : 디렉토리 1회 + 버킷 1회의 디스크 접근으로 검색 완료.
5. 디렉토리 지수 확장 : 전역 깊이 증가 시 디렉토리 엔트리가 2배로 증가.

## Ⅲ. 확장성 해싱의 구조 (흐름)

- 핵심 요약 : 디렉토리-버킷 매핑 구조와 버킷 분할 의사결정 흐름.

```text
[ 확장성 해싱 구조 (전역 깊이 d=2) ]
디렉토리(접두사)      버킷
  00  ----------> [Bucket A] 지역 깊이 d'=2
  01  ----------> [Bucket B] 지역 깊이 d'=2
  10  ----+
          +-----> [Bucket C] 지역 깊이 d'=1
  11  ----+       (10, 11 두 엔트리가 공동 참조)
```

```text
[ 버킷 분할 의사결정 ]
버킷 오버플로우 발생
  ├─ d' < d  → 디렉토리 확장 불필요
  │            → 버킷만 2개로 분할, d' = d' + 1
  └─ d' = d  → 디렉토리 크기 2배 확장 (d = d + 1)
               → 디렉토리 엔트리 2^d → 2^(d+1) 증가
               → 버킷 분할 후 d' + 1 및 포인터 재설정
```

## Ⅳ. 확장성 해싱과 선형 해싱의 비교

- 핵심 요약 : 디렉토리 필요 여부, 확장 방식, 오버플로우 처리, 메모리 오버헤드의 차이.

| 비교 항목 | 확장성 해싱(Extendible Hashing) | 선형 해싱(Linear Hashing) |
| :--- | :--- | :--- |
| 디렉토리 필요 여부 | 필수 | 불필요 |
| 확장 방식 | 전역 깊이 증가 시 디렉토리 2배 급증 | 버킷을 순차적으로 1개씩 점진 확장 |
| 오버플로우 처리 | 버킷 분할로 해결 | 임시 오버플로우 페이지 연결 후 분할 |
| 메모리 오버헤드 | 디렉토리 확장 시 부담 가능 | 극히 적음 |
| 검색 I/O | 디렉토리 + 버킷 2회 | 디렉토리 없이 1회~2회 |

## Ⅴ. 확장성 해싱의 장점과 한계

- 핵심 요약 : 검색 I/O 최소화와 동적 확장의 장점, 디렉토리 폭증과 이중 I/O·락 경합의 한계.

- 장점
  1. 최대 2회 디스크 접근으로 검색 성능 보장.
  2. 오버플로우 체이닝 최소화.
  3. 데이터 증감에 따른 유연한 크기 확장.

- 한계점 1 : 전역 깊이 증가에 따른 디렉토리 지수 폭증
  - 한계점 : 해시 충돌이 특정 버킷에 집중되면 지역 깊이가 증가하고 전역 깊이도 증가하여 디렉토리 엔트리가 $2^d$ 로 폭증.
  - 해결 방안 : 균등 분산 해시 함수 채택, 디렉토리 불필요 구조의 선형 해싱으로의 전환 검토.
- 한계점 2 : 디렉토리 이중 디스크 I/O 오버헤드
  - 한계점 : 디렉토리가 메모리를 초과해 디스크에 저장되면 레코드 1건 조회에 디렉토리 참조와 버킷 접근의 2회 I/O 발생.
  - 해결 방안 : 디렉토리 계층 압축과 인메모리 버퍼 풀 핀(Pin) 고정, 다단계 페이징 디렉토리 설계.
- 한계점 3 : 동시성 환경의 디렉토리 분할 락 경합
  - 한계점 : 디렉토리 배열 재할당·포인터 갱신 중 배타적 쓰기 락으로 동시 처리량 급감.
  - 해결 방안 : 락 프리 원자적 포인터 교체(CAS, Compare-And-Swap), 버킷 레벨 래치 분리.

## Ⅵ. 확장성 해싱에 대한 기술사적 제언

- 핵심 요약 : 디렉토리 메모리 상주화, 해시 키 스큐 방지, 동시성 제어 세분화.
- 디렉토리 메모리 상주화 : 2회 I/O 장점 유지를 위해 디렉토리의 인메모리(RAM, Random-Access Memory) 상주 관리.
- 해시 키 스큐 방지 : 비트 분포 불균일 시 특정 접두사 편향으로 디렉토리만 폭발하므로 균등 분포 해시 함수 적용.
- 동시성 제어 세분화 : 디렉토리 전체 락 대신 버킷 단위 래치와 원자적 포인터 교환의 병행 도입.

## Ⅶ. 결론

- 핵심 요약 : 확장성 해싱은 디렉토리 관리와 깊이 제어가 성패를 좌우하는 동적 해싱 기법.
- 요약 : 전역·지역 깊이와 버킷 분할 알고리즘, 최대 2회 I/O 검색 구조.
- 시사점 : 해시 함수의 균등성과 디렉토리 메모리 관리, 동시성 제어의 균형 설계 필요.
