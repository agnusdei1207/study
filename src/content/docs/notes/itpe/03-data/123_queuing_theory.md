## 지식 로드맵 내 현재 위치

데이터베이스 → 통계·데이터 분석 → 대기행렬이론

## 30초 인출

- 본질: **대기행렬이론은 요청의 도착과 서비스 과정에서 생기는 대기 현상을 확률 모형으로 분석하는 이론**
- 메커니즘: 도착률·서비스율·서버 수·대기 규칙을 정해 시스템 내 개체 수와 체류시간을 추정
- 통찰: IT 시스템의 응답 지연과 자원 병목을 수리적으로 모델링하기 위해 포아송 도착과 지수 서비스 시간을 가정한 켄달 표기법(M/M/c) 기반 성능 분석 필수

<details><summary>핵심 용어</summary>

- **대기행렬이론 (Queueing Theory)** : 도착하는 개체와 서비스 시설 사이의 대기 현상을 분석하는 확률 모형 체계
- **켄달 표기법 (Kendall's Notation)** : 도착 분포·서비스 분포·서버 수·용량·모집단·서비스 규율로 대기 모형을 표현하는 표기
- **리틀의 법칙 (Little's Law)** : 안정된 시스템의 평균 개체 수와 유효 도착률·평균 체류시간 사이의 관계 $L=\lambda W$
- **이용률 $\rho$** : 서버가 바쁜 시간 비율을 나타내는 모형별 부하 지표

</details>

## 2~4교시 25점 답안

## Ⅰ. 대기행렬이론의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **대기행렬이론** 은 요청의 도착·대기·서비스를 확률 모형으로 분석하는 이론 |
| 목적 | 서비스 지연과 시스템 부하를 추정해 운영·용량 결정을 지원 |

## Ⅱ. 대기행렬이론의 특징

| 특징 | 용량 분석 의미 |
|---|---|
| 확률적 유입·처리 | 같은 평균 도착률도 변동성에 따라 대기 길이와 지연이 달라짐 |
| 이용률과 지연의 비선형 관계 | 처리 능력에 유입률이 가까워질수록 일부 모형의 대기가 급증 |
| 장기 평균과 피크의 구분 | 평균 관계식은 버스트·긴 꼬리 지연을 단독으로 설명하지 못함 |

## Ⅲ. 도착·대기·서비스 체계와 용량 검증 프로세스

```text
요청 도착(도착 간격 A, 유효 도착률 λ)
       ↓
대기열(규율 Z, 최대 수용량 K) → 서버 c개(서비스시간 S) → 완료·이탈
       ↓                              ↓
큐 길이·대기시간 관측             처리율·이용률 관측
       └──────── 지연 목표와 비교해 용량·규율 조정 ────────┘
```

### 유효 도착률과 체류시간의 평균 관계

```text
실제 유입 → 수용·완료된 요청의 유효 도착률 λ_eff
                         × 평균 체류시간 W
                         ↓
              평균 시스템 내 요청 수 L
                    L = λ_eff W
```

유한 버퍼에서 거절된 요청을 유효 도착률에 혼용 배제. 서버 용량 후보는 실제 도착·서비스 분포와 피크 조건을 부하 시험에 넣어 지연·큐 길이와 대조 검증.

## Ⅳ. 켄달 표기와 대표 대기 모형의 비교

| 표기·모형 | 의미·전제 | 해석 대상 |
|---|---|---|
| $A/S/c/K/N/Z$ | 도착 간격·서비스시간 분포, 서버 수, 수용량, 모집단, 서비스 규율 | 실제 시스템을 어떤 가정으로 단순화했는지 |
| M/M/1 | 지수 도착 간격·서비스시간, 단일 서버; $\rho=\lambda/\mu<1$ | 정상상태에서 $L=\rho/(1-\rho)$, $W=L/\lambda$ |
| M/G/1 | 지수 도착 간격, 일반 서비스시간 분포, 단일 서버 | 서비스시간 변동성이 대기에 미치는 영향 |

리틀의 법칙은 M/M/1에만 적용하는 공식이 아니라 적절한 안정·평균 조건에서 성립하는 장기 평균 관계임. $M$은 Markovian 가정에 따른 지수 간격·시간 의미.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 평균 트래픽만으로 피크·버스트 지연을 놓침 | 실제 도착·서비스 분포로 부하 시험하고 지연·큐 길이 목표와 대조 |
| 불안정한 유입을 정상상태 공식에 대입 | 유입률·처리율·거절률 추세를 확인해 안정 조건을 먼저 검증 |
| 수용량 제한으로 거절된 요청을 처리율에 포함 | 수용·완료된 유효 도착률과 거절률을 분리해 관계식과 서비스 목표 평가 |

## Ⅵ. 제언

서버 이용률(ρ = λ/μ)이 1에 가까워질수록 대기시간이 기하급수적으로 폭증하므로 시스템 안정 가동을 위해 자원 임계치를 70~80% 수준으로 통제.

### M/M/1 단일 서버 대기행렬 시스템 구조

```text
[고객/요청 도착] (도착률 λ, 포아송 과정)
         │
         ▼
┌──────────────────┐           ┌──────────────────┐
│  대기 큐 (Queue) │ ────────► │ 서비스 창구 (서버)│ ──► [서비스 완료 퇴장]
│ (선입선출: FIFO) │           │ (서비스율 μ)     │
└──────────────────┘           └──────────────────┘
[대기 시스템 내 평균 고객 수 L = λ / (μ - λ), 이용률 ρ = λ / μ]
```

### 선택 근거: 제언: 이용률 90% 임계 시스템

| 구분 | 이용률 50% 시스템 | 제언: 이용률 90% 임계 시스템 |
|---|---|---|
| 평균 대기시간 | 대기 지연 거의 없이 즉각 처리 | 이용률 1에 근접 시 대기시간 무한대 발산 |
| 버퍼 큐 적체 | 큐 공백 유지 (메모리 안정) | 스파이크 트래픽 시 큐 오버플로우/OOM 위험 |
| 자원 운영 전략 | 자원 낭비 가능성 존재 | 오토스케일링 연동하여 이용률 70% 탄력적 유지 |
