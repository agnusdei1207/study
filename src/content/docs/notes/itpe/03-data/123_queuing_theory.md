```text
 ┃
 ┣━ Ⅰ 개요 ───── 서비스 요청의 도착 과정, 대기열(Queue), 서버의 처리 용량을 수학적 확률 모형으로 분석하여 시스템의 성능과 지연시간을 예측하는 통계 이론
 ┣━ Ⅱ 특징 ───── 켄달 표기법(A/B/c/K/m/Z) 분류 · 이용률($\rho = \lambda / c\mu$)과 대기시간의 비선형 폭증 관계 · 리틀의 법칙($L = \lambda W$) 성립
 ┣━ Ⅲ 구조 ───── 고객 도착 과정(포아송 $\lambda$) / 서비스 시간 분포(지수분포 $\mu$) / 서버 수($c$) / 큐 용량($K$) / 서비스 규율(FIFO, LIFO, Priority)
 ┣━ Ⅳ 흐름 ───── ① 도착률($\lambda$) 및 서비스율($\mu$) 측정 → ② 시스템 이용률($\rho$) 산출 → ③ 안정 상태($\rho < 1$) 여부 검증 → ④ 평균 대기시간($W_q$) 및 큐 길이($L_q$) 계산 → ⑤ 서버 스케일아웃 판단
 ┣━ Ⅴ 비교 ───── M/M/1 vs M/M/c vs M/G/1 (단일 서버 지수형 vs 다중 병렬 서버 vs 일반 서비스 시간 분포)
 ┗━ Ⅵ 실무 ───── 시스템 이용률이 90%를 초과할 때 대기시간이 지수함수적으로 폭발하여 전체 API 타임아웃 장애 유발
```

## 한 줄 본질
- 불규칙한 서비스 요청 유입과 제한된 서버 처리 능력으로 인한 대기 지연 불가피 → 고객 도착률($\lambda$)과 처리율($\mu$)을 포아송/지수 모델로 수식화하여 평균 대기시간을 계산 → 적정 서버 용량(Sizing) 산정 / 이용률 100% 근접 시 대기 큐 무한대 발산

## 핵심 그림
```text

  (포아송 도착: λ)        (용량 K, 규율 Z)             (서비스율 μ, 서버 수 c)

     고객 도착                                         서버 1
       ───►          ┌───┬───┬───┬───┐               ┌───────┐
       ───►          │ 4 │ 3 │ 2 │ 1 │ ─────────────►│   μ   │───► 처리 완료
       ───►          └───┴───┴───┴───┘               └───────┘

                                                     ┌───────┐
                                       ─────────────►│   μ   │───► 처리 완료

    - B: 서비스 시간 분포 (M: 지수분포, D, G)
    - c: 병렬 서버 수 (1, 2, ...)
    - K: 시스템 최대 수용 용량 (생략 시 무한대)
    - m: 모집단 크기 (생략 시 무한대)
    - Z: 대기열 서비스 규율 (FIFO, LIFO, PRI)
```

## 핵심 용어
- 리틀의 법칙(Little's Law): 안정된 대기행렬 시스템에서 평균 시스템 체류 고객 수($L$)는 고객의 평균 도착률($\lambda$)에 고객이 시스템에 머무는 평균 시간($W$)을 곱한 것과 같다는 정리 ($L = \lambda W$)
- 시스템 이용률(Server Utilization, $\rho$): 단일 서버($c=1$)에서 서버가 쉬지 않고 일하는 시간의 비율 ($\rho = \frac{\lambda}{\mu}$), 다중 서버에서는 $\rho = \frac{\lambda}{c\mu}$

## 핵심 통찰
- 시스템 이용률($\rho$)이 70%에서 90%로 20%p 올라갈 때, 대기시간($W_q = \frac{\rho}{\mu(1-\rho)}$)은 2배가 아니라 '3배~5배'로 폭증함 → 분모에 $(1-\rho)$가 있어 이용률이 1에 다가갈수록 대기시간이 수직 상승
- 엔지니어링 관점에서 서버 CPU를 90% 이상 쓰도록 설계하는 것은 비용 절감이 아니라 '장애를 예약하는 행위'임 → 트래픽의 작은 출렁임 하나만 들어와도 큐가 수직으로 쌓여 전면 타임아웃 붕괴 발생
- M/M/1 단일 서버의 큐 길이는 $L_q = \frac{\rho^2}{1-\rho}$로 계산되므로, 웹 서버의 스레드 풀이나 커넥션 풀 크기를 산정할 때 직관이 아닌 대기행렬 수식을 대입해야 정확한 메모리 한도 설정 가능

## 이웃 토픽과 구분
- 대기행렬이론 vs 시뮬레이션: 대기행렬이론 = 포아송/지수분포 가정을 바탕으로 수학 공식(Closed-form)을 통해 평균 대기시간을 즉시 도출 / 시뮬레이션 = 분포가 너무 복잡하거나 네트워크 큐가 얽혀 수학식 유도가 불가능할 때 컴퓨터로 난수를 발생시켜(Monte Carlo) 수치적으로 추정

## 내 의견
