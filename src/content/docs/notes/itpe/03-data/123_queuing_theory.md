## Ⅰ. 시스템 병목 및 용량 산정의 수학적 기초, 대기행렬이론 개요

### 가. 대기행렬이론(Queuing Theory)의 정의
- 서버나 서비스 창구에 고객(또는 트랜잭션, 패킷)이 도착하여 대기열(Queue)을 형성하고 서비스를 받은 후 떠나는 일련의 대기 현상을 확률 모델로 수학적으로 분석하여, 시스템의 평균 대기 시간, 대기열 길이, 자원 가동률을 예측하는 운영 연구(Operations Research) 및 성능 공학 기법.
- IT 시스템의 웹 서버 커넥션 풀 크기, 메시지 큐 용량 산정, 네트워크 라우터 버퍼 설계의 이론적 토대.

## Ⅱ. 켄달 표기법(Kendall's Notation)과 시스템 구성 요소

### 가. 켄달의 $A / S / c / K / N / D$ 표기 체계

```text
[ 켄달(Kendall) 표준 표기법 구조 ]
      A  /  S  /  c  /  K  /  N  /  D
      |     |     |     |     |     |
      |     |     |     |     |     +---> 대기열 서비스 정책 (FCFS, LCFS, RR)
      |     |     |     |     +---------> 모집단 크기 (무한 or 유한)
      |     |     |     +---------------> 시스템 총 수용 한계 용량 (Queue + Server)
      |     |     +---------------------> 병렬 서비스 채널(서버) 수
      |     +---------------------------> 서비스 시간 분포 (M: 지수분포, D: 결정론, G: 일반분포)
      +---------------------------------> 고객 도착 간격 분포 (M: 마르코프/포아송, D, G)
```

### 나. 가장 기본적이고 널리 쓰이는 $M/M/1$ 대기 모형
- **도착 분포 ($A=M$)** : 평균 도착률 $\lambda$(단위 시간당 도착 고객 수)를 갖는 포아송 과정(도착 간격은 지수분포).
- **서비스 분포 ($S=M$)** : 평균 서비스율 $\mu$(단위 시간당 처리 고객 수)를 갖는 지수분포.
- **서버 수 ($c=1$)** : 단 1개의 처리 서버 존재.

## Ⅲ. 리틀의 법칙(Little's Law)과 M/M/1 모형의 수학적 성능 척도

### 가. 대기행렬의 절대 법칙: 리틀의 법칙 (Little's Law)
$$L = \lambda W$$
- 시스템 내 평균 고객 수($L$)는 고객의 평균 도착률($\lambda$)과 고객이 시스템에 머무는 평균 체류 시간($W$)의 곱과 정확히 일치함 (분포 형태와 무관하게 항상 성립).

### 나. $M/M/1$ 시스템의 4대 핵심 성능 척도 공식

| 성능 지표 | 기호 | 수학적 계산 산식 | 비즈니스/시스템적 의미 |
| :--- | :--- | :--- | :--- |
| **서버 이용률 (Utilization)** | $\rho$ | $\rho = \frac{\lambda}{\mu}$ (단, 정상 상태 조건 $\rho < 1$) | 서버가 쉬지 않고 일하고 있는 시간의 비율 (트래픽 부하) |
| **시스템 내 평균 체류 시간** | $W$ | $W = \frac{1}{\mu - \lambda} = \frac{1}{\mu (1 - \rho)}$ | 대기 시간 + 실제 서비스 처리 시간을 합친 전체 응답 시간 |
| **큐 대기 시간 (Wait Time)** | $W_q$ | $W_q = \frac{\lambda}{\mu (\mu - \lambda)} = \frac{\rho}{\mu (1 - \rho)}$ | 순수하게 앞사람의 처리를 기다리는 대기 지연 시간 |
| **시스템 내 평균 고객(패킷) 수** | $L$ | $L = \frac{\lambda}{\mu - \lambda} = \frac{\rho}{1 - \rho}$ | 서버에서 처리 중인 고객을 포함하여 시스템 내 존재하는 총 개수 |

### 다. 부하율($\rho$)에 따른 응답 지연의 폭발적 비선형 증가

```text
[ 부하율 
ho와 평균 체류 시간 W의 관계 ]
  체류 시간 W
   ^                                   |
   |                                   |  <-- 
ho가 1에 근접하면 대기 시간이
   |                                 **|      무한대(infty)로 수직 발산!
   |                             ****  |
   |                       ******      |
   |           ************            |
   +-----------------------------------+-----> 서버 이용률 
ho (lambda / mu)
   0.0        0.5         0.7   0.8   0.9  1.0
```

- 이용률 $\rho$가 70%를 넘어서면 대기 시간이 기하급수적으로 폭증하기 시작하며, 90% 이상에서는 시스템이 사실상 마비 상태에 이름.

## Ⅳ. 대기행렬이론(Queuing Theory)의 주요 한계점 및 해결 방안

- **포아송 도착(Poisson Arrival) 및 지수 서비스 시간 가정의 비현실성** :
  - **한계점** : 실제 IT 시스템 및 네트워크 트래픽은 버스트(Burst) 특성과 헤비테일(Self-similar / Pareto) 분포를 띠므로 $M/M/1$ 모형 적용 시 대기 시간 과소 추정.
  - **해결 방안** : 일반화된 분포를 수용하는 $G/G/1$ 또는 $M/G/1$ 모형(Pollaczek-Khinchine 공식) 적용, 이산 사건 시뮬레이션(DES: Discrete Event Simulation) 도구 병행.
- **시스템 활용률($\rho \to 1$) 근접 시 대기열 길이와 지연 시간의 기하급수적 발산** :
  - **한계점** : 자원 효율화를 위해 CPU나 서버 사용률을 90% 이상으로 유지하려 할 경우 리틀의 법칙에 의해 대기 시간이 무한대로 급증하여 서비스 장애(SLA 위반) 초래.
  - **해결 방안** : 목표 활용률을 통상 70~80% 선으로 캡핑(Knee of Curve 제어), 오토스케일링 트리거를 선제적(Predictive Autoscaling)으로 설정하여 버퍼 용량 확보.
- **다계층 마이크로서비스(MSA) 및 복합 큐 네트워크(Queuing Network) 모델링 난제** :
  - **한계점** : 프런트엔드-API 게이트웨이-MSA-DB로 이어지는 다단계 종속 서비스 환경에서는 단일 대기행렬 수식으로 병목 지점 및 연쇄 지연 예측 불가.
  - **해결 방안** : 잭슨 네트워크(Jackson Network) 이론 적용, eBPF 및 APM 분산 추적 데이터를 기반으로 실시간 대기행렬 지표(큐 깊이, 서비스 레이턴시)를 자동 모델링하는 AIOps 연계.

## Ⅴ. 클라우드 인프라 및 소프트웨어 아키텍처 실무 제언

- **서버 적정 이용률(Target Utilization) 70% 룰** : 비용 절감을 위해 서버 CPU/메모리 이용률을 90% 이상으로 유지하려는 시도는 대기행렬이론상 아주 미세한 트래픽 유입에도 큐가 폭발하여 전체 장애를 초래함. 따라서 오토스케일링(Auto-scaling) 임계치는 반드시 **$\rho \approx 70\%$ 수준에서 스케일아웃이 트리거** 되도록 설계해야 함.
- **백프레셔(Backpressure)와 서킷 브레이커 결합** : 메시지 큐(Kafka, RabbitMQ)의 소비율($\mu$)보다 인입률($\lambda$)이 장시간 높은 비정상 상황에서는 컨슈머 메모리 고갈을 막기 위해 상류 시스템의 전송 속도를 늦추는 리액티브 스트림 백프레셔(Backpressure) 메커니즘을 필수 탑재할 것을 제언함.
