## Ⅰ. 이벤트 로그 기반 비즈니스 프로세스 가시화, 프로세스 마이닝 개요

### 가. 프로세스 마이닝(Process Mining)의 정의
- **프로세스 마이닝** : ERP, CRM, 그룹웨어 등 정보시스템의 이벤트 로그(Event Log)로부터 실제 수행된 업무 프로세스 흐름을 알고리즘을 통해 자동으로 추출·시각화하고, 원래 설계된 표준 모델과의 일치 여부를 적합도(Conformance) 검사하며, 병목 구간을 진단하여 프로세스를 개선하는 데이터 과학 기법.
- 인터뷰와 설문조사에 의존하던 전통적 업무 혁신(PI/BPR)의 주관성과 왜곡을 극복하고, 객관적 디지털 발자국에 기반한 사실 기반 프로세스 분석을 제공함.

## Ⅱ. 프로세스 마이닝의 3대 핵심 유형 및 이벤트 로그 요건

### 가. 3대 분석 유형

```text
[ 프로세스 마이닝 3대 유형 구조도 ]
+---------------------+---------------------+---------------------+
| 1. 발견 (Discovery) | 2. 적합성 검사      | 3. 향상 (Enhancement)|
|                     |    (Conformance)    |                      |
+---------------------+---------------------+---------------------+
| 사전 모델 없이      | 기 구축 표준 모델과 | 실제 로그를 바탕으로|
| 이벤트 로그만으로   | 실제 로그 간의      | 기존 프로세스 모델을|
| 실제 프로세스 모델  | 불일치/위반/우회    | 병목 제거 및 최적화 |
| 자동 시각화 도출    | 프로세스 탐지       | 재설계/자동화(RPA)  |
+---------------------+---------------------+---------------------+
```

### 나. 이벤트 로그의 3대 필수 속성 (C-A-T)

```text
[ 프로세스 마이닝 최소 필수 로그 구조 ]
Case ID (사례 식별자) | Activity (수행 활동) | Timestamp (수행 시각) | (Optional: 자원/비용)
----------------------+----------------------+-----------------------+-----------------------
Order #1001           | 주문 접수            | 2026-03-30 09:00:00   | 홍길동
Order #1001           | 결제 승인            | 2026-03-30 09:05:00   | PG 시스템
Order #1001           | 배송 준비            | 2026-03-30 11:00:00   | 물류센터
Order #1002           | 주문 접수            | 2026-03-30 09:10:00   | 이몽룡
```

## Ⅲ. 프로세스 발견 핵심 알고리즘 및 척도

### 가. 대표 발견 알고리즘 비교
- **알파 알고리즘 (Alpha Miner)** : 이벤트 로그 내 활동 간의 선후 인과 관계($a \rightarrow b$, $a \parallel b$)를 수학적 페트리 넷(Petri Net)으로 변환하는 최초의 이론적 알고리즘 (루프 및 노이즈에 취약).
- **휴리스틱 마이너 (Heuristic Miner)** : 빈도수를 기반으로 유의미한 주 흐름만 남기고 노이즈성 희귀 경로를 자동 필터링하여 실무 복잡 프로세스 시각화에 탁월.
- **직접 후속 그래프 (DFG, Directly-Follows Graph)** : 상용 툴(Celonis)에서 널리 활용되는 직관적 전이 그래프.

### 나. 적합도 평가 4대 품질 척도
1. **재현율 (Fitness)** : 로그에 기록된 모든 실행 경로를 모델이 얼마나 온전히 설명할 수 있는가?
2. **정밀도 (Precision)** : 로그에 한 번도 나타나지 않은 엉뚱한 경로를 모델이 과도하게 허용하지 않는가?
3. **일반화 (Generalization)** : 미래에 발생할 새로운 인스턴스를 모델이 수용할 수 있는가?
4. **간결성 (Simplicity)** : 모델이 불필요하게 복잡하지 않고 직관적인가 (오컴의 면도날).

## Ⅳ. 프로세스 마이닝(Process Mining)의 주요 한계점 및 해결 방안

- **스파게티 프로세스(Spaghetti Process)** 현상으로 인한 시각적 판독 불가 :
  - 한계점 : 실제 업무 현장의 수많은 예외 케이스와 비정형 경로가 모두 노출되어 프로세스 맵이 거미줄처럼 얽혀 핵심 병목이나 표준 경로 식별 곤란.
  - 해결 방안 : 노드 및 엣지 빈도 기반 필터링(Trace/Activity Filtering) 적용, 휴리스틱 마이너(Heuristic Miner) 및 퍼지 마이너(Fuzzy Miner) 알고리즘을 통한 추상화 수준 조절.
- 이벤트 로그의 데이터 품질 불량(Garbage In, Garbage Out) :
  - 한계점 : 케이스 ID(Case ID) 누락, 타임스탬프 순서 역전(시계 불일치), 액티비티 명칭 비표준화로 인해 잘못된 프로세스 흐름이 발견되는 오류 빈발.
  - 해결 방안 : 프로세스 마이닝 전용 데이터 전처리 파이프라인 구축, 타임스탬프 정밀도 표준화(ms 단위), 도메인 규칙 기반 케이스 식별자 바인딩 정제.
- 컨포먼스 체킹(Conformance Checking)과 실제 비즈니스 제약 간의 괴리 :
  - 한계점 : 규범적 표준 모델(BPMN)과 실제 로그 비교 시 정상적인 비즈니스 유연성(현업의 합리적 예외 처리)까지 모두 위반(Non-compliant)으로 오판.
  - 해결 방안 : 얼라인먼트(Alignment) 알고리즘의 페널티 비용 파라미터 튜닝, 도메인 전문가와의 정기적 예외 경로 리뷰 워크숍을 통한 표준 프로세스 모델 개정.

## Ⅴ. 엔터프라이즈 디지털 전환(DX)을 위한 실무 제언

- **RPA(로봇 프로세스 자동화)** 대상 과제의 과학적 발굴 : 현업의 주관적 추천에 의존하지 않고, 프로세스 마이닝을 통해 병목 지연 시간이 가장 길고 반복 횟수가 많은 **'해피 패스(Happy Path)'** 구간을 정량 도출하여 RPA 봇을 타깃 구축해야 투자 대비 효과(ROI)를 극대화할 수 있음.
- 실시간 실행 관리(**Execution Management** System)로의 확장 : 사후에 지난달 데이터를 분석하는 배치 분석에 머무르지 않고, Kafka 이벤트 스트림과 Celonis EMS를 실시간 연동하여 배송 지연이나 승인 누락 징후가 감지되는 즉시 담당자에게 자동으로 작업 티켓을 발행하는 능동형 조치 체계를 구축할 것을 제언함.
