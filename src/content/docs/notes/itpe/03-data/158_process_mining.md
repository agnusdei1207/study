## 답안 골격
```text
[프로세스 마이닝 (Process Mining)] ◀━━ 머리: Ⅶ 내 의견 (이벤트 로그 기반 프로세스 자동 발견과 적합도 검사를 통한 업무 병목 혁신)
 ┃
 ┣━ Ⅰ 개요 ───── 정보시스템(ERP, CRM, 그룹웨어 등)에 기록된 이벤트 로그(Event Log)를 분석하여 실제 수행된 업무 프로세스를 시각화하고 병목과 이상을 진단·개선하는 데이터 기반 혁신 기술
 ┣━ Ⅱ 특징 ───── 데이터 과학과 BPM의 융합 · 이벤트 로그 3대 필수 속성(Case ID, Activity, Timestamp) · 3대 유형(발견, 적합도, 향상) · 객관적 사실 기반
 ┣━ Ⅲ 구조 ───── 3대 핵심 유형: 프로세스 발견(Discovery) / 적합도 검사(Conformance) / 프로세스 향상(Enhancement)
 ┣━ Ⅳ 흐름 ───── ① 이벤트 로그 추출 및 정제 → ② 프로세스 맵 자동 도출(Alpha/Inductive Miner) → ③ 표준 프로세스 대비 편차/우회 탐지 → ④ 병목 원인 진단 → ⑤ 프로세스 재설계
 ┣━ Ⅴ 비교 ───── 프로세스 마이닝 vs 데이터 마이닝 vs 전통적 BPM
 ┗━ Ⅵ 실무 ───── 수작업 오프라인 업무의 로그 누락 / 예외 케이스 과다로 인한 스파게티 프로세스(Spaghetti Process) 시각화 혼란
```
- 필수 키워드: 프로세스 마이닝 · 이벤트 로그(Event Log) · Case ID · Activity · Timestamp · 프로세스 발견(Discovery) · 적합도 검사(Conformance) · 프로세스 향상(Enhancement) · Celonis
- 기출: 118회 `정보시스템의 이벤트 로그를 활용한 프로세스 마이닝(Process Mining)의 개념, 3대 유형 및 비즈니스 프로세스 혁신 방안을 설명하시오.` → Ⅰ 정의 + Ⅲ 3대 유형(발견, 적합도, 향상) + Ⅳ 절차 + Ⅵ 적용 효과

## 한 줄 본질
- 종이 매뉴얼에 적힌 이상적 업무 절차와 현업의 실제 수행 과정 간의 괴리를 파악 불가 → 시스템 이벤트 로그(사건-시간-주체)를 추적하여 실제 흘러간 업무 경로를 엑스레이처럼 시각화 → 병목 구간과 부정 우회 즉각 적발 / 로그 품질에 의존

## 핵심 그림
```text
[프로세스 마이닝의 3대 핵심 유형 및 이벤트 로그 분석 구조]

  [1. 원천 데이터: 이벤트 로그 (Event Log)]
   Case ID │ Activity (수행 활동) │ Timestamp (일시)   │ Resource (담당자)
  ─────────┼──────────────────────┼────────────────────┼───────────────────
   Ord#101 │ 주문 접수            │ 2026-09-20 09:00   │ 김대리
   Ord#101 │ 결제 승인            │ 2026-09-20 09:05   │ 시스템
   Ord#101 │ 배송 출발            │ 2026-09-20 14:00   │ 박과장
           │
           ▼ 프로세스 마이닝 엔진 (Celonis 등)
  ┌───────────────────────────────────────────────────────────────────────┐
  │ 2. 3대 분석 유형                                                      │
  │  (1) 발견 (Discovery)   : 로그로부터 실제 프로세스 맵(Flow) 자동 도출 │
  │  (2) 적합도 (Conformance): 표준 규정 매뉴얼 vs 실제 로그 간 위반 탐지 │
  │  (3) 향상 (Enhancement) : 병목 소요시간 분석을 통한 최적화 재설계     │
  └───────────────────────────────────────────────────────────────────────┘
```

## 핵심 용어
- Case ID: 프로세스 마이닝에서 개별 업무 인스턴스를 고유하게 식별하는 키(예: '주문번호', '클레임 접수번호')
- 적합도 검사(Conformance Checking): 조직이 규정한 공식 표준 비즈니스 프로세스 모델과 이벤트 로그에 기록된 실제 실행 이력을 대조하여, 규정 위반이나 승인 단계 우회(Bypass)를 찾아내는 활동

## 핵심 통찰
- 전통적인 인터뷰 기반 컨설팅은 '사람이 기억하는 왜곡된 프로세스'만 듣지만, 프로세스 마이닝은 '시스템 로그가 증명하는 냉혹한 팩트'를 보여줌 → 현업은 "규정대로 한다"고 하지만 실제 로그를 보면 30%가 승인 결재를 우회하고 있음
- 이벤트 로그에서 가장 중요한 최소 속성은 딱 3개뿐임: `Case ID(어떤 건인가), Activity(무엇을 했는가), Timestamp(언제 했는가)` → 이 3개만 있으면 어떤 복잡한 ERP 시스템이라도 프로세스 맵 복원 가능
- 수백만 건의 로그를 가공 없이 그대로 그리면 선들이 거미줄처럼 얽혀 알아볼 수 없는 '스파게티 프로세스(Spaghetti Process)'가 되므로, 상위 80% 빈도의 '해피 패스(Happy Path)'만 필터링하는 기법 필수

## 이웃 토픽과 구분
- 프로세스 마이닝 vs 전통적 데이터마이닝: 데이터마이닝 = 고객의 이탈 확률이나 구매 품목처럼 '정적 속성 간의 패턴'을 탐색 / 프로세스 마이닝 = 시간의 흐름에 따른 '행위의 순서와 병목 경로(시공간적 워크플로우)'를 탐색

## 문제·원인·대책
- 적용 상황: 글로벌 제조사의 구매-조달(Procure-to-Pay) 프로세스 효율화 및 내부 감사
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 구매 발주 승인 전 물품을 먼저 입고받는 규정 위반(선입고 후발주) 다수 발생 | 기존 수작업 샘플링 감사로는 비표준 우회 경로 적발 불가 | 적합도 검사(Conformance Checking) 알고리즘으로 전수 로그 자동 전수 조사 | 규정 위반 프로세스 100% 실시간 탐지 |
| 고객 클레임 처리 기간이 평균 15일로 지연되어 고객 불만 폭증 | 특정 부서 간 승인 단계에서 10일 이상 정체되는 병목 존재 | 프로세스 향상(Enhancement) 지연시간 분석으로 대기 병목 노드 특정 및 자동 승인화 | 전체 리드타임 15일에서 3일로 80% 단축 |

## 이렇게 출제된다
- 제118회: "정보시스템의 이벤트 로그를 활용한 프로세스 마이닝(Process Mining)의 개념, 3대 주요 분석 유형(발견, 적합도, 향상) 및 이벤트 로그의 구성요소를 설명하고, 기업의 비즈니스 프로세스 혁신 방안을 기술하시오." → 요구 포인트: 프로세스 마이닝 정의 + 3대 필수 로그 필드 + 3대 분석 유형 상세 매핑 + 스파게티 프로세스 극복

## 내 의견
- [RPA와 프로세스 마이닝의 유기적 결합] 무작정 화면 자동화(RPA)부터 도입했다가 잘못된 프로세스까지 고속으로 자동화해 버리는 '엉뚱한 자동화' 실패 빈발 → 나라면: 프로세스 마이닝을 선행하여 수작업 반복 빈도가 가장 높고 병목이 심한 핵심 작업 구간을 데이터로 정량 식별한 뒤, 해당 타겟 구간에만 정밀하게 RPA 봇을 투입하는 데이터 주도 자동화(Hyper-automation) 프레임워크 구축

## 찾아볼 것
- 이벤트 로그로부터 수학적으로 프로세스 넷을 도출하는 대표적 디스커버리 알고리즘인 `Alpha Miner`와 최신 `Inductive Miner`의 차이
