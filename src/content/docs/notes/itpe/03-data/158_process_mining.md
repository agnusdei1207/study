## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터 마이닝 → **프로세스 마이닝**

## 30초 인출

- 본질: 프로세스 마이닝은 정보시스템의 이벤트 로그로 실제 업무 흐름을 발견·비교·분석하는 방법
- 메커니즘: Case ID·Activity·Timestamp를 정합화해 케이스별 흔적을 만든 뒤, 발견(로그에서 모델 도출)·적합도(참조 모델과 비교)·향상(시간·자원 정보 추가)을 수행하고 현업이 원인을 검토해 개선·재측정
- 통찰: 케이스 식별과 시각이 어긋나거나 시스템 밖 수작업이 로그에서 빠지면 경로와 처리 시간이 왜곡되므로 로그를 정합화하고 결과를 현업과 검증하며, 드문 경로는 빈도가 아니라 규정·위험 영향으로 선별

<details>
<summary>핵심 용어</summary>

- **프로세스 마이닝(Process Mining)** : 이벤트 로그에서 프로세스를 발견·검사·향상하는 분석
- **이벤트 로그** : 케이스 식별자·활동·시각을 담은 실행 기록
- **발견(Discovery)** : 사전 모델 없이 로그에서 프로세스 모델을 도출
- **적합도 검사(Conformance)** : 참조 모델과 실제 로그의 차이를 확인
- **향상(Enhancement)** : 성능·자원 정보를 모델에 더해 개선점 도출
- **알파·휴리스틱·인덕티브 마이너** : 대표 프로세스 발견 알고리즘
- **BPM** : 업무 프로세스의 모델링·관리·개선 활동

</details>

## 2~4교시 25점 답안

## Ⅰ. 프로세스 마이닝의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **프로세스 마이닝** 은 이벤트 로그로 업무 흐름을 발견·비교·분석하는 방법 |
| 목적 | 실제 수행과 참조 모델의 차이·성능 특성을 파악해 업무 개선 지원 |

## Ⅱ. 특징

| 특징 | 분석 의미 |
|---|---|
| 케이스별 실행 흔적 | 같은 업무 건의 활동 순서·시각 복원 |
| 실제·설계 흐름 비교 | 관측 경로와 참조 모델의 차이 확인 |
| 성능과 규칙 연결 | 대기·반복·예외를 개선 후보로 해석 |

## Ⅲ. 분석 체계

```text
원천 이벤트 → Case ID·Activity·Timestamp 정합화 → 케이스별 흔적
   ├ 발견: 로그 → 실제 모델
   ├ 적합도: 참조 모델과 비교 → 차이
   └ 향상: 시간·자원 정보 추가
        ↓ 현업 원인 검토 → 개선 → 재측정
```

| 케이스 | 활동 | 시각 | 선택 속성 |
|---|---|---|---|
| 주문-001 | 주문 접수 | 발생 시각 | 수행 조직 |
| 주문-001 | 결제 승인 | 발생 시각 | 처리 자원 |
| 주문-001 | 출고 완료 | 발생 시각 | 채널·비용 |

시각 정밀도·시간대·활동 의미를 원천 시스템 간에 확인.

## Ⅳ. 발견 알고리즘과 유사 개념 비교

| 알고리즘 | 접근 | 확인 |
|---|---|---|
| 알파 마이너 | 직접 후행 관계에서 페트리 넷 구조 도출 | 노이즈·불완전 로그, 짧은 루프 표현의 한계 |
| 휴리스틱 마이너 | 활동 간 빈도·의존도로 모델 구성 | 임계값에 따른 예외 경로 누락·복잡도 |
| 인덕티브 마이너 | 로그를 재귀 분할해 프로세스 트리 구성 | 로그·변형·필터 조건과 모델의 적합성 |

어느 알고리즘도 모든 데이터에 우월하다고 단정하지 않고 로그 품질과 필요한 표현력으로 선택.

| 비교 | BPM | 데이터 마이닝 | 프로세스 마이닝 |
|---|---|---|---|
| 초점 | 프로세스 모델링·관리·개선 | 패턴·예측 관계 탐색 | 이벤트 로그의 프로세스 동작 분석 |
| 근거 | 업무 규칙·모델·운영 정보 | 데이터와 특징량 | 케이스별 활동·시각, 참조 모델 |
| 관계 | 기준·개선 활동 제공 | 예측·분류를 보완 | 실행 흐름과 모델 차이로 BPM 개선 지원 |

경로가 많으면 질문에 맞춰 케이스·기간·활동 범위를 필터링하고, 자동화는 원인과 규칙을 확인한 개선안 중 반복 작업에 적용한 뒤 변경 후 로그로 재검증.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 케이스 식별·시각 불일치로 경로·처리 시간 왜곡 | 로그 범위·활동 의미·시간대 정합화, 현업과 결과 검증 |
| 로그에 없는 수작업이 흐름에서 누락 | 시스템 밖 활동을 현업과 확인하고 분석 범위·누락 명시 |
| 드문 경로를 빈도만으로 제거해 규정 위반을 놓침 | 빈도와 함께 위험·규정 영향으로 예외 경로 선정 |

## Ⅵ. 제언

로그를 정합화한 뒤 적합도로 차이를 찾고 현업과 원인을 검증해 개선하며 변경 후 다시 측정

```text
로그 정합화 → 발견·적합도 → 현업 검증 → 개선 → 재측정
```

| 구분 | 설계 문서만 신뢰 | 제언: 로그 기반 검증 |
|---|---|---|
| 실제 흐름 | 파악 곤란 | 경로·시간 확인 |
| 개선 효과 | 추정 | 재측정 |
