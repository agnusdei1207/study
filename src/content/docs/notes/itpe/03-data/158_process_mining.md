## Ⅰ. 프로세스 마이닝의 개요

- 핵심 요약 : 이벤트 로그로부터 실제 업무 프로세스를 자동으로 발견하고 검증하며 개선하는 데이터 기반 분석 기법.
- 개념 : 정보시스템에 기록된 실행 이력인 **이벤트 로그**(Event Log)를 분석해 실제 업무 흐름을 도출하는 **프로세스 마이닝**(Process Mining).
- 배경 및 필요성 : 인터뷰와 설문에 의존하는 업무 재설계(BPR, Business Process Reengineering)는 담당자의 주관이 개입해 실제 흐름과 차이가 생기므로, 로그에 근거한 사실 분석이 필요해짐.
- 주요 목적 : 실제 프로세스의 가시화, 병목과 예외 경로의 진단, 그리고 RPA(Robotic Process Automation, 로봇 프로세스 자동화) 대상 발굴.

## Ⅱ. 프로세스 마이닝의 특징 및 장점

- 핵심 요약 : 발견, 적합성 검사, 향상의 3가지 유형이 프로세스의 가시화, 검증, 최적화를 하나의 흐름으로 제공.

1. **Discovery**(발견) : 사전 모델 없이 로그만으로 실제 프로세스 모델을 자동 도출 → 주관이 배제된 현황 파악.
2. **Conformance**(적합성 검사) : 기준 모델과 실제 로그의 불일치를 탐지 → 규정 위반과 예외 경로를 식별.
3. **Enhancement**(향상) : 성능 정보를 모델에 보강해 병목을 찾고 재설계 → 자동화와 개선 우선순위 결정.
4. **이벤트 로그 요건** : Case ID(사례 식별자), Activity(수행 활동), Timestamp(발생 시각)의 3요소를 갖춰야 분석이 가능 → 로그 품질이 분석 결과를 결정.

## Ⅲ. 3대 유형의 흐름과 로그 구조

- 핵심 요약 : 이벤트 로그에서 모델을 발견하고 기준 모델과 대조한 뒤, 병목을 개선하는 순환 흐름.

```text
[ 프로세스 마이닝 흐름 ]

이벤트 로그 (Case·Activity·Timestamp)
   ↓
Discovery : 실제 프로세스 모델 도출
   ↓
Conformance : 기준 모델과 대조
   ↓
Enhancement : 병목 제거·재설계
```

```text
[ 이벤트 로그 예시 ]

Case: Order-1001
  09:00:00  주문 접수
  09:05:00  결제 승인
  11:00:00  배송 준비
```

## Ⅳ. 발견 알고리즘과 품질 척도 비교

- 핵심 요약 : 발견 알고리즘은 노이즈 처리 방식으로 구분되고, 모델의 품질은 4대 품질 척도로 평가.
- **Alpha Miner** : 로그의 순서 관계를 페트리 넷(Petri Net)으로 변환하는 초기 알고리즘 → 노이즈에 취약.
- **Heuristic Miner** : 발생 빈도로 의존 관계의 강도를 계산 → 노이즈를 걸러내 실무 로그에 적합.
- **DFG**(Directly-Follows Graph, 직접 후행 관계 그래프) : 활동 간 직접 연결을 그래프로 표시 → 직관적 탐색에 강점.

| 알고리즘 | 방식 | 노이즈 처리 | 적합 상황 |
| --- | --- | --- | --- |
| Alpha Miner | 페트리 넷 변환 | 취약 | 이론적 기초 학습 |
| Heuristic Miner | 빈도 기반 의존 관계 | 빈도로 필터링 | 실무의 복잡한 프로세스 |
| DFG | 직접 후행 관계 그래프 | 빈도 임계값으로 조정 | 탐색 중심 분석, 상용 도구 |

| 품질 척도 | 의미 | 부족할 때 나타나는 문제 |
| --- | --- | --- |
| 적합도(Fitness, 재현율) | 로그의 행위를 모델이 얼마나 재현하는가 | 실제 행위가 모델에서 누락 |
| 정밀도(Precision) | 모델이 허용하는 행위 중 로그에 실제 있는 비율 | 모델이 불필요한 행위까지 허용 |
| 일반화(Generalization) | 로그에 없는 정상 행위까지 설명하는 정도 | 로그만 외운 과적합 모델 |
| 간결성(Simplicity) | 모델이 단순하게 표현되는 정도 | 스파게티 프로세스 |

## Ⅴ. 프로세스 마이닝의 한계와 방안

- 핵심 요약 : 스파게티 프로세스, 로그 품질 불량, 기준 모델과의 괴리를 필터링, 전처리, 얼라인먼트로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 스파게티 프로세스 | 예외 경로가 많아 모델을 판독할 수 없음 | 빈도 기준 필터링, Fuzzy Miner로 요약 모델 생성 | 경로 수 |
| 로그 품질 불량 | Case ID 누락, 타임스탬프 역전으로 순서가 왜곡 | 전처리 파이프라인, 시각 형식 표준화 | 데이터 품질 지표 |
| 적합성 괴리 | 합리적인 예외까지 위반으로 판정 | 얼라인먼트(Alignment) 비용 튜닝, 기준 모델 개정 | 적합도 |

## Ⅵ. 프로세스 마이닝에 대한 기술사적 제언

- 핵심 요약 : 로그 분석을 RPA 대상 발굴과 실시간 모니터링으로 확장해 프로세스 개선을 상시 운영 체계로 전환.
1. 로그에서 예외가 적은 정상 경로(Happy Path)를 정량적으로 도출한 뒤 자동화 대상을 고를 필요가 있다. 투자 대비 효과를 먼저 검증할 수 있기 때문이다.
2. 이벤트 로그를 Apache Kafka 같은 메시지 스트리밍 플랫폼과 연결해 지연 이벤트를 실시간으로 감지하고, 담당 부서에 자동 티켓을 발행하는 체계를 구축할 필요가 있다.
3. 현업과 IT 부서가 이벤트 로그의 기록 규칙을 공동으로 정의하고 품질을 상시 점검하는 거버넌스를 둘 필요가 있다.

## Ⅶ. 결론

- 핵심 요약 : 프로세스 마이닝은 로그로 실제 업무를 입증하는 사실 기반 프로세스 분석 기법.
- 시사점 : 3대 유형과 로그 품질 요건이 함께 갖춰질 때 개선의 근거가 실효를 거둠.
