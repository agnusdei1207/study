## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터베이스 성능 → **테이블 파티셔닝**

## 30초 인출

- 본질: 테이블 파티셔닝은 하나의 논리 테이블을 파티션 단위로 나누어 저장·관리하는 DBMS 기능
- 메커니즘: 분할 키 값을 범위·목록·해시 규칙에 대입해 파티션에 배치하고, 질의의 키 조건과 맞으면 옵티마이저가 관련 없는 파티션을 제외(프루닝)
- 통찰: 분할 키가 실제 질의 조건과 다르면 스캔량이 줄지 않으므로 질의 분포·증가·보관 주기로 키를 정하고 실행계획에서 읽은 파티션 수를 확인

<details>
<summary>핵심 용어</summary>

- **파티셔닝(Partitioning)** : 논리 테이블을 여러 파티션으로 나누어 관리하는 기능
- **분할 키** : 행을 어느 파티션에 둘지 정하는 열
- **범위·목록·해시 분할** : 연속 구간 / 지정 값 / 해시 값 기준의 분할
- **파티션 프루닝** : 조건에 맞지 않는 파티션을 읽지 않는 최적화
- **로컬 인덱스** : 테이블 파티션에 대응하는 인덱스 파티션
- **글로벌 인덱스** : 여러 파티션을 아우르는 인덱스
- **샤딩** : 여러 독립 노드에 데이터를 분산하는 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. 파티셔닝의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **파티셔닝** 은 하나의 논리 테이블을 파티션 단위로 나누어 관리하는 DBMS 기능 |
| 목적 | 질의 접근 범위를 줄이고 대량 데이터의 운영 단위를 조정 |

## Ⅱ. 특징

| 특징 | 모습 | 효과의 조건 |
|---|---|---|
| 논리적 단일 테이블 | 물리적으로 여러 파티션에 배치 | 응용은 하나의 테이블로 질의 |
| 조건부 접근 축소 | 파티션 키로 대상 선택 | 질의 조건과 키가 맞아야 프루닝 |
| 관리 단위 분리 | 기간·범주별 파티션 | 보관·삭제·교체를 구간별 처리 |

## Ⅲ. 분할 키와 프루닝

```text
대표 질의 조건·증가 패턴 → 분할 키 선정 → 범위·목록·해시 규칙 → 파티션 배치
같은 키 조건의 질의 → 옵티마이저가 조건 불일치 파티션 제외
→ 실행계획에서 읽은 파티션 수·응답시간 확인 → 키 편중·보관 주기와 비교해 조정
```

## Ⅳ. 분할 방식과 인덱스

| 방식 | 배치 규칙 | 적합 패턴 | 유의 |
|---|---|---|---|
| 범위 | 연속 구간별 | 기간·구간 조회, 기간별 관리 | 한쪽 구간에 신규 데이터 집중 |
| 목록 | 지정 값별 | 지역·업무 코드별 | 새 값의 기본 처리 필요 |
| 해시 | 해시 값별 | 동등 조건·분산 | 범위 조건으로 일부만 찾기 어려움 |
| 복합 | 범위 안에서 해시 등 | 기간과 엔티티 키 병용 | 파티션 수·관리 복잡 |

| 구분 | 구조 | 운영 고려 |
|---|---|---|
| 로컬 인덱스 | 테이블 파티션에 대응 | 파티션 추가·삭제 관리가 국소적 |
| 글로벌 인덱스 | 여러 파티션을 아우름 | 파티션 변경 시 유지·재구성 옵션 검토 |
| 샤딩 | 여러 노드에 분산 | 라우팅·분산 질의·재분배 별도 설계 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 분할 키가 질의 조건과 달라 스캔량 미감소 | 질의 분포·증가·보관 주기로 키 선정, 프루닝 검증 |
| 최신 구간 쓰기 집중 | 유입 분포 측정, 간격·복합 분할 조정 |
| 파티션 교체 시 인덱스 유지 부담 | 인덱스 유지 방식과 DBMS별 재구성 옵션 확인 |

## Ⅵ. 제언

대표 질의의 키 조건과 보관 주기로 분할 키를 정하고 프루닝을 실행계획으로 확인

```text
질의·보관 주기 분석 → 분할 키·방식 → 로컬 인덱스 위주 설계 → 프루닝 검증
```

| 구분 | 키 선정 없이 분할 | 제언: 질의 기반 분할 |
|---|---|---|
| 스캔량 | 미감소 | 프루닝으로 감소 |
| 운영 | 복잡도만 증가 | 구간별 관리 |
