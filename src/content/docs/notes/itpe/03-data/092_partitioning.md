## Ⅰ. 대용량 데이터베이스의 물리적 분할 관리, 파티셔닝 개요

### 가. 파티셔닝(Partitioning)의 정의
- **파티셔닝**은 하나의 거대한 논리적 데이터베이스 테이블이나 인덱스를 물리적으로 독립된 작은 단위의 파티션(Partition) 세그먼트로 분할하여 디스크에 저장하고 관리하는 기술.
- 애플리케이션 관점에서는 기존 단일 테이블과 동일하게 SQL을 수행할 수 있도록 논리적 투명성을 유지하면서, 관리성(Manageability), 성능(Performance), 가용성(Availability)을 극대화함.

---

## Ⅱ. 4대 파티셔닝 분할 전략 및 파티션 인덱스 분류

### 가. 4대 기본 분할 방식 비교

```text
[ 4대 파티셔닝 전략 ]
1. Range (범위)     : 연속된 값 범위 (날짜, 연속 숫자) -> 시계열 이력 관리 최적
2. List (목록)      : 불연속적 이산 값 (지역코드, 사업부) -> 업무 단위 물리적 격리
3. Hash (해시)      : 해시 함수 균등 분산 (고객ID, 계좌번호) -> I/O 경합 균등 분산
4. Composite (복합) : 1차 분할 + 2차 서브 분할 (예: Range-Hash, Range-List)
```

### 나. 글로벌 인덱스 vs 로컬 인덱스 비교

```text
[ 파티션 인덱스 2대 구조 ]
(A) 로컬 파티션 인덱스 (Local Partitioned Index)
    [Table Part 1] <---> [Index Part 1]   * 테이블 파티션과 인덱스 파티션이 1:1 완벽 대응
    [Table Part 2] <---> [Index Part 2]   * 파티션 Drop 시 타 파티션 영향 없음 (유지보수 극상)

(B) 글로벌 파티션 인덱스 (Global Partitioned Index)
    [Table Part 1] \
    [Table Part 2] ---> [Global Index Part A, B...] * 테이블 분할과 무관한 독립적 분할
    [Table Part 3] /                                * 단일 파티션 Drop 시 전체 인덱스 깨짐(Unusable)
```

| 비교 항목 | 로컬 파티션 인덱스 (Local Index) | 글로벌 파티션 인덱스 (Global Index) |
| :--- | :--- | :--- |
| **테이블과의 매핑 관계** | 테이블 파티션과 인덱스 파티션이 **1:1 완벽 일치** | 테이블 파티션과 인덱스 파티션이 독립적 (N:M) |
| **파티션 조작 독립성** | 특정 파티션 `DROP/TRUNCATE` 시 **해당 로컬 인덱스만 삭제됨 (타 파티션 영향 없음)** | 특정 파티션 변경 시 **글로벌 인덱스 전체가 UNUSABLE 상태로 깨짐** |
| **고유성(Unique) 보장** | 파티션 키가 인덱스 키에 반드시 포함되어야 PK 생성 가능 | 파티션 키와 무관하게 전역 유일성(Unique PK) 보장 가능 |
| **실무 권장도** | **OLTP 및 대용량 배치에 최우선 권장** | 전역 PK 강제가 불가피한 경우에 한해 제한적 사용 |

## Ⅲ. 파티션 프루닝(Partition Pruning)과 파티션 와이즈 조인

### 가. 파티션 프루닝(Partition Pruning)의 성능 혁신
- SQL 쿼리의 `WHERE` 절에 파티션 키 조건이 주어졌을 때, 쿼리 실행 엔진이 불필요한 파티션 세그먼트의 디스크 I/O를 원천 배제하고 **조건에 해당하는 특정 파티션만 선별적으로 스캔** 하는 최적화 메커니즘.

### 나. 파티션 와이즈 조인 (Partition-wise Join)
- 조인 대상이 되는 두 대용량 테이블이 동일한 파티션 키 기준으로 분할되어 있을 때, 전체 조인이 아닌 파티션 대 파티션 1:1 독립 조인으로 쪼개어 병렬 분산 처리함으로써 메모리 버퍼 오버헤드를 대폭 경감.

## Ⅳ. 파티셔닝(Partitioning)의 주요 한계점 및 해결 방안

- **파티션 프루닝(Partition Pruning) 실패로 인한 전 파티션 풀 스캔** :
  - **한계점** : SQL WHERE 조건절에서 파티션 키 컬럼을 함수로 가공하거나 바인드 변수 타입 불일치 시 옵티마이저가 프루닝을 수행하지 못해 전체 파티션을 스캔하는 성능 저하 발생.
  - **해결 방안** : 파티션 키 컬럼 가공 금지 표준화, 실행 계획의 `Pstart`/`Pstop` 모니터링 자동화 및 정적/동적 프루닝 유도 힌트 적용.
- **글로벌 인덱스(Global Index) 구성 시 파티션 유지보수 작업의 가용성 저해** :
  - **한계점** : 과거 데이터 파티션 삭제(DROP/TRUNCATE) 시 글로벌 인덱스가 Unusable 상태로 전환되어 전체 테이블의 트랜잭션이 중단되는 결함 유발.
  - **해결 방안** : 가능한 로컬 인덱스(Local Prefixed Index) 중심 설계 채택, 불가피한 글로벌 인덱스는 `UPDATE GLOBAL INDEXES` 절을 병행 사용하여 백그라운드 인덱스 동기화 수행.
- **파티션 키 선정 오류에 따른 데이터 편향(Skewness) 및 핫스팟** :
  - **한계점** : 특정 일자나 특정 고객사에 트래픽과 데이터가 편중되는 경우 특정 파티션만 I/O가 집중되어 파티셔닝의 부하 분산 효과 무력화.
  - **해결 방안** : 복합 파티셔닝(Range-Hash 또는 Range-List 결합)을 통해 1차 기간 분할 후 2차 해시 분할로 블록 물리적 고른 분산 유도.

## Ⅴ. 무중단 라이프사이클 관리를 위한 실무 제언

- **파티션 익스체인지(Partition Exchange)를 통한 초고속 데이터 적재** : 대량의 신규 데이터를 운영 파티션 테이블에 직접 INSERT하면 락 경합과 인덱스 갱신 부하가 발생하므로, 동일 구조의 임시 일반 테이블에 고속 벌크 로드(Direct Path) 및 인덱스 생성을 마친 후 `ALTER TABLE ... EXCHANGE PARTITION` DDL을 통해 수 밀리초 만에 포인터만 교체 적재할 것.
- **글로벌 인덱스 무효화 방지(UPDATE GLOBAL INDEXES)** : 파티션 삭제(`DROP PARTITION`) 작업 시 반드시 `UPDATE GLOBAL INDEXES` 절을 함께 명시하여 인덱스가 비활성화되어 전체 트랜잭션이 중단되는 대형 운영 사고를 원천 방지할 것을 제언함.
