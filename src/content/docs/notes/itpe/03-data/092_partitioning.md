## 연관 키워드

**파티셔닝(Partitioning)**, **Range/List/Hash/Composite**, **로컬/글로벌 인덱스**, **파티션 프루닝(Pruning)**, **파티션 와이즈 조인**, **관리성·성능·가용성**

## Ⅰ. 개요

- 핵심 요약 : **파티셔닝**은 대용량 테이블·인덱스를 물리적으로 분할해 관리성·성능·가용성을 높이는 기술.
- 목적 : 논리적 투명성 유지하며 물리적 분할로 I/O·유지보수 효율화.
- 배경 : 단일 테이블 비대화로 백업·복구·쿼리 성능 저하 → 분할 필요.
- 특징 : Range/List/Hash/Composite 4대 전략, 로컬/글로벌 인덱스.

## Ⅱ. 특징 및 장점

- 핵심 요약 : **물리적 분할**로 스캔 범위 축소와 유지보수 독립성 확보.
- **관리성** : 파티션 단위 백업·복구·아카이빙.
- **성능** : 프루닝으로 불필요 파티션 스캔 배제.
- **가용성** : 파티션 단위 작업으로 서비스 중단 최소화.
- **병렬 처리** : 파티션 와이즈 조인으로 병렬 분산.
- **I/O 분산** : 핫스팟 완화 및 경합 감소.

## Ⅲ. 프루닝·와이즈 조인 흐름

- 핵심 요약 : **프루닝**으로 스캔 파티션 축소, **와이즈 조인**으로 병렬 조인.
- 파티션 프루닝 : WHERE 절 파티션 키 조건으로 해당 파티션만 스캔.
- 파티션 와이즈 조인 : 동일 키 분할된 두 테이블을 파티션 단위로 독립 조인.

```text
[ 4대 파티셔닝 전략 ]

1. Range (범위)     : 연속 값 (날짜) -> 시계열 이력
2. List (목록)      : 이산 값 (지역코드) -> 업무 단위 격리
3. Hash (해시)      : 해시 균등 분산 (고객ID) -> I/O 경합 분산
4. Composite (복합) : 1차 + 2차 서브 분할 (Range-Hash)
```

```text
[ 로컬 vs 글로벌 인덱스 ]

로컬 : 테이블 파티션과 1:1, Drop 시 해당 인덱스만 삭제
글로벌 : 독립 분할, Drop 시 전체 인덱스 Unusable
```

## Ⅳ. 로컬 vs 글로벌 인덱스 비교

- 핵심 요약 : **유지보수 독립성**은 로컬, **전역 유일성**은 글로벌.

| 항목 | 로컬 인덱스 | 글로벌 인덱스 |
|---|---|---|
| 테이블 매핑 | 1:1 완벽 일치 | 독립적 (N:M) |
| 파티션 조작 | Drop 시 해당 인덱스만 삭제 | Drop 시 전체 Unusable |
| 고유성 보장 | 파티션 키 포함 필요 | 전역 PK 보장 |
| 실무 권장 | OLTP·배치 최우선 | 전역 PK 불가피 시 |

## Ⅴ. 한계와 방안

- 핵심 요약 : **프루닝 실패·글로벌 인덱스 무효화·데이터 편향**을 표준화·로컬 인덱스·복합 분할로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 프루닝 실패 | 파티션 키 가공·타입 불일치로 전체 파티션 스캔 | 키 컬럼 가공 금지, Pstart/Pstop 모니터링 | 스캔 파티션 수 |
| 글로벌 인덱스 무효화 | 파티션 Drop 시 인덱스 Unusable → 트랜잭션 중단 | 로컬 인덱스 우선, UPDATE GLOBAL INDEXES | 인덱스 상태 |
| 데이터 편향 | 특정 파티션에 트래픽 집중 | 복합 파티셔닝 (Range-Hash) | 파티션별 I/O |

## Ⅵ. 기술사적 제언

- 핵심 요약 : **익스체인지·글로벌 인덱스 보호·복합 분할**로 무중단 운영.
- 파티션 익스체인지 : 임시 테이블 고속 로드 후 포인터 교체 적재.
- 글로벌 인덱스 : Drop 시 UPDATE GLOBAL INDEXES 병행.
- 파티션 키 선정 : 복합 분할로 핫스팟 방지.

## Ⅶ. 결론

- 핵심 요약 : 파티셔닝은 **물리적 분할 + 프루닝**으로 대용량 관리성·성능·가용성 확보.
- 답안에는 4대 전략, 로컬/글로벌 인덱스, 프루닝, 한계·대응을 연결.
