## 연관 키워드

- 파티셔닝, Range, List, Hash, Composite, 로컬 인덱스, 글로벌 인덱스, 파티션 프루닝, 파티션 와이즈 조인, 관리성, 성능, 가용성

## Ⅰ. 파티셔닝의 개요

- 핵심 요약 : 대용량 데이터를 물리적으로 나눠 관리와 성능을 함께 높이는 기술.
- 개념 : 대용량 테이블과 인덱스를 기준 값에 따라 물리적 단위로 분할하되, 애플리케이션에는 하나의 테이블로 보이게 하는 기술(**파티셔닝**, Partitioning).
- 배경 및 필요성 : 단일 테이블이 비대해지면 백업·복구와 쿼리 성능이 떨어지므로, 분할을 통해 작업 범위를 줄일 필요가 있음.
- 주요 목적 : **관리성**·**성능**·**가용성**을 높이고 I/O와 유지보수 효율을 개선하는 것.
- 특징 : 분할 기준에 따라 4가지 전략을 선택하고, 인덱스는 파티션과 맞추는 방식에 따라 나뉨.

```text
[ 파티셔닝 구조 ]

대용량 테이블
     ↓ 분할 기준 (키 값)
파티션 1 | 파티션 2 | 파티션 3
     ↓
인덱스 (파티션과 맞춤)
```

## Ⅱ. 파티셔닝의 특징 및 장점

- 핵심 요약 : 물리적 분할로 스캔 범위를 줄이고 유지보수 단위를 독립시키는 구조.

1. 관리성 : 파티션 단위로 백업·복구·아카이빙을 수행 → 작업 범위 축소.
2. 성능 : **파티션 프루닝** (Partition Pruning, 조건에 맞지 않는 파티션을 건너뛰는 기능) → 불필요한 파티션 스캔 배제.
3. 가용성 : 파티션 단위 작업으로 서비스 중단 범위를 최소화.
4. 병렬 처리 : **파티션 와이즈 조인** (Partition-Wise Join, 같은 키로 나뉜 두 테이블을 파티션 단위로 짝지어 조인하는 방식) → 파티션별 병렬 분산.
5. I/O 분산 : 데이터가 여러 파티션에 나뉘어 핫스팟과 I/O 경합 완화.

## Ⅲ. 파티셔닝의 전략·프루닝·조인 흐름

- 핵심 요약 : 파티션 프루닝으로 스캔 대상을 줄이고, 파티션 와이즈 조인으로 조인을 파티션 단위로 병렬화.
- **Range** (범위 분할) : 날짜처럼 연속된 값으로 나눠 시계열 이력 관리에 적합.
- **List** (목록 분할) : 지역 코드처럼 이산 값으로 나눠 업무 단위를 격리.
- **Hash** (해시 분할) : 해시 값으로 고르게 나눠 I/O 경합을 분산.
- **Composite** (복합 분할) : 1차 분할 후 2차 서브 분할을 적용 (예: Range-Hash).
- **로컬 인덱스** (Local Index, 테이블 파티션과 1:1로 대응하는 인덱스) : 파티션 단위 조작 시 해당 인덱스만 함께 처리됨.
- **글로벌 인덱스** (Global Index, 파티션과 무관하게 테이블 전체를 가리키는 인덱스) : 전역 고유성을 보장하지만 파티션 Drop 시 무효화될 수 있음.

```text
[ 파티션 프루닝 흐름 ]

WHERE 조건 (파티션 키)
          ↓
대상 파티션 판별
          ↓
해당 파티션만 스캔
          ↓
나머지 파티션 배제
```

- 파티션 와이즈 조인은 두 테이블이 같은 키로 분할되어 있을 때 파티션 쌍을 독립적으로 조인한다.

## Ⅳ. 로컬 인덱스와 글로벌 인덱스의 비교

- 핵심 요약 : 로컬 인덱스는 유지보수 독립성, 글로벌 인덱스는 전역 고유성에 강점이 있음.

| 항목 | 로컬 인덱스 | 글로벌 인덱스 |
| --- | --- | --- |
| 파티션 대응 | 파티션마다 대응 (1:1) | 파티션과 독립된 구조 |
| 파티션 조작 | Drop 시 해당 파티션 인덱스만 삭제 | Drop 시 전체 인덱스 Unusable |
| 고유성 보장 | 고유 제약에 파티션 키 포함 필요 | 전역 PK 보장 가능 |
| 실무 권장 | 배치·파티션 유지보수가 잦은 경우 우선 | 전역 PK가 불가피한 경우 |

```text
[ 로컬 vs 글로벌 인덱스 ]

로컬 : 파티션마다 인덱스 하나 (1:1)
       → Drop 시 해당 인덱스만 삭제
글로벌 : 인덱스 하나가 전체를 가리킴
       → Drop 시 전체 인덱스 Unusable
```

## Ⅴ. 파티셔닝의 한계와 방안

- 핵심 요약 : 프루닝 실패, 글로벌 인덱스 무효화, 데이터 편향을 키 관리, 로컬 인덱스 우선, 복합 분할로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 프루닝 실패 | 파티션 키 가공이나 타입 불일치로 전체 파티션 스캔 | 키 컬럼 가공 금지, 실행 계획의 파티션 범위(Pstart/Pstop) 모니터링 | 스캔 파티션 수 |
| 글로벌 인덱스 무효화 | 파티션 Drop 시 인덱스 Unusable → 트랜잭션 중단 | 로컬 인덱스 우선, Oracle의 UPDATE GLOBAL INDEXES 옵션 병행 | 인덱스 상태 |
| 데이터 편향 | 특정 파티션에 트래픽 집중 | 복합 분할(Range-Hash) 적용 | 파티션별 I/O |

## Ⅵ. 파티셔닝에 대한 기술사적 제언

- 핵심 요약 : 파티션 교체 적재, 글로벌 인덱스 보호, 복합 분할을 결합해 무중단 운영 체계를 구축.

1. 대량 적재는 임시 테이블에 먼저 적재한 뒤 파티션 익스체인지(Partition Exchange, 임시 테이블과 파티션을 데이터 교체 방식으로 맞바꾸는 연산)로 반영하면, 운영 중 잠금 시간을 줄일 수 있다.
2. 파티션 Drop이 잦은 환경에서는 글로벌 인덱스가 무효화되지 않도록 Drop 작업에 인덱스 갱신 옵션을 함께 적용하고, 로컬 인덱스를 우선 검토할 필요가 있다.
3. 특정 파티션에 트래픽이 몰리는 핫스팟은 파티션 키를 정하는 단계에서 복합 분할을 적용해 완화하는 것이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : 파티셔닝은 물리적 분할과 파티션 프루닝으로 대용량 데이터의 관리성·성능·가용성을 확보하는 기술임.
- 시사점 : 4대 전략의 선택, 로컬과 글로벌 인덱스의 트레이드오프, 프루닝 조건과 한계 대응을 함께 설계해야 효과가 유지됨.
