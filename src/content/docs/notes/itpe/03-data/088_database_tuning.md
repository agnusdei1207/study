## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터베이스 성능 → **데이터베이스 튜닝**

## 30초 인출

- 본질: 데이터베이스 튜닝은 응답·처리 성능을 측정하고 병목을 찾아 개선하는 작업
- 메커니즘: 대표 부하로 지연 분포(p95)와 처리량의 기준선을 측정하고, 느린 질의와 대기 구간을 분리해 원인에 맞는 변경을 하나씩 적용한 뒤 같은 부하로 재측정해 확정 또는 롤백
- 통찰: 평균 응답과 계획상 비용은 실제 개선을 보장하지 않고 인덱스는 쓰기 비용을 늘리므로, 지연 분포와 읽기·쓰기 부하를 같은 조건에서 전후 비교

<details>
<summary>핵심 용어</summary>

- **튜닝(Tuning)** : 성능 병목을 찾아 개선하는 활동
- **기준선(Baseline)** : 변경 전 성능의 측정 기준
- **p95 지연** : 요청의 95%가 이 시간 안에 처리되는 지연
- **실행계획(Execution Plan)** : DBMS가 질의를 처리하는 경로
- **논리 읽기** : 버퍼에서 읽은 블록 수
- **통계 갱신** : 옵티마이저가 쓰는 데이터 분포 정보를 최신화하는 작업
- **회귀(Regression)** : 변경 후 성능이나 기능이 나빠지는 것

</details>

## 2~4교시 25점 답안

## Ⅰ. 데이터베이스 튜닝의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터베이스 튜닝** 은 응답·처리 성능을 측정하고 병목을 개선하는 작업 |
| 목적 | 업무 부하에 맞는 자원 사용과 예측 가능한 질의 성능 확보 |

## Ⅱ. 특징

| 특징 | 관찰 대상 | 의미 |
|---|---|---|
| 업무 부하 의존 | 대표 SQL·동시성·데이터 분포 | 같은 설정도 업무마다 효과가 다름 |
| 계층 간 영향 | SQL·인덱스·DBMS·저장장치 | 한 계층의 개선이 다른 계층의 비용을 바꿈 |
| 실측 검증 | 지연 분포·처리량·자원·오류 | 예상 비용보다 실제 전후 결과 우선 |

## Ⅲ. 튜닝 절차

```text
대표 읽기·쓰기 부하로 p95·처리량 기준선 측정
        ↓ 느린 질의·대기 구간 분리
 ├ 계획 행 수와 실제 행 수의 차이 → 통계·접근/조인 경로 검토
 └ CPU·I/O·잠금 대기 집중 → 자원·경합 검토
        ↓ 원인에 맞는 변경 한 가지 적용
같은 부하로 재측정 ─ 목표 달성 → 확정
                    └ 효과 없음·회귀 → 롤백·다른 원인 분석
```

## Ⅳ. 튜닝 영역과 조정 항목

| 영역 | 점검 | 대표 조정 |
|---|---|---|
| 데이터 모델 | 중복·관계·증가량·접근 빈도 | 정규화·반정규화 검토, 파티션·저장 구조 |
| DBMS·인프라 | CPU·메모리·디스크·세션·대기 | 용량·설정·배치 시간 조정, 경합 완화 |
| SQL·인덱스 | 실행계획·조건절·조인·정렬·논리 읽기 | SQL 수정, 통계 갱신, 인덱스 추가·변경·제거 |

인덱스는 조회 경로를 줄이지만 저장 공간과 DML 비용이 늘며, 인덱스 열을 가공하는 조건은 표현식 인덱스 등 DBMS 기능에 따라 대응.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 평균 응답만 보면 느린 요청이 가려짐 | p95 등 지연 분포와 처리량 함께 측정 |
| 조회용 인덱스가 쓰기·저장 비용 증가 | 읽기·쓰기 부하를 같은 조건에서 전후 비교, 롤백 기준 설정 |
| 계획상 비용 감소를 실제 개선으로 오인 | 실행계획과 실제 행 수·대기 시간 대조, 부하 시험 |

## Ⅵ. 제언

기준선 측정 → 원인 분리 → 한 번에 하나의 변경 → 동일 부하 재측정을 반복

```text
기준선 → 병목 분리 → 변경 1건 → 재측정 → 확정·롤백 → 기록
```

| 구분 | 경험 기반 일괄 변경 | 제언: 측정 기반 단계 변경 |
|---|---|---|
| 원인 파악 | 불명확 | 변경별 효과 확인 |
| 회귀 위험 | 큼 | 롤백 기준 |
