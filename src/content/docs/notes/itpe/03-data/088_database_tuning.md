## 연관 키워드

**데이터베이스 튜닝**, **병목 분석**, **실행계획**, **인덱스**, **조인**, **대기 이벤트**, **성능 기준선**

## Ⅰ. 개요

- 핵심 요약 : **데이터베이스 튜닝**은 관측된 병목을 분석하고 SQL·설계·자원 설정을 조정해 서비스 성능을 개선하는 활동이다.
- 목표 : 응답시간·처리량·자원 사용과 안정성 간의 균형 확보.
- 원칙 : 측정과 실행계획에 근거해 변경하고, 변경 전후를 같은 조건으로 비교한다.

## Ⅱ. 특징 및 장점

- 핵심 요약 : **SQL·데이터 구조·인덱스·DBMS 자원**을 계층적으로 점검해 병목 원인을 구체화한다.
- **근거 기반** : 실행계획·대기 이벤트·상위 SQL로 병목 가설을 세운다.
- **다계층 개선** : 쿼리, 스키마·인덱스, 설정·인프라 순서로 원인을 좁힌다.
- **지속 관리** : 워크로드와 데이터량 변화에 따라 성능 기준선을 갱신한다.
- 튜닝 효과는 워크로드·DBMS·데이터 분포에 따라 다르며 특정 계층이 항상 가장 큰 효과를 내는 것은 아니다.

## Ⅲ. 진단 및 개선 흐름

- 핵심 요약 : **기준선 측정 → 병목 확인 → 변경 가설 → 통제된 적용 → 회귀 검증**으로 반복한다.

```text
[서비스 SLO·성능 기준선]
          ▼
[상위 SQL·대기·자원 측정]
          ▼
[실행계획·데이터 분포 분석]
          ▼
[SQL·인덱스·설정 변경]
          ▼
[부하·정합성·회귀 검증]
          ▼
[성과 기록·지속 모니터링]
```

- Explain Plan과 실제 실행 통계의 차이를 확인하고, 대표 데이터·파라미터 조건을 사용해 재현한다.
- 변경은 한 번에 가능한 한 한 요인씩 적용해 원인과 효과를 구분한다.

## Ⅳ. 주요 튜닝 대상 비교

- 핵심 요약 : **실행계획의 접근·조인·정렬 비용**을 워크로드에 맞게 평가한다.

| 대상 | 확인 항목 | 선택·개선 기준 |
|---|---|---|
| SQL | 불필요한 조회·반복 연산 | 결과 동일성·호출 빈도 |
| 인덱스 | 선택도·컬럼 순서·유지 비용 | 읽기 개선과 쓰기 비용 균형 |
| Nested Loop | 외부 행 수·내부 인덱스 접근 | 작은 입력과 효율적 인덱스 |
| Hash Join | 메모리·해시 spill | 대량 동등 조인 등 |
| Sort/Merge | 정렬 비용·입력 정렬 상태 | 정렬·범위 조건 적합성 |
| DBMS 자원 | CPU·메모리·I/O·대기 | 병목 증거가 있을 때 조정 |

- 조인 방식과 인덱스 사용은 옵티마이저·데이터 분포·제품 구현에 따라 달라진다.

## Ⅴ. 한계와 방안

- 핵심 요약 : **측정 오류·인덱스 부작용·실행계획 변화·하드웨어 의존**을 관리한다.
- **불완전한 진단** → 피크 시간과 실제 파라미터를 포함한 기준선을 수집한다.
- **인덱스 과다** → 읽기 성능뿐 아니라 삽입·갱신·저장 공간 비용도 측정한다.
- **통계정보 변화** → 갱신 이후 실행계획과 핵심 SQL 성능을 재검증한다.
- **용량 증설만 반복** → SQL·데이터 모델·잠금·자원 병목을 구분해 근본 원인을 해결한다.

```text
잘못된 기준선 → 실제 워크로드 수집
인덱스 부작용 → 읽기·쓰기 함께 측정   → 지속 가능한 성능 개선
계획 변화     → 통계·회귀 검증
```

## Ⅵ. 기술사적 제언

- 핵심 요약 : **성능 개선을 SLO와 변경관리**에 연결해 안전하게 운영한다.
- 응답시간 백분위, 처리량, 오류율, 대기시간, 자원 사용을 함께 기록한다.
- 부하 시험·카나리 적용·롤백 기준을 마련하고 성능과 데이터 정합성을 확인한다.
- DBMS별 진단 도구와 로그의 해석 범위를 문서화하고 민감한 SQL 값을 보호한다.

## Ⅶ. 결론

- 핵심 요약 : 데이터베이스 튜닝은 증설보다 먼저 **측정·실행계획·검증을 바탕으로 병목을 개선하는 과정**이다.
- 답안에는 튜닝 계층, 진단 흐름, 인덱스·조인 선택과 변경 후 회귀 검증을 연결한다.
