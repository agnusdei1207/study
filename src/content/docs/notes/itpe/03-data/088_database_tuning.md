## Ⅰ. 데이터베이스 튜닝의 개요

- 핵심 요약 : 데이터베이스 튜닝은 측정된 병목을 실행계획·스키마·인덱스·쿼리·자원 설정에서 찾아 성능목표에 맞게 개선하는 과정.
- 개념 : 데이터베이스 튜닝은 측정된 병목을 실행계획·스키마·인덱스·쿼리·자원 설정에서 찾아 성능목표에 맞게 개선하는 과정.
- 배경 및 필요성 : 응답지연·처리량·경합이 업무 SLO와 운영비용에 영향.
- 주요 목적 : DB 자원·구조·질의 경로의 효율과 안정성 향상.

## Ⅱ. 데이터베이스 튜닝의 특징 및 장점

- 핵심 요약 : 측정 우선: 기준선·부하·대기 이벤트 확인 → 원인 기반 개선; 계획 분석: 실제 실행계획·통계 확인 → 스캔·조인·정렬 병목 파악; 회귀 통제: 변경 전후 동일 부하 재현 → 성능·정합성 확인.

1. 측정 우선: 기준선·부하·대기 이벤트 확인 → 원인 기반 개선
2. 계획 분석: 실제 실행계획·통계 확인 → 스캔·조인·정렬 병목 파악
3. 회귀 통제: 변경 전후 동일 부하 재현 → 성능·정합성 확인

## Ⅲ. 데이터베이스 튜닝의 구조 (흐름)

- 핵심 요약 : SLO·기준선 설정 → 상위 쿼리·대기·자원 수집 → 실행계획·통계·스키마 분석 → 한 번에 한 변경 적용 → 부하·회귀시험·관측.

```text
SLO·기준선 설정
  ↓
상위 쿼리·대기·자원 수집
  ↓
실행계획·통계·스키마 분석
  ↓
한 번에 한 변경 적용
  ↓
부하·회귀시험·관측
```

- 핵심 구성 : 요청 → 쿼리 → 옵티마이저 계획 → I/O·CPU·잠금 → 지연·대기 측정 → 병목 개선

```text
요청 → 쿼리 → 옵티마이저 계획 → I/O·CPU·잠금 → 지연·대기 측정 → 병목 개선
```

## Ⅵ. 데이터베이스 튜닝의 제언

- 핵심 요약 : DBA는 서비스 SLO·상위 SQL·대기 이벤트를 기준으로 우선순위화하고 모든 튜닝 변경에 재현 가능한 기준선·롤백을 남김.
- 실행 제안 : DBA는 대표 데이터·동시성·캐시상태를 포함한 기준 부하를 재현해 계획 변경 전후 SLO와 롤백 조건 기록.

## Ⅶ. 데이터베이스 튜닝의 결론

- 핵심 요약 : 튜닝은 설정값을 많이 바꾸는 일이 아니라 측정으로 병목을 좁혀 작은 변경을 검증하는 성능개선 루프.
- 시사점 : 성능개선은 대표 부하의 동일 기준선과 변경 후 회귀검증을 통해서만 확인 가능.
