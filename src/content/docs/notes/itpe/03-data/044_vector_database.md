```text

 ┃
 ┣━ Ⅰ 개요 ───── 비정형 데이터(텍스트·이미지 등)를 임베딩 벡터로 변환하여 고차원 공간에서 유사도 기반 검색 수행
 ┣━ Ⅱ 특징 ───── 고차원 밀집 벡터 저장 · 근사 최근접 이웃(ANN) 탐색 · 유사도 메트릭(코사인·유클리드) · 메타데이터 필터링
 ┣━ Ⅲ 구조 ───── 임베딩 엔진 / 벡터 인덱스(HNSW, IVF, ScaNN) / 메타데이터 스토어 / 쿼리 파서 및 실행기
 ┣━ Ⅳ 흐름 ───── ① 비정형 데이터 입력 → ② 임베딩 모델 변환 → ③ 고차원 벡터 인덱싱 → ④ 유사도 검색 쿼리 → ⑤ k-NN 결과 반환
 ┣━ Ⅴ 비교 ───── HNSW vs IVF (그래프 기반 고정확도/고메모리 vs 클러스터링 기반 저메모리/빠른 색인)
 ┗━ Ⅵ 실무 ───── 차원의 저주로 인한 탐색 지연 / 과도한 메모리 점유 비용 / 메타데이터 필터링 성능 저하
```
- 필수 키워드: 고차원 임베딩 · ANN(Approximate Nearest Neighbor) · HNSW · IVF · 코사인 유사도 · RAG(검색 증강 생성) · 밀집 벡터(Dense Vector)
- 기출: 137회 4교시 2번 `벡터 DB의 효율적 검색을 위한 HNSW와 IVF 동작원리` → Ⅲ 색인 구조 + Ⅴ HNSW/IVF 비교

## 한 줄 본질
- 키워드 일치 방식의 텍스트 검색 한계 → 고차원 의미 공간(Embedding Space) 투영 후 근사 최근접 이웃(ANN) 그래프·역색인 탐색 → 의미적 맥락 검색 실현 / 고차원 메모리 비용 수반

## 핵심 용어
- ANN(Approximate Nearest Neighbor): 전수 조사(Exact k-NN)의 시간 복잡도 $O(N)$을 $O(\log N)$ 수준으로 낮추기 위해 약간의 정확도를 희생하고 속도를 극대화한 탐색 알고리즘
- HNSW(Hierarchical Navigable Small World): 다계층 스킵리스트 구조를 그래프 공간에 적용해 고속 탐색을 수행하는 그래프 기반 ANN 알고리즘

## 핵심 통찰
- 벡터 검색은 100% 완벽한 일치를 보장하지 않음 → ANN은 확률적 근사이므로 재현율(Recall)과 쿼리 레이턴시 사이의 트레이드오프 조정이 핵심
- 단순 벡터 유사도만으로는 최신성, 사용자 권한, 카테고리 같은 정형 조건을 만족하지 못함 → 벡터 인덱싱과 관계형 메타데이터 필터링을 결합하는 '하이브리드 검색' 필수
- 고차원(1536차원 등) 벡터 수백만 건은 RAM을 극도로 소모 → 스토리지 계층화 및 곱 양자화(Product Quantization, PQ) 없이는 인프라 비용 감당 불가

## 딸려 나오는 하위 토픽
| 하위 토픽 | 상위 구조 속 위치 | 한 줄 |
|---|---|---|
| IVF(Inverted File Index) | 공간 분할 기반 ANN 인덱스 | 벡터 공간을 보로노이 셀로 클러스터링한 후 해당 셀의 역색인 리스트만 탐색 |
| 코사인 유사도(Cosine Similarity) | 벡터 간 거리 측정 메트릭 | 두 벡터의 크기를 배제하고 사잇각의 코사인 값을 계산하여 방향적 의미 일치도 판정 |

## 이웃 토픽과 구분
- 벡터 DB vs 전문 검색 엔진(Elasticsearch): 벡터 DB = 고차원 임베딩 의미적 유사도 검색 / 전문 검색 엔진 = 역색인(Inverted Index) 기반 키워드 형태소 일치 검색

## 문제·원인·대책
- 적용 상황: 사내 지식 기반 생성형 AI(RAG) 챗봇 구축
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 벡터 데이터 증가 시 검색 레이턴시가 500ms 이상으로 급증 | 인덱스가 메모리 한계를 초과하여 디스크 스왑 발생 | HNSW 대신 IVF-PQ(곱 양자화) 적용으로 벡터 압축 | 메모리 사용량 80% 절감, 응답속도 50ms 회복 |
| 특정 프로젝트 문서만 검색해야 하나 타 부서 문서 혼입 | 순수 벡터 유사도만으로 검색하여 메타데이터 격리 누락 | Pre-filtering(메타데이터 조건 선반영 후 벡터 탐색) 구현 | 데이터 보안 및 권한 격리 준수 |
