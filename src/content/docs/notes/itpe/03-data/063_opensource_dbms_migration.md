## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터베이스 운영 → **오픈소스 DBMS 전환**

## 30초 인출

- 본질: 오픈소스 DBMS 전환은 기존 DB의 데이터·스키마·응용 연계를 대상 오픈소스 DBMS로 옮기고 운영을 넘기는 작업
- 메커니즘: 의존성과 호환성을 분석해 스키마·SQL을 변환하고, 전체 적재와 변경분 동기화(CDC)로 데이터를 옮긴 뒤 데이터·기능·성능을 검증해 쓰기 통제·최종 동기화·접속 전환(컷오버)을 하고 실패 시 복귀
- 통찰: 자료형·SQL 방언·격리 동작이 DBMS마다 달라 이관 완료가 곧 업무 성공이 아니므로 대표 업무로 회귀 시험하고 승인 기준과 복귀 조건을 리허설한 뒤 컷오버

<details>
<summary>핵심 용어</summary>

- **DBMS 마이그레이션** : 데이터·스키마·응용을 다른 DBMS로 이전하는 작업
- **호환성 분석** : 자료형·SQL·기능·응용 연계의 차이를 조사하는 활동
- **CDC(Change Data Capture)** : 원천 DB의 변경분을 포착해 대상에 적용하는 기법
- **컷오버(Cutover)** : 업무 접속을 원천에서 대상으로 전환하는 시점의 절차
- **회귀 테스트** : 변환 후에도 기존 기능과 결과가 같은지 확인하는 시험
- **SQL 방언** : DBMS마다 다른 SQL 문법·함수

</details>

## 2~4교시 25점 답안

## Ⅰ. 오픈소스 DBMS 전환의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **오픈소스 DBMS 전환** 은 기존 DB의 데이터·스키마·응용 연계를 오픈소스 DBMS로 이전하고 운영을 전환하는 작업 |
| 목적 | 데이터와 응용 기능을 유지하며 지속 가능한 운영 기반 확보 |

## Ⅱ. 특징과 전환 배경

| 특징 | 전환 영향 |
|---|---|
| 이기종 호환성 | 자료형·SQL·저장 기능·격리 동작 변환·검증 |
| 데이터 연속성 | 전체 적재와 변경분 동기화의 정합성 관리 |
| 업무 컷오버 | 기능·성능·복귀 기준을 충족한 뒤 접속 전환 |

| 전환 배경 | 내용 |
|---|---|
| 비용 | 라이선스·유지보수 비용 부담 |
| 종속성 | 특정 벤더 기능·정책에 대한 의존 |
| 기술 환경 | 클라우드·컨테이너 등 운영 환경 변화 |

## Ⅲ. 단계별 마이그레이션 절차

```text
객체·SQL·응용 의존성 분석 → 스키마·기능 변환
                              ↓
원천 DB ── 초기 적재 + CDC 변경분 동기화 ──→ 대상 DB
                              ↓
데이터·기능·성능 검증 → 승인 → 쓰기 통제 → 최종 동기화 → 접속 전환
                                              └ 실패 시 복귀
```

| 순서 | 활동 | 판단 자료 |
|---|---|---|
| 1. 사전 분석 | 범위·의존성·호환성 조사 | 객체·업무·위험 목록 |
| 2. 변환·개발 | 스키마·SQL·DB 기능 변환 | 변환 결과·미전환 항목 |
| 3. 적재·동기화 | 전체 적재, 변경 반영 | 진행·복제 지연 |
| 4. 검증 | 데이터·기능·성능·운영 절차 점검 | 불일치·결함 처리 내역 |
| 5. 컷오버 | 쓰기 통제·최종 동기화·전환 | 승인 기준·복귀 조건 |

## Ⅳ. 제약사항(호환성 검토)

| 영역 | 확인 항목 |
|---|---|
| 데이터·스키마 | 자료형·제약·인덱스·파티션·대용량 객체 |
| DB 기능 | 저장 프로시저·트리거·함수·권한·스케줄 |
| 응용 연계 | SQL 방언·드라이버·트랜잭션·격리 수준 의존 |
| 운영 요구 | 부하 특성·백업·복구·가용성·보안 |

자동 변환 결과에도 수작업 수정이 남을 수 있어 변환 보고서와 응용 코드를 함께 점검.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 자료형·함수·SQL 동작 차이로 기능 불일치 | 대표 업무 SQL·트랜잭션의 회귀 테스트와 결과 비교 |
| 적재·CDC 중 불일치·복제 지연 | 건수·표본·업무 규칙 검증과 지연 감시 |
| 전환 후 복귀 시 신규 변경 미반영 | 복귀 시점 쓰기 정책과 재전환 절차를 사전 설계·훈련 |
| 이관 완료를 업무 성공으로 오인 | 업무별 승인 기준과 리허설 근거로 컷오버 판단 |

## Ⅵ. 제언

호환성 분석과 회귀 시험, 컷오버 리허설을 거쳐 승인 기준을 충족한 뒤 전환하고 고가용성 구성으로 운영 신뢰성을 확보

```text
분석 → 변환 → 적재·CDC → 회귀·성능 검증 → 리허설 → 컷오버(복귀 조건 포함) → HA 운영
```

| 구분 | 일괄 전환 | 제언: 검증·리허설 후 전환 |
|---|---|---|
| 위험 | 전환 후 결함 발견 | 사전 발견 |
| 복귀 | 준비 부족 | 복귀 조건 훈련 |
