## 지식 로드맵 내 현재 위치

<div class="itpe-topic-path" aria-label="지식 경로"><span>데이터 관리</span><span>거버넌스·책임체계</span><strong>데이터 거버넌스</strong></div>

## 큰 그림과 30초 인출

```text
[비즈니스 전략·규제·데이터 가치]
                 │
                 ▼
       [의사결정권·원칙·정책]
          │        │        │
          ▼        ▼        ▼
       조직/R&R  프로세스   기준·통제
       CDO/Owner  표준·품질  보안·생명주기
          └────────┬────────┘
                   ▼
      Catalog·Metadata·Lineage·MDM·DQ
                   ▼
         [신뢰 가능한 활용·성과]
```

- 본질: **데이터에 관한 의사결정권·책임·원칙·통제를 정하여 가치와 위험을 함께 관리하는 전사 운영체계**
- 암기: `원-조-프-기-성` = 원칙 → 조직 → 프로세스 → 기술 → 성과
- 구분: 거버넌스는 누가 무엇을 결정하는지, 데이터 관리는 그 결정을 어떻게 실행하는지에 초점

## 예상문제

> 데이터 거버넌스의 개념과 구성요소, 조직별 역할 및 구축절차를 설명하고 중앙집중형과 연합형 거버넌스의 적용방안을 논하시오. (25점)

## Ⅰ. 데이터의 의사결정권과 책임을 정하는 거버넌스 개요

- 정의: 데이터 거버넌스는 데이터의 가치 극대화와 위험 통제를 위해 원칙·정책·의사결정권·책임·프로세스·성과기준을 수립하고 운영하는 체계
- 목적: 데이터 사일로·정의 불일치·품질 저하·권한 오남용을 줄이고 신뢰 가능한 재사용과 규제 준수 확보
- 필요성: 도구와 플랫폼만 통합해도 부서별 소유권·정의·승인 기준이 다르면 동일 데이터의 의미와 책임이 일치하지 않음

## Ⅱ. 통제와 활용을 함께 추구하는 거버넌스 특징

| 특징 | 핵심 내용 | 성공 조건 |
|---|---|---|
| 전사 정렬 | 데이터 목표를 경영·업무 목표와 연결 | 경영진 후원·명확한 가치 |
| 책임 명확화 | Owner·Steward·Custodian 역할 구분 | 결정권·에스컬레이션 정의 |
| 정책 기반 | 표준·품질·접근·보존 원칙 수립 | 예외·변경 절차 포함 |
| 생명주기 관리 | 생성부터 폐기까지 통제 | 계보·보존·삭제 증적 |
| 성과 중심 | 준수뿐 아니라 탐색·재사용·품질 성과 측정 | 업무 KPI와 연계 |

## Ⅲ. 원칙·조직·프로세스·기술·성과의 구성체계

| 구성요소 | 핵심 내용 | 대표 산출물·도구 |
|---|---|---|
| 원칙·정책 | 소유·공유·품질·보안·보존 기준 | 정책·표준·데이터 원칙 |
| 조직·R&R | 의사결정·소유·관리·기술 책임 | 위원회·CDO·Owner·Steward |
| 프로세스 | 표준·품질·접근·이슈·변경·생명주기 | 워크플로·이슈대장·SLA |
| 기술·정보 | 발견·이해·추적·통제 지원 | Catalog·Metadata·Lineage·MDM |
| 성과·감사 | 정책 준수와 업무가치 측정 | KPI·대시보드·감사보고 |

```text
위원회: 원칙·우선순위·분쟁 결정
CDO: 전사 전략·운영 총괄
Data Owner: 도메인 데이터의 최종 책임·승인
Data Steward: 정의·품질·메타데이터의 일상 관리
Custodian: 플랫폼·보안·백업 등 기술 운영
Consumer: 정책에 따라 사용하고 이슈 피드백
```

## Ⅳ. 가치 중심 데이터 거버넌스 구축절차

```text
① 현황·문제·규제 진단 → ② 비전·원칙·우선 도메인
 → ③ 운영모델·R&R → ④ 정책·표준·프로세스
 → ⑤ Catalog·DQ·MDM 도구 적용 → ⑥ 성과·감사·개선
```

| 단계 | 핵심 활동 | 완료 기준 |
|---|---|---|
| 진단 | 사일로·품질·권한·규제·활용 장애 식별 | 문제와 업무 영향 연결 |
| 설계 | 중앙/연합 운영모델과 결정권 정의 | RACI·위원회·분쟁절차 |
| 실행 | 우선 데이터 제품에 정책·메타데이터·품질 적용 | Owner와 기준·증적 존재 |
| 확산 | 재사용 가능한 표준·자동통제 확대 | 도메인 간 상호운용 |
| 개선 | 품질·탐색시간·재사용·위험 지표 검토 | KPI 기반 정책 갱신 |

## Ⅴ. 중앙집중형·분산형·연합형 비교

| 구분 | 중앙집중형 | 분산형 | 연합형(Federated) |
|---|---|---|---|
| 결정권 | 중앙 조직 | 각 도메인 | 공통 원칙은 중앙, 실행은 도메인 |
| 강점 | 일관성·규제 대응 | 민첩성·업무 전문성 | 일관성과 자율성 균형 |
| 한계 | 병목·현업 이탈 | 중복·정의 불일치 | 경계·상호운용 설계 필요 |
| 적합 | 강한 규제·초기 표준화 | 독립 사업단위 | 다도메인·Data Mesh 환경 |
| 통제 | 사전 승인 중심 | 도메인 책임 중심 | Policy as Code·공통 인터페이스 |

- 선택 기준: 데이터 위험·도메인 자율성·조직 성숙도·공유 빈도를 고려하고 단일 모델을 전사에 강제하지 않음

## Ⅵ. 문서 거버넌스를 실행 거버넌스로 바꾸는 고려사항

| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 메타데이터가 오래됨 | 등록 책임·변경연계 부재 | DDL·파이프라인에서 메타데이터·계보 자동 수집 | 현행성 확보 |
| Owner가 명목상 존재 | 결정권·성과·시간 배정 없음 | 승인권·KPI·에스컬레이션을 직무에 반영 | 실질 책임 확보 |
| 중앙 승인이 병목 | 모든 변경을 동일 절차로 통제 | 위험기반 차등 승인·연합형 운영·정책 자동검증 | 민첩성 유지 |
| 이용자는 카탈로그를 안 씀 | 검색 결과에 품질·접근·예제가 없음 | 품질점수·Owner·사용예·접근신청 통합 | 데이터 발견·재사용 향상 |
| 통제 성과만 측정 | 업무 가치와 연결되지 않음 | 탐색시간·재사용·오류비용·규제위험 KPI 병행 | 투자 정당성 확보 |

## Ⅶ. 통제기관이 아닌 데이터 제품의 신뢰기반으로 전환

- **[공통 정책과 도메인 책임의 연합형 운영]**: 중앙팀이 모든 데이터 변경을 승인하면 병목이 되고, 도메인 자율만 두면 상호운용성이 붕괴
- 나라면: 중앙은 식별·보안·품질·상호운용 정책을 코드화하고 도메인 Owner는 데이터 제품과 SLO를 책임지며, 카탈로그에서 준수·품질·사용성과를 함께 공개

#### 한줄 요약

- 데이터 거버넌스의 성과는 통제 문서 수가 아니라 신뢰할 데이터를 더 빨리 찾고 안전하게 재사용하는 능력임

## 1교시 10점 답안 발췌

```text
전략·규제 → 원칙·조직·프로세스 → Catalog·DQ·MDM → 신뢰·활용성과
```

| 역할 | 책임 |
|---|---|
| Owner | 도메인 데이터의 최종 의사결정·승인 |
| Steward | 정의·품질·메타데이터의 일상 관리 |
| Custodian | 플랫폼·보안·백업의 기술 운영 |

- 차별화: 공통 정책은 중앙, 데이터 제품은 도메인이 책임지는 연합형 모델과 Policy as Code 적용
