## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터 관리 → **데이터 거버넌스**

## 30초 인출

- 본질: 데이터 거버넌스는 데이터의 관리·이용에 관한 의사결정 권한과 책임, 정책·표준·절차를 정해 조직 전체가 일관되게 데이터를 다루게 하는 체계
- 메커니즘: 데이터 책임자와 관리 담당자를 지정하고 표준·품질·보안 정책을 정해 메타데이터와 계보로 실행 결과를 추적
- 통찰: 정책만 만들고 책임자가 없으면 현업이 따르지 않으므로 핵심 데이터 영역별로 책임자를 지정하고 품질·접근 정책을 실제 시스템에 적용해 점검

<details>
<summary>핵심 용어</summary>

- **데이터 거버넌스(Data Governance)** : 데이터 관리에 관한 권한·책임·정책·절차를 정한 체계
- **데이터 책임자(Data Owner)** : 업무 관점에서 데이터의 정의·품질·이용에 책임지는 사람
- **데이터 관리 담당자(Data Steward)** : 표준과 품질 규칙을 일상적으로 적용·점검하는 담당자
- **데이터 표준** : 데이터 명칭·정의·형식·코드를 공통으로 쓰기 위한 규칙
- **메타데이터** : 데이터의 뜻·구조·출처·책임·이용 조건을 설명하는 정보
- **데이터 계보(Lineage)** : 데이터가 원천에서 가공·제공되기까지의 흐름과 이력
- **DAMA-DMBOK** : 데이터 관리 지식 영역을 정리한 프레임워크

</details>

## 2~4교시 25점 답안

## Ⅰ. 데이터 거버넌스의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터 거버넌스** 는 데이터 관리에 관한 권한·책임·정책·절차를 정한 체계 |
| 목적 | 데이터의 일관된 관리와 신뢰성·활용성 확보 |

## Ⅱ. 개별 데이터 관리와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 조직 차원의 결정 체계 | 부서별이 아닌 전사 책임 구조 |
| 정책 중심 | 표준·품질·보안 규칙의 명문화 |
| 지속 점검 | 준수 여부의 측정과 개선 |

## Ⅲ. 구성 체계

```text
데이터 거버넌스
    ├─ 조직 ── 데이터 책임자 · 관리 담당자 · 협의체
    ├─ 정책·표준 ── 데이터 표준 · 품질 · 보안 · 이용
    ├─ 프로세스 ── 표준 관리 · 품질 점검 · 접근 승인
    └─ 지원 도구 ── 메타데이터 · 계보 · 카탈로그
```

## Ⅳ. 관리 영역

| 영역 | 내용 |
|---|---|
| 데이터 표준 | 명칭·형식·코드의 공통 규칙 |
| 데이터 품질 | 품질 기준과 점검 |
| 메타데이터·계보 | 데이터 의미와 흐름의 추적 |
| 보안·접근 | 권한과 이용 조건 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 책임자 없이 정책만 있어 현업이 준수하지 않음 | 핵심 데이터 영역별 책임자 지정 |
| 정책과 실제 시스템의 불일치 | 정책을 시스템 규칙과 카탈로그에 반영 |
| 준수 여부의 미측정 | 품질·접근 점검 지표를 정해 정기 보고 |

## Ⅵ. 제언

핵심 데이터 영역부터 책임자를 지정하고 정책을 시스템에 적용해 준수를 점검

```text
핵심 데이터 영역 선정 → 책임자 지정 → 정책을 시스템에 적용 → 준수 지표 점검
```

| 구분 | 정책 문서만 작성 | 제언: 책임자·시스템 적용 |
|---|---|---|
| 준수 | 현업 재량 | 시스템 규칙으로 통제 |
| 책임 | 불명확 | 영역별 지정 |

## 출제 이력과 검증 출처
