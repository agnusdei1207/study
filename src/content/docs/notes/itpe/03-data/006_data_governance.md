## 연관 키워드

- 데이터 거버넌스(Data Governance), CDO, 데이터 스튜어드(Data Steward), 메타데이터 관리, 데이터 리니지(Lineage)
- 데이터 사일로, SSOT, RBAC·ABAC, Data Mesh, Active Metadata, 데이터 리터러시

## Ⅰ. 데이터 거버넌스의 개요

- 핵심 요약 : 전사 데이터 자산의 가용성·유용성·무결성·보안성을 보장하는 종합 관리 체계.
- 개념 : 기업이 보유한 데이터 자산의 가용성(Availability), 유용성(Usability), 무결성(Integrity), 보안성(Security)을 보장하기 위해 원칙, 정책, 프로세스, 조직, 기술을 종합적으로 갖춘 관리 체계인 **데이터 거버넌스** (Data Governance).
- 배경 및 필요성 :
  1. 부서별 독립 시스템에 따른 데이터 사일로(Silo)가 심화되어 중복과 표준 불일치가 생기고, 전사 단일 진실 공급원(SSOT, Single Source of Truth)이 없음.
  2. 개인정보 보호 규제가 강화되어 GDPR(General Data Protection Regulation)과 국내 개인정보보호법 등 프라이버시 보호 의무가 커짐.
  3. 생성형 인공지능의 확산으로 고품질 데이터 공급 없이는 대규모 언어 모델(LLM, Large Language Model)의 파인튜닝이나 검색 증강 생성(RAG, Retrieval-Augmented Generation) 시스템의 신뢰성을 확보하기 어려움.
- 주요 목적 : 데이터 전 생명주기의 통제를 통해 품질을 높이고, 컴플라이언스 리스크를 관리하며, 비즈니스 가치 창출을 앞당기는 것.

## Ⅱ. 데이터 거버넌스의 특징 및 장점

- 핵심 요약 : 5대 구성 요소와 3계층 조직 체계, 전 생명주기 통제가 결합되어 데이터의 신뢰와 활용을 함께 확보하는 방식.

1. 5대 구성 요소 : 데이터 표준화, 데이터 품질관리, 메타데이터 관리, 보안·규제 준수, 데이터 라이프사이클 관리가 하나의 체계로 움직임 → 영역 간 정책 충돌 감소.
2. 3계층 조직 : 거버넌스 위원회, **데이터 스튜어드** (Data Steward), 데이터 커스토디언·엔지니어로 역할을 나눔 → 정책 결정과 현업 책임, 기술 운영의 분담 명확화.
3. 전 생명주기 통제 : 생성부터 폐기까지 정책과 기술 조치를 연결 → 데이터 품질과 보존 기한 관리의 빈틈 축소.
4. 규제 대응 내재화 : 프라이버시·보안 정책을 프로세스에 자동으로 연계 → 사후 적발 대신 사전 통제.
5. 가치 창출 지향 : 신뢰할 수 있는 데이터를 분석과 AI에 공급 → 의사결정과 모델의 신뢰성 향상.

## Ⅲ. 데이터 거버넌스의 구조 (흐름)

- 핵심 요약 : 전략과 리더십 아래 5대 도메인이 놓이고, 조직 체계가 이를 운영하는 구조이며, 거버넌스 모델은 중앙집중형에서 페더레이션 방식으로 진화하는 흐름.

```text
[ 데이터 거버넌스 프레임워크 ]

 데이터 전략 및 리더십 (경영진)
          ↓
 1. 데이터 표준화
 2. 데이터 품질관리
 3. 메타데이터·리니지 관리
 4. 보안·규제 준수
 5. 데이터 라이프사이클 관리
          ↓
 조직·역할 (위원회, 스튜어드, 엔지니어)
```

```text
[ 거버넌스 모델의 진화 ]

 중앙집중형 거버넌스
   전사 데이터팀이 정책·표준을 독점
          ↓ 승인 병목 해소 필요
 페더레이션 거버넌스 (Data Mesh)
   도메인이 데이터를 제품으로 운영
   전사 표준은 플랫폼에서 자동 강제
```

| 구성 영역 | 핵심 관리 항목 | 주요 활동 및 산출물 |
|---|---|---|
| 데이터 표준화 | 표준 단어, 표준 용어, 도메인, 표준 코드 | 전사 데이터 사전, 코드 매핑 테이블, 명명 규칙 |
| 데이터 품질 | 정확성, 완전성, 일관성, 유효성 SLA(Service Level Agreement) | 품질 지표 측정, 결함 원인 분석, 자동 정제 파이프라인 |
| 메타데이터·리니지 | 비즈니스 카탈로그, 스키마 정의, 데이터 흐름 | 메타데이터 저장소 MDR(Metadata Repository), 종단간 계보(Lineage) 그래프 |
| 보안·프라이버시 | RBAC(Role-Based Access Control)·ABAC(Attribute-Based Access Control), 암호화, 가명화 | 보안 정책, 접근 감사 로그, 개인정보 영향평가 |
| 라이프사이클 | 수집, 보존 기한, 계층형 스토리지, 완전 파기 | 수명주기 분류 체계, 핫·콜드 데이터 티어링 정책, 영구 삭제 절차 |

- 조직 체계 및 역할 :
  1. 거버넌스 위원회(Council) : 최고데이터책임자(CDO, Chief Data Officer) 주관으로 전사 정책을 결정하고 부서 간 이해관계를 조정.
  2. 데이터 스튜어드 : 현업 부서의 비즈니스 데이터 오너로서 데이터 정의와 품질 요구사항을 제시.
  3. 데이터 커스토디언(Data Custodian)·엔지니어 : 물리적 저장, 백업, 보안, 파이프라인 기술 운영을 담당.
- 액티브 메타데이터(Active Metadata) : 정적 카탈로그를 넘어 파이프라인 실행 로그와 질의 패턴, 리니지를 실시간 분석해 자동 태깅이나 이상 시 다운스트림 알림 같은 거버넌스 동작을 트리거.

## Ⅳ. 중앙집중형 거버넌스와 Data Mesh의 비교

- 핵심 요약 : 중앙 독점 통제의 병목을 줄이기 위해 도메인 자율과 연합 거버넌스로 전환하는 흐름.

| 비교 축 | 중앙집중형 거버넌스 | 페더레이션 거버넌스(Data Mesh) |
|---|---|---|
| 정책·표준 통제 | 전사 데이터팀이 정책과 표준을 독점 | 전사 공통 표준을 플랫폼 코드로 자동 강제 |
| 데이터 소유 | 중앙 조직 소유 | 도메인 자율 소유, 데이터의 제품화(Data as a Product) |
| 승인 절차 | 중앙 승인 병목으로 개발 지연 | 도메인 내 자율 결정으로 병목 해소 |
| 표준 강제 방식 | 문서와 심의 중심의 수동 준수 | 플랫폼 기능에 내장된 자동 준수 |
| 적합 환경 | 단일 조직·소규모 데이터 환경 | 도메인 다양성이 큰 대규모 조직 |

- 전환 방향 : 셀프서비스 데이터 플랫폼과 동적 접근 제어를 결합해 중앙 통제 의존을 완화.

## Ⅴ. 데이터 거버넌스의 한계와 방안

- 핵심 요약 : 관료화에 따른 민첩성 저하, 정적 메타데이터, 실행 문화 정착 실패를 셀프서비스·동적 접근 제어·능동형 메타데이터·스튜어드 인센티브로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 규제 중심 통제에 따른 민첩성 저하 | 요청·승인 절차의 관료화로 접근 리드타임이 길어지고 섀도 IT(Shadow IT)가 양산됨 | 셀프서비스 데이터 플랫폼과 RBAC·ABAC 기반 동적 접근 제어 결합, 연합형 거버넌스로 전환 | 데이터 접근 리드타임, 섀도 IT 건수 |
| 정적 메타데이터와 메타 사일로 | 수작업 등록과 분절된 저장소로 시스템 변경 시 메타데이터가 실제 스키마와 어긋남 | 액티브 메타데이터 플랫폼 도입, CI/CD 파이프라인 연계 자동 메타 추출, OpenLineage 기반 리니지 동기화 | 메타데이터 동기화율 |
| 실행 문화 정착 실패 | 일회성 프로젝트로 끝나 현업의 지속 관리 동기가 없고, 표준 미준수 데이터가 누적됨 | 데이터 품질과 비즈니스 KPI(Key Performance Indicator) 연계, 스튜어드 인센티브 체계화, 데이터 리터러시(Data Literacy) 교육 상시 운영 | 표준 준수율, 교육 이수율 |

## Ⅵ. 데이터 거버넌스 구축에 대한 기술사적 제언

- 핵심 요약 : 하향식 스폰서십과 상향식 자동화의 조화, 핵심 데이터 요소 중심의 점진적 롤아웃.
- 경영진의 정책적 후원과 CDO의 권한 강화를 바탕으로 하되, 현업 엔지니어가 거버넌스를 규제가 아니라 생산성 도구로 체감하도록 dbt 테스트, Great Expectations, OpenLineage 같은 자동화 도구를 함께 제공하는 것이 바람직함.
- 전사 수천 개 테이블을 한 번에 표준화하는 빅뱅 방식은 피하고, 비즈니스 영향도가 가장 큰 핵심 데이터 요소(CDE, Critical Data Element)부터 선정해 조기 성공 사례를 만드는 것이 현실적임.

## Ⅶ. 결론

- 핵심 요약 : 데이터 거버넌스는 정책·조직·기술의 유기적 결합과 점진적 정착 전략이 성공 조건인 체계.
- 시사점 : 규제 준수와 데이터 활용 민첩성의 균형을 설계하고, 빠른 성과를 거둔 영역을 확산하는 방식이 필요함.
