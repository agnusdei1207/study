## 연관 키워드

- 데이터 거버넌스(Data Governance), CDO, 데이터 스튜어드(Data Steward), 메타데이터 관리, 데이터 리니지(Lineage)
- 데이터 사일로, SSOT, RBAC·ABAC, Data Mesh, Active Metadata, 데이터 리터러시

## Ⅰ. 데이터 거버넌스의 개요

- 핵심 요약 : 전사 데이터 자산의 가용성·유용성·무결성·보안성을 보장하는 종합 관리 체계.
- 개념 : 기업·기관이 보유한 전사 데이터 자산의 가용성(Availability), 유용성(Usability), 무결성(Integrity), 보안성(Security)을 보장하기 위해 수립된 원칙, 정책, 프로세스, 조직 및 기술의 종합적 관리 체계.
- 배경 및 필요성 :
  1. 데이터 사일로(Silo) 심화 : 부서별 독립 시스템 구축에 따른 데이터 중복, 표준 불일치, 전사 단일 진실 공급원(SSOT, Single Source of Truth) 부재.
  2. 데이터 규제 강화 : GDPR(General Data Protection Regulation), 개인정보보호법 개정 등 글로벌 프라이버시 보호 의무화.
  3. 생성형 AI(Artificial Intelligence)·분석 요구 : 고품질 데이터 공급 없이는 LLM(Large Language Model) 파인튜닝 및 RAG(Retrieval-Augmented Generation) 시스템의 신뢰성 확보 불가.
- 주요 목적 : 데이터 전 생명주기의 통제를 통한 품질 극대화, 컴플라이언스 리스크 통제, 비즈니스 가치 창출 가속.

## Ⅱ. 데이터 거버넌스의 특징

- 핵심 요약 : 5대 구성 요소와 3계층 조직 체계, 전 생명주기 통제의 결합.

1. 5대 구성 요소 : 데이터 표준화, 데이터 품질관리, 메타데이터 관리, 보안·규제 준수, 데이터 라이프사이클 관리.
2. 조직 체계 : 거버넌스 위원회, 데이터 스튜어드, 데이터 커스토디언·엔지니어의 3계층 역할 분담.
3. 전 생명주기 통제 : 데이터 생성부터 폐기까지의 정책·기술적 관리.
4. 규제 대응 내재화 : 프라이버시 보호·보안 정책의 프로세스 자동 연계.
5. 가치 창출 지향 : 품질 높은 데이터 공급을 통한 분석·AI 신뢰성 기반 제공.

## Ⅲ. 데이터 거버넌스의 구조 (흐름)

- 핵심 요약 : 전략·리더십 하의 5대 도메인과 조직 체계, 중앙집중형에서 페더레이션 거버넌스로의 진화.

```text
[ 데이터 거버넌스 프레임워크 ]
 데이터 전략 및 리더십 (CDO, 경영진)
 │
 ├─ 1. 데이터 표준화       : 표준 용어, 도메인, 코드체계
 ├─ 2. 데이터 품질관리     : 프로파일링, 업무규칙 검증
 ├─ 3. 메타데이터 관리     : 카탈로그, 리니지 추적
 ├─ 4. 보안·규제 준수      : 접근 제어, 암호화
 ├─ 5. 데이터 라이프사이클 : 아카이빙, 폐기
 │
 └─ 조직·역할 : 위원회, 스튜어드, 엔지니어
```

```text
[ 중앙집중형 vs 페더레이션 거버넌스 ]
 중앙집중형
  - 전사 데이터팀의 정책·표준 독점 통제
  - 승인 병목에 따른 개발 지연
 페더레이션 거버넌스 (Data Mesh)
  - 도메인 자율성 : 데이터를 제품으로 개발
    (Data as a Product)
  - 연합 거버넌스 : 전사 공통 표준의
    플랫폼 코드 기반 자동 강제
```

| 구성 영역 | 핵심 관리 항목 | 주요 활동 및 산출물 |
|---|---|---|
| 데이터 표준화 | 표준 단어, 표준 용어, 도메인, 표준 코드 | 전사 데이터 사전(Data Dictionary), 코드 매핑 테이블, 명명 규칙 |
| 데이터 품질(DQM, Data Quality Management) | 정밀도, 완전성, 일관성, 유효성 SLA(Service Level Agreement) | 품질 지표 측정, 결함 원인 분석, 자동 정제 파이프라인 |
| 메타데이터·리니지 | 비즈니스 카탈로그, 스키마 정의, 데이터 흐름 | 전사 메타데이터 저장소(MDR, Metadata Repository), 종단간 데이터 계보(Lineage) 그래프 |
| 보안·프라이버시 | RBAC(Role-Based Access Control)·ABAC(Attribute-Based Access Control) 접근 권한, 암호화, 개인정보 가명화 | 데이터 보안 정책, 접근 감사 로그, 개인정보 영향평가 |
| 라이프사이클(ILM, Information Lifecycle Management) | 수집, 보존 기한, 계층형 스토리지, 완전 파기 | 수명주기 분류 체계, 핫·콜드 데이터 티어링 정책, 영구 삭제 절차 |

- 조직 체계 및 R&R :
  1. 데이터 거버넌스 위원회(Council) : 최고데이터책임자(CDO, Chief Data Officer) 주관의 전사 정책 결정 및 부서 간 이해관계 조정.
  2. 데이터 스튜어드(Data Steward) : 현업 부서별 비즈니스 데이터 오너로서 데이터 정의 및 품질 요구사항 제시.
  3. 데이터 커스토디언(Data Custodian)·엔지니어 : IT(Information Technology) 시스템 내 물리적 데이터 저장, 백업, 보안 및 파이프라인 기술 운영.
- 액티브 메타데이터(Active Metadata) : 정적 카탈로그를 넘어 파이프라인 런타임 로그, 질의 패턴, 데이터 리니지의 실시간 분석을 통한 최적화·거버넌스 자동 트리거(자동 태깅, 이상치 탐지 시 다운스트림 알림).

## Ⅳ. 중앙집중형 거버넌스와 Data Mesh의 비교

- 핵심 요약 : 중앙 독점 통제의 병목 해소를 위한 도메인 자율·연합 거버넌스로의 전환.

| 비교 축 | 중앙집중형 거버넌스 | 페더레이션 거버넌스(Data Mesh) |
|---|---|---|
| 정책·표준 통제 | 전사 데이터팀의 정책·표준 독점 통제 | 전사 공통 표준의 플랫폼 코드 기반 자동 강제 |
| 데이터 소유 | 중앙 조직 소유 | 도메인 자율, 데이터의 제품화(Data as a Product) |
| 승인 절차 | 중앙 승인 병목으로 개발 지연 | 도메인 자율성 보장, 병목 해소 |
| 표준 강제 방식 | 문서·심의 중심의 수동 준수 | 플랫폼 기능에 내장된 자동 준수 |
| 적합 환경 | 단일 조직·소규모 데이터 환경 | 도메인 다양성이 큰 대규모 조직 |

- 전환 방향 : 셀프서비스 데이터 플랫폼과 동적 접근 제어의 결합을 통한 중앙 통제 의존의 완화.

## Ⅴ. 데이터 거버넌스의 장점과 한계

- 핵심 요약 : 품질·컴플라이언스·AI 신뢰성의 장점과 민첩성 저하·메타 사일로·문화 정착 실패의 한계.

- 장점
  1. 전사 데이터 품질·무결성의 체계적 보장.
  2. 개인정보보호 등 컴플라이언스 리스크의 선제 통제.
  3. LLM·RAG 등 AI 시스템의 신뢰성 기반 확보.

- 한계점 1 : 규제 중심 통제로 인한 데이터 활용 민첩성(Agility) 저하
  - 한계점 : 데이터 요청·승인 절차의 관료화로 현업 부서의 데이터 접근 리드타임 장기화 및 비즈니스 기회 손실, 섀도우 IT(Shadow IT) 양산.
  - 해결 방안 : 셀프서비스 데이터 플랫폼과 역할·속성 기반 동적 접근 제어(RBAC/ABAC)의 결합, 중앙 집중 통제에서 데이터 메시(Data Mesh) 기반 연합 거버넌스로의 전환.
- 한계점 2 : 정적 메타데이터 관리의 한계 및 메타 사일로화
  - 한계점 : 수작업 등록과 분절된 MDR로 시스템 변경 시 메타데이터 동기화 실패, 실제 운영 스키마와 메타데이터 간 괴리 심화.
  - 해결 방안 : 액티브 메타데이터(Active Metadata) 플랫폼 도입, CI(Continuous Integration)/CD(Continuous Delivery) 파이프라인 연계 자동 메타 추출 및 데이터 리니지(OpenLineage) 실시간 동기화.
- 한계점 3 : 전사 거버넌스 조직 및 실행 문화 정착 실패
  - 한계점 : 일회성 프로젝트성 거버넌스 수립 후 현업의 지속 관리 동기 결여로 표준 미준수 데이터 누적 및 거버넌스 시스템 사장화.
  - 해결 방안 : 비즈니스 KPI(Key Performance Indicator)와 데이터 품질의 연계, 데이터 스튜어드 인센티브 체계화 및 전사 데이터 리터러시(Data Literacy) 교육 프로그램의 상시 운영.

## Ⅵ. 데이터 거버넌스 구축을 위한 기술사적 제언

- 핵심 요약 : 하향식 스폰서십과 상향식 자동화의 조화, CDE 중심의 점진적 롤아웃.
- 하향식(Top-Down)과 상향식(Bottom-Up)의 조화 : 경영진의 강력한 정책적 스폰서십(CDO 권한 강화)과 함께 현업 엔지니어가 거버넌스를 규제가 아닌 생산성 도구로 체감하도록 자동화 툴링(dbt test, Great Expectations, OpenLineage) 제공.
- 점진적(Phased) 롤아웃 전략 : 전사 수천 개 테이블의 일괄 표준화 빅뱅 방식 지양, 비즈니스 영향도가 가장 높은 핵심 데이터 요소(CDE, Critical Data Element)의 우선 선정을 통한 조기 성공 사례(Quick-Win) 창출.

## Ⅶ. 결론

- 핵심 요약 : 데이터 거버넌스는 정책·조직·기술의 유기 결합과 점진적 정착 전략이 성공 조건.
- 요약 : 5대 구성 요소와 3계층 조직, Data Mesh·액티브 메타데이터로의 진화 체계.
- 시사점 : 규제 준수와 데이터 활용 민첩성의 균형 설계 및 Quick-Win 기반 확산 필요.
