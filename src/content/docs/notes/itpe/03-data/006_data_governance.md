## 연관 키워드
- 데이터 거버넌스, 데이터 소유자, 데이터 관리자, 정책, 메타데이터, 책임성

### Ⅰ. 데이터 거버넌스의 개요

- 핵심 요약 : 데이터 거버넌스는 데이터의 가치·품질·보안·접근·보존을 조직 차원에서 지시하고 책임지는 의사결정 체계.
- 개념 : 데이터의 가치·품질·보안·접근·보존을 조직 차원에서 지시하고 책임지는 의사결정 체계(**데이터 거버넌스**, Data Governance).
- 배경 및 필요성 : 데이터가 여러 부서·시스템에 분산되면서 정의·권한·품질·책임이 불일치.
- 주요 목적 : 데이터를 신뢰하고 합법적이며 일관되게 활용할 조직 역량 확보.

### Ⅱ. 데이터 거버넌스의 특징 및 장점

- 핵심 요약 : 정책·표준·역할·책임·통제·증거는 조직 공통 원칙과 결정·운영 책임 명확화, 준수와 활용을 동시에 지원하는 데이터 거버넌스 요소.

1. 정책·표준 : 용어·분류·보존·접근 기준 제정 → 조직 공통 원칙.
2. 역할·책임 : 소유자와 관리자 지정 → 결정·운영 책임 명확화.
3. 통제·증거 : 품질·계보·접근 기록 → 준수와 활용을 동시에 지원.

### Ⅲ. 데이터 거버넌스의 구조 (흐름)

- 핵심 요약 : 전략·원칙 설정 → 도메인·데이터 자산 지정 → 역할·정책 수립 → 표준·통제 구현 → 지표·이슈 개선.

```text
전략·원칙 설정
  ↓
도메인·데이터 자산 지정
  ↓
역할·정책 수립
  ↓
표준·통제 구현
  ↓
지표·이슈 개선
```

```text
경영진 후원·데이터위원회
           ↓ 정책·우선순위
데이터 소유자 → 정의·접근 승인
           ↓ 기준·통제
데이터 관리자 → 품질·메타데이터 운영
```

### Ⅳ. 데이터 거버넌스와 데이터 관리 비교

- 핵심 요약 : 범위 기준 — 데이터 거버넌스: 기업 전체·도메인 간 공통 기준; 데이터 관리: 플랫폼·품질·보안 등 개별 운영 프로세스.

| 비교 축 | 데이터 거버넌스 | 데이터 관리 |
|---|---|---|
| 의사결정 | 정책·책임·권한·감독 정의 | 정책을 구현하는 일상적 기술·업무 운영 |
| 범위 | 기업 전체·도메인 간 공통 기준 | 플랫폼·품질·보안 등 개별 운영 프로세스 |
| 중점 | 데이터 의사결정권·책임·통제와 활용 정렬 | 개별 시스템 운영과 품질 관리 |

### Ⅴ. 데이터 거버넌스의 한계와 방안

- 핵심 요약 : 위원회 형식화·중앙집중 병목 등 실제 위험을 원인에 맞는 통제와 지표로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 위원회 형식화 | 의사결정만 하고 실행책임·예산 부재 | 데이터 도메인 소유자·실행권한·에스컬레이션 정의 | 결정 이행률 |
| 중앙집중 병목 | 모든 정의·권한을 중앙 승인해 현업 지연 | 연합형 원칙과 위험기반 승인 설계 | 승인 소요시간 |
| 통제와 활용 충돌 | 보호만 강조하거나 무제한 개방 | 분류·목적·최소권한 기반 접근으로 균형 | 적법 활용률·위반 건수 |

### Ⅵ. 데이터 거버넌스에 대한 제언

- 핵심 요약 : 최고데이터책임자와 도메인 소유자는 정책을 데이터 카탈로그·접근통제·품질 SLA에 연결하고 성과·위험을 정기 경영 의제로 보고.

- 실행 제안 : 데이터위원회는 데이터 도메인 소유자에게 정의·품질·접근 승인권을 위임하고 범부서 분쟁만 상향 심의.

### Ⅶ. 결론

- 핵심 요약 : 데이터 거버넌스는 기술도구만의 문제가 아니라 데이터 의사결정권·책임·통제와 활용을 정렬하는 운영체계.
- 시사점 : 공통 규칙과 도메인 자율성을 함께 설계해야 통제가 현업 활용의 병목이 되지 않음.
