## 연관 키워드
- 고가용성, 장애도메인, 이중화, 장애조치, RTO, RPO, quorum

### Ⅰ. 고가용성 아키텍처의 개요

- 핵심 요약 : 고가용성 아키텍처는 장애 시에도 합의된 수준의 서비스를 지속·복구하도록 중복 구성·장애감지·전환 절차를 설계하는 체계.
- 개념 : 장애 시에도 합의된 수준의 서비스를 지속·복구하도록 중복 구성·장애감지·전환 절차를 설계하는 체계(**고가용성 아키텍처**, High Availability Architecture).
- 배경 및 필요성 : 단일 장애점·장애 복구 지연으로 업무 서비스 중단 및 데이터 손실 발생.
- 주요 목적 : 데이터 무결성, 가용성, 신뢰성을 지속적으로 보장하는 운영 역량.

### Ⅱ. 고가용성 아키텍처의 특징 및 장점

- 핵심 요약 : 구축·성능·가용성·보안의 4대 직무를 한 책임자가 종합 관리해 장애와 유출 위험을 줄이는 구조.

1. 구축·모델링 : 물리 스키마 배포와 표준화 담당 → 배포 오류와 용량 산정 실패 감소.
2. 성능 최적화 : **슬로우 쿼리**(Slow Query) 분석과 인덱스·버퍼 설정 조정 → 응답 지연 감소.
3. 가용성 및 재해 복구 : **고가용성**(HA, High Availability)으로 이중화하고 **재해 복구**(DR, Disaster Recovery) 절차로 백업을 관리 → 복구 목표 시간(**RTO**, Recovery Time Objective)과 복구 시점 목표(**RPO**, Recovery Point Objective)를 충족.
4. 보안 및 감사 : **역할 기반 접근 제어**(RBAC, Role-Based Access Control)와 **투명 데이터 암호화**(TDE, Transparent Data Encryption)를 적용하고 접근 로그를 남김 → 유출 위험과 감사 대응 비용 감소.
5. 클라우드 적응 : **DBaaS**(Database as a Service) 환경에서는 자동화 도구로 운영을 표준화하고 역할을 설계와 비용 관리로 고도화.

### Ⅲ. 고가용성 아키텍처의 구조 (흐름)

- 핵심 요약 : 모델링에서 보안까지 4대 직무 영역이 순서대로 맞물리는 운영 흐름.
- 대상 데이터베이스의 생애 흐름을 따라 직무가 이어진다. 각 단계의 산출물이 다음 단계의 입력이 된다.

```text
[ 고가용성 아키텍처의 구조 ]

요구 수집
   ↓
분석
   ↓
설계
   ↓
구현
   ↓
배포
   ↓
운영
```

```text
[ 비즈니스 데이터 모델링 ]

요구사항 분석
   ↓
논리 모델링
   ↓
물리 모델링
   ↓
스키마 설계
```

```text
[ DB 배포 프로세스 ]

개발 서버 ← 테스트 데이터
      ↓
운영 서버 ← 실제 데이터
```

### Ⅳ. DA와 DBA의 비교

- 핵심 요약 : 논리·비즈니스 관점의 DA와 물리·기술 운영 관점의 DBA로 역할 경계를 나눔.

| 비교 항목 | DA (데이터 아키텍트) | DBA (데이터베이스 관리자) |
|---|---|---|
| 관점 | 논리·비즈니스 | 물리·기술 운영 |
| 주요 산출물 | ERD(엔터티-관계 다이어그램), 표준 용어 사전 | DDL(데이터 정의어) 스크립트, 백업 정책, 튜닝 보고 |
| 정규화 방향 | 3NF(제3정규형), BCNF(보이스-코드 정규형) 지향 | 성능 요구에 따른 선택적 비정규화 |
| 협업 방식 | 논리 모델 확정 후 인계 | 인계받은 모델을 물리 구현 |

```text
[ DA와 DBA의 역할 경계 ]

DA (논리 모델·표준 사전)
       ↓ 인계
DBA (물리 설계·운영·보안)
       ↓
DBMS 운영 (성능·가용성·백업)
```

### Ⅴ. 고가용성 아키텍처의 한계와 방안

- 핵심 요약 : 클라우드 자동화, CI/CD 병목, 다종 DBMS 확산에 대해 역할 전환, 자동화, 표준화로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 클라우드 자동화 | DBaaS(데이터베이스 서비스로 서비스)의 도입으로 전통적 운영 업무의 가치 하락 | 데이터 운영(DataOps)과 비용 관리(FinOps) 역량으로 역할 전환 | 역할 전환 이수율 |
| CI/CD 병목 | DDL(데이터 정의어) 수동 승인으로 배포 민첩성 저하 | Flyway, Liquibase 같은 마이그레이션 도구와 CI 파이프라인 자동 검증 | 배포 리드타임 |
| 다종 DBMS 파편화 | NoSQL, 벡터 DB 등 관리 대상 증가로 운영 표준 분산 | 표준화 가이드 수립, 통합 관제, 전담 조직(CoE, 센터 오브 엑셀런스) 운영 | 지원 DBMS 종류 수 |

### Ⅵ. 고가용성 아키텍처에 대한 기술사적 제언

- 핵심 요약 : 코드 기반 배포와 비용 관리, 보안 기준을 결합해 클라우드 시대의 DBA 역할을 재정의하는 방향.
- 데이터베이스 변경 이력을 **DaaC**(Database as a Code, DDL과 DML을 코드로 관리하는 방식)로 전환하여 Git의 변경 요청과 CI/CD 파이프라인으로 승인과 배포를 자동화하는 것이 바람직함.
- 비용 측면에서는 **FinOps**(클라우드 비용을 성능과 함께 관리하는 운영 방식)를 적용해 IOPS(초당 입출력 연산 횟수)와 vCPU 사용량을 분석하고 자원 규모를 맞춤하며, 오래된 데이터는 저비용 저장소로 이전하는 것이 바람직함.
- 보안 측면에서는 **PoLP**(최소 권한 원칙, Principle of Least Privilege)를 기본 정책으로 두어 계정마다 필요한 권한만 부여하는 것이 중요함.

### Ⅶ. 결론

- 핵심 요약 : 고가용성 아키텍처는 데이터베이스 운영의 책임을 지는 역할로, 클라우드 환경에서는 자동화·비용·보안을 함께 다루는 역할로 진화.
- 시사점 : 4대 직무의 기본기 위에 자동화와 비용 관리 역량을 더할 때 고가용성 아키텍처의 가치가 유지됨.
