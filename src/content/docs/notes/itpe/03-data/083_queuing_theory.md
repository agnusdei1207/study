## 연관 키워드

대기행렬이론, 켄달 표기법, M/M/1, 리틀의 법칙, 이용률, 백프레셔, SLA, 포아송 도착, 잭슨 네트워크

## Ⅰ. 대기행렬이론의 개요

- 핵심 요약 : 대기와 서비스 현상을 확률 모델로 분석해 대기 시간, 대기 행렬 길이, 가동률을 예측하는 성능 공학 기법.
- 개념 : 요청이 도착해 대기하고 서비스를 받는 과정을 수학적 모델로 분석하는 이론 (**대기행렬이론**, Queuing Theory).
- 배경 및 필요성 : 웹 서버, 메시지 큐, 네트워크 라우터는 요청이 몰리면 처리 부하 비율에 따라 대기 시간이 급격히 늘어나므로, 장애가 난 뒤 대응하는 비용을 줄이려면 용량을 미리 계산해 두는 설계 계층이 필요함.
- 주요 목적 : 시스템 병목 지점 식별, 용량 산정, 서비스 수준 협약(SLA, Service Level Agreement) 달성 여부 예측.
- 특징 : 표준 표기 체계와 기본 모형, 보편 법칙을 바탕으로 한 성능 계산.

## Ⅱ. 대기행렬이론의 특징 및 장점

- 핵심 요약 : 표기 체계, 기본 모형, 보편 법칙이 맞물려 이용률에 따른 대기 성능을 수치로 계산하는 구조.

1. **켄달 표기법** (Kendall Notation) : A/S/c/K/N/D 형식으로 도착 과정, 서비스 시간 분포, 서버 수, 시스템 용량, 모집단, 대기 규칙을 표현 → 시스템 구조를 짧은 기호로 정의.
2. **M/M/1** 모형 : 포아송 도착과 지수 서비스 시간을 가정한 단일 서버 모형 → 해석 공식으로 바로 계산 가능.
3. **리틀의 법칙** (Little's Law) : $L = \lambda W$로 시스템 내 평균 고객 수와 체류 시간을 연결 → 도착과 서비스의 분포 가정 없이 성립.
4. **이용률** (ρ, Utilization) : $\rho = \lambda/\mu$ → 1 미만이어야 시스템이 안정 상태를 유지.
5. 비선형 지연 : 이용률이 1에 가까워지면 대기 시간이 급증 → 여유 용량 확보의 근거가 됨.

## Ⅲ. 성능 척도 흐름

- 핵심 요약 : 이용률에서 출발해 체류 시간, 대기 시간, 시스템 내 고객 수를 차례로 구하는 계산 흐름.
- M/M/1 산식 : $W = 1/(\mu-\lambda)$, $W_q = \lambda/(\mu(\mu-\lambda))$, $L = \lambda/(\mu-\lambda)$.
- 척도 의미 : λ는 도착률, μ는 서비스율이며, W는 체류 시간, Wq는 대기 시간, L은 시스템 내 평균 고객 수를 뜻함.

```text
[ M/M/1 성능 척도 흐름 ]

이용률 ρ = λ / μ (1 미만이면 안정)
      ↓
체류 시간 W = 1 / (μ - λ)
      ↓
대기 시간 Wq = λ / (μ(μ - λ))
      ↓
시스템 고객 수 L = λ / (μ - λ)
```

```text
[ ρ와 체류 시간 W의 관계 ]

W = (1/μ) / (1 - ρ)

ρ = 0.5 → W = 2/μ
ρ = 0.8 → W = 5/μ
ρ = 0.9 → W = 10/μ
ρ → 1   → W 무한대로 발산
```

## Ⅳ. 켄달 표기와 M/M/1 비교

- 핵심 요약 : 켄달 표기의 각 자리가 M/M/1에서 어떤 값을 갖는지 대응해 기본 모형의 구조를 파악함.

| 항목 | 켄달 표기의 의미 | M/M/1에서의 값 |
| --- | --- | --- |
| 도착 과정 | M은 포아송 도착(지수 간격) | 포아송 도착 |
| 서비스 시간 | M은 지수 분포 | 지수 분포 |
| 서버 수 | c는 채널 수 | 1 |
| 시스템 용량 | K는 수용 가능 고객 수 | 무한 |
| 모집단 | N은 고객의 전체 수 | 무한 |

- 선택 기준 : 서버가 하나이고 도착과 서비스가 지수 분포에 가까우면 M/M/1, 서버가 여럿이면 M/M/c, 서비스 시간이 일반 분포이면 M/G/1로 표기를 바꿔 모형을 고름.

## Ⅴ. 한계와 방안

- 핵심 요약 : 포아송 가정의 한계, 이용률이 1에 가까울 때의 발산, 다단계 서비스의 연쇄 지연을 일반화 모형, 이용률 상한, 네트워크 분석으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 포아송 가정 | 실제 트래픽은 버스트가 잦고 꼬리가 두꺼운 분포라 예측 오차 발생 | G/G/1이나 M/G/1(Pollaczek-Khinchine 공식) 적용, 이산 사건 시뮬레이션(DES, Discrete Event Simulation) | 예측값과 실측값의 차이 |
| ρ→1 발산 | 이용률이 과도하면 대기 시간이 무한에 가깝게 증가 | 이용률 상한을 정하고 예측 기반 자동 확장(Predictive Autoscaling) 적용 | 이용률, 체류 시간 |
| MSA 큐 네트워크 | 마이크로서비스가 연쇄 호출되어 단일 큐 모형으로는 설명 불가 | 잭슨 네트워크(Jackson Network) 모형, APM 분산 추적, AIOps(AI for IT Operations) | 큐 깊이, 응답 지연 |

## Ⅵ. 기술사적 제언

- 핵심 요약 : 여유 있는 이용률 기준으로 용량을 확보하고, 과부하가 시스템 전체로 번지지 않게 막는 설계와 용량 산정 절차를 함께 갖추어야 안정적인 운영이 가능함.

1. 여유 있는 임계치 : 오토스케일링 임계치를 이용률이 한계 가까이 올라간 뒤가 아니라 여유가 남은 수준에서 발동하도록 설정해, 대기 시간이 급증하기 전에 용량을 늘린다.
2. 백프레셔 적용 : **백프레셔** (Backpressure, 하류가 처리하지 못할 때 상류에 속도를 낮추라고 전달하는 신호)를 설계에 넣고, 서킷 브레이커(Circuit Breaker)와 함께 큐가 무한정 쌓여 폭주하는 상황을 차단한다.
3. 용량 산정 : 리틀의 법칙으로 목표 동시 요청 수에서 처리량과 체류 시간을 역산해 서버 수와 큐 용량을 정하고, 실측값으로 주기적으로 보정한다.

## Ⅶ. 결론

- 핵심 요약 : 대기행렬이론은 대기와 서비스 성능을 정량화하는 기법으로, 리틀의 법칙과 이용률 관리가 핵심임.
- 시사점 : 이용률이 높을수록 지연에 취약하므로, 성능 목표를 평균 처리량이 아닌 이용률 여유 기준으로 정하는 것이 안정적 운영으로 이어짐.
