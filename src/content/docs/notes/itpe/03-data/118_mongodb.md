<details><summary>핵심 용어</summary>

- **MongoDB** : BSON 문서 중심의 NoSQL 데이터베이스 관리 시스템
- **BSON (Binary JSON)** : MongoDB가 문서와 값의 자료형을 표현하는 이진 직렬화 형식
- **Embedding** : 함께 조회·갱신되는 관련 데이터를 한 문서 안에 포함하는 모델링 방식
- **Sharding** : 샤드 키를 기준으로 컬렉션 데이터를 여러 샤드에 분산하는 방식
- **Mongos** : 클라이언트 요청을 메타데이터에 따라 샤드로 전달하는 질의 라우터

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | MongoDB는 BSON 문서를 컬렉션 단위로 저장·조회하는 문서형 데이터베이스 |
| 목적 | 가변적인 데이터 구조를 문서 모델로 표현하고 업무 조회에 맞게 저장·확장 |

## Ⅱ. BSON 문서와 접근 패턴 중심 모델링의 특징

| 특징 | 설계상 의미 |
|---|---|
| BSON 문서 | 중첩 필드와 배열로 업무 단위 데이터 표현 |
| 접근 패턴 중심 | 함께 읽기·갱신하는 범위로 임베딩·참조 결정 |
| 분산 구성 | 복제 세트와 샤딩의 역할을 구분해 가용성·규모 요구 대응 |

단일 문서 쓰기의 원자성을 활용하되, 임베딩이 항상 빠르거나 참조가 항상 정규화에 유리하다고 단정하지 않고 실제 접근 패턴과 변경 빈도로 결정

## Ⅲ. 문서 저장·복제·샤드 라우팅 체계

```text
업무 조회·갱신 패턴 → 함께 읽고 바뀌는 값은 임베딩
                  └→ 독립 변경·큰 관계는 참조
                           ↓ BSON 문서·컬렉션 저장
                    Primary ─oplog→ Secondary 복제
                           ↓ 규모 증가 시 샤드 키 결정
클라이언트 → mongos ─메타데이터 조회→ 대상 샤드의 복제 세트
                    └ 키 없는 질의 → 여러 샤드에 분산 조회
```

### 샤드 키와 대상 질의의 분기

```text
질의 조건에 샤드 키/복합 키 접두부 있음 → mongos가 대상 샤드만 조회
조건에 샤드 키 없음                  → 여러 샤드에 조회·결과 취합
```

## Ⅳ. 임베딩·참조와 복제·샤딩 역할 비교

| 선택 | 적합한 조건 | 고려사항 |
|---|---|---|
| 임베딩 | 함께 조회되는 종속 데이터 | 배열 증가와 문서 크기 상한 관리 |
| 참조 | 독립적으로 조회·갱신되거나 관계가 커지는 데이터 | 추가 조회 또는 `$lookup` 비용 검토 |

| 기능 | 구조와 작동 |
|---|---|
| 복제 세트 | Primary의 변경을 Secondary가 oplog를 통해 비동기 복제; 읽기 일관성·쓰기 확인은 read/write concern 설정으로 선택 |
| 샤드 | 분산된 데이터 일부를 보유하는 샤드 단위, 각 샤드는 복제 세트로 운영 |
| Mongos | 샤드 키와 클러스터 메타데이터를 바탕으로 질의를 라우팅 |
| Config server | 청크 범위 등 샤딩 메타데이터 보관 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 초기 접근 패턴과 실제 질의·변경이 다르면 문서 재설계와 샤드 핫스팟이 생길 수 있음 | 대표 질의·변경을 부하 시험에 반영하고 샤드 분포·타깃 질의 비율을 확인 |
| 임베딩 배열이 계속 증가해 문서 크기·갱신 부담 증가 | 데이터의 성장·독립 갱신 여부를 측정해 참조 구조로 분리 |
| 샤드 키 없는 질의가 전체 샤드에 퍼짐 | 대표 필터와 키 접두부를 대조하고 타깃 질의 비율을 관측 |

## Ⅵ. 제언

샤드 키가 실제 질의 조건과 맞지 않으면 전체 샤드 조회와 핫스팟이 생기므로 대표 필터·쓰기 부하의 타깃 질의 비율과 샤드 분포를 측정해 키를 결정한다.
