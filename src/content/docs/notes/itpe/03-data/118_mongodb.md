## 30초 인출

- 본질: **MongoDB는 BSON 문서를 컬렉션에 저장하고 문서 구조에 맞춰 조회·확장하는 문서형 데이터베이스**
- 메커니즘: 임베딩·참조로 문서 관계를 모델링하고, 복제 세트로 가용성을 높이며 샤딩으로 데이터를 분산

<details><summary>핵심 용어</summary>

- **MongoDB** : BSON 문서 중심의 NoSQL 데이터베이스 관리 시스템
- **BSON (Binary JSON)** : MongoDB가 문서와 값의 자료형을 표현하는 이진 직렬화 형식
- **Embedding** : 함께 조회·갱신되는 관련 데이터를 한 문서 안에 포함하는 모델링 방식
- **Sharding** : 샤드 키를 기준으로 컬렉션 데이터를 여러 샤드에 분산하는 방식
- **Mongos** : 클라이언트 요청을 메타데이터에 따라 샤드로 전달하는 질의 라우터

</details>

## 1교시 10점 답안

### Ⅰ. MongoDB 개요

| 구분 | 핵심 |
|---|---|
| 정의 | MongoDB는 BSON 문서를 컬렉션 단위로 저장·조회하는 문서형 데이터베이스 |
| 목적 | 가변적인 데이터 구조를 문서 모델로 표현하고 업무 조회에 맞게 저장·확장 |

### Ⅱ. 데이터 모델·확장 구조

| 판단 | 모델·구성 |
|---|---|
| 관련 데이터 | 함께 읽고 갱신하면 임베딩, 독립 수명·대규모 관계면 참조 검토 |
| 가용성 | 복제 세트의 Primary가 쓰기를 받고 Secondary가 변경 로그를 비동기 반영 |
| 수평 확장 | 샤드 키로 데이터를 분산하고 Mongos가 요청을 해당 샤드로 전달 |
| 문서 크기 | BSON 문서 최대 크기 16 MiB, 큰 이진 자료에는 GridFS 등 별도 저장 방식 검토 |

## 2~4교시 25점 답안

## Ⅰ. MongoDB 개요

| 구분 | 핵심 |
|---|---|
| 정의 | MongoDB는 BSON 문서를 컬렉션 단위로 저장·조회하는 문서형 데이터베이스 |
| 목적 | 가변적인 데이터 구조를 문서 모델로 표현하고 업무 조회에 맞게 저장·확장 |

## Ⅱ. 문서 모델링

| 선택 | 적합한 조건 | 고려사항 |
|---|---|---|
| 임베딩 | 함께 조회되는 종속 데이터 | 배열 증가와 문서 크기 상한 관리 |
| 참조 | 독립적으로 조회·갱신되거나 관계가 커지는 데이터 | 추가 조회 또는 `$lookup` 비용 검토 |

단일 문서 쓰기의 원자성을 활용하되, 임베딩이 항상 빠르거나 참조가 항상 정규화에 유리하다고 단정하지 않고 실제 접근 패턴과 변경 빈도로 결정

## Ⅲ. 복제와 샤딩 구조

| 기능 | 구조와 작동 |
|---|---|
| 복제 세트 | Primary의 변경을 Secondary가 oplog를 통해 비동기 복제; 읽기 일관성·쓰기 확인은 read/write concern 설정으로 선택 |
| 샤드 | 분산된 데이터 일부를 보유하는 샤드 단위, 각 샤드는 복제 세트로 운영 |
| Mongos | 샤드 키와 클러스터 메타데이터를 바탕으로 질의를 라우팅 |
| Config server | 청크 범위 등 샤딩 메타데이터 보관 |

## Ⅳ. 설계 판단과 운영 한계

| 설계 축 | 이점 | 한계·점검 |
|---|---|---|
| 문서 경계 | 업무 단위 조회·갱신에 적합 | 과도한 임베딩은 문서 비대화·갱신 집중 유발 |
| 인덱스 | 조회 조건에 맞춘 탐색 지원 | 쓰기 비용·저장공간 증가 |
| 샤드 키 | 분산과 타깃 질의의 기준 | 편향 키는 분산 불균형, 키 없는 질의는 scatter-gather 가능 |
| 일관성 설정 | 내구성과 읽기 가시성 선택 | 다수 확인 수준이 높을수록 지연이 커질 수 있음 |

## Ⅴ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 초기 부하 가정과 실제 접근 패턴 차이로 샤드 핫스팟 또는 문서 재설계 비용 발생 | 대표 질의·변경 이벤트를 부하 시험에 반영하고, 샤딩 전후 분포·타깃 질의 비율을 확인하는 설계 검토 단계 마련 |
