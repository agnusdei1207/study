## 지식 로드맵 내 현재 위치

자료처리·데이터 → 자료구조·알고리즘 → **선형 vs 비선형 자료구조**

## 30초 인출

- 본질: 요소 간 관계 개수로 나눈 자료구조 분류, **선형 자료구조** 는 앞뒤 요소가 1:1로 이어진 순차 관계, **비선형 자료구조** 는 계층·망으로 이어진 1:N·N:M 관계
- 메커니즘: 선형은 위치 기반 삽입·삭제와 LIFO·FIFO 입출력, 비선형은 노드·간선 연결과 분기 순회로 다대다 관계 표현
- 통찰: 데이터의 접근 패턴과 관계 복잡도에 따라 선형 구조의 순차성과 비선형 구조의 계층·네트워크 탐색 효율을 최적으로 조합하는 하이브리드 설계 필수

<details>
<summary>핵심 용어</summary>

- **선형 자료구조(Linear Data Structure)** : 각 요소가 최대 하나의 선행자와 하나의 후속자를 갖는 순차 나열 구조
- **비선형 자료구조(Non-linear Data Structure)** : 한 요소가 여러 요소와 연결되는 계층·망 구조
- **스택(Stack)** : 한쪽 끝에서만 삽입·삭제가 일어나는 후입선출(LIFO, Last-In First-Out) 선형 구조
- **큐(Queue)** : 뒤에서 삽입하고 앞에서 삭제하는 선입선출(FIFO, First-In First-Out) 선형 구조
- **데크(Deque)** : 양쪽 끝에서 모두 삽입·삭제가 가능한 선형 구조
- **연결 리스트(Linked List)** : 노드의 데이터와 다음 노드 포인터로 요소를 연결해 삽입·삭제 시 이동 없이 링크만 갱신하는 선형 구조
- **트리(Tree)** : 루트에서 부모-자식 관계로 계층을 만드는 비선형 구조
- **그래프(Graph)** : 정점과 간선으로 임의의 다대다 관계를 표현하는 비선형 구조
- **순회(Traversal)** : 비선형 구조의 모든 요소를 정해진 규칙으로 한 번씩 방문하는 연산

## 2~4교시 25점 답안

## Ⅰ. 선형 vs 비선형 자료구조의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 요소 간 관계 개수에 따른 자료구조 분류, **선형 자료구조** 는 1:1 선후 관계의 순차 나열, **비선형 자료구조** 는 1:N·N:M 계층·망 관계 |
| 목적 | 저장 대상 데이터의 관계 모양과 연산 패턴에 맞는 구조 선택으로 탐색·표현 비용의 최소화 |

## Ⅱ. 선형·비선형 자료구조의 핵심 특징

| 특징 | 선형 | 비선형 |
|---|---|---|
| 관계 개수 | 요소당 선행자·후속자 각 최대 1개 | 요소당 여러 자식·간선 연결 |
| 순회 경로 | 처음부터 끝까지의 단일 순서 | 깊이·너비 우선 등 분기 순회 필요 |
| 메모리 표현 | 배열의 연속 할당 또는 포인터 체인 | 노드 + 다중 포인터·간선 리스트 |
| 응용 중심 | 순차 처리·버퍼·되돌리기 | 검색 인덱스·경로 탐색·우선순위 처리 |

## Ⅲ. 자료구조 분류 체계와 입출력 원리

### 선형·비선형 구성 분류

```text
자료구조
    ├─ 선형 자료구조 ── 1:1 순차 관계
    │    ├─ 배열 ── 인덱스 직접 접근
    │    ├─ 연결 리스트 ── 포인터 체인
    │    ├─ 스택 ── LIFO
    │    ├─ 큐 ── FIFO
    │    └─ 데크 ── 양방향 입출력
    └─ 비선형 자료구조 ── 1:N·N:M 관계
         ├─ 트리 ── 계층 관계
         ├─ 힙 ── 우선순위 관계
         └─ 그래프 ── 망 관계
```

### 선형 구조의 입출력 원리 확대: 스택·큐·데크

```text
스택(LIFO)          큐(FIFO)            데크(양방향)
입력→ [top] ↓ 삽입   입력→ [rear] 삽입    입력→ [front/rear] 삽입
출력← [top] ↑ 삭제   출력← [front] 삭제   출력← [front/rear] 삭제
가장 나중 입력의      가장 먼저 입력의      양쪽 끝 모두에서의
먼저 출력            먼저 출력            삽입·삭제 허용
```

| 구조 | 대표 연산 | 연산 비용의 성격 |
|---|---|---|
| 배열 | 인덱스 접근, 중간 삽입·삭제 | 접근 O(1), 중간 삽입·삭제 시 이동 O(N) |
| 연결 리스트 | 노드 링크 갱신, 순차 탐색 | 삽입·삭제 O(1), 탐색 O(N) |
| 스택·큐 | 한쪽 끝·양끝 입출력 | 입출력 O(1), 내부 요소 직접 접근 불가 |
| 트리·그래프 | 분기 탐색·순회 | 균형 트리 O(log N), 그래프는 정점·간선 수에 비례 |

## Ⅳ. 선형 vs 비선형 구조 비교

| 비교축 | 선형 자료구조 | 비선형 자료구조 |
|---|---|---|
| 표현하는 관계 | 순서·대기열 같은 선후 관계 | 포함·소속·연결 같은 계층·망 관계 |
| 탐색 방식 | 처음부터의 순차 탐색 또는 정렬 기반 이분 탐색 | 루트·시작 정점에서의 분기 탐색 |
| 삽입·삭제 | 위치 확정 후 이동 또는 링크 갱신 | 노드 연결 재구성, 균형·순환 관리 동반 |
| 대표 활용 | 스택의 함수 호출·되돌리기, 큐의 작업 대기·버퍼 | 트리의 인덱스·파일 시스템, 그래프의 경로·네트워크 분석 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 선형 구조의 비순차 조건 탐색 시 O(N) 비용 발생 | 조건 검색 대상의 트리·해시 기반 인덱스 병행 |
| 계층·망 관계 데이터의 선형 저장 시 중복·조인 비용 증가 | 관계 모양에 맞는 트리·그래프 모델 채택 |
| 비선형 구조의 복잡한 순회·균형 관리 구현 부담 | 표준 라이브러리와 정형화된 순회·균형 알고리즘 활용 |

## Ⅵ. 제언

순차적 흐름 처리는 큐/스택을 적용하고 다대다 관계 및 계층 탐색은 트리/그래프를 채택하며 메모리 연속성과 캐시 친화성을 고려한 자료구조 선정.

### 자료구조 분류 체계 및 변환 관계

```text
[컴퓨터 자료구조 분류]
       │
       ├─ [선형 자료구조 (1:1 선형 순서)] ──► 배열, 연결 리스트, 스택, 큐
       │        │
       │        ▼ (인덱싱 및 계층화)
       └─ [비선형 자료구조 (1:N, N:M 계층/망)]
                ├─ 트리 (Tree)   : 1:N 계층 구조 (BST, B-Tree, Heap)
                └─ 그래프 (Graph): N:M 네트워크 관계 (DAG, 인접리스트)
```

### 선택 근거: 비선형 자료구조 (Non-linear)

| 구분 | 선형 자료구조 (Linear) | 비선형 자료구조 (Non-linear) |
|---|---|---|
| 관계 표현 | 데이터 간 1:1 전후 연속 관계 | 데이터 간 1:N 계층 또는 N:M 복합 관계 |
| 순회 방식 | 단일 방향 순차 순회 | 전위/중위/후위 순회, DFS, BFS 다각 순회 |
| 탐색 복잡도 | O(N) 선형 탐색 | 트리 기반 O(log N) 고속 탐색 |
