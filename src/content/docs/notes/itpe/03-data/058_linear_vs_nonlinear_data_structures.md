## 연관 키워드

- 선형 vs 비선형 자료구조

## Ⅰ. 선형과 비선형 자료구조의 개요

- 핵심 요약 : 데이터 원소 간 관계에 따른 자료구조의 양대 분류와 선정 기준 체계.
- 개념 : 컴퓨터 시스템에서 대량의 데이터를 효율적으로 저장·조직화·처리하기 위해 데이터 간 논리적 관계와 물리적 메모리 배치를 체계화한 방법의 분류.
- 배경 및 필요성 :
  1. 업무 데이터의 관계 특성에 부합하는 자료구조 선정 필요.
  2. 시간 복잡도와 공간 효율성의 최적화 요구.
  3. 메모리 계층과 캐시 특성을 반영한 성능 설계 필요.
- 주요 목적 : 관계의 본질에 맞는 자료구조 선정을 통한 연산 효율성과 성능 극대화.

## Ⅱ. 선형과 비선형 자료구조의 특징

- 핵심 요약 : 1:1 순차 관계와 1:N·N:M 복합 관계, 순회 경로와 메모리 배치의 차이.

1. 선형 구조의 1:1 순차 관계 : 앞뒤 원소가 각각 하나씩 존재하는 순차 배열.
2. 비선형 구조의 복합 관계 : 계층(1:N) 또는 망형(N:M)의 다대다 연결.
3. 순회 경로의 차이 : 단일 순회 경로와 재귀·큐·스택 기반의 다방향 탐색.
4. 메모리 배치 방식 : 연속 배열·포인터 연결과 참조 네트워크·인접 행렬·인접 리스트.
5. 연산 복잡도의 차이 : 접근·탐색·삽입·삭제의 자료구조별 복잡도 분포.

## Ⅲ. 선형과 비선형 자료구조의 구조 (흐름)

- 핵심 요약 : 양대 분류의 계통 구조와 세부 자료구조의 동작 메커니즘.

```text
[ 자료구조 계통 분류도 ]
+-----------------------------+-----------------------------+
|   선형 자료구조 (Linear)    | 비선형 자료구조 (Non-linear)|
+-----------------------------+-----------------------------+
| - 1:1 순차 배열             | - 1:N 계층, N:M 망형 관계   |
| - 단일 순회 경로            | - 다양한 순회 경로          |
| - 배열, 연결리스트          | - 트리, 그래프              |
| - 스택, 큐, 덱              | - 힙, 트라이                |
+-----------------------------+-----------------------------+
```

```text
[ 세부 자료구조 동작 메커니즘 ]
- 스택(Stack)  : LIFO(후입선출) → 함수 호출 스택, 실행 취소
- 큐(Queue)    : FIFO(선입선출) → 프린터 스풀, 메시지 큐
- 트리(Tree)   : 루트 기준 비순환 계층 → 디렉토리, B-Tree 인덱스
- 그래프(Graph): 정점과 간선의 순환 허용 망형 → 네트워크, 최단 경로
```

## Ⅳ. 선형 자료구조와 비선형 자료구조의 비교

- 핵심 요약 : 원소 관계, 메모리 배치, 순회 방식, 대표 구조와 활용 분야의 차이.

| 비교 항목 | 선형 자료구조(Linear) | 비선형 자료구조(Non-linear) |
| :--- | :--- | :--- |
| 원소 간 관계 | 1:1 (선행자·후임자 각 1개) | 1:N (부모-자식), N:M (정점-간선) |
| 메모리 배치 | 연속(배열) 또는 포인터 단방향 연결 | 복합 포인터 네트워크, 인접 행렬·리스트 |
| 순회 방식 | 단일 루프 선형 순회 | 재귀, 큐·스택 활용 다방향 탐색 |
| 대표 구조 | Array, Linked List, Stack, Queue, Deque | Binary Tree, B-Tree, Heap, Graph, Trie |
| 주요 활용 | 버퍼, 실행 취소, 대기열, 메모리 풀 | 디렉토리, DB 인덱스, 네트워크 라우팅 |

## Ⅴ. 선형과 비선형 자료구조의 장점과 한계

- 핵심 요약 : 단순 순차 처리와 복합 관계 표현의 장점, 탐색 복잡도와 캐시 미스·스택 오버플로우의 한계.

- 장점
  1. 선형 구조의 단순성과 캐시 친화적 연속 메모리 접근.
  2. 비선형 구조의 계층·망형 관계의 정확한 표현.
  3. 업무 관계에 부합하는 자료구조 선정의 유연성.

- 한계점 1 : 선형 구조의 대규모 탐색 복잡도 $O(n)$
  - 한계점 : 정렬되지 않은 배열·연결 리스트의 순차 탐색은 데이터 규모 증가 시 처리 지연 심화.
  - 해결 방안 : B+Tree·Red-Black Tree 등 비선형 트리 또는 해시 테이블로 전환하여 탐색 복잡도를 $O(\log n)$ 이하로 단축.
- 한계점 2 : 비선형 포인터 구조의 캐시 미스와 메모리 단편화
  - 한계점 : 힙 메모리에 무작위 분산 할당된 노드는 캐시 로컬리티 파괴로 실제 실행 속도 저하.
  - 해결 방안 : 캐시 친화적 자료구조(Cache-Oblivious B-Tree, Flattened Array Tree)와 풀 메모리 할당자 적용.
- 한계점 3 : 재귀 탐색의 호출 스택 오버플로우
  - 한계점 : 깊은 트리나 순환 그래프를 DFS로 순회하면 호출 스택 한계 초과로 프로세스 강제 종료.
  - 해결 방안 : 명시적 반복문과 인메모리 스택·큐(BFS) 구조로 리팩토링, 방문 노드 추적 해시셋으로 무한 루프 차단.

## Ⅵ. 자료구조 선정에 대한 기술사적 제언

- 핵심 요약 : 캐시 로컬리티 우선, 관계의 본질 부합 선정, 메모리 접근 패턴 검증.
- 캐시 로컬리티 우선 : 이론적 $O(1)$ 연결 리스트보다 물리적 연속 배열이 캐시 적중률 덕분에 런타임 성능에서 유리.
- 관계의 본질 부합 선정 : 계층·분류 업무는 트리 구조(Closure Table, 재귀적 CTE(Common Table Expression)), 상호 연관·추천·사기 탐지(FDS, Fraud Detection System)는 그래프 DB 채택.
- 메모리 접근 패턴 검증 : 실제 워크로드의 접근 빈도와 지역성을 측정하여 자료구조를 검증.

## Ⅶ. 결론

- 핵심 요약 : 자료구조 선정은 데이터 관계와 메모리 접근 특성의 부합이 성능을 좌우하는 설계 요소.
- 요약 : 선형·비선형의 분류 기준과 원소 관계, 순회, 복잡도 비교.
- 시사점 : 업무 모델과 하드웨어 캐시 특성을 함께 고려한 자료구조 선정 필요.
