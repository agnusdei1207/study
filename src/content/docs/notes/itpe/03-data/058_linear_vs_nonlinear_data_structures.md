## 연관 키워드

- 선형 자료구조(Linear Data Structure), 비선형 자료구조(Non-linear Data Structure)
- 배열(Array), 연결 리스트(Linked List), 스택(Stack), 큐(Queue), 트리(Tree), 그래프(Graph), 시간 복잡도(Time Complexity)

## Ⅰ. 선형과 비선형 자료구조의 개요

- 핵심 요약 : 데이터 원소 간 관계에 따라 자료구조를 양대 분류하고, 관계 특성에 맞춰 선정하는 기준.
- 개념 : 데이터 원소 간 논리적 관계에 따라 자료구조를 **선형 자료구조**(Linear Data Structure)와 **비선형 자료구조**(Non-linear Data Structure)로 나눈 분류 체계.
- 배경 및 필요성 : 관계와 맞지 않는 자료구조를 쓰면 탐색과 갱신 비용이 커지므로, 업무 데이터의 관계 특성에 맞춘 선정이 필요.
- 주요 목적 : 관계의 본질에 맞는 자료구조를 골라 연산 효율과 성능을 확보.

## Ⅱ. 선형과 비선형 자료구조의 특징 및 장점

- 핵심 요약 : 원소 간 관계의 차이가 순회 경로와 메모리 배치, 연산 비용을 결정.

1. 선형 구조 : 앞뒤 원소가 각각 하나씩 있는 1:1 순차 배열 → 단순한 순차 처리와 캐시 친화적 접근.
2. 비선형 구조 : 계층(1:N)이나 망형(N:M)의 다대다 연결 → 복합 관계의 정확한 표현.
3. 순회 경로 : 선형은 단일 경로로 순회하고, 비선형은 재귀 호출이나 보조 자료구조를 활용한 다방향 탐색 → 관계 구조에 맞는 탐색 가능.
4. 메모리 배치 : 선형은 연속 배열이나 포인터 단방향 연결을 쓰고, 비선형은 인접 행렬·인접 리스트 같은 참조 구조를 씀.
5. 연산 복잡도 : 접근·탐색·삽입·삭제의 시간 복잡도가 구조마다 달라 연산 빈도에 맞춰 선택.

## Ⅲ. 선형과 비선형 자료구조의 구조 (흐름)

- 핵심 요약 : 양대 분류의 계통과 세부 구조의 동작 원리를 한눈에 보는 구조.

```text
[자료구조]
  선형 (1:1 순차)
    배열 / 연결 리스트 / 스택 / 큐 / 덱
  비선형 (1:N, N:M)
    트리 / 그래프 / 힙 / 트라이
```

- **스택** (Stack) : LIFO(Last In First Out, 후입선출) 구조로 함수 호출 스택과 실행 취소에 쓰인다.
- **큐** (Queue) : FIFO(First In First Out, 선입선출) 구조로 프린터 스풀과 메시지 큐에 쓰인다.
- **트리** (Tree) : 루트를 기준으로 순환이 없는 계층 구조로 디렉터리와 B-Tree 인덱스에 쓰인다.
- **그래프** (Graph) : 정점과 간선으로 이루어진 망형 구조로 네트워크와 최단 경로 탐색에 쓰인다.

```text
[비선형 탐색의 두 경로]
  DFS : 스택 또는 재귀로 깊이 우선 탐색
  BFS : 큐로 너비 우선 확장
          ↓
  방문 기록(해시셋)으로 순환 차단
```

## Ⅳ. 선형 자료구조와 비선형 자료구조의 비교

- 핵심 요약 : 원소 관계, 메모리 배치, 순회 방식의 차이가 대표 구조와 활용 분야를 가름.

| 비교 항목 | 선형 자료구조(Linear) | 비선형 자료구조(Non-linear) |
| --- | --- | --- |
| 원소 간 관계 | 1:1 (선행자·후임자 각 1개) | 1:N (부모-자식), N:M (정점-간선) |
| 메모리 배치 | 연속 배열 또는 포인터 단방향 연결 | 포인터 네트워크, 인접 행렬·인접 리스트 |
| 순회 방식 | 단일 경로의 순차 순회 | 재귀, 큐·스택 활용 다방향 탐색 |
| 대표 구조 | 배열, 연결 리스트, 스택, 큐, 덱 | 이진 트리, B-Tree, 힙, 그래프, 트라이 |
| 주요 활용 | 버퍼, 실행 취소, 대기열 | 디렉터리, DB 인덱스, 네트워크 라우팅 |

- 선택 기준 : 원소 관계가 순차인지 계층·망형인지, 그리고 연산이 삽입·삭제 중심인지 탐색 중심인지에 따라 구조를 고른다.

## Ⅴ. 선형과 비선형 자료구조의 한계와 방안

- 핵심 요약 : 선형은 대규모 탐색 비용, 비선형은 캐시 미스와 재귀 깊이가 한계이므로 구조 전환과 실행 방식 개선을 함께 적용.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 선형 구조의 탐색 비용 O(n) | 정렬되지 않은 배열·연결 리스트의 순차 탐색 → 데이터 증가 시 지연 심화 | B+Tree, Red-Black Tree 같은 트리 또는 해시 테이블로 전환해 O(log n) 이하로 단축 | 탐색 응답 시간, 원소 수 대비 지연 |
| 비선형 포인터 구조의 캐시 미스·메모리 단편화 | 힙에 무작위로 흩어진 노드 → 캐시 지역성 저하로 실행 속도 저하 | 캐시 친화적 구조(Cache-Oblivious B-Tree)와 메모리 풀(Memory Pool) 할당자 적용 | 캐시 미스율 |
| 재귀 탐색의 호출 스택 오버플로우 | 깊은 트리나 순환 그래프를 DFS 재귀로 순회 → 호출 스택 한계 초과로 강제 종료 | 명시적 반복문과 스택·큐(BFS) 구조로 재작성, 방문 노드 해시셋으로 무한 루프 차단 | 최대 탐색 깊이, 스택 사용량 |

## Ⅵ. 자료구조 선정에 대한 기술사적 제언

- 핵심 요약 : 캐시 지역성을 고려하고 업무 관계에 맞춰 구조를 고른 뒤, 실제 접근 패턴으로 검증하는 방향.
- 이론상 O(1)인 연결 리스트보다 물리적으로 연속된 배열이 캐시 적중률 덕분에 실제 실행 속도에서 유리한 경우가 많으므로, 선정 전에 벤치마크로 확인한다.
- 계층·분류 업무는 트리 구조로 설계하고 계층 질의는 Closure Table이나 재귀적 CTE(Common Table Expression)로 처리한다. 상호 연관, 추천, 사기 탐지(FDS, Fraud Detection System) 같은 관계 탐색 업무에는 그래프 데이터베이스를 검토한다.
- 실제 워크로드의 접근 빈도와 지역성을 측정해 자료구조 선정 결과를 검증한다.

## Ⅶ. 결론

- 핵심 요약 : 자료구조 선정은 데이터 관계와 메모리 접근 특성의 부합이 성능을 좌우하는 설계 요소.
- 시사점 : 업무 모델과 하드웨어 캐시 특성을 함께 고려해 선정해야 설계 근거가 남는다.
