## 연관 키워드
- 파티셔닝, 샤딩, 수평 분할, 수직 분할, 파티션 키, 리밸런싱

### Ⅰ. 데이터베이스 분할·샤딩의 개요

- 핵심 요약 : 파티셔닝은 테이블·데이터를 관리 가능한 조각으로 나누는 방법이며 샤딩은 그 조각을 여러 독립 노드에 분산 배치하는 수평 확장 방식.
- 개념 : 테이블·데이터를 관리 가능한 조각으로 나누는 방법이며 샤딩은 그 조각을 여러 독립 노드에 분산 배치하는 수평 확장 방식(**데이터베이스 분할·샤딩**, Database Partitioning and Sharding).
- 배경 및 필요성 : 데이터량·처리량 증가로 단일 노드의 저장·연산·운영 한계 도달.
- 주요 목적 : 데이터 관리성과 수평 처리용량 확대.

### Ⅱ. 데이터베이스 분할·샤딩의 특징 및 장점

- 핵심 요약 : 수평 분할·수직 분할·샤드는 데이터 규모와 병렬 처리를 확장하는 데이터베이스 분할 방식.

1. 수평 분할 : 행을 범위·해시·목록 키로 나눔 → 데이터량·병렬처리 확장.
2. 수직 분할 : 열·도메인 기준 분리 → 접근 빈도·책임 분리.
3. 샤딩 : 파티션을 노드에 배치 → 노드 단위 확장, 분산 트랜잭션 부담.

### Ⅲ. 데이터베이스 분할·샤딩의 구조 (흐름)

- 핵심 요약 : 분할 목적·쿼리 분석 → 파티션/샤드 키 선정 → 라우팅·인덱스 구성 → 분산 배치·리밸런싱 → 장애·정합성 검증.

```text
분할 목적·쿼리 분석
  ↓
파티션/샤드 키 선정
  ↓
라우팅·인덱스 구성
  ↓
분산 배치·리밸런싱
  ↓
장애·정합성 검증
```

```text
논리 테이블
  ↓ 파티션 키 함수
P0 → 노드 A     P1 → 노드 B
P2 → 노드 C     라우터가 키별 위치 결정
```

### Ⅳ. 테이블 파티셔닝과 샤딩 비교

- 핵심 요약 : 주목적 기준 — 테이블 파티셔닝: 관리·조회·보관 성능; 샤딩: 저장·쓰기 처리량 수평 확장.

| 비교 축 | 테이블 파티셔닝 | 샤딩 |
|---|---|---|
| 분산 범위 | 한 DB 인스턴스 내 논리·물리 파티션 가능 | 다수 DB 노드에 데이터 분산 |
| 주 목적 | 관리·조회·보관 성능 | 저장·쓰기 처리량 수평 확장 |
| 운영 | DBMS가 파티션 관리 가능 | 라우팅·분산 운영·리밸런싱 필요 |

### Ⅴ. 데이터베이스 분할·샤딩의 한계와 방안

- 핵심 요약 : 핫 파티션·교차 샤드 질의 등 실제 위험을 원인에 맞는 통제와 지표로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 핫 파티션 | 키 편향으로 일부 노드 과부하 | 카디널리티·분포 측정, 복합·해시 키 검토 | 노드 부하 편차 |
| 교차 샤드 질의 | 조인·정렬·트랜잭션이 네트워크 분산 | 샤드 키 중심 접근·조회 모델·일관성 요구 설계 | 교차 샤드 비율 |
| 재분배 복잡성 | 데이터 증가·노드 변경 시 이동·가용성 위험 | 가상 샤드·온라인 리밸런싱·복구 리허설 | 리밸런싱 시간 |

### Ⅵ. 데이터베이스 분할·샤딩에 대한 제언

- 핵심 요약 : 아키텍트는 샤딩을 마지막 수단 중 하나로 검토하고 단일 DB 파티셔닝·인덱스 최적화와 비용·운영성 비교 후 키·재분배 계획 승인.

- 실행 제안 : 플랫폼 팀은 샤드 키별 분포·핫 키·교차 샤드 질의 비율을 추적하고 온라인 리밸런싱을 정기 리허설.

### Ⅶ. 결론

- 핵심 요약 : 샤딩은 물리적 분산과 수평 확장을 제공하지만 라우팅·분산 트랜잭션·재배치라는 새로운 복잡성을 수반.
- 시사점 : 샤딩은 확장성을 얻는 대신 교차 샤드 질의·트랜잭션·리밸런싱을 운영 책임으로 가져옴.
