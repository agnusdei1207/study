## 지식 로드맵 내 현재 위치

자료처리·데이터 → 분산 데이터베이스 → **분산 데이터베이스**

## 30초 인출

- 본질: 분산 데이터베이스는 여러 노드에 나누거나 복제한 데이터를 함께 관리하며 질의·갱신을 처리하는 데이터베이스
- 메커니즘: 라우터가 위치 메타데이터로 분할 키에 맞는 노드와 복제 정책에 맞는 복제본을 정해 처리하고, 여러 노드의 변경은 조정자가 준비 요청에 이은 커밋 또는 취소로 확정(2PC)
- 통찰: 노드를 늘려도 키 쏠림·복제 지연·노드 간 조인은 사라지지 않으므로 업무별 질의·갱신·복구 목표로 배치와 일관성 정책을 정하고, 2PC·합의·보상 흐름은 서로 다른 문제를 풀므로 목적에 맞게 선택

<details>
<summary>핵심 용어</summary>

- **분산 데이터베이스** : 여러 노드에 분할·복제된 데이터를 논리적으로 하나처럼 관리
- **분할(샤딩)·복제** : 데이터를 나누어 배치 / 같은 데이터를 여러 곳에 둠
- **2PC(2단계 커밋)** : 준비 요청 후 전원 준비 시 커밋, 하나라도 실패하면 취소하는 분산 커밋
- **합의(Consensus)** : 복제본이 같은 변경 순서에 동의하는 프로토콜
- **보상 트랜잭션(Saga)** : 긴 업무 흐름의 각 단계를 취소하는 보상 단계로 정합성 유지
- **분산 투명성** : 위치·분할·복제를 이용자에게 숨기는 성질

</details>

## 2~4교시 25점 답안

## Ⅰ. 분산 데이터베이스의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **분산 데이터베이스** 는 여러 노드에 나누거나 복제한 데이터를 함께 관리하며 질의·갱신을 처리하는 데이터베이스 |
| 목적 | 데이터·부하 분산, 장애 대응, 논리적 접근 제공 |

## Ⅱ. 특징

| 특징 | 운영 영향 |
|---|---|
| 분할·복제 결합 | 부하 분산과 읽기·장애 대응을 별도 정책으로 설계 |
| 논리적 접근 | 라우터·메타데이터가 실제 위치를 숨김 |
| 부분 실패 | 일부 노드·통신 장애가 질의·갱신에 서로 다르게 영향 |

## Ⅲ. 처리 체계와 분산 커밋

```text
응용 질의·갱신 → 위치 메타데이터를 읽는 라우터
   ├ 분할 키 → 담당 노드의 데이터 조각
   └ 복제 정책 → 읽기·갱신 대상 복제본
   ↓ 노드별 처리·결과 병합·갱신 조정 → 장애·복제 지연·정합성 목표 확인
```

```text
조정자 → 참여 노드에 준비 요청 ← 준비·실패 응답
   ├ 모두 준비 → 커밋 결정 전달
   └ 하나라도 실패 → 취소 결정 전달
```

## Ⅳ. 구성과 트랜잭션 방식

| 구성 | 역할 | 확인할 한계 |
|---|---|---|
| 분할·샤딩 | 데이터량·부하 분산 | 키 쏠림·노드 간 조인 |
| 복제 | 읽기·장애 대응 | 지연·충돌·전환 |
| 라우팅·메타데이터 | 데이터 위치·질의 대상 결정 | 배치 변경·오류 |
| 질의 조정 | 노드별 결과 병합 | 네트워크·부분 실패 |

| 투명성 | 숨기는 정보 | 내부 처리 |
|---|---|---|
| 위치 | 저장 노드 | 라우팅 |
| 분할 | 데이터 조각 | 조각 선택·병합 |
| 복제 | 복제본 | 읽기 대상·갱신 전파 |

| 요구 | 처리 방식 예 | 절충 |
|---|---|---|
| 여러 노드의 원자적 확정 | 2PC 등 분산 커밋 | 조정 지연·장애 시 대기 |
| 복제본의 동일한 변경 순서 | 합의·로그 복제 | 통신·합의 비용 |
| 서비스 간 긴 업무 흐름 | 보상 단계·재시도 | 중간 상태·보상 실패 관리 |

2PC·합의·보상 흐름은 해결하는 문제가 다르며 서로의 일반적 대체재가 아님. 투명성은 제품·설정에 따라 범위가 다르고 지연·부분 장애를 없애지 않음.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 키 쏠림·복제 지연으로 노드 확장이 성능·정합성을 보장하지 못함 | 업무별 질의·갱신·복구 목표로 배치·일관성 정책 결정, 장애 시험 |
| 샤드 간 질의 증가로 네트워크·병합 비용 증가 | 대표 조인·집계의 데이터 배치와 통신량 측정 |
| 일부 노드 장애 시 분산 갱신 대기·실패 | 원자적 커밋 범위와 재시도·복구 절차를 장애 시험으로 확인 |

## Ⅵ. 제언

업무별 정합성·복구 목표에 맞춰 배치와 일관성 수준을 정하고, 분산 커밋의 범위를 최소화

```text
질의·갱신 패턴 분석 → 분할·복제 설계 → 일관성·커밋 방식 선택 → 부하·정합성·장애 시험
```

| 구분 | 모든 갱신에 분산 커밋 | 제언: 범위 최소화 |
|---|---|---|
| 지연 | 커짐 | 단일 노드 처리 위주 |
| 장애 | 대기 확산 | 영향 축소 |
