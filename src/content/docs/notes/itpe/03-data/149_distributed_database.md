## 연관 키워드

- 분산 데이터베이스

## Ⅰ. 분산 데이터베이스의 개요

- 핵심 요약 : 물리적으로 분산된 노드를 논리적으로 단일 DB(Database)처럼 운영하는 분산 데이터 관리 체계.
- 개념 : 물리적으로 서로 다른 지리적 위치나 네트워크 노드에 분산 배치된 여러 개의 데이터베이스 시스템이 통신 네트워크로 상호 연결되어 있으면서도, 논리적으로는 단일한 하나의 데이터베이스 시스템처럼 사용자에게 통합된 데이터 서비스를 제공하는 시스템.
- 배경 및 필요성 :
  1. 단일 대형 서버의 수직 확장(Scale-Up) 한계 및 단일 장애점(SPOF, Single Point of Failure) 리스크 극복 필요.
  2. 글로벌 서비스 환경에서 지리적 접근성을 통한 데이터 전송 지연 시간(Latency) 단축 필요.
  3. 대규모 트래픽 분산 처리를 통한 시스템 가용성 및 처리량 확보 필요.
- 주요 목적 : 데이터 분할·복제·투명성 설계를 통한 수평 확장(Scale-Out) 체계 구축과 분산 트랜잭션 원자성 보장.

## Ⅱ. 분산 데이터베이스의 특징

- 핵심 요약 : 분할·할당·복제·투명성의 4대 설계 영역과 분산 트랜잭션 프로토콜 기반의 운영 체계.

1. 분할(Fragmentation) : 단일 릴레이션을 수평·수직·혼합 방식으로 작은 조각(Fragment)으로 나누는 설계 기법.
2. 할당(Allocation) : 쪼개진 조각들을 어느 물리적 노드 서버에 배치할 것인가 결정하는 배치 정책.
3. 복제(Replication) : 데이터 가용성을 위해 동일 조각 사본을 여러 노드에 동시 보관하는 이중화 체계.
4. 투명성(Transparency) : 분할, 위치, 복제 사실을 애플리케이션으로부터 은닉하여 단일 시스템처럼 사용하게 하는 특성.
5. 분산 트랜잭션 프로토콜 : 2PC(Two-Phase Commit) 등 다수 노드 간 원자성 보장을 위한 커밋 프로토콜 운영.

## Ⅲ. 분산 데이터베이스의 구조 (흐름)

- 핵심 요약 : 4대 분산 설계 영역의 구조와 2PC 프로토콜 기반 분산 트랜잭션 처리 흐름.

```text
[ 분산 설계 4대 영역 ]
 1. 분할 (Fragmentation) : 단일 릴레이션을 여러 작은 조각(Fragment)으로 나눔 (수평, 수직, 혼합)
 2. 할당 (Allocation)     : 쪼개진 조각들을 어느 물리적 노드 서버에 배치할 것인가 결정
 3. 복제 (Replication)    : 데이터 가용성을 위해 동일 조각 사본을 여러 노드에 동시 보관
 4. 투명성 (Transparency) : 분할, 위치, 복제 사실을 애플리케이션으로부터 완벽 은닉
```

```text
[ 2단계 커밋 (2PC, Two-Phase Commit) 동작 흐름 ]
 [조정자 (Coordinator)]                [참여자 1 (Participant)]   [참여자 2 (Participant)]
 ------------------------------------------------------------------------------------------
 (Phase 1: 준비 단계)
    --- Prepare(준비) 메시지 전송 --->
                                       --- Vote-Commit(준비 완료) 응답 --->
                                       --- Vote-Commit(준비 완료) 응답 --->
 (Phase 2: 커밋 단계)
    [모든 참여자 성공 확인!]
    --- Global-Commit 메시지 브로드캐스트 --->
                                       --- ACK (적용 완료) 응답 --->
                                       --- ACK (적용 완료) 응답 --->
    [트랜잭션 완전 종료]
```

- 릴레이션 분할의 3대 유형 비교 :

| 분할 유형 | 분할 기준 및 메커니즘 | 재구성 복원 연산 | 장점 및 고려사항 |
| :--- | :--- | :--- | :--- |
| 수평 분할(Horizontal) | 특정 조건절(WHERE)을 기준으로 행(Tuple)들을 분할 | 합집합(Union) | 지역별/기간별 독립 처리에 최적, 전수 조사 시 네트워크 집계 필요 |
| 수직 분할(Vertical) | 속성(Column)들을 기준으로 분할 (단, PK(Primary Key)는 모든 조각에 필수 포함) | 자연 조인(Natural Join) | 자주 접근하는 핵심 컬럼의 메모리 캐시 적중률 극대화, 조인 비용 발생 |
| 혼합 분할(Hybrid) | 수평 분할과 수직 분할을 다단계로 교차 적용 | 합집합 후 조인 | 정밀한 데이터 로컬리티 달성, 분산 트랜잭션 관리 복잡도 극상 |

## Ⅳ. 분산 데이터베이스와 중앙 집중식 데이터베이스의 비교

- 핵심 요약 : 단일 노드 중심의 중앙 집중식 DB와 다중 노드 분산 처리 체계의 구조적 차이.

| 비교 항목 | 중앙 집중식 DB(Database) | 분산 데이터베이스(Distributed Database) |
| :--- | :--- | :--- |
| 데이터 배치 | 단일 서버 노드에 집중 저장 | 다수 노드에 분산 저장 및 복제 |
| 확장 방식 | 수직 확장(Scale-Up) | 수평 확장(Scale-Out) |
| 장애 영향 | 단일 장애점(SPOF)으로 전체 중단 | 부분 장애 시에도 서비스 지속 가능 |
| 트랜잭션 관리 | 로컬 트랜잭션으로 단순 처리 | 2PC 등 분산 트랜잭션 프로토콜 필요 |
| 데이터 일관성 | 강한 일관성 보장 용이 | CAP(Consistency, Availability, Partition Tolerance) 정리 기반 트레이드오프 수반 |
| 네트워크 의존성 | 낮음 | 높음 (지연, 파티션 리스크) |

## Ⅴ. 분산 데이터베이스의 장점과 한계

- 핵심 요약 : 수평 확장성·가용성의 장점과 분산 트랜잭션 복잡도·일관성 트레이드오프의 한계.

- 장점
  1. 저비용 범용 노드 추가를 통한 유연한 수평 확장(Scale-Out) 체계.
  2. 지리적 분산 배치를 통한 데이터 전송 지연 시간(Latency) 단축 효과.
  3. 노드 복제를 통한 고가용성(HA, High Availability) 및 장애 내성 확보 효과.
  4. 논리적 단일 시스템 뷰 제공으로 애플리케이션 개발 복잡도 완화 효과.

- 한계점 1 : 2PC(Two-Phase Commit)의 블로킹(Blocking) 문제
  - 한계점 : 분산 트랜잭션 수행 중 코디네이터(Coordinator) 노드가 장애를 일으키면 모든 참여 노드가 락(Lock)을 보유한 채 대기 상태에 빠져 시스템 전체 중단(Hang) 발생.
  - 해결 방안 : Raft/Paxos 합의 알고리즘 기반 복제 적용, 마이크로서비스 간에는 2PC 대신 사가(Saga) 패턴(보상 트랜잭션) 및 TCC(Try-Confirm-Cancel) 패턴 적용.
- 한계점 2 : 분산 노드 간 물리적 시계 불일치
  - 한계점 : 개별 서버의 NTP(Network Time Protocol) 시계 드리프트(Clock Drift)로 인해 분산 트랜잭션의 커밋 순서 판별이 왜곡되어 스냅샷 격리성 파괴 및 데이터 덮어쓰기 발생.
  - 해결 방안 : 구글 트루타임(TrueTime: GPS(Global Positioning System) + 원자시계 결합) API(Application Programming Interface) 활용, 또는 논리적 인과관계를 보장하는 HLC(Hybrid Logical Clock) 및 벡터 클록(Vector Clock) 도입.
- 한계점 3 : 네트워크 파티션 발생 시 일관성(CP)과 가용성(AP)의 트레이드오프
  - 한계점 : 노드 간 네트워크 단절 시 쓰기를 거부하여 비즈니스 중단이 발생하거나, 쓰기를 허용하여 데이터 불일치 및 스플릿 브레인(Split Brain) 초래.
  - 해결 방안 : 정족수(Quorum) 기반 쓰기/읽기 설정(W + R > N), 충돌 없는 복제 데이터 타입(CRDT, Conflict-Free Replicated Data Type) 적용, 도메인 중요도별 CP/AP 이원화 아키텍처 수립.

## Ⅵ. 분산 데이터베이스에 대한 기술사적 제언

- 핵심 요약 : 하이브리드 논리 시계 채택, 분산 조인 최소화, 도메인별 일관성 등급 분리 설계.
- 글로벌 정렬을 위한 하이브리드 논리 시계(HLC) 채택 : 지리적으로 분산된 다중 데이터센터 간 트랜잭션의 엄격한 직렬성(Strict Serializability)을 보장하기 위해, 원자시계가 필요한 구글 트루타임의 대안으로 NTP 오차를 논리 시계로 보정하는 HLC를 표준으로 검토할 필요.
- 분산 조인의 네트워크 셔플(Shuffle) 최소화 : 분산 DB에서 서로 다른 노드에 위치한 테이블 간 조인은 막대한 네트워크 대역폭을 고갈시키므로, 외래키 관계의 자식 테이블을 부모 테이블과 동일한 물리 노드 파티션에 함께 묶어 저장하는 인터리브드 테이블(Interleaved Table / Colocation) 설계 적용 필요.
- 도메인별 일관성 등급 분리 : 금융 원장 등 강한 일관성이 필수인 도메인은 CP 계열, 추천·로그 등 가용성이 우선인 도메인은 AP 계열로 분리 운영하는 이원화 아키텍처 수립 필요.

## Ⅶ. 결론

- 핵심 요약 : 분산 데이터베이스는 수평 확장과 고가용성을 달성하는 대신 일관성 제어 복잡도를 수반하는 아키텍처.
- 요약 : 분할·복제·투명성 설계와 2PC 프로토콜 기반의 분산 트랜잭션 관리 체계.
- 시사점 : CAP 정리 기반의 도메인별 일관성 전략 수립과 NewSQL 기술 도입이 분산 데이터베이스 성공의 핵심 요소.
