## 연관 키워드

- 힙, Heap
- 완전 이진 트리, 최대 힙, 최소 힙
- Heapify, 우선순위 큐, 힙 정렬

## Ⅰ. 힙(최대·최소 힙)의 개요

- 핵심 요약 : **힙**(Heap)은 완전 이진 트리 형태에 부모와 자식 간 대소 관계를 유지하여 최댓값 또는 최솟값을 즉시 꺼내는 자료구조.
- 개념 : **완전 이진 트리**(Complete Binary Tree) 형태에 부모-자식 간 대소 속성을 더한 자료구조로, **최대 힙**은 부모가 자식보다 크거나 같고 **최소 힙**은 작거나 같은 구조.
- 배경 및 필요성 : 최댓값 또는 최솟값을 반복해서 조회하고 삽입·삭제해야 하는 작업 환경에서, 정렬된 배열의 유지 비용을 줄일 필요.
- 주요 목적 : **우선순위 큐**(Priority Queue) 구현, 힙 정렬, Top-K 탐색 지원.

## Ⅱ. 힙의 특징 및 장점

- 핵심 요약 : 완전 이진 트리의 형태 속성과 힙 속성이 결합되어, 최값 조회는 빠르고 삽입·삭제는 높이에 비례하는 비용으로 처리되는 구조.

1. 형태 속성 : 완전 이진 트리 구조를 유지하며 마지막 레벨은 왼쪽부터 채움 → 배열로 빈틈없이 저장 가능.
2. 힙 속성 : 최대 힙은 부모 ≥ 자식, 최소 힙은 부모 ≤ 자식 → 루트에 최댓값 또는 최솟값 위치.
3. **Heapify** : 삽입 시 위로 올리는 Heapify-Up, 삭제 시 아래로 내리는 Heapify-Down 수행 → 힙 속성을 O(log n)으로 복원.
4. **배열 매핑** : 인덱스 산술로 부모와 자식 위치 계산 → 포인터 없이 메모리 효율과 캐시 친화성 확보.
5. **일괄 구성** : 바닥부터 Heapify를 수행하는 방식으로 O(n) 시간에 전체 힙 구성.

## Ⅲ. 힙의 구조 (흐름)

- 핵심 요약 : 1차원 배열의 인덱스 산술로 트리를 표현하고, 삽입과 삭제가 끝 원소와 루트의 교환 후 Heapify로 복원되는 흐름.

```text
[ 배열 인덱스 기반 힙 (1-based) ]

          [1] 루트
         /    \
      [2]      [3]
     /   \    /   \
   [4]   [5] [6]   [7]

Parent(i) = floor(i / 2)
Left(i)   = 2i
Right(i)  = 2i + 1
```

```text
[ 핵심 연산 흐름 ]

삽입 : 배열 끝에 추가
   ↓
Heapify-Up으로 부모와 비교 교환 (O(log n))
```

```text
[ 삭제 연산 흐름 ]

삭제 : 루트 추출
   ↓
마지막 원소를 루트로 이동
   ↓
Heapify-Down으로 자식과 비교 교환 (O(log n))
```

## Ⅳ. 힙의 연산 비교

- 핵심 요약 : 최값 조회, 삽입, 삭제, 빌드, 임의 검색의 시간 복잡도를 비교하면 힙은 최값 접근에 특화된 구조임.

| 연산 | 시간 복잡도 | 비고 |
| --- | --- | --- |
| 최값 조회 | O(1) | 루트 원소 접근 |
| 삽입 | O(log n) | Heapify-Up |
| 삭제 | O(log n) | Heapify-Down |
| 일괄 구성 | O(n) | 바닥부터 Heapify |
| 임의 값 검색 | O(n) | 선형 탐색 필요 |

## Ⅴ. 힙의 한계와 방안

- 핵심 요약 : 임의 검색의 비효율, 캐시 비친화성, 동시 접근 시 락 경합의 한계를 색인 구조와 분기 계수 조정, 동시성 제어로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 임의 검색과 삭제의 O(n) | 중간 원소 위치를 알 수 없어 선형 탐색 필요 | 해시 맵과 결합한 색인 힙 구성, **피보나치 힙**(Fibonacci Heap) 검토 | 검색 소요 시간 |
| 캐시 비친화성 | 트리가 깊어 캐시 미스 증가 | **d-ary 힙**(분기 계수 d를 키운 힙) 적용 | 캐시 미스율 |
| 멀티스레드 락 경합 | 단일 뮤텍스에 접근이 몰림 | 세분화 락 또는 작업 분산 큐 구조 적용 | 처리량 |

## Ⅵ. 힙에 대한 기술사적 제언

- 핵심 요약 : 0-based 인덱스와 사전 할당 메모리를 표준 구현 규칙으로 삼고, 힙을 K-way Merge와 Top-K 응용에 재사용하는 설계가 바람직함.
- 구현 표준은 0-based 인덱스를 기준으로 삼는 것이 바람직하다. 이때 Left는 2i+1, Right는 2i+2, Parent는 (i-1)/2로 계산하면 나눗셈을 비트 연산으로 대체할 수 있다.
- 재할당에 따른 지연을 줄이려면 사전 할당 메모리 풀에서 힙 배열을 확보하는 방식을 권장한다.
- 여러 정렬 구간을 병합하는 작업에는 **K-way Merge**(K개의 정렬된 입력을 최소 힙으로 병합)를 적용하고, 대량 데이터의 상위 K건 탐색에는 Top-K 처리를 힙으로 구현하는 것이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : 힙은 최값 접근을 빠르게 처리하는 완전 이진 트리 기반 자료구조로, 우선순위 큐와 힙 정렬의 기반.
- 임의 검색이 잦은 작업에는 적합하지 않으므로, 자료구조 선택 시 연산 빈도를 먼저 분석하는 것이 필요하다.
