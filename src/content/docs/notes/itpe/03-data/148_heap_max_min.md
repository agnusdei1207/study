## 답안 골격
```text
[힙 (Max·Min Heap)] ◀━━ 머리: Ⅶ 내 의견 (완전 이진 트리의 배열 1:1 매핑을 통한 캐시 친화적 우선순위 큐 구현)
 ┃
 ┣━ Ⅰ 개요 ───── 최댓값 또는 최솟값을 $O(1)$의 시간복잡도로 빠르게 추출하기 위해 부모와 자식 간의 대소 관계를 일정하게 유지하는 완전 이진 트리(Complete Binary Tree)
 ┣━ Ⅱ 특징 ───── 완전 이진 트리 특성(포인터 없이 1차원 배열 구현) · 느슨한 정렬(Semi-sorted) · 삽입/삭제 $O(\log N)$ · 우선순위 큐(Priority Queue)의 핵심
 ┣━ Ⅲ 구조 ───── 최대 힙(부모 $\ge$ 자식, 루트가 최댓값) / 최소 힙(부모 $\le$ 자식, 루트가 최솟값) / 배열 인덱스 규칙(부모 $\lfloor i/2 \rfloor$, 자식 $2i, 2i+1$)
 ┣━ Ⅳ 흐름 ───── ① 삽입: 최하단 리프 추가 후 Up-Heap(부모와 비교 승격) → ② 삭제: 루트 추출 후 마지막 노드를 루트로 이동 → ③ Down-Heap(자식과 비교 강등)
 ┣━ Ⅴ 비교 ───── 힙(Heap) vs 이진 탐색 트리(BST)
 ┗━ Ⅵ 실무 ───── 힙 생성(Heapify) 비용 최적화($O(N)$ 상향식 구성) / 실시간 대용량 트래픽의 Top-K 랭킹 추출
```
- 필수 키워드: 힙(Heap) · 최대 힙(Max Heap) · 최소 힙(Min Heap) · 완전 이진 트리 · 우선순위 큐 · Up-Heap · Down-Heap · Heapify · 힙 정렬($O(N \log N)$)
- 기출: 124회 `자료구조 힙(Heap)의 개념, 유형(최대 힙, 최소 힙) 및 삽입과 삭제 연산 과정을 설명하시오.` → Ⅰ 정의 + Ⅲ 2대 유형 및 배열 매핑 + Ⅳ 연산 과정 도식 + Ⅴ BST와의 비교

## 한 줄 본질
- 전체를 완벽히 정렬하지 않고 오직 1등(최댓값/최솟값)만 가장 빨리 뽑아내야 할 때 정렬 오버헤드 낭비 → 부모-자식 간에만 대소 관계를 둔 완전 이진 트리로 구성하여 $O(1)$에 추출 → 극적인 연산 효율 확보 / 2등 이하의 탐색은 $O(N)$ 소요

## 핵심 그림
```text
[최대 힙(Max Heap)의 트리 구조와 1차원 배열 인덱스 1:1 매핑]

        [트리 형태: 부모 >= 자식]                    [1차원 배열 물리 매핑]
                 [90] (인덱스 1)             인덱스:  [0]  [1]  [2]  [3]  [4]  [5]  [6]
                ╱    ╲                        값   :  -   [90] [70] [80] [30] [50] [60]
             [70]    [80]                                   │    │
            ╱   ╲    ╱                                      │    └── 좌: 2*2=4, 우: 2*2+1=5
         [30]  [50] [60]                                    └─────── 좌: 2*1=2, 우: 2*1+1=3
         (2)   (3)  (4)

  * 인덱스 계산 공식 (1-based):
    - 부모 노드: i / 2
    - 왼쪽 자식: 2 * i
    - 오른쪽 자식: 2 * i + 1
```

## 핵심 용어
- 완전 이진 트리(Complete Binary Tree): 마지막 레벨을 제외하고 모든 레벨이 완전히 채워져 있으며, 마지막 레벨의 노드들은 왼쪽부터 빈틈없이 순서대로 채워진 트리
- Heapify(힙 생성): 임의의 순서로 나열된 $N$개의 원소를 자식 노드부터 역순으로 Down-Heap을 수행하여 단 $O(N)$의 선형 시간 내에 힙 구조로 재배열하는 알고리즘

## 핵심 통찰
- 힙은 포인터(메모리 참조)를 전혀 쓰지 않음 → '완전 이진 트리'라는 성질 덕분에 단순한 1차원 배열 하나만으로 모든 부모-자식 관계를 비트 시프트 연산(`i << 1`)으로 초고속 계산 가능하여 CPU 캐시 적중률이 극대화됨
- 힙은 '느슨한 정렬(Semi-ordered)' 상태임 → 루트 노드만 확실한 최댓값일 뿐, 2등 노드는 루트의 왼쪽 자식일 수도 있고 오른쪽 자식일 수도 있음(형제 노드 간 순서 없음)
- 실시간 실시간 검색어 순위나 주식 호가창에서 'Top 100위'를 유지할 때, 전체 1,000만 건을 매번 정렬하면 $O(N \log N)$으로 뻗지만, 크기 100짜리 최소 힙을 쓰면 $O(N \log K)$로 연산량을 99.9% 절감 가능

## 이웃 토픽과 구분
- 힙 vs 이진 탐색 트리(BST): 힙 = '부모-자식 간의 상하 관계'만 존재(좌우 순서 없음), 최댓값/최솟값 고속 추출($O(1)$) 특화 / BST = '왼쪽 < 부모 < 오른쪽'이라는 엄격한 좌우 순서 존재, 임의의 키 탐색($O(\log N)$) 특화

## 문제·원인·대책
- 적용 상황: 대규모 실시간 스트리밍 로그에서 에러 발생 빈도 상위 10개(Top-10) 실시간 집계
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 로그가 들어올 때마다 전체 배열을 재정렬(`Arrays.sort`)하여 CPU 100% 다운 | 매 건당 $O(N \log N)$ 전체 정렬 연산 수행 | 크기 10의 최소 힙(Min Heap)을 유지하며 새 데이터와 루트 비교 | 연산 복잡도 $O(\log 10)$으로 축소 및 실시간 처리 안정화 |
| $N$개의 배열을 힙으로 만들 때 원소를 하나씩 삽입하여 $O(N \log N)$ 지연 발생 | 상향식 삽입(Up-Heap)의 반복 적용으로 인한 불필요한 깊은 순회 | 리프 노드를 제외한 내부 노드부터 하향식 Down-Heap(Heapify) 적용 | 힙 빌드 시간을 $O(N \log N)$에서 선형 $O(N)$으로 80% 단축 |

## 찾아볼 것
- 두 개의 힙을 단 $O(\log N)$에 빠르게 병합할 수 있도록 포인터 기반으로 설계된 피보나치 힙(Fibonacci Heap)의 원리와 다익스트라(Dijkstra) 알고리즘 적용
