## 연관 키워드

- 제5정규형(5NF, Fifth Normal Form), PJNF(Projection-Join Normal Form), 조인 종속성(JD, Join Dependency)
- 다치 종속성(MVD, Multivalued Dependency), 무손실 조인 분해, 4NF, BCNF

## Ⅰ. 제5정규형의 개요

- 핵심 요약 : 모든 비자명(non-trivial) 조인 종속성이 후보 키, 즉 슈퍼키에 의해서만 성립하도록 만든 정규형.
- 개념 : 세 개 이상의 릴레이션으로 분해할 때 가짜 튜플 없이 원래 관계를 복원할 수 있도록 조인 종속성을 제거한 정규형 (**제5정규형**, 5NF, Fifth Normal Form). 투영-조인 정규형(PJNF, Projection-Join Normal Form)이라고도 부름.
- 배경 및 필요성 : 4NF까지의 정규화로 해결하지 못하는 순환적 삼항 제약에서는 두 개의 릴레이션으로 나누면 가짜 튜플이 생기므로, 세 개 이상으로 분해할 필요가 생김.
- 주요 목적 : 다원 분해에서 무손실 조인을 보장해 데이터 중복과 갱신 이상을 제거.

## Ⅱ. 제5정규형의 특징 및 장점

- 핵심 요약 : 조인 종속성을 제거해 다원 분해의 무손실성을 보장하는, 정규화 계층의 최상위 단계.

1. **조인 종속성** (JD, Join Dependency, 여러 투영을 조인하면 원래 릴레이션이 복원되는 종속 관계) : 분해한 릴레이션들을 조인한 결과가 원본과 일치 → 복원 시 가짜 튜플 제거.
2. **다치 종속성** (MVD, Multivalued Dependency, 한 속성 값에 대해 다른 속성의 값 집합이 독립적으로 결정되는 종속) : 2개 릴레이션으로 분해하는 JD의 특수한 경우이며, 4NF에서 제거됨.
3. 3분해의 필요성 : 순환적 삼항 관계는 2분해 시 가짜 튜플이 생기고, 3분해 시 원본을 정확히 복원 → 분해 단위를 늘려 정보 손실을 막음.
4. **무손실 조인 분해** (Lossless Join Decomposition, 분해 후 조인해도 정보 손실과 가짜 튜플이 생기지 않는 분해) : 데이터 무결성 보존.
5. PJNF 성질 : 모든 조인 종속성이 후보 키에 의해 함축되는 상태 → 정규화의 이론적 완결점.

## Ⅲ. 조인 종속성의 구조 (흐름)

- 핵심 요약 : SPJ 삼항 관계에서 2분해는 가짜 튜플을 만들고 3분해는 원본을 복원하는 구조.
- SPJ : 공급자(S), 부품(P), 프로젝트(J)의 삼항 관계로, S가 P를 공급하고 J가 P를 사용하며 S가 J에 참여하면 S는 J에 P를 공급해야 하는 제약을 가짐.

```text
[ 5NF 위반 사례: SPJ 삼항 관계 ]

규칙: S가 P를 공급 + J가 P를 사용
      + S가 J에 참여
      => S는 J에 P를 공급

원본: 복합 키 (S, P, J)
```

```text
[ 분해 비교 ]

2분해 SP ⋈ PJ   -> 가짜 튜플 발생
3분해 SP ⋈ PJ ⋈ SJ -> 원본 복원
```

- 정규형 계층 : 1NF에서 시작해 BCNF(Boyce-Codd Normal Form, 모든 결정자가 후보 키인 정규형)를 거쳐 4NF와 5NF로 확장됨.

```text
[ 정규형 계층 ]

1NF
 ↓
2NF -> 3NF -> BCNF
 ↓
4NF (MVD 제거)
 ↓
5NF (JD 제거)
```

## Ⅳ. 4NF와 5NF의 비교

- 핵심 요약 : 4NF는 다치 종속성을, 5NF는 조인 종속성을 제거하며, 분해 단위가 2개에서 3개 이상으로 늘어남.

| 항목 | 4NF | 5NF |
| --- | --- | --- |
| 제거 대상 | 다치 종속성 (MVD) | 조인 종속성 (JD) |
| 분해 단위 | 2개 릴레이션 | 3개 이상 릴레이션 |
| 발생 배경 | 독립적인 다치 속성의 중복 | 순환적 삼항 제약 |

## Ⅴ. 제5정규형의 한계와 방안

- 핵심 요약 : JD 판별의 어려움, 조인 성능 저하, 다중 테이블 갱신 문제를 설계 검토, BCNF 상한, 트리거로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| JD 판별 복잡도 | 조인 종속성은 데이터만으로 찾기 어려워 업무 의미 분석이 필요 | 도메인 전문가와 업무 규칙을 점검하고 모델링 도구로 설계 검증 | 설계 검토 결과 |
| 조인 성능 오버헤드 | 3중 조인으로 OLTP(Online Transaction Processing) 성능 저하 | BCNF까지만 엄격히 정규화하고, 필요한 영역만 5NF 적용 후 반정규화 | 조인 응답 시간 |
| 갱신 난제 | 세 개 이상의 테이블을 원자적으로 갱신해야 해 이상 현상 우려 | 복합 외래 키와 인덱스 설계, 트리거로 갱신 로직 캡슐화 | 트랜잭션 성공률 |

## Ⅵ. 제5정규형에 대한 기술사적 제언

- 핵심 요약 : 실무에서는 BCNF를 정규화 상한으로 두고, 5NF 수준의 제약은 복합 키와 트리거로 처리하는 것이 바람직함.

1. 엔터프라이즈 RDBMS(Relational Database Management System)는 성능과 유지보수를 고려해 BCNF까지 엄격히 정규화하는 것을 기준으로 삼는 것이 좋다.
2. 5NF 수준의 조인 종속 제약이 업무상 중요하다면 테이블을 무리하게 나누기보다 복합 기본 키 제약과 트리거로 규칙을 강제하는 편이 실용적이다.
3. 조인 종속성은 자동으로 식별하기 어려우므로, 설계 리뷰 단계에서 업무 전문가와 함께 규칙을 확인하는 절차를 두는 것이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : 제5정규형은 조인 종속성을 제거해 무손실 분해를 보장하는 이론적 완결 정규형임.
- 시사점 : 실무 설계는 성능과 유지보수 비용을 고려해 BCNF를 상한으로 두고, 5NF는 규칙이 명확한 영역에 한정하는 것이 현실적임.
