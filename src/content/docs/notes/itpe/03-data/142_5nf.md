## 큰 그림과 30초 인출

```text
[제5정규형 (5NF, PJNF) 아키텍처 개요]

  [4NF 상태의 3자 복합 관계 테이블] R(의사, 환자, 약품)
                     │
                     │ 2개로 분해 시: R1(의사, 환자) ⋈ R2(환자, 약품)
                     │ ──► 가짜 튜플(Spurious Tuple) 발생! 데이터 무결성 붕괴
                     ▼
  [조인 종속성(JD)에 따른 3개 릴레이션 동시 분해]
   ┌─────────────────┬─────────────────┬─────────────────┐
   │ R1 (의사, 환자) │ │ R2 (환자, 약품) │ │ R3 (의사, 약품) │
   └─────────────────┴─────────────────┴─────────────────┘
                     │
                     ▼ 자연 조인(Natural Join) 복원
   [무손실 조인(Lossless Join) 완료: R1 ⋈ R2 ⋈ R3 == R]
```

- 본질: **제4정규형(4NF)을 만족하면서 릴레이션에 존재하는 모든 조인 종속성(Join Dependency, JD)이 해당 릴레이션의 후보키(Candidate Key)에 의해서만 성립되도록 하여, 2개의 부분 릴레이션으로는 분해할 수 없고 반드시 3개 이상의 릴레이션으로 동시 분해해야만 거짓 튜플(Spurious Tuple) 없이 무손실 복원이 보장되는 정규형(PJNF)**
- 암기: `오-조-후-무` (5NF, 조인종속성, 후보키에종속, 무손실조인) / `의-환-약` (의사-환자-약품 3자 복합 관계 사례)
- 판단축:
  - **4NF 위배 해소**: 1개의 결정자에 둘 이상의 독립적인 다치 종속(MVD)이 얽힌 경우 $\rightarrow$ 2개의 테이블로 분해 ($A \twoheadrightarrow B \mid C$).
  - **5NF 위배 해소**: 3개 이상의 속성이 상호 순환적으로 결합되어 2개로 분해 시 거짓 튜플이 발생하는 조인 종속(JD)인 경우 $\rightarrow$ 반드시 3개 이상의 테이블로 동시 분해 ($\bowtie [R_1, R_2, R_3]$).
- 주의: 실무 OLTP 환경에서 5NF 적용 시 단순 조회 질의에도 3개 이상의 테이블 조인 I/O가 발생하여 성능이 급격히 저하되므로, 실무 데이터 모델링은 대다수 3NF/BCNF에서 마감하고 조인 종속성은 비즈니스 규칙(제약조건/트리거)으로 방어함

## 1교시 10점 답안

| 항목 | 핵심 서술 내용 |
|:---|:---|
| **정의** | 4NF를 만족하면서 모든 조인 종속성(JD)이 후보키에 의해서만 성립되어, 3개 이상의 릴레이션으로 무손실 분해되는 프로젝트-조인 정규형(PJNF) |
| **등장 배경** | 3자 복합 관계 릴레이션을 2개로 분해 시 가짜 튜플(Spurious Tuple)이 생성되어 원래 데이터로 무손실 복원이 불가능한 결함 해결 |
| **핵심 수식** | $R = \Pi_{R_1}(R) \bowtie \Pi_{R_2}(R) \bowtie \Pi_{R_3}(R)$, 단 모든 $R_i$가 $R$의 슈퍼키 |
| **4NF vs 5NF** | 4NF는 다치 종속(MVD) 제거 및 2개 분해 / 5NF는 조인 종속(JD) 제거 및 3개 이상 동시 분해 |
| **실무 제언** | 3-Way 조인 I/O 병목 방지를 위해 실무는 BCNF 수준에서 정규화를 타협하고 도메인 계층 검증 로직으로 무결성 방어 |

### 핵심 관계

| 비교 항목 | 제4정규형 (4NF) | 제5정규형 (5NF, PJNF) |
|:---|:---|:---|
| **제거 대상 종속성** | 비자명 다치 종속성 (MVD, Multi-Valued Dependency) | 비자명 조인 종속성 (JD, Join Dependency) |
| **수학적 표기** | $X \twoheadrightarrow Y \mid Z$ | $\bowtie [R_1, R_2, ..., R_n]$ ($n \ge 3$) |
| **분해 릴레이션 수** | 항상 **2개**의 부분 릴레이션으로 분해 | 반드시 **3개 이상**의 부분 릴레이션으로 분해 |
| **선행 정규형 조건** | BCNF 만족 | 4NF 만족 |
| **성립 조건** | 모든 MVD $X \twoheadrightarrow Y$에 대해 $X$가 슈퍼키 | 모든 JD $\bowtie [R_1, ..., R_n]$에 대해 각 $R_i$가 슈퍼키 |
| **복원 연산** | 2개 릴레이션의 자연 조인 ($R_1 \bowtie R_2 = R$) | 3개 이상 릴레이션의 순환 자연 조인 ($\bowtie_{i=1}^n R_i = R$) |
| **판별 난이도** | 보통 (속성 간 독립적 1:N 관계 식별) | 매우 극심 (도메인 업무 규칙에 대한 n자 결합성 추적 필요) |
| **실무 적용도** | 실무에서 간혹 적용 (독립 취미/자격증 모델링) | 실무 적용 극히 희박 (이론적 학술 모델 수준) |

## 2~4교시 25점 답안

### Ⅰ. 제5정규형(5NF)의 개념 및 등장 배경

#### 한줄 요약: 2개의 릴레이션으로는 무손실 분해가 불가능하고 반드시 3개 이상의 릴레이션으로 쪼개야 거짓 튜플 없이 복원되는 정규형

- **배경**:
  - 제4정규형(4NF)은 다치 종속성(MVD)을 제거하여 릴레이션을 2개로 분해함으로써 중복을 제거함
  - 그러나 3개 이상의 속성이 대등하게 얽혀 있는 복합 관계(n-ary Relationship)에서는 릴레이션을 임의로 2개로 분해할 경우 원래 데이터에 없던 거짓 튜플(Spurious Tuple)이 생성되어 무손실 조인이 깨지는 현상 발생
  - Ronald Fagin(1979)이 제안한 프로젝트-조인 정규형(PJNF, Project-Join Normal Form)으로, 조인 종속성(JD)을 완벽히 통제하는 최종 이론적 정규형으로 정립됨
- **정의**:
  - 릴레이션 $R$이 제4정규형(4NF)을 만족하고, $R$에 성립하는 모든 조인 종속성 $\bowtie [R_1, R_2, ..., R_n]$에 대해 각 부분 릴레이션 $R_i$가 $R$의 슈퍼키(Super Key)이거나 자명한(Trivial) 조인 종속성만 존재하는 상태
- **핵심 가치**:
  - n자 관계 데이터의 삽입·삭제·갱신 이상(Anomaly)을 수학적으로 완벽히 차단
  - 다차원 프로젝트-조인 연산 간의 무손실 복원(Lossless Join Decomposition) 보장

### Ⅱ. 조인 종속성(Join Dependency, JD)의 메커니즘과 수식

#### 한줄 요약: 프로젝션 후 자연 조인했을 때 원본과 정확히 일치하는 성질로, 4NF의 MVD를 n차원으로 일반화한 개념

### 1. 조인 종속성의 수학적 정의
- 릴레이션 $R$의 속성 부분집합 $R_1, R_2, ..., R_n$에 대해 다음 관계가 성립할 때, $R$은 조인 종속성 $\bowtie [R_1, R_2, ..., R_n]$을 만족함:
  $$R = \Pi_{R_1}(R) \bowtie \Pi_{R_2}(R) \bowtie ... \bowtie \Pi_{R_n}(R)$$
- 여기서 $\bigcup_{i=1}^n R_i = R$이며, 각 $R_i$는 $R$의 진부분집합임

### 2. 자명한(Trivial) 조인 종속성
- $R_1, R_2, ..., R_n$ 중 어느 하나가 $R$ 전체 속성 집합과 동일한 경우($\exists i, R_i = R$), 이는 항상 참이 되므로 자명한 조인 종속성이라 함
- 5NF의 목표는 **비자명한(Non-trivial) 조인 종속성**이 후보키가 아닌 속성들에 의해 발생하는 것을 제거하는 것임

### 3. 대표 사례: 의사-환자-약품 3자 관계 (Doctor-Patient-Medicine)
- 제약 규칙:
  1. 의사 $D$는 환자 $P$를 진료함
  2. 환자 $P$는 약품 $M$을 복용함
  3. 의사 $D$는 약품 $M$을 처방할 수 있는 권한이 있음
  4. 단, 의사 $D$가 환자 $P$에게 약품 $M$을 처방하려면 위의 3가지 조건이 동시에 충족되어야 함
- 문제 발생: 이를 단일 테이블 $R(D, P, M)$으로 관리하면 특정 의사가 진료하는 환자에게 본인이 처방 권한이 없는 약품이 매핑되는 이상현상 발생
- 잘못된 2자 분해: $R_1(D, P)$와 $R_2(P, M)$으로 분해 후 조인하면, 의사 $D$가 권한이 없는 약품 $M$까지 조인 결과로 생성되는 **거짓 튜플** 발생

### Ⅳ. 제4정규형(4NF)과 제5정규형(5NF)의 비교

#### 한줄 요약: 2개 분해를 다루는 다치 종속성(MVD)과, 3개 이상 분해를 다루는 조인 종속성(JD)의 수학적 확장 차이

| 비교 항목 | 제4정규형 (4NF) | 제5정규형 (5NF, PJNF) |
|:---|:---|:---|
| **제거 대상 종속성** | 비자명 다치 종속성 (MVD, Multi-Valued Dependency) | 비자명 조인 종속성 (JD, Join Dependency) |
| **수학적 표기** | $X \twoheadrightarrow Y \mid Z$ | $\bowtie [R_1, R_2, ..., R_n]$ ($n \ge 3$) |
| **분해 릴레이션 수** | 항상 **2개**의 부분 릴레이션으로 분해 | 반드시 **3개 이상**의 부분 릴레이션으로 분해 |
| **선행 정규형 조건** | BCNF 만족 | 4NF 만족 |
| **성립 조건** | 모든 MVD $X \twoheadrightarrow Y$에 대해 $X$가 슈퍼키 | 모든 JD $\bowtie [R_1, ..., R_n]$에 대해 각 $R_i$가 슈퍼키 |
| **복원 연산** | 2개 릴레이션의 자연 조인 ($R_1 \bowtie R_2 = R$) | 3개 이상 릴레이션의 순환 자연 조인 ($\bowtie_{i=1}^n R_i = R$) |
| **판별 난이도** | 보통 (속성 간 독립적 1:N 관계 식별) | 매우 극심 (도메인 업무 규칙에 대한 n자 결합성 추적 필요) |
| **실무 적용도** | 실무에서 간혹 적용 (독립 취미/자격증 모델링) | 실무 적용 극히 희박 (이론적 학술 모델 수준) |

### Ⅴ. 5NF 정규화 절차 및 무결성 검증 체계

#### 한줄 요약: 3자 조인 종속성 식별 $\rightarrow$ 투영 분해 $\rightarrow$ 거짓 튜플 검증 $\rightarrow$ 무결성 제약조건 설정의 4단계

```text
[5NF 정규화 및 검증 4단계 프로세스]

  [Step 1: 4NF 확인] ──► BCNF 및 다치 종속성(MVD) 완전 해소 여부 검증
           │
           ▼
  [Step 2: JD 식별]   ──► 3개 이상 속성 집합 간 순환적 결합 제약조건 도출
           │              - JD(R1, R2, R3)의 비자명성 및 후보키 여부 검토
           ▼
  [Step 3: 투영 분해] ──► n개의 부분 릴레이션으로 무손실 프로젝션
           │              - R1(A, B), R2(B, C), R3(A, C)
           ▼
  [Step 4: 무손실 검증]──► 자연 조인 연산 수행 (R1 ⋈ R2 ⋈ R3)
                          - Spurious Tuple 존재 여부 확인 후 FK/체크 제약 배포
```

1. **Step 1 (4NF 정규화 완결)**:
   - 모든 결정자가 후보키인 BCNF 상태에서, 독립된 다치 종속성(MVD)이 모두 분해되었는지 확인.
2. **Step 2 (비자명 조인 종속성 식별)**:
   - 복합 기본키를 구성하는 3개 이상의 속성 간에 쌍(Pair) 단위의 제약조건이 존재하는지 업무 규칙 분석.
3. **Step 3 (투영 분해, Projection)**:
   - 원본 릴레이션을 3개의 부분 릴레이션으로 동시 투영 생성.
4. **Step 4 (무손실 복원 및 외래키 검증)**:
   - 3개 테이블을 자연 조인했을 때 원본과 카디널리티 및 튜플 내용이 100% 일치함을 수학적/데이터적으로 입증.

### Ⅵ. 실무 아키텍처 한계와 반정규화 트레이드오프

#### 한줄 요약: 5NF의 무결성 보장 이면의 다중 조인 I/O 병목으로 인해, 실무에서는 3NF/BCNF 타협 및 애플리케이션 방어 채택

```text
[5NF 정규화 vs 반정규화의 트레이드오프]

  ┌─────────────────────────────────────────────────────────────┐
  │                 5NF 완전 정규화 설계                        │
  │  - 장점: 데이터 중복 0%, 완벽한 무결성, 이상현상 원천 차단 │
  │  - 단점: 단순 조회 시 3-Way Join 디스크 I/O 및 CPU 급증     │
  └──────────────────────────────┬──────────────────────────────┘
                                 │ 트레이드오프 판정
                                 ▼
  ┌─────────────────────────────────────────────────────────────┐
  │                 실무적 반정규화 타협 아키텍처               │
  │  - RDBMS 설계: 3NF 또는 BCNF 수준에서 테이블 구조 유지      │
  │  - 3자 무결성: DB 체크 제약조건, 트리거, 애플리케이션 검증  │
  │  - 조회 최적화: 읽기 모델(Read Model) 캐싱 및 Materialized View │
  └─────────────────────────────────────────────────────────────┘
```

- **조회 성능의 치명적 저하**:
  - 온라인 트랜잭션(OLTP) 환경에서 환자의 처방 이력을 한 번 조회할 때마다 3개 테이블을 결합하는 복합 Nested Loop / Hash Join이 발생하여 응답 속도가 급격히 지연됨
- **개발 생산성 및 쿼리 복잡도 증가**:
  - CRUD 모든 영역에서 3개 테이블에 대한 동시 트랜잭션 락(Lock)과 분산 쓰기가 요구되어 데드락(Deadlock) 위험 상승
- **엔지니어링 대응 방안**:
  - 테이블 구조는 BCNF 수준으로 단순화하되, 의사-약품 간 처방 인가 규칙은 별도의 마스터 테이블(`DOCTOR_MEDICINE_PERMISSION`)로 관리하고, 처방 트랜잭션 시 애플리케이션 서비스 계층(Domain Validator)에서 검증 수행

### Ⅶ. 기술사적 제언

### 학습자 통찰 메모 — 답안 밖

> **[핵심 통찰]**
> 제5정규형(5NF)은 데이터베이스 정규화 이론의 '수학적 정점'이지만, 엔지니어링 실무에서는 '교조주의의 함정'을 보여주는 대표적인 반면교사이다. 5NF의 본질은 "2개로는 못 쪼개지만 3개로는 쪼갤 수 있는 특이한 결합 관계(JD)"를 수학적으로 풀어낸 것이다. 기술사 답안에서는 5NF의 수학적 정의(JD 수식과 무손실 분해)를 정확히 도식화하여 이론적 깊이를 과시하되, 마지막 결론에서는 실무 OLTP 환경의 조인 비용과 트레이드오프를 짚어내며 "왜 현업 아키텍트들이 3NF/BCNF에서 정규화를 멈추고 애플리케이션 무결성으로 우회하는가"를 설득력 있게 제시해야 고득점을 얻는다.

> **[나라면 이렇게 쓴다]**
> 1교시형 문제라면 5NF 정의와 의-환-약 3자 분해 SVG 다이어그램, 4NF와의 비교표를 반 페이지 안에 밀도 높게 집약하겠다. 2교시형 문제라면 3자 조인으로 인한 디스크 I/O 블록 I/O 폭증 메커니즘을 버퍼 캐시 관점에서 분석하고, CQRS(명령-조회 책임 분리) 패턴을 접목하여 C(쓰기)는 3NF+도메인 밸리데이터, R(조회)는 비정규화된 캐시/검색 엔진으로 분리하는 현대적 엔터프라이즈 아키텍처 해법을 제언하겠다.

### 실전 답안용 기술사적 제언

- **판정**: 5NF는 이론적으로 무결성을 완벽히 보장하나, 3-Way 조인에 따른 I/O 부하와 트랜잭션 복잡성으로 인해 순수 OLTP 시스템에 직접 적용하는 것은 부적합함.
- **대응**: 데이터 모델은 3NF/BCNF 수준에서 안정화하고, 3자 복합 종속성에 대한 제약은 RDBMS 복합 유니크 인덱스, 트리거, 또는 DDD(도메인 주도 설계) 엔터티 검증 로직으로 이관함.
- **검증**: 무결성 검증 테스트 스위트를 파이프라인에 구축하여 Spurious Tuple 유입을 상시 방어하고, 쿼리 플랜 분석(`EXPLAIN ANALYZE`)을 통해 3자 조인 부하 발생 지점을 모니터링함.
- **효과**: 디스크 I/O 및 버퍼 풀 경합을 최소화하여 TPS 300% 이상 개선 및 데이터 정합성 100% 동시 달성.
