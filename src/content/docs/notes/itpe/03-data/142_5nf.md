## 답안 골격
```text
[제5정규형 (5NF, Fifth Normal Form / PJNF)] ◀━━ 머리: Ⅶ 내 의견 (3개 이상의 복합 조인 종속성 해소와 실무 조회 성능을 고려한 정규화 타협)
 ┃
 ┣━ Ⅰ 개요 ───── 제4정규형(4NF)을 만족하면서 릴레이션의 모든 조인 종속성(JD)이 해당 릴레이션의 후보키(Candidate Key)에 의해서만 성립되는 정규형
 ┣━ Ⅱ 특징 ───── 프로젝트-조인 정규형(PJNF) · 3개 이상의 릴레이션으로 무손실 분해 및 재결합 · 거짓 튜플(Spurious Tuple) 없는 복원 보장
 ┣━ Ⅲ 구조 ───── 조건: 4NF 만족 + 모든 $JD(R_1, R_2, ..., R_n)$에 대해 각 $R_i$가 슈퍼키 ┃ 사례: (의사, 환자, 약품) 3자 관계의 무손실 분해
 ┣━ Ⅳ 흐름 ───── ① 4NF 릴레이션 식별 → ② 3개 이상 속성 간 순환 조인 종속성($\bowtie [R_1, R_2, R_3]$) 발견 → ③ 후보키가 아닌 JD 제거를 위해 3개 테이블로 분해 → ④ 무손실 조인 검증
 ┣━ Ⅴ 비교 ───── 4NF(다치 종속 MVD, 2개 분해) vs 5NF(조인 종속 JD, 3개 이상 분해)
 ┗━ Ⅵ 실무 ───── 5NF 적용 시 3개 테이블 조인으로 인한 극심한 쿼리 지연 발생으로 실무에서는 대다수 3NF/BCNF에서 정규화 중단
```
- 필수 키워드: 제5정규형(5NF) · PJNF · 조인 종속성(Join Dependency) · 무손실 분해 · 거짓 튜플 · 4NF · 다치 종속(MVD) · 후보키
- 배점 전략: 10점 = Ⅰ → Ⅲ (의사, 환자, 약품) 3개 테이블 분해 도식 → Ⅴ 4NF vs 5NF 비교표 / 25점 = Ⅰ~Ⅶ, Ⅳ 조인 종속성 수식 증명 및 Ⅵ 실무적 반정규화 절충 기준
- 기출: 124회 `데이터베이스 정규화 과정에서 제4정규형(4NF)과 제5정규형(5NF)의 개념, 종속성 유형 및 분해 과정을 비교 설명하시오.` → Ⅰ 정의 + Ⅲ JD 개념 및 사례 + Ⅴ 4NF vs 5NF 비교 + Ⅵ 실무 적용성 한계

## 한 줄 본질
- 2개 테이블로는 무손실 분해가 안 되지만 3개 이상의 테이블로는 쪼개어 복원할 수 있는 복합 관계 존재 → 모든 조인 종속성을 오직 후보키만으로 제한하여 3개 이상의 릴레이션으로 분해 → 완벽한 데이터 무결성 달성 / 실무 조인 비용 폭증

## 핵심 그림
```text
[제5정규형(5NF): 3개 릴레이션으로의 조인 종속(JD) 무손실 분해]

  [5NF 위배 릴레이션 R: (의사, 환자, 약품)]
  * 의사가 특정 환자를 진료하고, 환자가 특정 약품을 복용하며, 의사가 해당 약품을 처방할 수 있는 3자 제약

                   ┌───────────────────────────────┐
                   │ R (의사, 환자, 약품)          │
                   └──────────────┬────────────────┘
                                  │ 2개로는 분해 불가! (거짓 튜플 발생)
                                  │ 반드시 '3개 릴레이션'으로 동시 분해!
          ┌───────────────────────┼───────────────────────┐
          ▼                       ▼                       ▼
  ┌───────────────┐       ┌───────────────┐       ┌───────────────┐
  │ R1 (의사,환자)│       │ R2 (환자,약품)│       │ R3 (의사,약품)│
  └───────────────┘       └───────────────┘       └───────────────┘
          ▲                       ▲                       ▲
          └───────────────────────┴───────────────────────┘
            자연 조인 (R1 ⋈ R2 ⋈ R3 = R) : 무손실 조인 복원 성공!
```

## 핵심 용어
- 조인 종속성(Join Dependency, JD): 릴레이션 $R$이 부분 릴레이션들 $R_1, R_2, ..., R_n$으로 프로젝션된 후 자연 조인했을 때 원래의 $R$과 완전히 동일하게 복원되는 성질 ($\bowtie [R_1, R_2, ..., R_n]$)
- 거짓 튜플(Spurious Tuple): 릴레이션을 잘못 분해한 후 다시 조인했을 때, 원래 테이블에는 없었던 엉뚱하고 가짜인 행(데이터)이 새롭게 생겨나는 무결성 파괴 현상

## 핵심 통찰
- 4NF는 '2개의 부분 릴레이션으로 무손실 분해되는 다치 종속(MVD)'을 다루지만, 5NF는 '오직 3개 이상으로 쪼개야만 원래대로 복원되는 조인 종속(JD)'을 다룸
- 5NF 위배 테이블을 2개로 쪼개서 다시 조인하면 무조건 거짓 튜플(Spurious Tuple)이 생겨 데이터가 오염됨 → 반드시 3개($R_1, R_2, R_3$)로 쪼개서 3자 조인을 해야만 원래 데이터가 나옴
- 하지만 실무 엔지니어링 환경에서 5NF는 '이론적 학술 모델'에 가까움 → 5NF까지 정규화하면 단순 조회 하나를 위해 매번 3개 이상의 테이블을 조인해야 하므로, 실무에서는 거의 예외 없이 3NF나 BCNF 수준에서 정규화를 멈춤

## 이웃 토픽과 구분
- 4NF vs 5NF: 4NF = 하나의 속성에 둘 이상의 독립적인 다치 속성이 얽힌 다치 종속(MVD, $A \twoheadrightarrow B$)을 제거하여 2개 테이블로 분해 / 5NF = 3개 이상의 속성이 맞물려 2개로는 안 되고 3개 이상으로 쪼개야 하는 조인 종속(JD)을 제거

## 문제·원인·대책
- 적용 상황: 병원 통합 의료 정보 시스템의 의사-환자-처방약 데이터 모델링
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 의사-환자-약품 단일 테이블 적재 시 의사가 다룰 수 없는 약품이 환자에게 매핑되는 이상현상 | 후보키가 아닌 속성 간 조인 종속성(JD) 방치 | 3개의 독립 릴레이션((의사, 환자), (환자, 약품), (의사, 약품))으로 5NF 분해 | 처방 권한 제약조건 100% 무결성 유지 |
| 5NF 분해 후 매 진료 조회마다 3개 테이블 조인으로 화면 렌더링 3초 지연 | 과도한 5NF 분해로 인한 다중 조인 디스크 I/O 병목 | 조인 빈도가 높은 화면을 위해 반정규화된 통합 뷰 또는 캐시 테이블 도입 | 무결성 검증은 트리거로 이관하고 조회 응답 0.05초로 단축 |

## 내 의견
- [교조적 고차 정규화의 함정 탈피] 데이터 모델러가 이론에 매몰되어 5NF까지 테이블을 쪼개어 개발자들에게 수십 줄짜리 복합 조인 SQL을 강요하는 비실용적 설계 경계 → 나라면: 온라인 트랜잭션 시스템(OLTP)은 BCNF 수준에서 정규화를 완결하고, 3자 이상의 복합 비즈니스 무결성 규칙은 DDL 선언이나 애플리케이션 서비스 도메인 계층(DDD)의 밸리데이터로 방어하는 실용적 아키텍처 수립
