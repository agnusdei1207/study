## 지식 로드맵 내 현재 위치

자료처리·데이터 → 데이터 가용성·복구 → **데이터 복제**

## 30초 인출

- 본질: 데이터 복제는 원본의 변경을 다른 노드·저장소에 전달해 사본을 유지하는 기술
- 메커니즘: 원본의 변경을 스토리지(블록)·DBMS(로그)·CDC(행 이벤트) 계층에서 복제 채널로 전달해 사본에 적용하고, 원본 장애 시 RPO·승격 조건을 확인해 사본을 승격한 뒤 옛 원본은 쓰기를 차단하고 재동기화
- 통찰: 복제가 성공해도 복구 시간(RTO)과 손실(RPO)이 충족되는 것은 아니고 논리적 손상도 사본에 전파되므로, 업무별 RPO·RTO를 정하고 승격·재동기화를 훈련하며 백업·시점 복구를 병행

<details>
<summary>핵심 용어</summary>

- **데이터 복제(Replication)** : 원본 변경을 사본에 전달·반영해 동기화하는 기술
- **스토리지·DBMS·CDC 복제** : 블록·볼륨 / 로그·엔진 / 행 변경 이벤트 단위 복제
- **동기·비동기·반동기** : 복제 확인을 기다림 / 기다리지 않음 / 지정 수신 확인만 기다림
- **RPO·RTO** : 허용 데이터 손실 시점 / 서비스 복구 목표 시간
- **승격(Failover)·재동기화** : 사본을 원본으로 전환 / 복구된 옛 원본을 새 원본에 맞춤
- **멱등 처리** : 같은 이벤트를 여러 번 적용해도 결과가 같은 처리

</details>

## 2~4교시 25점 답안

## Ⅰ. 데이터 복제의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터 복제** 는 원본 변경을 다른 노드·저장소에 전달해 사본을 유지하는 기술 |
| 목적 | 장애 복구·가용성·읽기 확장 요구에 맞는 사본 제공 |

## Ⅱ. 특징

| 특징 | 운영상 의미 |
|---|---|
| 변경 전파 | 원본 변경이 사본에 반영되기까지 순서·지연·확인 지점 존재 |
| 복제 단위 선택 | 블록·로그·행 이벤트에 따라 복구 범위와 재처리 방식이 달라짐 |
| 복구와의 분리 | 사본이 있어도 승격·재동기화·논리적 손상 대비 필요 |

## Ⅲ. 복제 체계와 장애 복구

```text
업무 쓰기 → 원본 DB ─ 변경 기록·전달 → 복제 채널 → 대기 노드·사본 (적용·재생)
        └ 커밋 확인 조건 → 사용자 응답        복제 지연·적용 상태 감시
```

```text
원본 장애 감지 → 쓰기 권한·복제 상태 확인
   ├ 목표 RPO·승격 조건 충족 → 사본 승격·트래픽 전환
   └ 미충족 → 손실 범위 판단·백업/시점 복구
복구된 옛 원본 → 쓰기 차단 확인 → 새 원본에서 재동기화
```

## Ⅳ. 복제 계층과 동기화 방식 비교

| 계층 | 복제 단위 | 제약 |
|---|---|---|
| 스토리지 | 블록·볼륨 변경 | 일관된 복구는 스토리지·DBMS 구성에 의존 |
| DBMS | 물리·논리 로그 | 제품·모드별 기능 확인 |
| CDC | 행 변경 이벤트 | 이기종 전달, 순서·중복·스키마·재처리 설계 필요 |

| 방식 | 확인 | 장점 | 한계 |
|---|---|---|---|
| 동기 | 커밋 응답 전 복제 확인 | 설정된 장애 범위에서 손실 감소 | 원격 지연이 응답에 반영 |
| 비동기 | 원본 커밋 후 전달 | 원격 대기 부담 감소 | 장애 시 미전달 변경 손실 |
| 반동기 | 제품이 정한 수신·기록 확인 | 동기와 비동기의 절충 | ACK가 디스크 반영을 뜻하는지 제품별 확인 |

어느 방식도 설정과 장애 조건을 벗어난 절대 보장을 뜻하지 않음.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 복제 성공을 복구 성공으로 착각 | 업무별 RPO·RTO를 정하고 승격·재동기화 훈련 결과와 비교 |
| 복제 지연·미전달 변경으로 손실 | 지연·재생 속도·로그 보존량 관측, 승격 기준 마련 |
| 양쪽 쓰기·논리적 손상이 사본에 전파 | 단일 쓰기 권한·펜싱과 별도 백업·시점 복구 병행 |
| CDC 재처리의 순서·중복 오류 | 이벤트 식별자·멱등 처리·스키마 변경 절차 검증 |

## Ⅵ. 제언

복제는 가용성 수단으로, 논리적 손상 대비는 별도 백업·시점 복구로 설계하고 승격을 정기 훈련

```text
RPO·RTO 정의 → 복제 계층·방식 선택 → 승격·재동기화 훈련 → 백업·시점 복구 병행
```

| 구분 | 복제만으로 복구 | 제언: 복제 + 백업 + 훈련 |
|---|---|---|
| 논리적 손상 | 사본에도 전파 | 시점 복구로 대응 |
| RTO | 미검증 | 훈련으로 확인 |
