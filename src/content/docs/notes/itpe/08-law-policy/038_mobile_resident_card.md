## 30초 인출

- 본질: **모바일 주민등록증** 은 주민등록법에 따라 휴대전화에 암호화된 형태로 설치되며 실물 주민등록증과 효력이 같은 디지털 신분증
- 메커니즘: IC 주민등록증 태깅 또는 주민센터 발급 절차로 설치하고, 확인자는 검증앱으로 필요한 정보를 요청해 사용자의 동의를 받은 항목 확인

<details><summary>핵심 용어</summary>

- **모바일 주민등록증** : 주민등록법 제24조의2에 따라 이동통신단말장치에 암호화된 형태로 설치되며 실물 주민등록증과 효력이 같은 신분증.
- **IC (Integrated Circuit) 주민등록증** : 모바일 주민등록증 발급에 필요한 보안 정보를 저장한 집적회로 칩이 내장된 주민등록증.
- **QR (Quick Response) 발급** : 주민센터에서 신청한 뒤 안내된 QR 코드를 촬영해 모바일 주민등록증을 발급받는 경로.
- **신원 확인자** : 모바일 신분증 검증앱 등을 이용해 제시된 신분증의 진위와 요청 정보를 확인하는 기관·사업자.
- **선택 정보 제공** : 확인 요청 항목을 사용자가 확인하고 동의한 뒤 해당 정보를 제공하는 방식.

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **모바일 주민등록증** 은 이동통신단말장치에 암호화된 형태로 설치되는 실물 주민등록증과 효력이 같은 신분증 |
| 목적 | 디지털 환경에서 주민등록증의 신원 확인 기능을 제공하고 정보 제시의 편의성 향상 |

### Ⅱ. 법적 기반과 발급 경로

| 항목 | 기준 |
|---|---|
| 근거 | 주민등록법 제24조의2 및 시행령 제38조 |
| 효력 | 주민등록증과 동일 |
| IC 경로 | IC 주민등록증을 단말기로 태깅해 발급·재발급 신청 |
| QR 경로 | 주민센터 방문 신청 후 안내된 QR 코드 촬영·본인 확인 |
| 설치 제한 | 본인이 사용하는 이동통신단말장치 1대에 발급 |

```text
발급 신청
   │
   ├─ IC 주민등록증 소지 ──> 단말기 태깅 ──> 본인 확인 ──> 설치
   │
   └─ QR 방식 ────────────> 주민센터 방문·신청 ──> QR 촬영 ──> 설치
```

### Ⅲ. 제시·진위 확인

| 참여자 | 처리 |
|---|---|
| 신원 확인자 | 업무 목적에 필요한 정보 요청 |
| 사용자 | 요청 항목 확인과 제공 동의 |
| 검증앱 | 모바일 신분증의 진위 확인과 승인된 정보 제시 |

전자정보 유효기간은 3년. 단말기 교체·분실·훼손 또는 만료 때 재발급·분실 신고 절차 확인.

제언: 확인자의 요청 항목을 업무 목적에 맞게 제한하고 사용자가 동의한 정보만 확인하는 절차 마련.

---

## 2~4교시 25점 답안

## Ⅰ. 법적 근거와 기능

| 구분 | 핵심 |
|---|---|
| 정의 | **모바일 주민등록증** 은 이동통신단말장치에 암호화된 형태로 설치되는 실물 주민등록증과 효력이 같은 신분증 |
| 목적 | 디지털 환경에서 주민등록증의 신원 확인 기능을 제공하고 정보 제시의 편의성 향상 |

발급 대상은 주민등록증을 발급받은 사람. 발급권자는 시장·군수·구청장이며 세부 절차는 주민등록법령에 따름.

## Ⅱ. 발급·재발급 경로

| 경로 | 절차 | 특징 |
|---|---|---|
| IC 칩 | IC 주민등록증 발급·수령 → 단말기 태깅 → 본인 확인 | 해당 IC 주민등록증 보유자는 단말기에서 발급·재발급 신청 가능 |
| QR | 주민센터 방문 → 주민등록증 제시·신청 → QR 촬영·본인 확인 | IC 칩이 없는 실물증도 신청 가능 |
| 재발급 | 단말기 교체·사용 불가·전자정보 만료 등 사유에 맞춘 재신청 | 기존 발급 경로와 신청 요건 확인 |

## Ⅲ. 정보 제시와 진위 확인

```text
┌────────────────┐
│ 확인자가 항목 요청 │
└────────┬───────┘
         v
┌────────────────┐
│ 사용자가 요청 확인 │
└────────┬───────┘
         │ 동의
         v
┌────────────────┐
│ 검증앱이 진위 확인 │
└────────┬───────┘
         v
요청·동의된 신원정보 제시
```

확인자는 검증앱 등 공식 절차로 진위를 확인하고 업무 목적에 필요한 정보를 요청. 화면 이미지·캡처본만으로 공식 검증을 대체하지 않도록 처리 절차 구성.

## Ⅳ. 발급 정보와 보안 운영

| 항목 | 법령·운영 기준 |
|---|---|
| 설치 형태 | 이동통신단말장치에 암호화된 형태 |
| 발급 단말 | 본인 사용 단말 1대 |
| 전자정보 유효기간 | 3년 |
| 분실·사용 불가 | 공식 분실 신고 및 재발급 신청 절차 이용 |

## Ⅴ. 위험과 대응

| 한계 | 대응 |
|---|---|
| 확인 목적보다 많은 개인정보를 요구·저장할 수 있음 | 요청 항목을 업무 목적과 연동하고 꼭 필요한 정보만 확인·보존 |
| 화면 캡처·복제물이 검증을 대체할 수 있음 | 공식 검증앱으로 진위를 확인하고 캡처 이미지를 신분증으로 취급하지 않음 |
| 단말 분실 뒤 신분증 이용이 이어질 우려 | 분실 신고 경로를 안내하고 신고 후 사용 상태 확인 |
| 단말 교체·3년 유효기간 만료로 확인이 중단될 수 있음 | 만료일과 재발급 절차를 사전 안내하고 대체 확인 경로 마련 |

## Ⅵ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 모바일 확인을 도입해도 최소정보 원칙·분실 대응이 각 업무 시스템에 반영되지 않을 수 있음 | 확인 API와 업무 화면에 목적별 요청 항목을 등록하고 동의·진위확인 결과를 남기며, 분실·교체 접수 경로를 사용자 지원 절차에 연결 |
