## 30초 인출

- 본질: **모바일 주민등록증** 은 스마트폰 단말의 보안 저장소(SE/TEE)에 암호화 탑재되어 실물 주민등록증과 동등한 법적 효력을 발휘하는 분산신원(DID) 기반 국가 모바일 신분증
- 메커니즘: IC 칩 접촉(NFC) 또는 주민센터 QR 코드로 본인 인증 후 신원 증명서(VC)를 단말에 발급받고, 검증자 요청 시 선택적 정보만 제출(VP)하여 진위 확인
- 통찰: 단말 분실 및 불필요한 개인정보 과다 노출 위험이 상존하므로 영지식 증명(ZKP) 기반 선택적 속성 검증과 중앙 폐기 목록(Revocation List) 즉시 동기화 체계 확립 필수

<details><summary>핵심 용어</summary>

- **모바일 주민등록증** : 주민등록법 제24조의2에 근거하여 개인 단말기에 암호화 탑재되는 실물 주민등록증과 동일한 효력의 디지털 신분증.
- **분산신원증명 (DID, Decentralized Identifier)** : 중앙 집중형 검증기관에 의존하지 않고 개인이 자신의 신원 정보를 직접 관리·통제하는 탈중앙화 신원 체계.
- **검증 가능한 자격증명 (VC, Verifiable Credential)** : 발행기관의 전자서명이 포함되어 변조 여부를 검증할 수 있는 표준 디지털 신원 정보.
- **검증 가능한 제출본 (VP, Verifiable Presentation)** : 보유자가 특정 검증 목적에 맞추어 VC 데이터 중 필요한 항목만을 선별·조합하여 생성한 증명 객체.
- **영지식 증명 (ZKP, Zero-Knowledge Proof)** : 자신의 비밀 정보를 전혀 노출하지 않으면서도 참임을 상대방에게 증명하는 암호학적 기법.
- **안전영역 (SE / TEE)** : 하드웨어 격리 기반의 물리적 암호화 영역(Secure Element) 및 신뢰 실행 환경(Trusted Execution Environment).

</details>

## 2~4교시 25점 답안

## Ⅰ. 모바일 주민등록증의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **모바일 주민등록증** 은 주민등록법에 근거하여 이동통신단말장치의 안전영역(SE/TEE)에 암호화 설치되는 실물 주민등록증과 동일한 법적 효력의 디지털 신분증 |
| 목적 | 공공·금융·일상생활 전반의 대면·비대면 디지털 신원 확인 단일화, 불필요한 개인정보 노출 방지 및 위·변조 방지 |

## Ⅱ. 모바일 주민등록증의 법적·기술적 특징

| 구분 | 주요 특징 | 상세 설명 및 기술적 사양 |
|---|---|---|
| **법적 효력** | 주민등록법 제24조의2 명시 | 실물 주민등록증과 동등한 효력 보장, 관공서·은행·편의점 등에서 완전한 대체 인정 |
| **자기주권 신원** | SSI(Self-Sovereign Identity) | 데이터 주권의 사용자 환원, 신원 정보의 중앙 서버 미저장 및 단말 분산 보관 |
| **보안 아키텍처** | SE/TEE 기반 하드웨어 격리 | 루팅·탈옥 방지, 단말 1인 1기기 원칙 및 생체인증(FIDO) 결합 기반의 다중 서명 |
| **프라이버시** | 선택적 속성 제출(Selective Disclosure) | 성인 여부, 주소 등 검증자가 요구하는 필수 속성만 선별 제공하여 과다 수집 원천 차단 |
| **유효기간 관리** | 3년 단위 갱신 체계 | 3년 주기 전자서명 키 만료 및 단말 교체 시 중앙 저장소와 연동한 즉시 폐기 처리 |

## Ⅲ. 모바일 주민등록증의 아키텍처 및 발급·검증 프로세스

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ [ 모바일 주민등록증 DID 기반 종단간(End-to-End) 아키텍처 ]                  │
└─────────────────────────────────────────────────────────────────────────────┘
  [ 주민등록 발급기관 (행안부/지자체) ] ──── 발급정보 공시 ───> [ DID 블록체인 / 저장소 ]
                 │ VC 발급                                             ▲
                 ▼                                                     │
   [ 이용자 단말 (안전영역: SE/TEE) ]                                  │ DID Document /
        - 개인키(Private Key) 분산 보관                                │ 전자서명 검증
        - VC 수납 및 VP 생성 엔진                                      │
                 │                                                     │
                 │ 1. 검증 요청(Nonce/요구속성)                        │
                 │ 2. 선택적 VP 제출 (영지식 증명 적용)                │
                 ▼                                                     │
        [ 검증자 (관공서 / 금융사 / 검증앱) ] ─────────────────────────┘
```

```text
[ 1. 발급 단계: IC 태깅 / QR 창구 ]
사용자 신청 ─> IC 주민등록증 휴대폰 NFC 태깅 ─> FIDO 생체인증 ─> 정부 발급서버 VC 발행 ─> 단말 안전영역 저장

[ 2. 검증 단계: 동적 QR / BLE 통신 ]
검증자 QR 제시 ─> 이용자 단말 스캔 ─> 최소 속성 선택(성인인증 등) ─> VP 서명 전송 ─> 진위 확인 완료
```

| 단계 | 수행 주체 | 처리 메커니즘 및 보안 통제 |
|---|---|---|
| **발급 신청** | 사용자 → 지자체/정부24 | IC 주민등록증 NFC 태깅(비밀번호 입력) 또는 읍·면·동 행정복지센터 방문 일회용 QR 발급 |
| **키 생성·등록** | 단말 TEE ↔ DID 서버 | 단말 내부 하드웨어 키스토어에서 암호키 쌍 생성, 공개키는 블록체인 DID Document에 등록 |
| **VC 발급** | 발급기관 → 단말 안전영역 | 행정안전부 인증서 기반 서명된 신원 자격증명(VC) 전송, 단말 보안영역 암호화 적재 |
| **VP 생성·제시** | 사용자 → 검증자 | 검증자가 전송한 임의 난수(Nonce)와 필수 속성만 조합하여 서명된 제출본(VP) 동적 생성 |
| **진위 검증** | 검증기관 → DID 레지스트리 | 블록체인 원장의 발행자 공개키로 서명 검증 및 폐기 목록(Revocation List) 대조 판정 |

## Ⅳ. 실물 주민등록증과 모바일 주민등록증 비교

| 비교 항목 | 실물 주민등록증 | 모바일 주민등록증 |
|---|---|---|
| **저장 매체** | 폴리카보네이트(PC) 수지 플라스틱 카드 | 스마트폰 하드웨어 보안영역 (SE / TEE) |
| **정보 노출 범위** | 성명, 사진, 주민번호, 주소 전체 노출 | 필요한 최소 항목만 선택적 노출 (선택적 제출) |
| **위·변조 식별** | 육안 확인, 홀로그램, 형광인쇄 확인 한계 | 비대칭 암호화 전자서명 및 블록체인 분산원장 검증 |
| **대면/비대면 지원** | 대면 중심 (비대면 시 사본 캡처 악용 취약) | 대면(동적 QR/BLE) 및 비대면(API 연계) 동시 지원 |
| **분실 시 조치** | 분실 신고 접수 전까지 도용 방지 불가 | 통신사 분실 신고 즉시 효력 정지, 원격 데이터 삭제 |
| **유효기간** | 영구 사용 (파손/재발급 전까지 유지) | 3년 주기 갱신 (보안 암호키 최신성 보장) |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 신분증 검증 시 화면 단순 캡처본 또는 미러링 앱을 활용한 위·변조 편법 통과 위험 | 동적 시각 보안 워터마크(움직이는 애니메이션), 일회용 동적 QR 코드(Time-based OTP 결합), 화면 캡처 방지 API(FLAG_SECURE) 강제 적용 |
| 단말기 도난·분실 시 비정상 접근 및 오프라인 단말에서의 신원 사칭 가능성 | 통신사 분실 신고 즉시 연동되는 실시간 폐기 목록(CRL/OCSP) 조회 및 단말 FIDO 생체인증 실패 시 잠금(Brute-Force 방어) 메커니즘 구축 |
| 검증자 측의 불필요한 전체 속성 일괄 요구로 인한 자기결정권 침해 | 검증자 앱의 요청 속성을 심사·승인하는 인가 체계 도입 및 영지식 증명(ZKP) 기반 특정 조건(만 19세 이상 여부 등) 불리언(Boolean) 검증 의무화 |

## Ⅵ. 제언

단말 분실 및 사칭 위협에 대응하기 위하여 FIDO2 생체인증과 영지식 증명을 결합하고 실시간 폐기 검증 게이트웨이를 구축하는 제로트러스트 기반 신원 거버넌스 확립.

```text
[ 검증 요청 발생 ]
        │
        ▼
[ 스마트폰 하드웨어 생체인증 (FIDO2 / TEE) ] ──(실패 시)──> [ 즉시 잠금 및 접근 차단 ]
        │
        ▼ (인증 성공)
[ 영지식 증명(ZKP) 엔진 가동 ]
  - 나이 계산: 생년월일 미노출 -> "19세 이상 = True" 증명 생성
        │
        ▼
[ 실시간 폐기 목록(CRL) 게이트웨이 조회 ] ──(분실/정지)─> [ 즉시 거래 무효화 ]
        │
        ▼ (정상 활성)
[ 최소 권한 신원 인증 통과 ]
```

| 구분 | 단순 화면 확인 방식 | 제언: ZKP 결합 동적 분산 신원 체계 |
|---|---|---|
| **검증 방식** | 검증자가 화면의 텍스트·사진 육안 판독 | 비대칭 암호키 기반 서명 검증 및 영지식 증명 판정 |
| **노출 정보** | 성명·주민번호·주소 등 전체 개인정보 노출 | 참/거짓 불리언 값 및 동적 일회용 토큰만 노출 |
| **통신 보안** | 오프라인 육안 확인으로 이력 관리 불가 | mTLS 기반 안전 채널 및 검증 이력 암호화 감사 추적 |
| **분실 대응** | 분실 사실 인지 지연 시 악용 무방비 | 분실 신고 시스템 즉각 연동을 통한 분초 단위 인증 차단 |
