## 30초 인출

- 본질: **개인정보 보호법 (PIPA)** 은 모든 공공·민간 영역에서 개인정보의 수집·이용·제공·파기 등 전 생애주기를 규율하고 정보주체의 사생활과 자기결정권을 수호하는 최상위 일반법률
- 메커니즘: 법정 6대 수집 근거와 최소 수집 원칙을 기반으로 열람·삭제·전송요구·자동화 결정 대응권을 보장하며, 침해 시 전체 매출액 기준 최대 10%의 과징금을 부과
- 통찰: 수집 시점의 형식적 체크박스 동의만으로는 AI 2차 가공 및 클라우드 연쇄 유출을 방어하기 어려우므로 프라이버시 중심 설계(PbD)와 데이터 계보(Lineage) 기반 자동 파기 체계 구축 필수

<details><summary>핵심 용어</summary>

- **개인정보 보호법 (PIPA)** : 대한민국 내 살아있는 개인에 관한 모든 정보의 적법 처리와 안전 관리를 강제하는 일반법.
- **최소 수집의 원칙** : 개인정보처리자는 목적에 필요한 최소한의 개인정보만을 수집해야 하며 필수 외 정보 미제공을 이유로 서비스 제공을 거부할 수 없는 원칙.
- **정보주체 5대 권리** : 열람 요구권, 정정·삭제 요구권, 처리정지 요구권, 전송요구권, 자동화된 결정에 대한 거부·설명요구권.
- **프라이버시 중심 설계 (PbD)** : 시스템 기획 및 개발 초기 단계부터 개인정보 보호 요소를 기본 설정(By Default)으로 내재화하는 공학적 방법론.
- **개인정보보호위원회 (PIPC)** : 국무총리 소속 중앙행정기관으로 개인정보 보호 정책 총괄, 분쟁조정 및 시정명령·과징금 부과 기구.

</details>

## 2~4교시 25점 답안

## Ⅰ. 개인정보 보호법의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **개인정보 보호법 (PIPA)** 은 개인정보의 유출·오남용을 방지하고 정보주체의 권익을 보장하기 위해 공공과 민간의 모든 개인정보 처리를 통일적으로 규율하는 국가 일반법 |
| 목적 | 개인의 존엄과 가치 수호, 사생활의 비밀 보장 및 데이터의 안전한 신뢰 기반 활용 촉진 |

## Ⅱ. 개인정보 보호법 6대 처리 원칙 및 법적 특징

| 6대 처리 원칙 | 법적 근거 및 의미 | 상세 특징 및 기술적 적용 기준 |
|---|---|---|
| **1. 처리 목적 명확화** | 제3조제1항 | 처리 목적을 명확히 하고 그 목적에 필요한 범위에서 최소한으로 적법·정당하게 수집 |
| **2. 최소 수집의 원칙** | 제16조제1항 | 목적 달성에 필요한 최소한의 정보만 수집, 입증 책임은 처리자에게 있으며 선택 항목 강요 금지 |
| **3. 목적 외 이용 제한** | 제18조 | 수집 목적 범위를 초과하여 이용하거나 제3자에게 제공 금지 (법정 예외 사유 철저 검토) |
| **4. 정확성·최신성 보장** | 제3조제3항 | 처리 목적에 부합하도록 개인정보의 정확성, 완전성, 최신성을 보장하고 오류 즉시 수정 |
| **5. 안전성 확보조치** | 제29조 | 분실·도난·유출 방지를 위한 관리적·기술적·물리적 보안 조치 강제 (암호화, 접근통제) |
| **6. 투명성 및 파기 의무** | 제3조제5항, 제21조 | 개인정보 처리방침 상시 공개, 보유기간 경과 및 목적 달성 시 복구 불가능한 방법으로 영구 파기 |

## Ⅲ. 개인정보 E2E 생애주기 관리 및 안전조치 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 개인정보 보호법 전 생애주기(Life-Cycle) 및 엔지니어링 통제 파이프라인 ]│
└────────────────────────────────────────────────────────────────────────┘

 [ 1. 수집·이용 단계 (Collect) ]
    ├── 법 제15조 적법 근거 확보 (동의, 계약 체결·이행, 법률상 의무)
    ├── 필수 / 선택 동의 분리 UI 및 14세 미만 법정대리인 동의 확인
    └── 네트워크 전송 암호화 (TLS 1.3 강제)
          │
          ▼
 [ 2. 저장·보유 단계 (Store) ]
    ├── 고유식별정보(주민/여권/운전면허), 비밀번호, 바이오정보 DB 암호화 (AES-256)
    ├── 비밀번호 일방향 솔트(Salt) 해시 암호화 (SHA-256 이상)
    └── DB 접근제어 솔루션 연동 및 접속기록 WORM 스토리지 1~2년 보관
          │
          ▼
 [ 3. 제공·활용 단계 (Utilize) ]
    ├── 제3자 제공 동의 및 위·수탁 계약 체결 (수탁사 교육·관리감독)
    ├── 정보주체 권리 행사 게이트 (열람, 정정, 삭제, 전송요구, 자동화 결정 대응)
    └── 가명정보 결합 특례 적용 (결합전문기관 승인 및 추가정보 분리 격리)
          │
          ▼
 [ 4. 파기 단계 (Destroy) ]
    ├── 보유기간 만료 또는 회원 탈퇴 시 지체 없이(5일 이내) 영구 삭제
    ├── 전자적 파일: DoD 5220 덮어쓰기 또는 DB 레코드 완전 Wipe Out
    └── 타 법령 보존 대상: 원천 DB에서 완전 분리하여 별도 격리 보관
```

| 생애주기 단계 | 주요 엔지니어링 통제 조치 | 핵심 감사 증적 |
|---|---|---|
| **수집 (Collection)** | 동의 획득 타임스탬프, 최소 수집 항목 유효성 검증 | 동의 로그, 개인정보 처리방침 |
| **보관 (Storage)** | 컬럼 레벨 암호화, 개인정보 취급자 계정 RBAC 통제 | 암호화 알고리즘 검증서, DB 권한대장 |
| **권리 보장 (Rights)** | 마이데이터 FAPI 전송, 30일 이내 권리 행사 처리 | 권리행사 접수·처리 대장 |
| **파기 (Destruction)** | 배치(Batch) 프로그램에 의한 자동 물리적 영구 파쇄 | 데이터 파기 증명서, 관리대장 |
| **유출 통제 (Breach)** | 유출 인지 시 72시간 이내 신고 및 피해자 통지 | 침해사고 긴급 대응 리포트 |

## Ⅳ. 국내 개인정보 보호법과 EU GDPR 비교

| 비교 항목 | 국내 개인정보 보호법 (PIPA) | 유럽연합 일반 개인정보보호법 (EU GDPR) |
|---|---|---|
| **법률의 성격** | 형벌 중심의 강력한 실정법 일반 규범 | 원칙 기반 거버넌스 및 행정 제재 중심 규제 |
| **과징금 상한** | 전체 매출액의 **3% (가중 시 최대 10%)** | 전 세계 연간 매출액의 **최대 4% 또는 2,000만 유로** |
| **형사 처벌** | 5년 이하 징역 등 취급자·대표자 징역형 다수 | 원칙적으로 형사 처벌 조항 없음 (과징금 중심) |
| **법정 책임자** | **CPO (개인정보보호책임자)** 지정 의무 | **DPO (Data Protection Officer)** 독립 지정 |
| **신기술 권리** | **개인정보 전송요구권, 자동화 결정 대응권** 완비 | 데이터 이동권(Portability), 프로파일링 거부권 |
| **적정성 평가** | EU로부터 적정성 결정(Adequacy Decision) 승인 | 글로벌 데이터 이전의 기준 프레임워크 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 클라우드 및 마이크로서비스(MSA) 확산으로 인해 백엔드 데이터베이스 간 개인정보 흐름 추적 불가 및 파기 누락 | eBPF 및 정적 코드 분석 기반의 '데이터 계보(Data Lineage) 자동 맵핑' 도구를 CI/CD 파이프라인에 구축 |
| LLM 사전 학습 데이터 내 무단 수집된 개인정보(PII)로 인한 생성물 내 개인정보 노출 및 망각권(삭제권) 침해 | 사전 학습 단계 PII 자동 마스킹 파이프라인과 RAG 기반 지식 분리 및 머신 언러닝(Machine Unlearning) 기법 적용 |

## Ⅵ. 제언

데이터 보호 컴플라이언스를 완벽히 준수하기 위해 시스템 기획 단계부터 프라이버시를 코드화하는 PbD(Privacy by Design) 기반 자동 거버넌스 아키텍처 구축 필요.

```text
[ 소프트웨어 아키텍처 기획/설계 ]
             │
             ▼
[ Privacy by Design (PbD) 자동화 파이프라인 ]
   ├── Step 1: PII 데이터 사전 자동 등록 및 컬럼별 보유기간 태깅
   ├── Step 2: 암호화 적용 여부(AES-256) 정적 코드 검사(SAST)
   └── Step 3: 보유기간 만료 시 DB 레코드 자동 삭제 트리거 생성
             │
             ▼
[ CPO 컴플라이언스 대시보드 ] ──(실시간 모니터링)──> [ 무중단 안전 서비스 배포 ]
```

| 구분 | 기존 수동 체크리스트 점검 | 제언: PbD 기반 코드화된 컴플라이언스 |
|---|---|---|
| **설계 단계** | 개발 완료 후 규제 부서에 사후 자문 | 기획 시점부터 코드 레벨 PII 스키마 제약 강제 |
| **파기 실행** | DB 관리자가 수기 SQL 실행 (휴먼에러) | 데이터 수명주기(TTL) 기반 자동 영구 파쇄 |
| **권리 대응** | 고객센터 수기 접수 후 개발자에게 쿼리 요청 | 사용자 셀프서비스 포털 통한 즉각 삭제·전송 |
| **증적 관리** | 감사 시점 서류 위조 위험 | 시스템 감사 로그 WORM 영구 보존 |
