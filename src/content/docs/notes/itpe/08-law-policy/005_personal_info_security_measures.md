## 30초 인출

- 본질: **개인정보의 안전성 확보조치 기준** 은 개인정보의 분실·도난·유출·위조·변조·훼손을 방지하기 위해 개인정보처리자가 의무적으로 이행해야 하는 법정 관리적·기술적·물리적 보호조치 기준
- 메커니즘: 내부관리계획을 기반으로 접근권한 최소화, 전송·저장 암호화, 접속기록 최소 1~2년 보관 및 월 1회 이상 점검, 취급자 단말 인터넷망 차단 통제를 다계층 적용
- 통찰: 형식적 규정 준수만으로는 내부자 권한 남용 및 지능형 지속 위협(APT) 방어에 한계가 있으므로 제로 트러스트(Zero Trust) 원칙과 AI 기반 사용자 행위 분석(UEBA) 체계 결합 필수

<details><summary>핵심 용어</summary>

- **안전성 확보조치 기준** : 개인정보 보호법 제29조 및 시행령 제30조에 따라 개인정보보호위원회가 제정·고시한 법정 보안 가이드라인.
- **내부관리계획** : CPO 지정, 전담 인력 배정, 정기 교육, 접근권한 관리 절차 등을 규정한 전사 개인정보 보호 실행 지침.
- **접속기록** : 개인정보처리시스템에 접속하여 수행한 계정, 접속일시, 접속지 정보, 수행 업무, 정보주체 식별정보 등의 로그 데이터.
- **망분리/인터넷망 차단** : 개인정보처리시스템에 직접 접속하거나 다운로드·파기 권한을 보유한 단말을 인터넷 공중망과 논리적·물리적으로 분리하는 통제.
- **UEBA (User and Entity Behavior Analytics)** : 사용자와 장치의 행동 패턴을 기계학습으로 학습하여 비정상 대량 다운로드 등 이상 징후를 탐지하는 기술.

</details>

## 2~4교시 예상문제 (25점)

> 개인정보 보호법 제29조에 따른 '개인정보의 안전성 확보조치 기준'의 관리적·기술적·물리적 통제 항목을 설명하고, 최근 망분리(인터넷망 차단) 제도 개선 내용과 대규모 개인정보 유출 방지를 위한 엔지니어링 통제 체계를 논하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개인정보 안전성 확보조치 기준의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **개인정보의 안전성 확보조치 기준** 은 개인정보처리자가 처리하는 개인정보의 안전한 관리를 위해 법령상 준수해야 할 최소한의 기술적·관리적·물리적 보안 조치 고시 |
| 목적 | 해킹, 내부자 유출 등 보안 사고 예방 및 정보주체의 권익과 사생활 비밀 보장 |

## Ⅱ. 안전성 확보조치 기준의 핵심 통제 체계 및 개정 특징

| 구분 | 주요 법정 통제 항목 | 기술적 상세 특징 및 엔지니어링 구현 요건 |
|---|---|---|
| **관리적 조치** | 내부관리계획 수립·시행 | CPO 역할 명시, 취급자 교육, 접근권한 부여·말소 절차 규정화 |
| | 정기적 보안 감사 | 연 1회 이상 내부 관리계획 이행 실태 자체 점검 및 미비점 개선 |
| **기술적 조치** | 접근권한 및 접근통제 | 업무별 최소 권한(RBAC), 2차 인증(MFA), 불법 접근 탐지(IPS/WAF) |
| | 개인정보 암호화 | 고유식별정보·비밀번호·바이오정보 저장 암호화, 네트워크 전송 암호화(TLS 1.3) |
| | 접속기록 보관 및 점검 | 접속기록 1년(5만 명 이상/민감정보는 2년) 보관, 월 1회 이상 이상징후 점검 |
| | 악성프로그램 방지 | 백신 소프트웨어 실시간 감시, 자동 업데이트 및 주기적 정밀 검사 |
| **물리적 조치** | 통제구역 설정 및 잠금장치 | 전산실·자료보관실 보호구역 지정, 출입통제 및 물리적 접근 기록 유지 |
| | 매체 보관 및 파기 | 외장 스토리지 잠금 보관, 불용 매체 물리적 파쇄 또는 디가우징(Degaussing) |
| **최근 개정 특징** | 인터넷망 차단 합리화 | 일률적 물리적 망분리에서 위험분석 기반 논리적 통제 및 클라우드 친화적 보안 전환 |

## Ⅲ. 엔드투엔드 개인정보 보안 통제 아키텍처 및 접속기록 관리

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 개인정보 안전성 확보조치 E2E 다계층 방어(Defense-in-Depth) 체계 ]   │
└────────────────────────────────────────────────────────────────────────┘

 [ 외부 비인가 네트워크 ]
            │ (불법 침입 차단: WAF, DDoS 방어, IPS)
            ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ [ DMZ 및 API 게이트웨이 ] ── TLS 1.3 암호화 통신, 토큰 기반 MFA 인증  │
 └──────────────────────────────────────────────────────────────────────┘
            │
            ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ [ 취급자 접속 통제 구역 ] ── 망분리/VDI 환경, 세션 타임아웃, DRM 적용 │
 └──────────────────────────────────────────────────────────────────────┘
            │ (DB 접근제어 및 쿼리 통제: 결재 승인, SQL 인젝션 차단)
            ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ [ 개인정보처리시스템 / DB ]                                         │
 │  ├── 저장 암호화: AES-256, ARIA (주민번호, 여권번호, 계좌번호 등)    │
 │  └── 비밀번호: SHA-256 이상 일방향 단방향 암호화 + Salt 필수        │
 └──────────────────────────────────────────────────────────────────────┘
            │
            ▼ (실시간 감사 로그 파이프라인)
 ┌──────────────────────────────────────────────────────────────────────┐
 │ [ WORM 접속기록 스토리지 ] ── 월 1회 AI 이상행위(대량 다운로드) 분석  │
 └──────────────────────────────────────────────────────────────────────┘
```

| 접속기록 항목 | 관리 세부 기준 | 위반 및 이상행위 판정 기준 |
|---|---|---|
| **계정 및 접속일시** | 취급자 고유 ID, 접속 시작 및 종료 타임스탬프 | 동일 ID 동시 다중 접속, 비인가 시간대(심야/휴일) 접속 |
| **접속지 정보** | 접속 단말의 공인/사설 IP 주소, MAC 주소 | 사전 등록되지 않은 외부 비인가 IP에서의 원격 접근 |
| **수행 업무** | 조회, 출력, 수정, 삭제, 다운로드 상세 내역 | 일일 통상 조회량의 300% 초과 대량 조회 및 엑셀 다운로드 |
| **정보주체 정보** | 식별 가능한 고유 ID, 고객 식별자 정보 | 특정 VIP 또는 유명인 개인정보에 대한 집중 열람 시도 |

## Ⅳ. 처리자 유형별 차등 적용 및 인터넷망 차단 기준 비교

| 비교 항목 | 대규모 처리자 (100만 명 이상) | 중소 규모 처리자 | 소상공인 등 소규모 처리자 |
|---|---|---|---|
| **내부관리계획** | 전사 필수 수립 및 CPO 전담 운영 | 필수 수립 (간소화 서식 허용) | 기본 항목 중심의 약식 계획 허용 |
| **접속기록 보관** | **2년 이상** 의무 보관 | 1년 이상 (5만 명 초과 시 2년) | 1년 이상 의무 보관 |
| **접속기록 점검** | **월 1회 이상** 정기 분석 점검 | 월 1회 이상 정기 점검 | 반기 1회 이상 간이 점검 |
| **인터넷망 차단** | **의무 적용** (위험분석 시 예외 가능) | 권고 (일부 민감정보 시 의무) | 자율 적용 (PC 백신 중심) |
| **취약점 점검** | 연 1회 이상 모의 침투 및 취약점 진단 | 연 1회 자체 또는 위탁 점검 | KISA 원격 보안점검 등 활용 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 접속기록 단순 누적 보관으로 인한 대량 유출 인시던트의 실시간 탐지 실패 및 사후 통보 지연 | SIEM 및 SOAR 연계 실시간 감사 로그 파이프라인 구축 및 비정상 대량 다운로드 즉시 세션 차단 |
| 레거시 온프레미스 중심의 망분리 규제로 인한 클라우드(SaaS) 기반 협업 도구 도입 저해 | 제로 트러스트(ZTNA) 보안 모델 도입 및 위험성 평가 기반 조건부 클라우드 접근 허용 제도 활용 |

## Ⅵ. 제언

클라우드 및 재택근무 환경으로의 변화에 맞춰 경계 기반 보안에서 제로 트러스트 보안 모델로 전환하고, UEBA 기반 개인정보 접근 실시간 모니터링 체계 구축 필요.

```text
[ 데이터 취급자 단말 ]
          │ (상호 인증 mTLS + 기기 컴플라이언스 검증)
          ▼
[ 제로 트러스트 정책 시행 지점 (PEP) ]
   ├── 사용자 ID, 기기 상태, 위치 기반 동적 인가
   └── 최소 권한(JIT: Just-In-Time) DB 접속 토큰 발급
          │
          ▼
[ AI 기반 UEBA 이상행위 분석 엔진 ]
   ├── 평소 업무 패턴과 다운로드 빈도 비교
   └── 이상치 감지 시 즉시 세션 강제 종료 및 CPO 알림
```

| 구분 | 기존 경계 기반 안전조치 | 제언: 제로 트러스트 & UEBA 지능형 조치 |
|---|---|---|
| **보안 경계** | 사내 네트워크 내부자는 전면 신뢰 | 모든 접속을 의심하고 지속 검증 (Never Trust, Always Verify) |
| **접근 제어** | 정적 IP 및 역할 기반 정적 권한 | 컨텍스트 기반 동적 최소 권한(Just-In-Time) 부여 |
| **로그 점검** | 월 1회 관리자 수기 사후 점검 | 스트리밍 엔진 기반 실시간 이상행위 자동 차단 |
| **인프라 환경** | 물리적 망분리 온프레미스 종속 | 하이브리드 클라우드 및 원격지 안전 접속 보장 |
