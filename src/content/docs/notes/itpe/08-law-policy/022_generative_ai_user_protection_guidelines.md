## 30초 인출

- 본질: **생성형 AI 서비스 이용자 보호 가이드라인** 은 생성형 AI 서비스의 급속한 보급에 따른 명예훼손, 딥페이크 및 정보 유출로부터 이용자를 보호하기 위해 마련된 방송통신위원회의 자율 실천 지침
- 메커니즘: 인간 통제·설명·안전·공정의 4대 기본원칙을 토대로 입력데이터 수집 통제, 서비스 결정 과정 고지, 피해 구제 등 6대 실행방식을 AI 서비스 라이프사이클에 체계화
- 통찰: 자율 규범의 한계로 인한 실효성 부족과 프롬프트 탈옥(Jailbreak)에 따른 유해 출력 위험이 상존하므로 오픈소스 LLM 가드레일 결합과 인공지능기본법상 법적 책임 연계 체계 구축 필수

<details><summary>핵심 용어</summary>

- **생성형 AI 서비스 이용자 보호 가이드라인** : 생성형 AI 생태계의 건전한 발전과 이용자 권익 증진을 위해 방통위가 제정한 4대 원칙·6대 실행방식 가이드라인.
- **인간 통제 (Human Control)** : AI의 자동화된 추론 결과에 사람이 최종적으로 개입하고 통제할 수 있는 권한과 장치를 보장하는 원칙.
- **입력데이터 관리** : 이용자가 프롬프트 창에 입력한 데이터가 모델 재학습에 무단 활용되지 않도록 선택권(Opt-out)을 제공하는 통제.
- **LLM 가드레일 (Guardrails)** : 프롬프트 입력과 모델 출력의 양방향에서 유해성, 개인정보, 탈옥 시도를 실시간 필터링하는 소프트웨어 안전 계층.
- **피해구제 핫라인** : 허위정보나 명예훼손 생성물로 피해를 입은 이용자가 즉각적인 삭제 및 차단을 요청할 수 있는 신속 권리구제 창구.

</details>

## 2~4교시 25점 답안

## Ⅰ. 생성형 AI 서비스 이용자 보호 가이드라인의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **생성형 AI 서비스 이용자 보호 가이드라인** 은 AI 개발사와 서비스 제공자가 이용자의 인격권, 안전 및 권익을 침해하지 않도록 준수해야 할 4대 기본원칙과 6대 실행방식 지침 |
| 목적 | 생성형 AI의 환각(Hallucination), 편향, 프라이버시 침해 등 역기능 최소화 및 이용자 신뢰 확보 |

## Ⅱ. 4대 기본원칙 및 제도적 특징

| 4대 기본원칙 | 핵심 의미 및 가치 | 상세 특징 및 기술적 요구사항 |
|---|---|---|
| **1. 존엄성·권리 및 인간 통제** | 인간 존엄성 및 기본권 존중 | AI가 인간을 지배하거나 조작하지 못하도록 **사람의 관리·감독(Human-in-the-Loop)** 보장 |
| **2. 알기 쉬운 설명** | 투명성 및 이해가능성 확보 | 비전문가 이용자도 이해할 수 있는 평이한 언어로 **AI 활용 사실 및 출력의 한계** 안내 |
| **3. 안전성 확보** | 잠재적 위해 사전 차단 | 적대적 프롬프트 공격(Jailbreak), 탈옥 방어 및 예기치 못한 유해 출력 방지 필터링 |
| **4. 공정성 보장** | 차별 및 불공정 배제 | 성별, 인종, 종교, 장애에 따른 **알고리즘 편향 차단** 및 데이터 다양성 확보 |
| **제도적 성격 특징** | **민관 협력 자율 규범** | 경직된 법적 처벌보다 사업자의 자발적 보호조치 유도, 인공지능기본법과 상호 보완 |

## Ⅲ. 6대 실행방식 및 서비스 라이프사이클 통제 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 생성형 AI 서비스 이용자 보호 6대 실행방식 E2E 아키텍처 ]             │
└────────────────────────────────────────────────────────────────────────┘

 [ 1. 입력 단계 (Input Phase) ]
    ├── [실행방식 ④ 입력데이터 관리]: 프롬프트 입력창 "학습 미활용(Opt-out)" 토글
    └── PII 마스킹 엔진 (주민번호, 전화번호, 이메일 실시간 검출 및 비식별화)
          │
          ▼
 [ 2. 추론 및 가드레일 계층 (Processing Phase) ]
    ├── [실행방식 ① 인격권 보호]: 비방, 명예훼손, 음란물 프롬프트 차단
    ├── [실행방식 ③ 다양성 존중]: 편향된 가중치 교정 (RLHF / DPO 정렬)
    └── 입력/출력 듀얼 가드레일 (NeMo Guardrails / Llama Guard)
          │
          ▼
 [ 3. 출력 및 고지 단계 (Output Phase) ]
    ├── [실행방식 ② 서비스 결정과정 알리기]: "본 답변은 AI가 생성한 것으로 오류 가능"
    └── 워터마크 주입 (C2PA 디지털 서명 메타데이터 및 육안 텍스트 표시)
          │
          ▼
 [ 4. 유통 및 사후 관리 단계 (Distribution & Feedback) ]
    ├── [실행방식 ⑥ 건전한 유통·배포]: 악의적 재배포 방지 모니터링
    └── [실행방식 ⑤ 문제 해결 책임]: 원클릭 오류 신고 버튼 및 피해구제 전담 창구
```

| 6대 실행방식 | 엔지니어링 구현 조치 | 핵심 검증 산출물 |
|---|---|---|
| **① 이용자 인격권 보호** | 딥페이크 합성 및 명예훼손 출력 차단 블랙리스트 운영 | 유해 프롬프트 차단율 (99% 이상) |
| **② 결정과정 알리기** | AI 모델 명칭, 학습 데이터 기준 시점, 신뢰도 UI 표시 | 서비스 투명성 고지문 |
| **③ 다양성 존중** | 인구통계학적 편향 완화를 위한 프롬프트 증강(Augmentation) | 공정성 평가지표(Disparate Impact) |
| **④ 입력데이터 관리** | 프롬프트 저장 주기 설정(30일 후 자동 폐기), 재학습 배제 | 데이터 보관 정책 및 Opt-out 로그 |
| **⑤ 문제 해결 책임** | 오작동 피해 접수 핫라인 및 신속 삭제·정정 처리 | 피해구제 접수 대장, 조치 확인서 |
| **⑥ 건전한 유통 배포** | 악의적 딥페이크 유포 방지를 위한 플랫폼 API 레이트 리밋 | API 이상 트래픽 감시 보고서 |

## Ⅳ. 개발사(AI Builder)와 서비스 제공자(AI Deployer)의 역할 비교

| 비교 항목 | 파운데이션 모델 개발사 (AI Builder) | 응용 서비스 제공자 (AI Deployer) |
|---|---|---|
| **생태계 위치** | LLM 및 기본 모델을 연구·학습·제작하는 기업 | 개발사의 모델을 API로 조달하여 대민 서비스 운영 |
| **인격권 보호** | 모델 프리트레이닝 데이터 정제 및 저작권 준수 | 서비스 프롬프트 필터링 및 악의적 입력 차단 |
| **입력데이터 관리** | API 호출 데이터를 기본 학습에서 배제하는 옵션 제공 | 이용자에게 학습 활용 여부 고지 및 동의 징구 |
| **설명 및 투명성** | 모델 카드(Model Card) 및 시스템 프롬프트 규격 공개 | 서비스 화면 내 알기 쉬운 한글 안내 문구 렌더링 |
| **사후 책임** | 모델 결함 패치 및 파인튜닝 가이드 제공 | 피해 발생 시 1차 접수, 피해자 보상 및 신속 삭제 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 다국어 우회 입력(Base64 인코딩, 외국어 은어)을 통한 프롬프트 탈옥 시 가드레일 필터링 무력화 | 멀티모달 임베딩 기반 의미론적 유사도(Semantic Similarity) 이상치 탐지 및 다계층 방어 모델 도입 |
| 비구속적 자율 가이드라인 특성상 영세 스타트업의 경우 개발 일정 압박으로 가이드라인 준수 기피 | 방통위·KISA 주관 '생성형 AI 신뢰성 마크' 인증제 도입 및 통신사업자 앱 마켓 등록 시 적합성 심사 연계 |

## Ⅵ. 제언

이용자 보호 가이드라인의 실효성을 담보하기 위해 LLM 추론 파이프라인 전·후단에 실시간 양방향 가드레일 아키텍처를 구축하고, 피해구제 원스톱 시스템 구축 필요.

```text
[ 사용자 프롬프트 입력 ]
          │
          ▼
[ 인바운드 가드레일 (Inbound Guard) ]
   ├── PII(개인식별정보) 자동 마스킹 및 학습 Opt-out 태깅
   └── 탈옥/적대적 프롬프트 인젝션 즉각 차단
          │
          ▼ (정제된 프롬프트)
[ 생성형 LLM 추론 엔진 ]
          │
          ▼ (원천 생성 텍스트)
[ 아웃바운드 가드레일 (Outbound Guard) ]
   ├── 환각(Hallucination) 지수 스코어링 (팩트체크 API 대조)
   ├── 혐오/비방 표현 차단 및 C2PA 워터마크 자동 주입
   └── 서비스 고지문("AI 생성 답변") 자동 결합
          │
          ▼
[ 안전한 최종 답변 사용자 전달 ]
```

| 구분 | 단순 LLM API 연동 | 제언: 양방향 가드레일 아키텍처 |
|---|---|---|
| **입력 통제** | 프롬프트 원문 그대로 전송 | PII 실시간 마스킹 및 학습 배제 강제 |
| **안전 필터링** | 모델 자체 안전성 의존 (탈옥 취약) | 전용 가드레일 모델의 2중 교차 검증 |
| **피해 구제** | 고객센터 이메일 수기 접수 | 원클릭 신고 즉시 문제 텍스트 격리 및 로깅 |
| **신뢰성** | 환각 및 가짜뉴스 무방비 노출 | 팩트체크 그라운딩을 통한 신뢰성 입증 |
