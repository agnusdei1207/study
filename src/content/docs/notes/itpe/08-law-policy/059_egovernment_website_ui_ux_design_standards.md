## 연관 키워드

- 전자정부 웹사이트 UI/UX 설계기준, 웹 접근성(KWCAG), 웹 호환성, 웹 개방성, 웹 접속성
- 코어 웹 바이탈(LCP, INP, CLS), robots.txt, 시맨틱 마크업, WAI-ARIA, 반응형 웹
- 사용자 테스트(UT), 자동 접근성 검사, 플러그인 배제, 품질 진단

## Ⅰ. 전자정부 웹사이트 UI/UX 설계기준의 개요

- 핵심 요약 : 공공 웹사이트의 화면 구조와 품질을 표준화하여 국민이 민원을 막힘없이 끝내도록 하는 공공 지침.
- 개념 : 행정기관과 공공기관의 웹사이트가 국민에게 편리한 탐색과 이용을 제공하도록 **화면 인터페이스**와 **웹사이트 품질**을 정한 공공 지침.
- 배경 및 필요성 : 문법 검사를 통과한 사이트도 모바일 화면이 깨지거나 스크린리더가 읽지 못하는 문제가 남는다. 이 간극의 비용은 이용자가 민원을 포기하는 형태로 나타나므로, 웹 접근성 기준(KWCAG 2.2)에 따른 사용자 테스트와 성능 지표의 상시 모니터링을 함께 두어야 한다.
- 주요 목적 : 디지털 서비스 이용 장벽 제거, 특정 플랫폼 종속 탈피, 장애인과 고령자의 정보 접근권 보장, 행정 정보의 신속한 전달.

## Ⅱ. 전자정부 웹사이트 UI/UX 설계기준의 특징 및 장점

- 핵심 요약 : 4대 품질 요소와 사용자 중심 설계 기준을 함께 적용해, 기능 존재 여부가 아니라 이용 완결 여부로 품질을 판단하는 방식.

1. 4대 품질 요소 : **웹 접근성**, **웹 호환성**, **웹 개방성**, **웹 접속성**으로 나눠 진단 → 품질 영역별 누락을 줄임.
2. 사용자 중심 설계 기준 : 핵심 민원을 전면에 배치하고 작업 단계를 줄임 → 민원 신청 이탈 감소.
3. 플러그인 배제 : 특정 브라우저 전용 플러그인을 없애고 표준 웹 기술로 구현 → 운영체제와 브라우저에 관계없이 이용 가능.
4. **코어 웹 바이탈** (Core Web Vitals) 지표 : 로딩, 반응, 시각 안정을 수치로 관리 → 저사양 기기에서도 이용 지연 최소화.

## Ⅲ. 전자정부 웹사이트 UI/UX 설계기준의 구조 (흐름)

- 핵심 요약 : 기획에서 운영까지 품질 검증을 단계마다 거치고, 정부가 외부에서 주기적으로 진단하는 구조.

```text
[ 1 기획·설계 ] 5대 UI/UX 기준 반영
      ↓
[ 2 개발·퍼블리싱 ] 웹 표준 마크업
      ↓
[ 3 품질 검증 ] 4대 품질 요소 점검
      ↓
[ 4 정부 품질 진단 ] 실태조사, 시정 권고
      ↓
[ 5 운영 ] 상시 모니터링, 깨진 링크 탐지
```

```text
[ 4대 품질 요소 ]
접근성 ─ 대체 텍스트, 키보드 이동
호환성 ─ 웹 표준 준수, 플러그인 배제
개방성 ─ 검색 허용, 사이트맵 제공
접속성 ─ 로딩·반응·안정 지표 관리
```

## Ⅳ. 형식 검사 중심 품질과 사용자 기반 품질의 비교

- 핵심 요약 : 문법과 외형 검사는 기계적으로 쉽지만 결함을 놓치며, 실사용 테스트와 결합해야 품질 기준이 실효를 가짐.

| 비교 축 | 형식 검사 중심 | 사용자 기반 품질 (본 설계기준) |
| --- | --- | --- |
| 검증 대상 | 문법과 마크업 적합성 | 실제 민원 수행 과정과 화면 동작 |
| 발견 가능한 결함 | 문법 오류, 명백한 누락 | 스크린리더 초점 유실, 모바일 레이아웃 깨짐 |
| 검증 주체 | 개발자와 자동 도구 | 자동 도구와 취약계층 이용자 |
| 한계 | 실제 이용 장벽을 놓침 | 테스트 비용과 시간이 큼 |

- 선택 기준 : 빌드 단계의 기초 점검은 자동 도구로, 공공 민원 화면의 최종 품질은 사용자 테스트로 확인하는 것이 합리적임.

## Ⅴ. 전자정부 웹사이트 UI/UX 설계기준의 한계와 방안

- 핵심 요약 : 동적 화면의 접근성 결함, 무분별한 웹 개방, 저사양 기기의 로딩 지연을 시맨틱 마크업, 경로별 개방 정책, 자원 최적화로 관리해야 함.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 문법 검사 위주 검증에 따른 동적 화면 결함 | SPA(Single-Page Application) 화면에서 초점 이동이 어긋나 스크린리더 사용이 막힘 | 시맨틱 마크업과 WAI-ARIA 속성을 적용하고, 시각장애 이용자가 참여하는 사용자 테스트 수행 | 접근성 결함 건수 |
| 무분별한 웹 개방에 따른 정보 노출과 서버 부하 | 게시판 개인정보 노출, 무단 수집 봇에 따른 서버 과부하 | 경로별로 robots.txt 정책을 세분화하여 비공개·민감 경로 차단 | 개인정보 노출 점검 건수 |
| 저사양 기기와 음영 지역의 로딩 지연 | 큰 이미지와 과다한 스크립트가 로딩을 지연시킴 | 차세대 이미지 포맷 전환, 스크립트 분할 로딩, CDN 캐싱으로 전송량 축소 | 최대 콘텐츠 표시 시간(LCP) 달성률 |

## Ⅵ. 전자정부 웹사이트 UI/UX 설계기준에 대한 기술사적 제언

- 핵심 요약 : 품질 점검을 배포 때마다 자동으로 실행하고, 접근성은 실사용자 검증으로 보완하는 상시 품질 거버넌스 구축.

1. 검증 시점의 전환 : 구축 완료 시점의 1회성 점검에서 벗어나, 배포 파이프라인에 품질 점검을 넣어 매 배포마다 확인하는 방향이 필요하다.
2. 접근성의 실사용 검증 : 자동 도구가 잡지 못하는 사용 불편은 취약계층 이용자 테스트로 확인하는 것을 기관의 정기 절차로 삼아야 한다.
3. 성능 예산의 관리 : 서버 증설에 의존하지 않고 페이지별 로딩 목표를 정해 프런트엔드 자원을 관리하는 기준을 두는 것이 적절하다.

## Ⅶ. 결론

- 핵심 요약 : 전자정부 웹사이트 설계기준은 문법 통과가 아니라 취약계층이 민원을 실제로 끝내는 품질을 보장하는 기준임.
- 시사점 : 설계기준의 성과는 점검표 통과율이 아니라 실사용 완결률과 접근성 결함의 감소로 평가해야 한다.
