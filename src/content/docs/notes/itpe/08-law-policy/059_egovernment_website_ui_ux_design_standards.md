## 30초 인출

- 본질: **전자정부 웹사이트 UI/UX 설계기준** 은 대국민 공공 웹사이트의 사용자 중심 정보 구조화와 서비스 탐색 편의성을 확보하고, 웹 접근성·호환성·개방성·접속성의 4대 웹 품질을 보장하기 위한 행정안전부 공공 표준 지침
- 메커니즘: 사용자 목적에 부합하는 7대 UI/UX 설계기준을 화면 구조에 반영하고, 「전자정부 웹사이트 품질관리 지침」에 따른 4대 품질 진단 지표를 개발 및 운영 단계에 걸쳐 체계적으로 검증
- 통찰: 단순 웹 표준 문법 유효성 검사 통과에 매몰되어 모바일 기기 반응형 레이아웃 깨짐 및 스크린리더 인지 불가 오류가 빈발하므로 KWCAG 2.2 표준 기반 사용자 테스트(UT)와 자동화된 접속성(Lighthouse) 모니터링 결합 필수

<details><summary>핵심 용어</summary>

- **UI/UX 설계기준** : 공공 웹사이트 이용자가 최소한의 탐색 단계로 원하는 행정 과업을 완결할 수 있도록 규정한 인터페이스 원칙.
- **웹 접근성 (Accessibility)** : 신체적·인지적 제약이 있는 장애인과 고령자도 비장애인과 동등하게 웹사이트의 정보를 인식하고 이용할 수 있도록 보장하는 품질.
- **웹 호환성 (Compatibility)** : 특정 OS(Windows, Mac)나 웹 브라우저(Chrome, Safari, Edge)에 종속되지 않고 동일한 기능과 화면을 제공하는 품질.
- **웹 개방성 (Openness)** : 주요 검색로봇(Google, Naver 등)이 공공 웹사이트의 공개 콘텐츠에 정상 접근하여 국민에게 검색 정보를 노출할 수 있도록 하는 품질.
- **웹 접속성 (Connectivity)** : 기존 '웹 최적화' 개념이 발전한 지표로, 브라우저 로딩 속도, 첫 바이트 시간(TTFB), 용량 경량화 및 링크 무결성을 관리하는 품질.
- **전자정부 웹사이트 품질관리 지침** : 행정안전부가 매년 공공 웹사이트의 운영 현황을 진단하고 개선을 권고하기 위해 고시한 법정 관리 기준.

## 2~4교시 25점 답안

## Ⅰ. 전자정부 웹사이트 UI/UX 설계기준의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **전자정부 웹사이트 UI/UX 설계기준** 은 국민이 행정기관 및 공공기관의 웹사이트를 편리하게 탐색·이용할 수 있도록 화면 인터페이스와 웹사이트 품질을 표준화한 공공 지침 |
| 목적 | 디지털 서비스 이용 장벽 제거, 특정 플랫폼 종속 탈피(Non-ActiveX), 장애인·고령자 정보 접근권 보장 및 신속한 행정 정보 전달 |

## Ⅱ. 전자정부 웹사이트 UI/UX 7대 설계기준 및 특징

| 구분 | 7대 설계기준 | 세부 특징 및 공학적 적용 지침 |
|---|---|---|
| **기준 1** | 필요 정보·기능 우선 제공 | 공급자 위주 조직도 나열을 배제하고, 국민이 가장 많이 찾는 핵심 민원 메뉴 전면 배치 |
| **기준 2** | 작업 시간과 단계 최소화 | 민원 신청 및 발급 퍼널을 단축하고 자동 완성 및 임시 저장 기능 지원 |
| **기준 3** | 직관적이고 일관된 구성 | 전 부처 공통 디자인 시스템 적용 및 메뉴 명칭의 일상 언어(Plain Language)화 |
| **기준 4** | 사용자 선호 방식 제공 | PC, 스마트폰, 태블릿 등 멀티 디바이스 반응형 웹(Responsive Web) 완벽 지원 |
| **기준 5** | 사용자의 실수 예방 | 입력 양식의 실시간 유효성 체크, 파괴적 행위(삭제 등) 수행 전 확인 모달 팝업 제공 |
| **기준 6** | 모든 유형의 사용자 포용 | 스크린리더 음성 출력 대체텍스트, 키보드 전용 내비게이션 등 무장애(Barrier-Free) 보장 |
| **기준 7** | 쉬운 정보·서비스 검색 | 지능형 자동완성 검색창 중앙 배치, 메타태그 최적화를 통한 외부 검색엔진 노출 보장 |

┌─────────────────────────────────────────────────────────────────────────────┐

└─────────────────────────────────────────────────────────────────────────────┘
  [ 공공 웹사이트 기획/설계 ] ── 7대 UI/UX 기준 반영 및 반응형 와이어프레임 작성
                 │
                 ▼
  [ 웹 개발 및 퍼블리싱 ] ──── W3C 표준 시맨틱 마크업(HTML5/CSS3) 코딩
                 │

  ┌──────────────────────────────────────────────────────────────┐

  │  2. [웹 호환성] ── Chrome, Edge, Safari, Firefox 크로스 브라우징 │
  │  3. [웹 개방성] ── robots.txt 설정 검증 및 검색 메타태그 점검 │
  │  4. [웹 접속성] ── 페이지 로딩 3초 이내, 번들 경량화, 링크 점검│
  └──────────────────────────────────────────────────────────────┘
                 │
                 ▼
  [ 행정안전부 공공 웹사이트 품질 진단 ] ── 정기 실태조사 및 시정 권고
                 │
                 ▼
  [ 운영 및 상시 모니터링 ] ── 깨진 링크(Dead Link) 자동 탐지 및 성능 튜닝

├─────────────────────────┼─────────────────────────┼─────────────────────────┤
│ 최대 콘텐츠풀 페인트    │ 첫 입력 지연 / 상호작용 │ 누적 레이아웃 이동      │

|---|---|---|
| **설계 단계** | 명도 대비, 폰트 크기, 터치 영역 크기 | 명도 대비 4.5:1 이상, 터치 타깃 44x44px 이상 |
| **개발 단계** | W3C HTML5/CSS3 문법 유효성(Validation) | W3C 유효성 검사 에러 제로(Zero Syntax Error) |
| **배포 전 단계** | 크로스 브라우징 렌더링 동등성 | 최소 3개 이상 주요 브라우저 엔진 화면 일치 |
| **운영 단계** | 코어 웹 바이탈(Core Web Vitals) 및 링크 | LCP 2.5초 미만, HTTP 404/500 링크 오류율 0% |

## Ⅳ. 4대 웹사이트 품질요소(접근성/호환성/개방성/접속성) 상세 비교

| 품질 요소 | 법적·기술적 핵심 개념 | 주요 진단 항목 |
|---|---|---|
| **1. 웹 접근성 (Accessibility)** | 장애인·고령자 등 정보 취약계층의 동등한 웹 이용 보장 | 이미지 대체텍스트(`alt`), 자막 제공, 키보드 초점 이동, 초점 가시성 |
| **2. 웹 호환성 (Compatibility)** | 플랫폼 및 브라우저 환경에 구애받지 않는 동등한 서비스 | W3C 웹 표준 준수, 비표준 플러그인(ActiveX/exe) 전면 제거, 멀티 OS 지원 |
| **3. 웹 개방성 (Openness)** | 공공 정보의 검색엔진 수집 허용 및 정보 유통성 확보 | robots.txt 검색 허용 설정, 사이트맵(sitemap.xml) 제공, 오픈그래프 태그 |
| **4. 웹 접속성 (Connectivity)** | 브라우저 상의 신속한 응답속도 및 안정적 연결 유지 | 첫 페이지 로딩 속도(3초 이내), 이미지 압축(WebP), 사장된 링크(Broken Link) 부재 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 정적 HTML 문법 검사기 위주의 검증으로 인해 동적 SPA(React, Vue) 환경에서 화면 렌더링 시 스크린리더 초점 유실 및 접근성 결함 잔존 | 시맨틱 마크업과 WAI-ARIA 속성을 엄격히 바인딩하고, 실제 전맹 시각장애인 당사자 중심의 사용성 테스팅(UT) 참여 의무화 |
| 무분별한 검색로봇 허용(웹 개방성)으로 인해 공공 게시판 내 개인정보 노출 및 해외 AI 크롤러의 무단 스크래핑으로 인한 서버 과부하 | robots.txt 정책을 세분화하여 비공개·민감 경로를 차단하고, OpenSearch 표준 API 기반의 통제된 검색엔진 색인 메커니즘 구축 |
| 모바일 통신 음영지역 또는 저사양 단말 접속 시 고해상도 이미지와 과다한 JS 라이브러리로 인한 접속성(로딩 지연) 저하 | 차세대 이미지 포맷(WebP/AVIF) 변환, JS 코드 스플리팅(Code Splitting) 및 CDN 에지 캐싱 파이프라인을 통한 페이로드 최소화 |

## Ⅵ. 제언

공공 디지털 서비스의 품질을 상시 보장하기 위해 빌드 파이프라인에 웹 품질 4대 요소 자동화 테스트를 통합하고 코어 웹 바이탈을 실시간 관제하는 DevSecOps 거버넌스 수립.

```text
[ 프런트엔드 소스코드 커밋 ]
                 │
                 ▼
[ CI/CD 빌드 파이프라인 (자동 품질 게이트) ]
    ├── Step 1: W3C HTML 유효성 린터 (문법 오류 차단)
    ├── Step 2: axe-core 웹 접근성 자동 검사 (KWCAG 준수)
    ├── Step 3: Google Lighthouse CI (접속성/성능 점수 90점 이상)
    └── Step 4: 무효 링크(Dead Link) 자동 크롤러 검사
                 │
                 ▼ (전체 테스트 통과 시에만 프로덕션 배포)
[ 글로벌 CDN 에지 배포 및 RUM(실제 사용자 모니터링) 성능 관제 ]
```

| 구분 | 연 1회 사후 품질 진단 | 제언: CI/CD 통합 상시 웹 품질관리 |
|---|---|---|
| **검증 주기** | 시스템 구축 완료 후 1회성 | 코드 커밋 및 배포 시마다 자동 검증 |
| **접근성 통제** | 서면 체크리스트 작성 | axe-core + 장애인 UT 실사용자 교차 검증 |
| **성능 최적화** | 서버 하드웨어 증설 의존 | 프런트엔드 리소스 압축 및 CDN 에지 캐싱 |
| **링크 관리** | 민원 제기 후 수동 링크 수정 | 404 에러 자동 감지 및 실시간 리다이렉션 |
