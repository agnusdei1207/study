## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **전자정부 웹사이트 UI·UX 설계기준**은 이용자 요구와 과업에 맞춰 공공 웹사이트의 정보·기능을 설계하는 기준 |
| 목적 | 이용자가 필요한 서비스를 찾고 과업을 수행하도록 돕는 것 |

### Ⅱ. 7개 설계기준과 품질요소

2019년 전자정부 웹사이트 UI·UX 가이드라인의 7개 기준은 사용자에게 필요한 정보·기능을 제공하고, 과업 시간을 줄이며, 직관성·일관성, 이용방식의 유연성, 오류 예방, 포용성, 정보 탐색을 지원한다.

| UI·UX 설계기준 | 핵심 질문 |
|---|---|
| 필요한 정보와 기능 제공 | 사용자의 목적에 맞는 내용과 기능인가? |
| 작업 시간·단계 최소화 | 과업을 불필요하게 오래 하거나 반복하지 않는가? |
| 직관성과 일관성 | 화면과 조작 방식이 이해하기 쉽고 일관적인가? |
| 이용방식의 유연성 | 사용자가 환경과 선호에 맞춰 이용할 수 있는가? |
| 실수 예방 | 오류가 나기 전에 예방하고 복구를 돕는가? |
| 모든 사용자를 고려 | 장애와 이용환경 차이가 있어도 서비스를 쓸 수 있는가? |
| 정보·서비스 찾기 | 원하는 정보와 기능을 쉽게 발견할 수 있는가? |

품질 측면에서는 접근성·호환성·개방성·최적화를 살핀다. 현행 「전자정부 웹사이트 품질관리 지침」은 네 번째 원칙을 ‘접속성’으로 표현한다.

| 웹 품질요소 | 핵심 |
|---|---|
| 접근성 | 누구나 정보·기능을 이용할 수 있게 한다. |
| 호환성 | 브라우저·기기별로 동등하게 동작하게 한다. |
| 개방성 | 공개 정보를 검색엔진에서 찾을 수 있게 한다. |
| 최적화(현행 접속성) | 응답시간·속도·용량·링크 상태를 관리한다. |

**제언:** 사용자 과업 점검과 네 가지 웹 품질 진단을 함께 수행한다.

## 2~4교시 25점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **전자정부 웹사이트 UI·UX 설계기준**은 이용자 요구와 과업에 맞춰 공공 웹사이트의 정보·기능을 설계하는 기준 |
| 목적 | 이용자가 필요한 서비스를 찾고 과업을 수행하도록 돕는 것 |

**정의:** 전자정부 UI·UX 설계기준은 사용자의 목적과 과업에 맞게 공공 웹사이트를 설계하도록 돕는 기준이다.

**목적:** 이용환경이나 신체·인지 조건에 관계없이 국민이 정보를 찾고 행정서비스를 이용할 수 있게 한다.

2019년 가이드라인은 7개 설계기준과 사용자경험 진단 자료를 제시했다. 같은 해의 웹사이트 자가진단지표는 접근성·호환성·개방성·최적화를 품질 항목으로 다뤘다.

| 구분 | 질문하는 내용 |
|---|---|
| UI·UX 설계기준 | 이용자가 무엇을 하려는지, 화면과 기능이 그 과업을 돕는지 |
| 웹사이트 품질요소 | 이용자가 접근·호환·검색·응답 품질을 확보했는지 |

### Ⅱ. UI·UX 7개 설계기준

| 기준 | 핵심 설계 방향 |
|---|---|
| 사용자에게 필요한 정보와 기능 제공 | 사용자 조사와 요구를 바탕으로 목적에 맞는 콘텐츠·기능을 정한다. |
| 작업 시간과 단계 최소화 | 자주 하는 과업을 중심으로 절차를 줄이고 완료 가능성을 확인한다. |
| 직관적이고 일관성 있게 구성 | 익숙한 용어·조작 방식을 쓰고 화면 간 표현을 통일한다. |
| 사용자가 원하는 방식으로 이용 | 이용환경과 과업 특성을 고려해 선택 가능한 경로를 제공한다. |
| 사용자의 실수 예방 | 오류가 생기기 쉬운 단계에서 안내하고 입력·취소·복구를 돕는다. |
| 모든 유형의 사용자가 이용 | 장애·연령·기기 차이를 고려해 정보와 기능을 제공한다. |
| 정보와 서비스를 쉽게 찾게 함 | 메뉴·검색·분류를 사용자의 탐색 목적에 맞춘다. |

이 기준은 화면 장식 목록이 아니라 사용자의 과업을 설계·점검하기 위한 질문이다. 실제 적용은 핵심 이용자와 과업을 확인한 뒤 각 화면과 절차에 반영한다.

### Ⅲ. 네 가지 웹사이트 품질요소와 현행 용어

| 품질요소 | 의미·점검 초점 | 현행 지침 |
|---|---|---|
| 웹 접근성 | 다양한 신체·인지 조건의 사용자가 정보와 기능을 이용할 수 있게 한다. | 현행 품질관리 지침에서도 같은 원칙을 둔다. |
| 웹 호환성 | 웹 표준을 사용해 여러 브라우저·기기에서 동등한 서비스를 제공한다. | 현행 지침에서도 웹 표준과 브라우저·모바일 기기의 동등한 서비스 제공을 요구한다. |
| 웹 개방성 | 검색엔진을 통해 공개 정보를 발견할 수 있게 한다. | 2025년 개정은 검색로봇 접근의 완전 허용에서 일부 차단 가능으로 기준을 조정했다. |
| 웹 최적화 | 브라우저에 표시되는 응답시간·속도·용량·링크 상태를 적절히 관리한다. | 현행 지침은 이 품질 원칙을 ‘접속성’으로 표현한다. |

2019년 가이드의 ‘웹 최적화’는 현행 지침의 ‘접속성’으로 이어진다. 2025년 개정에 따라 공개 정보의 검색 가능성은 보장하되, 시스템 부하나 크롤링 악용을 막기 위한 일부 제한도 정책에 맞게 설정할 수 있다. 2019년 전자정부 웹사이트 UI·UX 가이드라인은 2024년 디지털 정부서비스 UI/UX 가이드라인으로 대체됐으므로, 실무의 기술 기준은 현행 지침과 가이드를 확인한다.

### Ⅳ. 품질관리 절차

```text
[웹사이트 품질관리 계획 수립]
            | 진단 범위·일정 설정
            v
[운영 웹사이트 품질진단]
            | 미흡 항목 확인
            v
[개선 조치·결과 통보]
            | 결과를 다음 계획에 반영
            v
[다음 품질관리 계획]
```

「전자정부 웹사이트 품질관리 지침」은 기관이 품질관리 계획을 세우고 웹사이트를 진단·개선하도록 한다. 행정안전부는 진단 결과에 따른 개선이나 통합·폐기를 권고할 수 있고, 기관은 필요한 조치와 결과를 통보한다. 구체적인 기술 진단항목은 현행 지침과 관련 가이드에서 확인한다.

### Ⅴ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 개편 때 한 번만 점검하면 신규 화면·기능에서 접근성·호환성 결함이 다시 생길 수 있음 | 사용자 과업 기반 검토와 현행 품질진단을 기획·개발·운영 단계에 연계하고, 결함과 조치 결과를 추적한다. |
| 공개 정보와 내부·민감 정보가 같은 크롤링 정책에 묶일 수 있음 | 정보 공개 범위를 구분해 검색 허용·차단을 설정하고, 검색 결과와 이용자 접근을 확인한다. |
