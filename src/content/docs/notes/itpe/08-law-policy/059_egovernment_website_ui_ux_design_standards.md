## Ⅰ. 전자정부 웹사이트 UI/UX 설계기준의 개요

- **개념** : 국민이 행정기관 및 공공기관의 웹사이트를 편리하게 탐색·이용할 수 있도록 화면 인터페이스와 웹사이트 품질을 표준화한 공공 지침.
- **제정 배경 및 필요성** : 단순 웹 표준 문법 유효성 검사 통과에 매몰되어 모바일 기기 반응형 레이아웃 깨짐 및 스크린리더 인지 불가 오류가 빈발하므로 KWCAG 2.2 표준 기반 사용자 테스트(UT)와 자동화된 접속성(Lighthouse) 모니터링 결합 필수.
- **핵심 목적** : 디지털 서비스 이용 장벽 제거, 특정 플랫폼 종속 탈피(Non-ActiveX), 장애인·고령자 정보 접근권 보장 및 신속한 행정 정보 전달.

## Ⅱ. 전자정부 웹사이트 UI/UX 설계기준의 법제도 체계 및 핵심 메커니즘

**전자정부 웹사이트 UI/UX 설계기준**은 사용자 목적에 부합하는 7대 UI/UX 설계기준을 화면 구조에 반영하고, 「전자정부 웹사이트 품질관리 지침」에 따른 4대 품질 진단 지표를 개발 및 운영 단계에 걸쳐 체계적으로 검증 과정을 거쳐 체계적인 법제도적 통제와 기술적 신뢰성을 확보함.

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ [ 전자정부 웹사이트 4대 품질 진단 및 지속적 최적화 파이프라인 ]             │
└─────────────────────────────────────────────────────────────────────────────┘
  [ 공공 웹사이트 기획/설계 ] ── 7대 UI/UX 기준 반영 및 반응형 와이어프레임 작성
                 │
                 ▼
  [ 웹 개발 및 퍼블리싱 ] ──── W3C 표준 시맨틱 마크업(HTML5/CSS3) 코딩
                 │
                 ▼
  ┌──────────────────────────────────────────────────────────────┐
  │ [ 4대 웹사이트 품질 요소 검증 게이트 ]                       │
  │  1. [웹 접근성] ── KWCAG 2.2 지침 검사항목 충족    │
  │  2. [웹 호환성] ── Chrome, Edge, Safari, Firefox 크로스 브라우징 │
  │  3. [웹 개방성] ── robots.txt 설정 검증 및 검색 메타태그 점검 │
  │  4. [웹 접속성] ── 페이지 로딩 3초 이내, 번들 경량화, 링크 점검│
  └──────────────────────────────────────────────────────────────┘
                 │
                 ▼
  [ 행정안전부 공공 웹사이트 품질 진단 ] ── 정기 실태조사 및 시정 권고
                 │
                 ▼
  [ 운영 및 상시 모니터링 ] ── 깨진 링크(Dead Link) 자동 탐지 및 성능 튜닝

[ 웹 접속성(Performance) 핵심 측정 지표 ]
┌─────────────────────────┬─────────────────────────┬─────────────────────────┐
│       LCP (로딩 속도)   │     FID/INP (반응성)    │      CLS (시각적 안정)  │
├─────────────────────────┼─────────────────────────┼─────────────────────────┤
│ 최대 콘텐츠풀 페인트    │ 첫 입력 지연 / 상호작용 │ 누적 레이아웃 이동      │
│ 2.5초 이하 권장         │ 100ms / 200ms 이하 권장 │ 0.1 이하 권장           │
└─────────────────────────┴─────────────────────────┴─────────────────────────┘
```

- **기준 1** : 필요 정보·기능 우선 제공 - 공급자 위주 조직도 나열을 배제하고, 국민이 가장 많이 찾는 핵심 민원 메뉴 전면 배치.
- **기준 2** : 작업 시간과 단계 최소화 - 민원 신청 및 발급 퍼널을 단축하고 자동 완성 및 임시 저장 기능 지원.
- **기준 3** : 직관적이고 일관된 구성 - 전 부처 공통 디자인 시스템 적용 및 메뉴 명칭의 일상 언어(Plain Language)화.
- **기준 4** : 사용자 선호 방식 제공 - PC, 스마트폰, 태블릿 등 멀티 디바이스 반응형 웹(Responsive Web) 완벽 지원.
- **기준 5** : 사용자의 실수 예방 - 입력 양식의 실시간 유효성 체크, 파괴적 행위(삭제 등) 수행 전 확인 모달 팝업 제공.

## Ⅲ. 전자정부 웹사이트 UI/UX 설계기준의 세부 규정 및 국내외 제도 비교 분석

| 품질 요소 | 법적·기술적 핵심 개념 | 주요 진단 항목 |
|---|---|---|
| **1. 웹 접근성 (Accessibility)** | 장애인·고령자 등 정보 취약계층의 동등한 웹 이용 보장 | 이미지 대체텍스트(`alt`), 자막 제공, 키보드 초점 이동, 초점 가시성 |
| **2. 웹 호환성 (Compatibility)** | 플랫폼 및 브라우저 환경에 구애받지 않는 동등한 서비스 | W3C 웹 표준 준수, 비표준 플러그인(ActiveX/exe) 전면 제거, 멀티 OS 지원 |
| **3. 웹 개방성 (Openness)** | 공공 정보의 검색엔진 수집 허용 및 정보 유통성 확보 | robots.txt 검색 허용 설정, 사이트맵(sitemap.xml) 제공, 오픈그래프 태그 |

- **제도적 시사점** : 전자정부 웹사이트 UI/UX 설계기준은 상기 비교 지표를 바탕으로 법적 의무 준수와 비즈니스 연속성 간의 균형을 확보하고, 규제 환경 변화에 선제적으로 대응할 수 있는 아키텍처 및 거버넌스 체계를 확립해야 함.

## Ⅳ. 전자정부 웹사이트 UI/UX 설계기준의 주요 한계점 및 해결 방안

- **정적 문법 검사 위주 검증으로 동적 SPA 환경 초점 유실 결함 잔존** :
  - **한계점** : 정적 HTML 문법 검사기 위주의 검증으로 인해 동적 SPA(React, Vue) 환경에서 화면 렌더링 시 스크린리더 초점 유실 및 접근성 결함 잔존.
  - **해결 방안** : 시맨틱 마크업과 WAI-ARIA 속성을 엄격히 바인딩하고, 실제 전맹 시각장애인 당사자 중심의 사용성 테스팅(UT) 참여 의무화.
- **무분별한 웹 개방 시 게시판 내 개인정보 유출 및 AI 크롤러 과부하** :
  - **한계점** : 무분별한 검색로봇 허용(웹 개방성)으로 인해 공공 게시판 내 개인정보 노출 및 해외 AI 크롤러의 무단 스크래핑으로 인한 서버 과부하.
  - **해결 방안** : robots.txt 정책을 세분화하여 비공개·민감 경로를 차단하고, OpenSearch 표준 API 기반의 통제된 검색엔진 색인 메커니즘 구축.
- **모바일 저사양 단말 접속 시 무거운 JS 라이브러리로 인한 접속성 저하** :
  - **한계점** : 모바일 통신 음영지역 또는 저사양 단말 접속 시 고해상도 이미지와 과다한 JS 라이브러리로 인한 접속성(로딩 지연) 저하.
  - **해결 방안** : 차세대 이미지 포맷(WebP/AVIF) 변환, JS 코드 스플리팅(Code Splitting) 및 CDN 에지 캐싱 파이프라인을 통한 페이로드 최소화.

## Ⅴ. 전자정부 웹사이트 UI/UX 설계기준 정착 및 실효성 확보를 위한 기술사적 제언

공공 디지털 서비스의 품질을 상시 보장하기 위해 빌드 파이프라인에 웹 품질 4대 요소 자동화 테스트를 통합하고 코어 웹 바이탈을 실시간 관제하는 DevSecOps 거버넌스 수립.

- **검증 주기 관점의 고도화 및 실무 전환** : 시스템 구축 완료 후 1회성의 한계와 비효율을 탈피하고, 코드 커밋 및 배포 시마다 자동 검증을 체계적으로 도입·적용하여 실무적 신뢰성과 거버넌스 실효성을 극대화해야 함.
- **접근성 통제 관점의 고도화 및 실무 전환** : 서면 체크리스트 작성의 한계와 비효율을 탈피하고, axe-core + 장애인 UT 실사용자 교차 검증을 체계적으로 도입·적용하여 실무적 신뢰성과 거버넌스 실효성을 극대화해야 함.
- **성능 최적화 관점의 고도화 및 실무 전환** : 서버 하드웨어 증설 의존의 한계와 비효율을 탈피하고, 프런트엔드 리소스 압축 및 CDN 에지 캐싱을 체계적으로 도입·적용하여 실무적 신뢰성과 거버넌스 실효성을 극대화해야 함.
