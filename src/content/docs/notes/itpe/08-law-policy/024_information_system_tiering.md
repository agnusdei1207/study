## Ⅰ. 정보시스템 등급제의 개요

- **개념** : 공공 정보시스템의 대민 파급도, 행정 중요도, 연계 복잡성을 종합 평가하여 A1부터 A4까지 등급을 부여하고 차등적 안정성을 확보하는 제도.
- **제정 배경 및 필요성** : 주민등록, 정부24 등 국가 행정망의 대규모 마비 사고로 인해 국가적 혼란이 초래됨에 따라, 행정·공공기관의 모든 정보시스템을 파급도와 중요도에 따라 4단계(A1~A4)로 재분류하고 차등화된 복구성·가용성 기준을 강제하기 위해 개편됨.
- **핵심 목적** : 한정된 예산·인력의 효율적 집중, 행정망 마비 방지 및 국민 체감 관점의 무중단 디지털 정부 실현.

## Ⅱ. 정보시스템 등급제의 법제도 체계 및 핵심 메커니즘

정보시스템 등급제은(는) 기관 자체 분류 및 행정안전부 등급심의위원회를 통해 등급을 확정하고, 등급별로 이중화 아키텍처, 재해복구(DR), 정기 예방점검 및 장애 즉시 보고 의무를 부여 과정을 거쳐 상호 연동 및 단계별 법적·기술적 통제를 수행함.

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 정보시스템 등급 산정·심의 및 장애 관리 E2E 라이프사이클 ]           │
└────────────────────────────────────────────────────────────────────────┘

 [ 소관 행정·공공기관 ]
    │ ① 시스템별 영향도 자체 진단 (별표 1 평가 매트릭스 대조)
    ▼
 [ 행정안전부 등급심의위원회 ]
    │ ② 적정성 심의 및 A1~A4 최종 등급 확정 (신규 시스템 6개월 내 제출)
    ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ [ 등급별 기술적 인프라 및 아키텍처 구현 단계 ]                       │
 │  ├── A1 등급: 멀티 리전 액티브-액티브 DR 센터, 완전 이중화           │
 │  ├── A2 등급: 액티브-스탠바이 DR 및 자동 페일오버(Failover)          │
 │  └── A3/A4 등급: 클라우드 오토스케일링 및 오프사이트 백업            │
 └──────────────────────────────────────────────────────────────────────┘
    │
    ▼ (평시 운영 및 장애 발생 시)
 ┌──────────────────────────────────────────────────────────────────────┐
 │ [ 장애 관제 및 긴급 대응 단계 ]                                      │
 │  ├── A1~A3 등급 장애 즉시 ──> [ 행안부 디지털안전상황실 10분 내 통보 ]│
 │  └── 긴급 복구 매뉴얼 가동 ──> 등급별 목표 RTO 준수 복구 완료        │
 └──────────────────────────────────────────────────────────────────────┘
    │
    ▼
 [ 사후 재발방지 및 연간 재평가 ] ── 연 1회 안정성 자체 점검 결과 등록
```

- **A1 (국가 핵심)** : 국가 안보, 대규모 금융·신분 증명 (정부24, 주민등록, 모바일 신분증) - **초고가용성 보장** : 실시간 이중화(Active-Active), RTO 1시간 이내, 상시 관제
- **A2 (대국민 필수)** : 국민 다수가 일상적으로 이용하는 포털 (홈택스, 우체국, 고용보험) - **고신뢰 복구성** : 핫스탠바이(Hot-Standby), RTO 2시간 이내, 피크 트래픽 분산
- **A3 (행정 중요)** : 공무원 행정 처리 및 타 시스템 연계 (온-나라 결재, 공공 조달) - **업무 복원력** : 웜스탠바이(Warm-Standby), RTO 4시간 이내, 일 백업 보증
- **A4 (일반 보조)** : 단순 기관 홍보 웹, 통계 조회 포털 - **기본 관리** : 콜드스탠바이(Cold-Standby), 정기 백업 및 장애 시 수동 복구

## Ⅲ. 정보시스템 등급제의 세부 규정 및 국내외 제도 비교 분석

| 비교 항목 | 기존 5단계 등급제 (구 체계) | 개편 A1~A4 등급제 (현행 체계) |
|---|---|---|
| **등급 체계** | 1등급 ~ 5등급 (5단계) | **A1 ~ A4 (4단계 간소화·명확화)** |
| **핵심 평가 지표** | 기관 규모, 서버 하드웨어 대수, 접속자 수 | **국민 생활 파급도, 행정 마비 위험, 서비스 대체성** |
| **저평가 왜곡** | 이용자는 적으나 마비 시 국가 대란 시스템 저평가 | 소규모 시스템이라도 중요성 높으면 **A1 전격 상향** |
| **장애 통보 의무** | 각 기관 자율적 또는 지연 보고 | **A1~A3 장애 시 디지털안전상황실 즉시 보고 강제** |
| **관리 요건 연계** | 권고 수준의 재해복구 가이드 | **등급별 SLA 및 인프라 이중화 의무 명문화** |
| **심의 기구** | 기관별 자체 판단 중심 | **행정안전부 중앙 등급심의위원회 최종 통제** |

- **제도적 정합성 및 대응 방향** : 정보시스템 등급제은(는) 상기 비교 지표를 바탕으로 법적 규제 준수(Compliance) 요건과 엔터프라이즈 운영 효율성을 균형 있게 확보하고, 선제적인 관리체계를 수립해야 함.

## Ⅳ. 정보시스템 등급제의 주요 한계점 및 해결 방안

- **A1·A2 등급 상향에 따른 재해복구(DR) 센터 구축 및 이중화 예산 확보 난항** :
  - **한계점** : A1·A2 등급 상향에 따라 요구되는 DR 센터 구축 및 전산망 이중화 예산 확보 난항.
  - **해결 방안** : 행정안전부 차원의 '공공 클라우드 DR 통합 센터'를 구축하여 다수 기관이 공동 활용하는 멀티 테넌트 DR 인프라 제공.
- **기관 간 연계 API 장애 시 단일 시스템 장애가 전이되는 연쇄 부도(Cascading Failure)** :
  - **한계점** : 기관 간 연계 API 장애 발생 시 단일 시스템 장애가 타 기관 시스템으로 전이되는 연쇄 부도(Cascading Failure) 현상.
  - **해결 방안** : 마이크로서비스(MSA) 아키텍처 기반 서킷 브레이커(Circuit Breaker) 패턴 의무화 및 느슨한 결합(Loose Coupling) 표준화.

## Ⅴ. 정보시스템 등급제 정착 및 실효성 확보를 위한 기술사적 제언

- **eBPF 기반 실시간 API 트래픽 자동 토폴로지 매핑을 통한 복합 의존성 가시화** : 기존의 문서화된 시스템 아키텍처 다이어그램 한계를 극복하기 위해 eBPF 기반 실시간 API 트래픽 자동 토폴로지 매핑 체계를 선제적으로 확립하여 엔터프라이즈 거버넌스를 완성해야 함.
- **마이크로서비스(MSA) 아키텍처 기반 서킷 브레이커(Circuit Breaker) 패턴 의무화** : 기존의 연계 기관 연쇄 다운 발생 한계를 극복하기 위해 서킷 브레이커를 통한 장애 도메인 자동 차단 체계를 선제적으로 확립하여 엔터프라이즈 거버넌스를 완성해야 함.
- **행정안전부 차원의 범정부 공공 클라우드 DR 통합 센터 구축 및 멀티 테넌트 제공** : 기존의 관리자 수기 매뉴얼 확인 후 DR 전환 한계를 극복하기 위해 등급별 자동화된 카오스 엔지니어링 및 자동 절체 체계를 선제적으로 확립하여 엔터프라이즈 거버넌스를 완성해야 함.
