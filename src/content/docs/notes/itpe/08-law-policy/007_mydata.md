## 30초 인출

- 본질: **마이데이터 (MyData)** 는 정보주체가 자신에 관한 개인정보를 보유한 기관에 요구하여 본인 또는 제3자에게 직접 전송하도록 함으로써 데이터 주권을 실현하는 제도적·기술적 체계
- 메커니즘: 표준 API와 고신뢰 인증(OAuth 2.0 / FAPI)을 기반으로 정보보유자로부터 정보수신자에게 암호화된 데이터를 전송하고 통합 자산·건강·행정 맞춤형 서비스 제공
- 통찰: 스크래핑 방식 금지 이후 API 트래픽 폭증과 수신 데이터의 목적 외 오남용 위험이 상존하므로 전 주기 동의 철회 메커니즘과 데이터 파기 감사 추적 체계 구축 필수

<details><summary>핵심 용어</summary>

- **마이데이터 (MyData)** : 정보주체가 개인데이터에 대한 실질적 통제권을 행사하여 본인 정보를 능동적으로 관리·이동·활용하는 패러다임.
- **개인정보 전송요구권** : 정보주체가 본인의 개인정보를 본인 또는 지정한 제3자(마이데이터 사업자)에게 전송하도록 요구할 수 있는 법적 권리.
- **표준 API (Standard API)** : 스크래핑 방식의 보안 취약성을 극복하기 위해 정부 및 기관이 공통으로 규격화한 데이터 연계 인터페이스.
- **FAPI (Financial-grade API)** : 금융권 및 고위험 마이데이터 환경에서 요구되는 고보안 수준의 OAuth 2.0 / OIDC 기반 인증·인가 프로파일.
- **본인신용정보관리업** : 신용정보법에 따라 금융 마이데이터 서비스를 합법적으로 영위하기 위해 금융위원회의 인가를 받은 전문 사업자.

</details>

## 2~4교시 25점 답안

## Ⅰ. 마이데이터의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **마이데이터 (MyData)** 는 개인이 본인 정보의 제공처와 활용 범위를 스스로 결정하여 신용, 의료, 통신 등 분산된 데이터를 본인 또는 제3자에게 전송하게 하는 데이터 주권 실현 체계 |
| 목적 | 데이터 독점 해소, 정보주체의 자기결정권 보장 및 산업 간 융합 혁신 서비스 창출 |

## Ⅱ. 마이데이터의 핵심 원칙 및 생태계 특징

| 구분 | 핵심 원칙 및 구성 요소 | 상세 특징 및 기술적 요구사항 |
|---|---|---|
| **정보주체 통제권** | 자기결정권 보장 | 개인이 데이터 이동의 주체가 되어 전송 항목, 수신자, 보유 기간을 개별 선택 |
| | 동의 철회 및 삭제권 | 전송 요구를 언제든 즉시 철회할 수 있으며 수신 기관의 원본 데이터 즉각 삭제 보장 |
| **기술적 전송 규격** | 표준 API 기반 전송 | 과거 스크린 스크래핑(Screen Scraping) 전면 금지, RESTful JSON 표준 API 강제 |
| | FAPI 고보안 프로파일 | 상호 mTLS 암호화 통신, PKCE(Proof Key for Code Exchange) 및 서명된 JWT 적용 |
| **생태계 거버넌스** | 전 분야(Cross-Domain) 확산 | 금융(신용정보법) 중심에서 의료, 통신, 공공, 에너지(개인정보 보호법)로 전면 확대 |
| | 중계기관 및 허브 운영 | 중소 전송기관의 인프라 부담 완화를 위한 분야별 공인 데이터 중계기관 운영 |

## Ⅲ. 마이데이터 표준 전송 아키텍처 및 E2E 통신 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 마이데이터(MyData) 표준 전송 및 FAPI 인증 E2E 아키텍처 ]            │
└────────────────────────────────────────────────────────────────────────┘

 [ 정보주체 (이용자 앱) ]
    │ ① 전송요구 및 본인 인증 (사설 공동인증서 / 패스 등 전자서명)
    ▼
 [ 마이데이터 사업자 (정보수신자) ]
    │ ② 인가 코드(Authorization Code) 요청
    ▼
 [ 종합포털 / 개별 전송기관 인증 서버 ] ── ③ 토큰 검증 및 OAuth 2.0 Access Token 발급
    │
    ▼ (④ FAPI 표준 REST API 호출: Bearer Token 전송)
 [ 정보전송기관 (은행, 병원, 통신사) ]
    ├── API 게이트웨이: 트래픽 제어(Rate Limiting), 토큰 유효성 검증
    ├── 데이터 가공: 요청된 범위의 PII 최소 추출 및 JSON 직렬화
    └── 전송 암호화: TLS 1.3 기반 상호 인증 (mTLS)
    │
    ▼ (⑤ 암호화 데이터 페이로드 회신)
 [ 마이데이터 사업자 ] ── ⑥ 고객 데이터 통합 분석 및 자산/건강 맞춤형 서비스 제공
    │
    ▼ (⑦ 전송 및 활용 이력 보관)
 [ 마이데이터 종합지원센터 (KISA/금융보안원) ] ── 사후 이상거래 탐지(FDS) 및 권리 행사 지원
```

| 프로세스 단계 | 주요 수행 업무 | 핵심 보안 및 기술 요건 |
|---|---|---|
| **1. 권리 행사 및 본인 인증** | 이용자가 앱에서 전송 대상 기관 및 항목 선택 | 다중 인증(MFA), 전자서명 기반 전자위임장 생성 |
| **2. 인가 및 토큰 발급** | FAPI 규격에 따른 단기 Access Token 발급 | 토큰 유효기간 1년 이내 제한, Refresh Token 회전 |
| **3. 표준 API 데이터 조회** | HTTP GET/POST 기반 RESTful JSON 데이터 요청 | 대용량 분할 전송(Pagination), 전송 압축(GZIP) |
| **4. 데이터 수신 및 적재** | 전송 데이터 복호화 후 분석 데이터베이스 적재 | 수신 데이터 저장 암호화(AES-256), DB 접근 통제 |
| **5. 동의 철회 및 파기** | 이용자의 전송 중단 요구 및 계정 해지 시 즉시 파기 | 철회 API 호출, 수신 정보 영구 삭제 및 확인서 발급 |

## Ⅳ. 전 분야 마이데이터와 금융 마이데이터 비교

| 비교 항목 | 전 분야 마이데이터 (일반 체계) | 금융 마이데이터 (선도 체계) |
|---|---|---|
| **근거 법률** | 개인정보 보호법 제35조의2 | 신용정보의 이용 및 보호에 관한 법률 제33조의2 |
| **소관 부처** | 개인정보보호위원회 | 금융위원회, 금융감독원 |
| **적용 영역** | 통신, 의료, 에너지, 유통, 공공 등 전 산업 | 은행, 카드, 증권, 보험, 핀테크 등 금융권 |
| **진입 규제** | 개인정보관리전문기관 지정 및 등록제 | 본인신용정보관리업 허가제 (인가제) |
| **전송 인프라** | 범정부 마이데이터 중계 플랫폼 및 개별 API | 금융보안원 마이데이터 중계센터 및 개별 표준 API |
| **핵심 쟁점** | 비정형 데이터(진료기록 등) 표준화 및 인프라 비용 | 서비스 유료화 전환 및 대형 포털과의 데이터 비대칭 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 동의 절차의 복잡성으로 인한 이용자의 '무의식적 동의(Dark Pattern)' 및 데이터 과다 제공 | 직관적인 데이터 영수증(Data Receipt) 도입 및 항목별 동의 수준을 시각화하는 UI/UX 가이드라인 강제 |
| 대규모 전송기관의 API 서버 과부하 및 트래픽 폭증에 따른 대민 서비스 장애 위험 | 트래픽 셰이핑(Rate Limiting) 표준화, 비동기 배치 전송 큐 도입 및 캐싱 아키텍처 적용 |

## Ⅵ. 제언

전 분야 마이데이터의 신뢰성 확보를 위해 데이터의 이동부터 폐기까지 전 과정을 블록체인 스마트 컨트랙트로 자동 통제하고, 데이터 영수증 기반 투명성 확보 체계 구축 필요.

```text
[ 정보주체 ] ──(동의 설정: 항목, 기한 3개월)──> [ 블록체인 스마트 컨트랙트 ]
                                                         │
                                                         ▼ (인가 정책 동기화)
[ 마이데이터 API 전송 ] ──> [ 데이터 활용 ] ──> [ 3개월 경과 시점 자동 폐기 ]
                                                         │
                                                         ▼
[ 블록체인 분산 원장 로그 ] ──(데이터 영수증 실시간 발급)──> [ 사용자 확인 및 제어 ]
```

| 구분 | 기존 마이데이터 운영 방식 | 제언: 스마트 컨트랙트 기반 자동화 체계 |
|---|---|---|
| **동의 관리** | 사업자 서버 DB 내 플래그 저장 | 블록체인 기반 위변조 불가능한 분산 원장 기록 |
| **만료 파기** | 배치 프로그램 수동 실행 (누락 위험) | 스마트 컨트랙트에 의한 자동 파기 및 증적 생성 |
| **투명성 제공** | 복잡한 텍스트 약관 고지 | 실시간 스마트 데이터 영수증 발행 및 열람 |
| **트래픽 제어** | 각 기관별 상이한 임계치 적용 | API 거버넌스 플랫폼 기반 실시간 통합 스로틀링 |
