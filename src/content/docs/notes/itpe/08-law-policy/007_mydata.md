## 연관 키워드

- 마이데이터, 개인정보 전송요구권, 정보주체 자기결정권
- 본인전송, 제3자 전송, 정보전송자, 정보수신자
- 표준 전송 방식, 전송 이력, 필요 최소한의 범위

## Ⅰ. 마이데이터의 개요

- 핵심 요약 : 정보주체가 법정 범위의 자기 정보를 자신 또는 지정한 수신자에게 옮기도록 요구하는 **마이데이터**(MyData)는 **개인정보 전송요구권**에 근거한 데이터 이동 체계.
- 개념 : 개인이 보유 기관에 자신의 개인정보 전송을 요구하고, 본인 또는 허용된 수신자가 이를 활용하도록 하는 데이터 이동 제도.
- 배경 및 필요성 : 데이터가 서비스별로 흩어져 있어 이용자가 자신의 정보를 활용하기 어렵고, 특정 사업자에 데이터가 집중되는 문제를 완화할 필요가 있음.
- 주요 목적 : **정보주체 자기결정권** 확대와 안전한 데이터 이동을 통한 서비스 선택권 보장과 혁신 촉진.

## Ⅱ. 마이데이터의 특징 및 장점

- 핵심 요약 : 정보주체가 전송을 시작하고 대상과 경로를 통제하며, 표준 절차로 필요한 정보만 이동시켜 서비스 전환 가능성을 높이는 구조.

1. 정보주체의 요구 : 개인이 전송을 직접 요구 → 사업자 간 임의 공유 대신 통제권 강화.
2. **본인·제3자 전송**의 구분 : 전송 목적지에 따라 법정 요건을 달리 확인 → 권리 행사와 서비스 이용의 연결 명확화.
3. 표준화된 전송 : 전송 대상, 형식, 보안 절차를 맞춰 기관 간 연계 비용 감소.
4. 필요 최소한의 범위 : 요청 목적과 관련된 정보만 이동 → 과다 수집과 2차 이용 위험 축소.
5. 분야별 단계적 확대 : 의료·통신·에너지 등에서 시작해 법령과 시행령으로 대상 분야를 넓혀 이용자 선택 기회 확대.

## Ⅲ. 마이데이터의 전송 구조와 흐름

- 핵심 요약 : 전송 요구에서 본인 확인, 범위 검증, 정보 전송, 이력 관리로 이어지는 흐름과 본인·제3자 두 경로의 분기.

```text
[ 전송 경로 ]

정보주체 (요구·철회)
        ↓
정보전송자 (보유 기관)
     ↓                  ↓
본인에게 전송      제3자에게 전송
     ↓                  ↓
정보주체 본인    법정 요건 충족 수신자
```

```text
[ 전송 절차 ]

요구 접수
   ↓
본인 확인 → 대상 정보 확인
   ↓
전송
   ↓
수신자 이용
   ↓
이력 조회 · 철회 · 권리 행사
```

- 전송받는 주체와 분야에 따라 개인정보 보호법, 신용정보법 등 적용 법령과 참여 기관의 자격을 확인해야 함.
- API(Application Programming Interface) 기반 표준 전송 방식을 확대하는 추세이며, 기존 방식의 정리 시점은 분야별 공식 안내로 확인.
- 정보수신자는 전송 목적에 맞게 처리하고 접근 권한, 보유 기간, 이용 이력을 관리해야 함.

## Ⅳ. 전 분야 마이데이터와 금융 마이데이터의 비교

- 핵심 요약 : 두 체계 모두 정보 이동을 지원하지만 근거 법률, 참여자 요건, 전송 대상과 절차가 다름.

| 비교 항목 | 전 분야 마이데이터 | 금융 마이데이터 |
| --- | --- | --- |
| 주요 법적 근거 | 개인정보 보호법 제35조의2 | 신용정보법상 마이데이터 사업 관련 규정 |
| 중점 데이터 | 법령이 정한 개인정보 전송 대상 | 개인신용정보 등 금융 관련 정보 |
| 감독·운영 | 개인정보보호위원회와 관계 기관 | 금융위원회 등 금융 당국 |
| 확인 사항 | 본인 전송·제3자 전송 대상과 시행 범위 | 사업 허가 요건과 신용정보 보호 기준 |

- 전 분야라는 표현은 모든 개인정보가 언제나 전송 대상이라는 뜻이 아니므로, 법령상 대상과 전송자 범위를 항상 확인해야 함.

## Ⅴ. 마이데이터의 한계와 방안

- 핵심 요약 : 과다 전송, 이용자 혼란, 연계 장애, 분야별 표준 차이를 이용자 중심 설계와 운영 지표로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 과다 전송 | 복잡한 요구 화면에서 범위를 이해하지 못할 수 있음 | 항목·목적·수신자를 구분한 간결한 요구 화면 | 과다 전송 관련 민원 건수 |
| 이용자 혼란 | 본인 전송과 제3자 전송의 절차가 다름 | 전송 목적지와 이후 이용 방식을 명확히 표시 | 철회·문의 처리 소요 시간 |
| 연계 장애 | 기관의 트래픽 집중, 인증 실패 | 호출 제한, 재시도, 장애 알림과 전송 이력 관리 | 전송 성공률 |
| 분야별 표준 차이 | 데이터 형식과 참여 자격이 다름 | 공통 의미 체계와 분야별 매핑·검증 | 매핑 오류율 |

## Ⅵ. 마이데이터에 대한 기술사적 제언

- 핵심 요약 : 전송 보안에 그치지 않고 이용자의 이해, 통제, 사후 확인까지 포함한 전 주기 설계가 필요함.

1. 법정 전송 대상과 목적을 화면과 API 권한 범위에 동일하게 반영하는 것이 필요하다.
2. 정보주체가 전송 항목, 수신자, 시점과 이력을 한눈에 확인하고 철회할 수 있는 기능을 제공해야 한다.
3. 인증이나 전송이 실패했을 때 중복 전송과 누락을 막는 복구 절차를 운영하는 것이 바람직하다.
4. 분야별 시행 범위와 전송 방법은 법령 개정과 공식 안내를 주기적으로 확인해 반영해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 마이데이터의 가치는 데이터의 단순 집적보다 정보주체의 선택과 안전한 이동에 있음.
- 시사점 : 자기결정권을 실질적으로 보장하려면 전송 범위의 명료성, 안전한 연계, 사후 권리 행사 지원이 함께 갖춰져야 함.

근거 : 개인정보 보호법 제35조의2(국가법령정보센터 원문 확인), 2025년 3월 본격 시행 보도 기준.
