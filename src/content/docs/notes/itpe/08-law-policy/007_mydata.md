## Ⅰ. 마이데이터(MyData)의 개요

- 개념 : 개인이 본인 정보의 제공처와 활용 범위를 스스로 결정하여 신용, 의료, 통신 등 분산된 데이터를 본인 또는 제3자에게 전송하게 하는 데이터 주권 실현 체계.
- 제정 배경 및 필요성 : 개인정보의 실질적 통제권을 정보주체에게 환원하여 데이터 주권을 실현하고, 분산된 개인 데이터를 안전하게 이동·융합하여 금융·의료·공공 등 전 산업에 걸친 초개인화 혁신 서비스를 창출하기 위해 제도화됨.
- 핵심 목적 : 데이터 독점 해소, 정보주체의 자기결정권 보장 및 산업 간 융합 혁신 서비스 창출.

## Ⅱ. 마이데이터(MyData)의 법제도 체계 및 핵심 메커니즘

**마이데이터** (MyData) : 표준 API와 고신뢰 인증(OAuth 2.0 / FAPI)을 기반으로 정보보유자로부터 정보수신자에게 암호화된 데이터를 전송하고 통합 자산·건강·행정 맞춤형 서비스 제공 과정을 거쳐 상호 연동 및 단계별 법적·기술적 통제를 수행함.

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 마이데이터(MyData) 표준 전송 및 FAPI 인증 E2E 아키텍처 ]            │
└────────────────────────────────────────────────────────────────────────┘

 [ 정보주체 (이용자 앱) ]
    │ ① 전송요구 및 본인 인증 (사설 공동인증서 / 패스 등 전자서명)
    ▼
 [ 마이데이터 사업자 (정보수신자) ]
    │ ② 인가 코드(Authorization Code) 요청
    ▼
 [ 종합포털 / 개별 전송기관 인증 서버 ] ── ③ 토큰 검증 및 OAuth 2.0 Access Token 발급
    │
    ▼ (④ FAPI 표준 REST API 호출: Bearer Token 전송)
 [ 정보전송기관 (은행, 병원, 통신사) ]
    ├── API 게이트웨이: 트래픽 제어(Rate Limiting), 토큰 유효성 검증
    ├── 데이터 가공: 요청된 범위의 PII 최소 추출 및 JSON 직렬화
    └── 전송 암호화: TLS 1.3 기반 상호 인증 (mTLS)
    │
    ▼ (⑤ 암호화 데이터 페이로드 회신)
 [ 마이데이터 사업자 ] ── ⑥ 고객 데이터 통합 분석 및 자산/건강 맞춤형 서비스 제공
    │
    ▼ (⑦ 전송 및 활용 이력 보관)
 [ 마이데이터 종합지원센터 (KISA/금융보안원) ] ── 사후 이상거래 탐지(FDS) 및 권리 행사 지원
```

- **정보주체 통제권** : 자기결정권 보장 - 개인이 데이터 이동의 주체가 되어 전송 항목, 수신자, 보유 기간을 개별 선택
- **동의 철회 및 삭제권** : 전송 요구를 언제든 즉시 철회할 수 있으며 수신 기관의 원본 데이터 즉각 삭제 보장
- **기술적 전송 규격** : 표준 API 기반 전송 - 과거 스크린 스크래핑(Screen Scraping) 전면 금지, RESTful JSON 표준 API 강제
- **FAPI 고보안 프로파일** : 상호 mTLS 암호화 통신, PKCE(Proof Key for Code Exchange) 및 서명된 JWT 적용
- **생태계 거버넌스** : 전 분야(Cross-Domain) 확산 - 금융(신용정보법) 중심에서 의료, 통신, 공공, 에너지(개인정보 보호법)로 전면 확대

## Ⅲ. 마이데이터(MyData)의 세부 규정 및 국내외 제도 비교 분석

| 비교 항목 | 전 분야 마이데이터 (일반 체계) | 금융 마이데이터 (선도 체계) |
|---|---|---|
| 근거 법률 | 개인정보 보호법 제35조의2 | 신용정보의 이용 및 보호에 관한 법률 제33조의2 |
| 소관 부처 | 개인정보보호위원회 | 금융위원회, 금융감독원 |
| 적용 영역 | 통신, 의료, 에너지, 유통, 공공 등 전 산업 | 은행, 카드, 증권, 보험, 핀테크 등 금융권 |
| 진입 규제 | 개인정보관리전문기관 지정 및 등록제 | 본인신용정보관리업 허가제 (인가제) |
| 전송 인프라 | 범정부 마이데이터 중계 플랫폼 및 개별 API | 금융보안원 마이데이터 중계센터 및 개별 표준 API |
| 핵심 쟁점 | 비정형 데이터(진료기록 등) 표준화 및 인프라 비용 | 서비스 유료화 전환 및 대형 포털과의 데이터 비대칭 |

- 제도적 정합성 및 대응 방향 : 마이데이터는 상기 비교 지표를 바탕으로 법적 규제 준수(Compliance) 요건과 엔터프라이즈 운영 효율성을 균형 있게 확보하고, 선제적인 관리체계를 수립해야 함.

## Ⅳ. 마이데이터(MyData)의 주요 한계점 및 해결 방안

- 복잡한 동의 절차와 다크 패턴(Dark Pattern)에 따른 데이터 과다 제공 :
  - 한계점 : 동의 절차의 복잡성으로 인한 이용자의 '무의식적 동의(Dark Pattern)' 및 데이터 과다 제공.
  - 해결 방안 : 직관적인 데이터 영수증(Data Receipt) 도입 및 항목별 동의 수준을 시각화하는 UI/UX 가이드라인 강제.
- 대규모 정보제공기관의 API 트래픽 폭증 및 인프라 과부하 장애 위험 :
  - 한계점 : 대규모 전송기관의 API 서버 과부하 및 트래픽 폭증에 따른 대민 서비스 장애 위험.
  - 해결 방안 : 트래픽 셰이핑(Rate Limiting) 표준화, 비동기 배치 전송 큐 도입 및 캐싱 아키텍처 적용.

## Ⅴ. 마이데이터(MyData) 정착 및 실효성 확보를 위한 기술사적 제언

- 데이터 이동부터 파기까지 전 주기 블록체인 스마트 컨트랙트 감사 추적 : 기존의 사업자 서버 DB 내 플래그 저장 한계를 극복하기 위해 블록체인 기반 위변조 불가능한 분산 원장 기록 체계를 선제적으로 확립하여 엔터프라이즈 거버넌스를 완성해야 함.
- 직관적인 데이터 영수증(Data Receipt) 및 세분화된 항목별 동의 UI/UX 표준화 : 기존의 배치 프로그램 수동 실행 (누락 위험) 한계를 극복하기 위해 스마트 컨트랙트에 의한 자동 파기 및 증적 생성 체계를 선제적으로 확립하여 엔터프라이즈 거버넌스를 완성해야 함.
- 트래픽 셰이핑(Rate Limiting)과 비동기 배치 전송 큐 기반 대용량 API 안정화 : 기존의 복잡한 텍스트 약관 고지 한계를 극복하기 위해 실시간 스마트 데이터 영수증 발행 및 열람 체계를 선제적으로 확립하여 엔터프라이즈 거버넌스를 완성해야 함.
