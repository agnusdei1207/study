## 연관 키워드

- 프로젝트 한강, 중앙은행 디지털화폐, 예금토큰, 2계층 구조
- 통합원장, 프로그래머블 머니, 실시간 정산, 스마트 계약
- 영지식 증명, 오프라인 결제, 형식 검증

## Ⅰ. 프로젝트 한강의 개요

- 핵심 요약 : 중앙은행 화폐와 민간 은행 예금토큰을 한 원장에서 운용하는 2계층 지급결제 실증 사업.
- 개념 : 한국은행이 금융기관 간 결제용 **중앙은행 디지털화폐** (CBDC, Central Bank Digital Currency)를 발행하고, 시중은행이 이를 바탕으로 일반 이용자용 예금토큰을 발행하는 지급결제 실증 프로젝트.
- 배경 및 필요성 : 은행 간 결제의 정산 지연과 디지털 자산 거래에 쓸 실시간 결제 수단의 부재를 해소하기 위한 지급결제 혁신 검증 필요.
- 주요 목적 : 토큰화 자산 거래의 결제 수단 확보, 목적이 정해진 지원금의 사용처 통제 가능성 검증, 원화 기반 금융 시스템의 안정성 유지.
- 추진 경과 : 2025년 4~6월 1단계 실거래, 2026년 2단계 추진(보도 기준 하반기 실거래 목표).

## Ⅱ. 프로젝트 한강의 특징 및 장점

- 핵심 요약 : 2계층 구조와 예금 담보 발행이 결합하여 신뢰성과 정산 속도를 함께 확보하는 결제 모델.

1. 2계층 구조 : 중앙은행은 기관 간 도매 결제를, 민간 은행은 이용자 대상 소매 결제를 맡음 → 민간 은행의 금융 중개 기능 유지.
2. **예금토큰** : 고객 예금을 담보로 발행하는 토큰 → 법정화폐와 1대1로 연결되어 예금자 보호 체계(최대 5천만 원)와 함께 작동.
3. 프로그래머블 지급 : 스마트 계약으로 사용처와 기간 조건을 설정 → 지원금의 목적 외 사용 차단 가능성.
4. **통합원장** : 중앙은행 화폐와 예금토큰을 한 원장에서 운용 → 정산 단계 축소와 실시간 종결.

```text
[ 토큰 구분 ]

예금토큰 (Token I): 일반 결제용
   ↓
바우처 토큰 (Token II): 사용처·기간 제한
   ↓
조건 충족 시에만 지급 실행
```

## Ⅲ. 프로젝트 한강의 구조 (흐름)

- 핵심 요약 : 중앙은행 발행에서 참가 은행 발행, 이용자 결제, 조건 검증, 실시간 정산으로 이어지는 단계형 흐름.

```text
[ 2계층 지급결제 흐름 ]

한국은행 (기관용 CBDC 발행)
   ↓
참가 은행 (예금 담보 예금토큰 발행)
   ↓
이용자 결제 요청 (전자지갑)
   ↓
스마트 계약 조건 검증
   ↓
실시간 정산 (통합원장)
```

## Ⅳ. 프로젝트 한강과 기존 전자지급 수단의 비교

- 핵심 요약 : 기존 간편결제의 사후 정산 구조와 달리, 예금토큰은 예금 담보와 실시간 정산을 결합한 구조.

| 비교 축 | 예금토큰 (프로젝트 한강) | 기존 간편결제 (선불전자지급수단) |
| --- | --- | --- |
| 발행 주체 | 인가받은 시중은행 | 전자금융업자 |
| 담보 | 은행 예금 기반 | 선불 충전금 (예치·보증) |
| 정산 방식 | 중앙은행 화폐 기반 실시간 정산 | 은행망과 결제망을 통한 사후 정산 |
| 예금 보호 | 은행 예금과 같은 보호 체계 | 선불 충전금 보호 체계 |
| 조건부 지급 | 스마트 계약 기반 조건 설정 가능 | 제한적 프로그래밍 수준 |

## Ⅴ. 프로젝트 한강의 한계와 방안

- 핵심 요약 : 처리 성능, 개인정보 보호, 오프라인 연속성, 계약 보안의 네 한계를 계층 분리와 설계 기준으로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 대규모 실시간 트래픽 처리 병목 | 소매 결제가 몰리면 원장 처리 성능이 한계에 부딪힘 | 결제와 정산 계층을 분리하고 확장 구조를 검증 | 실거래 처리 지연율 |
| 영구 기록과 개인정보 삭제 요구의 충돌 | 분산원장의 변경 불가 기록이 파기 요구와 상충 | 개인식별정보는 원장 밖에 저장하고 영지식 증명 적용 검토 | 개인정보 처리 점검 건수 |
| 통신 단절 시 결제 연속성 저하 | 중앙화 망 대비 오프라인 결제 수단이 취약 | 근거리 무선 기반 오프라인 잔액 검증과 사후 동기화 | 동기화 오류율 |
| 스마트 계약의 로직 오류 | 계약 결함이 곧 자금 유출로 이어질 위험 | 배포 전 형식 검증(formal verification) 의무화 | 감사 지적 건수 |

## Ⅵ. 프로젝트 한강에 대한 기술사적 제언

- 핵심 요약 : 기술 파일럿을 넘어 상호운용성과 보안을 기준으로 한 표준 설계를 정착시키는 것이 과제.
- 참가 은행이 서로 다른 원장과 연동할 때 쓸 인터페이스 표준을 먼저 정하여 은행 간 결제 호환성을 확보해야 한다.
- 스마트 계약은 배포 전에 형식 검증을 거치도록 하고, 검증 결과를 감사 체계와 연계하여 국고 손실 위험을 낮춰야 한다.
- 실증에서 얻은 거래 데이터를 공개 가능한 형태로 축적하여 제도 설계의 근거로 삼아야 한다.

## Ⅶ. 결론

- 핵심 요약 : 프로젝트 한강은 중앙은행 화폐와 예금토큰을 결합한 차세대 지급결제 구조를 검증하는 실증 사업임.
- 실증의 성패는 대규모 실거래에서 안정성과 보안을 동시에 입증하는지에 따라 판가름 날 것이다.
