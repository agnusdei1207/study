## Ⅰ. 프로젝트 한강의 개요

- **개념** : 한국은행이 금융기관 간 결제용 '기관용 CBDC'를 발행하고, 시중은행이 이를 바탕으로 일반 이용자 결제용 '예금토큰'을 발행하여 지급결제 혁신을 검증하는 2계층 통화 실증 프로젝트.
- **제정 배경 및 필요성** : 스마트 계약 취약점으로 인한 토큰 탈취 위험과 프라이빗 블록체인의 거래 처리 속도(TPS) 한계를 극복하기 위해 제로지식 증명(ZKP) 기반 프라이버시 보호 및 은행 레거시 코어뱅킹과의 롤백 보장 원자적 결제(Atomic Swap) 아키텍처 필수.
- **핵심 목적** : 미래 토큰화 자산 거래의 안정적 결제 수단 확보, 복지 바우처 등의 부정수급 차단(프로그래머블 머니), 글로벌 CBDC 표준 주도 및 기존 통화 금융 시스템 안정성 유지.

## Ⅱ. 프로젝트 한강의 법제도 체계 및 핵심 메커니즘

프로젝트 한강은(는) 한국은행이 참가 은행에 기관용 CBDC 공급 및 은행 간 거액 결제망 운영 → 참가 은행이 100% 예금 담보 기반 예금토큰(Token I) 및 조건부 바우처(Token II) 발행 → 이용자 전자지갑 결제 요청 → 스마트 계약 기반 조건 충족 검증 후 실시간 동시 정산(PvP/DvP) 과정을 거쳐 체계적인 법제도적 통제와 기술적 신뢰성을 확보함.

```text
[ 프로젝트 한강의 2계층 결제 및 프로그래머블 지급 프로세스 ]

+--------------------------------------------------------------------------+
| 1계층: 한국은행 (중앙은행 도매 결제망)                                    |
|  - 기관용 CBDC 분산원장 플랫폼 운영 및 발행                             |
|  - 참가 은행 간 예금토큰 정산에 따른 최종 차액 결제(한은금융망 연동)     |
+--------------------------------------------------------------------------+
                                    │
               기관용 CBDC 발행 / 정산│ 차액 결제
                                    ▼
+--------------------------------------------------------------------------+
| 2계층: 참가 시중은행 (민간 소매 결제망)                                  |
|  - 고객 예금 담보 100% 락업(Lock-up) → 예금토큰(Token I/II) 민팅(Mint)   |
|  - 스마트 계약 기반 거래 조건(사용처, 유효기간, 환불 규정) 제어          |
+--------------------------------------------------------------------------+
                                    │
                                    ▼
[ 사용자 간 결제 및 가맹점 실거래 흐름 ]
┌────────────────────────┐      ┌────────────────────────┐      ┌────────────────────────┐
│   이용자 전자지갑      │      │      가맹점 단말기     │      │   스마트 계약 검증     │
│ - 예금토큰 보유        │──┐   │ - 결제 승인 요청       │──┐   │ - 바우처 사용처 확인   │
│ - QR/NFC 결제 요청     │  │   │ - 영수증 발급          │  │   │ - 조건 미충족 시 반려  │
└────────────────────────┘  │   └────────────────────────┘  │   └────────────────────────┘
                            ▼                               ▼
                 ┌─────────────────────────────────────────────────────┐
                 │  허가형 분산원장 네트워크 (Permissioned DLT)        │
                 │  - 합의 알고리즘(IBFT 2.0 / Raft), 초당 수천 건 TPS │
                 │  - 실시간 자산 이전 및 롤백 보장 원자적 스왑        │
                 └─────────────────────────────────────────────────────┘
```

- **2계층 통화 시스템(Two-Tier Architecture)** : 중앙은행은 금융기관 대상 도매형 CBDC만 취급하고, 대고객 소매 결제는 민간 은행이 예금토큰으로 담당하여 통화금융 중개기능 보존.
- **토큰 형태의 다양화 (Token I & II)** : 단순 결제용 예금토큰(Token I)과 사용 목적·기간이 제한된 바우처용 토큰(Token II, 프로그래머블) 분리 실증.
- **예금자 보호법 및 동일 가치 보장** : 예금토큰은 법정화폐(원화)와 1:1 패깅되며, 기존 은행 예금과 동일하게 예금자 보호법(최대 5천만 원) 적용.
- **분산원장과 중앙집중형 레거시 연동** : 이더리움 기반 허가형 블록체인(프라이빗 DLT)과 한국은행 한은금융망(BOK-Wire+) 및 은행 코어뱅킹 간 원자적 결제(Atomic Settlement) 지원.

|---|---|---|---|
| 발행 주체 | 인가받은 시중 상업은행 | 전자금융업자 (빅테크/핀테크) | 민간 가상자산 발행 재단/기업 |
| 담보 자산 | 은행 예금 100% (지급준비금 연계) | 선불 충전금 (보증보험/예치) | 발행사 자체 관리 상업어음, 국채 등 |
| 법적 지위 | 은행 예금과 동등 (예금자 보호) | 선불전자지급수단 | 가상자산 (자본시장법/가상자산법) |

- **제도적 시사점** : 프로젝트 한강은(는) 상기 비교 지표를 바탕으로 법적 의무 준수와 비즈니스 연속성 간의 균형을 확보하고, 규제 환경 변화에 선제적으로 대응할 수 있는 아키텍처 및 거버넌스 체계를 확립해야 함.

## Ⅳ. 프로젝트 한강의 주요 한계점 및 해결 방안

- **국가 소매 결제 대규모 실시간 트래픽 유입 시 분산원장 처리 성능(TPS) 병목** :
  - **한계점** : 초당 수만 건에 달하는 대규모 국가 실시간 소매 결제 트래픽 유입 시 분산원장의 처리 성능(TPS) 및 확장성 병목.
  - **해결 방안** : 레이어2 롤업(Rollup) 기술 도입, 샤딩(Sharding) 아키텍처 적용 및 결제와 정산 계층의 물리적 원장 분리.
- **분산원장 영구 기록 특성과 개인정보 보호법상 파기권(잊힐 권리) 충돌** :
  - **한계점** : 분산원장에 영구 기록되는 결제 트랜잭션으로 인한 거래 내역 유출 및 개인정보 보호법상 파기권(잊힐 권리) 충돌.
  - **해결 방안** : 영지식 증명(Zero-Knowledge Proof) 암호화 기법 적용 및 개인식별정보(PII)의 오프체인 해시 저장 분리 구조 설계.
- **통신망 단절 및 재해 발생 시 오프라인 결제 연속성 보장 메커니즘 난제** :
  - **한계점** : 통신망 단절, 디바이스 방전, 자연재해 발생 시 중앙화 망 대비 취약한 오프라인 결제 연속성 보장 난제.
  - **해결 방안** : 근거리 무선통신(NFC)과 보안 하드웨어(SE/TEE)를 연계한 듀얼 오프라인 잔액 검증 및 사후 온라인 원장 동기화 체계 구축.

## Ⅴ. 프로젝트 한강 정착 및 실효성 확보를 위한 기술사적 제언

- **법제도 정비 및 선제적 가이드라인 수립** : 프로젝트 한강은 국가 통화 인프라의 미래를 결정짓는 핵심 국정과제이므로, 기술적 파일럿에 머무르지 않고 금융 보안과 상호운용성을 담보하는 표준 아키텍처 정립 필요.
- **상호운용성 중심 거버넌스 및 실행 전략** : 은행 간 분산원장 상호 연동 표준 인터페이스(API/SDK) 단일화를 중점 추진하여 다수 시중은행 간 단절 없는 결제 호환성 보장의 가시적 성과를 확보하고 제도의 안정적 정착을 도모해야 함.
- **보안성 중심 거버넌스 및 실행 전략** : 스마트 계약 배포 전 포멀 베리피케이션(Formal Verification) 의무화를 중점 추진하여 컨트랙트 해킹, 로직 오류에 의한 국고 유출 원천 차단의 가시적 성과를 확보하고 제도의 안정적 정착을 도모해야 함.
