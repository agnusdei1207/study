## 연관 키워드

- SaaS(Software as a Service), 공공부문 SaaS 이용, 디지털 서비스 전문계약, CSAP
- 공동책임모델, 벤더 종속(Vendor Lock-in), 출구 전략(Exit Strategy), 데이터 주권

## Ⅰ. 공공부문 SaaS 이용 가이드라인의 개요

- 핵심 요약 : 공공기관이 자체 개발 대신 검증된 민간 클라우드 소프트웨어를 구독할 때의 도입·계약·운영·출구 기준을 정한 지침.
- 개념 : 행정·공공기관이 **SaaS**(Software as a Service, 클라우드로 제공되는 소프트웨어를 구독하는 방식)를 업무에 쓸 때 따르는 도입 기준.
- 배경 및 필요성 : 디지털플랫폼정부 정책에 따라 공공부문의 클라우드 SaaS 활용이 늘었고, 행정안전부는 보안과 성능 기준을 충족한 SaaS만 공공 업무에 쓰도록 하는 방침을 밝힘 (행정안전부 발표 기준). 이에 따라 도입 절차를 표준화할 필요가 생김.
- 주요 목적 : 도입 기간 단축, 구축 예산 절감, 민간 소프트웨어의 신속한 공공 활용, 데이터 보호와 사업자 교체 가능성 확보.

## Ⅱ. 공공부문 SaaS 이용의 특징 및 장점

- 핵심 요약 : 조달 간소화, 보안 인증 확인, 책임 분담, 출구 전략이 맞물려 빠른 도입과 통제를 동시에 얻는 방식.

1. 조달 간소화 : 디지털 서비스 전문계약 제도를 통해 카탈로그 기반으로 계약 → 도입 기간 단축.
2. 보안 인증 확인 : CSAP(Cloud Security Assurance Program, 클라우드 보안인증제) 인증 여부를 선정 기준으로 사용 → 공공 데이터 처리의 보안 수준 확인.
3. 책임 분담 : 클라우드 공동책임모델에 따라 인프라 운영 책임은 공급사가, 데이터와 접근 관리 책임은 기관이 짐 → 책임 경계 명확화.
4. 출구 전략 : 계약 종료 시 데이터 반환과 파기 절차를 계약에 명시 → 사업자 교체와 데이터 주권 유지.

```text
[ 출구 전략 실행 순서 ]

데이터 추출 (표준 형식)
   ↓
신규 시스템 이관 및 정합성 검증
   ↓
기존 사업자 데이터 파기 확인
```

## Ⅲ. 공공부문 SaaS 도입의 흐름

- 핵심 요약 : 기획에서 출구까지 다섯 단계가 계약과 인증 확인으로 이어지는 도입 흐름.

```text
[ 공공 SaaS 도입 흐름 ]

도입 기획 (업무 요건, 데이터 중요도 분류)
   ↓
보안 적격성 확인 (CSAP 인증, 보안성 검토)
   ↓
조달·계약 (SLA, 데이터 반환 조항)
   ↓
운영 (인증 연계, 성능·가용성 모니터링)
   ↓
출구 (데이터 추출, 이관, 파기 확인)
```

## Ⅳ. 자체 구축형과 공공부문 SaaS의 비교

- 핵심 요약 : 자체 구축은 자본 투자와 장기 개발이, SaaS는 구독 비용과 공급사 의존 관리가 중심인 구조.

| 비교 축 | 자체 구축형 (On-Premises SI) | 공공부문 SaaS 이용 |
| --- | --- | --- |
| 구축 기간 | 요구 분석·설계·개발에 장기간 소요 | 구독 후 바로 사용 가능 |
| 비용 구조 | 초기 대규모 자본 지출(CAPEX, Capital Expenditure) | 구독료 기반 운영 비용(OPEX, Operating Expenditure) |
| 기능 갱신 | 노후화 시 재구축 예산 필요 | 공급사가 기능을 갱신 |
| 보안 책임 | 인프라부터 응용까지 기관 책임 | 클라우드 공동책임모델 적용 |
| 벤더 종속 | 소스 확보로 변경이 상대적으로 용이 | 공급사 API와 데이터 구조에 종속될 위험 |

- 선택 기준 : 데이터 민감도와 업무 차별성에 따라 자체 구축과 SaaS 중 적용 범위를 정함.

## Ⅴ. 공공부문 SaaS 이용의 한계와 방안

- 핵심 요약 : 데이터 락인, 가격 협상력 부족, 책임 경계 오해를 계약 조건과 관리 절차로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 데이터 락인 (Data Lock-in) | 사업자 고유 데이터 구조 → 전환 시 이전 비용과 손실 발생 | 표준 형식 데이터 추출 권한과 이전 지원 조건을 계약에 명시 | 데이터 추출 성공률, 이전 소요 기간 |
| 가격 인상 협상력 부족 | 일방적 요금·라이선스 변경 → 예산 불확실성 | 다년 계약 시 가격 조정 조건과 상한을 사전 합의 | 연간 비용 변동률 |
| 공동책임 경계 오해 | 공급사 인프라 보안을 기관 책임으로 오인하거나 그 반대로 판단 | 책임 분계표를 계약 부속으로 두고 연 1회 점검 | 책임 분계 미준수 건수 |
| 보안 인증 미확인 | 인증 범위 밖 서비스 도입 → 데이터 보호 공백 | 도입 전 인증 범위와 등급 확인, 변경 시 재확인 | 인증 범위 적합 여부 |

## Ⅵ. 공공부문 SaaS 이용에 대한 기술사적 제언

- 핵심 요약 : 계약 단계의 출구 조건과 인증 확인을 표준 절차로 굳히고, 운영 중에도 데이터 이동성을 점검하는 체계로 전환.

공공기관은 SaaS 계약서에 데이터 추출 방식과 종료 시 반환·파기 절차를 기본 조항으로 넣고, 이를 검증할 수 있는 점검 주기를 두어야 한다. 행정안전부와 조달 기관은 인증된 서비스의 목록과 표준 계약 양식을 갱신해 기관이 같은 기준으로 비교하도록 지원하는 것이 바람직하다. 이러한 절차를 정보화 사업 관리 체계와 연계하면 도입 속도와 통제 수준을 함께 확보할 수 있다.

## Ⅶ. 결론

- 핵심 요약 : 공공부문 SaaS 이용 가이드라인은 빠른 도입과 데이터 주권을 함께 지키기 위한 도입·계약·출구의 기준선.
- 구독형 소프트웨어를 쓰더라도 사업자 교체 가능성을 계약 단계에서 확보하는 것이 장기 운영의 전제가 됨.
