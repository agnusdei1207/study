## 30초 인출

- 본질: **공공부문 SaaS 이용 가이드라인** 은 공공기관이 자체 SI 구축 대신 민간 클라우드 소프트웨어(SaaS)를 안전하게 도입하여 공공 업무를 혁신할 수 있도록 규정한 법정 보안·조달 지침
- 메커니즘: 업무·데이터 중요도 분석 후 디지털서비스 전문계약제도를 통해 신속 조달하고, CSAP 인증 확인 및 SLA 체결을 거쳐 운영하며 계약 종료 시 데이터 반환·파기 출구 전략을 이행
- 통찰: 특정 상용 벤더 종속(Lock-in)과 서비스 중단 시 대민 행정 마비 및 데이터 유실 위험이 크므로 개방형 표준 데이터 추출(API) 의무화와 사전 출구 모의훈련(Exit Drill) 체계 구축 필수

<details><summary>핵심 용어</summary>

- **공공 SaaS (Software as a Service)** : 공공기관이 직접 서버를 구축하지 않고 클라우드 제공자의 완성형 소프트웨어를 구독 형태로 이용하는 서비스.
- **CSAP (Cloud Security Assurance Program)** : 공공기관에 공급되는 클라우드 서비스의 정보보호 기준 적합성을 검증하는 클라우드 보안인증제도.
- **디지털서비스 전문계약제도** : 일반 경쟁입찰 대신 사전에 선정된 디지털서비스 풀에서 수의계약 또는 카탈로그 계약으로 수일 내 신속 도입하는 제도.
- **출구 전략 (Exit Strategy)** : SaaS 공급업체의 도산, 계약 만료 시 공공데이터를 안전하게 반환받고 타 시스템으로 이전하기 위한 전환 계획.
- **국정원 보안성 검토** : 국가·공공기관이 민간 클라우드를 도입하기 전 국가 사이버 안보 차원의 취약점과 데이터 주권을 검증받는 행정 절차.

</details>

## 2~4교시 예상문제 (25점)

> 행정·공공기관의 클라우드 전환 가속화에 따른 '공공부문 SaaS 이용 가이드라인'의 도입 목적과 주요 절차를 설명하고, CSAP 보안인증 등급 연계 및 벤더 락인(Lock-in) 방지를 위한 출구 전략(Exit Strategy) 방안을 논하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 공공부문 SaaS 이용의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **공공부문 SaaS 이용** 은 행정·공공기관이 자체 소프트웨어 개발 대신 검증된 민간 클라우드 애플리케이션을 구독하여 사용하는 공공 정보화 추진 모델 |
| 목적 | 정보화 사업 기간 단축, 예산 절감, 민간 혁신 SW 기술의 신속한 공공 접목 및 유지보수 효율화 |

## Ⅱ. 공공 SaaS 도입 요건 및 보안 거버넌스 특징

| 구분 | 핵심 도입 요건 | 상세 특징 및 기술적 적용 기준 |
|---|---|---|
| **조달 방식 (특징)** | **디지털서비스 전문계약** | 조달청 '디지털서비스몰'을 통한 수의계약 및 카탈로그 계약 허용 (도입 기간 1개월 단축) |
| **보안성 검증** | **CSAP 보안인증 획득** | 공공 데이터 처리 SaaS는 한국인터넷진흥원(KISA)의 CSAP 인증 필수 (하 등급 등 차등 적용) |
| | 국가정보원 보안성 검토 | 도입 전 데이터 처리 위치, 암호화 키 관리, 해외 사업자 백도어 유무 등 보안성 검토 필 |
| **데이터 주권** | 국내 데이터센터 입지 | 공공데이터 저장 스토리지는 대한민국 영토 내 위치 원칙, 국외 무단 이전 원천 금지 |
| **품질 및 연속성** | 공공 SLA 체결 | 서비스 가용률 99.9% 이상 보장, 장애 발생 시 통지 절차 및 복구 목표(RTO) 명시 |
| **출구 보장 (특징)** | **데이터 반환 및 파기 의무** | 계약 만료 시 공공데이터를 범용 포맷(JSON, CSV)으로 무상 제공하고 잔존 데이터 영구 파기 |

## Ⅲ. 공공부문 SaaS 도입·운영·출구(Exit) E2E 라이프사이클 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 공공부문 민간 SaaS E2E 도입·운영 및 출구 전략 파이프라인 ]           │
└────────────────────────────────────────────────────────────────────────┘

 [ 1. 도입 기획 및 적합성 검토 ]
    ├── 공공 업무 요건 분석 (ERP, 협업도구, 전자결재, CRM 등)
    └── 데이터 중요도 분류 (비공개 업무 vs 일반 대민 행정)
          │
          ▼
 [ 2. 보안 적격성 및 조달 계약 ]
    ├── CSAP 인증 여부 확인 및 디지털서비스 전문계약 풀 선정
    ├── 국정원 보안성 검토 신청 및 승인
    └── 서비스수준협약(SLA) 및 데이터 출구 계약서(Exit Clause) 서명
          │
          ▼
 [ 3. 공공기관 행정망 연계 및 운영 ]
    ├── SSO(Single Sign-On) 및 공공 GPKI/행정전자서명 연계
    ├── 공공망-민간 SaaS 간 TLS 1.3 암호화 터널링 (IP 화이트리스트)
    └── 상시 가관측성(APM) 기반 SLA 달성률 모니터링
          │
          ▼ (계약 만료 또는 사업자 교체 시)
 [ 4. 출구 전략(Exit Strategy) 실행 ]
    ├── Step 1: 전체 공공데이터 표준 덤프 추출 (API 기반 무손실 백업)
    ├── Step 2: 신규 시스템/SaaS로의 데이터 마이그레이션 및 정합성 검증
    └── Step 3: 기존 공급사 스토리지 내 공공데이터 완전 파기(DoD 5220) 확인서 징구
```

| 라이프사이클 | 주요 수행 업무 | 핵심 증적 및 산출물 |
|---|---|---|
| **도입 검토** | 표준 SaaS 기능 충족도 평가, 커스터마이징 최소화 | SaaS 적합성 검토 보고서 |
| **계약 체결** | CSAP 유효기간 확인, 위약금 및 손해배상 조항 삽입 | 디지털서비스 계약서, SLA 협약서 |
| **망 연계 구축** | 공공기관 접근제어 솔루션과 SaaS 테넌트 보안 연동 | 계정 연계 아키텍처 정의서 |
| **운영 모니터링** | 월별 가용성 평가, 패치 및 버전 업데이트 영향 분석 | 월간 서비스 품질 평가서 |
| **계약 종료(Exit)** | 데이터 완전 추출 확인, 백업 데이터 영구 삭제 입증 | 데이터 이전 확인서, 영구파기 증명서 |

## Ⅳ. 자체 구축형(SI)과 공공 민간 SaaS 도입 비교

| 비교 항목 | 전통적 자체 구축형 (On-Premises SI) | 공공부문 민간 SaaS 이용 (Cloud) |
|---|---|---|
| **구축 기간** | 통상 1년~2년 소요 (요구분석·설계·개발) | **즉시 또는 1개월 이내 구독 시작 가능** |
| **초기 투자 비용** | 수십억~수백억 원대 대규모 자본 지출(CAPEX) | **월/연 단위 구독료 기반 운영 비용(OPEX)** |
| **기능 업그레이드** | 노후화 시 대규모 재구축 예산 소요 (5~7년 주기) | **클라우드 상에서 최신 기능 무중단 자동 갱신** |
| **보안 책임** | 기관이 인프라부터 앱까지 모든 보안 자체 책임 | **클라우드 공동책임모델 (인프라는 공급사 책임)** |
| **벤더 종속성** | 구축 후 소스코드 확보로 커스터마이징 용이 | **공급자 API 및 데이터 스키마에 종속 위험 상존** |
| **장애 복구성** | 기관 자체 DR 센터 구축 및 복구 의존 | **공급사의 멀티 가용영역(AZ) 기반 고가용성 활용** |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 특정 SaaS 벤더의 독점적 데이터 구조로 인해 타 서비스로 전환 시 데이터 손실 및 막대한 이전 비용 발생 | 계약서 내 표준 REST API 기반의 원천 데이터 추출 권한을 명문화하고 데이터 이관 비용 상한제 설정 |
| 공급업체의 일방적인 서비스 가격 인상 및 라이선스 정책 변경 시 공공기관의 협상력 부재 | 다년 계약 체결 시 연간 인상률 상한(예: 물가상승률 이내)을 제한하는 '공공 표준 계약 가이드라인' 강제 |

## Ⅵ. 제언

공공 SaaS의 벤더 락인을 원천 방지하고 서비스 연속성을 보장하기 위해 데이터 출구 파이프라인을 자동화하고, 매년 정기 출구 모의훈련(Disaster Recovery & Exit Drill) 체계 구축 필요.

```text
[ 공공기관 SaaS 운영 환경 ]
               │
               ▼ (일 단위 자동 증분 백업)
[ 기관 로컬/G-클라우드 독립 아카이빙 스토리지 ]
   ├── 표준 JSON/CSV 포맷으로 데이터 비동기 미러링
   └── 객체 스토리지 불변 WORM(Write Once Read Many) 보관
               │
               ▼ (비상 시 또는 계약 만료 시)
[ 자동 데이터 변환 및 마이그레이션 엔진 ]
   ├── 대체 SaaS B의 스키마로 자동 매핑 및 변환
   └── 단절 없는 행정 서비스 즉시 재개 (전환 시간 < 4시간)
```

| 구분 | 기존 수동 출구 대응 | 제언: 상시 아카이빙 연계 자동 출구 체계 |
|---|---|---|
| **백업 방식** | 계약 종료 직전 일회성 일괄 추출 | 일일 주기 표준 포맷 자동 증분 아카이빙 |
| **이전 소요 시간** | 수개월간 데이터 포맷 변환 수작업 | 자동 변환 매퍼를 통한 수시간 내 신규 SaaS 이관 |
| **데이터 손실 위험** | 벤더 갑작스러운 파산 시 전면 유실 | 자체 보관 스토리지 보유로 데이터 주권 완벽 수호 |
| **협상 주도권** | 벤더에 끌려다니는 수동적 지위 | 언제든 타사 전환 가능한 구조로 가격 협상력 확보 |

## 출제 이력과 검증 출처

- 제134회 정보관리기술사 2교시 1번: 클라우드 서비스 도입 시 위험관리 원칙, 보안성 검토 및 서비스수준협약(SLA)
- 국가법령정보센터 「행정기관 및 공공기관의 클라우드컴퓨팅서비스 이용 기준 및 안전성 확보 등에 관한 고시」
- 과학기술정보통신부 「공공부문 SaaS 도입 가이드라인 및 모범 사례집」
- 한국지능정보사회진흥원(NIA) 「디지털서비스 전문계약제도 안내서」
