## Ⅰ. 공공부문 SaaS 이용 가이드라인의 개요

- 개념 : 행정·공공기관이 자체 소프트웨어 개발 대신 검증된 민간 클라우드 애플리케이션을 구독하여 사용하는 공공 정보화 추진 모델.
- 제정 배경 및 필요성 : 정부의 디지털플랫폼정부 구현 및 민간 혁신 기술 활용 정책에 따라 공공부문의 클라우드 서비스(SaaS) 도입이 본격화되면서, 보안 우려를 불식하고 표준화된 도입·계약·운영 절차를 정립하여 안전한 SaaS 전환을 촉진하기 위해 제정됨.
- 핵심 목적 : 정보화 사업 기간 단축, 예산 절감, 민간 혁신 SW 기술의 신속한 공공 접목 및 유지보수 효율화.

## Ⅱ. 공공부문 SaaS 이용 가이드라인의 법제도 체계 및 핵심 메커니즘

**공공부문 SaaS 이용 가이드라인** : 업무·데이터 중요도 분석 후 디지털서비스 전문계약제도를 통해 신속 조달하고, CSAP 인증 확인 및 SLA 체결을 거쳐 운영하며 계약 종료 시 데이터 반환·파기 출구 전략을 이행 과정을 거쳐 상호 연동 및 단계별 법적·기술적 통제를 수행함.

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 공공부문 민간 SaaS E2E 도입·운영 및 출구 전략 파이프라인 ]           │
└────────────────────────────────────────────────────────────────────────┘

 [ 1. 도입 기획 및 적합성 검토 ]
    ├── 공공 업무 요건 분석 (ERP, 협업도구, 전자결재, CRM 등)
    └── 데이터 중요도 분류 (비공개 업무 vs 일반 대민 행정)
          │
          ▼
 [ 2. 보안 적격성 및 조달 계약 ]
    ├── CSAP 인증 여부 확인 및 디지털서비스 전문계약 풀 선정
    ├── 국정원 보안성 검토 신청 및 승인
    └── 서비스수준협약(SLA) 및 데이터 출구 계약서(Exit Clause) 서명
          │
          ▼
 [ 3. 공공기관 행정망 연계 및 운영 ]
    ├── SSO(Single Sign-On) 및 공공 GPKI/행정전자서명 연계
    ├── 공공망-민간 SaaS 간 TLS 1.3 암호화 터널링 (IP 화이트리스트)
    └── 상시 가관측성(APM) 기반 SLA 달성률 모니터링
          │
          ▼ (계약 만료 또는 사업자 교체 시)
 [ 4. 출구 전략(Exit Strategy) 실행 ]
    ├── Step 1: 전체 공공데이터 표준 덤프 추출 (API 기반 무손실 백업)
    ├── Step 2: 신규 시스템/SaaS로의 데이터 마이그레이션 및 정합성 검증
    └── Step 3: 기존 공급사 스토리지 내 공공데이터 완전 파기(DoD 5220) 확인서 징구
```

- **조달 방식** (특징) : **디지털서비스 전문계약** - 조달청 '디지털서비스몰'을 통한 수의계약 및 카탈로그 계약 허용 (도입 기간 단축)
- **보안성 검증** : **CSAP 보안인증 획득** - 공공 데이터 처리 SaaS는 한국인터넷진흥원(KISA)의 CSAP 인증 필수 (하 등급 등 차등 적용)
- **국가정보원 보안성 검토** : 도입 전 데이터 처리 위치, 암호화 키 관리, 해외 사업자 백도어 유무 등 보안성 검토 필
- **데이터 주권** : 국내 데이터센터 입지 - 공공데이터 저장 스토리지는 대한민국 영토 내 위치 원칙, 국외 무단 이전 원천 금지
- **품질 및 연속성** : 공공 SLA 체결 - 높은 서비스 가용률 보장, 장애 발생 시 통지 절차 및 복구 목표(RTO) 명시

## Ⅲ. 공공부문 SaaS 이용 가이드라인의 세부 규정 및 국내외 제도 비교 분석

| 비교 항목 | 전통적 자체 구축형 (On-Premises SI) | 공공부문 민간 SaaS 이용 (Cloud) |
|---|---|---|
| 구축 기간 | 장기간 소요 (요구분석·설계·개발) | 즉시 구독 시작 가능 |
| 초기 투자 비용 | 수십억~수백억 원대 대규모 자본 지출(CAPEX) | 월/연 단위 구독료 기반 운영 비용(OPEX) |
| 기능 업그레이드 | 노후화 시 대규모 재구축 예산 소요 (5~7년 주기) | 클라우드 상에서 최신 기능 무중단 자동 갱신 |
| 보안 책임 | 기관이 인프라부터 앱까지 모든 보안 자체 책임 | **클라우드 공동책임모델** (인프라는 공급사 책임) |
| 벤더 종속성 | 구축 후 소스코드 확보로 커스터마이징 용이 | 공급자 API 및 데이터 스키마에 종속 위험 상존 |
| 장애 복구성 | 기관 자체 DR 센터 구축 및 복구 의존 | 공급사의 멀티 가용영역(AZ) 기반 고가용성 활용 |

- 제도적 정합성 및 대응 방향 : 공공부문 SaaS 이용 가이드라인은 상기 비교 지표를 바탕으로 법적 규제 준수(Compliance) 요건과 엔터프라이즈 운영 효율성을 균형 있게 확보하고, 선제적인 관리체계를 수립해야 함.

## Ⅳ. 공공부문 SaaS 이용 가이드라인의 주요 한계점 및 해결 방안

- 특정 SaaS 벤더의 독점적 데이터 구조로 인한 전환 시 데이터 락인 및 비용 급증 :
  - 한계점 : 특정 SaaS 벤더의 독점적 데이터 구조로 인해 타 서비스로 전환 시 데이터 손실 및 막대한 이전 비용 발생.
  - 해결 방안 : 계약서 내 표준 REST API 기반의 원천 데이터 추출 권한을 명문화하고 데이터 이관 비용 상한제 설정.
- 공급업체의 일방적 서비스 가격 인상 및 라이선스 변경 시 공공기관 협상력 부재 :
  - 한계점 : 공급업체의 일방적인 서비스 가격 인상 및 라이선스 정책 변경 시 공공기관의 협상력 부재.
  - 해결 방안 : 다년 계약 체결 시 연간 인상률 상한(예: 물가상승률 이내)을 제한하는 '공공 표준 계약 가이드라인' 강제.

## Ⅴ. 공공부문 SaaS 이용 가이드라인 정착 및 실효성 확보를 위한 기술사적 제언

- 계약 단계부터 표준 REST API 기반 데이터 출구 파이프라인(Exit Strategy) 의무화 : 기존의 계약 종료 직전 일회성 일괄 추출 한계를 극복하기 위해 일일 주기 표준 포맷 자동 증분 아카이빙 체계를 선제적으로 확립하여 엔터프라이즈 거버넌스를 완성해야 함.
- 다년 계약 체결 시 물가상승률 이내 가격 인상 상한을 두는 공공 표준 계약제 도입 : 기존의 수개월간 데이터 포맷 변환 수작업 한계를 극복하기 위해 자동 변환 매퍼를 통한 수시간 내 신규 SaaS 이관 체계를 선제적으로 확립하여 엔터프라이즈 거버넌스를 완성해야 함.
- 공공 특화 CSAP 인증 SaaS 식별 및 멀티 테넌트 데이터 암호화 격리 검증 : 기존의 벤더 갑작스러운 파산 시 전면 유실 한계를 극복하기 위해 자체 보관 스토리지 보유로 데이터 주권 완벽 수호 체계를 선제적으로 확립하여 엔터프라이즈 거버넌스를 완성해야 함.
