## 연관 키워드

- 공공데이터베이스 표준화, 표준단어, 표준도메인, 표준용어, 표준코드
- 메타데이터 관리시스템, 프로파일링, 데이터 가상화, ETL, DDL
- 레거시 DB, 예방적 품질관리, 정규화, 주키(PK), 외래키(FK)

## Ⅰ. 공공데이터베이스 표준화 관리 매뉴얼의 개요

- 핵심 요약 : 표준용어를 DB 설계부터 운영까지 적용해 데이터 품질을 사후 정비가 아닌 예방 방식으로 관리하는 지침.
- 개념 : 공공기관 정보시스템의 DB(Database) 구축과 운영 때 데이터 용어, 도메인, 코드를 표준에 맞추고 품질을 미리 관리하도록 정한 행정 지침이며, 핵심은 **표준용어** (표준단어와 표준도메인을 결합한 속성명)의 일관된 사용이다.
- 배경 및 필요성 : 기관마다 명명 방식이 달라 레거시 DB를 연계할 때마다 매핑 오류가 되풀이되고 연계 비용이 시스템 수만큼 쌓인다. 이 비용을 줄이려면 용어를 설계 단계에서 통제하고, 이관 전후 데이터 값을 프로파일링으로 검증해야 한다.
- 주요 목적 : 기관 간 데이터 연계 장애 해소, 데이터 중복 투자 방지, 범정부 데이터 활용의 기반이 되는 품질 높은 데이터 자산 확보.

## Ⅱ. 공공데이터베이스 표준화 관리 매뉴얼의 특징 및 장점

- 핵심 요약 : 표준단어 조합으로 명명을 통제하고 도메인으로 형식을 고정해, 데이터 해석 차이와 연계 오류를 줄이는 예방형 관리.

1. 표준용어 조합 : **표준단어** (업무상 쓰는 최소 의미 단위)와 **표준도메인** (데이터 타입, 자릿수, 단위를 정한 속성 형식)을 결합 → 컬럼명과 속성명이 기관 간에 같은 뜻으로 읽혀 연계 오류 감소.
2. 도메인 기반 형식 통제 : 도메인에 자릿수와 제약조건을 정의 → 값 형식 오류를 설계 단계에서 차단.
3. 표준코드 우선 적용 : **표준코드** (범정부 행정표준코드, 법정동 코드 등)를 최우선 사용 → 기관별 코드 불일치 감소.
4. 생명주기별 진단 : 계획부터 운영까지 단계마다 진단 → 운영 후 대규모 정제 비용 감소.

## Ⅲ. 공공데이터베이스 표준화 관리 매뉴얼의 구조 (흐름)

- 핵심 요약 : 표준용어가 명명 규칙으로 도출되는 축과 생명주기별 진단이 결합된 이중 구조.
- 표준용어 도출 : 표준단어와 표준도메인을 합성해 표준용어를 만들고, 이를 물리 컬럼명으로 대응시키는 규칙.

```text
[ 표준단어 ] 고객 + 식별
      ↓
[ 표준도메인 ] 번호 (VARCHAR2 20)
      ↓
[ 표준용어 ] 고객식별번호
      ↓
[ 물리 컬럼명 ] CUST_ID_NO
```

- 생명주기 진단 : 단계별로 점검 영역을 배치하여 설계 오류가 이관과 운영으로 넘어가지 않도록 하는 흐름.

```text
[ 1 계획·발주 ] 품질 요구사항 명시
      ↓
[ 2 분석·설계 ] 표준 준수, 정규화 검증
      ↓
[ 3 개발·이행 ] DDL 배포, 이관 데이터 정제
      ↓
[ 4 시험·전환 ] 업무 무결성 규칙 검증
      ↓
[ 5 운영·유지 ] 메타 등록, 상시 품질 모니터링
```

## Ⅳ. 공공데이터베이스 표준화 관리 방식의 비교

- 핵심 요약 : 사후 점검형 관리에서 설계 단계 강제와 전수 자동 진단을 쓰는 예방형 관리로 전환하는 것이 본 매뉴얼의 방향.

| 비교 축 | 사후 점검형 관리 | 예방형 관리 (본 매뉴얼) |
| --- | --- | --- |
| 점검 시점 | 시스템 오픈 후 정기 점검 | 발주, 설계, 이행 단계마다 점검 |
| 점검 방식 | 샘플링 기반 수작업 SQL 조회 | 프로파일링 도구를 통한 전수 자동 검사 |
| 표준 반영 | 운영 중 사후 정비 | 설계 단계에서 표준용어와 도메인 강제 |
| 형상 관리 | 모델과 물리 DB가 분리되어 괴리 발생 | 모델, DDL, 메타데이터를 단일 파이프라인으로 관리 |

## Ⅴ. 공공데이터베이스 표준화 관리 매뉴얼의 한계와 방안

- 핵심 요약 : 레거시 전환 부담, 임의 DDL로 인한 형상 불일치, 복합 도메인 용어의 자의적 해석을 단계적 이관과 배포 통제, 표준 변경 절차로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 레거시 비표준 컬럼 일괄 전환 부담 | 줄임말과 일련번호 컬럼명 때문에 배치와 쿼리를 전면 수정해야 함 | 데이터 가상화 계층으로 논리적 표준 뷰를 먼저 제공하고, 재구축 때 ETL로 단계적 이관 | 표준 뷰 적용 비율 |
| 임의 DDL 반영에 따른 모델-DB 불일치 | 개발 편의를 위한 직접 DDL 반영 → 모델과 물리 스키마 괴리 | CI/CD 파이프라인에 메타데이터 관리시스템 API를 연동하여 승인 통과 시에만 운영 배포 | 모델-DB 불일치 건수 |
| 복합 행정 도메인 용어의 자의적 해석 | 공통표준단어 조합으로 표현하기 어려워 기관별 해석이 갈림 | 공통표준 변경 요청 절차를 정례화하고, 기관 용어와 공통 표준 사이의 유의어 매핑 관리 | 표준 변경 요청 처리 기간 |

## Ⅵ. 공공데이터베이스 표준화 관리에 대한 기술사적 제언

- 핵심 요약 : 품질을 사후에 치유하지 않도록 설계, 배포, 운영을 하나의 관리 체계로 묶는 예방적 거버넌스 구축.

1. 설계 단계의 통제 : 사업 발주 때 데이터 표준과 메타데이터 등록을 요구 사항으로 명시하고, 설계 검토에서 표준 준수 여부를 판정하는 방향이 필요하다.
2. 배포 파이프라인의 단일화 : 모델, DDL, 메타데이터를 하나의 형상 파이프라인에서 관리하여 설계 문서와 운영 DB가 어긋나지 않도록 하는 것이 적절하다.
3. 상시 진단 체계의 전환 : 연 1회 점검이나 샘플 기반 수작업 검사에서 벗어나, 프로파일링을 활용한 상시 자동 진단으로 옮겨 가야 한다.

## Ⅶ. 결론

- 핵심 요약 : 공공DB 표준화는 용어 통일을 넘어 설계 단계부터 데이터 품질을 강제하는 예방형 관리 체계임.
- 시사점 : 표준은 문서로 남는 규칙이 아니라 배포 파이프라인에서 실행되는 통제일 때 연계 비용을 실질적으로 줄일 수 있다.
