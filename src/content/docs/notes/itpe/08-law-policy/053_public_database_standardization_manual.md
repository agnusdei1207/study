## 30초 인출

- 본질: **공공데이터베이스 표준화 관리 매뉴얼** 은 공공기관이 정보시스템을 구축·운영할 때 데이터의 상호운용성, 일관성 및 품질을 확보하기 위해 행정안전부와 NIA가 고시·배포한 데이터 표준 관리 실무 가이드라인
- 메커니즘: 표준단어와 표준도메인을 합성하여 표준용어를 제정하고, 사업 계획부터 운영까지 4대 진단영역(표준, 구조, 값, 관리체계)의 9개 진단항목을 바탕으로 단계별 예방적 품질관리 집행
- 통찰: 범정부 공통표준 준수와 기관별 특화 업무 도메인 간의 불일치로 레거시 DB 매핑 오류가 빈발하므로 메타데이터 관리시스템(MDS) 기반 자동 동기화와 데이터 이관 전후 프로파일링(Profiling) 검증 파이프라인 결합 필수

<details><summary>핵심 용어</summary>

- **공공데이터 표준화** : 공공기관이 구축하는 DB의 데이터 형식, 명칭, 도메인 및 코드를 통일하여 연계·공동활용을 가능하게 하는 표준화 활동.
- **표준용어** : 공공DB의 테이블 컬럼명 등에 사용되는 표준 명칭으로, 의미를 가진 '표준단어'와 데이터 형식인 '표준도메인'의 합성어.
- **표준도메인** : 데이터 컬럼에 허용되는 물리적 데이터 타입, 길이 및 허용 값의 논리적 범위를 규정한 기준.
- **예방적 품질관리** : 사후 데이터 정제가 아닌 정보시스템 개발 생명주기(기획-분석-설계-개발-운영) 전 단계에 걸쳐 품질 요건을 선제 반영·진단하는 기법.
- **메타데이터 관리시스템 (MDS)** : 데이터베이스의 테이블, 컬럼, 코드, 도메인 정보를 중앙에서 등록·통제·공시하는 표준 저장소.
- **데이터 프로파일링 (Data Profiling)** : 원천 데이터의 패턴, 중복률, 결측치, 무결성 규칙 위반 여부를 통계적으로 전수 분석하는 작업.

</details>

## 2~4교시 예상문제 (25점)

> 공공데이터의 상호운용성 및 품질 확보를 위한 「공공데이터베이스 표준화 관리 매뉴얼」의 표준화 핵심 구성요소를 설명하고, 시스템 구축 단계별 '예방적 품질관리 활동'과 '4개 진단영역 및 9개 진단항목'을 제시한 후, 레거시 DB 표준화 전환 및 운영 방안을 논하시오. (기출·제132회 4교시 2번 변형·25점)

## 2~4교시 25점 답안

## Ⅰ. 공공데이터베이스 표준화 관리 매뉴얼의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **공공데이터베이스 표준화 관리 매뉴얼** 은 공공기관의 정보시스템 DB 구축·운영 시 데이터 용어, 도메인, 코드의 표준 준수와 예방적 품질관리를 위해 행정안전부 고시를 구체화한 행정 지침 |
| 목적 | 기관 간 데이터 연계·공유 장애 해소, 데이터 중복 투자 방지 및 범정부 데이터 기반 행정 활성화를 위한 고품질 데이터 자산 구축 |

## Ⅱ. 공공데이터베이스 표준화 핵심 구성요소 및 특징

| 구분 | 표준화 핵심 요소 | 세부 특징 및 공학적 합성 규칙 |
|---|---|---|
| **표준단어** | 업무상 사용하는 최소 의미 단위 | 단어의 한글명, 영문 약어명(대문자), 영문 전체명 정의 및 동음이의어·이음동의어 정비 |
| **표준도메인** | 속성의 물리적 형식과 허용 범위 | 데이터 타입(VARCHAR2, NUMBER 등), 자릿수, 단위(원, %, 건) 및 제약조건 규정 |
| **표준용어** | 표준단어 + 표준도메인 결합 | 단어 조합의 끝에 반드시 도메인 단어를 부착하여 엔티티 속성명 및 DB 컬럼명으로 명명 |
| **표준코드** | 공통·행정 표준코드 준수 | 범정부 행정표준코드(법정동, 기관코드 등)를 최우선 적용하고 기관 특화 코드의 관리 번호화 |
| **메타데이터** | DB 구조 및 스키마 설명 정보 | 공공데이터 포털 및 범정부 메타데이터 관리시스템(공공데이터 메타)에 최신 스키마 등록 |

## Ⅲ. 예방적 품질관리 4대 진단영역 및 시스템 구축 프로세스

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ [ 공공DB 생명주기별 예방적 품질관리 및 4대 영역 진단 파이프라인 ]           │
└─────────────────────────────────────────────────────────────────────────────┘
  [ 1. 계획/발주 단계 ] ── RFP에 데이터 표준·품질 요구사항 및 메타데이터 등록 의무 명시
                 │
                 ▼
  [ 2. 분석/설계 단계 ] ── 개념·논리·물리 ERD 모델링
                 │      ├── [영역 1: 데이터 표준] ── 표준단어/도메인/용어 사전 확정
                 │      └── [영역 2: 데이터 구조] ── 정규화(3NF), 물리 명명규칙 검증
                 ▼
  [ 3. 개발/이행 단계 ] ── DDL 스크립트 배포 및 기존 레거시 데이터 이관(ETL)
                 │      └── [영역 3: 데이터 값]   ── 이관 데이터 정제 및 프로파일링
                 ▼
  [ 4. 시험/전환 단계 ] ── 품질 진단 도구를 통한 비즈니스 무결성 룰 검증
                 │
                 ▼
  [ 5. 운영/유지 단계 ] ── 범정부 메타 등록 및 상시 품질 모니터링
                        └── [영역 4: 데이터 관리체계] ── 품질관리 전담 조직 및 지침
```

```text
[ 표준용어 도출 메커니즘 ]
[표준단어: 고객] + [표준단어: 식별] + [표준도메인: 번호(VARCHAR2 20)] ──> [표준용어: 고객식별번호]
컬럼 물리명 매핑: CUST + ID + NO ──> CUST_ID_NO (영문 약어 합성)
```

| 생명주기 단계 | 주요 품질관리 활동 | 핵심 산출물 |
|---|---|---|
| **계획·발주** | 품질관리 목표치 수립, 사업 예산 반영 | 제안요청서(RFP), 사업수행계획서 |
| **분석·설계** | 표준사전 정의, 논리/물리 데이터 모델링 | 표준단어·용어·도메인 사전, ERD 다이어그램 |
| **개발·이행** | ETL 매핑 정의, 데이터 클렌징(Cleansing) | 데이터 이관 계획서, 정제 규칙서, DDL 스크립트 |
| **시험·운영** | 메타데이터 최신화, 정기 프로파일링 수행 | 데이터 품질 진단 보고서, 메타데이터 등록부 |

## Ⅳ. 4대 진단영역 및 9대 진단항목 상세 비교

| 진단영역 | 세부 진단항목 (9대) | 중점 점검 내용 및 기준 |
|---|---|---|
| **1. 데이터 표준** | 1.1 데이터 표준화 및 상위표준 준수 | 범정부 공통표준 준수율, 기관 표준사전 제정 및 최신화 여부 |
| | 1.2 데이터 표준 관리 | 표준 승인·변경 절차 준수, 표준 미준수 컬럼의 식별 및 예외 승인 |
| **2. 데이터 구조** | 2.1 데이터 구조 설계 | 개념·논리·물리 모델의 완전성, 식별자 정의 및 주키(PK)/외래키(FK) 설계 |
| | 2.2 데이터 구조 검증 | 모델-DB 물리 스키마 간 일치성(Reverse Engineering 대조) 검증 |
| | 2.3 데이터 구조 관리 | 모델 형상관리 체계, 구조 변경 시 영향도 분석 수행 여부 |
| **3. 데이터 값** | 3.1 데이터 값 검증 | 유효값 범위, 날짜 형식 오류, NULL 허용 컬럼 무결성 등 오류율 측정 |
| | 3.2 이관 데이터 값 검증 | 레거시 데이터 마이그레이션 시 손실·왜곡 여부 및 건수 대조 |
| **4. 데이터 관리체계**| 4.1 데이터 품질관리 체계 | 품질관리 책임자(DQC) 지정, 전사 품질관리 가이드라인 수립 여부 |
| | 4.2 데이터 개방 및 메타데이터 관리 | 공공데이터 포털 메타 연계 주기, 데이터 개방 계획 준수도 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 수십 년간 누적된 레거시 시스템의 비표준 컬럼명(줄임말, 일련번호 필드)으로 인한 일괄 표준 전환 시 기간계 배치·쿼리 전면 수정 부담 | 데이터 가상화(Data Virtualization) 계층을 도입하여 물리 DB 수정 전 논리적 표준 뷰(View)를 우선 제공하고, 차세대 재구축 시 단계적 ETL 이관 |
| 개발 편의를 위한 개발자의 임의 테이블/컬럼 추가 및 DDL 직접 반영으로 인한 모델-DB 스키마 불일치 | CI/CD 배포 파이프라인 상에 메타데이터 관리시스템(MDS) API를 연동하여 DDL 변경 승인 검증 통과 시에만 운영 DB 배포가 실행되도록 통제 |
| 공통표준단어의 조합만으로 표현하기 어려운 복합 행정 업무 도메인의 용어 정의 한계 및 자의적 해석 | 행정안전부 공통표준 변경 요청 프로세스를 정례화하고, 기관 표준 용어와 공통 표준 간의 1:N 유의어 매핑 온톨로지 구축 |

## Ⅵ. 제언

데이터 품질의 사후 치유 한계를 극복하기 위하여 모델-DB 자동 동기화 게이트웨이를 구축하고 DDL 배포와 메타데이터 관리를 단일 파이프라인으로 결합하는 예방적 거버넌스 수립.

```text
[ 데이터 아키텍트 ERD 모델링 ]
                 │
                 ▼
[ 메타데이터 관리시스템 (MDS) 검증 ]
    ├── Step 1: 표준용어 사전(단어+도메인) 자동 구문 분석
    ├── Step 2: PK/FK 무결성 및 인덱스 누락 정적 검사
    └── Step 3: 공통표준 준수율 100% 검증
                 │
                 ▼ (검증 승인 완료)
[ DDL 자동 생성 및 형상관리(Git) 커밋 ]
                 │
                 ▼
[ CI/CD 파이프라인 ──> 운영 DB 자동 배포 & 공공데이터 포털 메타 실시간 푸시 ]
```

| 구분 | 사후 품질 진단 및 정제 | 제언: CI/CD 연계 예방적 품질관리 |
|---|---|---|
| **표준화 시점** | 시스템 오픈 후 연 1회 진단 | DDL 배포 전 모델링 및 커밋 단계 강제 |
| **품질 점검** | 샘플링 기반 수기 SQL 쿼리 조회 | 프로파일링 도구를 통한 전수 데이터 자동 검사 |
| **구조 일치성** | 모델과 물리 DB의 형상 분리(괴리) | Git-DDL-MDS 단일 형상 파이프라인 동기화 |
| **관리 주체** | 소수 데이터 관리자의 수작업 | 개발팀 전체가 참여하는 자동화된 린팅(Linting) |
