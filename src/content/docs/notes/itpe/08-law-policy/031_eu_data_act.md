## 30초 인출

- 본질: **EU Data Act** 는 커넥티드 기기(IoT)와 관련 서비스에서 생성되는 데이터에 대해 사용자의 공정한 접근·공유 권리를 보장하고 클라우드 서비스 전환 장벽을 해소하기 위한 유럽연합의 법률
- 메커니즘: 데이터 보유자가 보유한 기기 데이터를 사용자에게 실시간 무상 제공하도록 강제하고 제3자 전송권을 보장하며, 클라우드 전환 비용을 단계적으로 폐지(2027년 0원)
- 통찰: 기기 데이터 개방에 따른 제조업체의 영업비밀 침해 우려와 복잡한 클라우드 데이터 이관 기술 부채가 상존하므로 암호화 기반 영업비밀 보호 조약과 오픈 API 표준 인터페이스 구축 필수

<details><summary>핵심 용어</summary>

- **EU Data Act (Regulation (EU) 2023/2854)** : 비개인 데이터와 개인 데이터를 포괄하여 데이터 경제 활성화를 도모하는 유럽연합의 데이터 통합 규정.
- **커넥티드 제품 (Connected Product)** : 사용 및 환경 데이터를 수집·생성하고 네트워크를 통해 전송할 수 있는 스마트 기기, 커넥티드 카, 산업용 로봇 등.
- **데이터 보유자 (Data Holder)** : 커넥티드 제품이나 서비스에서 생성된 데이터에 합법적으로 접근하고 통제할 수 있는 권한을 가진 제조사 및 기업.
- **전환 비용 폐지 (Switching Charges)** : 고객이 한 클라우드에서 다른 클라우드로 마이그레이션할 때 부과되던 데이터 이그레스(Egress) 및 전환 수수료를 2027년까지 완전 폐지하는 조치.
- **상호운용성 표준 (Interoperability Standards)** : 서로 다른 데이터 스페이스 및 클라우드 플랫폼 간 원활한 데이터 이전을 위해 유럽 표준화 기구에 의해 규격화되는 기술 표준.

</details>

## 2~4교시 25점 답안

## Ⅰ. EU Data Act의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **EU Data Act** 는 스마트 기기 등 커넥티드 제품에서 생성되는 데이터에 대한 이용자의 접근·공유 권한을 법제화하고 클라우드 벤더 종속을 해소하는 유럽연합 규정 |
| 목적 | 제조사의 데이터 독점 해소, 애프터마켓(수리·유지보수) 경쟁 촉진 및 공정하고 개방적인 데이터 시장 생태계 조성 |

## Ⅱ. EU Data Act 핵심 규율 영역 및 제도적 특징

| 규율 영역 | 법적 요구 내용 | 상세 특징 및 기술적 적용 요건 |
|---|---|---|
| **기기 데이터 접근권** | 사용자 무상 접근 보장 | 커넥티드 제품 사용자(B2B, B2C)에게 생성 데이터에 대한 **실시간, 무상, 직접 접근** 허용 |
| **제3자 데이터 공유** | 독립 수리업체 등 공유 | 사용자가 지정한 제3자(애프터마켓 서비스)에게 원본 품질 그대로 데이터 제공 의무화 |
| **영업비밀 보호 (특징)** | **비밀 유출 방지 장치** | 기기 데이터 공유 시 기술적 보호조치(NDA, DRM) 요구 가능, 영업비밀 침해 우려 시 거부 |
| **클라우드 전환 촉진** | **락인(Lock-in) 해소 (특징)**| 클라우드 사업자 교체 시 30일 이내 이전 완료 의무화 및 **전환 수수료 2027년 완전 폐지** |
| **B2G 긴급 데이터 제공** | 공공 비상사태 대응 | 홍수, 전염병 등 공공 비상사태 시 정부기관의 긴급 데이터 제공 요청에 기업 협조 의무화 |

## Ⅲ. 커넥티드 제품 데이터 공유 및 클라우드 전환 E2E 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ EU Data Act 커넥티드 제품 데이터 공유 및 클라우드 전환 파이프라인 ]  │
└────────────────────────────────────────────────────────────────────────┘

 [ 1. 커넥티드 제품 데이터 접근 및 공유 (B2B / B2C) ]
   [ 스마트 기기 / 산업 장비 ] ──(센서 데이터 생성: 시동, 연비, 결함 로그)
                 │
                 ▼
   [ 데이터 보유자 (제조사 플랫폼) ]
      ├── 기획 단계부터 데이터 직접 다운로드 포털 구현 (Design by Default)
      │      │ (사용자 직접 열람 및 다운로드: 무상)
      │      ▼
      │   [ 제품 소유자 / 이용자 ]
      │      │
      │      ▼ (이용자의 전송 지시)
      └── [ 제3자 서비스 업체 (독립 정비소, 보험사 등) ]
             - 원본과 동일한 품질의 기계 판독형 API 전송 (REST / JSON)
             - NDA 체결 및 경쟁사 복제 제품 개발 목적 활용 원천 금지

─────────────────────────────────────────────────────────────────────────

 [ 2. 클라우드 서비스 전환 (Cloud Switching) ]
   [ 고객 (전환 요청) ] ──> [ 기존 CSP A ] ──(30일 전환 절차 가동)
                                  │
                                  ▼ (데이터 및 디지털 자산 무손실 추출)
                            [ 신규 CSP B / 온프레미스 ]
                                  │
                                  ▼ (전환 비용 단계적 폐지)
                            - 2025~2026년: 실비 한도 감액 부과
                            - 2027년 1월부터: 전환 수수료 0원 (완전 무료화)
```

| 프로세스 단계 | 주요 수행 업무 | 핵심 기술 및 엔지니어링 요건 |
|---|---|---|
| **기기 데이터 설계** | 제품 설계 시점부터 사용자 데이터 추출 인터페이스 반영 | 로컬 인터페이스(USB, BLE) 및 클라우드 텔레메트리 API |
| **제3자 공유 통제** | 데이터 전송 계약서 내 영업비밀 보호 및 목적 제한 명시 | 스마트 컨트랙트 기반 접근 권한 제어, OAuth 2.0 |
| **클라우드 전환 통지** | 전환 요청 접수 시 최대 30일의 의무 이행 기간 개시 | 표준화된 데이터 반출 툴킷 및 스키마 매핑 문서 제공 |
| **데이터 이그레스** | 가상머신, DB, 스토리지 데이터를 범용 포맷으로 이전 | 고속 네트워크 터널링, 대역폭 차별 금지 |
| **완전 삭제 입증** | 이전 완료 후 기존 CSP 서버 내 고객 잔여 데이터 파기 | 데이터 완전 삭제 확인서 및 암호화 파쇄 증명서 |

## Ⅳ. EU GDPR(개인정보)과 EU Data Act(산업/비개인 데이터) 비교

| 비교 항목 | EU GDPR (일반 데이터보호법) | EU Data Act (데이터법) |
|---|---|---|
| **주요 대상** | **개인정보 (Personal Data)** 에 한정 | **비개인 데이터(기계/센서 데이터) + 개인 데이터 전반** |
| **핵심 목적** | 정보주체의 기본권 보호 및 프라이버시 수호 | 데이터 재사용 활성화 및 공정한 산업 데이터 경쟁 촉진 |
| **접근 권한자** | 정보주체 본인 (자연인) | **제품의 소유자, 임차인, 사용자 (자연인 및 법인)** |
| **데이터 전송** | 개인정보 이동권(Portability) | 커넥티드 기기 데이터 직접 접근권 및 제3자 전송권 |
| **인프라 규제** | 개인정보 안전성 확보조치 | **클라우드 서비스 전환 촉진 및 전환 수수료 폐지** |
| **상호 관계** | 프라이버시 침해 시 GDPR 우선 적용 | GDPR을 보완하여 산업용 기계 데이터의 활용권 보장 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 제조사의 핵심 지식재산권(IP) 및 영업비밀이 포함된 센서 로우 데이터가 경쟁사로 유출될 위험 | 원시 신호에서 영업비밀을 마스킹하는 변환 필터를 거치고 엄격한 비밀유지협약(NDA) 위반 시 징벌적 배상 조항 강제 |
| 클라우드 사업자마다 데이터 스토리지 및 컨테이너 규격이 달라 실질적인 30일 이내 완전 무손실 전환 기술적 한계 | 오픈스택, OCI(Open Container Initiative) 기반 표준 클라우드 상호운용성 표준 프레임워크 준수 의무화 |

## Ⅵ. 제언

EU Data Act 컴플라이언스를 충족하고 글로벌 스마트 기기 수출 경쟁력을 확보하기 위해 IoT 제품 설계 시 표준 데이터 접근 API와 C2PA 디지털 서명을 내재화하는 아키텍처 구축 필요.

```text
[ 스마트 IoT 기기 (차량, 로봇, 가전) ]
             │
             ├──> [ Layer 1: 로컬 사용자 직접 추출 포트 (BLE / OBD-II) ]
             └──> [ Layer 2: 클라우드 표준 텔레메트리 파이프라인 ]
                        │
                        ▼
[ EU 표준 오픈 데이터 스페이스 API 게이트웨이 ]
   ├── 고객 인증 및 제3자 정비업체 RBAC 인가
   ├── 영업비밀 보호 자동 필터링 (알고리즘 내부 파라미터 은닉)
   └── C2PA 기반 데이터 무결성 및 원천 생성자 디지털 서명 주입
                        │
                        ▼
[ 사용자 앱 및 독립 서비스 업체 실시간 무상 데이터 공급 ]
```

| 구분 | 기존 폐쇄형 제조사 아키텍처 | 제언: EU Data Act 준수 개방형 아키텍처 |
|---|---|---|
| **데이터 접근성** | 제조사 내부 정비망만 데이터 독점 | 사용자가 공인 API 통해 실시간 무상 다운로드 |
| **제3자 제공** | 경쟁사 차단을 위해 서드파티 접근 불허 | 법정 요구에 따른 제3자 정비업체 즉각 개방 |
| **클라우드 락인** | 자체 폐쇄 포맷으로 이관 불가능 | 표준 JSON/Parquet 포맷 및 컨테이너 이관 보장 |
| **수출 경쟁력** | EU 시장 진출 시 대규모 규제 위반 | EU 규정 선제 충족으로 글로벌 신뢰도 제고 |
