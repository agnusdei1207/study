## 연관 키워드

- EU Data Act(유럽연합 데이터법), 커넥티드 제품(Connected Product), 데이터 보유자(Data Holder), 데이터 경제
- 제3자 전송권, 애프터마켓(After-market), 클라우드 전환(Cloud Switching), 락인(Lock-in)
- 영업비밀, 디지털 권리 관리(DRM, Digital Rights Management), 상호운용성, GDPR(General Data Protection Regulation)

## Ⅰ. EU Data Act의 개요

- 핵심 요약 : 커넥티드 제품이 만든 데이터에 대한 이용자의 접근·공유 권리를 법으로 보장하고, 클라우드 사업자 교체의 장벽을 낮추는 유럽연합 규정.
- 개념 : 스마트 기기와 산업 장비가 생성하는 데이터에 대해 이용자가 접근하고 제3자에게 전송할 수 있도록 정한 **EU Data Act** (유럽연합 데이터법).
- 배경 및 필요성 : 기기가 만든 방대한 데이터가 소수 제조사에 묶여 있어 수리·보험 등 애프터마켓 경쟁이 제한되었다. 이에 기기 데이터를 이용자와 제3자가 쓸 수 있도록 개방해 공정한 **데이터 경제**를 만들 필요가 생겼다.
- 주요 목적 : 제조사의 데이터 독점을 줄이고, 애프터마켓 경쟁과 클라우드 전환을 촉진해 개방적인 데이터 시장을 조성하는 데 있다.

## Ⅱ. EU Data Act의 특징 및 장점

- 핵심 요약 : 데이터 접근권, 제3자 전송권, 영업비밀 보호, 전환 장벽 제거가 한 법으로 묶여 공정한 경쟁과 보호를 함께 확보하는 구조.

1. **기기 데이터 접근권** (데이터 보유자가 생성 데이터를 이용자에게 실시간·직접 제공) : 이용자가 자신의 기기 데이터를 직접 확보 → 정비와 보험 등 서비스 선택지 확대.
2. **제3자 전송권** (이용자가 지정한 제3자에게 원본 품질의 데이터를 전송) : 독립 정비업체가 같은 데이터로 서비스 → 애프터마켓 경쟁 촉진.
3. 영업비밀 보호 : **디지털 권리 관리** (DRM, Digital Rights Management) 같은 기술적 보호 조치와 비밀유지 계약을 요구할 수 있고, 영업비밀 침해 우려가 있으면 공유를 거부할 수 있음 → 제조사의 핵심 자산 보존.
4. **락인 해소** (Lock-in 해소, 클라우드 사업자 교체 시 이전 지원 의무화와 전환 수수료 폐지) : 다른 사업자로 옮기는 비용 감소 → 특정 사업자 종속 완화.

## Ⅲ. EU Data Act의 구조 (흐름)

- 핵심 요약 : 기기 데이터의 공유 흐름과 클라우드 전환 절차라는 두 경로를 한 규정이 다룸.

```text
[ 커넥티드 제품 (기기·장비) ]
      ↓ 센서 데이터 생성
[ 데이터 보유자 (제조사 플랫폼) ]
      ↓ 이용자 요청
[ 이용자 ] → [ 제3자 서비스 업체 ]
```

```text
[ 클라우드 전환 절차 ]
이용자가 전환 요청
      ↓
기존 사업자가 전환 절차 진행
      ↓
데이터와 디지털 자산 이전
      ↓
전환 수수료 단계적 폐지
```

- 전환 수수료는 2027년 1월부터 폐지되며, 그 이전에는 실비 수준으로 제한된다.
- 시행 시점은 2025년 9월 12일 이후 적용되는 규정으로, 사업자는 전환 절차 문서화를 준비해야 한다.

## Ⅳ. GDPR과 EU Data Act의 비교

- 핵심 요약 : GDPR이 개인 정보 자체를 보호하는 법이라면, EU Data Act는 기기가 만든 산업 데이터의 활용권을 보장하는 법이다.

| 비교 항목 | GDPR (General Data Protection Regulation) | EU Data Act |
| --- | --- | --- |
| 주요 대상 | 개인정보에 한정 | 기계·센서 데이터를 포함한 데이터 전반 |
| 핵심 목적 | 정보주체의 기본권과 프라이버시 보호 | 데이터 재사용 활성화와 공정한 산업 데이터 경쟁 |
| 접근 권한자 | 정보주체 본인 | 제품의 소유자·임차인·사용자 |
| 데이터 전송 | 개인정보 이동권 | 기기 데이터 접근권과 제3자 전송권 |
| 인프라 규제 | 개인정보 안전성 확보 조치 | 클라우드 전환 촉진과 전환 수수료 폐지 |

- 선택 기준 : 개인정보가 섞인 데이터는 GDPR이 우선하고, 비개인 기기 데이터는 Data Act의 접근·공유 규칙이 적용된다.

## Ⅴ. EU Data Act의 한계와 방안

- 핵심 요약 : 영업비밀 유출과 클라우드 간 호환성 부족을 기술적 마스킹과 개방형 표준으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 영업비밀 유출 위험 | 센서 원시 데이터에 핵심 지식재산이 포함되어 경쟁사로 유출될 가능성 | 원시 신호에서 영업비밀을 가리는 변환 필터 적용과 비밀유지 계약 체결 | 마스킹 적용률, 계약 위반 건수 |
| 클라우드 간 상호운용성 부족 | 사업자마다 데이터 저장 형식이 달라 완전한 무손실 전환이 어려움 | 개방형 표준 포맷과 공개 API 명세 준수 | 이전 성공률, 포맷 변환 손실률 |
| 서드파티 접근 지연 | 제조사 내부 정비망에 한정되어 제3자가 데이터를 얻기 어려움 | 기기 펌웨어 단계부터 표준 추출 API와 OAuth 2.0 인가 구현 | 제3자 요청 처리 기간 |

## Ⅵ. EU Data Act 대응을 위한 기술사적 제언

- 핵심 요약 : 설계 단계의 데이터 추출 구조와 영업비밀 통제를 함께 갖출 때 규정이 실효성을 얻음.

1. 제조 기업은 기기 펌웨어 설계 단계부터 표준 데이터 추출 API와 OAuth 2.0 기반 인가를 넣어 이용자와 제3자가 기기 데이터를 바로 받을 수 있도록 한다.
2. 데이터 관리 조직은 공유 전에 영업비밀을 가리는 마스킹 절차를 두고, 제3자 계약에 목적 제한과 감사 조항을 포함한다.
3. 클라우드를 이용하는 기업은 전환 절차를 점검 항목으로 문서화해, 사업자를 바꿀 때 데이터와 설정을 옮길 수 있는지 주기적으로 시험한다.

## Ⅶ. 결론

- 핵심 요약 : EU Data Act는 기기 데이터의 활용권과 클라우드 전환권을 보장해 데이터 경제의 경쟁 조건을 바꾸는 규정.
- 시사점 : 데이터 공유 의무는 영업비밀 보호와 함께 설계되어야 하며, 기업은 공유 기능과 보호 기능을 동시에 갖춰야 한다.
