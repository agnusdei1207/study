## 연관 키워드

- **웹 접근성**, **KWCAG 2.2**, **WCAG 2.2**, **POUR**
- **대체 텍스트**, **키보드 접근성**, **명도 대비**, **스크린리더**
- **자동 검사**, **수동 평가**, **장애 당사자 사용성 평가**

## Ⅰ. 웹 접근성의 개요

- 핵심 요약 : 장애 여부나 사용 환경에 관계없이 웹의 정보와 기능을 인식·조작·이해할 수 있도록 설계하는 품질 특성.
- 개념 : 시각·청각·운동·인지적 제약을 고려해 콘텐츠와 인터페이스의 이용 장벽을 제거하는 설계·개발·평가 활동.
- 배경 및 필요성 : 웹 서비스가 생활 필수 수단이 되면서 장애인·고령자 등의 정보 접근권 보장 필요.
- 목적 : 동등한 과업 수행, 정보 격차 완화, 이용성 및 법·표준 대응 수준 향상.

## Ⅱ. 웹 접근성의 특징 및 장점

- 핵심 요약 : **POUR 4대 원칙**을 구현 요소에 연결해 장애인뿐 아니라 다양한 기기·환경의 이용자 경험 개선.

1. **인식 가능(Perceivable)** : 이미지 대체 텍스트와 자막을 제공하여 감각 수단이 달라도 정보 획득 가능.
2. **운용 가능(Operable)** : 키보드 접근과 명확한 초점 표시로 마우스 사용이 어려운 이용자의 기능 수행 지원.
3. **이해 가능(Understandable)** : 예측 가능한 동작과 오류 안내로 입력 실수와 인지 부담 감소.
4. **견고성(Robust)** : 의미 있는 HTML과 보조기술 호환성을 확보해 브라우저·스크린리더 간 이용 가능성 향상.
5. **다중 평가** : 자동 검사에 수동 탐색·당사자 과업 평가를 더해 도구가 놓치는 실제 사용 장애 발견.

## Ⅲ. 웹 접근성의 구조와 평가 흐름

- 핵심 요약 : **POUR 원칙 → 구현 → 자동·수동 검사 → 당사자 과업 검증 → 개선**의 반복 과정.

```text
POUR 원칙
 ├─ 인식 가능 → 대체 텍스트·자막·명도 대비
 ├─ 운용 가능 → 키보드·초점·시간 조절
 ├─ 이해 가능 → 일관된 탐색·입력 오류 안내
 └─ 견고성   → 의미 있는 마크업·보조기술 호환성
```

- **시맨틱 HTML**을 먼저 사용하고, 기본 요소로 의미가 전달되지 않을 때 WAI-ARIA를 보완적으로 적용.
- 색상 대비와 타깃 크기 등 수치 기준은 적용하는 표준·성공 기준·적합 수준을 함께 확인.
- 자동 도구의 통과만으로 모든 이용자의 과업 완수를 입증할 수 없으므로 키보드·스크린리더·실사용 평가 병행.

```text
설계 기준 선정 → 컴포넌트 구현 → 자동 검사 → 수동 탐색·보조기술 시험
       ↑                                        ↓
       └──────── 장애 당사자 과업 평가·결함 수정 ────────┘
```

## Ⅳ. KWCAG 2.2와 WCAG 2.2의 비교

- 핵심 요약 : 국내 국가표준 **KWCAG 2.2**와 W3C **WCAG 2.2**는 같은 접근성 원칙을 공유하지만 적용 문맥과 세부 검사 기준을 확인해야 함.

| 비교 항목 | KWCAG 2.2 | WCAG 2.2 |
|---|---|---|
| 제정·관리 | 국내 국가표준 체계 | W3C 웹 접근성 권고 |
| 기반 | 국내 서비스·보조기술 환경을 고려한 검사 항목 | POUR 4대 원칙과 검증 가능한 성공 기준 |
| 활용 | 국내 평가·개발 기준 | 국제적 설계·적합성 평가 기준 |
| 실무 유의 | 최신 국내 표준·인증 기준 확인 | 목표 적합 수준(A/AA/AAA)과 해당 성공 기준 확인 |

- 국내의 법적 편의 제공 의무, 기술 표준, 품질인증은 같은 개념이 아니므로 대상 서비스별 적용 근거를 구분.

## Ⅴ. 웹 접근성의 한계와 방안

- 핵심 요약 : **동적 UI의 초점 소실**, **자동 검사의 사각지대**, **형식적 인증**을 컴포넌트 규칙과 실사용 평가로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 동적 화면의 초점 소실 | 경로·모달 변경 시 보조기술이 맥락을 잃음 | 제목·초점·상태 알림을 사용자 흐름에 맞게 관리 | 키보드 과업 성공률 |
| 자동 검사 한계 | 대체 텍스트의 적절성·논리적 초점은 자동 판정 곤란 | 수동 검사와 스크린리더 시험 병행 | 수동 결함 발견 건수 |
| 시각적 대비 부족 | 색상만으로 상태를 나타내면 구분 어려움 | 텍스트·아이콘을 함께 사용하고 명도 대비 점검 | 대비 실패 건수 |
| 일회성 평가 | 기능 변경 후 기존 인증 결과가 노후화 | 배포 전 회귀 검사와 정기 당사자 평가 | 재발 결함률 |

## Ⅵ. 웹 접근성에 대한 기술사적 제언

- 핵심 요약 : 접근성은 출시 직전 검사보다 **디자인 시스템·개발·운영 전 단계**에 품질 기준으로 내재화 필요.

1. 공통 컴포넌트에 키보드·초점·이름·역할·상태 규칙을 정의.
2. CI에서 자동 검사로 반복 결함을 차단하고 주요 사용자 여정은 수동으로 검증.
3. 장애 당사자와 함께 핵심 과업을 수행해 실제 이용 가능성을 측정.
4. 법적 요구, 국내 표준, 국제 표준, 품질인증의 적용 범위를 별도 기록.

## Ⅶ. 결론

- 핵심 요약 : **웹 접근성**은 POUR 원칙을 실제 과업 수행으로 검증할 때 의미가 있으며 자동 도구만으로 완료되지 않음.
- 시사점 : 보조기술 호환성과 장애 당사자 경험을 제품 품질의 지속적 지표로 관리 필요.
