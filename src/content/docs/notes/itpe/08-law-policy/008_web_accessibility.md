## Ⅰ. 웹 접근성(Web Accessibility)의 개요

- **개념** : 장애인, 고령자 등 정보 취약계층이 웹 사이트 이용 시 비장애인과 동등하게 정보를 인식하고 제어할 수 있도록 보장하는 기술적·법적 설계 지침.
- **제정 배경 및 필요성** : 디지털 서비스의 급속한 일상화 속에서 장애인, 고령자 등 디지털 취약계층의 정보 접근 격차가 심화됨에 따라, 법률상 모든 공공·민간 웹사이트가 신체적 조건에 구애받지 않고 평등하게 이용할 수 있도록 기술 표준 준수를 의무화함.
- **핵심 목적** : 디지털 정보 격차 해소, 보편적 사용자 경험(UX) 제공 및 법적 컴플라이언스 준수.

## Ⅱ. 웹 접근성(Web Accessibility)의 법제도 체계 및 핵심 메커니즘

**웹 접근성**(Web Accessibility)은 POUR 4대 원칙(인식의 용이성·운용의 용이성·이해의 용이성·견고성)을 준수하여 시맨틱 HTML5 및 WAI-ARIA 태그를 적용하고 스크린리더 및 키보드 단독 조작 지원 과정을 거쳐 상호 연동 및 단계별 법적·기술적 통제를 수행함.

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 웹 접근성 진단 및 엔드투엔드 품질인증 심사 파이프라인 ]             │
└────────────────────────────────────────────────────────────────────────┘

 [ 웹 서비스 기획/디자인 ] ── 명도 대비 검증, 건너뛰기 링크(Skip Navigation) 설계
           │
           ▼
 [ 프런트엔드 개발 단계 ] ── 시맨틱 마크업, WAI-ARIA 속성 및 키보드 이벤트 핸들러
           │
           ▼
 [ 1단계: 전문가 자동 평가 ] ── K-WAH, axe-core, Lighthouse 자동 진단 (신택스 오류 검출)
           │
           ▼
 [ 2단계: 전문가 수동 평가 ] ── 키보드 단독 조작, 화면 낭독기(NVDA/센스리더) 음성 검증
           │
           ▼
 [ 3단계: 사용자 체감 평가 ] ── 전맹·저시력·지체·뇌병변 장애 당사자 과업 수행(Task Test)
           │
           ▼
 [ 접근성 품질인증 심사 ] ──(합격 기준 충족)──> [ 품질인증 마크(WA) 획득 및 갱신 ]
```

- **1. 인식의 용이성 (Perceivable)** : 정보와 사용자 인터페이스 요소를 인지할 수 있도록 제공 - **대체 텍스트** : 비텍스트 콘텐츠 `alt` 속성 제공 **자막 제공** : 멀티미디어 동영상에 동기화된 자막/수어 **색상 독립성** : 명도 대비 4.5:1 이상 확보 (대형 3:1)
- **2. 운용의 용이성 (Operable)** : 인터페이스 구성 요소를 원활하게 조작 가능하도록 보장 - **키보드 접근성** : 모든 기능을 마우스 없이 탭 키로 접근 **초점 이동** : 논리적 초점 순서 및 가시적 초점 링 표시 **조작 시간** : 시간제한 연장 기능, 광과민성 발작 예방
- **3. 이해의 용이성 (Understandable)** : 콘텐츠와 인터페이스 작동 방식을 쉽게 이해하도록 설계 - **기본 언어 표기** : `html lang="ko"` 속성 명시 **예측 가능성** : 초점 획득 시 맥락 자동 변경(팝업) 금지 **입력 오류 방지** : 오류 위치 텍스트 안내 및 수정 기회
- **전문가 자동 심사** : HTML 문법 유효성, 대체 텍스트 누락, 명도 대비 자동 검사 - axe DevTools, Lighthouse, 자동 검사 리포트
- **전문가 수동 심사** : 키보드 트랩 탈출 여부, 포커스 순서, 프레임 제목 제공 - NVDA, 센스리더, VoiceOver, 수동 진단표

## Ⅲ. 웹 접근성(Web Accessibility)의 세부 규정 및 국내외 제도 비교 분석

| 비교 항목 | 한국형 KWCAG 2.2 | 국제 표준 W3C WCAG 2.2 |
|---|---|---|
| **제정 주체** | 과학기술정보통신부, 국립전파연구원 | W3C WAI (Web Accessibility Initiative) |
| **체계 구성** | 4대 원칙 기반 검사 항목 | 4대 원칙 13개 지침 86개 성공 기준 (Level A/AA/AAA) |
| **타깃 플랫폼** | 국내 행정·공공기관 및 민간 웹사이트 | 글로벌 웹, 모바일, 디지털 기기 전반 |
| **모바일 대응** | 모바일 터치 타깃 크기(9mm) 규정 준용 | 최소 타깃 크기 24x24 CSS 픽셀 등 구체적 명시 |
| **인증 연계** | 국내 공인 정보통신접근성 품질인증 심사 기준 | 글로벌 웹 접근성 소송 대응 및 적합성 평가 기준 |
| **포커스 통제** | 초점 이동 및 가시적 표시 요구 | 가시적 초점(Focus Appearance) 최소 영역 및 명도 공식화 |

- **제도적 정합성 및 대응 방향** : 웹 접근성은 상기 비교 지표를 바탕으로 법적 규제 준수(Compliance) 요건과 엔터프라이즈 운영 효율성을 균형 있게 확보하고, 선제적인 관리체계를 수립해야 함.

## Ⅳ. 웹 접근성(Web Accessibility)의 주요 한계점 및 해결 방안

- **동적 SPA(Single Page Application) 환경에서 라우팅 변경 시 포커스 소실** :
  - **한계점** : 리액트/뷰 기반 SPA 환경에서 라우팅 변경 시 스크린리더가 페이지 갱신을 인지하지 못하는 한계.
  - **해결 방안** : 라우터 이동 시 `aria-live="polite"` 알림 영역을 활용해 페이지 타이틀을 음성 출력하고 포커스를 메인 콘텐츠로 자동 이동.
- **자동화 진단 도구 통과 위주의 형식적 인증 획득과 실제 과업 완수율 저하** :
  - **한계점** : 자동화 검사 통과 위주의 형식적 인증 획득으로 인해 실제 장애인의 과업 완수율 저하.
  - **해결 방안** : CI/CD 파이프라인 내 Cypress 기반 키보드 E2E 테스트 자동화 및 장애인 사용자 패널 상시 검증 체계 구축.

## Ⅴ. 웹 접근성(Web Accessibility) 정착 및 실효성 확보를 위한 기술사적 제언

- **디자인 시스템 단계부터 접근성 토큰을 내재화(Design-System-in-Accessibility)** : 기존의 개발 완료 후 출시 직전 수동 진단 한계를 극복하기 위해 디자인 및 코드 커밋 시 실시간 자동 검증 체계를 선제적으로 확립하여 엔터프라이즈 거버넌스를 완성해야 함.
- **CI/CD 파이프라인 내 키보드 탐색 및 스크린리더 E2E 자동 테스트 구축** : 기존의 결함 발견 시 전체 DOM 재구조화로 고비용 한계를 극복하기 위해 컴포넌트 단위 사전 차단으로 유지보수 최소화 체계를 선제적으로 확립하여 엔터프라이즈 거버넌스를 완성해야 함.
- **WAI-ARIA 가이드라인 준수 및 장애 당사자 참여 상시 사용성 검증 정례화** : 기존의 렌더링 후 상태 변화 추적 곤란 한계를 극복하기 위해 Storybook 상태별 ARIA 실시간 유효성 평가 체계를 선제적으로 확립하여 엔터프라이즈 거버넌스를 완성해야 함.
