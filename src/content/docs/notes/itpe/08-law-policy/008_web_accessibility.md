<details><summary>핵심 용어</summary>

- **WCAG**: Web Content Accessibility Guidelines, W3C의 웹 콘텐츠 접근성 지침.
- **웹 접근성**: 다양한 이용자가 웹 콘텐츠와 기능을 인식·조작할 수 있게 하는 설계·구현 원칙.
- **W3C**: World Wide Web Consortium, 웹 표준과 지침을 개발하는 국제 협의체.
- **KWCAG**: Korean Web Content Accessibility Guidelines, 한국형 웹 콘텐츠 접근성 지침.
- **POUR**: 인식 가능(Perceivable)·운용 가능(Operable)·이해 가능(Understandable)·견고성(Robust)의 네 원칙.
- **대체 텍스트**: 이미지 등 비문자 콘텐츠의 목적·정보를 문자로 전달하는 설명.
- **정보통신접근성 품질인증**: 지능정보화 기본법에 근거해 접근성 기준을 평가·인증하는 제도.

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **웹 접근성**은 다양한 이용자가 웹 콘텐츠와 기능을 인식·조작할 수 있게 하는 설계·구현 원칙 |
| 목적 | 정보 접근과 온라인 서비스 이용에서 배제 감소 |

### Ⅱ. 네 가지 웹 접근성 원칙(POUR: Perceivable, Operable, Understandable, Robust)

| 원칙 | 구현 예 |
|---|---|
| 인식 가능 | 이미지 대체 텍스트, 자막·텍스트 대안, 충분한 대비 |
| 운용 가능 | 키보드 조작, 초점 표시, 시간·움직임 제어 |
| 이해 가능 | 명확한 문장·레이블, 일관된 탐색, 오류 안내 |
| 견고성 | 표준 마크업과 보조기술 호환성 검증 |

### Ⅲ. 제언

제언: 자동 검사와 장애 당사자·보조기술을 활용한 수동 사용성 검증을 함께 운영.

## 2~4교시 25점 답안

## Ⅰ. 웹 접근성의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **웹 접근성**은 다양한 이용자가 웹 콘텐츠와 기능을 인식·조작할 수 있게 하는 설계·구현 원칙 |
| 목적 | 정보 접근과 온라인 서비스 이용에서 배제 감소 |

### 이용자 장벽과 대응

시각·청각·지체·인지 등 이용 조건이 달라도 웹 정보를 인식하고 기능을 조작할 수 있도록 하는 것이 웹 접근성의 목적. 국내 법적 의무는 장애인차별금지법 등 적용 법령과 대상 행위자·서비스 범위에 따라 판단.

| 사용자 장벽 | 접근성 대응 |
|---|---|
| 이미지·시각 단서만으로 정보 제공 | 의미 있는 대체 텍스트와 텍스트 대안 |
| 마우스 사용을 전제한 조작 | 키보드 접근·초점 순서와 표시 |
| 영상에 자막·설명 부재 | 자막·수어·화면해설 등 콘텐츠에 맞는 대안 |
| 복잡한 입력·오류 메시지 | 명확한 레이블·오류 위치와 수정 방법 안내 |

## Ⅱ. POUR 원칙별 설계·검증

| 원칙 | 설계 기준 | 검증 방법 |
|---|---|---|
| 인식 가능 | 텍스트 대안, 자막, 구조화·대비 | 스크린리더·확대·색상 의존성 점검 |
| 운용 가능 | 키보드 조작, 포커스, 시간 제어 | 키보드만으로 전체 흐름 수행 |
| 이해 가능 | 읽기 쉬운 안내, 예측 가능한 동작 | 사용자 과업·오류 복구 점검 |
| 견고성 | 표준 의미구조·호환 마크업 | 브라우저·보조기술 조합 시험 |

## Ⅲ. 법·표준·인증 관계

| 층위 | 역할 | 주의점 |
|---|---|---|
| 장애인차별금지법·시행령 | 정보통신·의사소통에서의 정당한 편의 제공 의무와 범위 규정 | 적용 대상과 단계별 범위는 현행 법령 확인 |
| 지능정보화 기본법 | 정보통신접근성 품질인증 등 제도 근거 | 인증 여부와 법적 의무 범위는 구분 |
| 한국형 웹 콘텐츠 접근성 지침 | 국내 웹 콘텐츠 접근성 평가 기준 | 버전과 적용 기준 확인 |
| World Wide Web Consortium (W3C)의 Web Content Accessibility Guidelines (WCAG) 2.2 | 국제 기술 권고와 성공 기준 | 국내 법적 의무와 동일시하지 않음 |

## Ⅳ. 접근성 확보 절차

```text
요구·사용자 조사
        ↓
접근 가능한 정보구조·화면 설계
        ↓
개발 중 키보드·대체텍스트·표준 구조 반영
        ↓
자동 점검 + 수동·보조기술 검증
        ↓
장애 당사자 사용성 평가·개선
        ↓
배포 후 회귀 점검
```

## Ⅴ. 운영상 한계와 대응

| 한계 | 원인 | 대응 |
|---|---|---|
| 자동 검사 통과 후 실제 이용 불가 | 자동 도구가 의미·작업 흐름·보조기술 동작을 모두 검증하지 못함 | 키보드·스크린리더 수동 시험과 이용자 평가 추가 |
| 접근성 품질이 배포 후 저하 | 콘텐츠·컴포넌트 변경 때 회귀 검증 누락 | 디자인 시스템 기준·배포 전 검사·정기 회귀 시험 운영 |
| 인증만으로 법적 적합성을 단정 | 인증과 법정 의무 적용 범위가 다름 | 대상 법령·행위자·서비스 조건을 별도로 검토 |

## Ⅵ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 접근성 점검이 출시 직전 인증 준비에 집중되어 실제 사용 장벽이 남음 | 설계·개발 완료 기준에 WCAG·KWCAG 점검과 키보드·보조기술·당사자 검증을 포함하고 배포 후 회귀 검사 운영 |
