## 연관 키워드

- 전자문서증명서, 전자문서지갑, 공인전자문서중계자, 전자증명서 발급·유통 체계
- 해시(Hash), 전자서명, 시점확인(TSA), 블록체인, 온체인(On-Chain), 오프체인(Off-Chain)
- 개인식별정보(PII), 불변성(Immutability), 상호운용성, 폐기 목록(CRL), 자기주권

## Ⅰ. 전자문서증명서(Electronic Document Certification)의 개요

- 핵심 요약 : 원문은 안전한 저장소에 두고 해시값만 원장에 기록해, 종이 증명서를 전자적으로 대체하는 진위 검증 체계.
- 개념 : 행정기관이 권리관계나 법적 사실을 증명하기 위해 발급하는 **전자문서** 형태의 공적 민원증명서이며, 발급 주체의 전자서명과 원문의 해시값으로 진위를 확인한다.
- 배경 및 필요성 : 증명서 원문을 블록체인에 그대로 올리면 개인식별정보(PII, Personally Identifiable Information)가 삭제할 수 없는 형태로 남아 개인정보 파기 의무와 충돌한다. 따라서 원문은 외부 암호화 저장소에 두고, 원장에는 해시값만 기록하는 분리 구조가 필요하다.
- 주요 목적 : 종이 서류의 발급·보관·제출 비용 절감, 위·변조 방지, 비대면 민원과 금융 서비스의 혁신.

## Ⅱ. 전자문서증명서(Electronic Document Certification)의 특징 및 장점

- 핵심 요약 : 원문과 해시의 분리, 전자서명과 시점확인, 이용자 중심의 지갑 보관이 맞물려 신뢰와 개인정보 보호를 함께 확보하는 방식.

1. 해시 기반 무결성 : 원문의 **해시값** (Hash)을 원장에 등록 → 제출된 문서의 해시를 대조해 위·변조 여부를 판별.
2. 전자서명과 시점확인 : 발급 기관의 전자서명에 **시점확인** (TSA, Time Stamping Authority)을 더함 → 발급 주체와 발급 시점을 증명.
3. 자기주권 보관 : 이용자가 **전자문서지갑** (Wallet)에 보관하고 제출 기관을 직접 선택 → 원문 노출 범위를 이용자가 통제.
4. 실시간 상태 조회 : 원장에서 유효·폐기 상태를 확인 → 취소된 증명서의 사용 차단.

## Ⅲ. 전자문서증명서(Electronic Document Certification)의 구조 (흐름)

- 핵심 요약 : 발급 시스템이 원문과 해시를 나누어 보관하고, 제출 기관이 지갑 문서와 원장을 대조하는 구조.

```text
[ 1 민원인 신청 ]
      ↓
[ 2 발급 시스템 ] 원문 생성, 전자서명
      ↓
[ 3 해시 추출 ]
   ├─ 원문 → 오프체인 암호화 저장소
   └─ 해시 → 블록체인 원장 등록
      ↓
[ 4 민원인 지갑 보관 ]
      ↓
[ 5 제출 기관 ] 해시 대조, 상태 확인
```

- 온체인과 오프체인의 분리 : 개인정보는 원문 저장소에 두고, 원장에는 식별자와 해시만 남기는 구조.

```text
[ 오프체인 ] 원문, 개인정보
  암호화 저장, 접근 통제
      ↔ 해시값으로만 연결
[ 온체인 ] 문서 식별자, 해시값
  유효·폐기 상태 기록
```

## Ⅳ. 종이 증명서, 공인전자문서중계자 방식, 블록체인 전자증명서의 비교

- 핵심 요약 : 종이 증명서는 대면 확인에, 중계 방식은 고지 수신에, 블록체인 전자증명서는 제출용 자격 증명에 적합한 구조.

| 비교 항목 | 전통적 종이 증명서 | 공인전자문서중계자 방식 | 블록체인 전자문서증명서 |
| --- | --- | --- | --- |
| 문서 형태 | 실물 종이 인쇄물 | 전자 고지문 | 표준 전자문서와 전자문서지갑 |
| 주요 용도 | 기관 방문 대면 제출 | 행정 처분과 안내문 수신 확인 | 자격 증명, 신청 시 제출 |
| 진위 검증 | 육안 식별, 인쇄 바코드 스캔 | 중계자 시스템의 수신 증명 | 원장의 해시 실시간 대조 |
| 보관 주체 | 오프라인 서류철 | 중계자 서버와 개인 단말 | 개인 단말의 전자문서지갑 |

- 선택 기준 : 원문의 법적 효력이 중요한 제출용 증명은 블록체인 전자증명서, 수신 사실이 중요한 고지는 중계 방식이 적합함.

## Ⅴ. 전자문서증명서(Electronic Document Certification)의 한계와 방안

- 핵심 요약 : 불변성과 파기 의무의 충돌, 발급 후 사정 변경의 반영 지연, 지갑 간 상호운용성 부족을 데이터 분리, 상태 동기화, 표준 인터페이스로 관리해야 함.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 블록체인 불변성과 개인정보 파기 의무의 충돌 | 원장은 삭제가 불가능하여 파기 요구에 대응하기 어려움 | 원문과 개인정보는 외부 암호화 저장소에 격리하고, 원장에는 솔트(Salt)를 더한 단방향 해시만 기록 | 파기 처리 완료율 |
| 발급 후 사정 변경의 실시간 반영 한계 | 정정이나 자격 취소가 생기면 제출 기관이 무효 상태를 알 수 없음 | 취소 발생 시 원장 상태를 폐기로 즉시 변경하고 폐기 목록을 실시간 동기화 | 폐기 반영 소요 시간 |
| 사설 전자문서지갑 난립에 따른 상호운용성 부족 | 기관별 지갑과 연동 방식이 달라 연계 비용 증가 | 표준 연계 인터페이스와 공통 개발 키트 보급으로 이기종 지갑 간 전송 지원 | 연동 가능 지갑 종류 수 |

## Ⅵ. 전자문서증명서에 대한 기술사적 제언

- 핵심 요약 : 증명서의 신뢰를 기술 자체가 아니라 발급과 유통을 아우르는 공공 거버넌스로 보장하고, 개인정보는 최소 보관 원칙으로 관리하는 체계 구축.

1. 유통 거버넌스의 정립 : 발급 기관, 유통 기관, 지갑 사업자의 역할과 책임을 표준 지침으로 묶어 장애와 분쟁 시 책임 주체가 분명하도록 하는 방향이 필요하다.
2. 최소 보관 원칙의 적용 : 원문의 보관 기간과 열람 범위를 유효기간 기준으로 정하고, 사용이 끝난 원문은 파기되도록 하는 운영 원칙을 세워야 한다.
3. 실시간 검증 기반의 공통화 : 제출 기관이 해시 대조와 폐기 여부를 항상 확인할 수 있는 조회 기반을 공공 공통 서비스로 제공하는 것이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : 전자문서증명서는 원문을 옮기지 않고 진위만 검증하는 구조로 종이 증명서를 대체하는 신뢰 인프라.
- 시사점 : 증명의 효력은 블록체인 자체가 아니라 발급 주체의 전자서명과 상태 관리에서 나오므로, 그 운영 책임을 명확히 하는 것이 핵심이다.
