## 답안 골격
```text
[전자문서증명서] ◀━━ 머리: Ⅶ 내 의견 (모바일 전자문서지갑 확산과 블록체인 기반 종이 없는 행정의 원스톱 유통 혁신)
 ┃
 ┣━ Ⅰ 개요 ───── 종이 증명서 발급·유통의 사회적 비용 절감을 위해 스마트폰 전자문서지갑으로 발급·제출하는 공공 디지털 증명 체계
 ┣━ Ⅱ 특징 ───── 블록체인 위변조 방지 · 전자서명 기반 무결성 보장 · 모바일 전자문서지갑 연계 · 종이 증명서와 동일한 법적 효력
 ┣━ Ⅲ 구조 ───── 발급기관(정부24 등) + 전자문서지갑(스마트폰 앱) + 블록체인 진위확인 노드 + 이용기관(은행, 공공기관)
 ┣━ Ⅳ 흐름 ───── 민원인 발급 신청 → 전자증명서 생성 및 서명 → 전자문서지갑 전송 → 열람/제출(QR/지갑주소) → 진위 검증
 ┣━ Ⅴ 비교 ───── 전자문서증명서(블록체인·지갑 유통) vs 전자문서(PDF/공인전자주소 #메일) vs 행정정보 공동이용(DB 직접조회)
 ┗━ Ⅵ 실무 ───── 금융권 수기 심사 관행으로 인한 전자 제출 거부 / 타 지갑 앱 간 상호 연계 및 데이터 표준화 지연
```
- 필수 키워드: 전자문서증명서 · 전자문서지갑 · 행정안전부 · 블록체인 진위확인 · 전자정부법 · 공공 마이데이터
- 배점 전략: 10점 = Ⅰ 추진 배경 → Ⅲ 4대 주체 및 유통 도식 → Ⅴ 타 전자문서 유통 방식 비교 / 25점 = Ⅰ~Ⅶ 전개, Ⅳ 발급·유통·검증 기술 아키텍처와 Ⅵ 금융·공공 서비스 연계 실무 심층화
- 기출: 121회 4교시 2번 `최근 행정안전부에서 전자문서증명서 사업을 추진하고 있다. 전자증명서의 개념, 발급 및 유통 절차, 블록체인 연계 방안을 설명하시오.` → Ⅰ·Ⅱ·Ⅲ·Ⅳ·Ⅵ 전수

## 한 줄 본질
- 주민등록등본 등 각종 종이 민원 증명서를 암호화된 전자 파일로 모바일 전자문서지갑에 발급받아, 블록체인 진위확인을 거쳐 은행·공공기관에 비대면으로 안전하게 제출하는 디지털 증명 유통 체계 → 종이 발급·유통 비용 절감 / 지갑 앱 및 제출처 시스템 연동 비용 수반

## 핵심 그림
```text
+--------------------------------------------------------------------------------+
|                   전자문서증명서 발급 및 블록체인 유통 아키텍처                |
+--------------------------------------------------------------------------------+
|                                                                                |
|  [ 1. 발급 단계 ]                                                              |
|  민원인 (정부24 신청) =====> 행안부 전자문서발급센터 (증명서 PDF/JSON 생성)    |
|                                       |                                        |
|                                       +--> 전자서명 및 타임스탬프(TSA) 부여    |
|                                       |                                        |
|                                       +--> 문서 해시(Hash) 블록체인에 기록    |
|                                       |                                        |
|                                       v                                        |
|  [ 2. 보관 단계 ]                                                              |
|  민원인 스마트폰 [ 모바일 전자문서지갑 ] (정부24, 카카오, 토스, PASS 등)       |
|  - 보안 영역(Secure Storage)에 암호화 보관 및 유효기간(90일) 관리              |
|                                       |                                        |
|                                       v  제출 (QR코드, 지갑주소 전송)          |
|  [ 3. 제출 및 수신 단계 ]                                                      |
|  수취 기관 (은행, 통신사, 공공기관 창구)                                       |
|  - 수신된 전자문서증명서 복호화 및 열람                                        |
|                                       |                                        |
|                                       v  진위 검증 (Hash 비교)                 |
|  [ 4. 진위확인 단계 ]                                                          |
|  수취 기관 서버 <===================> [ 블록체인 진위확인 노드 ]               |
|  (제출 문서의 해시값과 블록체인 원장 해시값 일치 여부 판별 -> 위변조 차단)     |
+--------------------------------------------------------------------------------+
```

## 핵심 용어
- 전자문서지갑: 스마트폰 앱 형태로 제공되며, 행정안전부와 연계하여 공공 전자증명서를 안전하게 다운로드받아 보관·제출할 수 있는 디지털 지갑
- 타임스탬프(TSA, Time Stamping Authority): 증명서가 특정 시점에 생성되었고 이후 수정되지 않았음을 입증하는 암호학적 시간 공증
- 전자정부법 제36조의2: 전자문서로 발급된 증명서에 종이 증명서와 완전히 동등한 법적 효력을 부여하는 법적 근거

## 핵심 통찰
- 기존 종이 증명서는 발급 비용(인쇄, 우편), 보관 비용뿐만 아니라 위변조(컬러 복사, 위조 도장)에 취약한 근본적 한계를 지님
- 전자문서증명서는 원본 문서 전체를 블록체인에 올리지 않고 "문서의 암호화 해시(SHA-256)"만 블록체인 분산원장에 기록함으로써, 용량 문제와 개인정보 노출 문제를 동시에 해결함
- 최근에는 증명서 전체 파일을 주고받는 방식을 넘어, 필요한 최소 항목(소득 금액, 자격 여부)만 API로 전송하는 '공공 마이데이터'로 진화하는 징검다리 역할을 수행함

## 딸려 나오는 하위 토픽
| 하위 토픽 | 상위 구조 속 위치 | 한 줄 |
|---|---|---|
| 공공 마이데이터 | 전자증명서의 데이터화 발전 | 증명서 문서 대신 필요한 개별 행정정보만 추출해 데이터 형태로 직접 전송하는 체계 |
| 모바일 신분증 | 신원 증명 인프라 연계 | 블록체인 DID 기술을 바탕으로 주민등록증, 운전면허증을 모바일에 담는 국가 신원 체계 |

## 이웃 토픽과 구분
- 전자문서증명서 vs 공인전자주소(#메일): 전자문서증명서 = 모바일 지갑 중심, 블록체인 해시 진위 검증 / #메일 = 공인전자문서중계자 기반의 이메일 형태 송수신 증명

## 문제·원인·대책
- 사례: 121회 기출 시중은행 비대면 대출 심사 시 고객이 제출한 전자증명서 수신 처리 지연
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 민간 플랫폼(카카오·토스) 지갑과 공공 수신 서버 간 API 프로토콜 불일치 | 전자증명서 유통 표준 스펙 미비 및 버전 파편화 | 행안부 전자문서증명서 표준 API 규격 배포 및 공통 검증 게이트웨이 일원화 | 유통 지연 해소 및 즉시 심사 완료 |
| 유효기간(90일) 경과 증명서 제출에 따른 심사 반려 | 증명서 라이프사이클 관리 미흡 | 지갑 앱 내 만료 D-7일 사전 알림 및 정부24 자동 재발급 플로우 제공 | 반려율 최소화 및 고객 편의 증대 |

## 이렇게 출제된다
- 제121회 4교시 2번: "최근 행정안전부에서 전자문서증명서 사업을 추진하고 있다. 전자증명서의 개념, 발급 및 유통 절차, 블록체인 연계 방안을 설명하시오." → 요구 포인트: Ⅰ 사업 추진 배경 + Ⅲ 발급/유통 주체 및 절차 + Ⅳ 블록체인 해시 검증 아키텍처

## 내 의견
- [증명서 단위 제출에서 공공 마이데이터 최소 정보 전송(Data-level)으로 전면 전환] 등본 한 장을 낼 때 제출처와 무관한 동거인, 과거 주소 변동 이력 등 과도한 개인정보가 함께 유출되는 문제가 남아 있음 → 나라면: 전자문서증명서를 종이 서식 형태의 PDF 렌더링 방식에서 탈피시키고, 금융 심사에 필요한 항목만 선택적으로 추출·검증할 수 있는 W3C Verifiable Credentials(VC) 표준 기반의 데이터 단위 제출 시스템으로 재설계

## 찾아볼 것
- W3C Verifiable Credentials(VC) 및 DID 표준과 행안부 전자증명서 지갑 간의 상호운용성 표준화 동향
