## 30초 인출

- 본질: **전자문서증명서** 는 행정기관이 특정 권리관계나 사실을 증명하기 위해 종이 서류 대신 모바일 전자문서 형태로 발급하여 스마트폰 전자문서지갑을 통해 보관·제출·유통되는 디지털 민원증명서
- 메커니즘: 「민원 처리에 관한 법률」 제28조의2에 근거하여 행안부 전자증명서 발급·유통시스템을 통해 발급되고, 위·변조 방지를 위해 원문 해시(Hash)값을 블록체인 분산원장에 등록하여 실시간 검증
- 통찰: 블록체인 원장에 원문 및 개인식별정보(PII)가 영구 저장되는 컴플라이언스 위반을 방지하기 위해 오프체인(Off-Chain) 원문 저장 및 해시값 온체인(On-Chain) 분리 아키텍처 수립 필수

<details><summary>핵심 용어</summary>

- **전자증명서** : 행정기관 등이 발급하는 주민등록표등본, 예방접종증명서 등을 위·변조 방지 기술이 적용된 전자문서 형태로 발급한 증명서.
- **전자문서지갑** : 스마트폰 정부24, 금융사 앱 등에서 전자증명서를 안전하게 수신, 암호화 보관, 열람, 제출할 수 있는 소프트웨어 저장소.
- **오프체인 (Off-Chain)** : 대용량 데이터나 민감한 개인정보를 블록체인 외부의 보안 스토리지에 암호화 보관하는 아키텍처.
- **온체인 (On-Chain)** : 블록체인 블록 내에 트랜잭션으로 직접 영구 기록하는 영역으로, 해시값·발급일시·상태값 등에 한정.
- **시점확인 (TSA, Time Stamping Authority)** : 전자증명서가 특정 시점에 존재하였고 그 이후 위·변조되지 않았음을 공인 기관이 증명하는 암호 기술.
- **행정정보 공동이용** : 민원인이 서류를 발급받지 않고도 처리 기관이 행정망 전산 조회를 통해 직접 구비서류를 확인하는 체계.

</details>

## 2~4교시 예상문제 (25점)

> 페이퍼리스(Paperless) 행정 구현을 위한 '전자문서증명서(전자증명서)'의 법적 근거와 핵심 구성요소를 설명하고, 블록체인 기반 발급·유통·진위확인 프로세스 및 개인정보보호(온체인/오프체인 분리)와 실시간 폐기·취소 검증 방안을 논하시오. (기출·제121회 4교시 2번 변형·25점)

## 2~4교시 25점 답안

## Ⅰ. 전자문서증명서의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **전자문서증명서** 는 행정기관이 특정 권리관계나 법적 사실을 증명하기 위해 전자문서 또는 전자화문서 형태로 발급하는 공적 민원증명서 |
| 목적 | 종이 서류 발급·보관·제출에 따른 사회적 비용 절감, 위·변조 위험 원천 차단 및 비대면 원스톱 공공·금융 서비스 혁신 |

## Ⅱ. 전자증명서의 법적 근거 및 핵심 기술적 특징

| 구분 | 주요 기준 | 상세 특징 및 기술적 요건 |
|---|---|---|
| **법적 근거** | 민원 처리에 관한 법률 제28조의2 | 전자민원창구를 통해 전자증명서를 발급하고, 종이 증명서와 완전한 동등 효력 부여 |
| **발급·유통 체계** | 행안부 전자증명서 처리지침 | 발급기관(지자체 등), 유통기관(통신·금융사), 전자문서지갑 운영 표준 규정 |
| **위·변조 방지** | 블록체인 & PKI 전자서명 | 발급기관의 공인 전자서명, 시점확인(TSA), 위변조 방지용 2차원 바코드(QR) 결합 |
| **자기주권 유통** | 전자문서지갑(Wallet) 모델 | 민원인이 직접 자신의 지갑에 보관하고, 제출 대상 기관을 선택하여 전송(P2P/API) |
| **프라이버시 통제** | 온/오프체인 분리 원칙 | 개인정보가 포함된 원문은 암호화 저장소에 두고, 블록체인에는 무결성 검증용 해시만 기록 |

## Ⅲ. 블록체인 기반 전자증명서 발급·유통·검증 프로세스

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ [ 블록체인 연계 전자증명서 발급·유통 및 온/오프체인 분리 아키텍처 ]         │
└─────────────────────────────────────────────────────────────────────────────┘
  [ 1. 민원인 신청 (정부24/금융앱) ]
           │
           ▼
  [ 2. 행정안전부 전자증명서 발급·유통시스템 (발급기관 연계) ]
    ├── 공적 장부 조회 및 전자증명서 XML/PDF 원문 생성
    ├── 발급기관 기관인증서 전자서명 및 TSA 시점확인 날인
    └── SHA-256 해시값(Hash) 추출
           │
       ┌───┴──────────────────────────────────────────┐
       ▼ (원문 암기/보관)                             ▼ (해시 등록)
  [ 오프체인 스토리지 (보안 저장소) ]        [ 허가형 블록체인 (Hyperledger) ]
  - 암호화된 전자증명서 원문 보관          - [블록 트랜잭션]
  - 열람용 일회용 다운로드 링크             * 증명서 식별자 (Doc ID)
           │                                 * 발급기관 식별자
           ▼                                 * 원본 SHA-256 해시값
  [ 민원인 모바일 전자문서지갑 ]             * 유효기간 및 상태 (ACTIVE)
           │                                          │
           │ 3. 제출기관 지정 전송                    │ 4. 실시간 무결성 조회
           ▼                                          ▼
  [ 제출기관 (은행/통신사/공공) ] <───────────────────┘
    ├── 제출된 증명서 해시 계산 ──> 블록체인 원장 해시와 1:1 비교
    └── 유효기간 및 취소(폐기) 여부 확인 ──> [ 진위 확인 완료 및 업무 처리 ]
```

```text
[ 온체인과 오프체인의 데이터 분리 구조 ]
┌───────────────────────────────────┐    ┌───────────────────────────────────┐
│     오프체인 (Off-Chain Storage)   │    │     온체인 (On-Chain Ledger)      │
├───────────────────────────────────┤    ├───────────────────────────────────┤
│ - 주민등록등본 PDF 원문           │ ≠  │ - 문서 고유 UUID                  │
│ - 성명, 주민번호, 주소, 세대원    │    │ - SHA-256 해시 다이제스트         │
│ - AES-256 암호화 및 접근통제      │    │ - 폐기 상태 플래그 (ACTIVE/REVOKED)│
└───────────────────────────────────┘    └───────────────────────────────────┘
```

| 처리 단계 | 주요 수행 주체 | 핵심 기술 및 산출물 |
|---|---|---|
| **발급 신청** | 민원인 → 정부24 | FIDO 본인인증, 발급 신청 트랜잭션 |
| **전자서명·해싱**| 발급기관 (지자체 등) | X.509 전자서명, RFC 3161 TSA 타임스탬프 |
| **원장 등록** | 행정안전부 시스템 | 블록체인 스마트 콘트랙트 호출, 트랜잭션 영구 기록 |
| **지갑 수납** | 사용자 스마트폰 단말 | 전자문서지갑 내 암호화 적재, QR 코드 생성 |
| **제출 및 검증**| 제출기관 (수요처) | API 기반 원문 복호화, 블록체인 해시 대조, CRL 검증 |

## Ⅳ. 종이 증명서 vs 공인전자문서중계자 vs 블록체인 전자증명서 비교

| 비교 항목 | 전통적 종이 증명서 | 공인전자문서중계자 (모바일 전자고지) | 블록체인 전자문서증명서 |
|---|---|---|---|
| **문서 형태** | 실물 종이 인쇄물 (워터마크) | 멀티미디어 메시지(카카오페이 등) | 표준 전자문서(XML/PDF) + 전자지갑 |
| **주요 용도** | 기관 방문 대면 제출용 | 행정 처분·안내문 수신 확인용 | 자격 증명, 대출 신청 등 제출용 |
| **진위 검증** | 육안 식별, 인쇄 바코드 스캔 | 중계자 시스템 유통증명서 발급 | 블록체인 분산원장 실시간 해시 대조 |
| **보관 주체** | 오프라인 서류철, 캐비닛 | 중계자 서버 및 개인 단말 | 개인 스마트폰 안전영역(전자문서지갑) |
| **위·변조 위협**| 위조 인쇄, 컬러 복사본 취약 | 중간자 공격, 메시지 탈취 위험 | PKI 전자서명 및 블록체인 불변성 보장 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 블록체인의 '삭제 불가능(Immutability)' 특성으로 인해 개인정보보호법상 '파기 의무' 및 잊힐 권리 충돌 | 개인정보 및 증명서 원문은 100% 오프체인 암호화 스토리지에 격리하고, 블록체인 온체인에는 복원 불가능한 단방향 솔트(Salt) 해시값만 기록 |
| 전자증명서 발급 후 주민등록 정정, 자격 취소 등 사정 변경 발생 시 제출기관에서 실시간 무효화 상태 파악 불가 | 스마트 콘트랙트 내 '상태 관리(State Management)' 함수를 구현하여 발급기관의 취소 트랜잭션 발생 시 온체인 상태를 'REVOKED'로 즉시 변경 |
| 금융사, 통신사, 핀테크사별 사설 전자문서지갑 난립으로 인한 상호운용성 부족 및 연동 API 개발 비용 과다 | 행정안전부 '전자증명서 표준 연계 API 인터페이스' 보급 및 오픈소스 SDK 배포를 통한 이기종 지갑 간 자유로운 P2P 전송 지원 |

## Ⅵ. 제언

전자문서증명서의 신뢰성과 보안성을 극대화하기 위하여 오프체인 임시 보관 및 제로트러스트 기반 실시간 폐기 검증 게이트웨이를 결합한 공공 유통 거버넌스 수립.

```text
[ 민원인: 전자증명서 제출 실행 ]
                 │
                 ▼
[ 제출기관 수신 게이트웨이 ]
    ├── Step 1: 오프체인 스토리지에서 일회용 토큰으로 원문 다운로드
    ├── Step 2: 원문 해시 계산 ──> 블록체인 분산원장 대조 (무결성 검증)
    └── Step 3: 실시간 스마트 콘트랙트 호출 (상태 == ACTIVE 확인)
                 │
                 ▼ (검증 통과 시)
[ 민원 업무 즉시 승인 및 오프체인 임시 파일 24시간 내 자동 파기 ]
```

| 구분 | 단순 PDF 파일 첨부 방식 | 제언: 블록체인 연계 온/오프체인 체계 |
|---|---|---|
| **위변조 검증** | 포토샵 수정 등 위조에 취약 | SHA-256 해시 블록체인 대조로 위조 원천 차단 |
| **개인정보 통제** | 메일/서버에 영구 방치 | 24시간 유효기간 설정 및 사용 후 즉시 파기 |
| **상태 동기화** | 발급 후 취소 여부 확인 불가 | 스마트 콘트랙트 기반 실시간 폐기 목록(CRL) 동기화 |
| **유통 투명성** | 제출 경로 추적 불가 | 허가형 노드 간 분산원장 감사 로그 보존 |
