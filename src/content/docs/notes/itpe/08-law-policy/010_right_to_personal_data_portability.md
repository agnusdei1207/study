## 30초 인출

- 본질: **개인정보 전송요구권** 은 정보주체가 개인정보처리자가 보유한 자신의 개인정보를 본인 또는 일정한 요건을 갖춘 제3자에게 직접 전송하도록 요구할 수 있는 법적 권리
- 메커니즘: 정보주체의 전송 요구 및 전자서명 검증 후 정보전송자가 기계 판독이 가능한 표준화된 형식(JSON)으로 암호화하여 표준 API를 통해 정보수신자에게 전송
- 통찰: 사업자가 자체 생성·가공한 파생 데이터의 전송 제외 분쟁과 수신 기관에서의 2차 유출 위험이 크므로 전송 대상 경계 표준화와 FAPI 기반 엔드투엔드 토큰 추적 체계 구축 필수

<details><summary>핵심 용어</summary>

- **개인정보 전송요구권 (Data Portability)** : 개인정보 보호법 제35조의2에 근거하여 정보주체의 데이터 이동 및 자기결정권을 보장하는 권리.
- **정보전송자** : 매출액, 개인정보 보유 규모 등이 대통령령 기준에 해당하여 전송요구에 응할 법적 의무가 있는 개인정보처리자.
- **개인정보관리 전문기관** : 개인정보 보호법 제35조의3에 따라 정보주체를 대신하여 개인정보를 수집·관리·전송하는 공인 기관.
- **파생 데이터 (Derived Data)** : 개인정보처리자가 수집된 정보를 기반으로 인공지능 분석, 추론, 가공 등을 거쳐 독자 생성한 비전송 대상 정보.
- **기계 판독 가능 형식 (Machine-Readable Format)** : 소프트웨어 프로그램이 사람의 개입 없이 데이터를 즉시 식별·추출·변환할 수 있는 표준 규격.

</details>

## 2~4교시 25점 답안

## Ⅰ. 개인정보 전송요구권의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **개인정보 전송요구권** 은 정보주체가 개인정보처리자에게 본인에 관한 개인정보를 본인 또는 개인정보관리 전문기관 등 제3자에게 전송할 것을 요구하는 법적 권리 |
| 목적 | 데이터 독점 방지, 정보주체의 데이터 이동권 보장 및 산업 간 데이터 융합 촉진 |

## Ⅱ. 개인정보 전송요구권의 법적 요건 및 대상 정보 특징

| 구분 | 법적 기준 및 요건 | 상세 특징 및 기술적 적용 기준 |
|---|---|---|
| **대상 정보의 성격** | 본인에 관한 정보 | 정보주체의 동의를 받아 처리되거나 계약의 체결·이행을 위해 처리된 정보 |
| | 기계 판독 가능성 | 컴퓨터 등 정보처리장치에 의해 처리되는 전자적 형태의 정형 데이터 |
| | **제외 정보 (특징)** | 처리자가 수집된 정보를 기초로 별도 가공·분석·생성한 **파생 정보(AI 분석값 등) 제외** |
| **정보전송자 요건** | 의무 대상 사업자 | 연간 매출액 1,500억 원 이상 또는 100만 명 이상의 개인정보를 보유한 대규모 사업자 |
| **정보수신자 요건** | 적격 수신 기관 | 본인, 개인정보관리 전문기관, 시설·장비 등 안전조치 기준을 갖춘 개인정보처리자 |
| **거절 및 중단 사유** | 정당한 거절 요건 | 본인 확인 불가, 제3자의 권리 침해, 시스템 장애, 법정 전송 대상 정보가 아닌 경우 |

## Ⅲ. 개인정보 전송요구권 행사 및 데이터 전송 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 개인정보 전송요구권 E2E 행사 및 표준 API 전송 프로세스 ]            │
└────────────────────────────────────────────────────────────────────────┘

 [ 정보주체 ]
    │ ① 전송요구권 행사 신청 (본인 확인 및 전송 대상 항목·수신자 지정)
    ▼
 [ 마이데이터 앱 / 중계 포털 ]
    │ ② 전자서명 검증 및 전송요구서(OAuth Scope) 생성
    ▼
 [ 개인정보전송자 (보유기관) ]
    ├── ③ 법적 적격성 심사 (의무 대상 여부, 파생 데이터 제외 필터링)
    ├── ④ 본인 확인 및 거절 사유 존재 여부 확인
    └── ⑤ 대상 개인정보 추출 및 표준 기계판독 포맷(JSON) 변환
    │
    ▼ (⑥ FAPI 기반 상호 인증 및 TLS 1.3 암호화 전송)
 [ 정보수신자 (개인정보관리 전문기관) ]
    ├── ⑦ 데이터 수신 무결성 검증 및 복호화
    └── ⑧ 지정된 이용 목적 내에서만 분석 및 정보주체 서비스 제공
    │
    ▼ (⑨ 전송 결과 통지 및 감사 로그 보존)
 [ 정보주체 및 감독기관 ] ── 전송 내역 영수증 열람 및 사후 이상 전송 감시
```

| 프로세스 단계 | 주요 수행 업무 | 기술적 검증 기준 |
|---|---|---|
| **1. 권리 신청** | 대상 정보 범위 및 수신 기관 선택, 전자서명 인증 | 전자서명법상 공동/금융인증서, 간편인증 검증 |
| **2. 대상성 판정** | 계약/동의 기반 원천 정보 여부 판정, 파생 정보 제외 | 메타데이터 기반 원천 컬럼 필터링(Data Filtering) |
| **3. 거절 요건 검토** | 기술적 불가, 제3자 권리 침해, 타인 식별자 포함 검토 | 거절 사유 발생 시 지체 없이 정보주체에 통지 |
| **4. 표준 전송** | 범정부 표준 API 호출을 통한 기계판독 데이터 전송 | RESTful API, JSON 스키마 유효성 검사, TLS 1.3 |
| **5. 사후 권리 보장** | 전송 내역 보관, 전송 철회 시 즉각 전송 중단 | 전송 이력 3년 보관, 실시간 철회 Webhook 연동 |

## Ⅳ. 본인 전송과 제3자 전송의 비교

| 비교 항목 | 본인에게 전송 요구 | 제3자에게 전송 요구 (마이데이터) |
|---|---|---|
| **수신 주체** | 정보주체 본인 (개인 PC, 모바일 단말) | 개인정보관리 전문기관, 적격 인가 사업자 |
| **전송 방식** | 파일 다운로드(CSV, JSON) 또는 뷰어 제공 | 표준 RESTful API 기반 서버 간 직접 전송 |
| **수신자 보안 요건** | 개인 단말기 보안 (별도 법적 설비 의무 없음) | 물리적·기술적 안전조치 및 전문기관 지정 요건 충족 |
| **적용 목적** | 개인의 단순 열람, 보관, 직접 활용 | 통합 조회, 맞춤형 자산·의료 등 융합 서비스 이용 |
| **거절 가능성** | 본인 확인 불가 시에만 극히 제한적 거절 | 수신자 적격성 미달, 기술적 설비 미비 시 거절 가능 |
| **수신 후 규율** | 개인 영역 (개인정보 보호법 적용 제외) | 개인정보 보호법상 처리자 의무 전면 적용 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 원천 수집 정보와 사업자 고유 자산인 파생·가공 정보 간의 경계 모호성에 따른 법적 분쟁 | 산업별 전송 대상 표준 데이터 사전(Data Dictionary) 제정 및 법정 네거티브 규제 명확화 |
| 다수 기관 연계 전송 시 특정 중계 노드 침해로 인한 대규모 개인정보 연쇄 유출 위험 | 엔드투엔드 애플리케이션 레벨 페이로드 암호화(JWE) 적용 및 토큰 탈취 방지 DPoP 표준 강제 |

## Ⅵ. 제언

전송요구권의 안전하고 투명한 운영을 위해 개인정보 전송 전 주기에 디지털 서명 영수증 체계를 도입하고, 파생 데이터 자동 필터링 엔진 구축 필요.

```text
[ 정보전송자 원천 DB ]
          │
          ▼
[ AI 기반 전송 데이터 필터링 엔진 ]
   ├── 원천 수집/계약 데이터 자동 선별 (전송 허용)
   └── 영업비밀 및 알고리즘 추론 파생값 자동 마스킹 (전송 차단)
          │
          ▼
[ FAPI 보안 게이트웨이 ] ──(DPoP 기반 토큰 검증)──> [ 적격 수신기관 전송 ]
          │
          ▼
[ KISA 전송요구 이력 원장 ] ──(디지털 영수증 발행)──> [ 정보주체 실시간 확인 ]
```

| 구분 | 기존 수기 기반 전송 관리 | 제언: AI 필터링 및 디지털 영수증 연계 |
|---|---|---|
| **파생 데이터 통제** | 담당자 수동 쿼리 작성 (누락·유출 위험) | 메타데이터 기반 파생 정보 자동 격리 및 차단 |
| **인증 보안 수준** | 일반 OAuth 2.0 Bearer Token (탈취 취약) | FAPI 및 DPoP(Proof-of-Possession) 서명 토큰 |
| **투명성 검증** | 월별 사후 통지 메일 발송 | 실시간 모바일 디지털 데이터 영수증 발급 |
| **철회 반영 속도** | 영업일 기준 3~5일 소요 | 이벤트 기반 비동기 Webhook으로 즉시 전송 파기 |
