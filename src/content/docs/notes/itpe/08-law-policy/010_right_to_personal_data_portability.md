## 30초 인출

- 본질: 개인정보 전송요구권은 법정 요건을 충족하는 본인 개인정보를 자신이나 지정된 수신자에게 보내도록 요구하는 정보주체의 권리다.
- 메커니즘: 대상 정보·전송자·수신자를 확인하고, 처리 가능한 형태로 전송하며, 정보주체는 요구를 철회할 수 있다.

## 1교시 10점 답안

### 정의·목적

- 정의: 개인정보 전송요구권은 정보주체가 법정 요건을 충족하는 본인 개인정보를 자신이나 지정된 적격 수신자에게 전송하도록 요구하는 권리다.
- 목적: 데이터 이동과 정보주체의 선택권을 보장하면서 전송 대상·방식·수신자를 법률로 통제한다.

### 요건과 흐름

```text
정보주체가 전송 요구
        ↓ 본인·대상·수신자 확인
정보전송자: 법정 대상 정보 판정
        ↓ 처리 가능한 형태로 전송
적격 수신자 또는 정보주체
        ↓
철회·거절·중단 절차 적용
```

제언: 정보 범위와 수신자를 구체적으로 보여주고 철회 경로를 제공한다.

## 2~4교시 25점 답안

### Ⅰ. 권리의 범위와 법정 요건

정보주체는 대통령령 기준에 해당하는 개인정보처리자에게 법이 정한 요건을 모두 충족하는 본인 개인정보를 자신에게 전송하도록 요구할 수 있다. 제3자 전송 요구는 적격 수신자·전송자 및 기술적으로 허용되는 합리적 범위 등 별도 요건을 따른다.

| 판정 요건 | 내용 |
|---|---|
| 본인에 관한 정보 | 동의 처리 정보, 계약 이행 관련 정보, 법정 절차로 지정된 정보 등 해당 항목 |
| 정보의 성격 | 처리자가 수집한 정보를 기초로 분석·가공해 별도 생성한 정보가 아닐 것 |
| 처리 형태 | 컴퓨터 등 정보처리장치로 처리되는 개인정보 |
| 전송자·수신자 | 시행령상 전송자와 법정 수신자 자격을 확인 |

### Ⅱ. 정보 이동 구조

```text
정보주체
  │ 전송요구·인증·정보/수신자 선택
  ▼
정보전송자
  │ 범위·자격 확인 후 안전한 기계처리 형태로 전송
  ▼
본인 또는 적격 수신자
  │ 목적 범위의 이용·보호
  ▼
정보주체: 요구 철회·권리 행사
```

### Ⅲ. 처리 절차와 책임

| 참여자 | 책임 |
|---|---|
| 정보주체 | 전송 범위·수신자 선택, 요구 철회 |
| 정보전송자 | 본인·대상·수신자 확인, 처리 가능한 형태로 안전하게 전송 |
| 정보수신자 | 전송 목적·범위에 맞게 이용하고 안전조치·보유·삭제 기준 준수 |
| 중계·기술 지원자 | 해당 제도에서 정한 인증·전송·기록·장애 대응 수행 |

### Ⅳ. 거절·중단·철회

| 상황 | 처리 |
|---|---|
| 본인 여부 확인 불가 등 법령상 사유 | 전송 요구를 거절하거나 전송을 중단할 수 있음 |
| 정보주체가 요구 철회 | 전송 절차를 중지하고 법정 처리에 따름 |
| 제3자 권리·정당한 이익 침해 우려 | 대상·범위와 법정 요건을 재검토 |
| 전송 완료 후 수신 정보 처리 | 전송 철회와 이미 수신된 정보의 이용·보유·삭제 의무를 구분해 처리 |

### Ⅴ. 기술·운영 고려사항

| 문제 | 대응 |
|---|---|
| API·데이터 형식 차이로 전송 실패 | 법정 표준·고시와 분야별 데이터 규격을 적용하고 호환성 시험 |
| 과도한 수집 또는 기만적 동의 화면 | 항목·목적·수신자를 분리해 안내하고 최소 범위 선택 지원 |
| 토큰·전송 구간 탈취 | 강한 인증, 암호화, 최소 권한, 접근·전송 이력 점검 |
| 철회와 후속 데이터 처리가 혼동 | 중단·보유·삭제 절차를 분리하고 정보주체에게 결과 안내 |

### Ⅵ. 기술사적 제언

| 문제 | 해결 방안 |
|---|---|
| 전송권 구현이 API 제공에 치우쳐 수신 이후의 권리·보안 통제가 흐려짐 | 전송요구의 검증부터 수신 이후 이용·보유·철회 처리까지 추적 가능한 권리 관리 기록을 두고, 분야별 법정 기준과 표준 API를 함께 운영한다. |
