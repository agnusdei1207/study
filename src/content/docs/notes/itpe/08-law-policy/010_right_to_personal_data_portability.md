## 연관 키워드

- **개인정보 전송요구권**, **개인정보 보호법 제35조의2**
- **본인 전송**, **제3자 전송**, **개인정보관리 전문기관**
- **전송 대상 요건**, **전송요구 철회**, **기계처리 가능 형태**

## Ⅰ. 개인정보 전송요구권의 개요

- 핵심 요약 : 정보주체가 법정 요건에 맞는 자신의 개인정보를 본인이나 적격 제3자에게 전송하도록 요구할 수 있는 권리.
- 개념 : 개인정보 보호법 제35조의2에 따라 일정한 개인정보처리자에게 정보의 이동을 요구하는 정보주체 권리.
- 배경 및 필요성 : 서비스마다 흩어진 개인정보를 이용자가 이동·활용하기 어렵고, 기존 서비스에 종속되는 문제 완화 필요.
- 목적 : 정보주체의 실질적 통제와 안전한 데이터 이동 지원.

## Ⅱ. 개인정보 전송요구권의 특징 및 장점

- 핵심 요약 : **전송 대상·전송자·수신자**를 법률로 구분해 권리 행사를 가능하게 하면서 과도한 정보 이전 방지.

1. **본인 전송** : 정보주체가 법정 대상 정보를 자신에게 요청할 수 있어 보유 정보의 재사용성 향상.
2. **제3자 전송** : 적격 전문기관 또는 안전 기준을 충족한 수신자에게 이동할 수 있어 서비스 선택권 확대.
3. **대상 정보 제한** : 본인 관련성·처리 근거·전자적 처리 여부를 확인하여 전송 범위의 예측 가능성 확보.
4. **파생 정보 제외** : 수집 정보를 기초로 별도 분석·가공해 생성한 정보는 원칙적인 전송 대상에서 제외하여 권리 경계 명확화.
5. **철회·거절 규정** : 정보주체의 철회와 법정 거절·중단 사유를 두어 부정확한 요구·오용 위험 관리.

## Ⅲ. 개인정보 전송요구권의 행사 구조

- 핵심 요약 : **요구 대상 확인 → 본인 확인 → 수신자 검증 → 합리적 범위의 전송 → 이력·철회 관리** 흐름.

```text
정보주체 ── 전송 요구 ──> 정보전송자
   │                         ├─ 대상 정보·요건 확인
   │                         ├─ 본인 여부·거절 사유 확인
   │                         └─ 기계처리 가능 형태로 전송
   └──────────────> 본인 또는 적격 제3자
```

- **법 제35조의2제1항**의 전송 대상은 본인 관련성, 법정 처리 근거, 파생 정보 제외, 전자적 처리 등의 요건을 함께 충족해야 함.
- **제2항**의 제3자 전송은 법정 기준의 개인정보관리 전문기관 또는 안전조치·시설·기술 기준을 충족한 자를 대상으로 함.
- 전송은 시간·비용·기술적으로 허용되는 합리적 범위에서 수행하며, 정보주체는 전송 요구를 철회 가능.

```text
대상 정보 검토
   ├─ 수집·처리된 본인 정보인가?
   ├─ 별도 분석·가공 생성 정보는 아닌가?
   └─ 컴퓨터 등으로 처리되는가?
       ↓ 모두 충족
전송자 기준·수신자 적격성·본인 확인 → 전송
```

## Ⅳ. 본인 전송과 제3자 전송의 비교

- 핵심 요약 : 같은 권리라도 전송 목적지에 따라 **정보전송자 기준**과 **수신자 요건**이 다름.

| 비교 항목 | 본인에게 전송 | 적격 제3자에게 전송 |
|---|---|---|
| 수신자 | 정보주체 본인 | 개인정보관리 전문기관 또는 법정 안전 기준 충족자 |
| 전송 대상 | 제35조의2제1항 요건 충족 정보 | 제1항 대상 정보 중 기술적으로 허용되는 합리적 범위 |
| 확인 사항 | 본인 확인·정보 범위 | 본인 확인·수신자 자격·전송 범위 |
| 공통 권리 | 전송 요구와 철회 | 전송 요구와 철회 |

- **열람권**은 내용을 확인하는 권리이고 **전송요구권**은 기계처리 가능한 형태로 정보의 이동을 요청한다는 점에서 구분.

## Ⅴ. 개인정보 전송요구권의 한계와 방안

- 핵심 요약 : **대상 정보 경계**, **부정 전송**, **전송 실패**를 데이터 분류·신원 검증·오류 복구로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 대상 경계 분쟁 | 수집 정보와 별도 생성된 파생 정보의 구별 어려움 | 데이터 계보와 생성 과정을 기록해 전송 대상 표준화 | 분쟁·재심사 건수 |
| 부정 전송 | 위장 요구·잘못된 수신자 지정으로 유출 가능 | 본인 확인과 수신자 자격·범위 검증 | 부정 전송 차단 건수 |
| 전송 장애 | 기관 간 형식·연결 실패 | 전송 상태 알림, 재시도·중복 방지 | 전송 성공률 |
| 권리 행사 복잡성 | 법정 범위·철회 방식을 이용자가 이해하기 어려움 | 항목·수신자·철회 방법을 한 화면에 명확히 제시 | 철회 처리시간 |

## Ⅵ. 개인정보 전송요구권에 대한 기술사적 제언

- 핵심 요약 : **법적 대상 판정**, **안전한 연계**, **정보주체의 사후 통제**를 하나의 서비스 흐름으로 설계 필요.

1. 전송 대상과 제외되는 파생 정보를 데이터 카탈로그에 구분하고 변경 이력 기록.
2. 전송자·수신자 자격 및 본인 확인 결과를 추적 가능하게 보관.
3. 기술 방식은 최신 분야별 표준에 맞추되 특정 프로토콜을 모든 분야의 법정 필수 수단으로 단정하지 않음.
4. 정보주체에게 요구 현황·결과·철회 경로를 이해하기 쉽게 제공.

## Ⅶ. 결론

- 핵심 요약 : **개인정보 전송요구권**은 단순 다운로드 기능이 아니라 대상 정보와 수신자 요건을 지키며 데이터 이동을 보장하는 권리.
- 시사점 : 안전한 전송과 정보주체가 행사할 수 있는 명확한 통제 기능이 함께 필요.
