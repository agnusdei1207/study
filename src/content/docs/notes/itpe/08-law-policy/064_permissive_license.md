## 30초 인출

- 본질: **허용적 라이선스** 는 저작권 표시 및 보증 면책(Disclaimer) 고지 등 최소한의 요건만 준수하면 소스코드 공개 의무 없이 소프트웨어의 자유로운 수정, 상용화 및 독점 소프트웨어로의 재라이선싱을 허용하는 오픈소스 라이선스
- 메커니즘: MIT(최소 고지), BSD 계열(이름 사용 제한 등), Apache 2.0(명시적 특허권 부여 및 NOTICE 파일 보존) 등으로 구성되며, 파생 저작물에 소스코드 공개 전염성을 전파하지 않음
- 통찰: 조건 없는 무료 소프트웨어로 오인하여 NOTICE 파일 누락 및 잠재적 특허 침해 분쟁이 발생하므로 CI/CD 파이프라인 내 오픈소스 고지서 자동 생성과 특허 크로스 라이선스 사전 검토 필수

<details><summary>핵심 용어</summary>

- **허용적 라이선스 (Permissive License)** : 카피레프트(Copyleft)와 대조되는 개념으로, 재배포 시 소스코드 공개 의무를 부과하지 않는 비상호주의 라이선스.
- **MIT License** : 매사추세츠 공과대학교에서 개발한 가장 간결하고 대중적인 라이선스로, 저작권 및 면책 문구 유지 외에 아무런 제약을 두지 않음.
- **BSD License** : 버클리 캘리포니아 대학에서 만든 라이선스로, 3-Clause의 경우 저작권자의 이름을 제품 홍보나 보증에 무단 사용하는 것을 금지함.
- **Apache License 2.0** : 아파치 소프트웨어 재단의 라이선스로, 명시적인 특허권 라이선스 부여, 특허 보복 조항, 코드 수정 표시 및 NOTICE 파일 전달을 의무화.
- **NOTICE 파일** : 원작자가 저작권, 기여자 및 필수 고지사항을 기재한 텍스트 파일로, 재배포 시 반드시 변경 없이 동봉해야 하는 법적 문서.
- **특허 보복 조항 (Patent Retaliation Clause)** : 오픈소스 라이선스 수락자가 해당 오픈소스를 상대로 특허 침해 소송을 제기할 경우 부여받은 특허 라이선스를 즉시 박탈하는 방어 조항.

</details>

## 2~4교시 예상문제 (25점)

> 오픈소스 소프트웨어(OSS) 활용 확산에 따라 기업에서 널리 채택되는 '허용적 라이선스(Permissive License)'의 개념과 카피레프트 라이선스와의 핵심 차이점을 설명하고, 대표적 허용적 라이선스 3종(MIT, BSD, Apache 2.0)의 고지·특허 조항 비교 및 상용 소프트웨어 제품 출시 시의 컴플라이언스 준수 방안을 논하시오. (기출·제122회 1교시 4번 변형·25점)

## 2~4교시 25점 답안

## Ⅰ. 허용적 라이선스의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **허용적 라이선스** 는 원저작자의 저작권 표시와 보증 면책 고지만 유지하면 소스코드 공개 의무 없이 소프트웨어의 자유로운 수정·재배포·상용 판매를 허용하는 오픈소스 라이선스 |
| 목적 | 기술의 신속한 확산과 상용 소프트웨어 생태계와의 원활한 결합 지원, 기업의 지적재산권(IP) 보호 및 오픈소스 활용 극대화 |

## Ⅱ. 대표적 허용적 라이선스 3종의 핵심 요건 및 특징

| 구분 | MIT License | BSD (3-Clause) | Apache License 2.0 |
|---|---|---|---|
| **저작권·면책 고지** | 모든 사본/주요 부분에 저작권 및 면책 고지 필수 | 소스 및 바이너리 배포 시 저작권·면책 문구 유지 | 저작권, 라이선스 사본, 면책 고지 필수 |
| **소스코드 공개 의무**| 소스코드 공개 의무 전무 | 소스코드 공개 의무 전무 | 소스코드 공개 의무 전무 |
| **수정 사실 표시** | 별도 수정 표시 의무 없음 | 별도 수정 표시 의무 없음 | 수정한 모든 파일에 변경 사실 명시 필수 |
| **홍보·이름 사용** | 별도 제한 조항 없음 | 저작권자 이름을 홍보 목적으로 사용 금지 | 상표권 및 저작권자 이름 무단 사용 금지 |
| **NOTICE 파일** | 해당 없음 | 해당 없음 | 원본에 포함된 NOTICE 파일 필수 전달 |
| **특허권 허락** | 명시적 특허 조항 없음 (묵시적) | 명시적 특허 조항 없음 | 명시적 영구 특허 허락 및 특허 보복 조항 |

## Ⅲ. 허용적 라이선스 컴플라이언스 및 배포 관리 프로세스

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ [ 허용적 오픈소스 라이선스 도입 및 상용 배포 컴플라이언스 파이프라인 ]      │
└─────────────────────────────────────────────────────────────────────────────┘
  [ 오픈소스 의존성 반입 (npm, Maven, PyPI) ]
                 │
                 ▼
  [ 라이선스 메타데이터 자동 추출 ] ── SPDX 식별자 대조 (MIT / BSD / Apache-2.0)
                 │
                 ▼
  ┌──────────────────────────────────────────────────────────────┐
  │ [ 라이선스별 세부 의무 요건 자동 충족 게이트 ]               │
  │  - MIT: 저작권 문구 및 면책(DISCLAIMER) 텍스트 추출          │
  │  - BSD: 기여자 명칭의 홍보 브로슈어 배제 여부 확인          │
  │  - Apache 2.0: 수정된 소스 파일 헤더에 변경일시/내역 주석    │
  │               NOTICE 파일 추출 및 중복 제거                  │
  └──────────────────────────────────────────────────────────────┘
                 │
                 ▼
  [ 통합 오픈소스 고지문(Open Source Notice) 자동 생성 ]
                 │
                 ▼
  ┌──────────────────────────────────────────────────────────────┐
  │ [ 상용 제품 형태별 고지물 탑재 및 배포 ]                     │
  │  - 웹 서비스: 하단 Footer 내 '오픈소스 라이선스' 링크 연동   │
  │  - 모바일 앱: 설정 > 오픈소스 라이선스 액티비티(Activity) 삽입│
  │  - 하드웨어/임베디드: 제품 사용설명서 또는 오픈소스 리플릿 동봉│
  └──────────────────────────────────────────────────────────────┘
```

```text
[ Apache 2.0 특허 보복(Patent Retaliation) 메커니즘 ]
[이용자: 특허 소송 제기] ──(해당 Apache SW 대상)──> [특허 라이선스 즉시 자동 해지] ──> [특허 침해 역피소]
```

| 준수 단계 | 주요 수행 내용 | 핵심 산출물 |
|---|---|---|
| **라이선스 식별** | 코드베이스 내 LICENSE 및 COPYING 파일 추출 | 컴포넌트 라이선스 인벤토리, SBOM |
| **수정 사항 추적** | Apache 2.0 라이브러리 내부 직접 수정 여부 확인 | 소스 파일 헤더 변경 주석(Modification Notice) |
| **NOTICE 병합** | 여러 오픈소스에 포함된 NOTICE 파일 텍스트 취합 | 통합 NOTICE.txt 파일 |
| **상용 배포 검증** | 바이너리 및 웹 화면 내 최종 고지문 노출 확인 | 오픈소스 고지문(Open Source Attribution) |

## Ⅳ. 허용적 라이선스와 카피레프트 라이선스 상세 비교

| 비교 항목 | 허용적 라이선스 (MIT / Apache) | 약한 카피레프트 (LGPL / MPL) | 강력한 카피레프트 (GPL / AGPL) |
|---|---|---|---|
| **핵심 철학** | 극대화된 자유와 비즈니스 친화 | 라이브러리 단위의 타협적 자유 | 전체 파생물의 완전한 자유 보장 |
| **소스코드 공개** | 비공개 가능 (독점 상용화 100%) | 라이브러리 자체 수정 시만 공개 | 전체 프로젝트 소스 강제 공개 |
| **결합 방식 제약**| 정적/동적 링크 불문하고 제약 없음 | 동적 링크 시 상용 코드 보호 | 정적/동적 링크 시 전체 전염 |
| **재라이선싱** | 다른 독점 라이선스로 변경 가능 | 불가 (동일 라이선스 유지) | 불가 (GPL 계열 유지 강제) |
| **기업 선호도** | 최우선 채택 (라이선스 리스크 제로) | 아키텍처 격리 하에 채택 | 기업 내 사용 금지 또는 엄격 격리 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| "허용적 라이선스는 제약이 없다"는 개발자의 무지로 인해 상용 소프트웨어 배포 시 저작권 고지문 및 NOTICE 파일 누락으로 계약 위반 발생 | 빌드 툴(Webpack, Gradle) 플러그인을 연동하여 의존성 라이브러리의 라이선스 텍스트를 취합한 `open-source-licenses.html`을 앱 번들에 자동 생성 강제화 |
| 명시적 특허 조항이 없는 MIT/BSD 라이브러리 사용 시 원작자 또는 제3자 특허권자로부터 특허 침해 소송을 당할 잠재적 위험 | 기업의 핵심 전략 제품군에는 명시적 특허 이용허락 및 특허 보복 조항이 구비된 Apache 2.0 라이선스 기반 오픈소스를 우선 선정·도입 |
| Apache 2.0 코드를 내부적으로 커스터마이징하고도 소스코드 파일 상단에 변경 사실(Modification Notice)을 미표기하는 실무적 관리 누락 | 정적 코드 분석(SonarQube 등) 룰셋에 라이선스 헤더 검사 규칙을 추가하여 수정 파일 상단에 변경 주석이 누락된 경우 PR 머지 자동 차단 |

## Ⅵ. 제언

허용적 라이선스를 상용 제품에 안전하게 내재화하기 위하여 CI/CD 기반 고지문 자동화 생성기를 운영하고, 특허 조항 유무에 따른 차등 라이선스 채택 거버넌스 수립.

```text
[ 신규 오픈소스 라이브러리 검토 ]
                 │
                 ▼
[ 라이선스 특허 및 고지 조건 판정 ]
    ├── MIT / BSD ─────> 특허 위험도 분석 후 고지문(License) 추출
    └── Apache 2.0 ────> 특허 보복 조항 확보, NOTICE 파일 및 변경 주석 점검
                 │
                 ▼
[ CI/CD 빌드 파이프라인 연계 ]
    ├── License-Checker 실행: 누락된 라이선스 텍스트 자동 수집
    └── 최종 릴리스 번들 내 About/Licenses 메뉴에 표준 UI 자동 생성
                 │
                 ▼
[ 법무팀 최종 승인 및 컴플라이언스 무결점 제품 출시 ]
```

| 구분 | 수작업 오픈소스 고지 | 제언: CI/CD 연계 자동 고지 거버넌스 |
|---|---|---|
| **고지문 작성** | 릴리스 직전 개발자가 복사·붙여넣기 | 빌드 시 의존성 트리 기반 전수 자동 추출 |
| **NOTICE 처리** | Apache NOTICE 파일의 존재 자체를 무시 | 원본 NOTICE 파일 누락 없이 100% 병합 |
| **특허 리스크** | 특허 소송에 무방비 노출 | Apache 2.0 라이선스 우선 채택으로 특허 방어 |
| **감사 추적성** | 배포 후 사용된 버전 파악 불가 | SPDX 표준 SBOM으로 패키지 버전 및 라이선스 박제 |
