## 연관 키워드

- 허용적 라이선스(Permissive License), MIT, BSD, Apache 2.0
- 저작권 고지, 면책 고지, NOTICE 파일, 특허 보복 조항, 수정 사실 표시
- 카피레프트, 오픈소스 고지문, SPDX, CI/CD, 특허 리스크

## Ⅰ. 허용적 라이선스(Permissive License)의 개요

- 핵심 요약 : 저작권 고지와 면책 문구만 유지하면 소스 공개 의무 없이 수정과 상용 재배포를 허용하는 오픈소스 라이선스.
- 개념 : 원저작자의 저작권 표시와 면책 고지만 남기면, 소스코드 공개 없이 수정·재배포·상용 판매까지 허용하는 **허용적 라이선스**(Permissive License).
- 배경 및 필요성 : 무조건 자유로운 소프트웨어로 오인해 고지문과 NOTICE 파일을 빠뜨리는 실무 사고가 잦고, 명시적 특허 조항의 유무에 따라 특허 분쟁 위험도 달라지므로 자동 고지와 사전 검토가 필요함.
- 주요 목적 : 기술의 빠른 확산과 상용 소프트웨어와의 결합 지원, 오픈소스 활용의 극대화.

## Ⅱ. 허용적 라이선스(Permissive License)의 특징 및 장점

- 핵심 요약 : MIT, BSD, Apache 2.0의 의무 수준이 다르며, 특히 Apache 2.0은 명시적 특허 허락과 고지 요건을 함께 둔 형태.

1. **MIT 라이선스** : 저작권 고지와 허가 문구의 포함만 요구 → 의무가 가장 가벼워 도입 장벽이 낮음.
2. **BSD 계열** : 저작권 고지와 면책 문구를 유지하고, 기여자 이름의 홍보 사용을 제한 → 상표와 명칭 보호.
3. **Apache 2.0** : 명시적 특허 허락과 NOTICE 파일 보존, 수정 사실 표시를 요구 → 특허 분쟁 시 라이선스 종료 조항으로 특허 방어.

## Ⅲ. 허용적 라이선스(Permissive License)의 구조 (흐름)

- 핵심 요약 : 의존성 반입에서 고지문 자동 생성을 거쳐 제품 형태별 고지물을 탑재하는 준수 흐름과, Apache 2.0의 특허 보복 구조로 이루어짐.

```text
[ 허용적 라이선스 준수 흐름 ]

의존성 반입 (npm, Maven, PyPI)
   ↓
라이선스 메타데이터 추출
   ↓
라이선스별 의무 항목 확인
   ↓
오픈소스 고지문 자동 생성
   ↓
제품 형태별 고지물 탑재
```

```text
[ Apache 2.0 특허 보복 구조 ]

이용자가 Apache SW 특허 소송 제기
   ↓
해당 Apache 라이선스 즉시 종료
   ↓
특허 라이선스 상실 (역방향 소송 방어)
```

## Ⅳ. 허용적 라이선스와 카피레프트 라이선스의 비교

- 핵심 요약 : 허용적 라이선스는 결합 방식에 제약이 없고, 카피레프트 라이선스는 파생물까지 공개 의무가 이어진다는 점이 핵심 차이.

| 비교 축 | 허용적 라이선스 (MIT, Apache) | 약한 카피레프트 (LGPL, MPL) | 강한 카피레프트 (GPL, AGPL) |
| --- | --- | --- | --- |
| 핵심 철학 | 극대화된 자유와 상업적 친화 | 라이브러리 단위의 타협 | 파생물 전체의 자유 보장 |
| 소스 공개 | 비공개 상용화 가능 | 라이브러리 수정 시에만 공개 | 전체 프로젝트 공개 |
| 결합 방식 | 정적·동적 링크 제약 없음 | 동적 링크 시 상용 코드 보호 | 결합 시 전체 전염 |
| 재라이선싱 | 독점 라이선스로 변경 가능 | 동일 라이선스 유지 | GPL 계열 유지 강제 |

- 선택 기준 : 상용 제품의 독점 보호와 배포 편의가 중요하면 허용적 라이선스를, 특허 방어가 중요하면 Apache 2.0을 우선 검토함.

## Ⅴ. 허용적 라이선스의 한계와 방안

- 핵심 요약 : 고지문과 NOTICE 누락, 명시적 특허 조항 부재, 수정 표시 누락이 주요 한계이며, 자동 생성과 정적 검사로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 고지문과 NOTICE 파일 누락 | 무제한 사용으로 오인해 계약 위반 발생 | 빌드 도구 플러그인으로 라이선스 텍스트를 모아 앱 번들에 자동 포함 | 고지문 누락 건수 |
| MIT, BSD의 명시적 특허 조항 부재 | 제3자 특허권자의 소송 위험 노출 | 핵심 제품군에는 명시적 특허 허락이 있는 Apache 2.0 우선 채택 | 특허 조항 보유 비율 |
| Apache 2.0 수정 사실 미표기 | 내부 커스터마이징 후 파일 헤더 변경 주석 누락 | 정적 분석 규칙으로 헤더 누락 시 병합 차단 | 헤더 누락 파일 수 |

## Ⅵ. 허용적 라이선스의 실효성 확보를 위한 기술사적 제언

- 핵심 요약 : 고지문 생성을 빌드 파이프라인에 맡기고, 특허 조항 유무를 기준으로 라이선스 채택 정책을 차등화.

고지문은 개발자가 손으로 모으지 않고 빌드 시점에 의존성 트리에서 자동 추출하도록 하며, 그 결과를 SPDX(Software Package Data Exchange) 식별자와 함께 보관해야 한다. 채택 정책은 핵심 제품군과 주변 도구를 나누어, 특허 위험이 큰 영역에는 명시적 특허 허락이 있는 라이선스를 기본값으로 두는 것이 합리적이다. 최종 판단은 라이선스 해석에 따라 법무 검토를 거치도록 절차를 정해 두어야 한다.

## Ⅶ. 결론

- 핵심 요약 : 허용적 라이선스는 자유로운 상용화를 가능하게 하지만, 고지와 특허 관리가 뒤따를 때에만 안전하게 쓸 수 있음.
- 시사점 : 라이선스 준수를 사람의 기억이 아닌 자동화된 고지 체계로 보장하는 조직이 오픈소스 활용의 이점을 지속적으로 얻음.
