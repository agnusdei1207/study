## 연관 키워드

- 정보보호 제품 신속 확인 제도, 신속확인서, 기존 인증 부재, 공인 시험기관
- CC인증(Common Criteria), 보호프로파일(PP, Protection Profile), 보안약점 진단, 취약점 분석·평가
- SBOM(Software Bill of Materials), 공공시장 판로, 정보보호 신기술 제품, 표준 PP 전환

## Ⅰ. 정보보호 제품 신속 확인 제도의 개요

- 핵심 요약 : 기존 인증 기준이 없는 신기술·융복합 정보보호제품을 빠르게 검증해 공공시장 진입을 돕는 임시 확인 제도.
- 개념 : 기존 **CC인증** (Common Criteria, 국제 공통평가기준) 대상이 아닌 정보보호 제품에 시험과 심의를 거쳐 **신속확인서**를 발급하는 제도.
- 배경 및 필요성 : 보호프로파일(PP) 같은 평가기준이 제정되기까지 시간이 걸려 신기술 제품이 공공 도입에서 배제되는 문제가 발생. 정식 기준 이전에 최소 보안성을 먼저 검증하는 경로가 필요함.
- 주요 목적 : 혁신 보안제품의 공공 판로를 열고, 정식 평가기준이 마련될 때까지 공공기관의 보안 수준을 유지.
- 근거 : 과학기술정보통신부 고시 제2022-61호 「정보보호시스템 평가·인증 등에 관한 고시」에 따라 2022년 11월부터 시행(관련 보도 기준).

## Ⅱ. 정보보호 제품 신속 확인 제도의 특징 및 장점

- 핵심 요약 : 기존 인증 부재를 먼저 가려내고 최소 필수 보안성을 짧은 기간에 확인하는 구조가 공공 도입 기간 단축으로 이어짐.

1. 기존 인증 부재 판정 : 신청 제품이 CC인증 등 기존 평가 대상인지 먼저 심사 → 적용 범위가 한정되어 불필요한 인증 절차 감소.
2. 기능·보안 시험 병행 : 기능시험, **보안약점 진단**, **취약점 분석·평가**를 한 흐름에서 수행 → 최소 필수 보안성을 짧은 기간에 확인.
3. 2년 유효 임시 인정 : 확인서 유효기간을 2년으로 두어 정식 기준 마련을 유도 → 공공 판로는 빠르게 열고 장기 보증은 정식 인증으로 연결.

## Ⅲ. 정보보호 제품 신속 확인 제도의 구조 (흐름)

- 핵심 요약 : 기존 인증 부재 판정 뒤 공인 시험기관 시험과 심의위원회 의결을 거쳐 확인서가 발급되는 단계형 구조.

```text
[ 신속 확인 절차 ]

신청 (제조사)
   ↓
기존 인증 대상 여부 심사
   ↓ (기존 인증 부재 판정 시)
공인 시험기관 시험
   ↓
신속확인심의위원회 의결
   ↓
신속확인서 발급 (유효 2년)
```

- 공인 시험기관은 기능시험, 보안약점 진단, 취약점 분석·평가의 3대 시험 항목을 수행한다.

```text
[ 3대 시험 항목 ]

1. 기능시험
   - 제품 고유 보안기능 동작 확인
2. 보안약점 진단
   - 소스코드 정적 분석, 입력값 검증
3. 취약점 분석·평가
   - 알려진 취약점 점검, 인증 우회 시험
```

## Ⅳ. 정보보호 제품 신속 확인 제도와 유사 제도의 비교

- 핵심 요약 : 평가기준이 있는 제품은 CC인증이나 성능평가로, 기준이 없는 신기술 제품은 신속확인으로 가르는 상보적 관계.

| 비교 축 | 정보보호 제품 신속 확인 | CC인증 | 정보보호 제품 성능평가 |
| --- | --- | --- | --- |
| 적용 대상 | 평가기준이 없는 신기술·융복합 제품 | 보호프로파일이 있는 제품 | 고시로 지정된 성능평가 품목 |
| 평가 초점 | 최소 필수 보안성 | 구조적 보안 보증 | 성능 지표 |
| 유효 기간 | 발급일로부터 2년 | 보증 수준과 인증 체계에 따름 | 제도 고시에 따름 |
| 공공 효력 | 공공 도입 판로 확보 | 공공 도입 자격의 근거 | 기술평가 가점 등 |

- 선택 기준 : 제품에 적용 가능한 평가기준이 있는지 먼저 확인하고, 없을 때만 신속확인 경로를 택함.

## Ⅴ. 정보보호 제품 신속 확인 제도의 한계와 방안

- 핵심 요약 : 임시 인정 기간의 만료, 인증 후 형상 변경, 오픈소스 취약점 세 가지 한계를 정식 기준 연계와 지속 검증으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 유효기간 만료 전 정식 PP 미제정 | 2년 만료 시 도입 기관의 철거·교체 부담 발생 | 확인서 발급과 동시에 PP 개발 과제 연계 | 확인서 대비 정식 인증 전환율 |
| 확인 후 소스코드 무단 변경 | 패치와 기능 추가 과정에서 형상이 달라져 보안 보증 훼손 | 형상관리 태그와 연동한 빌드 검증, 변경 범위 기준 재시험 | 변경 후 재시험 완료율 |
| 오픈소스 컴포넌트 신규 취약점 | 의존 라이브러리의 취약점 파악과 패치가 지연 | SBOM 제출 의무화와 취약점 정보 연계 알림 | 미조치 취약점 경과 일수 |

## Ⅵ. 정보보호 제품 신속 확인 제도에 대한 기술사적 제언

- 핵심 요약 : 확인 이후의 생명주기 관리를 제도 안에 넣어, 신속 확인이 임시 통과로 끝나지 않도록 설계.

확인서 발급 기관은 발급 시점에 정식 보호프로파일 개발 과제를 함께 등록하고, 제조사는 SBOM을 기준으로 의존성 변화를 발급 이후에도 보고하는 체계를 갖추어야 한다. 아울러 빌드 파이프라인에서 보안 점검을 상시 반복하면, 2년 유효기간에 쫓기지 않고 제품의 보안 상태를 실제로 확인할 수 있다.

## Ⅶ. 결론

- 핵심 요약 : 신속 확인 제도는 평가기준 공백을 메우는 임시 판로이며, 정식 인증과 지속 검증으로 이어질 때 효과가 완성됨.
- 시사점 : 발급된 확인서는 공공 도입의 출발점일 뿐이므로, 정식 기준 전환과 공급망 점검을 함께 관리하는 것이 제도의 신뢰를 지키는 길임.
