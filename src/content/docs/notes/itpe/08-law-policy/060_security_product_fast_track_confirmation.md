## 30초 인출

- 본질: **정보보호제품 신속확인 제도** 는 기존 공통평가기준(CC)의 보호프로파일(PP)이 마련되지 않은 AI, 양자암호, 클라우드 등 신기술·융복합 정보보호제품이 공공기관에 신속히 도입될 수 있도록 보안성과 기능성을 검증하는 특별 평가 제도
- 메커니즘: 신청 제품의 기존 인증 부재 확인 후, 공인 제3자 시험기관에서 취약점 분석·평가 및 소프트웨어 보안약점(CWE)을 진단하고 신속확인심의위원회를 거쳐 2년 유효기간의 확인서 발급
- 통찰: 확인서 발급 이후 빈번한 소스코드 패치에 따른 형상 왜곡 및 신규 제로데이 취약점 전이를 차단하기 위해 SBOM(소프트웨어 자재명세서) 기반 공급망 추적과 정식 보호프로파일(PP) 개발 연계 필수

<details><summary>핵심 용어</summary>

- **신속확인제도** : CC인증 기준이 없어 공공 진입이 막혔던 혁신 보안 신제품의 공공 판로를 개척하기 위한 패스트트랙(Fast-Track) 보안성 확인 제도.
- **공통평가기준 (CC, Common Criteria)** : 정보보호제품의 보안 기능을 국제적으로 표준화된 기준으로 평가·인증하는 ISO/IEC 15408 표준.
- **보호프로파일 (PP, Protection Profile)** : 방화벽, 침입탐지 등 특정 제품군이 반드시 충족해야 할 구현 독립적 보안 요구사항 명세서.
- **소프트웨어 보안약점 진단** : 소스코드 내 잠재적인 보안 결함(SQL 인젝션, XSS, 버퍼 오버플로우 등)을 시큐어 코딩 기준(행안부 49개 조항)으로 검사하는 활동.
- **보안적합성 검증** : 국가·공공기관이 도입하는 IT 보안제품에 대해 국가정보원(국가사이버안보센터)이 취약성 여부를 최종 확인하는 절차.
- **SBOM (Software Bill of Materials)** : 소프트웨어를 구성하는 오픈소스 및 상용 라이브러리의 버전, 종속성, 라이선스 정보를 명시한 부품 명세서.

</details>

## 2~4교시 예상문제 (25점)

> 인공지능, 제로트러스트, 양자암호 등 신기술 기반 정보보호제품의 공공 수요 증가에 대응하여 도입된 '정보보호제품 신속확인 제도'의 목적과 대상 판정 기준, 3대 시험 항목(취약점·보안약점·기능시험)을 설명하고, CC인증과의 비교 및 공공기관 그룹별(가·나·다) 도입 기준과 사후관리 방안을 논하시오. (기출·제129회 1교시 11번 변형·25점)

## 2~4교시 25점 답안

## Ⅰ. 정보보호제품 신속확인 제도의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **정보보호제품 신속확인 제도** 는 국가용 보안요구사항이나 CC인증 평가기준(PP)이 없어 공공 진입이 불가능한 신기술·융복합 보안제품을 대상으로 보안성과 기능성을 신속 평가·인정하는 제도 |
| 목적 | 혁신 정보보호 신제품의 신속한 공공시장 진출 지원, 국가·공공기관의 신종 사이버 위협 대응력 강화 및 정보보호 산업 생태계 활성화 |

## Ⅱ. 신속확인 제도의 핵심 평가 요건 및 특징

| 구분 | 주요 기준 | 상세 특징 및 기술적 요건 |
|---|---|---|
| **대상 판정** | 기존 인증 기준 부재 | 신청 제품이 기존 CC인증(보호프로파일), 성능평가 등의 평가 대상에 해당하지 않음을 사전 심사 |
| **유효 기간** | 발급일로부터 2년 | 임시 도입 수단으로 2년 유효기간 부여 (정식 PP 개발 시 표준 CC인증 전환 유도) |
| **평가 주체** | 독립 제3자 시험기관 | 제조사와 이해관계가 없는 한국인터넷진흥원(KISA) 지정 공인 시험기관에서 기술 시험 전담 |
| **3대 기술 시험** | 기능성 및 보안성 검증 | 주요 기능시험(GS 1등급 대체 가능), 소프트웨어 보안약점 진단(시큐어 코딩), 취약점 분석·평가 |
| **형상 관리** | 변경 승인 의무화 | 소스코드 수정, 보안 기능 변경 발생 시 영향도 분석 및 변경 승인 절차 필수 이행 |

## Ⅲ. 신속확인 심사·발급 절차 및 공공기관 도입 프로세스

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ [ 정보보호제품 신속확인 신청·시험·심의 및 공공 도입 파이프라인 ]            │
└─────────────────────────────────────────────────────────────────────────────┘
  [ 제조사 (신청기업) ] ──> 대상 여부 검토 신청서 및 제품 기능설명서 제출
           │
           ▼
  [ 신속확인기관 (KISA) ] ──> 기존 인증제도(CC/PP) 적용 가능 여부 심사
           │ (기존 기준 없음 판정 시)
           ▼
  [ 공인 제3자 시험기관 (KISA, TTA 등) 기술 시험 ]
    ├── 1. 기능시험: 제품설명서 기반 정상 동작 검증 (GS인증 대체 가능)
    ├── 2. 보안약점 진단: 시큐어 코딩 정적 분석 (행안부 가이드 49개 점검)
    └── 3. 취약점 분석: 포트 스캔, 동적 모의해킹(Known/Unknown CVE 검증)
           │
           ▼ (시험성적서 발급)
  [ 신속확인심의위원회 ] ── 산·학·연·관 전문가 심의 및 적합 여부 의결
           │
           ▼
  [ 신속확인서 교부 (유효기간: 2년) ]
           │
           ▼
  ┌──────────────────────────────────────────────────────────────┐
  │ [ 공공기관 도입 및 보안적합성 검증 분기 ]                     │
  │  - '나·다' 그룹 (지자체·공사): 별도 보안적합성 검증 없이 즉시 도입 │
  │  - '가' 그룹 (중앙행정기관·국방): 국가사이버안보센터 검증 후 도입 │
  └──────────────────────────────────────────────────────────────┘
```

```text
[ 3대 핵심 시험 항목 구조 ]
┌─────────────────────────┬─────────────────────────┬─────────────────────────┐
│     1. 기능시험         │   2. 보안약점 진단      │    3. 취약점 분석·평가   │
├─────────────────────────┼─────────────────────────┼─────────────────────────┤
│ - 제품 고유 보안기능    │ - 소스코드 정적 분석    │ - 네트워크 패킷 분석    │
│ - 관리자 통제 인터페이스│ - 입력값 검증, 메모리   │ - 알려진 CVE 취약점 진단│
│ - 정상 입출력 무결성    │ - 암호 알고리즘 적용    │ - 모의 침투 및 인증 우회│
└─────────────────────────┴─────────────────────────┴─────────────────────────┘
```

| 절차 단계 | 주요 수행 주체 | 산출물 및 기준 |
|---|---|---|
| **대상 확인** | KISA 신속확인사무국 | 대상 여부 확인 통보서 (기존 인증 부재 확인) |
| **시험 의뢰** | 신청 기업 → 공인 시험기관 | 시험신청서, 제품 소스코드, 관리자 매뉴얼 |
| **보안 시험** | 제3자 시험기관 | 소프트웨어 보안약점 진단서, 취약점 시험성적서 |
| **심의 의결** | 신속확인심의위원회 | 심의의결서 (적합/부적합/조건부 판정) |
| **공공 조달** | 조달청 (디지털서비스몰) | 정보보호제품 신속확인서 (혁신시제품 지정 등록) |

## Ⅳ. 신속확인 제도 vs CC인증 vs 성능평가 제도 비교

| 비교 항목 | 정보보호제품 신속확인 | CC인증 (Common Criteria) | 정보보호제품 성능평가 |
|---|---|---|---|
| **적용 대상** | 평가기준(PP)이 없는 신기술 제품 | 표준 보호프로파일(PP) 기보유 제품 | 침입방지시스템, 백신 등 고시 품목 |
| **평가 초점** | 최소 필수 보안성(취약점·약점) | 구조적 보안 보증(EAL2~EAL4) | 트래픽 처리량, 탐지율 등 성능 지표 |
| **소요 기간** | 약 2~3개월 (패스트트랙) | 약 6개월~1년 이상 소요 | 약 1~2개월 소요 |
| **유효 기간** | 2년 (제한적 1회 연장) | 3년~5년 (국내/국제용) | 2년 |
| **공공 효력** | 나·다 그룹 보안적합성 면제 | 전 공공기관 도입 자격 획득 | 공공 도입 시 기술평가 가점 부여 |
| **제도 목적** | 신시장 창출 및 신속 진입 | 엄격한 보안 신뢰성 국제 공인 | 외산 대비 처리 성능 및 품질 검증 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 2년 한시적 확인서의 만료 시점에 맞춰 정식 보호프로파일(PP)이 제정되지 않을 경우 도입 공공기관의 철거·교체 위기 | 과기정통부-국안센 협업을 통해 신속확인 제품 발급 즉시 표준 PP 개발 과제로 직결하고, 심사 트랙을 일반 CC인증으로 패스트트랙 연계 |
| 신속확인서 획득 이후 지속적인 기능 추가 및 버그 패치 과정에서 비인가 소스코드 수정으로 인한 백도어·취약점 노출 | 소스코드 변경 관리(Git Tag)와 연동된 빌드 검증 파이프라인을 운영하고, 주요 형상 변경 시 신속 재시험(Delta Testing) 간소화 |
| 공급망 소프트웨어에 포함된 오픈소스 컴포넌트의 신규 취약점(Log4j 등)에 대한 실시간 파악 및 사후 패치 지연 | 신속확인 신청 시 SPDX/CycloneDX 표준 SBOM 제출을 의무화하고, KISA 취약점 정보 포털과 연계한 자동 패치 권고 알림 체계 구축 |

## Ⅵ. 제언

신기술 보안제품의 공공망 안전성을 담보하기 위하여 SBOM 기반의 지속적 공급망 검증을 결합하고 유효기간 내 정식 국가 표준 PP로 전환하는 전주기 생명주기 거버넌스 수립.

```text
[ 신기술 보안제품 개발 완료 ]
                 │
                 ▼
[ 신속확인서 획득 (2년 유효) ] ── CycloneDX 표준 SBOM 등록
                 │
                 ▼
[ 공공기관 '나·다' 그룹 도입 및 운영 ]
                 │
                 ▼ (상시 관제 및 패치)
[ 실시간 오픈소스 취약점(CVE) 자동 스캐너 연동 ] ──> 패치 발생 시 KISA 변경 승인
                 │
                 ▼ (만료 6개월 전)
[ 표준 국가용 보호프로파일(PP) 완성 ──> 정식 CC인증 전환 완료 ]
```

| 구분 | 한시적 임시 도입 관행 | 제언: SBOM 연계 전주기 관리 체계 |
|---|---|---|
| **도입 목적** | 판로 개척을 위한 확인서 획득 | 공공망 실증 후 정식 표준 규격(PP) 전환 |
| **소스 통제** | 1회성 정적 시큐어 코딩 점검 | CI/CD 파이프라인 상시 취약점 자동 재검증 |
| **공급망 보안**| 오픈소스 라이브러리 파악 불가 | SBOM 의무화 기반 의존성 실시간 모니터링 |
| **사후 관리** | 2년 후 만료 시 혼란 야기 | 표준 CC인증 마이그레이션 로드맵 사전 확정 |

## 출제 이력과 검증 출처

- 제129회 정보관리기술사 1교시 11번: 정보보호제품 신속확인 제도의 개념 및 도입 절차
- 과학기술정보통신부 고시 「정보보호시스템 평가·인증 지침」
- 한국인터넷진흥원(KISA) 「정보보호제품 신속확인제도 운영세칙 및 가이드라인」
- 국가정보원 「국가·공공기관 정보보호제품 도입기준 및 보안적합성 검증안내서」

- 공통평가기준 (CC인증)
- 소프트웨어 개발보안 (시큐어 코딩)
- 보안적합성 검증
- SBOM (소프트웨어 자재명세서)
