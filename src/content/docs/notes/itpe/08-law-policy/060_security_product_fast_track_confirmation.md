## Ⅰ. 정보보호 제품 신속 확인 제도의 개요

- **개념** : 국가용 보안요구사항이나 CC인증 평가기준(PP)이 없어 공공 진입이 불가능한 신기술·융복합 보안제품을 대상으로 보안성과 기능성을 신속 평가·인정하는 제도.
- **제정 배경 및 필요성** : 확인서 발급 이후 빈번한 소스코드 패치에 따른 형상 왜곡 및 신규 제로데이 취약점 전이를 차단하기 위해 SBOM(소프트웨어 자재명세서) 기반 공급망 추적과 정식 보호프로파일(PP) 개발 연계 필수.
- **핵심 목적** : 혁신 정보보호 신제품의 신속한 공공시장 진출 지원, 국가·공공기관의 신종 사이버 위협 대응력 강화 및 정보보호 산업 생태계 활성화.

## Ⅱ. 정보보호 제품 신속 확인 제도의 법제도 체계 및 핵심 메커니즘

정보보호 제품 신속 확인 제도은(는) 신청 제품의 기존 인증 부재 확인 후, 공인 제3자 시험기관에서 취약점 분석·평가 및 소프트웨어 보안약점(CWE)을 진단하고 신속확인심의위원회를 거쳐 2년 유효기간의 확인서 발급 과정을 거쳐 체계적인 법제도적 통제와 기술적 신뢰성을 확보함.

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ [ 정보보호제품 신속확인 신청·시험·심의 및 공공 도입 파이프라인 ]            │
└─────────────────────────────────────────────────────────────────────────────┘
  [ 제조사 (신청기업) ] ──> 대상 여부 검토 신청서 및 제품 기능설명서 제출
           │
           ▼
  [ 신속확인기관 (KISA) ] ──> 기존 인증제도(CC/PP) 적용 가능 여부 심사
           │ (기존 기준 없음 판정 시)
           ▼
  [ 공인 제3자 시험기관 (KISA, TTA 등) 기술 시험 ]
    ├── 1. 기능시험: 제품설명서 기반 정상 동작 검증 (GS인증 대체 가능)
    ├── 2. 보안약점 진단: 시큐어 코딩 정적 분석 (행안부 가이드 49개 점검)
    └── 3. 취약점 분석: 포트 스캔, 동적 모의해킹(Known/Unknown CVE 검증)
           │
           ▼ (시험성적서 발급)
  [ 신속확인심의위원회 ] ── 산·학·연·관 전문가 심의 및 적합 여부 의결
           │
           ▼
  [ 신속확인서 교부 (유효기간: 2년) ]
           │
           ▼
  ┌──────────────────────────────────────────────────────────────┐
  │ [ 공공기관 도입 및 보안적합성 검증 분기 ]                     │
  │  - '나·다' 그룹 (지자체·공사): 별도 보안적합성 검증 없이 즉시 도입 │
  │  - '가' 그룹 (중앙행정기관·국방): 국가사이버안보센터 검증 후 도입 │
  └──────────────────────────────────────────────────────────────┘

[ 3대 핵심 시험 항목 구조 ]
┌─────────────────────────┬─────────────────────────┬─────────────────────────┐
│     1. 기능시험         │   2. 보안약점 진단      │    3. 취약점 분석·평가   │
├─────────────────────────┼─────────────────────────┼─────────────────────────┤
│ - 제품 고유 보안기능    │ - 소스코드 정적 분석    │ - 네트워크 패킷 분석    │
│ - 관리자 통제 인터페이스│ - 입력값 검증, 메모리   │ - 알려진 CVE 취약점 진단│
│ - 정상 입출력 무결성    │ - 암호 알고리즘 적용    │ - 모의 침투 및 인증 우회│
└─────────────────────────┴─────────────────────────┴─────────────────────────┘
```

- **대상 판정** : 기존 인증 기준 부재 - 신청 제품이 기존 CC인증(보호프로파일), 성능평가 등의 평가 대상에 해당하지 않음을 사전 심사.
- **유효 기간** : 발급일로부터 2년 - 임시 도입 수단으로 2년 유효기간 부여 (정식 PP 개발 시 표준 CC인증 전환 유도).
- **평가 주체** : 독립 제3자 시험기관 - 제조사와 이해관계가 없는 한국인터넷진흥원(KISA) 지정 공인 시험기관에서 기술 시험 전담.
- **3대 기술 시험** : 기능성 및 보안성 검증 - 주요 기능시험(GS 1등급 대체 가능), 소프트웨어 보안약점 진단(시큐어 코딩), 취약점 분석·평가.

## Ⅲ. 정보보호 제품 신속 확인 제도의 세부 규정 및 국내외 제도 비교 분석

| 비교 항목 | 정보보호제품 신속확인 | CC인증 (Common Criteria) | 정보보호제품 성능평가 |
|---|---|---|---|
| **적용 대상** | 평가기준(PP)이 없는 신기술 제품 | 표준 보호프로파일(PP) 기보유 제품 | 침입방지시스템, 백신 등 고시 품목 |
| **평가 초점** | 최소 필수 보안성(취약점·약점) | 구조적 보안 보증(EAL2~EAL4) | 트래픽 처리량, 탐지율 등 성능 지표 |
| **소요 기간** | 약 2~3개월 (패스트트랙) | 약 6개월~1년 이상 소요 | 약 1~2개월 소요 |
| **유효 기간** | 2년 (제한적 1회 연장) | 3년~5년 (국내/국제용) | 2년 |
| **공공 효력** | 나·다 그룹 보안적합성 면제 | 전 공공기관 도입 자격 획득 | 공공 도입 시 기술평가 가점 부여 |

- **제도적 시사점** : 정보보호 제품 신속 확인 제도은(는) 상기 비교 지표를 바탕으로 법적 의무 준수와 비즈니스 연속성 간의 균형을 확보하고, 규제 환경 변화에 선제적으로 대응할 수 있는 아키텍처 및 거버넌스 체계를 확립해야 함.

## Ⅳ. 정보보호 제품 신속 확인 제도의 주요 한계점 및 해결 방안

- **2년 한시 확인서 만료 전 표준 PP 미제정 시 기도입 제품 철거 위기** :
  - **한계점** : 2년 한시적 확인서의 만료 시점에 맞춰 정식 보호프로파일(PP)이 제정되지 않을 경우 도입 공공기관의 철거·교체 위기.
  - **해결 방안** : 과기정통부-국안센 협업을 통해 신속확인 제품 발급 즉시 표준 PP 개발 과제로 직결하고, 심사 트랙을 일반 CC인증으로 패스트트랙 연계.
- **신속확인 후 소스코드 추가 수정 및 패치 시 백도어·취약점 노출 위험** :
  - **한계점** : 신속확인서 획득 이후 지속적인 기능 추가 및 버그 패치 과정에서 비인가 소스코드 수정으로 인한 백도어·취약점 노출.
  - **해결 방안** : 소스코드 변경 관리(Git Tag)와 연동된 빌드 검증 파이프라인을 운영하고, 주요 형상 변경 시 신속 재시험(Delta Testing) 간소화.
- **공급망 오픈소스 라이브러리 신규 보안 취약점의 실시간 모니터링 한계** :
  - **한계점** : 공급망 소프트웨어에 포함된 오픈소스 컴포넌트의 신규 취약점(Log4j 등)에 대한 실시간 파악 및 사후 패치 지연.
  - **해결 방안** : 신속확인 신청 시 SPDX/CycloneDX 표준 SBOM 제출을 의무화하고, KISA 취약점 정보 포털과 연계한 자동 패치 권고 알림 체계 구축.

## Ⅴ. 정보보호 제품 신속 확인 제도 정착 및 실효성 확보를 위한 기술사적 제언

신기술 보안제품의 공공망 안전성을 담보하기 위하여 SBOM 기반의 지속적 공급망 검증을 결합하고 유효기간 내 정식 국가 표준 PP로 전환하는 전주기 생명주기 거버넌스 수립.

- **도입 목적 관점의 고도화 및 실무 전환** : 판로 개척을 위한 확인서 획득의 한계와 비효율을 탈피하고, 공공망 실증 후 정식 표준 규격(PP) 전환을 체계적으로 도입·적용하여 실무적 신뢰성과 거버넌스 실효성을 극대화해야 함.
- **소스 통제 관점의 고도화 및 실무 전환** : 1회성 정적 시큐어 코딩 점검의 한계와 비효율을 탈피하고, CI/CD 파이프라인 상시 취약점 자동 재검증을 체계적으로 도입·적용하여 실무적 신뢰성과 거버넌스 실효성을 극대화해야 함.
- **공급망 보안 관점의 고도화 및 실무 전환** : 오픈소스 라이브러리 파악 불가의 한계와 비효율을 탈피하고, SBOM 의무화 기반 의존성 실시간 모니터링을 체계적으로 도입·적용하여 실무적 신뢰성과 거버넌스 실효성을 극대화해야 함.
