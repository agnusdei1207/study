## 연관 키워드

- 초거대 AI(Hyper-scale AI), 생성형 AI, 파운데이션 모델, sLLM(small LLM), RAG(Retrieval-Augmented Generation)
- 프롬프트 인젝션, 환각(Hallucination), HITL(Human in the Loop), CSAP(Cloud Security Assurance Program)
- 범정부 AI 공통기반, PII(Personally Identifiable Information), RBAC(Role-Based Access Control), 공무원 최종 승인

## Ⅰ. 공공부문 초거대 AI 도입·활용 가이드라인 2.0의 개요

- 핵심 요약 : 행정기관이 생성형 AI를 기획부터 성과관리까지 안전하게 도입·운영하도록 안내하는 공공 실무 지침.
- 개념 : 행정·공공기관이 **초거대 AI** (Hyper-scale AI)와 생성형 AI(Generative AI) 기술을 도입할 때 따를 단계별 기준을 정리한 실무 지침.
- 배경 및 필요성 : 공공기관의 생성형 AI 도입이 개념 실증(PoC, Proof of Concept) 단계에서 실제 업무 적용으로 옮겨가면서, 환각과 데이터 유출, 프롬프트 인젝션 같은 위험을 통제할 기준이 필요해졌다. 2026년 6월 행정안전부는 공공부문 AI 도입을 지원하는 실무 가이드를 전국 공공기관에 배포한다고 보도 자료로 밝혔으며, 2.0 개정 세부 내용은 발표 주체의 원문으로 확인해야 한다.
- 주요 목적 : 행정 생산성을 높이되, 환각과 정보 유출을 사전에 막고, 범정부 AI 공통기반을 공유해 중복 투자를 줄이는 데 있다.

## Ⅱ. 공공부문 초거대 AI 도입 지침의 특징 및 장점

- 핵심 요약 : 전 주기 관리, 공통 기반 활용, 지식 연계형 답변, 다계층 보안이 결합해 도입 위험과 비용을 함께 낮추는 방식.

1. 전 주기 관리 : 기획, 구축, 운영, 성과평가 단계별 산출물을 표준화 → 사업 중단과 재투자 위험 감소.
2. **범정부 AI 공통기반** (국가 차원의 GPU 자원과 파운데이션 모델을 기관이 공동으로 활용하는 기반) : 자체 전산실 구축을 지양 → 인프라 중복 투자 감소.
3. **RAG** (Retrieval-Augmented Generation, 외부 지식을 검색해 답변의 근거로 삼는 방식) : 기관 내부 행정 지침을 검색 DB로 연계 → 근거 있는 답변과 **환각** (Hallucination, 사실과 다른 그럴듯한 생성) 억제.
4. 다계층 보안 : 개인정보 가명처리와 마스킹, **프롬프트 인젝션** (Prompt Injection, 악의적 입력으로 지시를 바꾸는 공격) 차단, 보안 인증을 받은 클라우드 활용 (CSAP, Cloud Security Assurance Program) → 정보 유출 위험 감소.

## Ⅲ. 아키텍처 유형과 통제 계층의 구조 (흐름)

- 핵심 요약 : 사용자 입력이 가드레일과 검색기를 거쳐 모델에 도달하고, 응답은 사람의 승인을 거쳐 행정 처리로 이어지는 통제 흐름.

```text
[ 사용자 질의 ]
      ↓
[ 프롬프트 가드레일 ]
PII 필터·입력 검증
      ↓
[ RAG 지식 검색 ]
행정 지식 DB (RBAC 접근통제)
      ↓
[ 초거대 AI 모델 ]
공통기반 또는 인증 클라우드
      ↓
[ 응답 필터링과 HITL ]
출처 표기 검증 → 공무원 최종 승인
```

```text
도입 단계별 추진
기획·수요검토 → 설계·구축
      ↓
검증·배포 → 운영·성과관리
```

## Ⅳ. 도입 아키텍처 유형의 비교

- 핵심 요약 : 공통기반 연계형은 비용이, 기관 전용 sLLM 구축형은 보안이, 민간 SaaS 연계형은 구축 속도가 강점인 구조.

| 구분 | 범정부 AI 공통기반 연계형 | 기관 전용 sLLM 구축형 | 민간 공공 클라우드 SaaS 연계형 |
| --- | --- | --- | --- |
| 개념 | 공통 GPU와 파운데이션 모델을 API로 활용 | 기관 내부에 소형 특화 모델을 구축 | 인증 받은 민간 생성형 AI를 API로 연동 |
| 인프라 비용 | 낮음 (공동 활용 자원) | 높음 (고성능 서버 구축) | 중간 (이용량 기반 요금) |
| 보안성 | 우수 (국가 정보통신망 연동) | 최고 (폐쇄망 운영) | 양호 (보안 인증과 전송 암호화) |
| 적합 서비스 | 범용 행정 지원, 문서 요약 | 최고 보안등급 업무 | 대민 안내 챗봇, 교육 서비스 |
| 구축 난이도 | 낮음 (표준 API 호출) | 높음 (파인튜닝과 MLOps 필요) | 낮음 (SaaS 설정과 프롬프트 조정) |

- 선택 기준 : 업무의 보안등급과 데이터 민감도를 먼저 나누고, 그 결과에 따라 아키텍처 유형을 정한다.

## Ⅴ. 도입 지침의 한계와 방안

- 핵심 요약 : 지식베이스 최신성, 환각에 따른 책임, 인프라 중복 투자 문제를 접근 통제와 사람 승인, 공통기반 활용으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 지식베이스 최신성 부족과 비공개 데이터 노출 | 검색 인덱스가 낡거나 권한 없는 문서가 노출될 위험 | 메타데이터 기반 접근 권한(RBAC, ABAC)과 임베딩 갱신 파이프라인 | 인덱스 갱신 지연, 권한 외 노출 건수 |
| 환각에 따른 오답과 책임 소재 불명확 | 생성 결과가 행정 처분의 근거가 되면 법적 책임이 모호해짐 | 행정 결정 자동화 배제, 공무원 최종 승인(HITL), 출처 표기 강제 | 오답률, 승인 전 반려 건수 |
| 고성능 인프라 중복 투자 | 기관마다 GPU 서버를 따로 구축해 비용이 커짐 | 범정부 AI 공통기반 우선 활용과 sLLM 기반 공공 특화 파인튜닝 | 공통기반 활용률, 기관별 인프라 투자액 |

## Ⅵ. 공공부문 초거대 AI 도입에 대한 기술사적 제언

- 핵심 요약 : 행정의 무결성과 대민 신뢰를 우선으로 두고, 기술 통제를 사업 검수 기준에 넣는 거버넌스가 핵심.

1. 행정기관은 신규 사업을 기획할 때 범정부 AI 공통기반 활용 여부를 먼저 검토하고, 자체 구축은 보안등급상 불가피한 경우로 한정한다.
2. 정보화 부서는 프롬프트 가드레일, RBAC 기반 검색, 출처 표기를 기본 기능으로 두고, 이를 검수 항목으로 명시한다.
3. 감사·법무 조직은 AI 응답이 행정 처리에 쓰이는 경로마다 공무원 승인 지점을 지정하고, 그 기록을 주기적으로 점검한다.

## Ⅶ. 결론

- 핵심 요약 : 공공 초거대 AI는 공통기반과 통제 계층을 갖춘 상태에서만 행정 생산성을 높이는 도구가 된다.
- 시사점 : 기술의 성능보다 행정 무결성과 책임 구조가 먼저 확보되어야 도입 효과가 지속된다.
