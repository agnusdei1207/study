## 연관 키워드

- 데이터 주권(Data Sovereignty), 데이터 현지화(Data Residency), 역외 관할권, CLOUD Act
- 고객 관리 키, HYOK(Hold Your Own Key), 기밀 컴퓨팅(Confidential Computing), 소버린 클라우드(Sovereign Cloud)
- 국외 이전, 동형암호(HE, Homomorphic Encryption), 에어갭(Air-Gapped)

## Ⅰ. 데이터 주권의 개요

- 핵심 요약 : 데이터의 저장과 처리가 데이터가 속한 국가의 관할권과 통제 아래 있어야 한다는 원칙.
- 개념 : 데이터의 생성, 처리, 보관, 활용 전 과정이 해당 국가의 **사법적 관할권**과 통제권 아래 유지되어야 한다는 원칙 (**데이터 주권**, Data Sovereignty).
- 배경 및 필요성 : 국내 공공과 민간이 해외 클라우드 사업자에 의존하는 비중이 커졌고, 미국 **CLOUD Act**(2018년 제정, 미국 사업자가 보유한 데이터에 대한 미국 당국의 제출 명령 근거)처럼 역외 관할권이 데이터에 미치는 위험이 제기됨.
- 주요 목적 : 해외 사법 당국의 무단 제출 요구를 막고, 국가 기관과 국민의 데이터에 대한 통제권을 지키는 것.

## Ⅱ. 데이터 주권 보장의 특징 및 장점

- 핵심 요약 : 위치, 키, 연산, 운영의 네 계층이 함께 작동해야 데이터 통제가 성립하는 구조.

1. 데이터 현지화 : 저장 위치를 국내로 제한 → 물리적 위치 통제.
2. 키 주권 : 암호키를 고객이 보유 (**HYOK**, Hold Your Own Key) → 사업자가 평문에 접근할 수 없게 함.
3. 연산 주권 : 메모리 연산 중에도 보호되는 **기밀 컴퓨팅**(Confidential Computing) 환경 사용 → 처리 과정의 노출 차단.
4. 운영 주권 : 인가된 국내 인력만 인프라를 유지보수 → 원격 접근 통제.

## Ⅲ. 데이터 주권 보장의 구조 (흐름)

- 핵심 요약 : 저장 위치에서 운영 인력까지 네 계층을 쌓아 통제 범위를 넓히는 구조.

```text
[ 데이터 주권 계층 ]

1. 데이터 현지화 (국내 저장)
   ↓
2. 키 주권 (고객 보유 키)
   ↓
3. 연산 주권 (기밀 컴퓨팅)
   ↓
4. 운영 주권 (인가된 인력만 접근)
```

- 국내 법적 근거 : 개인정보 보호법 제28조의8은 개인정보의 국외 이전을 정보주체 동의 또는 법정 보호조치 요건 충족 등 일정 요건에 한정하고 있음.

```text
[ 외국 제출 요구 시 기술 차단 ]

외국 당국의 제출 요구
   ↓
고객이 암호키를 보유하는지 확인
   ↓
보유 시 사업자의 복호화 불가
```

## Ⅳ. 데이터 현지화와 데이터 주권의 비교

- 핵심 요약 : 현지화는 데이터의 위치를 다루고, 데이터 주권은 누가 접근하고 어떤 법이 적용되는지를 다룸.

| 비교 항목 | 데이터 현지화 (Data Residency) | 데이터 주권 (Data Sovereignty) |
| --- | --- | --- |
| 통제의 초점 | 데이터가 어디에 저장되는가 | 데이터에 누가 접근하고 어떤 관할권이 미치는가 |
| 보안 수단 | 국내 데이터센터 저장 | 고객 키 보유, 기밀 컴퓨팅, 운영 통제 |
| 역외 관할권 대응 | 저장 위치만으로는 대응이 어려움 | 키와 접근 통제로 제출 가능성을 크게 낮춤 |
| 관리자 접근 | 해외 원격 접근이 허용될 수 있음 | 인가된 국내 인력으로 제한 |

- 선택 기준 : 공개 데이터는 현지화로 충분할 수 있으나, 국가 기관과 민감 정보는 키와 운영 통제까지 요구함.

## Ⅴ. 데이터 주권 보장의 한계와 방안

- 핵심 요약 : 키 주권과 기밀 연산은 기능 제약과 최신 기술 도입 지연을 수반하므로, 이를 기술 대안과 조달 방식으로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 기능 제약 | 고객 키 사용 시 사업자의 서버 측 기능(검색, 분석)이 평문 연산을 하지 못함 | 암호화 상태에서 연산하는 기술과 기밀 컴퓨팅 환경을 결합 | 기능 제약 항목 수 |
| 최신 기술 도입 지연 | 격리된 환경에서는 해외 모델과 서비스의 갱신이 늦어짐 | 외부 기술을 검증 후 격리 환경에 반입하는 조달 절차 마련 | 모델 반영 소요 기간 |
| 운영 비용 증가 | 전용 키 관리 장비와 인력이 필요함 | 위험 등급에 따라 적용 범위를 구분 | 비용 대비 적용 범위 |

## Ⅵ. 데이터 주권 정착을 위한 기술사적 제언

- 핵심 요약 : 데이터 주권은 모든 데이터에 같은 수준으로 적용하기보다, 데이터 등급에 따라 키와 연산 통제를 차등 적용하는 체계로 정착.

기관은 데이터 중요도를 먼저 분류하고, 민감 데이터에 대해서만 고객 키와 기밀 컴퓨팅을 적용하는 계층형 설계를 택하는 것이 현실적이다. 정부는 사업자가 키 관리와 국외 이전 조건을 공개하도록 기준을 마련하고, 조달 과정에서 이 기준을 충족하는지 확인하는 절차를 두어야 한다. 이러한 체계는 주권 확보와 기술 도입 속도 사이의 균형을 맞추는 수단이 된다.

## Ⅶ. 결론

- 핵심 요약 : 데이터 주권은 데이터의 위치, 키, 연산, 운영을 국가 관할권 아래 두는 다층 통제 개념.
- 저장 위치만으로는 충분하지 않으므로, 데이터 등급에 맞춘 키 통제와 운영 통제를 함께 설계하는 것이 핵심임.
