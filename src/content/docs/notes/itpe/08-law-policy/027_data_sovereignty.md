<details><summary>핵심 용어</summary>

- **데이터 주권(Data Sovereignty)**: 데이터에 적용되는 법적 관할과 데이터 접근·이용을 통제할 권한을 함께 다루는 개념.
- **데이터 현지화**: 특정 데이터의 국내 저장·처리를 요구하는 정책·규제 수단.
- **개인정보 국외 이전**: 개인정보를 국외에 제공·처리위탁·보관하는 처리로, 개인정보 보호법 제28조의8 요건 확인 대상.
- **HYOK (Hold Your Own Key)**: 고객이 암호키를 직접 관리하고 클라우드 서비스 접근과 분리하는 키 관리 방식.

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터 주권(Data Sovereignty)**은 데이터에 적용되는 법적 관할과 접근·이용 통제 주체를 함께 살피는 관점 |
| 목적 | 국경을 넘는 데이터 처리에서도 법적 의무와 보호 책임을 명확히 관리 |

### Ⅱ. 판단 요소

| 요소 | 확인할 내용 |
|---|---|
| 법적 관할 | 데이터 주체·처리자·서비스 제공자에 적용되는 법과 관할 |
| 데이터 위치 | 저장·처리·백업 장소와 재위탁 경로 |
| 접근 통제 | 관리자·지원 인력의 접근 범위와 감사 기록 |
| 암호키 | 키 보유자, 사용 권한, 복구·폐기 절차 |

국내 저장만으로 외국 법률의 적용 가능성이 사라지지 않으며 암호키 분리만으로 모든 법적 접근 요구 배제도 불가. 개인정보 국외 이전은 개인정보 보호법 제28조의8의 근거·요건 확인.

### Ⅲ. 기술사적 제언

계약서와 기술 설계에서 데이터 흐름·접근 주체·키 관리 책임을 함께 확인.

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터 주권(Data Sovereignty)**은 데이터에 적용되는 법적 관할과 접근·이용 통제 주체를 함께 살피는 관점 |
| 목적 | 국경을 넘는 데이터 처리에서도 법적 의무와 보호 책임을 명확히 관리 |

데이터 주권은 하나의 보편적 법률이나 단일 기술로 정의되는 제도가 아니라, 국경 간 처리에서 관할·접근·이용 통제력을 분석하는 거버넌스 관점.

## Ⅱ. 위험을 결정하는 요소
| 요소 | 주권에 미치는 영향 |
|---|---|
| 저장·처리 위치 | 현지 법과 규제, 이전 경로에 영향 |
| 서비스 제공자의 관할 | 사업자에게 적용되는 법적 의무와 정부 요청 절차에 영향 |
| 관리자 접근 | 국경 밖 인력·하위 처리자의 데이터 접근 가능성 |
| 키·복호화 권한 | 저장 데이터가 실제로 누구에게 읽힐 수 있는지 결정 |

데이터 현지화는 위치 통제 수단이며 데이터 주권 전체와 동일하지 않음. 미국 CLOUD Act는 미국 관할 서비스 제공자가 보유·관리·통제하는 데이터에 대한 유효한 절차의 제출 명령을 규율하므로 해외 서버 저장만으로 검토가 끝나지 않음.

## Ⅲ. 법적·계약적 통제
| 통제 단계 | 확인 사항 |
|---|---|
| 데이터 분류 | 개인정보·민감정보·영업비밀 등 법적 보호 대상 파악 |
| 이전 근거 | 개인정보 국외 이전에 해당하는지와 제28조의8상 근거·요건 확인 |
| 계약 | 처리 목적, 장소, 하위 처리자, 접근 통지·감사·반환·삭제 조건 명시 |
| 법적 요청 | 정부기관 요청의 통지·검토·이의제기 절차와 법률상 제한 확인 |

개인정보 국외 이전의 유일한 근거가 별도 동의인 것은 아님. 이전 유형·조건별 법정 근거와 고지 등 요건 확인.

## Ⅳ. 기술·운영 통제
```text
데이터 분류·흐름과 관할 확인
               ↓
처리 목적·국외 이전 근거 확인
               ↓
전송·저장 보호와 키 권한 설계
               ↓
관리자 접근 제한·기록·감사
               ↓
반환·삭제 및 잔존본 확인
```

HYOK·고객 관리 키·기밀 컴퓨팅은 위험에 따라 선택하는 통제 수단. 키 분리 후에도 서비스의 평문 처리나 제공자 복호화 경로가 있으면 접근 위험 잔존; 실제 접근 경로·복구 권한 검증 필요.

## Ⅴ. 선택 기준과 한계
| 선택 | 적합한 경우 | 한계·점검점 |
|---|---|---|
| 국내 리전 | 위치·지연·계약상 국내 보관 요구 | 서비스 사업자 관할과 관리자 접근은 별도 확인 |
| 고객 관리 키 | 키 통제와 키 접근 감사가 중요 | 키 분실 복구와 서비스 운영 호환성 검토 |
| 자체·전용 인프라 | 외부 접근과 관할 위험을 더 강하게 제한해야 함 | 비용, 운영 역량, 공급망 의존성 고려 |

## Ⅵ. 기술사적 제언
| 한계 | 해결 방안 |
|---|---|
| 저장 위치만 확인하고 처리자 관할·관리자 접근·키 권한을 놓칠 수 있음 | 데이터 흐름도와 하위 처리자 목록을 맞춰 보고 변경 때마다 관할·접근·키 통제를 재평가 |
