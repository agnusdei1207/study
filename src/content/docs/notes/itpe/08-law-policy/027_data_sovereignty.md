## 30초 인출

- 본질: **데이터 주권 (Data Sovereignty)** 은 데이터가 수집·생성된 국가의 법적 관할권 아래에 놓이며 국가와 정보주체가 데이터의 접근·이용·처분을 주도적으로 통제할 수 있는 배타적 권리
- 메커니즘: 데이터의 물리적 저장 위치 통제와 더불어 CSP 법적 관할권 확인, 고객 소유 암호키(HYOK) 분리 및 기밀 컴퓨팅(TEE)을 적용해 해외 정부의 강제 징구와 원격 접근 차단
- 통찰: 단순 국내 리전 저장만으로는 미국 CLOUD Act 등 글로벌 빅테크 본국법에 의한 원격 데이터 징구를 막을 수 없으므로 암호키의 완전한 로컬 격리와 소버린 클라우드(Sovereign Cloud) 체계 구축 필수

<details><summary>핵심 용어</summary>

- **데이터 주권 (Data Sovereignty)** : 국가와 조직이 자체 데이터에 대한 배타적 지배권과 법적 관할권을 확보하여 타국의 외교·사법적 간섭을 배제하는 권리.
- **데이터 현지화 (Data Residency)** : 법률에 따라 특정 중요 데이터(공공, 금융, 의료 등)의 저장을 자국 영토 내 데이터센터로 한정하는 규제.
- **CLOUD Act** : 미국 법 집행 기관이 미국 테크 기업이 관리하는 데이터라면 서버 위치와 무관하게 데이터 제출을 명령할 수 있는 미국 역외 법률.
- **소버린 클라우드 (Sovereign Cloud)** : 데이터 저장, 하드웨어 운영, 유지보수 인력까지 전 과정을 현지 법률 및 주권 통제 하에 두는 특화 클라우드.
- **HYOK (Hold Your Own Key)** : 클라우드 제공업체가 암호키에 절대 접근할 수 없도록 고객사 자체 온프레미스 HSM에서 키를 통제하는 보안 모델.

</details>

## 2~4교시 25점 답안

## Ⅰ. 데이터 주권(Data Sovereignty)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터 주권 (Data Sovereignty)** 은 데이터의 생성, 처리, 보관, 활용 전 과정이 데이터가 귀속된 국가의 사법적 관할권과 자율적 통제권 하에 유지되어야 한다는 원칙 |
| 목적 | 글로벌 빅테크의 데이터 독점 방지, 타국 사법당국의 무단 영장 집행 차단 및 국가 안보와 국민 프라이버시 수호 |

## Ⅱ. 데이터 주권의 위협 요인 및 제도적 특징

| 구분 | 핵심 위험 및 규제 요인 | 상세 특징 및 기술적 쟁점 |
|---|---|---|
| **역외 관할권 충돌** | 미국 CLOUD Act (18 U.S.C.) | 서버가 한국에 있어도 미국 CSP(AWS, MS, 구글)는 미국 정부 명령 시 데이터 제출 의무 발생 |
| **원격 관리자 접근** | 해외 본사 인력의 관리 접근 | 데이터는 국내에 보관되나 해외 원격 엔지니어가 유지보수 목적으로 평문 데이터 열람 가능 |
| **암호키 통제권 결여** | CSP 관리 키 (KMS 종속) | 클라우드 제공자가 암호키를 보관·관리할 경우 법원 영장 제시 시 고객 모르게 복호화 제공 |
| **국내 법적 대응 (특징)** | 개인정보 보호법 제28조의8 | 개인정보 국외 이전 시 정보주체 동의 또는 안전성 인정 국가에 한해 허용, 위반 시 중지명령 |
| **소버린 클라우드 (특징)** | 기술 주권 및 운영 주권 분리 | 인프라 운영사, 유지관리 인력, 데이터센터, 거버넌스 전반을 현지 법인으로 완전 분리 격리 |

## Ⅲ. 소버린 클라우드 및 국경 간 데이터 보호 아키텍처

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 데이터 주권 보장을 위한 소버린 클라우드(Sovereign Cloud) 아키텍처 ]   │
└────────────────────────────────────────────────────────────────────────┘

 [ 대한민국 정부 / 민간 데이터 주권 구역 ]
    │
    ▼ (데이터 암호화 적재)
 ┌──────────────────────────────────────────────────────────────────────┐
 │ [ 1. 데이터 현지화 계층 (Local Data Residency) ]                     │
 │  └── 국내 데이터센터 물리적 저장 강제, 국외 무단 백업 원천 차단      │
 └──────────────────────────────────────────────────────────────────────┘
    │
    ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ [ 2. 키 주권 계층: HYOK (Hold Your Own Key) ]                         │
 │  ├── 고객사 자체 데이터센터 내 하드웨어 보안 모듈(HSM) 구축          │
 │  └── CSP는 암호화된 블롭(Blob)만 저장, 복호화 키 접근 절대 불가     │
 └──────────────────────────────────────────────────────────────────────┘
    │
    ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ [ 3. 연산 주권 계층: 기밀 컴퓨팅 (Confidential Computing) ]          │
 │  ├── 하드웨어 격리 실행 환경 (Intel SGX, AMD SEV 기반 TEE Enclave)    │
 │  └── CPU 메모리 연산 중에도 데이터 암호화 상태 유지 (CSP 관리자 차단) │
 └──────────────────────────────────────────────────────────────────────┘
    │
    ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ [ 4. 운영 주권 계층 (Operational Sovereignty) ]                      │
 │  └── 신원 검증된 현지 국적자(한국인)만 인프라 물리/논리 유지보수 인가  │
 └──────────────────────────────────────────────────────────────────────┘
```

| 주권 통제 계층 | 엔지니어링 구현 기술 | 핵심 방어 효과 |
|---|---|---|
| **데이터 현지화** | 지오펜싱(Geo-fencing), 국내 독립 가용영역(AZ) | 타국 물리적 영장 집행 압류 방지 |
| **키 주권 (HYOK)** | 외부 KMS 연동, BYOK/HYOK 인터페이스 | CSP 본국의 사법적 복호화 명령 무력화 |
| **연산 주권 (TEE)** | 메모리 암호화 연산(Trusted Execution Env) | 클라우드 하이퍼바이저 관리자 덤프 공격 차단 |
| **운영 주권** | 로컬 보안관제센터(SOC), 2인 승인 접속(PAM) | 해외 본사 엔지니어의 비인가 백도어 원격 접근 차단 |

## Ⅳ. 단순 데이터 현지화와 데이터 주권의 비교

| 비교 항목 | 단순 데이터 현지화 (Data Residency) | 종합적 데이터 주권 (Data Sovereignty) |
|---|---|---|
| **통제의 초점** | 데이터가 **'어디에 저장되어 있는가'** (물리적 위치) | 데이터에 **'누가 접근하고 어떤 법이 적용되는가'** (관할권) |
| **보안 메커니즘** | 국내 데이터센터 상면 입주 | HYOK 키 격리 + TEE 기밀 컴퓨팅 + 운영 통제 |
| **CLOUD Act 대응** | **대응 불가** (미국 테크 기업 서버면 강제 징구) | **완벽 대응** (CSP도 키가 없어 평문 제출 불가) |
| **관리자 접근** | 해외 원격 엔지니어 접근 허용 (위험 상존) | 인가된 현지 거주 국적자만 접근 통제 |
| **운영 모델** | 글로벌 퍼블릭 클라우드 국내 리전 | 현지 파트너사 운영 소버린 전용 클라우드 파티션 |
| **보장 수준** | 초급 수준의 형식적 위치 규제 충족 | 국가 안보 및 최고 기밀을 보호하는 완전 주권 보장 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| HYOK 적용 시 클라우드 네이티브 서비스(검색, AI 분석 등)의 서버 측 평문 연산 불가로 기능 제약 | 암호화된 상태에서 직접 연산을 수행하는 동형암호(HE) 가속기 및 안전한 TEE Enclave 기반 메모리 복호화 연산 결합 |
| 소버린 클라우드 구축 시 글로벌 CSP의 최신 AI 모델(GPT, Claude 등) 업데이트 주기 지연 | 글로벌 기술 모델을 로컬 인프라로 격리 수입하는 '에어갭(Air-Gapped) 소버린 AI 플랫폼' 조달 모델 확립 |

## Ⅵ. 제언

데이터 주권의 완성을 위해 데이터 저장부터 연산까지 전 주기에서 CSP를 신뢰하지 않는 제로 트러스트 기밀 컴퓨팅 및 고객 주도 키 관리(HYOK) 아키텍처 구축 필요.

```text
[ 데이터 소유자 (기관) ]
          │ (자체 온프레미스 HSM에서 생성된 키로 클라이언트 암호화)
          ▼
[ 소버린 클라우드 스토리지 ] ──(저장 시 완전 암호화 Blob)
          │
          ▼ (연산 요청 시 암호문 그대로 TEE로 전송)
[ 하드웨어 격리 TEE (Intel SGX / AMD SEV) ]
   ├── 고객 HSM과 보안 원격 증명(Remote Attestation) 수행
   ├── TEE 하드웨어 칩 내부에서만 일시 복호화 및 연산 수행
   └── 연산 결과 즉시 재암호화 후 메모리 완전 소거 (Wipe Out)
          │
          ▼
[ CSP 및 타국 정부는 전송·저장·연산 전 과정에서 데이터 열람 원천 불가 ]
```

| 구분 | 기존 퍼블릭 클라우드 국내 리전 | 제언: TEE & HYOK 결합 소버린 클라우드 |
|---|---|---|
| **저장 데이터 보호** | CSP 관리 키로 투명 암호화 (TDE) | 고객 독점 온프레미스 HSM 키로 암호화 (HYOK) |
| **연산 데이터 보호** | 메모리 상에 평문 노출 (덤프 취약) | 하드웨어 TEE Enclave 내 메모리 암호화 연산 |
| **사법 영장 집행** | 본국 정부 명령 시 평문 징구 불가피 | 키가 없어 기술적으로 평문 제공 불가능 (면책) |
| **운영 거버넌스** | 글로벌 통합 원격 관제망 | 국가 공인 기관 검증 독립 로컬 관제 |
