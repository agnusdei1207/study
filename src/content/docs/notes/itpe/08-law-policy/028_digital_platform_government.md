## 30초 인출

- 본질: **디지털 플랫폼 정부 (DPG)** 는 모든 데이터가 연결되는 개방형 디지털 플랫폼 위에서 국민, 기업, 정부가 함께 사회문제를 해결하고 선제적 맞춤형 공공서비스를 창출하는 차세대 정부 혁신 모델
- 메커니즘: DPG 허브를 코어로 공공·민간 데이터 칸막이를 해소하고 초거대 AI, 마이데이터 및 행정정보 공동이용을 결합하여 신청주의를 탈피한 선제적 원스톱 행정 구현
- 통찰: 범정부 데이터 통합 연계에 따른 권한 남용 및 단일 장애점(SPOF) 발생 시 전 국가적 서비스 마비 위험이 크므로 제로 트러스트(Zero Trust) 보안과 분산 메시 API 거버넌스 체계 구축 필수

<details><summary>핵심 용어</summary>

- **디지털플랫폼정부 (DPG)** : 디지털 기술과 데이터를 기반으로 민관이 협력하여 정책을 수립하고 서비스를 제공하는 플랫폼 중심 정부 패러다임.
- **DPG 허브 (DPG Hub)** : 공공과 민간의 데이터·서비스를 안전하게 연계하고 초거대 AI 등 혁신 인프라를 지원하는 범정부 통합 데이터 중계 플랫폼.
- **구비서류 제로화** : 행정기관 간 데이터 연계를 통해 국민이 공공기관에 증명 서류를 직접 발급받아 제출할 필요가 없도록 만든 행정 혁신.
- **선제적 서비스** : 국민이 직접 신청하지 않아도 생애주기별(출산, 입학, 취업, 은퇴) 혜택을 정부가 알아서 먼저 찾아 추천하고 지원하는 서비스.
- **행정정보 공동이용** : 전자정부법 제36조에 따라 행정기관 등이 보유한 행정정보를 타 기관이 공동 활용하는 법정 체계.

</details>

> 국가 행정 서비스의 대전환을 위한 '디지털플랫폼정부(DPG)'의 추진 배경과 4대 핵심 전략을 설명하고, DPG 허브 기반의 민·관 데이터 연계 아키텍처 및 안전한 구현을 위한 기술적 통제 방안을 논하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 디지털 플랫폼 정부의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **디지털 플랫폼 정부** 는 인공지능과 데이터 기반으로 공공과 민간의 자원을 연계하여 국민 중심의 원스톱 맞춤형 행정을 실현하는 혁신 정부 플랫폼 |
| 목적 | 부처 간 데이터 칸막이 철폐, 신청주의 행정의 한계 극복 및 민간 혁신 생태계와 융합한 국가 성장 동력 창출 |

## Ⅱ. DPG 4대 핵심 추진 전략 및 플랫폼 특징

| 4대 전략 | 핵심 내용 및 서비스 목표 | 상세 특징 및 기술적 적용 기준 |
|---|---|---|
| **1. 오직 국민을 위한 정부** | 구비서류 제로화 및 선제적 복지 | 생애주기별 혜택 자동 추천, 관공서 방문 및 불필요한 종이 서류 제출 완전 폐지 |
| **2. 하나의 정부** | 부처 간 데이터 칸막이 해소 | 개별 부처 레거시 사일로를 타파하고 **DPG 허브** 기반의 실시간 데이터 공동활용 |
| **3. 민관 협력 혁신 경제** | 공공데이터 전면 민간 개방 | 공공데이터를 API 형태로 민간에 개방하여 스타트업 혁신 비즈니스 및 AI 학습 지원 |
| **4. 안전하고 신뢰받는 정부** | 제로 트러스트 보안 체계 | 경계 기반 보안에서 벗어나 전 연계 구간 상호 인증, 데이터 계보 관리 및 개인정보 보호 |
| **플랫폼 성격 특징** | **신청주의에서 선제형 전환 (특징)** | 국민의 능동적 신청 대기에서 벗어나 정부가 데이터를 분석하여 선제적으로 권리 제공 |

## Ⅲ. DPG 통합플랫폼(DPG 허브) 아키텍처 및 서비스 연계 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 디지털플랫폼정부 허브(DPG Hub) 및 민관 융합 서비스 아키텍처 ]         │
└────────────────────────────────────────────────────────────────────────┘

 [ 대민 채널 (국민비서, 정부24, 카카오, 토스 등 민간 앱) ]
               │
               ▼ (통합 인증: Any-ID 간편인증)
 ┌──────────────────────────────────────────────────────────────────────┐
 │ [ 디지털플랫폼정부 허브 (DPG Hub) 코어 엔진 ]                        │
 │  ├── 통합 API 게이트웨이: 트래픽 제어, 라우팅, OAuth 2.0 인가       │
 │  ├── 데이터 레이크 & 연계 파이프라인: 공공·민간 데이터 카탈로그     │
 │  └── 초거대 AI 공공 서비스 플랫폼: RAG 기반 행정 지식 검색 엔진      │
 └──────────────────────────────────────────────────────────────────────┘
        │                                  │
        ▼ (표준 행정 데이터 연계)           ▼ (민관 데이터 결합)
 ┌───────────────────────────┐      ┌───────────────────────────┐
 │ [ 범부처 행정 정보시스템 ]  │      │ [ 민간 혁신 서비스 기업 ]  │
 │ - 대법원 가족관계등록부   │      │ - 마이데이터 사업자(핀테크)│
 │ - 행안부 주민등록 DB      │      │ - 민간 생성형 AI 포털     │
 │ - 국세청 소득금액증명 DB  │      │ - 헬스케어 및 물류 플랫폼 │
 └───────────────────────────┘      └───────────────────────────┘
```

| 프로세스 단계 | 주요 수행 업무 | 핵심 기술 및 프로토콜 |
|---|---|---|
| **1. 통합 본인 인증** | 민간 간편인증 및 모바일 신분증 연계 단일 로그인 | FIDO2, OIDC (OpenID Connect) |
| **2. 데이터 라우팅** | DPG 허브가 소관 기관의 데이터 연계 API 자동 호출 | RESTful JSON, GraphQL API |
| **3. 구비서류 자동 판정** | 행정정보 공동이용망을 통해 자격 요건 즉각 스크리닝 | 원천 DB 다이렉트 쿼리 (서류 발급 불요) |
| **4. 맞춤형 혜택 추천** | 공공 초거대 AI가 수혜 가능한 청년/육아 정책 매칭 | 벡터 DB 임베딩, 코사인 유사도 검색 |
| **5. 민간 서비스 송출** | 토스, 네이버 등 민간 친숙 앱으로 행정 알림 발송 | 웹훅(Webhook) 푸시 알림, Kafka 스트림 |

## Ⅳ. 전통적 전자정부(e-Gov)와 디지털플랫폼정부(DPG) 비교

| 비교 항목 | 전통적 전자정부 (Electronic Government) | 디지털 플랫폼 정부 (Digital Platform Government) |
|---|---|---|
| **행정 패러다임** | 부처별 분절된 온라인화 (사일로 구축) | **부처 간 데이터가 연결된 단일 플랫폼 (One-Gov)** |
| **서비스 제공 방식** | **신청주의** (국민이 사이트 찾아 직접 신청) | **선제주의** (정부가 요건 충족 시 알아서 먼저 제공) |
| **서류 처리 방식** | 전자민원 발급 후 PDF 출력/업로드 (불편) | **구비서류 제로화** (기관 간 데이터 직접 대조) |
| **민관 협력 모델** | 정부 주도 포털 중심 (정부24 단일 창구) | **민간 플랫폼(카카오, 토스 등)과의 양방향 개방 융합** |
| **데이터 활용** | 부처 내부 업무 처리용 보관 | **초거대 AI 학습 및 민간 경제 활성화 자원화** |
| **보안 모델** | 물리적 망분리 기반 폐쇄적 경계 보안 | **제로 트러스트(Zero Trust) 기반 동적 검증** |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| DPG 허브 중앙 집중 연계 구조로 인한 단일 장애점(SPOF) 발생 시 전국 공공서비스 동시 마비 위험 | 멀티 리전 분산 클라우드 아키텍처 및 서비스 메시(Service Mesh) 기반 분산 게이트웨이 이중화 |
| 부처 간 데이터 소유권 다툼 및 책임 회피로 인한 핵심 행정 데이터 연계 기피 관행 | 데이터기반행정법 개정을 통한 데이터 제공 거부 사유 축소 및 범부처 데이터 메타데이터 등록 의무화 |

## Ⅵ. 제언

디지털플랫폼정부의 안전하고 민첩한 확산을 위해 마이크로서비스(MSA)와 제로 트러스트 보안을 융합한 이벤트 기반 공공 서비스 아키텍처 구축 필요.

```text
[ 국민 생애주기 이벤트 발생 (출산 신고 접수) ]
                     │
                     ▼ (Apache Kafka 이벤트 발행)
[ DPG 허브 이벤트 브로커 (Event Broker) ]
   ├── Topic 1: [ 복지부 ] ── 아동수당 자동 신청 및 계좌 지급
   ├── Topic 2: [ 지자체 ] ── 출산 축하금 및 첫만남이용권 바우처 발급
   └── Topic 3: [ 한전/도시가스 ] ── 대가족 전기요금 복지 할인 자동 적용
                     │
                     ▼
[ 민간 모바일 앱 알림 ] ── "출산 관련 3대 혜택이 모두 자동 신청 완료되었습니다"
```

| 구분 | 기존 부처별 개별 신청 방식 | 제언: 이벤트 기반 선제형 DPG 플랫폼 |
|---|---|---|
| **국민 행동** | 주민센터 방문 및 3개 기관 개별 신청 | 출산 신고 1회로 모든 후속 혜택 자동 완료 |
| **처리 시간** | 각 부처 심사로 수주일 소요 | 비동기 이벤트 스트림으로 실시간 자동 처리 |
| **서류 증빙** | 주민등록등본, 통장사본 등 수기 제출 | DPG 허브 백엔드 데이터 대조로 증빙 제로화 |
| **행정 비용** | 단순 서류 심사에 수많은 공무원 투입 | 자동화 처리를 통해 심층 복지 상담에 집중 |
