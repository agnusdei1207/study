## Ⅰ. 디지털 정부서비스 UI/UX 가이드라인의 개요

- 개념 : 중앙행정기관, 지자체 및 공공기관이 대국민 디지털 서비스를 구축·운영할 때 일관되고 접근성 높은 **사용자 경험**을 제공하도록 규정한 행정안전부 표준 지침.
- 제정 배경 및 필요성 : **공통 컴포넌트** 단순 복제 적용에 그칠 경우 기관 고유의 복잡한 행정 맥락에서 과업 중도 이탈률이 증가하므로 **공공 표준 npm UI(User Interface) 패키지** 배포와 실제 취약계층 대상 **사용성 평가** (UT) 결합 필수.
- 핵심 목적 : 공공 웹·앱 전반의 사용자 경험 통일, 불필요한 탐색 비용 절감, 디지털 취약계층의 행정 접근성 보장 및 공공 SW(Software) 개발 비용 절감.

## Ⅱ. 디지털 정부서비스 UI/UX 가이드라인의 법제도 체계 및 핵심 메커니즘

**디지털 정부서비스 UI/UX(User Experience) 가이드라인** : **대한민국 정부 디자인 시스템** (KRDS)을 토대로 기본 원칙, 디자인 스타일, UI 컴포넌트, 기본 패턴 및 복합 서비스 패턴의 5단계 계층을 정의하고, **사용자 여정 맵** 기반의 사용성 테스트 집행 과정을 거쳐 체계적인 법제도적 통제와 기술적 신뢰성을 확보함.

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ [ 대한민국 정부 디자인 시스템(KRDS) 4단계 설계 및 검증 파이프라인 ]         │
└─────────────────────────────────────────────────────────────────────────────┘
  [ Layer 1: 스타일 가이드 (Style Guide) ]
    ├── 타이포그래피(Pretendard GOV), 공공 색상 팔레트(Color Token), 그리드 시스템
          │
          ▼
  [ Layer 2: UI 컴포넌트 (UI Components) ]
    ├── 버튼, 텍스트 입력 폼, 체크박스, 모달 팝업, 탭(Tab), 브레드크럼(Breadcrumb)
          │
          ▼
  [ Layer 3: 기본 패턴 (Basic Patterns) ]
    ├── 검색 필터링, 도움말 툴팁, 오류 검증(Validation), 페이지네이션
          │
          ▼
  [ Layer 4: 서비스 패턴 (Service Patterns) ]
    ├── 공공 원스톱 과업 흐름: [본인인증] ─> [신청서 입력] ─> [제출] ─> [진행/결과 조회]
          │
          ▼
  [ Layer 5: 사용성 검증 및 품질 감사 ]
    ├── KWCAG 웹 접근성 준수 평가 (명도 대비 4.5:1, 스크린리더 음성 호환)
    └── 실제 타깃 사용자(고령층·장애인) 대상 UT(Usability Test) 수행

[ 공공 서비스 패턴의 선형적(Linear) 과업 완결 흐름 ]
[1. 서비스 안내/자격 확인] ─> [2. 간편인증 로그인] ─> [3. 폼 입력 & 자동완성] ─> [4. 최종 승인 & 알림]
```

- 원칙 1 : **사용자 중심** (User-Centered) - 공급자 중심 행정 용어 탈피, 일상적 언어 사용 및 직관적 과업 완결 지원.
- 원칙 2 : **포용성** (Inclusivity) - 장애인·고령자·다문화 가정도 차별 없이 이용 가능한 배리어프리 및 웹 접근성(KWCAG, Korean Web Content Accessibility Guidelines) 준수.
- 원칙 3 : **일관성과 조화** - 범정부 공통 사용자 경험(KRDS)을 유지하면서도 개별 기관의 업무 맥락 수용.
- 원칙 4 : **간결한 이용** (Simplicity) - 한 화면에 단일 핵심 목적만 제시, 불필요한 입력 필드 제거(구비서류 제로화).
- 원칙 5 : **이해하기 쉬운 상호작용** - 버튼·링크의 역할 명확화, 오류 발생 시 명확한 해결 방법 안내.

## Ⅲ. 디지털 정부서비스 UI/UX 가이드라인의 세부 규정 및 국내외 제도 비교 분석

| 설계 계층 | 정의 및 구성 요소 | 주요 역할 및 공학적 예시 |
|---|---|---|
| 1. **스타일** (Style) | 시각적 기본 규칙 (색상, 서체, 간격) | Gov Blue 메인 컬러, 명도 대비 4.5:1 이상 토큰화 적용 |
| 2. **컴포넌트** (Component) | 단일 인터랙션을 수행하는 기본 UI 부품 | Button, Input, Select, DatePicker, Accordion, Modal |
| 3. **기본 패턴** (Basic Pattern) | 컴포넌트의 유기적 결합 조합 | Form Validation(실시간 인라인 오류), Search & Filter |

- 제도적 시사점 : 디지털 정부서비스 UI/UX 가이드라인은 상기 비교 지표를 바탕으로 법적 의무 준수와 비즈니스 연속성 간의 균형을 확보하고, 규제 환경 변화에 선제적으로 대응할 수 있는 아키텍처 및 거버넌스 체계를 확립해야 함.

## Ⅳ. 디지털 정부서비스 UI/UX 가이드라인의 주요 한계점 및 해결 방안

- KRDS 스타일만 복사하고 복잡한 행정 서식을 유지하는 무늬만 표준화 :
  - 한계점 : KRDS 스타일만 형식적으로 복사하고 실제 행정 절차는 기존의 복잡한 다단계 서식(PDF(Portable Document Format) 다운로드 등)을 유지하는 무늬만 표준화.
  - 해결 방안 : 사업 착수 시 'AS-IS 사용자 여정 분석(Journey Map)'을 의무화하고, 행정 서식 자체를 디지털 인터랙티브 폼으로 간소화하는 BPR(Business Process Reengineering) 선행.
- 발주·개발사의 자의적 컴포넌트 변형에 따른 보조공학기기 호환성 파괴 :
  - 한계점 : 발주사 및 개발사의 자체적인 컴포넌트 변형으로 인해 화면 깨짐 및 스크린리더 등 보조공학 기기 호환성 파괴.
  - 해결 방안 : 공식 오픈소스 npm 패키지(`@krds/core`) 의무 도입, CI(Continuous Integration)/CD(Continuous Delivery) 테스트 단계에서 axe-core 기반 접근성 자동 테스트 강제화.
- 복잡한 행정 전문용어와 자격 요건으로 인한 정보취약계층 접근 포기 :
  - 한계점 : 고령층 및 다문화 가정이 행정 전문용어와 복잡한 조건문(소득분위, 자격요건)을 이해하지 못해 포기.
  - 해결 방안 : 생성형 AI(Artificial Intelligence) 기반 '쉬운 말 서비스(Easy-read)' 자동 변환 모듈 결합 및 원스톱 자격 자동 판정 알고리즘 적용.

## Ⅴ. 디지털 정부서비스 UI/UX 가이드라인 정착 및 실효성 확보를 위한 기술사적 제언

국민 중심 디지털 정부를 완성하기 위해 오픈소스 KRDS 디자인 토큰을 프런트엔드 빌드 파이프라인에 직접 바인딩하고, 실제 사용성 지표(완결 시간·이탈률)를 상시 추적하는 데이터 기반 UX 거버넌스 확립.

- 개발 방식 관점의 고도화 및 실무 전환 : 가이드라인 PDF 보고 수동 코딩의 한계와 비효율을 탈피하고, npm 패키지 기반 공식 컴포넌트 직접 임포트를 체계적으로 도입·적용하여 실무적 신뢰성과 거버넌스 실효성을 극대화해야 함.
- 품질 검증 관점의 고도화 및 실무 전환 : 검수 시점 육안 화면 점검의 한계와 비효율을 탈피하고, CI/CD 자동화 접근성(axe-core) 린팅을 체계적으로 도입·적용하여 실무적 신뢰성과 거버넌스 실효성을 극대화해야 함.
- 평가 기준 관점의 고도화 및 실무 전환 : 행정 지침 형식 준수 여부의 한계와 비효율을 탈피하고, 실제 사용자의 과업 완료율(Task Success Rate)를 체계적으로 도입·적용하여 실무적 신뢰성과 거버넌스 실효성을 극대화해야 함.
