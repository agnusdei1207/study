## 한 줄 본질
- 수백 개 공공 웹사이트마다 제각각이던 레이아웃, 버튼, 로그인 방식을 통일된 범정부 디자인 시스템 규격으로 표준화하여, 국민이 어떤 공공 서비스를 이용하든 동일한 경험으로 손쉽게 완결하게 돕는 공공 UI/UX 기준서 → 대국민 편의성 및 개발 생산성 향상 / 개별 기관의 디자인 자율성 제한

## 핵심 용어
- 범정부 디자인 시스템: 모든 공공기관이 공통으로 사용할 수 있도록 UI 컴포넌트의 디자인 토큰(Design Tokens)과 퍼블리싱 소스코드를 패키지화한 체계
- 디자인 토큰: 색상, 폰트 크기, 간격 등의 스타일 값을 플랫폼(Web, iOS, Android)에 무관하게 동기화할 수 있도록 Key-Value 형태로 정의한 규격
- 사용자 여정(User Journey): 국민이 공공 포털에 접속하여 목적하는 민원 신청을 완료하고 결과를 통보받기까지 거치는 일련의 상호작용 흐름

## 핵심 통찰
- 과거 전자정부 웹사이트는 기관 중심의 정보 나열과 화려한 비주얼 배너 위주였으나, 본 가이드라인은 "민원 완결(Task Completion)" 중심의 기능적 UX로 완전히 전환함
- 버튼의 명도 대비(4.5:1 이상)와 키보드 접근성, 스크린리더 음성 안내를 기본 컴포넌트 레벨에서 강제하여 별도 추가 작업 없이도 웹 접근성 인증을 획득할 수 있도록 설계됨
- 단순 가이드라인 문서를 넘어, Figma 디자인 키트와 오픈소스 프론트엔드 코드(HTML/CSS, React 컴포넌트) 형태로 배포되어 개발 생산성을 비약적으로 향상시킴

## 딸려 나오는 하위 토픽
| 하위 토픽 | 상위 구조 속 위치 | 한 줄 |
|---|---|---|
| KWCAG 2.2 (한국형 웹 콘텐츠 접근성 지침) | 필수 법적 준수 요건 | 장애인과 고령자가 공공 웹 서비스를 동등하게 이용할 수 있도록 보장하는 기술 기준 |
| 행정·공공기관 웹사이트 구축·운영 가이드 | 상위 거버넌스 지침 | UI/UX뿐만 아니라 보안, 성능, 인프라 운영 전반을 포괄하는 행안부 종합 가이드 |

## 이웃 토픽과 구분
- UI/UX 가이드라인 vs 웹 접근성 지침: UI/UX 가이드라인 = 사용성, 일관성, 편의성을 포괄하는 '디자인 및 사용 경험 표준' / 웹 접근성 지침 = 차별 없는 이용을 위한 '최소 법적 필수 기준'

## 문제·원인·대책
- 사례: 133회 기출 동일한 정부 민원 서식임에도 기관마다 다른 입력 폼과 오류 메시지로 인한 신청 실패
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 사이트마다 다른 로그인 방식과 비밀번호 규칙으로 국민 혼란 가중 | 기관별 분산 구축 및 독자 인증 인터페이스 고집 | 디지털 정부서비스 UI/UX 표준 간편인증 통합 컴포넌트 적용 | 인증 소요 시간 단축 및 이탈률 감소 |
| 모바일 환경에서 버튼 크기가 너무 작아 오터치 빈발 | 데스크톱 기준 하드코딩 및 반응형 UI 미적용 | 가이드라인 권장 최소 터치 타깃(44x44px) 및 반응형 그리드 준수 | 모바일 민원 처리 성공률 제고 |

## 이렇게 출제된다
- 제133회 2교시 2번: "‘디지털정부서비스UI/UX가이드라인’(2024.2,행정안전부)은디지털서비스를구성하는 사용자 인터페이스(User Interface; UI)와 사용자 경험(User Experience; UX) 품질에 큰영향을주는요소에대하여행정기관및공공기관이준수해야할세부사항을제시한다. 이와 관련하여 다음을 설명하시오." → 요구 포인트: Ⅰ 가이드라인 제정 목적 및 의의 + Ⅲ 스타일·컴포넌트·패턴 3대 구성체계 + Ⅵ 실무 적용 및 확산 전략

## 내 의견
- [공공 SI 제안요청서(RFP)에 표준 컴포넌트 라이브러리 활용 의무화 및 디자인 검수 절차 도입] 가이드라인이 배포되었으나 공공 SI 사업에서 수행업체들이 여전히 자체 부트스트랩을 쓰며 스타일을 왜곡하는 문제가 반복됨 → 나라면: 공공 발주 시 RFP 요구사항에 '행안부 배포 UI/UX 웹 컴포넌트 패키지(NPM)' 적용을 명시하고, 감리 단계에서 표준 컴포넌트 준수율을 자동 채점하는 검사 도구를 활용하여 감리 적격 판정 기준으로 연계
