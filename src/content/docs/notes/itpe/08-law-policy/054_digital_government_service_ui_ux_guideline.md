## 연관 키워드

- 디지털 정부서비스 UI/UX 가이드라인, 대한민국 정부 디자인 시스템(KRDS), 사용자 여정 맵
- 웹 접근성(KWCAG), 사용성 테스트(UT), 공통 컴포넌트, 과업 완결률
- 사용자 중심, 포용성, 간결한 이용, 보조공학, 자동 접근성 검사

## Ⅰ. 디지털 정부서비스 UI/UX 가이드라인의 개요

- 핵심 요약 : 공공 디지털 서비스의 화면과 상호작용을 표준화하여 국민이 행정 과업을 끝까지 완료하도록 돕는 행정 지침.
- 개념 : 중앙행정기관, 지자체, 공공기관이 대국민 디지털 서비스를 구축·운영할 때 일관되고 접근성 높은 **사용자 경험**(UX, User Experience)을 제공하도록 정한 행정 지침.
- 배경 및 필요성 : 기관마다 화면을 따로 만들면 이용자는 서비스를 옮길 때마다 탐색 비용을 다시 치르고, 고령층과 장애인은 과업을 중간에 포기한다. 이 비용을 줄이려면 공통 **디자인 시스템** 부품을 쓰게 하고, 실제 취약계층을 대상으로 사용성을 평가해야 한다.
- 주요 목적 : 공공 웹·앱 전반의 사용자 경험 통일, 불필요한 탐색 비용 절감, 디지털 취약계층의 행정 접근성 보장, 공공 소프트웨어(SW) 개발 비용 절감.

## Ⅱ. 디지털 정부서비스 UI/UX 가이드라인의 특징 및 장점

- 핵심 요약 : 공통 설계 계층과 원칙, 접근성 기준을 함께 두어 기관별 화면 차이를 줄이고 과업 완결을 보장하는 방식.

1. 계층형 설계 : **대한민국 정부 디자인 시스템** (KRDS, Korea Government Design System)을 토대로 스타일, 컴포넌트, 패턴을 계층으로 정의 → 기관이 같은 부품으로 화면을 조립해 개발 중복 감소.
2. 5대 설계 원칙 : 사용자 중심, 포용성, 일관성과 조화, 간결한 이용, 이해하기 쉬운 상호작용을 기준으로 삼음 → 화면 검수 기준이 명확해짐.
3. 접근성 기준 내장 : **웹 접근성** (KWCAG, Korean Web Content Accessibility Guidelines) 준수를 품질 기준으로 두어 장애인과 고령자의 접근 장벽을 설계 단계에서 제거.
4. 사용성 검증 : **사용성 테스트** (UT, Usability Test)를 실제 취약계층 대상으로 수행 → 과업 완결 여부를 화면 형식보다 우선하여 확인.

## Ⅲ. 디지털 정부서비스 UI/UX 가이드라인의 구조 (흐름)

- 핵심 요약 : 스타일에서 서비스 패턴까지 쌓이는 5단계 설계 계층과, 이를 검증하는 품질 계층의 결합 구조.
- 설계 계층 : 아래 부품일수록 기본 단위이고 위로 갈수록 과업 단위의 조합이 되는 구조.

```text
[ 1 스타일 ] 색상, 서체, 간격 토큰
      ↓
[ 2 컴포넌트 ] 버튼, 입력 폼, 모달
      ↓
[ 3 기본 패턴 ] 검색·필터, 오류 검증
      ↓
[ 4 서비스 패턴 ] 원스톱 과업 흐름
      ↓
[ 5 검증 ] 접근성 평가, 사용성 테스트
```

- 서비스 패턴 흐름 : 이용자가 한 번에 끝까지 가도록 단계를 선형으로 배치한 과업 흐름.

```text
[ 과업 완결 흐름 ]
1. 안내·자격 확인
      ↓
2. 간편인증 로그인
      ↓
3. 폼 입력과 자동완성
      ↓
4. 최종 승인과 결과 알림
```

## Ⅳ. 형식적 표준 준수와 과업 기반 표준 준수의 비교

- 핵심 요약 : 스타일만 복제하는 형식적 준수는 표준 효과가 없고, 이용자의 과업 완결을 기준으로 삼아야 표준이 실효를 가짐.

| 비교 축 | 형식적 준수 (스타일 복제) | 과업 기반 준수 (본 가이드라인) |
| --- | --- | --- |
| 적용 단위 | 색상과 서체 등 시각 요소 | 과업 흐름 전체와 컴포넌트 |
| 기준 | 가이드 문서와의 외형 일치 | 이용자가 과업을 끝내는지 여부 |
| 검증 | 검수 시점 육안 점검 | 접근성 자동 검사와 사용성 테스트 |
| 한계 | 복잡한 행정 서식이 그대로 남음 | 업무 절차 재설계까지 요구 |

## Ⅴ. 디지털 정부서비스 UI/UX 가이드라인의 한계와 방안

- 핵심 요약 : 형식적 복제, 임의 컴포넌트 변형, 전문 용어 장벽을 업무 재설계, 공식 부품 사용, 쉬운 안내로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 스타일만 복사하고 복잡한 서식 유지 | 행정 절차가 다단계 서식으로 남아 과업 중도 이탈 발생 | 사업 착수 때 현행 사용자 여정 분석을 의무화하고, 서식을 디지털 입력 폼으로 재설계하는 업무 재설계(BPR, Business Process Reengineering) 선행 | 과업 완료 시간, 중도 이탈률 |
| 임의 컴포넌트 변형에 따른 보조공학 호환성 파괴 | 개발사 자체 변형으로 화면이 깨지고 스크린리더가 오작동 | 공식 컴포넌트 라이브러리 의무 사용, 빌드 단계에서 접근성 자동 점검 도구(axe-core) 실행 | 접근성 점검 통과율 |
| 전문 용어와 자격 조건으로 인한 취약계층 이탈 | 행정 용어와 복잡한 조건문을 이해하지 못해 신청 포기 | 쉬운 말 안내 문구 제공, 자격 요건을 사전에 확인하는 흐름 배치 | 취약계층 신청 완료율 |

## Ⅵ. 디지털 정부서비스 UI/UX 가이드라인에 대한 기술사적 제언

- 핵심 요약 : 디자인 시스템을 참조 문서가 아니라 개발 파이프라인의 공통 부품으로 편입하고, 이용자 완결 지표로 상시 관리.

1. 디자인 표준의 코드화 : 주관 부처가 공식 컴포넌트를 배포 가능한 라이브러리 형태로 제공하고, 발주 기관이 이를 사용하는 조건을 사업 계약에 명시하는 방향이 필요하다.
2. 품질 기준의 자동화 : 접근성 검사를 빌드의 통과 조건으로 두어, 검수 단계의 육안 점검에 의존하지 않도록 해야 한다.
3. 성과 지표의 상시 관리 : 과업 완료율과 중도 이탈률을 기관별로 추적하여, 화면 개선이 실제 이용자의 완결로 이어졌는지 판단하는 거버넌스가 필요하다.

## Ⅶ. 결론

- 핵심 요약 : 디지털 정부서비스 UI/UX 가이드라인은 화면 통일이 아니라 국민의 과업 완결을 보장하는 표준임.
- 시사점 : 표준 준수는 화면 형식이 아니라 취약계층이 신청을 끝까지 마치는지로 증명되어야 한다.
