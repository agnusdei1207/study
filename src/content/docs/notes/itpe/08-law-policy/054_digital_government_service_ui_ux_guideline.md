## 30초 인출

- 본질: **디지털 정부서비스 UI/UX 가이드라인** 은 공공 웹사이트와 모바일 앱마다 제각각이던 사용자 인터페이스를 표준화하여 국민이 단일한 사용 경험으로 쉽고 직관적으로 행정서비스를 이용할 수 있도록 행정안전부가 제정한 범정부 UI/UX 설계 표준 규격
- 메커니즘: 대한민국 정부 디자인 시스템(KRDS)을 토대로 기본 원칙, 디자인 스타일, UI 컴포넌트, 기본 패턴 및 복합 서비스 패턴의 5단계 계층을 정의하고, 사용자 여정 맵 기반의 사용성 테스트 집행
- 통찰: 공통 컴포넌트의 단순 복제 적용에 그칠 경우 기관 고유의 복잡한 행정 맥락에서 과업 중도 이탈률이 증가하므로 공공 표준 npm UI 패키지 배포와 실제 취약계층 대상 사용성 평가(UT) 결합 필수

<details><summary>핵심 용어</summary>

- **UI/UX 가이드라인** : 공공 디지털 서비스의 일관성과 사용성을 보장하기 위해 레이아웃, 색상, 서체, 인터랙션 등을 규정한 지침.
- **KRDS (Korea Government Design System)** : 디지털 정부서비스를 빠르고 일관되게 개발할 수 있도록 제공하는 오픈소스 범정부 디자인 시스템.
- **디자인 토큰 (Design Tokens)** : 색상, 여백, 타이포그래피 등 디자인 의도를 플랫폼 독립적인 코드(JSON 등)로 캡슐화한 변수.
- **서비스 패턴 (Service Pattern)** : 로그인, 신청서 작성, 결제, 결과 조회 등 특정 공공 과업 목적을 완결하기 위한 화면 흐름 표준.
- **사용자 여정 (User Journey)** : 사용자가 공공 서비스를 인지하고 탐색하여 신청, 결과 확인에 이르는 전 생애주기적 경험 경로.
- **배리어프리 (Barrier-Free)** : 고령자, 장애인 등 모든 사용자가 물리적·인지적 제약 없이 동등하게 정보에 접근할 수 있는 무장애 설계.

</details>

## 2~4교시 25점 답안

## Ⅰ. 디지털 정부서비스 UI/UX 가이드라인의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **디지털 정부서비스 UI/UX 가이드라인** 은 중앙행정기관, 지자체 및 공공기관이 대국민 디지털 서비스를 구축·운영할 때 일관되고 접근성 높은 사용자 경험을 제공하도록 규정한 행정안전부 표준 지침 |
| 목적 | 공공 웹·앱 전반의 사용자 경험 통일, 불필요한 탐색 비용 절감, 디지털 취약계층의 행정 접근성 보장 및 공공 SW 개발 비용 절감 |

## Ⅱ. 가이드라인 핵심 원칙 및 특징

| 구분 | 7대 핵심 원칙 | 세부 설계 특징 및 공학적 지침 |
|---|---|---|
| **원칙 1** | 사용자 중심 (User-Centered) | 공급자 중심 행정 용어 탈피, 일상적 언어 사용 및 직관적 과업 완결 지원 |
| **원칙 2** | 포용성 (Inclusivity) | 장애인·고령자·다문화 가정도 차별 없이 이용 가능한 배리어프리 및 웹 접근성(KWCAG) 준수 |
| **원칙 3** | 일관성과 조화 | 범정부 공통 사용자 경험(KRDS)을 유지하면서도 개별 기관의 업무 맥락 수용 |
| **원칙 4** | 간결한 이용 (Simplicity) | 한 화면에 단일 핵심 목적만 제시, 불필요한 입력 필드 제거(구비서류 제로화) |
| **원칙 5** | 이해하기 쉬운 상호작용 | 버튼·링크의 역할 명확화, 오류 발생 시 명확한 해결 방법 안내 |
| **원칙 6** | 다양한 이용 상황 고려 | 반응형 웹(Responsive Web) 기본 지원, 모바일·태블릿·데스크톱 연속성 보장 |
| **원칙 7** | 신뢰성 (Trustworthiness) | 공식 정부 도메인(.go.kr) 표기, 최신 정보 갱신 일자 표시 및 보안 신뢰감 제공 |

## Ⅲ. KRDS 아키텍처 및 UI/UX 설계·검증 프로세스

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ [ 대한민국 정부 디자인 시스템(KRDS) 4단계 설계 및 검증 파이프라인 ]         │
└─────────────────────────────────────────────────────────────────────────────┘
  [ Layer 1: 스타일 가이드 (Style Guide) ]
    ├── 타이포그래피(Pretendard GOV), 공공 색상 팔레트(Color Token), 그리드 시스템
          │
          ▼
  [ Layer 2: UI 컴포넌트 (UI Components) ]
    ├── 버튼, 텍스트 입력 폼, 체크박스, 모달 팝업, 탭(Tab), 브레드크럼(Breadcrumb)
          │
          ▼
  [ Layer 3: 기본 패턴 (Basic Patterns) ]
    ├── 검색 필터링, 도움말 툴팁, 오류 검증(Validation), 페이지네이션
          │
          ▼
  [ Layer 4: 서비스 패턴 (Service Patterns) ]
    ├── 공공 원스톱 과업 흐름: [본인인증] ─> [신청서 입력] ─> [제출] ─> [진행/결과 조회]
          │
          ▼
  [ Layer 5: 사용성 검증 및 품질 감사 ]
    ├── KWCAG 웹 접근성 준수 평가 (명도 대비 4.5:1, 스크린리더 음성 호환)
    └── 실제 타깃 사용자(고령층·장애인) 대상 UT(Usability Test) 수행
```

```text
[ 공공 서비스 패턴의 선형적(Linear) 과업 완결 흐름 ]
[1. 서비스 안내/자격 확인] ─> [2. 간편인증 로그인] ─> [3. 폼 입력 & 자동완성] ─> [4. 최종 승인 & 알림]
```

| 설계 단계 | 주요 구현 활동 | 산출물 및 개발 리소스 |
|---|---|---|
| **스타일 정의** | CSS 디자인 토큰 정의 | globals.css, theme.json, 디자인 토큰 명세서 |
| **컴포넌트 조립** | 웹 표준 시맨틱 HTML5 태그 기반 구현 | KRDS React/Vue/HTML 컴포넌트 라이브러리 |
| **패턴 적용** | 다단계 입력 폼 위저드(Wizard) 구성 | 폼 유효성 검사 모듈, 접근성 ARIA 라벨 |
| **사용성 검증** | 사용성 평가(UT) 및 접근성 진단 | 사용성 평가 보고서, 웹 접근성 품질마크 |

## Ⅳ. KRDS 4대 설계 계층 상세 비교

| 설계 계층 | 정의 및 구성 요소 | 주요 역할 및 공학적 예시 |
|---|---|---|
| **1. 스타일 (Style)** | 시각적 기본 규칙 (색상, 서체, 간격) | Gov Blue 메인 컬러, 명도 대비 4.5:1 이상 토큰화 적용 |
| **2. 컴포넌트 (Component)** | 단일 인터랙션을 수행하는 기본 UI 부품 | Button, Input, Select, DatePicker, Accordion, Modal |
| **3. 기본 패턴 (Basic Pattern)** | 컴포넌트의 유기적 결합 조합 | Form Validation(실시간 인라인 오류), Search & Filter |
| **4. 서비스 패턴 (Service Pattern)** | 대국민 핵심 과업을 완결하는 E2E 여정 | 간편로그인, 수수료 결제, 구비서류 첨부, 민원 처리 추적 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| KRDS 스타일만 형식적으로 복사하고 실제 행정 절차는 기존의 복잡한 다단계 서식(PDF 다운로드 등)을 유지하는 무늬만 표준화 | 사업 착수 시 'AS-IS 사용자 여정 분석(Journey Map)'을 의무화하고, 행정 서식 자체를 디지털 인터랙티브 폼으로 간소화하는 BPR 선행 |
| 발주사 및 개발사의 자체적인 컴포넌트 변형으로 인해 화면 깨짐 및 스크린리더 등 보조공학 기기 호환성 파괴 | 공식 오픈소스 npm 패키지(`@krds/core`) 의무 도입, CI/CD 테스트 단계에서 axe-core 기반 접근성 자동 테스트 강제화 |
| 고령층 및 다문화 가정이 행정 전문용어와 복잡한 조건문(소득분위, 자격요건)을 이해하지 못해 포기 | 생성형 AI 기반 '쉬운 말 서비스(Easy-read)' 자동 변환 모듈 결합 및 원스톱 자격 자동 판정 알고리즘 적용 |

## Ⅵ. 제언

국민 중심 디지털 정부를 완성하기 위해 오픈소스 KRDS 디자인 토큰을 프런트엔드 빌드 파이프라인에 직접 바인딩하고, 실제 사용성 지표(완결 시간·이탈률)를 상시 추적하는 데이터 기반 UX 거버넌스 확립.

```text
[ 디자이너 피그마(Figma) KRDS UI 설계 ]
                 │
                 ▼
[ 디자인 토큰(Design Tokens) 자동 추출 및 Git 동기화 ]
                 │
                 ▼
[ 프런트엔드 빌드 파이프라인 (CI/CD) ]
    ├── Step 1: KRDS 공식 컴포넌트 무결성 검증
    ├── Step 2: axe-core 웹 접근성 자동 스캔 (100% Pass)
    └── Step 3: 반응형 뷰포트(Mobile/Tablet/PC) 자동 렌더링 검사
                 │
                 ▼ (배포 완료)
[ 사용자 행동 분석 (과업 완료율, 클릭 히트맵, 이탈 퍼널 상시 추적) ]
```

| 구분 | 단순 디자인 가이드라인 준수 | 제언: 데이터 주도 디지털 UI/UX |
|---|---|---|
| **개발 방식** | 가이드라인 PDF 보고 수동 코딩 | npm 패키지 기반 공식 컴포넌트 직접 임포트 |
| **품질 검증** | 검수 시점 육안 화면 점검 | CI/CD 자동화 접근성(axe-core) 린팅 |
| **평가 기준** | 행정 지침 형식 준수 여부 | 실제 사용자의 과업 완료율(Task Success Rate) |
| **지속 개선** | 구축 후 유지보수 방치 | 사용자 이탈 데이터 기반 UI 주기적 A/B 개선 |
