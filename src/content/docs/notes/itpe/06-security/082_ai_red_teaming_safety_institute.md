- 메커니즘: 위협 모델·시험 범위 설정 → 공격 재현 → 증거 기록·완화 → 재시험; 시험 통과가 안전 보증은 아님

## 2~4교시 25점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | AI 레드티밍은 승인된 범위에서 모델·응용·도구의 오용 가능성을 공격자 관점으로 시험하는 활동 |
| 목적 | 배포 위험 발견과 완화 조치의 재시험 |

- 배포 전후 AI 시스템의 위험을 적대적 시나리오로 발견하고 완화 효과를 확인.
### Ⅱ. 레드팀 시험 구성과 흐름

```text
모델: 탈옥·유해 출력
응용: 간접 지시·민감정보 노출
도구: 권한 오용·외부 상태 변경
           ↓ 승인 범위·중단 조건
        시험·재현·조치 확인
```
- 탈옥·간접 프롬프트 인젝션, 민감정보 노출, 도구 오용, 편향·유해 출력 등을 모델·응용 맥락별 선정.
### Ⅲ. 시험 단계와 검증 항목

| 단계 | 산출물 | 확인 기준 |
|---|---|---|
| 범위 설정 | 승인 대상·중단 조건 | 업무 영향과 시험 권한 |
| 공격 시험 | 재현 가능한 입력·결과 | 성공 조건·증거 기록 |
| 완화·회귀 | 수정 내역·재시험 결과 | 변경 후 같은 경로의 차단 여부 |
- 승인된 범위와 중단 조건 → 공격 시나리오·평가 지표 → 시험·재현 → 위험도 분류 → 조치·회귀시험.
#### 역할·한계
- 연구기관의 평가 방법·공동 연구와 조직의 배포 책임을 구분. 시험 통과는 새 공격이나 모델 변경 이후의 안전을 보장하지 않음.

### Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 한 번의 레드팀 시험 통과가 모델 변경 뒤 안전을 보장하지 못함 | 발견 공격을 완화·회귀시험 항목으로 남기고 변경마다 재시험 |

### Ⅴ. 제언

평가 범위와 중단 조건을 먼저 승인하고 발견된 공격을 수정·회귀시험 항목으로 남긴다.
