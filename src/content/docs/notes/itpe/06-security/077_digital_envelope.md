## 연관 키워드

- 전자봉투(Digital Envelope), 하이브리드 암호화(Hybrid Encryption), 세션키(Session Key), 일회용 세션키
- 대칭키, 비대칭키, AES(Advanced Encryption Standard), 공개키, 개인키
- PKCS #7 EnvelopedData, S/MIME, OpenPGP, 전자서명(Digital Signature), Sign-then-Encrypt
- 중간자 공격(MitM), X.509 인증서, 쇼어 알고리즘(Shor's Algorithm), ML-KEM

## Ⅰ. 전자봉투의 개요

- 핵심 요약 : 대칭키의 처리 속도와 비대칭키의 안전한 키 전달을 결합해 대용량 기밀 메시지를 보내는 하이브리드 구조.
- 개념 : 평문은 **일회용 세션키** (Session Key)로 대칭 암호화하고, 세션키만 수신자의 공개키로 암호화해 함께 보내는 **전자봉투** (Digital Envelope) 기법.
- 배경 및 필요성 : 대칭키는 빠르지만 키를 안전하게 나눠 갖기 어렵고, 비대칭키는 키 전달이 쉽지만 대용량 연산이 느림. 두 방식의 약점을 나누어 맡기는 **하이브리드 암호화** (Hybrid Encryption) 구조가 요구됨.
- 주요 목적 : 대용량 기밀 메시지의 기밀성과 처리 성능을 동시에 확보.

## Ⅱ. 전자봉투의 특징 및 장점

- 핵심 요약 : 세션키의 일회성과 두 암호 방식의 역할 분담이 기밀성, 성능, 키 관리 부담 경감으로 이어지는 구조.

1. 일회용 세션키 : 메시지마다 새 키를 만듦 → 키 하나가 노출되어도 다른 메시지는 영향을 받지 않음.
2. 역할 분담 : 본문은 **AES** (Advanced Encryption Standard)로, 세션키는 공개키로 보호 → 대용량 처리 성능과 키 배송 문제를 함께 해결.
3. 수신자 한정 개봉 : 봉투는 수신자의 개인키로만 열림 → 전송 경로의 도청자가 본문을 읽을 수 없음.

## Ⅲ. 전자봉투의 구조 (흐름)

- 핵심 요약 : 송신 측의 세션키 생성, 본문 암호화, 봉투 생성이 수신 측의 봉투 개봉, 본문 복원과 대응되는 두 단계 흐름.

```text
[ 송신 단계 (Alice) ]

1. 일회용 세션키 무작위 생성
   ↓
2. 평문 본문을 세션키로 대칭 암호화
   ↓
3. 세션키를 수신자 공개키로 암호화 (봉투)
   ↓
4. 본문 암호문과 봉투를 함께 전송
```

```text
[ 수신 단계 (Bob) ]

1. 봉투를 수신자 개인키로 복호화
   ↓
2. 세션키 복구
   ↓
3. 세션키로 본문 복호화 → 평문 복원
```

## Ⅳ. 전자봉투와 유사 기법의 비교

- 핵심 요약 : 전자봉투는 기밀성, 전자서명은 인증과 무결성, 두 기능을 합친 방식은 기밀성과 인증을 함께 제공하는 구분.

| 비교 항목 | 전자봉투 (Digital Envelope) | **전자서명** (Digital Signature) | 서명 후 봉투 (Signed & Enveloped) |
| --- | --- | --- | --- |
| 핵심 보안 목적 | 데이터 기밀성 | 신원 인증, 무결성, 부인방지 | 기밀성, 무결성, 인증, 부인방지 |
| 사용되는 키 | 수신자의 공개키와 개인키 | 송신자의 개인키와 공개키 | 송신자 개인키와 수신자 공개키 |
| 처리 대상 | 대칭 세션키 | 메시지 해시값 | 해시값(서명)과 본문 및 세션키(봉투) |
| 표준 프로토콜 | PKCS(Public Key Cryptography Standards) #7 EnvelopedData | PKCS #7 SignedData | S/MIME, OpenPGP |
| 한계 | 송신자 인증 불가, 위조 메시지 가능 | 본문이 평문으로 노출 | 서명과 암호화 연산 부담 증가 |

- 선택 기준 : 본문 보호만 필요하면 전자봉투, 발신 사실과 무결성만 필요하면 전자서명, 두 요구가 함께 있으면 서명 후 봉투 구조를 사용함.

## Ⅴ. 전자봉투의 한계와 방안

- 핵심 요약 : 공개키 위조, 발신자 인증 부재, 양자 컴퓨터 위협을 인증서 검증, 서명 후 봉투, 양자내성 키 캡슐화로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **중간자 공격** (MitM, Man-in-the-Middle) | 검증되지 않은 공개키로 봉인되면 공격자가 세션키를 얻어 도청 가능 | 공인인증기관이 발행한 **X.509 인증서** 체인을 검증해 공개키의 진위 확인 | 인증서 검증 실패율 |
| 발신자 인증 부재 | 봉투 단독으로는 누가 보냈는지 확인할 수 없어 제3자가 위조 메시지를 봉투에 담을 수 있음 | 본문 해시에 송신자가 먼저 서명한 뒤 본문과 서명을 함께 봉투로 감싸는 **서명 후 암호화** (Sign-then-Encrypt) 적용 | 서명 검증 실패 건수 |
| 양자 컴퓨터 위협 | 쇼어 알고리즘으로 RSA와 ECC가 깨지면 봉투 속 세션키가 노출됨 | **ML-KEM** (Module-Lattice-Based Key-Encapsulation Mechanism, FIPS(Federal Information Processing Standards) 203)을 이용한 키 캡슐화와 기존 방식을 결합한 하이브리드 봉투 구성 | PQC 전환율 |

## Ⅵ. 전자봉투에 대한 기술사적 제언

- 핵심 요약 : 전자봉투의 실효성은 공개키 신뢰 체계와 알고리즘 전환 일정에 달려 있어, 제도와 운영을 함께 설계해야 함.

1. 신뢰 체계 : 전자 인증 관리 기관이 공개키 인증서의 발급과 폐지 절차를 정비하고, 인증서 상태 조회 체계를 기관 간에 공유하도록 함.
2. 전환 일정 : 국가 암호 정책 기관이 RSA와 ECC 기반 봉투의 사용 중단 시한을 정하고, 기관별 전환 계획을 주기적으로 점검함.
3. 제품 선정 : 정보보호 조직이 전자메일과 파일 보안 제품을 도입할 때 S/MIME 등 표준 프로토콜 지원 여부와 서명 후 봉투 구조 지원 여부를 기준으로 삼음.

## Ⅶ. 결론

- 핵심 요약 : 전자봉투는 하이브리드 암호화로 대용량 기밀 전송을 구현하는 표준적 구조.
- 시사점 : 봉투의 안전성은 공개키 인증과 전환 능력에 달려 있으므로, 기밀성과 발신자 인증을 함께 설계해야 기능이 완결됨.
