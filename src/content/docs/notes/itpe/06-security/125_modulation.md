## 답안 골격
```text
[변조(Modulation / Modification)] ◀━━ 머리: Ⅶ 내 의견 (단순 전송로 신뢰 탈피 → 해시 체인 및 암호학적 메시지 인증(MAC)을 통한 실시간 무결성 변조 검증)
 ┃
 ┣━ Ⅰ 개요 ───── 정보보안 및 통신 환경에서 전송 중이거나 저장된 정당한 데이터·신호의 내용을 비인가된 제3자가 불법적으로 수정·변경·왜곡하여 무결성(Integrity)을 훼손하는 핵심 사이버 위협
 ┣━ Ⅱ 특징 ───── 무결성(Integrity) 침해 · 기존 원본 데이터의 존재를 전제함 · 능동적 공격(Active Attack) 형태 · 통신 공학적 신호 변조(Modulation)와 보안상 데이터 변조(Modification)의 이중적 해석
 ┣━ Ⅲ 구조 ───── 송신자 원본 데이터 + 비인가 개입자(MITM 중간자 공격) + 데이터 변조 행위(비트 반전, 값 조작) + 변조된 수신 데이터
 ┣━ Ⅳ 흐름 ───── 정상 송신자 패킷 발송 → 공격자의 중간 가로채기(ARP 스푸핑 등) → 데이터 페이로드 수정(계좌번호/금액 변경) → 재전송 → 수신자가 변조 사실 인지 못하고 수락
 ┣━ Ⅴ 비교 ───── 변조(Modification, 기존 정당한 데이터의 일부를 바꿈, 무결성 침해) vs 위조(Fabrication, 없던 가짜 데이터를 새롭게 만들어냄, 인증/진정성 침해)
 ┗━ Ⅵ 실무 ───── 단순 체크섬(CRC32)의 변조 탐지 무력화 / 전자서명 미검증 시 비트 플리핑 노출 / 블록체인 등 분산 원장의 51% 변조 위협
```
- 필수 키워드: 변조(Modification/Modulation) · 위조(Fabrication) · 무결성(Integrity) · 중간자 공격(MITM) · HMAC · 전자서명 · 비트 플리핑
- 기출: 제127회 1교시 9번: "변조(Modification)와 위조(Fabrication)"

## 한 줄 본질
- 네트워크 상에서 전송되는 데이터를 공격자가 중간에서 몰래 가로채 특정 필드(금액, 수신자)를 조작하는 무결성 훼손 병목 → 암호학적 단방향 해시 함수와 비밀키 기반 MAC·전자서명으로 1비트의 변조도 즉각 검출 → 완벽한 데이터 무결성 보장 / 송수신 양단의 암호학적 연산 오버헤드 발생

## 핵심 그림
```text
[정보보안의 4대 전송 위협 중 변조(Modification)와 위조(Fabrication)의 차이]

[1. 변조 (Modification) - 무결성 침해]
  [정상 송신자] ──(정상 메시지: 100만 원)──> [공격자 (중간자 MITM)]
                                                     │ (금액을 1억 원으로 수정!)
                                                     ▼
  [정상 수신자] <────────(변조된 메시지: 1억 원)──────┘

[2. 위조 (Fabrication) - 인증/진정성 침해]
  [정상 송신자] (아무런 메시지도 보내지 않음!)

  [공격자]      ──(송신자 명의를 도용해 가짜 메시지 직접 생성)──> [정상 수신자]
```

## 핵심 용어
- 변조 (Modification): 정당한 주체 간에 오가는 원본 데이터의 내용을 중간에서 불법적으로 조작, 변경, 순서 교체, 지연 전송하여 수신자를 속이는 행위로 무결성(Integrity)을 침해함
- 위조 (Fabrication): 송신자가 존재하지 않거나 아무것도 보내지 않았음에도 불구하고, 공격자가 정당한 송신자의 신원을 사칭하여 허위의 데이터를 새롭게 생성해 시스템에 주입하는 행위로 진정성(Authenticity)을 침해함

## 핵심 통찰
- 변조는 "있는 것을 바꾸는 것"이고, 위조는 "없는 것을 만드는 것"임 → 은행 송금에서 공격자가 송금액 1만 원을 100만 원으로 바꾸는 것은 '변조'이고, 송금 요청을 한 적도 없는데 가짜 송금 지시서를 제출하는 것은 '위조'임
- 네트워크 오류를 검출하는 CRC32나 패리티 비트는 변조를 막지 못함 → 공격자는 데이터를 변조한 후 그에 맞게 CRC 값을 다시 계산해서 패킷에 넣으면 그만이기 때문임
- 따라서 변조를 막으려면 반드시 공격자가 알지 못하는 '비밀키'가 결합된 암호학적 서명(HMAC, Digital Signature)을 적용해야 함

## 이웃 토픽과 구분
- 변조(Modification) vs 가로채기(Interception): 가로채기 = 몰래 훔쳐보는 수동적 도청(기밀성 침해, 원본 손상 없음) / 변조 = 데이터를 적극적으로 뜯어고치는 능동적 침해(무결성 파괴)

## 문제·원인·대책
- 사례: 사물인터넷(IoT) 센서가 서버로 전송하는 온도·압력 패킷을 중간자가 변조하여 공장 설비의 이상 과열 경보를 무력화한 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 센서 데이터 패킷의 파라미터 변조로 인한 오작동 | 평문 통신 및 단순 체크섬(Checksum) 무결성 검증 사용 | 암호학적 메시지 인증 코드(HMAC-SHA256) 또는 TLS 1.3 암호화 적용 | 데이터 1비트 변조 시에도 수신단에서 태그 불일치로 즉각 폐기 |
| 데이터베이스 저장 기록의 관리자 권한 무단 변조 | 단일 중앙 DB의 업데이트 권한 남용 및 감사 추적 결여 | 블록체인 분산 원장 또는 WORM(Write-Once) 스토리지 도입 | 과거 데이터의 수정 및 변조 원천 불가능화 |

## 이렇게 출제된다
- 제127회 1교시 9번: "변조(Modification)와 위조(Fabrication)" → 요구 포인트: Ⅰ 변조와 위조의 정의 + Ⅲ 공격 흐름 비교 도식 + Ⅴ 무결성 vs 진정성 침해 관점의 상세 비교표

## 내 의견
- [전자금융 거래의 엔드-투-엔드 변조 방지(E2E 암호화) 가상 키패드 표준화] PC나 모바일 단말의 메모리 레벨에서 키보드 입력값을 가로채 변조하는 메모리 해킹이 기승을 부림 → 나라면: 사용자 입력 시점부터 금융사 백엔드 서버의 HSM까지 평문 노출 없이 단 대 단으로 암호화되는 동적 이미지 난수 가상 키패드 규격을 강제하고, 세션 토큰에 트랜잭션 서명(TX-Sign)을 결합해 파라미터 변조 시 거래가 자동 무효화되도록 구현
