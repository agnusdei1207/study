지식 위치: 정보보호 기본 → 무결성·진정성 침해 → **변조와 위조**

## 30초 인출

- **본질:** 변조는 전송·저장 중인 기존 데이터의 비인가 변경(무결성 침해)이며, 위조는 정당한 송신자를 사칭하여 허위 데이터를 새로 생성·주입하는 공격(진정성 침해)
- **메커니즘:** 능동적 중간자 공격(MitM)을 통한 패킷 페이로드 조작(변조) 또는 위조 신원·세션 주입(위조) → HMAC/AEAD 인증 태그 검증 및 전자서명 유효성 판정으로 방어
- **통찰:** 단순 해시/CRC는 공격자의 재계산으로 무력화되므로 비밀키 기반 HMAC/AEAD를 적용하고 재생 공격 방지를 위한 단조 시퀀스와 타임스탬프 윈도우 결합 필수

<details>
<summary>핵심 용어</summary>

- **변조 (Modification)** : 전송 중이거나 저장된 정당한 데이터의 일부 또는 전체를 비인가로 수정·삭제·삽입하는 행위.
- **위조 (Fabrication)** : 송신 권한이 없는 자가 정당한 송신자의 신원을 사칭하여 존재하지 않던 허위 데이터를 생성·주입하는 행위.
- **HMAC (Hash-based MAC)** : 공유 비밀키와 암호학적 해시 함수를 결합하여 데이터의 무결성과 출처 진정성을 보장하는 인증 코드.
- **AEAD (Authenticated Encryption with Associated Data)** : 데이터의 기밀성(암호화)과 무결성·인증을 단일 연산으로 동시 제공하는 암호 방식.

</details>

## 2~4교시 예상문제 (25점)

> 네트워크 및 데이터 보안 관점에서 데이터 변조(Modification)와 위조(Fabrication)의 개념적 차이, 공격 시나리오를 설명하고, 전송 및 저장 데이터의 무결성·진정성을 보장하기 위한 암호학적 검증 아키텍처와 엔지니어링 방안을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 변조(Modification)는 기존의 합법적인 데이터를 인가 없이 변경하는 무결성(Integrity) 침해이며, 위조(Fabrication)는 허위 데이터를 신규 생성하여 주입하는 진정성(Authenticity) 침해 공격 |
| 목적 | 데이터 라이프사이클(전송, 처리, 저장) 전반에 걸쳐 비인가 데이터 오염 및 신원 사칭을 원천 차단하고 종단간 신뢰성(End-to-End Trust) 확립 |

- ITU-T X.800 보안 아키텍처 상의 4대 능동적·수동적 위협 중 능동적 공격(Active Attack)에 해당하며, 비즈니스 트랜잭션의 법적 효력과 신뢰 기반을 붕괴시키는 핵심 요인

## Ⅱ. 변조와 위조의 기술적 특성

| 특성 항목 | 데이터 변조 (Modification) | 데이터 위조 (Fabrication) |
|---|---|---|
| 침해 보안 속성 | 무결성 (Integrity) | 진정성 (Authenticity) 및 인가(Authorization) |
| 공격 대상 데이터 | 이미 존재하는 정당한 트랜잭션·파일 | 존재하지 않던 신규 트랜잭션·가짜 패킷 |
| 공격자 역할 | 중간자(MitM)로서 통신 데이터 가로채기 후 수정 | 사칭자(Impersonator)로서 허위 메시지 생성 및 주입 |
| 탐지 기술 메커니즘 | 메시지 인증 코드(MAC), AEAD 인증 태그, 머클 트리 | 전자서명(Digital Signature), 상호 인증(mTLS), Kerberos 티켓 |
| 대표적 공격 사례 | 계좌 이체 금액/수취인 변조, 센서 데이터 조작 | ARP/DNS 스푸핑, 위조 이메일(스피어피싱), 가짜 인증 토큰 주입 |

- 두 공격은 상호 독립적으로 발생할 수 있으나, 패킷 가로채기 후 변조하여 재전송하는 복합 위협 형태로 빈번히 발생

## Ⅲ. 변조·위조 공격 흐름 및 암호학적 방어 아키텍처

```text
[변조·위조 공격 모델 및 암호학적 방어 메커니즘]

 1. 데이터 변조 공격 및 HMAC 방어
 [송신자 A] ──(평문 M + HMAC(K, M))──> [중간 공격자: M 변조] ──(M' + HMAC(K,M))──> [수신자 B]
                                                                               │
                                                                   HMAC(K, M') != HMAC(K, M)
                                                                   ==> 변조 즉시 탐지 및 폐기

 2. 데이터 위조 공격 및 전자서명 방어
 [공격자 C] ──(사칭 메시지 M_fake + 위조 서명)──> [수신자 B]
                                                   │
                                       A의 공개키로 서명 검증 실패
                                       ==> 위조 메시지 즉시 기각
```

| 검증 계층 | 적용 핵심 기술 | 보안 기능 및 무결성 보장 방식 |
|---|---|---|
| 전송 계층 (In-Transit) | TLS 1.3 (AES-GCM / ChaCha20-Poly1305 AEAD) | 전송 패킷의 기밀성과 무결성을 동시 검증, 인증 태그 불일치 시 연결 강제 리셋 |
| 메시지 계층 (In-Message) | HMAC-SHA256, Ed25519 전자서명, JWS | 공유 대칭키 또는 공개키 기반으로 메시지 단위 출처 확인 및 부인 방지 제공 |
| 저장 계층 (At-Rest) | 머클 트리(Merkle Tree), WORM 스토리지, SHA-256 해시 체인 | 저장된 데이터의 무단 수정 시 루트 해시 불일치로 변조 블록 즉시 식별 |
| 데이터베이스 계층 | 암호학적 원장(Cryptographic Ledger), 블록체인 | Append-Only 불변 원장 구조를 통해 과거 데이터 수정 및 위조 원천 차단 |

## Ⅳ. ITU-T X.800 4대 보안 위협 비교

| 위협 유형 | 침해 속성 | 공격 특성 | 주 공격 방식 | 대표적 방어 대책 |
|---|---|---|---|---|
| 가로막기 (Interruption) | 가용성 (Availability) | 능동적 공격 | 시스템 자원 파괴, 네트워크 단선, DoS/DDoS | 이중화, 트래픽 스크러빙, 분산 인프라 |
| 가로채기 (Interception) | 기밀성 (Confidentiality) | 수동적 공격 | 네트워크 스니핑, 무선 도청, 패킷 캡처 | 대칭/비대칭 암호화, IPsec, TLS 전송 |
| 변조 (Modification) | 무결성 (Integrity) | 능동적 공격 | 패킷 내용 조작, 파일 변조, 시퀀스 변경 | 해시 함수, HMAC, AEAD, 전자서명 |
| 위조 (Fabrication) | 진정성 (Authenticity) | 능동적 공격 | 신원 사칭, 위조 패킷 주입, 재생 공격 | 전자서명, PKI, 챌린지-응답 상호 인증 |

## Ⅴ. 변조·위조 방어 시 엔지니어링 한계와 해결 방안

| 한계 | 방안 |
|---|---|
| 단순 순환 중복 검사(CRC32)나 체크섬 적용 시 공격자가 변조된 데이터에 맞춰 체크섬을 재계산하여 검증 우회 | 공유 비밀키가 포함되지 않은 단순 체크섬을 전면 배제하고, 암호학적 안전성이 입증된 HMAC-SHA256 또는 AEAD(AES-GCM) 암호 스위트 강제 적용 |
| 올바른 HMAC/서명이 포함된 정상 패킷을 공격자가 도청 후 그대로 다시 전송하는 재생 공격(Replay Attack) 방어 불가 | 데이터 페이로드에 단조 증가 시퀀스 번호(Monotonic Counter), 암호학적 일회용 난수(Nonce) 및 유효 타임스탬프 윈도우(Time Window)를 결합하여 검증 |
| 엔드포인트 단말 메모리가 악성코드에 감염되어 서명/암호화 함수 호출 직전에 메모리 상의 평문이 변조되는 MitB(Man-in-the-Browser) 공격 | 하드웨어 기반 신뢰실행환경(TEE/TrustZone) 내에서 서명 키 격리 및 트랜잭션 승인을 수행하고, Out-of-Band 모바일 푸시 상호 인증 결합 |
| 데이터베이스 관리자(DBA) 권한 탈취 시 로컬 데이터 직접 UPDATE 및 로그 파일 무단 변조(Log Tampering) 통제 한계 | 블록체인형 불변 데이터베이스(AWS QLDB 등) 적용, 머클 트리 기반 데이터 감사 로그 생성 및 WORM(Write Once Read Many) 전용 원격 스토리지 격리 |

## Ⅵ. 무결성·진정성 보장을 위한 엔터프라이즈 아키텍처 제언

```text
[엔드투엔드 무결성·진정성 보증 엔터프라이즈 아키텍처]

  +---------------------------------------------------------------+
  |                 1. 엔드포인트 계층: TEE 기반 격리             |
  |     - ARM TrustZone / Intel SGX 기반 개인키 격리 서명          |
  |     - 런타임 메모리 보호 (W^X, ASLR, Control Flow Guard)     |
  +---------------------------------------------------------------+
                                  │
                                  ▼
  +---------------------------------------------------------------+
  |                 2. 통신 구간 계층: AEAD & mTLS                |
  |     - TLS 1.3 상호 인증 (Mutual TLS) 강제                     |
  |     - Nonce + Timestamp 기반 재생 공격 방어 필터 적용         |
  +---------------------------------------------------------------+
                                  │
                                  ▼
  +---------------------------------------------------------------+
  |                 3. 저장 및 감사 계층: Merkle WORM             |
  |     - 분산 원장 머클 트리 기반 트랜잭션 불변성 체인 구축       |
  |     - WORM 스토리지 기반 사후 무단 변경 원천 차단             |
  +---------------------------------------------------------------+
```

| 영역 | 엔지니어링 핵심 과제 | 검증 지표 |
|---|---|---|
| 전송 무결성 | API 게이트웨이 전 구간 TLS 1.3 및 HMAC 메시지 인증 적용 | 위변조 패킷 탐지 및 드롭율 100%, 복호화 지연 < 5ms |
| 신원 진정성 | 서비스 간 통신(mTLS) 및 사용자 트랜잭션별 전자서명 검증 | 인가되지 않은 위조 요청 차단율 100% |
| 저장 무결성 | 감사 로그 및 핵심 금융 원장의 머클 트리 해시 체인 연동 | 데이터 무단 수정 발생 시 5초 이내 변조 블록 감지 |
