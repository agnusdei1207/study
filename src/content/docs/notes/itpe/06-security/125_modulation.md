## 지식 로드맵 내 현재 위치

지식 위치: 정보보호 기본 → 무결성·진정성 침해 → **변조와 위조**

## 30초 인출

- 본질: 변조는 기존 데이터의 비인가 변경, 위조는 정당한 발신자를 사칭한 새 허위 데이터 생성
- 메커니즘: 공격자가 전송 메시지를 수정하거나 새 메시지를 주입해 수신자가 원본·출처를 잘못 신뢰하도록 유도
- 통찰: 한계: CRC는 공격자가 재계산할 수 있어 악의적 변경을 막지 못함 → 방안: MAC·전자서명 또는 AEAD로 출처·무결성을 확인

<details>
<summary>핵심 용어</summary>

- **변조(Modification)** : 기존 데이터를 권한 없이 바꾸는 무결성 침해.
- **위조(Fabrication)** : 정당한 발신자를 사칭해 새 허위 메시지를 만드는 행위.
- **HMAC** : 공유 비밀키로 메시지 출처와 무결성을 검증하는 인증 코드.
- **AEAD** : 암호화와 인증을 결합해 기밀성·무결성을 함께 제공하는 방식.

</details>

## 2~4교시 예상문제 (25점)

> 데이터 변조와 위조의 차이를 공격 흐름으로 설명하고, 전송·저장 데이터의 무결성 검증 구조를 설계하시오. (예상·25점)

## 2~4교시 25점 답안

### Ⅰ. 개요

| 항목 | 개요 |
|---|---|
| 정의 | 데이터 변조는 기존 데이터의 비인가 변경, 위조는 발신자를 사칭한 새 허위 데이터의 생성 |
| 목적 | 무결성·출처 진정성 침해 유형에 맞는 인증·검증 통제 적용 |

무결성은 부적절한 정보 수정·파괴로부터의 보호. 출처 인증은 수신한 메시지가 기대한 발신자의 것인지 확인하는 절차.

### Ⅱ. 공격 흐름

```text
[변조] A의 원본 메시지 → 공격자가 내용 변경 → B가 변경본 수신
[위조] A의 송신 없음    → 공격자가 A를 사칭해 허위 메시지 생성 → B 수신
```

변조·위조는 구분되지만, 공격자가 기존 메시지를 수정한 뒤 다시 발신한 경우 두 성격이 겹칠 수 있음.

### Ⅲ. 대응 기술과 검증 범위

| 기술 | 보호 내용 | 주의점 |
|---|---|---|
| CRC·일반 체크섬 | 우발적 오류 탐지 | 적대적 변경에 대한 인증 미제공 |
| HMAC | 공유 비밀키를 이용한 메시지 출처·무결성 확인 | 키 배포·보관, 재전송 방어 별도 설계 |
| 전자서명 | 공개키 검증을 이용한 출처·무결성 확인 | 인증서·키 바인딩 검증 필요 |
| AEAD | 암호문 기밀성과 무결성 동시 보호 | 논스 재사용 금지와 태그 검증 필요 |
| WORM·감사 로그 | 사후 기록 변경 억제·추적 | 접근 통제와 보존 정책 병행 |

HMAC은 해시 함수만 적용하는 것과 다르며, MAC 검증 성공이 내용의 업무상 진실성까지 증명하지는 않음.

#### 금융 거래 적용

| 단계 | 설계 |
|---|---|
| 입력 | 수취 계좌·금액·거래 식별자 확인 |
| 서명·인증 | 서버와 단말의 신뢰 경계를 고려해 거래 내용 바인딩 |
| 수신 검증 | 인증 태그·서명·거래 식별자·시각 검증 |
| 저장 | 변경 권한 분리, 감사 로그와 복구 가능성 관리 |

단순 TLS 전송 보안만으로 감염된 단말 내부의 거래값 조작을 제거할 수 없으므로, 사용자에게 승인 대상 거래 내용을 독립적으로 확인시키는 설계 필요.

### Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| CRC는 공격자가 재계산할 수 있어 악의적 변경을 막지 못함 | MAC·전자서명·AEAD로 출처와 무결성을 검증 |

### Ⅴ. 제언

전송 구간의 암호학적 인증과 저장 기록의 권한·감사 통제를 연계한 종단간 무결성 관리.
