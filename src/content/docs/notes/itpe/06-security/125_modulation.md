## Ⅰ. 데이터 변조(Modification)와 위조(Fabrication)의 개요

- 개념 : **데이터 변조** (Modification)는 전송 중이거나 저장된 정상 데이터를 인가되지 않은 제3자가 불법적으로 수정·삭제·추가하는 **무결성 침해** 공격이며, **데이터 위조** (Fabrication)는 권한이 없는 자가 허위의 메시지나 자원을 마치 정당한 송신자가 보낸 것처럼 거짓 생성하여 주입하는 **인증 및 진본성 침해** 공격.
- 배경 및 필요성 : 초기 인터넷 프로토콜(IP, TCP, ARP, DNS 등)은 통신 상대방의 정당성을 검증하는 암호학적 인증 메커니즘 없이 설계되었으며, 이를 악용한 **중간자 공격** (MITM), 스푸핑, 세션 하이재킹이 일상화됨.
- 핵심 목적 : 데이터의 3대 보안 목표(CIA) 중 무결성(Integrity)과 신원 인증(Authentication), **부인 방지** (Non-repudiation)를 파괴하는 공격 메커니즘을 규명하고, 암호학적 방어 기법을 통해 원본의 진본성을 보장.

## Ⅱ. 데이터 변조(Modification)와 위조(Fabrication)의 핵심 아키텍처 및 동작 메커니즘

변조는 정상 트래픽을 가로채어 내용을 변경(Man-In-The-Middle)하는 흐름을 가지며, 위조는 존재하지 않던 가짜 트래픽을 인위적으로 주입(Packet Injection)하는 방식으로 발생함.

```text
[ 데이터 변조(Modification) vs 데이터 위조(Fabrication) 메커니즘 ]

 1. 데이터 변조 (Modification) : 중간에서 기존 메시지 내용 변경
    +--------+         [ 중간자 (Attacker) ]         +--------+
    | 송신자 | ------> | 가로채기 -> 내용 변경 | ------> | 수신자 |
    +--------+         | "송금: 100원" -> 10만원|         +--------+
                       +-----------------------+
                       (원래 트래픽의 무결성 침해)

 2. 데이터 위조 (Fabrication) : 가짜 신원과 메시지를 새로 생성하여 주입
                       +-----------------------+
                       | 공격자 (Spoofed IP)   |
                       | "나 정상 송신자야!"   |
                       +-----------+-----------+
                                   | (허위 메시지 신규 발행)
                                   v
    +--------+                 +--------+
    | 송신자 | (모름/침묵)     | 수신자 | (속아서 처리)
    +--------+                 +--------+
                               (출처 진본성 및 가용성 침해)
```

- 변조(Modification)의 특징 : 전송 중인 패킷을 스니핑하여 패킷 필드 값을 임의 조작(TCP 시퀀스 번호 조작, 데이터 페이로드 변경)하거나 DB 내 레코드를 **SQL Injection**으로 무단 변경.
- 위조(Fabrication)의 특징 : 발신자 IP나 MAC 주소를 도용하여 **ARP Reply** 패킷을 주기적으로 뿌리거나(ARP 스푸핑), 허위 DNS 응답을 질의자보다 먼저 전송(DNS 포이즈닝)하여 가짜 서버로 유도.
- 보안 위협 대상 : 변조는 무결성(Integrity)을 정면으로 훼손하며, 위조는 인증(Authenticity)과 진본성을 훼손하고 **서비스 거부** (DoS)를 유발.
- 핵심 대응 프리미티브 : 단순 체크섬(CRC)은 재계산이 가능하여 방어가 불가하며, **HMAC** (비밀키 기반 메시지 인증 코드) 및 **디지털 서명** (Digital Signature, 비대칭키 방식) 적용 필수.

## Ⅲ. 데이터 변조(Modification)와 위조(Fabrication)의 세부 구성 요소 및 비교 분석

| 비교 항목 | **데이터 변조** (Modification) | **데이터 위조** (Fabrication) | **데이터 가로채기** (Interception) | **데이터 가로막기** (Interruption) |
| --- | --- | --- | --- | --- |
| 공격 성격 | 능동적 공격 (Active Attack) | 능동적 공격 (Active Attack) | 수동적 공격 (Passive Attack) | 능동적 공격 (Active Attack) |
| 침해 속성 | 무결성 (Integrity) | 인증성 (Authenticity), 무결성 | 기밀성 (Confidentiality) | 가용성 (Availability) |
| 공격 행위 | 기존 데이터의 불법 수정, 삽입, 순서 변경 | 허위 데이터 및 가짜 신원 신규 생성 주입 | 트래픽 도청, 패킷 스니핑, 불법 복제 | 네트워크 단절, 서비스 DoS, 파일 물리적 삭제 |
| 대표 사례 | 파라미터 변조 결제, 웹페이지 디페이스 | ARP 스푸핑, DNS 캐시 포이즈닝, 딥페이크 | 와이어샤크 스니핑, 무선 도청 | SYN Flood DDoS, 랜섬웨어 파일 암호화 |
| 핵심 방어책 | HMAC, 전자서명, 블록체인 무결성 검증 | 상호 TLS(mTLS), DNSSEC, 802.1X 인증 | 전송 구간 엔드투엔드 암호화 (TLS) | 이중화 인프라, 안티 DDoS, 백업 복구 |

- 변조와 위조는 데이터의 신뢰성을 근본적으로 파괴하는 능동적 공격이므로, 단순 해시 함수가 아닌 암호화 키가 결합된 HMAC 및 공개키 기반 상호 인증이 필수적 방어책임.

## Ⅳ. 데이터 변조(Modification)와 위조(Fabrication)의 주요 한계점 및 해결 방안

- 단순 해시(MD5, SHA-256)의 중간자 재계산 변조 취약점 :
  - 한계점 : 데이터와 해시값을 평문으로 함께 전송할 경우 중간자가 데이터를 변조한 후 새로운 해시값을 생성하여 전송하면 수신자는 변조 여부 감지 불가.
  - 해결 방안 : 사전 공유된 비밀키가 결합된 메시지 인증 코드(HMAC)나 송신자 개인키로 서명된 디지털 서명(ECDSA) 의무화.
- 정상 패킷을 재전송하는 재전송 공격(Replay Attack) 방어 한계 :
  - 한계점 : 패킷 내용 자체는 변조하지 않고 정상 서명된 금융 거래 요청을 그대로 녹음하여 반복 재전송하면 위조 효과 발생.
  - 해결 방안 : 메시지 페이로드에 난수(Nonce), 타임스탬프, 증가하는 시퀀스 카운터를 포함하여 이전 메시지의 재사용을 즉시 폐기.
- 비대칭 암호키 노출 시 변조·위조의 전면 허용 :
  - 한계점 : 송신자의 개인키(Private Key)가 엔드포인트 탈취 등으로 유출되면 공격자가 완벽히 합법적인 서명으로 위조 및 변조를 감행하여 검증 무력화.
  - 해결 방안 : 개인키를 소프트웨어 파일이 아닌 하드웨어 보안 모듈(HSM)이나 TPM 내부에 저장하고, 인증서 폐기 목록(CRL/OCSP Stapling) 실시간 연동.

## Ⅴ. 데이터 변조(Modification)와 위조(Fabrication) 적용 및 발전을 위한 기술사적 제언

- 전송 계층 상호 인증(Mutual TLS)의 전사 확대 : 클라이언트와 서버가 서로의 X.509 인증서를 상호 검증하는 mTLS를 마이크로서비스 간 통신에 기본 적용하여 위조 패킷 주입을 차단.
- DNSSEC 및 RPKI 기반 인터넷 코어 인프라 위조 방어 : DNS 캐시 포이즈닝 방지를 위한 DNSSEC 서명 도입과 BGP 하이재킹 차단을 위한 RPKI(Resource Public Key Infrastructure) 라우팅 검증 구축.
- 블록체인 분산 원장 기술을 활용한 감사 증적 변조 불가성 확보 : 주요 설정 로그, 접근 기록, 전자 계약 데이터를 하이퍼레저 또는 이더리움 블록체인 해시로 앵커링하여 사후 변조 시도를 원천 입증.
