## Ⅰ. 섀도우 AI(Shadow AI)의 개요

- **개념** : 사내 공식 보안 평가 및 승인 절차를 거치지 않고 임직원이 개인 계정이나 브라우저 확장을 통해 외부 퍼블릭 생성형 AI를 업무에 무단 활용하는 상태.
- **배경 및 필요성** : 조직 내 임직원이 IT 및 보안 부서의 사전 승인 없이 개인 계정으로 외부 생성형 AI(ChatGPT 등)를 업무에 무단 활용하여 기업 소스코드, 고객 정보 등 핵심 기밀이 외부로 누출되는 위험을 통제하기 위해 출현함.
- **핵심 목적** : 섀도우 AI로 인한 핵심 영업비밀 및 개인정보 유출을 방지하고, 승인된 안전한 엔터프라이즈 AI 인프라를 제공하여 업무 생산성과 보안성의 균형 달성.

## Ⅱ. 섀도우 AI(Shadow AI)의 핵심 아키텍처 및 동작 메커니즘

섀도우 AI(Shadow AI)은(는) 신뢰할 수 있는 보안 구조와 표준화된 절차를 기반으로 동작하며, 세부적인 아키텍처와 구성요소 간의 상호작용 메커니즘은 다음과 같음.

```text
[ 1. 기존 비인가 섀도우 AI 경로 (Shadow AI Path) ]
사내 단말 (임직원) ──▶ [ 비인가 퍼블릭 AI 웹/플러그인 ] ──▶ [ 모델 재학습 및 기밀 유출 발생! ]
                     (개인정보, 소스코드 무단 복사)

[ 2. 엔터프라이즈 AI 양성화 보안 아키텍처 (Enterprise AI Gateway) ]
사내 단말 (임직원)
       │
       ▼
[ CASB / SSE 게이트웨이 ]
 ├── [비인가 AI 도구 감시]: 비승인 무료 AI 사이트 접속 전면 차단 (URL 필터링)
 └── [승인 AI 리다이렉트]: 사내 공용 엔터프라이즈 AI 포털로 사용자 자동 유도
       │
       ▼
[ 엔터프라이즈 AI 보안 게이트웨이 (Private AI Gateway) ]
 ├── 1. 신원 인증: 사내 SSO / SAML 기반 사용자 직무별 접근 권한 인가
 ├── 2. 인라인 DLP: 프롬프트 내 주민번호, API 키, 핵심 키워드 실시간 마스킹 (Presidio)
 ├── 3. 프롬프트 인젝션 방어: 탈옥 및 유해 프롬프트 사전 차단
 └── 4. 로깅 및 감사: 입력 프롬프트 및 응답 결과 암호화 감사 저장 (SIEM 연동)
       │
       ▼
[ 전용 기업용 LLM 엔드포인트 (ZDR 계약 적용 클라우드 또는 온프레미스 Llama) ]
```

- **1. 가시성 확보** : CASB, EDR, 웹 게이트웨이(SWG) 섀도우 AI Discovery 분석 (사내 사용 중인 비인가 AI 서비스 식별).
- **2. 접속 통제** : DNS 싱크홀, 웹 필터링, 엔드포인트 브라우저 확장 설치 제한 (보안 미검증 퍼블릭 AI 도구 무단 접속 차단).
- **3. 프롬프트 보호** : 인라인 AI-DLP 프록시 구축, 데이터 토큰화(Tokenization) (기밀 소스코드 및 개인식별정보 전송 원천 차단).
- **4. 계약 및 보증** : 엔터프라이즈 전용 라이선스 도입 (ZDR, BAA 계약 체결) (입력 데이터의 벤더 측 모델 학습 배제 보장).
- **5. 모니터링/감사** : 중앙 집중 프롬프트/응답 로깅 파이프라인 및 이상 질의 탐지 (침해사고 발생 시 부인방지 및 책임 추적성 확보).

## Ⅲ. 섀도우 AI(Shadow AI)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 전통적 섀도우 IT (Shadow IT) | 섀도우 AI (Shadow AI) |
|---|---|---|
| 사용 대상 | 웹하드(Dropbox), 개인 메일, 협업 메신저(Slack) | 생성형 AI 챗봇(ChatGPT), 코드 완성 툴, 이미지 생성 AI |
| 주된 위험 | 단순 파일 저장 및 공유를 통한 데이터 유출 | 입력 데이터의 모델 학습 풀 흡수 및 비결정론적 정보 재생성 |
| 인터랙션 방식 | 파일 업로드/다운로드 중심 | 프롬프트 기반 실시간 대화, 파일 분석, 코드 실행 위임 |
| 데이터 침해 범위 | 유출된 파일 자체에 국한 | 향후 전 세계 불특정 다수 사용자에게 답변 형태로 기밀 재유출 |
| 대응 패러다임 | URL 차단 및 포트 제어로 비교적 통제 용이 | 단순 차단 시 생산성 저하 반발 극심, '양성화'가 유일한 해법 |

- 섀도우 AI(Shadow AI)은(는) 상기 핵심 비교 지표와 아키텍처 구성을 바탕으로 보안 위협에 대한 방어 효과성을 극대화하며, 기존 레거시 통제 기법 대비 우수한 신뢰성과 운영 효율성을 제공함.

## Ⅳ. 섀도우 AI(Shadow AI)의 주요 한계점 및 해결 방안

- **한계점** : 사내 PC에서 퍼블릭 AI 웹을 차단할 경우 스마트폰(BYOD)이나 개인 테더링을 이용해 프롬프트를 수동 입력하는 우회 행위 발생.
  - **해결 방안** : 차단 일변도 정책을 지양하고, 사내망 및 모바일 업무 앱 내에 안전한 전용 프라이빗 AI 챗봇 인터페이스를 공식 구축하여 양성화.
- **한계점** : 개발자가 복잡하게 난독화하거나 변형한 소스코드의 경우 정규식(Regex) 기반 DLP 엔진으로 탐지 불가.
  - **해결 방안** : AST(추상구문트리) 및 코드 구조를 분석하는 AI 기반 시맨틱 DLP 엔진을 게이트웨이에 연동하여 소스코드 패턴 정밀 탐지.
- **한계점** : 외부 AI 벤더가 계약상 ZDR(Zero Data Retention)을 약속했음에도 내부 로깅 정책 오류로 데이터가 잔존하는 서드파티 신뢰 결함.
  - **해결 방안** : 사내 온프레미스 GPU 클러스터 또는 프라이빗 VPC 내에 오픈소스 기초 모델(Llama-3, Mistral)을 자체 호스팅하는 완전 격리형 인프라 구축.
- **한계점** : AI가 생성한 소스코드가 오픈소스 라이선스(GPL 등)를 침해하거나 기존 저작권을 표절하여 법적 분쟁 유발.
  - **해결 방안** : CI/CD 파이프라인 내 코드 유사도 검증기(Code Snippet Matching)를 연동하여 표절 및 카피레프트 라이선스 감염 여부 자동 스캔.

## Ⅴ. 섀도우 AI(Shadow AI) 적용 및 발전을 위한 기술사적 제언

- **거버넌스 및 정책 중심의 거버넌스 및 실행 체계 구축** : 사내 생성형 AI 사용 가이드라인 제정 및 승인/예외 신청 패스트트랙 운영을(를) 적극 추진하여, 임직원 준법의식 고취 및 섀도우 AI 사용 동기 원천 제거 효과를 극대화해야 함.
- **플랫폼 구축 중심의 거버넌스 및 실행 체계 구축** : 전사 단일 창구 AI Gateway 및 자체 RAG 기반 사내 지식 비서 구축을(를) 적극 추진하여, 외부 유출 없는 안전한 환경에서 업무 생산성 향상 효과를 극대화해야 함.
- **지속적 모니터링 중심의 거버넌스 및 실행 체계 구축** : 프롬프트 감사 로그의 SIEM 연동 및 비정상 대량 데이터 질의 실시간 차단을(를) 적극 추진하여, 영업비밀 유출 리스크 제로화 및 법적 규제 준수 효과를 극대화해야 함.
