## 지식 로드맵 내 현재 위치

생성형 AI 보안 → 기업 AI 거버넌스 → 섀도우 AI(Shadow AI) 관리 및 양성화

## 30초 인출

- **본질:** 기업 IT 및 정보보안 부서의 공식 승인과 보안 가시성 없이 임직원이 업무 효율성을 위해 임의로 외부 퍼블릭 생성형 AI, 브라우저 확장 프로그램, 비공식 API를 사용하는 현상.
- **메커니즘:** 임직원이 사내 기밀 소스코드/고객 개인정보를 외부 퍼블릭 AI 프롬프트에 입력 → 벤더 클라우드 저장 및 모델 재학습 데이터 활용 → 기업 핵심 지적재산권 유출 및 규제 위반.
- 통찰: 무차별적 전면 차단은 개인 모바일 우회 등 음성화를 촉진하므로, ZDR(데이터 보존 제로) 엔터프라이즈 AI 게이트웨이 제공과 CASB/DLP 기반 양성화 거버넌스 필수.

<details><summary>핵심 용어</summary>

- **섀도우 AI(Shadow AI)**: 기업의 통제를 벗어나 임직원이 자의적으로 사용하는 비승인 생성형 AI 도구 및 서비스.
- **CASB(Cloud Access Security Broker)**: 사용자와 클라우드 서비스 사이에서 트래픽을 중계하며 비인가 SaaS/AI 접근을 탐지하고 데이터 유출을 차단하는 플랫폼.
- **AI 보안 게이트웨이(AI Security Gateway)**: 사내 모든 AI 호출을 단일 채널로 집약하여 인라인 DLP 마스킹, 프롬프트 인젝션 방어, 로깅을 수행하는 프록시.
- **ZDR(Zero Data Retention)**: 기업이 입력한 프롬프트와 생성된 결과물을 벤더의 서버에 영구 저장하지 않고 모델 재학습에도 사용하지 않음을 보증하는 계약 조건.
- **프롬프트 DLP(Prompt DLP)**: 프롬프트 입력 창에 주민등록번호, 신용카드, 소스코드, 비밀번호 등이 감지될 경우 실시간 마스킹하거나 전송을 차단하는 기술.
</details>

## 2~4교시 예상문제 (25점)

> 기업 내 생성형 AI 활용 급증에 따른 '섀도우 AI(Shadow AI)'의 확산 배경과 보안 위협을 데이터 유출, 컴플라이언스, 저작권 관점에서 분석하고, 무조건적 차단 정책의 한계를 극복하기 위한 엔터프라이즈 양성화 및 기술적 엔지니어링 방어 아키텍처를 제시하시오. (25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 사내 공식 보안 평가 및 승인 절차를 거치지 않고 임직원이 개인 계정이나 브라우저 확장을 통해 외부 퍼블릭 생성형 AI를 업무에 무단 활용하는 상태 |
| 목적 | 섀도우 AI로 인한 핵심 영업비밀 및 개인정보 유출을 방지하고, 승인된 안전한 엔터프라이즈 AI 인프라를 제공하여 업무 생산성과 보안성의 균형 달성 |

## Ⅱ. 섀도우 AI의 핵심 특징 및 확산 원인

| 특징 항목 | 세부 양상 | 비즈니스 및 기술적 위험 |
|---|---|---|
| 극단적 접근 용이성 | 별도 인프라 설치 없이 웹 브라우저 접속 및 개인 신용카드 결제만으로 즉시 사용 가능 | 보안팀이 인지하지 못하는 사이 전사 수백 개 부서로 동시다발적 침투 |
| 데이터 외부 학습 위험 | 무료/일반 계정 사용 시 입력한 프롬프트가 차세대 파운데이션 모델의 학습 데이터셋으로 흡수 | 경쟁사 프롬프트 질의 시 사내 핵심 알고리즘 및 사업 기밀 누출 |
| 비가시적 전송(SaaS) | 정상 HTTPS(443) 암호화 트래픽으로 전송되어 레거시 네트워크 방화벽에서 식별 불가 | 내부망 데이터 유출(Exfiltration) 통제 사각지대 형성 |
| 브라우저 플러그인 남용 | 화면 요약, 맞춤법 검사 등 비인가 브라우저 확장 프로그램이 화면 전체 DOM을 탈취 | 백그라운드에서 실시간 사내 인트라넷 데이터 해외 C2 유출 |
| 규제 컴플라이언스 위반 | EU GDPR, 개인정보보호법상 국외 이전 승인 및 제3자 제공 동의 없는 데이터 처리 | 기업 대상 천문학적 과징금 및 집단 손해배상 소송 직면 |

## Ⅲ. 섀도우 AI 위협 매핑 및 엔터프라이즈 양성화 아키텍처

```text
[ 1. 기존 비인가 섀도우 AI 경로 (Shadow AI Path) ]
사내 단말 (임직원) ──▶ [ 비인가 퍼블릭 AI 웹/플러그인 ] ──▶ [ 모델 재학습 및 기밀 유출 발생! ]
                     (개인정보, 소스코드 무단 복사)

[ 2. 엔터프라이즈 AI 양성화 보안 아키텍처 (Enterprise AI Gateway) ]
사내 단말 (임직원)
       │
       ▼
[ CASB / SSE 게이트웨이 ]
 ├── [비인가 AI 도구 감시]: 비승인 무료 AI 사이트 접속 전면 차단 (URL 필터링)
 └── [승인 AI 리다이렉트]: 사내 공용 엔터프라이즈 AI 포털로 사용자 자동 유도
       │
       ▼
[ 엔터프라이즈 AI 보안 게이트웨이 (Private AI Gateway) ]
 ├── 1. 신원 인증: 사내 SSO / SAML 기반 사용자 직무별 접근 권한 인가
 ├── 2. 인라인 DLP: 프롬프트 내 주민번호, API 키, 핵심 키워드 실시간 마스킹 (Presidio)
 ├── 3. 프롬프트 인젝션 방어: 탈옥 및 유해 프롬프트 사전 차단
 └── 4. 로깅 및 감사: 입력 프롬프트 및 응답 결과 암호화 감사 저장 (SIEM 연동)
       │
       ▼
[ 전용 기업용 LLM 엔드포인트 (ZDR 계약 적용 클라우드 또는 온프레미스 Llama) ]
```

| 거버넌스 단계 | 엔지니어링 구현 솔루션 | 핵심 통제 목표 |
|---|---|---|
| 1. 가시성 확보 | CASB, EDR, 웹 게이트웨이(SWG) 섀도우 AI Discovery 분석 | 사내 사용 중인 비인가 AI 서비스 100% 식별 |
| 2. 접속 통제 | DNS 싱크홀, 웹 필터링, 엔드포인트 브라우저 확장 설치 제한 | 보안 미검증 퍼블릭 AI 도구 무단 접속 차단 |
| 3. 프롬프트 보호 | 인라인 AI-DLP 프록시 구축, 데이터 토큰화(Tokenization) | 기밀 소스코드 및 개인식별정보 전송 원천 차단 |
| 4. 계약 및 보증 | 엔터프라이즈 전용 라이선스 도입 (ZDR, BAA 계약 체결) | 입력 데이터의 벤더 측 모델 학습 배제 보장 |
| 5. 모니터링/감사 | 중앙 집중 프롬프트/응답 로깅 파이프라인 및 이상 질의 탐지 | 침해사고 발생 시 부인방지 및 책임 추적성 확보 |

## Ⅳ. 전통적 섀도우 IT vs 섀도우 AI(Shadow AI) 비교

| 비교 항목 | 전통적 섀도우 IT (Shadow IT) | 섀도우 AI (Shadow AI) |
|---|---|---|
| 사용 대상 | 웹하드(Dropbox), 개인 메일, 협업 메신저(Slack) | 생성형 AI 챗봇(ChatGPT), 코드 완성 툴, 이미지 생성 AI |
| 주된 위험 | 단순 파일 저장 및 공유를 통한 데이터 유출 | 입력 데이터의 모델 학습 풀 흡수 및 비결정론적 정보 재생성 |
| 인터랙션 방식 | 파일 업로드/다운로드 중심 | 프롬프트 기반 실시간 대화, 파일 분석, 코드 실행 위임 |
| 데이터 침해 범위 | 유출된 파일 자체에 국한 | 향후 전 세계 불특정 다수 사용자에게 답변 형태로 기밀 재유출 |
| 대응 패러다임 | URL 차단 및 포트 제어로 비교적 통제 용이 | 단순 차단 시 생산성 저하 반발 극심, '양성화'가 유일한 해법 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 사내 PC에서 퍼블릭 AI 웹을 차단할 경우 스마트폰(BYOD)이나 개인 테더링을 이용해 프롬프트를 수동 입력하는 우회 행위 발생 | 차단 일변도 정책을 지양하고, 사내망 및 모바일 업무 앱 내에 안전한 전용 프라이빗 AI 챗봇 인터페이스를 공식 구축하여 양성화 |
| 개발자가 복잡하게 난독화하거나 변형한 소스코드의 경우 정규식(Regex) 기반 DLP 엔진으로 탐지 불가 | AST(추상구문트리) 및 코드 구조를 분석하는 AI 기반 시맨틱 DLP 엔진을 게이트웨이에 연동하여 소스코드 패턴 정밀 탐지 |
| 외부 AI 벤더가 계약상 ZDR(Zero Data Retention)을 약속했음에도 내부 로깅 정책 오류로 데이터가 잔존하는 서드파티 신뢰 결함 | 사내 온프레미스 GPU 클러스터 또는 프라이빗 VPC 내에 오픈소스 기초 모델(Llama-3, Mistral)을 자체 호스팅하는 완전 격리형 인프라 구축 |
| AI가 생성한 소스코드가 오픈소스 라이선스(GPL 등)를 침해하거나 기존 저작권을 표절하여 법적 분쟁 유발 | CI/CD 파이프라인 내 코드 유사도 검증기(Code Snippet Matching)를 연동하여 표절 및 카피레프트 라이선스 감염 여부 자동 스캔 |

## Ⅵ. 제언

```text
[ 섀도우 AI 극복 및 생산성 혁신 3대 프레임워크 ]

+-------------------------+      +-------------------------+      +-------------------------+
|     1. 가시화(Discover) | ---> |     2. 양성화(Enable)   | ---> |     3. 가드레일(Govern) |
| (CASB 기반 비인가 식별) |      | (엔터프라이즈 AI 제공)  |      | (인라인 DLP / ZDR 강제) |
+-------------------------+      +-------------------------+      +-------------------------+
```

| 관리 영역 | 세부 엔지니어링 구현 과제 | 비즈니스 가치 |
|---|---|---|
| 거버넌스 및 정책 | 사내 생성형 AI 사용 가이드라인 제정 및 승인/예외 신청 패스트트랙 운영 | 임직원 준법의식 고취 및 섀도우 AI 사용 동기 원천 제거 |
| 플랫폼 구축 | 전사 단일 창구 AI Gateway 및 자체 RAG 기반 사내 지식 비서 구축 | 외부 유출 없는 안전한 환경에서 업무 생산성 30% 이상 향상 |
| 지속적 모니터링 | 프롬프트 감사 로그의 SIEM 연동 및 비정상 대량 데이터 질의 실시간 차단 | 영업비밀 유출 리스크 제로화 및 법적 규제 100% 준수 |
