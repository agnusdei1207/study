<details><summary>핵심 용어</summary>

- **OWASP Top 10 for LLM Applications**: LLM·생성형 AI 애플리케이션의 주요 보안위험과 완화 방향을 분류한 OWASP 자료.
- **OWASP(Open Worldwide Application Security Project)**: 소프트웨어·애플리케이션 보안 지식과 공개 프로젝트를 제공하는 비영리 재단.
- **LLM(Large Language Model, 대규모 언어 모델)**: 대량의 언어 자료로 학습해 문맥에 따른 텍스트를 처리·생성하는 모델.
- **Prompt Injection**: 신뢰할 수 없는 지시가 모델의 의도된 동작을 바꾸도록 유도하는 취약점.
- **RAG(Retrieval-Augmented Generation)**: 외부 자료를 검색해 모델 문맥에 제공하고 응답을 생성하는 구조.
- **Excessive Agency**: 모델 기반 애플리케이션에 과도한 기능·권한·자율성을 부여해 예상 밖 작업이 가능해지는 위험.
- **Improper Output Handling**: 모델 출력을 충분히 검증·정제하지 않고 후속 기능에서 사용하는 취약점.

### Ⅱ. 위험이 실행으로 이어지는 경계

```text
사용자 입력·검색 문서
          ↓ 비신뢰 자료
       LLM 처리
          ├── 응답 → 출력 검증 → 사용자·후속 시스템
          └── 도구 요청 → 별도 권한·정책검사 → 제한된 실행
```

핵심 위험은 지시 조작, 정보 노출, 권한 오용, 출력의 안전하지 않은 사용, 자원 남용 등.

제언: 모델 응답과 검색 자료를 비신뢰 입력으로 다루고 권한·실행 통제를 모델 외부에 둘 것.

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **OWASP Top 10 for LLM Applications**는 LLM 애플리케이션의 주요 위험과 완화 방향을 분류한 보안 안내 목록. |
| 목적 | 생성형 AI 애플리케이션의 설계·시험·운영에서 반복되는 위험을 체계적으로 검토. |

## Ⅱ. 2025년 주요 위험 분류

| 항목 | 위험 핵심 |
|---|---|
| LLM01 Prompt Injection | 직접·간접 지시가 모델 행동을 바꾸는 위험 |
| LLM02 Sensitive Information Disclosure | 모델·애플리케이션을 통한 민감정보 노출 |
| LLM03 Supply Chain | 모델·데이터·구성요소의 공급망 취약성 |
| LLM04 Data and Model Poisoning | 학습·미세조정·임베딩 자료 또는 모델 오염 |
| LLM05 Improper Output Handling | 출력 검증 부족으로 후속 처리에서 취약점 발생 |
| LLM06 Excessive Agency | 과도한 도구·권한·자율성에 따른 의도 밖 행위 |
| LLM07 System Prompt Leakage | 시스템 프롬프트 내용 노출 |
| LLM08 Vector and Embedding Weaknesses | 벡터·임베딩·검색 경계의 취약성 악용 |
| LLM09 Misinformation | 부정확한 생성 결과가 판단·처리에 영향 |
| LLM10 Unbounded Consumption | 자원 사용 제어 부족에 따른 비용·가용성 영향 |

OWASP 목록은 위험 검토의 출발점이며 전체 보안 기준이나 모든 조직에 동일한 위험 우선순위를 뜻하지 않음.

## Ⅲ. RAG·도구 연계의 신뢰 경계

```text
사용자 지시 ─┐
              ├→ 모델 문맥 구성 → 응답 또는 도구 요청
검색 문서 ───┘                         │
    비신뢰 자료                       ↓
                              코드 기반 검증·권한검사
                               ├─ 거부·기록
                               └─ 제한된 실행
```

검색 자료는 모델 지시와 분리된 신뢰 경계가 아니며, RAG나 미세조정만으로 프롬프트 인젝션을 완전히 방지할 수 없음. 모델 출력을 명령으로 직접 실행하지 않고 외부 정책으로 권한을 검증.

## Ⅳ. 설계·운영 통제

| 영역 | 통제 방향 |
|---|---|
| 데이터·검색 | 출처·사용권한 확인, 사용자별 검색 권한 적용, 민감정보 노출 점검 |
| 입력·프롬프트 | 비신뢰 입력 경계 표시, 직접·간접 인젝션 시나리오 시험 |
| 출력 | 형식·스키마 검증, 명령·쿼리의 안전한 후속 처리 |
| 도구·권한 | 최소 권한, 허용된 기능만 노출, 중요 작업은 별도 승인 |
| 공급망 | 모델·데이터·라이브러리의 출처·버전·변경 이력 확인 |
| 자원·운영 | 요청·토큰·호출 제한, 로그·탐지·중단·복구 절차 마련 |

## Ⅴ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 모델 필터만으로는 간접 지시와 후속 도구 실행을 모두 통제하기 어려움. | 검색·모델·실행 계층의 권한을 분리하고 고영향 도구 동작은 사전 승인과 사후 추적으로 제한하는 방안. |
