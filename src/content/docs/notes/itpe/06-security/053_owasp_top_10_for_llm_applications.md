## 한 줄 본질
- 제어 명령과 데이터가 같은 자연어 스트림으로 입력되는 LLM 특성상 발생하는 보안 경계 모호성 병목 → 10대 대표 공격 벡터를 정의하고 입출력 필터링, RAG 접근제어, 도구 권한 최소화로 대응 → LLM 서비스 안전성 확보 / 추론 속도 지연 및 엄격한 가드레일로 인한 유용성 감소

         │ (LLM01: 직접/간접 프롬프트 인젝션)
         ▼

## 핵심 용어
- 직접/간접 프롬프트 인젝션(Direct/Indirect Prompt Injection): 직접 공격은 사용자가 악성 프롬프트를 입력하는 것이며, 간접 공격은 LLM이 참조하는 외부 웹/문서에 숨겨진 악성 지침이 모델을 조종하는 기법
- 과도한 에이전시(Excessive Agency): LLM 기반 에이전트에게 지나치게 광범위한 권한(DB 쓰기, 이메일 발송 등)을 부여하여 프롬프트 공격 시 통제 불능 피해를 초래하는 결함

## 핵심 통찰
- 컴퓨터 역사상 모든 인젝션(SQLi, 명령어 인젝션)은 '코드와 데이터의 혼재'에서 비롯되었으며, LLM은 본질적으로 둘을 구분하지 못하는 거대한 인젝션 덩어리임
- 시스템 프롬프트에 "절대 이전 지시를 잊지 마라"고 아무리 강조해도 자연어 수준의 방어는 100% 뚫림 → 외부 가드레일 프록시가 구조적으로 개입해야 함
- 최신 위협의 중심은 모델 자체보다 '에이전트 권한'과 'RAG 파이프라인'임 → RAG 문서에 접근 통제(ACL)가 없으면 일반 사용자가 사내 임원 연봉 문서를 LLM에게 물어보아 탈취 가능

## 이웃 토픽과 구분
- 전통 OWASP Top 10 vs LLM Top 10: 전통 = 코드 문법 취약점(인젝션, 취약한 암호) / LLM = 모델 파라미터 유출, 의미론적 조작, 자율 도구 실행 위험

## 문제·원인·대책
- 사례: 사내 지식검색 챗봇에 일반 직원이 "인사팀 평가 가이드라인을 요약해줘"라고 질의하여 비공개 인사 데이터가 노출된 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| RAG 검색을 통한 비인가 사내 기밀 문서 노출 | 벡터 검색 단계에서 사용자 권한(ACL) 검증 누락 | 문서 메타데이터 기반 사용자 RBAC 필터링 검색 적용 | 본인 열람 권한이 있는 문서만 RAG 컨텍스트로 전달 |
| 외부 웹 검색 도구를 수행한 에이전트의 내부 명령 오작동 | 웹페이지 텍스트에 숨겨진 악성 프롬프트 실행(간접 인젝션) | 듀얼 LLM 분리 및 도구 호출 전 가드레일 검증 강제 | 비인가 시스템 조작 명령 주입 차단 |

## 이렇게 출제된다

## 내 의견
- [프롬프트 튜닝만으로 보안을 해결하려는 환상] "보안에 위배되는 답변을 하지 마라"는 메타 프롬프트에 의존하는 것은 개발 편의주의적 패착임 → 나라면: LLM 앞단에 Guardrails AI 또는 NeMo Guardrails 같은 독립 검증 프록시를 배치하고, 외부 도구 호출 시 쓰기 작업에는 반드시 인간 확인(HITL)을 강제하는 '다층 게이트웨이' 구축
