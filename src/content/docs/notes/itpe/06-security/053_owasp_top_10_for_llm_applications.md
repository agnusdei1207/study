## 연관 키워드

- OWASP Top 10 for LLM, 프롬프트 주입, 민감정보 노출, 공급망 취약점
- 데이터·모델 오염, 출력 무검증 처리, 과도한 에이전시, 시스템 프롬프트 노출
- 벡터·임베딩 취약점, 무제한 자원 소비, RAG, 최소 권한 원칙, HITL, WAF

## Ⅰ. OWASP Top 10 for LLM Applications의 개요

- 핵심 요약 : 생성형 AI 애플리케이션에서 빈번하고 영향이 큰 10대 위험을 정리한 글로벌 점검 기준.
- 개념 : **OWASP**(Open Worldwide Application Security Project, 오픈소스 웹 애플리케이션 보안 프로젝트)가 **대규모 언어 모델**(LLM, Large Language Model) 애플리케이션의 설계·배포·운영에서 자주 나타나는 10가지 취약점을 체계화한 가이드라인.
- 배경 및 필요성 : 기존 OWASP Top 10이 다루는 SQL 인젝션과 XSS만으로는 자연어를 입력받아 결과가 비결정적으로 바뀌는 LLM 애플리케이션의 위험을 설명하기 어려워, 2023년 첫 발표 이후 2025년판으로 개정됨.
- 주요 목적 : LLM 구조에 고유한 약점을 드러내고, 개발자와 보안 아키텍트가 적용할 완화 조치를 제시하며, AI 서비스 보안 점검의 기준선을 세우는 것.

## Ⅱ. OWASP Top 10 for LLM의 특징 및 장점

- 핵심 요약 : 취약점을 처리 단계별로 나눠 보게 함으로써, 입력·모델·출력·도구 각 지점에 맞는 통제를 설계할 수 있게 하는 체계.

1. 계층별 분류 : 취약점을 입력, 모델·파이프라인, 출력·도구 계층으로 나눔 → 통제 지점을 특정해 대응 책임을 분담.
2. 자연어 위협의 명명 : 프롬프트 주입과 시스템 프롬프트 노출처럼 웹에 없던 위협에 이름을 부여 → 점검 항목을 표준화.
3. 자율 에이전트 대응 : **과도한 에이전시**(Excessive Agency)를 별도 항목으로 다룸 → 도구 호출 권한 설계를 보안 요구사항으로 명시.

```text
[ 취약점 위치별 분류 ]

입력 계층
  LLM01 프롬프트 주입
모델·파이프라인 계층
  LLM03 공급망 · LLM04 데이터 오염
  LLM10 무제한 자원 소비
출력·도구 계층
  LLM02 민감정보 노출 · LLM05 출력 무검증
  LLM06 과도한 권한 · LLM07 시스템 프롬프트 노출
  LLM08 벡터·임베딩 취약점
```

- **프롬프트 주입**(Prompt Injection) : 직접 또는 외부 문서를 통한 간접 지시로 모델의 안전 지침을 우회하는 최우선 위협.

## Ⅲ. OWASP Top 10 for LLM의 구조 (흐름)

- 핵심 요약 : 요청이 입력에서 모델을 거쳐 도구 실행까지 이어지는 흐름마다 검사 지점을 두는 구조.

```text
[ 요청 처리 흐름과 통제 지점 ]

사용자 입력
      ↓ 입력 검사 (프롬프트 주입 필터)
LLM·RAG 파이프라인
      ↓ 검색 문서 신뢰도 필터
모델 출력
      ↓ 출력 인코딩·정책 검사
도구 호출 (최소 권한 적용)
```

| 순위 | 취약점 명칭 (2025년판) | 위협 내용 | 엔지니어링 대응책 |
| --- | --- | --- | --- |
| LLM01 | 프롬프트 주입 | 자연어 명령으로 모델의 동작 통제 탈취 | 입력 격리, 의미 기반 가드레일 |
| LLM02 | 민감정보 노출 | 학습 데이터나 맥락 속 개인정보·기밀의 응답 노출 | 데이터 가명화, 출력의 개인정보 마스킹 |
| LLM03 | 공급망 취약점 | 검증되지 않은 모델 가중치와 오픈소스 종속성 | 모델 무결성 검증, AI 구성 명세(ML-BOM) 관리 |
| LLM04 | 데이터·모델 오염 | 학습 데이터나 RAG 데이터 오염으로 백도어 주입 | 데이터 출처 검증, 이상 임베딩 탐지 |
| LLM05 | 출력 무검증 처리 | 모델 출력을 신뢰해 백엔드나 브라우저에서 실행 | 출력 인코딩, 파라미터화된 질의 강제 |
| LLM06 | 과도한 에이전시 | 에이전트의 과도한 자율성과 고권한 남용 | 최소 권한 원칙, HITL(Human in the Loop) 승인 |

- 핵심 관점 : 이 목록은 웹 보안의 입력값 검증 중심 접근과 달리, 확률적으로 생성되는 출력과 자율 에이전트의 권한 위임을 중심에 둠.

## Ⅳ. OWASP Top 10 for LLM의 비교

- 핵심 요약 : 전통적 웹 방화벽과 LLM 전용 검사는 막는 대상이 달라, 웹 방어 장비만으로는 프롬프트 주입을 잡을 수 없다는 차이가 핵심.

| 비교 축 | 전통적 웹 방어 (WAF) | LLM 전용 검사 |
| --- | --- | --- |
| 검사 대상 | SQL 특수문자, 스크립트 태그 | 자연어 의도와 맥락 |
| 탐지 방식 | 시그니처 규칙 매칭 | 의미 유사도와 분류 모델 |
| 대표 위협 | SQL 인젝션, XSS | 프롬프트 주입, 시스템 프롬프트 노출 |
| 오탐 관리 | 규칙 튜닝 | 임계치 조정과 사람 검토 병행 |

- 선택 기준 : 정형 입력을 받는 API에는 웹 방어가 여전히 유효하므로, 자연어 입력과 생성 출력이 있는 경로에만 LLM 전용 검사를 덧붙이는 것이 현실적임.

## Ⅴ. OWASP Top 10 for LLM의 한계와 방안

- 핵심 요약 : 웹 방화벽의 사각지대, 출력의 2차 실행 위험, 벡터 데이터 오염을 의미 기반 검사, 출력 격리, 출처 검증으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 웹 방화벽의 자연어 공격 미탐 | 문장형 프롬프트 주입은 규칙으로 식별되지 않음 | 입력·출력 경로에 의미 기반 검사 계층(AI 방화벽)을 두고 분류 모델로 검사 | 주입 시도 탐지율, 오탐률 |
| 출력의 2차 실행 | 생성된 스크립트나 마크다운을 검증 없이 렌더링하면 클라이언트 장악으로 이어짐 | LLM 출력을 비신뢰 입력으로 취급해 이스케이프 처리(DOMPurify)와 CSP 적용 | 무검증 렌더링 지점 수 |
| 벡터 임베딩 조작 | 적대적 문서가 RAG 검색 결과에 섞여 잘못된 답 유도 | 문서 출처의 서명 검증과 검색 결과 신뢰도 임계치 필터링 | 검색 문서 출처 검증률 |

## Ⅵ. OWASP Top 10 for LLM에 대한 기술사적 제언

- 핵심 요약 : 출시 전 점검과 자동화된 공격 시험, 도구 권한 설계를 AI 서비스 개발 절차의 기본 단계로 편입하는 것이 핵심.

1. 신규 생성형 AI 서비스는 출시 전에 이 목록의 10개 항목을 기준으로 점검하고, 보안 검토 회의를 통과해야 배포되도록 절차를 정하는 것이 바람직하다.
2. 배포 전에는 Garak이나 PyRIT 같은 자동화된 레드팀 도구로 프롬프트 주입과 민감정보 노출 시도를 반복 실행해, 취약점이 실제로 악용되는지 계측해야 한다.
3. 에이전트가 호출하는 도구는 시한부 인가 토큰과 허용 파라미터 목록으로 제한해, 프롬프트 조작이 성공하더라도 피해 범위가 제한되도록 설계해야 한다.

## Ⅶ. 결론

- 핵심 요약 : OWASP Top 10 for LLM은 생성형 AI 애플리케이션을 위한 위험 목록이자 점검 기준선임.
- 시사점 : 모델 자체의 성능보다 입력·출력·도구 권한의 경계를 어떻게 설계하느냐가 AI 서비스의 보안 수준을 결정하므로, 이 경계를 설계 단계에서 명시하는 조직이 신뢰를 얻음.
