## 연관 키워드

- 타원곡선암호, ECC, 타원곡선 이산대수 문제, ECDLP, 스칼라 곱셈
- ECDSA, Ed25519, EdDSA, RSA, 짧은 키 길이, 전자서명
- 단순 전력 분석, SPA, 몽고메리 사다리, 상수 시간 구현, RFC 6979
- 쇼어 알고리즘, 하이브리드 키 교환, 암호 민첩성, ML-KEM

## Ⅰ. 타원곡선암호의 개요

- 핵심 요약 : 타원곡선 위 점의 스칼라 곱셈이 역연산이 어려운 성질을 이용해, 짧은 키로 높은 보안 강도를 내는 공개키 암호.
- 개념 : 유한체 $GF(p)$ 위에 정의된 타원곡선의 군(Group) 구조에서 점의 덧셈과 **스칼라 곱셈** 으로 만들어지는 **타원곡선 이산대수 문제** (ECDLP, Elliptic Curve Discrete Logarithm Problem)에 기반한 **공개키 암호** (Public-Key Cryptography) 알고리즘.
- 배경 및 필요성 : RSA(Rivest-Shamir-Adleman) 등 전통 공개키 암호는 키 길이가 커질수록 연산과 대역폭 부담이 늘어나므로, IoT, 모바일, 블록체인처럼 자원이 제약된 환경에 맞는 암호화와 전자서명 체계가 요구됨.
- 주요 목적 : RSA보다 **짧은 키 길이** (256비트 대 3072비트)로 같은 수준의 보안 강도를 제공하여, 자원 제약 환경에서도 기밀성과 전자서명을 효율적으로 제공.

## Ⅱ. 타원곡선암호의 특징 및 장점

- 핵심 요약 : 짧은 키 길이가 연산과 전송 부담의 감소로 이어져, 자원 제약 기기에 적합한 암호와 서명 체계를 제공하는 방식.

1. 짧은 키 길이 : 같은 보안 강도를 더 작은 키로 달성 → 인증서와 패킷 크기 감소로 대역폭과 저장 공간 절약.
2. 효율적인 키 생성 : 스칼라 곱셈 기반 공개키 계산이 가벼워 → 저사양 IoT 기기와 스마트카드에서 부담 감소.
3. **ECDSA** (Elliptic Curve Digital Signature Algorithm) 전자서명 : 타원곡선 기반 서명으로 무결성과 인증을 제공 → 짧은 서명값으로 인증 절차 경량화.
4. 표준 곡선 활용 : 검증된 표준 도메인 파라미터를 사용하여 → 구현 간 호환성과 상호운용성 확보.

## Ⅲ. 타원곡선암호의 구조 (흐름)

- 핵심 요약 : 도메인 파라미터 정의에서 개인키 난수 선택, 스칼라 곱셈에 의한 공개키 도출, 공개키 검증으로 이어지는 순차 흐름.

1. 도메인 파라미터 정의 : 소수 p, 계수 a와 b, 기준점 G, 위수 n, 보조인수 h를 합의 → 표준 곡선(secp256r1, Ed25519 등) 채택.
2. 개인키 생성 : **암호학적 난수 생성기** (CSPRNG, Cryptographically Secure Pseudorandom Number Generator)로 1부터 n-1 사이의 정수 d 선택 → 하드웨어 **진성 난수 생성기** (TRNG, True Random Number Generator) 사용 권장.
3. 공개키 계산 : 스칼라 곱셈 Q = d · G로 좌표 Q 도출 → **몽고메리 사다리** (Montgomery Ladder) 연산 적용.
4. 공개키 검증 : Q가 무한원점이 아니고 곡선 방정식을 만족하며 nQ = O인지 확인 → 유효하지 않은 곡선 공격 방어.

```text
[ 공개키 생성 흐름 ]

도메인 파라미터 (p, a, b, G, n)
      ↓
개인키 d (CSPRNG로 1~n-1 선택)
      ↓
공개키 Q = d·G (스칼라 곱셈)
      ↓
공개키 검증 (무한원점, nQ = O)
```

```text
[ 스칼라 곱셈의 원리 ]

점 P, Q 덧셈 (직선과 곡선의 제3 교점 대칭)
      ↓
같은 점 2배 (접선 이용, Point Doubling)
      ↓
반복 덧셈으로 Q = d·G 계산 (Double-and-Add)
      ↓
Q와 G로부터 d 역산은 ECDLP로 곤란
```

## Ⅳ. 타원곡선암호와 RSA의 비교

- 핵심 요약 : 같은 보안 강도에서 ECC는 훨씬 짧은 키를 쓰며, 그 차이가 자원 제약 환경의 적합성을 좌우.

| 비교 항목 | 타원곡선암호 (ECC) | RSA 암호 |
| --- | --- | --- |
| 수학적 기반 난제 | 타원곡선 이산대수 문제 (ECDLP) | 큰 합성수의 소인수분해 문제 (IFP, Integer Factorization Problem) |
| 128비트 보안 강도 키 크기 | 256비트 | 3072비트 |
| 192비트 보안 강도 키 크기 | 384비트 | 7680비트 |
| 256비트 보안 강도 키 크기 | 512비트 | 15360비트 |
| 연산 특성 | 키 생성과 서명 연산이 상대적으로 가벼움 | 서명 검증은 빠르나 키 생성 비용이 큼 |
| 자원 적합성 | IoT, 스마트카드 등 자원 제약 환경에 적합 | 큰 키로 통신 부담과 저장 공간 증가 |
| 주요 적용 분야 | TLS 1.3 키 교환, 블록체인 서명, IoT 보안 칩 | 레거시 PKI(Public Key Infrastructure), 웹 서버 인증서 |

- 선택 기준 : 자원 제약 환경과 신규 시스템에는 ECC를, 기존 인증 체계와의 호환이 우선인 환경에는 RSA를 검토.

## Ⅴ. 타원곡선암호의 한계와 방안

- 핵심 요약 : 서명 난수 편향, 부채널 노출, 양자컴퓨터 위협을 결정론적 서명, 상수 시간 구현, 하이브리드 전환으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| ECDSA 서명 난수 중복·편향 | 임시 난수 k가 중복되거나 편향되면 두 서명값으로 개인키 d가 역추출됨 | **RFC 6979** (결정론적 ECDSA) 또는 Ed25519(EdDSA, Edwards-curve Digital Signature Algorithm) 채택 | 난수 생성기 점검 결과 |
| **단순 전력 분석** (SPA, Simple Power Analysis) | 비밀키 비트에 따른 연산 시간과 전력 소모 차이가 노출됨 | 비트 값과 무관하게 연산 패턴을 같게 하는 몽고메리 사다리와 상수 시간 구현 채택 | 부채널 측정 점검 결과 |
| 양자컴퓨터에 의한 ECDLP 붕괴 | 쇼어 알고리즘으로 대규모 양자컴퓨터에서 ECDLP가 다항 시간에 풀릴 위험 | 격자 기반 양자내성암호(ML-KEM 등)와의 하이브리드 키 교환(X25519 + ML-KEM), **암호 민첩성** (Crypto-Agility) 확보 | 암호 전환 완료율 |

## Ⅵ. 타원곡선암호에 대한 기술사적 제언

- 핵심 요약 : 암호 민첩성을 설계 원칙으로 삼고, 개발 표준에 부채널 검증을 포함하며, 양자 전환을 로드맵으로 관리하는 방향.

1. 정보보안 조직은 ECC를 포함한 공개키 암호 목록을 자산별로 관리하고, 알고리즘을 교체할 수 있도록 암호 민첩성을 설계 원칙으로 정하는 체계를 마련할 필요가 있음.
2. 장기간 보관해야 하는 데이터를 다루는 기관은 양자 위협이 현실화되기 전에 하이브리드 키 교환을 우선 적용하는 전환 로드맵을 수립하는 것이 바람직함.
3. 개발 조직은 상수 시간 암호 라이브러리의 사용과 부채널 검증 절차를 개발 표준에 포함하여, 구현 취약점을 출시 전 단계에서 걸러내는 거버넌스를 갖출 필요가 있음.

## Ⅶ. 결론

- 핵심 요약 : ECC는 짧은 키로 높은 보안 강도를 제공하는 공개키 암호이며, 효율성의 이점이 구현 품질과 양자 전환 관리에 달린 기술.
- 시사점 : 짧은 키가 주는 효율은 구현의 안전성이 뒷받침될 때만 유효하므로, 암호 민첩성을 전제로 한 운용이 장기 신뢰의 조건이 됨.
