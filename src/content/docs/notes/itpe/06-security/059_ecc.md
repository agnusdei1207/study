## 30초 인출

- **본질**: 타원곡선암호는 유한체 위 타원곡선의 점 연산과 이산로그 계산 난도를 이용하는 공개키 암호 방식.
- **메커니즘**: 개인 스칼라 `k`와 기준점 `G`로 `Q = kG`를 계산하며, 적절한 매개변수에서는 `Q`에서 `k`를 찾기 어렵다는 가정에 기반.
- **용도**: ECDH는 키 합의, ECDSA는 전자서명에 사용하며 데이터는 별도 대칭키로 암호화.

<details><summary>핵심 용어</summary>

- **타원곡선암호(ECC)**: Elliptic Curve Cryptography의 약칭으로, 타원곡선 군 연산의 계산 난도를 이용하는 공개키 암호 방식.
- **유한체(Finite Field)**: 타원곡선 좌표와 연산을 정해진 유한 집합 안에서 수행하게 하는 대수 구조.
- **ECDLP(Elliptic Curve Discrete Logarithm Problem)**: `G`와 `Q = kG`에서 비밀 스칼라 `k`를 찾는 문제.
- **ECDH(Elliptic Curve Diffie-Hellman)**: 각 당사자의 개인키·상대 공개키로 같은 공유 비밀을 계산하는 키 합의 방식.
- **ECDSA(Elliptic Curve Digital Signature Algorithm)**: 타원곡선 기반 디지털 서명 알고리즘.
- **RSA(Rivest-Shamir-Adleman)**: 정수 인수분해의 계산 난도를 바탕으로 한 공개키 암호 알고리즘 계열.
- **NIST(National Institute of Standards and Technology)**: 암호 알고리즘·키관리 권고를 발간하는 미국 연방 기술표준 기관.

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **타원곡선암호(ECC)**는 유한체 위 타원곡선의 점 연산과 이산로그 계산 난도를 이용하는 공개키 암호 방식. |

## Ⅱ. 수학적 기반과 키 생성

```text
곡선·유한체·기준점 G 공개
          ↓
개인 스칼라 k 생성
          ↓ 점의 스칼라 곱
공개점 Q = kG 계산
          ↓
공개키 Q 배포 · 개인키 k 보호
```

곡선은 흔히 `y² = x³ + ax + b` 형태로 표현되지만 실제 연산은 규격이 정한 유한체·도메인 매개변수 안에서 수행. 공개점 유효성 검증과 비밀 스칼라 보호 필요.

## Ⅲ. 키 합의와 전자서명 기능

| 기능 | 알고리즘 | 결과·검증 |
|---|---|---|
| 키 합의 | ECDH | 양측이 같은 공유 비밀을 계산하고 키 유도에 사용 |
| 전자서명 | ECDSA | 개인키 서명과 공개키 검증으로 출처·무결성 확인 |
| 데이터 암호화 | 대칭키 암호 | 공유 비밀에서 유도한 세션 키로 실제 데이터 보호 |

ECDSA 서명에 쓰는 임시 비밀 난수의 재사용·편향은 개인키 노출로 이어질 수 있어 안전한 난수와 표준화된 구현 필요.

## Ⅳ. RSA와 보안 강도 비교

| 비교축 | 타원곡선암호(ECC) | RSA |
|---|---|---|
| 기반 문제 | 타원곡선 이산로그 | 정수 인수분해 관련 계산 문제 |
| 128비트 수준의 대표 크기 | 곡선군 차수 약 256비트 | 모듈러스 약 3072비트 |
| 대표 용도 | ECDH 키 합의, ECDSA 서명 | RSA 서명·키 수송 등 규격에 정의된 용도 |
| 선택 시 고려 | 곡선·점 검증·부채널·구현 | 패딩·키 길이·구현 및 프로토콜 |

NIST의 보안 강도 표는 대표 키 크기의 근사 비교이며 알고리즘 간 기능·성능이 완전히 같다는 뜻은 아님. 큰 규모의 양자컴퓨터가 현실화되면 ECC와 RSA 모두 현재 공개키 보안 가정이 위협받는 대상.

## Ⅴ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 비밀키 연산의 부채널·잘못된 점 입력·구현 차이가 수학적 강도와 별개로 위험을 만듦. | 승인된 곡선·검증된 암호 라이브러리와 공개키 유효성 검증을 적용하고, 키 보호·부채널 시험·양자내성 전환계획을 함께 관리하는 방안. |
