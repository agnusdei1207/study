## 지식 로드맵 내 현재 위치

- 정보보안 → 애플리케이션 및 소프트웨어 보안 → 리버스 엔지니어링 대응 → 코드 난독화(Code Obfuscation)

```text
[원본 소스/바이너리] ──(난독화 컴파일러: OLLVM, ProGuard)──> [난독화 바이너리]
                                                                     │
                                  ├── 레이아웃: 심볼/디버그 정보 박탈
                                  ├── 제어 흐름: 평탄화(Flattening), 불투명 술어
                                  └── 가상화: 독자적 가상 바이트코드 엔진 임베딩
                                                                     │
                                                                     ▼
                                             [디컴파일 및 정적 분석 원천 지연]
```

## 30초 인출

- **본질:** 프로그램의 원래 기능과 입출력 동작은 완벽히 보존하면서, 역공학자나 디컴파일러가 내부 논리 알고리즘을 분석하지 못하도록 구조를 고의로 복잡화하는 변환 기술.
- **메커니즘:** 심볼 제거(Strip) → 문자열/상수 동적 복호화 → 불투명 술어(Opaque Predicate) 삽입 → 제어 흐름 평탄화(Control Flow Flattening) 및 스위치 문 루프 변환.
- **통찰:** 난독화는 역공학을 영구히 막는 절대적 방패가 아닌 시간 지연 전술이므로, 기호 실행(Symbolic Execution) 분석에 대응하기 위해 화이트박스 암호화 및 런타임 무결성 검증(RASP) 결합 필수.

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 소프트웨어의 의미적 기능(Semantic Equivalence)을 변경하지 않고, 소스코드나 컴파일된 바이너리를 사람이 읽기 어렵고 디컴파일 도구가 해석하기 어렵게 변환하는 기술 |
| 목적 | 핵심 알고리즘 및 지식재산권(IP) 보호, 라이선스 우회 방지, 모바일 앱 위변조 방지(정당한 목적) 또는 악성코드의 안티바이러스 정적 시그니처 탐지 회피(악용 목적) |

- Collberg 교수의 이론적 체계에 기반하여 레이아웃, 데이터, 제어 흐름, 예방 난독화로 분류되며, 최근에는 커스텀 가상 머신(VM) 기반 난독화로 고도화됨.

## Ⅱ. 코드 난독화의 핵심 특징 및 Collberg 3대 평가 척도

### 1. 코드 난독화의 핵심 특징

| 특징 | 설명 | 기술적 파급 영향 |
|---|---|---|
| 기능적 동치성 (Equivalence) | 입력에 대한 출력 결과 불변 | 난독화 전후 프로그램의 비즈니스 로직과 시스템 동작은 100% 동일하게 유지 |
| 복잡도 인위적 증폭 | 제어 흐름 및 데이터 종속성 왜곡 | 순차적 분기문을 거대한 상태 머신(State Machine)으로 변환하여 정적 분석 방해 |
| 자원 오버헤드 수반 | 실행 속도 저하 및 바이너리 크기 증가 | 더미 코드 및 런타임 복호화 루틴 추가로 CPU 사이클과 메모리 사용량 증가 |
| 보안상의 양면성 | 보호 수단이자 공격 회피 수단 | 상용 앱의 IP 보호에 필수적인 반면, 악성코드의 EDR 탐지 회피 기술로 악용 |

### 2. Collberg 난독화 3대 평가 척도

```text
[Collberg의 난독화 평가 3대 지표]
  ├── 1. 유효성 / 복잡도 (Potency)   ──> 사람이 코드를 인지하고 이해하기 어렵게 만든 정도 (순환 복잡도 증가)
  ├── 2. 탄력성 / 복원 저항성 (Resilience) ──> 자동화된 디컴파일러, 기호 실행 도구가 역난독화하는 데 걸리는 시간/비용
  └── 3. 비용 (Cost)                  ──> 난독화 적용으로 인해 추가되는 CPU 실행 시간 오버헤드 및 바이너리 크기 증가율
```

## Ⅲ. 제어 흐름 평탄화 및 불투명 술어 메커니즘

### 1. 제어 흐름 평탄화 (Control Flow Flattening) 아키텍처

```text
[평탄화 전: 계층적 기본 블록 (CFG)]              [평탄화 후: 단일 루프 + 스위치 상태 머신]
          [Block 1]                                      ┌──> [상태 변수 State = 1]
          /       \                                      │              │
     [Block 2]   [Block 3]                               │              ▼
          \       /                                      │    [while (State != END)]
          [Block 4]                                      │              │
                                                         │              ▼
                                                         │       [switch (State)]
                                                         │         ├── Case 1: [Block 1 실행] ──> State = 2
                                                         │         ├── Case 2: [Block 2 실행] ──> State = 4
                                                         │         ├── Case 3: [Block 3 실행] ──> State = 4
                                                         │         └── Case 4: [Block 4 실행] ──> State = END
                                                         └──────────────┘
```

### 2. 불투명 술어 (Opaque Predicates) 동작 원리

- 개발자/분석 도구 관점에서는 실행 시점의 분기를 알 수 없는 것처럼 보이지만, 수학적 항진 성질에 의해 컴파일러/작성자는 항상 참(True) 또는 거짓(False)임을 아는 조건식.
- 예: 임의의 정수 $x$에 대해 항상 참인 식 $(x^2 + x) \pmod 2 == 0$을 분기문 조건에 삽입하여 절대 실행되지 않는 죽은 코드(Dead Code) 블록을 강제 생성.

## Ⅳ. 난독화 기법 4종 및 가상화 난독화 비교

### 1. 난독화 4대 기법 분류 및 특성

| 구분 | 주요 기법 | 적용 대상 | 분석 방해 효과 | 비용(오버헤드) |
|---|---|---|---|---|
| 레이아웃 난독화 (Layout) | 변수/함수명 랜덤 문자 치환(`a`, `b`), 주석 및 디버그 심볼 제거 | 식별자, 메타데이터 | 코드의 의미 파악 방해, 디컴파일 가독성 저하 | 거의 없음 (오히려 용량 감소) |
| 데이터 난독화 (Data) | 문자열 AES 암호화, 변수 분할(1개 정수를 2개로 분리), 배열 인덱스 셔플링 | 상수, 전역 변수, 문자열 | 바이너리 내 하드코딩된 API 키, URL, 평문 탐색 차단 | 낮음~보통 (런타임 복호화) |
| 제어 흐름 난독화 (Control Flow) | 평탄화(Flattening), 불투명 술어, 무한 루프 삽입, 점프 인스트럭션 난조 | 함수 분기문, 조건문 | 정적 제어 흐름 그래프(CFG) 복원 차단, 복잡도 폭증 | 중간 (분기 예측 실패 유발) |
| 가상화 난독화 (Virtualization) | 독자적인 가상 명령어 집합(V-ISA) 정의 및 인터프리터 바이트코드 런타임 구동 | 핵심 함수 및 알고리즘 | 표준 x86/ARM 역어셈블러(IDA Pro, Ghidra) 완전 무력화 | 높음 (실행 속도 10~50배 저하) |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 심볼릭 실행(Symbolic Execution, angr 도구) 및 동적 Taint 분석을 통해 불투명 술어와 상태 변수의 제어 흐름이 수학적으로 역산되어 무력화 | 수학적 술어 대신 난수 발생기, 실시간 시스템 호출(Syscall) 반환값, 스레드 레이스 컨디션을 조건에 결합하는 동적 비결정론적 술어 적용 |
| 제어 흐름 평탄화 및 가상화 난독화 적용 시 CPU 캐시 미스(Cache Miss) 및 분기 예측 실패로 인해 성능이 10~100배 저하되어 게임/금융 앱 지연 | 전체 코드에 일괄 적용을 지양하고 보안이 필수적인 인증, 결제, 라이선스 검증 함수만 선별 적용하는 핫스팟 프로파일링 기반 차등 난독화 수립 |
| 안티바이러스(AV) 및 EDR 장비가 비정상적으로 높은 엔트로피를 가진 고도 난독화 바이너리를 악성코드로 오탐하여 정상 업무 소프트웨어 차단 | 공인된 코드 서명(Code Signing) 인증서로 바이너리를 서명하고 기업 표준 빌드 파이프라인의 해시값을 EDR 화이트리스트에 사전 등록 |

## Ⅵ. 제언

### 1. 차세대 소프트웨어 보호 다계층 방어 모델

```text
[소스/컴파일 계층] ──> [난독화 컴파일러 (OLLVM)] ──> [화이트박스 암호 (WBC)]
                              │                             │
                              ├── 제어 흐름 평탄화          └── 암호키를 알고리즘에 융합 (메모리 덤프 차단)
                              └── 가상화 인터프리터 임베딩
                                                            │
                                                            ▼
[런타임 실행 계층] ──> [RASP 자가 방어 엔진] ──> [안티 디버깅 / 루팅 탐지 / 무결성 검증]
```

### 2. 난독화 도구 및 역난독화 기술 비교 평가

| 분류 | 대표 기술 / 솔루션 | 주요 기능 | 장점 및 특징 |
|---|---|---|---|
| 정적 난독화 툴 | ProGuard, DexGuard, OLLVM | 심볼 변경, 평탄화, 문자열 암호화 | 모바일(Android) 및 C/C++ 표준 툴 |
| 가상화 난독화 툴 | VMProtect, Themida | 커스텀 가상 CPU 아키텍처 변환 | 현존 최고 수준의 상용 리버싱 저항성 |
| 역난독화 프레임워크 | angr, Triton, D810 | 기호 실행, CFG 재구성, 불투명 술어 제거 | 평탄화된 상태 머신을 원래 코드로 자동 복원 |
| 동적 분석 도구 | Frida, QEMU, PIN | 런타임 함수 후킹, 메모리 인스트럭션 추적 | 난독화와 무관하게 실행 시점 평문 가로채기 |

- 코드 난독화는 만능의 보안책이 아니며 리버스 엔지니어링의 시간과 비용을 극대화하는 지연 기술이므로, RASP 및 화이트박스 암호(WBC)와 결합한 다계층 소프트웨어 보호 체계 구축 필수.
