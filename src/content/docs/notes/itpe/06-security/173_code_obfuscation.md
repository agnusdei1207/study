# 코드 난독화(Code Obfuscation)

## 핵심 개념
- 프로그램의 원래 기능과 실행 결과는 완벽히 유지하면서, 소스코드나 바이너리의 구조를 복잡하게 변경하여 사람이 읽고 이해하기 어렵게(역공학 난이도 증가) 변환하는 소프트웨어 보호 기술.
- 상용 소프트웨어의 지적재산권(IP) 보호, 라이선스 크랙 방지, 모바일 앱 위변조 방어뿐만 아니라, 악성코드 제작자가 백신의 시그니처 탐지와 보안 분석을 회피하기 위한 수단으로도 양면적으로 활용됨.

```
+-------------------------------------------------------------+
|                      코드 난독화의 핵심 원리                  |
+-------------------------------------------------------------+
| [ 원본 프로그램 P ] === 난독화 변환기(T) ===> [ 난독화 프로그램 P' ] |
|                                                             |
| * 프로그램 기능성 보존: ∀x, P(x) == P'(x) (동일한 입출력 보장) |
| * 가독성/해석력 저하: 사람이 역공학 도구로 분석 시 시간·비용 극대화 |
+-------------------------------------------------------------+
```

---

## 코드 난독화 4대 기법 분류 (Collberg 분류 기준)

```
+-------------------------------------------------------------+
|                   Collberg의 난독화 분류 체계                 |
+-------------------------------------------------------------+
| 1. 레이아웃 난독화 (Layout)       | 식별자 변경, 주석/디버그 정보 제거 |
| 2. 데이터 난독화 (Data)           | 문자열 암호화, 변수 분할 및 병합  |
| 3. 제어 흐름 난독화 (Control Flow)| 불투명 술어, 루프 전개, 제어 평탄화|
| 4. 예방/지연 기법 (Preventive)    | 디컴파일러 버그 유발, 안티 디버깅 |
+-------------------------------------------------------------+
```

### 1. 레이아웃 난독화 (Layout Obfuscation)
- **식별자 변경(Identifier Renaming)**: 의미 있는 변수명, 함수명, 클래스명을 무의미한 문자열(`a`, `b`, `_0x1a` 등)로 치환.
- **메타데이터 제거(Stripping)**: 컴파일 결과물에서 주석, 디버그 심볼, 원본 파일명 정보를 완전히 삭제.

### 2. 데이터 난독화 (Data Obfuscation)
- **문자열 암호화(String Encryption)**: API 엔드포인트, DB 연결 문자열 등 평문 스트링을 암호화하여 런타임에만 동적 복호화.
- **변수 분할 및 인코딩**: 하나의 정수 변수 $X$를 두 개의 변수 $A, B$로 분할하여 $X = 2A + B$ 형태로 조작하거나, 부울 플래그를 정수 비트마스크로 변환.
- **배열 재배치**: 1차원 배열을 다차원 배열로 접거나, 인덱스 매핑 순서를 무작위로 섞음.

### 3. 제어 흐름 난독화 (Control Flow Obfuscation)
- **불투명 술어(Opaque Predicate)**: 컴파일러나 분석가는 쉽게 알 수 없지만 항상 참(True) 또는 거짓(False)이 되는 복잡한 수학적 조건식을 삽입하여 실행되지 않는 거짓 분기(Dead Code) 생성.
- **제어 흐름 평탄화(Control Flow Flattening)**: 기존의 if-else, while 구조를 단일 거대한 switch-case 문과 상태 변수 머신 구조로 재구성하여 프로그램 흐름의 위계질서를 파괴.
- **루프 변환**: 루프 전개(Unrolling), 루프 분할(Splitting)을 적용하여 반복문 구조 은닉.

### 4. 예방 기법 (Preventive Transformation)
- **디컴파일러 결함 악용**: IDA Pro, Ghidra 등 역공학 도구가 특정 바이트 패턴 파싱 시 크래시를 일으키거나 디컴파일을 중단하도록 유도.
- **안티 디버깅 및 안티 탬퍼링**: `IsDebuggerPresent()`, `ptrace` 등을 호출하여 디버거 부착 시 프로그램을 강제 종료하고, 메모리 무결성 해시 검증 수행.

## 난독화 평가 기준 3대 척도 (Collberg Framework)

| 평가 지표 | 정의 및 세부 측정 기준 |
|---|---|
| **복잡도 (Potency)** | 사람이 코드를 이해하기 얼마나 어려워졌는가? (순환 복잡도, 중첩 깊이 증가율) |
| **견고성 (Resilience)** | 자동화된 디옵퍼스케이터(De-obfuscator) 도구에 얼마나 잘 견디는가? (해체 소요 시간) |
| **비용 (Cost)** | 난독화로 인해 프로그램의 실행 시간 및 메모리 오버헤드가 얼마나 증가하였는가? |

## 난독화 기법별 특성 비교

| 기법 구분 | 적용 대상 | 역공학 방어 효과 | 실행 성능 영향 |
|---|---|---|---|
| **식별자 변경** | Java, .NET, JS 바이트코드 | 기본적 가독성 저하 | 성능 저하 없음 (파일 크기 감소) |
| **문자열 암호화** | 모든 바이너리/스크립트 | 핵심 로직 및 자격증명 탐색 지연 | 런타임 복호화 오버헤드 미미 |
| **불투명 술어** | 제어 분기문 | 정적 역공학 도구 흐름 분석 마비 | 분기 예측 실패로 약간의 지연 발생 |
| **제어 흐름 평탄화**| 함수 전체 구조 | 제어 흐름 그래프(CFG) 복원 극도로 어려움 | switch 문 반복으로 성능 저하 발생 |

## 결론 및 실무 시사점
- 코드 난독화는 역공학을 원천 차단하는 완전한 보안 솔루션이 아니며, 공격자의 분석 소요 시간과 비용을 지연(Delay)시키는 방어 심층화 수단임.
- 무분별한 난독화는 심각한 런타임 성능 저하와 디버깅 곤란을 유발하므로, 핵심 비즈니스 로직 및 지적재산 모듈에 선별 적용하고 RASP(런타임 애플리케이션 자가보호)와 병행해야 함.
