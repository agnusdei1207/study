## 지식 로드맵 내 현재 위치

네트워크 보안 → 경계 기반 통제(Castle-and-Moat) → 제로트러스트 아키텍처(ZTA) 전이

## 30초 인출

- **본질:** 외부 비신뢰 네트워크와 내부 신뢰 네트워크의 접점(경계)에 방화벽, VPN, IPS 등을 배치하여 침입을 방어하는 전통적인 성곽-해자(Castle-and-Moat) 보안 모델.
- **메커니즘:** 경계 게이트웨이에서 1회성 진입 인증 통과 시 내부망 전체에 무조건적 암묵적 신뢰(Implicit Trust)를 부여하고 자유로운 횡적 통신 허용.
- 통찰: 내부망 침투 시 측면 이동(Lateral Movement)에 무방비한 취약점을 해결하기 위해 CISA ZTMM v2.0 기반 '자원 중심 지속 검증' 제로트러스트 아키텍처로의 전환 필수.

<details><summary>핵심 용어</summary>

- **경계 기반 보안(Castle-and-Moat)**: 성곽 둘레에 해자를 파고 성문에서만 출입을 검사하듯, 네트워크 물리적 경계에서만 출입을 통제하는 레거시 보안 패러다임.
- **암묵적 신뢰(Implicit Trust)**: 네트워크 경계 내부(사내망)에 위치한 모든 장치와 사용자는 안전하다고 가정하는 잘못된 신뢰 모델.
- **측면 이동(Lateral Movement)**: 단일 엔드포인트에 침투한 공격자가 평면적인 사내망 구조를 악용하여 내부의 핵심 DB 및 도메인 컨트롤러로 전이하는 공격 기법.
- **ZTNA(Zero Trust Network Access)**: 사용자와 기기의 신원 및 보안 태세를 지속 검증하여 승인된 특정 애플리케이션에만 1:1 암호화 터널을 제공하는 기술.
- **마이크로세그멘테이션(Microsegmentation)**: 내부 네트워크를 워크로드 단위의 미세한 보안 존으로 분할하여 호스트 간 비인가 횡적 통신을 원천 차단하는 기술.
</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 외부 인터넷과 내부 사내망 사이의 물리적·논리적 경계 지점에 방화벽, 침입방지시스템(IPS), VPN 등을 구축하여 외부 위협의 진입을 방어하는 보안 접근법 |
| 목적 | 단일 통제 지점을 통한 중앙 집중적 트래픽 검사 및 정책 집행, 명확한 네트워크 물리적 신뢰 구획 분리를 통한 인프라 자산 보호 |

## Ⅱ. 경계 기반 보안의 핵심 특징 및 한계점

| 특징 항목 | 세부 동작 내용 | 구조적 취약점 및 한계 |
|---|---|---|
| 암묵적 신뢰 부여 | 경계 통과(VPN/게이트웨이 로그인) 성공 시 내부 자원에 대한 광범위한 통신 허용 | 1개 단말 감염 시 사내 전산망 전체로 랜섬웨어 무혈입성 |
| 평면적 내부망(Flat Network) | 서브넷 간 엄격한 접근 제어 부재로 호스트 간 Any-to-Any 통신 가능 | LotL 도구를 악용한 측면 이동(Lateral Movement) 방어 불가 |
| 경계 소멸(De-perimeterization) | 클라우드(SaaS/IaaS), 모바일, 재택근무 확산으로 물리적 경계선 해체 | 보호해야 할 데이터와 워크로드가 사내 방화벽 외부에 상주 |
| 정적 IP/포트 기반 정책 | 사용자 신원이나 단말 상태 대신 출발지/목적지 IP 및 포트 번호로 룰셋 구성 | 동적 클라우드 컨테이너 환경에서 룰셋 복잡도 폭증 및 관리 실패 |
| 내부자 위협 대응 부재 | 악의적 내부자 또는 합법 권한을 탈취당한 정상 계정의 데이터 유출 통제 불가 | 인가된 세션 내부에서 발생하는 권한 오남용 감시 사각지대 |

## Ⅲ. 경계 기반 보안 아키텍처 vs 제로트러스트 전이 모델

```text
[ 1. 전통적 경계 기반 보안 모델 (Castle-and-Moat) ]
외부 인터넷 ──▶ [ 방화벽 / VPN 게이트웨이 ] ──▶ [ 내부 신뢰 사내망 (Implicit Trust Zone) ]
                     (1회성 경계 인증)                    ├── 업무용 PC (침해 발생!)
                                                           ├── 파일 서버 ◀── [측면 이동 무차별 확산]
                                                           └── 코어 DB   ◀── [랜섬웨어 암호화]

[ 2. 제로트러스트 아키텍처 (ZTA) 전이 모델 ]
사용자/단말 ──▶ [ 정책 결정점 (PDP) ] ◀── CTI / EDR 단말 무결성 / IAM 정책 엔진
                     │ (지속적 위험 평가: Continuous Assessment)
                     ▼
              [ 정책 집행점 (PEP) / ZTNA 게이트웨이 ]
                     │ (신원 확인 + 기기 적합성 통과 시 최소 권한 1:1 연결)
                     ├──────────────────┬──────────────────┐
                     ▼                  ▼                  ▼
              [ App A 워크로드 ]   [ App B 워크로드 ]   [ 코어 DB 워크로드 ]
              (마이크로세그멘테이션 격리: 타 워크로드 간 직접 통신 전면 차단)
```

| 기둥 (CISA ZTMM) | 레거시 경계 기반 보안 통제 | 제로트러스트(ZTA) 전이 구현 모델 |
|---|---|---|
| 신원 (Identity) | ID/PW 기반 VPN 1회성 로그인, 정적 패스워드 | 피싱 저항 MFA(FIDO2), 위험 기반 연속 인증(CARTA) |
| 기기 (Device) | 인가된 MAC 주소 또는 사내 자산 태그 확인 | EDR 텔레메트리 연동, 단말 무결성(컴플라이언스) 실시간 평가 |
| 네트워크 (Network) | 거대한 단일 사내망 서브넷, DMZ 분리 수준 | 마이크로세그멘테이션, ZTNA 기반 1:1 소프트웨어 정의 경계 |
| 워크로드 (Workload) | 서버 OS 단위 방화벽 룰, 정적 인프라 호스팅 | 서비스 메시(Istio) mTLS 상호 인증, 컨테이너 불변 실행 |
| 데이터 (Data) | 사내망 저장 파일 평문 유지, 네트워크 유출 차단 의존 | 데이터 분류, 컬럼 암호화, DRM/DLP, 객체 레벨 세부 인가 |

## Ⅳ. 경계 기반 보안(Castle-and-Moat) vs 제로트러스트(Never Trust, Always Verify) 비교

| 비교 항목 | 경계 기반 보안 (Perimeter Security) | 제로트러스트 보안 (Zero Trust Architecture) |
|---|---|---|
| 기본 보안 철학 | 신뢰하되 검증한다 (Trust, but Verify) | 절대 신뢰하지 않고 항상 검증한다 (Never Trust, Always Verify) |
| 신뢰의 기준 | 물리적 네트워크 위치 (내부 사내망 vs 외부 인터넷) | 검증된 사용자 신원, 기기 무결성 상태, 요청 컨텍스트 |
| 네트워크 토폴로지 | 북-남(North-South) 트래픽 중심 집중 검사 | 동-서(East-West) 트래픽 전수 인라인 검사 및 격리 |
| 원격 접속 기술 | VPN (사내 네트워크 대역 전체로 IP 할당 진입) | ZTNA (인가된 특정 애플리케이션 단일 세션만 브로커링) |
| 측면 이동 내성 | 취약 (내부 진입 시 다른 호스트로 자유로운 이동) | 우수 (마이크로세그멘테이션으로 호스트 간 이동 차단) |
| 클라우드 적합성 | 낮음 (모든 트래픽을 본사로 백홀하여 병목 유발) | 매우 높음 (클라우드 네이티브 분산 환경 완벽 지원) |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 전사 임직원 재택근무 시 VPN 장비로 트래픽이 집중되어 대역폭 병목 및 서비스 가용성 다운타임 유발 | 클라우드 기반 보안 서비스 엣지(SSE/SASE)를 도입하여 사용자와 가장 가까운 글로벌 PoP에서 분산 ZTNA 인라인 검사 수행 |
| 경계 방화벽 통과 후 내부 호스트 간 통신(East-West)에 대한 모니터링 및 접근 제어 부재 | 호스트 기반 소프트웨어 방화벽 및 eBPF 기반 마이크로세그멘테이션 솔루션(Illumio/Cilium)을 적용하여 프로세스 단위 횡적 통신 강제 차단 |
| 공격자가 사내망 상주 직원의 정상 자격증명을 탈취할 경우 경계 장비에서 악의적 행위 식별 불가 | 사용자 및 엔티티 행위 분석(UEBA)을 연동하여 평소와 다른 자원 접근, 대량 파일 다운로드 등 이상 징후 발생 시 세션 즉시 강제 종료 |
| 레거시 메인프레임이나 구형 프로토콜을 사용하는 기간계 시스템의 경우 현대적 ZTNA 에이전트 설치 불가 | 레거시 자산 전면에 역방향 프록시(Reverse Proxy) 또는 점프 호스트(Bastion)를 배치하고 계정 권한을 시간 제한 단기 토큰으로 중계 통제 |

## Ⅵ. 제언

```text
[ 경계 보안에서 제로트러스트로의 3단계 진화 로드맵 ]

  [ 1단계: 하이브리드 공존 ]         [ 2단계: 핵심 자산 ZTNA 전환 ]      [ 3단계: 전사 마이크로세그멘테이션 ]
+----------------------------+     +-------------------------------+     +-------------------------------+
| • VPN 유지 + 피싱 저항 MFA | ──> | • 클라우드/SaaS 접근 ZTNA 분리| ──> | • 온프레미스 망 마이크로세그  |
| • 중요 단말 EDR 전면 배포  |     | • CISA ZTMM 2단계 성숙도 달성 |     | • 전사 자원 완전 제로트러스트 |
+----------------------------+     +-------------------------------+     +-------------------------------+
```

| 진화 단계 | 엔지니어링 구현 과제 | 핵심 달성 효과 |
|---|---|---|
| 1단계 (초기 정비) | 관리자 계정 대상 FIDO2 MFA 강제화 및 인터넷 접점 엣지 장비 취약점 전수 패치 | 자격증명 도용 및 외부 침입 위험 80% 차단 |
| 2단계 (클라우드 ZTNA) | 비즈니스 중요 SaaS 및 클라우드 워크로드부터 VPN 접속을 배제하고 ZTNA 전환 | VPN 트래픽 병목 해소 및 직무별 세부 인가 구현 |
| 3단계 (성숙도 완성) | 사내 코어 DB 및 서버 팜 대상 마이크로세그멘테이션 완성 및 CARTA 동적 인가 연동 | 침해 발생 시에도 피해 범위를 단일 노드로 100% 국소화 |

## 출제 이력과 검증 출처

- NIST SP 800-207, Zero Trust Architecture
- Gartner, Market Guide for Zero Trust Network Access (ZTNA)
