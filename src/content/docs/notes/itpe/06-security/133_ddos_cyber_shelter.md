## 지식 로드맵 내 현재 위치

지식 위치: 정보보안 → DDoS 대응·서비스 연속성 → **DDoS 사이버대피소**

## 30초 인출

- **본질:** 분산 서비스 거부(DDoS) 공격을 받는 영세·중소기업 웹 서버를 보호하기 위해 DNS를 대피소로 우회하여 대규모 공격 트래픽을 정화(Scrubbing)하고 정상 요청만 원본에 전달하는 공공 방어 서비스
- **메커니즘:** 침해 발생 및 대피소 적용 신청 → DNS A 레코드 변경(대피소 VIP) → 대용량 스크러빙 센터 트래픽 정제 → 리버스 프록시 기반 정상 패킷 원본 전달
- **통찰:** 원본 IP 직접 공격은 원본 방화벽의 대피소 IP 외 전면 Drop으로 차단하고 DNS TTL 단축과 Keyless SSL을 결합하여 전환 지연과 키 유출 위험 동시 해결 필수

<details>
<summary>핵심 용어</summary>

- **사이버대피소** : KISA가 운영하는 중소기업 무료 분산 서비스 거부(DDoS) 방어 인프라.
- **Traffic Scrubbing (트래픽 정제)** : 대용량 유입 패킷 중 L3~L7 비정상 공격 트래픽을 선별 차단하고 정상 트래픽만 추출하는 기술.
- **Reverse Proxy** : 클라이언트와 원본 서버 사이에서 중계자 역할을 하며 IP 은닉 및 캐싱을 수행하는 아키텍처.
- **Direct IP Attack** : DNS를 우회하여 과거 노출된 원본 서버의 실제 공인 IP로 직접 대량 트래픽을 투사하는 공격.

</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 한국인터넷진흥원(KISA)이 DDoS 공격으로 서비스 장애를 겪는 중소기업을 위해 대규모 공격 트래픽을 우회시켜 정제한 후 정상 패킷만 원본 서버로 안전하게 전달하는 공공 클라우드 스크러빙 서비스 |
| 목적 | 고가의 전용 DDoS 방어 장비 및 대역폭 증설 여력이 부족한 중소기업의 웹 서비스 가용성을 보장하고 금전적 피해와 2차 사이버 침해 방지 |

- 공격 발생 시 긴급 방어뿐 아니라 평상시 사전 등록을 통해 상시 방어 체계로의 신속한 전환을 지원하는 공공 사이버 안전망

## Ⅱ. 사이버대피소의 핵심 기술적 특성

| 특성 항목 | 세부 내용 및 기술적 의미 | 운영 및 방어 이점 |
|---|---|---|
| DNS 기반 트래픽 우회 | 네트워크 물리 회선이나 하드웨어 재구축 없이 도메인 A 레코드 변경만으로 방어망 투입 | 수분 내 신속한 비상 전환 가능, 인프라 변경 제로 |
| 대용량 스크러빙 인프라 | 수백 Gbps 이상의 분산 대역폭과 고성능 안티DDoS 방어 클러스터 보유 | 회선 대역폭 고갈 공격(UDP/ICMP/SYN Flood) 완전 흡수 |
| 다계층(L3~L7) 통합 정화 | 볼륨 공격뿐 아니라 정상 HTTP를 위장한 L7 CC Attack, Slowloris 등 지능형 웹 공격 차단 | 정상 비즈니스 트랜잭션의 중단 없는 서비스 보장 |
| 무상 공공 보안 서비스 | 정보보호 투자 여력이 열악한 중소기업법상 중소기업 및 비영리 기관에 무료 제공 | 보안 취약 지대의 사회적 사이버 탄력성 강화 |

- 보호 대상 웹 서버의 실제 IP를 외부에 은닉하는 리버스 프록시(Reverse Proxy) 기반 보호 특성 보유

## Ⅲ. 사이버대피소 아키텍처 및 4단계 트래픽 처리 메커니즘

```text
[KISA DDoS 사이버대피소 우회 및 트래픽 정제 아키텍처]

               공격자 / 일반 사용자
                        │
                        ▼ (도메인 웹 접속 요청)
            [ DNS 쿼리: www.site.com ]
                        │ (A 레코드가 대피소 가상 IP로 변경됨)
                        ▼
    ┌─────────────────────────────────────────────────────────────┐
    │                 KISA DDoS 사이버대피소 스크러빙 센터         │
    │   ┌─────────────────────────────────────────────────────┐   │
    │   │ 1. 대용량 L3/L4 방어 (SYN, UDP, ICMP Flood 차단)     │   │
    │   └──────────────────────────┬──────────────────────────┘   │
    │                              ▼                              │
    │   ┌─────────────────────────────────────────────────────┐   │
    │   │ 2. L7 웹 공격 분석 (HTTP GET/POST Flood, Slowloris) │   │
    │   └──────────────────────────┬──────────────────────────┘   │
    │                              ▼                              │
    │   ┌─────────────────────────────────────────────────────┐   │
    │   │ 3. 리버스 프록시 엔진 (정상 HTTP/HTTPS 트래픽 선별)  │   │
    │   └──────────────────────────┬──────────────────────────┘   │
    └──────────────────────────────┼──────────────────────────────┘
                                   │
                                   ▼ (정상 요청만 포워딩: 방화벽 화이트리스트)
                    [ 기업 내부 원본 웹 서버 (Origin) ]
                    (대피소 IP 외 공인 인터넷 직접 접속 전면 차단)
```

| 처리 단계 | 핵심 엔지니어링 활동 | 기술 메커니즘 |
|---|---|---|
| 1. 신청 및 적격성 확인 | 피해 기업이 보호나라를 통해 긴급 방어 신청, DNS 설정 정보 및 원본 IP 등록 | 중소기업 적격성 및 도메인 소유권 확인 |
| 2. DNS A 레코드 변경 | 도메인의 네임서버에서 보호 대상 호스트 IP를 대피소 가상 IP(VIP)로 갱신 | DNS 우회(Redirection) 적용 |
| 3. 대피소 스크러빙 | 대피소 유입 트래픽에 대해 임계치 기반 L3/L4 필터링 및 챌린지 기반 L7 검사 수행 | 비정상 패킷 드롭, 정상 세션 통과 |
| 4. 원본 서버 전달 | 정제된 정상 HTTP/HTTPS 패킷을 사전에 지정된 기업 원본 서버 IP로 프록시 전송 | 원본 서버 부하 제로화 및 가용성 유지 |

## Ⅳ. DDoS 방어 체계 비교: 사이버대피소 vs 상용 클라우드 CDN vs 온프레미스 장비

| 비교 항목 | KISA DDoS 사이버대피소 | 상용 글로벌 CDN (Cloudflare 등) | 온프레미스 안티DDoS 장비 |
|---|---|---|---|
| 서비스 비용 | 전액 무료 (정부 공공 지원) | 종량제 또는 유료 플랜 구독 | 수억 원대 하드웨어 구매/유지보수 |
| 주 보호 대상 | 국내 영세·중소기업 및 비영리 웹사이트 | 전 세계 글로벌 엔터프라이즈 | 기업 자체 데이터센터/전산실 인프라 |
| 지원 프로토콜 | HTTP, HTTPS 중심 (웹 전용) | HTTP/HTTPS, TCP/UDP 전 프로토콜 | 전 네트워크 계층 (IP/BGP 연동) |
| 원본 대역폭 한계 | 대피소가 흡수 (회선 증설 불필요) | 글로벌 Anycast 네트워크가 전량 흡수 | 전산실 인입 회선 대역폭 초과 시 마비 |
| 도입 소요 시간 | 신청 후 1~2시간 내 (DNS 전환) | 수분 내 셀프 서비스 적용 | 하드웨어 발주 및 실장 수주~수개월 |

## Ⅴ. 사이버대피소 도입 시 엔지니어링 한계와 해결 방안

| 한계 | 방안 |
|---|---|
| 과거 기록(Shodan, Censys)이나 메일 헤더(MX 레코드) 등을 통해 원본 서버의 실제 공인 IP가 노출되어 대피소를 거치지 않는 Direct IP 공격 발생 | 원본 서버 앞단 방화벽(AWS 시큐리티 그룹, 온프레미스 방화벽)에서 KISA 대피소 인바운드 IP 대역만 80/443 허용하고 그 외 모든 외부 IP는 전면 Drop 차단 |
| DNS 캐시 및 로컬 ISP 네임서버의 TTL(Time-to-Live) 잔여 시간으로 인해 A 레코드 변경 후 트래픽이 즉시 우회되지 않고 전환 지연 발생 | 평상시 도메인 TTL을 300초(5분) 이하로 단축 유지하고, 상시 대피소 모드로 운영하거나 사전 등록을 통한 비상 전환 자동화 스크립트 확보 |
| HTTPS 웹사이트 보호를 위해 대피소에 기업 SSL/TLS 인증서 및 개인키(Private Key)를 제출해야 하므로 기밀성 침해 및 키 유출 우려 | 개인키를 대피소에 전달하지 않고 암호 연산만 원본 서버로 원격 위임하는 Keyless SSL 아키텍처 도입 또는 대피소 전용 임시 인증서 분리 발급 |
| 사이버대피소는 원칙적으로 웹 트래픽(HTTP/HTTPS) 전용이므로 게임, 메일, 비표준 TCP/UDP 서비스에 대한 DDoS 공격 방어 불가 | 비웹 서비스는 통신사(KT, SKB, LGU+)의 BGP Flowspec 기반 클린존(Clean Zone) 회선 스크러빙 서비스를 연계하거나 전용 프록시 터널링 구축 |

## Ⅵ. 중소기업 비즈니스 연속성을 위한 DDoS 다계층 방어 제언

```text
[DDoS 서비스 연속성 보장을 위한 3단계 대응 체계]

  ┌─────────────────────────────────────────────────────────────┐
  │                 1. 평상시 사전 예방 단계                    │
  │   - KISA 사이버대피소 사전 등록 완료 및 모의 훈련           │
  │   - DNS TTL 300초 설정 및 MX/메일 서버 원본 IP 격리         │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
  ┌──────────────────────────────┴──────────────────────────────┐
  │                 2. 공격 발생 및 긴급 전환 단계              │
  │   - 자동화 API 연동 DNS A 레코드 대피소 VIP 갱신           │
  │   - 원본 서버 방화벽 대피소 외 외부 인바운드 차단 활성화    │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
  ┌──────────────────────────────┴──────────────────────────────┐
  │                 3. 공격 종료 및 복귀 단계                  │
  │   - KISA 관제센터 공격 소멸 통보 확인                      │
  │   - 사후 침해 지표(IOC) 분석 및 원본 IP 변경 재배치         │
  └─────────────────────────────────────────────────────────────┘
```

| 영역 | 엔지니어링 세부 과제 | 통제 목표치 |
|---|---|---|
| 사전 등록률 | 사내 전 대외 공개 웹사이트의 KISA 대피소 사전 승인 확보 | 사전 등록 완료율 100% |
| 우회 전환 시간 | 공격 인지 후 대피소 트래픽 전환 완료까지 소요 시간(MTTD+MTTR) | 전체 전환 소요 시간 < 15분 |
| 원본 IP 은닉 | 검색엔진 및 DNS 레코드 상의 원본 IP 노출 여부 주기적 스캔 | 원본 공인 IP 노출 건수 0건 |

## 출제 이력과 검증 출처

- 제128회 정보관리기술사 예상 연계 주제: DDoS 공격 유형 및 공공 사이버대피소 대응
- KISA 보호나라: DDoS 사이버대피소 서비스 소개 및 이용 안내
- KISA: 분산 서비스 거부(DDoS) 공격 대응 가이드라인
- IETF RFC 1035: Domain Names - Implementation and Specification (TTL & DNS Caching)
- Cloudflare Architecture: Keyless SSL and Anycast DDoS Mitigation
