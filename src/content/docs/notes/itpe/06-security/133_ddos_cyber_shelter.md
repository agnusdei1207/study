## 지식 로드맵 내 현재 위치

정보보안 → DDoS 대응·서비스 연속성 → DDoS 사이버대피소

## 30초 인출
- **본질:** KISA 사이버대피소는 중소기업 웹사이트의 DDoS 트래픽을 우회·정화해 정상 요청을 원본에 전달하는 지원 서비스

## 처리 흐름
```text
공격 발생 → 사전 등록 또는 긴급 적용 신청 → 적격·환경 확인
→ 보호 웹사이트 DNS 정보 변경 → 대피소 트래픽 분석·차단
→ 정상 요청 원본 전달 → 사후 모니터링 및 결과 통보
```

- **메커니즘:** 신청·적격 확인 → DNS 우회 → 공격 분석·차단 → 정상 요청 원본 전달
- **통찰:** 한계: 대피소 우회만으로 원본 IP 직접 공격을 막을 수 없음 → 방안: 원본 접근을 제한하고 DNS 전환·복귀를 시험

<details><summary>핵심 용어</summary>

- **DDoS:** 분산된 다수 출처의 트래픽으로 서비스 가용성을 저해하는 공격.
- **원본 서버:** ** 정화된 정상 요청을 처리하는 보호 대상 웹 서버.

</details>

## 2~4교시 25점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 중소기업 웹사이트의 대량 분산 트래픽을 정화해 정상 접속을 원본 서버로 전달하는 KISA의 방어 지원 서비스 |
| 목적 | 공격 중 웹 서비스의 정상 접속 유지 |

### Ⅱ. 필요성과 구성

```text
도메인 DNS ─우회 설정─> 사이버대피소
이용자·공격 요청 ──────> 분석·차단
                             └─ 정상 요청 → 원본 서버
```
중소기업 회선 또는 서버 자원이 대량의 분산 요청으로 고갈되는 상황에 대한 공공 방어 지원. 보호 대상 웹사이트, DNS, 대피소의 분석·차단 기능, 원본 서버로 구성.

### Ⅲ. 절차
| 단계 | 주요 확인 |
|---|---|
| 준비 | 사전 등록, 서비스 환경과 도메인·원본 설정 확인 |
| 대응 | 공격 탐지, 방어 적용 신청, 적격성 확인 |
| 우회 | 웹사이트 DNS 정보 변경, 대피소에서 정상·공격 트래픽 분리 |
| 복구 | 공격 소멸 확인, 사후 모니터링과 결과 통보 |

#### 운영 유의
원본 서버가 외부에 그대로 노출되면 대피소를 거치지 않는 직접 공격 가능. DNS 캐시와 서비스 구성에 따른 전환 지연 고려. 적용 전 지원 대상과 해외 접속·비웹 트래픽 등 제공 범위를 KISA 안내에서 확인. 서비스만으로 모든 유형의 DDoS 방어 또는 무중단 보장 불가.

### Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 대피소 우회 후 원본 서버가 노출되면 직접 DDoS 공격 가능 | 원본 접근을 제한하고 DNS 전환 지연·복구 경로를 사전 시험 |

### Ⅴ. 제언

- 원본 IP 노출 여부와 DNS 전환 시간을 사전에 점검하고, 실제 트래픽 우회·복귀를 모의 시험한다.
