# 제로 트러스트 보안(Zero Trust Security)

## 핵심 개념
- "결코 신뢰하지 말고, 항상 검증하라(Never Trust, Always Verify)"를 기본 철학으로 삼아, 내부망과 외부망의 물리적 경계를 불문하고 모든 접근 주체의 신원과 기기 상태를 지속적으로 검증하는 보안 패러다임.
- 침해를 기본 전제(Assume Breach)로 두고 권한을 최소화(Least Privilege)하며, NIST SP 800-207 표준 아키텍처를 기반으로 제어 영역(Control Plane)과 데이터 영역(Data Plane)을 분리 통제.

```
+-------------------------------------------------------------+
|                 제로 트러스트 3대 핵심 기본 원칙                |
+-------------------------------------------------------------+
| 1. 명시적 검증 (Verify Explicitly)  | 신원, 위치, 단말 무결성, 이상행위 상시 검증 |
| 2. 최소 권한 (Least Privilege)      | JIT(적시), JEA(적정) 권한 및 마이크로 세그먼트 |
| 3. 침해 가정 (Assume Breach)        | 내부망 침투를 전제하여 측면이동(Lateral) 차단 |
+-------------------------------------------------------------+
```

## NIST SP 800-207 제로 트러스트 아키텍처

```
+-------------------------------------------------------------+
| 제어 영역 (Control Plane)                                    |
|   +-----------------------------------------------------+   |
|   |         정책 결정 지점 (Policy Decision Point: PDP)  |   |
|   |  +--------------------+    +----------------------+ |   |
|   |  | 정책 엔진 (PE)     |<-->| 정책 관리자 (PA)     | |   |
|   |  | (Policy Engine)    |    | (Policy Admin)       | |   |
|   |  +--------------------+    +----------------------+ |   |
|   +-----------------------------------------------------+   |
+-------------------------------------------------------------+
       ^                                            |
       | 컨텍스트 수집 (신원, 단말, SIEM, 위협정보)  | 동적 세션 제어 명령
       v                                            v
+-------------------------------------------------------------+
| 데이터 영역 (Data Plane)                                    |
|  [주체/단말] ====> [정책 시행 지점: PEP] ====> [엔터프라이즈 리소스]|
|  (Subject)        (Policy Enforcement)       (Enterprise Resource)|
+-------------------------------------------------------------+
```

### 1. 주요 논리적 구성 요소
- **정책 엔진 (PE, Policy Engine)**: 주체의 신원, 단말 상태, 접근 대상 자원의 민감도, 외부 위협 인텔리전스를 종합하여 자원 접근 허용/차단 여부를 최종 판정.
- **정책 관리자 (PA, Policy Administrator)**: PE의 결정을 수신하여 주체와 리소스 간의 통신 경로를 동적으로 개설하거나 차단하는 자격증명/토큰 발급.
- **정책 시행 지점 (PEP, Policy Enforcement Point)**: 제어 영역(PDP)의 지시에 따라 실제 데이터 패킷 흐름을 라우팅, 암호화 터널링 또는 차단하는 게이트웨이.

## 전통적 경계 보안 vs 제로 트러스트 보안 비교

| 비교 항목 | 전통적 경계 보안 (Perimeter Security) | 제로 트러스트 보안 (Zero Trust) |
|---|---|---|
| **신뢰 모델** | 성과 해자(Castle-and-Moat) 모델, 내부망 무조건 신뢰 | 신뢰 영역 없음(Zero Trust), 내부망도 잠재적 적대 영역 |
| **인증 시점** | 망 진입 시점 1회 인증 (VPN, 방화벽 통과 후 자유) | 트랜잭션 및 자원 접근마다 지속적·동적 검증 |
| **접근 단위** | 서브넷/네트워크 대역 단위 접근 허용 | 애플리케이션 및 개별 데이터 자원 단위 격리 |
| **망 분할** | 대규모 서브넷 분할(VLAN, ACL) | 마이크로 세그멘테이션(Micro-segmentation) |
| **측면 이동** | 내부 침투 성공 시 망 전체로 쉽게 횡적 확산 가능 | 호스트 간 통신 통제로 공격자의 측면 이동 원천 차단 |

## 제로 트러스트 5대/6대 핵심 요소(Pillars)

```
[1. 신원 (Identity)] ----> 강력한 MFA, FIDO2, 기계 계정(NHI) 포함 엄격한 신원 검증
[2. 기기 (Device)]   ----> MDM, EDR 연계 무결성·패치 상태·탈옥 여부 컴플라이언스 점검
[3. 네트워크 (Net)]  ----> ZTNA(Zero Trust Network Access), 소프트웨어 정의 경계(SDP)
[4. 애플리케이션]    ----> API 게이트웨이 연계, 개별 앱 단위 보안 프록시
[5. 데이터 (Data)]   ----> 데이터 분류·태깅, 전송/저장 암호화, DRM/DLP 연계
[6. 가시성 및 분석]  ----> SIEM/SOAR 기반 실시간 로그 상관분석, 위험도 동적 산출
```

## 제로 트러스트 구현 핵심 기술

### 1. ZTNA (Zero Trust Network Access) / SDP (Software Defined Perimeter)
- 네트워크 IP 대역 자체를 인터넷에서 완전히 은닉(Black Cloud)하고, SPA(Single Packet Authorization) 단일 패킷 사전 인증 통과 시에만 특정 애플리케이션 포트 터널을 1:1 동적 개설.

### 2. 마이크로 세그멘테이션 (Micro-segmentation)
- 가상화 및 클라우드 워크로드 단위로 호스트 기반 소프트웨어 방화벽을 적용하여, 동일 서브넷 내 동-서(East-West) 트래픽을 엄격히 차단.

### 3. CARTA (지속적 적응형 위험 및 신뢰 평가)
- 정적 룰셋이 아닌 머신러닝 기반 UEBA(사용자·개체 행위 분석)를 통해 사용자의 행위 이상 징후 발생 시 세션을 즉시 차단하거나 MFA 재인증 트리거.

---

## 결론 및 실무 시사점
- 제로 트러스트는 단일 제품이나 솔루션이 아니며, 엔드포인트·신원·네트워크 전반을 아우르는 보안 아키텍처적 전환임.
- 국내 국가사이버안보센터 및 KISA의 '국가 제로트러스트 가이드라인 2.0'에 발맞추어 단계별 성숙도 모델(도입-발전-고도화)을 수립하고 점진적으로 전환해야 함.
