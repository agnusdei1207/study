## 지식 로드맵 내 현재 위치

- 정보보안 → 보안 아키텍처 → 네트워크 및 접근통제 → 제로 트러스트(Zero Trust)

```text
[전통 경계 보안 (성곽-해자)] ──> [내부망 침투 시 횡적 이동(Lateral Movement) 취약]
                                          │
                                          ▼
[제로 트러스트 아키텍처 (ZTA)] ──> [Never Trust, Always Verify]
                                   ├── 제어 평면 (PE / PA): 동적 정책 판단 및 세션 제어
                                   └── 데이터 평면 (PEP): 암호화 터널 수립 및 마이크로세그멘테이션
```

## 30초 인출

- **본질:** 네트워크 위치나 경계에 기반한 암묵적 신뢰를 전면 제거하고, 모든 접근 요청에 대해 주체·기기·컨텍스트를 동적으로 지속 검증하여 최소 권한을 부여하는 보안 패러다임.
- **메커니즘:** 접근 요청(주체/기기) → PEP 인터셉트 → PE 동적 위험 평가 → PA mTLS 세션 수립 지시 → PEP 통신 허가 및 지속적 세션 무결성 모니터링.
- **통찰:** 단순 솔루션(ZTNA/SDP) 도입만으로는 완성되지 않으며, 전사 데이터 인벤토리 자산 식별과 아이덴티티 거버넌스(IGA)를 통합한 CARTA 기반의 지속적 적응형 인가 체계 구축 필수.

## 2~4교시 예상문제 (25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | "절대 신뢰하지 말고, 항상 검증하라(Never Trust, Always Verify)"는 원칙 하에 내부망과 외부망 구분 없이 모든 자원 접근을 지속적으로 검증·통제하는 보안 모델 |
| 목적 | 클라우드 전환과 재택근무 확산에 따른 물리적 경계 붕괴를 극복하고, 내부 침투 공격자의 횡적 이동(Lateral Movement) 및 데이터 유출을 원천 차단 |

- NIST SP 800-207 표준에 의해 공식화되었으며, 신원(Identity), 기기(Device), 네트워크(Network), 워크로드(Workload), 데이터(Data) 5대 축을 중심으로 구성.

## Ⅱ. 제로 트러스트의 핵심 특징 및 7대 기본 원칙

### 1. 제로 트러스트의 핵심 특징

| 특징 | 설명 | 기술적 구현 내용 |
|---|---|---|
| 암묵적 신뢰 영역 배제 | 사내망 IP 주소에 대한 신뢰 박탈 | 내부 인트라넷 접속이라도 외부 인터넷 접속과 동일한 수준의 엄격한 검증 강제 |
| 트랜잭션별 동적 인가 | 로그인 시점 검증을 넘어 매 요청 검증 | 세션 유지 중에도 기기 상태, 접속 IP 이상 발생 시 실시간 권한 축소 및 차단 |
| 세분화된 마이크로세그멘테이션 | 네트워크 세그먼트를 단일 워크로드로 축소 | 침해 발생 시 공격자가 인접 서버로 확산되지 못하도록 호스트 단위 방화벽 격리 |
| 데이터 중심 보호 | 자산의 중요도에 따른 차등 암호화 | 전송 중(Data in Transit) 및 저장 중(Data at Rest) 전 구간 종단간 암호화 적용 |

### 2. NIST SP 800-207 7대 기본 원칙

```text
[NIST SP 800-207 7대 테넷(Tenets)]
  1. 모든 데이터 소스와 컴퓨팅 서비스는 자원(Resource)으로 간주
  2. 네트워크 위치에 관계없이 모든 통신을 안전하게 보호 (E2EE 암호화)
  3. 개별 세션 단위로 개별 기업 자원에 대한 접근 권한 부여
  4. 자원에 대한 접근은 주체/기기 상태 및 행위 속성을 반영한 동적 정책으로 결정
  5. 기업은 모든 연계 자산의 상태와 보안 태세를 감시하고 무결성 측정
  6. 모든 자원 인증과 인가는 동적이며 접근 허용 전 엄격히 강제
  7. 자산의 현재 상태, 인프라, 통신에 관한 가능한 많은 정보를 수집하여 보안 개선에 활용
```

## Ⅲ. NIST SP 800-207 논리 아키텍처 및 세션 수립 프로세스

### 1. ZTA 논리적 구성 컴포넌트 아키텍처

```text
+-----------------------------------------------------------------------------------------+
|                               NIST SP 800-207 논리 아키텍처                               |
+-----------------------------------------------------------------------------------------+
                         [정책 결정 지점 (PDP: Policy Decision Point)]
                         +-----------------------------------------+
                         |       정책 엔진 (PE: Policy Engine)      | <── [위협 인텔리전스]
                         |   - 주체/자산/위협 기반 접근 허용 결정  | <── [지속 진단 완화 CDM]
                         +-----------------------------------------+ <── [PKI / ID 관리]
                                              │
                                              ▼
                         +-----------------------------------------+
                         |  정책 관리자 (PA: Policy Administrator)  |
                         |   - 세션 자격증명 생성 및 PEP 제어 토큰  |
                         +-----------------------------------------+
                                              │ 제어 평면 (Control Plane)
  ────────────────────────────────────────────┼────────────────────────────────────────────
                                              │ 데이터 평면 (Data Plane)
  +-------------------+              +------------------+              +------------------+
  |  주체 (Subject)   | ──(접근 요청)─>|  정책 집행 지점  | ──(인가 연결)─>|  기업 자원 자산  |
  |  (사용자 / 단말)  |              |  (PEP)           |              |  (Enterprise)    |
  +-------------------+              +------------------+              +------------------+
+-----------------------------------------------------------------------------------------+
```

### 2. ZTA 세션 수립 및 동적 검증 5단계 프로세스

| 단계 | 수행 작업 | 관여 컴포넌트 및 프로토콜 |
|---|---|---|
| 1. 접근 요청 인입 | 사용자가 엔터프라이즈 업무 시스템에 특정 자원 트랜잭션 요청 | 단말 에이전트 → PEP (mTLS 핸드셰이크) |
| 2. 컨텍스트 수집 | 주체 신원(ID/역할), 기기 보안 태세(EDR 무결성), 네트워크 위치 수집 | PEP → PA → PE (컨텍스트 텔레메트리 전달) |
| 3. 정책 평가 (PDP) | 기업 보안 정책, CTI 위협 피드, 사용자 위험 점수를 종합하여 인가 결정 | PE (Trust Engine, OPA 정책 엔진 실행) |
| 4. 동적 통로 개방 | 인가 승인 시 단기 유효 암호화 통로(mTLS 세션) 생성 명령 하달 | PA → PEP (One-time 접근 제어 명령 발행) |
| 5. 지속 모니터링 | 통신 트래픽 패킷 검사 및 실시간 이상 징후 발생 시 세션 즉시 종료 | PEP ──> SIEM/SOAR/UEBA 실시간 피드백 |

## Ⅳ. 경계 기반 보안 vs 제로 트러스트 및 ZTA 3대 구현 모델 비교

### 1. 경계 기반 보안 vs 제로 트러스트 비교

| 비교 항목 | 전통적 경계 기반 보안 (Castle-and-Moat) | 제로 트러스트 보안 (Zero Trust Architecture) |
|---|---|---|
| 기본 가정 | 신뢰할 수 있는 내부망 vs 신뢰할 수 없는 외부망 | 모든 네트워크(사내망/클라우드)를 본질적으로 적대적 환경으로 간주 |
| 접근 제어 방식 | 네트워크 IP 대역 및 포트 기반 정적 ACL | 주체 신원, 기기 무결성, 상황적 컨텍스트 기반 동적 인가 |
| 통제 경계 | 물리적 방화벽, VPN 게이트웨이 | 소프트웨어 정의 마이크로 경계 (워크로드 및 개별 자원 단위) |
| 내부 이동(Lateral) | 내부망 진입 성공 시 전 시스템 자유로운 수평 이동 가능 | 자원 단위 격리로 횡적 이동 원천 차단 (최소 권한 유지) |
| 세션 보증 기간 | 로그인 성공 후 세션 만료 시까지 암묵적 신뢰 유지 | 세션 수립 후에도 트랜잭션 단위로 지속적 신뢰 평가(CARTA) |

### 2. ZTA 3대 핵심 구현 접근법

```text
[ZTA 3대 구현 모델]
  ├── 1. 네트워크 세그멘테이션 기반 ──> 차세대 방화벽(NGFW) 및 SDN 기반 내부 가상 네트워크 격리
  ├── 2. 소프트웨어 정의 경계 (SDP)  ──> Dark Cloud(비공개 IP), SPA(단일 패킷 권한 부여) 기반 은폐
  └── 3. 서비스 메시 (Service Mesh)  ──> Istio/Envoy 기반 mTLS 워크로드 간 상호 인증 및 마이크로 인가
```

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 모든 세션 요청마다 PE/PA를 거쳐 동적 정책을 평가함에 따라 네트워크 지연 시간(Latency) 및 PDP 성능 병목 발생 | PDP 정책 평가 결과를 로컬 PEP에 초단기 암호화 토큰(Micro-ticket) 형태로 캐싱하고 엣지 컴퓨팅 기반 분산 정책 집행 엔진(Edge PEP) 구축 |
| 레거시 메인프레임, 폐쇄망 OT/SCADA 기기, 프린터 등 최신 mTLS 및 에이전트 설치가 불가능한 비관리 장비의 통제 한계 | 인라인 리버스 프록시 게이트웨이를 앞단에 배치하여 외부 통신을 대리 종단하고 네트워크 마이크로세그멘테이션을 통한 가상 패치 및 물리적 망분리 유지 |
| 복잡한 사용자 행동 프로파일링과 상황적 위험 점수 오판으로 인한 정상 업무 차단(오탐) 및 사용자 반발 급증 | 파일럿 단계에서 모니터링 모드(Permissive Mode)로 로그를 축적하여 기준선(Baseline)을 확립하고 단계적 적응형 인가(Step-up MFA) 정책 순차 적용 |

## Ⅵ. 제언

### 1. 제로 트러스트 성숙도 모델 (ZTM) 진화 로드맵

```text
[전통 단계 (Traditional)] ──> [초기 단계 (Advanced)] ──> [최적화 단계 (Optimal)]
- 정적 경계 보안 (VPN)         - 클라우드 ZTNA 도입           - 완전 자동화된 Dynamic Policy
- 패스워드 기반 인증           - 피싱 저항 MFA 적용           - AI/ML 기반 지속적 CARTA 평가
- 대규모 세그먼트             - 앱 단위 마이크로세그멘테이션 - 완전 코드화된 인프라(IaC + PaC)
```

### 2. ZTA 핵심 구성 기술 비교 평가

| 핵심 기술 | 주요 역할 | 구축 난이도 | 보안 효과성 | 주 적용 대상 |
|---|---|---|---|---|
| ZTNA (Zero Trust Network Access) | 원격 VPN 대체, 비인가 자산 은폐 | 중간 | 최상 | 원격 근무자, 외주 협력사 접근 제어 |
| 마이크로세그멘테이션 | 데이터센터/VPC 내부 횡적이동 차단 | 높음 | 최상 | 쿠버네티스 파드, 클라우드 가상머신 |
| Identity 거버넌스 (IGA/IAM) | 중앙 신원 수명주기 및 최소권한 통제 | 높음 | 상 | 전사 임직원 및 서비스 계정 권한 |
| EDR/XDR 단말 무결성 | 접속 단말의 실시간 위협 및 패치 진단 | 중간 | 상 | 업무용 PC, 모바일 기기 |

- 제로 트러스트는 단일 솔루션 구매로 달성할 수 있는 상태가 아니며, 신원, 기기, 네트워크, 워크로드의 전 영역에 걸쳐 점진적이고 지속적인 아키텍처 전환 추진 필수.
