<summary>핵심 용어</summary>

- **제로 트러스트 보안**: 네트워크 위치나 소유권만으로 암묵적 신뢰를 부여하지 않고 자원 접근을 검증하는 보안 접근.
- **ZTA(Zero Trust Architecture)**: 제로 트러스트 원칙을 기업 자원과 접근 흐름에 적용한 아키텍처.
- **PE(Policy Engine)**: 접근 요청을 정책과 상황 정보에 따라 허용·거부 판단하는 논리 구성요소.
- **PA(Policy Administrator)**: 정책 판단을 실행할 접근 경로의 수립·종료를 조정하는 구성요소.
- **PEP(Policy Enforcement Point)**: 주체와 자원 사이의 연결을 허용·감시·종료하는 집행 지점.
- **최소 권한**: 업무에 필요한 자원·행위만 허용하는 원칙.

## 2~4교시 25점 답안

## Ⅰ. 제로 트러스트 보안의 정의와 목적

| 구분 | 내용 |
|---|---|
| 정의 | **제로 트러스트 보안**은 네트워크 위치만으로 신뢰하지 않고 자원 접근마다 주체·기기·맥락을 검증하는 방식 |
| 목적 | 내부·외부 경계를 넘는 비인가 접근과 침해 확산 제한 |

내부망을 폐기한다는 뜻이 아니라 보호 자원에 도달하는 요청을 위치와 무관하게 판단하는 원칙.

## Ⅱ. 정책 판단·집행 구조

```text
주체 → PEP → 보호 자원
         ↑
   PA ← PE의 접근 판단
```

| 구성 | 책임 | 판단·집행 |
|---|---|---|
| PE | 접근 허용 여부 결정 | 정책·신원·기기·위험 |
| PA | 연결 수립·종료 조정 | PE 판단을 PEP에 전달 |
| PEP | 연결 허용·감시·종료 | 실제 자원 접근 집행 |

## Ⅲ. 접근 결정의 입력

```text
접근 요청
  ├─ 주체 신원·역할
  ├─ 기기 상태
  ├─ 대상 자원·행위
  └─ 위협·이상 징후
        ↓
     PE 정책 판단
```

| 정보 | 확인 사항 |
|---|---|
| 신원 | 인증 상태와 업무 권한 |
| 기기 | 관리·패치·보안 상태 |
| 자원 | 데이터 중요도와 요청 행위 |
| 상황 | 위치·시간·위협 정보의 변화 |

인증은 접근 판단의 시작이며 허용 뒤에도 위험 신호에 따라 연결을 재평가.

## Ⅳ. 단계적 도입

```text
중요 자원 식별
    ↓ 접근 경로·주체 파악
PE 정책과 PEP 집행 지점 배치
    ↓ 접근 로그·기기 상태 연결
예외·정책을 반복 조정
```

| 단계 | 산출물 |
|---|---|
| 자원 분류 | 보호 우선순위 |
| 권한 정리 | 주체·행위별 최소 권한 |
| 집행 | 우회 없는 접근 경로 |
| 검증 | 허용·차단·예외 기록 |

## Ⅴ. 한계와 제언

| 한계 | 대응 |
|---|---|
| 도구만 설치하고 자원·권한 목록이 부정확하면 정책 오류 | 핵심 업무 자원과 실제 접근 경로부터 정비 |
| 한 번 인증한 연결을 무기한 신뢰하면 상태 변화 반영 불가 | 세션·기기·위협 변화에 따른 재평가 기준 설정 |
