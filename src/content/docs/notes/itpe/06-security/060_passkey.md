## 지식 로드맵 내 현재 위치

사용자 인증 → 공개키 기반 피싱 저항 인증 → 패스키

## 30초 인출

- **본질**: 패스키는 웹·앱 로그인을 위한 발견형 FIDO 공개키 자격증명.
- **메커니즘**: 서비스가 챌린지 발급 → 인증기가 개인키로 응답 서명 → 서비스가 저장된 공개키·origin·챌린지 검증.
- **구분**: 기기 종속형은 한 기기, 동기화형은 제공자 계정의 보호·복구 체계에 의존.

<details><summary>핵심 용어</summary>

- **패스키** (Passkey): 비밀번호 대신 공개키로 웹·앱 사용자를 인증하는 발견형 자격증명.
- **FIDO(Fast IDentity Online)**: 공개키 기반의 피싱 저항 인증 표준·생태계.
- **WebAuthn(Web Authentication)**: 웹사이트와 인증기 사이 공개키 자격증명의 생성·사용을 위한 W3C API 표준.
- **RP(Relying Party)**: 사용자를 인증하려는 웹서비스 또는 앱.
- **RP ID(Relying Party Identifier)**: 패스키의 사용 범위를 특정 서비스 도메인에 묶는 식별자.
- **CTAP(Client to Authenticator Protocol)**: 클라이언트와 외부 FIDO 인증기 사이 통신 프로토콜.
- **챌린지(Challenge)**: 서비스가 인증 요청마다 생성하는 일회성 데이터로 서명 응답의 재사용을 방지.
- **동기화형 패스키(Synced Passkey)**: 제공자 계정을 통해 여러 기기에서 사용하도록 안전하게 동기화되는 패스키.
- **기기 종속형 패스키(Device-bound Passkey)**: 특정 기기·보안키에 묶여 다른 기기로 동기화되지 않는 패스키.

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **패스키**는 비밀번호 대신 공개키로 웹·앱 사용자를 인증하는 발견형 자격증명. |
| 목적 | 비밀번호 재사용·피싱·검증자 비밀 유출 위험을 줄이고 로그인 절차를 간소화. |

## Ⅱ. 구성요소와 등록 절차

```text
RP 서비스 → 브라우저·OS → 인증기
    │             │          ├─ 사용자 확인(PIN·생체 등)
    │             │          └─ 공개키 자격증명 생성
    │ ← 공개키·응답 ←────────┘
    └─ 챌린지·origin 검증 후 자격증명 등록
```

서비스는 자격증명 정보와 공개키를 보관하며 개인키 자체를 검증용으로 저장하지 않음. 사용자 확인은 인증기 잠금해제·승인 절차이고 생체정보 자체를 서비스에 전송하는 방식과 구별.

## Ⅲ. 인증과 피싱 저항성

```text
RP: 새 챌린지 발급
          ↓
인증기: 사용자 확인 → RP 범위의 개인키로 응답 서명
          ↓
RP: 공개키·서명·챌린지·origin 검증
          ↓
인증 성공 또는 거부
```

| 검증 요소 | 보안 목적 |
|---|---|
| 일회성 챌린지 | 과거 응답 재전송 방지 |
| RP ID·origin | 다른 사이트에서 자격증명 사용 방지 |
| 등록 공개키·서명 | 해당 자격증명 개인키 보유 확인 |
| 사용자 확인 | 기기 잠금해제 등 로컬 승인 확인 |

피싱 저항성은 도메인 연결과 검증 구현에 기반하며 생체인식만으로 얻어지는 성질이 아님.

## Ⅳ. 저장 유형과 도입 위험

| 유형 | 사용 범위 | 운영상 고려 |
|---|---|---|
| 기기 종속형 | 특정 기기·보안키 | 분실·고장 시 복구·대체 자격증명 필요 |
| 동기화형 | 제공자 계정을 거쳐 여러 기기 | 제공자 계정 보호·동기화·복구 경로 검증 |
| 다른 기기 인증 | 별도 기기의 인증기를 근거리 연결 등으로 사용 | 사용자 의도와 클라이언트·서비스 지원 확인 |

| 한계 | 해결 방안 |

| 기기 분실·계정 복구 악용이 계정 탈취 또는 로그인 불가로 이어질 수 있음. | 복수 패스키 등록, 동기화 계정 보호와 복구 시 추가 본인확인·알림을 적용하고 단계적 전환을 검증하는 방안. |
