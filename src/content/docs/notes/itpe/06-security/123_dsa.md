## 지식 로드맵 내 현재 위치

지식 위치: 플랫폼 규제 → 온라인 중개 서비스 책임 → **EU 디지털서비스법(DSA)**

## 30초 인출

- **본질:** EU 디지털 단일 시장 내 온라인 중개 서비스의 불법 콘텐츠 유통 방지, 이용자 기본권 보호, 플랫폼 투명성 확보를 위해 사업자 규모별 차등 의무를 부과하는 법률
- **메커니즘:** 중개 서비스 기본 의무 → 호스팅 불법 콘텐츠 통지·조치(Notice & Action) → 온라인 플랫폼 다크패턴 금지·투명성 보고 → VLOP/VLOSE 시스템 위험 평가 및 외부 감사
- **통찰:** 일률적 사전 필터링은 일반적 모니터링 금지 원칙과 충돌하므로 AI 탐지와 신뢰 플래거 및 인간 검수(Human-in-the-loop)를 결합한 설명 가능한 거버넌스 구현 필수

<details>
<summary>핵심 용어</summary>

- **DSA (Digital Services Act)** : 온라인 불법 콘텐츠 대응 및 플랫폼 책임 강화를 규정한 EU 규정 (EU 2022/2065).
- **Notice and Action** : 불법 콘텐츠 신고 접수 시 신속히 검토하고 조치 여부 및 사유를 통지하는 법정 절차.
- **VLOP / VLOSE** : EU 인구의 10%(4,500만 명) 이상 월간 활성 이용자를 보유한 초대형 플랫폼 및 검색엔진.
- **다크 패턴 (Dark Patterns)** : 이용자의 자유로운 의사결정을 왜곡·방해하여 원치 않는 선택을 유도하는 기만적 UI/UX 설계.

</details>

## 2~4교시 예상문제 (25점)

> EU 디지털서비스법(DSA)의 제정 배경, 4단계 계층적 비례 규제 체계, 통지 및 조치(Notice & Action) 절차를 설명하고, 국내 플랫폼 기업의 글로벌 진출 시 엔지니어링 한계 및 기술적 대응 방안을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 온라인 중개 서비스, 호스팅, 소셜 미디어, 마켓플레이스 등 디지털 플랫폼의 불법 유해 콘텐츠 유통을 억제하고 이용자 기본권을 보장하기 위한 EU의 포괄적 디지털 규제법 |
| 목적 | 안전하고 투명한 온라인 환경을 조성하고, 빅테크의 사회적 시스템 위험을 통제하며, 서비스 규모에 비례한 차등적 법적 책임(Due Diligence) 부과 |

- 기존 전자상거래 지침(e-Commerce Directive 2000/31/EC)의 한계를 극복하고, 온라인 플랫폼의 비대칭적 권력 남용과 허위 조작 정보, 혐오 표현에 대한 법적 규율을 글로벌 표준으로 정립

## Ⅱ. EU DSA의 핵심 입법 및 기술적 특성

| 특성 항목 | 세부 내용 및 기술적 의미 | 엔지니어링 영향 |
|---|---|---|
| 비례적 차등 규제 (Tiered Scope) | 단순 도관부터 초대형 플랫폼(VLOP)까지 서비스 기능과 영향력에 따라 4계층으로 차등화 | 서비스 규모 및 기능별 규제 준수 아키텍처 분리 설계 |
| 사전 일반 감시 의무 배제 | 플랫폼에 모든 사용자 트래픽을 사전에 전수 감시(General Monitoring)할 일반 의무 부과 금지 | 자동 필터링 강제 대신 신고 접수 기반 사후 조치 우선 |
| 알고리즘 투명성 의무화 | 추천 알고리즘의 주요 파라미터를 공개하고, 프로파일링에 기반하지 않은 대안 추천 제공 | 추천 시스템 내 비개인화 랭킹 모델 및 설명 메타데이터 구축 |
| 다크 패턴 원천 금지 | 이용자의 서비스 해지, 쿠키 수락 거부 등을 고의로 어렵게 설계한 기만적 인터페이스 차단 | UI/UX 디자인 시스템의 컴플라이언스 가이드라인 수립 |

- 위반 시 전 세계 연간 매출액의 최대 6%에 달하는 강력한 과징금 및 집행 조치가 수반되는 규제 특성 보유

## Ⅲ. DSA 4단계 규제 프레임워크 및 Notice & Action 프로세스

```text
[EU DSA 계층적 비례 의무 체계 및 통지·조치(Notice & Action) 흐름]

  +---------------------------------------------------------------+
  |  4. 초대형 플랫폼/검색엔진 (VLOP/VLOSE: 이용자 4,500만 이상)     |
  |     - 연례 시스템 위험 평가 및 완화 조치, 독립적 외부 감사     |
  |     - 비프로파일링 추천 옵션 제공, 연구자 데이터 접근권 보장   |
  +---------------------------------------------------------------+
  |  3. 온라인 플랫폼 (SNS, 앱스토어, 전자상거래)                  |
  |     - 신뢰 플래거(Trusted Flaggers) 우선 처리, 내부 불복 절차 |
  |     - 다크 패턴 금지, 미성년자 타겟팅 광고 전면 금지          |
  +---------------------------------------------------------------+
  |  2. 호스팅 서비스 (클라우드, 웹호스팅)                         |
  |     - 불법 콘텐츠 통지 및 조치(Notice & Action), 사유 통지     |
  +---------------------------------------------------------------+
  |  1. 중개 서비스 (ISP, CDN, DNS)                               |
  |     - 법정 접점(Point of Contact) 지정, 투명성 보고서 발행     |
  +---------------------------------------------------------------+

[Notice and Action 엔지니어링 프로세스]
신고 접수(이용자/신뢰플래거) ──> 형식 요건 검증 ──> AI 사전분류 + 인간 검수 ──> 조치 및 사유통지(SOR) ──> 이의신청 처리
```

| 절차 단계 | 핵심 엔지니어링 활동 | 준수 요건 |
|---|---|---|
| 신고 접수 (Notice) | 전용 웹 폼 및 API를 통해 불법 콘텐츠 URL, 정확한 사유, 신고자 정보 수집 | 신고 접수 확인 통지 즉시 자동 발송 |
| 적격성 검토 | 신고 내용의 객관적 증빙 검토 및 회원국 관할 법률 침해 여부 판정 | 고의적 허위·남용 신고 필터링 메커니즘 가동 |
| 조치 및 사유 고지 (SoR) | 콘텐츠 삭제, 계정 정지, 노출 차단 수행 및 투명성 DB에 사유서(Statement of Reasons) 등록 | EU 집행위 DSA 투명성 데이터베이스 연동 |
| 내부 불복 처리 | 이용자가 조치 결정에 이의 제기 시 자동화 툴이 아닌 전문 인력의 재심사 배정 | 최소 6개월 이상 이의신청권 보장 |

## Ⅳ. EU DSA vs EU DMA 비교 분석

| 비교 항목 | 디지털서비스법 (DSA) | 디지털시장법 (DMA) |
|---|---|---|
| 법적 목적 | 이용자 권리 보호, 안전한 콘텐츠 환경, 플랫폼 책임성 확립 | 플랫폼 시장의 공정성 및 독과점 방지, 경쟁 촉진 |
| 주 규제 대상 | 모든 온라인 중개 서비스 (기능 및 규모별 4계층 차등) | 게이트키퍼(Gatekeeper)로 지정된 소수 지배적 빅테크 |
| 핵심 의무 | 불법 콘텐츠 조치, 추천 알고리즘 투명성, 다크패턴 금지 | 자사 우대(Self-preferencing) 금지, 상호운용성 보장, 사이드로딩 허용 |
| 모니터링 방식 | 신뢰 플래거 연계, 시스템 위험 평가, 연례 독립 감사 | 사전적 행위 규제(Ex-ante), 결합 데이터 활용 제한 |
| 최대 과징금 | 전 세계 연간 매출액의 최대 6% | 전 세계 연간 매출액의 최대 10% (반복 시 20%) |
| 발효 시점 | 2024년 2월 전면 시행 (VLOP은 2023년 8월 선행) | 2023년 5월 시행 (2024년 3월 본격 집행) |

## Ⅴ. 글로벌 서비스 적용 시 엔지니어링 한계와 해결 방안

| 한계 | 방안 |
|---|---|
| 대규모 실시간 콘텐츠 환경에서 AI 필터링 오탐(False Positive)으로 합법적 표현물 차단 및 검열 논란 | AI 모델의 불법 판정 임계치(Threshold)를 계층화하고, 신뢰 플래거(Trusted Flaggers) 채널 분리 및 고위험 콘텐츠에 인간 검수(Human-in-the-Loop) 강제 적용 |
| 프로파일링 기반 개인화 추천 금지 옵션 제공 시 추천 품질 저하 및 사용자 이탈 위험 | 비개인화 모드 전환 시 세션 기반(Session-based) 협업 필터링, 최신성 및 인기도 기반 문맥(Contextual) AI 알고리즘 파이프라인 병렬 구축 |
| 추천 알고리즘 설명 의무화 및 외부 감사 대응 시 딥러닝 블랙박스로 인한 의사결정 파라미터 입증 불가 | 설명 가능한 AI(XAI: SHAP, LIME)를 적용하여 추천 랭킹 결정에 영향을 미친 주요 가중치를 역추적 로깅하고, 감사용 파이프라인 아티팩트 보관 |
| EU 집행위 투명성 데이터베이스(DSA Transparency DB)로의 수백만 건 사유서(SoR) 실시간 전송 시 API 병목 | 비동기 메시지 큐(Kafka/RabbitMQ) 기반 전송 버퍼링 아키텍처를 구축하고 배치 전송 및 재시도(Retry) 서킷 브레이커 구현 |

## Ⅵ. DSA 컴플라이언스 충족을 위한 플랫폼 아키텍처 제언

```text
[글로벌 플랫폼의 DSA 컴플라이언스 통합 아키텍처]

  ┌─────────────────────────────────────────────────────────────┐
  │                 UI / UX 레이어 (Dark Pattern-Free)           │
  │   - 원클릭 쿠키 거부   - 간소화된 회원탈퇴   - 투명한 약관   │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
  ┌──────────────────────────────┴──────────────────────────────┐
  │              알고리즘 및 콘텐츠 거버넌스 레이어              │
  │   ┌────────────────────────┐    ┌────────────────────────┐  │
  │   │  추천 시스템 파이프라인 │    │  Notice & Action 엔진  │  │
  │   │  [개인화] vs [비프로파일]│    │  (AI 탐지 + 인간 검수) │  │
  │   └────────────────────────┘    └────────────────────────┘  │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
  ┌──────────────────────────────┴──────────────────────────────┐
  │                   컴플라이언스 데이터 레이어                 │
  │   - DSA SoR 자동 연동 API   - XAI 감사 로그 불변 저장소      │
  └─────────────────────────────────────────────────────────────┘
```

| 영역 | 핵심 구축 과제 | 성공 지표 |
|---|---|---|
| 콘텐츠 대응 | 신뢰 플래거 신고 전용 Fast-track API 및 사유서 자동 생성 연동 | 불법 콘텐츠 조치 소요 시간 < 24시간, SoR 등록률 100% |
| 추천 거버넌스 | 이용자가 클릭 한 번으로 비프로파일링 추천 모드로 전환 가능한 UI 구현 | 비프로파일링 모드 응답 지연 < 100ms, XAI 감사 증적 확보 |
| 투명성 보고 | 시스템적 위험 평가 보고서 및 반기별 투명성 메트릭 자동 추출 | 연례 독립 감사(Independent Audit) 무결점 통과 |
