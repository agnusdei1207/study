## 연관 키워드

- Mirai 봇넷, 변종, Satori, Okiru, Echobot, Mozi
- DDoS, C2, 싱크홀링, P2P, DHT, ECDSA
- IoT 봇넷, UPnP 취약점, 펌웨어 취약점, 이기종 아키텍처, NDR

## Ⅰ. Mirai 봇넷의 개요

- 핵심 요약 : 소스코드 공개 이후 **IoT** (Internet of Things) 기기를 감염시키는 봇넷이 변종을 거듭하며 중앙 차단이 어려운 구조로 진화한 현상.
- 개념 : 2016년 **Mirai** 악성코드의 소스코드가 공개된 뒤 여러 행위자가 파생시킨 IoT 봇넷 계열. 감염 대상 CPU 아키텍처의 확대, 새로운 **RCE** (Remote Code Execution) 취약점 결합, **P2P** (Peer-to-Peer) 기반 명령 체계 도입이 특징이다.
- 배경 및 필요성 : 소스코드 공개로 제작 진입 장벽이 낮아졌고, 공격자들은 기본 계정 대입에 더해 라우터, 카메라, NAS(Network-Attached Storage) 같은 장비의 웹 취약점을 결합하여 감염 범위를 넓혔다.
- 주요 목적 : 중앙 **C2** (Command and Control) 서버 차단을 피하고 기업 네트워크 장비까지 공격 표면을 넓혀, **DDoS** (Distributed Denial of Service) 공격과 악성코드 유포 인프라를 유지하는 것.

## Ⅱ. Mirai 봇넷의 특징 및 장점

- 핵심 요약 : 취약점 결합과 분산 명령 체계가 감염의 지속성과 차단 저항성으로 이어지는 구조.

1. 다중 침투 경로 : 기본 계정 대입에서 웹 취약점 악용으로 확장 → 방화벽과 패스워드 정책만으로는 막기 어려워짐.
2. 모듈형 취약점 결합 : 여러 장비군의 취약점(**UPnP** (Universal Plug and Play) 포함)을 모듈처럼 묶어 사용 → 한 기기군의 패치가 끝나도 다른 기기군으로 감염이 이어짐.
3. 탈중앙 명령 체계 : **DHT** (Distributed Hash Table) 기반 P2P 통신으로 명령을 전달 → 중앙 서버가 없어 차단 지점이 사라짐.
4. 명령 검증 : 봇마스터가 서명한 명령만 실행하도록 **ECDSA** (Elliptic Curve Digital Signature Algorithm) 서명을 검증 → 다른 공격자가 봇넷을 가로채기 어려움.

## Ⅲ. Mirai 봇넷의 구조 (흐름)

- 핵심 요약 : 중앙 C2 구조에서 P2P 구조로 옮겨 가며 차단 난도가 높아진 세대별 진화 흐름.

```text
[ 1세대: 오리지널 Mirai (2016) ]

Telnet 기본 계정 대입 → 중앙 C2 서버
   ↓ 소스코드 공개 후 변종 확산
[ 2세대: 취약점 결합형 (2017~2019) ]

UPnP 제로데이 취약점 결합
   ↓ 탈중앙화 시도
[ 3세대: P2P형 (Mozi, 2019~) ]

웹 취약점 + 약한 계정 → P2P 노드 간 명령 공유
```

```text
[ P2P 봇넷의 명령 전달 ]

봇 노드 A ↔ 봇 노드 B ↔ 봇 노드 C
   (DHT 기반 명령 전파)
   ↓
서명 검증 통과 명령만 실행
```

- 2세대 변종은 **Satori** (UPnP 취약점 결합형 웜), **Okiru** (ARC 아키텍처 감염 지원), **Echobot** (다수 RCE 취약점 모듈 결합)으로 분화하였다.
- 구조 흐름의 핵심은 중앙 서버 의존을 없애는 방향으로 진화했다는 점이며, 이 때문에 차단 전략도 서버 중심에서 노드 중심으로 바뀌어야 한다.

## Ⅳ. Mirai 봇넷 변종의 비교

- 핵심 요약 : 세대가 내려갈수록 중앙 차단은 어려워지고, 침투 수단은 장비 취약점 중심으로 바뀜.

| 비교 항목 | 오리지널 Mirai | Satori 변종 | Mozi 봇넷 |
| --- | --- | --- | --- |
| 등장 시기 | 2016년 | 2017년 | 2019년 이후 |
| 주요 침투 수단 | Telnet 기본 계정 대입 | 라우터 UPnP 취약점 (CVE-2017-17215) | 웹 취약점과 약한 계정 복합 |
| C2 구조 | 중앙 집중형 | 중앙 집중형 | 탈중앙 P2P (DHT) |
| 차단 난도 | 낮음 (C2 싱크홀링 가능) | 중간 (C2 주소 차단) | 높음 (P2P 노드 전체 차단 필요) |
| 주 대상 장비 | 영상 녹화기, 감시 카메라, 공유기 | 가정용 라우터 | 라우터, NAS, IoT 장비 |

- 선택 기준 : 중앙 서버가 있는 봇넷은 서버 주소 차단과 싱크홀링이 효과적이고, P2P 봇넷은 노드 단위 탐지와 트래픽 분석이 필요하다.

## Ⅴ. Mirai 봇넷의 한계와 방안

- 핵심 요약 : 중앙 차단 불가, 장비 펌웨어 악용, 이기종 분석 난도를 노드 분석, 패치 관리, 샌드박스로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| P2P 기반 C2의 싱크홀링 불가 | 중앙 주소가 없고 감염 노드가 명령을 나눠 전달 | DHT 트래픽 패턴 분석으로 악성 노드 식별 | 비정상 DHT 트래픽 발생 단말 수 |
| 기업 네트워크 장비의 펌웨어 취약점 | 방화벽과 VPN(Virtual Private Network) 장비가 내부 침투 거점으로 악용 | 외곽 노출 장비 점검과 벤더 권고 즉시 패치 | 노출 장비 패치 소요 시간 |
| 이기종 프로세서 분석 난도 | 여러 프로세서 아키텍처용 바이너리가 분석 도구를 가로막음 | 다중 아키텍처를 에뮬레이션하는 자동 샌드박스 | 샘플 분석 소요 시간 |

## Ⅵ. Mirai 봇넷에 대한 기술사적 제언

- 핵심 요약 : 기기 출하 단계의 보안 기준과 네트워크 단위 탐지를 함께 세워 봇넷의 확산 경로를 조기에 끊는 방향.

1. 출하 단계 보안 인증 : 기본 패스워드 제거, 보안 부팅, 서명된 펌웨어 업데이트를 갖춘 IoT 기기만 유통되도록 KISA(Korea Internet & Security Agency)의 IoT 보안인증 기준을 실효성 있게 운영해야 한다.
2. 통신사 단위 트래픽 차단 공조 : 대규모 볼륨 공격이 발생하면 통신사 백본에서 공격 패킷의 특성을 공유해 경계에서 흡수하는 협력 체계를 평소에 마련해 두는 것이 바람직하다.
3. 내부망 비정상 트래픽 탐지 : 업무망과 데이터센터 내부에서 P2P 프로토콜이 비정상적으로 쓰이는 단말을 **NDR** (Network Detection and Response) 체계로 탐지하고 즉시 격리하는 절차를 둔다.

## Ⅶ. 결론

- 핵심 요약 : Mirai 계열은 소스 공개 이후 중앙 차단을 피하는 P2P 봇넷으로 진화해, 네트워크 단위의 단일 차단이 어려워진 위협.
- 시사점 : 봇넷 대응은 서버 차단에서 기기 출하 기준과 노드 단위 탐지로 무게중심을 옮겨야 한다.
