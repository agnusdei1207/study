## 연관 키워드

- 에이전틱 AI(Agentic AI), 과도한 대리 권한(Excessive Agency), 도구 호출(Tool Calling), 간접 프롬프트 주입(Indirect Prompt Injection)
- HITL(Human-in-the-Loop), 정책 집행 지점(PEP, Policy Enforcement Point), 샌드박스(Sandbox), 서킷 브레이커(Circuit Breaker)
- 승인 피로(Approval Fatigue), 의사결정 추적성(Auditability), 인공지능 경영시스템 표준

## Ⅰ. 에이전틱 AI 보안 감독 (Agentic AI Security Supervision)의 개요

- 핵심 요약 : 자율적으로 계획하고 도구를 실행하는 에이전트의 행동을 전 주기에 걸쳐 감시하고 통제하는 보안 체계.
- 개념 : 텍스트 응답을 넘어 자율적인 추론, **계획** (Planning), **도구 호출** (Tool Calling), 멀티 에이전트 협업으로 작업을 완수하는 **에이전틱 AI** (Agentic AI) 시스템의 폭주, 권한 오남용, 적대적 탈취를 감시하고 통제하는 보안 아키텍처.
- 배경 및 필요성 : LLM(Large Language Model)이 운영체제 명령을 실행하고 금융 거래와 클라우드 설정을 바꾸게 되면서, 환각이나 간접 프롬프트 주입 한 번으로 인프라가 손상되는 **과도한 대리 권한** (Excessive Agency) 위험이 커짐.
- 주요 목적 : 행동 단위의 실시간 가드레일 집행, 비인가 도구 실행 차단, 인간 승인 체계 보장, **의사결정 추적성** (Auditability) 확보.

## Ⅱ. 에이전틱 AI 보안 감독 (Agentic AI Security Supervision)의 특징 및 장점

- 핵심 요약 : 계획, 도구 호출, 사후 감사의 각 단계에 보안 검증기를 두어, 행동이 실행되기 전에 차단할 수 있는 구조.

1. 다계층 행동 감독 : 계획, 도구 호출, 실행 결과 단계마다 독립된 검증기를 배치하고, 도구 호출 지점에는 정책 집행 지점(PEP, Policy Enforcement Point)을 둠 → 한 계층이 뚫려도 다음 계층에서 차단.
2. **HITL** (Human-in-the-Loop) 승인 : 읽기 전용 작업은 자율 허용하고, 쓰기·삭제·외부 전송은 사람이 승인 → 비가역 피해 방지.
3. 실행 샌드박싱 : 에이전트가 호출하는 코드를 호스트와 격리된 경량 WebAssembly(Wasm) 또는 임시 컨테이너에서만 실행 → 백엔드 시스템 손상 범위 축소.
4. 사고 과정 감사 : 명령 실행의 근거와 추론 요약을 감사 로그로 남김 → 책임 소재 입증.

```text
[ 에이전트 행동 감독 흐름 ]

사용자 요청
        ↓
에이전트가 행동 계획 수립
        ↓
계획 검증 (목표 적합성, 우회 경로)
        ↓
도구 호출 시 정책 집행 점검 통과
```

## Ⅲ. 에이전틱 AI 보안 감독 (Agentic AI Security Supervision)의 구성 요소 및 흐름

- 핵심 요약 : 쓰기나 외부 전송 같은 고위험 도구 호출만 사람 승인으로 넘기고, 나머지는 격리 실행과 기록으로 처리하는 것이 핵심.

```text
[ 도구 호출 판정 흐름 ]

도구 호출 요청
        ↓
읽기 전용 작업 ──> 자동 허용
고위험 작업 ─────> HITL 관리자 승인
        ↓
격리 샌드박스에서 실행
        ↓
실행 결과와 근거를 감사 로그에 기록
```

| 비교 항목 | 전통적 챗봇 | RAG(Retrieval-Augmented Generation) 기반 질의응답 | 에이전틱 AI |
| --- | --- | --- | --- |
| 동작 모델 | 단순 질의와 응답 | 검색 문서 기반 생성 | 목표 수립, 계획, 도구 실행 |
| 환경 영향력 | 화면 출력에 국한 | 화면 출력에 국한 | API(Application Programming Interface) 호출, 파일 수정 등 실제 행동 |
| 핵심 위협 | 유해 발언, 탈옥 | 데이터 오염, 검색 문서 프롬프트 주입 | 과도한 권한 남용, 무한 실행 |
| 필요 통제 | 입출력 필터링 | 벡터 데이터베이스 접근제어, 출처 검증 | 실시간 행동 감독, HITL, 샌드박스 |

- 에이전틱 AI는 말하는 AI에서 행동하는 AI로 진화했으므로, 보안도 텍스트 필터링에서 자율 행동의 실행 통제와 거버넌스로 전환되어야 함.

## Ⅳ. 에이전틱 AI 보안 감독 (Agentic AI Security Supervision)의 비교 분석

- 핵심 요약 : 사후 로그 감사, 사람 승인, 정책 기반 자동 차단은 통제 시점과 비용이 달라, 행동의 위험도에 따라 조합해야 함.

| 비교 축 | 사후 감사 중심 | HITL 승인 중심 | 정책 기반 자동 차단 |
| --- | --- | --- | --- |
| 통제 시점 | 실행 이후 | 실행 직전 | 실행 직전 |
| 장점 | 구현 부담이 낮음 | 비가역 작업 방지에 효과적 | 사람 개입 없이 빠른 처리 |
| 한계 | 피해를 되돌리기 어려움 | 승인 요청이 많으면 형식화 | 정책 밖 상황에 취약 |
| 적합 작업 | 읽기 전용, 저위험 작업 | 쓰기, 삭제, 외부 전송 | 명백한 금지 패턴 |

## Ⅴ. 에이전틱 AI 보안 감독 (Agentic AI Security Supervision)의 한계와 방안

- 핵심 요약 : 에이전트 간 감염 전파, 실행 루프와 비용 폭주, 승인 피로가 주요 한계이며 격리와 한도 설정, 위험도 기반 승인으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 에이전트 간 감염 전파 | 한 에이전트가 간접 프롬프트 주입에 감염되면 협업 에이전트에 왜곡된 지시가 전달 | 에이전트 간 메시지에 상호 인증과 무결성 검증을 적용하고 최소 권한 격리 | 비정상 메시지 차단 건수 |
| 실행 루프와 비용 폭주 | 오류 복구를 반복하며 같은 API를 과도 호출 → 클라우드 비용 급증 (Denial of Wallet) | 최대 실행 단계, 토큰 한도, 비용 상한을 강제하는 서킷 브레이커 | 한도 도달 횟수 |
| 승인 피로 | 승인 요청이 잦아 관리자가 내용을 확인하지 않고 승인 | 위험도 기반 적응형 승인으로 일상 작업은 자동 처리하고 변칙 작업만 사람에게 전달 | 승인 요청 대비 반려율 |

## Ⅵ. 에이전틱 AI 보안 감독 (Agentic AI Security Supervision)에 대한 기술사적 제언

- 핵심 요약 : 감독 역할을 독립시키고, 에이전트 전용 권한과 국제 표준 기반 감사 체계를 갖추는 방향이 필요함.

1. 업무를 수행하는 에이전트와 분리된 감독 에이전트를 두어 모든 행동 계획을 교차 검증하게 하는 구조를 설계하는 것이 필요함.
2. 에이전트마다 별도의 서비스 계정을 부여하고, 작업에 필요한 최소 API 권한만 임시로 발급하는 체계를 기본으로 삼는 것이 바람직함.
3. ISO(International Organization for Standardization)/IEC(International Electrotechnical Commission) 42001 인공지능 경영시스템 표준에 맞추어 행동 이력과 의사결정 근거를 감사 가능한 형태로 보관하는 파이프라인을 구축하는 것이 필요함.

## Ⅶ. 결론

- 핵심 요약 : 에이전틱 AI 보안은 입력 텍스트를 거르는 일에서 자율 행동의 실행을 통제하는 일로 바뀜.
- 시사점 : 최소 권한, 고위험 행동의 사람 승인, 추적 가능한 기록이 함께 갖춰질 때 에이전트 도입의 위험이 관리 가능한 수준이 됨.
