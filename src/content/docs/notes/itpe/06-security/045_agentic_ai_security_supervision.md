## 지식 로드맵 내 현재 위치

## 30초 인출

- **본질**: 에이전틱 AI 보안 감독은 모델이 고른 도구와 실행 권한을 별도 정책으로 통제하는 보안 설계.
- **메커니즘**: 요청된 행위의 신원·권한·영향을 실행 경계에서 검사하고, 고영향 작업은 사람 승인과 감사기록으로 통제.

<details><summary>핵심 용어</summary>

- **에이전틱 AI 보안 감독**: 목표를 수행하는 AI 에이전트의 도구·데이터 접근과 실제 실행을 정책·권한·승인으로 통제하는 설계.
- **AI(Artificial Intelligence, 인공지능)**: 데이터와 알고리즘으로 인식·추론·생성 등 지능적 작업을 수행하는 기술.
- **HITL(Human-in-the-Loop, 사람 개입 통제)**: 사람이 고영향 작업의 실행 전 내용을 확인하고 승인하는 통제 방식.
- **PEP(Policy Enforcement Point, 정책 집행 지점)**: 요청이 실제 자원에 도달하기 전에 인가 정책을 적용하는 실행 경계.
- **과도한 에이전시(Excessive Agency)**: 에이전트에 불필요한 기능·권한·자율성을 부여해 오작동이나 조작된 지시에 따른 피해를 키우는 취약 상태.
- **간접 프롬프트 인젝션(Indirect Prompt Injection)**: 외부 문서·검색 결과 등에 숨은 지시가 에이전트 동작에 영향을 주도록 유도하는 공격.

### Ⅱ. 실행 전 감독 흐름

```text
사용자 목표와 에이전트 도구 요청
                 ↓
신원·자원·행위별 권한 검사
          ┌──────┴──────┐
       허용 가능       고영향 작업
          ↓                ↓
최소 권한으로 실행    사람 검토·승인
          └──────┬──────┘
                 ↓
           실행 기록·검토
```

사람 승인은 모든 동작이 아니라 삭제·외부 전송 등 사전에 정한 고영향 작업에 적용.

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **에이전틱 AI 보안 감독**은 에이전트의 도구·데이터 접근과 실행을 정책·권한·승인으로 통제하는 보안 설계. |
| 목적 | 자율 작업의 이점을 유지하면서 비인가 접근과 고영향 오작동을 제한. |

## Ⅱ. 주요 위협

| 위협 | 작동 원인 | 보안 영향 |
|---|---|---|
| 과도한 권한·기능 | 작업에 필요 없는 도구나 넓은 권한을 에이전트에 제공 | 정보 조회·변경·삭제 범위 확대 |
| 간접 프롬프트 인젝션 | 검색 자료·문서의 비신뢰 지시가 에이전트 계획에 개입 | 의도하지 않은 도구 호출 가능성 |
| 과도한 자율 실행 | 고영향 실행 전 독립 검증·승인 부재 | 외부 전송·삭제·거래의 피해 확대 |

## Ⅲ. 실행 경계 설계

```text
사용자 ── 업무 요청 ──> AI 에이전트
                          │ 도구 호출 제안
                          ▼
             정책 집행 지점(PEP)
          신원·사용자 권한·도구·행위 검사
                  ┌───────┴───────┐
            허용된 저위험          고영향 행위
                  │             사람 승인 필요
                  └───────┬───────┘
                          ▼
               격리된 최소권한 도구
                          │ 실행 결과
                          └──────> 에이전트
          모든 요청·승인·실행은 감사기록에 보존
```

정책 검사는 모델의 계획 문장에만 의존하지 않고 도구 호출과 데이터 접근이 실제 수행되는 경계에서 집행.

## Ⅳ. 위험별 감독 통제

| 통제 지점 | 적용 방안 |
|---|---|
| 신원·권한 | 사용자와 에이전트의 신원을 구분하고 사용자 맥락의 최소 권한 적용 |
| 도구 | 허용된 기능만 노출하고 범용 셸·무제한 URL 호출 등 개방형 기능 제한 |
| 데이터 | 입력 출처와 신뢰 수준 표시, 비신뢰 지시와 정책 지시의 경계 유지 |
| 고영향 작업 | 삭제·외부 게시·자금 이동 등에 실행 전 사람 승인과 결과 확인 적용 |
| 감사·복구 | 호출 인자·승인자·실행 결과를 기록하고 취소·복구 경로 마련 |

## Ⅴ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 에이전트 신원과 실행 위임 권한의 기준이 아직 정착 중이며, 모델 응답만 검사하면 실제 도구 행위를 통제하지 못할 수 있음. | 조직의 기존 신원·인가 체계 안에 에이전트별 신원, 위임 범위, 수명, 감사 주체를 등록하고, 도구 실행 경계의 정책 집행으로 연결하는 시범 설계를 제안. |
