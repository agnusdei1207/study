## 지식 로드맵 내 현재 위치

인공지능 보안 → 도구를 사용하는 자율형 시스템 → 에이전틱 AI 보안 감독

## 30초 인출

- **본질:** LLM 에이전트가 외부 도구, API, 시스템 셸을 자율 호출할 때 발생 가능한 권한 오남용과 지시 오염을 제어하기 위한 실행 경계 거버넌스 및 런타임 감독 체계
- **메커니즘:** 입력 프롬프트 검증(Guardrails) → 계획 단계 위험 평가(PDP) → 도구 호출 가로채기(PEP) → 고위험 행위 사람 승인(HITL) → 격리 샌드박스 실행 및 감사 로깅
- 통찰: 모델의 자율적 도구 호출 권한을 신뢰하지 않고 실행 경계에 독립적인 PEP 정책 프록시와 비가역적 고위험 작업에 대한 HITL 승인 게이트를 결합한 심층 방어 체계 구축 필수

<details><summary>핵심 용어</summary>

- **에이전틱 AI 보안 감독:** 목표 달성을 위해 도구·데이터를 자율 활용하는 AI 에이전트의 권한, 실행, 상호작용을 정책과 런타임 가드레일로 통제하는 기술.
- **과도한 에이전시(Excessive Agency):** 불필요하게 넓은 도구 권한이나 자율성을 부여받아 프롬프트 인젝션 시 시스템 파괴나 정보 유출을 초래하는 취약 상태.
- **간접 프롬프트 인젝션(Indirect Prompt Injection):** 웹페이지, 이메일, RAG 문서 등 외부 데이터에 악의적 프롬프트를 은닉하여 에이전트의 실행 계획을 변조하는 공격.
- **HITL(Human-in-the-Loop):** 데이터 삭제, 금융 거래, 외부 전송 등 고영향 작업을 에이전트가 단독 수행하지 못하도록 사람의 사전 승인을 강제하는 절차.
- **PEP 인터셉터(Policy Enforcement Point Interceptor):** 모델과 실제 API/시스템 사이에 위치하여 권한 및 파라미터를 강제 검증하는 보안 프록시.

</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 자율적 추론과 도구 호출(Function Calling)을 수행하는 AI 에이전트의 실행 경계에 독립적 정책 엔진과 인가 통제를 배치하여 비인가 행위 및 오작동을 차단하는 런타임 보안 감독 체계 |
| 목적 | 자율 에이전트의 업무 자동화 효익을 보장하면서 과도한 권한 남용, 악의적 지시 오염, 데이터 파괴 등 고위험 비가역적 사고 방지 |

## Ⅱ. 에이전틱 AI 보안 감독의 주요 특징

| 특징 | 세부 내용 | 구현 요소 |
|---|---|---|
| 실행 경계 기반 인가 | 모델 내부의 추론에 의존하지 않고 외부 도구 호출 접점(PEP)에서 물리적 권한 강제 집행 | API Gateway, 사이드카 프록시 |
| 최소 권한 및 임시 권한 | 에이전트에게 상시 관리자 권한을 부여하지 않고 세션별 작업 목적에 국한된 단기 토큰 발급 | OIDC 단기 토큰, JIT(Just-in-Time) 권한 |
| 고영향 작업 인간 개입 | 데이터 삭제, 외부 전송, 대량 변경 등 비가역적 작업은 사람의 승인 없이는 실행 차단 | HITL 게이트웨이, 다중 서명 워크플로우 |
| 컨텍스트 인지형 감사 | 모델의 입력 프롬프트, 사고 과정(CoT), 도구 호출 인자, 실행 결과를 연계하여 전수 불변 로깅 | WORM 스토리지, 인과관계 추적 로그 |

## Ⅲ. 에이전틱 AI 보안 감독 아키텍처 및 통제 프로세스

```text
[ 사용자 / 외부 데이터 ]
         │ (업무 요청 / RAG 컨텍스트)
         ▼
┌──────────────────┐
│ 입력 가드레일    │ ─── 간접 프롬프트 인젝션 필터링, 탈옥 탐지
└────────┬─────────┘
         ▼
┌──────────────────┐
│ AI 에이전트 (LLM)│ ─── ReAct 기반 추론 및 도구 호출(Tool Call) 생성
└────────┬─────────┘
         │ 도구 실행 요청 (JSON Payload)
         ▼
┌──────────────────────────────────────────────────────────┐
│ 정책 집행 프록시 (PEP Interceptor)                       │
│  - 에이전트 신원 및 작업 컨텍스트 검증                   │
│  - 파라미터 유효성 및 SQLi/명령어 삽입 정적 분석        │
│  - 위험도 판정: [ 저위험 ] ───▶ [ 즉시 실행 ]            │
│                 [ 고위험 ] ───▶ [ HITL 사람 승인 요청 ]  │
└────────────────────────┬─────────────────────────────────┘
                         ▼
┌──────────────────────────────────────────────────────────┐
│ 실행 계층: 격리된 도구 실행 샌드박스 (gVisor / Firecracker)│
│  - 백엔드 DB / 사내 API / 이메일 발송 / 셸 스크립트 실행  │
└────────────────────────┬─────────────────────────────────┘
                         ▼
┌──────────────────────────────────────────────────────────┐
│ 출력 가드레일 & 통합 감사 로깅 (SIEM / SOAR 연계)        │
└──────────────────────────────────────────────────────────┘
```

| 단계 | 통제 활동 | 핵심 메커니즘 |
|---|---|---|
| 1. 입력 가드레일 | 외부 비신뢰 데이터 내 시스템 프롬프트 조작 및 인젝션 패턴 사전 차단 | 프롬프트 정규화, 유해성 벡터 유사도 분석 |
| 2. 계획 및 추론 | ReAct 루프 내에서 작업 단계별 권한 요구사항 및 도구 매핑 정의 | 추론 단계별 정책 적합성 사전 체크 |
| 3. PEP 인터셉트 | 도구 호출 시 전달되는 파라미터, 타깃 URL, 쿼리 구문의 무결성 검증 | 스키마 밸리데이션, 정적 필터링 규칙 |
| 4. HITL 승인 게이트 | 데이터 변경, 전송 등 임계치 초과 행위에 대해 관리자 콘솔 결재 승인 | 웹훅 기반 관리자 알림, 인라인 인터럽트 |
| 5. 격리 실행 및 감사 | 컨테이너 격리 샌드박스 내 도구 구동 및 전체 호출 체인 불변 기록 | 마이크로VM 격리, 체인 오브 커스터디 로그 |

## Ⅳ. 에이전틱 AI 보안 위협 및 방어 통제 비교

| 구분 | 과도한 에이전시 (Excessive Agency) | 간접 프롬프트 인젝션 (Indirect Prompt Injection) | 악의적 도구 중독 (Tool Poisoning) |
|---|---|---|---|
| 공격 메커니즘 | 에이전트에 불필요하게 광범위한 쓰기/삭제 권한 부여 시 취약점 악용 | 외부 문서에 은닉된 악성 지시문이 모델의 원래 목표를 변조하여 강제 도구 실행 | MCP 또는 서드파티 도구 명세에 악성 코드를 주입하여 호출 탈취 |
| 위험 영향 | 사내 데이터 무단 삭제, 비인가 금융 결제 | 내부 기밀 데이터의 외부 C2 서버 유출 | 원격 코드 실행(RCE), 공급망 침해 |
| 방어 기술 | 최소 권한 도구 분할, JIT 세션 토큰 | 데이터-지시문 격리 파싱, 입력 가드레일 | 서드파티 도구 레지스트리 서명 검증 |
| 인간 개입 (HITL) | 필수 (비가역적 데이터 변경 작업) | 선택 (비정상 외부 전송 탐지 시 강제) | 필수 (신규 도구 등록 및 권한 승인 시) |

## Ⅴ. 에이전틱 AI 보안 감독의 한계와 방안

| 한계 | 방안 |
|---|---|
| LLM 모델의 확률적·비결정적 특성으로 인해 정적 룰셋 기반 PEP를 우회하는 난독화된 악성 호출 발생 | 의미론적(Semantic) 의도 분석 엔진과 기계학습 기반 동적 이상 탐지 모델을 PEP에 결합하여 파라미터 변칙 탐지 강화 |
| 다중 에이전트(Multi-agent) 협업 환경에서 상호 위임 호출 시 신원 연쇄 증명 불가 및 책임 추적성 상실 | SPIFFE/SPIRE 기반 에이전트 간 암호학적 신원 토큰(SVID) 및 호출 체인 서명(Token Chaining) 아키텍처 도입 |
| 과도한 HITL 승인 요청으로 인한 운영자 승인 피로(Approval Fatigue) 및 무비판적 일괄 승인 위험 | 비즈니스 영향도와 위험 점수를 정량화하여 저위험 반복 작업은 정책 기반 자율 처리하고 고위험 작업만 선별 승인 |

## Ⅵ. 제언

```text
[ 단일 AI 모델 추론 ]                 [ 에이전틱 AI 보안 거버넌스 ]
단순 텍스트 생성 ────┐               ┌── 입력/출력 듀얼 가드레일 배치
직접 API 연동 ──────┼─→ [ 통제 상실 ] ─┼── 독립 PEP 기반 도구 가로채기
전체 권한 상시 부여 ──┘               └── HITL 승인 게이트 및 마이크로 샌드박스
```

| 평가 영역 | 통제 부재 에이전트 | 보안 감독 적용 에이전트 | 향후 발전 방향 |
|---|---|---|---|
| 신뢰성 및 안전성 | 조작된 입력에 취약 | 정책 기반 경계 방어로 안전 | 자기 반성(Self-Reflection) 기반 자율 오류 복구 |
| 규제 준수성 | EU AI Act 고위험 요건 위반 | 감사 추적 및 HITL로 컴플라이언스 충족 | AI 거버넌스 자동화(Governance as Code) 연동 |
| 시스템 확장성 | 장애 발생 시 전체 전파 | 마이크로VM 격리로 장애 국소화 | 에이전트 전용 전송 계층 보안(mTLS) 표준화 |

에이전틱 AI의 도입은 생산성 혁신의 기회인 동시에 공격 표면의 폭발적 확장을 의미하므로, 실행 경계에서 엄격한 인가를 수행하는 제로 트러스트 기반 보안 감독 아키텍처 구축이 필수적 과제.
