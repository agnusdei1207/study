## 1교시 예상문제 (10점)

> 클라우드 책임공유모델과 IaaS·PaaS·SaaS의 책임 차이를 설명하시오. (예상)

---

## 1교시 10점 답안

### 1. 정의·목적

정의: 책임공유모델은 클라우드 보안 책임을 CSP와 고객 사이에 서비스 범위별로 나누는 모델이다.
목적: 책임 경계를 명확히 해 설정 오류와 통제 누락으로 인한 보안사고를 줄인다.

### 2. 서비스별 책임

| 서비스 | CSP가 관리하는 범위 | 고객이 관리하는 범위 |
|---|---|---|
| IaaS | 물리 인프라·가상화 | OS·애플리케이션·데이터와 권한 설정 |
| PaaS | 인프라·운영 플랫폼 | 애플리케이션·데이터와 권한 설정 |
| SaaS | 서비스 운영 기반 | 데이터·계정 및 접근 설정 |

제안: 서비스별 책임표를 만들고 클라우드 설정을 지속 점검한다.

## 2~4교시 25점 답안
```text
[클라우드 보안] ◀━━ 머리: Ⅶ 내 의견 (책임공유모델 경계 명확화 + CSPM/CWPP 기반 멀티 클라우드 통합 가시성 확보)
 ┃
 ┣━ Ⅰ 개요 ───── 온프레미스에서 멀티/하이브리드 클라우드로 전환 → 물리적 통제권 상실 및 CSP-이용자 간 책임공유 리스크 부각
 ┣━ Ⅱ 특징 ───── 책임공유모델(Shared Responsibility) · 다중 테넌시(Multi-Tenancy) 위험 · 동적 리소스 생성 · 컴플라이언스(CSAP)
 ┣━ Ⅲ 구조 ───── 클라우드 보안 아키텍처(IaaS/PaaS/SaaS) · 인증 규격(CSAP, ISO/IEC 27017, ISO/IEC 27018) · 통제 도구(CSPM/CWPP/CNAPP)
 ┣━ Ⅳ 흐름 ───── ① 클라우드 위험 식별 → ② 책임 모델 매핑 → ③ 보안 설정 감사(IaC 스캔) → ④ 런타임 위협 탐지
 ┣━ Ⅴ 비교 ───── IaaS(인프라만 CSP, OS/앱/데이터는 고객 책임) vs PaaS(플랫폼까지 CSP) vs SaaS(데이터/접근권한만 고객 책임)
 ┗━ Ⅵ 실무 ───── S3 버킷 비인가 공개 설정 오류(Misconfiguration) / CSP 락인 및 종속성 리스크 / CSAP 유형·등급별 인증기준 대응
```
- 필수 키워드: 책임공유모델 · CSAP · ISO/IEC 27017 · 설정 오류(Misconfiguration) · CSPM · CWPP
- 기출: 130회 4교시 3번 `클라우드 도입 시 보안 고려사항` → Ⅰ·Ⅲ·Ⅵ / 129회 4교시 6번 `CSP(클라우드 서비스 제공자) 리스크 관리` → Ⅱ·Ⅵ

## 한 줄 본질
- 제3자 인프라(CSP)에 데이터와 시스템을 위탁 운영하는 환경 → 물리적 통제권 부재와 이용자의 잘못된 설정으로 데이터 유출 위험 발생 → 인프라 민첩성 및 확장성 획득 / 설정 오류 및 책임 소재 불명확 리스크

## 핵심 그림
```text
[클라우드 서비스 모델별 책임공유모델 (Shared Responsibility Model)]

   계층             온프레미스        IaaS              PaaS              SaaS
 ┌──────────────┐   ┌─────────┐   ┌─────────┐       ┌─────────┐       ┌─────────┐
 │ 데이터/IAM   │   │ 고객    │   │ 고객    │       │ 고객    │       │ 고객    │
 ├──────────────┤   ├─────────┤   ├─────────┤       ├─────────┤       ├─────────┤
 │ 애플리케이션 │   │ 고객    │   │ 고객    │       │ 고객    │       │   CSP   │
 ├──────────────┤   ├─────────┤   ├─────────┤       ├─────────┤       ├─────────┤
 │ 미들웨어/런타임│ │ 고객    │   │ 고객    │       │   CSP   │       │   CSP   │
 ├──────────────┤   ├─────────┤   ├─────────┤       ├─────────┤       ├─────────┤
 │ 운영체제(OS) │   │ 고객    │   │ 고객    │       │   CSP   │       │   CSP   │
 ├──────────────┤   ├─────────┤   ├─────────┤       ├─────────┤       ├─────────┤
 │ 가상화/물리인프라││ 고객    │   │   CSP   │       │   CSP   │       │   CSP   │
 └──────────────┘   └─────────┘   └─────────┘       └─────────┘       └─────────┘
```

## 핵심 용어
- 책임공유모델(Shared Responsibility Model): 보안의 책임이 CSP(클라우드 자체의 보안: 물리 인프라, 하이퍼바이저)와 고객(클라우드 내부의 보안: 데이터, IAM, OS 패치)으로 분할되는 모델
- CSPM(Cloud Security Posture Management): 클라우드 인프라의 설정 오류, 컴플라이언스 위반, 공개 버킷 노출 등을 자동으로 스캔하고 시정 조치를 권고하는 보안 솔루션

## 핵심 통찰
- 클라우드 환경에서는 설정 오류와 과도한 IAM 권한이 주요 위험이 될 수 있으므로, 자산·권한·구성 상태를 지속 점검함
- CSAP는 클라우드 서비스 보안인증 제도이며, 신청 유형과 등급별 적용 요건은 최신 안내서와 고시에서 확인함
- ISO/IEC 27017은 클라우드 특화 보안 통제(가상머신 격리, CSP 해지 시 자산 반환 및 삭제 등)를 제공하여 전통적 27001의 사각지대를 보완함

## 이웃 토픽과 구분
- CSAP vs ISO/IEC 27017: CSAP = 국내 클라우드 서비스 보안인증 제도 / ISO/IEC 27017 = 클라우드 서비스 보안 통제를 다루는 국제 표준

## 문제·원인·대책
- 사례: 130회 기출 개발자가 AWS S3 스토리지 버킷을 실수로 'Public Read'로 설정하여 수백만 건 고객 DB가 전 세계에 노출된 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 스토리지 버킷 공개 설정 오류로 데이터 유출 | 수작업 콘솔 설정 실수 및 정책 점검 부재 | CSPM 솔루션 도입 및 AWS Account 레벨의 'Public Access Block' 강제 | 설정 오류 실시간 자동 탐지 및 자동 교정(Auto-remediation) |
| 개발자 GitHub에 하드코딩된 클라우드 IAM 액세스 키 유출 | 소스코드 형상관리 업로드 전 시크릿 검사 미흡 | Git 사전 커밋 훅(TruffleHog) 및 AWS IAM 단기 임시 자격증명(STS) 사용 | 시크릿 키 유출 사전 차단 및 유출 시 즉시 만료 |

## 이렇게 출제된다
- 제130회 4교시 3번: "최근 다수의 기업들이 클라우드 서비스를 도입하면서 다양한 보안 문제가 대두되고 있다. IT 담당자 입장에서 클라우드 서비스 도입 시 고려해야 할 보안 요소를 설명하시오." → 요구 포인트: Ⅱ 책임공유모델 + Ⅲ 통제 도구(CSPM) + Ⅵ 실무 점검 항목
- 제129회 4교시 6번: "조직이 클라우드컴퓨팅 서비스를 이용하고자 할 경우, 클라우드서비스 제공자(CSP)에 대한 리스크를 관리하여야 한다. CSP 리스크 유형과 관리 방안을 설명하시오." → 요구 포인트: Ⅱ CSP 종속성 및 장애 리스크 + Ⅵ SLA 및 계약상 통제권 확보

## 내 의견
- [CSP를 향한 맹목적 보안 위임의 착각] "AWS/Azure를 쓰니 인프라 보안은 끝났다"고 방심하여 OS 보안 패치와 IAM 권한 관리를 방치하다가 단일 인스턴스 침해로 전체 VPC가 탈취되는 참사 만연 → 나라면: CI/CD 파이프라인에 코드형 인프라(IaC) 정적 검사(Checkov)를 결속하여 테라폼 코드 작성 단계부터 보안 결함을 차단하고, 런타임에는 CWPP 에이전트를 통해 컨테이너 내부 이상 행위를 실시간 감시
