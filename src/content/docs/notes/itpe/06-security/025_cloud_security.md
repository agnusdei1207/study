## 지식 로드맵 내 현재 위치

보안 아키텍처 → 클라우드 보안 → 책임공유 모델, CSAP 인증 및 CNAPP 거버넌스

## 30초 인출

- **본질:** 클라우드 서비스 제공자(CSP)와 이용자 간의 책임공유 모델(Shared Responsibility Model)에 기반하여 인프라, 플랫폼, 데이터 및 신원을 통합 보호하는 체계
- **메커니즘:** IaaS·PaaS·SaaS 계층별 책임 명확화 → CSPM/CWPP/CIEM 통합 CNAPP 적용 → CSAP 및 ISO/IEC 27017 컴플라이언스 준수
- 통찰: IaC 형상 드리프트로 인한 S3 공개 오설정과 과도한 IAM 권한 탈취를 방지하기 위해 GitOps 기반 정책 차단과 CIEM 유휴 권한 자동 회수 필수

<details>
<summary>핵심 용어</summary>

- **책임공유 모델 (Shared Responsibility Model):** 클라우드 인프라 자체의 보안(Security OF the Cloud)은 CSP가, 클라우드 내부 데이터와 설정(Security IN the Cloud)은 고객이 분담하는 기본 원칙
- **CSAP (Cloud Security Assurance Program):** 공공기관에 안전성이 검증된 민간 클라우드를 도입하기 위해 KISA가 운영하는 클라우드 보안인증제도 (상·중·하 3등급 체계)
- **ISO/IEC 27017:** 클라우드 서비스 제공자와 고객 양측의 정보보호 통제 및 책임 구분을 정의한 국제 표준 정보보호 지침
- **CSPM (Cloud Security Posture Management):** 멀티클라우드 환경의 잘못된 설정(Misconfiguration), 컴플라이언스 위반을 지속해서 모니터링하고 자동 교정하는 솔루션
- **CIEM (Cloud Infrastructure Entitlement Management):** 클라우드 환경의 과도한 권한(Over-privileged IAM)을 분석하고 최소 권한 원칙에 따라 회수하는 솔루션
</details>

## 2~4교시 예상문제 (25점)

> 클라우드 서비스 모델(IaaS, PaaS, SaaS)별 책임공유 모델(Shared Responsibility Model)의 보안 경계를 설명하고, 주요 CSP 리스크(오설정, IAM 과다 권한)와 이를 해결하기 위한 CNAPP(CSPM, CWPP, CIEM) 아키텍처 및 국내 CSAP 3등급 개편 방안을 기술하시오. (예상·25점)

---
## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **클라우드 보안(Cloud Security)** 은 클라우드 컴퓨팅 환경에서 제공되는 가상화 인프라, 플랫폼, 애플리케이션 및 데이터를 내외부 사이버 위협과 오설정으로부터 보호하기 위해 CSP와 고객이 협력하여 구현하는 종합 보안 프레임워크 |
| 목적 | 데이터 유출 사고 예방, 서비스 가용성 보장, 클라우드 특유의 오설정(Misconfiguration) 제거 및 글로벌/국내 컴플라이언스 준수 |

물리적 경계가 사라지고 API 기반으로 자원이 프로비저닝되는 클라우드 환경 특성상 온프레미스와 전혀 다른 신원(Identity) 및 코드 중심의 보안 통제 요구.

## Ⅱ. 클라우드 보안의 특징 및 책임공유 모델

```text
[서비스 모델별 보안 책임공유 모델(Shared Responsibility Model) 비교]

 계층 (Layers)                IaaS             PaaS             SaaS
+-----------------------+---------------+----------------+----------------+
| 데이터 및 접근 권한   |   고객 책임   |   고객 책임    |   고객 책임    |
+-----------------------+---------------+----------------+----------------+
| 애플리케이션          |   고객 책임   |   고객 책임    |    CSP 책임    |
+-----------------------+---------------+----------------+----------------+
| 런타임 및 미들웨어    |   고객 책임   |    CSP 책임    |    CSP 책임    |
+-----------------------+---------------+----------------+----------------+
| 운영체제 (Guest OS)   |   고객 책임   |    CSP 책임    |    CSP 책임    |
+-----------------------+---------------+----------------+----------------+
| 가상화 및 하이퍼바이저|    CSP 책임   |    CSP 책임    |    CSP 책임    |
+-----------------------+---------------+----------------+----------------+
| 물리 서버, 스토리지   |    CSP 책임   |    CSP 책임    |    CSP 책임    |
+-----------------------+---------------+----------------+----------------+
| 물리 데이터센터 시설  |    CSP 책임   |    CSP 책임    |    CSP 책임    |
+-----------------------+---------------+----------------+----------------+
```

| 구분 | CSP 책임 영역 (Security OF the Cloud) | 이용자(고객) 책임 영역 (Security IN the Cloud) |
|---|---|---|
| **IaaS** | 물리 DC 시설, 하드웨어, 네트워크 인프라, 하이퍼바이저 | 게스트 OS 패치, 방화벽(보안그룹), IAM 계정, 데이터 암호화 |
| **PaaS** | 인프라 + OS 패치 + 미들웨어 + DB 엔진 유지보수 | 배포된 애플리케이션 코드, API 연동, 데이터 접근 권한 관리 |
| **SaaS** | 애플리케이션 소프트웨어 전체 인프라 및 운영 | 사용자 계정 관리(MFA), 접근 인가, 업로드 데이터 관리 |

## Ⅲ. 클라우드 네이티브 보안 아키텍처 (CNAPP 메커니즘)

```text
[CNAPP: Cloud-Native Application Protection Platform 통합 구조]

 +---------------------------------------------------------------+
 |            [CNAPP 통합 대시보드 및 리스크 상관분석]           |
 +-------------------------------+-------------------------------+
                                 |
         +-----------------------+-----------------------+
         |                       |                       |
 +-------v-------+       +-------v-------+       +-------v-------+
 |     CSPM      |       |     CWPP      |       |     CIEM      |
 | 클라우드 보안 |       | 클라우드 워크 |       | 클라우드 신원 |
 | 형상 관리     |       | 로드 보호     |       | 권한 관리     |
 | - 오설정 스캔 |       | - 컨테이너취약|       | - 유휴권한회수|
 | - 컴플라이언스|       | - 런타임 eBPF |       | - STS 단기토큰|
 +---------------+       +---------------+       +---------------+
```

### 1. CNAPP 3대 핵심 컴포넌트 동작

| 컴포넌트 | 핵심 기능 | 엔지니어링 수행 내용 |
|---|---|---|
| **CSPM** (형상 관리) | 퍼블릭 클라우드 설정 오류 및 컴플라이언스 위반 실시간 탐지 | AWS CIS 벤치마크 기반 S3 버킷 공개, 미암호화 볼륨, 비인가 포트(22, 3389) 개방 즉시 탐지 |
| **CWPP** (워크로드 보호) | VM, 컨테이너, 서버리스 함수의 런타임 위협 방어 | 컨테이너 이미지 취약점(CVE) 스캔, 쿠버네티스 파드 런타임 eBPF 비정상 시스템 콜 탐지 |
| **CIEM** (권한 관리) | 사용자 및 머신(서비스 계정)의 과도한 권한 정제 | 할당된 권한 대비 실제 사용 권한(Audit Log)을 대조하여 와일드카드(`*`) 권한 최소화 자동 회수 |

## Ⅳ. 클라우드 보안 컴플라이언스 및 표준 비교

| 비교 항목 | 국내 CSAP 인증 | ISO/IEC 27017 | 미국 FedRAMP |
|---|---|---|---|
| **주관 기관** | 과학기술정보통신부 / KISA | ISO / IEC 국제표준화기구 | 미국 연방 총무청(GSA) |
| **적용 대상** | 공공기관에 공급하는 민간 클라우드 | 전 세계 CSP 및 클라우드 이용 기업 | 미국 연방정부 공급 클라우드 서비스 |
| **등급 체계** | **상·중·하 3단계 등급제**<br>(상: 기밀, 중: 비공개, 하: 개인정보 미포함) | 단일 표준 가이드라인 | Low, Moderate, High 3단계 |
| **망분리 요건** | 상/중: 물리적 망분리<br>하: 논리적 망분리 허용 | 논리적 격리 가이드라인 제공 | 논리적/물리적 다계층 격리 통제 |
| **평가 초점** | 국내 공공 데이터 주권 및 물리적 보안 | 제공자와 고객 간의 책임 정의 | NIST SP 800-53 기반 엄격한 통제 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **IaC 형상 드리프트(Drift)로 인한 스토리지 및 포트 비인가 공개**<br>개발자가 콘솔에서 임시로 방화벽 포트나 S3 버킷을 전체 공개(`0.0.0.0/0`)한 후 원복하지 않아 데이터 대량 유출 사고 발생 | **GitOps 기반 CI/CD 파이프라인 정책 차단 및 CSPM 자동 롤백**<br>Terraform 배포 전 Checkov/Tfsec을 통해 소스코드 레벨에서 오설정을 사전 차단(Shift-Left)하고, 런타임 CSPM이 콘솔 수동 변경(Drift) 감지 시 5분 내 원상태로 자동 격리·롤백하는 Auto-Remediation 구현 |
| **단일 IAM 자격증명(Access Key) 유출 시 멀티클라우드 전역 장악**<br>GitHub 등에 하드코딩된 영구 자격증명(Long-term Key)이 노출되어 공격자가 백도어 생성, 랜섬웨어 암호화, 가상화폐 채굴 인스턴스 대량 생성 | **CIEM 기반 OIDC 연동 및 단기 임시 토큰(STS) 강제화**<br>영구 Access Key 생성을 전면 금지하고 GitHub Actions 및 외부 시스템과 클라우드 간 OIDC(OpenID Connect) 페더레이션을 구축하여 1시간 유효의 STS 임시 자격증명만 발급받도록 제한 |

## Ⅵ. 제언

```text
[클라우드 전 생애주기 보안 거버넌스 구현 모델]

 +--------------------+     +---------------------+     +--------------------+
 | 1. 코드 보안       | --> | 2. 인프라 배포      | --> | 3. 런타임 보호     |
 | IaC 보안 스캔      |     | CSPM 형상 검증      |     | CWPP / CIEM 모니터 |
 | (Checkov / Trivy)  |     | (CSAP 기준 준수)    |     | (실시간 봇 및 침해)|
 +--------------------+     +---------------------+     +--------------------+
```

| 추진 단계 | 핵심 엔지니어링 조치 | 기대 효과 |
|---|---|---|
| **1단계: 가시성 확보** | 전사 멀티클라우드 자산 CSPM 전수 연결 | 사각지대(Shadow Cloud) 및 오설정 100% 식별 |
| **2단계: 신원 최소화** | CIEM 도입 및 OIDC 단기 자격증명 전환 | 크리덴셜 탈취로 인한 피해 반경 원천 차단 |
| **3단계: 워크로드 보호** | 쿠버네티스 eBPF 기반 CWPP 도입 | 컨테이너 탈출(Container Escape) 제로데이 실시간 차단 |

클라우드 보안은 단일 방화벽 설치 방식에서 탈피하여, 개발 단계(IaC)부터 배포 및 런타임까지 연속적으로 통제하는 통합 CNAPP 플랫폼 구축 권장.
