## 연관 키워드

- 파일 슬랙(File Slack), RAM 슬랙(RAM Slack), 드라이브 슬랙(Drive Slack), 볼륨 슬랙(Volume Slack)
- 클러스터, 섹터, 파일 시스템, 디지털 포렌식, 안티 포렌식, 데이터 은닉, 와이핑, TRIM

## Ⅰ. 파일슬랙(File Slack)의 개요

- 핵심 요약 : 파일 크기와 할당 단위의 차이로 생기는 미사용 잔여 공간이며, 과거 데이터가 남아 포렌식 증거원이 되는 영역.
- 개념 : 파일 시스템(FAT, NTFS, EXT4 등)이 파일을 저장할 때, 실제 데이터 크기와 고정 할당 단위인 섹터와 클러스터 사이에 남는 **파일 슬랙** (File Slack) 공간.
- 배경 및 필요성 : 운영체제는 입출력 효율을 위해 디스크를 섹터와 클러스터 단위로 할당하므로, 파일 끝에서 할당 블록 끝까지 빈 공간이 필연적으로 생기며, 여기에 이전에 지워진 데이터가 남을 수 있음.
- 주요 목적 : **디지털 포렌식** (Digital Forensics) 수사에서 삭제되었거나 은닉된 파편, 암호 키, 악성코드 조각을 찾는 증거 수집 영역으로 활용.

## Ⅱ. 파일슬랙(File Slack)의 특징 및 장점

- 핵심 요약 : 고정 블록 할당이라는 원리가 잔여 공간을 만들고, 그 공간이 삭제 데이터를 보존하여 포렌식 가치로 이어지는 구조.

1. 고정 단위 할당 : 섹터(512B)와 클러스터 단위로만 저장 → 파일 끝과 블록 끝 사이에 빈 공간이 항상 발생.
2. 이전 데이터 잔존 : 새 파일이 덮어쓰지 않은 구간에 과거 파일 파편이 그대로 남음 → 삭제된 증거를 복원할 여지 확보.
3. 메모리 흔적 구분 : 섹터 단위 잔여 공간과 클러스터 단위 잔여 공간을 나누어 보면 기록 출처를 구분할 수 있음 → 분석 범위를 좁힘.

## Ⅲ. 파일슬랙(File Slack)의 구조 (흐름)

- 핵심 요약 : 파일 슬랙은 섹터 단위의 RAM 슬랙과 클러스터 단위의 드라이브 슬랙으로 나뉘며, 파티션 단위의 볼륨 슬랙이 추가로 존재.

```text
[ 클러스터 1개 = 4,096B (섹터 8개) ]

 섹터 1~2 : 실제 데이터 1,024B
 섹터 3   : 데이터 276B + RAM 슬랙 236B
 섹터 4~8 : 드라이브 슬랙 2,560B
            (이전 삭제 파일 잔존 가능)

 파일 슬랙 합계 = 236B + 2,560B = 2,796B
```

```text
[ 잔여 공간의 위치 구분 ]

 파일 끝 ~ 섹터 끝         : RAM 슬랙
 섹터 끝 ~ 클러스터 끝     : 드라이브 슬랙
 파티션 끝 ~ 볼륨 끝       : 볼륨 슬랙
```

- **RAM 슬랙** (RAM Slack) : 마지막 데이터가 있는 섹터의 끝까지 남는 공간. 구형 OS는 메모리 내용이 그대로 기록되는 사례가 있었으나, 현대 OS는 대부분 0으로 채움.
- **드라이브 슬랙** (Drive Slack) : 데이터 섹터 다음부터 클러스터 끝까지 남는 공간. 같은 클러스터를 쓰다 삭제된 이전 파일의 원본 파편이 남을 수 있어 포렌식의 핵심 대상.
- **볼륨 슬랙** (Volume Slack) : 파티션 크기가 클러스터 단위로 나누어 떨어지지 않아 남는 잉여 섹터 공간.
- **데이터 은닉** (Data Hiding) : 안티 포렌식 공격자가 드라이브 슬랙에 악성코드나 기밀 문서를 숨겨 탐색기와 백신 검사를 피하는 기법.

## Ⅳ. 파일슬랙(File Slack)과 유사 영역의 비교

- 핵심 요약 : 세 영역은 위치와 크기가 다르며, 포렌식 가치는 드라이브 슬랙이 가장 높고 RAM 슬랙은 낮음.

| 비교 항목 | RAM 슬랙 | 드라이브 슬랙 | 볼륨 슬랙 |
| --- | --- | --- | --- |
| 위치 범위 | 파일 끝 ~ 섹터(512B) 끝 | 데이터 섹터 다음 ~ 클러스터 끝 | 파티션 끝 ~ 볼륨 끝 |
| 기록 데이터 | 현대 OS는 0 패딩, 구형은 메모리 잔여 | 이전에 삭제된 파일의 원본 파편 | 포맷 이전의 원시 잔여 데이터 |
| 포렌식 가치 | 낮음 | 매우 높음 (삭제 문서 복원) | 높음 (은닉 영역 조사) |
| 은닉 가능성 | 크기가 작아 은닉 제약 | 은닉 도구로 데이터 숨김 빈발 | 숨겨진 파티션, 부트킷 은닉 가능 |

- 선택 기준 : 삭제 파일의 복원이 목적이면 드라이브 슬랙을, 은닉 정황 조사가 목적이면 볼륨 슬랙까지 함께 수집하는 방식으로 범위를 정함.

## Ⅴ. 파일슬랙(File Slack)의 한계와 방안

- 핵심 요약 : SSD 자동 소거, 와이핑에 의한 인멸, 대용량 디스크의 분석 부담이 증거 확보를 어렵게 하므로 수집 절차와 우선순위로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| SSD의 TRIM에 의한 자동 소거 | 파일 삭제 시 컨트롤러가 블록을 정리하여 복원 불능 가능 | 전원을 즉시 차단하고 저수준 덤프 도구로 수집 | 수집 전 전원 차단 여부 |
| 와이핑 도구에 의한 인멸 | 슬랙 공간을 0 또는 난수로 덮어써 흔적 제거 | 인위적 와이핑 흔적 자체를 증거로 채증 | 와이핑 흔적 탐지 건수 |
| 테라바이트급 디스크의 분석 지연 | 수백만 개 슬랙 영역의 전수 카빙에 수일 소요 | MACB(Modified, Accessed, Changed, Birth) 시간으로 사고 시점 파일을 우선 수집 | 우선 수집 대상 처리 시간 |

## Ⅵ. 파일슬랙(File Slack)에 대한 기술사적 제언

- 핵심 요약 : 증거 수집은 물리 이미징으로 시작하고, 기업은 폐기 단계의 슬랙 와이핑과 은닉 탐지를 정책으로 관리해야 함.

1. 증거 수집 단계에서는 파일 복사가 아니라 디스크 섹터를 1:1로 복제하는 물리 이미징을 기본으로 삼아 슬랙 영역을 보존해야 한다.
2. 퇴사자 PC 반납이나 불용 장비 매각 전에 파일 시스템 메타데이터와 함께 슬랙 및 비할당 영역을 와이핑하는 절차를 폐기 정책에 포함시켜야 한다. 이때 미국 국방부(DoD, Department of Defense)의 5220.22-M 같은 공인 와이핑 지침을 기준으로 삼는 것이 바람직하다.
3. 파일의 실제 크기와 파일 시스템 메타데이터에 기록된 할당 크기가 어긋나는 항목을 자동 비교하는 점검 스크립트를 상시 운영하여, 슬랙에 숨은 이상 파일을 조기에 찾아야 한다.

## Ⅶ. 결론

- 핵심 요약 : 파일 슬랙은 파일 시스템의 고정 할당 구조가 만드는 필연적 잔여 공간이면서 삭제 증거와 은닉 정황을 함께 담는 포렌식 영역.
- 수집 절차와 폐기 정책을 함께 설계할 때 이 영역의 증거 가치가 실제 수사에서 살아남음.
