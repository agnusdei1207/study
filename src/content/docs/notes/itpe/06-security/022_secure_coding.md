<details><summary>핵심 용어</summary>

- **보안 약점(Weakness) vs 보안 취약점(Vulnerability)**: 보안 약점(CWE) = 소프트웨어 버그나 결함 자체 / 보안 취약점(CVE) = 보안 약점이 실제 공격에 악용될 수 있는 상태
- **정적 응용프로그램 보안 테스트(SAST)**: 컴파일 또는 실행 없이 소스코드의 구문 트리(AST)와 데이터 흐름(Taint Analysis)을 추적해 결함을 찾는 도구

</details>

## 30초 인출

- 본질: 시큐어 코딩은 개발 단계에서 소프트웨어의 보안약점을 줄이는 방법이다.
- 메커니즘: 코딩 규칙과 정적·동적 진단으로 결함을 찾아 수정해 배포 전 위험을 낮춘다.

## 1교시 10점 답안

### 1. 정의·목적

| 항목 | 답안 |
|---|---|
| 정의 | 시큐어 코딩은 개발 단계에서 보안약점을 줄이도록 안전한 코딩 규칙과 진단을 적용하는 방법이다. |
| 목적 | 운영 단계에 취약점이 넘어가는 것을 줄여 수정 부담과 공격 가능성을 낮춘다. |

### 2. 진단 분야

| 구분 | 주요 점검 내용 |
|---|---|
| 입력 데이터 검증·표현 | SQL 삽입, XSS, 경로 조작 방지 |
| 보안 기능·시간 및 상태 | 인증·암호화와 경쟁 조건 점검 |
| 오류 처리·코드 오류 | 예외 정보 노출과 결함 점검 |
| 캡슐화·API 악용 | 접근 제한과 취약 API 사용 점검 |

제안: 코딩 규칙과 SAST를 개발 파이프라인에 적용하고 발견된 결함을 수정한 뒤 빌드한다.

## 2~4교시 25점 답안


### Ⅰ. 보안약점 진단 분야
| 소프트웨어 보안약점 분야 | 예시 |
|---|---|
| 입력 데이터 검증·표현 | SQL 인젝션, XSS, 경로 조작 |
| 보안 기능 | 취약한 암호화, 하드코딩한 암호 |
| 시간·상태 | 경쟁 조건, TOCTOU |
| 에러 처리 | 상세 스택 추적 노출 |
| 코드 오류 | 널 포인터 역참조, 자원 해제 누락 |
| 캡슐화 | 잘못된 접근 지정자, 디버그 코드 |
| API 오용 | 안전하지 않은 표준 함수 사용 |

### Ⅱ. 개발 과정에 적용하는 원칙

| 원칙 | 개발 통제 |
|---|---|
| 조기 발견 | 설계·구현 단계에서 약점을 찾아 배포 이후 수정 부담과 운영 위험을 줄인다. |
| 반복 검사 | 코드 변경 때 정적 분석과 검토를 실행하고, 심각한 발견은 병합 전에 해결한다. |
| 생성 코드 검토 | 자동 생성 코드도 입력 검증·권한·비밀정보 취급을 검토한다. |

### Ⅲ. 시큐어 코딩과 WAF 비교

| 구분 | 시큐어 코딩 | WAF |
|---|---|---|
| 작동 위치 | 설계·소스 코드 | 애플리케이션 앞단의 트래픽 |
| 역할 | 코드 결함을 줄임 | 공격 요청을 탐지·차단하는 보완 통제 |

### Ⅳ. 대표 약점과 통제

| 문제 | 원인 | 통제 방향 |
|---|---|---|
| SQL 인젝션 | 사용자 입력을 쿼리 문자열에 직접 결합 | 파라미터화 쿼리와 안전한 ORM 사용을 검토한다. |
| 크로스사이트 스크립팅(XSS) | 신뢰하지 않는 입력을 문맥에 맞게 처리하지 않음 | 입력 검증과 출력 인코딩을 적용한다. |
### Ⅴ. 기술사적 제언

| 문제 | 해결 방안 |
|---|---|
| 배포 직전 한 번만 진단하면 수정 시간이 부족하고 발견 사항이 누락될 수 있다. | IDE·코드 저장소에 정적 분석과 동료 검토를 통합하고 심각도에 따라 병합 조건을 설정한다. |
