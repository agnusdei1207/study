## 30초 인출

- **본질:** **시큐어 코딩**은 개발 과정에 보안 요구와 안전한 구현 원칙을 적용해 소프트웨어 약점을 줄이는 방법
- **메커니즘:** 요구·설계 반영 → 안전한 구현·검토 → 정적·동적 시험 → 결함 수정·재검증
- **적용:** 자동화 진단을 코드 검토·시험과 결합하고, 발견 결과를 확인해 수정

<details>
<summary>핵심 용어</summary>

- **시큐어 코딩:** 개발 과정에서 보안 요구·코딩 규칙·검토·시험을 적용해 소프트웨어의 보안 약점을 줄이는 활동
- **보안 약점(weakness):** 제품이나 코드에 존재하는 결함 성격으로, 조건에 따라 취약성의 원인이 될 수 있는 요소
- **취약점(vulnerability):** 공격자가 악용할 수 있는 보안 결함이나 조건
- **CVE (Common Vulnerabilities and Exposures):** 공개된 취약점에 부여하는 식별자 체계로, 보안 약점 분류 자체와는 다른 개념
- **SAST (Static Application Security Testing):** 프로그램 실행 없이 소스·바이트코드 등을 분석해 잠재 결함을 찾는 시험
- **DAST (Dynamic Application Security Testing):** 실행 중인 애플리케이션에 입력·요청을 보내 외부 관점의 결함을 찾는 시험
- **SCA (Software Composition Analysis):** 외부 구성요소의 버전·라이선스·취약점 정보를 분석하는 활동

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **시큐어 코딩**은 개발 과정에 보안 요구와 안전한 구현 원칙을 적용해 소프트웨어 약점을 줄이는 방법 |
| 목적 | 배포 전에 악용 가능한 결함을 발견·개선해 운영 위험과 수정 부담을 낮추는 것 |

시큐어 코딩은 특정 도구의 도입이 아니라 요구사항부터 검증·운영까지 보안을 통합하는 개발 활동.

## Ⅱ. 보안약점 분야

| 분야 | 점검 예 |
|---|---|
| 입력 데이터 검증·표현 | SQL 삽입, 경로 조작, 출력 인코딩 누락 |
| 보안 기능 | 인증·인가·암호처리 오류, 하드코딩 자격증명 |
| 시간·상태 | 경쟁 조건, TOCTOU |
| 오류 처리 | 예외·진단정보의 과다 노출 |
| 코드 품질 | 널 처리·자원관리 등 구현 결함 |
| 캡슐화 | 민감정보·내부 상태의 부적절한 노출 |
| API 오용 | 위험한 함수·인터페이스의 부적절한 사용 |

## Ⅲ. 생애주기 적용

| 단계 | 보안활동 | 산출·확인 |
|---|---|---|
| 요구·설계 | 자산·위협·보안 요구 식별 | 요구사항·위협모델 |
| 구현 | 안전한 코딩 기준·동료 검토 | 코드·검토 결과 |
| 검증 | SAST·DAST·SCA·보안시험 | 확인된 결함·위험도 |
| 배포·운영 | 조치 확인·예외 승인·변경 관리 | 수정·재시험·추적 기록 |

## Ⅳ. 진단방식과 활용

| 방식 | 분석 관점 | 적용상 유의점 |
|---|---|---|
| SAST | 실행 전 코드·프로그램 구조 | 오탐·미탐 가능, 데이터흐름·프레임워크 맥락 확인 |
| DAST | 실행 중 애플리케이션의 외부 응답 | 시험환경·인증 상태·요청 범위에 따라 탐지 한계 |
| SCA | 외부 라이브러리·구성요소 | 직접 의존성과 전이 의존성, 사용 여부 확인 |
| 코드검토 | 로직·권한·업무 맥락 | 자동화 진단으로 찾기 어려운 설계 결함 보완 |

```text
도구·검토 결과
      ↓
재현·영향 확인
      ↓
우선순위·조치 담당 결정
      ↓
수정 → 재시험 → 예외·잔여위험 기록
```

## Ⅴ. 한계와 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 자동 진단 결과에 오탐·미탐이 있어 도구만으로 안전성을 판정하기 어려움 | 위험도·재현성 검토와 코드리뷰·동적시험을 결합하고 수정 후 재시험 |
| 개발 말기에 결함이 집중 발견되면 수정·일정 부담이 커짐 | 코드 저장소와 빌드 절차에 단계별 검증을 배치하고 심각도 기준을 사전 합의 |
