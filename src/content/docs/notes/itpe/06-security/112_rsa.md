## 연관 키워드

- RSA(Rivest-Shamir-Adleman), 공개키 암호, 개인키, 모듈러스, 소인수분해 문제
- RSAES-OAEP, RSASSA-PSS, PKCS#1, 블라인딩(Blinding), 중국인의 나머지 정리(CRT)
- 블라이헨바허 공격, 패딩 오라클, 부채널 공격, ML-KEM, 암호 민첩성

## Ⅰ. RSA 공개키 암호의 개요

- 핵심 요약 : 큰 합성수의 소인수분해가 어렵다는 계산 난제를 바탕으로 기밀성과 전자서명을 함께 제공하는 공개키 암호.
- 개념 : 두 큰 소수의 곱인 합성수의 **소인수분해** (Integer Factorization) 난이도에 기반해 암호화와 전자서명을 구현하는 비대칭 암호 알고리즘 (**RSA**(Rivest-Shamir-Adleman)).
- 배경 및 필요성 : 대칭키는 키를 미리 공유해야 하는 난제가 있었으므로, 공개키와 개인키를 분리해 안전한 키 교환과 인증서 기반 신뢰 체계를 세울 필요가 있었음.
- 주요 목적 : 키 사전 공유 문제를 해결하고, 공개키 인증서를 통해 전자상거래와 **PKI** (Public Key Infrastructure)의 신뢰 체계를 세우는 것.

## Ⅱ. RSA 공개키 암호의 특징 및 장점

- 핵심 요약 : 공개키와 개인키의 분리가 키 배포 편의와 부인방지 가능성이라는 장점으로 이어지는 구조.

1. 키 분리 : 공개키는 누구에게나 배포하고 개인키는 소유자만 보관 → 키 사전 공유 없이 기밀 통신 가능.
2. 전자서명 : 개인키로 서명하고 공개키로 검증 → 제3자 검증과 부인방지 제공.
3. 표준 성숙도 : 수십 년간 검토된 RSAES-OAEP, RSASSA-PSS 체계 → 인증서와 프로토콜 전반에 널리 채택.

## Ⅲ. RSA 공개키 암호의 구조 (흐름)

- 핵심 요약 : 키 생성 후 암호화와 서명이 각각 공개키와 개인키의 지수 연산으로 나뉘는 구조.
- **OAEP** (Optimal Asymmetric Encryption Padding) : 무작위 시드와 해시를 결합해 암호화 전에 평문을 인코딩하는 패딩 방식.
- **PSS** (Probabilistic Signature Scheme) : 매 서명마다 무작위 Salt를 결합해 서명값이 달라지도록 하는 서명 인코딩 방식.

```text
[ 1. 키 생성 ]

서로 다른 큰 소수 p, q 선택
   ↓
n = p × q, 공개 지수 e (통상 65537)
   ↓
개인 지수 d: e·d ≡ 1 (mod φ(n))
   ↓
공개키 (e, n) 배포 / 개인키 d 보관
```

```text
[ 2. 암호화와 서명 ]

암호화: 평문 → OAEP 인코딩 → C = EM^e mod n
복호화: C^d mod n → OAEP 해제 → 평문
서명: 메시지 해시 → PSS 인코딩 → S = EM^d mod n
검증: S^e mod n → PSS 확인 → 해시 일치
```

- 소수 생성 : 암호학적 난수 생성기로 후보를 만들고 Miller-Rabin 소수 판정을 적용.
- 복호화 가속 : 중국인의 나머지 정리(CRT)를 적용해 개인키 연산을 두 소수 기준으로 나눠 계산.

## Ⅳ. RSA 패딩 방식의 비교

- 핵심 요약 : 패딩이 없는 원시 RSA는 쓸 수 없고, PKCS#1 v1.5는 오라클 공격에 취약해 OAEP와 PSS가 현행 권고.

| 비교 항목 | 원시 RSA (Textbook RSA) | RSA PKCS#1 v1.5 | RSA-OAEP / RSA-PSS |
| --- | --- | --- | --- |
| 무작위성 | 없음 (결정론적 암호화) | 무작위 패딩 존재 | 마스크 생성 함수로 무작위성 확보 |
| 대수적 구조 악용 | 곱셈 준동형성으로 조작 가능 | 일부 취약 | 준동형 조작을 차단하도록 설계 |
| 패딩 오라클 내성 | 해당 없음 | 블라이헨바허 공격에 노출 | 오류 정보 누출을 줄이도록 설계 |
| 안전성 근거 | 증명 없음 | 휴리스틱 안전성 | 랜덤 오라클 모델에서 IND-CCA2 증명 |
| 현행 권고 | 사용 금지 | 신규 시스템에서 퇴역 | 권고 |

- 선택 기준 : 신규 시스템은 OAEP와 PSS를, 기존 시스템은 PKCS#1 v1.5의 잔존 범위를 확인해 단계적으로 교체.

## Ⅴ. RSA 공개키 암호의 한계와 방안

- 핵심 요약 : 양자 컴퓨터, 패딩 오라클, 부채널, 잘못된 파라미터 사용이 RSA의 실제 위험 요인.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 양자 컴퓨터 위협 | Shor 알고리즘으로 소인수분해가 가능해지면 RSA 전체가 무력화 | NIST PQC 표준인 ML-KEM과 ML-DSA로 이행하고, 과도기에는 RSA와 PQC 하이브리드 적용 | PQC 전환 대상 시스템 비율 |
| 작은 공개 지수 사용 | e=3 같은 값에서 같은 메시지를 여러 수신자에게 보내면 CRT로 평문 복원 (Håstad 브로드캐스트 공격) | e를 65537로 고정하고 OAEP로 메시지 간 연관성 제거 | 파라미터 점검 위반 건수 |
| 패딩 오라클 | 패딩 실패 응답 차이로 평문을 점진적으로 복원 (블라이헨바허 공격) | 패딩 검증 실패를 즉시 알리지 않고 복호화 루틴을 일정하게 수행 | 오류 응답 종류 수 |
| 부채널 누출 | 모듈러 지수 연산의 시간·전력 차이로 개인키 추론 | 연산 전 난수로 블라인딩하는 RSA 블라인딩 기법 적용 | 부채널 시험 통과율 |

## Ⅵ. RSA 운용에 대한 기술사적 제언

- 핵심 요약 : 알고리즘 설정, 키 보관, 암호 민첩성을 묶어 RSA의 퇴출과 이행을 계획된 일정으로 관리.

1. 레거시 패딩과 짧은 키를 폐기하고 OAEP와 PSS, 2048비트 이상 키로 설정을 통일하는 것이 바람직하다.
2. 개인키는 공인 검증을 받은 하드웨어 보안 모듈 안에서만 생성과 연산이 이뤄지도록 구성하면, 메모리 덤프와 부채널을 통한 유출 위험을 줄일 수 있다.
3. 알고리즘을 설정으로 교체할 수 있는 암호 민첩성 구조를 도입하고 PQC 테스트 환경과 연동해, 양자 시대의 이행을 서비스 중단 없이 준비할 필요가 있다.

## Ⅶ. 결론

- 핵심 요약 : RSA는 공개키 인증 체계의 기반을 세운 알고리즘이지만, 패딩 설계와 양자 내성 측면에서 이행 계획이 필수.
- 시사점 : 현행 RSA의 안전한 사용 기준을 지키면서 PQC로의 전환을 준비하는 조직만이 공개키 신뢰 체계를 장기간 유지할 수 있다.
