## Ⅰ. RSA 공개키 암호의 개요

- **개념** : 매우 큰 두 개의 소수를 곱한 합성수의 소인수분해 계산 복잡성에 기반하여 데이터 암호화(기밀성)와 전자서명(인증/부인방지)을 구현하는 비대칭 암호 알고리즘.
- **배경 및 필요성** : 큰 두 소수의 곱을 구하기는 쉬우나 합성수를 소인수분해하기는 극도로 어렵다는 수학적 계산 난제(IFP)에 기반하여, 전 세계 전자상거래와 디지털 인증서(PKI)의 기밀성 및 전자서명을 가능케 한 기념비적 공개키 암호로 도입됨.
- **핵심 목적** : 대칭키 암호의 키 사전 공유 난제를 해결하고, 단일 공개키-개인키 쌍을 통해 안전한 키 교환, 종단 간 기밀 통신 및 공인인증서 신뢰 체계 확립.

## Ⅱ. RSA 공개키 암호의 핵심 아키텍처 및 동작 메커니즘

RSA 공개키 암호은(는) 신뢰할 수 있는 보안 구조와 표준화된 절차를 기반으로 동작하며, 세부적인 아키텍처와 구성요소 간의 상호작용 메커니즘은 다음과 같음.

```text
[ 1. RSA 키 쌍 생성 단계 ]
서로 다른 대형 소수 p, q 선택 (각 1024-bit 이상)
       │
       ▼
모듈러스 n = p * q 및 오일러 함수 phi(n) = (p-1)(q-1) 계산
       │
       ▼
공개 지수 e 선택: 1 < e < phi(n) 이며 gcd(e, phi(n)) = 1 (통상 e = 65537)
       │
       ▼
개인 지수 d 계산: e * d = 1 (mod phi(n)) (확장 유클리드 알고리즘 적용)
       │
       ▼
[공개키: (e, n)] 배포  /  [개인키: (d, n), p, q] HSM에 기밀 보관

[ 2. RSAES-OAEP 암호화 / 복호화 ]             [ 3. RSASSA-PSS 전자서명 / 검증 ]
평문 메시지 M                                 원문 메시지 M
     │                                             │
     ▼                                             ▼
OAEP 패딩 인코딩 (M + Salt + MGF1)            SHA-256 해시 H(M) 도출
     │                                             │
     ▼                                             ▼
인코딩된 블록 EM                              PSS 패딩 인코딩 (H(M) + Salt)
     │                                             │
     ▼                                             ▼
암호화: C = EM^e mod n (공개키)                서명 생성: S = EM^d mod n (개인키)
     │                                             │
     ▼ (전송)                                      ▼ (전송)
복호화: EM = C^d mod n (개인키)                서명 검증: EM' = S^e mod n (공개키)
     │                                             │
     ▼                                             ▼
OAEP 언패딩 및 원문 M 복원                     PSS 무결성 및 해시 H(M) 일치 검증
```

- **소수 생성** : 암호학적 난수 생성기(CSPRNG)와 밀러-라빈(Miller-Rabin) 소수 판정법 적용 (FIPS 186-5 규격).
- **키 생성** : $n = p \times q$, $e = 65537$, $d = e^{-1} \pmod{\text{lcm}(p-1, q-1)}$ (PKCS#1 v2.2).
- **복호화 가속** : 중국인의 나머지 정리(CRT)를 적용하여 복호화 연산 속도 약 4배 향상 ($d_p, d_q, q_{inv}$) (RSA-CRT 최적화).
- **암호화 (OAEP)** : 평문에 2개의 해시 함수와 무작위 시드(Seed)를 Feistel 구조로 결합하여 암호화 (RFC 8017 RSAES-OAEP).
- **서명 (PSS)** : 메시지 해시값에 무작위 Salt를 결합하여 매 서명마다 다른 서명값 출력 (RFC 8017 RSASSA-PSS).

## Ⅲ. RSA 공개키 암호의 세부 구성 요소 및 비교 분석

| 비교 항목 | 원시 RSA (Textbook RSA) | RSA PKCS#1 v1.5 | RSA-OAEP / RSA-PSS (최신) |
|---|---|---|---|
| 무작위성 (Randomness) | 없음 (결정론적 암호화) | 존재 (무작위 패딩 바이트 추가) | 완벽함 (암호학적 마스크 생성 함수 MGF1) |
| 대수적 공격 내성 | 취약 (승법 준동형성 조작 가능) | 일부 취약 | 우수 (수학적 준동형성 완전 차단) |
| 패딩 오라클 내성 | 해당 없음 (패딩 미사용) | 치명적 취약 (Bleichenbacher 공격 노출) | 안전함 (오라클 오류 정보 누출 차단) |
| 암호 안전성 증명 | 안전성 증명 불가 | 휴리스틱 안전성 (수학적 증명 없음) | 랜덤 오라클 모델 하에서 IND-CCA2 증명 |
| 현대 표준 권고 | 사용 절대 금지 | 신규 시스템 퇴역 (Legacy 유지) | NIST 및 FIPS 186-5 표준 권고 |

- RSA 공개키 암호은(는) 상기 핵심 비교 지표와 아키텍처 구성을 바탕으로 보안 위협에 대한 방어 효과성을 극대화하며, 기존 레거시 통제 기법 대비 우수한 신뢰성과 운영 효율성을 제공함.

## Ⅳ. RSA 공개키 암호의 주요 한계점 및 해결 방안

- **한계점** : Shor 알고리즘 기반 양자컴퓨터 등장 시 다항식 시간($O((\log n)^3)$) 내 소인수분해 완료로 RSA 체계 전면 붕괴.
  - **해결 방안** : NIST PQC 표준인 격자 기반 ML-KEM(Kyber) 및 ML-DSA(Dilithium)로 마이그레이션하고, 과도기적으로 RSA-PQC 하이브리드 암호화 도입.
- **한계점** : 고정된 작은 공개 지수($e=3$) 사용 시 동일 메시지를 3개 이상의 수신자에게 전송할 경우 중국인의 나머지 정리로 평문 복원(Håstad 브로드캐스트 공격).
  - **해결 방안** : 공개 지수 $e$를 관례적인 $65537(2^{16}+1)$로 강제 고정하고 최신 RSAES-OAEP 패딩을 적용하여 메시지 간 연관성 제거.
- **한계점** : 복호화 실패 시 반환되는 오류 메시지(패딩 불일치 vs 암호문 손상)의 차이를 이용한 블라이헨바허(Bleichenbacher) 백만 메시지 공격.
  - **해결 방안** : 패딩 검증 실패 시 즉시 에러를 반환하지 않고 무작위 가짜 평문을 생성하여 복호화 루틴을 끝까지 수행하는 상수 시간 오류 처리 적용.
- **한계점** : 모듈러 멱승 연산($C^d \bmod n$) 수행 시 비트가 1일 때와 0일 때의 연산 시간 및 전력 소비 차이를 측정하는 부채널(Side-Channel) 공격.
  - **해결 방안** : 멱승 연산 전에 암호문에 무작위 난수를 곱해 연산하고 사후에 제거하는 RSA 블라인딩(Blinding) 기법 강제 적용.

## Ⅴ. RSA 공개키 암호 적용 및 발전을 위한 기술사적 제언

- **알고리즘 설정 중심의 거버넌스 및 실행 체계 구축** : 레거시 PKCS#1 v1.5 및 1024-bit RSA 키 전면 폐기, 2048/3072-bit OAEP/PSS 단일화을(를) 적극 추진하여, 패딩 오라클 취약점 및 통계적 해독 위험 100% 제거 효과를 극대화해야 함.
- **키 저장 및 연산 중심의 거버넌스 및 실행 체계 구축** : FIPS 140-3 레벨 3 인증 HSM 내부에서 키 생성·보관 및 CRT 블라인딩 연산 강제을(를) 적극 추진하여, 메모리 덤프 및 사이드채널 기반 비밀키 유출 원천 차단 효과를 극대화해야 함.
- **암호 민첩성 중심의 거버넌스 및 실행 체계 구축** : 암호 알고리즘 교체가 용이한 Crypto-Agility 프레임워크 구축 및 PQC 테스트베드 연동을(를) 적극 추진하여, 양자컴퓨터 도래 시 서비스 중단 없는 무결 마이그레이션 보장 효과를 극대화해야 함.
