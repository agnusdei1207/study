## 지식 로드맵 내 현재 위치

지식 위치: 공개키 암호 → 인수분해 기반 암호 → **RSA**

## 30초 인출

- RSA는 큰 정수의 인수분해 어려움에 기초한 공개키 방식으로, 암호화·키 운반 및 전자서명 체계에 활용
- 실무에서는 **RSAES-OAEP** 암호화와 **RSASSA-PSS** 서명을 구별. 교과서식 거듭제곱만 적용한 원시 RSA는 안전한 완성형 체계가 아님
- TLS 1.3의 세션 키 합의는 RSA 암호문으로 세션 키를 운반하는 옛 방식과 구별

## 1교시 예상문제 (10점)

> RSA의 키 생성 원리와 암호화·서명 용도를 구별하여 설명하시오. (예상·10점)

## 1교시 10점 답안

### Ⅰ. 키 생성과 수학적 핵심

소수 p,q를 선택해 n=pq 생성, 공개 지수 e와 대응하는 개인 지수 d를 계산. 공개키 (n,e)와 개인키 d를 분리해 운용.

### Ⅱ. 용도 구분

| 용도 | 실무 체계 | 검증 대상 |
|---|---|---|
| 암호화·키 운반 | RSAES-OAEP | 올바른 패딩과 복호화 오류 처리 |
| 전자서명 | RSASSA-PSS | 메시지 해시·서명·공개키 검증 |

`m^e mod n`과 `s^d mod n`은 수학적 핵심을 보여 주는 식이며 실제 안전한 포맷과 인코딩 절차를 생략한 표현.

## 2~4교시 예상문제 (25점)

> RSA의 키 생성·암호화·전자서명 원리를 설명하고, 패딩·키 관리·하이브리드 암호 적용 시의 보안 조건을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

### Ⅰ. 개요

RSA는 공개키와 개인키의 분리로 암호화와 전자서명을 지원하는 공개키 암호 체계. 구현 안전성은 키 생성·패딩·오류 처리·개인키 보호에 의존.

### Ⅱ. 키 생성과 처리 흐름

```text
서로 다른 큰 소수 p,q → n=pq → 공개 지수 e·개인 지수 d
암호화: 공개키 + OAEP 인코딩 → 암호문 → 개인키 복호화
서명: 메시지 해시 + PSS 인코딩 → 개인키 서명 → 공개키 검증
```

실제 알고리즘은 CRT 가속·블라인딩 등 구현 보호를 함께 고려.

### Ⅲ. 암호화와 서명 비교

| 구분 | RSAES-OAEP | RSASSA-PSS |
|---|---|---|
| 목표 | 메시지·키 운반의 기밀성 | 서명자의 키 보유와 메시지 무결성 확인 |
| 공개키 역할 | 암호화 | 검증 |
| 개인키 역할 | 복호화 | 서명 |
| 필수 안전 요소 | OAEP 파라미터와 복호화 오류 처리 | PSS 해시·salt·서명 검증 |

'개인키로 암호화하면 서명'이라는 식은 패딩·해시·검증 절차를 누락하므로 실무 설명으로 부적절.

### Ⅳ. 하이브리드 암호 적용

큰 데이터는 대칭키 기반 AEAD로 보호하고, RSA를 쓰는 프로토콜에서는 제한된 길이의 대칭키 재료를 OAEP로 운반 가능. 최신 프로토콜은 (EC)DHE 또는 KEM으로 공유 비밀을 합의할 수 있으므로 RSA 키 운반을 보편 구조로 일반화하지 않음.

### Ⅴ. 운영 위험

| 위험 | 대응 |
|---|---|
| 약한 난수·키 길이 | 승인된 키 생성기와 보안 강도 지침 준수 |
| 원시 RSA·잘못된 패딩 | 검증된 OAEP/PSS 라이브러리 사용 |
| 복호화 오류 누출 | 오라클 공격을 막는 오류 처리 |
| 개인키 노출 | 키 접근 통제·백업·교체 및 필요 시 HSM |
| 양자 컴퓨터의 장기 위험 | 데이터 보존 기간에 맞춘 전환 계획 |

### Ⅵ. 기술사적 제언

수학적 RSA 연산과 검증된 응용 체계를 분리해 설명하고, 키 수명·패딩·프로토콜의 키 합의 방식을 함께 검토.
