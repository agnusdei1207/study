## 지식 로드맵 내 현재 위치

AI 보안 → 국내 실무 지침 → 과기정통부·KISA 인공지능(AI) 보안 안내서 및 거버넌스

## 30초 인출

- **본질:** 과학기술정보통신부와 KISA가 안전한 AI 생태계 조성을 위해 AI 모델 개발·구축·운영 전 생애주기에 걸친 사이버 보안 위협과 실무 통제 기준을 제시한 국가 표준 가이드라인
- **메커니즘:** 기획·설계 → 데이터 수집·가공 → 모델 개발·학습 → 서비스 배포·운영 → 폐기 전 단계별 체크리스트 적용 및 위험 완화
- 통찰: 학습 데이터 공급망 중독(Poisoning)과 모델 추출(역공학) 공격을 방어하기 위해 데이터 계보 추적 및 가중치 워터마킹 결합 필수

<details>
<summary>핵심 용어</summary>

- **AI 보안 안내서:** 과기정통부와 KISA가 AI 서비스 개발자, 운영자, 이용자를 위해 AI 고유의 보안 위협과 대응 기술을 체계화한 공식 실무 지침서
- **AI 생애주기 보안:** 기획 단계의 위협 모델링부터 데이터 가공, 모델 학습, 배포, 런타임 모니터링, 안전한 폐기에 이르는 전 주기 보안 내재화
- **데이터 중독 (Data Poisoning):** 학습 데이터셋에 의도적으로 오염된 데이터나 백도어 트리거를 삽입하여 특정 조건에서 오작동을 유발하는 공격
- **모델 추출 공격 (Model Extraction):** API 질의-응답 결과를 지속해서 수집하여 원본 상용 모델의 가중치와 동작을 복제하는 지식재산권 침해 공격
</details>

## 2~4교시 예상문제 (25점)

> 과학기술정보통신부와 KISA가 발표한 '인공지능(AI) 보안 안내서'의 주요 내용과 생애주기별(기획, 개발, 운영, 폐기) 핵심 보안 통제 요구사항을 설명하고, NIST AI RMF와의 비교 및 모델 추출·데이터 중독 공격에 대응하기 위한 엔지니어링 방안을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **AI 보안 안내서(과기정통부·KISA)** 는 인공지능 모델 및 서비스가 기획·설계부터 개발, 운영, 폐기 단계에 이르기까지 직면하는 고유한 사이버 위협(프롬프트 주입, 데이터 중독, 탈옥, 모델 탈취 등)을 예방하고 안전성을 확보하기 위해 정부가 제시한 실무 보안 지침서 |
| 목적 | 국내 기업의 안전한 AI 도입 지원, AI 서비스 신뢰성 및 안전성(Safety) 확보, 글로벌 AI 규제(EU AI Act 등) 선제 대응 |

전통적 소프트웨어 보안(시큐어 코딩)에 머무르지 않고, 학습 데이터 및 모델 파라미터의 무결성을 보장하는 AI 특화 다계층 보안 프레임워크 제공.

## Ⅱ. AI 보안 안내서의 특징 및 기본 방향

| 핵심 특징 | 세부 추진 내용 | 보안 거버넌스 가치 |
|---|---|---|
| **전 생애주기 보안 내재화** | 기획·설계, 데이터 구축, 모델 개발, 서비스 운영, 폐기 5단계 연계 | 사후 규제 대응이 아닌 'Security by Design' 구현 |
| **이해관계자별 역할 정의** | AI 서비스 개발사, 클라우드 인프라 제공자, 도입 기업, 최종 이용자 | 책임공유 모델(Shared Responsibility)을 AI로 확장 |
| **AI 고유 위협 대응** | 데이터 포이즈닝, 적대적 공격, 모델 전복, 간접 프롬프트 주입 수록 | 소프트웨어 결함(CVE)과 구별되는 데이터/모델 리스크 관리 |
| **글로벌 정합성** | NIST AI RMF 및 ISO/IEC 42001(AI 경영시스템) 표준 부합 | 국내 기업의 해외 진출 시 규제 장벽 완화 |

## Ⅲ. AI 생애주기 5단계별 핵심 보안 요구사항

```text
[AI 보안 안내서 기반 5단계 생애주기 보안 아키텍처]

 1. 기획·설계        2. 데이터 구축        3. 모델 개발·학습    4. 배포·운영        5. 폐기·종료
+---------------+   +---------------+   +---------------+   +---------------+   +---------------+
| AI 위협모델링 |-->| 데이터 출처검증|-->| 가중치 무결성 |-->| API 가드레일  |-->| 모델 가중치   |
| 보안요구 정의 |   | 개인정보 비식별|   | 적대적 훈련   |   | 실시간 이상감시|   | 영구 삭제     |
| 라이선스 검토 |   | 포이즈닝 필터 |   | 개발망 망분리 |   | 탈옥/유출 차단|   | 데이터 완전소거|
+---------------+   +---------------+   +---------------+   +---------------+   +---------------+
```

### 1. 단계별 핵심 엔지니어링 통제 기준

| 생애주기 단계 | 주요 보안 위협 | 핵심 보안 통제 및 엔지니어링 조치 |
|---|---|---|
| **1. 기획·설계** | 법적 규제 위반, 잘못된 위협 가정 | AI 위험 식별 및 위협 모델링(STRIDE for AI), 저작권 및 개인정보 침해 리스크 사전 평가 |
| **2. 데이터 구축** | 데이터 중독(Poisoning), 개인정보 유출 | 데이터 계보(Lineage) 관리, PII 자동 탐지 및 마스킹, 비정상 이상치(Outlier) 통계적 정제 |
| **3. 모델 개발·학습** | 백도어 삽입, 공급망 취약 오픈소스 모델 | HuggingFace 사전학습 가중치 해시 검증, 폐쇄형 학습망 운영, 악성 Pickle 파일 역직렬화 차단 |
| **4. 배포·운영** | 프롬프트 인젝션, 모델 추출, DoS | 입출력 보안 가드레일(NeMo/Llama Guard), API Rate Limiting, 질의-응답 섭동 노이즈 주입 |
| **5. 폐기·종료** | 가중치 잔재 노출, 폐기 데이터 유출 | 모델 아티팩트 및 임시 캐시 디스크 영구 소거(DoD 5220.22-M), API 키 및 토큰 즉시 무효화 |

## Ⅳ. 주요 글로벌 AI 보안 프레임워크 비교

| 비교 항목 | 과기정통부·KISA AI 보안 안내서 | NIST AI RMF 1.0 (미국) | EU AI Act (유럽연합) |
|---|---|---|---|
| **성격 및 지위** | **국내 실무 기술 지침서 (가이드라인)** | 자율적 위험관리 프레임워크 (표준) | **법적 구속력을 가진 공식 법률 (위반 시 벌금)** |
| **접근 방식** | **생애주기 단계별 보안 체크리스트** | 4대 기능 (Govern, Map, Measure, Manage) | 4단계 위험도 분류 (허용불가, 고위험 등) |
| **주요 초점** | 사이버 침해 공격 방어 및 엔지니어링 | AI 신뢰성, 공정성, 편향 및 보안 전반 | 인권 침해 방지, 투명성 의무, 고위험 AI 규제 |
| **적용 대상** | 국내 AI 모델 개발사 및 서비스 운영사 | 미국 연방기관 및 글로벌 기업 자율 채택 | EU 시장에 진출하는 모든 글로벌 AI 기업 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **학습 데이터셋의 방대한 규모로 인한 데이터 중독(Poisoning) 전수 검증 불가**<br>수억 건의 웹 크롤링 텍스트 내에 정교하게 은닉된 백도어 트리거 및 오염 데이터를 수동 전수 검사하는 것은 현실적으로 불가능 | **데이터 계보(Data Lineage) 추적 및 클러스터링 기반 이상치(Outlier) 필터링**<br>DVC(Data Version Control) 및 MLflow를 도입하여 데이터 유입 경로를 불변 기록하고, 임베딩 벡터 공간에서 이상 패턴을 형성하는 군집을 통계적으로 자동 격리하는 클린즈 파이프라인 구축 |
| **API 무제한 질의를 통한 모델 추출(Model Extraction) 및 역공학 공격**<br>공격자가 수십만 건의 질의-응답 쌍을 수집하여 상용 모델의 성능을 거의 동일하게 모사하는 파생 모델을 제작함으로써 기업의 핵심 IP 탈취 | **적응형 Rate Limiting, 응답 섭동 주입 및 모델 워터마킹(Watermarking)**<br>동일 IP/계정의 비정상적 체계적 대량 쿼리를 차단하고, 출력 로짓(Logit)에 인간이 인지할 수 없는 미세한 노이즈를 주입하며, 특정 트리거 입력 시 고유 서명을 출력하는 모델 워터마킹 삽입 |

## Ⅵ. 제언

```text
[지속 가능한 AI DevSecOps 거버넌스 구현 모델]

 +--------------------+     +---------------------+     +--------------------+
 | 1. DataSec         | --> | 2. ModelSec         | --> | 3. AppSec          |
 | 데이터 수집/정제   |     | 가중치 서명 검증    |     | 런타임 가드레일    |
 | PII 마스킹/계보추적|     | 백도어/퍼징 테스트  |     | 모델 추출 방지 방어|
 +--------------------+     +---------------------+     +--------------------+
```

| 구현 계층 | 권장 핵심 조치 | 적용 기술 스택 |
|---|---|---|
| **데이터 계층** | 학습 데이터셋 불변 무결성 검증 | DVC, Great Expectations, Presidio |
| **모델 계층** | 모델 가중치 디지털 서명 및 변조 감시 | Sigstore Model Signing, Safetensors 포맷 |
| **서빙 계층** | 런타임 입출력 필터링 및 프롬프트 가드레일 | NeMo Guardrails, vLLM 보안 미들웨어 |

AI 보안 안내서를 일회성 개발 지침으로 끝내지 않고, MLOps 파이프라인 전체에 보안 게이트를 내재화하는 AI DevSecOps 파이프라인 구축 권장.
