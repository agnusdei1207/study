## 연관 키워드

- AI 보안 안내서(과기정통부·KISA), 생명주기 보안, 생성형 AI(Generative AI), 프롬프트 인젝션(Prompt Injection)
- 학습 데이터 오염(Data Poisoning), 입·출력 가드레일, AI 레드팀(Red Teaming), 섀도우 AI(Shadow AI)
- CASB, DLP, 인공지능 기본법, ISMS, 모델 가중치, 파인튜닝

## Ⅰ. AI 보안 안내서 (과기정통부·KISA)의 개요

- 핵심 요약 : 생성형 AI의 기획부터 폐기까지 전 생명주기에 보안 기준을 제시한 국가 차원의 안내 지침.
- 개념 : 과학기술정보통신부와 한국인터넷진흥원(KISA, Korea Internet & Security Agency)이 **생성형 AI** (Generative AI) 서비스의 개발자, 제공자, 이용자가 따를 보안 기준과 수칙을 정리한 안내 문서.
- 배경 및 필요성 : 거대언어모델(LLM, Large Language Model) 활용이 급증하면서 기밀 유출, 데이터 오염, 편향, 프롬프트 인젝션 같은 신종 위협이 늘어나 국가 차원의 기준이 필요해짐.
- 주요 목적 : AI 서비스의 **생명주기 보안** (Lifecycle Security)을 내재화하고, 주체별 보안 역할을 명확히 하여 안전한 AI 생태계를 조성.

## Ⅱ. AI 보안 안내서 (과기정통부·KISA)의 특징 및 장점

- 핵심 요약 : 생명주기 전 단계에 통제를 배치하고 주체별 책임을 나눔으로써, 사후 대응보다 설계 단계의 예방을 강조하는 체계.

1. 생명주기 관점 : 기획, 데이터, 학습, 배포, 운영 단계마다 통제를 배치 → 특정 단계 누락에 따른 위험 감소.
2. 주체별 역할 분리 : 개발자, 서비스 제공자, 이용자의 책임을 구분 → 책임 공백 감소.
3. **학습 데이터 오염** (Data Poisoning) 방지 : 검증된 출처의 데이터만 수집하고 무결성을 검사 → 백도어 삽입 위험 감소.
4. **입·출력 가드레일** (Guardrails) : 입력 단계에서 악성 프롬프트를 차단하고, 출력 단계에서 개인정보나 악성코드 생성 여부를 필터링 → 이중 차단.
5. **AI 레드팀** (Red Teaming) 정례화 : 배포 전 적대적 공격 시나리오로 모의 해킹을 수행 → 취약점 사전 보완.

## Ⅲ. AI 보안 안내서 (과기정통부·KISA)의 구조 (흐름)

- 핵심 요약 : 기획에서 운영까지 다섯 단계 생명주기에 단계별 위협과 통제를 대응시킨 흐름.

```text
[ 생명주기별 보안 통제 흐름 ]

1. 기획·설계 : 위협 모델링, AI 거버넌스
          ↓
2. 데이터 준비 : 출처 검증, 개인정보 필터링
          ↓
3. 모델 학습 : 적대적 학습, 가중치 보호
          ↓
4. 서비스 배포 : 가드레일, API 최소 권한
          ↓
5. 운영·모니터링 : 입출력 감사, 레드팀 점검
```

| 생명주기 단계 | 핵심 보안 위협 | 주요 통제 |
| --- | --- | --- |
| 기획 및 설계 | 보안 요구사항 누락, 프라이버시 침해 | STRIDE 등 위협 모델링, AI 거버넌스 수립 |
| 데이터 수집·가공 | 저작권 침해, 개인정보 유출, 데이터 오염 | 가명처리, 출처 검증, 무결성 검사 |
| 모델 학습·튜닝 | 백도어 삽입, 모델 추출 | 적대적 학습, 체크포인트 해시 검증, TEE(Trusted Execution Environment) 활용 |
| 서비스 배포 | 프롬프트 인젝션, 시스템 프롬프트 노출 | 가드레일 계층, 입력 정규화, API 최소 권한 |
| 운영 및 모니터링 | 서비스 악용, 환각에 의한 정보 노출, 비정상 트래픽 | 실시간 감사 로깅, 정기 레드팀 점검, 모델 드리프트 감시 |

## Ⅳ. AI 보안 안내서 (과기정통부·KISA)의 비교

- 핵심 요약 : 안내서는 권고 성격이고 법령은 구속력이 있으며 인증 제도는 심사 기준이어서, 세 축이 연결될 때 준수가 확보됨.

```text
[ 권고를 준수로 잇는 방향 (제언) ]

안내서 (권고 기준)
          ↓
ISMS 인증 심사 기준 편입
          ↓
인공지능 기본법상 의무 연계
```

| 구분 | 안내서 | 인공지능 기본법 | ISMS(Information Security Management System) 인증 |
| --- | --- | --- | --- |
| 성격 | 권고 기준 | 법적 구속력이 있는 규범 | 인증 심사 기준 |
| 적용 방식 | 자율 준수 | 법령에 따른 의무 | 인증 취득 및 유지 시 심사 |
| 한계 | 준수 강제력 부재 | 세부 기준은 하위 규정 의존 | 인증 범위 밖의 AI 서비스는 적용 곤란 |

## Ⅴ. AI 보안 안내서 (과기정통부·KISA)의 한계와 방안

- 핵심 요약 : 권고 성격, 오픈소스 모델 검증, 섀도우 AI가 주요 한계이며 법제도 편입과 기술적 통제를 함께 적용해야 함.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 권고 성격에 따른 준수율 한계 | 강제력이 없어 중소 AI 기업이 통제 구현을 미룸 | 인공지능 기본법과 ISMS 인증 기준에 AI 생명주기 보안 항목을 단계적으로 편입 | 자체 점검 이행률 |
| 오픈소스 모델 가중치의 검증 한계 | 사전 학습 단계의 백도어 여부를 파인튜닝 기업이 확인하기 어려움 | 모델 파일 취약점 스캐닝과 파인튜닝 전 백도어 탐지 도구 적용 | 검증 완료 모델 비율 |
| 섀도우 AI 사용의 통제 사각지대 | 임직원이 개인 계정으로 외부 생성형 AI에 소스코드를 입력하는 유출 경로 | **CASB** (Cloud Access Security Broker)와 **DLP** (Data Loss Prevention) 연동으로 비인가 사이트 접속 제한, 사내 폐쇄형 AI 포털 제공 | 비인가 AI 접속 시도 건수 |

## Ⅵ. AI 보안 안내서 (과기정통부·KISA)에 대한 기술사적 제언

- 핵심 요약 : 학습 재사용 차단 계약, 침해 대응 절차, 임직원 교육을 제도로 묶어 안전한 사내 AI 이용 기반을 마련.
- 기업은 사내 데이터가 모델 학습에 재사용되지 않도록 보장하는 데이터 무보관 계약(Zero Data Retention)을 갖춘 엔터프라이즈 AI 환경을 우선 도입하는 것이 바람직하다.
- 모델 오작동이나 대규모 개인정보 환각 노출이 발생하면 서비스를 격리하고 가중치를 이전 버전으로 되돌리는 AI 침해사고 대응 절차를 별도로 마련할 필요가 있다.
- 개발자에게는 시큐어 프롬프트 엔지니어링 교육을, 전 임직원에게는 생성형 AI 활용 보안 수칙 준수 서약을 정기적으로 시행하는 것이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : 이 안내서는 AI 보안을 모델 기술 문제가 아니라 생명주기 전반의 거버넌스 문제로 규정한 국가 기준임.
- 권고를 법령과 인증 제도로 잇는 후속 조치가 뒤따를 때 기준의 실효성이 확보됨.
