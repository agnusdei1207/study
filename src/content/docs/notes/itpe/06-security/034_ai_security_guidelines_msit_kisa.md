## 지식 로드맵 내 현재 위치

AI 보안 → 국내 실무 지침 → 인공지능(AI) 보안 안내서

## 30초 인출

- **본질:** **인공지능(AI) 보안 안내서**는 AI 모델·서비스를 외부 사이버 위협으로부터 보호하기 위한 실무 참고지침
- **메커니즘:** 기획·개발·운영·유지보수·개선·파기의 생애주기별로 보안 요구를 확인
- **적용:** 서비스 책임자와 개발·운영 담당자가 현재 안내서 판본의 항목을 업무통제에 연결

<details>
<summary>핵심 용어</summary>

- **인공지능(AI) 보안 안내서:** 과학기술정보통신부와 KISA가 AI 모델·서비스 보호를 위해 제공하는 실무 참고지침
- **KISA (Korea Internet & Security Agency):** 한국인터넷진흥원으로, AI 보안 안내서를 발간·배포한 기관
- **AI 서비스 생애주기:** 기획·설계에서 개발·운영·유지보수·개선·파기까지 서비스가 거치는 단계
- **NIST (National Institute of Standards and Technology):** 미국 국립표준기술연구소
- **AI RMF (Artificial Intelligence Risk Management Framework):** NIST의 자율적 AI 위험관리 프레임워크
- **보안 내재화(Secure by Coding):** 개발과 구현 과정에 보안 요구·검증을 반영하는 접근
- **CIA (Confidentiality, Integrity, Availability):** 기밀성·무결성·가용성의 정보보호 기본 속성
</details>

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **인공지능(AI) 보안 안내서**는 AI 모델·서비스를 외부 사이버 위협으로부터 보호하기 위한 실무 참고지침 |
| 목적 | AI 서비스 생애주기별 위협 식별과 보안통제 적용 지원 |

### Ⅱ. 생애주기 보안점검

```text
기획·설계
    ↓
개발·구축
    ↓
제공·운영
    ↓
유지보수·지원
    ↓ 운영 결과·사고
피드백·개선
    ├─ 계속 운영 → 기획·설계에 개선 반영
    └─ 종료 결정 → 서비스 파기
```

| 단계 | 우선 확인 사항 |
|---|---|
| 기획·설계 | 자산·데이터 흐름·위협·보안 책임 |
| 개발·구축 | 학습데이터·모델 무결성·개발환경 접근 |
| 제공·운영 | API·인터페이스·입출력·이상행위 감시 |
| 유지보수·개선·파기 | 변경 검증·사고 피드백·데이터와 자산의 안전한 종료 |

**제언:** 조직은 안내서 최신 수정본을 기준으로 단계별 책임자와 확인 증적을 지정

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **인공지능(AI) 보안 안내서**는 AI 모델·서비스를 외부 사이버 위협으로부터 보호하기 위한 실무 참고지침 |
| 목적 | AI 서비스 생애주기별 위협 식별과 보안통제 적용 지원 |

## Ⅱ. 생애주기별 점검

| 단계 | 대표 보안 검토 |
|---|---|
| 기획·설계 | 서비스 목적·자산·데이터흐름·위협·책임 정의 |
| 개발·구축 | 데이터 권한·민감정보·암호화, 모델·파이프라인 무결성과 접근통제 |
| 제공·운영 | 서비스 이상행위 감시, API (Application Programming Interface)·인터페이스 보호, 백업·복구 |
| 유지보수·지원 | 모델·구성 변경의 검증, 취약점·사고 조치의 추적 |
| 피드백·개선 | 사용자·운영 사건의 분석과 통제 개선 |
| 서비스 파기 | 모델·데이터·계정·키·백업의 보유 필요성 확인과 안전한 종료 |

## Ⅲ. 모델 개발·서비스 운영 통제

| 대상 | 위험 | 통제 방향 |
|---|---|---|
| 데이터 | 무단 사용·민감정보·오염 | 출처·권한·목적 확인, 최소수집·암호화·무결성 점검 |
| 모델·개발환경 | 모델 변조·취약한 의존성·과도한 개발권한 | 모델·구성요소 출처 확인, 접근통제·변경검토 |
| API·인터페이스 | 비인가 호출·입력 악용·민감정보 출력 | 인증·권한·호출조건 검증, 입출력 검사 |
| 운영·복구 | 이상행위·서비스 장애·정보 유출 | 실시간 점검, 사고대응·백업 복구 절차 |

## Ⅳ. 참고 프레임워크와 적용 관계

| 구분 | AI 보안 안내서 | NIST AI RMF |
|---|---|---|
| 성격 | 국내 AI 모델·서비스 보안 요구사항 참고 | 조직의 AI 위험관리 활동을 구조화하는 자율 프레임워크 |
| 구성 관점 | 생애주기별 보안 점검 | Govern·Map·Measure·Manage 기능 |
| 활용 관계 | 구체 점검항목과 통제 선택 참고 | 조직의 위험관리·책임·평가 절차와 연결 |

## Ⅴ. 한계와 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 안내서 항목을 문서 체크리스트로만 소비하면 서비스별 책임·운영기록과 분리될 수 있음 | 가장 영향이 큰 서비스 한 개부터 요구사항을 소유자·개발·운영 절차에 연결하고, 실제 증적·사고 대응까지 검증하는 적용 순서 제안 |
| 안내서 개정에 따라 항목과 표현이 달라질 수 있음 | 기준 문서의 판본·개정일을 통제목록에 기록하고, 개정 확인 시 영향 항목과 책임자를 재검토 |
