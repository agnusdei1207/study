## Ⅰ. 생성형 AI 서비스 개발·이용 보안 안내서 (과기정통부·KISA)의 개요

- 개념 : 과학기술정보통신부와 한국인터넷진흥원(KISA)이 생성형 AI 확산에 따른 보안 위협을 선제적으로 예방하기 위해, AI 서비스 개발자, 서비스 제공자, 이용자가 준수해야 할 전 생명주기 보안 통제 기준과 안전 수칙을 제시한 국가 보안 가이드라인.
- 배경 및 필요성 : ChatGPT 등 거대언어모델(LLM) 활용 급증으로 사내 기밀 유출, 데이터 오염, 편향성, 프롬프트 인젝션 등 신종 위협이 폭증함에 따라 국가 차원의 체계적인 보안 기준 마련 필요.
- 핵심 목적 : AI 서비스 기획부터 폐기까지 전 생명주기 보안 내재화, 개발자·제공자·이용자 주체별 보안 역할 명확화 및 안전한 AI 생태계 조성.

## Ⅱ. 생성형 AI 서비스 개발·이용 보안 안내서 (과기정통부·KISA)의 핵심 아키텍처 및 동작 메커니즘

안내서는 AI 서비스 생명주기를 5단계(기획·설계 -> 데이터 수집·가공 -> 모델 학습 -> 서비스 개발·배포 -> 운영·모니터링)로 구분하고 각 단계별 기술적·관리적 보안 체크리스트를 규정함.

```text
[ 과기정통부·KISA 생성형 AI 서비스 생명주기별 보안 통제 프레임워크 ]

  [ 1. 기획·설계 ] -> AI 위협 모델링, 윤리/보안 정책 수립, 침해 영향 평가
           │
           ▼
  [ 2. 데이터 준비 ] -> 수집 데이터 저작권/개인정보 필터링, 데이터 오염(Poisoning) 검증
           │
           ▼
  [ 3. 모델 학습 ]   -> 적대적 학습(Adversarial Training), 모델 가중치 암호화 보관
           │
           ▼
  [ 4. 개발·배포 ]   -> 프롬프트 인젝션 방어, 가드레일 적용, API 및 플러그인 권한 최소화
           │
           ▼
  [ 5. 운영·유지 ]   -> 실시간 입출력 모니터링, 환각/오남용 탐지, 정기 레드팀 훈련
```

- 주체별 3대 보안 요구사항 : AI 개발사(안전한 모델 학습/가드레일), 서비스 제공자(플러그인 보안/입출력 필터링), 최종 이용자(개인정보/기밀 입력 금지).
- **학습 데이터 오염(Poisoning) 방지** : 검증된 데이터 소스만 수집하고, 데이터 해시 무결성 검증 및 악의적 백도어 트리거 데이터 사전 정제.
- **입·출력 2중 가드레일 구축** : 사용자 입력 단계에서 악성 프롬프트 차단, 모델 출력 단계에서 개인정보·악성코드 생성 여부 필터링.
- **AI 레드팀(Red Teaming) 정례화** : 상용 서비스 배포 전 적대적 공격 시나리오를 바탕으로 모의 해킹을 수행하여 취약점 보완.

## Ⅲ. 생성형 AI 서비스 개발·이용 보안 안내서 (과기정통부·KISA)의 세부 구성 요소 및 비교 분석

| 생명주기 단계 | 핵심 보안 위협 | 주요 보안 통제 조치 (안내서 기준) |
| --- | --- | --- |
| 1. 기획 및 설계 | 보안 요구사항 누락, 프라이버시 침해 | 위협 모델링(STRIDE/ATLAS), AI 거버넌스 수립 |
| 2. 데이터 수집/가공 | 저작권 침해, 개인정보 유출, 데이터 오염 | 비식별 조치(가명화), 데이터셋 출처 검증, 무결성 검사 |
| 3. 모델 학습/튜닝 | 백도어 삽입, 모델 추출, 과적합 | 적대적 훈련, 체크포인트 해시 서명, 하드웨어 TEE |
| 4. 서비스 배포 | 프롬프트 인젝션, 시스템 프롬프트 노출 | 가드레일 레이어, 입력 정규화, API 최소 권한 |
| 5. 운영 및 모니터링 | 서비스 악용, 개인정보 환각, 비정상 트래픽 | 실시간 감사 로깅, 정기 AI 레드팀 점검, 모델 드리프트 감시 |

- 안내서는 단순한 기술적 방어에 그치지 않고 개발-제공-이용에 이르는 전 가치사슬의 거버넌스를 포괄하며, 글로벌 NIST AI RMF 및 EU AI Act의 규제 방향과 긴밀히 부합함.

## Ⅳ. 생성형 AI 서비스 개발·이용 보안 안내서 (과기정통부·KISA)의 주요 한계점 및 해결 방안

- 법적 강제력이 없는 권고 성격의 가이드라인으로 인한 현장 준수율 한계 :
  - 한계점 : 공식 법률이 아닌 가이드라인 형태로 배포되어 스타트업이나 중소 AI 기업에서 비용 문제로 보안 통제 구현 기피.
  - 해결 방안 : '인공지능 기본법' 및 ISMS-P 인증 기준 내에 AI 생명주기 보안 통제 항목을 필수 법정 심사 기준으로 단계적 편입.
- **오픈소스 파운데이션 모델** (LLaMA 등) 활용 시 자체 학습 단계 검증 불가 :
  - 한계점 : 사전 학습된 오픈소스 가중치를 다운받아 파인튜닝만 수행하는 대다수 기업은 원천 학습 데이터의 백도어 존재 여부 검증 곤란.
  - 해결 방안 : Hugging Face 모델 가중치에 대한 오픈소스 취약점 스캐닝 도구(PickleScan 등) 및 파인튜닝 전 백도어 트리거 역탐지 도구 적용.
- 임직원의 **섀도우 AI** (개인 계정 유료 모델) 사용에 대한 기술적 통제 사각지대 :
  - 한계점 : 사내 망에서 임직원이 개인 스마트폰이나 사적 웹 브라우저로 ChatGPT에 소스코드를 붙여넣는 유출 행위 통제 곤란.
  - 해결 방안 : CASB(Cloud Access Security Broker) 및 DLP를 연동하여 기업 네트워크 내 비인가 생성형 AI 사이트 접속 차단 및 사내 폐쇄형 포털(엔터프라이즈 AI) 제공.

## Ⅴ. 생성형 AI 서비스 개발·이용 보안 안내서 (과기정통부·KISA) 적용 및 발전을 위한 기술사적 제언

- '엔터프라이즈 전용 AI 안심존' 인프라 구축 : 사내 데이터가 모델 학습에 재사용되지 않도록 보장하는 기업용 API 계약(Zero Data Retention) 체결 의무화.
- AI 서비스 침해사고 대응 전용 SOP 수립 : 모델 오작동, 대규모 개인정보 환각 유출 발생 시 서비스 즉시 격리 및 가중치 롤백을 수행하는 AI 침해대응 매뉴얼 정비.
- 정기적인 **AI 윤리 및 보안 리터러시** 사내 교육 정례화 : 개발자 대상 시큐어 프롬프트 엔지니어링 교육과 전 임직원 대상 생성형 AI 활용 보안 수칙 준수 서약 체결.
