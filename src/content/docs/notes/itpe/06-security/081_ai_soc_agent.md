## 답안 골격
```text
[AI SOC 에이전트] ◀━━ 머리: Ⅶ 내 의견 (보안관제 경보 피로 해소 완성 → 인간-인공지능 협업(HITL) 기반 자율 관제 파이프라인 구축)
 ┃
 ┣━ Ⅰ 개요 ───── 보안 경보와 자산 맥락을 LLM 에이전트가 조회·분석해 조사 우선순위와 대응 근거를 제안하는 관제 구성
 ┣━ Ⅱ 특징 ───── 다단계 추론 · 경보 분류 지원 · 증거 기반 트리아지(Triage) · 제한된 보안 도구 연동(API/SOAR 호출)
 ┣━ Ⅲ 구조 ───── 경보 수집기(SIEM/XDR 연동) + 컨텍스트 엔진(RAG, 위협 인텔리전스) + LLM 추론 코어 + 행동 실행기(SOAR 플레이북 실행)
 ┣━ Ⅳ 흐름 ───── 보안 이벤트 인입 → 경보 중복 제거 및 컨텍스트 보강 → AI 가설 수립 및 공격 타임라인 분석 → 대응 스크립트 생성 → 인간 승인(HITL) 또는 자율 격리
 ┣━ Ⅴ 비교 ───── AI SOC 에이전트(문맥 이해, 다단계 자율 추론, 동적 대응) vs 전통적 SIEM/SOAR(정적 룰셋, 조건문 기반 정형 플레이북, 오탐 과다)
 ┗━ Ⅵ 실무 ───── AI 환각(Hallucination)에 의한 오차단 방지 / 프롬프트 인젝션을 통한 에이전트 탈취 방어 / 고영향 조치에 대한 인간 개입(HITL) 설계
```
- 필수 키워드: AI SOC 에이전트 · 경보 피로(Alert Fatigue) · 자율 추론(ReAct) · 트리아지(Triage) · SOAR 연동 · 인간 개입(Human-in-the-Loop, HITL)
- 출제 이력: 확인 가능한 공식 제132~140회 원문에서 이 표제어의 직접 문항 미확인. 아래 문항은 예상문제

## 한 줄 본질
- 대량의 보안 경보에서 사건의 우선순위와 증거를 정리하는 데 드는 시간 절감 가능성. LLM 에이전트의 추론 결과는 검증하고, 차단 권한과 오판의 업무 영향은 별도 통제.

## 핵심 그림
```text
[AI SOC 에이전트의 인시던트 자율 트리아지 및 대응 구조]

   [보안 경보 유입] (SIEM, EDR, 클라우드 로그 수십만 건)
          │
          ▼
   ┌────────────────────────────────────────────────────────┐
   │                  AI SOC 에이전트 코어                  │
   │  1. 컨텍스트 보강: RAG (내부 자산 정보 + MITRE ATT&CK)   │
   │  2. 자율 추론 (ReAct): 공격 시나리오 가설 수립 및 검증│
   │  3. 도구 실행: OSINT 검색, EDR 메모리 덤프 조회 API    │
   └──────────────────────────┬─────────────────────────────┘
                              │
               [판단 신뢰도 임계값 검증]
              ┌───────────────┴───────────────┐
       [정책상 자동조치 허용]          [고영향/모호한 이벤트]
              │                               │
              ▼                               ▼
       [범위가 제한된 조치]            [보안 분석가 검토]
       (재조회·티켓 생성 등)         (근거 확인·승인 후 격리)
```

## 핵심 용어
- 트리아지(Triage): 수집된 보안 경보에서 실제 조사가 필요한 사건과 오탐 가능성을 구분하고 대응 우선순위를 정하는 작업
- Human-in-the-Loop(HITL): AI 에이전트가 단독으로 모든 조치를 수행하지 않고, 서버 셧다운이나 전사 계정 잠금 등 비즈니스 영향도가 큰 결정에는 인간 분석가의 최종 승인을 거치도록 설계하는 통제 기제

## 핵심 통찰
- 전통적인 SOAR의 치명적 한계는 '정의되지 않은 패턴'을 만나면 멈추거나 오작동한다는 점임 → AI SOC 에이전트는 공격자의 새로운 변종 기법을 MITRE ATT&CK 매트릭스와 대조하며 문맥(Context)을 이해하고 스스로 다음 조사 단계를 결정함
- AI 관제 품질은 모델 성능과 자산 중요도·로그 품질·위협 맥락·분석자 검증에 함께 좌우됨.
- 에이전트가 침해당하면 공격자가 AI를 조종하여 방화벽을 스스로 열어주는 재앙이 발생할 수 있으므로, 에이전트의 시스템 실행 권한은 최소화하고 강력한 샌드박스에서 격리해야 함

## 이웃 토픽과 구분
- AI SOC 에이전트 vs 전통 SOAR: AI SOC 에이전트 = 비정형 경보를 스스로 추론하고 가설을 검증하는 동적 에이전트 / 전통 SOAR = 사람이 사전에 작성한 `if-then` 플레이북을 실행하는 정적 자동화 엔진

## 문제·원인·대책
- 가상 시나리오: 정상적인 대용량 데이터 이전을 유출로 잘못 분류했을 때 자동 차단의 업무 영향을 검토한다.
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| AI 에이전트의 오탐으로 인한 핵심 비즈니스 서비스 차단 | 정상 업무 맥락 부재 및 AI의 환각(Hallucination)에 의한 과잉 대응 | 영향도 높은 네트워크 차단 조치에 HITL 승인 적용 | 오차단 가능성과 피해 범위 축소 |
| 로그·경보 안의 악성 지시가 분석 결론이나 도구 호출에 영향을 줌 | 비신뢰 관제 데이터를 정책 지시로 취급 | 입력 출처 분리, 도구 권한 제한, 실행 전 독립 정책 검사 | 지시 유입 시 영향 범위 축소 |

## 1교시 예상문제 (10점)
- AI SOC 에이전트의 개념과 안전한 관제 적용 조건을 설명하시오.

## 1교시 10점 답안
- **정의:** 보안 경보와 자산·위협 정보를 조회해 사건의 우선순위와 조사 근거를 제안하거나 제한된 조치를 수행하는 AI 기반 관제 구성.
- **흐름:** 경보 수집 → 맥락 검색·가설 생성 → 증거 확인 → 정책 검토 → 분석가 승인 또는 저위험 자동 조치.
- **통제:** 비신뢰 로그의 프롬프트 인젝션, 환각, 도구 권한 남용에 대비해 권한 제한·기록·고영향 조치 승인.

## 2~4교시 예상문제 (25점)
- AI SOC 에이전트의 구조와 기존 SIEM·SOAR 연계, 오탐·권한 위험 통제를 설명하시오.

## 2~4교시 25점 답안
### Ⅰ. 도입 목적
- 경보 우선순위 지정과 조사 자료 정리에 드는 시간을 줄이되 판단 근거와 책임 경계 유지.
### Ⅱ. 아키텍처
- SIEM/EDR 경보 → 자산·위협 맥락 조회 → 에이전트 분석 → 정책 집행점 → 티켓·SOAR 및 분석가 승인.
### Ⅲ. 역할 구분
- SIEM은 이벤트 수집·상관, SOAR는 정의된 절차 실행, 에이전트는 비정형 증거의 요약·가설 제안에 활용.
### Ⅳ. 운영 검증
- 오탐·미탐, 분석 시간, 증거 일치율, 도구 호출 이력과 차단의 업무 영향을 측정. 고영향 조치는 인간 승인.

## 이렇게 출제된다
- 예상문제: "AI SOC 에이전트의 개념과 관제 아키텍처, 인간 승인(HITL)과 프롬프트 인젝션 방어를 설명하시오." → 요구 포인트: 경보·맥락 수집, 분석 근거 검증, 조치 권한 구분

## 내 의견
- AI가 제시한 경보 요약은 증거와 함께 분석자가 검토하도록 하고, 자동 조치 범위는 오탐 시 업무 영향과 복구 가능성을 시험한 뒤 단계적으로 정할 것. 특정 시점의 인력 대체율은 근거 없이 예측하지 않음.
