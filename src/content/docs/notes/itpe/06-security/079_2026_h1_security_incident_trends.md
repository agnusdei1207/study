## 연관 키워드

- 침해사고(Security Incident), 공급망 공격(Supply Chain Attack), 비인간 신원(NHI, Non-Human Identity)
- 정상 도구 악용(LotL, Living-off-the-Land), 이중 갈취형 랜섬웨어, 디도스(DDoS), 사이버 레질리언스(Cyber Resilience)
- SBOM(Software Bill of Materials), SLSA(Supply-chain Levels for Software Artifacts), WORM(Write Once Read Many), 제로 트러스트(Zero Trust)

## Ⅰ. 2026 상반기 침해사고 위협 점검의 개요

- 핵심 요약 : 2026년 상반기 확인된 침해사고 동향을 바탕으로 공격 경로를 분석하고, 예방과 탐지와 복구 통제를 점검하는 활동.
- 개념 : 2026년 상반기 국내외 침해사고 동향을 근거로 **공급망 공격** (Supply Chain Attack)과 **비인간 신원** (NHI, Non-Human Identity) 탈취 같은 위협 경로를 정리하고, 조직의 방어 통제를 점검하는 위협 분석 활동.
- 배경 및 필요성 : 과기정통부와 KISA의 '2026년 상반기 국내 사이버위협 동향'에 따르면 상반기 침해사고 신고는 1,236건으로 전년 같은 기간보다 19.5% 늘었고, 디도스 신고는 56.7%, 랜섬웨어 신고는 76.8% 증가함. 생성형 AI가 취약점 탐색과 공격 코드 작성에 쓰이면서 공격 준비 시간이 줄어든 점도 함께 지적됨.
- 주요 목적 : 공급망과 계정 탈취 중심의 위협에 맞서 예방, 탐지, 복구를 잇는 방어 체계의 빈틈을 찾는 것.

## Ⅱ. 2026 상반기 침해사고 위협 점검의 특징 및 장점

- 핵심 요약 : 개별 취약점보다 신원과 공급망이라는 연결 고리를 노리는 공격이 늘어, 점검의 초점을 계정과 빌드 파이프라인으로 옮기는 것이 핵심.

1. 공급망 공격 증가 : 개발자 계정과 접근 토큰을 탈취해 악성 패키지를 정상 배포 경로로 밀어 넣음 → 한 번의 침해가 여러 조직으로 확산. Wiz의 2026 상반기 분석에서는 주요 사건 가운데 공급망 공격이 차지하는 비중이 약 25%로 보고됨.
2. 신원 중심 침해 : 소스코드와 로그에 노출된 API 키와 토큰이 정상 세션처럼 쓰여 탐지가 어려움 → 계정 통제와 자격증명 수명 관리가 방어의 중심이 됨.
3. 정상 도구 악용 : 운영체제에 내장된 관리 도구로 공격을 수행해 백신 탐지를 우회 → 행위 기반 로깅과 탐지가 필요함.

## Ⅲ. 2026 상반기 침해사고 위협 점검의 구조 (흐름)

- 핵심 요약 : 초기 자격증명 탈취에서 공급망과 클라우드 확산을 거쳐 데이터 유출이나 랜섬웨어로 끝나는 공격 경로와, 단계별 방어 통제의 대응 구조.

```text
[ 공격 경로 (일반 흐름) ]

자격증명 탈취 (계정, 토큰, API 키)
   ↓
공급망 침투 (악성 패키지, 빌드 파이프라인)
   ↓
정상 도구 악용 (내장 관리 도구 실행)
   ↓
클라우드 확산 → 데이터 유출 또는 랜섬웨어
```

```text
[ 단계별 방어 통제 ]

자격증명 탈취 → 시크릿 스캔, 단기 자격증명
   ↓
공급망 침투 → SBOM 생성, 서명 검증
   ↓
정상 도구 악용 → 스크립트 블록 로깅, 행위 탐지
   ↓
데이터 파괴 → WORM 불변 백업, 복구 훈련
```

## Ⅳ. 2026 상반기 위협 유형의 비교

- 핵심 요약 : 위협 유형마다 주된 공격 수단과 탐지 난이도가 달라, 통제도 유형별로 나누어 설계해야 함.

| 위협 유형 | 주된 공격 수단 | 탐지 난이도 | 주요 방어 통제 |
| --- | --- | --- | --- |
| 비인간 신원 탈취 | 소스코드와 로그에 노출된 API 키, 토큰 수집 | 높음 (정상 세션처럼 보임) | 시크릿 하드코딩 제거, 단기 자격증명, 중앙 금고 관리 |
| 소프트웨어 공급망 오염 | 개발자 계정 탈취, 악성 패키지 배포, 의존성 변조 | 매우 높음 (신뢰된 배포본에 숨음) | **SBOM** 생성, **SLSA** 프레임워크 기반 빌드 무결성 검증 |
| 정상 도구 악용 (LotL) | 내장 관리 도구의 메모리 실행, 무파일 공격 | 높음 (백신 파일 검사 우회) | 스크립트 블록 로깅, 비정상 명령 인자 행위 분석 |
| 이중 갈취형 랜섬웨어 | 자격증명 획득 후 백업 삭제, 데이터 암호화와 유출 병행 | 중간 (대량 입출력과 트래픽 급증) | **WORM** 불변 백업, 외부 전송량 임계치 모니터링 |

- 선택 기준 : 자격증명 위협은 신원 통제, 공급망 위협은 빌드 검증, 데이터 파괴 위협은 복구 체계에 우선 투자하는 순서로 판단함.

## Ⅴ. 2026 상반기 침해사고 위협 점검의 한계와 방안

- 핵심 요약 : 정상 도구 악용, 심층 의존성 변조, 방치된 계정, 백업 관리자 탈취를 행위 로깅, 락파일 검증, 계정 전수 관리, 다중 승인으로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 정상 도구 악용 탐지 어려움 | 관리자의 정상 명령과 공격 명령이 구분되지 않아 오탐과 미탐이 생김 | 파워셸 스크립트 블록 로깅(Windows 이벤트 ID 4104) 활성화, 부모-자식 프로세스 관계 기반 탐지 규칙 적용 | 탐지 규칙 적용률, 오탐률 |
| 심층 의존성 변조 | 간접 의존 패키지가 변조되면 직접 확인한 소스만으로는 악성 코드를 찾기 어려움 | 의존성 잠금 파일의 해시 검증 의무화, 격리 환경에서 동적 분석 수행 | 해시 검증 실패 건수 |
| 방치된 비인간 계정 | 장기간 쓰는 API 키와 서비스 계정의 소유자와 사용 범위가 관리되지 않음 | 계정 전수 조사와 미사용 키 폐기, 단기 토큰 발급 체계로 전환 | 장기 자격증명 잔존 건수 |
| 백업 관리자 탈취 | 공격자가 백업 관리 계정을 얻어 백업 스냅샷을 함께 삭제함 | 백업 삭제에 다중 승인 적용, 보존 기간 중 삭제가 불가능한 WORM 모드 적용 | 다중 승인 우회 시도 건수 |

## Ⅵ. 2026 상반기 침해사고 위협에 대한 기술사적 제언

- 핵심 요약 : 신원, 공급망, 복구를 하나의 거버넌스로 묶어 상시 점검하는 체계를 갖출 때 상반기 위협 경향에 실효성 있게 대응할 수 있음.

1. 신원 거버넌스 : 정보보호 조직이 사람과 기계 계정의 소유자와 권한 기준을 한 체계로 관리하고, 계정 현황을 분기마다 보고하도록 제도화함.
2. 공급망 거버넌스 : 개발 조직이 외부 패키지 반입 기준과 빌드 서명 정책을 전사 표준으로 정하고, 도입 전 검토 절차를 거치도록 함.
3. 복구 거버넌스 : 업무 연속성 담당 부서가 백업 격리와 복구 훈련을 정례화하여, 랜섬웨어 피해 시에도 핵심 업무의 복구 시간을 점검할 수 있도록 함.

## Ⅶ. 결론

- 핵심 요약 : 2026년 상반기 위협은 개별 취약점보다 계정과 공급망이라는 신뢰 연결 고리를 겨냥하는 경향이 뚜렷함.
- 시사점 : 방어의 출발점은 계정과 빌드 파이프라인의 신뢰 검증이며, 이를 복구 체계와 함께 운영해야 피해를 줄일 수 있음.
