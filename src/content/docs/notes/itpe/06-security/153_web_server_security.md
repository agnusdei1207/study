## 연관 키워드

- 웹 서버 보안, 서버 하드닝(Server Hardening), 웹쉘(Web Shell), 심층 방어(Defense in Depth)
- 웹 방화벽(WAF), 디렉토리 리스팅, 보안 헤더, HSTS, CSP
- 요청 스머글링(HTTP Request Smuggling), CDR, 코드형 인프라(IaC), CIS 벤치마크

## Ⅰ. 웹 서버 보안의 개요

- 핵심 요약 : 인터넷에 노출된 웹 서버의 설정과 실행 환경을 강화해 공격 표면을 줄이는 계층형 보안 체계.
- 개념 : 인터넷에서 HTTP(Hypertext Transfer Protocol)·HTTPS(Hypertext Transfer Protocol Secure) 요청을 가장 먼저 처리하는 웹 서버(Apache, Nginx, IIS 등)의 운영체제, 서버 데몬, 프록시 계층을 **서버 하드닝** (Server Hardening, 불필요한 기능을 걷어내고 기본 설정을 강화하는 작업)과 접근 통제로 보호하는 체계(**웹 서버 보안**).
- 배경 및 필요성 : 웹 서버는 80·443 포트를 상시 개방해야 하므로 외부 공격 표면을 없앨 수 없고, 이 표면을 통한 침해는 **웹쉘** (Web Shell) 업로드, 권한 상승, 서비스 중단으로 이어져 피해가 크다. 그래서 서버 데몬부터 방화벽까지 계층마다 공격 면을 줄이는 방어가 필요하다.
- 주요 목적 : 불필요한 서비스와 공격 표면을 제거하고, 웹쉘 실행과 권한 상승을 차단하며, 웹 방화벽(WAF, Web Application Firewall)으로 SQL 인젝션(SQLi, SQL Injection)과 XSS(Cross-Site Scripting)를 걸러내어 웹 서비스의 기밀성·무결성·가용성을 확보.

## Ⅱ. 웹 서버 보안의 특징 및 장점

- 핵심 요약 : 최소 노출, 최소 권한, 실행 차단, 다계층 중첩이 침해 피해 범위를 국소화하는 장점으로 이어지는 방어 방식.

1. 최소 노출 : 불필요한 모듈·HTTP 메서드·서버 배너를 제거 → 공격자가 얻는 버전 정보가 줄어 특정 버전 대상 공격의 준비 비용 상승.
2. 최소 권한 실행 : 웹 데몬을 root가 아닌 비특권 전용 계정으로 구동 → 데몬이 뚫려도 시스템 전체 장악까지 이르는 경로가 제한.
3. 업로드 실행 차단 : 업로드 디렉토리를 정적 파일 서빙 전용으로 제한 → 웹쉘이 저장되어도 스크립트로 실행되지 않음.
4. 브라우저 측 보안 헤더 : HSTS(HTTP Strict Transport Security)는 HTTPS 강제로 다운그레이드 공격을, CSP(Content Security Policy)는 주입된 스크립트의 실행을 완화.
5. 다계층 중첩 : 웹 방화벽, 서버 데몬, 파일 시스템 계층을 겹쳐 둠 → 한 계층이 우회되어도 다음 계층에서 차단되어 단일 장애 지점 제거.

## Ⅲ. 웹 서버 보안의 구조 (흐름)

- 핵심 요약 : 외부 요청이 WAF, 서버 데몬, 호스트 파일 시스템을 차례로 통과하는 3계층 심층 방어 구조.

```text
[ 외부 요청 (HTTPS 443) ]
          ↓
[1계층] 네트워크 · WAF 계층
  - WAF로 SQLi·XSS·웹쉘 요청 차단
  - HTTPS 암호화 종단과 보안 헤더 적용
          ↓
[2계층] 웹 서버 데몬 계층
  - 서버 배너 은닉, 디렉토리 리스팅 차단
  - 불필요한 HTTP 메서드 차단
  - 비특권 계정으로 데몬 실행
          ↓
[3계층] 호스트 OS · 파일 시스템 계층
  - 업로드 디렉토리 실행 권한 제거
  - SELinux·AppArmor 강제 접근 통제
  - 웹쉘 탐지 등 파일 무결성 감시
```

- **디렉토리 리스팅** (Directory Listing) 차단 : 인덱스 파일이 없는 디렉토리에서 파일 목록이 노출되지 않도록 설정(Options -Indexes)에서 비활성화.
- 웹쉘 실행 차단 : 공격자가 업로드한 스크립트를 실행 권한 제거로 막아 정적 파일로만 서빙.

```text
[ 웹쉘 업로드 시도와 차단 지점 ]

공격자의 웹쉘 업로드 요청
          ↓
WAF 악성 업로드 시그니처 검사 → 차단 (1차)
          ↓ (우회 시)
업로드 파일 저장 (정적 경로)
          ↓
실행 요청 → 실행 권한 없음 → 차단 (2차)
```

## Ⅳ. 웹 서버 보안과 인접 보안 체계의 비교

- 핵심 요약 : 웹 서버 보안은 인프라 계층의 기본 설정을, 시큐어 코딩은 소스코드를, WAF는 네트워크 계층의 요청을 맡는 상호 보완 관계.

| 비교 항목 | 웹 서버 보안 (Apache/Nginx) | 시큐어 코딩 (웹 애플리케이션 보안) | 웹 방화벽 (WAF) |
| --- | --- | --- | --- |
| 통제 계층 | 인프라와 서버 데몬 계층 (OS/Daemon) | 소스코드와 비즈니스 로직 계층 | 애플리케이션 계층(L7) 인라인 프록시 |
| 담당 주체 | 시스템 엔지니어, 인프라 보안 담당자 | 소프트웨어 개발자, 시큐어 코딩 점검 담당 | 보안관제 요원, 네트워크 보안팀 |
| 핵심 조치 | 디렉토리 인덱싱 제거, 배너 은닉, 권한 격리 | 입력값 검증, 준비된 문(PreparedStatement), XSS 필터 | 시그니처 기반 HTTP 악성 페이로드 필터링 |
| 방어 대상 | 웹 서버 원격 코드 실행, 설정 오류 | SQLi, XSS, CSRF(Cross-Site Request Forgery) | 알려진 대량 웹 공격 패턴의 인라인 차단 |
| 한계점 | 애플리케이션 로직의 취약점은 방어하지 못함 | 개발자 실수와 레거시 코드 잔존 | 신규 제로데이 공격과 정교한 난독화 우회에 취약 |

- 선택 기준 : 공격이 서버 설정이나 데몬을 노리는지, 애플리케이션 로직을 노리는지, 네트워크 요청 패턴을 노리는지에 따라 담당 계층을 나눔.

## Ⅴ. 웹 서버 보안의 한계와 방안

- 핵심 요약 : 데몬 결함, 프록시 간 해석 차이, 파일 위장 우회를 최소 권한, 구간 통일, 파일 무해화로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 데몬 자체의 취약점 | Apache의 경로 순회 결함(CVE(Common Vulnerabilities and Exposures)-2021-41773)처럼 서버 코드 결함으로 WAF를 우회해 쉘 장악 | 비특권 계정 구동, 컨테이너 격리 배포, 보안 패치의 신속한 적용 | 패치 적용 주기, 미조치 취약점 수 |
| **요청 스머글링** (HTTP Request Smuggling) | 프론트엔드와 백엔드의 Content-Length, Transfer-Encoding 해석 차이로 다른 사용자의 세션 가로채기·변조 | 내부 구간을 HTTP/2 이상으로 통일, 모호한 이중 헤더 요청을 프록시에서 폐기 | 모호한 헤더 요청 차단 건수 |
| 업로드 기능을 악용한 웹쉘 은닉 | 스크립트를 PNG(Portable Network Graphics) 등 정상 이미지에 숨겨 확장자 검사 우회 | 이미지 재인코딩으로 은닉 스크립트 제거, **CDR** (Content Disarm and Reconstruction) 기반 파일 무해화 | 무해화 처리 건수, 업로드 차단 건수 |

## Ⅵ. 웹 서버 보안에 대한 기술사적 제언

- 핵심 요약 : 하드닝 기준의 코드화, 파일 수준 실시간 감시, 커널 수준 관측을 단계적으로 결합해 웹 서버 보안을 상시 운영 체계로 정착.

1. 인프라 조직은 **코드형 인프라** (IaC, Infrastructure as Code)로 CIS(Center for Internet Security) 벤치마크 기준의 하드닝 템플릿을 표준화하여, 서버를 늘릴 때마다 같은 보안 수준이 자동으로 유지되도록 하는 것이 바람직하다.
2. 보안관제 조직은 웹 디렉토리의 파일 생성과 수정 이벤트를 실시간 감시하는 탐지 체계를 상시 가동하고, 새 스크립트가 유입되면 즉시 격리하고 관리자에게 알리도록 구성해야 한다.
3. 정보보호 조직은 웹 서버 프로세스가 셸이나 다운로드 명령을 실행하는 시도를 커널 수준에서 관측하는 기술을 검토하되, 운영 부하와 오탐을 검증한 뒤 단계적으로 도입하는 것이 타당하다.
4. 개발과 인프라 조직은 웹 서버 설정 점검을 배포 파이프라인에 포함시켜, 설정 변경이 운영 환경에 닿기 전에 보안 기준 위반을 걸러내도록 해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 웹 서버 보안은 웹 서비스의 첫 관문에서 기본 설정과 실행 권한을 통제하는 가장 기초적인 방어 계층.
- 시사점 : 웹 서버 보안은 시큐어 코딩과 WAF를 대신하지 못하므로, 세 계층을 함께 운영해야 웹 서비스의 연속성이 확보된다.
