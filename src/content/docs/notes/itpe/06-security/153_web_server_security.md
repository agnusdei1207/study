## 2~4교시 25점 답안

# 웹 서버 보안

## 핵심 개념
- 인터넷을 통해 대외 서비스를 제공하는 웹 서버(Apache, Nginx, IIS 등)의 OS, 웹 데몬, 웹 애플리케이션, 네트워크 전반에 걸친 보안 강화(Hardening) 및 침해사고 예방 체계.
- 외부 직접 노출 특성상 주요 침투 표적이 되므로 시스템 자원 격리, 설정 오류 제거, 취약 서비스 비활성화, 웹 방화벽(WAF) 연계를 통한 다계층 방어가 필수적임.

```
+-------------------------------------------------------------+
|                     웹 서버 다계층 방어 구조                   |
+-------------------------------------------------------------+
| 1. 네트워크 계층   | DMZ 망분리, 방화벽/IPS, 웹 방화벽(WAF)       |
| 2. 운영체제(OS)    | 최소 권한 데몬 계정, 파일 권한(Umask), 패치 |
| 3. 웹 데몬(Server) | 디렉터리 리스팅 차단, 배너 은닉, 메소드 제한 |
| 4. 웹 앱(App)      | 시큐어 코딩, 입력값 검증, 안전한 세션 관리   |
+-------------------------------------------------------------+
```

## 주요 보안 설정 항목 및 취약점 대응

### 1. 정보 노출 방지 (Banner Grabbing 대응)
- **서버 배너 은닉**: 응답 헤더의 서버 소프트웨어 및 버전 정보(`Server`, `X-Powered-By`)를 제거하거나 마스킹하여 자동화 스캐너에 의한 버전 기반 익스플로잇 방지.
- **맞춤형 에러 페이지(Custom Error Page)**: 404, 500 등 오류 발생 시 디폴트 스택 트레이스나 DBMS 오류 정보 노출을 차단하고 통일된 사용자 안내 화면 제공.

### 2. 디렉터리 및 파일 접근 통제
- **디렉터리 리스팅(Directory Listing) 비활성화**: 기본 인덱스 파일(`index.html` 등)이 없을 때 폴더 내 모든 파일 목록이 브라우저에 출력되는 현상 차단(`Options -Indexes`).
- **상위 디렉터리 접근(Directory Traversal) 차단**: URL 경로 조작(`../`)을 통한 시스템 주요 파일(`/etc/passwd` 등) 접근 차단.
- **불필요한 파일 및 백업본 제거**: 소스코드 백업 파일(`.bak`, `.old`, `.zip`), 설정 샘플 파일, 관리자 매뉴얼 디렉터리 영구 삭제.

### 3. 파일 업로드 보안 및 실행 권한 격리
- **업로드 디렉터리 실행 제한**: 사용자가 업로드하는 폴더에 웹 셸 실행을 방지하기 위해 스크립트 실행 권한(`php`, `jsp`, `asp`, `cgi` 등) 원천 박탈.
- **문서 루트(DocumentRoot) 외 저장**: 업로드된 파일은 웹 루트 외부에 저장하고, 다운로드 시 프록시 스크립트를 거치도록 설계.

### 4. HTTP 메소드 및 통신 프로토콜 통제
- **위험 메소드 차단**: 웹 분산 저작(WebDAV) 및 디버깅 메소드(`PUT`, `DELETE`, `TRACE`, `CONNECT`)를 비활성화하고 `GET`, `POST`, `HEAD`만 허용.
- **안전한 전송 프로토콜 강제**: 평문 HTTP(80) 요청을 HTTPS(443)로 강제 리다이렉트하고, HSTS 헤더를 적용하여 다운그레이드 공격(SSL Strip) 차단.

## 주요 웹 보안 헤더 규격

| 보안 응답 헤더 | 설정 예시 | 방어 목적 |
|---|---|---|
| **HSTS** | `Strict-Transport-Security: max-age=31536000; includeSubDomains` | 평문 통신 차단 및 브라우저 강제 HTTPS 연결 |
| **CSP** | `Content-Security-Policy: default-src 'self'` | 비인가 스크립트 실행 차단 및 XSS 방어 |
| **X-Frame-Options** | `X-Frame-Options: DENY` | 타 사이트 iframe 삽입 차단 및 클릭재킹 방어 |
| **X-Content-Type-Options** | `X-Content-Type-Options: nosniff` | MIME 스니핑 방지로 스크립트 오작동 차단 |
| **Referrer-Policy** | `Referrer-Policy: strict-origin-when-cross-origin` | 외부 사이트 전이 시 민감 경로 정보 누출 방지 |

## 결론 및 실무 시사점
- 웹 서버 보안은 단순한 웹 방화벽 도입에 그치지 않고, OS 계정 권한 분리, 웹 데몬의 하드닝, 보안 헤더 구성이 통합 적용되어야 함.
- 주요정보통신기반시설 기술적 취약점 분석·평가 기준 및 KISA 웹 서버 보안 가이드라인에 따른 정기적인 취약점 점검과 자동화된 보안 패치 관리가 필수적임.
