## 30초 인출

- **본질:** 웹 서버 보안은 외부 요청을 받는 서버의 설정·권한·통신 경계를 통제해 서비스와 데이터를 보호하는 활동.
- **메커니즘:** 요청을 필요한 경로·메서드로 제한하고 파일·프로세스 권한을 줄이며 TLS와 응답 정책을 적용.
- **핵심:** 공개 범위 최소화, 업로드 파일 격리, 설정 변경 검증.

<details>
<summary>핵심 용어</summary>

- **웹 서버 보안**: HTTP 요청을 처리하는 서버의 공개 자원·설정·통신·실행권한을 보호하는 통제.
- **TLS(Transport Layer Security)**: 통신 상대 인증과 전송 데이터의 기밀성·무결성을 제공하는 프로토콜.
- **HSTS(HTTP Strict Transport Security)**: 브라우저가 해당 사이트에 HTTPS 연결을 사용하도록 알리는 응답 정책.
- **CSP(Content Security Policy)**: 브라우저에서 허용할 콘텐츠 출처를 제한하는 응답 정책.
- **웹 루트**: 웹 서버가 외부에 제공할 파일을 찾는 기준 디렉터리.

## 2~4교시 25점 답안

## Ⅰ. 웹 서버 보안의 정의와 목적

| 구분 | 내용 |
|---|---|
| 정의 | **웹 서버 보안**은 외부 요청을 처리하는 서버의 공개 자원·설정·통신·권한을 보호하는 통제 |
| 목적 | 비인가 접근·정보 노출·악성 파일 실행·서비스 장애 예방 |

웹 서버 설정은 애플리케이션의 인증·인가·입력 검증과 함께 작동해야 하는 경계 통제.

## Ⅱ. 노출면과 통제 영역

```text
웹 서버
  ├─ 요청 ─ 경로·메서드 제한
  ├─ 파일 ─ 웹 루트·업로드 격리
  ├─ 실행 ─ 프로세스 최소 권한
  ├─ 통신 ─ TLS·인증서 관리
  └─ 응답 ─ 보안 헤더·캐시 정책
```

| 노출면 | 위험 | 설정 원칙 |
|---|---|---|
| 경로·메서드 | 관리 화면·백업 파일 노출 | 필요한 자원·메서드만 공개 |
| 파일·업로드 | 악성 스크립트 실행 | 확장자·내용 검사, 실행 영역 분리 |
| 프로세스 | 서버 침해 뒤 권한 확대 | 서비스 계정·파일 권한 최소화 |
| 통신·응답 | 도청·브라우저 오용 | TLS와 상황에 맞는 보안 헤더 |

## Ⅲ. 파일·권한 보호

```text
업로드 요청
    ↓ 형식·크기·내용 검사
웹 루트 밖 저장
    ↓ 실행권한 제거
인가된 다운로드 경로만 제공
```

| 대상 | 통제 |
|---|---|
| 웹 루트 | 소스·환경설정·백업 파일 제외 |
| 업로드 | 임의 파일명, 허용 형식, 악성코드 검사 |
| 서비스 계정 | 쓰기·실행·관리 권한 분리 |

## Ⅳ. 통신·응답·운영 점검

```text
설정 기준 작성
    ↓ 배포 설정 검증
TLS·헤더·경로 시험
    ↓ 운영 중 로그·패치 점검
설정 변경 시 재검증
```

| 점검 항목 | 목적 |
|---|---|
| TLS·인증서 | 상대 인증과 전송 보호 |
| HSTS·CSP 등 | HTTPS 강제와 브라우저 콘텐츠 제한 |
| 로그·오류 응답 | 사고 분석과 민감정보 노출 방지 |
| 패치·설정 변경 | 알려진 취약점과 설정 이탈 관리 |

보안 헤더는 방어를 돕지만 서버의 접근통제나 애플리케이션 입력 검증을 대체하지 않는 보조 통제.

## Ⅴ. 한계와 제언

| 한계 | 대응 |
|---|---|
| 서버 설정만 강화하고 애플리케이션의 권한·업로드 처리 오류를 놓침 | 서버·애플리케이션·저장소의 경계별 테스트를 한 배포 점검에 연결 |
| 수동 설정 변경으로 운영 서버 간 기준이 달라짐 | 설정 형상관리와 배포 후 외부 관점 자동 검증 |
