## Ⅰ. 웹 서버 보안의 개요

- **개념** : 인터넷에 직접 노출되어 클라이언트의 HTTP/HTTPS 요청을 최초로 수신·처리하는 웹 서버(Apache, Nginx, IIS 등)의 시스템 운영체제, 서버 소프트웨어 데몬, 네트워크 인터페이스 및 웹 애플리케이션 프록시 계층을 내외부 사이버 위협으로부터 방어하기 위한 종합적인 보안 하드닝(Hardening) 및 접근 통제 체계.
- **배경 및 필요성** : 웹 서버는 공인 인터넷에 상시 80/443 포트를 개방해야 하는 구조적 특성상 해커들의 최우선 타깃이 되며, 서버 데몬의 취약점이나 부실한 기본 설정(Default Configuration)으로 인해 웹쉘 업로드 및 침해 사고가 빈발함.
- **핵심 목적** : 불필요한 서비스와 공격 표면을 제거하고, 시스템 권한 상승 및 웹쉘 실행을 차단하며, 웹 방화벽(WAF) 및 시스템 하드닝을 통해 웹 서비스의 연속성과 기밀성을 확보.

## Ⅱ. 웹 서버 보안의 핵심 아키텍처 및 동작 메커니즘

웹 서버 보안은 운영체제 커널 계층, 웹 서버 데몬 설정 계층, 전면 웹 방화벽(WAF) 계층, 런타임 파일 시스템 무결성 계층의 다계층 심층 방어(Defense in Depth) 아키텍처로 구성됨.

```text
[ 웹 서버 다계층 심층 방어(Defense-in-Depth) 아키텍처 ]

 [ 외부 인터넷 사용자 ]
            |
            v (HTTPS: 443 포트)
 +-------------------------------------------------------------+
 | 1. 네트워크 및 전면 방어 계층 (WAF / DDoS 방어)             |
 |  * 클라우드 WAF / 하드웨어 WAF (ModSecurity 등)             |
 |  * 악성 SQLi, XSS, 웹쉘 업로드 요청 사전 차단              |
 |  * SSL/TLS 암호화 종단 및 보안 헤더(HSTS 등) 강제          |
 +------------------------------+------------------------------+
                                |
                                v
 +-------------------------------------------------------------+
 | 2. 웹 서버 데몬 하드닝 계층 (Nginx / Apache / IIS)          |
 |  * ServerTokens Prod / ServerSignature Off (서버 배너 은닉) |
 |  * 디렉토리 리스팅(Directory Listing / Browsing) 원천 비활성화|
 |  * 불필요한 HTTP 메서드(PUT, DELETE, TRACE) 차단            |
 |  * 최소 권한 전용 비특권 계정(nobody/www-data)으로 데몬 실행|
 +------------------------------+------------------------------+
                                |
                                v
 +-------------------------------------------------------------+
 | 3. 호스트 OS 및 파일 시스템 격리 계층                      |
 |  * 업로드 디렉토리 실행 권한 제거 (noexec 마운트)          |
 |  * 리눅스 chroot jail / 도커 컨테이너 격리 환경              |
 |  * SELinux / AppArmor 강제 접근 통제(MAC) 적용              |
 |  * 실시간 웹쉘 탐지기(Webshell Detector) 파일 감시          |
 +-------------------------------------------------------------+
```

- **서버 배너 및 버전 정보 은닉** : HTTP 응답 헤더의 'Server' 및 'X-Powered-By' 필드에서 구체적인 웹 서버 종류와 버전 번호를 감추어 특정 버전 대상 익스플로잇 사전 차단.
- **디렉토리 리스팅(Directory Listing) 차단** : 인덱스 파일이 없는 디렉토리 접근 시 파일 목록이 브라우저에 노출되는 브라우징 취약점을 설정(Options -Indexes)에서 원천 비활성화.
- **업로드 디렉토리 실행 권한 제거** : 공격자가 웹쉘(jsp, php, asp)을 업로드하더라도 서버에서 스크립트로 파싱되어 실행되지 못하도록 업로드 폴더의 실행(Execute) 권한을 박탈하고 정적 파일로만 서빙.
- **보안 헤더(HTTP Security Headers) 적용** : HSTS(Strict-Transport-Security), CSP(Content-Security-Policy), X-Frame-Options, X-Content-Type-Options를 강제 적용하여 브라우저 측면 공격 방어.

## Ⅲ. 웹 서버 보안의 세부 구성 요소 및 비교 분석

| 비교 항목 | 웹 서버 보안 (Apache/Nginx) | 웹 애플리케이션 보안 (시큐어코딩) | 웹 애플리케이션 방화벽 (WAF) |
| --- | --- | --- | --- |
| 통제 계층 | 인프라 및 서버 데몬 계층 (OS/Daemon) | 소스코드 및 비즈니스 로직 계층 | 네트워크 L7 인라인 프록시 계층 |
| 담당 주체 | 시스템 엔지니어, 인프라 보안 담당자 | 소프트웨어 개발자, 시큐어코딩 감사원 | 보안관제 요원, 네트워크 보안팀 |
| 핵심 조치 | 디렉토리 인덱싱 제거, 배너 은닉, 권한 격리 | 입력값 검증, PreparedStatement, XSS 필터 | 시그니처 기반 HTTP 악성 페이로드 필터링 |
| 방어 대상 | 웹 서버 원격 코드 실행(RCE), 설정 오류 | SQLi, XSS, CSRF, 비즈니스 로직 우회 | 알려진 대량 웹 공격 패턴의 인라인 차단 |
| 한계점 | 애플리케이션 취약점 자체는 방어 불가 | 개발자의 실수 및 레거시 코드 잔존 | 신규 제로데이 및 정교한 난독화 우회 취약 |

- 웹 서버 보안은 웹 서비스의 첫 번째 관문이므로, 부실한 기본 설정을 제거하는 서버 하드닝과 웹쉘 실행 차단을 위한 파일 시스템 권한 분리가 필수적임.

## Ⅳ. 웹 서버 보안의 주요 한계점 및 해결 방안

- **웹 서버 데몬 자체의 제로데이 취약점에 따른 RCE 노출** :
  - **한계점** : Apache HTTP Server의 경로 순회(CVE-2021-41773) 등 웹 서버 자체 C/C++ 코드 결함으로 방화벽을 우회해 시스템 쉘 장악.
  - **해결 방안** : 웹 데몬을 root가 아닌 최소 권한 전용 사용자(www-data)로 구동하고 컨테이너 샌드박스(Docker)로 격리 배포.
- **리버스 프록시와 백엔드 간 HTTP 요청 스머글링(Request Smuggling)** :
  - **한계점** : 프론트엔드 Nginx와 백엔드 WAS 간에 Content-Length와 Transfer-Encoding 파싱 방식 차이로 인해 공격자가 다른 사용자의 HTTP 세션을 가로채거나 변조.
  - **해결 방안** : 프론트엔드와 백엔드 간 통신을 HTTP/2 이상으로 통일하거나 모호한 이중 헤더를 포함한 HTTP/1.1 패킷을 프록시 단에서 즉시 드롭.
- **정상적인 대용량 파일 업로드 기능을 악용한 웹쉘 난독화 우회** :
  - **한계점** : 악성 웹쉘을 정상 이미지 파일(PNG/GIF) 내부에 삽입(스테가노그래피)하여 확장자 검사를 우회하고 시스템에 저장.
  - **해결 방안** : 업로드된 이미지를 서버에서 강제로 리사이징(Re-encoding)하여 은닉 스크립트를 파괴하고 CDR 기술을 연동한 파일 무해화 적용.

## Ⅴ. 웹 서버 보안 적용 및 발전을 위한 기술사적 제언

- **코드형 인프라(IaC) 기반 CIS 벤치마크 보안 하드닝 자동화** : Apache 및 Nginx 설정 파일에 CIS Benchmark 보안 권고안을 100% 반영한 Ansible 플레이북을 작성하여 서버 증설 시 일관된 하드닝 자동 적용.
- **웹쉘 실시간 탐지 및 실행 차단 솔루션 상시 가동** : 파일 생성/수정 이벤트를 실시간 감시(Inotify)하여 웹 디렉토리에 새로운 스크립트 파일이 유입될 때 즉시 격리 및 관리자 알림.
- **차세대 eBPF 기반 커널 시스템 콜 감시 체계 도입** : 웹 서버 프로세스가 비정상적으로 /bin/sh, curl, wget 등 시스템 명령어를 실행하려는 시도를 eBPF 레벨에서 감지하여 즉시 프로세스 강제 종료.
