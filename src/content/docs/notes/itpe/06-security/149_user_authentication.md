## 지식 로드맵 내 현재 위치

정보보안 → 접근 통제 → 사용자 인증

## 30초 인출

- **본질:** 사용자 인증은 접근을 요청한 사람이 주장한 계정의 정당한 사용자인지 확인하는 절차.
- **메커니즘:** 계정 식별 → 인증수단 검증 → 세션 발급. 인가는 인증 후 자원별 허용 여부를 판단하는 별도 단계.
- **통찰:** 한계: 강한 로그인 인증도 취약한 계정 복구 경로로 우회 가능 → 방안: 위험도별 피싱 저항성 인증을 적용하고 복구 절차에도 동등한 보호를 적용.

<details>
<summary>핵심 용어</summary>

- **사용자 인증** : 접근자가 주장한 계정의 정당한 사용자인지 인증수단으로 검증하는 절차.
- **인증 요소** : 지식·소유·생체처럼 사용자의 신원을 입증하는 서로 다른 근거.
- **MFA(Multi-Factor Authentication)** : 서로 다른 종류의 인증 요소를 둘 이상 사용하는 인증.
- **FIDO2(Fast Identity Online 2)** : 공개키 암호를 이용해 웹·기기에서 비밀번호 의존을 줄이는 인증 표준군.
- **패스키(Passkey)** : 서비스별 공개키·개인키 쌍을 이용하는 FIDO 기반 인증수단.
- **인가(Authorization)** : 인증된 주체가 특정 자원·행위를 할 수 있는지 판단하는 통제.
</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 내용 |
|---|---|
| 정의 | **사용자 인증** 은 접근자가 주장한 계정의 정당한 사용자인지 확인하는 절차 |
| 목적 | 계정 도용을 줄이고 허가된 주체에게만 후속 접근 판단을 허용 |

식별은 어떤 계정을 쓰는지 밝히는 단계, 인증은 그 계정의 정당한 사용자임을 검증하는 단계, 인가는 인증 뒤 자원 접근을 결정하는 단계.

## Ⅱ. 인증 처리와 피싱 저항성

```text
계정 식별
    ↓
인증수단의 소유·통제 검증
    ↓
위험·정책에 따른 추가 확인
    ↓
세션 발급 → 자원별 인가
```

| 방식 | 장점 | 유의점 |
|---|---|---|
| 비밀번호 | 범용성 | 재사용·피싱·탈취 |
| OTP | 추가 요소 | 중계형 피싱 가능 |
| 패스키·보안키 | 서비스 도메인에 결합된 공개키 검증 | 기기·키 분실 시 복구 설계 |

## Ⅲ. 인증 요소와 다중 요소

```text
인증 요소
  ├─ 지식 ─ 비밀번호·PIN
  ├─ 소유 ─ 보안키·인증 앱
  └─ 생체 ─ 지문·얼굴
       ※ 서로 다른 요소의 조합이 MFA
```

| 조합 | 판정 |
|---|---|
| 비밀번호 + PIN | 지식 요소 두 개: MFA 아님 |
| 비밀번호 + 보안키 | 지식 + 소유: MFA |
| 보안키 + 기기에서의 생체 확인 | 소유 + 생체: MFA 구성 가능 |

생체정보만으로 인증을 끝내는 방식은 유출·위조·복구 위험 검토 필요.

### 운영 통제

```text
등록 ─ 신원·기기 확인
사용 ─ 인증·세션 보호
변경 ─ 새 수단 등록 검증
복구 ─ 분실·탈취 신고와 재발급
```

| 통제 지점 | 검증 항목 |
|---|---|
| 등록 | 계정 소유자와 인증수단 연결 |
| 로그인 | 피싱·무차별 시도·이상 기기 |
| 세션 | 유효기간·재인증 조건 |
| 복구 | 우회 가능한 약한 본인확인 제거 |

## Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 강한 인증수단을 도입해도 복구 절차가 약하면 계정 탈취 가능 | 등록·복구에 동일한 신원 검증과 통지·지연·감사 적용 |
| 인증 성공만으로 모든 자원 접근을 허용하면 권한 남용 | 인증 뒤 자원별 인가와 세션 위험 평가를 별도 운영 |

## Ⅴ. 제언

고위험 계정의 피싱 저항성 인증을 우선 도입하고 인증수단 재등록·복구 경로를 함께 시험.
