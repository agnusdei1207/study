## 지식 로드맵 내 현재 위치

지식 위치: 정보보안 → 접근 통제 → **사용자 인증**

## 30초 인출

- **본질:** 시스템 접근을 요청하는 주체가 자신이 주장하는 식별자(ID)의 정당한 소유자임을 지식·소유·생체 기반의 검증 수단을 통해 입증하고 신뢰 세션을 형성하는 보안 통제
- **메커니즘:** 신원 식별 $\rightarrow$ 인증자(MFA/FIDO2) 검증 $\rightarrow$ 위험 기반 조건부 접근 평가 $\rightarrow$ 세션 토큰 발급 및 자원별 인가(Authorization) 연동
- **통찰:** SMS/푸시 2차 인증의 AitM 피싱 및 MFA 피로 공격은 FIDO2 패스키로 방어하고 취약한 계정 복구 경로는 IAL2 신원 확인으로 결합 필수

<details>
<summary>핵심 용어</summary>

- **MFA (Multi-Factor Authentication)** : 지식, 소유, 생체의 서로 다른 2개 이상의 독립된 요소를 결합한 다요소 인증.
- **AAL (Authenticator Assurance Level)** : NIST SP 800-63B에 정의된 인증자 보안 보증 등급 (AAL1~3).
- **AitM (Adversary-in-the-Middle)** : 리버스 프록시를 통해 로그인 자격증명과 세션 쿠키를 실시간 가로채는 중간자 피싱.
- **MFA Fatigue (피로 공격)** : 피해자에게 푸시 승인 알림을 수백 번 연속 전송하여 실수로 승인하도록 유도하는 사회공학 공격.

</details>

## 2~4교시 예상문제 (25점)

> 사용자 인증의 3대 요소(지식, 소유, 생체)와 NIST SP 800-63B 인증자 보증 등급(AAL1~3)을 설명하고, 중간자 피싱(AitM) 및 MFA 피로 공격에 대응하기 위한 피싱 저항성 인증체계 구축 방안을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 정보시스템에 접근하려는 사용자(주체)가 자신이 주장하는 신원(Identity)의 진정한 소유자임을 사전에 등록된 자격증명(지식, 소유, 생체 정보)을 통해 암호학적으로 검증하는 접근통제 절차 |
| 목적 | 비인가자의 계정 도용, 크리덴셜 스터핑(Credential Stuffing), 무차별 대입 공격을 차단하고, 신뢰된 주체에게만 최소 권한 기반의 자원 접근(인가) 허용 |

- 정보보호의 AAA(Authentication, Authorization, Accounting) 체계 중 첫 번째 관문이며, 경계 기반 보안에서 아이덴티티 중심 제로 트러스트 보안으로 전환되는 핵심 축

## Ⅱ. 사용자 인증의 핵심 기술적 특성

| 특성 항목 | 세부 내용 및 기술적 의미 | 엔지니어링 구현 가치 |
|---|---|---|
| 인증 요소의 독립성 (MFA) | 지식(Know), 소유(Have), 생체(Are) 중 서로 다른 독립 범주 2개 이상을 반드시 결합 | 단일 인증 요소 탈취 시에도 계정 장악 원천 차단 |
| 피싱 저항성 (Phishing Resistance) | 인증 프로토콜과 브라우저의 접속 도메인(Origin/RP ID)이 암호학적으로 상호 결속 | 위조 피싱 사이트에서의 실시간 자격증명 릴레이 무력화 |
| 동적 위험 기반 평가 (Adaptive Auth) | 로그인 시 단말 무결성, IP 위치, 접속 시간, 과거 행위 기준선을 종합 분석해 인증 강도 조절 | 정상 사용자의 편의성 유지 및 이상 징후 발생 시 추가 챌린지 강제 |
| 식별·인증·인가의 엄격한 분리 | 아이디 제출(식별) $\rightarrow$ 소유 검증(인증) $\rightarrow$ 권한 판정(인가)의 단계를 독립 모듈화 | 세션 하이재킹 및 권한 상승 취약점(IDOR) 방지 |

- NIST SP 800-63-4 표준에 따라 신원 확인(IAL), 인증자 검증(AAL), 페더레이션 연계(FAL)를 독립적으로 평가·설계하는 특성 보유

## Ⅲ. NIST SP 800-63B 인증 프로세스 및 피싱 저항성 아키텍처

```text
[NIST SP 800-63B 기준 사용자 인증 및 위험 기반 인가 아키텍처]

  [사용자 단말]                                [인증 및 정책 서버 (PDP)]           [엔터프라이즈 자원 (PEP)]
       │                                                   │                                     │
       │ 1. 신원 식별 요청 (ID 제출)                        │                                     │
       ├──────────────────────────────────────────────────>│                                     │
       │                                                   │ 2. 위험 컨텍스트 평가:               │
       │                                                   │    - 기기 상태 (TPM 무결성)         │
       │                                                   │    - IP 지리적 위치, 비정상 시간    │
       │ 3. 피싱 저항성 FIDO2 챌린지 발송                   │                                     │
       │<──────────────────────────────────────────────────┤                                     │
       │                                                   │                                     │
       │ 4. 로컬 생체 인증 (Touch ID / Windows Hello)      │                                     │
       │    도메인 결속 개인키 서명 (Origin 바인딩)         │                                     │
       │ 5. 서명된 Assertion 전송                          │                                     │
       ├──────────────────────────────────────────────────>│                                     │
       │                                                   │ 6. 공개키 서명 및 챌린지 검증        │
       │                                                   │    AAL3 최고 보안 등급 판정         │
       │ 7. DPoP 결속 단기 Access Token 발급               │                                     │
       │<──────────────────────────────────────────────────┤                                     │
       │                                                                                         │
       │ 8. 보호 자원 요청 (Header: Bearer DPoP Token)                                            │
       ├────────────────────────────────────────────────────────────────────────────────────────>│
       │ 9. 토큰 및 권한(RBAC/ABAC) 검증 후 인가 승인                                            │
       │<────────────────────────────────────────────────────────────────────────────────────────┤
```

| 프로세스 단계 | 핵심 세부 동작 메커니즘 | 통제 결과 |
|---|---|---|
| 1. 식별 및 위험 수집 | 사용자 ID 수신 후 단말 EDR 상태, 위치, 네트워크 IP 등 컨텍스트 텔레메트리 수집 | 초기 위험 점수(Risk Score) 산출 |
| 2. 적응형 인증 요구 | 저위험 시 단말 내장 패스키 인증, 이상 징후 감지 시 하드웨어 보안키 및 추가 검증 강제 | AAL 등급별 맞춤형 챌린지 발송 |
| 3. 피싱 저항성 서명 | 브라우저가 현재 URL을 서명 데이터에 포함하여 하드웨어 보안 영역(SE)에서 비대칭 서명 | AitM 중간자 프록시 사칭 무력화 |
| 4. 세션 인가 및 바인딩 | 서명 검증 후 클라이언트 키에 바인딩된 DPoP 토큰 발급 및 자원 접근 권한 부여 | 세션 쿠키 메모리 도난 재사용 방어 |

## Ⅳ. 사용자 인증 3대 요소 및 방식별 심층 비교

| 비교 항목 | 지식 기반 (Something You Know) | 소유 기반 (Something You Have) | 생체 기반 (Something You Are) | 피싱 저항성 패스키 (FIDO2) |
|---|---|---|---|---|
| 주요 수단 | 패스워드, PIN, 질의응답 | SMS OTP, 모바일 OTP(TOTP), 보안카드 | 지문, 홍채, 안면(Face ID), 정맥 | TPM/SE 내장 비대칭키 + 생체 인식 |
| 대표적 위협 | 브루트포스, 크리덴셜 스터핑, 키로깅 | SIM 스와핑, AitM 리버스 프록시 피싱 | 생체 데이터 도난 유출, 딥페이크 위조 | 기기 분실 시 백업 계정 침해 |
| 복구 용이성 | 비밀번호 재설정으로 즉시 가능 | 물리 토큰 재발급 또는 번호 인증 | 영구 고유치로 유출 시 변경 불가 | 다중 등록 기기 또는 클라우드 키체인 |
| NIST AAL 등급 | AAL1 (기본 등급) | AAL2 (다요소 인증) | AAL2 (단독 사용 불가, 소유와 결합) | AAL3 (최고 보안 등급) |
| 사용자 경험 | 암기 부담, 주기적 변경 피로 | 스마트폰 앱 확인 및 6자리 수동 입력 | 접촉/응시만으로 1초 내 즉시 인증 | 패스워드 없는 원클릭 무암호 인증 |

## Ⅴ. 사용자 인증 시스템 운용 시 엔지니어링 한계와 해결 방안

| 한계 | 방안 |
|---|---|
| SMS OTP 및 모바일 앱 푸시 인증이 Evilginx2 등 AitM(중간자) 역프록시 피싱 도구에 의해 일회용 코드와 세션 쿠키가 실시간 탈취 무력화 | 웹 브라우저가 실제 접속 도메인을 서명 페이로드에 강제 바인딩하는 W3C WebAuthn 기반 FIDO2 패스키(Passkey)를 표준 인증으로 전면 도입 |
| 공격자가 훔친 ID/PW로 심야 시간에 피해자 스마트폰에 수백 번의 푸시 승인을 연속 발송해 실수 승인을 유도하는 MFA 피로 공격(MFA Fatigue) | 단순 예/아니오 승인 팝업을 폐지하고, 로그인 화면에 표시된 2자리 난수를 모바일 앱에 직접 입력하도록 강제하는 수치 매칭(Number Matching) 및 지오펜싱 차단 적용 |
| 강력한 FIDO2 인증을 구축했더라도 단말 분실 후 계정 복구(Account Recovery) 경로에서 취약한 이메일 링크나 상담원 전화 인증을 악용해 우회 탈취 | 계정 복구 및 재등록 절차에 IAL2/3 수준의 강력한 신원 확인(모바일 신분증, 은행 1원 인증, 화상 안면 라이브니스 검증)을 의무화하고 계정 변경 시 24시간 쿨링오프(Cooling-off) 지연 적용 |
| 인증 완료 후 발급된 세션 쿠키나 Bearer 토큰이 정보탈취형 악성코드(RedLine, Lumma 등 Infostealer)에 의해 브라우저 메모리에서 덤프 탈취 | RFC 9449 DPoP(Demonstrating Proof-of-Possession) 및 mTLS를 연동하여 세션 토큰을 클라이언트 비대칭키와 암호학적으로 결속하고, CAEP 프로토콜 기반 이상 징후 실시간 세션 강제 만료 |

## Ⅵ. 제로 트러스트 아이덴티티 및 패스워드리스 전환 제언

```text
[엔터프라이즈 제로 트러스트 사용자 인증 성숙도 로드맵]

 ┌─────────────────────────────────────────────────────────────┐
 │       1단계: 취약 인증 제거 (Legacy Sunset)                 │
 │   - 정적 비밀번호 단독 로그인 및 SMS OTP 전면 폐지          │
 │   - 모바일 OTP 푸시 수치 매칭(Number Matching) 적용         │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │       2단계: 패스워드리스 FIDO2 전환 (AAL3 달성)             │
 │   - 전사 임직원 PC/모바일에 OS 내장 FIDO2 패스키 전면 배포   │
 │   - 특권 관리자 계정에 FIPS 140 Level 3 하드웨어 보안키 강제 │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │       3단계: 지속적 위험 적응형 인증 (Continuous Zero Trust)│
 │   - DPoP 기반 토큰 도난 무력화 및 CAEP 실시간 세션 제어     │
 │   - EDR 단말 무결성 점수와 연동된 실시간 조건부 접근 인가   │
 └─────────────────────────────────────────────────────────────┘
```

| 관리 영역 | 핵심 엔지니어링 세부 과제 | 통제 목표치 |
|---|---|---|
| 피싱 저항성 | 사내 인트라넷 및 전사 SaaS 시스템의 FIDO2 패스키 적용율 | 패스키 적용율 100%, 피싱 탈취 사고 0건 |
| MFA 강화 | 레거시 단순 푸시 승인 폐지 및 2자리 수치 매칭 강제화 | MFA 피로 공격 성공률 0% |
| 토큰 보호 | API 게이트웨이 전 구간 DPoP 및 토큰 바인딩 적용 | 도난 세션 쿠키 재사용 시도 차단율 100% |
