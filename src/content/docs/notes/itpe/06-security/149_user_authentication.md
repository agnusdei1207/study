## 연관 키워드

- 사용자 인증, 신원 확인, 다중 요인 인증(MFA), 적응형 인증, 지속적 인증
- 지식·소유·생체 요인, FIDO2, WebAuthn, 패스키, OTP, TOTP
- 푸시 피로 공격, SIM 스와핑, 번호 매칭, 캔슬러블 바이오메트릭스
- IAM, RBAC, ABAC, 최소 권한 원칙, 제로 트러스트

## Ⅰ. 사용자 인증의 개요

- 핵심 요약 : 신원을 증명하는 여러 증거를 조합해 접근을 통제하고, 위험 신호에 따라 강도를 조절하는 인증 체계.
- 개념 : 시스템에 접근하려는 사용자가 주장하는 **신원** (Identity)이 진짜 본인인지 지식, 소유, 생체 등의 증거로 검증하는 절차.
- 배경 및 필요성 : 비밀번호만 쓰는 단일 요인 인증은 크리덴셜 스터핑, 피싱, 무차별 대입, 키로깅에 취약하다. 그래서 서로 다른 범주의 증거를 결합하는 **다중 요인 인증** (MFA, Multi-Factor Authentication)이 기본 요건으로 바뀌었다.
- 주요 목적 : 비인가자의 신원 도용과 불법 접근을 막고, 위험도에 따라 인증 강도를 달리해 보안과 편의의 균형을 맞추는 것.

## Ⅱ. 사용자 인증의 특징 및 장점

- 핵심 요약 : 요인의 다양성과 위험 기반 판단이 결합되어, 한 요인이 유출되어도 계정 장악을 막는 구조.

1. 요인 결합 : 지식, 소유(**OTP** (One-Time Password) 등), 생체 가운데 서로 다른 범주를 함께 요구 → 비밀번호 하나가 유출되어도 두 번째 요인이 막음.
2. 피싱 저항성 : **FIDO2** 표준(FIDO Alliance 제정)은 인증 정보가 접속 도메인에 묶여 있어 패스키(passkey)를 가짜 사이트에 입력해도 가짜 사이트에 입력해도 쓸모가 없음 → 중간자 피싱 차단.
3. 적응형 판단 : 접속 위치, 기기 상태, 접속 시간을 평가해 필요할 때만 추가 인증 → 사용자 부담과 위험을 함께 줄임.
4. 생체 로컬 처리 : 생체 정보는 단말 안의 보안 영역에서만 매칭되고 서버로 원본이 가지 않음 → 서버 유출 시 생체 정보 노출을 줄임.

## Ⅲ. 사용자 인증의 구조 (흐름)

- 핵심 요약 : 4대 인증 요인을 바탕으로 위험 엔진이 로그인 시점마다 필요한 인증 강도를 정하는 흐름.

```text
[ 4대 인증 요인 ]

지식: 비밀번호, 패턴
소유: OTP, 스마트폰, 보안키
생체: 지문, 홍채, 얼굴
행위·위치: 접속 위치, 입력 패턴
```

```text
[ 적응형 위험 기반 인증 ]

로그인 요청
   ↓
위험 엔진: IP 평판, 국가, 기기 상태 평가
   ↓
위험 낮음 → 기본 인증 통과
위험 높음 → 추가 MFA 또는 차단
```

- 4대 요인 가운데 소유 요인이 가장 많이 쓰이는 방식이며, 위험 평가 결과에 따라 어떤 요인을 추가할지 정하는 것이 적응형 인증의 핵심이다.

## Ⅳ. 사용자 인증 방식의 비교

- 핵심 요약 : 편의성과 비용은 비밀번호가 앞서지만, 보안 강도는 피싱 저항성을 갖춘 방식과 적응형 방식이 앞선다.

| 비교 항목 | 지식 기반 (비밀번호) | 소유 기반 (OTP, 문자 인증) | 생체 기반 (지문, 얼굴) | 적응형 MFA |
| --- | --- | --- | --- | --- |
| 보안 강도 | 낮음 (유출, 피싱 취약) | 중간 (중간자 피싱 가능) | 높음 (위조 난도 높음) | 높음 (문맥 기반 판단) |
| 사용자 편의성 | 낮음 (암기 부담) | 보통 (단말 확인 필요) | 높음 (터치나 응시) | 높음 (위험 시에만 추가 인증) |
| 구축 비용 | 낮음 | 중간 (인증 서버, 문자 발송) | 높음 (센서와 보안 영역) | 높음 (위험 분석 플랫폼) |
| 주요 취약점 | 크리덴셜 스터핑, 무차별 대입 | SIM 스와핑, 푸시 피로 공격 | 생체 정보 유출 시 변경 불가 | 탐지 엔진의 오탐과 미탐 |

- 선택 기준 : 공공과 금융 등 고위험 업무는 피싱 저항성을 갖춘 **FIDO2** 방식을 기본으로 삼고, 일반 업무는 적응형 판단으로 강도를 조절한다.

## Ⅴ. 사용자 인증의 한계와 방안

- 핵심 요약 : 푸시 피로, 생체 정보 불변성, 문자 인증 탈취를 번호 매칭, 템플릿 보호, 앱 기반 OTP 전환으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 푸시 피로 공격 | 탈취한 비밀번호로 승인 요청을 반복 전송해 사용자가 무심코 승인 | 승인 화면에 표시된 숫자를 앱에 입력하는 **번호 매칭** (Number Matching) 강제 | 비정상 승인 요청 건수 |
| 생체 정보 유출 | 생체 정보는 교체할 수 없어 한 번 유출되면 영구적 도용 위험 | 단말 내 보안 영역에서만 매칭하고, 원본 대신 변경 가능한 템플릿을 쓰는 **캔슬러블 바이오메트릭스** (Cancelable Biometrics) 적용 | 템플릿 재발급 건수 |
| SIM(Subscriber Identity Module) 스와핑을 통한 문자 인증 탈취 | 사회공학으로 유심을 복제해 문자 인증번호를 가로챔 | 문자 인증을 폐기하고 앱 기반 **TOTP** (Time-based One-Time Password) 또는 보안키로 전환 | 문자 인증 잔존 비율 |

## Ⅵ. 사용자 인증에 대한 기술사적 제언

- 핵심 요약 : 피싱 저항 인증을 기본값으로 정하고, 세션 중에도 위험을 재평가하며, 권한은 최소 단위로 나누는 방향.

1. 피싱 저항 인증의 기본화 : 내부 업무 시스템은 **WebAuthn** (Web Authentication) 기반 FIDO2 인증을 기본으로 도입하고, 비밀번호만 쓰는 로그인 경로를 단계적으로 닫는다. 미국 행정명령 14028호가 연방 기관에 다중 인증을 요구한 것도 같은 방향이다.
2. 지속적 인증 체계 : 로그인 이후에도 **CAEP** (Continuous Access Evaluation Profile) 같은 신호 공유 방식을 활용해 기기 상태나 네트워크 변화가 생기면 세션을 재평가하는 구조를 마련한다.
3. 권한 거버넌스 통합 : **IAM** (Identity and Access Management) 체계에서 역할 기반 **RBAC** (Role-Based Access Control)과 속성 기반 **ABAC** (Attribute-Based Access Control)을 함께 쓰고, 업무에 필요한 최소 권한만 동적으로 부여한다.

## Ⅶ. 결론

- 핵심 요약 : 사용자 인증은 비밀번호 중심에서 피싱 저항과 위험 기반 판단 중심으로 이동 중인 보안의 첫 관문.
- 시사점 : 인증 강도보다 인증이 어느 시점에 어떤 위험에 맞춰 이루어지는지가 성패를 가르므로, 인증을 제로 트러스트 원칙 아래 세션 전체의 설계로 보아야 한다.
