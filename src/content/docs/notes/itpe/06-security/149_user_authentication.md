## Ⅰ. 사용자 인증의 개요

- 개념 : 정보 시스템에 접근을 시도하는 주체(인간 사용자)가 주장하는 **신원** (Identity)이 진정한 본인임을 신뢰할 수 있는 암호학적 및 물리적 증거를 통해 검증하고 보증하는 정보보호의 최우선 관문 프로세스.
- 배경 및 필요성 : 전통적인 단일 요인(비밀번호) 인증 체계는 크리덴셜 스터핑, 피싱, 무차별 대입, 키로깅 공격에 취약하여 기업 침해 사고의 대부분의 발단이 됨에 따라 **다중 요인 인증** (MFA)으로의 전환이 필수화됨.
- 핵심 목적 : 비인가자의 신원 도용 및 불법 시스템 접근을 원천 방지하고, 적응형(Adaptive) 위험 기반 접근 제어를 통해 보안성과 사용자 편의성의 균형을 달성.

## Ⅱ. 사용자 인증의 핵심 아키텍처 및 동작 메커니즘

사용자 인증은 **4대 인증 요인** (지식, 소유, 생체, 특징/위치)을 기반으로 구성되며, 현대 보안에서는 정적 1회성 로그인을 넘어 지속적 위험 평가를 수행하는 **적응형 인증** (Adaptive MFA)으로 동작함.

```text
[ 4대 사용자 인증 요인 및 적응형 위험 기반 인증(Adaptive Auth) 아키텍처 ]

 +----------------------------------------------------------------------+
 |                    4대 인증 요인 (Authentication Factors)             |
 |                                                                      |
 | [Type 1: 지식 (Knowledge)]   | [Type 2: 소유 (Possession)]           |
 | * 알고 있는 것               | * 가지고 있는 것                      |
 | * 비밀번호, PIN, 패턴        | * OTP 토큰, 스마트폰, 하드웨어 키(FIDO)|
 | -----------------------------+-------------------------------------- |
 | [Type 3: 고유 존재 (Inherence)| [Type 4: 행위/위치 (Context/Behavior)]|
 | * 본인 자체 (생체 정보)      | * 있는 곳, 행동하는 패턴              |
 | * 지문, 홍채, 얼굴, 정맥     | * GPS 위치, 타이핑 습관, 마우스 궤적  |
 +----------------------------------+-----------------------------------+
                                    |
                                    v
 [ 적응형 위험 기반 인증 엔진 (Adaptive Risk Engine) ]
  * 접속 IP 평판, 접속 국가, 디바이스 보안 상태(EDR), 접속 시간 분석
                                    |
         +--------------------------+--------------------------+
         | (위험도: Low - 평소와 동일)| (위험도: High - 해외 심야 접속)
         v                          v
 [ 1차 인증 통과 (SSO/FIDO) ]   [ 강화된 추가 MFA 요구! ]
  * 무감지(Passwordless) 로그인  * FIDO2 보안키 터치 또는 모바일 푸시 인증
                                * 위험도 극상 시 접속 즉각 차단
```

- **지식 기반 인증(What you know)** : 비밀번호, PIN 등 사용자의 기억에 의존하며 구현이 간편하나 망각 위험과 유출 및 무차별 대입 공격에 취약.
- **소유 기반 인증(What you have)** : 물리적 OTP 토큰, SMS 인증 문자, 스마트폰 앱, 하드웨어 보안 키(YubiKey) 등을 소유하고 있음을 증명.
- **생체 기반 인증(What you are)** : 지문, 홍채, 얼굴, 음성 등 개인 고유의 신체적 특성을 활용하며 위조가 극히 어려우나 유출 시 영구적 변경이 불가능한 한계 존재.
- **다중 요인 인증(MFA: Multi-Factor Authentication)** : 서로 다른 범주의 2가지 이상의 요인(예: 비밀번호 + OTP)을 필수 결합하여 단일 요인 유출 시에도 계정 장악을 완벽 차단.

## Ⅲ. 사용자 인증의 세부 구성 요소 및 비교 분석

| 비교 항목 | **지식 기반** (비밀번호) | **소유 기반** (OTP / SMS) | **생체 기반** (지문 / FaceID) | **적응형 MFA** (Adaptive) |
| --- | --- | --- | --- | --- |
| 보안 강도 | 낮음 (유출 및 피싱 취약) | 중간 (중간자 피싱 가능) | 높음 (위조 난이도 극상) | 극상 (문맥 기반 동적 방어) |
| 사용자 편의성 | 낮음 (복잡한 패스워드 암기) | 보통 (별도 단말 확인 필요) | 높음 (터치/응시만으로 완료) | 최상 (위험 시에만 선택적 인증) |
| 구축 비용 | 극도로 저렴 | 중간 (인증 서버/SMS 발송비) | 높음 (센서 및 전용 칩 필요) | 높음 (AI 위험 분석 플랫폼) |
| 핵심 취약점 | 크리덴셜 스터핑, 브루트포스 | 심스왑(SIM Swap), MFA 피로 공격 | 생체 템플릿 유출 시 불변성 | 이상 탐지 엔진의 오탐/미탐 |
| 최신 트렌드 | Passwordless로 전면 퇴출 | FIDO2 패스키로 전환 추세 | FIDO 생체 단말 로컬 매칭 | 제로 트러스트 필수 통제 채택 |

- 단순 2FA는 피싱 및 푸시 피로(MFA Fatigue) 공격에 우회될 수 있으므로, 암호학적으로 도메인이 바인딩된 피싱 저항(Phishing-resistant) FIDO2와 적응형 컨텍스트 인증 결합이 필수적임.

## Ⅳ. 사용자 인증의 주요 한계점 및 해결 방안

- MFA 푸시 피로(MFA Fatigue / Push Bombing) 공격에 의한 사용자 승인 :
  - 한계점 : 공격자가 탈취한 비밀번호로 심야 시간에 수십 번의 로그인 푸시 알림을 연속 전송하여 사용자가 무심코 '승인' 버튼을 누르도록 유도.
  - 해결 방안 : 단순 승인 버튼을 폐지하고, 로그인 화면에 표시된 2자리 숫자를 모바일 앱에 직접 입력하도록 하는 번호 매칭(Number Matching) 강제.
- 생체 정보 유출 시 복구 및 재발급의 원천 불가능성 :
  - 한계점 : 비밀번호는 유출 시 즉시 변경할 수 있으나, 지문이나 홍채 데이터는 평생 변경할 수 없어 한 번 유출되면 영구적인 신원 도용 위험.
  - 해결 방안 : 서버에 생체 원본을 전송하지 않고 단말 내 격리 영역(TEE)에서만 로컬 매칭하는 FIDO 원칙 준수 및 캔슬러블 바이오메트릭스(Cancelable Biometrics) 적용.
- 통신사 SIM 스와핑(SIM Swapping)을 통한 SMS 2차 인증 가로채기 :
  - 한계점 : 사회공학적 기법으로 피해자의 유심(USIM)을 공격자 폰으로 불법 복제하여 금융 및 포털의 SMS 인증번호를 가로채 계정 탈취.
  - 해결 방안 : SMS 기반 인증을 기업 및 금융 시스템에서 전면 폐기하고 모바일 앱 기반 OTP(TOTP) 또는 하드웨어 보안키로 전환.

## Ⅴ. 사용자 인증 적용 및 발전을 위한 기술사적 제언

- 피싱 저항 다중 인증(Phishing-Resistant MFA) 전사 의무화 : 미국 백악관 행정명령(EO 14028) 및 CISA 지침에 따라 공공 및 주요 기업의 내부 업무망에 FIDO2/WebAuthn 표준 인증 의무 적용.
- 지속적 적응형 접근 평가(CAEP / Continuous Authentication) 도입 : 로그인 시점의 1회성 인증을 넘어, 세션 유지 중에도 기기 탈옥 여부, IP 변경, 마우스 타이핑 동역학을 지속 재평가하여 이상 시 즉시 재인증 요구.
- 통합 계정 거버넌스(IAM)와 최소 권한 원칙(Least Privilege) 결합 : 인증 성공 후에도 사용자 역할(RBAC) 및 상황 속성(ABAC)을 동적 평가하여 업무 수행에 필요한 최소한의 애플리케이션 권한만 인가.
