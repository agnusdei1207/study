## Ⅰ. GADI의 개요

- **GADI**(Global Architecture for Digital Identity)는 DID Alliance가 제안한 디지털 신원 체계 간 **상호운용성**과 신뢰 연결을 위한 아키텍처 구상.
- 목적 : 서로 다른 국가·기관·서비스의 신원 체계를 연결하면서 사용자와 기관의 신뢰 관계를 관리하고 디지털 신원 이용의 포용성 확대.
- 지위 : 특정 산업 연합의 아키텍처 구상과 W3C·ITU 등의 개별 표준을 구분. GADI라는 명칭만으로 모든 국가에서 법적으로 통용되는 신원 표준이나 구현 완료 상태를 의미하지 않음.

## Ⅱ. 신원 상호운용의 구성 관점

| 관점 | 확인할 사항 | 설계상의 의미 |
|---|---|---|
| 신원 확인 | 발급·등록 과정과 실제 주체 확인 수준 | 식별자 보유와 실제 인물 신뢰도를 구분 |
| 기술 연결 | 식별자·자격증명·인증 프로토콜 | 서로 다른 신원 체계의 교환·검증 방식 결정 |
| 신뢰 연결 | 발급기관 자격, 책임, 폐기·상태 관리 | 서명 검증 성공과 발급기관 신뢰를 구분 |
| 이용자 보호 | 최소 정보 공개, 동의·통제, 복구 | 접근성·프라이버시·사용 편의의 절충 |

- **탈중앙 식별자**(DID, Decentralized Identifier)는 식별자와 검증 방법 등을 연결하는 W3C 표준. DID 자체가 분산 원장이라는 뜻은 아니며 모든 DID 방식이 블록체인을 요구하지 않음.
- **검증 가능한 자격증명**(VC, Verifiable Credential)은 발급자·보유자·검증자 간 자격 정보를 표현하는 모델. 영지식 증명이나 특정 원장이 모든 자격증명의 필수 구성은 아님.
- **검증 가능한 제시**(VP, Verifiable Presentation)와 선택적 공개는 채택한 데이터 형식·암호 방식 및 교환 프로토콜에 따라 지원. 표준 명칭만으로 즉시 호환성이 보장되지 않음.

## Ⅲ. 관련 개념과의 구분

| 구분 | 주된 역할 | GADI와의 관계 |
|---|---|---|
| 자기주권신원(SSI, Self-Sovereign Identity) | 이용자 중심의 신원 통제 원칙 | 관련 설계 방향이나 GADI와 동일한 규격은 아님 |
| DID·VC | 식별자와 자격증명 모델 | 신원 연결에 활용 가능한 개별 표준 |
| Trust over IP(ToIP) | 기술·거버넌스 신뢰 체계 | 별도 프레임워크로 적용 범위 확인 필요 |
| OpenID Connect·SAML | 인증 및 연합 신원 연결 | 기존 체계와 연계 시 프로토콜·신뢰 정책 검토 |

- 신원 아키텍처의 분산 정도와 개인정보 보호 수준은 별개. 발급·복구·검증 서비스의 장애점, 추적 가능성 및 사용자 정보 공개 범위를 실제 구현에서 확인.
- 참고 : [ITU WSIS의 DID Alliance·GADI 소개](https://www.itu.int/net4/wsis/forum/2021/en/Agenda/Session/264), [W3C DID Core](https://www.w3.org/TR/did-core/), [W3C VC 데이터 모델](https://www.w3.org/TR/vc-data-model-2.0/).

## Ⅳ. 디지털 신원 상호운용의 한계점 및 해결 방안

- 기술적으로 검증 가능하나 법적으로 인정되지 않는 신원 : 국가·기관별 신뢰 프레임워크와 책임·증거 요건 확인.
- 키·기기 분실과 복구 위험 : 신원 재확인과 키 교체·폐기·백업 정책을 함께 설계.
- 개인정보 상관분석과 원장 기록 위험 : 직접 식별정보뿐 아니라 해시·식별자의 연결 가능성을 평가하고 데이터 최소화·공개 범위 통제.

## Ⅴ. 디지털 신원 아키텍처 적용을 위한 제언

- 특정 아키텍처 이름이나 블록체인 채택 여부보다 실제 신원 확인 수준, 발급기관 신뢰 및 이용자 보호를 기준으로 평가.
- 연결할 서비스 사이에서 자격증명 형식·상태 확인·키 교체·오류 처리의 호환성을 시험하고 법적 인정 범위를 함께 확인.
