## 지식 로드맵 내 현재 위치

정보보안 → 암호학 → 대칭키 암호화(Symmetric Key Encryption) 및 키 관리

## 30초 인출

- **본질:** 암호화와 복호화에 동일한 하나의 비밀키(Secret Key)를 사용하여 대용량 데이터를 고속으로 암·복호화하는 전통적 대칭 암호 체계
- **메커니즘:** 비밀키 공유(KDC/ECDH) → 데이터 암호화(블록: AES/ARIA, 스트림: ChaCha20) → 운용 모드(GCM) 인증 태그 결합 → 수신자 동일 키 복호화
- 통찰: 빠른 연산 속도에도 불구하고 통신 참여자 증가에 따른 키 배송 문제와 관리적 확장성 한계를 극복하기 위해 공개키 기반 키 합의(ECDH) 및 봉투 암호화(DEK/KEK 계층화)를 결합한 하이브리드 키 관리 아키텍처 필수

<details><summary>핵심 용어</summary>

- **대칭키 암호 (Symmetric Cipher):** 송신자와 수신자가 사전에 공유한 동일한 비밀키를 사용하여 암호화와 복호화를 수행하는 방식.
- **키 배송 문제 (Key Distribution Problem):** 안전하지 않은 통신 채널을 통해 도청 없이 대칭 비밀키를 상대방에게 전달해야 하는 본질적 난제.
- **키 개수 복잡도 ($N(N-1)/2$):** $N$명의 사용자가 상호 간 비밀 통신을 위해 1:1 대칭키를 보유할 때 요구되는 총 키의 개수.
- **봉투 암호화 (Envelope Encryption):** 실제 데이터를 암호화하는 데이터 키(DEK)와 DEK를 암호화하여 보호하는 키 암호화 키(KEK)로 계층화하는 기법.
- **AEAD(Authenticated Encryption with Associated Data):** 대칭키 암호화 시 기밀성뿐만 아니라 위변조 방지를 위한 메시지 무결성(MAC)을 동시 제공.

</details>

## 2~4교시 예상문제 (25점)

> 대칭키 암호화(Symmetric Key Encryption)의 동작 원리와 분류(블록 암호 vs 스트림 암호)를 설명하고, 비대칭키 암호화와의 장단점 비교 및 $N(N-1)/2$ 키 관리 한계 극복을 위한 봉투 암호화(Envelope Encryption)와 하이브리드 적용 방안을 제시하시오. (기출·제132회 1교시 4번)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 평문의 암호화 연산과 암호문의 복호화 연산에 동일한 단일 비밀키(Secret Key)를 사용하는 암호화 알고리즘 |
| 목적 | 대용량 데이터베이스, 파일 시스템, 네트워크 스트림 트래픽의 고속 기밀성 보장 및 효율적인 자원 소모 최소화 |

## Ⅱ. 대칭키 암호화의 주요 특징

| 특징 | 세부 내용 | 구현 요소 |
|---|---|---|
| 동일한 비밀키 사용 | 암호화 키 $K$와 복호화 키 $K$가 동일하므로 키의 비밀성 유지가 보안의 절대적 전제 | 비밀키 분배 및 보관 |
| 고속 처리 및 저연산 부하 | 비대칭키 암호화 대비 수백~수천 배 연산 속도가 빠르고 CPU 점유율 및 메모리 오버헤드 극소 | AES-NI 하드웨어 가속 |
| 데이터 처리 방식에 따른 분류 | 고정 크기 블록 단위로 처리하는 '블록 암호'와 연속적 비트/바이트 단위로 처리하는 '스트림 암호' | AES, ARIA vs ChaCha20, RC4 |
| 키 관리 복잡성 증가 | 참여자 수가 $N$명일 때 완전 연결망 구성을 위해 필요한 키의 수가 $O(N^2)$로 급증 | KMS, KDC, 하이브리드 암호 |

## Ⅲ. 대칭키 암호화 아키텍처 및 봉투 암호화 프로세스

```text
[ 1. 대칭키 기본 통신 구조 ]
평문 (Plaintext) ──▶ [ 암호화: E(P, K) ] ──▶ 암호문 (Ciphertext) ──▶ [ 복호화: D(C, K) ] ──▶ 평문
                             ▲                                                ▲
                             └────────── 동일한 비밀키 (K) 공유 ──────────────┘

[ 2. 봉투 암호화 (Envelope Encryption: KMS 연계) ]
대용량 원본 데이터 (DB/파일)
       │
       ▼ (1. 평문 DEK로 초고속 암호화)
암호화된 데이터 저장 ◀── [ AES-256-GCM ] ◀── 메모리 내 단기 데이터 키 (DEK)
                                                  │
                                                  ▼ (2. 마스터 KEK로 DEK 암호화)
                                         [ KMS 내 마스터 키 (KEK) ]
                                                  │
                                                  ▼
암호화된 DEK (Encrypted DEK) ─────────────▶ 데이터와 함께 안전하게 보관/전송
```

| 단계 | 수행 작업 | 핵심 메커니즘 |
|---|---|---|
| 1. 데이터 암호화 | 데이터 암호화 키(DEK)를 메모리에서 생성하여 대용량 평문 데이터를 AES-256으로 고속 암호화 | 고속 블록 암호화, AEAD 인증 태그 생성 |
| 2. 키 암호화 (Wrapping) | 안전한 하드웨어(HSM/KMS) 내에 보관된 키 암호화 키(KEK)로 DEK를 암호화 | 키 래핑(Key Wrapping), 봉투 생성 |
| 3. 평문 DEK 파기 | 암호화 완료 즉시 메모리 상의 평문 DEK를 완전 소거하여 메모리 덤프 공격 차단 | Zeroization, 메모리 보호 |
| 4. 데이터 복호화 | 암호화된 DEK를 KMS로 전송하여 KEK로 복호화한 후, 획득한 DEK로 원본 데이터 복호화 | KMS 권한 인가(IAM 정책) |

## Ⅳ. 대칭키 vs 비대칭키 비교 및 블록 vs 스트림 암호 비교

### 1. 대칭키 암호화와 비대칭키 암호화 비교

| 구분 | 대칭키 암호화 (Symmetric) | 비대칭키 암호화 (Asymmetric) |
|---|---|---|
| 키 구조 | 암·복호화 키가 동일 (비밀키 1개) | 암호화용 공개키(Public) + 복호화용 개인키(Private) 쌍 |
| 연산 속도 | 매우 빠름 (초당 수 Gbps 이상 처리) | 상대적으로 매우 느림 (수학적 거듭제곱 연산) |
| 키 관리 개수 | $N(N-1)/2$ 개 (참여자 증가 시 폭증) | $2N$ 개 (사용자당 공개키/개인키 1쌍) |
| 주요 용도 | 대용량 파일 암호화, DB 암호화, TLS 데이터 전송 | 전자서명, 부인방지, 디지털 인증서, 세션 키 교환 |
| 한계점 | 안전한 초기 키 배송 난제, 부인방지 불가 | 연산 부하로 인한 대용량 데이터 암호화 부적합 |
| 대표 알고리즘 | AES, ARIA, LEA, SEED, ChaCha20 | RSA, ECC, ECDSA, ElGamal, PQC(Kyber/Dilithium) |

### 2. 블록 암호와 스트림 암호 비교

| 구분 | 블록 암호 (Block Cipher) | 스트림 암호 (Stream Cipher) |
|---|---|---|
| 처리 단위 | 고정 크기 블록 (64비트, 128비트 등) | 비트(bit) 또는 바이트(byte) 연속 스트림 |
| 핵심 원리 | 치환(S-Box)과 순열(P-Box)의 다중 라운드 반복 | 의사난수 발생기(PRNG)를 통한 키스트림 XOR |
| 패딩 필요 여부 | 마지막 블록 정렬을 위해 패딩 필요 (PKCS#7) | 패딩 불필요 (평문 길이와 암호문 길이 동일) |
| 대표 알고리즘 | AES, DES, ARIA, LEA | ChaCha20, Salsa20, RC4(폐기) |

## Ⅴ. 대칭키 암호화 운영의 한계와 방안

| 한계 | 방안 |
|---|---|
| 완전 연결 통신망에서 참여자 $N$명 증가 시 $N(N-1)/2$로 키 개수가 폭증하고 안전한 초기 키 배송(Key Distribution) 불가 | 공개키 기반의 타원곡선 디피-헬만(ECDH) 키 교환을 통해 통신 개시 시점에 임시 세션키를 동적으로 합의하거나 Kerberos KDC 도입 |
| 정적 마스터 대칭키를 소스코드, 환경변수, 설정 파일에 하드코딩하여 단일 침해 시 전사 데이터 복호화 위험 노출 | 클라우드 KMS 및 온프레미스 HSM을 연계한 2계층 봉투 암호화(Envelope Encryption) 적용 및 최소 90일 주기 키 자동 회전(Key Rotation) 수립 |
| 단순 대칭키 암호화(CBC 등)는 데이터의 위변조(Bit-flipping)를 감지하지 못하여 기밀성은 유지되나 무결성 훼손 취약 | 기밀성과 무결성(MAC)을 단일 패스로 동시에 검증하는 인증 암호화 표준인 AEAD(AES-GCM, ChaCha20-Poly1305) 전면 의무화 |

## Ⅵ. 제언

```text
[ 전통적 단순 대칭키 운용 ]           [ 하이브리드 봉투 암호화 거버넌스 ]
정적 키 하드코딩 ────┐               ┌── 클라우드 KMS / HSM 기반 중앙 키 수명주기
단일 키로 전 데이터 ─┼─→ [ 유출 참사 ] ─┼── 봉투 암호화(DEK/KEK 계층 분리)
무결성 검증 부재 ────┘               └── AEAD (AES-GCM) 기반 기밀성·무결성 일체화
```

| 평가 영역 | 과거 대칭키 운용 | 현대적 하이브리드 운용 | 향후 발전 방향 |
|---|---|---|---|
| 키 배송 및 공유 | 물리적 보안 전달 한계 | ECDH/PQC 기반 자동 키 합의 | 양자키분배(QKD) 기반 물리적 키 주입 |
| 키 저장 보안성 | 서버 로컬 파일 저장 | HSM FIPS 140-3 3등급 격리 | 기밀 컴퓨팅(TEE) 내부 키 격리 연산 |
| 무결성 보증 | 별도 해시 함수 결합 | AEAD 단일 알고리즘 검증 | 포스트 퀀텀 대비 256비트 대칭키 상향 |

대칭키 암호화는 디지털 사회의 방대한 데이터를 초고속으로 보호하는 가장 실용적이고 강력한 기저 기술이며, 비대칭키의 안전한 키 교환과 클라우드 KMS 기반 봉투 암호화가 결합된 하이브리드 아키텍처 구축 필수.
