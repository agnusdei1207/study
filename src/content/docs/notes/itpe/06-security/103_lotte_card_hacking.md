## 한 줄 본질
- 프로젝트 납기 중심의 개발 편의를 위해 운영 DB 실데이터를 외주 인력 단말에 평문 제공한 통제 병목 → 테스트 데이터 가명화 강제 및 단말기 입출력 매체(USB/네트워크) 완전 봉쇄 → 내부 유출 차단 / 개발 및 테스트 작업의 전처리 공수 증가

[취약했던 유출 당시 구조]

        │
  [외주 개발자]

## 핵심 용어
- 데이터 마스킹(Data Masking): 개발·테스트 환경에서 실데이터의 민감정보(주민등록번호, 카드번호)를 형태만 유지한 채 식별 불가능한 값으로 변환하는 보안 기술
- DLP (Data Loss Prevention): 엔드포인트 PC에서 USB 복사, 인쇄, 화면 캡처, 외부 전송 등 중요 데이터의 사외 유출 행위를 실시간 감시하고 차단하는 보안 솔루션

## 핵심 통찰
- 시스템을 해킹하는 가장 쉬운 방법은 시스템을 공격하는 것이 아니라 '시스템 관리자 권한을 가진 인간'을 포섭하는 것임 → 내부 인력 및 상주 외주 인력은 가장 위험한 잠재적 공격 벡터임
- "개발을 위해 어쩔 수 없이 실데이터를 써야 한다"는 개발팀의 주장은 게으름의 산물임 → 운영 DB 덤프를 개발 서버에 복사하는 행위는 예외 없이 즉각적인 파면 및 형사 처벌 대상이어야 함
- DB 접근제어 솔루션이 수천만 건의 SELECT 및 EXPORT 쿼리를 실시간 감지하지 못하고 사후 감사 로그로만 남긴 것이 치명적 실패 요인이었음 → 대량 쿼리 임계치 초과 시 즉시 세션을 강제 종료해야 함

## 이웃 토픽과 구분
- 내부자 데이터 유출 vs 랜섬웨어: 내부자 데이터 유출 = 기밀성(Confidentiality) 침해 및 암시장 판매 목적 / 랜섬웨어 = 가용성(Availability) 파괴 및 업무 마비를 통한 금전 갈취

## 문제·원인·대책
- 사례: 신용카드사 대규모 개인정보 유출 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 외주 직원이 운영 DB에서 수천만 건의 고객 정보 일괄 덤프 | DB 접근 권한의 과도한 부여 및 대용량 추출 행위 모니터링 부재 | DB 접근제어(Query 임계치 차단) 및 쿼리 승인 결재제 | 비인가 대량 데이터 조회 시 실시간 세션 차단 |
| 다운로드된 고객 개인정보를 USB 메모리에 담아 사외 반출 | 엔드포인트 매체 제어 미흡 및 USB 암호화 미적용 | 전사 단말 매체제어(USB 포트 완전 차단) 및 DLP 도입 | 물리적 보조기억장치를 통한 파일 이동 원천 봉쇄 |

## 이렇게 출제된다
- 미출제. 예상: "금융 및 엔터프라이즈 환경에서 내부자 또는 외주 인력에 의한 데이터 유출 사고를 방지하기 위해 구축해야 하는 다층 보안 체계(DB 접근제어, 데이터 마스킹, VDI, 감사 추적)를 설명하시오." → 요구 포인트: Ⅰ 사고 원인 분석 + Ⅲ 개선 통제 아키텍처 + Ⅵ 실무 통제 프로세스

## 내 의견
- [테스트 데이터 생태계의 합성데이터(Synthetic Data) 전면 전환] 마스킹된 데이터조차 결합 분석을 통해 재식별될 위험이 상존함 → 나라면: 실제 고객 데이터에 기반한 마스킹 방식을 전면 폐지하고, 생성형 AI 및 통계적 기계학습 모델을 활용하여 실제 데이터의 분포와 특성만 모사한 '순수 합성데이터'를 생성해 외주 개발 환경에 제공함으로써 유출 위험을 0%로 제거
