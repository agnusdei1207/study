## Ⅰ. 롯데카드 해킹의 개요

- **개념** : 2025년 8월 롯데카드 온라인 결제 서버가 외부 해커에 의해 침해되어 웹셸이 설치되고 대규모 신용정보 및 비밀번호/CVC 정보가 유출된 침해사고.
- **배경 및 필요성** : 외주 관리자 PC 또는 협력업체 경로를 통해 대규모 고객 결제 정보와 금융 데이터가 유출되었던 대표적 금융 침해사고로서, 외주 인력 접근 통제, 개인정보 암호화, 이상 금융거래 탐지시스템(FDS) 강화의 결정적 계기가 됨.
- **핵심 목적** : 전자금융 인프라의 대고객 웹서버 보안 취약점과 결제 데이터 처리 과정의 맹점을 규명하고, 결제 전주기 토큰화 및 웹셸 차단 아키텍처 수립.

## Ⅱ. 롯데카드 해킹의 핵심 아키텍처 및 동작 메커니즘

롯데카드 해킹은(는) 신뢰할 수 있는 보안 구조와 표준화된 절차를 기반으로 동작하며, 세부적인 아키텍처와 구성요소 간의 상호작용 메커니즘은 다음과 같음.

```text
[ 공격 체인 (Cyber Kill Chain) ]
외부 인터넷 ──▶ 온라인 결제 웹서버 (취약점 악용: 파일 업로드 / RCE)
                     │
                     ▼
결제 서버 내 웹셸(WebShell) 설치 ──▶ 파일 무결성 감시(FIM) 우회 및 시스템 명령 셸 획득
                     │
                     ▼
메모리 덤프 및 결제 로그 수집 ──▶ 트랜잭션 중 평문 처리된 카드번호, CVC, 비밀번호 탈취
                     │
                     ▼
외부 C2 서버로 대량 반출 (Exfiltration) ──▶ 장기간 분할 압축 암호화 전송 (Egress 탐지 미비)

[ 전주기 금융 엔지니어링 방어 아키텍처 ]
├── [진입 방어]: WAF(웹방화벽) 웹셸 업로드 차단, 파일 업로드 디렉터리 실행 권한(noexec) 제거
├── [호스트 방어]: 파일 무결성 감시(FIM) 실시간 가동, EDR 기반 비정상 웹 프로세스(cmd/sh) 스폰 차단
├── [데이터 방어]: 메모리 상 CVC 즉시 삭제, 종단 간 암호화(E2EE), 결제 토큰화(Tokenization)
└── [유출/거래 방어]: Egress 트래픽 이상 대역폭 탐지, AI-FDS 기반 유출 카드 실시간 승인 거절
```

- **1. 웹 진입 방어** : 웹셸 패턴(난독화 PHP/JSP) 실시간 탐지 및 업로드 차단 (WAF, RASP(런타임 애플리케이션 자가진단)).
- **2. 서버 실행 격리** : 업로드 디렉터리 내 스크립트 실행 권한 제거(`noexec`) (OS 파일시스템 마운트 옵션, AppLocker).
- **3. 파일 무결성 감시** : 웹 루트 디렉터리 내 신규 파일 생성 시 실시간 경보 및 삭제 (OSSEC, Tripwire, FIM 솔루션).
- **4. 데이터 비식별화** : CVC 및 비밀번호의 디스크 로깅 원천 금지, 메모리 즉시 소거 (결제 토큰화(EMV Tokenization), E2EE 가상 키패드).
- **5. 이상 거래 차단** : 유출 카드 정보 기반의 해외/심야/고액 결제 실시간 스코어링 (규칙+AI 기반 앙상블 이상금융거래탐지시스템(FDS)).

## Ⅳ. 롯데카드 해킹의 주요 한계점 및 해결 방안

- **한계점** : 온라인 결제 승인 과정에서 CVC와 비밀번호가 WAS 메모리에 일시 로드되거나 디버그 로그에 평문 노출되는 취약점.
  - **해결 방안** : 카드사 자체에 CVC 저장을 영구 금지하고, 클라이언트(앱/웹)에서 발급사 결제 코어까지 전용 HSM 암호화 터널(E2EE)을 직결하여 WAS 평문 노출 차단.
- **한계점** : 공격자가 정상 80/443 포트를 통해 웹셸 통신을 수행함에 따라 경계 방화벽에서 C2 트래픽 식별 불가.
  - **해결 방안** : EDR 에이전트를 통해 웹 서버 데몬(`httpd`, `tomcat`)이 하위 프로세스로 셸(`sh`, `bash`, `cmd`)을 실행하는 행위(Living-off-the-Land)를 탐지하여 즉시 프로세스 킬 강제.
- **한계점** : 2주간(8/14~8/27) 대량의 고객 데이터가 외부로 분할 전송되었음에도 네트워크 트래픽 이상 탐지 실패.
  - **해결 방안** : 데이터 유출 방지(NDLP) 솔루션을 Egress 게이트웨이에 구축하여 카드번호 포맷(Luhn 알고리즘) 및 대용량 Outbound 세션 실시간 탐지/차단.
- **한계점** : 유출된 CVC와 비밀번호를 이용해 공격자가 무차별 해외 결제 및 취약 가맹점 결제를 시도하는 2차 피해 발생.
  - **해결 방안** : 유출 의심 계좌에 대해 FDS 위험도를 최고 등급(Score 100)으로 강제 상향하고, 결제 승인 시 고객 폰 FIDO2 생체인증(Step-Up Auth) 의무화.

## Ⅴ. 롯데카드 해킹 적용 및 발전을 위한 기술사적 제언

- **결제 데이터 아키텍처 중심의 거버넌스 및 실행 체계 구축** : 실 카드번호(PAN) 대신 일회용 토큰(Token) 결제 체계 전면 확대 및 CVC 메모리 상시 소거을(를) 적극 추진하여, 결제 서버 침해 시에도 실제 유효 금융 데이터 노출 원천 차단 효과를 극대화해야 함.
- **서버 애플리케이션 보안 중심의 거버넌스 및 실행 체계 구축** : 파일 업로드 디렉터리 전면 분리 및 웹 루트 파일 무결성 감시(FIM) 상시 가동을(를) 적극 추진하여, 웹셸 기반 악성코드 실행 및 백도어 확립 사전 봉쇄 효과를 극대화해야 함.
- **사후 피해 방어 중심의 거버넌스 및 실행 체계 구축** : 머신러닝 기반 차세대 FDS 엔진 연동을 통한 유출 카드 실시간 결제 차단율 향상을(를) 적극 추진하여, 대고객 금전적 피해 제로화 및 전자금융사고 배상책임 리스크 해소 효과를 극대화해야 함.
