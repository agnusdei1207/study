## 지식 로드맵 내 현재 위치

금융 보안 → 결제 인프라 침해사고 → 2025년 롯데카드 해킹 및 웹셸 유출

## 30초 인출

- **본질:** 2025년 8월 롯데카드 온라인 결제 서버(WAS)가 해킹되어 웹셸(WebShell)이 업로드되고, 약 297만 명의 고객 개인신용정보와 28만 명의 카드 비밀번호/CVC까지 유출된 대형 금융 침해사고.
- **메커니즘:** 인터넷 노출 결제 서버 취약점 침투 → 웹셸 설치 및 백도어 확립 → 2주간(8월 14일~27일) 메모리/로그 내 민감 결제 정보 수집 → 외부 C2 서버로 대량 데이터 유출.
- 통찰: 2014년 내부자 물리적 유출과 달리 외부 웹서버 취약점 침투로 발생하였으므로, 파일 무결성 감시(FIM), 메모리 암호화, 결제 데이터 전송 구간 토큰화(Tokenization) 및 이상금융거래탐지(FDS) 고도화 필수.

<details><summary>핵심 용어</summary>

- **롯데카드 해킹 사고(2025)**: 온라인 결제 서버 취약점을 통해 웹셸이 주입되어 카드번호뿐 아니라 CVC, 비밀번호까지 대량 유출된 금융 보안 사고.
- **웹셸(WebShell)**: 웹 서버의 취약점을 통해 업로드되어 공격자가 원격에서 시스템 명령어 실행, 파일 조작, DB 조회를 수행할 수 있도록 지원하는 악성 웹 스크립트.
- **개인신용정보**: 신용정보법상 보호되는 금융거래 정보로, 특히 카드번호, CVC, 비밀번호 등은 유출 시 직접적 부정 결제 피해를 유발하는 핵심 민감 정보.
- **파일 무결성 모니터링(FIM)**: 웹 루트 디렉터리 내에 비인가된 스크립트나 실행 파일이 생성·수정되는 것을 실시간 감지하여 자동 차단하는 보안 기술.
- **FDS(이상금융거래탐지시스템)**: 결제 패턴, 위치, 기기 정보를 인공지능으로 실시간 분석하여 도난·유출된 카드 정보의 부정 결제를 사전 차단하는 시스템.

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 2025년 8월 롯데카드 온라인 결제 서버가 외부 해커에 의해 침해되어 웹셸이 설치되고 약 297만 명의 신용정보 및 28만 명의 비밀번호/CVC가 유출된 침해사고 |
| 목적 | 전자금융 인프라의 대고객 웹서버 보안 취약점과 결제 데이터 처리 과정의 맹점을 규명하고, 결제 전주기 토큰화 및 웹셸 차단 아키텍처 수립 |

## Ⅱ. 2025 롯데카드 침해사고의 핵심 특징 및 사고 개요

| 특징 항목 | 세부 사고 내용 | 보안 및 비즈니스 영향 |
|---|---|---|
| 치명적 결제정보 유출 | 카드번호, 유효기간뿐 아니라 카드 비밀번호 및 CVC 번호까지 대량 노출 | 복제 카드 생성 및 온라인 무단 결제 등 직접적 금전 피해 위험 폭증 |
| 웹셸 기반 장기 잠복 | 결제 서버 내 웹셸을 설치하고 약 2주간(8/14~8/27) 지속적으로 자료 수집 및 반출 | 실시간 침해 탐지 및 Egress 데이터 유출 모니터링 체계 실패 입증 |
| 결제 WAS 구간 침투 | DB 서버 직접 침투가 아닌 결제 트랜잭션이 처리되는 온라인 결제 서버(WAS) 타깃 | 트랜잭션 처리 중 메모리/임시 파일에 잔존하는 평문 결제 데이터 노출 |
| 금융위 중징계 의결 | 전자금융감독규정상 안전성 확보 의무 위반으로 금융위 제재 및 대규모 과징금 부과 | 신용카드 발급 중단 등 영업 제한 및 금융사 신인도 치명타 |
| FDS 긴급 비상 체계 | 유출 고객 대상 카드 전면 무료 재발급 및 24시간 FDS 감시 체계 비상 가동 | 수백억 원의 카드 재발급 비용 및 금융권 부정 결제 보상 비용 발생 |

## Ⅲ. 웹셸 기반 침해 공격 체인 및 전주기 방어 아키텍처

```text
[ 공격 체인 (Cyber Kill Chain) ]
외부 인터넷 ──▶ 온라인 결제 웹서버 (취약점 악용: 파일 업로드 / RCE)
                     │
                     ▼
결제 서버 내 웹셸(WebShell) 설치 ──▶ 파일 무결성 감시(FIM) 우회 및 시스템 명령 셸 획득
                     │
                     ▼
메모리 덤프 및 결제 로그 수집 ──▶ 트랜잭션 중 평문 처리된 카드번호, CVC, 비밀번호 탈취
                     │
                     ▼
외부 C2 서버로 대량 반출 (Exfiltration) ──▶ 약 2주간 분할 압축 암호화 전송 (Egress 탐지 미비)

[ 전주기 금융 엔지니어링 방어 아키텍처 ]
├── [진입 방어]: WAF(웹방화벽) 웹셸 업로드 차단, 파일 업로드 디렉터리 실행 권한(noexec) 제거
├── [호스트 방어]: 파일 무결성 감시(FIM) 실시간 가동, EDR 기반 비정상 웹 프로세스(cmd/sh) 스폰 차단
├── [데이터 방어]: 메모리 상 CVC 즉시 삭제, 종단 간 암호화(E2EE), 결제 토큰화(Tokenization)
└── [유출/거래 방어]: Egress 트래픽 이상 대역폭 탐지, AI-FDS 기반 유출 카드 실시간 승인 거절
```

| 방어 단계 | 세부 통제 과제 | 핵심 엔지니어링 구현 솔루션 |
|---|---|---|
| 1. 웹 진입 방어 | 웹셸 패턴(난독화 PHP/JSP) 실시간 탐지 및 업로드 차단 | WAF, RASP(런타임 애플리케이션 자가진단) |
| 2. 서버 실행 격리 | 업로드 디렉터리 내 스크립트 실행 권한 제거(`noexec`) | OS 파일시스템 마운트 옵션, AppLocker |
| 3. 파일 무결성 감시 | 웹 루트 디렉터리 내 신규 파일 생성 시 실시간 경보 및 삭제 | OSSEC, Tripwire, FIM 솔루션 |
| 4. 데이터 비식별화 | CVC 및 비밀번호의 디스크 로깅 원천 금지, 메모리 즉시 소거 | 결제 토큰화(EMV Tokenization), E2EE 가상 키패드 |
| 5. 이상 거래 차단 | 유출 카드 정보 기반의 해외/심야/고액 결제 실시간 스코어링 | 규칙+AI 기반 앙상블 이상금융거래탐지시스템(FDS) |

## Ⅳ. 2014 카드사 유출(내부자) vs 2025 롯데카드 유출(외부 웹셸) 비교

| 비교 항목 | 2014년 카드 3사 유출 사고 | 2025년 롯데카드 침해 사고 |
|---|---|---|
| 공격 주체 | 외주 FDS 개발 용역 직원 (악의적 내부자) | 불상의 외부 전문 해킹 조직 |
| 유출 매개체 | 물리적 저장매체 (USB 메모리 복사 반출) | 온라인 결제 서버 내 웹셸 및 네트워크 C2 전송 |
| 침해 공격 표면 | 개발 및 테스트 PC의 관리 소홀 (DLP 부재) | 인터넷에 노출된 온라인 결제 웹 서버(WAS) |
| 유출 데이터 항목 | 이름, 주민번호, 카드번호, 직장 정보 등 (CVC 제외) | 기본 신용정보 + 카드 비밀번호 및 CVC 번호 포함 |
| 2차 부정결제 위험 | CVC/비밀번호 미포함으로 직접 결제 불가 (스미싱 악용) | 결제 필수 정보 완비로 온라인 즉각 결제 가능 (위험도 극상) |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 온라인 결제 승인 과정에서 CVC와 비밀번호가 WAS 메모리에 일시 로드되거나 디버그 로그에 평문 노출되는 취약점 | 카드사 자체에 CVC 저장을 영구 금지하고, 클라이언트(앱/웹)에서 발급사 결제 코어까지 전용 HSM 암호화 터널(E2EE)을 직결하여 WAS 평문 노출 차단 |
| 공격자가 정상 80/443 포트를 통해 웹셸 통신을 수행함에 따라 경계 방화벽에서 C2 트래픽 식별 불가 | EDR 에이전트를 통해 웹 서버 데몬(`httpd`, `tomcat`)이 하위 프로세스로 셸(`sh`, `bash`, `cmd`)을 실행하는 행위(Living-off-the-Land)를 탐지하여 즉시 프로세스 킬 강제 |
| 2주간(8/14~8/27) 대량의 고객 데이터가 외부로 분할 전송되었음에도 네트워크 트래픽 이상 탐지 실패 | 데이터 유출 방지(NDLP) 솔루션을 Egress 게이트웨이에 구축하여 카드번호 포맷(Luhn 알고리즘) 및 대용량 Outbound 세션 실시간 탐지/차단 |
| 유출된 CVC와 비밀번호를 이용해 공격자가 무차별 해외 결제 및 취약 가맹점 결제를 시도하는 2차 피해 발생 | 유출 의심 계좌에 대해 FDS 위험도를 최고 등급(Score 100)으로 강제 상향하고, 결제 승인 시 고객 폰 FIDO2 생체인증(Step-Up Auth) 의무화 |

## Ⅵ. 제언

```text
[ 금융 결제 인프라 신뢰 회복 3대 아키텍처 모델 ]

+-------------------------+      +-------------------------+      +-------------------------+
|     1. 무평문 결제      | ---> |     2. 런타임 자가보호  | ---> |     3. AI-FDS 실시간 방어|
| (결제 토큰화 / E2EE 강제|      | (RASP / FIM 실시간 차단)|      | (유출 카드 즉각 승인 거절
+-------------------------+      +-------------------------+      +-------------------------+
```

| 관리 영역 | 핵심 엔지니어링 구현 과제 | 비즈니스 가치 |
|---|---|---|
| 결제 데이터 아키텍처 | 실 카드번호(PAN) 대신 일회용 토큰(Token) 결제 체계 전면 확대 및 CVC 메모리 상시 소거 | 결제 서버 침해 시에도 실제 유효 금융 데이터 노출 원천 차단 |
| 서버 애플리케이션 보안 | 파일 업로드 디렉터리 전면 분리 및 웹 루트 파일 무결성 감시(FIM) 100% 가동 | 웹셸 기반 악성코드 실행 및 백도어 확립 사전 봉쇄 |
| 사후 피해 방어 | 머신러닝 기반 차세대 FDS 엔진 연동을 통한 유출 카드 실시간 결제 차단율 99.9% 달성 | 대고객 금전적 피해 제로화 및 전자금융사고 배상책임 리스크 해소 |

## 출제 이력과 검증 출처

- 제134회 정보관리기술사 (금융 웹애플리케이션 취약점 및 웹셸 대응 방안)
- 금융위원회, 롯데카드 정보유출 침해사고 조사 결과 및 제재 의결 공표
- 금융감독원, 금융권 웹서버 보안 강화 및 파일 무결성 관리 가이드라인
- PCI-DSS v4.0 (Payment Card Industry Data Security Standard) Requirement 3 & 6

## 연결 토픽

- SGI서울보증 랜섬웨어 사고
- 금융분야 망분리 개선 로드맵
- 시큐어 코딩(Secure Coding)
- 비인간 신원(NHI)
