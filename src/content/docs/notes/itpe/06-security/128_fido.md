## 연관 키워드

- FIDO(Fast IDentity Online), FIDO2, WebAuthn, CTAP, 패스키(Passkey), 동기화 패스키
- 공개키 암호, 피싱 저항성, 오리진 바인딩, 인증장치(Authenticator), 패스워드리스(Passwordless)

## Ⅰ. FIDO 인증과 FIDO2의 개요

- 핵심 요약 : 비밀번호 없이 단말의 생체인식이나 보안키로 전자서명을 만들어 인증하는 표준 체계.
- 개념 : 비밀번호 입력 없이(Passwordless) 단말 내 생체인식이나 하드웨어 보안키로 **공개키 암호** (Public Key Cryptography) 방식의 서명을 만들어 사용자를 인증하는 FIDO(Fast IDentity Online) 표준.
- 배경 및 필요성 : 비밀번호 재사용, 키로깅, 크리덴셜 스터핑, 피싱 사이트를 통한 자격증명 탈취가 침해 사고의 주요 경로가 되면서 비밀번호 중심 인증을 대체할 구조가 필요해짐.
- 주요 목적 : 서버가 생체정보나 공유 비밀을 보관하지 않게 하여 서버 침해 시 자격증명 대량 유출을 막고, 피싱 공격에 저항하는 인증 확보.

## Ⅱ. FIDO 인증과 FIDO2의 특징 및 장점

- 핵심 요약 : 개인키의 단말 보관과 도메인 검증이 서버 유출 방지와 피싱 저항으로 이어지는 방식.

1. 개인키의 단말 보관 : 개인키는 단말 보안 영역에서만 생성·보관되고 외부로 나가지 않음 → 서버에 재사용 가능한 비밀이 남지 않아 서버 침해 피해 축소.
2. 생체정보 로컬 처리 : 지문·얼굴 매칭을 단말 안에서만 수행 → 생체정보가 서버로 전송되지 않아 서버 측 유출 위험 제거.
3. **피싱 저항성** (Phishing Resistance) : 브라우저가 실제 접속 도메인을 **오리진 바인딩** (Origin Binding)으로 서명 데이터에 포함 → 가짜 사이트에 제출된 서명은 검증 실패.
4. 표준 기반 호환성 : **WebAuthn** (W3C Web Authentication API)과 **CTAP** (Client to Authenticator Protocol)의 조합으로 주요 브라우저와 OS가 같은 방식을 지원 → 서비스별 자체 구현 부담 감소.

## Ⅲ. FIDO 인증과 FIDO2의 구조 (흐름)

- 핵심 요약 : 등록 때 공개키만 서버에 전달하고, 인증 때 서버 난수에 대한 단말 서명을 공개키로 검증하는 구조.
- **인증장치** (Authenticator) : 개인키를 보관하고 챌린지에 서명하는 단말 내 구성요소이며, 외부 USB 보안키도 여기에 해당.
- **FIDO2** : WebAuthn과 CTAP을 합친 표준 명칭으로, 등록 단계 1회 이후 인증 단계마다 같은 흐름을 반복.

```text
[ FIDO2 인증 흐름 ]

서버 : 일회용 난수(챌린지) 발급
   ↓
사용자 : 생체 확인 또는 보안키 터치
   ↓
인증장치 : 개인키로 챌린지 서명
   ↓
브라우저 : 오리진 정보 포함해 전달
   ↓
서버 : 저장된 공개키로 서명 검증
```

```text
[ FIDO 구성 계층 ]

인증장치 (생체·보안키, 개인키 보관)
   ↓ FIDO CTAP
브라우저 / 모바일 앱 (WebAuthn API)
   ↓ HTTPS (JSON)
서비스 서버 (RP, 공개키 저장)
```

## Ⅳ. FIDO 인증과 FIDO2의 비교

- 핵심 요약 : UAF와 U2F에서 FIDO2를 거쳐 패스키로 이어지며, 호환성과 기기 종속 해소가 확대된 흐름.

| 비교 항목 | FIDO UAF (1.0) | FIDO U2F (1.0) | FIDO2 (WebAuthn/CTAP) | 동기화 패스키 |
| --- | --- | --- | --- | --- |
| 주요 목적 | 모바일 중심 비밀번호 대체 | 비밀번호 + 2차 보안키 | 웹 표준 기반 패스워드리스 인증 | 다중 기기 클라우드 동기화 |
| 동작 환경 | 모바일 앱 (SDK 필요) | 크롬 브라우저 + USB 토큰 | 주요 웹 브라우저와 OS 내장 | 플랫폼 계정 키체인 연동 |
| 인증 형태 | 단일 요인 (생체인증 중심) | 2차 요인 (비밀번호 + 키 터치) | 디바이스 소유 + 생체 등 | 클라우드 계정 소유 + 생체 등 |
| 기기 종속 | 특정 단말에 키 종속 | 특정 USB 키에 종속 | 특정 단말에 종속 (분실 위험) | 종속성 완화 (클라우드 동기화) |

- 선택 기준 : 업무 위험도가 높을수록 기기 종속 키를, 편의성이 중요할수록 동기화 패스키를 택하는 방향으로 정함.

## Ⅴ. FIDO 인증과 FIDO2의 한계와 방안

- 핵심 요약 : 기기 분실 복구, 플랫폼 종속, 레거시 호환성 세 가지 한계를 동기화, 표준 이전, 게이트웨이로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 기기 분실 시 계정 복구 | 개인키가 단말 보안 영역에만 있으면 본인 확인과 재등록 절차가 복잡 | 동기화 패스키 도입과 대체 복구 수단 마련 | 복구 요청 처리 시간 |
| 플랫폼 종속(락인) | 플랫폼 클라우드에 묶여 OS 간 이전이 어려움 | 자격증명 교환 표준(CXP, Credential Exchange Protocol) 지원 | 자격증명 이전 성공률 |
| 레거시 시스템 호환성 | 구형 ERP(Enterprise Resource Planning)와 구형 브라우저가 WebAuthn 미지원 | OIDC(OpenID Connect)·SAML(Security Assertion Markup Language) 기반 IdP(Identity Provider)에서 FIDO2 인증 완결 | 미지원 시스템 비율 |

## Ⅵ. FIDO 인증과 FIDO2에 대한 기술사적 제언

- 핵심 요약 : 편의성과 보증 수준을 업무별로 나누어 패스키를 전사 인증 체계로 단계 도입.
- 공공·금융 로그인 화면에는 패스키 자동완성 연계 UI를 먼저 도입하여, 비밀번호 입력 대신 생체 확인만으로 로그인되는 경험을 제공하는 것이 바람직하다.
- 사내망 접근에서는 SMS(Short Message Service)나 이메일 OTP(One-Time Password) 같은 피싱에 취약한 수단을 단계적으로 줄이고, FIDO2 보안키와 생체 인증을 기본 수단으로 두는 것이 제로 트러스트(Zero Trust) 원칙에 맞는다.
- 일반 업무에는 동기화 패스키를 허용하되, 관리자 권한과 핵심 원장 접근에는 하드웨어 토큰 기반 바인딩 패스키를 요구하는 업무 위험도별 정책을 두는 것이 현실적이다.

## Ⅶ. 결론

- 핵심 요약 : FIDO2와 패스키는 비밀번호를 없애면서도 피싱 저항성과 서버 유출 방지를 함께 확보하는 인증 표준.
- 시사점 : 편의성은 동기화 패스키가, 보증 수준은 기기 바인딩 키가 맡는 이원 구조가 전환 경로로 현실적이다.
