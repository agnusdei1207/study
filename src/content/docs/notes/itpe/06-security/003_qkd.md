## 30초 인출

- **본질:** QKD(Quantum Key Distribution)는 송·수신자가 양자 상태를 이용해 공통 비밀키를 만드는 키 분배 기술
- **메커니즘:** 양자 상태 전송·측정 → 공개 채널에서 기저 대조·오류 추정 → 조건 충족 시 키 정제
- **구분:** QKD는 키 재료를 분배하며, 데이터 암호화는 별도 대칭키 암호 등이 수행

<summary>핵심 용어</summary>

- **QKD (Quantum Key Distribution):** 양자 상태의 전송·측정과 공개 절차를 이용해 송·수신자가 공통 키를 생성하는 방식
- **BB84 (Bennett–Brassard 1984):** 두 개의 측정 기저를 무작위로 선택해 양자 상태를 보내는 대표적인 QKD 프로토콜
- **QBER (Quantum Bit Error Rate):** 표본 비트의 불일치 비율로, 채널 오류와 도청 가능성을 포함한 오류 수준을 추정하는 지표
- **비밀성 증폭 (Privacy Amplification):** 남아 있을 수 있는 상대방의 정보를 줄이도록 오류 정정 후 키를 압축하는 절차
- **PQC (Post-Quantum Cryptography):** 양자컴퓨터 공격에도 안전하도록 설계된 수학적 암호 알고리즘

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **QKD (Quantum Key Distribution)**는 양자 상태의 전송·측정과 공개 절차를 이용해 송·수신자가 공통 비밀키를 생성하는 방식 |
| 목적 | 키 교환 과정에서 도청 가능성을 추정하고 안전한 공통 키를 마련 |

### Ⅱ. 기본 동작

```text
송신자: 무작위 비트·기저 선택
          ↓ 양자 상태 전송
수신자: 무작위 기저로 측정
          ↓ 공개 채널에서 기저 대조
일치한 표본으로 오류 수준 추정
          ↓ 기준 초과 시 중단
오류 정정·비밀성 증폭 → 공통 키
```

공개 채널은 기저·검증 정보를 교환하는 채널이며 인증이 필요. QKD는 생성한 키를 암호통신에 공급하며 응용 데이터를 직접 암호화하지 않음.

**제언:** 적용 구간의 키 수요·물리 경로·중계 노드 신뢰조건을 먼저 검토한 뒤 QKD 도입 여부 결정

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **QKD (Quantum Key Distribution)**는 양자 상태의 전송·측정과 공개 절차를 이용해 송·수신자가 공통 비밀키를 생성하는 방식 |
| 목적 | 키 교환 과정에서 도청 가능성을 추정하고 안전한 공통 키를 마련 |

QKD의 보안성은 프로토콜의 보안 증명과 구현·장비·인증 등 전제조건에 따름. 물리 도청을 절대 차단하거나 전체 통신의 보안을 보장하는 기술은 아님.

## Ⅱ. 구성요소와 역할

| 구성요소 | 역할 |
|---|---|
| 송신기·수신기 | 양자 상태 준비·전송 및 측정 |
| 양자 채널 | 광자 등 양자 상태의 전달 |
| 인증된 공개 채널 | 기저 대조, 표본 검증, 오류 정정 등 후처리 정보 교환 |
| 키 관리 기능 | 정제된 키를 저장·중계·응용에 전달 |

```text
송신기 ── 양자 채널 ── 수신기
   └──── 인증된 공개 채널 ────┘
                 ↓ 후처리
             공통 키
```

## Ⅲ. BB84 기반 키 생성

```text
송신자: 비트·기저 무작위 선택
          ↓ 상태 부호화·전송
수신자: 측정 기저 무작위 선택·측정
          ↓ 공개 채널에서 기저만 대조
일치 기저 비트 선별
          ↓ 표본 오류 추정
오류가 허용 수준을 넘음 ──→ 키 생성 중단
          ↓ 허용 수준 이내
오류 정정 → 비밀성 증폭 → 공통 키
```

기저 대조 때 비트값 전체를 공개하지 않으며, 일부 표본의 불일치율을 이용해 채널의 오류 수준을 평가. 실제 중단 기준은 프로토콜·장비·운영 조건에 따라 정해지므로 하나의 QBER 임계값을 모든 구현에 적용할 수 없음.

| 후처리 단계 | 기능 |
|---|---|
| 오류 추정 | 표본 불일치로 키 생성 가능성 평가 |
| 오류 정정 | 송·수신자의 선별 비트 일치 |
| 비밀성 증폭 | 잠재적 누출 정보를 제한하도록 최종 키 압축 |

## Ⅳ. QKD와 PQC 비교

| 구분 | QKD | PQC |
|---|---|---|
| 기반 | 양자 상태 전송·측정 | 양자컴퓨터 공격을 고려한 수학적 암호 알고리즘 |
| 기능 | 키 재료 분배 | 키 설정 또는 전자서명 등 암호 기능 |
| 적용 조건 | 양자 장비·채널 및 키 관리 인프라 | 표준 알고리즘을 소프트웨어·기존 시스템에 통합 |
| 주요 검토점 | 거리·채널·장비 구현·중계 신뢰성 | 알고리즘 선택·성능·기존 프로토콜 호환성 |

두 기술은 대체 관계로만 볼 수 없으며, 보안 요구와 운영환경에 따라 함께 사용할 수 있음.

## Ⅴ. 적용 한계와 대응

| 한계 | 대응 방안 |
|---|---|
| 광 채널 손실과 장비 조건이 키 생성률·거리 제약으로 연결 | 실제 경로의 링크 예산과 키 수요를 측정하고 적용 구간을 선정 |
| 중계 구조의 신뢰 노드에서 키 노출 가능성 | 노드 접근통제·변조탐지·키 수명주기 통제를 적용하고 신뢰 경계를 명시 |
| 양자 장비만으로 단말·응용 데이터 보호가 완성되지 않음 | 인증된 키관리와 대칭키 암호, 종단 간 보안통제를 함께 설계 |
| 구현 결함·채널 인증 실패가 프로토콜 보증을 약화 | 인증·장비 검증·키 폐기 조건을 운영 절차와 연계 |

## Ⅵ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| QKD 도입이 목적화되면 키 수요·운영비·신뢰 경계가 맞지 않을 수 있음 | 중요 통신 구간의 위협·키 수요·물리경로를 기준으로 적용 범위를 선정하고, PQC 등과 혼합한 전환 구조를 검증 |
