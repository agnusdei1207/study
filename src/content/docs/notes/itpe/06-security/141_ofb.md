## 지식 로드맵 내 현재 위치

지식 위치: 정보보안 → 블록 암호 운용 모드 → **OFB**

## 30초 인출

- **본질:** 블록 암호 함수의 출력값(Output)을 다음 단계의 입력으로 연속 피드백하여 평문과 무관한 독립적 키스트림을 생성하고 XOR 연산하는 동기식 스트림 암호 운용 모드
- **메커니즘:** IV 암호화($E_K$) $\rightarrow$ 출력 블록 $O_i$를 키스트림으로 사용 및 다음 $E_K$ 입력 피드백 $\rightarrow$ 평문과 $O_i$ XOR $\rightarrow$ 암호문 생성 (암·복호화 회로 동일)
- **통찰:** 전송 비트 오류가 후속 블록에 전파되지 않는 장점이 있으나 비트 플리핑에 취약하므로 무결성 검증을 위한 HMAC 결합 또는 현대적 AEAD(GCM) 전환 필수

<details>
<summary>핵심 용어</summary>

- **OFB (Output Feedback)** : 암호화 함수의 출력을 다음 입력으로 피드백하여 키스트림을 생성하는 모드.
- **Synchronous Stream Cipher** : 키스트림이 평문이나 암호문과 완전히 독립적으로 생성되는 동기식 암호.
- **Pre-computation (사전 연산)** : 평문이 도착하기 전에 백그라운드에서 키스트림을 미리 계산해 두는 기법.
- **Two-Time Pad Attack** : 동일한 키스트림으로 두 개의 서로 다른 평문을 암호화할 때 평문 간 XOR 관계가 노출되는 취약점.

</details>

## 2~4교시 예상문제 (25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 블록 암호 알고리즘의 출력(Output) 블록을 다음 암호화 함수의 입력으로 지속 피드백하여 의사난수 키스트림을 생성하고, 이를 평문과 비트 단위로 XOR 연산하는 동기식 스트림 운용 모드 |
| 목적 | 블록 단위 패딩(Padding) 없이 임의 길이의 데이터 스트림을 실시간 암호화하고, 전송 채널 상의 1비트 오류가 다른 비트로 전파되지 않도록 격리 |

- 평문이 개입하기 전에 암호화 엔진($E_K$)을 연속 구동하여 키스트림을 사전에 대량 계산(Pre-computation)해 둘 수 있는 독특한 아키텍처 특성 보유

## Ⅱ. OFB 모드의 핵심 기술적 특징

| 특징 항목 | 세부 내용 및 기술적 의미 | 엔지니어링 구현 가치 |
|---|---|---|
| 오류 전파 제로 (No Error Propagation) | 전송 중 암호문 1비트에 오류가 발생해도 복호화 시 오직 해당 1비트의 평문만 반전 | 위성 통신, 음성/영상 스트리밍 등 노이즈가 많은 채널에 적합 |
| 키스트림 사전 계산 (Pre-computation) | 키스트림 생성이 평문 데이터와 완전히 독립적이므로 유휴 시간에 키스트림 사전 생성 | 데이터 도착 시 즉시 XOR 연산만 수행하므로 암호화 지연 제로 |
| 암·복호화 구조의 완전한 대칭성 | 복호화 과정에서도 복호화 알고리즘($D_K$)을 쓰지 않고 암호화 알고리즘($E_K$)을 동일 적용 | 하드웨어 칩(FPGA/ASIC) 면적 절감 및 펌웨어 리소스 최소화 |
| 패딩 오버헤드 부재 | 데이터가 블록 크기(128비트)의 배수가 아니어도 패딩을 추가할 필요가 없음 | 패딩 오라클(Padding Oracle) 공격의 공격 표면 원천 제거 |

- 단, 암호화 과정에서 직전 출력이 나와야 다음 출력을 계산할 수 있으므로 키스트림 생성 자체는 병렬화할 수 없는 직렬 의존성 특성 보유

## Ⅲ. OFB 암·복호화 메커니즘 및 키스트림 생성 프로세스

```text
[OFB 모드 암호화 및 복호화 프로세스]

 [키스트림 생성 및 암호화]
       IV (Initial Vector)
              │
              ▼
        ┌───────────┐
        │  E_K (암호)│ <── 대칭키 K
        └─────┬─────┘
              │
              ├──────────────────────────────┐ (피드백)
              ▼ (키스트림 O1)                 ▼
 평문 P1 ───> ⊕ ───────────────> 암호문 C1    ┌───────────┐
                                              │  E_K (암호)│ <── 대칭키 K
                                              └─────┬─────┘
                                                    │
                                                    ├────────────────> (피드백)
                                                    ▼ (키스트림 O2)
                                       평문 P2 ───> ⊕ ───────────────> 암호문 C2

 [복호화]
 암호문 C1 ───> O1 (E_K(IV))과 ⊕ ───> 평문 P1 (암호화 함수 E_K 동일 사용)
```

| 프로세스 단계 | 핵심 수학적 연산 | 상세 설명 |
|---|---|---|
| 1. 초기 키스트림 생성 | $O_1 = E_K(IV)$ | 고유한 초기화 벡터(IV)를 비밀키 $K$로 암호화하여 첫 번째 출력 블록 $O_1$ 생성 |
| 2. 연속 피드백 연산 | $O_j = E_K(O_{j-1}) \quad (j \ge 2)$ | 직전 단계의 출력 블록 $O_{j-1}$을 다시 암호화 함수에 입력하여 의사난수열 확장 |
| 3. 평문 암호화 | $C_j = P_j \oplus O_j$ | 평문 블록 $P_j$와 생성된 키스트림 블록 $O_j$를 XOR하여 암호문 $C_j$ 산출 |
| 4. 복호화 처리 | $P_j = C_j \oplus O_j$ | 동일한 IV와 $K$로 생성된 키스트림 $O_j$를 수신 암호문 $C_j$와 XOR하여 평문 복원 |

## Ⅳ. 스트림 변환 블록 암호 모드 비교: OFB vs CFB vs CTR vs GCM

| 비교 항목 | OFB (Output Feedback) | CFB (Cipher Feedback) | CTR (Counter) | GCM (Galois/Counter Mode) |
|---|---|---|---|---|
| 피드백 원천 | 암호화 함수 출력 ($O_{i-1}$) | 직전 암호문 블록 ($C_{i-1}$) | 카운터 값 증가 ($IV + Counter$) | 카운터 증가 + GHASH 인증 |
| 오류 전파 특성 | 오류 전파 없음 (해당 비트만) | 해당 비트 + 다음 블록 전체 왜곡 | 오류 전파 없음 (해당 비트만) | 인증 태그 불일치로 전체 패킷 폐기 |
| 키스트림 사전 계산 | 가능 (평문 도착 전 생성) | 불가능 (암호문 필요) | 가능 (사전 생성 가능) | 가능 (CTR 부분 사전 생성) |
| 병렬 처리 지원 | 불가 (직렬 의존성) | 복호화만 병렬 가능 | 암·복호화 완전 병렬 지원 | 암·복호화 및 인증 병렬 고속 가속 |
| 무결성 인증 제공 | 미지원 (기밀성 전용) | 미지원 (기밀성 전용) | 미지원 (기밀성 전용) | 기본 지원 (AEAD 인증 태그) |
| 비트 동기 누락 영향 | 동기 완전 파괴 (복구 불가) | 1블록 후 자동 자기 동기화 | 동기 파괴 (카운터 동기 필요) | 세션 재수립 필요 |

## Ⅴ. OFB 모드 적용 시 엔지니어링 한계와 해결 방안

| 한계 | 방안 |
|---|---|
| 동일한 키 $K$와 초기화 벡터 $IV$가 재사용될 경우 동일한 키스트림이 생성되어 Two-Time Pad 공격에 의해 평문 간 XOR 관계($C_1 \oplus C_2 = P_1 \oplus P_2$) 노출 | 암호학적으로 안전한 의사 난수 생성기(CSPRNG)를 통해 매 전송 세션마다 충돌 없는 유니크 IV 생성을 강제하고, 동일 키당 최대 암호화 블록 수(예: $2^{32}$ 블록) 도달 시 강제 키 교체 |
| 오류 전파가 없다는 특성으로 인해 공격자가 암호문의 특정 비트를 반전시키면 복호화 평문의 해당 비트가 정확히 조작되는 비트 플리핑(Bit-flipping) 취약점 | 무결성 검증을 위해 암호문 뒤에 HMAC-SHA256을 결합하는 Encrypt-then-MAC(EtM) 아키텍처를 적용하거나, 표준 인증 암호화인 AES-GCM/ChaCha20-Poly1305로 전면 교체 |
| 전송 중 비트 손실(Bit Drop) 또는 비트 추가가 발생할 경우 키스트림과의 비트 오프셋 동기가 영구히 파괴되어 이후 전체 데이터 복호화 실패 | 하위 계층에 TCP 등 신뢰성 있는 전송 프로토콜을 사용하고, 데이터 링크 프레임 단위로 명시적 시퀀스 번호(Sequence Number)를 부여하여 프레임 단위 재동기화 메커니즘 구축 |
| 키스트림 생성이 이전 출력에 순차적으로 종속되어 멀티코어 CPU 및 병렬 하드웨어 파이프라인 가속을 활용할 수 없는 직렬 병목 | 순수 병렬 연산이 가능하여 성능이 수배 이상 향상되는 카운터 모드(CTR) 또는 AES-NI 하드웨어 가속을 완벽 지원하는 AES-GCM으로 마이그레이션 |

## Ⅵ. 안전한 스트림 암호화 아키텍처 마이그레이션 제언

```text
[레거시 OFB에서 고성능 AEAD(AES-GCM)로의 현대화 로드맵]

  +---------------------------------------------------------------+
  |        레거시 레벨: 순수 OFB 모드 (단순 기밀성 스트림)          |
  |        [ IV ] ──> [ E_K ] ──> [ O_i ] ──> ⊕ [ P_i ] ──> [ C_i ]│
  +---------------------------------------------------------------+
                                  │
                                  ▼ (무결성 보강 단계)
  +---------------------------------------------------------------+
  |        중간 레벨: OFB + HMAC (비트 플리핑 변조 방어)          |
  |        [ C_i ] 전송 + [ HMAC(K_mac, C_1 || ... || C_n) ]      |
  +---------------------------------------------------------------+
                                  │
                                  ▼ (고성능 표준화 단계)
  +---------------------------------------------------------------+
  |        현대 표준: AES-GCM (하드웨어 병렬 가속 + AEAD)          |
  |   - CTR 병렬 암호화 + GMAC 무결성 인증 태그 단일 파이프라인   |
  +---------------------------------------------------------------+
```

| 검토 영역 | 엔지니어링 세부 과제 | 통과 기준 지표 |
|---|---|---|
| IV 유일성 보장 | 세션별 고유 난수 IV 생성 메커니즘 및 중복 검증 | 동일 키 하에서 IV 재사용 확률 0% |
| 무결성 검증 | 전송 데이터의 비트 변조 여부를 판별하는 메시지 인증 코드 결합 | 비인가 조작 패킷 탐지 및 차단율 100% |
| 알고리즘 현대화 | 레거시 통신 프로토콜의 OFB 모드를 AES-GCM 또는 ChaCha20으로 전환 | 초당 암복호화 처리량(Throughput) >= 200% 향상 |
