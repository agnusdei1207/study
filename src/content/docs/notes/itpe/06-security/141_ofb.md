## Ⅰ. OFB의 개요

- 개념 : 블록 암호화 알고리즘을 사용하여 평문과 무관한 **의사난수 키 스트림** (Keystream)을 독립적으로 생성하고, 이를 평문 비트열과 비트 단위로 **XOR** 연산하여 암호문을 생성하는 **동기식** (Synchronous) 스트림 암호 운용 모드.
- 배경 및 필요성 : **CFB** 모드는 암호문 비트 전송 오류 발생 시 후속 블록까지 에러가 연속 전파되어 복호화가 불가능해지는 문제가 있어, 음성 통신이나 실시간 화상회의처럼 패킷 손실이 잦은 환경에서 에러 전파가 발생하지 않는 블록 암호 모드가 필요해짐.
- 핵심 목적 : 전송 채널의 1비트 반전 오류가 다른 비트로 전파되지 않도록 국소화하고, 평문이 도착하기 전에 키 스트림을 사전에 미리 계산(Pre-computation)하여 초저지연 암호화를 실현.

## Ⅱ. OFB의 핵심 아키텍처 및 동작 메커니즘

OFB는 암호 엔진의 출력값(Output)이 평문과 XOR되기 전에 다음 단계 암호 엔진의 입력으로 직접 피드백되는 독립적 키 생성 구조를 가짐.

```text
[ OFB(Output Feedback) 모드 암호화 및 복호화 메커니즘 ]

 1. OFB 암호화 (Encryption)
    [ 초기화 벡터 (IV) ] -----------------+
             |                            |
             v                            |
    +-----------------+                   | (암호 엔진 출력값 직접 피드백!)
    | 블록 암호 엔진  | <--- [ 키 (K) ]   |  * 평문(P)이나 암호문(C)에 전혀
    +--------+--------+                   |    영향을 받지 않는 독립 루프!
             |                            |
      [ 키 스트림 (O_i) ] ----------------+
             |
             v
          (+) <---- [ 평문 (P_i) ]
             |
             v
       [ 암호문 (C_i) ]

 2. OFB 복호화 (Decryption)
    [ 초기화 벡터 (IV) ] -----------------+
             |                            |
             v                            |
    +-----------------+                   | (암호 엔진 출력값 직접 피드백)
    | 블록 암호 엔진  | <--- [ 키 (K) ]   |  * 복호화 시에도 암호 엔진은
    +--------+--------+                   |    동일하게 "암호화(E)" 모드로 구동!
             |                            |
      [ 키 스트림 (O_i) ] ----------------+
             |
             v
          (+) <---- [ 암호문 (C_i) ]
             |
             v
        [ 평문 (P_i) ]
```

- **독립적 키 스트림 생성** : 키 스트림 생성 루프가 평문이나 암호문 데이터와 완전히 분리되어 동작하므로, 고속 네트워크에서 평문 수신 전에 암호화 키를 사전 생성 가능.
- **무에러 전파 특성(No Error Propagation)** : 전송 채널의 노이즈로 암호문의 1개 비트가 손상되어도 복호화된 평문의 해당 1개 비트만 손상될 뿐, 후속 데이터 복호화에는 전혀 영향을 미치지 않음.
- **대칭적 하드웨어 구조** : 암호화와 복호화 과정이 동일한 키 스트림 생성 및 XOR 연산으로 완전히 일치하므로 하드웨어 구현이 극히 단순하고 경량화 가능.
- **패딩 불필요** : 스트림 암호로 동작하므로 블록 경계(128비트)에 맞추기 위한 PKCS 패딩 처리가 불필요하여 원본 데이터 크기 보존.

## Ⅲ. OFB의 세부 구성 요소 및 비교 분석

| 비교 항목 | **OFB** (Output Feedback) | **CFB** (Cipher Feedback) | **CTR** (Counter Mode) | **CBC** (Cipher Block Chaining) |
| --- | --- | --- | --- | --- |
| 피드백 대상 | 이전 암호 엔진의 출력값 | 이전 생성된 암호문 블록 | 피드백 없음 (카운터 기반) | 이전 생성된 암호문 블록 |
| 에러 전파 | 해당 1비트만 오류 (전파 없음) | 해당 비트 + 후속 블록 오류 | 해당 1비트만 오류 (전파 없음) | 해당 블록 전체 + 다음 블록 1비트 |
| 사전 연산 | 키 스트림 사전 계산 가능 | 불가능 (평문 암호화 후 가능) | 키 스트림 사전 계산 가능 | 불가능 (순차적 블록 처리) |
| 병렬 연산 | 불가 (키 스트림 루프 순차 종속) | 암호화 불가 / 복호화 가능 | 암호화 및 복호화 완전 병렬 가능 | 암호화 불가 / 복호화 가능 |
| 주요 적용 | 위성 통신, 음성 암호화 통신 | 실시간 대화형 단말 스트림 | 고속 IPSec, TLS 1.3, 고성능 스토리지 | 전통적 파일 및 DB 암호화 |

- OFB 모드는 에러 전파가 없는 이상적인 통신용 암호 모드이나, 순차적 키 스트림 연산의 한계로 현대 고성능 컴퓨팅 환경에서는 병렬 처리가 가능한 CTR 및 GCM 모드로 대체됨.

## Ⅳ. OFB의 주요 한계점 및 해결 방안

- 비트 반전 공격(Bit-flipping Attack)에 의한 무결성 취약성 :
  - 한계점 : 공격자가 전송 중인 암호문의 특정 비트를 0에서 1로 반전시키면 복호화 시 평문의 동일 비트가 정확히 반전되어 위조 및 변조에 무방비.
  - 해결 방안 : 단독 OFB 사용을 금지하고, HMAC-SHA256 등의 메시지 인증 코드를 결합하거나 Galois/Counter Mode(GCM) 등 AEAD 표준으로 전환.
- 초기화 벡터(IV) 재사용 시 치명적 키 스트림 노출 :
  - 한계점 : 동일한 비밀키 하에서 동일한 IV를 두 번 사용하면 완전히 동일한 키 스트림($O$)이 생성되어, 두 암호문의 XOR($C_1 \oplus C_2 = P_1 \oplus P_2$)로 평문이 즉시 노출.
  - 해결 방안 : 메시지 암호화 시마다 암호학적 난수 생성기를 통해 고유하고 중복되지 않는 IV 생성을 시스템 레벨에서 강제.
- 키 스트림 연산의 순차적(Sequential) 병목 :
  - 한계점 : 카운터(CTR) 모드와 달리 이전 암호화 출력이 나와야 다음 출력을 계산할 수 있어 멀티코어 병렬 처리가 불가능.
  - 해결 방안 : 10Gbps 이상의 고속 백본망 환경에서는 병렬성과 임의 접근(Random Access)이 보장되는 CTR/GCM 모드로 전면 교체.

## Ⅴ. OFB 적용 및 발전을 위한 기술사적 제언

- 잡음이 심한 물리적 무선·위성 통신 링크에 제한적 적용 : 비트 손실과 패킷 에러율이 높은 무선 통신(군용 무전, 인공위성 텔레메트리) 채널에 무에러 전파 특성을 살려 안전하게 적용.
- 인증 암호화(Authenticated Encryption) 결합 필수화 : 무결성이 보장되지 않는 스트림 모드의 한계를 보완하기 위해 키 교환 단계에서 파생된 별도 키로 메시지 무결성 태그(MAC) 동시 전송.
- NIST SP 800-38A 준수 및 PQC(양자내성암호) 연계 : AES-256 기반의 OFB 모드를 유지하되, Grover 알고리즘에 의한 키 공간 축소에 대비하여 최소 256비트 이상의 대칭키 크기 확보.
