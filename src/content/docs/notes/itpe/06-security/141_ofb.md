## 답안 골격
```text
[OFB(Output Feedback Mode)] ◀━━ 머리: Ⅶ 내 의견 (비트 플리핑 변조 취약점 극복 → 사전 연산 키스트림과 HMAC을 결합한 무결성 보장 동기식 스트림 암호화)
 ┃
 ┣━ Ⅰ 개요 ───── 블록 암호 엔진의 출력(Output) 자체를 다음 단계 암호화 엔진의 입력으로 피드백하여 평문과 무관한 의사 난수 키 스트림을 생성하고, 이를 평문과 XOR 연산하여 스트림 암호화하는 블록 암호 운용 모드
 ┣━ Ⅱ 특징 ───── 전송 오류 전파(Error Propagation) 완전 부재 · 패딩(Padding) 불필요 · 키 스트림 사전 연산(Pre-computation) 가능 · 복호화 시 암호화 함수($E_K$)만 단독 사용
 ┣━ Ⅲ 구조 ───── 초기화 벡터(IV) + 대칭키 암호 엔진($E_K$) + 키 스트림 생성기($O_i$) + 평문/암호문 XOR 연산기
 ┣━ Ⅳ 흐름 ───── [키스트림 생성]: $O_0 = IV$, $O_i = E_K(O_{i-1})$ / [암호화]: $C_i = P_i \oplus O_i$ / [복호화]: 동일 키스트림 생성 후 $P_i = C_i \oplus O_i$
 ┣━ Ⅴ 비교 ───── CFB(암호문 $C_i$를 피드백, 1비트 에러 시 후속 블록 연쇄 파괴) vs OFB(엔진 출력 $O_i$를 피드백, 에러 전파 제로, 사전 연산 가능) vs CTR(카운터 암호화, 병렬 연산)
 ┗━ Ⅵ 실무 ───── 동일한 IV 재사용 시 키스트림 노출(Two-Time Pad 공격) / 비트 플리핑(Bit-flipping) 공격에 무방비(무결성 태그 미제공)
```
- 필수 키워드: OFB(Output Feedback) · 키 스트림(Key Stream) · 사전 연산(Pre-computation) · 오류 전파 없음 · 패딩 불필요 · 비트 플리핑 · $E_K$ 단일 엔진
- 배점 전략: 10점 = Ⅰ OFB 정의 및 키스트림 생성 원리 → Ⅲ 암복호화 흐름도 도식 → Ⅴ CFB vs OFB vs CTR 비교표 / 25점 = Ⅰ~Ⅶ 전개, 제127회 4교시 기출 완벽 대응, 통신 노이즈 환경(위성, 음성)에서 오류 전파가 없는 수학적 이유, 키스트림 사전 생성에 따른 실시간 레이턴시 제로화 메커니즘 심층 상술
- 기출: 제127회 4교시 6번: "블록(Block) 암호 모드에 대한..."

## 한 줄 본질
- 암호문 1비트 에러가 후속 데이터 전체를 파괴하는 연쇄 오류 전파 병목 → 평문이나 암호문과 완전히 독립된 난수 키스트림을 암호 엔진 출력을 통해 사전 생성하여 평문과 순수 XOR → 오류 전파 0% 및 실시간 초저지연 확보 / 키스트림 재사용 시 평문 완전 노출

## 핵심 그림
```text
[OFB(Output Feedback) 운용 모드의 독립 키스트림 생성 및 암복호화 메커니즘]

[키스트림 생성 흐름 (평문/암호문과 무관하게 미리 계산 가능!)]
  [초기화 벡터 IV] ──> [암호 엔진 E_K] ──┬──> [키스트림 O1] ──> [암호 엔진 E_K] ──┬──> [키스트림 O2] ...
                                         │                                        │
                                (엔진 출력을 피드백!)                    (엔진 출력을 피드백!)

[실시간 암호화 및 복호화]
  [평문 P1] ──(XOR)──> [암호문 C1]         [암호문 C1] ──(XOR)──> [평문 P1]
                ▲                                          ▲
                │                                          │
          [키스트림 O1]                              [키스트림 O1]

* 통신 중 C1의 1비트가 깨져도 P1의 해당 1비트만 깨질 뿐, O2 생성에 영향이 없어 P2는 100% 완벽 복원!
```

## 핵심 용어
- 독립 키 스트림 (Independent Key Stream): 평문이나 암호문의 내용과 전혀 결합되지 않고 오직 초기화 벡터(IV)와 대칭키($K$)만으로 순수하게 생성되는 의사 난수 수열
- 비트 플리핑 공격 (Bit-flipping Attack): 암호문 $C_i$의 특정 비트를 0에서 1로 반전시키면 복호화된 평문 $P_i$의 동일한 비트 위치가 정확히 0에서 1로 반전되는 취약점을 악용하여 공격자가 데이터를 의도한 값으로 위변조하는 공격

## 핵심 통찰
- OFB의 가장 큰 매력은 "통신 선로의 품질이 극도로 나쁜 환경(군용 위성 통신, 무전기 음성 통신)"에 최적이라는 점임 → 잡음으로 패킷 일부 비트가 튀어도 오직 그 비트만 깨지고 다음 음성은 깨끗하게 복호화됨
- "사전 연산(Pre-computation)"이 가능함 → CPU가 한가할 때 미리 수 메가바이트의 키스트림($O_1, O_2, ...$)을 계산해 메모리에 담아두면, 데이터가 들어오는 즉시 단순 XOR 연산만 수행하므로 통신 지연이 1마이크로초도 발생하지 않음
- 치명적 약점은 "동일한 IV를 두 번 쓰는 순간 파멸"이라는 점임 → $C_1 \oplus C_2 = P_1 \oplus P_2$가 되어 공격자가 두 평문의 차이점을 분석해 비밀키 없이도 원문을 복원해 냄

## 이웃 토픽과 구분
- OFB vs CTR: OFB = 직전 출력을 순차 피드백하므로 키스트림 생성이 직렬(Serial) 방식 / CTR = 카운터 값을 독립 암호화하므로 키스트림 생성이 완전 병렬(Parallel) 방식 (현대에는 CTR이 우세)

## 문제·원인·대책
- 사례: 원격 제어 명령 패킷에 OFB 모드를 단독 적용했다가 공격자가 암호문 비트를 조작하여 '밸브 닫힘' 명령을 '밸브 열림'으로 변조한 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 암호문 비트 플리핑을 통한 특정 제어 데이터 악의적 변조 | OFB가 기밀성만 제공하고 암호문 무결성(인증)을 검증하지 않음 | HMAC-SHA256 연계(Encrypt-then-MAC) 또는 AEAD(AES-GCM) 전환 | 암호문 1비트 변조 시에도 즉각 검증 실패로 패킷 폐기 |
| 고정된 IV 재사용으로 인한 암호문 상호 XOR 평문 추출 | 통신 재연결 시 동일한 세션 IV 재사용 오류 | 암호화 세션마다 고유하고 예측 불가능한 암호학적 난수 IV 보장 | 키스트림 재사용 공격 원천 차단 |

## 이렇게 출제된다
- 제127회 4교시 6번: "블록 암호 운용 모드 5가지(ECB, CBC, CFB, OFB, CTR)의 특징과 장단점을 비교하고, 최근 널리 활용되는 AEAD 모드에 대하여 설명하시오." → 요구 포인트: Ⅰ OFB 개념 + Ⅲ 독립 키스트림 생성 흐름도 + Ⅴ 오류 전파 없는 특성 및 5대 모드 비교

## 내 의견
- [실시간 음성 및 영상 암호화에서 OFB의 레거시 퇴출과 ChaCha20 전환] OFB는 오류 전파가 없다는 장점에도 불구하고 키스트림 생성이 직렬로 묶여 있어 최신 고해상도 4K 스트리밍의 대역폭을 감당하지 못함 → 나라면: 신규 실시간 프로토콜(WebRTC 등) 설계 시 OFB를 배제하고, 병렬 스트림 암호화와 Poly1305 인증 태그를 단일 패스에 고속 처리하는 ChaCha20-Poly1305를 표준 암호 스위트로 채택
