## 연관 키워드

- OFB(Output Feedback), 키 스트림(Keystream), 초기화 벡터(IV), 에러 전파, 비트 반전 공격
- CFB, CTR, CBC, GCM, AEAD

## Ⅰ. OFB의 개요

- 핵심 요약 : 블록 암호의 출력을 되먹임하여 평문과 무관한 키 스트림을 만들고, 이를 XOR하는 동기식 스트림 운용 모드.
- 개념 : 블록 암호 알고리즘으로 평문과 무관한 키 스트림을 독립적으로 생성하고, 이를 평문과 비트 단위로 XOR(Exclusive OR) 연산하여 암호문을 만드는 **출력 피드백 모드** (OFB, Output Feedback).
- 배경 및 필요성 : CFB(Cipher Feedback) 모드는 암호문 비트 오류가 후속 블록으로 연속 전파되어 복호화가 어려워지므로, 패킷 손실이 잦은 음성 통신이나 화상회의 환경에는 에러 전파가 없는 모드가 필요해짐.
- 주요 목적 : 채널 오류를 해당 비트로 국소화하고, 평문이 도착하기 전에 키 스트림을 미리 계산하여 초저지연 암호화를 실현.

## Ⅱ. OFB의 특징 및 장점

- 핵심 요약 : 독립적인 키 스트림과 무에러 전파 특성이 저지연 암호화와 경량 구현으로 이어지는 방식.

1. 독립 키 스트림 : 키 스트림 생성 루프가 평문·암호문과 분리됨 → 평문 수신 전에 키 스트림을 사전 계산 → 암호화 지연 감소.
2. **무에러 전파** (No Error Propagation) : 암호문 1비트가 손상되면 복호문의 해당 1비트만 손상됨 → 패킷 손실 환경에서 후속 데이터 보존.
3. 대칭적 구조 : 암호화와 복호화가 같은 키 스트림 생성과 XOR로 동일함 → 하드웨어 구현이 단순하고 경량화 가능.
4. 패딩 불필요 : 스트림처럼 동작하여 블록 경계를 맞추는 패딩이 없음 → 원본 데이터 크기를 그대로 보존.

```text
[ OFB 암호화 흐름 ]

초기화 벡터 (IV)
    ↓
블록 암호 엔진 (키 K 사용)
    ↓ 출력 O_i
    ↓ (O_i는 다음 블록 입력으로 피드백)
키 스트림 O_i
    ↓
평문 P_i ⊕ O_i = 암호문 C_i
```

## Ⅲ. OFB의 구조 (흐름)

- 핵심 요약 : 초기화 벡터를 시작 입력으로 하여 암호 엔진의 출력을 다음 입력으로 되먹임하는 순환 구조.
- **초기화 벡터** (IV, Initialization Vector) : 같은 키를 쓰더라도 메시지마다 다른 키 스트림이 나오도록 하는 시작 값.
- 복호화 특성 : 복호화에도 암호 엔진을 암호화 방향으로 구동하고, 암호문에 같은 키 스트림을 XOR하여 평문을 얻음.

```text
[ OFB 복호화 흐름 ]

동일 IV·키 → 블록 암호 엔진 (암호화 방향 구동)
    ↓ 키 스트림 O_i
암호문 C_i ⊕ O_i = 평문 P_i
```

## Ⅳ. OFB의 비교 분석

- 핵심 요약 : OFB는 에러 전파가 없으나 순차 연산 때문에 병렬 처리에 약해, 고속 환경에서는 카운터 기반 모드로 대체되는 구조.

비교 대상은 **카운터 모드** (CTR, Counter Mode)와 **암호 블록 체이닝** (CBC, Cipher Block Chaining)이다.

| 비교 축 | OFB | CFB | CTR | CBC |
| --- | --- | --- | --- | --- |
| 피드백 대상 | 이전 암호 엔진의 출력 | 이전 암호문 블록 | 피드백 없음 (카운터 사용) | 이전 암호문 블록 |
| 에러 전파 | 해당 1비트만 | 해당 비트와 후속 블록 | 해당 1비트만 | 해당 블록 전체와 다음 블록 1비트 |
| 사전 계산 | 키 스트림 사전 계산 가능 | 불가 (암호문 생성 이후 가능) | 키 스트림 사전 계산 가능 | 불가 (순차 블록 처리) |
| 병렬 처리 | 불가 (키 스트림 순차 종속) | 암호화 불가, 복호화 가능 | 암호화·복호화 모두 병렬 | 암호화 불가, 복호화 가능 |
| 주요 적용 | 위성·음성 등 오류가 잦은 통신 | 실시간 스트림 단말 | IPsec(Internet Protocol Security), GCM(Galois/Counter Mode) 기반 TLS(Transport Layer Security) 1.3, 고성능 스토리지 | 전통적 파일 및 DB 암호화 |

- 선택 기준 : 비트 오류율이 높은 무선·위성 구간에서는 OFB의 무에러 전파가 장점이지만, 고속 백본이나 병렬 처리가 필요하면 CTR이나 GCM을 택하는 것이 일반적인 기준임.

## Ⅴ. OFB의 한계와 방안

- 핵심 요약 : 무결성 부재, IV 재사용, 순차 연산이라는 세 한계를 인증 암호 결합, 난수 IV 강제, 병렬 모드 전환으로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **비트 반전 공격** (Bit-flipping Attack) | 암호문 비트를 뒤집으면 평문의 같은 비트가 정확히 반전되어 무결성 검증 없이 위·변조가 가능 | 단독 OFB 사용을 금지하고 HMAC(Hash-based Message Authentication Code) 같은 메시지 인증 코드를 결합하거나, **AEAD** (Authenticated Encryption with Associated Data) 방식인 GCM으로 전환 | 무결성 검증 실패 건수 |
| **IV 재사용** (IV Reuse) | 같은 키와 IV를 두 번 쓰면 키 스트림이 동일해져, 두 암호문을 XOR하면 평문 관계가 노출 | 메시지마다 암호학적 난수 생성기로 고유 IV를 만들고, 시스템 수준에서 IV 중복 사용을 차단 | IV 중복 검출 건수 |
| 순차 키 스트림 병목 | 이전 출력이 나와야 다음 출력을 계산할 수 있어 멀티코어 병렬 처리가 불가능 | 병렬성과 임의 접근이 보장되는 CTR 또는 GCM 모드로 전환 | 처리량, 코어당 활용률 |

## Ⅵ. OFB의 기술사적 제언

- 핵심 요약 : OFB는 오류가 잦은 무선·위성 구간에 적용 범위를 한정하고, 무결성과 병렬성을 갖춘 AEAD 모드를 기본값으로 두는 설계 원칙.

1. 잡음이 많은 무선·위성 링크처럼 비트 오류가 빈번한 구간에서만 OFB의 무에러 전파 특성을 활용하되, 적용 구간을 설계 문서에 명시하여 사용 범위를 통제하는 것이 바람직하다.
2. 신규 시스템에는 무결성 태그를 함께 제공하는 AEAD 모드를 기본으로 채택하도록 암호 모드 선정 기준을 조직 표준으로 제정할 필요가 있다.
3. NIST(National Institute of Standards and Technology) SP 800-38A 같은 공인 지침을 준수 기준으로 삼고, 양자 컴퓨팅 위협에 대비해 AES-256 같은 256비트 키 길이 정책을 함께 운영해야 한다.

## Ⅶ. 결론

- 핵심 요약 : OFB는 에러 전파가 없는 저지연 스트림 모드이지만, 무결성과 병렬성이 필요한 현대 환경에서는 보조적 선택지에 머묾.
- 시사점 : 오류 국소화라는 장점은 살리되, 인증 암호와 고속 모드를 기본으로 둘 때에만 OFB의 쓰임새가 명확해짐.
