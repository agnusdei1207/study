## 지식 로드맵 내 현재 위치

콘텐츠 신뢰 → 출처 및 편집 증명 → C2PA / 콘텐츠 자격증명

## 30초 인출

- **본질:** 이미지, 비디오, 오디오 등 디지털 콘텐츠의 생성 주체, 편집 이력, AI 생성 여부 등의 출처 정보를 암호학적 서명 매니페스트로 캡슐화하는 개방형 기술 표준.
- **메커니즘:** 미디어 생성/수정 시 메타데이터 클레임 생성 → 암호학적 해시로 원본 미디어와 바인딩 → X.509 인증서 기반 디지털 서명 임베딩 → 뷰어에서 신뢰 사슬 검증.
- 통찰: SNS 업로드 시 재인코딩으로 메타데이터가 삭제되는 하드 바인딩의 한계를 보완하기 위해 워터마크 및 지각적 해시(Perceptual Hash)를 활용한 소프트 바인딩의 하이브리드 결합 필수.

<details><summary>핵심 용어</summary>

- **C2PA(Coalition for Content Provenance and Authenticity)**: 어도비, 마이크로소프트, 인텔 등이 주도하여 설립한 콘텐츠 출처 및 진위 확인 연합 표준 기구.
- **콘텐츠 자격증명(Content Credentials)**: C2PA 규격을 준수하여 미디어에 부착되는 검증 가능한 디지털 출처 라벨(CR 아이콘).
- **매니페스트(Manifest)**: 작성자 정보, 사용된 도구(AI 프롬프트 포함), 수정 이력, 원본 해시값 및 디지털 서명을 포함하는 표준화된 데이터 블록.
- **하드 바인딩(Hard Binding)**: 미디어 파일 컨테이너 내부(JUMBF, EXIF 등)에 매니페스트를 직접 임베딩하고 암호학적 해시로 결합하는 방식.
- **소프트 바인딩(Soft Binding)**: 워터마크, 지각적 해시(Fingerprint)를 추출하여 외부 분산 원장이나 클라우드 매니페스트 저장소와 사후 연계하는 방식.
</details>

## 2~4교시 예상문제 (25점)

> 생성형 AI 확산에 따른 딥페이크 및 가짜 뉴스 방지를 위한 C2PA(Coalition for Content Provenance and Authenticity) 표준의 아키텍처와 매니페스트 생성·검증 메커니즘을 설명하고, 유통 플랫폼에서의 메타데이터 유실 한계와 이를 극복하기 위한 엔지니어링 방안을 제시하시오. (25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 디지털 콘텐츠의 생성자, 사용 장비/도구, AI 생성 여부, 편집 이력 정보를 암호화 서명 매니페스트 형태로 자산에 결합하여 위변조를 탐지하는 기술 표준 |
| 목적 | 딥페이크 및 악의적 조작 미디어의 무분별한 확산 방지, 디지털 미디어의 투명한 출처(Provenance) 추적성 및 콘텐츠 신뢰 생태계 조성 |

## Ⅱ. C2PA 콘텐츠 자격증명의 주요 특징

| 특징 | 세부 내용 | 구현 요소 및 표준 |
|---|---|---|
| 암호학적 무결성 | 비대칭키 전자서명을 적용하여 매니페스트나 미디어 데이터 변조 시 검증 즉시 실패 | X.509 PKI, SHA-256 해시 바인딩 |
| 전주기 이력 추적 | 카메라 원본 촬영부터 편집 소프트웨어(Photoshop 등) 수정 이력을 계층적 트리로 누적 | Manifest Chain, C2PA 클레임 구조 |
| AI 생성 투명성 | 생성형 AI 툴(DALL-E, Midjourney 등)에서 생성된 콘텐츠임을 명시적 클레임으로 기록 | c2pa.ai_generative 속성 태그 |
| 독립적 검증성 | 특정 기업이나 플랫폼에 종속되지 않고 오픈소스 검증기 및 웹 브라우저에서 진위 검증 | C2PA 오픈소스 SDK, Verify 웹 도구 |
| 프라이버시 보호 | 서명자 신원 노출을 원치 않을 경우 익명 암호화 자격증명(Verifiable Credential) 지원 | W3C DID, 익명화 속성 선택 공개 |

## Ⅲ. C2PA 매니페스트 생성, 바인딩 및 검증 아키텍처

```text
[ 1. 콘텐츠 생성 및 서명 단계 ]
+----------------------+      +----------------------+
| 원본 미디어 자산      | ──> | 바인딩 해시 계산     | ──+
| (Image/Video/Audio)  |      | (Asset Hash SHA-256) |   |
+----------------------+      +----------------------+   |
                                                          ▼
+----------------------+      +-------------------------------------------+
| 출처 클레임 생성     | ──> | C2PA 매니페스트 어설션(Assertion) 생성     |
| (도구, AI여부, 저작자)|      | - c2pa.actions (수정 내역)                |
+----------------------+      | - c2pa.hash.data (자산 해시값 매핑)       |
                               +-------------------------------------------+
                                                          │
                                                          ▼
                               +-------------------------------------------+
                               | 공인 서명키로 매니페스트 서명 (Sign)       |
                               | (인증서 체인 + 타임스탬프 토큰 결합)       |
                               +-------------------------------------------+
                                                          │
                                                          ▼
[ 2. 결합 배포 ] <──────────── [ JUMBF 포맷으로 미디어 파일 컨테이너에 임베딩 ]

[ 3. 유통 및 검증 단계 ]
[ 미디어 열람자 ] ──▶ [ C2PA Reader / Browser ] ──▶ 1. X.509 인증서 체인 유효성 검증
                                                 ──▶ 2. 매니페스트 내 서명 무결성 검증
                                                 ──▶ 3. 미디어 파일 해시 재계산 및 대조
                                                 ──▶ 4. 출처 정보 UI 표출 (CR 뱃지)
```

| 구성 요소 | 기술적 역할 | 적용 표준 및 규격 |
|---|---|---|
| 어설션 (Assertion) | 저작자, 편집 작업(크롭, 필터), AI 모델 파라미터 등 개별 출처 메타데이터 | JSON-LD, C2PA Assertion Schema |
| 클레임 (Claim) | 여러 개의 어설션들을 모아 단일 패키지로 구성하고 자산과의 바인딩 정보 명시 | C2PA Claim Structure v2.1 |
| 클레임 서명 (Signature) | 클레임 전체 해시값에 대해 공인 인증서(X.509) 비밀키로 서명 수행 | COSE Sign1 (RFC 9052), CMS/PKCS#7 |
| JUMBF 컨테이너 | JPEG, PNG, MP4 등 다양한 미디어 포맷 내부에 바이너리 매니페스트를 은닉 삽입 | ISO/IEC 19566-5 JUMBF 표준 |
| 신뢰 목록 (Trust List) | 신뢰할 수 있는 카메라 제조사, SW 개발사, AI 서비스 제공자의 인증서 CA 목록 | C2PA Public Trust List, KISA 인증체계 |

## Ⅳ. 하드 바인딩(Hard Binding) vs 소프트 바인딩(Soft Binding) 비교

| 비교 항목 | 하드 바인딩 (Hard Binding) | 소프트 바인딩 (Soft Binding) |
|---|---|---|
| 결합 메커니즘 | 파일 내부 메타데이터 헤더(JUMBF)에 매니페스트 임베딩 | 미디어 신호 내 보이지 않는 워터마크 또는 지각 해시 추출 |
| 변조 내성 | 비트 단위 무결성 엄격 보장 (1비트만 바뀌어도 무효화) | 압축, 리사이징, 화면 캡처 등 유실 공격에도 생존 |
| 메타데이터 보존 | SNS 업로드, 포맷 변환, EXIF 스트리핑 시 즉시 유실 | 미디어 데이터 자체가 훼손되지 않는 한 출처 복원 가능 |
| 인프라 의존성 | 파일 자체만으로 검증 가능 (완전 자립형) | 외부 매니페스트 저장소(Cloud Registry) 검색 필수 |
| 연산 부하 | 암호학적 해시 계산으로 연산 오버헤드 극소 | 딥러닝 기반 지각적 해시 및 워터마크 디코딩 연산 요구 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 주요 SNS(인스타그램, X 등) 업로드 시 서버 인코더가 EXIF 및 JUMBF 메타데이터를 강제 삭제하여 신뢰 사슬 단절 | 비가시적 디지털 워터마크(SynthID 등)와 시각적 지각 해시(PDQ, TMK)를 하이브리드 결합하여 외부 클라우드 레지스트리에서 매니페스트를 역추적하는 소프트 바인딩 병행 |
| 서명 검증 성공이 '서명자의 주장' 무결성만 증명할 뿐, 촬영된 피사체나 사건의 실제 진실성을 보장하지 못함 | C2PA 검증 UI 상에 '서명된 출처(Provenance)'와 '사실 여부(Fact-Checking)'를 엄격히 분리 표기하고, 독립적 팩트체크 기관의 메타데이터 링크 연동 |
| 스마트폰 화면을 재촬영하는 아날로그 홀(Analog Hole) 또는 스크린샷 캡처 시 C2PA 메타데이터 원천 소실 | 하드웨어 카메라 센서 레벨에서 Secure Enclave 하드웨어 서명을 강제하고, 캡처 방지 워터마크 및 프레임 레이트 이상 탐지 결합 |
| 고화질 4K/8K 대용량 영상 스트리밍 시 프레임별 해시 계산 및 매니페스트 검증에 따른 클라이언트 버퍼링 유발 | 전체 비디오 프레임 대상 해시를 지양하고 키프레임(I-Frame) 중심의 머클 트리(Merkle Tree) 구조 서명 기법 적용 |

## Ⅵ. 제언

```text
[ 엔드투엔드 디지털 콘텐츠 신뢰 생태계 모델 ]

+-------------------------+      +-------------------------+      +-------------------------+
|     디바이스 하드웨어   | ---> |     유통 및 소셜 플랫폼 | ---> |     사용자 및 규제 기관 |
| (카메라 센서 보안 서명) |      | (소프트바인딩/워터마크) |      | (투명한 팩트/출처 확인) |
+-------------------------+      +-------------------------+      +-------------------------+
```

| 계층 | 중점 엔지니어링 과제 | 기대 효과 |
|---|---|---|
| 생성/캡처 | 카메라 SoC 칩셋 내부에 하드웨어 암호화 엔진 탑재 및 촬영 즉시 센서 서명 임베딩 | 촬영 시점 원본 증명 및 딥페이크 사전 차단 |
| 유통/배포 | 주요 포털 및 SNS 플랫폼의 C2PA 매니페스트 보존 표준 채택 및 소프트 바인딩 연계 | 콘텐츠 리인코딩 시에도 출처 정보 영구 유지 |
| 소비/검증 | 웹 브라우저 및 모바일 OS 차원에서 C2PA 검증 엔진 기본 탑재 및 사용자 UI 직관화 | 전 국민 대상 가짜 뉴스 및 허위 조작 정보 면역력 확보 |

## 출제 이력과 검증 출처

- 제134회 정보관리기술사 (딥페이크 대응 및 디지털 콘텐츠 워터마크)
- C2PA Technical Specification v2.1 (Coalition for Content Provenance and Authenticity)
- NIST AI 100-4, Reducing Risks Posed by Synthetic Content
- W3C Verifiable Credentials Data Model v2.0

- 디지털 서명(Digital Signature)
- 양자내성암호(PQC)
