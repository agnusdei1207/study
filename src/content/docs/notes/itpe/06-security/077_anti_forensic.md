 ┃
 ┣━ Ⅰ 개요 ───── 디지털 포렌식 증거 수집·분석을 방해·지연·무력화하기 위해 디지털 증거를 조작·변조·삭제·은닉하는 공격 기법
 ┣━ Ⅱ 특징 ───── 증거 능력 훼손(무결성·신뢰성 파괴) · 포렌식 도구 무력화 · 흔적 완전 인멸(Secure Deletion) · 분석 시간과 비용 폭증
 ┣━ Ⅲ 구조 ───── 데이터 은닉(Steganography, Slack Space) · 데이터 삭제(Wiping, Degaussing) · 데이터 변조(타임스탬프 조작, Timestomp) · 암호화
 ┣━ Ⅳ 흐름 ───── 악성 행위 수행 → 흔적 은닉/변조(Timestomp, 메모리 주입) → 안티포렌식 도구 가동(Wiping) → 포렌식 분석 방해

 ┗━ Ⅵ 실무 ───── 포렌식 도구 취약점 익스플로잇 / 클라우드 환경 휘발성 증거 손실 / 컴플라이언스 시스템을 통한 선제적 원격 증적 격리

- 필수 키워드: 안티포렌식 · 와이핑(Wiping) · 스테가노그래피(Steganography) · 슬랙 공간(Slack Space) 은닉 · 타임스톰프(Timestomp) · 컴플라이언스 시스템
- 기출: 133회 3교시 1번 `안티포렌식(Anti-Forensic)이 등장하게 된 배경 및 기술을 설명하고, 안티포렌식에 대응하기 위한 컴플라이언스(Compliance)시스템의 구축 프로세스와활용 프로세스에 대하여 설명하시오.` → Ⅰ 배경 + Ⅲ 안티포렌식 기술 + Ⅵ 컴플라이언스 구축/활용 프로세스

## 한 줄 본질
- 디지털 범죄 흔적이 아티팩트와 디스크에 고스란히 남아 유죄 증거로 채택되는 위협 → 데이터 완전삭제, 메타데이터 변조, 은닉 기법으로 증거 능력을 무력화 → 범죄 흔적 인멸 및 수사 지연 / 분석가의 역추적과 원격 무결성 보존 체계에 의해 탐지 가능

## 핵심 용어
- 와이핑(Wiping): 단순 파일 삭제(OS 메타데이터만 제거)와 달리, 데이터 저장 영역 전체를 무작위 비트(0, 1, 난수)로 여러 번 덮어써 카빙(Carving) 복구를 원천 방지하는 기법
- 타임스톰프(Timestomp): 포렌식 타임라인 분석을 교란하기 위해 NTFS의 `$MFT` 메타데이터 내 MACB(Modified, Accessed, Created, Born) 시간을 정상 파일의 시간으로 조작하는 행위
- 스테가노그래피(Steganography): 이미지, 비디오, 오디오 파일의 LSB(Least Significant Bit)나 비가시적 영역에 기밀 데이터를 숨겨 존재 자체를 감추는 은닉 기술

## 핵심 통찰
- 일반적인 파일 삭제는 인덱스(Pointer)만 지우고 실제 데이터는 디스크 블록에 그대로 남으므로 포렌식 카빙으로 100% 복구됨 → 안티포렌식은 덮어쓰기(Overwrite)를 통해 복구 가능성을 물리적으로 파괴함
- 로컬 시스템의 로그는 관리자 권한을 탈취한 공격자가 얼마든지 지우거나 조작할 수 있음 → 안티포렌식을 방어하는 유일한 길은 '사건 발생 시점 이전에 로그를 WORM 스토리지로 실시간 복제'하는 것임
- 안티포렌식 행위 자체(와이핑 도구 실행 흔적, 이벤트 로그 삭제 이벤트 Event ID 1102 등)가 역설적으로 가장 확실한 범죄 고의성의 강력한 정황 증거가 됨

## 이웃 토픽과 구분
- 안티포렌식 vs 침해 대응: 안티포렌식 = 공격자가 증거를 인멸하고 수사를 방해하는 행위 / 침해 대응 = 방어자가 사고 원인을 규명하고 피해를 복구하는 절차

## 문제·원인·대책
- 사례: 사내 기밀 유출 직후 직원이 상용 와이핑 프로그램을 실행하여 하드디스크의 타임스탬프와 미할당 영역을 덮어쓴 사건
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 디스크 카빙 시도 시 모든 데이터가 무작위 0으로 채워져 복구 불가 | 로컬 하드디스크에 대한 와이핑 도구의 다중 덮어쓰기 실행 | EDR 에이전트 기반 와이핑 소프트웨어 실행 차단 및 MFT 저널 분석 | 인멸 시도 도구의 실행 흔적 확보 및 고의적 파괴 입증 |
| 침해 사고 조사 시 이벤트 뷰어의 보안 로그가 공백 상태로 발견 | 로컬 관리자 권한 탈취 후 `wevtutil cl` 명령어로 로그 삭제 | Syslog 및 SIEM으로 실시간 원격 WORM 전송 정책 강제 | 로컬 로그 삭제와 무관하게 원격 저장소에서 완벽한 타임라인 복원 |

## 이렇게 출제된다
- 제133회 3교시 1번: "안티포렌식(Anti-Forensic)이 등장하게 된 배경 및 기술을 설명하고, 안티포렌식에 대응하기 위한 컴플라이언스(Compliance)시스템의 구축 프로세스와활용 프로세스에 대하여 설명하시오." → 요구 포인트: Ⅰ 등장 배경 + Ⅲ 4대 안티포렌식 기술 + Ⅵ 컴플라이언스 시스템 구축 프로세스(요구사항-설계-도입-검증) 및 활용 프로세스(실시간 수집-무결성 보증-감사-증거 제출)

## 내 의견
- [로컬 증거 중심주의의 탈피] 단말기 디스크 포렌식에만 의존하는 사후 조사는 안티포렌식 도구 하나에 무력화됨 → 나라면: 감사 대상 시스템의 모든 활동 로그(네트워크 패킷, API 호출, 프로세스 생성)를 단말기 저장소에 의존하지 않고 전용 회선을 통해 변경 불가능(WORM)한 원격 클라우드 로그 볼트에 즉시 전송하는 '원격 무결성 증적 컴플라이언스 체계'를 필수 구축
