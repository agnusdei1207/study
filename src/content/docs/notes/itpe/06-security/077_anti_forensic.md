## 연관 키워드

- 안티포렌식(Anti-Forensic), 디지털 포렌식(Digital Forensic), 법적 증거 능력, 증거 무결성
- 데이터 파괴(Wiping), 데이터 은닉(Data Hiding), 스테가노그래피(Steganography), NTFS 대체 데이터 스트림(ADS)
- 타임스토밍(Timestomping), 이벤트 로그 삭제, 분석 방해, 안티 VM(Anti-VM)
- WORM(Write Once Read Many), SIEM(Security Information and Event Management), 휘발성 메모리 포렌식, 파일 카빙(File Carving)

## Ⅰ. 안티포렌식의 개요

- 핵심 요약 : 공격자가 흔적을 지우고 증거의 신뢰성을 흔드는 모든 기술로, 대응은 증거가 사라지기 전에 보전하는 방향으로 설계되어야 함.
- 개념 : 수사관의 증거 수집과 분석을 방해하거나, 수집된 디지털 증거의 **법적 증거 능력** (무결성과 진정성)을 훼손하는 데 쓰이는 기술 일체.
- 배경 및 필요성 : 공격자가 파일 완전 삭제, 시간 정보 조작, 로그 삭제 같은 훼손 기법을 쓰면서 사후 분석만으로는 침해 경위를 입증하기 어려워짐. 이에 따라 실시간 증거 보전과 메모리 확보 같은 대응 기술이 요구됨.
- 주요 목적 : 침투 흔적과 거점의 은폐, 공격자 행위 분석 방해, 법정에 제출될 증거의 신뢰성 훼손.

## Ⅱ. 안티포렌식의 특징 및 장점

- 핵심 요약 : 네 가지 공격 방향이 흔적 제거와 분석 지연을 동시에 노려, 사후 분석에 의존하는 조사를 어렵게 만드는 구조.

1. **Wiping** (데이터 파괴) : 파일 영역을 0이나 난수로 덮어써 복구 가능한 흔적을 없앰 → 디스크 기반 복원 경로 차단.
2. **Steganography** (데이터 은닉) : 이미지 등 정상 파일 속에 데이터를 숨기고, **Alternate Data Stream** (ADS, 파일에 붙는 부가 데이터 스트림)에 부가 데이터를 붙여 탐지 우회.
3. **Timestomping** (흔적 변조) : 파일의 생성·수정·접근 시각을 과거 정상 시점으로 바꿔 시간선 분석을 흐트러뜨림.
4. **Anti-VM** (분석 방해) : 가상환경을 감지하면 동작을 멈추거나 위장하고, 패킹과 난독화로 정적 분석을 어렵게 함 → 샌드박스 기반 동적 분석 실패.

## Ⅲ. 안티포렌식의 구조 (흐름)

- 핵심 요약 : 공격자의 네 영역 은닉 행위와 수사관의 보전 대응이 시간 순서로 맞물리는 구조.

```text
[ 안티포렌식 4대 공격 영역 ]

안티포렌식
  1. 데이터 파괴 (Wiping, 파쇄)
  2. 데이터 은닉 (ADS, 스테가노그래피)
  3. 흔적 변조 (Timestomping, 로그 삭제)
  4. 분석 방해 (패킹, 안티 VM)
```

```text
[ 공격과 대응의 시간 흐름 ]

공격자의 흔적 은닉 (1~4 영역)
   ↓
로컬 증거 훼손 → 원격 로그로 즉시 보전
   ↓
메모리 덤프와 파일 시스템 저널로 교차 복원
```

## Ⅳ. 안티포렌식 기법과 대응 기법의 비교

- 핵심 요약 : 공격 기법마다 남는 잔존 흔적이 다르므로, 대응 도구도 기법별 흔적에 맞추어 달라짐.

| 안티포렌식 기법 | 공격자 행위 | 조사관 대응 기법 | 복원 원리 |
| --- | --- | --- | --- |
| Timestomping | `$STANDARD_INFORMATION`의 시간 값을 조작 | `$FILE_NAME` 속성과 `$UsnJrnl` 교차 검증 | NTFS(New Technology File System)가 두 시간 속성을 따로 기록해 불일치 탐지 |
| 이벤트 로그 삭제 | `wevtutil cl` 명령으로 로그 삭제 | 외부 SIEM(Security Information and Event Management)의 원격 로그와 메모리 잔존 흔적 분석 | 보안 로그 삭제 행위 자체가 이벤트 ID 1102로 기록 |
| 파일 완전 와이핑 | SDelete로 섹터 덮어쓰기 | 볼륨 섀도 복사본(VSS, Volume Shadow Copy Service)과 메모리 캐시 덤프 분석 | 삭제 전 VSS 스냅샷이나 RAM 내 잔존 평문 확보 |
| NTFS ADS 은닉 | 정상 파일에 `:숨김이름` 형태의 스트림 부착 | Sysinternals `streams` 도구와 MFT 레코드 전수 파싱 | `$DATA` 속성이 2개 이상인 MFT(Master File Table) 레코드 추출 |

- 선택 기준 : 흔적이 디스크에 남는지 메모리에 남는지, 원격 로그로 보전되었는지에 따라 우선 확보할 증거 순서를 정함.

## Ⅴ. 안티포렌식의 한계와 방안

- 핵심 요약 : 로컬 로그 훼손, 디스크 복구 불가, 가상환경 회피를 원격 보전, 메모리 우선 확보, 분석 환경 고도화로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 로컬 로그 훼손 | 단말의 로그와 시간 값이 조작되면 사건 전후 인과관계를 입증하기 어려움 | 로그를 발생 즉시 **WORM** (Write Once Read Many) 방식의 원격 저장소로 전송하고 파일 시스템 저널과 교차 분석 | 로그 전송 지연 시간, 로그 누락률 |
| 디스크 복구 불가 | 와이핑과 섀도 복사본 삭제 후에는 파일 카빙으로 복구할 수 없음 | 시스템이 켜진 상태에서 RAM(Random-Access Memory) 라이브 덤프를 우선 채취하고 메모리 분석 도구로 키와 잔존 흔적 추출 | 메모리 채취 성공률 |
| 동적 분석 실패 | 악성코드가 가상환경을 감지해 동작을 바꾸면 샌드박스 분석 결과가 왜곡됨 | 하이퍼바이저 흔적을 줄인 분석 환경과 물리 장비 기반 분석 환경 병행 | 가상환경 탐지율, 분석 재현율 |

## Ⅵ. 안티포렌식에 대한 기술사적 제언

- 핵심 요약 : 안티포렌식은 기술 경쟁만으로 막기 어려우므로, 보전 정책과 수사 절차 표준을 함께 갖출 때 증거력이 유지됨.

1. 정책 : 정보보호 부서가 로그 보존 기간과 원격 보전 기준을 전사 정책으로 정하고, 이행 여부를 정기 감사로 확인하도록 제도화.
2. 인력 : 침해대응 조직이 디지털 포렌식 전문 인력을 상시 확보하고, 증거 채취 절차에 대한 교육을 정례화해 현장 대응 품질을 유지.
3. 법제 : 법무 부서와 수사 기관이 전자 증거의 수집과 보관 절차를 사전에 합의해, 증거 능력이 소송 단계에서 인정되도록 준비.

## Ⅶ. 결론

- 핵심 요약 : 안티포렌식은 흔적을 지우는 공격 기법이며, 대응은 흔적이 사라지기 전에 보전하는 체계로 설계되어야 함.
- 시사점 : 단일 단말 증거에 의존하지 않고 원격 보전과 메모리 확보를 기본으로 삼는 것이 증거 능력 확보의 출발점임.
