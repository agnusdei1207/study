## Ⅰ. 안티포렌식(Anti-Forensic)의 개요

- 개념 : 디지털 범죄 및 해킹 공격자가 수사관의 포렌식 도구, 조사 절차, 증거 수집 활동을 방해하거나 수집된 디지털 증거의 **법적 증거 능력** (무결성, 진정성)을 훼손하기 위해 사용하는 일체의 기술.
- 배경 및 필요성 : 사이버 범죄자 및 공격자가 침해 흔적을 지우기 위해 데이터 와이핑, 타임스탬프 조작, 메모리 상주 등 디지털 증거 훼손 기법을 고도화함에 따라, 법적 증거력을 보존하고 실시간 침해 조사를 수행하기 위한 대응 기술이 요구됨.
- 핵심 목적 : 침투 흔적 및 거점 은폐, 공격자 프로파일링(TTPs) 방해, 법정 제출 증거의 오염 및 증거 배제 유도.

## Ⅱ. 안티포렌식(Anti-Forensic)의 핵심 아키텍처 및 동작 메커니즘

안티포렌식(Anti-Forensic)은(는) 신뢰할 수 있는 보안 구조와 표준화된 절차를 기반으로 동작하며, 세부적인 아키텍처와 구성요소 간의 상호작용 메커니즘은 다음과 같음.

```text
┌────────────────────────────────────────────────────────┐
│ [ 안티포렌식 4대 핵심 공격 영역 ]                      │
│                                                        │
│  ├─ 1. 데이터 파괴 (Data Destruction)                  │
│  │   - 파일 완전삭제(Wiping), 디가우징, 디스크 파쇄    │
│  │                                                     │
│  ├─ 2. 데이터 은닉 (Data Hiding)                       │
│  │   - 스테가노그래피, NTFS 대체 데이터 스트림(ADS)    │
│  │                                                     │
│  ├─ 3. 메타데이터 변조 (Artifact Modification)         │
│  │   - MFT 타임스톰핑(Timestomping), 이벤트 로그 삭제 │
│  │                                                     │
│  └─ 4. 분석 방해 (Analysis Hindrance)                  │
│      - 코드 패킹, 난독화, 안티 디버깅, 가상머신 탐지   │
└────────────────────────┬───────────────────────────────┘
                         ▼
┌────────────────────────────────────────────────────────┐
│ [ 포렌식 수사관 및 컴플라이언스 대응 체계 ]            │
│  - 실시간 원격 WORM 감사 로그 수집 (SIEM 연계)         │
│  - 휘발성 메모리 포렌식 (Volatility, LiME)             │
│  - NTFS 저널($LogFile, $UsnJrnl) 타임라인 교차 복원   │
└────────────────────────────────────────────────────────┘
```

- **1. 데이터 파괴** : **디스크 와이핑** (Wiping), 제로필, 물리적 파쇄 (잔여 자기 정보를 없애기 위해 0 또는 난수로 덮어쓰기).
- **2. 데이터 은닉** : 스테가노그래피, NTFS ADS, 슬랙(Slack) 공간 은닉 (이미지 LSB 변조, 파일명 뒤 `:hidden` 스트림 부착).
- **3. 흔적 변조** : Timestomping, 윈도우 로그 삭제(wevtutil cl) (파일의 생성/수정/접근 일시를 과거 정상 시점으로 조작).
- **4. 분석 방해** : 코드 난독화, UPX 패킹, 안티 VM, 안티 디버깅 (디버거 감지 시 자가 종료(IsDebuggerPresent), 가상환경 회피).

## Ⅲ. 안티포렌식(Anti-Forensic)의 세부 구성 요소 및 비교 분석

| 안티포렌식 기법 | 공격자 행위 | 포렌식 조사관 대응 기법 | 증거 복원 원리 |
|---|---|---|---|
| **타임스톰핑 (Timestomp)** | `$STANDARD_INFORMATION`의 MACB 시간을 조작 | `$FILE_NAME` 속성 및 `$UsnJrnl` 교차 검증 | NTFS는 두 개의 시간 속성을 가지므로 불일치 탐지 |
| **이벤트 로그 삭제** | `wevtutil cl System`으로 로컬 이벤트 로그 삭제 | 외부 SIEM 원격 로그 및 메모리 내 잔존 아티팩트 분석 | 삭제 행위 자체(이벤트 ID 1102: 감사로그 삭제) 추적 |
| **파일 완전 와이핑** | SDelete 도구로 디스크 섹터 덮어쓰기 수행 | 볼륨 섀도 복사본(VSS) 및 메모리 캐시 덤프 분석 | 삭제 직전 VSS 스냅샷 또는 RAM 내 잔존 평문 복구 |
| **NTFS ADS 은닉** | `malware.exe > normal.txt:mal.exe` 스트림 은닉 | Sysinternals `streams` 도구 및 MFT 레코드 전수 파싱 | MFT 엔트리 내 `$DATA` 속성이 2개 이상인 레코드 추출 |

- 안티포렌식(Anti-Forensic)은(는) 상기 핵심 비교 지표와 아키텍처 구성을 바탕으로 보안 위협에 대한 방어 효과성을 극대화하며, 기존 레거시 통제 기법 대비 우수한 신뢰성과 운영 효율성을 제공함.

## Ⅳ. 안티포렌식(Anti-Forensic)의 주요 한계점 및 해결 방안

- 한계점 : 로컬 시스템의 이벤트 로그 삭제 및 타임스탬프 조작 시 단일 단말 분석만으로는 사건의 전후 인과관계 **시간선** (Timeline) 입증 불가.
  - 해결 방안 : 로그 발생 즉시 로컬 단말 외부의 원격 불변(WORM) 스토리지로 전송하는 중앙 집중 **SIEM** 파이프라인 구축 및 NTFS 저널($LogFile, $UsnJrnl) 교차 분석.
- 한계점 : 디스크 와이핑(DoD 덮어쓰기) 및 볼륨 섀도 복사본 삭제 시 기존 시그니처 기반 **파일 카빙** (File Carving) 기술로 데이터 복구 불가능.
  - 해결 방안 : 전원이 켜진 상태에서 휘발성 RAM 메모리 라이브 덤프를 우선 채취(Volatility 분석)하여 프로세스 메모리에 상주하는 복호화 키 및 잔존 아티팩트 추출.
- 한계점 : 악성코드가 가상머신(VMware, VirtualBox) 환경을 탐지하고 자가 소멸하거나 정상 동작으로 위장하여 동적 악성코드 분석 실패.
  - 해결 방안 : 커널 레벨의 **베어메탈** (Bare-metal) 샌드박스를 구축하고, 하이퍼바이저 아티팩트를 은닉하는 맞춤형 분석 환경(Anti-Anti-VM) 도입.

## Ⅴ. 안티포렌식(Anti-Forensic) 적용 및 발전을 위한 기술사적 제언

- **실시간 원격 WORM 로그 전송** (위변조 차단) 체계 도입 : 실시간 원격 WORM 로그 전송 (위변조 차단) 기술을 적극 적용하여 보안 취약점을 차단하고 시스템 신뢰성을 보장해야 함.
- **라이브 메모리 포렌식 우선 확보** 체계 도입 : 라이브 메모리 포렌식 우선 확보 기술을 적극 적용하여 보안 취약점을 차단하고 시스템 신뢰성을 보장해야 함.
- **MFT, 저널, EDR 다차원 교차 검증** 체계 도입 : MFT, 저널, EDR 다차원 교차 검증 기술을 적극 적용하여 보안 취약점을 차단하고 시스템 신뢰성을 보장해야 함.
