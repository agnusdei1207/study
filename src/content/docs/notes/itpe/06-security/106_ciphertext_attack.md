## 연관 키워드

- 암호문 단독 공격(COA), 빈도 분석, 전치 분석, ECB 모드, 블록 패턴 분석
- 길이 누출, 브루트 포스, 일회용 패드(OTP), 계산적 안전성
- 초기화 벡터(IV), Nonce, CSPRNG, TRNG, AES-GCM, KMS

## Ⅰ. 암호문 단독 공격의 개요

- 핵심 요약 : 암호문만 가지고 평문이나 키를 알아내려는 가장 수동적인 공격 모델로, 통계적 패턴 노출을 막는 것이 설계 기준.
- 개념 : 공격자가 도청으로 가로챈 **암호문** (Ciphertext)만을 단서로 삼아 평문이나 암호키를 알아내려는 수동적 암호 분석 모델.
- 배경 및 필요성 : 평문에 대한 사전 정보가 전혀 없어도 암호문의 통계적 편향을 이용하면 해독이 가능하므로, 빈도 분석에 취약하지 않은 설계가 기본 척도로 요구됨.
- 주요 목적 : 가장 열악한 정보 조건에서도 패턴이 노출되지 않도록 하여 **계산적 안전성** (Computational Security)을 확보하는 것.

## Ⅱ. 암호문 단독 공격의 특징 및 장점

- 핵심 요약 : 고전 암호의 통계 분석부터 블록 암호의 운용 모드 결함까지, 암호문 자체에 남는 흔적을 이용하는 기법들의 집합.

1. **빈도 분석** (Frequency Analysis) : 단일 문자와 n-gram의 출현 빈도를 세어 치환 암호를 복원 (시저, 비즈네르 암호).
2. **전치 분석** (Transposition Analysis) : 문자 빈도는 그대로지만 위치가 바뀐 패턴을 행렬로 역추적 (컬럼 전치, 레일 펜스).
3. **반복 블록 탐색** (ECB Analysis) : 고정 크기 블록 중 동일한 블록을 묶어 평문 구조를 노출 (AES-ECB 모드).
4. **길이 분석** (Length Leakage) : 패딩 없는 가변 길이 평문의 암호문 길이로 내용 추정 (압축 후 암호화된 웹 트래픽의 CRIME 공격).
5. **브루트 포스** (Brute-Force) : 키 공간이 작거나 패스워드 기반 키가 약하면 가능한 키를 전수 대입 (DES 56비트 키).

```text
[ 안전한 운용의 구조 ]

평문 블록 ──▶ 암호 라운드 함수 ──▶ 암호문 블록
                     ▲
              비밀키 K (128/256비트)

ECB: 같은 평문 → 같은 암호문 (패턴 노출)
CBC·GCM: IV/Nonce 결합 → 매번 다른 암호문
```

## Ⅲ. 암호문 단독 공격의 구조 (흐름)

- 핵심 요약 : 암호문을 얻은 공격자가 통계 분석 → 구조 추정 → 키 또는 평문 복원으로 이어지는 단계적 과정.

1. 도청으로 암호문 스트림을 수집하고, 블록 단위 중복과 길이를 측정한다.
2. 중복과 빈도의 편향에서 평문 구조(언어, 고정 서식, 명령 형식)를 추정한다.
3. 추정한 구조와 가능한 키 공간을 대조해 평문 또는 키를 복원한다.

```text
[ COA 판정 흐름 ]

암호문 도청 수집
   ↓
블록 중복·길이 측정
   ↓
평문 구조 추정 (편향 존재 시)
   ↓
키 또는 평문 복원
```

## Ⅳ. 암호문 단독 공격의 비교

- 핵심 요약 : 고전 치환 암호는 즉시 해독되고, ECB는 구조가 노출되며, 안전한 운용 모드는 COA로 해독할 수 없는 구조로 나아감.

| 비교 항목 | 고전 치환 암호 | 블록 암호 ECB 모드 | AES-GCM (Galois/Counter Mode) |
| --- | --- | --- | --- |
| 주요 취약 요인 | 알파벳 출현 확률의 불균형 | 동일 블록의 결정론적 매핑 | 정상 운용 시 해당 없음 |
| 암호문 특성 | 평문의 통계 편향이 그대로 남음 | 같은 평문 블록이 같은 암호문 생성 | 같은 평문도 매번 다른 암호문 |
| COA 결과 | 짧은 암호문으로도 해독 가능 | 부분 평문과 데이터 윤곽 노출 | 정상 운용 시 해독 불가 |
| 안전성 기준 | 없음 | 계산적 안전성 미달 | IND-CPA 및 IND-CCA2 만족 |
| 권장 대응 | 사용 금지 | CBC 또는 GCM 모드로 전환 | 고유 Nonce와 충분한 키 길이 사용 |

- 선택 기준 : 데이터의 반복 구조 여부와 무결성 보호 필요 여부에 따라 운용 모드를 정함.

## Ⅴ. 암호문 단독 공격의 한계와 방안

- 핵심 요약 : 운용 모드 결함, 일회용 패드의 키 분배 문제, 트래픽 메타데이터 누출, 난수 결함이 실제 공격 면을 만듦.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| ECB 모드 사용 | 구현 편의로 평문 구조가 암호문에 그대로 노출 | ECB를 개발 표준에서 금지하고 IV를 쓰는 GCM 또는 CBC로 강제 | ECB 사용 코드 건수 |
| 일회용 패드(OTP)의 키 분배 | 평문과 같은 길이의 키를 안전하게 공유해야 해 실무 적용이 어려움 | 정보이론적 안전성 대신 검증된 암호학적 난수 기반 계산적 안전성 채택 | 키 교체 주기 준수율 |
| 트래픽 메타데이터 누출 | 암호문 크기와 전송 간격으로 내용이 추론됨 | 고정 크기 패딩과 가상 트래픽 주입(Chaffing) 적용 | 패딩 적용률 |
| 난수 생성기 결함 | 임베디드 기기의 PRNG 결함으로 키 공간이 줄어 전수 대입 가능 | 하드웨어 **TRNG** (True Random Number Generator) 탑재와 NIST SP 800-90A 기준 CSPRNG 사용 | 난수 품질 검증 통과율 |

## Ⅵ. 암호문 단독 공격 대응을 위한 기술사적 제언

- 핵심 요약 : 운용 모드와 키·난수 관리를 표준으로 고정하고, 메타데이터 보호까지 포함한 암호 거버넌스로 관리.

1. 사내 데이터베이스와 통신 암호화를 인증 암호 모드 하나로 통일하면, 패턴 노출과 무결성 변조를 함께 줄이는 효과를 기대할 수 있다.
2. 키와 난수 관리를 키 관리 시스템(KMS)과 연동된 중앙 체계로 운영하면, 개별 개발자의 Nonce 실수가 키스트림 누출로 이어지는 일을 줄일 수 있다.
3. 민감 서비스는 전송 계층에서 메타데이터 보호 기능을 적용하는 방향으로 점검 범위를 넓히는 것이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : 암호문 단독 공격은 암호 설계가 패턴을 얼마나 숨기는지 판정하는 가장 기본적인 시험.
- 시사점 : 운용 모드와 난수 품질이 함께 갖춰진 암호만이 가장 열악한 정보 조건에서도 기밀을 지킬 수 있다.
