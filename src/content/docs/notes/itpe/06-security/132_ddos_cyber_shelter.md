## 연관 키워드

- DDoS 사이버대피소, 분산 서비스 거부(DDoS), 스크러빙 센터(Scrubbing Center), 청정 트래픽
- DNS CNAME 우회, WAF(Web Application Firewall), BGP 블랙홀 라우팅, 상시 대피소 연동
- 원본 서버(Origin Server), TTL(Time-To-Live), ACME

## Ⅰ. DDoS 사이버대피소의 개요

- 핵심 요약 : 자체 방어 장비가 없는 중소기업에 KISA가 무료로 트래픽을 우회·정화해 주는 공공 DDoS 방어 서비스.
- 개념 : 한국인터넷진흥원(KISA, Korea Internet & Security Agency)이 운영하는 **사이버대피소** 서비스로, 대규모 **분산 서비스 거부** (DDoS, Distributed Denial of Service) 공격 시 웹 트래픽을 대피소로 돌려 공격 트래픽을 걸러내고 정상 트래픽만 원본 서버로 전달하는 국가 주도 방어 인프라.
- 배경 및 필요성 : 공격 규모가 대형화되면서 보안 예산과 인력이 없는 중소기업 웹 서버가 마비되어 영업 손실이 커졌고, 이에 대응할 공공 안전망의 필요성이 제기됨.
- 주요 목적 : 중소기업 웹 서비스의 연속성 보장과, 악성 트래픽이 상위 망으로 번지는 것을 사전에 차단하는 국가 차원의 방어력 강화.
- 운영 기준 : KISA 공식 안내에 따르면 중소기업기본법상 중소기업을 대상으로 하며, 이용 기간은 기본 1개월이고 재공격이 예상되면 1개월 단위로 연장 가능. 2022년 보도에서는 방어 건수가 2020년 235건으로 집계되었다고 전함.

## Ⅱ. DDoS 사이버대피소의 특징 및 장점

- 핵심 요약 : DNS 기반 긴급 우회, 다계층 정화, 원본 IP 제한이 중소기업의 방어 비용 부담을 낮추는 방식.

1. DNS 기반 긴급 우회 : 도메인 레코드를 대피소 쪽으로 바꿔 트래픽을 전환 → 자체 장비 없이 공격 중에도 서비스 경로 유지.
2. 다계층 정화 : 대역폭 공격은 하위 계층 필터로, HTTP 공격은 웹 계층 탐지로 나누어 처리 → 공격 유형별로 정상 트래픽 손실 최소화.
3. 원본 IP 보호 : 대피소 프록시 대역만 원본 서버에 허용 → 공격자가 원본 주소로 직접 접근하는 경로 차단.
4. 상시 연동 : 사전 등록 시 평시부터 연동해 두어 공격 시점의 전환 지연을 줄임.

## Ⅲ. DDoS 사이버대피소의 구조 (흐름)

- 핵심 요약 : DNS 전환으로 트래픽을 대피소에 모으고, 정화된 트래픽만 원본 서버로 프록시하는 두 단계 구조.
- **DNS CNAME 우회** : 도메인 레코드를 대피소 도메인으로 바꾸어 트래픽을 강제로 경유시키는 방식.
- **스크러빙 센터** (Scrubbing Center) : 공격 트래픽을 걸러내고 **청정 트래픽** (Clean Traffic)만 남기는 정화 설비.

```text
[ 트래픽 우회 흐름 ]

정상 사용자 + 공격 트래픽
   ↓ DNS 레코드 변경 (CNAME)
KISA 사이버대피소 (스크러빙)
   ↓ 정화된 트래픽만 프록시
중소기업 원본 웹 서버
```

```text
[ 다계층 정화 ]

L3/L4 볼륨 방어
 (UDP 플러드, 증폭 공격 드롭)
   ↓
L7 웹 방어
 (WAF 검사, 행위 기반 탐지)
```

## Ⅳ. DDoS 사이버대피소와 다른 방어 방식의 비교

- 핵심 요약 : 무료 공공 서비스는 웹 중심이고 전환 지연이 있으며, 상용 스크러빙이나 온프레미스 장비는 비용과 운영 부담이 큼.

| 비교 항목 | KISA DDoS 사이버대피소 | 상용 클라우드 스크러빙 | 온프레미스 안티 DDoS 장비 |
| --- | --- | --- | --- |
| 이용 비용 | 중소기업 대상 무료 (정부 지원) | 서비스 계약에 따른 유료 | 장비 구매와 회선 증설 비용 |
| 지원 프로토콜 | 주로 HTTP·HTTPS 웹 서비스 | 웹과 TCP·UDP, DNS 등 다수 | L3~L7 인라인 전 프로토콜 |
| 전환 속도 | DNS 전파 지연 가능 | 상시 프록시 운영 시 지연 최소 | 인라인 구성으로 즉시 차단 |
| 주요 대상 | 국내 중소기업, 영세 사업자, 비영리 | 대형 기업과 서비스 사업자 | 자체 데이터센터를 가진 기관 |

- 선택 기준 : 예산과 인력이 부족하고 웹 서비스 중심이면 대피소가, 비웹 서비스나 즉시 차단이 필요하면 상용 또는 자체 장비가 적합.

## Ⅴ. DDoS 사이버대피소의 한계와 방안

- 핵심 요약 : DNS 전환 지연, 원본 IP 노출, 비웹 프로토콜 미지원을 사전 설정과 방화벽 차단, 경로 다변화로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| DNS 캐시 TTL에 따른 전환 지연 | 레코드를 바꿔도 ISP 캐시가 만료될 때까지 공격 트래픽이 원본으로 유입 | 평시 TTL을 짧게 관리하고 상시 연동 모드 적용 | 전환 완료 소요 시간 |
| 원본 공인 IP 노출 | 과거 DNS 이력 등으로 원본 주소가 드러나면 대피소를 우회한 직접 공격 발생 | 원본 서버 앞단 방화벽에서 대피소 프록시 대역 외 인바운드 차단 | 우회 접속 시도 건수 |
| 비웹 프로토콜 제약 | 게임, VoIP, VPN 등 독자 포트 서비스는 웹 프록시 구조로 보호 곤란 | BGP Flowspec 등 L3/L4 대피 경로 검토와 프록시 파이프라인 확충 | 비웹 서비스 보호 범위 |

## Ⅵ. DDoS 사이버대피소에 대한 기술사적 제언

- 핵심 요약 : 사후 신청 중심에서 사전 등록과 민관 공조로 전환해야 대응 속도와 범위가 함께 확보됨.
- 중소기업 대상 사전 등록과 상시 연동을 확대하여, 공격 이후 신청하는 방식에서 평시에 준비된 방어로 옮겨 가는 것이 바람직하다.
- 대피소 용량을 넘는 대규모 공격에 대비해, 통신사 망에서 공격 발원 대역을 BGP 블랙홀 라우팅으로 차단하는 민관 공조 절차를 정립하는 것이 필요하다.
- 원본 서버 인증서를 대피소에 맡겨야 할 경우 파일을 수동 전달하기보다 ACME(Automatic Certificate Management Environment) 기반의 자동 갱신 방식을 검토하는 것이 키 유출 위험을 줄인다.

## Ⅶ. 결론

- 핵심 요약 : DDoS 사이버대피소는 자체 방어 여력이 없는 중소기업의 웹 서비스를 지키는 공공 안전망.
- 시사점 : 공공 방어망의 효과는 DNS 전환 속도와 원본 서버 보호 설정에 좌우되므로, 사전 설정이 방어 성능을 결정.
