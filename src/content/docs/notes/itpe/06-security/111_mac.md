## 지식 로드맵 내 현재 위치

정보보안 → 암호학 → 메시지 무결성 및 주체 인증 → 메시지 인증 코드(MAC)

## 30초 인출

- **본질:** 송수신자가 공유한 대칭 비밀키와 임의 길이 메시지를 입력으로 고정 길이 태그(Tag)를 생성하여, 전송 중 데이터 위변조 탐지(무결성)와 발신자의 정당한 키 소유 여부(인증)를 동시에 검증하는 대칭 암호 기술.
- **메커니즘:** 송신자가 $Tag = MAC(K, M)$ 생성 후 전송 → 수신자가 동일 비밀키 $K$로 $Tag' = MAC(K, M)$ 재계산 → 상수 시간 비교($Tag == Tag'$)를 통해 변조 여부 판정.
- 통찰: 대칭키 공유 구조로 인해 제3자에 대한 부인방지(Non-repudiation)가 불가능하며, 재생 공격(Replay Attack) 방지를 위해 시퀀스 번호 및 Nonce 결합 필수.

<details><summary>핵심 용어</summary>

- **MAC(Message Authentication Code)**: 메시지의 무결성과 송신자의 인증을 단일 메커니즘으로 제공하는 암호학적 체크섬.
- **HMAC(Hash-based MAC)**: MD5, SHA-256 등 일방향 해시 함수와 비밀키를 내부/외부 패딩(ipad, opad) 구조로 결합한 표준 MAC (RFC 2104).
- **CMAC(Cipher-based MAC)**: AES 등 블록 암호의 CBC 모드를 기반으로 메시지 길이 확장 공격을 방어하도록 설계된 NIST 표준 MAC (SP 800-38B).
- **GMAC(Galois MAC)**: Galois/Counter Mode(GCM)의 인증 알고리즘(GHASH)만을 활용하여 암호화 없이 고속으로 메시지를 인증하는 하드웨어 친화적 MAC.
- **부인방지 결여(Lack of Non-repudiation)**: 송신자와 수신자가 동일한 비밀키를 공유하므로, 수신자가 직접 태그를 위조할 수 있어 제3자에게 송신 사실을 법적으로 증명할 수 없는 한계.
</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 송신자와 수신자가 사전에 공유한 대칭키(K)를 바탕으로 메시지로부터 작은 고정 블록의 인증 태그(Tag)를 생성하여 데이터의 무결성과 메시지 출처를 확인하는 암호 기술 |
| 목적 | 네트워크 전송 중 공격자에 의한 패킷 변조(Tampering) 및 위조(Spoofing)를 탐지하고, 대칭키 기반의 고속 인증 채널 구현 |

## Ⅱ. 메시지 인증 코드(MAC)의 핵심 특징 및 보안 보장 속성

| 보안 속성 | 세부 동작 메커니즘 | 기술적 한계 및 보완 |
|---|---|---|
| 데이터 무결성 (Integrity) | 메시지 내 단 1비트만 변경되어도 수신자 재계산 태그와 불일치 유발 | 공격자의 메시지 조작 즉각 탐지 및 패킷 드롭 |
| 메시지 출처 인증 (Authentication) | 올바른 비밀키(K)를 보유한 정당한 참여자만이 유효한 태그 생성 가능 | 비밀키 미보유 외부 제3자의 메시지 위조 차단 |
| 고속 처리 성능 | 비대칭키 전자서명 대비 수십~수백 배 빠른 연산 속도 제공 | 대용량 네트워크 패킷(IPsec, TLS) 실시간 인증 최적 |
| 기밀성 미제공 | 순수 MAC 단독으로는 평문 데이터를 암호화하지 않음 | 기밀성이 필요할 경우 대칭 암호와 결합(AEAD) 필수 |
| 부인방지 불가 | 송신자와 수신자가 동일한 대칭키를 공유하므로 수신자도 태그 생성 가능 | 제3자 앞에서의 법적 송신 부인 방지 불가 (전자서명 필요) |

## Ⅲ. MAC 동작 프로세스 및 주요 알고리즘 아키텍처

```text
[ 송신자 (Sender) ]                                          [ 수신자 (Receiver) ]
메시지 M ───────────────────── [ 평문 메시지 M 전송 ] ─────────────────────▶ 수신 메시지 M
   │                                                                           │
   ▼                                                                           ▼
[ MAC 생성 알고리즘 ] ◀── 공유 비밀키 K                    공유 비밀키 K ──▶ [ MAC 검증 알고리즘 ]
   │                                                                           │
   ▼                                                                           ▼
인증 태그 T = MAC(K, M) ─── [ 인증 태그 T 전송 ] ─────────────────────────▶ 계산된 태그 T' = MAC(K, M)
                                                                               │
                                                                               ▼
                                                                     [ 상수 시간 비교: T == T' ]
                                                                       ├── [일치]: 무결/인증 성공
                                                                       └── [불일치]: 변조 패킷 폐기
```

| 구분 | HMAC (Hash-based MAC) | CMAC (Cipher-based MAC) | GMAC (Galois MAC) |
|---|---|---|---|
| 기반 알고리즘 | 암호학적 일방향 해시 함수 (SHA-256 등) | 대칭키 블록 암호 (AES-128/256) | 갈루아체($GF(2^{128})$) 곱셈 기반 GHASH |
| 핵심 수식/원리 | $H((K \oplus opad) \parallel H((K \oplus ipad) \parallel M))$ | CBC-MAC 변형, 서브키($K_1, K_2$) XOR | 다항식 해시 연산 및 Nonce 암호화 결합 |
| 표준 규격 | RFC 2104, FIPS 198-1 | NIST SP 800-38B, RFC 4493 | NIST SP 800-38D |
| 취약점 방어 | 단순 $H(K \parallel M)$의 길이 확장 공격 방어 | 임의 길이 메시지 패딩 오라클/확장 방어 | 고속 연산 가능하나 Nonce 재사용 시 파멸적 취약 |
| 하드웨어 가속 | 일반적 (CPU 해시 명령어 지원) | AES-NI 명령어 세트 활용 | 최상 (Intel PCLMULQDQ 명령어 고속 가속) |
| 주 활용 분야 | JWT 서명, IPsec, TLS 1.2 PRF | 금융 결제 단말기, 임베디드 차량 보안 | TLS 1.3 AEAD 인증 태그, 고속 네트워크 스위치 |

## Ⅳ. 메시지 인증 코드(MAC) vs 디지털 전자서명(Digital Signature) 비교

| 비교 항목 | 메시지 인증 코드 (MAC) | 디지털 전자서명 (Digital Signature) |
|---|---|---|
| 사용 암호키 | 송수신자 간 대칭 공유 비밀키 (Symmetric Key) | 송신자 개인키(서명) / 수신자 공개키(검증) |
| 연산 속도 | 매우 빠름 (수 마이크로초 단위) | 상대적으로 느림 (비대칭키 모듈러/타원곡선 연산) |
| 메시지 무결성 | 보장함 | 보장함 |
| 송신자 인증 | 통신 상대방 간에만 상호 인증 가능 | 전 세계 누구나 송신자 신원 검증 가능 |
| 부인방지 (Non-repudiation) | 불가 (수신자도 키를 알기 때문에 태그 자가 생성 가능) | 절대 보장 (오직 송신자 개인키로만 서명 생성 가능) |
| 키 관리 체계 | $N$자 간 통신 시 $O(N^2)$ 대칭키 공유 부담 | PKI 인증서 기반 $O(N)$ 공개키 관리 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 공격자가 이전에 도청한 정상적인 메시지와 MAC 태그를 그대로 다시 전송하는 재전송 공격(Replay Attack) 취약 | 메시지 페이로드에 단조 증가 시퀀스 번호(Sequence Number), 세션 Nonce 또는 RFC 3161 타임스탬프를 필수 결합하여 인증 범위에 포함 |
| 소프트웨어에서 MAC 태그 비교 시 바이트 단위 순차 비교(`memcmp`)를 수행하여 발생하는 타이밍 공격(Timing Attack) 누출 | 암호문 불일치 시에도 모든 바이트를 전수 비교한 후 결과를 반환하는 상수 시간 비교 함수(`CRYPTO_memcmp`) 강제 사용 |
| GMAC 사용 시 실수로 동일한 초기화 벡터(Nonce)를 2회 이상 재사용할 경우 비밀 인증 키(H)가 수학적으로 즉시 노출 | 카운터 기반 Nonce 생성 시 결정론적 단조 증가 로직을 강제하고 키당 최대 암호화 패킷 수(예: $2^{32}$회) 도달 시 세션키 자동 갱신 |
| 대칭키 공유 특성상 분쟁 발생 시 법원에서 송신자가 해당 거래를 보냈음을 입증할 수 없는 법적 증거력 한계 | 금융 및 전자계약 등 법적 책임이 수반되는 거래에서는 MAC 대신 PKI 기반의 X.509 전자서명과 타임스탬프 토큰을 복합 적용 |

## Ⅵ. 제언

```text
[ 고신뢰 메시지 인증 아키텍처 3대 원칙 ]

+-------------------------+      +-------------------------+      +-------------------------+
|     1. AEAD 단일화      | ---> |     2. 신선도(Freshness)| ---> |     3. 상수 시간 비교   |
| (AES-GCM / ChaCha-Poly) |      | (Sequence + Nonce 결합) |      | (Constant-Time Compare) |
+-------------------------+      +-------------------------+      +-------------------------+
```

| 구현 계층 | 엔지니어링 실무 구현 과제 | 비즈니스 가치 |
|---|---|---|
| 암호화/인증 결합 | 암호화 후 MAC(Encrypt-then-MAC) 수작업을 지양하고 AEAD 표준(AES-GCM) 단일 채널 채택 | 패딩 오라클 공격 및 결합 오류 원천 차단 |
| 재전송 방어 | 슬라이딩 윈도우(Sliding Window) 기반 패킷 시퀀스 번호 검증 및 타임아웃 통제 | 재생 공격을 통한 비인가 중복 거래(결제 등) 방지 |
| 라이브러리 검증 | FIPS 140-3 검증 암호 모듈 활용 및 안전한 상수 시간 비교 API 강제 | 사이드채널 타이밍 분석을 통한 MAC 위조 100% 방어 |

## 출제 이력과 검증 출처

- 제127회 정보관리기술사 (메시지 인증 코드와 전자서명 비교)
- NIST FIPS PUB 198-1, The Keyed-Hash Message Authentication Code (HMAC)
- NIST SP 800-38B, Recommendation for Block Cipher Modes of Operation: The CMAC Mode for Authentication
- NIST SP 800-38D, Recommendation for Block Cipher Modes of Operation: Galois/Counter Mode (GCM) and GMAC
