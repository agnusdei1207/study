## Ⅰ. 메시지 인증 코드(MAC)의 개요

- **개념** : 송신자와 수신자가 사전에 공유한 대칭키(K)를 바탕으로 메시지로부터 작은 고정 블록의 인증 태그(Tag)를 생성하여 데이터의 무결성과 메시지 출처를 확인하는 암호 기술.
- **배경 및 필요성** : 데이터 전송 중 제3자에 의한 비인가 변조 및 위조를 탐지하고 송신자의 정당성을 확인하기 위해, 대칭 비밀키를 공유하는 송·수신자 간에 메시지의 무결성과 인증을 동시에 보장하는 암호학적 메커니즘으로 필수화됨.
- **핵심 목적** : 네트워크 전송 중 공격자에 의한 패킷 변조(Tampering) 및 위조(Spoofing)를 탐지하고, 대칭키 기반의 고속 인증 채널 구현.

## Ⅱ. 메시지 인증 코드(MAC)의 핵심 아키텍처 및 동작 메커니즘

메시지 인증 코드(MAC)은(는) 신뢰할 수 있는 보안 구조와 표준화된 절차를 기반으로 동작하며, 세부적인 아키텍처와 구성요소 간의 상호작용 메커니즘은 다음과 같음.

```text
[ 송신자 (Sender) ]                                          [ 수신자 (Receiver) ]
메시지 M ───────────────────── [ 평문 메시지 M 전송 ] ─────────────────────▶ 수신 메시지 M
   │                                                                           │
   ▼                                                                           ▼
[ MAC 생성 알고리즘 ] ◀── 공유 비밀키 K                    공유 비밀키 K ──▶ [ MAC 검증 알고리즘 ]
   │                                                                           │
   ▼                                                                           ▼
인증 태그 T = MAC(K, M) ─── [ 인증 태그 T 전송 ] ─────────────────────────▶ 계산된 태그 T' = MAC(K, M)
                                                                               │
                                                                               ▼
                                                                     [ 상수 시간 비교: T == T' ]
                                                                       ├── [일치]: 무결/인증 성공
                                                                       └── [불일치]: 변조 패킷 폐기
```

- **기반 알고리즘** : 암호학적 일방향 해시 함수 (SHA-256 등) (대칭키 블록 암호 (AES-128/256)).
- **핵심 수식/원리** : $H((K \oplus opad) \parallel H((K \oplus ipad) \parallel M))$ (CBC-MAC 변형, 서브키($K_1, K_2$) XOR).
- **표준 규격** : RFC 2104, FIPS 198-1 (NIST SP 800-38B, RFC 4493).
- **취약점 방어** : 단순 $H(K \parallel M)$의 길이 확장 공격 방어 (임의 길이 메시지 패딩 오라클/확장 방어).
- **하드웨어 가속** : 일반적 (CPU 해시 명령어 지원) (AES-NI 명령어 세트 활용).
- **주 활용 분야** : JWT 서명, IPsec, TLS 1.2 PRF (금융 결제 단말기, 임베디드 차량 보안).

## Ⅲ. 메시지 인증 코드(MAC)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 메시지 인증 코드 (MAC) | 디지털 전자서명 (Digital Signature) |
|---|---|---|
| 사용 암호키 | 송수신자 간 대칭 공유 비밀키 (Symmetric Key) | 송신자 개인키(서명) / 수신자 공개키(검증) |
| 연산 속도 | 매우 빠름 (수 마이크로초 단위) | 상대적으로 느림 (비대칭키 모듈러/타원곡선 연산) |
| 메시지 무결성 | 보장함 | 보장함 |
| 송신자 인증 | 통신 상대방 간에만 상호 인증 가능 | 전 세계 누구나 송신자 신원 검증 가능 |
| 부인방지 (Non-repudiation) | 불가 (수신자도 키를 알기 때문에 태그 자가 생성 가능) | 절대 보장 (오직 송신자 개인키로만 서명 생성 가능) |
| 키 관리 체계 | $N$자 간 통신 시 $O(N^2)$ 대칭키 공유 부담 | PKI 인증서 기반 $O(N)$ 공개키 관리 |

- 메시지 인증 코드(MAC)은(는) 상기 핵심 비교 지표와 아키텍처 구성을 바탕으로 보안 위협에 대한 방어 효과성을 극대화하며, 기존 레거시 통제 기법 대비 우수한 신뢰성과 운영 효율성을 제공함.

## Ⅳ. 메시지 인증 코드(MAC)의 주요 한계점 및 해결 방안

- **한계점** : 공격자가 이전에 도청한 정상적인 메시지와 MAC 태그를 그대로 다시 전송하는 재전송 공격(Replay Attack) 취약.
  - **해결 방안** : 메시지 페이로드에 단조 증가 시퀀스 번호(Sequence Number), 세션 Nonce 또는 RFC 3161 타임스탬프를 필수 결합하여 인증 범위에 포함.
- **한계점** : 소프트웨어에서 MAC 태그 비교 시 바이트 단위 순차 비교(`memcmp`)를 수행하여 발생하는 타이밍 공격(Timing Attack) 누출.
  - **해결 방안** : 태그 불일치 시에도 모든 바이트를 전수 비교한 후 결과를 반환하는 상수 시간 비교 함수(`CRYPTO_memcmp`) 강제 사용.
- **한계점** : GMAC 사용 시 실수로 동일한 초기화 벡터(Nonce)를 2회 이상 재사용할 경우 비밀 인증 키(H)가 수학적으로 즉시 노출.
  - **해결 방안** : 카운터 기반 Nonce 생성 시 결정론적 단조 증가 로직을 강제하고 키당 최대 암호화 패킷 수(예: $2^{32}$회) 도달 시 세션키 자동 갱신.
- **한계점** : 대칭키 공유 특성상 분쟁 발생 시 법원에서 송신자가 해당 거래를 보냈음을 입증할 수 없는 법적 증거력 한계.
  - **해결 방안** : 금융 및 전자계약 등 법적 책임이 수반되는 거래에서는 MAC 대신 PKI 기반의 X.509 전자서명과 타임스탬프 토큰을 복합 적용.

## Ⅴ. 메시지 인증 코드(MAC) 적용 및 발전을 위한 기술사적 제언

- **암호화/인증 결합 중심의 거버넌스 및 실행 체계 구축** : 암호화 후 MAC(Encrypt-then-MAC) 수작업을 지양하고 AEAD 표준(AES-GCM) 단일 채널 채택을(를) 적극 추진하여, 패딩 오라클 공격 및 결합 오류 원천 차단 효과를 극대화해야 함.
- **재전송 방어 중심의 거버넌스 및 실행 체계 구축** : 슬라이딩 윈도우(Sliding Window) 기반 패킷 시퀀스 번호 검증 및 타임아웃 통제을(를) 적극 추진하여, 재생 공격을 통한 비인가 중복 거래(결제 등) 방지 효과를 극대화해야 함.
- **라이브러리 검증 중심의 거버넌스 및 실행 체계 구축** : FIPS 140-3 검증 암호 모듈 활용 및 안전한 상수 시간 비교 API 강제을(를) 적극 추진하여, 사이드채널 타이밍 분석을 통한 MAC 위조 100% 방어 효과를 극대화해야 함.
