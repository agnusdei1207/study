## 지식 로드맵 내 현재 위치

지식 위치: 암호학 → 메시지 무결성·인증 → **MAC**

## 30초 인출

- 본질: MAC은 공유 비밀키와 메시지로 태그를 만들고 검증해 무결성과 키 보유를 확인하는 방식
- 메커니즘: 송신자가 K·메시지로 태그 생성 → 수신자가 같은 K로 재계산·비교 → 수락 또는 거부
- 통찰: 한계: 공유키만으로는 송신자 단독 책임이나 재전송 방지를 보장할 수 없음 → 방안: 순서번호·논스를 인증 대상에 포함하고 키 사용 주체를 관리

<details><summary>핵심 용어</summary>

- HMAC: 해시 함수 기반 메시지 인증 코드.
- GMAC: GCM 인증 함수를 암호화 없이 사용하는 메시지 인증 방식.

</details>

## 2~4교시 예상문제 (25점)

> MAC의 동작 원리와 HMAC·CMAC·GMAC을 비교하고, 서비스 메시지 인증 설계 시의 주의점을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | MAC은 공유 비밀키와 메시지로 태그를 만들고 검증해 메시지 무결성과 키 보유를 확인하는 방식 |
| 목적 | 전송 중 변조와 키 미보유 공격자의 메시지 위조 탐지 |

MAC은 공유 비밀키를 아는 참여자만 유효 태그를 만들 수 있다는 가정에 기반한 메시지 인증 수단. 기밀성 암호화 기능 자체는 제공하지 않음.

### Ⅱ. 구조와 검증 흐름

```text
송신자: 공유키 K + 메시지·순서번호 → 태그 T
                │ (메시지·번호·태그) 전달
                ↓
수신자: K로 재계산 → 태그 비교 + 번호 재사용 검사
```

| 단계 | 처리 |
|---|---|
| 키 배포 | 송수신자가 신뢰 가능한 경로로 K 공유 |
| 태그 생성 | T = MAC(K, 메시지·메타데이터) |
| 전송 | 메시지·태그·필요한 논스/순서번호 전송 |
| 검증 | 태그 재계산 후 시간차 공격을 줄이는 방식으로 비교 |
| 재전송 제어 | 논스·시각·순서번호와 상태 검증 |

### Ⅲ. 알고리즘 비교

| 방식 | 기반 | 적용상 주의 |
|---|---|---|
| HMAC | 암호학적 해시와 공유키 | 단순 Hash(K∥M)과 구별 |
| CMAC | 블록 암호 | 승인된 블록 암호·키 길이 선택 |
| GMAC | GCM 인증 함수 | 같은 키에서 논스 재사용 금지 |

GMAC은 암호화하지 않는 데이터의 MAC 생성에 쓰이는 GCM 특수화. GCM 암호화 전체를 GMAC이라고 부르지 않음.

#### 설계 위험과 대책

| 위험 | 대책 |
|---|---|
| 태그만 재전송 | 거래 ID·논스·시각을 인증 대상에 포함 |
| 키 유출 | 키 분리·교체·접근 통제 |
| 메시지 의미 혼동 | 메시지 길이·타입·발신자·수신자 맥락을 인증 대상에 포함 |
| 짧은 태그·잘못된 비교 | 적정 태그 길이와 라이브러리의 안전한 비교 함수 사용 |

#### MAC과 전자서명 구분

공유키를 가진 양측 모두 같은 태그를 만들 수 있어, MAC 단독으로 제삼자에게 특정 송신자만 보냈음을 입증할 수 없음. 법적 부인 방지 여부는 기술적 서명 검증 외에도 신원·절차·증거 보존에 의존.

### Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 공유키 MAC만으로 송신자 단독 책임과 재전송 방지를 보장하지 못함 | 순서번호·nonce를 인증 범위에 넣고 키 사용 주체를 관리 |

### Ⅴ. 제언

메시지의 내용뿐 아니라 문맥과 신선도를 함께 인증하고, 키 수명 주기와 검증 실패 처리까지 설계.
