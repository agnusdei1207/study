## 연관 키워드

- NAC(Network Access Control), 802.1X, EAP, 보안 상태 검역(Posture Assessment), 격리 VLAN
- 에이전트리스(Agentless), 포트 보안(Port Security), ZTNA, SASE, EDR, NDR

## Ⅰ. NAC의 개요

- 핵심 요약 : 단말의 신원과 보안 상태를 검증해 접속을 허용, 격리, 치료하는 중앙 집중형 접근 통제 체계.
- 개념 : 기업 내부망에 유·무선으로 접속하는 PC(Personal Computer), 노트북, 스마트폰, IoT(Internet of Things) 단말의 신원을 인증하고, 백신 설치, 최신 패치, 비인가 소프트웨어 등 보안 컴플라이언스 준수 여부를 검증하여 접속을 허용·격리·치료하는 **네트워크 접근 제어** (NAC, Network Access Control) 솔루션.
- 배경 및 필요성 : 원격 근무, BYOD(Bring Your Own Device), 무선 망 확산으로 보안 통제를 벗어난 단말이 사내망에 접속하면서, 감염된 개인 기기가 내부 랜섬웨어 확산의 진원지가 되는 문제가 커짐.
- 주요 목적 : 인가되지 않은 단말의 접속을 원천 차단하고, 인가된 단말도 보안 무결성이 확인된 경우에만 최소 네트워크 권한을 부여.

## Ⅱ. NAC의 특징 및 장점

- 핵심 요약 : 인증, 검역, 격리, 사후 모니터링이 순서대로 연결되어 검증되지 않은 단말이 업무망에 닿지 않는 방식.

1. **접속 전 검역** (Pre-admission Assessment) : 정식 IP 할당 전 격리 VLAN(Virtual Local Area Network)에서 백신 업데이트, 보안 설정, 불법 P2P 프로그램 여부를 점검 → 검증 전 단말의 내부망 노출 차단.
2. **포트 기반 인증** (IEEE 802.1X) : EAP(Extensible Authentication Protocol)를 스위치 포트 단위로 수행 → 표준 기반이라 가장 강력한 접속 통제.
3. **지속적 사후 모니터링** (Post-admission Monitoring) : 접속 후에도 유해 트래픽이나 백신 프로세스 강제 종료를 감지하면 세션을 끊고 격리 VLAN으로 이동 → 접속 이후 상태 변화에 대응.
4. 에이전트리스(Agentless) 병행 : 프린터나 IP 카메라처럼 에이전트를 설치할 수 없는 기기는 MAC(Media Access Control)과 SNMP(Simple Network Management Protocol) 기반으로 식별 → 관리 대상 범위 확대.

```text
[ NAC 접근 제어 흐름 ]

엔드포인트 단말 (접속 시도)
    ↓ (802.1X 인증 요청)
네트워크 접근 계층 (스위치·무선 AP)
    ↓ (EAP 인증 요청)
NAC 정책 서버 (식별·검역)
    ↓
검역 통과 → 업무망 (VLAN 10)
검역 실패 → 격리망 (VLAN 99)
```

## Ⅲ. NAC의 구조 (흐름)

- 핵심 요약 : 인증, 검역, 접근 권한 제어, 치료가 순환하는 4단계 프레임워크로 단말 접속을 통제하는 구조.
- **사용자·단말 인증** (Authentication) : 계정과 단말 식별 정보(MAC 주소, 인증서)를 Active Directory·LDAP(Lightweight Directory Access Protocol)과 연계하여 확인.
- **보안 상태 검역** (Posture Assessment) : 백신 실시간 감시, OS 최신 패치, 필수 보안 에이전트인 DLP(Data Loss Prevention)와 DRM(Digital Rights Management) 실행 여부를 확인.
- **접근 권한 제어** (Access Control) : 검역 결과에 따라 업무망 또는 격리망의 VLAN을 할당.
- **사후 감사 및 치료** (Remediation) : 격리된 단말을 백신·패치 서버로만 연결하여 자가 치료를 유도한 뒤 재검역.

```text
[ NAC 4단계 프레임워크 ]

인증 (Authentication)
    ↓
검역 (Posture Assessment)
    ↓
접근 권한 제어 (Access Control)
    ↓
감사·치료 (Remediation)
    ↓ (검역 실패 시 격리 후 재검역)
```

## Ⅳ. NAC의 비교 분석

- 핵심 요약 : 접속 지점을 지키는 NAC, 경계 트래픽을 검사하는 차세대 방화벽, 신원 기반으로 앱 접근을 제어하는 제로 트러스트 방식이 통제 계층에서 구분되는 구조.

비교 대상은 **차세대 방화벽** (NGFW, Next-Generation Firewall)과 **제로 트러스트 네트워크 액세스** (ZTNA, Zero Trust Network Access)다.

| 비교 축 | NAC | NGFW | ZTNA |
| --- | --- | --- | --- |
| 통제 계층 | L2 데이터링크 계층 (단말 접속 지점) | L3~L7 네트워크 경계 | L7 애플리케이션 계층 (신원 기준) |
| 통제 초점 | 단말 무결성과 접속 여부 | IP·포트·애플리케이션 흐름 | 사용자 신원과 최소 권한 앱 접근 |
| 검역 방식 | 사전 검역과 격리 | 인라인 심층 패킷 검사 (DPI, Deep Packet Inspection) | 신원 검증 후 소프트웨어 정의 경계(SDP, Software-Defined Perimeter) 형성 |
| 내부 횡적 이동 | 동일 VLAN 내 이동 통제 한계 | 서브넷 간 이동만 통제 | 마이크로 세그멘테이션(Micro-segmentation)으로 격리 |
| 주요 대상 | 유무선 사내망 단말 (IoT 포함) | 내·외부망 경계 트래픽 | 클라우드와 원격 근무 환경 |

- 선택 기준 : 사내망 접속 지점의 단말 통제는 NAC가, 경계 트래픽 검사는 NGFW가, 클라우드와 원격 접근의 신원 기반 통제는 ZTNA가 담당하며, 현대에는 세 체계가 연계되는 방향으로 운영됨.

## Ⅴ. NAC의 한계와 방안

- 핵심 요약 : ARP(Address Resolution Protocol) 기반 제어의 부하, 허브와 공유기를 통한 단말 은닉, 에이전트 설치 불가 기기가 주요 한계.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| ARP 기반 제어의 부하 | 가짜 응답을 지속 전송하는 소프트웨어 방식이 스위치에 과부하를 주어 네트워크 장애 위험 초래 | ARP 방식을 탈피하고 스위치 기반 **802.1X** 동적 VLAN 할당으로 전환 | 스위치 부하율, ARP 트래픽 양 |
| 사설 공유기·허브를 통한 단말 은닉 | 인가 단말 뒤에 공유기를 연결하면 NAT(Network Address Translation)로 여러 단말이 숨겨져 MAC 기반 식별 우회 | 스위치 포트에 **포트 보안** (Port Security, 허용 MAC 수 제한)을 설정하고 802.1X 다중 인증(Multi-Auth) 모드 적용 | 포트당 MAC 위반 건수 |
| 에이전트 설치 불가 단말 관리 | IoT, 스마트 TV, 공조기는 에이전트를 설치할 수 없어 보안 상태 점검이 어려움 | 통신 패턴 기반 **NDR** (Network Detection and Response)로 기기 유형을 자동 분류하고 전용 IoT VLAN으로 격리 | 미분류 기기 수, IoT 격리율 |

## Ⅵ. NAC의 기술사적 제언

- 핵심 요약 : 인증서 기반 단말 식별, 엔드포인트 보안과의 자동 연동, 원격 환경으로의 확장을 통해 접속 통제를 상시화하는 방향.

1. 기기마다 고유한 사설 PKI(Public Key Infrastructure) 인증서를 발급하고, 802.1X 위에서 **EAP-TLS** (EAP-Transport Layer Security) 인증으로 상호 인증하도록 구성하면, MAC 주소 복제 공격의 실효성을 구조적으로 낮출 수 있다.
2. 악성 행위를 탐지하는 **EDR** (Endpoint Detection and Response) 솔루션과 API로 연동하여, 위험 행위가 감지된 단말을 NAC가 스위치 포트 단위로 즉시 격리하는 절차를 표준 운영 절차로 삼는 것이 바람직하다.
3. 사내망 경계에 머무는 NAC를 넘어 재택·원격 근무까지 포괄하도록 **SASE** (Secure Access Service Edge) 체계로 확장하여, 클라우드 환경에서도 같은 단말 검역 기준을 적용할 필요가 있다.

## Ⅶ. 결론

- 핵심 요약 : NAC는 네트워크 최초 진입 지점에서 단말의 신원과 보안 상태를 확인하는 관문 통제 체계.
- 시사점 : 접속 전 검증이라는 NAC의 본질은 신원 기반 접근 통제와 결합될 때 내부 확산을 막는 기본 통제로 유효함.
