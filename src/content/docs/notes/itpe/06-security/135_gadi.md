## 연관 키워드

- GADI(Global Architecture for Digital Identity), DID Alliance, 디지털 신원, 상호운용성
- 탈중앙 식별자(DID, Decentralized Identifier), 검증 가능한 자격증명(VC, Verifiable Credential)
- 자기주권신원(SSI, Self-Sovereign Identity), 신뢰 연결, 디지털 주소(Digital Address)

## Ⅰ. GADI의 개요

- 핵심 요약 : 서로 다른 디지털 신원 체계를 신뢰 있게 연결하기 위해 DID Alliance가 제시한 아키텍처 구상.
- 개념 : **GADI** (Global Architecture for Digital Identity)는 DID Alliance가 디지털 신원 체계 간 상호운용성과 신뢰 연결을 위해 제안한 아키텍처 구상.
- 배경 및 필요성 : 국가, 기관, 서비스마다 신원 체계가 분절되어 중복 인증과 이용자 통제권 부재가 문제로 제기되었으며, DID Alliance는 2019년 10월 출범 발표에서 이 문제의 해결을 목표로 제시함.
- 주요 목적 : 신원 체계 간 신뢰 관계를 관리하고, 이용자가 자신의 신원 정보를 더 잘 통제하며 디지털 신원 이용의 포용성을 높이는 것.
- 지위 : 발표 자료에 따라 Global Architecture 또는 Global Association으로 표기되기도 함. 산업 연합의 구상이며 W3C나 ITU 등의 표준과 구분해야 하고, 법적 통용이나 구현 완료를 의미하지 않음. 최근 공개 자료에서 구현 현황은 확인되지 않음.

## Ⅱ. GADI의 특징 및 장점

- 핵심 요약 : 발급기관의 신원 확인과 표준 자격증명을 결합해 신원 연결의 신뢰 근거를 세우려는 구상.

1. 확인된 신원 발급 : 발표 자료 기준으로 인증된 발급기관이 실명 확인 절차를 거쳐 식별자를 발급 → 식별자 보유와 실제 주체의 신뢰도를 구분하는 근거 마련.
2. 표준 기술 조합 : DID와 VC 같은 W3C 표준을 활용하는 구성 → 개별 신원 체계 사이의 기술적 교환 방식을 맞출 수 있음.
3. 이용자 통제 지향 : 자기주권 원칙을 지향하여 이용자가 정보 공개 범위를 정하는 구조 → 개인정보 보호와 편의성의 균형 시도.

## Ⅲ. GADI의 구성 관점 (흐름)

- 핵심 요약 : 발급, 자격증명 제시, 검증으로 이어지는 신뢰 흐름에서 각 단계의 신뢰 근거를 구분해 확인해야 하는 구조.
- **DID** (Decentralized Identifier) : 식별자와 검증 방법을 연결하는 W3C 표준이며, 블록체인을 요구하지 않음.
- **VC** (Verifiable Credential) : 발급자, 보유자, 검증자 사이에서 자격 정보를 표현하는 모델.

```text
[ 신원 연결 흐름 ]

발급기관 : 신원 확인 후 식별자 발급
   ↓
보유자 : 자격증명(VC) 보관
   ↓ 선택 공개 (VP)
검증자 : 서명과 발급기관 신뢰 확인
```

```text
[ 신뢰 확인 3단계 ]

서명 검증 : 자격증명이 변조되지 않았는가
   ↓
발급기관 신뢰 : 발급자가 신뢰 체계에 속하는가
   ↓
상태 확인 : 자격증명이 폐기되지 않았는가
```

| 관점 | 확인할 사항 | 설계상 의미 |
| --- | --- | --- |
| 신원 확인 | 발급·등록 과정과 실제 주체 확인 수준 | 식별자 보유와 실제 인물의 신뢰도 구분 |
| 기술 연결 | 식별자, 자격증명, 인증 프로토콜 | 신원 체계 간 교환과 검증 방식 결정 |
| 신뢰 연결 | 발급기관의 자격, 책임, 폐기 관리 | 서명 검증 성공과 발급기관 신뢰를 구분 |
| 이용자 보호 | 최소 정보 공개, 동의와 통제, 복구 | 편의성과 프라이버시의 절충 |

## Ⅳ. GADI와 관련 개념의 비교

- 핵심 요약 : GADI는 아키텍처 구상이고 SSI, DID·VC, ToIP, OIDC·SAML은 각각 원칙, 표준, 프레임워크, 프로토콜이라는 점에서 층위가 다름.

| 구분 | 주된 역할 | GADI와의 관계 |
| --- | --- | --- |
| 자기주권신원 (SSI, Self-Sovereign Identity) | 이용자 중심 신원 통제 원칙 | 설계 방향은 관련되나 동일한 규격은 아님 |
| DID·VC | 식별자와 자격증명 모델 | 신원 연결에 활용 가능한 개별 표준 |
| Trust over IP (ToIP) | 기술과 거버넌스를 포함한 신뢰 프레임워크 | 별도 프레임워크로 적용 범위를 확인해야 함 |
| OIDC·SAML | 인증과 연합 신원 프로토콜 | 기존 체계와 연계 시 신뢰 정책 검토 필요 |

- 분산 정도와 개인정보 보호 수준은 별개의 문제이므로, 아키텍처가 분산형이라는 이유만으로 보호 수준이 높다고 볼 수 없음.

## Ⅴ. GADI의 한계와 방안

- 핵심 요약 : 법적 인정, 키 분실, 상관분석 위험을 신뢰 프레임워크 확인, 복구 정책, 데이터 최소화로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 기술적으로 검증되나 법적으로 인정되지 않는 신원 | 국가·기관별 신뢰 프레임워크와 증거 요건이 달라 효력이 제한 | 대상 국가와 기관의 신뢰 프레임워크와 책임 요건을 사전 확인 | 법적 인정 범위 확인 건수 |
| 키·기기 분실과 복구 위험 | 키를 잃으면 신원 증명이 불가능해짐 | 신원 재확인, 키 교체·폐기, 백업 정책을 함께 설계 | 복구 처리 소요 시간 |
| 개인정보 상관분석과 기록 위험 | 식별자나 해시가 연결되면 이용 기록이 추적될 수 있음 | 데이터 최소화와 공개 범위 통제, 식별자 연결 가능성 평가 | 과다 공개 사례 수 |

## Ⅵ. GADI 아키텍처 적용에 대한 기술사적 제언

- 핵심 요약 : 아키텍처의 이름이나 블록체인 여부보다 신원 확인 수준과 발급기관 신뢰, 이용자 보호를 기준으로 평가하는 것이 바람직함.
- 신원 연계 서비스를 설계할 때는 블록체인 채택 여부보다 실제 신원 확인 수준과 발급기관의 신뢰 근거를 먼저 평가하는 것이 합리적이다.
- 연결할 서비스 사이에서 자격증명 형식, 상태 확인, 키 교체, 오류 처리의 호환성을 시험하고, 법적 인정 범위를 함께 확인하는 절차를 도입해야 한다.

## Ⅶ. 결론

- 핵심 요약 : GADI는 디지털 신원 체계 간 신뢰 연결을 목표로 한 구상이며, 표준이나 구현 완료 상태로 단정할 수 없음.
- 시사점 : 신원 상호운용의 실효성은 기술 규격보다 발급기관 신뢰와 법적 인정 범위에 달려 있어, 도입 전 이 두 가지를 먼저 확인해야 함.
