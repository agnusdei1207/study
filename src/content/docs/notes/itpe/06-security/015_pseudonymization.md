## 지식 로드맵 내 현재 위치

개인정보 보호 → 안전한 데이터 활용 → 가명정보 처리 및 결합전문기관 절차

## 30초 인출

- **본질:** 개인정보의 일부를 삭제하거나 대체함으로써 추가 정보 없이는 특정 개인을 알아볼 수 없도록 처리하는 개인정보 보호 기법
- **메커니즘:** 사전준비 → 위험도 검토 → 가명처리 → 적정성 검토 → 안전관리 5단계 및 추가정보의 분리 보관·접근 통제
- 통찰: 추가정보 유출로 인한 원본 재식별 위험과 비정형 데이터 내 준식별자 누락을 방지하기 위해 HSM 암호키 분리 격리와 딥러닝 기반 NER 가명화 파이프라인 결합 필수

<details>
<summary>핵심 용어</summary>

- **가명정보:** 개인정보보호법 제2조에 따라 추가 정보의 사용·결합 없이는 특정 개인을 알아볼 수 없는 정보로, 법적으로 개인정보에 해당
- **익명정보:** 시간·비용·기술을 합리적으로 고려할 때 더 이상 개인을 알아볼 수 없는 정보로, 개인정보보호법 적용 제외
- **추가정보 (Additional Information):** 가명정보를 원래의 개인정보로 복원하거나 특정 개인을 알아보기 위해 사용되는 매핑 테이블, 알고리즘, 암호화 키
- **결합전문기관:** 서로 다른 개인정보처리자 간의 가명정보 결합을 안전하게 지원하기 위해 개인정보보호위원회가 지정한 공인 전문기관
</details>

> 개인정보보호법 상의 가명정보의 법적 정의와 처리 목적을 설명하고, 가명처리 5단계 표준 절차 및 결합전문기관을 통한 데이터 결합 메커니즘과 안전성 확보 조치 방안을 기술하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **가명처리(Pseudonymization)** 는 개인정보의 일부를 삭제하거나 대체하여 추가 정보 없이는 특정 개인을 식별할 수 없도록 처리하는 기술적·관리적 조치 |
| 목적 | 데이터 3법 개정에 따른 통계작성, 과학적 연구, 공익적 기록보존 등의 목적으로 정보주체의 동의 없이도 안전한 데이터 활용 보장 |

완전한 익명화와 달리 추가정보와 결합하면 재식별될 수 있으므로 여전히 '개인정보'로 분류되어 엄격한 기술적 보호조치가 의무화됨.

## Ⅱ. 가명정보의 특징 및 법적 지위

| 법적 항목 | 개인정보보호법 규정 내용 | 엔지니어링 및 보안 함의 |
|---|---|---|
| **처리 특례 (제28조의2)** | 통계작성, 과학적 연구, 공익적 기록보존 목적인 경우 동의 없이 가명정보 처리 허용 | 산업적 AI 학습, 상업적 통계 분석에 광범위하게 활용 가능 |
| **재식별 금지 (제28조의5)** | 특정 개인을 알아보기 위한 목적으로 가명정보를 처리하는 행위 절대 금지 | 위반 시 전체 매출액의 3% 이하 과징금 및 형사처벌 부과 |
| **안전조치 의무 (제28조의4)** | 추가정보의 분리 보관, 접근 권한 분리, 접속기록 1년 이상 보관 | 가명정보 DB와 매핑 테이블 DB의 물리적·논리적 분리 필수 |
| **결합 제한 (제28조의3)** | 서로 다른 기업 간 가명정보 결합은 정부 지정 결합전문기관을 통해서만 수행 | 기업 간 사적 임의 결합을 원천 차단하여 식별 위험 방지 |

## Ⅲ. 가명정보 처리 5단계 절차 및 결합 메커니즘

```text
[가명정보 처리 및 결합전문기관 5단계 표준 라이프사이클]

 1. 사전준비       2. 위험도 검토       3. 가명처리        4. 적정성 검토       5. 안전한 활용
+------------+   +--------------+   +-------------+   +--------------+   +--------------+
| 목적 정의  |-->| 식별 위험도  |-->| 식별자 삭제 |-->| 적정성 평가  |-->| 분리 보관    |
| 대상 추출  |   | 처리환경 평가|   | 준식별자범주|   | 추가처리 여부|   | 반출 심사    |
+------------+   +--------------+   +-------------+   +--------------+   +--------------+
                                                           |
                                                           v (기관 간 결합 시)
                         +--------------------------------------------------+
                         | [결합전문기관]                                   |
                         |  - 결합키 연계정보(Salt 결합) 생성 및 매칭       |
                         |  - 결합 데이터 생성 후 결합키 즉시 영구 파기     |
                         |  - 반출승인심사위원회 심의 후 최종 반출          |
                         +--------------------------------------------------+
```

### 1. 5단계 세부 절차별 핵심 엔지니어링 태스크

| 단계 | 수행 작업 내용 | 필수 통제 사항 |
|---|---|---|
| **1. 사전준비** | 가명처리 목적 정의, 데이터셋 항목 식별, 법적 근거 검토 | 활용 목적(통계/연구/기록)의 명확성 확보 |
| **2. 위험도 검토** | 식별자·준식별자 분류, 데이터셋 환경(내부/외부 제공) 위험도 평가 | 외부 공개 데이터와의 결합 가능성 시뮬레이션 |
| **3. 가명처리** | 직접식별자 삭제/암호화, 준식별자 범주화(k-익명성), 마스킹 | 추가정보(Salt, 매핑키)의 별도 암호화 보관 |
| **4. 적정성 검토** | 전문가로 구성된 '적정성 검토위원회' 심의 및 재식별 위험 측정 | 미흡 시 3단계 피드백 재처리, 적정 판정 시 승인 |
| **5. 안전한 활용** | 가명정보 이용 및 파기, 기술적·관리적·물리적 보안 조치 | 추가정보 접근 권한 통제, 연 1회 점검 |

## Ⅳ. 개인정보 vs 가명정보 vs 익명정보 심층 비교

| 비교 항목 | 개인정보 (PII) | 가명정보 (Pseudonymized Data) | 익명정보 (Anonymized Data) |
|---|---|---|---|
| **개념 정의** | 특정 개인을 직접 알아볼 수 있는 정보 | 추가정보 없이는 개인을 알 수 없도록 처리한 정보 | 더 이상 개인을 알아볼 수 없도록 복원 불가능하게 처리한 정보 |
| **법적 성격** | 개인정보보호법 전면 적용 | **개인정보에 해당** (특례 조항 적용) | **개인정보보호법 적용 전면 제외** |
| **정보주체 동의** | 수집·이용·제공 시 원칙적 동의 필수 | 통계/연구/기록 목적 시 동의 면제 | 동의 불필요 (자유로운 활용·유통) |
| **재식별 가능성** | 식별 가능 | 추가정보 결합 시 재식별 가능 | 이론상 및 현실적으로 재식별 불가 |
| **안전조치 의무** | 개인정보 안전성 확보조치 기준 준수 | **추가정보 분리 보관, 물리적 분리 의무** | 법적 안전조치 의무 없음 |
| **정보주체 권리** | 열람, 정정, 삭제, 처리정지권 보장 | 열람, 정정, 삭제권 등 행사 제한 가능 | 권리 행사 대상 아님 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **추가정보(매핑 테이블) 보관 부실 및 결합 재식별 위험**<br>가명처리 시 사용된 해시 솔트(Salt)나 원본 매핑 키가 가명정보와 동일한 시스템 내에 존재할 경우, 서버 침해 시 일괄 역난독화되어 원본 유출 | **추가정보의 물리적 망분리 및 HSM 기반 암호키 봉인**<br>가명정보와 추가정보 보관 서버를 물리적으로 분리하고, 가명화 연산에 사용된 대칭키를 FIPS 140-2 Level 3 이상의 HSM(하드웨어 보안 모듈)에 격리하며, 처리 직후 임시 매핑 테이블 즉시 영구 삭제 |
| **비정형 텍스트·음성 내 맥락적 준식별자 누락에 의한 재식별**<br>고객 상담 로그, 진료 기록 등 비정형 데이터 내에 포함된 희귀 질환명, 특정 지명, 직책 등이 정규식 마스킹을 우회하여 그대로 노출 | **사전학습 언어모델(NER) 기반 문맥 탐지 및 안전구역(Clean Room) 격리**<br>KoBERT/RoBERTa 기반의 개체명 인식(NER) 파이프라인을 구축하여 문맥 속 미세 식별자를 99% 이상 자동 가명화하고, 데이터 분석을 외부 반출 없는 데이터 클린룸(Clean Room) 내로 한정 |

## Ⅵ. 제언

```text
[데이터 경제 활성화를 위한 안전한 데이터 클린룸 아키텍처]

 +--------------------+     +---------------------+     +--------------------+
 | 기관 A 가명 데이터 | --> | 데이터 클린룸       | --> | 집계 결과물 반출   |
 | 기관 B 가명 데이터 | --> | (TEE / 가상 데스크톱|     | (차등정보보호 적용 |
 |                    |     |  인터넷/반출 차단)  |     |  원시 데이터 잔류) |
 +--------------------+     +---------------------+     +--------------------+
```

| 접근 방식 | 기존 파일 반출형 가명 결합 | 데이터 클린룸 기반 분석 (권장) |
|---|---|---|
| **데이터 이동** | 결합된 원시 가명 데이터를 분석 기관 서버로 전송 | 데이터는 보안 인프라 내에 머물고 분석 알고리즘만 진입 |
| **재식별 위험** | 분석 기관 내부자의 결합 공격 및 외부 유출 위험 잔존 | 원시 데이터 반출 원천 차단으로 재식별 위험 제로화 |
| **규제 안전성** | 이용 기간 만료 후 파기 여부 감사 난항 | 플랫폼 내에서 사용 후 즉시 파기 및 전수 감사 로그 유지 |

가명정보의 안전한 산업적 활용을 위해서는 원시 데이터 파일 반출 방식을 지양하고, 클라우드 TEE 기반 데이터 클린룸 환경에서 분석 후 집계 결과만 반출하는 패러다임 전환 권장.
