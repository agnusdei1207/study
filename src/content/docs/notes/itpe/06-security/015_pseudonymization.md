## 연관 키워드

- 가명처리(Pseudonymization), 가명정보, 익명처리(Anonymization), 결합키(Join Key), 결합전문기관
- 동적 솔트(Salt), 사전 대입 공격(Dictionary Attack), 준식별자(Quasi-identifier), 재식별(Re-identification)
- 상하단 코딩(Top/Bottom Coding), k-익명성(k-Anonymity), 안심구역(Safe Room), 합성 데이터(Synthetic Data), HSM(Hardware Security Module)

## Ⅰ. 가명처리의 개요

- 핵심 요약 : 추가 정보 없이는 특정 개인을 알아볼 수 없도록 식별자를 대체하는 처리로, 법적으로는 여전히 개인정보 보호법의 규율을 받는 **가명정보** 처리 방식.
- 개념 : 개인정보의 식별자를 삭제하거나 일방향 값으로 대체해, 결합키나 매핑 테이블 같은 **추가 정보** 없이는 개인을 특정할 수 없도록 만드는 처리를 **가명처리** (Pseudonymization)라 함.
- 배경 및 필요성 : 데이터 3법 개정으로 통계 작성, 과학적 연구, 공익적 기록 보존 목적에 한해 정보주체의 동의 없이 가명정보를 결합·활용할 수 있는 근거가 마련되면서 핵심 처리 기법으로 자리 잡음.
- 주요 목적 : 원본 데이터의 식별 위험을 낮춰 정보주체의 프라이버시를 보호하고, 연구와 산업 분석에 필요한 데이터의 **유용성** (Utility)을 유지.

## Ⅱ. 가명처리의 특징 및 장점

- 핵심 요약 : 식별자 대체, 결합키 기반 연계, 추가 정보 분리가 원본 노출 없이 데이터를 연결하고 분석할 수 있게 하는 구조.

1. 식별자 대체 : 주민등록번호 같은 식별자를 일방향 해시나 토큰으로 바꿈 → 원본 식별값을 노출하지 않고 레코드를 연결할 수 있음.
2. 결합키 기반 연계 : 결합전문기관이 배포한 솔트를 더해 기관별 결합키를 만들고 일치 레코드를 매핑 → 원본을 교환하지 않고 기관 간 결합 분석이 가능.
3. 추가 정보 분리 : 매핑표와 솔트를 가명정보와 별도 서버에 보관 → 가명정보만 유출되어도 재식별 난도가 높아짐.

## Ⅲ. 가명처리의 구조 (흐름)

- 핵심 요약 : 식별자 추출에서 가명화, 결합, 반출 심사까지 단계별로 분리되어 있어, 각 단계의 통제가 재식별을 막는 구조.
- **결합전문기관** : 서로 다른 기관의 가명정보를 결합하고 반출 심사를 맡는 지정 기관으로, 원본 식별자와 분리되어 운영됨.
- **결합키** (Join Key) : 기관별 식별자에 솔트를 더해 만든 값으로, 결합전문기관에서 레코드를 연계하는 기준이 됨.

```text
[ 가명처리 및 결합 절차 ]

식별자 추출 (주민번호 등)
      ↓
가명화 연산 (솔트 해시, 토큰화)
      ↓
결합키 생성 후 기관별 분리 보관
      ↓
결합전문기관에서 결합 (일치 레코드 연계)
      ↓
추가 비식별 조치와 반출 심사
      ↓
폐쇄 분석실에서 분석
```

```text
[ 개인정보 처리 구분 ]

원본 개인정보 (식별 가능)
      ↓ 추가 정보 분리 보관
가명정보 (개인정보 보호법 적용)
      ↓ 추가 정보 파기, 재식별 불가
익명정보 (개인정보 보호법 적용 제외)
```

## Ⅳ. 가명처리의 비교

- 핵심 요약 : 가명처리는 추가 정보가 있으면 원본으로 복원되는 가역적 처리이고, 익명처리는 복원이 불가능하며 법 적용에서 벗어나는 처리라는 점에서 구별됨.

| 비교 항목 | 가명처리 (Pseudonymization) | 익명처리 (Anonymization) | 암호화 (Encryption) |
| --- | --- | --- | --- |
| 정의 | 추가 정보 없이는 개인 식별 불가 | 어떤 수단으로도 개인 식별이 어려움 | 키를 써서 평문을 암호문으로 변환 |
| 법적 성격 | 개인정보로서 안전조치 의무 적용 | 개인정보 보호법의 적용에서 벗어나는 것이 원칙 | 기술적 보호조치의 일환 |
| 가역성 | 추가 정보가 있으면 복원 가능 | 복원 불가 | 복호화 키가 있으면 복원 가능 |
| 활용 목적 | 통계 작성, 연구, 데이터 결합 | 공개 데이터 활용 | 저장과 전송 구간 보호 |
| 안전 통제 | 추가 정보 분리 보관, 내부 감사 | 적정성 평가 후 활용 | 키 관리 체계 |

- 선택 기준 : 원본 식별 가능성을 남겨 연구 결합이 필요하면 가명처리, 식별 가능성을 없애 공개하려면 익명처리를 택함. 가명처리는 법적 면책이 아니라 동의 요건을 완화하는 절차적 특례로 이해해야 함.

## Ⅴ. 가명처리의 한계와 방안

- 핵심 요약 : 사전 대입 공격, 희귀 속성자의 재식별, 내부 연구자의 재결합 시도를 솔트, 범주화, 반출 통제로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **사전 대입 공격** (Dictionary Attack) | 주민등록번호처럼 입력 범위가 작은 값을 고정 해시하면 사전 계산으로 원본이 역산됨 | 기관별 **동적 솔트** (Salt) 적용, 키 유도 함수(PBKDF2, Password-Based Key Derivation Function 2)와 HMAC(Hash-based Message Authentication Code) 결합 | 솔트 관리 점검률 |
| 특이값(Outlier)에 의한 재식별 | 고소득자나 초고령자처럼 희귀 속성을 가진 사람은 외부 정보와 결합해 식별될 수 있음 | **상하단 코딩** (Top/Bottom Coding)으로 범주화, **k-익명성** (k-Anonymity) 기준을 정해 준식별자 조합 점검. 준식별자(Quasi-identifier)는 단독으로는 식별력이 낮지만 조합하면 개인을 좁히는 속성 | 특이값 레코드 비율 |
| 내부 연구자의 재식별 시도 | 분석 권한자가 원본과 재결합하거나 특정 개인을 찾으려 함 | 분석실 외부 반출 차단, 화면 캡처 방지, 쿼리 감사 로그 모니터링, 위반 시 처벌 규정 고지 | 감사 로그 이상 탐지 건수 |

## Ⅵ. 가명처리에 대한 기술사적 제언

- 핵심 요약 : 원본 반출 없는 분석 환경, 키의 기계적 관리, 합성 데이터 활용을 조합해 재식별 위험 자체를 줄이는 방향.

연구와 분석 목적의 데이터 활용은 원본을 가져가는 방식에서 벗어나, 안심구역 안에서 분석하고 비식별 통계 결과만 반출하는 방식으로 옮겨 가는 것이 바람직하다.

결합키의 생성과 폐기를 수작업에 맡기지 않고 전용 **HSM** (Hardware Security Module, 암호키를 하드웨어 안에서 보관하고 연산하는 장치) 클러스터로 옮기면 키 노출 가능성을 구조적으로 줄일 수 있다.

재식별 위험이 높은 분석에는 원본 가명정보 대신 **합성 데이터** (Synthetic Data, 원본의 통계적 성질을 모사해 만든 가상 데이터)를 점진적으로 활용하는 방안을 검토할 만하다.

## Ⅶ. 결론

- 핵심 요약 : 가명처리는 추가 정보 분리를 전제로 식별 위험을 낮추면서 데이터 활용을 허용하는 개인정보 보호 기법.
- 시사점 : 가명처리의 효과는 알고리즘보다 추가 정보와 결합키를 얼마나 엄격히 분리하고 통제하는지에 달려 있음.
