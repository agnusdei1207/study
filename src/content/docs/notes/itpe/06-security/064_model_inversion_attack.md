## 한 줄 본질
- 딥러닝 모델이 출력하는 정밀한 클래스별 확률값(Softmax)이 내부 가중치의 단서가 되는 정보 노출 병목 → 출력 확률값을 최대화하는 방향으로 입력 공간을 경사 하강 역산하여 학습 원본을 시각적으로 복원 → 기밀 학습 데이터 유출 / 방어를 위한 차분 프라이버시 적용 시 모델 정확도 저하 발생

## 핵심 용어
- 모델 전도 공격(Model Inversion Attack): 모델의 예측 결과(출력 신뢰도)만을 관찰하여 역방향 최적화를 통해 모델 내부 학습에 사용된 특정 클래스의 특징 및 원본 데이터를 재구성하는 공격
- 차분 프라이버시(DP, Differential Privacy): 데이터셋에 특정 개인의 데이터가 포함되든 제외되든 분석 결과의 확률 분포 차이를 수학적 경계(Epsilon) 내로 제한하여 역추론을 차단하는 기술

## 핵심 통찰
- "학습 데이터는 서버에만 있고 외부에는 모델 가중치나 API만 공개했으니 안전하다"는 생각은 착각임 → 고차원 딥러닝 모델은 학습 데이터를 가중치 내부에 '기억(Memorization)'하고 있음
- 모델이 과적합(Overfitting)될수록 학습 데이터 샘플의 고유 특징을 강하게 외우게 되므로 모델 전도 공격에 대한 취약성이 기하급수적으로 커짐
- 가장 실용적인 방어는 '출력 정보의 최소화'임 → API가 `[0.98234, 0.0123, ...]` 같은 정밀한 부동소수점 확률 벡터를 반환하지 않고, 단순히 1위 레이블(Top-1 Label) 이름만 반환하면 경사 정보를 얻을 수 없어 공격이 무력화됨

## 이웃 토픽과 구분
- 멤버십 추론(Membership Inference) vs 모델 전도(Model Inversion): 멤버십 추론 = "이 환자 데이터가 암 진단 모델 학습에 쓰였는가?"(Yes/No) / 모델 전도 = "모델아, 네가 학습한 1번 환자의 얼굴이나 심전도를 직접 그려내봐"(데이터 복원)

## 문제·원인·대책
- 사례: 안면인식 출입통제 API를 외부 서비스에 연동했다가 공격자가 API 질의를 역산하여 사내 임직원들의 얼굴 사진을 복원해 낸 사례
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 정밀 확률값 노출로 인한 입력 데이터 역추론 | API가 모든 클래스의 소프트맥스 확률값을 완전 노출 | 상위 1개 레이블만 반환(Top-1 Hard Label) 또는 확률값 라운딩(양자화) | 경사 정보 손실로 역전파 최적화 차단 |
| 모델이 소수 환자의 희귀 질환 데이터를 과도하게 암기 | 과적합(Overfitting) 및 정규화 부재 | 학습 시 DP-SGD(차분 프라이버시 경사하강법) 적용 및 드롭아웃 강화 | 개별 학습 데이터의 가중치 기여도 은폐로 복원 불가 |

## 내 의견
- [API 편의성을 위한 과도한 디버그 정보 반환 관행] 개발자 편의를 위해 머신러닝 서빙 API에 각 클래스별 신뢰도 점수와 내부 레이어 텐서까지 그대로 응답 JSON에 담아 보내는 보안 불감증 상존 → 나라면: 프로덕션 API 게이트웨이에서 최종 판정 클래스명 외의 내부 확률 점수를 기본 마스킹(Strip)하고, 비정상적으로 짧은 시간에 대량의 유사 입력을 주입하는 역산 최적화 쿼리 패턴을 탐지하여 API 호출을 차단하는 속도 제한(Rate Limiting) 정책 적용
