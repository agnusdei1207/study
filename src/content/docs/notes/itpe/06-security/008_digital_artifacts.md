## 지식 로드맵 내 현재 위치

정보보호 운영 → 디지털 포렌식 → 디지털 흔적 분석 및 증거 보존

## 30초 인출

- **본질:** 시스템 및 응용 프로그램 실행, 사용자 행위 과정에서 저장매체와 메모리에 남겨지는 디지털 증거 데이터
- **메커니즘:** 실행 흔적(Prefetch, Shimcache)과 파일 활동($MFT, USN Journal), 레지스트리 교차 검증을 통한 시간순 행위 복원
- 통찰: 단일 타임스탬프 조작 위험을 극복하기 위해 MFT의 표준정보와 파일이름 속성을 비교하고 파일시스템 저널 및 메모리 잔재를 결합한 다계층 교차분석 체계 확립 필수

<details>
<summary>핵심 용어</summary>

- **Prefetch (.pf):** 응용 프로그램 실행 가속을 위해 생성되며 마지막 실행 시각, 실행 횟수, 참조 라이브러리 정보를 저장하는 파일
- **Shimcache (AppCompatCache):** 응용 프로그램 호환성 검사를 위해 레지스트리에 기록되며 실행 여부와 경로를 추적하는 아티팩트
- **Amcache.hve:** 프로그램 실행 경로, SHA-1 해시, 컴파일 시각, 설치 정보를 기록하는 윈도우 레지스트리 하이브 파일
- **타임스톰핑(Timestomping):** 파일의 수정·접근·생성(MACB) 타임스탬프를 인위적으로 위변조하여 분석을 방해하는 안티포렌식 기법
</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **디지털 아티팩트(Digital Artifact)** 는 운영체제, 파일시스템, 응용 프로그램 동작 및 사용자 활동 과정에서 생성되어 비휘발성·휘발성 영역에 남겨지는 디지털 흔적 데이터 |
| 목적 | 침해사고 조사 및 법적 소송에서 공격 경로 역추적, 행위자 식별, 시간대별 활동 타임라인 재구성 및 법적 증거능력 확보 |

공격자의 안티포렌식 시도에도 불구하고 운영체제 커널 및 서브시스템의 복합 캐시 영역에 다중 분산 저장되는 특성 보유.

## Ⅱ. 디지털 아티팩트의 특징

| 특징 | 설명 | 포렌식 가치 |
|---|---|---|
| **비고의적 생성** | 사용자나 프로세스의 명시적 의도 없이 OS 메커니즘에 의해 자동 생성 | 공격자가 인지하지 못한 침해 흔적 확보 |
| **다계층 연관성** | 메모리, 레지스트리, 파일시스템, 이벤트 로그에 동시 기록 | 단일 흔적 훼손 시 타 계층 교차 복원 가능 |
| **시간 의존성** | MACB(Modified, Accessed, Created, Born) 타임스탬프 기반 | 침해사고 전후의 완전한 타임라인 구성 |
| **휘발성 스펙트럼** | L1/L2 캐시부터 디스크 영구 저장소까지 소멸 속도 상이 | RFC 3227 증거 수집 순서 결정의 기준 |

## Ⅲ. 아티팩트 분석 체계 및 주요 유형

```text
[디지털 아티팩트 수집 및 교차 검증 체계]

 +-------------------+     +---------------------+     +--------------------+
 |   실행 흔적 분석   |     |   파일 활동 분석    |     |   사용자 행위 추적  |
 | Prefetch / Amcache|     | $MFT / $UsnJrnl /   |     | LNK, JumpList,     |
 | Shimcache / BAM   |     | Shellbags / WebLog  |     | UserAssist, SAM    |
 +---------+---------+     +----------+----------+     +---------+----------+
           |                          |                          |
           +--------------------------+--------------------------+
                                      |
                                      v
                 [타임라인 정규화 및 안티포렌식 교차 대조]
                  - $STANDARD_INFO vs $FILE_NAME 비교
                  - 볼륨 섀도우 복사본(VSS) 시계열 복원
```

### 1. 주요 운영체제별 아티팩트 상세

| 분류 | 아티팩트 명칭 | 저장 위치 / 형식 | 추출 증거 및 정보 가치 |
|---|---|---|---|
| **실행 흔적** | **Prefetch (.pf)** | `C:\Windows\Prefetch` | 실행 파일명, 최근 8회 실행 시각, 참조 DLL 목록 |
| | **Shimcache** | `SYSTEM` 하이브 `AppCompatCache` | 실행 파일 경로, 수정 시각, 실행 플래그 |
| | **Amcache.hve** | `C:\Windows\appcompat\Programs` | 파일 SHA-1 해시, 컴파일 타임, PE 헤더 정보 |
| **파일 활동** | **$MFT** | NTFS 파일시스템 메타데이터 | 파일 크기, 클러스터 할당, MACB 타임스탬프 |
| | **$UsnJrnl** | NTFS 변경 저널 ($Extend\$UsnJrnl) | 파일 생성·수정·이동·삭제에 대한 시간순 이벤트 |
| | **Shellbags** | `UsrClass.dat` 레지스트리 | 삭제된 폴더의 존재 여부, GUI 탐색 이력 |
| **사용자 활동** | **LNK / JumpList** | `Recent`, `AutomaticDestinations` | 원본 파일 경로, 대상 드라이브 시리얼, MACB |
| | **UserAssist** | `NTUSER.DAT` 레지스트리 (ROT13) | 실행 횟수, 마지막 실행 시각, GUI 클릭 이력 |

## Ⅳ. 주요 아티팩트 비교 및 상호 검증

| 비교 항목 | Prefetch | Shimcache | Amcache | $UsnJrnl |
|---|---|---|---|---|
| **기록 목적** | 응용 프로그램 실행 가속 | 호환성 데이터베이스 캐싱 | 드라이버·응용프로그램 추적 | 파일시스템 트랜잭션 저널링 |
| **수집 경로** | 파일시스템 파일 (`.pf`) | 레지스트리 (`SYSTEM`) | 전용 레지스트리 하이브 | 메타데이터 저널 스트림 |
| **실행 증명력** | 실제 실행 입증 (최대 8회) | 실행 가능성 증명 (경로 확인) | 설치 및 실행 바이너리 식별 | 트랜잭션 수준의 상태 전이 |
| **제공 정보** | 실행 시각, 파일 경로, 볼륨 | 경로, 수정 시간, 크기 | SHA-1 해시, 퍼블리셔 정보 | 파일 변경 유형, 타임스탬프 |
| **안티포렌식 취약성** | 파일 삭제 및 비활성화 가능 | 메모리 상주 후 셧다운 시 기록 | 하이브 청소 유틸리티 노출 | 롤오버(덮어쓰기) 발생 가능 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **타임스톰핑($STANDARD_INFO 조작) 공격**<br>공격자가 유틸리티를 활용해 `$STANDARD_INFORMATION` 속성의 MACB 타임스탬프를 정상 파일로 위조하여 타임라인 교란 | **$FILE_NAME 속성과의 교차 검증 및 저널 대조**<br>일반 유틸리티로 수정이 불가능한 커널 레벨 `$FILE_NAME` 속성의 타임스탬프를 대조하고, `$UsnJrnl` 및 `$LogFile` 트랜잭션을 역추적하여 조작 시점 검출 |
| **볼륨 섀도우 복사본(VSS) 및 이벤트 로그 강제 삭제**<br>`vssadmin delete shadows` 및 `wevtutil cl`을 통한 스냅샷 및 보안 로그 즉각 파괴로 추적 단절 | **비할당 영역 카빙 및 레지스트리 미할당 슬랙 분석**<br>디스크 비할당 영역(Unallocated Space)에서 VSS 카빙을 수행하고, 볼륨 복제본 잔재 및 레지스트리 셀 슬랙(Slack Space)에서 미삭제 키를 복원 |

## Ⅵ. 제언

```text
[엔터프라이즈 환경의 디지털 아티팩트 라이프사이클 관리 체계]

 +-------------------+     +---------------------+     +--------------------+
 | 실시간 EDR 수집   | --> | 불변 WORM 중앙 저장 | --> | 자동화 타임라인 분석|
 | 메모리/OS 아티팩트|     | 블록체인/WORM 로그  |     | Super Timeline 구성|
 +-------------------+     +---------------------+     +--------------------+
```

| 접근 방식 | 기존 사후 포렌식 | EDR 기반 연속적 아티팩트 수집 (권장) |
|---|---|---|
| **수집 시점** | 침해사고 인지 후 호스트 격리 및 이미징 | 이벤트 발생 즉시 실시간 스트리밍 수집 |
| **위변조 취약성** | 침해 대상 시스템 내 안티포렌식 툴에 취약 | 중앙 SIEM/데이터 레이크 분리 격리로 불변성 보장 |
| **분석 신속성** | 수 TB 디스크 이미지 파싱에 수일 소요 | 정규화된 아티팩트 기반 수 분 내 위협 헌팅 완결 |

단일 호스트 중심의 사후 아티팩트 추출에서 탈피하여, 엔터프라이즈 EDR과 연계된 연속적 아티팩트 텔레메트리 보존 및 Super Timeline 자동화 파이프라인 구축 권장.
