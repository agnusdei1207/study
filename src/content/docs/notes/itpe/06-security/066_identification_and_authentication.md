## 지식 로드맵 내 현재 위치

정보보안 → 접근 통제 → 식별·인증·인가(AAA) 및 다중요소인증(MFA)

## 30초 인출

- **본질:** 정보 시스템의 접근 통제를 위해 주체가 신원을 주장(식별)하고, 그 신원의 진위성을 지식·소유·생체 기반의 독립된 요소로 검증(인증)하여 권한을 부여하는 보안 통제 절차
- **메커니즘:** 신원 주장(ID) → 챌린지 생성 → 인증 요소 검증(지식: 암호, 소유: OTP/토큰, 생체: 지문) → 다중요소 결합(MFA) 판정 → 인가 및 감사 로깅
- 통찰: 단순 2단계 인증이라도 SMS/OTP는 실시간 피싱 프록시(AitM) 및 세션 하이재킹에 취약하므로, FIDO2/WebAuthn 기반의 암호학적 피싱 저항성 인증과 지속적 적응형 인가(CAEP) 결합 필수

<details><summary>핵심 용어</summary>

- **식별 (Identification):** 사용자가 시스템에 자신이 누구인지 고유 식별자(ID, 사번, 이메일)를 제시하여 신원을 주장하는 행위.
- **인증 (Authentication):** 신원을 주장하는 주체가 본인이 맞는지 증명 수단(Authenticator)을 통해 참임을 확인하는 행위.
- **인가 (Authorization):** 인증된 주체에게 특정 리소스나 작업에 대한 접근 권한을 정책(RBAC/ABAC)에 따라 허용하는 행위.
- **지식 기반 (Something you know):** 비밀번호, PIN, 보안 질문 등 주체의 기억에 의존하는 인증 요소.
- **소유 기반 (Something you have):** 스마트폰(OTP), 하드웨어 토큰, 스마트카드 등 주체가 물리적으로 보유한 인증 요소.
- **생체 기반 (Something you are):** 지문, 홍채, 안면, 음성 등 주체의 고유한 생체학적 특성에 기반한 인증 요소.
- **피싱 저항성 (Phishing Resistance):** 중간자 공격(AitM)이나 가짜 피싱 사이트에서도 인증 자격증명이 탈취되지 않도록 암호학적으로 보증하는 특성.

</details>

> 접근 통제의 기본 원칙인 식별(Identification), 인증(Authentication), 인가(Authorization), 책임추적성(Accounting)의 역할을 비교하고, 3대 인증 요소와 다중요소인증(MFA)의 구성 원칙 및 피싱 저항성 인증으로의 고도화 방안을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 정보 시스템 접근 통제의 출발점으로서 주체의 신원을 고유하게 주장(식별)하고, 상호 독립된 인증 요소를 통해 진위성을 증명(인증)하여 적절한 권한을 부여하는 체계 |
| 목적 | 비인가 접근 및 사칭 방지, 계정 탈취 사고 예방, 최소 권한 원칙 집행 및 모든 접근 행위에 대한 사후 책임추적성 확보 |

## Ⅱ. 식별·인증·인가·책임추적성(AAA)의 주요 특징

| 구분 | 역할 및 개념 | 핵심 질문 | 주요 구현 기술 |
|---|---|---|---|
| 식별 (Identification) | 주체가 자신의 신원(Identity)을 시스템에 주장 | "당신은 누구인가?" | 사용자 ID, 사번, 이메일, 공개키 ID |
| 인증 (Authentication) | 주체가 주장한 신원이 참(True)임을 증거로 입증 | "당신이 본인이 맞는가?" | 패스워드, OTP, 생체인증, FIDO2 |
| 인가 (Authorization) | 인증된 주체에게 허용된 권한 범위를 결정 | "당신은 무엇을 할 수 있는가?" | RBAC, ABAC, ACL, OAuth 2.0 스코프 |
| 책임추적성 (Accounting) | 시스템 내에서 수행한 모든 행위를 기록 및 감사 | "당신은 시스템에서 무엇을 했는가?" | SIEM 감사 로그, WORM 스토리지 |

## Ⅲ. 인증 3대 요소 및 다중요소인증(MFA) 아키텍처

```text
[ 1. 사용자 신원 주장 (식별: ID 입력) ]
                   │
                   ▼
┌────────────────────────────────────────────────────────┐
│ [인증 요소 계층 (Authentication Factors)]              │
│                                                        │
│  ├─ 요소 1: 지식 기반 (Something you KNOW)             │
│  │   - 비밀번호, PIN 번호, 패턴                        │
│  │                                                     │
│  ├─ 요소 2: 소유 기반 (Something you HAVE)             │
│  │   - 스마트폰(OTP), 하드웨어 보안키, 스마트카드      │
│  │                                                     │
│  └─ 요소 3: 생체 기반 (Something you ARE)              │
│      - 지문, 안면(Face ID), 홍채, 정맥 패턴            │
└────────────────────────┬───────────────────────────────┘
                         │ 서로 다른 2개 이상의 독립 요소 결합
                         ▼
┌────────────────────────────────────────────────────────┐
│ 다중요소인증 엔진 (MFA Engine)                         │
│  - 문맥 신호(Contextual Signals) 평가: IP, 위치, 단말 무결성│
│  - 피싱 저항성 프로토콜 검증 (WebAuthn / FIDO2)        │
└────────────────────────┬───────────────────────────────┘
                         ▼
┌────────────────────────────────────────────────────────┐
│ 인증 성공 ──▶ 인가(Authorization: RBAC) ──▶ 세션 토큰 발급│
└────────────────────────────────────────────────────────┘
```

| 인증 요소 | 특성 및 정의 | 장점 | 단점 및 취약점 |
|---|---|---|---|
| 1. 지식 (Knowledge) | 사용자의 기억에 저장된 비밀 정보 | 구현 용이, 추가 비용 없음 | 추측, 무차별 대입, 크리덴셜 스터핑 취약 |
| 2. 소유 (Possession) | 사용자가 물리적으로 소지한 장치/토큰 | 지식 요소 탈취 시 2차 방어 | 기기 분실/도난, SIM 스와핑, 복제 위험 |
| 3. 생체 (Inherence) | 사용자의 고유한 물리적/행동적 특성 | 분실 위험 없음, 사용자 편의성 | 위변조 시 변경 불가(비가역성 결여), FRR/FAR 오차 |

## Ⅳ. 인증 방식 및 메커니즘 비교

| 구분 | 단일 요소 인증 (SFA) | 전통적 2단계 인증 (SMS/OTP) | 피싱 저항성 다중요소인증 (FIDO2/패스키) |
|---|---|---|---|
| 적용 요소 | 지식 단독 (비밀번호) | 지식(비밀번호) + 소유(SMS/OTP) | 소유(하드웨어 칩) + 생체/지식(생체인증/PIN) |
| AitM 프록시 피싱 | 완전 무력화 (입력 즉시 유출) | 취약 (실시간 일회용 OTP 가로채기 가능) | **완전 방어 (Origin/RP ID 암호학적 바인딩)** |
| 푸시 피로 공격 | 해당 없음 | 취약 (MFA Fatigue 승인 유도) | 면역 (사용자 제스처 및 생체 확인 필수) |
| 계정 탈취율 | 99% 이상 공격에 노출 | 대량 자동화 공격 방어, 표적 피싱에 취약 | 표적형 피싱 및 자격증명 재사용 100% 방어 |
| 표준 가이드 | NIST AAL1 수준 (퇴출 권고) | NIST AAL2 수준 (제한적 허용) | NIST AAL3 최고 보안 보증 등급 |

## Ⅴ. 식별·인증 구현의 한계와 방안

| 한계 | 방안 |
|---|---|
| 동일한 지식 요소(비밀번호 + 2차 비밀번호)를 중복 적용하고 이를 MFA로 오인하여 크리덴셜 스터핑에 뚫리는 개념적 오류 | 반드시 서로 다른 독립된 범주(지식+소유, 소유+생체)의 요소를 결합하도록 강제하는 엔터프라이즈 IAM 정책 수립 |
| 모바일 푸시 알림 인증 시 공격자가 야간에 수백 번 승인을 요청하여 무의식적 승인을 유도하는 MFA 피로(MFA Fatigue) 공격 | 단순 '승인' 버튼을 폐지하고 화면에 표시된 2자리 난수를 단말에 직접 입력하도록 하는 번호 매칭(Number Matching) 적용 |
| 중간자 프록시 도구(Evilginx)를 악용한 세션 쿠키 탈취 및 SMS 가로채기 공격으로 전통적 2FA 무력화 | 중간자가 개입할 수 없는 공개키 기반 도메인 바인딩 기술인 FIDO2/WebAuthn 표준 기반 피싱 저항성 패스키 전면 의무화 |

## Ⅵ. 제언

```text
[ 레거시 인증 체계 ]                 [ 피싱 저항성 및 연속 적응형 인증 ]
단순 패스워드 단독 ──┐               ┌── FIDO2 패스키 (피싱 저항성 MFA)
정적 SMS/OTP 결합 ──┼─→ [ 계정 탈취 ] ─┼── 지속적 적응형 인가 (CAEP / ZTA)
로그인 시 1회 검증 ──┘               └── UEBA 기반 이상 세션 실시간 강제 종료
```

| 평가 영역 | 비밀번호 중심 SFA | SMS/OTP 기반 MFA | FIDO2 기반 피싱 저항성 MFA |
|---|---|---|---|
| 피싱 방어력 | 전무 (피싱 즉시 유출) | 제한적 (AitM 공격에 붕괴) | 완벽 (암호학적 원천 차단) |
| 사용자 경험 | 주기적 변경 스트레스 | 번호 복사 및 지연 발생 | 생체 원터치 즉시 로그인 |
| 제로 트러스트 적합도 | 부적합 | 부분 충족 | 완전 충족 (지속적 검증 연계) |

식별과 인증은 모든 보안 아키텍처의 관문이며, 단순 요소의 개수 추가를 넘어 중간자 공격을 원천 차단하는 FIDO2 피싱 저항성 인증과 세션 전주기 위험을 모니터링하는 제로 트러스트 연속 적응형 인가 체계로의 진화가 필수.
