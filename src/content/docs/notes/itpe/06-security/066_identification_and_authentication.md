## Ⅰ. 식별·인증·인증 요소의 개요

- 개념 : 정보 시스템 접근 통제의 출발점으로서 주체의 신원을 고유하게 주장(식별)하고, 상호 독립된 인증 요소를 통해 진위성을 증명(인증)하여 적절한 권한을 부여하는 체계.
- 배경 및 필요성 : 비인가자의 시스템 침입과 신원 위조를 방지하기 위해 사용자의 신원을 명확히 특정하고 정당한 권한 보유 여부를 **다중 요소** (MFA) 및 암호학적 기법으로 검증하는 근본적인 보안 관문으로 요구됨.
- 핵심 목적 : 비인가 접근 및 사칭 방지, 계정 탈취 사고 예방, 최소 권한 원칙 집행 및 모든 접근 행위에 대한 사후 책임추적성 확보.

## Ⅱ. 식별·인증·인증 요소의 핵심 아키텍처 및 동작 메커니즘

식별·인증·인증 요소은(는) 신뢰할 수 있는 보안 구조와 표준화된 절차를 기반으로 동작하며, 세부적인 아키텍처와 구성요소 간의 상호작용 메커니즘은 다음과 같음.

```text
[ 1. 사용자 신원 주장 (식별: ID 입력) ]
                   │
                   ▼
┌────────────────────────────────────────────────────────┐
│ [인증 요소 계층 (Authentication Factors)]              │
│                                                        │
│  ├─ 요소 1: 지식 기반 (Something you KNOW)             │
│  │   - 비밀번호, PIN 번호, 패턴                        │
│  │                                                     │
│  ├─ 요소 2: 소유 기반 (Something you HAVE)             │
│  │   - 스마트폰(OTP), 하드웨어 보안키, 스마트카드      │
│  │                                                     │
│  └─ 요소 3: 생체 기반 (Something you ARE)              │
│      - 지문, 안면(Face ID), 홍채, 정맥 패턴            │
└────────────────────────┬───────────────────────────────┘
                         │ 서로 다른 2개 이상의 독립 요소 결합
                         ▼
┌────────────────────────────────────────────────────────┐
│ 다중요소인증 엔진 (MFA Engine)                         │
│  - 문맥 신호(Contextual Signals) 평가: IP, 위치, 단말 무결성│
│  - 피싱 저항성 프로토콜 검증 (WebAuthn / FIDO2)        │
└────────────────────────┬───────────────────────────────┘
                         ▼
┌────────────────────────────────────────────────────────┐
│ 인증 성공 ──▶ 인가(Authorization: RBAC) ──▶ 세션 토큰 발급│
└────────────────────────────────────────────────────────┘
```

- **1. 지식 (Knowledge)** : 사용자의 기억에 저장된 비밀 정보 (구현 용이, 추가 비용 없음).
- **2. 소유 (Possession)** : 사용자가 물리적으로 소지한 장치/토큰 (지식 요소 탈취 시 2차 방어).
- **3. 생체 (Inherence)** : 사용자의 고유한 물리적/행동적 특성 (분실 위험 없음, 사용자 편의성).

## Ⅲ. 식별·인증·인증 요소의 세부 구성 요소 및 비교 분석

| 구분 | 단일 요소 인증 (SFA) | 전통적 2단계 인증 (SMS/OTP) | 피싱 저항성 다중요소인증 (FIDO2/패스키) |
|---|---|---|---|
| 적용 요소 | 지식 단독 (비밀번호) | 지식(비밀번호) + 소유(SMS/OTP) | 소유(하드웨어 칩) + 생체/지식(생체인증/PIN) |
| AitM 프록시 피싱 | 완전 무력화 (입력 즉시 유출) | 취약 (실시간 일회용 OTP 가로채기 가능) | 완전 방어 (Origin/RP ID 암호학적 바인딩) |
| 푸시 피로 공격 | 해당 없음 | 취약 (MFA Fatigue 승인 유도) | 면역 (사용자 제스처 및 생체 확인 필수) |
| 계정 탈취율 | 공격에 크게 노출 | 대량 자동화 공격 방어, 표적 피싱에 취약 | 표적형 피싱 및 자격증명 재사용에 강한 방어 |
| 표준 가이드 | NIST AAL1 수준 (퇴출 권고) | NIST AAL2 수준 (제한적 허용) | NIST AAL3 최고 보안 보증 등급 |

- 식별·인증·인증 요소은(는) 상기 핵심 비교 지표와 아키텍처 구성을 바탕으로 보안 위협에 대한 방어 효과성을 극대화하며, 기존 레거시 통제 기법 대비 우수한 신뢰성과 운영 효율성을 제공함.

## Ⅳ. 식별·인증·인증 요소의 주요 한계점 및 해결 방안

- 한계점 : 동일한 지식 요소(비밀번호 + 2차 비밀번호)를 중복 적용하고 이를 MFA로 오인하여 크리덴셜 스터핑에 뚫리는 개념적 오류.
  - 해결 방안 : 반드시 서로 다른 독립된 범주(지식+소유, 소유+생체)의 요소를 결합하도록 강제하는 엔터프라이즈 IAM 정책 수립.
- 한계점 : 모바일 푸시 알림 인증 시 공격자가 야간에 반복적으로 승인을 요청하여 무의식적 승인을 유도하는 **MFA 피로** (MFA Fatigue) 공격.
  - 해결 방안 : 단순 '승인' 버튼을 폐지하고 화면에 표시된 2자리 난수를 단말에 직접 입력하도록 하는 **번호 매칭** (Number Matching) 적용.
- 한계점 : 중간자 프록시 도구(Evilginx)를 악용한 세션 쿠키 탈취 및 SMS 가로채기 공격으로 전통적 2FA 무력화.
  - 해결 방안 : 중간자가 개입할 수 없는 공개키 기반 도메인 바인딩 기술인 **FIDO2/WebAuthn** 표준 기반 피싱 저항성 패스키 전면 의무화.

## Ⅴ. 식별·인증·인증 요소 적용 및 발전을 위한 기술사적 제언

- **FIDO2 패스키** (피싱 저항성 MFA) 체계 도입 : FIDO2 패스키 (피싱 저항성 MFA) 기술을 적극 적용하여 보안 취약점을 차단하고 시스템 신뢰성을 보장해야 함.
- **지속적 적응형 인가** (CAEP / ZTA) 체계 도입 : 지속적 적응형 인가 (CAEP / ZTA) 기술을 적극 적용하여 보안 취약점을 차단하고 시스템 신뢰성을 보장해야 함.
- **UEBA 기반 이상 세션 실시간 강제 종료** 체계 도입 : UEBA 기반 이상 세션 실시간 강제 종료 기술을 적극 적용하여 보안 취약점을 차단하고 시스템 신뢰성을 보장해야 함.
