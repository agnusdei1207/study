## 연관 키워드

- TPM(Trusted Platform Module), 신뢰점(Root of Trust), 측정 부트(Measured Boot), 보안 부트(Secure Boot)
- PCR(Platform Configuration Register), 확장(Extend), 밀봉 저장(Sealed Storage), 원격 검증(Remote Attestation)
- EK(Endorsement Key), SRK(Storage Root Key), TEE(Trusted Execution Environment), HSM(Hardware Security Module)
- vTPM(Virtual TPM), fTPM(Firmware TPM), 복구 키(Recovery Key), ZTNA(Zero Trust Network Access)

## Ⅰ. TPM(Trusted Platform Module)의 개요

- 핵심 요약 : 키 생성·보관과 무결성 측정을 변조 불가능한 하드웨어 칩 안에서 수행하는 플랫폼 보안 칩.
- 개념 : 암호화 키의 생성과 저장, 무결성 측정, 원격 검증을 하드웨어 수준에서 격리 수행하는 보안 암호 프로세서이며, 표준은 ISO(International Organization for Standardization)/IEC(International Electrotechnical Commission) 11889에 규정되어 있다.
- 배경 및 필요성 : 운영체제(OS, Operating System) 커널이나 백신 같은 소프트웨어 기반 통제는 **루트킷** (Rootkit)과 **부트킷** (Bootkit)처럼 OS 하위 계층을 장악하는 공격에 무력화되므로, 변조할 수 없는 하드웨어 신뢰점의 필요성이 커졌다.
- 주요 목적 : 부팅 단계부터 OS 로딩까지 무결성 체인을 측정하고, 개인키를 칩 내부에서만 생성·보관하여 키 탈취를 근본적으로 차단하는 것.

## Ⅱ. TPM(Trusted Platform Module)의 특징 및 장점

- 핵심 요약 : 하드웨어 신뢰점과 레지스터 확장 기록이 부팅 상태의 위변조를 드러내고, 그 결과를 키 봉인과 원격 증명으로 연결하는 구조.

1. **신뢰점** (Root of Trust) : 측정, 보고, 저장 기능을 맡는 변조 불가능한 닻 역할 → 이후 모든 검증의 출발점이 확보됨.
2. **확장** (Extend) : PCR(Platform Configuration Register)에 이전 값과 새 측정값의 해시를 결합하여 기록 → 기록된 값을 되돌리거나 덮어쓸 수 없어 위변조가 드러남.
3. **밀봉 저장** (Sealed Storage) : 데이터 암호키를 특정 PCR 상태에 묶음 → 악성코드로 부팅 상태가 바뀌면 복호화가 거부됨.
4. **원격 검증** (Remote Attestation) : PCR 값과 TPM 서명(Quote)을 검증자에게 전달 → 단말의 무결성 상태를 원격에서 증명함.

## Ⅲ. TPM(Trusted Platform Module)의 구조 (흐름)

- 핵심 요약 : 칩 내부의 PCR과 키 계층이 측정 부트 체인과 맞물려 부팅 전 과정을 기록하는 구조.
- **EK** (Endorsement Key) : 제조사가 칩에 심는 고유 인증 키로, 칩의 진위를 증명하는 기준이 됨.
- **SRK** (Storage Root Key) : 사용자 플랫폼의 저장 데이터를 보호하는 최상위 저장 키.
- **측정 부트** (Measured Boot) : 각 단계의 코드를 측정해 PCR에 기록하고, 그 기록을 나중에 검증할 수 있게 하는 방식.

```text
[ 측정 부트 체인 ]

CRTM (초기 신뢰점)
   ↓ 측정 → PCR 기록
UEFI 펌웨어
   ↓ 측정 → PCR 기록
부트 로더 (GRUB 등)
   ↓ 측정 → PCR 기록
OS 커널
```

```text
[ 키 계층과 칩 내부 구성 ]

Endorsement Primary Seed
   ↓
EK (제조사 소유 고유 인증 키)

Storage Primary Seed
   ↓
SRK (사용자 저장 데이터 보호 키)

PCR 0~23 : 해시 확장으로만 갱신
```

## Ⅳ. TPM(Trusted Platform Module)과 유사 보안 기술의 비교

- 핵심 요약 : TPM은 부팅 무결성과 키 봉인에 특화되고, TEE는 실행 중 보호, HSM은 고성능 암호 연산과 키 수탁에 특화된 구조.

| 비교 축 | TPM | TEE (Trusted Execution Environment, ARM TrustZone·Intel SGX) | HSM (Hardware Security Module) |
| --- | --- | --- | --- |
| 하드웨어 형태 | 메인보드에 실장된 독립 보안 칩 | 메인 CPU 내부의 격리 실행 영역 | 독립형 PCI 카드 또는 네트워크 장비 |
| 주요 목적 | 부팅 무결성 측정, 키 봉인 | 실행 중 애플리케이션과 메모리 보호 | 고속 암호 연산과 키 수탁 |
| 연산 성능 | 상대적으로 낮음 | CPU 속도에 준하는 연산 | 전용 가속 칩으로 매우 높음 |
| 주요 사용처 | BitLocker 디스크 암호화, Windows 11 요구 사양 | 지문 인증, DRM, 기밀 컴퓨팅 | 인증기관(CA), 금융 결제망, 대규모 PKI |
| 주요 취약 공격 | 칩과 CPU 사이 버스 스니핑 | CPU 캐시 부채널 공격 | 물리적 탈취와 부채널 분석 (보호 수준 최상) |

- 선택 기준 : 부팅과 디스크 키 보호는 TPM, 실행 중 메모리 보호는 TEE, 대량 키 관리는 HSM으로 역할을 나누는 것이 일반적이다.

## Ⅴ. TPM(Trusted Platform Module)의 한계와 방안

- 핵심 요약 : 버스 노출, 가상화 환경의 칩 공유 불가, 칩 고장 시 키 유실 문제를 파라미터 암호화, vTPM, 복구 키 에스크로로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 칩-CPU 버스 스니핑 | 키가 칩과 CPU 사이 버스를 지날 때 물리적 탭으로 평문 키 탈취 가능 | TPM 2.0 파라미터 암호화 적용, 세션 키로 채널 보호 | 파라미터 암호화 적용률 |
| 가상화 환경의 물리 TPM 공유 불가 | 멀티 테넌트 VM이 하나의 칩을 나눠 쓸 수 없어 게스트 무결성 검증이 제한됨 | 하이퍼바이저 기반 가상 TPM(vTPM, Virtual TPM) 도입, VM별 독립 인스턴스 제공 | VM별 vTPM 할당률 |
| 칩 고장 시 키 유실 | 보드 교체 시 칩에 묶인 키로 암호화된 볼륨을 복구할 수 없음 | 디렉터리 서비스 연계 복구 키 에스크로 백업 | 복구 키 보관 점검 주기 |

## Ⅵ. TPM(Trusted Platform Module)에 대한 기술사적 제언

- 핵심 요약 : 단말 무결성 증명을 접근 통제에 연결하고, 측정 부트와 보안 부트를 함께 쓰며, 펌웨어 공급망을 점검하는 방향으로 TPM을 활용해야 한다.
- 제로 트러스트 접근 통제에서는 제로 트러스트 네트워크 접근(ZTNA, Zero Trust Network Access)의 인가 단계에 TPM 원격 검증 결과를 연결하여, 무결성이 확인된 단말만 사내 자원에 접속하도록 설계하는 것이 자연스럽다.
- 보안 부트가 서명되지 않은 코드의 실행을 차단하고, 측정 부트가 전 과정을 PCR에 남기는 두 기능은 역할이 달라 함께 적용할 때 심층 방어가 완성된다.
- 펌웨어 TPM(fTPM, Firmware TPM)처럼 CPU 펌웨어로 구현된 신뢰 기능은 펌웨어 패치 주기와 제조사 공급망 검증이 보안성을 좌우하므로, 패치 관리 절차를 함께 점검해야 한다.

## Ⅶ. 결론

- 핵심 요약 : TPM은 하드웨어에 뿌리를 둔 엔드포인트 신뢰의 기반으로, 부팅 무결성과 키 보호를 담당하는 보안 표준 요소.
- 시사점 : 칩 자체의 보호만으로는 충분하지 않으므로, 원격 검증과 복구 체계를 함께 설계해야 기술의 효과가 유지된다.
