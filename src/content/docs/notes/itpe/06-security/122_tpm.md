## Ⅰ. TPM(Trusted Platform Module)의 개요

- 개념 : 컴퓨팅 플랫폼의 암호화 키 생성 및 저장, 무결성 측정, 보안 부팅, 원격 검증을 하드웨어 수준에서 안전하게 격리 수행하는 국제 표준 **ISO/IEC 11889** 기반의 **보안 암호 프로세서** 칩.
- 배경 및 필요성 : 소프트웨어 기반의 보안 통제(OS 커널, 백신)는 **루트킷** (Rootkit), **부트킷** (Bootkit) 등 OS 하위 계층을 장악하는 지능형 공격에 무력화되므로, 변조 불가능한 하드웨어 신뢰점(Root of Trust)의 필요성이 대두됨.
- 핵심 목적 : 디바이스의 부팅 단계부터 OS 로딩까지 전체 무결성 체인을 검증(Measured Boot)하고, 하드웨어 칩 내부에서만 개인키를 생성·보관하여 물리적/논리적 키 탈취를 근본 차단.

## Ⅱ. TPM(Trusted Platform Module)의 핵심 아키텍처 및 동작 메커니즘

TPM 2.0은 신뢰점(RoT), 플랫폼 구성 레지스터(PCR), 암호화 엔진, **비휘발성 저장소** (NVRAM)로 구성되며, **Endorsement Key** (EK)와 **Storage Root Key** (SRK) 기반의 계층적 키 아키텍처를 가짐.

```text
[ TPM 2.0 하드웨어 아키텍처 및 무결성 측정 체인 ]

 +----------------------------------------------------------------------+
 |                    TPM 2.0 하드웨어 칩 (격리 영역)                   |
 |                                                                      |
 |  +--------------------------------+  +----------------------------+  |
 |  | 암호 엔진 (Crypto Engine)      |  | PCR (Platform Config Reg)  |  |
 |  | - RSA, ECC, SHA-256, AES       |  | - PCR 0~23: 해시 체인 확장  |  |
 |  | - 진성 난수 생성기 (TRNG)      |  |   PCR_new = SHA(PCR || Data|  |
 |  +--------------------------------+  +----------------------------+  |
 |                                                                      |
 |  +----------------------------------------------------------------+  |
 |  | 계층적 키 관리 구조 (Key Hierarchy)                           |  |
 |  |  [Endorsement Primary Seed] -> EK (제조사 소유/고유 인증서)    |  |
 |  |  [Owner/Storage Primary Seed] -> SRK (사용자 플랫폼 스토리지 키)|  |
 |  |  [Platform Primary Seed]    -> 플랫폼 펌웨어 제어 키           |  |
 |  +----------------------------------------------------------------+  |
 +----------------------------------+-----------------------------------+
                                    | (LPC / SPI / I2C 버스)
                                    v
 [ 하드웨어 측정 부트 체인 (Chain of Trust) ]
   +--------+      +--------+      +--------+      +--------+
   | CRTM   | ---> | UEFI   | ---> | Boot   | ---> | OS     |
   | (초기  | 측정 | 펌웨어 | 측정 | 로더   | 측정 | 커널   |
   | 신뢰점)|      | 무결성 |      | (GRUB) |      | (부팅) |
   +--------+      +--------+      +--------+      +--------+
      |               |               |               |
      +---------------+---------------+---------------+
                              |
                     [ PCR 레지스터에 기록 ]
                     (Sealed Storage 조건 검증)
```

- **신뢰점(Root of Trust)** : 측정을 위한 신뢰점(RTM/CRTM), 보고를 위한 신뢰점(RTR), 저장을 위한 신뢰점(RTS)으로 구성되어 변조 불가능한 신뢰 닻(Anchor) 역할 수행.
- **PCR(Platform Configuration Register) 해시 확장** : 레지스터에 값을 직접 덮어쓰지 않고, 이전 값과 새 측정값의 해시를 결합하는 **Extend** 연산($PCR_{new} = H(PCR_{old} \parallel Measurement)$)을 수행하여 위변조 방지.
- **밀봉 저장(Sealed Storage)** : 데이터를 특정 암호키로 암호화할 때 특정 PCR 상태(정상 시스템 상태)에 바인딩하여, 부팅 과정에서 악성코드 감염 등으로 PCR 값이 변하면 복호화가 원천 거부됨.
- **원격 검증(Remote Attestation)** : 원격 검증자(Verifier)에게 장치의 PCR 값과 그에 대한 TPM 서명(Quote)을 전송하여 단말의 무결성 상태를 원격 증명.

## Ⅲ. TPM(Trusted Platform Module)의 세부 구성 요소 및 비교 분석

| 비교 항목 | **TPM** (Trusted Platform Module) | **TEE** (ARM TrustZone / Intel SGX) | **HSM** (Hardware Security Module) |
| --- | --- | --- | --- |
| 하드웨어 형태 | 메인보드 실장 독립 보안 마이크로칩 | 메인 CPU 내부의 보안 격리 실행 영역 | 독립형 고성능 PCI 카드 또는 네트워크 장비 |
| 주요 목적 | 플랫폼 부팅 무결성 측정, 키 봉인 | 실행 중인 애플리케이션 및 메모리 보호 | 초고속 엔터프라이즈 암호 연산 및 키 수탁 |
| 연산 성능 | 상대적으로 매우 낮음 (보안 특화) | 네이티브 CPU 속도로 연산 가능 | 극도로 높음 (하드웨어 가속 ASIC 탑재) |
| 주요 사용처 | BitLocker 디스크 암호화, Windows 11 | 스마트폰 지문인식, DRM, 기밀 컴퓨팅 | 인증기관(CA), 금융 결제망, 대규모 PKI |
| 취약 공격 | 물리적 버스(LPC/SPI) 스니핑 공격 | CPU 캐시 부채널 공격, 메모리 누수 | 물리적 도난 및 부채널 분석 (보호수준 극상) |

- TPM은 하드웨어 루트 오브 트러스트로서 엔드포인트 보안의 기반을 제공하며, Windows 11의 최소 요구 사양으로 지정되는 등 보안 표준으로 필수화됨.

## Ⅳ. TPM(Trusted Platform Module)의 주요 한계점 및 해결 방안

- TPM과 메인 CPU 간 통신 버스(LPC/SPI) 물리적 스니핑 취약점 :
  - 한계점 : BitLocker 복호화 키가 TPM에서 CPU로 전송될 때 마더보드 버스 라인을 오실로스코프나 로직 아날라이저로 태핑하여 평문 키 탈취 가능.
  - 해결 방안 : TPM 2.0 파라미터 암호화(Parameter Encryption) 적용 및 TPM 칩셋과 CPU 간 통신 채널에 세션 키 암호화 의무화.
- 클라우드 가상화 환경에서의 물리 TPM 매핑 난제 :
  - 한계점 : IaaS/PaaS 멀티 테넌트 VM 환경에서 단일 물리 TPM 칩을 공유할 수 없어 게스트 OS의 하드웨어 무결성 검증 한계.
  - 해결 방안 : 하이퍼바이저 기반 가상 TPM(vTPM) 아키텍처 도입 및 각 VM별 독립된 vTPM 인스턴스 격리 제공.
- 메인보드 고장 시 TPM 내부에 밀봉된 복호화 키 유실 위험 :
  - 한계점 : 하드웨어 칩 고장이나 보드 교체 시 SRK로 암호화된 디스크 볼륨 복구가 불가능하여 데이터 영구 손실 발생.
  - 해결 방안 : 엔터프라이즈 Active Directory / Azure AD와 연계된 비상 복구 키(Recovery Key) 에스크로 백업 체계 사전 구축.

## Ⅴ. TPM(Trusted Platform Module) 적용 및 발전을 위한 기술사적 제언

- 제로 트러스트 단말 상태 검증(Posture Check)과 원격 검증 연계 : ZTNA 솔루션 인가 단계에서 클라이언트의 TPM Attestation 서명값을 검증하여 무결성이 증명된 디바이스만 사내망 접속 허용.
- 측정 부트(Measured Boot)와 보안 부트(Secure Boot)의 상호 보완 적용 : 서명 검증으로 부팅을 차단하는 Secure Boot와 전체 부팅 과정을 PCR에 기록하는 Measured Boot를 결합하여 심층 방어 완성.
- 펌웨어 공급망 보안을 위한 fTPM 취약점 관리 : 하드웨어 칩 대신 CPU 펌웨어로 구현된 fTPM(Intel PTT, AMD fTPM)의 보안 패치를 정기 배포하고 제조사 공급망 검증 프로세스 강화.
