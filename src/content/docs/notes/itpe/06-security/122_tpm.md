## 지식 로드맵 내 현재 위치

지식 위치: 플랫폼 보안 → 하드웨어 신뢰 루트 → **TPM 2.0**

## 30초 인출

- **본질:** 암호 연산, 안전한 키 저장, 부팅 무결성 측정(PCR) 및 원격 증명(Attestation)을 하드웨어 수준에서 격리 제공하는 TCG 표준 보안 마이크로컨트롤러
- **메커니즘:** CRTM 부팅 시작 → 단계별 코드 해시를 PCR에 누적 확장(Extend) → 정상 무결성 상태 확인 시에만 디스크 암호키 언실링(Unsealing) 및 Quote 원격 서명
- **통찰:** SPI/LPC 버스 도청 공격은 파라미터 암호화 세션이나 fTPM/Pluton으로 방어하고, 수동 측정 한계는 Secure Boot와 결합한 능동 실행 차단으로 보완 필수

<details>
<summary>핵심 용어</summary>

- **TPM (Trusted Platform Module)** : 하드웨어 신뢰 루트(Root of Trust)를 구현한 보안 칩셋.
- **PCR (Platform Configuration Register)** : 측정값 해시를 순차적으로 누적 확장(Extend)하는 특수 하드웨어 레지스터.
- **실링 (Sealing)** : 시스템이 특정 PCR 측정 상태(변조 없는 정상 부팅)일 때만 비밀 키를 복원할 수 있도록 잠그는 기능.
- **Quote (원격 증명)** : AIK(증명키)로 현재 PCR 레지스터 값과 난수(Nonce)에 서명하여 원격 검증 서버에 전송하는 메커니즘.

</details>

## 2~4교시 예상문제 (25점)

> TPM 2.0의 신뢰 루트(Root of Trust) 개념, PCR 측정 확장 및 실링(Sealing) 메커니즘, 원격 증명(Remote Attestation) 절차를 설명하고, SPI 버스 스니핑 등 물리적 보안 한계와 엔지니어링 대응 방안을 제시하시오. (제132회 1교시 기출 연계·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | TCG(Trusted Computing Group) 표준 규격으로 암호화 키 생성·저장, 플랫폼 무결성 측정, 원격 증명 기능을 독립된 하드웨어 칩셋 내에서 안전하게 수행하는 보안 모듈 |
| 목적 | 운영체제(OS) 및 소프트웨어 계층의 침해와 무관하게 시스템 부팅 전 과정의 무결성을 검증하고, 디스크 완전 암호화(FDE) 키를 물리적으로 격리 보호 |

- 하드웨어 신뢰 루트 3대 요소인 측정 신뢰 루트(RTM), 저장 신뢰 루트(RTS), 보고 신뢰 루트(RTR)를 단일 칩 내에 구현

## Ⅱ. TPM 2.0의 핵심 아키텍처 특성

| 특성 항목 | 세부 내용 및 기술적 의미 | TPM 1.2 대비 개선점 |
|---|---|---|
| 다중 암호 알고리즘 지원 (Agility) | SHA-256, SHA-384, ECC(NIST P-256, P-384), RSA-2048 등 현대 암호화 지원 | 기존 SHA-1, RSA-2048 고정 한계 탈피 및 암호 민첩성 확보 |
| 4대 독립 키 계층 (Hierarchy) | Platform(펌웨어/OEM), Storage(사용자 데이터), Endorsement(칩 신원), Null(휘발성) | 도메인별 키 접근 권한의 완벽한 논리적 격리 |
| 향상된 인가 정책 (Policy Auth) | 단순 비밀번호/HMAC 인증을 넘어 복합 정책(PCR 상태, 시간, 다중 서명 결합) 평가 | 세밀하고 유연한 키 언실링(Unsealing) 조건식 구성 가능 |
| 다양한 구현 폼팩터 | 독립 칩(Discrete dTPM), 펌웨어(fTPM/ARM TrustZone), 통합(iTPM/SoC) 형태 지원 | PC, 서버, 모바일, IoT 기기 전반에 걸친 유연한 도입 지원 |

- 플랫폼 부팅 단계의 펌웨어 변조, 부트로더 감염(부트킷, 루트킷) 공격을 하드웨어 수준에서 근본적으로 탐지 및 차단하는 특성 보유

## Ⅲ. TPM 부팅 측정(PCR Extend) 및 실링·원격 증명 프로세스

```text
[TPM 2.0 부팅 무결성 측정 체계 및 원격 증명(Attestation) 흐름]

 [하드웨어 CRTM] ──> [UEFI 펌웨어] ──> [Bootloader] ──> [OS Kernel]
         │                 │                │               │
         ▼ (측정 해시값)   ▼ (측정 해시값)  ▼ (측정 해시값) ▼ (측정 해시값)
  ┌─────────────────────────────────────────────────────────────┐
  │                 TPM PCR Extend 연산 엔진                    │
  │    PCR_new = SHA-256( PCR_old || Measurement_Hash )         │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
                 ┌───────────────┴───────────────┐
                 ▼ (조건 비교)                   ▼ (증명 요청)
  ┌─────────────────────────────┐ ┌─────────────────────────────┐
  │        실링 (Sealing)       │ │     원격 증명 (Quote)       │
  │ - PCR 기대값 일치 확인      │ │ - AIK 서명 생성             │
  │ - BitLocker VMK 복호화 인계 │ │ - 원격 검증 서버로 전송     │
  └─────────────────────────────┘ └─────────────────────────────┘
```

| 단계 | 수행 프로세스 | 보안 통제 및 엔지니어링 메커니즘 |
|---|---|---|
| 1. CRTM 부팅 개시 | 메인보드 전원 인가 시 변경 불가능한 코어 신뢰 루트(CRTM)에서 첫 코드 실행 | 최초 불변 실행 코드 무결성 보장 |
| 2. PCR 확장 (Extend) | 다음 실행할 단계의 바이너리를 해시하여 TPM에 전송, $PCR_{new} = H(PCR_{old} \parallel Data)$ 누적 | 과거 측정 기록을 지우거나 덮어쓰기 불가능 (단방향 체인) |
| 3. 상태 기반 언실링 | OS 부트로더가 디스크 복호화 키 요청 시 현재 PCR[0~7] 값이 실링 정책과 일치하는지 검증 | 변조된 부트로더 감지 시 키 방출을 거부하여 디스크 보호 |
| 4. Quote 서명 생성 | 원격 증명 요청 시 TPM 내부 개인키(AK: Attestation Key)로 PCR 상태와 논스(Nonce) 서명 | 재전송 공격 방지 및 하드웨어 칩 기반 무결성 증적 생성 |
| 5. 원격 서버 검증 | 원격 제로 트러스트 검증 서버가 서명을 검증하고 레퍼런스 무결성 골든 이미지와 대조 | 네트워크 격리 해제 및 조건부 기업 인트라넷 접근 승인 |

## Ⅳ. Measured Boot(TPM) vs Secure Boot vs HSM 비교

| 비교 항목 | Measured Boot (TPM) | Secure Boot (UEFI) | 하드웨어 보안 모듈 (HSM) |
|---|---|---|---|
| 핵심 역할 | 부팅 구성요소의 상태 측정 및 기록 | 디지털 서명 검증을 통한 비인가 코드 실행 차단 | 고성능 암호 연산 및 서버 마스터 키 격리 |
| 실행 통제력 | 수동적(Passive): 변조 실행 자체는 허용하되 사후 감지 | 능동적(Active): 서명 검증 실패 시 부팅 즉시 중단 | 수동적: 암호화 요청에 대한 처리만 수행 |
| 키 보호 기능 | 실링(Sealing): PCR 상태에 종속된 키 방출 | 키 저장 기능 없음 (공개키/인증서 DB만 유지) | 최고 수준 물리적 탬퍼 저항성(FIPS 140-3 L3/4) |
| 하드웨어 위치 | PC/서버 메인보드 상의 마이크로칩 (LPC/SPI) | 메인보드 UEFI SPI 플래시 ROM | PCIe 카드, 네트워크 외장 어플라이언스 |
| 주요 적용처 | 엔드포인트 디스크 암호화(BitLocker), 단말 증명 | PC/서버 부팅 시 루트킷/부트킷 실행 방지 | 금융 결제망, CA 인증서 서명, KMS 마스터 키 |

## Ⅴ. TPM 적용 시 보안 한계와 엔지니어링 해결 방안

| 한계 | 방안 |
|---|---|
| 외장형 dTPM 칩과 CPU 간 통신 버스(LPC/SPI)를 로직 분석기로 물리 도청하여 디스크 암호키(VMK) 평문 탈취 | TPM 2.0의 세션 파라미터 암호화(TPM2_StartAuthSession with Salt)를 적용하여 버스 전송 패킷을 암호화하거나, SoC 내부 통합형 fTPM 및 Microsoft Pluton 프로세서 도입 |
| Measured Boot 단독 운용 시 악성 부트킷 실행 자체를 사전에 저지하지 못하고 사후 격리만 수행하는 수동성 한계 | UEFI Secure Boot와 연계하여 서명 검증 실패 시 즉시 부팅을 중단하고, Secure Boot 통과 후에만 TPM Measured Boot 체인에 진입하도록 계층적 결합 |
| 정기 펌웨어(BIOS) 및 커널 업데이트 시 정상 변경임에도 PCR 해시값이 달라져 디스크가 잠기고 복구키 요구 발생 | TPM2_PolicyAuthorize 기반의 인가 정책 서명 메커니즘을 도입하여, 관리자가 디지털 서명한 펌웨어 패치인 경우 PCR 정책을 동적으로 갱신 허용 |
| 단말 콜드 부팅(Cold Boot) 공격 및 DMA(Direct Memory Access)를 통한 런타임 메모리 키 탈취 취약점 | TPM 단독 의존을 탈피하여 사전 부팅 인증(PBA: Pre-Boot Authentication) PIN 번호를 필수화하고, IOMMU 기반 DMA 가드 활성화 |

## Ⅵ. 제로 트러스트 엔드포인트 무결성 검증 체계 구현 제언

```text
[TPM 기반 제로 트러스트 단말 상태 증명(Device Attestation) 아키텍처]

  +-----------------------+                         +-----------------------+
  |    클라이언트 단말     |                         |  Zero Trust Policy    |
  |  ┌─────────────────┐  |                         |  Decision Point (PDP) |
  |  │ TPM 2.0 Chip    │  |                         +-----------┬-----------+
  |  │ - PCR[0~15]     │  |  1. Attestation Quote               │
  |  │ - AK Private Key│  | ────────────────────────> 2. 서명 검증 및 Golden PCR 대조
  |  └─────────────────┘  |    (PCR 해시 + 서명 + Nonce)│
  |  ┌─────────────────┐  |                         3. 접근 인가 토큰 발급
  |  │ EDR 에이전트    │  | <──────────────────────── (mTLS 인증서 세션 허용)
  |  └─────────────────┘  |
  +-----------------------+
```

| 핵심 구축 축 | 구현 엔지니어링 세부 과제 | 관리 지표 |
|---|---|---|
| 하드웨어 무결성 | 기업 표준 단말 전수 TPM 2.0 활성화 및 Secure Boot 강제 | TPM 2.0 및 Secure Boot 적용률 100% |
| 동적 원격 증명 | MDM/ZTNA 게이트웨이 연계 부팅 시점 PCR Quote 자동 검증 | 무결성 위변조 단말 사내망 진입 차단율 100% |
| 비상 복구 체계 | Active Directory / Azure AD 연계 TPM 복구 키 중앙 백업 | 펌웨어 패치 시 장애 단말 복구 소요 시간 < 5분 |
