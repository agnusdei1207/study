## 답안 골격
```text
[TPM(Trusted Platform Module)] ◀━━ 머리: Ⅶ 내 의견 (소프트웨어 기반 키 보관의 메모리 덤프 한계 극복 → 하드웨어 RoT와 실링 기반의 무결성 검증 강제)
 ┃
 ┣━ Ⅰ 개요 ───── TCG(Trusted Computing Group)가 제정한 국제 표준(ISO/IEC 11889) 하드웨어 칩으로, 암호화 키를 물리적으로 격리 보관하고 시스템 부팅 전 과정의 무결성을 측정·증명하는 하드웨어 신뢰 루트(Root of Trust, RoT)
 ┣━ Ⅱ 특징 ───── 하드웨어 기반 변조 불가성(Tamper-resistant) · 암호화 키의 칩 외부 유출 차단 · 부팅 단계별 무결성 측정(Measured Boot) · 데이터 봉인(Sealing) 및 원격 증명(Remote Attestation)
 ┣━ Ⅲ 구조 ───── 실행 엔진(RNG, RSA/ECC, SHA-256) + 불휘발성 메모리(EK, SRK) + 플랫폼 구성 레지스터(PCR) + 휘발성 메모리(AIK)
 ┣━ Ⅳ 흐름 ───── 전원 인가(CRTM) → BIOS/UEFI 해시 측정 및 PCR 확장(Extend) → 부트로더 및 OS 커널 순차 측정 → PCR 일치 시 BitLocker 디스크 복호화 키 언실링(Unsealing)
 ┣━ Ⅴ 비교 ───── 소프트웨어 보안(OS 커널 및 메모리 탈취 취약, 취약점 패치 의존) vs TPM 하드웨어 보안(칩 내부 연산 및 키 격리, 물리적 탐침 공격 방어)
 ┗━ Ⅵ 실무 ───── 메인보드와 TPM 간 버스(LPC/SPI) 스니핑 공격 노출 / 메인보드 고장 시 BitLocker 복구 키 분실 위험 / 가상화 환경(vTPM) 보안
```
- 필수 키워드: TPM 2.0 · 신뢰 루트(Root of Trust) · 엔도스먼트 키(EK) · 플랫폼 구성 레지스터(PCR) · 실링(Sealing) · 측정 부팅(Measured Boot) · 원격 증명(Attestation)
- 기출: 제132회 1교시 8번: "TPM(Trusted Platform Module)"

## 한 줄 본질
- OS가 부팅되기 전 펌웨어와 부트로더에 침투하는 루트킷(Rootkit)을 소프트웨어 백신이 감지하지 못하는 신뢰 기반 병목 → 메인보드 전용 보안 칩(TPM)에서 부팅 체인의 해시값을 하드웨어 레지스터(PCR)에 누적 기록하고 정상 상태에서만 디스크 암호키를 해제 → 하드웨어 레벨 부팅 무결성 확보 / 칩 교체 시 데이터 복구 복잡성 증가

## 핵심 그림
```text
[TPM 2.0 기반 측정 부팅(Measured Boot) 및 데이터 실링(Sealing) 아키텍처]

[부팅 무결성 측정 체인 (Chain of Trust)]
  [전원 On (CRTM)] ──> [UEFI 펌웨어] ──> [부트로더 (GRUB)] ──> [OS 커널] ──> [디스크 복호화]
         │                     │                  │                 │                  │
         ▼ (측정 해시값)       ▼                  ▼                 ▼                  │
┌────────────────────────────────────────────────────────────────────────┐             │
│                       TPM 2.0 하드웨어 보안 칩                         │             │
│                                                                        │             │
│  [PCR 레지스터] $PCR_{new} = SHA256(PCR_{old} \parallel Hash_{stage})$ │             │
│  - 직접 쓰기 불가, 오직 누적 확장(Extend)만 허용                       │             │
│                                                                        │             │
│  [데이터 실링 (Sealing)]                                               │             │
│  - BitLocker 마스터 키 봉인 ───────────────────────────────────────────┼─────────────┘
│  - PCR 값이 정상 부팅 해시와 정확히 일치할 때만 키를 풀어줌(Unseal)!    │
└────────────────────────────────────────────────────────────────────────┘
```

## 핵심 용어
- 플랫폼 구성 레지스터 (PCR, Platform Configuration Register): 펌웨어, 부트로더, 커널 등의 코드를 측정한 해시값을 순차적으로 누적 저장하는 레지스터로, 이전 값을 덮어쓸 수 없고 오직 $Extend(PCR, Data) = Hash(PCR \parallel Data)$ 방식으로만 갱신 가능
- 실링 (Sealing): 암호화 키나 기밀 데이터를 특정 PCR 상태(정상적이고 안전한 부팅 상태)에 결합하여 암호화하는 기술로, 시스템이 해킹되어 부트로더가 1비트라도 변조되면 PCR 값이 달라져 키 복호화(Unseal)가 거부됨

## 핵심 통찰
- 컴퓨터 보안의 딜레마는 "누가 감시자를 감시하는가?"임 → OS 커널이 악성코드에 장악되면 OS가 실행하는 모든 보안 소프트웨어는 공격자의 손바닥 안에서 거짓 보고를 함
- TPM은 컴퓨터의 전원이 켜지는 0초 시점의 가장 밑바닥 하드웨어 '신뢰의 닻(Trust Anchor / CRTM)'을 내려놓고, 부팅의 각 단계를 도미노처럼 검증하며 올라감
- Windows 11이 TPM 2.0을 최소 사양으로 강제한 이유는 메모리 해킹과 펌웨어 랜섬웨어에 소프트웨어만으로 맞서는 것이 공학적으로 한계에 도달했기 때문임

## 이웃 토픽과 구분
- TPM vs HSM: TPM = PC·노트북·서버의 메인보드에 상주하며 부팅 무결성과 로컬 디스크 암호키를 보호 / HSM = 데이터센터 네트워크에 연결되어 초당 수만 건의 금융 거래 전자서명 및 암복호화를 수행하는 고성능 전용 장비

## 문제·원인·대책
- 사례: 공격자가 분실된 노트북의 SSD를 떼어내 다른 PC에 연결하여 BitLocker 암호화 해제를 시도한 사건
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 도난 단말기의 물리적 분해를 통한 드라이브 평문 탈취 | 디스크 암호화 키를 일반 파일이나 레지스트리에 보관 | TPM 2.0 기반 BitLocker 바인딩(TPM 칩 내부 SRK로 키 봉인) | 타 PC에 디스크를 장착해도 TPM 칩이 없어 복호화 불가능 |
| 메인보드와 TPM 간의 SPI 버스 통신선을 도청해 복호화 키 가로채기 | TPM 칩과 CPU 간 통신 구간이 평문(Unencrypted Bus)으로 전송 | 버스 암호화(Parameter Encryption) 지원 TPM 2.0 적용 및 사전 부팅 PIN 강제 | 물리적 프로브(탐침) 도청 공격 무력화 |

## 이렇게 출제된다
- 제132회 1교시 8번: "TPM(Trusted Platform Module)" → 요구 포인트: Ⅰ 정의 및 RoT 개념 + Ⅲ PCR 및 실링 메커니즘 도식 + Ⅵ 부팅 무결성 측정 및 실무 적용 방안

## 내 의견
- [엔터프라이즈 업무용 단말의 제로트러스트 원격 증명(Remote Attestation) 필수화] 사내 네트워크에 접속하는 재택근무 단말기가 펌웨어 수준에서 안전한지 네트워크 접근 제어(NAC)가 확인할 방법이 없음 → 나라면: 사내 접속 포털 로그인 시 단말의 TPM PCR 서명(Quote)을 검증 서버로 전송하도록 의무화하여, 비인가 UEFI 펌웨어나 변조된 OS로 구동된 PC는 사내 인트라넷 접근을 인라인 단계에서 원천 차단
