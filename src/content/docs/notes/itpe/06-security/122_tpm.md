## 30초 인출

- 구별: **Measured Boot**는 부팅 측정값 기록, **Secure Boot**는 허용된 부팅 코드 실행 통제. TPM의 측정만으로 변조 부팅을 자동 차단하지 않음
- 경계: TPM에 봉인한 비밀도 정책 충족 후 호스트로 전달될 수 있음. 칩 밖으로 모든 비밀이 절대 나가지 않는다는 설명은 부정확

## 1교시 예상문제 (10점)

> TPM의 핵심 구성 요소와 PCR 기반 측정 부팅·실링의 관계를 설명하시오. (제132회 1교시 8번 표제어 연계·10점)

## 1교시 10점 답안

### Ⅰ. 개념

TPM(Trusted Platform Module)은 플랫폼의 키 생성·보호, 부팅 상태 측정, 정책 기반 비밀 해제와 증명을 제공하는 TCG 규격의 신뢰 모듈.

### Ⅱ. 핵심 기능

| 기능 | 역할 |
|---|---|
| PCR | 부팅 구성요소의 측정값을 확장 연산으로 누적 |
| 실링 | 지정된 PCR 상태 등 정책에 비밀 해제를 결합 |
| Quote | TPM이 측정 상태에 대한 증거를 서명해 제공 |
| 키 관리 | 보호되는 키와 인증 구조 제공 |

```text
부팅 구성요소 측정 → PCR 확장 → 정책 확인 → 봉인된 비밀 해제
                                   └→ Quote → 원격 검증
```

## 2~4교시 예상문제 (25점)

> TPM 2.0의 키 관리·PCR·실링·원격 증명 구조를 설명하고 Secure Boot와의 차이 및 운영 위험을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

### Ⅰ. 개요

TPM 2.0은 플랫폼 신원과 측정 상태를 암호학적으로 다루는 하드웨어 또는 펌웨어 기반 신뢰 구성요소. 제품별 구현·인증·물리 방어 수준은 상이.

### Ⅱ. 구성과 측정 경로

```text
UEFI·부트로더 등 실행 전후 측정값 → TPM PCR extend
                                   ↓
                           PCR 상태·이벤트 로그
                              ├─ 정책 충족 시 비밀 해제
                              └─ Quote 발급 → 원격 검증자
```

| 구성 | 역할 |
|---|---|
| Endorsement Key(EK) | TPM 신원 관련 키 |
| Storage 계층 | TPM 객체·키 보호의 계층 구조 |
| PCR | 측정값의 순차 누적 |
| Attestation Key | Quote 등 증명 데이터 서명 |

PCR 값은 부팅 구성요소의 해시로부터 파생되지만, 이를 읽는 것만으로 실행 자체가 자동 거부되지는 않음.

### Ⅲ. Measured Boot와 Secure Boot

| 구분 | Measured Boot | Secure Boot |
|---|---|---|
| 핵심 | 무엇이 부팅되었는지 측정·기록 | 허용된 코드만 부팅하도록 서명·정책 확인 |
| TPM 관계 | PCR·이벤트 로그로 증명 | TPM 없이도 검증 기능 가능; TPM 측정과 결합 가능 |
| 실패 시 | 증명 실패·봉인 해제 거부 등의 정책 가능 | 부팅 코드 실행 차단 가능 |

### Ⅳ. 실링과 원격 증명

| 절차 | 검증 |
|---|---|
| 실링 | 비밀 해제 조건에 PCR 정책 등을 지정 |
| 언실링 | 현재 정책이 만족되면 비밀 반환 가능 |
| Quote | 선택 PCR 값의 서명 증거 발급 |
| 원격 검증 | Quote 서명·신선도·이벤트 로그·허용 상태 비교 |

TPM은 저장된 키 보호를 돕지만, 정상 정책으로 해제된 디스크 키가 호스트 메모리·버스를 통과할 수 있음. 물리 공격과 OS 침해까지 일괄 차단하는 보장으로 해석 금지.

### Ⅴ. 운영 위험과 대응

| 위험 | 대응 |
|---|---|
| 펌웨어 업데이트 후 PCR 상태 변화 | 복구 키 보관·변경 시험·허용 정책 관리 |
| TPM·메인보드 고장 | 별도 복구 키 절차와 접근 통제 |
| 부팅 시 버스 관측 등 물리 공격 | 사전 부팅 PIN, 장치별 보안 설계·물리 보호 |
| 잘못된 원격 증명 판단 | 이벤트 로그와 기준 상태를 함께 검증 |

### Ⅵ. 기술사적 제언

측정·실행 차단·키 해제·원격 검증의 기능을 구분하고, 복구 경로와 물리 위협 모델까지 포함한 플랫폼 신뢰 설계.
