- **메커니즘**: 업무·정보를 식별하고 C/S/O 등급을 분류한 뒤, 위협과 환경을 고려해 필요한 통제를 선정·검증.

<details><summary>핵심 용어</summary>

- **국가 망 보안체계(N2SF)**: 공공 업무와 정보의 중요도·위협에 맞춰 정보시스템 보안통제를 적용하는 국가 보안체계.
- **N2SF(National Network Security Framework, 국가 망 보안체계)**: 국가·공공기관의 정보시스템 보안정책과 통제 적용을 업무·정보 중심으로 정리한 체계.
- **C/S/O(Classified/Sensitive/Open, 기밀/민감/공개)**: 업무정보를 보안 중요도에 따라 구분하는 N2SF 정보 등급.
- **보안통제(Security Control)**: 식별된 위험을 관리하기 위해 업무·정보·시스템에 적용하는 보호 조치.

### Ⅱ. C/S/O 등급과 적용 흐름

```text
업무·정보 식별
      ↓
C 기밀 ─ S 민감 ─ O 공개 중 등급 분류
      ↓
위협·정보 흐름·시스템 환경 분석
      ↓
필요 보안통제 선정·적용·검증
```

등급은 정보명만 보고 기계적으로 정하지 않고 업무 맥락과 공개 영향을 반영. 세부 분류와 통제 기준은 현행 N2SF 가이드라인 및 기관 절차에 따름.

### Ⅲ. 한 줄 제언

제언: 분류 근거와 통제 선택 이유를 기록해 업무 변경 때 재검토 가능한 보안 설계 기준으로 활용.

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **국가 망 보안체계(N2SF)**는 공공 업무와 정보의 중요도·위협에 맞춰 정보시스템 보안통제를 적용하는 국가 보안체계. |
| 목적 | 업무 활용을 고려하면서 국가·공공 정보의 기밀성·무결성·가용성을 보호. |

## Ⅱ. C/S/O 정보 분류

| 등급 | 의미 | 분류 시 검토 |
|---|---|---|
| C (Classified) | 기밀 정보 | 비밀 관련 법령·기준과 업무상 취급 요건 |
| S (Sensitive) | 민감 정보 | 공개 영향, 정보주체·업무에 미치는 피해, 접근 범위 |
| O (Open) | 공개 정보 | 공개 가능성 및 무결성·가용성 요구 |

분류는 업무 기능과 정보의 실제 내용·공개 영향에 따라 수행하며, 기관이 적용하는 공식 가이드라인의 세부 기준을 우선.

## Ⅲ. 업무·정보 중심 적용 절차

```text
보호할 업무·정보와 시스템 식별
              ↓
업무·정보별 C/S/O 분류
              ↓
정보 저장·이동·공유 흐름 파악
              ↓
위협·취약점·운영 환경 분석
              ↓
보안통제 설계·적용
              ↓
보안성 확인과 변경 시 재검토
```

## Ⅳ. 통제 설계와 안전한 활용

| 업무 상황 | 통제 설계 관점 |
|---|---|
| 여러 등급의 정보를 한 업무에서 처리 | 정보 흐름과 이용 주체를 구분하고 분리·연계 통제 검토 |
| 외부 클라우드·서비스와 연계 | 데이터 처리 위치·접근권한·기록·반출 조건을 검토 |
| 업무·시스템 구성 변경 | 정보 등급과 통제의 적합성을 다시 평가 |

```text
업무 기능 ── 처리 정보 ── 이용 주체
    │           │             │
    └────── 보안통제 설계 ────┘
                    ↓
       업무 수행과 정보 보호의 균형
```

## Ⅴ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 정보 등급과 통제 근거가 문서에만 남으면 시스템 변경 뒤 실제 구성과 어긋날 수 있음. | 업무·정보 분류, 데이터 흐름, 시스템 구성, 적용 통제를 하나의 변경 검토 기록으로 묶고 중요 변경 때 재승인을 받는 방안을 제안. |
