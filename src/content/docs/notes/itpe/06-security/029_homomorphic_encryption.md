## 지식 로드맵 내 현재 위치

암호기술 → 개인정보 보호 계산(PET) → 동형암호 및 프라이버시 보존 연산

## 30초 인출

- **본질:** 데이터를 복호화하지 않고 암호화된 상태 그대로 사칙연산을 수행하여 평문 연산과 동일한 결과를 도출할 수 있는 4세대 차세대 암호 기술
- **메커니즘:** RLWE(Ring-LWE) 격자 난제 기반 암호화 → 동형 덧셈·곱셈 평가(Evaluation) → 재선형화 및 부트스트래핑(노이즈 제거) → 복호화
- 통찰: 부트스트래핑의 극심한 연산 지연과 비선형 활성화 함수 연산 불가를 극복하기 위해 FPGA 하드웨어 가속과 체비쇼프 다항식 근사화 결합 필수

<details>
<summary>핵심 용어</summary>

- **동형성 (Homomorphism):** 암호문 공간에서의 연산 결과가 평문 공간에서의 대응하는 연산 결과와 일치하는 수학적 대수 구조 ($Enc(m_1) \otimes Enc(m_2) = Enc(m_1 \times m_2)$)
- **완전 동형암호 (FHE, Fully Homomorphic Encryption):** 암호화된 상태에서 횟수 제한 없이 임의의 덧셈과 곱셈 연산을 모두 지원하는 암호 방식
- **부트스트래핑 (Bootstrapping):** 동형 곱셈 시 기하급수적으로 증가하는 암호문 내부 노이즈를 암호문 상태에서 복호화 회로를 실행하여 제거하는 핵심 기법
- **CKKS (Cheon-Kim-Kim-Song):** 국내 연구진이 개발하여 표준화된 스킴으로, 부동소수점 기반의 실수·복소수 근사 연산을 고속으로 지원하는 4세대 FHE 스킴
- **재선형화 (Relinearization):** 두 암호문의 곱셈 후 차수가 3으로 증가한 암호문 크기를 평가키(RelinKey)를 사용하여 다시 원래 차수(2)로 축소하는 변환 과정
</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **동형암호(Homomorphic Encryption)** 는 암호화된 데이터(Ciphertext)를 복호화하여 평문(Plaintext)으로 노출하지 않고도 검색, 통계 분석, 기계학습 등의 복합 연산을 직접 수행할 수 있는 암호학적 기술 |
| 목적 | 클라우드 서비스 제공자(CSP) 및 외부 분석 기관을 신뢰할 수 없는 환경에서 연산 중(Data-in-Use) 데이터의 기밀성 보장 및 개인정보 유출 리스크 원천 차단 |

저장(At-Rest) 및 전송(In-Transit) 단계의 암호화를 넘어 처리(In-Use) 단계까지 암호화를 확장하는 프라이버시 강화 기술(PET)의 핵심 축.

## Ⅱ. 동형암호의 특징 및 세대별 발전

| 세대 구분 | 주요 방식 및 스킴 | 수학적 기반 및 특징 |
|---|---|---|
| **1세대 (PHE)** | RSA (곱셈 동형), Paillier (덧셈 동형) | 덧셈 또는 곱셈 중 단 1가지 연산만 무제한 지원 |
| **2세대 (SWHE/FHE)** | BGV, BFV, Gentry 초기 모델 | 격자(Lattice) 기반, 정해진 횟수(회로 깊이) 내에서 덧셈과 곱셈 동시 지원 |
| **3세대 (GSW)** | GSW (Gentry-Sahai-Waters) | 행렬 암호 기반으로 부트스트래핑 연산 복잡도를 획기적으로 개선 |
| **4세대 (근사 FHE)** | **CKKS**, TFHE | **실수/복소수 연산 지원(CKKS)**, 비트 단위 초고속 부트스트래핑 지원(TFHE) |

## Ⅲ. 동형암호 내부 메커니즘 및 노이즈 관리

```text
[동형암호 암호화, 연산 및 부트스트래핑 라이프사이클]

 1. 평문 입력 (m)      2. 암호문 연산 (Eval)               3. 노이즈 포화 방지
+---------------+     +--------------------------------+     +-------------------+
| 메시지 인코딩 |     | 암호문 덧셈 (노이즈 선형 증가) |     | [부트스트래핑]    |
|       ↓       | --> | 암호문 곱셈 (노이즈 제곱 증가) | --> | 노이즈 상한 도달시|
| RLWE 암호화   |     |       ↓                        |     | 암호문 상태에서   |
| (초기 노이즈) |     | 재선형화 (차수 축소 3 -> 2)    |     | 노이즈 리셋(초기화|
+---------------+     +--------------------------------+     +---------+---------+
                                                                       |
 4. 결과 복호화                                                        |
+----------------------------------------------------------------------+
| 비밀키(sk)로 복호화 -> f(m1, m2) 평문 연산 결과와 100% 일치
+----------------------------------------------------------------------+
```

### 1. 주요 엔지니어링 메커니즘 상세

| 메커니즘 | 기술적 동작 원리 | 해결하는 문제 |
|---|---|---|
| **RLWE 난제** | 원시 다항식 링 상에서 $c = (a \cdot s + e + m, a)$ 형태로 암호화 | 양자컴퓨터의 쇼어 알고리즘 공격에 대한 수학적 면역성 제공 |
| **재선형화 (Relinearization)** | 곱셈 결과 $(c_0, c_1, c_2)$에 대해 평가키를 곱해 $(c'_0, c'_1)$ 차수로 환원 | 연산이 반복될수록 암호문 크기가 기하급수적으로 커지는 현상 방지 |
| **스케일링/재스케일링** | CKKS에서 실수 연산 시 곱셈 후 증가한 스케일 인자($\Delta^2$)를 $\Delta$로 절삭 | 고정밀도 실수 연산에서 비트 오버플로 방지 및 유효 자릿수 보존 |
| **부트스트래핑 (Bootstrapping)** | 암호화된 비밀키(Enc(sk))를 이용해 암호문 내부에서 복호화 함수를 동형 평가 | 노이즈가 임계치를 초과하여 평문이 깨지는 현상 원천 방지 |

## Ⅳ. 주요 동형암호 스킴 심층 비교

| 비교 항목 | BGV / BFV 스킴 | CKKS 스킴 | TFHE 스킴 |
|---|---|---|---|
| **데이터 도메인** | 모듈러 정수 ($\mathbb{Z}_t$) | **실수 및 복소수 ($\mathbb{R}, \mathbb{C}$)** | 이진 비트 ($\{0, 1\}$) |
| **연산 결과 특성** | **정확한(Exact) 정수값 산출** | **근사값(Approximate) 산출** (오차 허용) | 정확한 논리 게이트 산출 |
| **부트스트래핑 속도** | 느림 (수 초 단위) | 보통 (수백 ms ~ 1초) | **극도로 빠름 (수십 ms 단위)** |
| **주요 활용 분야** | 금융 계좌 잔액 집계, 전자투표, DB 쿼리 | **의료 AI 영상 진단, 딥러닝 추론/학습** | 실시간 제어, 스마트 컨트랙트 |
| **대표 오픈소스** | Microsoft SEAL, PALISADE | Microsoft SEAL, OpenFHE, HEAAN | TFHE-rs, Concrete |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **부트스트래핑의 극심한 CPU 연산 지연 및 메모리 대역폭 병목**<br>동형 곱셈 회로 깊이가 깊어질 때 노이즈 제거를 위한 부트스트래핑 연산에 수백 ms~수 초가 소요되어, 실시간 대화형 서비스 적용 불가 | **RNS 기반 NTT 다항식 가속 및 전용 ASIC/FPGA 하드웨어 가속기**<br>대규모 정수 연산을 독립된 작은 모듈러로 분할하는 RNS(Residue Number System) 체계를 적용하고, NTT(수론 변환) 전용 연산 유닛을 내장한 FPGA/ASIC 가속 카드를 도입하여 연산 속도를 100배 이상 단축 |
| **CKKS 스킴의 비선형 활성화 함수(ReLU, Max-pooling) 직접 연산 불가**<br>동형암호는 다항식(덧셈, 곱셈) 연산만 지원하므로, 음수를 0으로 자르는 ReLU나 크기 비교 조건문을 직접 계산할 수 없어 딥러닝 모델 정확도 급감 | **체비쇼프(Chebyshev) 다항식 근사화 및 TEE 하이브리드 오프로딩**<br>활성화 함수 구간을 고차 체비쇼프 다항식으로 근사($f(x) \approx a_0 + a_1 x + a_2 x^2 + \dots$)하여 동형 연산으로 치환하거나, 비선형 계층만 Intel SGX 등 TEE 보안 엔클레이브로 전송하여 고속 처리하는 하이브리드 아키텍처 채택 |

## Ⅵ. 제언

```text
[프라이버시 보존형 머신러닝(PPML) 동형암호 서비스 모델]

 +--------------------+     +---------------------+     +--------------------+
 | 1. 클라이언트 암호화| --> | 2. 클라우드 AI 연산 | --> | 3. 클라이언트 복호화|
 | CKKS 공개키 암호화 |     | 모델 파라미터와     |     | 암호화된 진단 결과 |
 | (개인 의료 영상 전송|     | 동형 곱셈/덧셈 추론 |     | 개인키로 단독 복호 |
 +--------------------+     +---------------------+     +--------------------+
```

| 구현 전략 | 핵심 기술 요소 | 도입 권장 분야 |
|---|---|---|
| **정밀 금융 통계** | BFV/BGV + RNS 가속 | 금융사 간 개인신용정보 유출 없는 연합 신용평가 |
| **프라이버시 AI 추론** | CKKS + 체비쇼프 근사 다항식 | 민간 병원 간 희귀 질환 진단 AI 원격 서비스 |
| **실시간 조건 분기** | TFHE + TEE 하이브리드 | 자율주행 차량 간 실시간 위치 데이터 비식별 연산 |

동형암호의 상용화를 위해서는 모든 알고리즘을 암호문에서 처리하려는 시도를 지양하고, 선형 연산은 CKKS로, 비선형 분기는 TEE로 위임하는 실용적 하이브리드 파이프라인 구축 권장.
