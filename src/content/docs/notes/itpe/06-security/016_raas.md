## Ⅰ. RaaS(서비스형 랜섬웨어)의 개요

- **개념** : 랜섬웨어 개발자(Operator)가 악성코드 제작, C2 인프라, 암호화폐 결제 시스템, 유출 사이트를 플랫폼 서비스 형태로 구축하고, 제휴 파트너(Affiliate)가 이를 구독·대여하여 실제 공격을 수행한 후 갈취한 랜섬 머니를 배분하는 사이버 범죄 비즈니스 모델.
- **배경 및 필요성** : 소프트웨어 서비스(SaaS)의 분업화·전문화 모델이 다크웹 사이버 범죄 생태계로 전이되면서, 고도의 코딩 지식이 없는 비전문 해커도 손쉽게 엔터프라이즈급 타깃 공격을 감행할 수 있는 진입 장벽 붕괴 초래.
- **핵심 목적** : RaaS 생태계 분업 구조(초기 침투, 악성코드 배포, 협상, 자금 세탁) 이해를 통한 초기 공격 표면 차단, CTI 기반 조기 탐지 및 침해 확산 방지.

## Ⅱ. RaaS(서비스형 랜섬웨어)의 핵심 아키텍처 및 동작 메커니즘

RaaS는 운영자(Operator), 초기 침투 브로커(IAB, Initial Access Broker), 공격 실행자(Affiliate)가 다크웹 포털을 통해 철저한 수익 분배(운영자와 파트너 간 사전 약정 비율) 계약으로 협업함.

```text
[ RaaS(서비스형 랜섬웨어)의 3계층 다크웹 분업 생태계 ]

  +-------------------------------------------------------------+
  | RaaS 운영자 (Operator / Core Team)                          |
  |  - 랜섬웨어 악성코드 개발 (빌더 제공, 난독화, 간헐적 암호화)|
  |  - C2 서버 및 다크웹 유출 사이트(Leak Site) 운영            |
  |  - 피해자 협상 포털 및 암호화폐(Bitcoin/Monero) 결제 플랫폼 |
  +------------------------------┬------------------------------+
                                 │ 플랫폼 대여 및 악성 바이너리 배포
                                 ▼
  +-------------------------------------------------------------+
  | 침투 브로커 (IAB) -> 공격 실행자 (Affiliate / Partners)     |
  |  - 기업 VPN 계정, RDP 권한 매입 -> 실제 내부망 침투         |
  |  - AD 장악, 데이터 외부 반출, 랜섬웨어 실행                 |
  +------------------------------┬------------------------------+
                                 │
                                 ▼ 침해 및 갈취 (Extortion)
  +-------------------------------------------------------------+
  | 피해 기업 (Victim) : 다크웹 결제 포털 접속 -> 몸값 지불     |
  |  - 수익 자동 분배 : 운영자·파트너 약정 비율 (스마트 컨트랙트)|
  +-------------------------------------------------------------+
```

- **IAB(초기 침투 브로커)의 자격증명 거래** : 다크웹 포럼에서 피싱이나 인포스틸러로 탈취한 기업 VPN/VDI/RDP 접속 권한을 대량 구매하여 침투 시간 단축.
- **웹 기반 악성코드 빌더(Custom Builder)** : 파트너가 다크웹 관리자 대시보드에서 대상 기업에 맞춤화된 C2 주소, 회피 옵션, 암호화 확장자를 선택하여 원클릭 컴파일.
- **다중 협박(Multi-extortion) 인프라 지원** : 파일 암호화 외에도 탈취한 기밀을 카운트다운 방식으로 공개하는 네임앤셰임(Name-and-Shame) 유출 블로그 기본 제공.
- **전문 협상팀 및 암호화폐 믹서 연계** : 피해자와의 실시간 채팅, 몸값 할인 협상, 지불된 암호화폐의 세탁(Tornado Cash 등)까지 일체형 서비스 제공.

## Ⅲ. RaaS(서비스형 랜섬웨어)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 전통적 랜섬웨어 공격 | 현대 RaaS 기반 공격 | 주요 대응 전략 |
| --- | --- | --- | --- |
| 공격 주체 | 악성코드 개발자 본인이 직접 유포 | 개발자(운영자) + 다수의 외부 제휴 파트너 | 초기 침투 브로커(IAB) 자격증명 무력화 |
| 공격 속도/규모 | 제작자의 역량에 따른 소규모 유포 | 동시다발적 전 세계 엔터프라이즈 타깃 폭증 | 외부 노출 공격표면(ASM) 실시간 스캔 |
| 악성코드 변종 | 단일 시그니처 중심 | 파트너별 맞춤형 난독화 및 매일 새로운 변종 | EDR 기반 행위 분석, 프로세스 트리 추적 |
| 협박 수단 | 단순 파일 복구 비용 요구 | 데이터 유출 협박, DDoS, 협력사 연락 | 데이터 손실 방지(DLP), 불변(WORM) 백업 |
| 수익 모델 | 단독 수취 | 수익 쉐어링 모델 (20:80 또는 30:70) | 자금 세탁 경로 온체인 블록체인 추적 |

- RaaS는 사이버 범죄의 기업화(Enterprise Crime)를 의미하며, 공격자가 인프라 개발에 시간을 쓰지 않고 기업 내부 정찰과 권한 상승에만 집중하므로 공격의 정밀도와 파괴력이 극대화됨.

## Ⅳ. RaaS(서비스형 랜섬웨어)의 주요 한계점 및 해결 방안

- **초기 침투 브로커(IAB)를 통한 합법적 자격증명 로그인 탐지 한계** :
  - **한계점** : 공격자가 악성코드를 쓰지 않고 다크웹에서 구매한 유효한 임직원 계정으로 SSL-VPN에 정상 로그인하므로 경계 보안 솔루션 탐지 우회.
  - **해결 방안** : 피싱 저항성 MFA(FIDO2)를 전사 의무화하고, 사용자 행위 분석(UEBA)을 통해 비정상적인 시간대/위치에서의 접속을 즉시 격리.
- **운영자 체포 시에도 파트너 그룹의 브랜드 리브랜딩(Rebranding) 및 재출현** :
  - **한계점** : 사법기관이 특정 RaaS 그룹(LockBit, BlackCat 등)을 와해시켜도 핵심 파트너들이 소스코드를 들고 새로운 이름으로 부활하는 두더지 잡기 현상.
  - **해결 방안** : MITRE ATT&CK 기반 TTPs(전술, 기법, 절차) 중심의 프로파일링을 수행하여 악성코드 명칭이 바뀌어도 공격 행위 시퀀스를 선제 차단.
- **이중 협박(Double Extortion)으로 인한 백업 복구 무력화** :
  - **한계점** : 완벽한 백업을 보유하고 있어도 데이터 유출 협박으로 인해 거액의 몸값 지불을 강요당하는 구조적 딜레마.
  - **해결 방안** : 핵심 데이터베이스에 대한 전송/보관/사용 중 암호화 전면 적용 및 엔드포인트 대량 아웃바운드 트래픽 발생 시 자동 세션 차단(DLP).

## Ⅴ. RaaS(서비스형 랜섬웨어) 적용 및 발전을 위한 기술사적 제언

- **다크웹 위협 인텔리전스(CTI) 서비스 상시 구독** : 우리 기업의 유출 계정, 내부 인프라 접속 권한이 IAB 포럼에 매물로 등록되는지 24시간 감시 체계 구축.
- **랜섬웨어 대응 전용 침해사고 대응팀(CSIRT) 플레이북 고도화** : 침해 발생 시 감염 호스트 네트워크 격리, 액티브 디렉터리 암호 일괄 리셋, 포렌식 증적 보존의 자동화 스크립트 정비.
- **공급망 벤더 및 서드파티 접근에 대한 제로트러스트 ZTNA 강제** : RaaS 파트너들이 가장 선호하는 경로인 외주 유지보수 업체의 원격 접속에 대해 최소 권한 및 세션 실시간 녹화 적용.
