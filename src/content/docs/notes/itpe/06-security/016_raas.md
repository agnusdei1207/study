## 지식 로드맵 내 현재 위치

사이버위협 → 랜섬웨어 → 서비스형 랜섬웨어(RaaS) 생태계 및 공급망 대응

## 30초 인출

- **본질:** 악성코드 개발자가 랜섬웨어 빌더와 C2 인프라를 서비스 형태로 제공하고, 침투 전문 제휴사(Affiliate)가 공격을 수행하여 수익을 배분하는 사이버 범죄 프랜차이즈 모델
- **메커니즘:** IAB 접근 권한 매수 → 어필리에이트 내부 침투 및 권한 상승 → 데이터 유출 및 WORM 백업 파괴 → 다중 갈취(Quadruple Extortion) 실행
- 통찰: BYOVD 커널 드라이버 무력화와 다크웹 데이터 누출 협박을 방어하기 위해 하드웨어 기반 코드 무결성(HVCI)과 카나리 파일 조기 탐지 체계 구축 필수

<details>
<summary>핵심 용어</summary>

- **RaaS (Ransomware as a Service):** 클라우드 SaaS 모델을 모방하여 랜섬웨어 제작, 유포, 협상, 암호화폐 정산 인프라를 구독 또는 수익 배분형으로 제공하는 플랫폼
- **어필리에이트 (Affiliate):** RaaS 플랫폼에 가입하여 표적 기업에 직접 침투하고 랜섬웨어를 전파하는 실행 파트너 (수익의 70~80% 취득)
- **초기 접근 브로커 (IAB, Initial Access Broker):** 기업의 유출된 VPN 크리덴셜, RDP 계정, 웹 취약점 접근권을 다크웹에서 전문적으로 매매하는 중개자
- **BYOVD (Bring Your Own Vulnerable Driver):** 정상적으로 서명되었으나 취약점이 존재하는 레거시 드라이버를 로드하여 보안 백신과 EDR 커널 콜백을 강제 종료하는 공격 기법
- **다중 갈취 (Multi-Extortion):** 1차 암호화, 2차 데이터 공개 협박(DLS), 3차 디도스(DDoS) 공격, 4차 피해 기업의 고객·협력사 직접 연락 협박
</details>

## 2~4교시 예상문제 (25점)

> 서비스형 랜섬웨어(RaaS) 생태계의 분업화 구조와 다중 갈취(Multi-Extortion) 메커니즘을 설명하고, BYOVD 기법 및 백업 무력화에 대응하기 위한 엔지니어링 방어 아키텍처를 제시하시오. (예상·25점)

---
## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **RaaS(Ransomware as a Service)** 는 악성코드 개발 조직이 랜섬웨어 제작 도구(Builder), 명령제어(C2) 인프라, 암호화폐 결제 포털을 구축하여 플랫폼으로 제공하고, 유포 파트너(Affiliate)가 이를 구독하거나 수익을 분배받는 분업화된 사이버 범죄 모델 |
| 목적 | 고도화된 악성코드 개발 기술이 없는 초급 해커도 대규모 기업을 공격할 수 있게 진입장벽을 낮추고, 범죄 조직의 수익 극대화 및 추적 회피 달성 |

과거 단일 공격자의 일회성 악성코드 살포 방식에서 현대에는 전문 기업처럼 분업화된 고수익 B2B 사이버 범죄 산업군으로 고착화.

## Ⅱ. RaaS 생태계의 특징

| 특징 | 설명 | 방어 관점의 시사점 |
|---|---|---|
| **역할의 고도 분업화** | 개발자, 침투 파트너(Affiliate), 브로커(IAB), 자금세탁책의 완전 분리 | 침투 기법과 악성코드 패밀리가 수시로 교차 조합됨 |
| **공격 주기의 극단적 단축** | IAB를 통한 사전 확보된 권한 매수로 침투부터 암호화까지 수 시간 내 완료 | 초기 침투 탐지 실패 시 즉각적인 전사적 암호화 피해 |
| **SaaS 형태의 편의성** | 웹 기반 관리 대시보드, 랜섬노트 자동 생성, 암호화폐 에스크로 지원 | 글로벌 차원의 대규모 동시다발적 공격 양산 |
| **갈취 모델의 다변화** | 단순 파일 암호화를 넘어 유출 데이터 공개 사이트(DLS)와 연계 | 백업 복원만으로 공격 무력화 불가 (정보 유출 위협) |

## Ⅲ. RaaS 비즈니스 아키텍처 및 다중 갈취 메커니즘

```text
[RaaS 생태계 구성원 및 4중 갈취(Quadruple Extortion) 공격 흐름]

 +-------------------------------------------------------------------+
 |                      [RaaS 핵심 운영자 (Operator)]                |
 |  - 랜섬웨어 바이너리 개발, C2 인프라 운영, 암호화폐 세탁, DLS 운영 |
 +----------------------------------+--------------------------------+
                                    | (플랫폼 제공 / 수익 20% 배분)
 +----------------------------------v--------------------------------+
 |                  [실행 파트너 (Affiliate)]                        |
 |   수익 80% 획득, 도구 커스터마이징, 표적 기업 선정 및 직접 침투   |
 +------------------+--------------------------------+---------------+
                    ^ (접근권 매입)                  | (표적 침투)
                    |                                v
 +------------------+---------------+   +----------------------------+
 | 초기 접근 브로커 (IAB)           |   |       [피해 기업 인프라]   |
 | - 침해된 VPN/RDP 계정, Web CVE   |   |  AD 장악 -> EDR 우회(BYOVD)|
 +----------------------------------+   +--------------+-------------+
                                                       |
   +---------------------------------------------------+
   v
 [4중 갈취 프로세스: Quadruple Extortion]
 1. 데이터 암호화 (복호화 키 대가 요구)
 2. 데이터 유출 및 DLS(Leak Site) 게시 협박
 3. 복구 및 협상 방해를 위한 고객사 웹 서비스 대상 DDoS 공격
 4. 피해 기업의 고객, 파트너사, 규제기관에 직접 유출 통보 협박
```

### 1. RaaS 공격의 주요 전개 단계

| 단계 | 주요 공격 행위 | 공격에 활용되는 도구 및 기법 |
|---|---|---|
| **1. 초기 침투** | IAB를 통한 다크웹 VPN 크리덴셜 매수 또는 피싱 메일 | RDP 무차별 대입, 퍼블릭 SSL-VPN 취약점 |
| **2. 내부 정찰·확산** | 액티브 디렉터리(AD) 장악 및 도메인 컨트롤러 침해 | BloodHound, Mimikatz, Cobalt Strike, 메타스플로잇 |
| **3. 방어 무력화** | EDR 서비스 강제 종료 및 섀도우 복사본 삭제 | BYOVD 기법, `vssadmin delete shadows`, BCDEdit |
| **4. 데이터 탈취·암호화** | 민감 파일 외부 전송 및 타깃 시스템 동시 암호화 | Rclone, Mega.nz, 커스텀 멀티스레드 암호화 바이너리 |

## Ⅳ. 전통적 랜섬웨어 vs RaaS 비교

| 비교 항목 | 전통적 단일 랜섬웨어 (Legacy Ransomware) | 서비스형 랜섬웨어 (RaaS) |
|---|---|---|
| **공격 주체** | 개발자 본인이 직접 제작 및 유포 단독 수행 | 코어 개발팀과 수많은 독립 어필리에이트의 제휴 |
| **수익 모델** | 단독 취득 (비트코인 직접 수취) | 스마트 컨트랙트 및 에스크로 기반 수익 배분 (2:8) |
| **침투 기술 수준** | 무작위 스팸 메일 등 초보적 유포 의존 | IAB 및 전문 APT 해커의 정밀 타깃 침투 |
| **방어 회피 기법** | 단순 패커 및 난독화 수준 | 커널 레벨 BYOVD 드라이버 공격, LOLBins 악용 |
| **협박 방식** | 1차 암호화 (파일 잠금) | **4중 갈취 (암호화 + 유출 + DDoS + 협력사 협박)** |
| **대표 사례** | WannaCry, NotPetya | LockBit, BlackCat(ALPHV), DarkSide, REvil |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **BYOVD(취약한 드라이버 악용)를 통한 커널 레벨 EDR 무력화**<br>공격자가 정상 마이크로소프트 디지털 서명이 포함된 취약 드라이버(GigaByte, Process Hacker 등)를 로드하여 EDR 커널 후킹을 강제 해제하고 백신 프로세스를 종료 | **HVCI(하이퍼바이저 보호 코드 무결성) 및 취약 드라이버 블록리스트**<br>Windows HVCI 및 가상화 기반 보안(VBS)을 강제 활성화하여 미승인 커널 메모리 수정을 차단하고, MS 권고 드라이버 블록리스트(Driver Blocklist) 배포 및 eBPF 기반 비인가 커널 진입 행위 차단 |
| **데이터 유출 협박(DLS)에 따른 전통적 백업 복구 무력화**<br>불변 스토리지로 데이터를 정상 복원하더라도, 유출된 고객 개인정보와 핵심 기밀을 다크웹에 공개하겠다는 협박으로 인해 거액의 금전 갈취에 굴복 | **DLP/CASB 기반 대량 외부 유출 사전 차단 및 카나리 파일 조기 경보**<br>비정상적인 대용량 아웃바운드 트래픽 발생 시 엔드포인트 네트워크를 자동 격리하고, 파일서버 곳곳에 미끼 파일(Honeytoken / Canary Files)을 배치하여 암호화 또는 유출 시도 즉시 탐지·차단 |

## Ⅵ. 제언

```text
[RaaS 침해 저항성(Cyber Resilience) 프레임워크]

 +--------------------+     +---------------------+     +--------------------+
 | 엔드포인트 방어    | --> | 제로트러스트 격리   | --> | 불변 에어갭 복구   |
 | HVCI / EDR 무결성  |     | AD 도메인 관리 분리 |     | 3-2-1-1-0 스토리지 |
 +--------------------+     +---------------------+     +--------------------+
```

| 대응 축 | 핵심 통제 조치 | 달성 목표 |
|---|---|---|
| **식별 및 예방** | ASM(공격표면관리), 외부 노출 자산 전수 다중인증(MFA) | IAB에 의한 초기 침투 통로 원천 봉쇄 |
| **탐지 및 격리** | 카나리 파일, EDR 안티-템퍼링(Anti-tampering), SOAR 격리 | 암호화 시작 전 침해 호스트 5분 내 격리 |
| **대응 및 복구** | WORM 불변 백업, 오프라인 에어갭, 정기 복원 훈련 | 복호화 키 지불 없이 비즈니스 24시간 내 정상화 |

RaaS 방어는 침투를 100% 막는 개념에서 탈피하여, 침해를 가정한 상태에서 내부 확산 지연, 카나리 파일 기반 조기 차단, 불변 스토리지를 통한 비즈니스 연속성(Resilience) 확보 체계로 전환 권장.
