## 연관 키워드

- ISA/IEC 62443, 산업자동화 및 제어시스템(IACS), OT(Operational Technology), ICS(Industrial Control System)
- Zone과 Conduit, 보안 수준(SL, Security Level), 기초 요구사항(FR, Foundational Requirements), Purdue 모델
- ISASecure, 보안 개발 수명주기(SDL), SBOM, 데이터 다이오드, SIS(Safety Instrumented System)

## Ⅰ. ISA/IEC 62443 산업제어시스템 보안의 개요

- 핵심 요약 : 산업 제어 환경의 가용성과 안전성을 목표로, 자산 소유자와 통합자, 제조사 전 주기에 걸쳐 위험 기반 심층 방어를 규정한 국제 표준군.
- 개념 : **산업자동화 및 제어시스템**(IACS, Industrial Automation and Control Systems)의 운영 연속성, 기능 안전, 사이버 복원력을 확보하기 위한 국제 표준군.
- 배경 및 필요성 : 폐쇄망 중심이던 **OT**(Operational Technology)와 **ICS**(Industrial Control System) 인프라가 스마트 팩토리와 산업용 사물인터넷, 클라우드와 연결되면서 외부 위협에 노출됨. 스턱스넷(Stuxnet), 트라이톤(Triton) 등 물리 피해를 노린 공격이 알려지며 제어 전용 보안 표준이 요구됨.
- 주요 목적 : IT 환경의 기밀성 우선 원칙과 달리 가용성과 안전성을 최우선으로 보장하고, Zone과 Conduit 분할로 위협의 수평 확산을 차단.

## Ⅱ. ISA/IEC 62443의 특징 및 장점

- 핵심 요약 : 4계층 표준 구조, Zone과 Conduit 분할, 보안 수준 체계, 7대 기초 요구사항이 결합되어 공정 정지 위험을 낮추는 방식.

1. **4계층 표준 구조** : 일반, 정책·절차, 시스템, 구성요소로 역할을 나눔 → 소유자, 통합자, 제조사의 책임이 분명해짐.
2. **Zone과 Conduit 분할** : 보안 요구가 비슷한 자산을 Zone으로 묶고 Zone 사이 통신을 Conduit으로 통제 → 침해의 수평 확산 차단.
3. **보안 수준(SL, Security Level)** : SL 1(우발적 위반 방어)부터 SL 4(국가 수준 자원을 가진 공격 방어)까지 목표, 역량, 달성 수준을 나누어 평가 → 위험에 비례한 투자 가능.
4. **7대 기초 요구사항(FR)** : 식별·인증, 사용 통제, 시스템 무결성, 데이터 기밀성, 제한된 데이터 흐름, 사건 대응, 자원 가용성을 규정 → 점검 항목을 표준화.
5. **구성요소 단위 검증** : 제조사의 보안 개발 수명주기(SDL)까지 관할 → 조달 제품의 보안 신뢰도 확보.

## Ⅲ. ISA/IEC 62443의 구조 (흐름)

- 핵심 요약 : 4계층 표준이 Zone과 Conduit 설계의 근거를 제공하고, 각 Zone은 목표 보안 수준에 맞춰 분리되는 구조.

```text
[ ISA/IEC 62443 4계층 ]

Part 1 일반: 용어, 개념, SL 모델
   ↓
Part 2 정책·절차: 자산 소유자 관리
   ↓
Part 3 시스템: Zone과 Conduit 설계
   ↓
Part 4 구성요소: 제품 보안 개발
```

```text
[ Zone과 Conduit 분할 (예시) ]

Zone A 제어 서버 영역 (목표 SL 3)
   ↓
Conduit 산업용 방화벽, 데이터 다이오드
   ↓
Zone B 현장 PLC·RTU 영역 (목표 SL 2)
```

## Ⅳ. ISA/IEC 62443, ISO/IEC 27001, NIST SP 800-82의 비교

- 핵심 요약 : 세 표준은 대상 환경과 우선순위가 달라, 산업 제어 환경에는 가용성과 안전을 앞세우는 ISA/IEC 62443이 적합함.

| 비교 항목 | ISA/IEC 62443 | ISO/IEC 27001 | NIST SP 800-82 |
|---|---|---|---|
| 대상 환경 | 산업자동화 및 제어시스템 (OT/ICS) | 전사 정보보호 관리체계 (IT) | 연방 산업제어시스템 보안 가이드 |
| 보안 우선순위 | 가용성 > 무결성 > 기밀성 | 기밀성 > 무결성 > 가용성 | 안전과 가용성 > 무결성 > 기밀성 |
| 핵심 구조 | 4계층 (일반, 정책, 시스템, 구성요소) | PDCA 기반 ISMS와 부속서 A 통제 | ICS 아키텍처, 위협 모델, 완화 대책 |
| 분할 원칙 | Zone과 Conduit, SL 연계 | 자산 분류 경계 | Purdue 모델 기반 세그멘테이션 |
| 인증 체계 | ISASecure 적합성 인증 | ISO/IEC 27001 제3자 인증 | 가이드라인 (자율 준수) |

- ISA/IEC 62443은 공정 정지와 물리 피해 방지를 최우선으로 두고 구성요소 단위까지 관할하므로, 산업 제어 환경의 실효 기준으로 활용됨.

## Ⅴ. ISA/IEC 62443 적용의 한계와 방안

- 핵심 요약 : 레거시 기기의 자원 한계, 가동 중 검증의 어려움, 멀티벤더 공급망 파편화를 경계 보호, 디지털 트윈, 조달 기준으로 대응.

| 한계 | 원인·영향 | 대응 방안 |
|---|---|---|
| 레거시 PLC·RTU의 자원 한계 | 메모리와 CPU가 제한되어 TLS나 인증서 기반 통신 탑재 시 제어 지연 발생 | 단말을 고치지 않고 Conduit 경계에 산업용 IPS와 프로토콜 게이트웨이를 배치해 심층 패킷 검사와 가상 패칭 수행 |
| 가동 중 검증과 침투 테스트 불가 | 공정 가동 중 패치나 모의 침투 시 미세한 트래픽에도 공정 정지 위험 | CPS **디지털 트윈**(Digital Twin)에서 사전 검증 후 정기 정비 기간에 배포 |
| 멀티벤더 공급망 파편화 | 제조사별 패치 주기가 다르고 62443-4 인증이 없는 모듈이 유입 | 조달 단계에서 62443-4 계열 인증을 요구하고 **SBOM**(Software Bill of Materials) 제출 의무화 |

## Ⅵ. ISA/IEC 62443 적용에 대한 기술사적 제언

- 핵심 요약 : IT와 OT를 잇는 관제, 경계 기반 세그멘테이션, 안전계장 시스템의 물리 분리를 함께 추진하는 방향.

IT와 OT 통합 관제 체계를 구축하여 기존 SIEM과 SOAR에 Modbus, DNP3, OPC UA 같은 산업 프로토콜의 비정상 패킷 정보를 결합하면 OT 이상 징후를 조기에 찾을 수 있다.

Purdue 모델의 계층 사이에는 데이터 다이오드와 제로 트러스트 접근 정책을 함께 두어 경계가 뚫려도 횡적 이동이 어렵도록 설계하는 것이 필요하다.

비상 정지와 인명 안전을 담당하는 안전계장 시스템은 상용 제어망과 물리적으로 분리된 전용 Conduit으로 격리하는 것이 원칙이다.

## Ⅶ. 결론

- 핵심 요약 : ISA/IEC 62443은 산업 제어 환경을 가용성과 안전성 기준으로 보호하는 국제 표준 체계.
- 표준 적용의 실효성은 Zone과 Conduit 설계와 공급망 인증이 함께 갖춰질 때 확보됨.
