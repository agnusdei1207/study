## 지식 로드맵 내 현재 위치

- 정보보안 → 침해사고 대응 및 조사 → 디지털 수사 → 컴퓨터 포렌식(Computer Forensics)

```text
[사이버 침해사고 발생] ──> [증거 5대 원칙 준수 (정당성/재현성/신속성/연계보관성/무결성)]
                                     │
                                     ├── 휘발성 수집 (Order of Volatility: RAM, 프로세스)
                                     └── 비휘발성 수집 (쓰기 방지 장치 하 비트스트림 E01 이미징)
                                     │
                                     ▼
                     [사본 분석 ──> 타임라인/아티팩트 재구성 ──> 법정 증거 보고서]
```

## 30초 인출

- **본질:** 컴퓨터 시스템 및 디지털 저장매체에 잔존하는 전자적 데이터를 사법기관 또는 법정에 제출 가능한 법적 증거(Admissible Evidence)로 확보하기 위한 과학적 조사 절차.
- **메커니즘:** 적법 절차 및 영장 집행 → 휘발성 데이터 수집(Order of Volatility) → 원본 쓰기 방지 및 사본 이미징(SHA-256 검증) → 아티팩트 정밀 분석 → 연계보관성(Chain of Custody) 보고서 제출.
- **통찰:** 휘발성 메모리 증거 소실과 안티 포렌식(Anti-Forensics) 위협에 대응하기 위해 전원 차단 전 라이브 메모리 덤프를 우선 수행하고 하드웨어 쓰기방지 장치 기반의 비트스트림 사본 채증 원칙 확립 필수.

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 컴퓨터 시스템, 네트워크, 저장매체 등 디지털 장치에 존재하는 데이터를 법적 효력을 갖는 증거로 활용하기 위해 과학적이고 체계적인 방법으로 수집, 보존, 분석, 현출하는 일련의 조사 과정 |
| 목적 | 내부 부정행위, 해킹, 악성코드 유포 등 사이버 범죄의 행위 주체(Attribution)와 행적을 규명하고, 법정에서 증거능력(Admissibility)을 인정받기 위함 |

- 디지털 데이터의 고유한 특성인 비가시성, 대량성, 변조 용이성(취약성), 매체 독립성을 극복하기 위해 엄격한 사법 절차와 기술적 무결성 검증이 요구됨.

## Ⅱ. 컴퓨터 포렌식의 핵심 특징 및 증거의 5대 기본 원칙

### 1. 디지털 증거의 핵심 특성

| 특성 | 설명 | 법적·기술적 요구조건 |
|---|---|---|
| 취약성 및 변조 용이성 | 수정, 삭제, 덮어쓰기가 극히 용이 | 원본 저장매체에 하드웨어 쓰기 방지(Write Blocker) 연결 의무 |
| 비가시성 / 비가독성 | 0과 1의 2진 바이트로 존재 | 전문 디코더 및 변환 도구를 통한 시각적 현출(Rendering) 필수 |
| 매체 독립성 | 물리적 매체와 분리되어 자유로운 복제 | 원본과 비트 단위로 동일한 사본(Bit-stream Image) 생성 허용 |
| 초국경성 / 휘발성 | 네트워크를 통한 즉각적 소멸 | 휘발성 순위에 따른 신속한 라이브 메모리 덤프 우선 수행 |

### 2. 디지털 증거의 5대 기본 원칙

```text
[디지털 포렌식 증거의 5대 기본 원칙]
  ├── 1. 정당성의 원칙 (Legality)     ──> 적법절차(위법수집증거 배제 법칙), 영장주의 및 동의서 획득
  ├── 2. 재현성의 원칙 (Repeatability) ──> 제3의 전문가가 동일 도구와 환경으로 재검증 시 동일 결과 도출
  ├── 3. 신속성의 원칙 (Promptness)    ──> 휘발성 데이터 소실 및 덮어쓰기 방지를 위한 신속한 현장 수집
  ├── 4. 연계보관성의 원칙 (Chain of Custody) ──> 증거의 최초 획득부터 법정 제출까지 전 과정 인계·보관 이력 기록
  └── 5. 무결성의 원칙 (Integrity)     ──> 원본과 사본의 해시값(SHA-256)이 전 단계에서 일치함 입증
```

## Ⅲ. 조사 5단계 절차 및 데이터 휘발성 순서(Order of Volatility)

### 1. 포렌식 조사 5단계 표준 프로세스

```text
+-----------------------------------------------------------------------------------------+
|                               컴퓨터 포렌식 5단계 표준 프로세스                           |
+-----------------------------------------------------------------------------------------+
  [1. 준비 단계] ──> [2. 획득 단계] ──> [3. 보존 단계] ──> [4. 분석 단계] ──> [5. 보고 단계]
  - 권한/영장 확인   - 라이브 수집      - 증거물 봉인/라벨  - 타임라인 분석     - 조사 결과서 작성
  - 도구 무결성 점검 - 쓰기방지 이미징  - 금고 보관 관리    - 아티팩트 카빙     - 연계보관증 첨부
  - 현장 격리(망분리)- 해시값 산출      - 작업 사본 복제    - 안티포렌식 대응   - 법정 증언 준비
+-----------------------------------------------------------------------------------------+
```

### 2. RFC 3227 기반 데이터 휘발성 순서 (Order of Volatility)

```text
[휘발성 높음 (가장 먼저 수집)]
  ▲  1. CPU 레지스터 및 캐시 메모리 (Register, Cache)
  │  2. 라우팅 테이블, ARP 캐시, 프로세스 테이블, 커널 통계 메모리
  │  3. 메인 메모리 (Physical RAM)
  │  4. 임시 파일 시스템 (스왑 공간, 가상 메모리 페이징 파일)
  │  5. 비휘발성 로컬 저장 디스크 (HDD, SSD, 플래시 메모리)
  │  6. 원격 로깅 시스템 및 네트워크 모니터링 데이터 (SIEM, 방화벽 로그)
  ▼  7. 물리적 백업 매체 및 테이프 아카이브
[휘발성 낮음 (나중에 수집)]
```

## Ⅳ. 라이브 포렌식 vs 데드 포렌식 및 포렌식 도구 비교

### 1. 라이브 포렌식(Live)과 데드 포렌식(Dead) 비교

| 비교 항목 | 라이브 포렌식 (Live Forensics) | 데드 포렌식 (Dead Forensics) |
|---|---|---|
| 시스템 상태 | 시스템 전원이 켜져 있고 부팅된 상태 | 시스템 전원을 차단(Cold Boot)하고 디스크 분리 상태 |
| 주요 수집 대상 | 휘발성 메모리(RAM), 활성 네트워크 세션, 실행 중인 악성코드 | 비휘발성 디스크 전체 비트스트림 이미지, 삭제 파일 파편 |
| 장점 | 암호화 볼륨(BitLocker) 마운트 상태 덤프 가능, 인젝션 프로세스 확인 | 원본 훼손 위험 극히 낮음, 완벽한 무결성 해시 유지 |
| 단점 | 수집 도구 실행 시 일부 RAM 및 레지스트리 상태 미세 변경 | 전원 차단 시 RAM 내 암호화 키, 프로세스, 세션 영구 소멸 |
| 주요 수집 도구 | LiME, WinPmem, FTK Imager Lite, DumpIt | EnCase, Forensic Falcon, Tableau 쓰기방지 장치, X-Ways |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 타임스톰핑(Timestomping)을 통해 파일의 생성·수정 시간($MFT $STANDARD_INFORMATION)을 조작하여 분석관의 시간 순서 추적 교란 | 조작이 극히 어려운 $MFT $FILE_NAME 속성의 시간 정보와 USN 저널($UsnJrnl), 윈도우 이벤트 로그(Security Event 4663)를 상호 대조하는 다차원 교차 검증 수행 |
| 공격자가 비트라커(BitLocker)나 파일볼트(FileVault) 등 전체 디스크 암호화(FDE)를 적용하여 전원 차단 시 사본 분석 전면 불가 | 현장에서 전원을 차단하지 않고 라이브 메모리(RAM)를 우선 덤프하여 메모리 풀 내 평문 볼륨 마스터 키(FVEK)를 추출하거나 키 에스크로 백업 시스템 조회 |
| SSD의 웨어 레벨링(Wear Leveling) 및 자동 TRIM 명령으로 인해 쓰기 방지 장치를 연결해도 컨트롤러 내부적으로 슬랙 블록이 자동 소거 | 디스크 전원 인가 시 즉시 SATA 컨트롤러 핀 통신을 차단하는 전용 하드웨어 포렌식 툴을 사용하고 칩오프(Chip-off) 또는 벤더 디버그 모드로 원시 플래시 블록 직접 덤프 |

## Ⅵ. 제언

### 1. 제로 트러스트 기반 포렌식 연계보관성(Chain of Custody) 아키텍처

```text
[현장 증거 수집] ──> [블록체인 무결성 등록] ──> [포렌식 분석 사본 전달] ──> [법정 증거 현출]
  - 하드웨어 쓰기방지     - SHA-256 해시 생성          - 원본 완전 밀봉 보관          - 타임라인 분석 보고서
  - 사본 2벌 생성        - 시간인증(TSA) 스탬프        - 작업 사본으로만 분석          - 무결성 검증 로그
  - 수집자 서명 날인     - 스마트 컨트랙트 기록        - 도구 버전 및 명령어 기록      - 법관/배심원 시각화
```

### 2. 포렌식 조사 환경별 기술적 난이도 및 대응 전략 비교

| 조사 대상 영역 | 증거 획득 난이도 | 휘발성 수준 | 핵심 증거 아티팩트 | 권장 수사 기법 |
|---|---|---|---|---|
| 엔드포인트 PC | 보통 | 중~고 | $MFT, Prefetch, LNK, 브라우저 캐시 | 라이브 RAM 덤프 후 E01 디스크 이미징 |
| 클라우드 인스턴스 | 높음 | 매우 높음 | VPC 플로우 로그, CloudTrail, EBS 스냅샷 | CSP API 기반 인스턴스 격리 및 볼륨 볼라틸리티 스냅샷 |
| 모바일 기기 (스마트폰) | 최고 (하드웨어 암호화) | 높음 | SQLite DB, 메신저 대화록, 위치 정보 | Checkm8 취약점 익스플로잇 및 상용 추출기(Cellebrite) |
| 네트워크 인프라 | 높음 | 즉시 소멸 | NetFlow, PCAP 패킷 덤프, 방화벽 세션 | 네트워크 탭(TAP) 미러링 상시 캡처 파이프라인 |

- 컴퓨터 포렌식은 단순한 기술 분석을 넘어 법정에서의 엄격한 증거능력을 충족해야 하므로, 기술적 무결성 보증과 연계보관성(Chain of Custody)을 완벽히 입증할 수 있는 표준화된 절차 준수 필수.
