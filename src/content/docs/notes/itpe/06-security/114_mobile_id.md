## 지식 로드맵 내 현재 위치

디지털 신원 → 국가 신원 증명 체계 → 모바일 신분증 (Mobile ID & DID)

## 30초 인출

- **본질:** 실물 플라스틱 신분증(주민등록증, 운전면허증)과 법적으로 동일한 효력을 가지며, 스마트폰 하드웨어 보안 영역(SE)과 분산 신원증명(DID) 기술을 결합하여 자기주권적 신원 증명과 선택적 정보 제공을 보장하는 국가 공공 신원 체계.
- **메커니즘:** 발급기관(행정안전부) 신원 확인 후 VC 발급 → 사용자 스마트폰 SE에 암호화 저장 → 검증자에게 필요한 속성만 담은 VP를 동적 QR코드로 제시 → 블록체인 원장 기반 서명 검증.
- 통찰: 단순 육안 확인(화면 캡처 위조) 및 과도한 개인정보 노출을 방지하기 위해 영지식 증명(ZKP) 기반 선택적 속성 공개와 단말 보안 칩(SE/TEE) 연동 FIDO2 생체인증 필수.

<details><summary>핵심 용어</summary>

- **모바일 신분증(Mobile ID)**: 도로교통법 및 주민등록법에 근거하여 행정안전부가 개인의 스마트폰에 발급하는 공인 디지털 신분증.
- **DID(Decentralized Identifier)**: 중앙화된 인증 기관 없이 블록체인 분산 원장을 통해 신원 주체가 자신의 식별자를 직접 통제하는 W3C 국제 표준 식별 체계.
- **VC(Verifiable Credential)**: 발급기관이 암호학적 서명을 적용하여 발급한 검증 가능한 디지털 자격 증명서.
- **VP(Verifiable Presentation)**: 사용자가 신원 검증자에게 제출하기 위해 하나 이상의 VC로부터 필요한 속성만을 추출하여 직접 서명한 제출용 데이터.
- **선택적 정보 공개(Selective Disclosure)**: 성인 인증 시 주민등록번호나 주소는 감추고 오직 '성인 여부(IsAdult: True)'만을 선별하여 제공하는 프라이버시 보호 기술.
</details>

## 2~4교시 예상문제 (25점)

> 행정안전부의 '모바일 신분증(Mobile ID)' 구축에 적용된 분산 신원증명(DID) 아키텍처와 발급·저장·제시·검증 전주기 메커니즘을 설명하고, 개인정보 과잉 노출 방지(선택적 공개) 및 도용 방지를 위한 기술적 한계와 엔지니어링 해결 방안을 제시하시오. (25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 개인의 스마트폰 안전 영역(SE)에 암호화 저장되어 온·오프라인에서 신원과 자격을 증명할 수 있는 블록체인 DID 기반의 국가 공인 모바일 신분증 체계 |
| 목적 | 플라스틱 신분증 휴대의 불편함과 분실 시 개인정보 노출 위험을 해소하고, 위변조 방지 및 최소 개인정보 제공을 통한 프라이버시 중심의 디지털 정부 구현 |

## Ⅱ. 모바일 신분증의 핵심 특징 및 신원 모델

| 특징 항목 | 세부 구현 내용 | 보안 및 사용자 가치 |
|---|---|---|
| 법적 동일 효력 | 도로교통법 및 주민등록법상 실물 플라스틱 신분증과 100% 동일한 법적 효력 인정 | 관공서, 은행, 편의점, 렌터카 등 전 분야 실물 대체 |
| 자기주권 신원 (SSI) | 중앙 서버가 개인의 인증 이력을 추적하지 못하도록 단말 내부에서 직접 신원 관리 | 중앙 집중형 데이터베이스 해킹으로 인한 대량 유출 방지 |
| 선택적 속성 공개 | 주류 구매 시 생년월일/주소를 숨기고 '만 19세 이상' 정보만 선택 제공 가능 | 영지식 증명(ZKP) 및 W3C VC 기반 프라이버시 보호 극대화 |
| 하드웨어 보안 격리 | 스마트폰 내부 eSE(embedded Secure Element) 및 TEE 보안 영역에 개인키 격리 | 단말기 루팅이나 악성 앱에 의한 암호키 탈취 원천 차단 |
| 동적 1회성 QR 검증 | 고정된 바코드가 아닌 30초 주기로 변경되는 동적 일회용 QR코드 및 BLE 통신 사용 | 화면 캡처 이미지 도용 및 재생 공격(Replay Attack) 방지 |

## Ⅲ. 모바일 신분증 발급·제시·검증 프로세스 및 DID 아키텍처

```text
[ 1. 발급 단계 (Issuance) ]
[ 사용자 (Holder) ] ──▶ 1. 본인 확인 및 발급 신청 ──▶ [ 발급기관: 행안부 (Issuer) ]
                    ◀── 2. 서명된 VC 발급 (eSE 저장) ──┤
                                                         │ 3. 발급자 DID Document 등록
                                                         ▼
                                          [ 블록체인 분산 원장 (DID Registry) ]
                                                         ▲
[ 2. 제시 및 검증 단계 (Presentation & Verification) ]   │
[ 사용자 (Holder) ]                                      │
  │ 4. 필요한 속성만 추출하여 VP 생성 및 서명             │
  ▼                                                      │
[ 동적 QR / BLE 통신 ]                                   │ 6. 공개키 및 폐기 목록(Revocation) 확인
  │                                                      │
  ▼ 5. 검증 요청 (VP 전달)                               │
[ 신원 검증자 (Verifier: 은행, 관공서, 편의점 앱) ] ───────┘
  │ 7. 암호학적 서명 검증 및 실시간 유효성 판정 완료
  ▼
[ 신원 확인 승인 ]
```

| 생애주기 단계 | 주요 활동 | 핵심 엔지니어링 기술 |
|---|---|---|
| 발급 (Issuance) | IC 신분증 태그 또는 모바일 운전면허시험장 방문 대면 확인 후 단말기 eSE에 키 생성 | FIDO2 인증, PKI 전자서명, W3C Verifiable Credentials |
| 저장 (Storage) | 발급받은 신원 정보(VC)를 스마트폰 내 보안 칩(eSE/TEE)에 AES-256 암호화 저장 | Android StrongBox, iOS Secure Enclave, 하드웨어 바인딩 |
| 제시 (Presentation) | 검증자 요청 스펙에 맞춰 필요한 클레임만 추출하여 1회용 VP 생성 및 서명 | W3C Verifiable Presentation, 동적 TOTP 기반 QR코드 |
| 검증 (Verification) | 블록체인 분산 원장에서 발급기관 공개키를 조회하여 VC 서명 및 폐기 상태 확인 | DID Document 조회, 단말 간 암호화 BLE 채널(mTLS) |
| 폐기 (Revocation) | 단말기 분실 신고 시 즉시 블록체인 폐기 목록(Revocation List)에 반영하여 무효화 | 암호학적 누산기(Cryptographic Accumulator), OCSP |

## Ⅳ. 실물 신분증 vs 모바일 신분증 vs 사설 모바일 인증서 비교

| 비교 항목 | 실물 플라스틱 신분증 | 모바일 신분증 (정부 DID) | 사설 모바일 인증서 (카카오/토스 등) |
|---|---|---|---|
| 발급 주체 | 행정안전부, 경찰청 | 행정안전부, 경찰청 | 민간 전자서명인증사업자 |
| 법적 효력 | 법정 공식 신분증 (온·오프라인) | 법정 공식 신분증 (온·오프라인 100% 동일) | 전자서명 효력 (신분증 대체 일부 불가) |
| 정보 제공 방식 | 주민번호, 주소 등 모든 정보 강제 노출 | 필요한 속성만 선택적 공개 (Selective) | 사설 플랫폼 앱 내부 인증 확인 |
| 위변조 검증 | 육안 홀로그램 확인 (위조 위험 높음) | 공개키 암호 및 블록체인 수학적 검증 | 중앙 인증 서버 질의 검증 |
| 분실 시 위험 | 습득자에 의한 개인정보 악용 노출 | 생체인증 잠금 및 원격 즉시 폐기 가능 | 스마트폰 잠금 해제 시 위험 노출 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 비행기 기내나 지하 통신 음영 지역 등 오프라인 환경에서 블록체인 원장의 실시간 폐기 여부(Revocation) 검증 불가 | 유효 기간이 24시간인 단기 단말 검증 티켓(Ephemeral Verifier Ticket)을 발급하고, 오프라인 시에도 서명자 공개키를 캐싱하여 로컬 검증 지원 |
| 스마트폰 분실 또는 도난 시 공격자가 단말기 PIN 번호를 훔쳐보거나 강제로 잠금 해제하여 신분증 도용 위험 | 생체인증(지문/Face ID) 실패 시 즉시 앱 데이터가 자폭(Self-Destruct)되도록 설정하고 통신사 분실 신고 즉시 원격 킬스위치(Kill-Switch) 가동 |
| 스마트폰 화면 캡처 방지 기능이 일부 커스텀 안드로이드 OS(루팅 단말)에서 무력화되어 위조 화면 제시 가능 | 모바일 신분증 화면에 실시간 움직이는 동적 워터마크 애니메이션과 30초 유효시간 타이머를 강제하고 검증자 전용 앱의 스캐닝 확인 의무화 |
| 보안 칩(eSE)이 탑재되지 않은 저가형 구형 스마트폰의 경우 소프트웨어 키스토어 사용으로 인한 암호키 탈취 취약점 | eSE 미지원 기기는 화이트박스 암호(White-Box Cryptography) 라이브러리를 적용하고 1일 1회 재인증을 강제하는 차등 보안 정책 적용 |

## Ⅵ. 제언

```text
[ 글로벌 상호운용 가능한 모바일 신분증 발전 모델 ]

+-------------------------+      +-------------------------+      +-------------------------+
|     1. ZKP 전면 상용화  | ---> |     2. ISO 표준 호환    | ---> |     3. 모바일 운전면허  |
| (영지식 기반 완전 프라이버|    | (ISO/IEC 18013-5 mDL)   |      | (글로벌 국가 간 상호인정)
+-------------------------+      +-------------------------+      +-------------------------+
```

| 발전 영역 | 핵심 엔지니어링 구현 과제 | 비즈니스 가치 |
|---|---|---|
| 프라이버시 보호 | 영지식 증명(ZKP) 암호 알고리즘 상용 탑재를 통한 완전 비식별 자격 증명 실증 | 주민등록번호 없는 신원 증명 사회로의 완벽 전환 |
| 글로벌 상호운용 | 국제 표준 ISO/IEC 18013-5(모바일 운전면허증) 및 mdoc 규격과의 완벽한 호환성 확보 | 해외 공항 및 렌터카에서 대한민국 모바일 신분증 통용 |
| 민간 생태계 개방 | 오픈 API 기반 신원 검증 SDK를 전 산업(유통, 공유경제, 핀테크)에 무료 보급 | 신원 확인 비용 90% 절감 및 비대면 신뢰 거래 확립 |

## 출제 이력과 검증 출처

- 제121회 정보관리기술사 (분산 ID 기반 모바일 신분증 체계)
- 대한민국 행정안전부, 모바일 신분증 서비스 표준 가이드라인
- W3C Verifiable Credentials Data Model v2.0 & Decentralized Identifiers (DIDs) v1.0
- ISO/IEC 18013-5:2021, Personal identification — ISO-compliant driving licence — Part 5: Mobile driving licence (mDL) application

## 연결 토픽

- 연속 인증(Continuous Authentication)
- 크리덴셜 스터핑(Credential Stuffing)
- 패스키(Passkey) / FIDO2
- 비대칭키 암호화
