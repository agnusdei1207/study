## Ⅰ. 모바일 신분증의 개요

- ** 개념** : 개인의 스마트폰 안전 영역(SE)에 암호화 저장되어 온·오프라인에서 신원과 자격을 증명할 수 있는 블록체인 DID 기반의 국가 공인 모바일 신분증 체계.
- ** 배경 및 필요성** : 플라스틱 실물 신분증의 위변조, 분실 및 과도한 개인정보 노출 문제를 해결하고, 블록체인 DID(탈중앙 신원증명) 및 보안 칩(SE/TEE)을 기반으로 필요한 정보만 선택적으로 제출(자기주권신원)하기 위해 국가 표준으로 구축됨.
- ** 핵심 목적** : 플라스틱 신분증 휴대의 불편함과 분실 시 개인정보 노출 위험을 해소하고, 위변조 방지 및 최소 개인정보 제공을 통한 프라이버시 중심의 디지털 정부 구현.

## Ⅱ. 모바일 신분증의 핵심 아키텍처 및 동작 메커니즘

모바일 신분증은(는) 신뢰할 수 있는 보안 구조와 표준화된 절차를 기반으로 동작하며, 세부적인 아키텍처와 구성요소 간의 상호작용 메커니즘은 다음과 같음.

```text
[ 1. 발급 단계 (Issuance) ]
[ 사용자 (Holder) ] ──▶ 1. 본인 확인 및 발급 신청 ──▶ [ 발급기관: 행안부 (Issuer) ]
                    ◀── 2. 서명된 VC 발급 (eSE 저장) ──┤
                                                         │ 3. 발급자 DID Document 등록
                                                         ▼
                                          [ 블록체인 분산 원장 (DID Registry) ]
                                                         ▲
[ 2. 제시 및 검증 단계 (Presentation & Verification) ]   │
[ 사용자 (Holder) ]                                      │
  │ 4. 필요한 속성만 추출하여 VP 생성 및 서명             │
  ▼                                                      │
[ 동적 QR / BLE 통신 ]                                   │ 6. 공개키 및 폐기 목록(Revocation) 확인
  │                                                      │
  ▼ 5. 검증 요청 (VP 전달)                               │
[ 신원 검증자 (Verifier: 은행, 관공서, 편의점 앱) ] ───────┘
  │ 7. 암호학적 서명 검증 및 실시간 유효성 판정 완료
  ▼
[ 신원 확인 승인 ]
```

- ** 발급 (Issuance)** : IC 신분증 태그 또는 모바일 운전면허시험장 방문 대면 확인 후 단말기 eSE에 키 생성 (FIDO2 인증, PKI 전자서명, W3C Verifiable Credentials).
- ** 저장 (Storage)** : 발급받은 신원 정보(VC)를 스마트폰 내 보안 칩(eSE/TEE)에 AES-256 암호화 저장 (Android StrongBox, iOS Secure Enclave, 하드웨어 바인딩).
- ** 제시 (Presentation)** : 검증자 요청 스펙에 맞춰 필요한 클레임만 추출하여 1회용 VP 생성 및 서명 (W3C Verifiable Presentation, 동적 TOTP 기반 QR코드).
- ** 검증 (Verification)** : 블록체인 분산 원장에서 발급기관 공개키를 조회하여 VC 서명 및 폐기 상태 확인 (DID Document 조회, 단말 간 암호화 BLE 채널(mTLS)).
- ** 폐기 (Revocation)** : 단말기 분실 신고 시 즉시 블록체인 폐기 목록(Revocation List)에 반영하여 무효화 (암호학적 누산기(Cryptographic Accumulator), OCSP).

## Ⅲ. 모바일 신분증의 세부 구성 요소 및 비교 분석

| 비교 항목 | 실물 플라스틱 신분증 | 모바일 신분증 (정부 DID) | 사설 모바일 인증서 (카카오/토스 등) |
|---|---|---|---|
| 발급 주체 | 행정안전부, 경찰청 | 행정안전부, 경찰청 | 민간 전자서명인증사업자 |
| 법적 효력 | 법정 공식 신분증 (온·오프라인) | 법정 공식 신분증 (온·오프라인 100% 동일) | 전자서명 효력 (신분증 대체 일부 불가) |
| 정보 제공 방식 | 주민번호, 주소 등 모든 정보 강제 노출 | 필요한 속성만 선택적 공개 (Selective) | 사설 플랫폼 앱 내부 인증 확인 |
| 위변조 검증 | 육안 홀로그램 확인 (위조 위험 높음) | 공개키 암호 및 블록체인 수학적 검증 | 중앙 인증 서버 질의 검증 |
| 분실 시 위험 | 습득자에 의한 개인정보 악용 노출 | 생체인증 잠금 및 원격 즉시 폐기 가능 | 스마트폰 잠금 해제 시 위험 노출 |

- 모바일 신분증은(는) 상기 핵심 비교 지표와 아키텍처 구성을 바탕으로 보안 위협에 대한 방어 효과성을 극대화하며, 기존 레거시 통제 기법 대비 우수한 신뢰성과 운영 효율성을 제공함.

## Ⅳ. 모바일 신분증의 주요 한계점 및 해결 방안

- ** 비행기 기내나 지하 통신 음영 지역 등 오프라인 관련 보안 한계 및 취약점** : - ** 한계점** : 비행기 기내나 지하 통신 음영 지역 등 오프라인 환경에서 블록체인 원장의 실시간 폐기 여부(Revocation) 검증 불가.
  - ** 해결 방안** : 유효 기간이 24시간인 단기 단말 검증 티켓(Ephemeral Verifier Ticket)을 발급하고, 오프라인 시에도 서명자 공개키를 캐싱하여 로컬 검증 지원.
- ** 스마트폰 분실 또는 도난 시 공격자가 단말기 PIN 취약점** : - ** 한계점** : 스마트폰 분실 또는 도난 시 공격자가 단말기 PIN 번호를 훔쳐보거나 강제로 잠금 해제하여 신분증 도용 위험.
  - ** 해결 방안** : 생체인증(지문/Face ID) 실패 시 즉시 앱 데이터가 자폭(Self-Destruct)되도록 설정하고 통신사 분실 신고 즉시 원격 킬스위치(Kill-Switch) 가동.
- ** 스마트폰 화면 캡처 방지 기능이 일부 커스텀 안드로 취약점** : - ** 한계점** : 스마트폰 화면 캡처 방지 기능이 일부 커스텀 안드로이드 OS(루팅 단말)에서 무력화되어 위조 화면 제시 가능.
  - ** 해결 방안** : 모바일 신분증 화면에 실시간 움직이는 동적 워터마크 애니메이션과 30초 유효시간 타이머를 강제하고 검증자 전용 앱의 스캐닝 확인 의무화.
- ** 보안 칩(eSE)이 탑재되지 않은 저가형 구형 스마 취약점** : - ** 한계점** : 보안 칩(eSE)이 탑재되지 않은 저가형 구형 스마트폰의 경우 소프트웨어 키스토어 사용으로 인한 암호키 탈취 취약점.
  - ** 해결 방안** : eSE 미지원 기기는 화이트박스 암호(White-Box Cryptography) 라이브러리를 적용하고 1일 1회 재인증을 강제하는 차등 보안 정책 적용.

## Ⅴ. 모바일 신분증 적용 및 발전을 위한 기술사적 제언

- ** 프라이버시 보호 중심의 거버넌스 및 실행 체계 구축** : 영지식 증명(ZKP) 암호 알고리즘 상용 탑재를 통한 완전 비식별 자격 증명 실증을(를) 적극 추진하여, 주민등록번호 없는 신원 증명 사회로의 완벽 전환 효과를 극대화해야 함.
- ** 글로벌 상호운용 중심의 거버넌스 및 실행 체계 구축** : 국제 표준 ISO/IEC 18013-5(모바일 운전면허증) 및 mdoc 규격과의 완벽한 호환성 확보을(를) 적극 추진하여, 해외 공항 및 렌터카에서 대한민국 모바일 신분증 통용 효과를 극대화해야 함.
- ** 민간 생태계 개방 중심의 거버넌스 및 실행 체계 구축** : 오픈 API 기반 신원 검증 SDK를 전 산업(유통, 공유경제, 핀테크)에 무료 보급을(를) 적극 추진하여, 신원 확인 비용 90% 절감 및 비대면 신뢰 거래 확립 효과를 극대화해야 함.
