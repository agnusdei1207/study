## 답안 골격
```text
[모바일 신분증(Mobile ID)] ◀━━ 머리: Ⅶ 내 의견 (중앙 집중형 개인정보 보관 탈피 → 블록체인 분산 ID(DID)와 영지식 증명 기반 프라이버시 중심 신원 검증)
 ┃
 ┣━ Ⅰ 개요 ───── 개인의 스마트폰 안전 영역(Secure Element)에 암호화하여 저장하고, 온·오프라인 어디서나 실물 신분증과 동일한 법적 효력으로 자신의 신원을 증명하는 블록체인 기반 자기주권 신원(DID/VC) 서비스
 ┣━ Ⅱ 특징 ───── 자기주권 신원증명(SSI) 구현 · 선택적 정보 제공(Selective Disclosure) · 영지식 증명(ZKP) 연계 가능 · 하드웨어 보안 영역(SE/TEE) 기반 개인키 보호
 ┣━ Ⅲ 구조 ───── 신원 3주체(발급자 Issuer, 보유자 Holder, 검증자 Verifier) + 블록체인 분산원장(DID Registry) + 단말 보안 영역(SE)
 ┣━ Ⅳ 흐름 ───── 신원 확인 및 VC 발급(정부) → 단말 SE 개인키 생성 및 VC 저장 → 신원 검증 요청(검증자) → 선택적 속성 추출 및 VP 서명 제출 → 분산원장 공개키 검증
 ┣━ Ⅴ 비교 ───── 기존 중앙집중 신분증(신원 증명 시 중앙 서버 조회 필요, 프라이버시 감시 위험) vs 모바일 신분증(단말 로컬 검증, 중앙 서버 개입 차단, 최소 정보 공개)
 ┗━ Ⅵ 실무 ───── 스마트폰 분실·도난 시 폐기 처리(Revocation) / 루팅·탈옥 단말의 개인키 탈취 위험 / 고령층 디지털 소외
```
- 필수 키워드: 모바일 신분증 · DID(Decentralized Identifier) · VC(Verifiable Credential) · VP(Verifiable Presentation) · 자기주권 신원(SSI) · Secure Element(SE) · 영지식 증명(ZKP)
- 배점 전략: 10점 = Ⅰ 모바일 신분증 개념 및 법적 효력 → Ⅲ DID 신원 3주체 구조도 → Ⅵ 핵심 보안 메커니즘 요약 / 25점 = Ⅰ~Ⅶ 전개, 제121회 기출 대응, W3C DID 표준 아키텍처, 선택적 정보 제공(주민번호 숨김) 및 단말 하드웨어(SE/TEE) 보안 기술 심층 상술
- 기출: 제121회 1교시 11번: "모바일 신분증"

## 한 줄 본질
- 신분증을 제시할 때마다 모든 개인정보(주민등록번호, 주소)가 타인에게 노출되는 프라이버시 침해 병목 → 블록체인 분산 ID(DID)와 단말 하드웨어 보안 칩을 결합해 필요한 자격(성인 여부 등)만 암호학적으로 증명 → 자기주권 프라이버시 확보 / 스마트폰 분실 및 단말 보안 의존성 증가

           ▼                                                        ▼

## 핵심 용어
- VC (Verifiable Credential): 발급기관(정부)이 암호학적으로 서명하여 위·변조가 불가능함을 보장하는 디지털 자격증명(운전면허증, 주민등록증 원본 데이터)
- VP (Verifiable Presentation): 보유자가 검증자의 요구에 맞추어 VC의 특정 정보(예: 성인 여부)만 골라내어 자신의 개인키로 서명해 제출하는 프레젠테이션 데이터
- Secure Element (SE): 스마트폰 내부의 물리적으로 격리된 독립 보안 마이크로칩으로, 외부 소프트웨어 해킹이나 운영체제 루팅으로부터 암호화 개인키를 안전하게 보호

## 핵심 통찰
- 모바일 신분증의 혁신은 "플라스틱 카드를 화면에 띄우는 것"이 아니라 "정보의 주권을 개인에게 돌려주는 것"임 → 편의점에서 술을 살 때 생년월일과 이름, 주소를 보여줄 필요 없이 "성인(True)"이라는 수학적 참(True) 값만 제시함
- 신원 검증 시 중앙 서버에 실시간 조회를 요청하지 않음 → 정부 서버가 사용자가 언제 어디서 누구에게 신분증을 제시했는지 추적할 수 없는 구조적 프라이버시(Privacy-by-Design)를 달성함
- 블록체인 위에는 개인정보(이름, 주민번호)를 1글자도 올리지 않음 → 오직 발급자의 공개키, DID 도큐먼트, 그리고 취소된 신분증의 해시 목록(Revocation List)만 기록함

## 이웃 토픽과 구분
- 모바일 신분증(DID) vs 공동인증서(PKI): 모바일 신분증 = 탈중앙화 신원, 사용자가 정보 제출 범위 통제, 단말 SE 중심 / 공동인증서 = 중앙 집중형 공인인증기관(CA) 발급, 전자서명 용도 중심

## 문제·원인·대책
- 사례: 모바일 운전면허증이 탑재된 스마트폰을 분실하여 타인에 의한 부정 사용이 우려된 상황
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 스마트폰 분실 및 화면 잠금 해제 시 신분증 도용 위험 | 로컬 단말에 저장된 신분증 앱의 무단 실행 가능성 | 앱 실행 시 생체인증(지문/FaceID) 필수화 및 분실 신고 시 즉시 원격 폐기(Revoke) | 비인가자의 신원 도용 원천 방지 |
| 루팅된 안드로이드 단말에서 메모리 해킹을 통한 개인키 덤프 | OS 커널 권한 탈취로 인한 앱 데이터 영역 접근 | 하드웨어 기반 Secure Element(eSE/iSE) 저장 강제 및 루팅 탐지 시 앱 자동 삭제 | 최고 등급의 하드웨어 하이재킹 저항력 확보 |

## 이렇게 출제된다
- 제121회 1교시 11번: "모바일 신분증" → 요구 포인트: Ⅰ 개념 및 특징 + Ⅲ DID 3주체 및 블록체인 연계 구조 + Ⅵ 단말 보안(SE) 및 프라이버시 보호 기술

## 내 의견
- [생성형 AI 시대 비인간 에이전트 신원증명(Agent ID)으로의 확장] 향후 자율 AI 에이전트가 금융 거래와 계약을 대리 수행할 때 인간 사용자가 발급한 위임 자격증명이 필수적임 → 나라면: 현행 모바일 신분증 아키텍처에 '위임형 VC(Delegated Credential)' 규격을 추가하여, 사용자가 특정 에이전트에 특정 한도(예: 100만 원 이하 결제)와 기간 동안만 유효한 대리인 신분증을 발행하고 블록체인 스마트 컨트랙트로 자동 소멸시키는 프레임워크를 선제적 도입
