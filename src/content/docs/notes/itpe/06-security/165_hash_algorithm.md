# 해시 알고리즘(Hash Algorithm)

## 핵심 개념
- 임의의 가변 길이 메시지를 입력받아 고정된 길이의 비트열(해시값 또는 메시지 다이제스트)로 변환하는 일방향(One-way) 수학적 함수.
- 데이터의 무결성(Integrity) 검증, 전자서명(Digital Signature), 비밀번호 저장, 블록체인 블록 연결의 핵심 암호 요소로 작동.

```
+-------------------------------------------------------------+
|               암호학적 해시 함수의 3대 보안 특성               |
+-------------------------------------------------------------+
| 1. 역상 저항성 (Pre-image Resistance)        | 일방향성, h=H(M)에서 M 계산 불가 |
| 2. 제2 역상 저항성 (Second Pre-image)         | 주어진 M에 대해 H(M)=H(M')인 M' 탐색 불가 |
| 3. 충돌 저항성 (Collision Resistance)         | H(M)=H(M')인 임의의 쌍 (M, M') 탐색 불가 |
+-------------------------------------------------------------+
```

---

## 해시 알고리즘의 암호학적 특성 상세

```
[1. 역상 저항성 (단방향성)]
   M (원문) -----------> H(M) = h (해시값)
    ?    <--- X -------- h (해시값만으로 원문 M 역산 불가)

[2. 제2 역상 저항성 (약한 충돌 저항성)]
   주어진 원문 M1 ---------> H(M1)
                              ||  (H(M1) == H(M2)가 되는 다른 M2를 찾기 불가)
   탐색 대상 M2 ---------> H(M2)

[3. 강한 충돌 저항성]
   공격자가 임의로 선택한 두 메시지 M1 != M2에 대해
   H(M1) == H(M2)가 성립하는 쌍 자체를 찾아내는 것이 계산상 불가능.
```

- **눈사태 효과(Avalanche Effect)**: 입력 데이터가 단 1비트만 변경되어도 출력 해시값의 절반 이상의 비트가 무작위로 완전히 뒤바뀌는 특성.
- **생일 역설(Birthday Paradox)**: $n$비트 해시 함수에서 충돌 쌍을 찾기 위한 연산 복잡도는 $2^n$이 아니라 약 $2^{n/2}$에 불과하므로 충돌 저항성을 위해 충분한 출력 비트 길이가 필수적임.

## 주요 해시 알고리즘 계열 비교

| 알고리즘 계열 | 발표 기관 | 다이제스트 길이 | 내부 구조 | 보안 상태 및 권고 |
|---|---|---|---|---|
| **MD5** | Ronald Rivest (1991) | 128 bit | Merkle-Damgard | 충돌 공격 성공, 사용 전면 금지 |
| **SHA-1** | NIST / NSA (1995) | 160 bit | Merkle-Damgard | 실질적 충돌 공격(SHAttered) 성공, 폐기 |
| **SHA-2** | NIST / NSA (2001) | 224, 256, 384, 512 bit | Merkle-Damgard | 현재 표준으로 널리 사용 (SHA-256 권고) |
| **SHA-3** | NIST (2015, Keccak) | 224, 256, 384, 512 bit | 스펀지 구조(Sponge) | SHA-2 대체 차세대 표준, 길이 확장 공격 면역 |
| **LSH** | 한국 KISA / 국가보안기술연구소 | 256, 512 bit | 덧셈·순환이동·XOR (ARX) | 국내 표준(KS X 3262), 경량·고속 소프트웨어 최적화 |

## 내부 아키텍처: 머클-담고르 vs 스펀지 구조

```
[머클-담고르 구조 (SHA-2 등)]
메시지 블록 M1, M2, ... 를 순차 압축 함수 f에 반복 투입
IV ----> [ f ] ----> [ f ] ----> ... ----> [ f ] ----> 해시값 출력
          ^           ^                     ^
          M1          M2                    Mn
* 한계: 길이 확장 공격(Length Extension Attack)에 취약할 수 있음.

[스펀지 구조 (SHA-3 / Keccak)]
흡수(Absorbing) 단계: 메시지를 내부 상태(Rate r)에 XOR 후 치환(f) 반복
압착(Squeezing) 단계: 상태의 일부(Rate r)를 출력 스트림으로 추출
       메시지 M1        메시지 M2                해시 Z1          해시 Z2
          |                |                        ^                ^
[Rate r]  v                v              [Rate r]  |                |
+----+----+----+    +----+----+----+      +----+----+----+    +----+----+----+
|    |  f |    | -> |    |  f |    | ...  |    |  f |    | -> |    |  f |    |
+----+----+----+    +----+----+----+      +----+----+----+    +----+----+----+
[Capacity c]        [Capacity c]          [Capacity c]        [Capacity c]
  <-- 흡수 (Absorbing) 단계 -->             <-- 압착 (Squeezing) 단계 -->
```

## 비밀번호 저장 전용 키 스트레칭 알고리즘

단순 해시 함수는 연산 속도가 너무 빨라 GPU 및 ASIC 기반 무차별 대입(Brute Force) 공격에 취약하므로, 비밀번호 해싱에는 솔트(Salt)와 의도적 연산 지연(Work Factor)을 부여하는 전용 알고리즘을 사용함.

| 알고리즘 | 특징 및 설계 메커니즘 | 메모리 요구량 |
|---|---|---|
| **PBKDF2** | SHA-256 등 해시 함수를 수만~수십만 회 반복 수행(HMAC 반복) | CPU 집약적 (메모리 제약 없음) |
| **bcrypt** | Blowfish 암호 알고리즘 기반, 솔트 내장 및 가변 비용 인자 지원 | 소량 메모리 필요 (GPU 병렬화 지연) |
| **scrypt** | 대규모 메모리 버퍼 할당 강제로 ASIC/FPGA 하드웨어 제작 무력화 | 메모리 집약적 (설정 가능) |
| **Argon2** | Password Hashing Competition 우승작, 메모리/CPU/스레드 복합 제어 | 최고 수준의 GPU/ASIC 공격 저항 |

## 결론 및 실무 시사점
- MD5 및 SHA-1의 암호학적 파괴로 인해 현대 시스템은 최소 SHA-256 이상의 해시 함수를 기본 적용해야 함.
- 사용자 비밀번호 저장 시 단순 해시 저장은 중대 결함이며, KISA 지침에 따라 솔트(Salt) 적용과 PBKDF2/bcrypt/Argon2 기반의 키 스트레칭 메커니즘을 의무화해야 함.
