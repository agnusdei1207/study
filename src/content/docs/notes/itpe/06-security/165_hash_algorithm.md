## 지식 로드맵 내 현재 위치

- 정보보안 → 암호학(Cryptography) → 단방향 암호화 → 해시 함수(Hash Algorithm)

```text
[임의 길이 입력 메시지 M] ──(단방향 압축 함수 H)──> [고정 길이 다이제스트 H(M)]
                                                     ├── Merkle-Damgård 구조: MD5, SHA-1, SHA-2 (길이 확장 취약)
                                                     └── Sponge 구조 (Keccak): SHA-3, SHAKE (길이 확장 면역)
```

---

## 30초 인출

- **본질:** 임의 길이의 데이터를 입력받아 수학적으로 역산이 불가능한 고정 길이의 고유 해시값(다이제스트)을 출력하는 일방향 암호학적 압축 함수.
- **메커니즘:** 입력 메시지 패딩(Padding) 및 블록 분할 → 압축 함수 반복 연산(Merkle-Damgård) 또는 상태 순열 스펀지 흡수·압출(Keccak Sponge) → 고정 크기 출력.
- **통찰:** Merkle-Damgård 구조는 내부 상태 노출로 인한 길이 확장 공격(Length Extension Attack)에 취약하므로, 순열 기반 스펀지 구조를 채택한 SHA-3로의 전환 및 HMAC 결합 필수.

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 임의의 가변 길이를 갖는 입력 데이터를 수학적 단방향 압축 연산을 거쳐 고정된 길이의 유일한 비트열(Digest)로 변환하는 함수 |
| 목적 | 데이터 전송 및 저장 과정에서의 위변조 여부를 신속히 검증(무결성)하고, 전자서명, HMAC, 블록체인 PoW의 기반 기술로 활용 |

- 암호화 키를 사용하지 않는 단방향 함수로서 원본 복호화가 이론적으로 불가능해야 하며, 미세한 입력 변화에도 출력이 완전히 뒤바뀌는 눈사태 효과(Avalanche Effect) 보장 필요.

## Ⅱ. 해시 알고리즘의 핵심 특징 및 3대 암호학적 안전성 요건

### 1. 해시 알고리즘의 핵심 특징

| 특징 | 설명 | 기술적 요구조건 |
|---|---|---|
| 일방향성 (One-way) | 출력값으로부터 원본 역산 불가 | 다이제스트 $y$가 주어졌을 때 $H(x) = y$인 $x$를 찾는 계산 복잡도가 $2^n$에 수렴 |
| 고정 길이 출력 | 입력 크기와 무관한 일관된 크기 | SHA-256은 256비트, SHA-512는 512비트의 균일한 블록 다이제스트 생성 |
| 눈사태 효과 (Avalanche Effect) | 1비트 변경 시 전체 해시값 50% 이상 변동 | 입력값의 미세한 변조도 즉각적으로 감지할 수 있도록 비트 확산성 보장 |
| 고속 연산성 | 하드웨어/소프트웨어 고속 처리 | 대용량 파일 및 실시간 네트워크 패킷에 대한 지연 없는 무결성 검증 수행 |

### 2. 해시 함수의 3대 암호학적 안전성 요건

```text
[암호학적 해시 함수의 3대 안전성]
  ├── 1. 제1역상 저항성 (Pre-image Resistance, 단방향성)
  │     - 주어진 해시값 y에 대해 H(x) = y를 만족하는 x를 찾는 것이 계산상 불가능 (공격 복잡도: O(2^n))
  │
  ├── 2. 제2역상 저항성 (Second Pre-image Resistance, 약한 충돌 저항성)
  │     - 특정 입력 x가 주어졌을 때, H(x) = H(x')를 만족하는 다른 입력 x'(x' ≠ x)를 찾는 것이 불가능 (공격 복잡도: O(2^n))
  │
  └── 3. 충돌 저항성 (Collision Resistance, 강한 충돌 저항성)
        - 생일 역설(Birthday Attack)에 기반하여 H(x) = H(x')를 만족하는 임의의 두 입력 쌍 (x, x')를 찾는 것이 불가능 (공격 복잡도: O(2^(n/2)))
```

## Ⅲ. Merkle-Damgård 구조 vs Sponge 구조 아키텍처 비교

### 1. Merkle-Damgård 구조 (MD5, SHA-1, SHA-2)

```text
+-----------------------------------------------------------------------------------------+
|                               Merkle-Damgård 반복 압축 아키텍처                          |
+-----------------------------------------------------------------------------------------+
  초기 벡터 (IV) ──> [압축 함수 f] ──> [압축 함수 f] ──> ... ──> [압축 함수 f] ──> 최종 해시 다이제스트
                          ▲                   ▲                       ▲
                          │                   │                       │
                    메시지 블록 M_1     메시지 블록 M_2         메시지 블록 M_k (패딩 + 길이)
+-----------------------------------------------------------------------------------------+
* 취약점: 최종 다이제스트가 마지막 압축 함수의 내부 상태와 동일하여, 공격자가 악성 데이터를 덧붙여
  유효한 새 해시를 위조하는 길이 확장 공격(Length Extension Attack)에 구조적으로 노출됨.
```

### 2. Sponge 구조 (SHA-3, Keccak)

```text
+-----------------------------------------------------------------------------------------+
|                                   Keccak Sponge 아키텍처                                |
+-----------------------------------------------------------------------------------------+
       <─── 흡수 단계 (Absorbing Phase) ───>       <─── 압출 단계 (Squeezing Phase) ───>
       M_1 ⊕ r      M_2 ⊕ r                         출력 Z_1        출력 Z_2
          │            │                               ▲               ▲
  IV ──> [ f ] ─────> [ f ] ── ... ──> [ f ] ───────> [ f ] ────────> [ f ]
          │            │                │
          c (용량)     c (용량)         c (내부 상태 비공개로 길이 확장 공격 원천 차단)
+-----------------------------------------------------------------------------------------+
```

## Ⅳ. 주요 해시 알고리즘 계열별 특성 비교

### 1. 해시 알고리즘 계열 4종 비교

| 구분 | MD5 | SHA-1 | SHA-2 (SHA-256) | SHA-3 (SHA3-256) |
|---|---|---|---|---|
| 표준화 연도 | 1992년 (RFC 1321) | 1995년 (FIPS 180-1) | 2001년 (FIPS 180-4) | 2015년 (FIPS 202) |
| 설계 구조 | Merkle-Damgård | Merkle-Damgård | Merkle-Damgård | Sponge 구조 (Keccak-p 순열) |
| 다이제스트 크기 | 128 비트 | 160 비트 | 256 비트 (224~512) | 256 비트 (가변 XOF 지원) |
| 내부 상태 크기 | 128 비트 | 160 비트 | 256 비트 | 1,600 비트 ($r=1088, c=512$) |
| 충돌 공격 복잡도 | 실시간 충돌 생성 ($2^{21}$) | 실증 충돌 발표 ($2^{63}$, SHAttered) | 안전 ($2^{128}$ 보증) | 최고 안전 ($2^{128}$ 보증) |
| 길이 확장 공격 | 취약 | 취약 | 취약 (HMAC 결합 필수) | 면역 (구조적으로 완전 방어) |
| 현재 보안 상태 | 폐기 (사용 절대 금지) | 폐기 (NIST 2030 완전 퇴출) | 표준 권장 (광범위 채택) | 차세대 표준 권장 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| Merkle-Damgård 기반 SHA-256을 `H(Secret + Message)` 형태로 단순 결합 시 공격자가 원본 키를 몰라도 패딩 블록 뒤에 임의 명령을 추가하는 길이 확장 공격(Length Extension Attack) 발생 | 내부 상태를 노출하지 않는 HMAC-SHA-256 구조(`H(K⊕opad + H(K⊕ipad + M))`)로 전환하거나 Sponge 구조 기반의 SHA-3(Keccak) 알고리즘 적용 |
| 일반 범용 암호 해시 함수는 처리 속도가 너무 빨라 공격자가 고성능 GPU/ASIC 클러스터를 동원해 초당 수백억 개의 무차별 대입(Brute-force) 역산 가능 | 사용자 비밀번호 저장 시 범용 해시를 금지하고 메모리 집약적 연산과 Salt, 반복 횟수를 강제하는 패스워드 전용 해시 함수(Argon2id, bcrypt, PBKDF2) 적용 |
| 대규모 양자 컴퓨터 환경에서 Grover 알고리즘 적용 시 해시 충돌 및 역상 탐색 연산 복잡도가 절반($O(2^{n/2}), O(2^{n/3})$)으로 급락하여 보안 강도 저하 | 양자 저항 강도 128비트 유지를 위해 최소 출력 길이가 256비트 이상인 SHA-256/384/512 또는 SHA3-256 이상 알고리즘으로 전면 마이그레이션 |

## Ⅵ. 제언

### 1. 양자 내성 및 용도별 해시 알고리즘 적용 아키텍처

```text
[데이터 용도별 해시 매핑]
  ├── 메시지 무결성 / 블록체인 ──> SHA-256 / SHA3-256 (표준 암호 해시)
  ├── API 메시지 인증          ──> HMAC-SHA256 / KMAC128 (키 결합 서명)
  ├── 사용자 비밀번호 저장      ──> Argon2id (Memory-hard KDF, ASIC 내성)
  └── 가변 길이 키 유도 함수    ──> HKDF / SHAKE256 (XOF: Extendable-Output)
```

### 2. 레거시 해시 전환 및 알고리즘 종합 평가

| 알고리즘 | 현재 권고 상태 | 연산 오버헤드 | 하드웨어 가속 지원 | 최적 활용 도메인 |
|---|---|---|---|---|
| MD5 / SHA-1 | 즉시 폐기 | 극히 낮음 | 범용 지원 | 단순 파일 다운로드 체크섬 (보안성 없음) |
| SHA-256 | 현재 표준 | 낮음 | Intel SHA-NI 기본 탑재 | TLS/HTTPS 인증서, Git, 비트코인 블록체인 |
| SHA3-256 | 차세대 표준 | 보통 | 전용 ASIC/FPGA 최적화 | 국방/금융 고보안 시스템, 포스트 양자 암호 체계 |
| Argon2id | 패스워드 표준 | 조절 가능 (고연산) | CPU/메모리 부하 인위적 유도 | 데이터베이스 사용자 계정 비밀번호 암호화 저장 |

- 정보 시스템 전반에 걸쳐 하드코딩된 MD5/SHA-1 레거시 코드를 전수 식별하여 퇴출하고, 암호 민첩성(Crypto-Agility) 원칙에 따라 미래 양자 위협에 대비한 SHA-3 전환 로드맵 수립 필수.
