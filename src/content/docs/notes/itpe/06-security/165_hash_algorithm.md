## Ⅰ. 해시 알고리즘(Hash Algorithm)의 개요

- 개념 : 임의의 가변 길이 데이터를 입력받아 고정된 길이의 고유한 **비트열** (해시값, 다이제스트)로 변환하며, 역연산이 수학적으로 불가능하고 충돌을 회피하는 3대 보안 특성을 만족하는 **일방향 암호화 함수** (One-Way Cryptographic Hash Function).
- 배경 및 필요성 : 데이터의 무결성 검증, 전자서명 생성, 비밀번호의 안전한 저장, 블록체인 **작업증명** (PoW) 등에서 원본 데이터를 노출하지 않고 고속으로 위변조 여부를 증명하기 위해 개발됨.
- 핵심 목적 : 데이터의 미세한 1비트 변경도 완전히 다른 해시값으로 변환(눈사태 효과)시켜 데이터의 무결성을 보증하고, **메시지 인증 코드** (HMAC) 및 디지털 서명의 기반을 제공.

## Ⅱ. 해시 알고리즘(Hash Algorithm)의 핵심 아키텍처 및 동작 메커니즘

해시 알고리즘은 **압축 함수** (Compression Function)를 반복 적용하는 **머클-담고르** (Merkle-Damgård) 구조(MD5, SHA-1, SHA-2)에서 **스펀지 함수** (Sponge Function) 구조를 채택한 Keccak(SHA-3)으로 진화함.

```text
[ 해시 알고리즘 아키텍처: Merkle-Damgard vs Sponge 구조(SHA-3) ]

 1. Merkle-Damgard 구조 (MD5, SHA-1, SHA-256)
    [ 초기 벡터 (IV) ] -----------------+
                                         v
    [ 평문 블록 M_1 ] -------------> [ 압축 함수 (f) ]
                                         | 중간 해시 (H_1)
                                         v
    [ 평문 블록 M_2 ] -------------> [ 압축 함수 (f) ]
                                         |
                                         v
    [ 평문 블록 M_k (Padding) ] ----> [ 압축 함수 (f) ] ---> [ 최종 해시 Digest ]
    * 취약점: 길이 확장 공격(Length Extension Attack)에 노출 위험!

 2. Sponge 구조 (SHA-3 / Keccak)
    [ Absorbing (흡수 단계) ]             [ Squeezing (스퀴징 단계) ]
     M_1 (+)          M_2 (+)               Z_1            Z_2
      |   |            |   |                 ^              ^
    [--- 상태 r (Rate) ---]     f          [--- 상태 r ---]      f
    [--- 용량 c (Capacity)-] ---------->   [--- 용량 c ---] --------->
    * 내부 상태 순열(Permutation) 기반으로 길이 확장 공격 완벽 면역!
```

- **역상 저항성(Pre-image Resistance, 일방향성)** : 주어진 해시값 $h$에 대해, $H(m) = h$를 만족하는 원본 평문 $m$을 찾는 것이 계산적으로 불가능해야 하는 특성.
- **제2 역상 저항성(Second Pre-image Resistance, 약한 충돌 회피)** : 주어진 평문 $m_1$에 대해, $H(m_1) = H(m_2)$를 만족하는 또 다른 평문 $m_2$($m_1 \neq m_2$)를 찾는 것이 계산적으로 불가능.
- **충돌 저항성(Collision Resistance, 강한 충돌 회피)** : 동일한 해시값을 생성하는 임의의 서로 다른 두 평문 쌍 $(m_1, m_2)$을 찾는 것이 계산적으로 불가능 (생일 역설에 의해 $\approx 2^{n/2}$ 복잡도).
- **눈사태 효과(Avalanche Effect)** : 입력 데이터의 단 1비트만 변경되어도 출력되는 해시값의 절반 이상의 비트가 무작위로 완전히 뒤바뀌는 극적인 통계적 무작위성.

## Ⅲ. 해시 알고리즘(Hash Algorithm)의 세부 구성 요소 및 비교 분석

| 비교 항목 | **MD5** | **SHA-1** | **SHA-2** (SHA-256) | **SHA-3** (Keccak) |
| --- | --- | --- | --- | --- |
| 출력 길이 | 128 비트 | 160 비트 | 256 / 512 비트 | 224 / 256 / 384 / 512 비트 |
| 내부 구조 | Merkle-Damgard | Merkle-Damgard | Merkle-Damgard | Sponge 순열 구조 |
| 충돌 취약점 | 완전 붕괴 (수초 내 충돌 생성) | 충돌 발견 (SHAttered 시연) | 현재까지 충돌 없음 (안전) | 충돌 없음 (최고 수준 안전성) |
| 길이확장공격 | 취약 | 취약 | 취약 (HMAC으로 극복) | 완벽 면역 (구조적 방어) |
| 현재 지위 | 사용 전면 금지 (폐기) | 사용 전면 금지 (NIST 폐기) | 현재 산업계 사실상 표준 | 차세대 표준 (SHA-2 대체 백업) |

- MD5 및 SHA-1은 암호학적 충돌이 완벽히 입증되어 사용이 금지되었으며, 현재는 SHA-256이 표준이나 길이 확장 공격 면역을 위해 차세대 SHA-3 및 HMAC의 병용이 권장됨.

## Ⅳ. 해시 알고리즘(Hash Algorithm)의 주요 한계점 및 해결 방안

- 단순 해시의 고속 연산 특성으로 인한 비밀번호 브루트포스 취약 :
  - 한계점 : SHA-256은 초고속 데이터 무결성 검증을 위해 설계되었으므로, 최신 GPU 클러스터로 초당 수백억 개의 해시를 연산하여 레인보우 테이블 및 무차별 대입 성공.
  - 해결 방안 : 단순 해시 대신 의도적으로 CPU/메모리 부하를 유발하는 키 스트레칭 패스워드 전용 해시 함수(Argon2id, PBKDF2, bcrypt) 필수 채택.
- Merkle-Damgard 구조의 길이 확장 공격(Length Extension Attack) :
  - 한계점 : $H(secret \parallel message)$ 형태로 단순 메시지 인증을 구현할 경우, 공격자가 비밀키를 몰라도 뒤에 새로운 악성 데이터를 덧붙여 유효한 새 해시값 조작 가능.
  - 해결 방안 : 단순 결합 해시를 금지하고, 내부 키와 외부 키로 이중 해싱하는 표준 메시지 인증 코드인 HMAC(RFC 2104) 또는 SHA-3 적용.
- 양자 컴퓨터(Grover 알고리즘)에 의한 충돌 및 역상 저항성 반감 :
  - 한계점 : Grover의 양자 탐색 알고리즘을 사용하면 충돌 저항성 복잡도가 $2^{n/3}$, 역상 저항성이 $2^{n/2}$로 대폭 축소되어 128비트 해시는 안전성 상실.
  - 해결 방안 : 양자 컴퓨팅 시대에 대비하여 최소 256비트(SHA-256) 이상, 장기 기밀의 경우 384/512비트(SHA-384, SHA-512) 해시 함수 강제 채택.

## Ⅴ. 해시 알고리즘(Hash Algorithm) 적용 및 발전을 위한 기술사적 제언

- 사용자 비밀번호 저장 시 Salt + Argon2id 채택 표준화 : KISA 및 NIST 비밀번호 가이드라인에 따라 사용자마다 고유한 암호학적 Salt(16바이트 이상)를 부여하고 메모리 경합 기반 Argon2id 알고리즘 적용.
- 블록체인 및 무결성 검증의 하이브리드 해시 파이프라인 구성 : 비트코인 등에서 사용하는 SHA-256 이중 해싱(Double SHA-256) 기법을 활용하여 길이 확장 공격을 방어하고 무결성 신뢰도 극대화.
- 레거시 시스템 내 MD5 및 SHA-1 알고리즘 전수 제거(Zero Legacy Hash) : 소스코드 정적 분석 도구(SAST)를 가동하여 사내 인증 및 무결성 검증 로직에 잔존하는 MD5, SHA-1 코드를 식별하고 SHA-256 이상으로 전면 교체.
