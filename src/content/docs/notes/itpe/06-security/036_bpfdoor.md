## Ⅰ. BPFdoor(Berkeley Packet Filter door)의 개요

- **개념** : 리눅스 및 유닉스 운영체제의 커널 패킷 필터링 기술인 BPF(Berkeley Packet Filter)와 원시 소켓(Raw Socket)을 악용하여, 시스템에 개방 포트(Listening Port)를 열지 않고 잠복하다가 사전에 정의된 특정 매직 패킷(Magic Packet)을 수신하면 원격 리버스 셸(Reverse Shell)을 활성화하는 고도화된 스텔스 백도어.
- **배경 및 필요성** : 통신사, 금융망, 정부 공공 인프라를 표적으로 삼아 수년간 탐지되지 않고 은닉 잠복한 고도 표적형(APT) 악성코드로, 전통적인 포트 스캐닝 및 방화벽 통제를 완전히 무력화하며 등장.
- **핵심 목적** : 네트워크 경계 및 호스트 방화벽 우회 메커니즘 규명, 커널 시스템 콜 감시 체계 수립 및 eBPF 기반 스텔스 백도어 탐지 역량 확보.

## Ⅱ. BPFdoor(Berkeley Packet Filter door)의 핵심 아키텍처 및 동작 메커니즘

BPFdoor는 `AF_PACKET` 원시 소켓을 생성하고 BPF 바이트코드를 필터로 등록하여 로컬 방화벽(iptables) 이전의 네트워크 드라이버 단에서 패킷을 스니핑한 후 매직 바이트 검증을 거쳐 동적으로 리버스 셸을 수립함.

```text
[ BPFdoor의 스텔스 동작 메커니즘 및 침해 흐름 ]

  [ 외부 공격자 (C2) ]
           │
           ▼ 1. 매직 패킷(Magic Packet) 전송 (ICMP, UDP 또는 TCP 패킷 내 암호화 키 삽입)
  +-------------------------------------------------------------+
  | 희생자 리눅스 서버 (네트워크 인터페이스 드라이버)          |
  |  - 정상적인 리스닝 포트 없음 (netstat / lsof로 탐지 불가!)    |
  +------------------------------┬------------------------------+
                                 │
         ┌───────────────────────┴───────────────────────┐
         │ 2. 패킷 복사 (프로미스큐어스 모드)             │
         ▼                                               ▼
  [ BPF 커널 필터 (AF_PACKET 소켓) ]           [ 로컬 호스트 방화벽 (iptables) ]
  - 커널 수준에서 패킷 가로챔                   - BPFdoor 패킷을 단순 드롭 처리
  - 매직 바이트 시그니처 일치 검증               (방화벽이 차단해도 BPF는 이미 수신!)
         │
         ▼ 3. 매직 바이트 일치 확인 성공
  +-------------------------------------------------------------+
  | BPFdoor 사용자 공간 프로세스 (/sbin/udevd 위장)              |
  |  - Step A: iptables에 공격자 IP 허용 임시 룰 동적 삽입      |
  |  - Step B: 공격자 C2 서버로 아웃바운드 리버스 셸 연결        |
  |  - Step C: 세션 종료 즉시 iptables 룰 삭제 및 흔적 인멸      |
  +-------------------------------------------------------------+
```

- **리스닝 포트 부재(Portless Backdoor)** : `bind()` 및 `listen()` 시스템 콜을 호출하지 않고 `SOCK_RAW`로 패킷을 스니핑하므로 Nmap 등 외부 포트 스캔으로 탐지 불가.
- **로컬 방화벽(iptables) 우회** : 리눅스 네트워킹 스택 상 BPF는 Netfilter(iptables) 방화벽 체인보다 먼저 패킷을 복사하므로 방화벽 차단 정책 무력화.
- **동적 iptables 조작** : 패킷 수신 시 일시적으로 로컬 방화벽에 허용 룰을 삽입하고, 리버스 셸 통신 종료 즉시 룰을 삭제하여 안티포렌식 구현.
- **프로세스명 및 타임스탬프 위장** : `prctl(PR_SET_NAME)`을 통해 프로세스명을 `/sbin/udevd`, `auditd` 등 정상 시스템 데몬으로 위장하고 타임스탬프 변조(Timestomp).

## Ⅲ. BPFdoor(Berkeley Packet Filter door)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 전통적 백도어 (Netcat, Meterpreter) | BPFdoor 스텔스 백도어 | 탐지 및 방어 엔지니어링 |
| --- | --- | --- | --- |
| 포트 개방 여부 | 특정 포트 개방 (LISTEN 상태 유지) | 포트 미개방 (Raw Socket 스니핑) | 리스닝 포트 검사 무용, 프로미스큐어스 감시 |
| 네트워크 감지 | 외부 포트 스캔(Nmap)으로 즉각 탐지 | 포트 스캔으로 감지 불가 | `setsockopt(SO_ATTACH_FILTER)` 시스템콜 추적 |
| 방화벽 차단 | 호스트 인바운드 방화벽에 차단됨 | iptables 앞단에서 패킷 복제 | 경계 네트워크 NIDS에서 매직 패킷 시그니처 탐지 |
| 프로세스 은닉 | 비정상 프로세스명 노출 빈번 | 정상 시스템 데몬으로 완벽 위장 | 실행 바이너리 경로(`/dev/shm`) 및 프로세스 환경 검사 |
| 명령 제어 | C2와 지속적 TCP 세션 유지 (비콘) | 평시 무통신, 매직 패킷 수신 시만 동작 | 비정상 아웃바운드 리버스 셸 트래픽 모니터링 |

- BPFdoor는 리눅스 커널의 네트워크 아키텍처 특성을 악용하여 전통적인 호스트 보안 진단 체계를 무력화한 지능형 악성코드로, 커널 이벤트 추적 없이는 탐지가 불가능함.

## Ⅳ. BPFdoor(Berkeley Packet Filter door)의 주요 한계점 및 해결 방안

- **표준 시스템 진단 도구(netstat, ss, lsof)의 완전한 무력화** :
  - **한계점** : 보안 관제 요원이 감염 서버에 접속하여 네트워크 상태를 점검해도 열린 포트가 전혀 보이지 않아 침해 사실을 인지하지 못함.
  - **해결 방안** : 네트워크 인터페이스의 프로미스큐어스(Promiscuous) 모드 활성화 플래그(`ip link` PROMISC 확인) 및 Raw 소켓 열거 도구 전사 실행.
- **임시 파일시스템(/dev/shm)을 악용한 디스크 쓰기 방지 및 휘발** :
  - **한계점** : 공격자가 악성 바이너리를 공유 메모리 공간(`/dev/shm`, `/run`)에 두고 실행한 후 파일을 삭제하여 정적 디스크 포렌식 증적 인멸.
  - **해결 방안** : 시스템 파티션 마운트 시 `/dev/shm` 및 `/tmp` 영역에 대해 `noexec, nosuid, nodev` 마운트 옵션을 강제하여 메모리 파일 실행 원천 차단.
- **정상 시스템 데몬 위장으로 인한 시그니처 백신 탐지 실패** :
  - **한계점** : 프로세스명이 `/sbin/udevd -d`로 표시되고 부모 프로세스가 init(PID 1)으로 되어 있어 프로세스 목록 검사 우회.
  - **해결 방안** : 프로세스의 실제 실행 파일 링크(`/proc/<PID>/exe`)가 가리키는 실제 바이너리 해시를 검증하고 YARA 룰 기반 메모리 스캐닝 적용.

## Ⅴ. BPFdoor(Berkeley Packet Filter door) 적용 및 발전을 위한 기술사적 제언

- **eBPF 기반 런타임 보안 도구(Tetragon, Falco) 도입** : BPFdoor가 호출하는 `socket(AF_PACKET)` 및 `setsockopt` 커널 시스템 콜 이벤트를 실시간 후킹하여 무인가 원시 소켓 생성 즉시 차단.
- **아웃바운드 엄격 통제(Egress Filtering) 강화** : 내부 서버에서 인터넷 C2로 나가는 비인가 아웃바운드 TCP/UDP 연결을 외곽 게이트웨이에서 기본 차단(Default Deny) 정책 수립.
- **Linux 감사 데몬(auditd) 룰셋 고도화** : 시스템 내 iptables 명령어 호출, 네트워크 네임스페이스 변경, 프로세스 명칭 변경 이벤트를 실시간 감사 로그로 영구 기록.
