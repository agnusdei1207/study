```text
[BPFdoor] ◀━━ 머리: Ⅶ 내 의견 (포트 오픈 없는 은닉 백도어 차단 → eBPF 기반 커널 감사 및 원시 소켓 바인딩 통제)
 ┃
 ┣━ Ⅰ 개요 ───── 전통적 리눅스 방화벽(iptables)을 완벽히 우회하는 지능형 스텔스 백도어 → 리눅스 커널 BPF를 악용한 수동적 감청
 ┣━ Ⅱ 특징 ───── 열린 포트(Listening Port) 부재 · 방화벽 우회 · 패킷 스니핑 기반 활성화(Magic Packet) · 메모리 상주 은닉
 ┣━ Ⅲ 구조 ───── 원시 소켓(Raw Socket) 바인딩 · BPF 바이트코드 필터 · 매직 패킷 파서 · 리버스 쉘 생성 모듈
 ┣━ Ⅳ 흐름 ───── ① 원시 소켓으로 모든 유입 패킷 감청 → ② 매직 패킷(비밀 패스워드) 식별 → ③ 로컬 방화벽에 송신자 IP 임시 허용 → ④ 역방향 리버스 쉘 연결
 ┣━ Ⅴ 비교 ───── 전통 백도어(특정 포트 개방, netstat 노출) vs BPFdoor(포트 미개방, BPF 패킷 필터링으로 스텔스 대기)
 ┗━ Ⅵ 실무 ───── netstat/lsof 명령어로 탐지 불가 / eBPF/Falco를 통한 커널 레벨 원시 소켓 감시 / 프로세스 메모리 무결성 검증
```

## 한 줄 본질
- 리눅스 커널의 네트워크 패킷 필터링 기술(BPF)을 악용하여, 시스템에 어떤 포트도 열지 않고 원시 소켓으로 유입 패킷을 은밀히 감청하다가 특정 매직 패킷 수신 시에만 리버스 쉘을 열어주는 스텔스 악성코드 → 완벽한 은닉 침투 달성 / 원시 소켓 시스템 콜 감시 시 탐지 가능

## 핵심 그림
```text
[BPFdoor의 포트 미개방(Stealth) 및 매직 패킷 활성화 메커니즘]

  [ 외부 공격자 ] ──(임의의 패킷 전송: 매직 문자열 포함)──> [ 방화벽 (iptables) ]
                                                                   │ 통과/차단 무관
                                                                   ▼ (커널 레벨 복제)
                                                      ┌─────────────────────────┐
                                                      │ 리눅스 커널 네트워크 스택│
                                                      │  - BPF 필터링 드라이버 │
                                                      └────────────┬────────────┘
                                                                   │ 원시 소켓(Raw Socket)
                                                                   ▼ 감청
                                                      ┌─────────────────────────┐
                                                      │ BPFdoor 데몬 프로세스    │
                                                      │ (netstat에 포트 안 뜸)  │
                                                      └────────────┬────────────┘
                                                                   │ 매직 패킷 일치 확인
                                                                   ▼
                                                      [ 외부 공격자에게 리버스 쉘 연결 ]
```

## 핵심 용어
- BPF(Berkeley Packet Filter): 커널 공간에서 사용자 공간으로 패킷을 복사하기 전에 고속으로 필터링하기 위해 개발된 커널 가상머신 메커니즘 (tcpdump의 핵심 기반)
- 매직 패킷(Magic Packet): 잠자고 있는 BPFdoor 프로세스를 깨우기 위해 공격자가 패킷 페이로드 내부에 심어둔 특정 시그니처 문자열 및 암호화된 명령어

## 핵심 통찰
- 일반적인 백도어는 외부 접속을 기다리기 위해 특정 포트(예: 4444)를 리슨(Listen)해야 하므로 `netstat -tlpn` 명령으로 즉시 발각되지만, BPFdoor는 포트를 전혀 열지 않아 프로세스 목록만으로 탐지가 불가능함
- 리눅스 로컬 방화벽(iptables) 앞단에서 커널 드라이버가 패킷을 복제해 BPFdoor 원시 소켓으로 전달하므로, 방화벽이 외부 인바운드를 모두 차단하고 있어도 패킷 감청이 가능함
- 매직 패킷이 수신되면 BPFdoor는 로컬 iptables 규칙을 일시 수정하여 공격자 IP를 허용하고 리버스 쉘을 공격자에게 아웃바운드로 연결함

## 이웃 토픽과 구분
- BPFdoor vs 루트킷(Rootkit): 루트킷 = 커널 함수(syscall) 테이블을 직접 후킹하여 파일/프로세스를 숨김 / BPFdoor = 합법적인 BPF 원시 소켓 기능을 악용하는 사용자 영역 데몬

## 문제·원인·대책
- 사례: 137회 기출 통신사 및 정부 서버에 수년간 잠복하여 감시망을 회피해 온 지능형 BPFdoor 침해 사건
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 포트 스캔 및 일반 EDR 백신으로 탐지 불가 | 포트를 열지 않고 커널 BPF 패킷 스니핑 방식 활용 | Falco/Tracee 등 eBPF 기반 커널 모니터링으로 `AF_PACKET` 원시 소켓 생성 감시 | 원시 소켓 비인가 바인딩 즉각 적발 |
| 공격자에게 나가는 아웃바운드 리버스 쉘 미탐지 | 내부에서 외부로 나가는 모든 아웃바운드 트래픽 허용 | 아웃바운드 방화벽 화이트리스트 강제 및 비인가 외부 세션 즉시 차단 | 외부 C2 리버스 쉘 연결 통로 차단 |
