## 지식 로드맵 내 현재 위치

악성코드·침해분석 → Linux 백도어 → BPFdoor

## 30초 인출

- **본질:** **BPFdoor**는 Linux 패킷 필터와 소켓을 악용하는 은닉형 백도어
- **메커니즘:** 수신 패킷의 매직 조건 감시 → 일치 시 셸·명령 채널 활성화
- **탐지:** 포트 개방 여부뿐 아니라 BPF 필터·패킷 소켓·프로세스·네트워크 행위의 상관분석

<details>
<summary>핵심 용어</summary>

- **BPFdoor:** Linux 패킷 감시 기능을 이용해 특정 패킷 조건에서 원격 명령 채널을 여는 백도어 악성코드
- **BPF (Berkeley Packet Filter):** 패킷에 필터 조건을 적용해 관찰·처리하는 패킷 필터 기술
- **AF_PACKET:** Linux에서 링크 계층 패킷을 다루는 소켓 주소군
- **SOCK_RAW:** 링크·네트워크 계층 패킷에 접근하는 원시 소켓 유형
- **SOCK_DGRAM:** 패킷 데이터를 데이터그램 형태로 전달하는 소켓 유형
- **매직 패킷(magic packet):** 악성코드가 사전에 정한 바이트 조건을 확인하는 트리거 패킷
- **바인드 셸(bind shell):** 감염 호스트가 연결을 기다리는 방식의 원격 셸
- **리버스 셸(reverse shell):** 감염 호스트가 원격 제어자 쪽으로 연결을 여는 방식의 셸
- **C2 (Command and Control):** 감염 시스템에 명령을 전달하고 상태를 관리하는 통신·제어
</details>

### Ⅱ. 트리거와 은닉 흐름

```text
패킷 소켓·BPF 필터 감시
          ↓
수신 패킷에서 매직 조건 검사
       ┌──┴──┐
     불일치  일치
       ↓      ↓
   감시 지속  셸·명령 채널 활성화
```

| 관찰점 | 보안상 의미 |
|---|---|
| 수신 포트 | 리스닝 서비스 목록만으로 탐지하기 어려운 변종 가능성 |
| 필터·소켓 | 승인되지 않은 프로세스의 BPF 필터·패킷 소켓 사용 여부 |
| 실행 흔적 | 매직 패킷 직후의 프로세스·외부 연결·명령 실행 변화 |

**제언:** 정상 패킷 도구의 기준선을 마련하고 필터·소켓·프로세스 행위의 변화를 함께 감시

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **BPFdoor**는 Linux 패킷 필터·소켓 감시를 악용해 특정 트리거 패킷에 반응하는 백도어 |
| 목적 | 전형적인 수신 포트 개방을 드러내지 않고 원격 명령 실행 경로 확보 |

```text
원격 제어자
    ↓ 매직 패킷 전송
감염 호스트의 패킷 소켓·BPF 필터
    ↓ 조건 일치
바인드 셸 또는 리버스 셸 활성화
    ↓
명령 실행·상태 통신
```

공개된 변종 분석에서 필터·소켓 유형과 연결 방식의 차이가 확인되므로, 단일 IOC나 포트 규칙에 의존하지 않는 점검 필요.

## Ⅱ. 은닉 특성과 침해 징후

| 특성 | 점검 관점 |
|---|---|
| 비전형적 패킷 대기 | 승인되지 않은 `AF_PACKET` 소켓과 BPF 필터 부착 프로세스 |
| 리스닝 포트 비노출 가능 | 소켓·커널 이벤트와 네트워크 흐름을 함께 확인 |
| 프로세스 위장·메모리 실행 가능 | 실행경로·해시·명령행·메모리 맵·삭제된 실행파일 조사 |
| 정상 관리도구와 기능 중첩 | 실행 주체·변경 이력·업무시간·승인 기록 대조 |

## Ⅲ. 탐지 기준과 정상 사용 구분

| 분석 항목 | 악용 의심 단서 | 오탐 구분 자료 |
|---|---|---|
| BPF·패킷 소켓 | 비인가 프로세스의 필터 부착·비정상 수신 대기 | 승인된 진단·보안도구 목록과 실행 계정 |
| 프로세스 | 시스템 데몬으로 위장한 경로·삭제된 실행파일 | 패키지 서명·기준 이미지·실행 경로 |
| 네트워크 | 특이 패킷 이후 발생한 셸·외부 연결 | 관리 통신·정비 작업 승인기록 |
| 지속성 | 비정상 자동실행·계정·설정 변경 | 변경관리 기록과 알려진 배포 설정 |

## Ⅳ. 식별·격리·복구

```text
필터·소켓·프로세스·네트워크 징후 수집
                 ↓ 상관분석
         감염 범위·진입경로 확인
                 ↓
증거 보존 후 통신·계정 격리
                 ↓
지속성 제거·자격증명 교체·신뢰 이미지 복구
                 ↓
패치·접속경계 보완 후 운영 재개
```

| 단계 | 핵심 조치 |
|---|---|
| 식별 | 엔드포인트·커널 감사와 네트워크 흐름의 시간축 대조 |
| 격리 | 증거 보존을 우선하고 감염 호스트·관련 계정의 통신 제한 |
| 근절·복구 | 지속성·초기 침투 경로 제거, 신뢰 가능한 이미지와 검증된 백업으로 복구 |
| 재발 방지 | 불필요한 BPF·원시 패킷 권한과 원격 접근경로 축소 |

## Ⅴ. 한계와 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 알려진 해시·포트·고정 문자열만 사용하면 변종의 필터·소켓 변경과 새 트리거를 놓칠 수 있음 | 정상 패킷도구 기준선 위에 소켓 유형·필터 부착·프로세스 정체성·후속 네트워크 행위를 묶은 행위기반 탐지 규칙을 설계하고 변종 시험으로 보완 |
| 시스템마다 합법적인 패킷 캡처 사용이 달라 단일 패턴 경보는 오탐을 높일 수 있음 | 업무별 승인도구·계정·호스트를 기준정보로 관리하고 예외의 소유자·만료일을 함께 검토 |
