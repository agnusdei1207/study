# 파일카빙(File Carving)

## 핵심 개념
- 파일 시스템의 메타데이터(FAT, MFT, Inode 등 파일 이름, 크기, 위치 정보)가 손상되거나 삭제된 상태에서, 저장 매체의 비할당 영역(Unallocated Space)이나 원시 바이트 스트림(Raw Data)을 직접 탐색하여 파일 고유의 시그니처와 구조를 바탕으로 파일을 복원하는 디지털 포렌식 기술.
- 파일의 시작을 나타내는 헤더(Header) 시그니처, 끝을 나타내는 푸터(Footer) 시그니처, 내부 구조적 특성을 활용하여 조각난 데이터를 추출(Carving).

```
+-------------------------------------------------------------+
|                      파일카빙 핵심 원리                        |
+-------------------------------------------------------------+
| [ 비할당 영역 원시 데이터 스트림 ]                            |
|  ... 00 FF D8 FF E0 ... [파일 본문 데이터] ... FF D9 00 12 ...|
|         ^                                      ^            |
|         |-- 헤더 시그니처 (JPEG 시작)            |-- 푸터 시그니처|
|         +============== 카빙 복원 파일 ============+            |
+-------------------------------------------------------------+
```

## 파일카빙 주요 기법 분류

```
+-------------------------------------------------------------+
|                     파일카빙 기술 4대 분류                    |
+-------------------------------------------------------------+
| 1. 시그니처 기반 (헤더-푸터) | 매직 넘버(Magic Number) 패턴 매칭|
| 2. 파일 크기 기반           | 헤더 시그니처 + 헤더 내 명시된 크기 필드 |
| 3. 파일 구조 기반           | 청크(Chunk), 태그, 트리 구조 파싱 복원 |
| 4. 통계/의미론적 카빙       | 엔트로피 분석, 인접 바이트 통계적 일치도 |
+-------------------------------------------------------------+
```

### 1. 헤더-푸터 기반 카빙 (Header-Footer Carving)
- 파일의 시작 매직 바이트(예: JPEG `FF D8 FF`, PDF `%PDF`)를 검색하고, 이후 연속된 바이트 중 해당 파일의 종료 매직 바이트(예: JPEG `FF D9`, PDF `%%EOF`)를 찾아 그 사이의 데이터를 추출.
- *한계*: 푸터가 존재하지 않는 파일 포맷(예: BMP, WAV)이나 파일이 여러 클러스터에 불연속적으로 단편화(Fragmentation)된 경우 복원 오류 발생.

### 2. 파일 크기 기반 카빙 (Header-Size Carving)
- 파일 헤더 내부에 전체 파일 크기가 명시되어 있는 파일 포맷(예: PNG, ZIP, BMP)을 대상으로, 헤더를 찾은 후 크기 필드에 기록된 바이트 수만큼 일괄 추출.

### 3. 파일 내부 구조 기반 카빙 (File Structure-based Carving)
- 파일 내부가 청크(Chunk) 구조(PNG의 IHDR-IDAT-IEND 청크)나 태그 기반 포맷(TIFF, XML)으로 구성된 경우, 내부 토큰 및 블록의 유효성을 검증하며 체계적으로 데이터 복원.

### 4. 시맨틱/통계적 기반 카빙 (Semantic / Statistical Carving)
- 푸터나 구조 정보가 부족하거나 텍스트/실행 파일인 경우, 바이트 엔트로피(Entropy), 문자 출현 빈도, 바이트 간 전이 확률(Markov Chain)을 계산하여 파일의 경계를 식별.

## 대표적인 파일 형식별 매직 넘버(시그니처)

| 파일 형식 | 헤더 시그니처 (Hex) | 푸터 시그니처 (Hex) | 특징 |
|---|---|---|---|
| **JPEG** | `FF D8 FF E0` (또는 `E1`) | `FF D9` | 사진, 이미지 복원의 기본 |
| **PNG** | `89 50 4E 47 0D 0A 1A 0A` | `49 45 4E 44 AE 42 60 82` | IEND 청크로 종료 |
| **GIF** | `47 49 46 38 37 61` (`39a`) | `00 3B` | 애니메이션 이미지 |
| **PDF** | `25 50 44 46` (`%PDF`) | `25 25 45 4F 46` (`%%EOF`) | 문서 포렌식 핵심 |
| **ZIP** | `50 4B 03 04` | `50 4B 05 06` | 압축 파일 및 MS Office(docx, xlsx) |
| **Windows PE**| `4D 5A` (`MZ`) | 푸터 없음 (PE 헤더 크기 참조) | 실행 파일(exe, dll) |

## 단편화(Fragmentation) 파일 카빙과 해결 과제

```
[비단편화 파일 (연속 할당)]
[헤더 블록] ====> [본문 블록 1] ====> [본문 블록 2] ====> [푸터 블록] (복원 용이)

[단편화 파일 (불연속 할당)]
[헤더 블록] ====> [타 파일 데이터] ====> [본문 블록 1] ====> [푸터 블록] (정상 복원 불가)
```

- **단편화 문제점**: 디스크에 파일이 연속적으로 쓰이지 않고 조각나 있을 때, 단순 헤더-푸터 카빙을 수행하면 중간에 끼어든 타 파일의 쓰레기 데이터가 포함되어 파일 손상(Corrupted File) 발생.
- **고도화 카빙 기술**:
  - **Bifragment Gap Carving**: 누락된 단편의 크기를 추정하고 비할당 공간 내 후보 블록들의 조합을 전수 대조.
  - **스마트 카빙(Smart Carving)**: 압축 알고리즘(Deflate 등)의 디컴프레션 검증 루틴을 통과하는 블록 조합만 선별하여 재조합.
  - **머신러닝 기반 블록 분류**: CNN/RNN 또는 딥러닝 모델을 활용하여 개별 4KB 섹터 블록이 어떤 파일 유형(텍스트, JPEG, 오디오 등)인지 통계적으로 사전 분류 후 연결.

## 결론 및 실무 시사점
- 파일카빙은 메타데이터가 완전히 파괴된 안티 포렌식 환경이나 포맷된 드라이브에서 결정적 증거를 인양하는 핵심 기법임.
- 대용량 저장 장치와 빈번한 단편화 환경에서는 복원 정확도와 연산 복잡도 사이의 균형이 요구되며, 스마트 카빙 및 인공지능 기반 블록 매칭 기법의 적용이 필수적임.
