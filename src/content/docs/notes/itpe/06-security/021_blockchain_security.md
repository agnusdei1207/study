- **본질:** **블록체인 보안**은 분산원장·합의·네트워크·응용계층의 자산과 거래를 보호하는 활동
- **메커니즘:** 계층별 신뢰경계의 결함이 거래 합의, 키 관리, 컨트랙트 실행에 서로 다른 위험을 만듦
- **방향:** 합의·피어·오라클·컨트랙트·지갑을 각각 점검하고 상호 연계된 위험을 관리

- **블록체인 보안:** 분산원장과 그 합의·연계·응용 구성요소의 기밀성·무결성·가용성 및 자산을 보호하는 통제
- **합의 공격:** 합의 규칙이나 참여자 권한의 취약점을 이용해 블록 생성·거래 확정에 영향을 주는 공격
- **이클립스 공격(Eclipse attack):** 특정 노드의 피어 연결을 장악해 그 노드가 보는 네트워크 정보를 왜곡하는 공격
- **스마트 컨트랙트:** 블록체인에서 조건에 따라 실행되는 프로그램으로, 코드·권한·외부 입력의 결함이 자산에 영향을 줄 수 있는 대상
- **오라클:** 블록체인 밖의 데이터를 컨트랙트에 전달하는 구성요소
- **개인키:** 거래·메시지에 서명하는 비밀값으로, 유출 시 권한 도용 위험이 발생하는 자산

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **블록체인 보안**은 분산원장·합의·네트워크·응용계층의 자산과 거래를 보호하는 활동 |
| 목적 | 거래 무결성과 서비스 가용성을 지키고 키·컨트랙트 결함에 따른 자산 피해를 줄이는 것 |

### Ⅱ. 계층별 위협과 통제

| 계층 | 대표 위협 | 대응 초점 |
|---|---|---|
| 네트워크·P2P | 시빌·이클립스 | 피어 다양성·노드 정보 검증 |
| 합의·검증 | 지분·해시파워 집중, 검증자 권한 오용 | 합의 규칙·집중도·확정성 위험 점검 |
| 컨트랙트·오라클 | 코드 결함, 외부 데이터 조작 | 코드 검토·시험, 입력 출처 확인 |
| 지갑·키 | 개인키 탈취·피싱 서명 | 키 보호·다중승인·거래 검토 |

**제언:** 원장 무결성만을 전체 보안으로 간주하지 말고 계층별 권한·코드·키 통제를 함께 점검

---
## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **블록체인 보안**은 분산원장·합의·네트워크·응용계층의 자산과 거래를 보호하는 활동 |
| 목적 | 거래 무결성과 서비스 가용성을 지키고 키·컨트랙트 결함에 따른 자산 피해를 줄이는 것 |

블록의 해시 연결과 합의는 거래 기록의 변조를 어렵게 하는 설계요소이며, 지갑·컨트랙트·오라클의 안전까지 자동 보장하지는 않음.

## Ⅱ. 계층과 신뢰경계

| 계층 | 보호 대상 | 보안 경계 |
|---|---|---|
| 네트워크 | 노드 연결·전파 정보 | 피어·통신 경로 |
| 합의·원장 | 거래 순서·블록 확정 | 합의 규칙·검증 권한 |
| 응용 | 컨트랙트·오라클 입력 | 코드·관리 권한·외부 데이터 |
| 사용자 자산 | 지갑·서명 키 | 기기·키 보관·승인 절차 |

```text
사용자·지갑 ──서명──> 응용·컨트랙트 <──외부값── 오라클
                         │
                         ↓ 거래 요청
                  합의·원장 기록
                         │
                         ↓ 전파·검증
                    P2P 노드
```

## Ⅲ. 합의·네트워크 위협

| 공격 | 작동·영향 | 방어 초점 |
|---|---|---|
| 합의 권한 집중 | 특정 합의 방식의 참여 권한이 집중되면 거래 검열·재구성 위험 증가 | 합의 설계에 따른 권한 분포·확정성·재구성 징후 점검 |
| 시빌 공격 | 다수의 가짜 신원으로 피어·투표 관점을 왜곡 | 참여자 인증·자원비용·다양한 정보원 검토 |
| 이클립스 공격 | 한 노드의 연결을 장악해 수신 정보 제한·왜곡 | 피어 다양성·독립 경로·비정상 연결 탐지 |

‘51% 공격’은 주로 작업증명(PoW) 해시파워 과반 장악을 가리키는 통용 표현이며, 실제 영향은 프로토콜 규칙에 따름. 지분증명 등 다른 합의에 동일 비율을 그대로 적용하지 않음.

## Ⅳ. 컨트랙트·키 위협

| 대상 | 취약점 예 | 통제 |
|---|---|---|
| 스마트 컨트랙트 | 재진입, 권한검사 오류, 경제적 논리 결함 | 설계 검토·정적분석·테스트·독립 감사 |
| 오라클 | 외부 데이터 조작·단일 원천 장애 | 출처·갱신시각 검증, 다중 원천·이상치 확인 |
| 개인키·지갑 | 키 탈취·피싱 서명·과도한 승인 | 안전한 키 보관, 거래 내용 검토, 다중승인·출금 분리 |

```text
배포 전: 설계·권한 검토 → 코드 시험·감사 → 제한된 배포
                                      ↓
운영 중: 키·오라클·거래 감시 → 이상 시 일시중지·사고대응
```

## Ⅴ. 한계와 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 원장의 무결성을 전체 서비스의 안전성과 혼동 | 합의·컨트랙트·오라클·지갑을 별도 자산과 신뢰경계로 모델링해 검증 |
| 탈중앙화 구조에서 변경·복구 권한과 책임이 불명확 | 긴급정지·업그레이드·키 복구의 권한·승인·감사 조건을 설계 단계에서 명시 |
