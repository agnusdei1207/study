## 지식 로드맵 내 현재 위치

분산시스템 보안 → 분산원장 → 블록체인 계층별 보안 및 스마트 컨트랙트 보호

## 30초 인출

- **본질:** 분산 네트워크의 합의 메커니즘, 암호학적 원장, 스마트 컨트랙트, 사용자 지갑 생태계 전반의 자산 및 거래 신뢰성을 보장하는 다계층 보안 체계
- **메커니즘:** P2P 통신 방어 → PoW/PoS 합의 무결성 검증 → 스마트 컨트랙트 상태 전이 통제 → 오프체인 오라클 연계 무결성 보장
- 통찰: 배포 후 수정 불가능한 불변성 딜레마와 플래시론 오라클 조작을 극복하기 위해 UUPS 업그레이더블 프록시 패턴과 TWAP 시간가중 오라클 도입 필수

<details>
<summary>핵심 용어</summary>

- **51% 공격 (Double Spending):** 특정 집단이 전체 네트워크 해시레이트(PoW) 또는 스테이킹 지분(PoS)의 과반을 장악하여 거래를 변조하거나 이중 지불을 실행하는 공격
- **이클립스 공격 (Eclipse Attack):** 악의적인 노드들이 특정 희생자 노드의 모든 P2P 피어 연결을 독점 장악하여 고립시키고 잘못된 블록 정보를 주입하는 네트워크 계층 공격
- **시빌 공격 (Sybil Attack):** 단일 공격자가 수많은 가짜 식별자(노드)를 생성하여 네트워크 평판 시스템이나 분산 투표 결과를 왜곡하는 공격
- **오라클 문제 (Oracle Problem):** 블록체인 외부의 실세계 데이터(환율, 주가, 날씨 등)를 온체인으로 가져오는 과정에서 발생하는 데이터 신뢰성 및 조작 위험
- **플래시 론 (Flash Loan):** 단일 블록 트랜잭션 내에서 무담보로 대규모 자금을 차입하고 상환하는 디파이 서비스로, 가격 오라클 조작 공격의 레버리지로 악용
</details>

## 2~4교시 예상문제 (25점)

> 블록체인의 4계층 아키텍처(네트워크, 합의, 스마트 컨트랙트, 애플리케이션)별 주요 보안 위협을 설명하고, 디파이(DeFi) 생태계의 오라클 조작 및 재진입 취약점에 대응하기 위한 엔지니어링 방안을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **블록체인 보안(Blockchain Security)** 은 분산 P2P 네트워크, 분산 합의 알고리즘, 암호화 원장, 스마트 컨트랙트 가상머신(EVM), 오프체인 연계 시스템 전반의 기밀성·무결성·가용성을 보장하는 엔지니어링 체계 |
| 목적 | 51% 이중 지불 방지, 스마트 컨트랙트 결함에 의한 자산 탈취 차단, 오라클 조작 방어 및 분산 합의 네트워크의 지속적 가용성 확보 |

블록체인 원장 자체의 불변성이 상위 스마트 컨트랙트의 비즈니스 로직 안전성이나 오프체인 오라클의 진실성을 자동으로 보증하지는 않음.

## Ⅱ. 블록체인의 특징 및 4계층 보안 모델

| 계층 (Layer) | 주요 구성요소 | 핵심 보안 목표 및 고려사항 |
|---|---|---|
| **1. 애플리케이션/지갑 계층** | 사용자 지갑, DApp 프론트엔드, API | 개인키 탈취 방지, 니모닉 보존, 웹 프론트엔드 피싱 차단 |
| **2. 스마트 컨트랙트 계층** | Solidity 코드, EVM, DeFi 프로토콜 | 재진입 공격 방지, 정수 오버플로 방지, 비즈니스 로직 무결성 |
| **3. 합의 계층 (Consensus)** | PoW, PoS, PBFT, Raft | 51% 공격 저항성, 비잔틴 결함 허용(BFT), 롱 레인지 공격 방어 |
| **4. 네트워크 계층 (Network)** | P2P 프로토콜, Gossip, RPC 노드 | 시빌 공격 방지, 이클립스 격리 차단, DDoS 방어 |

## Ⅲ. 블록체인 계층별 위협 메커니즘 및 공격 흐름

```text
[블록체인 4계층별 공격 벡터 및 플래시론 오라클 공격 메커니즘]

 +---------------------------------------------------------------+
 | 1. 애플리케이션 / 지갑 계층: 피싱 서명, 지갑 개인키 탈취      |
 +-------------------------------+-------------------------------+
                                 | (서명된 트랜잭션 전송)
 +-------------------------------v-------------------------------+
 | 2. 스마트 컨트랙트 계층: 재진입(Reentrancy), 접근제어 결함     |
 |    [플래시론 공격 메커니즘]                                   |
 |    1) 무담보 거액 대출 -> 2) DEX 스왑으로 가격 일시적 폭락 유도 |
 |    -> 3) 타깃 대출 프로토콜 청산 실행 -> 4) 플래시론 상환 완료|
 +-------------------------------+-------------------------------+
                                 | (트랜잭션 실행 결과 반영)
 +-------------------------------v-------------------------------+
 | 3. 합의 계층: 51% 이중지불, Nothing at Stake, 슬래싱 회피      |
 +-------------------------------+-------------------------------+
                                 | (블록 및 트랜잭션 브로드캐스트)
 +-------------------------------v-------------------------------+
 | 4. 네트워크 계층: Sybil 공격, Eclipse 노드 고립, P2P DoS      |
 +---------------------------------------------------------------+
```

### 1. 주요 계층별 위협 상세 분석

| 공격 명칭 | 대상 계층 | 공격 동작 원리 | 방어 통제 기술 |
|---|---|---|---|
| **이클립스 공격** | 네트워크 | 대상 노드의 모든 P2P 슬롯을 공격자 노드로 채워 고립 | 연결 피어 무작위화, 신뢰 피어 화이트리스트 |
| **51% 이중 지불** | 합의 | 과반 해시파워로 프라이빗 체인을 길게 채굴 후 공개하여 기존 체인 재구성(Reorg) | 블록 확정성(Finality) 대기 수 증가, PoS 슬래싱 |
| **재진입 공격** | 컨트랙트 | 상태 변경 전 외부 컨트랙트를 호출하여 출금 함수를 재귀 호출 | Checks-Effects-Interactions 패턴, ReentrancyGuard |
| **플래시론 오라클 조작**| 컨트랙트/응용| 단일 트랜잭션 내 스팟 가격 왜곡으로 비정상 청산 수익 실현 | TWAP(시간가중평균) 오라클, Chainlink 탈중앙 오라클 |

## Ⅳ. 퍼블릭 블록체인 vs 프라이빗/컨소시엄 블록체인 비교

| 비교 항목 | 퍼블릭 블록체인 (Public) | 프라이빗/컨소시엄 블록체인 (Private) |
|---|---|---|
| **참여 자격** | 무허가형 (Permissionless, 누구나 참여) | 허가형 (Permissioned, 사전 승인된 기관만 참여) |
| **합의 알고리즘** | PoW, PoS (확률적 확정성, 경제적 유인) | PBFT, Raft, IBFT (결정론적 즉각 확정성) |
| **네트워크 공격** | 시빌/이클립스/51% 공격 위험 상존 | PKI 신원 인증 기반으로 시빌 공격 원천 차단 |
| **처리 성능 (TPS)** | 낮음 ($15 \sim 수천$ TPS) | 높음 ($수천 \sim 수만$ TPS) |
| **데이터 기밀성** | 원장 전체 공개 (트랜잭션 완전 투명) | 채널 분리, 영지식증명, 접근 통제 적용 용이 |
| **대표 플랫폼** | Bitcoin, Ethereum, Solana | Hyperledger Fabric, R3 Corda |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **스마트 컨트랙트 불변성(Immutability)에 따른 제로데이 패치 불가**<br>이미 메인넷에 배포된 스마트 컨트랙트에 논리적 취약점이나 재진입 버그가 발견되어도 코드를 수정할 수 없어 수천억 원의 자금 유출 방치 | **UUPS 업그레이더블 프록시 패턴 및 Pausable 회로 차단기**<br>상태 저장소(Proxy)와 비즈니스 로직(Implementation)을 분리하는 ERC-1967 UUPS 프록시 패턴을 적용하여 취약점 발생 시 구현 컨트랙트를 교체하고, OpenZeppelin Pausable 모듈을 통해 이상 징후 감지 즉시 다중서명(Multi-sig)으로 계약 기능을 동결 |
| **단일 스팟 가격 오라클 조작을 통한 플래시 론(Flash Loan) 자금 탈취**<br>DEX 풀의 즉각적인 스팟 가격(Spot Price)을 가격 기준으로 삼는 디파이 프로토콜의 취약점을 노려, 플래시론으로 수천만 달러를 일시 스왑하여 담보 비율을 조작 후 프로토콜 자금 드레인 | **탈중앙화 오라클 네트워크(DON) 및 TWAP(시간가중평균가격) 다중화**<br>단일 온체인 풀 가격 대신 Chainlink의 다수 노드가 오프체인 CEX 데이터를 집계한 암호학적 서명 오라클을 사용하고, 유니스왑 V3 TWAP(Time-Weighted Average Price)을 결합하여 단일 블록 내 순간적 가격 왜곡 공격을 수학적으로 무력화 |

## Ⅵ. 제언

```text
[블록체인 스마트 컨트랙트 전 생애주기 보안 아키텍처]

 +--------------------+     +---------------------+     +--------------------+
 | 배포 전 검증       | --> | 배포 후 실시간 모니터| --> | 이상 거래 자동 차단 |
 | 정적분석/정형검증  |     | 온체인 봇 탐지 (Forta)|   | Forta + Pausable   |
 | Slither / Certora  |     | 멤풀(Mempool) 이상감시|     | 30초 내 긴급 정지  |
 +--------------------+     +---------------------+     +--------------------+
```

| 생애주기 단계 | 보안 공학적 조치 | 적용 도구 및 표준 |
|---|---|---|
| **설계 단계** | 최소 권한 접근 제어, 경제적 인센티브 위협 모델링 | OpenZeppelin AccessControl, Threat Modeling |
| **개발/검증 단계** | 정적 분석, 퍼징(Fuzzing), 수학적 정형 검증 | Slither, Foundry, Echidna, Certora Prover |
| **운영/모니터링 단계**| 멤풀(Mempool) 프런트러닝 감시 및 자동 일시정지 | Forta Network, OpenZeppelin Defender, Gnosis Safe |

블록체인 보안은 코드 배포 전의 엄격한 정형 검증뿐만 아니라, 배포 후 온체인 이상 징후를 실시간 감시하여 비상 시 즉각 작동하는 서킷 브레이커 체계 확립 권장.
