## 연관 키워드

- 블록체인 보안, 분산 원장 기술(DLT), 51% 공격, 이중 지불(Double Spending)
- 재진입(Reentrancy), 이클립스 공격(Eclipse Attack), 시빌 공격(Sybil Attack), 무지분 검증(Nothing at Stake)
- 오라클(Oracle), 플래시론(Flash Loan), TWAP, 프록시 패턴(Proxy Pattern), 불변성(Immutability)
- 형식 검증(Formal Verification), MPC, ZKP, MEV, 가상자산사업자(VASP)

## Ⅰ. 블록체인(Blockchain) 보안의 개요

- 핵심 요약 : 합의, 네트워크, 스마트 컨트랙트, 키 관리의 각 계층에서 발생하는 위협을 막는 다계층 보안 체계.
- 개념 : 합의 알고리즘, P2P(Peer-to-Peer) 네트워크, 암호학(해시 함수, 전자서명), 스마트 컨트랙트 계층에서 발생하는 위협(51% 공격, 포크, 로직 취약점, 키 탈취)을 방어하기 위한 종합 보안 아키텍처이며, 기반은 **분산 원장 기술** (DLT, Distributed Ledger Technology)이다.
- 배경 및 필요성 : 블록체인은 위변조가 어렵다고 알려져 있지만, 스마트 컨트랙트 결함, 51% 해시 파워 장악, 개인키 관리 부실로 금융 피해가 이어지고 있어 전 계층의 보안 검증이 필요함.
- 주요 목적 : 합의 무결성 보장, 스마트 컨트랙트 결함 제거, 비인가 자산 탈취 방지, 분산 거버넌스의 신뢰성 확보.

## Ⅱ. 블록체인(Blockchain) 보안의 특징 및 장점

- 핵심 요약 : 계층별 독립 방어, 합의 경제성, 컨트랙트 사전 검증, 분산 키 관리가 결합되어 단일 지점 실패를 줄이는 구조.

1. 계층별 독립 방어 : 네트워크, 합의, 컨트랙트, 지갑 계층에 각각 통제를 둠 → 한 계층이 뚫려도 다음 계층에서 차단.
2. 합의 무결성 : 해시 파워의 **51% 공격** 방지와 지분 기반 페널티로 이중 지불 시도의 비용 상승.
3. 노드 연결 다양화 : 무작위 피어 선택으로 **이클립스 공격** (Eclipse Attack)과 **시빌 공격** (Sybil Attack) 가능성 감소.
4. 컨트랙트 사전 검증 : 정적 분석 도구(Slither), 기호 실행 도구(Mythril), **형식 검증** (Formal Verification)을 조합 → 배포 전에 로직 결함 제거.
5. **MPC** (Multi-Party Computation, 다자간 연산) 기반 키 분산 : 단일 개인키가 유출되어도 자산 전체가 털리지 않도록 서명 권한을 나눔.

## Ⅲ. 블록체인(Blockchain) 보안의 구조 (흐름)

- 핵심 요약 : 네트워크에서 애플리케이션까지 4계층이 쌓이며, 상위 계층일수록 사람의 실수와 연결된 공격이 많음.

```text
[ 블록체인 4계층 보안 구조 ]

4. 애플리케이션·지갑 계층
   피싱, 키 탈취, 악성 서명 승인
-----------------------------------
3. 스마트 컨트랙트 계층
   재진입, 정수 오버플로, 오라클 조작
-----------------------------------
2. 합의 계층
   51% 장악, 무지분 검증, 이기적 채굴
-----------------------------------
1. 네트워크·P2P 계층
   이클립스 공격, 시빌 공격, 라우팅 조작
```

```text
[ 재진입 공격 흐름 ]

공격 컨트랙트가 출금 함수 호출
        ↓
대상 컨트랙트가 잔고 차감 전 송금
        ↓
송금 과정에서 출금 함수 재호출
        ↓
잔고 확인이 통과되어 잔액 반복 인출
```

- **재진입** (Reentrancy) : 잔고를 줄이기 전에 외부 컨트랙트를 다시 호출하도록 만들어 잔액을 반복 인출하는 공격.
- **오라클** (Oracle) : 외부 현실 데이터를 블록체인이 읽을 수 있게 전달하는 연결 장치로, 사람이 쓴 컨트랙트 코드와 함께 가장 취약한 공격 표면이 됨.

## Ⅳ. 블록체인(Blockchain) 보안의 공격 유형 비교

- 핵심 요약 : 공격 유형마다 발생 계층과 메커니즘이 달라 계층별 대응 기술이 대응됨.

| 공격 유형 | 발생 계층 | 공격 메커니즘 | 대표 사례 / 대응 기술 |
| --- | --- | --- | --- |
| 51% 공격 | 합의 계층 | 전체 연산력의 과반을 장악해 이중 지불(Double Spending) 수행 | 이더리움 클래식 연속 침해 / 체크포인트 지정 |
| 재진입 | 스마트 컨트랙트 | 잔고 차감 전 외부 호출을 되풀이해 잔액 탈취 | The DAO 해킹 (약 6,000만 달러 규모) / 재진입 방지 가드 |
| 이클립스 공격 | P2P 네트워크 | 희생자 노드의 이웃 피어를 공격자가 독점해 조작된 블록 주입 | 노드 고립 사례 연구 / 인바운드 피어 수 제한 |
| 오라클 조작 | 데이터 연동 | 플래시론으로 DEX 가격을 왜곡해 청산 유발 | DeFi 다수 침해 / TWAP, 다중 소스 오라클 |
| 프라이빗 키 탈취 | 애플리케이션 | 소스코드 내 키 하드코딩, 피싱, 악성 서명 유도 | Ronin 브릿지 키 유출 / 하드웨어 지갑, MPC |

## Ⅴ. 블록체인(Blockchain) 보안의 한계와 방안

- 핵심 요약 : 배포 후 수정 불가, 무담보 가격 조작, 브릿지 중앙화 검증의 세 한계를 구조 설계로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **불변성** (Immutability)에 따른 패치 난제 | 배포된 컨트랙트에서 취약점이 발견되어도 코드를 고치거나 되돌릴 수 없음 | **프록시 패턴** (Proxy Pattern)으로 로직 컨트랙트를 교체 가능하게 설계하고 비상 정지 함수 구현 | 비상 정지 대응 시간 |
| **플래시론** (Flash Loan) 기반 가격 조작 | 한 블록 안에서 무담보 대출로 DEX(Decentralized Exchange) 가격을 왜곡한 뒤 상환하는 공격 | **TWAP** (Time-Weighted Average Price, 시간 가중 평균 가격) 오라클과 다중 소스 교차 검증 | 가격 편차율 |
| **크로스체인 브릿지** (Cross-chain Bridge) 중앙화 검증 | 검증 노드 몇 개만 탈취되어도 래핑 토큰이 무단 발행됨 | **ZKP** (Zero-Knowledge Proof, 영지식 증명) 기반 무신뢰 브릿지 전환, 출금 시간 지연과 한도 제한 | 검증자 분산도, 출금 한도 준수율 |

## Ⅵ. 블록체인(Blockchain) 보안에 대한 기술사적 제언

- 핵심 요약 : 배포 전 수학적 검증, 온체인 실시간 감시, 사업자 보관 기준을 블록체인 보안의 기본 체계로 제시.

1. 형식 검증 의무화 : 금융·자산 거래 컨트랙트는 배포 전에 수학적 명세와 대조하는 형식 검증 절차를 기준으로 삼는 것이 바람직하다.
2. 온체인 위협 탐지 : 멤풀(Mempool)에서 **MEV** (Maximal Extractable Value, 최대 추출 가능 가치)를 노리는 악성 트랜잭션을 실시간 감시하고, 이상 징후가 잡히면 자금 이동을 자동 정지하는 서킷 브레이커를 두는 것이 필요하다.
3. 사업자 보관 기준 : **가상자산사업자** (VASP, Virtual Asset Service Provider)는 가상자산 이용자 보호 등에 관한 법률이 정한 콜드월렛 보관 기준을 지키고, 다중서명 키를 분산 보관하는 체계를 갖추어야 한다.

## Ⅶ. 결론

- 핵심 요약 : 블록체인의 암호 기반은 견고하지만, 컨트랙트·오라클·키 관리가 실질적인 보안 경계임.
- 시사점 : 계층별 사전 검증과 사후 대응 체계를 함께 갖춰야 블록체인 기반 서비스의 신뢰가 유지됨.
