# 익명처리(Anonymization)

## 핵심 개념
- 시간·비용·기술 등을 합리적으로 고려할 때 다른 정보를 사용하여도 더 이상 특정 개인을 알아볼 수 없도록 개인정보를 영구적으로 비가역적 변환하는 기술적·관리적 조치.
- 처리된 정보(익명정보)는 개인정보보호법상 개인정보에 해당하지 않으므로, 법적 규제(동의, 목적 외 이용 제한 등)를 받지 않고 자유로운 활용 및 제3자 제공이 가능함.

```
+-------------------------------------------------------------+
|                개인정보 보호 수준별 데이터 분류               |
+-------------------------------------------------------------+
| 1. 개인정보 (Personal Data)  | 특정 개인을 직접 식별 가능한 원본 데이터    |
| 2. 가명정보 (Pseudonymized) | 추가 정보 없이는 식별 불가 (법적 개인정보)  |
| 3. 익명정보 (Anonymized)     | 어떠한 방법으로도 식별 불가 (법 적용 제외)  |
+-------------------------------------------------------------+
```

---

## 가명처리(Pseudonymization) vs 익명처리(Anonymization)

```
[ 원본 개인정보 ] ===== 가명처리 =====> [ 가명정보 ] <--- 추가정보 결합 시 재식별 가능
       |                                     (개인정보보호법 적용 대상)
       |
       +============= 익명처리 =====> [ 익명정보 ] <--- 어떠한 결합으로도 식별 불가
                                             (개인정보보호법 적용 배제)
```

| 비교 항목 | 가명처리(Pseudonymization) | 익명처리(Anonymization) |
|---|---|---|
| **개념** | 추가 정보(매핑 테이블 등) 없이는 개인을 알아볼 수 없는 상태 | 모든 수단을 동원해도 개인을 영구히 알아볼 수 없는 상태 |
| **가역성** | 추가 정보 결합 시 복원 가능(가역적) | 원천적으로 복원 불가능(비가역적) |
| **법적 성격** | 개인정보보호법상 여전히 개인정보에 해당 | 개인정보에 해당하지 않음 (법률 적용 완전 제외) |
| **활용 범위** | 통계작성, 과학적 연구, 공익적 기록보존 등에 한정 | 상업적 판매, 공개 배포 등 제한 없이 자유 활용 |
| **안전조치 의무** | 추가정보 분리 보관, 접근통제 등 법적 안전조치 필수 | 법적 안전조치 의무 없음 |

## 주요 익명처리 기술 및 프라이버시 보호 모델

### 1. 프라이버시 보호 모델
- **k-익명성(k-Anonymity)**: 준식별자(QI: 나이, 성별, 주소 등)의 속성값이 동일한 레코드가 데이터셋 내에 최소 $k$개 이상 존재하도록 하여 특정인을 $1/k$ 이하의 확률로만 식별되도록 보장.
  - *한계*: 동질성 공격(Homogeneity Attack), 배경지식 공격(Background Knowledge Attack)에 취약.
- **l-다양성(l-Diversity)**: 각 동질 그룹(Equivalence Class) 내의 민감한 속성(Sensitive Attribute) 값이 최소 $l$개 이상의 서로 다른 값을 갖도록 보장.
  - *한계*: 쏠림 공격(Skewness Attack), 유사성 공격(Similarity Attack)에 취약.
- **t-근접성(t-Closeness)**: 동질 그룹 내 민감 속성의 확률 분포와 전체 데이터셋의 민감 속성 확률 분포 간의 거리(EMD)를 $t$ 이하로 유지하여 정보 유출 차단.
- **차분 프라이버시(Differential Privacy)**: 데이터셋에 임의의 1건의 레코드가 포함되거나 제외되어도 질의 결과의 통계적 분포 차이가 $\epsilon$(엡실론) 이하가 되도록 수학적 노이즈(Laplace / Gaussian Noise)를 주입.

### 2. 세부 익명화 가공 기법

```
+-------------------------------------------------------------+
|                    익명화 가공 세부 기법                      |
+-------------------------------------------------------------+
| 1. 식별자 삭제   | 성명, 주민등록번호, 전화번호 등 직접식별자 영구 파기|
| 2. 범주화/일반화 | 27세 -> 20대, 서울시 강남구 역삼동 -> 서울시      |
| 3. 마스킹        | 홍길동 -> 홍**, 1234-5678 -> 1234-****           |
| 4. 데이터 섭동   | 실제 나이에 ±2세 무작위 잡음 추가, 수치 교란      |
| 5. 합성 데이터   | 원본 통계적 상관관계만 복제한 가상 인공 데이터 생성  |
+-------------------------------------------------------------+
```

## 익명처리 절차 및 적정성 평가

```
[1. 사전 준비] ----> [2. 위험도 측정] ----> [3. 익명처리 수행] ----> [4. 적정성 평가] ----> [5. 사후 관리]
 - 데이터 식별       - 재식별 가능성 분석      - 삭제, 범주화,       - 전문가 위원회 심의      - 환경 변화 감시
 - 활용 목적 확정    - 준식별자 결합 위험      차분 노이즈 주입      - k, l, t 모델 검증       - 재식별 시 즉시 파기
```

1. **사전 준비**: 데이터의 처리 목적, 데이터셋 항목 분석, 법적 요구사항 검토.
2. **위험도 측정**: 공공 데이터와의 결합 가능성, 희귀 속성치(Extreme Value) 유무 분석.
3. **익명처리 수행**: 식별자 완전 삭제, 준식별자의 과감한 상위 범주화(Generalization) 및 레코드 억제(Suppression).
4. **적정성 평가**: 프라이버시 모델 지표 충족 여부 및 외부 전문가 위원회의 승인 심사.
5. **사후 관리**: 외부 공개 데이터 추가 등 데이터 생태계 변화에 따른 재식별 위험도 지속 감시.

## 결론 및 실무 시사점
- 데이터 경제 활성화와 인공지능 학습 데이터 수요 급증에 따라 개인정보 침해 없이 대규모 데이터를 공유할 수 있는 익명처리의 중요성이 증대됨.
- 과도한 익명처리는 데이터의 유용성(Utility)을 심각하게 저하시키므로, 차분 프라이버시 및 생성형 AI 기반 합성 데이터(Synthetic Data)를 결합하여 유용성과 안전성의 균형을 확보해야 함.
