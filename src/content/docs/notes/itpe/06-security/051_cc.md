## Ⅰ. CC(Common Criteria, 공통평가기준)의 개요

- 개념 : 국가마다 상이하던 정보보호제품의 보안성 평가 기준을 일원화하기 위해 제정된 국제 표준 **ISO(International Organization for Standardization)/IEC(International Electrotechnical Commission) 15408** 체계로서, 정보보호제품의 보안 기능 요구사항과 보증 요구사항을 체계적으로 평가·인증하는 다자간 상호인정 체계.
- 배경 및 필요성 : 미국의 TCSEC, 유럽의 ITSEC 등 국가별 평가 기준의 차이로 인한 중복 인증 비용과 무역 장벽을 해소하고, 글로벌 상호인정협정(CCRA)을 통해 공인된 보안 신뢰성을 확보하기 위해 도입.
- 핵심 목적 : 정보보호제품의 객관적 보안 품질 보증, 국가·공공기관 납품 자격 부여, CCRA 가입국 간 인증서 상호 인정을 통한 글로벌 수출 지원.

## Ⅱ. CC(Common Criteria, 공통평가기준)의 핵심 아키텍처 및 동작 메커니즘

CC(Common Criteria) 평가는 보호프로파일(PP)과 보안목표명세서(ST)를 바탕으로 평가대상제품(TOE)이 목표로 하는 EAL(Evaluation Assurance Level) 1~7 보증등급을 만족하는지 엄격히 검증함.

```text
[ CC(공통평가기준) 3대 핵심 구조 및 평가 관계도 ]

  +-------------------------------------------------------------+
  | 보호프로파일 (PP : Protection Profile)                      |
  |  - 특정 제품군(방화벽 등)에 대한 '소비자/국가의 보안 요구서' |
  +------------------------------┬------------------------------+
                                 │ PP 준수 (Conform)
                                 ▼
  +-------------------------------------------------------------+
  | 보안목표명세서 (ST : Security Target)                       |
  |  - 개발자가 작성한 '우리 제품(TOE)의 실제 구현 보안 명세서' |
  +------------------------------┬------------------------------+
                                 │ 평가 대상 매핑
                                 ▼
  +-------------------------------------------------------------+
  | 평가대상제품 (TOE : Target of Evaluation)                   |
  |  - 실제 하드웨어/소프트웨어 정보보호제품                    |
  |  - 보안 기능 요구사항 (SFR) + 보안 보증 요구사항 (SAR) 평가 |
  +------------------------------┬------------------------------+
                                 │ 평가 수행 (시험기관 -> 인증기관)
                                 ▼
  [ CC 인증서 발급 (EAL 1 ~ EAL 7 등급 부여, CCRA 상호인정) ]
```

- **PP** (보호프로파일) : 특정 제품 범주(예: 차세대 방화벽, 스마트카드)에 요구되는 보안 목적과 기능을 국가 또는 공인 기관이 정의한 공통 규격서.
- **ST** (보안목표명세서) : 개발사가 자사 제품(TOE)의 기능과 환경에 맞추어 PP를 준수하거나 독자적으로 작성한 평가 기준서.
- **TOE** (평가대상제품) : 소프트웨어, 펌웨어, 하드웨어로 구성되어 실제 평가를 받는 최종 상용 제품.
- **EAL 1 ~ EAL 7** (보증 등급) : 기능 시험(EAL1)부터 정형적 검증(EAL7)까지 7단계로 구분되며, 상용 보안제품은 통상 EAL2~EAL4 등급 획득.
- **CCRA** (Common Criteria Recognition Arrangement) : 인증서 발행국(CAP)과 수용국(CCP) 간에 EAL2(일부 EAL4)까지 인증 결과를 상호 인정하는 국제 협정.

## Ⅲ. CC(Common Criteria, 공통평가기준)의 세부 구성 요소 및 비교 분석

| 보증 등급 | 명칭 | 평가 엄격성 | 적용 대상 |
| --- | --- | --- | --- |
| EAL 1 | 기능 시험 (Functionally Tested) | 제품 설명서 및 기본 기능 작동 여부 검토 | 상용 저위험 소프트웨어 |
| EAL 2 | 구조 시험 (Structurally Tested) | 개발사 시험 결과 검토, 취약점 기본 점검 | 일반 상용 정보보호제품 (CCRA 표준 인정) |
| EAL 3 | 체계적 시험 및 점검 (Methodically Tested) | 설계 문서화 검토, 형상 관리 검증 | 엔터프라이즈 네트워크 장비 |
| EAL 4 | 체계적 설계, 시험 및 복습 (Methodically Designed) | 소스코드 하위 모듈 분석, 독립적 취약점 분석 | 전통적 고신뢰 방화벽, OS(Operating System), DBMS (Database Management System, 국내 공공 다수) |
| EAL 5~7 | 준정형/정형적 설계 및 검증 (Formal Verification) | 수학적 모델링, 엄격한 코드 증명 | 군사 지휘통제, 스마트카드 칩, 우주 항공 제어 |

- CC 인증은 제품의 '절대적 무결함'을 증명하는 것이 아니라, 명시된 보안 환경에서 정해진 보안 목적을 달성할 수 있는 '보증(Assurance)'을 제공하는 프로세스임.

## Ⅳ. CC(Common Criteria, 공통평가기준)의 주요 한계점 및 해결 방안

- 인증 평가 기간의 장기화(6개월~1년 이상) 및 막대한 비용 부담 :
  - 한계점 : 평가 계약부터 인증서 발급까지 과도한 시간과 상당한 비용이 소요되어 신기술 소프트웨어의 출시 지연 초래.
  - 해결 방안 : 국내 **신속확인제** (Fast-Track)를 활용하여 2개월 이내에 공공 시장에 선제 진입하고, 평가 프로세스 자동화 도구 도입.
- CCRA 협정 개정으로 인한 국내 고등급(**EAL4** 이상) 인증의 국제 효력 제한 :
  - 한계점 : CCRA 가입국 간 상호 인정 범위가 협약 개정으로 EAL2(cPP 기반)로 조정되어 국내 공공용 EAL4 인증서의 해외 직수출 제약.
  - 해결 방안 : 국제 협력형 보호프로파일(cPP, collaborative PP)을 준수한 제품 개발 및 글로벌 공인 시험소와의 다자간 교차 평가 추진.
- 애자일/클라우드 환경의 빈번한 업데이트에 대응 불가한 경직성 :
  - 한계점 : 소스코드 한 줄만 수정되어도 **변경 승인** (Assurance Continuity)이나 재평가를 받아야 하므로 주 단위 CI(Continuous Integration)/CD(Continuous Delivery) 배포 불가능.
  - 해결 방안 : 패치 영역의 보안 영향도를 자동 판별하는 **지속적 보증** (Continuous CC) 프레임워크 연구 및 형상 변경 절차 간소화.

## Ⅴ. CC(Common Criteria, 공통평가기준) 적용 및 발전을 위한 기술사적 제언

- 신속확인제와 CC 인증의 전략적 투트랙 운영 : 클라우드, AI(Artificial Intelligence) 등 혁신 보안제품은 신속확인제로 공공 레퍼런스를 우선 확보하고, 레거시 네트워크 제품은 정규 CC 유지.
- **cPP** (국제공통보호프로파일) 기반 제품 개발 표준화 : 글로벌 시장 진출을 목표로 하는 정보보호 기업은 국내 전용 PP 대신 글로벌 cPP 규격을 선제 반영하여 설계.
- 평가 제출물의 **코드형 문서화** (Docs-as-Code) 체계 내재화 : ST 및 설계 문서를 소스코드 리포지토리와 연동하여 버전 관리함으로써 형상 변경 시 인증 유지보수 비용 최소화.
