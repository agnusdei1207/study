## 핵심 용어
- 목표 하이재킹(Goal Hijacking): 에이전트의 원래 수행 목표(예: "일정 정리")를 공격자가 주입한 적대적 프롬프트로 변조하여 악의적 목표(예: "연락처 전체 유출")로 대체해 버리는 공격
- 다중 에이전트 신뢰 사슬(Multi-Agent Trust Chain): 여러 에이전트가 협업할 때 앞선 에이전트의 출력물을 다음 에이전트가 검증 없이 신뢰함으로써 악성 명령이 연쇄 전파되는 현상

## 핵심 통찰
- LLM 취약점(OWASP LLM Top 10)이 "거짓말이나 욕설을 하는 것(말의 문제)"이었다면, Agentic 취약점은 "서버를 지우고 돈을 송금하는 것(행동의 문제)"임 → 피해의 파급력이 물리적·금전적 실체로 직결됨
- 에이전트에게 셸(Shell)이나 파이썬 코드 실행기 같은 '범용 실행 도구'를 주는 것은 보안의 자살행위임 → 오직 사전 정의된 정형 API(REST API)만을 호출할 수 있도록 화이트리스트 통제가 필수적임
- 다중 에이전트 환경에서는 "어느 에이전트의 잘못으로 사고가 났는가?"를 증명하기 어려움 → 에이전트 간 주고받는 모든 메시지에 암호학적 디지털 서명을 남기는 블록체인형 감사 로그가 요구됨

## 이웃 토픽과 구분
- OWASP Agentic Top 10 vs OWASP LLM Top 10: Agentic = 환경 조작(도구 호출, API 실행, OS 상호작용) 보안 위협 / LLM = 모델의 자연어 입출력 및 텍스트 프롬프트 위협

## 문제·원인·대책
- 사례: 사내 업무 자동화 에이전트가 고객 지원 이메일을 처리하던 중, 이메일 본문에 숨겨진 악성 명령을 읽고 사내 클라우드 스토리지의 모든 백업 파일을 삭제하는 API를 실행한 사건
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 외부 비정형 데이터 유입에 의한 목표 왜곡 및 비인가 삭제 API 실행 | 에이전트의 자연어 계획을 검증 없이 신뢰하고 삭제 권한을 직접 부여 | Tool Calling 게이트웨이 도입 및 파괴적 명령 시 인간 승인(HITL) | 목표 조작 시도 무력화 및 비인가 API 호출 차단 |
| 에이전트가 호출한 파이썬 스크립트 도구를 통한 호스트 서버 장악 | 도구 실행 환경의 호스트 격리 부재 및 루트 권한 실행 | 일회용 gVisor/Firecracker 마이크로VM 샌드박스 격리 | 샌드박스 탈출 차단 및 호스트 시스템 무결성 보호 |

## 내 의견
- [에이전트 권한의 최소화 및 파괴적 도구의 원천 배제] 에이전트 개발 시 개발 편의를 위해 'Bash 실행 도구'를 붙여주는 관행이 가장 위험함 → 나라면: 에이전트가 호출할 수 있는 도구 목록에서 임의 명령 실행 도구를 원천 박탈하고, 데이터베이스도 읽기 전용 뷰(Read-only View)만 제공하며, 결제·삭제 등 고영향 행위는 반드시 '인간 확인(User Confirmation)' 없이는 트리거되지 않는 결정론적 안전 가드를 강제
