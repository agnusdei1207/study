## 연관 키워드

- 섀도우 AI(Shadow AI), 생성형 AI(Generative AI), 섀도우 IT(Shadow IT)
- DLP(Data Loss Prevention), CASB(Cloud Access Security Broker), ZDR(Zero Data Retention)
- AI 게이트웨이, RAG(Retrieval-Augmented Generation), 프롬프트 인젝션, 양성화

## Ⅰ. 섀도우 AI의 개요

- 핵심 요약 : 승인되지 않은 외부 생성형 AI 사용이 기밀 유출 통로가 되어, 차단과 양성화를 함께 설계해야 하는 보안 과제.
- 개념 : 임직원이 IT·보안 부서의 승인 없이 개인 계정이나 브라우저 확장으로 외부 **생성형 AI** (Generative AI)를 업무에 사용하는 상태 (**섀도우 AI** (Shadow AI)).
- 배경 및 필요성 : 소스코드와 고객정보가 외부 AI에 입력되면 학습 활용이나 재노출 위험이 생기는데, 개인 계정 사용은 기존 보안 통제 밖에 있어 가시성이 낮음.
- 주요 목적 : 기밀 유출을 막으면서 승인된 안전한 AI 환경을 제공해 보안과 업무 생산성을 함께 확보.

## Ⅱ. 섀도우 AI의 특징 및 장점

- 핵심 요약 : 가시성, 접속 통제, 프롬프트 보호, 계약 보증, 감사가 유출 경로를 단계별로 막는 다층 구조.

1. 가시성 확보 : **CASB** (Cloud Access Security Broker), EDR(Endpoint Detection and Response), SWG(Secure Web Gateway)로 사내에서 쓰이는 비승인 AI 서비스를 식별 → 통제 대상을 먼저 파악.
2. 접속 통제 : DNS 차단, 웹 필터링, 브라우저 확장 설치 제한 → 미검증 AI 도구 접근 축소.
3. 프롬프트 보호 : **DLP** (Data Loss Prevention) 프록시가 입력값의 개인정보와 소스코드를 전송 전에 마스킹·토큰화 → 기밀의 외부 전송 차단.
4. 계약·보증 : 엔터프라이즈 라이선스에 **ZDR** (Zero Data Retention) 조건을 명시 → 벤더 측 학습 배제의 계약 근거 확보.
5. 모니터링·감사 : 프롬프트와 응답을 SIEM에 연동 → 사고 시 부인방지와 책임 추적성 확보.

## Ⅲ. 섀도우 AI의 구조 (흐름)

- 핵심 요약 : 비인가 경로를 끊고 승인 경로로 사용자를 유도하는 게이트웨이 구조의 양성화.
- **AI 게이트웨이** : 사내 단일 진입점에서 인증, 민감정보 필터링, 프롬프트 인젝션 방어, 감사를 한꺼번에 처리하는 중계 계층.

```text
[ 1. 비인가 경로 (섀도우 AI) ]

임직원 단말
   ↓
개인 계정 외부 AI 웹·확장
   ↓
기밀 입력 → 학습·재노출 위험
```

```text
[ 2. 양성화 경로 (승인 AI) ]

임직원 단말
   ↓
CASB·SWG (비승인 차단, 승인 경로 유도)
   ↓
사내 AI 게이트웨이 (인증·DLP·감사)
   ↓
기업 전용 LLM 엔드포인트
```

사내 AI 게이트웨이의 구성 요소는 다음과 같다.

1. 신원 인증 : 사내 SSO(Single Sign-On)와 SAML(Security Assertion Markup Language) 기반 직무별 접근 인가.
2. 인라인 DLP : 프롬프트 안의 주민번호, API 키 같은 민감 정보를 실시간 마스킹.
3. **프롬프트 인젝션** 방어 : 탈옥(Jailbreak) 시도와 악성 지시문을 모델 호출 전에 차단.
4. 로깅·감사 : 입력과 응답을 암호화해 저장하고 SIEM(Security Information and Event Management)으로 전달.

## Ⅳ. 섀도우 AI의 비교

- 핵심 요약 : 섀도우 IT는 파일 유출이 문제이지만, 섀도우 AI는 입력 데이터의 학습과 재생성으로 유출이 확산되는 문제.

| 비교 축 | 전통적 섀도우 IT (Shadow IT) | 섀도우 AI (Shadow AI) |
| --- | --- | --- |
| 사용 대상 | 웹하드, 개인 메일, 협업 메신저 | 생성형 AI 챗봇, 코드 완성 도구, 이미지 생성 AI |
| 주된 위험 | 파일 저장·공유를 통한 유출 | 입력 데이터의 학습 흡수와 답변을 통한 재노출 |
| 상호작용 | 파일 업로드·다운로드 중심 | 프롬프트 기반 대화, 파일 분석, 코드 실행 위임 |
| 유출 범위 | 유출된 파일에 국한 | 외부 사용자 응답을 통한 기밀 재노출 가능 |
| 대응 방식 | URL 차단과 포트 제어로 비교적 통제 용이 | 차단만으로는 우회가 많아 양성화를 병행 |

- 선택 기준 : 입력이 실시간 대화형인지, 벤더 계약으로 보존 정책을 통제할 수 있는지에 따라 차단과 양성화의 비중을 정함.

## Ⅴ. 섀도우 AI의 한계와 방안

- 핵심 요약 : 차단 우회, 정규식 탐지의 한계, 벤더 신뢰 결함, 생성 코드의 라이선스 문제를 양성화와 기술 보완으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 전면 차단의 우회 | 개인 스마트폰이나 테더링으로 프롬프트를 입력해 통제 밖으로 유출 | 차단 일변도를 피하고 사내 전용 AI 챗봇을 공식 제공 | 비승인 AI 접속 시도 건수, 승인 AI 사용률 |
| 정규식 DLP의 한계 | 난독화되거나 변형된 소스코드를 패턴으로 탐지하지 못함 | **AST**(Abstract Syntax Tree, 추상 구문 트리) 기반 코드 구조 분석을 더한 시맨틱 DLP 연동 | 탐지율, 오탐률 |
| 벤더 보존 정책의 신뢰 결함 | ZDR 계약에도 벤더 내부 로깅 오류로 데이터가 잔존할 수 있음 | 민감 업무는 오픈소스 모델을 사내 GPU 클러스터나 전용 클라우드에 자체 호스팅 | 외부 전송 건수, 계약 점검 결과 |
| AI 생성 코드의 라이선스·표절 | 생성 코드가 **카피레프트 라이선스** (GPL 등)나 기존 저작물과 유사해 법적 분쟁 유발 | CI/CD 파이프라인에 코드 유사도 검증과 라이선스 스캔 연동 | 스캔 차단 건수, 라이선스 위반 건수 |

## Ⅵ. 섀도우 AI 적용을 위한 기술사적 제언

- 핵심 요약 : AI 사용을 막기보다 안전한 사용 경로를 먼저 제공하고, 그 위에 통제를 얹는 거버넌스로 전환.

1. 사용 원칙과 예외 승인 절차를 정책으로 제정하되, 승인 기간을 업무 요구에 맞게 짧게 운영하는 편이 바람직하다.
2. 자체 **RAG** (Retrieval-Augmented Generation) 기반 사내 지식 비서처럼 기업이 통제하는 AI 플랫폼을 공동으로 운영하고, 정보보호 조직과 업무 부서가 데이터 분류 기준을 함께 정한다.
3. 감사 로그와 탐지 지표를 정기적으로 재검토하여, 새로 등장하는 AI 서비스에 통제 규칙이 뒤처지지 않도록 갱신한다.

## Ⅶ. 결론

- 핵심 요약 : 섀도우 AI는 업무 생산성에 대한 수요가 만든 현상이므로, 막는 것보다 안전한 경로로 흡수하는 것이 핵심.
- 시사점 : 가시성과 양성화를 함께 갖춘 조직만이 AI 확산 속에서 기밀을 지키면서 업무 효율을 얻을 수 있다.
