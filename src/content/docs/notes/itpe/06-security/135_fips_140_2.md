## 지식 로드맵 내 현재 위치

지식 위치: 정보보안 → 암호 모듈 검증 → **FIPS 140-2**

## 30초 인출

- **본질:** 민감한 연방 정보를 보호하는 하드웨어·소프트웨어·하이브리드 암호 모듈의 보안 요구사항과 1~4단계 보안 레벨을 규정한 NIST/CMVP 공인 표준 규격
- **메커니즘:** 11대 보안 영역(역할·서비스, 물리보안, 키 관리, 자체시험 등) 명세 → 공인 시험소(NVLAP) 평가 → CMVP 검토 및 등급 인증서 발행
- **통찰:** 상위 앱의 메모리 누출은 TEE/HSM 격리 연산으로 방어하고 FIPS 140-3 전환 및 국내 공공 진출 시 KCMVP(국산 암호 모듈) 하이브리드 결합 필수

<details>
<summary>핵심 용어</summary>

- **FIPS 140-2** : 미국 NIST와 캐나다 CCCS가 공동 제정한 암호 모듈 보안 요구사항 표준.
- **CMVP (Cryptographic Module Validation Program)** : FIPS 140 표준에 따라 암호 모듈의 보안성을 공인 검증하는 프로그램.
- **CSP (Critical Security Parameter)** : 암호화 키, 인증 데이터, 비밀번호 등 노출 시 보안이 파괴되는 핵심 보안 매개변수.
- **Zeroization (제로화)** : 물리적 침투 감지 시 모듈 내의 모든 CSP를 메모리에서 즉각적이고 비가역적으로 소거하는 절차.

</details>

## 2~4교시 예상문제 (25점)

> 암호 모듈 검증 표준인 FIPS 140-2의 4단계 보안 레벨 분류, 암호화 시스템 설계 시 핵심 고려사항, 4대 보안 요소 및 보안 위협 대응 전략을 설명하고, FIPS 140-3 전환 및 KCMVP와의 상호운용성 확보 방안을 제시하시오. (제132회 4교시 기출 연계·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 정부 및 공공·금융 기관에서 민감 데이터를 보호하기 위해 사용되는 하드웨어, 소프트웨어, 펌웨어 암호 모듈의 11대 보안 요구사항과 4단계 보안 등급을 규정한 미국 연방 표준 |
| 목적 | 암호 알고리즘의 단순 구현을 넘어, 암호 모듈 경계(Cryptographic Boundary), 키 생명주기 관리, 물리적 탬퍼 저항성, 오류 발생 시 자체시험의 안전성을 객관적으로 공인 |

- NIST의 암호 알고리즘 검증(CAVP)을 통과한 알고리즘을 바탕으로, 모듈 전체의 물리적·논리적 방어력을 종합 평가하는 글로벌 디팩토 암호 검증 표준

## Ⅱ. FIPS 140-2의 4단계 보안 레벨(Security Level) 분류 특성

| 보안 레벨 | 핵심 물리적 보안 요구사항 | 인증 및 운영체제 요구사항 | 대표적 구현 형태 |
|---|---|---|---|
| Level 1 | 물리적 보안 요구사항 없음 (표준 생산 등급) | 기본 인증 불요, 범용 OS(GPC) 허용 | 순수 소프트웨어 암호 라이브러리 (OpenSSL FIPS) |
| Level 2 | 탬퍼 증거(Tamper-evident) 봉인 테이프, 외관 코팅 | 역할 기반 인증(Role-based Auth), CC EAL2 이상 OS | 펌웨어 내장 라우터, 스마트카드, 방화벽 장비 |
| Level 3 | 탬퍼 대응(Tamper-responsive: 케이스 개방 시 키 제로화) | 신원 기반 인증(Identity-based), I/O 포트 분리 | 서버 장착용 PCIe HSM, 암호 가속 카드 |
| Level 4 | 완전 밀폐 포락선(Envelope), 환경 이상(EFP: 온도/전압) 감지 즉시 제로화 | 최고 수준 다요소 인증, 엄격한 자체시험, EAL4 OS | 군용 보안 장비, 고신뢰 루트 CA 전용 외장 HSM |

- 레벨이 높아질수록 물리적 침투 공격(고체 드릴, 화학 물질 부식, 부채널 분석)에 대한 능동적 방어 메커니즘 강제 특성 보유

## Ⅲ. FIPS 140-2 암호 모듈 경계 및 11대 보안 요구 영역

```text
[FIPS 140-2 암호 모듈 물리적·논리적 경계 아키텍처]

 ┌─────────────────────────────────────────────────────────────┐
 │                물리적/논리적 암호 모듈 경계                 │
 │  ┌───────────────────────────────────────────────────────┐  │
 │  │ 1. 역할, 서비스 및 인증 (사용자, 암호관제관 역할 분리)│  │
 │  ├───────────────────────────────────────────────────────┤  │
 │  │ 2. 유한 상태 모델 (FSM: 전원인가, 자가시험, 암호연산) │  │
 │  ├───────────────────────────────────────────────────────┤  │
 │  │ 3. 암호 키 및 CSP 관리 (생성, 분배, 저장, 제로화)   │  │
 │  ├───────────────────────────────────────────────────────┤  │
 │  │ 4. 자가 시험 (Self-tests: 부팅 시 알고리즘/무결성 점검)│  │
 │  ├───────────────────────────────────────────────────────┤  │
 │  │ 5. 물리적 보안 (Tamper Detection / Zeroization 회로) │  │
 │  └───────────────────────────────────────────────────────┘  │
 │       ▲ Data In           ▲ Control In          ▲ Power     │
 │       ▼ Data Out          ▼ Status Out          │           │
 └───────┴───────────────────┴─────────────────────┴───────────┘
```

| 11대 보안 요구 영역 | 핵심 평가 내용 |
|---|---|
| 1. 암호 모듈 명세 | 하드웨어, 소프트웨어, 펌웨어 구성 요소의 명확한 경계 및 설명 |
| 2. 암호 모듈 포트 및 인터페이스 | 데이터 입력, 데이터 출력, 제어 입력, 상태 출력의 논리적/물리적 분리 |
| 3. 역할, 서비스 및 인증 | 사용자(User), 암호 관제관(Crypto Officer) 역할 분리 및 접근 인가 |
| 4. 유한 상태 모델 (FSM) | 정상, 오류, 자가시험 등 모듈의 모든 동작 상태와 전이 규칙 명세 |
| 5. 물리적 보안 | 침투 방지 외함, 탬퍼 실링, 환경 이상 감지(EFP) 및 키 소거 |
| 6. 운영 환경 | 범용 OS 상에서 실행 시 접근통제 및 무결성 보호(CC 평가 연동) |
| 7. 암호 키 관리 | 무작위 난수 생성(DRBG), 키 합의, 비휘발성 저장, 안전한 폐기(Zeroize) |
| 8. EMI / EMC | 미 연방통신위원회(FCC) 전자파 적합성 규정 준수 |
| 9. 자가 시험 (Self-tests) | 부팅 시 알고리즘 기지답 시험(KAT), 펌웨어 무결성 시험, 조건부 시험 |
| 10. 설계 보증 | 형상 관리, 기능 명세서, 소스코드 보안 분석 |
| 11. 기타 공격 완화 | 차분 전력 분석(DPA), 타이밍 분석 등 부채널 공격 완화 명세 |

## Ⅳ. 암호화 시스템 설계 시 고려사항 및 4대 보안 요소

| 설계 고려사항 (4대 축) | 엔지니어링 세부 내용 | 위협 대응 전략 매핑 |
|---|---|---|
| 1. 알고리즘 및 키 길이 | 양자 컴퓨팅 위협 대비 최소 AES-256, RSA-3072, ECC P-384 채택 | 브루트포스 및 수학적 해독 공격 방어 |
| 2. 키 라이프사이클 관리 | 생성 $\rightarrow$ 분배 $\rightarrow$ 보관 $\rightarrow$ 갱신 $\rightarrow$ 폐기 전 주기의 KMS 중앙 통제 | 키 유출, 비인가 복제 및 분실 방어 |
| 3. 모듈 폼팩터 및 성능 | 처리 대역폭에 따른 HW HSM(고속 암호 가속) vs SW 모듈 최적화 | 서비스 지연 방지 및 병목 현상 해소 |
| 4. 컴플라이언스 범위 | 대상 시스템의 데이터 등급에 부합하는 FIPS 140 레벨(보통 Level 3) 선정 | 법적 규제 준수 및 감사 증적 확보 |

| 암호화 시스템 4대 보안 요소 | 세부 구현 메커니즘 | 방어 위협 |
|---|---|---|
| 기밀성 (Confidentiality) | 검증된 대칭키 블록 암호(AES-GCM) 기반 저장·전송 암호화 | 네트워크 스니핑, 하드디스크 도난 유출 |
| 무결성 (Integrity) | HMAC-SHA256, 전자서명 및 AEAD 인증 태그 검증 | 데이터 변조, 악의적 페이로드 주입 |
| 가용성 (Availability) | 암호 가속 장비(HSM)의 액티브-액티브 이중화 및 장애 페일오버 | 암호화 연산 병목으로 인한 서비스 거부 |
| 부인 방지 (Non-Repudiation) | 개인키 기반 전자서명(ECDSA/Ed25519) 및 타임스탬프 결합 | 거래 사실 부인, 위조 트랜잭션 제출 |

## Ⅴ. FIPS 140-2 도입 시 엔지니어링 한계와 해결 방안

| 한계 | 방안 |
|---|---|
| FIPS 인증 모듈 자체는 안전하나, 상위 소프트웨어가 메모리에서 평문 키를 다룰 때 메모리 덤프나 부채널 공격으로 키 누출 | 키를 호스트 메모리에 올리지 않고 모든 암호 연산을 HSM 내부에서만 완결하는 PKCS#11 / KMIP 아키텍처를 강제하고, 메모리 제로화(Secure Zeroization) API 적용 |
| NIST의 FIPS 140-2 공식 인증 종료 및 FIPS 140-3(ISO/IEC 19790 표준 기반) 전면 전환에 따른 기존 인증 장비의 레거시화 | 신규 조달 시 ISO/IEC 19790 기반 FIPS 140-3 인증 모듈을 기본 요건으로 명시하고, 암호 민첩성(Crypto Agility) 설계를 통해 모듈 교체 영향 최소화 |
| 글로벌 FIPS 140-2 인증 HSM 장비를 국내 공공·금융 시스템에 도입 시 국가정보원 암호모듈검증제도(KCMVP) 미승인으로 컴플라이언스 충돌 | KCMVP 검증필 국산 암호모듈(ARIA, LEA 탑재)을 연계한 이중 암호화 아키텍처를 구성하거나 KCMVP 인증 전용 HSM 장비와 연동 게이트웨이 구축 |
| 모듈 부팅 시 수행되는 전수 알고리즘 자가시험(Self-tests)으로 인해 시스템 리부팅 시 수초~수십 초의 가용성 지연 발생 | 자가시험 병렬화 설계를 적용하고, 클러스터링 기반 롤링 리부팅(Rolling Reboot)을 수행하여 암호 서비스 중단 방지 |

## Ⅵ. 차세대 암호 모듈 거버넌스 및 FIPS 140-3 전환 제언

```text
[글로벌 FIPS 140-3 및 국내 KCMVP 통합 암호 거버넌스 아키텍처]

 ┌─────────────────────────────────────────────────────────────┐
 │                 1. 엔터프라이즈 KMS 레이어                   │
 │   - KMIP / PKCS#11 표준 인터페이스 기반 키 라이프사이클 관리│
 │   - HashiCorp Vault / Cloud KMS 연동 암호 민첩성 확보       │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │              2. 하이브리드 암호 모듈 레이어 (Dual-Engine)    │
 │   ┌────────────────────────┐    ┌────────────────────────┐  │
 │   │ 글로벌 FIPS 140-3 HSM  │    │ 국내 KCMVP 인증 모듈   │  │
 │   │ (AES-256, PQC P-384)   │    │ (ARIA-256, LEA, SEED)  │  │
 │   └────────────────────────┘    └────────────────────────┘  │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │                 3. 탬퍼 저항성 물리 인프라 (Level 3/4)       │
 │   - 침투 감지 시 하드웨어 키 제로화 (Zeroization 회로)      │
 │   - FIPS 140-3 부채널(Non-invasive) 분석 검증 통과          │
 └─────────────────────────────────────────────────────────────┘
```

| 영역 | 엔지니어링 세부 과제 | 통제 목표치 |
|---|---|---|
| 인증 갱신 | 기존 FIPS 140-2 모듈의 CMVP Active 목록 상태 점검 및 140-3 전환 | 유효 인증 모듈 비율 100% |
| 규제 정합성 | 공공 부문 국산 암호 알고리즘(KCMVP) 준수 및 글로벌 FIPS 호환 | 국내외 보안 감사 결함 0건 |
| 물리 안전성 | 코어 CA 및 KMS 키 보관소의 FIPS 140 Level 3 이상 유지 | 하드웨어 탬퍼 저항성 검증 100% |
