## Ⅰ. FIPS 140-2의 개요

- 개념 : 미국 국립표준기술원(NIST)이 제정한 암호 모듈의 하드웨어, 소프트웨어, 펌웨어 전반에 걸친 보안성, 무결성, **물리적 침해 방지** 요구사항을 **4단계 보안 레벨** 로 규정한 연방 정보처리 표준.
- 배경 및 필요성 : 공공 및 금융 시스템에서 사용하는 암호 장비와 소프트웨어가 취약한 **난수 생성기** 사용, 부실한 키 관리, 물리적 해킹 공격에 노출되는 것을 방지하기 위해 국가 차원의 객관적이고 엄격한 검증 기준이 필요해짐.
- 핵심 목적 : 연방 정부 및 민간 규제 산업(금융, 의료)에서 민감 정보를 처리하는 암호 모듈의 암호학적 안전성과 하드웨어 **내탬퍼** (Tamper-resistance) 성능을 객관적으로 공인·보증.

## Ⅱ. FIPS 140-2의 핵심 아키텍처 및 동작 메커니즘

FIPS 140-2는 암호 모듈 명세, 포트 및 인터페이스, 역할/서비스/인증, 소프트웨어 보안, 물리적 보안 등 11개 영역을 평가하며, Level 1부터 Level 4까지 계층적 보안 수준을 정의함.

```text
[ FIPS 140-2 4단계 보안 수준 (Security Levels) 계층 구조 ]

  [ Security Level 4 ] : 완전한 물리적 침투 방지 및 능동적 영도화
   * 환경 보호(온도, 전압 이상 탐지 시 키 즉시 삭제: Zeroization)
   * 물리적 무단 침입 시도 시 모든 암호 키 즉시 소멸
   ---------------------------------------------------------------------
  [ Security Level 3 ] : 물리적 침입 방어 및 신원 기반 인증
   * 탬퍼 저항성(Tamper Detection/Resistance): 외관 개봉 시 즉각 반응
   * 강력한 신원 기반 인증 (Identity-based Authentication)
   * 암호 파라미터의 물리적/논리적 분리 및 인터페이스 격리
   ---------------------------------------------------------------------
  [ Security Level 2 ] : 탬퍼 증거성 및 역할 기반 인증
   * 탬퍼 에비던트(Tamper-evident): 개봉 흔적이 남는 특수 봉인 씰
   * 역할 기반 인증 (Role-based Authentication: 관리자, 사용자)
   * 승인된 범용 OS(EAL2 이상) 상에서 소프트웨어 동작
   ---------------------------------------------------------------------
  [ Security Level 1 ] : 순수 소프트웨어 기반 기본 암호 모듈
   * 승인된 암호 알고리즘(AES, SHA, RSA 등) 정확한 구현 검증
   * 물리적 보안 요구사항 없음 (일반 PC, 모바일 소프트웨어 라이브러리)
```

- **11대 보안 영역 평가** : 암호 모듈 사양, 암호 모듈 포트 및 인터페이스, 역할·서비스·인증, 유한 상태 모델(FSM), 물리적 보안, 운영 환경, 암호 키 관리, 전자파 적합성(EMI/EMC), 자가 진단(Self-tests), 설계 보증, 타 공격 완화.
- **변조 흔적(Tamper Evidence)과 저항(Tamper Resistance)** : Level 2의 개봉 흔적 라벨 부착부터, Level 3의 침입 감지 회로, Level 4의 센서 기반 능동적 전압/온도 감시 및 영도화(Zeroization) 구현.
- **자가 진단 테스트(Self-Tests)** : 전원 인가 시 암호 알고리즘 무결성과 펌웨어 변조를 검사하는 파워온 테스트와, 난수 생성 시 연속 동일값 생성을 차단하는 **조건부 자가 테스트** 필수.
- **FIPS 140-3으로의 발전** : ISO/IEC 19790 표준과 일치시키고 부채널 공격(Side-channel) 평가를 의무화한 차세대 FIPS 140-3 규격으로 2021년부터 전면 전환 진행 중.

## Ⅲ. FIPS 140-2의 세부 구성 요소 및 비교 분석

| 비교 항목 | **FIPS 140-2 / 140-3** | **CC 인증** (Common Criteria) | **KCMVP** (한국 암호모듈검증제도) |
| --- | --- | --- | --- |
| 검증 대상 | 암호 모듈 단독 (SW, HW, 펌웨어) | IT 제품 전반 (방화벽, OS, 스마트카드 등) | 공공기관 도입 암호 모듈 (SW, HW) |
| 주관 기관 | 미국 NIST / 캐나다 CCCS (CMVP) | 국제 공통평가기준 승인 협정 (CCRA) | 한국 국가정보원 / KISA |
| 등급 체계 | Level 1 ~ Level 4 (4단계) | EAL 1 ~ EAL 7 (7단계) | 보안 1등급 ~ 4등급 (4단계) |
| 핵심 평가 | 암호 알고리즘 적합성, 키 관리, 탬퍼링 | 보안목표명세서(ST) 기반 기능 및 보증 | 국내 표준 암호(ARIA, SEED, LEA 등) |
| 글로벌 통용 | 글로벌 시장 사실상 표준 (북미, 금융권) | CCRA 회원국 간 상호 인정 (EAL2~4) | 국내 공공/국방 시장 한정 통용 |

- FIPS 140-2는 엔터프라이즈 하드웨어 보안 모듈(HSM) 및 클라우드 KMS의 필수 인증 척도이며, 최근 ISO 표준과 정렬된 FIPS 140-3으로의 신속한 전환이 요구됨.

## Ⅳ. FIPS 140-2의 주요 한계점 및 해결 방안

- 클라우드 가상화 및 컨테이너 환경에서 물리적 보안(Level 3/4) 검증 난제 :
  - 한계점 : 물리 서버를 직접 통제할 수 없는 멀티테넌트 가상화 환경에서는 하드웨어 탬퍼 저항성 및 전압 감시를 소프트웨어 수준에서 충족 불가.
  - 해결 방안 : 클라우드 서비스 제공자가 인증받은 전용 물리 HSM(AWS CloudHSM 등)을 테넌트 전용으로 할당하여 연동하는 하이브리드 아키텍처 적용.
- 장기간 소요되는 인증 기간에 따른 배포 지연 :
  - 한계점 : 소프트웨어 패치나 사소한 버전 업데이트만 발생해도 재인증이 필요하여 고속 CI/CD 개발 환경의 애자일 배포 주기와 심각한 충돌.
  - 해결 방안 : NIST의 자동화된 암호 알고리즘 검증 프로그램(ACVP: Automated Cryptographic Validation Protocol) 도입을 통한 인증 기간 단축.
- FIPS 모드 활성화 시 비승인 현대 알고리즘 차단에 따른 호환성 저하 :
  - 한계점 : FIPS 모드가 켜진 OS/라이브러리에서는 ChaCha20-Poly1305, Ed25519 등 우수한 비표준 최신 알고리즘이 비승인으로 강제 비활성화됨.
  - 해결 방안 : FIPS 140-3 승인 알고리즘 목록을 상시 갱신하고, 필요 시 업무 영역별로 FIPS 준수 존과 비-FIPS 고속 처리 존을 네트워크 세그멘테이션으로 분리.

## Ⅴ. FIPS 140-2 적용 및 발전을 위한 기술사적 제언

- 클라우드 KMS 및 데이터베이스 암호화 시 FIPS 140-2 Level 3 이상 HSM 채택 : 금융 마이데이터 및 결제 카드 데이터(PCI-DSS) 처리 환경에는 키 생성과 보관이 외부로 유출되지 않는 Level 3 공인 모듈 필수 구성.
- FIPS 140-3 및 부채널(Side-channel) 공격 방어 체계 선제 대응 : 전력 분석(DPA)이나 전자파 분석(EMA)에 견딜 수 있는 차세대 하드웨어 암호 칩셋 설계를 조기 확보하고 FIPS 140-3 시험 규격 준수.
- 국내 KCMVP와 글로벌 FIPS 인증의 듀얼 아키텍처 수립 : 국내외 시장을 동시 공략하는 솔루션 개발 시 국내 국정원 검증(KCMVP)과 글로벌 FIPS 140-2/3을 모듈 추상화 계층(Crypto Abstraction Layer)을 통해 유연하게 선택 가능하도록 설계.
