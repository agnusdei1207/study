## 한 줄 본질
- FIPS 140-2는 암호 모듈의 보안 요구사항을 정한 미국·캐나다 CMVP 검증의 종전 기준. 2026년 9월 21일 기존 140-2 검증 모듈의 현역 목록·연방 수용 전환 시한 경과. 신규 적용 시 FIPS 140-3 상태 확인 필요

## 핵심 구분
| 구분 | 의미 |
|---|---|
| FIPS 140-2 | 암호 모듈의 역할·서비스, 키 관리, 자체시험, 물리 보안 등을 다룬 종전 표준 |
| 보안 수준 1~4 | 모듈의 전체 보안 요구 수준. 등급별 상세 요건은 각 영역과 구현 형태에 따라 차이 |
| CMVP | NIST·캐나다 사이버 보안 센터가 운영하는 암호 모듈 검증 프로그램 |
| FIPS 140-3 | 후속 암호 모듈 보안 요구사항. 검증서의 제품·버전·운영 환경 범위 확인 필요 |

## 10점 답안
FIPS 140-2는 하드웨어·소프트웨어·펌웨어 암호 모듈의 보안 요구사항을 정한 연방 정보처리 표준. CMVP가 시험 결과를 바탕으로 특정 모듈 구성의 적합성을 검증하며 보안 수준은 1~4. 암호 알고리즘의 적합성만으로 모듈 검증을 대신할 수 없고, 인증 제품이라도 인증서에 기재된 버전·운영 환경·보안 정책 확인 필요. 2026년 9월 21일 140-2 검증의 연방 수용 전환 시한이 지나 신규 설계에서는 140-3 검증 현황을 우선 확인.

## 25점 답안
### Ⅰ. 목적과 범위
암호 모듈 경계 안의 역할·서비스, 인터페이스, 소프트웨어·펌웨어, 키·보안 매개변수 관리, 자체시험, 물리 보안 등에 대한 공통 검증 기준.

### Ⅱ. 검증 절차
개발사가 모듈 경계와 보안 정책 정의 → 공인 시험소 평가 → CMVP 검토·인증서 발행 → 인증서의 제품명, 버전, 운영 환경, 보안 수준 및 상태 확인. 알고리즘 검증과 모듈 검증의 구분 필요.

### Ⅲ. 보안 수준
1~4 수준에 따라 요구 강도 증가. 수준 2의 변조 흔적 확인, 수준 3의 강화된 물리 보안·인증, 수준 4의 환경 이상 대응 등이 대표적 차이. 모든 수준 3 모듈이 키를 절대 외부로 내보내지 않는다거나, 모든 개봉 시 나노초 단위로 자동 소거된다는 단정은 부정확.

### Ⅳ. 암호화 시스템 설계 시 고려사항
보호 데이터와 위협 수준에 맞는 알고리즘·키 길이 선정, 인증된 키 생성·분배·보관·교체·폐기, 암호 모듈 경계·운영 환경·성능 요구의 확인. 140-2 검증 모듈 사용 여부는 인증서 상태와 실제 구성 일치 여부로 판단.

### Ⅴ. 보안 요소와 위협 대응
기밀성(적절한 암호화), 무결성·인증(AEAD 또는 MAC), 키 관리와 접근통제, 물리 보안·자체시험·감사 기록으로 구성. 키 유출, 변조, 재사용·잘못된 운영 환경, 물리적 침해에 각각 키 보호·무결성 검증·안전한 초기값 관리·변조 대응 등 적용. FIPS 검증만으로 서비스 전체 보안 보장 불가.

### Ⅵ. 현행 적용
FIPS 140-2와 후속 140-3을 비교할 때 사용 시점과 CMVP 인증서 상태 확인. 암호 모듈 검증은 국내 법제 준수를 자동 보증하지 않음.
