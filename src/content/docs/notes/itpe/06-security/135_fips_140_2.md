## 답안 골격
```text
[FIPS 140-2(암호 모듈 보안 요구사항)] ◀━━ 머리: Ⅶ 내 의견 (소프트웨어 암호화의 물리 탈취 취약점 극복 → FIPS 140-2 Level 3 이상의 하드웨어 HSM 및 변조 감지 키 소거 강제)
 ┃
 ┣━ Ⅰ 개요 ───── 미국 국립표준기술연구소(NIST)가 제정한 암호 모듈(하드웨어, 소프트웨어, 펌웨어)의 안전성과 신뢰성을 검증하기 위한 연방 정보처리 표준이자 글로벌 벤치마크 규격
 ┣━ Ⅱ 특징 ───── 4단계 보안 등급(Level 1~4) 체계 · 11개 세부 보안 영역 검증 · CMVP(암호모듈 검증 프로그램)를 통한 공인 인증 · 물리적 변조 방지 및 능동적 키 소거(Zeroization) 요구
 ┣━ Ⅲ 구조 ───── 4단계 보안 레벨: Level 1(기본 SW) < Level 2(변조 증거 씰) < Level 3(변조 감지 및 키 삭제) < Level 4(환경적 전압·온도 공격 방어)
 ┣━ Ⅳ 흐름 ───── 암호 모듈 설계 → FIPS 140-2 11개 영역 구현 → 공인 시험소(NVLAP) 평가 시험 → NIST/CCCS 공동 검증 → CMVP 인증 목록 등재
 ┣━ Ⅴ 비교 ───── FIPS 140-2(기존 표준, 11개 영역, 4단계) vs FIPS 140-3(ISO/IEC 19790 기반 개정, 비침습적 보안 강화, 서비스 기반 인터페이스) vs 국내 KCMVP
 ┗━ Ⅵ 실무 ───── 인증 획득에 소요되는 장기간(1~2년) 및 고비용 / 오픈소스 암호 라이브러리의 FIPS 모드 활성화 시 성능 저하 / 하드웨어 변경 시 재인증 부담
```
- 필수 키워드: FIPS 140-2 · CMVP · 4단계 보안 등급(Level 1~4) · 11개 보안 요구 영역 · 물리적 변조 방지(Tamper-proof) · 영점화(Zeroization) · FIPS 140-3
- 기출: 제132회 4교시 1번: "FIPS(Federal Information Processing Standard) 140-2에 대하여 다음을 설명하시오."

## 한 줄 본질
- 검증되지 않은 엉터리 자체 제작 암호 모듈 사용으로 인한 키 유출과 알고리즘 결함 병목 → NIST의 엄격한 11개 영역 기준과 4단계 등급에 따라 물리적·논리적 안전성을 공인 검증(CMVP) → 최고 수준의 신뢰성 보장 / 인증 비용 및 제품 개발 기간 장기화

## 핵심 그림
```text
[FIPS 140-2 암호 모듈 4단계 보안 등급(Security Level 1~4) 피라미드]

  [Level 4: 완전한 물리 방호 및 환경 장애 보호]
  - 칩 외피 개봉 시 즉각 키 영점화(Zeroization)
  - 비정상 전압·온도 공격(Fault Injection) 탐지 및 방어
  ────────────────────────────────────────────────────────────
  [Level 3: 변조 탐지 및 능동적 대응 (HSM 표준)]
  - 물리적 케이스 개방 감지 시 비밀키 즉각 자동 삭제
  - 신원 기반 인증(Identity-based), 데이터/제어 포트 물리적 분리
  ────────────────────────────────────────────────────────────
  [Level 2: 물리적 변조 증거 (Tamper-evident)]
  - 뜯으면 흔적이 남는 보안 봉인 씰(Seals), 코팅 적용
  - 역할 기반 인증(Role-based Auth), 검증된 OS 환경
  ────────────────────────────────────────────────────────────
  [Level 1: 기본적 암호화 기능 (기본 SW)]
  - 표준 암호 알고리즘 탑재 (AES, RSA 등), 물리적 보안 요구 없음
  - 일반 상용 OS에서 동작하는 소프트웨어 암호 라이브러리 허용
```

## 핵심 용어
- 영점화 (Zeroization): 공격자가 암호 모듈의 외피를 뜯거나 강제로 전압을 가하는 물리적 침입을 시도할 때, 내부 센서가 이를 감지하여 불휘발성 메모리에 저장된 모든 개인키와 마스터 비밀키를 1나노초 이내에 0(Zero)으로 덮어써 완전히 파괴하는 기능
- CMVP (Cryptographic Module Validation Program): 미국 NIST와 캐나다 CCCS가 공동 운영하며 FIPS 140 표준에 따라 민간 기업의 암호 모듈을 시험·평가하고 공식 인증서를 발급하는 프로그램 (한국의 KCMVP의 모태)

## 핵심 통찰
- 소프트웨어로 암호화를 아무리 잘해도 "루트 권한을 뺏긴 서버의 메모리 덤프" 앞에서는 무력함 → FIPS 140-2 Level 3 이상의 하드웨어 보안 모듈(HSM)이 필요한 이유는 개인키가 칩 밖으로 절대로 나가지 않기 때문임
- FIPS 140-2의 핵심 철학은 "물리적 보안(Physical Security)"과 "논리적 보안"의 결합임 → Level 1은 순수 소프트웨어이지만, Level 2부터는 물리적 씰(스티커), Level 3부터는 회로 센서, Level 4는 극한의 환경 공격(드라이아이스 냉각 등)까지 막아냄
- 현재는 후속 표준인 FIPS 140-3(ISO/IEC 19790 기반)으로 완전히 전환되고 있으므로, 신규 구축 시스템은 140-3 적합성을 함께 검토해야 함

## 이웃 토픽과 구분
- FIPS 140-2 vs 공통평가기준(CC 인증): FIPS 140 = 오직 "암호 모듈(Cryptographic Module)" 자체의 안전성만 전문 평가 / CC 인증 = 방화벽, 침입탐지시스템 등 IT "보안 완제품 시스템" 전체의 보안 기능을 평가

## 문제·원인·대책
- 사례: 클라우드 서버 내 소프트웨어 키 저장소(Keystore)가 관리자 계정 유출로 인해 복사되어 중요 고객 DB 암호화 키가 노출된 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 호스트 OS 침해로 인한 메모리 상주 암호화 마스터키 덤프 | FIPS Level 1 소프트웨어 암호 모듈 사용으로 물리/메모리 격리 부재 | FIPS 140-2 Level 3 인증을 획득한 클라우드 전용 HSM(CloudHSM) 도입 | 마스터키가 하드웨어 내부에서만 연산되어 외부 유출 0% 보장 |
| 암호 칩 케이스를 물리적으로 뚫어 키를 추출하는 침탐 공격 | 하드웨어 칩의 변조 감지 및 자동 소거 회로 미비 | Level 3/4 요구조건인 능동적 변조 탐지 센서 및 자동 영점화(Zeroization) 장착 | 케이스 손상 즉시 내부 키가 완전 소멸되어 물리 추출 무력화 |

## 이렇게 출제된다
- 제132회 4교시 1번: "FIPS(Federal Information Processing Standard) 140-2에 대하여 다음을 설명하시오." → 요구 포인트: Ⅰ FIPS 140-2 개념 및 CMVP + Ⅲ 4단계 보안 등급(Level 1~4) 비교 매트릭스 + Ⅵ 11개 보안 영역 및 FIPS 140-3 전환 시사점

## 내 의견
- [국내 KCMVP의 FIPS 140-3 상호인정협정(MRA) 추진] 국내 암호모듈 검증(KCMVP)은 해외에서 인정되지 않고, 외산 FIPS 인증 제품은 국내 공공기관에 납품할 수 없어 글로벌 진출과 기술 혁신에 거대한 장벽으로 작용함 → 나라면: 국내 KCMVP 기준을 ISO/IEC 19790 기반의 FIPS 140-3과 조화롭게 일치시키고, 미국 NIST와의 암호모듈 상호인정협정을 단계적으로 추진하여 국내 보안 기업의 수출 경쟁력을 확보
