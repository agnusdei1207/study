## 연관 키워드

- FIPS 140-2, FIPS 140-3, 암호 모듈 검증, CMVP, 보안 수준(Security Level), 탬퍼 저항성
- 자가 진단(Self-test), 제로화(Zeroization), HSM(Hardware Security Module), KMS
- CC 인증, KCMVP, ACVP, 역사적 목록(Historical List)

## Ⅰ. FIPS 140-2의 개요

- 핵심 요약 : 미국 연방 표준으로 암호 모듈의 보안성과 물리적 침해 방지를 4단계로 검증하던 기준이며, 2026년 전환으로 신규 조달 기준에서 물러남.
- 개념 : 미국 국립표준기술원(NIST, National Institute of Standards and Technology)이 제정한 **FIPS 140-2** (Federal Information Processing Standards Publication 140-2)로, 암호 모듈의 하드웨어, 소프트웨어, 펌웨어에 대한 보안, 무결성, 물리적 침해 방지 요구사항을 4단계 보안 수준으로 규정.
- 배경 및 필요성 : 공공과 금융의 암호 장비가 취약한 난수 생성, 부실한 키 관리, 물리적 공격에 노출되는 것을 막기 위해 객관적인 검증 기준이 필요해짐.
- 주요 목적 : 연방 정부와 규제 산업에서 민감 정보를 처리하는 암호 모듈의 안전성과 탬퍼 저항성을 공인된 절차로 보증.
- 전환 현황 : NIST 전환 일정에 따르면 FIPS 140-3은 2019년 9월 발효되었고, 신규 FIPS 140-2 인증은 2021년 9월 중단되었으며, 2026년 9월 21일을 마지막 활성 기준일로 하여 이후 FIPS 140-2 인증서는 역사적 목록으로 이동.

## Ⅱ. FIPS 140-2의 특징 및 장점

- 핵심 요약 : 4단계 보안 수준과 물리 대응, 자가 진단을 결합해 모듈의 신뢰 수준을 등급으로 제시하는 방식.

1. 4단계 보안 수준 : 소프트웨어 전용 Level 1부터 물리 침입 시 키를 지우는 Level 4까지 등급화 → 도입 환경에 맞는 요구 수준을 고를 수 있음.
2. 물리적 탬퍼 대응 : 개봉 흔적 표시, 침입 감지, 능동 제로화로 단계별 대응 → 하드웨어 키 유출 위험을 낮춤.
3. 자가 진단 : 전원 인가 시 무결성 점검과 난수 생성의 연속 동일값 차단 → 오동작과 변조를 조기에 감지.
4. 11개 영역 평가 : 사양, 인터페이스, 역할, 물리 보안, 키 관리 등을 포괄 검증 → 모듈 전반의 보증 수준 확보.

## Ⅲ. FIPS 140-2의 구조 (흐름)

- 핵심 요약 : 보안 수준이 올라갈수록 물리 대응 요구가 누적되는 계층 구조.
- **제로화** (Zeroization) : 침입이나 이상 상태를 감지하면 암호 키를 즉시 지우는 기능.
- **탬퍼 저항성** (Tamper Resistance) : 물리적 개봉이나 조작을 어렵게 하거나 즉시 감지하는 설계.

```text
[ FIPS 140-2 보안 수준 ]

Level 4 : 물리 침입 시 키 즉시 제로화
   ↓ 누적
Level 3 : 탬퍼 감지·저항, 신원 기반 인증
   ↓ 누적
Level 2 : 탬퍼 증거(봉인), 역할 기반 인증
   ↓ 누적
Level 1 : 승인 알고리즘 정확한 구현 검증
```

- 자가 진단 : 전원 인가 시 파워온 테스트, 난수 생성 시 조건부 자가 테스트를 수행해 모듈 오동작을 막음.

```text
[ 표준 전환 흐름 ]

2019년 9월 FIPS 140-3 발효
   ↓
2021년 9월 신규 FIPS 140-2 인증 중단
   ↓
2026년 9월 FIPS 140-2 인증서 역사적 목록 이동
```

## Ⅳ. FIPS 140-2와 유사 인증 제도의 비교

- 핵심 요약 : FIPS는 암호 모듈 단위의 물리·알고리즘 검증이고, CC는 IT 제품 전반의 보증, KCMVP는 국내 공공 시장 중심의 암호 모듈 검증.

| 비교 항목 | FIPS 140-2 / 140-3 | CC 인증 (Common Criteria) | KCMVP (국내 암호모듈 검증제도) |
| --- | --- | --- | --- |
| 검증 대상 | 암호 모듈 (SW, HW, 펌웨어) | IT 제품 전반 (방화벽, OS, 스마트카드 등) | 공공 도입 암호 모듈 (SW, HW) |
| 주관 기관 | 미국 NIST, 캐나다 CCCS | 국제 공통평가기준 승인 협정 (CCRA) | 국가정보원 및 관련 기관 |
| 등급 체계 | Level 1~4 | EAL 1~7 | 보안 1~4등급 |
| 핵심 평가 | 알고리즘 적합성, 키 관리, 탬퍼 대응 | 보안목표명세서 기반 기능과 보증 | 국내 표준 암호 (ARIA, SEED, LEA 등) |
| 통용 범위 | 북미 및 금융권 중심 사실상 표준 | CCRA 회원국 간 상호 인정 (등급별 범위 제한) | 국내 공공과 국방 시장 중심 |

## Ⅴ. FIPS 140-2의 한계와 방안

- 핵심 요약 : 클라우드의 물리 통제 부재, 긴 인증 기간, 비승인 알고리즘 차단을 전용 HSM, 자동 검증, 존 분리로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 가상화 환경의 물리 보안 검증 난제 | 물리 서버를 통제할 수 없어 탬퍼 저항과 전압 감시를 소프트웨어로 충족하기 어려움 | 인증된 전용 물리 HSM을 테넌트에 할당하는 하이브리드 구성 | 인증 HSM 사용 비율 |
| 긴 재인증 기간 | 소규모 패치에도 재인증이 필요해 CI/CD 배포 주기와 충돌 | NIST의 자동화 검증 프로토콜(ACVP, Automated Cryptographic Validation Protocol) 활용으로 알고리즘 검증 기간 단축 | 재인증 소요 기간 |
| 승인 알고리즘 제약 | FIPS 모드에서는 ChaCha20-Poly1305, Ed25519 등이 비승인으로 차단 | 승인 목록을 주기적으로 갱신하고, 업무 영역별로 FIPS 존과 비-FIPS 존을 분리 | 비승인 알고리즘 호출 건수 |

## Ⅵ. FIPS 140-2에 대한 기술사적 제언

- 핵심 요약 : 신규 조달과 설계는 FIPS 140-3 기준으로 옮기고, 국내외 인증을 추상화 계층으로 함께 수용하는 방향이 바람직함.
- 금융과 결제 카드 데이터를 처리하는 키 관리 환경에는 키 생성과 보관이 외부로 나가지 않는 FIPS 140-3 Level 3 수준의 HSM을 기준으로 두는 것이 적절하다.
- 부채널 공격에 대한 평가가 강화된 FIPS 140-3 시험 기준을 설계 단계부터 반영하여, 전력 분석과 전자파 분석에 견디는 하드웨어를 확보하는 것이 바람직하다.
- 국내와 해외 시장을 함께 겨냥하는 제품은 KCMVP와 FIPS 검증을 암호 추상화 계층 뒤에서 교체할 수 있도록 설계하는 것이 유연하다.

## Ⅶ. 결론

- 핵심 요약 : FIPS 140-2는 암호 모듈 검증의 기준점이었으나, 2026년 전환으로 역사적 목록에 편입되어 신규 조달은 FIPS 140-3을 기준으로 해야 함.
- 시사점 : 기존 140-2 인증 모듈은 운용 중 기간 동안 쓰일 수 있으나, 신규 시스템은 140-3 인증 여부를 먼저 확인하는 것이 필요.
