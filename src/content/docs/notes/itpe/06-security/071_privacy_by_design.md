## 연관 키워드

- 개인정보보호 중심 설계(Privacy by Design), 기본 설정으로서의 프라이버시(Privacy as Default), GDPR
- 영향평가(DPIA), 데이터 최소화, 가명화, 프라이버시 강화 기술(PET)
- 차분 프라이버시, 기밀 컴퓨팅, 동형암호, 연합학습, 합성 데이터
- 암호화 파기, WORM, 다크 패턴

## Ⅰ. 개인정보보호 중심 설계(Privacy by Design)의 개요

- 핵심 요약 : 사후 패치가 아니라 기획 단계부터 프라이버시 통제를 시스템의 기본 속성으로 내장하는 설계 원칙.
- 개념 : 제품, 서비스, 인프라의 기획과 설계 단계부터 프라이버시 보호를 기본 속성으로 내장하는 공학적 설계 철학인 **개인정보보호 중심 설계** (Privacy by Design).
- 배경 및 필요성 : 구축을 마친 뒤 보안을 덧붙이는 방식으로는 대규모 유출과 규제 위반을 막기 어려워, 생명주기 전 단계에 보호 기술과 기본 비공개 설정을 넣는 방식이 요구됨.
- 주요 목적 : 유출 사고의 사전 예방, 기본 설정에 따른 정보주체 권리 보장, GDPR(General Data Protection Regulation) 제25조와 국내 개인정보 보호법상 준거성 확보.

## Ⅱ. 개인정보보호 중심 설계(Privacy by Design)의 특징 및 장점

- 핵심 요약 : 일곱 가지 원칙이 사전 예방과 기본 비공개를 출발점으로 프라이버시와 사업 기능을 함께 달성하는 구조.

1. **사전 예방** (Proactive not Reactive) : 위험을 사고 전에 예측해 설계에 반영 → 사후 대응 비용과 피해 축소.
2. **기본 설정으로서의 프라이버시** (Privacy as Default) : 이용자가 조작하지 않아도 초기 설정이 최고 수준의 보호를 제공 → 권리 행사의 실효성 확보.
3. **설계 내재화** (Privacy Embedded into Design) : 부가 기능이 아닌 아키텍처의 필수 요소로 편입 → 사후 보완 비용 감소.
4. **포지티브 섬** (Positive-Sum) : 프라이버시와 사업 목표를 이분법으로 보지 않고 함께 충족 → 현업의 적용 저항 완화.
5. **종단 간 전주기 보호** (End-to-End Lifecycle Protection) : 수집부터 파기까지 전 구간을 보호 → 생명주기 중간의 보호 공백 제거.
6. **가시성과 투명성** (Visibility and Transparency) : 처리 과정과 통제를 독립적으로 검증할 수 있도록 공개 → 이용자 신뢰 확보.
7. **정보주체 존중** (Respect for User Privacy) : 직관적인 동의 인터페이스와 권리 행사 수단 제공 → 동의의 실질화.

## Ⅲ. 개인정보보호 중심 설계(Privacy by Design)의 구조 (흐름)

- 핵심 요약 : 기획부터 사후 관리까지 다섯 단계에 프라이버시 통제를 순서대로 배치하고, 그 중심에 영향평가를 두는 구조.
- 설계 게이트 : 기획 단계에서 개인정보 영향평가(DPIA, Data Protection Impact Assessment)를 선행해 수집 범위와 위험을 확정.
- **프라이버시 강화 기술** (PET, Privacy-Enhancing Technology) : 가명화와 토큰화, 차분 프라이버시(DP, Differential Privacy), 기밀 컴퓨팅(TEE, Trusted Execution Environment), 동형암호(HE, Homomorphic Encryption) 등 데이터를 노출하지 않고 쓰는 기술 묶음.

```text
[ 1. 기획·요구 분석 ]
   ↓ 최소 수집 요건, 영향평가 선행
[ 2. 아키텍처 설계 ]
   ↓ 가명화, 테이블 분리, 역할 기반 접근
[ 3. 구현·테스트 ]
   ↓ 전송·저장 암호화, 자동 파기 트리거
[ 4. 배포·운영 ]
   ↓ 이해하기 쉬운 처리방침, 투명한 동의
[ 5. 사후 관리 ]
   열람·정정·삭제권 보장, 감사 로그 기록
```

## Ⅳ. 개인정보보호 중심 설계(Privacy by Design)의 비교

- 핵심 요약 : 생명주기 단계마다 위험의 성격이 다르므로, 수집은 최소화, 이용은 분석 기술, 파기는 키 폐기로 대응 기술이 달라지는 구조.

| 생명주기 | 주요 위험 | 설계 기술 |
| --- | --- | --- |
| 수집 | 과도한 수집, 다크 패턴(Dark Pattern) 유도 | 입력 항목 최소화, 선택 항목 기본 해제, 주민등록번호 수집 원천 차단 |
| 저장 | DB 유출, 관리자의 직접 열람 | 필드 단위 AES(Advanced Encryption Standard) 암호화, KMS(Key Management Service) 기반 키 분리, 가명화와 토큰화 |
| 이용 | 목적 외 이용, 내부자 오남용 | 차분 프라이버시 기반 통계 분석, 기밀 컴퓨팅 연산, WORM(Write Once Read Many) 감사 로그 |
| 제공 | 제3자 제공 시 재식별 위험 | 안전한 데이터 결합 전문기관 활용, 동형암호 기반 암호문 상태의 연계 |
| 파기 | 백업 잔존, 불완전 삭제 | 보유기간 도달 시 자동 파기, 암호화 키 폐기 |

- 선택 기준 : 데이터의 민감도와 제공 범위를 기준으로, 최소 수집으로 충분한지 먼저 판단하고 나머지 위험을 기술로 보완.

## Ⅴ. 개인정보보호 중심 설계(Privacy by Design)의 한계와 방안

- 핵심 요약 : 수익 모델과의 충돌, 분산 저장소의 잔존 데이터, 기만적 UI라는 세 한계를 연합학습, 암호화 파기, 기본값 강제로 통제하는 구조.

```text
[ 암호화 파기 (Crypto-shredding) ]

레코드 → 사용자 전용 키로 암호화
   ↓ 탈퇴 요청
해당 사용자 키만 영구 폐기
   ↓
백업본 포함 전체 복호화 불가
```

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 수익 모델과의 상충 | 타깃 광고와 빅데이터 분석 중심의 수익 구조로 현업이 적용을 기피 | 원본 데이터를 직접 결합하는 대신 연합학습(Federated Learning)과 합성 데이터(Synthetic Data)를 활용해 효용과 보호를 함께 달성 | 원본 데이터 외부 반출 건수 |
| 분산 저장소의 잔존 데이터 | 마이크로서비스와 다중 백업 환경에서 탈퇴 정보가 완전히 삭제되지 않음 | 레코드를 사용자 전용 키로 암호화하고, 탈퇴 시 해당 키만 폐기하는 암호화 파기(Crypto-shredding) 자동화 | 파기 완료 확인율 |
| 기만적 UI, 다크 패턴 | 기본 체크, 탈퇴 경로 은폐로 동의를 왜곡 | Privacy as Default를 UI/UX 가이드에 강제 반영하고, 개인정보보호위원회의 다크패턴 가이드라인 기준으로 정기 검수 | 동의 화면 점검 결함 건수 |

## Ⅵ. 개인정보보호 중심 설계(Privacy by Design)에 대한 기술사적 제언

- 핵심 요약 : 프라이버시를 개별 기능 점검이 아닌 조직의 설계 의사결정 기준으로 정착.

1. 기획 단계에서 영향평가를 의무 절차로 두고, 수집 항목은 서비스 목적에 필요한 최소 범위로 제한하는 기준을 정책으로 정한다.
2. 개발과 운영 조직은 프라이버시 강화 기술의 적용 기준을 사내 표준으로 만들어, 데이터 성격에 따라 가명화, 차분 프라이버시, 기밀 컴퓨팅을 선택하도록 한다.
3. 최고경영진은 프라이버시를 제품 품질 지표에 편입하고, 신규 서비스 출시 승인 과정에서 프라이버시 설계 검토를 필수 단계로 두어 조직 문화로 정착시킨다.

## Ⅶ. 결론

- 핵심 요약 : 개인정보보호 중심 설계는 사후 보호가 아니라 설계 단계에서 프라이버시를 기본 속성으로 내장하는 원칙.
- 시사점 : 최소 수집, 기본 비공개, 암호화 파기를 설계 표준으로 고정할 때 규제 준수와 사고 억제를 함께 얻음.
