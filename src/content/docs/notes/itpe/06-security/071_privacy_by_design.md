## 30초 인출

- **본질:** Privacy by Design(PbD)은 개인정보 보호를 제품·서비스·업무의 설계와 기본 운영에 반영하는 접근이다.
- **메커니즘:** 처리의 목적·범위·위험을 고려해 필요한 개인정보만 처리하고, 설계 단계와 실제 처리 중에 적절한 기술적·조직적 보호조치를 적용한다.
- **법적 연결:** GDPR 제25조는 설계 및 기본 설정에 의한 정보보호를 규정한다. 기본 설정은 각 목적에 필요한 개인정보만 처리하고, 필요한 기간과 접근 범위를 제한한다.

<details>
<summary>핵심 용어</summary>

- **Privacy by Design(PbD):** 개인정보 보호를 정보시스템뿐 아니라 업무 절차와 서비스 운영의 설계에 반영하는 접근이다.
- **Privacy by Default:** 별도 변경 없이 기본 설정만으로 각 처리 목적에 필요한 범위의 개인정보만 처리하도록 하는 원칙이다.
- **데이터 최소화:** 목적에 필요한 개인정보만 수집·이용하도록 처리 범위를 제한하는 원칙이다.
- **개인정보 영향평가(DPIA 등):** 개인정보 처리의 위험을 식별·평가하고 필요한 보호조치를 결정하는 평가다. 적용 요건은 법령·조직·처리 위험에 따라 다르다.
</details>

> Privacy by Design의 개념과 기본 원칙, 설계·기본 설정에서의 적용 방안을 설명하시오.

---
## 1교시 10점 답안

### 1. 정의·목적

- **정의:** PbD는 개인정보 보호를 서비스·시스템·업무의 설계와 기본 운영에 반영하는 접근이다.
- **목적:** 개인정보 처리 과정에서 발생할 수 있는 위험을 사전에 고려하고 적절한 보호조치를 구현한다.

### 2. 일곱 기본 원칙

| 원칙 | 핵심 |
|---|---|
| 사전 예방 | 문제 발생 후 조치보다 위험을 먼저 식별·예방 |
| 기본값 프라이버시 | 별도 조작 없이 필요한 최소 정보만 처리 |
| 설계 내재화 | 개인정보 보호조치를 구조·기능에 반영 |
| 포지티브섬 | 개인정보 보호와 업무 기능을 함께 고려 |
| 전 생애주기 보호 | 수집부터 이용·보관·파기까지 보호 |
| 가시성과 투명성 | 처리와 보호조치를 이해·점검할 수 있게 함 |
| 사용자 프라이버시 존중 | 정보주체의 권리·이익과 선택을 고려 |

**제언:** 서비스 기획부터 데이터 필요성·기본 공개 범위·보유기간을 검토하고 변경 시 다시 평가한다.

---
## 2~4교시 25점 답안

### Ⅰ. 개념과 목적

PbD는 개인정보 보호를 시스템·업무 설계와 기본 운영에 반영해 처리 전 과정의 위험을 관리하는 접근이다. Ann Cavoukian이 정리한 일곱 기본 원칙은 예방·기본값·설계 내재화부터 투명성과 사용자 존중까지 개인정보 보호를 조직 운영에 포함한다.

| 설계 관점 | 적용 질문 |
|---|---|
| 목적·필요성 | 이 개인정보 처리가 명확한 목적에 필요한가? |
| 데이터 범위 | 목적에 필요한 항목과 정밀도만 처리하는가? |
| 위험·보호조치 | 접근·이용·보관·공유에서 권리 침해 위험을 줄였는가? |

### Ⅱ. 일곱 기본 원칙

| 원칙 | 설명 |
|---|---|
| 사전 예방, 사후 조치가 아님 | 위험을 미리 식별하고 설계 단계에서 줄임 |
| 기본 설정으로서의 프라이버시 | 기본값으로 목적에 필요한 최소 정보만 처리 |
| 설계에 내재된 프라이버시 | 보호조치를 기능과 아키텍처에 포함 |
| 완전한 기능성, 포지티브섬 | 개인정보 보호와 서비스의 다른 목적을 함께 추구 |
| 종단 간 보안, 생애주기 보호 | 수집부터 파기까지 보호·책임을 이어감 |
| 가시성과 투명성 | 처리와 보호조치를 이해하고 검증할 수 있게 함 |
| 사용자 프라이버시 존중 | 정보주체의 이익·권리·선택을 중심에 둠 |

### Ⅲ. 생명주기별 적용

개인정보가 어디에서 왜 수집되고 어디로 전달·보관·파기되는지 파악한 뒤, 각 단계의 필요성과 위험에 맞춰 보호조치를 둔다. 처리 위험이 법정 평가 요건에 해당하면 개인정보 영향평가 등 요구되는 절차를 수행한다.

```mermaid
flowchart LR
  A[기획·목적·필요성 검토] --> B[수집 범위·기본값 설계]
  B --> C[접근·이용·공유 보호조치]
  C --> D[보유기간·파기 설계]
  D --> E[운영 중 권리·위험·변경 점검]
  E -->|개선사항 반영| A
```

### Ⅳ. ICT 적용 통제

PbD는 하나의 기술 제품이 아니라 처리 목적과 위험에 따라 선택하는 설계·운영 접근이다. 암호화·가명처리 등 개인정보 보호 강화 기술은 위험 저감 수단으로 활용하되, 적법한 처리 근거나 정보주체 권리를 대신하지 않는다.

| 적용 영역 | 설계·운영 통제 | 확인 사항 |
|---|---|---|
| 데이터 수집 | 목적별 최소 항목·정밀도 설정 | 불필요한 선택 항목·기본 수집 제거 |
| 접근·공유 | 최소 권한, 목적별 접근과 기록 | 내부·외부 이용 범위와 책임 관리 |
| 보관·삭제 | 목적·기간에 따른 보유와 파기 | 백업·로그·파생 데이터 처리 검토 |
| 분석·AI | 데이터 출처·목적·민감도·재사용 검토 | 가명처리만으로 익명화·적법성으로 단정하지 않음 |
| 투명성·권리 | 이해하기 쉬운 처리 안내와 권리행사 경로 | 동의가 법적 근거인 경우 자유롭고 구체적인 선택 보장 |

### Ⅴ. 기술사적 제언

| 문제 | 해결 방안 |
|---|---|
| 개발 완료 뒤 개인정보 요구를 반영해 구조 변경 비용·위험 발생 | 요구사항·데이터 흐름·위협 모델 검토를 설계 승인에 포함 |
| 기본 설정이 과도한 수집·공개를 허용 | 목적별 필수 데이터와 접근 범위를 기본값으로 설정 |
| 암호화·가명처리를 법적 근거·정보주체 권리의 대체로 오인 | 기술적 보호와 적법성·투명성·권리 보장을 함께 검토 |
| 탈퇴 후 백업 등에서 데이터가 계속 남음 | 보유기간·파기 요건을 주 데이터와 복제·백업 수명주기에 반영 |
