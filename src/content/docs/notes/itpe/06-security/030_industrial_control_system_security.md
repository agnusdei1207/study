## 30초 인출

- **본질:** **산업제어시스템(ICS)** 은 물리 공정을 감시·제어하는 장치와 소프트웨어의 결합
- **메커니즘:** 센서 측정 → 제어기 판단 → 구동기 동작 → 공정 상태 변화·재측정
- **보안 관점:** 안전·신뢰성·가용성·실시간 성능에 미치는 영향을 고려해 통제를 적용

<details>
<summary>핵심 용어</summary>

- **산업제어시스템(ICS, Industrial Control System):** 산업 공정을 모니터링·제어하는 시스템의 통칭
- **OT (Operational Technology):** 물리 환경·장치·공정을 감시하거나 변경하는 프로그래머블 시스템·장치
- **PLC (Programmable Logic Controller):** 센서 입력과 제어 로직을 처리해 산업 설비 동작을 제어하는 장치
- **RTU (Remote Terminal Unit):** 원격 현장의 계측·상태를 취득하고 중앙 제어와 연결하는 장치
- **SCADA (Supervisory Control and Data Acquisition):** 원격 공정의 상태를 감시하고 감독 제어를 지원하는 시스템
- **HMI (Human-Machine Interface):** 운영자와 제어시스템 간 상태 확인·명령 입력을 위한 인터페이스
- **IACS (Industrial Automation and Control Systems):** ISA/IEC 62443에서 다루는 산업 자동화·제어시스템 범위
- **Purdue 모델:** 정보·제어 기능을 계층으로 이해하는 참조 모델로, 모든 현장의 필수 물리 망 설계도가 아님
- **IT (Information Technology, 정보기술):** 정보의 처리·저장·전달을 다루는 컴퓨팅 기술
- **NIST (National Institute of Standards and Technology):** 미국 연방의 표준·기술기관
- **ISA (International Society of Automation):** 산업 자동화 관련 표준·전문기술을 다루는 국제 협회
- **IEC (International Electrotechnical Commission):** 전기·전자·관련 기술 국제표준을 개발하는 기관
</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **산업제어시스템(ICS)** 은 물리 공정을 감시·제어하는 장치와 소프트웨어의 결합 |
| 목적 | 설비·공정의 안전하고 신뢰성 있는 운전과 통제 유지 |

NIST의 OT 보안지침은 OT 특유의 성능·신뢰성·안전 요구를 고려한 보안설계를 제시.

## Ⅱ. 구성과 공정 흐름

| 구성요소 | 공정상 역할 |
|---|---|
| 센서·계측 | 물리 상태를 측정해 제어 입력 제공 |
| 제어기(PLC·RTU) | 로직·설정에 따라 출력·상태를 처리 |
| 구동기 | 밸브·모터 등 물리 동작 수행 |
| 감독계층(SCADA·HMI) | 상태 표시와 운영자 설정·명령 입력 |

```text
공정변수 → 센서 → 제어기 → 구동기 → 공정변화
                       ↕
                감독·운영자 인터페이스
```

## Ⅲ. IT·OT 보안 요구와 위협

| 차이·위험 | 보안 영향 | 설계 고려 |
|---|---|---|
| 실시간성·가용성 | 지연·중단이 생산·서비스에 영향 | 부하·가용성·장애 전환 시험 |
| 안전·물리 영향 | 제어 변경이 인명·설비·환경에 영향 가능 | 안전절차와 사이버 위험관리 연계 |
| 이기종·장수명 설비 | 패치·인증·암호화 제약 | 자산별 위험평가·보완통제 |
| 원격접속·이동식 매체 | 악성코드·계정 악용·영역 간 이동 | 접속 중계·승인·매체 검사·기록 |

기밀성·무결성·가용성의 우선순위를 IT·OT 전체에 일률 적용하지 않고 공정 위험·운전 요구에 따라 결정.

## Ⅳ. 영역분리·운영 통제

ISA/IEC 62443의 영역(zone)·통신경로(conduit) 개념은 위험을 기준으로 자산을 구분하고 경계 통신을 통제하는 참조. Purdue 모델도 계층 이해를 돕는 구조이며, 그대로 복제하는 필수 토폴로지는 아님.

```text
기업 IT 영역
     │ 허용 통신·감시된 경계
     ↓
중계·운영지원 영역
     │ 승인된 제어 통신경로
     ↓
제어 영역 ──> 현장제어기·센서·구동기
```

| 통제영역 | 운영 방안 |
|---|---|
| 자산·통신 | 자산·프로토콜·업무 흐름 목록화, 필요한 통신만 허용 |
| 계정·원격관리 | 개인 식별·최소권한·시간제한 접근, 세션 기록·승인 |
| 취약점·변경 | 운영 영향·벤더 지원·안전 확인 후 시험·정비 시간에 변경 |
| 감시·대응 | 수동형 통신 감시, 공정 이상징후 연계, 안전한 수동운전·복구 훈련 |

## Ⅴ. 한계와 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| IT용 보안도구를 공정시험 없이 적용하면 지연·가용성·안전 영향 가능 | 자산·공정 위험평가를 바탕으로 수동형 감시와 시험구간 검증부터 단계 확대 |
| 평면 네트워크와 상시 원격접속은 침해 시 제어영역까지 영향 확산 가능 | 업무흐름 기반 영역분리, 승인된 중계경로, 시간제한 계정·감사기록 적용 |
