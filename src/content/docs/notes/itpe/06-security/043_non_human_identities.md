## 지식 로드맵 내 현재 위치

접근통제·IAM → 머신·워크로드 신원 → 비인간 신원(NHI) 보안 및 무시크릿(Secretless) 아키텍처

## 30초 인출

- **본질:** 서비스 계정, API 키, 토큰, 인증서 등 사람이 아닌 애플리케이션, 마이크로서비스, 클라우드 워크로드가 리소스에 접근하기 위해 사용하는 디지털 신원
- **메커니즘:** 워크로드 신원 증명(SPIFFE/SPIRE) → OIDC 기반 단기 토큰 발급 → 시크릿 금고(Vault) 동적 주입 → 자동 회전(Rotation) 및 폐기
- 통찰: 하드코딩된 장기 시크릿 노출과 고아 신원의 권한 누적을 방지하기 위해 무시크릿(Secretless) 페더레이션과 CIEM 기반 일몰(Sunset) 정책 필수

<details>
<summary>핵심 용어</summary>

- **NHI (Non-Human Identity):** 인간 사용자가 아닌 소프트웨어 봇, 서비스 계정, CI/CD 러너, 컨테이너 워크로드에 부여된 시스템 접근 자격증명
- **머신 대 인간 비율:** 클라우드 네이티브 및 MSA 환경 확산으로 기업 내 NHI 수는 인간 계정 대비 10배~45배 이상 급증
- **SPIFFE / SPIRE:** 이기종 분산 클라우드 환경에서 서비스 워크로드에 표준 암호학적 신원(SVID)을 발급하고 상호 인증을 지원하는 오픈소스 표준
- **고아 신원 (Orphaned NHI):** 생성한 개발자의 퇴사나 프로젝트 종료 후에도 회수되지 않고 장기간 유효한 상태로 방치된 서비스 계정
- **무시크릿 아키텍처 (Secretless):** 소스코드나 서버 설정 파일에 API 키를 영구 저장하지 않고, OIDC 토큰 교환을 통해 1시간 미만의 단기 STS 토큰을 동적 주입받는 구조
</details>

## 2~4교시 예상문제 (25점)

> 클라우드 네이티브 및 마이크로서비스 환경에서 비인간 신원(NHI)의 급증 배경과 보안 취약점(시크릿 하드코딩, 고아 계정, 과다 권한)을 설명하고, SPIFFE/SPIRE 기반 워크로드 신원 인증 및 무시크릿(Secretless) 엔지니어링 방안을 제시하시오. (기출·140회 1교시 11번 변형·25점)

---
## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **비인간 신원(NHI, Non-Human Identities)** 은 인간 사용자가 아닌 애플리케이션, 서비스 계정(Service Account), CI/CD 파이프라인, 컨테이너, 자동화 봇 등이 다른 시스템 및 클라우드 API에 접근하기 위해 부여받은 디지털 식별자 및 자격증명의 총칭 |
| 목적 | 시스템 간 머신-투-머신(M2M) 통신의 안전한 인증·인가, 하드코딩된 정적 시크릿 제거, 마이크로서비스 간 최소 권한 제로트러스트 통제 |

클라우드 전환 및 마이크로서비스 아키텍처(MSA) 확산으로 인해 기업 내 자격증명의 90% 이상이 NHI로 구성되면서 사이버 공격자의 최우선 표적으로 부상.

## Ⅱ. 비인간 신원(NHI)의 특징 및 취약 요인

| 특징 구분 | 기술적 내용 | 보안 취약 요인 |
|---|---|---|
| **폭발적 수량 증가** | 인간 임직원 수 대비 10배~45배에 달하는 NHI 생성 | 전사 자산 인벤토리 파악 불가 (가시성 상실) |
| **다요소 인증(MFA) 불가**| 사람이 아니므로 SMS, OTP, 지문 등 대화형 MFA 적용 불가 | **API 키나 비밀 토큰 단 1회 유출 시 즉시 무단 접속** |
| **정적 시크릿 장기 보존** | 환경 변수(`.env`), GitHub 소스코드, 설정 파일에 하드코딩 | 키 회전(Rotation) 주기가 수개월~수년간 방치 |
| **과도한 권한 부여** | 개발 편의를 위해 `AdministratorAccess`, 와일드카드(`*`) 부여 | 단일 서비스 계정 탈취 시 클라우드 인프라 전역 장악 |

## Ⅲ. NHI 관리 아키텍처 및 워크로드 신원 연동

```text
[무시크릿(Secretless) 기반 워크로드 신원(SPIFFE/OIDC) 인증 메커니즘]

 [GitHub Actions / Pod]              [클라우드 IdP: AWS/Azure]            [시크릿 관리자: Vault]
         |                                     |                                   |
         | 1. OIDC ID 토큰 요청                |                                   |
         | (워크로드 환경 증명)                |                                   |
         | ----------------------------------> |                                   |
         | 2. 서명된 OIDC JWT 토큰 발급        |                                   |
         | <---------------------------------- |                                   |
         |                                     |                                   |
         | 3. OIDC 토큰 제시 및 임시 권한 요청 |                                   |
         | ----------------------------------------------------------------------> |
         |                                     | 4. OIDC 서명 검증 및 역할 대조    |
         |                                     | <-------------------------------- |
         | 5. 1시간 유효 단기 STS 토큰 동적 주입                                   |
         | <---------------------------------------------------------------------- |
         | (정적 비밀키 보관 없이 API 안전 호출)
```

### 1. 주요 NHI 자격증명 유형별 비교

| NHI 유형 | 주요 용도 | 위험 요소 및 관리 통제 |
|---|---|---|
| **서비스 계정 (Service Account)** | 쿠버네티스 파드, 클라우드 VM의 기본 IAM 실행 권한 | 네임스페이스 격리 및 자동 토큰 마운트 제한 |
| **API 키 (API Key)** | 서드파티 SaaS 연동 (Slack, OpenAI, SendGrid) | 소스코드 스캔(TruffleHog), 정기 자동 회전 |
| **OAuth 클라이언트 크리덴셜** | 마이크로서비스 간(M2M) 백엔드 API 상호 호출 | Client Secret 유출 방지 및 단기 Access Token 발급 |
| **mTLS 인증서** | 제로트러스트 서비스 메시(Istio) 간 암호화 통신 | SPIFFE 기반 자동 발급 및 24시간 미만 단기 수명 |

## Ⅳ. 인간 신원(Human) vs 비인간 신원(NHI) 비교

| 비교 항목 | 인간 신원 (Human Identity) | 비인간 신원 (Non-Human Identity) |
|---|---|---|
| **신원 주체** | 임직원, 고객, 파트너 (자연인) | **애플리케이션, 봇, 서버리스 함수, 파이프라인** |
| **수량 규모** | 사원 수에 비례 (수백~수천 개) | **인간 계정의 수십 배 (수만~수십만 개)** |
| **생애주기 관리** | 입사 $\rightarrow$ 부서이동 $\rightarrow$ 퇴사 (HR 시스템 연동) | **빌드 $\rightarrow$ 배포 $\rightarrow$ 릴리즈 (DevOps 파이프라인 연동)** |
| **인증 메커니즘** | ID/PW, SSO, 생체인증, FIDO2, MFA | **API Key, Private Key, JWT 토큰 (MFA 불가)** |
| **주요 위협** | 피싱 메일, 패스워드 스프레잉 | **GitHub 소스코드 노출, 고아 계정, 과다 권한** |
| **관리 솔루션** | IAM, IGA, PAM | **NHI 관리 플랫폼, 시크릿 금고(Vault), CIEM** |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **소스코드 및 CI/CD 파이프라인 내 영구 시크릿 하드코딩 노출**<br>개발자가 빠른 배포를 위해 장기 유효기간을 가진 AWS Access Key나 DB 패스워드를 코드에 기록하여 GitHub 퍼블릭 커밋 시 수 초 만에 탈취 | **Git-secrets 프리커밋 차단 및 OIDC 기반 무시크릿(Secretless) 아키텍처**<br>개발자 로컬 환경에 Git Pre-commit Hook(TruffleHog)을 강제하여 시크릿 탐지 시 커밋을 원천 차단하고, GitHub Actions와 AWS IAM 간 OIDC 페더레이션을 구축하여 영구 시크릿을 없애고 1시간 만료의 동적 단기 토큰만 사용 |
| **퇴사자 및 사장된 프로젝트의 '고아 신원(Orphaned NHI)' 방치**<br>서비스 계정을 생성한 담당자가 퇴사하거나 테스트 컨테이너가 삭제된 후에도 클라우드 IAM에 관리자급 권한을 가진 계정이 수년간 삭제되지 않고 잔존 | **CIEM(클라우드 인프라 권한 관리) 기반 감사 및 일몰(Sunset) 정책 자동화**<br>CIEM을 통해 클라우드 전역을 전수 스캔하여 90일 이상 API 호출이 없는 유휴 NHI는 자동으로 권한을 박탈하고, 서비스 배포 시 만료 기한(TTL)을 필수로 기재하는 신원 일몰 정책 강제 |

## Ⅵ. 제언

```text
[전사 NHI 제로 트러스트 거버넌스 3단계 프레임워크]

 +--------------------+     +---------------------+     +--------------------+
 | 1. 자산 디스커버리 | --> | 2. 무시크릿 전환    | --> | 3. 런타임 이상 탐지|
 | 전사 API 키 / 토큰 |     | OIDC 페더레이션     |     | 비정상 API 호출 패턴|
 | 인벤토리 100% 가시화|    | HashiCorp Vault 도입|     | 머신러닝 실시간 차단|
 +--------------------+     +---------------------+     +--------------------+
```

| 구현 계층 | 추천 솔루션 및 표준 | 보안 공학적 목표 |
|---|---|---|
| **신원 표준** | SPIFFE / SPIRE 표준 프레임워크 | 이기종 쿠버네티스/클라우드 워크로드에 고유 신원 부여 |
| **시크릿 관리** | HashiCorp Vault, AWS Secrets Manager | 정적 API 키를 동적 자격증명으로 100% 전환 |
| **권한 통제** | CIEM (Wiz, Prisma Cloud), OPA Rego | 과도한 와일드카드(`*`) 권한 최소화 및 고아 신원 제거 |

NHI 보안은 기존 인적 IAM 솔루션으로는 해결할 수 없으므로, 소스코드 정적 스캔부터 런타임 동적 토큰 주입에 이르는 전 생애주기 무시크릿(Secretless) 파이프라인 구축 권장.
