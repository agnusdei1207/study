- **메커니즘:** 사용자 데이터와 실행 구문을 문자열로 결합 → 해석기가 입력을 명령으로 실행.
- **핵심 대응:** 데이터와 명령 분리, 허용된 값 검증, 실행 계정 최소 권한.

<details>
<summary>핵심 용어</summary>

- **인젝션(Injection) 공격**: 외부 입력을 명령·쿼리 문맥에 삽입해 원래 의도와 다른 실행을 유도하는 공격.
- **SQL 인젝션**: 입력을 SQL 구문으로 해석하게 해 데이터베이스 질의를 바꾸는 공격.
- **매개변수화 질의**: SQL 구문과 값의 결합을 구조적으로 분리하는 질의 방식.
- **허용목록 검증**: 입력값을 사전에 허용한 형식·범위와 비교하는 검증.
- **최소 권한**: 계정과 프로세스에 필요한 권한만 부여하는 원칙.

### Ⅱ. 발생 구조와 방어

```text
취약: 코드 문자열 + 사용자 입력 → 해석기 실행
안전: 고정된 명령 구조 + 별도 값 바인딩
```

| 해석기 | 공격 예 | 우선 방어 |
|---|---|---|
| SQL | 질의 조건 변경 | 매개변수화 질의 |
| OS 셸 | 추가 명령 실행 | 셸 호출 회피·인수 분리 |

**제언:** 외부 입력이 해석기에 도달하는 경로를 찾고 값 바인딩 여부를 우선 시험.

## 2~4교시 25점 답안

## Ⅰ. 인젝션 공격의 정의와 목적

| 구분 | 내용 |
|---|---|
| 정의 | **인젝션(Injection) 공격**은 외부 입력을 명령·쿼리 일부로 해석하게 해 의도와 다른 실행을 유도하는 공격 |
| 목적 | 데이터·명령 경계의 붕괴를 막아 비인가 조회·변경·실행 예방 |

특정 특수문자만의 문제가 아니라 신뢰할 수 없는 값을 실행 문맥에 섞는 설계의 문제.

## Ⅱ. 발생 구조와 유형

```text
취약: 코드 문자열 + 사용자 입력 → 해석기 실행
안전: 고정된 명령 구조 + 별도 값 바인딩
```

| 유형 | 경계 붕괴 | 영향 |
|---|---|---|
| SQL 인젝션 | 데이터가 질의 구문으로 해석 | 비인가 조회·변경 |
| OS 명령 인젝션 | 값이 셸 문법으로 해석 | 명령 실행 |
| 템플릿·검색식 인젝션 | 값이 해당 엔진 문법으로 해석 | 출력 조작·권한 확대 |

## Ⅲ. 설계·개발 방어

```text
외부 입력
    ↓ 타입·길이·허용값 확인
안전한 API로 값 전달
    ↓ 코드·데이터 분리
해석기는 고정된 구문만 실행
```

| 우선순위 | 통제 | 유의점 |
|---|---|---|
| 1 | 안전한 API·매개변수화 | SQL 값 바인딩; 식별자는 별도 허용목록 |
| 2 | 형식·범위 검증 | 단독으로 코드·데이터 분리 대체 불가 |
| 3 | 문맥별 이스케이프 | 안전한 API 사용이 어려울 때 보조 적용 |

정규식 하나로 모든 해석기의 문법을 차단한다는 방식은 우회 가능.

## Ⅳ. 운영·검증 체계

```text
입력 지점 목록화
    ↓ 해석기 호출까지 데이터 흐름 추적
매개변수화·권한 점검
    ↓ 공격 입력 시험
발견된 경로 수정·재시험
```

| 확인 대상 | 이유 |
|---|---|
| 데이터베이스 계정 권한 | 성공한 공격의 피해 제한 |
| 오류·로그 | 공격 흔적 확인, 민감정보 노출 방지 |
| 테스트 | 우회 문자열보다 데이터 흐름과 실행 결과 확인 |

## Ⅴ. 한계와 제언

| 한계 | 대응 |
|---|---|
| 웹 방화벽·문자 차단에만 의존하면 새 입력 형태가 우회 | 해석기별 안전한 API와 값 바인딩을 기본 통제로 채택 |
| SQL만 검사하면 셸·템플릿 호출이 남음 | 모든 외부 입력의 해석기 도달 경로를 같은 점검 체계에 포함 |
