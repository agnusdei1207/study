## 연관 키워드

- OWASP LLM Top 10, 프롬프트 인젝션, 민감정보 노출, 공급망 취약점, 데이터 및 모델 중독
- 부적절한 출력 처리, 과도한 대행, 시스템 프롬프트 노출, 벡터 및 임베딩 취약점
- 오정보, 무제한 자원 소비, 검색 증강 생성(RAG), 레드티밍

## Ⅰ. OWASP LLM Top 10(2025)의 개요

- 핵심 요약 : 대규모 언어 모델 기반 애플리케이션의 대표 보안 위험 10개를 정리한 공통 기준.
- 개념 : 대규모 언어 모델(LLM, Large Language Model) 기반 애플리케이션의 대표 보안 위험 10개를 정리한 **OWASP LLM Top 10** (OWASP(Open Worldwide Application Security Project)가 발간한 목록).
- 배경 및 필요성 : 생성형 AI 서비스가 확산되면서 전통적 웹 취약점 목록만으로는 조작된 입력, 학습 데이터 오염, 모델 출력 오남용 같은 위험을 다루기 어려워 별도 기준이 필요해짐.
- 주요 목적 : 기존 웹 보안 통제에 더해 확률적으로 응답하는 모델과 도구 실행 환경의 보안 공백을 줄이는 것.

## Ⅱ. OWASP LLM Top 10(2025)의 특징 및 장점

- 핵심 요약 : 위험을 계층별로 나눠 통제 지점을 특정하고, 공격 예시와 대응을 함께 제시하는 실무형 분류 체계.

1. 계층 분류 : 입력, 모델·데이터, 도구 실행, 출력 계층으로 위험을 나눠 점검 → 위험이 발생하는 위치를 특정해 통제 지점을 정하기 쉬움.
2. 실무 중심 : 위험마다 공격 예시와 완화 방안을 함께 정리 → 개발팀이 설계 단계에서 바로 반영 가능.
3. 에이전트 권한 별도 관리 : **과도한 대행** (에이전트가 업무에 필요한 범위를 넘는 도구 권한을 갖는 위험)을 독립 항목으로 둬 도구 호출 권한을 다른 위험과 분리하여 관리 → 자율 도구 사용 시스템의 통제 범위가 명확해짐.

## Ⅲ. OWASP LLM Top 10(2025)의 구조 (흐름)

- 핵심 요약 : 입력에서 출력까지 네 계층에 10개 위험이 배치되며, 위험은 계층을 따라 연쇄적으로 전파됨.

```text
[ 계층별 위험 배치 ]

[ 입력 계층 ]
프롬프트 인젝션 / 무제한 자원 소비
              ↓
[ 모델·데이터 계층 ]
공급망 취약점 / 데이터 및 모델 중독
벡터 및 임베딩 취약점 / 시스템 프롬프트 노출
              ↓
[ 도구 실행 계층 ]
과도한 대행
              ↓
[ 출력 계층 ]
민감정보 노출 / 부적절한 출력 처리 / 오정보
```

```text
[ 연쇄 공격 흐름의 예 ]

간접 프롬프트 인젝션 (LLM01)
              ↓
도구 권한 남용 (LLM06)
              ↓
비인가 데이터 외부 전송 (LLM02)
```

1. **프롬프트 인젝션** (Prompt Injection) : 조작된 입력으로 시스템 지시와 안전 정책을 무력화하는 공격.
2. **민감정보 노출** (Sensitive Information Disclosure) : 개인정보, 인증 정보, 사내 기밀이 응답에 포함되는 위험.
3. **공급망 취약점** (Supply Chain Vulnerabilities) : 외부 모델, 플러그인, 라이브러리에 섞인 악성 요소가 유입되는 위험.
4. **데이터 및 모델 중독** (Data and Model Poisoning) : 학습·미세조정 데이터에 백도어 트리거를 심는 위험.
5. **부적절한 출력 처리** (Improper Output Handling) : 검증 없이 모델 출력을 웹 화면이나 질의문으로 실행하는 위험.
6. 과도한 대행 (Excessive Agency) : 에이전트에 부여된 도구 권한이 과해 파괴적 작업이 실행되는 위험.
7. **시스템 프롬프트 노출** (System Prompt Leakage) : 비공개 지시문이 추출되어 방어 로직이 드러나는 위험.
8. **벡터 및 임베딩 취약점** (Vector and Embedding Weaknesses) : 검색 증강 생성(RAG, Retrieval-Augmented Generation) 저장소의 접근 통제 실패로 타 사용자 문서가 검색되는 위험.
9. **오정보** (Misinformation) : 모델이 사실처럼 그럴듯한 허위 내용을 생성해 의사결정 오류를 낳는 위험.
10. **무제한 자원 소비** (Unbounded Consumption) : 대량·장문 질의로 연산 자원과 비용이 고갈되는 위험.

## Ⅳ. OWASP LLM Top 10(2025)과 초기판의 비교

- 핵심 요약 : 2023년 초기판의 챗봇 중심 목록과 달리, 2025년판은 검색 증강 생성과 에이전트 구조의 위험을 독립 항목으로 반영.

| 비교 축 | 2023년 초기판 (v1.0) | 2025년판 |
| --- | --- | --- |
| 주요 대상 | 단일 LLM 채팅·API 응용 | RAG 구조와 에이전트 도구 호출 구조 |
| 신설 항목 | 없음 | 시스템 프롬프트 노출, 벡터 및 임베딩 취약점 |
| 대체 항목 | 과잉 의존(Overreliance), 모델 탈취(Model Theft) | 오정보, 무제한 자원 소비 |
| 도구 권한 | 과도한 대행이 하위 우선순위 | 과도한 대행을 독립 항목으로 관리 |

## Ⅴ. OWASP LLM Top 10(2025)의 한계와 방안

- 핵심 요약 : 권한 경계 누락, 도구 오남용, 입력 우회, 자원 고갈을 테넌트 분리, 권한 최소화, 다층 필터, 호출 제한으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 테넌트 간 문서 혼입 | 검색 필터 오류로 타 테넌트 문서 노출 | 테넌트별 저장 공간 분리, 검색 결과 단계 권한 재검증 | 교차 테넌트 검색 차단 건수 |
| 도구 호출 오남용 | 주입된 지시로 위험 명령 실행 | 호출 파라미터 화이트리스트, 고위험 호출 사람 승인 | 승인 거부율 |
| 필터 우회 입력 | 다국어·인코딩 변형으로 규칙 기반 필터 미탐 | 의미 기반 분류 모델 병행, 시스템 프롬프트 변경 감지 | 미탐 사례 건수 |
| 자원 고갈 | 장문·대량 질의로 연산 자원 소진 | 입력 토큰 상한, 사용자별 요청 제한 | 사용자별 토큰 사용량 |

## Ⅵ. OWASP LLM Top 10(2025)에 대한 기술사적 제언

- 핵심 요약 : LLM 보안을 모델 성능과 분리된 운영 역량으로 보고, 설계·운영·공급 전 단계에 통제를 내재화해야 함.

1. 설계 단계 : 보안팀과 AI 개발팀이 공동으로 LLM 아키텍처 검토 체크리스트를 만들고, 이를 신규 서비스 기획 단계부터 적용하는 체계 필요.
2. 운영 단계 : 프롬프트, 응답, 도구 호출 기록을 감사 가능하게 남기고, 정기 레드티밍으로 위험 목록의 실효성을 점검하는 절차 필요.
3. 공급 단계 : 외부 모델과 데이터셋의 출처 및 무결성 검증을 조달 기준에 포함하는 제도 마련 필요.

## Ⅶ. 결론

- 핵심 요약 : LLM 보안은 입력, 도구, 출력 전 구간을 통제하는 운영 역량의 문제임.
- 시사점 : OWASP LLM Top 10은 그 통제 범위를 정하는 공통 기준이므로, 모델 도입 전 점검 목록으로 활용하는 것이 타당함.
