## 답안 골격
```text
[검사 시점과 사용 시점(TOCTOU, Time Of Check To Time Of Use)] ◀━━ 머리: Ⅶ 내 의견 (비원자적 파일 경로 검사 탈피 → 파일 디스크립터 기반 원자적 연산과 심볼릭 링크 추적 차단 강제)
 ┃
 ┣━ Ⅰ 개요 ───── 멀티스레드 및 동시성(Concurrency) 환경에서 시스템 자원의 상태나 권한을 '검사하는 시점(Time Of Check)'과 이를 실제로 '사용하는 시점(Time Of Use)' 사이의 시간차(Race Window)를 악용하여 자원을 바꿔치기하는 경쟁 상태(Race Condition) 보안 약점
 ┣━ Ⅱ 특징 ───── 비원자적(Non-atomic) 연산 구조에서 기인 · 심볼릭 링크(Symbolic Link) 바꿔치기 공격 빈번 · 루트 권한 프로세스 하이재킹 · 정적 분석으로 탐지하기 어려운 동적 타이밍 결함
 ┣━ Ⅲ 구조 ───── 검사 시점(TOC, `access()`) + 경쟁 구간(Race Window) + 공격자 개입(심볼릭 링크 조작) + 사용 시점(TOU, `open()`)
 ┣━ Ⅳ 흐름 ───── 권한 체크(일반 파일 접근 가능 확인) → 시간차 틈새에 타깃 파일을 시스템 핵심 파일(`/etc/shadow`)의 심볼릭 링크로 교체 → 루트 데몬이 파일 쓰기 수행 → 시스템 관리자 파일 변조 및 권한 상승
 ┣━ Ⅴ 비교 ───── 논리적 권한 결함(코드 로직 자체의 버그) vs TOCTOU(논리는 정상이지만 운영체제 스케줄링 시간차와 비원자성으로 인해 발생하는 동시성 취약점)
 ┗━ Ⅵ 실무 ───── 임시 디렉토리(`/tmp`) 공유 파일 접근 시 취약 / 파일 경로 문자열 기반 검사의 한계 / 운영체제 스레드 선점으로 인한 시간차 발생
```
- 필수 키워드: TOCTOU · 경쟁 상태(Race Condition) · 레이스 윈도우(Race Window) · 심볼릭 링크 공격 · 원자적 연산(Atomic Operation) · 파일 디스크립터(fstat) · `O_NOFOLLOW`
- 배점 전략: 10점 = Ⅰ TOCTOU 개념 및 발생 원리 → Ⅲ TOC-TOU 시간차 공격 흐름도 도식 → Ⅵ 핵심 시큐어 코딩 대책 / 25점 = Ⅰ~Ⅶ 전개, 제125회 2교시 4번 기출 완벽 대응, C/C++ 및 자바/파이썬 환경에서의 구체적 취약 코드와 안전한 코드 대조, POSIX 원자적 시스템 콜(`O_CREAT | O_EXCL`) 및 파일 디스크립터 바인딩 심층 분석
- 기출: 제125회 2교시 4번: "구현단계에서 발생 가능한 코딩 보안 약점인 검사시점과 사용시점(TOCTOU)"

## 한 줄 본질
- 자원이 안전한지 확인하고 나서 실제로 사용하기까지의 수 마이크로초 틈새에 공격자가 자원을 바꿔치기하는 타이밍 간극 병목 → 검사와 사용을 하나의 원자적(Atomic) 연산으로 묶고 경로 대신 파일 디스크립터를 직접 다룸 → 권한 상승 및 파일 위변조 원천 방지 / 코드 복잡도 증가

## 핵심 그림
```text
[TOCTOU(검사 시점과 사용 시점) 경쟁 구간(Race Window) 악용 메커니즘]

[루트 권한 프로세스]                                    [공격자 프로세스 (일반 권한)]
        │                                                              │
  1. [Time Of Check (TOC)]                                             │
     - `access("/tmp/file", W_OK)` 호출                                │
     - "일반 파일이 맞고 쓰기 권한 있음!" 확인                        │
        │                                                              │
        │ ══════════════ [경쟁 구간: Race Window (수 마이크로초)] ═══════════ │
        │                                                              │
        │                                                     2. [심볼릭 링크 바꿔치기!]
        │                                                        - `unlink("/tmp/file")`
        │                                                        - `symlink("/etc/shadow", "/tmp/file")`
        │                                                              │
  3. [Time Of Use (TOU)]                                               │
     - `open("/tmp/file", O_WRONLY)` 실행                              │
     - 루트 권한으로 심볼릭 링크를 따라가 `/etc/shadow`를 덮어써 버림! │
        │                                                              │
        ▼                                                              ▼
  [결과]: 공격자가 루트 패스워드 파일을 덮어써 시스템 최고 관리자 권한 획득 성공!
```

## 핵심 용어
- 레이스 윈도우 (Race Window): 자원의 상태 검사가 완료된 직후부터 실제 그 자원을 소비·수행하는 시점 사이에 존재하는 미세한 시간 간격으로, 공격자가 파일 시스템 상태를 조작할 수 있는 유일한 기회의 창
- 원자적 연산 (Atomic Operation): 더 이상 쪼갤 수 없는 단일 명령으로 실행되어, 중간에 다른 프로세스가 개입하거나 상태를 변경할 수 없도록 운영체제와 하드웨어가 보장하는 연산

## 핵심 통찰
- 프로그래머는 코드가 "위에서 아래로 한 줄씩 순간 이동하듯 실행된다"고 착각함 → 하지만 멀티태스킹 OS는 `access()` 직후 스레드를 멈추고(Context Switch) 다른 프로세스를 수천 번 실행시킬 수 있음
- 파일 "이름(경로)"으로 검사하고 파일 "이름"으로 여는 것은 100% 취약함 → 이름과 실제 하드디스크의 inode(실물) 사이의 연결 고리는 언제든 바뀔 수 있기 때문임
- 따라서 먼저 파일 디스크립터로 열어젖힌(`open()`) 후, 얻어낸 핸들에 대고 상태를 검사(`fstat()`)해야 대상이 바뀌지 않음

## 이웃 토픽과 구분
- TOCTOU vs 데드락(Deadlock): TOCTOU = 시간차를 틈타 자원을 바꿔치기하는 보안 취약점 / 데드락 = 둘 이상의 프로세스가 서로의 자원을 점유한 채 무한 대기하는 가용성 장애

## 문제·원인·대책
- 사례: 특권 데몬이 임시 파일을 생성하는 과정에서 심볼릭 링크 레이스 컨디션이 발생해 시스템 중요 환경설정 파일이 손상된 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 검사 후 심볼릭 링크 교체로 인한 중요 시스템 파일 덮어쓰기 | 파일 경로 기반의 `access()` 후 `open()` 비원자적 호출 | `O_NOFOLLOW` 플래그 사용 및 `O_CREAT | O_EXCL` 원자적 파일 생성 | 심볼릭 링크 조작 시 즉각 에러 반환 및 중복 생성 방지 |
| 파일 권한 검사와 사용 사이의 시간차 권한 우회 | 경로 문자열을 매개변수로 넘기며 다중 시스템 콜 호출 | 파일 오픈 후 파일 디스크립터 기반(`fstat`, `fchown`) 검사 | 파일 객체 고정을 통한 바꿔치기 원천 무력화 |

## 내 의견
- [공용 임시 디렉토리(`/tmp`) 사용 금지 및 사용자 격리 런타임 디렉토리 강제] 리눅스 표준인 `/tmp` 디렉토리는 모든 로컬 사용자가 쓰기 권한을 가지는 스티키 비트(Sticky Bit) 영역이라 TOCTOU 공격의 절대적 온상임 → 나라면: 사내 모든 애플리케이션에 대해 `/tmp` 대신 `systemd`가 제공하는 사용자별 전용 격리 런타임 디렉토리(`/run/user/<UID>`) 또는 프라이빗 임시 마운트 네임스페이스(`PrivateTmp=true`)를 강제 적용하여 타 프로세스의 심볼릭 링크 개입 자체를 인프라 레벨에서 봉쇄
