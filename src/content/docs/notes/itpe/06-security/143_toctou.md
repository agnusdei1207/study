## 한 줄 본질
- TOCTOU는 자원의 상태를 확인한 뒤 사용하기 전에 상태가 바뀌어 검사 결과가 무효화되는 경쟁 상태 취약점

## 10점 답안
TOCTOU(Time of Check to Time of Use)는 파일·권한 등 자원을 검사하는 시점과 실제 사용하는 시점 사이에 상태가 변경되는 경쟁 상태. 공유 디렉터리에서 경로를 확인한 후 다시 열 때 심볼릭 링크나 파일 대상이 바뀌는 상황이 대표적. 검사와 사용을 가능한 한 같은 자원 핸들에 묶고 원자적 생성·갱신 API, 전용 임시 디렉터리, 적절한 잠금과 권한 설계로 경쟁 구간 축소. 시간 간격을 줄이는 것만으로 원천 제거 불가.

## 25점 답안
### Ⅰ. 발생 구조
```text
검사: 경로 A는 안전 → 타 프로세스가 A의 대상 변경 → 사용: 변경된 대상을 열거나 수정
```
검사 대상과 사용 대상이 동일하다는 가정이 깨지는 문제. 파일 시스템뿐 아니라 권한·잔액·재고 등 공유 상태에도 적용.

### Ⅱ. 파일 사례와 대응
| 취약 동작 | 개선 원칙 |
|---|---|
| `access(path)` 후 별도 `open(path)` | 실제 연 파일 디스크립터 기준으로 `fstat` 등 검사 |
| 예측 가능한 공유 임시파일 이름 | 전용 디렉터리와 안전한 임시파일 생성 API |
| 링크·경로 재해석 | 플랫폼에 맞는 링크 추적 제한과 원자적 파일 작업 |

### Ⅲ. 구현 유의
`O_NOFOLLOW`는 마지막 경로 성분의 심볼릭 링크 제한 등 특정 조건에만 유효하며 모든 경로 경쟁을 자동 해결하지 않음. 파일 디스크립터를 열고 검사하더라도 검사 결과에 맞게 사용하는 동일 객체·권한·동시 변경 통제 확인 필요. 다중 자원 갱신에는 트랜잭션·잠금 등 별도 원자성 설계.
