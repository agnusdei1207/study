## 답안 골격
```text
[FIDO(Fast Identity Online)] ◀━━ 머리: Ⅶ 내 의견 (서버 비밀번호 보관의 구조적 유출 한계 극복 → 로컬 생체인증과 FIDO2/WebAuthn 기반 공개키 무암호 인증 표준화)
 ┃
 ┣━ Ⅰ 개요 ───── 비밀번호(Password)의 보안 취약성과 입력 불편을 해결하기 위해, 사용자 로컬 단말의 생체인증과 공개키(PKI) 암호화 알고리즘을 결합하여 안전하고 편리한 온라인 무암호 인증을 제공하는 글로벌 표준
 ┣━ Ⅱ 특징 ───── 생체정보의 단말 외부 유출 0%(로컬 인증) · 서버에는 오직 공개키만 보관 · 피싱 저항성(Phishing-resistant, 도메인 바인딩) · 크리덴셜 스터핑 원천 무력화
 ┣━ Ⅲ 구조 ───── FIDO 인증장치(Authenticator, 스마트폰 지문/TPM) + FIDO 클라이언트(웹 브라우저/OS) + FIDO 서버(공개키 검증)
 ┣━ Ⅳ 흐름 ───── [등록]: 키 쌍 생성 → 단말 내 개인키 격리 저장 → 서버로 공개키 전송 / [인증]: 서버 챌린지 수신 → 로컬 지문 인증 통과 → 개인키로 챌린지 서명 → 서버 검증 성공
 ┣━ Ⅴ 비교 ───── FIDO 1.0(모바일 전용 UAF, 외장 USB U2F 분리) vs FIDO2(WebAuthn 웹 표준 + CTAP 프로토콜 통합, PC/웹 브라우저 전면 지원) vs Passkey(동기화 자격증명)
 ┗━ Ⅵ 실무 ───── 기기 분실 시 계정 복구(Recovery) 절차 설계 / 레거시 브라우저 호환성 / 생체정보 위조(가짜 지문)에 대한 단말 하드웨어 신뢰성
```
- 필수 키워드: FIDO2 · WebAuthn · CTAP(Client to Authenticator Protocol) · 무암호 인증(Passwordless) · 로컬 인증 · 피싱 저항성 · 패스키(Passkey)
- 기출: 제118회 기출: "FIDO(Fast Identity Online) 1.0과 FIDO 2.0의 기술요소 및 차이점을 비교 설명하시오." (이전: 107, 116회)

## 한 줄 본질
- 서버에 비밀번호나 생체 템플릿을 저장했다가 대규모 해킹으로 털리는 중앙 집중 유출 병목 → 단말기 내부에서만 생체인식을 수행하고 서버와는 비대칭키 전자서명(WebAuthn)으로만 소통 → 서버가 해킹되어도 자격증명 유출 0% 보장 / 단말기 분실 시 계정 복구 프로세스 복잡

## 핵심 용어
- WebAuthn (Web Authentication): W3C와 FIDO 얼라이언스가 공동 표준화한 브라우저 자바스크립트 API로, 웹사이트가 비밀번호 없이 단말의 지문 센서나 하드웨어 보안 키를 직접 호출할 수 있게 해주는 표준 인터페이스
- CTAP (Client to Authenticator Protocol): PC 브라우저나 OS(Client)가 USB, 블루투스(BLE), NFC로 연결된 외부 보안 토큰이나 스마트폰(Authenticator)과 암호학적으로 통신하는 프로토콜

## 핵심 통찰
- 사용자의 지문이나 얼굴 데이터는 "절대로 인터넷 네트워크를 타지 않음" → 단말기 내부 보안 칩(SE/TEE)에서만 대조되고 서버로는 오직 "로컬 인증이 성공했다"는 서명 데이터만 전송됨
- FIDO2는 피싱 공격을 100% 무력화함(Phishing-resistant) → WebAuthn은 브라우저가 접속한 실제 웹 도메인(예: `bank.com`)을 챌린지 서명 데이터에 강제로 바인딩하므로, 가짜 피싱 사이트(`bank-fake.com`)에 접속하면 서명이 원천 거부됨
- 최근의 패스키(Passkey)는 FIDO2 개인키를 애플 아이클라우드 키체인이나 구글 패스워드 매니저를 통해 기기간 종단간 암호화(E2EE)로 동기화하여 기기 변경 시의 사용성을 획기적으로 개선함

## 이웃 토픽과 구분
- FIDO vs 공인인증서/공동인증서: FIDO = 단말 로컬 생체인증 기반 무암호화, 사이트별 고유 키 쌍 생성으로 추적 불가 / 공동인증서 = 비밀번호 기반 암호화 파일(NPKI), 단일 인증서를 여러 사이트에서 공용

## 문제·원인·대책
- 사례: 가짜 은행 웹사이트를 구축하고 SMS 피싱으로 사용자를 유인해 일회용 비밀번호(OTP)까지 가로채 송금한 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 중간자(MITM) 피싱 사이트를 통한 계정 자격증명 및 OTP 실시간 갈취 | 비밀번호 및 정적 OTP가 사람이 읽고 피싱 사이트에 입력 가능한 구조 | FIDO2 WebAuthn 도입(브라우저 레벨의 오리진 도메인 암호학적 바인딩) | 사칭 도메인 접속 시 단말이 서명 생성을 거부하여 피싱 원천 차단 |
| FIDO 등록 단말기 분실 시 사용자의 서비스 영구 잠김 | 단말 로컬 하드웨어(SE)에만 개인키가 단독 종속된 설계 | FIDO 패스키(Passkey) 다중 단말 클라우드 백업 및 계정 복구(E2EE) 연동 | 기기 분실 시에도 타 인증 기기를 통해 손쉽게 신원 복구 |
