## 지식 로드맵 내 현재 위치

지식 위치: 신원·인증 → 공개키 기반 사용자 인증 → **FIDO2**

## 30초 인출

- 본질: 서비스별 공개키 자격증명을 이용해 공유 비밀번호 없이 사용자를 인증하는 FIDO 표준군
- 구성: WebAuthn은 서비스·브라우저 사이 웹 API, CTAP은 클라이언트·외부 인증장치 사이 프로토콜
- 보안 성질: 사이트의 RP ID·오리진에 바인딩해 사칭 도메인으로의 인증을 저항. 계정 복구·세션 탈취·등록 절차는 별도 보호 대상

## 1교시 예상문제 (10점)

> FIDO2의 구성 요소와 등록·인증 절차를 설명하시오. (예상·10점)

## 1교시 10점 답안

### Ⅰ. 개념

FIDO2는 WebAuthn과 CTAP을 바탕으로 공개키 자격증명을 이용하는 사용자 인증 체계. 인증장치는 개인키를 관리하고, 서비스는 대응 공개키를 보유.

### Ⅱ. 절차

```text
등록: 서버 도전값 → 인증장치 키 생성·사용자 확인 → 공개키 등록
인증: 서버 도전값 → 사용자 확인 → 개인키 서명 → 서버 공개키 검증
```

생체인식은 로컬 사용자 확인 수단의 하나이며 PIN·보안키 등도 사용 가능. 패스키는 동기화형과 기기 귀속형이 있음.

## 2~4교시 예상문제 (25점)

> FIDO1과 FIDO2의 기술 요소를 비교하고, WebAuthn 등록·인증 과정과 패스키 운영 시의 보안 고려 사항을 설명하시오. (예상·25점)

## 2~4교시 25점 답안

### Ⅰ. 개요

서버의 공유 비밀번호 검증에서 벗어나 서비스별 공개키와 개인키의 증명으로 인증. 개인키 보관 위치와 사용자 확인 방식은 인증장치 및 패스키 유형에 따라 다름.

### Ⅱ. FIDO 표준군 비교

| 구분 | 주요 기술 | 사용자 경험 |
|---|---|---|
| FIDO UAF | 로컬 사용자 확인과 공개키 인증 | 주로 비밀번호 없는 경험 |
| FIDO U2F | 보안키 기반 보조 인증 | 기존 비밀번호의 두 번째 요소 |
| FIDO2 | WebAuthn + CTAP | 비밀번호 없는 인증 또는 추가 요소 |
| 패스키 | FIDO 자격증명의 사용자 친화적 사용 형태 | 동기화형 또는 기기 귀속형 |

### Ⅲ. 구성과 인증 경로

```text
[서비스/RP] ─ 도전값·RP ID ─> [브라우저/WebAuthn]
                                  │ CTAP(외부 인증장치인 경우)
                                  ▼
                           [인증장치·개인키]
                                  │ 사용자 확인 후 서명
                                  ▼
[서비스/RP] <─ 서명·오리진 등 검증 ─ [브라우저]
```

내장 인증장치 사용 시 CTAP을 통한 외부 장치 연결이 항상 필요한 것은 아님.

### Ⅳ. 피싱 저항성과 경계

| 통제 | 의미 | 잔여 위험 |
|---|---|---|
| RP ID·오리진 바인딩 | 사칭 도메인에 등록된 자격증명 사용 저항 | 등록 단계의 계정 탈취 |
| 도전값 서명 | 재전송·비밀번호 재사용 공격 저항 | 세션 쿠키 탈취 |
| 로컬 사용자 확인 | 장치 소지자 확인 | 기기·OS 침해 또는 약한 복구 경로 |
| 동기화형 패스키 | 여러 기기에서 복구·사용 가능 | 동기화 계정 보호와 제공자 신뢰 |

FIDO 인증은 피싱 저항성을 제공하지만 모든 피싱과 계정 탈취를 100% 제거한다는 뜻은 아님.

### Ⅴ. 배포·운영 설계

| 과제 | 대응 |
|---|---|
| 등록·복구 | 최초 등록 확인, 대체 인증장치와 복구 채널의 보호 |
| 기기 분실 | 복수 인증장치 또는 동기화형 패스키 정책 |
| 관리자·고위험 계정 | 기기 귀속형 자격증명과 별도 승인 고려 |
| 인증 후 세션 | 쿠키 보호, 세션 재검증, 고위험 거래의 재확인 |

### Ⅵ. 기술사적 제언

인증 성공만으로 거래 승인까지 간주하지 않고, 등록·복구·세션·고위험 작업의 전체 경로에서 피싱 저항성 유지.
