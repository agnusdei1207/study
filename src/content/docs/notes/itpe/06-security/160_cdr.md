## 연관 키워드

- CDR(Content Disarm and Reconstruction), 콘텐츠 무해화, 액티브 콘텐츠, VBA 매크로
- 파싱, 분해, 추출, 재구성, 제로데이 취약점, 샌드박스, 망연계, 보안 이메일 게이트웨이

## Ⅰ. CDR(Content Disarm and Reconstruction)의 개요

- 핵심 요약 : 문서 파일의 실행 요소를 탐지 대신 제거하고, 남은 정적 내용으로 새 파일을 다시 만드는 선제적 무해화 기술.
- 개념 : 이메일 첨부, 웹 다운로드, USB 등으로 들어오는 문서 파일(MS Office, PDF, HWP 등)을 구조 단위로 분해해 매크로, 액티브 콘텐츠, 외부 자동 실행 링크를 제거한 뒤 정적 요소로 깨끗한 파일을 재구성하는 **콘텐츠 무해화** (CDR, Content Disarm and Reconstruction).
- 배경 및 필요성 : 시그니처 기반 백신과 샌드박스는 **제로데이** (Zero-day) 취약점을 노리거나 샌드박스 탐지를 회피하는 신종 악성 문서를 사전에 걸러내기 어려움.
- 주요 목적 : 악성 여부를 판별하는 데 시간을 쓰지 않고, 모든 실행 요소를 잠재 위협으로 간주해 제거함으로써 문서형 악성코드의 유입 경로를 차단.

## Ⅱ. CDR(Content Disarm and Reconstruction)의 특징 및 장점

- 핵심 요약 : 판별 대신 제거하는 방식이 제로데이 대응력과 짧은 처리 지연으로 이어지는 구조.

1. 실행 요소 전면 제거 : 매크로, 임베디드 OLE 객체, 외부 자동 호출 링크를 원천 제거 → 문서 안의 코드 실행 경로가 사라져 신종 취약점 문서에도 대응.
2. 원본 포맷 유지 재구성 : 폰트, 서식, 표, 이미지를 보존한 새 파일을 생성 → 업무 문서로서 열람 가능성 유지.
3. 악성 패턴 비의존 : 시그니처를 알 필요가 없음 → 미공개 취약점에 대한 방어 공백 축소.
4. 행위 관찰 없는 처리 : 파싱과 재생성 중심이라 샌드박스의 장시간 행위 관찰이 필요 없음 → 사용자 업무 지연 감소.

## Ⅲ. CDR(Content Disarm and Reconstruction)의 구조 (흐름)

- 핵심 요약 : 파싱, 분해, 추출, 재구성의 4단계 파이프라인으로 실행 요소만 걸러내는 구조.
- 파싱(Parsing) : 파일 포맷 명세에 따라 헤더, 본문, 이미지, 폰트, 매크로 스트림을 객체 단위로 식별.
- 분해(Disarm) : 실행 가능한 객체를 제거하고, 추출 단계로 넘기지 않음.
- 추출(Extraction) : 텍스트, 정적 이미지, 레이아웃처럼 안전이 확인된 요소만 분리.
- 재구성(Reconstruction) : 분리한 요소를 새 백지 파일에 재조합하여 원본과 같은 형식의 정화 파일을 생성.

```text
[ 외부 유입 문서 (이메일 첨부 등) ]
              ↓
1. 파싱 (Parsing)
   헤더·본문·이미지·매크로 스트림 식별
              ↓
2. 분해 (Disarm)
   매크로·스크립트·OLE 객체·외부 링크 제거
              ↓
3. 추출 (Extraction)
   텍스트·정적 이미지·레이아웃만 분리
              ↓
4. 재구성 (Reconstruction)
   새 파일에 서식 유지하여 재조합
              ↓
[ 무해화된 파일 배포 ]
```

CDR은 단독 차단보다 기존 탐지 장비와 병행할 때 효과가 크다. 정화 파일은 즉시 전달하고 원본은 샌드박스에서 분석하는 병행 흐름이 일반적이다.

```text
[ 유입 문서 원본 ]
        ↓
   사본으로 분기
   ↓                   ↓
[ CDR 무해화 ]     [ 샌드박스 정밀 분석 ]
   ↓                   ↓
[ 사용자 즉시 전달 ] [ 위협 DB 시그니처 축적 ]
```

## Ⅳ. CDR(Content Disarm and Reconstruction)과 유사 기술의 비교

- 핵심 요약 : 탐지 방식인 백신과 샌드박스에 비해 CDR은 판별 없이 제거하므로 제로데이 대응력이 높지만, 문서 기능 손실이라는 대가가 따른다.

| 비교 축 | CDR (콘텐츠 무해화) | 안티바이러스 (백신) | 지능형 샌드박스 |
| --- | --- | --- | --- |
| 동작 원리 | 실행 요소 제거 후 재구성 | 알려진 악성 패턴(시그니처) 대조 | 격리 환경에서 실행 후 행위 관찰 |
| 처리 속도 | 파싱과 재생성 중심, 빠른 편 | 패턴 매칭 중심, 빠른 편 | 행위 관찰 시간만큼 지연 |
| 제로데이 대응 | 객체 구조 자체를 제거하여 대응 | 시그니처가 없으면 통과 가능 | 회피 기법에 따라 부분 대응 |
| 문서 기능 영향 | 정상 매크로도 함께 제거 | 원형 유지 | 원형 유지 |
| 오탐·미탐 특성 | 전수 무해화이므로 탐지 개념 없음 | 변종에 대한 미탐 가능성 | 회피 기법에 의한 미탐과 오탐 가능 |

- 선택 기준 : 외부 유입 경로처럼 공격 표면이 넓은 구간에는 CDR을, 기능 보존이 중요한 문서에는 샌드박스 분석을 병행하여 적용 범위를 나눈다.

## Ⅴ. CDR(Content Disarm and Reconstruction)의 한계와 방안

- 핵심 요약 : 정상 매크로 기능 손실, 비표준 포맷 재구성 오류, 암호화 압축 파일 미처리를 정책과 엔진 기능으로 보완해야 함.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 정상 매크로 문서의 기능 손실 | 전수 제거로 재무·회계 업무 매크로가 중단 | 신뢰 발신자 예외를 승인 절차로 관리하고 별도 격리 환경으로 우회 | 예외 승인 건수, 업무 중단 신고 건수 |
| 비표준 문서 재구성 오류 | HWP, CAD 도면 등에서 서식이 깨지거나 폰트가 뒤틀림 | 국내 표준(HWP, OWPML)을 지원하는 엔진 채택, 렌더링 검증 | 재구성 실패율 |
| 암호화 및 다중 중첩 압축 파일 | 엔진이 내부 파싱에 실패하고 그대로 통과 | 암호 첨부 기본 격리, 수신자 복호화 후 CDR 적용 | 미처리 압축 파일 수 |

## Ⅵ. CDR(Content Disarm and Reconstruction) 적용을 위한 기술사적 제언

- 핵심 요약 : 망연계와 웹 업로드 구간에 CDR을 기본 장치로 두고, 샌드박스와 병행하는 운영 체계를 제도화하는 것이 바람직함.

1. 외부망에서 내부망으로 넘어오는 파일 전송 구간과 웹메일 첨부 검사 지점에 CDR을 필수 장치로 지정하고, 예외는 승인된 소수 항목으로 한정한다.
2. 대고객 업로드 게시판은 파일을 저장하기 전에 무해화를 거치는 설계를 표준으로 삼는다.
3. 정화 파일은 즉시 전달하고 원본은 샌드박스로 정밀 분석하는 이중 체계를 운영하여, 업무 연속성과 위협 정보 축적을 함께 확보한다.

## Ⅶ. 결론

- 핵심 요약 : CDR은 위협을 찾아내는 대신 실행 가능한 요소를 없애 문서형 공격 표면을 줄이는 선제적 방어 기술.
- 탐지 기술과 결합하면 기능 손실을 관리하면서도 위협 가시성을 유지할 수 있음.
