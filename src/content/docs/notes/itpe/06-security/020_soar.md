<summary>핵심 용어</summary>

- **SOAR (Security Orchestration, Automation and Response):** 보안 도구와 대응 업무흐름을 연결해 반복 사건의 조사·조치를 관리하는 운영 방식 또는 플랫폼
- **오케스트레이션:** 서로 다른 보안도구·정보·업무절차 사이의 작업 연결
- **플레이북:** 특정 경보나 사건의 조회·판단·승인·조치 순서를 정의한 대응 절차
- **SIEM (Security Information and Event Management):** 로그·이벤트를 수집·분석해 보안 경보 생성에 활용하는 시스템
- **CISA (Cybersecurity and Infrastructure Security Agency):** 미국의 사이버보안·핵심기반시설 보호를 담당하는 연방기관

### Ⅱ. 기능과 처리 흐름

| 기능 | 핵심 역할 |
|---|---|
| 오케스트레이션 | 보안도구·업무시스템의 조회·작업 연결 |

```text
        ↓
허용된 도구 조치·사건 기록
```

**제언:** 차단·계정정지처럼 영향이 큰 조치는 승인과 복구 경로를 둔 뒤 단계적으로 자동화

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **SOAR (Security Orchestration, Automation and Response)** 는 보안 도구와 대응 절차를 연계해 사건 처리를 지원·자동화하는 운영 역량 |
| 목적 | 반복적인 조사·대응을 일관되게 수행하고 분석자의 판단 업무를 지원 |

SOAR는 경보의 정확성이나 자동조치의 안전을 저절로 보장하지 않으며, 자동화 범위는 위험과 조직 절차에 따라 설계.

## Ⅱ. 구성과 처리 흐름

| 구성 | 역할 |
|---|---|
| 커넥터·API 연계 | 보안도구·자산정보·업무시스템 간 정보·요청 전달 |
| 플레이북 엔진 | 조건·분기·승인 절차에 따른 대응 작업 실행 |
| 사건·티켓 관리 | 담당·상태·판단·조치·결과 추적 |

```text
경보 접수
   ↓
정보 보강·중복/맥락 확인
   ↓
플레이북 조건에 따른 분류
   ↓
분석·사람 승인(필요 시)
   ↓
허용된 조치 → 결과 검증·기록
```

## Ⅲ. SIEM과 역할 비교

| 관점 | SIEM | SOAR |
|---|---|---|
| 중심 기능 | 로그·이벤트 수집, 상관분석, 경보 생성 지원 | 도구·업무흐름 연계, 조사·대응 작업 관리 |
| 대표 입력 | 로그·이벤트 | 경보·사건·위협정보 |
| 관계 | 탐지 결과를 경보로 제공할 수 있음 | 경보를 받아 후속 조사·조치를 지원할 수 있음 |

## Ⅳ. 플레이북 안전운영

| 단계 | 검토·통제 |
|---|---|
| 입력 확인 | 출처·자산·심각도·중복 경보 검증 |
| 보강·판단 | 위협정보와 내부 맥락 조회, 오탐·예외 검토 |
| 조치 | 도구·대상별 권한 제한, 고영향 작업 승인 |
| 결과 확인 | 조치 성공 여부와 서비스 영향 확인, 필요 시 복구 |
| 변경관리 | 플레이북·커넥터 버전과 실행기록 관리 |

## Ⅴ. 한계와 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 오탐 경보가 자동 차단으로 이어져 업무에 영향 | 위험기반 승인, 제한된 자동화 범위, 차단 해제·복구 절차 적용 |
| API·업무절차 변경으로 플레이북이 오작동 | 커넥터·플레이북 변경시험과 버전관리, 수동 대응 절차 유지 |
| 처리 건수나 시간 단축만으로 효과를 판단 | 오탐·재작업·서비스 영향·대응 품질을 함께 점검 |
