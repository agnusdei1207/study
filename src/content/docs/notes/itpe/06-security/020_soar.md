## 지식 로드맵 내 현재 위치

보안운영 → 보안관제(SOC) → SOAR 및 자율형 보안 침해사고 대응

## 30초 인출

- **본질:** 다양한 이기종 보안 솔루션을 단일 워크플로우로 연계하고, 사전 정의된 플레이북을 통해 위협 탐지부터 격리까지의 대응 절차를 자동화하는 보안 운영 플랫폼
- **메커니즘:** SIEM 경보 수신 → TIP 위협 인텔리전스 연계 보강 → 플레이북 기반 자동 분류·조사 → 방화벽/EDR 자동 차단 및 티켓 생성
- 통찰: 오탐에 의한 핵심 비즈니스 서비스 차단과 API 스키마 변경 크래시를 방지하기 위해 위험 등급별 HITL 승인 절차와 서킷 브레이커 아키텍처 도입 필수

<details>
<summary>핵심 용어</summary>

- **보안 오케스트레이션 (SO, Security Orchestration):** 방화벽, EDR, SIEM, 위협 인텔리전스(TIP) 등 서로 다른 제조사의 보안 도구를 API로 상호 연동하여 하나의 체계로 결합하는 기술
- **보안 자동화 (SA, Security Automation):** 반복적인 침해 조사, IP 평판 조회, 엔드포인트 격리 등의 수동 작업을 사람의 개입 없이 기계적으로 실행하는 기술
- **플레이북 (Playbook):** 특정 보안 이벤트(랜섬웨어 감염, 피싱 메일 등) 발생 시 수행해야 할 일련의 조건, 분기, 승인, 조치 단계를 코드로 정의한 표준 대응 절차서
- **MTTD / MTTR:** 평균 탐지 시간(Mean Time to Detect) 및 평균 대응 시간(Mean Time to Respond)으로, SOAR 도입을 통해 시간 단위를 수 시간에서 수 초 단위로 단축
</details>

## 2~4교시 예상문제 (25점)

> 차세대 보안관제센터(SOC)의 핵심 인프라인 SOAR(Security Orchestration, Automation and Response)의 3대 핵심 구성요소와 처리 아키텍처를 설명하고, SIEM 및 XDR과의 차이점과 플레이북 자동 실행 시의 엔지니어링 한계 및 방어 전략을 기술하시오. (예상·25점)

---
## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **SOAR(Security Orchestration, Automation and Response)** 는 보안관제 센터에 유입되는 방대한 보안 경보를 표준화된 플레이북(Playbook)에 따라 자동으로 조사·분석하고, 이기종 보안 도구와 연계하여 침해 대응을 신속하게 완결하는 지능형 보안 운영 플랫폼 |
| 목적 | 관제 요원의 경보 피로(Alert Fatigue) 해소, 침해사고 평균 대응 시간(MTTR)의 획기적 단축 및 대응 프로세스의 표준화 |

SIEM이 수집 및 탐지 중심의 수동적 플랫폼인 반면, SOAR는 능동적 조치(Active Response)와 프로세스 자동화에 초점.

## Ⅱ. SOAR의 3대 핵심 기둥 특징

| 핵심 영역 | 세부 기능 및 역할 | 구현 기술 요소 |
|---|---|---|
| **보안 오케스트레이션**<br>(Security Orchestration) | 사일로화된 이기종 보안 장비(방화벽, WAF, EDR, 메일 보안)를 단일 인터페이스로 통합 | RESTful API 커넥터, OpenC2, 표준 데이터 모델 정규화 |
| **보안 자동화**<br>(Security Automation) | 사람이 반복 수행하던 단순·정형화된 조사 및 차단 작업을 무인화 실행 | 워크플로우 엔진, 파이썬 스크립트 실행기, 서드파티 통합 플러그인 |
| **보안 대응 및 인텔리전스**<br>(Response & Threat Intel) | 사건 티켓팅, 침해 지표(IoC) 평판 조회, 외부 TIP 연계 및 사후 포렌식 기록 관리 | TIP(STIX/TAXII), 케이스 관리 시스템(Case Management), 감사 추적 |

## Ⅲ. SOAR 처리 아키텍처 및 플레이북 워크플로우

```text
[SOAR 기반 지능형 보안 침해사고 대응 라이프사이클]

 +--------------------+     +---------------------+     +--------------------+
 | 1. SIEM / XDR 탐지 | --> | 2. 데이터 보강(TIP) | --> | 3. 플레이북 분기   |
 | 고위험 악성코드 경보|     | VirusTotal / CTI    |     | 위험도 스코어 산출 |
 +--------------------+     +---------------------+     +----------+---------+
                                                                   |
            +------------------------------------------------------+
            v
 +-------------------------------------------------------------------+
 | 4. 대응 조치 실행 (Orchestrated Response)                          |
 |    - [저위험 / 확실한 위협] : 무인 자동 격리 (방화벽 IP 차단 / EDR 격리) |
 |    - [고위험 비즈니스 자산]: HITL(Human-in-the-Loop) 관제사 승인 요청 |
 +----------------------------------+--------------------------------+
                                    v
 +-------------------------------------------------------------------+
 | 5. 케이스 종결 및 보고서 자동 생성 (ITSM Jira / ServiceNow 티켓 연동)|
 +-------------------------------------------------------------------+
```

### 1. 단계별 엔지니어링 세부 프로세스

| 처리 단계 | 세부 동작 메커니즘 | 적용 기술 및 프로토콜 |
|---|---|---|
| **1. 경보 수신 및 정규화** | SIEM 등에서 발생하는 Syslog, Webhook 수신 후 공통 이벤트 스키마로 파싱 | JSON 정규화, CEF, ECS(Elastic Common Schema) |
| **2. 컨텍스트 보강** | 추출된 IP, URL, 파일 해시를 CTI 및 내부 CMDB 자산 정보와 교차 조회 | STIX/TAXII 2.1, VirusTotal, 내부 자산 DB 연계 |
| **3. 플레이북 실행** | 조건부 로직(IF-THEN)에 따라 악성 여부 자동 판정 및 격리 절차 구동 | BPMN 기반 플레이북 엔진, Python/Go 샌드박스 |
| **4. 연동 격리 및 차단** | 방화벽 차단 룰 배포, EDR 호스트 네트워크 격리, AD 계정 잠금 수행 | 방화벽 API, EDR 커넥터, LDAP/AD Powershell |

## Ⅳ. SIEM vs SOAR vs XDR 비교

| 비교 항목 | SIEM (로그 및 탐지) | SOAR (연계 및 대응 자동화) | XDR (확장 탐지 및 대응) |
|---|---|---|---|
| **주요 역할** | 전사 로그 중앙 수집 및 상관분석 탐지 | 이기종 도구 오케스트레이션 및 대응 자동화 | 엔드포인트-네트워크-클라우드 통합 분석 |
| **데이터 소스** | 방화벽, 서버, 애플리케이션 로그 전반 | SIEM 경보, 침해 지표(IoC), TIP 인텔리전스 | 벤더 고유의 엔드포인트/네트워크 텔레메트리 |
| **대응 방식** | 관제사에게 경보 알림 전송 (수동 대응) | **플레이북 기반 사전 정의된 자동 조치** | 네이티브 에이전트 기반 내장 차단 기능 |
| **연동 개방성** | 표준 로그 포맷 수집 중심 | **모든 서드파티 솔루션 API 연계 특화** | 단일 벤더 중심 생태계 (폐쇄적 경향) |
| **핵심 지표 개선** | MTTD(탐지 시간) 단축 | **MTTR(대응 시간) 90% 이상 단축** | MTTD 및 MTTR 동시 단축 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **오탐(False Positive)으로 인한 핵심 비즈니스 서버 오차단 장애**<br>SIEM의 오탐 경보를 수신한 플레이북이 무인 자동화 모드로 구동되어 정상적인 ERP 데이터베이스 서버의 IP를 방화벽에서 일괄 차단함으로써 대규모 서비스 중단 유발 | **위험도 기반 다계층 승인(HITL) 및 롤백 서킷 브레이커 도입**<br>자산 중요도(Asset Criticality)가 높은 핵심 시스템 대상 조치는 반드시 관제 요원의 원클릭 승인(HITL)을 거치도록 강제하고, 오차단 발생 시 10초 이내에 정책을 원복하는 롤백 API 및 트래픽 이상 시 자동 중단되는 서킷 브레이커 구현 |
| **이기종 보안 벤더의 API 스키마 변경에 따른 플레이북 런타임 크래시**<br>클라우드 보안 및 방화벽 벤더의 소프트웨어 업데이트로 REST API 파라미터가 변경되거나 인증 토큰이 만료되어 비상 대응 플레이북 실행 중단 사고 발생 | **OpenC2 표준 채택 및 커넥터 CI/CD 자동화 카나리 검증**<br>OASIS OpenC2 표준 명령 규격을 미들웨어로 적용하여 개별 벤더 API 의존성을 추상화하고, 매일 모의 공격 이벤트를 주입하여 플레이북 및 API 커넥터 상태를 검증하는 카나리 헬스체크 파이프라인 상시 운영 |

## Ⅵ. 제언

```text
[차세대 자율형 보안관제(Autonomous SOC) 아키텍처 로드맵]

 +--------------------+     +---------------------+     +--------------------+
 | AI 기반 경보 필터  | --> | 지능형 SOAR 실행    | --> | 관제사 역량 고도화 |
 | 오탐 95% 사전 제거 |     | 정형화된 대응 100%   |     | 고위험 위협 헌팅   |
 | (LLM Agent 연계)   |     | (MTTR 분 단위 완결) |     | 집중 수행 체계     |
 +--------------------+     +---------------------+     +--------------------+
```

| 관제 성숙도 | 운영 방식 | 도입 기술 |
|---|---|---|
| **Level 1: 전통적 관제** | 24x365 관제 요원 수동 로그 분석 및 티켓팅 | SIEM, 침입탐지시스템(IDS) |
| **Level 2: 반자동 관제** | 경보 분류 및 CTI 인리치먼트 자동화 | SOAR 플레이북 (단순 조회 무인화) |
| **Level 3: 고도화 관제 (권장)** | AI 기반 오탐 필터링 및 고위험 HITL 자동 격리 | Generative AI Agent + SOAR + XDR 통합 |

단순히 도구만 도입하는 것을 넘어 조직의 침해사고 대응 지침(SOP)을 코드로 자산화(Code-as-Playbook)하는 지속적 엔지니어링 거버넌스 확립 권장.
