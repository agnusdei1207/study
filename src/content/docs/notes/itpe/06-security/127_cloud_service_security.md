## 지식 로드맵 내 현재 위치

지식 위치: 인프라 보안 → 클라우드 → **공동 책임 모델과 설정·워크로드 보호**

## 30초 인출

- **본질:** CSP(클라우드 서비스 제공자)와 고객이 서비스 모델(IaaS·PaaS·SaaS)별 보안 책임을 분할하고, 자산 형상·신원 권한·워크로드를 엔드투엔드로 보호하는 프레임워크
- **메커니즘:** 책임 공유 모델 확립 → CI/CD 내 IaC 보안 정적 검사(Shift-Left) → CSPM(설정)/CIEM(권한) 거버넌스 → CWPP(eBPF 기반 런타임 감시) 통합 CNAPP 운영
- **통찰:** 멀티클라우드 환경의 권한 파편화는 CIEM 기반 사용 이력 분석으로 최소 권한을 자동화하고, 단기 컨테이너 워크로드는 eBPF 기반 에이전트리스 실시간 탐지 체계 필수

<details>
<summary>핵심 용어</summary>

- **공동 책임 모델 (Shared Responsibility)** : 인프라 자체 보안(Security OF the Cloud)과 클라우드 내부 자원 보안(Security IN the Cloud)을 분계하는 원칙.
- **CSPM (Cloud Security Posture Management)** : 클라우드 자원의 잘못된 설정(Misconfiguration) 및 규정 준수 여부를 자동 감사하는 도구.
- **CIEM (Cloud Infrastructure Entitlement Management)** : 클라우드 내 인간 및 머신 신원의 과다 권한을 분석하고 최소 권한을 부여하는 기술.
- **CWPP (Cloud Workload Protection Platform)** : VM, 컨테이너, 서버리스 등 클라우드 실행 워크로드의 런타임 위협을 실시간 방어하는 솔루션.

</details>

## 2~4교시 예상문제 (25점)

> 클라우드 서비스 모델(IaaS, PaaS, SaaS)별 책임 공유 모델(Shared Responsibility Model)의 한계점을 분석하고, CNAPP(CSPM, CIEM, CWPP) 아키텍처를 중심으로 한 클라우드 네이티브 보안 체계 및 엔지니어링 구현 방안을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 클라우드 인프라 제공자(CSP)와 이용자(고객) 간의 서비스 모델별 책임 한계를 명확히 구분하고, 동적 가상 자원에 대한 신원·설정·데이터·워크로드를 보호하는 종합 보안 체계 |
| 목적 | 물리적 경계가 사라진 소프트웨어 정의 인프라(SDI) 환경에서 설정 오류(Misconfiguration)와 과다 권한에 의한 대규모 데이터 유출을 방지하고 비즈니스 연속성 보장 |

- 클라우드 침해 사고의 95% 이상이 CSP의 인프라 결함이 아닌 고객의 잘못된 설정 및 자격증명 관리 미흡에서 비롯되므로 고객 영역의 능동적 보안 거버넌스가 핵심

## Ⅱ. 클라우드 보안의 핵심 기술적 특성

| 특성 항목 | 세부 내용 및 기술적 의미 | 엔지니어링 구현 방식 |
|---|---|---|
| 책임의 동적 이동성 | IaaS에서 PaaS, SaaS로 전환될수록 고객의 운영 책임이 축소되고 CSP의 관리 영역 확장 | 계약서 및 SLA 상의 RACI 매트릭스 수립 |
| API 및 소프트웨어 정의 통제 | 네트워크, 서버, 스토리지가 모두 코드로 프로비저닝(IaC)되므로 보안 정책 역시 코드로 배포 | DevSecOps 파이프라인 내 PaC(Policy as Code) 구현 |
| 단기 워크로드 수명 (Ephemeral) | 컨테이너 및 서버리스 인스턴스가 수초에서 수분 내 생성·소멸하는 휘발성 특성 | 불변 이미지 서명 및 에이전트리스 eBPF 감시 |
| 아이덴티티가 새로운 경계 | IP 기반 성벽 방어가 무력화되고 IAM 역할과 권한 토큰이 핵심 접근 제어 경계로 대체 | 제로 트러스트 기반 동적 임시 자격증명(STS) 적용 |

- 멀티 테넌시(Multi-Tenancy) 환경에서 가상화 격리(하이퍼바이저, 컨테이너 네임스페이스)와 고객 데이터 완전 암호화를 기본 전제로 동작하는 특성 보유

## Ⅲ. 클라우드 네이티브 통합 보안(CNAPP) 아키텍처 및 메커니즘

```text
[클라우드 네이티브 애플리케이션 보호 플랫폼(CNAPP) 통합 아키텍처]

 ┌─────────────────────────────────────────────────────────────┐
 │       1. 개발 및 빌드 단계 (Shift-Left DevSecOps)            │
 │   - IaC 템플릿 정적 분석 (Checkov, tfsec)                   │
 │   - 컨테이너 베이스 이미지 취약점 및 악성코드 스캔 (Trivy)  │
 └──────────────────────────────┬──────────────────────────────┘
                                │
                                ▼ (CI/CD 배포 파이프라인)
 ┌─────────────────────────────────────────────────────────────┐
 │           2. 배포 및 형상 거버넌스 단계 (CSPM & CIEM)        │
 │   ┌────────────────────────┐    ┌────────────────────────┐  │
 │   │ CSPM (형상/컴플라이언스)│    │ CIEM (권한 및 신원 관리)│  │
 │   │ - S3 버킷 퍼블릭 차단  │    │ - 미사용 과다권한 회수 │  │
 │   │ - 보안 그룹 드리프트 감│    │ - AssumeRole 체인 분석 │  │
 │   └────────────────────────┘    └────────────────────────┘  │
 └──────────────────────────────┬──────────────────────────────┘
                                │
                                ▼ (런타임 프로덕션 운영)
 ┌─────────────────────────────────────────────────────────────┐
 │          3. 런타임 워크로드 보호 단계 (CWPP & CDR)          │
 │   - eBPF 커널 프로브 기반 무에이전트 시스템 콜/네트워크 감시│
 │   - 컨테이너 런타임 이상 프로세스 및 권한 상승 실시간 차단  │
 │   - Cloud SIEM 연동 위협 탐지 및 람다 자동 격리(SOAR)      │
 └─────────────────────────────────────────────────────────────┘
```

| CNAPP 구성 요소 | 보호 영역 및 기술 메커니즘 | 실시간 통제 효과 |
|---|---|---|
| CSPM (형상 관리) | CSP API를 지속 폴링하여 CIS Benchmark 기준 리소스 설정 오류 및 컴플라이언스 위반 분석 | S3 퍼블릭 오픈, 비인가 방화벽 포트(22, 3389) 개방 즉시 탐지 |
| CIEM (권한 거버넌스) | 인간 및 머신(서비스 어카운트) 신원의 IAM 권한과 실제 CloudTrail 호출 로그 대조 | 사용률 0% 권한 및 과도한 와일드카드(`*`) 정책 자동 축소 |
| CWPP (워크로드 보호) | 쿠버네티스 Pod 및 VM 내 프로세스 메모리, 파일 무결성, 네트워크 인아웃바운드 검사 | 웹쉘 실행, 리버스 쉘 생성, 컨테이너 탈출(Breakout) 실시간 차단 |
| CDR (위협 탐지·대응) | 클라우드 컨트롤 플레인(CloudTrail, VPC Flow) 로그를 머신러닝으로 분석해 비정상 행위 감지 | 비인가 지역 API 호출, 대량 스냅샷 유출 시 자동 세션 만료 |

## Ⅳ. 서비스 모델별 책임 공유(Shared Responsibility) 비교

| 관리 영역 | 전통 온프레미스 | IaaS (예: EC2) | PaaS (예: RDS, App Engine) | SaaS (예: M365) |
|---|---|---|---|---|
| 데이터 분류 및 접근 통제 | 고객 책임 | 고객 책임 | 고객 책임 | 고객 책임 |
| 계정 및 IAM 신원 거버넌스 | 고객 책임 | 고객 책임 | 고객 책임 | 고객 책임 |
| 애플리케이션 및 코드 | 고객 책임 | 고객 책임 | 고객 책임 | CSP 책임 |
| 런타임 및 미들웨어 | 고객 책임 | 고객 책임 | CSP 책임 | CSP 책임 |
| 게스트 운영체제(OS) 패치 | 고객 책임 | 고객 책임 | CSP 책임 | CSP 책임 |
| 가상화 하이퍼바이저/서버 | 고객 책임 | CSP 책임 | CSP 책임 | CSP 책임 |
| 물리 네트워크 및 데이터센터 | 고객 책임 | CSP 책임 | CSP 책임 | CSP 책임 |

## Ⅴ. 클라우드 보안 운영 시 엔지니어링 한계와 해결 방안

| 한계 | 방안 |
|---|---|
| 멀티클라우드(AWS, Azure, GCP) 환경에서 CSP별 IAM 정책 표현식 차이로 권한 파편화 및 방치된 과다 권한 발생 | 통합 CIEM 엔진을 도입하여 멀티클라우드 IAM 정책을 표준 모델로 정규화하고, 최근 90일간 실제 호출되지 않은 미사용 권한을 자동 롤백하는 최소 권한 자동화 구현 |
| 개발자의 웹 콘솔 직접 수정(ClickOps)으로 인해 코드와 실제 인프라 상태가 불일치하는 구성 드리프트(Drift) 발생 | 모든 인프라 변경을 GitOps PR을 통해서만 허용하고, 콘솔 수정 발생 시 이벤트 브릿지(EventBridge)와 람다를 연동하여 IaC 템플릿 기준으로 자동 복구(Auto-Healing) |
| 마이크로서비스 컨테이너의 수명이 수초~수분에 불과하여 무거운 전통 EDR 에이전트 설치 시 부하 및 포렌식 누락 | Linux 커널 계층의 eBPF(Extended Berkeley Packet Filter) 기술을 적용하여 호스트 및 컨테이너 무중단 무에이전트 런타임 텔레메트리를 수집하고 메모리 덤프 자동 스냅샷 연동 |
| CSPM의 수만 건 경보 발생으로 인한 보안 운영자의 경보 피로(Alert Fatigue) 및 우선순위 식별 실패 | 공격 경로 분석(Attack Path Analysis) 그래프 알고리즘을 도입하여 '인터넷 노출 + 심각 취약점 + 고권한 IAM'이 결합된 치명적 위험 경로(Toxic Combination)만 선별 통보 |

## Ⅵ. DevSecOps 기반 클라우드 네이티브 보안 성숙도 제언

```text
[클라우드 네이티브 보안 성숙도 3단계 로드맵]

 ┌─────────────────────────────────────────────────────────────┐
 │       1단계: 정적 기반 가시성 확보 (Foundational)             │
 │   - CIS Benchmark 기반 CSPM 자동 점검 체계 구축             │
 │   - KMS 기반 전 저장 데이터 암호화(CMEK) 적용                │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │       2단계: 파이프라인 통합 및 거버넌스 (Integrated)         │
 │   - CI/CD 파이프라인 내 IaC 보안 검사(Policy as Code) 통과 강제│
 │   - CIEM 기반 최소 권한 자동 다운사이징 체계 가동           │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │       3단계: 지능형 런타임 능동 방어 (Advanced CNAPP)        │
 │   - eBPF 기반 CWPP 실시간 컨테이너 위협 능동 차단            │
 │   - SOAR 연계 클라우드 침해 사고 5분 내 자동 격리 파이프라인│
 └─────────────────────────────────────────────────────────────┘
```

| 성숙도 지표 | 엔지니어링 세부 목표 | 통제 기준치 |
|---|---|---|
| 빌드 보안 통과율 | CI/CD 단계에서 심각(Critical) 취약점 포함 이미지의 배포 자동 차단율 | 차단율 100% (취약점 무관용 원칙) |
| 설정 오류 해결 시간 | CSPM 탐지 퍼블릭 스토리지 등 치명적 설정 오류의 평균 조치 시간(MTTR) | MTTR < 10분 (자동 복구 람다 가동) |
| IAM 최소 권한율 | 전사 머신 및 사용자 계정 중 실사용 권한만 부여된 최소 권한 달성 비율 | 최소 권한 적합률 > 95% 유지 |
