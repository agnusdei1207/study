## 지식 로드맵 내 현재 위치

지식 위치: 인프라 보안 → 클라우드 → **공동 책임 모델과 설정·워크로드 보호**

## 30초 인출

- 본질: 클라우드 제공자와 고객이 서비스 모델별 책임을 나누고, 자산·신원·설정·데이터·워크로드를 통제하는 보안 체계
- 경계: 제공자의 인프라 보안과 고객의 클라우드 사용 보안을 구분. 세부 책임은 서비스·계약·설정에 따라 확인

## 1교시 예상문제 (10점)

> 클라우드 보안의 공동 책임 모델을 IaaS·PaaS·SaaS별로 설명하시오. (예상·10점)

## 1교시 10점 답안

### Ⅰ. 개념

공동 책임 모델은 CSP가 운영하는 기반 계층과 고객이 구성·사용하는 계층의 보안 책임을 서비스별로 나누는 방식.

### Ⅱ. 모델별 책임의 예

| 서비스 | 제공자 주된 영역 | 고객 주된 영역 |
|---|---|---|
| IaaS | 물리 시설·호스트·가상화 기반 | 게스트 OS·응용·데이터·접근 정책 |
| PaaS | 기반·관리형 런타임 | 응용 코드·데이터·사용자 권한 |
| SaaS | 기반·서비스 응용 운영 | 계정·데이터·테넌트 설정 |

서비스마다 세부 경계가 다르므로 계약서와 서비스별 책임 문서로 확정.

## 2~4교시 예상문제 (25점)

> 클라우드 서비스 모델별 공동 책임을 설명하고, 설정 오류·과다 권한·워크로드 위협에 대응하는 보안 설계를 제시하시오. (예상·25점)

## 2~4교시 25점 답안

### Ⅰ. 개요

클라우드 보안은 제공자의 인프라 보호와 고객의 안전한 구성·사용을 결합. 서비스 모델이 관리 범위에 영향을 주지만 고객의 데이터·신원 관리가 사라지지는 않음.

### Ⅱ. 책임 분계

```text
CSP: 시설 → 물리 서버 → 가상화 기반 → 관리형 서비스 계층
고객: 업무 데이터 → 신원·권한 → 응용·설정 → 게스트 OS(IaaS)
                         ↑ 서비스에 따라 경계 이동
```

공동 책임은 한 사고에 대해 책임 비율을 일괄 50:50으로 나누는 뜻이 아님.

### Ⅲ. 주요 위협과 통제

| 위협 | 원인 | 통제 |
|---|---|---|
| 공개 스토리지 | 잘못된 접근 정책·자산 가시성 부족 | 기본 비공개·설정 점검·변경 감시 |
| 과다 권한 | 장기 자격증명과 넓은 역할 | 최소 권한·임시 자격증명·권한 검토 |
| 취약 워크로드 | 이미지·패키지·런타임 취약점 | 공급망 검사·패치·런타임 탐지 |
| 데이터 유출 | 분류·암호화·키 관리 미흡 | 데이터 분류·암호화·키 분리 |
| 로그 공백 | 서비스별 감사 설정 누락 | 중앙 로그·보존·사고 대응 훈련 |

### Ⅳ. 도구의 역할

| 기능 | 적용 대상 |
|---|---|
| CSPM | 클라우드 자원 구성·정책 상태 |
| CIEM | 클라우드 권한과 미사용·과다 권한 |
| CWPP | VM·컨테이너 등 워크로드 보호 |
| CASB | 사용자의 SaaS 접근·이용 가시성 |

CNAPP는 공급자별로 여러 기능을 통합하는 제품 범주. CASB를 CNAPP의 필수·동일 구성 요소로 단정할 수 없음.

### Ⅴ. 구축 절차

```text
자산·데이터 분류 → 책임 경계·계약 확인 → IAM·네트워크 기준
              → IaC 검사·배포 → 지속 점검·로그·복구 훈련
```

IaC 기반 배포는 변경 통제에 유리하지만 긴급 변경·관리 콘솔 접근을 무조건 차단하는 것이 보편 해법은 아님.

### Ⅵ. 실무 쟁점

| 쟁점 | 확인할 내용 |
|---|---|
| 멀티클라우드 | 정책 표현·로그 형식·키 관리 차이 |
| 위탁·인증 | 적용 산업·서비스 범위별 CSAP 등 요건 |
| 사고 대응 | 제공자와 고객의 증적·연락·복구 역할 |
| 자동 교정 | 오탐에 따른 서비스 중단을 피할 승인·롤백 |

### Ⅶ. 기술사적 제언

서비스 모델과 실제 계약에 맞는 책임표를 먼저 확정하고, 설정·권한·워크로드 통제를 배포 단계부터 운영·복구까지 연결.
