## 지식 로드맵 내 현재 위치

정보보안 → 암호 분석학(Cryptanalysis) → 암호 공격 모델 (COA·KPA·CPA·CCA)

## 30초 인출

- **본질:** 암호 해독 시 공격자가 보유한 사전 지식과 암호화/복호화 오라클 질의 능력에 따라 분류한 4대 공격 모델(COA, KPA, CPA, CCA)과 현대 암호의 안전성 증명 체계.
- **메커니즘:** 암호문 단독 관찰(COA) → 평문-암호문 쌍 획득(KPA) → 임의 평문 암호화 질의(CPA) → 적응적 암호문 복호화 질의(CCA)로 공격자 역량 단계적 고도화.
- 통찰: 현대 암호 시스템은 최강의 능동적 공격 모델인 적응적 선택 암호문 공격(CCA2) 하에서 구별 불가능성(IND-CCA2)을 달성해야 하므로, AEAD 및 RSA-OAEP 적용 필수.

<details><summary>핵심 용어</summary>

- **COA(암호문 단독 공격, Ciphertext-Only Attack)**: 공격자가 오직 가로챈 암호문만을 바탕으로 평문이나 비밀키를 유추하는 가장 기본적인 공격 모델.
- **KPA(기지 평문 공격, Known-Plaintext Attack)**: 특정 평문과 그에 대응하는 암호문 쌍을 이미 확보한 상태에서 다른 암호문의 평문이나 키를 찾는 공격.
- **CPA(선택 평문 공격, Chosen-Plaintext Attack)**: 공격자가 임의의 평문을 선택하여 암호화 장치(오라클)로부터 그에 대응하는 암호문을 획득할 수 있는 모델 (공개키 암호는 기본적으로 CPA 노출).
- **CCA(선택 암호문 공격, Chosen-Ciphertext Attack)**: 공격자가 타깃 암호문을 제외한 임의의 암호문을 복호화 오라클에 입력하여 그에 대한 복호화 결과를 얻을 수 있는 강력한 공격 모델 (CCA1: 비적응적, CCA2: 적응적).
- **IND-CCA2**: 적응적 선택 암호문 공격 하에서 임의의 두 평문 중 어떤 것이 암호화되었는지 확률적으로 구별할 수 없는(Indistinguishability) 현대 암호의 표준 안전성 요건.
</details>

## 2~4교시 예상문제 (25점)

> 암호 해독(Cryptanalysis)의 4대 공격 모델(COA, KPA, CPA, CCA)을 공격자가 보유한 정보와 오라클 질의 능력 관점에서 비교하고, 현대 암호학의 안전성 기준인 IND-CPA 및 IND-CCA2의 개념과 실무 오라클 공격(패딩 오라클 등)에 대한 엔지니어링 방어 방안을 제시하시오. (25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 암호 알고리즘과 통신 프로토콜의 안전성을 분석하기 위해 공격자가 관찰 가능한 데이터와 암·복호화 시스템(오라클)에 대해 행사할 수 있는 질의 권한 수준을 정의한 이론적·실무적 공격 분류 체계 |
| 목적 | 시스템 설계 시 공격자의 잠재적 능력을 과소평가하지 않고 최악의 적대적 환경에서도 기밀성과 무결성을 수학적으로 보장하기 위한 안전성 척도 수립 |

## Ⅱ. 4대 암호 해독 공격 모델의 핵심 특징 및 공격자 능력

| 공격 모델 | 공격자 보유 정보 및 질의 권한 | 공격 성공 난이도 | 주요 분석 기술 및 공격 벡터 |
|---|---|---|---|
| COA (암호문 단독 공격) | 도청을 통해 획득한 암호문 C 집합만 보유 | 가장 어려움 (공격자에게 가장 불리) | 빈도 분석(Frequency Analysis), 통계적 전수 조사 |
| KPA (기지 평문 공격) | 암호문 C와 사전에 짝을 이룬 일부 평문 P 쌍 확보 | 보통 | 선형 암호분석(Linear Cryptanalysis), 전치 암호 역산 |
| CPA (선택 평문 공격) | 자신이 원하는 임의의 평문 P를 골라 암호문 C 획득 가능 | 상대적으로 쉬움 | 차분 암호분석(Differential), 공개키 암호 전수 대조 |
| CCA (선택 암호문 공격) | 타깃 암호문 외에 임의의 조작된 C에 대한 복호화 오라클 질의 | 가장 쉬움 (공격자에게 가장 유리) | 패딩 오라클(Padding Oracle), 블라이헨바허(Bleichenbacher) |

## Ⅲ. 암호 공격자 오라클 모델 및 IND-CCA2 증명 아키텍처

```text
[ 현대 암호학의 IND-CCA2 (적대적 구별 불가능성 게임) 아키텍처 ]

[ 도전자 (Challenger) ]                                       [ 공격자 (Adversary) ]
         │                                                            │
         │ ◀─── 1. 복호화 질의 (Decryption Query: C_i) ───────────────┤ (1단계 Phase 1)
         ├───── 2. 복호화 결과 반환 (Dec(C_i) = P_i) ────────────────>│
         │                                                            │
         │ ◀─── 3. 챌린지 평문 제출 (P_0, P_1 선택, 길이 동일) ───────┤
[무작위 비트 b in {0,1} 선택]                                          │
[암호문 생성 C* = Enc(P_b)]                                           │
         ├───── 4. 챌린지 암호문 C* 전달 ────────────────────────────>│
         │                                                            │
         │ ◀─── 5. 추가 복호화 질의 (단, C* 자체는 질의 불가!) ───────┤ (2단계 Phase 2)
         ├───── 6. C* 변형 암호문 C'에 대한 복호화 응답 ─────────────>│
         │                                                            │
         │ ◀─── 7. 비트 추측 결과 b' 출력 (b == b' 이면 공격자 승리!) ┤
         │                                                            │
[ 판정: 공격자가 우연(1/2)보다 유의미하게 높은 확률로 맞추지 못해야 IND-CCA2 안전성 만족 ]
```

| 암호 분석 모델 | 오라클 환경 및 공격 메커니즘 | 실무 적용 취약점 사례 |
|---|---|---|
| COA (Ciphertext-Only) | 네트워크 구간 도청을 통해 암호화 패킷만 획득한 수동적 공격자 모델 | 레거시 시저 암호, DES 축소 라운드 통계 분석 |
| KPA (Known-Plaintext) | 헤더, 프로토콜 고정 문자열(HTTP GET, PDF 매직넘버 등)로 평문-암호문 쌍 획득 | 2차 대전 에니그마 해독, ZIP 암호 해독(PKZIP 취약점) |
| CPA (Chosen-Plaintext) | 공개키 암호(RSA, ECC)는 누구나 공개키로 암호화할 수 있으므로 본질적으로 CPA에 노출 | 결정론적 RSA 암호화 시 사전 평문 후보군 전수 암호화 비교 |
| CCA1 (비적응적 CCA) | 챌린지 암호문을 받기 전까지만 복호화 오라클을 사용할 수 있는 제한적 모델 | 점심시간 공격(Lunchtime Attack), 나오르-융(Naor-Yung) |
| CCA2 (적응적 CCA) | 챌린지 암호문을 받은 후에도 이를 변형한 암호문들을 지속 질의 가능한 최강 모델 | TLS 1.2 CBC 패딩 오라클(POODLE), RSA PKCS#1 v1.5 공격 |

## Ⅳ. 4대 암호 공격 모델(COA, KPA, CPA, CCA) 기술적 비교

| 비교 항목 | COA | KPA | CPA | CCA |
|---|---|---|---|---|
| 공격자 권한 | 수동적 수집 (Passive Sniffing) | 일부 짝지어진 데이터 수동 확보 | 암호화 연산 장치 자유 질의 | 복호화 서버 응답/오류 실시간 질의 |
| 공개키 환경 노출 | 자연 노출 | 기본 노출 | 100% 본질적 노출 (공개키가 공개됨) | 복호화 서버가 오류/응답 제공 시 노출 |
| 암호학적 요구 안전성 | 통계적 무작위성 | 일방향성(OW-CPA) | 구별 불가능성(IND-CPA) | 적응적 구별 불가능성(IND-CCA2) |
| 대표적 공격 대상 | 취약한 스트림 암호 | 고정 블록 암호화 | ECB 모드, 무작위 패딩 없는 RSA | CBC 모드, PKCS#1 v1.5 패딩 |
| 방어 설계 기술 | 충분한 키 길이 (256-bit) | IV(초기화 벡터) 무작위화 | 확률적 암호화(Randomized Padding) | AEAD(인증 암호화), RSA-OAEP |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 서버가 잘못된 암호문 수신 시 '패딩 오류'와 'MAC 불일치 오류'를 서로 다른 응답 코드나 시간차로 반환하여 복호화 오라클(CCA2)로 기능 | 암호화와 무결성 검증을 분리하지 말고 단일 연산으로 처리하는 AEAD(AES-GCM, ChaCha20-Poly1305) 모드로 전면 전환하고, 오류 메시지 단일화 |
| 암호 연산 시 처리하는 데이터 값에 따라 CPU 실행 시간이나 전력 소비량이 달라지는 사이드채널(Side-Channel) 누출 | 암호문과 무관하게 항상 동일한 CPU 사이클을 소비하도록 컴파일 단계에서 상수 시간 연산(Constant-Time Execution) 알고리즘 라이브러리 강제 적용 |
| 공개키 암호화 시 동일한 평문에 대해 항상 동일한 암호문이 생성되어 사전 대조 공격(CPA)에 무방비 | 결정론적 암호화를 전면 금지하고 무작위 난수(Salt/Seed)를 결합하는 확률적 암호화 표준인 RSA-OAEP 및 ECIES 적용 |
| 블록 암호화 운용 시 초기화 벡터(IV)나 논스(Nonce)를 고정하거나 재사용하여 평문 XOR 패턴이 유출되는 결함 | 암호학적으로 안전한 난수 생성기(CSPRNG)를 통해 매 세션마다 유일한(Unique) IV를 생성하고 카운터 기반 중복 방지 로직 강제 |

| 암호 설계 계층 | 핵심 구현 과제 | 비즈니스 가치 |
|---|---|---|
| 대칭키 암호화 | 취약한 CBC/ECB 모드를 영구 퇴역시키고 AES-256-GCM 표준으로 전면 교체 | 패딩 오라클 기반 데이터 복호화 공격 원천 차단 |
| 비대칭키 암호화 | 레거시 PKCS#1 v1.5를 배제하고 최신 RSA-OAEP 및 FIPS 203 PQC(ML-KEM) 도입 | 복호화 오라클 공격 차단 및 양자컴퓨터 도래 대비 |
| 구현 및 운영 | OpenSSL/BoringSSL 공인 라이브러리 사용 및 하드웨어 보안 모듈(HSM) 내 키 격리 | 사이드채널 및 메모리 덤프를 통한 비밀키 유출 제로화 |
