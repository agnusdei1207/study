## 지식 로드맵 내 현재 위치

지식 위치: 암호 분석 → 공격자 정보·질의 능력 → **COA·KPA·CPA·CCA**

## 30초 인출

- 본질: COA·KPA·CPA·CCA는 공격자가 관찰·질의할 수 있는 정보와 오라클 능력의 모델
- 메커니즘: 암호문 관찰(COA), 알려진 평문쌍(KPA), 선택 평문 암호화(CPA), 선택 암호문 복호화(CCA)로 가정 구분
- 통찰: 한계: 공격 모델을 단순 강약 순서로만 보면 실제 오류 오라클을 놓침 → 방안: 프로토콜의 질의 가능 범위와 응답 차이를 시험

<details><summary>핵심 용어</summary>

- CPA: 선택한 평문에 대한 암호화 결과를 얻는 공격 모델.
- CCA: 타깃 외에 선택한 암호문의 복호화 결과를 얻는 공격 모델.

</details>

## 2~4교시 예상문제 (25점)

> 암호 해독의 COA·KPA·CPA·CCA 모델과 실무 오라클 사례를 비교하고 방어 설계 시 필요한 안전성 조건을 설명하시오. (예상·25점)

## 2~4교시 25점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 암호 공격의 정보·오라클 모델은 공격자가 관찰하거나 질의할 수 있는 평문·암호문 범위를 정의하는 분석 틀 |
| 목적 | 실제 공격자 능력에 따른 암호 구성·오류 경로의 안전성 평가 |

암호 알고리즘·프로토콜을 평가할 때 공격자가 관측하거나 질의할 수 있는 범위를 명시하는 추상 모델.

### Ⅱ. 암호 체계와 공격자 오라클의 관계

```text
암호 체계 ─ 암호문·오류 응답 ─→ 공격자
    ↑                          │
    └── 허용된 암호화·복호화 질의 ┘
               ↓ 관측 결과 비교
     평문 정보·키 정보·구별 가능성 추론
```

공격 가능성은 암호문 외에 공격자가 어떤 평문 쌍과 암호화·복호화 질의 결과를 관측할 수 있는지에 따라 달라진다.

### Ⅲ. 공격자 능력 비교와 실무 사례

```text
암호문 관찰(COA)
   ├─ 평문·암호문 쌍 추가(KPA)
   ├─ 선택 평문의 암호화 질의(CPA)
   └─ 선택 암호문의 복호화 질의(CCA)
```

상세한 능력 포함 관계와 난이도는 모델·질의 제한에 따라 달라져 하나의 선형 순서로 단정하지 않음.

| 사례 | 공격 모델·원인 | 대응 |
|---|---|---|
| ECB 반복 패턴 | 암호문에서 구조 노출 | 적절한 무작위화·인증 암호 |
| 결정론적 공개키 암호 | 공격자가 공개키로 후보 평문 암호화·비교 | 검증된 확률적 체계 |
| RSA PKCS#1 v1.5 오류 차이 | 복호화 결과의 유효성 오라클 | 프로토콜 교체·오류 처리 |
| CBC 패딩 오류 차이 | 암호문 조작 후 응답 차이 | 인증 암호 및 안전한 처리 |

Bleichenbacher RSA 오라클과 SSL 3.0의 POODLE은 서로 다른 구조·공격.

#### 보안성 요구

IND-CPA·IND-CCA는 특정 게임과 가정 아래의 구별 불가능성. 모든 시스템에 'IND-CCA2 인증서'를 부여하는 고정 등급이 아니며, 필요 수준은 위협 모델과 사용 프로토콜에 따라 결정. GCM 등 AEAD는 적절한 논스·태그 검증 조건이 중요.

#### 설계·검증

| 항목 | 확인 |
|---|---|
| 암호 구성 | 검증된 표준 알고리즘·운용 모드·패딩 |
| 논스·IV | 생성·유일성 등 해당 모드 요건 |
| 오류 응답 | 상세 오류·시간차·재시도 정보 노출 |
| 키 | 생성·보관·교체와 서비스 간 분리 |

### Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 공격 모델을 단순 강약 순서로 해석하면 실제 오류 오라클을 놓침 | 프로토콜별 공격자 질의 가능 범위와 응답 차이를 시험 |

### Ⅴ. 제언

알고리즘 이름보다 공격자의 질의 능력과 실제 시스템 오류·로그 경로를 먼저 점검.

## 출제 이력과 검증 출처

- 제137회 Q-net 원문 1교시 4번은 “암호문 공격(Ciphertext Attack)”이며 유형 비교를 직접 요구하지 않음. 위 문항은 확장 예상문제.
