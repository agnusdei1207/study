## 지식 로드맵 내 현재 위치

소프트웨어 보안 → 개발·빌드·배포 → 공급망 검증

## 30초 인출
- 본질: 소프트웨어 공급망 보안은 외부 구성요소와 개발·빌드·배포 경로의 출처·무결성을 검증하는 활동
- 메커니즘: 공급자·개발자 신원 확인 → 승인된 코드 반입·격리 빌드 → 산출물 서명 검증 → SBOM 기반 영향 조사
- 통찰: 한계: SBOM만으로 악성 변경을 판별할 수 없음 → 방안: 공급자 신원·빌드 출처·산출물 서명을 각각 검증

---

<details><summary>핵심 용어</summary>

- SBOM: 제품에 포함된 소프트웨어 구성요소 목록.
- SLSA: 소프트웨어 산출물의 공급망 무결성 수준을 높이는 프레임워크.

</details>

## 2~4교시 예상문제 (25점)

> 소프트웨어 공급망의 개발·배포·운영 단계별 위협과 출처·무결성 검증 방안을 제시하시오. (예상·25점)

---

## 2~4교시 25점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 소프트웨어 공급망 보안은 외부 구성요소와 개발·빌드·배포 경로의 신원·출처·무결성을 검증하는 활동 |
| 목적 | 악성 변경·취약 구성요소의 제품·서비스 전파 가능성 감소 |

개발 원천 코드, 간접 의존성, 저장소·패키지 레지스트리, CI/CD, 배포 채널, 외부 유지보수 접근이 공급망. 오염된 패키지, 탈취된 게시 권한, 변조된 빌드 결과가 주요 위협.

### Ⅱ. 제로트러스트 기반 구조
```text
공급자·개발자 신원 확인 → 승인된 코드·의존성 반입
→ 격리된 빌드와 산출물 출처 기록 → 서명·무결성 검증 후 배포
→ SBOM 기반 영향 파악·취약점 대응
```

### Ⅲ. 통제와 한계
| 지점 | 검증 항목 |
|---|---|
| 신원·권한 | 공급자·개발자·CI 계정의 최소 권한·단기 자격증명 |
| 빌드 | 입력물·빌드 환경·생성물의 무결성 및 출처 |
| 배포 | 서명 검증, 승인된 저장소·버전 |
| 운영 | SBOM과 취약점·침해 정보의 매핑, 긴급 교체 |

SBOM은 구성요소 목록이며 악성 여부의 자동 보증서가 아님. SLSA 등은 위험에 맞게 적용하고 모든 공공 조달에 동일한 제출 의무가 있다고 단정하지 않음.

### Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| SBOM만으로 악성 구성요소나 변조 빌드를 자동 판정하지 못함 | 공급자 신원·빌드 출처·서명을 검증하고 SBOM을 영향 조사에 활용 |

### Ⅴ. 제언

외부 의존성 반입과 CI 배포 경로부터 소유자·서명 검증 지점을 정하고 변조 산출물 차단을 시험.
