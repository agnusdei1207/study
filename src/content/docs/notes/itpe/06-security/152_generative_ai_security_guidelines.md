## 지식 로드맵 내 현재 위치

지식 위치: 정보보안 → 인공지능 보안 → **생성형 AI 보안 지침**

## 30초 인출

- **본질:** 생성형 AI 시스템의 데이터 준비, 모델 학습, RAG/도구 연동, 배포 및 운영 전 주기에 걸쳐 신뢰성(Trustworthiness)과 보안을 확보하기 위한 NIST AI RMF 기반 위험관리 가이드라인
- **메커니즘:** 거버넌스 수립(Govern) $\rightarrow$ 고유 위험 식별(Map) $\rightarrow$ 레드팀 취약점 측정(Measure) $\rightarrow$ 입출력 가드레일 및 지속 모니터링(Manage)
- **통찰:** 일회성 사전 평가는 RAG 문서 추가 시 무력화되므로 PyRIT 기반 지속적 자동화 레드팀과 에이전트 도구 API 최소 권한 강제 필수

<details>
<summary>핵심 용어</summary>

- **NIST AI 600-1** : 생성형 AI의 고유 위험에 대응하기 위해 수립된 NIST AI RMF의 전용 프로파일.
- **AI RMF (Risk Management Framework)** : AI 위험을 통제하기 위한 4대 기능(Govern, Map, Measure, Manage) 기반 프레임워크.
- **Automated Red Teaming** : LLM의 탈옥, 프롬프트 인젝션 취약점을 도구를 통해 지속적·자동으로 공격 검증하는 기술.
- **AI TRiSM** : 인공지능의 신뢰(Trust), 위험(Risk), 보안(Security)을 통합 관리하는 가트너의 아키텍처 모델.

</details>

## 2~4교시 예상문제 (25점)

> NIST AI RMF 기반의 생성형 AI 프로파일(NIST AI 600-1)의 4대 기능 및 12대 핵심 위험 요소를 설명하고, RAG 및 에이전트 환경에서의 개발·운영 수명주기별 보안 통제 아키텍처를 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 대형언어모델(LLM) 및 멀티모달 생성형 AI 시스템의 기획, 데이터 수집, 모델 훈련, 서비스 오케스트레이션 및 폐기 전 주기에 걸쳐 사이버 보안 및 프라이버시 위험을 체계적으로 식별·완화하는 종합 위험관리 프레임워크 |
| 목적 | 생성형 AI의 잠재적 위험(기밀 유출, 허위 정보, 탈옥, 도구 남용)을 억제하고 책임 있는 AI(Responsible AI) 및 신뢰 가능한 AI 시스템 구축 |

- 전통적인 소프트웨어 보안 기준을 넘어 인공지능 특유의 확률적 동작, 환각, 프롬프트 인젝션 등 새로운 적대적 머신러닝(Adversarial ML) 위협을 통제하는 글로벌 가이드라인

## Ⅱ. 생성형 AI 보안 가이드라인(NIST AI 600-1)의 핵심 특성

| 특성 항목 | 세부 내용 및 기술적 의미 | 엔지니어링 구현 가치 |
|---|---|---|
| 전사 위험 거버넌스 (Govern) | 조직의 AI 투명성, 위험 수용 한계선, 법적 책임 구조를 규정하는 최상위 통제 | 경영진-개발팀-보안팀 간 단절 없는 AI 위험 의사결정 체계 |
| 12대 생성형 AI 특화 위험 분류 (Map) | CBRN 위협, 사이버 공격 코드 생성, 지적재산권 침해, 프롬프트 탈옥 등 구체적 매핑 | AI 시스템의 위험 수준에 따른 맞춤형 보안 통제 설계 |
| 정량적 보안 평가 (Measure) | 벤치마크 데이터셋 및 적대적 레드팀 평가를 통해 모델의 탈옥 방어율 정량화 | 배포 승인 여부를 결정하는 객관적 보안 품질 지표(KPI) |
| 지속적 모니터링 및 억제 (Manage) | 런타임 가드레일, 에이전트 권한 제약, 드리프트 탐지 등 능동적 보안 운영 | 서비스 운영 중 발생하는 제로데이 탈옥 및 지식 오염 차단 |

- 단일 제품 규제가 아닌 프로세스 중심의 수명주기 지속 위험 평가(Continuous Risk Management) 특성 보유

## Ⅲ. NIST AI 600-1 수명주기별 보안 통제 아키텍처

```text
[생성형 AI 전주기 수명주기별 핵심 보안 통제 파이프라인]

 ┌─────────────────────────────────────────────────────────────┐
 │  1. 데이터 준비 단계 (Data Acquisition & Prep)              │
 │   - 데이터 출처(Provenance) 및 지적재산권 라이선스 검증     │
 │   - PII 스크러빙 (개인정보 비식별화) 및 데이터 오염 탐지    │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │  2. 모델 학습 및 미세조정 단계 (Model Training & Tuning)    │
 │   - 공급망 무결성 (Safetensors 포맷, 모델 서명 검증)        │
 │   - 차등 프라이버시(DP-SGD) 적용 및 정렬(RLHF/DPO) 하드닝   │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │  3. 시스템 연동 및 RAG 단계 (System Integration)            │
 │   - RAG 벡터 DB 접근제어(ABAC) 및 지식 청크 출처 격리       │
 │   - 도구(Tool) API 최소 권한 분리 및 Human-in-the-Loop 적용  │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │  4. 배포 및 런타임 운영 단계 (Deployment & Monitoring)      │
 │   - PyRIT 기반 자동화 적대적 레드팀(Red Teaming) 정례화     │
 │   - 인라인 입출력 가드레일 및 AI TRiSM 이상 징후 실시간 관제│
 └─────────────────────────────────────────────────────────────┘
```

| 수명주기 단계 | 주요 발생 위협 | 엔지니어링 통제 메커니즘 |
|---|---|---|
| 데이터 수집 | 무단 크롤링, 저작권 침해, 개인정보 포함 | 데이터 계보(Lineage) 추적, PII 정규식 필터링 |
| 모델 개발 | 악성 모델 가중치(Pickle RCE), 백도어 주입 | Safetensors 표준 강제, Cosign 모델 이미지 서명 |
| 서비스 통합 | 간접 프롬프트 주입, 비인가 도구 호출 | ChatML 컨텍스트 태깅, 고위험 액션 시 2차 승인 |
| 서비스 운영 | 신종 탈옥 프롬프트, 모델 성능 저하 | 자동화 레드팀 파이프라인, LLM-as-a-Judge 감사 |

## Ⅳ. 글로벌 AI 위험관리 프레임워크 비교

| 비교 항목 | NIST AI RMF (AI 600-1 Profile) | ISO/IEC 42001 (AIMS) | EU AI Act (인공지능법) |
|---|---|---|---|
| 성격 및 법적 효력 | 자발적 가이드라인 및 참조 프로파일 | 국제 표준 인공지능 경영시스템 인증 | 법적 강제 규제 (위반 시 최대 7% 과징금) |
| 핵심 초점 | 생성형 AI 특화 위험 식별 및 엔지니어링 통제 | 조직 차원의 AI 관리 프로세스 및 통제 프레임워크 | 위험 등급별(금지, 고위험, 제한, 최소) 차등 규제 |
| 통제 체계 구조 | Govern, Map, Measure, Manage (4대 축) | Plan-Do-Check-Act (PDCA) 수명주기 | 적합성 평가(Conformity Assessment), CE 마크 |
| 기술적 요구사항 | 프롬프트 인젝션 방어, 가드레일, RAG 통제 | AI 시스템 영향평가, 형상 관리, 투명성 | 데이터 거버넌스, 설명가능성, 인간 감독 |
| 주 적용 대상 | 미국 연방기관, 글로벌 AI 개발·도입 기업 | AI 시스템을 개발·운영하는 전 세계 조직 | EU 시장 내에서 유통·사용되는 모든 AI 시스템 |

## Ⅴ. 생성형 AI 가이드라인 적용 시 엔지니어링 한계와 해결 방안

| 한계 | 방안 |
|---|---|
| 배포 전(Pre-deployment) 레드팀 테스트를 완벽히 통과했더라도, RAG 지식 베이스가 동적으로 갱신되거나 도구 API가 추가될 때 새로운 침투 공격 표면 노출 | 마이크로소프트 PyRIT 또는 Garak 등 오픈소스 적대적 레드팀 자동화(Automated Red Teaming) 도구를 CI/CD 파이프라인에 통합하여, RAG 문서 및 도구 갱신 시마다 회귀 모의 침투 테스트 자동 실행 |
| 모델 파인튜닝 시 소량의 오염된 데이터(Poisoning Data) 주입만으로도 사전 학습된 안전 정렬(Safety Alignment)이 붕괴되는 타깃 중독 취약점 | 학습 데이터 수집 단계에서 임베딩 클러스터링 기반 이상치 탐지(Outlier Detection)를 적용하여 비정상 데이터셋을 사전 격리하고, 파인튜닝 시 LoRA 가중치 갱신 델타 범위를 엄격히 제한 |
| LLM의 비결정론적(Stochastic) 응답 특성으로 인해 고정된 정적 룰셋 기반 출력 가드레일이 높은 오탐(정상 답변 차단)과 미탐 발생 | 출력 계층에 LLM-as-a-Judge 구조를 적용하여 작은 크기의 경량 심사 모델(Llama Guard 등)이 응답의 유해성을 다각도로 채점(Scoring)하고, 기준 점수 초과 시 안전 대체 응답(Fallback) 자동 반환 |
| AI 에이전트가 외부 시스템과 통신할 때 인증 토큰을 탈취당하거나 위조된 API 호출을 수행하는 크리덴셜 남용 위협 | 에이전트 전용 단기 수명 토큰(Ephemeral Token)을 발급하고, 에이전트가 호출 가능한 API 화이트리스트를 mTLS 및 마이크로세그멘테이션으로 엄격히 격리 |

## Ⅵ. 지속 가능한 AI TRiSM 구현을 위한 종합 제언

```text
[엔터프라이즈 AI TRiSM 통합 보안 거버넌스 아키텍처]

 ┌─────────────────────────────────────────────────────────────┐
 │                 1. 모델 및 데이터 무결성 계층                │
 │   - 공급망 소프트웨어 자재명세서 (AI SBOM / AIBOM) 구축      │
 │   - 모델 가중치 서명 검증 및 안전한 Safetensors 포맷 강제   │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │              2. 오케스트레이션 및 런타임 제어 계층           │
 │   - 이중 LLM 기반 입력 프롬프트 실시간 이상 징후 검사       │
 │   - RAG 검색 청크 ABAC 기반 사용자 권한별 데이터 격리       │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │                 3. 지속적 안전성 감사 계층                  │
 │   - Automated Red Teaming (PyRIT) 주간 자동 실행            │
 │   - LLM-as-a-Judge 기반 출력 위험도 실시간 채점 및 감사     │
 └─────────────────────────────────────────────────────────────┘
```

| 관리 영역 | 핵심 엔지니어링 세부 과제 | 통제 목표치 |
|---|---|---|
| 공급망 무결성 | 전사 도입 오픈소스 AI 모델 가중치 및 라이브러리 SBOM 관리 | 미검증 모델/데이터 배포 0건 |
| 런타임 안전성 | RAG 검색 문서 및 에이전트 도구 권한의 최소 권한 격리율 | 권한 초과 비인가 데이터 접근 0건 |
| 지속적 검증 | PyRIT 기반 자동화 적대적 모의 공격 정례화 및 회귀 검증 | 탈옥/인젝션 취약점 조치율 100% |
