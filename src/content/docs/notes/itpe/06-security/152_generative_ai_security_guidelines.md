## 30초 인출

- **본질:** 생성형 AI 보안 가이드라인은 데이터 준비부터 모델·애플리케이션 개발과 운영까지 신뢰 경계를 유지하는 보안 기준.
- **메커니즘:** 데이터·모델 출처 확인 → 배포 전 공격 시험 → 서비스 권한·출력 검증 → 운영 중 감시·개선.
- **핵심:** 모델만 보호하는 것이 아니라 RAG 자료, 도구 호출, 사용자 권한과 후속 시스템까지 보호.

<details>
<summary>핵심 용어</summary>

- **생성형 AI 보안 가이드라인**: 생성형 AI 시스템의 개발·배포·운영 과정에서 보안위험을 식별하고 통제를 정하는 기준.
- **RAG(Retrieval-Augmented Generation)**: 검색한 자료를 모델의 응답 생성에 결합하는 방식.
- **모델 오염**: 학습 데이터·모델 구성요소의 조작으로 출력이 왜곡되는 위험.
- **프롬프트 인젝션(Prompt Injection)**: 신뢰할 수 없는 입력으로 모델의 지시나 행동을 바꾸려는 공격.
- **AI RMF(Artificial Intelligence Risk Management Framework)**: AI 위험을 조직의 목적에 맞게 관리하도록 NIST가 제시한 자발적 프레임워크.
</details>

NIST AI RMF의 생성형 AI 프로파일은 자발적 위험관리 자료. 개별 기술을 모두 의무로 요구하는 규정과 구분.

## Ⅱ. 개발·운영 수명주기

```text
데이터 확보 ─ 출처·권한·오염 점검
      ↓
모델 개발 ─ 구성요소·변경 검증
      ↓
서비스 연동 ─ RAG·도구 권한 통제
      ↓
운영 ─ 공격 시험·감시·사고 대응
```

| 단계 | 위험 | 통제 |
|---|---|---|
| 데이터 확보 | 개인정보 부적절 처리·오염 | 이용 근거·출처·품질 확인 |
| 모델 개발 | 변조된 모델·의존성 | 공급처·무결성·버전 관리 |
| 서비스 연동 | 프롬프트 인젝션·과도한 권한 | 검색 권한·도구 인가 |
| 운영 | 새로운 공격과 성능 변화 | 재시험·감시·사고 대응 |

## Ⅲ. 데이터·모델 신뢰

```text
공급처 확인
    ↓ 데이터·모델 구성요소 등록
무결성·사용권한 확인
    ↓
승인된 버전만 학습·배포
```

| 대상 | 확인할 정보 |
|---|---|
| 학습·검색 자료 | 출처, 이용 권한, 오염 가능성 |
| 모델·라이브러리 | 공급처, 버전, 변경 내역 |
| 평가 자료 | 운영 사례와 공격 사례의 대표성 |

## Ⅳ. 서비스 경계와 운영

```text
사용자·외부 문서
       ↓ 출처·권한 구분
모델 응답
       ↓ 출력·도구 인수 검증
데이터·외부 서비스 접근
       ↓
호출 기록·이상 징후 감시
```

| 통제 | 목적 |
|---|---|
| 사용자별 검색 권한 | 타인의 문서 노출 방지 |
| 도구별 최소 권한 | 잘못된 자동 실행의 영향 제한 |
| 출력 검증 | 후속 시스템의 명령·코드·쿼리 악용 방지 |
| 변경·사고 관리 | 새 모델·자료·도구의 영향 확인 |

## Ⅴ. 한계와 제언

| 한계 | 대응 |
|---|---|
| 입력 필터만으로 새로운 프롬프트 인젝션을 모두 차단하기 어려움 | 도구 인가·출력 검증을 별도 방어선으로 유지 |
| 배포 전 평가만으로 운영 중의 자료·모델 변화를 반영하기 어려움 | 변경 시점마다 공격 시나리오와 권한 경계 재검증 |
