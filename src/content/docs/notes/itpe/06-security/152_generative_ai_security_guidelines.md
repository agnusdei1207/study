# 생성형AI 보안 가이드라인

## 핵심 개념
- 생성형 AI 서비스를 기획·개발·배포·운영하는 전 과정에서 요구되는 보안 내재화(Security by Design) 및 개인정보 보호 지침.
- 과기정통부·KISA의 개발·운영 가이드라인, 개인정보보호위원회의 'AI 단계별 개인정보 처리 기준', 국제 표준(OWASP, NIST AI RMF)을 종합하여 신뢰성과 안전성을 검증.

```
+-------------------------------------------------------------+
|            생성형 AI 개발·운영 수명주기별 보안 통제            |
+-------------------------------------------------------------+
| 1. 데이터 수집/정제 | 크롤링 합법성, 가명·익명처리, 데이터 오염 방지  |
| 2. 모델 학습/튜닝   | 차분 프라이버시(DP), 백도어 탐지, 가중치 서명 |
| 3. 서비스 구축/연동 | 시스템 프롬프트 보호, RAG 접근제어, API 게이트웨이|
| 4. 배포 및 모니터링 | AI 레드팀 검증, 실시간 가드레일, 출력 살균     |
+-------------------------------------------------------------+
```

---

## AI 개발 및 서비스 4단계 보안 기준

```
[1. 기획/데이터 수집]
        |   - 개인정보 비식별 조치, 저작권 및 웹스크래핑 적법성 검토
        v
[2. 모델 개발/학습]
        |   - 학습 데이터 중독(Poisoning) 탐지, 가중치 암호화 및 서명
        v
[3. 서비스 연동/배포]
        |   - 프롬프트 가드레일(NeMo/Llama Guard), RAG 권한 분리
        v
[4. 운영 및 모니터링]
        |   - AI 레드팀 평가, 입력 탈옥 차단, 출력 필터링(DLP 연계)
        v
[안전하고 신뢰할 수 있는 AI 서비스 제공]
```

### 1. 데이터 수집 및 전처리 단계
- **적법성 및 동의 관리**: 공개된 데이터 수집 시 약관 준수, 정보주체의 권리 행사(삭제·거부 요구) 보장.
- **개인정보 비식별화(De-identification)**: 학습 데이터셋 내 주민등록번호, 연락처, 주소, 계좌번호 등 개인식별정보를 가명처리 또는 합성 데이터(Synthetic Data)로 대체.
- **학습 데이터 무결성 검증**: 악의적인 데이터 중독(Poisoning) 공격 방지를 위해 데이터 소스 신뢰도 점검 및 이상치 필터링.

### 2. 모델 학습 및 미세조정(Fine-tuning) 단계
- **차분 프라이버시(Differential Privacy)**: 역추론(Model Inversion) 공격에 의한 개인정보 복원을 차단하기 위해 그래디언트에 제어된 노이즈 주입(DP-SGD).
- **가중치 및 공급망 보호**: 사전 학습된 모델(Foundation Model) 다운로드 시 체크섬 및 전자서명 검증, 안전한 직렬화 포맷(Safetensors) 사용(Pickle 배제).
- **정렬(Alignment) 강화**: 인간 피드백 기반 강화학습(RLHF) 및 직접 선호도 최적화(DPO)를 통해 유해 출력 생성 억제.

### 3. 서비스 배포 및 인프라 연동 단계
- **프롬프트 가드레일(Guardrails)**: 시스템 계층과 사용자 입력 사이에 프롬프트 필터링 계층을 배치하여 악의적 탈옥 및 프롬프트 인젝션 패턴 사전 차단.
- **RAG(검색증강생성) 보안**: 외부 지식 베이스 연동 시 검색 사용자 권한에 따른 문서 접근 통제(Document-level ACL) 적용.
- **플러그인/에이전트 권한 최소화**: 외부 API 및 시스템 도구 호출 시 필요한 최소한의 읽기 권한만 부여하고, 중요 쓰기·전송 동작은 최종 사용자 확인(HITL) 절차 의무화.

### 4. 운영 및 모니터링 단계
- **출력 데이터 필터링**: 모델이 생성한 응답 내 PII, API 키, 사내 기밀 유출 여부를 정규식 및 DLP 엔진으로 실시간 살균.
- **지속적 AI 레드팀(Red Teaming)**: 알려지지 않은 취약점, 최신 탈옥 기법, 환각 발생 취약점을 능동적으로 발굴하기 위한 모의 공격 수행.
- **감사 추적성 확보**: 사용자 프롬프트, 모델 출력, 도구 호출 기록을 식별 불가능한 형태로 보관하여 이상 거래 및 보안 사고 사후 분석 지원.

## 가이드라인 규제 프레임워크 비교

| 구분 | 과기정통부·KISA 가이드라인 | 개인정보보호위원회 기준 | NIST AI RMF 1.0 |
|---|---|---|---|
| **중점 영역** | 생성형 AI 서비스 개발·운영 보안 기술 | 개인정보 처리 생애주기별 적법성 및 권리보호 | AI 위험 관리 거버넌스 및 신뢰성 프레임워크 |
| **핵심 요구사항** | 프롬프트 인젝션 방어, 가드레일 구축, 안전한 공급망 | 개인정보 가명화, 학습 제외(Opt-out), 투명성 고지 | Govern, Map, Measure, Manage 4대 기능 수행 |
| **위험 통제** | AI 레드팀, 취약점 점검 체계 | 개인정보 유출 통지, 침해사고 대응 | 신뢰성(신뢰도, 설명가능성, 공정성, 보안성) 확보 |

---

## 결론 및 실무 시사점
- 생성형 AI 보안 가이드라인은 모델 개발사뿐만 아니라 이를 파인튜닝하거나 RAG 기반 에이전트로 래핑하여 서비스하는 모든 기업의 준수 기준이 됨.
- 보안 내재화(DevSecOps) 파이프라인에 모델 취약점 스캐닝, 가드레일 자동 테스트, 데이터 비식별화 엔진을 통합하여 컴플라이언스 위험을 선제 관리해야 함.
