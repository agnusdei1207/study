## 지식 로드맵 내 현재 위치

인증·접근통제 → 생체인증 → 바이오정보 분산관리 및 금융 보안

## 30초 인출

- **본질:** 변경이 불가능한 생체 특징 정보를 2개 이상의 조각으로 암호학적으로 분할하여 금융회사와 공인 분산관리센터(금융결제원)에 분산 저장·인증하는 금융 보안 아키텍처
- **메커니즘:** 원본 생체 템플릿 추출 → 비밀 분산(Shamir's Secret Sharing) 2분할 → 금융회사와 결제원 분산 보관 → 인증 시 상호 결합 검증 후 즉시 파기
- 통찰: 인증 시 결합 순간의 메모리 덤프 탈취와 센서 위조(스푸핑) 공격을 방지하기 위해 TEE 기밀 컴퓨팅 기반 매칭과 하드웨어 라이브니스 탐지(PAD) 결합 필수

<details>
<summary>핵심 용어</summary>

- **바이오정보 분산관리:** 전자금융감독규정에 따라 생체인증 템플릿을 분할하여 개별 금융기관과 금융결제원에 각각 보관함으로써 단독 유출 시 원본 복원을 원천 차단하는 체계
- **생체 템플릿 (Biometric Template):** 지문, 홍채, 정맥 등 원본 생체 이미지에서 식별 특징점(Minutiae)을 추출하여 디지털 데이터로 변환한 특징 정보
- **비밀 분산 기법 (Secret Sharing):** 임계치 암호학을 활용하여 데이터를 여러 조각으로 나누고, 정해진 임계치($k$ out of $n$) 이상의 조각이 모여야만 복원이 가능한 암호 알고리즘
- **위조 검출 기술 (PAD, Presentation Attack Detection):** 실리콘 지문, 사진, 딥페이크 비디오 등 인공 위조 생체 신호를 센서 및 알고리즘 레벨에서 판별하는 생체 생체성(Liveness) 검증 기술
</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **바이오정보 분산관리** 는 금융거래 시 본인확인을 위해 수집된 생체정보(지문, 정맥, 홍채 등)의 특징점 템플릿을 암호학적으로 분할하여 금융회사와 분산관리센터(금융결제원)에 분산 저장하고 인증 시에만 연계 검증하는 금융 보안 표준 |
| 목적 | 생체정보의 비가역적 특성(유출 시 재발급 불가)에 따른 대규모 단일 유출 사고 방지 및 금융사 간 생체인증 호환성 확보 |

과거 단일 금융사 중앙 서버에 생체 템플릿을 전량 저장하던 구조의 침해 위험을 원천 해결하기 위해 제정.

## Ⅱ. 바이오정보 분산관리의 특징

| 특징 | 설명 | 보안 공학적 가치 |
|---|---|---|
| **정보의 불완전성** | 분할된 개별 조각 정보만으로는 원래의 생체 특징점을 유추하거나 재구성 불가 | 개별 금융사 또는 결제원 중 한 곳이 침해당해도 원본 불변 |
| **비밀 분산 알고리즘** | 샤미르 비밀 분산(Shamir's Secret Sharing) 또는 XOR 기반 분할 적용 | 수학적 정보이론 기반 무조건적 안전성 제공 |
| **금융 공동 인프라** | 금융결제원이 통합 인증중계센터 역할을 수행하여 전 금융사 상호 연동 | 은행, 증권, 보험 등 타 금융기관 방문 시에도 생체정보 재활용 가능 |
| **단기 결합 검증** | 인증 트랜잭션 수행 시에만 메모리 상에서 임시 결합 후 인증 즉시 휘발 파기 | 저장 시점뿐만 아니라 유휴 상태(At-Rest)에서의 지속적 안전성 확보 |

## Ⅲ. 바이오정보 분산관리 아키텍처 및 등록/인증 메커니즘

```text
[금융결제원 바이오정보 분산관리 등록 및 인증 프로세스]

 +---------------------------------------------------------------+
 |                       [사용자 / ATM / 창구]                   |
 |              생체 특징점(Template) 획득 및 2개 조각 분할      |
 +-------------------------------+-------------------------------+
                 조각 A 전송     |               | 조각 B 전송
                 +---------------+               +---------------+
                 v                                               v
 +-------------------------------+               +-------------------------------+
 |         [금융회사 서버]       |               |     [금융결제원 분산관리센터]  |
 |                               |               |                               |
 |   - 분할정보 A 저장           |               |   - 분할정보 B 저장           |
 |   - 고객 식별값(ID) 매핑      |               |   - 공통 분산관리 키 매핑     |
 +---------------+---------------+               +---------------+---------------+
                 |                                               |
                 +-----------------------+-----------------------+
                                         v
                         [인증 요청 시 (In-Memory 매칭)]
                          1. 조각 A + 조각 B 결합 요청
                          2. TEE 보안 영역 내에서 템플릿 복원
                          3. 입력된 생체 템플릿과 매칭 스코어 판정
                          4. 판정 완료 즉시 메모리 영구 소거
```

### 1. 등록 및 인증 상세 프로세스

| 단계 | 세부 엔지니어링 메커니즘 | 보안 요구사항 |
|---|---|---|
| **1. 생체정보 획득** | 센서(지문/정맥)로부터 원본 생체 이미지 취득 후 특징점(Minutiae) 추출 | 원본 생체 이미지 파일은 추출 즉시 영구 삭제 |
| **2. 분할 및 암호화** | 특징점 데이터를 분할 알고리즘으로 분할 정보 A와 B로 생성하고 각각 별도 대칭키로 암호화 | 난수 기반 솔트(Salt) 적용, 분할 조각 단독 복원 불가 |
| **3. 분산 저장** | 분할 정보 A는 개별 금융회사 내부 DB에, 분할 정보 B는 금융결제원 센터 DB에 전송 저장 | 전송 구간 mTLS 암호화 및 DB 내 컬럼 레벨 암호화 |
| **4. 연계 인증** | 거래 요청 시 결제원 또는 금융사 인증 서버로 조각 정보를 전송하여 매칭 후 결과 리턴 | 세션 만료 즉시 복원 데이터 메모리 제로화(Zeroize) |

## Ⅳ. 바이오정보 관리 방식 3자 비교

| 비교 항목 | 중앙집중 저장 방식 | 금융결제원 분산관리 방식 | FIDO 온디바이스 방식 |
|---|---|---|---|
| **저장 위치** | 단일 금융사 중앙 DB 서버 | **금융사 DB + 금융결제원 분산센터** | 사용자 스마트폰 보안영역(SE/TEE) |
| **서버 침해 영향** | 전 고객 생체정보 대량 유출 | **단독 침해 시 원본 복원 절대 불가** | 서버에 생체정보가 전혀 없음 (안전) |
| **기기 의존성** | 기기 무관 (ATM, 창구 가능) | **기기 무관 (전국 ATM, 창구 호환)** | 사용자 개인 스마트폰 필수 소지 |
| **인증 주체** | 서버 측 템플릿 매칭 | **분할 결합 후 서버/TEE 매칭** | 클라이언트 단말 내 검증, 비대칭키 서명 |
| **표준 규격** | 개별 기업 자체 구축 | 금융보안원 바이오정보 분산관리 표준 | FIDO Alliance UAF / FIDO2 표준 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **인증 시 분할 정보 결합 순간의 인메모리 덤프 공격 노출**<br>인증 매칭을 수행하기 위해 금융사 또는 결제원 서버 메모리 상에 조각 A와 조각 B를 결합하여 복원하는 찰나의 순간, 고권한 커널 공격자가 메모리 덤프를 통해 원본 템플릿 탈취 가능 | **TEE(신뢰실행환경) 기반 기밀 컴퓨팅 매칭 및 캔슬러블 바이오메트릭스**<br>인텔 SGX 또는 AMD SEV 기반 하드웨어 보안 엔클레이브(Enclave) 내부에서만 결합 및 매칭을 수행하여 호스트 OS 관리자도 메모리를 볼 수 없게 격리하고, 변환 파라미터를 교체할 수 있는 비가역적 캔슬러블(Cancelable) 템플릿 기술 결합 |
| **입력 센서 단에서의 위조 생체(실리콘/젤라틴/딥페이크) 스푸핑**<br>전송 및 저장 아키텍처가 안전하더라도, 사용자 인터페이스 단에서 정교하게 복제된 가짜 실리콘 지문이나 모니터 재생 공격에 의해 인증 시스템이 속아 넘어가는 위협 존재 | **다중 스펙트럼 센서 및 AI 라이브니스 탐지(ISO/IEC 30107 PAD) 적용**<br>체온, 혈류, 산소포화도를 감지하는 다중 스펙트럼 광학 센서를 도입하고, 딥러닝 기반 생체 진위 판별(PAD: Presentation Attack Detection) 알고리즘을 센서 펌웨어에 내장 |

## Ⅵ. 제언

```text
[옴니채널 금융 환경의 바이오인증 하이브리드 아키텍처]

       +-------------------------------------------------------+
       |               옴니채널 금융 바이오인증                |
       +---------------------------+---------------------------+
                                   |
         +-------------------------+-------------------------+
         |                                                   |
         v                                                   v
+-------------------------+               +--------------------------+
|  대면 / ATM / 무인점포   |               |  모바일 / 비대면 뱅킹    |
|  - 바이오정보 분산관리  |               |  - FIDO2 / Passkey       |
|  - 정맥/지문 금융결제원 |               |  - 온디바이스 생체인증   |
+-------------------------+               +--------------------------+
```

| 채널 분류 | 채널 특성 | 최적 인증 기술 스택 |
|---|---|---|
| **오프라인 창구 및 ATM** | 개인 단말 없이 신원 확인 요구 | 지정맥/손바닥정맥 기반 **바이오정보 분산관리 시스템** |
| **비대면 모바일 뱅킹** | 개인 전용 스마트폰 환경 | 스마트폰 지문/FaceID 기반 **FIDO2 / WebAuthn 표준** |
| **고액 이체 등 복합 인증** | 다중 요소(MFA) 강력 보안 필요 | 모바일 FIDO 인증 + 창구 분산관리 바이오 등록 교차 검증 |

오프라인 무인 금융 점포의 경우 금융결제원 분산관리 방식을 표준으로 확립하고, 모바일 스마트폰 환경은 FIDO2 온디바이스 방식을 결합하는 채널별 특화 하이브리드 인증 전략 수립 권장.

## 출제 이력과 검증 출처

- 정보관리기술사 116회, 125회 바이오정보 분산관리 및 생체인증 보안

- ISO/IEC 30107 Presentation Attack Detection (PAD) Standards
