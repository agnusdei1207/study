## 30초 인출
- SQL 삽입은 신뢰할 수 없는 입력이 SQL 명령 구조에 포함될 때 발생하는 취약점. 값의 매개변수 바인딩, 구조 요소의 허용 목록, DB 권한 최소화가 핵심 대응
- **메커니즘:** ** 입력의 SQL 문자열 결합 → 구문 해석 위험; 매개변수 바인딩 → 값으로 처리

<details><summary>핵심 용어</summary>

- **매개변수화:** SQL 구조와 입력값을 분리해 바인딩하는 방법.
- **허용 목록:** ** 열명·정렬 방향 등 구조 요소를 서버가 정한 값 중에서만 선택하는 통제.

</details>

## 1교시 예상문제 (10점)

> SQL 삽입의 발생 원리와 기본 방어 방법을 설명하시오. (예상·10점)

---

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 외부 입력이 SQL 구문으로 해석되어 의도하지 않은 질의를 실행시키는 주입 취약점 |
| 목적 | 비인가 데이터 조회·변조와 인증 우회 방지 |

SQL 삽입(SQL Injection)은 외부 입력을 SQL 문자열에 직접 결합해 입력값이 명령문 일부로 해석되는 취약점. 인증 우회, 비인가 조회·변경 등 영향은 쿼리와 DB 권한에 좌우. 값은 준비된 질의의 매개변수로 바인딩하고, 바인딩할 수 없는 테이블·열 이름이나 정렬 방향은 허용 목록으로 선택. 저장 프로시저·ORM도 내부에 동적 문자열 결합이 있으면 취약 가능. 계정 최소 권한과 오류 노출 제한은 피해 완화책.

> SQL 삽입의 공격 유형과 코드·데이터 경계 붕괴를 설명하고 매개변수화·허용 목록·권한 분리 방안을 제시하시오. (예상·25점)

---

## 2~4교시 25점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 외부 입력이 SQL 구문으로 해석되어 의도하지 않은 질의를 실행시키는 주입 취약점 |
| 목적 | 비인가 데이터 조회·변조와 인증 우회 방지 |

### Ⅱ. 원인과 흐름
```text
외부 입력 → 문자열 결합 SQL → DB가 데이터 대신 구문으로 해석
외부 입력 → 매개변수 바인딩 → 데이터 값으로 처리
```
근본 원인은 코드와 데이터의 경계 붕괴. 입력 위치, 질의 종류, 계정 권한에 따라 공격 가능 범위 상이.

### Ⅲ. 주요 유형
| 유형 | 판단 경로 |
|---|---|
| 인밴드 | 오류 또는 질의 결과가 응답에 나타남 |
| 블라인드 | 참·거짓 반응 또는 응답 시간 차이 관찰 |
| 아웃오브밴드 | 환경이 허용하는 별도 통신 경로 이용 |

### Ⅳ. 방어 설계
값 바인딩을 기본값으로 적용. 열명·정렬 방향 같은 SQL 구조는 서버 측 허용 목록으로 매핑. 안전하지 않은 동적 SQL을 저장 프로시저·ORM 내부까지 점검. 앱 계정의 테이블·작업 권한 최소화, 에러 정보·감사 로그 관리. WAF나 특수문자 차단은 보조 통제이며 매개변수화를 대체하지 못함.

### 기술사적 제언

- 입력값은 매개변수로 처리하고 구조 요소는 서버 측 허용 목록으로 선택하며 DB 계정 권한을 제한한다.
