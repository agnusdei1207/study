## 지식 로드맵 내 현재 위치

통신 보안 → TLS → TLS 1.3 핸드셰이크·레코드

## 30초 인출
- TLS 1.3은 핸드셰이크로 상대 인증·키 설정을 수행하고 레코드 계층의 AEAD로 통신 내용을 보호하는 프로토콜. 2026년 RFC 9846이 기존 RFC 8446을 대체

---

<details><summary>핵심 용어</summary>

- 핸드셰이크: 인증·암호 매개변수 협상·공유 키 설정 절차.
- AEAD: 암호화와 데이터 인증을 결합한 방식.

</details>

## 1교시 10점 답안

**공통 개요**

| 구분 | 핵심 |
|---|---|
| 정의 | TLS 1.3은 핸드셰이크로 인증·키 설정을 수행하고 레코드 계층으로 통신을 보호하는 프로토콜 |
| 목적 | 통신 주체 사이의 기밀성·무결성을 갖춘 보안 채널 형성 |
TLS 1.3은 클라이언트·서버 간 보안 채널을 설정하는 프로토콜. 핸드셰이크에서 버전·암호 매개변수 협상, 서버 인증, 공유 비밀 도출을 수행하고 레코드 계층에서 데이터를 인증된 암호로 보호. TLS 1.2에서 허용되던 정적 RSA 키 교환·CBC 같은 레거시 암호군을 제거하고 일반 연결의 핸드셰이크 왕복을 줄임. PSK 전용 재개와 0-RTT는 순방향 비밀성과 재전송 위험을 따로 평가해야 함.

## 2~4교시 25점 답안

**공통 개요**

| 구분 | 핵심 |
|---|---|
| 정의 | TLS 1.3은 핸드셰이크로 인증·키 설정을 수행하고 레코드 계층으로 통신을 보호하는 프로토콜 |
| 목적 | 통신 주체 사이의 기밀성·무결성을 갖춘 보안 채널 형성 |
### Ⅰ. 프로토콜 구조와 핸드셰이크
```text
ClientHello(지원 버전·암호군·key share)
→ ServerHello(선택 매개변수·key share)
→ 암호화된 서버 인증서·서명·Finished
→ 클라이언트 Finished → 애플리케이션 데이터 레코드 보호
```
핸드셰이크는 인증·키 설정, 레코드 계층은 데이터 기밀성·무결성 제공. 기본 ClientHello의 SNI는 별도 ECH가 성공적으로 적용되지 않으면 평문 노출 가능.

### Ⅱ. TLS 1.2와 개선점
| 항목 | TLS 1.2의 위험 설정 | TLS 1.3의 변화 |
|---|---|---|
| 키 설정 | 정적 RSA 키 교환 허용 | 정적 RSA 키 교환 제거, 공개키 기반 키 설정의 순방향 비밀성 |
| 레코드 보호 | CBC 등 레거시 암호군 허용 | AEAD 중심 |
| 핸드셰이크 | 보통 더 많은 왕복 | 일반 연결 1-RTT |

TLS 1.2의 모든 설정이 취약하다는 뜻은 아니며 안전한 설정의 TLS 1.2와 비교해야 함.

### Ⅲ. 운영 고려
0-RTT 조기 데이터는 재전송 가능성 때문에 중복 실행 위험이 있는 작업에 적용하지 않음. 재개 방식, 암호군·버전 정책, 인증서 검증, 중간 장비와 클라이언트 호환성을 함께 점검. RFC 9846은 RFC 8446을 대체한 TLS 1.3 개정 규격.

## 기술사적 제언

0-RTT를 쓰는 서비스는 중복 요청의 업무 영향을 시험하고 PSK 재개 방식의 보안 조건을 따로 확인한다.
