## 연관 키워드

- 랜섬웨어(Ransomware), 서비스 복원력(Service Resilience), 사이버 레질리언스(Cyber Resilience)
- 불변 백업(Immutable Backup), 3-2-1-1-0 백업 원칙, WORM(Write Once Read Many)
- RTO(Recovery Time Objective), RPO(Recovery Point Objective), 단계적 서비스 재개, 단일 장애점(SPOF)

## Ⅰ. 2025년 예스24 랜섬웨어 사고의 개요

- 핵심 요약 : 2025년 6월 대형 온라인 서점의 서버 랜섬웨어 감염으로 주문, 전자책, 티켓 서비스가 장기간 멈춘 사고로, 백업과 복구 순서의 중요성을 보여준 사례.
- 개념 : 2025년 6월 9일 새벽 예스24의 시스템이 **랜섬웨어** (Ransomware)에 감염되어 홈페이지와 앱이 마비되고, 도서 주문, 전자책, 공연 티켓 예매가 중단된 침해사고.
```text
[ 사고 경과 (2025년 6월) ]

6.9 새벽 감염 → 홈페이지·앱 마비
   ↓
6.13 일부 서비스 재개 시작
   ↓
6.16 핵심 서비스 복구 완료 발표
```

- 배경 및 필요성 : 주문과 결제가 집중된 온라인 플랫폼은 가용성 중단이 곧 매출 중단으로 이어지므로, 단일 장애점을 줄이고 **사이버 레질리언스** (Cyber Resilience, 공격 이후에도 핵심 서비스를 복구하는 능력)를 확보할 필요가 드러남.
- 주요 목적 : 침해 대응 과정에서 나타난 복구 지연 요인을 분석하고, 불변 백업과 단계적 재개를 포함한 재해복구 체계의 기준을 정리하는 것.

## Ⅱ. 예스24 사고 대응의 특징 및 장점

- 핵심 요약 : 침해 격리, 불변 백업, 무결성 검증, 우선순위 기반 재개가 서비스 복원 시간을 좌우하는 원칙.

1. 침해 격리 : 감염 시스템을 네트워크에서 즉시 분리해 확산을 막는다 → 추가 피해 범위 축소.
2. 불변 백업 : **WORM** (Write Once Read Many) 방식의 백업을 관리자 권한으로도 지우기 어렵게 보관 → 백업 자체의 삭제 위험 차단.
3. 무결성 검증 : 복구 전 백업본의 해시와 악성 코드 잔존 여부를 확인 → 재감염 위험 감소.
4. 우선순위 재개 : 계정·인증, 결제·주문, 물류 순으로 서비스를 단계적으로 복구 → 핵심 매출 기능을 먼저 회복.

## Ⅲ. 복구 흐름의 구조

- 핵심 요약 : 침해 격리에서 검증된 백업 복원을 거쳐 우선순위에 따라 서비스를 여는 세 단계의 흐름.
- **3-2-1-1-0 백업 원칙** : 사본 3개, 매체 2종, 오프사이트 1곳, 불변 또는 오프라인 1개를 두고, 복구 테스트 오류 0을 목표로 하는 백업 기준.

```text
[ 1. 침해 격리 ]

이상 징후 탐지
   ↓
감염 시스템 네트워크 분리
   ↓
[ 2. 검증된 백업 복원 ]

불변 백업 선택 → 무결성 검사
   ↓
[ 3. 단계적 서비스 재개 ]

계정·인증 → 결제·주문 → 물류
```

- 복원 방식 : 트랜잭션 DB는 특정 시점(PITR, Point-in-Time Recovery)으로 되돌리고, 감염 환경은 클린 환경에서 재구축한 뒤 연결한다.
- 재개 방식 : 접속이 몰리는 시기에는 대기열을 두고 소규모 트래픽부터 열어 장애가 재발하지 않는지 확인한다.

## Ⅳ. 금융 기관 사고와 이커머스 사고의 비교

- 핵심 요약 : 금융 기관은 규제상 복구 목표 시간이 엄격하고, 이커머스는 매출과 고객 경험에 직결된 가용성이 핵심 기준.

| 비교 축 | 금융 기관 침해 | 대형 이커머스 침해 (예스24 사례) |
| --- | --- | --- |
| 핵심 트랜잭션 | 대출 심사, 계좌 이체 | 도서 주문, 결제, 물류 출고, 티켓 예매 |
| 주요 피해 | 금융 거래 정체, 심사 지연 | 매출 중단, 배송 지연, 서비스 이용 불가 |
| 복구 기준 | 감독 규정상 목표 시간 내 복구 | 가능한 한 빠른 재개와 고객 신뢰 회복 |
| 인프라 환경 | 망분리 기반 온프레미스 중심 | 클라우드와 온프레미스 혼합 |
| 데이터 특성 | 개인신용정보, 거래 이력 | 배송지, 결제 관련 정보, 디지털 콘텐츠 권리 정보 |

- 선택 기준 : 서비스 중단이 금전 손실과 규제 위반 중 무엇을 먼저 키우는지에 따라 복구 목표와 투자 우선순위를 정함.

## Ⅴ. 사고의 한계와 방안

- 핵심 요약 : 복구 시간 초과, 백업 자격증명 탈취, 유출 여부 규명 지연, 인증 서버 장애가 복원력의 취약점으로 드러남.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 대용량 DB 복원 지연 | 암호화된 트랜잭션 DB의 대규모 복원이 RTO를 넘김 | 다중 리전 **액티브-액티브** (Active-Active) 구성으로 단일 센터 침해 시 자동 절체 | 실제 복구 소요 시간, RTO 달성률 |
| 백업 관리자 자격증명 탈취 | 공격자가 백업 솔루션 관리 권한으로 스냅샷을 동시 삭제 | 보존 기간 동안 삭제가 불가능한 **Object Lock** (WORM Compliance Mode) 적용, 백업 권한 분리 | 백업 삭제 시도 탐지 건수 |
| 유출 여부 규명 지연 | 개인정보 유출 확인이 늦어져 72시간 통지 기한을 넘길 위험 | 이그레스 구간에 네트워크 DLP를 배치하고 대량 외부 전송 자동 차단과 포렌식 자료 확보 | 통지 소요 시간, 탐지 후 차단 시간 |
| 인증 서버 장애 시 콘텐츠 열람 불가 | 전자책 DRM 라이선스 서버가 중단되면 기존 다운로드 콘텐츠도 열람 불가 | 단말 로컬 캐시에 일정 기간의 오프라인 유예 모드 적용 | 인증 장애 중 열람 성공률 |

## Ⅵ. 랜섬웨어 복원력 강화를 위한 기술사적 제언

- 핵심 요약 : 백업, 복구 자동화, 재개 훈련을 하나의 운영 체계로 묶어 복구를 설계 대상이 아닌 상시 역량으로 관리.

1. 정보보호 조직은 백업 정책을 온프레미스와 클라우드에 걸친 공통 기준으로 정하고, 불변 저장소 적용 범위를 핵심 서비스 전체로 넓히는 것이 바람직하다.
2. 인프라 구성을 코드로 관리하면, 침해 후 환경을 재구축하는 시간이 크게 줄어 복구 목표 달성에 유리하다.
3. 경영진은 핵심 주문과 결제 서비스를 대상으로 정기적인 복구 훈련을 지시하고, 고객 공지 절차를 사고 대응 매뉴얼에 포함시킬 필요가 있다.

## Ⅶ. 결론

- 핵심 요약 : 예스24 사고는 랜섬웨어 자체보다 복구 가능한 백업과 재개 순서가 서비스 복원력을 가른다는 사실을 보여준 사례.
- 시사점 : 공격을 완전히 막을 수 없다는 전제 아래, 검증된 불변 백업과 훈련된 재개 절차를 갖춘 조직이 피해를 줄이고 신뢰를 지킬 수 있다.
