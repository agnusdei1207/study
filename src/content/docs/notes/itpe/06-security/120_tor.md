## 연관 키워드

- Tor(The Onion Router), 어니언 라우팅(Onion Routing), 서킷(Circuit), 가드 노드(Entry Guard)
- 미들 릴레이(Middle Relay), 출구 노드(Exit Node), 히든 서비스(Hidden Service), 랑데부 포인트(Rendezvous Point)
- 트래픽 분석(Traffic Analysis), 트래픽 상관 분석(Traffic Correlation), 플러거블 트랜스포트(Pluggable Transports), 디렉터리 서버(Directory Authority)

## Ⅰ. Tor와 어니언 라우팅의 개요

- 핵심 요약 : 무작위 다중 경유와 계층 암호화로 통신 당사자의 IP 주소와 통신 내용을 함께 숨기는 익명 통신 체계.
- 개념 : 자원봉사 릴레이 네트워크를 통해 트래픽을 계층 암호화하고 무작위 경로로 우회시켜 발신자를 은닉하는 **어니언 라우팅** (Onion Routing, 메시지를 양파 껍질처럼 겹겹이 감싸 전달하는 기법)과 이를 구현한 익명 통신망.
- 배경 및 필요성 : 감시·검열·도청에 맞서 프라이버시를 지키려는 요구가 커졌고, 미국 해군 연구소(NRL, Naval Research Laboratory)의 어니언 라우팅 연구를 바탕으로 발전하여 언론인과 내부고발자 등의 통신 수단으로 쓰여 옴.
- 주요 목적 : 발신지와 목적지를 잇는 **트래픽 분석** (Traffic Analysis)의 상관관계를 끊고, 익명 웹 이용과 검열 우회 환경을 제공하는 것.

## Ⅱ. Tor와 어니언 라우팅의 특징 및 장점

- 핵심 요약 : 계층 암호화와 노드별 역할 분리가 어느 한 노드도 발신자와 목적지를 동시에 알 수 없게 만들어 익명성을 확보하는 구조.

1. 계층 암호화 : 클라이언트가 노드별 키를 협상해 3중 암호화하여 전송 → 노드마다 한 겹씩만 열려 단일 노드의 정보 독점이 차단됨.
2. 3단계 **서킷** (Circuit, 노드를 순서대로 엮은 가상 경로) : 가드·미들·출구의 3홉 구성 → 경로 전체를 추적하려면 여러 노드의 공모가 필요함.
3. 주기적 경로 교체 : 통상 약 10분 주기로 서킷을 폐기하고 재구성 → 장기 관찰을 통한 경로 고정 추적이 어려워짐.
4. **히든 서비스** (Hidden Service, .onion 주소로 접속하는 서버) : 랑데부 포인트를 거쳐 상호 익명 접속 → 서버 위치 은닉과 검열 회피.

## Ⅲ. Tor와 어니언 라우팅의 구조 (흐름)

- 핵심 요약 : 서킷 위에서 노드마다 한 겹씩 복호화되는 계층 전달 구조와, 디렉터리 서버가 노드 정보를 배포하는 보조 구조.
- **가드 노드** (Entry Guard) : 발신자의 실제 IP를 아는 첫 진입 노드.
- **미들 릴레이** (Middle Relay) : 앞뒤 노드만 알고 발신자와 목적지는 모르는 중간 노드.
- **출구 노드** (Exit Node) : 목적지 서버 주소만 알고 발신자는 모르는 마지막 노드.
- **디렉터리 서버** (Directory Authority) : 노드의 상태와 공개키를 합의 문서(Consensus)로 배포하는 기관 서버.

```text
[ Tor 서킷의 계층 암호화 전달 ]

사용자 (Tor 클라이언트)
   ↓ 3중 암호문
가드 노드 (Entry)
   : 1겹 해제, 발신자 IP만 인지
   ↓ 2중 암호문
미들 릴레이 (Middle)
   : 2겹 해제, 앞뒤 노드만 인지
   ↓ 1중 암호문
출구 노드 (Exit)
   : 최종 해제, 목적지만 인지
   ↓ 평문 또는 TLS
최종 목적지 서버
```

```text
[ 서킷 수립과 재구성 ]

디렉터리 서버 (합의 문서 배포)
   ↓
노드 3개 선택 (Entry·Middle·Exit)
   ↓
노드별 키 교환 후 서킷 수립
   ↓
약 10분 후 서킷 폐기 → 재수립
```

## Ⅳ. Tor와 유사 익명 통신 방식의 비교

- 핵심 요약 : Tor는 여러 독립 노드에 신뢰를 나누는 대신 속도를 희생하고, 상용 VPN은 단일 사업자를 신뢰하는 대신 속도를 얻는 구조.

| 비교 축 | Tor | 상용 VPN (Virtual Private Network) | I2P (Invisible Internet Project) |
| --- | --- | --- | --- |
| 네트워크 구조 | 자원봉사 기반 분산 3홉 오버레이 | 상업 사업자의 중앙 서버 단일 홉 터널 | P2P 기반 분산 구조와 갈릭 라우팅 |
| 신뢰 대상 | 단일 노드가 전체 경로를 알 수 없음 | VPN 사업자 자체 | 참여 피어 간 분산 신뢰 |
| 속도 | 다중 홉과 암호화로 느린 편 | 고속 대역폭 보장 | 피어 트래픽에 따라 가변적 |
| 주요 목적 | 웹 이용 시 발신자 익명화 | IP 우회와 공용 Wi-Fi 암호화 | 폐쇄형 내부 서비스 통신 |
| 주요 취약점 | 트래픽 상관 분석, 출구 노드 도청 | 사업자 로그 보관과 제출 요구 | Sybil 공격, 이클립스 공격 |

- 선택 기준 : 익명성이 목적인지, 단순 IP 우회와 속도가 목적인지에 따라 세 방식의 적용 범위가 갈린다.

## Ⅴ. Tor와 어니언 라우팅의 한계와 방안

- 핵심 요약 : 출구 구간 평문 노출, 트래픽 상관 공격, 범죄 악용을 종단 암호화, 타이밍 방어, 노드 평판 관리로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 출구 노드 평문 노출 | 출구에서 목적지까지 HTTP(Hypertext Transfer Protocol) 평문 구간 존재 → 악성 출구 노드가 자격증명과 쿠키를 가로챔 | HTTPS 강제 전환, 엔드-투-엔드 TLS(Transport Layer Security) 사용, .onion 히든 서비스 활용 | 평문 요청 비율 |
| **트래픽 상관 공격** (Traffic Correlation) | 전역 감시 능력을 가진 공격자가 진입·출구 트래픽의 타이밍과 패킷 크기를 대조해 발신자 역추적 | 고정 크기 셀 사용, 더미 트래픽 패딩, 전송 지연 무작위화(Jitter) | 지연 및 패딩 오버헤드 |
| 범죄 악용 | 랜섬웨어 C2(Command and Control) 서버 은닉, 자금 세탁, 불법 거래 은폐로 사법기관의 차단 대상이 됨 | 비정상 출구 노드 평판 DB 운영, 포렌식 협조를 위한 분석 체계 | 악성 출구 노드 차단 건수 |

## Ⅵ. Tor와 어니언 라우팅에 대한 기술사적 제언

- 핵심 요약 : 노드 신뢰도 관리, 검열 우회 기술 유지, 기업 내부 통제를 함께 운영하는 것이 익명 통신의 가치를 살리는 길.
- 가드 노드를 소수로 고정해 운용하면 악의적 노드에 반복 연결될 확률이 줄어드는 만큼, 운영 기관은 신뢰도 높은 가드 노드 목록을 장기적으로 관리하는 데 우선순위를 둬야 한다.
- 검열 방화벽이 Tor 시그니처를 식별하지 못하도록 **플러거블 트랜스포트** (Pluggable Transports, 트래픽을 다른 형태로 위장하는 전송 모듈)를 지속 갱신하는 것이 필요하다.
- 기업은 차세대 방화벽의 애플리케이션 식별로 Tor 접속 패턴과 디렉터리 목록을 차단하되, 연구 목적 접속에 대한 예외 승인 절차를 함께 두어 통제가 과잉되지 않도록 해야 한다.

## Ⅶ. 결론

- 핵심 요약 : Tor는 계층 암호화와 분산 노드로 익명성을 구현한 대표적 익명 통신망으로, 보호 가치와 악용 위험이 함께 존재하는 기술.
- 시사점 : 익명성의 보호 가치와 범죄 악용 위험을 동시에 관리하는 기술적 균형과 정책적 판단이 요구된다.
