## 연관 키워드

- 대칭키 암호, 비대칭키 암호, 하이브리드 암호, 키 배송 문제, 세션키
- AES, RSA, ECC, 디피-헬만 키 교환, 전자서명, 부인 방지
- PKI, 인증서, 양자내성암호(PQC), Shor 알고리즘, Grover 알고리즘

## Ⅰ. 대칭키 vs 비대칭키 암호의 개요

- 핵심 요약 : 대칭키의 연산 속도와 비대칭키의 키 배송·전자서명 능력을 결합한 하이브리드 암호가 현대 보안의 기반.
- 개념 : **대칭키 암호** (Symmetric Key Cryptography)는 암호화와 복호화에 같은 비밀키를 쓰고, **비대칭키 암호** (Asymmetric Key Cryptography)는 공개키와 개인키의 한 쌍을 쓰는 방식이다.
- 배경 및 필요성 : 대칭키는 통신 전에 비밀키를 안전한 경로로 공유해야 하는 **키 배송 문제**를 가지며, 참여자가 늘면 키 개수가 급증한다. 이 한계를 **디피-헬만 키 교환** (Diffie-Hellman)과 **RSA** (Rivest-Shamir-Adleman)가 풀면서 비대칭키 암호가 실용화되었다.
- 주요 목적 : 기밀성, 무결성, 인증, 부인 방지를 함께 충족하는 **하이브리드 암호** (Hybrid Cryptosystem) 체계를 구현하는 것.

## Ⅱ. 대칭키 vs 비대칭키 암호의 특징 및 장점

- 핵심 요약 : 두 방식의 특성이 결합되어 대용량 암호화와 안전한 키 배송을 동시에 얻는 구조.

1. 연산 속도 : **AES** (Advanced Encryption Standard)를 비롯한 대칭키는 하드웨어 가속을 받아 대용량 데이터를 빠르게 처리 → 실시간 통신에 적합.
2. 키 배송 안전성 : 공개키는 공개 채널로 배포해도 개인키 소유자만 복호화할 수 있음 → 사전 비밀 공유 채널이 불필요.
3. 확장성 : n명이 상호 비밀 통신할 때 대칭키는 n(n-1)/2개, 비대칭키는 1인당 1쌍(총 2n개)을 관리 → 대규모 네트워크 운용 가능.
4. 부인 방지 : 개인키로 만든 전자서명은 소유자만 생성할 수 있음 → 법적 증거력 확보.

## Ⅲ. 대칭키 vs 비대칭키 암호의 구조 (흐름)

- 핵심 요약 : 일회용 세션키를 비대칭키로 전달하고 본문은 대칭키로 암호화하는 2단 구조.
- **세션키** (Session Key) : 한 번의 통신마다 새로 만드는 대칭키로, 비대칭 암호로 안전하게 전달된 뒤 본문 암호화에 쓰임.

```text
[ 하이브리드 암호 동작 흐름 ]

송신자: 일회용 세션키 생성
   ↓
세션키를 수신자 공개키로 암호화 (비대칭)
   ↓
데이터를 세션키로 암호화 (대칭)
   ↓
전송: 암호문 + 암호화된 세션키
   ↓
수신자: 개인키로 세션키 복원 (비대칭)
   ↓
세션키로 데이터 복호화 (대칭)
```

```text
[ 참여자 n명의 키 관리 개수 ]

대칭키: 쌍마다 비밀키 → n(n-1)/2개
   ↓ 예: n=100 이면 4,950개
비대칭키: 1인당 공개키·개인키 1쌍 → 2n개
   ↓ 예: n=100 이면 200개
```

## Ⅳ. 대칭키 vs 비대칭키 암호의 비교

- 핵심 요약 : 속도와 키 관리는 대칭키가, 키 배송과 서명은 비대칭키가 우위이며 실제 프로토콜은 둘을 결합.

| 비교 항목 | 대칭키 암호 | 비대칭키 암호 | 하이브리드 암호 |
| --- | --- | --- | --- |
| 키의 종류 | 단일 비밀키 | 공개키 + 개인키 | 세션키(대칭) + 공개키·개인키 |
| 연산 속도 | 매우 빠름 | 대칭키 대비 느림 | 대칭키 속도에 가까움 |
| 키 관리 복잡도 | 참여자 증가 시 급증 | 1인당 1쌍으로 완만 | PKI 연계로 확장성 확보 |
| 키 배송 | 안전한 사전 공유 필요 | 공개 채널로 공개키 배포 가능 | 비대칭으로 세션키 배송 |
| 제공 기능 | 기밀성 | 기밀성, 전자서명, 부인 방지, 키 교환 | 기밀성, 부인 방지, 고속 전송 |
| 대표 알고리즘 | AES, ARIA, SEED, ChaCha20 | RSA, ECC, ECDSA, Ed25519 | TLS, SSH, S/MIME, PGP |

- 선택 기준 : 대용량 데이터 암호화는 대칭키, 신원 확인과 키 교환은 비대칭키에 맡기며, 두 방식은 대체 관계가 아닌 보완 관계로 본다.

## Ⅴ. 대칭키 vs 비대칭키 암호의 한계와 방안

- 핵심 요약 : 양자 위협, 연산 부담, 공개키 신뢰성의 세 한계를 알고리즘 전환, 하드웨어 가속, 인증 체계로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 양자 컴퓨터에 의한 비대칭키 붕괴 | Shor 알고리즘이 RSA·ECC의 수학적 난제를 무력화할 우려 | PQC(Post-Quantum Cryptography) 알고리즘으로 단계적 전환 | PQC 적용 시스템 비율 |
| 비대칭 연산의 CPU·전력 부담 | 큰 정수 연산이 IoT 센서·스마트카드의 배터리와 응답 시간에 부담 | ECC 채택과 하드웨어 암호 엔진 탑재 | 핸드셰이크 지연 시간 |
| 공개키 위조와 중간자 공격 | 공개키만으로는 소유자 신원이 증명되지 않음 | 인증기관 서명 인증서(PKI)와 인증서 투명성 적용 | 인증서 검증 실패율 |

## Ⅵ. 대칭키 vs 비대칭키 암호에 대한 기술사적 제언

- 핵심 요약 : 양자 위협과 키 관리를 함께 보고, 하이브리드 키 교환을 선제 도입하는 전환 전략이 필요.

1. 양자내성 키 교환의 선제 도입 : 기존 ECDH 방식과 PQC 키 캡슐화를 함께 쓰는 하이브리드 키 교환을 먼저 적용하면, 지금 수집된 암호문이 나중에 해독되는 위험을 줄일 수 있다.
2. 대칭키 길이의 상향 : Grover 알고리즘은 대칭키의 유효 강도를 절반으로 낮추므로, 신규 시스템은 AES-256을 기본으로 삼는 것이 합리적이다.
3. 키 관리 체계의 일원화 : 마스터키와 개인키를 소프트웨어에 두지 않고 HSM(Hardware Security Module)에서 생성·배포·파기까지 통합 관리하도록 KMS 정책을 정비한다.

## Ⅶ. 결론

- 핵심 요약 : 대칭키와 비대칭키는 대체재가 아닌 결합재이며, 하이브리드 암호가 현대 보안 프로토콜의 표준 구조다.
- 시사점 : 양자 시대에도 이 결합 구조는 유지되므로, 교체해야 할 대상은 알고리즘이지 구조 자체가 아님을 기억해야 한다.
