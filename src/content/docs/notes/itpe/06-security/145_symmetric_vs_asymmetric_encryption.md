## 지식 로드맵 내 현재 위치

정보보안 → 암호 기법 비교 → 대칭키 vs 비대칭키 암호

## 30초 인출
- **본질:** 대칭키는 공유 비밀키로 데이터를 보호하고 비대칭키는 공개·개인키로 키 설정·서명 등을 지원
- **메커니즘:** 공개키 진위 확인·키 설정 → 세션키 도출 → 대칭키로 데이터 보호
- **통찰:** 한계: 공개키만 게시해도 상대 인증이 된다고 오해하면 키 대체 위험이 있음 → 방안: 공개키 진위를 확인하고 대칭키·비대칭키 역할을 분리

<details><summary>핵심 용어</summary>

- **대칭키:** 암·복호화에 공유 비밀키를 사용하는 방식.
- **비대칭키:** ** 공개키·개인키 쌍의 역할을 분리하는 방식.

</details>

## 2~4교시 25점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 공유 비밀키를 쓰는 대칭키 암호와 공개키·개인키 쌍을 쓰는 비대칭키 암호의 비교 |
| 목적 | 데이터 보호와 키 설정·서명에 적합한 암호 방식의 선택 |

### Ⅱ. 키 설정과 데이터 보호의 하이브리드 구조
```text
대칭키: 공유 비밀키 ─> 대용량 데이터 암·복호
비대칭키: 공개키·개인키 ─> 키 설정·서명
                  │
                  └─ 세션키 도출 후 대칭키 보호
```

### Ⅲ. 대칭·비대칭 방식 비교

| 기준 | 대칭키 | 비대칭키 |
|---|---|---|
| 키 | 공유 비밀키 | 공개키·개인키 쌍 |
| 주요 용도 | 데이터 암호화·메시지 인증 | 키 설정·전자서명·일부 암호화 |
| 처리 특성 | 대용량 처리에 효율적 | 보통 계산 비용이 큼 |
| 관리 과제 | 공유키의 안전한 분배·교체 | 공개키 진위·개인키 보호·폐기 |


| 하이브리드 단계 | 사용 방식 | 검증 조건 |
|---|---|---|
| 상대 확인 | 공개키·인증서 | 키 소유자 진위 |
| 키 설정 | 비대칭 키 합의·캡슐화 | 세션키 도출 조건 |
| 데이터 보호 | 대칭키 AEAD | nonce·태그·키 수명 |
상대 신원과 공개키 검증 → 인증된 키 합의 또는 키 캡슐화 → 세션키 파생 → AEAD 등 대칭키 방식으로 실제 데이터 보호. TLS 1.3의 키 설정을 항상 RSA로 세션키를 직접 암호화하는 방식으로 그리면 부정확.

#### 설계 유의
쌍마다 독립 비밀키를 요구하는 단순 모델에서는 대칭키 쌍의 수가 n(n-1)/2이나, 실제 키 관리 구조가 반드시 이 수를 요구하는 것은 아님. 전자서명의 부인 방지 역시 개인키 통제와 운영·법적 요건을 전제. 알고리즘별 목적과 보안 강도를 구분하고 키 수명·저장·회전을 설계.

### Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 공개키만 게시하면 키 대체와 상대 사칭 위험이 남음 | 공개키 진위·개인키 보호를 확인하고 대칭·비대칭 역할을 분리 |

### Ⅴ. 제언

- 공개키 진위와 개인키 보호를 검증한 후 인증된 키 설정과 대칭키 데이터 보호를 결합한다.
