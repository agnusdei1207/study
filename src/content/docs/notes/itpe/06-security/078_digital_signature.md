## 연관 키워드

- 전자서명(Digital Signature), 개인키, 공개키, 무결성, 부인방지, 서명자 인증
- 인증서, 인증서 경로 검증, CRL(Certificate Revocation List), OCSP(Online Certificate Status Protocol)
- RSA-PSS, ECDSA, EdDSA, ML-DSA, LTV(Long-Term Validation), HSM(Hardware Security Module)

## Ⅰ. 전자서명의 개요

- 핵심 요약 : 개인키로 만든 서명값을 공개키로 검증해 무결성, 서명자 인증, 부인방지를 제공하는 암호 기술.
- 개념 : **개인키**로 메시지의 서명값을 생성하고, 대응하는 **공개키**로 검증하여 **무결성**, 서명자 인증, **부인방지**의 근거를 제공하는 **전자서명** (Digital Signature) 기술.
- 배경 및 필요성 : 전자 문서와 거래가 종이 서명을 대신하면서, 누가 보냈는지와 전송 중 내용이 바뀌지 않았는지를 기계적으로 확인할 수단이 필요해짐.
- 주요 목적 : 메시지의 무결성과 서명자 신원을 검증 가능한 형태로 확보.

## Ⅱ. 전자서명의 특징 및 장점

- 핵심 요약 : 서명은 메시지를 숨기지 않고, 개인키 소유와 인증서 신뢰를 근거로 서명자를 확인하는 구조.

1. 무결성 검증 : 메시지의 해시값이 서명에 묶임 → 한 비트만 바뀌어도 검증이 실패함.
2. 서명자 인증 : 개인키 소유자만 서명을 생성할 수 있고, 인증서가 공개키와 신원을 연결 → 서명자 확인 가능.
3. 부인방지 : 검증이 성공하면 서명자가 서명 사실을 부정하기 어려움 → 법적 증거의 근거가 됨. 다만 키 탈취 여부와 법적 효력은 별도로 판단해야 함.
4. 기밀성 미제공 : 서명은 본문을 암호화하지 않으므로 기밀성이 필요하면 암호화와 결합해야 함.

## Ⅲ. 전자서명의 구조 (흐름)

- 핵심 요약 : 서명 생성과 검증이 공개키 쌍으로 나뉘며, 검증 성공 뒤에는 인증서 신뢰 확인이 추가로 따르는 흐름.

```text
[ 서명 생성 (서명자) ]

메시지 M → 해시 (알고리즘 규칙)
   ↓
해시값을 개인키 SK로 서명 → 서명값 S
```

```text
[ 검증 (검증자) ]

M, S, 공개키 PK 입력
   ↓
서명 검증 → 성공 또는 실패
   ↓
인증서 체인·유효기간·폐기 상태 확인
```

- **해시 함수**와 메시지 인코딩은 알고리즘이 정한 방식으로 적용하며, 사전 해시 모드와 일반 메시지 서명 모드를 구분하고 임의로 이중 해시하지 않도록 구현함.
- **인증서 경로 검증**으로 신뢰 앵커(Trust Anchor)까지 연결을 확인하고, **인증서 폐기목록** (CRL, Certificate Revocation List)과 **온라인 인증서 상태 프로토콜** (OCSP, Online Certificate Status Protocol)을 검증 정책에 따라 적용함.
- 검증 성공은 공개키와 메시지·서명이 일치한다는 뜻일 뿐, 서명 시점의 의사나 법적 효력까지 보증하지는 않음.

## Ⅳ. 대표 서명 알고리즘의 비교

- 핵심 요약 : RSA-PSS는 소인수분해, ECDSA와 EdDSA는 타원곡선, ML-DSA는 모듈 격자 난제에 기반해 키 크기와 양자 대응 수준이 갈림.

| 구분 | RSA-PSS | ECDSA / EdDSA | ML-DSA |
| --- | --- | --- | --- |
| 명칭 | RSA(Rivest-Shamir-Adleman)의 확률적 서명 방식 (PSS, Probabilistic Signature Scheme) | 타원곡선 전자서명 (ECDSA, Elliptic Curve Digital Signature Algorithm), 에드워즈 곡선 서명 (EdDSA, Edwards-curve Digital Signature Algorithm) | 모듈 격자 기반 서명 (ML-DSA, Module-Lattice-Based Digital Signature Algorithm) |
| 기반 난제 | 소인수분해 관련 난제 | 타원곡선 이산대수 난제 | 모듈 격자 관련 난제 |
| 규격 | RFC 8017 | FIPS 186-5, RFC 8032 | FIPS 204 |
| 크기 예시 | 3072비트 RSA의 서명 384바이트 | Ed25519의 공개키 32바이트, 서명 64바이트 | ML-DSA-44의 공개키 1312바이트, 서명 2420바이트 |
| 보안 수준 해석 | 3072비트 RSA는 전통적 보안강도 128비트 수준 | 곡선과 매개변수에 따라 결정 | ML-DSA-44는 NIST 보안 범주 2 (키 비트 수로 단순 비교 불가) |
| 양자 위협 | 충분한 규모의 양자 컴퓨터에서 쇼어 알고리즘에 취약 | 동일한 위협 | 양자 공격에 대한 내성을 목표로 설계 |

- 참고 : ML-DSA는 CRYSTALS-Dilithium을 바탕으로 표준화되었으므로, 최종 표준의 인코딩과 매개변수를 따라야 하며 이전 Dilithium 구현의 키 길이와 혼용하지 않아야 함. 표준 원문은 [NIST FIPS 204](https://csrc.nist.gov/pubs/fips/204/final)와 [RFC 8032](https://www.rfc-editor.org/rfc/rfc8032)에서 확인 가능.
- 선택 기준 : 기존 호환성과 짧은 서명이 중요하면 ECDSA나 EdDSA, 장기 기밀과 검증 수명이 중요하면 ML-DSA 전환을 함께 검토함.

## Ⅴ. 전자서명의 한계와 방안

- 핵심 요약 : 개인키 유출, 장기 검증 정보 소실, 양자 위협을 키 보호, 검증 증거 보존, 단계적 알고리즘 전환으로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 개인키 유출 | 키가 복제되면 공격자가 정당한 서명자를 가장해 서명 생성 가능 | **HSM** (Hardware Security Module)으로 키 추출을 제한하고, 접근 통제와 키 폐기·교체 절차를 결합 | 키 폐기 처리 시간 |
| 장기 검증 정보 소실 | 시간이 지나 인증서와 폐기 정보가 사라지면 오래된 서명을 검증할 수 없음 | 시점확인 토큰과 당시의 인증서·폐기 정보를 보존하는 **장기 검증성** (LTV, Long-Term Validation) 형식 적용 | 증거 갱신 주기 준수율 |
| 양자 위협과 전환 비용 | 쇼어 알고리즘으로 RSA와 ECC가 깨질 수 있어 알고리즘 교체가 필요함 | 알고리즘, 키, 인증서의 의존성을 조사한 뒤 ML-DSA 등으로 단계적 전환, 하이브리드 서명은 대상 프로토콜의 지원 여부 확인 후 도입 | 전환 완료율 |

- 키 격리만으로는 운영자 권한 남용까지 막을 수 없으므로, 키 사용 기록의 감사를 함께 두어야 함.

## Ⅵ. 전자서명에 대한 기술사적 제언

- 핵심 요약 : 전자서명의 실효성은 서명 기술보다 검증 정책과 장기 보존 체계에서 판가름 나므로, 두 요소를 제도로 정하는 것이 핵심.

1. 검증 정책 : 전자서명을 도입하는 기관은 전자서명법 등 관련 법령과 인증 체계를 근거로, 서명 연산 성공과 인증서 신뢰 확인, 법적 증거력을 구분하는 검증 정책을 문서로 정하고 내부 감사에 포함함.
2. 기록 보존 : 기록 관리 부서가 원문과 검증 증거를 함께 보관하는 규정을 두고, 보존 기간을 가정한 재검증 훈련을 정기적으로 수행함. 장기 보존 형식을 써도 법적 효력이 영구히 보장된다고 단정하지 않음.
3. 전환 거버넌스 : 암호 정책 기관이 서명 알고리즘 전환 로드맵을 정하고, 기관별로 HSM과 인증서 체계가 교체 가능한 구조인지 점검하도록 함.

## Ⅶ. 결론

- 핵심 요약 : 전자서명은 개인키와 공개키 쌍으로 무결성과 서명자 인증을 제공하는 기술이며 기밀성은 제공하지 않음.
- 시사점 : 검증 성공이 곧 키의 안전이나 법적 효력을 뜻하지 않으므로, 키 관리, 인증서 신뢰, 장기 보존을 함께 설계해야 전자서명이 완결됨.
