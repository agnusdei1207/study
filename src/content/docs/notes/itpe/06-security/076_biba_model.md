## 지식 로드맵 내 현재 위치

정보보안 → 접근 통제 → 강제적 접근통제(MAC) 및 무결성 모델(Biba)

## 30초 인출

- **본질:** 벨-라파듈라(BLP) 모델의 기밀성 편향을 극복하고, 무결성 등급(Integrity Level)을 기반으로 저신뢰 데이터가 고신뢰 시스템을 오염시키는 것을 방지하는 무결성(Integrity) 전용 접근통제 모델
- **메커니즘:** 단순 무결성 속성(No Read Down: 상위 주체 하위 읽기 금지) + 스타 무결성 속성(No Write Up: 하위 주체 상위 쓰기 금지) + 호출 속성(하위 주체 상위 호출 금지)
- 통찰: 무결성 오염 차단이라는 엄격한 원칙에도 불구하고 외부 데이터 수용 불가로 인한 업무 경직성을 해결하기 위해 검증(Sanitization) 게이트웨이 및 클락-윌슨(Clark-Wilson) 모델과의 결합 필수

<details><summary>핵심 용어</summary>

- **비바 모델 (Biba Model):** Kenneth J. Biba가 1977년 제안한 다중 무결성 수준(Multilevel Integrity)을 보장하는 형식적 수학 모델.
- **단순 무결성 속성 (Simple Integrity Property):** No Read Down (NRD). 주체는 자신보다 낮은 무결성 수준의 객체를 읽을 수 없음(오염 방지).
- **스타(*) 무결성 속성 (*-Integrity Property):** No Write Up (NWU). 주체는 자신보다 높은 무결성 수준의 객체에 데이터를 쓸 수 없음(변조 방지).
- **호출 속성 (Invocation Property):** 낮은 무결성 수준의 주체는 높은 무결성 수준의 주체나 서비스를 호출할 수 없음.
- **무결성 등급 (Integrity Level):** 데이터의 신뢰도와 변경 가능성을 정의한 계층적 보안 레이블.

</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 정보 시스템에서 데이터와 프로그램의 무결성(Integrity)을 유지하기 위해 무결성 등급을 기반으로 주체의 읽기, 쓰기, 실행 권한을 강제 통제하는 수학적 상태 전이 모델 |
| 목적 | 저신뢰 외부 데이터나 비인가된 악성 주체에 의해 핵심 시스템 데이터 및 실행 코드가 불법 변조·오염되는 사고의 원천 차단 |

## Ⅱ. 비바 모델의 주요 특징 및 3대 접근통제 속성

| 속성 명칭 | 규칙 및 핵심 원리 | 상세 설명 | 방어 목적 |
|---|---|---|---|
| 단순 무결성 속성 (Simple Integrity) | **No Read Down (NRD)** | 주체는 자신보다 낮은 무결성 등급의 객체를 절대 읽을 수 없음 | 오염된 저신뢰 데이터 유입 방지 |
| 스타(*) 무결성 속성 (*-Integrity) | **No Write Up (NWU)** | 주체는 자신보다 높은 무결성 등급의 객체에 절대 쓸 수 없음 | 하위 권한 주체의 핵심 데이터 변조 차단 |
| 호출 속성 (Invocation Property) | **No Call Up (NCU)** | 주체는 자신보다 높은 무결성 등급을 가진 주체나 프로세스를 호출할 수 없음 | 비인가된 프로세스 권한 오남용 차단 |

- **무결성 지배 관계:** 정보의 신뢰도 수준을 유지하기 위해 데이터는 오직 '상위 등급에서 하위 등급으로만(Clean to Dirty)' 흐르도록 통제.

## Ⅲ. 비바 모델의 무결성 흐름 및 접근 제어 체계

```text
[ 높은 무결성 등급 (High Integrity) ]
          │                    ▲
   쓰기   │ (Write Down 가능)  │ 읽기 (Read Up 가능)
   허용   ▼                    │ 허용
[ 낮은 무결성 등급 (Low Integrity) ]

─────────────────────────────────────────────────────────────
[ 접근 통제 규칙 판정 매트릭스 ]
           ┌───────────────────────────────┐
           │      객체 (Object Level)      │
           ├───────────────┬───────────────┤
           │  높음 (High)  │  낮음 (Low)   │
┌────┬─────┼───────────────┼───────────────┤
│    │ High│ 읽기/쓰기 가능│ 쓰기만 가능   │
│주체│     │               │ (NRD:읽기금지)│
│    ├─────┼───────────────┼───────────────┤
│(S) │ Low │ 읽기만 가능   │ 읽기/쓰기 가능│
│    │     │ (NWU:쓰기금지)│               │
└────┴─────┴───────────────┴───────────────┘
```

| 접근 요청 유형 | 객체 > 주체 | 객체 = 주체 | 객체 < 주체 |
|---|---|---|---|
| 읽기 (Read) | **허용 (Read Up)** | 허용 | **거부 (No Read Down)** |
| 쓰기 (Write) | **거부 (No Write Up)** | 허용 | **허용 (Write Down)** |
| 호출 (Invocation) | **거부 (No Call Up)** | 허용 | 허용 |

## Ⅳ. 비바(Biba) vs 벨-라파듈라(BLP) vs 클락-윌슨(Clark-Wilson) 비교

| 구분 | 비바 모델 (Biba) | 벨-라파듈라 모델 (BLP) | 클락-윌슨 모델 (Clark-Wilson) |
|---|---|---|---|
| 최우선 보안 목표 | **무결성 보장 (Integrity)** | **기밀성 보장 (Confidentiality)** | **상업적 무결성 및 직무 분리** |
| 읽기 통제 원칙 | **No Read Down (NRD)** | **No Read Up (NRU)** | 변환 절차(TP) 통한 무결성 읽기 |
| 쓰기 통제 원칙 | **No Write Up (NWU)** | **No Write Down (NWD)** | 비인가 변환 차단 (CDI 보호) |
| 데이터 흐름 방향 | 높은 무결성 $\rightarrow$ 낮은 무결성 | 낮은 기밀성 $\rightarrow$ 높은 기밀성 | 정형화된 트랜잭션 루프 |
| 대표적 결함 | 기밀성 유출 방어 불가 (Write Down 허용) | 무결성 파괴 (Write Up 허용) | 구현 난이도 및 성능 오버헤드 |
| 주요 적용처 | 윈도우 무결성 메커니즘(MIC), 금융 | 군사, 국방, 안보 다중 등급 체계 | ERP, 뱅킹 시스템, 감사 추적 |

## Ⅴ. 비바 모델의 한계와 방안

| 한계 | 방안 |
|---|---|
| No Read Down(하향 읽기 금지) 규칙으로 인해 높은 무결성을 가진 관리자나 백신 프로그램이 외부 인터넷의 저신뢰 데이터를 읽어 분석할 수 없는 업무 마비 발생 | 신뢰된 검증자(Sanitizer)를 두고 외부 데이터를 정제·검증한 후 무결성 레이블을 상향 조정하는 데이터 정제 및 승격(Sanitization) 게이트웨이 구축 |
| 무결성만 엄격히 통제하고 기밀성을 전혀 다루지 않으므로 상위 주체가 하위 객체에 데이터를 기록하는 하향 쓰기(Write Down) 시 기밀 정보 유출 발생 | 기밀성을 보장하는 BLP 모델과 무결성을 보장하는 Biba 모델을 직교 결합하는 이중 격자(Dual Lattice) 강제 접근통제 아키텍처 수립 |
| 기업 환경에서 필수적인 회계 원장의 직무 분리(SoD) 및 이중 결재(Dual Control) 같은 상업적 비즈니스 트랜잭션 무결성 요구 충족 불가 | 상태 전이 모델 대신 인증된 변환 절차(TP)와 무결성 검증 절차(IVP)를 강제하는 클락-윌슨(Clark-Wilson) 모델로 전환 |

## Ⅵ. 제언

```text
[ 단일 비바 모델의 경직성 ]           [ 현대적 복합 무결성 거버넌스 ]
하향 읽기 차단으로 분석 마비 ─┐       ┌── 정제(Sanitization) 파이프라인 도입
기밀성 유출 무방비 노출 ───┼─→ [ 업무 단절 ] ┼── 듀얼 격자(Biba 무결성 + BLP 기밀성)
단순 등급 통제 한계 ───────┘       └── 윈도우 MIC(Mandatory Integrity Control) 연계
```

| 평가 영역 | 전통적 Biba 모델 | Biba + BLP 복합 모델 | 클락-윌슨 모델 |
|---|---|---|---|
| 무결성 강도 | 수학적 완벽 보증 | 무결성 + 기밀성 동시 보증 | 비즈니스 트랜잭션 무결성 |
| 현실 적용성 | 매우 낮음 (업무 마비) | 군사/공공 일부 적용 | 상업용 금융/엔터프라이즈 최적 |
| OS 구현체 | 이론적 모델 위주 | 윈도우 비스타 이후 MIC 적용 | 데이터베이스 트랜잭션 ACID |

비바 모델은 정보 시스템의 변조와 오염을 수학적으로 방지하는 강제적 무결성 통제의 기초 모델이며, 현대 운영체제의 필수 무결성 제어(Windows MIC)와 클락-윌슨 모델의 상업적 무결성 원리로 계승 발전 필수.
