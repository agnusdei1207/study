## Ⅰ. 비바 모델(Biba Model)의 개요

- **개념** : 정보 시스템에서 데이터와 프로그램의 무결성(Integrity)을 유지하기 위해 무결성 등급을 기반으로 주체의 읽기, 쓰기, 실행 권한을 강제 통제하는 수학적 상태 전이 모델.
- **배경 및 필요성** : 군사적 기밀성에 치중된 BLP 모델의 상향 쓰기(Write Up)에 따른 고의적 데이터 변조 및 오염 문제를 방지하고, 상업 시스템과 금융 환경에서 요구되는 데이터의 정확성과 무결성을 보장하기 위해 제안됨.
- **핵심 목적** : 저신뢰 외부 데이터나 비인가된 악성 주체에 의해 핵심 시스템 데이터 및 실행 코드가 불법 변조·오염되는 사고의 원천 차단.

## Ⅱ. 비바 모델(Biba Model)의 핵심 아키텍처 및 동작 메커니즘

비바 모델(Biba Model)은(는) 신뢰할 수 있는 보안 구조와 표준화된 절차를 기반으로 동작하며, 세부적인 아키텍처와 구성요소 간의 상호작용 메커니즘은 다음과 같음.

```text
[ 높은 무결성 등급 (High Integrity) ]
          │                    ▲
   쓰기   │ (Write Down 가능)  │ 읽기 (Read Up 가능)
   허용   ▼                    │ 허용
[ 낮은 무결성 등급 (Low Integrity) ]

─────────────────────────────────────────────────────────────
[ 접근 통제 규칙 판정 매트릭스 ]
           ┌───────────────────────────────┐
           │      객체 (Object Level)      │
           ├───────────────┬───────────────┤
           │  높음 (High)  │  낮음 (Low)   │
┌────┬─────┼───────────────┼───────────────┤
│    │ High│ 읽기/쓰기 가능│ 쓰기만 가능   │
│주체│     │               │ (NRD:읽기금지)│
│    ├─────┼───────────────┼───────────────┤
│(S) │ Low │ 읽기만 가능   │ 읽기/쓰기 가능│
│    │     │ (NWU:쓰기금지)│               │
└────┴─────┴───────────────┴───────────────┘
```

- **읽기 (Read)** : 상위 무결성 객체는 **허용 (Read Up)**, 하위 무결성 객체는 **거부 (No Read Down)**.
- **쓰기 (Write)** : 하위 무결성 객체는 **허용 (Write Down)**, 상위 무결성 객체는 **거부 (No Write Up)**.
- **호출 (Invocation)** : 상위 무결성 주체의 호출은 **거부 (No Call Up)**.

## Ⅲ. 비바 모델(Biba Model)의 세부 구성 요소 및 비교 분석

| 구분 | 비바 모델 (Biba) | 벨-라파듈라 모델 (BLP) | 클락-윌슨 모델 (Clark-Wilson) |
|---|---|---|---|
| 최우선 보안 목표 | **무결성 보장 (Integrity)** | **기밀성 보장 (Confidentiality)** | **상업적 무결성 및 직무 분리** |
| 읽기 통제 원칙 | **No Read Down (NRD)** | **No Read Up (NRU)** | 변환 절차(TP) 통한 무결성 읽기 |
| 쓰기 통제 원칙 | **No Write Up (NWU)** | **No Write Down (NWD)** | 비인가 변환 차단 (CDI 보호) |
| 데이터 흐름 방향 | 높은 무결성 $\rightarrow$ 낮은 무결성 | 낮은 기밀성 $\rightarrow$ 높은 기밀성 | 정형화된 트랜잭션 루프 |
| 대표적 결함 | 기밀성 유출 방어 불가 (Write Down 허용) | 무결성 파괴 (Write Up 허용) | 구현 난이도 및 성능 오버헤드 |
| 주요 적용처 | 윈도우 무결성 메커니즘(MIC), 금융 | 군사, 국방, 안보 다중 등급 체계 | ERP, 뱅킹 시스템, 감사 추적 |

- 비바 모델(Biba Model)은(는) 상기 핵심 비교 지표와 아키텍처 구성을 바탕으로 보안 위협에 대한 방어 효과성을 극대화하며, 기존 레거시 통제 기법 대비 우수한 신뢰성과 운영 효율성을 제공함.

## Ⅳ. 비바 모델(Biba Model)의 주요 한계점 및 해결 방안

- **한계점** : No Read Down(하향 읽기 금지) 규칙으로 인해 높은 무결성을 가진 관리자나 백신 프로그램이 외부 인터넷의 저신뢰 데이터를 읽어 분석할 수 없는 업무 마비 발생.
  - **해결 방안** : 신뢰된 검증자(Sanitizer)를 두고 외부 데이터를 정제·검증한 후 무결성 레이블을 상향 조정하는 데이터 정제 및 승격(Sanitization) 게이트웨이 구축.
- **한계점** : 무결성만 엄격히 통제하고 기밀성을 전혀 다루지 않으므로 상위 주체가 하위 객체에 데이터를 기록하는 하향 쓰기(Write Down) 시 기밀 정보 유출 발생.
  - **해결 방안** : 기밀성을 보장하는 BLP 모델과 무결성을 보장하는 Biba 모델을 직교 결합하는 이중 격자(Dual Lattice) 강제 접근통제 아키텍처 수립.
- **한계점** : 기업 환경에서 필수적인 회계 원장의 직무 분리(SoD) 및 이중 결재(Dual Control) 같은 상업적 비즈니스 트랜잭션 무결성 요구 충족 불가.
  - **해결 방안** : 상태 전이 모델 대신 인증된 변환 절차(TP)와 무결성 검증 절차(IVP)를 강제하는 클락-윌슨(Clark-Wilson) 모델로 전환.

## Ⅴ. 비바 모델(Biba Model) 적용 및 발전을 위한 기술사적 제언

- **정제(Sanitization) 파이프라인 체계 도입** : 정제(Sanitization) 파이프라인 기술을 적극 적용하여 보안 취약점을 차단하고 시스템 신뢰성을 보장해야 함.
- **듀얼 격자(Biba 무결성 + BLP 기밀성) 체계 도입** : 듀얼 격자(Biba 무결성 + BLP 기밀성) 기술을 적극 적용하여 보안 취약점을 차단하고 시스템 신뢰성을 보장해야 함.
- **윈도우 MIC(Mandatory Integrity Control) 연계 체계 도입** : 윈도우 MIC(Mandatory Integrity Control) 연계 기술을 적극 적용하여 보안 취약점을 차단하고 시스템 신뢰성을 보장해야 함.
