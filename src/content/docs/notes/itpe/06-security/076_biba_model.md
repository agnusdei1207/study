## 연관 키워드

- 비바 모델(Biba Model), 무결성 등급(Integrity Level), 무결성 보장(Integrity)
- 단순 무결성 속성(Simple Integrity Property), No Read Down, No Write Up, No Call Up
- 벨라파듈라 모델(BLP, Bell-LaPadula), 클락-윌슨 모델(Clark-Wilson), 정제(Sanitization), Low-Water-Mark 정책
- Windows MIC(Mandatory Integrity Control), 직무 분리(SoD, Separation of Duties)

## Ⅰ. 비바 모델의 개요

- 핵심 요약 : 무결성 등급에 따라 주체의 읽기와 쓰기를 강제 통제해 데이터와 실행 코드의 변조를 막는 무결성 모델.
- 개념 : 데이터와 프로그램의 무결성을 지키기 위해, 주체와 객체에 부여한 무결성 등급을 기준으로 읽기·쓰기·호출을 제한하는 **비바 모델** (Biba Model).
- 배경 및 필요성 : 기밀성 중심의 벨라파듈라 모델(BLP, Bell-LaPadula)은 하위 등급이 상위 객체에 쓰는 것을 허용해 고등급 데이터가 오염될 수 있으므로, 상업·금융 환경에서 요구되는 데이터 정확성을 보장할 모델이 필요해짐.
- 주요 목적 : 저신뢰 외부 데이터나 비인가 주체에 의해 핵심 데이터와 실행 코드가 변조되는 경로를 원천 차단.

## Ⅱ. 비바 모델의 특징 및 장점

- 핵심 요약 : 무결성 등급 기반의 세 가지 규칙이 핵심 데이터의 오염 경로를 막아 무결성을 형식적으로 강제하는 구조.

1. **단순 무결성 속성** (Simple Integrity Property, **No Read Down**) : 주체는 자신보다 낮은 무결성 객체를 읽을 수 없음 → 저신뢰 데이터가 핵심 판단에 섞이는 것 차단.
2. **무결성 쓰기 규칙** (\*-Integrity Property, **No Write Up**) : 주체는 자신보다 높은 무결성 객체에 쓸 수 없음 → 핵심 데이터로 가는 변조 경로 차단.
3. **호출 규칙** (**No Call Up**) : 낮은 등급 주체가 높은 등급 주체의 프로그램을 호출할 수 없음 → 권한 상승 경로 차단.

## Ⅲ. 비바 모델의 구조 (흐름)

- 핵심 요약 : 읽기는 무결성이 높은 쪽으로, 쓰기는 무결성이 낮은 쪽으로만 허용되는 방향성 있는 판정 흐름.

```text
[ 읽기 요청 판정 ]

읽기 요청 (Read)
   ↓
객체 무결성 ≥ 주체 무결성 ?
   ↓ 예 : 허용 (Read Up)
   ↓ 아니오 : 거부 (No Read Down)
```

```text
[ 쓰기 요청 판정 ]

쓰기 요청 (Write)
   ↓
객체 무결성 ≤ 주체 무결성 ?
   ↓ 예 : 허용 (Write Down)
   ↓ 아니오 : 거부 (No Write Up)
```

```text
[ 외부 데이터 승격 흐름 ]

외부 저신뢰 데이터 (Low)
   ↓
정제·검증 (Sanitization)
   ↓
검증 통과 시 무결성 등급 상향 (High)
```

## Ⅳ. 비바 모델과 유사 모델의 비교

- 핵심 요약 : 비바 모델은 무결성, 벨라파듈라 모델은 기밀성, 클락-윌슨 모델은 업무 절차 기반 무결성을 목표로 해 적용 영역이 다름.

| 구분 | 비바 모델 (Biba) | 벨라파듈라 모델 (BLP) | 클락-윌슨 모델 (Clark-Wilson) |
| --- | --- | --- | --- |
| 최우선 목표 | 무결성 보장 | 기밀성 보장 | 상업적 무결성과 직무 분리 |
| 읽기 원칙 | 낮은 무결성 객체 읽기 금지 | 높은 등급 객체 읽기 금지 | 인증된 변환 절차를 거친 접근 |
| 쓰기 원칙 | 높은 무결성 객체 쓰기 금지 | 낮은 등급 객체 쓰기 금지 | 검증되지 않은 변경 차단 |
| 정보 흐름 방향 | 높은 무결성에서 낮은 무결성으로 흐름 | 낮은 등급에서 높은 등급으로 흐름 | 정해진 트랜잭션 순서를 따름 |
| 대표 결함 | 기밀성 유출 방어 불가 | 무결성 훼손 가능 | 구현 난이도와 운영 부담 |
| 주요 적용처 | Windows MIC(Mandatory Integrity Control), 금융 | 군사, 국방, 다중 등급 체계 | ERP, 뱅킹, 감사 추적 |

- 선택 기준 : 데이터 오염 방지가 핵심이면 비바 모델, 기밀 유출 방지가 핵심이면 벨라파듈라 모델, 업무 절차와 직무 분리가 핵심이면 클락-윌슨 모델을 기준으로 삼음.

## Ⅴ. 비바 모델의 한계와 방안

- 핵심 요약 : 하향 읽기 금지로 생기는 업무 경직, 기밀성 공백, 상업 트랜잭션 요구를 정제, 결합 적용, 절차 모델로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 업무 경직 | 높은 무결성 주체가 외부의 저신뢰 데이터를 읽지 못해 분석과 점검이 막힘 | 검증 후 등급을 올리는 **정제** (Sanitization) 게이트웨이 운영, **Low-Water-Mark** 정책 적용 | 정제 통과율, 정제 처리 지연 |
| 기밀성 공백 | 하향 쓰기가 허용되어 상위 기밀 정보가 낮은 등급으로 기록될 수 있음 | 벨라파듈라 모델의 기밀성 규칙을 함께 적용하는 결합 구조 설계 | 기밀 등급 위반 탐지 건수 |
| 상업 트랜잭션 요구 미충족 | 직무 분리와 이중 승인 같은 업무 통제를 표현할 수 없음 | 인증된 변환 절차와 **무결성 검증 절차** (IVP, Integrity Verification Procedure)를 강제하는 클락-윌슨 모델 도입 | 검증 절차 위반 건수 |

## Ⅵ. 비바 모델에 대한 기술사적 제언

- 핵심 요약 : 무결성 모델은 데이터 등급 거버넌스와 운영체제 기능이 함께 갖춰질 때 실효성을 가짐.

1. 금융과 공공 원장을 운영하는 조직은 데이터 무결성 등급 분류 기준을 문서화하고, 외부 데이터가 내부 등급으로 승격되는 조건을 정책으로 정함.
2. 정보보호 조직은 운영체제의 무결성 수준 기능을 기본 보호 설정으로 두고, 예외 설정은 승인 절차를 거치도록 관리 체계를 세움.
3. 개발 조직은 외부 입력을 다루는 모듈의 설계 검토 항목에 데이터 출처 확인을 포함해, 검증되지 않은 데이터가 핵심 경로에 들어오지 않도록 함.

## Ⅶ. 결론

- 핵심 요약 : 비바 모델은 상향 쓰기와 하향 읽기를 규칙으로 막아 무결성을 형식적으로 보장한 모델.
- 시사점 : 무결성과 기밀성은 서로 다른 보호 목표이므로, 비바 모델만으로는 기밀성을 보장할 수 없어 목표에 맞는 모델을 조합해 설계해야 함.
