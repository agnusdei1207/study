## Ⅰ. ISMS-P(정보보호 및 개인정보보호 관리체계)의 개요

- 개념 : 조직이 수립·운영하는 **정보보호 관리체계** (ISMS, Information Security Management System)와 **개인정보보호 관리체계** (PIMS, Personal Information Management System)를 유기적으로 통합하여, 과학기술정보통신부와 개인정보보호위원회가 공동 고시한 3대 영역 인증기준에 적합한지 종합 심사하는 국가 공인 인증제도.
- 배경 및 필요성 : 기존의 분리 운영되던 ISMS(망법)와 PIMS(개보법)로 인한 기업의 중복 인증 비용 및 심사 부담을 해소하고, 데이터 경제 시대에 정보자산 보안과 개인정보 생명주기 통제를 일체화할 필요성 대두.
- 핵심 목적 : 정보보호 및 개인정보보호 관리 수준 제고, 개인정보 유출 사고 사전 예방, 법적 컴플라이언스(개보법 제32조의2) 통합 달성 및 고객 신뢰성 확보.

## Ⅱ. ISMS-P(정보보호 및 개인정보보호 관리체계)의 핵심 아키텍처 및 동작 메커니즘

ISMS-P는 관리체계 수립 및 운영(16개), 보호대책 요구사항(64개), 개인정보 처리단계별 요구사항의 인증기준을 기반으로 정보보호와 개인정보보호 전주기를 통제함.

```text
[ ISMS-P 3대 인증 영역 인증기준 구조 ]

  +-------------------------------------------------------------+
  | 1. 관리체계 수립 및 운영 (16개 기준)                         |
  |  - 1.1 관리체계 기반 마련 (최고책임자 지정, 범위 설정)      |
  |  - 1.2 위험 관리 (자산 식별, 위협/취약점 분석, DoA 수립)     |
  |  - 1.3 관리체계 운영 / 1.4 관리체계 점검 및 개선 (내부감사) |
  +------------------------------┬------------------------------+
                                 │
         ┌───────────────────────┴───────────────────────┐
         ▼                                               ▼
  +-------------------------------+ +-------------------------------+
  | 2. 보호대책 요구사항 (64개)   | | 3. 개인정보 처리단계별 |
  |  - 정책, 조직, 직무 보안      | |  - 3.1 수집 시 보호조치       |
  |  - 외부자 및 인적 보안        | |  - 3.2 보유 및 이용 시 보호   |
  |  - 자산 관리 및 보안 시스템   | |  - 3.3 제공 시 보호조치       |
  |  - 물리 보안 및 접근 통제     | |  - 3.4 파기 시 보호조치       |
  |  - 암호화 및 운영/개발 보안   | |  - 3.5 정보주체 권리 보장     |
  |  - 침해사고 대응 및 복구      | |    (열람, 정정, 삭제, 전송)   |
  +-------------------------------+ +-------------------------------+
```

- **관리체계 수립·운영** (16개) : CISO(Chief Information Security Officer)/CPO(Chief Privacy Officer)의 공동 거버넌스 확립, **개인정보 흐름표** (Data Flow) 작성, DoA 기준 위험 평가 및 이행 계획 수립.
- **보호대책 요구사항** (64개) : 기술적·물리적·관리적 보안 대책을 정보시스템 전반에 적용(접근권한 관리, 암호화, 네트워크 분리, 취약점 점검).
- **개인정보 처리단계별 요구사항** : 수집-보유-이용-제공-파기 전주기에서 **최소 수집 원칙** 준수, 동의 획득, 목적 외 이용 제한, 안전한 파기 검증.
- **정보주체 권리 보장** : 열람·정정·삭제·처리정지 요구권 처리 절차 구축 및 마이데이터(개인정보 전송요구권) 대응 체계 수립.

## Ⅲ. ISMS-P(정보보호 및 개인정보보호 관리체계)의 세부 구성 요소 및 비교 분석

| 비교 항목 | ISMS (정보보호 관리체계) | ISMS-P (통합 관리체계) | ISO(International Organization for Standardization)/IEC(International Electrotechnical Commission) 27701 (개인정보 국제 표준) |
| --- | --- | --- | --- |
| 인증 기준 수 | 총 80개 기준 | ISMS 인증기준 + 개인정보 처리단계별 인증기준 | ISO 27001 확장 (통제항목 31개 추가) |
| 핵심 목적 | 기업 정보자산(IT(Information Technology) 인프라) 기밀/완전/가용성 | 정보자산 보호 + 개인정보 자기결정권 보장 | 글로벌 프라이버시(GDPR, General Data Protection Regulation) 대응 및 신뢰 입증 |
| 주관 부처 | 과학기술정보통신부 | 개인정보보호위원회 / 과기정통부 공동 | ISO / IEC 국제표준화기구 |
| 의무 대상 | 매출액/이용자수 충족 ISP(Internet Service Provider), IDC(Internet Data Center), 병원 등 | 대규모 개인정보(100만 명 이상 등) 보유 기업 | 국제 진출 기업 (자율 인증) |
| 인증의 효력 | 국내 망법 상 법적 의무 이행 | 망법 및 개보법 동시 충족, 과징금 감경 | 글로벌 비즈니스 및 GDPR 컴플라이언스 증명 |

- ISMS-P는 국내 최고 권위의 통합 인증 제도로서 인증 획득 시 정보통신망법상 ISMS 의무를 갈음하며, 대규모 개인정보 유출 사고 시 과징금 산정의 중요한 감경 사유로 참작됨.

## Ⅳ. ISMS-P(정보보호 및 개인정보보호 관리체계)의 주요 한계점 및 해결 방안

- 클라우드 SaaS 및 국외 이전 환경에서의 개인정보 국외 제3자 제공 통제 사각지대 :
  - 한계점 : 클라우드 네이티브 서비스 도입 시 해외 리전으로 데이터가 자동 복제되거나 국외 SaaS(Salesforce 등) 연동 시 국외 이전 법정 동의 누락 위험.
  - 해결 방안 : 클라우드 서비스 제공자(CSP, Cloud Service Provider)와의 계약서 내 **표준계약조항** (SCC) 체결, **데이터 상주성** (Data Residency) 통제 및 DSPM 연계 국외 이전 흐름 자동 감사.
- 가명정보 결합 및 AI(Artificial Intelligence) 학습 데이터 활용 시 재식별 위험 평가의 심사 기준 모호성 :
  - 한계점 : LLM(Large Language Model) 학습 및 빅데이터 분석을 위해 결합된 가명정보의 적정성 평가가 정량화되지 않아 심사 결함 판정 및 라이프사이클 통제 혼선 초래.
  - 해결 방안 : 개인정보 비식별 조치 가이드라인 기반 k-익명성, l-다양성 측정 자동화 도구를 구축하고, **AI 데이터 안심구역** 내 폐쇄형 분석 환경 운영 증적 제출.
- CISO와 CPO의 분리 지정에 따른 조직 간 R&R 충돌 및 거버넌스 분절 :
  - 한계점 : 정보보호최고책임자(CISO)와 개인정보보호책임자(CPO)의 우선순위(보안 인프라 vs 서비스 편의 및 동의 관리) 불일치로 관리체계 운영 비효율 발생.
  - 해결 방안 : 전사 정보보호·개인정보보호 통합위원회를 정례화하고, **CISO-CPO 공동 승인 체계** (Dual Authorization)와 통합 위험관리 워크플로우 확립.

## Ⅴ. ISMS-P(정보보호 및 개인정보보호 관리체계) 적용 및 발전을 위한 기술사적 제언

- **Privacy-by-Design** (설계 단계 프라이버시 보호) 엔지니어링 내재화 : 서비스 기획 단계부터 개인정보 흐름을 모델링하고, CI(Continuous Integration)/CD(Continuous Delivery) 파이프라인에서 암호화 및 보관기간 설정을 자동 검증해야 함.
- **개인정보 전송요구권** (마이데이터) 대응 API(Application Programming Interface) 보안 아키텍처 수립 : 개정 개인정보 보호법에 따른 본인 전송요구권에 대응하여 mTLS, OAuth(Open Authorization) 2.0 및 FAPI(Financial-grade API) 기반 보안 API 표준 구현 필수.
- **상시 평가** (Continuous Audit) 시스템 구축 : 1년 주기의 사후 심사 대응을 넘어, DB(Database) 접근제어 및 KMS(Key Management Service) 암호키 변경 로그를 매일 분석하여 통제 결함을 실시간 식별하는 상시 감사 체계 확립 필요.
