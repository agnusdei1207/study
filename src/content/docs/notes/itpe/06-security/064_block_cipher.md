## 연관 키워드

- 블록 암호(Block Cipher), 대칭키 암호, 라운드 함수, Feistel 구조, SPN 구조
- AES, ARIA, LEA, DES, 3DES, 운용 모드(Mode of Operation)
- ECB, CBC, CTR, GCM, AEAD, 패딩 오라클, Nonce 재사용, Sweet32, 키 회전

## Ⅰ. 블록 암호(Block Cipher)의 개요

- 핵심 요약 : 고정 크기 블록을 다중 라운드로 변환하는 대칭키 암호이며, 운용 모드 선택이 실제 안전성을 좌우하는 방식.
- 개념 : 평문을 64비트, 128비트 같은 고정 길이 블록으로 나누고, 비밀키에서 유도한 라운드 키로 여러 라운드를 반복해 같은 길이의 암호문 블록을 만드는 **블록 암호** (Block Cipher).
- 배경 및 필요성 : 대용량 데이터를 빠르게 암호화해야 하는 저장·전송 환경에서 기밀성을 확보할 기반 기술이 필요하며, 이 요구에 맞춰 Feistel 구조와 SPN 구조가 표준 설계 계열로 정착함. 대표 예는 고급 암호화 표준(AES, Advanced Encryption Standard)과 데이터 암호화 표준(DES, Data Encryption Standard)이다.
- 주요 목적 : 대용량 데이터의 고속 기밀성 확보, 그리고 **AEAD** (Authenticated Encryption with Associated Data) 운용으로 무결성과 인증을 함께 달성.

## Ⅱ. 블록 암호(Block Cipher)의 특징 및 장점

- 핵심 요약 : 라운드 반복과 블록 단위 처리가 고속 기밀성과 통계 공격 저항으로 이어지는 구조.

1. **라운드 변환** (Round Function) : 치환과 확산을 여러 라운드 반복 → 입력과 출력의 통계적 관계를 흐려 통계 분석 공격에 대응.
2. **Feistel 구조** : 블록을 좌우 반쪽으로 나눠 한쪽에만 라운드 함수를 적용 → 라운드 함수의 역함수가 필요 없어 암호화와 복호화를 같은 회로로 구현.
3. **SPN 구조** (Substitution-Permutation Network, 치환-순열 네트워크) : 블록 전체에 치환과 순열을 병렬 적용 → 적은 라운드에서도 전체 블록이 빠르게 섞여 고속 처리.
4. **운용 모드** (Mode of Operation) : 블록을 연결하는 방식을 선택 → 같은 평문 패턴이 암호문에 드러나는 것을 막는 방식으로 기밀성 수준을 결정.
5. AEAD : 기밀성과 무결성을 하나의 알고리즘에서 함께 보장 → 암호문 위변조를 복호화 단계에서 탐지.

## Ⅲ. 블록 암호(Block Cipher)의 구조 (흐름)

- 핵심 요약 : 블록을 절반씩 맞바꾸는 Feistel 구조와 블록 전체를 병렬 변환하는 SPN 구조의 이원 체계.
- Feistel 구조 : 블록을 $L$, $R$로 2등분하여 $L_i = R_{i-1}$, $R_i = L_{i-1} \oplus F(R_{i-1}, K_i)$로 갱신하는 구조. 복호화 시 라운드 키 순서만 뒤집는다.
- SPN 구조 : 라운드마다 키 결합, 치환(S-Box), 순열을 적용하는 구조. 복호화에는 각 연산의 역변환이 별도로 필요하다.

```text
[ Feistel 구조 ]

평문 블록
   ↓ 좌우 2등분 (L, R)
R → 라운드 함수 F(R, Ki)
   ↓ 결과를 L과 결합 (⊕)
좌우 맞바꿈 (Swap)
   ↓ 라운드 반복
암호문 블록
```

```text
[ SPN 구조 ]

평문 블록 (128비트)
   ↓ 라운드 키 결합 (AddRoundKey)
   ↓ 치환 (SubBytes, S-Box)
   ↓ 순열 (ShiftRows, MixColumns)
   ↓ 라운드 반복 (AES 10~14회)
암호문 블록
```

## Ⅳ. 블록 암호(Block Cipher)의 비교

- 핵심 요약 : 구조 간에는 설계 복잡도와 처리 속도가, 운용 모드 간에는 무결성 제공 여부가 핵심 차이.

| 비교 축 | Feistel 구조 | SPN 구조 |
| --- | --- | --- |
| 대표 알고리즘 | DES, SEED | AES, ARIA, LEA(Lightweight Encryption Algorithm) |
| 설계 복잡도 | 역함수가 불필요해 하드웨어 설계가 단순 | 각 연산의 역변환 회로가 추가로 필요 |
| 처리 속도 | 매 라운드 블록의 절반만 갱신되어 상대적으로 느림 | 블록 전체를 병렬 처리해 고속 암호화에 유리 |
| 확산 방식 | 전역 확산까지 더 많은 라운드 필요 | 라운드 내에서 전역 확산이 빠르게 진행 |

| 운용 모드 | 동작 원리 | 병렬 처리 | 무결성 인증 | 권장 여부 |
| --- | --- | --- | --- | --- |
| ECB(Electronic Codebook) | 블록마다 독립적으로 암호화 | 가능 | 미제공 | 사용 금지 (동일 패턴 노출) |
| CBC(Cipher Block Chaining) | 이전 암호문 블록과 배타적 논리합(XOR, Exclusive OR) 후 암호화 | 암호화는 순차, 복호화는 병렬 | 미제공 | 단독 사용 지양 (패딩 오라클 취약) |
| CTR(Counter Mode) | Nonce와 카운터를 암호화해 평문과 XOR | 암·복호화 모두 병렬 | 미제공 | 스트림형 고속 처리에 적합 |
| GCM(Galois/Counter Mode) | CTR 암호화에 GHASH 기반 인증 결합 | 완전 병렬 | 제공 (AEAD) | 현행 표준 권장 |

- 선택 기준 : 데이터 무결성 보장이 필요하면 AEAD 계열(GCM)을 우선 선택하고, 블록 크기와 운용 모드를 함께 정함.

## Ⅴ. 블록 암호(Block Cipher)의 한계와 방안

- 핵심 요약 : 블록 크기, 패딩, Nonce 관리의 세 지점에서 취약점이 생기며, 128비트 블록과 AEAD 모드, Nonce 통제로 막는 구조.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 64비트 블록 암호 잔존 | 생일 역설로 약 2^32개 블록(약 32GB) 처리 시 블록 충돌 발생, 평문 일부 노출 위험 (Sweet32) | 128비트 블록 암호(AES, ARIA, LEA)로 전환, TLS(Transport Layer Security) 1.3에서 64비트 알고리즘 제외 | 64비트 블록 알고리즘 잔존 세션 비율 |
| CBC 패딩 오라클 | 패딩 오류 응답을 악용해 평문 복원, 비트 플리핑으로 위변조 | AEAD(AES-GCM, ChaCha20-Poly1305) 의무 적용 | 패딩 오류 응답 노출 건수 |
| Nonce 재사용 | CTR·GCM에서 같은 키와 Nonce가 반복되면 키스트림 노출과 인증 위조 위험 | 암호학적 난수 또는 단조 증가 카운터로 Nonce 생성 강제, 전송량 임계 도달 시 키 회전 | Nonce 중복 탐지 건수 |

## Ⅵ. 블록 암호(Block Cipher) 적용을 위한 기술사적 제언

- 핵심 요약 : 알고리즘 목록보다 암호 정책과 인벤토리 관리를 먼저 세워 블록 암호를 전사 표준으로 운영.

1. 정보보호 조직은 전사 암호 알고리즘 인벤토리를 구축하고, 폐기 대상 블록 암호와 운용 모드 목록을 주기적으로 갱신하는 거버넌스를 둔다.
2. 개발 표준에 AEAD 모드 사용을 기본값으로 정하고, 예외 승인 절차를 거친 경우에만 다른 모드를 허용하도록 한다.
3. 장기 보관 데이터는 양자 내성 암호 전환 로드맵과 함께 재암호화 일정을 세워 키와 알고리즘의 수명 주기를 관리한다.

## Ⅶ. 결론

- 핵심 요약 : 블록 암호의 안전성은 알고리즘 자체보다 운용 모드, Nonce, 키 관리 체계에서 결정.
- 시사점 : 128비트 블록과 AEAD 모드를 기본값으로 삼는 표준화가 기밀성과 무결성을 동시에 확보하는 출발점.
