## 지식 로드맵 내 현재 위치

AI 보안 → LLM 연계 보안 → MCP 보안

## 30초 인출

- **본질:** **MCP 보안 취약점**은 외부 Server·리소스·도구를 신뢰경계 없이 연결하거나 과도한 권한을 부여할 때 생기는 위험
- **구조:** Host 애플리케이션의 Client가 Server와 메시지를 교환하고, Server가 리소스·프롬프트·도구를 제공
- **보안 핵심:** 연결 규약만으로 안전한 실행이 보장되지 않으므로 Host·Server의 신뢰경계, 사용자 동의, 대상별 권한을 관리

<details>
<summary>핵심 용어</summary>

- **MCP (Model Context Protocol):** LLM 애플리케이션이 외부 컨텍스트와 기능을 표준 방식으로 연동하는 프로토콜
- **LLM (Large Language Model, 대규모 언어 모델):** 대규모 텍스트 데이터로 학습해 언어 입력을 처리·생성하는 모델
- **JSON (JavaScript Object Notation):** 구조화된 데이터를 표현하는 경량 텍스트 형식
- **RPC (Remote Procedure Call):** 네트워크를 통해 원격 시스템의 기능을 호출하는 방식
- **STDIO (standard input/output):** 프로세스의 표준 입력·출력 스트림을 이용하는 통신 방식
- **HTTP (Hypertext Transfer Protocol):** 웹에서 요청·응답을 교환하는 애플리케이션 계층 프로토콜
- **Host:** 사용자·모델 상호작용을 관리하고 Client를 포함하는 애플리케이션
- **Client:** Host 안에서 MCP Server와 요청·응답을 교환하는 연결 구성요소
- **Server:** Host·Client에 리소스, 프롬프트, 도구 등 기능을 제공하는 구성요소
- **Tool:** Server가 제공하고 모델이 호출을 요청할 수 있는 기능으로, 실행 전 권한·영향 검토가 필요한 대상
- **혼동된 대리인(confused deputy):** 중개 서비스가 호출자의 권한·의도를 잘못 해석해 다른 주체의 권한을 과도하게 행사하는 취약성
- **토큰 전달(token passthrough):** 받은 인증 토큰을 대상·권한 검증 없이 다른 서비스로 넘기는 위험한 구현
</details>

> MCP 연계에서 발생하는 주요 보안 취약점과 Host·Server의 통제 원칙을 설명하시오. *(10점 예상문제)*

---
## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **MCP 보안 취약점**은 외부 Server·리소스·도구와의 연결에서 신뢰경계·권한·토큰 검증이 부족할 때 발생하는 위험 |
| 목적 | 악성 콘텐츠 유입·과도한 도구 실행·인증정보 오용을 통제 |

### Ⅱ. 구성과 보안 통제

| 구성요소 | 역할·주요 통제 |
|---|---|
| Host | 사용자 동의·모델 상호작용·도구 실행 정책 관리 |
| Client | 연결 대상·인증정보·응답 검증 |
| Server | 리소스·프롬프트·도구 제공, 사용자별 권한·데이터 최소화 |
| Tool | 최소권한, 입력 검증, 영향도에 따른 사용자 승인 |

```text
사용자 요청
    ↓
Host·Client ──요청/응답── Server
    │                         │
    │ 사용자 동의·권한 검사   └─ 리소스·프롬프트·도구 제공
    ↓
승인된 데이터 조회·도구 실행
```

리소스·도구 결과의 악성 지시, 과도한 도구 권한, 인증정보의 타 서버 전달이 주요 위험. **제언:** Server별 권한을 제한하고 도구 실행 전 사용자 동의와 영향을 확인

---
## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **MCP 보안 취약점**은 외부 Server·리소스·도구와의 연결에서 신뢰경계·권한·토큰 검증이 부족할 때 발생하는 위험 |
| 목적 | 악성 콘텐츠 유입·과도한 도구 실행·인증정보 오용을 통제 |

MCP는 JSON-RPC 기반 메시지로 연결 기능을 표준화하며, 모든 사용자 권한·실행 안전을 프로토콜 자체가 강제하는 것은 아님.

## Ⅱ. 구성요소와 신뢰 경계

| 구성요소 | 제공·사용 기능 | 보안 책임의 중심 |
|---|---|---|
| Host | 사용자·모델 상호작용 관리 | 동의, 정책, 도구 실행 승인 |
| Client | Host와 Server 사이 요청·응답 | 서버 대상, 인증정보, 응답 검증 |
| Server | 리소스·프롬프트·도구 제공 | 사용자별 접근권한, 데이터 최소화, 안전한 실행 |

```text
┌────────────── Host 애플리케이션 ──────────────┐
│ 사용자·모델 ↔ 정책·동의 검사 ↔ MCP Client    │
└──────────────────────┬───────────────────────┘
                       │ MCP 메시지
                       ↓
                 MCP Server
       리소스 · 프롬프트 · 도구 제공
```

## Ⅲ. 주요 보안위협

| 위협 | 취약 지점 | 영향 |
|---|---|---|
| 악성·변조 Server | 미검증 출처·업데이트 | 민감정보 수집, 의도하지 않은 기능 수행 |
| 간접 프롬프트 주입 | 비신뢰 리소스·도구 설명 | 모델의 응답·호출 결정에 악성 지시 반영 |
| 과도한 도구 권한 | Host 권한을 그대로 위임 | 파일·계정·업무 데이터에 과도한 영향 |
| 토큰 오용·혼동된 대리인 | 대상·호출자 검증 누락 | 다른 Server나 자원에 인증 권한 전달 |

## Ⅳ. 인증·인가와 데이터 보호

원격 HTTP 전송의 MCP Authorization은 선택 기능이며, 적용 시 OAuth 기반 규칙과 리소스 대상 검증을 준수. STDIO 전송에는 HTTP Authorization 절차를 그대로 적용하지 않음.

```text
클라이언트 인증
      ↓ 대상 Server·요청 자원 확인
대상에 맞는 토큰·요청 권한 검증
      ↓
사용자별 최소 데이터 조회
      ↓
토큰 재전달 없이 해당 Server에서 처리
```

| 통제 | 핵심 적용 |
|---|---|
| 대상 바인딩 | 토큰의 발급 주체·대상 자원을 검증하고 다른 Server용 토큰을 수용·중계하지 않음 |
| 최소권한 | 사용자·도구·자원별로 필요한 범위만 허용하고 민감 작업은 추가 동의 적용 |
| 개인정보 | 요청 목적에 필요한 데이터만 제공하고 로그·캐시의 노출을 제한 |

## Ⅴ. 도구·Server 실행 통제

| 실행 지점 | 통제 기준 |
|---|---|
| Server 등록 | 출처·버전·제공 기능 검토, 변경 승인, 취약점 갱신 확인 |
| 도구 호출 | 인자·호출자 권한 확인, 부작용 설명, 고위험 작업 사용자 승인 |
| 로컬 Server | 전용 계정·샌드박스, 파일·네트워크 권한 제한 |
| 운영 관측 | 호출·권한 변경 기록, 이상행위 탐지, 사고 시 연결·자격증명 차단 |

## Ⅵ. 한계와 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 프로토콜 연결만으로 악성 콘텐츠와 위험한 호출을 판별할 수 없음 | Host 정책에서 비신뢰 입력을 분리하고, 실행 전 목적·권한·영향을 확인하는 승인 경로 구성 |
| 여러 Server에 걸친 권한과 데이터 흐름이 한눈에 보이지 않음 | Server·도구별 신뢰목록과 자원별 권한을 관리하고, 호출·토큰 사용 이력을 연계 점검 |
