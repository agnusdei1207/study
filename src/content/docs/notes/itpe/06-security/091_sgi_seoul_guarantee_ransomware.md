## 연관 키워드

- SGI서울보증, 랜섬웨어, 불변 백업, 에어갭, 3-2-1-1-0 백업, 사업연속성계획
- 이중 갈취, 하드웨어 보안 모듈(HSM), 특권 접근 통제, 금융 인프라

## Ⅰ. SGI서울보증 랜섬웨어 사고의 개요

- 핵심 요약 : 2025년 7월 보증 서비스가 수일간 중단된 뒤 민관 공조로 복구된 금융 인프라 침해 사고.
- 개념 : 2025년 7월 SGI서울보증의 전산 서버가 **랜섬웨어** (Ransomware, 데이터를 암호화한 뒤 복구 대가를 요구하는 악성코드)에 감염되어, 보증서 발급 등 대국민 서비스가 중단되었다가 복구된 침해사고.
- 배경 및 필요성 : 보증 발급이 은행의 전세대출 심사와 맞물린 금융 기반 서비스라서, 한 시스템의 장애가 이용자의 대출 일정 전체로 번지는 구조적 위험이 드러남. 이에 따라 망분리 예외 구간 점검, **불변 백업** (WORM, Write Once Read Many, 한 번 기록하면 수정이나 삭제가 불가능한 저장 방식), 사업연속성계획(BCP, Business Continuity Plan)의 중요성이 부각됨.
- 주요 목적 : 금융 공공 인프라의 랜섬웨어 대응 실패 요인을 분석하고, 백업 신뢰성과 금융망 전반의 연속성을 높일 방안을 도출하는 것.

## Ⅱ. SGI서울보증 랜섬웨어 사고의 특징 및 장점

- 핵심 요약 : 금융 연계 서비스의 특성상 피해가 이용자 전체로 번지고, 복구 속도가 백업 신뢰성에 좌우된 사고.

1. 대국민 금융 연계 : 보증서 발급이 은행 대출 심사와 연결되어 한 시스템의 중단이 금융 거래 전반으로 확산 → 피해가 사고 기업을 넘어 이용자에게 전가됨.
2. 민관 공조 체계 : 금융당국과 금융보안원이 복구를 지원하며 사고 대응이 신속히 조율됨 → 전문기관의 분석 역량이 복구 경로를 좌우함.
3. 백업 정합성의 중요성 : 감염 전 백업 데이터의 정합성을 검증하는 데 시간이 걸려 완전 복구가 늦어짐 → 백업의 무결성 확보가 복구 속도를 결정하는 요인임을 드러냄.
4. **이중 갈취** (Double Extortion, 데이터 암호화에 더해 유출을 빌미로 추가 금품을 요구하는 수법)의 위험 : 서비스 복구와 별개로 기밀 유출 여부를 확인해야 하는 부담이 추가됨.

## Ⅲ. SGI서울보증 랜섬웨어 사고의 구조 (흐름)

- 핵심 요약 : 침해 인지, 격리와 포렌식, 공조 복구, 단계적 정상화의 네 단계로 진행된 복구 흐름.

```text
[ 사고 대응 경과 (2025년 7월) ]

침해 인지 (7월 14일)
              ↓
네트워크 차단, 비상대응 체계 가동
              ↓
감염 서버 격리와 포렌식 분석
              ↓
금융당국·금융보안원 공조, 데이터 복구
              ↓
보증서 발급 재개 (7월 17일 보도)
```

```text
[ 복구 수단의 계층 ]

1차: 불변 스냅샷으로 즉시 롤백
              ↓
2차: 불변 백업 원본 보존
              ↓
3차: 물리적 격리 소산본으로 최종 복구
```

## Ⅳ. SGI서울보증 랜섬웨어 사고와 일반 기업 대응의 비교

- 핵심 요약 : 금융 핵심 인프라는 일반 기업과 달리 복구 목표, 백업 구조, 대체 업무, 보고 체계를 금융 거래 연속성 기준으로 설계해야 함.

| 비교 항목 | 일반 기업 랜섬웨어 대응 | 금융 핵심 인프라 랜섬웨어 대응 |
| --- | --- | --- |
| 복구 목표 | 업무 중요도에 따라 수일의 복구 기간 허용 | 금융 거래 전반의 중단을 막기 위해 최단 시간 복구 요구 |
| 백업 구조 | 로컬 저장소와 클라우드 일반 백업 | **3-2-1-1-0 백업** (복제본 3개, 매체 2종, 원격지 1곳, 불변·**에어갭** 1곳, 복구 검증 오류 0)의 적용 |
| 대체 업무 | 서비스 중단 공지와 임시 처리 | 수작업 발급 절차와 사후 정산 절차를 사전에 준비 |
| 보고 체계 | 내부 보고 중심 | 금융당국 즉시 보고와 금융권 공조 |

## Ⅴ. SGI서울보증 랜섬웨어 사고의 한계와 방안

- 핵심 요약 : 백업 삭제, 외부 복호화 의존, 연쇄 대출 중단, 유출 확인 지연을 다자 승인, 즉시 롤백, 사후 검증 심사, 암호화 키 관리로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 온라인 백업의 동시 삭제 | 백업 서버 관리자 권한 탈취로 온라인 백업이 함께 손실 | 백업 삭제에 다자 승인을 적용하고, 논리적으로 분리된 에어갭 소산본 운영 | 백업 접근 권한 변경 이력 |
| 외부 기관 복호화 의존 | 자체 복호화 능력이 없어 외부 분석 결과에 복구 시점이 종속 | 불변 스냅샷 기반의 즉시 롤백 체계를 1차 복구 수단으로 구축 | 복구 소요 시간 |
| 대출 심사 연쇄 중단 | 보증 시스템 장애 시 은행 전세대출 심사도 동시에 멈춤 | 은행 연계 구간에 사후 검증 조건부 비상 심사 절차를 사전 설계 | 비상 심사 처리 건수 |
| 이중 갈취에 따른 유출 확인 지연 | 기밀 유출 협박 시 데이터 영향 범위 파악이 늦어짐 | 저장 데이터를 컬럼 단위로 토큰화하고 하드웨어 보안 모듈(HSM, Hardware Security Module) 기반 봉투 암호화 적용 | 유출 영향 확인 소요 시간 |

## Ⅵ. SGI서울보증 랜섬웨어 사고에 대한 기술사적 제언

- 핵심 요약 : 백업 무결성, 특권 접근 통제, 업무 연속성 훈련을 함께 갖춰 복구 가능성을 설계 기준으로 삼아야 함.

1. 백업 무결성 : 복구 가능한 백업을 유지하도록 불변 저장소와 에어갭 소산본을 함께 설계하는 방향 필요.
2. 특권 접근 : 관리자 계정의 사용 범위를 줄이고 관리자 단말을 분리하여, 공격자가 도메인 전체를 장악하는 경로를 막는 체계 필요.
3. 업무 연속성 : 핵심 금융 업무를 대상으로 정기 복구 훈련을 실시하고, 수작업 대체 절차를 평소에 준비하는 체계 필요.

## Ⅶ. 결론

- 핵심 요약 : 랜섬웨어 피해의 크기는 침입 차단보다 복구 가능성을 얼마나 설계했는지에 따라 갈림.
- 시사점 : 백업 무결성과 훈련된 대체 절차를 갖춘 금융 기관이 사고 이후에도 대국민 서비스를 지속할 수 있음.
