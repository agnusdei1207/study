## 지식 로드맵 내 현재 위치

계정 보안 → 자동화 인증 공격(OAT-008) → 크리덴셜 스터핑(Credential Stuffing)

## 30초 인출

- **본질:** 사용자의 비밀번호 재사용(Password Re-use) 습관을 악용하여, 외부 타사 서비스 침해로 유출된 방대한 계정 ID/PW 쌍(콤보 리스트)을 다른 웹/모바일 서비스 로그인 창에 봇넷으로 자동 무차별 대입하는 공격.
- **메커니즘:** 다크웹 콤보 리스트 확보 → 분산 주거용 프록시 및 자동화 도구(OpenBullet 등)로 대량 로그인 시도 → 성공 계정 선별 → 포인트 탈취, 명의 도용, 2차 사기 결제 자행.
- 통찰: 단순 패스워드 복잡도 정책으로는 방어가 불가능하므로, FIDO2 패스키 전환, 봇 매니지먼트(행동 기반 핑거프린팅), 유출 비밀번호 사전 차단(HIBP 연동) 필수.

<details><summary>핵심 용어</summary>

- **크리덴셜 스터핑(OWASP OAT-008)**: 사전에 유출된 유효 자격증명 목록을 대규모 자동화 툴을 이용해 표적 사이트에 대입하는 공격.
- **콤보 리스트(Combo List)**: 다크웹이나 해킹 포럼에서 유통되는 `이메일:비밀번호` 또는 `아이디:비밀번호` 형태의 대량 텍스트 데이터베이스.
- **비밀번호 재사용(Password Re-use)**: 여러 사이트에서 동일한 아이디와 패스워드를 중복 설정하여 사용하는 사용자의 보안 불감 관행.
- **주거용 프록시(Residential Proxy)**: 가정용 ISP IP를 대여해 주는 프록시 네트워크로, 데이터센터 IP 차단 룰을 완벽히 우회하는 데 악용됨.
- **봇 매니지먼트(Bot Management)**: 요청 헤더, TLS 지문(JA3/JA4), 브라우저 렌더링 특성(캔버스 핑거프린트)을 분석하여 자동화 스크립트와 인간 사용자를 구별하는 기술.
</details>

## 2~4교시 예상문제 (25점)

> 사용자의 비밀번호 재사용 습관을 악용한 '크리덴셜 스터핑(Credential Stuffing)'의 공격 메커니즘을 브루트 포스 및 패스워드 스프레이와 비교 분석하고, 로그인 엔드포인트 방어, 봇 탐지 및 계정 탈취 사후 대응을 위한 엔지니어링 방안을 제시하시오. (기출·제131회 1교시 10번)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 타 서비스 침해사고로 유출된 수백만 건의 ID/PW 콤보 리스트를 확보한 후, 자동화 봇과 분산 프록시를 동원해 다른 표적 사이트들에 무차별 로그인 대입을 시도하는 사이버 공격 |
| 목적 | 계정 탈취(ATO: Account Takeover)를 통해 적립금/마일리지 횡령, 저장된 결제 수단 도용, 민감 개인정보 조회 및 스팸/피싱 계정 유통 |

## Ⅱ. 크리덴셜 스터핑의 핵심 특징 및 공격 라이프사이클

| 특징 항목 | 세부 공격 내용 | 엔지니어링 파급 효과 |
|---|---|---|
| 높은 공격 성공률 | 일반적인 무작위 브루트포스(0.01% 이하) 대비 1~3% 수준의 높은 로그인 성공률 보유 | 수만 건의 정상 계정이 수 시간 만에 대량 탈취 |
| 분산 주거용 IP 활용 | 수만 개의 정상 가정용 IP(Residential Proxy)로 분산 요청하여 IP 기반 차단 우회 | 단일 IP 레이트 리밋(Rate Limit) 정책 무력화 |
| 정상 로그인 트래픽 위장 | 탈취된 자격증명 자체가 유효하므로 시스템 로그 상 '정상 로그인 성공'으로 기록 | 전통적인 시그니처 및 침입탐지시스템(IDS) 탐지 불가 |
| 로그인 서버 과부하 | 초당 수천 건의 자동화 HTTP POST 요청이 유입되어 로그인 API 서버 DoS 유발 | 정상 고객의 로그인 지연 및 전자상거래 가용성 저하 |
| 비즈니스 금전 손실 | 계정에 저장된 기프트카드, 항공사 마일리지, 커머스 캐시 즉시 세탁 및 현금화 | 고객 피해 보상 비용 및 전자금융사고 배상책임 직면 |

## Ⅲ. 크리덴셜 스터핑 공격 프로세스 및 다계층 방어 아키텍처

```text
[ 크리덴셜 스터핑 공격 체인 ]
타사 유출 콤보 리스트 (ID/PW DB) ──▶ 자동화 툴 (OpenBullet / Sentry MBA)
                                          │
                                          ▼
주거용 프록시 네트워크 (수만 개 가정용 IP) ──▶ [ 표적 서비스 로그인 API (POST /login) ]
                                          │
                                          ▼
[ 다계층 엔지니어링 방어 아키텍처 ]
+---------------------------------------------------------------------------------+
| 1. 네트워크 및 봇 방어선 (Edge WAF / Bot Management)                            |
|  ├── TLS 핑거프린팅: JA3/JA4 지문 대조를 통한 Python/curl 스크립트 차단        |
|  ├── 행동 챌린지: 비가시적 PoW(Proof-of-Work) 및 Turnstile 인터랙션 검증        |
|  └── 레이트 리밋: 계정 식별자(ID) 기반 슬라이딩 윈도우 시도 횟수 제한          |
+---------------------------------------------------------------------------------+
                                          │ (통과 트래픽)
                                          ▼
+---------------------------------------------------------------------------------+
| 2. 인증 애플리케이션 방어선 (Auth Core)                                         |
|  ├── 유출 암호 대조: HIBP k-Anonymity API 연동 유출된 비밀번호 차단            |
|  ├── 피싱 저항 MFA: FIDO2 패스키(Passkey) 강제 적용 (패스워드 입력 배제)        |
|  └── Step-Up 인증: 신규 IP/단말 감지 시 추가 OTP 또는 이메일 승인 요구         |
+---------------------------------------------------------------------------------+
                                          │ (로그인 성공 후)
                                          ▼
+---------------------------------------------------------------------------------+
| 3. 사후 세션 및 거래 감시 (FDS / UEBA)                                          |
|  └── 비정상 행위 감시: 로그인 직후 즉각적인 포인트 환전/주소지 변경 실시간 동결|
+---------------------------------------------------------------------------------+
```

| 방어 단계 | 세부 통제 과제 | 핵심 엔지니어링 구현 상세 |
|---|---|---|
| 엣지 게이트웨이 | 봇넷 식별 및 트래픽 필터링 | JA4 핑거프린트 매칭, 헤드리스 브라우저(Puppeteer) 캔버스 지문 분석 |
| 계정 레벨 통제 | 단일 계정 대상 속도 제한 | IP 무관 계정 ID 기준 분당 5회 실패 시 15분간 임시 계정 잠금 |
| 패스워드 정책 | 기 유출 자격증명 차단 | 사용자 패스워드 변경/로그인 시 k-익명성 기반 유출 DB 실시간 대조 |
| 인증 현대화 | 패스워드리스(Passwordless) | WebAuthn 기반 생체인증 패스키(Passkey) 도입으로 ID/PW 자체 폐기 |
| 이상 징후 분석 | 계정 탈취(ATO) 이상 거래 탐지 | 로그인 직후 배송지 변경, 고액 상품권 구매 시 FDS 결제 보류 |

## Ⅳ. 크리덴셜 스터핑 vs 브루트 포스 vs 패스워드 스프레이 비교

| 비교 항목 | 브루트 포스 (Brute Force) | 패스워드 스프레이 (Password Spray) | 크리덴셜 스터핑 (Credential Stuffing) |
|---|---|---|---|
| 대상 계정 수 | 단일 타깃 계정 (1명) | 전사 임직원 다수 계정 (N명) | 불특정 다수 대량 계정 (수백만 명) |
| 대입 패스워드 | 무작위 문자열 전수 대입 | 흔히 쓰이는 소수 암호 (`P@ssw0rd!`) | 외부 유출된 실제 유효 콤보 리스트 |
| 계정 잠금 위험 | 매우 높음 (단일 계정 임계치 초과) | 낮음 (계정당 1~2회 시도로 회피) | 낮음~보통 (1회 시도 후 다음 계정 이동) |
| 주된 공격 목표 | 특정 고위직/관리자 계정 탈취 | 단일 계정 침투를 통한 사내망 진입 | 대량의 일반 사용자 계정 포인트 횡령 |
| 공격 성공률 | 극히 낮음 ($10^{-6}$ 이하) | 보통 (일부 취약 패스워드 사용자 적발)| 높음 (재사용률로 인해 1~3% 성공) |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 공격자가 실제 사용자의 감염된 홈 PC(주거용 프록시)를 통해 요청을 분산하여 기존 IP 차단 룰 무력화 | IP 차단을 지양하고, 브라우저 HTTP/2 프로토콜 지문, TLS ClientHello 파라미터(JA4), 마우스 동작 이벤트를 종합하는 행동 봇 매니지먼트 구축 |
| 그래픽 캡차(CAPTCHA)를 도입했으나 공격자가 2Captcha 등 인도의 유료 인간 솔버 API를 연동하여 자동 우회 | 사용자 마찰을 유발하는 이미지 맞추기 대신, 백그라운드에서 브라우저 CPU 암호 퍼즐을 풀게 하는 보이지 않는 작업증명(Proof of Work) 챌린지 강제 |
| 패스워드 복잡도(특수문자, 대소문자 혼용)를 아무리 강화해도 사용자가 동일한 복합 암호를 전 사이트에 재사용 | 패스워드 개념을 완전히 제거하는 FIDO2 WebAuthn 패스키(Passkey)를 기본 인증 수단으로 전면 전환하여 유출 비밀번호 가치 상실 유도 |
| 공격자가 정상 로그인 성공 후 1주일간 잠복하다가 포인트를 소액씩 분할 인출하여 FDS 탐지를 회피하는 고도화 | 계정 생성/로그인 이력과 트랜잭션 패턴을 연결하는 사용자 엔티티 행위 분석(UEBA)을 연동하여 장기 잠복 후 발생한 최초 거래 정밀 심사 |

## Ⅵ. 제언

```text
[ 크리덴셜 스터핑 제로화를 위한 3대 인증 혁신 모델 ]

+-------------------------+      +-------------------------+      +-------------------------+
|     1. 패스키 전환      | ---> |     2. 봇 지능 차단     | ---> |     3. HIBP 유출 차단   |
| (FIDO2 WebAuthn 전면화) |      | (JA4 + PoW 백그라운드)  |      | (k-익명성 유출 암호 거부|
+-------------------------+      +-------------------------+      +-------------------------+
```

| 이행 영역 | 엔지니어링 실무 구현 과제 | 비즈니스 가치 |
|---|---|---|
| 인증 체계 혁신 | 모바일 앱 및 웹 로그인에 생체 기반 패스키(Passkey) 기본 채택 | ID/PW 유출로 인한 계정 탈취 위험 100% 제거 |
| 인프라 보안 | 로그인 엔드포인트 전면에 Cloudflare/Akamai 봇 매니지먼트 및 PoW 챌린지 배포 | 자동화 대량 대입 트래픽 99.9% 엣지 단계 사전 드롭 |
| 사후 계정 보호 | Have I Been Pwned API 연동을 통해 유출된 비밀번호 사용자의 로그인 시 강제 변경 | 비밀번호 재사용 사용자의 선제적 보안 강화 달성 |
