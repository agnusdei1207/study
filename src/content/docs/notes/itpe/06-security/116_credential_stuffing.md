## 지식 로드맵 내 현재 위치

지식 위치: 계정 보안 → 유출 자격증명 재사용 → **크리덴셜 스터핑**

## 30초 인출

- 본질: 한 서비스에서 유출된 ID·비밀번호 쌍을 다른 서비스의 로그인에 자동 대입해 재사용 계정을 찾는 공격
- 메커니즘: 외부 유출 ID·비밀번호 쌍을 자동 로그인에 대입 → 성공 계정 선별 → 부정 사용
- 통찰: 한계: MFA만으로 세션 탈취·약한 복구를 막을 수 없음 → 방안: 유출 비밀번호 차단·속도 제한·성공 계정 이상 탐지를 결합

<details>
<summary>핵심 용어</summary>

- **크리덴셜 스터핑(Credential Stuffing)** : 다른 서비스에서 유출된 계정·비밀번호 쌍을 재사용해 로그인을 시도하는 공격
- **유출 자격증명** : 침해·노출로 공격자가 확보한 계정 식별자와 인증 비밀의 조합
- **속도 제한(Rate Limiting)** : 계정·기기·네트워크의 로그인 시도 횟수·속도를 제어하는 통제
- **다중요소 인증(Multi-Factor Authentication, MFA)** : 서로 다른 유형의 인증 요소를 결합해 신원을 확인하는 방식

</details>

## 2~4교시 예상문제 (25점)

> 크리덴셜 스터핑의 원인·공격 절차를 설명하고 로그인·계정 복구·사후 탐지 전 단계의 대응 체계를 설계하시오. (예상·25점)

## 2~4교시 25점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **크리덴셜 스터핑** 은 외부에서 유출된 계정·비밀번호 쌍을 다른 서비스 로그인에 재사용하는 공격 |
| 목적 | 계정 탈취를 예방하고 자동 대입·부정 사용을 조기 탐지 |

공격자는 분산 IP·프록시·정상 브라우저와 유사한 동작으로 탐지를 회피할 수 있다.

### Ⅱ. 공격과 관측 신호

```text
외부 유출 계정 쌍
       ↓ 자동 대입·분산 접속
로그인 실패 다수 ──> 성공 계정 선별
                         ↓ 새 기기·위치
                    부정 조회·변경
```

| 단계 | 징후 |
|---|---|
| 목록 확보 | 외부 유출 계정 쌍의 유통 |
| 자동 대입 | 다수 계정 대상 반복 실패·분산 접속 |
| 성공 계정 선별 | 새 위치·기기에서 로그인 성공 |
| 부정 사용 | 비밀번호·복구 수단 변경, 거래·정보 조회 |

### Ⅲ. 통제 구조

```text
비밀번호 생성·변경 → 유출 비밀번호 목록 점검
로그인 요청 → 계정·IP·기기별 속도 제한·행동 분석
           → MFA/패스키 확인
           → 이상 세션·거래 감시
복구 요청 → 동일 수준의 신원 확인·알림·재설정 보호
```

#### 통제별 한계

| 통제 | 한계·보완 |
|---|---|
| IP 차단 | 분산 프록시 우회; 계정·기기·위험 신호 결합 |
| CAPTCHA | 자동화 우회와 사용자 마찰 가능 |
| SMS MFA | 피싱·SIM 교체 가능성; 위험에 따라 패스키 등 |
| 유출 비밀번호 점검 | 공개된 목록 밖의 유출은 탐지 불가 |
| 로그인 탐지 | 정상 로그인 성공 뒤의 세션·거래 감시 필요 |

봇 차단 99%, 비밀번호 재사용 80% 등 근거 없는 보편 수치 배제.

#### 대응·복구

성공 계정의 세션 무효화, 비밀번호 재설정, 인증수단 재등록 검토, 이용자 알림과 피해 거래 확인. 개인정보 보호를 고려한 로그인 로그 보존.

### Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| MFA만으로 세션 탈취와 약한 계정 복구를 막지 못함 | 유출 암호 차단·속도 제한·세션 이상 탐지와 복구 경로 보호 |

### Ⅴ. 제언

로그인 API의 방어를 계정 생성·복구·세션·거래까지 연결하고, 오탐과 사용자 접근성을 실제 트래픽으로 검증.
