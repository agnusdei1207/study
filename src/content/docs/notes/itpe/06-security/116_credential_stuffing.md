## Ⅰ. 크리덴셜 스터핑(Credential Stuffing)의 개요

- **개념** : 타 서비스 침해사고로 유출된 수백만 건의 ID/PW 콤보 리스트를 확보한 후, 자동화 봇과 분산 프록시를 동원해 다른 표적 사이트들에 무차별 로그인 대입을 시도하는 사이버 공격.
- **배경 및 필요성** : 다크웹 등에서 유출된 방대한 계정 자격증명(ID/PW) 데이터베이스를 기반으로 공격자가 자동화된 봇넷을 통해 다른 서비스에 무차별 대입 로그인을 시도하는 대규모 계정 탈취 공격을 차단하기 위해 방어 체계가 요구됨.
- **핵심 목적** : 계정 탈취(ATO: Account Takeover)를 통해 적립금/마일리지 횡령, 저장된 결제 수단 도용, 민감 개인정보 조회 및 스팸/피싱 계정 유통.

## Ⅱ. 크리덴셜 스터핑(Credential Stuffing)의 핵심 아키텍처 및 동작 메커니즘

크리덴셜 스터핑(Credential Stuffing)은(는) 신뢰할 수 있는 보안 구조와 표준화된 절차를 기반으로 동작하며, 세부적인 아키텍처와 구성요소 간의 상호작용 메커니즘은 다음과 같음.

```text
[ 크리덴셜 스터핑 공격 체인 ]
타사 유출 콤보 리스트 (ID/PW DB) ──▶ 자동화 툴 (OpenBullet / Sentry MBA)
                                          │
                                          ▼
주거용 프록시 네트워크 (수만 개 가정용 IP) ──▶ [ 표적 서비스 로그인 API (POST /login) ]
                                          │
                                          ▼
[ 다계층 엔지니어링 방어 아키텍처 ]
+---------------------------------------------------------------------------------+
| 1. 네트워크 및 봇 방어선 (Edge WAF / Bot Management)                            |
|  ├── TLS 핑거프린팅: JA3/JA4 지문 대조를 통한 Python/curl 스크립트 차단        |
|  ├── 행동 챌린지: 비가시적 PoW(Proof-of-Work) 및 Turnstile 인터랙션 검증        |
|  └── 레이트 리밋: 계정 식별자(ID) 기반 슬라이딩 윈도우 시도 횟수 제한          |
+---------------------------------------------------------------------------------+
                                          │ (통과 트래픽)
                                          ▼
+---------------------------------------------------------------------------------+
| 2. 인증 애플리케이션 방어선 (Auth Core)                                         |
|  ├── 유출 암호 대조: HIBP k-Anonymity API 연동 유출된 비밀번호 차단            |
|  ├── 피싱 저항 MFA: FIDO2 패스키(Passkey) 강제 적용 (패스워드 입력 배제)        |
|  └── Step-Up 인증: 신규 IP/단말 감지 시 추가 OTP 또는 이메일 승인 요구         |
+---------------------------------------------------------------------------------+
                                          │ (로그인 성공 후)
                                          ▼
+---------------------------------------------------------------------------------+
| 3. 사후 세션 및 거래 감시 (FDS / UEBA)                                          |
|  └── 비정상 행위 감시: 로그인 직후 즉각적인 포인트 환전/주소지 변경 실시간 동결|
+---------------------------------------------------------------------------------+
```

- **엣지 게이트웨이** : 봇넷 식별 및 트래픽 필터링 (JA4 핑거프린트 매칭, 헤드리스 브라우저(Puppeteer) 캔버스 지문 분석).
- **계정 레벨 통제** : 단일 계정 대상 속도 제한 (IP 무관 계정 ID 기준 분당 5회 실패 시 15분간 임시 계정 잠금).
- **패스워드 정책** : 기 유출 자격증명 차단 (사용자 패스워드 변경/로그인 시 k-익명성 기반 유출 DB 실시간 대조).
- **인증 현대화** : 패스워드리스(Passwordless) (WebAuthn 기반 생체인증 패스키(Passkey) 도입으로 ID/PW 자체 폐기).
- **이상 징후 분석** : 계정 탈취(ATO) 이상 거래 탐지 (로그인 직후 배송지 변경, 고액 상품권 구매 시 FDS 결제 보류).

## Ⅲ. 크리덴셜 스터핑(Credential Stuffing)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 브루트 포스 (Brute Force) | 패스워드 스프레이 (Password Spray) | 크리덴셜 스터핑 (Credential Stuffing) |
|---|---|---|---|
| 대상 계정 수 | 단일 타깃 계정 (1명) | 전사 임직원 다수 계정 (N명) | 불특정 다수 대량 계정 (수백만 명) |
| 대입 패스워드 | 무작위 문자열 전수 대입 | 흔히 쓰이는 소수 암호 (`P@ssw0rd!`) | 외부 유출된 실제 유효 콤보 리스트 |
| 계정 잠금 위험 | 매우 높음 (단일 계정 임계치 초과) | 낮음 (계정당 1~2회 시도로 회피) | 낮음~보통 (1회 시도 후 다음 계정 이동) |
| 주된 공격 목표 | 특정 고위직/관리자 계정 탈취 | 단일 계정 침투를 통한 사내망 진입 | 대량의 일반 사용자 계정 포인트 횡령 |
| 공격 성공률 | 극히 낮음 ($10^{-6}$ 이하) | 보통 (일부 취약 패스워드 사용자 적발)| 높음 (재사용률로 인해 1~3% 성공) |

- 크리덴셜 스터핑(Credential Stuffing)은(는) 상기 핵심 비교 지표와 아키텍처 구성을 바탕으로 보안 위협에 대한 방어 효과성을 극대화하며, 기존 레거시 통제 기법 대비 우수한 신뢰성과 운영 효율성을 제공함.

## Ⅳ. 크리덴셜 스터핑(Credential Stuffing)의 주요 한계점 및 해결 방안

- **한계점** : 공격자가 실제 사용자의 감염된 홈 PC(주거용 프록시)를 통해 요청을 분산하여 기존 IP 차단 룰 무력화.
  - **해결 방안** : IP 차단을 지양하고, 브라우저 HTTP/2 프로토콜 지문, TLS ClientHello 파라미터(JA4), 마우스 동작 이벤트를 종합하는 행동 봇 매니지먼트 구축.
- **한계점** : 그래픽 캡차(CAPTCHA)를 도입했으나 공격자가 2Captcha 등 유료 인간 솔버(CAPTCHA 풀이 대행) API를 연동하여 자동 우회.
  - **해결 방안** : 사용자 마찰을 유발하는 이미지 맞추기 대신, 백그라운드에서 브라우저 CPU 암호 퍼즐을 풀게 하는 보이지 않는 작업증명(Proof of Work) 챌린지 강제.
- **한계점** : 패스워드 복잡도(특수문자, 대소문자 혼용)를 아무리 강화해도 사용자가 동일한 복합 암호를 전 사이트에 재사용.
  - **해결 방안** : 패스워드 개념을 완전히 제거하는 FIDO2 WebAuthn 패스키(Passkey)를 기본 인증 수단으로 전면 전환하여 유출 비밀번호 가치 상실 유도.
- **한계점** : 공격자가 정상 로그인 성공 후 1주일간 잠복하다가 포인트를 소액씩 분할 인출하여 FDS 탐지를 회피하는 고도화.
  - **해결 방안** : 계정 생성/로그인 이력과 트랜잭션 패턴을 연결하는 사용자 엔티티 행위 분석(UEBA)을 연동하여 장기 잠복 후 발생한 최초 거래 정밀 심사.

## Ⅴ. 크리덴셜 스터핑(Credential Stuffing) 적용 및 발전을 위한 기술사적 제언

- **인증 체계 혁신 중심의 거버넌스 및 실행 체계 구축** : 모바일 앱 및 웹 로그인에 생체 기반 패스키(Passkey) 기본 채택을(를) 적극 추진하여, ID/PW 유출로 인한 계정 탈취 위험 100% 제거 효과를 극대화해야 함.
- **인프라 보안 중심의 거버넌스 및 실행 체계 구축** : 로그인 엔드포인트 전면에 Cloudflare/Akamai 봇 매니지먼트 및 PoW 챌린지 배포을(를) 적극 추진하여, 자동화 대량 대입 트래픽 99.9% 엣지 단계 사전 드롭 효과를 극대화해야 함.
- **사후 계정 보호 중심의 거버넌스 및 실행 체계 구축** : Have I Been Pwned API 연동을 통해 유출된 비밀번호 사용자의 로그인 시 강제 변경을(를) 적극 추진하여, 비밀번호 재사용 사용자의 선제적 보안 강화 달성 효과를 극대화해야 함.
