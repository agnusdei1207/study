## 답안 골격
```text
[크리덴셜 스터핑(Credential Stuffing)] ◀━━ 머리: Ⅶ 내 의견 (사용자 비밀번호 복잡성 강제 무용론 인정 → 패스키(FIDO2) 도입 및 유출 DB 연동 사전 차단)
 ┃
 ┣━ Ⅰ 개요 ───── 다크웹 등에서 유출된 타 사이트의 대량 계정 자격증명(ID/PW) 목록을 자동화 봇 도구를 이용해 다른 웹사이트에 무차별 대입하여 정상 로그인을 탈취하는 사이버 공격 기법
 ┣━ Ⅱ 특징 ───── 사용자의 비밀번호 재사용(Password Reuse) 습관 악용 · 정상적인 인증 절차를 모사하므로 단순 방화벽 탐지 우회 · 대규모 프록시 봇넷을 통한 분산 시도
 ┣━ Ⅲ 구조 ───── 유출 계정 DB(Combo List) + 공격 자동화 봇(Sentry MBA 등) + 분산 프록시 네트워크 + 타깃 웹/앱 로그인 API
 ┣━ Ⅳ 흐름 ───── 다크웹 콤보 리스트 확보 → 프록시 IP 로테이션 설정 → 타깃 사이트 로그인 API로 대량 전송 → 성공 계정 선별(Valid Hit) → 포인트 탈취 및 계정 탈취
 ┣━ Ⅴ 비교 ───── 무차별 대입(Brute Force, 단일 계정에 임의 비밀번호 조합 시도) vs 사전 공격(Dictionary Attack) vs 크리덴셜 스터핑(이미 검증된 유출 ID/PW 쌍 대량 투입)
 ┗━ Ⅵ 실무 ───── 정상 사용자 로그인 요청과 봇 트래픽의 구분 난항 / IP 차단 시 분산 프록시 우회 / CAPTCHA 남발에 따른 고객 이탈
```
- 필수 키워드: 크리덴셜 스터핑 · 비밀번호 재사용 · 콤보 리스트(Combo List) · 봇넷(Botnet) · 패스키(Passkey) · 다중 요소 인증(MFA) · 레이트 리미팅(Rate Limiting)
- 기출: 제131회 1교시 10번: "크리덴셜 스터핑(Credential stuffing)"

## 한 줄 본질
- 사용자의 80% 이상이 여러 서비스에서 동일한 ID/비밀번호를 재사용하는 행동적 병목 → 봇 관리(Bot Management)와 유출 자격증명 자동 대조(Have I Been Pwned 연동) 및 패스키를 적용해 탈취 무력화 → 계정 탈취 원천 차단 / 유출 DB 동기화 및 봇 탐지 솔루션 비용 발생

## 핵심 그림
```text
[크리덴셜 스터핑(Credential Stuffing) 공격 체인 및 다층 방어 체계]

[공격자 메커니즘]
  [다크웹 유출 DB] ──> [공격 자동화 도구] ──> [분산 주거용 프록시 (Residential Proxy)]
  (Combo List 수억 건)      (자동 로그인 스크립트)            │ (수만 개 가정용 IP로 분산)
                                                              ▼
                                                   [타깃 서비스 로그인 엔드포인트]
                                                              │
                                                              ▼
[방어 계층: 인라인 봇 관리 및 자격증명 검증]
  1. L7 트래픽 분석: 요청 간격, 마우스 무브먼트 부재, 헤더 비정상 감지 ──> [CAPTCHA / 봇 차단]
  2. 유출 자격증명 검사: 로그인 시 입력된 해시값이 기유출 DB에 존재 시  ──> [비밀번호 강제 재설정]
  3. 무암호 인증: FIDO2 패스키(Passkey) 적용                              ──> [비밀번호 자체 제거!]
```

## 핵심 용어
- 콤보 리스트 (Combo List): 과거 여러 사이트에서 해킹되어 유출된 '이메일:비밀번호' 쌍 수백만~수억 개를 텍스트 형태로 모아 다크웹과 텔레그램에서 유통하는 공격용 데이터베이스
- 주거용 프록시 (Residential Proxy): 전 세계 일반 가정의 인터넷 회선(초고속 인터넷, IoT 기기) IP를 경유하여 공격 트래픽을 전송함으로써, 보안 솔루션의 IP 대역 기반 평판 차단을 무력화하는 기만 기술

## 핵심 통찰
- 크리덴셜 스터핑은 "해킹이 아니라 자동화된 로그인"임 → 시스템의 취약점을 익스플로잇하는 것이 아니라 정상적인 기능을 빠르게 호출하는 것이므로 애플리케이션 레벨의 버그 패치로는 막을 수 없음
- 사용자에게 "특수문자를 포함해 12자리 이상으로 바꾸라"고 강요하는 정책은 문제를 해결하지 못함 → 사용자는 그 복잡한 비밀번호를 다른 사이트에서도 똑같이 복사해 씀
- 궁극의 해결책은 서비스에서 '비밀번호'라는 인증 요소를 아예 없애는 '패스키(FIDO2)'로의 전환임 → 사이트마다 비대칭키 쌍이 완전히 고유하므로 한 곳이 털려도 다른 곳에 대입할 수 없음

## 이웃 토픽과 구분
- 크리덴셜 스터핑 vs 패스워드 스프레잉(Password Spraying): 크리덴셜 스터핑 = 유출된 특정 ID와 그에 매칭된 특정 PW를 1:1로 대입 / 패스워드 스프레잉 = 계정 잠금을 피하기 위해 수천 개의 ID에 흔한 비밀번호 1개(예: `Spring2026!`)만 대입

## 문제·원인·대책
- 사례: 대형 온라인 커머스 플랫폼에서 수십만 건의 계정에 무단 로그인이 발생해 적립금이 무단 결제된 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 대규모 분산 IP를 통한 로그인 무차별 시도로 계정 대량 탈취 | 단일 IP 차단 정책(L4 방화벽)에만 의존 및 분산 봇 탐지 미흡 | WAF 기반 봇 관리(Bot Management) 및 디바이스 핑거프린팅 도입 | 브라우저 환경 및 인간 행동 미보유 봇 트래픽 99% 차단 |
| 유출된 자격증명으로 타 사이트 정상 로그인 성공 | 사용자의 비밀번호 재사용 및 단일 요소 인증(비밀번호만 사용) | MFA(SMS/앱 OTP) 강제 및 기유출 비밀번호 실시간 검증(KISA/HIBP) | 탈취된 ID/PW 대입 성공 시에도 2차 인증에서 차단 |

## 이렇게 출제된다
- 제131회 1교시 10번: "크리덴셜 스터핑(Credential stuffing)" → 요구 포인트: Ⅰ 개념 및 공격 원리 + Ⅲ 공격 흐름 및 봇넷 구조 + Ⅵ 봇 관리 및 패스키 등 방어 대책

## 내 의견
- [로그인 API 엔드포인트의 디바이스 증명(Device Attestation) 의무화] 웹보다 모바일 앱의 백엔드 REST API(`/api/v1/login`)가 WAF 보호를 덜 받아 봇의 주요 타깃이 됨 → 나라면: 모바일 로그인 엔드포인트에 구글 Play Integrity API 또는 애플 App Attest를 연동하여 실제 인가된 순정 앱에서 발생한 요청인지 하드웨어 기반으로 서명 검증하고, 스크립트로 호출되는 모든 다이렉트 API 호출을 원천 드롭
