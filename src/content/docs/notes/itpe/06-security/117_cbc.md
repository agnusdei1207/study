## 답안 골격
```text
[CBC(Cipher Block Chaining)] ◀━━ 머리: Ⅶ 내 의견 (직렬 암호화와 패딩 오라클 한계 극복 → 인증과 병렬 가속을 내장한 AES-GCM(AEAD)으로 전면 교체)
 ┃
 ┣━ Ⅰ 개요 ───── 이전 암호문 블록과 현재 평문 블록을 XOR 연산한 후 대칭키 암호화 함수를 수행함으로써, ECB 모드의 동일 패턴 노출 결함을 완벽히 해결한 대표적 블록 암호 운용 모드
 ┣━ Ⅱ 특징 ───── 초기화 벡터(IV) 필수 · 암호화의 직렬 처리(병렬화 불가) · 복호화의 병렬 처리 지원 · 1비트 오류 발생 시 해당 블록 전체 파괴 및 다음 블록 1비트 전파
 ┣━ Ⅲ 구조 ───── 평문 블록($P_i$) + 이전 암호문 블록($C_{i-1}$) + 초기화 벡터(IV) + 대칭키 암호 엔진($E_K, D_K$) + PKCS#7 패딩
 ┣━ Ⅳ 흐름 ───── [암호화]: $C_1 = E_K(P_1 \oplus IV)$, $C_i = E_K(P_i \oplus C_{i-1})$ / [복호화]: $P_1 = D_K(C_1) \oplus IV$, $P_i = D_K(C_i) \oplus C_{i-1}$
 ┣━ Ⅴ 비교 ───── ECB(블록별 독립 암호화, 패턴 노출) vs CBC(체이닝, 순차 암호화, 패딩 오라클 취약) vs CTR/GCM(스트림 카운터, 고속 병렬 처리, 무결성 인증)
 ┗━ Ⅵ 실무 ───── 고정되거나 예측 가능한 IV 재사용 금지 / 패딩 검증 오류 메시지를 악용한 패딩 오라클 공격 노출 / 무결성(인증) 미보장
```
- 필수 키워드: CBC(Cipher Block Chaining) · 초기화 벡터(IV) · PKCS#7 패딩 · 패딩 오라클(Padding Oracle) · 비트 플리핑(Bit Flipping) · 오류 전파 · AEAD
- 기출: 제127회 4교시 6번: "블록(Block) 암호 모드에 대한..."

## 한 줄 본질
- 동일한 평문 블록이 항상 동일한 암호문으로 변환되는 ECB의 패턴 노출 병목 → 이전 암호문 블록과 현재 평문을 체이닝(XOR)하여 평문의 무작위성을 확산 → 패턴 은닉 확보 / 직렬 연산 병목 및 패딩 오라클 공격에 취약

## 핵심 그림
```text
[CBC(Cipher Block Chaining) 운용 모드의 암호화 및 복호화 메커니즘]

[CBC 암호화 (직렬 연산만 가능)]
  [평문 P1]          [평문 P2]                 [CBC 복호화 (병렬 연산 가능)]
     │                  │                       [암호문 C1]        [암호문 C2]
     ▼                  ▼                           │   ＼             │   ＼
  ┌──┴──┐            ┌──┴──┐                        ▼     ＼           ▼     ＼
  │ XOR │ <─ [IV]    │ XOR │ <── [암호문 C1]     [복호 D_K] ＼      [복호 D_K] ＼
  └──┬──┘            └──┬──┘                        │        ＼        │        ＼
     ▼                  ▼                           ▼          ▼       ▼          ▼
  [암호 E_K]         [암호 E_K]                  ┌──┴──┐    ┌──┴──┐ ┌──┴──┐    ┌──┴──┐
     │                  │                        │ XOR │    │ XOR │ │ XOR │    │ XOR │
     ▼                  ▼                        └──┬──┘    └──┬──┘ └──┬──┘    └──┬──┘
  [암호문 C1]        [암호문 C2]                 <─ [IV]   <─ [C1]   <─ [C1]   <─ [C2]
     │                  │                           ▼                  ▼
     └────── 체이닝 ─────┘                       [평문 P1]          [평문 P2]
```

## 핵심 용어
- 초기화 벡터 (IV, Initialization Vector): 최초의 평문 블록 $P_1$과 XOR 연산하기 위해 사용되는 무작위 블록으로, 동일한 키로 동일한 문서를 다시 암호화해도 완전히 다른 암호문이 나오도록 보장하는 난수
- 패딩 오라클 공격 (Padding Oracle Attack): CBC 모드 복호화 시 수신자가 PKCS#7 패딩 오류 메시지나 응답 시간차를 노출할 경우, 공격자가 암호문 바이트를 1비트씩 조작하며 평문 전체를 역산해 내는 치명적 공격

## 핵심 통찰
- CBC 모드의 암호화는 병렬 처리가 불가능함 → $C_i$를 구하려면 반드시 앞 단계 $C_{i-1}$의 암호화가 끝나야 하므로 최신 멀티코어 CPU나 GPU의 병렬 하드웨어 가속을 활용할 수 없음
- 그러나 복호화는 병렬 처리가 가능함 → 이미 모든 암호문 $C_i$를 수신자가 알고 있으므로 각 블록을 동시에 독립 복호화한 후 이전 암호문과 XOR하면 됨
- 인터넷 보안의 20년을 지배했던 CBC는 '인증(MAC)의 부재'로 인해 종말을 맞이함 → 암호문 자체에 무결성 태그가 없기 때문에 공격자가 암호문을 살짝 뒤틀어 원하는 평문으로 변조(Bit-flipping)하는 것을 막지 못함

## 이웃 토픽과 구분
- CBC vs CTR: CBC = 이전 암호문 블록과 체이닝 결합, 직렬 암호화, 패딩 필수 / CTR = 카운터 값을 암호화하여 평문과 XOR(스트림 암호화), 양방향 완전 병렬 처리, 패딩 불필요

## 문제·원인·대책
- 사례: TLS 통신에서 CBC 모드의 패딩 검증 오류 시간차를 악용해 세션 쿠키를 바이트 단위로 복호화한 POODLE 공격
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 패딩 에러를 관찰하여 평문을 추출하는 패딩 오라클 공격 | CBC 복호화 후 패딩 오류와 MAC 오류 메시지를 차별적으로 노출 | 패딩 연산이 전혀 없는 CTR 모드 기반 AEAD(AES-GCM)로 전면 전환 | 패딩 구조 자체를 제거하여 오라클 공격 원천 무력화 |
| 고정된 IV 사용으로 인한 초기 평문 블록 노출 | 예측 가능한 시퀀스 번호나 상수값을 IV로 재사용 | CSPRNG 기반의 암호학적 난수 IV 매 암호화 시 생성 | 동일 평문이라도 매번 무작위 암호문 생성 보장 |

## 이렇게 출제된다
- 제127회 4교시 6번: "블록 암호 운용 모드 5가지(ECB, CBC, CFB, OFB, CTR)의 특징과 장단점을 비교하고, 최근 널리 활용되는 AEAD 모드에 대하여 설명하시오." → 요구 포인트: Ⅰ CBC 체이닝 수식 + Ⅲ 암복호화 흐름도 + Ⅴ 5대 모드 비교 매트릭스

## 내 의견
- [레거시 CBC 모드의 전사 퇴출 가이드라인 수립] 여전히 많은 엔터프라이즈 레거시 API 및 DB 암호화 솔루션이 기본값으로 `AES/CBC/PKCS5Padding`을 사용하여 잠재적 취약점에 노출되어 있음 → 나라면: 사내 모든 시스템에 대해 CBC 모드 사용을 보안 비권고(Deprecated)로 지정하고, 암호화와 무결성 검증을 1-Pass로 동시 해결하는 `AES-256-GCM`으로의 일괄 전환 프로젝트를 추진
