## 지식 로드맵 내 현재 위치

지식 위치: 대칭키 암호 → 블록 암호 운용 모드 → **CBC**

## 30초 인출

- CBC는 현재 평문 블록과 이전 암호문 블록을 XOR한 뒤 블록 암호로 암호화하는 **기밀성** 모드
- 첫 블록에는 예측 불가능한 IV를 사용. CBC 단독으로는 무결성·출처 인증이 없음
- POODLE은 주로 SSL 3.0의 CBC 패딩 처리 결함을 이용한 공격. 모든 CBC 사용이 같은 취약점이라는 뜻은 아님

## 1교시 예상문제 (10점)

> CBC 모드의 암호화·복호화 구조와 IV의 역할을 설명하시오. (예상·10점)

## 1교시 10점 답안

### Ⅰ. 동작

```text
C₀ = IV
암호화: Cᵢ = Eₖ(Pᵢ ⊕ Cᵢ₋₁)
복호화: Pᵢ = Dₖ(Cᵢ) ⊕ Cᵢ₋₁
```

| 요소 | 역할 |
|---|---|
| IV | 첫 블록의 무작위화; CBC에서는 예측 불가능성 필요 |
| 연쇄 | 동일한 평문 블록도 앞선 암호문에 따라 다른 결과 |
| 패딩 | 블록 크기의 배수가 아닌 입력을 처리; 검증 오류 누출 주의 |

- 제언: 신규 설계에서는 인증 암호(AEAD) 우선 검토.

## 2~4교시 예상문제 (25점)

> CBC 모드의 구조·특성·오류 전파를 설명하고, 패딩 오라클 위험과 안전한 적용 조건을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

### Ⅰ. 개요

CBC(Cipher Block Chaining)는 이전 암호문 블록을 다음 평문 블록과 결합해 암호화하는 블록 암호의 기밀성 운용 모드.

### Ⅱ. 암호화·복호화 흐름

```text
P₁ ─⊕ IV ─Eₖ→ C₁
P₂ ─⊕ C₁ ─Eₖ→ C₂
P₃ ─⊕ C₂ ─Eₖ→ C₃

C₂ ─Dₖ─⊕ C₁ → P₂
```

각 암호문 블록은 앞 블록에 의존하므로 암호화는 연쇄 순서가 필요. 복호화의 블록 암호 연산은 블록별 병렬화 가능.

### Ⅲ. 보안 성질과 오류 영향

| 항목 | 내용 |
|---|---|
| 기밀성 | 올바른 키·IV·패딩·사용 조건 아래 제공 |
| 무결성 | CBC 단독으로 제공하지 않음; 공격자의 암호문 수정 가능 |
| IV | CBC 암호화에서 예측 불가능해야 하며 재사용 위험 관리 |
| 오류 전파 | Cᵢ의 비트 오류는 Pᵢ를 크게 손상하고 Pᵢ₊₁의 대응 비트를 뒤집음 |

### Ⅳ. 패딩 오라클과 POODLE

패딩 검증 결과나 오류 시간 차이가 누출되면 암호문 조작을 반복해 평문 정보를 얻을 수 있음. POODLE은 SSL 3.0 CBC의 패딩 처리 결함에 대한 사례. CBC 자체의 수학적 구조만으로 SSL 3.0의 취약성을 일반화하지 않음.

### Ⅴ. 적용·전환

| 상황 | 대응 |
|---|---|
| 신규 프로토콜 | GCM 등 AEAD 사용 검토 |
| CBC 유지 필요 | 인증 태그를 적절히 결합하고 검증 실패 정보를 노출하지 않음 |
| 레거시 SSL 3.0 | 프로토콜 사용 중단 |
| 운영 검증 | IV 생성·패딩 처리·오류 응답·키 분리 시험 |

### Ⅵ. 기술사적 제언

암호화와 인증의 기능을 분리해 이해하고, 레거시 CBC 구현은 패딩·오류 응답을 점검해 인증 암호로 단계적 전환.
