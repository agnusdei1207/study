## 지식 로드맵 내 현재 위치

정보보안 → 대칭키 암호 → 블록 암호 운용 모드 → CBC(Cipher Block Chaining)

## 30초 인출

- **본질:** 직전 암호문 블록과 현재 평문 블록을 배타적 논리합(XOR)한 후 암호화하여 블록들을 연쇄(Chaining)시키는 운용 모드로, 무작위 초기화 벡터(IV)를 통해 동일 평문의 패턴 노출을 방지하는 대칭 암호 기법.
- **메커니즘:** 암호화 시 $C_i = E_K(P_i \oplus C_{i-1})$ (단, $C_0 = IV$) 연쇄 수행 → 복호화 시 $P_i = D_K(C_i) \oplus C_{i-1}$ 로 역산 (암호화는 순차 처리, 복호화는 병렬 처리 가능).
- 통찰: 무결성 검증 부재로 패딩 오라클(POODLE 등) 및 비트 플리핑 공격에 취약하므로, Encrypt-then-MAC 결합 또는 인증 암호인 AES-GCM(AEAD)으로의 전환 필수.

<details><summary>핵심 용어</summary>

- **CBC(Cipher Block Chaining)**: 이전 블록의 암호화 결과가 다음 블록 암호화에 영향을 미치도록 체인 구조를 형성하는 NIST SP 800-38A 표준 블록 암호 모드.
- **초기화 벡터(IV, Initialization Vector)**: 첫 번째 평문 블록과 XOR 연산되는 난수로, 동일 평문이라도 매 세션마다 다른 암호문을 생성하도록 보장하는 값.
- **오류 전파(Error Propagation)**: 전송 중 암호문 1비트 에러 발생 시 복호화 과정에서 해당 블록 전체가 파괴되고 다음 블록의 동일 비트가 반전되는 특성.
- **패딩 오라클 공격(Padding Oracle Attack)**: 서버가 PKCS#7 패딩 오류를 반환하는 피드백 채널을 악용하여 암호키 없이 평문 바이트를 한 글자씩 복원하는 선택 암호문 공격(CCA).
- **비트 플리핑 공격(Bit-Flipping Attack)**: $C_{i-1}$의 특정 비트를 조작하여 복호화되는 $P_i$의 특정 비트(예: 관리자 권한 플래그)를 공격자가 원하는 값으로 변경하는 공격.
</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 첫 번째 평문 블록은 무작위 초기화 벡터(IV)와 XOR하고, 이후 평문 블록들은 직전 단계의 암호문 블록과 XOR한 후 대칭키 암호화 알고리즘에 입력하는 블록 연쇄 운용 방식 |
| 목적 | ECB(Electronic Codebook) 모드의 치명적 결함인 '동일 평문 블록에 대한 동일 암호문 출력' 패턴 노출을 완전히 제거하여 강력한 기밀성 확보 |

## Ⅱ. CBC 모드의 핵심 특징 및 오류 전파 특성

| 특징 항목 | 세부 동작 내용 | 엔지니어링 및 보안적 의미 |
|---|---|---|
| 연쇄 의존성 (Chaining) | 현재 암호문 $C_i$는 현재 평문뿐만 아니라 $P_1$부터 $P_{i-1}$까지의 모든 이전 평문에 의존 | 데이터의 통계적 패턴 완전 은닉 (IND-CPA 달성) |
| 순차 암호화 (Sequential) | 이전 암호문 $C_{i-1}$이 생성되어야 다음 블록 암호화 가능 | 암호화 연산의 멀티코어 병렬화(Parallelization) 원천 불가 |
| 병렬 복호화 (Parallel) | 수신된 암호문 블록 $C_i$와 $C_{i-1}$만 있으면 즉시 복호화 가능 | 복호화 과정은 멀티스레드/SIMD를 통한 초고속 병렬 처리 가능 |
| 1비트 오류 전파 특성 | 암호문 $C_i$ 전송 중 1비트 반전 시 $P_i$ 블록 전체 파괴 + $P_{i+1}$ 동일 1비트 반전 | 공격자가 특정 평문 비트를 원하는 값으로 조작(비트 플리핑) 가능 |
| 무결성 검증 결여 | 암호문 자체에 대한 인증 태그가 없어 변조 여부 사전 탐지 불가 | 무결성 보장을 위해 별도 MAC 결합 또는 AEAD 필수 |

## Ⅲ. CBC 모드 암호화/복호화 프로세스 아키텍처

```text
[ 1. CBC 암호화 프로세스 (순차적 연쇄) ]
평문 P_1               평문 P_2               평문 P_3
   │                      │                      │
   ▼                      ▼                      ▼
 ( ⊕ ) ◀── 무작위 IV    ( ⊕ ) ◀── [C_1]        ( ⊕ ) ◀── [C_2]
   │                      │                      │
   ▼                      ▼                      ▼
 [ E_K ]                [ E_K ]                [ E_K ]
   │                      │                      │
   ▼                      ▼                      ▼
암호문 C_1 ───────────▶ 암호문 C_2 ───────────▶ 암호문 C_3

[ 2. CBC 복호화 프로세스 (병렬 처리 가능) ]
암호문 C_1             암호문 C_2             암호문 C_3
   │   │                  │   │                  │
   │   ▼                  │   ▼                  ▼
   │ [ D_K ]              │ [ D_K ]            [ D_K ]
   │   │                  │   │                  │
   │   ▼                  │   ▼                  ▼
   │  ( ⊕ ) ◀── IV        │  ( ⊕ ) ◀── [C_1]    ( ⊕ ) ◀── [C_2]
   │   │                  │   │                  │
   │   ▼                  │   ▼                  ▼
   └── 평문 P_1           └── 평문 P_2           └── 평문 P_3
```

| 처리 단계 | 수학적 연산 공식 | 처리 제약 및 특성 |
|---|---|---|
| 첫 블록 암호화 | $C_1 = E_K(P_1 \oplus IV)$ | IV는 반드시 CSPRNG 기반 예측 불가능한 난수여야 함 |
| i번째 블록 암호화 | $C_i = E_K(P_i \oplus C_{i-1})$ | 이전 암호문 $C_{i-1}$ 연산 완료 대기 필수 (파이프라인 지연) |
| 패딩 (Padding) | $P_n$의 부족한 바이트를 PKCS#7 규격으로 채움 | 16바이트 정수배가 아닐 경우 필수 적용 (패딩 오라클 취약점 노출) |
| 첫 블록 복호화 | $P_1 = D_K(C_1) \oplus IV$ | 송신자가 전송한 원본 IV 수신 필수 |
| i번째 블록 복호화 | $P_i = D_K(C_i) \oplus C_{i-1}$ | $C_i$와 $C_{i-1}$만으로 독립 연산 가능 (멀티코어 병렬 복호화) |

## Ⅳ. 주요 블록 암호 운용 모드(ECB vs CBC vs CTR vs GCM) 비교

| 비교 항목 | ECB (Electronic Codebook) | CBC (Cipher Block Chaining) | CTR (Counter Mode) | GCM (Galois/Counter Mode) |
|---|---|---|---|---|
| 연쇄 의존성 | 없음 (독립 블록) | 있음 (직전 암호문 연쇄) | 없음 (카운터 암호화) | 없음 (카운터 암호화) |
| 암호화 병렬화 | 가능 | 불가 (순차 처리) | 가능 (고속 병렬) | 가능 (최고속 병렬) |
| 복호화 병렬화 | 가능 | 가능 | 가능 | 가능 |
| 무작위성 (IV) | 불필요 | 필수 (예측 불가 난수) | 필수 (유일한 Nonce) | 필수 (유일한 Nonce) |
| 패딩 필요 여부 | 필수 (PKCS#7) | 필수 (PKCS#7) | 불필요 (스트림 암호화) | 불필요 (스트림 암호화) |
| 메시지 무결성 | 미제공 | 미제공 | 미제공 | 자체 제공 (AEAD 인증 태그) |
| 주요 취약점 | 패턴 노출 (Penguin) | 패딩 오라클, 비트 플리핑 | Nonce 재사용 시 XOR 누출 | Nonce 재사용 시 인증키 노출 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 서버가 패딩 오류 발생 시 '500 Internal Error' 등 식별 가능한 에러를 반환하여 공격자가 한 바이트씩 평문을 복원(Padding Oracle) | 암호문 복호화 전에 먼저 메시지 인증 코드(MAC)를 검증하는 Encrypt-then-MAC 아키텍처를 적용하거나, 복호화 오류 시 에러 메시지와 처리 시간을 통일(Constant-Time) |
| 공격자가 $C_{i-1}$의 특정 바이트를 변조하여 $P_i$의 중요한 평문 비트(예: `isAdmin=0` -> `isAdmin=1`)를 조작하는 비트 플리핑 취약성 | 전송 구간에 암호화와 무결성/인증을 단일 연산으로 동시에 제공하는 AEAD 모드인 AES-256-GCM 또는 ChaCha20-Poly1305로 전면 교체 |
| 대용량 데이터 암호화 시 앞선 블록의 연산이 끝날 때까지 대기해야 하므로 멀티코어 CPU 및 GPU 가속 활용 불가 | 대용량 트래픽 처리 구간(IPsec, 고속 스토리지)에서는 블록 간 종속성이 전혀 없어 100% 병렬 암·복호화가 가능한 CTR 또는 GCM 모드로 전환 |
| 이전 연결의 마지막 암호문 블록을 다음 세션의 IV로 재사용하거나 예측 가능한 카운터를 IV로 사용하여 CPA 공격에 노출 | 암호학적 난수 생성기(CSPRNG)를 사용하여 매 세션마다 128비트 완전 무작위 IV를 생성하고 재사용 여부를 엄격히 검증 |

| 키 및 IV 거버넌스 | 세션당 단일 IV 사용 원칙 강제 및 FIPS 140-3 검증 난수 생성기 연동 | IV 예측 공격 및 암호문 재전송 공격 완전 무력화 |
