## 연관 키워드

- CBC(Cipher Block Chaining), 초기화 벡터(IV, Initialization Vector), ECB(Electronic Codebook), 블록 연쇄
- PKCS#7 패딩, 패딩 오라클(Padding Oracle), 비트 플리핑, CTR(Counter Mode), GCM(Galois/Counter Mode)
- Encrypt-then-MAC, AEAD(Authenticated Encryption with Associated Data), CSPRNG, 선택 평문 공격(CPA)

## Ⅰ. CBC 운용 모드의 개요

- 핵심 요약 : 각 평문 블록을 직전 암호문 블록과 XOR한 뒤 암호화하여 블록 간 연쇄를 만드는 대칭키 운용 방식.
- 개념 : 첫 평문 블록은 무작위 **초기화 벡터**(IV, Initialization Vector)와 XOR하고, 이후 블록은 직전 암호문 블록과 XOR한 뒤 대칭키 알고리즘으로 암호화하는 **블록 연쇄** 방식(**CBC**, Cipher Block Chaining).
- 배경 및 필요성 : 동일한 평문 블록이 동일한 암호문 블록으로 나와 패턴이 드러나는 **ECB**(Electronic Codebook) 모드의 결함을 해결하기 위해 체이닝 방식이 표준으로 채택됨.
- 주요 목적 : 동일 평문의 반복 패턴 노출을 없애 기밀성을 확보.

## Ⅱ. CBC 운용 모드의 특징 및 장점

- 핵심 요약 : 연쇄 구조가 패턴 노출을 막는 장점을 주지만, 암호화는 순차 처리되고 무결성은 따로 보장해야 하는 특성을 가짐.

1. **블록 연쇄** : 각 암호문이 이전 블록에 의존 → 같은 평문이라도 IV에 따라 다른 암호문 생성, 패턴 노출 차단.
2. **IV 사용** : 매번 무작위 IV를 사용 → 같은 메시지를 여러 번 암호화해도 결과가 달라짐.
3. **복호화 병렬화** : 각 블록의 복호화는 두 암호문 블록만으로 독립 계산 → 다중 코어에서 병렬 복호화 가능.
4. **무결성 미제공** : 암호화만 수행하므로 변조 탐지를 위한 MAC을 별도로 결합해야 함.

## Ⅲ. CBC 운용 모드의 구조 (흐름)

- 핵심 요약 : 암호화는 직전 암호문을 기다리는 순차 구조이고, 복호화는 블록별로 독립 계산이 가능한 구조.

```text
[ CBC 암호화 ]

P1 ⊕ IV (무작위 초기화 벡터)
   ↓
E_K 암호화 → C1
   ↓
P2 ⊕ C1
   ↓
E_K 암호화 → C2
   ↓ (블록 수만큼 반복)
```

```text
[ CBC 복호화 ]

Ci 블록을 D_K로 복호화
   ↓
직전 암호문과 XOR (C1이면 IV)
   ↓
평문 Pi 복원
   ※ 블록별 독립 계산, 병렬 처리 가능
```

- **첫 블록 암호화** : C1 = E_K(P1 ⊕ IV). IV는 예측할 수 없는 난수여야 하며, 암호학적 난수 생성기(CSPRNG, Cryptographically Secure Pseudorandom Number Generator)로 생성함.
- **i번째 블록 암호화** : Ci = E_K(Pi ⊕ Ci-1). 직전 블록 결과가 나와야 계산이 가능함.
- **패딩** : 마지막 블록이 블록 길이에 맞지 않으면 **PKCS#7** 규격으로 채움.
- **복호화** : Pi = D_K(Ci) ⊕ Ci-1 (P1은 IV와 XOR).

## Ⅳ. ECB·CBC·CTR·GCM 운용 모드의 비교

- 핵심 요약 : 연쇄 의존성, 병렬성, 무결성 제공 여부가 모드마다 달라 용도에 맞는 모드를 골라야 함.

| 비교 항목 | ECB | CBC | CTR | GCM |
|---|---|---|---|---|
| 연쇄 의존성 | 없음 | 있음 (직전 암호문) | 없음 (카운터 암호화) | 없음 (카운터 암호화) |
| 암호화 병렬화 | 가능 | 불가 (순차) | 가능 | 가능 |
| 무작위성 요건 | 불필요 | IV 예측 불가 | 유일한 Nonce | 유일한 Nonce |
| 패딩 필요 | 필요 (PKCS#7) | 필요 (PKCS#7) | 불필요 | 불필요 |
| 무결성 제공 | 미제공 | 미제공 | 미제공 | AEAD 인증 태그 제공 |
| 주요 취약점 | 패턴 노출 | 패딩 오라클, 비트 플리핑 | Nonce 재사용 시 키스트림 노출 | Nonce 재사용 시 인증키 노출 |

## Ⅴ. CBC 운용 모드의 한계와 방안

- 핵심 요약 : 패딩 오류 응답, 비트 플리핑, 순차 처리, IV 재사용의 네 가지 한계를 인증 후 복호화, AEAD 전환, 병렬 모드 전환, 난수 관리로 대응.

| 한계 | 원인·영향 | 대응 방안 |
|---|---|---|
| 패딩 오라클 공격 | 패딩 오류가 식별 가능하게 응답되어 공격자가 평문을 바이트 단위로 복원 | 복호화 전에 MAC을 먼저 검증하는 Encrypt-then-MAC 적용, 오류 응답과 처리 시간을 일정하게 유지 |
| 비트 플리핑 | 이전 암호문 변조로 다음 블록 평문의 특정 비트가 조작됨 | 암호화와 무결성을 함께 제공하는 AEAD 모드(AES-256-GCM, ChaCha20-Poly1305)로 전환 |
| 순차 처리에 따른 병렬화 불가 | 블록 간 의존성 때문에 다중 코어와 GPU 가속 활용이 어려움 | 대용량 구간은 CTR 또는 GCM 모드로 전환 |
| IV 재사용·예측 가능 IV | 예측 가능한 IV로 선택 평문 공격(CPA)에 노출 | CSPRNG로 세션마다 무작위 IV를 생성하고 재사용 여부를 검증 |

## Ⅵ. CBC 운용 모드 적용에 대한 기술사적 제언

- 핵심 요약 : 프로토콜 수준에서 CBC 암호군을 퇴출하고, 구현과 키·IV 관리 절차를 함께 정비하는 방향.

레거시 SSL 3.0과 TLS 1.0, 1.1의 CBC 암호군을 차단하고 TLS 1.3 기반 AEAD 암호군으로 단일화하면 POODLE, Lucky 13 같은 패딩 오라클 계열 공격을 구조적으로 막을 수 있다.

암호화 라이브러리를 최신 버전으로 유지하고 하드웨어 AES 가속 명령을 활용하면 성능과 사이드채널 대응을 함께 확보할 수 있다.

키와 IV 관리 기준으로 세션별 단일 IV 사용 원칙을 정하고 검증된 난수 생성기를 연동하는 것이 필요하다.

## Ⅶ. 결론

- 핵심 요약 : CBC는 패턴 노출을 막은 연쇄 모드이지만, 무결성이 없어 단독으로 쓰면 공격에 취약한 모드임.
- 신규 시스템은 인증을 포함한 AEAD 모드를 기본으로 채택하는 것이 바람직함.
