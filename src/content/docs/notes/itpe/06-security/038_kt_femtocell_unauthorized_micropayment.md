## 지식 로드맵 내 현재 위치

정보보호 관리·사고 대응 → 이동통신망 보안 → 불법 펨토셀 침해사고 및 무선 인프라 보호

## 30초 인출

- **본질:** 공통 인증서 관리 부실로 복제된 비인가 소형 기지국(펨토셀)이 통신사 코어망에 무단 접속하여 가입자 통신을 가로채고 소액결제 ARS 인증을 탈취한 대규모 침해사고
- **메커니즘:** 복제 인증서로 IPsec 터널 개설 → 단말 강제 접속 유도(IMSI Catching) → 암호화 해제 다운그레이드 → 결제 인증정보 탈취 → 무단 소액결제 실행
- 통찰: 공통 인증서 복제와 단일 SMS/ARS 인증 취약성을 극복하기 위해 하드웨어 TPM 기반 장비 고유 인증서와 FIDO2 분리 채널 다요소 인증 결합 필수

<details>
<summary>핵심 용어</summary>

- **펨토셀 (Femtocell):** 아파트, 지하 등 음영지역의 통화 품질 개선을 위해 초고속 인터넷망을 백홀로 사용하는 10~20m 반경의 초소형 이동통신 기지국
- **IMSI (International Mobile Subscriber Identity):** USIM 칩에 저장되어 이동통신망이 가입자를 식별하고 위치를 추적하는 국제 고유 식별 번호
- **IMSI Catcher (가짜 기지국):** 정상 기지국보다 강한 전파 신호를 송출하여 인근 단말의 접속을 강제로 유도한 후 통신을 감청하는 무선 공격 장비
- **IPsec 보안 게이트웨이 (SeGW):** 펨토셀과 통신사 코어망 사이의 공중 인터넷 백홀 구간을 암호화 터널로 보호하는 보안 장비
</details>

## 2~4교시 예상문제 (25점)

> KT 불법 펨토셀 침해사고의 공격 경로와 발생 원인을 통신망 아키텍처 관점에서 분석하고, IMSI 탈취 및 무단 소액결제 메커니즘과 통신사·결제사 차원의 재발 방지 엔지니어링 대책을 기술하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **KT 불법 펨토셀 무단 소액결제 사고** 는 공격자가 통신사의 부실한 장비 인증 체계를 악용하여 복제된 비인가 펨토셀을 코어망에 접속시킨 뒤, 인근 가입자 단말의 통신을 가로채 IMSI/IMEI 등 식별정보와 결제 ARS/SMS 인증을 탈취하여 수억 원대의 무단 소액결제를 발생시킨 사이버 침해사고 |
| 목적 | 사고 원인(공통 인증서, 암호화 미적용, 단말 제어 취약성) 분석 및 이동통신 무선망과 결제 인프라의 공급망 보안 대책 수립 |

단말-기지국-코어망에 이르는 텔레콤 인프라의 신뢰 모델이 공격자의 물리적 가짜 기지국 반입으로 붕괴된 대표적 사례.

## Ⅱ. 사고의 핵심 특징 및 공격자 수법

| 특징 구분 | 공격자의 악용 수법 | 통신망 보안 결함 요인 |
|---|---|---|
| **공통 인증서 악용** | 다수 장비에 동일하게 설치된 통신사 사설 인증서를 덤프하여 복제 펨토셀에 탑재 | 장비별 개별 인증서 발급 부재, 인증서 폐기 목록(CRL) 미검증 |
| **전파 세기 조작** | 주변 정상 기지국보다 높은 송출 출력으로 스마트폰의 핸드오버 강제 유도 | 단말의 가장 강한 신호 우선 접속 메커니즘 악용 (IMSI Catcher) |
| **암호화 해제 (다운그레이드)** | 통신 제어 메시지를 무암호(Null Cipher)로 협상하여 음성 및 SMS 평문 수신 | 코어망과의 상호 인증 강제성 결여 및 무선 구간 암호화 누락 |
| **결제 인증정보 가로채기** | 소액결제 시 발생하는 통신사 ARS 전화 및 인증 문자를 불법 펨토셀에서 직접 수신 | 결제 승인 채널과 통신 회선의 일체화(단일 채널 의존) 결함 |

## Ⅲ. 침해사고 공격 아키텍처 및 소액결제 메커니즘

```text
[KT 불법 펨토셀 무단 소액결제 침해사고 공격 흐름도]

 [피해자 단말]                     [불법 복제 펨토셀]               [KT 코어망 / SeGW]
      |                                   |                                |
      |                                   | 1. 복제된 공통 인증서로        |
      |                                   |    IPsec VPN 터널 무단 접속    |
      |                                   | -----------------------------> |
      |                                   | <----------------------------- |
      |                                   |    (비인가 장비 망 접속 성공)  |
      |                                   |                                |
      | 2. 강한 신호 송출로 단말 유인     |                                |
      |    (IMSI Catching 강제 접속)      |                                |
      | <-------------------------------- |                                |
      |                                   |                                |
      | 3. 가입자 식별정보(IMSI/IMEI) 수집|                                |
      | --------------------------------> |                                |
      |                                   |                                |
      |                                   | 4. 공격자가 웹 쇼핑몰에서      |
      |                                   |    피해자 번호로 소액결제 요청 |
      |                                   |    (PG사 -> 통신사 ARS 발신)   |
      |                                   | <----------------------------- |
      |                                   |                                |
      | 5. 결제 ARS/SMS 가로채기          |                                |
      |    (피해자 폰으로 전달 차단)      |                                |
      | 6. 불법 펨토셀에서 인증 완료 응답 |                                |
      | -----------------------------------------------------------------> |
      |    (소액결제 최종 승인 및 현금화 완료)
```

### 1. 단계별 엔지니어링 세부 프로세스

| 단계 | 세부 동작 내용 | 침해된 보안 통제 |
|---|---|---|
| **1. 코어망 침투** | 기지국 인증 서버(SeGW)에 사전 유출된 공통 인증서로 상호 인증 통과 | 장비 식별자-IPsec 인증서 간 1:1 바인딩 부재 |
| **2. 가입자 포섭** | B7(LTE 1.8GHz) 대역에서 고출력 비콘을 방출하여 단말의 재선택 유도 | 단말-기지국 간 상호 인증(Mutual Auth) 미흡 |
| **3. 데이터 탈취** | 단말이 전송하는 초기 접속 메시지(`Attach Request`)에서 IMSI, IMEI 추출 | 평문 무선 구간 스니핑 방지 실패 |
| **4. 결제 인증 탈취** | PG사의 결제 확인 전화(ARS) 착신을 가로채어 DTMF 신호를 인위적으로 입력 | 다요소 인증(MFA) 및 이상금융거래탐지(FDS) 부재 |

## Ⅳ. 정상 펨토셀 vs 불법 악성 펨토셀 비교

| 비교 항목 | 정상 펨토셀 (Normal Femtocell) | 불법 악성 펨토셀 (Rogue Femtocell) |
|---|---|---|
| **망 접속 인증** | 통신사가 직접 관리하는 승인된 인증서 | **사설망에서 불법 추출·복제된 공통 인증서** |
| **설치 위치 검증** | GPS 기반 좌표 및 코어망 기지국 위치 일치 확인 | 위치 검증 우회 (임의의 공격 거점에 설치) |
| **무선 구간 암호화**| LTE 암호화 알고리즘(SNOW 3G, AES) 강제 | **통신 암호화 무력화 및 평문 다운그레이드** |
| **단말 트래픽 처리**| 코어망으로 정상 중계 및 음성/데이터 라우팅 | **IMSI 탈취, 통화 가로채기, SMS/ARS 변조** |
| **관리 가시성** | NMS(망관리시스템) 상에서 정상 등록 및 감시 | NMS 감시 사각지대 존재 또는 비정상 트래픽 미탐 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **장비 전수 동일 공통 사설 인증서 탑재로 인한 인증서 추출 시 전 기지국 복제**<br>유지보수 편의를 위해 수만 대의 펨토셀에 동일한 사설 인증서를 공통으로 탑재하여, 단 1대의 장비 펌웨어 덤프만으로 복제 기지국을 대량 양산 가능 | **하드웨어 보안 칩(TPM/eUICC) 기반 기기 고유 인증서 및 단기 갱신**<br>모든 펨토셀 내부에 하드웨어 보안 모듈(TPM)을 의무 탑재하여 추출 불가능한 개별 고유 개인키를 생성하고, CMP(Certificate Management Protocol)를 통해 유효기간이 30일 이내인 단기 인증서로 자동 갱신 |
| **소액결제 시 통신망 단일 채널(SMS/ARS) 의존으로 인한 무단 승인 취약성**<br>휴대전화 번호와 수신 통화(ARS)만으로 결제가 완결되어, 기지국 레벨에서 통화가 가로채어질 경우 금융/결제사가 이를 탐지할 수 없음 | **Out-of-Band 앱 기반 FIDO2 생체인증 및 FDS 이상 거래 탐지 연동**<br>SMS/ARS 결제 방식을 전면 폐기하고 금융사 전용 앱을 통한 FIDO2 생체인증(Passkey) 채널로 분리하며, 평소 접속 기지국 위치와 결제 요청 위치가 불일치할 경우 결제를 자동 차단하는 통신-금융 연계 FDS 구축 |

## Ⅵ. 제언

```text
[통신-금융 융합 인프라 제로 트러스트 보안 프레임워크]

 +--------------------+     +---------------------+     +--------------------+
 | 1. 장비 하드웨어   | --> | 2. 텔레콤 코어망    | --> | 3. 금융 결제 채널  |
 | TPM 고유 인증서    |     | 펨토셀 GPS 위치검증 |     | FIDO2 Out-of-Band  |
 | 펌웨어 시큐어 부트 |     | 이상 트래픽 DPI 감시|     | 위치 기반 FDS 차단 |
 +--------------------+     +---------------------+     +--------------------+
```

| 대응 계층 | 기술적 통제 조치 | 달성 효과 |
|---|---|---|
| **단말 및 무선망** | 5G-AKA 상호 인증, 기지국 신호 이상 모니터링 | 가짜 기지국(IMSI Catcher) 접속 원천 차단 |
| **코어 및 SeGW** | 기지국 등록 IP-위치-인증서 삼중 바인딩 검증 | 비인가 복제 장비의 망 침투 100% 차단 |
| **결제 및 서비스** | 통신사 ARS 대체 앱 푸시 서명, 통신망 FDS 공유 | 통신망 침해 발생 시에도 금융 자산 보호 |

통신망 침해사고는 단순 IT 침해를 넘어 국가 기간 인프라와 금융 결제망 전체를 마비시킬 수 있으므로, 하드웨어 신뢰점(RoT) 기반 장비 검증과 채널 분리형 다요소 인증 체계 구축 권장.
