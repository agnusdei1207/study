## 지식 로드맵 내 현재 위치

- 정보보안 → 인프라 및 플랫폼 보안 → 클라우드 보안 → 클라우드 컴퓨팅 보안(Cloud Security)

```text
[클라우드 도입 가속화] ──> [책임공유 모델 (Shared Responsibility Model)]
                                  │
                                  ├── IaaS / PaaS / SaaS 계층별 보안 경계 확립
                                  ├── 설정 오류(Misconfiguration) 및 과다 권한(Over-permission) 해소
                                  └── CNAPP 통합: CSPM(형상) + CWPP(워크로드) + CIEM(권한)
                                  │
                                  ▼
                [지속적 클라우드 컴플라이언스 및 제로 트러스트 런타임 방어]
```

---

## 30초 인출

- **본질:** CSP와 이용자 간의 명확한 책임 분계선(Security of the Cloud vs In the Cloud)을 바탕으로 동적 가상화 인프라, 컨테이너 워크로드, API 자산을 보호하는 보안 프레임워크.
- **메커니즘:** 클라우드 IAM 최소 권한 부여 → IaC 배포 파이프라인 정적 보안 검사 → CSPM 설정 드리프트 실시간 감시 → CWPP 런타임 행위 탐지 및 자동 격리.
- **통찰:** 클라우드 침해 사고의 95% 이상이 고객 측 형상 관리 오류(Misconfiguration)에서 기인하므로, 포인트 솔루션 도입을 탈피하여 형상·워크로드·권한을 통합 제어하는 CNAPP 플랫폼 전환 필수.

## 2~4교시 예상문제 (25점)

> 클라우드 서비스 모델(IaaS, PaaS, SaaS)별 책임공유 모델(Shared Responsibility Model)의 보안 경계를 비교하고, 클라우드 네이티브 애플리케이션 보호 플랫폼(CNAPP)의 구성 요소(CSPM, CWPP, CIEM)와 엔터프라이즈 거버넌스 구축 방안을 제시하시오. (25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 클라우드 서비스 제공자(CSP)와 클라우드 이용자 간에 물리 인프라, 플랫폼, 애플리케이션, 데이터의 관리 책임을 분할하여 정의하고 이행하는 종합 보안 체계 |
| 목적 | 클라우드 고유의 탄력성과 민첩성을 저해하지 않으면서 설정 오류(Misconfiguration), 자격증명 유출, 섀도우 IT, 데이터 유출 위험을 원천 예방 |

- 가트너(Gartner)에 따르면 2025년까지 클라우드 보안 사고의 99%는 CSP의 인프라 결함이 아닌 고객의 설정 오류 및 권한 오용에 의해 발생할 것으로 전망됨.

## Ⅱ. 클라우드 보안의 핵심 특징 및 책임공유 모델

### 1. 클라우드 보안의 핵심 특징

| 특징 | 설명 | 기술적 영향 |
|---|---|---|
| 책임공유 원칙 (Shared Responsibility) | 클라우드 자체 보안 vs 클라우드 내부 보안 | CSP는 기반 인프라(하드웨어, 하이퍼바이저)를, 고객은 데이터, IAM, OS 패치를 책임 |
| 소프트웨어 정의 인프라 (IaC) | 코드로 인프라가 배포·변경되는 환경 | 배포 파이프라인 상 정적 검사(IaC Scanning)를 통한 사전 위험 차단 가능 |
| 동적 탄력성과 휘발성 | 컨테이너와 서버리스의 초단기 수명주기 | 전통적인 IP 기반 방화벽 및 에이전트 설치가 무력화되어 API 기반 모니터링 필수 |
| 경계의 탈중앙화 | 사내 인트라넷 경계의 완전한 소멸 | 아이덴티티(Identity)가 새로운 1차 보안 경계(New Perimeter)로 대두 |

  ─────────────────────────────────────────────────────────────────────────────────────────
  데이터 및 자격증명       [고객 책임]       [고객 책임]        [고객 책임]        [고객 책임]

## Ⅲ. 클라우드 서비스 모델별 책임 및 CNAPP 아키텍처

### 1. CNAPP (Cloud Native Application Protection Platform) 통합 아키텍처

```text
+-----------------------------------------------------------------------------------------+
|                                    CNAPP 통합 보안 아키텍처                              |
+-----------------------------------------------------------------------------------------+
  [개발 단계 (Build)]           [배포 단계 (Deploy)]          [운영 단계 (Run)]
  - IaC 소스코드 보안 검사     - 컨테이너 이미지 취약점 스캔   - 런타임 이상 행위 탐지
  - 시크릿(API Key) 스캔       - 쿠버네티스 매니페스트 감사    - 마이크로세그멘테이션
  - CI/CD 파이프라인 OPA 검증   - Admission Controller 검증   - CSPM 설정 드리프트 교정
         │                             │                             │
         ▼                             ▼                             ▼
  ┌─────────────────────────────────────────────────────────────────────────────────────┐
  │                         CNAPP (통합 클라우드 네이티브 보안 플랫폼)                    │
  │  ├── 1. CSPM (형상 관리): AWS/Azure/GCP 설정 오류 및 컴플라이언스 자동 점검         │
  │  ├── 2. CIEM (권한 관리): 과다 권한 IAM 역할 회수, 최소 권한 프로파일 강제          │
  │  └── 3. CWPP (워크로드 보호): VM, 컨테이너, 서버리스 파드 런타임 EDR 및 파일 무결성 │
  └─────────────────────────────────────────────────────────────────────────────────────┘
+-----------------------------------------------------------------------------------------+
```

### 2. 클라우드 주요 위협 벡터 및 방어 대책

| 위협 벡터 | 발생 원인 | 기술적 영향 | 핵심 방어 솔루션 |
|---|---|---|---|
| 클라우드 설정 오류 (Misconfiguration) | S3 버킷 퍼블릭 오픈, 보안그룹 0.0.0.0/0 개방 | 대량의 기업 기밀 데이터 인터넷 무단 노출 | CSPM (실시간 설정 스캔 및 자동 롤백) |
| IAM 과다 권한 및 계정 탈취 | 관리자 권한 남발, 사용되지 않는 휴면 역할 | 공격자의 권한 상승 및 횡적 인프라 장악 | CIEM (IAM 사용률 분석 및 권한 최소화) |
| 공급망 취약점 오염 | 오염된 오픈소스 베이스 이미지 사용 | 컨테이너 내 백도어 및 크립토마이너 실행 | 이미지 서명 검증(Notary), Trivy 취약점 검증 |
| 비인가 API 통신 노출 | 외부 노출된 마이크로서비스 엔드포인트 | BOLA 취약점 및 데이터 무단 덤프 | API Gateway, WAAP, 서비스 메시 mTLS |

## Ⅳ. 클라우드 보안 솔루션(CSPM, CWPP, CIEM, CASB) 비교

### 1. 클라우드 보안 4대 솔루션 비교

| 구분 | CSPM (형상 관리) | CWPP (워크로드 보호) | CIEM (권한 관리) | CASB (SaaS 브로커) |
|---|---|---|---|---|
| 주요 보호 대상 | 클라우드 인프라 설정, 제어 평면 | 가상머신, 컨테이너, 서버리스 | IAM 사용자, 역할, 서비스 계정 | SaaS 서비스 (Office 365, Slack) |
| 동작 계층 | Cloud Control Plane (API) | Data Plane (워크로드 내부) | Identity / IAM 계층 | 네트워크 프록시 및 API 연동 |
| 에이전트 유무 | Agentless (CSP API 연동) | 에이전트 기반 또는 eBPF | Agentless (IAM 분석) | 프록시 모드 / API 연동 모드 |
| 핵심 기능 | CIS 벤치마크 점검, 규정 준수 검증 | 런타임 안티바이러스, EDR, 무결성 | 과다 권한 탐지, 직무 분리 감사 | SaaS DLP, 비인가 파일 업로드 차단 |
| 결합 트렌드 | CNAPP으로 통합 진화 | CNAPP으로 통합 진화 | CNAPP으로 통합 진화 | SASE/SSE 아키텍처로 통합 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| CSPM이 수만 건의 취약점과 설정 오류를 쏟아내어 보안 담당자가 실제 악용 가능한 위협을 식별하지 못하는 알람 피로(Alert Fatigue) 발생 | 공격 그래프(Attack Graph) 기술을 적용하여 인터넷 노출 여부, IAM 권한, 워크로드 취약점을 상호 연관 분석해 침투 경로가 성립하는 고위험군만 우선순위화(Toxic Combinations 분석) |
| 컨테이너의 수명이 수 분~수 시간에 불과하여 전통적인 호스트 에이전트 방식의 무거운 보안 엔진 설치 시 CPU 부하 및 부팅 지연 발생 | 리눅스 커널 레벨에서 시스템 호출(Syscall)을 오버헤드 없이 제로 카피로 감시하는 eBPF(Extended Berkeley Packet Filter) 기반 경량 워크로드 보안 엔진 도입 |
| 멀티 클라우드(AWS, Azure, GCP) 환경에서 벤더별로 IAM 문법, 보안 정책, 로그 포맷이 상이하여 일관된 전사 거버넌스 수립 난항 | Open Policy Agent(OPA) 기반의 Rego 언어로 단일 보안 정책을 표준화하고 멀티 클라우드 통합 대시보드를 제공하는 중앙화된 GRC 플랫폼 구축 |

## Ⅵ. 제언

### 1. DevSecOps 기반 클라우드 보안 시프트 레프트(Shift-Left) 모델

```text
[코드 작성 (IDE)] ──> [Git PR (Checkov)] ──> [CI 파이프라인 (Trivy)] ──> [CD 배포 (OPA)] ──> [런타임 (CNAPP)]
  - 시크릿 하드코딩 탐지  - IaC 정적 린팅       - 컨테이너 이미지 스캔    - 쿠버네티스 승인 통제  - eBPF 실시간 방어
  - 실시간 교정 팁       - 빌드 통과 여부 결정   - CVE 위험도 산정         - 규정 미준수 거부     - 자동 격리 및 롤백
```

### 2. 클라우드 보안 성숙도 모델 비교 평가

| 성숙도 단계 | 주요 특징 | 사용 기술 | 거버넌스 수준 |
|---|---|---|---|
| 1단계: 수동 대응 | 사후 감사, 스프레드시트 점검, 수동 방화벽 | CSP 콘솔 수동 확인 | 단순 규제 대응, 설정 오류 빈발 |
| 2단계: 개별 도구 도입 | CSPM 또는 백신을 독립적으로 운영 | 독립 포인트 솔루션 | 알람 과다 발생, 연관 분석 부재 |
| 3단계: 통합 CNAPP | 형상, 워크로드, 권한의 통합 플랫폼 운영 | CNAPP + CIEM | 위험 우선순위화, 신속한 자동 대응 |
| 4단계: DevSecOps | 파이프라인 상 보안 완전 자동화, Policy as Code | IaC + OPA + eBPF | 보안이 개발 속도를 저해하지 않는 자율 방어 |

- 클라우드 컴퓨팅 보안의 승패는 사후 차단이 아니라 코드 기반 인프라 배포 단계에서 취약점을 사전에 걸러내는 시프트 레프트(Shift-Left)와 런타임 CNAPP의 유기적 결합에 달려 있음.

## 출제 이력과 검증 출처

- 정보관리기술사 121회 2교시 (클라우드 책임공유 모델과 서비스 모델별 보안 통제)

- NIST SP 800-144 Guidelines on Security and Privacy in Public Cloud Computing
- CSA(Cloud Security Alliance) Cloud Controls Matrix (CCM) v4
- Gartner Market Guide for Cloud-Native Application Protection Platforms (CNAPP)
