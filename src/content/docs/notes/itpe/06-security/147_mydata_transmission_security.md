# 마이데이터 전송 보안

## 핵심 개념
- 정보주체의 개인정보 자기결정권 보장을 위해 정보제공자(보유기관)에서 본인 또는 마이데이터 사업자(본인신용정보관리회사 등)로 개인정보를 안전하게 전송하는 체계.
- 데이터 전송 전 주기(요청·인가, 전송 채널, 데이터 보호, 사후 관리)에서 기밀성, 무결성, 부인방지를 달성하기 위해 mTLS, FAPI(Financial-grade API), JWE/JWS 표준 암호 기술을 적용.

```
+-------------------------------------------------------------+
|               마이데이터 전송 보안 4대 영역                    |
+-------------------------------------------------------------+
| 1. 접근 및 인가 통제 | OAuth 2.0 + FAPI 표준, 본인확인 및 서명  |
| 2. 전송 구간 암호화 | 상호 TLS(mTLS 1.2/1.3), 고강도 암호 스위트 |
| 3. 메시지 수준 보호 | 민감정보 필드 암호화(JWE), 위변조 방지(JWS)|
| 4. 감사 및 이상탐지 | 전송 로그 불변 기록, FDS 연계 비정상 트래픽 차단|
+-------------------------------------------------------------+
```

## 핵심 보안 요구사항 및 기술 규격

### 1. 신원확인 및 인가 체계 (Authentication & Authorization)
- **OAuth 2.0 / FAPI(Financial-grade API)**: OpenID Connect 기반 고강도 보안 프로파일 적용.
- **Client Authentication**: 공개키 기반 클라이언트 인증(Mutual TLS Client Authentication 또는 Private Key JWT) 의무화.
- **PKCE(Proof Key for Code Exchange)**: 모바일 앱 환경에서 Authorization Code 가로채기 공격 방지.
- **전자서명 및 부인방지**: 정보주체의 전송요구 의사표시 시 사설인증서 또는 공동인증서 기반 전자서명 생성 및 저장.

### 2. 구간 보안 (Transport Layer Security)
- **상호 인증 TLS(mTLS)**: 정보제공자와 수신자 양단이 공인된 인증서로 상호 신원을 검증하고 전송 구간 암호화.
- **TLS 버전 및 암호 스위트**: TLS 1.3 우선 권고(최소 TLS 1.2 이상), 순방향 비밀성(PFS)을 보장하는 ECDHE-RSA 또는 ECDHE-ECDSA 스위트 필수 적용.
- **취약 스위트 배제**: CBC 모드, RC4, DES, 3DES 및 안전하지 않은 해시(MD5, SHA-1) 사용 금지.

### 3. 메시지 수준 보안 (Application Layer Security)
- **민감정보 개별 암호화**: 계좌 비밀번호, 주민등록번호 등 민감 식별자는 DB 저장뿐만 아니라 API 페이로드 전송 시에도 JWE(JSON Web Encryption)를 적용하여 종단간(E2E) 암호화.
- **페이로드 무결성 보증**: 전송 메시지 위변조 방지를 위해 JWS(JSON Web Signature)를 적용하여 헤더 및 바디 서명.
- **UUID 기반 식별자 치환**: 전송 구간에서 주민등록번호 직접 노출을 배제하고 CI(연계정보) 또는 CI 기반 가상 식별자(UUID) 사용.

### 4. 사후 관리 및 이상징후 모니터링
- **전송 이력 로깅**: 전송 일시, 요청 기관, 전송 데이터 항목, 정보주체 식별자를 불변 로그로 5년간 보관.
- **FDS(이상금융거래탐지시스템) 연동**: 단시간 내 대량 API 호출, 심야 시간대 비정상적 전송 요구, 비인가 IP 접근 탐지 및 자동 차단.

## 전송 방식 비교: 스크래핑 vs API 전송

| 비교 항목 | 화면 스크래핑(Screen Scraping) | 마이데이터 표준 API |
|---|---|---|
| **인증 정보 취급** | 이용자의 공인인증서·비밀번호를 제3자 서버에 저장 | 인가 토큰(OAuth 2.0 Access Token)만 발급받아 사용 |
| **보안 통제력** | 데이터 소유 기관의 통제 불가, 과도한 트래픽 부하 | API Gateway를 통한 트래픽 제어(Rate Limiting), mTLS 상호인증 |
| **전송 무결성** | UI 변경 시 데이터 파싱 오류 발생 | 표준 규격(JSON/REST) 및 JWS 서명으로 무결성 보장 |
| **법적 적합성** | 접근권한 남용 및 정보 유출 위험(금지 권고) | 개인정보보호법 및 신용정보법 상 전송요구권 적법 이행 |

## 결론 및 실무 시사점
- 마이데이터 전송 보안은 기존의 스크래핑 방식에서 발생하던 비밀번호 탈취 위험을 근본적으로 해소하고, 권한 최소화(Least Privilege) 원칙을 수립.
- 향후 전송요구권이 의료·통신·유통 등 전 산업 분야로 확대됨에 따라 이기종 산업 간 상호호환성 확보와 제로 트러스트 기반 지속적 권한 검증 체계 구축이 핵심 과제임.
