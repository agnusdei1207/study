## 30초 인출

- **본질:** 마이데이터 전송 보안은 본인의 데이터 전송 요구를 확인하고 허가된 수신자에게 필요한 데이터만 안전하게 전달하는 통제.
- **메커니즘:** 본인 확인·전송 동의 → 수신자 인가 → API 전송 → 전송 이력 관리.
- **핵심:** 동의 범위와 API 권한의 일치, 전송 구간과 데이터의 보호, 사후 추적.

<details>
<summary>핵심 용어</summary>

- **마이데이터 전송 보안**: 정보주체의 전송 요구에 따라 개인정보·신용정보를 허가된 수신자에게 전달할 때 적용하는 신원·권한·전송·감사 통제.
- **전송요구권**: 정보주체가 자신에 관한 정보를 지정한 수신자에게 전송하도록 요구하는 권리.
- **OAuth 2.0**: 이용자의 비밀번호를 수신자에게 주지 않고 범위가 제한된 접근 권한을 위임하는 프레임워크.
- **FAPI(Financial-grade API)**: 민감한 정보를 다루는 API에 적용하는 OAuth 기반 고보안 프로파일.
- **mTLS(mutual Transport Layer Security)**: 클라이언트와 서버가 서로 인증서를 확인하는 TLS 방식.
- **DPoP(Demonstrating Proof of Possession)**: 클라이언트가 토큰 사용 시 보유한 키를 증명해 토큰 탈취 후 재사용을 줄이는 방식.

## 2~4교시 25점 답안

## Ⅰ. 마이데이터 전송 보안의 정의와 목적

| 구분 | 내용 |
|---|---|
| 정의 | **마이데이터 전송 보안**은 본인의 전송 요구를 확인하고 허가된 수신자에게 필요한 데이터만 안전하게 전달하는 통제 |
| 목적 | 정보주체의 권리 보장과 전송 데이터의 기밀성·무결성·추적성 확보 |

보안의 기준은 암호기술의 나열보다 본인이 지정한 수신자·항목·기간과 실제 전송의 일치 여부.

## Ⅱ. 전송 주체와 절차

```text
정보주체 ─ 전송 대상·수신자 지정
    ↓ 본인 확인·동의 범위 검증
인가된 수신자 ─ 권한·토큰 검증
    ↓ 보호된 API 요청
정보보유자 ─ 허용된 항목만 전송
    ↓
전송 이력·이상 징후 관리
```

| 주체 | 역할 | 검증할 내용 |
|---|---|---|
| 정보주체 | 전송 요구·동의 | 본인 의사와 대상 범위 |
| 수신자 | 인가된 API 요청 | 클라이언트 신원·권한 |
| 정보보유자 | 허용 데이터 제공 | 토큰과 요청 항목의 일치 |

## Ⅲ. 인증·인가와 데이터 범위 통제

```text
전송 요구 범위
  ├─ 수신자 ─ 등록·인증된 기관
  ├─ 항목 ─ 요청한 데이터만
  ├─ 목적·기간 ─ 허용 범위 안에서 사용
  └─ 철회 ─ 후속 접근 차단
```

| 공격·오류 | 대응 |
|---|---|
| 다른 이용자의 데이터 접근 | 본인·토큰·자원 식별자 결합 검증 |
| 토큰 탈취·재사용 | 짧은 유효기간, 송신자 구속 토큰 등 |
| 과다 전송 | 동의 항목과 응답 필드의 대조 |
| 수신자 사칭 | 클라이언트 인증과 등록 정보 확인 |

FAPI 2.0은 고가치 API의 송신자 구속 토큰에 mTLS 또는 DPoP를 사용할 수 있도록 규정. 특정 마이데이터 분야에서 어느 프로파일과 방식이 의무인지 별도 운영 기준 확인 필요.

## Ⅳ. 전송·감사 통제

```text
API 요청 수신
    ↓ 상대·토큰·범위 검증
허용 항목 추출
    ↓ 전송 구간 보호
응답 제공
    ↓
요청·응답 이력과 이상 징후 추적
```

구간 보호, 메시지 서명·암호화, 전송 이력 보존은 적용 분야의 규정과 위협 모델에 맞춰 선택. 모든 전송에 JWE·JWS·특정 TLS 버전을 일률적으로 필수라 단정하지 않음.

| 확인 대상 | 점검 기준 |
|---|---|
| 구간 | 종단·인증서·암호 설정 |
| 메시지 | 필요한 기밀성·무결성 수준 |
| 기록 | 요청 주체·수신자·항목·시각·결과 |
| 이상 징후 | 대량 요청·반복 실패·철회 후 접근 |

## Ⅴ. 한계와 제언

| 한계 | 대응 |
|---|---|
| API가 안전해도 동의 범위보다 넓은 데이터를 보내면 권리 침해 | 요구·토큰 권한·응답 항목을 같은 데이터 항목 사전으로 연결하고 불일치 요청 차단 |
| 수신자와 보유자 사이에서 책임 구간이 흐려질 수 있음 | 인가·전송·철회·사고 대응의 담당 기관과 증적을 단계별로 지정 |
