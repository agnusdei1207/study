정보보안 → 침해사고 대응 및 디지털 증거 분석 → **디지털 포렌식(Digital Forensics)**

## 30초 인출

- 본질: **디지털 포렌식 (Digital Forensics)** : 전자적 증거물(Digital Evidence)이 사법 기관과 법정에서 법적 증거능력(Admissibility)을 인정받을 수 있도록 과학적이고 체계적인 절차에 따라 수집, 보존, 분석, 보고하는 컴퓨터 법과학 기술
- 메커니즘: 포렌식 5대 기본 원칙(정당성, 재현성, 신속성, 연계보관성, 무결성) 준수 → 휘발성 순서(RFC 3227)에 따른 메모리 선행 수집 → 하드웨어 쓰기방지 장치 기반 사본 이미징 → 타임라인 아티팩트 분석
- 통찰: 강제 전원 차단 시 파일리스 악성코드 및 RAM 상주 암호키 영구 소실과 클라우드 물리 디스크 접근 불가 한계 극복을 위해 라이브 메모리 덤프 선행과 CSP 볼륨 스냅샷 파이프라인 연계 필수

<details>
<summary>핵심 용어</summary>

- **연계보관성 (Chain of Custody)** : 증거물이 최초 획득된 순간부터 법정에 제출될 때까지 증거의 취급자, 보관 장소, 인계 시간, 이동 목적을 빈틈없이 기록하여 위변조가 없었음을 입증하는 관리 체계
- **무결성 (Integrity)** : 증거 수집 시점의 원본 해시값(SHA-256)과 분석 시점의 사본 해시값이 100% 동일함을 증명하여 데이터 변조가 없음을 보장하는 특성
- **쓰기 방지 장치 (Write Blocker)** : 원본 저장매체를 분석 시스템에 연결할 때 읽기 전용으로만 마운트하여 수집 과정 중 원본 데이터의 1비트 변경도 물리적으로 차단하는 하드웨어 장치
- **비트스트림 이미지 (Bit-stream Image)** : 단순 파일 복사가 아니라 삭제된 영역(Unallocated Space)과 슬랙 공간(Slack Space)까지 포함하여 섹터 단위로 1:1 완벽 복제한 포렌식 이미지 (E01, RAW)
- **휘발성 순서 (Order of Volatility)** : RFC 3227에 규정된 원칙으로, 전원 차단이나 시간 경과에 따라 가장 빠르게 소멸하는 데이터부터 우선순위를 두고 수집하는 절차

</details>

## 2~4교시 25점 답안

## Ⅰ. 디지털 포렌식의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | PC, 서버, 모바일, 네트워크, 클라우드 등 디지털 매체에 잔존하는 전자적 증거물을 수집·보존·분석하여 범죄 사실이나 보안 침해사고의 원인을 과학적으로 규명하고 법적 증거력을 부여하는 법과학 기술 |
| 목적 | 내부 횡령, 기밀 유출, 랜섬웨어 침해사고 등 사이버 범죄의 행위자를 특정하고, 사법 절차에서 위법수집증거 배제 원칙을 통과하는 완벽한 법적 증거능력 확보 |

## Ⅱ. 디지털 포렌식의 특징 및 5대 기본 원칙

| 기본 원칙 | 핵심 개념 | 사법적 의미 및 엔지니어링 특징 |
|---|---|---|
| **1. 정당성의 원칙** | 적법 절차 준수 | 영장주의 및 형사소송법에 의거하여 적법하게 획득된 증거만 채택 (위법수집증거배제) |
| **2. 재현성의 원칙** | 동일 결과 도출 | 동일한 조건과 도구를 사용하여 동일한 분석 절차를 밟을 경우 언제나 동일한 결과 도출 |
| **3. 신속성의 원칙** | 시간 지연 방지 | 전원 차단 및 시간 경과에 따른 휘발성 데이터(RAM, 로그)의 영구 소멸 전 신속 수집 |
| **4. 연계보관성의 원칙**| 이력 추적성 유지 | 획득부터 법정 제출까지 증거의 소지자, 이동 경로, 보관 장소를 연속적 서면 기록 (**Chain of Custody**) |
| **5. 무결성의 원칙** | 데이터 불변성 증명 | 수집 시점의 원본 해시값(SHA-256)과 분석에 사용된 사본 해시값의 완전 일치 검증 |

## Ⅲ. 디지털 포렌식 증거 수집·분석 절차 및 휘발성 순서

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ 디지털 포렌식 표준 수행 프로세스 및 휘발성 순서 ]   │
│                                                                        │
│   [침해사고 인지 및 현장 보존] ── (전원 차단 절대 금지!)                │
│          │                                                             │
│          ▼ [1단계: 라이브 포렌식 (RFC 3227 휘발성 순서 수집)]          │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ ① CPU 레지스터, 캐시 메모리 수집                              │   │
│   │ ② 물리 RAM 메모리 덤프 (LiME / WinPmem) -> 활성 연결/프로세스 │   │
│   │ ③ 네트워크 소켓, 커널 라우팅 테이블, 열린 파일 디스크립터     │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   │                                    │
│                                   ▼ [2단계: 데드 포렌식 (저장매체 이미징)]│
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ 하드웨어 쓰기방지 장치(Write Blocker) 연결                     │   │
│   │ 비트스트림 사본(Bit-stream Image, .E01) 획득 및 SHA-256 해시 검증│ │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   │ 원본 금고 봉인 (사본으로만 분석)   │
│                                   ▼ [3단계: 포렌식 심층 분석]          │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ 프리페치(Prefetch), 쉼(Shimcache), 레지스트리, MFT 타임라인 분석│   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   │                                    │
│                                   ▼ [4단계: 증거 보고서 작성 및 법정 증언]│
│                     [ 신뢰할 수 있는 법적 증거 완성 ]                  │
└────────────────────────────────────────────────────────────────────────┘
```

| 절차 단계 | 주요 작업 내용 | 필수 산출물 및 엔지니어링 통제 |
|---|---|---|
| **1. 증거 획득 (Acquisition)**| 휘발성 메모리 덤프 선행 수집 및 비트스트림 디스크 이미징 | RAM 덤프 파일, E01 이미지, 쓰기방지 확인서 |
| **2. 증거 보존 (Preservation)**| 원본 매체를 정전기 방지 백에 밀봉하고 증거물 관리 대장 기록 | Chain of Custody 서식, 원본 및 사본 해시 대조표 |
| **3. 증거 분석 (Analysis)** | 타임스탬프 기반 사건 타임라인 재구성, 삭제 파일 카빙(Carving) | 분석 로그, 아티팩트 추출 목록, 타임라인 차트 |
| **4. 결과 보고 (Reporting)** | 객관적 사실과 분석관의 전문 의견을 명확히 구분하여 서술 | 최종 디지털 포렌식 감정 보고서 |

## Ⅳ. 라이브 포렌식(Live) vs 정적 포렌식(Dead) 비교

| 비교 항목 | 라이브 포렌식 (Live Forensics) | 정적 포렌식 (Dead / Post-mortem Forensics) |
|---|---|---|
| **수행 시점** | **시스템이 가동(Powered-on) 중인 상태에서 즉시 수집** | **시스템 전원을 완전히 끈 상태에서 수집 (사후)** |
| **수집 대상** | **RAM 메모리, 실행 중인 악성 프로세스, 네트워크 연결** | **SSD, HDD, USB 등 비휘발성 보조기억장치 전체** |
| **장점** | 파일리스 악성코드, 암호화 볼륨 마운트 키, 실시간 세션 획득 | 원본 데이터 훼손 위험 극소화, 표준화된 절차 확립 |
| **위험 및 단점** | 명령어 실행 시 메모리 상태 일부 변조 위험 (발자국 남김) | **전원 차단 즉시 RAM 내 모든 핵심 증거 영구 소멸** |
| **대표 도구** | Volatility, Rekall, LiME, FTK Imager Lite | EnCase, Autopsy, X-Ways Forensics, dd |

## Ⅴ. 디지털 포렌식 수행 시 핵심 엔지니어링 한계와 방안

| 한계 | 방안 |
|---|---|
| 침해사고 현장에서 초동 대응자가 관행적으로 서버 전원 코드를 뽑아버려(Cold Boot) RAM에만 상주하는 파일리스(Fileless) 인메모리 악성코드, 인젝션된 쉘코드, 비트라커(BitLocker) 복호화 마스터 키가 영구 소멸 | 사고 대응 지침(SOP)을 개정하여 전원 차단을 엄격히 금지하고, 사전에 무결성이 검증된 포렌식 전용 USB를 장착하여 RAM 덤프(WinPmem, LiME)를 최우선 생성한 후 시스템을 안전 격리하는 휘발성 우선 수집 절차 의무화 |
| 멀티테넌트 퍼블릭 클라우드(AWS, Azure) 환경에서는 물리 하이퍼바이저 및 디스크 섀시에 직접 접근할 수 없으며, 인스턴스 정지/종료 시 임시(Ephemeral) 디스크 데이터가 즉시 삭제되는 물리적 수집 불가능 한계 봉착 | 클라우드 전용 침해사고 대응 파이프라인을 구축하여, 이상 탐지 즉시 클라우드 API를 통해 가상 머신 메모리 덤프를 생성하고 EBS/디스크 볼륨 스냅샷을 즉시 트리거하여 포렌식 전용 격리 VPC로 사본 마운트 분석 체계 적용 |
| 공격자가 안티 포렌식(Anti-Forensics) 기술을 사용하여 타임스탬프를 조작하는 타임스톰프(Timestomp) 공격을 감행하거나 미할당 영역 와이핑(Wiping)을 수행하여 침투 경로를 은닉 | 파일 시스템의 `$STANDARD_INFORMATION` 속성과 `$FILE_NAME` 속성의 타임스탬프 불일치를 교차 분석하여 조작을 적발하고, 마스터 파일 테이블($MFT) 레코드와 USN 저널($UsnJrnl), 윈도우 이벤트 로그를 상호 대조하여 실제 파일 수정 시간 완벽 복원 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
기업 내 디지털 포렌식 역량 내재화 시, 사고 발생 후 대응하는 수동적 사후 분석에 그치지 않고 평상시에 전사 엔드포인트에서 프로세스 생성, 네트워크 소켓 연결, 파일 해시를 실시간 수집 및 중앙 저장하는 EDR(Endpoint Detection & Response) 및 엔터프라이즈 포렌식 준비도(Forensic Readiness) 체계 수립 권장

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│               [ 클라우드 환경 서버리스 자동화 포렌식 아키텍처 ]         │
│                                                                        │
│   [침해 의심 인스턴스 (EC2 / VM)]                                      │
│          │                                                             │
│          ▼ 1. GuardDuty 이상 징후 탐지 알람 발생                        │

│   │  - 2. 네트워크 격리 (모든 인바운드/아웃바운드 차단 보안그룹 교체)│   │
│   │  - 3. EC2 콘솔 API 호출: 인스턴스 메모리 덤프(RAM) 즉시 생성   │   │

│                                   │ 사본 스냅샷 전송                   │
│                                   ▼                                    │

│   │            격리된 포렌식 분석 VPC (Forensics Workstation)      │   │
│   │  - 스냅샷으로부터 신규 읽기 전용 볼륨 복원 마운트              │   │
│   │  - Volatility 메모리 프로파일링 및 Plaso 타임라인 자동 추출    │   │
│   └────────────────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 포렌식 분야 | 주요 분석 대상 | 핵심 수집 아티팩트 | 주 활용 도구 |
|---|---|---|---|
| **디스크 포렌식** | 파일 시스템, 파티션 테이블 | $MFT, Prefetch, Registry, LNK 파일 | EnCase, Autopsy, FTK |
| **메모리 포렌식** | 물리/가상 RAM 메모리 | 실행 중인 은닉 프로세스, 네트워크 세션, VAD 트리 | Volatility 3, Rekall, LiME |
| **네트워크 포렌식**| 인라인 패킷, NetFlow | 전체 패킷 캡처(PCAP), TLS 세션 키, DNS 질의 | Wireshark, Zeek, Suricata |
| **클라우드 포렌식**| 클라우드 인프라 감사 로그 | CloudTrail, VPC Flow Logs, 볼륨 스냅샷 | Athena, AWS CISO-IR, Plaso |
