## 지식 로드맵 내 현재 위치

사이버위험 관리 → 공격 노출의 반복 개선 → 지속적 위협 노출 관리(CTEM)

## 30초 인출

- **본질:** 취약점 수치(CVSS) 중심의 단편적 패치 방식을 탈피하여, 비즈니스 핵심 자산에 도달 가능한 공격 경로와 노출을 5단계 사이클로 지속 평가·검증·교정하는 방어 프레임워크
- **메커니즘:** 비즈니스 범위 설정(Scoping) → 다차원 자산 탐색(Discovery) → 위협 맥락 기반 우선순위화(Prioritization) → 공격 가능성 검증(Validation) → 조직적 조치 동원(Mobilization)
- 통찰: 단순 CVSS 기반의 무차별적 패치 지연을 극복하기 위해 실제 공격 도달 경로와 무기화된 악용 정황을 기준으로 검증된 고위험 노출에 조치 역량을 집중하는 동적 거버넌스 체계 필수

<details><summary>핵심 용어</summary>

- **CTEM(Continuous Threat Exposure Management):** 가트너가 제안한 프로그램으로, 조직의 디지털 자산 노출 위험을 지속적으로 축소하기 위한 5단계 반복 관리 모델.
- **공격 경로 분석(Attack Path Analysis):** 자산 간 연결성, 계정 권한, 네트워크 방화벽 규칙을 분석하여 공격자가 핵심 자산에 도달 가능한 경로를 가시화하는 기법.
- **EPSS(Exploit Prediction Scoring System):** 공개된 취약점(CVE)이 향후 30일 이내에 실제 야생(In-the-wild)에서 악용될 확률을 추정하는 머신러닝 점수 모델.
- **CISA KEV(Known Exploited Vulnerabilities):** 공격자에 의해 실제 사이버 침해 공격에 무기화되어 악용되고 있음이 입증된 취약점 공인 카탈로그.
- **BAS(Breach and Attack Simulation):** 사이버 킬체인 및 MITRE ATT&CK 기반 모의 공격을 자동 수행하여 보안 통제의 방어 유효성을 입증하는 도구.

</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 공격자가 악용 가능한 조직의 디지털 자산, 취약점, 잘못된 설정을 비즈니스 위험 관점에서 식별·우선순위화·검증하여 지속적으로 조치하는 일련의 5단계 보안 운영 체계 |
| 목적 | 수많은 취약점 중 실제 침해로 이어지는 공격 경로를 선별 무력화하고, 보안 투자와 운영 조직 간 협업을 정렬하여 공격 표면 최소화 |

## Ⅱ. CTEM의 주요 특징

| 특징 | 세부 내용 | 구현 요소 |
|---|---|---|
| 비즈니스 중심 평가 | 인프라 관점이 아닌 핵심 비즈니스 서비스 및 디지털 자산의 영향도 우선 고려 | 비즈니스 영향 분석(BIA), 자산 중요도 매핑 |
| 지속적 순환 관리 | 연 1~2회 일회성 진단이 아닌 365일 상시 가동되는 폐루프(Closed-loop) 사이클 | 상시 EASM, 실시간 위협 인텔리전스 |
| 공격자 관점 검증 | 취약점 존재 여부 확인을 넘어 공격자가 실제로 침투 가능한지 모의 공격으로 입증 | BAS, 자동화 침투 테스트(Pen-Testing) |
| 조직 간 동원(Mobilization) | 보안팀의 일방적 패치 요구를 지양하고 IT·개발·운영팀과의 조치 워크플로우 통합 | ITSM 티켓팅 자동 연계, 사전 검증된 교정 스크립트 |

## Ⅲ. CTEM 5단계 아키텍처 및 세부 프로세스

```text
┌────────────────────────────────────────────────────────┐
│ 1. 범위 설정 (Scoping)                                 │
│    - 중요 비즈니스 서비스, 외부 노출 자산, 평가 목표 정의│
└────────────────────────┬───────────────────────────────┘
                         ▼
┌────────────────────────────────────────────────────────┐
│ 2. 자산 탐색 (Discovery)                               │
│    - EASM(외부 표면) + CAASM(내부 자산) + 코드/클라우드 │
└────────────────────────┬───────────────────────────────┘
                         ▼
┌────────────────────────────────────────────────────────┐
│ 3. 우선순위화 (Prioritization)                         │
│    - 자산 중요도 + CVSS 심각도 + EPSS 악용 확률 + KEV  │
└────────────────────────┬───────────────────────────────┘
                         ▼
┌────────────────────────────────────────────────────────┐
│ 4. 유효성 검증 (Validation)                            │
│    - BAS 기반 모의 공격 + 공격 경로(Attack Path) 시뮬레이션│
└────────────────────────┬───────────────────────────────┘
                         ▼
┌────────────────────────────────────────────────────────┐
│ 5. 조치 동원 (Mobilization)                            │
│    - SecOps-DevOps 협업 + 패치/보완 통제 + 결과 피드백  │
└────────────────────────┴───────────────────────────────┘
                         │ (다음 순환 주기로 피드백)
                         └───────────────────────────────▶
```

| 단계 | 주요 활동 내용 | 적용 기술 및 도구 |
|---|---|---|
| 1. Scoping (범위 설정) | 비즈니스 가치가 높은 핵심 시스템, 고객 데이터 저장소, 공급망 접점 정의 | 비즈니스 영향 평가(BIA), 자산 분류표 |
| 2. Discovery (자산 탐색) | 공격 표면에 노출된 서버, 오픈 포트, 인증서, 잘못된 클라우드 설정 탐지 | EASM, CAASM, CSPM, 소스코드 SAST |
| 3. Prioritization (우선순위화) | 침해 발생 시 비즈니스 피해 규모와 실제 익스플로잇 가능성 종합 산출 | CVSS v4.0, FIRST EPSS, CISA KEV |
| 4. Validation (공격 검증) | 공격자가 해당 노출을 악용하여 내부 횡적 이동이 가능한지 모의 공격 수행 | BAS(침해 시뮬레이션), 침투 테스팅 도구 |
| 5. Mobilization (조치 동원) | 패치 적용, 방화벽 차단 룰 추가, 계정 권한 회수 등 협업 조치 이행 | ITSM(Jira/ServiceNow), SOAR 플레이북 |

## Ⅳ. 전통적 취약점 관리(RBVM)와 지속적 위협 노출 관리(CTEM) 비교

| 구분 | 전통적 취약점 관리 (RBVM) | 지속적 위협 노출 관리 (CTEM) |
|---|---|---|
| 통제 대상 | 소프트웨어 CVE 취약점 중심 | CVE + 클라우드 설정 오류 + 계정 권한(IAM) + 서드파티 노출 |
| 우선순위 기준 | CVSS 기본 점수 (Base Score) 중심 | 비즈니스 맥락 + 실시간 악용 정황(EPSS/KEV) + 공격 경로 |
| 검증 방식 | 취약점 스캐너의 정적 시그니처 매칭 | BAS 및 시뮬레이션을 통한 공격 성공 여부 실증 |
| 운영 주기 | 월간/분기별 정기 스캔 및 보고서 발행 | 상시 지속적 탐색 및 이벤트 기반 즉시 검증 |
| 조치 방식 | IT 부서에 수천 건의 패치 권고 전달 | 검증된 고위험 경로에 대한 부서 간 협업 및 대체 통제 적용 |

## Ⅴ. CTEM 도입 및 운영의 한계와 방안

| 한계 | 방안 |
|---|---|
| 하이브리드 멀티클라우드 환경에서 섀도우 IT 및 단절된 사일로로 인한 비즈니스 자산 스코핑(Scoping) 누락 | CSPM, CIEM, SaaS API를 상시 수집하는 CAASM 그래프 데이터베이스 구축 및 자산 연관관계 실시간 토폴로지 자동 갱신 |
| 발견된 수천 개의 노출에 대해 개발 및 운영 현업 부서가 운영 안정성을 이유로 패치를 거부하거나 지연(Mobilization 병목) | CVSS 외에 실시간 무기화 여부(KEV)와 가용 공격 경로를 시각화하여 설득 논리를 확보하고, WAF/가상패치 등 대체 보완 통제 병행 |
| 실서버 환경에서 BAS 공격 시뮬레이션(Validation) 수행 시 시스템 다운타임 및 서비스 장애 유발 리스크 | 프로덕션 미러링 환경 및 카나리 워크로드 기반 시뮬레이션 격리 수행, 비파괴적(Non-destructive) 검증 프로토콜 적용 |

## Ⅵ. 제언

```text
[ 기존 취약점 관리의 한계 ]             [ CTEM 기반 능동적 노출 제어 ]
수만 건의 CVE 취약점 ──┐               ┌── 비즈니스 맥락 기반 고위험 노출 선별
단순 CVSS 9.0+ 집착 ──┼─→ [ 조치 지연 ] ─┼── BAS 공격 경로 실증으로 신뢰성 확보
현업 개발팀과 마찰 ────┘               └── SecOps-DevOps 자동화 조치 파이프라인
```

| 평가 영역 | 전통적 취약점 관리 | CTEM 적용 체계 | 향후 발전 방향 |
|---|---|---|---|
| 조치 집중도 | 모든 고위험 CVE 대상 분산 | 실제 악용 가능 경로에 집중 | AI 기반 익스플로잇 가능성 자율 예측 |
| 조직 간 협업 | 보안팀의 일방적 조치 지시 | 공유된 위험 지표 기반 협업 | 플랫폼 엔지니어링 및 GitOps 자동 패치 연계 |
| 침해 예방률 | 미패치 제로데이 침투 노출 | 공격 경로 사전 차단으로 무력화 | 제로 트러스트 아키텍처(ZTA) 정책 자동 동기화 |

CTEM은 끝없는 패치 피로감에서 벗어나 실제 비즈니스에 치명적인 침투 경로를 선별 차단하는 현대 보안 운영의 표준 프레임워크이며, Gartner가 강조하듯 2026년 이후 사이버 복원력의 핵심 척도로 정착될 것임.
