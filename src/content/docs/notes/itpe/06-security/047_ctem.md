## Ⅰ. 지속적 위협 노출 관리(CTEM)의 개요

- **개념** : 조직의 공격 표면(Attack Surface) 전반에 존재하는 취약점, 설정 오류, 자격증명 노출 등 잠재적 보안 위험을 단순히 식별하는 데 그치지 않고, 공격자의 실제 악용 가능성(Exploitability)과 비즈니스 영향도를 검증하여 우선순위화하고 지속적으로 완화하는 5단계 순환형 보안 관리 프레임워크.
- **배경 및 필요성** : 가트너(Gartner)가 제시한 핵심 보안 트렌드로, 매년 수만 개의 CVE 취약점이 쏟아져 모든 결함을 패치하는 것이 불가능한 상황에서 '실제 침투 가능한 경로'만을 선별 집중 타격하기 위해 출현.
- **핵심 목적** : 취약점 조치의 우선순위 최적화, 보안 피로도(Alert Fatigue) 해소, 조직의 공격 노출 지수(Exposure Index) 지속 감축 및 침해 위험 최소화.

## Ⅱ. 지속적 위협 노출 관리(CTEM)의 핵심 아키텍처 및 동작 메커니즘

CTEM은 범위 설정(Scoping) -> 발견(Discovery) -> 우선순위화(Prioritization) -> 유효성 검증(Validation) -> 조치 동원(Mobilization)의 5단계 폐루프(Continuous Loop)로 반복 수행됨.

```text
[ 지속적 위협 노출 관리(CTEM) 5단계 순환 프레임워크 ]

       +-------------------------------------------------------+
       | 1. 범위 설정 (Scoping) : 비즈니스 핵심 자산 및 경계 정의 |
       +---------------------------┬---------------------------+
                                   │
                                   ▼
       +-------------------------------------------------------+
       | 2. 발견 (Discovery)    : 내·외부 공격표면, 취약점, 계정 탐지|
       +---------------------------┬---------------------------+
                                   │
                                   ▼
       +-------------------------------------------------------+
       | 3. 우선순위화 (Prioritize) : CTI, EPSS, 공격 경로 분석 |
       +---------------------------┬---------------------------+
                                   │
                                   ▼
       +-------------------------------------------------------+
       | 4. 유효성 검증 (Validation) : BAS, 모의침투로 실제 악용 입증|
       +---------------------------┬---------------------------+
                                   │
                                   ▼
       +-------------------------------------------------------+
       | 5. 조치 동원 (Mobilization) : 가상패치, 패치, 프로세스 개선|
       +---------------------------┬---------------------------+
                                   │ (피드백을 통한 지속적 반복)
                                   └───────────────────────────>
```

- **1단계: 범위 설정(Scoping)** : 모든 자산이 아닌 비즈니스 가치가 높은 핵심 인프라, SaaS, 공급망 파트너를 집중 관리 범위로 정의.
- **2단계: 발견(Discovery)** : EASM(외부공격표면), CAASM(사이버자산), 취약점 스캐너를 통해 숨겨진 섀도우 IT와 미관리 노출 자산 전수 발굴.
- **3단계: 우선순위화(Prioritization)** : CVSS 점수뿐 아니라 실제 악용 확률 지표인 EPSS(Exploit Prediction Scoring System)와 CTI를 결합하여 실제 침해 가능한 소수 취약점 선별.
- **4단계: 유효성 검증(Validation)** : 침해·공격 시뮬레이션(BAS)과 자동화된 침투 테스트를 통해 공격자가 실제로 방어벽을 뚫을 수 있는지 실증.
- **5단계: 조치 동원(Mobilization)** : 보안팀과 IT 개발·운영팀이 협업하여 패치, 가상 패치(WAF 룰), 또는 세그멘테이션 격리를 신속하게 실행.

## Ⅲ. 지속적 위협 노출 관리(CTEM)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 전통적 취약점 관리 (VM) | 공격표면관리 (ASM) | 지속적 위협 노출 관리 (CTEM) |
| --- | --- | --- | --- |
| 관리 범위 | 알려진 내부 서버 및 SW 취약점(CVE) | 인터넷에 노출된 외부 자산 및 포트 | 내·외부 자산, SaaS, 클라우드, 계정 권한 전반 |
| 평가 기준 | 단순 CVSS 심각도 점수 (CVSS 7.0 이상) | 자산의 외부 노출 여부 및 개방성 | 실제 악용 가능성(EPSS), 공격 경로, 비즈니스 가치 |
| 검증 방식 | 스캐너 기반 단순 시그니처 매칭 | 외부 네트워크 핑/포트 프로빙 | BAS(공격 시뮬레이션)를 통한 실효성 검증 |
| 수행 주기 | 분기별 또는 연간 1회 정기 진단 | 지속적 외부 스캐닝 | 5단계 폐루프의 상시 지속적 순환 운영 |
| 최종 산출물 | 방대한 분량의 취약점 나열 보고서 | 외부 노출 자산 인벤토리 목록 | 검증된 고위험 경로에 대한 즉각적 완화 조치 |

- 전통적 취약점 관리가 '패치해야 할 결함 목록'을 끝없이 던져주어 개발팀을 지치게 했다면, CTEM은 '지금 당장 공격자가 뚫고 들어올 수 있는 단 3개의 경로'를 검증하여 집중 해결하도록 유도함.

## Ⅳ. 지속적 위협 노출 관리(CTEM)의 주요 한계점 및 해결 방안

- **보안팀과 IT 운영/개발팀 간의 협업 마찰(조치 동원의 병목)** :
  - **한계점** : 보안팀이 우선순위를 지정해도 운영팀의 서비스 안정성 우려나 개발 일정 충돌로 인해 실제 패치가 이행되지 않는 문화적 단절.
  - **해결 방안** : Jira, ServiceNow 등 IT 서비스 관리 도구와 CTEM을 API로 연동하고, 미조치 시 경영진 승인 예외 처리를 요구하는 거버넌스 수립.
- **공격 경로 그래프(Attack Path) 연산의 복잡도 급증** :
  - **한계점** : 멀티 클라우드와 다수의 엔드포인트가 얽힌 복잡한 환경에서 방대한 잠재적 공격 경로를 그래프로 분석할 때 시스템 성능 병목.
  - **해결 방안** : 그래프 데이터베이스(Neo4j 등) 기반 클라우드 보안 태세 관리(CSPM) 및 Choke Point(핵심 경유점) 중심의 경로 압축 알고리즘 적용.
- **외부 침투 테스트 도구의 비즈니스 트래픽 간섭 우려** :
  - **한계점** : 4단계 검증(Validation) 과정에서 자동화 공격 도구가 운영 DB에 비정상 쿼리를 전송하여 서비스 중단 발생 위험.
  - **해결 방안** : 안전성이 검증된 BAS 프레임워크를 사용하고, 공격 페이로드를 실행하지 않고 방화벽 통과 여부만 확인하는 안전 모드(Safe Mode) 검증.

## Ⅴ. 지속적 위협 노출 관리(CTEM) 적용 및 발전을 위한 기술사적 제언

- **EPSS(Exploit Prediction Scoring System) 지표의 전사 채택** : 정적 CVSS 점수 대신, 향후 30일 이내에 실제 공격에 악용될 확률을 통계적으로 산출하는 EPSS를 패치 우선순위 기준으로 도입.
- **CTEM 거버넌스 협의체 구성** : 보안팀, 클라우드 엔지니어링팀, 인프라 운영팀이 매월 합동 회의를 열어 검증된 Top 5 노출 위험에 대해 일괄 조치 합의.
- **가상 패칭(Virtual Patching)을 통한 선제 조치 가속화** : 코드 수정과 재배포에 수주가 소요되는 경우 WAF, API 게이트웨이, EDR에서 선제적 가상 차단 룰을 24시간 내 배포하는 체계 확립.
