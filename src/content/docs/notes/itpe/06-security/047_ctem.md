## 답안 골격
```text
[CTEM] ◀━━ 머리: Ⅶ 내 의견 (단순 취약점 스캔 탈피 → 공격자 관점 5단계 순환 주기 기반 악용 가능 노출점 우선 조치)
 ┃
 ┣━ Ⅰ 개요 ───── 폭증하는 CVE 취약점 전수 조치 한계 → 실제 공격 가능성과 비즈니스 위험도를 기준으로 노출점을 지속 평가·개선하는 가트너 5단계 프레임워크
 ┣━ Ⅱ 특징 ───── 상시 순환 주기(Continuous Cycle) · 공격자 관점 우선순위화 · 악용 가능성 실증(Validation) · 조직 위험 완화 중심
 ┣━ Ⅲ 구조 ───── 범위설정(Scoping) · 발견(Discovery) · 우선순위화(Prioritization) · 검증(Validation) · 조치(Mobilization)
 ┣━ Ⅳ 흐름 ───── ① 대상 자산/공격표면 범위 정의 → ② 취약점/잘못된 설정 발견 → ③ 위험도 정량 평가 → ④ BAS 공격 시뮬레이션 검증 → ⑤ 조직 협업 조치
 ┣━ Ⅴ 비교 ───── 전통 취약점 관리(Vulnerability Management: 연/분기 1회 스캔, CVSS 단순 나열) vs CTEM(상시 순환, 공격자 관점 실증 검증, 비즈니스 맥락 우선순위)
 ┗━ Ⅵ 실무 ───── 취약점 데이터 사일로 현상 / 개발-보안 부서 간 조치 지연 / CVSS 점수 의존 탈피 및 EPSS 도입
```
- 필수 키워드: CTEM · 5단계 사이클(Scoping, Discovery, Prioritization, Validation, Mobilization) · 공격표면 · 악용 가능성 · BAS · CVSS/EPSS
- 기출: 139회 1교시 11번 `CTEM(Continuous Threat Exposure Management)` → Ⅰ 정의 + Ⅲ 5단계 프레임워크 + Ⅵ 효과

## 한 줄 본질
- 수천 개의 소프트웨어 취약점을 모두 패치할 수 없는 운영 리소스의 한계 병목 → 비즈니스 중요도와 실제 공격자의 침투 경로 검증을 거쳐 5단계 순환 주기로 실행 가능한 노출점만 선별 조치 → 침해 가능성 급감 / 상시 검증 도구 운영 및 부서 협업 비용 발생

## 핵심 그림
```text
[가트너 CTEM(지속적 위협노출관리) 5단계 순환 프레임워크]

               ┌────────────────────────┐
               │ 1. 범위 설정 (Scoping)  │
               │  - 핵심 비즈니스 자산  │
               └───────────┬────────────┘
                           ▼
               ┌────────────────────────┐
               │ 2. 발견 (Discovery)    │
               │  - 자산/취약점/설정오류│
               └───────────┬────────────┘
                           ▼
  ┌──────────> ┌────────────────────────┐
  │            │ 3. 우선순위화          │
  │            │  - CVSS + EPSS + 위협  │
  │            └───────────┬────────────┘
  │                        ▼
  │            ┌────────────────────────┐
  │            │ 4. 검증 (Validation)   │
  │            │  - BAS 공격 시뮬레이션 │
  │            └───────────┬────────────┘
  │                        ▼
  │            ┌────────────────────────┐
  │            │ 5. 조치 (Mobilization) │ ───┐
  │            │  - 패치/보상통제/협업  │    │
  │            └────────────────────────┘    │
  └──────────────────(지속적 개선 선순환)─────┘
```

## 핵심 용어
- EPSS(Exploit Prediction Scoring System): 특정 취약점(CVE)이 향후 30일 이내에 실제 야생(In-the-wild)에서 악용될 확률을 0~1 사이로 예측하는 정량 모델
- BAS(Breach and Attack Simulation): 침해 공격 시뮬레이션을 통해 식별된 취약점이 실제 침투 경로로 이어지는지 자동으로 실증하는 기술

## 핵심 통찰
- 취약점의 80% 이상은 실제 공격에서 전혀 쓰이지 않거나 도달 불가능함 → CVSS 9점 이상만 쫓아다니면 운영팀은 패치 과로로 지치고 정작 공격자는 7점짜리 결합 체인으로 침투함
- CTEM 4단계 '검증(Validation)'이 빠지면 이전의 취약점 스캐너와 다를 바 없음 → 공격 시뮬레이션을 통해 방화벽이나 WAF가 막아주고 있는지를 입증해야 불필요한 긴급 패치 부하를 제거
- 5단계 '조치(Mobilization)'는 패치만이 답이 아님 → 패치가 불가능한 레거시는 WAF 룰 적용, 네트워크 격리, 접근통제 강화 등 보상 통제(Compensating Control)로 위험 수준 완화

## 이웃 토픽과 구분
- 취약점 관리(VM) vs CTEM: VM = 발견된 소프트웨어 버그 패치 중심 / CTEM = 계정 탈취, 잘못된 설정, 공급망 노출까지 포괄한 비즈니스 위험 관리

## 문제·원인·대책
- 사례: 수만 개의 취약점 보고서가 쌓여 보안팀과 개발팀 간 우선순위 갈등으로 중요 패치가 수개월간 지연된 사례
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 수천 개의 High/Critical 취약점 보고서로 인한 조치 불능 | CVSS 기본 점수에만 의존한 일률적 조치 요구 | EPSS 및 실제 외부 노출 여부(Reachable) 결합 필터링 적용 | 실제 조치 대상 취약점을 상위 5% 이내로 압축 |
| 레거시 시스템 패치 적용 시 서비스 장애 발생 우려 | 구형 운영체제 및 단종 라이브러리로 패치 파일 부재 | 가상 패치(Virtual Patching) 및 제로트러스트 마이크로세그멘테이션 격리 | 무중단 상태에서 악용 시도 차단 |

## 이렇게 출제된다
- 제139회 1교시 11번: "CTEM(Continuous Threat Exposure Management)" → 요구 포인트: Ⅰ 개념 및 등장 배경 + Ⅲ 5단계 프레임워크 세부 내용 + Ⅵ 기대 효과

## 내 의견
- [조치(Mobilization) 없는 발견 도구의 범람] 기업들이 EASM, CAASM, 취약점 스캐너를 경쟁적으로 사들이지만 조치 담당 부서(인프라·개발팀)와의 티켓 연동이 없어 노출점 수치만 올라가는 모순 발생 → 나라면: CTEM 플랫폼을 Jira 및 ITSM 파이프라인과 직접 연동하고, 검증된 침투 경로가 확인된 노출점에 한해 자동으로 SLA(서비스수준협약) 티켓을 발행하여 72시간 내 조치율을 경영진 KPI에 반영

## 찾아볼 것
- CISA KEV(Known Exploited Vulnerabilities) 카탈로그와 조직 CTEM 파이프라인 통합
