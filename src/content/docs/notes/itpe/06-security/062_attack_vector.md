## 연관 키워드

- 공격 벡터, Attack Vector, 초기 접근, 공격 표면, 공격 경로
- 워터링 홀, 피싱 프록시, AitM, 제로데이, 공급망
- 횡적 이동, RASP, 가상 패치, ZTNA, EASM, CAASM

## Ⅰ. 공격 벡터의 개요

- 핵심 요약 : 공격자가 보안 통제를 우회해 시스템에 발을 들이는 구체적인 침투 수단과 진입 경로.
- 개념 : 공격자가 목표 시스템의 보안 통제를 우회하여 **초기 접근** (Initial Access) 지점을 확보하거나 악성 페이로드를 전달하기 위해 악용하는 구체적인 침투 수단 및 진입 경로.
- 배경 및 필요성 : 클라우드 전환, 원격 근무 확산, 서드파티 공급망 연계로 경계 기반 보안이 약해지면서 침투 경로가 다변화됨 → 진입 표면을 입체적으로 파악하고 벡터별 방어선을 설계하는 체계적 식별 체계가 필요해짐.
- 주요 목적 : 침투 벡터별 선제 방어 통제를 수립하고, 침투 시도 단계에서 조기 차단하여 내부 인프라로의 확산을 막음.

## Ⅱ. 공격 벡터의 특징 및 장점

- 핵심 요약 : 침투 수단을 유형별로 분류하고 공격 표면, 공격 경로와 구분하여 관리하는 방식이 방어 투자의 우선순위와 차단 지점을 명확하게 함.

1. 벡터 단위 분류 : 이메일·웹, 공개 서비스, 자격증명, 공급망, 물리 매체로 나눠 관리 → 통제 대상이 명확해져 방어 투자 우선순위 결정.
2. 표면과 수단의 분리 : 노출 면적(공격 표면)과 침투 수단(벡터)을 구분해 진단 → 노출 축소와 진입 차단을 각각 설계.
3. 경로 연계 분석 : 벡터가 이어지는 공격 경로로 시야를 넓힘 → 횡적 이동을 끊을 지점을 식별.

## Ⅲ. 공격 벡터의 구조 (흐름)

- 핵심 요약 : 4종의 진입 벡터가 각기 다른 입구로 침투한 뒤, 초기 접근 이후에는 권한 상승과 횡적 이동의 공통 흐름을 따르는 구조.

1. **피싱 프록시** (AitM, Adversary-in-the-Middle) 및 이메일·웹 : 스피어 피싱, 악성 매크로 첨부파일, **워터링 홀** (Watering Hole) 공격으로 악성코드 다운로드와 계정 탈취.
2. 공개 서비스 결함 : SQL 삽입(SQLi, SQL Injection), 원격 코드 실행(RCE, Remote Code Execution), 미패치 CVE(Common Vulnerabilities and Exposures), 클라우드 설정 오류로 웹셸 업로드와 서버 권한 탈취.
3. 인증 자격증명 : 유출 계정 대입, VPN(Virtual Private Network)과 RDP(Remote Desktop Protocol) 무차별 대입으로 내부망 원격 침투.
4. 공급망 : 오픈소스 라이브러리 의존성 오염, 벤더 소프트웨어 변조 (SolarWinds, Log4j 사태가 대표 사례).
5. 물리 및 이동매체 : 감염된 USB(Universal Serial Bus)를 통한 배드USB 공격과 비인가 물리 접근으로 폐쇄망 악성코드 유입 (Stuxnet 사례).

```text
[ 진입 벡터 4종 ]

1. 이메일·웹 → 사용자 단말
2. 공개 서비스 → DMZ 서버
3. 원격 접속 자격증명 → 게이트웨이
4. 소프트웨어 공급망 → 빌드 시스템
```

```text
[ 초기 침투 이후의 흐름 ]

초기 접근 (Initial Access, 내부 거점 확보)
      ↓ 권한 상승
내부 권한 확보 (Privilege Escalation)
      ↓ 횡적 이동
내부 자산 확산 (Lateral Movement)
```

## Ⅳ. 공격 표면, 공격 벡터, 공격 경로의 비교

- 핵심 요약 : 공격 표면은 노출된 면적, 공격 벡터는 침투 수단, 공격 경로는 침투부터 목표까지의 연결을 가리켜 방어 지점을 구분하는 기준.

| 구분 | 공격 표면 (Attack Surface) | 공격 벡터 (Attack Vector) | 공격 경로 (Attack Path) |
| --- | --- | --- | --- |
| 개념적 정의 | 공격자가 접촉할 수 있는 노출 접점의 총합 | 침투를 실행하는 구체적 수단과 경로 | 초기 침투부터 최종 목표 자산까지의 연결 |
| 관점 | 면적, 정적 상태 | 방향, 침투 수단 | 선, 동적 연쇄 흐름 |
| 예시 | 공개된 포트, 원격 VPN 접점, 직원 이메일 | 취약한 웹 서비스 익스플로잇, 피싱 메일 | 피싱 메일 → 단말 장악 → 자격증명 탈취 → 도메인 컨트롤러 장악 |
| 통제 목표 | 불필요 자산 폐쇄로 면적 최소화 | 방화벽, 백신, WAF(Web Application Firewall)로 진입 차단 | 마이크로 세그먼테이션으로 이동 차단 |
| 분석 도구 | EASM(External Attack Surface Management), CAASM(Cyber Asset Attack Surface Management) | EDR(Endpoint Detection and Response), 이메일 보안 게이트웨이 | BAS(Breach and Attack Simulation), 공격 경로 분석 도구 |

## Ⅴ. 공격 벡터의 한계와 방안

- 핵심 요약 : 딥페이크 기반 사칭, 제로데이, 정상 계정 악용이라는 벡터의 진화를 피싱 저항 인증, 런타임 보호, 제로트러스트 접근으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| AI(Artificial Intelligence) 기반 사칭과 피싱 프록시 (AitM) | 딥페이크 음성과 영상으로 SMS·OTP와 교육 중심 방어가 약화 | 세션 탈취에 강한 FIDO2/WebAuthn 기반 패스키 의무화, 이메일 수신단의 문맥 분석 도입 | 피싱 저항 인증 적용률 |
| **제로데이** (0-Day) 익스플로잇 | 정적 시그니처 기반 IPS(Intrusion Prevention System)와 WAF가 알려지지 않은 공격을 막지 못함 | **RASP** (Runtime Application Self-Protection)를 탑재해 악성 행위 시 시스템 호출 차단, **가상 패치** (Virtual Patching) 즉시 배포 | 가상 패치 적용 소요 시간 |
| 정상 계정과 정상 프로토콜의 악용 | 탈취된 VPN·RDP 계정이 정상 경로로 유입되어 경계 방화벽이 탐지하지 못함 | 기기 무결성과 접속 맥락(위치, 시간, 행위)을 실시간 평가하는 **ZTNA** (Zero Trust Network Access) 전환 | 맥락 기반 차단 건수 |

## Ⅵ. 공격 벡터에 대한 기술사적 제언

- 핵심 요약 : 벡터별 통제 책임을 명확히 하고, 공격 표면 관리와 경로 분석을 진입 차단으로 연결하는 운영 방향.

1. 조직은 진입 벡터별 통제 책임자를 지정하고, 벡터 단위의 점검 항목을 정기 보안 점검에 포함하는 체계를 마련할 필요가 있음.
2. 원격 접속과 공급망 보안은 별도 기준으로 관리하여, 소프트웨어 의존성 검증과 접속 기기 평가가 함께 이뤄지도록 하는 것이 바람직함.
3. EASM으로 파악한 노출 자산과 공격 경로 분석 결과를 연계하여, 벡터 점검이 실제 침투 경로 차단으로 이어지도록 운영할 필요가 있음.

## Ⅶ. 결론

- 핵심 요약 : 공격 벡터는 공격자가 실제로 들어오는 수단이며, 이를 표면과 경로로부터 구분해 관리하는 것이 방어의 출발점.
- 시사점 : 진입 수단은 계속 바뀌므로 특정 기술보다 벡터별 통제 체계의 주기적 갱신이 방어의 지속성을 좌우함.
