## 답안 골격
```text
[TTPs] ◀━━ 머리: Ⅶ 내 의견 (단순 침해지표(IoC) 차단 탈피 → 침해 피라미드 최상위 TTPs 기반 위협 프로파일링 및 능동 방어)
 ┃
 ┣━ Ⅰ 개요 ───── IP/해시값 등 단순 침해지표(IoC)의 잦은 변경으로 인한 방어 한계 → 공격자의 행동 양식(전술·기법·절차)을 체계화한 위협 분석 프레임워크
 ┣━ Ⅱ 특징 ───── 계층적 추상화(전술 > 기법 > 절차) · 공격자 프로파일링 · MITRE ATT&CK 매핑 · 방어 회피 불가능성(공격자 변경 비용 극대화)
 ┣━ Ⅲ 구조 ───── 전술(Tactics, 공격 목적) · 기법(Techniques, 수행 수단) · 절차(Procedures, 구체적 실행 명령어/시나리오)
 ┣━ Ⅳ 흐름 ───── ① 침해 로그/행위 수집 → ② MITRE ATT&CK 기법 분류 → ③ 공격 그룹(APT) 프로파일링 매핑 → ④ 취약 경로 선제 방어 및 탐지 룰(Sigma) 생성
 ┣━ Ⅴ 비교 ───── 하위 침해지표(Hash, IP, Domain: 도구 변경으로 쉽게 우회) vs 최상위 지표 TTPs(공격자의 습관과 프로세스로 변경 비용 극대)
 ┗━ Ⅵ 실무 ───── TTPs 추출의 고도 분석 인력 의존성 / 방대한 ATT&CK 매트릭스 분류 부담 / EDR 및 위협 헌팅 도구와의 자동 연계
```

## 한 줄 본질
- IP나 해시값만 차단하면 공격자가 1초 만에 인프라를 바꿔 우회하는 악순환 병목 → 공격자의 근본적인 공격 목적(전술), 기술 수단(기법), 실행 단계(절차)를 분석하여 공격 행위 자체를 무력화 → 공격자의 공격 비용 극대화 / 고도의 행위 분석 역량 및 상관분석 인프라 비용 발생

```text

                     ▲  [ TTPs (전술·기법·절차) ]  ◀── 공격자에게 극도의 고통!
                    / \   - 방어자가 TTPs를 무력화하면
                   /   \    공격자는 공격 습관 전체를 바꿔야 함
                  / 도구 \  - 도구 (Mimikatz, Cobalt Strike 등)
                 / 네트워크\ - 네트워크/호스트 아티팩트 (C2 도메인)
                / 도메인 이름\
               /  IP 주소    \  - IP 주소 (VPN, 프록시로 쉽게 변경)
              /   해시 값     \ - 해시 값 (1비트만 바꿔도 무력화)
             ─────────────────── ◀── 공격자에게 사소한 비용 (Trivial)
```

## 핵심 용어
- 침통의 피라미드(Pyramid of Pain): David Bianco가 제안한 위협 지표 모델로, 피라미드 상단(TTPs)으로 갈수록 방어자가 탐지했을 때 공격자에게 가해지는 비용과 고통이 기하급수적으로 커짐을 도식화
- MITRE ATT&CK: 실제 공격 사례를 바탕으로 사이버 공격자의 전술(Tactics), 기법(Techniques), 하위기법을 체계화한 전 세계 표준 지식베이스

## 핵심 통찰
- 방화벽에서 악성 IP 1,000개를 차단하는 것은 방어자의 자기만족일 뿐 공격자는 5분 만에 클라우드 새 IP를 할당받음
- 공격자의 본질은 '도구'가 아니라 '습관(TTPs)'임 → 특정 APT 그룹은 항상 특정 방식으로 권한을 상승시키고 측면 이동을 수행하므로 TTPs를 알면 도구가 바뀌어도 동일 공격 그룹 식별 가능
- TTPs 관제의 핵심은 EDR/SIEM 규칙을 정적 시그니처가 아닌 '행위(Behavior)' 기반으로 작성하는 것임 (예: `cmd.exe`가 `powershell.exe`를 실행하고 LSASS 메모리를 덤프하는 행위 탐지)

## 이웃 토픽과 구분
- IoC vs TTPs: IoC(침해지표) = 사건의 결과로 남은 파편(IP, 파일 해시, 도메인) / TTPs = 사건을 일으킨 공격자의 행동 양식과 실행 절차

## 문제·원인·대책
- 사례: C2 서버 IP와 악성코드 해시값을 차단했으나 공격자가 악성코드를 재컴파일하고 도메인을 변경해 지속적으로 내부망을 유린한 사례
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 정적 IoC 차단 후 신종 변종 악성코드에 재침해 | 해시값 기반 차단은 1바이트 코드 변경 시 탐지 실패 | MITRE ATT&CK 기법 기반의 행위 탐지 룰(Sigma/YARA-L) 도입 | 파일 변조와 무관하게 동일 공격 행위(TTPs) 지속 차단 |
| 공격자의 내부 침투 후 측면 이동 식별 지연 | 단일 장비 이벤트만 감시하고 다단계 절차 상관성 미분석 | TTPs 시나리오 기반 위협 헌팅(Threat Hunting) 및 XDR 상관분석 | 정상 도구 악용(LotL) 공격의 다단계 킬체인 조기 적발 |
