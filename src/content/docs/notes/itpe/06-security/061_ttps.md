## 지식 로드맵 내 현재 위치

위협정보 분석 → 공격 행위 모델링 → TTPs와 MITRE ATT&CK 프레임워크

## 30초 인출

- **본질:** 사이버 공격자의 공격 목적(전술), 구현 방식(기법), 구체적 실행 절차(절차)를 구조화하여 공격자의 행동 양식을 분석하고 방어 체계를 수립하는 행위 기반 위협 인텔리전스(CTI) 개념
- **메커니즘:** 침해 로그 수집 → MITRE ATT&CK 전술/기법 매핑 → 구체적 공격 절차(TTPs) 식별 → Sigma/YARA 기반 행위 탐지 룰 생성 → 능동적 위협 헌팅 및 방어선 보강
- 통찰: IP, 해시 등 하위 침해지표는 공격자가 즉시 변경 가능하므로, 고통의 피라미드 최상위인 TTPs 수준에서 행동 패턴을 모델링하고 실시간 행위 기반 탐지 및 위협 헌팅 체계 구축 필수

<details><summary>핵심 용어</summary>

- **TTPs:** 전술(Tactics), 기법(Techniques), 절차(Procedures)의 약칭으로 공격자의 공격 수명주기 전반의 행동 패턴을 의미.
- **전술 (Tactics, Why):** 공격자가 특정 행동을 수행하는 전술적 목표나 이유(예: 초기 접근, 권한 상승, 방어 회피).
- **기법 (Techniques, How):** 전술적 목표를 달성하기 위해 사용하는 일반화된 기술적 방법(예: 프로세스 인젝션, 피싱).
- **절차 (Procedures, What):** 특정 공격 그룹(APT)이 실제로 구동한 도구, 스크립트, 구체적 명령어 실행 이력.
- **MITRE ATT&CK:** 실제 관측된 사이버 공격자의 행동을 14개 전술과 수백 개 기법/하위기법으로 체계화한 지식베이스.
- **고통의 피라미드 (Pyramid of Pain):** 데이비드 비앙코가 제안한 위협 지표 계층 모델로, TTPs는 방어 시 공격자에게 가장 큰 타격과 비용을 주는 최상위 계층.

</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 공격자가 사이버 공격 목표를 달성하기 위해 사용하는 전술(Tactics, 목적), 기법(Techniques, 수단), 절차(Procedures, 실행 도구/명령어)의 복합적 행동 패턴 체계 |
| 목적 | IP, 해시 등 쉽게 변조되는 단편적 지표를 넘어 공격자의 본질적 공격 행위 패턴을 식별·차단함으로써 공격자의 침투 비용을 극대화하고 사전 예방 역량 확보 |

## Ⅱ. TTPs의 계층적 구성요소 및 특징

| 구성요소 | 핵심 질문 | 세부 정의 | 대표 예시 |
|---|---|---|---|
| 전술 (Tactics) | WHY (목적) | 공격자가 달성하고자 하는 궁극적 단계별 목표 | 정찰, 초기 침투, 권한 상승, 방어 회피, 유출 |
| 기법 (Techniques) | HOW (방식) | 해당 전술적 목표를 실행하기 위한 기술적 공격 메커니즘 | 스피어 피싱(T1566), 프로세스 주입(T1055) |
| 절차 (Procedures) | WHAT (도구/실행) | 특정 공격 그룹(APT)이 실제 환경에서 구사한 구체적 스크립트 및 도구 | Mimikatz 명령어 실행, PowerShell 난독화 다운로드 |

- **고통의 피라미드 최상위치:** 해시나 도메인은 공격자가 1초 만에 재생성 가능하나, 수년에 걸쳐 습득한 공격 도구와 실행 절차(TTPs)는 강제 변경 시 막대한 재훈련 비용 발생.

## Ⅲ. TTPs 기반 위협 모델링 및 MITRE ATT&CK 매핑 체계

```text
[ 1. 보안 로그 및 이벤트 수집 ]
EDR 텔레메트리 / Sysmon / 네트워크 패킷 / 클라우드 감사 로그
       │
       ▼
[ 2. 공격 행위 식별 및 추출 ] ── 비정상 프로세스 생성, 자격증명 덤프 포착
       │
       ▼
[ 3. MITRE ATT&CK 프레임워크 매핑 ]
   ┌────────────────────────────────────────────────────────┐
   │ 전술: 자격증명 접근 (Credential Access, TA0006)         │
   │  └── 기법: OS 자격증명 덤프 (OS Credential Dumping, T1003)│
   │       └── 하위기법: LSASS 메모리 (T1003.001)           │
   │            └── 절차: Mimikatz "sekurlsa::logonpasswords"│
   └────────────────────────────────────────────────────────┘
       │
       ▼
[ 4. 행위 기반 탐지 룰화 ] ── Sigma / YARA-L / Splunk SPL 룰 작성
       │
       ▼
[ 5. 위협 헌팅 (Threat Hunting) 및 공격 시뮬레이션(BAS) 유효성 검증 ]
```

| 단계 | 수행 작업 | 산출물 및 적용 기술 |
|---|---|---|
| 1. 데이터 수집 | 프로세스 계층, 명령행 인수(CLI), 레지스트리 수정 로그 확보 | Sysmon 이벤트 ID 1, EDR 프로세스 트리 |
| 2. 행위 역공학 | 악성코드 분석 및 사고 조사에서 발견된 TTPs 도출 | 정적/동적 샌드박스 분석 보고서 |
| 3. ATT&CK 매핑 | 관측된 공격 동작을 ATT&CK 매트릭스의 기법 ID로 표준화 매핑 | Enterprise Matrix v15, Navigator 레이어 |
| 4. 탐지 룰 개발 | 개별 파일명이 아닌 API 호출 순서 및 부모-자식 관계 기반 룰셋 작성 | Sigma 룰, EDR 커스텀 탐지 정책 |
| 5. 모의 검증 | 원자적 공격 스크립트로 방어 통제가 실제 기법을 탐지하는지 실증 | Atomic Red Team, Caldera 시뮬레이터 |

## Ⅳ. 침해지표(IoC) vs 침해행위(TTPs) 비교 (Pyramid of Pain)

```text
▲  [ TTPs ] ───────── 공격자의 행동 양식 및 도구 활용 (공격자에게 치명적 타격)
│  [ Tools ] ──────── 공격에 사용된 백도어, 유틸리티, 스크립트
│  [ Network/Host ] ─ C2 도메인, IP 주소, 레지스트리 키
│  [ Hash Values ] ── MD5, SHA-256 (공격자가 1비트 변경으로 회피 용이)
```

| 구분 | 침해지표 (IoC: Indicators of Compromise) | 침해행위 (TTPs: Tactics, Techniques & Procedures) |
|---|---|---|
| 데이터 성격 | IP 주소, URL, 도메인, 파일 해시값 등 정적 데이터 | 공격자의 전술적 목표, 공격 기법, 구체적 실행 명령어 패턴 |
| 방어 효과 | 이미 알려진 동일 공격체의 즉각적 차단 | 변종 악성코드 및 신규 제로데이 공격의 행위 기반 탐지 |
| 공격자 회피 난이도 | 사소함 (Trivial): 코드 재컴파일만으로 해시값 즉시 변조 | 극도로 고통스러움 (Tough): 침투 전략 및 개발 도구 전면 재구축 |
| 방어자 구축 난이도 | 쉬움: 방화벽 블랙리스트 IP 등록, 백신 시그니처 배포 | 높음: 전사 EDR 로그 상관분석, 정밀 행위 분석 룰셋 설계 필요 |
| 주 활용 분야 | 방화벽 차단 정책, 안티바이러스, SIEM 단순 매칭 | 위협 헌팅, SOC 관제 고도화, BAS 모의 침투 시뮬레이션 |

## Ⅴ. TTPs 기반 보안 운영의 한계와 방안

| 한계 | 방안 |
|---|---|
| MITRE ATT&CK 매트릭스의 수백 개 기법을 단순히 엑셀로 체크하는 '체크리스트식 색칠'에 매몰되어 실제 데이터 수집 사각지대 간과 | ATT&CK의 데이터 컴포넌트(Data Components)를 역추적하여 조직의 EDR/Sysmon 로그가 해당 기법을 감시할 수 있는지 데이터 가시성(Data Coverage) 우선 검증 |
| 공격자가 정상 운영체제 내장 도구(PowerShell, WMI, Certutil)를 악용하는 LOLBins(Living off the Land) 구사 시 정상 업무와 오탐 혼선 | 단일 명령어 매칭을 지양하고 부모-자식 프로세스 실행 계통 트리(Process Tree Context) 및 비정상 네트워크 아웃바운드 결합 상관분석 적용 |
| 동일한 ATT&CK 기법 번호라도 공격 그룹마다 컴파일 옵션이나 스크립트 절차(Procedures)를 변형하여 정적 탐지 룰 우회 발생 | Atomic Red Team 및 Caldera 기반 오픈소스 모의 공격 프레임워크를 연동하여 기법별 변종 절차에 대한 자동화 회귀 테스트 상시 가동 |

## Ⅵ. 제언

```text
[ 기존 IoC 중심 방어 ]                [ TTPs 기반 능동적 위협 헌팅 ]
알려진 IP/해시 차단 ──┐               ┌── MITRE ATT&CK 전술/기법 매핑
단순 시그니처 매칭 ─┼─→ [ 침투 허용 ] ─┼── 부모-자식 프로세스 인과관계 추적
변종 공격에 무력화 ───┘               └── 원자적 공격 시뮬레이션(BAS) 지속 검증
```

| 평가 영역 | 1세대 IoC 방어 체계 | 차세대 TTPs 방어 체계 | 향후 발전 방향 |
|---|---|---|---|
| 방어 유효성 | 과거 공격만 방어 가능 | 신규 변종 행위 탐지 가능 | 공격자 TTPs 생성형 AI 자율 역추적 |
| 헌팅 방식 | 사후 감사 로그 대조 | 가설 기반 능동적 위협 헌팅 | SOAR 기반 TTPs 대응 플레이북 자동화 |
| 보안 투자 효과 | 차단 목록의 기하급수적 팽창 | 공격자 침투 비용 극대화 | 위협 인텔리전스 공유 표준(STIX 2.1) 연계 |

TTPs는 공격자를 수동적으로 기다리지 않고 공격자의 사고방식과 행동 절차를 체계적으로 프로파일링하여 방어망을 선제 구축하는 현대 사이버 위협 인텔리전스(CTI)의 핵심 나침반.
