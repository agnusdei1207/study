## 연관 키워드

- TTPs, MITRE ATT&CK, 침해지표, IoC, APT
- LOLBins, 자격증명 덤프, Sigma, 위협 헌팅, BAS, Atomic Red Team
- 부모-자식 프로세스, 로그 가시성, 탐지 룰, 제로데이

## Ⅰ. TTPs의 개요

- 핵심 요약 : 공격자의 전략, 기법, 실행 절차를 묶은 행동 패턴으로 공격을 식별하는 방어 관점의 위협 분석 체계.
- 개념 : 공격자가 목표를 달성하기 위해 쓰는 **TTPs** (Tactics, Techniques, and Procedures)로, 전술(목적), 기법(수단), 절차(실행 도구와 명령 패턴)로 구성된 행동 체계.
- 배경 및 필요성 : IP 주소, 도메인, 파일 해시 같은 **침해지표** (IoC, Indicators of Compromise)는 공격자가 손쉽게 바꿀 수 있어 보안 장비의 차단 효과가 짧음 → 공격자의 행동 패턴을 **MITRE ATT&CK**(Adversarial Tactics, Techniques, and Common Knowledge) 체계로 분류하여 **지능형 지속 위협** (APT, Advanced Persistent Threat)에 선제 대응하는 방식이 요구됨.
- 주요 목적 : 쉽게 변조되는 단편 지표를 넘어 공격 행위 패턴을 식별·차단하여, 공격자의 침투 비용을 높이고 사전 예방 역량을 확보.

## Ⅱ. TTPs의 특징 및 장점

- 핵심 요약 : 행위 중심 탐지와 공통 분류 체계가 변종 공격 대응과 탐지 품질 측정으로 이어지는 방식.

1. 행위 중심 탐지 : 파일 해시가 바뀌어도 공격 행위의 순서와 관계는 유지됨 → 변종 악성코드와 제로데이 공격의 탐지 가능.
2. 공통 분류 체계 : ATT&CK 기법 ID를 공통 언어로 사용 → 기관과 조직 간 위협 정보 공유와 탐지 범위 비교 용이.
3. 검증 가능성 : **BAS** (Breach and Attack Simulation, 침해 공격 시뮬레이션)로 탐지 통제가 실제 기법을 잡는지 측정 → 방어 체계의 실효성 근거 확보.
4. 공격자 비용 상승 : 침투 전략과 개발 도구를 바꿔야 대응이 우회되므로 → 공격자의 재구축 부담 증가.

## Ⅲ. TTPs의 구조 (흐름)

- 핵심 요약 : 로그 수집에서 행위 식별, ATT&CK 매핑, 탐지 룰화, 헌팅과 검증으로 이어지는 순환 구조.

```text
[ 행위 기반 탐지 흐름 ]

로그 수집 (엔드포인트, Sysmon, 네트워크, 클라우드)
      ↓
행위 식별 (비정상 프로세스, 자격증명 덤프)
      ↓
ATT&CK 매핑 (전술 → 기법 → 절차)
      ↓
탐지 룰화 (Sigma 등) → 위협 헌팅·검증
```

```text
[ ATT&CK 계층 매핑 예시 ]

전술: 자격증명 접근 (TA0006)
  ↳ 기법: OS 자격증명 덤프 (T1003)
      ↳ 하위 기법: LSASS 메모리 (T1003.001)
          ↳ 절차: Mimikatz 명령 실행
```

1. 데이터 수집 : 프로세스 계층, 명령행 인수(CLI, Command-Line Interface), 레지스트리 변경 로그 확보 → EDR(Endpoint Detection and Response)의 프로세스 트리로 행위 재구성.
2. 행위 분석 : 악성코드 분석과 사고 조사에서 관측된 동작을 TTPs 단위로 도출 → 샌드박스 분석 결과를 행위 목록으로 정리.
3. ATT&CK 매핑 : 관측 동작을 전술과 기법 ID로 표준화 → 탐지 커버리지 지도 작성.
4. 탐지 룰 개발 : 파일명이 아닌 API 호출 순서와 부모-자식 관계로 룰 작성 → Sigma 룰과 EDR 커스텀 정책 적용.
5. 모의 검증 : 원자적 공격 스크립트로 탐지 통제의 실효성 확인 → Atomic Red Team과 Caldera 같은 시뮬레이터 활용.

## Ⅳ. 침해지표와 TTPs의 비교

- 핵심 요약 : 침해지표는 알려진 공격체를 즉시 차단하는 데 강하고, TTPs는 변종과 신규 공격을 행위로 잡는 데 강함.

| 비교 항목 | 침해지표 (IoC) | 침해행위 (TTPs) |
| --- | --- | --- |
| 데이터 성격 | IP 주소, URL, 도메인, 파일 해시 등 정적 데이터 | 공격자의 전술 목표, 기법, 실행 명령 패턴 |
| 방어 효과 | 이미 알려진 공격체의 즉각 차단 | 변종과 신규 제로데이 공격의 행위 기반 탐지 |
| 공격자 회피 난이도 | 낮음 (Trivial): 파일 재컴파일로 해시 변경 가능 | 높음 (Tough): 침투 전략과 도구 전면 재구축 필요 |
| 방어자 구축 난이도 | 낮음: 방화벽 차단 목록 등록, 시그니처 배포 | 높음: 전사 EDR 로그 상관분석과 행위 룰셋 설계 필요 |
| 주 활용 분야 | 방화벽 정책, 안티바이러스, SIEM(Security Information and Event Management) 단순 매칭 | 위협 헌팅, SOC(Security Operations Center) 관제 고도화, BAS 검증 |

- 선택 기준 : 알려진 위협의 빠른 차단에는 침해지표를, 변종과 표적 공격 대응에는 TTPs를 중심에 두고 두 방식을 함께 운영.

## Ⅴ. TTPs의 한계와 방안

- 핵심 요약 : 체크리스트식 매핑, 내장 도구 악용, 절차 변형에 따른 룰 우회를 데이터 가시성 검증, 상관분석, 자동 회귀 테스트로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 체크리스트식 ATT&CK 매핑 | 기법을 표에 채우는 데 그쳐 실제 로그 사각지대를 간과 | ATT&CK의 데이터 컴포넌트 기준으로 EDR과 Sysmon 로그의 감시 가능 여부 검증 | 데이터 소스 커버리지 비율 |
| **LOLBins** (Living off the Land Binaries) 악용 | PowerShell, WMI, Certutil 같은 정상 내장 도구 사용으로 정상 업무와 오탐 혼선 | 단일 명령 매칭을 피하고 부모-자식 프로세스 계통과 비정상 외부 연결을 결합한 상관분석 | 오탐률 |
| 절차 변형에 의한 룰 우회 | 같은 기법 번호라도 도구 옵션과 스크립트를 바꿔 정적 룰 회피 | Atomic Red Team과 Caldera 기반 자동 회귀 테스트 상시 운영 | 변종 탐지율 |

## Ⅵ. TTPs에 대한 기술사적 제언

- 핵심 요약 : ATT&CK 매핑을 체크리스트가 아닌 탐지 품질 지표로 운영하고, 헌팅과 검증을 정기 절차로 고정하는 방향.

1. 보안관제 조직은 ATT&CK 매핑 결과를 기법별 로그 가시성과 탐지 성공률로 환산해 주기적으로 점검하는 체계를 갖출 필요가 있음.
2. 정보보안 조직은 EDR과 로그 수집 정책을 전사 표준으로 맞추고, 위협 헌팅과 BAS 검증을 정기 절차로 운영하는 거버넌스를 수립하는 것이 바람직함.
3. 기관 간에는 ATT&CK 기법 ID를 공통 언어로 삼아 위협 정보를 공유하는 협력 체계를 마련할 필요가 있음.

## Ⅶ. 결론

- 핵심 요약 : TTPs는 공격자의 행위 패턴을 기준으로 방어하는 체계로, 파일 단위 탐지의 한계를 보완하는 분석 관점.
- 시사점 : 행위 탐지의 가치는 로그 가시성과 검증 주기에 좌우되므로, 탐지 룰의 수보다 검증된 기법 범위를 관리 지표로 삼아야 함.
