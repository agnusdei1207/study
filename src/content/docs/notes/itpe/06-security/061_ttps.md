## 30초 인출

- **본질** : TTPs는 공격자의 목적·행동 방식·실제 구현을 나타내는 행위 분석 개념.
- **구조** : 전술(Why) ── 기법(How) ── 절차(관측된 구현 사례).
- **활용** : ATT&CK와 연결해 위협정보·탐지분석의 공통 언어로 쓰되, 매핑만으로 방어 완료를 판단하지 않음.

<details><summary>핵심 용어</summary>

- **TTPs** (Tactics, Techniques and Procedures): 공격자의 목적·행동 방식·실제 구현을 구분해 기술하는 위협 분석 개념.
- **전술(Tactic)** : 공격자가 특정 행동을 수행하는 이유나 목적.
- **기법(Technique)** : 공격자가 전술적 목적을 이루기 위해 취하는 행동 방식.
- **절차(Procedure)** : 실제 공격에서 기법·하위기법을 구현한 구체 사례.
- **ATT&CK** (Adversarial Tactics, Techniques, and Common Knowledge): 실제 관측된 공격 행위를 전술·기법 등으로 정리한 지식베이스.
- **IoC(Indicator of Compromise)** : 침해와 연관된 IP·도메인·파일 해시 등 구체 식별 정보.
</details>

### Ⅱ. 구성과 분석 활용

```text
전술(Why: 공격 목적)
       └─ 기법(How: 목적을 이루는 행동)
                └─ 절차(실제 관측된 구체 구현)

사건 증거 → 행동 분석 → ATT&CK 매핑 → 탐지·대응 검증
```

공격 절차는 기법의 실제 구현 사례이며, ATT&CK는 관측된 행위를 공통 언어로 분류.

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **TTPs** 는 공격자의 목적·행동 방식·실제 구현을 구분해 기술하는 행위 분석 개념. |
| 목적 | 개별 침해지표를 넘어 공격 행동을 분석하고 위협정보·탐지설계에 활용. |

## Ⅱ. 전술·기법·절차의 관계

```text
전술(WHY: 이루려는 목적)
           │ 여러 기법이 목적을 뒷받침
           ↓
기법(HOW: 목적 달성 행동) ── 하위기법: 더 구체적인 행동
           │
           └── 절차: 실제 환경에서 관측된 구현 사례
```

ATT&CK에서 전술은 공격자가 행위를 하는 이유, 기법은 전술적 목표를 달성하는 방법, 절차는 특정 기법의 실제 구현 사례.

## Ⅲ. ATT&CK 매핑과 탐지분석

| 단계 | 분석 행위 | 산출 근거 |
|---|---|---|
| 관측 | 로그·경보·사건 맥락 수집 | 출처·시각·자산·행동 증거 |
| 해석 | 관측된 행동과 대안 설명 검토 | 행위 설명과 판단 근거 |
| 매핑 | 증거에 맞는 전술·기법·절차 연결 | ATT&CK 객체와 신뢰도 |
| 검증 | 데이터 원천·분석 규칙·탐지 결과 시험 | 실제 가시성·경보 검증 결과 |

ATT&CK는 실제 관측 사례의 지식베이스이며 조직에 모든 기법이 적용되는 것은 아님. 색칠한 매트릭스만으로 탐지 능력이나 범위를 증명할 수 없음.

## Ⅳ. TTP와 IoC의 상호보완

| 비교 | IoC 중심 | TTP 중심 |
|---|---|---|
| 대상 | IP·도메인·파일 해시 등 구체 지표 | 공격 목적·행동 방식·실제 구현 |
| 장점 | 알려진 지표의 신속한 검색·차단 | 지표·도구가 달라져도 유사 행동 탐색 가능 |
| 한계 | 변경·재사용에 영향 | 로그 가시성·행위 분석·시험 역량 필요 |
| 활용 | 사건 대응 식별·차단 신호 | 위협정보 구조화·탐지 시나리오 설계 |

## Ⅴ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| ATT&CK 매핑 자체를 탐지 완료로 간주하면 관측되지 않은 행위와 데이터 공백을 놓칠 수 있음. | 조직의 자산·위협·로그 원천에 맞춰 적용 기법을 정하고, 증거·분석규칙·시험 결과를 연결해 탐지 가능성을 검증하는 방안. |
