## 연관 키워드

- 제로트러스트(Zero Trust), NIST SP 800-207, 정책 결정 지점(PDP), 정책 집행 지점(PEP)
- 마이크로세그멘테이션(Micro-Segmentation), ZTNA(Zero Trust Network Access), SDP(Software-Defined Perimeter)
- UEBA(User and Entity Behavior Analytics), 최소 권한(Least Privilege), 횡적 이동(Lateral Movement), 단계별 인증(Step-up Authentication)

## Ⅰ. 제로트러스트의 개요

- 핵심 요약 : 네트워크 위치를 믿지 않고 모든 접근을 신원과 단말 상태로 매번 검증하는 보안 원칙.
- 개념 : "절대 신뢰하지 않고 항상 검증한다"(Never Trust, Always Verify)는 원칙 아래, 내부망과 외부망의 구분 없이 모든 사용자, 단말, 애플리케이션의 접근 요청마다 신원을 인증하고 권한을 판단하는 **제로트러스트** (Zero Trust) 보안 모델.
- 배경 및 필요성 : 클라우드 전환, 원격·재택근무, 모바일 기기 사용이 늘면서 네트워크 경계가 사라졌고, 가상 사설망(VPN, Virtual Private Network)으로 내부에 들어온 뒤 무제한으로 이동할 수 있는 구조가 침해 확산의 통로가 됨.
- 주요 목적 : 신원 기반의 세분화된 접근 통제, 공격 표면 축소, 침해 발생 시 **횡적 이동** (Lateral Movement, 내부망에서 다른 시스템으로 옮겨 가는 공격 행위) 차단.

## Ⅱ. 제로트러스트의 특징 및 장점

- 핵심 요약 : 명시적 검증, 최소 권한, 지속 평가가 침해 시 피해 범위를 줄이는 효과로 이어지는 원칙 체계.

1. 명시적 검증 : 위치와 무관하게 모든 접근 시 **다중 인증** (MFA, Multi-Factor Authentication)과 단말 무결성을 확인 → 내부에 있다는 이유만으로 생기는 과신을 제거.
2. **최소 권한** (Least Privilege) : 필요한 애플리케이션 기능에만 시한부 접근을 부여 → 계정이 탈취되어도 접근 가능한 자원이 제한됨.
3. 지속 평가 : 세션 중에도 **사용자·개체 행위 분석** (UEBA, User and Entity Behavior Analytics)과 단말 상태를 감시해 위험이 커지면 권한을 낮추거나 세션을 종료 → 장시간 세션을 노린 공격의 영향 축소.
4. 마이크로세그멘테이션 : 워크로드 단위로 네트워크를 격리 → 한 시스템이 뚫려도 인접 시스템으로의 전파가 차단됨.

## Ⅲ. 제로트러스트의 구조 (흐름)

- 핵심 요약 : 판단을 맡는 제어 평면과 실제 통로를 맡는 데이터 평면을 분리해, 모든 세션을 정책으로 통제하는 구조.
- **정책 결정 지점** (PDP, Policy Decision Point) : 신뢰도를 계산하는 정책 엔진과 접근을 승인하는 정책 관리자로 구성.
- **정책 집행 지점** (PEP, Policy Enforcement Point) : PDP의 판단에 따라 실제 연결을 허용하거나 차단하는 관문.
- 이 구조는 미국 국립표준기술연구소(NIST, National Institute of Standards and Technology)의 **NIST SP 800-207** 지침에서 논리 구조로 정리되어 있음.

```text
[ 제어 평면 : 판단 ]

접근 요청 (주체)
      ↓
정책 결정 지점 (PDP)
  - 정책 엔진: 신뢰도 계산
  - 정책 관리자: 접근 승인
      ↓ 허용·차단 명령
```

```text
[ 데이터 평면 : 집행 ]

정책 집행 지점 (PEP)
      ↓ 허용된 세션만 연결
기업 자원 (애플리케이션, 데이터)
      ↑ 세션 중 상태를 PDP에 보고
```

```text
[ 지속적 신뢰 평가 ]

세션 수립 (MFA, 단말 상태 확인)
      ↓
행위 모니터링 (UEBA)
      ↓
위험 점수 상승 시 단계별 인증
      ↓
권한 강등 또는 세션 종료
```

## Ⅳ. 제로트러스트의 비교

- 핵심 요약 : 전통적 경계 보안이 네트워크 위치를 신뢰 기준으로 삼는 반면, 제로트러스트는 신원·단말·맥락을 기준으로 삼는 점이 근본적 차이.
- 구현 기술 : 애플리케이션 단위 접근을 제공하는 **ZTNA** (Zero Trust Network Access)와, 인프라를 숨긴 채 접근 허가를 받은 연결만 여는 **SDP** (Software-Defined Perimeter, 소프트웨어 정의 경계)가 대표적.

| 비교 항목 | 전통적 경계 보안 | 제로트러스트 |
| --- | --- | --- |
| 신뢰 가정 | 내부망은 신뢰, 외부망은 비신뢰 | 모든 네트워크와 단말을 기본 비신뢰 |
| 인증 시점 | 네트워크 진입 시 1회 인증 | 자원 접근 시마다 지속 인증 |
| 접근 범위 | 네트워크 단위 접속, 서브넷 노출 | 애플리케이션 단위 접속, 인프라 은폐 |
| 통제 기준 | IP 주소, 포트 번호 | 사용자 신원, 단말 상태, 접근 맥락 |
| 주요 구현 기술 | 방화벽, VPN | ZTNA, SDP, 서비스 메시 기반 마이크로세그멘테이션 |

- 선택 기준 : 자산이 사내망에만 있고 외부 접근이 적으면 경계 보안의 비용이 낮고, 클라우드와 원격 접근이 많으면 신원 중심 통제의 필요성이 커짐.

## Ⅴ. 제로트러스트의 한계와 방안

- 핵심 요약 : 레거시 시스템 연동, 과도한 재인증, 중앙 정책 엔진 장애를 게이트웨이 설계와 정책 분산으로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 레거시 시스템의 연동 불가 | 메인프레임, SCADA(Supervisory Control and Data Acquisition) 등 최신 신원 기반 접속을 지원하지 않음 | 에이전트 없이 동작하는 리버스 프록시와 **점프 호스트** (Bastion) 배치, SDP 게이트웨이 연동 | 연동 대상 자산 비율 |
| 잦은 재인증에 따른 생산성 저하 | 검증을 과도하게 적용하면 MFA 요구가 반복되어 업무가 지연됨 | **단계별 인증** (Step-up Authentication)으로 위험 점수가 높을 때만 추가 인증 요구, 무암호 인증(FIDO2, Fast IDentity Online 2) 확대 | 추가 인증 요구 빈도 |
| 정책 결정 지점 장애 | 모든 접근 판단이 중앙 PDP에 의존해 단일 장애점(SPOF, Single Point of Failure)이 됨 | 정책 캐싱을 지원하는 분산 PEP 구성과 PDP 이중화 | 정책 동기화 지연 시간 |

## Ⅵ. 제로트러스트에 대한 기술사적 제언

- 핵심 요약 : 신원 중심의 통제 체계를 먼저 세우고, 국가 가이드라인의 단계적 성숙도 모델에 맞춰 전환 범위를 넓히며, 데이터 보호를 함께 설계하는 방향.

IP 주소 중심의 통제를 버리고, 클라우드 신원 제공자(IdP, Identity Provider)를 전사 공통 신원 원천으로 통합하는 것부터 시작하는 것이 바람직하다.

전환은 과학기술정보통신부·한국인터넷진흥원(KISA, Korea Internet & Security Agency)의 「제로트러스트 가이드라인 2.0」이 제시하는 성숙도 단계를 참고해, 신원·단말·네트워크 영역을 순서대로 넓혀 나가는 방식이 현실적이다.

네트워크 통제가 뚫리더라도 데이터가 보호되도록, 데이터의 민감도를 분류하고 암호화를 연계하는 **데이터 보안 태세 관리** (DSPM, Data Security Posture Management)를 함께 설계해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 제로트러스트는 네트워크 위치 대신 신원과 단말 상태를 매 접근마다 검증하는 보안 원칙.
- 시사점 : 경계가 사라진 환경에서 보안의 기준점을 네트워크 위치에서 신원과 데이터로 옮기는 것이 핵심 과제임.
