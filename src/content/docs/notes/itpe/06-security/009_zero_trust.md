## 큰 그림과 30초 인출

```text
과거: 내부=신뢰 / 외부=비신뢰 → 경계 침해 후 횡적이동

Zero Trust: Never Trust, Always Verify
[주체] ─ 접근요청 ─▶ [PEP] ─▶ [자원]
                         ▲
                         │ 허용·거부·세션제어
                       [PDP]
                ┌────────┴────────┐
              [PE]              [PA]
          정책·맥락 판단       명령 실행

신원·기기·워크로드·데이터·네트워크·가시성
```

- 본질: **네트워크 위치만으로 신뢰하지 않고, 모든 접근을 자원 단위로 명시적·지속 검증**
- 원칙: 명시적 검증, 최소권한, 침해 가정, 동적 정책, 지속 모니터링
- 구성: `Policy Engine(PE)`, `Policy Administrator(PA)`, `Policy Enforcement Point(PEP)`

## 예상문제

> 제로트러스트의 개념과 원칙, 논리 구성요소와 접근결정 절차를 설명하고 경계형 보안과 비교한 후 단계적 도입방안을 제시하시오. (25점)

## Ⅰ. 위치 기반 암묵적 신뢰를 제거하는 제로트러스트 개요

- 정의: **제로트러스트 아키텍처**는 주체와 자원의 네트워크 위치·소유관계만으로 신뢰를 부여하지 않고, 세션마다 정책과 맥락을 평가해 최소권한 접근을 허용하는 보안 아키텍처
- 배경: 클라우드·원격근무·SaaS·공급망 확대로 내부/외부 경계가 약화되고, 계정 탈취 후 내부 횡적이동이 주요 위험으로 부상
- 목표: 자원 단위 접근 통제, 침해 범위 축소, 지속적인 신원·기기·행위 검증

## Ⅱ. 명시적 검증·최소권한·침해 가정의 원칙

| 원칙 | 구현 | 효과 |
|---|---|---|
| **모든 자원을 보호대상화** | 데이터·서비스·워크로드 단위 정책 | 네트워크 세그먼트보다 세밀한 통제 |
| **주체·기기별 접근** | 사용자·서비스계정·기기 상태 결합 | 탈취 계정 단독 사용 억제 |
| **세션별 최소권한** | JIT/JEA·짧은 세션·동적 권한 | 권한 남용과 체류시간 축소 |
| **동적 정책** | 신원·위치·기기·위험·행위 신호 평가 | 상황 변화에 따른 재인증·차단 |
| **지속 관측** | 인증·접근·행위 텔레메트리 수집 | 이상행위 탐지와 정책 개선 |

## Ⅲ. PDP와 PEP 중심의 논리 구조

```text
[Subject + Device] ───── Access Request ─────▶ [PEP] ───▶ [Resource]
                                                   ▲
                                                   │ Decision/Command
                                            +------┴------+
                                            |    PDP      |
                                            | PE  +  PA   |
                                            +------┬------+
                                                   │
       Identity · Device Posture · Threat Intel · Logs · Data Policy
```

| 구성요소 | 책임 |
|---|---|
| **PE** | 정책과 신뢰 신호를 종합해 허용·거부·조건부 허용 판단 |
| **PA** | PE 결정을 바탕으로 자격·세션·구성 명령 생성 |
| **PEP** | 요청을 가로채 정책결정을 집행하고 세션 종료 |
| **신뢰 데이터원** | IdP, EDR/MDM, 자산·취약점, 위협정보, SIEM 로그 제공 |

## Ⅳ. 접근요청에서 지속 검증까지의 동작

```text
① 주체·기기 식별 → ② 자원·행위 요청 → ③ 정책·위험 신호 수집
       → ④ PE 판단 → ⑤ PA가 세션 조건 생성 → ⑥ PEP 집행
       → ⑦ 행위·상태 지속 관측 → 위험 변화 시 재평가·축소·종료
```

- 단일 로그인 통과를 영구 신뢰로 바꾸지 않고 세션 중에도 기기 위험·행위 이상·자원 민감도 변화를 재평가
- 실패 시 무조건 광범위 차단보다 추가 인증, 읽기 전용 전환, 세션 시간 축소 등 조건부 통제 가능

## Ⅴ. 경계형 보안과 제로트러스트 비교

| 기준 | 경계형 보안 | 제로트러스트 |
|---|---|---|
| 신뢰 기준 | 내부망 위치 중심 | 신원·기기·자원·맥락 중심 |
| 통제 단위 | 네트워크 구간 | 자원·세션·행위 |
| 인증 시점 | 최초 접속 중심 | 지속적 재평가 |
| 권한 | 장기·광범위 권한 가능 | 최소권한·동적 권한 |
| 침해 대응 | 경계 차단 후 내부 탐지 | 침해 가정·횡적이동 축소 |
| 전환 전략 | 기존 방화벽 중심 | IAM·기기·마이크로세그멘테이션·가시성 연계 |

## Ⅵ. 자산·신원부터 단계적으로 전환하는 방안

| 단계 | 핵심 활동 | 완료 기준 |
|---|---|---|
| **가시화** | 중요 자산·데이터·사용자·기기·흐름 식별 | 미식별 자산과 계정 감소 |
| **신원 강화** | MFA, 계정 수명주기, 특권·비인간 신원 관리 | 장기 특권·휴면 계정 통제 |
| **기기 신뢰** | MDM/EDR, 보안상태 기반 조건부 접근 | 비준수 기기 접근 차단 |
| **자원 세분화** | 애플리케이션 프록시·마이크로세그멘테이션 | 횡적이동 경로 축소 |
| **데이터 보호** | 분류·암호화·DLP·세션별 사용정책 | 민감정보 접근 추적 |
| **자동화·최적화** | SIEM/SOAR와 정책결정 연계 | 평균 탐지·차단시간 개선 |

- 빅뱅 전환 대신 중요 업무 여정부터 보호면을 정하고, 레거시 예외에는 책임자·만료일·보완통제를 부여
- 성과는 MFA 도입률 하나가 아니라 과다권한 수, 관리되지 않은 기기 접근, 횡적이동 가능 경로, 정책결정 지연으로 측정

## Ⅶ. 제품 도입이 아니라 신뢰결정 체계를 바꾸는 결론

- 제로트러스트는 단일 솔루션이 아니라 **신원·기기·자원·행위 신호를 정책결정과 집행으로 연결하는 아키텍처 전환**
- 중요 자산과 실제 접근 흐름을 기준으로 단계적으로 도입하고, 지속 관측 결과를 정책에 환류해 최소권한과 업무 연속성을 함께 확보해야 함

## 1교시 10점 답안 발췌

### 1. 정의와 원칙

- 네트워크 위치를 신뢰 근거로 삼지 않고 모든 자원 접근을 명시적·지속 검증하는 보안 아키텍처
- 명시적 검증, 최소권한, 침해 가정

### 2. 논리 구조

```text
Subject → PEP → Resource
           ▲
           └─ PDP(PE 판단 + PA 명령)
                 ↑ Identity·Device·Risk·Log
```

### 3. 도입 핵심

- 자산 가시화 → 신원·기기 강화 → 자원 세분화 → 데이터 보호 → 자동화 순으로 전환
