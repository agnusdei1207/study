정보보안 → 보안 아키텍처 → 제로 트러스트 및 신원 기반 접근 통제

## 30초 인출

- **본질:** 네트워크 위치나 경계에 기반한 암묵적 신뢰를 전면 배제하고 모든 접근 요청을 명시적으로 검증하는 보안 패러다임
- **메커니즘:** 제어 평면의 PDP(Policy Decision Point: PE/PA)가 주체·기기·컨텍스트 위험도를 지속 평가하여 데이터 평면의 PEP(Policy Enforcement Point)로 접근을 동적 인가
- 통찰: PDP의 실시간 평가 오버헤드와 레거시 환경의 비호환성을 해소하기 위해 엣지 분산 캐싱과 SDP 및 마이크로세그멘테이션 하이브리드 전환 전략 필수

<details>
<summary>핵심 용어</summary>

- **NIST SP 800-207:** 제로 트러스트의 7대 기본 원칙과 논리적 아키텍처(PDP/PEP)를 정의한 미국 국립표준기술연구소의 공식 표준
- **정책결정점 (PDP, Policy Decision Point):** 정책 엔진(PE)과 정책 관리자(PA)로 구성되어 접근 요청의 허용 여부를 결정하고 통제하는 제어 평면
- **정책집행점 (PEP, Policy Enforcement Point):** 주체와 엔터프라이즈 리소스 간의 실제 데이터 트래픽 연결을 생성, 모니터링, 종료하는 데이터 평면 게이트웨이
- **소프트웨어 정의 경계 (SDP, Software Defined Perimeter):** SPA(단일 패킷 인가) 기법을 활용하여 인증 전에는 인프라를 외부에서 은닉(Dark IP)하는 ZTA 구현 기술
</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **제로트러스트(Zero Trust)** 는 "절대 신뢰하지 않고, 항상 검증한다(Never Trust, Always Verify)"는 원칙하에 네트워크 내부·외부 구분을 배제하고 모든 자원 접근을 지속해서 인증·인가하는 보안 패러다임 |
| 목적 | 내부 침투 성공 후 공격자의 횡적 이동(Lateral Movement) 차단 및 하이브리드·멀티클라우드 환경에서 분산된 데이터·워크로드 보호 |

기존의 성과 해자(Castle-and-Moat) 모델 기반 경계 보안이 내부자 위협 및 크리덴셜 탈취 공격에 무력화됨에 따라 전사적 신원 중심 통제로 전환.

## Ⅱ. 제로트러스트의 특징 및 기본 원칙

NIST SP 800-207에서 명시한 7대 기본 테넷(Tenets)을 바탕으로 구현.

| 구분 | 핵심 원칙 | 아키텍처 구현 내용 |
|---|---|---|
| **자원 범위** | 모든 데이터 소스와 컴퓨팅 서비스를 자원으로 간주 | 엔드포인트, 클라우드 워크로드, SaaS, 온프레미스 DB 포괄 |
| **통신 보호** | 네트워크 위치와 무관하게 모든 통신 암호화 | 전송 구간 mTLS(상호 TLS) 암호화 강제 |
| **세션 단위** | 개별 리소스 접근 단위로 동적 인가 부여 | 단일 세션 단위 최소 권한 허가 및 재인증 요구 |
| **동적 정책** | 클라이언트 상태 및 요청 컨텍스트 기반 동적 평가 | 디바이스 보안 상태(EDR), 사용자 신원, 위치, 위협 인텔리전스 반영 |
| **자산 모니터링** | 소유 및 관련 자산의 무결성과 보안 상태 감시 | 패치 수준, 취약점 유무, EDR 에이전트 정상 동작 여부 측정 |
| **동적 인증·인가** | 접근 허용 전 엄격한 인증 및 세션 중 지속 검증 | MFA(다요소 인증), 패스워드리스, 위험 기반 조건부 액세스 |
| **지속적 진단** | 인프라 상태 수집 및 로깅을 통한 개선 피드백 | 통신 메타데이터 중앙 수집 및 XDR/SIEM 상관분석 피드백 |

## Ⅲ. 제로트러스트 아키텍처(ZTA) 체계 및 메커니즘

```text
[NIST SP 800-207 기반 제로트러스트 논리 구조]

     +---------------------------------------------------------------+
     |              [제어 평면: Control Plane (PDP)]                 |
     |                                                               |
     |  +--------------------+             +----------------------+  |
     |  | 정책 엔진 (PE)     |<----------->| 정책 관리자 (PA)     |  |
     |  | Policy Engine      |             | Policy Administrator |  |
     |  +---------^----------+             +----------^-----------+  |
     +------------|-----------------------------------|--------------+
                  | (위험도 평가)                     | (연결 토큰 발급)
  [외부 입력원]   |                                   |
  - 신원 관리(IdP)|                                   v
  - 디바이스(EDR) |               +--------------------------------------+
  - 위협 인텔(TI) |               |    [데이터 평면: Data Plane]         |
  - SIEM / SOAR   |               |                                      |
                  |     요청      |  +----------+         +-----------+  |
       [주체] ----+-------------> |  | 정책집행점|========>| 엔터프라이즈| |
      (Subject)                   |  | (PEP)    |  mTLS   | 리소스    |  |
                                  |  +----------+         +-----------+  |
                                  +--------------------------------------+
```

### 1. 논리 컴포넌트별 상세 역할

| 컴포넌트 | 기능 및 동작 메커니즘 | 기술적 구성 요소 |
|---|---|---|
| **정책 엔진 (PE)** | 접근 요청 주체의 신원, 디바이스 포스처, 리소스 민감도를 엔터프라이즈 정책과 대조하여 최종 허용/거부 결정 생성 | OPA(Open Policy Agent), 규칙 기반 엔진, 머신러닝 이상 탐지 |
| **정책 관리자 (PA)** | PE의 결정을 수신하여 PEP에 명령을 하달하고, 암호화된 세션 키(mTLS 인증서 또는 토큰)를 주체와 리소스 간에 주입 | 컨트롤러, CA(인증기관), 세션 브로커 |
| **정책집행점 (PEP)** | 주체와 엔터프라이즈 리소스 간의 통신 경로를 물리적/논리적으로 차단하고, PA의 승인 하에 통신 세션만 브리지 | 차세대 방화벽, 서비스 메시(Envoy), SDP 게이트웨이, 리버스 프록시 |

## Ⅳ. 경계 기반 보안 vs 제로트러스트 비교

| 비교 항목 | 기존 경계 기반 보안 (Perimeter Security) | 제로트러스트 보안 (Zero Trust) |
|---|---|---|
| **신뢰 모델** | 외부(Untrusted) vs 내부(Trusted) 이분법 | 모든 영역 불신(Untrusted), 명시적 검증 |
| **인가 단위** | 네트워크 서브넷 또는 VLAN 단위 광범위 인가 | 개별 애플리케이션 및 데이터 자원 단위 최소 인가 |
| **제어 메커니즘** | 고정 IP/Port 기반 방화벽 룰셋 및 ACL | 신원(IdP), 기기 상태(Posture), 컨텍스트 기반 동적 토큰 |
| **내부 이동 통제** | 내부 침투 시 평면 네트워크에서 자유로운 횡적 이동 가능 | 마이크로세그멘테이션으로 엔드포인트 간 통신 원천 격리 |
| **네트워크 가시성** | VPN 연결 후 내부 전체 네트워크 스캔 및 탐색 노출 | SDP 적용을 통해 인증 전 포트 비개방(Dark Cloud) |
| **접근 지속성** | 로그인 성공 시 세션 만료 전까지 지속 신뢰 | 세션 진행 중에도 이상 행위 감지 시 즉시 세션 파기 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **PDP 단일 장애점(SPOF) 및 인가 레이턴시 병목**<br>모든 리소스 접근 트래픽마다 중앙 집중식 PDP에 실시간 질의할 경우 네트워크 병목 및 수십 ms 단위 지연 발생 | **엣지 PEP 기반 분산 캐싱 및 JWT 토큰 분산 검증**<br>단기 유효 기간(TTL)을 가진 서명된 JWT/비대칭키 토큰을 로컬 PEP에 캐싱하고, OPA 엣지 인메모리 컴파일 방식을 적용해 PDP 통신 부하를 분산하고 인가 지연을 서브 밀리초(sub-ms)로 단축 |
| **레거시 프로토콜 및 비호환 시스템의 연동 한계**<br>mTLS, HTTP/2, OIDC/SAML을 지원하지 않는 메인프레임, 산업용 제어망(SCADA), 레거시 SMB/RPC 시스템의 PEP 수용 불가 | **프로토콜 변환 리버스 프록시 및 마이크로세그멘테이션 오버레이**<br>레거시 장비 전면에 프로토콜 변환 전용 사이드카(Sidecar) 프록시를 배치하거나, 네트워크 가상화(VXLAN, eBPF) 기반 호스트 에이전트 오버레이를 통해 L4/L7 방화벽 레벨에서 제로트러스트 격리 계층 형성 |

## Ⅵ. 제언

```text
[성공적인 제로트러스트 마이그레이션 3대 핵심 아키텍처 축]

       +-------------------------------------------------------+
       |           전사 통합 신원 (Universal IdP)              |
       +---------------------------+---------------------------+
                                   |
         +-------------------------+-------------------------+
         |                                                   |
         v                                                   v
+-------------------------+               +--------------------------+
|  SDP (원격·외부 접근)   |               | 마이크로세그멘테이션     |
|  - 사용자-앱 간 점대점 |               | - 워크로드-워크로드 간   |
|  - SPA 패킷 단일 인가  |               | - eBPF 기반 동적 격리    |
+-------------------------+               +--------------------------+
```

| 구현 전략 | 핵심 기술 스택 | 적용 우선순위 |
|---|---|---|
| **신원 및 접근 관리 (IAM)** | IdP 중앙화, FIDO2 패스워드리스, 조건부 액세스 | 1단계 (필수 기반 확보) |
| **소프트웨어 정의 경계 (SDP)** | SPA(Single Packet Authorization), 원격 ZTNA 프록시 | 2단계 (기존 VPN 전면 대체) |
| **마이크로세그멘테이션** | eBPF, 쿠버네티스 CNI(Cilium), 서비스 메시(Istio) | 3단계 (클라우드/데이터센터 내부 격리) |

빅뱅 방식의 전면 교체 대신, 위험도가 높은 핵심 데이터베이스 및 외부 원격 접속 VPN을 우선 대상으로 SDP와 IAM을 선제 적용하는 단계적 성숙도(CMM) 기반 로드맵 수립 권장.
