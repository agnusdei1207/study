## 30초 인출
- 본질: XZ Utils 백도어는 일부 5.6.x 배포 소스에 악성 코드가 포함된 공급망 침해 사례
- 메커니즘: 오염된 릴리스 tarball의 빌드 입력이 특정 조건에서 liblzma에 반영돼 인증 경로에 영향을 줄 수 있었음
- 통찰: 한계: 저장소 코드 검토만으로 릴리스 오염을 발견하기 어려움 → 방안: tarball과 실제 빌드 입력을 교차 검증하고 영향 버전을 추적

## 2~4교시 25점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | XZ Utils 백도어는 2024년 일부 XZ 배포 소스에 악성 코드가 포함된 공급망 침해 사례 |
| 목적 | 소스 저장소·릴리스 산출물·실제 빌드 경로의 교차 검증 |

유지보수·릴리스 권한 → 배포 소스 생성 → 패키지 빌드 → 라이브러리 로드 → 의도치 않은 인증 경로 영향. 소스 코드 저장소만 검토하고 릴리스 tarball과 실제 빌드 산출물을 보지 않을 때 검증 공백 발생.

### Ⅱ. 통제 지점

```text
저장소 코드 ─┐
릴리스 묶음 ─┼─> 차이·출처 검증 ─> 빌드 스크립트·산출물 확인
빌드 입력 ───┘                         ↓
                             영향 버전·운영 경로 추적
```
| 단계 | 검증 |
|---|---|
| 유지보수 | 변경 승인·릴리스 권한 분리, 의심 변경 검토 |
| 빌드 입력 | 소스 저장소와 배포물 차이·서명·출처 확인 |
| 패키징 | 빌드 스크립트와 테스트 파일까지 검토, 재현 빌드 활용 |
| 운영 | 영향 버전·링크 관계 파악, 안전한 버전으로 교체 |

### Ⅲ. 일반화할 교훈

| 공급망 증거 | 확인 가능 | 추가 검증 |
|---|---|---|
| SBOM | 포함된 구성요소·버전 | 악성 행위 자체 탐지 |
| 출처 증명 | 빌드·배포 경로 기록 | 승인 주체의 악성 의도 |
| 코드·운영 점검 | 변경 동작·실행 징후 | 실제 영향 범위의 증거 |
SBOM은 영향 대상을 찾는 데 유용하지만 악성 행위를 자동 탐지하지 않음. 출처 증명도 악성 유지보수자의 승인 자체를 막지는 못하므로 코드·빌드·운영 검증의 다층 적용 필요. 사건의 실제 영향 범위와 가상 최악 시나리오 구분.

### Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| SBOM·출처 증명만으로 악성 유지보수자나 변조 빌드를 자동 탐지하지 못함 | 코드·빌드·배포·운영 검증을 분리해 변경을 단계적으로 확인 |

### Ⅴ. 제언

저장소 코드뿐 아니라 릴리스 묶음과 실제 빌드 입력의 차이를 검증하고 영향 버전을 추적한다.

## 출제 이력과 검증 출처
- 확인한 제132~140회 공식 문제지에서 표제어 직접 출제 미확인. 공급망 보안 학습용 예상 토픽
