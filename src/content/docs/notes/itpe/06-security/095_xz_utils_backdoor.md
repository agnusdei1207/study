## 핵심 용어
- GNU IFUNC (Indirect Function): 런타임 시 CPU 아키텍처(AVX 지원 여부 등)에 따라 가장 최적화된 함수 구현체를 동적으로 선택해 연결해 주는 glibc 기능으로, 공격자가 이를 악용해 OpenSSH의 인증 함수를 가로챔
- 재현 가능 빌드(Reproducible Builds): 동일한 소스코드로 빌드했을 때 누구나 1비트의 오차도 없이 완전히 동일한 바이너리 산출물이 나오는 것을 보장하여 빌드 과정의 백도어 주입을 방지하는 기술

## 핵심 통찰
- 공격자(Jia Tan)는 2년 이상 정상적인 버그 수정과 기여를 하며 원작자의 신뢰를 얻은 후 관리자 권한을 이양받음 → 이는 기술적 해킹이 아니라 국가 기관 수준의 고도화된 '장기 사회공학(Social Engineering) 작전'이었음
- 마이크로소프트의 엔지니어(안드레스 프로인트)가 SSH 접속 시 CPU 사용량이 0.5초 늘어나고 밸그라인드(Valgrind) 메모리 오류가 나는 이상 현상을 집요하게 추적하여 우연히 발견함 → 그렇지 않았다면 전 세계 클라우드 리눅스 서버 전체가 조용히 함락되었을 것임
- 리눅스 배포판들이 편의를 위해 `systemd-notify`를 통해 서로 아무 관련이 없는 `sshd`와 압축 라이브러리(`liblzma`)를 무리하게 링크시켜 놓았던 아키텍처적 결함이 공격 통로를 열어줌

## 이웃 토픽과 구분
- XZ 백도어 vs SolarWinds: XZ = 비영리 오픈소스 생태계의 메인테이너 권한 장악 및 Tarball 변조 / SolarWinds = 상용 소프트웨어 개발사의 폐쇄망 빌드 시스템 침투

## 문제·원인·대책
- 사례: 글로벌 리눅스 배포판(Fedora, Debian 등)의 최신 패키지 빌드에 OpenSSH 우회 백도어가 삽입되어 긴급 배포 중단 및 롤백이 단행된 사건
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| Git 저장소 코드 리뷰를 우회하여 릴리스 바이너리에 백도어 삽입 | GitHub 소스와 릴리스 아카이브(Tarball) 간의 무결성 검증 부재 | 재현 가능 빌드(Reproducible Builds) 및 SLSA 레벨 3 도입 | 소스코드와 배포 바이너리 간의 불일치 즉각 감지 |
| 압축 라이브러리 감염이 핵심 인증 데몬(sshd) 장악으로 전이 | systemd 연동으로 인한 sshd 데몬과 liblzma 간의 불필요한 링킹 | 최소 권한 의존성 설계(소프트웨어 디커플링 및 동적 링크 제한) | 보조 라이브러리 침해 시에도 핵심 시스템 데몬 보호 |
