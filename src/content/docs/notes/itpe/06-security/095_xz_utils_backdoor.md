## 한 줄 본질
- CVE-2024-3094는 XZ Utils의 오염된 배포 소스에 악성 코드가 포함된 공급망 사고. 패키지 이름의 신뢰만으로 릴리스 산출물의 무결성을 보장할 수 없음

## 10점 답안
XZ Utils 백도어(CVE-2024-3094)는 2024년 일부 XZ 5.6.x 릴리스 배포물에 악성 코드가 삽입된 공급망 침해 사례. 특정 빌드 조건에서 악성 코드가 `liblzma`에 반영되고, 영향받는 리눅스 환경에서 OpenSSH 인증 경로에 영향을 줄 수 있었음. 모든 XZ 설치·모든 리눅스 배포판이 같은 수준으로 침해된 것은 아님. 소스 저장소와 배포 tarball 차이 확인, 빌드 입력 검증, 의존성 최소화, 영향 버전 식별·롤백이 핵심 대응.

## 25점 답안
### Ⅰ. 공격 경계
유지보수·릴리스 권한 → 배포 소스 생성 → 패키지 빌드 → 라이브러리 로드 → 의도치 않은 인증 경로 영향. 소스 코드 저장소만 검토하고 릴리스 tarball과 실제 빌드 산출물을 보지 않을 때 검증 공백 발생.

### Ⅱ. 통제 지점
| 단계 | 검증 |
|---|---|
| 유지보수 | 변경 승인·릴리스 권한 분리, 의심 변경 검토 |
| 빌드 입력 | 소스 저장소와 배포물 차이·서명·출처 확인 |
| 패키징 | 빌드 스크립트와 테스트 파일까지 검토, 재현 빌드 활용 |
| 운영 | 영향 버전·링크 관계 파악, 안전한 버전으로 교체 |

### Ⅲ. 일반화할 교훈
SBOM은 영향 대상을 찾는 데 유용하지만 악성 행위를 자동 탐지하지 않음. 출처 증명도 악성 유지보수자의 승인 자체를 막지는 못하므로 코드·빌드·운영 검증의 다층 적용 필요. 사건의 실제 영향 범위와 가상 최악 시나리오 구분.

## 출제 근거
