## 지식 로드맵 내 현재 위치

정보보안 → 개인정보 보호 및 프라이버시 강화 기술 → **가명·익명·비식별 처리**

## 30초 인출

- 본질: **비식별 처리 (De-identification)** : 개인정보에서 직접 식별자 및 준식별자(QI)를 변환·삭제·일반화하여 특정 개인을 식별할 수 없도록 조치하는 프라이버시 보존 엔지니어링 기술
- 메커니즘: 사전 준비 → 비식별 조치(가명화, 범주화, 마스킹, 총계처리, 억제) → 프라이버시 보호 모델 검증($k$-익명성, $l$-다양성, $t$-근접성) → 사후 재식별 위험도 평가의 4단계 라이프사이클 수행
- 통찰: $k$-익명성 적용 시 동질성 공격 및 결합 공격에 의한 속성 누출 한계와 유용성 저하 극복을 위해 $t$-근접성과 차분 프라이버시(Differential Privacy) 연계 필수

<details>
<summary>핵심 용어</summary>

- **가명정보 (Pseudonymous Data)** : 추가 정보(매핑 테이블, 암호화 키)의 사용·결합 없이는 특정 개인을 알아볼 수 없는 정보로 통계작성, 과학적 연구, 공익적 기록보존에 동의 없이 활용 가능
- **익명정보 (Anonymous Data)** : 시간, 비용, 기술 등 합리적으로 고려할 수 있는 모든 수단을 동원해도 특정 개인을 영구히 알아볼 수 없는 정보로 개인정보보호법 적용 전면 제외
- **준식별자 (Quasi-Identifier, QI)** : 성별, 나이, 우편번호, 직업 등 단독으로는 개인을 식별할 수 없으나 외부 공개 데이터와 결합 시 개인 식별에 기여하는 속성
- **k-익명성 (k-Anonymity)** : 동일한 준식별자 값을 갖는 동등 클래스(Equivalence Class) 내에 최소 $k$개 이상의 레코드가 존재하도록 일반화하는 모델
- **l-다양성 (l-Diversity)** : 동일한 준식별자 군집 내에서 민감한 속성(질병, 소득 등)의 종류가 최소 $l$개 이상 다양하게 분포하도록 강제하여 동질성 공격을 방어하는 모델
- **t-근접성 (t-Closeness)** : 동등 클래스 내 민감 속성의 분포와 전체 데이터셋의 민감 속성 분포 간의 거리(EMD: Earth Mover's Distance) 격차를 $t$ 이하로 제한하는 모델

</details>

## 2~4교시 25점 답안

## Ⅰ. 가명·익명·비식별 처리의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 개인정보에 포함된 고유 식별자(주민번호, 이름)와 준식별자(생년월일, 주소, 직업)를 삭제, 암호화, 범주화, 마스킹 등의 공학적 변환을 통해 특정 개인의 식별 가능성을 원천적으로 축소시키는 기술적 보호조치 |
| 목적 | 데이터 3법 개정에 따른 AI 훈련, 빅데이터 통계 분석 등 데이터 결합·활용을 보장하면서도 개인의 사생활 침해 및 재식별 위협 원천 방어 |

## Ⅱ. 비식별 처리의 특징 및 5대 핵심 기술 기법

| 기법 유형 | 처리 메커니즘 | 변환 예시 | 특징 및 데이터 영향도 |
|---|---|---|---|
| **1. 가명화 (Pseudonymization)** | 식별자를 일방향 암호화 해시, 난수, 토큰으로 일괄 대체 | 홍길동 ──► `a8f5c2d...` (SHA-256) | 추가정보(Salt) 분리 보관 필수; 레코드 간 연계 분석 가능 |
| **2. 총계처리 (Aggregation)** | 개별 상세값을 집계하여 총합, 평균, 중간값으로 변환 | 키 175, 180, 185 ──► 평균 180cm | 개별 특성 은닉; 통계 분석에는 유용하나 미세 분석 불가 |
| **3. 데이터 삭제 (Suppression)** | 식별성이 높은 이상치(Outlier)나 특정 속성을 컬럼/행 삭제 | 주민번호 열 삭제, 99세 이상 행 삭제 | 민감도 높은 속성 원천 제거; 데이터 손실률(Information Loss) 큼 |
| **4. 데이터 범주화 (Generalization)**| 연속형 수치값을 구간(코드화)이나 상위 개념으로 추상화 | 나이 23세 ──► 20대, 주소 역삼동 ──► 강남구 | $k$-익명성 달성의 핵심 기법; 분석 해상도(Resolution) 감소 |
| **5. 데이터 마스킹 (Masking)** | 식별자 또는 준식별자의 특정 문자 위치를 `*`로 공백 대체 | 950101-1234567 ──► `950101-1******` | 직관적인 식별 차단; 개발/테스트 DB 및 화면 출력에 대중적 |

## Ⅲ. 프라이버시 보호 모델(k-l-t) 아키텍처 및 재식별 위험 검증

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ 프라이버시 보호 모델 (k-l-t) 진화 체계 ]           │
│                                                                        │
│   [k-익명성 (k=3)]                  [동질성 공격 발생!]                 │
│   나이     지역     질병(민감)      -> 20대 서울 거주자 3명이 모두     │
│   20대     서울     위암            "위암" 환자라면 홍길동의 질병이     │
│   20대     서울     위암            "위암"임이 100% 특정 노출됨!        │
│   20대     서울     위암            (속성 누출: Attribute Disclosure)   │
│          │                                                             │
│          ▼ [l-다양성 도입으로 보완 (l=3)]                               │
│   나이     지역     질병(민감)      -> 동등 클래스 내에 서로 다른       │
│   20대     서울     위암            질병 3종 이상 다양하게 배치!       │
│   20대     서울     당뇨            (동질성 공격 방어 성공)             │
│   20대     서울     감기                                               │
│          │                                                             │
│          ▼ [t-근접성 도입으로 완성 (분포 거리 제한)]                   │
│   - 특정 군집 내 "위암" 비율이 90%이고 전체 데이터셋 위암 비율이 1%라면 │
│     스큐니스 공격(Skewness Attack) 가능                                │
│   - 군집 내 질병 확률 분포 P와 전체 분포 Q의 EMD 거리 <= t 로 강제!     │
└────────────────────────────────────────────────────────────────────────┘
```

| 프라이버시 모델 | 핵심 보장 원리 | 방어 대상 공격 유형 | 엔지니어링 한계점 |
|---|---|---|---|
| **$k$-익명성 (k-Anonymity)** | 준식별자 동등 클래스 크기 $\ge k$ | 연결 공격 (Linkage Attack) | 동질성 공격, 배경지식 공격에 무력 |
| **$l$-다양성 (l-Diversity)** | 동등 클래스 내 서로 다른 민감값 $\ge l$ | 동질성 공격 (Homogeneity) | 왜곡 공격(Skewness), 유사성 공격에 취약 |
| **$t$-근접성 (t-Closeness)** | 클래스 내 분포와 전체 분포 거리 $\le t$ | 왜곡 공격, 유사성 공격 완벽 방어 | 거리 계산(EMD) 복잡도 높고 유용성 급감 |

## Ⅳ. 원본 개인정보 vs 가명정보 vs 익명정보 비교

| 비교 항목 | 원본 개인정보 | 가명정보 (Pseudonymous Data) | 익명정보 (Anonymous Data) |
|---|---|---|---|
| **식별 가능성** | 직접 식별 가능 (이름, 주민번호 등) | **추가정보 결합 없이는 식별 불가** | **모든 수단을 동원해도 식별 불가** |
| **법적 지위** | 개인정보 (전면 규제 적용) | **개인정보에 해당 (특례 조항 적용)**| **개인정보 비대상 (보호법 전면 제외)**|
| **이용 가능 범위**| 정보주체의 사전 동의 범위 내 | **통계작성, 연구, 공익 기록은 동의 면제**| **제한 없이 영리적 자유 활용 가능** |
| **안전조치 의무** | 개인정보보호법상 법정 안전조치 | **추가정보 분리 보관, 재식별 금지** | 안전조치 의무 없음 |
| **파기 의무** | 보유 기간 만료 시 즉시 파기 | 연구 목적 달성 후 추가정보 파기 | 파기 의무 없음 (영구 보관 가능) |

## Ⅴ. 비식별 처리 운영 시 핵심 엔지니어링 한계와 방안

| 한계 | 방안 |
|---|---|
| $k$-익명성 및 $l$-다양성을 만족하더라도 공격자가 대상자의 가족력, 거주지 특성 등 외부 배경지식(Background Knowledge)을 보유하고 있을 경우 특정 질병이나 자산 규모를 역추론해내는 속성 노출(Attribute Disclosure) 발생 | 전체 데이터 분포와 국소 군집 간의 확률 분포 차이를 엄격히 제약하는 $t$-근접성($t \le 0.15$)을 적용하고, 데이터셋 공개 방식 대신 안전한 연산 환경에서 통계적 결과값에 노이즈를 주입하는 차분 프라이버시(Differential Privacy) 기법 연계 |
| 공격자가 공개된 외부 빅데이터(SNS 위치 체크인, 공공 마이데이터, 카드 결제 내역)와 비식별화된 데이터셋을 결합하여 고차원 희소 데이터의 특이 레코드를 찾아내는 결합 재식별(Linkage Attack) 공격 발생 | 고위험 고유 식별자 조합에 대해 k-익명성 기준을 엄격히 높이고, 사설 결합을 엄격히 금지하며 법적으로 지정된 '결합전문기관'을 통해서만 안전한 일방향 솔트 해시 결합키(HMAC) 기반의 전문 결합 수행 |
| 프라이버시 보호 모델의 매개변수($k, l, t$)를 과도하게 엄격하게 설정할 경우 대부분의 데이터가 삭제되거나 초광범위하게 범주화되어 머신러닝 모델의 예측 정확도 및 통계 분석 유용성(Utility)이 붕괴되는 프라이버시-유용성 트레이드오프 발생 | 원본의 통계적 특성과 상관관계를 완벽히 복제하면서도 수학적으로 실존 인물과 1:1 매핑되지 않는 생성형 AI 기반의 합성 데이터(Synthetic Data, CTGAN/Diffusion)를 생성하여 분석용 데이터셋으로 공급 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
마이데이터 및 헬스케어 인공지능 플랫폼 구축 시, 가명처리된 데이터라 할지라도 추가정보(암호화 키, 원본 매핑 테이블)를 분리된 물리적 네트워크 망(망분리 영역)에 별도 암호화 보관해야 하며, 내부 개발자나 데이터 사이언티스트에 의한 고의적 재식별 시도를 방지하기 위해 재식별 행위 시 즉시 계정 정지 및 형사 처벌(5년 이하 징역 또는 5천만원 이하 벌금) 규정을 보안 서약서에 명시 권장

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│               [ 가명정보 처리 및 재식별 위험도 평가 파이프라인 ]       │
│                                                                        │
│   [1단계: 데이터 준비]                                                  │
│   - 원본 RDB에서 식별자, 준식별자(QI), 민감 속성(SA) 분류             │
│          │                                                             │
│          ▼ [2단계: 가명/비식별 조치]                                   │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │              비식별화 변환 엔진 (ARX Data Anonymizer)          │   │
│   │  - 식별자: HMAC-SHA256 토큰화 (Salt는 HSM에 격리 보관)         │   │
│   │  - 준식별자: 주소 동->구 일반화, 나이 10세 단위 범주화         │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   │                                    │
│                                   ▼ [3단계: 프라이버시 모델 검증]      │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ k-익명성(k=5), l-다양성(l=3), t-근접성(t=0.2) 수식 자동 연산   │   │
│   └───────┬────────────────────────────────────────────────┬───────┘   │
│           │ [통과 (재식별 위험 < 임계치)]                  │ [미달]    │
│           ▼                                                ▼           │
│   [4단계: 데이터 반출 승인]                         [추가 억제/노이즈]  │
│   (분석가에게 가명 데이터셋 안전 제공)               (파라미터 재조정)   │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 보호 기술 | 프라이버시 보호 수준 | 데이터 분석 유용성 | 구현 복잡도 | 주요 적용 유스케이스 |
|---|---|---|---|---|
| **전통적 마스킹/가명화**| 낮음 (결합 시 재식별 취약) | **최고 (원형 데이터 유지)** | 매우 낮음 | 사내 개발/테스트 DB 구축 |
| **k-l-t 프라이버시 모델**| **중간~높음 (수학적 보장)** | **중간 (범주화로 해상도 저하)**| 중간 | **공공 데이터 개방, 학술 연구** |
| **차분 프라이버시 (DP)** | **최고 (정보이론적 증명)** | 낮음~중간 (잡음 왜곡 발생) | 높음 | 인구센서스 통계, 연합학습 훈련 |
| **합성 데이터 (Synthetic)**| **최우수 (실존 인물 매핑 전무)**| **우수 (상관관계 통계 복제)** | **매우 높음 (GAN/생성AI 필요)**| **의료 AI 학습, 금융 사기탐지 훈련** |
