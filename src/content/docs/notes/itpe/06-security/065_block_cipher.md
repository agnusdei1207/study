## 지식 로드맵 내 현재 위치

정보보안 → 암호학 → 대칭키 블록 암호(Block Cipher) 및 운용 모드

## 30초 인출

- **본질:** 평문 데이터를 고정된 크기의 블록(Block) 단위로 분할하여 동일한 크기의 암호문 블록으로 변환하는 대칭키 암호화 알고리즘
- **메커니즘:** 클로드 섀넌의 혼돈(Confusion, S-Box)과 확산(Diffusion, P-Box) 원리 → Feistel 또는 SPN 구조의 라운드 함수 반복 → 키 스케줄링 → 블록 운용 모드(CBC, CTR, GCM) 적용
- 통찰: 단순 블록 암호화에 그치지 않고 짧은 64비트 블록 충돌(Sweet32) 방어, 초기화 벡터(IV) 무작위성 확보, 패딩 오라클 공격 차단, 기밀성과 무결성을 동시 제공하는 인증 암호화(AES-GCM) 적용 필수

<details><summary>핵심 용어</summary>

- **블록 암호(Block Cipher):** 고정된 길이(예: 64비트, 128비트)의 입력을 비밀키를 사용하여 같은 길이의 암호문으로 일대일 대응 변환하는 알고리즘.
- **혼돈 (Confusion):** 암호문과 암호키 사이의 상관관계를 통계적으로 숨기는 성질(주로 비선형 치환 S-Box로 구현).
- **확산 (Diffusion):** 평문의 미세한 1비트 변화가 암호문 전체의 여러 비트에 파급되도록 하는 성질(주로 순열 P-Box 및 선형 혼합으로 구현).
- **Feistel 구조:** 블록을 좌우로 분할하여 라운드 함수를 단방향으로 적용하고 교차하는 구조(DES, SEED). 복호화 시 라운드 함수 역함수 불필요.
- **SPN 구조 (Substitution-Permutation Network):** 블록 전체에 치환층(S-Box)과 확산층(P-Box)을 번갈아 적용하는 구조(AES, ARIA). 높은 병렬성 제공.
- **AEAD(Authenticated Encryption with Associated Data):** 데이터 암호화(기밀성)와 메시지 인증 코드(무결성/인증)를 동시에 제공하는 현대적 운용 모드(GCM, CCM).

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 평문을 고정된 크기(64/128/256비트)의 블록 단위로 분할하여 비밀키로부터 유도된 라운드 키를 적용해 동일한 길이의 암호문 블록으로 치환하는 대칭키 암호 기술 |
| 목적 | 대용량 데이터의 고속 기밀성 보장, 통계적 분석 공격 방어, 검증된 운용 모드와 결합하여 무결성 및 인증(AEAD) 동시 달성 |

## Ⅱ. 블록 암호의 주요 설계 원리 및 특징

| 특징 | 세부 내용 | 구현 요소 |
|---|---|---|
| 혼돈 (Confusion) | 암호문과 암호키의 수학적 상관관계를 은닉하여 통계적 키 유출 공격 차단 | S-Box (비선형 치환) |
| 확산 (Diffusion) | 평문의 단 1비트 변경이 암호문 전체의 절반 이상을 뒤바꾸는 쇄도 효과(Avalanche Effect) 유발 | P-Box (순열), ShiftRows, MixColumns |
| 라운드 반복 구조 | 단순한 치환·순열 연산을 수십 회 반복(Round)하여 암호학적 복잡성과 안전성 극대화 | 키 스케줄러 (Round Key Generator) |
| 가변 길이 처리 모드 | 단일 블록 크기를 초과하는 임의 길이 평문을 안전하게 암호화하기 위해 다양한 운용 모드 제공 | CBC, CTR, GCM, XTS |

## Ⅲ. 블록 암호 핵심 아키텍처(Feistel vs SPN) 및 라운드 프로세스

```text
[ 1. Feistel 구조 (DES, SEED) ]                 [ 2. SPN 구조 (AES, ARIA) ]
        평문 블록 (2w 비트)                             평문 블록 (128 비트)
          ┌──────┴──────┐                                      │
          ▼             ▼                                      ▼
      [ L_{i-1} ]   [ R_{i-1} ] ───┐                  ┌──▶ [ AddRoundKey ] (키 결합)
          │             │          │                  │        │
          │             ▼          │                  │        ▼
          │         [ 함수 F ] ◀── 라운드키 K_i       │    [ SubBytes ] (S-Box 비선형 치환)
          │             │                             │        │
          ▼             ▼                             │        ▼
       ( XOR ) ◀────────┘                             │    [ ShiftRows ] (행 단위 순환 이동)
          │                                           │        │
          ▼                                           │        ▼
       [ R_i ]       [ L_i ]                          │    [ MixColumns ] (열 단위 선형 혼합)
          └──────┬──────┘                             │        │
                 ▼                                    └────────┴── 라운드 반복 (10~14회)
         좌우 블록 스왑 (Swap)                                 ▼
                                                        최종 암호문 블록 도출
```

| 구조 유형 | 동작 메커니즘 | 암호화/복호화 대칭성 | 대표 알고리즘 |
|---|---|---|---|
| Feistel 구조 | 블록을 $L, R$로 2등분하여 $L_i = R_{i-1}$, $R_i = L_{i-1} \oplus F(R_{i-1}, K_i)$ 수행 | 동일 회로 사용 (라운드 키 순서만 역순) | DES, 3DES, SEED |
| SPN 구조 | 전체 블록에 키 결합 $\rightarrow$ 치환층(S-Box) $\rightarrow$ 확산층(P-Box)을 병렬 적용 | 역변환을 위한 별도 복호화 모듈 필요 | AES, ARIA, LEA |

## Ⅳ. Feistel vs SPN 비교 및 주요 운용 모드 비교

### 1. Feistel 구조와 SPN 구조 비교

| 구분 | Feistel 구조 | SPN 구조 (Substitution-Permutation) |
|---|---|---|
| 설계 복잡도 | 라운드 함수 $F$의 역함수가 불필요하여 하드웨어 설계 단순 | 치환과 순열의 역함수를 별도 구현해야 하므로 복호화 회로 추가 필요 |
| 처리 속도 | 매 라운드마다 블록의 절반만 연산되므로 상대적으로 느림 | 블록 전체를 한 번에 병렬 연산하므로 고속 암호화 가능 |
| 확산 속도 | 쇄도 효과가 나타나기까지 더 많은 라운드 수 요구 (DES 16라운드) | 1~2라운드 만에 빠른 전역 확산 달성 (AES 10~14라운드) |

### 2. 블록 암호 주요 운용 모드(Mode of Operation) 비교

| 모드 | 동작 원리 | 오류 전파 | 병렬 처리 | 무결성 인증 | 권장 여부 |
|---|---|---|---|---|---|
| ECB | 블록별 독립적 단순 암호화 | 없음 | 가능 | 미제공 | **절대 금지** (패턴 노출) |
| CBC | 이전 암호문 블록과 평문 XOR 후 암호화 | 해당 및 다음 블록 전파 | 복호화만 가능 | 미제공 | 패딩 오라클 취약 |
| CTR | 카운터 값을 암호화하여 평문과 XOR | 없음 | 암·복호화 모두 가능 | 미제공 | 고속 스트림 방식 |
| **GCM** | **CTR 모드 암호화 + GHASH 기반 GMAC 결합** | **인증 태그 불일치 시 전체 폐기** | **완전 병렬 처리 가능** | **제공 (AEAD)** | **최신 글로벌 표준 권장** |

## Ⅴ. 블록 암호 운용의 한계와 방안

| 한계 | 방안 |
|---|---|
| 64비트 레거시 블록 암호(3DES, Blowfish) 사용 시 생일 역설(Birthday Paradox)로 인해 $2^{32}$개(약 32GB) 블록 처리 시 블록 충돌(Sweet32 공격) 발생 | 블록 크기가 128비트 이상인 현대 표준 블록 암호(AES, ARIA, LEA)로 즉각 전면 전환하고 TLS 1.3에서 64비트 알고리즘 전면 퇴출 |
| CBC 모드 적용 시 PKCS#7 패딩 처리 오류 메시지를 악용한 패딩 오라클(Padding Oracle) 및 비트 플리핑(Bit-flipping) 평문 복원 취약점 노출 | 기밀성과 무결성을 단일 알고리즘 내에서 암호학적으로 동시에 보장하는 AEAD 인증 암호화 모드(AES-GCM, ChaCha20-Poly1305) 의무 적용 |
| 고속 CTR 및 GCM 운용 모드에서 동일한 암호키로 초기화 벡터(IV/Nonce)가 중복 사용(Nonce-Reuse)될 경우 키스트림 노출 및 인증 태그 위조 위험 | 96비트 암호학적 난수 생성기를 적용하거나 단조 증가 카운터 기반 Nonce를 강제하고, 일정 데이터 전송량 도달 시 키 갱신(Rekeying) 프로토콜 구축 |

## Ⅵ. 제언

```text
[ 레거시 취약 모드 ]                 [ 현대적 고성능 AEAD 표준 체계 ]
64비트 DES/3DES ─────┐               ┌── 128비트 AES / 국산 경량 LEA 채택
패딩 오라클 취약 CBC ┼─→ [ 침해 노출 ] ─┼── AES-GCM (기밀성 + 무결성 단일 패스)
별도 HMAC 결합 복잡 ─┘               └── 하드웨어 가속(AES-NI) 및 자동 키 회전
```

| 평가 영역 | 과거 레거시 암호 체계 | 최신 블록 암호 체계 | 향후 발전 방향 |
|---|---|---|---|
| 블록 안전성 | 64비트 (Sweet32 충돌) | 128비트 이상 (충돌 내성) | 256비트 양자 그로버 내성 키 길이 |
| 운용 모드 | ECB / CBC (패딩 취약) | GCM / CCM (AEAD 표준) | 부채널 내성 Masked AES 하드웨어 |
| 처리 성능 | 소프트웨어 직렬 처리 | AES-NI 하드웨어 병렬 처리 | 초경량 IoT 전용 블록 암호(LEA) 확산 |

블록 암호는 현대 데이터 보안의 핵심 원천 기술이며, 알고리즘 자체의 수학적 안전성을 넘어 AES-GCM과 같은 안전한 AEAD 운용 모드와 엄격한 Nonce 라이프사이클 관리를 결합하는 것이 암호학적 무결성을 완성하는 핵심.
