## Ⅰ. 블록 암호(Block Cipher)의 개요

- 개념 : 평문을 고정된 크기(64/128/256비트)의 블록 단위로 분할하여 비밀키로부터 유도된 라운드 키를 적용해 동일한 길이의 암호문 블록으로 치환하는 대칭키 암호 기술.
- 배경 및 필요성 : 대용량 정형/비정형 디지털 데이터를 고속으로 암호화하여 기밀성을 보장하고, 클라우드 스토리지 및 네트워크 전송 구간에서 데이터 무결성과 안전성을 확보하기 위해 Feistel 및 SPN 기반 암호 구조가 필수적으로 발전함.
- 핵심 목적 : 대용량 데이터의 고속 기밀성 보장, 통계적 분석 공격 방어, 검증된 운용 모드와 결합하여 무결성 및 인증(AEAD) 동시 달성.

## Ⅱ. 블록 암호(Block Cipher)의 핵심 아키텍처 및 동작 메커니즘

블록 암호(Block Cipher)은(는) 신뢰할 수 있는 보안 구조와 표준화된 절차를 기반으로 동작하며, 세부적인 아키텍처와 구성요소 간의 상호작용 메커니즘은 다음과 같음.

```text
[ 1. Feistel 구조 (DES, SEED) ]                 [ 2. SPN 구조 (AES, ARIA) ]
        평문 블록 (2w 비트)                             평문 블록 (128 비트)
          ┌──────┴──────┐                                      │
          ▼             ▼                                      ▼
      [ L_{i-1} ]   [ R_{i-1} ] ───┐                  ┌──▶ [ AddRoundKey ] (키 결합)
          │             │          │                  │        │
          │             ▼          │                  │        ▼
          │         [ 함수 F ] ◀── 라운드키 K_i       │    [ SubBytes ] (S-Box 비선형 치환)
          │             │                             │        │
          ▼             ▼                             │        ▼
       ( XOR ) ◀────────┘                             │    [ ShiftRows ] (행 단위 순환 이동)
          │                                           │        │
          ▼                                           │        ▼
       [ R_i ]       [ L_i ]                          │    [ MixColumns ] (열 단위 선형 혼합)
          └──────┬──────┘                             │        │
                 ▼                                    └────────┴── 라운드 반복 (10~14회)
         좌우 블록 스왑 (Swap)                                 ▼
                                                        최종 암호문 블록 도출
```

- **Feistel 구조** : 블록을 $L, R$로 2등분하여 $L_i = R_{i-1}$, $R_i = L_{i-1} \oplus F(R_{i-1}, K_i)$ 수행 (동일 회로 사용 (라운드 키 순서만 역순)).
- **SPN 구조** : 전체 블록에 키 결합 $\rightarrow$ 치환층(S-Box) $\rightarrow$ 확산층(P-Box)을 병렬 적용 (역변환을 위한 별도 복호화 모듈 필요).

## Ⅲ. 블록 암호(Block Cipher)의 세부 구성 요소 및 비교 분석

| 구분 | Feistel 구조 | SPN 구조 (Substitution-Permutation) |
|---|---|---|
| 설계 복잡도 | 라운드 함수 $F$의 역함수가 불필요하여 하드웨어 설계 단순 | 치환과 순열의 역함수를 별도 구현해야 하므로 복호화 회로 추가 필요 |
| 처리 속도 | 매 라운드마다 블록의 절반만 연산되므로 상대적으로 느림 | 블록 전체를 한 번에 병렬 연산하므로 고속 암호화 가능 |
| 확산 속도 | 쇄도 효과가 나타나기까지 더 많은 라운드 수 요구 (DES 16라운드) | 1~2라운드 만에 빠른 전역 확산 달성 (AES 10~14라운드) |

| 모드 | 동작 원리 | 오류 전파 | 병렬 처리 | 무결성 인증 | 권장 여부 |
|---|---|---|---|---|---|
| ECB | 블록별 독립적 단순 암호화 | 없음 | 가능 | 미제공 | 절대 금지 (패턴 노출) |
| CBC | 이전 암호문 블록과 평문 XOR 후 암호화 | 해당 및 다음 블록 전파 | 복호화만 가능 | 미제공 | 패딩 오라클 취약 |
| CTR | 카운터 값을 암호화하여 평문과 XOR | 없음 | 암·복호화 모두 가능 | 미제공 | 고속 스트림 방식 |
| **GCM** | CTR 모드 암호화 + GHASH 기반 GMAC 결합 | 인증 태그 불일치 시 전체 폐기 | 완전 병렬 처리 가능 | 제공 (AEAD) | 최신 글로벌 표준 권장 |

- 블록 암호(Block Cipher)은(는) 상기 핵심 비교 지표와 아키텍처 구성을 바탕으로 보안 위협에 대한 방어 효과성을 극대화하며, 기존 레거시 통제 기법 대비 우수한 신뢰성과 운영 효율성을 제공함.

## Ⅳ. 블록 암호(Block Cipher)의 주요 한계점 및 해결 방안

- 한계점 : 64비트 레거시 블록 암호(3DES, Blowfish) 사용 시 **생일 역설** (Birthday Paradox)로 인해 $2^{32}$개(약 32GB) 블록 처리 시 블록 충돌(Sweet32 공격) 발생.
  - 해결 방안 : 블록 크기가 128비트 이상인 현대 표준 블록 암호(AES, ARIA, LEA)로 즉각 전면 전환하고 TLS 1.3에서 64비트 알고리즘 전면 퇴출.
- 한계점 : CBC 모드 적용 시 PKCS#7 패딩 처리 오류 메시지를 악용한 **패딩 오라클** (Padding Oracle) 및 비트 플리핑(Bit-flipping) 평문 복원 취약점 노출.
  - 해결 방안 : 기밀성과 무결성을 단일 알고리즘 내에서 암호학적으로 동시에 보장하는 **AEAD 인증 암호화 모드** (AES-GCM, ChaCha20-Poly1305) 의무 적용.
- 한계점 : 고속 CTR 및 GCM 운용 모드에서 동일한 암호키로 초기화 벡터(IV/Nonce)가 중복 사용(Nonce-Reuse)될 경우 키스트림 노출 및 인증 태그 위조 위험.
  - 해결 방안 : 96비트 암호학적 난수 생성기를 적용하거나 단조 증가 카운터 기반 Nonce를 강제하고, 일정 데이터 전송량 도달 시 **키 갱신** (Rekeying) 프로토콜 구축.

## Ⅴ. 블록 암호(Block Cipher) 적용 및 발전을 위한 기술사적 제언

- **128비트 AES / 국산 경량 LEA 채택** 체계 도입 : 128비트 AES / 국산 경량 LEA 채택 기술을 적극 적용하여 보안 취약점을 차단하고 시스템 신뢰성을 보장해야 함.
- **AES-GCM** (기밀성 + 무결성 단일 패스) 체계 도입 : AES-GCM (기밀성 + 무결성 단일 패스) 기술을 적극 적용하여 보안 취약점을 차단하고 시스템 신뢰성을 보장해야 함.
- **하드웨어 가속(AES-NI) 및 자동 키 회전** 체계 도입 : 하드웨어 가속(AES-NI) 및 자동 키 회전 기술을 적극 적용하여 보안 취약점을 차단하고 시스템 신뢰성을 보장해야 함.
