## 핵심 용어
- 취약한 접근 통제(Broken Access Control): 사용자가 다른 사용자의 데이터에 접근하거나(수평적 권한 상승), 일반 사용자가 관리자 페이지에 접근할 수 있는(수직적 권한 상승) 권한 검증 누락 결함
- 안전하지 않은 설계(Insecure Design): 코드 작성 이전의 아키텍처 및 요구사항 설계 단계에서 위협 모델링과 보안 통제 설계가 누락되어 발생하는 근본적 구조 결함

## 핵심 통찰
- 오랫동안 1위를 지키던 '인젝션(SQL Injection)'이 3위로 내려앉고 '취약한 접근 통제'가 1위로 올라섬 → ORM 프레임워크 보급으로 단순 SQL 문법 버그는 줄었으나, 권한 로직 누락은 프레임워크가 대신 해결해 주지 못하기 때문
- A04(Insecure Design)의 신설은 "코드를 아무리 버그 없이 깔끔하게 짜도, 설계 자체가 잘못되었으면 해킹당한다"는 패러다임 전환을 의미함 (예: 비밀번호 재설정 질문을 '출신 초등학교'로 설계한 것)
- A06(Vulnerable Components)은 Log4j 사태에서 보듯 자체 코드가 완벽해도 외부 라이브러리 하나로 시스템 전체가 장악될 수 있음을 경고함

## 이웃 토픽과 구분
- CWE Top 25 vs OWASP Top 10: CWE = 구체적인 소스코드 수준 버그(버퍼 오버플로우, 널 포인터 역참조 등) 목록 / OWASP = 웹 서비스 비즈니스 위험 중심의 상위 범주화

## 문제·원인·대책
- 사례: URL 주소의 파라미터 `user_id=100`을 `user_id=101`로 변경하자 타인의 주문 내역이 그대로 노출된 IDOR(Insecure Direct Object Reference) 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 파라미터 변조를 통한 타인 계정 정보 무단 열람 | 서버 컨트롤러에서 현재 로그인 세션과 요청 객체 간 소유권 검증 누락 | 개별 객체 접근 시 세션 기반 권한 검증(ABAC/RBAC) 미들웨어 강제 | 비인가 사용자의 타인 데이터 접근 원천 차단 |
| 오픈소스 라이브러리 제로데이 취약점 유입 | 프로젝트 의존성 라이브러리의 버전 관리 부재 | CI/CD 파이프라인에 SCA(Software Composition Analysis) 도구 연동 | CVE 취약점 포함 라이브러리 빌드 시 자동 차단 |
