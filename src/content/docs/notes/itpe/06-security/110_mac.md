## 연관 키워드

- 메시지 인증 코드(MAC), HMAC, CMAC, GMAC, 인증 태그(Tag)
- 대칭키(Symmetric Key), 무결성, 메시지 출처 인증, 디지털 전자서명
- 재전송 공격, 타이밍 공격, 부인방지, 상수 시간 비교

## Ⅰ. 메시지 인증 코드의 개요

- 핵심 요약 : 공유한 대칭키로 메시지마다 인증 태그를 만들어 무결성과 출처를 확인하는 대칭키 기반 암호 기술.
- 개념 : 송신자와 수신자가 사전에 공유한 **대칭키** (Symmetric Key) K로 메시지 M에서 고정 길이의 **인증 태그** (Tag)를 생성해 데이터의 **무결성**과 메시지 출처를 확인하는 기술 (**메시지 인증 코드**, MAC).
- 배경 및 필요성 : 전송 중 제3자의 변조나 위조를 탐지하고 송신자 정당성을 확인해야 하지만, 공개키 연산은 고속 통신에 비용이 커서 대칭키 기반 인증 수단이 요구됨.
- 주요 목적 : 패킷 변조와 위조를 탐지하고, 대칭키 기반의 고속 인증 채널을 구현하는 것.

## Ⅱ. 메시지 인증 코드의 특징 및 장점

- 핵심 요약 : 대칭키 연산의 속도와 단순성이 고속 무결성 검증이라는 장점으로 이어지는 구조.

1. 고속 연산 : 해시나 블록 암호 기반의 대칭키 연산만 사용 → 실시간 패킷 검증에 적합.
2. 무결성 검증 : 태그가 메시지 전체를 덮으므로 한 비트만 바뀌어도 불일치 → 변조 탐지.
3. 하드웨어 가속 : CPU의 AES 명령어 집합을 활용 → 임베디드와 금융 단말에서도 부담이 적음.

```text
[ MAC 생성·검증 흐름 ]

송신자: 태그 T = MAC(K, M) 생성
   ↓
메시지 M과 태그 T 전송
   ↓
수신자: T' = MAC(K, M) 재계산
   ↓
상수 시간 비교 (T == T')
```

- 기반 알고리즘 : 해시 기반 HMAC(RFC 2104, FIPS 198-1)과 블록 암호 기반 CMAC(NIST SP 800-38B, RFC 4493).
- 해시 기반 구성 : `HMAC(K, M) = H((K ⊕ opad) ∥ H((K ⊕ ipad) ∥ M))`, 단순 `H(K ∥ M)` 방식이 가진 길이 확장 공격을 막기 위한 이중 해시 구조.
- 주 활용 분야 : JWT 서명, IPsec, TLS의 HMAC 기반 레코드 보호.

## Ⅲ. 메시지 인증 코드의 구조 (흐름)

- 핵심 요약 : 송신자는 공유키로 태그를 붙이고, 수신자는 같은 키로 재계산해 상수 시간에 비교하는 대칭 구조.
- **상수 시간 비교** (Constant-Time Comparison) : 불일치 위치와 무관하게 비교 시간이 일정하도록 구현한 태그 검증 방식.

```text
[ 송신 단계 ]

메시지 M + 공유키 K
   ↓
MAC 생성 → 태그 T
   ↓
(M, T) 전송
```

```text
[ 수신 단계 ]

수신 (M, T) + 공유키 K
   ↓
MAC 재계산 → T'
   ↓
상수 시간 비교: T == T'
   ▸ 일치 : 무결성·출처 인증 성공
   ▸ 불일치 : 패킷 폐기
```

## Ⅳ. 메시지 인증 코드와 디지털 전자서명의 비교

- 핵심 요약 : MAC은 빠르고 가볍지만 부인방지를 줄 수 없고, 전자서명은 느리지만 제3자 검증과 부인방지를 제공.

| 비교 항목 | 메시지 인증 코드 (MAC) | 디지털 전자서명 (Digital Signature) |
| --- | --- | --- |
| 사용 키 | 송수신자 간 공유 대칭키 | 송신자 개인키로 서명, 수신자 공개키로 검증 |
| 연산 속도 | 빠름 | 상대적으로 느림 (비대칭 연산) |
| 메시지 무결성 | 보장 | 보장 |
| 송신자 인증 | 키를 공유한 상대방 사이에서만 가능 | 누구나 공개키로 검증 가능 |
| 부인방지 | 불가 (수신자도 태그를 만들 수 있음) | 가능 (개인키 보유자만 서명 가능) |
| 키 관리 | 쌍별 공유키가 참여자 수의 제곱에 비례해 증가 | PKI 인증서 기반 공개키 관리 |

- 선택 기준 : 통신 상대가 고정되고 속도가 중요하면 MAC을, 분쟁 시 제3자 입증이 필요하면 전자서명을 선택.

## Ⅴ. 메시지 인증 코드의 한계와 방안

- 핵심 요약 : 재전송, 타이밍 누출, Nonce 재사용, 부인방지 부재가 MAC 운용의 주요 취약점.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 재전송 공격 (Replay Attack) | 도청한 정상 메시지와 태그를 그대로 다시 보내 인증 통과 | 메시지에 **시퀀스 번호**(Sequence Number)나 세션 Nonce를 포함하고 인증 범위에 결합 | 재전송 거부 건수 |
| 타이밍 공격 (Timing Attack) | 바이트 단위 순차 비교로 응답 시간 차이에서 태그 정보 누출 | 불일치와 무관하게 전체를 비교하는 상수 시간 비교 강제 | 비교 함수 감사 결과 |
| GMAC의 Nonce 재사용 | 동일 Nonce를 두 번 쓰면 인증 키 H가 노출될 수 있음 | 카운터 기반 Nonce를 강제하고 키 사용량 한도에 도달하면 키 갱신 | Nonce 중복 검출 건수 |
| 부인방지 부재 | 키를 공유하므로 분쟁 시 송신자 입증이 불가능 | 법적 책임이 큰 거래에는 X.509 전자서명과 타임스탬프 토큰을 복합 적용 | 분쟁 입증 실패 건수 |

## Ⅵ. 메시지 인증 코드 적용에 대한 기술사적 제언

- 핵심 요약 : 암호화와 인증을 하나의 검증된 모드로 묶고, 재전송 방어와 검증 모듈 관리를 표준으로 고정하는 방향.

1. 암호화 후 별도로 MAC을 붙이는 수작업 대신 AEAD 표준 모드 하나로 통일하면, 결합 오류와 패딩 오라클 위험을 함께 줄일 수 있다.
2. 시퀀스 번호 검증과 슬라이딩 윈도우 기반 재전송 방어를 통신 표준에 포함시키면 결제 같은 거래의 중복 처리를 막을 수 있다.
3. 검증 모듈은 공인 암호 모듈 인증을 받은 라이브러리로 제한하고, 상수 시간 비교 API 사용을 코드 점검 항목으로 삼는 것이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : MAC은 공유 비밀을 전제로 한 고속 무결성 장치이며, 부인방지가 필요한 곳에서는 전자서명과 함께 쓰는 기술.
- 시사점 : 키 공유 구조와 재전송 방어를 함께 설계하는 조직만이 MAC의 속도 장점을 안전하게 누릴 수 있다.
