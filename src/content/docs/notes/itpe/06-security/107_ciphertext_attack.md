## 지식 로드맵 내 현재 위치

정보보안 → 암호 분석학(Cryptanalysis) → 암호문 단독 공격(Ciphertext-Only Attack, COA)

## 30초 인출

- **본질:** 공격자가 평문이나 비밀키, 암·복호화 오라클에 대한 어떠한 사전 정보도 없이 오직 도청된 암호문(Ciphertext)만을 관찰하여 평문이나 비밀키를 유추하는 가장 기본적인 암호 해독 기법.
- **메커니즘:** 도청된 암호문의 통계적 문자 빈도, 블록 간 반복 패턴(ECB), 패킷 길이 및 전송 타이밍을 분석하여 평문의 통계적 편향성을 역추적.
- 통찰: 암호문 단독 공격을 방어하기 위해 샤논의 완전 안전성(Perfect Secrecy) 원리를 이해하고, 현대 블록 암호에서는 충분한 라운드의 혼돈/확산과 무작위 IV 기반 운용 모드(CBC/GCM) 적용 필수.

<details><summary>핵심 용어</summary>

- **암호문 단독 공격(COA, Ciphertext-Only Attack)**: 공격자에게 가장 불리한 조건으로, 오직 암호문 데이터만을 가지고 평문이나 키를 찾는 암호 분석 모델.
- **완전 안전성(Perfect Secrecy)**: 암호문 C를 관찰한 후에도 평문 M에 대한 사후 확률이 사전 확률과 완전히 동일한 상태($P(M|C) = P(M)$).
- **빈도 분석(Frequency Analysis)**: 자연어의 특정 알파벳이나 바이트가 나타나는 통계적 빈도를 암호문의 출현 빈도와 대조하여 치환표를 복원하는 공격 기법.
- **ECB 모드 결함(ECB Penguin)**: 동일한 평문 블록이 항상 동일한 암호문 블록으로 매핑되어, 데이터 전체의 윤곽과 패턴이 암호문 상태로 노출되는 현상.
- **트래픽 분석(Traffic Analysis)**: 암호문 본문을 복호화하지 않고도 패킷의 크기, 발생 빈도, 통신 주기를 관찰하여 업무 내용이나 통신 프로토콜을 추론하는 기법.
</details>

## 2~4교시 예상문제 (25점)

> 암호 해독의 기본 모델인 암호문 단독 공격(Ciphertext-Only Attack)의 개념과 공격자가 활용하는 통계적·구조적 분석 기법을 설명하고, 샤논(Shannon)의 완전 안전성(Perfect Secrecy)과 현대 블록 암호 운용 모드(ECB, CBC, GCM)에서의 엔지니어링 방어 방안을 제시하시오. (기출·제137회 1교시 4번)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 공격자가 도청을 통해 가로챈 암호문(Ciphertext) 스트림만을 유일한 단서로 삼아, 대응하는 평문(Plaintext)이나 암호키(Key)를 알아내려는 가장 수동적인 암호 분석 모델 |
| 목적 | 가장 열악한 정보 조건에서도 암호 시스템이 해독되지 않도록 통계적 패턴 노출을 원천 차단하고 현대 암호학적 계산 안전성(Computational Security) 확보 |

## Ⅱ. 암호문 단독 공격(COA)의 핵심 특징 및 공격 기법

| 특징 항목 | 세부 동작 메커니즘 | 공격자의 분석 관점 |
|---|---|---|
| 최소 사전 정보 | 공격자는 평문-암호문 쌍(Pair)이나 암호화 장치에 접근 불가 | 도청된 암호문 패킷의 비트열 자체에만 전적으로 의존 |
| 통계적 빈도 분석 | 평문 언어(영어 e, t, a 등)의 고유 출현 빈도가 암호문에 잔존하는 결함 추적 | 단순 대치 암호(Monoalphabetic Cipher)의 즉각 해독 |
| 구조적 반복 탐색 | 블록 암호의 ECB 모드처럼 동일 입력에 대한 동일 암호문 블록 패턴 식별 | 이미지 실루엣, 프로토콜 헤더, 고정 포맷 레코드 구조 식별 |
| 키스트림 재사용 추적 | 스트림 암호에서 동일한 키와 논스(Nonce)가 재사용될 때 암호문 간 XOR 분석 | 두 암호문의 XOR 연산($C_1 \oplus C_2 = P_1 \oplus P_2$)으로 평문 누출 |
| 메타데이터 분석 | 암호문 페이로드의 크기, 전송 주기, 버퍼 패딩 크기를 통한 사이드채널 분석 | 압축 후 암호화 시 발생하는 CRIME/BREACH 공격 연계 |

## Ⅲ. COA 공격 메커니즘 및 정보이론적 안전성(Perfect Secrecy) 아키텍처

```text
[ 1. 정보이론적 완전 안전성 (Information-Theoretic Security) ]
평문 M (n bits) ────▶ [ XOR 연산 ] ────▶ 암호문 C (n bits)
                             ▲
키 K (n bits, 완전 무작위) ──┘ (샤논의 원칙: P(M|C) = P(M), 키는 1회만 사용!)
- 암호문 C를 아무리 분석해도 평문 M에 대한 추가 정보 획득 확률 제로 (OTP 모델)

[ 2. 현대 계산적 안전성 (Computational Security) 아키텍처 ]
평문 블록 P_i ──────▶ [ 혼돈(Confusion) & 확산(Diffusion) 라운드 함수 ] ────▶ 암호문 C_i
                             ▲
의사난수 키 K (128/256 bits) ─┘ (충분한 계산 복잡도: 2^256 전수 공격 불가)
                             │
       ┌─────────────────────┴─────────────────────┐
       ▼ [취약한 운용: ECB 모드]                   ▼ [안전한 운용: CBC / GCM 모드]
동일 평문 ──▶ 항상 동일 암호문 블록 매핑     무작위 IV/Nonce 결합 ──▶ 동일 평문도 매번 다른 암호문
(패턴 및 이미지 윤곽 100% 노출!)            (통계적 무작위성 확보로 COA 원천 무력화)
```

| 분석 기법 | 분석 세부 절차 | 공격 대상 및 취약점 |
|---|---|---|
| 빈도 분석 (Frequency Analysis) | 암호문 내 단일 문자 및 n-gram(다이어그램/트라이그램) 빈도 분포 작성 | 시저(Caesar), 비즈네르(Vigenère) 등 고전 암호 |
| 전치 분석 (Transposition Analysis) | 문자의 빈도는 정상이지만 위치가 바뀐 패턴을 기하학적 매트릭스로 역추적 | 컬럼너(Columnar) 전치 암호, 레일 펜스(Rail Fence) |
| 반복 블록 탐색 (ECB Analysis) | 16바이트 단위로 분할된 암호문 블록 중 동일한 해시를 갖는 블록 클러스터링 | AES-ECB 모드, 전자문서 고정 서식 데이터 |
| 패킷 길이 분석 (Length Leakage) | 가변 길이 평문이 패딩 없이 암호화될 때 암호문 길이로 단어/명령어 추정 | VoLTE 음성 트래픽 분석, 압축된 웹 트래픽(CRIME) |
| 브루트 포스 (Brute-Force) | 키 공간이 작을 경우(예: DES 56-bit) 암호문 전체에 대해 가능한 키를 전수 대입 | 짧은 암호키, 취약한 패스워드 기반 키 유도(PBKDF) |

## Ⅳ. 암호문 공격(COA) 대상 취약 구성 비교

| 비교 항목 | 고전 단일 치환 암호 | 현대 블록 암호 (ECB 모드) | 안전한 현대 암호 (AES-GCM) |
|---|---|---|---|
| 주요 취약 요인 | 알파벳 출현 확률의 불균형 | 블록 간 무작위성(IV) 결여 | 취약 요인 없음 (정상 운영 시) |
| 암호문 특성 | 평문의 통계적 편향이 1:1 보존 | 동일 평문 블록이 동일 암호문 생성 | 동일 평문도 매 세션 완전히 다른 난수로 매핑 |
| COA 성공 여부 | 100% 해독 가능 (단 몇 줄의 암호문) | 부분 평문 및 데이터 윤곽 해독 가능 | COA 공격으로 해독 원천 불가능 |
| 안전성 보장 기준 | 없음 (수작업 해독 가능) | 계산적 안전성 미달 | IND-CPA 및 IND-CCA2 만족 |
| 권장 대응책 | 사용 금지 | CBC/GCM 운용 모드 전환 | 256-bit 키 및 고유 Nonce 사용 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 블록 암호 운용 시 구현 편의를 위해 ECB 모드를 채택하여 평문의 구조와 데이터 패턴이 암호문으로 누출 | ECB 모드를 사내 개발 표준에서 영구 퇴출(Banned)하고, 초기화 벡터(IV)를 필수 사용하는 CBC 모드 또는 인증 암호인 GCM 모드로 강제 전환 |
| 샤논의 완전 안전성을 제공하는 일회용 패드(OTP)는 평문과 동일한 길이의 키를 사전 공유해야 하는 '키 분배의 난제' 존재 | 정보이론적 안전성 대신 현대적 의사난수 생성기(AES-CTR/GCM) 기반의 계산적 안전성(Computational Security)을 채택하여 현실적 구현성 확보 |
| 암호화 페이로드는 안전하지만 패킷의 크기와 전송 주기(Inter-arrival Time)로 인해 어떤 영상이나 명령인지 추론되는 트래픽 누출 | 패킷 전송 시 고정 크기로 더미 바이트를 채우는 패킷 패딩(Traffic Padding) 및 가상 트래픽 주입(Chaffing) 기법 적용 |
| 저사양 임베디드 IoT 장비에서 난수 생성기(PRNG) 결함으로 키 공간이 축소되어 COA 전수 대입 공격에 노출 | 하드웨어 기반 TRNG(진성 난수 생성기)를 탑재하고 NIST SP 800-90A 표준을 통과한 암호학적 안전 난수(CSPRNG) 라이브러리 강제 |

## Ⅵ. 제언

```text
[ 암호문 단독 공격 무력화를 위한 3대 암호 설계 원칙 ]

+-------------------------+      +-------------------------+      +-------------------------+
|     1. 무작위 IV 강제   | ---> |     2. 인증 암호화(AEAD)| ---> |     3. 트래픽 마스킹    |
| (결정론적 패턴 완전 제거|      | (AES-256-GCM 표준화)    |      | (패킷 패딩/사이드채널 방어
+-------------------------+      +-------------------------+      +-------------------------+
```

| 설계 영역 | 엔지니어링 실무 구현 과제 | 비즈니스 가치 |
|---|---|---|
| 운용 모드 표준화 | 사내 모든 데이터베이스 및 통신 암호화에 AES-256-GCM 또는 ChaCha20-Poly1305 단일화 | 암호문 패턴 노출 및 무결성 변조 동시 차단 |
| 키 및 난수 관리 | CSPRNG 기반 유일한 IV/Nonce 생성 및 키 수명 관리(KMS 연동) 체계 구축 | Nonce 재사용으로 인한 키스트림 누출 위험 제로화 |
| 메타데이터 보호 | HTTPS/TLS 1.3 기반 ECH(Encrypted Client Hello) 및 고정 블록 패딩 적용 | 트래픽 분석 및 도청자를 통한 업무 행위 추론 원천 차단 |
