## 답안 골격
```text
[공격 표면(Attack Surface)] ◀━━ 머리: Ⅶ 내 의견 (자산 추가 시 보안 검토 탈피 → 불필요한 포트·기능의 원천 비활성화 및 상시 공격표면 축소(ASR))
 ┃
 ┣━ Ⅰ 개요 ───── 인가되지 않은 사용자가 시스템에 진입하거나 데이터를 추출할 수 있는 모든 잠재적 접점(점, 경로, 환경)의 총합
 ┣━ Ⅱ 특징 ───── 확장성(클라우드·IoT로 지속 확대) · 다계층성(SW, 네트워크, 인간, 물리) · 가변성(동적 컨테이너 생성/삭제) · 비례성(표면적↑ = 침해위험↑)
 ┣━ Ⅲ 구조 ───── 소프트웨어 공격표면(코드, API, 라이브러리) · 네트워크 공격표면(오픈 포트, 프로토콜, 라우팅) · 인간 공격표면(임직원, 협력사)
 ┣━ Ⅳ 흐름 ───── ① 전사 자산 및 외부 노출 접점 식별 → ② 공격표면 분석 및 위험 점수화 → ③ 불필요한 노출점 제거(포트 폐쇄, 최소 설치) → ④ 상시 감시 및 통제
 ┣━ Ⅴ 비교 ───── 공격 표면(Attack Surface: 침투 가능한 모든 영역의 총합) vs 공격 벡터(Attack Vector: 실제로 이용하는 특정 침투 경로)
 ┗━ Ⅵ 실무 ───── 클라우드 인프라 확장에 따른 섀도우 IT 폭증 / 레거시 인터페이스 방치 / 불필요한 서비스 기본 활성화 / ASR(공격표면축소) 룰 적용
```
- 필수 키워드: 공격 표면 · 공격표면 축소(ASR) · 소프트웨어 표면 · 네트워크 표면 · 인간 표면 · 섀도우 IT · 최소 권한
- 기출: 138회 3교시 5번 `IT 인프라 확장에 따른 사이버 위협(공격 벡터 및 공격 표면)` → Ⅰ 정의 + Ⅲ 3대 공격표면 + Ⅵ 축소 방안

## 한 줄 본질
- 시스템 기능과 외부 연결이 늘어날수록 침투 가능 접점이 비례하여 증가하는 복잡도 병목 → 불필요한 포트, 미사용 API, 과도한 권한을 선제적으로 제거하여 노출 면적을 최소화 → 침해 발생 확률 극소화 / 서비스 유연성 및 개발 편의성 제약 발생

## 핵심 그림
```text
[3대 공격 표면(Attack Surface) 구성 영역 및 축소 원리]

      ┌──────────────────────────────────────────────────┐
      │             [ 인간 공격 표면 ]                   │
      │  - 임직원 피싱 노출, 소셜 미디어 정보 노출       │
      │  - 협력사/외주 인력의 보안 인식 부재             │
      └─────────────────────────┬────────────────────────┘
                                │
      ┌─────────────────────────┴────────────────────────┐
      │            [ 네트워크 공격 표면 ]                │
      │  - 인터넷 개방 포트 (RDP, SSH, DB 등)           │
      │  - 취약한 VPN 게이트웨이, 미인가 Wi-Fi AP        │
      └─────────────────────────┬────────────────────────┘
                                │
      ┌─────────────────────────┴────────────────────────┐
      │           [ 소프트웨어 공격 표면 ]               │
      │  - 오픈소스 라이브러리(CVE), 공개 REST API       │
      │  - 레거시 관리자 웹페이지, 미인증 엔드포인트     │
      └──────────────────────────────────────────────────┘
       * 대응 원칙: 공격표면 축소 (Attack Surface Reduction, ASR)
         "쓰지 않는 포트는 닫고, 쓰지 않는 코드는 삭제하라!"
```

## 핵심 용어
- 공격표면 축소(ASR, Attack Surface Reduction): 시스템 하드닝(Hardening), 불필요한 포트 및 기능 비활성화, 스크립트 실행 제한 등을 통해 공격자가 악용할 수 있는 취약 지점을 사전에 최소화하는 보안 조치
- 소프트웨어 공격표면(Software Attack Surface): 시스템 코드 실행에 영향을 줄 수 있는 입력 채널, 환경 변수, 파일 파서, API 엔드포인트의 총합

## 핵심 통찰
- 공격 표면은 보안 장비 도입으로 줄어들지 않음 → 아무리 고가의 WAF를 설치해도 외부에 공개된 불필요한 테스트용 웹서버가 10개 있다면 공격 표면은 여전히 넓은 것임
- 가장 강력한 보안은 '존재하지 않는 것'임 → 포트가 닫혀 있으면 0-Day 취약점이 있어도 익스플로잇 자체가 도달하지 못함
- 클라우드 네이티브 환경에서는 IaC(Terraform 등)를 통해 서버가 수초 만에 수백 대 생성되므로, 개발 단계에서 기본 베이스 이미지를 최소화(Minimal/Distroless 컨테이너)하는 것이 표면 축소의 핵심임

## 이웃 토픽과 구분
- 취약점 vs 공격 표면: 취약점 = 시스템 내에 존재하는 구체적 결함(버그) / 공격 표면 = 취약점이 존재할 수 있는 노출된 모든 인터페이스의 총량

## 문제·원인·대책
- 사례: 기본 이미지에 포함된 불필요한 SSH 및 디버그 포트가 클라우드 배포 시 외부에 열려 있어 무차별 대입 공격에 노출된 사례
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 컨테이너 내 불필요한 유틸리티(curl, bash)로 인한 공격표면 노출 | 풀 패키지 OS 베이스 이미지(Ubuntu 등) 남용 | Distroless 및 최소 경량(Alpine) 컨테이너 베이스 이미지 적용 | 침투 후 공격자의 셸 명령어 실행 및 측면 이동 원천 봉쇄 |
| 개발/테스트 목적 임시 포트의 영구 방치 | 변경 관리 프로세스 부재 및 프로젝트 종료 후 정리 미흡 | 공격표면관리(ASM) 도구를 통한 외부 개방 포트 상시 자동 회수 | 인터넷 노출 접점 최소화 유지 |

## 이렇게 출제된다
- 제138회 3교시 5번: "IT 인프라 확장에 따른 사이버 위협에 대하여 다음 내용을 설명하시오." → 요구 포인트: Ⅰ 인프라 확장에 따른 공격 표면 증가 문제 + Ⅲ 공격 표면의 구성 분류 + Ⅵ 공격 표면 축소(ASR) 실무 전략

## 내 의견
- [기능 편의성을 위한 기본값 '모두 허용' 관행] 인프라 프로비저닝 시 방화벽 룰을 `0.0.0.0/0 All Open`으로 설정하고 방치하는 개발 관행 만연 → 나라면: CI/CD 배포 파이프라인에 OPA(Open Policy Agent)를 결합하여 인바운드 개방 포트가 명시적 승인 목록(Whitelist)에 없으면 배포 자체를 원천 거부하는 '기본 차단(Deny-by-default) 공격표면 통제' 제도화
