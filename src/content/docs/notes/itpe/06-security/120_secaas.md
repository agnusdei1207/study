## 지식 로드맵 내 현재 위치

지식 위치: 클라우드 보안 → 서비스형 보안 기능 → **SECaaS**

## 30초 인출

- **본질:** 하드웨어 어플라이언스 구매 없이 클라우드 인프라를 통해 보안 기능(SWG, CASB, WAF, SIEM 등)을 온디맨드 구독형으로 제공받는 서비스 모델
- **메커니즘:** 트래픽 수집(인라인 프록시/API/에이전트) → 클라우드 PoP 보안 엔진(트래픽 복호화·위협 분석·정책 매칭) → 차단/허용 제어 및 통합 대시보드 관제
- **통찰:** 인라인 트래픽 집중에 따른 네트워크 레이턴시와 PoP 단일 장애점은 애니캐스트 라우팅과 로컬 브레이크아웃으로 분산하고 공유 책임 모델 기반 형상 관리를 동시 수행 필수

<details>
<summary>핵심 용어</summary>

- **SECaaS** : 보안 솔루션 구축 없이 클라우드 서비스 형태로 제공받는 클라우드 기반 보안(Security as a Service).
- **인라인 프록시 (Inline Proxy)** : 트래픽 흐름의 중간에 위치하여 실시간 패킷 복호화, 검사, 차단을 수행하는 전송 모델.
- **API 연동형 (Out-of-band)** : 클라우드 서비스(SaaS/IaaS)의 감사 API를 폴링하여 비인가 설정 및 데이터 유출을 사후 탐지하는 모델.
- **SSE (Security Service Edge)** : SWG, CASB, ZTNA 등을 단일 클라우드 플랫폼으로 통합한 SECaaS 아키텍처.

</details>

## 2~4교시 예상문제 (25점)

> SECaaS(Security as a Service)의 개념, 제공 방식별 아키텍처, 주요 기능 범주를 설명하고, 대규모 트래픽 환경 도입 시 발생하는 네트워크·데이터 프라이버시 한계와 엔지니어링 대응 방안을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 온프레미스 보안 장비 구축 대신 클라우드 컴퓨팅 인프라를 통해 보안 소프트웨어와 보안 관제 기능을 구독형(Subscription)으로 제공하는 보안 운영 모델 |
| 목적 | 초기 대규모 CAPEX(자본적 지출) 투자를 OPEX(운영비용)로 전환하고, 분산된 재택·지사 사용자에게 일관된 보안 정책을 신속하게 배포 및 확장 |

- 클라우드 전환 및 하이브리드 근무 환경에서 기존 데이터센터 중심의 성벽형(Castle-and-Moat) 보안 경계가 붕괴됨에 따라 트래픽 발생 지점 근접 보안 처리가 핵심 요구사항으로 대두

## Ⅱ. SECaaS의 기술적 특징

| 특징 항목 | 세부 내용 및 기술적 가치 | 비즈니스·운영 효과 |
|---|---|---|
| 탄력적 확장성 (Scalability) | 클라우드 오토스케일링 기반으로 대규모 트래픽 급증(DDoS, 계절성 트래픽) 시 자동 확장 | 장비 사이징 실패로 인한 서비스 병목 및 용량 초과 장애 방지 |
| 신속한 위협 인텔리전스 | 글로벌 PoP에서 수집된 제로데이 위협 정보를 전 세계 테넌트에 실시간 즉시 반영 | 개별 벤더 시그니처 수동 패치 지연(Window of Vulnerability) 최소화 |
| 중앙 집중식 단일 정책 | 본사, 지사, 원격 근무자 단말에 관계없이 통합 웹 콘솔에서 일관된 보안 정책 배포 | 섀도우 IT 및 단말 위치에 따른 보안 정책 편차(Drift) 제거 |
| 유지보수 및 TCO 절감 | 하드웨어 EOL(수명종료) 교체, 펌웨어 핫픽스, 랙 상면 및 전력 비용 완전 제거 | 인력 부족 기업의 전문 보안 운영 리소스 확보 및 총소유비용 40% 이상 절감 |

- 클라우드 네이티브 아키텍처를 기반으로 단일 관리 콘솔에서 멀티 테넌시(Multi-Tenancy) 격리를 보장하며 글로벌 통합 가시성 제공 특성 보유

## Ⅲ. SECaaS 트래픽 제공 아키텍처 및 메커니즘

```text
[SECaaS 아키텍처 및 트래픽 연계 3대 모델]

 ┌─────────────────┐
 │ 사용자 및 단말   │
 └────────┬────────┘
          │
          ├── [1. 인라인 프록시형] ──────────────────────────┐
          │   (PAC/IPsec/GRE 터널링)                        ▼
          │                                        ┌─────────────────────────┐
          ├── [2. 에이전트/로그형] ─-┐              │   SECaaS 글로벌 PoP     │
          │   (Telemetry/Syslog)     │             │  - SSL/TLS 복호화 엔진  │
          │                          ▼             │  - 차세대 WAF / SWG     │
          │                  ┌──────────────┐      │  - CASB / DLP / ZTNA    │
          │                  │ Cloud SIEM   │      │  - 위협 인텔리전스 DB   │
          │                  │ Threat Intel │      └───────────┬─────────────┘
          │                  └──────────────┘                  │
          │                                                    ▼ (검사 완료 트래픽)
          └── [3. API 연동형 (Out-of-band)]                ┌─────────────────────────┐
              (CSPM / SaaS 감사 로그 연계)                │ 외부 인터넷 / SaaS 앱   │
              ──────────────────────────────────────────> │ (M365, Salesforce, AWS) │
                                                           └─────────────────────────┘
```

| 제공 모델 | 동작 메커니즘 | 적용 보안 기능군 | 장단점 분석 |
|---|---|---|---|
| 인라인 프록시 (Inline Proxy) | DNS 변경 또는 IPsec/GRE 터널을 통해 사용자 트래픽을 SECaaS PoP로 강제 경유 | SWG, 클라우드 WAF, DDoS 방어, CASB 프록시, ZTNA | 실시간 차단 가능, 네트워크 홉 증가로 인한 레이턴시 발생 가능 |
| API 연계형 (Out-of-Band) | SaaS/IaaS 공급자의 REST API와 OAuth 토큰으로 연동하여 비동기 데이터 검사 | CSPM, SSPM, SaaS DLP, 악성 저장 파일 검사 | 트래픽 지연 없음, 사용자 경험 유지, 위협 탐지까지 수분 지연 발생 |
| 단말 에이전트 (Agent-based) | 호스트 OS 커널 레벨에 경량 드라이버를 설치하여 프로세스 및 네트워크 행위 수집 | 클라우드 EDR, XDR, 호스트 방화벽, 취약점 스캐너 | 엔드포인트 심층 가시성 확보, OS 호환성 관리 및 리소스 점유 고려 |

## Ⅳ. SECaaS vs 온프레미스 어플라이언스 vs 관리형 보안관제(MSSP) 비교

| 비교 항목 | 클라우드 SECaaS | 온프레미스 어플라이언스 | 관리형 보안관제 (MSSP) |
|---|---|---|---|
| 구축 방식 | 클라우드 테넌트 생성 (수분 내 배포) | 전용 HW 구매, 데이터센터 랙 실장, 배선 | 고객사 인프라에 원격 관제 에이전트 연계 |
| 비용 구조 | 월/연 단위 구독형 (OPEX) | 대규모 초기 구매비 및 유지보수비 (CAPEX) | 관제 인력 파견 및 회선당 월 위탁 수수료 |
| 글로벌 커버리지 | 전 세계 분산 PoP 제공으로 로컬 접속 | 데이터센터로 트래픽 백홀링(Trombone 현상) | 고객사 물리 인프라 위치에 종속 |
| 최신 위협 대응 | 글로벌 클라우드 엔진 실시간 자동 업데이트 | 벤더 패턴 파일 수동 다운로드 및 핫픽스 | 관제 요원의 룰셋 튜닝 및 수동 대응 |
| 데이터 통제권 | 공급자 클라우드로 패킷 전송 (통제권 일부 양도) | 기업 내부망에서 평문 유지 (완전한 통제) | 데이터는 내부 유지, 로그만 외부 관제센터 전송 |

## Ⅴ. SECaaS 도입 시 기술적 한계와 엔지니어링 극복 방안

| 한계 | 방안 |
|---|---|
| 인라인 프록시 경유에 따른 RTT 지연 및 SECaaS PoP 장애 시 전사 인터넷 접속 전면 차단 (SPOF) | 글로벌 Anycast BGP 라우팅으로 최인접 PoP 자동 우회, 로컬 브레이크아웃(SD-WAN 연계) 적용, PoP 장애 시 바이패스(Fail-Open) 정책 수립 |
| TLS 패킷 검사를 위해 고객사 인증서 프라이빗 키 위임 시 내부 기밀 및 금융 개인정보 노출 위험 | 고객 관리형 암호화 키(CMEK/BYOK) 적용, 기밀 컴퓨팅(Enclave) 기반 복호화 처리, 금융/인사 등 민감 도메인은 SSL 검사 예외(Bypass) 룰 설정 |
| 클라우드 책임 공유 모델(Shared Responsibility) 미인지로 인한 고객 측 보안 설정 오류(Misconfiguration) | SECaaS와 CSPM/SSPM 솔루션을 통합 연동하여 보안 설정 드리프트(Drift)를 실시간 감사하고, RACI 매트릭스 기반 책임 한계 계약 명시 |
| 멀티 테넌트 환경에서 인접 테넌트의 대규모 트래픽 공격 유입 시 발생하는 자원 고갈(Noisy Neighbor) | 공급자 선정 시 완전한 테넌트별 컨테이너/VM 격리 아키텍처 및 컴퓨팅/대역폭 Quota 보장 SLA 확인 |

## Ⅵ. 안정적 SECaaS 전환을 위한 단계별 프레임워크 및 제언

```text
[SECaaS 성공적 구축을 위한 3단계 전환 로드맵]

 [1단계: 준비 및 평가]      ===>      [2단계: 하이브리드 연동]     ===>     [3단계: 완전 클라우드 네이티브]
 - 자산 및 트래픽 분석                - 비인가 SaaS CASB 차단               - ZTNA 기반 온프레미스 VPN 폐기
 - CMEK 키 관리 수립                  - SWG 기반 웹 트래픽 전환             - SASE/SSE 단일 플랫폼 완성
 - 네트워크 레이턴시 실측              - 데이터센터-PoP 전용선 구축          - 전사 XDR 통합 자동 대응(SOAR)
```

| 평가 영역 | 핵심 점검 항목 | 통과 기준 지표 |
|---|---|---|
| 네트워크 성능 | 본사/지사/재택 환경에서 PoP 연결 레이턴시 및 패킷 손실률 | 추가 지연 시간 < 15ms, 패킷 손실률 < 0.1% |
| 규제 및 컴플라이언스 | 로그 저장소의 국내 데이터센터 상주 여부 및 개인정보 국외 이전 이슈 | ISMS-P, CSAP, SOC 2 Type II 인증 보유 |
| 서비스 가용성 | 장애 발생 시 페일오버 시간 및 무중단 전환 SLA | 연간 가용성 SLA >= 99.99%, 장애 복구 시간 < 1분 |
