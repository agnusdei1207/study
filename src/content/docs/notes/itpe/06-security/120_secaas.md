## 연관 키워드

- SECaaS(Security as a Service), SASE(Secure Access Service Edge), SSE(Security Service Edge), PoP(Point of Presence)
- SWG(Secure Web Gateway), CASB(Cloud Access Security Broker), ZTNA(Zero Trust Network Access), FWaaS(Firewall as a Service)
- SSL/TLS 인스펙션, DLP(Data Loss Prevention), SD-WAN, 데이터 주권, 출구 전략(Exit Strategy)

## Ⅰ. SECaaS의 개요

- 핵심 요약 : 방화벽과 침입 방지 같은 보안 기능을 클라우드에서 구독형으로 제공받는 보안 서비스 모델.
- 개념 : 조직 내부에 방화벽과 IPS(Intrusion Prevention System) 같은 전용 장비를 직접 구축하지 않고, 클라우드 환경에서 **서비스형 보안**(SECaaS)으로 기능을 구독하는 모델.
- 배경 및 필요성 : 원격 근무, 클라우드 전환, SaaS 활용이 늘면서 기업의 **네트워크 경계**(Perimeter)가 흐려졌고, 보안 인력 부족과 **자본적 지출**(CAPEX) 부담도 커짐.
- 주요 목적 : 보안 인프라의 총소유비용(TCO) 절감, 글로벌 PoP 기반의 일관된 제로 트러스트 정책 적용, 위협 정보의 신속한 반영을 통한 운영 민첩성 확보.

## Ⅱ. SECaaS의 특징 및 장점

- 핵심 요약 : 구독형 과금, 클라우드 PoP 기반 단일 정책, 실시간 위협 정보, 기능 통합이 맞물려 비용과 관리 부담을 함께 줄이는 방식.

1. **구독형 과금** (OPEX, Operating Expenditure) : 장비 구매 대신 이용량에 따라 비용을 지불 → 초기 투자와 장비 교체 부담 감소.
2. **단일 정책 적용** : 본사, 지사, 재택근무자가 같은 PoP 정책을 통과 → 지사별 방화벽 정책 불일치 해소.
3. **실시간 위협 정보 반영** : 여러 지역 PoP에서 수집한 위협 데이터를 중앙에서 분석하여 전 고객에 신속히 배포 → 신규 위협 대응 공백 축소.
4. **기능 통합** (SASE, SSE) : 네트워크 연결과 SWG, CASB, ZTNA, FWaaS를 하나의 플랫폼으로 제공 → 제품별 관리 복잡도 감소.

## Ⅲ. SECaaS의 구조 (흐름)

- 핵심 요약 : 사용자 트래픽이 클라우드 PoP의 정책 엔진과 통합 검사 엔진을 거쳐 목적지로 전달되는 구조.

```text
[ 트래픽 흐름 ]

사용자 / 지사 / 원격근무
   ↓ 암호화 터널
클라우드 PoP 정책 엔진
   ↓
SWG, CASB, ZTNA 정책 적용
   ↓
통합 검사 엔진
   ↓
본사 SaaS, 클라우드 자원
```

```text
[ PoP 통합 검사 계층 ]

TLS 복호화 후 검사
   ↓
FWaaS, IPS 정책 판단
   ↓
악성코드 샌드박스 분석
   ↓
글로벌 위협 정보 연계
```

- **SWG** (Secure Web Gateway) : 악성 URL과 웹 위협을 필터링.
- **CASB** (Cloud Access Security Broker) : SaaS 데이터의 업로드와 다운로드를 통제하고 DLP를 적용.
- **ZTNA** (Zero Trust Network Access) : 사용자 신원과 기기 상태에 따라 애플리케이션 단위로 접근을 허용.
- **CSA 보안 도메인** : 클라우드 보안 연합(CSA, Cloud Security Alliance)이 제시한 IAM, DLP, 웹 보안, 암호 관리, BCDR 등 보안 영역 체계를 참조 기준으로 삼음.

## Ⅳ. SECaaS, 온프레미스 장비, 매니지드 보안의 비교

- 핵심 요약 : 세 방식은 비용 구조, 확장성, 데이터 통제 방식에서 차이가 나며, SECaaS는 분산 환경에서 정책 일관성을 확보하는 데 강점이 있음.

| 비교 항목 | **SECaaS** | 온프레미스 보안 장비 | **매니지드 보안 서비스** (MSSP, Managed Security Service Provider) |
|---|---|---|---|
| 구축 방식 | 클라우드 구독 (OPEX) | 장비 구매와 설치 (CAPEX) | 장비 유지보수와 관제 외주 |
| 확장성 | 클라우드 기반 즉각 확장 | 장비 교체 필요 | 인력 투입 규모에 따라 제약 |
| 위협 대응 | 벤더 위협 정보 실시간 반영 | 관리자가 수동 배포 | 관제 요원의 분석 후 대응 |
| 정책 적용 | 본사, 지사, 재택 단일 정책 | 지사별 장비와 정책 불일치 | 이종 장비 정책 매핑 어려움 |
| 데이터 통제 | 트래픽이 클라우드 PoP을 경유 | 내부망에서 직접 통제 | 내부 데이터 보존, 외부 관제망 연결 |

## Ⅴ. SECaaS의 한계와 방안

- 핵심 요약 : 데이터 주권, 사업자 장애, 검사에 따른 지연과 프라이버시 문제를 국내 PoP, 이중화, 선별 검사로 대응.

| 한계 | 원인·영향 | 대응 방안 |
|---|---|---|
| 데이터 주권 위반 | 민감 데이터가 해외 PoP을 경유하면 개인정보 보호 법령과 망분리 규제와 충돌 | 국내 PoP 상주를 보장하는 사업자를 선정하고 로컬 구간에서 기밀 데이터를 마스킹 |
| 사업자 장애에 따른 업무 중단 | 글로벌 인프라 장애 시 인터넷 연결과 업무 접근이 함께 중단 | 멀티 리전 이중화와 비상 시 로컬 인터넷 연결 우회(Bypass) 정책 구성, SLA 준수 모니터링 |
| 전수 TLS 검사에 따른 지연과 프라이버시 침해 | 화상회의 품질 저하, 금융·의료 사이트 접속 내용 노출 우려 | 애플리케이션 범주별 선별 우회(Bypass) 목록 적용 |

## Ⅵ. SECaaS 도입에 대한 기술사적 제언

- 핵심 요약 : 데이터 유실 방지, 제로 트러스트 전환, 계약 단계의 종속 방지를 함께 설계하는 방향.

SaaS 환경의 비인가 업로드와 다운로드는 CASB와 DLP를 연계하여 통제하고, 섀도 IT를 가시화하여 관리 대상으로 편입하는 것이 필요하다.

단순 VPN은 점진적으로 ZTNA로 대체하고, 사용자 신원과 기기 상태, 위치 위험도를 실시간으로 확인하여 애플리케이션별로 최소 권한만 부여하는 체계로 옮겨가야 한다.

SLA에는 장애 시 보상 기준과 함께 로그 반환 형식, 다른 사업자로 이전하는 출구 전략을 명시하여 특정 벤더 종속을 계약 단계에서 막아야 한다.

## Ⅶ. 결론

- 핵심 요약 : SECaaS는 경계가 흐려진 환경에서 정책과 위협 정보를 클라우드로 일원화하는 보안 서비스 모델임.
- 다만 데이터 주권과 사업자 종속을 함께 관리해야 실효성이 확보됨.
