## 연관 키워드

- 미라이 봇넷(Mirai Botnet), IoT(Internet of Things), 봇넷(Botnet), C2(Command and Control)
- DDoS(Distributed Denial of Service), 기본 계정(Default Credentials), 사전 대입 공격(Dictionary Attack), 로더(Loader)
- 메모리 상주(Memory-only Execution), 변종(Variant), 싱크홀링(Sinkholing), UPnP(Universal Plug and Play)

## Ⅰ. 미라이 봇넷(Mirai Botnet)의 개요

- 핵심 요약 : 기본 계정을 쓰는 IoT 기기를 대규모로 감염시켜 대규모 DDoS 공격을 일으킨 봇넷.
- 개념 : 취약한 **기본 계정** (Default Credentials)을 쓰는 IoT(Internet of Things) 기기를 텔넷(Telnet) 프로토콜로 감염시키고, C2(Command and Control) 서버의 명령에 따라 대규모 **분산 서비스 거부** (DDoS, Distributed Denial of Service) 공격을 수행하는 봇넷.
- 배경 및 필요성 : 2016년경 IP 카메라, 디지털 비디오 레코더(DVR, Digital Video Recorder), 가정용 라우터 같은 저가 IoT 기기가 보안 고려 없이 대량 보급되었고, 출하 시 기본 패스워드가 바뀌지 않은 채 인터넷에 노출되면서 확산됨.
- 주요 목적 : 보안 패치가 어려운 대량의 IoT 기기를 좀비로 만들어 도메인 네임 시스템(DNS, Domain Name System) 서비스와 호스팅 기업을 마비시키는 대규모 증폭 공격을 수행하는 것.

## Ⅱ. 미라이 봇넷(Mirai Botnet)의 특징 및 장점

- 핵심 요약 : 기본 계정 무차별 대입과 다중 아키텍처 감염이 결합되어, 정교한 취약점 없이도 대규모 감염을 만드는 구조.

1. **사전 대입 공격** (Dictionary Attack) : 하드코딩된 소수의 제조사 기본 계정 목록으로 무차별 침투 → 몇 시간 안에 대량 장악이 가능함.
2. 크로스 컴파일 : MIPS, ARM, x86 등 이종 아키텍처별 바이너리를 준비 → 다양한 기종의 IoT 기기를 감염 대상으로 삼음.
3. 경쟁 악성코드 제거 : 장악 직후 다른 악성 프로세스를 종료하고 Telnet 포트를 막음 → 독점적 제어권을 유지함.
4. **메모리 상주** (Memory-only Execution) : 디스크에 흔적을 남기지 않고 RAM(Random-Access Memory)에서만 동작 → 재부팅 시 제거되지만 네트워크에 연결된 채로 재감염됨.

## Ⅲ. 미라이 봇넷(Mirai Botnet)의 구조 (흐름)

- 핵심 요약 : 스캔, 침투, 보고, 적재로 이어지는 감염 수명주기와, C2의 명령으로 피해자에게 트래픽을 집중시키는 공격 구조.
- **로더** (Loader) : 취약 기기 정보를 받아 기기 CPU 아키텍처에 맞는 바이너리를 내려받아 실행하는 서버 구성 요소.
- **C2** (Command and Control) : 감염된 봇에 공격 대상과 방식을 내리는 제어 서버.

```text
[ 미라이 감염 수명주기 ]

1. 스캔 : 무작위 IPv4에 Telnet 포트 탐색
   ↓
2. 침투 : 기본 계정 목록으로 로그인 시도
   ↓
3. 보고 : 취약 기기 정보를 보고 서버에 전송
   ↓
4. 적재 : 로더가 아키텍처별 바이너리 설치
   ↓
5. 상주 : 메모리 상주, 경쟁 악성코드 제거
```

```text
[ C2 명령에 따른 대규모 DDoS ]

C2 서버
   ↓ 공격 명령
수십만 대의 좀비 IoT 봇
   ↓ 대규모 트래픽
희생자 서버 (대상 호스트)
   : SYN Flood, UDP Flood, DNS 증폭
```

## Ⅳ. 미라이 봇넷(Mirai Botnet)과 유형별 봇넷의 비교

- 핵심 요약 : 미라이는 기본 계정 관리 부실을 노린 대량 감염과 볼륨형 DDoS에 특화되었고, 다른 봇넷은 취약점 체이닝이나 개인 PC 침해에 무게가 실린다.

| 비교 축 | 미라이 봇넷 | Reaper (IoTroop) | PC 봇넷 (Zeus, Conficker) |
| --- | --- | --- | --- |
| 감염 대상 | 카메라, DVR, 가정용 라우터 등 IoT | IoT 기기와 기업 네트워크 장비 | Windows 기반 개인용 PC와 워크스테이션 |
| 침투 기법 | Telnet 기본 패스워드 무차별 대입 | 다수의 알려진 원격 코드 실행 취약점 | 피싱 첨부파일, 드라이브 바이 다운로드 |
| 전파 속도 | 공인 IP 무작위 고속 스캔으로 매우 빠름 | 취약점 체이닝이 필요해 중간 수준 | 사용자의 악성 링크 클릭에 의존해 느림 |
| 주요 공격 | 대용량 DDoS (SYN 플러드, UDP(User Datagram Protocol) 플러드, DNS 증폭) | DDoS와 내부망 침투 거점 | 금융 자격증명 탈취, 랜섬웨어 유포 |
| 지속성 | 재부팅 시 삭제, 재감염으로 유지 | 플래시 펌웨어 변조로 영구 상주 | 레지스트리와 서비스 등록으로 영구 상주 |

- 선택 기준 : 봇넷의 위험을 판단할 때는 감염 대상 장비의 패치 가능 여부와 상주 방식을 함께 보아야 한다.

## Ⅴ. 미라이 봇넷(Mirai Botnet)의 한계와 방안

- 핵심 요약 : 소스 공개에 따른 변종 확산, 좀비 기기의 인지 부재, 패치 수단 부재를 시그니처 차단, 이상 트래픽 탐지, 기기 격리로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 소스 공개에 따른 변종 확산 | 원작 소스 공개 후 Satori, Okiru, Mozi 등 취약점을 결합한 변종 등장 | 알려진 IoT 취약점 시그니처를 침입 방지 시스템에 신속 반영, 악성 C2 트래픽 싱크홀링 | 신규 변종 탐지 건수 |
| 좀비 기기의 장기 방치 | 모니터가 없는 기기는 사용자가 감염을 알아채기 어려움 | 사업자가 비정상 외부 스캔 단말을 탐지해 통보하고 격리 네트워크로 전환 | 격리 단말 해제까지 소요 기간 |
| 펌웨어 패치 수단 부재 | 제조사 폐업이나 원격 펌웨어 업데이트 미지원으로 조치 불가 | 패치 불가 노후 기기의 인터넷 연결 차단, 가정용 IoT 전용 VLAN 격리 | 패치 불가 기기 비율 |

## Ⅵ. 미라이 봇넷(Mirai Botnet)에 대한 기술사적 제언

- 핵심 요약 : 기본 비밀번호 금지 제도, 라우터 기본 설정 강화, 글로벌 분산 방어망을 함께 갖추어 봇넷의 감염 기반과 공격 용량을 동시에 줄여야 한다.
- 제조사는 기기마다 고유한 무작위 초기 비밀번호를 부여하는 것을 기본으로 삼아야 하며, 국내 IoT 보안 인증 제도와 해외 기본 비밀번호 금지 법제를 연계해 준수를 점검할 필요가 있다.
- 가정용 라우터는 UPnP(Universal Plug and Play) 기능을 기본 비활성화하여 내부 기기가 방화벽을 우회해 외부에 포트를 열지 못하도록 설정하는 것이 바람직하다.
- 통신사와 CDN(Content Delivery Network) 사업자는 BGP(Border Gateway Protocol) 기반 애니캐스트(Anycast)로 분산된 스크러빙 센터(Scrubbing Center)를 확충하여, 대용량 공격 트래픽을 로컬 회선이 아닌 전 세계 거점에서 흡수하도록 설계해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 미라이는 정교한 제로데이가 아닌 기본 계정 관리 부실만으로도 인터넷 기반 인프라를 마비시킬 수 있음을 보여준 사례.
- 시사점 : IoT 보안의 출발점은 초기 설정과 기본 계정 관리이며, 이를 제도와 기술로 함께 강제하는 것이 봇넷 재발을 막는 길이다.
