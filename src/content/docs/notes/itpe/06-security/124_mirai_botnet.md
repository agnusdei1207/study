## 지식 로드맵 내 현재 위치

지식 위치: 네트워크 보안 → IoT 악성코드 → **미라이 봇넷**

## 30초 인출

- 본질: 인터넷에 노출된 IoT·임베디드 장비의 기본 자격증명을 대입해 감염시키고, 명령제어 서버 지시로 DDoS 트래픽을 발생시킨 봇넷
- 구별: 미라이는 최초의 IoT 봇넷이 아님. 2016년 Dyn DNS 장애에는 미라이 감염 장비가 관여했으나, 특정 공격의 처리량을 근거 없이 1.2 Tbps로 단정하지 않음.

## 1교시 예상문제 (10점)

> 미라이 봇넷의 감염 경로와 DDoS 실행 구조를 설명하시오. (예상·10점)

## 1교시 10점 답안

### Ⅰ. 개념

미라이(Mirai)는 공유기·카메라·DVR 등 인터넷 노출 장비를 기본 계정 대입으로 감염시키고, 감염 장비를 DDoS 봇으로 사용하는 악성코드·봇넷.

### Ⅱ. 감염·공격 경로

```text
인터넷 노출 Telnet 탐색 → 기본 계정 대입 → 장비별 바이너리 설치
                                             ↓
                C2 공격 지시 ← 감염 봇 → 대상 서비스에 트래픽 집중
```

- 방어: 기본 계정 제거·장비별 고유 비밀번호, 불필요한 Telnet 차단, 펌웨어 업데이트, 이상 트래픽 감시.

## 2~4교시 예상문제 (25점)

> 미라이 봇넷의 감염·제어·공격 구조를 설명하고 IoT 기기와 서비스 사업자의 다층 방어 방안을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

### Ⅰ. 개요

미라이는 2016년 대형 DDoS 사건으로 알려진 IoT 봇넷. 보안 설정이 취약한 임베디드 장비가 대량 감염되면 각각의 낮은 성능이 집합적인 공격 트래픽으로 전환.

### Ⅱ. 구성과 역할

| 구성 | 역할 | 방어 관점 |
|---|---|---|
| 스캐너 | 노출된 Telnet 서비스 탐색과 계정 대입 | 관리 포트의 인터넷 노출 차단 |
| 로더 | 기기 아키텍처에 맞는 바이너리 전달 | 무결성 검증·패치·실행 통제 |
| 봇 | 재스캔과 C2 명령 수행 | 감염 징후 감시·격리 |
| C2 | 감염 봇에 공격 지시 | 지시 경로 탐지·차단 |
| DDoS 대상 | SYN·UDP·응용 계층 트래픽 수신 | 사업자·통신사 측 분산 방어 |

### Ⅲ. 공격 흐름과 사례

```text
Telnet 23/2323 탐색
      ↓ 기본 자격증명 대입
IoT 장비 감염·로더를 통한 실행
      ↓
감염 봇의 C2 연결·공격 명령 수신
      ↓
DNS·웹 등 대상에 분산 트래픽 집중
```

2016년 10월 Dyn의 DNS 장애에서 미라이가 관여. 연구에서 Dyn 대상 공격 명령과 감염 봇 IP를 관측했으나 다른 호스트의 관여 가능성도 명시. 사건별 트래픽 규모와 전체 인터넷 장애 범위를 검증 없이 단정할 수 없음.

### Ⅳ. 취약성의 원인

| 원인 | 결과 |
|---|---|
| 공통·추측 가능한 기본 비밀번호 | 자동화한 계정 대입 가능 |
| 관리 서비스의 인터넷 노출 | 대규모 무작위 스캔에 노출 |
| 업데이트·자산 관리 부족 | 감염 이후 재노출·재감염 위험 |
| 감염 징후 확인의 어려움 | 운영자가 공격 발신 사실을 늦게 인지 |

### Ⅴ. 다층 방어

| 위치 | 방안 | 한계·검증 |
|---|---|---|
| 제조·출하 | 장비별 고유 암호 또는 최초 설정 강제, 안전한 기본 설정 | 공통 암호 금지와 갱신 경로 점검 |
| 기기 운영 | Telnet 비활성화, 접근 제어, 펌웨어 갱신, 감염 시 초기화 | 초기화만 하면 재노출 위험 |
| 통신사 | 감염 장비 탐지·가입자 통지·격리, 비정상 발신 트래픽 제한 | 정상 서비스 영향 검토 |
| 서비스 사업자 | DDoS 흡수·우회·트래픽 분석·DNS 이중화 | 공격 유형과 규모별 훈련 |

BCP 38의 출발지 주소 위조 방지는 유용하지만, 실제 주소를 쓰는 감염 봇의 직접 DDoS 자체를 막는 대책으로 오인하면 안 됨.

### Ⅵ. 제도·운영 고려

영국의 소비자 연결 제품 보안 제도는 공통 기본 비밀번호와 쉽게 추측 가능한 암호를 금지. 국내 정책을 논의할 때는 제품 유형·공급망·유지보수 기간과 개인정보 영향을 함께 검토.

### Ⅶ. 기술사적 제언

장비의 안전한 출하 설정과 운영 중 자산·패치 관리, 네트워크와 서비스 측 DDoS 방어의 결합.
