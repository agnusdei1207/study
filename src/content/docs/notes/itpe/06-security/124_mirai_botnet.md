## Ⅰ. 미라이 봇넷(Mirai Botnet)의 개요

- **개념** : 취약한 기본 계정(Default Credentials)을 사용하는 전 세계 사물인터넷(IoT) 기기를 텔넷(Telnet) 프로토콜을 통해 대규모로 감염시켜, C2 서버의 명령에 따라 기가급~테라급의 분산 서비스 거부(DDoS) 공격을 감행하는 악명 높은 IoT 봇넷.
- **배경 및 필요성** : 2016년 IP 카메라, 디지털 비디오 레코더(DVR), 가정용 라우터 등 저가형 IoT 기기가 보안 고려 없이 대량 보급되었고, 공장 출하 시 설정된 기본 패스워드가 변경되지 않은 채 공인 인터넷에 무방비로 노출됨에 따라 발생함.
- **핵심 목적** : 보안 패치가 불가능한 수십만 대의 IoT 기기를 좀비화하여 Dyn DNS, 프랑스 호스팅사 OVH, 블로거 브라이언 크렙스 등을 마비시키는 사상 최대 규모의 증폭 DDoS 공격 감행.

## Ⅱ. 미라이 봇넷(Mirai Botnet)의 핵심 아키텍처 및 동작 메커니즘

미라이 봇넷은 감염 스캐너(Scanner), 페이로드 다운로더(Loader/Wget), 봇 바이너리, C2(Command and Control) 서버의 4단계 라이프사이클로 유기적으로 작동함.

```text
[ Mirai 봇넷 감염 수명주기 및 대규모 DDoS 공격 메커니즘 ]

 +----------------------------------------------------------------------+
 | 1. 정찰/전파 (Scan)  : 무작위 IPv4 생성 -> 23/2323번(Telnet) 포트 스캔|
 | 2. 침투 (Brute-Force): 60여 개 기본 계정/패스워드 사전 대입 공격       |
 |                        (root/xc3511, admin/admin 등)                 |
 | 3. 보고 (Report)     : 취약 기기 발견 시 C&C 보고 서버로 IP/계정 전송 |
 | 4. 적재 (Infection)  : 로더(Loader) 서버가 기기 CPU 아키텍처(MIPS,   |
 |                        ARM 등)에 맞는 미라이 바이너리 전송 및 실행   |
 | 5. 상주 (Persistence): 메모리 상주, 타 악성코드 킬(Kill), Telnet 차단 |
 +----------------------------------------------------------------------+
                                    |
                                    v
     [ C2 서버의 공격 명령 ] -------------------> [ 수십만 대 좀비 IoT 봇 ]
                                                        |
                                                        | 대규모 트래픽 발생
                                                        v
                                          [ 희생자 서버 (Target Host) ]
                                          * SYN Flood, ACK Flood
                                          * DNS Query Amplification
                                          * GRE / UDP Water Torture
```

- **크로스 컴파일(Cross-compilation) 지원** : MIPS, ARM, x86, PowerPC, SuperH 등 다양한 이종 IoT 하드웨어 아키텍처별 전용 바이너리를 컴파일하여 광범위한 기종 감염.
- **단순하지만 치명적인 사전 대입(Dictionary Attack)** : 하드코딩된 소수의 취약한 제조사 기본 계정 목록만으로 전 세계 수십만 대의 장비를 몇 시간 만에 장악.
- **경쟁 악성코드 제거 및 포트 차단** : 기기 장악 즉시 메모리 내의 타 악성 프로세스를 강제 종료하고 23번 포트를 차단하여 타 해커의 침투를 막고 독점적 제어권 유지.
- **메모리 기반 상주(Memory-only Execution)** : 디스크 플래시 메모리에 흔적을 남기지 않고 RAM 상에서만 동작하여, 기기를 재부팅하면 악성코드가 사라지지만 인터넷에 연결된 채 재부팅 즉시 수 분 내 재감염.

## Ⅲ. 미라이 봇넷(Mirai Botnet)의 세부 구성 요소 및 비교 분석

| 비교 항목 | Mirai 봇넷 | Reaper (IoTroop) | 전통적 PC 봇넷 (Zeus/Conficker) |
| --- | --- | --- | --- |
| 감염 대상 | 폐쇄회로 카메라, DVR, 가정용 라우터 (IoT) | IoT 기기 및 엔터프라이즈 네트워킹 장비 | Windows OS 기반 개인용 PC 및 워크스테이션 |
| 침투 기법 | Telnet 포트 기본 패스워드 무차별 대입 | 알려진 다중 소프트웨어 취약점 (RCE) | 피싱 이메일 첨부파일, 드라이브 바이 다운로드 |
| 전파 속도 | 극도로 빠름 (공인 IP 무작위 고속 스캔) | 중간 (취약점 익스플로잇 체이닝 필요) | 느림 (이용자의 악성 링크 클릭 등 개입 필요) |
| 주요 공격 | 초대형 볼륨성 DDoS (SYN, UDP, DNS 증폭) | DDoS 및 내부망 침투 거점 활용 | 인터넷 뱅킹 자격증명 탈취, 랜섬웨어 유포 |
| 지속성 | 재부팅 시 삭제 (메모리 상주, 재감염 의존) | 플래시 메모리 펌웨어 변조를 통한 영구 상주 | 레지스트리 및 서비스 등록을 통한 영구 상주 |

- Mirai는 정교한 제로데이 취약점이 아닌 가장 기초적인 계정 관리 부실만으로도 인터넷 기간 인프라(DNS)를 무너뜨릴 수 있음을 입증한 보안 역사의 경종임.

## Ⅳ. 미라이 봇넷(Mirai Botnet)의 주요 한계점 및 해결 방안

- **오픈소스 공개로 인한 변종(Variant) 봇넷의 폭발적 양산** :
  - **한계점** : 원작자가 깃허브에 소스코드를 공개한 이후 Satori, Okiru, Mozi 등 수많은 공격자가 다양한 RCE 취약점을 결합한 고도화 변종 양산.
  - **해결 방안** : 알려진 IoT 취약점 시그니처를 침입방지시스템(IPS)에 긴급 업데이트하고 ISP 레벨의 악성 C2 트래픽 블랙홀 라우팅(Sinkholing) 공조.
- **사용자 인지 부재로 인한 좀비 기기의 장기 방치** :
  - **한계점** : 스마트폰이나 PC와 달리 모니터가 없는 Headless 기기 특성상 사용자는 기기가 감염되어 DDoS 공격에 가담하고 있음을 인지 불가.
  - **해결 방안** : 통신 사업자(ISP) 차원에서 비정상 아웃바운드 스캐닝 트래픽 발생 단말을 자동 탐지하여 사용자에게 통보 및 격리 네트워크로 전환.
- **저가형 단말의 펌웨어 보안 패치 업데이트 메커니즘 결여** :
  - **한계점** : 제조사가 도산했거나 원격 OTA(Over-The-Air) 펌웨어 업데이트를 지원하지 않아 원천적인 보안 조치 불가.
  - **해결 방안** : 보안 패치가 불가능한 노후 장비의 인터넷 연결 차단 및 가정용 공유기 레벨의 IoT 전용 VLAN 격리 지원.

## Ⅴ. 미라이 봇넷(Mirai Botnet) 적용 및 발전을 위한 기술사적 제언

- **IoT 기기 기본 비밀번호 탑재 금지 법제화 이행** : 미국 캘리포니아 SB-327, 영국 PSTI 법 및 국내 IoT 보안인증제도와 연계하여 기기별 고유 랜덤 비밀번호 부여 의무화 강제.
- **UPnP(Universal Plug and Play) 프로토콜 비활성화** : 내부망 기기가 라우터 방화벽을 우회하여 외부 인터넷에 포트를 자동 개방하지 않도록 라우터의 UPnP 기능을 기본 해제.
- **ISP 및 CDN 사업자의 BGP Anycast 기반 글로벌 스크러빙 센터 확충** : 초대형 볼륨 공격을 로컬 회선에서 방어하는 것은 불가능하므로, 전 세계 분산 Anycast PoP에서 공격 트래픽을 흡수·소거하는 클라우드 방어망 필수화.
