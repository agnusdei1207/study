## 지식 로드맵 내 현재 위치

AI 보안 → 조직 보안 아키텍처 → AI 보안 플랫폼(AI-SPM, AI Gateway, AI-BOM)

## 30초 인출

- **본질:** 기업 내 분산된 AI 모델, 데이터셋, 에이전트 자산의 보안 형상을 통합 관리하고, 런타임 추론 트래픽의 입출력 위협을 실시간 차단하는 통합 보안 플랫폼
- **메커니즘:** AI-SPM 자산 발견·위험 평가 → AI-BOM 공급망 추적 → AI Gateway 기반 인라인 입출력 정책 집행(탈옥 탐지, PII 차단)
- 통찰: 사내 비인가 섀도우 AI 사용과 인라인 게이트웨이 추론 지연을 극복하기 위해 CASB 트래픽 강제 프록시화와 스트리밍 비동기 토큰 검사 필수

<details>
<summary>핵심 용어</summary>

- **AI-SPM (AI Security Posture Management):** 기업 내 배포된 모든 파운데이션 모델, 미세조정 가중치, 벡터 DB의 취약점과 권한 오설정을 실시간 감시하는 형상 관리 기술
- **AI Gateway:** 애플리케이션과 LLM API(OpenAI, Claude 등) 사이에 위치하여 토큰 쿼터, 레이트 리밋, 가드레일 정책을 일괄 집행하는 리버스 프록시
- **AI-BOM (AI Bill of Materials):** AI 모델 구축에 사용된 데이터셋 출처, 사전학습 베이스 모델, 파이프라인 라이브러리의 전체 계보를 명세화한 소프트웨어 자재명세서
- **Shadow AI (섀도우 AI):** 사내 보안 부서의 승인 없이 임직원이 임의로 외부 생성형 AI(ChatGPT 등)에 사내 기밀 코드나 고객 데이터를 입력하는 비인가 활용 행위
</details>

## 2~4교시 예상문제 (25점)

> 엔터프라이즈 생성형 AI 도입 확산에 따른 'AI 보안 플랫폼(AI Security Platform)'의 3대 핵심 아키텍처(AI-SPM, AI Gateway, AI-BOM)를 설명하고, 전통적 CSPM과의 차이점 및 Shadow AI 차단과 런타임 지연(Latency) 완화를 위한 엔지니어링 방안을 기술하시오. (예상·25점)

---
## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **AI 보안 플랫폼(AI Security Platform)** 은 기업이 자체 개발하거나 도입한 인공지능(AI) 모델, 학습 데이터셋, 벡터 데이터베이스, AI 에이전트 등 전사 AI 자산의 형상 위험(AI-SPM)을 가시화하고, 런타임 프롬프트 및 응답 트래픽(AI Gateway)을 보호하는 통합 엔터프라이즈 보안 솔루션 |
| 목적 | 사내 핵심 기밀 및 개인정보(PII) 유출 방지, 프롬프트 인젝션 및 유해 콘텐츠 실시간 차단, AI 공급망 취약점 제거 및 글로벌 AI 규제(EU AI Act 등) 준수 |

기존의 호스트·네트워크 중심 CSPM으로는 비정형 자연어 프롬프트와 확률적 AI 모델의 취약점을 통제할 수 없음에 따라 AI 특화 전용 플랫폼으로 분화.

## Ⅱ. AI 보안 플랫폼의 3대 핵심 기둥 특징

| 핵심 영역 | 주요 기능 및 역할 | 구현 기술 스택 |
|---|---|---|
| **1. AI-SPM**<br>(형상 관리) | 전사 AI 자산(파운데이션 모델, 벡터 DB, 에이전트) 자동 발견 및 취약 구성, 과도한 권한 스캔 | 클라우드 API 연동, 자산 그래프 분석, CIS AI Benchmark |
| **2. AI Gateway**<br>(런타임 보호) | 사용자-모델 간 실시간 중계, 탈옥(Jailbreak) 차단, 민감정보(주민번호/API Key) 마스킹 | 리버스 프록시, NeMo Guardrails, 스트리밍 토큰 필터 |
| **3. AI-BOM**<br>(공급망 무결성) | 학습 데이터셋 계보, 오픈소스 모델 라이선스, 서드파티 의존성 무결성 추적 | SPDX / CycloneDX 확장 스펙, Sigstore 모델 서명 |

### 1. 세부 단계별 엔지니어링 메커니즘

| 처리 단계 | 세부 동작 방식 | 보안 통제 효과 |
|---|---|---|
| **입력 인젝션 필터링** | 프롬프트 벡터 임베딩 유사도 분석 및 가드레일 모델 추론 | 시스템 프롬프트 무력화 및 간접 인젝션 사전 차단 |
| **인라인 PII 마스킹** | 정규식 및 NER 딥러닝 모델로 개인정보를 토큰(`[CREDIT_CARD]`)으로 치환 | 외부 CSP로 민감 개인정보가 전송되는 법적 리스크 원천 차단 |
| **출력 가드레일** | LLM 생성 토큰 스트림을 실시간 감시하여 비인가 코드 생성 차단 | 유해 콘텐츠 및 독점 지식베이스 원문 유출 방지 |
| **자산 디스커버리** | 클라우드(AWS, GCP, Azure) IAM 및 컨테이너를 스캔하여 미인가 모델 탐지 | 관리자 몰래 배포된 Shadow 모델 및 오픈 벡터 DB 식별 |

## Ⅳ. 전통적 클라우드 보안(CSPM) vs AI 보안 플랫폼(AI-SPM) 비교

| 비교 항목 | 전통적 클라우드 보안 (CSPM / CWPP) | AI 보안 플랫폼 (AI-SPM / AI Gateway) |
|---|---|---|
| **주요 보호 대상** | 가상머신, S3 버킷, 쿠버네티스 파드, VPC | **LLM 모델, 임베딩 벡터 DB, RAG 파이프라인, AI 에이전트** |
| **데이터 분석 방식** | 정적 인프라 설정 룰셋 (CIS Benchmark) | **비정형 자연어 프롬프트, 모델 가중치, 임베딩 벡터** |
| **런타임 보안 방식** | 네트워크 L4/L7 방화벽 패킷 필터링 | **시맨틱(Semantic) 가드레일, 프롬프트 인젝션 차단** |
| **주요 위협** | 오픈 포트, 루트 권한 탈취, 랜섬웨어 | **탈옥, 프롬프트 인젝션, 환각(Hallucination), PII 유출** |
| **의존성 관리** | 라이브러리 CVE 취약점 (SBOM) | **학습 데이터셋 오염, 모델 백도어, AI-BOM 계보** |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **임직원의 미승인 외부 AI(Shadow AI) 사용으로 인한 사내 기밀 유출**<br>보안 게이트웨이를 우회하여 개인 스마트폰이나 사설 브라우저로 ChatGPT, Claude 웹에 직접 회사 소스코드를 붙여넣어 데이터 유출 발생 | **CASB/SWG 기반 AI 도메인 전수 제어 및 사내 전용 AI Gateway 강제화**<br>사내 웹 게이트웨이(SWG) 및 차세대 방화벽에서 공용 LLM 접속을 전면 차단하고, DLP가 내장된 사내 전용 AI Gateway(Private 엔드포인트)로만 접속하도록 강제 리디렉션 |
| **인라인 AI 게이트웨이 가드레일 분석에 따른 극심한 추론 지연(Latency)**<br>프롬프트와 응답을 별도의 보안 검증 모델(Llama Guard)로 2회 이상 추론할 경우 응답 대기 시간이 $500\text{ms} \sim 2\text{초}$ 증가하여 사용자 경험 저하 | **스트리밍 비동기 토큰 검사(Streaming Token Inspection) 및 시맨틱 캐시**<br>사용자에게 첫 토큰을 즉시 스트리밍하면서 백그라운드에서 청크 단위로 비동기 검사를 병행하고, 자주 묻는 질의-응답은 Redis 기반 시맨틱 캐싱(Semantic Cache)으로 즉각 반환 |

## Ⅵ. 제언

```text
[엔터프라이즈 AI 보안 플랫폼 단계적 구축 로드맵]

 +--------------------+     +---------------------+     +--------------------+
 | 1단계: 가시성 확보 | --> | 2단계: 게이트웨이 구축| --> | 3단계: 거버넌스 자동|
 | 전사 AI 자산 디스커|     | 중앙 AI Gateway 배치|     | MLOps CI/CD 파이프 |
 | 버리 및 Shadow 탐지|     | PII 마스킹/인젝션차단|     | 라인 보안 게이트화 |
 +--------------------+     +---------------------+     +--------------------+
```

| 추진 단계 | 핵심 도입 기술 | 달성 목표 |
|---|---|---|
| **1단계: 자산 식별** | AI-SPM 도입, CASB 연동 | 전사 AI 사용 현황 100% 가시화 |
| **2단계: 인라인 보호** | AI Gateway 프록시 배포, 가드레일 적용 | 프롬프트 인젝션 및 사내 기밀 유출 차단 |
| **3단계: 공급망 보안** | AI-BOM 파이프라인, 모델 서명 검증 | 오픈소스 모델 백도어 및 저작권 리스크 제거 |

AI 보안은 개별 애플리케이션 단위의 땜질식 처방을 지양하고, 전사 AI 트래픽을 단일 관문으로 통제하는 엔터프라이즈 AI 보안 플랫폼 아키텍처 확립 권장.
