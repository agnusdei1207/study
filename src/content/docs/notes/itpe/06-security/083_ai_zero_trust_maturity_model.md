## 연관 키워드

- AI 제로트러스트 성숙도 모델, CISA 제로트러스트 성숙도 모델(ZTMM, Zero Trust Maturity Model)
- 제로 트러스트(Zero Trust), 머신 신원, SPIFFE, 사전 필터링, 의미론적 가드레일, 정책 집행점(PEP)

## Ⅰ. AI 제로트러스트 성숙도 모델의 개요

- 핵심 요약 : CISA 제로트러스트 성숙도 모델을 AI 파이프라인에 맞춰 단계별 통제 수준을 평가하는 이행 프레임워크.
- 개념 : CISA(Cybersecurity and Infrastructure Security Agency)의 **제로트러스트 성숙도 모델** (ZTMM, Zero Trust Maturity Model)의 5개 기둥(신원, 기기, 네트워크, 애플리케이션 및 워크로드, 데이터)을 LLM, RAG 지식베이스, 자율 에이전트 인프라에 적용해 **4단계 성숙도**로 평가하는 프레임워크.
- 배경 및 필요성 : AI 파이프라인인 데이터 수집, 학습, 추론, 에이전트 실행 전 구간에 보안 사각지대가 있어, 단계별 통제 수준을 진단하고 제로 트러스트 구조로 옮길 기준이 필요해짐.
- 주요 목적 : 내부자 위협, 프롬프트 인젝션, 비인간 계정 탈취를 줄이고, 단계별 보안 투자 우선순위를 정하는 것.

## Ⅱ. AI 제로트러스트 성숙도 모델의 특징 및 장점

- 핵심 요약 : 기존 5개 기둥에 AI 고유 통제를 얹어 진단과 투자 순서를 함께 제시.

1. 단계적 진단 : 기둥별로 전통, 초기, 고급, 최적화 단계를 평가 → 취약한 기둥부터 우선 투자 가능.
2. 기둥별 독립 진행 : 기둥마다 속도를 달리해 이행 → 조직 여건에 맞춘 점진적 전환 가능.
3. 공통 역량 결합 : 가시성·분석, 자동화·오케스트레이션, 거버넌스를 모든 기둥에 공통 적용 → 단계 간 연속성 확보.

## Ⅲ. AI 제로트러스트 성숙도 모델의 구조 (흐름)

- 핵심 요약 : 전통 단계에서 최적화 단계로 갈수록 정적 할당이 동적 인가와 실시간 방어로 바뀌는 진화 경로.
- 전통 : 영구 API 키와 네트워크 경계에 의존하고, 도구 권한이 넓게 열려 있음.
- 초기 : 역할 기반 정적 할당과 모델 서빙 네트워크 격리를 도입.
- 고급 : 워크로드 신원과 태스크별 임시 토큰, RAG 청크 단위 접근 통제를 적용.
- 최적화 : 행위 이상 탐지와 실시간 인라인 가드레일로 런타임을 자율 방어.

```text
[ 1. 전통 ]
정적 API 키, 경계 방화벽 의존
        ↓
[ 2. 초기 ]
역할 기반 할당, 서빙 네트워크 격리
        ↓
[ 3. 고급 ]
워크로드 신원, 청크 단위 접근 통제
        ↓
[ 4. 최적화 ]
행위 이상 탐지, 실시간 인라인 가드레일
```

## Ⅳ. 일반 제로트러스트와 AI 워크로드 특화 제로트러스트의 비교

- 핵심 요약 : 정형 데이터의 행·열 인가에서, 자연어 입출력과 의미 기반 검색의 인가로 검증 대상이 확장.

| 비교 축 | 일반 IT 워크로드 제로트러스트 | AI 워크로드 특화 제로트러스트 |
| --- | --- | --- |
| 보호 대상 | 사용자 계정, 웹 앱, 관계형 DB | 자율 에이전트, 모델 가중치, 벡터 DB 임베딩 |
| 신뢰 검증 | IP, 인증서, 기기 상태 | 프롬프트, 도구 파라미터, 출력 유해성 |
| 데이터 인가 | 테이블·행·열 단위 정형 인가 | 의미 유사도 검색 결과의 청크 단위 인가 |
| 주요 위협 | SQL 인젝션, 세션 탈취 | 프롬프트 인젝션, 모델 도난, 데이터 중독 |
| 검증 수단 | 정규식·시그니처 인라인 검사 | 의미 판별 모델, 실시간 정책 엔진 |

## Ⅴ. AI 제로트러스트 성숙도 모델의 한계와 방안

- 핵심 요약 : 정적 속성 검증의 한계, 검색 지연, 이기종 신원 표준 부재, 암호화 지연을 의미 기반 가드레일, 사전 필터링, 단일 신원 표준, 데이터 플레인 가속으로 해소.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 비결정론적 출력 통제 불가 | 정적 속성 검증 중심이라 LLM의 생성 텍스트 위험을 못 봄 | 워크로드 기둥에 의미 기반 인라인 가드레일을 독립 PEP로 배치 | 유해 출력 차단률 |
| 벡터 검색 지연 | 검색 후 메타데이터 ACL 검사로 쿼리 지연 증가 | 벡터 검색 단계에서 사전 필터링을 적용해 인가되지 않은 청크를 연산 전에 제외 | 쿼리 응답 시간 |
| 하이브리드 환경의 신원 표준 부재 | 클라우드별 IAM이 달라 에이전트 신원 체계가 분산 | SPIFFE/SPIRE 기반 워크로드 신원과 OIDC 연합으로 단일화 | 신원 체계 통합 비율 |
| 암호화와 정책 검사 지연 | 모든 호출에 mTLS와 정책 검증을 적용해 추론 응답 지연 | 데이터 플레인 가속(eBPF 기반 네트워킹)과 세션 캐싱 적용 | 호출당 추가 지연 |

```text
[ AI 요청의 계층별 검증 흐름 ]

워크로드 신원 확인 (SPIFFE/SPIRE, OIDC)
   ↓ 검색 단계
벡터 검색 전 사전 필터링 (미인가 청크 제외)
   ↓ 출력 단계
의미 기반 인라인 가드레일로 출력 검사
   ↓ 전송 구간
eBPF 데이터 플레인 가속과 세션 캐싱
```

## Ⅵ. AI 제로트러스트 성숙도 모델의 기술사적 제언

- 핵심 요약 : 신원, 런타임 방어, 성숙도 로드맵을 연결해 AI 자산 보호 수준을 단계적으로 끌어올리는 운영 체계.

1. 플랫폼 조직은 AI 에이전트의 머신 신원 등록과 동적 권한 위임을 자동화해, 신원 인프라가 에이전트 증가 속도를 따라가도록 해야 한다.
2. 보안 조직은 모델 서명 검증과 추론 게이트웨이의 가드레일을 배포 파이프라인에 포함해, 런타임 방어가 배포 단계부터 작동하게 해야 한다.
3. 경영진은 성숙도 평가를 정기적으로 시행하고 가장 낮은 기둥에 투자를 집중하는 로드맵을 승인해, 규제 요구에 맞춘 투자 순서를 확보해야 한다.

## Ⅶ. 결론

- 핵심 요약 : AI 제로트러스트 성숙도 모델은 AI 파이프라인 전 구간을 단계별로 진단하는 제로 트러스트 이행 도구.
- 시사점 : 가장 약한 기둥이 전체 보안 수준을 결정하므로, 성숙도 진단을 투자 판단과 연결하는 조직이 AI 보안을 안정적으로 높일 수 있음.
