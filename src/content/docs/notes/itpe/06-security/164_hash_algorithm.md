## 연관 키워드

- 해시 알고리즘(Hash Algorithm), 일방향 암호 해시 함수, 해시값(다이제스트), 충돌 저항성, 역상 저항성
- 눈사태 효과, 머클-담고르(Merkle-Damgård) 구조, 스펀지(Sponge) 구조, SHA-3, 길이 확장 공격
- HMAC, 키 스트레칭, Argon2id, 솔트(Salt), 그로버(Grover) 알고리즘

## Ⅰ. 해시 알고리즘(Hash Algorithm)의 개요

- 핵심 요약 : 임의 길이 입력을 고정 길이 값으로 바꾸며, 되돌리기와 충돌 찾기가 어려운 일방향 암호 함수.
- 개념 : 가변 길이 데이터를 고정 길이의 비트열인 **해시값** (Digest)으로 변환하며, 역연산과 충돌 생성이 계산적으로 불가능하도록 설계된 **일방향 암호 해시 함수** (One-Way Cryptographic Hash Function). 대표 계열은 MD5(Message Digest 5)와 SHA(Secure Hash Algorithm) 계열이다.
- 배경 및 필요성 : 원본을 노출하지 않고 무결성을 빠르게 확인해야 하는 요구에서 출발하여, 파일 검증, 전자서명, 비밀번호 저장, 블록체인 연결 구조의 기반으로 쓰임.
- 주요 목적 : 입력의 1비트 변경이 출력 전체를 바꾸는 특성으로 데이터 무결성을 보증하고, **HMAC** (Hash-based Message Authentication Code)과 전자서명의 기반을 제공.

## Ⅱ. 해시 알고리즘(Hash Algorithm)의 특징 및 장점

- 핵심 요약 : 세 가지 보안 특성과 눈사태 효과가 위변조 탐지와 인증의 근거가 되는 구조.

1. **역상 저항성** (Pre-image Resistance) : 주어진 해시값 $h$에 대해 $H(m) = h$인 원본 $m$을 찾기 어려움 → 해시값만 저장해도 원본 노출 위험 감소.
2. **제2 역상 저항성** (Second Pre-image Resistance) : 주어진 $m_1$과 같은 해시값을 내는 다른 $m_2$를 찾기 어려움 → 원본 파일을 다른 파일로 바꿔치기하는 공격 차단.
3. **충돌 저항성** (Collision Resistance) : 같은 해시값을 내는 임의의 서로 다른 두 입력을 찾기 어려움 → 서명 대상 문서의 위조 방지. 생일 역설에 따라 출력 길이 $n$비트에서 약 $2^{n/2}$ 복잡도가 기준.
4. **눈사태 효과** (Avalanche Effect) : 입력 1비트 변경에 출력 절반 이상의 비트가 바뀌어 변경 탐지가 확실해짐.

## Ⅲ. 해시 알고리즘(Hash Algorithm)의 구조 (흐름)

- 핵심 요약 : 초기 벡터를 거쳐 블록을 순차 압축하는 머클-담고르 구조에서, 흡수와 짜내기로 진행하는 스펀지 구조로 발전.

```text
[ 머클-담고르 구조 (MD5, SHA-1, SHA-2) ]
 초기 벡터 (IV)
       ↓
 블록 M1 → 압축 함수 f → 중간 해시 H1
       ↓
 블록 M2 → 압축 함수 f → 중간 해시 H2
       ↓
 마지막 블록 (패딩 포함) → 최종 해시
```

```text
[ 스펀지 구조 (SHA-3, Keccak) ]
 흡수 (Absorbing) : 블록을 상태 r에 XOR 후 순열 f
       ↓
 용량 c 영역은 외부에 노출되지 않음
       ↓
 짜내기 (Squeezing) : 상태 r에서 해시 출력
```

- **머클-담고르** (Merkle-Damgård) 구조 : 압축 함수를 블록마다 반복하는 방식으로, 구조상 길이 확장 공격에 노출됨.
- **스펀지** (Sponge) 구조 : 내부 상태의 일부만 입출력하고 나머지는 숨기는 방식으로, 길이 확장 공격이 구조적으로 성립하지 않음.

## Ⅳ. 해시 알고리즘(Hash Algorithm)의 세부 비교

- 핵심 요약 : MD5와 SHA-1은 충돌이 실증되어 폐기 대상이며, 현재는 SHA-2가 사실상 표준이고 SHA-3가 대체 및 병행 후보.

| 비교 항목 | MD5 | SHA-1 | SHA-2 (SHA-256) | SHA-3 (Keccak) |
| --- | --- | --- | --- | --- |
| 출력 길이 | 128비트 | 160비트 | 256 / 512비트 등 | 224 / 256 / 384 / 512비트 |
| 내부 구조 | 머클-담고르 | 머클-담고르 | 머클-담고르 | 스펀지 |
| 충돌 취약성 | 실용적 시간 내 충돌 생성 가능 | 충돌 쌍 시연 사례 존재 (SHAttered) | 현재까지 실용적 충돌 보고 없음 | 실용적 충돌 보고 없음 |
| 길이 확장 공격 | 취약 | 취약 | 취약 (HMAC으로 대응) | 구조적으로 면역 |
| 현재 지위 | 사용 금지 | NIST(National Institute of Standards and Technology)가 폐기 권고 | 산업계 사실상 표준 | 차세대 표준, SHA-2 대체 후보 |

- 선택 기준 : 신규 시스템은 SHA-256 이상을 기본으로 하고, 길이 확장 공격이 우려되는 메시지 인증에는 HMAC 또는 SHA-3를 적용.

## Ⅴ. 해시 알고리즘(Hash Algorithm)의 한계와 방안

- 핵심 요약 : 고속 해시의 비밀번호 저장 취약성, 길이 확장 공격, 양자 컴퓨터에 의한 안전성 감소를 용도별 함수 선택으로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 고속 해시의 비밀번호 무차별 대입 | SHA-256은 무결성 검증용으로 빨라 GPU(Graphics Processing Unit) 병렬 연산으로 대량 시도 가능 | 키 스트레칭을 적용한 비밀번호 전용 함수(Argon2id, PBKDF2, bcrypt) 사용 | 비밀번호 저장 방식 점검 결과 |
| 길이 확장 공격 | H(secret ∥ message) 구조에서 비밀키 없이 데이터 덧붙이기 가능 | 단순 결합 해시를 금지하고 HMAC(RFC 2104) 또는 SHA-3 사용 | 단순 결합 해시 사용 건수 |
| 양자 컴퓨터의 그로버 알고리즘 | 충돌 저항성은 약 $2^{n/3}$, 역상 저항성은 약 $2^{n/2}$로 낮아짐 | 장기 보안을 고려해 SHA-256 이상, 장기 기밀은 SHA-384 또는 SHA-512 선택 | 암호 전환 계획 진척률 |

## Ⅵ. 해시 알고리즘(Hash Algorithm)에 대한 기술사적 제언

- 핵심 요약 : 용도별 함수 분리, 레거시 해시 전수 점검, 암호 전환 계획을 통해 해시 체계를 장기간 안전하게 유지해야 함.

1. 비밀번호 저장에는 사용자마다 무작위 솔트를 부여하고 Argon2id 같은 메모리 경합형 함수를 쓰는 것을 표준으로 삼아야 한다.
2. 무결성 검증과 메시지 인증은 SHA-256 이상과 HMAC 조합을 기본 규칙으로 정해, 개발 단계의 라이브러리 선택을 통제해야 한다.
3. 소스코드 정적 분석 도구(SAST, Static Application Security Testing)로 MD5와 SHA-1 호출을 주기적으로 찾아내고, 전환 일정을 관리하는 암호 전환 절차를 운영해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 해시 알고리즘은 원본을 드러내지 않고 무결성을 증명하는 기반 기술이지만, 용도에 맞는 함수 선택이 전제됨.
- 폐기된 알고리즘을 걷어내고 용도별 함수를 구분하는 운영이 해시 체계의 신뢰를 지키는 조건임.
