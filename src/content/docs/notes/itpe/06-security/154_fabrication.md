지식 위치: 정보보안 → 정보 무결성 → **위조 공격**

## 30초 인출

- **본질:** 비인가된 공격자가 정당한 송신자의 신원을 사칭하여 존재하지 않던 허위 메시지, 가짜 트랜잭션, 위조 패킷을 생성·주입하는 능동적 진정성(Authenticity) 침해 공격
- **메커니즘:** 송신자 신원 위장 $\rightarrow$ 사칭 데이터 주입(ARP/DNS/IP 스푸핑) $\rightarrow$ 수신 측의 진위 검증 실패 $\rightarrow$ 비인가 명령 실행 및 허위 거래 처리
- **통찰:** 단순 내용 무결성 검증만으로는 사칭 객체 삽입을 막을 수 없으므로 PKI 상호 인증(mTLS)과 타임스탬프 기반 신선도 검증 및 이상 거래 탐지(FDS) 결합 필수

<details>
<summary>핵심 용어</summary>

- **Fabrication (위조)** : 송신 권한이 없는 자가 정당한 송신자를 사칭하여 허위 데이터를 새로 생성·주입하는 능동적 공격.
- **Authenticity (진정성)** : 정보가 조작되지 않고 진짜 송신자로부터 전송되었음을 입증하는 보안 속성.
- **Replay Attack (재생 공격)** : 정상적인 서명이나 토큰을 가로채어 그대로 재전송함으로써 유효한 요청으로 오인시키는 공격.
- **FDS (Fraud Detection System)** : 정상 사용자의 거래 패턴과 다른 비정상 이상 징후를 실시간 탐지하는 사기 방지 시스템.

</details>

## 2~4교시 예상문제 (25점)

> 네트워크 및 시스템 보안 관점에서 위조(Fabrication) 공격의 개념, 침투 메커니즘, 주요 공격 유형을 변조(Modification)와 비교 설명하고, 진정성 및 신선도(Freshness)를 보장하기 위한 엔지니어링 방어 아키텍처를 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 권한이 없는 제3자가 정당한 송신자의 신원을 사칭하여 시스템 내에 존재하지 않던 가짜 트랜잭션, 허위 패킷, 위조 객체를 생성·주입하는 능동적 공격(Active Attack) |
| 목적 | 데이터의 진정성(Authenticity)과 출처 무결성을 붕괴시켜, 수신 시스템이 비인가 명령을 정상 명령으로 오인하여 실행하거나 허위 결제·계정 생성을 승인하도록 유도 |

- ITU-T X.800 보안 아키텍처에서 규정한 4대 보안 위협 중 하나로, 기존 데이터를 변경하는 '변조(Modification)'와 달리 '새로운 허위 데이터를 무단 삽입'하는 것이 핵심 차이점

## Ⅱ. 위조(Fabrication) 공격의 핵심 기술적 특성

| 특성 항목 | 세부 내용 및 기술적 의미 | 엔지니어링 영향 |
|---|---|---|
| 진정성 및 인가 침해 | 기밀성이나 가용성 파괴를 넘어 시스템의 신뢰 기반(Trust Chain)을 무력화 | 잘못된 신원 기반의 비인가 트랜잭션 실행 유발 |
| 다양한 계층적 발현 | L2(ARP 위조), L3(IP 스푸핑), L7(DNS 위조, 이메일 사칭), 앱(위조 토큰) 등 전 계층 발생 | 계층별 독립된 상호 인증 및 무결성 검증 체계 요구 |
| 재생 공격과의 융합 | 공격자가 정상 패킷을 캡처한 후 재전송하여 마치 새로운 정상 요청인 것처럼 기만 | 단순 암호화만으로는 방어 불가, 신선도 검증 필수 |
| 부인 방지 무력화 시도 | 송신자의 개인키가 유출되거나 취약한 인증을 악용하여 허위 서명 생성 | 법적 효력을 갖는 전자서명의 신뢰성 붕괴 |

- 단순 데이터 암호화(기밀성)로는 방어할 수 없으며, 반드시 암호학적 출처 인증(Source Authentication)과 권한 검증이 결합되어야 하는 특성 보유

## Ⅲ. 위조 공격 흐름 및 4단계 방어 프로세스

```text
[위조(Fabrication) 공격 주입 모델 및 다계층 방어 메커니즘]

  [정상 송신자 A] -----------------------------------------------------> [수신자 B]
                                                                            ▲
  [공격자 C] ──(A의 신원 사칭)──> [가짜 메시지 M_fake 생성] ───────────────┘
                                   │
                                   ▼ [수신자 B의 4단계 진위 검증 파이프라인]
  ┌────────────────────────────────────────────────────────────────────────┐
  │ 1. 출처 인증 (Source Auth)  ──> A의 공개키로 전자서명/MAC 검증 (실패 시 차단)│
  │ 2. 신선도 검사 (Freshness)   ──> 타임스탬프 윈도우 + Nonce 대조 (재생 차단)   │
  │ 3. 권한 인가 (Authorization)──> 사칭된 주체의 해당 행위 권한 보유 여부 확인 │
  │ 4. 이상 징후 (FDS Engine)   ──> IP 위치, 비정상 거래 패턴 탐지 및 최종 인가 │
  └────────────────────────────────────────────────────────────────────────┘
```

| 프로세스 단계 | 핵심 세부 동작 메커니즘 | 기술적 엔지니어링 포인트 |
|---|---|---|
| 1. 출처 인증 (Source Auth) | 수신된 패킷의 전자서명(ECDSA) 또는 HMAC 태그를 검증하여 실제 송신자 확인 | 공개키 인증서(X.509) 유효성 및 CA 신뢰 체인 확인 |
| 2. 신선도 검증 (Freshness) | 패킷 헤더의 타임스탬프가 허용 윈도우(예: $\pm 30$초) 이내인지, Nonce가 중복되지 않았는지 대조 | 재생된 유효 패킷의 2차 위조 실행 차단 |
| 3. 권한 인가 (Authorization) | 서명이 유효하더라도 해당 계정이 요청된 트랜잭션(예: 10억 원 이체)의 한도를 초과하는지 검증 | RBAC / ABAC 기반 세분화된 접근 통제 |
| 4. FDS 이상 행위 감지 | 과거 정상적인 사용자 행동 기준선(Baseline)과 비교하여 이상 접속지나 이상 속도 탐지 | 머신러닝 기반 사기 거래 실시간 차단 |

## Ⅳ. ITU-T X.800 4대 보안 위협 상세 비교

| 비교 항목 | 위조 (Fabrication) | 변조 (Modification) | 가로채기 (Interception) | 가로막기 (Interruption) |
|---|---|---|---|---|
| 침해 보안 속성 | 진정성 (Authenticity) | 무결성 (Integrity) | 기밀성 (Confidentiality) | 가용성 (Availability) |
| 공격의 성격 | 능동적 공격 (Active) | 능동적 공격 (Active) | 수동적 공격 (Passive) | 능동적 공격 (Active) |
| 공격 대상 객체 | 존재하지 않던 가짜 신규 객체 | 이미 존재하는 정당한 객체 | 전송 중이거나 저장된 객체 | 시스템 자원, 네트워크 회선 |
| 주요 공격 사례 | ARP/DNS 스푸핑, 골든티켓 위조 | 패킷 페이로드 조작, 파일 변조 | 스니핑, 무선 도청, 메모리 덤프 | DoS/DDoS, 랜섬웨어 파일 파괴 |
| 핵심 기술 방어선 | 전자서명, PKI, mTLS, FDS | HMAC, AEAD, 머클 트리 | 대칭/비대칭 암호화, TLS 전송 | 서버 이중화, 트래픽 스크러빙 |

## Ⅴ. 위조 공격 대응 시 엔지니어링 한계와 해결 방안

| 한계 | 방안 |
|---|---|
| 암호학적 서명이 정상적으로 포함된 패킷을 공격자가 중간에서 가로채 그대로 재전송하는 재생 공격(Replay Attack) 발생 시 서명 검증만으로 차단 불가 | 데이터 페이로드에 단조 증가 시퀀스 번호(Monotonic Sequence Counter), 암호학적 일회용 난수(Nonce) 및 타임스탬프 윈도우(Timestamp Window)를 필수 결합하여 중복 수신 패킷 즉시 폐기 |
| 송신자의 개인키가 엔드포인트 단말 침해(Infostealer 등)로 유출되어 공격자가 진짜 개인키로 위조 서명된 트랜잭션을 합법적으로 생성 | 단일 개인키 의존을 탈피하여 다자간 계산(MPC) 기반 임계값 서명(TSS) 및 FIPS 140 Level 3 하드웨어 보안 모듈(HSM)에 키를 격리하고, 비정상 거래 패턴을 탐지하는 AI 기반 FDS 실시간 차단 결합 |
| 로컬 L2 네트워크에서 ARP 스푸핑을 통해 게이트웨이 MAC 주소를 위조하여 중간자(MitM) 위치를 확보하고 패킷을 위조 주입 | 네트워크 L2 스위치에서 Dynamic ARP Inspection(DAI), DHCP Snooping, IP Source Guard를 전면 활성화하여 위조된 ARP 응답 브로드캐스트 즉각 차단 |
| 공격자가 권한을 탈취한 후 감사 로그 데이터베이스에 직접 접근하여 가짜 정상 로그를 삽입(Log Fabrication)하거나 조작하여 침적 은닉 | 감사 로그 저장소를 Write-Once-Read-Many(WORM) 불변 스토리지로 격리하고, 로그 레코드마다 머클 트리 해시 체인(Merkle Tree Hash Chain)을 생성하여 사후 위조 삽입 시 루트 해시 불일치로 즉각 탐지 |

## Ⅵ. 데이터 진정성 및 무결성 보증 엔터프라이즈 아키텍처 제언

```text
[엔드투엔드 위조 방어 및 진정성 보증 아키텍처]

 ┌─────────────────────────────────────────────────────────────┐
 │                 1. 네트워크 계층: 신원 위조 방어             │
 │   - L2 스위치: Dynamic ARP Inspection (DAI) + DHCP Snooping │
 │   - 서비스 간 통신: mTLS (Mutual TLS 1.3) 상호 인증        │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │              2. 메시지 및 트랜잭션 계층: 신선도 보증        │
 │   - Ed25519 전자서명 + Monotonic Counter + Nonce 결합       │
 │   - FDS (이상 거래 탐지) 머신러닝 엔진 연동 실시간 검증     │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │                 3. 감사 및 저장 계층: 불변 원장 관리        │
 │   - 머클 트리(Merkle Tree) 기반 트랜잭션 불변성 체이닝      │
 │   - WORM 스토리지 기반 사후 위조 삽입 및 로그 변조 원천 차단│
 └─────────────────────────────────────────────────────────────┘
```

| 관리 영역 | 핵심 엔지니어링 세부 과제 | 통제 목표치 |
|---|---|---|
| 네트워크 신원 | 사내망 전 L2 스위치 DAI 및 서버 간 mTLS 상호 인증 적용 | 신원 사칭 패킷 통과율 0% |
| 재생 공격 방어 | API 전 구간 Nonce 및 타임스탬프 윈도우 검증 강제 | 패킷 재사용 공격 성공률 0% |
| 로그 진정성 | 핵심 원장 및 감사 로그의 WORM 스토리지 불변 저장 | 감사 증적 위조 시도 차단율 100% |
