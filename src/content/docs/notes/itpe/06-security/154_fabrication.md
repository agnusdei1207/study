## 30초 인출

- **본질:** 위조 공격은 권한 없는 주체가 가짜 메시지·거래·신원을 만들어 시스템에 정상 객체처럼 끼워 넣는 공격.
- **메커니즘:** 출처를 속인 새 객체의 삽입 → 수신 측의 진위 검증 실패 → 잘못된 처리.
- **구분:** 변조는 기존 객체의 내용을 바꾸고, 위조는 없던 객체를 만들어 넣는 데 초점.

<details>
<summary>핵심 용어</summary>

- **위조(Fabrication) 공격**: 권한 없는 주체가 허위 객체를 만들어 시스템에 삽입하는 공격.
- **변조(Modification)**: 이미 존재하는 메시지·데이터·객체의 내용을 바꾸는 공격.
- **재전송 공격(Replay Attack)**: 이전의 유효한 메시지를 다시 보내 잘못된 처리를 유도하는 공격.
- **무결성**: 정보가 허가되지 않은 방식으로 바뀌지 않도록 유지하는 성질.
- **출처 인증**: 메시지를 보낸 주체가 주장한 송신자인지 확인하는 절차.
</details>

## 2~4교시 25점 답안

## Ⅰ. 위조 공격의 정의와 목적

| 구분 | 내용 |
|---|---|
| 정의 | **위조(Fabrication) 공격**은 권한 없는 주체가 허위 객체를 만들어 정상 데이터처럼 삽입하는 공격 |
| 목적 | 출처를 속인 거래·명령·기록의 잘못된 처리 차단 |

정보 흐름에 허위 객체를 추가하는 적극적 공격. 정보 유출인 가로채기, 기존 객체의 변경인 변조와 구별.

## Ⅱ. 공격 구조와 유형

```text
정상 흐름: 송신자 → 수신자
위조 삽입: 공격자 → 가짜 메시지 → 수신자
                           ↓
                   출처·무결성 검증 필요
```

| 유형 | 사례 | 필요한 검증 |
|---|---|---|
| 주체 위조 | 허위 장치·계정 요청 | 신원·소유 증명 |
| 메시지 위조 | 존재하지 않는 거래·명령 | 출처·내용·권한 검증 |
| 기록 위조 | 허위 로그·증빙 | 생성 주체와 변경 이력 검증 |

## Ⅲ. 변조·재전송과의 차이

```text
원본 메시지
  ├─ 변조 ─ 기존 내용 변경
  ├─ 위조 ─ 새 허위 메시지 삽입
  └─ 재전송 ─ 과거 메시지 재사용
```

| 공격 | 출발점 | 주요 방어 |
|---|---|---|
| 변조 | 기존 객체 | 내용 무결성 |
| 위조 | 허위 객체 신규 생성 | 출처 인증·권한 확인 |
| 재전송 | 이전의 유효 객체 | 신선도·중복 확인 |

서명이나 MAC은 출처와 무결성 검증을 돕지만, 현재 요청이 허가된 행위인지와 재사용 여부는 별도로 확인할 필요.

## Ⅳ. 수신 측 검증체계

```text
메시지 수신
    ↓ 송신자·키 확인
서명·MAC 검증
    ↓ 시각·일련번호 확인
행위별 권한 검사
    ↓
허가된 처리·감사 기록
```

| 지점 | 실패 시 영향 |
|---|---|
| 출처 인증 | 사칭 메시지 수용 |
| 신선도 검사 | 재전송 처리 |
| 권한 검사 | 진짜 사용자라도 허용 범위 초과 |
| 감사 기록 | 위조 사고 추적 곤란 |

## Ⅴ. 한계와 제언

| 한계 | 대응 |
|---|---|
| 암호학적 무결성만 확인하면 탈취된 계정의 허위 명령을 막기 어려움 | 거래 맥락·권한·이상 행위까지 함께 검증 |
| 위조와 변조를 같은 진단 항목으로 묶으면 발생 경로가 흐려짐 | 새 객체 삽입과 기존 객체 변경을 구분해 시험·증적 설계 |
