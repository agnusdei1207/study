# 위조(Fabrication)

## 핵심 개념
- 송신 권한이 없는 비인가자(공격자)가 마치 정당한 인가 주체인 것처럼 가장하여 존재하지 않던 가짜 데이터, 신원, 패킷 또는 객체를 새롭게 생성하여 시스템에 주입하는 능동적 보안 공격(Active Attack).
- 컴퓨터 및 네트워크 보안의 기본 위협 4대 분류(가로막기, 가로채기, 변조, 위조) 중 하나로, 주로 인증성(Authenticity)과 무결성(Integrity)을 침해함.

```
+-------------------------------------------------------------+
|                     보안 위협 4대 유형 분류                   |
+-------------------------------------------------------------+
| 1. 가로막기(Interruption) | 서비스 거부, 물리적 단절     -> 가용성 침해 |
| 2. 가로채기(Interception) | 도청, 스니핑, 비인가 열람     -> 기밀성 침해 |
| 3. 변조(Modification)     | 기존 데이터 내용 불법 수정   -> 무결성 침해 |
| 4. 위조(Fabrication)      | 가짜 객체·패킷·신원 신규 생성 -> 인증성 침해 |
+-------------------------------------------------------------+
```

---

## 위조(Fabrication) vs 변조(Modification) 비교

```
[변조 (Modification)]
송신자 =====[ 정상 메시지 A ]=====> [공격자가 A를 A'로 수정] =====> 수신자 (A' 수신)
* 기존에 정상적으로 전송되던 원본 객체가 존재하며, 그 내용을 불법 변경.

[위조 (Fabrication)]
송신자 (전송 없음 / 침묵)
                            [공격자가 가짜 메시지 B 생성] =====> 수신자 (송신자가 보낸 줄 앎)
* 원본 객체가 전혀 존재하지 않는 상태에서, 공격자가 허위 객체를 무에서 생성하여 주입.
```

| 비교 항목 | 변조(Modification) | 위조(Fabrication) |
|---|---|---|
| **행위 본질** | 기존에 존재하는 정당한 데이터의 내용 변경 | 존재하지 않던 가짜 객체를 신규 생성 및 삽입 |
| **침해 보안 속성** | 무결성(Integrity) | 인증성(Authenticity), 무결성(Integrity) |
| **공격 사례** | 전송 중인 금액 필드 수정($100 → $10,000), 패킷 변조 | IP 스푸핑, 위조 인증서 발급, 피싱 이메일 생성 |
| **핵심 방어 기술** | 메시지 인증 코드(MAC), 해시 함수, 암호화 | 전자서명(Digital Signature), 상호 인증, PKI 검증 |

## 위조 공격의 주요 유형

### 1. 신원 위조 (Identity Spoofing)
- **IP/MAC 스푸핑**: 송신자 IP 또는 MAC 주소를 신뢰받는 호스트의 주소로 위조하여 방화벽 필터링을 우회하고 세션 하이재킹 수행.
- **이메일 스푸핑**: SMTP 헤더의 `From` 필드를 거래처 또는 금융기관으로 위조하여 BEC(Business Email Compromise) 사기 및 피싱 유도.
- **DNS 스푸핑**: 가짜 DNS 응답 패킷을 질의자에게 먼저 도달시켜 공격자가 구축한 파밍(Phishing) 웹사이트로 유도.

### 2. 메시지 및 트랜잭션 위조 (Message Fabrication)
- **재생 공격(Replay Attack)**: 과거의 정상 패킷을 캡처한 후 재전송하여 새로운 정당한 요청인 것처럼 시스템을 기만.
- **트랜잭션 위조**: 금융 거래 시스템에서 정당한 사용자의 서명 없이 허위 이체 전문을 새롭게 생성하여 잔고 탈취 시도.

### 3. 인증서 및 신뢰 객체 위조 (Certificate / Credential Fabrication)
- **위조 SSL/TLS 인증서**: 비인가 사설 인증기관(CA) 또는 탈취된 루트 CA 키를 악용하여 위조 도메인 인증서를 발급하고 중간자 공격(MITM) 수행.
- **쿠키 및 토큰 위조**: 서명 검증 키(Secret Key)가 취약한 JWT 토큰의 페이로드를 위조하거나 'alg: none' 취약점을 악용하여 관리자 권한 토큰 위조.

## 위조 방어 기술 체계

```
+-------------------------------------------------------------+
|                      위조 방어 기술 체계                      |
+-------------------------------------------------------------+
| 1. 전자서명 (Digital Signature)  | 송신자 개인키 서명, 부인방지 및 인증성 |
| 2. 메시지 인증 코드 (HMAC)        | 대칭키 기반 메시지 무결성 및 출처 검증 |
| 3. 난수 기반 챌린지-응답 (Nonce)  | 1회용 난수/타임스탬프를 통한 재생 차단 |
| 4. 공개키 기반 구조 (PKI)        | 공인 인증기관의 인증서 폐기목록(CRL/OCSP)|
| 5. 도메인 메일 인증 (SPF/DKIM/DMARC)| 발신 서버 IP 및 암호학적 서명 검증     |
+-------------------------------------------------------------+
```

- **전자서명(Digital Signature)**: 비대칭키 기반으로 작성자의 개인키로 서명하므로 타인이 동일한 서명을 생성하는 위조가 수학적으로 불가능함(부인방지).
- **HMAC(Hash-based MAC)**: 사전 공유된 비밀키와 메시지 해시를 결합하여 키를 보유하지 않은 제3자의 패킷 위조를 완벽 차단.
- **SPF/DKIM/DMARC 메커니즘**:
  - `SPF`: 도메인 관리자가 DNS에 등록한 허용 IP 대역에서 발송되었는지 검증.
  - `DKIM`: 메일 헤더에 개인키 기반 전자서명을 첨부하여 수신 측이 공개키로 검증.
  - `DMARC`: SPF 및 DKIM 검증 실패 시 메일 처리 정책(격리, 차단)을 수신 측에 강제.

## 결론 및 실무 시사점
- 위조 공격은 단순한 데이터 변경을 넘어 시스템의 신뢰 기반(Identity & Trust)을 붕괴시키는 고위험 공격임.
- 제로 트러스트(Zero Trust) 철학 하에서 "결코 신뢰하지 말고 항상 검증하라(Never Trust, Always Verify)" 원칙에 따라, 모든 수신 트랜잭션과 패킷에 대해 상호 인증 및 암호학적 무결성 검증을 필수로 적용해야 함.
