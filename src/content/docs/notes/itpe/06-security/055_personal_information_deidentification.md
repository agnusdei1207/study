## 지식 로드맵 내 현재 위치

개인정보 보호 → 데이터 활용과 식별 위험 → 가명정보 처리

## 30초 인출

- **본질**: 개인정보 비식별화는 개인을 알아볼 가능성을 낮추는 처리의 통칭이며, 현행 법제의 핵심 처리 유형은 가명처리.
- **메커니즘**: 목적·처리환경 확인 → 위험 검토 → 가명처리 → 적정성 검토 → 안전한 활용·관리.
- **구별점**: 가명정보는 계속 개인정보로 보호되고, 익명정보는 합리적으로 고려 가능한 수단으로 개인 식별이 불가능한 정보.

<details><summary>핵심 용어</summary>

- **개인정보 비식별화(De-identification)**: 데이터에서 개인을 알아볼 가능성을 낮추는 처리의 통칭으로, 법률상 단일 처리기법 명칭은 아님.
- **가명정보(Pseudonymized Information)**: 추가정보를 사용하지 않고는 특정 개인을 알아볼 수 없도록 처리한 개인정보.
- **가명처리(Pseudonymization)**: 개인정보의 일부를 삭제·대체하는 등 추가정보 없이는 개인 식별이 어렵게 만드는 처리.
- **익명정보(Anonymous Information)**: 시간·비용·기술 등 합리적으로 고려할 수 있는 수단으로도 개인을 알아볼 수 없는 정보.
- **추가정보(Additional Information)**: 가명정보를 원래 상태로 복원하거나 개인 식별에 쓰일 수 있는 정보.
- **개인정보보호위원회(PIPC, Personal Information Protection Commission)**: 개인정보 보호 정책·감독을 담당하는 대한민국 중앙행정기관.
</details>

### Ⅱ. 정보 유형 구분

| 유형 | 식별 가능성·법적 성격 |
|---|---|
| 개인정보 | 개인을 알아볼 수 있거나 다른 정보와 쉽게 결합해 알아볼 수 있는 정보 |
| 가명정보 | 추가정보 없이는 개인을 알아보기 어렵도록 처리한 개인정보 |
| 익명정보 | 합리적으로 고려 가능한 수단으로도 개인을 알아볼 수 없는 정보 |

가명정보는 개인정보이므로 목적·안전조치·재식별 금지의 적용 대상.

### Ⅲ. 한 줄 제언

제언: 활용 목적과 결합환경을 먼저 평가하고 가명정보와 추가정보를 분리 관리.

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **개인정보 비식별화**는 데이터에서 개인을 알아볼 가능성을 낮추는 처리의 통칭으로, 법률상 핵심 유형은 가명처리. |
| 목적 | 법이 허용하는 데이터 활용에서 개인 식별·정보 노출 위험을 낮추고 안전조치 기반을 마련. |

## Ⅱ. 가명처리와 익명성의 구별

| 유형 | 처리·판단 기준 | 법적·운영상 유의 |
|---|---|---|
| 가명정보 | 추가정보 없이는 특정 개인 식별 곤란 | 개인정보 지위 유지, 보호법상 안전조치·금지의무 적용 |
| 익명정보 | 합리적으로 고려 가능한 시간·비용·기술을 고려해도 식별 불가 | 익명성이 유지되는지 환경 변화에 따라 재평가 |
| 비식별화 | 식별 가능성을 낮추는 여러 처리 방법을 가리키는 표현 | 가명처리·익명처리와 같은 법률상 단일 용어로 혼용하지 않음 |

## Ⅲ. 위험도 기반 가명처리 절차

```text
① 목적·활용자·처리환경 확인
              ↓
② 위험도 판단 ── 내부 활용 / 제3자 제공 / 환경 통제 수준
              ↓
③ 필요한 가명처리·추가정보 분리
              ↓
④ 적정성 검토·필요한 서류 작성
              ↓
⑤ 접근통제·기록·안전한 활용
              └── 목적·제공자·환경이 바뀌면 재검토
```

개인정보보호위원회 2026년 가이드라인은 활용 주체와 처리환경을 중심으로 위험도를 판단하고 위험 수준에 따라 검토 절차·서류를 차등화. 구체 사례의 판단은 해당 가이드와 기관별 환경을 확인.

## Ⅳ. 기법·결합·보호 통제

| 처리·통제 | 역할과 적용 조건 |
|---|---|
| 삭제·대체·범주화 | 직접 식별자나 세부값을 줄여 식별 위험을 낮춤 |
| 총계처리·마스킹 | 세부 노출을 줄이는 기법이며 데이터 특성에 따라 단독 적용의 충분성 검토 |
| k-익명성 | 준식별자 조합의 동질집단 크기를 이용해 연결 가능성을 분석하는 모델 |
| l-다양성·t-근접성 | 집단 내 민감정보의 다양성·분포를 추가로 보는 분석 모델 |
| 가명정보 결합 | 서로 다른 처리자 간 결합은 지정 전문기관에서 수행, 외부 반출은 가명·익명 처리 및 승인 요건 확인 |
| 안전조치 | 추가정보 분리, 접근통제, 목적·처리 기록, 식별정보 생성 시 중지·회수·파기 |

k-익명성·l-다양성·t-근접성은 위험을 분석하는 모델이며 모든 상황을 보증하는 법정 절대 기준은 아님.

## Ⅴ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 명칭·직접식별자 삭제만으로는 외부 정보와의 결합 식별을 막기 어려움. | 활용자·처리환경·외부 결합 가능성을 함께 평가하고 위험 수준에 따라 기법·접근통제·검토 강도를 조정하는 방안. |
