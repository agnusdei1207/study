## 지식 로드맵 내 현재 위치

정보보호 위협 → 악성코드·데이터 갈취 → 예방·탐지·복구

## 30초 인출

- **본질:** 랜섬웨어는 파일·시스템을 사용할 수 없게 하거나 정보를 탈취해 금전적 대가를 요구하는 악성 행위
- **메커니즘:** 침투·권한 확보 → 데이터 암호화·유출 등 피해 → 복호화·비공개를 빌미로 협박
- **핵심 대응:** 침투 경로 축소·이상행위 탐지·격리·검증된 백업 복구

<summary>핵심 용어</summary>

- **랜섬웨어:** 데이터 접근을 막거나 탈취하고 대가를 요구하는 악성코드·공격 행위
- **RaaS (Ransomware as a Service):** 랜섬웨어 운영자가 악성코드·유포 기반 등을 제휴 공격자에게 서비스 형태로 제공하는 범죄 생태계
- **이중 갈취:** 데이터 암호화와 정보 유출 협박을 함께 사용해 피해자에게 압력을 가하는 수법
- **오프라인 백업:** 운영 시스템에서 분리되어 일반적인 네트워크 공격 경로로 바로 변경·삭제하기 어려운 백업 사본
- **불변 백업:** 설정한 보존 조건 동안 수정·삭제를 제한하는 저장 기능을 적용한 백업

---
## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **랜섬웨어**는 데이터 접근을 막거나 탈취하고 대가를 요구하는 악성코드·공격 행위 |
| 목적 | 데이터·서비스 피해와 업무 중단을 줄이고 안전한 복구 기반 확보 |

### Ⅱ. 피해 흐름과 통제

| 공격 단계 | 방어·대응 |
|---|---|
| 침투·계정 악용 | 취약점·원격접속 관리, 다중인증, 최소권한 |
| 내부 확산·백업 접근 | 단말·계정 이상징후 탐지, 백업 계정·경로 분리 |
| 암호화·유출 협박 | 감염 시스템 격리, 증거 보존, 사고대응 절차 가동 |
| 복구 | 깨끗한 백업 검증 후 단계적 복원·모니터링 |

```text
침투·계정 악용
       ↓ 내부 확산·백업 접근
암호화·정보 유출 협박
       ↓ 격리·조사
검증된 백업에서 복구
```

**제언:** 네트워크와 분리된 백업의 무결성·복원 절차를 정기 검증

---
## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **랜섬웨어**는 데이터 접근을 막거나 탈취하고 대가를 요구하는 악성코드·공격 행위 |
| 목적 | 데이터·서비스 피해와 업무 중단을 줄이고 안전한 복구 기반 확보 |

공격은 파일 암호화뿐 아니라 정보 유출·서비스 중단을 결합할 수 있으므로 백업만으로 모든 피해를 복구할 수 있다고 가정하지 않음.

## Ⅱ. 공격 경로와 영향

```text
피싱·취약 서비스·도난 계정
              ↓ 초기 접근
권한 악용·내부 확산·정보 수집
              ↓
백업·복구 경로 공격
              ↓
데이터 암호화 ── 정보 유출 협박
       ↓                 ↓
업무 중단          기밀성·규제 영향
```

| 공격 요소 | 가능한 영향 |
|---|---|
| 파일·시스템 암호화 | 업무서비스 중단, 데이터 복원 필요 |
| 정보 유출 | 기밀성 침해, 통지·규제·평판 위험 |
| 백업·관리계정 공격 | 복구 지연 또는 복구 선택지 축소 |
| 다중 협박 | 암호화 복호화 외에 유출·서비스 중단 압력 |

## Ⅲ. 예방·탐지 통제

| 통제 영역 | 주요 조치 |
|---|---|
| 침투면 | 인터넷 노출 자산·취약점·원격접속의 점검과 신속한 조치 |
| 계정·권한 | 다중인증, 관리자 계정 분리, 최소권한, 자격증명 보호 |
| 단말·네트워크 | 실행행위·대량 변경·비정상 통신 탐지, 구간 분리 |
| 백업 | 별도 계정·경로, 오프라인 또는 불변 사본, 복원 시험 |

## Ⅳ. 사고 대응

```text
탐지·신고
    ↓ 영향 범위 확인
감염 단말·계정·구간 격리
    ↓ 증거·로그 보존
확산·유출 여부 조사
    ↓ 복구 가능성·업무 우선순위 판단
복구 승인·단계적 서비스 재개
```

| 단계 | 판단 기준 |
|---|---|
| 격리 | 확산 방지와 증거 보존을 함께 고려 |
| 조사 | 침해 경로·범위·계정·백업 영향 확인 |
| 통지·협업 | 적용 법령·계약·기관 신고 기준에 따른 보고와 협력 |
| 재개 | 원인 제거, 계정·시스템 검증, 모니터링 준비 |

## Ⅴ. 복구·재발 방지

| 복구 요소 | 운영 기준 |
|---|---|
| 백업 사본 | 오프라인·불변 특성, 접근 분리, 복구 가능성 검증 |
| 복구 순서 | 핵심 업무·의존 서비스와 복구목표에 따른 우선순위 |
| 복원 검증 | 악성코드 잔존 여부·데이터 무결성·업무 기능 확인 |
| 사후 개선 | 침투 원인·통제 공백·대응 지연의 개선과 훈련 반영 |

## Ⅵ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 백업 보유 여부만 확인하면 실제 복구시간·업무 의존성·오염 가능성을 알기 어려움 | 핵심 서비스별 복구 우선순위와 목표시간을 정하고, 격리된 복구환경에서 복원·무결성·업무 검증을 함께 훈련 |
