## 답안 골격
```text
[랜섬웨어] ◀━━ 머리: Ⅶ 내 의견 (단순 백업 맹신 탈피 → 불변 백업(WORM) + EDR 측면 이동 차단 구축)
 ┃
 ┣━ Ⅰ 개요 ───── 전통적 시스템 파괴에서 금전 갈취 목적으로 진화 → 하이브리드 암호화 및 다중 협박 고도화
 ┣━ Ⅱ 특징 ───── 비대칭/대칭 복합 암호화 · VSS(섀도우복사본) 삭제 · 이중/삼중 협박 · 측면 이동(Lateral Movement)
 ┣━ Ⅲ 구조 ───── 전달(피싱/취약점) · 실행/권한상승 · 내부 정찰/전파 · 암호화/유출 · 랜섬노트/협박
 ┣━ Ⅳ 흐름 ───── ① 초기 침투(VPN/RDP) → ② 자격증명 탈취(Mimikatz) → ③ 백업 서버 파괴 → ④ 대량 암호화
 ┣━ Ⅴ 비교 ───── 1세대(단순 화면 잠금) vs 2세대(로컬 암호화) vs 3세대(이중협박: 유출+암호화) vs 4세대(DDoS 결합 다중협박)
 ┗━ Ⅵ 실무 ───── AD(Active Directory) 도메인 컨트롤러 장악 방어 / 불변 스토리지(Immutable Backup) 운영
```
- 필수 키워드: 하이브리드 암호화 · 볼륨 섀도 복사본(VSS) · 이중 협박(Double Extortion) · RaaS · 에어갭 백업 · WORM
- 기출: 138회 4교시 5번 `랜섬웨어 피해와 RaaS 확산` → Ⅰ·Ⅲ·Ⅵ / 128회 1교시 12번 `랜섬웨어와 RaaS` → Ⅴ 비교

## 한 줄 본질
- 시스템 자산에 침투해 중요 파일을 고속 암호화하고 복호화 대가로 가상자산을 요구하는 악성코드 → 복호화 키 독점으로 비즈니스 중단 압박 / 에어갭 백업 부재 시 복구 불능

## 핵심 그림
```text
[현대 랜섬웨어의 다중 협박(Multi-extortion) 킬체인 및 방어 통제점]

  [1. 초기 침투]          [2. 측면 이동]          [3. 백업 파괴]          [4. 암호화/협박]
 ┌──────────────┐       ┌──────────────┐       ┌──────────────┐       ┌──────────────┐
 │ 취약점/RDP   │ ────> │ AD 자격증명  │ ────> │ 백업 콘솔    │ ────> │ 파일 암호화  │
 │ 악성 메일    │       │ 권한 상승    │       │ VSS 강제삭제 │       │ 데이터 유출  │
 └──────┬───────┘       └──────┬───────┘       └──────┬───────┘       └──────┬───────┘
        │                      │                      │                      │
   [MFA/VPN통제]          [EDR 이상탐지]        [불변스토리지WORM]      [유출데이터차단DLP]
```

## 핵심 용어
- 이중 협박(Double Extortion): 데이터를 암호화하기 전에 공격자 C2 서버로 먼저 유출한 뒤, 복호화 비용뿐만 아니라 데이터 비공개 대가까지 요구하는 협박 방식
- WORM(Write Once Read Many): 한 번 기록된 백업 데이터는 관리자 최고 권한으로도 지정 기간 동안 수정·삭제가 불가능한 불변 스토리지 기술

## 핵심 통찰
- 공격자는 파일 암호화 직전에 기업의 온라인 백업 서버와 NAS 디렉토리를 찾아내 백업본부터 우선 파괴함 → 온라인 백업만으로는 복구를 장담할 수 없음
- 랜섬웨어 암호화는 로컬 대칭키(AES)로 고속 암호화하고 해당 대칭키를 공격자의 공개키(RSA)로 감싸는 하이브리드 구조이므로 공격자의 개인키 없이는 수학적 복호화 불가
- 백업 복구 훈련이 없는 기업은 복구 과정에서 백업 데이터베이스 무결성 손상이나 랜섬웨어 재감염으로 복구 시간이 수주일 지연됨

## 이웃 토픽과 구분
- 랜섬웨어 vs 와이퍼(Wiper): 랜섬웨어 = 금전 갈취를 목적으로 복호화 키를 보유 / 와이퍼 = 정치·군사적 목적으로 데이터를 영구 파괴하며 복호화 자체가 불가능

## 문제·원인·대책
- 사례: 138회 기출 사내 중앙 백업 서버까지 랜섬웨어에 동시 감염되어 복구 실패한 제조사 침해 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 네트워크 드라이브에 연결된 백업본 일괄 암호화 | 백업 스토리지가 AD 도메인에 조인되어 관리자 권한 탈취 시 함께 장악됨 | 백업 전용 격리망 분리 및 WORM 기반 불변 백업(Object Lock) 적용 | 백업 데이터의 위변조 및 강제 삭제 차단 |
| 파일 암호화 방어 후에도 데이터 유출로 인한 2차 피해 발생 | 공격자의 데이터 탈취 단계 미탐지 | 대용량 외부 유출 트래픽 탐지(NDR) 및 중요 DB 전 구간 암호화 | 데이터 외부 반출 사전 차단 및 유출 시 기밀성 보장 |

## 이렇게 출제된다
- 제138회 4교시 5번: "최근 기업과 개인을 대상으로 한 랜섬웨어(Ransomware) 피해가 지속적으로 발생하고 있으며, 이를 서비스 형태로 제공하는 RaaS(Ransomware as a Service)의 등장으로 진입 장벽이 낮아지고 있다. 다음 내용을 설명하시오." → 요구 포인트: Ⅲ 공격 전파 메커니즘 + Ⅵ 실무 예방 및 복구 거버넌스
- 제128회 1교시 12번: "랜섬웨어(Ransomware)와 RaaS(Ransomware as a Service)를 설명하시오." → 요구 포인트: Ⅱ 특징 및 수익 모델 + Ⅴ 협박 형태 발전 과정

## 내 의견
- [공격자 협상 및 암호화폐 지불의 악순환] 백업이 무력화된 상태에서 비즈니스 재개를 위해 공격자에게 비용을 지불하지만 복호화 키를 받지 못하거나 2차 표적으로 재공격당하는 사례 빈번 → 나라면: 3-2-1 백업 원칙(3벌 복사, 2개 매체, 1개 오프사이트 에어갭 격리)을 엄격히 강제하고, 분기별 콜드 백업 베어메탈 복구 모의훈련을 전사 KPI로 지정해 무협상 복원력을 확보
