## 지식 로드맵 내 현재 위치

정보보안 → 침해사고 위협 및 악성코드 대응 → **랜섬웨어(Ransomware)**

## 30초 인출

- 본질: **랜섬웨어 (Ransomware)** : 대상 시스템의 사용자 파일, 데이터베이스, 시스템 볼륨을 비대칭·대칭 복합 알고리즘으로 암호화하여 인프라를 마비시키거나 데이터를 유출한 후, 복호화 및 기밀 유지를 빌미로 가상자산 대가를 요구하는 파괴적 악성코드
- 메커니즘: 초기 침투(피싱, VPN 취약점) → 액티브 디렉터리(AD) 장악 및 측면 이동 → 볼륨 섀도 복사본(VSS) 및 백업 서버 파괴 → 대용량 기밀 외번 유출 → 고속 암호화 집행 및 다중 갈취(Multi-extortion)
- 통찰: 관리자 계정 탈취 시 온라인 백업본이 동시 파괴되는 한계와 이중 갈취 위협 극복을 위해 WORM 불변 스토리지 기반 에어갭(Air-gap) 백업 및 사전 데이터 암호화 체계 구축 필수

<details>
<summary>핵심 용어</summary>

- **RaaS (Ransomware-as-a-Service)** : 랜섬웨어 제작자가 악성코드, 유포 인프라, 협상 포털을 플랫폼으로 제공하고 공격 실행자(Affiliate)가 수익을 배분받는 지하 범죄 비즈니스 모델
- **다중 갈취 (Multi-extortion)** : 1차 데이터 암호화 인질극에 이어 2차 데이터 다크웹 유출 협박, 3차 디도스(DDoS) 공격, 4차 피해 기업의 고객/주주에 직접 협박 통보를 결합하는 고도화 수법
- **VSS (Volume Shadow Copy Service)** : 윈도우 OS의 스냅샷 복원 기능으로, 랜섬웨어 침투 시 복원을 방해하기 위해 `vssadmin delete shadows /all /quiet` 명령으로 최우선 강제 삭제
- **WORM (Write Once Read Many)** : 한 번 기록된 데이터는 지정된 보존 기간 동안 최고 관리자 권한으로도 수정 및 삭제가 원천 불가능한 불변(Immutable) 스토리지 기술
- **Air-gap (에어갭)** : 네트워크 침해 전파를 원천 차단하기 위해 주 운영 네트워크와 물리적 또는 논리적으로 완전 격리된 상태를 유지하는 백업 보관 방식

</details>

> 지능화된 랜섬웨어(Ransomware)의 침투·측면이동·암호화 킬체인 단계와 다중 갈취(Multi-extortion) 메커니즘을 설명하고, 백업 서버 동시 파괴 한계 극복을 위한 3-2-1-1-0 백업 전략 및 엔지니어링 복원 방안을 제시하시오. (예상)

## 2~4교시 25점 답안

## Ⅰ. 랜섬웨어의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 시스템 내부의 중요 문서, 데이터베이스, 가상 머신 이미지를 고강도 암호화 기법(AES, ChaCha20, RSA)으로 잠그고 볼륨 섀도 복사본을 파괴하여 시스템을 불능 상태로 만든 후, 복구 키 제공을 조건으로 금전을 갈취하는 악성 소프트웨어 |
| 목적 | 전통적인 단순 화면 차단(Locker)을 넘어 기업의 핵심 지적재산(IP) 유출과 영구적 비즈니스 중단을 유발하여 막대한 가상자산 몸값(Ransom) 획득 |

## Ⅱ. 랜섬웨어의 특징 및 다중 갈취(Multi-extortion) 진화

| 갈취 세대 | 공격 수법 | 주요 협박 대상 및 피해 영향 |
|---|---|---|
| **1차 갈취 (단일)** | 엔드포인트 파일 암호화 | 데이터 복호화 키 대가 요구; 백업 보유 기업에는 효과 없음 |
| **2차 갈취 (이중)** | **데이터 사전 외번 유출 (Exfiltration)** | 백업 복원 시 **"다크웹 유출 사이트(DLS)에 고객사 기밀 공개"** 협박 |
| **3차 갈취 (삼중)** | **서비스 거부 공격 (DDoS)** | 협상 지연 시 피해 기업의 웹사이트, ERP, 인프라에 분산 서비스 거부 공격 감행 |
| **4차 갈취 (사중)** | **이해관계자 직접 압박** | 피해 기업의 고객, 환자, 규제 기관(개인정보위)에 직접 유출 사실을 통보하여 과징금 압박 |

## Ⅲ. 랜섬웨어 침투·장악·암호화 킬체인 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ 엔터프라이즈 랜섬웨어 킬체인 및 암호화 프로세스 ]   │
│                                                                        │
│   [1단계: 초기 침투] ──► 스피어 피싱 메일, 취약한 VPN/RDP 포트 무차별 대입│
│          │                                                             │
│          ▼ [2단계: 권한 상승 및 측면 이동]                             │
│   - Mimikatz 기반 메모리 LSASS 해시 덤프 -> 도메인 컨트롤러(AD) 장악   │
│   - PsExec / WMI / GPO(그룹 정책)를 통한 사내 전 호스트 악성 스크립트 전파│
│          │                                                             │
│          ▼ [3단계: 방어 무력화 및 백업 파괴]                           │
│   - 백신/EDR 강제 종료 (BYOVD 커널 드라이버 취약점 악용)              │
│   - vssadmin 볼륨 섀도 복사본 삭제, Veeam/백업 스토리지 자격증명 포맷  │
│          │                                                             │
│          ▼ [4단계: 데이터 사전 유출 (Exfiltration)]                    │
│   - Rclone / Mega 클라우드로 수백 GB 기밀 데이터 무단 암호화 전송      │
│          │                                                             │
│          ▼ [5단계: 대규모 병렬 암호화 집행]                            │
│   - ChaCha20/AES 대칭키로 초당 수천 개 파일 암호화 -> RSA 공개키로 대칭키 봉인│
│          │                                                             │
│          ▼ [6단계: 랜섬노트 출력 및 협상 유도]                         │
│   - 바탕화면 변조: "RESTORE_FILES_README.txt" 및 Tor 협상 사이트 주소 안내│
└────────────────────────────────────────────────────────────────────────┘
```

| 킬체인 단계 | 주관 공격 기술 | 핵심 방어 및 탐지 포인트 |
|---|---|---|
| **초기 침투** | 악성 매크로, CVE 취약점 익스플로잇 | 외부 노출 포트 스캔 차단, 이메일 첨부파일 CDR 무해화 |
| **측면 이동** | Living-off-the-Land (LotL), RDP 이동 | 네트워크 마이크로세그멘테이션, 계정 MFA 강제 적용 |
| **방어 무력화** | 백업 계정 탈취, VSS 섀도 삭제 | 백업망 물리 격리, 볼륨 섀도 복사본 삭제 명령어 EDR 차단 |
| **암호화 실행** | I/O 버퍼 고속 비동기 암호화 | 비정상적인 디스크 I/O 버스트 및 대량 파일 확장자 변경 탐지 |

## Ⅳ. 전통적 악성코드 vs 랜섬웨어 vs RaaS 비교

| 비교 항목 | 전통적 악성코드 (바이러스/웜) | 고전적 랜섬웨어 (WannaCry) | 현대 RaaS (BlackCat, LockBit) |
|---|---|---|---|
| **공격 주체** | 개인 해커, 단순 과시형 해커 | 불특정 다수 대상 자동 전파 악성코드 | **기업화된 사이버 범죄 조직 (개발사+제휴사)**|
| **표적 대상** | 무작위 일반 PC 대량 감염 | 무작위 SMB 취약 포트 감염 | **지불 능력이 높은 엔터프라이즈 타깃 사냥** |
| **공격 기법** | 단순 파괴, 봇넷 감염, 좀비 PC화 | 단일 호스트 파일 단순 암호화 | **AD 장악, 백업 선제 파괴, 다중 갈취 병행** |
| **침투 수단** | 악성 웹 다운로드, USB 전파 | EternalBlue 등 네트워크 취약점 | 피싱, 초기 접근 브로커(IAB) 계정 구매 |
| **복구 난이도** | 백신 치료 및 삭제 용이 | 백업 보유 시 복구 가능 | **백업까지 파괴되어 복구 극도로 곤란** |

## Ⅴ. 랜섬웨어 대응 시 핵심 엔지니어링 한계와 방안

| 한계 | 방안 |
|---|---|
| 공격자가 탈취한 도메인 최고 관리자(Domain Admin) 권한을 이용해 온라인으로 연결된 중앙 백업 시스템(Veeam, NAS)에 접속하여 백업 보존 주기를 단축하거나 스토리지 볼륨을 강제 포맷하여 백업본 동시 파괴 발생 | 백업 스토리지에 관리자 권한으로도 지정 기간 동안 삭제가 원천 불가능한 WORM 불변 객체 잠금(S3 Object Lock / Immutable Backup)을 설정하고, 메인 프로덕션 네트워크와 물리적으로 단절된 에어갭(Air-gap) 오프라인 테이프 및 격리된 사이버 벙커(Cyber Recovery Vault) 구축 |
| 백업 시스템을 복원하여 서비스를 재개하더라도 공격자가 침투 초기에 C2 서버로 대량 사전 유출(Exfiltration)한 고객사 개인정보 및 지적재산을 빌미로 다크웹 공개 협박을 가하는 2차 갈취에 무력화 | 사내 엔드포인트 및 게이트웨이 구간에 네트워크 DLP(Data Loss Prevention)를 구축하여 비정상 대용량 아웃바운드 트래픽을 실시간 차단하고, 중요 RDB 및 정형/비정형 데이터베이스에 저장 시점부터 필드 레벨 상시 암호화(Always Encrypted) 적용 |
| 백업 데이터 자체에 공격자가 심어둔 백도어 악성코드나 휴면 상태의 랜섬웨어 스크립트가 함께 백업되어 서비스 복원 시 악성코드가 재실행되며 2차 감염이 유발되는 복원 오염(Re-infection) 발생 | 프로덕션 환경으로 즉시 복원하지 않고 네트워크가 완벽히 차단된 격리 검증 샌드박스(Clean Room)에서 백업 이미지의 무결성 검증, YARA 룰 기반 악성코드 스캔, 취약점 패치 완료 후 무균 상태 확인 후 단계적 서비스 재개 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
랜섬웨어 대응은 단순 엔드포인트 백신(EPP) 수준을 넘어 전사적 사이버 복원력(Cyber Resilience) 관점에서 접근해야 하며, 기존 '3-2-1 백업 원칙'을 고도화하여 1개의 불변 백업과 0개의 복구 에러를 포함하는 '3-2-1-1-0 백업 전략'을 수립하고, 최소 반기 1회 이상 전사 불시 재해 복구(DR) 실전 전환 훈련 집행 권장

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│               [ 랜섬웨어 방어 3-2-1-1-0 백업 및 사이버 벙커 구조 ]     │
│                                                                        │
│   [운영 프로덕션 환경 (Production)]                                     │
│   - 데이터 복제본 3개 유지 (운영 1개 + 백업 2개)                        │
│          │                                                             │
│          ├───────────────────────┐                                     │
│          ▼ (로컬 고속 복제)      ▼ (네트워크 분리 복제)                │
│   [미디어 1: 로컬 NVMe/NAS]  [미디어 2: 오프사이트 백업]                │
│   (서로 다른 2종 매체)       (지리적으로 이격된 제2센터)                │
│                                  │                                     │
│                                  ▼ [단방향 에어갭 (Air-gap) 데이터 다이오드]│
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │                 격리된 사이버 벙커 (Cyber Vault)               │   │
│   │  - 1: 불변 스토리지 (WORM Object Lock: 관리자도 삭제 불가)     │   │
│   │  - 1: 오프라인 에어갭 (네트워크 물리적 분리)                   │   │
│   │  - 0: 복구 오류 0 (일일 자동 복구 유효성 검증 파이프라인 가동) │   │
│   └────────────────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 백업 기술 유형 | RTO (복구 시간) | 랜섬웨어 내성 | 관리 복잡도 | 엔지니어링 특징 |
|---|---|---|---|---|
| **온라인 NAS 백업** | 수 분 이내 (초고속) | **극히 취약 (백업본 동시 암호화)**| 낮음 | 단순 파일 공유 프로토콜(SMB/NFS) |
| **스냅샷 복원** | 수 초 이내 (즉각) | 취약 (VSS 및 스토리지 API 공격) | 중간 | 스토리지 컨트롤러 레벨 포인터 복원 |
| **WORM 불변 백업** | 수 시간 이내 | **매우 우수 (소프트웨어적 변조 차단)**| 중간 | S3 Object Lock, 보존 기간 강제 잠금 |
| **에어갭 사이버 볼트**| 수 시간 ~ 1일 | **최고 수준 (물리적 연결 차단)** | 높음 | 금융사/국가기반시설 전용 금고 인프라 |
