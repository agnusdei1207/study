## 연관 키워드

- 생성형 AI 보안 가이드라인, 국가정보원 AI 보안 가이드북, 개인정보 보호 가이드
- 폐쇄망 LLM, 온프레미스, SaaS AI, 프롬프트 입력 금지, 학습 데이터 활용 거부
- 섀도우 AI, DLP, 인간 검증, 망분리, 에이전틱 AI, 보안 위협과 보안 대책

## Ⅰ. 생성형 AI 활용 보안 가이드라인의 개요

- 핵심 요약 : 공공과 민간 조직이 생성형 AI를 도입·운영할 때 기밀 유출을 막기 위해 국가 기관이 제시한 보안 지침 체계.
- 개념 : **생성형 AI** (Generative AI), 그중에서도 **대형 언어 모델** (LLM, Large Language Model)의 도입과 운영에서 학습 데이터, 프롬프트, 산출물에 생기는 보안 위협을 점검하고 대책을 제시하는 AI 보안 가이드라인. 국내에서는 국가정보원이 발간한 AI 보안 가이드북이 대표적이다.
- 배경 및 필요성 : 임직원이 생성형 AI로 문서를 요약하거나 코드를 작성하는 과정에서 비공개 행정 정보와 영업비밀이 외부 AI 서비스로 전송되는 사례가 늘면서, 도입 기준을 정한 국가 지침이 필요해졌다.
- 주요 목적 : 도입 전 위험을 평가하고 운영 단계의 통제 항목을 명확히 하여, 기밀 유출 없이 AI를 업무에 활용하는 기반을 마련하는 것.
- 발표 내용 : 국가정보원 발표 기준으로, 개정판 가이드북은 학습데이터 오염 등 15개 보안위협과 30개 보안대책을 담았으며, 300개 공공기관의 AI 도입·보안관리 실태 조사를 반영했다. 생성형 AI뿐 아니라 에이전틱 AI와 피지컬 AI까지 범위에 포함했다.

## Ⅱ. 생성형 AI 활용 보안 가이드라인의 특징 및 장점

- 핵심 요약 : 업무 위험도에 따라 도입 방식을 나누고, 입력 금지 정보와 학습 활용 거부를 명문화하여 기밀 유출 경로를 줄이는 방식.

1. 위험도 기반 도입 방식 : 비공개 데이터를 다루는 업무는 **폐쇄망 LLM** (On-Premise)에, 공개 데이터의 일반 업무는 보안 검토를 거친 SaaS(Software as a Service) AI에 배치 → 업무 등급별로 노출 범위가 달라짐.
2. 프롬프트 입력 금지 정보의 명문화 : 비공개 행정 정보, 영업비밀, 개인정보, 계정 자격증명을 프롬프트에 넣지 않도록 규정 → 입력 단계의 유출을 원천에서 차단.
3. 학습 데이터 활용 거부 설정 : 상용 AI를 쓸 때 입력 내용이 후속 학습 데이터로 재사용되지 않도록 설정 → 외부 학습을 통한 2차 유출 방지.
4. 인간 검증 의무 : 생성 결과는 허위 정보나 라이선스 위반 가능성이 있으므로 사람이 최종 확인 → 산출물의 책임 소재를 명확히 함.

## Ⅲ. 생성형 AI 활용 보안 가이드라인의 구조 (흐름)

- 핵심 요약 : 기획, 구축, 운영의 세 단계에서 통제 항목이 나뉘고, 운영 단계에서 사내 프록시 감사로 마무리되는 생애주기 구조.

```text
[ 1. 사전 기획 ]

업무 위험도 평가 → 도입 방식 결정
   ↓
[ 2. 구축·개발 ]

학습 데이터 비식별화
프롬프트 인젝션 방어 필터
   ↓
[ 3. 이용·운영 ]

입력 금지 정보 준수
사내 AI 프록시 로깅과
DLP(Data Loss Prevention) 감사
```

```text
[ 가이드라인 연계 체계 ]

국가 기관 가이드 → 조직 보안 정책
   ↓
사내 AI 프록시 · 승인된 AI 포털
   ↓
임직원 이용 · 정기 점검
```

- 구조의 핵심은 도입 전 판단과 운영 중 감사가 이어져야 한다는 점이며, 가이드는 두 단계를 연결하는 역할을 한다.

## Ⅳ. 생성형 AI 활용 보안 가이드라인의 비교

- 핵심 요약 : 국가 기관 가이드는 기밀 보호와 망 통제에, 개인정보 가이드는 개인정보 처리에, 국제 프레임워크는 위험 관리 전 주기에 초점을 둔다.

| 비교 항목 | 국가정보원 AI 보안 가이드북 | 개인정보보호위원회 생성형 AI 가이드 | NIST AI RMF(Risk Management Framework) |
| --- | --- | --- | --- |
| 주관 기관 | 국가정보원 | 개인정보보호위원회 | 미국 국립표준기술연구소 (NIST) |
| 핵심 초점 | 기밀 보호, 보안 위협과 대책 | 개인정보의 적법 처리와 이용자 보호 | AI 시스템의 신뢰성과 위험 관리 |
| 주요 대상 | 공공기관과 주요 기업 | 개인정보를 다루는 AI 사업자와 이용자 | AI 개발과 활용 조직 |
| 구성 방식 | 위협과 대책의 목록 | 이용자 안내와 처리 원칙 | Govern, Map, Measure, Manage |

- 선택 기준 : 국내 공공 조직은 국가정보원 가이드북을 기준으로 삼고, 개인정보 처리가 포함되면 개인정보보호위원회 가이드를 함께 적용하며, 글로벌 조직은 NIST AI RMF를 위험 관리 틀로 쓴다.

## Ⅴ. 생성형 AI 활용 보안 가이드라인의 한계와 방안

- 핵심 요약 : 섀도우 AI, 망분리 충돌, 가이드와 에이전트의 간극을 단말 관리, 등급별 허용, 정기 개정으로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 섀도우 AI 통제의 어려움 | 개인 기기로 기밀 내용을 옮겨 상용 AI에 입력하면 사내망 통제가 닿지 않음 | 모바일 기기 관리(MDM, Mobile Device Management)와 승인된 사내 AI 포털 제공 | 승인 외 AI 서비스 접속 건수 |
| 망분리 규제와 클라우드 AI의 충돌 | 업무망이 인터넷과 분리되어 최신 클라우드 AI를 쓸 수 없음 | 공개 등급 업무부터 단계적으로 허용하고 업무망에는 경량 온프레미스 모델 배치 | 업무별 AI 활용 허용 범위 |
| 정적 가이드와 AI 에이전트의 간극 | 질의응답 중심 지침이라 도구를 스스로 호출하는 에이전트 위협을 충분히 다루지 못함 | 가이드의 주기적 개정과 에이전트 API 호출 권한의 IAM(Identity and Access Management) 통제 | 에이전트 권한 검토 주기 |

## Ⅵ. 생성형 AI 활용 보안 가이드라인에 대한 기술사적 제언

- 핵심 요약 : 가이드를 승인 절차와 감사 체계로 실제 운영에 연결하고, 에이전트 시대에 맞춰 개정 주기를 제도화하는 방향.

1. 보안성 검토 절차의 표준화 : 생성형 AI 도입 시 검토 항목을 체크리스트로 정형화하고, 검토를 통과한 서비스 목록을 조직 내에 공개해 현업이 승인된 도구를 쉽게 찾게 한다.
2. 프롬프트 감사 체계 구축 : 임직원의 질의를 DLP와 함께 감사하고, 기밀 키워드가 탐지되면 전송을 막는 절차를 두며, 보관 기간은 내부 규정에 맞춰 정한다.
3. 실전형 교육 : 문서 배포에 그치지 않고, 기밀 유출을 가정한 모의 훈련을 정기적으로 실시해 입력 금지 정보를 실제로 지키게 한다.

## Ⅶ. 결론

- 핵심 요약 : 생성형 AI 보안 가이드라인은 도입 기준과 운영 감사를 잇는 기준선으로, 기술보다 절차가 실효성을 좌우하는 영역.
- 시사점 : 가이드는 한 번 배포하는 문서가 아니라 AI 기술 변화에 맞춰 계속 갱신되는 체계로 운영되어야 한다.
