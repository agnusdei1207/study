## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **암호학적 해시 함수** 는 임의 길이 입력을 고정 길이 다이제스트로 변환하는 단방향 함수 |
| 목적 | 메시지 무결성 확인, 전자서명 대상 요약, HMAC 기반 메시지 인증 지원 |

검증자는 같은 메시지를 다시 해시해 값을 비교 가능. 해시값 공개만으로는 메시지 교체 방지나 출처 인증을 보장하지 않음.

| 처리 | 확인할 수 있는 점 | 단독으로 보장하지 않는 점 |
|---|---|---|
| 해시값 비교 | 비교 대상 메시지가 달라졌는지 확인 | 송신자 신원, 기밀성 |
| HMAC 검증 | 공유 비밀키 보유자에 의한 메시지 인증 | 공개 검증 가능한 부인방지 |
| 전자서명 검증 | 공개키 기반 서명 확인 | 메시지 기밀성 |

## Ⅱ. 구조와 계산 흐름

일반적인 반복형 해시 구성은 메시지를 블록으로 나누고 각 블록을 압축함수에 반영해 최종 다이제스트를 생성. 구체적인 내부 구조는 알고리즘별로 다르며 SHA-3 계열은 Keccak 순열 기반 구조.

```text
메시지
  ↓ 전처리·블록 구성
블록별 해시 연산
  ↓
최종 다이제스트
```

## Ⅲ. 핵심 보안 요구사항

```text
입력 M → H(M)=h
  ├─ h만 주어짐: 역상 M 탐색 저항
  ├─ M이 주어짐: 다른 M' 탐색 저항
  └─ 입력 제한 없음: 같은 h의 쌍 탐색 저항
```

해시 보안 요구사항은 공격자가 찾으려는 대상에 따른 구분. 작은 입력 변화에 출력이 달라지는 눈사태 효과는 유용한 설계 특성이지만 저항성 정의와는 별개.

| 요구사항 | 주어진 값 | 공격 목표 |
|---|---|---|
| 역상 저항성 | 다이제스트 `h` | `H(M)=h`인 메시지 M 찾기 |
| 제2역상 저항성 | 메시지 M | `H(M')=H(M)`인 다른 M' 찾기 |
| 충돌 저항성 | 없음 | `H(M)=H(M')`인 임의의 서로 다른 쌍 찾기 |

### 활용과 알고리즘 선택

NIST FIPS 180-4는 SHA-2 계열, FIPS 202는 SHA-3 계열 표준. SHA-1은 허용 용도가 제한되어 있으므로 신규 보안 설계에서는 현행 지침과 상호운용 요구를 확인한 알고리즘 선택.

| 활용 | 적용 방법 | 주의점 |
|---|---|---|
| 파일·메시지 무결성 | 안전한 해시값 비교 | 해시값 전달 경로도 신뢰해야 함 |
| 전자서명 | 다이제스트를 서명 절차에 입력 | 서명 스킴·키 관리와 함께 설계 |
| 메시지 인증 | HMAC 등 키 기반 구성 사용 | 단순 해시는 인증을 제공하지 않음 |
| 비밀번호 검증 | Salt와 전용 KDF로 검증값 저장 | 빠른 범용 해시만 반복 적용하지 않음 |

## Ⅳ. 한계와 방안

| 한계 | 해결 방안 |
|---|---|
| 충돌 저항성이 약한 레거시 알고리즘을 신규 서명·무결성에 사용 | 목적에 맞는 현행 권고 알고리즘으로 전환하고 상호운용성 시험 |
| 비밀번호를 SHA-256 등 빠른 일반 해시만으로 저장 | salt와 설정 가능한 비용을 갖춘 비밀번호 전용 KDF 사용 |
| 해시 비교만으로 송신자 인증을 보장한다고 오해 | 키 보유자를 인증해야 하면 HMAC, 공개키 검증이 필요하면 전자서명 적용 |

## Ⅴ. 제언

해시 사용처를 무결성·출처 인증·비밀번호 저장으로 구분하고 각 목적의 알고리즘과 키 관리 기준을 우선 점검.
