## 연관 키워드

- SKT 유심 정보 유출, 유심(USIM), HSS(Home Subscriber Server), IMSI(International Mobile Subscriber Identity)
- 가입자 인증키 Ki, AKA(Authentication and Key Agreement), 복제 유심(Clone SIM), 심 스와핑(SIM Swapping)
- HSM(Hardware Security Module), 제로트러스트(Zero Trust), SUCI(Subscription Concealed Identifier), 지능형 지속 위협(APT)

## Ⅰ. SKT 유심 정보 유출 사고의 개요

- 핵심 요약 : 통신 코어망 인증 DB에 키를 평문으로 둔 구조가 복제 유심과 심 스와핑 금융 사기 위험으로 이어진 이동통신 보안 사고.
- 개념 : 2025년 4월 공개된 SK텔레콤 해킹 사고로, **지능형 지속 위협** (APT, Advanced Persistent Threat) 조직이 통신 코어망의 가입자 인증 데이터베이스인 **HSS** (Home Subscriber Server)에 침투해 가입자 식별자 IMSI(International Mobile Subscriber Identity)와 인증 관련 키가 유출된 사건.
- 배경 및 필요성 : 이동통신 상호 인증의 근간인 **가입자 인증키** (Ki)가 함께 유출되면 **복제 유심** (Clone SIM)과 **심 스와핑** (SIM Swapping)을 통한 금융 사기 우려가 커짐. 단순 개인정보 유출과 달리 인증 체계 자체가 흔들리는 위협임.
- 주요 목적 : 인증 정보 평문 보관 결함 규명, **HSM** (Hardware Security Module) 기반 키 격리 체계로의 전환, 통신·금융 이상거래 연계 차단.

## Ⅱ. SKT 유심 정보 유출 사고의 특징 및 영향

- 핵심 요약 : 협력사 경로를 통한 내부 침투와 인증키 평문 보관이 결합되어, 통신 인증 신뢰가 금융 피해로 전이됨.

1. 평문 키 보관 : 가입자 인증키 Ki와 사업자 인증 파라미터 OPc를 암호화 없이 저장 → 데이터 탈취만으로 복제 유심 제작 조건 성립.
2. **AKA** (Authentication and Key Agreement) 상호 인증 : 단말과 망이 Ki 기반 응답을 주고받는 구조 → Ki를 아는 공격자가 정품과 같은 응답을 계산.
3. 협력사 경로 침투 : 외주 원격 접속 계정을 거쳐 망분리 경계 내부로 이동 → 외곽 통제만으로 내부 자산을 지키지 못함.
4. 금융 연쇄 피해 : 복제 유심 단말이 문자 인증과 통화를 수신 → 통신 침해가 금융 거래 피해로 확산.

```text
[ 공격 경로 ]

협력사 원격 접속 계정 탈취
        ↓
내부 연계 서버로 횡적 이동
        ↓
가입자 인증 DB(HSS) 접근
        ↓
인증키 포함 데이터 대량 반출
```

## Ⅲ. SKT 유심 정보 유출 사고의 구성 요소 및 흐름

- 핵심 요약 : 유출 항목별 역할과 결함을 대응시키면, 인증키의 하드웨어 격리가 가장 핵심적인 개선점임.

```text
[ 키 유출 이후 위협 흐름 ]

Ki·OPc 평문 유출
        ↓
복제 유심(Clone SIM) 제작
        ↓
심 스와핑으로 문자·통화 수신
        ↓
본인확인 우회 → 금융 거래 피해
```

| 유출 항목 | 기술적 역할 | 사고 시 결함 | 개선 방향 |
| --- | --- | --- | --- |
| IMSI | 가입자 고유 식별자 | 평문 노출로 회선 특정 가능 | SUCI(Subscription Concealed Identifier) 기반 식별자 은닉 |
| Ki | 유심과 HSS가 공유하는 128비트 대칭 비밀키 | DB에 평문 저장 | HSM 내 격리 보관 |
| OPc | 사업자 인증 파라미터 | Ki와 함께 평문 유출 | 키 관리 체계 기반 주기적 교체 |
| 코어망 접근 | HSS 등 서버 접속 통제 | 원격 유지보수 계정 단일 인증 | 제로트러스트(Zero Trust) 및 다요소 인증(MFA, Multi-Factor Authentication) |

## Ⅳ. SKT 유심 정보 유출 사고의 비교 분석

- 핵심 요약 : 키를 데이터베이스에 평문으로 두는 방식과 하드웨어에 격리하는 방식의 차이가 유출 시 피해 규모를 가름.

| 비교 축 | 평문 DB 보관 (사고 당시) | HSM 격리 보관 |
| --- | --- | --- |
| 탈취 시 결과 | 키가 그대로 노출되어 복제 유심 제작 가능 | 키 추출이 하드웨어 경계에서 차단됨 |
| 키 사용 방식 | 애플리케이션이 키 값을 직접 읽음 | 장치 내부에서 연산만 수행 |
| 접근 감사 | 누가 언제 조회했는지 추적이 어려움 | 키 사용 이력을 장치 단위로 기록 |

## Ⅴ. SKT 유심 정보 유출 사고의 한계와 방안

- 핵심 요약 : 유심의 물리적 교체 부담, 무선 구간 식별자 노출, 통신과 금융의 분절이 주요 한계이며 각각 기술과 연계 체계로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 유심 재발급 부담 | 키가 칩에 고정되어 대면 교체가 필요하고 물류 부담 증가 | eSIM 기반 소프트웨어 프로파일 원격 재발급(OTA, Over-The-Air) 확대 | 원격 재발급 완료율 |
| 무선 구간 IMSI 노출 | LTE(Long-Term Evolution) 초기 접속 시 식별자가 평문 노출되어 도청 위험 | 5G SUCI 방식으로 식별자 은닉 적용 | 식별자 평문 노출 건수 |
| 통신·금융 분절 | 통신사 침해가 금융 사기로 이어져도 실시간 연계 부재 | 통신사·금융사 간 FDS(Fraud Detection System) 연계와 기기 변경 시 거래 일시 제한 | 연계 경보 처리 시간 |

## Ⅵ. SKT 유심 정보 유출 사고에 대한 기술사적 제언

- 핵심 요약 : 인증키 보관을 하드웨어 경계 안으로 옮기고, 통신과 금융이 실시간으로 위협 신호를 주고받는 체계의 정착이 필요함.

1. 가입자 인증 시스템 전반에 HSM 기반 키 보관을 의무화하고, 키를 다루는 모든 데이터베이스에 공인 검증을 받은 장비만 쓰도록 기준을 정하는 것이 필요함.
2. 문자 기반 본인확인에 대한 의존을 줄이고, 단말에 묶인 인증 수단으로 전환하는 방향을 통신사와 금융사가 공동 기준으로 마련하는 것이 바람직함.
3. 통신 3사의 가입자 인증 서버를 핵심 기반시설 관리 대상에 포함하고 정기 보안 감사를 의무화하는 정책 검토가 필요함.

## Ⅶ. 결론

- 핵심 요약 : 인증키의 평문 보관은 통신 침해를 금융 피해로 바꾸는 지름길이라는 점을 보여준 사례.
- 시사점 : 키의 하드웨어 격리와 통신·금융 간 연계가 함께 갖춰질 때 가입자 인증 신뢰가 유지됨.
