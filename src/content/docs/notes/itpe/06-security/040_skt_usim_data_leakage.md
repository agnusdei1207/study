## Ⅰ. SKT 유심(USIM) 핵심 인증정보 유출 사고의 개요

- **개념** : 고도화된 지능형 지속 위협(APT) 해커 조직이 SK텔레콤 내부 백본망에 수년간 은닉 잠복하여 이동통신 가입자 인증 핵심 데이터베이스인 HSS(Home Subscriber Server)에 침투, 2,300만 명 가입자의 IMSI뿐 아니라 3GPP 비밀 인증키인 Ki 및 OPc를 통째로 평문 유출시킨 국가적 통신 보안 침해사고.
- **배경 및 필요성** : 단순한 고객 개인정보(이름, 주소) 유출을 넘어, 이동통신 암호학적 상호 인증의 근간인 가입자 비밀키(Ki)가 유출되어 복제 유심(Clone SIM) 제작 및 대규모 심 스와핑(SIM Swapping) 금융 사기 공포를 촉발.
- **핵심 목적** : 이동통신 코어망 가입자 인증 메커니즘 취약점 규명, 암호키 평문 보관 결함 제거, HSS 인프라의 하드웨어 보안 모듈(HSM) 봉인 및 통신-금융 이상거래 연계 차단.

## Ⅱ. SKT 유심(USIM) 핵심 인증정보 유출 사고의 핵심 아키텍처 및 동작 메커니즘

공격자는 협력업체 VPN을 통해 내부망에 침투한 후 Active Directory와 망 연계 서버를 장악하여 통신 코어망 HSS 데이터베이스를 덤프(9.82GB)하여 외부로 유출함.

```text
[ SKT 유심 정보 유출 사고 공격 경로 및 USIM 복제 메커니즘 ]

  [ 공격자 (외곽 침투) ] ──> 협력업체 원격 유지보수 계정 탈취 (VPN 통과)
                                    │
                                    ▼ 1. 횡적 이동 (Lateral Movement)
  +-------------------------------------------------------------+
  | SKT 내부 업무망 / 코어망 연계 서버                          |
  |  - 망분리 환경이었으나 유지보수용 연계 게이트웨이 침해      |
  |  - Active Directory 권한 상승 -> 도메인 컨트롤러 장악       |
  +------------------------------┬------------------------------+
                                 │ 2. 통신 코어망 HSS DB 침투
                                 ▼
  +-------------------------------------------------------------+
  | 가입자 마스터 DB : HSS (Home Subscriber Server)             |
  |  - 유출 데이터: 2,300만 건 (9.82GB)                          |
  |  - [치명적 결함] : 전화번호, IMSI 외에 비밀키 Ki, OPc가     |
  |                    암호화 조치 없이 '평문(Plaintext)' 보관! |
  +------------------------------┬------------------------------+
                                 │ 3. 대량 덤프 외부 반출
                                 ▼
  +-------------------------------------------------------------+
  | 복제 유심(Clone SIM) 제작 및 심 스와핑(SIM Swapping) 위험  |
  |  - 공유 비밀키(Ki)와 OPc를 공 USIM 칩에 기록 -> 복제 완료  |
  |  - 가입자의 모든 전화, SMS 수신을 복제폰으로 가로챔         |
  |  - 은행 공인인증서/OTP 재발급 -> 금융 자산 무단 이체 위험  |
  +-------------------------------------------------------------+
```

- **핵심 인증 파라미터(Ki, OPc) 평문 보관** : USIM 칩과 HSS에만 극비 보관되어야 하는 128비트 대칭 비밀키 Ki와 사업자 키 OPc가 DB 내에 암호화되지 않고 평문 저장되어 통째 탈취.
- **3GPP AKA 상호 인증 무력화** : Ki와 OPc를 알면 공격자가 정품 가입자와 수학적으로 완벽히 동일한 암호학적 응답(RES)과 세션 키(CK, IK)를 생성할 수 있어 복제 유심 제작 가능.
- **협력업체 공급망을 통한 망분리 무력화** : 외부 인터넷과 단절된 코어망이었으나, 외주 유지보수 업체의 원격 접속 망연계 경로를 공격자가 타고 넘어가는 공급망 횡적 이동 차단 실패.
- **심 스와핑(SIM Swapping) 금융 연쇄 위협** : 복제 유심을 단말에 장착하면 피해자의 모든 SMS 본인확인 문자와 금융 ARS 전화가 공격자 단말기로 수신되는 치명적 파급 효과.

## Ⅲ. SKT 유심(USIM) 핵심 인증정보 유출 사고의 세부 구성 요소 및 비교 분석

| 유출 항목 | 기술적 역할 | 사고 시 결함 상태 | 사후 엔지니어링 개선책 |
| --- | --- | --- | --- |
| IMSI | 국제 이동가입자 고유 식별 번호 (회선 식별자) | 평문 노출로 가입자 회선 특정 | 5G SUCI (공개키 암호화 은닉 식별자) 적용 |
| Ki (Subscriber Key) | USIM 칩과 HSS의 128비트 공유 대칭 비밀키 | HSS DB에 비암호화 평문 저장 | 하드웨어 보안 모듈(HSM) 내 영구 격리 봉인 |
| OPc (Operator Key) | 통신사 고유 파라미터 (MILENAGE 알고리즘 연산용) | Ki와 함께 평문 덤프 유출 | KMS 기반 주기적 키 로테이션 및 HSM 관리 |
| 코어망 접근통제 | HSS 등 가입자 코어 서버 접속 통제 | 원격 유지보수 계정 단일 인증 허용 | 제로트러스트 ZTNA, FIDO2 MFA, 전용 바스티온 |

- 이 사건은 데이터베이스에 보관되는 핵심 암호키(Ki)를 HSM 등 안전한 하드웨어에 격리하지 않고 평문으로 방치했을 때 초래되는 재앙적 결과를 보여준 이동통신 보안의 역사적 반면교사임.

## Ⅳ. SKT 유심(USIM) 핵심 인증정보 유출 사고의 주요 한계점 및 해결 방안

- **유출된 2,300만 가입자의 물리적 유심 재발급 비용 및 물류 한계** :
  - **한계점** : Ki가 털린 유심은 소프트웨어로 키를 바꿀 수 없어 전 국민이 대리점을 방문해 유심 칩을 물리적으로 교체해야 하는 막대한 물류 마비.
  - **해결 방안** : OTA(Over-The-Air) 원격 키 업데이트 기술 연구 및 eSIM 기반 소프트웨어 프로파일 원격 재발급 인프라 구축.
- **단말이 기지국과 통신할 때 IMSI가 무선 구간에 평문 송출되는 구조** :
  - **한계점** : LTE 환경에서는 단말이 최초 접속 시 IMSI를 평문으로 브로드캐스팅하므로 가짜 기지국(IMSI Catcher)에 의한 도청 취약 잔존.
  - **해결 방안** : 5G 표준 보안 기술인 SUPI-SUCI 암호화를 적용하여 무선 구간에 타원곡선 공개키(ECIES)로 암호화된 일회용 식별자만 전송.
- **통신사 침해가 금융권 사기로 전이되는 크로스 도메인 공격** :
  - **한계점** : 통신사가 해킹당했는데 금융 자산이 털리는 구조로, 통신사와 금융사 간의 실시간 위협 정보 공유 체계 부재.
  - **해결 방안** : 통신사-금융사 간 '심 스와핑 실시간 FDS 연계망'을 구축하여 유심이 기변되거나 복제 의심 시 금융 거래 자동 일시 중단.

## Ⅴ. SKT 유심(USIM) 핵심 인증정보 유출 사고 적용 및 발전을 위한 기술사적 제언

- **코어망 암호 자산의 HSM(Hardware Security Module) 전면 의무화** : HSS, UDM 등 가입자 인증키를 처리하는 모든 데이터베이스에 대해 FIPS 140-2 Level 3 이상 HSM 암호화 강제.
- **SMS 기반 본인확인 의존도 전면 폐지** : 통신 회선 침해에 취약한 SMS 인증 문자를 퇴출하고, 모바일 신분증 및 FIDO2 기반 앱 인앱 생체인증으로 전면 전환.
- **국가 기간통신망에 대한 침해사고 대응 지침 강화** : 통신 3사의 가입자 인증 서버를 국가 핵심정보통신기반시설로 상향 지정하고 정기 보안 감사 의무화.
