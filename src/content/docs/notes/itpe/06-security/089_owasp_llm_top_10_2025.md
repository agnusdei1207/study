## 핵심 그림
```text
[OWASP Top 10 for LLM Applications (2025년 버전) 10대 위협 구성]

   [입력/데이터 계층]
   ├─ LLM01: 프롬프트 인젝션 (Prompt Injection - 직접/간접 조작)
   ├─ LLM02: 민감정보 노출 (Sensitive Information Disclosure)
   ├─ LLM03: 공급망 취약점 (Supply Chain Vulnerabilities - 모델/데이터/플러그인)
   └─ LLM04: 데이터 및 모델 중독 (Data and Model Poisoning)

   [추론/시스템 계층]
   ├─ LLM05: 부적절한 출력 처리 (Improper Output Handling - XSS/RCE 유발)
   ├─ LLM06: 과도한 대행 (Excessive Agency - 에이전트의 과도한 자율 권한)
   ├─ LLM07: 시스템 프롬프트 유출 (System Prompt Leakage)
   └─ LLM08: 벡터 및 임베딩 취약점 (Vector and Embedding Weaknesses - RAG 오염)

   [운영/서비스 계층]
   ├─ LLM09: 모델 서비스 거부 (Model Denial of Service - 리소스 고갈)
   └─ LLM10: 무제한 소비 / 과도한 의존 (Unbounded Consumption / Overreliance)
```

## 핵심 용어
- 과도한 대행(Excessive Agency, LLM06): LLM 에이전트에게 비즈니스 프로세스를 실행할 수 있는 과도한 권한이나 자율성을 부여하여, 프롬프트 인젝션이나 환각 발생 시 비인가 데이터 삭제나 금전 이체가 발생하는 결함
- 벡터 및 임베딩 취약점(Vector Weaknesses, LLM08): 2025년 버전에 강조된 위협으로, RAG의 지식 검색을 담당하는 벡터 데이터베이스에 악성 임베딩을 주입하여 검색 결과를 오염시키는 공격

## 핵심 통찰
- 2025년 버전의 가장 큰 변화는 "LLM 단독 모델"의 위험에서 "RAG 및 에이전트(Agent) 생태계"로 무게중심이 완전히 이동했다는 점임
- LLM01(프롬프트 인젝션)은 여전히 부동의 1위지만, 웹 브라우징이나 이메일을 읽는 에이전트가 확산되면서 사용자가 아닌 외부 문서가 공격 주체가 되는 '간접 프롬프트 인젝션'이 주류로 부상함
- LLM 보안은 모델 자체를 수정하기 어렵기 때문에(Blackbox API), 모델 앞뒤에 위치하는 '프록시 및 가드레일 아키텍처'가 유일한 실질적 방어선임

## 이웃 토픽과 구분
- OWASP LLM Top 10 vs OWASP Top 10(Web): LLM Top 10 = 확률적 자연어 처리와 자율 에이전트의 의미론적(Semantic) 결함 / Web Top 10 = HTTP 프로토콜과 구문론적(Syntactic) 코드 결함

## 문제·원인·대책
- 사례: 고객 상담용 RAG 시스템에 공격자가 웹 크롤링 대상 문서로 악성 지시어가 포함된 문서를 업로드하여, 고객 문의 시 상담 챗봇이 회사의 미공개 재무제표를 답변으로 출력한 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| RAG 검색 오염을 통한 기밀 데이터 유출 (LLM02, LLM04) | 외부 크롤링 데이터의 무결성 검증 부재 및 벡터 DB 접근제어 미흡 | 데이터 수집 파이프라인 내 출처 검증 및 RAG 지식베이스 분리 | 오염된 외부 문서의 벡터 DB 유입 차단 |
| 에이전트가 조작된 프롬프트에 속아 관리자 DB 테이블 전체 삭제 (LLM06) | AI 에이전트에 DB 쓰기/삭제 슈퍼유저 권한 부여(과도한 대행) | 최소 권한 원칙(JIT 권한) 적용 및 파괴적 명령 시 인간 승인(HITL) 강제 | 에이전트의 비인가 파괴 행위 원천 봉쇄 |
