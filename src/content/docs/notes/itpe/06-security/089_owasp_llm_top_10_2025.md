## Ⅰ. OWASP LLM Top 10(2025)의 개요

- 개념 : LLM 애플리케이션, RAG 아키텍처, AI 에이전트가 직면한 10가지 핵심 보안 위험을 식별하고 방어 가이드라인을 제공하는 **OWASP** 표준 프레임워크.
- 배경 및 필요성 : **대규모 언어 모델** (LLM)을 활용한 애플리케이션 및 서비스에서 가장 치명적이고 빈발하는 10대 보안 위협(프롬프트 인젝션, 민감정보 노출, 공급망 결함 등)을 체계화하여 안전한 설계와 방어 대책을 가이드하기 위해 제정됨.
- 핵심 목적 : 전통적인 웹 취약점(OWASP Top 10) 통제를 넘어 **비결정론적** AI 모델 및 자율 도구 실행 환경의 보안 사각지대 해소.

## Ⅱ. OWASP LLM Top 10(2025)의 핵심 아키텍처 및 동작 메커니즘

OWASP LLM Top 10(2025)은(는) 신뢰할 수 있는 보안 구조와 표준화된 절차를 기반으로 동작하며, 세부적인 아키텍처와 구성요소 간의 상호작용 메커니즘은 다음과 같음.

```text

+---------------------------------------------------------------------------------+
| [입력 계층]                                                                     |
| • LLM01: 프롬프트 인젝션 (Direct / Indirect Prompt Injection)                   |
| • LLM10: 무제한 자원 소비 (DoS / Token Flooding)                                 |
+---------------------------------------------------------------------------------+
                                         │
                                         ▼
+---------------------------------------------------------------------------------+
| [지식 및 모델 계층]                                                             |
| • LLM03: 공급망 취약점 (오염된 허깅페이스 모델 / 악성 라이브러리)                |
| • LLM04: 데이터 및 모델 중독 (Poisoning)                                        |
| • LLM07: 시스템 프롬프트 노출 (Prompt Leakage)                                  |
| • LLM08: 벡터 및 임베딩 취약점 (RAG 벡터 테넌트 오염 / 인가 누락)                 |
+---------------------------------------------------------------------------------+
                                         │
                                         ▼
+---------------------------------------------------------------------------------+
| [오케스트레이션 및 에이전트 도구 계층]                                          |

+---------------------------------------------------------------------------------+
                                         │
                                         ▼
+---------------------------------------------------------------------------------+
| [출력 및 클라이언트 계층]                                                       |
| • LLM02: 민감정보 노출 (PII / Credentials Leakage)                              |
| • LLM05: 부적절한 출력 처리 (Improper Output Handling / XSS / SQLi)             |
| • LLM09: 오정보 (Misinformation / Hallucination)                                |
+---------------------------------------------------------------------------------+
```

- LLM01 : **프롬프트 인젝션** (조작된 입력으로 시스템 프롬프트 및 안전 정책 무력화).
- LLM02 : **민감정보 노출** (PII, 비밀번호, 사내 기밀이 출력 텍스트에 포함).
- LLM03 : **공급망 취약점** (서드파티 모델, 플러그인, 종속성 패키지의 악성코드 유입).
- LLM04 : **데이터 및 모델 중독** (학습/파인튜닝 데이터셋에 백도어 트리거 주입).
- LLM05 : **부적절한 출력 처리** (LLM 출력을 검증 없이 브라우저나 DB 쿼리로 실행).
- LLM06 : **과도한 대행** (에이전트가 과도한 도구 실행 권한으로 시스템 파괴).
- LLM07 : **시스템 프롬프트 노출** (프롬프트 추출 기법으로 비공개 지시문 탈취).
- LLM08 : **벡터 및 임베딩 취약점** (RAG 벡터 DB 접근 제어 실패로 타인 문서 열람).
- LLM09 : **오정보** (환각) (허위 정보를 사실처럼 생성하여 비즈니스 오류 초래).
- LLM10 : **무제한 자원 소비** (고비용 컨텍스트 윈도우 반복 요청으로 GPU 고갈).

## Ⅲ. OWASP LLM Top 10(2025)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 2023 초기 버전 (v1.0) | 2025 최신 버전 (v2.0) |
|---|---|---|
| 중점 아키텍처 | 챗GPT 형태의 단순 입출력 텍스트 챗봇 | RAG(검색 증강 생성) 및 **자율 에이전트** (Agentic AI) |
| 신설 취약점 | 미포함 (단순 데이터 누출 항목에 혼재) | LLM07(시스템 프롬프트 노출), LLM08(벡터/임베딩 취약점) 독립 신설 |
| 에이전트 권한 | LLM08 과도한 대행 (하위 순위) | LLM06 과도한 대행 (상위 중요 위협으로 승격) |
| 공급망 범위 | 서드파티 패키지 위주 | 사전학습 모델 가중치 파일, LoRA 어댑터, 임베딩 모델 포괄 |
| 방어 접근 방식 | 정적 규칙 기반 프롬프트 필터링 | 인라인 가드레일 프록시, OPA 동적 인가, AI 레드티밍 |

- OWASP LLM Top 10(2025)은(는) 상기 핵심 비교 지표와 아키텍처 구성을 바탕으로 보안 위협에 대한 방어 효과성을 극대화하며, 기존 레거시 통제 기법 대비 우수한 신뢰성과 운영 효율성을 제공함.

## Ⅳ. OWASP LLM Top 10(2025)의 주요 한계점 및 해결 방안

- 한계점 : RAG 아키텍처에서 공용 벡터 DB 사용 시 메타데이터 필터링 오류로 인한 테넌트 간 기밀 문서 누출(LLM08).
  - 해결 방안 : 벡터 데이터베이스 네임스페이스를 테넌트별 암호화 키로 물리적/논리적 완전 격리하고 검색 엔진 내부 ACL 검증 모듈 필수 결합.
- 한계점 : 에이전트가 복합 **도구 체이닝** (Tool Chaining)을 수행할 때 프롬프트 주입에 의해 치명적 셸 명령을 실행(LLM06).
  - 해결 방안 : 도구 실행 게이트웨이에 **OPA** (Open Policy Agent)를 전진 배치하여 실행 파라미터를 화이트리스팅하고 고위험 API는 HITL 승인 강제.
- 한계점 : 정교한 다언어(외국어) 및 다형성(Base64/Ciphers) 탈옥 시도에 대해 룰 기반 필터의 미탐 발생(LLM01).
  - 해결 방안 : 다국어 의미론적 유해성을 판별하는 **경량 가드레일 모델** (Llama Guard)과 시스템 프롬프트 무결성 해시 검증 이중화.
- 한계점 : 고의적인 초장문 프롬프트 및 비동기 다량 질의를 통한 GPU 메모리 고갈 및 서비스 거부 공격(LLM10).
  - 해결 방안 : API 게이트웨이 레벨에서 최대 입력 토큰 수 제한, 사용자별 슬라이딩 윈도우 레이트 리밋, 동시 요청 큐 관리 강제.

## Ⅴ. OWASP LLM Top 10(2025) 적용 및 발전을 위한 기술사적 제언

- 아키텍처 설계 중심의 거버넌스 및 실행 체계 구축 : 벡터 DB 테넌트 분리, **Safetensors** 모델 포맷 강제, 최소 권한 도구 매핑을(를) 적극 추진하여, LLM03, LLM08 공급망 및 데이터 오염 제로화 효과를 극대화해야 함.
- 런타임 통제 중심의 거버넌스 및 실행 체계 구축 : 입력 프롬프트 가드레일, 출력 DLP 마스킹, RFC 8693 에이전트 위임 인가을(를) 적극 추진하여, LLM01, LLM02, LLM06 인젝션 및 권한 탈취 차단 효과를 극대화해야 함.
- 모니터링 및 감사 중심의 거버넌스 및 실행 체계 구축 : 모든 프롬프트, 모델 응답, 도구 실행 파라미터의 암호화 감사 로깅 및 정기 레드팀을(를) 적극 추진하여, LLM Top 10 전수 취약점 모니터링 체계 완비 효과를 극대화해야 함.
