## 지식 로드맵 내 현재 위치

AI 보안 → LLM 애플리케이션 위험 → OWASP LLM Top 10 (2025)

## 30초 인출

- **본질:** LLM 및 RAG 기반 애플리케이션, 자율 에이전트 환경에서 발생하는 가장 치명적인 10대 보안 취약점과 엔지니어링 완화 방안을 정의한 OWASP의 글로벌 보안 표준.
- **메커니즘:** 입력(프롬프트) → 모델/공급망 → RAG/벡터 DB → 에이전트 도구 호출 → 출력 렌더링에 이르는 전 데이터 파이프라인 구간별 취약성 식별 및 심층 방어.
- 통찰: 2025 개정판의 핵심인 '과도한 대행(LLM06)', '시스템 프롬프트 노출(LLM07)', '벡터 및 임베딩 취약점(LLM08)'에 대응하기 위해 컨텍스트 기반 동적 인가와 RAG 테넌트 격리 설계 필수.

<details><summary>핵심 용어</summary>

- **OWASP LLM Top 10 (2025)**: 생성형 AI 시스템 설계, 개발, 배포 시 우선 고려해야 할 10대 취약점 목록의 2025년 최신 개정판.
- **LLM01 프롬프트 인젝션(Prompt Injection)**: 직접(탈옥) 또는 간접(외부 문서 주입) 방식으로 모델의 의도된 동작을 조작하는 공격.
- **LLM06 과도한 대행(Excessive Agency)**: 에이전트에 부여된 과도한 자율성, 과도한 권한, 과도한 기능으로 인해 발생하는 비인가 조작 취약점.
- **LLM07 시스템 프롬프트 노출(System Prompt Leakage)**: 비인가 사용자에게 모델의 내부 시스템 지시문, 기업 영업비밀, 숨겨진 로직이 유출되는 취약점.
- **LLM08 벡터 및 임베딩 취약점(Vector and Embedding Weaknesses)**: RAG 파이프라인에서 벡터 DB 오염, 임베딩 역추정, 테넌트 간 지식 침범이 발생하는 취약점.
</details>

| 구분 | 핵심 |
|---|---|

## Ⅱ. OWASP LLM Top 10(2025)의 핵심 특징 및 개정 방향

| 특징 | 2025 버전 주요 개정 내용 | 기술적 의미 |
|---|---|---|
| RAG 및 에이전트 반영 | 단순 챗봇을 넘어 RAG 검색 및 에이전트 자율 도구 호출 환경의 위협 집중 조명 | LLM06(과도한 대행), LLM08(벡터 취약점) 명문화 |
| 지적재산 보호 강화 | 시스템 프롬프트 및 비즈니스 로직 탈취 위험을 독립 항목으로 승격 | LLM07(시스템 프롬프트 노출) 신설 |
| 공급망 신뢰 체인 확장 | 사전 학습 모델뿐만 아니라 파인튜닝 가중치, LoRA 아티팩트, 플러그인 공급망 포괄 | LLM03(공급망 취약점)의 커버리지 확대 |
| 데이터 생애주기 보안 | 데이터 수집(중독), 임베딩(벡터 오염), 추론(정보 노출) 전주기 위험 포괄적 연계 | LLM02, LLM04, LLM08의 유기적 매핑 |
| 실효적 통제 프레임워크 | 체크리스트 나열이 아닌 입력 가드레일, 인가 게이트웨이, 샌드박스 등 구체적 구현 권고 | 설계 단계부터 위협 모델링(STRIDE/ATLAS) 적용 |

## Ⅲ. OWASP LLM Top 10(2025) 위협 매핑 및 방어 아키텍처

```text
[ OWASP LLM Top 10 (2025) 아키텍처 전주기 위협 매핑 ]

+---------------------------------------------------------------------------------+
| [입력 계층]                                                                     |
| • LLM01: 프롬프트 인젝션 (Direct / Indirect Prompt Injection)                   |
| • LLM10: 무제한 자원 소비 (DoS / Token Flooding)                                 |
+---------------------------------------------------------------------------------+
                                         │
                                         ▼
+---------------------------------------------------------------------------------+
| [지식 및 모델 계층]                                                             |
| • LLM03: 공급망 취약점 (오염된 허깅페이스 모델 / 악성 라이브러리)                |
| • LLM04: 데이터 및 모델 중독 (Poisoning)                                        |
| • LLM07: 시스템 프롬프트 노출 (Prompt Leakage)                                  |
| • LLM08: 벡터 및 임베딩 취약점 (RAG 벡터 테넌트 오염 / 인가 누락)                 |
+---------------------------------------------------------------------------------+
                                         │
                                         ▼
+---------------------------------------------------------------------------------+
| [오케스트레이션 및 에이전트 도구 계층]                                          |
| • LLM06: 과도한 대행 (Excessive Agency / Confused Deputy)                       |
+---------------------------------------------------------------------------------+
                                         │
                                         ▼
+---------------------------------------------------------------------------------+
| [출력 및 클라이언트 계층]                                                       |
| • LLM02: 민감정보 노출 (PII / Credentials Leakage)                              |
| • LLM05: 부적절한 출력 처리 (Improper Output Handling / XSS / SQLi)             |
| • LLM09: 오정보 (Misinformation / Hallucination)                                |
+---------------------------------------------------------------------------------+
```

| 취약점 ID | 공식 위협 명칭 | 핵심 위험 메커니즘 | 엔지니어링 완화 방안 |
|---|---|---|---|
| LLM01 | 프롬프트 인젝션 | 조작된 입력으로 시스템 프롬프트 및 안전 정책 무력화 | 인라인 가드레일, 데이터-명령 격리 구분자 |
| LLM02 | 민감정보 노출 | PII, 비밀번호, 사내 기밀이 출력 텍스트에 포함 | 출력 DLP 마스킹, 모델 차원의 차등 프라이버시 |
| LLM03 | 공급망 취약점 | 서드파티 모델, 플러그인, 종속성 패키지의 악성코드 유입 | 모델 서명 검증(Sigstore), Safetensors 포맷 강제 |
| LLM04 | 데이터 및 모델 중독 | 학습/파인튜닝 데이터셋에 백도어 트리거 주입 | 데이터 출처 검증, 이상치 탐지 데이터 정제 |
| LLM05 | 부적절한 출력 처리 | LLM 출력을 검증 없이 브라우저나 DB 쿼리로 실행 | 백엔드 파서 이스케이핑, 파라미터화 쿼리 |
| LLM06 | 과도한 대행 | 에이전트가 과도한 도구 실행 권한으로 시스템 파괴 | RFC 8693 JIT 최소 권한, 인간 승인(HITL) |
| LLM07 | 시스템 프롬프트 노출 | 프롬프트 추출 기법으로 비공개 지시문 탈취 | 프롬프트 내 하드코딩 제거, 출력 난독화 필터 |
| LLM08 | 벡터 및 임베딩 취약점 | RAG 벡터 DB 접근 제어 실패로 타인 문서 열람 | 컬렉션/네임스페이스 테넌트 격리, 청크 ACL |
| LLM09 | 오정보 (환각) | 허위 정보를 사실처럼 생성하여 비즈니스 오류 초래 | 고품질 RAG 검색 결합, 출처 근거(Factuality) 검증 |
| LLM10 | 무제한 자원 소비 | 고비용 컨텍스트 윈도우 반복 요청으로 GPU 고갈 | 레이트 리밋(Rate Limiting), 토큰 쿼터 통제 |

## Ⅳ. 2023 초기 버전 vs 2025 최신 버전 비교

| 비교 항목 | 2023 초기 버전 (v1.0) | 2025 최신 버전 (v2.0) |
|---|---|---|
| 중점 아키텍처 | 챗GPT 형태의 단순 입출력 텍스트 챗봇 | RAG(검색 증강 생성) 및 자율 에이전트(Agentic AI) |
| 신설 취약점 | 미포함 (단순 데이터 누출 항목에 혼재) | LLM07(시스템 프롬프트 노출), LLM08(벡터/임베딩 취약점) 독립 신설 |
| 에이전트 권한 | LLM08 과도한 대행 (하위 순위) | LLM06 과도한 대행 (상위 중요 위협으로 승격) |
| 공급망 범위 | 서드파티 패키지 위주 | 사전학습 모델 가중치 파일, LoRA 어댑터, 임베딩 모델 포괄 |
| 방어 접근 방식 | 정적 규칙 기반 프롬프트 필터링 | 인라인 가드레일 프록시, OPA 동적 인가, AI 레드티밍 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| RAG 아키텍처에서 공용 벡터 DB 사용 시 메타데이터 필터링 오류로 인한 테넌트 간 기밀 문서 누출(LLM08) | 벡터 데이터베이스 네임스페이스를 테넌트별 암호화 키로 물리적/논리적 완전 격리하고 검색 엔진 내부 ACL 검증 모듈 필수 결합 |
| 에이전트가 복합 도구 체이닝(Tool Chaining)을 수행할 때 프롬프트 주입에 의해 치명적 셸 명령을 실행(LLM06) | 도구 실행 게이트웨이에 OPA(Open Policy Agent)를 전진 배치하여 실행 파라미터를 화이트리스팅하고 고위험 API는 HITL 승인 강제 |
| 정교한 다언어(외국어) 및 다형성(Base64/Ciphers) 탈옥 시도에 대해 룰 기반 필터의 미탐 발생(LLM01) | 다국어 의미론적 유해성을 판별하는 경량 가드레일 모델(Llama Guard)과 시스템 프롬프트 무결성 해시 검증 이중화 |
| 고의적인 초장문 프롬프트 및 비동기 다량 질의를 통한 GPU 메모리 고갈 및 서비스 거부 공격(LLM10) | API 게이트웨이 레벨에서 최대 입력 토큰 수 제한, 사용자별 슬라이딩 윈도우 레이트 리밋, 동시 요청 큐 관리 강제 |

## Ⅵ. 제언

```text
[ 엔터프라이즈 LLM 애플리케이션 보안 성숙도 모델 ]

+-------------------------+      +-------------------------+      +-------------------------+
|     1단계: 안전 인프라   | ---> |     2단계: 런타임 방어   | ---> |     3단계: 지속적 검증   |
| (테넌트 격리 / ZDR 계약)|      | (가드레일 / OPA 인가)   |      | (AI 레드티밍 / 로깅)   |
+-------------------------+      +-------------------------+      +-------------------------+
```

| 실행 계층 | 세부 구현 과제 | 핵심 달성 지표 |
|---|---|---|
| 아키텍처 설계 | 벡터 DB 테넌트 분리, Safetensors 모델 포맷 강제, 최소 권한 도구 매핑 | LLM03, LLM08 공급망 및 데이터 오염 제로화 |
| 런타임 통제 | 입력 프롬프트 가드레일, 출력 DLP 마스킹, RFC 8693 에이전트 위임 인가 | LLM01, LLM02, LLM06 인젝션 및 권한 탈취 차단 |
| 모니터링 및 감사 | 모든 프롬프트, 모델 응답, 도구 실행 파라미터의 암호화 감사 로깅 및 정기 레드팀 | LLM Top 10 전수 취약점 모니터링 체계 완비 |
