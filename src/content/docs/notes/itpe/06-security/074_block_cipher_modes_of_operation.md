## 지식 로드맵 내 현재 위치

정보보안 → 암호학 → 블록 암호 운용 모드(NIST SP 800-38A/D)

## 30초 인출

- **본질:** 고정된 블록 크기(128비트 등)를 갖는 블록 암호 알고리즘을 활용하여 가변 길이의 대용량 평문 데이터를 안전하게 암호화하고 무결성을 보장하기 위한 연산 처리 규칙
- **메커니즘:** 단순 독립 암호화(ECB: 패턴 노출) → 이전 블록 체이닝(CBC) → 키스트림 스트림화(CTR) → 갈루아 체 기반 인증 태그 결합(GCM: AEAD)
- 통찰: 단순 기밀성 제공 모드의 패딩 오라클 및 비트 조작 취약점을 극복하기 위해 기밀성과 무결성을 단일 패스로 동시 보증하는 AEAD(AES-GCM) 표준화 및 고유 Nonce 생성 관리 필수

<details><summary>핵심 용어</summary>

- **운용 모드(Mode of Operation):** 블록 암호의 단일 블록 한계를 극복하여 임의 길이의 데이터를 처리하는 기법(NIST SP 800-38A).
- **초기화 벡터 (IV, Initialization Vector):** 첫 번째 블록 암호화 시 동일한 평문이 동일한 암호문으로 변환되지 않도록 투입하는 무작위 난수값.
- **Nonce (Number used ONCE):** CTR 및 GCM 모드에서 동일한 암호키 아래에서 단 한 번만 사용되어야 하는 고유한 일회용 값.
- **패딩 (Padding, PKCS#7):** 마지막 평문 블록의 길이가 블록 크기(16바이트)에 미달할 때 부족한 바이트를 채워주는 규칙.
- **AEAD (Authenticated Encryption with Associated Data):** 평문 암호화와 연관 데이터(헤더 등)의 무결성 검증 태그 생성을 단일 키/알고리즘으로 수행하는 모드(GCM, CCM).

</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 고정된 크기(128비트 등)의 블록 암호 프리미티브를 연속적으로 적용하여 임의 길이의 데이터 스트림을 안전하게 암호화하고 인증하기 위한 절차적 표준 규격 |
| 목적 | 평문의 통계적 패턴 은닉, 오류 전파 통제, 병렬 처리 성능 확보, 기밀성과 무결성의 동시 달성(AEAD) |

## Ⅱ. 블록 암호 운용 모드의 주요 특징 및 분류

| 특징 | 세부 내용 | 구현 요소 |
|---|---|---|
| 블록 단위 체이닝 (CBC) | 직전 암호문 블록을 다음 평문 블록과 XOR 연산 후 암호화하여 패턴 완벽 은닉 | IV, 직렬 처리, PKCS#7 패딩 |
| 스트림 변환 처리 (CTR) | Nonce와 카운터 값을 암호화하여 키스트림을 생성하고 평문과 XOR 연산 | 패딩 불필요, 완전 병렬 처리 |
| 인증 결합 (AEAD: GCM) | CTR 모드 기반 고속 암호화와 갈루아체($GF(2^{128})$) 곱셈 기반 GHASH 무결성 태그 생성 | 단일 패스 인증 암호화 |
| 오류 전파의 상이성 | 한 블록의 전송 오류가 다른 블록의 복호화에 미치는 영향이 모드별로 완전히 상이함 | 비트 에러 격리성 |

## Ⅲ. 주요 운용 모드(CBC vs CTR vs GCM) 아키텍처 및 연산 프로세스

```text
[ 1. CBC 모드 (직렬 암호화 구조) ]
평문 P1 ──▶ ( XOR ) ──▶ [ AES Enc ] ──▶ 암호문 C1 ──┐
               ▲                                    │
           초기화벡터(IV)                            ├─▶ 다음 블록 XOR 입력으로 피드백!
                                                    │
평문 P2 ──▶ ( XOR ) ◀───────────────────────────────┘
               │
               ▼
          [ AES Enc ] ──▶ 암호문 C2 (순차적 직렬 처리로 암호화 병렬화 불가)

[ 2. GCM 모드 (AEAD 고속 병렬 인증 암호화) ]
Nonce + 카운터 1 ──▶ [ AES Enc ] ──▶ ( XOR ) ◀── 평문 P1 ──▶ 암호문 C1 ──┐
Nonce + 카운터 2 ──▶ [ AES Enc ] ──▶ ( XOR ) ◀── 평문 P2 ──▶ 암호문 C2 ──┼─▶ [ GHASH ] ──▶ 인증 태그 (Tag)
(암호화 블록 병렬 처리 가능)                                               │     ▲
                                      인증 전용 부가 데이터 (AAD) ─────────┘     │ (갈루아 필드 곱셈)
```

| 모드 | 암호화 수식 | 복호화 수식 | 패딩 | 병렬성 |
|---|---|---|---|---|
| CBC | $C_i = E_K(P_i \oplus C_{i-1})$, $C_0 = IV$ | $P_i = D_K(C_i) \oplus C_{i-1}$ | 필수 | 복호화만 병렬 가능 |
| CTR | $C_i = P_i \oplus E_K(Nonce \parallel Counter_i)$ | $P_i = C_i \oplus E_K(Nonce \parallel Counter_i)$ | 불필요 | 암·복호화 모두 병렬 |
| **GCM** | **CTR 암호화 + GHASH(AAD, C, H) 인증** | **인증 태그 검증 성공 시에만 CTR 복호화** | **불필요** | **완전 하드웨어 병렬** |

## Ⅳ. 5대 블록 암호 운용 모드 및 GCM 종합 비교

| 모드 | 기밀성 원리 | 암호화 병렬화 | 복호화 병렬화 | 패딩 필요 | 무결성 인증 | 실무 권장 여부 |
|---|---|---|---|---|---|---|
| **ECB** | 블록별 독립 암호화 | 가능 | 가능 | 필수 | 미제공 | **절대 금지 (패턴 노출)** |
| **CBC** | 이전 암호문 피드백 XOR | **불가 (직렬)** | 가능 | 필수 | 미제공 | 레거시 한정 (패딩 오라클 취약) |
| **CFB** | 암호문 피드백 스트림화 | 불가 | 가능 | 불필요 | 미제공 | 특수 스트림 환경 |
| **OFB** | 키스트림 피드백 스트림화 | 불가 | 불가 | 불필요 | 미제공 | 비트 에러 무전파 환경 |
| **CTR** | 카운터 암호화 스트림화 | **가능 (초고속)**| **가능** | 불필요 | 미제공 | 고속 환경 권장 (단독 사용 시 무결성 결여) |
| **GCM** | **CTR 암호화 + GMAC 태그**| **완전 병렬** | **완전 병렬** | **불필요** | **제공 (AEAD)** | **TLS 1.3 / 현대 표준 최우선 권장** |

## Ⅴ. 블록 암호 운용 모드의 한계와 방안

| 한계 | 방안 |
|---|---|
| ECB 모드는 동일한 평문 블록이 항상 동일한 암호문 블록을 생성하므로 암호문 이미지에서 원본 윤곽(ECB Penguin)이 그대로 노출 | ECB 모드를 전면 폐기하고, 최소한 난수 IV가 적용되는 CBC 모드나 고속 AEAD 표준인 GCM 모드만 사용하도록 보안 정책 강제 |
| CBC 모드는 암호문 패딩 오류 응답을 악용한 패딩 오라클(Padding Oracle) 공격 및 비트 플리핑(Bit-flipping)에 의한 평문 변조에 무방비 | 패딩을 사용하지 않고 암호문과 인증 태그를 일체화하여 변조 시 즉각 패킷을 드롭하는 AES-GCM(AEAD)으로 전면 교체 |
| CTR 및 GCM 모드에서 동일 비밀키로 동일 Nonce가 2회 이상 중복 사용(Nonce-Reuse)될 경우 키스트림 노출 및 GHASH 인증키($H$) 탈취 | 암호학적 난수 생성기를 이용한 96비트 무작위 Nonce 할당, 단조 증가 카운터 기반 Nonce 생성 강제 및 임계 데이터량 도달 시 키 갱신(Rekeying) |

## Ⅵ. 제언

```text
[ 레거시 취약 모드 ]                 [ 차세대 고속 AEAD 표준 모드 ]
ECB 패턴 노출 위험 ──┐               ┌── AES-GCM (기밀성 + 무결성 완전 병렬)
CBC 패딩 오라클 공격 ┼─→ [ 침해 노출 ] ─┼── 고유 Nonce 관리 및 하드웨어 가속(CLMUL)
직렬 처리 성능 저하 ─┘               └── 스토리지 전용 XTS-AES / 경량 ChaCha20-Poly1305
```

| 평가 영역 | 과거 운용 모드 (ECB/CBC) | 차세대 인증 모드 (GCM) | 향후 발전 방향 |
|---|---|---|---|
| 보안성 | 기밀성만 제공 (변조 취약) | 기밀성 + 무결성 동시 보장 | SIV(Synthetic IV) 기반 Nonce 오남용 내성 |
| 처리 성능 | 직렬 의존으로 CPU 병목 | 인텔 AES-NI/CLMUL 가속 최적화 | 초경량 IoT 환경 전용 Ascon AEAD 채택 |
| 표준 준거성 | TLS 1.3에서 전면 퇴출 | TLS 1.3 및 IPsec 필수 표준 | 양자 내성 암호(PQC) 하이브리드 결합 |

블록 암호 운용 모드는 단순 데이터 암호화를 넘어 고속 병렬 처리와 위변조 방지(AEAD)를 동시에 달성하는 현대 통신 보안의 표준 기저 기술이며, Nonce의 유일성 보장과 하드웨어 가속을 접목한 AES-GCM 체계 구축 필수.
