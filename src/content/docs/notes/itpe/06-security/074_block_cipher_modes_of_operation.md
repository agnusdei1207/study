## Ⅰ. 블록 암호 운용 모드(Block Cipher Mode of Operation)의 개요

- 개념 : 고정된 크기(128비트 등)의 블록 암호 프리미티브를 연속적으로 적용하여 임의 길이의 데이터 스트림을 안전하게 암호화하고 인증하기 위한 절차적 표준 규격.
- 배경 및 필요성 : 고정 크기 블록 암호 알고리즘을 임의 길이의 가변 데이터에 안전하게 적용하고, 평문 블록의 반복 패턴 노출 방지 및 기밀성과 무결성 인증(AEAD)을 동시에 달성하기 위해 운용 모드 표준화가 추진됨.
- 핵심 목적 : 평문의 통계적 패턴 은닉, 오류 전파 통제, 병렬 처리 성능 확보, 기밀성과 무결성의 동시 달성(AEAD).

## Ⅱ. 블록 암호 운용 모드(Block Cipher Mode of Operation)의 핵심 아키텍처 및 동작 메커니즘

블록 암호 운용 모드(Block Cipher Mode of Operation)은(는) 신뢰할 수 있는 보안 구조와 표준화된 절차를 기반으로 동작하며, 세부적인 아키텍처와 구성요소 간의 상호작용 메커니즘은 다음과 같음.

```text
[ 1. CBC 모드 (직렬 암호화 구조) ]
평문 P1 ──▶ ( XOR ) ──▶ [ AES Enc ] ──▶ 암호문 C1 ──┐
               ▲                                    │
           초기화벡터(IV)                            ├─▶ 다음 블록 XOR 입력으로 피드백!
                                                    │
평문 P2 ──▶ ( XOR ) ◀───────────────────────────────┘
               │
               ▼
          [ AES Enc ] ──▶ 암호문 C2 (순차적 직렬 처리로 암호화 병렬화 불가)

[ 2. GCM 모드 (AEAD 고속 병렬 인증 암호화) ]
Nonce + 카운터 1 ──▶ [ AES Enc ] ──▶ ( XOR ) ◀── 평문 P1 ──▶ 암호문 C1 ──┐
Nonce + 카운터 2 ──▶ [ AES Enc ] ──▶ ( XOR ) ◀── 평문 P2 ──▶ 암호문 C2 ──┼─▶ [ GHASH ] ──▶ 인증 태그 (Tag)
(암호화 블록 병렬 처리 가능)                                               │     ▲
                                      인증 전용 부가 데이터 (AAD) ─────────┘     │ (갈루아 필드 곱셈)
```

- **CBC** : $C_i = E_K(P_i \oplus C_{i-1})$, $C_0 = IV$ ($P_i = D_K(C_i) \oplus C_{i-1}$).
- **CTR** : $C_i = P_i \oplus E_K(Nonce \parallel Counter_i)$ ($P_i = C_i \oplus E_K(Nonce \parallel Counter_i)$).
- **GCM** : CTR 암호화 + **GHASH** (AAD, C, H) 인증 (인증 태그 검증 성공 시에만 CTR 복호화).

## Ⅲ. 블록 암호 운용 모드(Block Cipher Mode of Operation)의 세부 구성 요소 및 비교 분석

| 모드 | 기밀성 원리 | 암호화 병렬화 | 복호화 병렬화 | 패딩 필요 | 무결성 인증 | 실무 권장 여부 |
|---|---|---|---|---|---|---|
| **ECB** | 블록별 독립 암호화 | 가능 | 가능 | 필수 | 미제공 | 절대 금지 (패턴 노출) |
| **CBC** | 이전 암호문 피드백 XOR | 불가 (직렬) | 가능 | 필수 | 미제공 | 레거시 한정 (패딩 오라클 취약) |
| **CFB** | 암호문 피드백 스트림화 | 불가 | 가능 | 불필요 | 미제공 | 특수 스트림 환경 |
| **OFB** | 키스트림 피드백 스트림화 | 불가 | 불가 | 불필요 | 미제공 | 비트 에러 무전파 환경 |
| **CTR** | 카운터 암호화 스트림화 | 가능 (초고속)| 가능 | 불필요 | 미제공 | 고속 환경 권장 (단독 사용 시 무결성 결여) |
| **GCM** | CTR 암호화 + GMAC 태그| 완전 병렬 | 완전 병렬 | 불필요 | 제공 (AEAD) | TLS 1.3 / 현대 표준 최우선 권장 |

- 블록 암호 운용 모드(Block Cipher Mode of Operation)은(는) 상기 핵심 비교 지표와 아키텍처 구성을 바탕으로 보안 위협에 대한 방어 효과성을 극대화하며, 기존 레거시 통제 기법 대비 우수한 신뢰성과 운영 효율성을 제공함.

## Ⅳ. 블록 암호 운용 모드(Block Cipher Mode of Operation)의 주요 한계점 및 해결 방안

- 한계점 : ECB 모드는 동일한 평문 블록이 항상 동일한 암호문 블록을 생성하므로 암호문 이미지에서 원본 윤곽(ECB Penguin)이 그대로 노출.
  - 해결 방안 : ECB 모드를 전면 폐기하고, 최소한 난수 IV가 적용되는 CBC 모드나 고속 AEAD 표준인 GCM 모드만 사용하도록 보안 정책 강제.
- 한계점 : CBC 모드는 암호문 패딩 오류 응답을 악용한 **패딩 오라클** (Padding Oracle) 공격 및 비트 플리핑(Bit-flipping)에 의한 평문 변조에 무방비.
  - 해결 방안 : 패딩을 사용하지 않고 암호문과 인증 태그를 일체화하여 변조 시 즉각 패킷을 드롭하는 AES-GCM(AEAD)으로 전면 교체.
- 한계점 : CTR 및 GCM 모드에서 동일 비밀키로 동일 Nonce가 2회 이상 중복 사용(Nonce-Reuse)될 경우 키스트림 노출 및 GHASH 인증키($H$) 탈취.
  - 해결 방안 : 암호학적 난수 생성기를 이용한 96비트 무작위 Nonce 할당, 단조 증가 카운터 기반 Nonce 생성 강제 및 임계 데이터량 도달 시 **키 갱신** (Rekeying).

## Ⅴ. 블록 암호 운용 모드(Block Cipher Mode of Operation) 적용 및 발전을 위한 기술사적 제언

- **AES-GCM** (기밀성 + 무결성 완전 병렬) 체계 도입 : AES-GCM (기밀성 + 무결성 완전 병렬) 기술을 적극 적용하여 보안 취약점을 차단하고 시스템 신뢰성을 보장해야 함.
- **고유 Nonce 관리 및 하드웨어 가속(CLMUL)** 체계 도입 : 고유 Nonce 관리 및 하드웨어 가속(CLMUL) 기술을 적극 적용하여 보안 취약점을 차단하고 시스템 신뢰성을 보장해야 함.
- **스토리지 전용 XTS-AES / 경량 ChaCha20-Poly1305** 체계 도입 : 스토리지 전용 XTS-AES / 경량 ChaCha20-Poly1305 기술을 적극 적용하여 보안 취약점을 차단하고 시스템 신뢰성을 보장해야 함.
