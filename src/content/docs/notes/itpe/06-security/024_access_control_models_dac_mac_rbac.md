## 1교시 예상문제 (10점)

> DAC, MAC, RBAC 접근통제 모델의 차이를 설명하시오. (예상)

---

## 1교시 10점 답안

### 1. 정의·목적

정의: 접근통제는 주체가 객체에 접근할 수 있는지를 보안정책에 따라 결정하는 통제이다.
목적: 비인가 접근을 막고 최소 권한과 직무 분리를 적용한다.

### 2. 모델 비교

| 모델 | 권한 결정 기준 | 특징 |
|---|---|---|
| DAC | 객체 소유자의 설정 | 유연하지만 권한이 전파될 수 있음 |
| MAC | 중앙 정책과 보안 등급 | 강제적이고 일관된 통제 |
| RBAC | 사용자에게 부여된 역할 | 직무 기반 관리, 역할 폭발 가능 |
| ABAC | 주체·객체·환경 속성 | 상황 속성을 정책에 반영 |

제안: 역할 수와 예외 권한을 주기적으로 검토하고 필요 시 속성 조건을 결합한다.

## 2~4교시 25점 답안
```text
[접근통제 정책·모델] ◀━━ 머리: Ⅶ 내 의견 (정적 역할 폭발(Role Explosion) 극복 → 컨텍스트 기반 ABAC 결합 하이브리드 제어)
 ┃
 ┣━ Ⅰ 개요 ───── 비인가자의 중요 정보 접근 차단 → 주체(Subject)의 객체(Object)에 대한 접근 권한을 체계적으로 통제하는 원칙
 ┣━ Ⅱ 특징 ───── 최소 권한의 원칙 · 직무 분리(SoD) · 신분 기반 vs 규칙 기반 vs 역할 기반 · 중앙화된 권한 감사
 ┣━ Ⅲ 구조 ───── 신분 기반(DAC: ACL, Capability) · 규칙 기반(MAC: 보안라벨, BLP, Biba) · 역할 기반(RBAC: Role 계층)
 ┣━ Ⅳ 흐름 ───── ① 주체 식별/인증 → ② 접근 정책 조회 → ③ 참조 모니터(Reference Monitor) 판정 → ④ 권한 부여 또는 거부
 ┣━ Ⅴ 비교 ───── DAC(소유자 임의 결정, 유연성) vs MAC(중앙 관리자 강제, 최고 기밀성) vs RBAC(직무 역할 할당, 운영 효율)
 ┗━ Ⅵ 실무 ───── 트로이 목마 정보 유출 취약(DAC) / 경직된 관리 부담(MAC) / 역할 폭발(Role Explosion) 현상(RBAC)
```
- 필수 키워드: DAC(임의적 접근통제) · MAC(강제적 접근통제) · RBAC(역할기반) · ABAC(속성기반) · 참조 모니터 · 역할 폭발
- 기출: 133회 4교시 3번 `접근통제 정책과 절차 및 메커니즘` → Ⅰ·Ⅲ·Ⅳ / 129회 2교시 2번 `접근 제어 정책과 LDAP 인증` → Ⅲ·Ⅴ

## 한 줄 본질
- 시스템 자원을 보호하기 위해 주체가 객체에 수행할 수 있는 연산(읽기/쓰기/실행)을 정책에 따라 제한하는 보안 메커니즘 → 권한 오남용 및 비인가 데이터 유출 차단 / 권한 정책 관리 복잡도 증가

## 핵심 그림
```text
[접근통제 3대 모델 및 참조 모니터(Reference Monitor) 구조]

                      [ 접근 정책 DB (DAC / MAC / RBAC) ]
                                       │
                                       ▼
  [ 주체 (Subject) ] ──> [ 참조 모니터 (Reference Monitor) ] ──> [ 객체 (Object) ]
  (사용자, 프로세스)      - 격리성 (Tamper-proof)                 (파일, DB, 디바이스)
                          - 완전성 (Always invoked)
                          - 검증성 (Small enough to analyze)
 ──────────────────────────────────────────────────────────────────────────
  • DAC: 객체 소유자가 권한을 임의 설정 (Linux chmod, NTFS ACL)
  • MAC: 보안 등급(Secret/Top Secret)과 인가 라벨 비교 강제 (SELinux)
  • RBAC: 사용자가 아닌 '역할(Role)'에 권한을 부여하고 사용자는 역할에 매핑
```

## 핵심 용어
- 참조 모니터(Reference Monitor): 주체의 객체 접근 요청을 가로채 접근통제 정책에 따라 허용 여부를 결정하는 운영체제의 핵심 보안 커널 추상화 개념
- 역할 폭발(Role Explosion): RBAC 환경에서 조직 규모가 커지고 세부 업무 예외가 증가함에 따라 생성되는 역할(Role)의 수가 사용자 수보다 많아져 관리가 불가능해지는 현상

## 핵심 통찰
- DAC는 사용자가 악성코드(트로이 목마)를 실행하면 악성코드가 사용자의 모든 파일 접근 권한을 그대로 상속받아 외부로 유출할 수 있는 치명적 약점이 존재함
- MAC은 정보의 기밀성을 완벽히 보장하지만 모든 파일과 프로세스에 보안 라벨을 붙여야 하므로 일반 엔터프라이즈 환경에서는 극도로 경직되고 운영 비용이 큼
- 현대 클라우드 및 제로트러스트 환경에서는 정적 RBAC의 한계를 넘어 접속 시간, 위치, 단말 위험도 등 동적 속성을 평가하는 ABAC(Attribute-Based Access Control)로 전환 중임

## 이웃 토픽과 구분
- RBAC vs ABAC: RBAC = 사용자의 정적 직무(Role)만 보고 권한 결정 / ABAC = 주체, 객체, 행위뿐만 아니라 환경 속성(시간, IP, 디바이스 상태)까지 동적으로 조합해 정책 결정

## 문제·원인·대책
- 사례: 133회 기출 엔터프라이즈 시스템에서 수백 개의 중복 Role 생성으로 권한 관리가 마비된 사건
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 수천 개 예외 역할 생성으로 권한 감사 불능 | 정적 RBAC 모델의 비즈니스 예외 수용 한계 | 직무 중심 RBAC 베이스에 동적 속성(부서, 시간)을 검사하는 ABAC 결합 | 역할 수 80% 감축 및 세밀한 최소권한 통제 달성 |
| 퇴직자의 잔존 권한을 통한 중요 고객정보 유출 | 계정 회수 절차의 수작업 누락 | HR 인사 DB와 IdP(Identity Provider) 간 SCIM 자동 계정 프로비저닝 연동 | 퇴사 처리 즉시 전사 시스템 접근 권한 자동 박탈 |

## 이렇게 출제된다
- 제133회 4교시 3번: "정보보호 방법을 암호화와 접근제어로 크게 분류할 때, 접근제어에 대하여, 그 개념과 정책, 절차, 그리고 이를 구현하는 메커니즘을 설명하시오." → 요구 포인트: Ⅰ 정의 + Ⅲ DAC/MAC/RBAC 정책 + Ⅳ 메커니즘(참조모니터, ACL)
- 제129회 2교시 2번: "접근 제어(Access Control)의 통제정책과 경량 디렉토리 액세스 프로토콜 (LDAP)의 인증 흐름을 설명하시오." → 요구 포인트: Ⅲ 통제정책 분류 + Ⅳ LDAP 디렉토리 연동

## 내 의견
- [기본 관리자(Admin) 권한 공유 관행의 위험] 운영 편의를 위해 개발팀 전체가 공용 'root'나 'admin' 계정을 공유하여 감사 추적성(Accountability)이 완전히 상실되는 현장 빈발 → 나라면: 개인 식별 계정 로그인을 강제하고, 권한 상승이 필요할 때만 시간 제한(JIT: Just-In-Time) 권한을 부여하는 특권접근관리(PAM) 솔루션을 필수 도입
