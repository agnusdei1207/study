## 30초 인출

- **본질:** **접근통제 정책·모델**은 주체가 객체에 수행할 수 있는 행위를 정책에 따라 결정하는 구조
- **메커니즘:** 주체의 접근 요청을 정책과 대조 → 허용·거부 → 결정 기록
- **선택 관점:** 권한 결정 주체와 기준에 따라 DAC·MAC·RBAC 등 모델 구분

<details>
<summary>핵심 용어</summary>

- **접근통제 정책·모델:** 주체·객체·행위에 대한 권한을 정의하고 접근 요청을 허용·거부하는 규칙과 구조
- **DAC (Discretionary Access Control):** 객체 소유자 등이 권한을 임의로 부여·회수할 수 있는 접근통제
- **MAC (Mandatory Access Control):** 중앙 정책이 보안 라벨·인가 조건에 따라 접근을 강제하는 통제
- **RBAC (Role-Based Access Control):** 역할에 권한을 연결하고 사용자에게 역할을 부여하는 통제
- **ABAC (Attribute-Based Access Control):** 주체·객체·행위·환경 속성에 정책을 적용하는 통제
- **참조 모니터(reference monitor):** 주체와 객체 사이의 접근 요청을 정책에 따라 중재하는 추상 보안 메커니즘
- **최소권한:** 업무 수행에 필요한 최소 권한만 부여하는 원칙
</details>

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **접근통제 정책·모델**은 주체가 객체에 수행할 수 있는 행위를 정책에 따라 결정하는 구조 |
| 목적 | 비인가 행위를 제한하고 필요한 권한만 부여해 정보자산 보호 |

### Ⅱ. 모델 비교

| 모델 | 권한 결정 기준 | 특징 |
|---|---|---|
| DAC | 객체 소유자 등의 권한 설정 | 유연한 공유, 권한 전파·회수 관리 필요 |
| MAC | 중앙 정책과 보안 라벨·인가 규칙 | 조직의 강제 정책에 따른 일관된 접근 |
| RBAC | 사용자에게 부여된 역할·역할 권한 | 직무 단위 권한 관리와 직무분리 지원 |

```text
주체의 접근 요청
        ↓
참조 모니터: 정책·권한 확인
        ↓
허용 또는 거부 → 기록·검토
```

**제언:** 업무별 최소권한을 기준으로 역할·예외를 정기 검토하고 권한 회수까지 관리

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **접근통제 정책·모델**은 주체가 객체에 수행할 수 있는 행위를 정책에 따라 결정하는 구조 |
| 목적 | 비인가 행위를 제한하고 필요한 권한만 부여해 정보자산 보호 |

접근통제는 식별·인증된 주체가 자원에 요청한 행위에 권한을 판정하는 보안 기능.

## Ⅱ. 참조 모니터 구조

| 원칙 | 의미 |
|---|---|
| 완전한 중재 | 보호 대상 접근 요청을 빠짐없이 통제 경유 |
| 변조 방지 | 비인가 주체가 통제 메커니즘을 변경하지 못하도록 보호 |
| 검증 가능성 | 작고 분석 가능한 구조로 구현·검토 |

```text
주체 ──접근 요청──> 참조 모니터 ──정책 판정──> 허용 / 거부
                              ↑
                    DAC·MAC·RBAC·ABAC 정책
```

## Ⅲ. 접근통제 모델 비교

| 모델 | 정책 기준 | 운영 특성·주의점 |
|---|---|---|
| DAC | 객체 소유자 등의 권한 설정 | 공유·위임이 유연하나 전파와 회수 관리 필요 |
| MAC | 중앙 보안정책과 라벨·인가 비교 | 라벨 분류·관리의 일관성 필요 |
| RBAC | 역할에 연결된 권한과 사용자 배정 | 직무 변경·역할 계층·분리 규칙 관리 |
| ABAC | 주체·객체·행위·환경 속성 조건 | 세밀한 조건 표현, 속성 품질·정책 복잡성 관리 |

## Ⅳ. 운영 통제와 적용

| 운영 위험 | 통제 |
|---|---|
| 직무 이동 후 권한 잔존 | 인사·계정 수명주기 연계, 권한 재검토와 회수 |
| 예외 역할 누적 | 역할 소유자·업무 근거 지정, 중복 역할 정리 |
| 직무상 상충 권한 결합 | 정적·동적 직무분리 제약과 승인 절차 |
| 관리자 계정의 추적성 부족 | 개인 식별 계정, 시간 제한 특권, 행위기록 |

## Ⅴ. 한계와 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 역할·속성 정책의 설계가 실제 업무와 어긋나면 과도한 허용이나 업무 차질 발생 | 자원 소유자와 업무 책임자가 권한 근거를 확인하고 접근기록·정기 재인증 결과로 정책 조정 |
| 권한모델 도입 후 역할·속성의 품질을 지속 관리하지 않으면 정책이 낡음 | 계정 변경·업무 변경·자원 변경을 권한검토 흐름에 연결하고 예외의 만료일 설정 |
