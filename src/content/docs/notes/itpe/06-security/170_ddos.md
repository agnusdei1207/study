## 연관 키워드

- DDoS(Distributed Denial of Service), 봇넷(Botnet), 가용성(Availability), 증폭 반사 공격(Amplification & Reflection)
- SYN Flood, Slowloris, L3/L4·L7 공격, 클라우드 스크러빙(Scrubbing), BGP Anycast, BGP Flowspec
- WAF(Web Application Firewall), CAPTCHA, 레이트 리미팅(Rate Limiting), RDDoS(Ransom DDoS), 사이버대피소

## Ⅰ. DDoS의 개요

- 핵심 요약 : 감염된 다수의 단말을 동원해 표적의 회선·서버·웹 애플리케이션에 대량 트래픽을 집중시켜 가용성을 무너뜨리는 공격.
- 개념 : 봇넷으로 묶인 감염 단말(좀비 PC, IoT 기기 등)이 정상 용량을 초과하는 트래픽을 동시에 보내 서비스를 마비시키는 **DDoS** (Distributed Denial of Service, 분산 서비스 거부 공격).
- 배경 및 필요성 : 공격 도구가 대중화되고 Mirai 계열 IoT 봇넷이 확산되었으며, 공격을 대행해 주는 서비스가 등장해 공격 규모가 Gbps급에서 Tbps급까지 커짐.
- 주요 목적 : 대고객 서비스를 중단시켜 금전 손실과 신뢰 하락을 일으키고, 협박을 통한 금전 갈취(**RDDoS** (Ransom DDoS))나 다른 침투를 가리는 연막으로 악용.

## Ⅱ. DDoS의 특징 및 장점

- 핵심 요약 : 공격 계층별 자원 고갈 방식이 구분되어 있어, 계층에 맞는 방어를 겹쳐 쓰는 다층 대응이 가능함.

1. **볼륨 공격** (L3/L4, 네트워크 대역폭을 소진) : 회선 용량을 넘는 트래픽을 보내 방화벽에 닿기 전 상위 회선을 포화 → 회선 확충만으로는 방어가 어려움.
2. **프로토콜 공격** (L4, OS의 TCP 연결 자원을 소진) : **SYN Flood** (TCP 3-Way Handshake 중 최종 응답을 생략해 연결 대기열을 채움) → 소량 패킷으로도 신규 연결 불능.
3. **애플리케이션 공격** (L7, 웹 서버의 스레드와 DB 연결을 점유) : **Slowloris** (HTTP 요청을 극도로 느리게 보내 연결을 붙잡는 방식) → 적은 트래픽으로도 서비스 마비.
4. **클라우드 스크러빙** (Scrubbing, 트래픽을 분산 클라우드로 우회해 정화) : 대규모 볼륨 공격을 원본 서버 도달 전에 흡수 → 원본 서버의 무중단 운영.

## Ⅲ. DDoS의 구조 (흐름)

- 핵심 요약 : 공격 트래픽이 글로벌 클라우드 센터에서 정화된 뒤에만 원본 서버로 전달되는 우회 구조.
- **증폭 반사 공격** (Amplification & Reflection, 출발지 IP를 피해자로 위조해 DNS·NTP 서버의 응답을 증폭시키는 방식) : 작은 요청이 큰 응답으로 되돌아와 피해자에게 집중됨.

```text
[ 공격 트래픽 발생 ]
        ↓
[ BGP Anycast 클라우드 센터 ]
        ↓
[ L3/L4 필터: 볼륨 공격 폐기 ]
        ↓
[ L7 검사: CAPTCHA·행동 분석으로 봇 차단 ]
        ↓
[ 정제된 트래픽만 원본 서버 전달 ]
```

```text
[ 공격 계층별 자원 고갈 지점 ]

L3/L4 볼륨  : 네트워크 대역폭
L4 프로토콜 : OS의 TCP 연결 대기열
L7 애플리케이션 : 웹 서버 스레드, DB 연결
```

## Ⅳ. DDoS 공격 유형의 비교

- 핵심 요약 : 볼륨 공격은 대역폭, 프로토콜 공격은 연결 자원, 애플리케이션 공격은 처리 자원을 노리므로 방어 장치도 달라짐.

| 비교 항목 | 대역폭 고갈 (볼륨) | 자원 고갈 (프로토콜) | 웹 애플리케이션 (L7) |
| --- | --- | --- | --- |
| 대상 계층 | L3/L4 네트워크 | L4 전송 (OS 커널 스택) | L7 애플리케이션 |
| 대표 공격 | UDP Flood, DNS·NTP 증폭 반사 | TCP SYN Flood, RST Flood | HTTP GET Flood, Slowloris |
| 트래픽 규모 | 대규모 (Gbps~Tbps급) | 중간 (패킷 수 중심) | 소량으로도 마비 가능 |
| 핵심 대응 | 클라우드 스크러빙, BGP Anycast | SYN Cookie, 연결 임계치 | WAF, CAPTCHA, 레이트 리미팅, CDN |

- 선택 기준 : 공격이 회선을 채우는지, 연결 자원을 고갈시키는지, 애플리케이션을 노리는지를 먼저 식별한 뒤 계층별 대응을 배치함.

## Ⅴ. DDoS의 한계와 방안

- 핵심 요약 : 회선 초과 공격, 정상 사용자와 위장 봇의 구별, 협박형 공격을 클라우드 흡수, 행위 기반 봇 탐지, 대응 절차로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 회선 대역폭 초과 공격 | 상위 ISP 라우터에서 회선이 먼저 포화되어 온프레미스 장비가 무력화 | 온프레미스 단독 방어를 버리고 BGP Anycast 기반 클라우드 DDoS 완화 서비스로 사전 흡수 | 공격 차단률, 서비스 가용률 |
| 위장 L7 봇 구별 난제 | 헤드리스 브라우저가 정상 브라우저 헤더를 흉내 내어 WAF가 정상 요청으로 오인 | 자바스크립트 챌린지, 행위 분석(마우스 궤적, 입력 지연)을 결합한 봇 식별 | 봇 차단률, 오탐률 |
| 협박형 RDDoS | 대가 지불을 요구하는 협박으로 경영진이 판단을 서두름 | 사전 비상 대응 훈련, 사이버대피소 사전 연동, 협상 거부 원칙 명문화 | 훈련 이행률, 대응 소요 시간 |

## Ⅵ. DDoS에 대한 기술사적 제언

- 핵심 요약 : 회선 확충이 아닌 클라우드 흡수, 계층별 임계치, 상위 망과의 공조를 묶은 다층 방어 체계로 전환.
- 서버 운영체제에서는 SYN Cookie를 켜 연결 대기열을 쌓지 않고 연결을 검증하도록 하고, 연결 임계치를 함께 설정해야 한다.
- API 게이트웨이에는 IP·토큰별 요청 수를 제한하는 **레이트 리미팅** (Rate Limiting) 정책을 적용하여 비정상적인 API 플러딩을 줄여야 한다.
- 공격 패킷의 특성을 **BGP Flowspec** (BGP 경로 정책으로 특정 트래픽 규칙을 라우터에 전파하는 기능) 규칙으로 상위 ISP 백본에 전파하면, 공격 트래픽을 외곽에서 바로 버릴 수 있다.

## Ⅶ. 결론

- 핵심 요약 : DDoS는 대역폭과 연결 자원, 애플리케이션을 함께 노리는 복합 공격이므로 계층별 다층 방어가 기본임.
- 시사점 : 회선 규모로 버티는 방식은 한계가 분명하므로, 클라우드 흡수와 행위 기반 탐지를 기본 설계로 삼아야 함.
