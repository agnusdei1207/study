## 지식 로드맵 내 현재 위치

정보보안 → 정보보호 거버넌스 및 컴플라이언스 → **ISMS(정보보호 관리체계)**

## 30초 인출

- 본질: **ISMS(Information Security Management System)** : 조직의 핵심 정보자산을 기밀성, 완전성, 가용성 관점에서 안전하게 보호하기 위해 정책 수립, 위험 관리, 통제 대책 구현, 사후 점검의 과정을 체계화한 종합 정보보호 관리체계 (정보통신망법 제47조)
- 메커니즘: 관리체계 수립·운영(16개)과 보호대책 요구사항(64개)의 총 80개 인증기준을 바탕으로, 자산 식별 → 위험 평가 → 위험 처리(DoA 기준) → 내부 점검의 PDCA 폐루프 지속 운영
- 통찰: 심사용 1회성 서류 구비로 인한 평시 운영 괴리와 클라우드 책임 공유 모델 누락 한계 극복을 위해 컴플라이언스 코드화 기반 실시간 증적 수집 체계 구축 필수

<details>
<summary>핵심 용어</summary>

- **ISMS (정보보호 관리체계)** : 정보자산의 보안 위협으로부터 주요 정보자산을 보호하기 위한 일련의 조치와 활동이 국가 공인 기준에 적합함을 증명하는 제도
- **DoA (Degree of Acceptance)** : 조직이 경영 전략상 감수할 수 있는 위험의 수용 한계 수준으로, DoA를 초과하는 위험은 위험 완화/회피/이전 등 정보보호 대책 수립 강제
- **인증 범위 (Scope)** : 조직의 전체 업무 중 ISMS 인증 기준을 적용받는 물리적 사업장, IT 인프라, 정보시스템 및 서비스의 경계
- **정보통신망법 제47조** : 매출액, 이용자 수 등 일정 요건을 충족하는 정보통신서비스 제공자 및 집적정보통신시설(IDC) 사업자의 ISMS 의무 인증 근거 조항
- **Compliance-as-Code (CaC)** : 수동 감사 서류 작성 대신 클라우드 API 및 형상 관리 도구를 통해 보안 규정 준수 여부를 코드로 자동화하여 실시간 검증하는 엔지니어링 기법

## 2~4교시 25점 답안

## Ⅰ. ISMS의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 기업 및 기관이 주요 정보자산을 보호하기 위해 수립·운영·관리하는 정보보호 관리체계가 과학기술정보통신부 및 KISA의 공인 인증기준에 적합한지 종합 심사하여 부여하는 국가 인증 제도 (정보통신망법 제47조) |
| 목적 | 해킹, 정보 유출, 랜섬웨어 등 사이버 위협에 대한 사전 예방력 확보, 비즈니스 연속성 보장 및 대외 보안 신뢰성 제고 |

## Ⅱ. ISMS의 특징 및 2대 영역 인증기준 구조

| 인증 영역 | 세부 항목 수 | 주요 포함 내용 및 엔지니어링 특징 |
|---|---|---|
| **1. 관리체계 수립 및 운영** | **16개 세부 기준** | **Plan-Do-Check-Act 거버넌스 체계 확립**<br/>- 1.1 관리체계 기반 마련 (최고책임자 지정, 예산/조직 할당, 범위 설정)<br/>- 1.2 위험 관리 (자산 식별, 위협/취약점 분석, DoA 수립, 이행계획)<br/>- 1.3 관리체계 운영 (보호대책 이행, 증적 기록 관리)<br/>- 1.4 관리체계 점검 및 개선 (연 1회 내부 감사, 경영진 보고) |
| **2. 보호대책 요구사항** | **64개 세부 기준** | **기술적·물리적·관리적 보안 통제 구현**<br/>- 2.1 정책, 조직, 직무 보안 (보안 서약서, 퇴사자 계정 회수)<br/>- 2.2 외부자 보안 (외주 용역 통제, SLA 관리)<br/>- 2.3 정보자산 식별 및 등급 부여<br/>- 2.4 암호화 적용 (DB, 전송 구간 TLS)<br/>- 2.5 접근 통제 (서버/DB 접근 제어, MFA 적용)<br/>- 2.6 운영 보안 및 2.7 보안 시스템 개발/도입 보안<br/>- 2.8 침해사고 대응 및 비상 복구 체계 |

## Ⅲ. ISMS 위험관리 라이프사이클 및 PDCA 순환 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ ISMS 위험관리 PDCA 폐루프 아키텍처 ]                │
│                                                                        │
│   [Plan (기획 및 수립)]                                                │
│   - 정보보호 최고책임자(CISO) 지정 및 정보보호위원회 가동             │
│   - 정보자산 목록 식별 및 중요도(기밀성/완전성/가용성) 등급 부여       │
│          │                                                             │
│          ▼                                                             │
│   [위험 평가 (Risk Assessment)]                                        │
│   - 위협(Threat) x 취약점(Vulnerability) = 위험도(Risk Level) 산출     │
│   - 위험 수용 한계(DoA) 설정 -> DoA 초과 잔여위험에 대한 대책 확정    │
│          │                                                             │
│          ▼                                                             │
│   [Do (보호대책 이행 및 운영)]                                         │
│   - 64개 보호대책 실행 (방화벽 룰 정비, DB 암호화, 보안 관제)         │
│   - 일상 운영 증적(접근 로그, 변경 승인서, 교육 확인서) 생성           │
│          │                                                             │
│          ▼                                                             │
│   [Check & Act (점검 및 지속적 개선)]                                  │
│   - 연 1회 내부 감사 실시 -> 부적합 항목 시정조치 요구                 │
│   - 경영진 보고 및 차년도 예산/정책 반영 (자가 진화 폐루프 달성)       │
└────────────────────────────────────────────────────────────────────────┘
```

| 관리 과정 단계 | 핵심 수행 작업 | 산출 증적 문서 |
|---|---|---|
| **자산 식별 및 분류** | 서버, 네트워크, DB, 클라우드 자산 및 개발 소스코드 인벤토리 작성 | 정보자산 식별 목록, 자산 분류 등급표 |
| **위험 평가 및 DoA 결정** | 취약점 진단(CVE 스캔)과 위협 빈도를 결합하여 위험 수용 수준(DoA) 설정 | 위험평가 방법론서, 위험평가 결과서 |
| **정보보호 대책 수립** | DoA 초과 자산에 대해 완화(Mitigate), 회피, 이전, 수용 조치 계획 수립 | 정보보호계획서(RTP), 이행 일정표 |
| **이행 점검 및 사후 관리**| 내부 감사원 구성 후 모의 심사 수행, 미이행 항목 보완 후 경영진 검토 | 내부 감사 보고서, 경영진 보고서 |

## Ⅳ. ISMS vs ISMS-P vs ISO/IEC 27001 비교

| 비교 항목 | ISMS (정보보호 관리체계) | ISMS-P (개인정보보호 통합) | ISO/IEC 27001 (국제 표준) |
|---|---|---|---|
| **인증 기준 수** | **총 80개 기준 (16+64)** | **총 101개 기준 (16+64+21)** | 4개 통제 영역 93개 통제 (2022년판) |
| **개인정보 통제**| 개인정보 기술적 보호조치 중심 | **개인정보 전 생애주기 21개 통제 추가**| 부속서(Annex A) 수준에서 개괄적 정의 |
| **법적 근거** | **정보통신망법 제47조** | **정보통신망법 + 개인정보보호법 제32조의2**| 국제표준화기구(ISO) 민간 표준 |
| **의무 대상자** | ISP, IDC, 일정 규모 이상 IT 기업 | 법적 의무 대상은 ISMS(선택적 P 취득) | 법적 의무 없음 (자율 취득) |
| **주관 및 인증기관**| 과학기술정보통신부 / KISA, 금융보안원 | 개인정보보호위원회, 과기정통부 / KISA 등 | 국제 공인 인증기관 (BSI, DNV 등) |
| **대외 통용성** | 국내 전용 인증 제도 | 국내 전용 인증 제도 (마이데이터 필수) | **글로벌 통용 (해외 진출, 수출 필수)** |

## Ⅴ. ISMS 운영 시의 핵심 엔지니어링 한계와 방안

| 한계 | 방안 |
|---|---|
| 연 1회 갱신 심사 직전에만 관련 문서와 로그를 몰아서 정리하는 형식적 운영으로 인해, 평상시 형상 변경 이력, 접근 제어 승인 누락, 퇴사자 계정 미회수 등 심각한 보안 사각지대 상존 | 클라우드 형상 관리 도구(Terraform, GitOps)와 SIEM을 연동하여 보안 설정 변경 및 계정 생성/삭제 이벤트를 실시간 모니터링하고 증적을 위변조 방지 스토리지(WORM)에 자동 아카이빙하는 상시 감사 체계 구축 |
| 멀티 클라우드(AWS, Azure) 및 마이크로서비스(MSA) 도입으로 수천 개의 컨테이너와 임시 인스턴스가 동적으로 생성·삭제되면서 기존 엑셀 기반 자산 원장에서 누락되는 자산 관리 붕괴 발생 | 클라우드 보안 태세 관리(CSPM) 및 클라우드 자산 탐지(CAASM) 솔루션을 도입하여 클라우드 API 기반으로 모든 가상 자산을 실시간 탐지하고 ISMS 자산 목록과 자동 양방향 동기화 구현 |
| 인증심사 수검 시 지적된 결함(부적합) 사항에 대해 표면적인 단기 조치만 수행하고 근본 원인 분석(RCA) 및 조직 프로세스 개선으로 연계되지 않아 차년도 심사에서 동일 지적 반복 | 결함 항목을 형상 관리 시스템(Jira) 티켓으로 등록하여 개발/인프라 스프린트 작업에 의무 할당하고, 재발 방지 유효성 검증 결과를 CISO 주관 보안위원회에 보고하는 환류 프로세스 제도화 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
ISMS 인증 취득을 단순 컴플라이언스 규제 준수 목적으로 접근하면 막대한 인력과 비용 낭비를 초래하므로, 개발 및 배포 전 주기에 보안을 자동 내재화하는 DevSecOps 및 컴플라이언스 코드화(Compliance-as-Code) 접근을 취해야 하며, 외부 감사인을 위한 일회성 보고서가 아닌 실시간 보안 대시보드를 기반으로 상시 거버넌스 체계 확립 권장

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│               [ Compliance-as-Code 기반 ISMS 상시 감사 아키텍처 ]       │
│                                                                        │
│   [클라우드 및 온프레미스 인프라]                                       │
│   - AWS IAM, Kubernetes, Git Repository, 사내 DB                      │
│          │                                                             │
│          ▼ 실시간 이벤트 스트림 (CloudTrail / Audit Log)               │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │                 CSPM & CaC 감사 엔진 (Open Policy Agent)       │   │
│   │  - 정책 코드로 ISMS 80개 기준 검증:                           │   │
│   │    * 규칙 2.5: "MFA 미적용 계정 탐지 시 즉시 알림"            │   │
│   │    * 규칙 2.4: "S3 버킷 비암호화 생성 차단"                    │   │
│   └───────┬────────────────────────────────────────────────┬───────┘   │
│           │ [위반 탐지]                                    │ [정상 증적]│
│           ▼                                                ▼           │
│   [SOAR 자동 티켓팅]                                [WORM 보안 스토리지]│
│   (담당자 슬랙 통보 및 자율 롤백)                    (감사용 증적 자동축적)│
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 평가 방식 | 수동 서류 감사 (전통적) | 정기 스크립트 점검 | CaC 기반 상시 지속 감사 (Continuous) |
|---|---|---|---|
| **증적 수집 주기** | 연 1~2회 수기 취합 | 월간 또는 분기별 배치 실행 | **실시간 스트리밍 자동 수집** |
| **운영 인력 리소스**| 보안팀 전담 수개월 소모 | 스크립트 유지보수 공수 발생 | **인프라 파이프라인 자동화로 최소화** |
| **보안 사각지대** | 심사 기간 외 위반 감지 불가 | 점검 주기 사이의 위반 미탐 | **설정 위반 즉시 탐지 및 차단** |
| **클라우드 적합성**| 매우 부적합 (동적 자산 추적 불가)| 한계 존재 | **클라우드 네이티브 환경에 최적** |

## 출제 이력과 검증 출처

- 정보관리기술사 138회 3교시: ISMS 인증 영역·법적 근거·관리과정 및 강화 방안
- 컴퓨터시스템응용기술사 128회 1교시: ISMS와 ISMS-P의 차이점 및 클라우드 환경에서의 관리체계 구축 방안
- 정보통신망 이용촉진 및 정보보호 등에 관한 법률 제47조 (정보보호 관리체계의 인증)
- 과학기술정보통신부·개인정보보호위원회 고시: 정보보호 및 개인정보보호 관리체계 인증 등에 관한 고시
