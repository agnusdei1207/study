## 지식 로드맵 내 현재 위치

지식 위치: 프라이버시 강화 암호 → **다자간 계산(MPC)**

## 30초 인출

- **본질:** 복수의 참여자가 각자의 비밀 입력값을 외부에 일체 공개하지 않고, 합의된 목적 함수의 결과만을 안전하게 공동 계산하는 암호학적 프로토콜
- **메커니즘:** 입력값 비밀 분할(Secret Sharing) 및 회로 난독화(Garbled Circuit) → OT(Oblivious Transfer) 기반 중간 연산 및 Beaver Triple 교환 → 최종 합의 결과 복원
- **통찰:** WAN 환경의 곱셈 게이트 통신 라운드 병목은 오프라인 비버 트리플 사전 생성으로 완화하고, 악의적 참여자 이탈은 검증 가능 비밀 분산(VSS)으로 무결성 보장 필수

<details>
<summary>핵심 용어</summary>

- **MPC (Multi-Party Computation)** : 비밀 입력값을 비공개 상태로 유지한 채 공동 계산을 수행하는 암호 기술.
- **비밀 분산 (Secret Sharing)** : 데이터를 여러 조각(Share)으로 분할하여 임계값 이상의 조각이 모여야만 복원 가능한 방식.
- **가블드 회로 (Garbled Circuit)** : 불리언 연산 회로의 진리표를 암호화하여 중간 와이어 값을 은닉하는 2자간 계산(2PC) 기법.
- **불확정 전송 (Oblivious Transfer)** : 송신자가 수신자의 선택 정보를 모른 채 수신자가 원하는 데이터만 전달하는 프로토콜.

</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 복수의 참여자가 개인 입력 데이터를 서로에게 공개하지 않고, 목표 함수 $y = f(x_1, x_2, \dots, x_n)$의 연산 결과만을 도출하는 프라이버시 보존 암호 프로토콜 |
| 목적 | 데이터 결합 및 분석 시 원천 데이터 노출 위험을 원천 차단하고, 프라이버시 침해 없는 다기관 데이터 공동 활용 및 탈중앙화 키 관리 실현 |

- 신뢰할 수 있는 제3자(TTP: Trusted Third Party) 없이도 참여자 간 암호학적 상호작용만으로 TTP가 연산한 것과 동일한 보안성(기밀성, 무결성) 제공

## Ⅱ. 다자간 계산(MPC)의 기술적 특성

| 특성 항목 | 세부 내용 및 기술적 의미 | 구현 메커니즘 |
|---|---|---|
| 입력 기밀성 (Privacy) | 정상 프로토콜 수행 과정에서 상대방의 입력 $x_i$에 대한 어떠한 정보도 노출 차단 | Shamir 비밀 분산 및 난독화 회로 키 매핑 |
| 연산 무결성 (Correctness) | 참여자가 프로토콜을 변조하거나 위조 입력을 주입해도 올바른 결과 $f(x)$ 계산 보장 | 검증 가능 비밀 분산(VSS), 영지식 증명(ZKP) |
| 단일 실패점 제거 (No SPOF) | 중앙화된 데이터 저장소나 단일 마스터 키 없이 분산 노드 간 협업으로 동작 | 임계값 암호학(Threshold Cryptography) |
| 공격자 모델 대응성 | 정직하지만 호기심 많은 모델(Semi-Honest)부터 능동적 악의적 모델(Malicious)까지 방어 | 참여자 수 $n$과 공모 허용 임계값 $t$의 정합 설계 ($t < n/2$ 또는 $t < n/3$) |

- 개인정보보호법 가명정보 결합 및 금융권 마이데이터 신용평가 모델에서 원천 데이터 반출 없는 연합 분석의 핵심 기술로 부각

## Ⅲ. MPC 연산 메커니즘 및 주요 기술 종류

```text
[다자간 계산(MPC)의 연산 흐름 및 핵심 기술 구성 체계]

 [참여자 1 (x1)]          [참여자 2 (x2)]          [참여자 3 (x3)]
        │                        │                        │
        ▼                        ▼                        ▼
 ┌──────────────┐         ┌──────────────┐         ┌──────────────┐
 │ Secret Share │         │ Secret Share │         │ Secret Share │
 │ [x1]1,[x1]2..│         │ [x2]1,[x2]2..│         │ [x3]1,[x3]2..│
 └──────┬───────┘         └──────┬───────┘         └──────┬───────┘
        │                        │                        │
        └────────────────┐       │       ┌────────────────┘
                         ▼       ▼       ▼
              ┌─────────────────────────────────────┐
              │      보호된 연산 계층 (MPC Core)     │
              │  - 덧셈: 로컬 연산 (Local Linear)   │
              │  - 곱셈: Beaver Triple 기반 통신    │
              │  - 비선형: Garbled Circuit + OT     │
              └──────────────────┬──────────────────┘
                                 │
                                 ▼
              ┌─────────────────────────────────────┐
              │  결과 복원 계층: 합의된 출력 y 계산  │
              │   y = f(x1, x2, x3) (입력값 은닉)   │
              └─────────────────────────────────────┘
```

| 기술 종류 | 핵심 메커니즘 | 장점 및 고려사항 |
|---|---|---|
| 비밀 분산 (Secret Sharing) | Shamir의 다항식 보간법 기반 $(t, n)$ 임계 분할, 덧셈은 통신 없이 로컬 수행 | 덧셈 연산 효율 극대화, 곱셈 연산 시 참여자 간 네트워크 통신 라운드 발생 |
| 가블드 회로 (Garbled Circuit) | 불리언 회로의 진리표를 대칭키로 4중 암호화하여 와이어 레이블 전송 (Yao's Protocol) | 회로 깊이와 무관하게 2자간 계산(2PC)에서 상수 라운드 통신 가능, 회로 크기 증가 |
| 불확정 전송 (OT) | $1\text{-out-of-}k$ 방식으로 수신자 인덱스 노출 없이 원하는 와이어 키를 획득 | 암호학적 기본 빌딩 블록, OT Extension 기술을 통해 공개키 연산 오버헤드 완화 |
| 임계값 서명 (TSS) | 개인키를 조각내어 보관하고, $t$개 이상의 노드가 MPC로 서명 조각을 연산하여 단일 서명 생성 | 단일 키 탈취 위험 원천 제거, 블록체인 지갑 및 MPC 무암호 인증의 기반 |

## Ⅳ. 프라이버시 보존 연산 기술 비교: MPC vs 동형암호 vs TEE

| 비교 항목 | 다자간 계산 (MPC) | 동형암호 (FHE) | 신뢰실행환경 (TEE) |
|---|---|---|---|
| 보안 기반 | 정보이론적·계산적 안전성 (분산 신뢰) | 수학적 격자 난제 (LWE 기반 단일 암호화) | 하드웨어 격리 영역 (Intel SGX, ARM TrustZone) |
| 연산 주체 | 다수 노드 간 상호 협력 통신 | 단일 클라우드 서버에서 암호문 직접 연산 | 단일 보안 엔클레이브(Enclave) 내부 평문 연산 |
| 네트워크 부하 | 높음 (곱셈 및 비선형 연산마다 통신 발생) | 낮음 (서버 단독 연산으로 통신 라운드 최소) | 없음 (단일 프로세서 내부 버스 통신) |
| 연산 속도 | 통신 대역폭 및 레이턴시에 종속 | CPU 집약적 연산 오버헤드 극심 (부트스트래핑) | 네이티브 CPU 속도에 근접 (매우 빠름) |
| 하드웨어 의존 | 없음 (순수 암호 소프트웨어 알고리즘) | 없음 (순수 수학적 암호 알고리즘) | 높음 (특정 CPU 하드웨어 칩셋 필수) |
| 부채널 취약성 | 네트워크 트래픽 패턴 분석 외 물리 공격 면역 | 수학적으로 안전 | 사이드채널(Spectre, Meltdown, 캐시 공격) 취약 |

## Ⅴ. 분산 환경 구축 시 엔지니어링 한계와 해결 방안

| 한계 | 방안 |
|---|---|
| WAN 환경에서 곱셈 게이트 수 증가에 따른 통신 라운드 누적 및 극심한 네트워크 레이턴시 지연 | 오프라인/온라인 2단계 연산 분리를 적용하여 유휴 시간에 Beaver Triple을 대량 사전 생성(Offline Preprocessing)하고, 실제 연산 시에는 1회 통신만으로 선형 처리 |
| 악의적 참여자가 프로토콜 중간에 비정상 종료(Abort)하거나 위조 공유값을 주입하여 연산 교란 | 검증 가능 비밀 분산(VSS: Verifiable Secret Sharing)과 영지식 증명(ZKP)을 결합하여 각 라운드마다 공유값 무결성을 실시간 검증하고 불공정 이탈 방지 메커니즘 구현 |
| 최종 출력값 $y = f(x)$ 자체의 정보량이 과도하여 차분 추론 공격(Inference Attack)으로 원본 역추론 위험 | MPC 최종 결과 출력 계층에 차등 프라이버시(Differential Privacy) 기반 라플라스/가우시안 노이즈 주입 모듈을 연동하고 질의 빈도 제한(Query Rate Limiting) 적용 |
| 참여 노드 수 증가에 따른 통신 복잡도 급증 ($O(n^2)$)으로 수십 개 이상 기관 참여 시 확장성 한계 | 전체 참여자 중 무작위 검증 위원회(Committee Selection)를 선출하여 연산을 위임하는 계층적 MPC 토폴로지 구성 및 SIMD 기반 배치 벡터화 연산 도입 |

## Ⅵ. MPC 기반 차세대 인증 서비스 아키텍처 및 구현 제언

```text
[MPC 기반 탈중앙화 무암호 인증(TSS) 서비스 아키텍처]

  [사용자 단말 (스마트폰)]         [인증 서비스 서버]         [독립 보안 백업 기관]
  ┌──────────────────────┐      ┌──────────────────────┐      ┌──────────────────────┐
  │ Key Share 1 (W1)     │      │ Key Share 2 (W2)     │      │ Key Share 3 (W3)     │
  │ Secure Enclave 저장   │      │ HSM 격리 저장        │      │ 콜드 스토리지 저장   │
  └──────────┬───────────┘      └──────────┬───────────┘      └──────────┬───────────┘
             │                             │                             │
             └──────────────┬──────────────┘                             │
                            ▼ (인증 요청 시 2-of-3 MPC 연산)              │
             ┌─────────────────────────────┐                             │
             │   TSS 기반 단일 전자서명 생성 │                             │
             │   (단일 개인키 복원 없이 생성)│                             │
             └──────────────┬──────────────┘                             │
                            │                                            │
                            ▼ (단말 분실/파손 시 키 복구 프로세스)       │
                            └────────────────────────────────────────────┘
                             2-of-3 MPC 재공유 프로토콜로 단말 키 재생성
```

| 구현 핵심 축 | 엔지니어링 세부 과제 | 검증 지표 |
|---|---|---|
| 키 분산 저장 | 개인키를 3개 조각으로 분산(단말, 인증서버, 백업기관)하고 임계치(2-of-3) 설계 | 키 저장소 단일 지점 탈취 시 원본 키 복원 불가 (안전성 증명) |
| 서명 프로세스 | 사용자 생체 인증 통과 시 단말-서버 간 MPC 프로토콜 수행으로 FIDO 서명 생성 | 서명 생성 지연 시간 < 300ms, 네트워크 통신 라운드 < 3회 |
| 복구 메커니즘 | 단말 분실 시 백업 기관과 인증 서버의 2개 조각으로 새 단말에 키 재공유(Resharing) | 서비스 중단 없는 원격 키 복구 시간 < 5초, 기존 분실 키 무효화 |
