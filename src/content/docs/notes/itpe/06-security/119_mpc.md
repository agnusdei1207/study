## 답안 골격
```text
[안전한 다자간 계산(MPC, Multi-Party Computation)] ◀━━ 머리: Ⅶ 내 의견 (중앙 집중형 데이터 결합의 프라이버시 유출 극복 → 비밀 분산과 혼란 회로 기반 원시 데이터 없는 협업 연산 생태계 구축)
 ┃
 ┣━ Ⅰ 개요 ───── 여러 참여자($P_1, P_2, \dots, P_n$)가 각자의 비밀 입력 데이터($x_1, x_2, \dots, x_n$)를 상대방에게 전혀 공개하지 않으면서, 공동의 연산 함수 결과값 $y = f(x_1, x_2, \dots, x_n)$만을 안전하게 계산해 내는 현대 암호학 기술
 ┣━ Ⅱ 특징 ───── 입력 프라이버시(Input Privacy) 보장 · 계산 결과의 정확성(Correctness) 보장 · 신뢰받는 제3자(TTP) 불필요 · 연산 및 네트워크 통신 오버헤드 큼
 ┣━ Ⅲ 구조 ───── 3대 핵심 기반 기술: 비밀 분산(Secret Sharing, Shamir) + 혼란 회로(Garbled Circuit, Yao) + 비의도적 전송(Oblivious Transfer, OT)
 ┣━ Ⅳ 흐름 ───── 각자 비밀 데이터를 조각(Share)으로 분할 → 참여자 간 분할 조각 암호 교환 → 로컬 게이트 연산 및 비의도적 전송 통신 → 조각 재결합을 통한 최종 함수 결과 복원
 ┣━ Ⅴ 비교 ───── MPC(다자간 분산 연산, TTP 불필요, 통신량 큼) vs 동형암호(단일 서버에 암호문 전달 후 연산, 연산량 극대) vs 연합학습(가중치만 공유, 통계적 역산 위험)
 ┗━ Ⅵ 실무 ───── 참여 노드 수 증가에 따른 통신 라운드 폭증 / 악의적 참여자(Malicious Adversary)의 입력 조작 대응 / 대용량 데이터 연산 시 지연
```
- 필수 키워드: 다자간 계산(MPC) · 비밀 분산(Secret Sharing) · 혼란 회로(Garbled Circuit) · 비의도적 전송(OT) · 야오의 백만장자 문제 · 입력 프라이버시 · PET
- 배점 전략: 10점 = Ⅰ MPC 개념 및 야오의 백만장자 문제 → Ⅲ 3대 암호학적 기반 기술 도식 → Ⅴ 동형암호 및 연합학습 비교표 / 25점 = Ⅰ~Ⅶ 전개, 제133회 4교시 기출 완벽 대응, 샤미르 비밀 분산 다항식($f(x)$) 수학적 원리, 2자간(2PC)에서 N자간(MPC) 확장 기술 및 암호화폐 MPC 지갑 실무 사례 심층 상술
- 기출: 제133회 4교시 1번: "데이터 중심 사회에서 데이터의 프라이버시와 보안은 매우 중요한 이슈로 부상하고 있고, 이를 해결하기 위한 다양한 기술적 접근이 시도되고 있다. 그러한 시도 중에서 다자간 계산(Multi-Party Computation; MPC)에 대하여 다음을 설명하시오."

## 한 줄 본질
- 서로 믿지 못하는 기관들이 기밀 데이터를 공유하지 못해 공동 분석이 차단되는 협업 병목 → 데이터를 여러 조각으로 쪼개어 암호화한 후 네트워크 상에서 상호 통신하며 결과만 산출 → 원본 노출 0%의 프라이버시 보존 연산 확보 / 통신 라운드 증가에 따른 네트워크 대역폭 비용 발생

## 핵심 그림
```text
[안전한 다자간 계산(MPC)의 동작 원리 및 3대 핵심 요소]

[참여자 A: 재산 X]                            [참여자 B: 재산 Y]
       │                                              │
       ▼                                              ▼
[샤미르 비밀 분산]                            [샤미르 비밀 분산]
조각: [Share A1], [Share A2]                  조각: [Share B1], [Share B2]
       │             │                                │             │
       │             └────────── 조각 교환 ───────────┘             │
       ▼                                                            ▼
 [노드 1: A1 + B1] ◀──(비의도적 전송 OT / 혼란 회로 연산)──▶ [노드 2: A2 + B2]
       │                                                            │
       └─────────────────────────────┬──────────────────────────────┘
                                     ▼
                  [최종 결과 도출: $X > Y$ 여부만 확인!]
                  (상대방의 실제 재산 수치는 전혀 알 수 없음)
```

## 핵심 용어
- 혼란 회로 (Garbled Circuit): 불린 회로(Boolean Circuit)의 논리 게이트(AND, OR) 진리표를 암호화하여, 연산자가 중간 입력값의 참/거짓을 알지 못하면서도 최종 출력 라벨만 해독할 수 있게 만드는 암호 기법
- 비의도적 전송 (OT, Oblivious Transfer): 송신자가 여러 데이터($m_0, m_1$)를 보낼 때 수신자가 원하는 하나($m_b$)만 받되, 송신자는 수신자가 무엇을 골랐는지 모르고 수신자는 고르지 않은 다른 데이터를 모르는 암호 프로토콜

## 핵심 통찰
- MPC의 출발점은 "누가 더 부자인지 알고 싶지만 자신의 재산은 말하기 싫은 두 백만장자의 딜레마(Yao's Millionaires' Problem)"임 → 제3의 공증인을 두지 않고 오직 수학과 통신 프로토콜만으로 진실을 확인하는 기적을 만듦
- 동형암호(FHE)는 '연산 능력'이 병목이지만, MPC는 '네트워크 통신 속도(RTT)'가 병목임 → 게이트마다 참여자 간 암호화된 메시지를 수십 차례 주고받아야 하므로 지연 시간이 긴 환경에서는 성능이 급락함
- 암호화폐 분야에서 단일 개인키 유출 위험을 없애기 위해 MPC 기반 키 관리(Key Sharding)가 표준으로 정착함 → 개인키 원본이 어느 서버나 메모리에도 결코 완성된 형태로 존재하지 않음

## 이웃 토픽과 구분
- MPC vs 동형암호(FHE): MPC = 다수 참여자가 네트워크 통신을 주고받으며 협업 연산 수행 / 동형암호 = 단일 참여자가 암호문을 서버에 던져두면 서버 혼자 암호화된 채로 계산 완료

## 문제·원인·대책
- 사례: 경쟁 병원들이 희귀병 환자 데이터를 합쳐 AI 모델을 학습시키려 했으나 의료법 및 개인정보보호법상 데이터 반출이 불가했던 문제
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 민감 환자 데이터의 외부 전송 및 결합 불가 | 기관 간 원시 데이터 직접 공유 시 법적 위반 및 유출 리스크 | MPC 기반 분산 통계 분석 및 연합 연산 플랫폼 구축 | 환자 원본 데이터의 병원 외부 반출 없이 글로벌 통계량 도출 |
| 참여자 중 일부가 악의적으로 조작된 허위 입력값 전송 | 반직관적(Semi-Honest) 모델 대비 악의적 공격자(Malicious) 통제 미비 | 영지식 증명(ZKP) 결합을 통한 입력값 유효성 검증 | 허위 데이터 주입 시 연산 거부 및 부정 참여자 색출 |

## 이렇게 출제된다
- 제133회 4교시 1번: "데이터 중심 사회에서 데이터의 프라이버시와 보안은 매우 중요한 이슈로 부상하고 있고, 이를 해결하기 위한 다양한 기술적 접근이 시도되고 있다. 그러한 시도 중에서 다자간 계산(Multi-Party Computation; MPC)에 대하여 다음을 설명하시오." → 요구 포인트: Ⅰ MPC 개념 및 특징 + Ⅲ 비밀분산/혼란회로/OT 원리 + Ⅴ 타 프라이버시 강화 기술(동형암호, TEE) 비교

## 내 의견
- [마이데이터 및 금융 신용평가 결합에 MPC 법적 효력 인정] 금융사와 통신사가 데이터를 결합할 때 현재는 제3의 데이터전문기관에 원본 데이터를 전송해야 하는 보안 및 독점 리스크가 존재함 → 나라면: 개인정보보호법 상의 안전성 확보 조치로서 MPC 기반 가상 결합 연산을 '데이터의 제3자 제공이 아닌 내부 연산'으로 법적 유권해석을 내리고, 중계 기관 없는 직접 P2P 신용 스코어링을 허용
