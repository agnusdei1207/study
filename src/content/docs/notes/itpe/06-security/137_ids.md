## 30초 인출

- **본질:** 네트워크 트래픽 또는 호스트 감사 로그를 실시간 분석하여 보안 정책 위반, 악성코드 침투, 비인가 침입 행위를 탐지하고 관제 센터에 경보하는 보안 모니터링 시스템
- **메커니즘:** SPAN/TAP 패킷 미러링 수집 → 디코딩 및 정규화 → 시그니처(오용) 매칭 및 기준선(이상) 분석 → 이벤트 상관 분석 및 관리자 실시간 Alert 발송
- **통찰:** TLS 1.3 암호화 패킷 사각지대는 JA4 핑거프린트 기반 ETA 분석으로 극복하고 수동적 감시 한계는 SOAR 연계 인라인 IPS 및 호스트 EDR 자동 격리 결합 필수

<details>
<summary>핵심 용어</summary>

- **IDS (Intrusion Detection System)** : 대역 외(Out-of-band)에서 침입을 탐지·기록·경보하는 침입 탐지 시스템.
- **NIDS / HIDS** : 각각 네트워크 트래픽(NIDS)과 호스트 OS 내부 이벤트/로그(HIDS)를 관찰하는 시스템.
- **오용 탐지 (Signature)** : 이미 알려진 공격 패턴(Rule)과 패킷 페이로드를 1:1 대조하는 방식.
- **이상 탐지 (Anomaly)** : 정상 행위 기준선(Baseline)을 학습한 후 통계적 임계치를 벗어나는 이상 징후를 탐지하는 방식.

</details>

## 2~4교시 예상문제 (25점)

> 침입 탐지 시스템(IDS)의 핵심 동작 원리, 오용 탐지와 이상 탐지 메커니즘, NIDS와 HIDS의 특징을 비교 설명하고, 암호화 트래픽(TLS 1.3) 증가 및 경보 피로(Alert Fatigue)에 대응하기 위한 엔지니어링 방안을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 컴퓨터 시스템이나 네트워크 세그먼트에서 발생하는 이벤트를 실시간으로 수집·분석하여 비인가된 접근 시도, 악성 행위, 정책 위반을 식별하고 경보를 생성하는 보안 관제 시스템 |
| 목적 | 시스템 침해 사고 발생 시 신속한 조기 경보를 통해 피해 확산을 방지하고, 침해 지표(IOC) 및 포렌식 감사 증적을 확보하여 사후 대응 지원 |

- 네트워크 흐름을 직접 차단하지 않고 TAP이나 미러링 포트를 통해 대역 외(Out-of-Band)에서 수동적으로 트래픽을 복제 감시하므로 서비스 가용성에 영향을 주지 않는 장점 보유

## Ⅱ. IDS의 핵심 기술적 특성

| 특성 항목 | 세부 내용 및 기술적 의미 | 운영 및 아키텍처 이점 |
|---|---|---|
| 비침해적 모니터링 (Out-of-Band) | 네트워크 스위치의 SPAN 포트나 광 TAP을 통해 복제된 패킷을 분석 | IDS 장비 장애가 발생해도 실제 서비스 트래픽은 무중단 유지 |
| 복합 탐지 엔진 탑재 | 규칙 기반의 오용 탐지(Snort/Suricata 룰)와 머신러닝 기반 이상 탐지 동시 지원 | 기지 공격의 정밀 탐지와 미지(Zero-day) 위협의 포괄적 감지 |
| 심층 패킷 분석 (DPI) | L2~L4 헤더뿐 아니라 L7 애플리케이션 계층 페이로드 내부 패턴까지 정밀 디코딩 | SQL Injection, XSS, 원격 코드 실행(RCE) 페이로드 탐지 |
| 풍부한 침해 감사 증적 | 탐지된 공격 패킷의 전체 PCAP 덤프 및 세션 메타데이터 저장 | 보안관제 요원의 사후 공격 경로 역추적 및 디지털 포렌식 근거 제공 |

- 탐지율 향상과 함께 오탐(False Positive) 및 미탐(False Negative) 간의 상충 관계(Trade-off)를 정밀 튜닝하는 것이 운영의 핵심 특성

## Ⅲ. IDS 아키텍처 및 4단계 탐지 프로세스

```text
[침입 탐지 시스템(IDS) 4단계 탐지 및 경보 처리 파이프라인]

 ┌─────────────────────────────────────────────────────────────┐
 │                1. 데이터 수집 계층 (Data Collection)         │
 │   - Network TAP / SPAN 포트 미러링 (RAW 패킷 수집)          │
 │   - 호스트 커널 이벤트, 프로세스 실행, Syslog 수집 (HIDS)   │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │              2. 전처리 및 정규화 (Preprocessing)             │
 │   - 패킷 디캡슐레이션, TCP 세션 재조합 (Stream Reassembly)   │
 │   - HTTP / DNS / TLS 프로토콜 파싱 및 정규화                │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │              3. 탐지 및 분석 계층 (Detection Engine)        │
 │   ┌────────────────────────┐    ┌────────────────────────┐  │
 │   │ 오용 탐지 (Signature)  │    │ 이상 탐지 (Anomaly)    │  │
 │   │ - Snort / Suricata Rule│    │ - 머신러닝 프로파일링  │  │
 │   │ - 알려진 취약점 매칭   │    │ - 통계적 기준선 이탈   │  │
 │   └────────────────────────┘    └────────────────────────┘  │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │              4. 상관 분석 및 경보 (Correlation & Alerting)  │
 │   - SIEM / SOAR 연계 중복 경보 제거 및 위험도 점수 산출     │
 │   - 보안관제 대시보드 경보 및 방화벽/IPS 차단 연동          │
 └─────────────────────────────────────────────────────────────┘
```

| 탐지 단계 | 핵심 세부 동작 메커니즘 | 기술적 엔지니어링 포인트 |
|---|---|---|
| 1. 데이터 수집 | 스위치 포트 미러링(SPAN) 또는 물리적 탭(TAP)을 통해 무손실 패킷 캡처 | 초고속 패킷 유실 방지를 위한 링 버퍼(Ring Buffer) 최적화 |
| 2. 세션 재조합 | 쪼개진 IP 프래그먼트 및 TCP 패킷을 순서대로 재조립하여 전체 스트림 복원 | 세션 고갈 공격(State Exhaustion) 방어 메모리 관리 |
| 3. 탐지 엔진 매칭 | Aho-Corasick 다중 패턴 매칭 알고리즘을 통해 수만 개 시그니처 고속 대조 | 오용 탐지 룰셋 정기 자동 업데이트 |
| 4. 상관 분석 및 통보 | 단일 패킷 경보를 묶어 공격 단계(정찰 $\rightarrow$ 침투 $\rightarrow$ C2)별 시나리오 상관 분석 | SIEM 연동 노이즈 경보 필터링 |

## Ⅳ. 탐지 기법 및 구축 유형별 비교 분석

| 비교 항목 | 오용 탐지 (Misuse Detection) | 이상 탐지 (Anomaly Detection) | NIDS (Network IDS) | HIDS (Host IDS) |
|---|---|---|---|---|
| 핵심 원리 | 알려진 공격 패턴과 1:1 비교 | 정상 행위 기준선 대비 편차 측정 | 네트워크 세그먼트 전 트래픽 감시 | 개별 서버 OS 커널 및 파일 감시 |
| 신종 위협 탐지 | 불가능 (미탐율 높음) | 가능 (Zero-day 탐지 가능) | 네트워크 계층 전파 위협 탐지 | 단말 내부 은밀한 악성 행위 탐지 |
| 오탐율 (False +) | 매우 낮음 (명확한 룰 매칭) | 높음 (정상 업무 변화 시 오탐) | 스위치 미러링 설정에 의존 | 로컬 행위 분석으로 정확도 높음 |
| 암호화 가시성 | 페이로드 암호화 시 무력화 | 통계적 메타데이터 분석 가능 | TLS 트래픽 내부 분석 불가 | 메모리/엔드포인트 평문 분석 가능 |
| 시스템 부하 | 패턴 수 증가 시 CPU 부하 | 통계 모델 학습 연산 부하 | 네트워크 대역폭 증가 시 부하 | 대상 서버의 CPU/RAM 리소스 점유 |

## Ⅴ. IDS 운용 시 엔지니어링 한계와 해결 방안

| 한계 | 방안 |
|---|---|
| 전체 웹 트래픽의 90% 이상이 TLS 1.3으로 암호화되어 NIDS가 패킷 페이로드를 열어보지 못하는 암호화 사각지대 발생 | 인라인 전용 SSL 복호화 브로커(Decryption Broker)를 통해 평문 트래픽을 IDS에 공급하거나, 페이로드 복호화 없이 패킷 길이, 시간 간격, TLS 핑거프린트(JA3/JA4)를 분석하는 암호화 트래픽 분석(ETA) 도입 |
| 100Gbps 이상 초고속 백본망에서 대규모 트래픽 유입 시 패킷 버퍼 오버플로우로 인한 패킷 드롭(Packet Drop) 및 탐지 누락 | 리눅스 커널 바이패스 기술인 eBPF/XDP 및 DPDK(Data Plane Development Kit)를 적용하여 제로카피 고속 패킷 수집 파이프라인을 구축하고 SmartNIC 하드웨어 오프로딩 적용 |
| 하루 수만~수십만 건의 경보 발생으로 인한 보안관제 요원의 경보 피로(Alert Fatigue) 및 치명적 침해 경보 간과 | SIEM/SOAR 기반 경보 집약(Alert Aggregation) 및 위험 점수화(Risk Scoring) 알고리즘을 적용하여 반복 노이즈 경보를 자동 필터링하고 동일 공격원 단일 티켓 통합 |
| IDS는 대역 외 수동 감시 특성상 탐지 시점에 이미 악성코드 실행이나 데이터 유출이 완료되어 실시간 능동 방어 불가 | IDS 탐지 이벤트를 SOAR 플레이북과 실시간 연동하여 방화벽 차단 API 호출, 스위치 802.1X 포트 차단, 호스트 EDR 네트워크 격리를 3초 내 자동 실행 |

## Ⅵ. 지능형 침입 탐지·대응(XDR) 진화 아키텍처 제언

```text
[차세대 통합 위협 탐지 및 자동 대응(NDR + EDR -> XDR) 아키텍처]

 ┌─────────────────────────────────────────────────────────────┐
 │                 1. 멀티 센서 텔레메트리 수집                │
 │   - 네트워크: NDR (100G DPDK 가속, TLS JA4 지문 분석)       │
 │   - 엔드포인트: EDR (eBPF 커널 프로세스 계보 감시)          │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │              2. 클라우드 네이티브 XDR 분석 엔진             │
 │   - MITRE ATT&CK 기반 TTP 매핑 및 상관 분석                 │
 │   - AI 기반 비정상 행위 기준선(Baseline) 동적 튜닝          │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │                 3. 능동형 자동 대응 (SOAR Orchestration)    │
 │   - 침해 호스트 즉각 네트워크 격리 (EDR 격리 API)           │
 │   - 경계 방화벽 C2 차단 룰 자동 등록 (Zero-Touch Response)  │
 └─────────────────────────────────────────────────────────────┘
```

| 영역 | 엔지니어링 세부 과제 | 통제 목표치 |
|---|---|---|
| 패킷 무손실 | 100G 고속 트래픽 환경에서 패킷 캡처 유실률 최소화 | 패킷 드롭률 < 0.001% 유지 |
| 경보 최적화 | SOAR 연계 룰 튜닝을 통한 무의미한 노이즈 경보 감축 | 관제 요원 실대응 경보 비율 > 80% 달성 |
| 침해 대응 속도 | 심각 침해 탐지부터 네트워크 격리까지 소요 시간(MTTR) | 자동 격리 완료 시간 < 10초 |
