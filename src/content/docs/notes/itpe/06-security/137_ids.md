## Ⅰ. IDS(Intrusion Detection System)의 개요

- 개념 : 네트워크 세그먼트나 호스트 시스템의 트래픽, 시스템 로그, 프로세스 행위를 실시간으로 모니터링하여 인가되지 않은 침입 시도, 악성코드 활동, 보안 정책 위반을 자동으로 탐지하고 보안 관리자에게 경보(Alert)를 발령하는 수동적 보안 모니터링 시스템.
- 배경 및 필요성 : 단순 패킷 필터링 방화벽은 허용된 포트(80, 443 등)를 통해 유입되는 정교한 애플리케이션 계층 공격(SQL Injection, 익스플로잇 코드)을 감지할 수 없으므로, 심층 트래픽 분석을 통한 침입 탐지 시스템의 도입이 불가피해짐.
- 핵심 목적 : 네트워크 및 시스템에 침투하는 악의적 위협을 조기에 가시화하고, 침해 사고 발생 시 사후 포렌식을 위한 정밀 감사 증적을 확보.

## Ⅱ. IDS(Intrusion Detection System)의 핵심 아키텍처 및 동작 메커니즘

IDS는 설치 위치에 따라 네트워크 기반(NIDS)과 호스트 기반(HIDS)으로 나뉘며, 탐지 방법론에 따라 시그니처 기반(오용 탐지)과 이상 징후 기반(변칙 탐지)으로 분류됨.

```text
[ IDS 분류 아키텍처 및 미러링 기반 패킷 수집 메커니즘 ]

 1. NIDS (네트워크 IDS) : 스위치 미러링(SPAN) 포트 연결 (수동적 모니터링)
    [ 외부 인터넷 ] ---> [ 라우터 / 방화벽 ] ---> [ 코어 스위치 ] ---> [ 내부망 ]
                                                      | (SPAN / TAP 미러링)
                                                      v
                                            +-------------------+
                                            | NIDS 센서 장비     |
                                            | - 패킷 캡처 (DPI) |
                                            | - 시그니처 매칭   |
                                            +---------+---------+
                                                      |
 2. HIDS (호스트 IDS) : 서버 내 에이전트 설치         | (경보/로그 전송)
    +---------------------------------------+         |
    | 엔드포인트 서버 (Web, DB, WAS)        |         |
    | - OS 시스템 콜, 인증 로그, 파일 무결성|         |
    | - [ HIDS 에이전트 (OSSEC/Wazuh) ]      |         |
    +-------------------+-------------------+         |
                        | (에이전트 로그 전송)         v
                        +---------------------> [ 중앙 IDS 관리 콘솔 / SIEM ]
                                                * 관제 요원 경보 알림
                                                * TCP Reset 전송 (제한적 차단)
```

- **시그니처 기반 탐지(Signature-based / Misuse Detection)** : 알려진 공격 패턴(규칙)을 DB화하여 입력 패킷과 대조하는 방식으로, 오탐률(False Positive)이 매우 낮으나 알려지지 않은 제로데이 공격 탐지 불가능.
- **이상 징후 기반 탐지(Anomaly-based / Heuristic Detection)** : 정상적인 시스템/네트워크 행위의 기준선(Baseline)을 프로파일링하고 이를 통계적·머신러닝 기법으로 벗어나는 행위를 탐지하여 변종 및 신종 공격 탐지 가능하나 오탐률이 높음.
- **NIDS(Network-based IDS)** : 네트워크 스위치의 모니터링 포트(SPAN)나 물리적 탭(TAP)에 연결되어 전체 서브넷의 트래픽을 비인가 간섭 없이 전수 감시.
- **HIDS(Host-based IDS)** : 개별 서버 내에 설치되어 시스템 파일 무결성(Tripwire), 커널 시스템 콜, 사용자 로그인 실패 로그, 권한 상승 시도를 내부에서 정밀 감시.

## Ⅲ. IDS(Intrusion Detection System)의 세부 구성 요소 및 비교 분석

| 비교 항목 | **침입 탐지 시스템** (IDS) | **침입 방지 시스템** (IPS) | **보안 정보 및 이벤트 관리** (SIEM) |
| --- | --- | --- | --- |
| 네트워크 위치 | 인라인 밖 (Out-of-Path, 미러링) | 인라인 경로 상 (In-Line, 패킷 경유) | 중앙 서버 (로그 수집 서버) |
| 트래픽 영향 | 패킷 지연(Latency) 전혀 없음 | 패킷 검사로 인한 미세 지연 발생 | 네트워크 실시간 패킷과 무관 |
| 공격 대응 | 수동적 경보 (Alert, TCP Reset) | 능동적 즉각 차단 (Drop, Blackhole) | 다중 장비 로그 상관분석 및 리포팅 |
| 장비 장애 시 | 인터넷 서비스 정상 유지 (Fail-Open) | 네트워크 단절 위험 (Fail-Open/Close) | 로그 수집만 지연, 서비스 무관 |
| 주요 역할 | 침해 시도 조기 가시화 및 사후 증적 | 실시간 익스플로잇 및 웜 바이러스 차단 | 전사 보안 이벤트 통합 및 컴플라이언스 |

- IDS는 서비스 지연을 유발하지 않고 전체 트래픽을 관찰할 수 있는 장점이 있으나, 능동 차단이 불가능하므로 현대 보안에서는 인라인 IPS 및 SIEM/SOAR와 결합 운영됨.

## Ⅳ. IDS(Intrusion Detection System)의 주요 한계점 및 해결 방안

- 능동적 실시간 차단 불가에 따른 골든 타임 상실 :
  - 한계점 : 패킷을 미러링하여 비동기로 분석하므로 악성 패킷이 이미 목적지 서버에 도달하여 취약점을 타격한 후에야 관리자 경보가 발생함.
  - 해결 방안 : 위험도가 명확한 시그니처는 인라인 IPS로 즉각 드롭시키고, 미러링 IDS는 심층 분석 및 헌팅 용도로 분리 이원화.
- TLS 1.3 암호화 트래픽 폭증에 따른 페이로드 가시성 상실 :
  - 한계점 : 인터넷 트래픽 대부분이 HTTPS/TLS로 암호화됨에 따라 NIDS가 패킷 내부의 HTTP 헤더나 공격 문자열을 검사하지 못하는 '장님(Blind)' 현상 발생.
  - 해결 방안 : NIDS 앞단에 전용 SSL 복호화 장비(SSL Visibility Appliance)를 배치하여 미러링 트래픽을 복호화 후 전달하거나 암호화 트래픽 분석(ETA) 도입.
- 방대한 오탐(False Positive)으로 인한 관제 요원의 경보 피로(Alert Fatigue) :
  - 한계점 : 이상 탐지 엔진이 정상적인 대용량 백업이나 신규 비즈니스 트래픽을 공격으로 오인하여 하루 수만 건의 경보를 쏟아내어 실제 중요 위협 간과.
  - 해결 방안 : SOAR(보안 오케스트레이션·자동화) 솔루션을 연계하여 1차 경보를 자동 필터링하고 AI 기반 위협 스코어링 알고리즘 적용.

## Ⅴ. IDS(Intrusion Detection System) 적용 및 발전을 위한 기술사적 제언

- NDR(Network Detection and Response) 체계로의 진화 : 단순 정적 시그니처 매칭 IDS를 탈피하여 비지도 학습 머신러닝 기반으로 네트워크 메타데이터(NetFlow/IPFIX)와 행위를 분석하는 NDR로 전환.
- MITRE ATT&CK 프레임워크 기반 탐지 룰셋 고도화 : Snort, Suricata 규칙을 MITRE ATT&CK 전술 및 기법과 맵핑하여 공격 단계별 침해 징후를 입체적으로 모니터링.
- 클라우드 네이티브 환경의 가상 미러링(VPC Traffic Mirroring) 설계 : AWS, Azure 등 클라우드 인프라 내 가상머신(VM) 및 컨테이너 트래픽을 클라우드 가상 탭을 통해 중앙 IDS 클러스터로 실시간 복제 검사 체계 구축.
