## 한 줄 본질
- IDS는 네트워크·호스트 이벤트를 분석해 침입 징후를 탐지하고 경보하는 체계. 탐지·경보와 차단은 서로 다른 기능

## 10점 답안
IDS(Intrusion Detection System)는 시스템 또는 네트워크 활동에서 공격·정책 위반 징후를 찾아 관리자에게 알리는 보안 시스템. 네트워크 기반 NIDS와 호스트 기반 HIDS로 구분 가능. 알려진 패턴을 찾는 시그니처 탐지와 정상 기준 이탈을 찾는 이상 탐지 등을 조합. 탐지 정책의 오탐·미탐, 센서 배치, 암호화 트래픽 가시성, 경보 처리 절차가 운영 성능을 좌우. IPS는 탐지 결과에 따라 인라인에서 트래픽 차단까지 수행하는 점이 주요 차이.

## 25점 답안
### Ⅰ. 구성과 동작
센서의 패킷·로그 수집 → 정규화·분석 → 규칙·행위 기준 대조 → 경보·사건 확인. NIDS는 네트워크 지점, HIDS는 호스트 이벤트·파일·프로세스 등 관찰.

### Ⅱ. 탐지 방식과 배치
| 방식 | 장점 | 한계 |
|---|---|---|
| 시그니처 | 알려진 공격의 구체적 패턴 설명 용이 | 미등록 변형·신종 공격 미탐 가능 |
| 이상 탐지 | 기준에서 벗어난 행위 발견 가능 | 기준 설정 오류에 따른 오탐 가능 |
| NIDS | 여러 시스템의 통신 관찰 | 암호화 내용·미러링 누락·패킷 손실 한계 |
| HIDS | 호스트 내부 행위 관찰 | 에이전트 설치·관리 부담 |

### Ⅲ. IDS와 IPS 비교
IDS는 보통 대역 외 감시와 경보 중심, IPS는 인라인 차단 중심. 제품 구성에 따라 대응 연계 기능은 달라질 수 있으므로 IDS가 절대 차단하지 못하거나 운영 영향이 0이라고 단정 불가. 탐지율과 오탐률은 실제 환경에서 측정.

### Ⅳ. 운영 관리
자산별 우선순위에 따른 센서 배치, 규칙 갱신, 경보 분류와 사고 대응 연결, 암호화 구간의 합법적 가시성 확보 및 개인정보 보호. 복호화만으로 모든 공격을 완전히 탐지할 수 없음.
