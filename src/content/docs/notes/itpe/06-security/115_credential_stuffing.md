## 연관 키워드

- 크리덴셜 스터핑(Credential Stuffing), 계정 탈취(ATO, Account Takeover), 콤보 리스트, 주거용 프록시
- 브루트 포스(Brute Force), 패스워드 스프레이(Password Spray), 봇 매니지먼트, JA3/JA4 지문
- 패스워드리스, 패스키(Passkey), FIDO2, 작업증명(PoW, Proof of Work), 유출 암호 대조

## Ⅰ. 크리덴셜 스터핑의 개요

- 핵심 요약 : 타 서비스에서 유출된 ID/PW 조합을 자동화 도구로 대량 대입해 계정을 탈취하는 공격.
- 개념 : 타 서비스 침해로 유출된 수백만 건의 ID/PW **콤보 리스트**를 확보한 뒤, 자동화 봇과 분산 프록시로 다른 사이트에 무차별 로그인을 시도하는 사이버 공격.
- 배경 및 필요성 : 여러 서비스에서 같은 비밀번호를 재사용하는 습관 때문에 유출 자격증명이 다른 서비스에서도 유효하여, 봇넷 기반의 대규모 **계정 탈취**(ATO, Account Takeover)를 막을 방어 체계가 요구됨.
- 주요 목적 : 계정 탈취를 통한 포인트와 마일리지 횡령, 저장된 결제 수단 도용, 개인정보 조회, 스팸 계정 유통을 차단.

## Ⅱ. 크리덴셜 스터핑의 특징 및 공격 원리

- 핵심 요약 : 실제 유효한 조합을 분산된 IP로 소량씩 시도하는 방식이라 잠금 정책과 IP 차단을 모두 피해 가는 구조.

1. **실제 유효 조합 사용** : 외부 유출 조합을 그대로 대입 → 재사용 비율만큼 성공 발생.
2. **분산 시도** : 주거용 **프록시**(Residential Proxy)로 요청 출처를 분산 → IP 기반 차단 무력화.
3. **계정당 소량 시도** : 한 계정에 한두 번만 시도하고 다음 계정으로 이동 → 계정 잠금 임계치 회피.
4. **자동화 도구 활용** : 자동화 툴이 대량 로그인을 처리 → 공격 규모 대비 비용 최소화.

## Ⅲ. 크리덴셜 스터핑의 공격 체인과 다계층 방어 구조

- 핵심 요약 : 공격 체인은 유출 조합, 자동화, 분산 프록시로 이어지며, 방어는 엣지 봇 차단, 인증 강화, 사후 거래 감시의 3계층으로 대응.

```text
[ 공격 체인 ]

유출 콤보 리스트 (ID/PW)
   ↓
자동화 툴로 대량 로그인 시도
   ↓
주거용 프록시로 출처 분산
   ↓
표적 서비스 로그인 API
```

```text
[ 3계층 방어 구조 ]

1. 엣지 봇 방어
   TLS 지문(JA4) 대조, 레이트 리밋
        ↓
2. 인증 방어
   유출 암호 대조, 패스키 강제, Step-Up
        ↓
3. 사후 거래 감시
   FDS, UEBA로 로그인 직후 거래 동결
```

## Ⅳ. 브루트 포스·패스워드 스프레이·크리덴셜 스터핑의 비교

- 핵심 요약 : 세 공격은 대입하는 대상과 방식이 다르며, 크리덴셜 스터핑은 실제 유출 조합을 대량 계정에 적용하는 점에서 계정 잠금을 가장 잘 회피함.

| 비교 항목 | **브루트 포스** (Brute Force) | **패스워드 스프레이** (Password Spray) | **크리덴셜 스터핑** (Credential Stuffing) |
|---|---|---|---|
| 대상 계정 | 단일 계정 | 다수 계정 (조직 구성원 등) | 불특정 다수 대량 계정 |
| 대입 패스워드 | 무작위 문자열 전수 대입 | 흔한 취약 패스워드 소수 | 외부 유출 실제 조합 |
| 계정 잠금 위험 | 매우 높음 | 낮음 (계정당 소수 시도) | 낮음~보통 (계정당 1회 시도) |
| 주된 목표 | 특정 관리자 계정 탈취 | 단일 계정으로 내부망 진입 | 일반 사용자 계정의 포인트 횡령 |
| 성공 가능성 | 매우 낮음 | 취약 패스워드 사용자 중 일부 | 재사용 비율에 따라 높음 |

## Ⅴ. 크리덴셜 스터핑의 한계와 방안

- 핵심 요약 : IP 차단, CAPTCHA, 복잡도 정책은 우회되므로 행동 기반 봇 관리, 작업증명, 패스키 전환, 행위 분석으로 전환해야 함.

| 한계 | 원인·영향 | 대응 방안 |
|---|---|---|
| 주거용 프록시로 IP 차단 무력화 | 감염된 가정용 PC를 경유하여 요청이 분산됨 | IP 차단을 지양하고 브라우저 지문(JA4), HTTP/2 지문, 마우스 이벤트를 종합한 행동 봇 매니지먼트 적용 |
| CAPTCHA 우회 | 유료 인간 솔버 API로 이미지 인증이 자동 풀이됨 | 사용자 마찰이 없는 **작업증명**(PoW, Proof of Work) 챌린지 적용 |
| 패스워드 재사용 | 복잡도를 높여도 동일 암호를 여러 사이트에 재사용 | **패스키**(Passkey, FIDO2 WebAuthn)를 기본 인증 수단으로 전환하여 유출 조합의 가치 상실 |
| 장기 잠복 후 분할 인출 | 정상 로그인 후 소액씩 나누어 인출해 탐지 임계치 회피 | 계정 행위와 거래 패턴을 연결하는 **사용자 엔티티 행위 분석**(UEBA) 연동, 최초 고액 거래 정밀 심사 |

## Ⅵ. 크리덴셜 스터핑 대응에 대한 기술사적 제언

- 핵심 요약 : 인증 수단의 전환, 엣지 봇 차단, 유출 암호 사후 관리를 조합하여 계정 탈취의 근본 원인을 줄이는 방향.

로그인 체계는 패스키를 기본으로 채택하여 패스워드 유출 자체가 계정 탈취로 이어지지 않도록 전환하는 것이 바람직하다.

로그인 엔드포인트 앞단에 봇 매니지먼트와 작업증명 챌린지를 배치하여 자동화된 대량 대입 트래픽을 애플리케이션 도달 전에 걸러내야 한다.

유출 암호 데이터베이스(Have I Been Pwned의 k-익명성 API 등)와 연동하여 유출된 암호를 쓰는 사용자에게 변경을 강제하는 사후 관리를 함께 운영해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 크리덴셜 스터핑은 재사용된 패스워드를 악용하는 공격이므로, 패스워드 의존을 줄이는 인증 전환이 근본 대응임.
- 엣지 봇 차단과 행위 기반 탐지는 이를 보완하는 수단으로 함께 운영되어야 함.
