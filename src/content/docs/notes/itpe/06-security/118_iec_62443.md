## 지식 로드맵 내 현재 위치

지식 위치: 산업제어 보안 → 위험 기반 표준 → **ISA/IEC 62443**

## 30초 인출

- **본질:** 산업자동화 및 제어시스템(IACS)의 자산 소유자, 시스템 통합자, 제품 공급자 전 주기에 걸친 위험 기반 심층방어 국제 보안 표준
- **메커니즘:** IACS 자산 분석 → Zone/Conduit 식별 → 위험 평가 기반 SL-T(목표 보안수준) 설정 → 7대 기초요구사항(FR) 통제 구현 및 SL-A 검증
- **통찰:** 실시간 결정론적 제어 보장과 레거시 제어기 연산 한계를 고려하여 단말 암호화 강제 대신 Conduit 경계 차단 및 가상 디지털 트윈 사전 검증 체계 병행 필수

<details>
<summary>핵심 용어</summary>

- **IACS** : 산업자동화·제어시스템(Industrial Automation and Control Systems).
- **Zone** : 동일한 보안 요구사항과 위험 수준을 공유하는 자산들의 논리적·물리적 그룹.
- **Conduit** : 서로 다른 Zone 간의 데이터 전송 통신 경로 및 보안 통제 인터페이스.
- **Security Level (SL)** : SL 1(우발적 노출)부터 SL 4(국가 수준 고도 공격)까지의 방어 역량 수준.

</details>

## 2~4교시 예상문제 (25점)

> ISA/IEC 62443의 4계층 표준 구성, Zone·Conduit 위험 평가 및 보안 수준(SL) 적용 절차를 설명하고, 무중단 플랜트 환경 적용 시 기술적 한계 및 엔지니어링 극복 방안을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 산업자동화 및 제어시스템(IACS)의 사이버 위협 대응을 위해 자산 소유자, 통합자, 공급자 전 주기를 포괄하는 위험 기반 국제 표준군 |
| 목적 | IT/OT 융합 환경에서 가용성과 안전성을 최우선으로 보장하고, Zone/Conduit 기반 심층 방어 체계를 확립하여 공정 마비 및 물리적 재해 방지 |

- 공정 제어(DCS, SCADA, PLC) 환경은 밀리초(ms) 단위 실시간성과 고가용성(99.999%)이 요구되므로, 기밀성 중심의 ISO/IEC 27001과 달리 가용성과 안전성(Safety)을 최우선 설계 원칙으로 채택

## Ⅱ. ISA/IEC 62443의 계층적 표준 구성 특징

| 계층 (Part) | 표준 번호 | 핵심 내용 및 특성 |
|---|---|---|
| Part 1: General | 62443-1-x | 용어 정의, 기본 개념, 메트릭, 보안 수준(SL) 모델 등 프레임워크 전반의 공통 기초 규정 |
| Part 2: Policies & Procedures | 62443-2-x | 자산 소유자(Asset Owner)의 보안 관리 체계, 패치 관리, 운영 및 유지보수 조직 프로세스 규정 |
| Part 3: System | 62443-3-x | 시스템 통합자(Integrator) 관점의 위험 평가(3-2), Zone/Conduit 설계, 시스템 기술적 보안 요구사항(3-3) 명시 |
| Part 4: Component | 62443-4-x | 제품 개발사(Vendor) 관점의 보안 개발 생명주기(SDL, 4-1) 및 개별 IACS 기기 기술적 보안 규격(4-2) 규정 |

- 자산 소유자, 시스템 통합자, 기기 공급자 간 R&R을 명확히 분리하고 상호 유기적으로 연계되는 4계층 라이프사이클 모델 특성 보유

## Ⅲ. Zone·Conduit 기반 위험 평가 및 보안 수준 적용 체계

```text
[ISA/IEC 62443 보안 수준 적용 및 Zone/Conduit 엔지니어링 프로세스]

+--------------------+      +--------------------+      +--------------------+
| 1. SuC 범위 정의    | ---> | 2. Zone/Conduit 분할| ---> | 3. 사이버 위험 평가 |
| (System under      |      | (동일 보안요구 그룹|      | (위협 식별 및      |
|  Consideration 식별|      |  물리/논리 경계 수립|      |  수용 가능 위험 산정|
+--------------------+      +--------------------+      +--------------------+
                                                                  │
+--------------------+      +--------------------+                ▼
| 6. 주기적 운영 검증 | <--- | 5. 보안 통제 구현  | <--- | 4. SL-T 목표치 할당 |
| (SL-A vs SL-T 비교 |      | (방화벽, IPS, VPN, |      | (Zone/Conduit별    |
|  취약점 지속 관리) |      |  인증, 감사로깅)   |      |  SL 1~4 등급 매핑) |
+--------------------+      +--------------------+      +--------------------+
```

| 절차 단계 | 핵심 엔지니어링 활동 | 산출물 및 통제 기준 |
|---|---|---|
| SuC 범위 정의 | 플랜트 내 공정 제어 자산(Purdue 레벨 0~3) 식별 및 네트워크 토폴로지 분석 | 시스템 범위 정의서, 자산 인벤토리 |
| Zone/Conduit 분할 | 물리적 위치, 공정 위험도, 데이터 흐름에 따라 논리적 Zone 격리 및 통신 Conduit 정의 | Zone/Conduit 다이어그램, 트래픽 매트릭스 |
| 위험 평가 (Risk Assessment) | 고유 위험 평가(Unmitigated Risk) 수행 및 비즈니스 영향 분석(BIA) | 사이버 위험 평가 보고서, 공정 위험 매트릭스 |
| SL-T 설정 | 7대 기본 요구사항(FR 1~7) 기반 목표 보안 수준(SL-Target) 도출 | Zone/Conduit별 SL-T 사양서 |
| 통제 구현 및 SL-C 매핑 | 장비 제조사의 지원 역량(SL-C)을 확인하여 부합 통제 구현 및 심층 방어 적용 | 방화벽 정책, 암호화 설정, SL-A 증적 |
| 지속적 검증 | 정기 취약점 분석 및 감사로 실제 달성 수준(SL-A) 평가 및 갭 조치 | 주기적 감사 결과서, 갭 완화 계획 |

## Ⅳ. ISA/IEC 62443 vs ISO/IEC 27001 비교 분석

| 비교 항목 | ISA/IEC 62443 | ISO/IEC 27001 |
|---|---|---|
| 대상 시스템 | 산업제어시스템 (OT/ICS, SCADA, DCS, PLC) | 기업 정보시스템 전반 (IT, ERP, 클라우드, 데이터센터) |
| 핵심 우선순위 | 가용성(Availability) > 무결성(Integrity) > 기밀성(Confidentiality) | 기밀성(Confidentiality) > 무결성(Integrity) > 가용성(Availability) |
| 최우선 가치 | 인명 안전(Safety), 환경 보호, 설비 파괴 방지 | 정보 자산 보호, 비즈니스 연속성, 법적 규제 준수 |
| 주요 구성 체계 | General, Policies, System, Component (4-Part) | 정보보호 경영시스템(ISMS) 요구사항 및 통제 항목(부속서 A) |
| 장비 수명주기 | 15~30년 (교체 주기 장기, 레거시 시스템 다수) | 3~5년 (하드웨어 교체 주기 단기, 최신 OS 신속 반영) |
| 변경 관리 | 정기 보수(O/H) 기간 외 패치 및 리부팅 극도로 제한 | 정기적 보안 패치, 실시간 취약점 업데이트 및 재기동 가능 |

## Ⅴ. 무중단 플랜트 적용 한계와 기술적 극복 방안

| 한계 | 방안 |
|---|---|
| 레거시 제어기(PLC/RTU)의 연산 한계로 인한 실시간 결정론(Determinism) 훼손 및 지연 발생 | 단말 자체 암호화 대신 Conduit 경계에 저지연 산업용 IPSec/MACsec 게이트웨이 및 데이터 다이오드(일방향 전송)를 구축하여 제어 주기(Scan time) 영향 제로화 |
| 24/365 연속 공정 특성상 실시간 보안 패치 적용 불가 및 시스템 리부팅에 따른 가동 중단 위험 | 실제 공정과 동일한 가상 시뮬레이션 디지털 트윈(Digital Twin) 테스트베드에서 사전 무결성 검증 후 계획 정비(O/H) 일정에 맞춘 롤링 패치 체계 확립 |
| Purdue 모델 경계 붕괴(스마트 팩토리 IoT 센서 직결)로 인한 기존 방화벽 기반 경계 통제 무력화 | IEC 62443-3-3 기반의 Micro-segmentation 및 제로 트러스트 OT 아키텍처를 도입하고, 내부 자산 간 상호 TLS 및 소프트웨어 정의 경계(SDP) 적용 |
| IT 보안팀과 OT 제어 엔지니어 간의 도메인 지식 단절로 인한 비현실적 보안 정책 적용 충돌 | IT-OT 융합 거버넌스 협의체를 제도화하고 공정 변수(PLC Logic, 안전 계장 시스템) 모니터링 전용 산업용 위협 탐지(OT NDR) 솔루션 기반 통합 관제 구축 |

```text
                                    │
                                    ▼
     +-------------------------------------------------------------+
     |                  2. 계층적 심층 방어 아키텍처                |

     +-------------------------------------------------------------+
                                    │
                                    ▼
     +-------------------------------------------------------------+
     |                 3. 디지털 트윈 기반 사전 검증                |

     +-------------------------------------------------------------+
```

| 추진 축 | 핵심 이행 과제 | 달성 성과 지표 (KPI) |
|---|---|---|
| 기술 (Technology) | Zone/Conduit 엄격 분리 및 산업용 일방향 전송 장비 구축 | 비인가 Zone 간 통신 차단율 100%, 지연 오버헤드 < 1ms |
| 프로세스 (Process) | IEC 62443-2-1 기반 위험 평가 및 O/H 연계 롤링 패치 정례화 | 취약점 조치율 95% 이상 달성, 패치로 인한 예기치 않은 트립 0건 |
| 조직/사람 (People) | 공정 엔지니어 대상 OT 사이버 안전 교육 및 전담 관제 조직 구성 | 이상 제어 패킷 탐지 및 대응 시간(MTTD/MTTR) 50% 단축 |
