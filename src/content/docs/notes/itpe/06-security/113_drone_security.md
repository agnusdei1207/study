## 지식 로드맵 내 현재 위치

지식 위치: 사이버 물리 시스템 → 무인항공기 → **드론 보안**

## 30초 인출

- 본질: 드론 보안은 기체·지상통제소·제어 링크·항법·저장 데이터를 보호하는 활동
- 메커니즘: GCS와 기체의 C2 메시지, 항법 센서, 기체 펌웨어의 각 신뢰경계에서 명령·위치·데이터를 검증
- 통찰: 한계: MAVLink 2 서명은 기밀성·GNSS 진실성을 보장하지 않음 → 방안: 별도 링크 암호화와 다중 센서 검증·안전 착륙 정책을 적용

<details>
<summary>핵심 용어</summary>

- **명령제어 링크(Command and Control Link, C2)** : 지상통제소와 기체 사이의 명령·상태 전달 경로
- **MAVLink 2 서명** : 제어 메시지의 출처·무결성과 재전송 여부를 확인하는 기능
- **GNSS 스푸핑** : 위조한 위성항법 신호로 수신 위치·시간을 오인하게 하는 공격
- **안전 종료(Fail-safe)** : 링크·항법 이상 때 임무에 맞춰 정지·복귀·착륙하는 절차

</details>

## 2~4교시 예상문제 (25점)

> 드론 시스템의 기체·GCS·C2 링크·항법 위협을 분석하고 통신 인증, 데이터 보호, 안전한 비행 종료를 포함한 방어 구조를 설계하시오. (예상·25점)

## 2~4교시 25점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **드론 보안** 은 기체·지상통제소·제어 링크·항법과 데이터를 보호하는 활동 |
| 목적 | 명령 위조·항법 교란·정보 노출을 줄이고 안전한 비행 유지 |

기체 펌웨어·무선 링크·항법 센서·촬영 자료·운영 계정을 함께 보호한다. 불법 드론 탐지·무력화인 안티드론과 구분한다.

### Ⅱ. MAVLink 2 명령 서명 메커니즘

```text
공유 비밀키 + 패킷 헤더·본문·CRC + 링크 ID·타임스탬프
        → SHA-256 → 앞 48비트 서명 필드
        → 수신 측 출처·무결성·시간 창 검증
```

서명 유효성은 명령 내용의 안전성이나 GNSS 위치의 진실성까지 보장하지 않음.

### Ⅲ. 드론 침해 경로와 보호 계층

```text
GCS ── C2 링크(명령·원격측정) ── 기체
          │ 도청·주입·재전송          │ 펌웨어·저장 데이터
          └─ GNSS 수신·센서 융합 ────┘ 항법 스푸핑·재밍
```

| 층 | 통제 |
|---|---|
| 명령 인증 | MAVLink 2 서명, 공유키 관리, 미서명 메시지 거부 정책 |
| 기밀성 | 별도 링크 암호화와 종단 키 관리 |
| 항법 | GNSS와 INS·영상·지도 등 독립 정보 비교 |
| 기체 | 안전한 업데이트·설정·분실 시 데이터 보호 |
| 비행 안전 | 링크 손실·항법 이상 시 임무별 복귀·정지·착륙 정책 |

#### 검증·운영 과제

| 과제 | 시험 |
|---|---|
| 미서명 메시지 허용 | 호환성 예외로 인증이 무력화되지 않는지 확인 |
| 키 교체 | 기체 분실·정비·GCS 변경 시 폐기·갱신 |
| 링크 장애 | 재밍·지연·패킷 손실에서 Fail-safe |
| 항법 교란 | 센서 불일치 탐지와 잘못된 자동 귀환 방지 |

### Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| MAVLink 2 서명만으로 링크 기밀성·GNSS 신뢰를 보장하지 못함 | 링크 암호화·다중 센서 검증·안전 착륙 정책을 분리 적용 |

### Ⅴ. 제언

명령 메시지의 인증, 무선 구간의 기밀성, 항법 정보의 신뢰성과 실제 비행 안전을 서로 다른 통제로 설계·시험.
