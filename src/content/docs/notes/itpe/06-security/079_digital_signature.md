## 답안 골격
```text
[전자서명(Digital Signature)] ◀━━ 머리: Ⅶ 내 의견 (디지털 신뢰 인프라 완성 → 양자컴퓨터 대비 PQC 전자서명(ML-DSA/SLH-DSA) 전환 추진)
 ┃
 ┣━ Ⅰ 개요 ───── 송신자의 개인키로 메시지 다이제스트를 암호화하여 수신자가 송신자의 신원 확인, 위변조 방지, 부인방지를 달성하는 암호 메커니즘
 ┣━ Ⅱ 특징 ───── 위조 불가(Unforgeable) · 서명자 인증(Authentication) · 부인 방지(Non-repudiation) · 변경 불가/무결성(Integrity)
 ┣━ Ⅲ 구조 ───── 해시 함수(SHA-2/3) + 비대칭키 서명 알고리즘(RSA, ECDSA, Ed25519) + 검증 알고리즘
 ┣━ Ⅳ 흐름 ───── [서명 생성]: 원문 메시지 → 해시 축약 → 송신자 개인키로 서명 생성 / [서명 검증]: 송신자 공개키로 서명 복호화 → 메시지 해시값과 일치 여부 비교
 ┣━ Ⅴ 비교 ───── RSA 서명(소인수분해 난제, 검증 속도 빠름, 서명 크기 큼) vs DSA/ECDSA(이산대수/타원곡선, 키 길이 짧음, 서명 속도 빠름) vs Ed25519(고속, 부채널 방어)
 ┗━ Ⅵ 실무 ───── 서명 검증 시 서명자의 공개키 유효성 보증을 위한 PKI 인증서 체인 및 CRL/OCSP 상태 조회 필수
```
- 필수 키워드: 전자서명 · 해시 함수 · 송신자 개인키 · 송신자 공개키 · 부인 방지 · RSA · ECDSA · PKI 인증서
- 기출: 126회 4교시 5번 `RSA(Rivest-Shamir-Adleman)알고리즘과 DSA(Digital Signature Algorithm)을 비교하여` → Ⅲ 전자서명 구조 + Ⅴ RSA vs DSA 비교

## 한 줄 본질
- 원격 비대면 환경에서 작성자 신원 사칭과 문서 위변조를 막을 수 없는 신뢰 병목 → 메시지 해시값을 송신자의 개인키로 암호화하고 공개키로 검증 → 위변조 탐지 및 법적 부인방지 달성 / 개인키 유출 시 서명 권한 전면 상실

## 핵심 그림
```text
[전자서명(Digital Signature) 생성 및 검증 절차]

  1. [서명 생성 (송신자 측)]
     [원문 메시지] ────(해시 함수: SHA-256)────> [다이제스트]
                                                     │
                                   (송신자 개인키로 암호화)
                                                     ▼
     [원문 메시지] ───────────────────────────> [전자서명] (함께 전송)

  2. [서명 검증 (수신자 측)]
     [전자서명] ───────(송신자 공개키로 복호화)──> [복원된 해시 A]
                                                        │ (일치 비교)
     [원문 메시지] ────(동일 해시 함수 계산)────> [계산된 해시 B]
     * 해시 A == 해시 B 일치 시: 위변조 없음(무결성) + 송신자가 작성함(부인방지) 증명!
```

## 핵심 용어
- 메시지 다이제스트(Message Digest): 가변 길이의 원문 데이터를 고정 길이(예: 256비트)의 고유한 지문 형태로 압축한 해시 결과값
- 부인 방지(Non-repudiation): 오직 서명자 본인만이 보유한 개인키로만 서명이 생성될 수 있으므로, 사후에 자신이 서명하지 않았다고 거짓 주장할 수 없는 성질

## 핵심 통찰
- 원문 전체를 개인키로 암호화하지 않고 '해시값만 암호화'하는 이유 → 비대칭키의 막대한 연산 비용을 수백 비트로 줄이고, 원문 내용의 노출 여부(기밀성)와 상관없이 순수 신뢰(인증·무결성)만 검증하기 위함
- 전자서명의 취약점은 알고리즘 자체가 아니라 '개인키 보관'에 있음 → 개발 서버 소스코드에 하드코딩된 서명 키나 엔드포인트의 탈취가 전자서명 체계를 일거에 붕괴시킴
- 전자서명은 양자컴퓨터의 쇼어(Shor) 알고리즘에 의해 가장 먼저 깨지는 영역임 → 미국 NIST가 PQC 표준 전자서명으로 ML-DSA(Dilithium)와 SLH-DSA(SPHINCS+)를 우선 공표한 이유임

## 이웃 토픽과 구분
- 전자서명 vs MAC(메시지 인증 코드): 전자서명 = 비대칭키 기반(제3자 검증 가능, 부인방지 제공) / MAC = 대칭키 기반(공유자끼리만 검증 가능, 부인방지 불가)

## 문제·원인·대책
- 사례: 소프트웨어 공급업체의 코드 사이닝(Code Signing) 개인키가 해킹되어 악성코드에 정식 전자서명이 부여된 채 배포된 침해 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 신뢰된 인증서로 서명된 악성코드 배포로 백신 무력화 | 빌드 서버 내 전자서명 개인키 파일의 평문 방치 | HSM(하드웨어 보안 모듈) 도입 및 서명 시 다중 승인 파이프라인 강제 | 개인키 외부 유출 원천 차단 및 비인가 서명 통제 |
| 서명자의 인증서가 폐기되었으나 검증기에서 이를 인지하지 못함 | CRL 다운로드 주기 지연 및 OCSP 검증 누락 | OCSP Stapling 및 단말기 실시간 유효성 검증 정책 활성화 | 폐기된 서명키를 통한 불법 거래 및 서명 즉각 차단 |

## 이렇게 출제된다
- 제126회 4교시 5번: "RSA(Rivest-Shamir-Adleman)알고리즘과 DSA(Digital Signature Algorithm)을 비교하여 설명하시오." → 요구 포인트: Ⅰ 전자서명 원리 + Ⅲ RSA(소인수분해 기반 암복호화 겸용) vs DSA(이산대수 난제 기반 전자서명 전용) 수학적 구조 비교 + Ⅴ 키 길이, 서명 속도, 검증 속도 비교표

## 내 의견
- [전자서명 키 생애주기의 하드웨어 격리] 전자서명 검증 소프트웨어보다 서명키 생성·서명 수행 환경이 훨씬 취약함 → 나라면: 금융권 및 공공기관의 모든 코드 사이닝과 중요 전자계약 시스템에 대해 FIPS 140-2 Level 3 이상의 클라우드 HSM 또는 온프레미스 전용 보안 토큰 보관을 의무화하고, 서명 시마다 2차 생체 인증을 요구하도록 통제
