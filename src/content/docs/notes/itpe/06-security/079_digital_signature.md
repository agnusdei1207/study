## 지식 로드맵 내 현재 위치

정보보안 → 암호학 → 전자서명

## 30초 인출

- **본질:** 서명자의 개인키(비밀키)로 메시지 다이제스트를 암호화하여 서명을 생성하고, 대응하는 공개키로 무결성과 서명 주체를 검증하는 기술.
- **메커니즘:** 송신자가 원문 해시값을 개인키로 서명하여 원문과 함께 전달하면, 수신자가 송신자 공개키로 서명을 복호화하여 해시값 일치 여부를 검증.
- 통찰: 수학적 서명 검증뿐만 아니라 PKI 기반 인증서 유효성 확인과 HSM 기반 서명키 보호, 양자 내성 서명(ML-DSA/SLH-DSA)으로의 암호 민첩성 확보 필수.

<details><summary>핵심 용어</summary>

- **전자서명(Digital Signature)**: 비대칭키 암호화 메커니즘을 기반으로 송신자의 신원 확인, 위변조 탐지, 부인방지를 달성하는 암호화 기술.
- **메시지 다이제스트(Message Digest)**: 임의 길이의 평문을 일방향 해시 함수를 통해 고정 길이 비트열로 압축한 요약값.
- **서명 개인키(Signing Private Key)**: 오직 서명 주체만이 단독 통제해야 하는 기밀 키로 서명 생성에 활용.
- **서명 검증 공개키(Verification Public Key)**: 인증서(PKI) 체계를 통해 서명 주체의 신원과 공증 매핑되는 공개 키.
- **부인방지(Non-repudiation)**: 제3자에게 서명자의 서명 생성 사실을 수학적·기술적·법적으로 증명하여 송신 사실 부인을 방지하는 성질.
</details>

## 2~4교시 예상문제 (25점)

> 전자서명의 기본 원리와 생성·검증 메커니즘을 설명하고, 주요 알고리즘 계열(RSA, ECDSA/EdDSA, PQC 서명)의 기술적 특성 비교 및 실무 적용 시의 한계와 엔지니어링 방안을 제시하시오. (25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 서명자의 개인키로 해시값을 암호화해 생성하고, 대응 공개키로 검증하는 암호학적 인증 기술 |
| 목적 | 데이터 위변조 탐지(무결성), 발신자 신원 보증(인증), 사후 발송 부인 차단(부인방지) 달성 |

## Ⅱ. 전자서명의 핵심 특징 및 3대 보안 특성

| 특성 항목 | 세부 메커니즘 | 기술적 보장 가치 |
|---|---|---|
| 서명자 인증(Authentication) | 서명자의 개인키 소유자만이 유효 서명값 생성 가능 | 비인가 제3자의 서명 도용 및 스푸핑 차단 |
| 데이터 무결성(Integrity) | 원문 변경 시 해시값 불일치로 즉시 검증 실패 유발 | 전송 중 패킷 변조 및 주입 공격 탐지 |
| 부인방지(Non-repudiation) | 개인키가 공개키와 유일하게 수학적으로 쌍을 형성 | 서명자가 메시지 발송 사실을 사후 부인 불가 |
| 서명 변경 불가(Unreusability) | 메시지 다이제스트와 결합되어 타 문서로 전용 불가 | 기존 유효 서명을 다른 문서에 재사용하는 공격 방지 |
| 위조 불가(Unforgeability) | 개인키를 획득하지 못하는 한 위조 서명 생성 불가 | 암호학적 난치 문제(소인수분해, 이산대수 등) 기반 안전성 |

## Ⅲ. 전자서명 생성 및 검증 프로세스

```text
[ 송신자(서명 생성) ]                                  [ 수신자(서명 검증) ]
+------------------+                                  +------------------+
|      원문 M      | -------------------------------> |      원문 M      |
+------------------+                                  +------------------+
         |                                                      |
  [일방향 해시 H()]                                       [일방향 해시 H()]
         v                                                      v
  다이제스트 H(M)                                        다이제스트 H(M)'
         |                                                      |
   [서명 생성 알고리즘]                                         | (일치 비교)
         ^                                                      v
  송신자 개인키(SK)                                     +------------------+
         |                                       +----> | H(M) == H(M)' ?  |
         v                                       |      +------------------+
    전자서명 Sig = Sign(SK, H(M))                |         |            |
         |                                       |       [일치]       [불일치]
         +---------------------------------------+         |            |
                         전송                    |      검증 성공    검증 실패
                                                 |    (무결/인증)   (변조/위조)
                                                 v
                                        [서명 검증 알고리즘]
                                                 ^
                                        송신자 공개키(PK)
                                        (인증서 체인 검증)
```

| 단계 | 세부 절차 | 핵심 기술 및 프로토콜 |
|---|---|---|
| 해시 생성 | 송신자가 원문 전체를 일방향 암호학적 해시 함수에 입력하여 고정 길이 다이제스트 도출 | SHA-256, SHA-3, BLAKE3 적용 |
| 서명 생성 | 서명자의 개인키(Private Key)로 다이제스트를 암호화하거나 서명 방정식 연산 수행 | RSA-PSS, Ed25519, ECDSA 서명 생성 |
| 원문/서명 전송 | 원문 메시지와 전자서명값, 서명자의 인증서(X.509)를 패키징하여 수신자에게 전송 | CMS/PKCS#7, JSON Web Signature(JWS) |
| 서명 검증 | 수신자가 송신자의 공인인증서 유효성(CRL/OCSP) 확인 후 공개키로 서명값 복호화/검증 | X.509 Path Validation, OCSP Stapling |
| 무결성 대조 | 수신자가 원문을 직접 해시 연산한 값과 서명에서 복원된 해시값을 비트 단위로 대조 | 불일치 시 패킷 즉시 폐기 및 감사 로그 기록 |

## Ⅳ. 전자서명 주요 알고리즘 유형 비교

| 구분 | RSA-PSS | ECDSA / EdDSA | ML-DSA (CRYSTALS-Dilithium) |
|---|---|---|---|
| 수학적 기반 | 대형 소수 곱의 소인수분해 난치성 | 타원곡선 이산대수 문제(ECDLP) | 격자 기반 학습오차(LWE/MLWE) 난치성 |
| 표준 규격 | PKCS#1 v2.2, FIPS 186-5 | ANSI X9.62, RFC 8032 (Ed25519) | NIST FIPS 204 (PQC 디지털 서명) |
| 키 길이 (보안강도 128-bit) | 3,072 bits | 256 bits | 공개키 1,312 bytes / 개인키 2,528 bytes |
| 서명 데이터 크기 | 384 bytes | 64 bytes | 2,420 bytes |
| 연산 속도 | 서명 생성 보통, 서명 검증 매우 빠름 | 키 생성 및 서명 빠름, 검증 보통 | 격자 행렬 연산 기반 매우 빠른 서명/검증 |
| 양자컴퓨터 저항성 | Shor 알고리즘에 의해 취약 | Shor 알고리즘에 의해 취약 | 양자 컴퓨팅 공격에 안전(양자 내성) |
| 주 활용 분야 | 전통적 PKI, 레거시 웹/인증 체계 | FIDO2 Passkey, TLS 1.3, 블록체인 | 차세대 TLS 1.3, 국방/금융 차세대 인증 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| Shor 알고리즘 상용화 시 RSA/ECC 기반 서명의 일괄 위조 위협 | NIST FIPS 204 표준 격자 기반 ML-DSA 및 FIPS 205 SLH-DSA를 점진 도입하고, 하이브리드 서명(Ed25519+ML-DSA) 체계 구축 필수 |
| 엔드포인트 메모리 덤프 및 사이드채널 공격으로 서명 개인키 유출 | FIPS 140-3 Level 3 이상 인증 HSM, TPM 2.0 또는 Secure Enclave 내에 개인키를 격리하고 추출 불가(Non-exportable) 정책 강제 |
| 서명 검증 성공 시에도 서명 시점 및 인증서 폐기 여부의 시차(Time Window) 취약점 | RFC 3161 기반 공인 시점확인(Timestamping Authority) 토큰 결합 및 OCSP Stapling 기반 실시간 폐기 검증 의무화 |
| 사물인터넷(IoT) 및 마이크로서비스 대량 서명 검증 시 CPU 부하 및 지연 급증 | 서명 검증 가속 전용 하드웨어 가속기(Crypto Offloader) 탑재 및 Ed25519/BLS 배치 서명 검증(Batch Verification) 기법 도입 |

## Ⅵ. 제언

```text
[ 차세대 고신뢰 전자서명 아키텍처 모델 ]

+--------------------+      +--------------------+      +--------------------+
|  HSM / TEE 보관   | ---> |  하이브리드 서명   | ---> |  장기 검증(LTV)    |
| (개인키 탈출 방지) |      | (ECC + PQC 결합)   |      | (RFC 3161 + OCSP)  |
+--------------------+      +--------------------+      +--------------------+
```

| 추진 축 | 세부 구현 과제 | 기대 효과 |
|---|---|---|
| 키 보안 강화 | HSM 내부 서명 연산 처리 및 다자간 연산(MPC) 기반 서명키 분할 보관 | 단일 장애점(SPOF) 해소 및 키 유출 위험 원천 제거 |
| 양자 내성 전환 | FIPS 204 ML-DSA 알고리즘 표준 라이브러리 탑재 및 암호 민첩성(Crypto-Agility) 확보 | 양자 컴퓨터 도래 시 인증 체계 전면 붕괴 방지 |
| 장기 검증성(LTV) | PAdES/XAdES 기반 전자서명 장기 보존 형식 및 주기적 타임스탬프 재갱신 | 10년 이상 장기 보관 전자문서의 법적 증거력 영구 유지 |

## 출제 이력과 검증 출처

- 제126회 정보관리기술사 4교시 (전자서명 원리 및 PKI 체계 연계)
- 제118회 컴퓨터시스템응용기술사 2교시 (전자서명과 전자봉투 비교)
- NIST FIPS 186-5, Digital Signature Standard (DSS)
- NIST FIPS 204, Module-Lattice-Based Digital Signature Standard (ML-DSA)

- 전자봉투
