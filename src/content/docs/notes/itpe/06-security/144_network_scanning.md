## 한 줄 본질
- 네트워크 스캐닝은 패킷 송신과 응답 분석으로 호스트·포트·서비스 상태를 파악하는 활동. 보안 점검과 공격 준비 양쪽에 쓰임

## 10점 답안
네트워크 스캐닝은 대상 네트워크의 활성 호스트, 열린 포트, 서비스 정보를 조사하는 기법. 호스트 발견, TCP·UDP 포트 상태 판별, 서비스·버전 식별 순서로 수행 가능. TCP connect 스캔은 연결을 완성하고 SYN 스캔은 보통 완전 연결 전에 응답으로 상태를 판단. SYN 스캔도 방화벽·IDS에 탐지·기록될 수 있음. 방어자는 승인된 자산 범위 정기 점검, 불필요한 포트 폐쇄, 관리 포트 접근 제한, 네트워크 탐지·로그 연계 수행.

## 25점 답안
### Ⅰ. 목적과 단계
자산 발견 → 포트 상태 확인 → 서비스 식별 → 노출의 업무 필요성 및 취약점 검토. 스캔 결과는 관찰 지점·방화벽 규칙·패킷 손실에 따라 달라짐.

### Ⅱ. 기법 비교
| 기법 | 판단 원리 | 한계 |
|---|---|---|
| TCP connect | OS의 완전 연결 시도 | 서비스 로그가 남을 가능성 |
| TCP SYN | SYN/ACK는 열림, RST는 닫힘, 무응답 등은 필터링 가능성 | 연결 미완료가 탐지 회피를 보장하지 않음 |
| UDP | 응답 또는 ICMP 오류 관찰 | 무응답은 열림과 필터링 구분 어려움 |
| FIN/NULL/Xmas | 비정상 플래그에 대한 구현별 반응 이용 | OS·방화벽 차이로 판별 제한 |

### Ⅲ. 방어·운영
승인된 대상·시간·강도로 주기적 자체 스캔. 노출 서비스 제거·패치, SSH/RDP 등 관리 접속 통제, 스캔 경보와 자산 대장 연계. 포트 번호 변경이나 배너 숨김은 보조 수단이며 실제 노출 제거 대책을 대신하지 못함.
