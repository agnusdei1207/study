## 지식 로드맵 내 현재 위치

지식 위치: 정보보안 → 네트워크 노출 점검 → **네트워크 스캐닝**

## 30초 인출

- **본질:** 네트워크 상의 활성 호스트, 열린 포트(Open Port), 구동 중인 네트워크 서비스 및 운영체제 종류를 식별하기 위해 조작된 패킷을 송수신하여 응답을 분석하는 정보 수집 활동
- **메커니즘:** 호스트 발견(Ping/ARP) $\rightarrow$ 포트 상태 판별(TCP SYN/Connect/스텔스) $\rightarrow$ 서비스 버전 및 OS 핑거프린팅 $\rightarrow$ 취약점 스캔 연계
- **통찰:** 방화벽 필터링에 의한 모호성은 ACK 스캔과 크리덴셜 진단으로 극복하고 미인가 포트 노출은 포트 노킹과 SDP 기반 제로 노출(Default Drop)로 원천 차단 필수

<details>
<summary>핵심 용어</summary>

- **Port Scanning** : 대상 IP의 특정 포트(0~65535)가 활성화되어 연결을 수락하는지 확인하는 기법.
- **TCP SYN Scan (Half-Open)** : 완전한 3-Way Handshake를 맺지 않고 SYN/ACK 응답 확인 즉시 RST를 전송하여 로그를 최소화하는 스캔.
- **Stealth Scan** : FIN, NULL, Xmas 등 비정상 플래그 패킷을 전송하여 방화벽 및 로깅 시스템을 우회하는 스캔.
- **OS Fingerprinting** : TCP 윈도우 크기, TTL, DF 플래그 등 OS별 프로토콜 스택 구현 차이를 분석해 운영체제를 판별하는 기술.

</details>

## 2~4교시 예상문제 (25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 공격자 또는 보안 진단자가 대상 시스템의 IP 대역에 패킷을 전송하고 반환되는 응답 패킷의 TCP 플래그 및 ICMP 에러 코드를 분석하여 활성 호스트, 개방 포트, 구동 서비스 목록을 파악하는 정찰 활동 |
| 목적 | 시스템의 외부 공격 표면(Attack Surface)을 사전에 파악하여 불필요한 포트를 차단하고, 알려진 서비스 취약점에 대한 침투 경로를 식별하여 보안 선제 조치 |

- 사이버 킬체인의 첫 단계인 정찰(Reconnaissance)의 핵심 기법으로, 침투 테스트 및 자산 인벤토리 관리를 위한 필수적인 보안 검증 메커니즘

## Ⅱ. 네트워크 스캐닝의 핵심 기술적 특성

| 특성 항목 | 세부 내용 및 기술적 의미 | 엔지니어링 구현 가치 |
|---|---|---|
| 프로토콜 규격(RFC 793) 역이용 | 정상 연결 외에 비정상 플래그 조합에 대한 표준 응답 규격을 역이용하여 포트 상태 추정 | 방화벽이나 로깅 시스템을 우회하는 스텔스 정찰 가능 |
| 비침해적 빠른 표면 식별 | 대규모 서브넷(/24, /16)의 수천 개 호스트 상태를 수 초~수 분 내 초고속 비동기 스캔 | 기업 전사 외부 노출 자산의 실시간 가시성 확보 |
| 패킷 수준 정밀 핑거프린팅 | 초기 SYN 패킷의 TCP Window Size, IP TTL, DF 비트 등 세부 필드 값의 편차 분석 | 배너 숨김 처리된 서버라도 기저 OS(Linux, Windows) 판별 가능 |
| 관찰 관점에 따른 가변성 | 스캐너가 위치한 네트워크 위치(외부 인터넷, DMZ, 내부망)에 따라 방화벽 룰로 결과 상이 | 내·외부 다각도 스캔을 통한 심층 방어 검증 필요 |

- 네트워크 스위치와 호스트에 대량의 비정상 트래픽 부하를 유발할 수 있으므로 속도 및 타이밍 제어가 중요한 운영 특성 보유

## Ⅲ. 네트워크 스캐닝 3단계 프로세스 및 TCP SYN 스캔 메커니즘

```text
[네트워크 스캐닝 3단계 절차 및 TCP SYN (Half-Open) 스캔 메커니즘]

 [1단계: 호스트 발견]   ===>   [2단계: 포트 스캐닝]   ===>   [3단계: 서비스/OS 식별]
 (ARP / ICMP Echo)             (TCP SYN / Connect)            (배너 그래빙 / TTL 분석)

 [TCP SYN (Half-Open) 스캔 흐름]
  [스캐너 (Attacker)]                         [대상 서버 (Target)]
          │                                             │
          │ 1. TCP SYN (Port 80)                        │
          ├────────────────────────────────────────────>│ (포트 Open 상태)
          │ 2. TCP SYN/ACK                              │
          │<────────────────────────────────────────────┤
          │ 3. TCP RST (강제 종료: Handshake 미완료)     │
          ├────────────────────────────────────────────>│ (연결 수립 안 됨 -> 애플리케이션 로그 미생성)
          │                                             │
          │ 4. TCP SYN (Port 81)                        │
          ├────────────────────────────────────────────>│ (포트 Closed 상태)
          │ 5. TCP RST/ACK                              │
          │<────────────────────────────────────────────┤ (포트 닫힘 확인)
```

| 스캔 단계 | 핵심 수행 활동 | 사용하는 프로토콜 및 도구 |
|---|---|---|
| 1. 호스트 발견 (Host Discovery) | 대상 서브넷 대역 내에서 실제로 전원이 켜져 있고 통신 가능한 활성 IP 식별 | ARP Request (로컬 LAN), ICMP Echo, TCP SYN Ping |
| 2. 포트 스캐닝 (Port Scanning) | 식별된 활성 호스트의 1~65535 포트에 패킷을 보내 Open, Closed, Filtered 상태 판별 | Nmap (TCP SYN `-sS`, Connect `-sT`, UDP `-sU`) |
| 3. 서비스 및 OS 식별 | 열린 포트에 특정 프로토콜 페이로드를 보내 반환되는 배너 텍스트 및 TCP 파라미터 대조 | Nmap Version Detection (`-sV`), OS Detection (`-O`) |

## Ⅳ. 주요 포트 스캔 방식별 동작 원리 및 응답 비교

| 스캔 유형 | 송신 패킷 | 포트 Open 시 응답 | 포트 Closed 시 응답 | 방화벽 Filtered 시 응답 | 특징 및 로그 생성 여부 |
|---|---|---|---|---|---|
| TCP Connect (`-sT`) | TCP SYN | SYN/ACK (이후 ACK 전송) | RST/ACK | 무응답 또는 ICMP 필터 에러 | 완전 연결 수립, 서버 앱에 완전한 연결 로그 남음 |
| TCP SYN (`-sS`) | TCP SYN | SYN/ACK (이후 RST 전송) | RST/ACK | 무응답 또는 ICMP 필터 에러 | Half-Open 스캔, 애플리케이션 로그 회피, 루트 권한 필요 |
| TCP FIN (`-sF`) | TCP FIN | 무응답 (Drop) | RST/ACK | 무응답 (Drop) | RFC 793 준수 OS에서 동작, 윈도우 OS는 무조건 RST 응답 |
| TCP NULL (`-sN`) | 플래그 없음 | 무응답 (Drop) | RST/ACK | 무응답 (Drop) | 비정상 플래그 스텔스 스캔, 방화벽 통과 시도 |
| TCP Xmas (`-sX`) | FIN, PSH, URG | 무응답 (Drop) | RST/ACK | 무응답 (Drop) | 패킷에 불이 켜진 크리스마스 트리 형상에서 유래 |
| UDP Scan (`-sU`) | 빈 UDP 패킷 | UDP 응답 또는 무응답 | ICMP Port Unreachable | 무응답 또는 ICMP 필터 에러 | 무응답 시 Open과 Filtered 구분 모호, 속도 매우 느림 |

## Ⅴ. 네트워크 스캐닝 방어 시 엔지니어링 한계와 해결 방안

| 한계 | 방안 |
|---|---|
| 상태 기반 방화벽(Stateful Inspection)이 비정상 플래그(FIN/NULL/Xmas)를 차단하여 포트가 실제로 열렸는지 방화벽에 막혔는지 구별 불가(Filtered 모호성) | 방화벽 필터링 규칙 자체를 매핑하기 위해 TCP ACK 스캔(`-sA`: 비필터링 시 RST 수신)을 병행하고, 내부 에이전트 기반 크리덴셜 취약점 진단(Authenticated Scan)으로 사각지대 해소 |
| 스캐닝 속도를 올릴 경우 IDS/IPS의 포트 스캔 임계치(Threshold) 탐지 룰에 의해 스캐너 IP가 즉시 자동차단(Drop)되어 진단 중단 | 전송 지연 시간을 무작위화하는 타이밍 템플릿(T2/Polite)을 적용하고, 패킷을 여러 개로 쪼개는 IP 단편화(Fragmentation: `-f`) 및 다중 가짜 IP를 섞는 데코이(Decoy: `-D`) 기법 적용 |
| 공격자가 Shodan, Censys 등 인터넷 전수 스캐닝 검색엔진의 캐시 DB를 활용하여 대상 시스템에 단 한 번의 패킷도 보내지 않고 노출 자산 정찰(Passive Recon) | 공격 표면 관리(ASM: Attack Surface Management) 솔루션을 도입하여 Shodan API를 역조회해 사내 자산의 무단 외부 노출을 실시간 모니터링하고 공인 IP 즉시 격리 |
| 열린 포트가 외부 인터넷에 항상 노출되어 있어 제로데이 취약점 발생 시 원격 공격자의 즉각적인 표적 공격 대상 노출 | 포트 노킹(Port Knocking) 또는 제로 트러스트 소프트웨어 정의 경계(SDP)를 도입하여, 사전에 상호 mTLS 인증을 거친 인가된 사용자 단말에만 방화벽 포트를 동적으로 개방(Default Closed/Drop) |

```text
[공격 표면 축소(ASM) 및 제로 트러스트 스텔스 네트워크 아키텍처]

 ┌─────────────────────────────────────────────────────────────┐
 │                 1. 외부 노출 차단 계층 (Dark Network)        │
 │   - 포트 전면 비노출 (Default Drop / Silent Discard)        │
 │   - SDP (소프트웨어 정의 경계) 기반 인가 전 포트 완전 은닉  │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │              2. 능동형 교란 및 탐지 계층 (Deception)        │

 │   - Shodan / Censys 위협 인텔리전스 API 연동 모니터링        │
 └─────────────────────────────────────────────────────────────┘
```

| 관리 영역 | 핵심 엔지니어링 세부 과제 | 통제 목표치 |
|---|---|---|
| 공격 표면 식별 | 전사 공인 대역 대상 자동화 포트 스캔 및 자산 대장 대조 | 미인가 개방 포트 탐지율 100% |
| 스텔스 방어 | 불필요한 관리 포트(SSH 22, RDP 3389) 외부 노출 원천 차단 | 공인 관리 포트 노출 건수 0건 |
| 스캔 탐지 대응 | 비정상 포트 스캐닝 시도 IP의 방화벽 블랙리스트 자동 등록 | 스캔 탐지 후 IP 자동 차단 소요 시간 < 5초 |
