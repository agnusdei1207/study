## 연관 키워드

- NFT(Non-Fungible Token), 스마트 컨트랙트(Smart Contract), 재진입 공격(Reentrancy), 서명 재생(Signature Replay)
- EIP-712, SetApprovalForAll, 메타데이터 교체 사기(Rug Pull), 형식 검증(Formal Verification)
- 다중서명(Multi-sig), 타임락(Timelock), 서킷 브레이커(Circuit Breaker), 트래블룰(Travel Rule)

## Ⅰ. NFT 마켓플레이스 보안의 개요

- 핵심 요약 : 블록체인에서 NFT를 발행하고 거래하는 플랫폼을 스마트 컨트랙트, 메타데이터, 지갑 서명 흐름 전반에서 방어하는 보안 체계.
- 개념 : 대체 불가능 토큰 **NFT** (Non-Fungible Token, 고유성을 가진 블록체인 토큰)를 발행, 거래, 보관하는 플랫폼에서 **스마트 컨트랙트** (Smart Contract, 블록체인에 배포되는 자동 실행 코드)의 결함, 메타데이터 변조, 웹 피싱, 비정상 거래를 막는 보안 활동.
- 배경 및 필요성 : NFT 시장으로 자본이 빠르게 유입되면서 컨트랙트 취약점 악용, 메신저와 웹 사이트를 통한 피싱, 자전거래(Wash Trading) 같은 사기가 반복적으로 보고되어 보안 체계의 필요성이 커짐.
- 주요 목적 : 컨트랙트 무결성과 자산 안전성 보장, 메타데이터 불변성 유지, 사용자 지갑 서명 과정 보호, 자금세탁 방지(AML, Anti-Money Laundering) 대응.

## Ⅱ. NFT 마켓플레이스 보안의 특징 및 장점

- 핵심 요약 : 비수탁 지갑과 온체인 불변성이 사용자 통제권과 감사 신뢰를 주는 대신, 실수 한 번이 되돌릴 수 없는 손실로 이어지는 구조.

1. 비수탁형 지갑 (Non-custodial Wallet) : 개인키를 사용자가 직접 보관 → 플랫폼이 침해되어도 자산 통제가 분산됨. 대신 잘못된 서명 한 번으로 자산이 즉시 빠질 수 있음.
2. 온체인 불변성 : 배포된 컨트랙트와 거래 기록이 변경되지 않음 → 감사와 이력 검증이 쉬움. 대신 발견된 취약점을 사후에 고칠 수 없음.
3. **오프체인 서명** (EIP-712, Ethereum Improvement Proposal 712, 구조화된 데이터에 서명하는 표준) : 주문을 서명만으로 제출해 가스비를 줄임 → 서명 재생과 도메인 혼동을 막는 설계가 필수.

## Ⅲ. NFT 마켓플레이스 보안의 구조 (흐름)

- 핵심 요약 : 사용자 지갑, 오프체인 메타데이터, 온체인 컨트랙트의 세 계층이 신뢰를 나누어 가지며, 각 계층마다 다른 공격이 발생하는 구조.
- 오프체인 메타데이터는 **IPFS** (InterPlanetary File System, 콘텐츠 주소 기반 분산 파일 저장)나 **Arweave** (영구 저장을 목표로 하는 분산 저장소)에 두는 경우가 많음.

```text
[ 3계층 신뢰 모델 ]

사용자 (Web3 지갑)
      ↓
프론트엔드 계층 (피싱, 승인 요청 위험)
      ↓
오프체인 메타데이터 (IPFS, Arweave)
      ↓
온체인 스마트 컨트랙트 (재진입, 서명 재생)
```

```text
[ EIP-712 주문 서명 흐름 ]

사용자 주문 데이터
      ↓ 도메인 분리기와 논스 포함 서명
오프체인 오더북 제출
      ↓ 컨트랙트에서 서명 검증
논스 소모 후 거래 체결
```

## Ⅳ. NFT 마켓플레이스 보안의 비교

- 핵심 요약 : 전통 이커머스와 중앙화 거래소는 운영 주체가 사고를 되돌릴 수 있지만, 탈중앙 마켓플레이스는 기술적 불변성 때문에 예방 중심으로 설계해야 함.

| 비교 항목 | 전통 이커머스 | 중앙화 거래소(CEX, Centralized Exchange) | 탈중앙 NFT 마켓플레이스 |
| --- | --- | --- | --- |
| 자산 통제권 | 플랫폼 데이터베이스의 계정 잔고 | 거래소의 중앙 지갑 보관 | 사용자의 비수탁 지갑 |
| 주요 침해 지점 | 웹 애플리케이션 취약점, 결제 연동 | 내부자 횡령, 키 탈취, API(Application Programming Interface) 악용 | 스마트 컨트랙트 결함, 악성 승인 서명 |
| 거래 취소·복구 | 관리자 롤백과 환불 가능 | 내부 기록 기반 취소 가능 | 블록체인 불변성으로 원천 복구 어려움 |
| 메타데이터 저장 | 내부 데이터베이스와 CDN(Content Delivery Network) | 중앙화 저장소 | 분산 저장소(IPFS, Arweave) |

- 선택 기준 : 자산 보관 주체가 사용자인지 플랫폼인지에 따라 보안 책임의 무게가 달라지므로, 사고 대응 설계의 출발점을 이 기준으로 정함.
- 탈중앙 구조에서는 배포 전 **형식 검증** (Formal Verification, 수학적 명세에 따라 컨트랙트 성질을 증명하는 기법)이 사실상 필수 절차가 됨.

## Ⅴ. NFT 마켓플레이스 보안의 한계와 방안

- 핵심 요약 : 과도한 승인 권한, 교체 가능한 메타데이터, 가스 최적화에 따른 검증 누락을 승인 설계, 콘텐츠 주소 지정, 정적 분석과 형식 검증으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **SetApprovalForAll** 권한 남용 | 피싱 UI에서 전체 NFT 전송 권한을 위임하면 보유 자산 전체가 탈취될 수 있음 | 단일 토큰 지정 승인과 기간 제한 승인 방식 적용, 트랜잭션 시뮬레이션 도구 연동 | 잔존 전체 승인 건수 |
| **메타데이터 교체 사기** (Rug Pull) | `tokenURI`가 일반 웹 서버를 가리키면 운영자가 이미지와 JSON(JavaScript Object Notation) 메타데이터를 임의로 바꿀 수 있음 | IPFS CID(Content Identifier)처럼 콘텐츠 해시를 기준으로 고정하고 메타데이터 동결 함수 제공 | 변경 가능한 메타데이터 비율 |
| 가스 최적화에 따른 검증 누락 | 비용을 줄이려 접근 통제 로직을 생략하거나 복잡하게 패킹하면서 권한 검증이 빠짐 | 정적 분석 도구(Slither)와 형식 검증 도구(Certora Prover) 적용, 외부 감사 보고서 공개 | 감사 지적 사항 해소 기간 |

## Ⅵ. NFT 마켓플레이스 보안에 대한 기술사적 제언

- 핵심 요약 : 권한의 분산, 이상 거래의 자동 차단, 규제 준수 절차를 함께 설계해 운영 단계의 사고 피해를 줄이는 방향.

컨트랙트 업그레이드와 수수료 등 파라미터 변경 권한을 단일 개인키에 두지 않고, 다중서명과 타임락으로 나누어 통제하는 것이 기본 원칙이다.

대량 출금이나 거래량이 비정상적으로 늘어나면 컨트랙트를 자동으로 일시 정지하는 **서킷 브레이커** (Circuit Breaker) 기능을 두고, 온체인 이상 거래 탐지 기준을 사전에 정해 두어야 한다.

가상자산 이용자 보호와 자금세탁 방지 규정을 지키기 위해, 블록체인 분석 도구로 제재 대상 지갑과의 거래를 사전에 걸러내는 **트래블룰** (Travel Rule) 대응 절차를 마련하는 것이 필요하다.

## Ⅶ. 결론

- 핵심 요약 : NFT 마켓플레이스 보안은 블록체인의 불변성을 전제로, 사고를 되돌리기 어려운 만큼 배포 전 검증과 권한 설계에 무게를 두는 체계.
- 시사점 : 사용자 지갑과 컨트랙트 양쪽의 단일 실수가 곧 자산 손실로 이어지므로, 예방 통제의 완성도가 신뢰를 결정함.
