## 지식 로드맵 내 현재 위치

디지털 자산 보안 → 블록체인 응용서비스 → NFT 마켓플레이스 및 스마트 컨트랙트 보안

## 30초 인출

- **본질:** 온체인 스마트 컨트랙트와 오프체인 메타데이터, 사용자 지갑 및 마켓 웹 프론트엔드가 결합된 복합 생태계의 자산 보호 아키텍처
- **메커니즘:** EIP-712 오프체인 서명 검증, ERC-721/1155 권한 통제, IPFS 기반 불변 콘텐츠 식별을 통한 소유권 및 거래 무결성 보장
- 통찰: 무제한 승인(setApprovalForAll) 탈취와 중앙화된 Web2 URL 메타데이터 위변조를 방지하기 위해 계정 추상화 기반 가디언 다중서명과 IPFS CID 영구 스토리지 바인딩 필수

<details>
<summary>핵심 용어</summary>

- **ERC-721 / ERC-1155:** 이더리움 블록체인 상의 대체 불가능 토큰(단일 발행) 및 멀티토큰(대량 발행) 표준 인터페이스
- **EIP-712:** 지갑 서명 시 사람이 읽을 수 있는 구조화된 데이터(도메인, 가격, 만료 시각)를 표시하여 블라인드 서명을 방지하는 표준
- **setApprovalForAll:** 마켓플레이스 컨트랙트에 특정 컬렉션 내 보유자의 모든 토큰 전송 권한을 일괄 위임하는 고위험 인터페이스
- **IPFS CID (Content Identifier):** 콘텐츠의 암호학적 해시값을 기반으로 주소를 지정하여 데이터 위변조를 원천 차단하는 탈중앙 분산 스토리지 식별자
</details>

## 2~4교시 예상문제 (25점)

> NFT(Non-Fungible Token) 마켓플레이스의 온체인·오프체인 아키텍처와 주요 공격 벡터(Blind Signing, 스마트 컨트랙트 취약점, 메타데이터 위변조)를 설명하고, 사용자 자산 보호를 위한 다계층 보안 통제 및 엔지니어링 방안을 제시하시오. (예상·25점)

---
## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **NFT 마켓플레이스 보안** 은 블록체인 온체인 상의 스마트 컨트랙트(ERC-721/1155), 오프체인 분산 스토리지(IPFS), 웹 애플리케이션 및 사용자 지갑(Web3 Wallet) 간의 상호작용 전반을 보호하는 종합 정보보안 체계 |
| 목적 | 사용자 개인키 및 자산 탈취 방지, 악성 오프체인 서명 방어, 스마트 컨트랙트 취약점(재진입 등) 익스플로잇 차단 및 메타데이터 무결성 확보 |

기존 웹 보안 취약점(XSS, CSRF)과 블록체인 특유의 비가역적 금융 거래 취약점이 융합된 고도화된 위협 영역.

## Ⅱ. NFT 마켓플레이스 보안의 특징

| 특징 | 설명 | 보안 아키텍처 요구사항 |
|---|---|---|
| **온·오프체인 결합성** | 토큰 소유권은 온체인에, 실제 이미지·동영상은 오프체인에 분리 저장 | 블록체인 상태와 외부 스토리지(IPFS) 간의 엄격한 해시 바인딩 |
| **거래의 비가역성** | 스마트 컨트랙트 실행 및 트랜잭션 블록 확정 후 롤백 불가능 | 오프체인 서명 시 사전 시뮬레이션 및 권한 범위 정밀 검증 |
| **블라인드 서명 취약성** | 바이트코드 수준의 해시 서명 시 사용자가 실제 전송 자산을 인지 불가 | EIP-712 기반의 사람이 판독 가능한 구조화된 서명 데이터 렌더링 |
| **외부 의존성** | 탈중앙 오라클(Oracle), 분산 스토리지 노드 가용성에 의존 | 오프라인 캐싱 및 신뢰성 높은 탈중앙 게이트웨이 다중화 |

## Ⅲ. NFT 마켓플레이스 아키텍처 및 위협 메커니즘

```text
[NFT 마켓플레이스 4대 계층별 상호작용 및 주요 공격 벡터]

 +---------------------------------------------------------------+
 | 1. 클라이언트/지갑 계층                                        |
 |    - 사용자 지갑 (MetaMask) <--- 피싱 사이트, 악성 서명 유도    |
 |    - Seaport / EIP-712 구조화된 오프체인 서명 생성             |
 +-------------------------------+-------------------------------+
                                 | (오프체인 오더북 전달)
 +-------------------------------v-------------------------------+
 | 2. 마켓플레이스 웹 백엔드 (Web2)                                |
 |    - 주문 매칭 엔진, REST/GraphQL API                         |
 |    - API 인젝션, CSRF 공격, 프론트엔드 DNS 하이재킹 위험      |
 +-------------------------------+-------------------------------+
                                 | (트랜잭션 실행 트랜잭터 브로드캐스트)
 +-------------------------------v-------------------------------+
 | 3. 온체인 스마트 컨트랙트 (Web3)                               |
 |    - ERC-721/1155 토큰 컨트랙트, 마켓플레이스 코어 컨트랙트   |
 |    - 재진입 공격(Reentrancy), setApprovalForAll 오남용        |
 +-------------------------------+-------------------------------+
                                 | (TokenURI 역참조)
 +-------------------------------v-------------------------------+
 | 4. 오프체인 메타데이터 스토리지                                |
 |    - IPFS / Arweave / 중앙화 AWS S3                           |
 |    - Rug Pull (중앙화 URL 교체), 링크 로트(Link Rot) 위험      |
 +---------------------------------------------------------------+
```

### 1. 주요 계층별 상세 공격 벡터 및 대응 메커니즘

| 계층 | 주요 공격 기법 (Attack Vector) | 기술적 동작 메커니즘 및 완화 방안 |
|---|---|---|
| **지갑/서명** | **Ice Phishing & Malicious Permit** | 가짜 에어드롭 사이트에서 `setApprovalForAll` 또는 `Permit2` 서명을 유도하여 공격자 지갑으로 일괄 이체. 트랜잭션 시뮬레이션(Tenderly)으로 차단 |
| **온체인 계약** | **재진입 공격 (Reentrancy)** | 외부 토큰 수신 함수(`onERC721Received`) 콜백을 악용하여 상태 갱신 전 출금 함수를 재귀 호출. Checks-Effects-Interactions 패턴 및 ReentrancyGuard 적용 |
| **오프체인** | **메타데이터 러그풀 (Rug Pull)** | 스마트 컨트랙트의 `tokenURI`가 일반 HTTPS URL일 경우, 서버 관리자가 이미지를 변경하거나 서버 폐쇄. IPFS 불변 CID 및 Pinning 서비스 의무화 |

## Ⅳ. 온체인 vs 오프체인 보안 영역 비교

| 비교 항목 | 온체인 (On-chain) 영역 | 오프체인 (Off-chain) 영역 |
|---|---|---|
| **대상 구성요소** | 스마트 컨트랙트, 토큰 원장, 트랜잭션 | 웹 서버, 오더북 DB, IPFS/S3 메타데이터 |
| **신뢰 모델** | 분산 합의 및 암호학적 검증 (Trustless) | 웹 애플리케이션 및 스토리지 운영자 신뢰 |
| **수정 가능성** | 불변(Immutable), 하드포크 없이 수정 불가 | 패치, 메타데이터 업데이트, DB 수정 용이 |
| **주요 위협** | 재진입, 정수 오버플로, 권한 체크 우회 | API 침해, 프론트엔드 악성 스크립트 주입, DNS 변조 |
| **방어 기술** | 정적 분석(Slither), 정형 검증, 다중서명 | WAF, DDoS 방어, CSP(콘텐츠 보안 정책), IPFS Pinning |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **setApprovalForAll 무제한 권한 위임에 의한 지갑 드레인(Drain)**<br>마켓플레이스 편의를 위해 단 1회 서명으로 전체 컬렉션의 처분권을 위임한 후, 서명 탈취 피싱에 걸릴 경우 지갑 내 전 자산이 즉시 도난당하는 취약성 | **ERC-4337 계정 추상화 기반 세션 키 및 최소 권한 Permit**<br>특정 단일 토큰 및 제한된 시간(TTL) 동안만 유효한 개별 승인(`approve`) 또는 지갑 내 스마트 컨트랙트 계정(ERC-4337)의 세션 키를 활용하고, Revoke.cash 자동 연동을 통한 유휴 권한 즉시 회수 체계 구현 |
| **중앙화 Web2 저장소 사용에 따른 메타데이터 변조 및 링크 로트(Link Rot)**<br>비용 절감을 위해 AWS S3 등 중앙화 HTTP 주소로 `tokenURI`를 지정한 경우, 도메인 만료 시 데이터가 소실되거나 공격자에 의해 악성 이미지로 변조 | **Arweave 영구 저장소 및 IPFS 멀티해시 온체인 하드 바인딩**<br>한 번 저장하면 영구 보존이 수학적으로 보장되는 Arweave(Permaweb)를 채택하고, 컨트랙트 민팅 시 메타데이터 해시값을 온체인 이벤트 로그에 영구 불변 각인하여 위변조 탐지 |

## Ⅵ. 제언

```text
[NFT 엔터프라이즈 마켓플레이스 심층 방어 체계]

 +--------------------+     +---------------------+     +--------------------+
 | 스마트 컨트랙트    | --> | 웹 프론트엔드 방어  | --> | 지갑 거래 시뮬레이션|
 | 정형 검증/감사 완료 |     | CSP / DNSSEC / WAF  |     | 사전 자산 변동 경고 |
 +--------------------+     +---------------------+     +--------------------+
```

| 계층별 방어 전략 | 권장 기술 스택 | 적용 목적 |
|---|---|---|
| **스마트 컨트랙트 검증** | Slither, Mythril, Certora 정형 검증 | 배포 전 스마트 컨트랙트 100% 결함 제거 |
| **서명 투명성 확보** | EIP-712 표준 채택, Blowfish/PocketUniverse | 사용자 서명 시 이동되는 자산 내역 사전 시각화 |
| **오프체인 데이터 보존** | Pinata IPFS 클러스터, Arweave 분산망 | 메타데이터 영구성 및 무결성 100% 보증 |

NFT 마켓플레이스는 블록체인 코드의 무결성뿐만 아니라 최종 사용자가 승인하는 서명의 가시성을 보장하는 다계층 제로트러스트 트랜잭션 보안 체계 확립 권장.
