- **NFT 마켓플레이스 보안:** 토큰·거래·지갑·외부 메타데이터가 맞물린 거래 서비스의 위협을 통제하는 보안 설계
- **NFT (Non-Fungible Token):** 계약과 토큰 식별자로 구별되는 대체 불가능 토큰

- **EIP-712 (Typed structured data hashing and signing):** 구조화된 데이터를 해시·서명할 때 도메인 정보를 포함하는 표준; 재전송 방지는 별도 설계
- **재진입 공격:** 외부 호출 중 원래 계약 함수에 다시 진입해 상태 검증을 우회할 수 있는 취약점 악용

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **NFT 마켓플레이스 보안**은 토큰·거래·지갑·외부 메타데이터의 신뢰성을 함께 지키는 보안 설계 |
| 목적 | 무단 자산이전·서명 오용·메타데이터 위변조 위험의 통제 |

토큰 소유상태와 외부 콘텐츠의 지속성·저작권 등 권리는 별도 확인 대상.

## Ⅱ. 온체인·오프체인 구성

| 영역 | 정보·기능 | 보안 책임 |
|---|---|---|
| 사용자·지갑 | 계정·키·거래 서명 | 키 보호·서명내용 확인·피싱 대응 |
| 마켓 서비스 | 목록·주문·API·사용자 화면 | 인증·권한·입력·업데이트 관리 |
| 온체인 계약 | 토큰 소유권·승인·거래 상태 | 코드·권한·상태전이 검증 |
| 오프체인 URI·데이터 | 토큰 메타데이터·미디어 | 출처·무결성·가용성·변경관리 |

```text
사용자·지갑 ── 거래요청·서명 ── 마켓 서비스
                                 │ 계약 호출
                                 ↓
                         온체인 스마트 계약
                                 │ URI 참조
                                 ↓
                       오프체인 메타데이터
```

## Ⅲ. 발행·거래 흐름과 검증점

```text
메타데이터 준비·URI 연결
             ↓ 민팅 요청·서명
계약의 토큰·권한 검증
             ↓ 소유·거래 상태 변경
마켓 표시·정산 처리
             ↓
URI 해석·콘텐츠 조회
```

| 흐름 단계 | 검증 사항 |
|---|---|
| 민팅 | 발행 권한·토큰 식별자·URI 지정의 적정성 |
| 서명·주문 | 체인·계약·자산·가격·수수료·만료·nonce 등 서명 맥락 확인 |
| 체결 | 소유자·승인·잔액·상태전이 검증 및 재진입 등 계약 취약점 점검 |
| 메타데이터 조회 | URI의 변경정책·콘텐츠 무결성·저장소 가용성 확인 |

EIP-712 서명은 구조화된 데이터와 도메인 구분에 도움을 주지만 재전송 방지는 별도 nonce·만료·사용상태 통제 필요.

## Ⅳ. 위협과 보안 통제

| 위협 | 영향 | 통제 |
|---|---|---|
| 악성 서명·피싱 | 승인 범위를 넘어선 자산이전 | 읽기 쉬운 거래정보 표시, 도메인 확인, 승인권한 정기 정리 |
| 계약 취약점·권한 오설정 | 무단 발행·이전·자금 손실 | 코드검토·테스트·외부 호출·관리자 권한 검증 |
| 주문 재사용·재전송 | 의도치 않은 거래 성립 | nonce·만료·체인·계약 도메인 바인딩 검사 |
| URI·저장소 조작·장애 | 자산 표시정보 변경·미디어 접근 실패 | 변경권한 관리, 콘텐츠 식별·검증, 복수 보존·복구계획 |
| 운영계정·API 침해 | 목록·정산·관리기능 악용 | 최소권한·비밀정보 보호·감사로그·이상거래 탐지 |

## Ⅴ. 개발·운영 생애주기

| 시점 | 통제 활동 |
|---|---|
| 설계 | 온·오프체인 경계·권한·업데이트 가능성과 자산모델 정의 |
| 개발·검증 | 정적·동적 분석, 단위·통합·권한·예외 시나리오 시험 |
| 배포 | 소스·빌드 산출물·배포주소 확인, 관리자 키·긴급중지 기능 보호 |
| 운영 | 계약·API·지갑 이상징후, URI 변경, 업데이트·사고 이력 감시 |

## Ⅵ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 토큰 발행·거래 성공만 확인하면 연결된 콘텐츠와 서명 의도까지 보장된다고 오해 | 토큰 상태·서명 맥락·외부 콘텐츠 식별자를 묶어 거래 전후 검증하고, 메타데이터 보존·변경책임을 운영계약에 반영 |
