## 지식 로드맵 내 현재 위치

AI 보안 → 개발 업무의 LLM 사용 → 데이터·지시·코드 위험

## 30초 인출

- 본질: 개발 업무에 LLM을 도입할 때는 입력 데이터 유출, 프롬프트 인젝션, 취약 코드 반영 위험을 평가해야 함
- 메커니즘: 데이터 분류·입력 제한 → 문서와 명령의 신뢰 경계 분리 → 생성 코드 리뷰·테스트·의존성 검증
- 통찰: 한계: 생산성 도구의 출력·검색 문서를 그대로 신뢰하면 기밀 유출과 취약 코드가 반영됨 → 방안: 입력 제한·도구 최소권한·코드 검증을 분리해 적용

---

<details><summary>핵심 용어</summary>

- 프롬프트 인젝션: 불신 콘텐츠의 지시가 모델 행동에 영향을 주는 공격.
- SAST: 소스코드에서 취약 패턴을 찾는 정적 분석.

</details>

## 2~4교시 예상문제 (25점)

> AI 기반 SW 개발에서 LLM 도입 시 보안 위험을 세 가지 이상 쓰고 각 대응 방안을 설명하시오. (예상·25점)

---

## 2~4교시 25점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | LLM 도입 보안 관리는 개발 과정에서 모델 입력·출력·도구 실행이 만드는 기밀 유출과 오용 위험을 통제하는 활동 |
| 목적 | 개발 생산성 활용과 코드·데이터·시스템 신뢰 경계 유지 |

- 코드 작성·문서 검색·자동화 도구 연결의 입력·출력·실행 경계를 정의.
### Ⅱ. 위험과 대응

```text
입력 경계: 소스·개인정보 외부 전송 → 분류·최소 전송
문서 경계: 비신뢰 지시 → 지시·자료 분리
실행 경계: 도구 호출 → 권한·승인 검사
출력 경계: 생성 코드 → 리뷰·시험·의존성 점검
```
| 위험 | 발생 경로 | 대응 |
|---|---|---|
| 기밀·개인정보 유출 | 프롬프트·로그·검색 자료의 외부 전송 | 데이터 분류·최소 전송·DLP·계약 확인 |
| 프롬프트 인젝션 | 외부 문서가 상위 지시처럼 해석 | 문서·지시 분리, 도구 권한 제한·승인 |
| 취약 코드·공급망 | 생성 코드·의존성의 검증 없는 병합 | 리뷰·테스트·SAST/DAST·구성요소 점검 |
### Ⅲ. 운영

| 업무 단계 | 위험 | 검증 지점 |
|---|---|---|
| 자료 입력 | 기밀·개인정보 반출 | 등급별 허용 범위 |
| 검색·도구 사용 | 외부 문서 지시의 실행 승격 | 사용자 권한·도구 인가 |
| 결과 채택 | 근거 없는 답·취약 코드 반영 | 원문·코드 검토 책임 |
- 모델 제공자의 저장·학습 정책, 접근 로그, 보존 기간과 사고 대응 책임을 확인.
#### 검증
- 실제 개발 흐름에서 입력 유출·주입·취약 코드 사례를 재현해 통제 효과를 반복 시험.

### Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 생성형 AI 출력·검색 문서를 그대로 신뢰하면 정보 유출과 취약 코드 반영 | 입력 제한·도구 최소권한·코드 검증을 별도 경계에 적용 |

### Ⅴ. 제언

승인된 개발용 모델의 입력 허용 범위와 생성 코드 검토 책임을 개발 파이프라인에 명시한다.
