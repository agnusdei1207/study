## 지식 로드맵 내 현재 위치

정보보호 기술 → 인증정보 보호 → 비밀번호 해시 공격과 방어(TMTO)

## 30초 인출

- **본질:** 해시 함수의 일방향성을 우회하기 위해 시간과 메모리의 절충(TMTO)을 이용하여 해시 체인의 시작점과 끝점만을 저장함으로써 사전 계산 크기와 검색 시간을 최적화한 비밀번호 역추적 공격 기법
- **메커니즘:** 평문 후보 → 해시 함수(H) → 다중 환원 함수(R_k) 연쇄 체인 생성 → 시작점/끝점 쌍 저장 → 목표 해시값에 환원 함수를 반복 적용해 끝점 검색 → 시작점부터 체인 재계산으로 평문 복원
- 통찰: 무작위 솔트(Salt)와 키 연장 함수(Argon2id, PBKDF2)를 적용하여 사전 계산 테이블의 재사용성을 원천 무효화하고 GPU/ASIC 병렬 크래킹에 대응하는 메모리 하드 암호화 아키텍처 필수

<details><summary>핵심 용어</summary>

- **레인보우 테이블(Rainbow Table):** Martin Hellman의 시간-메모리 절충(TMTO) 이론을 필립 옉스(Philippe Oechslin)가 다중 환원 함수 체인으로 발전시킨 사전 계산 공격 구조.
- **환원 함수(Reduction Function, R):** 해시값 공간의 출력을 원래의 평문 비밀번호 문자열 후보 공간으로 매핑하는 함수(해시의 역함수가 아님).
- **체인 병합(Chain Collision):** 서로 다른 시작점에서 출발한 체인이 중간에 동일한 평문/해시값을 만나 하나의 체인으로 합쳐져 검색 효율이 떨어지는 현상.
- **Salt(솔트):** 동일한 비밀번호라도 서로 다른 해시값이 생성되도록 입력 문자열에 덧붙이는 암호학적으로 안전한 고유 난수값.
- **Argon2id:** 메모리 및 CPU 비용을 동시 조절하여 병렬 하드웨어 공격(GPU/ASIC)을 방어하는 최신 암호학적 비밀번호 해싱 표준(RFC 9106).

</details>

> 비밀번호 해시 크래킹 기법인 레인보우 테이블(Rainbow Table)의 시간-메모리 절충(TMTO) 개념과 체인 생성 및 검색 메커니즘을 설명하고, 체인 충돌 문제와 이를 무력화하기 위한 안전한 비밀번호 저장 방안을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 단방향 해시 함수의 결과값을 평문으로 복원하기 위해 해시와 환원 함수를 반복 적용한 체인의 시작값과 끝값만을 저장하여 시간과 메모리를 절충한 사전 계산(Pre-computation) 공격 기법 |
| 목적 | 모든 평문-해시 쌍을 저장하는 사전 테이블의 거대한 저장공간 한계와 전수 조사(Brute-force)의 과도한 연산 시간을 동시에 극복 |

## Ⅱ. 레인보우 테이블의 주요 특징

| 특징 | 세부 내용 | 구현 요소 |
|---|---|---|
| 시간-메모리 절충 (TMTO) | 연산 시간과 저장 메모리 사이의 교환(Trade-off)을 통해 최적의 크래킹 자원 효율성 달성 | 헬만(Hellman) TMTO 모델, 옉스(Oechslin) 체인 |
| 다중 환원 함수 ($R_1 \dots R_k$) | 체인의 각 단계마다 서로 다른 환원 함수를 사용하여 동일 값 충돌에 의한 체인 병합 확률 억제 | 인덱스 기반 모듈러 환원 함수 |
| 양 끝점 저장 방식 | 체인의 시작점(Start Point)과 끝점(End Point)만 저장하여 수천 단계의 중간 해시 저장 공간 절약 | 압축형 레인보우 파일(.rt) |
| 오프라인 공격 모델 | 탈취된 패스워드 데이터베이스(해시덤프)를 대상으로 오프라인 상태에서 비인가 대조 수행 | Ophcrack, RainbowCrack 도구 |

## Ⅲ. 레인보우 테이블 체인 생성 및 검색 체계

```text
[ 1. 체인 생성 (Pre-computation) ]
시작점 P0 ──H──▶ H(P0) ──R1──▶ P1 ──H──▶ H(P1) ──R2──▶ P2 ── ... ──Rk──▶ Pk (끝점)
   │                                                                     │
   └───────────── 테이블에는 [ 시작점 P0 , 끝점 Pk ] 만 저장 ─────────────┘

[ 2. 패스워드 검색 (Online Lookup) ]
탈취된 목표 해시 H_target
   │
   ├─ 1단계: H_target ──Rk──▶ Y_k (끝점 매칭 확인) ───[ 불일치 ]
   ├─ 2단계: H_target ──R_{k-1}──▶ P ──H──▶ H ──Rk──▶ Y_k ───[ 일치 시 해당 시작점 P0 획득! ]
   │
   ▼
[ 3. 체인 재계산 (Chain Walk) ]
P0 ──H──▶ H0 ──R1──▶ P1 ──H──▶ H1 ... 계산 중 H(P_target) == H_target 발견 시 평문 복원 완료!
```

| 단계 | 수행 작업 | 세부 메커니즘 |
|---|---|---|
| 1. 체인 생성 | 임의의 평문 $P_0$에서 시작하여 해시($H$)와 환원($R_i$)을 $k$번 반복하여 최종 끝점 $P_k$ 도출 | $P_{i} = R_i(H(P_{i-1}))$, 최종 $(P_0, P_k)$ 테이블 인덱싱 |
| 2. 끝점 탐색 | 목표 해시 $H_x$에 마지막 환원 함수 $R_k$부터 역순으로 가상 체인을 계산하여 테이블 끝점과 비교 | 일치하는 끝점이 발견될 때까지 체인 길이만큼 연산 반복 |
| 3. 체인 워크 | 일치한 끝점의 시작점 $P_0$를 읽어 처음부터 순방향으로 $H$와 $R_i$를 재실행 | 재계산 도중 중간 생성된 해시값이 목표 해시와 일치하는 순간의 평문 획득 |
| 4. 거짓 탐지 검증 | 다른 시작점의 체인이 병합되어 끝점만 일치하고 실제 목표 평문이 없는 가오탐(False Alarm) 필터링 | 재계산 끝까지 일치 해시 미발견 시 다음 체인 탐색 계속 |

## Ⅳ. 비밀번호 크래킹 기법 비교

| 구분 | 무차별 대입 (Brute-force) | 사전 공격 (Dictionary Attack) | 전수 룩업 테이블 (Full Table) | 레인보우 테이블 (Rainbow Table) |
|---|---|---|---|---|
| 사전 계산 | 없음 (즉시 계산) | 없음 (단어장 해시화) | 모든 평문-해시 사전 계산 | 체인 기반 사전 계산 (TMTO) |
| 저장 공간 | 거의 없음 ($O(1)$) | 단어장 크기 ($O(N)$) | 천문학적 크기 ($O(N)$ 전수) | 극소화된 체인 끝점 ($O(N/k)$) |
| 검색 시간 | 극도로 느림 ($O(N)$) | 단어 수에 비례 ($O(M)$) | 매우 빠름 ($O(1)$ 해시맵) | 중간 속도 ($O(k^2)$ 재계산) |
| 솔트(Salt) 방어 | 무력화 불가 (계산량 증가) | 솔트별 재시도 필요 | 솔트 적용 시 무용지물 | 솔트 적용 시 사전 계산 무력화 |
| 체인 병합 위험 | 없음 | 없음 | 없음 | 체인 충돌 및 가오탐 발생 |

## Ⅴ. 레인보우 테이블 공격의 한계와 방어 방안

| 한계 | 방안 |
|---|---|
| 동일한 환원 함수 체인 내에서 서로 다른 시작점이 동일한 평문으로 매핑되어 체인이 합쳐지는 체인 병합(Collision)으로 검색 성공률 저하 | 체인의 매 스텝마다 고유한 환원 함수 $R_1, R_2, \dots, R_k$를 부여하는 레인보우 알고리즘 적용 및 적정 체인 길이($k$) 제한 |
| 계정마다 고유한 암호학적 솔트(Salt)가 적용된 경우 해시 테이블을 계정마다 매번 수백 GB 단위로 새로 사전 계산해야 하는 연산 병목 | 계정 생성 시 최소 128비트 이상의 CSPRNG 기반 무작위 고유 Salt를 부여하여 글로벌 사전 계산 테이블의 재사용을 원천 차단 |
| 단순 MD5, SHA-1, SHA-256 등 단일 해시 함수는 최신 GPU/ASIC 클러스터의 초당 수백억 회 병렬 연산에 의해 무차별 대입 노출 | 키 연장(Key Stretching)과 메모리 하드(Memory-hard) 알고리즘인 Argon2id, PBKDF2, bcrypt 도입으로 단일 해시 연산 비용 극대화 |

## Ⅵ. 제언

```text
[ 전통적 단순 해싱 ]                 [ 최신 안전한 비밀번호 보호 체계 ]
단순 SHA-256 해시 ──┐               ┌── 암호학적 난수 Salt (128bit+) 결합
솔트 없는 저장 ─────┼─→ [ 침해 취약 ] ─┼── Argon2id 메모리 하드 알고리즘 적용
단일 반복 연산 ─────┘               └── HSM 기반 서버 비밀키(Pepper) 이중 결합
```

| 평가 영역 | 단순 해시 저장 (취약) | 최신 패스워드 해싱 체계 | 향후 발전 방향 |
|---|---|---|---|
| TMTO 공격 내성 | 레인보우 테이블에 즉시 복원 | 솔트 적용으로 사전 계산 무력화 | 양자 암호 내성 기반 KDF 연구 |
| GPU 병렬 공격 | 고속 해시로 크래킹 용이 | 메모리 병목으로 GPU 연산 무력화 | 하드웨어 보안 모듈(HSM) 페퍼링 |
| 규제 및 표준 준수 | NIST 지침 및 ISMS-P 위반 | NIST SP 800-63B 기준 완전 충족 | 패스워드리스(FIDO2/Passkey) 전면 전환 |

레인보우 테이블은 암호학적 일방향성에만 의존한 단순 해싱의 치명적 결함을 드러낸 대표적 공격 기법이며, 현대 시스템은 솔트(Salt)와 페퍼(Pepper), 그리고 Argon2id 기반의 키 연장 메커니즘을 결합하여 완벽한 방어 탄력성을 갖추어야 함.
