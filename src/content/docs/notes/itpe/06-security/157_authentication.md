## 30초 인출

- **본질:** 인증은 주체가 주장한 신원이 맞는지 자격증명이나 인증수단으로 확인하는 절차.
- **메커니즘:** 식별 정보 제출 → 인증수단 검증 → 검증 결과를 세션에 연결.
- **구분:** 인증은 “누구인가”, 인가는 “무엇을 할 수 있는가”의 판단.

<details>
<summary>핵심 용어</summary>

- **인증(Authentication)**: 주체가 주장한 신원이 맞는지 인증수단을 검증하는 절차.
- **식별(Identification)**: 접근자가 사용하려는 계정이나 주체를 밝히는 단계.
- **인가(Authorization)**: 인증된 주체의 자원·행위별 접근 허용 여부를 판단하는 절차.
- **자격증명(Credential)**: 주체가 신원 검증에 제시하는 비밀번호·키·증명서 등의 정보.
- **세션(Session)**: 인증 뒤 일정 기간 동안 주체의 접속 상태를 연결해 관리하는 단위.
- **MFA(Multi-Factor Authentication)**: 서로 다른 종류의 인증 요소를 둘 이상 사용하는 방식.
</details>

## 2~4교시 25점 답안

## Ⅰ. 인증의 정의와 목적

| 구분 | 내용 |
|---|---|
| 정의 | **인증(Authentication)**은 접근자가 주장한 신원을 인증수단으로 확인하는 절차 |
| 목적 | 주체 사칭을 줄이고 후속 권한 판단에 신뢰할 수 있는 신원 제공 |

인증 결과는 권한의 근거 중 하나이며, 인증 성공 자체가 모든 자원 접근을 허용하는 것은 아님.

## Ⅱ. 인증의 위치와 처리 절차

```text
식별: 사용할 계정 제시
    ↓
인증: 자격증명·인증수단 검증
    ↓
인가: 자원·행위별 권한 판단
    ↓
접근 기록
```

| 단계 | 처리 |
|---|---|
| 식별 | 계정·주체 후보 지정 |
| 인증 | 비밀번호·키·생체와 등록 정보 검증 |
| 인가 | 역할·속성·정책에 따른 요청 판단 |
| 감사 | 접근 주체·행위·결과 기록 |

## Ⅲ. 인증수단과 보증 수준

```text
인증 요소
  ├─ 지식 ─ 비밀번호·PIN
  ├─ 소유 ─ 보안키·인증 앱
  └─ 생체 ─ 지문·얼굴
       ↓ 서로 다른 요소 결합
      MFA
```

| 방식 | 위험 | 강화 방향 |
|---|---|---|
| 비밀번호 | 재사용·피싱 | 유출 암호 차단, MFA |
| 일회용 코드 | 실시간 피싱 중계 | 피싱 저항성 검토 |
| 공개키·보안키 | 분실·복구 경로 | 안전한 등록·복구 |

## Ⅳ. 세션·복구·인가 연계

```text
인증 성공
    ↓ 세션 발급·보호
업무 요청
    ↓ 요청마다 필요한 인가
위험 변화
    ↓ 재인증·세션 해지
```

| 통제 | 확인 내용 |
|---|---|
| 세션 | 탈취·고정·만료·기기 변경 |
| 복구 | 등록된 수단 분실 시 신원 재확인 |
| 인가 | 대상 자원과 요청 행위의 권한 |

## Ⅴ. 한계와 제언

| 한계 | 대응 |
|---|---|
| 강한 로그인만 적용하고 복구 절차는 약하게 유지 | 복구·수단 재등록에 동일 수준의 신원 확인과 알림 적용 |
| 인증된 사용자에게 과도한 권한 부여 | 자원·행위별 인가와 중요 작업의 재인증 분리 |
