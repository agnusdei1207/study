## 지식 로드맵 내 현재 위치

- 정보보안 → 접근 통제(Access Control) → 식별 및 인증 → 사용자 인증(Authentication)

```text
[접근 주체] ──(신원 주장)──> [식별 (ID)] ──(자격증명 검증)──> [인증 (Authentication)]
                                                                  │
                                                                  ├── 지식/소유/존재/행위 기반
                                                                  └── FIDO2/WebAuthn 공개키 전자서명
                                                                  │
                                                                  ▼
                                                      [인가 (Authorization) & 감사 (Audit)]
```

---

## 30초 인출

- **본질:** 시스템 자원에 접근하려는 주체(사용자, 프로세스, 기기)가 주장하는 신원이 실제 본인임을 암호학적 자격증명(Credential)과 다중 요소를 통해 검증하는 절차.
- **메커니즘:** 식별자(ID) 입력 → 인증 요소(지식·소유·생체·행위) 제출 → 챌린지-응답 암호화 검증 → 세션 토큰(JWT/Session ID) 발급 및 컨텍스트 바인딩.
- **통찰:** 단순 SMS/OTP 기반 2차 인증은 실시간 중간자(AitM) 프록시 피싱에 무력화되므로, 도메인 결합(Origin Binding)과 비대칭키 전자서명을 제공하는 FIDO2 패스키(Passkey) 도입 필수.

---

## 2~4교시 예상문제 (25점)

> 접근통제의 3단계(식별, 인증, 인가)를 비교 설명하고, NIST SP 800-63-4 신원 보증 모델(IAL, AAL, FAL)과 피싱 저항성을 갖춘 차세대 패스키(Passkey/FIDO2) 구현 방안을 제시하시오. (25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 정보 시스템을 이용하려는 주체가 주장하는 신원(Identity)의 진위 여부를 지식, 소유, 생체, 행위 기반 자격증명을 통해 증명하고 검증하는 보안 메커니즘 |
| 목적 | 비인가 주체의 신원 위장 및 불법 도용을 차단하고, 후속 인가(Authorization) 및 감사 추적(Accounting)의 신뢰성 보장 |

- 접근통제의 핵심 관문이며, 단일 정적 패스워드 체계에서 위험 기반 적응형 인증(Adaptive MFA) 및 제로 트러스트 지속 인증(Continuous Adaptive Authentication)으로 진화.

## Ⅱ. 사용자 인증의 핵심 특징 및 4대 요소 체계

### 1. 인증의 핵심 특징

| 특징 | 설명 | 세부 내용 |
|---|---|---|
| 신원 위장 차단 | 본인 진위 여부의 기술적 입증 | 해시 함수, 대칭키 HMAC, 비대칭키 전자서명을 활용한 챌린지-응답 검증 |
| 다중 요소 결합 (MFA) | 서로 다른 성격의 2개 이상 팩터 융합 | 단일 요소 유출 시에도 타 요소 보호를 통해 전체 계정 탈취 차단 |
| 세션 라이프사이클 결합 | 인증 성공 후 일시적 접근 권한 위임 | 세션 하이재킹 및 재생 공격(Replay Attack) 방지를 위한 만료 시간 및 암호학적 토큰 바인딩 |
| 피싱 저항성 요구 | 중간자 프록시 우회 공격 방어 | 브라우저와 인증 장치 간 도메인(Origin) 암호학적 결합을 통한 피싱 방어 |

### 2. 인증의 4대 요소 (Authentication Factors)

```text
[인증 4대 요소]
  ├── 1. 지식 기반 (Something You Know)     ──> 패스워드, PIN, 질의응답 (망각 및 유출 취약)
  ├── 2. 소유 기반 (Something You Have)     ──> OTP 토큰, 스마트카드, FIDO 보안키, 모바일 앱 (분실/복제 위험)
  ├── 3. 생체 기반 (Something You Are)      ──> 지문, 홍채, 얼굴, 정맥 (위변조 곤란, 변경 불가)
  └── 4. 행위/위치 기반 (Something You Do)  ──> 타이핑 패턴, 마우스 궤적, GPS, 접속 IP (동적 이상징후 탐지)
```

## Ⅲ. 인증 프로세스 및 NIST SP 800-63 신원 보증 아키텍처

### 1. FIDO2 / WebAuthn 기반 챌린지-응답 인증 아키텍처

```text
+-----------------------------------------------------------------------------------------+
|                               FIDO2/WebAuthn 인증 프로세스                               |
+-----------------------------------------------------------------------------------------+
  [사용자 / Authenticator]           [클라이언트 브라우저]               [인증 서버 (Relying Party)]
         │                                   │                                    │
         │                                   │ 1. 로그인 요청                      │
         │                                   ├───────────────────────────────────>│
         │                                   │ 2. Challenge + RP ID 반환          │
         │                                   │<───────────────────────────────────┤
         │ 3. navigator.credentials.get()    │                                    │
         │<──────────────────────────────────┤                                    │
  [생체/PIN 로컬 검증]                        │                                    │
  [개인키로 Challenge 전자서명]                │                                    │
         │ 4. AuthenticatorData + Signature   │                                    │
         ├──────────────────────────────────>│                                    │
         │                                   │ 5. 전자서명 및 Challenge 검증 요청 │
         │                                   ├───────────────────────────────────>│
         │                                   │                                    │ [공개키 검증]
         │                                   │ 6. 검증 성공 및 Session/JWT 발급   │ [RP ID 일치 검증]
         │                                   │<───────────────────────────────────┤
+-----------------------------------------------------------------------------------------+
```

### 2. NIST SP 800-63-4 디지털 신원 보증 모델 체계

| 보증 모델 | 영문 명칭 | 정의 및 평가 대상 | 세부 단계 및 요건 |
|---|---|---|---|
| IAL | Identity Assurance Level | 신원 확인 보증 수준 (주체와 실세계 인물 간 일치성) | IAL1(자가진술) → IAL2(원격 실명증빙 확인) → IAL3(대면 실물 확인) |
| AAL | Authenticator Assurance Level | 인증자 보증 수준 (인증 세션의 암호학적 강도) | AAL1(단일요소) → AAL2(MFA 적용) → AAL3(하드웨어 암호모듈 기반 피싱저항 MFA) |
| FAL | Federation Assurance Level | 페더레이션 보증 수준 (IdP와 RP 간 토큰 전달 신뢰도) | FAL1(서명된 SAML/OIDC 토큰) → FAL2(암호화 전송) → FAL3(보유자 증명/키 바인딩) |

## Ⅳ. 주요 인증 방식별 메커니즘 및 보안성 비교

### 1. 전통적 인증 vs 차세대 인증 방식 비교

```text
+---------------------+      +---------------------+      +---------------------+
|   패스워드 기반     |      |    SMS / OTP 앱     |      |  FIDO2 / 패스키     |
+---------------------+      +---------------------+      +---------------------+
| 서버에 해시 저장    |      | 대칭키/시간 동기화  |      | 공개키 암호 전자서명 |
| 무차별 대입/피싱    | ---> | 심스와핑/AitM 피싱  | ---> | Origin 바인딩 완벽   |
| 자격증명 탈취 위험  |      | 중간자 프록시 우회  |      | 피싱 원천 차단       |
+---------------------+      +---------------------+      +---------------------+
```

| 구분 | 패스워드 인증 (Password) | 시간 동기화 OTP (TOTP) | SMS / 푸시 기반 인증 | FIDO2 / WebAuthn (Passkey) |
|---|---|---|---|---|
| 메커니즘 | Salted Hash(Argon2, bcrypt)와 사용자 입력 일치 검증 | 공유 대칭키(K)와 UNIX Time 기반 HMAC 연산(`HMAC-SHA1`) | 통신사 이동통신망 SMS 전송 또는 앱 푸시 승인 | 클라이언트 보안영역(Secure Enclave) 개인키 서명 + 서버 공개키 검증 |
| 피싱 저항성 | 취약 (가짜 사이트에 그대로 노출) | 취약 (AitM 도구가 일회용 코드 실시간 중계 탈취) | 취약 (심스왑 및 실시간 프록시 탈취) | 완벽 (브라우저가 Origin 도메인을 암호학적으로 서명에 결합) |
| 서버 자격증명 | 해시 및 솔트 데이터베이스 보관 | 사용자별 공유 비밀키(Secret Key) 보관 | 발송 서버 연동 정보 보관 | 사용자별 공개키(Public Key)만 보관 (탈취되어도 안전) |
| 사용 편의성 | 암기 부담, 주기적 변경 강요 | 별도 단말 앱 구동 및 번호 입력 필요 | 수신 대기 및 망 지연 발생 | 생체인식(Touch ID/Face ID) 원클릭 즉시 완료 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| Reverse Proxy 기반 AitM(Adversary-in-the-Middle, Evilginx) 도구에 의해 TOTP 일회용 코드 및 인증 완료 세션 쿠키가 실시간 중계 탈취 | WebAuthn 기반 Origin 결합 인증 체계를 의무화하고 OAuth 토큰 발행 시 DPoP(Demonstrating Proof-of-Possession) 및 mTLS 클라이언트 인증서를 바인딩 |
| FIDO2 패스키 분실 또는 신규 단말기 교체 시 기기간 동기화 실패로 인한 영구 계정 잠김(Account Lockout) 위험 | FIDO Alliance 표준 다중 장치 동기화 패스키(Synced Passkey)를 도입하고 종단간 암호화(E2EE) 백업 클라우드 키체인을 연동 |
| 인증 완료 후 세션 유지 구간에서 세션 하이재킹(Session Hijacking) 및 토큰 도난 시 사후 탐지 및 즉각적 세션 무력화 불가 | CAEP(Continuous Access Evaluation Profile) 및 RISC 프로토콜을 구현하여 IP 급변, 기기 탈취 의심 시 세션 강제 만료 및 즉각 재인증 요구 |

## Ⅵ. 제언

### 1. 제로 트러스트 적응형 지속 인증(Adaptive Continuous Auth) 모델

```text
[로그인 시점]                                    [세션 유지 시점 (지속적 검증)]
  - FIDO2 패스키 검증 (AAL3)                     - 디바이스 보안 상태 (EDR 무결성)
  - 접속 IP / 지리적 위치 확인                     - 사용자 행동 프로파일링 (UEBA 이상징후)
  - 위험 점수(Risk Score) 산정                     - 위험 점수 상승 시 Step-up 인증 강제
         │                                                │
         ▼                                                ▼
  [최초 세션 토큰 발행] ─────────────────────────> [동적 세션 해지 및 권한 격리]
```

### 2. 신원 및 인증 아키텍처 도입 요소 종합 평가

| 영역 | 도입 권장 기술 | 보안 수준 | 복잡도 | 운영 고려사항 |
|---|---|---|---|---|
| 사용자 인증 | FIDO2 / WebAuthn 패스키 | 최고 | 중간 | 레거시 브라우저 호환성 및 대체 복구 수단 사전 정의 |
| 서비스 간 인증 | mTLS + SPIFFE/SPIRE | 최고 | 높음 | x509 인증서 자동 발급 및 단기 만료(Rotation) 파이프라인 필수 |
| 세션 보안 | DPoP (RFC 9449) 토큰 바인딩 | 높음 | 중간 | 리버스 프록시 헤더 변조 방지 및 암호 연산 오버헤드 검토 |
| 계정 거버넌스 | IdP 중앙 집중화 (OIDC/SAML) | 상 | 높음 | Single Point of Failure(SPOF) 방지를 위한 멀티 리전 IdP 이중화 |

- 차세대 신원 인증은 패스워드를 완전히 제거하는 패스워드리스(Passwordless) 환경으로 전환되어야 하며, 로그인 시점의 1회성 검증을 넘어 제로 트러스트 원칙에 기반한 지속적 적응형 인가 체계와의 연동 필수.
