## Ⅰ. CFB의 개요

- **개념** : 블록 암호화 알고리즘(AES, SEED 등)을 자기 동기식(Self-synchronizing) 스트림 암호처럼 동작하도록 변환하여, 임의의 비트 단위(1비트, 8비트, $s$비트) 데이터를 패딩(Padding) 없이 즉시 암호화할 수 있는 블록 암호 운용 모드.
- **배경 및 필요성** : 전통적인 ECB, CBC 모드는 데이터가 반드시 64비트 또는 128비트의 고정 블록 크기 배수여야 하므로 패딩 추가에 따른 데이터 오버헤드가 발생하고, 실시간 키보드 입력이나 센서 스트림 데이터를 즉시 처리하기에 부적합함.
- **핵심 목적** : 고정 크기 블록 단위를 기다리지 않고 입력되는 스트림 데이터를 실시간으로 암호화하며, 이전 암호문 블록을 피드백하여 동일 평문에 대한 패턴 노출을 방지.

## Ⅱ. CFB의 핵심 아키텍처 및 동작 메커니즘

CFB는 시프트 레지스터(Shift Register), 초기화 벡터(IV), 블록 암호화 엔진, XOR 연산기로 구성되며, 평문이 암호 엔진으로 들어가지 않고 암호 엔진의 출력값과 XOR되는 구조를 가짐.

```text
[ CFB(Cipher Feedback) 모드 암호화 및 복호화 메커니즘 ]

 1. CFB 암호화 (Encryption)
    [ 초기화 벡터 (IV) ] -----------------+
             |                            |
             v                            |
    +-----------------+                   | (이전 암호문 피드백)
    | 블록 암호 엔진  | <--- [ 키 (K) ]   |
    +--------+--------+                   |
             |                            |
      (상위 s비트 선택)                   |
             |                            |
             v                            |
          (+) <---- [ 평문 (P_i) ]        |
             |                            |
             v                            |
       [ 암호문 (C_i) ] ------------------+ (시프트 레지스터 입력)

 2. CFB 복호화 (Decryption)
    [ 초기화 벡터 (IV) ] -----------------+
             |                            |
             v                            |
    +-----------------+                   | (수신된 이전 암호문 피드백)
    | 블록 암호 엔진  | <--- [ 키 (K) ]   |   * 복호화 시에도 암호 엔진은
    +--------+--------+                   |     "암호화(E)" 모드로 동작!
             |                            |
      (상위 s비트 선택)                   |
             |                            |
             v                            |
          (+) <---- [ 암호문 (C_i) ]      |
             |                            |
             v                            |
        [ 평문 (P_i) ] -------------------+
```

- **자기 동기화(Self-synchronization)** : 전송 도중 비트 손실이나 동기 이탈이 발생하더라도, 시프트 레지스터 크기만큼의 정상 암호문이 다시 수신되면 자동으로 동기가 복구되는 강력한 복원력.
- **복호화 시 암호화 엔진 사용** : 복호화 시에도 블록 암호의 복호화(D) 함수를 쓰지 않고 동일하게 암호화(E) 함수를 사용하여 키 스트림을 생성하므로 하드웨어 구현 면적 절감.
- **에러 전파 특성(Error Propagation)** : 전송 중 암호문 1비트에 오류가 발생하면, 해당 블록의 평문 복호화에 1비트 에러가 발생하고, 이후 시프트 레지스터에 머무는 동안 후속 블록들이 연속적으로 깨지는 국소적 에러 전파.
- **패딩 미사용** : 문자 단위($s=8$) 또는 임의 비트 단위로 즉시 XOR 암호화가 가능하여 데이터 길이가 원본과 완전히 동일하게 유지됨.

## Ⅲ. CFB의 세부 구성 요소 및 비교 분석

| 비교 항목 | CFB (Cipher Feedback) | OFB (Output Feedback) | CBC (Cipher Block Chaining) | CTR (Counter Mode) |
| --- | --- | --- | --- | --- |
| 피드백 소스 | 이전 암호문 블록 (C_i) | 이전 암호 엔진 출력값 (독립) | 이전 암호문 블록 (C_i) | 카운터 값 (Counter + i) |
| 연산 형태 | 자기 동기식 스트림 암호 | 동기식 스트림 암호 | 순수 블록 암호 | 동기식 스트림 암호 |
| 에러 전파 | 해당 비트 + 후속 레지스터 블록 오류 | 해당 비트만 오류 (후속 전파 없음) | 해당 블록 전체 + 다음 블록 1비트 | 해당 비트만 오류 (후속 전파 없음) |
| 병렬 처리 | 암호화 불가 / 복호화 가능 | 암호화 불가 / 복호화 불가 | 암호화 불가 / 복호화 가능 | 암호화 가능 / 복호화 가능 |
| 패딩 필요 | 불필요 (임의 비트 크기) | 불필요 (임의 비트 크기) | 필수 (블록 크기 정수배) | 불필요 (임의 비트 크기) |

- CFB 모드는 네트워크 장애로 인한 비트 손실 시 자동 재동기화가 가능한 장점이 있으나, 순차 암호화 연산 제약으로 고속 병렬 처리가 요구되는 현대 환경에서는 CTR/GCM으로 대체되는 추세임.

## Ⅳ. CFB의 주요 한계점 및 해결 방안

- **암호화 연산의 순차적(Sequential) 종속성에 따른 병렬화 불가** :
  - **한계점** : 현재 블록의 암호화 결과($C_i$)가 다음 블록 암호 엔진의 입력으로 사용되므로 멀티코어 CPU나 GPU를 활용한 병렬 고속 암호화가 원천 불가능.
  - **해결 방안** : 대용량 고속 데이터 처리가 요구되는 네트워크 장비에는 완벽한 병렬화와 사전 연산이 가능한 CTR 모드 또는 GCM 모드로 전환.
- **단일 비트 전송 오류 시 후속 블록 전체 파괴 (에러 전파)** :
  - **한계점** : 통신 채널 노이즈로 암호문 비트가 왜곡되면, 해당 데이터뿐만 아니라 시프트 레지스터가 비워질 때까지(128비트 동안) 모든 후속 데이터가 복호화 불능.
  - **해결 방안** : 상위 전송 계층에 오류 정정 부호(FEC: Forward Error Correction)를 결합하거나 무결성 검증용 MAC을 병행 적용.
- **재전송 공격 및 암호문 조작(Bit-flipping)에 대한 무결성 보장 한계** :
  - **한계점** : 스트림 암호의 고유 특성상 공격자가 암호문 비트를 반전시키면 복호화된 평문의 해당 비트가 정확히 반전되어 무결성이 훼손됨.
  - **해결 방안** : 단순 CFB 단독 운용을 금지하고, HMAC을 결합한 Encrypt-then-MAC 체계나 인증 암호화(AEAD) 모드 적용.

## Ⅴ. CFB 적용 및 발전을 위한 기술사적 제언

- **고유한 초기화 벡터(IV) 생성 및 재사용 금지 원칙 준수** : 동일한 키와 IV를 재사용할 경우 초기 키 스트림이 동일하게 생성되어 두 평문의 차분 공격(Known-Plaintext)에 노출되므로 암호학적 난수 IV 필수 적용.
- **IoT 및 원격 텔레메트리 스트림 전송 프로토콜 적용** : 센서 데이터처럼 버퍼링 없이 즉시 1바이트씩 전송해야 하는 경량 IoT 통신에 CFB-8 모드를 효율적으로 탑재.
- **현대적 표준 권고에 따른 AES-GCM 및 ChaCha20-Poly1305로의 마이그레이션** : NIST 가이드라인에 따라 무결성과 기밀성을 하드웨어 가속으로 동시 제공하는 최신 AEAD 모드로 암호 라이브러리 전면 교체 권장.
