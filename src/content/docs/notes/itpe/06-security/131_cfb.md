## 지식 로드맵 내 현재 위치

지식 위치: 암호 운용 모드 → 암호문 피드백 → **CFB**

## 30초 인출
- 본질: CFB는 이전 암호문을 피드백해 블록 암호를 세그먼트 단위로 사용하는 기밀성 운용 모드
- 메커니즘: IV·이전 암호문을 암호화 함수에 넣고 출력 일부를 평문과 XOR한 뒤 생성 암호문을 다음 입력에 피드백
- 통찰: 한계: CFB 자체에는 인증 기능이 없어 암호문 변조를 탐지하지 못함 → 방안: 무결성이 필요하면 인증된 암호 방식을 적용

<details>
<summary>핵심 용어</summary>

- **CFB** : 이전 암호문을 다음 입력에 피드백하는 블록 암호 기밀성 모드.
- **IV** : 첫 레지스터 상태에 사용하는 초기화 벡터.
- **세그먼트 크기** : 한 번의 연산에서 처리할 비트 수.
- **AEAD** : 암호화와 인증을 함께 제공하는 운용 방식.

</details>

## 동작 그림
```text
초기 레지스터 IV ── E_K ── 상위 s비트 ── XOR 평문 P₁ ── 암호문 C₁
        ↑                                           │
        └──────── 레지스터 이동 후 C₁ 피드백 ─────┘
복호화: 동일한 E_K 출력과 C₁을 XOR → P₁
```

## 2~4교시 25점 답안
### Ⅰ. 개요

| 항목 | 개요 |
|---|---|
| 정의 | CFB는 앞선 암호문을 피드백해 블록 암호를 세그먼트 단위로 사용하는 기밀성 운용 모드 |
| 목적 | 블록 암호의 패딩 없는 세그먼트 처리와 별도 인증에 의한 변조 위험 관리 |

IV, 블록 암호 함수 E_K, s비트 추출, XOR 및 피드백 레지스터로 구성. 암호화 시 레지스터 암호화 결과의 상위 s비트와 평문 XOR, 생성 암호문을 레지스터에 반영. 복호화도 E_K를 사용하고 수신 암호문을 피드백.

### Ⅱ. CFB 암호문 피드백 메커니즘

```text
전체 블록 CFB 예
IV ─ E_K(IV) ─ XOR P₁ → C₁
C₁ ─ E_K(C₁) ─ XOR P₂ → C₂

암호화 함수의 입력에 이전 암호문을 피드백
```

세그먼트 길이가 블록보다 작은 CFB는 시프트 레지스터의 일부를 새 암호문으로 갱신한다.

### Ⅲ. CFB와 다른 기밀성 모드 비교

```text
이전 암호문 이용: CBC(평문과 결합), CFB(암호화 입력)
암호 출력 이용: OFB(다음 출력에 피드백)
카운터 이용: CTR(증가값을 암호화)
             ↓
     오류 전파·병렬성·IV 조건 차이
```

| 모드 | 다음 입력 | 오류 영향 | 처리 특성 |
|---|---|---|---|
| CBC | 앞 암호문과 평문 결합 | 해당·다음 블록에 영향 | 블록 단위 패딩 필요 |
| CFB | 앞 암호문 피드백 | 해당 비트와 후속 일정 구간에 영향 | s비트 처리, 암호화 직렬 의존성 |
| OFB | 암호화 함수 출력 피드백 | 해당 비트에 국한 | 키스트림 재사용 금지 |
| CTR | 카운터 암호화 | 해당 비트에 국한 | 병렬 처리 가능, 카운터 재사용 금지 |

#### 설계 유의

| 설계 항목 | CFB 적용 판단 | 보완 |
|---|---|---|
| IV | 모드·세그먼트 조건 확인 | 키별 사용 규칙 검증 |
| 오류 전파 | 후속 일정 구간에 영향 | 전송 오류 처리 설계 |
| 메시지 인증 | CFB 자체는 기밀성 제공 | MAC 또는 AEAD 구성 |
IV 요구사항은 NIST SP 800-38A의 모드별 규칙에 맞춰 적용. CFB·OFB·CTR은 기밀성 모드이므로 메시지 인증 필요 시 AEAD 등 인증 기능 결합. 오류 전파가 없다는 이유만으로 OFB·CTR을 무결성 대책으로 간주할 수 없음.

### Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| CFB는 기밀성 모드로 암호문 변조를 탐지하지 못함 | 키·IV 재사용을 막고 별도 인증 또는 AEAD를 적용 |

### Ⅴ. 제언

CFB 적용 시스템의 키·IV 재사용 가능성을 먼저 확인하고 인증 기능을 별도 설계.
