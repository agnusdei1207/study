## 30초 인출

- **본질:** 비인간 신원(NHI) 및 AI 에이전트 자격증명 탈취, 오픈소스 SW 공급망 오염, Living-off-the-Land(LotL) 기법이 결합된 고도화된 타깃 침해 위협.
- **메커니즘:** 깃허브/CI 토큰 탈취 및 오픈소스 악성 패키지 배포 → LotL 정상 도구 기반 측면 이동 → 클라우드 데이터 유출 및 이중 갈취형 랜섬웨어 실행.
- 통찰: 단편적 엔드포인트 백신 대응을 탈피하여 NHI 전주기 거버넌스, 오픈소스 SBOM 서명 검증, CTEM 기반 지속적 공격 표면 제거 체계 구축 필수.

<details><summary>핵심 용어</summary>

- **비인간 신원(Non-Human Identity, NHI)**: API 키, 서비스 어카운트, OAuth 토큰, CI/CD 러너 등 머신 간 상호작용에 사용되는 자격증명.
- **Living-off-the-Land(LotL)**: 파워셸(PowerShell), WMI, BITS 등 운영체제 내장 정상 바이너리를 악용하여 시그니처 탐지를 우회하는 공격 기법.
- **SW 공급망 침해(Supply Chain Attack)**: 오픈소스 리포지토리(npm, PyPI)나 CI/CD 파이프라인, 서드파티 라이브러리를 오염시켜 하위 사용자를 대규모 감염시키는 기법.
- **이중 갈취(Double Extortion)**: 데이터를 암호화하여 인질로 삼는 동시에, 몸값을 지불하지 않으면 민감 데이터를 다크웹에 유출하겠다고 협박하는 랜섬웨어 기법.
- **CTEM(지속적 위협 노출 관리)**: 공격자의 시각에서 발견된 취약점과 자격증명 노출, 설정 오류를 상시 검증하고 우선순위화하는 보안 프레임워크.
</details>

## Ⅱ. 2026년 상반기 침해사고 위협의 주요 특징

| 특징 | 세부 양상 | 기술적 파급 효과 |
|---|---|---|
| 머신 신원(NHI) 표적화 | API 키, PAT(Personal Access Token), 서비스 계정 탈취 급증 | MFA가 미적용된 기계 자격증명으로 무혈입성(Credential Stuffing) |
| 정상 도구 은닉(LotL) | PowerShell, Certutil, MSBuild 등 OS 내장 바이너리 악용 | 안티바이러스 및 정적 시그니처 기반 보안 솔루션 전면 무력화 |
| 공급망 신뢰 체인 오염 | npm, PyPI 패키지 타이포스쿼팅 및 종속성 혼동(Dependency Confusion) | 단일 코드베이스 변조를 통해 수천 개 다운스트림 고객사로 일괄 확산 |
| AI 도구 결합 공격 | 생성형 AI 기반 맞춤형 스피어피싱 자동화 및 다형성 악성코드 제작 | 보안 담당자의 인지 한계를 초월하는 대량의 고정밀 타깃 공격 발생 |
| 클라우드 데이터 이중 갈취 | 온프레미스 파괴를 넘어 클라우드 스토리지(S3, Blob) 직접 암호화·탈취 | 복구 백업 체계의 클라우드 집중 타격으로 비즈니스 다운타임 장기화 |

## Ⅳ. 2026 상반기 4대 핵심 침해 위협 유형 비교

| 위협 유형 | 주 공격 메커니즘 | 공격 탐지 난이도 | 주요 방어 엔지니어링 통제 |
|---|---|---|---|
| 비인간 신원(NHI) 탈취 | 소스코드/로그 내 노출된 영구 API 키 및 PAT 수집 | 상 (정상 세션으로 로그인하여 탐지 극난) | 시크릿 하드코딩 제거, 단기 자격증명(STS), Vault 중앙 관리 |
| SW 공급망 오염 | 악성 커밋 기여, 유지관리자 계정 하이재킹, 의존성 변조 | 최상 (빌드 완료된 신뢰 바이너리에 은닉) | SLSA Level 3 달성, SBOM 생성 및 인-토토(in-toto) 검증 |
| 정상 도구 악용(LotL) | 내장 관리 도구(PowerShell, WMI, BITS)를 통한 메모리 실행 | 상 (백신 파일 스캔 우회, 무파일 악성코드) | 파워셸 스크립트 블록 로깅, 비인가 명령 인자 행위 분석 |
| 이중 갈취형 랜섬웨어 | 자격증명 획득 후 백업 카탈로그 삭제 및 클라우드 암호화 | 중 (대량 I/O 발생 및 네트워크 트래픽 증가) | WORM 불변 백업, Egress 트래픽 이상 임계치 모니터링 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| OS 내장 도구(LotL) 악용 시 정상 관리자 명령과 악의적 행위의 구분이 모호하여 오탐 및 미탐 빈발 | 파워셸 스크립트 블록 로깅(Event ID 4104)을 활성화하고, 부모-자식 프로세스 트리(예: Word->cmd->powershell) 기반 행위 탐지 룰 강제 배포 |
| 서드파티 오픈소스 패키지의 심층 의존성(Transitive Dependencies) 변조 시 소스 검토만으로 악성 행위 적발 불가 | CI/CD 파이프라인 내에 의존성 락파일(package-lock.json 등) 해시 검증을 의무화하고 가상 샌드박스 동적 행위 분석(Dynamic Analysis) 단계 필수 결합 |
| 수천 개 이상의 클라우드 마이크로서비스 계정 및 API 키 만료 주기가 관리되지 않아 사각지대 발생 | NHI 전용 Discovery 솔루션을 도입하여 미사용/과다권한 키를 전수 매핑하고, 장기 지속 키를 영구 제거한 후 OIDC 기반 단기 토큰 발급으로 전면 전환 |
| 랜섬웨어 공격자가 백업 솔루션 관리자 계정까지 탈취하여 백업 스냅샷을 동시 삭제하는 사태 발생 | 백업 데이터 삭제 시 멀티 유저 인가(Multi-Party Approval)를 의무화하고, 논리적 삭제 불가(WORM Compliance Mode) 스토리지 적용 |
