## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **제로트러스트 가이드라인 2.0**은 조직이 제로트러스트를 설계·도입·평가할 때 참고할 국내 적용 지침 |
| 목적 | 보호요소와 현재 성숙도를 기준으로 조직별 도입·개선 방향 설정 |

가이드라인은 국내 조직의 도입·평가를 돕는 안내이며, 제품 목록이나 일회성 인증으로 구현을 보증하는 제도는 아님.

## Ⅱ. 보호요소와 평가범위

| 보호요소 | 확인 대상의 예 |
|---|---|
| 신원 | 사용자·서비스 계정, 인증·권한 |
| 기기 | 단말 식별·보안상태 |
| 네트워크 | 접속 경로·세그먼트·통신정책 |
| 시스템 | 운영환경·서버·플랫폼 |
| 응용·워크로드 | 업무 애플리케이션·서비스 간 호출 |
| 데이터 | 분류·접근·전송·저장 통제 |

## Ⅲ. 원칙과 성숙도 적용

| 관점 | 적용 내용 |
|---|---|
| 접근 원칙 | 네트워크 위치만으로 신뢰하지 않고 요청 주체와 자원 맥락을 확인 |
| 최소권한 | 업무에 필요한 권한과 자원 범위만 허용 |
| 침해 가정 | 침해 가능성을 전제로 구간 분리·감시·대응 준비 |
| 성숙도 평가 | 조직의 현 수준과 목표 수준을 비교해 단계별 개선과제 선정 |

```text
보호요소별 현황·정책 집행 확인
              ↓
성숙도 평가 → 목표·우선순위 설정
              ↓
통제 적용·연계
              ↓
접근 기록·운영결과로 재평가
```

성숙도는 보호요소별 점검을 통해 개선수준을 판단하는 축이며, 각 보호요소를 서로 다른 성숙도 단계에 일대일로 고정하는 분류가 아님.

## Ⅳ. 도입·검증 방안

| 단계 | 실무 확인 |
|---|---|
| 자산·접근 파악 | 사용자·기기·서비스·데이터와 신뢰경계 식별 |
| 정책 설계 | 보호요소별 접근정책, 조건, 예외·승인 정의 |
| 구현·연계 | 신원·단말·네트워크·로그 간 정책·신호 연동 |
| 검증·개선 | 허용·거부 시나리오, 예외, 기록·대응의 실제 작동 확인 |

## Ⅴ. 한계와 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 평가 체크리스트가 실제 통제 집행을 대신할 수 없음 | 대표 사용자·기기·업무별 접근 시나리오를 시험하고 허용·거부 근거와 기록 확인 |
| 조직마다 자산·기존 체계·목표가 달라 동일한 구축순서가 적절하지 않을 수 있음 | 성숙도와 위험을 기준으로 우선 보호요소를 선정하고 기존 IAM·망분리·로그 체계와 연계 |
