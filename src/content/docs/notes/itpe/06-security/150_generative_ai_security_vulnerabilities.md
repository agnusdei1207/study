## 연관 키워드

- 생성형 AI 보안취약점, LLM, OWASP Top 10 for LLM, 가드레일
- 프롬프트 인젝션, 간접 프롬프트 인젝션, 탈옥, 불안전한 출력 처리
- 학습 데이터 오염, 과도한 자율성, 시스템 프롬프트 유출, RAG
- 벡터·임베딩 취약점, 레드 티밍, DLP, HITL

## Ⅰ. 생성형 AI 보안취약점의 개요

- 핵심 요약 : 자연어로 동작하는 생성형 AI 파이프라인 전 단계에서 생기는 기존 소프트웨어와 다른 구조적 취약점.
- 개념 : **대형 언어 모델** (LLM, Large Language Model)과 이를 쓰는 애플리케이션의 학습, 배포, 추론 과정에서 발생하는 프롬프트 조작, 데이터 오염, 민감정보 노출, 과도한 권한 부여 등의 취약점 총체. 국제 프로젝트 **OWASP** (Open Worldwide Application Security Project)의 **LLM 상위 10대 위험**(OWASP Top 10 for LLM Applications)이 대표적인 분류다.
- 배경 및 필요성 : 생성형 AI가 기업 업무와 고객 서비스에 깊이 들어오면서, SQL 삽입이나 **XSS** (Cross-Site Scripting) 같은 전통적 공격과 달리 자연어 입력 자체가 공격 벡터가 되었다.
- 주요 목적 : 결정론적이지 않은 AI 파이프라인의 취약점을 체계적으로 식별하고, **가드레일** (Guardrail) 같은 다층 방어를 세워 안전하게 운영하는 것.

## Ⅱ. 생성형 AI 보안취약점의 특징 및 장점

- 핵심 요약 : 취약점이 입력, 데이터, 출력, 에이전트 실행의 네 지점에 걸쳐 있어 단계별 통제를 설계해야 하는 특징.

1. 자연어 입력 공격 : 공격자가 지시문을 문장으로 입력하거나 문서에 숨겨 두면 모델이 이를 명령으로 해석 → 입력 필터만으로는 우회가 쉬움.
2. 데이터 의존성 : 학습 데이터와 **RAG** (Retrieval-Augmented Generation)가 검색한 문서가 모델의 행동을 바꾸므로 **학습 데이터 오염** (Training Data Poisoning)이 장기 백도어로 이어질 수 있음.
3. 출력의 실행성 : 모델 응답이 브라우저나 데이터베이스 명령으로 전달되면 **불안전한 출력 처리** (Insecure Output Handling)가 곧 원격 코드 실행으로 이어짐.
4. 에이전트 권한 : 모델이 **API** (Application Programming Interface)를 직접 호출하면 **과도한 자율성** (Excessive Agency)으로 파괴적 작업이 일어날 수 있음 → 권한 최소화가 필요함.

## Ⅲ. 생성형 AI 보안취약점의 구조 (흐름)

- 핵심 요약 : 학습, 추론, 출력·실행 단계마다 서로 다른 취약점이 생기는 전주기 공격 표면.

```text
[ 1. 학습·파인튜닝 단계 ]

학습 데이터 오염 (Data Poisoning)
공급망 취약점 (오염된 모델 파일)
   ↓
[ 2. 추론·RAG 검색 단계 ]

프롬프트 인젝션 (직접·간접)
민감정보 노출
   ↓
[ 3. 출력·에이전트 실행 단계 ]

불안전한 출력 처리 → XSS, SQL 삽입
과도한 자율성 → 비인가 삭제·발송
```

- 공격 표면은 입력과 출력 양쪽에 걸쳐 있으므로, 어느 한쪽만 막는 방어는 대부분 불완전하다.

## Ⅳ. 생성형 AI 보안취약점의 비교

- 핵심 요약 : 직접 인젝션은 입력 단계에서 막을 수 있지만, 간접 인젝션과 데이터 오염은 탐지 난도가 훨씬 높다.

| 비교 항목 | 직접 프롬프트 인젝션 | 간접 프롬프트 인젝션 | 학습 데이터 오염 |
| --- | --- | --- | --- |
| 공격 주체 | 챗봇에 직접 입력하는 사용자 | 웹페이지, 메일 등 외부 문서 작성자 | 학습 데이터 수집 경로의 공격자 |
| 침투 경로 | 입력창에 탈옥 문구 입력 | RAG가 검색한 문서에 지시문 포함 | 사전 학습·파인튜닝 데이터셋 |
| 공격 영향 | 시스템 프롬프트 유출, 유해 응답 | 사용자 모르게 메일 발송, 정보 유출 | 특정 입력 시 백도어 작동, 편향 |
| 탐지 난도 | 보통 (입력 필터로 일부 차단) | 높음 (신뢰된 문서 안에 숨김) | 매우 높음 (대량 데이터 속 은닉) |

- 선택 기준 : 입력 단계 공격은 입력 필터와 권한 분리로, 데이터 단계 공격은 출처 검증과 무결성 관리로 대응하는 것이 기본 원칙이다.

## Ⅴ. 생성형 AI 보안취약점의 한계와 방안

- 핵심 요약 : 입력 필터의 한계, RAG 간접 인젝션, 과도한 자율성을 가드레일 이중화, 문서 권한, 승인 절차로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 자연어 입력의 완전 필터링 불가 | 역할극, 다국어, 인코딩 등으로 탈옥 문구를 계속 우회 | 키워드 차단 대신 입력 의도를 분류하는 별도 가드레일 모델 이중 배치 | 차단 우회 성공률 |
| RAG 문서를 통한 간접 인젝션 | 사내 문서에 숨은 지시문이 검색되어 비인가 명령 실행 | 문서 단위 접근 통제 목록(ACL, Access Control List) 적용과 지시형 문구 정제 | 문서 정제 차단 건수 |
| 과도한 자율성 | 모델이 데이터베이스 수정이나 메일 발송을 직접 실행 | 파괴적 작업마다 사람의 승인을 요구하는 HITL(Human-in-the-Loop) 적용 | 승인 없는 실행 건수 |

## Ⅵ. 생성형 AI 보안취약점에 대한 기술사적 제언

- 핵심 요약 : 입력과 출력을 잇는 가드레일을 상시 운영하고, 공격을 주기적으로 시험하는 레드 티밍을 개발 주기 안에 넣는 방향.

1. 전용 가드레일 계층 도입 : 사용자 입력과 모델 응답 사이에 실시간 검사 계층을 두어, 유해 프롬프트와 개인정보가 오가는 것을 걸러내는 구조가 필요하다. 오픈소스 가드레일 프레임워크는 출발점으로 삼되, 조직 정책에 맞춘 규칙을 별도로 관리해야 한다.
2. 레드 티밍의 정례화 : 개발 조직과 분리된 보안 팀이 최신 탈옥 기법과 데이터 역추출 시험을 정기적으로 수행하고, 그 결과를 모델 배포 기준에 반영하는 절차를 둔다.
3. AI 게이트웨이와 DLP 연동 : 임직원이 외부 AI 서비스를 쓸 때 소스코드나 개인정보가 전송되기 전에 마스킹하거나 차단하도록, 프록시 단계에서 DLP(Data Loss Prevention)를 연동한다.

## Ⅶ. 결론

- 핵심 요약 : 생성형 AI 보안취약점은 자연어라는 입력 형식과 모델의 비결정성 때문에 기존 방어 규칙으로는 다 막을 수 없는 영역.
- 시사점 : 입력을 완벽히 거르기보다, 모델이 할 수 있는 행동의 범위를 권한으로 제한하는 설계가 더 실효적이다.
