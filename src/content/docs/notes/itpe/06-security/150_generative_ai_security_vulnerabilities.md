## 지식 로드맵 내 현재 위치

정보보안 → 인공지능 보안 → 생성형 AI 취약점

## 30초 인출

- **본질:** 생성형 AI 보안취약점은 모델·데이터·도구 연결 과정의 신뢰 경계가 무너지면서 정보 유출이나 비인가 행동을 일으키는 약점.
- **메커니즘:** 공격자가 입력·검색 문서·학습 데이터·도구 응답에 개입하고, 애플리케이션이 이를 권한 있는 지시나 신뢰할 출력으로 처리.
- **통찰:** 한계: 비신뢰 입력이 권한 있는 도구 호출로 이어지면 정보 유출·비인가 실행 가능 → 방안: 입력·도구 간 신뢰 경계를 시험하고 도구 권한을 최소화.

<details>
<summary>핵심 용어</summary>

- **생성형 AI 보안취약점** : 생성형 AI 시스템의 데이터·모델·애플리케이션·도구에서 공격자가 악용할 수 있는 약점.
- **프롬프트 인젝션(Prompt Injection)** : 신뢰할 수 없는 입력이 모델의 원래 지시를 바꾸도록 유도하는 공격.
- **데이터 오염(Data Poisoning)** : 학습·검색 자료 등을 조작해 모델 결과를 왜곡하는 공격.
- **RAG(Retrieval-Augmented Generation)** : 검색한 외부 자료를 모델의 응답 생성에 활용하는 방식.
- **공급망 위험** : 외부 모델·데이터·라이브러리·서비스의 취약점이나 변조가 시스템에 전파되는 위험.
</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 내용 |
|---|---|
| 정의 | **생성형 AI 보안취약점** 은 데이터·모델·도구 연결의 약점으로 정보 유출이나 비인가 행동을 일으킬 수 있는 상태 |
| 목적 | 신뢰 경계를 지켜 민감정보 노출과 잘못된 자동 실행 예방 |

보안 대상은 모델 자체뿐 아니라 검색 자료, 애플리케이션 코드, 사용자 권한, 도구 호출까지 포함.

## Ⅱ. 시스템별 공격 면

```text
생성형 AI 서비스
  ├─ 데이터·RAG ─ 오염·악성 문서
  ├─ 모델·프롬프트 ─ 지시 왜곡
  ├─ 도구·권한 ─ 비인가 호출
  └─ 출력·연계 ─ 유출·악성 결과 전달
```

| 지점 | 공격 예 | 영향 |
|---|---|---|
| 외부 문서·검색 | 악성 지시 삽입 | 응답·도구 행동 왜곡 |
| 학습·모델 공급망 | 데이터·모델 변조 | 편향된 답변·백도어 |
| 도구 연결 | 허용 범위 밖 API 호출 | 데이터 유출·상태 변경 |
| 출력 연계 | 모델 출력을 코드·쿼리로 신뢰 | 후속 시스템 침해 |

## Ⅲ. 프롬프트 인젝션과 권한 경계

```text
신뢰할 수 없는 문서
       ↓ 자료로만 전달
모델의 응답
       ↓ 정책·권한 검사
도구 호출 허용 여부 결정
```

프롬프트만으로 데이터베이스·파일·외부 API의 권한을 통제할 수 없음. 애플리케이션에서 사용자별 인가와 허용 도구·인수를 검증할 필요.

| 경계 | 통제 |
|---|---|
| 입력 → 모델 | 출처 표기, 악성 콘텐츠 탐지 |
| 모델 → 도구 | 도구별 최소 권한, 매개변수 검증 |
| 도구 → 데이터 | 사용자 권한 재확인, 결과 범위 제한 |

### 데이터·모델·출력 검증

```text
외부 자료 등록
    ↓ 출처·무결성 검증
검색·생성
    ↓ 민감정보·형식 검증
후속 시스템에 전달
    ↓ 기록·모니터링
```

| 대상 | 검증 기준 |
|---|---|
| 데이터·모델 | 공급처·버전·변경 이력 |
| RAG 자료 | 신뢰 등급·접근권한·갱신 |
| 응답 | 민감정보, 형식, 근거 자료 |
| 운영 | 악성 입력 시험, 도구 호출 로그 |

## Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 악성 입력을 모두 탐지하려 하면 새로운 표현의 공격에 취약 | 탐지와 별개로 권한 경계·도구 인가·출력 검증을 독립 통제 |
| 모델의 안전 응답만 확인하면 도구 실행과 데이터 유출 경로를 놓침 | 외부 문서에서 최종 API 호출까지 이어지는 공격 시나리오로 시험 |

## Ⅴ. 제언

외부 문서에서 권한 있는 도구 실행까지의 경로를 첫 위협 모델로 정하고 도구 권한·출력 검증을 시험.
