## 30초 인출

- **본질:** 생성형 AI 활용 보안 가이드라인은 조직 구성원이 AI 서비스를 사용할 때 정보 유출과 잘못된 결과 활용을 줄이기 위한 업무 규칙.
- **메커니즘:** 승인 서비스 선택 → 입력 자료 등급 확인 → 생성 결과 검증 → 사용 이력·사고 관리.
- **핵심:** 입력 허용 범위와 업무 결과의 검토 책임.

<details>
<summary>핵심 용어</summary>

- **생성형 AI 활용 보안 가이드라인**: 조직의 AI 서비스 사용 범위·정보 입력·결과 검토·사후 관리를 정하는 지침.
- **DLP(Data Loss Prevention)**: 중요정보의 무단 외부 유출을 탐지·차단하는 통제.
- **환각(Hallucination)**: 모델이 근거가 없거나 사실과 다른 내용을 그럴듯하게 생성하는 현상.
- **AI(Artificial Intelligence)**: 데이터와 계산을 이용해 인식·예측·생성 등의 과제를 수행하는 기술.

## 2~4교시 25점 답안

## Ⅰ. 생성형 AI 활용 보안 가이드라인의 정의와 목적

| 구분 | 내용 |
|---|---|
| 정의 | **생성형 AI 활용 보안 가이드라인**은 조직의 AI 서비스 사용·정보 입력·결과 검토 규칙 |
| 목적 | 업무정보 유출과 검증되지 않은 생성 결과의 업무 반영 예방 |

과학기술정보통신부·한국인터넷진흥원의 「인공지능(AI) 보안 안내서」 같은 공개 자료는 참고 기준. 특정 조직의 법적 의무나 명칭이 고정된 ‘3대 원칙’으로 단정하지 않는 구분 필요.

## Ⅱ. 업무 사용의 통제 지점

```text
업무용 생성형 AI 활용
  ├─ 서비스 선택 ─ 승인된 계정·계약
  ├─ 입력 ─ 정보 등급·제공 가능 범위
  ├─ 출력 ─ 사실·권리·보안 검토
  └─ 운영 ─ 이용 기록·사고 대응
```

| 지점 | 위험 | 통제 |
|---|---|---|
| 서비스 선택 | 승인되지 않은 외부 도구 사용 | 공급자 조건과 데이터 처리 방식 검토 |
| 입력 | 개인정보·기밀 유출 | 등급별 입력 허용 기준 |
| 출력 | 허위 정보·권리 침해 | 원문·공식 자료 대조 |
| 운영 | 사고 발견 지연 | 이용 기록·신고 절차 |

## Ⅲ. 사용자 업무 규칙

```text
사용 전 ─ 서비스·자료의 사용 가능 여부 확인
사용 중 ─ 업무에 필요한 최소 정보만 입력
사용 후 ─ 결과의 사실·기밀성 검토
업무 반영 ─ 담당자의 최종 확인
```

| 상황 | 점검 항목 |
|---|---|
| 고객 정보 입력 | 적법한 처리 근거·서비스 제공 조건 |
| 소스코드 입력 | 비공개 정보의 외부 제공 가능 여부 |
| 결과 인용 | 사실·출처·저작권 |

## Ⅳ. 관리자 운영 통제

```text
서비스 승인
    ↓ 계약·저장·접근권한 검토
정책 배포
    ↓ 계정·정보 반출 통제
사용 현황 점검
    ↓ 사고 대응과 정책 보완
```

| 관리 항목 | 확인 기준 |
|---|---|
| 서비스 등록 | 데이터 보존·학습 사용·삭제 조건 |
| 접근권한 | 승인된 사용자와 업무 |
| 교육·점검 | 구체적인 허용 사례·위반 처리 |
| 사고 대응 | 신고 채널·영향 범위·조치 기록 |

## Ⅴ. 한계와 제언

| 한계 | 대응 |
|---|---|
| “민감정보 입력 금지”만으로는 사용자가 경계를 판단하기 어려움 | 데이터 등급별 실제 사례와 입력 대체 방법 제공 |
| 결과 검토 책임을 선언만 하면 형식화 | 중요한 업무별 원문 대조·승인자·기록 기준 설정 |
