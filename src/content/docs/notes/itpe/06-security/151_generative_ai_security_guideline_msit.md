## 지식 로드맵 내 현재 위치

지식 위치: 정보보안 → 인공지능 보안 → **생성형 AI 활용 지침**

## 30초 인출

- **본질:** 조직 구성원의 생성형 AI 도입 및 활용 과정에서 발생할 수 있는 기업 기밀 유출, 개인정보 침해, 환각 결과 오용을 방지하기 위해 과기정통부·KISA가 수립한 생명주기 보안 통제 지침
- **메커니즘:** 승인된 엔터프라이즈 AI 선별 $\rightarrow$ 인라인 CASB/DLP 기반 프롬프트 민감정보 마스킹 $\rightarrow$ 옵트아웃(Zero Data Retention) 계약 $\rightarrow$ 생성 소스코드 SAST/SCA 검증
- **통찰:** 단순 사규 선언은 복사-붙여넣기 유출을 막지 못하므로 CASB 프롬프트 인라인 필터링과 코드 패키지 슬롭스쿼팅 방지 파이프라인 결합 필수

<details>
<summary>핵심 용어</summary>

- **생성형 AI 보안 가이드라인** : AI 서비스 도입·활용·개발 전 주기에 걸친 보안 요구사항을 정의한 정부 지침.
- **CASB (Cloud Access Security Broker)** : 사내 사용자와 외부 생성형 AI SaaS 간 트래픽을 중계하며 DLP를 집행하는 솔루션.
- **Slopsquatting (패키지 환각)** : LLM이 환각으로 지어낸 가짜 오픈소스 패키지명을 공격자가 등록하여 감염시키는 공급망 공격.
- **ZDR (Zero Data Retention)** : 기업이 입력한 프롬프트와 생성 데이터를 공급자 모델 재학습에 활용하지 않고 즉시 파기하는 계약 조건.

</details>

## 2~4교시 예상문제 (25점)

> 과기정통부 및 KISA의 생성형 AI 보안 가이드라인을 기반으로 기업의 AI 도입 시 주체별(이용자, 개발사, 보안관리자) 핵심 통제 항목을 설명하고, 소스코드 및 개인정보 유출 방지를 위한 엔지니어링 아키텍처를 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 기업 및 공공기관이 생성형 AI(ChatGPT, Claude 등) 서비스를 업무에 안전하게 도입하고 활용할 수 있도록 과학기술정보통신부와 KISA가 제정한 인공지능 전주기 보안 원칙 및 운영 지침 |
| 목적 | 임직원의 무분별한 프롬프트 입력으로 인한 기업 핵심 영업비밀(소스코드, 기밀문서) 및 개인정보 유출을 방지하고 생성물의 법적·보안적 신뢰성 확보 |

- AI 기술의 비즈니스 생산성 혁신을 지원하면서도 섀도우 AI(Shadow AI)의 무단 사용과 공급망 침해를 통제하는 기업 거버넌스의 표준 기준

## Ⅱ. 생성형 AI 활용 가이드라인의 핵심 특성

| 특성 항목 | 세부 내용 및 기술적 의미 | 엔지니어링 구현 가치 |
|---|---|---|
| 역할별 차등 가이드라인 | 최종 이용자, 서비스 개발사, 기업 인프라 관리자 등 역할별 책임 분계 명확화 | 전사 R&R 수립 및 계층별 보안 정책 적용 용이 |
| 전주기 라이프사이클 통제 | 서비스 기획 $\rightarrow$ 데이터 수집 $\rightarrow$ 프롬프트 입력 $\rightarrow$ 결과물 검증 $\rightarrow$ 폐기 전 과정 통제 | 단발성 검증이 아닌 엔드투엔드 거버넌스 확립 |
| 데이터 주권 및 재학습 차단 | 모델 제공업체(CSP)와의 계약 시 입력 데이터의 재학습(Training) 배제 조항 명문화 | 기업 기밀이 타사 답변으로 재생성되는 위험 원천 차단 |
| 생성물 인간 중심 검증 (HITL) | 환각(Hallucination), 편향, 저작권 침해 방지를 위해 최종 결과물의 인간 검토 의무화 | 인공지능 의사결정으로 인한 법적·윤리적 리스크 방어 |

- 기술적 차단 도구(CASB, DLP)와 관리적 보안 교육(Awareness)을 상호 보완적으로 통합하는 하이브리드 거버넌스 특성 보유

## Ⅲ. 엔터프라이즈 생성형 AI 보안 통제 아키텍처 및 데이터 흐름

```text
[엔터프라이즈 생성형 AI 프롬프트 필터링 및 소스코드 보안 아키텍처]

  [사내 임직원 PC / 개발자]
            │
            ▼ (외부 생성형 AI 웹/API 접속 시도)
  ┌─────────────────────────────────────────────────────────────┐
  │                 1. 네트워크 및 CASB 게이트웨이 계층         │
  │   - 비인가 개인용 무료 AI 도구(Shadow AI) 접근 전면 차단   │
  │   - 기업 승인 전용 Enterprise AI 포털로 강제 리다이렉트     │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
  ┌──────────────────────────────┴──────────────────────────────┐
  │              2. 인라인 프롬프트 검사 계층 (Prompt DLP)       │
  │   - PII 탐지: 주민번호, 이메일, 전화번호 실시간 자동 마스킹│
  │   - 기밀 탐지: API Secret Key, 사내 소스코드 정규식 차단   │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
                                 ▼ (정제된 프롬프트 전송: TLS 1.3)
  ┌─────────────────────────────────────────────────────────────┐
  │                 3. 상용 생성형 AI 서비스 (Enterprise API)   │
  │   - Zero Data Retention (ZDR) 계약 체결 (모델 재학습 금지) │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
                                 ▼ (생성 코드/답변 반환)
  ┌─────────────────────────────────────────────────────────────┐
  │              4. 결과물 무결성 및 공급망 검증 계층           │
  │   - 생성된 소스코드 Git 커밋 전 SAST/SCA 정적 취약점 분석  │
  │   - 패키지 환각(Slopsquatting) 방지 라이브러리 검증        │
  └─────────────────────────────────────────────────────────────┘
```

| 라이프사이클 단계 | 핵심 엔지니어링 통제 활동 | 기술 솔루션 및 도구 |
|---|---|---|
| 1. 서비스 도입 단계 | 엔터프라이즈 B2B 계약 체결, 재학습 방지 및 데이터 보관 기간(0일) 명시 | ZDR(Zero Data Retention) SLA 체결 |
| 2. 입력 전송 단계 | 사용자 프롬프트 텍스트를 실시간 DPI 분석하여 기밀 정보 인라인 차단 | CASB, 네트워크 DLP, 프롬프트 게이트웨이 |
| 3. 추론 및 모델 단계 | 데이터 전송 전 개인정보 가명화/익명화 처리 및 세션별 토큰 분리 | 자체 API 프록시 익명화 모듈 |
| 4. 결과 활용 단계 | LLM이 생성한 코드의 시큐어 코딩 규칙 준수 및 가짜 패키지 설치 차단 | SAST (SonarQube), SCA (Snyk, Dependency-Check) |

## Ⅳ. 생성형 AI 주체별 가이드라인 요구사항 비교

| 비교 항목 | 서비스 이용자 (일반 임직원) | 기업 서비스 개발사 (DevOps) | 보안 관리자 (CISO/Security Team) |
|---|---|---|---|
| 핵심 보안 목표 | 비인가 중요 기밀 정보 입력 방지 | 안전한 모델 파이프라인 및 앱 구현 | 전사 AI 거버넌스 및 자산 가시성 확보 |
| 주요 준수 사항 | 개인정보, 소스코드, 미공개 실적 입력 금지 | Safetensors 모델 포맷 적용, RAG 검증 | CASB 기반 섀도우 AI 차단 정책 수립 |
| 결과물 검증 책임 | 사실 여부 확인, 환각 결과 원문 대조 | 출력 인코딩, XSS/SQLi 주입 방어 | 전사 생성형 AI 사용 이력 감사 로깅 |
| 공급망 관리 | 승인된 기업용 계정만 로그인 사용 | 오픈소스 모델 가중치 악성코드 검증 | CSP의 보안 인증(SOC2, CSAP) 검토 |
| 위반 시 대응 | 보안사고 신고 채널을 통한 즉시 보고 | 취약 API 엔드포인트 긴급 롤백 | 계정 즉각 회수 및 네트워크 차단 |

## Ⅴ. 생성형 AI 가이드라인 적용 시 엔지니어링 한계와 해결 방안

| 한계 | 방안 |
|---|---|
| 단순 "민감정보 입력 금지" 사규 공지만으로는 개발자나 실무자의 브라우저 복사-붙여넣기(Copy & Paste) 유출 행위를 원천 차단 불가 | 엔드포인트 EDR/DLP 솔루션과 CASB 인라인 프록시를 결합하여 웹 브라우저 클립보드 이벤트 및 HTTP POST 본문 내 소스코드/API 키 정규식 패턴 실시간 감지 및 전송 강제 Drop |
| 무료 개인용 AI 모델 사용 시 입력된 사내 기밀 프롬프트가 CSP의 차세대 모델 사전학습/RLHF 데이터셋으로 흡수되어 경쟁사 질의에 유출 | 전사 방화벽에서 일반 퍼블릭 AI 도메인 접속을 전면 차단하고, 계약상 ZDR(Zero Data Retention)이 법적으로 보장된 기업 전용 엔터프라이즈 테넌트(Azure OpenAI 등)로만 접근 강제 |
| LLM이 존재하지 않는 허위 라이브러리/패키지명을 그럴듯하게 환각 추천하고, 공격자가 이를 노려 악성 패키지를 등록 배포하는 슬롭스쿼팅(Slopsquatting) 공격 | 사내 CI/CD 파이프라인에 내부 프라이빗 아티팩토리(Nexus, Artifactory)를 강제 경유하도록 구성하고, 공식 승인된 화이트리스트 패키지 외 외부 미등록 패키지의 자동 다운로드 전면 차단 |
| 임직원이 외부 AI 서비스를 경유하여 요약된 고객 개인정보를 무단 처리할 경우 개인정보보호법상 국외 이전 및 제3자 제공 위반 발생 | 프롬프트 입력 게이트웨이에 로컬 자연어 PII 추출 엔진(Presidio 등)을 탑재하여 이름, 주민번호, 계좌번호를 가상 토큰(`[PERSON_1]`)으로 자동 치환 후 LLM에 전송하고 수신 시 복원 |

## Ⅵ. 안전한 엔터프라이즈 AI 활용을 위한 3대 거버넌스 제언

```text
[성공적인 생성형 AI 전사 보안 거버넌스 확립 로드맵]

 ┌─────────────────────────────────────────────────────────────┐
 │                 1. 관리 및 제도 계층 (Policy First)         │
 │   - 사내 생성형 AI 윤리 및 보안 수칙 제정                   │
 │   - 데이터 민감도 등급별 AI 입력 허용 매트릭스 배포         │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │              2. 기술적 통제 계층 (Technical Controls)        │
 │   - CASB / DLP 연동 인라인 프롬프트 마스킹 게이트웨이 구축  │
 │   - CI/CD 파이프라인 내 생성 코드 자동 취약점 진단 강제     │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │                 3. 지속적 감사 계층 (Audit & Logging)        │
 │   - 프롬프트 요청 및 응답 메타데이터 감사 로그 1년 보존     │
 │   - 비정상 대량 프롬프트 유출 시 이상 징후 실시간 경보      │
 └─────────────────────────────────────────────────────────────┘
```

| 관리 영역 | 핵심 엔지니어링 세부 과제 | 통제 목표치 |
|---|---|---|
| 섀도우 AI 차단 | 비인가 외부 AI 도메인(개인 계정) 네트워크 접근 차단율 | 비인가 AI 접속 차단율 100% |
| 프롬프트 보안 | 프롬프트 내 민감정보(주민번호, 시크릿키) 자동 탐지 및 마스킹 | 민감정보 외부 누출 건수 0건 |
| 코드 공급망 | LLM 생성 코드의 배포 전 보안 취약점 및 가짜 패키지 검사 | AI 생성 코드 취약점 유입률 0% |

## 출제 이력과 검증 출처

- 제133회 정보관리기술사 예상 연계 주제: 과학기술정보통신부 생성형 AI 보안 가이드라인
- 과학기술정보통신부·KISA: 인공지능(AI) 서비스 개발·활용 보안 안내서
- 개인정보보호위원회: 생성형 AI 개인정보보호 정책방향 및 프라이버시 가이드라인
- NIST AI 600-1: Artificial Intelligence Risk Management Framework: Generative AI Profile
- CSA (Cloud Security Alliance): Security Implications of Generative AI in the Enterprise
