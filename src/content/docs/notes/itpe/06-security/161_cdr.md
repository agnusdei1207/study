## Ⅰ. CDR(Content Disarm and Reconstruction)의 개요

- **개념** : 이메일, 웹 다운로드, USB 등을 통해 조직 내부로 유입되는 문서 파일(MS Office, PDF, HWP 등) 내부에서 악성코드 시그니처나 행위를 탐지하는 대신, 파일 구조를 분해하여 매크로, 액티브 콘텐츠, 하이퍼링크 등 잠재적 위협 요소를 원천 제거(Disarm)한 후 안전한 시각적 구성 요소만 추출하여 깨끗한 정품 파일로 재조합(Reconstruct)하는 선제적 콘텐츠 무해화 기술.
- **배경 및 필요성** : 전통적인 시그니처 기반 백신과 샌드박스는 제로데이 취약점 문서나 정교한 샌드박스 탐지 회피(Sleep 호출, 가상머신 판별) 기술을 탑재한 신종 악성 문서를 사전에 걸러내지 못함.
- **핵심 목적** : 악의적인 의도가 있는지 판별하느라 시간을 허비하지 않고 모든 액티브 콘텐츠를 잠재적 위협으로 간주하여 제거함으로써, 제로데이 문서형 악성코드를 제로 레이턴시로 원천 차단.

## Ⅱ. CDR(Content Disarm and Reconstruction)의 핵심 아키텍처 및 동작 메커니즘

CDR은 파일 파싱(Parsing), 위험 요소 격리 및 분해(Disarm), 무해한 정적 데이터 추출(Extraction), 원본 포맷 무결 재구성(Reconstruction)의 4단계 파이프라인으로 수행됨.

```text
[ CDR(Content Disarm and Reconstruction) 4단계 무해화 파이프라인 ]

 [ 외부 유입 파일 (이메일 첨부 문서: 견적서.docx / 이력서.pdf) ]
   * 잠재적 위협 은닉: 악성 매크로(VBA), 임베디드 OLE 객체, 익스플로잇 쉘코드
                           |
                           v
 +-------------------------------------------------------------+
 | 1. 파싱 (Parsing) : 파일 포맷 명세 표준에 따른 구조적 분해   |
 |  - 헤더, 본문 텍스트, 이미지, 폰트, 매크로 스트림 객체 식별|
 +------------------------------+------------------------------+
                                |
                                v
 +-------------------------------------------------------------+
 | 2. 분해 (Disarm) : 실행 가능한 잠재적 위협 요소 원천 제거   |
 |  [제거 대상] : VBA 매크로, 자바스크립트, Flash, OLE 개체,    |
 |                외부 자동 호출 하이퍼링크, 실행 파일(.exe)    |
 +------------------------------+------------------------------+
                                |
                                v
 +-------------------------------------------------------------+
 | 3. 추출 (Extraction) : 안전성이 검증된     순수 요소만 격리|
 |  [안전 자산] : 순수 텍스트, 정적 이미지(JPG/PNG), 레이아웃  |
 +------------------------------+------------------------------+
                                |
                                v
 +-------------------------------------------------------------+
 | 4. 재구성 (Reconstruction) : 새로운 백지 파일에 클린 재조합 |
 |  - 원본과 시각적으로 완전히 동일한 새로운 docx/pdf 파일 생성|
 +------------------------------+------------------------------+
                                |
                                v
 [ 무해화 완료 안전 파일 (Clean Document) -> 내부 사용자에게 안전 배포! ]
```

- **실행 가능 객체(Active Content) 전면 제거** : 문서 파일 내에 포함될 수 있는 VBA 매크로, 파워포인트 액션, PDF 임베디드 자바스크립트, OLE 패키지 등 코드가 실행될 수 있는 모든 메커니즘을 원천 살균.
- **원본 포맷의 시각적 무결성 보존** : 단순히 파일을 텍스트나 저화질 이미지(PDF 인쇄)로 변환하는 것이 아니라, 원본 문서의 폰트, 서식, 표, 고화질 그래픽을 유지한 채 실행 코드만 제거하여 새 파일로 빌드.
- **제로데이(0-day) 취약점 완벽 방어** : 시그니처를 모르는 신규 오피스 취약점(Follina 등)이라도 취약점을 트리거하는 객체 구조 자체가 분해 과정에서 버려지므로 완벽 무력화.
- **초고속 실시간 처리 속도** : 가상머신에서 수 분간 실행을 지켜봐야 하는 샌드박스와 달리, 수백 밀리초(ms) 단위의 파일 파싱 및 재생성만으로 완료되므로 사용자 업무 지연 제로.

## Ⅲ. CDR(Content Disarm and Reconstruction)의 세부 구성 요소 및 비교 분석

| 비교 항목 | CDR (콘텐츠 무해화 및 재구성) | 안티바이러스 (백신) | 지능형 샌드박스 (Sandbox) |
| --- | --- | --- | --- |
| 동작 원리 | 잠재 위험 요소 원천 제거 후 재구성 | 알려진 악성 패턴(시그니처) 대조 | 가상 격리 환경에서 파일 실행 후 행위 관찰 |
| 처리 속도 | 극도로 빠름 (수초 이내 완료) | 극도로 빠름 (패턴 매칭) | 매우 느림 (수 분 이상 행위 관찰 지연) |
| 제로데이 방어 | 완벽 방어 (모든 코드 원천 살균) | 방어 불가 (시그니처 부재 시 통과) | 부분 방어 (샌드박스 탐지 회피에 취약) |
| 문서 기능 영향 | 정상 매크로도 함께 제거됨 | 문서 내용 원형 유지 | 문서 내용 원형 유지 |
| 오탐/미탐 리스크 | 오탐/미탐 개념 없음 (전수 무해화) | 미탐률 높음 (변종 악성코드) | 미탐(회피 기법) 및 오탐 발생 |

- CDR은 기존 탐지 중심 보안 패러다임을 '선제적 무해화'로 혁신한 기술이며, 지능형 샌드박스 및 백신과 결합한 3중 방어 파이프라인으로 구성할 때 최상의 실효성을 발휘함.

## Ⅳ. CDR(Content Disarm and Reconstruction)의 주요 한계점 및 해결 방안

- **업무상 정상적인 매크로(VBA) 사용 문서의 기능 무력화** :
  - **한계점** : 재무, 회계 부서에서 정상적으로 사용하는 복잡한 엑셀 매크로 수식까지 일괄 제거되어 정상적인 업무 처리가 불가능해지는 사용성(Usability) 충돌.
  - **해결 방안** : 부서 및 사용자 정책 기반으로 신뢰된 발신자의 매크로는 별도 격리 샌드박스로 우회시키는 화이트리스트 예외 정책 결합.
- **복잡한 비표준 문서의 재구성 시 레이아웃 깨짐 현상** :
  - **한계점** : 국내 전용 아래아한글(HWP/HWPX)이나 복잡한 CAD 도면, 특수 차트가 포함된 문서의 경우 분해 후 재조합 시 서식이 깨지거나 폰트 뒤틀림 발생.
  - **해결 방안** : 국내 소프트웨어 표준(HWP 바이너리 및 OWPML)을 완벽히 지원하는 전용 토종 CDR 파서 엔진 채택 및 지속적 렌더링 검증.
- **압축 파일(ZIP) 다중 중첩 및 암호화 파일의 무해화 한계** :
  - **한계점** : 공격자가 암호를 설정한 ZIP/7z 압축 파일이나 다중 압축 문서로 유입시킬 경우 CDR 엔진이 내부를 파싱하지 못하고 패스.
  - **해결 방안** : 이메일 게이트웨이에서 암호화 첨부파일의 수신을 기본 격리하고, 수신자가 직접 비밀번호를 입력하여 복호화 후 CDR을 거치도록 강제.

## Ⅴ. CDR(Content Disarm and Reconstruction) 적용 및 발전을 위한 기술사적 제언

- **보안 이메일 게이트웨이(SEG) 및 망연계 시스템 연동 필수화** : 외부 인터넷망에서 사내 업무망으로 유입되는 망연계 파일 전송 구간과 웹메일 첨부파일 검사 단계에 CDR 엔진을 인라인으로 의무 배치.
- **웹 사이트 파일 업로드 게시판의 CDR 선제 정제** : 대고객 서비스 게시판(입사지원서, 민원 접수)에 사용자가 업로드하는 모든 첨부파일에 대해 CDR 무해화를 즉시 거친 후 스토리지에 저장.
- **CDR + AI 샌드박스 하이브리드 인텔리전스 구성** : CDR로 무해화된 안전한 문서를 사용자에게 즉시 전달하여 업무 연속성을 보장함과 동시에, 원본 파일은 백그라운드 샌드박스에서 정밀 분석하여 위협 인텔리전스 DB에 시그니처 축적.
