## 지식 로드맵 내 현재 위치

- 정보보안 → 엔드포인트 및 콘텐츠 보안 → 파일 무해화 → CDR(Content Disarm and Reconstruction)

```text
[외부 유입 파일 (PDF, DOCX, HWP)] ──> [파일 파싱 및 액티브 요소 식별]
                                              │
                                              ├── 악성 매크로/OLE 객체/스크립트 제거 (Disarm)
                                              └── 텍스트/이미지 등 안전한 콘텐츠 추출
                                              │
                                              ▼
                               [표준 스키마 기반 무해화 파일 재구성 (Reconstruct)]
```

---

## 30초 인출

- **본질:** 유입되는 문서 파일의 내부 구조를 분해하여 실행 가능한 액티브 콘텐츠(매크로, 자바스크립트, 임베디드 OLE)를 제거하고 안전한 시각 데이터만 선별하여 깨끗한 정규 파일로 재구성하는 기술.
- **메커니즘:** 파일 포맷 파싱 → 위험 요소(VBA Macro, PE Shellcode, XML 외부 엔티티) 제거(Disarm) → 안전한 텍스트·벡터·래스터 이미지 추출 → 표준 규격에 맞춘 신규 파일 재생성(Reconstruct).
- **통찰:** 악성코드 유무를 탐지하는 수동적 방식에서 벗어나 제로 트러스트 관점에서 모든 잠재적 실행 요소를 제거하되, 업무 서식 및 합법 매크로 유실 문제를 해결하기 위해 안전 뷰어 변환과 단계적 원본 격리 정책 결합 필수.

## 2~4교시 예상문제 (25점)

> 이메일 첨부파일 및 망연계 시스템을 통한 지능형 제로데이(Zero-day) 공격 방어를 위한 CDR(Content Disarm and Reconstruction)의 동작 원리, 처리 절차를 설명하고, 전통적 안티바이러스 및 샌드박스와 비교 분석하시오. (25점)

---

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 유입되는 파일의 내부 구조를 분해하여 악성 행위를 유발할 수 있는 액티브 콘텐츠를 원천 제거하고, 안전한 원천 데이터만을 추출하여 새로운 정상 문서로 재조합하는 기술 |
| 목적 | 시그니처 미등록 제로데이 공격 및 샌드박스 우회(Evasion) 악성코드를 탐지 과정 없이 원천 무력화하여 무결한 문서 파일만 내부망으로 반입 |

- 악성 여부를 '판정(Detection)'하지 않고 모든 실행 가능 요소를 잠재적 위협으로 간주하는 제로 트러스트(Zero Trust) 파일 보안의 핵심 기술.

---

## Ⅱ. CDR의 핵심 특징 및 무해화 대상 요소

### 1. CDR의 핵심 특징

| 특징 | 설명 | 세부 구현 내용 |
|---|---|---|
| 탐지 비의존성 | 악성 시그니처 유무와 무관한 정제 | 알려지지 않은 제로데이 취약점 익스플로잇도 실행 코드가 배제되므로 무력화 |
| 결정론적 방어 | 100% 실행 요소 배제 보증 | 의심스러운 요소를 격리하는 대신 허용된 정적 텍스트와 래스터 그래픽만 재구성 |
| 가용성 유지 | 사용자의 문서 가독성 보존 | 텍스트 레이아웃, 폰트, 표, 이미지를 유지하여 원본과 동일한 시각적 경험 제공 |
| 포맷 정규화 | 비표준 구조 및 오버플로우 제거 | 파서 버그를 유발하는 비정상 메타데이터 필드 및 널 바이트 삽입 패턴 정제 |

### 2. 주요 무해화 제거 대상 액티브 요소

```text
[파일 내 무해화 대상 위협 요소]
  ├── 오피스 문서 (DOCX, XLSX) ──> VBA 매크로, DDE(Dynamic Data Exchange) 링크, 악성 외부 템플릿
  ├── PDF 문서                 ──> JavaScript 실행 구문, 임베디드 론칭 액션(/Launch), 오픈 액션(/OpenAction)
  ├── 한글 문서 (HWP/HWPX)     ──> PostScript 셸코드 인젝션, OLE 자동실행 객체, 악성 하이퍼링크
  └── 이미지 파일 (PNG, JPG)   ──> 스테가노그래피(Steganography) 은닉 데이터, EXIF 내 스크립트 코드
```

## Ⅲ. CDR 4단계 처리 메커니즘 및 시스템 연동 아키텍처

### 1. CDR 무해화 및 재구성 4단계 프로세스

```text
+-----------------------------------------------------------------------------------------+
|                                   CDR 4단계 처리 프로세스                                |
+-----------------------------------------------------------------------------------------+
  [1단계: 파일 수신 및 파싱] ──> [2단계: 콘텐츠 분해] ──> [3단계: 위험요소 제거] ──> [4단계: 클린 파일 재구성]
  - 매직 넘버 검증 (진위 판별)  - 텍스트/이미지 추출   - VBA 매크로 삭제      - 표준 규격 신규 생성
  - 파일 내부 구조 트리화       - 하이퍼링크/폰트 분리  - 악성 자바스크립트 소거 - 레이아웃 매핑
  - 압축 파일 다단계 해제       - 메타데이터 검증      - OLE 바이너리 박탈    - 디지털 서명 및 전달
+-----------------------------------------------------------------------------------------+
```

### 2. 엔터프라이즈 망연계 및 이메일 연동 아키텍처

```text
[외부 유입 채널] 
  ├── 이메일 첨부파일 (SMTP) ────┐
  ├── 웹 업로드 (HTTP POST) ─────┼──> [CDR 게이트웨이 파이프라인] ──> [무해화 완료 파일] ──> [내부 업무망]
  └── 망간 자료전송 시스템 ──────┘            │
                                               ├── 1차: 안티바이러스 멀티엔진 스캔
                                               ├── 2차: CDR 엔진 (분해 → 무해화 → 재구성)
                                               └── 3차: 원본 파일 격리 보관소(Vault) 저장
```

## Ⅳ. 전통적 파일 보안(백신, 샌드박스) vs CDR 기술 비교

### 1. 파일 보안 기술 3종 비교

| 비교 항목 | 안티바이러스 (AV) | 동적 샌드박스 (Sandbox) | 콘텐츠 무해화 및 재구성 (CDR) |
|---|---|---|---|
| 기본 원리 | 알려진 악성 패턴(시그니처) 매칭 | 가상 머신 환경 내 동적 행위 분석 | 파일 분해 후 안전한 데이터만 재구성 |
| 제로데이 방어 | 불가능 (시그니처 부재 시 통과) | 부분 가능 (행위 발생 시 탐지) | 완벽 방어 (액티브 요소 원천 삭제) |
| 분석 소요 시간 | 수 밀리초 (실시간 처리 가능) | 수 분 (동적 실행 대기 시간 필요) | 수 초 이내 (포맷 파싱 및 재생성) |
| 우회 가능성 | 패킹, 난독화, 다형성 악성코드 우회 | 슬립(Sleep) 공격, 안티 VM 기법 우회 | 우회 불가 (실행 코드 자체를 전달 안함) |
| 문서 원본성 | 원본 파일 그대로 유지 | 원본 파일 그대로 유지 | 매크로, 동적 수식, 양식 일부 유실 가능 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 재무, 회계, 생산 라인에서 필수적으로 사용하는 정상적인 업무용 VBA 매크로 및 동적 수식이 일괄 제거되어 업무 마비 초래 | 업무별 정책 기반 차등 무해화(Selective Sanitization)를 적용하고, 사내 코드 서명 인증서로 검증된 매크로는 예외 허용하는 화이트리스트 결합 |
| 다양한 독자 포맷(HWP, 특수 CAD 도면, 압축 아카이브) 파싱 중 버퍼 오버플로우 등 CDR 파서 자체 취약점을 노린 익스플로잇 공격 노출 | CDR 처리 엔진을 Rust 등 메모리 안전 언어로 재작성하고, 파싱 프로세스를 컨테이너 및 Seccomp 기반 샌드박스 내부로 완전 격리 |
| 대용량 복합 문서(수백 페이지 PDF, 수천 행 엑셀) 처리 시 과도한 CPU 연산으로 인한 망연계 지연 및 대기열(Queue) 병목 현상 | 분산 큐(Kafka/RabbitMQ) 기반 마이크로서비스 워커 풀을 구성하고, 정적 분석으로 1차 필터링 후 텍스트 기반 스트리밍 재구성 파이프라인 적용 |

## Ⅵ. 제언

### 1. 차세대 하이브리드 파일 보안 파이프라인

```text
[파일 유입] ──> [멀티 AV 스캔] ──(위험 탐지)──> [즉시 차단 (Drop)]
                     │ (정상 판단)
                     ▼
              [동적 CDR 엔진] ──> [무해화 재구성 완료] ──> [사용자 전달]
                     │
                     └──(비동기 병렬 전송)──> [AI 샌드박스 심층 행위 분석 (CTI 축적)]
```

### 2. 파일 무해화 도입 전략 비교 평가

| 도입 방식 | 처리 성능 | 보안 완결성 | 사용자 편의성 | 적합 대상 조직 |
|---|---|---|---|---|
| PDF 변환 방식 (Flattening) | 매우 빠름 | 최고 (이미지화) | 낮음 (텍스트 복사/수정 불가) | 민원 신청 서류, 열람 전용 공공 포털 |
| 스키마 정제 방식 (Structural CDR) | 보통 | 높음 (표준 준수) | 최고 (원본 편집성 완벽 유지) | 일반 기업 업무망, 그룹웨어 결재 시스템 |
| 샌드박스 결합 하이브리드 | 느림 (병렬) | 최상 (다계층) | 높음 (업무 연속성 보장) | 국가 주요 기반시설, 금융사 망연계망 |

- CDR은 기존 탐지 체계를 대체하는 것이 아니라 제로 트러스트 원칙에 기반하여 탐지 실패를 대비하는 심층 방어의 최후 방어선으로 정립 필요.
