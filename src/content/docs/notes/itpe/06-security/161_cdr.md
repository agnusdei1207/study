## 30초 인출

- **본질:** CDR은 문서에서 업무에 필요한 내용만 추출해 안전한 형식으로 다시 만들고 위험한 활성 요소를 제거하는 파일 보안 방식.
- **메커니즘:** 파일 형식 확인 → 구조 분석 → 허용 콘텐츠 추출 → 새 파일로 재구성.
- **핵심:** 악성코드 탐지와 다른 접근이며 원본의 기능·서식이 일부 사라질 수 있어 업무 적합성 확인 필요.

<details>
<summary>핵심 용어</summary>

- **CDR(Content Disarm and Reconstruction)**: 문서의 필요한 내용을 분리하고 위험한 요소를 제거한 뒤 새 파일로 재구성하는 기술.
- **활성 콘텐츠**: 매크로·스크립트·임베디드 객체처럼 문서를 열거나 처리할 때 실행될 수 있는 요소.
- **파일 파서**: 파일 형식의 내부 구조를 해석하는 프로그램.
- **샌드박스**: 의심 파일을 격리된 환경에서 실행·관찰하는 분석 방식.
- **허용목록**: 승인한 파일 형식·기능만 처리 대상으로 정하는 기준.
</details>

## 2~4교시 25점 답안

## Ⅰ. CDR의 정의와 목적

| 구분 | 내용 |
|---|---|
| 정의 | **CDR(Content Disarm and Reconstruction)**은 파일에서 필요한 콘텐츠만 추출해 새 파일로 재구성하는 보안 방식 |
| 목적 | 문서의 업무 활용을 유지하며 악성 활성 요소가 실행될 가능성 축소 |

CDR은 문서에 악성코드가 있는지 판정하는 것보다 허용한 구조만 남기도록 재구성하는 방식.

## Ⅱ. 파일 처리 구조

```text
외부 파일
    ↓ 형식·크기 확인
구조 분석·허용 콘텐츠 추출
    ↓ 활성 요소 제거
새 파일 재구성 → 이용자 전달
```

| 단계 | 핵심 점검 |
|---|---|
| 반입 | 파일 형식·크기·압축 여부 |
| 분석 | 문서 구조와 활성 요소 |
| 재구성 | 텍스트·이미지 등 허용 내용 |
| 전달 | 변환 결과와 실패 내역 |

## Ⅲ. 검사·샌드박스와의 관계

```text
파일 반입 통제
  ├─ 유형·크기 검사 ─ 처리 가능한 입력만 수용
  ├─ 악성코드 검사 ─ 알려진 징후 확인
  ├─ 샌드박스 ─ 동적 실행 행위 관찰
  └─ CDR ─ 허용 내용만 새 파일로 구성
```

| 방식 | 초점 | 한계 |
|---|---|---|
| 악성코드 검사 | 탐지 | 알려지지 않은 형태 |
| 샌드박스 | 실행 행위 | 실행 조건·분석 시간 |
| CDR | 구조 재구성 | 파일 기능·서식 손실 |

CDR 단독으로 모든 파일 형식과 취약한 파서를 보호한다고 단정하지 않음.

## Ⅳ. 적용·운영 기준

```text
반입 경로 식별
    ↓ 문서 유형별 허용 요소 결정
변환 시험
    ↓ 서식·내용 품질 검토
운영 중 실패·예외 관리
```

| 적용 경로 | 검토 항목 |
|---|---|
| 이메일 첨부 | 업무용 매크로·서식 손실 여부 |
| 웹 업로드 | 파일 형식 우회·변환 실패 |
| 망간 자료전송 | 승인·기록·원본 보존 정책 |

## Ⅴ. 한계와 제언

| 한계 | 대응 |
|---|---|
| 변환 뒤 수식·서명·서식 손실로 업무 문서의 의미가 달라질 수 있음 | 업무 유형별 수용 기준과 원본 대조 절차 마련 |
| 지원하지 않는 형식이나 파서 오류가 우회 경로가 될 수 있음 | 미지원 파일 차단·격리와 변환 실패 로그·예외 승인 절차 지정 |
