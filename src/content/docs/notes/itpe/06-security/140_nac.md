## 지식 로드맵 내 현재 위치

지식 위치: 정보보안 → 네트워크 접근통제 → **NAC**

## 30초 인출

- **본질:** 유·무선 엔드포인트 단말이 네트워크에 접속할 때 사용자 신원과 단말의 보안 상태(OS 패치, 백신, 무결성)를 검증하여 정상·격리·치료망으로 동적 인가하는 접근통제 시스템
- **메커니즘:** 단말 접속 시도 $\rightarrow$ IEEE 802.1X/RADIUS 인증 및 단말 상태(Posture) 평가 $\rightarrow$ 정책 엔진 판정 $\rightarrow$ 스위치 Dynamic VLAN/ACL 할당 $\rightarrow$ 지속적 모니터링 및 CoA 격리
- **통찰:** 단순 1회성 사전 인증 한계는 EDR 연계 지속적 상태 재평가와 CoA로 극복하고 에이전트리스 IoT 단말은 기기 핑거프린팅과 전용 격리망으로 통제 필수

<details>
<summary>핵심 용어</summary>

- **NAC (Network Access Control)** : 네트워크 접속 전후 단말의 무결성을 점검하고 인가 정책을 집행하는 솔루션.
- **Supplicant** : 네트워크 접속 인증을 요청하는 단말 측 소프트웨어 또는 OS 기본 내장 모듈.
- **Authenticator** : 단말의 물리 포트 접근을 통제하고 인증 트래픽을 중계하는 L2/L3 스위치 또는 무선 AP.
- **CoA (Change of Authorization)** : 단말 접속 중 보안 위협 감지 시 RADIUS 서버가 스위치에 세션 정책 변경을 강제 지시하는 RFC 5176 프로토콜.

</details>

## 2~4교시 예상문제 (25점)

> 네트워크 접근 제어(NAC)의 핵심 구성 요소, IEEE 802.1X 기반 접속 전·후(Pre/Post-admission) 동작 메커니즘을 설명하고, 비인가 MAC 스푸핑 및 에이전트리스 IoT 단말 환경에서의 엔지니어링 한계와 해결 방안을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 유·무선 사내 네트워크에 연결을 시도하는 모든 엔드포인트 기기에 대해 신원 인증과 필수 보안 컴플라이언스(백신 설치, 최신 OS 패치 등)를 검증하여 차등적 네트워크 권한을 부여하는 접근 통제 체계 |
| 목적 | 웜·랜섬웨어 감염 단말 및 비인가 사설 단말의 내부망 진입을 원천 차단하고, 취약 단말을 치료 격리망(Remediation VLAN)으로 유도하여 사내 네트워크 침해 확산 방지 |

- 네트워크 경계(L2/L3 스위치, AP) 단에서 IP/MAC 주소, 사용자 계정, 단말 보안 위생(Security Hygiene)을 결합하여 제로 트러스트 엔드포인트 검증을 실현

## Ⅱ. NAC의 핵심 기술적 특성

| 특성 항목 | 세부 내용 및 기술적 의미 | 엔지니어링 구현 가치 |
|---|---|---|
| 동적 네트워크 세그멘테이션 | 인증 결과 및 단말 상태에 따라 스위치 포트의 VLAN을 실시간으로 동적 변경 | 감염 단말을 물리적 케이블 분리 없이 논리적 격리망 격리 |
| 접속 전·후 지속 통제 | 최초 연결 시 검사(Pre-admission)뿐 아니라 접속 유지 중 상태 변화(Post-admission) 감시 | 백신 강제 종료 등 런타임 보안 정책 위반 즉각 감지 |
| 포괄적 기기 프로파일링 | 기기 제조사, OUI, DHCP 옵션, 배너 정보 분석을 통해 PC, 모바일, IoT 기기 자동 식별 | 에이전트 설치가 불가능한 프린터, IP전화기 자동 분류 |
| 표준 프로토콜 연동성 | IEEE 802.1X, RADIUS, EAP-TLS, SNMP, WebAuth 등 개방형 표준 프로토콜 기반 동작 | 멀티 벤더 네트워크 장비(Cisco, Juniper, Aruba 등) 통합 수용 |

- 에이전트(Agent) 방식의 정밀한 시스템 무결성 점검과 에이전트리스(Agentless) 방식의 네트워크 패킷 스니핑 탐지를 혼합 운영 가능한 특성 보유

## Ⅲ. IEEE 802.1X 기반 NAC 동작 메커니즘 및 프로세스

```text
[IEEE 802.1X 기반 NAC 접속 인증 및 동적 격리 프로세스]

  [Supplicant (PC 단말)]         [Authenticator (L2 스위치/AP)]        [Authentication Server (RADIUS/NAC)]
           │                                    │                                      │
           │ 1. EAPOL-Start (물리 링크 연결)      │                                      │
           ├───────────────────────────────────>│                                      │
           │ 2. EAP-Request/Identity            │                                      │
           │<───────────────────────────────────┤                                      │
           │ 3. EAP-Response/Identity (신원 제출)│                                      │
           ├───────────────────────────────────>│ 4. RADIUS Access-Request             │
           │                                    ├─────────────────────────────────────>│
           │                                    │                                      │ 5. 인증 및 Posture 검증:
           │                                    │                                      │    - ID/PW or 인증서 확인
           │                                    │                                      │    - OS 패치/백신 검사
           │                                    │ 6. RADIUS Access-Accept              │
           │                                    │    (VLAN ID = 10, ACL = Allow)      │
           │                                    │<─────────────────────────────────────┤
           │ 7. EAP-Success                     │                                      │
           │<───────────────────────────────────┤ 포트 Unblock 및 업무망 VLAN 10 활성화 │
           │                                                                           │
           │ 8. 접속 중 악성코드 감염 탐지 (EDR 연동) ─────────────────────────────────>│
           │                                    │ 9. RADIUS CoA (Change of Auth)       │
           │                                    │    (VLAN ID = 999: 격리망 강제 이동)  │
           │                                    │<─────────────────────────────────────┤
           │ 포트 격리망(VLAN 999)으로 재할당 및 치료 서버 유도                         │
```

| 절차 단계 | 핵심 엔지니어링 메커니즘 | 통제 결과 |
|---|---|---|
| 1. 접속 시도 및 차단 | 단말이 포트에 연결되면 Authenticator는 802.1X 프로토콜 외 모든 IP 패킷 차단 | 비인가 단말의 통신 원천 봉쇄 |
| 2. 신원 및 상태 인증 | Supplicant가 EAP-TLS 또는 EAP-PEAP를 통해 계정 및 단말 무결성 정보 제출 | RADIUS/정책 서버로 검증 위임 |
| 3. 정책 평가 및 매핑 | 백신 최신 업데이트 여부, 비인가 프로세스 탐지 결과에 따라 접근 등급 결정 | 정상망(VLAN 10) vs 치료망(VLAN 999) |
| 4. 포트 정책 집행 | RADIUS 응답에 포함된 VSA(Vendor Specific Attribute)를 스위치에 적용하여 포트 오픈 | 해당 VLAN 트래픽만 라우팅 허용 |
| 5. 지속적 재평가 (CoA) | EDR 또는 방화벽에서 C2 통신 감지 시 RFC 5176 CoA 명령을 스위치로 발송하여 즉시 세션 재인증/격리 | 실시간 위협 확산 차단 |

## Ⅳ. NAC 통제 방식별 기술 비교

| 비교 항목 | IEEE 802.1X 기반 통제 | ARP Spoofing 기반 센서 방식 | 인라인 게이트웨이 방식 | DHCP / DNS 제어 방식 |
|---|---|---|---|---|
| 통제 계층 | L2 포트 기반 하드웨어 통제 | L2 ARP 패킷 위조 리다이렉트 | L3/L4 네트워크 인라인 차단 | L7 애플리케이션 IP 할당 통제 |
| 네트워크 부하 | 없음 (스위치 하드웨어 처리) | 센서 브로드캐스트 부하 발생 | 전 트래픽 통과로 대역폭 병목 | 없음 (DNS 질의 시에만 개입) |
| 스위치 종속성 | 802.1X 지원 관리형 스위치 필수 | 더미 허브/레거시 스위치 지원 | 네트워크 홉(Hop) 추가 필요 | 네트워크 스위치 무관 |
| 보안 강도 | 극도로 높음 (L2 포트 완전 잠금) | 중간 (정적 ARP 설정 시 우회 가능) | 높음 (패킷 전수 검사) | 낮음 (고정 IP 설정 시 우회) |
| 장애 시 영향 | Fail-Open/Closed 정책 설정 | 센서 장애 시 통제 해제(안전) | 단일 장애점(SPOF) 위험 | DHCP 장애 시 신규 IP 불가 |

## Ⅴ. NAC 도입 시 엔지니어링 한계와 해결 방안

| 한계 | 방안 |
|---|---|
| 공격자가 정상 승인된 PC나 프린터의 MAC 주소를 위조(MAC Spoofing)하여 802.1X MAB(MAC Auth Bypass) 인증을 우회 침투 | 단순 MAC 인증을 금지하고, 스위치 단에서 DHCP Snooping, Dynamic ARP Inspection(DAI), IP Source Guard를 결합 활성화하며 IEEE 802.1AE MACsec 하드웨어 암호화 적용 |
| IP 카메라, 스마트 TV, 센서 등 Supplicant 에이전트를 설치할 수 없는 비인가 헤드리스 IoT 기기의 상태 점검 불가 | 에이전트리스 자동 프로파일링 엔진을 가동하여 OUI, DHCP Signature, TCP/IP 핑거프린팅을 통해 기기 모델을 식별하고, 비인가 통신을 원천 차단하는 마이크로세그멘테이션 격리 VLAN 자동 배정 |
| 접속 시점(Pre-admission) 1회 인증만 통과한 후 사용자가 백신을 강제 종료하거나 외부 USB로 악성코드에 감염되는 사후 위협 | 호스트 EDR 에이전트 및 사내 차세대 방화벽(NGFW)과 NAC 간 Open API를 연동하여, 이상 트래픽 발생 즉시 RFC 5176 CoA(Change of Authorization) 명령을 스위치로 날려 실시간 치료망 격리 |
| 스위치 펌웨어 오류 또는 NAC RADIUS 인증 서버 장애 발생 시 전사 임직원의 유무선 네트워크 연결 전면 마비 | 802.1X Critical VLAN(인증 서버 다운 시 업무용 예비 VLAN으로 임시 전환) 페일오버를 사전에 구성하고, RADIUS 서버 군집의 Anycast 로드밸런싱 이중화 배포 |

## Ⅵ. 제로 트러스트 엔드포인트 접근 통제 아키텍처 제언

```text
[제로 트러스트 엔드포인트 NAC + ZTNA 통합 아키텍처]

 ┌─────────────────────────────────────────────────────────────┐
 │                 1. 엔드포인트 계층 (Endpoint Posture)       │
 │   - 사내 단말: 802.1X EAP-TLS 인증서 + EDR 상태 검증        │
 │   - IoT 단말: DHCP/OUI 핑거프린팅 + MUD 프로파일 격리        │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │              2. 정책 결정 계층 (Policy Engine / RADIUS)      │
 │   - 단말 무결성 + 사용자 신원(IAM) + 위협 인텔리전스 결합    │
 │   - 지속적 평가 기반 동적 CoA (Change of Authorization) 발송 │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │                 3. 정책 집행 계층 (Enforcement Layer)        │
 │   - 유선/무선: L2 스위치 802.1X Dynamic VLAN / dACL          │
 │   - 재택/원격: ZTNA 소프트웨어 정의 경계(SDP) 게이트웨이 연동│
 └─────────────────────────────────────────────────────────────┘
```

| 관리 영역 | 핵심 엔지니어링 세부 과제 | 통제 목표치 |
|---|---|---|
| 단말 가시성 | 사내 유·무선 네트워크에 연결된 모든 IP/MAC 단말 인벤토리화 | 미인가 섀도우 IT 단말 탐지율 100% |
| 보안 컴플라이언스 | 필수 보안 프로그램(백신, 패치) 미준수 단말 업무망 접속 차단 | 컴플라이언스 준수율 > 99.5% |
| 자동 격리 대응 | 침해 위협 발생 단말 식별 후 격리망 전환까지 소요 시간 | CoA 격리 명령 집행 시간 < 3초 |
