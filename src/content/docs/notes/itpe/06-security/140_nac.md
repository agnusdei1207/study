## Ⅰ. NAC(Network Access Control)의 개요

- **개념** : 기업 내부 네트워크에 유·무선으로 접속을 시도하는 모든 엔드포인트 단말(PC, 노트북, 스마트폰, IoT)의 신원을 인증하고, 보안 컴플라이언스(백신 설치, 최신 패치, 비인가 SW) 준수 여부를 검증하여 접속 허용, 격리, 치료를 수행하는 중앙 집중형 네트워크 접근 제어 보안 솔루션.
- **배경 및 필요성** : 원격 근무, BYOD(Bring Your Own Device), 무선 Wi-Fi 도입으로 보안 통제를 벗어난 비인가 단말과 악성코드에 감염된 임직원 개인 기기가 사내망에 무분별하게 접속하여 내부망 랜섬웨어 확산의 진원지가 됨.
- **핵심 목적** : 인가되지 않은 불법 단말의 네트워크 접속을 원천 차단하고, 인가된 단말이라도 보안 무결성이 입증된 안전한 상태에서만 최소 네트워크 권한을 부여.

## Ⅱ. NAC(Network Access Control)의 핵심 아키텍처 및 동작 메커니즘

NAC는 사용자/단말 인증(Authentication), 보안 상태 검역(Posture Assessment), 접근 권한 제어(Access Control), 사후 감사 및 치료(Remediation)의 4단계 프레임워크로 작동함.

```text
[ NAC 네트워크 접근 제어 흐름 및 검역 격리 아키텍처 ]

  [ 엔드포인트 단말 (접속 시도) ]
               |
               v (1) 접속 요청 (802.1X / DHCP / ARP 스니핑)
  +-------------------------------------------------------------+
  |              네트워크 접근 계층 (L2 스위치 / 무선 AP)       |
  +------------------------------+------------------------------+
                                 |
                                 | (2) EAP / RADIUS 인증 요청
                                 v
  +-------------------------------------------------------------+
  |                     NAC 정책 서버 (Policy Server)           |
  |                                                             |
  |  1단계: 단말 식별/인증 (AD/LDAP 연계, MAC/인증서 검증)       |
  |  2단계: 보안 무결성 검역 (Posture Assessment)                |
  |         - 백신 실시간 감시 동작 여부                        |
  |         - OS 최신 보안 패치 적용 여부                       |
  |         - 필수 보안 에이전트(DLP, DRM) 실행 여부             |
  +------------------------------+------------------------------+
                                 |
         +-----------------------+-----------------------+
         | (검역 통과: 정상)                             | (검역 실패: 취약 단말)
         v                                               v
  +-----------------------------+                 +-----------------------------+
  | 정상 업무 네트워크 (VLAN 10) |                 | 검역/격리 네트워크 (VLAN 99)|
  | * 사내 ERP, 인트라넷, DB 접속|                 | * 인터넷 및 내부망 차단     |
  |   전면 허용                 |                 | * 백신/패치 업데이트 서버만 |
  +-----------------------------+                 |   접속 허용 (자가 치료 유도)|
                                                  +-----------------------------+
```

- **접속 전 검역(Pre-admission Assessment)** : 네트워크 IP를 정식 할당받기 전 또는 격리 VLAN 상태에서 백신 엔진 업데이트, 화면보호기 설정, 불법 P2P 프로그램 설치 여부를 검증.
- **접속 제어 방식의 다양성** : IEEE 802.1X EAP 포트 기반 인증(표준적/가장 강력), 스위치 미러링 기반 ARP Spoofing 방식(구축 용이, 레거시 호환), DHCP 기반 IP 통제 방식.
- **에이전트 vs 에이전트리스(Agentless)** : 단말에 전용 에이전트를 설치하여 정밀 점검을 수행하는 방식과, 프린터/IP카메라 등 에이전트 설치가 불가능한 기기를 위해 SNMP/MAC 기반으로 식별하는 방식 병행.
- **지속적 사후 모니터링(Post-admission)** : 최초 접속 시점뿐만 아니라 네트워크 사용 중에도 비정상 유해 트래픽 발생이나 백신 프로세스 강제 종료 시 즉시 세션을 끊고 격리 VLAN으로 강제 이동.

## Ⅲ. NAC(Network Access Control)의 세부 구성 요소 및 비교 분석

| 비교 항목 | NAC (네트워크 접근 제어) | 차세대 방화벽 (NGFW) | ZTNA (제로트러스트 네트워크액세스) |
| --- | --- | --- | --- |
| 통제 계층 | L2 데이터링크 계층 (단말 접속 지점) | L3~L7 네트워크 경계선 | L7 애플리케이션 계층 (신원 기반) |
| 통제 초점 | 디바이스 무결성, 네트워크 접속 여부 | IP/Port/App 기반 트래픽 흐름 차단 | 사용자 신원 및 최소 권한 앱 접근 |
| 검역 방식 | 사전 검역(Posture Check) 및 격리 | 인라인 심층 패킷 검사 (IPS/DPI) | 신원 검증 후 소프트웨어 경계(SDP) 형성 |
| 내부 횡적이동 | 동일 VLAN 내부 횡적이동 제어 한계 | 서브넷 간 이동만 통제 가능 | 마이크로 세그멘테이션으로 완벽 격리 |
| 주요 대상 | 유무선 사내망 연결 모든 단말(IoT 포함) | 내/외부망 경계 트래픽 | 클라우드 및 원격 재택근무 환경 |

- NAC는 기업 내부망의 물리적·논리적 최초 진입을 방어하는 관문 보안 솔루션이며, 현대에는 클라우드 시대에 발맞춰 ZTNA 프레임워크와 유기적으로 결합함.

## Ⅳ. NAC(Network Access Control)의 주요 한계점 및 해결 방안

- **ARP 스푸핑 방식의 네트워크 부하 및 스톰(Storm) 위험** :
  - **한계점** : 비인가 단말 차단을 위해 가짜 ARP Reply를 지속적으로 브로드캐스팅하는 소프트웨어 방식은 L2 네트워크 스위치에 과부하를 유발하고 네트워크 다운 위험 초래.
  - **해결 방안** : ARP 방식 의존을 탈피하고 엔터프라이즈 표준인 하드웨어 L2 스위치 802.1X 동적 VLAN 할당 방식으로 전면 전환.
- **비인가 허브 및 사설 공유기 연결 시 단말 은닉** :
  - **한계점** : 인가된 PC 뒤에 사설 공유기를 연결하여 여러 대의 스마트폰이나 비인가 노트북을 NAT로 숨겨 접속할 경우 MAC 기반 식별 우회 가능.
  - **해결 방안** : 스위치 포트 레벨에서 'Port Security'(허용 MAC 개수 1개 제한)를 설정하고, 802.1X 다중 인증(Multi-Auth) 모드 강제.
- **IoT, 스마트 TV, 공조기 등 에이전트 설치 불가 단말 관리 한계** :
  - **한계점** : 사내 스마트 오피스 확산으로 에이전트를 설치할 수 없는 수많은 IoT 기기의 보안 상태 점검이 불가능하여 취약점 방치.
  - **해결 방안** : AI 기반 네트워크 트래픽 프로파일링(DPI/NDR) 기술을 결합하여 통신 패턴을 기반으로 디바이스 유형을 자동 분류하고 전용 IoT VLAN으로 자동 격리.

## Ⅴ. NAC(Network Access Control) 적용 및 발전을 위한 기술사적 제언

- **802.1X EAP-TLS 인증서 기반의 강력한 단말 상호 인증 구축** : 취약한 MAC 주소 복제(Spoofing) 공격을 원천 차단하기 위해 디바이스마다 고유한 사설 PKI 인증서를 발급하여 EAP-TLS 인증 구현.
- **EDR(엔드포인트 탐지·대응) 솔루션과의 API 양방향 연동** : NAC의 네트워크 격리 기능과 EDR의 랜섬웨어 실시간 탐지 기능을 API로 연계하여, 단말에서 악성 행위 감지 시 NAC가 1초 내에 스위치 포트를 자동 셧다운하는 SOAR 체계 수립.
- **재택·원격 근무를 포괄하는 ZTNA 및 SASE로의 통합 진화** : 사내망 경계에 머무는 전통적 NAC를 넘어 클라우드 환경에서도 동일한 단말 보안 검역(Posture Check)을 수행하는 차세대 ZTNA 아키텍처로 확장.
