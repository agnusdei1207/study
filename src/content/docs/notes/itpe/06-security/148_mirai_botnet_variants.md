## 지식 로드맵 내 현재 위치

지식 위치: 정보보안 → 악성코드 → **봇넷**

## 30초 인출

- **본질:** 2016년 소스코드 공개 이후 취약한 자격증명 대입을 넘어 제로데이 취약점과 P2P 탈중앙화 C2 체계로 진화한 사물인터넷(IoT) 악성코드 변종 군집
- **메커니즘:** UPnP/RCE 취약점 고속 스캔 $\rightarrow$ 타깃 맞춤형 악성 바이너리 주입 $\rightarrow$ DHT/P2P 오버레이 C2 통신 $\rightarrow$ 테라비트급 볼륨 DDoS 및 크립토재킹 수행
- **통찰:** 중앙 C2 차단이 불가능한 P2P 봇넷은 ISP 차원의 DHT 트래픽 탐지와 라우터 레벨 UPnP 비활성화 및 RFC 8520 MUD 네트워크 격리 필수

<details>
<summary>핵심 용어</summary>

- **Mirai Variants** : 오리지널 Mirai 코드를 기반으로 익스플로잇과 통신 구조를 고도화한 파생 변종들.
- **Satori** : 기본 계정 대신 UPnP 및 라우터 원격 코드 실행(RCE) 취약점을 결합해 폭발적으로 확산된 변종.
- **Mozi** : 중앙 집중 C2 서버를 제거하고 BitTorrent DHT 기반 P2P 오버레이 네트워크로 제어되는 지능형 변종.
- **MUD (RFC 8520)** : 사물인터넷 기기의 승인된 통신 목적지를 엄격히 제한하는 네트워크 보안 프로파일.

</details>

## 2~4교시 예상문제 (25점)

> 오리지널 Mirai 봇넷 소스코드 공개 이후 등장한 주요 변종(Satori, Reaper, Mozi)의 진화 과정, 감염 벡터의 고도화(기본 계정 $\rightarrow$ N-day 취약점 $\rightarrow$ P2P 제어)를 설명하고, IoT 공급망 및 네트워크 관점의 방어 대책을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 2016년 오리지널 미라이(Mirai) 악성코드의 소스코드가 공개된 이후, 다양한 해커 그룹에 의해 원격 코드 실행(RCE) 취약점, UPnP 익스플로잇, P2P 명령제어 체계를 결합하여 지속 진화한 IoT 봇넷 변종 군집 |
| 목적 | 단순 텔넷 무차별 대입의 한계를 극복하고, 패치가 미비한 수천만 대의 네트워크 라우터, IP 카메라, NAS 및 클라우드 컨테이너까지 장악하여 대규모 DDoS 공격 및 불법 가상자산 채굴(Cryptojacking) 수행 |

- 소스코드의 모듈화 특성 덕분에 스캐너, 로더, 공격 모듈이 손쉽게 무기화되었으며, 중앙 C2 서버 단속(Takedown)을 회피하기 위해 P2P DHT 구조로 완성된 진화 양상 보유

## Ⅱ. Mirai 변종 봇넷의 진화적 기술 특성

| 특성 항목 | 세부 내용 및 기술적 의미 | 오리지널 대비 진화점 |
|---|---|---|
| 감염 벡터의 지능화 | 단순 기본 계정(admin/admin) 사전 대입에서 최신 0-day/N-day 웹 인터페이스 취약점 악용으로 진화 | 계정을 변경한 안전한 기기까지 취약점 익스플로잇으로 침투 |
| P2P 탈중앙화 C2 | 단일 IP/도메인 C2 서버를 탈피하고 Kademlia DHT 기반 완전 분산 P2P 통신망 구축 (Mozi) | 단일 C2 도메인 차단 및 싱크홀(Sinkhole) 전략 완전 무력화 |
| 대상 자산의 전방위 확장 | 초기 홈 라우터/CCTV에서 고성능 엔터프라이즈 방화벽, NAS, Docker/Kubernetes로 타깃 확대 | 단말당 대역폭 및 연산 파워가 수십 배 증가하여 공격 파괴력 증대 |
| 다목적 수익 모델 탑재 | 인프라 마비용 볼륨 DDoS 위주에서 모네로(XMR) 채굴, 프록시 대역폭 재판매, 랜섬웨어 유포로 다변화 | 사이버 범죄 생태계의 '서비스형 봇넷(BaaS)'으로 진화 |

- 크로스 컴파일 환경(ARM, MIPS, x86, PPC, ARC 등)을 계승하여 전 세계 거의 모든 임베디드 칩셋을 감염시키는 범용 침투성 보유

## Ⅲ. Mirai 변종 진화 계보 및 P2P C2 메커니즘

```text
[Mirai 소스코드 공개 이후 핵심 변종 진화 계보]

  [ 2016: Original Mirai ] ──> 텔넷 23/2323 무차별 대입, 중앙 IRC C2
             │
             ├──> [ 2017: Satori ] ────> UPnP/루프홀 취약점 (포트 37215) 고속 웜 확산
             │
             ├──> [ 2017: Reaper ] ────> 10개 이상 취약점 통합 프레임워크 (LUA 스크립팅)
             │
             └──> [ 2019~: Mozi ] ────> BitTorrent DHT 기반 P2P 오버레이 (단일 C2 제거)

 [Mozi의 DHT 기반 P2P 분산 명령제어 흐름]
  [Botmaster (공격자)]
          │ (ECDSA 서명된 악성 페이로드 및 지시문)
          ▼
   ┌─────────────┐       DHT 노드 간 전파       ┌─────────────┐
   │ P2P Bot A   │ <──────────────────────────> │ P2P Bot B   │
   └──────┬──────┘                              └──────┬──────┘
          │                                            │
          ▼                                            ▼
   [ Bot C (신규 감염) ]                         [ 표적 서비스 DDoS ]
   - C2 서버 IP가 없어 싱크홀 차단 불가         - 수십만 대 분산 트래픽 투사
```

| 진화 단계 | 핵심 변종 명칭 | 감염 및 제어 아키텍처 특성 |
|---|---|---|
| 1세대: 딕셔너리 기반 | Mirai (Original) | 60여 개 기본 계정 브루트포스, 중앙 집중형 C2 서버, SYN/UDP Flood |
| 2세대: 단일 익스플로잇 결합 | Satori / Okiru | 화웨이 라우터 CVE-2017-17215, 제로데이 취약점 결합, 수 시간 내 28만 대 감염 |
| 3세대: 복합 취약점 스캐너 | Reaper (IoTroop) | D-Link, Netgear, Linksys 등 10개 이상 RCE 익스플로잇 탑재, 자동 LUA 스캔 |
| 4세대: 완전 분산 P2P | Mozi | Kademlia DHT 분산 해시 테이블 채택, ECDSA 공개키 서명으로 명령 무결성 검증 |

## Ⅳ. Mirai 변종(Satori, Reaper, Mozi) 기술 상세 비교

| 비교 항목 | Original Mirai | Satori | Reaper (IoTroop) | Mozi |
|---|---|---|---|---|
| 주요 감염 방식 | 텔넷 기본 계정 대입 | UPnP 취약점 (RCE) | 복합 N-day 취약점 통합 | 취약점 악용 + 취약 계정 |
| 타깃 포트 | Port 23, 2323 | Port 37215, 52869 | Port 80, 8080, 81 | Port 80, 23, 다양한 IoT 포트 |
| C2 아키텍처 | 중앙 C2 (IRC / TCP) | 중앙 C2 (하드코딩 IP) | 중앙 C2 서버 | DHT 기반 완전 분산 P2P |
| 침투 속도 | 보통 (사전 대입 지연) | 극도로 빠름 (수분 내 웜 전파) | 보통 (취약점 순차 분석) | 매우 빠름 (P2P 자기 증식) |
| 차단 난이도 | 보통 (C2 IP 차단 가능) | 보통 (C2 IP 차단 가능) | 보통 (C2 도메인 테이크다운) | 극도로 높음 (단일 차단점 부재) |
| 주요 탑재 기능 | L3/L4 DDoS 공격 | 고속 DDoS 봇넷 구축 | DDoS, 트래픽 감시 스크립트 | DDoS, 데이터 탈취, 페이로드 실행 |

## Ⅴ. IoT 봇넷 변종 대응 시 엔지니어링 한계와 해결 방안

| 한계 | 방안 |
|---|---|
| Mozi 등 최신 변종이 중앙 C2 서버 없이 BitTorrent DHT 프로토콜로 명령을 P2P 전파하여 기존 DNS/IP 차단 무력화 | 통신사(ISP) 백본망에서 DHT 부트스트랩 노드 IP 풀을 식별하여 BGP Flowspec으로 선제 차단하고, 게이트웨이 레벨에서 비정상적인 고빈도 UDP/DHT 쿼리 패턴 필터링 |
| 제조사 지원 종료(EOL)로 영구적으로 펌웨어 보안 패치가 불가능한 수억 대의 레거시 IoT 기기가 인터넷에 상시 방치 | 네트워크 경계에서 RFC 8520 MUD(Manufacturer Usage Description) 표준 프로파일을 적용하여 해당 IoT 기기가 사전에 지정된 제조사 클라우드 외 외부 통신을 전면 격리(Zero Trust Isolation) |
| 취약한 UPnP(Universal Plug and Play) 기능이 기본 활성화되어 내부 사설망의 취약한 기기가 외부 공인 포트로 자동 포워딩 노출 | 공유기 및 라우터 출하 단계에서 WAN 측 UPnP 및 원격 관리 인터페이스(HNAP)를 기본 비활성화(Default Disabled) 강제 |
| 단순 재부팅(Reboot) 시 메모리 상주 바이너리는 삭제되나, 라우터 취약점이 패치되지 않아 수 초 내 재스캔에 의해 무한 재감염 루프 발생 | 하드웨어 신뢰 루트(RoT) 기반의 읽기 전용 불변 펌웨어(Secure Boot)를 적용하고, 네트워크 진입 시 격리 VLAN에서 원격 펌웨어 자동 핫픽스(FOTA) 완료 후 정상망 편입 |

## Ⅵ. IoT 생태계 전주기 공급망 및 네트워크 다층 방어 제언

```text
[IoT 봇넷 변종 확산 방지를 위한 3단계 전주기 방어 체계]

 ┌─────────────────────────────────────────────────────────────┐
 │                 1. 제조 및 출시 단계 (Secure by Design)     │
 │   - 기기별 고유 비밀번호 강제 (공통 비밀번호 금지)         │
 │   - UPnP/Telnet WAN 포트 영구 제거, 안전한 FOTA 서명 검증   │
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │              2. 네트워크 및 통신사 계층 (Edge Isolation)     │
 │   - RFC 8520 MUD 프로파일 적용 (인가 통신 외 전면 차단)     │
 │   - 통신사 에지 BCP 38 소스 IP 스푸핑 방지 및 Flowspec 차단│
 └──────────────────────────────┬──────────────────────────────┘
                                │
 ┌──────────────────────────────┴──────────────────────────────┐
 │                 3. 관제 및 위협 인텔리전스 (CTI Response)    │
 │   - DHT P2P 봇넷 트래픽 모니터링 및 시빌 노드(Sybil) 교란    │
 │   - 전사 공격 표면(ASM) 스캔을 통한 미인가 IoT 노출 실시간 제거│
 └─────────────────────────────────────────────────────────────┘
```

| 관리 영역 | 핵심 엔지니어링 세부 과제 | 통제 목표치 |
|---|---|---|
| 제조사 보안 | 기본 계정 완전 제거 및 WAN 측 UPnP 비활성화 펌웨어 적용 | 출하 기기 디폴트 취약점 0건 |
| 네트워크 격리 | MUD 기반 마이크로세그멘테이션으로 IoT와 업무망 분리 | 봇넷 내부 횡적 이동(Lateral Move) 차단율 100% |
| C2 차단 대응 | DHT P2P 트래픽 휴리스틱 탐지 및 통신사 공조 BGP 차단 | 봇넷 C2 제어 성공률 < 1% 억제 |
