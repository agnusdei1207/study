## 30초 인출

- **본질:** Mirai는 취약한 IoT 기기를 감염시켜 원격 제어하고 대규모 분산 서비스 거부 공격에 동원하는 악성코드.
- **메커니즘:** 접속 가능한 기기 탐색 → 취약한 계정으로 침투 → 악성코드 설치 → 명령제어 서버의 공격 지시.
- **핵심 대응:** 기본 계정 제거, 외부 관리 포트 축소, 안전한 업데이트와 감염 트래픽 탐지.

<details>
<summary>핵심 용어</summary>

- **Mirai 봇넷**: Mirai 악성코드에 감염되어 명령제어 서버의 지시를 받는 IoT 기기 집합.
- **IoT(Internet of Things)**: 인터넷에 연결되어 데이터를 주고받는 기기와 서비스.
- **봇(Bot)**: 공격자의 명령에 따라 자동으로 동작하는 감염 기기.
- **C2(Command and Control)**: 감염 기기에 지시를 내리는 명령제어 체계.
- **DDoS(Distributed Denial of Service)**: 다수의 기기에서 트래픽을 보내 대상 서비스의 이용을 방해하는 공격.
</details>

## 2~4교시 25점 답안

## Ⅰ. Mirai 봇넷의 정의와 목적

| 구분 | 내용 |
|---|---|
| 정의 | **Mirai 봇넷**은 취약한 IoT 기기를 감염·제어해 DDoS 등에 동원하는 기기 집합 |
| 목적 | 감염 경로와 제어 구조를 파악해 확산과 서비스 장애 예방 |

기본 자격증명과 외부로 열린 관리 인터페이스가 대표적인 초기 침투 조건. Mirai의 모든 후속 IoT 봇넷을 같은 변종으로 묶지 않는 구분 필요.

## Ⅱ. 감염·제어 구조

```text
취약 IoT 기기 탐색
       ↓ 약한 계정으로 접속
감염 대상 보고 → 로더의 악성코드 설치
       ↓
감염 봇 ← C2 공격 명령
       ↓
대상 서비스에 DDoS 트래픽
```

| 구성 요소 | 역할 |
|---|---|
| 스캐너 | 접속 가능한 기기와 취약한 계정 탐색 |
| 보고 서버·로더 | 대상 정보 수집과 기기용 악성코드 설치 |
| 봇 | 명령 수신·추가 탐색·공격 트래픽 발생 |
| C2 | 감염 봇에 공격 명령 전달 |

## Ⅲ. 공격이 커지는 이유

```text
기기별 기본 설정 미변경
       ↓
인터넷 노출 기기의 대량 감염
       ↓
동일 목표로 트래픽 집중
       ↓
서비스·네트워크 자원 고갈
```

| 확산 조건 | 보안 영향 |
|---|---|
| 같은 기본 계정의 반복 사용 | 여러 제조사·기기로 전파 |
| 관리 서비스의 인터넷 노출 | 원격 침투 면적 확대 |
| 업데이트 불가·지연 | 기존 취약점과 감염의 장기화 |

## Ⅳ. 기기·네트워크 방어

```text
제조·조달 ─ 고유 계정·업데이트 기능
운영      ─ 노출 포트·접근권한 관리
관제      ─ 스캔·C2·대량 전송 탐지
복구      ─ 격리·초기화·패치·계정 변경
```

| 계층 | 통제 | 확인 방법 |
|---|---|---|
| 기기 | 기본 비밀번호 제거, 안전한 업데이트 | 초기 설정·서명 검증 시험 |
| 네트워크 | 관리 포트 접근 제한, 분리 | 외부 노출·동서 트래픽 점검 |
| 탐지·대응 | 비정상 스캔·대량 송신 탐지 | 격리·재감염 여부 확인 |

## Ⅴ. 한계와 제언

| 한계 | 대응 |
|---|---|
| 감염 기기만 재부팅하면 약한 계정·노출 포트가 남아 재감염 가능 | 격리 후 계정 변경·패치·접근 제한을 함께 적용하고 재연결 전 검증 |
| 개별 기기 보호만으로 대규모 DDoS 영향 통제 곤란 | 제조사·운영자·통신망의 탐지와 차단 역할을 나눠 대응 |
