## 1교시 10점 답안

### 1. 정의·목적

정의: Mirai는 기본 계정정보가 취약한 IoT 장비를 감염시켜 봇넷으로 만드는 악성코드다.
목적: 감염 장비를 원격 제어해 주로 대규모 DDoS 공격에 동원한다.

### 2. 동작 단계

| 단계 | 동작 |
|---|---|
| 스캔·침투 | 장비를 찾고 기본 계정정보로 접속 시도 |
| 감염 | Loader가 장비 아키텍처에 맞는 악성코드 전달 |
| 제어·악용 | C&C 명령에 따라 DDoS 등 공격 수행 |

제안: IoT 장비의 기본 자격증명을 바꾸고 불필요한 원격 접속을 차단한다.

## 2~4교시 25점 답안

# 봇넷(Mirai)

## 핵심 개념
- 보안 설정이 취약한 사물인터넷(IoT) 장비(CCTV, IP 카메라, 홈 라우터 등)를 무차별 사전 공격(Brute Force)으로 감염시켜 좀비 네트워크(Botnet)로 구축하는 악성 소프트웨어.
- 소스코드가 공개된 이후 다양한 변종(Satori, Reaper, Mozi 등)으로 분기되었으며, 대규모 분산 서비스 거부(DDoS) 공격 및 암호화폐 채굴, 내부망 침투 거점으로 악용됨.

```
+-------------------------------------------------------------+
|                     Mirai 봇넷 동작 4단계                    |
+-------------------------------------------------------------+
| 1. 스캐닝(Scanning)   | 23/2323번 포트 무작위 IP 대역 고속 스캔    |
| 2. 무차별 대입(Brute) | 하드코딩된 60여 개 기본 계정/비밀번호 시도  |
| 3. 페이로드 로딩      | Loader 서버를 통한 아키텍처별 바이너리 다운|
| 4. C&C 연결 및 공격  | C&C 서버 명령 수신 후 테라급 DDoS 공격 수행|
+-------------------------------------------------------------+
```

## 미라이 봇넷 시스템 아키텍처

```
[감염된 IoT 봇 (Bot)]
       |
       | 1. 무작위 IP 대역 스캔 (Telnet: 23, 2323)
       v
[취약한 대상 IoT 장치] <----- 2. 기본 계정 로그인 성공 (admin/admin 등)
       |
       | 3. 대상 IP/포트/자격증명 보고
       v
[스캔 수신 서버 (Report Server)]
       |
       | 4. 감염 대상 정보 전달
       v
[로더 서버 (Loader / Wget Server)]
       |
       | 5. 기기 CPU 아키텍처(ARM/MIPS/x86) 확인 후 악성코드 주입
       v
[신규 감염 봇 (New Bot)]
       |
       | 6. C&C 서버 등록 및 심장박동(Heartbeat) 유지
       v
[C&C 제어 서버 (Command & Control)] ===> 7. 공격 명령 하달 ===> [희생자 서버 DDoS]
```

## 미라이 봇넷의 주요 구성 모듈 및 동작 원리

### 1. 스캐너 모듈 (Scanner)
- **비동기 무작위 스캐닝**: `SYN` 패킷을 전송하여 응답 속도를 극대화하고 사설망(10.0.0.0/8, 127.0.0.0/8 등) 및 특정 기관(국방부, 우편국 등) IP 대역은 제외 처리.
- **사전 대입 공격(Dictionary Attack)**: 벤더 기본값(admin/admin, root/vizcv 등) 60여 개 쌍을 순차 대입하여 원격 셸 권한 획득.

### 2. 로더 모듈 (Loader)
- **교차 컴파일 바이너리 배포**: MIPS, ARM, x86, PowerPC, SuperH 등 다양한 임베디드 아키텍처별 바이너리를 보관하고, 대상 장비의 셸에서 `wget` 또는 `tftp`로 적합한 페이로드 다운로드.
- **경쟁 악성코드 제거**: 메모리 프로세스 테이블 감시를 통해 포트 22/23/80을 점유하는 타 봇넷 프로세스를 강제 종료(Kill)하여 단독 제어권 확보.

### 3. 방어 회피 및 지속성 메커니즘
- **메모리 상주(In-memory Execution)**: 바이너리 실행 즉시 디스크 상의 원본 파일을 삭제(`unlink`)하여 포렌식 분석 방해.
- **워치독(Watchdog) 무력화**: 리눅스 하드웨어 워치독 타이머(`/dev/watchdog`)를 비활성화하여 기기 자동 재부팅 방지.
- **재부팅 시 소멸**: 플래시 메모리 변조를 피하고 램에만 상주하므로 재부팅 시 일시 제거되나, 재부팅 직후 수분 내 재감염.

## 미라이 변종 진화 현황

| 변종 명칭 | 주요 특징 및 진화 내용 |
|---|---|
| **미라이 원본(Mirai)** | 텔넷 기본 계정 사전 대입 위주, 단순 볼류메트릭 DDoS 수행 |
| **사토리(Satori / Okiru)** | 사전 대입 탈피, 제로데이/원격코드실행(RCE) 취약점(UPnP, 라우터 취약점) 결합 자동 전파 |
| **리퍼(Reaper / IoTroop)** | 소스코드 수준 재작성, 수십 종의 IoT 기기 취약점 익스플로잇 결합으로 감염 속도 급증 |
| **모지(Mozi)** | C&C 중앙 서버 탈피, DHT(Distributed Hash Table) 기반 P2P 분산 네트워크로 제어 구조 고도화 |
| **에코봇(Echobot)** | 엔터프라이즈 기기, NAS, SCADA 장비 취약점 50종 이상 통합 익스플로잇 탑재 |

## 공격 유형 및 대응 기술

### 1. 수행 공격 유형
- **볼류메트릭 DDoS**: UDP Flood, DNS Amplification, GRE IP Flood 등을 통해 수백 Gbps ~ Tbps 규모 대역폭 고갈.
- **프로토콜 악용 DDoS**: SYN Flood, ACK Flood 공격으로 희생자 서버의 백로그 큐 소진 및 연결 자원 고갈.
- **애플리케이션 계층 DDoS**: HTTP GET/POST Flood 공격으로 웹 서버 CPU 및 데이터베이스 연결 풀 고갈.

### 2. 기술적·제도적 대응 방안
- **초기 비밀번호 강제 변경**: 장비 최초 설정 시 기본 패스워드 사용을 원천 차단하고 복잡도 높은 비밀번호 설정 강제.
- **불필요 원격 관리 포트 차단**: 외부 인터넷망을 향한 Telnet(23), SSH(22), Web(80, 8080) 관리 포트 바인딩 해제.
- **IoT 보안 인증제 준수**: KISA IoT 보안인증 기준에 따라 펌웨어 암호화, 안전한 펌웨어 업데이트(OTA 서명 검증) 적용.
- **통신사 레벨 차단(ISP 협력)**: 텔넷/SSH 포트의 대규모 비정상 아웃바운드 스캐닝 트래픽 자동 필터링 및 블랙홀 라우팅.

## 결론 및 실무 시사점
- 미라이 봇넷은 보안 통제가 취약한 IoT 엔드포인트가 인터넷 전체 인프라를 위협하는 대규모 공격 무기로 악용될 수 있음을 증명.
- 에지 및 IoT 장비 설계 단계부터 '보안 내재화(Security by Design)' 원칙을 적용하고, 하드코딩 계정 제거와 제로 트러스트 기반 접근 통제를 확립해야 함.
