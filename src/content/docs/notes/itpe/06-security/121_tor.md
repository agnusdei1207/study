## 지식 로드맵 내 현재 위치

지식 위치: 프라이버시 네트워크 → 다중 릴레이 경로 → **Tor**

## 30초 인출

- **본질:** 메시지를 다중 계층 대칭키로 암호화하고 분산된 3단계 릴레이 노드를 경유시켜 송신자와 수신자 간의 네트워크 경로 추적을 차단하는 익명 통신 프로토콜
- **메커니즘:** 디렉토리 서버에서 노드 목록 수신 → Diffie-Hellman 기반 Guard·Middle·Exit 릴레이별 세션키 협상 → 다중 암호화 셀 전송 및 홉별 단일 계층 복호화
- **통찰:** 양 끝단 트래픽 상관 분석 공격은 셀 패딩과 지터 주입으로 방어하고, Exit 노드 도청은 HSTS 기반 종단간 TLS 강제 및 어니언 서비스 직결로 차단 필수

<details>
<summary>핵심 용어</summary>

- **Tor (The Onion Router)** : 양파 껍질 구조의 다중 암호화와 중계 릴레이를 이용하는 익명 오버레이 네트워크.
- **Guard Relay** : 클라이언트가 네트워크에 최초 진입하는 진입 노드로 클라이언트의 실제 IP를 알고 있음.
- **Middle Relay** : 트래픽의 앞뒤 릴레이 주소만 알며 송신자와 최종 목적지를 모두 알 수 없는 중계 노드.
- **Exit Relay** : 패킷의 마지막 암호 계층을 해제하여 최종 목적지 서버로 트래픽을 전달하는 출구 노드.

</details>

## 2~4교시 예상문제 (25점)

> Tor(The Onion Router)의 어니언 라우팅 동작 원리, 3단계 릴레이 구조 및 셀(Cell) 암호화 메커니즘을 설명하고, 트래픽 상관 분석 및 악의적 출구 노드 위협에 대응하기 위한 기술적 방안을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 인터넷 트래픽을 가상 회선(Circuit) 상의 3개 분산 릴레이를 경유시키고, 각 노드별 세션키로 다중 암호화하여 통신 경로의 식별성을 은닉하는 프라이버시 네트워크 기술 |
| 목적 | 단일 관측자나 중간 네트워크 사업자가 통신의 출발지(발신자 IP)와 목적지(웹 서버)를 동시에 파악하지 못하도록 분리하여 통신 프라이버시 및 검열 회피 보장 |

- 종단간 암호화(E2EE)가 데이터의 '내용'을 보호하는 반면, 어니언 라우팅은 통신의 '메타데이터'(누가 누구와 통신하는지)를 은닉하는 기술

## Ⅱ. Tor 어니언 라우팅의 핵심 기술 특성

| 특성 항목 | 세부 내용 및 기술적 의미 | 구현 메커니즘 |
|---|---|---|
| 다중 계층 암호화 (Onion Peeling) | 클라이언트가 릴레이 순서의 역순으로 메시지를 중첩 암호화하고, 각 릴레이는 한 껍질씩만 복호화 | 대칭키(AES-128/CTR 등) 중첩 암호화 및 홉별 복호화 |
| 완전 순방향 비밀성 (PFS) | 회로(Circuit) 생성 시 릴레이마다 임시 디피-헬만(Ephemeral DH) 키 교환을 수행하여 세션키 생성 | 마스터 키 탈취 시에도 과거 통신 세션 복호화 불가 |
| 정보 격리 분할 | 각 노드는 직전 노드(IP)와 직후 노드(IP)만 알 수 있도록 설계하여 단일 노드 탈취 시 정보 유출 차단 | 소스 라우팅(Source Routing) 및 홉별 셀 라우팅 헤더 교체 |
| 고정 크기 전송 (Fixed Cell) | 모든 데이터와 제어 신호를 512바이트 고정 셀(Cell) 단위로 분할하여 전송 | 패킷 크기 기반 트래픽 분석(Traffic Analysis) 방해 |

- 공개된 P2P 분산 자원봉사자 노드를 통해 오버레이 회로를 구성하므로 단일 중앙 서버나 단일 실패점이 부재한 비집중형 특성 보유

      │                           ├────────────────────────>│                        │                       │
      │                           │                         │ 복호화(K_mid)           │                       │

| 단계 | 수행 프로세스 | 보안 통제 및 데이터 상태 |
|---|---|---|
| 디렉토리 조회 | 신뢰할 수 있는 디렉토리 권한 서버(Directory Authorities)로부터 활성 릴레이 합의 문서 수신 | 합의 서명 검증을 통한 위조 릴레이 유입 방지 |
| 회로(Circuit) 구축 | Guard 노드 연결 후 순차적으로 텔레스코핑(Telescoping) 기법을 통해 Middle, Exit 노드 연결 | 각 릴레이와 독립적인 임시 세션키($K_G, K_M, K_E$) 협상 |
| 셀 캡슐화 및 전송 | 송신 데이터를 $K_E \rightarrow K_M \rightarrow K_G$ 순으로 3중 암호화하여 512B 셀 형태로 Guard로 전송 | Guard 노드는 클라이언트 IP와 Middle IP만 인지 |
| 홉별 껍질 박리 | Guard가 $K_G$ 복호화 후 Middle로, Middle이 $K_M$ 복호화 후 Exit로 포워딩 | Middle 노드는 트래픽 출발지와 목적지 모두 불인지 |
| 출구 전달 및 회신 | Exit 노드가 마지막 $K_E$ 복호화 후 원본 패킷을 목적지 서버로 전송, 응답은 역순 3중 암호화 | Exit 노드는 Middle IP와 목적지 서버 IP만 인지 |

## Ⅳ. 익명 통신 및 프록시 기술 비교

| 비교 항목 | Tor (어니언 라우팅) | 상용 VPN (Virtual Private Network) | I2P (Invisible Internet Project) |
|---|---|---|---|
| 네트워크 토폴로지 | 3홉 분산 오버레이 네트워크 | 클라이언트-VPN 게이트웨이 간 단일 홉 터널 | 단방향 터널 기반 분산 P2P (Garlic Routing) |
| 신뢰 모델 | 노드 간 비신뢰 (어떤 단일 노드도 전체 정보 모름) | VPN 서비스 제공자 100% 신뢰 (로그 유출 위험) | 노드 간 비신뢰 (분산 해시 테이블 기반) |
| 주요 용도 | 일반 웹 접속 시 클라이언트 익명성 및 검열 우회 | 기업망 사설 접속, 트래픽 암호화 터널링 | 폐쇄형 다크넷 내부 P2P 통신 및 파일 공유 |
| 암호화 방식 | 중첩 대칭키 암호화 (Onion Routing) | IPsec / OpenVPN / WireGuard 단일 터널 암호화 | 여러 메시지를 묶어 전송하는 Garlic 암호화 |
| 성능 및 대역폭 | 다중 홉 및 자원봉사자 대역폭으로 상대적 저속 | 고속 전용 회선 제공으로 고대역폭/저지연 | P2P 구조로 대역폭 분산, 내부망 속도 양호 |

## Ⅴ. Tor 네트워크의 보안 한계와 엔지니어링 대응 방안

| 한계 | 방안 |
|---|---|
| 국가 단위 감시자/ISP가 Guard 유입 트래픽과 Exit 유출 트래픽의 시간·패킷 크기·버스트 패턴을 대조하는 트래픽 상관 분석 공격(Correlation Attack) | 패킷 간 무작위 지연(Jitter Injection) 삽입, 512바이트 셀 단위 정적 패딩 강화, 유휴 구간 가짜 더미 트래픽(Cover Traffic) 지속 생성 |
| 악의적 Exit 노드가 최종 목적지 사이의 평문 트래픽을 도청하고 SSL Stripping 기법으로 인증서 위조 및 세션 탈취 수행 | 브라우저 차원의 HSTS Preload 강제 적용, HTTPS-Only 모드 활성화, Tor 네트워크 내부 완결형 어니언 서비스(v3 Onion Service: Ed25519 기반 E2EE) 활용 |
| 공격자가 다수의 고성능 Guard/Exit 노드를 네트워크에 대량 배치하여 확률적으로 동일 회선의 양 끝단을 동시 장악하는 시빌 공격(Sybil Attack) | 엔트리 가드 고정(Entry Guard Pinning: 소수의 검증된 Guard를 수개월간 고정 사용), 대역폭 측정 시스템 분산 합의 및 서열화 알고리즘 적용 |
| 브라우저 핑거프린팅(Canvas, WebGL, 폰트, 오디오 API) 및 DNS 누출(DNS Leak)로 인한 애플리케이션 계층 사용자 식별 | 모든 사용자 환경을 표준화한 Tor Browser 번들 강제 사용, SOCKS5 프록시 기반 원격 DNS 확인 및 WebRTC 원천 비활성화 |

## Ⅵ. 프라이버시 보장 및 침해 사고 방지를 위한 종합 제언

```text
[Tor 프라이버시 강화 및 기업 보안 관제 종합 대응 프레임워크]

  +---------------------------------------------------------------+
  |                 1. 사용자 종단: 강력한 E2EE 보장                |
  |     - Tor Browser 사용 (Canvas/WebGL 차단, 격리된 쿠키)        |
  |     - HTTPS 강제 (HSTS Preload) 및 v3 Onion Service 접속     |
  +---------------------------------------------------------------+
                                  │
                                  ▼
  +---------------------------------------------------------------+
  |               2. 네트워크 계층: 엔트리 가드 보안               |
  |     - Entry Guard Pinning 적용 (회로 양단 동시 장악 방지)     |
  |     - 셀 패딩(Padding Cell) 및 지터 주입 (트래픽 상관 방어)    |
  +---------------------------------------------------------------+
                                  │
                                  ▼
  +---------------------------------------------------------------+
  |                 3. 기업 내부망: Tor 악용 위협 방어            |
  |     - Exit 노드 IP 인텔리전스 DB 연동 (비인가 C2 접속 차단)     |
  |     - 프로토콜 심층 분석(DPI)으로 비표준 TLS 난독화 터널 탐지 |
  +---------------------------------------------------------------+
```

| 대응 축 | 엔지니어링 핵심 과제 | 성과 지표 |
|---|---|---|
| 익명성 보장 | 브라우저 핑거프린팅 방지 및 v3 어니언 주소 암호화 체계 적용 | 사용자 단말 식별 엔트로피 최소화, 비인가 누출 차단율 100% |
| 악의적 노드 차단 | 디렉토리 권한 서버의 릴레이 심사 강화 및 대역폭 검증 분산화 | 악의적 시빌 노드(Sybil Node) 회선 점유율 < 1% 억제 |
| 기업 보안 관제 | 악성코드 감염 PC의 Tor C2 터널링 탐지 및 침해사고 방지 | Tor 기반 C2 비인가 아웃바운드 트래픽 차단율 100% 달성 |
