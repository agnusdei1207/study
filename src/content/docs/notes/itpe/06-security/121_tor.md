## 답안 골격
```text
[TOR(The Onion Routing)] ◀━━ 머리: Ⅶ 내 의견 (단일 VPN 신뢰의 구조적 결함 극복 → 다계층 양파 암호화 회선 분리를 통한 완벽한 통신 익명성 보장)
 ┃
 ┣━ Ⅰ 개요 ───── 통신 데이터를 양파 껍질처럼 다계층으로 암호화하여 3개 이상의 중계 노드(가드, 미들, 출구)를 무작위로 거치게 함으로써, 발신자의 IP 주소와 수신지 간의 상관관계를 분리하는 분산 익명 통신 네트워크 기술
 ┣━ Ⅱ 특징 ───── 다계층 암호화(Onion Encryption) · 완전한 발신자 익명성 보장 · 노드별 부분 정보만 보유(앞/뒤 노드만 식별) · 다중 중계로 인한 심각한 전송 지연(High Latency)
 ┣━ Ⅲ 구조 ───── 디렉토리 서버(노드 목록 관리) + 진입 노드(Guard/Entry) + 중간 릴레이(Middle) + 출구 노드(Exit Node) + 히든 서비스(.onion)
 ┣━ Ⅳ 흐름 ───── 3개 노드와 순차적 Diffie-Hellman 키교환 → 3중 암호화 패킷 생성 → 가드 노드(1차 복호화) → 미들 노드(2차 복호화) → 출구 노드(3차 복호화 및 최종 목적지 전달)
 ┣━ Ⅴ 비교 ───── VPN(단일 터널링, VPN 운영자가 송수신자 모두 감시 가능, 고속) vs Tor(3단계 무작위 노드 경유, 단일 실패점 없음, 극심한 속도 저하)
 ┗━ Ⅵ 실무 ───── 출구 노드(Exit Node)의 비암호화(HTTP) 패킷 도청 위험 / 트래픽 상관관계 분석(Timing Attack) / 사이버 범죄 및 악성 C2 채널 악용
```
- 필수 키워드: Tor · 양파 라우팅 · 가드/미들/출구 노드(Guard/Middle/Exit) · 다계층 암호화 · 익명성(Anonymity) · VPN 비교 · 히든 서비스(.onion)

## 한 줄 본질
- 단일 VPN 제공자나 ISP가 마음만 먹으면 사용자의 인터넷 방문 기록을 전부 들여다보는 중앙집중형 감시 병목 → 3단계 중계 노드에 패킷을 다계층 암호화하여 통과시킴으로써 누구도 출발지와 목적지를 동시에 알 수 없게 차단 → 통신 익명성 확보 / 극심한 전송 지연 및 출구 노드 도청 위험 발생

## 핵심 그림
```text
[Tor(The Onion Routing)의 3계층 양파 암호화 및 릴레이 전달 메커니즘]

[사용자 PC]
  - 3중 암호화 생성: $E_{Guard}(E_{Middle}(E_{Exit}(M)))$
       │
       ▼ (1차 전송)
┌──────────────────────┐
│  가드 노드 (Guard)   │ ──> $E_{Guard}$ 복호화: 사용자 IP는 알지만, 최종 목적지 모름!
└──────────┬───────────┘
           │ (2차 전송: $E_{Middle}(E_{Exit}(M))$)
           ▼
┌──────────────────────┐
│  미들 노드 (Middle)  │ ──> $E_{Middle}$ 복호화: 가드와 출구 노드만 알고, 송신자/목적지 모두 모름!
└──────────┬───────────┘
           │ (3차 전송: $E_{Exit}(M)$)
           ▼
┌──────────────────────┐
│  출구 노드 (Exit)    │ ──> $E_{Exit}$ 복호화: 최종 목적지 웹서버로 평문 $M$ 전송!
└──────────┬───────────┘     (주의: 최종 목적지는 알지만, 최초 송신자 IP는 모름!)
           │ (평문 또는 HTTPS 전송)
           ▼
  [최종 목적지 웹서버]
```

## 핵심 용어
- 출구 노드 (Exit Node): Tor 회선(Circuit)의 마지막 노드로, 암호화 껍질을 완전히 벗겨내고 실제 목적지 웹서버로 트래픽을 내보내는 노드이며, 평문(HTTP) 통신 시 스니핑 위험이 집중되는 구간
- 랑데부 포인트 (Rendezvous Point): 클라이언트뿐만 아니라 서버의 실제 IP 위치까지 숨기는 '히든 서비스(Hidden Service, .onion)'를 구현하기 위해 양측이 익명으로 만나도록 중계하는 Tor 가상 접점

## 핵심 통찰
- VPN은 "당신의 ISP(통신사)로부터 트래픽을 숨겨주지만, 대신 VPN 회사에게 당신의 모든 트래픽을 넘겨주는 신뢰의 외주화"에 불과함 → 반면 Tor는 "어느 누구도 신뢰할 필요가 없는(Trustless) 수학적 익명성"을 제공함
- Tor가 안전하다고 해서 평문 HTTP 웹사이트에 접속하면 출구 노드 운영자가 계정 비밀번호를 그대로 훔쳐봄 → 출구 노드 구간의 도청을 막기 위해 반드시 "HTTPS over Tor" 형태로 이중 암호화해야 함
- 전 세계 네트워크 백본을 감시할 수 있는 초강대국 정보기관은 진입 트래픽과 출구 트래픽의 패킷 크기 및 시간차를 대조하는 '트래픽 상관관계 공격(Traffic Correlation Attack)'으로 익명성을 벗겨낼 수 있음

## 이웃 토픽과 구분
- Tor vs VPN: Tor = 3개 분산 자원봉사 노드 경유, 속도 매우 느림, P2P 탈중앙화 익명성 / VPN = 1개 상용 서버 경유, 속도 빠름, 중앙 서버에 모든 트래픽 로그 집중

## 문제·원인·대책
- 사례: 공공장소에서 Tor 브라우저를 통해 사내 인트라넷에 접속하던 직원의 로그인 자격증명이 출구 노드 스니핑으로 탈취된 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 악의적 출구 노드 운영자에 의한 민감 데이터 평문 도청 | 비암호화 통신(HTTP, FTP) 사용 시 최종 노드에서 복호화된 데이터 노출 | 종단 간 전송 계층 암호화(HTTPS, TLS 1.3) 결합 강제 | 출구 노드에서도 오직 암호화된 트래픽만 보여 도청 원천 차단 |
| 랜섬웨어 공격자가 Tor 네트워크를 C2(명령제어) 서버 은닉에 악용 | Tor 히든 서비스(.onion)의 IP 역추적 불가능 특성 악용 | 방화벽에서 알려진 Tor 진입 노드(Guard/Relay) IP 목록 전면 차단 | 사내 감염 단말의 Tor C2 서버 통신 시도 즉시 격리 |

## 내 의견
- [Tor 노드 트래픽의 제로트러스트 사내망 진입 원천 봉쇄] Tor는 내부고발자와 인권운동가를 위한 훌륭한 자유 도구이지만, 기업 보안 관점에서는 내부 데이터 반출과 랜섬웨어 C2 통신의 90% 이상이 경유하는 위험 통로임 → 나라면: 전사 경계 방화벽과 CASB에 Tor 공용 디렉토리 서버의 모든 중계 노드 IP 목록을 매시간 자동 수집·동기화하여 인바운드 및 아웃바운드 Tor 트래픽을 일체의 예외 없이 자동 드롭
