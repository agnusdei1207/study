## 지식 로드맵 내 현재 위치

- 정보보안 → 디지털 포렌식 → 저장매체 포렌식 → 파일슬랙(File Slack)

```text
[파일 클러스터 할당 (예: 4,096 Bytes)]
┌─────────────────────────────────┬────────────────────────────────┐
│ 논리적 파일 데이터 (예: 1,500B) │ 파일슬랙 (File Slack, 2,596B)  │
└─────────────────────────────────┴───┬────────────────────────────┘
                                      ├── RAM 슬랙 (마지막 섹터 끝까지)
                                      └── 드라이브 슬랙 (클러스터 끝까지)
```

## 30초 인출

- **본질:** 파일의 실제 논리적 바이트 크기와 파일시스템이 최소 할당 단위인 클러스터(Cluster)로 할당한 물리적 저장 공간 사이의 잉여 미사용 영역.
- **메커니즘:** 파일 쓰기 발생 → 고정 클러스터 단위 할당 → 유효 데이터 기록 후 잔여 섹터에 이전 삭제 데이터 또는 메모리 버퍼 잔존 → 비트스트림 이미징으로 추출.
- **통찰:** 단순 논리적 파일 복사로는 슬랙 공간이 누락되므로 반드시 E01/RAW 형식의 물리적 비트스트림 이미징을 수행하고 타임라인 및 메타데이터와 결합한 교차 검증 필수.

---

## 2~4교시 예상문제 (25점)

> 파일시스템의 할당 단위에 의해 발생하는 파일슬랙(File Slack)의 생성 원리와 세부 유형(RAM 슬랙, 드라이브 슬랙)을 설명하고, 디지털 포렌식 관점의 증거 수집 가치 및 안티 포렌식 은닉 공격 대응 방안을 제시하시오. (25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 파일에 저장된 실제 논리적 데이터의 끝(EOF)과 파일시스템이 해당 파일에 할당한 마지막 클러스터의 물리적 끝 사이에 존재하는 잉여 저장 영역 |
| 목적 | 파일이 덮어쓰여진 후에도 미처 지워지지 않은 이전 삭제 파일의 잔존 파편(Fragment)을 복원하여 삭제된 증거 및 은닉 악성코드 추적 |

- 운영체제는 디스크 입출력 효율화를 위해 섹터(512B/4KB)의 묶음인 클러스터(보통 4KB) 단위로 공간을 할당하므로 필연적으로 슬랙 공간이 발생.

---

## Ⅱ. 파일슬랙의 핵심 특징 및 공간 구조

### 1. 파일슬랙의 주요 특징

| 특징 | 설명 | 포렌식 분석 관점 |
|---|---|---|
| 과거 데이터 잔존 | 신규 파일이 덮어쓰지 못한 이전 블록 보존 | 이전에 삭제된 문서, 이메일, 웹 캐시의 텍스트 파편 획득 가능 |
| 파일시스템 인식 불가 | 운영체제 파일 브라우저에서 투명하게 은폐 | 일반 사용자는 접근 불가하며 전용 포렌식 도구로만 바이트 단위 덤프 가능 |
| 안티 포렌식 은닉 통로 | 비밀 데이터 및 악성 페이로드 은닉 악용 | 슬래커(Slacker), bmap 도구를 통해 탐지 회피용 C2 통신 모듈 은닉 |
| 논리적 복사 시 유실 | 파일 단위 복사 시 슬랙 데이터 배제 | 포렌식 무결성을 위해 물리적 비트스트림 덤프(Bit-stream Image) 필수 |

### 2. 클러스터 내 파일슬랙의 구조적 배치

```text
[클러스터 크기: 4,096 Bytes (512B 섹터 8개로 가정)]
+-----------------------------------------------------------------------------------------+
| Sector 1 | Sector 2 | Sector 3 (마지막 데이터 섹터) | Sector 4 | Sector 5 ~ Sector 8    |
+----------+----------+-----------------------------+----------+-------------------------+
| <─── 논리적 파일 유효 데이터 (1,200 Bytes) ───>|           |                         |
|                                                | RAM 슬랙  | <──── 드라이브 슬랙 ────>|
|                                                | (336 B)   | (Sector 4~8: 2,560 B)   |
| <─────────────────────── 유효 데이터 ──────────>| <────── 파일슬랙 (2,896 Bytes) ─────>|
+-----------------------------------------------------------------------------------------+
```

## Ⅲ. 파일슬랙 세부 구조 및 포렌식 수집·분석 프로세스

### 1. RAM 슬랙과 드라이브 슬랙의 비교 분석

```text
[파일슬랙 세부 분류]
  ├── 1. RAM 슬랙 (RAM Slack)
  │     - 파일의 논리적 끝(EOF)부터 파일이 위치한 마지막 섹터 끝(512B 경계)까지의 영역
  │     - 과거(Windows 95/98): OS 커널 RAM 버퍼의 잔존 데이터가 그대로 기록되어 민감정보 노출
  │     - 현대 OS(Windows NT 이후, Linux): 보안을 위해 마지막 섹터 여백을 0x00 (Zero-fill)으로 패딩
  │
  └── 2. 드라이브 슬랙 (Drive / File Slack)
        - 마지막 데이터 섹터 다음 섹터부터 할당된 클러스터의 마지막 섹터 끝까지의 영역
        - 섹터 단위 입출력 구조상 OS가 0으로 채우지 않고 이전 파일의 디스크 잔존 데이터를 그대로 보존
        - 디지털 포렌식 증거 복원의 핵심 대상 영역
```

### 2. 파일슬랙 수집 및 무결성 보증 4단계 프로세스

| 단계 | 수행 작업 | 핵심 통제 사항 |
|---|---|---|
| 1. 물리적 이미징 | 원본 저장매체 쓰기 방지 장치(Write Blocker) 연결 후 비트스트림 덤프 | 논리 복사가 아닌 RAW(DD), E01 포맷 물리 덤프 강제 |
| 2. 파일시스템 파싱 | MFT(NTFS) 또는 Inode(EXT4) 분석을 통한 클러스터 할당 매핑 확인 | 비할당 클러스터와 할당 클러스터의 슬랙 영역 분리 |
| 3. 슬랙 데이터 카빙 | Sleuth Kit, EnCase, FTK 등을 활용하여 슬랙 영역 내 정규표현식 및 시그니처 검색 | 정규 텍스트(주민번호, 계좌, 이메일), JPEG 헤더 파편 스캔 |
| 4. 교차 검증 및 증거화 | 파일 생성 타임라인($MFT $STANDARD_INFORMATION) 및 이벤트 로그 대조 | 이전 거주 파일의 삭제 시점과 현재 파일 생성 시점 비교 증명 |

## Ⅳ. 파일시스템 내 저장 공간 유형 비교

### 1. 파일시스템 공간 4종 비교

| 구분 | 할당 영역 (Allocated Space) | 파일슬랙 (File Slack) | 비할당 공간 (Unallocated Space) | 볼륨 슬랙 (Volume Slack) |
|---|---|---|---|---|
| 위치 기준 | 파일의 논리적 데이터가 차지하는 영역 | 파일의 끝부터 할당된 클러스터 끝 | 어떤 파일에도 할당되지 않은 클러스터 | 볼륨 파티션 끝과 물리 디스크 끝 사이 |
| 파일시스템 인식 | 디렉터리 엔트리에 유효 파일로 등록 | 활성 파일의 클러스터 내부로 인식 | 여유 공간(Free Space)으로 인식 | 파티션 테이블 외부 영역 |
| 포렌식 데이터 | 현재 사용 중인 최신 파일 원본 | 이전 삭제 파일 파편 또는 은닉 악성 데이터 | 완전 삭제된 파일의 전체 바이트 및 파편 | MBR/GPT 변조를 통한 파티션 은닉 데이터 |
| 분석 도구 | 표준 파일 탐색기, 일반 OS API | TSK(fls, blkls), EnCase, FTK | 카빙 도구(Scalpel, Foremost), X-Ways | 디스크 헥사 에디터, 파티션 복구 도구 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 솔리드 스테이트 드라이브(SSD)의 백그라운드 가비지 컬렉션(GC) 및 TRIM 명령 실행 시 드라이브 슬랙 데이터가 즉시 0x00으로 소거되어 증거 유실 | 침해 사고 단말 식별 즉시 전원을 물리적으로 차단하여 OS 차원의 TRIM 명령 전달을 차단하고 칩오프(Chip-off) 또는 벤더 전용 펌웨어 덤프 수행 |
| 공격자가 슬래커(Slacker) 도구를 악용하여 슬랙 공간에 악성코드나 기밀 문서를 주입하고 MFT 할당 레코드 크기를 조작하여 은닉 | 클러스터 할당 크기 대비 논리 파일 크기 비율(Slack Ratio)을 전수 스캔하는 자동화 엔트로피 분석 린터를 실행하여 비정상 고엔트로피 슬랙 섹터 색출 |
| 파편화된 슬랙 데이터만으로는 파일의 전체 맥락 및 생성 주체(User Attribution)를 법정에서 단정적으로 입증 불가 | USN 저널(Change Journal), 프리페치(Prefetch), 셸백(Shellbag) 및 윈도우 레지스트리의 삭제 이벤트 로그와 타임라인 결합 분석 수행 |

## Ⅵ. 제언

### 1. 안티 포렌식 슬랙 은닉 탐지 아키텍처

```text
[디스크 물리 이미지 (E01)] ──> [파일시스템 파서 (TSK)] ──> [슬랙 영역 바이트 스트림 분리]
                                                                      │
                                 ┌────────────────────────────────────┴────────────────────────────────────┐
                                 ▼                                                                         ▼
                      [엔트로피(Entropy) 분석]                                                  [시그니처 / 텍스트 카빙]
                      - 슬랙 영역의 비정상 고엔트로피 탐지                                        - 매직 넘버(MZ, PK, PDF) 탐지
                      - 암호화 은닉 페이로드 식별                                                - 삭제된 이메일/대화록 복원
                                 │                                                                         │
                                 └────────────────────────────────────┬────────────────────────────────────┘
                                                                      ▼
                                                       [디지털 증거 무결성 보고서]
```

### 2. 포렌식 분석 대상 영역별 가치 및 난이도 비교

| 분석 영역 | 증거 가치 | 추출 복잡도 | 데이터 무결성 보존도 | 주 분석 목적 |
|---|---|---|---|---|
| 활성 파일 영역 | 상 | 매우 낮음 | 완벽 (OS 지원) | 현재 실행 중인 파일 및 설정 분석 |
| 파일슬랙 (File Slack) | 최상 | 중간 | 보통 (새 파일 크기에 종속) | 삭제 파일의 잔존 파편 및 은닉 데이터 색출 |
| 비할당 공간 (Unallocated) | 상 | 높음 (카빙 필요) | 낮음 (조각화 심함) | 완전 삭제된 대용량 파일 복원 |
| 메모리 슬랙 (RAM Slack) | 보통 (최신 OS Zero) | 낮음 | 낮음 (대부분 0x00) | 구형 레거시 OS 환경 커널 잔존 버퍼 분석 |

- 디지털 포렌식 조사에서 파일슬랙은 삭제된 파일의 결정적 단서를 제공하는 핵심 보고이므로, 물리적 비트스트림 수집 원칙을 엄수하고 타 시스템 아티팩트와의 상호 연관성 분석을 통한 증거 능력 완성 필수.
