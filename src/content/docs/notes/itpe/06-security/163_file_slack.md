# 파일슬랙(File Slack)

## 핵심 개념
- 파일 시스템에서 파일을 저장할 때 할당되는 클러스터(Cluster) 또는 섹터(Sector)의 물리적 크기와 파일의 실제 논리적 데이터 크기 사이의 차이로 인해 발생하는 미사용 잉여 공간.
- 이전 파일의 잔존 데이터가 남아 있을 수 있어 디지털 포렌식 조사에서 삭제된 증거 복원의 핵심 영역으로 활용되며, 악성코드 은닉 및 안티 포렌식 수단으로도 악용됨.

```
+-------------------------------------------------------------+
|               클러스터 내부 슬랙 공간 구조 (예: 4KB)           |
+-------------------------------------------------------------+
| [ 실제 파일 데이터 (600B) ]                                  |
| [ RAM 슬랙 (424B) ]        <- 섹터(512B) 잔여 공간 (0 패딩) |
| [ 드라이브 슬랙 (3,072B) ]  <- 나머지 7개 섹터 (이전 데이터 잔존)|
+-------------------------------------------------------------+
```

---

## 슬랙 공간의 종류 및 상세 구조

```
클러스터 (1 Cluster = 8 Sectors = 4,096 Bytes 기준)
+----------+----------+----------+----------+----------+----------+----------+----------+
| Sector 1 | Sector 2 | Sector 3 | Sector 4 | Sector 5 | Sector 6 | Sector 7 | Sector 8 |
+----------+----------+----------+----------+----------+----------+----------+----------+
|<-파일(600B)->|                                                                       |
|  (Data)  |RAM 슬랙  | <------------------- 드라이브 슬랙 (3,072B) ------------------> |
|          | (424B)   |                                                                       |
+----------+----------+---------------------------------------------------------------+
|<--- Sector 1 & 2 -->|<----------------------- Sector 3 ~ 8 ------------------------->|
```

### 1. 램 슬랙 (RAM Slack)
- 파일의 마지막 데이터가 위치한 섹터의 끝부분까지의 빈 공간.
- 과거 운영체제(Windows 95/98 이전)에서는 메모리(RAM) 버퍼의 내용을 그대로 덤프하여 저장했기 때문에 시스템 메모리 잔존 데이터가 유출되었으나, 최신 OS는 보안을 위해 0x00(Null)으로 덮어씀(Zero-padding).

### 2. 드라이브 슬랙 / 파일 슬랙 (Drive / File Slack)
- 램 슬랙이 위치한 첫 섹터 이후부터 해당 클러스터의 마지막 섹터까지의 공간.
- 새 파일이 해당 섹터들을 덮어쓰지 않고 클러스터만 할당받았으므로, 과거에 이 클러스터를 사용했던 이전 파일의 데이터 조각(삭제된 이메일, 문서 내용 등)이 그대로 잔존.

### 3. 볼륨 슬랙 (Volume Slack)
- 전체 하드디스크 파티션(볼륨) 크기가 클러스터 크기의 정수 배로 나누어떨어지지 않아, 파티션의 끝과 마지막 클러스터 사이에 남는 미할당 섹터 공간.

### 4. 파일 시스템 슬랙 (File System Slack)
- 물리적 디스크 전체 용량과 운영체제가 생성한 파티션 크기 사이의 차이로 인해 운영체제에 의해 인식되지 않는 여유 공간.

## 슬랙 공간 유형별 비교

| 슬랙 유형 | 발생 위치 | 생성 원인 | 포렌식 가치 및 특징 |
|---|---|---|---|
| **RAM 슬랙** | 파일 끝 ~ 해당 섹터(512B) 끝 | 섹터 크기 불일치 | 최신 OS는 0x00 채움, 구형 OS는 메모리 단편 잔존 |
| **드라이브 슬랙** | 파일 끝 섹터 다음 ~ 클러스터 끝 | 클러스터 할당 단위 불일치 | 이전 파일의 파편 데이터 보존, 안티 포렌식 은닉지로 활용 |
| **볼륨 슬랙** | 마지막 클러스터 끝 ~ 볼륨 끝 | 볼륨 크기와 클러스터 정수배 불일치 | 파티션 끝 미할당 섹터, 비인가 데이터 은닉 가능 |
| **파일 시스템 슬랙** | 파티션 끝 ~ 물리 디스크 끝 | 전체 디스크와 파티션 크기 차이 | OS에 마운트되지 않으므로 고의적 데이터 은닉 표적 |

## 포렌식 조사 및 안티 포렌식 관점의 의미

### 1. 디지털 포렌식 증거 수집
- 용의자가 원본 파일을 삭제(Delete)한 후 새 파일을 덮어쓰더라도, 클러스터의 슬랙 공간에 이전 삭제된 파일의 텍스트, 암호화 키, 채팅 로그 파편이 그대로 남아 있을 가능성이 높음.
- EnCase, FTK, Autopsy 등 포렌식 도구는 파일 메타데이터뿐만 아니라 슬랙 공간 전체를 덤프 및 카빙(Carving)하여 증거 복원.

### 2. 안티 포렌식(Anti-Forensics) 악용 및 대응
- **은닉 기법**: B-slack, Slacker 등의 도구를 악용하여 악성코드 바이너리나 탈취한 기밀 데이터를 슬랙 공간에 쪼개어 은닉(Stenography)하고, 정상 파일처럼 위장.
- **와이핑(Wiping) 기술**: 증거 인멸을 방지하거나 보안 폐기를 위해 BleachBit, SDelete 등의 도구로 디스크의 슬랙 공간을 무작위 데이터로 여러 번 덮어쓰기(Zero-fill / DoD 5220.22-M) 수행.

## 결론 및 실무 시사점
- 파일슬랙은 파일 시스템의 할당 블록 단위(섹터, 클러스터)와 데이터 크기의 불일치로 필연적으로 발생하는 잉여 공간임.
- 침해사고 분석관은 슬랙 공간 내 잔존 아티팩트의 증거 능력을 확보하기 위해 비할당 영역을 포함한 물리 디스크 비트열 복제(Bit-stream Image) 원칙을 엄격히 준수해야 함.
