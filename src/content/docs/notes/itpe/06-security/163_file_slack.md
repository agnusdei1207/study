## Ⅰ. 파일슬랙(File Slack)의 개요

- 개념 : 컴퓨터 파일 시스템(FAT, NTFS, EXT4 등)에서 파일이 디스크에 저장될 때, 파일의 실제 물리적 데이터 크기와 운영체제가 할당하는 고정 단위(섹터 및 클러스터) 크기 간의 차이로 인해 발생하는 비어 있는 미사용 물리적 잔여 공간.
- 배경 및 필요성 : 운영체제는 입출력 효율성을 위해 디스크를 512바이트(섹터) 또는 4KB(클러스터) 단위의 블록으로 일괄 할당하므로, 파일 끝(EOF)부터 할당된 블록 끝까지 필연적으로 비어 있는 공간이 발생하며 여기에 과거 삭제된 데이터가 잔존함.
- 핵심 목적 : 디지털 포렌식(Digital Forensics) 수사 시 피의자가 은닉하거나 삭제한 과거의 민감 파일 파편, 암호 키, 악성코드 조각을 복원·분석하기 위한 핵심 증거 수집 영역.

## Ⅱ. 파일슬랙(File Slack)의 핵심 아키텍처 및 동작 메커니즘

파일 슬랙은 섹터 단위 잔여 공간인 RAM 슬랙(RAM Slack)과 클러스터 단위 잔여 공간인 드라이브 슬랙(Drive Slack / File Slack)으로 정밀하게 구분됨.

```text
[ 파일 슬랙(File Slack)의 물리적 구조 및 잔여 공간 분석 ]

  하나의 클러스터(Cluster) = 4,096 Bytes (8개 섹터로 구성, 섹터당 512B)
 +----------------------------------------------------------------------+
 | Sector 1 | Sector 2 | Sector 3 | Sector 4 | ... | Sector 7 | Sector 8|
 +----------------------------------------------------------------------+
 | <======== 실제 파일 데이터 (예: 1,300 Bytes) ========> |             |
 | [ 512B ] | [ 512B ] | [ 276B ] |                      |             |
 +---------------------+----------+----------------------+-------------+
                                  |                      |
                                  v                      v
                       [ RAM 슬랙 (RAM Slack) ]  [ 드라이브 슬랙 (Drive Slack) ]
                       * Sector 3의 나머지:      * Sector 4 ~ Sector 8 전체:
                         512 - 276 = 236 Bytes     512B * 5 = 2,560 Bytes
                       * 구형 OS: 메모리 덤프    * 과거에 이 클러스터를 쓰다가
                         최신 OS: 0x00(Zero)패딩   삭제된 이전 파일의 원본 데이터
                                                   파편이 고스란히 남아 있음!
 ========================================================================
 [ 전체 파일 슬랙 = RAM 슬랙(236B) + 드라이브 슬랙(2,560B) = 2,796 Bytes ]
 * 디지털 포렌식 도구(EnCase, FTK)가 슬랙 공간을 전수 덤프하여 증거 복원!
```

- **RAM 슬랙(RAM Slack)** : 파일의 마지막 데이터가 위치한 섹터의 끝까지 남는 공간(파일 끝 ~ 해당 512바이트 섹터 끝). 구형 OS(Windows 95/98)에서는 메인 메모리(RAM) 내용이 그대로 복사되어 메모리 기밀 유출이 발생했으나, 현대 OS는 0x00(Zero)으로 패딩.
- **드라이브 슬랙(Drive Slack)** : 마지막 데이터 섹터 다음 섹터부터 할당된 전체 클러스터 끝까지 남는 공간(Sector 4~8). 이전에 동일 클러스터에 저장되었다가 삭제된 파일의 실제 원본 데이터 파편이 덮어써지지 않고 그대로 잔존.
- **데이터 은닉 기술(Data Hiding) 악용** : 안티 포렌식 공격자가 정상 파일의 드라이브 슬랙 공간에 악성코드 바이너리나 기밀 문서를 은닉(Slacker 도구 등)하여 파일 탐색기 및 안티바이러스 검사 우회.
- **볼륨 슬랙(Volume Slack)** : 전체 파티션 크기가 클러스터 단위로 정확히 나누어떨어지지 않아 디스크 볼륨 끝에 할당되지 못한 채 버려지는 잉여 섹터 공간.

## Ⅲ. 파일슬랙(File Slack)의 세부 구성 요소 및 비교 분석

| 비교 항목 | **RAM 슬랙** (RAM Slack) | **드라이브 슬랙** (Drive Slack) | **볼륨 슬랙** (Volume Slack) |
| --- | --- | --- | --- |
| 위치 범위 | 파일 끝(EOF) ~ 해당 섹터(512B) 끝 | 데이터 섹터 다음 ~ 클러스터(4KB) 끝 | 파티션 할당 영역 끝 ~ 물리 볼륨 끝 |
| 기록 데이터 | 현대 OS는 0x00 패딩 (구형은 RAM 덤프) | 이전에 삭제된 파일의 원본 데이터 파편 | 파티션 포맷 이전의 원시 잔여 데이터 |
| 포렌식 가치 | 구형 시스템 메모리 흔적 (현재는 낮음) | 극도로 높음 (삭제된 문서, 비밀번호 복원) | 높음 (안티 포렌식 은닉 영역 조사) |
| 크기 범위 | 최대 511 Bytes 미만 | 수백 Bytes ~ 수천 Bytes (클러스터 종속) | 수 섹터 분량 (디스크 지오메트리 차이) |
| 은닉 가능성 | 크기가 작아 대용량 파일 은닉 불가 | 안티포렌식 툴을 통한 데이터 은닉 빈발 | 숨겨진 파티션 및 부트킷 은닉 가능 |

- 파일 슬랙은 파일 시스템의 고정 블록 할당 구조로 인해 필연적으로 발생하는 영역이며, 삭제된 핵심 증거 복원과 악의적 은닉 데이터 적발을 위한 포렌식의 필수 분석 대상임.

## Ⅳ. 파일슬랙(File Slack)의 주요 한계점 및 해결 방안

- SSD의 TRIM 명령어 활성화에 따른 슬랙 및 비할당 영역 자동 소거 :
  - 한계점 : 현대 SSD 드라이브는 성능 유지를 위해 파일 삭제 시 컨트롤러 레벨에서 TRIM을 실행하여 해당 블록을 0으로 자동 소거하므로 증거 복원 불능.
  - 해결 방안 : 증거 수집 시 SSD 펌웨어 레벨의 저수준 덤프 도구 활용 및 드라이브 전원 인가를 즉시 차단하여 가비지 컬렉션 동작 방지.
- 안티 포렌식 와이핑(Wiping) 도구에 의한 슬랙 공간 영구 삭제 :
  - 한계점 : 피의자가 CCleaner, BCWipe 등 포렌식 방해 도구를 사용하여 모든 파일 슬랙 공간을 난수(0x00, 0xFF)로 덮어쓰기(Zero-fill) 수행.
  - 해결 방안 : 슬랙 공간의 인위적 0 패딩 흔적 자체를 안티 포렌식 증거 인멸 정황(사법 방해)으로 포렌식 보고서에 채증 입증.
- 대용량 테라바이트(TB) 디스크 전수 조사 시 포렌식 분석 시간 폭증 :
  - 한계점 : 수백만 개의 파일 슬랙 공간을 일일이 추출하여 카빙 분석하는 데 수일 이상의 막대한 연산 시간 소요.
  - 해결 방안 : 타임라인 분석(MACB 시간)을 통해 침해 사고 발생 시점에 수정된 파일의 슬랙 공간을 우선순위화하여 타깃 수집.

## Ⅴ. 파일슬랙(File Slack) 적용 및 발전을 위한 기술사적 제언

- 디지털 포렌식 증거 수집 시 비트스트림 물리적 이미지(Raw E01) 필수 생성 : 단순 파일 복사가 아닌 디스크 물리적 섹터를 1:1 복제하는 이미징(EnCase E01/DD)을 수행하여 슬랙 공간을 완벽히 보존.
- 기업 데이터 폐기 정책에 슬랙 공간 전용 와이핑 의무화 : 퇴사자 PC 반납이나 중고 불용 장비 매각 시 파일 시스템 메타데이터뿐만 아니라 파일 슬랙 및 비할당 공간 전용 와이핑(DoD 5220.22-M 준수) 강제.
- 안티 포렌식 데이터 은닉 탐지 자동화 스크립트 가동 : 파일의 실제 헤더 크기와 파일 시스템 MFT에 기록된 할당 크기 간의 불일치를 자동 비교하여 슬랙 공간에 실행 코드가 숨겨진 이상 파일을 즉시 색출.
