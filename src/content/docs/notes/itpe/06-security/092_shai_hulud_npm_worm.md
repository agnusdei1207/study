## Ⅰ. Shai-Hulud npm 웜의 개요

- 핵심 요약 : 설치 시 실행되는 스크립트로 개발자 자격증명을 빼내 관리 중인 패키지를 자동 재배포하는 공급망 웜.
- 개념 : 노드 패키지 관리자(npm, Node Package Manager) 설치 과정에서 실행되는 **postinstall** (패키지 설치 직후 자동 실행되는 npm 라이프사이클 스크립트) 스크립트로 개발자의 토큰을 탈취하고, 그 토큰으로 감염자가 관리하는 다른 패키지에 악성 버전을 자동 재배포하는 **자가 증식 웜** (스스로 복제되어 확산하는 악성 코드).
- 배경 및 필요성 : 2025년 9월 npm 생태계에서 확인된 사례로, 정상 배포 경로를 통해 악성 코드가 퍼지면서 개발 환경과 CI/CD 파이프라인의 자격증명 보호가 시급해짐.
- 주요 목적 : 침해된 한 계정을 발판으로 다수의 패키지와 이를 쓰는 다운스트림 프로젝트에 연쇄적으로 침해를 확산하는 것.

## Ⅱ. Shai-Hulud npm 웜의 특징 및 장점

- 핵심 요약 : 정상 배포 권한을 재사용하는 자동 복제 구조가 탐지 우회와 연쇄 확산을 동시에 가능하게 함.

1. 정상 배포 경로 재사용 : 개발자의 정식 토큰으로 공식 레지스트리에 게시 → 정상 업데이트처럼 보여 기존 보안 룰을 우회.
2. 자격증명 기반 자동 확산 : 토큰이 가진 쓰기 권한의 패키지 목록을 조회해 반복 감염 → 중앙 공격 인프라 없이 확산.
3. CI/CD 연동 : 빌드 파이프라인의 자동 실행과 맞물려 감염 범위가 짧은 시간에 커짐.

## Ⅲ. Shai-Hulud npm 웜의 구조 (흐름)

- 핵심 요약 : 설치 시 스크립트 실행, 자격증명 수집, 쓰기 권한 패키지 재게시, 하위 의존자로의 확산이 이어지는 흐름.

```text
[ 감염 및 확산 흐름 ]

패키지 설치 (npm install)
              ↓
postinstall 스크립트 실행
              ↓
npm·GitHub 토큰, SSH 키 수집
              ↓
토큰의 쓰기 권한 패키지 목록 조회
              ↓
악성 버전 재게시 (정상 계정 명의)
              ↓
하위 의존자 프로젝트로 연쇄 설치
```

```text
[ 재게시 루프 ]

감염된 개발자 PC
              ↓
패키지 A의 악성 버전 게시
              ↓
패키지 A를 설치한 CI 빌드 실행
              ↓
빌드 환경의 토큰 수집 (감염 반복)
```

1. postinstall : package.json에 등록된 스크립트가 설치와 동시에 실행되어 악성 코드를 기동.
2. **자격증명 탈취** (Credential Theft) : `~/.npmrc`의 토큰과 `NPM_TOKEN`, `GITHUB_TOKEN` 같은 환경 변수를 수집해 외부 서버로 전송.
3. 자가 증식 (Worm Propagation) : 탈취한 토큰으로 쓰기 권한이 있는 패키지를 조회하고, 각 패키지에 악성 스크립트를 넣어 버전을 올린 뒤 재게시.

## Ⅳ. Shai-Hulud npm 웜과 전통적 타이포스쿼팅의 비교

- 핵심 요약 : 오타를 노리던 **타이포스쿼팅** (Typosquatting, 유명 패키지와 비슷한 이름으로 사용자의 오입력을 유도하는 공격)과 달리, 웜은 정식 패키지를 자동 확산의 매개로 씀.

| 비교 항목 | 타이포스쿼팅 | 자가 증식 웜 |
| --- | --- | --- |
| 패키지 명칭 | 유명 패키지와 유사한 오타 명칭 | 널리 쓰이는 정식 패키지 명칭 그대로 |
| 배포 주체 | 공격자가 만든 신규 익명 계정 | 침해된 정식 관리자 계정 |
| 전파 방식 | 개발자의 오입력에 의존 (수동적) | 탈취한 자격증명으로 자동 확산 (능동적) |
| 확산 속도 | 오타를 입력한 일부 사용자에게 한정 | CI/CD 자동 빌드를 타고 빠르게 확산 |
| 탐지 난이도 | 신규 계정과 패키지명 점검으로 탐지가 비교적 쉬움 | 공식 버전 업데이트로 보여 기존 탐지 룰을 우회 |

## Ⅴ. Shai-Hulud npm 웜의 한계와 방안

- 핵심 요약 : 설치 스크립트 차단의 부작용, 장기 토큰, 은닉된 의존성, 회수 지연을 허용 목록, 단기 신뢰 게시, 행위 분석, 격리 릴리즈로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 스크립트 전역 차단의 부작용 | 네이티브 모듈 빌드가 실패해 개발 생산성 저하 | 검증된 패키지에만 설치 스크립트 실행을 허용하는 허용 목록 도구 적용 | 허용 목록 등록 패키지 수 |
| 2단계 인증을 우회하는 자동화 토큰 | 자동 배포용 토큰은 유출 시 재게시에 악용 가능 | 장기 자동화 토큰 발급 금지, OIDC(OpenID Connect) 기반 단기 신뢰 게시(Trusted Publishers)로 전환 | 장기 토큰 잔존 건수 |
| 깊은 서브 의존성(Transitive Dependencies)의 은닉 코드 | 다수의 간접 의존성에 숨은 코드를 육안으로 식별 불가 | 빌드 단계에서 AST(Abstract Syntax Tree, 추상 구문 트리) 기반 행위 분석 도구로 네트워크 호출과 파일 접근 탐지 | 행위 분석 경고 건수 |
| 오염 버전의 회수 지연 | 감염 버전이 게시된 뒤 회수가 늦어져 피해 확산 | 신규 릴리스를 일정 기간 격리해 동적 분석 후 공개하는 **카나리아 릴리즈** (Canary Release) 정책 | 격리 중 차단 건수 |

## Ⅵ. Shai-Hulud npm 웜에 대한 기술사적 제언

- 핵심 요약 : 자격증명을 짧게 쓰고 권한을 나누며, 외부 패키지의 유입을 조직 차원에서 통제하는 체계가 필요함.

1. 자격증명 현대화 : 조직 내 장기 npm 토큰을 없애고 신뢰 게시 방식으로 옮기는 전환 로드맵 수립 필요.
2. 개발 환경 하드닝 : 개발자 단말과 CI 러너에 스크립트 실행 정책과 설정 파일 접근 통제를 기본값으로 적용하는 방향 필요.
3. 공급망 거버넌스 : 사내 패키지 저장소를 캐시로 두고 신규 패키지를 일정 기간 검증한 뒤 승인된 버전만 쓰는 절차 필요.

## Ⅶ. 결론

- 핵심 요약 : 공급망 웜의 피해 크기는 악성 패키지의 유입 경로보다 개발자 자격증명이 가진 권한의 범위에 좌우됨.
- 시사점 : 장기 토큰을 줄이고 설치 권한과 배포 권한을 분리하는 조직이 연쇄 확산을 끊을 수 있음.
