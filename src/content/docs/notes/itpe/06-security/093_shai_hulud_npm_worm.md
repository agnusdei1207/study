## 한 줄 본질
- 수천 개의 오픈소스 패키지를 설치할 때 실행되는 자동 스크립트(`postinstall`)의 맹목적 신뢰 병목 → 개발자 PC의 레지스트리 배포 토큰을 탈취하여 해당 개발자가 관리하는 모든 패키지에 악성코드를 주입·재배포하는 자가 증식 웜 → 수천 개 기업의 빌드 파이프라인 동시 오염 / 라이프사이클 스크립트 실행 차단 및 서명 검증 필요

## 핵심 용어
- 라이프사이클 스크립트(Lifecycle Scripts): `npm install` 실행 시 패키지 빌드나 네이티브 바인딩을 돕기 위해 사전에 자동으로 실행되도록 지원하는 `preinstall`, `install`, `postinstall` 등의 이벤트 훅
- 자가 증식형 웜(Self-propagating Worm): 외부의 지시 없이도 감염된 호스트의 자원을 이용하여 스스로 복제본을 만들고 다른 표적으로 전파되는 악성 소프트웨어

## 핵심 통찰
- 오픈소스 공급망 공격이 "수동적인 함정 설치(타이포스쿼팅)"에서 "개발자 계정을 감염 매개체로 삼는 능동적 웜(Worm)"으로 진화함
- npm 설치 과정에서 허용된 라이프사이클 스크립트가 실행될 수 있으며, 실행 권한은 npm을 실행한 계정과 환경에 따름. 항상 루트 권한으로 실행되는 것은 아님.
- 개발자 단말의 `~/.npmrc` 파일에 평문으로 저장된 장기 유효 퍼블리시 토큰이 오픈소스 생태계 전체를 파괴하는 뇌관으로 작용함

## 이웃 토픽과 구분
- 오픈소스 웜 vs 타이포스쿼팅: 오픈소스 웜 = 정상 개발자의 계정을 탈취해 정상 패키지의 새 버전으로 침투·자가 증식 / 타이포스쿼팅 = `lodahs`처럼 철자가 틀린 가짜 패키지를 올려놓고 실수를 유도

## 문제·원인·대책
- 사례: 사내 프론트엔드 빌드 파이프라인에서 오픈소스 라이브러리 업데이트 직후 AWS 키 유출 및 사내 프라이빗 패키지 변조 사건 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 패키지 설치 시 개발자 단말의 API 토큰 탈취 및 악성코드 실행 | 악성 설치 스크립트 실행과 비밀값 접근 | 위험 패키지의 설치 스크립트 제한, 격리된 설치·빌드와 비밀값 분리 | 해당 설치 경로의 악성 실행과 탈취 위험 감소 |
| 탈취된 토큰을 이용한 무단 패키지 게시 | 장기 게시 토큰과 넓은 권한 | 가능하면 OIDC 신뢰 게시로 장기 토큰을 없애고 게시 권한·승인 범위를 제한 | 토큰 탈취·재사용 위험 감소. 우회 2FA 토큰이 남아 있으면 MFA만으로 게시를 막지 못함 |

## 내 의견
- [CI/CD 빌드 파이프라인의 격리 및 스크립트 실행 박탈] 로컬 개발자 PC에서 직접 오픈소스 패키지를 퍼블리시하는 관행을 법인 차원에서 금지해야 함 → 나라면: 모든 npm 배포 권한을 개발자 개인이 아닌 서명된 CI/CD 파이프라인(OIDC 임시 토큰 기반)으로 일원화하고, 사내 프라이빗 npm 프록시(Nexus, Artifactory)를 두어 외부 패키지 유입 시 라이프사이클 스크립트가 포함된 패키지를 샌드박스에서 선별 격리 검증

## 10점 답안
Shai-Hulud는 2025년 npm 생태계에서 확인된 자가 증식형 공급망 악성코드 캠페인. 침해된 유지보수 계정으로 정상 패키지에 악성 설치 스크립트를 넣고, 이를 설치한 환경의 비밀값과 게시 권한을 노려 다른 패키지로 확산. 게시 계정 보호와 OIDC 기반 신뢰 게시, 설치 시 스크립트 통제, 격리된 빌드, 패키지·버전 검증이 대응 핵심. `--ignore-scripts`만으로 모든 공급망 위험을 제거할 수 없음.

## 25점 답안
### Ⅰ. 공격 구조
유지보수 계정 침해 → 정상 패키지의 악성 버전 게시 → 설치 단계 스크립트 실행 → 토큰·비밀값 탈취 → 접근 가능한 패키지 재게시의 반복. 캠페인 차수별 세부 기능은 구분.

### Ⅱ. 신뢰 경계
| 경계 | 취약점 | 대응 |
|---|---|---|
| 게시 | 탈취된 장기 토큰·계정 | OIDC 신뢰 게시, MFA, 권한 축소 |
| 설치 | 의존 패키지의 실행 스크립트 | 격리 설치, 스크립트 허용 정책, 버전 고정 |
| CI | 빌드 환경의 비밀값 노출 | 단기 자격증명, 비밀 접근 최소화, 작업별 격리 |
| 배포 후 | 오염된 아티팩트 전파 | 출처·무결성 확인, 악성 버전 식별과 교체 |

### Ⅲ. 운영 판단
의존성 변화와 게시 이력 점검, 침해 버전 확인 시 설치 중지·자격증명 회전·영향 범위 조사. 2FA 설정만으로 우회용 토큰과 손상된 CI의 위험이 사라지지 않음.
