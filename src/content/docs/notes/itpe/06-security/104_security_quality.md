## 지식 로드맵 내 현재 위치

지식 위치: 소프트웨어 품질 → 보안성 → **SDLC 보안 자동화**

## 30초 인출

- 본질: 소프트웨어가 비인가 접근·변경·손상에 저항하고 정해진 보안 요구를 충족하는 정도
- ISO/IEC 25010:2011의 보안성 부특성 5개와 2023년판의 저항성(Resistance) 추가를 구분
- 품질 확보: 요구·설계·구현·검증·운영의 위험 기반 자동화와 예외 관리

## 1교시 예상문제 (10점)

> 소프트웨어 보안 품질의 의미와 SDLC 단계별 자동화 활동을 설명하시오. (제136회 4교시 6번 연계·10점 변형)

## 1교시 10점 답안

### Ⅰ. 정의

보안 품질은 비인가 접근·수정에 대한 보호와 인증·책임 추적 등 보안 요구의 충족 정도. ISO/IEC 25010:2011은 기밀성·무결성·부인방지·책임성·진정성을, 2023년판은 저항성을 추가.

### Ⅱ. 자동화

| 단계 | 활동 |
|---|---|
| 요구·설계 | 보안 요구 추적·위협 모델 검토 |
| 구현 | SAST·SCA·비밀정보 검사 |
| 시험 | DAST·퍼징·권한·API 시험 |
| 배포·운영 | 서명·정책 검사·취약점 모니터링 |

도구 통과가 결함 부재를 보장하지 않으므로 수동 검토와 위험 수용 절차 병행.

## 2~4교시 예상문제 (25점)

> 소프트웨어 보안 품질의 정의와 중요성, 자동화 기술·도구, 라이프사이클 구현 방안, 기대 효과와 시사점을 설명하시오. (제136회 4교시 6번 원문 연계·25점)

## 2~4교시 25점 답안

### Ⅰ. 정의와 중요성

보안 품질은 제품의 보안 요구 충족과 비인가 접근·변경에 대한 보호 수준. 운영 단계에서만 결함을 발견하면 수정·배포·이용자 보호가 늦어지므로 개발 전 과정에서 관리.

### Ⅱ. 품질 모델

| 판본 | 보안성 부특성 |
|---|---|
| ISO/IEC 25010:2011 | 기밀성, 무결성, 부인방지, 책임성, 진정성 |
| ISO/IEC 25010:2023 | 위 다섯 개와 저항성(Resistance) |

2011년판의 '5대'와 2023년판을 혼합해 동일한 목록이라고 설명하지 않음.

### Ⅲ. 자동화 기술·도구

| 방식 | 주요 검출 | 한계 |
|---|---|---|
| SAST | 코드 패턴·데이터 흐름 | 실행 맥락에 따른 오탐·누락 |
| SCA | 외부 라이브러리 취약점·라이선스 | 실제 도달 가능성·설정 검토 필요 |
| DAST | 실행 중 입력·응답의 취약 동작 | 코드 경로·인증 상태에 따라 범위 제한 |
| 퍼징 | 예상 밖 입력에서의 충돌·오류 | 대상·시드·오라클 품질에 좌우 |
| 정책·비밀정보 검사 | 배포 설정·키 노출 | 관리 승인·검토가 필요한 예외 |

### Ⅳ. 라이프사이클 구현

```text
보안 요구·위험 분석
  → 설계 위협 모델
  → 코드/의존성 검사
  → 동적·침투 시험
  → 위험 기반 배포 결정
  → 운영 탐지·취약점 접수
  → 수정 결과의 다음 개발 주기 반영
```

| 운영 요소 | 실행 |
|---|---|
| 품질 게이트 | 심각도뿐 아니라 악용 가능성·노출·자산 중요도 반영 |
| 예외 | 책임자·사유·기한·완화 조치 기록 |
| 증적 | 검사 버전·범위·결과와 조치 이력 보관 |
| 공급망 | 외부 의존성·빌드 경로·아티팩트 무결성 관리 |

### Ⅴ. 기대 효과와 시사점

조기 결함 발견과 반복 가능한 점검, 수정 이력 추적. 그러나 모든 취약점의 자동 제거 또는 보안 사고 0% 보장은 불가. 검사 범위와 오탐률·미해결 위험의 지속 검증 필요.

### Ⅵ. 기술사적 제언

'도구 도입'보다 위험에 맞는 요구·검증·배포 판정과 운영 피드백을 연결한 보안 품질 관리.

## 출제 이력과 검증 출처

- 제136회 Q-net 원문 4교시 6번은 정의·중요성, 자동화 기술·도구, 라이프사이클 구현, 기대 효과·시사점의 네 항목 요구. 위 25점 답안은 이 순서를 반영.
