## Ⅰ. AI 제로트러스트 성숙도 모델의 개요

- 개념 : CISA의 **제로트러스트 5대 기둥** (신원, 기기, 네트워크, 워크로드, 데이터)을 LLM, RAG 지식베이스, 자율 에이전트 인프라에 맞추어 **4단계 성숙도**로 체계화한 평가 및 이행 프레임워크.
- 배경 및 필요성 : AI 파이프라인(데이터 수집, 학습, 추론, 에이전트 실행) 전반에 걸친 보안 사각지대를 해소하고, 신원·데이터·인프라·런타임 영역의 단계별 보안 통제 성숙도를 평가하여 체계적인 **제로 트러스트 아키텍처**를 구현하기 위해 개발됨.
- 핵심 목적 : AI 개발 및 서빙 전주기에서 내부자 위협, 프롬프트 인젝션, 비인간 계정 탈취를 원천 차단하고 단계적 보안 투자 우선순위 수립.

## Ⅱ. AI 제로트러스트 성숙도 모델의 핵심 아키텍처 및 동작 메커니즘

AI 제로트러스트 성숙도 모델은(는) 신뢰할 수 있는 보안 구조와 표준화된 절차를 기반으로 동작하며, 세부적인 아키텍처와 구성요소 간의 상호작용 메커니즘은 다음과 같음.

```text
[ AI 제로트러스트 성숙도 4단계 진화 경로 ]

  1. 전통적 (Traditional)        2. 초기 (Initial)           3. 고급 (Advanced)          4. 최적화 (Optimal)
+-------------------------+   +-----------------------+   +-----------------------+   +-----------------------+
| • 정적 API 키 하드코딩  |   | • 역할 기반 RBAC 도입  |   | • 속성 기반 ABAC 적용 |   | • AI 자율 위험 적응형  |
| • 네트워크 경계 방화벽  | → | • 모델 서빙 VPC 격리  | → | • mTLS 및 서비스메시  | → | • 실시간 인라인 가드레일|
| • 벡터 DB 권한 미분리   |   | • RAG 컬렉션별 분리   |   | • 청크 단위 ACL 필터링|   | • 완전 자동화 피드백  |
| • 1회성 감사 로그 수동  |   | • 중앙 로깅 체계 연동 |   | • SIEM 실시간 상관분석|   | • SOAR 기반 자율 격리 |
+-------------------------+   +-----------------------+   +-----------------------+   +-----------------------+
```

- **전통적 (Traditional)** : 영구 정적 API 키 사용, 수작업 배포, 도구 권한 무제한 허용 (온프레미스 경계 방화벽 의존, 평문 데이터셋 저장).
- **초기 (Initial)** : IAM 역할(Role) 기반 정적 할당, 쿠버네티스 네임스페이스 격리 (네트워크 서브넷 분리, 저장 데이터 AES 암호화).
- **고급 (Advanced)** : **SPIFFE** 워크로드 신원, 태스크별 임시 토큰, 도구 호출 검증 (서비스 메시(Istio) mTLS, RAG 벡터 청크 레벨 ACL 강제).
- **최적화 (Optimal)** : 컨텍스트 기반 **CARTA** 동적 인가, AI 에이전트 행위 이상 탐지 (마이크로세그멘테이션, 실시간 데이터 마스킹/DLP).

|---|---|---|
| 보호 주체 | 사용자 계정, 웹 애플리케이션, RDBMS | 자율 AI 에이전트, 기초 모델 가중치, 벡터 DB 임베딩 |
| 신뢰 경계 검증 | IP, 인증서, 장치 규격 준수 여부 확인 | 자연어 프롬프트, 도구 파라미터, 모델 출력 유해성 검증 |
| 데이터 접근 모델 | 테이블, 행, 열 단위의 정형적 인가 | 시맨틱(Semantic) 유사도 기반 비정형 검색 및 청크 인가 |

## Ⅳ. AI 제로트러스트 성숙도 모델의 주요 한계점 및 해결 방안

- 한계점 : CISA ZTMM의 5대 기둥은 정적 속성 검증 중심이므로 확률적·비결정론적인 LLM 출력의 위험 통제 불가.
  - 해결 방안 : 워크로드 기둥 내에 **의미론적 인라인 가드레일** (NeMo/Llama Guard)을 독립된 PEP로 구축하여 생성 텍스트의 유해성 및 기밀 노출 여부 실시간 차단.
- 한계점 : 대량의 벡터 임베딩 데이터 검색 시 메타데이터 ACL 검증으로 인한 과도한 쿼리 레이턴시 발생.
  - 해결 방안 : 벡터 검색 엔진(Milvus/Pinecone) 레벨에서 **사전 필터링** (Pre-filtering) 인덱싱 아키텍처를 적용하여 인가되지 않은 벡터 청크의 연산 자체를 원천 배제.
- 한계점 : 멀티 클라우드 및 온프레미스 하이브리드 환경에서 AI 에이전트의 통일된 **머신 신원** 연동 표준 부재.
  - 해결 방안 : 클라우드 종속적 IAM을 배제하고 **SPIFFE/SPIRE** 오픈 표준 기반의 X.509 워크로드 신원 발급 및 **OIDC 페더레이션** 체계 단일화.
- 한계점 : 모든 도구 호출과 API 요청에 대해 다계층 암호화(mTLS) 및 OPA 검증 수행 시 추론 응답 지연 급증.
  - 해결 방안 : 서비스 메시 데이터 플레인 가속을 위해 eBPF 기반 초고속 네트워킹(Cilium)을 도입하고 세션 캐싱 적용.

## Ⅴ. AI 제로트러스트 성숙도 모델 적용 및 발전을 위한 기술사적 제언

- 신원 인프라 고도화 중심의 거버넌스 및 실행 체계 구축 : AI 에이전트 대상 머신 신원 자동 등록 및 **RFC 8693** 동적 권한 위임 체계화을(를) 적극 추진하여, 비인가 대리 실행 및 자격증명 도용 원천 차단 효과를 극대화해야 함.
- 지능형 런타임 방어 중심의 거버넌스 및 실행 체계 구축 : MLOps 파이프라인 내 모델 서명 검증 및 추론 게이트웨이 인라인 가드레일 배포을(를) 적극 추진하여, 프롬프트 주입 및 민감정보 유출 사고 사전 차단 효과를 극대화해야 함.
- 성숙도 기반 로드맵 중심의 거버넌스 및 실행 체계 구축 : CISA ZTMM 기준 정기 자체 평가 수행 및 취약 기둥 대상 집중 보안 투자 집행을(를) 적극 추진하여, 국가 보안 권고 및 글로벌 규제(EU AI Act 등) 완벽 준수 효과를 극대화해야 함.
