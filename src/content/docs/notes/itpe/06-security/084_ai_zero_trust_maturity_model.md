## 지식 로드맵 내 현재 위치

제로트러스트 → CISA 성숙도 모델(ZTMM v2.0) → AI 워크로드 제로트러스트

## 30초 인출

- **본질:** CISA 제로트러스트 성숙도 모델(ZTMM v2.0)의 5대 기둥을 생성형 AI 파이프라인, 비인간 에이전트, RAG 데이터 환경에 확장 적용하여 보안 통제 수준을 단계별로 고도화하는 보안 프레임워크.
- **메커니즘:** 전통적(Traditional) → 초기(Initial) → 고급(Advanced) → 최적화(Optimal) 4단계 진화 경로를 따라 AI 신원 인증, 모델/도구 인가, 벡터 DB 접근 제어, 지속적 검증을 자동화.
- 통찰: 기존 인프라 중심의 ZTMM을 넘어 AI 모델의 비결정론적 출력과 에이전트의 대리 실행 권한 위험을 제어하기 위해 인라인 가드레일과 비인간 신원(NHI) 통제의 결합 필수.

<details><summary>핵심 용어</summary>

- **CISA ZTMM v2.0**: 미국 CISA가 발표한 제로트러스트 성숙도 모델로 5대 기둥(신원, 기기, 네트워크, 워크로드, 데이터)과 3대 공통 기능(가시성/분석, 자동화/오케스트레이션, 거버넌스)으로 구성.
- **비인간 신원(NHI) 제로트러스트**: AI 에이전트, 파이프라인 워커, API 키 등 머신 계정에 대해 '절대 신뢰하지 않고 항상 검증(Never Trust, Always Verify)'하는 원칙.
- **동적 가드레일(Dynamic Guardrails)**: AI 입출력 트래픽을 실시간 프록시 형태로 가로채 프롬프트 인젝션 및 데이터 유출을 차단하는 인라인 정책 집행점(PEP).
- **RAG 데이터 인가(RAG Ingestion Auth)**: 벡터 데이터베이스 검색 시점에 원본 문서의 접근 권한(ACL)을 대조하여 비인가 지식의 프롬프트 주입을 차단하는 제어.
- **연속적 적응형 위험 평가(CARTA)**: 정적 1회성 인증을 배제하고 AI 런타임 세션 중 발생하는 행위 위험도를 지속 재평가하는 모델.
</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | CISA의 제로트러스트 5대 기둥(신원, 기기, 네트워크, 워크로드, 데이터)을 LLM, RAG 지식베이스, 자율 에이전트 인프라에 맞추어 4단계 성숙도로 체계화한 평가 및 이행 프레임워크 |
| 목적 | AI 개발 및 서빙 전주기에서 내부자 위협, 프롬프트 인젝션, 비인간 계정 탈취를 원천 차단하고 단계적 보안 투자 우선순위 수립 |

## Ⅱ. AI 제로트러스트 성숙도 모델의 핵심 특징 및 5대 기둥 매핑

| 기둥(Pillars) | AI 워크로드 특화 보호 대상 | 제로트러스트 핵심 통제 메커니즘 |
|---|---|---|
| 신원 (Identity) | AI 에이전트, MLOps 엔지니어, 외부 API 토큰 | 비인간 신원(NHI) mTLS 인증, JIT(Just-In-Time) 최소 권한 발급 |
| 기기 (Device) | GPU 학습 클러스터, 추론 서버, 에지 AI 디바이스 | 호스트 무결성 증명(TPM/Secure Boot), 기기 상태 기반 동적 인가 |
| 네트워크 (Network) | 모델 서빙 VPC, 벡터 DB 클러스터, 외부 CTI 통신망 | 마이크로세그멘테이션, AI Egress 트래픽 화이트리스팅, 서비스 메시 |
| 워크로드 (Workload) | 컨테이너화된 모델 추론 팟(Pod), 도구 호출(Tool Calling) | CI/CD 불변 이미지 서명(Sigstore), 런타임 인라인 가드레일(PEP) |
| 데이터 (Data) | 학습 데이터셋, 파인튜닝 가중치, RAG 벡터 임베딩 | 데이터 계보(Lineage) 추적, 벡터 검색 시 문서 ACL 동적 필터링 |

## Ⅲ. AI 제로트러스트 성숙도 단계별 진화 아키텍처

```text
  1. 전통적 (Traditional)        2. 초기 (Initial)           3. 고급 (Advanced)          4. 최적화 (Optimal)

| • 벡터 DB 권한 미분리   |   | • RAG 컬렉션별 분리   |   | • 청크 단위 ACL 필터링|   | • 완전 자동화 피드백  |
| • 1회성 감사 로그 수동  |   | • 중앙 로깅 체계 연동 |   | • SIEM 실시간 상관분석|   | • SOAR 기반 자율 격리 |
+-------------------------+   +-----------------------+   +-----------------------+   +-----------------------+
```

| 성숙도 단계 | 신원 및 워크로드 통제 | 데이터 및 네트워크 통제 | 공통 거버넌스 및 자동화 |
|---|---|---|---|
| 전통적 (Traditional) | 영구 정적 API 키 사용, 수작업 배포, 도구 권한 무제한 허용 | 온프레미스 경계 방화벽 의존, 평문 데이터셋 저장 | 사후 수동 로그 감사, 보안 사고 발생 시 수작업 격리 |
| 초기 (Initial) | IAM 역할(Role) 기반 정적 할당, 쿠버네티스 네임스페이스 격리 | 네트워크 서브넷 분리, 저장 데이터 AES 암호화 | SIEM 로그 중앙 집약, 수작업 보안 취약점 점검 |
| 고급 (Advanced) | SPIFFE 워크로드 신원, 태스크별 임시 토큰, 도구 호출 검증 | 서비스 메시(Istio) mTLS, RAG 벡터 청크 레벨 ACL 강제 | CI/CD 파이프라인 내 AI 취약점 자동 검사 및 EDR 연동 |
| 최적화 (Optimal) | 컨텍스트 기반 CARTA 동적 인가, AI 에이전트 행위 이상 탐지 | 마이크로세그멘테이션, 실시간 데이터 마스킹/DLP | AI SOC 기반 자율 차단 및 정책 자동 갱신(Closed-Loop) |

## Ⅳ. 일반 IT 워크로드 vs AI 워크로드 제로트러스트 비교

| 비교 항목 | 일반 IT 워크로드 제로트러스트 | AI 워크로드 특화 제로트러스트 |
|---|---|---|
| 보호 주체 | 사용자 계정, 웹 애플리케이션, RDBMS | 자율 AI 에이전트, 기초 모델 가중치, 벡터 DB 임베딩 |
| 신뢰 경계 검증 | IP, 인증서, 장치 규격 준수 여부 확인 | 자연어 프롬프트, 도구 파라미터, 모델 출력 유해성 검증 |
| 데이터 접근 모델 | 테이블, 행, 열 단위의 정형적 인가 | 시맨틱(Semantic) 유사도 기반 비정형 검색 및 청크 인가 |
| 주요 위협 벡터 | SQL 인젝션, 버퍼 오버플로우, 세션 탈취 | 프롬프트 인젝션, 모델 도난, 데이터 중독, 환각 유도 |
| 검증 메커니즘 | 고정된 규칙(Regex, 시그니처) 기반 인라인 검사 | 의미론적 판별 모델(SLM Guard), 실시간 정책 엔진(OPA) |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| CISA ZTMM의 5대 기둥은 정적 속성 검증 중심이므로 확률적·비결정론적인 LLM 출력의 위험 통제 불가 | 워크로드 기둥 내에 의미론적 인라인 가드레일(NeMo/Llama Guard)을 독립된 PEP로 구축하여 생성 텍스트의 유해성 및 기밀 노출 여부 실시간 차단 |
| 수백만 건의 벡터 임베딩 데이터 검색 시 메타데이터 ACL 검증으로 인한 과도한 쿼리 레이턴시 발생 | 벡터 검색 엔진(Milvus/Pinecone) 레벨에서 사전 필터링(Pre-filtering) 인덱싱 아키텍처를 적용하여 인가되지 않은 벡터 청크의 연산 자체를 원천 배제 |
| 멀티 클라우드 및 온프레미스 하이브리드 환경에서 AI 에이전트의 통일된 머신 신원 연동 표준 부재 | 클라우드 종속적 IAM을 배제하고 SPIFFE/SPIRE 오픈 표준 기반의 X.509 워크로드 신원 발급 및 OIDC 페더레이션 체계 단일화 |
| 모든 도구 호출과 API 요청에 대해 다계층 암호화(mTLS) 및 OPA 검증 수행 시 추론 응답 지연 급증 | 서비스 메시 데이터 플레인 가속을 위해 eBPF 기반 초고속 네트워킹(Cilium)을 도입하고 세션 캐싱 적용 |
