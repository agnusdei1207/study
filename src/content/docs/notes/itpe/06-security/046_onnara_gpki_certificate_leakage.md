## 연관 키워드

- 온나라시스템(On-Nara), GPKI(Government Public Key Infrastructure), 인포스틸러(Infostealer), 전자서명 인증서
- G-VPN, ZTNA(Zero Trust Network Access), EDR(Endpoint Detection and Response), FIDO2
- CRL(Certificate Revocation List), OCSP(Online Certificate Status Protocol), DID(Decentralized Identifier), 모바일 공무원증

## Ⅰ. 온나라시스템·GPKI 전자서명 인증서 유출 침해사고의 개요

- 핵심 요약 : 원격근무 PC의 악성코드 감염이 파일형 전자서명 인증서와 접속 자격증명을 유출시킨 전자정부 침해사고.
- 개념 : 원격근무 공무원의 PC가 **인포스틸러** (Infostealer) 악성코드에 감염되어, 정부 전자문서 결재 시스템인 온나라시스템(On-Nara)의 접속 자격증명과 **GPKI** (Government Public Key Infrastructure, 행정전자서명) 인증서 파일 및 비밀번호가 다크웹에 유출된 침해사고.
- 배경 및 필요성 : 재택과 원격근무가 늘면서 개인 단말과 외부 인터넷 환경에서 정부 행정망에 접속하는 경로가 생겼고, 그 과정에서 단말 보안 통제의 결함이 드러남.
- 주요 목적 : 파일 기반 인증서의 취약성 분석, 원격 접속 경로의 결함 보완, 모바일 공무원증과 FIDO2 기반 인증 체계로의 전환.

## Ⅱ. 온나라시스템·GPKI 전자서명 인증서 유출 침해사고의 특징 및 영향

- 핵심 요약 : 인증서 파일과 저장된 비밀번호가 함께 단말에 남아 있었던 점, 단말 무결성을 확인하지 않은 원격 접속이 피해를 키움.

1. 파일형 인증서 보관 : 공개키 인증서와 개인키 파일이 로컬 디스크 폴더에 평문 파일로 존재 → 복사만으로 탈취 가능.
2. 단일 비밀번호 의존 : 개인키를 여는 비밀번호가 브라우저나 메모리에 남아 있어 인포스틸러가 함께 수집.
3. 단말 무결성 검증 미흡 : 원격 접속 시 백신과 EDR(Endpoint Detection and Response) 실행 여부를 확인하지 않고 인증서만으로 통과 → 감염 단말이 행정망에 진입.
4. 사후 긴급 대응 : 유출 확인 즉시 해당 인증서를 CRL(Certificate Revocation List)과 OCSP(Online Certificate Status Protocol)로 효력 정지하고 접속 차단.

```text
[ 침해 흐름 ]

원격근무 PC 감염 (피싱, 비인가 SW)
        ↓
인증서 파일과 자격증명 탈취
        ↓
다크웹 유출 후 공격자에게 전달
        ↓
G-VPN 통과 시도 → 온나라 접근
```

## Ⅲ. 온나라시스템·GPKI 전자서명 인증서 유출 침해사고의 구성 요소 및 흐름

- 핵심 요약 : 피해는 단말 감염에서 시작해 인증서 재사용으로 이어졌으며, 인증서 효력 정지가 가장 빠른 차단 수단이었음.

```text
[ 대응 흐름 ]

유출 징후 탐지
        ↓
해당 인증서 폐지 (CRL, OCSP 반영)
        ↓
자격증명 변경과 접속 차단
        ↓
감염 단말 격리와 전수 점검
```

## Ⅳ. 온나라시스템·GPKI 인증서 저장 방식의 비교 분석

- 핵심 요약 : 인증서 개인키를 어디에 두느냐에 따라 복제 가능성과 원격 탈취 위험이 크게 달라짐.

| 비교 항목 | 파일형 GPKI 인증서 | 하드웨어 보안 토큰 인증서 | 모바일 공무원증 (DID(Decentralized Identifier) 기반) |
| --- | --- | --- | --- |
| 개인키 보관 위치 | 단말 로컬 디스크 파일 | USB(Universal Serial Bus) 형태의 하드웨어 토큰 | 스마트폰 보안 칩 (SE, Secure Element / TEE, Trusted Execution Environment) |
| 키 복제 가능성 | 파일 복사로 쉽게 복제 | 칩 내부에 격리되어 복제 어려움 | 단말 고유 바인딩으로 복제 불가 |
| 원격 탈취 위험 | 악성코드에 취약 | 물리적 도난이 없는 한 낮음 | 원격 추출 차단, 생체인증 연동 |
| 사용 편의성 | 저장 후 자동 사용 | 토큰을 항상 휴대해야 함 | 스마트폰으로 간편 승인 |

- 파일형 소프트웨어 인증서의 저장 방식은 이번 사고로 한계가 드러났고, 하드웨어 보안 칩에 개인키를 봉인하는 방식으로 전환이 요구됨.

## Ⅴ. 온나라시스템·GPKI 인증서 유출 침해사고의 한계와 방안

- 핵심 요약 : 편의 중심의 인증서 파일 관행, 네트워크 전면 개방, 탐지 지연이 주요 한계이며 저장 방식 전환과 제로트러스트 접근 통제로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 인증서 파일 복사 관행 | 토큰 휴대의 불편으로 인증서 파일을 PC나 USB에 보관 | 로컬 디스크의 인증서 파일 저장을 운영체제 수준에서 금지하고 모바일 공무원증을 표준 수단으로 지정 | 파일형 인증서 잔존 건수 |
| G-VPN의 광범위한 접근 | 인증 통과 시 내부 서브넷 전체에 접근 가능 → 단일 단말 감염이 행정망 전체로 확산 우려 | ZTNA(Zero Trust Network Access)로 단말 상태를 검증하고 온나라 애플리케이션 포트만 개별 허용 | 단말 검증 실패 차단 건수 |
| 탐지 지연 | 유출 후 다크웹에서 발견되기까지 수개월 소요 | EDR 에이전트 강제 배포로 인증서 파일 접근과 비정상 외부 전송 즉시 차단 | 탐지부터 차단까지 소요 시간 |

## Ⅵ. 온나라시스템·GPKI 인증서 유출 침해사고에 대한 기술사적 제언

- 핵심 요약 : 파일형 인증서 퇴출, 관리형 단말만 허용하는 원격근무 기준, 유출 정보의 자동 폐기 체계를 함께 갖추어야 함.

1. 중앙부처와 지자체의 행정 시스템에서 파일형 GPKI 인증서 로그인을 단계적으로 퇴출하고, DID 기반 모바일 공무원증으로 인증 수단을 단일화하는 로드맵을 수립하는 것이 필요함.
2. 비인가 개인 PC의 원격 접속을 불허하고, 공공 전용 VDI(Virtual Desktop Infrastructure, 가상 데스크톱) 또는 MDM(Mobile Device Management)과 EDR이 탑재된 관리형 단말만 허용하는 기준을 세우는 것이 바람직함.
3. 정부 도메인 계정과 인증서가 다크웹 유출 로그에 등장하면 CTI(Cyber Threat Intelligence) 정보를 받아 해당 인증서를 OCSP로 자동 폐기하는 파이프라인을 구축하는 것이 필요함.

## Ⅶ. 결론

- 핵심 요약 : 이번 사고는 파일 형태로 단말에 남는 인증서가 더는 안전한 신원 수단이 아님을 보여준 사례.
- 시사점 : 개인키의 하드웨어 봉인과 단말 무결성 검증이 함께 적용될 때 행정망 인증의 신뢰가 회복됨.
