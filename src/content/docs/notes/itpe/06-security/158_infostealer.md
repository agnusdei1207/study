## 지식 로드맵 내 현재 위치

- 정보보안 → 악성코드 분석 및 대응 → 정보 탈취 악성코드 → 인포스틸러(Infostealer)

```text
[초기 침투 (피싱/악성광고)] ──> [인포스틸러 실행] ──> [브라우저 DPAPI/세션 쿠키 탈취]
                                                         │
                                                         ▼
                                 [C2 서버 전송 (Logs)] ──> [다크웹 마켓 유통 / 초기 침투 브로커(IAB)]
                                                         │
                                                         ▼
                                          [엔터프라이즈 내부 침투 (Pass-the-Cookie)]
```

## 30초 인출

- **본질:** 감염된 단말의 웹 브라우저 로컬 저장소, 메모리, 메신저 및 암호화폐 지갑 등에서 계정 자격증명과 활성 세션 쿠키를 수집하여 C2로 유출하는 정보 탈취형 악성코드.
- **메커니즘:** 악성 광고(Malvertising)/피싱 다운로드 → DPAPI 마스터키 복호화 및 SQLite 브라우저 DB 덤프 → 세션 쿠키/패스워드 압축 → Telegram API/HTTP C2 전송 → 다크웹 로그 유통.
- **통찰:** 단순 엔드포인트 악성코드 치료만으로는 이미 유출된 세션 쿠키를 통한 MFA 우회 접속을 방지할 수 없으므로, 감염 즉시 중앙 IdP 세션 전면 강제 만료와 클라이언트 토큰 바인딩(DPoP) 적용 필수.

## 2~4교시 예상문제 (25점)

> 최근 급증하는 인포스틸러(Infostealer)의 감염 경로와 자격증명 탈취 메커니즘을 설명하고, Pass-the-Cookie 공격에 의한 MFA 우회 위협에 대응하기 위한 엔드포인트 및 클라우드 신원 보안 대책을 제시하시오. (25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 사용자 단말에 잠입하여 웹 브라우저 저장 패스워드, 활성화된 세션 쿠키, 가상자산 지갑, VPN/RDP 계정 정보를 자동 수집·유출하는 트로이목마형 악성코드 |
| 목적 | 탈취된 자격증명 및 세션 로그를 다크웹에 판매하거나, 기업 인트라넷 침투를 위한 초기 침투 브로커(IAB: Initial Access Broker)의 교두보로 악용 |

- 전통적인 키로거와 달리 브라우저 마스터 암호키를 복호화하여 저장된 모든 세션 쿠키를 즉시 덤프하므로, MFA가 적용된 클라우드 계정까지 우회 침해 가능.

## Ⅱ. 인포스틸러의 핵심 특징 및 수집 대상

### 1. 인포스틸러의 핵심 특징

| 특징 | 설명 | 기술적 영향 |
|---|---|---|
| Pass-the-Cookie 공격 | 인증 완료된 세션 쿠키 직접 탈취 | 패스워드 및 2차 MFA 인증 과정 없이 대상 클라우드 콘솔에 즉시 로그인 |
| MaaS (Malware-as-a-Service) | 월 구독형 다크웹 서비스 유통 | 비전문가 공격자도 손쉽게 빌더 생성, C2 패널 및 유출 로그 수집 가능 |
| 파일리스 및 경량화 | 수 초 내 수집 완료 후 자폭 | 감염 즉시 압축 파일(`.zip`) 형태로 C2 전송 후 흔적 삭제로 포렌식 방해 |
| 광범위한 탈취 범위 | 브라우저 외 시스템 전반 탈취 | Chromium/Gecko 브라우저, Telegram, Discord, Steam, FileZilla, PuTTY 세션 망라 |

### 2. 주요 수집 대상 데이터 분류

```text
[인포스틸러 수집 대상 데이터]
  ├── 웹 브라우저       ──> 자동완성 패스워드, 세션 쿠키(Cookie), 자동완성 카드정보, 검색기록
  ├── 원격 접속/개발   ──> VPN 설정, RDP 자격증명, SSH 개인키(id_rsa), Git 토큰, AWS CLI 키
  ├── 가상자산 지갑     ──> Metamask, Exodus, Binance 확장프로그램 및 Wallet.dat 로컬 파일
  └── 메신저/협업도구   ──> Slack 토큰, Discord Token, Telegram tdata 세션 폴더
```

## Ⅲ. 감염-탈취-유통 라이프사이클 및 기술 아키텍처

### 1. 인포스틸러 공격 라이프사이클 아키텍처

```text
+-----------------------------------------------------------------------------------------+
|                              인포스틸러 공격 생명주기 및 아키텍처                         |
+-----------------------------------------------------------------------------------------+
  [1. 초기 침투]              [2. 정보 수집 및 복호화]       [3. C2 전송 및 유통]       [4. 2차 침해]
  - 악성 광고 (Malvertising)  - OS Crypt / DPAPI 복호화      - Telegram Bot API 전송    - Pass-the-Cookie
  - 피싱 메일 첨부파일       - Local State 키 탈취          - C2 패널 압축파일 유출    - SSO 포털 로그인
  - 상용 크랙 소프트웨어     - SQLite DB (Cookies/Login)    - 다크웹 마켓 거래         - 랜섬웨어 전파
         │                           │                              │                         │
         ▼                           ▼                              ▼                         ▼
  [단말기 실행] ───────────> [자격증명 덤프] ─────────────> [로그 패키징] ──────────> [내부망 침투]
+-----------------------------------------------------------------------------------------+
```

### 2. 브라우저 DPAPI 복호화 메커니즘 상세

| 단계 | 수행 프로세스 | 기술 메커니즘 |
|---|---|---|
| 1. 암호화 키 획득 | `User Data\Local State` 파일 파싱 | Base64 인코딩된 `os_crypt.encrypted_key` 문자열 추출 |
| 2. 마스터 키 복호화 | Windows DPAPI 라이브러리 호출 | `CryptUnprotectData()` API를 호출하여 사용자 로그인 컨텍스트로 복호화 |
| 3. 데이터베이스 접근 | Chromium 계열 SQLite DB 복제 | `Network\Cookies` 및 `Login Data` 파일 잠금 해제를 위해 임시 디렉터리로 복사 |
| 4. 페이로드 복호화 | AES-256-GCM 알고리즘 적용 | 암호문 헤더(`v10`) 검증 후 Nonce(12B)와 Tag를 분리하여 평문 쿠키 및 비밀번호 획득 |

## Ⅳ. 주요 인포스틸러 패밀리 및 탈취 기법 비교

### 1. 주요 악성코드 패밀리 계보

```text
[대표 인포스틸러 패밀리]
  ├── RedLine Stealer ──> C# 기반, 가장 광범위한 MaaS 시장 점유율, 상세 하드웨어 프로파일링
  ├── Vidar / Racoon  ──> C/C++ 기반, DLL 인젝션 및 Mastodon/Telegram을 C2 데드드롭으로 악용
  ├── Lumma Stealer   ──> 고도화된 안티 VM, 가상환경 탐지, 브라우저 확장프로그램 지갑 집중 탈취
  └── Stealc / Risepro ──> 신흥 경량 스틸러, 정적 시그니처 회피를 위한 동적 난독화 및 고속 수집
```

### 2. 주요 인포스틸러 패밀리 비교

| 구분 | RedLine Stealer | Racoon Stealer v2 | Lumma Stealer | Vidar Stealer |
|---|---|---|---|---|
| 개발 언어 | .NET (C#) | C / C++ | C / 어셈블리 | C / C++ |
| 배포 방식 | MaaS (다크웹 포럼 월 임대) | MaaS (구독형 서비스) | MaaS (계층형 라이선스) | 비공개 포럼 판매 |
| C2 통신 방식 | TCP Raw 소켓, SOAP/WCF | Telegram 채널 데드드롭, HTTP POST | 방탄 호스팅 HTTPS, 도메인 생성 알고리즘(DGA) | Steam 커뮤니티 프로필 악용 C2 리졸브 |
| 주요 수집 타깃 | 전 브라우저, 디스코드, FTP, 시스템 정보 | 크립토 월렛, 브라우저 쿠키/비밀번호 | 브라우저 확장 가상자산 지갑 70종 이상 | 2단계 인증 백업 코드, 텍스트 문서 |
| 탐지 회피 기술 | 스트링 인코딩, 난독화기(ConfuserEx) | API Hashing, 동적 라이브러리 로딩 | Control Flow Flattening, 안티 디버깅 | 실행 완료 후 자체 삭제(Self-deletion) |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 사용자가 정상 로그인한 세션 쿠키를 메모리/디스크에서 탈취하므로 단말에 MFA가 정상 적용되어 있어도 세션 하이재킹 무방비 노출 | 브라우저와 인증 서버 간 DPoP(Demonstrating Proof-of-Possession) 및 토큰 바인딩을 적용하고 기기 바운드 세션 자격증명(Device Bound Session Credentials) 강제 |
| Windows DPAPI 구조상 동일 사용자 세션 내에서 실행된 모든 비인가 프로세스가 `CryptUnprotectData`를 제한 없이 호출 가능 | 엔드포인트 AppLocker 및 WDAC(Windows Defender Application Control)를 적용하여 신뢰된 서명 바이너리 외 실행을 전면 차단하고 브라우저 자격증명 저장 GPO 금지 |
| 수 초 내 정보 수집 및 C2 전송 완료 후 자체 삭제되어 EDR의 사후 프로세스 차단 및 백신 시그니처 탐지 골든타임 상실 | 브라우저 데이터 폴더(`User Data`) 및 DPAPI 레지스트리 접근 프로세스를 실시간 감시하는 행위 기반 EDR 룰셋을 활성화하고 비정상 대역폭 유출 시 즉시 망 격리 |

## Ⅵ. 제언

### 1. 인포스틸러 다계층 방어 및 대응 아키텍처

```text
[엔드포인트 통제] ──> [네트워크 차단] ──> [클라우드 IdP 대응] ──> [CTI 위협 인텔리전스]
- 브라우저 비밀번호 저장 금지 - 신규 도메인 통신 차단   - 감염 계정 즉시 세션 해지  - 다크웹 유출 로그 모니터링
- AppLocker 실행 차단       - C2 통신 패킷 탐지     - 비밀번호 강제 리셋        - 초기 침투 브로커 차단
- EDR 상시 모니터링         - Telegram API 트래픽 차단 - 지속적 적응형 인가(CAEP)  - 유출 크리덴셜 블랙리스트
```

### 2. 인포스틸러 대응 기술 단계별 효과성 비교

| 대응 계층 | 적용 핵심 기술 | 유효성 | 구축 난이도 | 주요 제약 및 고려사항 |
|---|---|---|---|---|
| 사전 예방 | 중앙 브라우저 정책(GPO/MDM) | 상 | 낮음 | 사내 PC 대상 한정, 개인 단말(BYOD) 통제 불가 |
| 엔드포인트 방어 | EDR 비인가 메모리 접근 차단 | 최상 | 중간 | 고도화된 난독화 및 제로데이 스틸러 탐지 지연 |
| 인증/신원 보호 | DPoP 및 DBSC (기기 바인딩 세션) | 최고 | 높음 | 웹 표준 지원 브라우저 및 IdP 시스템 업그레이드 필요 |
| 사후 수습 | CTI 기반 다크웹 유출 모니터링 | 상 | 중간 | 유출 발생 후 인지까지 수 시간에서 수 일의 지연 존재 |

- 인포스틸러는 자격증명 도난을 넘어 기업 랜섬웨어 공격의 초기 진입로로 직결되므로, 단말 단위의 바이러스 백신 검사를 탈피하여 기기 바인딩 토큰과 CTI 기반의 계정 즉각 회수 체계 구축 필수.
