## 지식 로드맵 내 현재 위치

정보보안 → 암호학 → 키 분배 및 하이브리드 암호(Digital Envelope)

## 30초 인출

- **본질:** 대칭키 암호의 고속 처리 능력과 공개키 암호의 편리한 키 배송 방식을 결합하여, 대용량 본문은 일회용 세션키로 암호화하고 세션키는 수신자의 공개키로 암호화하여 전달하는 하이브리드 암호 기술
- **메커니즘:** 일회용 세션키 생성 → 본문 대칭 암호화(AES) → 세션키를 수신자 공개키로 암호화(봉투 생성) → 수신자 개인키로 세션키 복호화(봉투 개봉) → 본문 복호화
- 통찰: 기밀성과 키 분배 효율성을 완벽히 만족하지만 전자봉투 자체만으로는 송신자 신원 인증 및 부인방지가 불가능하므로 송신자 개인키 서명을 결합한 서명된 전자봉투(Signed & Enveloped Data) 구축 필수

<details><summary>핵심 용어</summary>

- **전자봉투 (Digital Envelope):** 공개키 암호화 기술을 사용하여 대칭 암호화 키를 봉인(Encapsulation)한 하이브리드 암호 구조.
- **세션키 (Session Key):** 대용량 메시지를 고속으로 암호화하기 위해 일회성으로 생성되는 대칭 암호키.
- **CMS (Cryptographic Message Syntax, RFC 5652):** 전자서명, 전자봉투, 다중 수신자 암호 메시지 포맷을 정의한 IETF 표준 규격.
- **KEM (Key Encapsulation Mechanism):** 비대칭 알고리즘을 이용해 대칭키를 안전하게 캡슐화하고 수신자가 역캡슐화하도록 설계된 현대적 키 전달 방식.
- **서명된 전자봉투 (Signed & Enveloped):** 송신자의 전자서명으로 무결성/부인방지를 보장하고, 전자봉투로 기밀성을 동시에 확보하는 결합 구조.

</details>

## 2~4교시 예상문제 (25점)

> 하이브리드 암호화 기법인 전자봉투(Digital Envelope)의 개념과 생성 및 개봉 메커니즘을 설명하고, 전자서명(Digital Signature)과의 기능 비교 및 송신자 인증과 양자 컴퓨팅 위협에 대비한 발전 방안을 제시하시오. (기출·제133회 1교시 4번)

---

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 대용량 평문 데이터는 고속 대칭키(세션키)로 암호화하고, 해당 세션키만을 수신자의 공개키로 암호화하여 암호문과 함께 전송하는 하이브리드 암호화 기법 |
| 목적 | 대칭키 암호화의 '키 배송 난제'와 비대칭키 암호화의 '과도한 연산 지연'을 상호 보완하여 대용량 기밀 통신의 안전성과 성능을 동시 달성 |

## Ⅱ. 전자봉투의 주요 특징

| 특징 | 세부 내용 | 구현 요소 |
|---|---|---|
| 하이브리드 구조 | 대칭키(AES)의 고속 연산성과 공개키(RSA/ECC)의 키 분배 용이성을 결합 | 대칭키 + 비대칭키 결합 |
| 일회용 세션키 사용 | 통신 세션마다 무작위 암호학적 난수로 세션키를 생성하여 키 누출 시 피해 국소화 | CSPRNG, 단기 대칭키 |
| 다중 수신자 지원 | 동일한 본문 암호문에 대해 여러 수신자의 공개키로 세션키를 각각 암호화하여 1:N 전송 가능 | CMS EnvelopedData 구조 |
| 기밀성 전용 메커니즘 | 전자봉투 단독으로는 오직 '기밀성'만을 제공하며, 송신자 인증이나 부인방지는 미제공 | 별도 전자서명 결합 필요 |

## Ⅲ. 전자봉투 생성 및 개봉 프로세스

```text
[ 1. 전자봉투 생성 (송신자: Alice) ]
대용량 평문 메시지 (M) ──────▶ [ AES-256 대칭 암호화 ] ────────▶ [ 암호문 (C) ]
                                        ▲                              │
일회용 비밀 세션키 (K) 생성 ────────────┘                              │
       │                                                               │
       ▼ (수신자 Bob의 공개키로 암호화)                                 │
[ 수신자 공개키 암호화 ] ──▶ [ 전자봉투 (Encrypted Key) ] ──────────────┼─▶ [ 전송 패킷 ]
                                                                       │
                                                                       ▼
[ 2. 전자봉투 개봉 (수신자: Bob) ]
수신 패킷 수신 ──▶ [ 전자봉투 ] ──▶ [ Bob의 개인키로 복호화 ] ──▶ 일회용 세션키 (K) 획득!
                         │                                              │
                         ▼                                              ▼
                   [ 암호문 (C) ] ──────────────────────────▶ [ AES 대칭 복호화 ] ──▶ 평문 (M) 복원
```

| 단계 | 수행 주체 | 상세 활동 내용 | 사용 암호키 |
|---|---|---|---|
| 1. 세션키 생성 | 송신자 | 통신에 사용할 일회용 대칭키(AES-256 등) 무작위 생성 | CSPRNG 난수키 |
| 2. 본문 암호화 | 송신자 | 대용량 평문 메시지를 세션키로 고속 대칭 암호화 | 일회용 세션키 |
| 3. 봉투 생성 | 송신자 | 수신자의 공개키를 조회하여 세션키를 비대칭 암호화 | **수신자의 공개키** |
| 4. 패킷 전송 | 송신자 $\rightarrow$ 수신자 | 암호문 본문과 전자봉투(암호화된 세션키)를 결합하여 발송 | 네트워크 전송 |
| 5. 봉투 개봉 | 수신자 | 자신의 개인키로 전자봉투를 복호화하여 세션키 추출 | **수신자의 개인키** |
| 6. 본문 복원 | 수신자 | 추출된 세션키를 대칭 복호화 알고리즘에 입력하여 평문 획득 | 일회용 세션키 |

## Ⅳ. 전자봉투 vs 전자서명 vs 서명된 전자봉투 비교

| 비교 항목 | 전자봉투 (Digital Envelope) | 전자서명 (Digital Signature) | 서명된 전자봉투 (Signed & Enveloped) |
|---|---|---|---|
| 핵심 보안 목적 | **데이터 기밀성 (Confidentiality)** | **신원 인증, 무결성, 부인방지** | **기밀성 + 무결성 + 인증 + 부인방지** |
| 사용되는 키 | **수신자의 공개키/개인키** | **송신자의 개인키/공개키** | **송신자 개인키 + 수신자 공개키** |
| 처리 대상 | 데이터 암호화용 대칭 세션키 | 메시지 다이제스트(해시값) | 해시값(서명) 및 본문+세션키(봉투) |
| 표준 프로토콜 | PKCS#7 EnvelopedData | PKCS#7 SignedData | S/MIME, PGP, OpenPGP |
| 취약점 | 송신자 사칭 및 변조 취약 | 본문 평문 노출 (기밀성 결여) | 연산 오버헤드 증가 (서명+암호화) |

## Ⅴ. 전자봉투의 한계와 방안

| 한계 | 방안 |
|---|---|
| 수신자의 공개키를 신뢰할 수 없는 경로에서 획득 시 중간자 공격(MitM)에 의해 공격자의 공개키로 봉인되어 도청 위험 | 공인인증기관(CA)이 발행하고 상호 인증된 X.509 디지털 인증서 체인을 엄격히 검증하여 수신자 공개키의 진위성 보장 |
| 전자봉투 단독 적용 시 발신자 인증이 불가능하여 제3자가 악의적인 가짜 메시지를 전자봉투로 포장하여 발송 가능 | 송신자가 본문 해시를 자신의 개인키로 먼저 서명한 후 본문과 서명값을 함께 전자봉투로 감싸는 Sign-then-Encrypt(S/MIME) 강제화 |
| 미래 양자컴퓨터의 쇼어(Shor) 알고리즘으로 인해 전자봉투를 감싸는 비대칭키(RSA/ECC)가 다항 시간 내 해독되어 세션키 노출 | 격자 기반 양자내성 암호인 ML-KEM(FIPS 203) 기반 키 캡슐화 메커니즘을 도입하여 포스트 퀀텀 하이브리드 전자봉투 구축 |

## Ⅵ. 제언

```text
[ 단순 전자봉투 (기밀성 단독) ]      [ 서명 결합형 PQC 양자내성 전자봉투 ]
수신자 공개키 단독 암호화 ─┐           ┌── 송신자 서명 (ML-DSA) 결합: 부인방지
발신자 신원 위장 노출 ───┼─→ [ 침해 위험 ] ─┼── 양자내성 KEM (ML-KEM) 봉투 캡슐화
양자 쇼어 공격 취약 ─────┘           └── 대용량 본문 AES-256-GCM 고속 처리
```

| 평가 영역 | 전통적 전자봉투 | 서명된 전자봉투 (S/MIME) | 차세대 PQC 전자봉투 |
|---|---|---|---|
| 제공 보안 서비스 | 기밀성 단독 | 기밀성, 무결성, 부인방지 | 4대 보안 서비스 + 양자 내성 |
| 적용 알고리즘 | RSA + AES | RSA/ECDSA + AES | ML-KEM + ML-DSA + AES-GCM |
| 주요 활용처 | 단순 암호화 파일 전송 | 보안 이메일, 전자문서 유통 | 국가 안보 통신, 금융 거래 원장 |

전자봉투는 비대칭키와 대칭키의 장점을 융합하여 현대 인터넷 데이터 암호화의 기틀을 마련한 핵심 아키텍처이며, 향후 안전한 디지털 유통을 위해 전자서명과의 결합 및 양자내성 KEM으로의 진화가 필수적 과제.
