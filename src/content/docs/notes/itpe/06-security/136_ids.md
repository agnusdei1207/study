## 연관 키워드

- IDS(Intrusion Detection System), NIDS, HIDS, 시그니처 기반 탐지, 이상 징후 기반 탐지
- 미러링(SPAN), 오탐(False Positive), 경보 피로, IPS, SIEM, SOAR, NDR, MITRE ATT&CK

## Ⅰ. IDS의 개요

- 핵심 요약 : 네트워크와 호스트의 트래픽·로그를 실시간으로 감시해 침입 징후를 경보로 알리는 탐지 체계.
- 개념 : 네트워크 세그먼트나 호스트의 트래픽, 시스템 로그, 프로세스 행위를 감시하여 침입 시도와 정책 위반을 탐지하고 관리자에게 경보(Alert)를 전달하는 **침입 탐지 시스템** (IDS, Intrusion Detection System).
- 배경 및 필요성 : 단순 패킷 필터링 방화벽은 허용된 포트(80, 443)로 들어오는 SQL(Structured Query Language) 인젝션 같은 애플리케이션 계층 공격을 걸러내지 못하므로, 트래픽 내용과 행위를 분석하는 탐지 체계가 보완 수단으로 필요함.
- 주요 목적 : 침해 징후를 조기에 가시화하고, 사고 발생 시 사후 포렌식에 쓸 감사 증적을 확보.

## Ⅱ. IDS의 특징 및 장점

- 핵심 요약 : 트래픽 사본 분석과 이중 탐지 방식이 서비스 지연 없는 관찰과 신종 위협 식별로 이어지는 구조.

1. 사본 기반 관찰 : 스위치 미러링이나 탭으로 트래픽 사본만 수집 → 서비스 경로에 지연이 생기지 않음.
2. **시그니처 기반 탐지** (Signature-based Detection) : 알려진 공격 패턴과 대조 → 오탐이 적고 경보의 판단 근거가 명확함.
3. **이상 징후 기반 탐지** (Anomaly-based Detection) : 정상 행위의 기준선(Baseline)을 학습하고 벗어난 행위를 탐지 → 변종·신종 공격에 대응하나 **오탐** (False Positive)이 늘어나는 한계가 있음.
4. 호스트 가시성 : 시스템 파일 무결성, 로그인 실패, 권한 상승 시도를 서버 내부에서 감시 → 내부 위협과 사후 증적을 함께 확보.

## Ⅲ. IDS의 구조 (흐름)

- 핵심 요약 : 설치 위치에 따라 네트워크 기반과 호스트 기반으로 나뉘고, 모든 경보가 중앙 관제로 모이는 구조.
- **NIDS** (Network-based IDS) : 스위치의 미러링(SPAN, Switched Port Analyzer) 포트나 탭(TAP, Test Access Point)에 연결되어 서브넷 전체 트래픽을 간섭 없이 감시.
- **HIDS** (Host-based IDS) : 개별 서버에 에이전트로 설치되어 파일 무결성, 커널 시스템 콜, 인증 로그를 내부에서 감시.

```text
[ IDS 설치 위치별 경보 흐름 ]

네트워크 구간
  코어 스위치
    ↓ (SPAN·TAP 미러링)
  NIDS 센서 (패킷 분석)
    ↓
  중앙 관제 (SIEM 연계)

호스트 구간
  Web·DB·WAS 서버
    ↓ (에이전트 로그 전송)
  HIDS 에이전트 (무결성 감시)
    ↓
  중앙 관제 (SIEM 연계)
```

```text
[ 탐지 처리 흐름 ]

패킷·로그 수집
    ↓
시그니처 매칭 또는 기준선 비교
    ↓
의심 행위 판정
    ↓
경보 생성 (Alert)
    ↓
관제 요원 분석·대응
```

## Ⅳ. IDS의 비교 분석

- 핵심 요약 : 탐지 전용 방식, 능동 차단 방식, 로그 상관분석 방식이 역할 축에서 구분되어 함께 운영될 때 완성되는 구조.

IDS와 비교되는 **침입 방지 시스템** (IPS, Intrusion Prevention System)과 **보안 정보 및 이벤트 관리** (SIEM, Security Information and Event Management)을 함께 놓고 비교한다.

| 비교 축 | IDS | IPS | SIEM |
| --- | --- | --- | --- |
| 네트워크 위치 | 인라인 밖 (미러링 연결) | 인라인 경로 (패킷 경유) | 중앙 로그 수집 서버 |
| 트래픽 영향 | 지연 없음 | 검사에 따른 미세 지연 | 실시간 패킷과 무관 |
| 대응 방식 | 경보 발령 | 드롭·차단 | 다중 장비 상관분석·리포팅 |
| 장애 시 영향 | 서비스 정상 유지 | 설정에 따라 단절 위험 | 로그 수집만 지연 |
| 핵심 역할 | 침해 징후의 조기 가시화, 증적 | 익스플로잇 실시간 차단 | 전사 이벤트 통합, 컴플라이언스 |

- 선택 기준 : 차단이 필요한 구간에는 인라인 IPS를, 전수 관찰과 사후 분석에는 IDS를 두고, 결과는 SIEM에서 상관분석하는 조합으로 운영하는 것이 현실적임.

## Ⅴ. IDS의 한계와 방안

- 핵심 요약 : 비동기 분석, 암호화 트래픽 확산, 오탐 누적이라는 세 한계를 차단 계층 분리, 복호화, 자동 분류로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 실시간 차단 불가 | 미러링 기반 비동기 분석으로 악성 패킷이 서버에 먼저 도달 | 확실한 시그니처는 인라인 IPS에서 차단하고, 미러링 IDS는 심층 분석과 위협 헌팅으로 역할 분리 | 탐지 후 조치 소요 시간 |
| 암호화 트래픽 가시성 상실 | TLS(Transport Layer Security) 확산으로 HTTP(Hypertext Transfer Protocol) 헤더와 공격 문자열 검사 불가 | SSL(Secure Sockets Layer) 복호화 장비를 앞단에 두어 미러링 트래픽을 복호화하거나 메타데이터 기반 암호화 트래픽 분석 도입 | 복호화 적용 비율 |
| 오탐 누적과 **경보 피로** (Alert Fatigue) | 정상 대용량 백업과 신규 서비스 트래픽을 공격으로 오인하여 중요 위협 간과 | **SOAR** (Security Orchestration, Automation and Response)로 1차 경보를 자동 분류하고 위협 점수화 적용 | 오탐률, 경보 평균 처리 시간 |

## Ⅵ. IDS의 기술사적 제언

- 핵심 요약 : 탐지 중심의 IDS를 행위 분석형 탐지와 공격 기법 기반 룰셋으로 고도화하는 방향.

1. 보안 관제 조직은 룰셋을 고정된 시그니처 목록으로 두지 말고 **MITRE ATT&CK** 프레임워크의 전술과 기법에 맞춰 매핑하여, 공격 단계별 징후를 입체적으로 관찰하는 관리 체계를 세우는 것이 바람직하다.
2. 네트워크 운영 부서는 메타데이터를 분석하는 **NDR** (Network Detection and Response) 체계로 점차 전환하여, 시그니처에 의존하지 않는 행위 탐지 역량을 확보할 필요가 있다.
3. 클라우드 전환이 가속되는 기업은 설계 단계부터 VPC(Virtual Private Cloud) 트래픽 미러링을 포함시켜, 가상 머신과 컨테이너 트래픽도 중앙 탐지 체계로 수집되도록 해야 한다.

## Ⅶ. 결론

- 핵심 요약 : IDS는 트래픽을 차단하지 않고 관찰하여 위협의 첫 신호를 알려주는 감시 체계.
- 시사점 : 탐지 결과가 차단과 분석으로 이어질 때 가치가 완성되므로, IDS는 IPS와 SIEM·SOAR 등 대응 체계와 한 세트로 설계되어야 함.
