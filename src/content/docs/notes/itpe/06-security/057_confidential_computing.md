## 연관 키워드

- 기밀 컴퓨팅, Confidential Computing, 사용 중 데이터, TEE, 신뢰 실행 환경
- 원격 증명, 메모리 암호화, 엔클레이브, 기밀 VM, SGX, TDX, SEV-SNP
- 동형암호, 부채널 공격, 신뢰 앵커, 제로트러스트, 신뢰된 오라클

## Ⅰ. 기밀 컴퓨팅의 개요

- 핵심 요약 : 메모리에서 연산 중인 데이터를 하드웨어 기반 신뢰 실행 환경에 격리해 운영자도 평문을 볼 수 없게 하는 컴퓨팅 기술.
- 개념 : 데이터가 CPU(Central Processing Unit)에서 연산되는 **사용 중 데이터** (In-Use Data) 상태를 하드웨어 기반 **신뢰 실행 환경** (TEE, Trusted Execution Environment)에 격리·암호화하여, 클라우드 운영자와 호스트 OS(Operating System) 관리자도 평문에 접근하지 못하게 하는 기술 (**기밀 컴퓨팅**, Confidential Computing).
- 배경 및 필요성 : 저장 데이터와 전송 데이터는 TLS(Transport Layer Security)와 AES(Advanced Encryption Standard)로 보호되지만, 연산을 위해 평문으로 메모리에 올라가는 구간은 관리자 권한 탈취나 콜드부트 공격에 노출되는 보안 공백으로 남음 → 이 공백을 하드웨어로 메우기 위해 등장.
- 주요 목적 : 연산 중 데이터의 하드웨어 수준 기밀성과 무결성을 보장하고, 제3자 퍼블릭 클라우드를 **제로트러스트** (Zero Trust) 환경으로 운용.

## Ⅱ. 기밀 컴퓨팅의 특징 및 장점

- 핵심 요약 : 하드웨어 격리, 실시간 메모리 암호화, 원격 증명이 결합되어 클라우드 관리자 권한을 배제하면서도 기존 소프트웨어 자산을 활용하는 구조.

1. 하드웨어 기반 격리 (TEE) : CPU 칩 안에 보호된 실행 구역을 두어 호스트 OS와 하이퍼바이저의 접근을 차단 → 클라우드 관리자 권한이 탈취되어도 평문 노출 감소.
2. 실시간 메모리 암호화 : CPU와 물리 메모리 사이의 데이터를 하드웨어 암호화 엔진이 즉시 암호화 → 메모리 덤프와 콜드부트 공격에서 평문 노출 차단.
3. **원격 증명** (Remote Attestation) : 하드웨어 서명 보고서로 자신의 코드가 정품 TEE에서 변조 없이 실행됨을 외부 사용자가 검증 → 위탁 연산에 대한 신뢰 근거 확보.
4. 기밀 가상머신 (기밀 VM) : VM 전체를 기밀 영역으로 감싸 애플리케이션 수정을 최소화 → 레거시 워크로드의 클라우드 이전 비용 절감.

## Ⅲ. 기밀 컴퓨팅의 구조 (흐름)

- 핵심 요약 : 비신뢰 영역과 신뢰 영역의 경계를 하드웨어가 긋고, 원격 증명이 그 경계 안의 실행 상태를 외부에 입증하는 이중 구조.

```text
[ 기밀 컴퓨팅의 신뢰 경계 ]

비신뢰 영역 (호스트 OS, 하이퍼바이저)
      ↓ 접근 차단
신뢰 영역 (TEE 엔클레이브·기밀 VM)
      ↓ 메모리 버스 암호화
물리 메모리 (암호문으로만 존재)
```

```text
[ 원격 증명 흐름 ]

사용자 (증명 요청)
      ↓ 검증용 난수 전달
TEE 하드웨어 (실행 상태 서명)
      ↓ 서명된 보고서
제조사 인증 체계로 서명 검증
      ↓
무결성 확인 후 비밀 데이터 전달
```

- **엔클레이브** (Enclave) : 프로세스 단위로 격리된 보호 영역이며, Intel SGX(Software Guard Extensions)가 대표적인 방식.
- **기밀 VM** : 가상머신 단위로 격리하는 방식이며 Intel TDX(Trust Domain Extensions), AMD SEV-SNP(Secure Encrypted Virtualization-Secure Nested Paging)가 대표적.
- 모바일·임베디드 영역 : ARM TrustZone과 Arm CCA(Confidential Compute Architecture)로 구현.

## Ⅳ. 기밀 컴퓨팅과 대안 기술의 비교

- 핵심 요약 : 동형암호는 암호문 상태의 연산으로 원리상 강하지만 성능 부담이 크고, 기밀 컴퓨팅은 평문 연산의 성능을 유지하면서 관리자 감시를 배제하는 실용적 절충안.

| 비교 항목 | 전통적 클라우드 가상화 | 동형암호 (FHE, Fully Homomorphic Encryption) | 기밀 컴퓨팅 |
| --- | --- | --- | --- |
| 연산 중 데이터 상태 | 평문으로 메모리에 상주 | 암호문 상태를 유지한 채 연산 | TEE 내부에서만 평문 처리 |
| 보안 근거 | 운영체제·하이퍼바이저의 논리적 권한 통제 | 격자 기반 수학적 난제 | CPU 제조사의 하드웨어 신뢰 |
| 연산 성능 | 네이티브 수준 | 일반 연산 대비 매우 느림 | 네이티브에 근접 |
| 적용 난이도 | 기존 방식 그대로 운영 | 알고리즘 재설계 필요 | 기밀 VM 사용 시 코드 수정 최소 |
| 주요 위협 | 관리자 권한 탈취, 하이퍼바이저 침해 | 연산 노이즈 관리와 비용 | 칩 내부 부채널 공격 |

## Ⅴ. 기밀 컴퓨팅의 한계와 방안

- 핵심 요약 : 부채널 취약성, 기존 코드 리팩토링 부담, 제조사 신뢰 종속을 패치 관리, 기밀 VM 전환, 신뢰 기반 다변화로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 부채널 공격 취약성 | 추측 실행(Spectre 등) 기반 캐시 접근 시간 차이로 키 누출 위험 잔존 | 마이크로코드 최신 패치 적용, 상수 시간(Constant-Time) 암호 구현 | 펌웨어 패치 적용률 |
| 프로세스 단위 격리의 전환 부담 | SGX는 코드 일부를 엔클레이브 함수로 재작성해야 해 레거시 소프트웨어 적용이 어려움 | 운영체제와 VM 전체를 감싸는 기밀 VM(TDX, SEV-SNP) 채택 | 기밀 VM 전환 워크로드 비율 |
| 제조사 신뢰 앵커 종속 | 증명의 신뢰 근거가 CPU 제조사 루트 인증서에 의존 → 제조사 키 유출 시 공급망 전체 신뢰 붕괴 우려 | 오픈소스 TEE 연구(Keystone 등) 병행, 다중 벤더 증명 검증 구조 검토 | 증명 검증 경로 수 |

## Ⅵ. 기밀 컴퓨팅에 대한 기술사적 제언

- 핵심 요약 : 공공·금융 워크로드의 클라우드 이전과 AI 및 블록체인 신뢰 구조에 기밀 컴퓨팅을 단계적으로 편입하는 방향.

1. 공공·금융 기관의 민감 워크로드를 퍼블릭 클라우드로 옮길 때는 정보보안 조직이 기밀 VM 기반 설계를 기본안으로 검토하고, 데이터 통제권을 증명 가능한 형태로 남기는 절차를 마련할 필요가 있음.
2. AI 모델 가중치와 학습·추론 데이터처럼 지적재산 가치가 큰 자산은 GPU 가속기의 기밀 컴퓨팅 지원 여부를 확인한 뒤 TEE 환경에서 처리하는 방식을 검토하는 것이 바람직함.
3. 블록체인 오라클처럼 외부 데이터를 신뢰해야 하는 구조에서는 TEE 내부에서 데이터를 검증한 뒤 공급하는 신뢰된 오라클(Trusted Oracle) 체계를 도입할 필요가 있음.

## Ⅶ. 결론

- 핵심 요약 : 기밀 컴퓨팅은 연산 중 데이터까지 보호하여 클라우드 보안의 마지막 공백을 메우는 하드웨어 기반 격리 기술.
- 시사점 : 신뢰의 근거가 소프트웨어 권한에서 칩 제조사의 하드웨어로 옮겨가므로, 실리콘 신뢰 전제와 부채널 대응을 함께 점검해야 함.
