## 지식 로드맵 내 현재 위치

클라우드 보안 → 데이터 기밀성 → 사용 중 데이터(Data-in-Use) 보호 및 TEE

## 30초 인출

- **본질:** 데이터 처리 런타임 단계에서 호스트 OS, 하이퍼바이저, 클라우드 운영자의 접근을 배제하고 하드웨어 기반 신뢰실행환경(TEE) 내에서 메모리를 실시간 암호화하여 연산하는 보안 기술
- **메커니즘:** 하드웨어 격리 영역(Enclave/CVM) 생성 → 하드웨어 기반 메모리 암호화 → 원격 증명(Remote Attestation) 검증 → 보안 키 및 데이터 주입 → 격리 연산 수행
- 통찰: 저장 및 전송 암호화의 공백인 런타임 메모리 평문 노출을 방어하기 위해 하드웨어 기반 TEE 격리와 원격 증명을 결합하되 부채널 공격 및 엔클레이브 내부 코드 취약성에 대한 계층적 심층 방어 체계 구축 필수

<details><summary>핵심 용어</summary>

- **기밀 컴퓨팅(Confidential Computing):** 하드웨어 기반의 검증 가능한 신뢰실행환경(TEE) 내에서 데이터를 처리함으로써 사용 중(In-Use) 데이터를 보호하는 기술.
- **TEE(Trusted Execution Environment):** 메인 프로세서 내부에 하드웨어적으로 보호되어 인가된 코드와 데이터만 실행되는 보안 격리 영역.
- **원격 증명(Remote Attestation):** TEE 내부의 해시 측정값과 하드웨어 서명을 원격 검증자가 확인하여 환경의 진위성과 무결성을 입증하는 절차.
- **Intel TDX / SGX:** 인텔의 하드웨어 보안 기술로, 애플리케이션 격리(SGX) 및 가상머신 전체 격리(Trust Domain Extensions, TDX)를 지원.
- **AMD SEV-SNP:** AMD EPYC 프로세서에서 VM 메모리를 암호화하고 하이퍼바이저의 상태 변조를 방어하는 기밀 가상화 기술.
- **CCC(Confidential Computing Consortium):** 리눅스 재단 산하에서 기밀 컴퓨팅 기술 표준과 생태계 확산을 주도하는 글로벌 협의체.

</details>

## 2~4교시 예상문제 (25점)

> 클라우드 환경에서 사용 중 데이터(Data-in-Use) 보호를 위한 기밀 컴퓨팅(Confidential Computing)의 개념과 TEE 기반 아키텍처를 설명하고, 원격 증명(Remote Attestation) 메커니즘 및 하드웨어 구현 기술 비교와 운영상 한계 극복 방안을 제시하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 클라우드 인프라 제공자(CSP), 호스트 OS, 하이퍼바이저의 권한을 신뢰하지 않고 CPU 하드웨어 기반 신뢰실행환경(TEE) 내에서 메모리 암호화와 격리 연산을 수행하는 보안 패러다임 |
| 목적 | 멀티테넌트 클라우드 환경에서 메모리 덤프 및 권한 상승 공격으로부터 사용 중인 민감 데이터와 AI 모델 지식재산의 원천적 보호 |

## Ⅱ. 기밀 컴퓨팅의 주요 특징

| 특징 | 세부 내용 | 구현 요소 |
|---|---|---|
| 사용 중 데이터 보호 (Data-in-Use) | 기존 저장(Rest) 및 전송(Transit) 중심 암호화 한계를 극복하여 메모리 연산 중 평문 노출 차단 | AES-128/256 하드웨어 메모리 암호화 엔진 |
| 하드웨어 신뢰 기점 (RoT) | 소프트웨어 계층(OS/VMM)을 배제하고 CPU 칩 제조사의 서명된 하드웨어 키를 신뢰의 출발점으로 설정 | CPU 내장 퓨즈 키, 보안 모듈 |
| 암호학적 원격 증명 | 원격 클라이언트가 TEE 내부 코드 및 구성의 무결성을 암호학적 서명 보고서로 사전 검증 | Quote 생성, Attestation Service |
| 제로 트러스트 클라우드 | 클라우드 인프라 운영자(루트 관리자)조차 고객사 컨테이너나 VM의 메모리를 열람 불가 | CVM(Confidential VM), 엔클레이브 |

## Ⅲ. 기밀 컴퓨팅 아키텍처 및 원격 증명 프로세스

```text
[ 물리적 하드웨어 계층 (CPU) ]
┌────────────────────────────────────────────────────────┐
│ CPU 칩셋 (Intel Xeon / AMD EPYC)                       │
│  ├── 하드웨어 메모리 암호화 엔진 (Memory Encryption)  │
│  └── 하드웨어 루트 오브 트러스트 (RoT 암호키 내장)      │
└────────────────────────┬───────────────────────────────┘
                         ▼
┌────────────────────────────────────────────────────────┐
│ 호스트 계층 (비신뢰 영역 - Untrusted Domain)          │
│  ├── 호스트 OS, 하이퍼바이저(KVM/ESXi), 클라우드 관리자 │
│  └── [격리 장벽] ── 메모리 접근 시 암호화된 블록만 노출 │
└────────────────────────┬───────────────────────────────┘
                         ▼
┌────────────────────────────────────────────────────────┐
│ 신뢰실행환경 (TEE: Trusted Domain / Secure Enclave)    │
│  ├── 기밀 워크로드 (애플리케이션, AI 추론 엔진)        │
│  └── 메모리 내 평문 연산 (외부에서는 암호문으로만 인지) │
└────────────────────────────────────────────────────────┘

[ 원격 증명 (Remote Attestation) 및 실행 흐름 ]
1. TEE 기동 ──▶ 2. 하드웨어 측정값(Quote) 서명 생성 ──▶ 3. 원격 검증 서버 전달
                                                              │
                                                              ▼ 4. 무결성 검증
6. 격리 연산 수행 ◀── 5. 검증 완료 후 복호화 키/데이터 주입 ───┘
```

| 단계 | 주요 활동 내용 | 핵심 산출물 및 프로토콜 |
|---|---|---|
| 1. 격리 영역 생성 | CPU 하드웨어 명령어로 격리된 메모리 페이지 할당 및 암호화 컨텍스트 설정 | SGX Enclave / TDX Trust Domain |
| 2. 측정값 생성 | 로딩된 코드, 데이터, 초기 상태의 SHA-256 측정값(PCR)을 CPU 키로 전자서명 | Attestation Report (Quote) |
| 3. 원격 증명 | 서명된 Quote를 독립된 외부 검증 서비스(Intel SGX DCAP, Azure Attestation)로 전송 | X.509 인증서 체인 검증 |
| 4. 키 주입 | 증명 성공 시 클라이언트가 TLS 채널을 통해 연산에 필요한 데이터 복호화 키 전송 | Key Broker Service (KBS) |
| 5. 기밀 실행 | 외부 노출 없이 TEE 내부에서만 데이터 복호화 및 알고리즘 연산 수행 후 결과 반환 | Encrypted Memory Pages |

## Ⅳ. 주요 하드웨어 TEE 구현 기술 및 데이터 상태별 비교

### 1. 하드웨어 기밀 컴퓨팅 기술 비교

| 구분 | Intel SGX | Intel TDX | AMD SEV-SNP | ARM CCA |
|---|---|---|---|---|
| 보호 단위 | 프로세스 / 엔클레이브 (App 단위) | 가상머신 전체 (Trust Domain) | 가상머신 전체 (CVM) | 렐름(Realm, 동적 가상머신) |
| 코드 수정 필요성 | 필수 (전용 SDK로 분할 개발) | 불필요 (기존 게스트 OS 그대로 구동) | 불필요 (Lift-and-Shift 가능) | 불필요 (Realm 아키텍처 구동) |
| 메모리 암호화 | MEE (Memory Encryption Engine) | TME-MK (다중 키 메모리 암호화) | AES-128/256 엔진 | 하드웨어 렐름 관리기(RMM) |
| 하이퍼바이저 격리 | 제한적 (시스템콜 처리 시 전환) | 하드웨어 차단 (TD-Module 제어) | 페이지 테이블 변조 방지(SNP) | 하이퍼바이저로부터 완전 분리 |

### 2. 데이터 3대 상태별 보안 비교

| 상태 | 설명 | 기존 보호 기술 | 기밀 컴퓨팅 적용 시 |
|---|---|---|---|
| 저장 중 (At-Rest) | 디스크 및 스토리지에 보관된 상태 | LUKS, BitLocker, TDE, KMS | 저장 암호화와 연계된 키 격리 보관 |
| 전송 중 (In-Transit) | 네트워크를 통해 이동 중인 상태 | TLS, mTLS, IPsec, VPN | TEE 종단 간 mTLS 터널링 보장 |
| 사용 중 (In-Use) | 메모리 적재 및 CPU 레지스터 연산 상태 | 기존 통제 부재 (평문 노출) | **TEE 하드웨어 실시간 메모리 암호화** |

## Ⅴ. 기밀 컴퓨팅의 한계와 방안

| 한계 | 방안 |
|---|---|
| 마이크로아키텍처 부채널 공격(캐시 타이밍, 분기 예측 변조, 과도 실행 등)으로 인한 엔클레이브 메모리 내 비밀키 유출 위험 | 최신 CPU 마이크로코드 보안 패치 적용, 하드웨어 레벨 캐시 분할 기술 적용 및 타이밍 공격 방지 상수 시간(Constant-time) 알고리즘 라이브러리 채택 |
| 하드웨어 메모리 암호화/복호화 엔진 및 TEE-호스트 간 컨텍스트 스위칭(Context Switch)으로 인한 5~30% 성능 지연 발생 | 앱 단위 SGX 대신 VM 레벨의 TDX/SEV-SNP 기술을 도입하고, I/O 집약적 작업에 대해 공유 버퍼 풀링(SWIOTLB) 메모리 최적화 적용 |
| TEE 내부에서 구동되는 게스트 애플리케이션 자체의 메모리 결함(Buffer Overflow)이나 취약 코드는 TEE 내부에서도 방어 불가 | CI/CD 단계에서 엄격한 SAST/DAST 정적 분석을 거친 검증된 바이너리만 원격 증명 베이스라인에 등록하고 경량 런타임 방어 결합 |

## Ⅵ. 제언

```text
[ 전통적 클라우드 보안 ]               [ 기밀 컴퓨팅 기반 무신뢰 클라우드 ]
스토리지/네트워크만 암호화 ─┐           ┌── CPU 하드웨어 RoT 기반 메모리 암호화
메모리 덤프 시 평문 노출 ─┼─→ [ 침해 노출 ] ─┼── 원격 증명(Attestation) 통과 후 키 주입
호스트 관리자 신뢰 의존 ──┘           └── CSP 관리자 및 하이퍼바이저 원천 배제
```

| 평가 영역 | 일반 클라우드 인프라 | 기밀 컴퓨팅 인프라 | 향후 발전 방향 |
|---|---|---|---|
| 데이터 보안 | 메모리 해킹에 무방비 | 런타임 메모리 실시간 보호 | 동형암호(HE)와 결합한 하이브리드 기밀 연산 |
| 규제 준수 | 금융/의료 데이터 이관 제약 | 데이터 주권 및 컴플라이언스 충족 | 기밀 컨테이너(CoCo) 쿠버네티스 표준화 |
| AI 보안 | 독점 모델 가중치 탈취 노출 | TEE 내부 안전한 모델 서빙 | 기밀 연합학습(Confidential FL) 플랫폼 확산 |

기밀 컴퓨팅은 클라우드 및 멀티테넌트 환경에서 '사용 중 데이터'를 하드웨어 수준에서 완벽히 보호함으로써 기업이 데이터 주권을 침해받지 않고 민감 데이터를 안전하게 연산할 수 있게 하는 미래 보안 인프라의 필수 주춧돌.
