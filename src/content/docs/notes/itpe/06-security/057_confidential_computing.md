## Ⅰ. 기밀 컴퓨팅(Confidential Computing)의 개요

- 개념 : 데이터가 메모리 상에서 CPU에 의해 처리·연산되는 **사용 중** (In-Use) 상태일 때, 하드웨어 기반의 신뢰 실행 환경(TEE, Trusted Execution Environment) 내에 메모리를 완벽히 암호화 격리함으로써 클라우드 운영자, 하이퍼바이저, 호스트 OS 관리자조차도 평문 데이터를 훔쳐볼 수 없도록 보호하는 최신 보안 컴퓨팅 기술.
- 배경 및 필요성 : 데이터 보안의 3대 상태 중 **전송 중** (TLS)과 **저장 중** (AES) 암호화는 정착되었으나, CPU가 연산할 때는 반드시 평문으로 메모리에 로드되어야 하므로 클라우드 관리자 권한 탈취나 콜드부트 공격에 무방비인 '사용 중 보안 공백' 해결 필요.
- 핵심 목적 : 데이터 사용 중(In-Use) 상태의 하드웨어 수준 기밀성 및 무결성 보장, 제3자 퍼블릭 클라우드에 대한 **무신뢰** (Zero Trust) 컴퓨팅 환경 구현.

## Ⅱ. 기밀 컴퓨팅(Confidential Computing)의 핵심 아키텍처 및 동작 메커니즘

기밀 컴퓨팅은 CPU 하드웨어 내부에 격리된 **보안 영역** (Enclave/기밀 VM)을 생성하고, **메모리 암호화 엔진** (MKTME)과 원격 증명(Remote Attestation)을 통해 신뢰성을 검증함.

```text
[ 기밀 컴퓨팅(TEE)의 하드웨어 메모리 암호화 및 격리 구조 ]

  [ 비신뢰 영역 (Untrusted Domain) ]
  - 호스트 OS (Linux/Windows), 하이퍼바이저 (KVM, ESXi), 클라우드 관리자(Root)
  - 악성코드, 루트킷, 메모리 덤프 도구 (모두 엔클레이브 내부 열람 불가!)
  ========================================================================
  [ 신뢰 영역 : 하드웨어 보안 격리 (Trusted Execution Environment) ]
  +-------------------------------------------------------------+
  | TEE 엔클레이브 / 기밀 VM (Intel SGX/TDX, AMD SEV, ARM CCA)   |
  |  - 애플리케이션 코드 및 민감 데이터 평문 실행 (초고속 연산) |
  +------------------------------┬------------------------------+
                                 │
                                 ▼ CPU 메모리 컨트롤러 암복호화
  +-------------------------------------------------------------+
  | 물리 메모리 (RAM) : 하드웨어 AES 암호키로 실시간 암호화     |
  |  - 칩 외부로 나가는 모든 메모리 버스는 실시간 암호문 전송!  |
  +-------------------------------------------------------------+
                                 │
  * 원격 증명 (Remote Attestation) : 외부 사용자가 하드웨어 서명을 통해
    자신의 코드가 정품 TEE 칩 내부에서 변조 없이 실행 중임을 암호학적으로 검증
```

- **신뢰 실행 환경** (TEE, Trusted Execution Environment) : CPU 칩 내부에 하드웨어적으로 보호된 안전 구역을 형성하여 외부 접근을 차단.
- **실시간 메모리 암호화** : CPU 내부 캐시에서 외부 물리 RAM으로 데이터가 이동할 때 하드웨어 암호화 엔진이 무작위 대칭키로 메모리 블록을 즉시 암호화.
- **원격 증명** (Remote Attestation) : TEE 하드웨어가 제조사(Intel, AMD)의 고유 비밀키로 서명된 증명 보고서를 생성하여, 원격 사용자에게 소프트웨어 무결성을 증명.
- 대표 하드웨어 아키텍처 : **프로세스 레벨 격리** (Intel SGX), **가상머신 전체 격리** (Intel TDX, AMD SEV-SNP), 모바일/임베디드(ARM TrustZone / CCA).

## Ⅲ. 기밀 컴퓨팅(Confidential Computing)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 전통적 클라우드 가상화 | 동형암호 (FHE) | 기밀 컴퓨팅 (Confidential Computing) |
| --- | --- | --- | --- |
| 연산 중 데이터 상태 | 평문으로 RAM에 상주 (루트 권한 탈취 시 노출) | 암호문 상태 유지 연산 (수학적 보호) | TEE 하드웨어 내부에서만 평문 복호화 |
| 보안 근거 | OS/하이퍼바이저 논리적 권한 통제 | 격자 기반 수학적 난제 (RLWE) | CPU 실리콘 하드웨어 제조사 신뢰 |
| 연산 성능/지연 | 기본 네이티브 성능 | 극도로 느림 (큰 지연) | 네이티브에 근접 (미세 오버헤드) |
| 적용 난이도 | 매우 쉬움 | 알고리즘 전면 재작성 필요 (비선형 불가) | 기밀 VM 기술로 기존 코드 수정 없이 구동 |
| 대표적 위협 | 클라우드 관리자 침해, 하이퍼바이저 탈출 | 부트스트래핑 잡음 누적 | CPU 마이크로아키텍처 부채널 공격 |

- 기밀 컴퓨팅은 동형암호의 치명적인 성능 저하 없이 기존 애플리케이션 코드를 거의 그대로 실행하면서도 클라우드 관리자의 감시를 배제할 수 있는 가장 실용적인 해결책임.

## Ⅳ. 기밀 컴퓨팅(Confidential Computing)의 주요 한계점 및 해결 방안

- CPU 캐시 타이밍 및 **추측 실행** (Spectre) 기반 부채널 공격 취약성 :
  - 한계점 : 하드웨어 칩 내부 격리에도 불구하고 캐시 메모리 접근 시간 차이나 마이크로아키텍처 결함을 이용한 메모리 키 누출 위험 잔존.
  - 해결 방안 : CPU 마이크로코드 최신 패치, 캐시 플러시(Flush) 강제 및 **상수 시간** (Constant-Time) 암호화 알고리즘 구현.
- 초기 **TEE** (Intel SGX)의 애플리케이션 리팩토링 부담 :
  - 한계점 : SGX는 코드의 일부만을 엔클레이브 함수로 분리 재작성해야 하여 기존 엔터프라이즈 레거시 소프트웨어 적용 난항.
  - 해결 방안 : 코드 수정 없이 운영체제와 VM 전체를 기밀 영역으로 감싸는 차세대 **기밀 가상머신** (Intel TDX, AMD SEV-SNP) 채택.
- 하드웨어 제조사(Intel, AMD, ARM)에 대한 **단일 신뢰 앵커** 종속 :
  - 한계점 : 원격 증명의 신뢰 근거가 CPU 제조사의 루트 인증서에 의존하므로 제조사 키 유출 시 공급망 전체 신뢰 붕괴 우려.
  - 해결 방안 : 오픈소스 하드웨어 보안 엔클레이브(Keystone) 연구 및 다자간 다중 벤더 증명 프로토콜 결합.

## Ⅴ. 기밀 컴퓨팅(Confidential Computing) 적용 및 발전을 위한 기술사적 제언

- 공공·금융 민감 워크로드의 퍼블릭 클라우드 이행 가속 : 기밀 컴퓨팅 기반 **기밀 VM** (Confidential VM)을 도입하여 규제 기관의 데이터 통제권 요건 충족.
- **기밀 AI** (Confidential AI) 인프라 구축 : 제3자 클라우드 GPU(NVIDIA H100 기밀 컴퓨팅 지원) 환경에서 지적재산권인 AI 모델 가중치와 환자 진료 데이터를 안전하게 추론.
- 블록체인 분산 노드 및 오라클의 TEE 통합 : 스마트 컨트랙트 외부에 존재하는 금융 API 데이터를 TEE 내부에서 검증하여 **신뢰된 오라클** (Trusted Oracle) 데이터 공급망 확립.
