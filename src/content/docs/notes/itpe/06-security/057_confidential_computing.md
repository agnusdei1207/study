## 지식 로드맵 내 현재 위치

클라우드 보안 → 데이터 기밀성 → 사용 중 데이터 보호

## 30초 인출

- **본질**: 기밀 컴퓨팅은 하드웨어 기반의 증명 가능한 신뢰실행환경에서 계산해 사용 중 데이터를 보호하는 방식.
- **메커니즘**: 격리된 실행 → 하드웨어 증거 제공 → 정책에 따른 원격 증명 검증 → 승인 후에만 비밀 제공.
- **핵심**: 보호는 TEE 경계에 한정되므로 코드·입출력·플랫폼·측면채널 위험을 별도로 관리.

<details><summary>핵심 용어</summary>

- **기밀 컴퓨팅** (Confidential Computing): 하드웨어 기반의 증명 가능한 TEE에서 연산해 사용 중 데이터를 보호하는 방식.
- **TEE(Trusted Execution Environment)**: 하드웨어가 제공하는 격리 경계 안에서 코드·데이터를 실행하는 환경.
- **원격 증명(Remote Attestation)**: 실행환경의 하드웨어 측정·상태 증거를 원격 검증자가 정책과 대조하는 절차.
- **CVM(Confidential Virtual Machine)**: 가상머신의 메모리·상태를 호스트로부터 보호하도록 지원하는 기밀 VM 유형.
- **VMM(Virtual Machine Monitor)**: 가상머신의 실행·자원 배분을 관리하는 하이퍼바이저.
- **CCC(Confidential Computing Consortium)**: 기밀 컴퓨팅 용어와 생태계 발전을 다루는 Linux Foundation 산하 협력 단체.
</details>

```text
데이터 소유자 ── 실행정책·측정기준 ──→ TEE 워크로드
                                         │ 증명자료

                                         │ 정책 통과 시

```

원격 증명은 하드웨어·실행환경의 측정 근거를 확인하는 수단이며 응용 코드가 안전하다는 보증은 아님.

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **기밀 컴퓨팅**은 하드웨어 기반의 증명 가능한 TEE에서 연산해 사용 중 데이터를 보호하는 방식. |
| 목적 | 클라우드 호스트 등 실행 인프라에 대한 신뢰 의존과 메모리 노출 위험을 줄임. |

## Ⅱ. 데이터 보호 범위

| 데이터 상태 | 대표 보호 | 남는 검토점 |
|---|---|---|
| 저장 중 | 저장장치·DB 암호화 | 키 관리·백업·권한 |
| 전송 중 | TLS 등 채널 암호화 | 종단·인증서·키 보호 |
| 사용 중 | TEE에서 실행·메모리 격리 | TEE 경계 밖의 코드·입출력·연계 위험 |

기밀 컴퓨팅은 저장·전송 보호를 대체하지 않고 사용 중 데이터의 특정 위협을 보완.

## Ⅲ. TEE 신뢰경계와 증거

```text
┌─────────────────────────────────────────┐
│ 호스트·운영체제·하이퍼바이저             │
│                                         │
│   ┌──── 하드웨어 보호 경계(TEE) ────┐   │
│   │ 승인 워크로드 + 사용 중 데이터  │   │
│   │ 격리 실행·측정값 생성           │   │
│   └─────────────────────────────────┘   │
│          허용된 입출력·공유 통로          │
└─────────────────────────────────────────┘
```

CCC가 제시하는 용어에서 기밀 컴퓨팅은 하드웨어 기반·증명 가능한 TEE에서 연산하여 사용 중 데이터를 보호하는 접근. 하드웨어가 규정한 격리 경계의 밖으로 나가는 데이터와 요청은 별도 보호 대상.

## Ⅳ. 원격 증명과 실행 절차

```text
① 소유자: 허용 코드·구성·정책 설정
                    ↓
② TEE: 실행 측정·암호학적 증거 생성
                    ↓ 증거 전달
③ 검증자: 증거·인증서·정책 비교
                    ↓ 통과 시 비밀 제공 승인
④ TEE: 키·데이터를 받아 격리 연산
                    ↓ 결과 반출 정책 적용
⑤ 소유자: 결과 수신·실행기록 점검
```

증명 성공은 정의된 측정기준과 플랫폼 상태가 정책에 맞는다는 증거일 뿐, 코드 취약성이나 업무 결과의 정확성까지 자동 보장하지 않음.

## Ⅴ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 증명 결과를 애플리케이션 자체의 무결점 보증으로 오해하기 쉬움. | 측정기준을 승인된 코드·구성·패치 상태와 연결하고 일반 코드 보안검토·취약점 관리와 함께 운영하는 방안. |
