<details>
<summary>핵심 용어</summary>

- **VPN (Virtual Private Network):** 공중망 위에 논리적으로 분리된 사설 통신경로를 제공하는 기술
- **IPsec (Internet Protocol Security):** IP 계층 트래픽 보호를 위한 보안 프로토콜 묶음
- **ESP (Encapsulating Security Payload):** IPsec에서 기밀성·무결성·인증 등의 트래픽 보호를 제공하는 프로토콜
- **AH (Authentication Header):** IPsec에서 무결성·데이터 출처 인증 등을 제공하며 기밀성을 제공하지 않는 프로토콜
- **IKEv2 (Internet Key Exchange version 2):** 피어를 인증하고 IPsec 보안연계·키를 협상하는 프로토콜
- **WireGuard:** 공개키 기반 피어 설정과 암호화된 IP 터널을 제공하는 VPN 프로토콜
- **OpenVPN:** TLS 기반 제어 채널과 VPN 데이터 터널을 제공하는 소프트웨어
</details>

### Ⅰ. 개요

| 구분 | 핵심 |

| 정의 | **VPN (Virtual Private Network)**은 공중망을 통해 논리적으로 분리된 사설 통신경로를 제공하는 기술 |
| 목적 | 전용 물리망 없이 원격 사용자·지점 간 통신의 기밀성·무결성·접근통제 지원 |

### Ⅱ. 동작과 유형

| 유형 | 주요 특성 |
|---|---|
| IPsec VPN | IP 계층 보호, 전송·터널 모드, IKEv2 기반 보안연계 협상 |
| WireGuard | 공개키·키 교환 기반의 IP 터널과 피어별 통신정책 |
| OpenVPN | TLS 기반 인증·키 교환과 IP 터널의 결합 |

```text
피어 인증·보안연계 설정
          ↓
패킷 캡슐화·암호화 등 보호
          ↓
공중망 터널 전송
          ↓
수신측 검증·복호화·전달
```

**제언:** 터널 암호화와 별도로 원격 계정·단말 상태·접근 가능한 자원의 권한을 제한

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **VPN (Virtual Private Network)**은 공중망을 통해 논리적으로 분리된 사설 통신경로를 제공하는 기술 |
| 목적 | 전용 물리망 없이 원격 사용자·지점 간 통신의 기밀성·무결성·접근통제 지원 |

보호 수준은 사용하는 프로토콜·암호설정·인증·접근정책의 실제 구성에 좌우.

## Ⅱ. 구성요소와 역할

| 구성요소 | 역할 |
|---|---|
| VPN 클라이언트·게이트웨이 | 터널 종단과 패킷 처리 |
| 인증·키관리 기능 | 피어 인증과 키·보안연계 수립 |
| 터널 프로토콜 | 트래픽 캡슐화와 암호·무결성 보호 |
| 접근정책·라우팅 | 통신 대상·경로·권한의 제한 |

```text
원격 사용자·지점
       ↓ 인증·정책 확인
VPN 터널 종단 ── 보호된 터널 ── VPN 게이트웨이
                                      ↓ 접근정책·라우팅
                                내부 자원
```

## Ⅲ. IPsec 동작과 모드

| 요소 | 기능 |
|---|---|
| IKEv2 | 피어 인증 및 IKE·Child SA 키·정책 협상 |
| ESP | 암호화·무결성·인증 등 보호 서비스 제공 |
| AH | 무결성·출처 인증 등 보호; 기밀성은 미제공 |

| 모드 | 보호 범위 |
|---|---|
| 전송 모드 | 기존 IP 헤더를 유지하고 주로 상위 계층 페이로드를 보호 |
| 터널 모드 | 원래 IP 패킷을 보호된 내부 패킷으로 포함하고 외부 IP 헤더 추가 |

```text
원격 피어
   ↓ IKEv2: 인증·보안연계 협상
ESP 보호 적용
   ↓ 전송 모드 또는 터널 모드
공중망으로 패킷 전송 → 반대편 IPsec 종단에서 검증·복호화
```

## Ⅳ. 구현 유형 비교

| 구분 | IPsec | WireGuard | OpenVPN |
|---|---|---|---|
| 계층·구성 | IP 트래픽 보호 | IP 터널·공개키 기반 피어 | TLS 제어·키교환과 VPN 데이터 터널 |
| 일반 적용 | 지점 간·원격접속 | 호스트·지점 간 IP 터널 | 클라이언트·서버형 원격접속 |
| 설계 검토 | 정책·SA·키관리·모드 | 피어키·라우팅·키교체 | 인증서·TLS·전송·클라이언트 설정 |

## Ⅴ. 원격접속 운영통제

| 위험 | 통제 |
|---|---|
| 계정·키 탈취 | 다중인증, 키·인증서 수명관리, 이상 로그인 감시 |
| VPN 연결 후 과도한 내부 접근 | 최소권한, 자원·구간별 정책, 관리망 분리 |
| 취약·관리되지 않은 단말 | 단말 보안상태 확인, 보안패치, 감염 단말 격리 |
| 터널 설정 오류 | 안전한 암호 설정, 라우팅·분할터널 정책 검토, 설정 변경감사 |

## Ⅵ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| VPN 접속 성공이 내부의 모든 자원에 대한 신뢰로 확대될 수 있음 | 터널 연결과 자원 접근 인가를 분리하고 사용자·단말·업무별 최소권한을 적용하며 접속 이후 로그를 지속 점검 |
