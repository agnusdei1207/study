## 답안 골격
```text
[VPN] ◀━━ 머리: Ⅶ 내 의견 (성능과 보안 절충을 위한 WireGuard 전환 + ZTNA 기반 접근통제 연동)
 ┃
 ┣━ Ⅰ 개요 ───── 고가의 전용선(Leased Line) 구축 비용 한계 → 공중망 위에 암호화 터널을 뚫어 전용선처럼 활용
 ┣━ Ⅱ 특징 ───── 터널링(Tunneling) · 암호화 및 무결성 · 사용자/기기 인증 · 접근 제어
 ┣━ Ⅲ 구조 ───── OSI 3계층(IPsec: AH, ESP, IKE) vs OSI 4~7계층(SSL/TLS: OpenVPN, WireGuard)
 ┣━ Ⅳ 흐름 ───── ① 피어 간 IKE 1단계(ISAKMP SA 협상) → ② IKE 2단계(IPsec SA 협상) → ③ 패킷 캡슐화 및 터널 전송
 ┣━ Ⅴ 비교 ───── IPsec VPN(네트워크 계층, Site-to-Site 적합) vs SSL VPN(전송 계층, Client-to-Site 적합)
 ┗━ Ⅵ 실무 ───── 단일 게이트웨이 병목 / VPN 자격증명 탈취 시 내부망 전면 노출 / 패킷 MTU 오버헤드
```

## 한 줄 본질

## 핵심 그림
```text
[IPsec VPN 터널 모드 vs 전송 모드 패킷 캡슐화 구조]

 1. 전송 모드 (Transport Mode: End-to-End 단말 간 보호)
 ┌──────────────┬──────────────┬────────────────────────┬─────────────┐
 │ 원본 IP 헤더 │  ESP 헤더    │       TCP/UDP 페이로드 │ ESP 트레일러│
 └──────────────┴──────────────┴────────────────────────┴─────────────┘
                                [◀───── 암호화 구간 ────▶]

 2. 터널 모드 (Tunnel Mode: Gateway-to-Gateway 본지사 간 보호)
 ┌──────────────┬──────────────┬──────────────┬─────────┬─────────────┐
 │ 신규 IP 헤더 │  ESP 헤더    │ 원본 IP 헤더 │ 페이로드│ ESP 트레일러│
 └──────────────┴──────────────┴──────────────┴─────────┴─────────────┘
                                [◀────── 암호화 구간 ────────────────▶]
```

## 핵심 용어
- ESP(Encapsulating Security Payload): IP 패킷에 대해 기밀성(암호화), 무결성, 인증 및 재전송 방지 기능을 모두 제공하는 IPsec 프로토콜
- IKE(Internet Key Exchange): 통신 쌍방 간에 암호 알고리즘과 비밀키를 안전하게 협상하고 보안 연계(SA: Security Association)를 맺는 프로토콜

## 핵심 통찰
- IPsec 터널 모드는 원본 IP 헤더까지 통째로 암호화하고 새로운 외부 IP 헤더를 씌우므로 내부 네트워크 토폴로지가 외부에 노출되지 않음
- SSL VPN은 전용 클라이언트 프로그램 설치 없이 웹 브라우저만으로 쉽게 접속할 수 있어 재택근무자 환경에 적합하나, 웹 애플리케이션 외 프로토콜 지원이 제한적임
- VPN은 경계 침투 방어선일 뿐 내부 확산 방어선이 아님 → VPN 계정 하나만 탈취되면 공격자가 내부 사내망 전체를 마음대로 스캐닝할 수 있는 '신뢰의 함정' 존재

## 이웃 토픽과 구분
- VPN vs ZTNA(Zero Trust Network Access): VPN = 통과하면 내부 네트워크 전체에 접속 허용 / ZTNA = 특정 사용자가 인가받은 단 하나의 애플리케이션에만 마이크로 연결

## 문제·원인·대책
- 사례: 133회 기출 원격 근무자의 VPN 계정이 크리덴셜 스터핑으로 유출되어 사내 인트라넷 침투 및 랜섬웨어 감염된 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| ID/PW 탈취만으로 사내망 침투 성공 | VPN 접속 시 단일 지식 기반(1-Factor) 인증 사용 | 생체인증 또는 FIDO 기반 MFA(다중요소인증) 강제 | 유출된 패스워드를 이용한 비인가 접속 99% 차단 |
| 재택 근무 단말의 악성코드가 VPN 터널 타고 내부 전파 | 스플릿 터널링(Split Tunneling) 사용 및 단말 검증 미흡 | mTLS 및 EDR 상태 검증(Posture Check) 연동 후 터널 개방 | 감염된 단말의 사내망 연결 차단 |
