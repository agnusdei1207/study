# PIMS(Personal Information Management System)

## 핵심 개념
- 조직이 수집·보유·이용하는 개인정보를 안전하게 보호·관리하기 위해 기술적·관리적·물리적 보호조치를 포함한 일련의 관리체계를 구축하고, 이를 독립된 전문 인증기관이 심사하여 인증을 부여하는 공인 제도.
- 2018년 정보보호 관리체계(ISMS)와 통합되어 현재는 'ISMS-P(정보보호 및 개인정보보호 관리체계)'로 운영되고 있으나, 개인정보 생명주기 통제 및 프라이버시 거버넌스의 이론적·실무적 근간을 이룸.

```
+-------------------------------------------------------------+
|               PIMS 3대 통제 영역 (전통적 PIMS 기준)             |
+-------------------------------------------------------------+
| 1. 관리과정 수립·운영 | 정책 수립, 조직 구성, 위험 관리, 사후 관리    |
| 2. 생명주기 관리      | 수집, 이용·제공, 보관, 파기 단계별 통제       |
| 3. 보호대책 요구사항  | 접근통제, 암호화, 계정관리, 물리적 보안 등     |
+-------------------------------------------------------------+
```

---

## PIMS 관리체계 인증 기준 구조

```
+-------------------------------------------------------------+
| [1. 관리과정 수립·운영]                                     |
|  - 기획: 경영진 참여, 범위 설정, 정책 수립                  |
|  - 구축: 자산 식별, 개인정보 흐름 분석, 위험 평가           |
|  - 운영: 보호대책 구현, 교육, 내부 감사                     |
|  - 점검 및 개선: 경영진 보고, 시정 조치                     |
+-------------------------------------------------------------+
                              |
                              v
+-------------------------------------------------------------+
| [2. 개인정보 생명주기 관리]                                 |
|  - 수집: 동의 획득, 최소 수집, 법정 서식 준수               |
|  - 이용 및 제공: 목적 내 이용, 제3자 제공 계약, 위탁 관리  |
|  - 보관: 보유기간 설정, 분리 보관                           |
|  - 파기: 목적 달성 시 복구 불가능한 영구 파기              |
+-------------------------------------------------------------+
                              |
                              v
+-------------------------------------------------------------+
| [3. 기술적·물리적 보호대책]                                 |
|  - 고유식별정보 암호화, 접근 권한 통제, 침입 차단/탐지      |
|  - 접속 기록(Log) 1년/2년 이상 보관 및 위변조 방지          |
|  - 전산실 출입통제 및 문서 보관함 시건 장치                |
+-------------------------------------------------------------+
```

## ISMS vs PIMS 비교

| 비교 항목 | ISMS (정보보호 관리체계) | PIMS (개인정보보호 관리체계) |
|---|---|---|
| **보호 대상** | 기업의 모든 주요 정보 자산 (시스템, DB, 네트워크) | 정보주체의 '개인정보' 및 관련 처리 시스템 |
| **핵심 목적** | 기밀성, 무결성, 가용성 (CIA Triad) 보장 | 정보주체의 권리 보장 및 프라이버시 침해 예방 |
| **법적 근거** | 정보통신망법 제47조 | 개인정보 보호법 제32조의2 |
| **통제 관점** | 인프라 및 시스템 중심의 기술적·물리적 보안 통제 | 수집-이용-제공-파기 생명주기 중심의 법적 컴플라이언스 |
| **의무 대상** | 매출액 및 이용자 수 기준 일정 규모 이상의 기업 | 자율 신청 (공공기관 및 기업 중심) |

## ISMS와 PIMS의 통합 (ISMS-P 출범)

2018년 11월, 기업의 중복 인증 부담을 해소하고 정보보호와 개인정보보호를 유기적으로 연계하기 위해 ISMS와 PIMS가 **ISMS-P**로 통합됨.

```
+---------------------+     +---------------------+
|    기존 ISMS        |     |    기존 PIMS        |
| (정보보호 관리체계) |     | (개인정보 관리체계) |
+---------------------+     +---------------------+
           \                           /
            \                         /
             v                       v
      +-------------------------------------+
      |        통합 ISMS-P 인증 제도         |
      |                                     |
      | 1. 관리체계 수립 및 운영 (16개 항목) |
      | 2. 보호대책 요구사항     (64개 항목) |
      | 3. 개인정보 처리단계별   (22개 항목) |
      |    요구사항                         |
      |    (총 102개 인증 기준)             |
      +-------------------------------------+
```

- **통합의 이점**:
  - 기업 입장: 중복 심사(비용, 수검 인력 부담) 해소, 단일 인증으로 정보보호와 개인정보 통합 관리.
  - 관리적 입장: 정보자산 보호와 개인정보 처리 흐름의 사각지대 제거.

---

## 결론 및 실무 시사점
- PIMS는 개인정보를 단순한 시스템 데이터가 아닌 정보주체의 기본권 차원에서 다루는 프라이버시 거버넌스의 기초를 마련함.
- 현재는 통합된 ISMS-P 인증 제도로 운영되므로, 기업은 인프라 보안 통제(ISMS 영역) 위에 개인정보 생애주기별 법적 요구사항(PIMS 영역)을 빈틈없이 결합하여 컴플라이언스를 확보해야 함.
