## 연관 키워드

- 비대칭키 암호화(Asymmetric Key Encryption), 공개키 암호(Public Key Cryptography), 공개키, 개인키
- 키 배송 문제(Key Distribution), 부인방지(Non-repudiation), 디지털 서명, 하이브리드 암호화(Hybrid Encryption)
- RSA, ECC(Elliptic Curve Cryptography), 디피-헬만(DH), ML-KEM, 쇼어 알고리즘(Shor's Algorithm), 암호 민첩성(Crypto-Agility)
- 공개키 기반구조(PKI, Public Key Infrastructure), 중간자 공격(MitM, Man-in-the-Middle)

## Ⅰ. 비대칭키 암호화의 개요

- 핵심 요약 : 공개키와 개인키 한 쌍으로 기밀성, 전자서명, 키 교환을 해결하는 공개키 암호 기술.
- 개념 : 수학적으로 연결된 키 쌍, 즉 누구나 아는 공개키와 소유자만 아는 개인키로 기밀성·전자서명·키 교환을 제공하는 **공개키 암호** (Public Key Cryptography) 방식.
- 배경 및 필요성 : 대칭키는 통신 전에 안전한 경로로 키를 나눠 가져야 하는 **키 배송 문제** (Key Distribution)가 있어, 이를 공개 채널에서도 해결하려는 요구에서 출현함.
- 주요 목적 : 공개 채널에서의 키 배송 문제 해소와 서명자의 행위를 부정할 수 없게 하는 **부인방지** (Non-repudiation) 제공.

## Ⅱ. 비대칭키 암호화의 특징 및 장점

- 핵심 요약 : 공개와 비공개를 분리한 키 구조가 키 배송 부담을 줄이고 서명과 키 교환을 가능하게 하는 원리.

1. 공개키 배포 : 공개키는 공개 채널로 배포해도 안전 → 사용자 수가 늘어도 키 배송 경로를 따로 만들 필요가 없음.
2. 개인키 독점 : 개인키로만 서명과 복호화를 수행 → 서명자 식별과 부인방지의 근거 확보.
3. 수학적 난제 기반 : 소인수분해나 이산대수 같은 역연산이 고전 컴퓨터에서 현실적으로 어려움 → 공개키로부터 개인키를 추론하기 어려움.
4. 키 교환 : 공개 파라미터를 주고받아 양측이 같은 공유 비밀을 계산 → 대칭 세션키를 안전하게 설정.

## Ⅲ. 비대칭키 암호화의 구조 (흐름)

- 핵심 요약 : 기밀성, 전자서명, 하이브리드 구성이 어떤 키를 어느 단계에 쓰는지에 따라 서로 다른 흐름을 가짐.

```text
[ 기밀성 ]

평문 M → 수신자 공개키로 암호화
   ↓
암호문 C (공개 채널로 전송)
   ↓
수신자 개인키로 복호화 → 평문 M
```

```text
[ 전자서명 ]

원본 M → 해시 → 송신자 개인키로 서명
   ↓
서명값 S와 원본 M 함께 전달
   ↓
송신자 공개키로 검증 → 무결성·신원 확인
```

```text
[ 하이브리드 암호화 ]

대용량 데이터 → 임의의 AES 세션키로 암호화
   ↓
세션키 → 수신자 공개키로 암호화
   ↓
수신자 개인키로 세션키 복구 → 데이터 복호화
```

## Ⅳ. 비대칭키 암호화의 비교

- 핵심 요약 : 공개키 암호는 키 관리가 쉬운 대신 연산이 느려, 대칭키와 역할을 나누어 쓰는 것이 실무의 기본 구도.

| 비교 축 | 비대칭키 암호화 | 대칭키 암호화 |
| --- | --- | --- |
| 키 구성 | 공개키와 개인키 쌍 | 하나의 공유 비밀키 |
| 연산 속도 | 상대적으로 느림 (큰 수의 모듈러 연산) | 빠름 (치환과 순열 중심) |
| 키 개수 (N명 기준) | 2N개로 선형 증가 | N(N-1)/2개로 급증 |
| 키 배송 | 공개키 공개로 해결 | 사전 안전 경로 필요 |
| 제공 기능 | 기밀성, 전자서명, 부인방지, 키 교환 | 기밀성, 무결성 (AEAD 모드 시) |
| 주 용도 | TLS 키 교환, 인증서, 전자서명 | 대용량 데이터, 파일과 디스크 암호화 |

| 구분 | RSA | ECC | DH | **ML-KEM** (Module-Lattice-Based Key-Encapsulation Mechanism) |
| --- | --- | --- | --- | --- |
| 기반 난제 | 큰 수의 소인수분해 | 타원곡선 이산대수 | 유한체 이산대수 | 모듈 격자 위 학습 오류 문제 |
| 128비트 보안 기준 키 크기 | 3072비트 | 256비트 (P-256) | 3072비트 | ML-KEM-768 공개키 1184바이트 |
| 특징 | 역사가 길고 검증됨 | 짧은 키와 빠른 연산 | 키 교환 전용 | 양자 컴퓨터 내성 |
| 대표 표준 | PKCS #1, FIPS 186-5 | FIPS 186-5, RFC 8032 (Ed25519) | RFC 3526, RFC 7919 | FIPS 203 |

- 선택 기준 : 기존 호환성이 중요하면 RSA나 ECC, 장기 기밀성이 필요하면 PQC 방식을 함께 검토함.

## Ⅴ. 비대칭키 암호화의 한계와 방안

- 핵심 요약 : 공개키 위조, 연산 부하, 양자 컴퓨터 위협을 인증 체계, 하이브리드 암호화, 암호 민첩성으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **중간자 공격** (MitM, Man-in-the-Middle) | 공개키가 변조되어 공격자의 키로 바뀌면 통신 내용이 노출됨 | 인증기관(CA)이 신원과 공개키를 묶어 서명한 인증서를 발급하는 **공개키 기반구조** (PKI, Public Key Infrastructure) 운영 | 인증서 검증 실패율 |
| 연산 부하 | 대용량 데이터를 공개키로 직접 암호화하면 CPU 부담이 커짐 | **하이브리드 암호화** (Hybrid Encryption)로 데이터는 대칭키로, 대칭키만 공개키로 보호 | 암호화 처리 지연 시간 |
| 양자 컴퓨터 위협 | 쇼어 알고리즘이 구동되면 RSA와 ECC가 실용 시간 안에 깨질 수 있음 | NIST가 표준화한 ML-KEM과 ML-DSA 도입, 알고리즘을 교체할 수 있는 **암호 민첩성** (Crypto-Agility) 확보 | PQC 전환율, 인증서 교체율 |

## Ⅵ. 비대칭키 암호화에 대한 기술사적 제언

- 핵심 요약 : 공개키 체계를 알고리즘 교체가 가능한 구조로 재편하고, PQC 전환을 국가와 조직 단위의 로드맵으로 관리.

1. 전환 로드맵 : 국가 암호 정책 기관이 알고리즘별 사용 중단 시한을 정하고, 기관별 전환 계획을 주기적으로 점검하도록 제도화.
2. 암호 자산 관리 : 정보보호 조직이 어떤 시스템이 어떤 공개키 알고리즘을 쓰는지 목록화하여, 설계 검토 단계에서 교체 가능성을 확인하도록 함.
3. 구현 검증 : 개발과 운영 조직이 하이브리드 구현의 호환성과 키 길이 기준을 시험 절차로 검증하고, 이를 담당자 교육과 연결함.

## Ⅶ. 결론

- 핵심 요약 : 비대칭키 암호는 키 배송 문제를 해결한 공개키 기술이며, 양자 시대의 과제는 알고리즘 전환 능력임.
- 시사점 : 공개키 암호의 안전성은 알고리즘 자체보다 키 관리와 교체 능력에 달려 있어, 암호 민첩성이 기본 설계 요건으로 자리 잡아야 함.
