## 지식 로드맵 내 현재 위치

정보보안 → 암호학 → 공개키 암호 및 비대칭키 암호화(Asymmetric Encryption)

## 30초 인출

- **본질:** 수학적 난제(일방향 트랩도어 함수)에 기반하여 서로 다른 공개키(Public Key)와 개인키(Private Key) 한 쌍을 생성함으로써 대칭키의 키 배송 문제를 해결한 현대 암호 체계
- **메커니즘:** 기밀성(수신자 공개키 암호화 $\rightarrow$ 개인키 복호화), 전자서명(송신자 개인키 서명 $\rightarrow$ 공개키 검증), 키 합의(ECDH/KEM을 통한 세션키 교환)
- 통찰: 수학적 난제에 기반한 뛰어난 키 분배 편의성 및 전자서명 부인방지 제공에도 불구하고 높은 연산 오버헤드를 극복하기 위해 대칭키와 결합한 하이브리드 암호화 및 쇼어 알고리즘 대응 격자 기반 PQC 전환 필수

<details><summary>핵심 용어</summary>

- **비대칭키 암호화 (공개키 암호):** 암호화에 사용하는 키와 복호화에 사용하는 키가 상이한 암호 방식(Diffie-Hellman 및 RSA 창안).
- **트랩도어 일방향 함수 (Trapdoor One-way Function):** 순방향 계산은 쉬우나 역방향 계산은 특정 비밀 정보(트랩도어) 없이는 수학적으로 불가능한 함수.
- **키 개수 복잡도 ($2N$):** $N$명의 참여자가 상호 비밀 통신을 위해 각자 1쌍의 공개키/개인키만 생성하면 되므로 총 키 수가 $2N$개로 선형적 유지.
- **전자서명 (Digital Signature):** 송신자의 개인키로 데이터 해시값을 암호화하여 송신자 신원 확인, 위변조 방지, 부인방지를 달성하는 기술.
- **KEM (Key Encapsulation Mechanism):** 비대칭 암호화를 사용하여 대칭키(공유 비밀)를 안전하게 캡슐화하여 전달하는 암호학적 프리미티브(NIST FIPS 203).

</details>

## 2~4교시 예상문제 (25점)

> 비대칭키 암호화(Asymmetric Key Encryption)의 수학적 원리(트랩도어 일방향 함수)와 3대 핵심 메커니즘(기밀성, 전자서명, 키 교환)을 설명하고, 대칭키 암호와의 비교 및 양자 컴퓨팅 위협에 대비한 PQC(양자내성암호) 전환 방안을 제시하시오. (기출·제132회 1교시 4번)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 수학적으로 연결된 한 쌍의 키(누구나 알 수 있는 공개키와 소유자만 아는 개인키)를 사용하여 데이터 기밀성, 전자서명, 키 교환을 제공하는 공개키 암호 기술 |
| 목적 | 대칭키의 본질적 난제인 안전하지 않은 채널에서의 '키 배송 문제(Key Distribution)' 해결 및 법적 효력을 갖는 부인방지(Non-repudiation) 제공 |

## Ⅱ. 비대칭키 암호화의 주요 특징

| 특징 | 세부 내용 | 구현 요소 |
|---|---|---|
| 수학적 일방향 트랩도어 | 순방향 연산은 쉬우나 개인키(트랩도어) 없이는 역방향 복호화가 불가능한 수학적 복잡도 난제 기반 | 소인수분해(RSA), 타원곡선 이산대수(ECC) |
| 키 관리의 선형성 ($2N$) | 사용자 수 $N$명에 대해 사용자당 1쌍씩 총 $2N$개의 키만 관리하면 되므로 확장성 탁월 | PKI 인증서 관리, LDAP |
| 기밀성과 부인방지 분리 | 수신자 공개키 암호화는 '기밀성'을, 송신자 개인키 서명은 '인증 및 부인방지'를 독립적으로 제공 | 암호화 vs 전자서명 |
| 하이브리드 연계성 | 연산 부하가 크므로 대용량 데이터는 대칭키(AES)로 처리하고, 대칭 세션키만 비대칭키로 암호화 | 하이브리드 암호, TLS 세션 키 합의 |

## Ⅲ. 비대칭키 3대 응용 아키텍처 및 메커니즘

```text
[ 1. 기밀성 보장 (Confidentiality) ] ── 수신자의 공개키 사용
송신자 ──▶ 평문 (M) ──▶ [ 수신자 공개키로 암호화 ] ──▶ 암호문 (C) ──▶ [ 수신자 개인키로 복호화 ] ──▶ 평문 (M)

[ 2. 인증 및 부인방지 (Digital Signature) ] ── 송신자의 개인키 사용
송신자 ──▶ 원본 (M) 해시 ──▶ [ 송신자 개인키로 서명 ] ──▶ 서명값 (S) ──▶ [ 송신자 공개키로 검증 ] ──▶ 무결성/신원 확인!

[ 3. 키 합의 및 수송 (Key Establishment / KEM) ]
클라이언트 ──▶ 공개키 파라미터 교환 (ECDH / ML-KEM) ◀── 서버
                    │                                        │
                    ▼                                        ▼
             동일한 대칭 세션키 (Session Key) 유도 ──▶ AES-GCM 대칭 통신 개시
```

| 응용 메커니즘 | 암호화 키 | 복호화/검증 키 | 핵심 달성 목표 |
|---|---|---|---|
| 데이터 기밀성 | **수신자의 공개키 (Receiver's Public Key)** | **수신자의 개인키 (Receiver's Private Key)** | 수신자 본인 외 해독 불가 (도청 방지) |
| 전자서명 (인증) | **송신자의 개인키 (Sender's Private Key)** | **송신자의 공개키 (Sender's Public Key)** | 송신자 신원 입증, 위변조 방지, 부인방지 |
| 키 교환 (KEM/ECDH)| 양측의 공개키 파라미터 교환 | 각자의 개인키로 동일 공유 비밀 유도 | 안전한 대칭키 공유 (TLS 1.3) |

## Ⅳ. 비대칭키 vs 대칭키 비교 및 주요 공개키 알고리즘 분류

### 1. 비대칭키와 대칭키 암호화 비교

| 비교 항목 | 비대칭키 암호화 (Asymmetric) | 대칭키 암호화 (Symmetric) |
|---|---|---|
| 키 구성 | 공개키 + 개인키 (비대칭 쌍) | 동일한 단일 비밀키 |
| 연산 속도 | 상대적으로 느림 (모듈러 멱승 연산) | 극도로 빠름 (비트 단위 치환/순열) |
| 키 개수 ($N$명) | **$2N$ 개** (선형적 확장) | **$N(N-1)/2$ 개** (기하급수적 폭증) |
| 키 배송 문제 | 해결 (공개키는 공개 채널로 배포) | 미해결 (사전 비밀 공유 경로 필요) |
| 제공 기능 | 기밀성, 전자서명, 부인방지, 키 교환 | 기밀성, 무결성(AEAD) |
| 주 용도 | TLS 키 교환, 인증서, 블록체인 서명 | 대용량 DB 암호화, 파일/디스크 암호화 |

### 2. 주요 비대칭키 암호 알고리즘 분류

| 구분 | RSA | 타원곡선 암호 (ECC) | 디피-헬만 (DH) | 격자 기반 PQC (ML-KEM) |
|---|---|---|---|---|
| 기반 난제 | 큰 합성수의 소인수분해 | 타원곡선 이산대수 (ECDLP) | 유한체 이산대수 (DLP) | 모듈 격자 상의 오류 학습 (MLWE) |
| 키 크기 (128bit 보안)| 3072 비트 | **256 비트** | 3072 비트 | 공개키 약 1184 바이트 |
| 특징 | 표준화 역사 오래됨, 검증됨 | 소형 키, 고속 연산, 저전력 | 키 교환 전용 알고리즘 | **양자컴퓨터 쇼어 알고리즘 내성** |
| 대표 표준 | PKCS#1, FIPS 186-5 | secp256r1, Ed25519 | RFC 3526, RFC 7919 | FIPS 203 (Kyber) |

## Ⅴ. 비대칭키 암호화의 한계와 방안

| 한계 | 방안 |
|---|---|
| 공개키가 공개 채널로 전달될 때 중간자 공격(MitM)에 의해 공격자의 가짜 공개키로 바꿔치기 당할 위험 | 공인인증기관(CA)이 소유자 신원과 공개키를 바인딩하여 서명한 X.509 공개키기반구조(PKI) 체계 수립 |
| 복잡한 고차원 수학 연산(모듈러 지수 연산)으로 인해 대용량 멀티미디어 및 데이터베이스 암호화 시 심각한 CPU 병목 | 실제 대용량 데이터는 AES 대칭키로 암호화하고, 해당 대칭키만 수신자 공개키로 암호화하는 하이브리드 암호화(Hybrid Encryption) 적용 |
| 대규모 범용 양자컴퓨터의 쇼어(Shor) 알고리즘 구동 시 소인수분해(RSA)와 이산대수(ECC) 기반 암호가 다항 시간 내에 완전 붕괴 | 미국 NIST가 표준화한 격자 기반 양자내성 암호(ML-KEM, ML-DSA)를 도입하고 기존 공개키와 PQC를 결합한 하이브리드 암호 민첩성(Crypto-Agility) 구축 |

## Ⅵ. 제언

```text
[ 전통적 공개키 암호 환경 ]           [ 양자 내성 하이브리드 암호 거버넌스 ]
RSA / ECC 단독 의존 ──┐               ┌── 하이브리드 키 교환 (X25519 + ML-KEM)
대용량 연산 지연 ─────┼─→ [ 양자 붕괴 ] ─┼── 하이브리드 전자서명 (Ed25519 + ML-DSA)
양자 쇼어 공격 무방비 ┘               └── X.509 PKI 인증서 체인 PQC 확장 표준화
```

| 평가 영역 | RSA 암호 체계 | ECC 암호 체계 | PQC 양자내성 체계 |
|---|---|---|---|
| 키 효율성 | 매우 낮음 (3072bit+) | 최고 수준 (256bit) | 중간 수준 (KB 단위 키) |
| 연산 속도 | 서명 느림, 검증 빠름 | 균형적 고속 처리 | 소프트웨어 벡터 가속(AVX2) 최적화 |
| 미래 안전성 | 양자컴퓨터에 즉시 해독 | 양자컴퓨터에 즉시 해독 | 쇼어 및 그로버 알고리즘 동시 방어 |

비대칭키 암호화는 전자상거래와 디지털 인증의 근간을 이룬 혁신적 기저 기술이며, 포스트 퀀텀 시대에 대응하기 위해 격자 기반 PQC 표준으로의 전환과 암호 민첩성(Crypto-Agility) 확보가 필수적 과제.
