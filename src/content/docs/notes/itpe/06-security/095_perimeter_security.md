## 연관 키워드

- 경계 기반 보안, Perimeter Security, 제로트러스트, ZTA, ZTNA, 마이크로세그멘테이션
- 정책 결정점, 정책 집행점, CARTA, UEBA, 역방향 프록시, 점프 호스트, SASE, eBPF

## Ⅰ. 경계 기반 보안(Perimeter Security)의 개요

- 핵심 요약 : 내부망과 외부망의 경계에 방화벽과 VPN을 세워 외부 위협의 진입을 막는 전통적 보안 접근법.
- 개념 : 외부 인터넷과 사내망의 경계 지점에 방화벽, 침입방지시스템(IPS, Intrusion Prevention System), VPN(Virtual Private Network)을 배치해 외부 위협의 진입을 통제하는 **경계 기반 보안** (Perimeter Security, 내부망을 신뢰하고 경계에서 위협을 차단하는 접근법).
- 배경 및 필요성 : 신뢰하는 내부망과 신뢰하지 않는 외부망을 나누는 모델로 오랫동안 쓰였으나, 클라우드와 원격근무가 확산되면서 내부와 외부의 경계가 흐려져 **제로트러스트 아키텍처** (ZTA, Zero Trust Architecture, 네트워크 위치와 무관하게 모든 접근을 검증하는 보안 모델)로 발전하는 중임.
- 주요 목적 : 경계 지점에서 트래픽을 중앙 집중 검사하고, 비무장지대(DMZ, Demilitarized Zone) 같은 구역으로 내부 자산을 물리적·논리적으로 보호하는 것.

## Ⅱ. 경계 기반 보안(Perimeter Security)의 특징 및 장점

- 핵심 요약 : 중앙 집중 통제와 네트워크 구획이라는 단순한 구조가 관리의 명확성과 도입 용이성을 제공함.

1. 중앙 집중 검사 : 모든 외부 트래픽을 한 지점에서 검사하고 기록 → 정책 적용과 감사가 단일 지점에서 이루어져 관리가 쉬움.
2. 네트워크 구획 : 내부망을 구역으로 나누고 DMZ에 노출 서버를 격리 → 외부에서 내부 자산에 직접 접근할 수 있는 면적이 줄어듦.
3. 운영 단순성 : 경계 장비 중심의 정책으로 구조가 직관적 → 익숙한 모델이라 초기 도입 부담과 학습 비용이 낮음.

## Ⅲ. 경계 기반 보안(Perimeter Security)의 구조 (흐름)

- 핵심 요약 : 경계 모델은 한 번의 관문 통과로 내부를 신뢰하는 구조이고, 제로트러스트는 매 요청마다 정책 결정점이 판단하는 구조임.

```text
[ 1. 경계 기반 모델 (Castle-and-Moat) ]

외부 인터넷
              ↓
방화벽 / VPN 게이트웨이 (1회 인증)
              ↓
내부 사내망 (내부 트래픽 신뢰)
   ├─ 업무용 PC
   ├─ 파일 서버
   └─ 코어 데이터베이스
```

```text
[ 2. 제로트러스트 모델 ]

사용자·단말
              ↓
정책 결정점 (PDP, Policy Decision Point)
  ← 신원, 기기 상태, 위협 정보 평가
              ↓
정책 집행점 (PEP, Policy Enforcement Point)
              ↓
애플리케이션별 최소 권한 연결
```

1. 신원 (Identity) : 1회성 VPN 로그인에서 피싱 저항성 다단계 인증(FIDO2)과 위험 기반 연속 인증(CARTA, Continuous Adaptive Risk and Trust Assessment)으로 전환.
2. 기기 (Device) : 자산 등록 여부와 EDR 기반 무결성 상태를 접속 시점마다 평가.
3. **마이크로세그멘테이션** (Microsegmentation, 워크로드 사이의 통신을 세밀하게 나눠 허용된 흐름만 통과시키는 기법) : 내부 서버 사이를 개별 정책으로 격리.
4. 워크로드 (Workload) : 서비스 메시의 상호 TLS(mTLS, mutual TLS)로 서비스 간 신원을 확인.
5. 데이터 (Data) : 데이터 분류에 따른 암호화와 DLP(Data Loss Prevention) 적용으로 데이터 자체에 통제를 부여.

## Ⅳ. 경계 기반 보안과 제로트러스트 보안의 비교

- 핵심 요약 : 신뢰의 기준을 네트워크 위치에서 신원과 기기 상태로 옮긴 것이 두 모델의 가장 큰 차이임.

| 비교 항목 | 경계 기반 보안 | 제로트러스트 보안 |
| --- | --- | --- |
| 기본 철학 | 신뢰하되 검증한다 | 절대 신뢰하지 않고 항상 검증한다 |
| 신뢰의 기준 | 내부망이라는 물리적 위치 | 검증된 신원, 기기 무결성, 요청 맥락 |
| 주요 검사 방향 | 북-남(North-South) 트래픽 중심 검사 | 동-서(East-West) 트래픽까지 검사와 격리 |
| 원격 접속 기술 | VPN으로 내부 대역 전체에 접근 | 제로트러스트 네트워크 접근(ZTNA, Zero Trust Network Access)으로 허가된 애플리케이션만 연결 |
| 측면 이동 내성 | 내부 진입 후 다른 호스트로 자유롭게 이동 | 마이크로세그멘테이션으로 호스트 간 이동 차단 |
| 클라우드 적합성 | 트래픽을 본사로 우회시켜 병목 발생 | 분산 클라우드 환경에 적합 |

## Ⅴ. 경계 기반 보안(Perimeter Security)의 한계와 방안

- 핵심 요약 : 원격 트래픽 집중, 내부 횡적 통신 무통제, 탈취된 자격증명, 레거시 시스템의 에이전트 부재를 클라우드 엣지, 호스트 격리, 행위 분석, 중계 접근으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 원격 근무 트래픽 집중 | VPN 장비로 트래픽이 몰려 대역폭 병목과 가용성 저하 발생 | 사용자와 가까운 지점에서 검사하는 보안 서비스 엣지(SSE, Security Service Edge)와 보안 접근 서비스 엣지(SASE, Secure Access Service Edge) 도입 | 원격 접속 지연 시간 |
| 내부 횡적 통신 무통제 | 경계 통과 후 내부 호스트 간 접근 통제와 모니터링 부재 | 호스트 방화벽과 eBPF(Extended Berkeley Packet Filter) 기반 마이크로세그멘테이션 솔루션(예: Cilium)으로 프로세스 단위 통신 제한 | 차단된 횡적 통신 건수 |
| 탈취된 자격증명의 정상 행세 | 정상 계정으로 접속하면 경계 장비가 악의를 구분하지 못함 | **사용자 및 엔티티 행위 분석** (UEBA, User and Entity Behavior Analytics)으로 평소와 다른 자원 접근, 대량 다운로드를 탐지해 세션 강제 종료 | 이상 행위 탐지 건수 |
| 레거시 시스템의 에이전트 설치 불가 | 구형 프로토콜 기간계 시스템에 ZTNA 에이전트를 설치할 수 없음 | 레거시 자산 앞에 역방향 프록시(Reverse Proxy)나 점프 호스트(Bastion)를 배치하고, 시간 제한 단기 토큰으로 접근 중계 | 점프 호스트 경유 접속 비율 |

## Ⅵ. 경계 기반 보안(Perimeter Security)에 대한 기술사적 제언

- 핵심 요약 : 제로트러스트로의 이행을 단계별 로드맵으로 관리하되, 신원과 행위를 공통 기준으로 삼아야 함.

1. 단계적 전환 : 관리자 계정에 피싱 저항성 다단계 인증을 먼저 적용하고 인터넷 접점 장비의 취약점을 정비한 뒤, 업무 중요도 순으로 ZTNA 전환을 진행하는 로드맵 필요.
2. 내부 분할 : 핵심 데이터베이스와 서버 자원부터 마이크로세그멘테이션을 완성하여, 침해가 발생해도 피해 범위를 단일 노드로 줄이는 설계 필요.
3. 신원 중심 운영 : 신원, 기기, 행위 신호를 정책 결정점으로 모아 경계 장비와 클라우드 접근 정책을 하나의 기준으로 관리하는 조직 체계 필요.

## Ⅶ. 결론

- 핵심 요약 : 경계 기반 보안은 제로트러스트로 이행하는 출발점이자 여전히 필요한 기본 통제임.
- 시사점 : 경계를 없애는 것보다 신뢰의 기준을 네트워크 위치에서 신원과 기기 상태로 옮기는 전환이 핵심 과제임.
