## 연관 키워드

- 인포스틸러(Infostealer), 세션 쿠키, 쿠키 주입, 말버타이징(Malvertising), DPAPI
- 초기 침투 브로커(IAB), 다크웹 마켓, MFA, 자격증명 탈취, 조건부 접근
- DPoP, EDR, ZTNA, 토큰 바인딩

## Ⅰ. 인포스틸러(Infostealer)의 개요

- 핵심 요약 : 인증이 끝난 세션 정보까지 훔쳐 다중 인증을 무력화하는 정보 탈취 악성코드군.
- 개념 : 감염된 단말의 웹 브라우저, 암호화폐 지갑, 메신저, VPN(Virtual Private Network) 클라이언트에 저장된 **계정 자격증명** (ID, PW), **세션 쿠키** (Session Cookie), 자동완성 데이터를 훔쳐 공격자의 C2(Command and Control) 서버로 보내는 악성코드군.
- 배경 및 필요성 : **다중 인증** (MFA, Multi-Factor Authentication)이 확산되자, 공격자는 로그인 시점의 2차 인증을 피해 이미 인증을 통과한 세션 쿠키를 탈취하는 방식으로 옮겨 갔고, 이에 맞춰 인포스틸러가 대량으로 유포되었다.
- 핵심 목적 : 탈취한 자격증명과 세션 쿠키를 다크웹 마켓에서 판매하거나, 기업 내부망 침투의 발판으로 활용하는 것.

## Ⅱ. 인포스틸러(Infostealer)의 특징 및 장점

- 핵심 요약 : 세션 쿠키 탈취, 일괄 자격증명 수집, 유통 분업, 탐지 회피가 결합되어 공격 효과와 규모를 키우는 특징.

1. 세션 쿠키 탈취 : 인증 이후의 세션 정보를 복사 → MFA 단계를 건너뛰어 정상 사용자로 접속.
2. 자격증명 일괄 수집 : 브라우저에 저장된 비밀번호를 OS 보호 키로 복호화 → 한 대의 감염으로 여러 계정이 동시에 노출.
3. 유통 분업 : 탈취 로그를 판매하고 **초기 침투 브로커** (IAB, Initial Access Broker)가 침투를 맡음 → 탈취자와 침투자가 분리되어 공격 규모 확대.
4. 탐지 회피 : 메모리에서 실행되고 난독화와 패커를 적용해 시그니처 탐지를 피함 → 백신 탐지 이전에 정보 유출 완료.

유포는 불법 크랙 소프트웨어, 피싱 메일, 검색 광고 악용 같은 경로로 이뤄지며, 말버타이징(Malvertising, 악성 광고)이 대표 경로다.

## Ⅲ. 인포스틸러(Infostealer)의 구조 (흐름)

- 핵심 요약 : 감염, 수집, 전송, 유통, 악용이 이어지는 탈취 흐름과, 세션 쿠키를 주입해 MFA를 건너뛰는 악용 구조.

```text
[ 인포스틸러 탈취와 유통 흐름 ]

(1) 감염 : 불법 크랙, 피싱, 말버타이징
          ↓
(2) 수집 : 브라우저 저장 ID·PW와 세션
          쿠키, 지갑 정보를 메모리에서 수집
          ↓
(3) 전송 : 압축 후 C2 서버로 암호화 전송
          ↓
(4) 유통 : 로그 패키지를 다크웹 마켓에 판매
          ↓
(5) 악용 : 구매자가 쿠키를 주입해 기업
          클라우드 서비스에 MFA 없이 로그인
```

```text
[ 세션 쿠키 탈취와 MFA 우회 ]

정상 로그인 (ID·PW + MFA 통과)
          ↓
세션 쿠키 발급 (인증 상태 보관)
          ↓
인포스틸러가 세션 쿠키 탈취
          ↓
공격자가 쿠키를 자신의 브라우저에 주입
          ↓
MFA 요구 없이 인증된 세션 유지
```

- **DPAPI** (Data Protection API) 복호화 : 크로미움 기반 브라우저가 사용자 자격증명으로 보호하는 마스터 키를 메모리에서 얻어, 저장된 비밀번호와 쿠키를 평문으로 복호화.
- **쿠키 주입** (Cookie Injection) : 비밀번호를 몰라도 탈취한 세션 쿠키를 브라우저에 넣으면 MFA를 거치지 않고 정상 사용자로 세션을 장악.
- 초기 침투 브로커 : 탈취 로그를 구매해 기업 내부망 접근권을 판매하는 중간 역할로, 이후 랜섬웨어 조직에 연결되는 범죄 분업의 한 축.
- 주요 패밀리 : RedLine Stealer, Vidar, Raccoon, Lumma Stealer 등이 알려져 있으며, 지속적인 난독화로 시그니처 탐지를 회피.

## Ⅳ. 인포스틸러와 인접 악성코드의 비교

- 핵심 요약 : 인포스틸러는 인증 이후의 세션 정보를 노린다는 점에서, 입력 키를 노리는 키로거나 원격 제어형 RAT, 행위 추적형 스파이웨어와 구분됨.

| 비교 항목 | 인포스틸러 (Infostealer) | 키로거 (Keylogger) | 원격 접근 트로이목마 (RAT, Remote Access Trojan) | 스파이웨어 (Spyware) |
| --- | --- | --- | --- | --- |
| 수집 대상 | 브라우저 저장 암호, 세션 쿠키, 지갑 정보 | 실시간 키보드 입력 | 원격 쉘, 화면 캡처, 시스템 제어권 | 웹 이용 이력, 개인 행위 정보 |
| MFA 우회 | 가능 (유효한 세션 쿠키 탈취) | 제한적 (일회용 OTP(One-Time Password)는 만료) | 가능 (원격 조작으로 직접 사용) | 직접 우회는 어려움 |
| 실행 방식 | 탈취 후 전송하고 종료하거나 대기 | 상주하며 입력을 후킹 | 백도어 연결을 상시 유지 | 백그라운드에 은닉 실행 |
| 주요 유포 | 검색 광고, 크랙 파일 | 피싱 메일 첨부 문서 | 취약점 공격, 공급망 공격 | 번들 프로그램 설치 |
| 주된 목적 | 자격증명과 쿠키의 판매 | 타깃 계정 탈취 | 랜섬웨어 유포와 내부망 침투 | 프로파일링과 광고 수익 |

- 선택 기준 : 공격자가 인증 정보 자체를 원하는지, 단말을 원격 제어하려는지, 행위 데이터를 원하는지에 따라 대응 솔루션을 나눠 적용.

## Ⅴ. 인포스틸러의 한계와 방안

- 핵심 요약 : 정상처럼 보이는 세션 악용, 브라우저 비밀번호 저장, 검색 광고 유포를 토큰 바인딩, 단말 정책, 도메인 차단으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 정상 세션 쿠키 악용의 서버 측 탐지 곤란 | 훔친 쿠키 요청은 인증된 정상 HTTP(Hypertext Transfer Protocol) 세션과 구분되지 않아 WAF(Web Application Firewall)와 방화벽을 통과 | OAuth 접근 토큰에 DPoP(Demonstrating Proof-of-Possession, RFC 9449)를 적용해 키 소유를 검증. 세션 쿠키는 DPoP 대상이 아니므로 단말 신뢰와 세션 수명 단축으로 별도 보완 | 비정상 세션 재사용 탐지 건수 |
| 브라우저 비밀번호 저장 관행 | 업무 계정 비밀번호가 단일 SQLite 파일에 저장되어 한 번의 감염으로 다수 계정이 노출 | GPO(Group Policy Object)와 MDM(Mobile Device Management)으로 전사 브라우저의 비밀번호 저장 기능 비활성화 | 저장 비밀번호 보유 단말 비율 |
| 검색 광고를 악용한 말버타이징 | 정상 업무 소프트웨어를 검색할 때 유료 광고가 가짜 다운로드 사이트로 유도 | DoH(DNS over HTTPS) 기반 보안 DNS로 타이포스쿼팅 도메인 차단, 말버타이징 모의 훈련 | 차단된 가짜 도메인 건수, 훈련 클릭률 |

## Ⅵ. 인포스틸러에 대한 기술사적 제언

- 핵심 요약 : 유출 감시, 단말 행위 감시, 단말 신뢰 기반 접근 통제를 결합해 탈취된 세션이 쓰이지 못하도록 하는 다층 체계로 정착.

1. 보안 조직은 다크웹 마켓과 텔레그램 유출 채널을 상시 살펴보는 위협 인텔리전스(Threat Intelligence)를 도입하고, 사내 계정이나 세션 정보가 발견되면 비밀번호 재설정과 활성 세션 종료를 즉시 실행해야 한다.
2. 엔드포인트 조직은 EDR(Endpoint Detection and Response)로 브라우저 저장 파일에 비인가 프로세스가 접근하는 행위를 감시하고, 이상 행위가 확인되면 해당 프로세스를 즉시 격리하도록 정책을 구성하는 것이 바람직하다.
3. 접근 통제 조직은 조건부 접근 정책에 디바이스 식별자 검증을 결합하여, 탈취된 쿠키가 있더라도 등록된 단말이 아니면 사내 시스템 접속을 거부하는 ZTNA(Zero Trust Network Access) 구조를 도입해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 인포스틸러는 다중 인증을 통과한 뒤의 세션 쿠키를 훔쳐 인증 자체를 무력화하는 악성코드군.
- 시사점 : 2차 인증만으로는 방어가 부족하므로, 세션을 단말에 묶는 토큰 바인딩과 단말 신뢰 검증이 함께 전제되어야 한다.
