## Ⅰ. CI/CD의 개요

- **개념** : 개발자가 작성한 소스코드를 공유 저장소에 빈번하게 병합하고(지속적 통합, CI), 빌드와 자동화 테스트를 거쳐 검증된 아티팩트를 스테이징 및 프로덕션 환경에 안전하고 신뢰성 있게 배포하는(지속적 전달/배포, CD) 현대 소프트웨어 공학의 핵심 자동화 파이프라인.
- **배경 및 필요성** : 개발 후반부에 발생하는 대규모 병합 지옥(Merge Hell)을 방지하고, 수작업 배포에 따른 인적 오류(배포 사고)를 근절하여 비즈니스 가치를 사용자에게 신속하게 전달.
- **핵심 구분** : CI(지속적 통합), CDelivery(수동 승인 배포), CDeployment(프로덕션 무인 자동 배포).

## Ⅱ. 엔드투엔드 CI/CD 파이프라인 흐름도

```text
   [ Git Commit / PR ]
            │
            ▼
   ┌────────────────────────────────────────────────────────┐
   │ [ 1. CI 단계: 빌드 및 품질 검증 ]                     │
   │  - 의존성 다운로드 및 바이너리 컴파일                  │
   │  - 단위 테스트 및 통합 테스트 자동 실행 (JaCoCo)       │
   │  - 정적 코드 분석 및 보안 점검 (SonarQube, Snyk)       │
   │  - 통과 시 컨테이너 이미지 빌드 및 태깅                │
   └────────┬───────────────────────────────────────────────┘
            │
            ▼
   [ Artifact Registry ] ──> 도커 이미지 저장 (Harbor, ECR)
            │
            ▼
   ┌────────────────────────────────────────────────────────┐
   │ [ 2. CD 단계: 배포 및 오케스트레이션 ]                 │
   │  - GitOps 컨트롤러(ArgoCD) 매니페스트 동기화          │
   │  - 스테이징 환경 배포 및 E2E 자동 테스트 수행          │
   │  - 프로덕션 무중단 배포 (Canary / Blue-Green)          │
   │  - Prometheus 메트릭 이상 감지 시 자동 롤백           │
   └────────────────────────────────────────────────────────┘
```

- **Trunk-Based Development** : 장기 실행 브랜치를 없애고 모든 개발자가 매일 메인 트렁크로 코드를 병합하여 통합 충돌 최소화.
- **GitOps 모델 (ArgoCD)** : Git 저장소를 시스템의 단일 진실 공급원(Single Source of Truth)으로 삼아 클러스터 상태를 선언적 매니페스트와 일치시킴.

## Ⅲ. 지속적 전달(Continuous Delivery)과 지속적 배포(Continuous Deployment)의 비교

| 구분 | 지속적 통합 (CI) | 지속적 전달 (Continuous Delivery) | 지속적 배포 (Continuous Deployment) |
|---|---|---|---|
| 범위 | 코드 커밋부터 빌드, 테스트, 아티팩트 생성 | 프로덕션 배포 직전 단계까지 모든 과정 자동화 | 프로덕션 환경 배포까지 인간 개입 없이 100% 자동화 |
| 프로덕션 배포 승인 | 배포 단계 포함하지 않음 | 비즈니스 담당자나 관리자의 수동 승인(One-Click) | 테스트 통과 즉시 자동으로 실운영 환경 배포 |
| 피드백 속도 | 코드 품질 및 결함 여부 즉각 피드백 | 릴리스 가능한 패키지 항시 대기 | 고객에게 신규 가치 실시간 제공 (분당/시간당) |
| 요구되는 성숙도 | 단위 테스트 및 기본 빌드 파이프라인 | 스테이징 통합 테스트 및 회귀 테스트 자동화 | 완벽한 카나리 배포, 자동 롤백, 정밀 관측성 인프라 |

## Ⅳ. 안정적인 CI/CD 정착을 위한 기술사적 제언

- **시프트 레프트(Shift-Left) 기반 DevSecOps 품질 게이트웨이 내재화** : 빠른 배포 속도로 인해 보안 구멍이 실서버로 유출되지 않도록, CI 단계에서 소스코드 보안약점 진단(SAST), 오픈소스 취약점 점검(SCA), 컨테이너 이미지 보안 스캔(Trivy)을 의무화하고 기준 미달 시 빌드를 차단하는 보안 게이트 구축.
- **선언적 GitOps 및 카나리 점진적 롤아웃(Progressive Delivery)** : ArgoCD와 Argo Rollouts를 결합하여 배포 후 오류율(HTTP 5xx)과 지연시간(Latency)을 프로메테우스 메트릭으로 실시간 분석하고, 이상 징후 발생 시 3초 이내에 자동 롤백되는 안전망 구축 필수.
