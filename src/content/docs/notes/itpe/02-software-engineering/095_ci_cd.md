## 연관 키워드
- CI/CD, 지속적 통합, 지속적 전달, 지속적 배포, 빌드 파이프라인, 자동 검증, 롤백

### Ⅰ. CI/CD의 개요

- 핵심 요약 : CI/CD(Continuous Integration and Continuous Delivery/Deployment)는 변경 사항을 자주 통합하고 자동 빌드·시험·패키징·배포 경로로 검증해 신뢰할 수 있는 소프트웨어 릴리스를 지원하는 실행 관행.
- 개념 : 변경 사항을 자주 통합하고 자동 빌드·시험·패키징·배포 경로로 검증해 신뢰할 수 있는 소프트웨어 릴리스를 지원하는 실행 관행(**CI/CD**, Continuous Integration and Continuous Delivery/Deployment).
- 배경 및 필요성 : 장기 브랜치와 수동 릴리스는 통합 충돌·릴리스 위험을 집중시키고 결함 발견을 늦춤.
- 주요 목적 : 작은 변경을 빠르고 안전하게 사용자에게 전달해 피드백과 제품 가치 실현을 앞당김.

### Ⅱ. CI/CD의 특징 및 장점

- 핵심 요약 : 지속적 통합(CI)·지속적 전달(Continuous Delivery)·지속적 배포(Continuous Deployment)·파이프라인·아티팩트 추적.

1. 지속적 통합(CI) : 잦은 코드 통합과 자동 빌드·시험 → 통합 오류 조기 발견.
2. 지속적 전달(Continuous Delivery) : 검증된 산출물을 언제든 배포 가능 상태로 유지 → 운영자 승인 후 신뢰성 있게 출시.
3. 지속적 배포(Continuous Deployment) : 모든 배포 게이트를 통과한 변경을 자동 운영 배포 → 승인 지연 없는 가치 전달.
4. 파이프라인·아티팩트 추적 : 동일한 산출물을 단계별 승격하고 환경·승인·결과 연결 → 재현성·감사 가능성 확보.

### Ⅲ. CI/CD의 구조 (흐름)

- 핵심 요약 : 코드 변경·리뷰 → 빌드·정적 검사 → 단위·통합 시험 → 보안·정책 게이트 → 아티팩트 저장 → 스테이징 검증 → 전달 승인 또는 자동 배포 → 모니터링·롤백.

```text
코드 변경·리뷰
   ↓
빌드·정적 검사
   ↓
단위·통합 시험
   ↓
보안·정책 게이트
   ↓
아티팩트 저장
   ↓
스테이징 검증
   ↓
전달 승인 또는 자동 배포
   ↓
모니터링·롤백
```

```text
Continuous Integration
변경 → 빌드·시험 → 통합 피드백
                 ↓
Continuous Delivery → 배포 가능 산출물
                 ↓ 승인 여부
Continuous Deployment → 자동 운영 반영
```

### Ⅳ. 지속적 전달과 지속적 배포 비교

- 핵심 요약 : 지속적 전달은 검증 산출물은 언제나 배포 준비, 운영 반영은 승인 가능, 지속적 배포는 조건 통과 시 자동으로 운영 환경 반영.

| 비교 대상 | 핵심 특성 | 적용·판단 기준 |
|---|---|---|
| 지속적 전달 | 검증 산출물은 언제나 배포 준비, 운영 반영은 승인 가능 | 변경 관리·규제 승인 게이트 유지 |
| 지속적 배포 | 조건 통과 시 자동으로 운영 환경 반영 | 자동 검증·관측·롤백이 성숙한 서비스 |
| 수동 릴리스 | 수작업 통합·승인·배포 | 배포 빈도가 낮고 자동화 위험을 수용하는 초기 환경 |

### Ⅴ. CI/CD의 한계와 방안

- 핵심 요약 : 빠른 파이프라인의 낮은 검증력·환경별 산출물 차이·복구·승인 준비 부족을 위험 기반 게이트·불변 아티팩트·기능 플래그로 관리.

| 위험 | 원인·영향 | 대응 통제 | 지표 예시 |
|---|---|---|---|
| 빠른 파이프라인의 낮은 검증력 | 자동 배포가 결함을 빠르게 확산 | 위험 기반 테스트·보안·정책 게이트와 점진 배포 | 변경 실패율, 결함 유출 |
| 환경별 산출물 차이 | 스테이징 검증이 운영 결과를 보장하지 못함 | 불변 아티팩트 승격·환경 구성 관리 | 산출물 해시 일치, 환경 드리프트 |
| 복구·승인 준비 부족 | 오류 배포가 장시간 고객 영향 | 기능 플래그·롤백·중단 권한·온콜 체계 | MTTR, 롤백 성공률 |

### Ⅵ. CI/CD 적용에 대한 기술사적 제언

- 핵심 요약 : 작은 변경을 빠르고 안전하게 사용자에게 전달해 피드백과 제품 가치 실현을 앞당김.

- 실행 제언 : 플랫폼·제품 팀은 CI와 CD를 단순 도구 설치가 아니라 개발·보안·운영의 공동 책임으로 설계하고, 지속적 전달과 자동 배포의 승인·위험 수준을 서비스별로 구분.

### Ⅶ. 결론

- 핵심 요약 : CI/CD(Continuous Integration and Continuous Delivery/Deployment)는 변경 사항을 자주 통합하고 자동 빌드·시험·패키징·배포 경로로 검증해 신뢰할 수 있는 소프트웨어 릴리스를 지원하는 실행 관행.
- 시사점 : CI/CD는 작고 검증된 변경을 지속적으로 통합·전달하는 소프트웨어 공급 체계로, 자동화 속도보다 안전한 피드백과 복구 역량이 핵심.
