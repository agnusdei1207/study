## 한 줄 본질
- 웹 브라우저를 단순 하이퍼텍스트 뷰어에서 ActiveX·Flash가 필요 없는 독립적인 범용 애플리케이션 런타임 플랫폼으로 도약시킨 개방형 웹 표준 / 플러그인 종속 탈피와 시맨틱 정보 구조화

## 핵심 용어
- 시맨틱 태그(Semantic Tags): 브라우저와 검색엔진, 스크린 리더에게 문서 구조의 의미를 명확히 전달하는 전용 마크업 요소 (`<header>`, `<nav>`, `<aside>`, `<footer>` 등)
- 캔버스(Canvas): 자바스크립트를 이용하여 픽셀 단위로 2D 및 3D 동적 그래픽을 프로그래밍 방식으로 렌더링하는 비트맵 영역
- 웹 소켓(WebSocket): 클라이언트와 서버 간에 단일 TCP 연결을 유지하며 지연 없이 양방향 전이중(Full-Duplex) 통신을 가능하게 하는 프로토콜
- 웹 스토리지(Web Storage): 클라이언트 브라우저에 키-값 쌍으로 데이터를 영구(LocalStorage) 또는 세션(SessionStorage) 동안 저장하는 5MB 내외의 고속 저장소
- 웹 워커(Web Worker): 브라우저의 메인 UI 렌더링 스레드를 차단하지 않고 백그라운드에서 무거운 연산 작업을 별도 스레드로 병렬 처리하는 API

## 핵심 통찰
- HTML5의 등장은 웹 생태계를 종속시키던 마이크로소프트의 ActiveX, 어도비의 Flash와 같은 폐쇄적 서드파티 바이너리 플러그인을 완전히 종식시켰음
- 단순 마크업 문서를 넘어서서 데스크톱/모바일 네이티브 앱과 대등한 수준의 기능을 브라우저 샌드박스 내부에서 수행할 수 있는 '애플리케이션 플랫폼'으로 진화함
- 반응형 웹(Responsive Web) 및 CSS3 미디어 쿼리와 결합하여 모바일, 태블릿, PC를 아우르는 원소스 멀티유즈(OSMU) 표준 개발의 기반이 됨

## 이웃 토픽과 구분
| 비교 항목 | HTML4 | XHTML 1.0 | HTML5 |
| :--- | :--- | :--- | :--- |
| **문법 엄격성** | 느슨함 (태그 미닫힘 허용) | 극도로 엄격함 (XML 문법 준수 강제) | 유연한 문법 지원 (실용주의 채택) |
| **플러그인 의존성** | 멀티미디어 재생 시 플러그인 필수 | 플러그인 필수 | 네이티브 지원 (플러그인 프리) |
| **의미 구조화** | 단순 `<div>`, `<span>` 남용 | `<div>` 중심 구조화 | 시맨틱 전용 태그 제공 |
| **클라이언트 스토리지** | 쿠키 (Cookie, 4KB 한계) | 쿠키 | LocalStorage, IndexedDB (수십 MB~GB) |
| **실시간 통신** | 폴링(Polling) 방식 의존 | 폴링 방식 | WebSocket, SSE 네이티브 지원 |

## 문제·원인·대책
| 문제상황 | 원인 | 기술적 대책 |
| :--- | :--- | :--- |
| **브라우저 버전별 지원 차이로 렌더링 왜곡** | 구형 브라우저 엔진 간의 HTML5 API 미지원 및 구현 차이 | Modernizr를 통한 기능 감지(Feature Detection) 및 폴리필(Polyfill) 스크립트 주입 |
| **LocalStorage 내 중요 정보 탈취 위험** | 스토리지에 암호화되지 않은 토큰/개인정보 저장 시 XSS 공격에 무방비 노출 | 민감 세션 토큰은 HttpOnly Cookie에 보관하고 CSP(콘텐츠 보안 정책) 헤더 적용 |
| **복잡한 캔버스 연산 시 화면 버벅임** | 메인 스레드에서 대량의 그래픽 연산과 DOM 처리를 동시 수행하여 프레임 드랍 발생 | OffscreenCanvas 및 Web Worker를 활용한 렌더링 연산 백그라운드 분리 |

## 내 의견
- HTML5는 현대 웹 프론트엔드 생태계(React, Vue, Next.js)를 가능하게 만든 만국 공통의 인프라 표준임
- 최근 웹 프론트엔드는 HTML5의 API 스펙을 기반으로 프로그레시브 웹 앱(PWA, Progressive Web Apps)과 결합하여 앱스토어 설치 없이도 오프라인 캐싱과 푸시 알림을 제공하는 방향으로 진화하고 있음
- 나아가 고성능 연산이 요구되는 CAD, 3D 렌더링, 인공지능 추론 영역에서는 HTML5 Canvas/WebGL과 WebAssembly(Wasm)를 결합하여 C++/Rust 코드를 브라우저에서 직접 실행하는 하이퍼 퍼포먼스 웹 환경을 구축해야 함
