## Ⅰ. HTML5의 개요

- 개념 : **HTML5** (HyperText Markup Language 5)는 시맨틱 요소, 멀티미디어와 웹 애플리케이션 기능을 확장한 HTML 표준의 역사적 버전. 현재 HTML은 WHATWG(Web Hypertext Application Technology Working Group)의 Living Standard로 발전하며, W3C(World Wide Web Consortium)의 관련 웹 표준과 함께 사용.
- 배경 및 필요성 : 비표준 플러그인의 보안 취약점과 모바일 기기(iOS, Android) 호환 불가 문제를 해결하고, **시맨틱 웹** (Semantic Web) 구현 및 크로스 플랫폼 웹 앱 표준 확립.
- 주요 기술 영역 : 시맨틱 태그, 멀티미디어 네이티브 지원, 2D/3D 그래픽스, 클라이언트 웹 스토리지, 실시간 통신 웹 API(Application Programming Interface). IndexedDB, WebGL, WebRTC 등은 HTML 문서 문법과 구분되는 별도 웹 표준 기술.

## Ⅱ. HTML5 핵심 기능 아키텍처 및 주요 기술 스택

```text
   ┌────────────────────────────────────────────────────────────────────────┐
   │ [ 차세대 웹 애플리케이션 플랫폼: HTML5 ]                               │
   │                                                                        │
   │  [ 1. 시맨틱 마크업 ] ── <header>, <nav>, <main>, <article>, <footer> │
   │  [ 2. 멀티미디어 ]   ── <audio>, <video> (코덱 네이티브 스트리밍)      │
   │  [ 3. 고성능 그래픽 ] ── <canvas> (2D/3D WebGL), SVG 벡터 그래픽       │
   │  [ 4. 오프라인 & 저장] ── localStorage, sessionStorage, IndexedDB       │
   │  [ 5. 차세대 통신 API] ── WebSocket (전이중 양방향), WebRTC (P2P 실시간)│
   │  [ 6. 백그라운드 처리] ── Web Workers (멀티스레드), Service Worker     │
   └────────────────────────────────────────────────────────────────────────┘
```

- **시맨틱 태그** (Semantic Tags) : `<div id="header">` 대신 `<header>`, `<nav>`, `<section>`, `<article>`, `<aside>`, `<footer>`를 사용하여 검색엔진(SEO, Search Engine Optimization)과 스크린 리더(웹 접근성)가 문서의 논리적 의미를 정확히 파악하도록 지원.
- **웹 스토리지** (Web Storage) : 키-값 문자열을 클라이언트에 보관하고 쿠키와 달리 HTTP(Hypertext Transfer Protocol) 요청에 자동 첨부하지 않는 저장 기능. 용량·삭제 정책은 브라우저와 저장 모드에 따라 달라지며, 한도 초과 시 QuotaExceededError 처리 필요.

## Ⅲ. 클라이언트 측 웹 저장소 기술 비교

| 비교 항목 | 쿠키 (Cookie) | 로컬 스토리지 (localStorage) | 세션 스토리지 (sessionStorage) | IndexedDB |
|---|---|---|---|---|
| 저장 용량 | 쿠키별 브라우저 제한 적용 | 브라우저·환경별 한도 적용 | 브라우저·환경별 한도 적용 | 디스크·브라우저 정책별 할당량 적용 |
| 수명 (Lifetime) | 세션 또는 만료 시점까지, 사용자·브라우저 삭제 가능 | 세션 간 유지, 영구 보존 보장 없음 | 페이지 세션 기준, 새로고침 시 유지·복원 정책 고려 | 지속 저장 가능, 정책상 축출·사용자 삭제 고려 |
| 서버 전송 여부 | 도메인·경로·보안 속성 등 조건에 맞는 요청에 자동 첨부 | 자동 첨부 없음 | 자동 첨부 없음 | 자동 첨부 없음 |
| 데이터 타입 | 문자열 (String) | 문자열 (String) | 문자열 (String) | 자바스크립트 객체 (트랜잭션 NoSQL(Not Only SQL)) |
| 주 활용 분야 | 세션 ID(Identifier), 자동로그인 토큰 | 사용자 테마(다크모드), 캐시 설정 | 1회성 결제 입력 폼, 일시적 상태 | 대용량 오프라인 데이터, 복합 쿼리 캐시 |

## Ⅳ. HTML5의 주요 한계점 및 해결 방안

- 브라우저 벤더별 API 지원 편차 및 크로스 브라우징 파편화 :
  - 한계점 : 웹소켓, 웹워커, 미디어 레코더 등 고급 HTML5 API의 구현 스펙과 성능이 브라우저 엔진(Blink, WebKit, Gecko)마다 상이하여 오작동 발생.
  - 해결 방안 : Babel/core-js 기반 **폴리필** (Polyfill) 자동 주입, Modernizr를 통한 **기능 감지** (Feature Detection) 및 **점진적 향상** (Progressive Enhancement) 기법 적용.
- **클라이언트 스토리지** (LocalStorage/IndexedDB)의 보안 취약성 :
  - 한계점 : 브라우저 저장소는 JavaScript 코드로 접근 가능하므로, XSS(Cross-Site Scripting) 공격 성공 시 저장된 인증 토큰(JWT, JSON Web Token) 및 민감 정보가 즉각 탈취됨.
  - 해결 방안 : 세션 설계에 맞춰 `HttpOnly`, `Secure`, `SameSite` 쿠키와 요청 위조 방어 적용. 출력 인코딩 및 CSP(Content Security Policy)로 스크립트 주입을 억제하고 민감 데이터의 클라이언트 저장 최소화. Web Crypto API 암호화도 실행 중인 악성 스크립트의 복호화 호출·평문 접근을 자동 차단하지 않음.
- 웹 기반 대용량 멀티미디어/그래픽 처리 시 메모리 누수 :
  - 한계점 : `<canvas>` 2D/WebGL 및 Web Audio 객체를 반복 생성하고 명시적으로 해제하지 않을 경우 브라우저 탭 메모리가 급증하여 크래시 발생.
  - 해결 방안 : 캔버스 컨텍스트 정리 및 텍스처 명시적 해제(`gl.deleteTexture()`), WeakMap 기반 객체 생명주기 관리 및 성능 프로파일링 정례화.

## Ⅴ. 현대 웹 엔지니어링 관점의 기술사적 제언

- **웹 워커** (Web Worker)를 통한 브라우저 메인 스레드 렌더링 블로킹 완화 : 고해상도 이미지 처리, 암호화, 대용량 JSON(JavaScript Object Notation) 파싱 등 CPU(Central Processing Unit) 연산을 별도 스레드로 격리하고, 데이터 전달 비용과 메인 UI(User Interface) 스레드 작업량을 함께 측정하여 반응성 확보.
- **웹소켓** (WebSocket) 및 WebRTC(Web Real-Time Communication) 기반 실시간 협업 : 통신 방식별 지연·연결 유지 비용을 평가하고 서비스 목적에 맞게 적용.
- 참고 : [WHATWG HTML](https://html.spec.whatwg.org/), [Web Storage](https://html.spec.whatwg.org/multipage/webstorage.html), [Storage Standard](https://storage.spec.whatwg.org/), [W3C Web Cryptography API 보안 고려사항](https://www.w3.org/TR/webcrypto/#security-considerations).
