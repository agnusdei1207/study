소프트웨어공학 > 웹 표준 > HTML5

## 30초 인출

- 본질: 액티브X, 플래시 등 비표준 서드파티 플러그인 없이도 멀티미디어 재생, 2D/3D 그래픽, 오프라인 저장소 및 양방향 통신을 네이티브로 지원하는 W3C/WHATWG 차세대 웹 표준 마크업 규격
- 메커니즘: 시맨틱 태그(`<header>`, `<nav>`, `<article>` 등)를 통한 문서 구조화 → 브라우저 파서의 DOM 트리 구축 → 네이티브 웹 API(Canvas, Web Storage, WebSocket 등)와의 연계를 통한 고성능 리치 웹 애플리케이션 구동
- 통찰: 단순 시각적 레이아웃 배치를 위해 `<div>` 태그를 남발할 경우 웹 접근성(A11y)과 검색엔진 최적화(SEO)가 훼손되므로 WAI-ARIA 속성 결합 및 시맨틱 요소 표준 준수 필수

<details>
<summary>핵심 용어</summary>

- **HTML5** : 플러그인 종속을 탈피하고 웹을 리치 애플리케이션 플랫폼으로 변모시킨 웹 표준 마크업 언어이자 웹 API 집합
- **시맨틱 마크업 (Semantic Markup)** : 태그 이름 자체에 콘텐츠의 의미(Header, Nav, Section, Footer 등)를 명확히 부여하여 기계와 보조기술이 문서를 올바르게 해석하도록 돕는 마크업
- **DOM (Document Object Model)** : HTML 문서를 브라우저 렌더링 엔진이 계층적 트리 구조의 객체 모델로 파싱하여 자바스크립트로 동적 제어가 가능하도록 제공하는 인터페이스
- **Canvas / WebGL** : 별도 플러그인 없이 웹 브라우저 내에서 자바스크립트를 이용해 2D 비트맵 그래픽 및 3D 셰이더를 하드웨어 가속으로 직접 렌더링하는 API
- **Web Storage (LocalStorage / SessionStorage)** : 쿠키(Cookie)의 4KB 용량 한계와 네트워크 오버헤드를 극복하기 위해 클라이언트 로컬에 대용량(5~10MB) 키-값 데이터를 보관하는 저장소
</details>

## 2~4교시 예상문제 (25점)

> HTML5의 등장 배경과 핵심 5대 구성요소를 설명하고, 시맨틱 태그(Semantic Tag) 기반의 웹 표준/접근성 향상 방안 및 풍부한 웹 애플리케이션(PWA)으로의 발전 전략을 기술하시오. (25점)

---

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 웹 문서를 구조화하고 표현하는 HTML의 5번째 주요 표준 개정판으로, 플러그인(ActiveX, Flash, Silverlight) 없이 브라우저 자체 기능만으로 풍부한 웹 애플리케이션 구축을 지원하는 마크업 및 API 표준 |
| 목적 | 플랫폼 및 디바이스(PC, 모바일, 태블릿) 독립적인 웹 상호운용성(Interoperability) 확보, 웹 접근성 및 SEO 향상, 강력한 웹 플랫폼 생태계 조성 |

## Ⅱ. 핵심 특징

| 특징 | 세부 내용 |
|---|---|
| 무 플러그인(Plug-in Free) 지향 | `<audio>`, `<video>` 태그를 통해 외부 플러그인 설치 없이 브라우저 네이티브 코덱으로 멀티미디어 스트리밍 지원 |
| 시맨틱 웹(Semantic Web) 구현 | `<header>`, `<nav>`, `<main>`, `<article>`, `<aside>`, `<footer>` 등 의미 중심의 태그를 도입하여 문서 정보 가치 극대화 |
| 디바이스 및 하드웨어 접근성 | Geolocation(위치 정보), Device Orientation(기울기), Camera/Mic(MediaStream) 등 모바일 하드웨어 자원 직접 제어 |
| 오프라인 및 로컬 저장 지원 | Service Worker, Cache API, LocalStorage, IndexedDB를 통해 네트워크 단절 상태에서도 작동하는 웹 구현 |

단순한 하이퍼텍스트 문서 작성 언어에서 범용 애플리케이션 실행 런타임 플랫폼으로 웹을 혁신시킨 기념비적 규격.

## Ⅲ. 체계·프로세스

```text
[HTML5 시맨틱 문서 구조 및 렌더링 체계]

[HTML5 시맨틱 문서 레이아웃]
  ┌────────────────────────────────────────────────────────┐
  │ <header> : 사이트 로고, 글로벌 검색, 유틸리티 메뉴     │
  ├────────────────────────────────────────────────────────┤
  │ <nav>    : 주 메뉴 및 핵심 내비게이션 링크             │
  ├───────────────────────────────┬────────────────────────┤
  │ <main> (주요 비즈니스 콘텐츠) │ <aside>                │
  │   ┌─────────────────────────┐ │  - 사이드바 / 광고     │
  │   │ <section> (주제별 구획) │ │  - 연관 링크 목록      │
  │   │   <article> (독립 기사) │ │                        │
  │   │   <article> (독립 기사) │ │                        │
  │   └─────────────────────────┘ │                        │
  ├───────────────────────────────┴────────────────────────┤
  │ <footer> : 저작권, 약관, 개인정보처리방침, 사업자 정보 │
  └────────────────────────────────────────────────────────┘
       │
       ▼ 브라우저 파서 (HTML Parser)
[DOM 트리 구축 및 렌더링 파이프라인]
  - DOM 생성 ──► WAI-ARIA 트리 결합 ──► 스크린 리더(접근성) & 검색엔진 크롤러 해석
```

시맨틱 요소 기반의 명확한 구조화로부터 브라우저 파싱, WAI-ARIA 접근성 트리 결합, 화면 및 보조기술 서빙으로 이어지는 처리 흐름.

## Ⅳ. 종류·비교

| 비교 항목 | HTML4 / XHTML | HTML5 |
|---|---|---|
| **문서 레이아웃 구성** | `<div>` 태그에 `id/class` 속성 부여 (예: `<div id="header">`) | `<header>`, `<nav>`, `<article>`, `<footer>` 등 시맨틱 전용 태그 기본 제공 |
| **멀티미디어 재생** | Flash, ActiveX, QuickTime 등 외부 플러그인 필수 설치 | `<video>`, `<audio>` 네이티브 태그를 통한 브라우저 직접 렌더링 |
| **그래픽 렌더링** | 외부 플러그인 또는 서버 사이드 이미지 렌더링 의존 | `<canvas>` (2D 비트맵), WebGL (3D), SVG (벡터) 네이티브 지원 |
| **클라이언트 저장소** | 쿠키 (Cookie, 4KB 제한, 요청 시마다 서버 전송 오버헤드) | Web Storage (5~10MB LocalStorage/SessionStorage), IndexedDB (대용량 NoSQL) |
| **양방향 통신** | 폴링(Polling), 롱폴링(Long-Polling) 등 불완전한 HTTP 꼼수 | WebSocket 네이티브 API를 통한 전이중(Full-Duplex) 실시간 소켓 통신 |
| **모바일 최적화** | 모바일 브라우저 호환성 극히 취약 | 반응형 뷰포트(`<meta name="viewport">`) 및 다양한 폼 입력 타입(`tel`, `email` 등) |

### HTML5 핵심 5대 웹 API 군 비교

| API 군 | 대표 기술 | 핵심 용도 및 실무 가치 |
|---|---|---|
| **그래픽 및 미디어** | Canvas 2D, WebGL, WebRTC | 웹 기반 게임, 데이터 시각화 차트, 브라우저 화상 통화 구현 |
| **오프라인 및 스토리지** | Service Worker, IndexedDB, Cache Storage | 오프라인 캐싱, PWA(프로그레시브 웹 앱) 구축, 대용량 로컬 캐시 |
| **실시간 네트워킹** | WebSocket, Server-Sent Events (SSE) | 실시간 금융 시세판, 채팅, 알림 스트리밍 |
| **백그라운드 스레드** | Web Workers, Shared Workers | 무거운 연산(암호화, 이미지 처리) 시 메인 UI 렌더링 블로킹 방지 |
| **디바이스 하드웨어** | Geolocation, Web Bluetooth, Web NFC | 사용자 현재 위치 기반 지도 서비스, 사물인터넷(IoT) 기기 제어 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 구형 브라우저(레거시 환경)에서의 HTML5 신규 태그 및 최신 API 미지원(파싱 오류) | HTML5 Shiv, Modernizr 라이브러리를 연동하여 브라우저 기능 감지(Feature Detection) 및 폴리필(Polyfill) 적용 |
| 무늬만 시맨틱 마크업을 적용하고 스크린 리더 초점 이동(Focus) 관리가 누락되어 웹 접근성 저하 | WAI-ARIA(Accessible Rich Internet Applications) 표준 역할(Role) 및 상태 속성을 병기하고 접근성 자동 진단 툴 적용 |
| 클라이언트 Web Storage(LocalStorage)에 인증 토큰(JWT) 보관 시 XSS 공격에 취약 | 민감한 인증 토큰은 JavaScript 접근이 원천 차단되는 HttpOnly/Secure 쿠키에 저장하고 CSP(콘텐츠 보안 정책) 적용 |

## Ⅵ. 제언

현대 프론트엔드 개발에서는 컴포넌트 단위 개발(React, Vue) 시에도 HTML5 표준 시맨틱 구조를 엄격히 준수하고, Service Worker와 결합하여 네이티브 앱 수준의 사용성을 제공하는 프로그레시브 웹 앱(PWA)으로의 발전 필요.

```text
[모던 HTML5 프론트엔드 아키텍처]
  컴포넌트 설계 (시맨틱+ARIA) → 번들링 (Polyfill) → 접근성 100점 검증 → PWA 배포
```

| 검증 단계 | 마크업 설계 단계 | 빌드 및 품질 검증 단계 |
|---|---|---|
| 핵심 통제 | 시맨틱 계층 구조(`<h1>`~`<h6>`) 및 폼 입력 유효성 속성 적용 | axe-core 및 Google Lighthouse 기반 웹 접근성/SEO 전수 검증 |
| 달성 목표 | 장애인차별금지법 준수(KWCAG 2.2 인증) | 기기 독립적인 반응형 멀티 플랫폼 웹 서빙 보장 |
