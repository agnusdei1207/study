## 연관 키워드

- HTML5(HyperText Markup Language 5), 시맨틱 태그(Semantic Tag), 웹 스토리지(Web Storage), WHATWG(Web Hypertext Application Technology Working Group)
- 캔버스(Canvas), 웹소켓(WebSocket), 웹 워커(Web Worker), 폴리필(Polyfill), 기능 감지(Feature Detection), 점진적 향상(Progressive Enhancement)

## Ⅰ. HTML5의 개요

- 핵심 요약 : 시맨틱·멀티미디어·웹 애플리케이션 기능을 확장한 HTML 표준의 핵심 버전.
- 개념 : 시맨틱 요소, 멀티미디어와 웹 애플리케이션 기능을 확장한 HTML(HyperText Markup Language) 표준의 역사적 버전. 현재 HTML은 WHATWG(Web Hypertext Application Technology Working Group)의 Living Standard로 발전하며, W3C(World Wide Web Consortium)의 관련 웹 표준과 함께 사용.
- 배경 및 필요성 : 비표준 플러그인의 보안 취약점과 모바일 기기(iOS, Android) 호환 불가 문제 해소, 시맨틱 웹(Semantic Web) 구현과 크로스 플랫폼 웹 앱 표준 확립 필요.
- 주요 기술 영역 : 시맨틱 태그, 멀티미디어 네이티브 지원, 2D/3D 그래픽스, 클라이언트 웹 스토리지, 실시간 통신 웹 API(Application Programming Interface). IndexedDB, WebGL, WebRTC(Web Real-Time Communication) 등은 HTML 문서 문법과 구분되는 별도 웹 표준 기술.

## Ⅱ. HTML5의 특징

- 핵심 요약 : 플러그인 의존 없이 시맨틱·멀티미디어·그래픽·오프라인·실시간 기능의 표준 제공.

1. 시맨틱 마크업 : `<header>`, `<nav>`, `<main>`, `<article>`, `<footer>` 등 의미 기반 문서 구조.
2. 멀티미디어 : `<audio>`, `<video>` 코덱 네이티브 스트리밍.
3. 고성능 그래픽 : `<canvas>` 2D/3D(WebGL), SVG 벡터 그래픽.
4. 오프라인·저장 : localStorage, sessionStorage, IndexedDB.
5. 차세대 통신 : WebSocket 전이중 통신, WebRTC P2P 실시간 통신.
6. 백그라운드 처리 : Web Workers 멀티스레드, Service Worker.
7. 시맨틱 구조 기반의 검색엔진 대응과 스크린 리더 웹 접근성 지원.

## Ⅲ. HTML5의 구조 (흐름)

- 핵심 요약 : 마크업·멀티미디어·그래픽·저장·통신·백그라운드의 6개 기능 축으로 구성되는 웹 애플리케이션 플랫폼.
- HTML5 핵심 기능 아키텍처.

```text
[ 차세대 웹 애플리케이션 플랫폼: HTML5 ]
 1. 시맨틱 마크업
    <header>, <nav>, <main>, <article>, <footer>
 2. 멀티미디어
    <audio>, <video> (코덱 네이티브 스트리밍)
 3. 고성능 그래픽
    <canvas> (2D/3D WebGL), SVG 벡터 그래픽
 4. 오프라인 & 저장
    localStorage, sessionStorage, IndexedDB
 5. 차세대 통신 API
    WebSocket (전이중), WebRTC (P2P 실시간)
 6. 백그라운드 처리
    Web Workers (멀티스레드), Service Worker
```

- 시맨틱 태그(Semantic Tag) : `<div id="header">` 대신 `<header>`, `<nav>`, `<section>`, `<article>`, `<aside>`, `<footer>` 사용, 검색엔진 SEO(Search Engine Optimization)와 스크린 리더 웹 접근성의 문서 논리 구조 파악 지원.
- 웹 스토리지(Web Storage) : 키-값 문자열의 클라이언트 보관, 쿠키와 달리 HTTP(Hypertext Transfer Protocol) 요청 자동 첨부 없음. 용량·삭제 정책은 브라우저와 저장 모드에 따라 상이, 한도 초과 시 QuotaExceededError 처리 필요.

## Ⅳ. 클라이언트 측 웹 저장소 기술의 비교

- 핵심 요약 : 서버 자동 전송 여부, 수명, 데이터 타입에 따른 저장 기술의 용도 분화.
- 쿠키와 웹 스토리지의 요청 동작 차이.

```text
 쿠키(Cookie)        : 브라우저 ──요청 시 자동 첨부──▶ HTTP 헤더
 웹 스토리지(Web Storage) : 브라우저 ──JavaScript 접근──▶ 서버 자동 전송 없음
```

| 비교 항목 | 쿠키(Cookie) | 로컬 스토리지(localStorage) | 세션 스토리지(sessionStorage) | IndexedDB |
|---|---|---|---|---|
| 저장 용량 | 쿠키별 브라우저 제한 적용 | 브라우저·환경별 한도 적용 | 브라우저·환경별 한도 적용 | 디스크·브라우저 정책별 할당량 적용 |
| 수명(Lifetime) | 세션 또는 만료 시점까지, 사용자·브라우저 삭제 가능 | 세션 간 유지, 영구 보존 보장 없음 | 페이지 세션 기준, 새로고침 시 유지·복원 정책 고려 | 지속 저장 가능, 정책상 축출·사용자 삭제 고려 |
| 서버 전송 여부 | 도메인·경로·보안 속성 조건에 맞는 요청에 자동 첨부 | 자동 첨부 없음 | 자동 첨부 없음 | 자동 첨부 없음 |
| 데이터 타입 | 문자열(String) | 문자열(String) | 문자열(String) | 자바스크립트 객체(트랜잭션 NoSQL(Not Only SQL)) |
| 주 활용 분야 | 세션 ID(Identifier), 자동로그인 토큰 | 사용자 테마(다크모드), 캐시 설정 | 1회성 결제 입력 폼, 일시적 상태 | 대용량 오프라인 데이터, 복합 쿼리 캐시 |

## Ⅴ. HTML5의 장점과 한계

- 핵심 요약 : 표준 기반 크로스 플랫폼·접근성의 장점, 브라우저 편차·저장소 보안·메모리 관리의 한계.
- 장점
  1. 비표준 플러그인 의존 제거를 통한 보안·호환성 개선.
  2. 시맨틱 구조 기반의 SEO(Search Engine Optimization)와 웹 접근성 향상.
  3. 오프라인 저장과 리치 웹 애플리케이션 구현.
  4. 모바일 등 멀티 디바이스 대응 크로스 플랫폼 표준.
- 한계점 1 : 브라우저 벤더별 API 지원 편차 및 크로스 브라우징 파편화
  - 한계점 : 웹소켓, 웹워커, 미디어 레코더 등 고급 HTML5 API의 구현 스펙·성능이 브라우저 엔진(Blink, WebKit, Gecko)마다 상이하여 오작동 발생.
  - 해결 방안 : Babel/core-js 기반 폴리필(Polyfill) 자동 주입, Modernizr 기반 기능 감지(Feature Detection) 및 점진적 향상(Progressive Enhancement) 기법 적용.
- 한계점 2 : 클라이언트 스토리지(LocalStorage/IndexedDB)의 보안 취약성
  - 한계점 : 브라우저 저장소의 JavaScript 접근 가능성으로 인한 XSS(Cross-Site Scripting) 공격 성공 시 저장된 인증 토큰(JWT, JSON Web Token)·민감 정보의 즉각 탈취 위험.
  - 해결 방안 : 세션 설계에 맞춘 `HttpOnly`, `Secure`, `SameSite` 쿠키와 요청 위조 방어 적용, 출력 인코딩 및 CSP(Content Security Policy) 기반 스크립트 주입 억제, 민감 데이터의 클라이언트 저장 최소화. Web Crypto API 암호화도 실행 중 악성 스크립트의 복호화 호출·평문 접근을 자동 차단하지 않음.
- 한계점 3 : 웹 기반 대용량 멀티미디어·그래픽 처리 시 메모리 누수
  - 한계점 : `<canvas>` 2D/WebGL 및 Web Audio 객체의 반복 생성과 미해제 시 브라우저 탭 메모리 급증 및 크래시 발생.
  - 해결 방안 : 캔버스 컨텍스트 정리와 텍스처 명시적 해제(`gl.deleteTexture()`), WeakMap 기반 객체 생명주기 관리, 성능 프로파일링 정례화.

## Ⅵ. 현대 웹 엔지니어링 관점의 기술사적 제언

- 핵심 요약 : 메인 스레드 블로킹 완화와 실시간 통신 기술의 목적 적합성 평가.
- 웹 워커(Web Worker)를 통한 브라우저 메인 스레드 렌더링 블로킹 완화 : 고해상도 이미지 처리, 암호화, 대용량 JSON(JavaScript Object Notation) 파싱 등 CPU(Central Processing Unit) 연산의 별도 스레드 격리, 데이터 전달 비용과 메인 UI(User Interface) 스레드 작업량의 동시 측정을 통한 반응성 확보.
- 웹소켓(WebSocket) 및 WebRTC 기반 실시간 협업 : 통신 방식별 지연·연결 유지 비용 평가 후 서비스 목적 적합성에 따른 적용 권장.
- 참고 : [WHATWG HTML](https://html.spec.whatwg.org/), [Web Storage](https://html.spec.whatwg.org/multipage/webstorage.html), [Storage Standard](https://storage.spec.whatwg.org/), [W3C Web Cryptography API 보안 고려사항](https://www.w3.org/TR/webcrypto/#security-considerations).
