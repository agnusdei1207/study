## Ⅰ. HTML5의 개요

- 개념 : **HTML5** 란 W3C(World Wide Web Consortium)와 WHATWG가 웹을 단순한 하이퍼텍스트 문서 플랫폼에서 플러그인(ActiveX, Flash, Silverlight) 없이도 멀티미디어, 고성능 그래픽, 오프라인 저장소, 실시간 양방향 통신을 실행할 수 있는 완전한 차세대 개방형 웹 애플리케이션 플랫폼으로 발전시킨 웹 표준 마크업 언어.
- 배경 및 필요성 : 비표준 플러그인의 보안 취약점과 모바일 기기(iOS, Android) 호환 불가 문제를 해결하고, **시맨틱 웹** (Semantic Web) 구현 및 크로스 플랫폼 웹 앱 표준 확립.
- 주요 5대 혁신 영역 : 시맨틱 태그, 멀티미디어 네이티브 지원, 2D/3D 그래픽스, 클라이언트 웹 스토리지, 실시간 통신 웹 API(Application Programming Interface).

## Ⅱ. HTML5 핵심 기능 아키텍처 및 주요 기술 스택

```text
   ┌────────────────────────────────────────────────────────────────────────┐
   │ [ 차세대 웹 애플리케이션 플랫폼: HTML5 ]                               │
   │                                                                        │
   │  [ 1. 시맨틱 마크업 ] ── <header>, <nav>, <main>, <article>, <footer> │
   │  [ 2. 멀티미디어 ]   ── <audio>, <video> (코덱 네이티브 스트리밍)      │
   │  [ 3. 고성능 그래픽 ] ── <canvas> (2D/3D WebGL), SVG 벡터 그래픽       │
   │  [ 4. 오프라인 & 저장] ── localStorage, sessionStorage, IndexedDB       │
   │  [ 5. 차세대 통신 API] ── WebSocket (전이중 양방향), WebRTC (P2P 실시간)│
   │  [ 6. 백그라운드 처리] ── Web Workers (멀티스레드), Service Worker     │
   └────────────────────────────────────────────────────────────────────────┘
```

- **시맨틱 태그** (Semantic Tags) : `<div id="header">` 대신 `<header>`, `<nav>`, `<section>`, `<article>`, `<aside>`, `<footer>`를 사용하여 검색엔진(SEO, Search Engine Optimization)과 스크린 리더(웹 접근성)가 문서의 논리적 의미를 정확히 파악하도록 지원.
- **웹 스토리지** (Web Storage) : 기존 쿠키(Cookie)의 4KB 용량 한계와 매 HTTP(Hypertext Transfer Protocol) 요청마다 전송되던 네트워크 낭비를 극복하여, 도메인당 5MB 이상의 대용량 키-값 데이터를 클라이언트에 안전하게 보관.

## Ⅲ. 클라이언트 측 웹 저장소 기술 비교

| 비교 항목 | 쿠키 (Cookie) | 로컬 스토리지 (localStorage) | 세션 스토리지 (sessionStorage) | IndexedDB |
|---|---|---|---|---|
| 저장 용량 | 4 KB | 약 5 MB | 약 5 MB | 250 MB 이상 (디스크 가용량 비례) |
| 수명 (Lifetime) | 만료일 지정 시까지 유지 | 영구 보관 (직접 삭제 전까지) | 브라우저 탭 닫을 때 즉시 삭제 | 영구 보관 |
| 서버 전송 여부 | 매 HTTP 요청 헤더에 자동 전송 | 클라이언트에만 존재 (네트워크 전송 없음) | 클라이언트에만 존재 | 클라이언트에만 존재 |
| 데이터 타입 | 문자열 (String) | 문자열 (String) | 문자열 (String) | 자바스크립트 객체 (트랜잭션 NoSQL(Not Only SQL)) |
| 주 활용 분야 | 세션 ID(Identifier), 자동로그인 토큰 | 사용자 테마(다크모드), 캐시 설정 | 1회성 결제 입력 폼, 일시적 상태 | 대용량 오프라인 데이터, 복합 쿼리 캐시 |

## Ⅳ. HTML5의 주요 한계점 및 해결 방안

- 브라우저 벤더별 API 지원 편차 및 크로스 브라우징 파편화 :
  - 한계점 : 웹소켓, 웹워커, 미디어 레코더 등 고급 HTML5 API의 구현 스펙과 성능이 브라우저 엔진(Blink, WebKit, Gecko)마다 상이하여 오작동 발생.
  - 해결 방안 : Babel/core-js 기반 **폴리필** (Polyfill) 자동 주입, Modernizr를 통한 **기능 감지** (Feature Detection) 및 **점진적 향상** (Progressive Enhancement) 기법 적용.
- **클라이언트 스토리지** (LocalStorage/IndexedDB)의 보안 취약성 :
  - 한계점 : 브라우저 저장소는 JavaScript 코드로 접근 가능하므로, XSS(Cross-Site Scripting) 공격 성공 시 저장된 인증 토큰(JWT, JSON Web Token) 및 민감 정보가 즉각 탈취됨.
  - 해결 방안 : 민감한 인증 토큰은 `HttpOnly` 및 `Secure`, `SameSite` 속성이 부여된 쿠키에 보관, 로컬 데이터는 Web Crypto API를 활용해 암호화 저장.
- 웹 기반 대용량 멀티미디어/그래픽 처리 시 메모리 누수 :
  - 한계점 : `<canvas>` 2D/WebGL 및 Web Audio 객체를 반복 생성하고 명시적으로 해제하지 않을 경우 브라우저 탭 메모리가 급증하여 크래시 발생.
  - 해결 방안 : 캔버스 컨텍스트 정리 및 텍스처 명시적 해제(`gl.deleteTexture()`), WeakMap 기반 객체 생명주기 관리 및 성능 프로파일링 정례화.

## Ⅴ. 현대 웹 엔지니어링 관점의 기술사적 제언

- **웹 워커** (Web Worker)를 통한 브라우저 메인 스레드 렌더링 블로킹 방지 : 고해상도 이미지 처리, 암호화, 대용량 JSON(JavaScript Object Notation) 파싱 등 무거운 CPU(Central Processing Unit) 연산 작업을 별도의 백그라운드 스레드로 격리하여, 브라우저 메인 UI(User Interface) 스레드가 멈추지 않고 60fps의 부드러운 반응성을 유지하도록 설계.
- **웹소켓** (WebSocket) 및 WebRTC 기반의 실시간 협업 서비스 고도화 : 주기적인 폴링(Polling)으로 인한 서버 트래픽 낭비를 제거하고, 주식 시세, 실시간 화상회의, 온라인 협업 도구(Figma 등)의 초저지연 양방향 통신을 위해 HTML5 표준 프로토콜을 적극 활용해야 함.
