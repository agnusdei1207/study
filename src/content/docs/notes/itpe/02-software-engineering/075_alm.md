## 연관 키워드

- 애플리케이션 수명 주기 관리(ALM, Application Lifecycle Management), 추적성, 도구 사일로
- 요구사항 관리, 형상 관리, 거버넌스, OSLC

## Ⅰ. ALM의 개요

- 핵심 요약 : 요구사항부터 운영까지 소프트웨어 수명 주기 전체의 활동과 정보를 하나의 흐름으로 연결 관리하는 체계.
- 개념 : 소프트웨어의 계획·요구·개발·시험·릴리스·운영 전 과정을 통합해 관리하는 체계인 **애플리케이션 수명 주기 관리**(ALM, Application Lifecycle Management).
- 배경 및 필요성 : 요구·개발·시험·운영을 서로 다른 도구로 따로 관리하면 **도구 사일로**(단계별 도구에 정보가 갈려 연결되지 않는 상태)가 생기고, 요구 변경의 영향 파악과 감사 증빙이 곤란.
- 주요 목적 : 수명 주기 전 단계의 **추적성**(요구에서 산출물까지 이어지는 연결 관계)과 투명성을 확보해 예측 가능한 품질·납기 관리와 규제 준수라는 조직 성과 달성.

## Ⅱ. ALM의 특징 및 장점

- 핵심 요약 : 전 주기 통합과 추적 링크, 도구 연계, 운영 환류가 품질·규제 준수 효과로 이어지는 구조.

1. 전 주기 통합 : 요구사항 관리·형상 관리·시험·릴리스를 하나의 작업 흐름으로 연결 → 단계 간 인계 손실과 중복 입력 감소.
2. 추적 링크 관리 : 요구-설계-코드-시험-릴리스 사이의 연결 관계를 유지 → 변경 영향 분석과 감사 증빙 확보.
3. **거버넌스 내재화** : 승인·역할·권한 등 통제와 책임의 활동을 프로세스 안에 포함 → 품질 기준과 규제 준수의 일관성 확보.
4. 이기종 도구 연계 : **OSLC**(Open Services for Lifecycle Collaboration) 같은 연계 표준과 API(Application Programming Interface)로 도구 간 데이터 연계 → 도구 교체 후에도 정보 흐름 유지.
5. 운영 환류 : 장애·사용 데이터를 요구사항과 백로그에 되돌려 반영 → 지속적인 제품 개선.

## Ⅲ. ALM의 구조 (흐름)

- 핵심 요약 : 거버넌스·개발·운영 3개 영역이 수명 주기 단계를 아우르고, 추적 링크가 단계 사이의 정보를 연결하는 구조.

```text
[ ALM 3개 영역 ]

거버넌스 : 계획·승인·감사
   ↓ 전 단계 통제
개발 : 요구·설계·구현·시험
   ↓ 릴리스 인계
운영 : 배포·모니터링·유지 보수
```

```text
요구사항 정의
   ↓ 추적 링크
설계·구현·형상 관리
   ↓ 추적 링크
시험·릴리스 승인
   ↓ 추적 링크
운영·유지 보수
   ↓ 장애·사용 데이터 환류
요구사항 갱신
```

## Ⅳ. ALM과 도구별 분산 관리의 비교

- 핵심 요약 : 단계별 도구를 따로 운영하는 분산 관리가 국소 효율에 머무는 데 비해, ALM은 전 주기 연결로 가시성과 증빙을 확보.

| 비교 축 | ALM | 도구별 분산 관리 |
| --- | --- | --- |
| 관리 범위 | 요구부터 운영까지 전 주기 | 각 단계 도구의 범위 안에 한정 |
| 추적성 | 전 단계 추적 링크로 연결 | 도구 간 단절, 수작업 대조 |
| 변경 대응 | 영향 분석 후 전 단계 일괄 반영 | 관련 도구를 개별 수색·수정 |
| 감사·증빙 | 승인·이력의 통합 조회 | 산출물별로 흩어진 증빙 |
| 협업 | 공통 작업 항목 기반 | 부서·도구 경계에서 끊김 |

## Ⅴ. ALM의 한계와 방안

- 핵심 요약 : 도구 사일로 재발·워크플로 과잉 표준화·도구 종속을 연계 기준·최소 통제·이전성 확보로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 도구 사일로 재발 | 연계 없는 도구 병행 도입 → 추적 링크 공백 | 공통 식별자·API 연계 기준과 링크 점검 절차 운영 | 추적 링크 완전성 |
| 워크플로 과잉 표준화 | 단일 프로세스 강제 → 팀 실무와의 충돌·우회 | 최소 공통 통제만 표준화하고 팀별 확장 허용 | 예외 승인·우회 건수 |
| 특정 도구 종속 | 데이터 이전 경로 부재 → 전환 비용 급증 | 내보내기 형식·API 확인과 이전 시험 의무화 | 이전성 시험 결과 |

## Ⅵ. ALM 적용에 대한 기술사적 제언

- 핵심 요약 : 도구 도입을 넘어 가치 흐름 관리·연계 표준·운영 자동화를 아우르는 조직 차원의 체계 정립 필요.
- 경영·정보시스템 조직 : **VSM**(Value Stream Management, 가치 흐름 관리) 관점에서 요구부터 릴리스까지의 흐름을 측정하고 개선 주체와 주기를 지정.
- 도구·표준 관리 조직 : 도구 평가 기준에 연계 표준(OSLC) 준수와 데이터 이전성 항목을 포함해 교체 가능성을 제도화.
- 개발·운영 조직 : **GitOps**(Git 저장소를 기준으로 운영 설정을 자동 반영하는 방식)로 배포·설정 변경 이력을 통일해 운영 정보를 수명 주기 관리에 편입.

## Ⅶ. 결론

- 핵심 요약 : ALM은 도구 묶음이 아니라 소프트웨어 가치 전달 전 과정을 연결하는 관리 체계임.
- 추적성과 거버넌스를 갖춘 관리 체계가 변화 대응과 규제 준수의 동시 확보를 가능하게 함.
