## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 개발 관리 → **형상관리(베이스라인)**

## 30초 인출

- 본질: 형상관리는 소프트웨어 산출물의 변경 이력과 버전을 식별·통제·기록·감사해 일관성을 유지하는 관리 활동
- 메커니즘: 형상항목을 식별해 기준선으로 확정하고, 변경 요청을 형상통제위원회가 심의해 승인된 변경만 반영하며 상태 보고와 감사로 확인
- 통찰: 기준선 없이 변경하면 어떤 버전이 승인본인지 알 수 없으므로 승인된 산출물을 기준선으로 고정하고 변경은 위원회 승인과 감사를 거쳐 새 기준선으로 갱신

<details>
<summary>핵심 용어</summary>

- **형상관리(SCM, Software Configuration Management)** : 소프트웨어 산출물의 변경을 식별·통제·기록·감사하는 관리 활동
- **형상항목(CI, Configuration Item)** : 형상관리로 통제하는 개별 단위. 소스 코드·명세서·설계서 등
- **기준선(Baseline)** : 검토·승인을 거쳐 확정되어 이후 변경을 공식 절차로만 허용하는 산출물 상태
- **형상통제위원회(CCB, Configuration Control Board)** : 변경 요청의 영향을 검토해 승인 여부를 결정하는 조직
- **형상 감사(Configuration Audit)** : 산출물이 요구와 일치하고 기준선과 실제가 같은지 확인하는 활동
- **Git** : 분산 저장소 방식의 형상관리 도구

</details>

## 2~4교시 25점 답안

## Ⅰ. 형상관리의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **형상관리** 는 소프트웨어 산출물의 변경을 식별·통제·기록·감사해 일관성을 유지하는 관리 활동 |
| 목적 | 산출물 변경의 추적 가능성과 승인본 무결성 확보 |

## Ⅱ. 단순 버전 저장과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 형상항목 단위 관리 | 소스뿐 아니라 명세·설계·시험 산출물까지 통제 |
| 승인 기반 변경 | 위원회 심의를 거친 변경만 반영 |
| 기준선 고정 | 승인된 산출물을 기준으로 이후 변경 비교 |

## Ⅲ. 형상관리 절차와 변경 통제

### 형상관리의 4가지 활동

```text
형상관리 계획
    │
    ├─ 형상 식별 ── 형상항목 선정·명명·버전 체계
    ├─ 형상 통제 ── 변경 요청 접수, 위원회 심의·승인
    ├─ 형상 상태 보고 ── 변경 이력·릴리스 현황 기록
    └─ 형상 감사 ── 기능 감사·물리 감사
```

### 확대: 변경 통제와 기준선 갱신 절차

```text
변경 요청(CR) 접수
    ↓
영향 분석 (범위·일정·비용·품질)
    ↓
형상통제위원회 심의
    ├─ 반려·보류 → 사유 기록 후 통보
    └─ 승인 → 변경 구현 → 시험
    ↓
형상 감사 후 새 기준선 확정
```

## Ⅳ. 기준선 유형과 형상관리 도구

### 생명주기별 기준선

| 기준선 | 확정 시점 | 확정 내용 |
|---|---|---|
| 기능 기준선 | 요구사항 확정 | 시스템 요구·기능 명세 |
| 할당 기준선 | 설계 확정 | 서브시스템·모듈별 할당 요구와 인터페이스 |
| 제품 기준선 | 시험 완료 | 최종 릴리스 산출물 |

### 형상관리 도구

| 구분 | 저장소 방식 | 대표 도구 | 특징 |
|---|---|---|---|
| 중앙집중형 | 서버 한 곳에 저장 | CVS, Subversion(SVN) | 서버 접속 시 변경 이력 조회 |
| 분산형 | 각 개발자가 전체 이력 보유 | Git | 오프라인 작업, 브랜치·병합 용이 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 기준선 없이 변경되어 승인본 식별 불가 | 단계별 승인 시점마다 기준선 확정과 태그 |
| 위원회 심의 지연으로 변경 병목 | 영향 범위가 작은 변경의 승인 절차 단순화 |
| 형상 감사 생략으로 산출물과 기준선 불일치 | 기준선 갱신 전 형상 감사를 필수 절차로 지정 |
| 저장소·브랜치 규칙 부재로 병합 충돌 | 브랜치 전략과 병합 규칙 문서화 |

## Ⅵ. 제언

승인된 산출물마다 기준선을 확정하고, 변경은 영향 분석과 위원회 승인·감사를 거친 뒤 새 기준선으로 갱신

### 기준선 중심의 변경 통제

```text
승인 산출물 → 기준선 확정
    ↓
변경 요청 → 영향 분석 → 위원회 승인
    ↓
구현·시험 → 형상 감사 → 새 기준선
```

### 선택 근거: 사후 기록과의 비교

| 구분 | 변경 후 사후 기록 | 제언: 기준선·승인 기반 |
|---|---|---|
| 승인본 식별 | 불명확 | 기준선으로 확정 |
| 변경 근거 | 사후 확인 | 영향 분석·승인 기록 |
| 불일치 확인 | 발견 지연 | 갱신 전 감사 |
