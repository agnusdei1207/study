## 연관 키워드

- 탐욕 알고리즘(Greedy Algorithm), 국소적 최적해(Local Optimum), 전체 최적해(Global Optimum)
- 탐욕적 선택 속성(Greedy Choice Property), 최적 부분 구조(Optimal Substructure)
- 동적 계획법(DP, Dynamic Programming), 교환 논법(Exchange Argument), 근사 알고리즘(Approximation Algorithm)

## Ⅰ. 탐욕 알고리즘의 개요

- 핵심 요약 : 매 순간의 국소적 최적 선택을 통해 전체 최적해 도달을 추구하는 알고리즘 설계 패러다임.
- 개념 : 최적화 문제를 해결할 때, 전체적인 미래 상황을 고려하지 않고 현재 순간에서 가장 최선이라고 판단되는 근시안적인 국소적 최적해(Local Optimum)를 단계별로 선택해 나감으로써 최종적인 전체 최적해(Global Optimum)에 도달하고자 하는 알고리즘 설계 패러다임.
- 배경 및 필요성 : 동적 계획법(DP, Dynamic Programming)이나 완전 탐색(Backtracking)의 높은 시간·공간 복잡도를 극복하고, 특정 조건을 만족하는 문제에 대해 매우 단순하고 빠른 다항 시간 내 최적해 도출.
- 2대 필수 성립 조건 : 탐욕적 선택 속성(Greedy Choice Property), 최적 부분 구조(Optimal Substructure).

## Ⅱ. 탐욕 알고리즘의 특징

- 핵심 요약 : 비번복의 국소 최적 선택, 2대 성립 조건, 정렬 기반 고속 해법의 결합.

1. 근시안적 국소 최적 선택 : 각 단계에서 가장 좋아 보이는 단 하나의 해를 즉시 선택.
2. 번복 없는 선택 : 한 번 내린 선택은 이후 단계에서 재고(Backtracking)하지 않는 구조.
3. 2대 성립 조건 : 탐욕적 선택 속성과 최적 부분 구조의 동시 만족 시에만 전체 최적성 보장.
4. 고속 해법 : 초기 정렬 후 주로 $O(N)$ 또는 $O(N \log N)$ 수준의 다항 시간 내 해 도출.
5. 대표 응용 : 최소 신장 트리(크루스칼·프림), 다익스트라(Dijkstra) 최단 경로, 허프만 코딩(Huffman Coding), 회의실 배정, 분할 가능 배낭 문제(Fractional Knapsack).

## Ⅲ. 탐욕 알고리즘의 구조 (흐름)

- 핵심 요약 : 선택→실행 가능성 검사→해 갱신의 반복 루프와 2대 조건 기반 최적성 증명 메커니즘.
- 탐욕 알고리즘의 일반 수행 흐름.

```text
[ 탐욕 알고리즘 일반 수행 흐름 ]
[ 후보 집합 초기화 ]
        ↓
[ 탐욕적 선택 기준 적용 ]
 (현재 시점 최선의 후보 선택)
        ↓
[ 실행 가능성 검사 ]
 - 만족 → 해 집합에 추가
 - 불만족 → 후보 폐기
        ↓
[ 해 집합 완성 검사 ]
 - 미완성 → 선택 단계 반복
 - 완성 → 최종 해 반환
```

- 2대 성립 조건과 최적성 증명 메커니즘.

```text
[ 탐욕적 선택 속성 ]
  (Greedy Choice Property)
 - 앞의 선택이 이후 선택에
   영향을 주지 않으며, 현재의
   최선의 선택이 전체 최적해의
   일부가 됨을 증명
   │
   ▼
[ 최적 부분 구조 ]
  (Optimal Substructure)
 - 최종 최적해가 하위 부분
   문제들의 최적해들로 구성됨
   │
   ▼
[ 최적성 증명 ]
 - 수학적 귀납법 또는 교환 논법
   (Exchange Argument)
 - 탐욕적 선택을 포함하지 않는
   가상의 최적해를 탐욕적
   선택으로 교체해도 해의
   품질이 나빠지지 않음을 입증
```

## Ⅳ. 탐욕 알고리즘과 동적 계획법의 비교

- 핵심 요약 : 선택 방식·번복 여부·효율성·최적성 보장이 상반된 두 최적화 패러다임.

| 비교 항목 | 탐욕 알고리즘 (Greedy) | 동적 계획법 (Dynamic Programming) |
|---|---|---|
| 선택 방식 | 현재 상태에서 가장 좋아 보이는 단 하나의 해를 즉시 선택 | 모든 가능한 부분 문제의 해를 전부 탐색하고 비교하여 선택 |
| 선택 번복(Backtracking) | 한 번 내린 선택은 결코 번복하지 않음 | 이전의 결정을 검토하며 하위 문제의 최적해를 조합 |
| 계산 효율성 | 매우 빠름 (주로 정렬 후 $O(N)$ 또는 $O(N \log N)$) | 상대적으로 느림 (메모이제이션 테이블 갱신, 다차원 배열) |
| 최적성 보장 여부 | 성립 조건을 증명하지 못하면 최적성 보장 없음(근사 비율도 별도 증명) | 유효한 상태·점화식·최적 부분 구조에 따라 정확히 계산한 경우 최적해 보장 |
| 배낭 문제 (Knapsack) | 분할 가능 배낭 문제(Fractional Knapsack: 무게당 가치 정렬) | 0-1 배낭 문제(물건을 쪼갤 수 없는 경우, DP·분기한정 등 활용 가능) |

## Ⅴ. 탐욕 알고리즘의 장점과 한계

- 핵심 요약 : 고속·단순 해법의 장점과 국소 최적 함정·정렬 오버헤드·제약 변화 취약성의 한계 공존.

- 장점
  1. 초기 정렬 후 단일 패스 수준의 매우 빠른 계산 효율성.
  2. 단순한 로직 구조를 통한 낮은 개발·유지보수 비용.
  3. 실시간 시스템 및 근사 해법 설계에의 즉각적 적용 가능성.

- 한계점 1 : 지역 최적해(Local Optimum) 함정 및 전역 최적해 보장 실패
  - 한계점 : 매 순간 가장 좋아 보이는 선택을 하지만, 미래의 선택지를 고려하지 않아 배낭 문제(0-1 Knapsack)처럼 전체 최적해를 도출하지 못하는 치명적 한계.
  - 해결 방안 : 탐욕적 선택 속성(Greedy Choice Property)과 최적 부분 구조(Optimal Substructure)의 수학적 증명 선행, 불가능할 경우 동적 계획법(DP)으로 전환.
- 한계점 2 : 입력 데이터 정렬에 따른 초기 연산 오버헤드
  - 한계점 : 회의실 배정 등 대다수 탐욕 알고리즘은 초기에 간선이나 구간을 정렬해야 하므로, 정렬 자체의 $O(N \log N)$ 시간 복잡도에 병목 종속.
  - 해결 방안 : 우선순위 큐(Min-Heap/Max-Heap)를 활용한 정렬 비용 분산 또는 데이터 인입 시 부분 정렬 상태를 유지하는 스트리밍 알고리즘 기법 적용.
- 한계점 3 : 문제 제약조건 추가 시 알고리즘 전체 무효화(Brittle Logic)
  - 한계점 : 기본 문제에 사소한 제약조건(예 : 가중치 제한, 비연속 선택 조건)이 하나만 추가되어도 탐욕적 규칙이 완전히 붕괴되어 재설계 불가피.
  - 해결 방안 : 엄격한 최적해 대신 합리적 오차 범위 내의 해를 허용하는 휴리스틱 근사 알고리즘(Approximation Algorithm)으로 설계하고 근사비(Approximation Ratio) 검증.

## Ⅵ. 시스템 최적화 및 휴리스틱 응용 관점의 기술사적 제언

- 핵심 요약 : 채택 전 정당성 증명 선행과 NP-Hard 문제의 근사 알고리즘 활용.
- 탐욕 해법의 정당성 증명(Proof of Correctness) 선행 : 탐욕 알고리즘은 직관적으로 맞아 보이지만 예외 케이스에서 오작동하기 쉬우므로(예 : 거스름돈 동전 단위가 배수 관계가 아닐 때 8원 = 5원+1원+1원+1원 vs 4원+4원), 반드시 교환 논법(Exchange Argument)을 통한 수학적 최적성 증명을 거친 후의 알고리즘 채택 필수.
- NP-Hard(Non-deterministic Polynomial-time Hard) 문제에 대한 고속 근사 알고리즘(Approximation Algorithm) 활용 : 외판원 순회(TSP, Traveling Salesman Problem), 정점 커버(Vertex Cover) 등 다항 시간 내에 최적해를 구할 수 없는 복잡한 최적화 문제에 대해, 100% 최적해 대신 이론적으로 오차 한계가 증명된 탐욕적 근사 알고리즘을 적용한 실시간 시스템의 연산 병목 돌파 권장.

## Ⅶ. 결론

- 핵심 요약 : 탐욕 알고리즘은 2대 성립 조건의 수학적 증명이 전제될 때 유효한 고속 최적화 수단.
- 요약 : 국소 최적 선택 기반의 고속 해법으로, 성립 조건 충족 시 전체 최적해 보장.
- 시사점 : 증명 불가 문제는 동적 계획법 전환 또는 근사비(Approximation Ratio) 검증형 근사 알고리즘 설계가 대안.
