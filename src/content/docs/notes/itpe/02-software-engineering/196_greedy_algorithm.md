```text
[ 문제 해결 탐색 공간 ]

        │                │

```

## 핵심 용어
- 탐욕적 선택 속성(Greedy Choice Property): 앞의 선택이 이후의 선택에 영향을 주지 않으며, 각 단계에서 탐욕적으로 내린 선택이 전체 문제의 최적해로 귀결되는 성질
- 최적 부분 구조(Optimal Substructure): 전체 문제의 최적해가 그 안에 포함된 부분 문제들의 최적해들로 구성되는 구조
- 활동 선택 문제(Activity Selection Problem): 한 번에 하나의 회의실만 사용할 수 있을 때, 서로 겹치지 않으면서 진행할 수 있는 최대 회의 개수를 구하는 대표적인 그리디 문제 (종료 시간 오름차순 정렬)
- 허프만 코딩(Huffman Coding): 문서 내 문자의 출현 빈도에 따라 자주 나오는 문자에는 짧은 비트를, 드물게 나오는 문자에는 긴 비트를 탐욕적으로 할당하는 무손실 압축 기법
- 매트로이드(Matroid): 그리디 알고리즘이 항상 전역 최적해를 찾아냄을 엄밀하게 증명할 수 있는 독립 집합 계열의 수학적 대수 구조

## 핵심 통찰
- 그리디 알고리즘의 최대 장점은 '압도적인 계산 속도와 단순함'임. 백트래킹처럼 이전 선택을 되돌아보거나(Backtrack), DP처럼 모든 상태를 테이블에 메모이제이션할 필요가 없음
- 그러나 대부분의 현실 문제는 매 순간의 최선이 미래의 발목을 잡기 때문에 그리디로 완벽한 최적해를 얻기 어려움
- 그리디를 적용하려면 반드시 수학적 증명(귀납법 또는 교환 논법, Exchange Argument)을 거쳐 최적해가 보장되는지 검증해야 함
- 최적해가 보장되지 않는 NP-Hard 문제(예: TSP, 0/1 Knapsack)라 할지라도, 완벽한 해 대신 '실행 가능한 근사해(Approximation)'를 수 밀리초 내에 빠르게 구하는 휴리스틱으로 실무 가치가 매우 높음

## 이웃 토픽과 구분
| 비교 항목 | 그리디 (Greedy) | 동적 계획법 (DP) | 분할 정복 (Divide & Conquer) | 백트래킹 (Backtracking) |
| :--- | :--- | :--- | :--- | :--- |
| **선택 방식** | 매 순간 당장 최선인 것 하나만 선택 | 모든 소문제의 최적해를 비교/취합 | 문제를 독립적 부분 문제로 쪼개어 정복 | 가능성을 탐색하다 막히면 되돌아감 |
| **하위 문제 중복**| 하위 문제 중복 없음 | 하위 문제들이 빈번하게 중복됨 | 하위 문제들이 서로 독립적임 | 상태 공간 트리를 완전/가지치기 탐색 |
| **메모이제이션** | 불필요 | 필수 (DP 테이블에 결과 캐싱) | 불필요 | 불필요 (방문 상태 복원) |
| **시간 복잡도** | 매우 빠름 (주로 정렬 $O(n \log n)$) | 다항 시간 ($O(n^2), O(n \cdot W)$ 등) | $O(n \log n)$ | 지수 시간 ($O(2^n), O(n!)$) |
| **대표 문제** | 다익스트라, 크루스칼, 활동선택 | 피보나치, 0/1 Knapsack, LCS | 병합 정렬, 퀵 정렬, 이진 탐색 | N-Queen, 미로 찾기, 스도쿠 |

## 문제·원인·대책
| 문제상황 | 원인 | 기술적 대책 |
| :--- | :--- | :--- |
| **동전 거스름돈 문제에서 최소 동전 수 실패** | 동전 단위가 서로 배수 관계가 아님 (예: 10원, 50원, 60원 체계에서 80원 거슬러주기) | 배수 관계가 아닌 화폐 체계에서는 동적 계획법(DP)으로 알고리즘 전면 교체 |
| **배낭 문제에서 최대 가치 산출 오류** | 물건을 쪼갤 수 없는 0/1 Knapsack 문제에 가치 대비 무게 비율로 그리디 적용 | 0/1 배낭 문제는 DP로 풀고, 물건을 쪼갤 수 있는 분할 가능 배낭(Fractional)에만 그리디 적용 |
| **최적해와 근사해 사이의 오차 제어 불가** | NP-Hard 문제에 휴리스틱 그리디 적용 시 특정 케이스에서 오차율 급증 | 근사비(Approximation Ratio)가 수학적으로 증명된 알고리즘(예: 크리스토피데스 알고리즘) 적용 |

## 내 의견
- 실무 엔지니어링에서 모든 문제에 대해 수학적으로 완벽한 글로벌 최적해를 구하는 것은 시간과 컴퓨팅 비용 측면에서 불가능한 경우가 많음
- 특히 클라우드 자원 오토스케일링, 쿠버네티스 파드(Pod) 스케줄링, 패킷 라우팅과 같은 실시간 인프라 제어에서는 마이크로초 단위의 신속한 의사결정이 필요하므로 그리디 기반의 휴리스틱 스케줄러가 사실상 표준으로 채택됨
- 따라서 시스템 설계자는 당면한 문제가 엄밀한 해를 요구하는 금융 정산(DP 필수)인지, 아니면 95% 수준의 만족스러운 해를 신속히 요구하는 실시간 최적화(Greedy 적합)인지 비즈니스 트레이드오프를 명확히 판정해야 함
