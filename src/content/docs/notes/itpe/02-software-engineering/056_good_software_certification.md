## 연관 키워드

- GS 인증, 소프트웨어진흥법, TTA, KTL
- ISO/IEC 25010, 8대 품질 특성

## Ⅰ. GS 인증의 개요

- 핵심 요약 : 국산 소프트웨어 품질을 제3의 기관이 시험·심사해 등급으로 보증하는 법정 품질인증 제도.
- 개념 : 국산 소프트웨어의 품질을 공인 시험기관이 종합 시험·평가하여 등급으로 공식 보증하는 국가 품질인증 제도 (**GS 인증**, Good Software Certification).
- 법적 근거 : **소프트웨어진흥법**의 소프트웨어 품질인증 제도 규정.
- 시험기관 : **TTA**(한국정보통신기술협회, Telecommunications Technology Association)와 **KTL**(한국산업기술시험원, Korea Testing Laboratory)의 시험·심사 수행.
- 주요 목적 : 국산 소프트웨어의 품질 신뢰성 제고와 공공 조달 판로의 지원.

## Ⅱ. GS 인증의 특징 및 장점

- 핵심 요약 : 국제 표준 기준과 제3자 시험의 결합이 공적 보증이라는 장점으로 연결되는 평가 체계.

1. 법정 인증의 공신력 : 소프트웨어진흥법 근거의 제도적 운영 → 인증 결과의 공적 신뢰 확보.
2. 국제 표준 기반 평가 : 품질 모델 **ISO/IEC 25010**을 준거로 한 **8대 품질 특성**의 평가 → 객관적이고 체계적인 품질 판정.
3. 시험과 심사의 결합 : 제품 시험 결과와 제품 해설서 등 산출물 심사의 종합 → 품질의 다면 판정.
4. 등급 부여 : 최우수·우수·보통의 3단계 등급 체계 → 품질 수준의 비교 가능성 제공.
5. 조달 연계 : 공공기관 우선구매 등 조달 제도와의 연동 → 인증 획득 제품의 판로 확대.

## Ⅲ. GS 인증의 구조 (흐름)

- 핵심 요약 : 신청에서 인증서 발급까지의 절차 흐름과 8대 품질 특성 기준의 평가 구조.
- 인증 절차의 단계별 순서.

```text
[ GS 인증 절차 ]

인증 신청 (기업)
   ↓
제품 접수와 계약 체결
   ↓
종합 시험 (TTA·KTL)
   ↓
결함 보완과 재시험
   ↓
심의 위원회의 등급 결정
   ↓
인증서 발급
```

- ISO/IEC 25010 품질 모델의 여덟 평가 축.

```text
[ ISO/IEC 25010 : 8대 품질 특성 ]

1. 기능 적합성    2. 성능 효율성
3. 호환성         4. 사용성
5. 신뢰성         6. 보안성
7. 유지보수성     8. 이식성
   ↓
여덟 축의 종합 평가로 등급 판정
```

## Ⅳ. GS 인증과 자체 내부 품질 평가의 비교

- 핵심 요약 : 외부 공인 기관의 검증 제도와 내부 QA의 자체 평가는 주체·기준·효력이 다름.

| 비교 축 | GS 인증 | 자체 내부 품질 평가 |
| --- | --- | --- |
| 평가 주체 | TTA·KTL 등 외부 공인 시험기관 | 개발 조직 내부의 QA 담당 |
| 평가 기준 | 소프트웨어진흥법과 ISO/IEC 25010의 법정·표준 기준 | 조직 내부 기준과 관행 |
| 객관성 | 제3자 검증의 독립성 | 이해관계가 포함된 자기 평가 |
| 결과의 효력 | 공적 보증과 조달 자격의 부여 | 내부 개선 근거에 한정 |
| 활용 | 공공 조달·우선구매 연계 | 내부 릴리스 판단 |

## Ⅴ. GS 인증의 한계와 방안

- 핵심 요약 : 심사 기간 부담, 시험 환경의 괴리, 지속 배포와의 불일치가 활용의 제약.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 심사 기간·비용 부담 | 시험·보완·발급 절차의 장기화 → 출시 시기의 지연 | 자가 진단 체크리스트와 표준 산출물의 사전 준비 | 인증 소요 기간 |
| 시험 환경과 실운영 환경의 괴리 | 표준 기준 시험의 한정된 범위 → 실제 트래픽 환경 품질의 미반영 | 실사용 시나리오 기반 부하 시험 결과의 보조 자료 제출 | 운영 환경 시험 커버리지 |
| 인증 이후 지속 배포와의 불일치 | 인증 대상이 시험 시점의 빌드로 한정 → 변경 후 효력의 불명확 | 변경 규모별 재시험 범위 기준의 수립 | 재시험 누락 건수 |

## Ⅵ. 품질 역량 강화에 대한 기술사적 제언

- 핵심 요약 : 인증 취득 자체가 아닌 제품의 내재 품질과 클라우드 시대 품질 기준으로의 확장 필요.
- 조직 : 시험 결함 보고서를 아키텍처 개선과 회귀 시험 체계의 입력으로 연계하는 품질 역량 체계 구축.
- 확산 : 클라우드 서비스 대상 제품의 CSAP(클라우드서비스 보안인증) 등 병행 인증 기준의 마련.
- 문화 : 인증 표식 확보 중심의 대응이 아닌 개발 단계 품질 내재화 문화의 정착.

## Ⅶ. 결론

- 핵심 요약 : GS 인증은 국산 소프트웨어 품질을 공적으로 보증하는 법정 품질인증 제도.
- 외부 보증과 내재 품질의 결합이 소프트웨어 신뢰 확보의 완성.
