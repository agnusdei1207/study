## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 요구공학·모델링 → **유스케이스 다이어그램(유스케이스 명세)**

## 30초 인출

- 본질: 유스케이스 다이어그램은 액터가 시스템에서 얻으려는 목표를 유스케이스로 나타내 시스템 기능의 범위를 보여 주는 UML 행위 다이어그램
- 메커니즘: 시스템 경계 안에 유스케이스를 두고 액터와 연결하며, 공통 기능은 포함(include), 조건부 기능은 확장(extend)으로 연결하고 명세서로 흐름을 기술
- 통찰: 유스케이스를 화면·기능 단위로 잘게 쪼개면 사용자 목표가 사라지므로 사용자 목표 단위로 정의하고 명세서에 기본·대안 흐름을 기술

<details>
<summary>핵심 용어</summary>

- **유스케이스 다이어그램(Use Case Diagram)** : 액터와 시스템 기능(유스케이스)의 관계를 나타내는 다이어그램
- **액터(Actor)** : 시스템 밖에서 시스템을 사용하거나 상호작용하는 사람·시스템
- **유스케이스(Use Case)** : 액터가 시스템으로 달성하는 하나의 목표 단위 기능
- **시스템 경계(System Boundary)** : 개발할 시스템의 범위를 나타내는 사각형
- **포함(include)** : 여러 유스케이스가 공통으로 반드시 사용하는 기능을 분리해 연결한 관계
- **확장(extend)** : 특정 조건에서만 추가로 수행되는 기능을 연결한 관계
- **유스케이스 명세서** : 사전·사후 조건, 기본 흐름, 대안 흐름 등을 기술한 문서

</details>

## 2~4교시 25점 답안

## Ⅰ. 유스케이스 다이어그램의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **유스케이스 다이어그램** 은 액터와 시스템 기능(유스케이스)의 관계를 나타내는 UML 행위 다이어그램 |
| 목적 | 시스템 기능 범위와 사용자 요구의 합의 |

## Ⅱ. 다른 행위 다이어그램과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 사용자 관점 | 시스템 내부가 아닌 사용자 목표 중심 |
| 범위 표현 | 시스템 경계로 기능 범위 구분 |
| 흐름은 명세서에 | 처리 순서는 유스케이스 명세서에 기술 |

## Ⅲ. 유스케이스 다이어그램의 구성과 명세

### 구성 요소

```text
액터(고객) ── 주문하기 ──┐
                        │ <<include>> 로그인
액터(고객) ── 결제하기 ──┤
                        │ <<extend>> 쿠폰 적용
액터(관리자) ── 주문 관리
(시스템 경계: 사각형 안에 유스케이스 배치)
```

### 확대: 유스케이스 명세서의 구성

```text
유스케이스명 · 액터
    ↓
사전 조건
    ↓
기본 흐름 → (조건 발생) → 대안 흐름·예외 흐름
    ↓
사후 조건
```

## Ⅳ. 관계의 비교와 다른 행위 다이어그램과의 관계

### 유스케이스 간 관계

| 관계 | 의미 | 예 |
|---|---|---|
| 포함(include) | 항상 함께 수행되는 공통 기능 | 주문 → 로그인 |
| 확장(extend) | 조건이 맞을 때 추가되는 기능 | 결제 → 쿠폰 적용 |
| 일반화 | 특수 유스케이스가 일반 유스케이스를 상속 | 카드 결제 → 결제 |

### 활동·상태 다이어그램과의 관계

| 구분 | 유스케이스 | 활동 | 상태 |
|---|---|---|---|
| 표현 | 기능과 액터 | 처리 흐름 | 객체 상태 변화 |
| 관계 | 유스케이스 명세의 흐름을 활동 다이어그램으로 구체화 | 흐름 상세 | 상태 변화 복잡 시 추가 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 유스케이스를 화면·기능 단위로 쪼개 사용자 목표 상실 | 액터가 달성하려는 목표 단위로 정의 |
| 다이어그램만으로 처리 순서 표현 불가 | 유스케이스 명세서로 기본·대안 흐름 기술 |
| include·extend 남용으로 구조 복잡 | 공통 기능·조건부 기능에만 사용 |

## Ⅵ. 제언

유스케이스는 액터의 목표 단위로 정의하고, 각 유스케이스마다 명세서에 기본 흐름과 대안 흐름을 기술

### 목표 단위 정의 순서

```text
액터 식별
    ↓
액터별 목표 → 유스케이스 도출
    ↓
유스케이스 명세서 작성 (기본·대안 흐름)
```

### 확대: 유스케이스 적정성 판단

```text
후보 유스케이스
    ├─ 액터의 목표를 하나 완결 → 유지
    └─ 화면·단계 수준 → 상위 목표로 통합
```

### 선택 근거: 기능 목록 나열과의 비교

| 구분 | 기능 목록 나열 | 제언: 목표 단위 유스케이스 |
|---|---|---|
| 단위 | 화면·기능 | 사용자 목표 |
| 요구 합의 | 사용자 의도 불명확 | 목표로 합의 |
| 시험 기준 | 기능별 | 흐름 기반 시나리오 |
