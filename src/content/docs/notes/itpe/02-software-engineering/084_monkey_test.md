## 연관 키워드

- 몽키 테스트, 무작위 입력, 이벤트 스트림, 난수 시드
- 덤 몽키, 스마트 몽키, 안정성, 재현성

## Ⅰ. 몽키 테스트의 개요

- 핵심 요약 : 몽키 테스트는 사전 설계 없이 무작위 입력·이벤트를 반복 주입해 충돌·멈춤 같은 안정성 결함을 탐색하는 시험.
- 개념 : 사전에 설계한 시험 케이스 없이 무작위 입력·사용자 이벤트를 대상에 반복 주입해 충돌·멈춤·비정상 상태를 탐색하는 시험(**몽키 테스트**, Monkey Test).
- 배경 및 필요성 : 정형 시험 케이스로는 모든 이벤트 순서·화면 전환·입력 조합을 포괄할 수 없어 설계 밖 조합의 검증 수단 필요.
- 주요 목적 : 예측하지 못한 상태 조합에서의 결함 조기 발견과 시스템 **안정성**(입력·사용에도 오작동 없이 유지되는 성질) 확보.

## Ⅱ. 몽키 테스트의 특징 및 장점

- 핵심 요약 : 무작위 입력 생성·덤/스마트 몽키 구분·장시간 반복·시드 재현·실패 신호 감시가 강건성 검증으로 연결.

1. 무작위 입력 생성 : 탭·스크롤·키 입력 등의 **이벤트 스트림**(연속된 입력 이벤트 열)을 난수로 생성 → 설계 밖 상태 전이 탐색.
2. 덤·스마트 몽키 구분 : **덤 몽키**(Dumb Monkey, 대상 구조를 모르는 순수 무작위)와 **스마트 몽키**(Smart Monkey, 상태·유효 동작을 아는 유도 무작위)의 선택 → 탐색 범위와 효율의 절충.
3. 장시간·대량 반복 : 다량의 이벤트를 연속 실행 → 메모리 누수·간헐적 충돌 같은 시간 의존 결함 발견.
4. 시드 기반 재현 : **난수 시드**(난수열을 고정하는 시작값)와 기기·버전 정보 기록 → 실패 입력의 재현·분석.
5. 실패 신호 감시 : **크래시**(crash, 비정상 종료)·ANR(Application Not Responding) 등 명확한 실패 신호의 자동 감시 → 판정 자동화.

## Ⅲ. 몽키 테스트의 구조 (흐름)

- 핵심 요약 : 격리 환경 준비에서 결함 수정까지의 실행 절차와, 입력 생성→감시→재현의 반복 고리 구조.

```text
대상·격리 시험 환경 준비
   ↓
무작위 입력 생성
   ↓
대상 실행·상태 관찰
   ↓
실패 신호·로그 수집
   ↓
시드·최소 재현 시퀀스 확보
   ↓
결함 수정·회귀 시험
```

```text
난수 시드 + 이벤트 생성기
   ↓
대상 앱·시스템 입력 주입
   ↓
크래시·멈춤·데이터 무결성 감시
   ↓
실패 입력 최소화·재현
   ↓
결함 시나리오 보고
```

## Ⅳ. 몽키 테스트와 설계 기반 시험 기법의 비교

- 핵심 요약 : 몽키 테스트는 무작위 탐색으로 예측 밖 결함을 찾고, 설계 기반 시험은 명세 분석으로 요구 충족을 검증하는 상호 보완 관계.

| 비교 축 | 몽키 테스트 | 설계 기반 시험 기법 |
| --- | --- | --- |
| 케이스 출처 | 난수 기반 자동 생성 | 명세·경계·흐름 분석 기반 설계 |
| 검증 목적 | 예측 밖 결함·강건성 탐색 | 요구 충족·논리 분기 검증 |
| 판정 기준 | 크래시·멈춤 등 실패 신호 중심 | 예상 결과와의 비교(오라클) |
| 재현성 | 시드·로그 기록으로 확보 | 케이스 자체가 재현 절차 |
| 운영 부담 | 자동화 후 인력 부담 적음 | 설계·유지보수 인력 필요 |
| 적합 영역 | UI 상태 전이·장시간 안정성 | 기능 명세 검증·회귀 시험 |

## Ⅴ. 몽키 테스트의 한계와 방안

- 핵심 요약 : 재현성 부재·얕은 탐색·판정 기준 부재·환경 피해을 기록 체계·탐색 유도·감시 보강·격리 운영으로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **재현성** 부재 | 무작위 시퀀스의 소실 → 결함 보고·분석 불가 | 시드·환경·이벤트 로그 저장, 실패 입력 최소화 도구 | 재현 성공률 |
| 얕은 탐색 | 순수 무작위 도달의 비효율 → 핵심 상태 미도달 | 스마트 몽키·상태 모델·유효 동작 제약으로 탐색 유도 | 상태·전이 도달률 |
| 판정 기준 부재 | 충돌이 아닌 잘못된 결과·데이터 손상 놓침 | 상태 불변식·로그·화면 검증 병행 | 미탐·오탐 건수 |
| 시험 환경 피해 | 실 계정·외부 연동에 무작위 이벤트 → 데이터 훼손·비용 | 격리 환경·가상 계정·초기화 장치 운영 | 초기화 성공률 |

## Ⅵ. 몽키 테스트 적용에 대한 기술사적 제언

- 핵심 요약 : CI 파이프라인 상시화·표준 도구 체계·결함 전환 프로세스로 몽키 테스트를 상시 품질 수단으로 내재화.
- 파이프라인 상시화 : 개발 조직은 야간·릴리스 전 자동 몽키 시험을 빌드 파이프라인에 통합해 상시 실행 체계 운영.
- 도구 체계 표준화 : 플랫폼 표준 도구와 자체 스마트 몽키 도구의 적용 기준·감시 항목을 표준 문서로 통일.
- 결함 전환 프로세스 : 품질 조직은 무작위 실패를 최소 재현 시퀀스로 자동 축소해 결함 티켓으로 전환하는 절차 구축.

## Ⅶ. 결론

- 핵심 요약 : 몽키 테스트는 사전 시나리오로 놓치기 쉬운 예외 상태를 탐색하는 보완 시험.
- 무작위 실패를 시드 기반의 재현 가능한 결함으로 전환할 때 설계 기반 시험의 공백을 메우는 가치 실현.
