## 연관 키워드

- GS(Good Software) 인증, 소프트웨어진흥법, TTA(Telecommunications Technology Association), KTL(Korea Testing Laboratory)
- ISO/IEC 25023, 8대 품질 특성, 공공기관 우선구매, 조달청 나라장터, 상용SW(Software) 분리발주, CSAP(Cloud Security Assurance Program)

## Ⅰ. GS 인증의 개요

- 핵심 요약 : 국산 소프트웨어 품질을 종합 시험·평가하여 공식 보증하는 소프트웨어진흥법 근거 국가 인증 제도.
- 개념 : 국산 소프트웨어의 품질 향상과 공공 판로 지원을 위해 소프트웨어진흥법에 근거하여 한국정보통신기술협회(TTA, Telecommunications Technology Association) 및 한국산업기술시험원(KTL, Korea Testing Laboratory)에서 소프트웨어의 기능적 적합성, 신뢰성, 효율성 등을 종합 시험·평가하여 품질을 공식 보증하는 국가 인증 제도(GS, Good Software).
- 법적 근거 : 소프트웨어진흥법(소프트웨어 품질인증 관련 조항), 과학기술정보통신부 고시 소프트웨어 품질인증 기준.
- 국제 표준 기반 : ISO(International Organization for Standardization)/IEC(International Electrotechnical Commission) 25023(소프트웨어 제품 품질 측정 기준), ISO/IEC 25051(패키지 소프트웨어 품질 요구사항).

## Ⅱ. GS 인증의 특징

- 핵심 요약 : ISO/IEC 25023 기반 8대 품질 특성 종합 평가와 1등급·2등급 등급 체계.
- ISO/IEC 25023 품질 모델 기반 평가 구조.

```text
[ ISO/IEC 25023 품질 모델 ]
  ├─ 1. 기능 적합성   2. 성능 효율성   3. 호환성
  ├─ 4. 사용성        5. 신뢰성        6. 보안성
  └─ 7. 유지보수성    8. 이식성
        │
        ▼
[ 종합 시험·평가 (TTA/KTL) ] → [ GS 1등급 / 2등급 ]
```

1. 기능 적합성(Functional Suitability)
2. 성능 효율성(Performance Efficiency)
3. 호환성(Compatibility)
4. 사용성(Usability)
5. 신뢰성(Reliability)
6. 보안성(Security)
7. 유지보수성(Maintainability)
8. 이식성(Portability)

- 등급 체계 : 제품 시험 결과와 제품 해설서 등 산출물 심사의 종합을 통한 GS 1등급 및 2등급 구분 부여.

## Ⅲ. GS 인증의 구조 (흐름)

- 핵심 요약 : 신청부터 시험 평가, 심의, 인증서 발급까지의 절차적 흐름.
- GS 인증 획득 절차.

```text
[ 인증 신청 ] (신청 기업)
   │
   ▼
[ 계약 체결 및 제품 입고 ]
 - 실행 파일 및 매뉴얼 접수
   │
   ▼
[ 시험 평가 (TTA/KTL) ]
 - 8대 품질 특성 결함 테스트
 - 제품 결함 보완 (Rework)
   │
   ▼
[ 심의 위원회 ] - 인증 등급 결정
   │
   ▼
[ 인증서 발급 ] (1등급 / 2등급)
```

## Ⅳ. GS 인증 획득 시 법적 혜택 비교

- 핵심 요약 : 공공 조달 우선권부터 정보화 사업 가점까지의 제도적 지원 항목별 혜택.

| 제도적 지원 항목 | 상세 혜택 내용 및 법적 근거 |
|---|---|
| 공공기관 우선구매 대상 지정 | 중소기업제품 구매촉진 및 판로지원에 관한 법률에 따른 우선구매 대상 |
| 조달청 제3자 단가계약 및 종합쇼핑몰 등록 | 나라장터 종합쇼핑몰 우수조달물품 등록 자격 부여 및 수의계약 체결 가능 |
| 상용SW(Software) 분리발주 대상 | 공공 SW 사업 추진 시 SI(System Integration) 통합 발주에서 제외하고 직접구매 의무 적용 |
| 성능인증 시 성능검사 면제 | 중소벤처기업부 성능인증(EPC, Excellent Performance Certification) 신청 시 기술성·성능검사 면제 혜택 |
| 국방 및 공공 정보화 사업 가점 | 국방/공공 정보화 용역 사업 평가 시 제품 품질 및 기술력 평가 가점 |

## Ⅴ. GS 인증의 장점과 한계

- 핵심 요약 : 공공 판로 개척과 품질 신뢰성 이점, 심사 기간·시험 환경·사후 품질 공백의 한계.
- 장점

  1. 국가 보증 품질 마크를 통한 제품 신뢰성 및 브랜드 경쟁력 향상.
  2. 공공기관 우선구매, 나라장터 등록 등 공공 조달 판로 개척.
  3. 시험 평가 피드백(TTA 결함 리포트)을 통한 제품 품질 개선 계기 확보.
- 한계점 1 : 인증 심사 기간 장기화 및 비용 부담으로 인한 출시 지연
  - 한계점 : 신청부터 제품 시험, 보완 조치, 인증서 발급까지 수개월 이상 소요에 따른 적기 릴리스 타이밍 상실.
  - 해결 방안 : 사전 품질 자가진단 툴킷 활용, 표준 시험 산출물 템플릿화, 과기정통부 패스트트랙(신속 시험) 제도 및 시험기관 사전 컨설팅 적극 연계.
- 한계점 2 : 정적 시험 환경과 실제 운영 도메인 환경 간의 괴리
  - 한계점 : ISO/IEC 25023 표준 기반 기능 적합성·성능 중심 시험의 실제 클라우드 분산 환경 및 대규모 트래픽 시나리오 미반영.
  - 해결 방안 : 표준 기능 검증 외 실사용자 유스케이스 기반 카오스 엔지니어링 및 스트레스 테스트 데이터의 심사 보조 지표 제출을 통한 실효성 보강.
- 한계점 3 : 인증 획득 후 CI/CD(Continuous Integration/Continuous Delivery) 지속 배포에 따른 사후 품질 공백
  - 한계점 : 인증 획득 시점의 특정 빌드 버전만 유효하여 애자일 환경의 빈번한 기능 추가·패치 발생 시 법적·품질적 인증 효력 유지 모호.
  - 해결 방안 : 형상관리 변경 영향도 분석 자동화 체계 수립, 메이저 버전과 마이너 버전 변경 시험 간소화 가이드라인 거버넌스 확립.

## Ⅵ. 소프트웨어 기업의 품질 역량 강화를 위한 기술사적 제언

- 핵심 요약 : 인증 이후의 내재적 품질 고도화와 클라우드 SaaS 대응 인증 체계의 선제 준비.
- 인증 획득을 넘어선 제품 내재적 품질 고도화 : 공공 납품용 '인증 딱지' 획득에 대한 안주 지양, TTA 결함 리포트 기반 소프트웨어 아키텍처 리팩토링 및 자동화된 회귀 테스트 스위트 구축 필요.
- 클라우드 SaaS(Software as a Service) 환경에 대응하는 인증 체계 대응 : 구축형(On-Premise) 패키지 중심 기준에서 벗어난 멀티 테넌시, 자동 확장성, SLA(Service Level Agreement) 보장 능력 중심의 클라우드 네이티브 품질 평가 기준과 CSAP(Cloud Security Assurance Program) 보안인증 병행 선제 준비 필요.

## Ⅶ. 결론

- 핵심 요약 : GS 인증은 품질 공식 보증과 공공 조달 자격을 부여하는 국가 품질 제도.
- 요약 : ISO/IEC 25023 기반 8대 품질 특성 시험을 통한 1·2등급 부여 및 우선구매 등 제도적 혜택 연계 체계.
- 시사점 : 심사 리드타임 단축, 실운영 환경 시험 보완, 지속 배포 시대의 인증 유지 거버넌스가 활용 효과 극대화의 관건.
