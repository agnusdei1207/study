## 30초 인출

- 본질: **GS(Good Software) 인증**은 소프트웨어 제품의 품질을 지정 기준에 따라 시험·평가해 인증하는 제도
- 메커니즘: 신청 제품·문서 확인 → 실행 소프트웨어와 설명서 평가 → 등급별 기준 판정 → 인증 결과 발급
- IT 관점: 요구 기능·품질 기준·시험 결과·제품 버전의 추적성 관리

<details>
<summary>핵심 용어</summary>

- **GS 인증(Good Software)**: 「소프트웨어 진흥법」 제20조에 근거해 소프트웨어 제품의 품질을 시험·평가하는 인증 제도
- **ISO/IEC 25023:2016(SQuaRE Product Quality Measurement)**: ISO/IEC 25010 품질 특성에 따라 소프트웨어·시스템 제품 품질을 측정하는 표준
- **ISO/IEC 25010:2023(Product Quality Model)**: ICT·소프트웨어 제품의 품질 특성을 9개 범주로 제시하는 제품 품질 모델
- **ISO/IEC 25051**: 사용 준비가 된 소프트웨어 제품의 품질 요구와 시험 지침을 다루는 표준
- **SP 인증(Software Process)**: 소프트웨어진흥법 제21조에 근거하여 개발 조직의 프로젝트 관리 및 개발 프로세스 성숙도를 평가하는 제도
- **CC 인증(Common Criteria)**: ISO/IEC 15408 기반 국가·공공기관 납품용 정보보호 제품의 보안 기능 및 신뢰성을 평가하는 제도
- **1등급·2등급 GS 인증**: 인증기관의 해당 등급별 평가 기준에 따라 판정되는 인증 등급

</details>

## 1교시 예상문제 (10점)

> GS(Good Software) 인증에 관하여 설명하시오. (예상)

---

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 소프트웨어 제품을 지정 기준에 따라 시험·평가해 인증하는 제도 |
| 목적 | 제품 품질의 객관적 확인과 품질정보 제공 |

### Ⅱ. 평가 및 등급

| 평가 요소 | 내용 |
|---|---|
| 제품 문서 | 제품 설명서와 사용자 취급 설명서의 식별성·일관성·정확성 평가 |
| 실행 제품 | 지정 환경에서 제품 기능 및 품질 특성 시험 |
| 인증 등급 | 신청 등급에 해당하는 인증기관의 평가 기준 충족 여부를 확인 |

### Ⅲ. 인증 절차

```text
신청 제품·제품 설명서
    ↓
제품 문서·실행 기능 시험
    ↓
GS 인증 기준 충족 여부 평가
    ↓
등급·인증 결과 기록
```

**제언:** 평가받은 제품 버전과 문서·시험 결과를 함께 관리.

## 2~4교시 25점 답안

## Ⅰ. 소프트웨어 제품 품질인증의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 소프트웨어 제품을 지정 기준에 따라 시험·평가해 인증하는 제도 |
| 목적 | 제품 품질의 객관적 확인과 품질정보 제공 |

GS는 제품을 평가하는 인증이며, 개발 조직의 프로세스 인증이나 정보보호제품의 보안성 평가와 구별.

```text
GS 인증의 평가 대상
    ├─ 소프트웨어 제품
    ├─ 제품 설명·사용자 문서
    └─ 제품 품질 특성·실행 결과

평가 결과 → 인증 등급 판단
```

**법적 근거:** 「소프트웨어 진흥법」 제20조의 제품 품질인증. 정보시스템 도입 시 인증 제품 버전과 실제 납품 버전의 일치 여부 확인.

## Ⅱ. GS 인증 평가 절차와 품질 기준

### 인증 평가 절차

```text
신청 제품·설명서 확인
    ↓
문서 평가·제품 실행 시험
    ↓
신청 등급 기준 판단
    ├─ 충족 → 인증 결과 발급
    └─ 미충족 → 결함 수정·재평가
```

### 제품 품질 모델과 측정 표준

ISO/IEC 25010:2023은 제품 품질 특성을 9개 범주로 구성하며, ISO/IEC 25023:2016은 25010 특성에 따른 제품 품질 측정 방법을 제시. 25023은 2016년판이 현행판이나 개정안이 개발 중이므로, 시험 적용 시 인증기관의 최신 평가 기준 확인.

| 품질 특성 | 세부 평가 항목 및 검증 기준 |
|---|---|
| **기능 적합성 (Functional Suitability)** | 요구된 기능의 완전성·정확성·적절성 확인 |
| **성능 효율성 (Performance Efficiency)** | 응답 시간과 자원 사용의 요구 충족 확인 |
| **호환성 (Compatibility)** | 다른 제품과의 공존·정보 교환 확인 |
| **상호작용 능력 (Interaction Capability)** | 사용자가 제품과 상호작용하고 목적을 달성하는 특성 확인 |
| **신뢰성 (Reliability)** | 가용성·결함 허용·복구 등 지속 동작 능력 확인 |
| **보안성 (Security)** | 기밀성·무결성·책임성 등 정보 보호 특성 확인 |
| **유지보수성 (Maintainability)** | 변경·분석·시험·수정 용이성 확인 |
| **유연성 (Flexibility)** | 다양한 환경과 요구에 대응하는 능력 확인 |
| **안전성 (Safety)** | 인명·재산·환경에 허용 불가한 위험을 만들지 않는 특성 확인 |
---

## Ⅲ. GS 인증의 범위

| 인증 | 평가 대상 |
|---|---|
| **GS(Good Software)** | 소프트웨어 제품·문서의 품질 |
| SP(Software Process) | 개발 조직·프로젝트의 프로세스 |
| CC(Common Criteria) | 정보보호 제품의 보안 기능·보증 |

GS 인증을 조직 전체의 개발 역량이나 모든 보안 요구 충족의 증거로 확대 해석하지 않음.

## Ⅳ. 적용 한계와 대응

| 한계 | 대응 |
|---|---|
| 제품 설명서와 실제 기능 불일치 | 문서·실행 제품·시험 조건을 같은 버전으로 관리 |
| 평가 환경과 도입 환경 차이 | 도입 환경에서 핵심 기능·성능을 별도로 검증 |
| 인증 뒤 제품 변경 | 변경 영향과 재시험·인증기관 확인 필요 여부 검토 |

## Ⅴ. 제언

```text
인증 제품 버전·문서·시험 결과
             ↓ 식별 정보 연결
도입 제품 버전 대조
             ↓
차이가 있으면 변경 영향·재검증 범위 확인
```

**제언:** 인증서 보유 여부와 함께 실제 도입 버전이 평가받은 제품과 같은지 확인.
