## 1. 30초 인출

- 본질: **GS(Good Software) 인증**은 소프트웨어 제품의 품질을 지정 기준에 따라 시험·평가해 인증하는 제도
- 메커니즘: 신청 제품·문서 확인 → 실행 소프트웨어와 설명서 평가 → 등급별 기준 판정 → 인증 결과 발급
- IT 관점: 요구 기능·품질 기준·시험 결과·제품 버전의 추적성 관리

<details>
<summary>핵심 용어</summary>

- **GS 인증(Good Software)**: 소프트웨어진흥법 제20조에 근거하여 국산 상용 SW의 완성도와 품질을 평가·보증하는 국가 공인 인증제도
- **ISO/IEC 25023:2016(SQuaRE Product Quality Measurement)**: ISO/IEC 25010 품질 특성에 따라 소프트웨어·시스템 제품 품질을 측정하는 표준
- **ISO/IEC 25010:2023(Product Quality Model)**: ICT·소프트웨어 제품의 품질 특성을 9개 범주로 제시하는 제품 품질 모델
- **ISO/IEC 25051(COTS SW Requirements)**: 상용 완제품 패키지 소프트웨어(COTS)의 사용자 매뉴얼 및 제품 설명서 정합성 평가 기준
- **SP 인증(Software Process)**: 소프트웨어진흥법 제21조에 근거하여 개발 조직의 프로젝트 관리 및 개발 프로세스 성숙도를 평가하는 제도
- **CC 인증(Common Criteria)**: ISO/IEC 15408 기반 국가·공공기관 납품용 정보보호 제품의 보안 기능 및 신뢰성을 평가하는 제도
- **1등급·2등급 GS 인증**: 1등급은 품질평가 80점 이상, 2등급은 품질평가 60%와 업무적합성 평가 40%를 합산해 70점 이상인 인증 등급

## 2~4교시 25점 답안

## Ⅰ. 소프트웨어 제품 품질인증의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 소프트웨어 제품을 지정 기준에 따라 시험·평가해 인증하는 제도 |
| 목적 | 제품 품질의 객관적 확인과 품질정보 제공 |

GS는 제품을 평가하는 인증이며, 개발 조직의 프로세스 인증이나 정보보호제품의 보안성 평가와 구별.

```text
GS 인증의 평가 대상
    ├─ 소프트웨어 제품
    ├─ 제품 설명·사용자 문서
    └─ 제품 품질 특성·실행 결과

평가 결과 → 인증 등급 판단
```

### 2. 법적 근거와 정보시스템 품질관리

「소프트웨어 진흥법」 제20조에 따른 제품 품질인증. 정보시스템 발주·도입에서는 요구사항, 시험 결과, 인증 제품 버전의 일치 여부를 확인 자료로 활용.
---

### Ⅱ. GS 인증 평가 메커니즘 및 8대 품질 특성

#### 1. GS 인증 평가 프로세스 및 체계도

```text
신청 제품·설명서 확인
    ↓
문서 평가·제품 실행 시험
    ↓
신청 등급 기준 판단
    ├─ 충족 → 인증 결과 발급
    └─ 미충족 → 결함 수정·재평가
```

#### 2. 제품 품질 모델과 측정 표준

ISO/IEC 25010:2023은 제품 품질 특성을 9개 범주로 구성하며, ISO/IEC 25023:2016은 25010 특성에 따른 제품 품질 측정 방법을 제시. 25023은 2016년판이 현행판이나 개정안이 개발 중이므로, 시험 적용 시 인증기관의 최신 평가 기준 확인.

| 품질 특성 | 세부 평가 항목 및 검증 기준 |
|---|---|
| **기능 적합성 (Functional Suitability)** | 요구된 기능의 완전성·정확성·적절성 확인 |
| **성능 효율성 (Performance Efficiency)** | 응답 시간과 자원 사용의 요구 충족 확인 |
| **호환성 (Compatibility)** | 다른 제품과의 공존·정보 교환 확인 |
| **상호작용 능력 (Interaction Capability)** | 사용자가 제품과 상호작용하고 목적을 달성하는 특성 확인 |
| **신뢰성 (Reliability)** | 가용성·결함 허용·복구 등 지속 동작 능력 확인 |
| **보안성 (Security)** | 기밀성·무결성·책임성 등 정보 보호 특성 확인 |
| **유지보수성 (Maintainability)** | 변경·분석·시험·수정 용이성 확인 |
| **유연성 (Flexibility)** | 다양한 환경과 요구에 대응하는 능력 확인 |
| **안전성 (Safety)** | 인명·재산·환경에 허용 불가한 위험을 만들지 않는 특성 확인 |
---

### Ⅲ. 소프트웨어 품질인증 유형 비교 (GS vs SP vs CC)

| 비교 항목 | GS 인증 (Good Software) | SP 인증 (Software Process) | CC 인증 (Common Criteria) |
|---|---|---|---|
| **평가 대상** | **소프트웨어 완제품 (Product)** | **개발 조직의 프로세스 (Process)** | **정보보호/보안 제품 (Security)** |
| **적용 표준** | ISO/IEC 25023, ISO/IEC 25051 | NIPA SP 인증 기준 고시 | ISO/IEC 15408 (공통평가기준) |
| **주관/시험기관**| 과기정통부 (TTA, KTL) | NIPA (정보통신산업진흥원) | 국가정보원 / KISA 및 공인시험기관 |
| **평가 방식** | 실제 소프트웨어 구동 블랙박스 시험 | 프로세스 산출물 문서 심사 및 현장 실사 | 보안목표명세서(ST) 기반 취약점 분석 |
| **평가 초점** | 제품 문서와 실행 소프트웨어의 품질 | 조직·프로젝트의 개발 프로세스 | 제품의 보안 기능과 보증 근거 |
---

### Ⅳ. GS 인증 취득 및 실무 적용 시 3대 위험 및 대응 전략

| 위험 | 대책 | 효과 |
|---|---|---|
| **매뉴얼-UI 명칭 불일치로 인한 시험 탈락** | 문서-코드 추적성 매트릭스 구축 및 E2E UI 텍스트 자동 검증 파이프라인 연계 | 문서 정합성 결함 방지 및 재시험 비용 절감 |
| **동시 다중 접속 시 응답 지연 기준 미달** | 사전 k6/JMeter 기반 모의 부하 테스트베드 구축 및 쿼리/커넥션 풀 최적화 | GS 인증 성능평가 기준 충족 |
| **인증 버전과 공공 납품 배포 버전 불일치** | CI/CD 파이프라인에 시맨틱 버저닝 및 변경인증 대상 판정 자동화 게이트 적용 | 공공 납품 컴플라이언스 위반 리스크 차단 |
---

### Ⅴ. 기술사적 제언: 요구사항·시험·인증 버전 추적

| 한계 | 해결 방안 |
|---|---|
| 인증 시 평가한 제품 버전과 실제 도입·운영 버전이 달라 품질 확인 근거가 약화될 수 있음 | 요구사항·시험 항목·결함 조치·인증 제품 버전을 형상관리 기준선으로 연결하고, 변경 영향에 따라 재시험 범위 확인 |
