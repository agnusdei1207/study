## 30초 인출

- 본질: GS 인증은 소프트웨어 제품이 품질 요구와 시험 기준을 충족하는지 제3의 시험기관이 평가해 인증하는 국내 소프트웨어 품질인증 제도
- 메커니즘: 인증 신청 후 시험기관이 품질 특성별 시험을 수행하고 결과를 심의해 인증서를 발급하며 사후 관리
- 통찰: 인증을 받은 제품도 이후 개발에서 품질이 변할 수 있으므로 인증 시점의 시험 기준을 자체 품질 게이트로 유지하고 변경 시 재시험 범위를 정함

<details>
<summary>핵심 용어</summary>

- **GS(Good Software) 인증** : 소프트웨어 제품의 품질을 시험·평가해 인정하는 국내 인증 제도
- **소프트웨어 품질인증** : 품질 특성별 시험 결과로 제품 품질을 공식 인정하는 제도
- **ISO/IEC 25010** : 제품 품질 특성을 정의한 품질 모델
- **ISO/IEC 25051** : 상용 소프트웨어 패키지의 품질 요구와 시험 지침 국제표준
- **시험기관** : 시험을 수행하는 제3의 기관
- **품질 게이트** : 단계나 릴리스 전 충족해야 하는 품질 기준

## 2~4교시 25점 답안

## Ⅰ. GS 인증의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **GS 인증** 은 소프트웨어 제품의 품질을 제3의 시험기관이 평가해 인증하는 제도 |
| 목적 | 소프트웨어 제품 품질의 객관적 확인과 이용자 신뢰 확보 |

## Ⅱ. 자체 시험과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 제3자 평가 | 개발사 외부 시험기관의 시험 |
| 표준 기반 | 품질 모델·시험 표준에 따른 평가 |
| 공식 인정 | 인증서 발급으로 공공·민간 도입 신뢰 |

## Ⅲ. 인증 절차와 평가 체계

### 인증 절차

```text
인증 신청
    ↓
시험 계획·시험 수행 (품질 특성별)
    ↓
결과 심의
    ↓
인증서 발급
    ↓
사후 관리
```

### 확대: 품질 특성별 시험

```text
품질 특성
    ├─ 기능 적합성 ── 기능 요구 충족
    ├─ 성능 효율성 ── 응답·자원 사용
    ├─ 사용성·신뢰성·보안성
    └─ 유지보수성·이식성·문서화
```

## Ⅳ. 인증 유형과 관련 제도 비교

| 구분 | GS 인증 | SP 인증 | ISO/IEC 25051 |
|---|---|---|---|
| 대상 | 소프트웨어 제품 | 개발 조직의 프로세스 | 상용 패키지 제품 |
| 평가 방식 | 제품 시험 | 프로세스 심사 | 품질 요구·시험 지침 |
| 목적 | 제품 품질 인정 | 개발 능력 인정 | 국제 표준 기준 제공 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 인증 시점 이후 개발로 품질 변화 | 인증 기준을 자체 품질 게이트로 유지 |
| 인증 준비 부담 | 개발 단계부터 시험 항목 반영 |
| 변경 시 재인증 범위 불명확 | 변경 영향에 따른 재시험 기준 정의 |

## Ⅵ. 제언

인증 시험 항목을 개발 단계의 품질 게이트로 미리 적용하고, 릴리스 변경마다 영향 범위의 재시험을 수행

### 인증 대비 품질 관리

```text
인증 시험 항목 → 개발 품질 게이트에 반영
    ↓
릴리스마다 영향 범위 재시험
    ↓
인증 신청·사후 관리
```

### 선택 근거: 인증 직전 준비와의 비교

| 구분 | 인증 직전 준비 | 제언: 개발 단계 반영 |
|---|---|---|
| 결함 발견 | 시험 단계 | 개발 단계 |
| 준비 부담 | 집중 | 분산 |
| 인증 이후 품질 | 유지 곤란 | 게이트로 유지 |
