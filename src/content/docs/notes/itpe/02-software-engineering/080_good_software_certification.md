## 1. 소프트웨어 품질인증의 개요 및 3대 축

### (1) 소프트웨어 품질인증의 정의
- 공인된 제3자 시험·평가기관이 국제 표준 규격에 따라 소프트웨어 제품의 기능성, 신뢰성, 보안성 및 개발 공정 성숙도를 객관적으로 검증하고 그 적합성을 공적으로 증명하는 제도.

### (2) 소프트웨어 품질인증의 3대 축 분류
1. **제품 품질인증 (Product)**: 완제품 소프트웨어 자체의 품질 특성을 실제 환경에서 시험 (예: **GS 인증** - ISO/IEC 25023).
2. **프로세스 품질인증 (Process)**: 소프트웨어를 개발하는 조직의 프로젝트 관리 및 개발 절차 성숙도를 심사 (예: **SP 인증**, **CMMI**).
3. **보안성 인증 (Security)**: 국가·공공기관에 도입되는 정보보호 제품의 보안 기능 및 안전성 집중 평가 (예: **CC 인증** - ISO/IEC 15408).

## 2. GS(Good Software) 인증 체계 및 평가 기준

### (1) GS 인증 체계 및 혜택 흐름도
```text
+-------------------------------------------------------------------------+
|               GS (Good Software) 인증 체계 및 평가 메커니즘              |
+-------------------------------------------------------------------------+
| [ 법적 근거 : 소프트웨어진흥법 제20조 (소프트웨어 품질인증) ]           |
|                                                                         |
| [ 공인 시험기관 (TTA / KTL) : ISO/IEC 25023 기반 블랙박스 실환경 시험 ]|
|  ├─ 1. 기능적합성  2. 성능효율성  3. 호환성      4. 사용성              |
|  └─ 5. 신뢰성      6. 보안성      7. 유지보수성  8. 이식성              |
|  + 제품설명서 / 사용자매뉴얼 내용과의 일치성(일반요구사항) 전수 검증    |
|                                │                                        |
|                                v (품질 기준 충족 시)                    |
| [ GS 인증서 발급 ] ──▶ 1등급 (전수 시험) / 2등급 (주요 기능 시험)       |
|                                │                                        |
|                                v (법적 제도적 혜택)                     |
| * 공공기관 우선구매 대상 지정 (중소기업 판로지원법)                     |
| * 조달청 우수조달물품 등록 및 나라장터 3자 단가계약 자격 부여           |
| * 공공 소프트웨어 사업 분리발주 대상 선정                               |
+-------------------------------------------------------------------------+
```

### (2) ISO/IEC 25023(SQuaRE) 8대 품질 특성
| 품질 특성 | 영문명 | 세부 평가 항목 및 기준 |
|---|---|---|
| **기능 적합성** | Functional Suitability | 기능 완전성, 기능 정확성, 기능 적절성 (매뉴얼 기재 기능 동작) |
| **성능 효율성** | Performance Efficiency | 시간 반응성(응답시간, 처리량), 자원 활용성(CPU/메모리 점유율) |
| **호환성** | Compatibility | 공존성(타 SW와의 자원 충돌 여부), 상호운용성(인터페이스 연계) |
| **사용성** | Usability | 적절성 인식성, 학습성, 운영 용이성, 사용자 오류 방지, 접근성 |
| **신뢰성** | Reliability | 성숙도, 결함 허용성(장애 시 복구), 가용성(무중단 가동률) |
| **보안성** | Security | 기밀성(암호화), 무결성, 부인방지, 책임추적성, 인증성 |
| **유지보수성** | Maintainability | 모듈성, 재사용성, 분석성, 수정성, 시험성 |
| **이식성** | Portability | 적응성, 설치 용이성, 대체 용이성 (이종 OS/환경 지원) |

## 3. 품질인증 유형 비교 (GS vs SP vs CC)

| 비교 항목 | GS 인증 (Good Software) | SP 인증 (Software Process) | CC 인증 (Common Criteria) |
|---|---|---|---|
| **평가 대상** | **소프트웨어 완성 제품 (Product)** | **개발 조직의 프로세스 (Process)** | **정보보호/보안 제품 (Security)** |
| **적용 표준** | ISO/IEC 25023, ISO/IEC 25051 | SP 인증 기준 (NIPA 고시) | ISO/IEC 15408 (공통평가기준) |
| **주관/인증기관**| 과기정통부 (TTA, KTL) | NIPA (정보통신산업진흥원) | 국가정보원 / 한국인터넷진흥원(KISA) |
| **평가 방식** | 제품 실행을 통한 실제 기능/성능 시험 | 프로세스 문서 심사 및 현장 인터뷰 | 보안목표명세서(ST) 기반 취약점 분석 |
| **주요 혜택** | 공공 우선구매, 조달청 3자 단가계약 | 공공 입찰 기술성 평가 가산점 부여 | 국가·공공기관 보안 제품 납품 필수 요건 |

## 4. 실무 실패 시나리오 및 해결 방안

| 실패 시나리오 | 근본 원인 | 공학적 해결 방안 | 정량적 기대효과 |
|---|---|---|---|
| **매뉴얼-UI 명칭 불일치로 인증 시험 탈락**<br>(3회 연속 결함 통보로 6개월 지연) | 개발 중 변경된 화면 텍스트를 제품설명서와 매뉴얼에 미반영 | 문서-기능 추적성 체크리스트 수립 및 매뉴얼 기반 역추적 E2E 자동화 테스트 | 문서 정합성 결함 0건 달성, 재시험 비용 방어 |
| **동시 접속 50명 시험 시 응답 10초 초과**<br>(성능효율성 기준 미달로 불합격) | 인증 전 부하 시험 부재 및 데이터베이스 비효율 풀스캔 쿼리 방치 | k6/JMeter 기반 모의 GS 부하 테스트베드 구축 및 APM 인덱스 튜닝 | GS 인증 성능평가 기준(응답 2초 이내) 100% 충족 |
| **GS 취득 버전과 실운영 배포 버전 상이**<br>(납품 후 공공기관 감사 지적) | 메이저 기능 수정 후 변경 인증 절차를 누락하고 무단 배포 | CI/CD 파이프라인에 시맨틱 버저닝 및 변경 인증 심의 프로세스 의무화 | 공공 납품 컴플라이언스 위반 리스크 원천 차단 |

## 5. 기술사 답안 차별화 포인트 (기술사의 시각)

```text
[과거: 설치형 패키지 1회성 인증]          [현대: 클라우드 SaaS 패스트트랙 품질인증]
- CD/온프레미스 단일 환경 수동 검수 ──▶   - 멀티테넌트 SaaS 아키텍처 적합성 시험
- 인증 취득 후 코드 변경 방치      ──▶   - CI/CD 변경분에 대한 '지속적 적합성 보증'
- 공공 조달 진입용 형식적 자격증    ──▶   - 글로벌 수출을 위한 ISO 25000 표준 포트폴리오 연계
```

- **클라우드 SaaS 시대에 걸맞은 'SaaS 전용 GS 인증 패스트트랙' 필요성**: 주 단위로 기능이 지속 배포되는 클라우드 네이티브 SaaS 제품에 과거의 3개월 소요 온프레미스 인증 방식을 강요하면 혁신이 저해됨. **API 표준 적합성, 멀티테넌트 데이터 격리, 자동 확장성(Elasticity)**을 중점 검증하는 신속 SaaS 인증 트랙 제도를 기술사적 정책 제언으로 피력해야 함.
- **GS 인증과 공공 소프트웨어 분리발주 제도와의 실무 시너지**: GS 인증을 획득한 상용 SW는 조달청 나라장터 종합쇼핑몰에 3자 단가계약으로 등록되어 수의계약이 가능하며, SI 사업 구축 시 '상용SW 분리발주' 대상이 됨. 이를 통해 중소 SW 기업이 SI 하도급의 굴레에서 벗어나 독자적 라이선스 수익 모델을 창출하는 선순환 산업 생태계 관점을 기술해야 함.
