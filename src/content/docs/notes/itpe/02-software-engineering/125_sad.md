## 연관 키워드

- SAD, ISO/IEC/IEEE 42010, 이해 관계자, 관심사
- 뷰·뷰포인트, ADR, 4+1 뷰

## Ⅰ. 소프트웨어 아키텍처 기술서의 개요

- 핵심 요약 : **SAD**(Software Architecture Description)는 시스템 아키텍처를 이해 관계자의 관심사별 관점으로 기술하고 구조·결정·근거를 남기는 표준 문서 산출물.
- 개념 : 아키텍처를 이해·분석·검토에 필요한 **뷰**(View, 특정 관점에서 본 시스템의 표현)와 모델·결정 근거로 체계화한 문서 산출물.
- 배경 및 필요성 : 아키텍처 정보가 구두·코드에만 존재하면 검토·변경·감리의 근거가 상실하고 이해 관계자별 관점 차이로 단일 기술의 소통 한계 → **ISO/IEC/IEEE 42010**(시스템·소프트웨어 아키텍처 기술의 국제 표준) 기반의 표준 기술 체계 필요.
- 주요 목적 : 아키텍처 공통 기준 확립을 통한 검토·의사 소통·변경 영향 관리·품질 검증 근거의 확보.

## Ⅱ. SAD의 특징 및 장점

- 핵심 요약 : 이해 관계자·관심사에서 뷰 체계와 결정 근거로 연결되는 표현이 설명력·검증 가능성을 확보.

1. 관심사 기반 기술 : 이해 관계자별 질문(기능·운영·배포·보안)을 해소하는 뷰 구성 → 정보 누락·과잉 방지.
2. 뷰포인트 체계 : **뷰포인트**(Viewpoint, 뷰의 작성 규칙·표기법을 정의하는 틀)에 따라 뷰 작성 → 표현의 표준화·일관성.
3. 다중 뷰 구성 : **4+1 뷰**(4+1 View, 논리·프로세스·개발·배포 뷰와 시나리오로 구성되는 뷰 모델) 등 관점별 분할 기술 → 복잡 구조의 이해·검토 용이.
4. 결정 근거 기록 : **ADR**(Architecture Decision Record, 아키텍처 결정의 배경·대안·결과를 기록하는 문서) 연계 → 변경 시 과거 판단의 재평가 가능.

## Ⅲ. SAD의 구조 (흐름)

- 핵심 요약 : 이해 관계자·관심사 식별에서 뷰 작성·정합성 검토를 거쳐 변경 관리로 이어지는 작성 흐름.

```text
[ SAD 작성 흐름 ]

이해 관계자·관심사 식별
   ↓
아키텍처 드라이버 정리
(품질 속성·제약·핵심 기능)
   ↓
뷰포인트·표기법 선정
   ↓
뷰·모델·인터페이스 기술
   ↓
결정 근거 연결·정합성 검토
   ↓
변경 승인과 함께 갱신
```

- 입력 요소 : **아키텍처 드라이버**(Architecture Driver, 품질 속성·주요 제약·핵심 기능처럼 설계를 지배하는 요구)의 먼저 확정 → 뷰 선정·모델 상세 수준의 판단 기준 확보.

```text
[ 4+1 뷰 구성 ]

논리 뷰 · 프로세스 뷰 · 개발 뷰 · 배포 뷰
        ↘    ↓    ↙
      시나리오 ( +1 )
뷰 간 정합성의 검증 기준
```

## Ⅳ. SAD와 문서화 없는 구현 중심 진행의 비교

- 핵심 요약 : 뷰·근거 체계의 SAD와 코드·구현 중심 진행은 의사 소통·결정 추적·변경 관리·검증 근거에서 차이.

| 비교 축 | SAD 기반 문서화 | 문서화 없는 구현 중심 진행 |
| --- | --- | --- |
| 의사 소통 | 이해 관계자별 뷰의 구조·관점 공유 | 구두 설명·개인 코드 의존 |
| 결정 추적 | ADR 등의 배경·대안 보존 | 결정 이력·근거 유실 |
| 변경 관리 | 뷰 기반 영향 범위 추적 | 변경 영향 파악 지연·누락 |
| 검증·감리 | 품질 속성·제약 검토 근거 제공 | 사후 검증 수단 부재 |
| 비용 구조 | 작성·갱신 비용 발생 | 초기 비용 낮으나 재작업·장애 비용 증가 |

## Ⅴ. SAD의 한계와 방안

- 핵심 요약 : 문서 진부화·형식주의·근거 유실을 변경 절차 편입·테일러링·결정 기록으로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 문서 진부화 | 코드·배포 변경 후 뷰 미갱신 → 오류 근거 제공 | 아키텍처 변경 승인 절차에 문서 갱신 편입 | 코드·문서 불일치 건수 |
| 형식주의·과잉 문서화 | 독자·질문 없는 뷰의 작성 → 유지 부담 | 관심사 기반 테일러링·뷰 최소화 | 미사용 뷰 비율 |
| 근거 유실 | 결정 결과만 남고 배경·대안 누락 | 중요 결정의 ADR 작성·요구와의 연계 | 근거 없는 결정 비율 |

## Ⅵ. SAD의 제언

- 핵심 요약 : 아키텍처 거버넌스 체계에서 SAD를 설계·리뷰·감리의 공통 작업물로 운영.

1. 아키텍처 위원회는 이해 관계자별 관심사·검토 시점을 문서 체계에 매핑한 표준 목차·테일러링 지침 운영.
2. 개발 조직은 뷰·ADR을 코드와 동일한 버전 관리 체계에 두고 리뷰·변경 승인과 연동.
3. 품질·감리 조직은 요구·품질 속성·결정·시험 증거의 추적성 표본 점검 체계 운영.

## Ⅶ. SAD의 결론

- 핵심 요약 : SAD는 아키텍처를 이해 관계자의 관심사에 맞는 뷰와 결정 근거로 남기는 표준 기술서.
- 시사점 : 문서 분량보다 이해 관계자 질문의 해소와 변경에 맞춘 갱신이 품질의 기준.
