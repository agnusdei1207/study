## 답안 골격
```text
[힙(Heap)] ◀━━ 머리: Ⅶ 내 의견 (메모리 연속 배열 기반 완전 이진 트리와 캐시 지역성을 고려한 우선순위 큐 설계)
 ┃
 ┣━ Ⅰ 개요 ───── 정렬되지 않은 배열의 극값 탐색 $O(N)$ 병목 → 완전 이진 트리 기반 반정렬 상태 $O(\log N)$ 보장
 ┣━ Ⅱ 특징 ───── 완전 이진 트리 구조 · 부모-자식 간 대소 관계만 정의(반정렬) · 1차원 배열 인덱스 매핑 연산
 ┣━ Ⅲ 구조 ───── 최대 힙(부모 ≥ 자식) / 최소 힙(부모 ≤ 자식) / 배열 인덱스 규칙(왼쪽 $2i$, 오른쪽 $2i+1$)
 ┣━ Ⅳ 흐름 ───── 삽입(말단 추가 후 Up-Heap 상향 선별) → 삭제(루트 추출 후 말단 노드 루트 이동 및 Down-Heap 하향 선별)
 ┣━ Ⅴ 비교 ───── 힙 vs 이진 탐색 트리(BST) vs 우선순위 큐(추상 자료형)
 ┗━ Ⅵ 실무 ───── 대량 데이터 힙 생성 시 재귀 호출 스택 오버플로 / 비재귀 상향식(Bottom-up) 힙 빌드($O(N)$)
```
- 필수 키워드: 완전 이진 트리 · 반정렬(Semi-sorted) · 최대 힙/최소 힙 · Up-Heap/Down-Heap · 우선순위 큐 · 힙 정렬($O(N \log N)$)
- 기출: 124회 1교시 `힙(Heap) 자료구조` → Ⅰ~Ⅳ / 90회 1교시 `최대 힙과 최소 힙` → Ⅲ

## 한 줄 본질
- 전체 정렬($O(N \log N)$)을 매번 수행하는 오버헤드 없이 최댓값·최솟값만 즉시 추출하기 위해 완전 이진 트리의 부모-자식 대소 조건만 유지하는 반정렬 자료구조 → $O(1)$ 극값 조회 및 $O(\log N)$ 삽입/삭제 획득 / 임의 노드 탐색 $O(N)$ 대가

## 핵심 그림
```text
[배열 인덱스 매핑과 최대 힙 트리 구조]
          [1] 90 (루트)
         /      \
      [2] 70     [3] 80
     /     \     /
   [4] 40 [5] 50 [6] 30

배열 배치: [Index 0은 미사용 또는 크기 보관]
Index: |  1  |  2  |  3  |  4  |  5  |  6  |
Value: |  90 |  70 |  80 |  40 |  50 |  30 |
규칙: 부모 i -> 왼쪽 자식 2*i, 오른쪽 자식 2*i+1, 부모 floor(i/2)
```

## 핵심 용어
- 상향 선별(Up-Heap / Sift-Up): 삽입 시 트리의 가장 마지막 리프에 원소를 둔 뒤 부모와 비교하며 루트 방향으로 교환해 올라가는 복구 연산($O(\log N)$)
- 하향 선별(Down-Heap / Sift-Down): 루트 삭제 시 말단 원소를 루트로 옮긴 뒤 두 자식 중 우선순위가 높은 자식과 비교해 교환해 내려가는 복구 연산($O(\log N)$)

## 핵심 통찰
- 힙은 "완전한 정렬이 불필요하고 가장 급한 작업 하나만 반복해서 꺼내는 스케줄러"에 최적화된 자료구조임
- 단순 삽입을 N번 반복하는 힙 생성은 $O(N \log N)$이지만, 리프 노드부터 거꾸로 올라가는 상향식(Bottom-up) 힙 빌드는 수학적으로 $\sum_{h=0}^{\lfloor\log N\rfloor} \frac{N}{2^{h+1}} O(h) = O(N)$에 수렴함
- 배열 기반 완전 이진 트리이므로 포인터 메모리 오버헤드가 없고 CPU 캐시 라인 연속 적재(Spatial Locality) 효율이 극대화됨

## 이웃 토픽과 구분
- 힙 vs 이진 탐색 트리(BST): 힙 = 좌우 자식 간 대소 관계 없음, 극값 탐색 $O(1)$, 완전 이진 트리 강제 / BST = 왼쪽 자식 < 부모 < 오른쪽 자식 엄격 유지, 임의 탐색 $O(\log N)$, 편향 트리 위험

## 문제·원인·대책
- 적용 상황: 대규모 실시간 트래픽 환경의 작업 우선순위 디스패처
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 작업 큐에 데이터 삽입/삭제 시 깊은 재귀로 인한 Call Stack 고갈 | Down-Heap 선별 함수를 재귀 호출 방식으로 순진하게 구현 | 반복문(While 루프) 기반 인덱스 스왑 반복 구조로 전환 | 함수 호출 프레임 오버헤드 제거 및 스택 메모리 안정성 확보 |
| 100만 건 정렬 초기화 시 지연 시간 폭증 | 원소를 하나씩 삽입(Top-down)하여 $O(N \log N)$ 소요 | 비트 연산 기반 상향식(Bottom-up) 선별 배열 자체 힙화 | 힙 초기화 시간 $O(N)$으로 단축 |

## 이렇게 출제된다
- 제124회 1교시: "힙(Heap) 자료구조의 개념과 연산(삽입, 삭제), 그리고 힙 정렬(Heap Sort)의 동작 과정을 설명하시오." → 요구 포인트: 완전 이진 트리 특성 + 1차원 배열 인덱스 연산 + Sift-Up/Sift-Down 추적 + $O(N \log N)$ 복잡도
- 제90회 1교시: "최대 힙(Max Heap)과 최소 힙(Min Heap)의 구조 및 적용 분야를 설명하시오." → 요구 포인트: 대소 관계 정의 + 우선순위 큐 및 다익스트라 최단 경로 적용

## 내 의견
- [우선순위 큐 구현 시 단순 리스트 정렬 남용] 개발 편의를 위해 매번 `List.sort()`를 호출하여 $O(N \log N)$ 낭비를 초래하는 안티패턴 방지 필요 → 나라면: 표준 라이브러리(Java `PriorityQueue`, C++ `priority_queue`)의 힙 기반 자료구조를 표준 컴포넌트로 지정하고, 변경 가능한 우선순위(Decrease-Key)가 빈번한 환경에서는 주소 참조 인덱스를 함께 보관하는 인덱스드 힙(Indexed Heap) 구조 도입
