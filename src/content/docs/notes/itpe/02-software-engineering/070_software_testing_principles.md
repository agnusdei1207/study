## Ⅰ. 소프트웨어 테스팅 7대 원리의 개요

- 핵심 요약 : 테스팅의 본질적 한계를 인정하고 공학적 실천 방향을 제시하는, 국제 자격 체계 기반의 7가지 기본 원리.
- 개념 : 국제 소프트웨어 테스팅 자격 위원회(ISTQB, International Software Testing Qualifications Board)가 정립한 **테스팅 7대 원리** (Seven Testing Principles)는 테스팅의 한계와 실천 방향을 제시하는 7가지 기본 지침이다.
- 배경 및 필요성 : 무제한 시간과 자원을 들여도 모든 입력 조합을 테스트하는 것은 불가능하므로, 한정된 자원으로 테스팅의 효과와 경제성을 높일 현실적 지침이 필요하다.
- 주요 가치 : 완벽성 추구에서 벗어나 위험 중심으로 테스팅을 운영하고, **시프트 레프트** (Shift-Left)로 결함을 앞 단계에서 예방하는 것.

## Ⅱ. 테스팅 7대 원리의 특징

- 핵심 요약 : 결함 존재 증명에서 오류-부재의 궤변까지 상호 연결된 7가지 원리 체계.

1. **결함 존재 증명** (Testing shows presence of defects) : 테스팅은 결함의 존재만 보여 줄 수 있고 부재는 증명하지 못함 → 무결점 선언을 경계.
2. **완벽한 테스팅 불가능** (Exhaustive testing is impossible) : 모든 입력과 사전 조건의 조합을 전수 검증할 수 없음 → 위험 기반의 선별 필요.
3. **조기 테스팅** (Early testing) : 요구분석과 설계 단계부터 테스팅 활동을 시작 → 수정 비용 최소화.
4. **결함 집중** (Defect clustering) : 결함은 소수의 복잡한 모듈에 몰리는 경향(파레토 원칙 80:20) → 고위험 모듈에 자원 집중.
5. **살충제 패러독스** (Pesticide Paradox) : 같은 테스트를 반복하면 새로운 결함을 잡지 못함 → 테스트 케이스의 정기 개정.
6. **정황 의존** (Context-dependent) : 도메인과 비즈니스 환경마다 적합한 테스트 접근이 다름 → 정황별 전략 차등화.
7. **오류-부재의 궤변** (Absence-of-errors Fallacy) : 결함을 모두 없애도 사용자 요구를 충족하지 못하면 가치가 없음 → 사용자 관점의 검증 병행.

## Ⅲ. 테스팅 7대 원리의 구조 (흐름)

- 핵심 요약 : 원리 간 전제와 파생 관계, 그리고 요구분석부터 운영까지 이어지는 전 주기 테스팅 체계.

```text
[ 7대 원리의 전제와 파생 관계 ]
결함 존재 증명 + 완벽한 테스팅 불가능
   ↓ 전제로 삼아 자원 배분
조기 테스팅 + 결함 집중
   ↓ 반복 실행에 따른 내성
살충제 패러독스 → 테스트 케이스 개정
   ↓ 정황에 맞춘 전략 차등
정황 의존 → 도메인별 전략
   ↓ 결함 제거만으로는 부족
오류-부재의 궤변 → 사용자 가치 검증
```

- 용어 설명 : TDD(Test-Driven Development)는 테스트를 먼저 작성하는 개발 방식이고, BDD(Behavior-Driven Development)는 행위 명세를 기준으로 하는 개발 방식이며, APM(Application Performance Monitoring)은 운영 중 애플리케이션 성능을 관찰하는 활동이다.

```text
[ 전 주기 테스팅 체계 ]
요구분석·설계 : 인스펙션, 검토
   ↓ 시프트 레프트 (원리 3)
구현 : TDD·BDD 기반 단위 테스트
   ↓
테스트 : 시스템·인수 테스트
   ↓ 시프트 라이트
운영 : 카나리 배포, 카오스 테스트, APM
```

- 원리 3과 원리 4의 결합 : 조기 테스팅으로 수정 비용을 낮추면서, 결함이 몰린 모듈을 먼저 검증.
- 원리 5와 원리 6의 결합 : 살충제 패러독스를 피하려고 테스트 케이스를 개정하되, 도메인 정황에 따라 전략을 나눔.

## Ⅳ. 7대 원리별 상세 내용 및 실무 대응 전략 비교

- 핵심 요약 : 원리마다 흔한 오해를 바로잡고, 그에 맞는 실무 엔지니어링 대응 전략을 짝지어 보는 것이 핵심.

| 테스팅 원리 | 핵심 개념 및 오해 | 실무 엔지니어링 대응 전략 |
| --- | --- | --- |
| 1. 결함 존재 증명 | 테스트는 결함의 존재만 증명, 부재는 증명 불가 | 무결점 선언 지양, 테스트 결과 보고 시 잔존 위험(Residual Risk) 정량화 |
| 2. 완벽한 테스팅 불가 | 모든 입력과 사전 조건 조합의 테스트는 불가능 | 위험 기반 테스팅과 우선순위화로 핵심 경로에 집중 |
| 3. 조기 테스팅 | 요구분석과 설계 단계부터 테스팅을 시작해야 함 | V-모델 적용, 정적 검토(인스펙션), TDD·BDD 기반 조기 결함 차단 |
| 4. 결함 집중 | 대다수 결함이 소수 핵심 모듈에 집중(파레토 80:20) | 과거 결함 지표를 추적해 고위험 모듈에 테스트 자원 집중 배분 |
| 5. 살충제 패러독스 | 같은 테스트 케이스 반복 시 새 결함 검출 불가 | 테스트 케이스 정기 개정, 뮤테이션 테스팅과 탐색적 테스팅 병행 |
| 6. 정황 의존 | 도메인과 비즈니스 환경마다 테스트 접근이 다름 | 의료·자율주행은 MC/DC(Modified Condition/Decision Coverage) 등 엄격한 기준, 웹 앱은 사용성과 성능 중심 |
| 7. 오류-부재의 궤변 | 결함 제거만으로는 사용자 요구와 비즈니스 기대를 충족 못 함 | 기술적 결함 제거를 넘어선 사용자 관점의 인수 테스트와 가치 검증 |

## Ⅴ. 테스팅 7대 원리 적용의 장점과 한계

- 핵심 요약 : 테스팅의 경제성과 효과성을 높이는 장점과, 원리의 면책 악용·검출력 감쇠·가치 불일치라는 한계가 공존.

- 장점
  1. 제한된 자원에서 테스팅의 경제성과 효과성을 높임.
  2. 결함 예방 중심의 조기 검증 문화를 정착시킴.
  3. 도메인 정황에 맞는 테스트 전략 수립의 기준을 제공.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 완벽한 테스팅 불가능 원리의 면책 수단 악용 | 결함 부재를 증명할 수 없다는 점을 책임 회피에 쓰거나, 반대로 경영진이 결함 0을 요구하는 모순 발생 | **위험 기반 테스팅** (RBT, Risk-Based Testing)으로 비즈니스 치명도가 높은 모듈에 자원 집중, 사전에 합의한 **종료 기준** (Exit Criteria) 준수 | 잔존 위험 등급, 종료 기준 달성률 |
| 살충제 패러독스에 따른 자동화 회귀 테스트의 검출력 감소 | 같은 자동화 케이스를 반복 실행해 새로운 유형의 결함을 놓침 | 정기적인 케이스 리뷰와 시나리오 추가, **뮤테이션 테스팅** (Mutation Testing)으로 테스트 유효성 평가, 탐색적 테스팅 병행 | 신규 결함 검출 건수, 뮤턴트 생존율 |
| 오류-부재의 궤변에 따른 비즈니스 가치 불일치 | 결함을 모두 제거하고 명세를 100% 충족해도 실제 사용자 요구를 충족하지 못함 | 명세 검증(Verification)을 넘어 사용자 가치 검증(Validation), 프로토타입과 카나리 배포 기반의 실사용자 피드백 루프 운영 | 사용자 만족도, 기능 사용률 |

## Ⅵ. 테스트 프로세스 혁신을 위한 기술사적 제언

- 핵심 요약 : 시프트 레프트와 시프트 라이트를 결합한 전 주기 체계와, 무작위 입력과 장애 주입으로 정형 케이스의 한계를 보완하는 방향.

1. 시프트 레프트와 시프트 라이트의 결합 : 요구사항 인스펙션과 단위 테스트를 앞당기는 시프트 레프트와, 운영 환경의 카나리 배포와 APM 관측을 결합하는 시프트 라이트를 함께 설계해야 프로덕션 결함을 이중으로 막을 수 있다.
2. 정형 케이스의 한계 보완 : 고정된 테스트 케이스만으로는 살충제 패러독스를 피하기 어려우므로, 무작위 입력을 넣는 **퍼징** (Fuzzing)과 서버·네트워크 단절을 유도하는 **카오스 엔지니어링** (Chaos Engineering)을 연계해 시스템의 회복 탄력성을 검증해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 7대 원리는 테스팅의 한계를 인정한 채 자원을 위험 중심으로 배치하는 공학적 지도 원리다.
- 시사점 : 원리를 면책 수단으로 쓰는 일을 막고 전 주기 테스팅과 가치 검증을 갖춰야 테스팅의 비즈니스 기여가 커진다.
