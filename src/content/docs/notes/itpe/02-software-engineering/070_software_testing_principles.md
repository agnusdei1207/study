- 정황 의존, 오류-부재의 궤변, 시프트 레프트(Shift-Left)

## Ⅰ. 소프트웨어 테스팅 7대 원리의 개요

- 핵심 요약 : 테스팅의 본질적 한계와 공학적 실천 방향을 제시하는 국제 표준 자격 체계 기반의 7가지 기본 공리.
- 개념 : 국제 소프트웨어 테스팅 자격 위원회(ISTQB, International Software Testing Qualifications Board)가 소프트웨어 테스팅의 본질적 한계와 공학적 실천 방향 제시를 위해 정립한 7가지 기본 공리이자 지도 원리.
- 배경 및 필요성 : 무제한의 시간·자원 투입으로 모든 가능한 경우의 수를 테스트하는 것이 물리적으로 불가능하므로, 테스팅의 경제성·효과성 극대화를 위한 현실적 지침 필요.
- 주요 가치 : 비현실적 완벽성 추구의 지양, 결함 예방 중심 시프트 레프트(Shift-Left)의 실현.

## Ⅱ. 테스팅 7대 원리의 특징

- 핵심 요약 : 결함 존재 증명부터 오류-부재의 궤변까지 상호 연계된 7가지 원리 체계.
1. 결함 존재 증명(Testing shows presence of defects) : 테스팅은 결함의 존재만을 증명하며 부재는 증명 불가.
2. 완벽한 테스팅 불가능(Exhaustive testing is impossible) : 모든 입력·사전 조건 조합의 전수 검증 불가.
3. 조기 테스팅(Early testing) : 요구분석·설계 단계부터의 테스팅 착수.
4. 결함 집중(Defect clustering) : 소수 복잡 모듈에 결함의 집중(파레토 80:20).
5. 살충제 패러독스(Pesticide paradox) : 동일 테스트 반복 시 신규 결함 검출력 상실.
6. 테스팅은 정황 의존(Context-dependent) : 도메인·비즈니스 환경별 상이한 접근법.
7. 오류-부재의 궤변(Absence-of-errors fallacy) : 결함 제거만으로 사용자 가치 보장 불가.

## Ⅲ. 테스팅 7대 원리의 구조 (흐름)

- 핵심 요약 : 원리 간 전제·파생 관계와 전 주기 테스팅 체계의 연계 구조.

```text
[ 7대 원리의 상호 연계 구조 ]
[ 1. 결함 존재 증명 ]
[ 2. 완벽한 테스팅 불가능 ]
   │
   ▼
[ 3. 조기 테스팅 ] ──> [ 4. 결함 집중 ]
 (초기 수정 비용 최소화)  (파레토 법칙)
   │
   ▼
[ 5. 살충제 패러독스 ]
 - 동일 테스트 반복 시 내성 → TC(Test Case) 지속 개선
   │
   ▼
[ 6. 테스팅은 정황에 의존 ]
 - 금융·의료 시스템 vs 게임 앱의 상이 접근
   │
   ▼
[ 7. 오류-부재의 궤변 ]
 - 결함이 없어도 가치 없으면 무용지물
```

```text
[ 전 주기 테스팅 체계 ]
요구분석 ──> 설계 ──> 구현 ──> 테스트 ──> 운영
 인스펙션    검토      TDD/BDD   시스템·인수   카나리·카오스·APM
 ── 시프트 레프트(원리 3) ──>   ── 시프트 라이트 ──>

 * TDD(Test-Driven Development), BDD(Behavior-Driven Development),
   APM(Application Performance Monitoring)
```

- 원리 3과 원리 4의 결합 : 조기 테스팅으로 초기 수정 비용 최소화와 결함 집중 모듈의 선제 검증 동시 달성.
- 원리 5와 원리 6의 결합 : 살충제 패러독스 극복을 위한 테스트 케이스 개정과 도메인 정황별 전략 차별화.

## Ⅳ. 7대 원리별 상세 내용 및 실무 대응 전략 비교

- 핵심 요약 : 각 원리별 오해 교정과 실무 엔지니어링 대응 전략의 매핑.

| 테스팅 원리 | 핵심 개념 및 오해 | 실무 엔지니어링 대응 전략 |
|---|---|---|
| 1. 결함 존재 증명 | 테스트는 결함 존재만 증명 가능, 부재 증명 불가 | 무결점 선언 지양, 테스트 결과 보고 시 잔존 위험(Residual Risk) 정량화 |
| 2. 완벽한 테스팅 불가 | 모든 입력·사전 조건 조합의 테스트 불가능 | 위험 분석(Risk-based Testing)·우선순위화를 통한 핵심 경로 집중 |
| 3. 조기 테스팅 | 요구분석·설계 단계부터 테스팅 착수 필요 | V-모델 적용, 정적 검토(인스펙션), BDD(Behavior-Driven Development)/TDD(Test-Driven Development) 기반 조기 결함 차단 |
| 4. 결함 집중 | 대다수 결함의 소수 핵심 모듈 집중(파레토 80:20) | 과거 결함 메트릭 추적을 통한 고위험 모듈 테스트 자원 집중 배분 |
| 5. 살충제 패러독스 | 동일 테스트 케이스 반복 시 신규 결함 검출 불가 | 테스트 케이스 정기 개정, 뮤테이션 테스트(Mutation Testing)·탐색적 테스팅 병행 |
| 6. 정황에 의존 | 도메인·비즈니스 환경별 상이한 테스트 접근법 | 의료·자율주행의 엄격한 MC/DC(Modified Condition/Decision Coverage)·안전성 테스트, 웹 앱의 사용성·성능 집중 |
| 7. 오류-부재의 궤변 | 결함 제거만으로 사용자 요구·비즈니스 기대 충족 불가 | 기술적 결함 제거를 넘어선 사용자 관점 인수 테스트·가치 검증 |

## Ⅴ. 테스팅 7대 원리 적용의 장점과 한계

- 핵심 요약 : 테스팅 경제성·효과성 극대화의 가치와 원리 오용·검출력 감쇠·가치 불일치의 한계 공존.
- 장점
  1. 제한된 자원에서의 테스팅 경제성·효과성 극대화.
  2. 결함 예방 중심 조기 검증 문화의 정착.
  3. 도메인 정황에 부합하는 테스트 전략 수립 기준 제공.
- 한계점 1 : 완벽한 테스팅 불가능 원리의 면책 수단 악용 및 품질 타협
  - 한계점 : 결함 부재 증명 불가능성의 오해로 프로덕션 장애 발생 시 테스트 팀 책임 회피 논리 남용, 반대로 경영진의 결함 0(Zero-defect) 강요 모순 발생.
  - 해결 방안 : 위험 기반 테스팅(RBT, Risk-Based Testing) 체계 수립을 통한 비즈니스 치명도 상위 모듈 자원 집중, 사전 합의된 정량적 테스트 종료 기준(Exit Criteria) 준수.
- 한계점 2 : 살충제 패러독스 기인 자동화 회귀 테스트 결함 검출력 감쇄
  - 한계점 : 동일한 자동화 회귀 테스트 케이스의 반복 실행으로 신규 유형 결함 미검출, 테스트 스위트 결함 검출 효용성 급락.
  - 해결 방안 : 정기적 테스트 케이스 리뷰·신규 시나리오 추가, 돌연변이 테스팅(Mutation Testing) 기반 테스트 유효성 평가, 직관·경험 활용 탐색적 테스팅(Exploratory Testing) 병행.
- 한계점 3 : 오류-부재의 궤변 기인 비즈니스 가치 불일치
  - 한계점 : 시스템 결함 전부 제거·명세서 요구사항 100% 충족에도 실제 사용자 니즈·비즈니스 사용성 미충족으로 시장 외면 실패 발생.
  - 해결 방안 : 명세 검증(Verification)을 넘어선 사용자 가치 검증(Validation), 조기 프로토타이핑·지속적 A/B 테스팅·카나리 배포 기반 실사용자 피드백 루프의 개발 생명주기 통합.

## Ⅵ. 테스트 프로세스 혁신을 위한 기술사적 제언

- 핵심 요약 : 시프트 레프트·시프트 라이트의 결합과 카오스 엔지니어링·퍼징 도입.
- 시프트 레프트(Shift-Left)와 시프트 라이트(Shift-Right)의 결합 : 요구사항 인스펙션·단위 테스트 조기화의 시프트 레프트와, 실운영 환경의 카나리 배포·카오스 엔지니어링·APM 관측성 기반 프로덕션 결함 방어의 시프트 라이트를 결합한 전 주기 테스팅 체계 확립.
- 살충제 패러독스 극복을 위한 카오스 엔지니어링·무작위 퍼징(Fuzzing) 도입 : 정형화된 테스트 케이스 한계의 극복, 무작위 예외 입력 주입 퍼징과 프로덕션 서버·네트워크 단절 유발 카오스 테스트의 연계를 통한 시스템 회복탄력성 극대화.

## Ⅶ. 결론

- 핵심 요약 : 7대 원리는 테스팅의 한계를 인정하는 가운데 자원을 지혜롭게 배치하는 공학적 지도 원리.
- 요약 : 전수 테스팅 불가능 전제 하의 위험 기반 집중, 조기 검증, 지속 개선, 정황 적응, 가치 검증의 체계.
- 시사점 : 원리의 면책 남용 방지와 전 주기 테스팅 체계 구축으로 테스팅의 비즈니스 가치 기여 극대화 필요.
