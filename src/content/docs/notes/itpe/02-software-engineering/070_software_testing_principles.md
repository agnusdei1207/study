## 30초 인출

- 본질: 소프트웨어 테스팅 7대 원리는 테스트의 한계와 효과적 수행 방법을 일곱 가지로 정리한 원칙(ISTQB)
- 메커니즘: 결함 존재 증명·전수 테스트 불가·초기 테스트·결함 집중·살충제 패러독스·정황 의존·오류 부재의 궤변으로 테스트 범위와 우선순위를 판단
- 통찰: 전수 테스트가 불가능하고 결함이 일부 모듈에 몰리므로 위험과 결함 이력을 기준으로 테스트 우선순위를 정하고 케이스를 주기적으로 갱신

<details>
<summary>핵심 용어</summary>

- **테스팅 원리(Testing Principles)** : 테스트의 한계와 효율적 수행을 위한 일반 원칙
- **ISTQB(International Software Testing Qualifications Board)** : 소프트웨어 테스팅 자격을 운영하는 국제 기구. 7대 원리를 정리
- **결함 집중(Defect Clustering)** : 결함의 대부분이 소수 모듈에 몰리는 현상
- **살충제 패러독스(Pesticide Paradox)** : 같은 테스트를 반복하면 더 이상 새 결함을 찾지 못하는 현상
- **오류 부재의 궤변(Absence-of-Errors Fallacy)** : 결함을 모두 고쳐도 요구를 충족하지 못하면 쓸모없다는 원리
- **위험 기반 테스팅(Risk-Based Testing)** : 위험이 큰 영역에 테스트 노력을 우선 배분하는 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. 테스팅 7대 원리의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **테스팅 7대 원리** 는 테스트의 한계와 효과적 수행 방법을 일곱 가지로 정리한 원칙 |
| 목적 | 테스트 범위·우선순위·수행 방식 판단의 기준 제공 |

## Ⅱ. 테스팅 원리의 특징

| 특징 | 의미 |
|---|---|
| 한계 인식 | 테스트가 결함 부재를 증명하지 못함 |
| 효율 지향 | 제한된 자원의 효과적 배분 |
| 일반 원칙 | 프로젝트 유형과 무관하게 적용 |

## Ⅲ. 7대 원리의 구조

### 일곱 가지 원리

```text
1. 결함이 있음을 밝히는 활동 (결함 부재는 증명 불가)
2. 완벽한 테스팅은 불가능 (전수 테스트 불가)
3. 초기 테스팅 (개발 초기부터 수행)
4. 결함 집중 (소수 모듈에 결함 집중)
5. 살충제 패러독스 (같은 테스트는 효과 감소)
6. 정황 의존 (도메인·환경에 따라 다르게)
7. 오류 부재의 궤변 (결함 없어도 요구 미충족이면 무의미)
```

### 확대: 원리를 적용한 우선순위 판단

```text
전수 불가(2) + 결함 집중(4)
    ↓
위험·결함 이력이 큰 모듈 우선 테스트
    ↓
살충제 패러독스(5) 대응: 케이스 주기 갱신
```

## Ⅳ. 원리별 의미와 대응

| 원리 | 의미 | 대응 |
|---|---|---|
| 결함이 있음을 밝힘 | 결함 발견 활동이며 부재 증명은 불가 | 결함 발견 기준의 케이스 설계 |
| 전수 테스트 불가 | 입력 조합은 사실상 무한 | 위험 기반 우선순위 |
| 초기 테스팅 | 늦을수록 수정 비용 증가 | 요구·설계 검토 |
| 결함 집중 | 결함이 일부에 편중 | 결함 이력 모듈의 집중 테스트 |
| 살충제 패러독스 | 반복 시 효과 감소 | 케이스 검토·갱신 |
| 정황 의존 | 안전 시스템과 웹 서비스는 접근이 다름 | 특성별 기법 선택 |
| 오류 부재의 궤변 | 요구 충족이 최종 목적 | 사용자 요구 기반 인수 테스트 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 모든 기능을 같은 깊이로 시험해 자원 낭비 | 위험·결함 이력 기반 우선순위 |
| 같은 케이스 반복으로 결함 미발견 | 케이스 주기 갱신과 새 기법 적용 |
| 후반 테스트로 수정 비용 증가 | 초기 단계 검토·테스트 설계 착수 |

## Ⅵ. 제언

위험과 결함 이력을 기준으로 테스트 우선순위를 정하고, 회차마다 케이스를 갱신

### 우선순위 기반 운영

```text
위험·결함 이력 분석
    ↓
우선순위 높은 모듈 집중 테스트
    ↓
결과로 케이스 갱신 → 우선순위 재산정
```

### 선택 근거: 균등 배분과의 비교

| 구분 | 균등 배분 | 제언: 위험 기반 |
|---|---|---|
| 자원 사용 | 분산 | 위험 영역에 집중 |
| 결함 발견 | 저하 | 향상 |
| 케이스 유지 | 고정 | 갱신 |
