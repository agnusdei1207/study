## 연관 키워드

- 서비스 워커(Service Worker), 프록시, PWA, 오프라인 캐시
- Cache Storage, 수명 주기, fetch 이벤트, 캐싱 전략, 백그라운드 동기화, 푸시 알림

## Ⅰ. 서비스 워커의 개요

- 핵심 요약 : 서비스 워커는 웹 페이지와 네트워크 사이에서 요청을 가로채 응답을 결정하는 이벤트 기반 브라우저 프록시.
- 개념 : 브라우저가 페이지와 별도의 워커 문맥에서 실행하고 네트워크 요청을 가로채 응답 출처를 대신 결정하는 스크립트를 **서비스 워커** (Service Worker)라 하며, 이 중재 위치 때문에 **프록시**(클라이언트와 서버 사이에서 요청을 대신 처리하는 매개)로 설명된다.
- 배경 및 필요성 : 전통적 웹 앱은 요청마다 네트워크 도달에 의존하는 구조라 연결 단절 시 화면 제공이 불가능하고, 네이티브 앱 대비 사용 경험에서 열위가 존재했다.
- 주요 목적 : 네트워크 상태와 무관한 웹 이용 보장과 설치·오프라인 사용 경험을 지원하는 **프로그레시브 웹 앱** (PWA, Progressive Web App)의 기반 확보.

## Ⅱ. 서비스 워커의 특징 및 장점

- 핵심 요약 : 네트워크 중재·분리된 수명 주기·오프라인 캐시가 응답성과 복원력이라는 장점으로 연결되는 구조.

1. 네트워크 중재 : **fetch 이벤트** (페이지의 네트워크 요청마다 발생하는 서비스 워커 이벤트)에서 요청을 검사한 뒤 응답 출처를 정책으로 선택 → 응답 방식을 애플리케이션이 통제하는 효과.
2. 분리된 수명 주기 : 등록→설치→대기→활성화의 **수명 주기** (워커 상태 전환의 단계적 절차)를 문서와 독립적으로 진행 → 신구 버전 전환이 안정적인 효과.
3. 오프라인 캐시 : **Cache Storage** (요청과 응답 쌍을 저장하는 브라우저 캐시 저장소)에 자원을 보관하는 **오프라인 캐시** → 재방문·단절 상황에서 즉시 화면 제공 효과.
4. 백그라운드 동작 : **백그라운드 동기화** (연결 복원 시점에 작업을 실행하도록 예약하는 기능)와 **푸시 알림** (서버 발송 메시지를 사용자에게 표시하는 기능) 지원 → 페이지 종료 후에도 작업이 이어지는 효과.
5. 보안 경계 : 보안 문맥(HTTPS, Hypertext Transfer Protocol Secure)과 스코프(적용 디렉터리 범위) 제약 하에서만 등록 → 통제된 범위에서만 네트워크 중재가 일어나는 효과.

## Ⅲ. 서비스 워커의 구조 (흐름)

- 핵심 요약 : 수명 주기 단계를 거쳐 활성화된 뒤 fetch 이벤트로 요청을 중재하고, 자원 유형별 캐싱 전략을 적용하는 구조.
- 수명 주기와 요청 중재가 핵심 흐름이며, 자원 유형에 따라 다섯 가지 **캐싱 전략** (응답을 캐시와 네트워크 중 어느 쪽에서 먼저 가져올지 정한 정책)을 선택한다.

```text
[서비스 워커 수명 주기]

등록 (register)
   ↓
설치 (install) - 핵심 자원 사전 캐시
   ↓
대기 (waiting) - 기존 워커 종료 대기
   ↓
활성화 (activate) - 구 버전 캐시 정리
   ↓
fetch 이벤트로 요청 중재
```

```text
[요청 중재 흐름]

페이지의 자원 요청 발생
   ↓
fetch 이벤트 진입
   ↓
Cache Storage 확인
   ↓
캐시 응답 또는 네트워크 응답 선택
```

- 전략 선택 기준은 자원 성격에 따른 응답 순서이다.

| 캐싱 전략 | 응답 순서 | 적용 자원 예시 |
| --- | --- | --- |
| 캐시 우선 | 캐시 → 미스 시 네트워크 | 앱 셸, 정적 자원 |
| 네트워크 우선 | 네트워크 → 실패 시 캐시 | 실시간 데이터 API |
| 재검증 후 캐시 | 캐시 즉시 응답 후 갱신 | 잦은 갱신 콘텐츠 |
| 캐시 전용 | 캐시 응답만 | 버전 고정 자원 |
| 네트워크 전용 | 네트워크 응답만 | 캐시 부적합 요청 |

## Ⅳ. 서비스 워커와 전통 서버 렌더링 의존 웹의 비교

- 핵심 요약 : 모든 요청을 서버가 답하는 구조에서 클라이언트 캐시가 먼저 답하는 구조로의 전환이 핵심 차이.

| 비교 축 | 서비스 워커 적용 웹 | 전통 서버 렌더링 의존 웹 |
| --- | --- | --- |
| 응답 위치 | 클라이언트 캐시가 우선 응답 | 서버 응답에 의존 |
| 오프라인 대응 | 저장 자원으로 화면 제공 | 연결 단절 시 이용 불가 |
| 재방문 성능 | 보관 자원 재사용 | 자원 재수신 필요 |
| 서버 부하 | 반복 요청을 캐시가 흡수 | 전 요청이 서버 집중 |
| 갱신 방식 | 수명 주기 기반 버전 전환 | 배포 시점 즉시 반영 |

## Ⅴ. 서비스 워커의 한계와 방안

- 핵심 요약 : 캐시 부패·갱신 지연·입력 유실·백그라운드 불확실성을 버전 정책과 재시도 체계로 관리하는 원칙.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 오래된 자원 제공 | 캐시 보존 기간 과다 → 신구 버전 기능 불일치 | 버전별 캐시 분리와 만료 정책 수립 | 신구 버전 혼재 건수 |
| 업데이트 반영 지연 | 새 워커의 대기 상태 지속 | 갱신 안내 UX와 즉시 전환 조건 검토 | 갱신 반영 소요 시간 |
| 오프라인 입력 유실 | 전송 전 연결 종료 → 사용자 데이터 손실 | 로컬 영속 저장 후 재전송 체계 | 데이터 손실 건수 |
| 백그라운드 불확실성 | 워커 수명이 브라우저 정책에 좌우 | 백그라운드 동기화 재시도 위임 | 동기화 실패율 |

## Ⅵ. 서비스 워커에 대한 기술사적 제언

- 핵심 요약 : PWA 전환을 개발·품질·운영 조직의 표준과 정책 체계로 내재화하는 방향.
- 도입 : 프런트엔드 조직이 자원 유형별 캐시 정책과 수명 주기 처리 방식을 아키텍처 결정 기록과 코딩 표준으로 먼저 정의.
- 확산 : 품질 조직이 오프라인·갱신·동기화 시나리오를 출시 게이트의 회귀 시험 체계에 편입해 전 서비스로 확산.
- 거버넌스 : 운영 조직이 캐시 이상 시의 원격 갱신·비활성화 절차와 저장 공간 사용 기준을 운영 정책으로 상시 관리.

## Ⅶ. 결론

- 핵심 요약 : 서비스 워커는 웹을 네트워크 의존에서 분리하는 PWA의 핵심 계층.
- 시사점 : 캐시 통제 권한의 확대만큼 버전 관리와 사용자 데이터 보호가 함께 요구되는 기술.
