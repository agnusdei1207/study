## 지식 로드맵 내 현재 위치

지식 위치: 소프트웨어공학 → 공공 소프트웨어 조달 및 사업 관리 → **원격지 개발**

---

## 30초 인출

- 본질: **원격지 개발** 은 「소프트웨어 진흥법」 제49조 및 관련 고시에 근거하여, 발주기관이 개발 인력을 기관 내부로 강제 상주시키던 불합리한 관행을 철폐하고, 국가정보보안 기본지침의 보안 요건을 충족하는 경우 수주 사업자가 제시한 작업 장소에서 원격으로 소프트웨어를 수행하도록 보장하는 제도
- 메커니즘: 제안요청서(RFP) 보안 요건 명시 → 사업자의 작업 장소 제안 → 보안성 및 적합성 상호 협의 확정 → VDI/VPN 기반 원격 개발 환경 구축 → 형상관리 및 온라인 협업 도구 기반 진척·인수 관리
- 통찰: 물리적 상주 배제에 따른 소통 부재와 소스코드/개인정보 유출 위험이 존재하므로 망분리 및 클라우드 가상 데스크톱(VDI), 제로 트러스트(Zero Trust) 접근 제어와 함께 CI/CD 기반 산출물 자동 동기화 체계를 결합해야 성공적인 원격 개발이 가능함

<details>
<summary>핵심 용어</summary>

- **소프트웨어 진흥법 제49조** : 공공 SW 사업 수행 시 수주 사업자가 제시하는 작업 장소를 우선 검토하도록 강제한 법률 조항
- **상주 개발 관행** : 지방 이전 공공기관 등에 개발 인력을 강제로 파견·상주시킴으로써 체재비 증가와 인력 이탈을 초래하던 불합리한 개발 형태
- **가상 데스크톱 인프라 (VDI)** : 서버 가상화 기술을 통해 중앙 데이터센터의 가상 PC 환경에서만 코딩하고 로컬 단말기로는 화면만 전송받는 보안 기술
- **제로 트러스트 (Zero Trust)** : '절대 신뢰하지 않고 항상 검증한다'는 원칙 하에 사용자 신원과 단말기 보안 상태를 매 접속마다 다중 인증하는 보안 모델
- **시큐어 코딩 (Secure Coding)** : 소스코드 보안 취약점을 제거하기 위해 행안부 47개 보안 약점 기준을 준수하여 원격지에서 개발하는 코딩 기법

</details>

## 2~4교시 예상문제 (25점)

> 공공 소프트웨어 사업에서 「원격지 개발」 제도의 도입 배경과 법적 근거를 설명하고, 작업장소 협의 절차, 원격지 개발 환경의 보안 요건(관리적·물리적·기술적 보안), 성공적인 사업 관리를 위한 온라인 협업 및 품질 보증 방안을 제시하시오.

---

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 공공 SW 사업 추진 시 발주기관 내부 사무실에 상주하지 않고, 보안 요건을 구비한 사업자의 사옥이나 원격 개발 센터에서 사업을 수행하는 방식 |
| 목적 | 지방 이전에 따른 개발자의 원거리 파견·체재비 부담 완화, 개발 생산성 향상, 우수 SW 개발 인력의 공공 사업 참여 유도 |

## Ⅱ. 핵심 특징

발주처 중심의 폐쇄적 파견 통제에서 '보안 기반의 산출물 중심 자율 관리'로 패러다임 전환.

| 핵심 영역 | 법적/기술적 메커니즘 | 실무 효과 |
|---|---|---|
| **사업자 제안 장소 우선** | SW 진흥법 제49조에 따라 사업자가 제시한 작업 장소를 우선 검토 | 발주처의 일방적인 구내 상주 강요 금지 |
| **보안 기준 동등성** | 공공기관 내부망 수준의 망분리, 암호화, 접근 통제 기술 적용 | 원격지에서도 국가정보원 보안 가이드라인 100% 충족 |
| **산출물 기반 진척 관리** | 출퇴근 감시가 아닌 Git 커밋, 이슈 트래커, 주간 빌드 산출물로 평가 | 객관적 진척도 측정 및 불필요한 대면 보고 최소화 |
| **클라우드 개발 환경** | VDI(가상 데스크톱) 및 SaaS 기반 형상관리/협업 도구 활용 | 로컬 PC로의 소스코드 무단 반출 원천 차단 |

## Ⅲ. 체계·프로세스

원격지 개발 협의 절차 및 보안 접속 아키텍처.

```text
+---------------------------------------------------------------------------------------------------------+
|                                    원격지 개발 협의 절차 및 보안 개발 체계                               |
+---------------------------------------------------------------------------------------------------------+
                                                                                                           
  [1] RFP 공고 단계 ──> [2] 제안서 제출 ──> [3] 작업장소 협의 ──> [4] 계약 체결 ──> [5] 원격 개발 착수   
                                                                                                           
  ── [원격지 보안 개발 아키텍처 (VDI & 제로 트러스트 기반)] ──────────────────────────────────────────────
                                                                                                           
  [ 원격지 개발 센터 (사업자 사옥) ]                          [ 공공 발주기관 클라우드 데이터센터 ]        
  +───────────────────────────────────+                       +─────────────────────────────────────────+  
  | 개발자 단말기 (Zero Client / PC)  |                       |  보안 게이트웨이 (VPN / SDP 제로트러스트)|  
  | - 화면만 전송 수신 (화면 캡처 방지)|                       +────────────────────┬────────────────────+  
  | - USB/프린터 등 매체 제어 (DLP)   |                                            │ SSL/TLS 전용선 암호화 
  +─────────────────┬─────────────────+                                            ▼                       
                    │                                         +─────────────────────────────────────────+  
                    │ 2차 추가 인증 (MFA OTP)                 |  개발망 VDI 팜 (Virtual Desktop Farm)   |  
                    └────────────────────────────────────────>|  - 가상 개발 PC 환경 (IDE, 빌드 도구)   |  
                                                              +────────────────────┬────────────────────+  
                                                                                   │                       
                                                                                   ▼ 내부 전용망 연결      
                                                              +─────────────────────────────────────────+  
                                                              |  형상관리 / CI 서버 (GitLab & Jenkins)   |  
                                                              |  - 코드 반출 시 발주처 관리자 사전 승인 |  
                                                              +─────────────────────────────────────────+  
```

- **원격지 개발 협의 4단계 프로세스**:
  1. **요건 제시(RFP)** : 발주기관은 제안요청서에 필수 보안 요건(국가정보보안기본지침 등)을 명확히 명시.
  2. **장소 제안(Proposal)** : 입찰 사업자는 보안 요건을 충족하는 원격 작업 장소와 보안 대책을 제안서에 포함하여 제출.
  3. **상호 협의(Negotiation)** : 기술 협상 단계에서 제안 장소의 보안 실사를 수행하고 최종 작업 장소를 상호 합의 확정.
  4. **보안 인프라 가동(Operation)** : SSL-VPN, VDI, 매체 제어 솔루션을 배포하고 개발자별 권한 부여 및 작업 개시.

## Ⅳ. 종류·비교

#### 전통적 상주 개발 vs 원격지 개발 비교

| 비교 항목 | 전통적 상주 개발 (On-site) | 원격지 개발 (Remote Development) |
|---|---|---|
| **개발 장소** | 발주기관 구내 파견 상주 | 사업자 사옥, 제3의 원격 개발 센터, 재택(VDI) |
| **비용 구조** | 숙박비, 체재비, 파견 수당 등 부대비용 과다 발생 | 부대비용 절감, 순수 R&D 인건비 투입 극대화 |
| **인력 수급** | 지방 파견 기피로 인한 초급/대체 인력 투입 위험 | 본사 고급 핵심 인력의 지속적 투입 가능 |
| **관리 방식** | 근태 및 출퇴근 중심의 주관적 통제 | Git 커밋, 이슈 트래커, 빌드 산출물 중심 통제 |
| **보안 통제** | 물리적 출입 통제 위주 | VDI, SDP, 제로 트러스트, DRM 등 기술적 통제 |

#### 원격지 개발 3대 보안 통제 요건

| 보안 영역 | 세부 통제 항목 | 필수 적용 기술 및 절차 |
|---|---|---|
| **관리적 보안** | 보안 서약서 징구, 인력 교체 관리, 정기 보안 교육 | 입퇴사 시 계정 즉시 회수, 월간 보안 감사 로그 검토 |
| **물리적 보안** | 시건장치, CCTV 설치, 외부인 출입 통제, 전용 개발실 | 원격지 개발 센터 내 지문/카드 출입 통제기 운영 |
| **기술적 보안** | 화면 워터마크, 매체 제어(DLP), 망분리, 소스 반출 통제 | VDI 기반 개발 환경, 소스코드 다운로드 차단, MFA 다중 인증 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 발주처 담당자의 대면 소통 선호 및 진척 불안감으로 인한 관행적 상주 요구 고수 | 스프린트 단위 화상 데모 회의 정례화 및 실시간 대시보드(Jira)를 통한 진척 투명성 제공 |
| 개발자 PC를 통한 소스코드, 고객 개인정보 등 중요 기밀 데이터의 외부 유출 위험 | 가상 데스크톱(VDI) 도입으로 로컬 저장 원천 차단 및 클라우드 소스코드 반출 승인 프로세스 의무화 |
| 원격지 개발 승인 후 발주기관의 불시 현장 보안 점검 시 미비점 지적으로 인한 분쟁 | 발주기관과 사업자가 합동으로 '원격지 개발 보안 체크리스트'를 사전 서명하고 정기 자가 점검 수행 |

## Ⅵ. 제언

원격지 개발의 성공적 정착을 위해서는 제안요청서 단계부터 원격 개발을 기본(Default)으로 상정하고, 공공 클라우드 기반의 표준 개발 플랫폼(VDI + DevOps)을 발주기관이 제공하는 제도적 지원 체계 확립이 필요.

```text
[공공 클라우드 SaaS 개발망 구축] ──> [원격지 제로 트러스트 접속] ──> [CI/CD 자동 품질/보안 검사] ──> [비대면 감리/인수]
    (VDI + GitLab 표준 템플릿)            (MFA OTP & 단말기 검증)            (시큐어코딩 린트 자동화)         (산출물 기반 완료)
```

| 추진 영역 | 권장 실천 과제 | 기대 성과 |
|---|---|---|
| **인프라 표준화** | 공공 클라우드(CSAP 인증) 기반 원격 개발 플랫폼 템플릿 배포 | 개발 환경 셋업 기간 2주 $\rightarrow$ 1일 단축 |
| **보안 고도화** | SDP(Software Defined Perimeter) 기반 제로 트러스트 인프라 적용 | 비인가 단말기 접근 원천 차단 및 통신 패킷 전수 암호화 |
| **제도 개선** | 발주기관 평가지표에 '원격지 개발 승인율' 가점 반영 | 공공 SW 사업의 원격지 개발 적용률 80% 이상 확대 |
