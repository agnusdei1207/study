소프트웨어 공학 → 공공 SW 사업 → **원격지 개발**

## 30초 인출

- 본질: 원격지 개발은 개발자가 발주기관에 상주하지 않고 사업자 사무실 등 떨어진 장소에서 개발하는 방식
- 메커니즘: 개발 환경과 데이터는 보안이 통제된 원격 접속(가상 데스크톱 등)으로 제공하고 형상·이슈 관리와 정기 협의로 협업하며 산출물을 검수
- 통찰: 원격 개발은 정보 유출과 소통 지연의 위험이 있으므로 접속 환경을 통제하고 형상·이슈 관리와 정기 점검 체계를 갖추어 상주 개발과 같은 관리 수준을 유지

<details>
<summary>핵심 용어</summary>

- **원격지 개발** : 발주기관이 아닌 사업자 사무실 등 원격지에서 소프트웨어를 개발하는 방식
- **상주 개발** : 개발 인력이 발주기관 사무실에서 개발하는 방식
- **가상 데스크톱(VDI, Virtual Desktop Infrastructure)** : 서버의 가상 PC를 원격으로 사용하게 해 데이터가 단말에 남지 않도록 하는 구조
- **제로 트러스트(Zero Trust)** : 접속을 항상 검증하는 보안 원칙
- **시큐어 코딩(Secure Coding)** : 소스 코드의 보안 취약점을 만들지 않도록 개발하는 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. 원격지 개발의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **원격지 개발** 은 개발자가 발주기관 밖의 장소에서 개발하는 방식 |
| 목적 | 개발 인력의 상주 부담 감소와 개발 환경의 효율적 운영 |

## Ⅱ. 상주 개발과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 장소 분리 | 개발 장소와 발주기관의 분리 |
| 접속 기반 | 원격 접속으로 개발 환경 이용 |
| 관리 방식 변화 | 대면 관리에서 도구·정기 협의로 전환 |

## Ⅲ. 원격지 개발 구조와 관리 흐름

### 원격 개발 환경 구조

```text
개발자(원격지)
    ↓ 보안 접속 (VPN·VDI, 접근 통제)
발주기관 개발 환경 ── 소스·데이터 (원격지에 저장하지 않음)
    ↔ 형상·이슈 관리 도구
```

### 확대: 협업·검수 흐름

```text
정기 협의 → 형상·이슈 관리로 진척 확인
    ↓
산출물 제출 → 발주기관 검수 → 승인
```

## Ⅳ. 상주와 원격지의 비교

| 구분 | 상주 개발 | 원격지 개발 |
|---|---|---|
| 협업 | 대면 | 도구·회의 |
| 보안 통제 | 물리적 통제 | 접속·단말 통제 |
| 인력 부담 | 이동·상주 부담 | 감소 |
| 위험 | 인력 상주 부담 | 정보 유출, 소통 지연 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 원격 접속을 통한 정보 유출 | 가상 데스크톱과 제로 트러스트 기반 접근 통제 |
| 소통 지연과 진척 확인 곤란 | 형상·이슈 관리 도구와 정기 협의 |
| 보안 취약한 코드 유입 | 시큐어 코딩과 취약점 점검 |

## Ⅵ. 제언

원격 개발 환경은 데이터가 원격지에 남지 않는 구조로 접속을 통제하고, 형상·이슈 관리와 정기 점검으로 상주 개발과 같은 수준의 관리 유지

### 통제 구조

```text
접근 통제(VDI·최소 권한)
    + 형상·이슈 관리
    + 정기 점검·검수
```

### 확대: 위반 대응

```text
접속·행위 로그 점검
    ├─ 이상 징후 → 접속 차단·조사
    └─ 정상 → 유지
```

### 선택 근거: 통제 없는 원격 개발과의 비교

| 구분 | 통제 없는 원격 | 제언: 접속·관리 통제 |
|---|---|---|
| 정보 유출 위험 | 큼 | 통제 |
| 진척 파악 | 곤란 | 도구로 확인 |
| 산출물 품질 | 편차 | 정기 점검 |
