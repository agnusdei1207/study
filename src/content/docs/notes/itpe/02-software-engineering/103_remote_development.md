## 연관 키워드

- 원격지 개발(Remote Development), 소프트웨어진흥법, VDI(Virtual Desktop Infrastructure), VPN(Virtual Private Network)
- ALM(Application Lifecycle Management), 스마트워크센터, 보안 통제, 파견 체재비, DLP(Data Loss Prevention)

## Ⅰ. 원격지 개발의 개요

- 핵심 요약 : 발주기관 사무실 상주 없이 사업자 자체 사업장에서 네트워크로 수행하는 소프트웨어 개발 방식.
- 개념 : 공공 및 민간 소프트웨어 개발 사업에서 수주 사업자가 발주기관의 사무실에 상주하지 않고, 사업자 자신의 상시 사업장이나 제3의 독립된 원격 사무실에서 네트워크(VDI, VPN)를 통해 프로젝트를 수행하는 유연한 소프트웨어 개발 방식.
- 배경 및 필요성 : 공공 발주기관의 불필요한 사업자 상주 요구로 인한 개발자 파견 비용(체재비) 부담, 열악한 파견 근무 환경에 따른 고급 기술자 이탈, 수도권 외 지방 이전 기관의 SW(Software) 인력 확보 난항 해소 필요.
- 주요 목적 : 사업자 비용 절감, 고급 기술자 유입 확대, 지역 인프라 활용한 분산 개발 생태계 조성.

## Ⅱ. 원격지 개발의 특징

- 핵심 요약 : 작업장소 우선 제안권, VDI/VPN 보안 통제, ALM 기반 기록형 소통이 결합된 유연 개발 체계.

1. 작업장소 우선 제안권 : 소프트웨어진흥법에 따라 수주 사업자는 입찰 제안 시 원격지 개발 장소를 우선적으로 제안할 수 있으며, 발주기관은 보안상 중대한 사유가 없는 한 이를 원칙적으로 승인해야 함.
2. 논리적 보안 통제 : 국가정보원 '국가정보보안기본지침'에 따른 VPN 또는 망분리 가상데스크톱(VDI), MFA(Multi-Factor Authentication, 2차 인증), 단말기 매체제어(DLP), 화면 워터마크 적용.
3. 기록형 의사소통 : ALM 도구(Jira, Confluence, 슬랙) 기반의 공식 기록 중심 협업으로 구두 지시로 인한 과업 변경 분쟁 방지.
4. 독립 사업장 활용 : 스마트워크센터 등 제3의 독립된 원격 사무실에서 개발 수행.

## Ⅲ. 원격지 개발의 구조 (흐름)

- 핵심 요약 : 제안, 승인, 보안 접속, 개발, 산출물 검증의 절차 흐름과 계층적 보안 아키텍처로 구성.
- 원격지 개발 절차 흐름.

```text
[ 입찰 제안서 제출 ]
  - 원격지 개발 장소 우선 제안
    │
    ▼
[ 발주기관 승인 검토 ]
  - 보안상 중대한 사유 여부 확인
    │
    ├─ 승인 -> [ 원격지 개발 수행 ]
    │            - ALM 기반 과업 지시 및 기록
    │            - VDI/VPN 접속 개발
    │            │
    │            ▼
    │          [ 산출물 검증 및 납품 ]
    │
    └─ 불승인 -> [ 상주 개발 전환 ] (예외)
```

- 계층적 보안 접속 아키텍처.

```text
[ 개발자 단말기 ]
  - 화면 캡처 방지, 매체 제어
  - 로컬 파일 다운로드 차단
    │
    ▼
[ SSL-VPN / VDI 접속 클라이언트 ]
    │ 공중망: TLS(Transport Layer Security) 1.3 암호화 전용 터널
    ▼
[ 보안 WAF(Web Application Firewall) / IPS(Intrusion Prevention System) ]
    │
    ▼
[ 발주기관 내부망 / 클라우드 센터 ]
  - VDI 서버 팜(가상 데스크톱)
    │
    ▼
[ 통합 개발/형상 서버 ]
  - Git(Git Repository) 레포지토리, CI/CD(Continuous Integration/Continuous Delivery) 러너
```

## Ⅳ. 상주 파견 개발과 원격지 개발의 비교

- 핵심 요약 : 물리적 상주 대신 논리적 보안 통제와 디지털 거버넌스로 전환한 개발 운영 체계.

| 비교 항목 | 전통적 상주 개발(On-Site) | 원격지 개발(Remote Development) |
|---|---|---|
| 근무 장소 | 발주기관 사옥 내 지정된 개발실 | 수주 사업자 본사 또는 제3의 스마트워크센터 |
| 사업자 비용 | 파견 체재비(숙박, 출장비) 및 상주 비용 과다 발생 | 사업자 자체 인프라 활용으로 불필요한 고정비 절감 |
| 인력 수급 | 지방 파견 기피로 인한 초급 인력 투입 위험 | 고급/전문 기술자의 유연한 참여로 생산성 향상 |
| 소통 방식 | 대면 구두 지시, 잦은 과업 외 부당 지시 노출 | ALM 기반의 기록형 의사소통 |
| 보안 관리 | 물리적 출입 통제 중심 | VDI/VPN 암호화 및 논리적 보안 모니터링 중심 |

## Ⅴ. 원격지 개발의 장점과 한계

- 핵심 요약 : 비용 절감과 인력 확보의 장점, 보안 리스크와 커뮤니케이션 왜곡의 한계 공존.
- 장점
  1. 파견 체재비 및 상주 비용 절감으로 사업자 경쟁력 강화.
  2. 고급 기술자의 유입 확대로 개발 품질 및 생산성 향상.
  3. 지역 인프라 활용한 분산 개발 생태계 조성.
- 한계점 1 : 소스코드 및 공공 데이터 유출 리스크
  - 한계점 : 개발자가 외부 사업장에서 작업함에 따라 단말기 해킹, 인가되지 않은 USB(Universal Serial Bus) 반출, 소스코드 유출 등 정보보안 위협 증대.
  - 해결 방안 : 망분리 기반 VDI 및 클라우드 개발환경(GitHub Codespaces, Coder) 적용, 로컬 데이터 저장 금지 및 제로 트러스트(Zero Trust) 통제.
- 한계점 2 : 비대면 협업에 따른 커뮤니케이션 왜곡
  - 한계점 : 발주자와 사업자 간 물리적 거리로 인해 즉각적인 질의응답이 어렵고, 업무 맥락 공유 부족으로 요구사항 오해 및 재작업 빈발.
  - 해결 방안 : 협업 도구(Slack, Notion, Miro) 기반 일일 비동기 스탠드업 정례화, 프로토타입 기반 주기적 화상 데모 및 요구사항 확정 세션 의무화.
- 한계점 3 : 발주기관의 원격 작업 관리 감독 불신
  - 한계점 : 공공 발주기관의 상주 개발 관행 잔존, 원격 개발 승인 요건의 까다로움으로 인해 제도 도입 취지 퇴색.
  - 해결 방안 : 공공SW 원격지 개발 가이드라인 준수 실적 평가 반영, 산출물 및 커밋 이력 기반의 객관적 성과 평가 지표(대시보드) 제공으로 상호 신뢰 구축.

## Ⅵ. 원격지 개발에 대한 기술사적 제언

- 핵심 요약 : 과업 지시 서면화와 보안 가이드라인 표준화로 제도 실효성 제고 필요.
- 과업 지시의 서면화 및 ALM 기반 투명한 진척 관리 : 원격지 개발 환경에서는 대면 구두 지시로 인한 과업 변경 분쟁을 방지하기 위해 모든 요구사항 변경과 이슈 처리를 Jira 티켓으로 공식화하는 디지털 거버넌스 수립 필수.
- 보안 요건의 합리적 가이드라인 표준화 : 발주기관이 보안을 이유로 원격지 개발을 부당하게 거부하지 못하도록, 클라우드 VDI 기반의 보안 표준 템플릿(국정원 보안성 검토 통과 모델)을 사전 공표하여 공공 SW 원격지 개발 비율을 실질적으로 끌어올려야 함.

## Ⅶ. 결론

- 핵심 요약 : 원격지 개발은 보안 통제와 디지털 거버넌스가 전제된 유연 개발 체계.
- 요약 : 소프트웨어진흥법의 작업장소 우선 제안권을 기반으로 발주기관 상주 없이 사업자 자체 사업장에서 네트워크를 통해 개발을 수행하는 방식.
- 시사점 : 성공적인 정착을 위해 VDI/VPN 보안 통제, ALM 기반 기록형 소통, 객관적 성과 평가 체계의 3요소 병행 필요.
