## 연관 키워드

- 원격지 개발(Remote Development), 소프트웨어진흥법, VDI(Virtual Desktop Infrastructure), VPN(Virtual Private Network)
- ALM(Application Lifecycle Management), 스마트워크센터, 보안 통제, 파견 체재비, DLP(Data Loss Prevention)

## Ⅰ. 원격지 개발의 개요

- 핵심 요약 : 발주기관 사무실에 상주하지 않고 사업자 사업장이나 독립 원격 사무실에서 네트워크로 수행하는 소프트웨어 개발 방식.
- 개념 : 수주 사업자가 발주기관 사무실에 상주하지 않고, 자신의 사업장이나 **스마트워크센터** (독립된 원격근무 사무 공간)에서 가상 데스크톱 인프라(VDI, Virtual Desktop Infrastructure)와 가상 사설망(VPN, Virtual Private Network)으로 접속해 프로젝트를 수행하는 **원격지 개발** (Remote Development) 방식.
- 배경 및 필요성 : 발주기관의 상주 요구로 생기는 **파견 체재비** 부담, 열악한 상주 환경으로 인한 고급 기술자 이탈, 수도권 밖 지역의 개발 인력 확보 난항을 해소할 필요가 있었다.
- 주요 목적 : 사업자 비용을 줄이고 고급 기술자의 참여를 늘리며, 지역 인프라를 활용한 분산 개발 생태계를 만드는 것.

## Ⅱ. 원격지 개발의 특징 및 장점

- 핵심 요약 : 작업 장소 제안 권한, 논리적 보안 통제, 기록형 소통이 결합된 유연한 개발 체계.

1. 작업장소 제안권 : **소프트웨어진흥법**에 따라 수주 사업자는 입찰 때 원격지 개발 장소를 제안할 수 있고, 발주기관은 보안상 중대한 사유가 없으면 이를 원칙적으로 승인 → 상주 없이도 개발 수행 가능.
2. **보안 통제** (Security Control) : 망분리 가상 데스크톱과 VPN 접속, 다중 인증(MFA, Multi-Factor Authentication), 단말기 매체 제어와 **DLP**(Data Loss Prevention, 데이터 유출 방지), 화면 워터마크를 적용 → 소스코드와 데이터의 외부 유출 경로 차단.
3. 기록형 의사소통 : ALM(Application Lifecycle Management) 도구에 과업 지시와 변경 내역을 공식 기록 → 구두 지시로 인한 과업 변경 분쟁 방지.
4. 독립 사업장 활용 : 상주 사무실 대신 독립된 원격 사무실을 쓰므로 사업자의 고정비가 줄고 인력 접근성이 넓어짐.

## Ⅲ. 원격지 개발의 구조 (흐름)

- 핵심 요약 : 제안과 승인, 보안 접속, 개발, 산출물 검증의 절차 흐름과 이를 떠받치는 계층형 보안 접속 구조.

```text
[ 입찰 제안서 제출 ]
 원격지 개발 장소 우선 제안
          ↓
[ 발주기관 승인 검토 ]
 보안상 중대한 사유 확인
          ↓
  승인               불승인
[ 원격지 개발 ]   [ 상주 개발 전환 ]
```

```text
[ 원격지 개발 수행 ]
 ALM 기반 과업 지시와 기록
          ↓
 VDI/VPN 접속으로 개발
          ↓
[ 산출물 검증 및 납품 ]
```

- 계층 구조 : 개발자 단말기에서 VPN 또는 VDI 클라이언트를 거쳐 WAF(Web Application Firewall)와 IPS(Intrusion Prevention System)를 통과한 뒤, 내부망의 가상 데스크톱 서버와 형상 서버에 접속한다.

```text
[ 개발자 단말기 ]
 화면 캡처 방지, 매체 제어
          ↓ 암호화 터널
[ VPN / VDI 접속 클라이언트 ]
          ↓
[ 웹 방화벽 · 침입 방지 ]
          ↓
[ 발주기관 내부망 / 클라우드 센터 ]
 VDI 서버 팜
          ↓
[ 통합 개발·형상 서버 ]
 Git 저장소, 빌드·배포 러너
```

## Ⅳ. 상주 파견 개발과 원격지 개발의 비교

- 핵심 요약 : 물리적 상주를 논리적 보안 통제와 디지털 거버넌스로 바꾼 개발 운영 체계.

| 비교 항목 | 전통적 상주 개발(On-Site) | 원격지 개발(Remote Development) |
| --- | --- | --- |
| 근무 장소 | 발주기관 사옥 내 지정 개발실 | 사업자 본사 또는 독립 원격 사무실 |
| 사업자 비용 | 파견 체재비와 상주 비용 과다 | 자체 인프라 활용으로 고정비 절감 |
| 인력 수급 | 지방 파견을 꺼려 초급 인력 투입 위험 | 고급 기술자의 유연한 참여로 생산성 향상 |
| 소통 방식 | 대면 구두 지시, 과업 외 지시 노출 | ALM 기반의 기록형 의사소통 |
| 보안 관리 | 물리적 출입 통제 중심 | VDI·VPN 암호화와 논리적 보안 모니터링 중심 |

## Ⅴ. 원격지 개발의 장점과 한계

- 핵심 요약 : 비용 절감과 인력 확보의 장점과 함께, 정보 유출 리스크, 소통 왜곡, 발주기관의 불신이 한계로 공존한다.

1. 파견 체재비와 상주 비용을 줄여 사업자의 경쟁력을 높임.
2. 고급 기술자의 참여가 늘어 개발 품질과 생산성이 향상됨.
3. 지역 인프라를 활용한 분산 개발 생태계를 만듦.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 소스코드·데이터 유출 | 외부 사업장에서 작업하면서 단말기 해킹, 비인가 USB 반출 등 위협 증대 | 망분리 기반 VDI와 클라우드 개발 환경 적용, 로컬 저장 금지와 제로 트러스트(Zero Trust) 통제 | 반출 시도 차단 건수, 로컬 저장 위반 건수 |
| 커뮤니케이션 왜곡 | 물리적 거리로 즉각적인 질의가 어렵고 맥락 공유가 부족해 요구사항 오해와 재작업 발생 | 비동기 일일 스탠드업 정례화, 프로토타입 기반 주기적 화상 데모와 요구사항 확정 세션 | 재작업 비율, 요구사항 변경 건수 |
| 발주기관의 불신 | 상주 개발 관행 잔존과 까다로운 승인 요건으로 제도 취지가 퇴색 | 가이드라인 준수 실적을 평가에 반영, 커밋 이력 기반의 객관적 성과 지표 제공 | 원격 승인 처리 기간, 원격 개발 비율 |

## Ⅵ. 원격지 개발에 대한 기술사적 제언

- 핵심 요약 : 과업 지시의 서면화와 보안 기준의 표준화로 원격지 개발 제도의 실효성을 높이는 방향.

1. 원격 환경에서는 대면 구두 지시가 사라지므로, 모든 요구사항 변경과 이슈 처리를 ALM 도구의 공식 티켓으로 남기는 디지털 거버넌스를 계약 조건에 명시해야 한다.
2. 발주기관이 보안을 이유로 원격지 개발을 부당하게 거부하지 못하도록, 클라우드 VDI 기반의 보안 표준 템플릿을 사전에 공표하고 그 템플릿을 공통 개발 환경으로 인정하는 절차를 마련해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 원격지 개발은 보안 통제와 디지털 거버넌스가 전제된 유연한 개발 체계.
- 시사점 : 소프트웨어진흥법상 작업장소 제안 권한을 실효성 있게 쓰려면 VDI·VPN 보안 통제, ALM 기록형 소통, 객관적 성과 평가 체계를 함께 갖춰야 한다.
