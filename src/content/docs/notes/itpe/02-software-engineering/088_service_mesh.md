## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 설계·아키텍처 → **서비스 메시(Service Mesh)**

## 30초 인출

- 본질: 서비스 메시는 마이크로서비스 사이의 통신을 애플리케이션 코드 밖의 프록시 계층에서 제어하는 인프라 계층
- 메커니즘: 각 서비스 옆의 사이드카 프록시(데이터 플레인)가 통신을 가로채 라우팅·암호화·관측을 수행하고 컨트롤 플레인이 정책을 배포
- 통찰: 서비스마다 재시도·암호화·추적을 코드에 넣으면 구현이 제각각이므로 통신 정책을 컨트롤 플레인에서 일괄 정의하되 프록시 추가로 지연과 운영 부담이 늘어남을 감안해 적용 범위를 정함

<details>
<summary>핵심 용어</summary>

- **서비스 메시(Service Mesh)** : 서비스 간 통신을 프록시 계층에서 제어·관측하는 인프라
- **사이드카 프록시(Sidecar Proxy)** : 서비스와 함께 배치되어 그 서비스의 통신을 대신 처리하는 프록시
- **데이터 플레인(Data Plane)** : 실제 서비스 간 트래픽을 처리하는 프록시 집합
- **컨트롤 플레인(Control Plane)** : 프록시에 라우팅 규칙·보안 정책을 배포하는 관리 계층
- **mTLS(Mutual TLS)** : 통신 양쪽이 인증서로 서로를 확인하고 암호화하는 방식
- **서킷 브레이커(Circuit Breaker)** : 장애 서비스 호출을 차단해 연쇄 장애를 막는 장치

</details>

## 2~4교시 25점 답안

## Ⅰ. 서비스 메시의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **서비스 메시** 는 서비스 간 통신을 프록시 계층에서 제어·관측하는 인프라 계층 |
| 목적 | 통신 정책·보안·관측의 일관된 적용 |

## Ⅱ. 라이브러리 방식과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 코드 밖 처리 | 애플리케이션 수정 없이 통신 기능 적용 |
| 언어 독립 | 서비스 구현 언어와 무관 |
| 중앙 정책 | 컨트롤 플레인에서 일괄 관리 |

## Ⅲ. 서비스 메시의 구조

### 서비스 메시 구조

```text
컨트롤 플레인 ── 정책·인증서 배포
        ↓
[서비스A + 사이드카] ⇄ [서비스B + 사이드카] ⇄ [서비스C + 사이드카]
        (데이터 플레인: 사이드카 프록시 간 통신)
```

### 확대: 서비스 호출 시 사이드카 처리

```text
서비스A 호출 → 사이드카A: mTLS 암호화·라우팅·재시도
    ↓
사이드카B: 인증 확인·지표 수집 → 서비스B
```

## Ⅳ. 주요 기능과 API 게이트웨이와의 비교

### 주요 기능

| 기능 | 내용 |
|---|---|
| 트래픽 관리 | 라우팅·부하 분산·재시도·카나리 |
| 보안 | mTLS와 서비스 간 접근 정책 |
| 관측 | 지표·로그·분산 추적 |
| 복원력 | 타임아웃·서킷 브레이커 |

### API 게이트웨이와의 비교

| 구분 | API 게이트웨이 | 서비스 메시 |
|---|---|---|
| 위치 | 외부와 내부의 경계(남북 방향) | 서비스 간 내부 통신(동서 방향) |
| 주 기능 | 인증·제한·라우팅 | 서비스 간 보안·복원력·관측 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 사이드카 추가로 지연과 자원 사용 증가 | 적용 서비스 범위 선정과 성능 시험 |
| 컨트롤 플레인 운영 복잡도 | 관리형 서비스 활용과 정책 표준화 |
| 오설정 시 통신 장애가 전체로 전파 | 정책 단계적 배포와 롤백 준비 |

## Ⅵ. 제언

통신 정책이 중요하고 서비스 수가 많은 영역부터 서비스 메시를 적용하고, 단계적으로 정책을 배포

### 단계적 적용

```text
적용 대상 선정 (서비스 수·보안 요구)
    ↓
관측 기능부터 적용
    ↓
mTLS·트래픽 정책 단계 확대
```

### 선택 근거: 서비스별 라이브러리 구현과의 비교

| 구분 | 서비스별 라이브러리 | 제언: 서비스 메시 |
|---|---|---|
| 정책 일관성 | 서비스마다 상이 | 중앙 정의 |
| 언어 제약 | 있음 | 없음 |
| 운영 부담 | 코드에 분산 | 메시 운영 필요 |
