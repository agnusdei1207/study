## 연관 키워드
- SOLID, SRP, OCP, LSP, ISP, DIP, 조합

### Ⅰ. 객체지향 설계원칙 SOLID의 개요

- 핵심 요약 : SOLID는 객체지향 설계의 책임 분리·확장성·대체가능성·인터페이스 분리·의존성 방향을 설명하는 다섯 원칙.
- 개념 : 객체지향 설계의 책임 분리·확장성·대체가능성·인터페이스 분리·의존성 방향을 설명하는 다섯 원칙(**SOLID**, Single Responsibility, Open-Closed, Liskov Substitution, Interface Segregation, Dependency Inversion).
- 배경 및 필요성 : 변경 영향이 모듈 전반에 퍼지거나 상속·의존성 구조가 경직되면 유지보수 위험 증가.
- 주요 목적 : 변경에 강하고 테스트·확장 가능한 모듈 경계 형성.

### Ⅱ. 객체지향 설계원칙 SOLID의 특징 및 장점

- 핵심 요약 : SRP, OCP, LSP, ISP, DIP의 다섯 원칙; 추상화·조합·의존성 역전 활용.

1. SRP(Single Responsibility Principle) : 클래스는 하나의 변경 이유만 가져야 함 → 책임 국소화.
2. OCP(Open-Closed Principle) : 확장에 열려 있고 수정에 닫혀 있어야 함 → 기존 코드 변경 없이 확장.
3. LSP(Liskov Substitution Principle) : 하위 타입은 기반 타입을 대체할 수 있어야 함 → 다형성 안전성.
4. ISP(Interface Segregation Principle) : 클라이언트가 사용하지 않는 메서드에 의존하지 않아야 함 → 인터페이스 분리.
5. DIP(Dependency Inversion Principle, 의존성 역전 원칙) : 고수준 모듈이 저수준 모듈이 아닌 추상에 의존해야 함 → 구현과 추상화 분리.

### Ⅲ. 객체지향 설계원칙 SOLID의 구조 (흐름)

- 핵심 요약 : 변경이유·의존성 분석 → 책임·인터페이스 경계 설정 → 구현·조합 → 대체가능성·변경 시나리오 검증.

```text
변경이유·의존성 분석
  ↓
책임·인터페이스 경계 설정
  ↓
구현·조합
  ↓
대체가능성·변경 시나리오 검증
```

```text
변경이유 식별 → 책임·추상화 → 의존성 방향 → 대체·확장 시험
```

### Ⅳ. 단일 거대 모듈과 SOLID 비교

- 핵심 요약 : 단일 거대 모듈은 여러 책임·변경이유가 한 클래스에 결합, 객체지향 설계원칙 SOLID는 책임·의존성 분리로 변경 국소화.

| 비교 축 | 단일 거대 모듈 | 객체지향 설계원칙 SOLID |
|---|---|---|
| 설계 결과 | 여러 책임·변경이유가 한 클래스에 결합 | 책임·의존성 분리로 변경 국소화 |

### Ⅴ. 객체지향 설계원칙 SOLID의 한계와 방안

- 핵심 요약 : 교조적 분리·취약한 상속·과잉 계층을 실제 변경압력·계약검증·간결한 구조로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 교조적 분리 | 모든 클래스에 인터페이스·추상화 | 실제 변경압력·대체필요에 따른 적용 | 추상화·파일 수 |
| 취약한 상속 | LSP 위반·기반클래스 변경 파급 | 계약검증·합성 우선 검토 | 대체실패·하위영향 |
| 과잉 계층 | 작은 변경에 추적 복잡성 | 간결한 구조·삭제 가능한 추상화 | 변경 경로·리뷰 시간 |

### Ⅵ. 객체지향 설계원칙 SOLID에 대한 제언

- 핵심 요약 : 설계 리더는 SOLID를 체크리스트로 강제하지 말고 실제 변경사례·테스트성·대체요구를 근거로 모듈 경계를 판단.

1. 설계 리더는 SOLID를 체크리스트로 강제하지 말고 실제 변경사례·테스트성·대체요구를 근거로 모듈 경계를 판단.
2. 추상화·파일 수·대체실패·하위영향·변경 경로·리뷰 시간을 정기 측정하고 편차에 대한 원인분석·개선결과를 기록.

### Ⅶ. 결론

- 핵심 요약 : SOLID는 객체지향 설계의 책임 분리·확장성·대체가능성·인터페이스 분리·의존성 방향을 설명하는 다섯 원칙.
- 시사점 : SOLID는 규칙의 기계적 적용이 아니라 변경과 의존성을 관리하는 객체지향 설계 휴리스틱.
