## 연관 키워드

- 무중단 배포(Zero-Downtime Deployment), 블루그린 배포(Blue-Green Deployment), 카나리 배포(Canary Deployment), 롤링 배포(Rolling Deployment)
- 무상태(Stateless), 헬스 체크(Health Check), 롤백(Rollback)

## Ⅰ. 무중단 배포의 개요

- 핵심 요약 : 서비스 중단 없이 신버전으로 전환하도록 트래픽·인스턴스·데이터 변경을 설계하는 배포 방식.
- 개념 : 배포 중에도 사용자 요청 처리를 유지하도록 신·구 버전의 공존과 트래픽 전환을 설계한 배포 기법이 **무중단 배포** (Zero-Downtime Deployment).
- 배경 및 필요성 : 중단 배포는 점검 시간 동안 서비스 이용이 불가하고 24시간 서비스 환경에서 가용성 손실이 사용자 이탈로 직결되어 무중단 전환 구조 필요.
- 주요 목적 : 가용성 유지, 배포 위험의 점진적 검증, 장애 시 신속한 **롤백** (Rollback, 이전 버전으로 되돌리는 절차) 확보.

## Ⅱ. 무중단 배포의 특징 및 장점

- 핵심 요약 : 버전 공존·트래픽 제어·무상태·헬스 체크의 결합이 배포 위험의 범위를 제한.

1. 버전 공존 : 신·구 버전이 동시에 실행되는 상태 유지 → 전환 시점·복구 시점의 자유로운 선택.
2. 트래픽 제어 : 라우터·로드밸런서가 전환 비율·대상을 조정 → 위험 노출 범위의 최소화.
3. 무상태 설계 : **무상태** (Stateless, 세션 등 상태를 애플리케이션 외부로 분리한 설계) 구조 → 인스턴스 교체·확장의 자유로움.
4. 헬스 체크 : **헬스 체크** (Health Check, 신버전의 준비 완료 상태 점검) 통과 후 트래픽 투입 → 불완전 버전의 유입 차단.

## Ⅲ. 무중단 배포의 구조 (흐름)

- 핵심 요약 : 준비·검증 후 트래픽을 이동시키고 지표 관측 결과에 따라 승격 또는 복구를 판단.
- 세 방식 : **롤링 배포** (Rolling Deployment)·**블루그린 배포** (Blue-Green Deployment)·**카나리 배포** (Canary Deployment)가 대표 유형.

```text
[ 블루그린 배포 ]
트래픽 → 블루(구버전) 운영
   ↓
그린(신버전) 배포·사전 검증
   ↓
라우팅 일괄 전환
   ↓
블루 대기 유지 (즉시 복구 경로)
```

```text
[ 카나리 배포 ]
소수 트래픽 → 신버전 노출
   ↓
오류율·응답 시간 관측
   ↓
기준 충족 시 노출 범위 단계 확대
   ↓
이상 감지 시 즉시 차단·롤백
```

```text
[ 롤링 배포 ]
일부 인스턴스 신버전 교체
   ↓
헬스 체크 통과 확인
   ↓
다음 인스턴스 순차 교체
   ↓
전체 교체 완료
```

## Ⅳ. 무중단 배포와 중단 배포의 비교

- 핵심 요약 : 무중단 3방식은 공통으로 가용성을 유지하되 자원 비용·전환 정밀도·복구 속도에서 차이.

| 비교 축 | 중단 배포 | 롤링 배포 | 블루그린 배포 | 카나리 배포 |
| --- | --- | --- | --- | --- |
| 서비스 중단 | 전환 동안 발생 | 없음 | 없음 | 없음 |
| 추가 자원 | 불필요 | 소규모 | 전체 환경 2세트 | 소규모 |
| 롤백 속도 | 재배포 필요 | 순차 재교체 | 라우팅 즉시 전환 | 트래픽 차단 즉시 |
| 위험 노출 | 전체 사용자 | 인스턴스 단위 | 전환 시점 일괄 | 소수 사용자 한정 |
| 적합 상황 | 내부 시스템·점검 가능 서비스 | 인스턴스 풀 운영 환경 | 전환 검증이 중요한 핵심 서비스 | 신기능의 실사용 검증 |

## Ⅴ. 무중단 배포의 한계와 방안

- 핵심 요약 : 상태·데이터 호환성과 감지 지연이 중단 원인이 되므로 애플리케이션 외부 의존성까지 설계 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 상태 의존 세션 | 인스턴스 교체 중 로그인·진행 상태 단절 | 무상태화·외부 세션 저장소 | 세션 단절 건수 |
| 데이터 구조 비호환 | 신·구 버전의 동시 접근 실패 | 하위 호환 단계의 스키마 변경·전환 기간 관리 | 호환성 오류 건수 |
| 이상 감지 지연 | 오류가 전체 사용자로 확산 후 인지 | 자동 롤백 임계값·알림 체계 | 평균 감지 시간 |
| 이중 자원 비용 | 블루그린 방식의 상시 2세트 운영 | 전환 완료 후 자원 회수 자동화 | 미회수 자원 수 |

## Ⅵ. 배포 거버넌스에 대한 제언

- 핵심 요약 : 배포 방식 선택·승인·복구 책임을 표준 절차와 자동화 정책으로 제도화.

1. 개발 조직은 API·메시지·스키마의 하위 호환 유지 기간을 배포 정책으로 명문화하고 변경 유형별 배포 방식을 표준화.
2. 신뢰성 엔지니어링(SRE, Site Reliability Engineering) 조직은 서비스 수준 목표(SLO, Service Level Objective)를 기준으로 트래픽 확대·중단 판단을 자동화 정책에 편성.
3. 운영 조직은 롤백·데이터 복구 절차의 정기 리허설을 변경 관리 규정의 의무 항목으로 포함.

## Ⅶ. 결론

- 핵심 요약 : 무중단 배포는 트래픽 전환 기술만으로 성립하지 않고 상태·데이터 호환 설계와 결합할 때 완성.
- 시사점 : 배포의 성공 판정은 전환 완료가 아니라 관측 지표의 안정 확인 기준.
