## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 지능형 개발환경 → **AI 네이티브 개발 플랫폼**

## 30초 인출

- 본질: 단순 코드 자동완성을 넘어 대규모 언어 모델(LLM) 기반 자율 에이전트가 전체 코드베이스 문맥과 개발 도구를 활용하여 기획, 분석, 구현, 테스트, 배포 전 과정을 주도적으로 수행하는 차세대 소프트웨어 엔지니어링 플랫폼
- 메커니즘: 의도 파악 및 작업 분해 → 컨텍스트 엔지니어링(RAG/AST) → 격리 샌드박스 내 도구(Bash, Git, Lint) 실행 → 자율 테스트 검증 루프 → Human-in-the-loop 최종 승인
- 통찰: 에이전트의 환각(Hallucination)과 무제한 권한 행사로 인한 운영 장애 및 보안 유출을 방어하기 위해 최소 권한 격리 샌드박스와 다계층 품질 게이트(Quality Gate) 강제 필수

<details>
<summary>핵심 용어</summary>

- **AI Native Dev Platform(AI 네이티브 개발 플랫폼)** : AI 에이전트를 개발의 핵심 주체로 설계하여 소프트웨어 생명주기(SDLC) 전반을 자율화하는 지능형 개발 환경
- **Autonomous Agent(자율 에이전트)** : 주어진 목표를 달성하기 위해 자율적으로 계획(Planning)을 수립하고 도구(Tools)를 호출하며 오류를 자체 수정하는 AI 시스템
- **Context Engineering(컨텍스트 엔지니어링)** : 거대한 코드 저장소에서 작업과 연관된 파일, AST, 커밋 히스토리, 린트 규칙을 선별하여 에이전트의 컨텍스트 윈도우에 최적화 주입하는 기법
- **Isolated Sandbox(격리 샌드박스)** : 에이전트가 코드를 빌드하고 셸 명령을 실행할 때 호스트 시스템을 보호하기 위한 컨테이너/gVisor 기반의 격리 실행 환경
- **Human-in-the-loop (HITL)** : AI 에이전트의 자율 실행 과정에서 고위험 작업(배포, 삭제, 권한 변경)에 대해 인간 엔지니어의 명시적 승인을 요구하는 안전 통제 모델

</details>

## 2~4교시 25점 답안

## Ⅰ. AI 네이티브 개발 플랫폼의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 전통적인 IDE 위에 단순 코파일럿(Copilot) 플러그인을 얹은 형태를 탈피하여, AI 에이전트가 코드베이스 전체의 문맥을 이해하고 터미널, 디버거, CI/CD 도구를 자율적으로 제어하여 개발 작업을 완수하도록 근본부터 재설계된 차세대 개발 플랫폼 |
| 목적 | 엔지니어의 반복적 코딩 및 디버깅 인지 부하 극적 경감, 개발 속도(Velocity) 혁신 및 코드 품질·보안 거버넌스의 선제적 자동화 |

## Ⅱ. AI 네이티브 개발 플랫폼의 핵심 특징

| 특징 | 의미 |
|---|---|
| 엔드투엔드 자율 실행 | 한 줄 코드 생성을 넘어 이슈 티켓 분석부터 코드 작성, 테스트 통과, PR 생성까지 전 주기 자율 수행 |
| 깊은 저장소 문맥 인지 | 프로젝트 전체의 심볼 그래프, AST(추상 구문 트리), 종속 라이브러리, 아키텍처 규칙을 총체적으로 파악 |
| 자가 수정 루프 (Self-healing) | 컴파일 에러나 단위 테스트 실패 발생 시 에이전트 스스로 스택 트레이스를 분석하고 코드를 수정하여 재검증 |
| 안전한 도구 제어 가드레일 | 격리된 컨테이너 환경에서 최소 권한(Least Privilege) 원칙으로 명령을 실행하며 민감 정보 유출 방지 |

## Ⅲ. AI 네이티브 플랫폼 아키텍처 및 자율 개발 루프

### 5계층 아키텍처 및 에이전트-엔지니어 협업 파이프라인

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 1. 상호작용 및 오케스트레이션 계층 (Interaction & Orchestration Layer) │
│    - 자연어 요구사항 수신 ("결제 타임아웃 재시도 로직 구현해줘")       │
│    - 작업 분해(Task Decomposition) 및 계획(Planning) 수립              │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 2. 지능형 컨텍스트 계층 (Context Engineering Layer)                   │
│    - 코드베이스 RAG / 시맨틱 검색 / AST 그래프 탐색                    │
│    - 연관 결제 모듈 파일, 단위 테스트, 아키텍처 가이드라인 추출        │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 3. 격리 실행 및 도구 계층 (Isolated Sandbox & Tools Layer)             │
│    - gVisor / Docker 격리 샌드박스 내부에서 도구 호출                  │
│    - [파일 편집 (Edit)] → [빌드 실행 (Build)] → [단위 테스트 (Test)]    │
│         ▲                                                    │         │
│         └────────── (테스트 실패 시 자체 수정 루프) ─────────┘         │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 단위 테스트 100% 통과
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 4. 품질 및 보안 게이트 계층 (Quality & Security Gate Layer)            │
│    - SAST 보안 스캔 (OWASP Top 10), 오픈소스 라이선스 검증, 린트 검사   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 검증 완료
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 5. Human-in-the-loop 최종 승인 계층 (Human-in-the-loop Approval)       │
│    - Git Pull Request 자동 생성 및 변경 Diff 시각화                    │
│    - 개발자 최종 리뷰 및 머지 승인(Merge)                             │
└────────────────────────────────────────────────────────────────────────┘
```

### AI 네이티브 플랫폼 핵심 모듈 분석

| 모듈 명칭 | 핵심 기술 및 구현 메커니즘 | 주요 역할 |
|---|---|---|
| **플래너 (Planner)** | ReAct(Reasoning + Acting), 체인 오브 솟(CoT) | 모호한 비즈니스 목표를 실행 가능한 세부 태스크 단위로 체계적 분해 |
| **컨텍스트 엔진** | Tree-sitter AST 파서, 벡터 DB, BM25 하이브리드 검색 | 토큰 낭비 없이 정확히 수정 대상이 되는 코드 범위와 종속성 식별 |
| **샌드박스 실행기** | WebAssembly, Firecracker microVM, Docker | 격리된 공간에서 안전하게 컴파일 및 셸 명령을 실행하여 호스트 감염 차단 |
| **품질 검증기** | JUnit, pytest, SonarQube, Semgrep | 에이전트가 작성한 코드가 요구 명세를 충족하는지 정량적 합격 판정 |

## Ⅳ. 전통적 AI 코파일럿 vs AI 네이티브 개발 플랫폼 비교

### 개발 보조 도구 패러다임별 비교

| 비교 항목 | 1세대: AI 코딩 보조 도구 (Copilot) | 2세대: AI 네이티브 개발 플랫폼 (Agentic) |
|---|---|---|
| **동작 패러다임** | **수동적 인라인 자동완성 (Inline Suggestion)** | **능동적 목표 지향 자율 수행 (Goal-driven Agent)** |
| **작업 처리 범위** | 현재 열려 있는 파일의 함수 및 코드 조각 작성 | **복수 파일 수정, 빌드, 테스트, 버그 수정 전 과정** |
| **도구 활용 능력** | 텍스트 생성에 국한, 외부 도구 실행 불가 | **셸, Git, 패키지 매니저, 테스트 러너 직접 호출** |
| **피드백 처리** | 개발자가 직접 컴파일 에러를 보고 코드 수동 수정 | **테스트 실패 시 에이전트가 자체 수정(Self-repair)** |
| **컨텍스트 인식** | 커서 주변의 수십~수백 라인 코드만 참고 | **전체 저장소 AST 및 의존성 그래프 전체 조망** |
| **엔지니어의 역할** | 코드 작성자 겸 타이핑 검토자 | **고수준 아키텍처 감독관 및 최종 승인권자 (Reviewer)** |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 에이전트의 환각(Hallucination)으로 인해 존재하지 않는 가짜 라이브러리를 임포트(Slops)하는 현상 | 사내 검증된 패키지만 허용하는 프라이빗 레지스트리 강제 및 의존성 검증 파이프라인 연계 |
| 에이전트가 악의적 프롬프트 인젝션(Prompt Injection)에 노출되어 파일 삭제 등 파괴적 명령 실행 | 파일 시스템 접근 및 네트워크 호출을 엄격히 제한하는 gVisor 기반 마이크로VM 샌드박스 격리 |
| 자가 수정 루프에서 동일 오류가 해결되지 않고 무한 루프에 빠져 API 비용 폭증 | 최대 시도 횟수(Max Iteration 5회) 및 실행 시간(Time-box) 초과 시 즉시 사람에게 작업 이관 |

## Ⅵ. 제언

Agentic CI/CD 파이프라인 구축 및 프롬프트 인젝션 방어를 위한 이중 보안 가드레일

### AI 네이티브 CI/CD 자동화 파이프라인

```text
[Jira 이슈 생성: 버그 수정 티켓]
       ↓
[AI 개발 에이전트 자동 배정]
  ├─ Git 브랜치 자동 생성
  ├─ 재현 테스트 케이스(Reproducing Test) 선작성
  ├─ 버그 수정 코드 작성 및 테스트 통과 확인
  └─ PR 및 체인지로그 자동 생성
       ↓
[독립된 AI 코드 리뷰어 에이전트]
  ├─ 보안 취약점 및 코딩 컨벤션 검토
  └─ 인간 개발자에게 리뷰 포인트 요약 전달
       ↓
[인간 엔지니어 원클릭 최종 승인 및 프로덕션 자동 배포]
```

### AI 네이티브 개발 도입 거버넌스 의사결정 체계

```text
소프트웨어 개발 작업 성격 분석
       ↓
[고도의 비즈니스 창의성과 도메인 아키텍처 설계가 요구되는가?]
       ├─ 예 ──→ 인간 엔지니어 주도 설계 (AI는 보조적 질의응답 활용)
       └─ 아니오 ─→ [명확한 테스트 케이스와 요구사항이 존재하는가?]
                         ├─ 예 ──→ AI 네이티브 자율 에이전트에 작업 위임
                         └─ 아니오 ─→ 요구사항 상세화(DoR) 선행 후 에이전트 투입
```

### 선택 근거: 전통적 개발 프로세스와 제언 AI 네이티브 프로세스 비교

| 구분 | 전통적 인간 중심 개발 | 제언: AI 네이티브 협업 개발 |
|---|---|---|
| 개발 리드타임 | 단순 버그 수정 및 단위 테스트 작성에 수 시간~수일 | 에이전트의 병렬 자율 실행으로 수 분 내 PR 생성 |
| 테스트 주도 개발 | 시간 부족을 이유로 TDD 실천률 저조 | 에이전트가 테스트 코드 작성을 선행하여 테스트 커버리지 극대화 |
| 코드 일관성 | 개발자 개인의 성향에 따라 컨벤션 파편화 | 전사 아키텍처 규칙이 반영된 프롬프트로 일관된 코드 품질 유지 |
