## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 개발 도구·환경 → **AI 네이티브 개발 플랫폼**

## 30초 인출

- 본질: AI 네이티브 개발 플랫폼은 AI 에이전트가 요구 분석·코드 작성·시험·배포 지원 같은 개발 활동을 수행하도록 설계한 개발 환경
- 메커니즘: 에이전트가 저장소·문서에서 필요한 맥락을 모아 계획을 세우고 격리된 환경에서 코드를 빌드·시험한 뒤 결과를 사람에게 검토 요청
- 통찰: 에이전트가 자율 실행한 변경이 검증 없이 배포까지 이어질 수 있으므로 격리 환경에서 실행하고 배포·삭제 같은 고위험 작업은 사람 승인 후 진행

<details>
<summary>핵심 용어</summary>

- **AI 네이티브 개발 플랫폼** : AI 에이전트를 개발 활동의 실행 주체로 두고 설계한 개발 환경
- **자율 에이전트(Autonomous Agent)** : 목표를 받아 계획·실행·점검을 스스로 반복하는 AI
- **컨텍스트 엔지니어링(Context Engineering)** : 큰 저장소에서 작업에 필요한 정보를 골라 AI에 제공하는 방법
- **격리 샌드박스(Isolated Sandbox)** : 에이전트가 코드를 실행해도 운영 환경에 영향을 주지 않도록 분리한 실행 환경
- **사람 승인(Human-in-the-Loop)** : 고위험 작업을 사람이 확인한 뒤 실행하는 통제 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. AI 네이티브 개발 플랫폼의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **AI 네이티브 개발 플랫폼** 은 AI 에이전트가 개발 활동을 수행하도록 설계한 개발 환경 |
| 목적 | 개발 활동의 자동화와 개발자 생산성 향상 |

## Ⅱ. 기존 코드 지원 도구와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 에이전트 실행 | 코드 제안을 넘어 계획·실행·점검 수행 |
| 맥락 활용 | 저장소·문서·이슈에서 필요한 정보 수집 |
| 사람 검토 | 결과의 승인·수정은 사람이 담당 |

## Ⅲ. 플랫폼 구성과 작업 흐름

### 플랫폼 구성

```text
개발자 ── 작업 지시·검토
    ↓
AI 에이전트 ── 계획·코드 작성
    ├─ 맥락 수집 ── 저장소·문서·이슈
    ├─ 실행 환경 ── 격리 샌드박스(빌드·시험)
    └─ 통제 ── 권한 제한·사람 승인
```

### 확대: 작업 흐름과 승인

```text
작업 지시
    ↓
맥락 수집 → 계획 → 코드 변경 → 샌드박스에서 빌드·시험
    ↓
변경 요약과 시험 결과 → 사람 검토
    ├─ 승인 → 병합·배포
    └─ 수정 요청 → 재작업
```

## Ⅳ. 실행 주체별 역할 비교

| 구분 | 개발자 직접 작성 | 코드 제안 도구 | AI 에이전트 |
|---|---|---|---|
| 작업 수행 | 사람 | 사람이 수락 | 에이전트가 실행 |
| 검증 | 사람 | 사람 | 시험 실행 후 사람 검토 |
| 위험 | 낮음 | 낮음 | 잘못된 변경의 자율 실행 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 에이전트가 운영 환경에 영향을 주는 명령 실행 | 격리 샌드박스와 최소 권한 |
| 검토 없이 변경이 병합·배포 | 배포·삭제 등 고위험 작업의 사람 승인 |
| 큰 저장소에서 필요한 맥락 누락 | 작업별 관련 파일·문서 선별 제공 |
| 생성 코드의 품질·라이선스 미확인 | 정적 분석·시험·라이선스 스캔 자동 실행 |

## Ⅵ. 제언

에이전트는 격리 환경에서만 실행하고, 병합·배포 전 시험 결과와 변경 요약에 대한 사람 승인을 필수 단계로 설정

### 승인 게이트 구조

```text
에이전트 변경 → 샌드박스 시험
    ↓
정적 분석·시험 통과
    ↓
사람 승인 → 병합·배포
```

### 선택 근거: 완전 자율 실행과의 비교

| 구분 | 완전 자율 실행 | 제언: 격리·승인 |
|---|---|---|
| 오류 영향 | 운영까지 전파 가능 | 샌드박스에서 차단 |
| 책임 | 불명확 | 승인자 명시 |
| 속도 | 빠름 | 승인 대기 발생 |
