소프트웨어 공학 → 설계·아키텍처 → **디자인 패턴(프록시 패턴)**

## 30초 인출

- 본질: 프록시 패턴은 대상 객체에 직접 접근하는 대신 같은 인터페이스의 대리 객체를 두어 접근을 제어하는 GoF 구조 패턴
- 메커니즘: 클라이언트가 Subject 인터페이스로 프록시를 호출하면 프록시가 사전 처리 후 실제 객체에 위임하고 사후 처리를 수행
- 통찰: 대상 객체 내부에서 자기 메서드를 직접 호출하면 프록시를 거치지 않아 부가 기능이 빠지므로 프록시가 필요한 호출은 별도 객체로 분리해 프록시를 경유

<details>
<summary>핵심 용어</summary>

- **디자인 패턴(Design Pattern)** : 반복되는 설계 문제에 대한 검증된 해법을 이름 붙여 정리한 설계 지침. GoF의 23개 패턴은 생성·구조·행위로 분류
- **프록시 패턴(Proxy Pattern)** : 대상 객체 앞에 대리 객체를 두어 접근을 제어하고 부가 기능을 수행하는 구조 패턴
- **Subject** : 프록시와 실제 객체가 공통으로 구현해 클라이언트가 구별 없이 호출하는 인터페이스
- **가상 프록시(Virtual Proxy)** : 생성 비용이 큰 객체를 실제 사용 시점까지 지연해 생성하는 프록시
- **보호 프록시(Protection Proxy)** : 호출자의 권한을 확인한 뒤에만 실제 객체로 위임하는 프록시
- **원격 프록시(Remote Proxy)** : 다른 주소 공간의 객체를 로컬 객체처럼 호출하게 하는 프록시
- **자기 호출(Self-Invocation)** : 객체 내부에서 자기 메서드를 직접 호출해 프록시를 거치지 않는 호출

</details>

## 2~4교시 25점 답안

## Ⅰ. 프록시 패턴의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **프록시 패턴** 은 대상 객체 앞에 같은 인터페이스의 대리 객체를 두어 접근을 제어하는 구조 패턴 |
| 목적 | 대상 객체 수정 없는 접근 제어와 부가 기능 삽입 |

## Ⅱ. 직접 호출과 구별되는 프록시 패턴의 특징

| 특징 | 의미 |
|---|---|
| 동일 인터페이스 | 클라이언트가 프록시와 실제 객체를 구별하지 않고 호출 |
| 접근 제어와 위임 | 프록시의 사전 처리 후 실제 객체로 요청 위임 |
| 대상 코드 불변 | 권한·캐시·지연 생성 같은 부가 기능을 대상 수정 없이 추가 |

## Ⅲ. 프록시 패턴의 구조와 요청 처리 흐름

### 프록시 패턴 구조

```text
Client ──→ [Subject 인터페이스]
                 ▲
         ┌───────┴───────┐
   [RealSubject]     [Proxy]
   (핵심 로직)        (RealSubject 참조 보유)
```

### 확대: 프록시의 요청 처리 흐름

```text
Client: subject.request()
    ↓
Proxy: 사전 처리 (권한 확인·캐시 조회)
    ├─ 캐시 적중·권한 없음 → 결과 반환 또는 거부
    └─ 그 외 → RealSubject.request() 위임
    ↓
Proxy: 사후 처리 (로깅·캐시 저장) 후 반환
```

## Ⅳ. 프록시 유형과 유사 패턴의 비교

### 프록시의 유형

| 유형 | 동작 | 예 |
|---|---|---|
| 가상 프록시 | 사용 시점까지 객체 생성 지연 | 대용량 이미지 지연 로딩 |
| 보호 프록시 | 권한 확인 후 위임 | 관리자 전용 기능 접근 제어 |
| 원격 프록시 | 원격 호출을 로컬 호출로 은닉 | 원격 서비스 호출 스텁 |
| 캐싱 프록시 | 동일 요청의 결과 보관 | 조회 결과 캐시 |

### 유사한 구조 패턴과의 비교

| 구분 | 프록시 | 어댑터 | 데코레이터 |
|---|---|---|---|
| 의도 | 접근 제어 | 인터페이스 변환 | 기능의 동적 추가 |
| 인터페이스 | 대상과 동일 | 대상과 다름 | 대상과 동일 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 객체 내부의 자기 호출이 프록시를 우회해 부가 기능 누락 | 프록시가 필요한 메서드를 별도 객체로 분리해 외부에서 호출 |
| 프록시 계층 추가로 호출 경로와 디버깅 복잡도 증가 | 프록시가 하는 일을 접근 제어·캐시 등으로 한정하고 호출 경로 문서화 |
| 프록시와 대상의 인터페이스 불일치로 클라이언트 코드 변경 | Subject 인터페이스 공유 |

## Ⅵ. 제언

프록시로 처리할 부가 기능이 필요한 메서드는 자기 호출이 아닌 다른 객체의 호출로 구성

### 호출 경로 분리 구조

```text
Client
    ↓
[Proxy] ── 부가 기능 (권한·트랜잭션·캐시)
    ↓
ServiceA ──→ ServiceB (별도 객체 호출은 다시 프록시 경유)
```

### 확대: 자기 호출과 분리 호출의 차이

```text
자기 호출:   ServiceA.a() → this.b()   → 프록시 우회 → 부가 기능 누락
분리 호출:   ServiceA.a() → ServiceB.b() → 프록시 경유 → 부가 기능 적용
```

### 선택 근거: 자기 호출 유지와의 비교

| 구분 | 자기 호출 유지 | 제언: 객체 분리 호출 |
|---|---|---|
| 프록시 경유 | 우회 | 경유 |
| 부가 기능 적용 | 누락 가능 | 일관 적용 |
| 구조 변경 | 없음 | 클래스 분리 필요 |
