## 연관 키워드
- GoF, 생성·구조·행위 패턴, Proxy, Subject, 접근 제어

## Ⅰ. 디자인 패턴과 프록시 패턴의 개요
- 핵심 요약 : 디자인 패턴은 반복 설계 문제의 검증된 해법이고, 프록시는 대리 객체로 대상 접근을 제어.
- 개념 : 패턴은 협력 객체의 역할·관계를 명명한 재사용 설계이고 Proxy는 실제 객체와 같은 인터페이스의 대리자.
- 필요성 : 반복되는 생성·결합·접근 문제를 이해 가능한 구조로 해결.
- 목적 : 변화 격리, 결합도 감소, 횡단 관심사의 관리.

## Ⅱ. 패턴의 특징 및 장점
- 핵심 요약 : 생성·구조·행위 패턴은 각각 객체 생성, 구성, 협력 방식의 복잡성을 다룸.
1. 공통 어휘 : 패턴명과 역할 공유 → 설계 의도 전달 단축.
2. 변화 격리 : 인터페이스 뒤에 구현 세부 배치 → 교체·확장 용이.
3. 프록시 통제 : 캐시·지연 생성·권한검사를 대리자에 배치 → 클라이언트 변경 최소화.

## Ⅲ. Proxy 패턴 구조와 유형
- 핵심 요약 : 클라이언트는 Subject 인터페이스를 호출하고 Proxy가 필요 시 RealSubject에 위임.
```text
Client → Subject 인터페이스 ← Proxy → RealSubject
            동일 호출             검사·지연·위임
```
```text
호출 → 접근검사/캐시/원격전달 → 실제 객체 실행 → 결과 반환
```
- 유형 : Virtual(지연 생성), Protection(권한 제어), Remote(원격 대리), Caching·Logging proxy.

## Ⅳ. Proxy와 Decorator·Adapter 비교
- 핵심 요약 : Proxy는 접근·수명 제어, Decorator는 책임 추가, Adapter는 인터페이스 변환이 목적.
| 기준 | Proxy | Decorator | Adapter |
|---|---|---|---|
| 의도 | 대상 접근 통제·대리 | 기존 객체에 기능 추가 | 호환되지 않는 인터페이스 변환 |
| 인터페이스 | 대상과 동일 | 대상과 동일 | 클라이언트 기대 인터페이스 |
| 사례 | 원격 호출·캐시 | 압축·암호화 래핑 | 외부 라이브러리 변환 |

## Ⅴ. 디자인 패턴 적용 한계와 대응
- 핵심 요약 : 패턴 남용은 간접 호출과 추상화 비용을 높이므로 실제 문제와 변화 축에 맞춰 선택.
| 한계 | 영향 | 대응 |
|---|---|---|
| 과도한 패턴화 | 클래스·호출 증가 | 단순 구현과 복잡도 비교 후 도입 |
| 프록시 부작용 | 지연·예외·캐시 불일치 | 타임아웃·무효화·오류 전파 정책 명시 |
| 기술 제약 | 프레임워크·직렬화 충돌 | 배포·보안·성능 조건에서 검증 |

## Ⅵ. 패턴 적용 제언
- 핵심 요약 : 설계자는 패턴명을 먼저 정하기보다 반복 문제와 품질 요구를 확인한 뒤 적용.
1. 설계자는 패턴의 참여자·협력 흐름을 코드 리뷰에서 설명.
2. 보안 담당자는 Protection Proxy의 우회 경로와 신뢰 경계를 검토.
3. 성능 담당자는 원격·캐시 프록시의 지연과 일관성을 부하시험.

## Ⅶ. 결론
- 핵심 요약 : 디자인 패턴은 맥락에 맞게 쓸 때 설계 의사소통과 변화 대응을 돕는 재사용 지식.
- 시사점 : Proxy의 핵심은 동일 인터페이스 뒤에서 접근 경로와 부가 정책을 제어하는 데 있음.
