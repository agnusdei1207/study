## 연관 키워드

- 오픈소스 라이선스, 퍼미시브(Permissive), 카피레프트(Copyleft)
- GPL, MIT, 소스 공개 의무, 고지 의무, SBOM, SCA

## Ⅰ. 오픈소스 라이선스의 개요

- 핵심 요약 : 오픈소스 라이선스는 사용·수정·재배포 권리와 조건을 규정해 자유로운 재사용과 저작권 보호를 양립하는 제도.
- 개념 : 저작권자가 소프트웨어의 복제·수정·재배포를 조건부로 허용하는 라이선스(**오픈소스 라이선스**, Open Source License), OSI(Open Source Initiative)의 인증 기준이 통용.
- 배경 및 필요성 : 소프트웨어 재사용과 협업 개발 확산으로 권리·의무의 명시적 계약 필요 증가.
- 주요 목적 : 재사용의 자유와 조건 준수·저작권 보호의 균형 유지.

## Ⅱ. 라이선스 유형의 특징 및 장점

- 핵심 요약 : 퍼미시브는 최소 의무로 활용 유연성, 카피레프트는 공개 전파로 공유 생태계를 강화.

1. **퍼미시브 라이선스** (Permissive License) : 재배포 시 저작권·라이선스 고지 유지 중심의 최소 의무 → 상용 제품과의 결합·배포 유연성, MIT·Apache-2.0·BSD가 대표.
2. **카피레프트 라이선스** (Copyleft License) : 파생 저작물 배포 시 동일 라이선스 적용 의무 → **소스 공개 의무**의 전파, GPL(GNU General Public License)이 대표.
3. 강도 구분 : 강한 카피레프트(GPL)는 파생물 전체, 약한 카피레프트(LGPL·MPL)는 파일·라이브러리 단위 → 결합 방식별 검토 필요.
4. 배포 트리거 구분 : GPL은 배포 시, AGPL(GNU Affero General Public License)은 네트워크 이용 시에도 의무 발생 → 서비스 형태별 준수 판단의 정밀화.

## Ⅲ. 오픈소스 라이선스의 구조 (흐름)

- 핵심 요약 : 의존성 식별부터 고지·소스 제공 이행까지의 준수 절차로 운영.
- **고지 의무** : 배포 시 저작권·라이선스 전문과 수정 사항을 명시하는 의무(NOTICE 파일 등).
- 구별 대상 : 소스 코드를 공개하더라도 오픈소스 정의를 충족하지 않는 소스 공개형(Source-Available) 라이선스는 사용 제한 조항의 별도 검토 대상.

```text
[ 라이선스 준수 흐름 ]

의존성 식별(전이 의존성 포함)
   ↓
라이선스·버전 확인
   ↓
결합·배포 방식별 의무 분석
   ↓
고지·소스 제공 이행
   ↓
배포 기록 보존
```

```text
[ 의무 판단 기준 ]

사용만 하는가
   ↓ 예
고지 의무 중심 이행
   ↓ 수정·재배포 시
배포 형태 확인(바이너리·소스·서비스)
   ↓
카피레프트 전파 범위 검토
```

- **SBOM** (Software Bill of Materials) : 소프트웨어 구성 요소·의존성·라이선스를 목록화한 명세.
- **SCA** (Software Composition Analysis) : 빌드 산출물을 분석해 구성 요소와 라이선스·취약점을 점검하는 도구·활동.

## Ⅳ. 오픈소스 라이선스와 독점 라이선스의 비교

- 핵심 요약 : 오픈소스 라이선스는 조건 준수를 전제로 재배포 권리를 부여하고 독점 라이선스는 계약된 사용 권한만 부여.
- **독점 라이선스** (Proprietary License) : 소스 비공개를 기본으로 계약된 사용 권한만 부여하는 상용 라이선스.

| 비교 축 | 퍼미시브 | 카피레프트 | 독점(상용) 라이선스 |
| --- | --- | --- | --- |
| 소스 공개 | 의무 없음 | 파생물 배포 시 공개 | 원칙적 비공개 |
| 수정·재배포 | 자유(고지 유지 조건) | 동일 라이선스 조건부 | 계약 범위 내 제한 |
| 대표 라이선스 | MIT·Apache-2.0·BSD | GPL·LGPL·MPL | 기업별 상용 계약 |
| 독점 코드와의 결합 | 유연 | 전파 의무 발생 가능 | 역공학·수정 금지 조항 |

## Ⅴ. 라이선스 관리의 한계와 방안

- 핵심 요약 : 전이 의존성 누락·오분류·고지 누락을 자동 스캔과 전문 검토의 결합으로 완화.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 전이 의존성 누락 | 위반 라이선스의 유입 | SBOM·SCA 기반 스캔·빌드 차단 | 미확인 의존성 수 |
| 라이선스 오분류 | 의무 과소·과대 판단 | 전문 기반 검증·법무 검토 | 오분류 정정 건수 |
| 고지물 누락 | 저작권 표기 위반·감사 지적 | 릴리스별 고지 자동 생성·검토 | 고지 미비 건수 |

## Ⅵ. 오픈소스 거버넌스에 대한 제언

- 핵심 요약 : 개발자의 라이선스 선택을 차단하지 않고 정책·자동화·교육의 결합으로 준수 비용을 낮추는 체계 필요.

1. 개발 조직은 신규 의존성 도입 시 출처·버전·라이선스·목적을 기록하는 절차 준수.
2. **OSPO** (Open Source Program Office)는 허용 라이선스 목록·예외 승인·고지 자동화 정책 운영.
3. 공급망 관리 조직은 SBOM을 릴리스 산출물로 보존하고 취약점·라이선스 정책의 통합 관리.

## Ⅶ. 결론

- 핵심 요약 : 오픈소스 활용은 재사용 권리와 배포 조건의 동시 취득.
- 정책·자동화·교육의 결합으로 개발 속도와 준수 수준의 동시 확보.
