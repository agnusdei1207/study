## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 빌드·배포·DevOps → **DevOps**

## 30초 인출

- 본질: DevOps는 개발과 운영이 함께 책임지며 변경을 자동화된 파이프라인으로 빠르고 안정적으로 전달하는 협업 방식
- 메커니즘: 코드 변경이 CI/CD 파이프라인의 빌드·시험·배포를 거쳐 운영에 반영되고, 운영 관측 결과가 다음 개발 계획으로 되돌아오는 순환
- 통찰: 개발은 배포 속도, 운영은 안정성으로 목표가 갈려 배포 병목이 생기므로 배포 빈도·변경 실패율·복구 시간을 공통 지표로 삼아 파이프라인 병목을 개선

<details>
<summary>핵심 용어</summary>

- **DevOps** : 개발(Development)과 운영(Operations)이 계획부터 운영까지 협업·자동화·측정·공유로 소프트웨어를 전달하는 체계
- **CI/CD(Continuous Integration/Continuous Delivery)** : 코드 통합·빌드·시험과 운영 환경 배포를 자동화해 자주 안전하게 반영하는 파이프라인
- **IaC(Infrastructure as Code)** : 인프라 구성을 코드로 정의하고 버전 관리해 환경을 같은 상태로 재현하는 방식
- **DevSecOps** : 파이프라인 단계마다 보안 점검을 넣어 보안을 개발 초기에 수행하는 DevOps 확장
- **DORA 지표** : 배포 빈도, 변경 리드타임, 변경 실패율, 복구 시간의 네 가지로 소프트웨어 전달 성능을 재는 지표
- **Silo(사일로)** : 개발과 운영이 조직·목표·도구로 나뉘어 협업 없이 일하는 구조

</details>

## 2~4교시 25점 답안

## Ⅰ. DevOps의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **DevOps** 는 개발과 운영이 함께 책임지고 변경을 자동화된 파이프라인으로 빠르고 안정적으로 전달하는 협업 방식 |
| 목적 | 배포 주기 단축과 운영 안정성의 동시 확보 |

## Ⅱ. 개발·운영 분리 방식과 구별되는 DevOps의 특징

| 특징 | 의미 |
|---|---|
| 공동 책임 | 개발과 운영의 서비스 품질 공동 관리 |
| 파이프라인 자동화 | 빌드·시험·보안 점검·배포의 도구 체인 연결 |
| 지속적 피드백 | 운영 관측 결과의 다음 개발 계획 반영 |
| 코드형 인프라 | **IaC** 로 환경 구성을 코드로 관리 |

## Ⅲ. DevOps 순환 체계와 CI/CD 파이프라인

### DevOps 순환 체계

```text
계획 → 개발 → 빌드 → 시험
 ↑                     ↓
모니터링 ← 운영 ← 배포 ← 릴리스
```

### 실행 확대: CI/CD 파이프라인

```text
코드 커밋
    ↓
CI: 빌드·정적 분석·단위 시험
    ↓
CD: 스테이징 배포·통합 시험
    ↓
운영 배포
    ↓
운영 관측(로그·지표) → 개선 항목 등록
```

## Ⅳ. 분리 모델과 DevOps의 비교, 장점과 단점

### Silo 모델과 DevOps 모델

| 비교 항목 | Silo 모델 | DevOps 모델 |
|---|---|---|
| 조직 목표 | 개발은 기능 속도, 운영은 안정성 | 전달 속도와 안정성의 공동 목표 |
| 배포 방식 | 대규모 변경의 비정기 배포 | 작은 변경의 빈번한 배포 |
| 인프라 관리 | 수작업 설정 | IaC의 자동 구성 |
| 장애 대응 | 팀 간 책임 공방 | 원인 분석과 개선 항목 등록 |

### DevOps의 장점과 단점

| 구분 | 내용 |
|---|---|
| 장점 | 배포 주기 단축, 결함의 조기 발견, 복구 시간 단축, 개발·운영 협업 강화 |
| 단점 | 문화·조직 전환 부담, 도구 체인의 복잡성, 파이프라인 구축·유지 비용, 보안·통제 체계의 재설계 필요 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 개발과 운영의 상충하는 목표로 배포 병목 발생 | 배포 빈도·변경 실패율·복구 시간의 **DORA 지표** 를 공통 지표로 설정 |
| 배포 직전의 보안 점검으로 일정 지연 | 파이프라인 단계별 자동 보안 점검(**DevSecOps**) |
| 수작업 환경 설정으로 시험·운영 환경 불일치 | **IaC** 기반 환경 구성과 변경 이력 관리 |

## Ⅵ. 제언

배포 빈도·변경 실패율·복구 시간의 현재 수준을 먼저 측정하고, 지표를 가장 악화시키는 파이프라인 단계부터 개선

### 지표 기반 개선 순환

```text
DORA 지표 현재 수준 측정
    ↓
병목 단계 식별 (예: 시험·승인·배포)
    ↓
해당 단계의 자동화·정책 개선
    ↓
지표 재측정
```

### 병목 식별 확대: 지표별 개선 대상

```text
변경 리드타임 지연 → 승인·시험 대기 단계 개선
변경 실패율 상승 → 시험·보안 점검 자동화 보강
복구 시간 지연 → 배포 롤백·관측 체계 개선
```

### 선택 근거: 도구 도입 중심과의 비교

| 구분 | 도구 도입 중심 | 제언: 지표 기반 개선 |
|---|---|---|
| 개선 시작점 | 도구 선정 | 지표로 확인한 병목 |
| 효과 판단 | 자동화 범위 | 배포 빈도·실패율·복구 시간 변화 |
| 개발·운영 목표 | 팀별 상이 | 공통 지표 |
