- **HCI(Human-Computer Interaction)** : 사람의 특성·과업·사용 맥락에 맞춰 대화형 시스템과의 상호작용을 설계·평가하는 학제 분야
- **MHP(Model Human Processor)** : 인간의 인지 과정을 지각(Perceptual), 인지(Cognitive), 운동(Motor) 3대 프로세서로 모델링한 인지공학 이론
- **GOMS 모델(Goals, Operators, Methods, Selection Rules)** : 사용자의 작업 수행 절차를 목표, 기본 동작, 방법, 선택 규칙으로 분해하여 수행 시간을 정량 예측하는 모델
- **KLM(Keystroke-Level Model)** : GOMS의 간소화 버전으로 키 입력, 마우스 이동 등 단위 동작 시간을 합산하여 작업 소요 시간을 측정하는 기법
- **어포던스(Affordance)** : 시스템 객체의 형태나 시각적 단서만으로 사용자가 직관적으로 조작 방법을 인지할 수 있는 행동 유도성
- **멘탈 모델(Mental Model)** : 사용자가 시스템의 작동 원리와 구조에 대해 머릿속에 형성하는 내적 인지 모형
- **NUI(Natural User Interface)** : 음성, 터치, 제스처, 시선 등 인간 본연의 신체 행동을 그대로 입력 매개체로 활용하는 인터페이스
- **사용성(Usability)** : 지정 사용자·목표·맥락에서 효과성·효율성·만족도로 살피는 사용 품질

## 2~4교시 25점 답안

## Ⅰ. HCI의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | HCI는 사람과 컴퓨터가 목표를 이루도록 상호작용을 설계·평가하는 학제 분야 |
| 목적 | 사용자가 목표를 효과적·효율적·만족스럽게 달성하도록 시스템을 설계·개선 |

## Ⅱ. HCI의 특징

사용자의 목표·인지 능력·사용 맥락을 함께 분석하고, 설계 결과를 실제 과업 수행으로 확인.

| 사용성 측면 | 과업 평가 기준 |
|---|---|
| 효과성 | 목표 과업의 정확한 완료 |
| 효율성 | 목표 달성에 필요한 시간·노력 |
| 만족도 | 상호작용에 대한 사용자의 수용 정도 |
---

## Ⅲ. HCI 상호작용·인지 분석 체계

### 사용자·시스템 상호작용의 큰 흐름

```text
사용자: 목표·의도
    ↓ 운동·조작
시스템: 입력 → 처리 → 출력
    ↓ 화면·상태 피드백
사용자: 지각 → 해석·평가

평가 결과 → 다음 조작
```

- **Norman의 실행·평가 간극**: 사용자가 의도한 조작을 찾는 어려움과 시스템 상태를 해석하는 어려움을 각각 입력 단서와 명확한 피드백으로 축소.

### GOMS 작업 분석의 하위 구조

```text
목표(Goals)
  └─ 방법(Methods) 후보
       ├─ 동작(Operators)의 순서와 시간
       └─ 선택 규칙(Selection Rules)으로 방법 결정
```

- **Goals (목표)** : 사용자가 시스템을 통해 성취하려는 최종 목적 (예: 장바구니 품목 결제).
- **Operators (동작)** : 목표 달성을 위한 최소 단위 물리적/인지적 기본 조작 (키보드 입력, 마우스 클릭).
- **Methods (방법)** : 특정 목표를 완수하기 위해 조직화된 연산자들의 순차적 실행 경로.
- **Selection Rules (선택 규칙)** : 동일한 목표를 달성하는 여러 방법이 존재할 때 상황에 맞게 최적의 방법을 결정하는 규칙.

## Ⅳ. 사용 맥락에 따른 인터페이스 유형 비교

| 구분 | 인터페이스 유형 | 주 입력 매개체 | 핵심 장점 | 주요 단점 및 한계 | 대표 사례 |
|---|---|---|---|---|---|
| 명령 중심 | **CLI(Command Line)** | 텍스트 명령 | 자동화·반복 작업에 적합 | 명령 학습 필요 | 셸 |
| 시각 중심 | **GUI(Graphical User Interface)** | 화면·포인터·키보드 | 상태와 선택지를 시각적으로 표현 | 화면·입력장치에 제약 | 데스크톱 앱 |
| 자연 입력 | **NUI(Natural User Interface)** | 터치·음성·제스처 | 상황에 맞는 다양한 입력 | 환경·인식 오류에 민감 | 음성 비서 |
---

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 과업 흐름이 복잡해 사용자가 중도 이탈 | 실제 사용자 과업을 관찰하고 탐색 단계를 줄인 뒤 완료율·소요시간으로 검증 |
| 중요 입력에서 오류를 뒤늦게 발견 | 입력 전후 상태 피드백과 정정 경로를 제공하고 오류 복구를 시험 |
| 입력 방식이 사용 맥락과 맞지 않음 | 접근성을 점검하고 대체 입력 방법을 실제 사용자와 시험 |
---

## Ⅵ. 제언

우선 실행: 대표 사용자·과업·사용 맥락을 정하고 관찰 및 측정 결과에 따라 설계를 반복 조정.

## 연결 토픽

- **선행 토픽** : 소프트웨어 요구공학, 사용자 중심 설계(UCD)
- **유사/비교 토픽** : 사용성 테스트(Usability Testing), 정보구조(IA), 디자인 씽킹
- **후속/연계 토픽** : 사용성 테스트, 웹 접근성
