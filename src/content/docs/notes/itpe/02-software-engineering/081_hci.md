## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 사용자 인터페이스 → **HCI(Human-Computer Interaction)**

## 30초 인출

- 본질: HCI는 사람이 컴퓨터를 쓰는 방식과 인터페이스를 연구해 쓰기 쉽고 오류가 적은 상호작용을 설계하는 분야
- 메커니즘: 사용자와 과업을 분석해 인터페이스 프로토타입을 만들고 사용성 평가로 문제를 찾아 반복 개선
- 통찰: 사용자의 목표와 인터페이스 조작 사이에 실행과 평가의 간극이 있으면 오류와 이탈이 생기므로 사용자 분석과 프로토타입 사용성 평가를 반복해 간극을 줄임

<details>
<summary>핵심 용어</summary>

- **HCI(Human-Computer Interaction)** : 사람과 컴퓨터의 상호작용을 연구·설계하는 분야
- **사용성(Usability)** : 사용자가 목표를 효과적이고 효율적이며 만족스럽게 달성하는 정도
- **실행의 간극(Gulf of Execution)** : 사용자의 의도와 인터페이스가 제공하는 조작 방법 사이의 차이
- **평가의 간극(Gulf of Evaluation)** : 시스템 상태를 보고 목표 달성 여부를 판단하는 데의 어려움
- **어포던스(Affordance)** : 사물의 형태가 사용 방법을 알려 주는 성질
- **사용자 중심 설계(UCD)** : 사용자 요구를 설계 전 과정에 반영하는 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. HCI의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **HCI** 는 사람과 컴퓨터의 상호작용을 연구해 쓰기 쉬운 인터페이스를 설계하는 분야 |
| 목적 | 사용성 향상과 사용자 오류 감소 |

## Ⅱ. HCI의 특징

| 특징 | 의미 |
|---|---|
| 학제적 | 인지심리·디자인·컴퓨터 공학의 결합 |
| 사용자 중심 | 사용자 목표와 특성 기반 설계 |
| 반복 개선 | 평가 결과의 설계 반영 |

## Ⅲ. 상호작용 모델과 설계 절차

### 사용자와 시스템의 상호작용

```text
사용자 목표
    ↓ 실행(Gulf of Execution)
인터페이스 조작
    ↓
시스템 반응
    ↓ 평가(Gulf of Evaluation)
사용자의 결과 해석 → 목표 달성 여부 판단
```

### 확대: 사용자 중심 설계 절차

```text
사용자·과업 분석
    ↓
프로토타입 설계
    ↓
사용성 평가
    ↓
개선 → 반복
```

## Ⅳ. 설계 원칙과 평가

### 사용성 설계 원칙

| 원칙 | 의미 |
|---|---|
| 가시성 | 시스템 상태와 가능한 동작이 드러남 |
| 피드백 | 조작에 대한 즉시 반응 |
| 일관성 | 같은 동작은 같은 방식으로 표현 |
| 오류 예방 | 오류가 생기지 않도록 설계하고 복구 수단 제공 |
| 어포던스 | 형태로 사용 방법 암시 |

### 평가 방법

| 방법 | 내용 |
|---|---|
| 사용성 테스트 | 사용자 과업 수행 관찰 |
| 휴리스틱 평가 | 전문가가 원칙에 비춰 점검 |
| 설문 | 만족도·이해도 조사 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 개발자 관점 설계로 실행·평가 간극 발생 | 사용자·과업 분석과 페르소나 활용 |
| 후반 평가로 수정 비용 증가 | 프로토타입 단계의 사용성 평가 |
| 다양한 사용자(접근성) 미반영 | 접근성 기준 적용과 사용자군별 평가 |

## Ⅵ. 제언

설계 초기에 사용자와 과업을 분석하고, 프로토타입으로 사용성 평가를 반복해 실행·평가 간극 줄임

### 반복 개선 순환

```text
사용자·과업 분석 → 프로토타입 → 사용성 평가
    ↑                                  ↓
    └────────────── 개선 ──────────────┘
```

### 선택 근거: 개발 후 평가와의 비교

| 구분 | 개발 후 평가 | 제언: 프로토타입 반복 평가 |
|---|---|---|
| 문제 발견 | 후반 | 초기 |
| 수정 비용 | 큼 | 작음 |
| 사용자 반영 | 사후 | 설계 중 |
