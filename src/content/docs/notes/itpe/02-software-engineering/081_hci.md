## 연관 키워드

- HCI(Human-Computer Interaction), 사용성(Usability), 접근성(Accessibility), UI(User Interface), UX(User Experience)
- 노먼의 상호작용 7단계, 실행의 간극(Gulf of Execution), 평가의 간극(Gulf of Evaluation), 닐슨 10대 휴리스틱(Heuristic), WAI-ARIA

## Ⅰ. HCI의 개요

- 핵심 요약 : 인간과 컴퓨터의 상호작용을 효율적이고 안전하며 만족스럽게 설계·평가하는 융합 학문이자 엔지니어링 방법론.
- 개념 : **HCI** (Human-Computer Interaction)는 사용자 인터페이스(UI, User Interface), 사용자 경험(UX, User Experience), 인지 심리학, 소프트웨어 공학을 융합해 인간과 컴퓨터 시스템의 상호작용을 설계·평가·구현하는 학문 및 엔지니어링 방법론이다.
- 배경 및 필요성 : 시스템이 복잡해지면서 조작 실수가 늘고, 디지털 전환(DX, Digital Transformation) 시대에는 고객 경험 만족이 경쟁력이 되었으며, 모바일·음성·XR(Extended Reality) 등 상호작용 채널이 다양해짐.
- 핵심 목표 : 사용성(Usability), 접근성(Accessibility), 사용자 경험 품질을 함께 달성하는 것.

## Ⅱ. HCI의 특징 및 장점

- 핵심 요약 : 학문 융합성, 인지 심리 기반 원리, 평가 원칙 체계, 다채널 확장성이 결합된 설계 체계.

1. 융합 학문 : UI, UX, 인지 심리학, 소프트웨어 공학을 통합적으로 접근 → 기술과 사람의 관점을 함께 설계에 반영.
2. **상호작용 7단계** (노먼, Donald Norman) : 목표 형성부터 상태 평가까지의 인지 흐름과 두 가지 간극 개념 → 조작 문제의 원인을 단계별로 진단.
3. **휴리스틱 평가** (Heuristic Evaluation) : 제이콥 닐슨(Jakob Nielsen)의 10대 원칙으로 화면을 점검 → 저비용으로 신속하게 결함 검출.
4. 멀티모달 확장 : 모바일, 워치, 음성 인터페이스, AR(Augmented Reality)/VR(Virtual Reality) 등 다양한 접점 지원 → 채널이 달라도 일관된 경험 유지.
5. 포용적 설계 : 장애인과 고령자를 포함한 전 사용자층의 접근성 확보 → 사용 가능한 사용자 범위 확대.

## Ⅲ. HCI의 구조 (흐름)

- 핵심 요약 : 목표 형성부터 시스템 상태 평가까지 순환하는 노먼의 상호작용 7단계와 두 가지 인지적 간극.

```text
[ 상호작용 7단계 (노먼) ]

[ 1. 목표 형성 ]
   ↓
[ 2. 의도 형성 → 3. 행동 계획 ]
   ↓
[ 4. 물리적 실행 ]
   ↓
[ 시스템 ]
   ↓
[ 5. 지각 → 6. 해석 ]
   ↓
[ 7. 시스템 상태 평가 ]
   ↓ 목표와 비교 (1단계로 회귀)
```

- **실행의 간극** (Gulf of Execution) : 사용자의 의도와 시스템이 제공하는 조작 방법의 차이 → **어포던스** (Affordance)와 시그니파이어(Signifier)로 해소.
- **평가의 간극** (Gulf of Evaluation) : 시스템 결과의 지각·해석과 원래 목표의 차이 → 즉각적이고 명확한 피드백으로 해소.

- 설계 평가 기준 : 닐슨의 사용성 평가 10대 휴리스틱.

| 휴리스틱 원칙 | 핵심 설명 및 가이드라인 |
| --- | --- |
| 1. 시스템 상태의 가시성 | 적절한 시간 안에 진행 상태를 지속적으로 피드백 |
| 2. 현실 세계와의 일치 | 전문 용어보다 사용자에게 친숙한 언어와 관습 사용 |
| 3. 사용자 제어와 자유 | 실수를 되돌리는 실행 취소와 탈출구 제공 |
| 4. 일관성과 표준 | 같은 단어, 아이콘, 배치가 플랫폼 전체에서 같은 의미를 가짐 |
| 5. 오류 예방 | 오류가 생길 조건을 사전에 제거하거나 확인 절차 제공 |
| 6. 회상보다 재인 | 기억에 의존하지 않고 화면에 선택지를 노출 |
| 7. 사용의 유연성과 효율성 | 숙련자를 위한 단축키와 가속기 제공 |
| 8. 미학적이고 미니멀한 디자인 | 무관한 정보를 배제해 시각적 혼란 방지 |
| 9. 오류 인식과 복구 지원 | 오류 메시지를 평이하게 쓰고 구체적인 해결책 제시 |
| 10. 도움말과 문서화 | 검색이 쉽고 작업에 구체적인 도움말 제공 |

## Ⅳ. 실행의 간극과 평가의 간극의 비교

- 핵심 요약 : 행동 실행 단계의 조작 문제와 결과 평가 단계의 해석 문제로 구분되는 두 간극.

```text
[ 실행의 간극과 평가의 간극 ]

[ 사용자 의도 ]
   ↓ ① 실행의 간극
[ 시스템 조작 ]
   ↓
[ 시스템 상태 변화 ]
   ↓ ② 평가의 간극
[ 원래 목표와 비교 ]
```

| 비교 항목 | 실행의 간극 (Gulf of Execution) | 평가의 간극 (Gulf of Evaluation) |
| --- | --- | --- |
| 발생 단계 | 목표 형성부터 물리적 실행까지 (1~4단계) | 지각부터 시스템 상태 평가까지 (5~7단계) |
| 문제 본질 | 의도와 시스템이 제공하는 조작 방법의 차이 | 결과의 지각·해석과 원래 목표의 차이 |
| 해소 수단 | 어포던스, 시그니파이어 | 즉각적이고 명확한 피드백 |
| 설계 시사점 | 조작 방법을 직관적으로 드러냄 | 수행 결과를 명확하게 가시화 |

## Ⅴ. HCI의 한계와 방안

- 핵심 요약 : 조작 실수 방지와 경험 만족도 향상의 이점, 인지 부하와 주관성, 접근성과 화려한 인터랙션 간 상충의 한계.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 다채널 환경의 인지 부하 | 모바일, 음성, AR/VR에서 상호작용 방식이 일관되지 않아 사용자의 혼란과 피로 증가 | 디자인 시스템 기반 크로스 플랫폼 일관성 유지, GOMS(Goals, Operators, Methods, Selection)와 KLM(Keystroke-Level Model)으로 작업 단계 정량 분석 | 작업 완료 시간, 오류율 |
| 정성 피드백의 주관성 | 인터뷰의 소수 의견 편향, 성능·일정 압박 속에서 UX 개선의 후순위화 | SUS(System Usability Scale) 같은 표준 지표와 A/B 테스트, 히트맵, 클릭 로그 분석을 병행 | SUS 점수 추이 |
| 접근성과 화려한 인터랙션의 상충 | 과도한 동적 그래픽이 스크린 리더와 색각 이상 사용자를 배제 | WAI-ARIA 등 웹 접근성 지침을 설계 원칙으로 두고, 자동 검사 도구를 빌드 파이프라인의 품질 게이트로 통합 | 접근성 검사 실패 건수 |

## Ⅵ. 현대 인터랙션 엔지니어링에 대한 기술사적 제언

- 핵심 요약 : 디자인 시스템으로 일관성을 기본값으로 만들고, 접근성 검증을 개발 파이프라인의 상시 절차로 두는 방향.
- 다변화된 프론트엔드 환경에서는 **디자인 시스템** (Design System)을 제품 기능보다 먼저 정비해야 한다. 디자인 조직과 개발 조직이 같은 디자인 토큰을 공유하면 화면마다 색과 간격이 달라지는 낭비가 줄고, 개발과 디자인 사이의 소통 비용도 낮아진다.
- 장애인과 고령자를 차별하지 않는 것은 설계 품질의 기본이므로, WCAG와 KWCAG(Korean Web Content Accessibility Guidelines)를 준수 기준으로 삼고, 자동 검사로 잡히지 않는 영역은 실사용자 검증 절차를 추가하는 것이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : HCI는 인지 심리 원칙과 공학적 검증을 결합한 상호작용 품질 체계.
- 시사점 : 디자인 시스템으로 일관성을 유지하고, 데이터로 UX 결정을 검증하며, 접근성 검사를 파이프라인에 내재화하는 것이 핵심 과제.
