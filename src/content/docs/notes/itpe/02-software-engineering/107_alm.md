## Ⅰ. ALM(애플리케이션 수명주기 관리)의 개요

- **개념** : 소프트웨어 애플리케이션의 최초 아이디어 발상 및 비즈니스 거버넌스 단계부터 요구사항 분석, 아키텍처 설계, 코딩, 빌드, 테스트, 배포, 유지보수, 그리고 최종 시스템 폐기(Sunset)에 이르는 전 생명주기를 사람, 프로세스, 통합 도구체계로 통제하고 관리하는 종합 엔지니어링 관리 패러다임.
- **배경 및 필요성** : 개발 부서, QA 부서, 운영 부서가 제각각 분리된 도구(Word, Jira, Jenkins, Excel)를 사용함으로써 발생하는 정보 단절(Silo), 추적성 상실, 규제 컴플라이언스 준수 증적 확보의 한계를 극복.
- **3대 핵심 관리 영역** : 거버넌스(Governance), 개발(Development), 운영(Operations).

## Ⅱ. ALM의 3대 핵심 영역 및 전 주기 통합 흐름

```text
   ┌────────────────────────────────────────────────────────────────────────┐
   │ [ 1. 거버넌스 (Governance) ]                                          │
   │  - 비즈니스 포트폴리오 관리, 투자 의사결정, 리스크/컴플라이언스 통제    │
   └──────────────────┬──────────────────────────────────┬──────────────────┘
                      │                                  │
                      ▼                                  ▼
   ┌──────────────────────────────────┐┌──────────────────────────────────┐
   │ [ 2. 개발 (Development) ]        ││ [ 3. 운영 (Operations) ]         │
   │  - 요구관리 (SRS, 추적성 RTM)    ││  - 무중단 배포 및 변경 관리      │
   │  - 아키텍처 설계 및 구현 (Git)   ││  - 서비스 데스크 (ITSM / ITIL)   │
   │  - 품질 검증 (CI/CD 자동 테스트) ││  - 관측성 (APM 모니터링, 로그)   │
   └──────────────────────────────────┘└──────────────────────────────────┘
                      ▲                                  │
                      └──────── (피드백 및 장애 개선 루프) ┘
```

- **도구 체계의 통합 (Toolchain Integration)** : 단일 벤더의 모놀리식 ALM(과거 HP ALM, IBM Rational)에서 벗어나, 현대에는 Git, Jira, Confluence, Jenkins, SonarQube, ServiceNow를 REST API와 웹훅으로 느슨하게 통합하는 오픈 ALM 에코시스템으로 진화.
- **엔드투엔드 추적성 (Traceability)** : 사용자 요구 티켓 클릭 한 번으로 관련 설계 문서, 담당 개발자의 커밋, 통과된 테스트 결과, 프로덕션 배포 파드 상태까지 즉시 가시화.

## Ⅲ. 전통적 SDLC와 현대 ALM의 비교

| 비교 항목 | 전통적 소프트웨어 수명주기 (SDLC) | 현대 통합 ALM (Application Lifecycle) |
|---|---|---|
| 관리 범위 | 주로 '개발(요구분석~인도)' 단계에 집중 | 비즈니스 아이디어부터 운영 및 폐기까지의 전 생명주기 포괄 |
| 조직 및 도구 | 기획팀, 개발팀, 운영팀이 분절된 도구 사용 | 크로스 펑셔널 팀이 단일 통합 플랫폼/대시보드로 협력 |
| 변경 추적성 | 수작업 엑셀 문서로 관리되어 동기화 누락 | 소스코드 커밋, PR, 빌드, 배포 티켓 간 실시간 양방향 자동 링크 |
| 품질 보증 | 개발 완료 후 사후 단계별 일괄 검증 | 전 공정에 걸친 지속적 통합(CI) 및 자동화된 품질 게이트웨이 |
| 대표 솔루션 | 개별 CASE 도구, 수작업 문서 | Atlassian Suite(Jira+Bitbucket), Azure DevOps, GitLab |

## Ⅳ. 고도화된 ALM 운영을 위한 기술사적 제언

- **GitOps 및 밸류 스트림 관리(VSM, Value Stream Management)와의 융합** : ALM 시스템에 VSM을 결합하여 요구사항 티켓이 생성된 후 실제 고객에게 가치로 인도될 때까지의 전 과정에서 발생하는 병목 시간(Wait Time)과 리드타임을 정량 측정하고 낭비 요소를 지속적으로 제거해야 함.
- **금융 및 의료 분야의 컴플라이언스 감사 자동화** : 금융감독원 전자금융감독규정이나 FDA/ISO 규제 준수를 위해 별도의 수검 문서를 만드는 낭비를 없애고, ALM의 티켓 이력, 코드 리뷰 승인 기록, 테스트 실행 로그 자체를 불변의 디지털 감사 증적(Audit Trail)으로 공인받을 수 있는 형상 거버넌스 체계 구축.
