## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **ALM(Application Lifecycle Management)**은 애플리케이션의 기획·개발·배포·운영·폐기 전 과정을 관리하는 접근법 |
| 목적 | 단계별 산출물·변경 정보를 연결해 협업과 애플리케이션의 지속 관리를 지원 |

### Ⅱ. 생명주기 흐름

```text
기획·요구
    ↓
설계·개발
    ↓
시험·배포
    ↓
운영·유지보수

운영 피드백 → 다음 요구·계획
```

### Ⅲ. ALM 정보

| 정보 | 관리 목적 |
|---|---|
| 요구·설계 | 구현 범위와 근거 확인 |
| 코드·시험 | 변경 버전과 검증 결과 연결 |
| 릴리스·운영 | 배포 내용과 운영 이력 추적 |

**제언:** 공통 식별자와 변경 기록을 정해 요구부터 배포·운영까지 연결.

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **ALM(Application Lifecycle Management)**은 애플리케이션의 기획·개발·배포·운영·폐기 전 과정을 관리하는 접근법 |
| 목적 | 단계별 산출물·변경 정보를 연결해 협업과 애플리케이션의 지속 관리를 지원 |

## Ⅱ. 관리 대상과 정보 연결

```text
요구·우선순위
    ↓ 추적
설계·코드 변경
    ↓
시험·검증 결과
    ↓
릴리스·배포 기록
    ↓
운영 결과·장애 이력

개선 요구 → 요구 백로그 반영
```

## Ⅲ. ALM과 SDLC

| 구분 | ALM | SDLC |
|---|---|---|
| 관리 범위 | 기획부터 개발·운영·폐기까지 애플리케이션 전체 | 소프트웨어 개발에 필요한 생명주기 활동 |
| 중심 | 사람·절차·도구와 생명주기 산출물의 연결 | 요구·설계·구현·시험·배포의 개발 활동 |
| 관계 | 애플리케이션의 지속 관리 관점 | ALM에서 다루는 개발 활동의 주요 부분 |

## Ⅳ. 도입 시 고려사항

| 고려사항 | 적용 방향 |
|---|---|
| 추적성 | 요구·코드·시험·릴리스 간 식별자와 연결 규칙 수립 |
| 변경·형상 | 승인 상태와 버전·변경 이력의 일관된 관리 |
| 도구 연계 | 이종 도구 간 필요한 정보와 책임 경계 정의 |
| 운영 피드백 | 운영 이슈가 요구·개선 작업으로 이어지는 경로 마련 |

## Ⅴ. 기술사적 제언 — 변경 추적 정보의 일관성

| 한계 | 해결 방안 |
|---|---|
| 각 단계의 도구에 정보가 분산돼 변경 영향과 배포 내용을 확인하기 어려운 상황 | 최소 공통 식별자와 산출물 관계를 정의하고 변경 승인부터 릴리스까지 추적 정보를 유지 |
