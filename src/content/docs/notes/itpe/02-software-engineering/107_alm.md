## 한 줄 본질
- 기획, 개발, 테스트, 운영 조직이 서로 다른 도구(Excel, Git, Jira, HP QC)를 사용하여 프로젝트 가시성이 단절되고 결함 추적이 불가능한 사일로 병목 → 애플리케이션의 구상부터 개발, 배포, 유지보수, 폐기까지 전 수명주기를 단일 데이터 모델과 통합 도구 체인으로 관리하는 종합 프레임워크 / 플랫폼 구축 및 문화적 적응 비용 수반

## 핵심 그림
```text

+-------------------------------------------------------------------------+
|                       [ 1. 거버넌스 (Governance) ]                      |
|            - IT 포트폴리오 관리, 요구사항 관리, 자원 및 일정 관리       |
|            - 전 생명주기 변경 관리, 컴플라이언스 및 품질 감사           |
|                                    │                                    |
|         +--------------------------+--------------------------+         |
|         v                                                     v         |
| [ 2. 개발 (Development) ]                 [ 3. 운영 (Operations) ]      |
| - 아키텍처 및 상세 설계                   - 릴리스 및 무중단 배포       |
| - 버전/형상 관리 (Git)                    - 서비스 데스크 (ITSM)        |
| - 지속적 통합 및 자동 빌드                - 인프라 모니터링 (APM)       |
| - 단위/통합/인수 테스트 자동화            - 장애 및 인시던트 관리       |
+-------------------------------------------------------------------------+
|                  통합 추적성 레이어 (OSLC / REST API 연동)              |
+-------------------------------------------------------------------------+
```

## 핵심 용어
- ALM 3대 기둥: 애플리케이션의 사업적 가치를 의사결정하는 '거버넌스(Governance)', 코드를 구현하고 테스트하는 '개발(Development)', 실제 환경에 배포하고 서비스하는 '운영(Operations)'의 유기적 결합
- OSLC(Open Services for Lifecycle Collaboration): 서로 다른 벤더의 ALM 도구(예: IBM, Atlassian, Microsoft) 간에 링크 기반으로 요구사항, 결함, 테스트 데이터를 상호 교환하기 위한 W3C 연계 오픈 표준

## 핵심 통찰
- SDLC(소프트웨어 개발 생명주기)가 "요구사항 분석부터 배포까지의 개발 프로세스 단계"를 의미한다면, ALM은 비즈니스 아이디어 발굴부터 폐기(Retirement)까지 "사람, 프로세스, 도구를 모두 묶는 경영 거버넌스 플랫폼"임
- 현대의 ALM은 과거의 무거운 모놀리식 단일 벤더 스위트(IBM Jazz 등)에서 탈피하여, Jira, GitHub, Jenkins, Datadog 등 모던 오픈 도구들을 API와 Webhook으로 유연하게 엮는 '통합 도구 체인 ALM'으로 진화함
- ALM의 궁극적 핵심 가치는 "요구사항 하나가 변경되었을 때, 어떤 코드가 커밋되었고, 어떤 테스트를 통과했으며, 언제 프로덕션에 배포되었는가"를 1초 만에 증명하는 '단일 진실 공급원(Single Source of Truth)' 확보임

## 이웃 토픽과 구분
- ALM vs DevOps: ALM = 요구사항, 프로젝트 관리, 변경 승인, 라이프사이클 전체를 아우르는 '거버넌스 프레임워크' / DevOps = 개발과 운영의 빠른 피드백과 자동화된 파이프라인(CI/CD)에 집중하는 '문화 및 실천 기술'

## 문제·원인·대책
- 적용 상황: 글로벌 분산 개발 환경의 엔터프라이즈 ERP 고도화 프로젝트
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 릴리스 직전 고객 요구사항과 실제 배포된 바이너리의 기능이 달라 인수 거부 | 기획 문서는 워드, 코드는 Git, 결함은 엑셀로 따로 관리되어 동기화 실패 | Atlassian 스위트(Jira-Bitbucket-Xray) 기반 전 생명주기 ALM 통합 구축 | 요구사항과 배포 산출물 일치율 100% 달성 |
| 도구 간 데이터 포맷 차이로 프로젝트 현황 취합 보고서 작성에 매주 2일 소요 | 각 개발 파트별 이종 도구 사용 및 데이터 파이프라인 부재 | REST API 및 OSLC 기반 ALM 대시보드 자동화 구축 | 수작업 보고 공수 95% 절감 및 실시간 현황 모니터링 |
