소프트웨어 공학 → 개발 관리 → **ALM(Application Lifecycle Management)**

## 30초 인출

- 본질: ALM은 요구·설계·개발·시험·배포·운영까지 애플리케이션 전 생명주기를 하나의 도구와 프로세스로 통합 관리하는 체계
- 메커니즘: 요구 관리·형상·빌드·시험·결함·배포 도구를 하나의 저장소와 요구 ID로 연결해 산출물 사이의 추적성과 진행 현황을 통합해서 확인
- 통찰: 도구가 분리되면 산출물 연결이 끊겨 변경 영향을 찾기 어려우므로 하나의 저장소와 공통 ID로 전 주기 추적성을 확보

<details>
<summary>핵심 용어</summary>

- **ALM(Application Lifecycle Management)** : 애플리케이션 전 생명주기를 통합 관리하는 체계
- **단일 진실 공급원(SSOT, Single Source of Truth)** : 모든 구성원이 같은 최신 정보를 보도록 하나로 관리하는 저장소
- **전주기 추적성(End-to-End Traceability)** : 요구에서 운영까지 산출물을 연결해 추적할 수 있는 성질
- **피드백 루프(Feedback Loop)** : 운영 중 결함·요구가 다음 개발 계획으로 되돌아가는 순환
- **형상관리(SCM)** : 산출물 변경과 버전을 통제하는 활동

</details>

## 2~4교시 25점 답안

## Ⅰ. ALM의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **ALM** 은 애플리케이션 전 생명주기를 통합된 도구와 프로세스로 관리하는 체계 |
| 목적 | 생명주기 전반의 추적성 확보와 개발 생산성·품질 향상 |

## Ⅱ. 개별 도구 사용과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 통합 관리 | 요구부터 운영까지 하나의 체계 |
| 추적성 | 산출물 사이의 연결 |
| 현황 가시성 | 진행·품질 현황의 통합 확인 |

## Ⅲ. ALM의 구성과 연계 흐름

### ALM 구성

```text
ALM 통합 저장소·ID
    ├─ 요구 관리 ── 요구·백로그
    ├─ 개발 관리 ── 형상·빌드
    ├─ 품질 관리 ── 시험·결함
    └─ 배포·운영 ── 릴리스·모니터링
```

### 확대: 피드백 루프

```text
요구 → 설계 → 개발 → 시험 → 배포 → 운영
 ↑                                      │
 └─── 운영 결함·사용자 요구 환류 ───────┘
```

## Ⅳ. 도구 방식의 비교와 기능

| 구분 | 개별 도구 운영 | ALM 통합 |
|---|---|---|
| 데이터 | 도구마다 분리 | 하나의 저장소 |
| 추적성 | 수작업 연결 | 공통 ID로 자동 연결 |
| 현황 파악 | 도구별 취합 | 통합 대시보드 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 도구 통합 비용과 구성 복잡도 | 핵심 도구부터 단계적 통합 |
| 팀별 도구·프로세스 상이로 도입 저항 | 공통 프로세스 정의와 교육 |
| ID 규칙 부재로 연결 불가 | 요구 ID·이슈 ID 규칙 표준화 |

## Ⅵ. 제언

요구·형상·시험·배포 도구를 하나의 저장소와 공통 ID로 연결해 전 주기 추적성을 확보하고, 핵심 도구부터 단계적으로 통합

### 단계적 통합

```text
요구·형상 도구 통합
    ↓
시험·결함 연계
    ↓
배포·운영 연계
```

### 선택 근거: 도구별 개별 운영과의 비교

| 구분 | 개별 운영 | 제언: 공통 ID 통합 |
|---|---|---|
| 변경 영향 | 수작업 탐색 | ID로 조회 |
| 현황 | 취합 필요 | 통합 확인 |
| 도입 부담 | 낮음 | 단계적 투자 |
