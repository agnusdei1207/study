## 큰 그림과 30초 인출

- **본질**: 기획, 개발, 테스트, 운영 조직이 각기 다른 도구로 일하면서 발생하는 사일로(Silo)를 해체하고, 요구사항 정의부터 개발, 배포, 유지보수, 폐기까지 전 과정을 단일 데이터 모델로 통합 관리하는 엔지니어링 거버넌스 체계이다.
- **메커니즘**: 거버넌스(Governance) $\rightarrow$ 개발(Development) $\rightarrow$ 운영(Operations)의 3대 핵심 축을 OSLC 표준과 REST API로 연계하여, 요구사항 하나가 코드 커밋과 테스트를 거쳐 배포되기까지 전 과정을 1초 만에 추적한다.
- **산출물**: ALM 통합 추적 대시보드, 엔드투엔드 요구사항 추적표, 변경 이력 및 형상 감사 보고서, DORA/품질 성숙도 리포트.

## 핵심 메커니즘

### (1) ALM 3대 핵심 기둥 (Gartner / Forrester)
1. **거버넌스 (Governance)**:
   - 비즈니스 전략과 IT 투자의 일치, 포트폴리오 관리, 요구사항 정의 및 우선순위 결정.
   - 컴플라이언스 준수 및 전 생명주기 변경 영향도 심의(CAB 연계).
2. **개발 (Development)**:
   - 애자일 스프린트 백로그 관리, 소스코드 버전 관리(Git), 지속적 통합(CI).
   - 테스트 케이스 설계, 실행, 정적 분석(SonarQube) 및 결함 추적.
3. **운영 (Operations)**:
   - 프로덕션 배포 파이프라인(CD), ITSM 서비스 데스크 연계, 인시던트 관리.
   - 사용자 피드백을 백로그로 재환류하는 지속적 개선 루프 가동.

### (2) SDLC vs ALM vs PLM 비교

| 비교 항목 | SDLC (소프트웨어 개발 생명주기) | ALM (애플리케이션 수명주기 관리) | PLM (제품 수명주기 관리) |
|---|---|---|---|
| **관리 대상** | 소프트웨어 개발 프로젝트 단계 | **소프트웨어 애플리케이션 전체 수명** | 물리적 제조 완제품 (자동차, 항공기 등) |
| **시간적 범위** | 요구사항 분석부터 배포 완료까지 | **사업 구상부터 개발, 운영, 폐기(Retirement)까지**| 제품 기획부터 제조, 유통, AS, 폐기까지 |
| **핵심 초점** | 공학적 개발 프로세스 순서 통제 | **사람, 프로세스, 도구를 묶는 경영 거버넌스** | 하드웨어 부품표(BOM) 및 CAD/CAM 도면 관리 |
| **대표 도구** | Waterfall, Scrum 방법론 모델 | **Jira, GitLab, Azure DevOps, Polarion** | Siemens Teamcenter, PTC Windchill |

### (3) OSLC (Open Services for Lifecycle Collaboration) 연계 표준
- 서로 다른 벤더의 파편화된 도구(예: Jira의 요구사항, Git의 소스코드, HP QC의 테스트 케이스)를 단일 데이터베이스로 통합하지 않고, **W3C Linked Data 기반의 URI 링크로 상호 연결하여 실시간 조회·추적을 실현하는 오픈 인터페이스 규격**임.

## 실무 적용 및 도입 체크리스트

1. **단일 진실 공급원(SSOT) 확립**: 분산된 이종 도구 체인이 웹훅(Webhook)과 REST API로 연동되어 단일 대시보드에서 전 생명주기 가시성이 확보되는가?
2. **개발자 입력 부담 제로화**: 개발자가 티켓 상태를 수작업 변경하지 않아도 Git 커밋, PR 머지, 빌드 성공 이벤트에 따라 티켓 상태가 자동 전이되는가?
3. **양방향 추적성 자동 감사**: 요구사항 티켓 클릭 시 연관된 모든 브랜치, 커밋 해시, 빌드 파이프라인 번호, 배포 클러스터 정보가 1클릭으로 노출되는가?
4. **ITSM 운영 피드백 환류**: 서비스 데스크에 접수된 고객 장애 티켓이 개발팀의 버그 백로그 티켓으로 즉시 자동 변환되는 프로세스가 수립되어 있는가?

| 위험 | 대책 | 효과 |
|---|---|---|

## 차세대 확장 및 융합

- **Value Stream Management (VSM) 플랫폼으로의 진화**: 전통적 ALM의 단순 티켓 관리를 넘어, 고객의 아이디어가 실제 배포되어 비즈니스 가치를 창출하기까지의 흐름(Value Stream)을 가시화하고 병목을 제거하는 지능형 VSM 플랫폼으로 발전하고 있다.
- **AI 증강 ALM (Generative ALM)**: 기획서 텍스트를 입력하면 사용자 스토리와 테스트 케이스를 자동 생성하고, 런타임 장애 로그를 분석하여 원인 코드와 담당 개발자 티켓을 자동 매핑하는 AI 주도 수명주기 관리가 현실화되고 있다.

## 25점형 실전 답안 프레임워크

### 1단락: ALM의 대두 배경 및 개념
- **배경**: 분산된 도구 사일로(Excel, Word, Git, ITSM)로 인한 프로젝트 가시성 상실과 결함 추적 불능 극복 필요.
- **정의**: 비즈니스 구상부터 요구사항, 개발, 테스트, 배포, 운영, 폐기까지 전 라이프사이클을 사람·프로세스·도구의 단일 체계로 묶는 통합 엔지니어링 거버넌스 프레임워크.

### 2단락: ALM 3대 핵심 기둥 및 아키텍처
- **3대 핵심 축**: 거버넌스(포트폴리오/요구사항) $\leftrightarrow$ 개발(형상/빌드/테스트) $\leftrightarrow$ 운영(릴리스/ITSM/모니터링).
- **도구 체인 통합 아키텍처 도해**: OSLC 및 REST API 기반 이종 툴(Jira, GitLab, SonarQube, ArgoCD, Datadog) 간 데이터 링크 연계 구조.
- **SDLC vs ALM vs PLM 상세 비교표**.

### 3단락: 실무 엔터프라이즈 ALM 구축 전략 및 실패 극복 방안
- **자동화된 이벤트 파이프라인**: Git Commitlint와 Webhook을 활용하여 개발자 수작업 입력을 배제하는 'Living ALM' 구현.
- **DORA 4대 핵심 지표 연계**: 배포 빈도, 변경 리드타임, 장애 복구 시간(MTTR)을 실시간 모니터링하여 지속적 프로세스 최적화.

### 4단락: 차세대 가치 스트림 관리(VSM)로의 기술사적 진화 제언
- **단순 도구 통합을 넘어 비즈니스 가치 흐름 최적화**: 티켓 개수 관리에 매몰된 과거의 ALM을 탈피하여, 아이디어에서 고객 가치 실현까지의 정체 구간을 실시간 탐지하는 VSM 플랫폼으로 진화할 것을 제언함.

## 10점형 핵심 요약

1. **정의**: 비즈니스 구상부터 개발, 테스트, 운영, 폐기까지 전 과정을 사람·프로세스·도구의 통합 체계로 관리하는 수명주기 거버넌스.
2. **3대 핵심 기둥**: 거버넌스(기획/요구사항), 개발(형상/테스트/CI/CD), 운영(릴리스/ITSM/관제).
3. **실무 핵심**: OSLC 표준과 웹훅 연동으로 개발자의 수작업 부담을 제거하고, 전 생명주기 실시간 양방향 추적성을 완성함.
