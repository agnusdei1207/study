## 연관 키워드

- 소프트웨어 시험, 시험 수준, 시험 유형, 단위 시험, 통합 시험, 시스템 시험, 인수 시험
- V-모델(V-Model), 테스트 피라미드(Test Pyramid), 검증(Verification), 확인(Validation), 신뢰성 시험, 이식성 시험

## Ⅰ. 소프트웨어 시험 유형·수준의 개요

- 핵심 요약 : 시험 수준은 검증 대상의 통합 범위, 시험 유형은 확인하려는 품질 특성을 나누는 상호 보완적 분류 체계.
- 개념 : 개발 산출물의 요구 충족 여부와 숨은 결함을 확인하는 **소프트웨어 시험** (Software Test)의 체계는 대상 범위 축인 **시험 수준** (Test Level)과 품질 특성 축인 **시험 유형** (Test Type)으로 구성.
- 배경 및 필요성 : 결함의 발견이 늦어질수록 수정 비용이 커지고 단일 시험으로 기능·성능·신뢰성을 모두 확인할 수 없어 단계별·관점별 체계 필요.
- 주요 목적 : 결함의 조기 발견, 요구사항과 시험 결과의 추적, 출시 판단의 객관적 근거 확보.

## Ⅱ. 시험 수준·유형의 특징 및 장점

- 핵심 요약 : 수준 분리가 결함 위치 추적을, 유형 분리가 품질 특성별 위험 가시화를 담당하는 이중 축 체계.

1. 수준 분리 : 단위 시험→통합 시험→시스템 시험→인수 시험 순서로 검증 대상 확대 → 결함 발생 위치의 신속한 특정.
2. 유형 분리 : 기능 시험과 성능·신뢰성·이식성 같은 비기능 시험의 구분 수행 → 품질 특성별 위험의 가시화.
3. V-모델 대응 : 각 개발 단계 산출물에 대응하는 시험 수준의 사전 계획 → 시험 활동의 조기 착수.
4. 위험 기반 배분 : 영향도와 발생 가능성이 높은 영역에 시험 자원 집중 → 한정 자원의 효율적 활용.

## Ⅲ. 소프트웨어 시험 체계의 구조 (흐름)

- 핵심 요약 : **V-모델** (V-Model, 개발 단계와 시험 수준의 대응을 V자로 표현한 모형)이 수준 배치를 정하고 **테스트 피라미드** (Test Pyramid, 하위 수준일수록 시험 수를 늘리는 계층 구조)가 자동화 비중을 안내.

```text
요구사항 정의 ──────── 인수 시험
  시스템 설계 ────── 시스템 시험
    아키텍처 설계 ── 통합 시험
      상세 설계 ──── 단위 시험
           구현
```

```text
        인수 시험  (소수·느림)
           ↑
       시스템 시험
           ↑
        통합 시험
           ↑
        단위 시험  (다수·빠름)
```

- 유형 대표 : 신뢰성 시험은 고장 발생·복구 특성과 결함 내성을, 이식성 시험은 환경별 설치·실행 가능성을 검증 대상으로 삼음.
- 유형 추가 : 성능 시험·보안 시험도 대표적 비기능 유형으로 운영 품질 위험을 다룸.

## Ⅳ. 검증(Verification)과 확인(Validation)의 비교

- 핵심 요약 : 수준(무엇을 시험하는가)과 유형(어떤 품질을 보는가)은 독립적인 축이며, 시험 전체는 명세 대비 검증과 사용자 요구 대비 확인의 두 관점으로 수렴.
- **검증** (Verification) : 산출물이 명세를 정확히 이행했는지 확인하는 관점.
- **확인** (Validation) : 산출물이 사용자 요구와 업무 목적에 부합하는지 확인하는 관점.

| 비교 축 | 검증 (Verification) | 확인 (Validation) |
| --- | --- | --- |
| 핵심 질문 | 명세대로 만들었는가 | 필요한 것을 만들었는가 |
| 판단 기준 | 설계·명세 문서 | 사용자 요구·업무 목적 |
| 주요 활동 | 리뷰·단위 시험·통합 시험 | 시스템 시험·인수 시험 |
| 수행 시점 | 개발 전 과정 | 완성된 산출물 대상 |
| 대표 오류 | 명세 이행 누락 | 요구 자체의 불일치 |

## Ⅴ. 시험 체계의 한계와 방안

- 핵심 요약 : 상위 수준 편중·환경 불일치·커버리지 착시·비기능 누락을 포트폴리오 균형과 추적 체계로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 상위 수준 시험 과다 | **E2E** (End-to-End) 시험 비중 확대 → 느리고 불안정한 회귀 | 단위·통합 시험 비중 확대의 피라미드 균형 | E2E 시험 비율 |
| 운영 환경 불일치 | 시험 환경 차이로 재현 불가 결함 잔존 | 환경 구성의 코드화·대표 조건 시험 | 환경 기인 결함 수 |
| 커버리지 착시 | 코드 실행률을 품질 증거로 오판 | 요구 추적 매트릭스와 결함 추세의 병행 해석 | 요구 커버리지율 |
| 비기능 시험 후행 | 성능·장애 이슈가 운영 단계로 유출 | 비기능 수용 기준의 계획 단계 명시 | 비기능 결함 유출률 |

## Ⅵ. 시험 체계 운영에 대한 제언

- 핵심 요약 : 품질보증 조직을 중심으로 요구-시험 추적과 수준·유형별 시험 포트폴리오의 제도화.

1. 품질보증(QA, Quality Assurance) 조직은 요구사항마다 시험 수준·유형·수용 기준을 추적 매트릭스로 등록하고 변경 시 갱신.
2. 개발 조직은 단위 시험 자동화를 코드 병합의 완료 조건으로 규정해 하위 수준의 결함 필터를 상시 유지.
3. 운영·보안 담당 조직은 장애 이력과 취약점 시나리오를 인수 시험 조건에 반영하는 협의 절차를 운영.

## Ⅶ. 결론

- 핵심 요약 : 시험 수준과 유형의 두 축을 함께 설계할 때 기능 적합성과 운영 품질이 균형 있게 검증됨.
- 시사점 : 빠른 하위 수준 피드백과 현실적인 상위 수준 확인의 조합이 출시 판단의 신뢰를 결정.
