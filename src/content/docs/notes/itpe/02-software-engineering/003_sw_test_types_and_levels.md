## 연관 키워드
- 테스트 레벨, 테스트 유형, V-모델, 테스트 피라미드, 신뢰성, 이식성

## Ⅰ. 테스트 레벨·유형의 개요
- 핵심 요약 : 테스트 레벨은 검증 대상을, 테스트 유형은 품질 관점을 나눠 결함을 단계별로 발견하는 체계.
- 개념 : 컴포넌트부터 인수까지 다양한 범위에서 요구 충족과 품질 특성을 확인하는 검증 활동.
- 필요성 : 한 단계 시험만으로 통합 결함, 요구 불일치, 운영 품질을 모두 보장하기 어려움.
- 목적 : 조기 결함 발견, 요구 추적, 출시 위험의 근거 기반 판단.

## Ⅱ. 테스트 레벨과 유형의 특징
- 핵심 요약 : 낮은 레벨은 빠른 국소 피드백, 높은 레벨은 실제 사용 맥락과 시스템 품질 확인에 적합.
1. 레벨 분리 : 단위·통합·시스템·인수로 대상 확대 → 결함 위치 추적 용이.
2. 유형 분리 : 기능성·성능·보안·신뢰성·이식성별 시험 → 비기능 위험 가시화.
3. 위험 기반 : 영향도·발생 가능성에 시험 깊이 배정 → 자원 집중.

## Ⅲ. V-모델과 테스트 피라미드
- 핵심 요약 : 개발 산출물마다 대응 테스트를 계획하고 자동화 피라미드로 반복 주기를 구성.
```text
요구사항 ───────────────── 인수 테스트
시스템 설계 ───────────── 시스템 테스트
아키텍처 설계 ───────── 통합 테스트
상세 설계 ───────────── 단위 테스트
              구현
```
```text
다수 단위 테스트(빠름)
          ↓
중간 규모 통합·계약 테스트
          ↓
소수 시스템·인수 테스트(느리나 현실적)
```
- 유형 예 : 신뢰성은 고장·복구 특성, 이식성은 환경별 설치·실행 가능성을 검증.

## Ⅳ. 레벨과 유형의 비교
- 핵심 요약 : 레벨은 '무엇을 묶어 시험하는가', 유형은 '어떤 품질 속성을 확인하는가'를 답함.
| 기준 | 테스트 레벨 | 테스트 유형 |
|---|---|---|
| 분류축 | 검증 대상·통합 범위 | 품질 특성·목적 |
| 예 | 단위, 통합, 시스템, 인수 | 기능, 성능, 신뢰성, 이식성 |
| 설계 질문 | 어느 경계에서 검증할까 | 어떤 품질 기준을 확인할까 |

## Ⅴ. 테스트 체계의 한계와 방안
- 핵심 요약 : 환경 차이·커버리지 착시·비기능 누락을 위험 기준과 재현 가능한 환경으로 보완.
| 한계 | 영향 | 대응 |
|---|---|---|
| E2E 시험 과다 | 느리고 불안정한 피드백 | 단위·계약·통합 시험 균형화 |
| 운영환경 차이 | 재현 실패·잠복 결함 | 환경 구성 코드화, 대표 조건 시험 |
| 커버리지 수치 오용 | 실행량을 품질로 오판 | 요구·위험·결함 추세와 함께 해석 |

## Ⅵ. 테스트 계획 제언
- 핵심 요약 : QA는 요구 추적성과 품질 위험을 레벨·유형·환경별 시험에 배분.
1. 분석가와 QA는 요구별 시험 레벨·유형·수용기준을 추적표에 연결.
2. 운영·보안 담당자는 복구·취약점·이식성 시험을 출시 조건에 포함.
3. 팀은 결함 유출률과 탐지 시점을 회고해 포트폴리오를 조정.

## Ⅶ. 결론
- 핵심 요약 : 레벨과 유형을 함께 설계해야 기능 적합성과 운영 품질을 균형 있게 검증.
- 시사점 : 빠른 단위 피드백과 현실성 있는 시스템 시험을 함께 유지.
