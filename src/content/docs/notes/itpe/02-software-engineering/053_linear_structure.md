소프트웨어 공학 → 자료구조·알고리즘 → **선형 구조(Linear Structure)**

## 30초 인출

- 본질: 데이터 원소들이 연속적인 일련의 순서를 가지고 1:1로 연결되어 앞뒤 원소 간의 전후 관계가 명확히 성립하는 기초 자료구조
- 메커니즘: 연속 메모리 블록과 인덱스 접근을 활용하는 배열(Array)과 노드 포인터 링크를 활용하는 연결 리스트(Linked List), 입출력 지점을 제한한 스택(LIFO)과 큐(FIFO)
- 통찰: 무조건적인 배열 사용은 중간 삽입/삭제 시 $O(n)$ 데이터 이동 비용과 크기 고정 한계를 초래하므로 데이터의 동적 증감과 접근 패턴에 맞춘 원형 큐 및 연결 리스트 선별 채택 필수

<details>
<summary>핵심 용어</summary>

- **Linear Structure(선형 구조)** : 데이터 원소들 사이에 1:1 관계가 성립하여 순차적인 나열을 형성하는 자료구조
- **Array(배열)** : 동일한 타입의 데이터 원소들이 메모리상에 연속적으로 저장되어 인덱스(Index)를 통한 $O(1)$ 임의 접근을 지원하는 구조
- **Linked List(연결 리스트)** : 데이터와 다음 노드를 가리키는 포인터를 포함하는 노드들이 체인 형태로 연결된 동적 자료구조
- **Stack(스택)** : 한쪽 끝(Top)에서만 데이터의 삽입(Push)과 삭제(Pop)가 일어나는 후입선출(LIFO) 형태의 선형 구조
- **Queue(큐)** : 한쪽 끝(Rear)에서는 삽입(Enqueue)만, 반대쪽 끝(Front)에서는 삭제(Dequeue)만 일어나는 선입선출(FIFO) 구조
- **Circular Queue(원형 큐)** : 배열 기반 선형 큐의 잘못된 포화 상태(메모리 낭비)를 극복하기 위해 배열의 양 끝을 논리적으로 연결한 큐

## 2~4교시 25점 답안

## Ⅰ. 선형 구조의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 데이터를 구성하는 원소들이 하나의 직선 형태로 연속되어 앞뒤 원소 간에 1:1의 선행·후행 관계를 갖는 가장 기초적인 자료구조 |
| 목적 | 순차적인 데이터의 저장과 처리, 인덱스 기반의 초고속 검색, 제한된 순서 제어를 통한 버퍼링 및 실행 취소(Undo) 구현 |

## Ⅱ. 선형 구조의 핵심 특징

| 특징 | 의미 |
|---|---|
| 1:1 순차성 | 첫 번째와 마지막 원소를 제외한 모든 원소가 정확히 하나의 선행 원소와 하나의 후행 원소를 가짐 |
| 메모리 할당 방식의 이원화 | 물리적으로 연속된 메모리에 할당하는 정적/동적 배열과 포인터로 논리적 연속성을 유지하는 연결 리스트 공존 |
| 연산 제약에 따른 특화 | 접근 지점을 양 끝으로 제한하여 스택(LIFO), 큐(FIFO), 데크(Deque) 등 다양한 제어 구조 파생 |
| 높은 캐시 지역성 | 배열의 경우 인접한 메모리 공간에 원소들이 밀집하여 CPU L1/L2 캐시 히트율(Spatial Locality) 극대화 |

## Ⅲ. 4대 선형 구조 체계 및 동작 메커니즘

### 4대 선형 구조의 메모리 모델 및 데이터 제어 흐름

```text
[1. 배열 (Array)] ── 물리적 연속 메모리
  Index:   [ 0 ]   [ 1 ]   [ 2 ]   [ 3 ]
  Value:  | DataA | DataB | DataC | DataD | ──→ arr[2] 임의 접근: O(1)
  ★ 중간 삽입 시: 이후 원소들을 우측으로 1칸씩 이동 (Shift Overhead: O(n))

[2. 연결 리스트 (Linked List)] ── 비연속 동적 메모리 노드 링크
  [Head] ──→ [DataA | Next] ──→ [DataB | Next] ──→ [DataC | null]
  ★ 중간 삽입 시: 포인터 링크만 변경 (O(1), 위치 탐색 O(n) 별도)

[3. 스택 (Stack) - LIFO]                  [4. 큐 (Queue) - FIFO]
       │ Top                                     │ Enqueue (삽입)
       ▼ Push / Pop                              ▼
  ┌──────────┐                             ┌──────────┐ ── Rear
  │  Data C  │ ◄── 가장 나중에 삽입        │  Data C  │
  ├──────────┤                             ├──────────┤
  │  Data B  │                             │  Data B  │
  ├──────────┤                             ├──────────┤
  │  Data A  │ ◄── 가장 먼저 삽입          │  Data A  │ ── Front
  └──────────┘                             └──────────┘
                                                 │ Dequeue (삭제)
                                                 ▼ (가장 먼저 삽입된 항목 인출)
```

### 4대 선형 구조 연산별 시간 복잡도 분석

| 자료구조 | 임의 접근 (Access) | 순차 검색 (Search) | 맨 앞/끝 삽입 | 중간 삽입/삭제 | 공간 복잡도 |
|---|---|---|---|---|---|
| **배열 (Array)** | **$O(1)$** | $O(n)$ | 끝: $O(1)$, 앞: $O(n)$ | **$O(n)$** (원소 시프트) | $O(n)$ (추가 포인터 없음) |
| **연결 리스트** | $O(n)$ | $O(n)$ | 앞: **$O(1)$**, 끝: $O(1)$ | 위치 알 때: **$O(1)$** | $O(n)$ (포인터 추가 메모리) |
| **스택 (Stack)** | 미지원 | $O(n)$ | Top: **$O(1)$** (Push/Pop) | 미지원 (Top만 조작) | $O(n)$ |
| **큐 (Queue)** | 미지원 | $O(n)$ | Rear/Front: **$O(1)$** | 미지원 (양 끝만 조작) | $O(n)$ |

## Ⅳ. 주요 선형 구조 간 비교 및 원형 큐 메커니즘

### 배열(Array) vs 연결 리스트(Linked List) 상세 비교

| 비교 항목 | 배열 (Array) | 연결 리스트 (Linked List) |
|---|---|---|
| **메모리 할당** | 컴파일 타임(정적) 또는 런타임 연속 블록 할당 | 힙(Heap) 영역에 노드별 동적 분산 할당 |
| **인덱스 접근 속도** | $O(1)$ (메모리 주소 직접 계산: `Base + i * size`) | $O(n)$ (Head부터 포인터를 타고 순차 탐색) |
| **삽입 및 삭제** | 원소들의 물리적 이동(Shift)으로 인해 $O(n)$ 소모 | 포인터 링크 2개만 변경하므로 $O(1)$ 완료 |
| **캐시 효율성** | 연속 메모리로 공간 지역성이 매우 우수함 | 포인터 참조로 메모리가 파편화되어 캐시 미스 증가 |
| **추가 오버헤드** | 미사용 공간에 대한 사전 할당 낭비 가능성 | 노드마다 포인터 변수(4~8바이트) 추가 메모리 소모 |

### 원형 큐(Circular Queue) 포화 및 공백 판정 메커니즘

```text
배열 기반 선형 큐의 앞쪽 빈 공간 낭비를 해결하기 위해 모듈러(mod) 연산 적용:
  - 큐 크기: Capacity
  - Front: 첫 번째 원소의 직전 위치
  - Rear: 마지막 원소의 위치

공백 상태 판정: Front == Rear
포화 상태 판정: (Rear + 1) % Capacity == Front (1칸을 비워두어 공백과 구분)
```

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 선형 큐에서 Dequeue로 발생한 앞쪽 빈 공간을 재활용하지 못해 가짜 포화(False Overflow) 발생 | 모듈러 연산(`% Capacity`)을 적용하여 인덱스를 원형으로 순환시키는 원형 큐 채택 |
| 스택의 크기를 정적으로 고정할 경우 재귀 호출 심화 시 Stack Overflow 예외 발생 | 동적 배열 기반 가변 스택을 구현하거나 꼬리 재귀 최적화(Tail Call Optimization) 적용 |
| 대규모 트래픽 발생 시 메시지 큐의 무제한 큐잉으로 인한 메모리 고갈(OOM) 장애 | 큐의 최대 용량(Bounded Queue)을 설정하고 초과 시 배압(Backpressure) 및 거부 정책 적용 |

## Ⅵ. 제언

CPU 캐시 친화적(Data-Oriented Design) 배열 구조와 링 버퍼(Ring Buffer) 기반 초저지연 IPC 파이프라인

### 고성능 링 버퍼 기반 IPC 파이프라인

```text
[생산자 프로세스 (Producer)]
       │
       ▼ (Lock-Free 원자적 CAS 연산)
┌────────────────────────────────────────────────────────────────────────┐
│ 고성능 공유 메모리 링 버퍼 (LMAX Disruptor Architecture)               │
│                                                                        │
│   [ 0 ] ─── [ 1 ] ─── [ 2 ] ─── [ 3 ] ─── [ 4 ] ─── [ 5 ]              │
│     ▲                   ▲                                              │
│     │ Front (소비자)     │ Rear (생산자)                                │
│                                                                        │
│   - 캐시 라인 패딩(Cache Line Padding)으로 False Sharing 완벽 차단      │
│   - 가비지 컬렉션(GC) 부하 제로: 사전 할당된 연속 원형 메모리 재활용   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼ (순차 읽기 O(1))
[소비자 프로세스 (Consumer)]
```

### 선형 자료구조 선택 의사결정 체계

```text
데이터 처리 요구사항 분석
       ↓
[데이터의 인덱스 기반 임의 접근(Random Access) 조회가 빈번한가?]
       ├─ 예 ──→ 배열(Array) 또는 동적 배열(ArrayList) 채택
       └─ 아니오 ─→ [데이터의 중간 삽입과 삭제가 실시간으로 발생하는가?]
                         ├─ 예 ──→ 연결 리스트(LinkedList) 채택
                         └─ 아니오 ─→ [데이터의 입출력 순서 제어가 필요한가?]
                                           ├─ 예: 후입선출 ──→ 스택 (Stack)
                                           └─ 예: 선입선출 ──→ 원형 큐 / 링 버퍼
```

### 선택 근거: 연결 리스트 기반 큐와 제언 연속 링 버퍼 비교

| 구분 | 노드 기반 연결 큐 (Linked Queue) | 제언: 연속 메모리 링 버퍼 (Ring Buffer) |
|---|---|---|
| 메모리 동적 할당 | 노드 인큐 시마다 힙 메모리 할당 및 GC 부하 | 기동 시 일괄 할당 후 재활용으로 GC 프리(Zero-GC) |
| 동기화 메커니즘 | 뮤텍스/락(Lock) 사용으로 쓰레드 경합 지연 | 원자적 CAS 기반 Lock-Free 구현으로 나노초 처리 |
| 캐시 적중률 | 노드 메모리 분산으로 캐시 미스 빈발 | 1차원 연속 배열 구조로 하드웨어 캐시 적중률 극대화 |
