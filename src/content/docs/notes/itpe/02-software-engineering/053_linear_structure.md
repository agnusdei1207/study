## 연관 키워드

- 선형 구조(Linear Structure), 배열(Array), 연결 리스트(Linked List), 스택(Stack), 큐(Queue), 덱(Deque)
- LIFO(Last In, First Out), FIFO(First In, First Out), 원형 큐(Circular Queue), 락프리(Lock-free), 링 버퍼(Ring Buffer)

## Ⅰ. 선형 구조의 개요

- 핵심 요약 : 원소 간 1:1 순서 관계를 유지하는 1차원 형태의 기본 자료구조.
- 개념 : 데이터 원소가 하나의 연속된 순서를 이루어 각 원소의 앞과 뒤에 1:1 관계가 성립하는 **선형 구조**(Linear Structure)다. 배열, 연결 리스트, 스택, 큐, 덱이 대표적이다.
- 배경 및 필요성 : 연속 데이터의 순차 저장, 임의 접근, 버퍼링, 후입선출·선입선출 처리는 대부분의 알고리즘에서 반복되는 기초 연산이므로, 선형 구조는 자료구조 설계의 기본 단위가 된다.
- 주요 목적 : 접근 패턴(임의 접근, 동적 삽입·삭제, 접근 순서 제어)에 맞는 구조를 골라 연산 비용을 통제하는 것.

## Ⅱ. 선형 구조의 특징 및 장점

- 핵심 요약 : 메모리 배치와 접근 정책(임의 접근, 포인터 연결, LIFO·FIFO)에 따라 자료구조마다 다른 연산 특성을 보임.

1. 배열(Array) : 연속된 메모리에 같은 타입의 원소를 배치 → 인덱스로 직접 접근하며 접근 비용이 O(1)로 빠름.
2. 연결 리스트(Linked List) : 각 노드가 데이터와 다음 노드의 포인터를 가짐 → 크기를 동적으로 바꾸고 중간 삽입·삭제가 쉬우나 임의 접근은 O(N)이 듦.
3. 스택(Stack) : 한쪽 끝(Top)에서만 삽입(Push)과 삭제(Pop)가 일어나는 **후입선출**(LIFO, Last In, First Out) 구조 → 함수 호출 기록이나 역순 처리에 적합.
4. 큐(Queue)와 덱(Deque) : 큐는 한쪽 끝에서 삽입하고 반대쪽에서 삭제하는 **선입선출**(FIFO, First In, First Out) 구조이며, 덱(Double-Ended Queue)은 양쪽 끝에서 모두 삽입과 삭제가 가능 → 작업 대기열과 버퍼링에 활용.

## Ⅲ. 선형 구조의 구조 (흐름)

- 핵심 요약 : 물리적 연속성을 가진 배열과 포인터로 이어진 연결 리스트, 그리고 접근 정책이 다른 스택과 큐의 구조 차이.

```text
[ 배열 (Array) ] 물리적으로 연속 할당
  [0] [1] [2] [3]
  인덱스로 즉시 접근 (O(1))

[ 연결 리스트 (Linked List) ] 포인터로 연결
  [Data|Next] ─> [Data|Next] ─> ...
  중간 삽입·삭제는 포인터만 수정
```

```text
[ 스택 (Stack) : LIFO ]

  Top
   ↓
  [ D ]  ← 마지막 입력이 먼저 출력
  [ C ]
  [ B ]
  [ A ]  Bottom
```

```text
[ 큐 (Queue) : FIFO ]

  Rear(삽입)           Front(삭제)
     ↓                     ↓
  [ D ] [ C ] [ B ] [ A ] ─→ A가 먼저 나감
```

```text
[ 원형 큐 (Circular Queue) ]

  인덱스  [0] [1] [2] [3] [4]
           F →         ← R
  다음 위치 = (인덱스 + 1) % N
  → 앞쪽 빈 칸을 재사용
```

## Ⅳ. 주요 선형 자료구조의 비교

- 핵심 요약 : 연산별 시간 복잡도와 메모리 오버헤드를 기준으로 구조를 고르며, 덱은 양단 연산에서 강점을 가짐.

| 자료구조 | 접근(Access) | 탐색(Search) | 삽입(Insertion) | 삭제(Deletion) | 메모리 오버헤드 |
| --- | --- | --- | --- | --- | --- |
| 배열(Array) | O(1) | O(N) | O(N), 뒤 원소 이동 | O(N), 뒤 원소 이동 | 거의 없음 |
| 연결 리스트(Linked List) | O(N) | O(N) | O(1), 위치를 알 때 | O(1), 위치를 알 때 | 노드마다 포인터 저장 |
| 스택(Stack) | Top만 가능 | O(N) | O(1), Push | O(1), Pop | 적음 |
| 큐(Queue) | Front만 가능 | O(N) | O(1), Enqueue | O(1), Dequeue | 원형 배열 또는 포인터 |
| 덱(Deque) | 양단 | O(N) | O(1), 양단 | O(1), 양단 | 양방향 포인터 또는 환형 배열 |

## Ⅴ. 선형 구조의 한계와 방안

- 핵심 요약 : 크기 고정, 캐시 비친화, 큐의 공간 낭비와 락 경합을 구조 교체, 원형 구조, 락프리 기법으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 크기 고정과 중간 삽입·삭제 비용 | 정적 배열은 크기 조절이 안 되고, 중간 삽입·삭제 때 뒤 원소를 모두 이동해 대량 데이터에서 지연 발생 | 빈번한 삽입·삭제 구간은 연결 리스트 또는 청크 단위 블록(Unrolled Linked List) 사용, 대규모 인덱싱은 B-Tree 계열로 전환 | 원소 이동 횟수, 응답 지연 |
| 포인터 오버헤드와 캐시 비친화 | 노드마다 포인터 공간이 필요하고 노드가 흩어져 있어 CPU(Central Processing Unit) 캐시 효율 저하 | 순차 조회가 많으면 연속 배열 기반 동적 배열(Vector, ArrayList) 채택 | 캐시 미스율 |
| 선형 큐의 공간 낭비와 락 경합 | 앞쪽 공간이 재사용되지 않고, 여러 스레드가 한 큐에 접근하면 락 경합 발생 | 원형 큐로 공간 재사용, 고성능 환경은 CAS(Compare and Swap) 기반 락프리 링 버퍼 적용 | 큐 대기 시간, 락 경합 횟수 |

## Ⅵ. 고성능 컴퓨팅 환경에서의 기술사적 제언

- 핵심 요약 : 이론상 빠른 연산보다 캐시 지역성을 기준으로 배열을 우선 고려하고, 버퍼는 원형 구조로 설계.

1. 캐시 지역성 기준의 구조 선택 : 연결 리스트의 삽입·삭제가 이론상 O(1)이어도 노드가 흩어진 구조는 캐시 미스로 느려질 수 있으므로, 실측 성능을 보고 연속 메모리 기반 동적 배열을 기본으로 삼는다.
2. 원형 버퍼의 표준화 : 로그 수집이나 트랜잭션 버퍼처럼 데이터가 연속으로 흐르는 시스템은 원형 큐 또는 락프리 링 버퍼를 공통 구현으로 두어 메모리 재사용과 동시성 제어를 함께 확보한다.

## Ⅶ. 결론

- 핵심 요약 : 선형 구조는 자료구조의 기초이며, 접근 패턴과 동시성 요건에 맞는 구조 선택이 성능을 좌우.
- 시사점 : 배열은 임의 접근, 연결 리스트는 동적 삽입·삭제, 스택·큐·덱은 접근 정책 제어에 쓰이므로, 목적별로 구분해 설계해야 한다.
