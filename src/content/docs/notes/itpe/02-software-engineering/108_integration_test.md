## 연관 키워드

- 통합 테스트(Integration Testing), 단위 테스트(Unit Testing), 하향식 통합, 상향식 통합, 빅뱅 통합, 샌드위치 통합
- 스텁(Stub), 드라이버(Driver), 테스트 더블(Test Double), 결함 격리

## Ⅰ. 통합 테스트의 개요

- 핵심 요약 : 통합 테스트는 모듈·구성 요소의 결합 과정에서 인터페이스와 상호 작용 결함을 검증하는 테스트 수준.
- 개념 : 개별 검증을 마친 모듈·구성 요소를 결합하며 호출·응답·상태 전달의 정합성을 확인하는 테스트 수준이 **통합 테스트** (Integration Testing).
- 배경 및 필요성 : **단위 테스트** (Unit Testing)로 각 모듈의 내부 동작을 확인해도 계약 불일치, 호출 순서, 연계 설정 오류는 결합 단계에 남는 상태.
- 주요 목적 : 구성 요소 경계 결함의 조기 발견과 시스템 수준 검증의 기반 확보.

## Ⅱ. 통합 테스트의 특징 및 장점

- 핵심 요약 : 경계 검증, 단계적 결합, 대체물 활용, 회귀 기반이 조립 위험의 감소로 연결.

1. 경계 검증 : 요청·응답 형식, 오류 코드, 상태 전달의 확인 → 연계 결함의 조기 발견 효과.
2. 단계적 결합 : 의존 방향에 따른 순차 통합 → 결함 격리 범위의 제한과 추적 용이성 효과.
3. 테스트 더블 활용 : 미완성 구성 요소를 **테스트 더블** (Test Double)로 대체 → 병렬 개발 중 조기 시험 효과.
4. 회귀 기반 축적 : 통합 버전과 시험 자산의 누적 → 상호 작용 결함의 재발 방지 효과.

## Ⅲ. 통합 테스트의 구조 (흐름)

- 핵심 요약 : 결합 시작점과 보조물 기준으로 하향식·상향식·빅뱅·샌드위치 접근법을 구분.
- 대체물 중 하위 모듈 대역이 **스텁** (Stub), 상위 호출 대역이 **드라이버** (Driver).

```text
단위 테스트 : 모듈 내부 로직
   ↓ 모듈 결합
통합 테스트 : 인터페이스·상호 작용
   ↓ 전체 결합
시스템 테스트 : 요구 충족 확인
```

```text
하향식 : 상위 제어 모듈부터 결합
   ↓ 미완성 하위는 스텁(Stub)으로 대체
실제 하위 모듈로 순차 교체
```

```text
상향식 : 하위 공통 모듈부터 결합
   ↑ 미완성 상위는 드라이버(Driver)로 대체
실제 상위 모듈로 순차 교체
```

| 접근법 | 결합 방향·시작점 | 보조물 | 강점 | 주의점 |
| --- | --- | --- | --- | --- |
| 하향식 통합 | 상위 제어 모듈부터 하위로 | 스텁 | 핵심 제어 흐름의 조기 확인 | 하위 상세 검증 지연 |
| 상향식 통합 | 하위 공통 모듈부터 상위로 | 드라이버 | 공통 기능의 조기 확보 | 사용자 흐름 검증 지연 |
| 빅뱅 통합 | 전체 구성 요소의 동시 결합 | 대체물 최소화 | 준비 부담의 경감 | 결함 격리의 곤란 |
| 샌드위치 통합 | 중간 계층 기준 상·하위 병행 | 스텁·드라이버 병용 | 대형 시스템의 병행 시험 | 관리 복잡성 증가 |

## Ⅳ. 통합 테스트와 단위 테스트의 비교

- 핵심 요약 : 검증 대상이 구성 요소의 경계인지 내부인지가 통합 테스트와 단위 테스트의 기본 구분.

| 비교 축 | 통합 테스트 | 단위 테스트 |
| --- | --- | --- |
| 검증 대상 | 모듈 간 인터페이스·상호 작용 | 개별 모듈의 내부 로직 |
| 대표 결함 | 계약 불일치·순서·설정 오류 | 분기·계산·예외 처리 오류 |
| 의존 처리 | 스텁·드라이버로 미완성 부분 대체 | 모의 객체 등의 외부 의존 격리 |
| 수행 시점 | 결합 단계별·빌드 주기 | 개발 즉시·매 변경 |
| 수행 주체 경향 | 통합·연계 담당의 협업 | 개발자의 자체 수행 |

## Ⅴ. 통합 테스트의 한계와 방안

- 핵심 요약 : 대체물과 실제 동작의 차이, 외부 의존, 비결정성, 격리 지연을 계약·환경 통제로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 스텁·드라이버와 실제 동작의 차이 | 낡은 계약의 모사 → 오검증 | 계약 테스트 병행·대역 최신화 | 계약 불일치 건수 |
| 외부 시스템 의존 불안정 | 외부 장애·속도 제한 → 실패 원인 혼재 | 격리 환경·소비자 계약 기반 모사 | 외부 의존 실패 건수 |
| 비결정적 실패 | 공유 상태·시간·순서 의존 → 신뢰 저하 | 데이터 격리·시간 고정·원인 분류 | 재현 실패 비율 |
| 결함 격리 지연 | 다수 모듈의 동시 결합 → 원인 추적 곤란 | 위험 기반 점진 통합·추적 식별자 부여 | 격리 소요 시간 |

## Ⅵ. 시험 전략에 대한 기술사적 제언

- 핵심 요약 : 개발 조직은 변경 위험이 큰 경계의 우선 자동화와 계약 기반 검증의 배포 절차 편입이 필요.
1. 서비스 소유 팀은 API(Application Programming Interface) 스키마, 이벤트 호환성, 데이터 이관을 배포 전 검증 항목으로 지정.
2. 품질 조직은 단위·통합·계약 시험의 책임 분리와 격리 환경 정리 절차의 표준 운영.

## Ⅶ. 결론

- 핵심 요약 : 통합 테스트는 구성 요소 사이의 계약과 상호 작용 결함을 찾는 필수 시험 수준.
- 시사점 : 결합 순서 선택과 계약 기반 검증이 시스템 조립 위험을 낮추는 핵심.
