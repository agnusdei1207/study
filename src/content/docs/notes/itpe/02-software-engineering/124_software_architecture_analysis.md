## 연관 키워드

- 소프트웨어 아키텍처 분석; 품질속성; 시나리오 기반 분석; ATAM; SAAM; 이해관계자; 절충점

## Ⅰ. 소프트웨어 아키텍처 분석의 개요

- 핵심 요약 : 소프트웨어 아키텍처 분석은 구조·전술·기술선택이 성능·수정성·가용성·보안 등 품질속성과 이해관계자 요구를 충족하는지 시나리오로 평가하는 활동.
- 개념 : 소프트웨어 아키텍처 분석은 구조·전술·기술선택이 성능·수정성·가용성·보안 등 품질속성과 이해관계자 요구를 충족하는지 시나리오로 평가하는 활동.
- 배경 및 필요성 : 요구사항 문서만으로 구조의 응답성·변경성·장애격리 같은 런타임·생애주기 특성을 검증하기 어려움.
- 주요 목적 : 구현 전에 구조적 위험과 품질속성 간 절충을 드러내 아키텍처 적합성과 투자 타당성을 높임.

## Ⅱ. 소프트웨어 아키텍처 분석의 특징 및 장점

- 핵심 요약 : 핵심 요소: 품질속성 시나리오·아키텍처 접근법·ATAM(Architecture Tradeoff Analysis Method, 아키텍처 절충 분석 방법)·SAAM. 설계목표는 구현 전에 구조적 위험과 품질속성 간 절충을 드러내 아키텍처 적합성과 투자 타당성을 높임.

1. 특징 : 품질속성 시나리오 : 자극·환경·응답·측정기준 구체화 → 추상 품질요구를 분석 가능한 기준으로 전환.
2. 특징 : 아키텍처 접근법 : 구성요소·커넥터·전술을 시나리오에 대조 → 위험·민감점·절충점 식별.
3. 특징 : ATAM(Architecture Tradeoff Analysis Method, 아키텍처 절충 분석 방법) : 이해관계자·품질목표·접근법·시나리오·위험을 반복 분석 → 상충하는 품질속성의 구조적 영향 파악.
4. 특징 : SAAM : 시나리오와 변경사항을 이용해 구조의 수정성 평가 → 변경비용·모듈 경계 검토.

## Ⅲ. 소프트웨어 아키텍처 분석의 구조 (흐름)

- 핵심 요약 : 목표·범위·이해관계자 정의 → 품질속성 시나리오 수집 → 구조·전술 설명 → 시나리오별 분석·위험 식별 → 절충점·민감점 검토 → 개선·재평가.

```text
목표·범위·이해관계자 정의
   ↓
품질속성 시나리오 수집
   ↓
구조·전술 설명
   ↓
시나리오별 분석·위험 식별
   ↓
절충점·민감점 검토
   ↓
개선·재평가
```

```text
품질속성 시나리오
자극 → 아키텍처 요소·전술 → 응답
  ↓ 위험·민감점·절충점 분석
구조 수정·프로토타입·시험
  ↓
잔여위험·결정기록 갱신
```

## Ⅳ. 소프트웨어 아키텍처 분석의 비교

- 핵심 요약 : ATAM: 복수 품질속성·시나리오·절충점 분석; SAAM: 시나리오로 구조·수정성 평가.

| 개념·방법 | 주요 특성 | 적합한 적용조건 |
| --- | --- | --- |
| ATAM | 복수 품질속성·시나리오·절충점 분석 | 성능·수정성·가용성 등 상충목표 평가 |
| SAAM | 시나리오로 구조·수정성 평가 | 변경 시나리오·모듈화 분석 |
| 프로토타입·벤치마크 | 실제 구현 일부로 성능·기술위험 측정 | 정량성능 가설을 실측할 때; 전체 구조 분석을 대체하지 않음 |

## Ⅴ. 소프트웨어 아키텍처 분석의 한계와 방안

- 핵심 요약 : 위험 초점: 품질요구의 추상성·구조 설명 부족·참여자 편중·조기분석. 권고 대응은 통제·책임을 명확히 해 구현 전에 구조적 위험과 품질속성 간 절충을 드러내 아키텍처 적합성과 투자 타당성을 높임.

| 위험 | 원인·영향 | 통제·대응 | 지표 예시 |
| --- | --- | --- | --- |
| 품질요구의 추상성 | 분석자마다 성공·실패 판단이 다름 | 측정가능한 자극·응답·환경·기준 정의 | 미측정 시나리오 수 |
| 구조 설명 부족 | 분석결론이 가정·선택에 연결되지 않음 | 뷰·인터페이스·전술·가정과 근거 기록 | 미설명 의존성 |
| 참여자 편중·조기분석 | 주요 이해관계자·현실 운영조건 누락 | 운영·보안·개발·사업 참여, 반복 검토 | 미참여 역할, 후속 재설계 |

## Ⅵ. 소프트웨어 아키텍처 분석 적용에 대한 기술사적 제언

- 핵심 요약 : 적용 원칙: 구현 전에 구조적 위험과 품질속성 간 절충을 드러내 아키텍처 적합성과 투자 타당성을 높임.
- 실행 제언 : 아키텍트는 품질속성 요구를 초기부터 시나리오로 구체화하고 주요 구조결정의 근거·대안·위험을 ADR에 기록해 프로토타입·운영관측 결과와 함께 재평가.

## Ⅶ. 결론

- 핵심 요약 : 소프트웨어 아키텍처 분석은 구조·전술·기술선택이 성능·수정성·가용성·보안 등 품질속성과 이해관계자 요구를 충족하는지 시나리오로 평가하는 활동.
- 시사점 : 아키텍처 분석은 설계도 검토가 아니라 구조적 선택이 품질목표에 미치는 영향을 이해관계자와 조기에 검증하는 의사결정 활동.
