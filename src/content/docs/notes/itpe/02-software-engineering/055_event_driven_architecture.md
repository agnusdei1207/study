## 연관 키워드

- EDA, 이벤트 생산자, 이벤트 브로커, 이벤트 소비자
- 브로커 토폴로지, 중재자 토폴로지, 코레오그래피, 오케스트레이션, 사가 패턴, 멱등성, Transactional Outbox

## Ⅰ. EDA의 개요

- 핵심 요약 : 상태 변화를 이벤트로 발행·소비하는 비동기 분산 아키텍처 스타일.
- 개념 : 시스템의 유의미한 상태 변화인 이벤트(Event)를 발행하고 전달·소비하는 비동기 아키텍처 스타일 (**EDA**, Event-Driven Architecture).
- 배경 및 필요성 : REST(Representational State Transfer)·RPC(Remote Procedure Call) 같은 동기 직접 호출 구조에서 서비스 간 강결합, 응답 대기에 따른 성능 저하, 연쇄 장애의 확산이 반복되는 상황.
- 주요 목적 : 서비스 간 결합도의 최소화를 통한 확장성과 반응성의 확보.

## Ⅱ. EDA의 특징 및 장점

- 핵심 요약 : 비동기 전달과 구성 요소의 역할 분리가 낮은 결합도와 높은 반응성이라는 장점으로 연결되는 구조.

1. 비동기 메시징 : 발행-구독(Publish-Subscribe) 방식으로 응답 대기 없이 다음 처리 진행 → 전체 흐름의 반응성 향상.
2. 역할의 분리 : 이벤트를 만드는 **이벤트 생산자**(Event Producer), 전달을 맡는 **이벤트 브로커**(Event Broker), 받아 처리하는 **이벤트 소비자**(Event Consumer)의 3요소 구성 → 관심사의 계층 분리.
3. 낮은 결합도 : 생산자가 소비자의 존재를 알지 못하는 구조 → 소비자의 추가·교체가 생산자에 미영향.
4. 토폴로지의 선택 : 중앙 제어 없이 연쇄 전파되는 **브로커 토폴로지**(Broker Topology)와 중재자가 흐름을 통제하는 **중재자 토폴로지**(Mediator Topology)의 선택 운용 → 업무 특성별 구성의 유연성.
5. 결과적 일관성 : 즉시 일관성 대신 최종 시점의 정합성을 지향하는 **결과적 일관성**(Eventual Consistency)의 채택 → 가용성과 확장성의 확보.

## Ⅲ. EDA의 구조 (흐름)

- 핵심 요약 : 자율 전파형 브로커 토폴로지와 통제형 중재자 토폴로지의 이원 구조.
- 브로커 토폴로지의 흐름은 **코레오그래피**(Choreography, 각 주체의 자율 반응) 방식.

```text
[ 브로커 토폴로지 : 코레오그래피 ]

이벤트 생산자
   ↓ 이벤트 발행
이벤트 브로커
   ↓ 전달
이벤트 소비자 A
   ↓ 후속 이벤트 재발행
이벤트 브로커
   ↓ 전달
이벤트 소비자 B
   (중앙 제어 없는 자율 전파)
```

- 중재자 토폴로지의 흐름은 **오케스트레이션**(Orchestration, 중앙의 단계 통제) 방식.

```text
[ 중재자 토폴로지 : 오케스트레이션 ]

이벤트 중재자 (오케스트레이터)
   ↓ 1단계 지시
작업 1 → 완료 보고
   ↓ 2단계 지시
작업 2 → 완료 보고
   ↓ 실패 시
보상 작업 지시
```

## Ⅳ. EDA와 동기 요청-응답 아키텍처의 비교

- 핵심 요약 : 이벤트의 비동기 전파와 직접 호출의 응답 대기는 결합도·장애 전파·일관성 모델에서 대조.

| 비교 축 | EDA | 동기 요청-응답 아키텍처 |
| --- | --- | --- |
| 통제 흐름 | 이벤트 발행과 소비의 비동기 전파 | 호출자의 요청과 응답 대기 |
| 결합도 | 브로커 경유의 느슨한 결합 | 상대 서비스 인터페이스의 직접 참조 |
| 응답성 | 발행 즉시 다음 처리의 진행 | 응답 수신까지의 대기 |
| 장애 전파 | 소비자 장애가 생산자에 미영향 | 호출 대상 장애의 호출자 전파 |
| 일관성 모델 | 결과적 일관성 | 요청 시점의 즉시 일관성 |

## Ⅴ. EDA의 한계와 방안

- 핵심 요약 : 정합성 지연, 이벤트 중복, 스키마 호환성의 세 위험이 비동기 구조의 신뢰성을 제약.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 정합성 지연과 추적 곤란 | 전역 트랜잭션의 부재 → 데이터 어긋남의 지속과 원인 파악의 곤란 | **사가 패턴**(Saga Pattern, 보상 트랜잭션의 연쇄)의 적용, 분산 추적 도입 | 보상 트랜잭션 실패율 |
| 이벤트 중복·순서 역전 | 브로커의 At-Least-Once 전달 → 중복 처리와 역순 수신 | **멱등성**(Idempotency, 같은 이벤트의 반복 처리 무영향) 키 설계, **Transactional Outbox**(DB 변경과 이벤트 발행의 원자적 기록) 적용 | 중복 처리 건수 |
| 스키마 호환성 파손 | 생산자의 필드 변경 → 다수 소비자의 역직렬화 오류 | 스키마 레지스트리(Schema Registry)의 호환성 규칙 검증 | 호환성 검증 실패 건수 |

## Ⅵ. EDA 운영 체계에 대한 기술사적 제언

- 핵심 요약 : 이벤트를 전사 계약으로 관리하고 적용 범위의 선별 기준을 아키텍처 원칙으로 제도화하는 방향.
- 제도 : 즉시 정합성이 업무상 필수인 영역의 동기 호출 병행 기준을 아키텍처 원칙으로 명시.
- 조직 : 이벤트 명명 규칙과 스키마 버전 정책을 관리하는 전사 계약 관리 주체의 지정.
- 검증 : 신규 이벤트 발행 전 소비자 영향 검토를 아키텍처 검토 절차로 정례화.

## Ⅶ. 결론

- 핵심 요약 : EDA는 결합도와 확장성을 얻는 대신 일관성·추적성을 설계로 떠안는 아키텍처 스타일.
- 적용 범위의 선별과 정합성 보장 설계가 EDA 도입 성패의 분기점.
