## 큰 그림과 30초 인출

```text
[의존성·코드 반입] → [SBOM·라이선스 식별] → [의무·호환성 판정]
       → [고지·소스 제공·승인] → [배포 관문] → [취약점·변경 감시]

Permissive < Weak Copyleft < Strong/Network Copyleft
SSPL·BSL = 조건 확인이 필요한 source-available, OSI 승인 OSS와 구분
```

## 예상문제

오픈소스 라이선스의 유형과 주요 의무를 비교하고, 도입부터 배포 이후까지의 준수 관리방안을 기술하시오.

## Ⅰ. 개요

- 오픈소스 라이선스는 저작권자가 소프트웨어의 사용·복제·수정·배포 조건을 허용하는 법적 약정이다.
- 무료 사용 여부보다 고지, 저작권 표시, 소스 제공, 동일 라이선스 적용 등 배포 조건을 정확히 이행하는 것이 핵심이다.

## Ⅱ. 유형별 비교

| 유형 | 예시 | 핵심 의무·특징 |
|---|---|---|
| 허용형 | MIT, BSD, Apache-2.0 | 고지 유지 중심, Apache는 특허 조항 포함 |
| 약한 카피레프트 | LGPL, MPL-2.0 | 라이브러리·파일 등 제한 범위에 공개 의무 |
| 강한 카피레프트 | GPL | 파생 저작물 배포 시 대응 소스와 동일 조건 |
| 네트워크 카피레프트 | AGPL | 네트워크 제공 시에도 대응 소스 제공 의무 발생 가능 |
| Source-available | SSPL, BSL | 소스 열람 가능하나 OSI 승인 OSS와 별도 분류 |

## Ⅲ. 준수 절차

```text
정책 수립 → 반입 신청 → SCA·SBOM 생성 → 라이선스·출처 확인
        → 결합·배포 방식별 의무 판정 → 조치·승인 → 배포 → 지속 감시
```

| 산출물 | 내용 |
|---|---|
| SBOM | 구성요소, 버전, 공급자, 식별자, 관계 |
| 의무 목록 | 고지, 라이선스문, 소스·변경사항 제공 |
| 검토 기록 | 결합 방식, 배포 형태, 호환성 판단과 승인 |

## Ⅳ. 호환성 판단 축

- 정적·동적 링크, 수정 여부, 파일 경계, 프로세스 분리 등 결합 방식을 확인한다.
- 내부 이용, 바이너리 배포, 소스 배포, SaaS 등 제공 형태를 구분한다.
- 복수 라이선스의 조건을 동시에 충족할 수 있는지와 특허·상표 조건을 검토한다.
- 최종 법적 판단은 원문 라이선스와 전문 검토를 기준으로 한다.

## Ⅴ. 주요 위험과 대응

| 위험 | 대응 |
|---|---|
| 전이 의무 누락 | 사용 금지·격리·대체·소스 제공 검토 |
| 고지·원문 누락 | NOTICE와 라이선스 묶음 자동 생성 |
| 미식별 의존성 | 빌드 단계 SCA와 SBOM 검증 |
| 라이선스 변경 | 버전 고정, 승인 목록, 변경 감시 |
| 취약 구성요소 | VEX·취약점 정보와 패치 절차 연계 |

## Ⅵ. 적용 시 고려사항

- 패키지 이름만이 아니라 버전별 라이선스 원문과 예외 조항을 확인한다.
- 개발 초기부터 정책을 자동화하고 릴리스 관문에서 고지문·SBOM·소스 제공물을 함께 검증한다.
- 생성형 AI가 만든 코드도 출처와 유사성, 학습·출력 이용조건을 별도로 검토한다.
- “소스 공개”와 “오픈소스”를 동일시하지 말고 OSI 승인 여부를 확인한다.

## Ⅶ. 결론

오픈소스 활용의 핵심은 사용 금지가 아니라 조건을 알고 증명 가능하게 이행하는 것이다. SBOM을 기준으로 법무·개발·보안 검토를 연결하고 배포 이후까지 지속 관리해야 한다.

## 1교시 10점 발췌

```text
유형: 허용형 → 약한 카피레프트 → 강한/네트워크 카피레프트
관리: 정책 → 반입 → SBOM/SCA → 의무·호환성 → 조치 → 배포 → 감시
주의: SSPL·BSL은 source-available이며 OSI 승인 OSS와 구분
```

## 공식 근거

- [Open Source Initiative Licenses](https://opensource.org/licenses): OSI 승인 라이선스와 오픈소스 정의
- [SPDX License List](https://spdx.org/licenses/): 표준 라이선스 식별자와 목록
- [NTIA SBOM](https://www.ntia.gov/page/software-bill-materials): SBOM 최소 요소와 활용 자료
- [Q-Net 정보관리기술사](https://www.q-net.or.kr/): 국가기술자격 시험 및 공개문제 공식 창구
