## 연관 키워드
- 오픈소스 라이선스, Permissive, Copyleft, Source-Available, SBOM, SCA, OSPO

### Ⅰ. 오픈소스 라이선스의 개요

- 핵심 요약 : 오픈소스 라이선스는 소프트웨어 사용·수정·배포 권리와 조건을 정하는 법적 계약.
- 개념 : 저작권자가 이용자에게 저작물의 복제·수정·재배포를 허용하면서 의무를 규정(**오픈소스 라이선스**, Open Source License).
- 배경 및 필요성 : 의존성 재사용이 늘며 고지·소스 공개·특허·배포 의무를 준수해야 함.
- 주요 목적 : 권리 침해·공급망 위험을 예방하고 오픈소스 활용을 통제.

### Ⅱ. 라이선스 유형의 특징

- 핵심 요약 : 허용적 라이선스는 재배포 조건이 비교적 약하고 Copyleft는 파생 배포물의 동일 라이선스 유지 의무가 강함.

1. Permissive(허용적) : 저작권·라이선스 고지와 보증 부인 유지 → 상업 배포 유연.
2. 약한 Copyleft : 특정 라이브러리 변경분 중심으로 공개 의무 → 결합·배포 방식 검토 필요.
3. 강한 Copyleft : 파생 저작물 배포 시 소스 제공 등 의무 가능 → 결합 구조·배포 형태 분석.
4. Source-Available : 소스 공개와 OSI 오픈소스 정의 충족은 별개 → 사용 제한 조건 검토.

### Ⅲ. 라이선스 준수 흐름 (구조)

- 핵심 요약 : 구성요소 식별 → 라이선스·버전 확인 → 의무·호환성 분석 → 고지·소스 제공 → 배포 승인.

```text
저장소·바이너리 스캔 → SBOM 생성 → 라이선스 정책 매칭
        ↓ 위반·미확인 항목 검토
대체·예외 승인·의무 이행 → 릴리스 기록
```

```text
개발자 선택 → OSPO/SCA 검토 → 법무·보안 승인(필요 시)
       → NOTICE·저작권 고지·소스 제공물 구성 → 배포
```

### Ⅳ. Permissive·Copyleft·Source-Available 비교

- 핵심 요약 : 공개 범위·재배포 의무·제한 조건이 다르므로 이름이 아닌 실제 라이선스 전문으로 평가.

| 비교 축 | Permissive | Copyleft | Source-Available |
|---|---|---|---|
| 소스 수정·배포 | 허용, 고지 의무 | 조건부 허용, 상호성 의무 | 라이선스별 상업·사용 제한 가능 |
| 파생물 의무 | 약함 | 동일·호환 라이선스 공개 가능 | 계약 조건에 따름 |
| 사례 | MIT, Apache-2.0, BSD | GPL, LGPL, MPL | SSPL 등(OSI 정의와 구별) |
| 검토 초점 | 고지·특허 조항 | 결합·배포 방식 | 사용 제한·상업 배포 조건 |

### Ⅴ. 라이선스 관리의 한계와 방안

- 핵심 요약 : 전이 의존성 누락과 라이선스 오분류를 SBOM·SCA·검토 절차로 줄임.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 전이 의존성 미식별 | 의무 누락 | 빌드 산출물 기준 SBOM·SCA | 미식별 의존성 수 |
| 라이선스 불명·복수 | 배포 중단 위험 | 원문 검증·대체·법무 승인 | 불명 라이선스 수 |
| 고지물 부실 | 위반·감사 지적 | 릴리스별 NOTICE 자동 생성·검토 | 고지 미비 건수 |

### Ⅵ. 오픈소스 거버넌스 제언

- 핵심 요약 : OSPO(Open Source Program Office)는 개발자 선택을 막기보다 허용 목록·예외·고지 자동화로 준수 비용을 낮춤.

1. 개발조직은 신규 의존성 요청에 출처·버전·라이선스·목적을 기록.
2. OSPO·법무는 배포 형태와 연결 방식에 따라 의무를 검토.
3. 공급망 담당자는 SBOM을 릴리스에 포함하고 취약점·라이선스 정책을 함께 관리.

### Ⅶ. 결론

- 핵심 요약 : 오픈소스 활용은 라이선스 권리를 얻는 동시에 배포 조건을 지는 행위.
- 시사점 : 라이선스 분류 자동화와 전문 검토를 결합해 개발 초기부터 의무를 관리.
