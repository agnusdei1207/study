## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 인터페이스·API → **Open API(API 일반)**

## 30초 인출

- 본질: Open API는 외부 개발자가 서비스의 데이터와 기능을 표준 프로토콜로 호출하도록 공개한 API
- 메커니즘: 외부 애플리케이션이 인증을 거쳐 REST·SOAP 형식으로 요청하면 게이트웨이가 인증·접근 제한을 처리하고 서비스가 응답
- 통찰: 공개 API는 인증만 통과하면 객체 식별자를 바꿔 다른 사용자의 데이터에 접근할 수 있으므로 게이트웨이의 인증과 서비스의 객체별 권한 검증을 함께 적용

<details>
<summary>핵심 용어</summary>

- **API(Application Programming Interface)** : 소프트웨어 간 기능과 데이터를 주고받는 규약
- **Open API** : 외부 개발자에게 공개해 누구나 호출할 수 있도록 한 API
- **REST** : 자원을 URI로 식별하고 HTTP 메서드로 조작하는 웹 아키텍처 스타일
- **SOAP** : XML 메시지와 WSDL로 서비스를 정의하는 프로토콜
- **OAuth 2.0** : 사용자의 비밀번호 없이 제3자 앱에 제한된 접근 권한을 위임하는 인가 표준
- **API 게이트웨이(API Gateway)** : 인증·라우팅·속도 제한·로깅을 중앙에서 처리하는 API 진입점
- **BOLA(Broken Object Level Authorization)** : 객체 식별자만 바꿔 다른 사용자의 객체에 접근하게 되는 권한 검증 누락

</details>

## 2~4교시 25점 답안

## Ⅰ. Open API의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **Open API** 는 외부 개발자가 서비스의 데이터와 기능을 표준 프로토콜로 호출하도록 공개한 API |
| 목적 | 외부 서비스와의 연계를 통한 데이터·기능의 재사용과 생태계 확장 |

## Ⅱ. 내부 API와 구별되는 Open API의 특징

| 특징 | 의미 |
|---|---|
| 외부 공개 | 조직 밖 개발자가 사용 |
| 표준 프로토콜 | HTTP 기반 REST·SOAP 사용 |
| 명세 공개 | 요청·응답 형식을 문서로 제공 |
| 접근 통제 | 인증키·OAuth로 사용자·앱 식별 |

## Ⅲ. Open API의 호출 구조

### Open API 호출 구조

```text
외부 애플리케이션
    ↓ 인증·요청
API 게이트웨이 ── 인증·속도 제한·로깅
    ↓
서비스(내부 시스템) ── 데이터·기능 처리
```

### 확대: OAuth 2.0 접근 위임 흐름

```text
사용자 → 앱: 접근 허용
    ↓
인가 서버 → 앱: 액세스 토큰 발급
    ↓
앱 → API: 토큰과 함께 요청 → 범위 내 자원 응답
```

## Ⅳ. SOAP·REST의 구성요소 비교와 취약점

### SOAP와 REST의 구성요소

| 구분 | SOAP | REST |
|---|---|---|
| 구성요소 | Envelope·Header·Body의 XML 메시지, WSDL, UDDI | 자원(URI), HTTP 메서드, 표현(JSON·XML) |
| 서비스 정의 | WSDL | URI와 메서드 규칙, OpenAPI 명세 |
| 상태 | 상태 유지 가능 | 무상태 |
| 특징 | 표준이 엄격하고 무거움 | 단순하고 가벼움 |

### 취약점과 대응 방안

| 취약점 | 내용 | 대응 |
|---|---|---|
| 객체 수준 권한 검증 누락(BOLA) | 식별자를 바꿔 타인 데이터 접근 | 객체별 소유자 권한 검증 |
| 인증 약함 | 키 유출·토큰 탈취 | OAuth 2.0, 토큰 만료·회전 |
| 과도한 데이터 노출 | 응답에 불필요한 필드 포함 | 응답 필드 최소화 |
| 요청 폭주 | 대량 호출로 서비스 장애 | 속도 제한(Rate Limiting) |
| 입력 검증 부재 | 인젝션 공격 | 입력 검증·스키마 검사 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 게이트웨이 인증만으로 객체 접근 통제 불가 | 서비스에서 요청자와 객체 소유자 일치 검증 |
| 명세 공개로 공격 표면 노출 | 공개 범위 최소화와 API 목록 관리 |
| 버전 변경 시 외부 앱 오류 | 버전 정책과 폐기 예고 |

## Ⅵ. 제언

게이트웨이에서 인증·속도 제한을 처리하고, 서비스에서는 요청마다 객체 소유자 권한을 검증

### 이중 통제 구조

```text
요청
    ↓
게이트웨이: 인증·속도 제한
    ↓
서비스: 객체별 소유자 권한 검증
    ├─ 일치 → 처리
    └─ 불일치 → 거부·기록
```

### 선택 근거: 게이트웨이 단독 통제와의 비교

| 구분 | 게이트웨이 단독 | 제언: 이중 통제 |
|---|---|---|
| 인증 | 처리 | 처리 |
| 타인 객체 접근 | 차단 어려움 | 서비스에서 차단 |
| 개발 부담 | 낮음 | 서비스별 검증 필요 |
