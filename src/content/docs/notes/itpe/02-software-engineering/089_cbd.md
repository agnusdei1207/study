## 연관 키워드

- CBD(Component-Based Development), 컴포넌트 기반 개발, 소프트웨어 컴포넌트, 인터페이스 계약
- 컴포넌트 조립, 재사용, 버전·의존성 관리, 3C, 전용 맞춤 개발

## Ⅰ. CBD의 개요

- 핵심 요약 : CBD는 명시적 계약을 가진 재사용 가능한 소프트웨어 컴포넌트의 조립으로 시스템을 구축하는 개발 방법.
- 개념 : 기능을 캡슐화하고 명시적 인터페이스로만 상호작용하는 **소프트웨어 컴포넌트** (독립적으로 배포 가능한 재사용 소프트웨어 단위)를 인터페이스 계약에 따라 조립해 시스템을 구축하는 개발 방법인 **컴포넌트 기반 개발** (CBD, Component-Based Development).
- 배경 및 필요성 : 유사 기능을 프로젝트마다 신규 구현하면 중복 비용과 품질 편차가 반복 발생. 모듈 간 내부 의존 구조에서는 한 곳의 수정이 여러 기능의 변경으로 파급.
- 주요 목적 : 검증된 컴포넌트의 재사용과 독립적 교체를 통한 생산성·품질·변경 유연성 확보, 조직 수준의 소프트웨어 자산화.

## Ⅱ. CBD의 특징 및 장점

- 핵심 요약 : 인터페이스 계약·구현 은닉·독립 배포·조립 중심 구성이 재사용성과 교체 가능성으로 이어짐.

1. 인터페이스 계약 : 제공·요구 인터페이스만 공개하고 내부 구현을 은닉하는 **블랙박스 재사용** (내부 구현을 보지 않고 인터페이스만으로 활용하는 재사용 방식) → 구현 변경과 무관한 교체 가능성 확보.
2. 독립 배포 단위 : 컴포넌트를 버전 단위로 패키징·배포 → 개별 갱신으로 변경 파급 범위 최소화.
3. 컴포넌트 조립 : 식별·선정된 컴포넌트를 아키텍처 관점에서 결합 → 신규 코딩 대비 개발 기간 단축.
4. 검증 이력의 재사용 : 기존 운영에서 오류가 제거된 컴포넌트 활용 → 품질·비용 효과가 프로젝트 단위를 넘어 누적.

## Ⅲ. CBD의 구조 (흐름)

- 핵심 요약 : 준비 → 컴포넌트 분석 → 설계 → 조립·구현 → 시험 절차로 진행되며, 컴포넌트는 3C 모델로 명세화.
- 컴포넌트 이해 모델 : **3C** (Concept·Content·Context) — 개념(인터페이스 명세)·내용(구현)·문맥(의존·협력 관계)의 세 층위로 컴포넌트를 기술하는 프레임.

```text
[ 컴포넌트의 3C 구조 ]

Concept  개념 : 인터페이스 계약
   ↓
Content  내용 : 구현(은닉)
   ↓
Context  문맥 : 의존·협력 환경
```

```text
[ CBD 개발 절차 ]

응용 준비(요구 분석)
   ↓
컴포넌트 분석
(재사용·신규 개발 판단)
   ↓
컴포넌트 설계(아키텍처·계약)
   ↓
컴포넌트 조립·구현
   ↓
시험 및 검증
```

## Ⅳ. CBD와 전용 맞춤 개발의 비교

- 핵심 요약 : CBD는 계약 기반 조립과 외부 재사용, 전용 맞춤 개발은 요구별 신규 구현과 단일 애플리케이션 내부 재사용이라는 차이.

| 비교 축 | CBD | 전용 맞춤 개발 |
|---|---|---|
| 구현 단위 | 컴포넌트 조립 | 요구별 신규 코딩 |
| 재사용 범위 | 조직·프로젝트 간 외부 재사용 | 단일 애플리케이션 내부 재사용 |
| 변경 대응 | 컴포넌트 교체·버전 갱신 | 해당 코드 직접 수정 |
| 비용 구조 | 컴포넌트 확보·계약 정의 비용 선행 | 초기 비용은 낮으나 반복 개발 비용 누적 |
| 품질 근거 | 컴포넌트의 사전 검증·운영 이력 | 해당 프로젝트 시험 결과 |
| 선택 기준 | 공통 기능 다수·교체 요구 존재 시 | 고유 요구 중심·외부 자산 부적합 시 |

## Ⅴ. CBD의 한계와 방안

- 핵심 요약 : 계약 불일치·숨은 의존성·버전 파편화를 계약 시험·의존성 명세·버전 정책으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 인터페이스 계약 불일치 | 제공·요구 인터페이스 해석 차이 → 통합 실패·런타임 오류 | 계약 기반 인터페이스 시험·호환성 정의 | 통합 결함 건수 |
| 블랙박스로 인한 숨은 의존성 | 내부 정보 부재 → 장애 원인 분석 지연 | 의존성·동작 전제 명세화, 공급자 지원 확인 | 미문서화 의존성 수 |
| 버전·의존성 파편화 | 갱신 지연·다중 버전 공존 → 유지보수 비용 증가 | 버전 호환성 정책·지원 종료 관리 | 다중 사용 버전 수 |

## Ⅵ. CBD 확산에 대한 기술사적 제언

- 핵심 요약 : 재사용 자산의 축적·품질·취득을 통제하는 조직·표준·제도의 거버넌스 체계 구축.

- 조직 : 전담 조직이 컴포넌트 등록·평가·배포를 총괄하는 재사용 거버넌스 운영.
- 표준·기술 : 인터페이스 계약 표준과 버전 호환성 규칙을 조직 표준으로 제정하고 저장소로 자산 공유.
- 제도 : 컴포넌트 도입 승인 절차에 품질 검증·보안 점검·라이선스 검토를 필수 단계로 포함.

## Ⅶ. 결론

- 핵심 요약 : CBD는 명시적 계약의 컴포넌트 조립으로 재사용 경제성과 변경 유연성을 함께 확보하는 개발 방법.
- 재사용 효과의 실현 조건은 컴포넌트 품질 관리와 계약·버전 관리 성숙도.
