소프트웨어 공학 → 테스트·검증 → **동적 테스트(Dynamic Testing)**

## 30초 인출

- 본질: 동적 테스트는 프로그램을 실제로 실행해 입력에 대한 출력과 동작을 확인하는 테스트이며 명세 기반·구조 기반·경험 기반으로 나뉨
- 메커니즘: 테스트 케이스의 입력으로 프로그램을 실행하고 실제 결과를 기대 결과(오라클)와 비교해 결함을 판정
- 통찰: 명세 기반은 코드가 없는 기능 누락을, 구조 기반은 실행되지 않은 코드를 찾으므로 동등 분할·분류 트리로 명세 케이스를 만들고 구조 커버리지로 미실행 코드를 보완

<details>
<summary>핵심 용어</summary>

- **동적 테스트(Dynamic Testing)** : 프로그램을 실행해 동작을 확인하는 테스트
- **정적 테스트(Static Testing)** : 코드를 실행하지 않고 산출물을 검토·분석하는 테스트
- **명세 기반 테스트** : 요구 명세의 입력·출력으로 케이스를 도출하는 테스트
- **구조 기반 테스트** : 코드의 구조(문장·분기·경로)를 기준으로 케이스를 도출하는 테스트
- **동등 분할(Equivalence Partitioning)** : 입력을 같은 동작의 클래스로 나눠 클래스별 대표값을 시험하는 기법
- **분류 트리(Classification Tree)** : 입력 특성을 트리로 분류해 조합으로 케이스를 도출하는 기법

</details>

## 2~4교시 25점 답안

## Ⅰ. 동적 테스트의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **동적 테스트** 는 프로그램을 실행해 입력에 대한 출력·동작을 확인하는 테스트 |
| 목적 | 실행 시 나타나는 결함의 발견 |

## Ⅱ. 정적 테스트와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 실행 필요 | 실행 가능한 프로그램 필요 |
| 결과 비교 | 기대 결과(오라클)와 실제 결과 비교 |
| 기법 분류 | 명세·구조·경험 기반 |

## Ⅲ. 동적 테스트의 분류와 케이스 도출

### 동적 테스트의 분류

```text
동적 테스트
    ├─ 명세 기반 ── 동등 분할·경계값·결정표·분류 트리
    ├─ 구조 기반 ── 구문·결정·조건 커버리지
    └─ 경험 기반 ── 오류 추측·탐색적 테스트
```

### 확대: 명세 예 — 정수 입력, 10 미만·100 초과는 Fail, 10~100은 Pass, 정수가 아니면 Invalid Input

```text
입력
 ├─ 정수 ── 10 미만 → Fail
 │        ├─ 10 이상 100 이하 → Pass
 │        └─ 100 초과 → Fail
 └─ 정수 아님 ── 문자·소수·빈 값 → Invalid Input
```

## Ⅳ. 명세 기반과 구조 기반의 비교, 케이스 작성

### 명세 기반과 구조 기반의 비교

| 구분 | 명세 기반 | 구조 기반 |
|---|---|---|
| 기준 | 요구 명세 | 코드 구조 |
| 발견 결함 | 기능 누락·명세 불일치 | 미실행 코드·논리 오류 |
| 시점 | 시스템·인수 단계 | 단위·통합 단계 |
| 코드 필요 | 불필요 | 필요 |

### 동등 분할과 분류 트리의 테스트 케이스

| 기법 | 케이스 | 입력 | 기대 결과 |
|---|---|---|---|
| 동등 분할 | 10 미만 | 5 | Fail |
| 동등 분할 | 10~100 | 50 | Pass |
| 동등 분할 | 100 초과 | 150 | Fail |
| 동등 분할 | 정수 아님 | abc | Invalid Input |
| 분류 트리 | 정수 아님 - 소수 | 3.5 | Invalid Input |
| 분류 트리 | 정수 아님 - 빈 값 | (없음) | Invalid Input |
| 경계값 보강 | 하한·상한 | 9, 10, 100, 101 | Fail, Pass, Pass, Fail |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 명세 기반만으로 미실행 코드 미확인 | 구조 커버리지 측정으로 보완 |
| 구조 기반만으로 기능 누락 미발견 | 명세 기반 케이스 병행 |
| 입력 조합이 많아 케이스 폭증 | 동등 분할·분류 트리로 조합 축소 |

## Ⅵ. 제언

명세 기반 케이스를 먼저 작성해 기능을 검증하고, 구조 커버리지로 미실행 코드를 찾아 케이스를 보완

### 병행 절차

```text
명세 기반 케이스 작성·실행
    ↓
구조 커버리지 측정
    ↓
미실행 코드 → 케이스 추가
```

### 선택 근거: 단일 기법과의 비교

| 구분 | 단일 기법 | 제언: 명세→구조 보완 |
|---|---|---|
| 기능 누락 | 명세 기반만 발견 | 발견 |
| 미실행 코드 | 구조 기반만 발견 | 발견 |
| 케이스 수 | 적음 | 필요한 만큼 |
