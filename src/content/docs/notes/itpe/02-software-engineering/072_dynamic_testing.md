## 30초 인출

- 본질: **동적 테스트(Dynamic Testing)는** 소프트웨어를 실행해 관찰 가능한 동작과 요구 결과를 확인하는 테스트
- 메커니즘: 테스트 조건·입력 설정 → 실행 → 결과 관찰 → 오라클로 기대 결과와 비교
- 통찰: 한계: 코드 검토만으로 런타임 상태·자원 사용의 실패를 알 수 없음 → 방안: 실행 조건과 기대 결과를 정해 실제 출력·로그를 오라클과 대조

<details>
<summary>핵심 용어</summary>

- **동적 테스트(Dynamic Testing):** 소프트웨어를 실행해 동작을 평가하는 테스트
- **정적 테스트(Static Testing):** 소프트웨어를 실행하지 않고 산출물을 평가하는 테스트
- **테스트 오라클(Test Oracle):** 관찰 결과가 기대와 일치하는지 판단하는 기준이나 방법
- **구조 기반 테스트(Structure-Based Testing):** 코드 구조를 바탕으로 테스트를 설계하는 기법
- **명세 기반 테스트(Specification-Based Testing):** 명세된 동작을 바탕으로 테스트를 설계하는 기법
- **경험 기반 테스트(Experience-Based Testing):** 테스터의 지식과 경험을 활용해 테스트를 설계하는 기법

</details>

## 2~4교시 25점 답안

## Ⅰ. 동적 테스트의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 동적 테스트는 소프트웨어를 실행해 동작을 관찰·평가하는 테스트 활동 |
| 목적 | 명세 충족, 결함 발견, 실행 시 품질 특성 평가 |

## Ⅱ. 동적 테스트의 특징

| 특징 | 판정에 필요한 근거 |
|---|---|
| 실행 중 동작 관찰 | 입력·환경·버전과 실제 출력·로그 |
| 기대 결과와 비교 | 명세·불변조건 등 테스트 오라클 |
| 재현 가능한 결함 보고 | 동일 조건의 입력·실행 기록 |

## Ⅲ. 실행 및 결과 판정 체계

```text
요구·위험 → 시험 조건·입력·환경·오라클 준비
                            ↓
대상 실행 → 출력·상태·로그 관찰 → 기대 결과 대조
                                 ├ 일치 → 통과 기록
                                 └ 불일치 → 결함 분석·보고
```

오라클은 판정 근거이며, 완전한 기대값이 어려우면 속성·불변조건·메타모픽 관계 등 문제에 맞는 방법을 선택.

## Ⅳ. 정적 테스트와 설계 기법의 비교

| 관점 | 정적 테스트 | 동적 테스트 |
|---|---|---|
| 실행 여부 | 실행 없이 검토·분석 | 테스트 대상 실행 |
| 근거 | 산출물과 규칙 | 입력, 실행 상태, 실제 결과 |
| 발견 예 | 누락·불일치·코딩 규칙 위반 | 잘못된 출력·예외·성능 문제 |

**동적 테스트의 설계 관점**

| 분류 | 설계 근거 | 예 |
|---|---|---|
| 구조 기반 | 코드의 구조와 실행 경로 | 문장·분기 커버리지 |
| 명세 기반 | 요구사항과 외부 동작 | 동등 분할, 경계값 분석 |
| 경험 기반 | 도메인 지식과 과거 결함 | 오류 추정, 탐색적 테스트 |

세 분류는 테스트를 설계하는 관점이며, 테스트 단계나 품질 수준을 뜻하지 않음.

**적용·검증 관점**

| 고려사항 | 적용 |
|---|---|
| 환경 대표성 | 목적에 맞는 설정을 고정·기록하고 운영 환경과 차이를 관리 |
| 테스트 데이터 | 유효·경계·오류 조건을 포함하고 민감정보를 보호 |
| 재현성 | 입력, 환경, 버전, 결과와 로그를 함께 기록 |
| 범위·우선순위 | 요구사항 추적성과 위험도를 기준으로 선택·수행 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 코드 검토만으로 런타임 상태·자원 사용의 실패를 알 수 없음 | 실행 조건과 기대 결과를 정해 실제 출력·로그를 오라클과 대조 |

## Ⅵ. 제언

업무 영향이 큰 요구부터 테스트 조건을 고르고 입력·환경·오라클·결과를 재현 가능한 기록으로 관리.
