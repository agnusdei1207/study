## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 요구공학 → **성능 요구사항(Performance Requirement)**

## 30초 인출

- 본질: 성능 요구사항은 시스템이 일정 부하에서 만족해야 할 응답 속도·처리량·자원 사용 수준을 측정 가능한 수치로 정한 비기능 요구사항
- 메커니즘: 응답시간·처리량·동시 사용자·자원 사용률 지표를 부하 조건과 함께 정하고 시험으로 충족 여부를 판정
- 통찰: 평균 응답시간만 정하면 소수의 느린 요청이 가려지므로 상위 백분위 응답시간(P95·P99)을 함께 정하고 부하 조건을 명시

<details>
<summary>핵심 용어</summary>

- **성능 요구사항** : 응답 속도·처리량·자원 사용 등 성능 수준을 정한 비기능 요구사항
- **응답시간(Response Time)** : 요청을 보낸 뒤 응답을 받을 때까지 걸리는 시간
- **처리량(Throughput, TPS)** : 단위 시간에 처리하는 트랜잭션 수
- **동시 사용자 수** : 같은 시점에 시스템을 사용하는 사용자 수
- **자원 사용률(Resource Utilization)** : CPU·메모리·디스크·네트워크의 사용 비율
- **P95·P99 응답시간** : 요청의 95%·99%가 그 시간 안에 처리되는 응답시간

</details>

## 2~4교시 예상문제 (25점)

> 정보시스템의 성능 요구사항 작성 시 고려해야 하는 주요 성능지표와 그 내용을 설명하시오. (예상)

---

## 2~4교시 25점 답안

## Ⅰ. 성능 요구사항의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **성능 요구사항** 은 부하 조건에서 시스템이 만족해야 할 속도·처리량·자원 수준을 수치로 정한 비기능 요구사항 |
| 목적 | 성능 목표의 합의와 시험·검수 기준 제공 |

## Ⅱ. 기능 요구사항과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 측정 가능 | 수치와 측정 조건 포함 |
| 부하 조건 의존 | 사용자 수·데이터량과 함께 정의 |
| 검수 기준 | 성능 시험 결과로 충족 판정 |

## Ⅲ. 주요 성능지표와 작성 방법

### 주요 성능지표

| 지표 | 내용 | 작성 예 |
|---|---|---|
| 응답시간 | 요청부터 응답까지의 시간 | 주요 조회 거래 P95 2초 이내 |
| 처리량 | 단위 시간 처리 건수 | 피크 시 500 TPS 이상 |
| 동시 사용자 | 동시에 접속·이용하는 수 | 동시 사용자 3,000명 |
| 자원 사용률 | CPU·메모리 등의 사용 비율 | 피크 시 CPU 70% 이하 |
| 가용성 | 서비스 이용 가능 시간 비율 | 월 가동률 99.9% 이상 |

### 확대: 성능 요구사항의 서술 구조(품질속성 시나리오)

```text
자극   : 피크 시간대 사용자 3,000명이 동시에 주문 조회 요청
환경   : 정상 운영 상태, 데이터 1천만 건
응답   : 시스템이 요청을 처리
측정   : P95 응답시간 2초 이내, CPU 사용률 70% 이하
```

## Ⅳ. 지표 선택과 평균·백분위 비교

| 구분 | 평균 응답시간 | 백분위(P95·P99) 응답시간 |
|---|---|---|
| 의미 | 전체 요청의 평균 | 상위 5%·1%를 제외한 기준 |
| 장점 | 계산 단순 | 소수의 느린 요청 반영 |
| 약점 | 느린 요청이 가려짐 | 표본 수 필요 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| "빠르게" 같은 모호한 표현 | 수치와 측정 조건을 함께 기술 |
| 평균만 정해 느린 요청 은폐 | 백분위 응답시간 병행 |
| 부하 조건 없이 수치만 정의 | 사용자 수·데이터량·시간대 명시 |

## Ⅵ. 제언

핵심 거래별로 응답시간(P95)·처리량·동시 사용자·자원 사용률을 부하 조건과 함께 시나리오로 작성해 성능 시험 기준으로 사용

### 요구에서 시험까지의 연결

```text
성능 요구 시나리오 (거래·부하·수치)
    ↓
성능 시험 계획의 부하 모델로 사용
    ↓
시험 결과와 수치 대조 → 미달 시 튜닝 후 재시험
```

### 확대: 판정

```text
P95 응답시간 ≤ 2초 ?   CPU ≤ 70% ?
   ├─ 모두 충족 → 검수 통과
   └─ 미충족 → 병목 분석·개선 후 재시험
```

### 선택 근거: 서술형 요구와의 비교

| 구분 | 서술형("빠르게") | 제언: 수치·조건 시나리오 |
|---|---|---|
| 해석 | 사람마다 상이 | 수치로 통일 |
| 시험 | 기준 없음 | 시험 계획으로 직결 |
| 검수 분쟁 | 발생 | 수치로 판정 |
