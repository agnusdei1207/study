## 연관 키워드
- 성능 요구사항, 응답시간, 처리량, 자원사용률, 동시성, SLI/SLO, 부하시험

## Ⅰ. 성능 요구사항의 개요
- 핵심 요약 : 성능 요구사항은 시스템의 응답·처리·자원사용 목표를 특정 부하와 환경에서 측정 가능하게 정의.
- 개념 : 응답시간, 처리량, 지연분포, 동시사용자, 자원사용률 등 품질목표와 조건을 명시.
- 필요성 : “빠르고 효율적” 같은 모호한 표현은 설계·시험·인수 기준으로 쓸 수 없음.
- 목적 : 아키텍처·용량계획·성능시험·운영 SLO의 검증기준 마련.

## Ⅱ. 성능요구의 특징 및 장점
- 핵심 요약 : 부하·측정위치·시간창·백분위·자원조건을 함께 명시해야 반복 측정과 인수판정 가능.
1. 측정가능성 : 수치·단위·범위 정의 → 주관적 평가 방지.
2. 부하조건 : 동시성·요청분포·데이터크기·기간 정의 → 시험 재현성 확보.
3. 사용자중심 : 평균뿐 아니라 p95/p99 지연·오류율·완료시간 고려 → 꼬리 지연 영향 반영.

## Ⅲ. 성능요구 정의와 검증 흐름
- 핵심 요약 : 업무시나리오·부하모델·목표치 합의 후 기준선 측정·부하시험·운영검증 수행.
```text
업무 시나리오·사용자 여정
    ↓ 동시성·요청비율·데이터량
응답시간·처리량·오류율·CPU/메모리 목표
    ↓
성능시험 → 병목분석·개선 → 재시험·SLO 수립
```
```text
예: 정상부하 500 동시세션에서 검색 API p95 ≤ 300ms,
    오류율 < 0.1%, 지속 30분, 지정 시험환경 기준
```
- 검증유형 : 부하·스트레스·스파이크·내구성 시험을 사용목표에 맞춰 선택.

## Ⅳ. 성능요구 지표 비교
- 핵심 요약 : 응답시간은 개별 요청지연, 처리량은 단위시간 완료량, 자원사용률은 용량·비용 여유를 평가.
| 지표 | 의미 | 주의점 |
|---|---|---|
| 응답시간 | 요청에서 결과까지 지연 | 평균 외 백분위·측정경계 포함 |
| 처리량 | 초당 요청·업무 완료량 | 성공률·요청혼합과 함께 해석 |
| 자원사용률 | CPU·메모리·I/O·연결풀 소비 | 지속 포화·급증 여부 관찰 |
| Turnaround | 배치·업무의 전체 완료시간 | 대화형 응답과 구분 |

## Ⅴ. 성능요구의 한계와 대응
- 핵심 요약 : 비현실적 목표·시험환경 차이·평균값 편향을 기준선·대표 부하·백분위 분석으로 완화.
| 한계 | 영향 | 대응 |
|---|---|---|
| 모호한 목표 | 시험 합격여부 불명 | 수치·환경·부하·시간창 합의 |
| 대표성 낮은 부하 | 실제 병목 미검출 | 운영 로그 기반 요청혼합·데이터크기 구성 |
| 늦은 검증 | 구조적 병목 수정비용 증가 | 아키텍처 단계 성능모델·조기 부하시험 |

## Ⅵ. 성능요구 제언
- 핵심 요약 : 아키텍트·제품책임자는 사용자 여정별 목표와 인프라 비용·서비스 수준을 함께 승인.
1. 요구분석가는 중요 시나리오와 성능목표·수용조건을 RTM에 기록.
2. 성능엔지니어는 기준선·병목·분포·시험환경을 재현 가능하게 보존.
3. SRE는 실제 지표를 SLO에 연결하고 용량·오류예산 검토에 활용.

## Ⅶ. 결론
- 핵심 요약 : 성능요구는 부하·환경·측정법이 명시된 정량 품질계약.
- 시사점 : 업무성과를 응답시간·처리량·자원비용과 연결해야 사용자가 체감하는 성능을 보장.
