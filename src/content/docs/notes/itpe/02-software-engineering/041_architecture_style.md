## 연관 키워드

- 아키텍처 스타일, 계층형, 클라이언트-서버, 파이프필터, 레포지토리
- 이벤트기반, 마이크로커널, 마이크로서비스, 품질속성, 트레이드오프

## Ⅰ. 아키텍처 스타일의 개요

- 핵심 요약 : 아키텍처 스타일은 구성요소·연결자·제약의 반복 패턴으로 시스템 골격을 정하는 설계 어휘 체계.
- 개념 : 시스템을 이루는 **구성요소**(component, 시스템의 기능 단위)와 요소를 잇는 **연결자**(connector, 요소 간 호출·메시지 수단), 그 상호작용 제약의 반복 패턴으로 기본 골격을 규정하는 설계 어휘 체계(**아키텍처 스타일**, Architecture Style).
- 배경 및 필요성 : 구조 없이 기능 추가를 반복하면 모듈 간 의존이 얽혀 변경 비용이 급증하는 상태에 이르며, 검증된 구조 패턴의 초기 적용이 이 비용의 통제 수단이 됨.
- 주요 목적 : 성능·가용성·변경 용이성 같은 **품질속성**(quality attribute, 기능 동작 밖에서 요구되는 품질 기준)에 맞는 시스템 골격과 통신 규칙의 조기 확정.

## Ⅱ. 아키텍처 스타일의 특징 및 장점

- 핵심 요약 : 검증된 구조 어휘와 제약, 트레이드오프의 공개가 설계 품질과 조직 의사결정 효율로 연결됨.

1. 구조 어휘 제공 : 검증된 패턴을 설계 언어로 공유 → 설계 논의의 조기 수렴과 표현·이해 비용 감소.
2. 제약의 설계 효과 : 의존 방향과 통신 방식을 허용 범위로 제한 → 구조 일관성·예측 가능성 확보.
3. 트레이드오프 공개 : 스타일마다 유리한 품질속성과 그 대가가 정해짐 → 선택 근거의 문서화와 책임 소재 명확.
4. 변이 관리 : **마이크로커널**(microkernel, 공통 코어에 확장 기능을 플러그인으로 붙이는 구조) 적용 시 변이점만 교체 → 제품군 개발 공수 절감.

## Ⅲ. 아키텍처 스타일의 구조 (흐름)

- 핵심 요약 : 호출·데이터 흐름·중앙 저장소·이벤트·독립 서비스 계열의 대표 스타일과, 품질요구에서 시나리오 평가를 거쳐 골격을 확정하는 선택 흐름.
- 대표 스타일 : **계층형**(기능을 층으로 나누고 상위에서 하위로의 단방향 호출만 허용), **클라이언트-서버**(요청자와 자원 제공자의 역할 분리), **파이프필터**(처리 단위인 필터를 파이프로 순차 연결), **레포지토리**(중앙 저장소를 두고 구성요소가 상태를 공유), **이벤트기반 아키텍처** (EDA, Event-Driven Architecture, 상태 변화를 이벤트로 발행하고 구독자가 반응), **마이크로서비스**(기능을 독립 배포 가능한 서비스로 분할).

```text
[ 스타일 선택 흐름 ]

품질속성 요구 도출
   ↓
후보 스타일 열거
   ↓
시나리오 기반 평가
   ↓
골격·연결 규칙 확정
   ↓
구현·운영에서 검증
```

```text
[ 파이프필터의 데이터 흐름 ]

입력 필터
   ↓ 파이프
변환 필터
   ↓ 파이프
출력 필터
```

## Ⅳ. 대표 아키텍처 스타일 간 비교

- 핵심 요약 : 같은 비교 축에서 계층형·파이프필터·레포지토리·이벤트기반·마이크로서비스가 서로 다른 강점 품질속성과 대가를 보임.

| 비교 축 | 계층형 | 파이프필터 | 레포지토리 | 이벤트기반 | 마이크로서비스 |
|---|---|---|---|---|---|
| 구성 단위 | 기능별 층 | 독립 필터 | 중앙 저장소·클라이언트 | 발행자·구독자 | 독립 배포 서비스 |
| 데이터 흐름 | 상위→하위 호출 | 파이프 순차 전달 | 저장소 기준 공유 | 이벤트 발행·구독 | 서비스 간 인터페이스 호출 |
| 강점 품질속성 | 이해 용이성·유지보수 | 재사용·처리량 | 데이터 일관성 | 확장성·장애 격리 | 자율성·독립 배포 |
| 주요 대가 | 계층 통과 성능 부담 | 상태 공유 곤란 | 저장소 집중 부하 | 흐름 추적 곤란 | 운영 복잡도 증가 |

## Ⅴ. 아키텍처 스타일의 한계와 방안

- 핵심 요약 : 유행 추종·만능 스타일 오해·구조 드리프트·일괄 전환을 시나리오 평가와 점진 전환으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 유행 추종 선택 | 조직 역량·문제 성격보다 기술 유행이 선택을 앞섬 → 운영 미달 장애 | 품질속성 시나리오 기반 대안 평가와 근거 기록 | 평가 미충족 항목 수 |
| 만능 스타일 오해 | 모든 서브시스템에 한 스타일 강제 → 국소 비효율 누적 | 도메인별 스타일 분리 적용과 경계 정의 | 서비스별 품질목표 달성률 |
| 구조 드리프트 | 결정 규칙 미문서화로 우회 의존 누적 → 구조 무결성 상실 | 결정 기록(ADR, Architecture Decision Record)과 정적 분석 기반 의존 규칙 검사 | 규칙 위반 건수 |
| 일괄 전환 위험 | 레거시의 한 번에 교체 시도 → 이관 장애·이중 운영 비용 | 위험도 낮은 경계부터의 점진 전환 | 전환 장애 건수 |

## Ⅵ. 아키텍처 스타일에 대한 기술사적 제언

- 핵심 요약 : 아키텍처 위원회 중심의 선택·변경 거버넌스와 패턴 자산·인력 역량의 조직적 내재화 필요.

1. 선택 거버넌스 : 개발조직은 아키텍처 위원회를 두어 스타일 채택·변경을 품질속성 시나리오 평가로 심사하고, **ATAM**(Architecture Tradeoff Analysis Method, 품질속성 트레이드오프 분석 방법) 같은 평가 방법을 공식 절차로 채택.
2. 자산·역량 확산 : 기업은 스타일 패턴 카탈로그와 참조 아키텍처를 사내 표준으로 배포하고, 아키텍트 교육과정으로 평가 역량을 조직 전반에 확산.

## Ⅶ. 결론

- 핵심 요약 : 아키텍처 스타일은 품질속성의 트레이드오프를 조기에 드러내는 설계 어휘 체계.
- 보편적으로 우위인 스타일은 없으며, 맥락에 맞는 선택과 그 근거의 기록이 고품질 시스템 구축의 출발점.
