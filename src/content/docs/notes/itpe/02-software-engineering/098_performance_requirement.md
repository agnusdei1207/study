## 연관 키워드
- 성능 요구사항, 응답 시간, 처리량, 자원 사용률, 동시성, SLI/SLO, 부하 시험

### Ⅰ. 성능 요구사항의 개요

- 핵심 요약 : 성능 요구사항은 시스템의 응답·처리·자원 사용 목표를 특정 부하와 환경에서 측정 가능하게 정의.
- 개념 : 응답 시간, 처리량, 지연 분포, 동시 사용자, 자원 사용률 등 품질 목표와 조건을 명시.
- 배경 및 필요성 : "빠르고 효율적" 같은 모호한 표현은 설계·시험·인수 기준으로 쓸 수 없음.
- 주요 목적 : 아키텍처·용량 계획·성능 시험·운영 SLO의 검증 기준 마련.

### Ⅱ. 성능 요구의 특징 및 장점

- 핵심 요약 : 부하·측정 위치·시간 창·백분위·자원 조건을 함께 명시해야 반복 측정과 인수 판정 가능.

1. 측정 가능성 : 수치·단위·범위 정의 → 주관적 평가 방지.
2. 부하 조건 : 동시성·요청 분포·데이터 크기·기간 정의 → 시험 재현성 확보.
3. 사용자 중심 : 평균 뿐만 아니라 p95/p99 지연·오류율·완료 시간 고려 → 꼬리 지연 영향 반영.

### Ⅲ. 성능 요구 정의와 검증 흐름 (구조)

- 핵심 요약 : 업무 시나리오·부하 모델·목표 치 합의 후 기준선 측정·부하 시험·운영 검증 수행.

```text
업무 시나리오·사용자 여정
    ↓ 동시성·요청 비율·데이터 량
응답 시간·처리량·오류율·CPU/메모리 목표
    ↓
성능 시험 → 병목 분석·개선 → 재 시험·SLO 수립
```

```text
예: 정상 부하 500 동시 세션에서 검색 API p95 ≤ 300ms,
    오류 율 < 0.1%, 지속 30분, 지정 시험 환경 기준
```

- 검증 유형 : 부하·스트레스·스파이크·내구성 시험을 사용 목표에 맞춰 선택.

### Ⅳ. 성능 요구 지표 비교

- 핵심 요약 : 응답 시간은 개별 요청 지연, 처리량은 단위 시간 완료 량, 자원 사용률은 용량·비용 여유를 평가.

| 비교 축 | 응답 시간 | 처리량 | 자원 사용률 | Turnaround |
|---|---|---|---|---|
| 의미 | 요청에서 결과 까지 지연 | 단위 시간 요청·업무 완료 량 | CPU·메모리·I/O·연결 풀 소비 | 배치·업무의 전체 완료 시간 |
| 주의 점 | 평균 외 백분위·측정 경계 포함 | 성공률·요청 혼합과 함께 해석 | 지속 포화·급증 여부 관찰 | 대화형 응답과 구분 |

### Ⅴ. 성능 요구의 한계와 방안

- 핵심 요약 : 비현실적 목표·시험 환경 차이·평균 값 편향을 기준선·대표 부하·백분위 분석으로 완화.

| 한계 | 영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 모호한 목표 | 시험 합격 여부 불명 | 수치·환경·부하·시간 창 합의 | 목표 달성 비율 |
| 대표성 낮은 부하 | 실제 병목 미 검출 | 운영 로그 기반 요청 혼합·데이터 크기 구성 | 병목 탐지 비율 |
| 늦은 검증 | 구조적 병목 수정 비용 증가 | 아키텍처 단계 성능 모델·조기 부하 시험 | 구조 변경 건수 |

### Ⅵ. 성능 요구 제언

- 핵심 요약 : 아키텍트·제품 책임 자는 사용자 여정 별 목표와 인프라 비용·서비스 수준을 함께 승인.

1. 요구 분석 자는 중요 시나리오와 성능 목표·수용 조건을 RTM에 기록.
2. 성능 엔지니어 는 기준선·병목·분포·시험 환경을 재현 가능하게 보존.
3. SRE 는 실제 지표를 SLO에 연결하고 용량·오류 예산 검토에 활용.

### Ⅶ. 결론

- 핵심 요약 : 성능 요구사항은 부하·환경·측정법이 명시된 정량 품질 계약.
- 시사점 : 업무 성과를 응답 시간·처리량·자원 비용과 연결 해야 사용자가 체감 하는 성능을 보장.
