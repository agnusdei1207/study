## 연관 키워드

- 성능 요구사항(Performance Requirement), 비기능 요구사항, 응답 시간, 처리량
- 자원 사용률, 부하 조건, 백분위 지연, 성능 시험, SLO(Service Level Objective)

## Ⅰ. 성능 요구사항의 개요

- 핵심 요약 : 성능 요구사항은 지정한 부하·환경에서 응답 시간·처리량·자원 사용률의 목표 수준을 측정 가능한 형태로 명시한 요구.
- 개념 : 시스템이 주어진 부하 조건에서 수행해야 할 성능 수준을 수치·단위·측정 방법과 함께 정의한 **성능 요구사항** (Performance Requirement)이며, 품질·제약 조건을 다루는 **비기능 요구사항** (기능 외 품질과 제약을 규정하는 요구)의 대표 항목이다. 대표 지표로 **응답 시간** (Response Time, 요청에서 응답 수신까지의 지연), **처리량** (Throughput, 단위 시간당 완료 처리 건수), **자원 사용률** (Resource Utilization, CPU·메모리 등 자원의 사용 비율)을 명시한다.
- 배경 및 필요성 : 빠르다·효율적이다 같은 정성 표현은 설계 결정과 시험 합격, 인수 판정의 근거가 되지 못하고, 성능 결함은 구조 변경 비용이 크므로 정의 시점이 앞서야 하는 필요가 존재.
- 주요 목적 : 아키텍처 결정·용량 계획·성능 시험 합격 기준·운영 수준 목표가 하나의 판정 기준을 공유하는 상태 확보.

## Ⅱ. 성능 요구사항의 특징 및 장점

- 핵심 요약 : 측정 가능성·부하 조건·사용자 관점 지표·환경 구속력이 재현 가능한 판정이라는 장점으로 연결.

1. 측정 가능성 : 수치와 단위, 측정 방법을 명시 → 주관적 평가 배제와 객관적 합격 판정 효과.
2. 부하 조건 명시 : **동시 사용자** (같은 시각에 시스템을 이용하는 사용자 수)·요청 혼합·데이터 크기·지속 시간을 함께 정의 → 시험 재현성 확보 효과.
3. 사용자 관점 지표 : 평균에 더해 **백분위 지연** (느린 쪽 일부 요청의 지연을 함께 보는 통계, p95·p99)을 명시 → 소수의 느린 경험까지 반영하는 효과.
4. 환경 구속력 : 측정 환경과 기준선을 지정 → 개발·시험·운영 간 동일 기준 판정 효과.

## Ⅲ. 성능 요구사항의 구조 (흐름)

- 핵심 요약 : 시나리오 선정→부하 조건 정의→지표·목표치 명시→성능 시험 검증의 단계 흐름.
- 명세 한 건은 시나리오·부하·지표·환경·기간을 갖추어 기록하며, 검증은 목적별 시험 유형으로 수행한다.

```text
[성능 요구 정의 흐름]

업무 시나리오 선정
   ↓
부하 조건 정의
   ↓
지표·목표치 명시
   ↓
성능 시험으로 검증
```

```text
[성능 요구 기록 형식의 구성]

시나리오 : 대표 업무·사용자 여정
부하 조건 : 동시 사용자·요청 혼합
지표 : 응답 시간·처리량·자원 사용률
환경 : 측정 전용 시험 환경 지정
기간 : 목표 수준 유지 시간
```

- 검증은 목적에 맞는 시험 유형을 선택한다.

| 시험 유형 | 목적 |
| --- | --- |
| 부하 시험 | 목표 부하에서 목표치 달성 확인 |
| 스트레스 시험 | 한계 부하와 붕괴 지점 확인 |
| 스파이크 시험 | 급격한 부하 변동 대응 확인 |
| 내구성 시험 | 장시간 운전 시 성능 열화 확인 |

## Ⅳ. 성능 요구사항과 기능 요구사항의 비교

- 핵심 요약 : 기능 요구사항이 수행 내용을 규정하는 반면 성능 요구사항은 수행 수준을 정량으로 규정하는 대척 관계.

| 비교 축 | 성능 요구사항 | 기능 요구사항 |
| --- | --- | --- |
| 초점 | 얼마나 잘 수행하는가 | 무엇을 수행하는가 |
| 표현 형식 | 수치·단위·조건의 정량 명세 | 입력·처리·출력의 동작 명세 |
| 검증 방법 | 부하 시험·측정 기반 판정 | 기능 시험·시나리오 기반 판정 |
| 미충족 영향 | 사용자 이탈·장애·용량 비용 | 업무 수행 자체 불가 |
| 변경 계기 | 트래픽·데이터 규모 변화 | 업무 정책·절차 변화 |

## Ⅴ. 성능 요구사항의 한계와 방안

- 핵심 요약 : 모호한 목표·비현실적 목표·늦은 검증·평균 편향을 명세 표준·기준선·조기 검증·백분위로 관리하는 원칙.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 모호한 목표 | 수치·환경 미명시 → 인수 판정 분쟁 | 측정 방법을 포함한 명세 템플릿 적용 | 명세 완비율 |
| 비현실적 목표 | 용량·비용 미고려 → 재설계·과다 인프라 비용 | 기준선 측정 후 비용 검토 병행 | 목표 미달 시나리오 비율 |
| 늦은 검증 | 구현 완료 후 확인 → 구조적 병목 수정 비용 증가 | 설계 단계 성능 모델과 조기 부하 시험 | 구조 변경 건수 |
| 평균 편향 | 평균만 추적 → 느린 요청·체감 품질 누락 | 백분위 지연과 오류율 병기 | 백분위 지표 적용률 |

## Ⅵ. 성능 요구사항에 대한 기술사적 제언

- 핵심 요약 : 성능 목표를 요구사항 거버넌스와 운영 수준 관리 체계로 연결하는 방향.
- 거버넌스 : 개발 조직이 요구사항 추적 체계에 성능 명세 템플릿을 등재하고 변경 통제 대상으로 관리.
- 승인 체계 : 아키텍트가 시나리오별 성능 목표를 아키텍처 결정 기록으로 승인하고, 성능 엔지니어가 기준선과 시험 환경을 재현 가능한 자산으로 보존.
- 운영 연계 : 운영 조직이 실측 지표를 **SLO** (Service Level Objective, 서비스 수준 목표)와 대조하는 용량 관리 프로세스를 상시 운영.

## Ⅶ. 결론

- 핵심 요약 : 성능 요구사항은 부하·환경·측정법이 명시된 정량 품질 계약.
- 시사점 : 수치로 합의된 성능 기준만이 설계·시험·운영을 하나의 판정 기준으로 묶는 효과.
