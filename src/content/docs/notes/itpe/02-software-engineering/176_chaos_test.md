## 지식 로드맵 내 현재 위치

소프트웨어공학 → 신뢰성 시험 → **카오스 테스트**

## 30초 인출

- **본질** : 카오스 테스트는 통제된 장애를 주입해 시스템이 예상한 서비스 상태를 유지하거나 회복하는지 확인하는 실험
- **메커니즘** : 정상 상태 정의 → 가설 설정 → 영향 범위 제한 → 장애 주입 → 사용자 지표 관찰·개선
- 통찰: 한계: 중단 조건 없는 장애 주입은 실험 자체가 사용자 피해로 번질 수 있음 → 방안: 정상 상태 지표와 영향 범위를 정한 뒤 작은 범위에서 검증

<details>
<summary>핵심 용어</summary>

- **카오스 엔지니어링(Chaos Engineering)** : 실제 장애를 닮은 변수를 통제된 실험에 도입해 시스템의 취약점을 발견하는 접근
- **정상 상태(Steady State)** : 처리량·오류율·지연 등 서비스가 평소 제공하는 상태를 나타내는 측정값
- **장애 주입(Fault Injection)** : 서버 중단·네트워크 지연 등 장애 조건을 의도적으로 만드는 행위
- **영향 범위(Blast Radius)** : 실험이 사용자·서비스·인프라에 영향을 미칠 수 있는 범위
- **복원력(Resilience)** : 장애에도 기능을 유지하거나 필요한 수준으로 회복하는 능력
- **중단 조건(Abort Condition)** : 실험 지표가 허용 범위를 벗어날 때 장애 주입을 멈추는 기준

</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **카오스 테스트** : 통제된 장애를 주입해 서비스의 정상 상태 유지·회복 여부를 확인하는 실험 |
| 목적 | 예상하지 못한 장애 전파와 복구 실패를 운영 사고 전에 발견 |

## Ⅱ. 카오스 테스트의 특징

| 특징 | 의미 |
|---|---|
| 가설 기반 | 장애 시 유지할 사용자 서비스 상태를 먼저 정의 |
| 통제된 주입 | 대상·시간·영향 범위와 중단 조건 설정 |
| 관측·재검증 | 정상 상태 지표와 비교하고 개선 후 같은 조건으로 재실험 |

## Ⅲ. 실험과 영향 범위 통제 절차

```text
정상 상태·핵심 지표 측정
    ↓
장애 상황의 기대 동작 가설
    ↓ 영향 범위·중단 조건 설정
통제된 장애 주입
    ↓
관측 결과와 가설 비교·개선
```

| 단계 | 핵심 조건 |
|---|---|
| 정상 상태 | 사용자가 체감하는 처리량·오류율·지연 수준 |
| 가설 | 인스턴스·연결 실패 때 유지할 서비스 수준 |
| 실험 | 장애 유형·주입 범위·지속 시간 |
| 판정 | 실험군과 기준 상태 차이의 허용 범위 |

### 영향 범위 통제

```text
실험 승인·책임자 지정
    ↓ 대상·시간·영향 범위 제한
안전 중단 조건·복구 경로 확인
    ↓ 실험 중 지표 관측
    ├─ 조건 이탈 → 중단·복구 확인
    └─ 조건 유지 → 가설 판정·종료
```

## Ⅳ. 장애 변수와 시험 방식 비교

| 구분 | 초점 |
|---|---|
| 일반 장애 시험 | 정해진 장애·복구 절차가 요구대로 작동하는지 확인 |
| 카오스 실험 | 현실적인 장애 조건에서 서비스 상태에 대한 가설을 검증 |

두 활동은 상호 배타적이지 않으며, 카오스 실험이 복구 절차 시험을 대신하지도 않음.

| 장애 변수 | 예상 위험 | 관측값 |
|---|---|---|
| 인스턴스 중단 | 단일 장애가 전체 오류로 확산 | 성공률·복구 시점 |
| 네트워크 지연·단절 | 타임아웃·재시도 폭증 | 응답 지연·대기열·오류율 |
| 의존 서비스 실패 | 연쇄 장애 | 차단기 동작·대체 경로·핵심 기능 유지 |

정상 상태는 CPU 수치만으로 정하지 않고 사용자에게 제공되는 서비스 결과를 포함.

| 통제 항목 | 실행 기준 |
|---|---|
| 범위 | 소수 인스턴스·트래픽부터 시작하고 단계적 확대 |
| 중단 | 오류율·지연·업무 지표가 합의된 허용 범위 이탈 시 종료 |
| 복구 | 주입 중단 후 서비스·데이터 상태가 회복됐는지 확인 |

**영향 범위 최소화** 는 피해가 절대 발생하지 않는다는 보장이 아니라 위험을 줄이기 위한 실험 설계 원칙.

### 결과 해석과 개선

| 관측 결과 | 해석·후속 조치 |
|---|---|
| 가설 유지 | 다른 장애 변수·영향 범위까지 검증 범위 확대 검토 |
| 가설 반증 | 취약한 의존성·재시도·복구 경로를 찾아 수정 |
| 관측 불충분 | 서비스 지표·분산 추적·로그 등 측정 가능성 개선 |

실험 도구나 자동화 플랫폼은 환경에 따라 선택하며, 도구 사용 자체를 복원력 확보로 간주하지 않음.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 중단 조건 없는 장애 주입 | 사용자 오류율·지연의 허용 범위를 정하고 이탈 시 즉시 중단·복구 |
| 사용자 영향 파악 부족 | CPU뿐 아니라 성공률·업무 지표를 정상 상태 기준으로 관측 |
| 취약점 발견 후 검증 누락 | 수정 후 같은 가설·지표로 재실험해 개선 효과 확인 |

## Ⅵ. 제언

우선 실행: 영향이 작은 장애 가설부터 실험하고 복구 지표가 개선됐는지 동일 조건에서 재검증.
