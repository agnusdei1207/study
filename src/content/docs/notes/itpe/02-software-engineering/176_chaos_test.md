## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 테스트·검증 → **카오스 테스트(Chaos Test)**

## 30초 인출

- 본질: 카오스 테스트는 서버 중단·네트워크 지연 같은 장애를 일부러 일으켜 시스템이 장애 속에서도 정상 서비스를 유지하는지 확인하는 실험
- 메커니즘: 정상 상태 지표를 정의하고 장애를 주입해 지표가 유지되는지 관찰하며 무너지면 약점을 수정한 뒤 다시 실험
- 통찰: 실험이 실제 사용자에게 피해를 줄 수 있으므로 영향 범위를 작게 시작하고 지표가 한도를 넘으면 즉시 중단하는 조건을 정해 두고 실행

<details>
<summary>핵심 용어</summary>

- **카오스 엔지니어링(Chaos Engineering)** : 장애를 주입해 시스템의 복원력을 실험으로 검증하는 방법
- **정상 상태(Steady State)** : 시스템이 잘 동작함을 나타내는 관측 지표의 범위
- **장애 주입(Fault Injection)** : 서버 종료·지연·패킷 손실 등을 인위적으로 일으키는 것
- **폭발 반경(Blast Radius)** : 실험이 미칠 수 있는 사용자·시스템의 영향 범위
- **중단 조건(Abort Condition)** : 지표가 한도를 넘으면 실험을 즉시 멈추는 조건

</details>

## 2~4교시 25점 답안

## Ⅰ. 카오스 테스트의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **카오스 테스트** 는 장애를 일부러 일으켜 시스템의 복원력을 검증하는 실험 |
| 목적 | 예상하지 못한 장애에 대한 시스템 약점의 사전 발견 |

## Ⅱ. 일반 장애 시험과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 가설 기반 | 정상 상태가 유지될 것이라는 가설 검증 |
| 실제 환경 지향 | 운영과 가까운 환경에서 실험 |
| 통제된 실험 | 영향 범위와 중단 조건 설정 |

## Ⅲ. 실험 순환

```text
  정상 상태 지표 정의
        ↓
┌→ 장애 주입 (범위 제한)
│      ↓
│  지표 관찰 ── 한도 초과 → 즉시 중단
│      ↓
└─ 약점 수정 후 재실험
```

## Ⅳ. 장애 유형과 실험 방식

| 장애 유형 | 예 | 확인 대상 |
|---|---|---|
| 자원 | 서버·컨테이너 종료 | 자동 복구·이중화 |
| 네트워크 | 지연·패킷 손실 | 타임아웃·재시도 |
| 의존 서비스 | 외부 API 실패 | 폴백·서킷 브레이커 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 실험이 실제 사용자에게 피해 | 작은 범위에서 시작하고 점차 확대 |
| 실험 중 통제 불능 | 중단 조건과 즉시 중단 수단 확보 |
| 실험 결과의 미반영 | 발견된 약점을 개선 과제로 관리 |

## Ⅵ. 제언

영향 범위를 작게 시작하고, 정상 상태 지표가 한도를 넘으면 자동 중단되도록 설정한 뒤 실험

```text
소규모(일부 인스턴스) → 지표 정상 → 범위 확대
                     └─ 한도 초과 → 즉시 중단·원인 분석
```

| 구분 | 전면 실험 | 제언: 단계적 확대 |
|---|---|---|
| 사용자 피해 | 클 수 있음 | 제한 |
| 중단 | 수동 | 자동 |
