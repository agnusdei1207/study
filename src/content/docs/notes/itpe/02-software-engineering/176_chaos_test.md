## 연관 키워드

- 카오스 테스트(Chaos Test), 카오스 엔지니어링(Chaos Engineering), 회복탄력성(Resilience)
- 카오스 몽키(Chaos Monkey), 정상 상태(Steady State), 폭발 반경(Blast Radius), 데드맨 스위치(Dead Man's Switch)
- 관측성(Observability), 서킷 브레이커(Circuit Breaker), GameDay

## Ⅰ. 카오스 테스트의 개요

- 핵심 요약 : 운영 환경에 의도적 장애를 주입해 분산 시스템의 회복탄력성을 검증하는 공학적 실험 기법.
- 개념 : 분산 시스템이 서버 다운, 네트워크 지연 같은 예기치 못한 장애 속에서도 서비스를 유지하는지 확인하려고 장애를 의도적으로 주입하는 실험인 **카오스 테스트**(Chaos Test). 이를 원칙과 절차로 체계화한 접근을 **카오스 엔지니어링**(Chaos Engineering)이라 부른다.
- 배경 및 필요성 : 마이크로서비스 아키텍처(MSA, Microservice Architecture)와 멀티 리전 클라우드처럼 구성 요소가 많아지면 일부 부품 장애는 상시 발생하는 것을 전제로 해야 한다. 장애를 막는 설계에서 장애를 견디는 설계(Fault-Tolerant)로 관점이 옮겨가면서, 실제 장애 상황에서 **회복탄력성**(Resilience)이 작동하는지 검증할 필요가 생겼다. 넷플릭스가 2011년경 공개한 Simian Army의 **카오스 몽키**(Chaos Monkey)가 이 접근의 출발점으로 알려져 있다.
- 주요 목적 : 장애 흡수 역량을 운영 중에도 상시 확인하고, 설계 가정과 실제 동작의 차이를 실험으로 드러내는 것.

## Ⅱ. 카오스 테스트의 특징 및 장점

- 핵심 요약 : 정상 상태 가설에 따른 검증형 실험과 폭발 반경 통제가 결합되어, 피해를 제한하면서 근거 있는 신뢰성 데이터를 얻는 방법론.

1. 가설 검증형 실험 : **정상 상태**(Steady State, 시스템이 정상이라고 판단하는 측정 지표의 상태)를 먼저 정의하고 장애 중에도 지표가 유지되는지 확인 → 장애 대응이 설계 의도대로인지 객관적으로 판정.
2. 실운영 환경 실험 : 실제 트래픽 패턴 아래에서 실험 → 스테이징 환경에서는 드러나지 않는 결함까지 발견.
3. 폭발 반경 통제 : **폭발 반경**(Blast Radius, 실험 장애가 미치는 영향의 범위)을 작게 시작해 점진적으로 확장 → 고객 피해를 제한하면서 학습.
4. 비상 정지 장치 : **데드맨 스위치**(Dead Man's Switch, 이상 징후 시 실험을 자동 중단하는 장치)를 상시 배치 → 통제 불능 상황을 차단.
5. 자동화된 지속 실행 : 스케줄 또는 무작위 주입 도구로 반복 실행 → 한 번 확인한 장애 흡수 역량이 이후 변경으로 무너지는 것을 방지.
6. 관측 기반 판정 : **관측성**(Observability, 메트릭·로그·분산 추적으로 내부 상태를 추론하는 능력) 위에서 정상 상태 유지 여부를 판단 → 장애 원인을 규명할 수 있음.
7. 숨은 결함의 조기 발견 : 실제 장애 전에 단일 장애점(SPOF, Single Point of Failure)을 찾아냄 → 장애 발생 후 대응이 아닌 사전 보강이 가능.
8. 복구 시간 단축 : 장애 대응 훈련이 반복되면서 평균 복구 시간(MTTR, Mean Time to Repair)이 줄어듦 → 서비스 중단 손실 감소.

## Ⅲ. 카오스 테스트의 구조 (흐름)

- 핵심 요약 : 정상 상태 정의에서 가설 수립, 장애 주입, 검증과 개선으로 이어지는 반복 실험 주기.
- 공개된 실험 원칙(Principles of Chaos Engineering)은 정상 상태 가설 수립, 실제 장애 변수 주입, 운영 환경 실험, 자동화된 지속 실행, 폭발 반경 최소화의 다섯 가지를 제시한다. 아래 주기는 이 원칙을 실행 순서로 풀어 쓴 것이다.

```text
[ 1. 정상 상태 정의 ]
   정상 지표 측정 (예: 결제 성공률)
        ↓
[ 2. 가설 수립 ]
   "파드가 죽어도 결제 성공률 유지"
        ↓
[ 3. 장애 주입 ]
   파드 강제 종료, 네트워크 지연 주입
        ↓
[ 4. 검증과 개선 ]
   지표 훼손 여부 확인
   서킷 브레이커, 타임아웃 보완 후 반복
```

- 실험 범위는 작게 시작해 넓힌다. 카나리(Canary) 트래픽의 일부에 장애를 주고, 지표가 유지되면 범위를 점진 확장한다. 이상 징후가 감지되면 데드맨 스위치가 즉시 실험을 중단한다.

```text
[ 실험 범위 확장 ]
  카나리 트래픽 일부 격리
        ↓
  소규모 장애 주입 → 지표 정상
        ↓
  범위 점진 확장
        ↓
  이상 감지 → 데드맨 스위치 → 중단
```

## Ⅳ. 전통적 장애 테스트와 카오스 엔지니어링의 비교

- 핵심 요약 : 사전 공지된 수동 모의 훈련에서 자동화된 실운영 지속 실험으로의 전환.

| 비교 축 | 재해 복구 테스트(DR, Disaster Recovery) | 카오스 엔지니어링 |
| --- | --- | --- |
| 수행 방식 | 사전 일정 공지 후 모의 시나리오대로 수동 수행 | 무작위 또는 자동화 스케줄에 따른 지속적 수행 |
| 수행 환경 | 격리된 테스트 환경 또는 야간 점검 시간 | 실제 트래픽이 흐르는 실운영 환경 |
| 주요 관심사 | 백업 복구 절차의 준수 여부 | 장애의 자동 흡수와 정상 상태 유지 여부 |
| 장애 주입 대상 | 서버 전원 차단, 네트워크 케이블 분리 | 파드 종료, CPU(Central Processing Unit) 부하, DNS(Domain Name System) 지연 |
| 대표 도구 | 수작업 스크립트, 데이터센터 DR 훈련 | Chaos Mesh, Gremlin, LitmusChaos, Chaos Toolkit |

## Ⅴ. 카오스 테스트의 한계와 방안

- 핵심 요약 : 연쇄 장애, 관측성 부재, 조직 저항이 주요 한계이며 범위 통제·관측 기반·단계적 신뢰 구축으로 대응.
- 운영 환경 실험은 통제에 실패하면 실제 고객 피해로 이어질 수 있으므로 실험 범위와 중단 장치를 먼저 설계해야 한다. 아래 표는 한계별 원인과 대응을 일대일로 정리한다.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 연쇄 장애 확산 | 의도한 지연·종료가 DB 데드락, 결제 트랜잭션 오류로 번져 복구 불가 피해 발생 | 폭발 반경 최소화, 카나리 트래픽 격리, 데드맨 스위치 구현 | 실험 중단 소요 시간 |
| 관측성 부재 | 분산 추적과 메트릭이 미비하면 붕괴 원인을 규명할 수 없어 가설 검증 실패 | 실험 전 정상 상태 정의, 메트릭·추적과 연동된 도구 사용 | 정상 상태 지표 정의율 |
| 조직 저항 | 운영 중 의도적 장애에 대한 개발·운영팀과 경영진의 불신으로 제도 정착 실패 | 스테이징 기반 단계적 신뢰 구축, 시나리오 사전 공유, **GameDay**(팀이 장애 시나리오를 함께 실행해 대응을 훈련하는 행사) 운영 | 실험 참여율 |

## Ⅵ. 고가용성 클라우드 아키텍처를 위한 기술사적 제언

- 핵심 요약 : 회복탄력성 패턴을 설계 단계에서 먼저 내재화하고, GameDay를 정례화해 조직의 대응 역량을 훈련.
- 서비스 설계자는 카오스 실험을 시작하기 전에 **서킷 브레이커**(Circuit Breaker)와 **그레이스풀 디그레이데이션**(Graceful Degradation)을 구현해 두어야 한다. 예컨대 추천 서비스가 멈추더라도 결제 흐름이 캐시된 응답 같은 대체 경로로 계속 동작하도록 설계해 두면, 실험 결과는 설계 결함이 아니라 검증 대상으로 남는다.
- 운영 조직은 실험 정책을 문서로 정하는 거버넌스가 필요하다. 실험 범위, 중단 기준, 승인 권한을 경영진 승인 아래 정해 두어야 실험이 일회성 이벤트가 아니라 상시 활동으로 자리 잡는다.
- 개발팀과 사이트 신뢰성 엔지니어링(SRE, Site Reliability Engineering) 팀은 분기 단위로 GameDay를 열어 온콜 경보 대응과 복구 시간 측정을 함께 훈련하고, 그 결과를 관측 체계 개선으로 연결하는 것이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : 카오스 테스트는 장애를 전제로 회복탄력성을 측정하는 과학적 실험 체계.
- 정상 상태 가설과 통제된 장애 주입이 결합될 때 설계 가정은 검증된 사실로 바뀐다. 도구보다 실험 원칙과 조직의 신뢰가 도입 성패를 가른다.
