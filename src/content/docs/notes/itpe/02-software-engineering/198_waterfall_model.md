```text
[폭포수 모델(Waterfall Model)] ◀━━ 머리: Ⅶ 내 의견 (엄격한 규제 컴플라이언스 환경에서의 폭포수 모델 테일러링과 추적성(Traceability) 확보)
 ┃
 ┣━ Ⅰ 개요 ───── 1970년 윈스턴 로이스(Royce)가 제안한 가장 고전적이고 체계적인 선형 순차 소프트웨어 생명주기(SDLC) 프로세스 모델
 ┣━ Ⅱ 특징 ───── 단계별 진입/종료 기준(Entry/Exit Criteria) 엄격 · 직전 단계로의 제한적 피드백 루프 · 산출물 베이스라인 동결 원칙
 ┣━ Ⅲ 구조 ───── 표준 SDLC 계층: 시스템 공학 → 요구분석 → 설계 → 코딩 → 테스팅 → 유지보수
 ┣━ Ⅳ 흐름 ───── 요구분석(SRS 베이스라인) → 아키텍처/상세설계(SDD) → 소스코드 작성 → 단위/통합/인수 시험 → 운영 전환
 ┣━ Ⅴ 비교 ───── 고전 폭포수 모델 vs 사시미 모델(중첩 폭포수) vs V-모델 vs 프로토타이핑 모델
 ┗━ Ⅵ 실무 ───── 후반부 요구사항 변경에 따른 납기/비용 통제 불능 / 단계별 공식 검토(Formal Review, Inspection) 필수 운영
```

## 한 줄 본질
- 이전 단계의 산출물 검토와 베이스라인 승인이 완료되어야만 다음 단계로 폭포수처럼 낙하 진행하는 고전적 선형 SDLC 모델 / 단계별 품질 게이트와 높은 예측 가능성

## 핵심 그림
```text
[ 폭포수 모델의 원형과 직전 단계 피드백 루프 (Royce, 1970) ]

  [ 시스템 요구사항 ] ──┐
          ▲            ▼
          └── [ 소프트웨어 요구분석 ] ──┐
                      ▲                 ▼
                      └── [ 소프트웨어 설계 ] ──┐
                                  ▲             ▼
                                  └── [ 코딩 및 구현 ] ──┐
                                              ▲           ▼
                                              └── [ 테스팅 및 검증 ] ──┐
                                                          ▲             ▼
                                                          └── [ 운영 및 유지보수 ]
```

## 핵심 용어
- 윈스턴 로이스(Winston Royce): 1970년 논문에서 폭포수 프로세스를 처음 문서화하였으며, 실제로는 단방향 진행의 위험성을 경고하고 이전 단계로의 피드백과 2회 이상의 프로토타이핑을 강조함
- 진입/종료 기준(Entry/Exit Criteria): 특정 개발 단계에 착수하기 위해 반드시 갖추어야 할 전제 조건과, 다음 단계로 넘어가기 위해 충족해야 할 품질 통과 기준
- 산출물 추적성(Traceability): 요구사항 ID로부터 설계 모듈, 소스코드 함수, 테스트 케이스 번호까지 일대일 또는 일대다로 양방향 추적이 가능한 상태
- 사시미 모델(Sashimi Model / Overlapping Waterfall): 폭포수의 경직성을 완화하기 위해 인접한 단계(예: 요구분석과 설계)를 일정 부분 겹치게(Overlap) 중첩 진행하는 변형 모델
- V-모델(V-Model): 폭포수 모델의 각 개발 단계에 대응하는 테스팅 단계를 오른쪽 날개에 매핑하여 검증과 확인의 관계를 시각화한 확장 모델

## 핵심 통찰
- 흔히 폭포수를 '피드백이 전혀 없는 맹목적 모델'로 비판하지만, 로이스의 본래 논문은 직전 단계로의 피드백 루프를 필수 요소로 정의했음
- 폭포수 모델이 성공하기 위한 절대 전제는 '프로젝트 시작 시점에 도메인 요구사항이 거의 완벽하게 파악될 수 있는가'임
- 개발 단계마다 명확한 베이스라인(Baseline)과 공식 인스펙션(Fagan Inspection)을 거치므로, 관공서 조달이나 국방 무기체계처럼 감사(Audit)와 계약적 책임 소재 규명이 최우선인 환경에서 독보적인 장점을 지님
- 그러나 현대의 급변하는 비즈니스 환경에서는 프로젝트 말기까지 동작하는 결과물을 볼 수 없다는 치명적 지연 리스크를 수반함

## 이웃 토픽과 구분
| 비교 항목 | 고전 폭포수 모델 | 사시미 모델 (중첩 폭포수) | V-모델 | 프로토타이핑 모델 |
| :--- | :--- | :--- | :--- | :--- |
| **단계 진행 방식** | 엄격한 단방향 직렬 진행 | 인접 단계 간 일정 부분 중첩 진행 | 개발과 시험의 V자 대칭 매핑 | 요구사항 도출을 위한 시제품 반복 |
| **피드백 시점** | 직전 단계로만 제한적 회귀 | 중첩 구간에서 실시간 피드백 | 각 개발 단계에 대응하는 시험 단계 | 프로토타입 시연 후 즉시 피드백 |
| **핵심 강조점** | 단계별 산출물 완성 및 승인 | 개발 기간 단축 및 유연성 확보 | 테스트 계획의 조기 수립 및 검증 | 고객 요구사항의 조기 명확화 |
| **문서화 강도** | 매우 높음 (엄격한 베이스라인) | 높음 | 매우 높음 (추적성 매트릭스) | 낮음 (시제품 중심으로 진행) |

## 문제·원인·대책
| 문제상황 | 원인 | 기술적 대책 |
| :--- | :--- | :--- |
| **프로젝트 후반부 인수 시험 시 대규모 요구 불일치** | 서면 문서(SRS)만으로 소통하여 고객과 개발팀 간의 멘탈 모델 불일치 | 분석 단계에서 UI 목업 및 핵심 기능 와이어프레임 프로토타이핑 의무화 |
| **설계 결함이 코딩 종료 후 통합 시험에서 발견** | 설계 단계의 검토가 형식적인 워크스루에 그침 | Fagan Inspection(공식 인스펙션) 적용 및 체크리스트 기반 설계 엄격 심의 |
| **일정 지연 시 테스팅 단계가 가장 먼저 축소** | 앞선 분석/설계/구현 단계의 지연으로 전체 일정의 마지노선인 시험 기간 압박 | 테스트 계획 및 테스트 케이스 설계를 개발 단계와 병렬 진행(V-모델 원칙 준수) |

## 이렇게 출제된다
- **10점형**: 폭포수 모델(Waterfall Model)의 개념, 단계별 핵심 산출물 및 특징을 설명하시오.
- **25점형**: 
  - 1) 윈스턴 로이스의 폭포수 원형 모델과 단계별 진입/종료 기준(Entry/Exit Criteria)을 도식으로 제시하시오.
  - 2) 폭포수 모델의 변형인 사시미(Sashimi) 모델과 V-모델의 구조 및 차이점을 비교 설명하시오.
  - 3) 요구사항 변경이 빈번한 프로젝트에서 폭포수 모델을 적용할 때 발생하는 리스크와 이를 완화하기 위한 산출물 추적성(Traceability) 관리 방안을 논하시오.

## 내 의견
- 폭포수 모델은 '낡고 버려야 할 구시대 유물'로 매도되기 쉬우나, 항공 우주, 원자력 제어, 의료기기, 자동차 전장 등 소프트웨어 결함이 곧장 인명 사고로 직결되는 안전 규격(IEC 61508, DO-178C)에서는 여전히 폭포수 기반 프로세스가 법적 표준임
- 폭포수의 치명적 약점인 '변화 대응 취약성'을 극복하기 위해서는 각 단계의 전환점에 정량적 품질 게이트(Quality Gate)를 두고, 요구사항 추적성 매트릭스(RTM)를 Jira/ALM 도구로 디지털화하여 변경 영향도(Impact)를 실시간 산정할 수 있는 체계를 갖추어야 함
