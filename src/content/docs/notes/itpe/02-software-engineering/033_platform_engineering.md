## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 빌드·배포·DevOps → **플랫폼 엔지니어링(Platform Engineering)**

## 30초 인출

- 본질: 플랫폼 엔지니어링은 개발자가 인프라·배포·운영 기능을 셀프서비스로 쓰도록 내부 개발자 플랫폼(IDP)을 제품처럼 만들어 제공하는 활동
- 메커니즘: 플랫폼 팀이 보안·모니터링이 내장된 표준 경로(Golden Path)를 IDP로 제공하고, 개발자가 티켓 없이 환경·파이프라인을 직접 생성
- 통찰: DevOps 도구가 늘수록 개발자의 인지 부하가 커지므로 자주 쓰는 배포 경로부터 셀프서비스 표준 경로로 제공하고 사용 지표로 개선

<details>
<summary>핵심 용어</summary>

- **플랫폼 엔지니어링(Platform Engineering)** : 개발자용 내부 플랫폼을 설계·운영해 개발 생산성을 높이는 활동
- **내부 개발자 플랫폼(IDP, Internal Developer Platform)** : 환경 생성·배포·관측 기능을 셀프서비스로 제공하는 사내 플랫폼
- **골든 패스(Golden Path)** : 보안·표준이 내장된 권장 개발·배포 경로
- **인지 부하(Cognitive Load)** : 개발자가 인프라·도구 학습에 쓰는 정신적 부담
- **제품으로서의 플랫폼(Platform as a Product)** : 내부 개발자를 고객으로 보고 플랫폼을 제품처럼 운영하는 방식
- **코드형 정책(Policy as Code)** : 보안·규정 정책을 코드로 정의해 자동으로 적용하는 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. 플랫폼 엔지니어링의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **플랫폼 엔지니어링** 은 개발자가 인프라·배포 기능을 셀프서비스로 쓰도록 내부 플랫폼을 제품처럼 제공하는 활동 |
| 목적 | 개발자 인지 부하 감소와 배포 표준화 |

## Ⅱ. DevOps 개별 도구 운영과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 셀프서비스 | 티켓 없이 환경·파이프라인 생성 |
| 표준 경로 | 보안·모니터링이 내장된 골든 패스 제공 |
| 제품형 운영 | 개발자를 고객으로 보고 사용 지표로 개선 |

## Ⅲ. IDP의 구성과 셀프서비스 흐름

### IDP 구성

```text
개발자
    ↓ 셀프서비스 포털
내부 개발자 플랫폼(IDP)
    ├─ 환경 프로비저닝 ── 코드형 인프라
    ├─ 배포 파이프라인 ── CI/CD
    ├─ 관측·보안 ── 골든 패스에 내장
    └─ 정책 ── 코드형 정책
```

### 확대: 골든 패스 기반 서비스 생성 흐름

```text
개발자: 템플릿 선택
    ↓
플랫폼: 저장소·파이프라인·환경 자동 생성 (보안·모니터링 포함)
    ↓
개발자: 코드 작성·배포
```

## Ⅳ. 도구별 운영과 플랫폼 방식의 비교

| 구분 | 팀별 도구 운영 | 플랫폼 엔지니어링 |
|---|---|---|
| 환경 생성 | 인프라 팀 요청·대기 | 셀프서비스 |
| 표준 준수 | 팀별 편차 | 골든 패스에 내장 |
| 개발자 부담 | 도구·인프라 학습 부담 | 표준 경로 사용 |
| 운영 주체 | 각 팀 | 플랫폼 팀이 제품으로 운영 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 표준 경로가 팀 요구와 맞지 않아 우회 발생 | 개발자 피드백 수렴과 확장 지점 제공 |
| 플랫폼 구축 범위 과다로 도입 지연 | 자주 쓰는 배포 경로부터 단계적 제공 |
| 사용 여부를 알 수 없어 개선 방향 부재 | 사용률·배포 시간 등 지표 수집 |

## Ⅵ. 제언

자주 쓰이는 배포 경로부터 골든 패스로 제공하고, 사용률과 배포 시간 지표로 확대 범위를 판단

### 단계적 확대

```text
개발자 인지 부하가 큰 작업 식별
    ↓
해당 배포 경로의 골든 패스 구축
    ↓
사용률·배포 시간 측정 → 다음 경로 확대
```

### 확대: 확대 판단

```text
지표 확인
    ├─ 사용률·배포 시간 개선 → 다음 경로로 확대
    └─ 우회 발생 → 피드백 반영 후 재확인
```

### 선택 근거: 전면 구축과의 비교

| 구분 | 전면 구축 | 제언: 단계적 제공 |
|---|---|---|
| 도입 시점 | 지연 | 빠름 |
| 요구 반영 | 사후 | 지표·피드백 |
| 낭비 위험 | 큼 | 작음 |
