## 연관 키워드

- 테스트 커버리지, 문장 커버리지, 분기 커버리지, 조건 커버리지
- 수정 조건/결정 커버리지(MC/DC), 경로 커버리지, 품질 게이트, 커버리지 래칫

## Ⅰ. 테스트 커버리지의 개요

- 핵심 요약 : 테스트 커버리지는 요구·코드 구문·분기·조건·경로 등 정의된 대상 항목 중 시험으로 실행한 범위의 비율을 정량화한 측정 지표.
- 개념 : 요구 사항과 코드의 구문·분기·조건·경로 등 정의된 테스트 대상 항목 중 시험으로 실행한 범위의 비율을 정량화한 측정 지표(**테스트 커버리지**, Test Coverage).
- 배경 및 필요성 : 테스트 케이스 개수와 통과율만으로는 미실행 코드와 검증되지 않은 요구의 공백 파악이 어려워 충분성의 객관적 기준 필요.
- 주요 목적 : 검증 공백의 가시화, 테스트 충분성 판단 기준 마련, 잔여 위험 기반의 시험 완결 관리.

## Ⅱ. 테스트 커버리지의 특징 및 장점

- 핵심 요약 : 문장·분기·조건·MC/DC·경로의 단계적 기준이 미시험 구간 발견과 검증 강도 선택이라는 장점으로 연결.

1. **문장 커버리지** (구문 커버리지, Statement Coverage) : 코드의 각 문장이 최소 한 번 실행되도록 케이스 설계 → 미실행 코드의 즉시 발견.
2. **분기 커버리지** (결정 커버리지, Decision Coverage) : 결정문의 참·거짓 결과를 모두 실행 → 조건식 양방향 동작의 검증.
3. **조건 커버리지** (Condition Coverage) : 결정을 구성하는 개별 조건의 참·거짓을 각각 실행 → 복합 조건 내부의 부분 검증.
4. **수정 조건/결정 커버리지** (MC/DC, Modified Condition/Decision Coverage) : 각 조건이 결정 결과를 독립적으로 바꾸는 조합을 실행 → 안전 중요 소프트웨어의 강한 논리 검증.
5. 위험 기반 적용 : 안전·보안·업무 영향 등급에 따라 목표 기준을 차등 설정 → 검증 자원의 우선순위 집중.

## Ⅲ. 테스트 커버리지의 구조 (흐름)

- 핵심 요약 : 대상·기준 정의에서 품질 게이트 판정까지의 측정 절차와, 기초에서 강한 기준으로 올라가는 유형 계층의 이중 구조.
- 측정 절차 : 계측 도구로 시험을 실행해 실행·미실행 항목을 수집하고 비율로 산출한 뒤, 미달 항목 보완과 품질 게이트 판정으로 마무리.

```text
대상·기준 정의
   ↓
계측 도구로 시험 실행
   ↓
실행·미실행 항목 수집
   ↓
커버리지 비율 산출
   ↓
미달 항목 보완·재측정
   ↓
품질 게이트 판정
```

```text
문장 커버리지     (기초 기준)
   ↓ 강도 증가
분기 커버리지     (문장 기준 포함)
   ↓ 강도 증가
조건·MC/DC       (복합 논리 검증)
   ↓ 강도 증가
경로 커버리지     (이론적 상한 기준)
```

## Ⅳ. 테스트 커버리지와 수행 개수 중심 평가의 비교

- 핵심 요약 : 커버리지는 실행 범위의 비율로 공백을 특정하는 반면, 수행 개수 중심 평가는 케이스 개수만 세어 미검증 범위를 남긴다.

| 비교 축 | 테스트 커버리지 | 수행 개수 중심 평가 |
| --- | --- | --- |
| 측정 기준 | 정의된 대상 항목의 실행 비율 | 실행한 케이스 개수·통과율 |
| 공백 파악 | 미실행 문장·분기·조건의 특정 가능 | 미검증 범위 식별 불가 |
| 목표 설정 | 코드 구조·위험 등급에 연동된 목표 | 획일적 개수 목표 |
| 개선 방향 | 미커버 항목에 케이스 추가 | 케이스 수·시간의 양적 확대 |

- 유형 간 비교 : 상위 기준일수록 검증 강도가 강해지지만 비용이 커지는 상하 관계로 배열.

| 유형 | 측정 대상 | 확보 효과 |
| --- | --- | --- |
| 문장 커버리지 | 각 문장의 실행 여부 | 미실행 코드 제거 |
| 분기 커버리지 | 결정의 참·거짓 양방향 | 조건식 양방향 검증 |
| 조건 커버리지 | 개별 조건의 참·거짓 | 복합 조건의 부분 검증 |
| MC/DC | 조건의 독립적 결정 기여 | 안전 중요 논리의 강한 검증 |
| **경로 커버리지** (Path Coverage) | 실행 가능한 경로 전체 | 최강 기준, 조합 폭발로 실용성 제한 |

## Ⅴ. 테스트 커버리지의 한계와 방안

- 핵심 요약 : 허위 안도감·단언 없는 케이스·계측 누락·기준 임의화를 시험 병행·탐지력 검증·계측 검토·기준 문서화로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 허위 안도감 | 100% 달성해도 요구 의미·오라클 정확성·경로 조합 보장 없음 → 결함 유출 | 요구 기반·경계·탐색 시험 병행 | 커버리지와 결함 유출 추이 |
| 단언 없는 테스트 | 실행만 되고 결과 검증이 없는 케이스 누적 → 수치 상승, 탐지력 정체 | **단언**(assertion, 결과 판정 코드) 포함 여부 점검과 변이 테스트로 탐지력 검증 | 변이 생존율 |
| 비동기·예외 구간 미측정 | 콜백·예외 처리 경로의 계측 누락 → 커버리지 과대 평가 | 예외 경로 케이스 보완, 계측 범위 검토 | 예외 경로 커버리지 |
| 기준·제외의 임의화 | 제외·생성 코드 설정에 따른 수치 왜곡 → 신뢰 하락 | 대상·제외 기준 문서화와 독립 검토 | 제외 코드 비율 |

## Ⅵ. 테스트 커버리지 적용에 대한 기술사적 제언

- 핵심 요약 : 측정 체계 표준화·CI 품질 게이트·위험 연동 기준으로 커버리지를 상시 품질 통제 수단으로 내재화.
- 측정 체계 표준화 : 품질 보증 조직은 계측 도구·대상·제외 기준을 표준 문서로 통일해 수치의 비교 가능성 확보.
- CI 품질 게이트 : 개발 조직은 빌드 파이프라인에 커버리지 판정을 통합하고, 기준선 이하 반락을 차단하는 **커버리지 래칫**(기준선을 점진 상향시키며 낮추지 않는 운영 방식) 운영.
- 위험 연동 기준 : 안전·보안 중요 모듈에 MC/DC 수준, 일반 모듈에 분기 커버리지 수준의 차등 기준 체계 확립.

## Ⅶ. 결론

- 핵심 요약 : 테스트 커버리지는 시험이 다룬 범위를 보여주는 지표이지 무결함 증거가 아님.
- 유형별 기준의 강도를 위험 수준에 맞게 선택하고, 수치를 요구·결함 데이터와 함께 해석할 때 검증 충분성 확보.
