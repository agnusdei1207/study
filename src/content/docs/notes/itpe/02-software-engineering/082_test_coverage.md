## 연관 키워드
- 테스트 커버리지, 요구사항 커버리지, 문장·분기 커버리지, 조건 커버리지, MC/DC, 위험 기반 테스트

### Ⅰ. 테스트 커버리지의 개요

- 핵심 요약 : 테스트 커버리지는 요구·코드 구조·조건·경로 등 정의된 테스트 대상 항목 중 시험으로 실행·검증된 범위의 비율.
- 개념 : 요구·코드 구조·조건·경로 등 정의된 테스트 대상 항목 중 시험으로 실행·검증된 범위의 비율(**테스트 커버리지**, Test Coverage).
- 배경 및 필요성 : 테스트 수·통과율만 보면 미실행 요구·분기와 특정 입력 조건의 검증 누락을 파악하기 어려움.
- 주요 목적 : 검증 공백을 드러내고 테스트의 충분성을 위험·요구·안전 중요도에 맞춰 판단.

### Ⅱ. 테스트 커버리지의 특징 및 장점

- 핵심 요약 : 요구 커버리지·문장·분기 커버리지·조건·MC/DC(Modified Condition/Decision Coverage, 수정 조건·결정 커버리지)·위험 기반 해석.

1. 요구 커버리지 : 요구 사항 별 시험 케이스·결과 추적 → 기능 요구 검증 누락 확인.
2. 문장·분기 커버리지 : 실행 된 문장·결정 분기 비율 측정 → 구조 상 미 시험 코드 확인.
3. 조건·MC/DC : 조건의 독립적 결정 영향을 검증 → 안전 중요 결정 논리의 강한 검증 기준 지원.
4. 위험 기반 해석 : 안전·보안·업무 영향에 따라 목표와 보고 단위 결정 → 낮은 위험의 수치 목표 보다 실제 잔여 위험에 집중.

### Ⅲ. 테스트 커버리지의 구조 (흐름)

- 핵심 요약 : 커버리지 대상·기준 정의 → 시험 계획·추적 연결 → 도구 실행·결과 수집 → 미 커버리지 분석 → 위험·요구 별 보완 → 기준 선·예외 승인.

```text
커버리지 대상·기준 정의
   ↓
시험 계획·추적 연결
   ↓
도구 실행·결과 수집
   ↓
미 커버리지 분석
   ↓
위험·요구 별 보완
   ↓
기준 선·예외 승인
```

```text
요구 사항 커버리지: 요구 ↔ 테스트·결과
코드 구조 커버리지:
문장 → 분기 → 조건 → MC/DC
        ↓
미 커버리지 위험 검토·추가 시험
```

### Ⅳ. 테스트 커버리지 측정 방식 비교

- 핵심 요약 : 요구 커버리지는 요구 사항과 시험 케이스·결과를 연결, 문장 커버리지는 실행 된 코드 문장 비율.

| 비교 방법 | 주요 특성 | 적합한 적용 조건 |
|---|---|---|
| 요구 커버리지 | 요구 사항과 시험 케이스·결과 연결 | 기능·품질 요구의 검증 완전성 |
| 문장 커버리지 | 실행 된 코드 문장 비율 | 미 실행 코드 탐색, 논리 분기 보장은 안 됨 |
| 분기·조건 커버리지 | 결정 결과·조건 조합 실행 | 조건 복잡도와 위험에 맞춘 강한 구조 검증 |
| MC/DC | 각 조건이 결정 결과에 독립 영향 주는지 확인 | 항공·안전 중요 소프트웨어의 엄격한 논리 검증 필요 |

### Ⅴ. 테스트 커버리지의 한계와 방안

- 핵심 요약 : 커버리지 100% 과신·분모·제외 기준 임의화·위험 수준 무시를 결함 기반 시험·기준선 설정·위험 등급 별 커버리지로 관리.

| 위험 | 원인·영향 | 대응 통제 | 지표 예시 |
|---|---|---|---|
| 커버리지 100% 과신 | 모든 경로·요구 의미·오라클 정확성을 보장하지 않음 | 결함 기반·요구 기반·경계·탐색 시험 병행 | 커버리지와 결함 유출 추이 |
| 분모·제외 기준 임의화 | 수치가 도구·예외 설정에 따라 왜곡 | 대상·제외·생성 코드 기준 선과 독립 검토 | 제외율, 미분류 코드 |
| 위험 수준 무시 | 낮은 중요 코드 목표 달성에 과 투자 | 안전·보안·영향 등급 별 커버리지 기준 | 위험 별 잔여 미 커버리지 |

### Ⅵ. 테스트 커버리지 적용에 대한 기술사적 제언

- 핵심 요약 : 검증 공백을 드러내고 테스트의 충분성을 위험·요구·안전 중요도에 맞춰 판단.

- 실행 제언 : 테스트 책임자는 커버리지 수치를 요구·위험·독립 검증 증거와 함께 해석하고, 안전 중요 소프트웨어에는 적용 표준이 정한 기준을 확인해 예외·제외를 문서화.

### Ⅶ. 결론

- 핵심 요약 : 테스트 커버리지는 요구·코드 구조·조건·경로 등 정의된 테스트 대상 항목 중 시험으로 실행·검증된 범위의 비율.
- 시사점 : 커버리지는 시험이 다룬 범위를 보여주는 지표이지 무결함 증명이 아니며, 검증 충분성은 요구의 의미와 위험을 함께 평가해야 확보.
