## 연관 키워드
- 형상관리, 식별·변경통제·상태기록·감사, 베이스라인, CCB, GitOps, IaC

### Ⅰ. 형상관리의 개요

- 핵심 요약 : 형상관리는 제품 구성항목과 변경 이력을 통제해 승인 산출물의 무결성과 재현성을 보장.
- 개념 : 요구·설계·코드·환경 등 형상항목을 식별하고 기준선·변경을 관리하는 활동(**형상관리**, Configuration Management).
- 배경 및 필요성 : 병렬 개발·릴리스 과정에서 승인·배포된 버전과 구성을 추적해야 함.
- 주요 목적 : 변경 통제, 상태 가시성, 감사·복구 가능성 확보.

### Ⅱ. 형상관리의 특징 및 장점

- 핵심 요약 : 식별·변경통제·상태기록·감사로 형상 무결성과 릴리스 재현성을 확보.

1. 형상 식별 : 항목·버전·관계 정의 → 범위와 책임 명확화.
2. 변경 통제 : 영향분석·승인·구현·검증 → 무단 변경 방지.
3. 상태 기록 : 기준선·변경 상태 보고 → 추적과 판단 지원.
4. 형상 감사 : 승인·구성 일치 확인 → 누락·불일치 검출.

### Ⅲ. 베이스라인과 변경 흐름 (구조)

- 핵심 요약 : 승인된 기준선을 통제된 변경으로 갱신하고 산출물·환경 구성까지 연결.

```text
요구 기준선 → 설계 기준선 → 구현 기준선 → 제품·운영 기준선
변경요청 → 영향분석 → CCB 승인 → 구현·검증 → 상태기록
```

```text
변경 제안 → 관련 형상항목 식별 → 승인/거절 → 버전관리·빌드
                                          ↓
                            구성 감사·릴리스 태그·배포
```

- 현대 적용 : Git 태그·IaC(IaC, Infrastructure as Code)·GitOps 선언 상태를 승인된 변경 이력에 연결.

### Ⅳ. 형상관리와 버전관리 비교

- 핵심 요약 : 버전관리는 파일 이력 중심, 형상관리는 승인·관계·상태·감사까지 포괄.

| 비교 축 | 버전관리 | 형상관리 |
|---|---|---|
| 범위 | 파일·코드 리비전 | 제품 구성항목·기준선·환경 |
| 통제 | 변경 이력·병합 | 승인·상태기록·구성감사 |
| 관계 | Git 등이 핵심 도구 | 프로세스·저장소·책임 체계 전체 |

### Ⅴ. 형상관리의 한계와 방안

- 핵심 요약 : 과도한 승인과 불완전한 식별은 각각 전달 지연과 구성 누락을 유발.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 승인 병목 | 사소한 변경까지 지연 | 위험·영향도별 승인 등급 | 승인 대기 시간 |
| 항목 누락 | 배포 구성 재현 실패 | 코드·인프라·문서 범위 합의 | 누락 항목 수 |
| 장기 브랜치 | 병합 충돌·기준선 불일치 | 짧은 수명 브랜치·자동 검증 | 브랜치 수명 |

### Ⅵ. 형상관리 제언

- 핵심 요약 : CCB(Change Control Board)는 고위험 기준선 변경에 집중하고 일상 변경은 자동 정책으로 통제.

1. 형상관리자는 항목·소유자·기준선·상태보고 규칙을 수립.
2. 개발·운영팀은 코드와 IaC를 버전관리하고 승인된 파이프라인만 배포.
3. 감사자는 릴리스 아티팩트와 승인 기록의 일치성을 표본 검증.

### Ⅶ. 결론

- 핵심 요약 : 형상관리는 소스 저장이 아니라 승인된 제품 구성을 재현·감사하는 통제 체계.
- 시사점 : 자동화는 기준선·소유자·승인 규칙이 명확할 때 신뢰성을 높임.
