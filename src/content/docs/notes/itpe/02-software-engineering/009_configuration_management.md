## 연관 키워드

- 형상관리, 형상항목, 베이스라인(기준선), 형상 식별·형상 통제·형상 상태 기록·형상 감사
- 형상통제위원회(CCB), GitOps, 코드형 인프라(IaC)

## Ⅰ. 형상관리의 개요

- 핵심 요약 : 형상관리는 소프트웨어 구성과 변경 이력을 통제해 승인된 산출물의 무결성·재현성을 보장하는 체계.
- 개념 : 개발·운영 산출물과 환경을 관리 대상으로 정의하고 기준선 수립과 변경을 통제하는 활동(**형상관리**, Configuration Management), 관리 대상 항목을 **형상항목** (Configuration Item)이라 함.
- 배경 및 필요성 : 병렬 개발과 반복 릴리스 환경에서 무단 변경, 버전 불일치, 재현 불가능한 배포가 품질 사고로 이어지는 상황.
- 주요 목적 : 임의 변경의 차단과 이력 추적을 통한 신뢰성 있는 릴리스와 감사 가능성 확보.

## Ⅱ. 형상관리의 특징 및 장점

- 핵심 요약 : 식별·통제·상태 기록·감사의 네 활동이 형상 무결성과 릴리스 재현성이라는 장점으로 연결.

1. **형상 식별** (Configuration Identification) : 관리 대상 형상항목과 버전·관계를 정의 → 관리 범위와 책임의 명확화.
2. **형상 통제** (Configuration Control) : 변경 요청에 대한 영향 분석과 승인 절차 적용 → 무단 변경 방지 효과.
3. **형상 상태 기록** (Configuration Status Accounting) : 기준선과 변경 이력의 보고 → 현재 구성에 대한 가시성 확보.
4. **형상 감사** (Configuration Audit) : 승인 내용과 실제 구성의 일치 확인 → 누락·불일치의 조기 검출.

## Ⅲ. 형상관리의 구조 (흐름)

- 핵심 요약 : 단계별 승인으로 기준선을 수립하고 모든 변경은 심의를 거쳐 기준선 갱신으로 반영.
- **베이스라인** (Baseline) : 형상항목이 공식 승인된 시점의 기준, 이후 변경은 통제 절차를 통해서만 반영되는 기준선.
- **형상통제위원회** (CCB, Change Control Board) : 변경 요청을 심의해 승인·거절을 결정하는 기구.

```text
[ 베이스라인 수립 계층 ]

요구사항 기준선
   ↓ 검토·승인
설계 기준선
   ↓ 검토·승인
구현 기준선(코드·빌드)
   ↓ 시험·인수
제품·운영 기준선
```

```text
[ 변경 통제 흐름 ]

변경 요청 접수
   ↓
영향 분석
   ↓
CCB 심의(승인·거절)
   ↓ 승인 시
구현·검증
   ↓
기준선 갱신·상태 기록
```

- 현대적 적용 : **GitOps**(Git 저장소의 선언형 상태를 배포 기준으로 삼는 운영 방식)와 **코드형 인프라** (IaC, Infrastructure as Code)를 기준선 체계에 연결한 구성 통제.

## Ⅳ. 형상관리와 변경 관리의 비교

- 핵심 요약 : 변경 관리가 승인 절차의 판단에 집중하는 반면 형상관리는 대상 식별부터 구성 감사까지 전 생애를 포괄.
- **변경 관리** (Change Management) : 변경 요청의 승인·일정·영향을 결정하는 절차 중심의 관리 활동.

| 비교 축 | 형상관리 | 변경 관리 |
| --- | --- | --- |
| 관리 대상 | 형상항목·기준선·구성 관계 | 변경 요청과 승인 절차 |
| 핵심 질문 | 무엇이 어떤 구성인가 | 이 변경을 승인할 것인가 |
| 수행 활동 | 식별·통제·상태 기록·감사 | 요청·심의·승인·이행 지시 |
| 산출물 | 형상 목록·상태 보고·감사 결과 | 변경 기록·승인 결정 |
| 상호 보완 | 변경 결과를 형상으로 등록 | 형상 통제의 승인 수단 제공 |

## Ⅴ. 형상관리의 한계와 방안

- 핵심 요약 : 승인 병목·항목 누락·기준선 불일치를 등급화·자동화·짧은 브랜치 정책으로 완화.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 승인 병목 | 사소한 변경까지 CCB 심의 → 일정 지연 | 변경 위험도별 승인 등급 분리 | 평균 승인 소요 시간 |
| 형상항목 누락 | 코드 외 산출물·환경 미등록 → 배포 재현 실패 | 등록 범위 기준 수립·자동 스캔 | 미등록 항목 수 |
| 기준선 불일치 | 장기 브랜치·무단 변경 → 병합 충돌·감사 지적 | 짧은 수명 브랜치·**트렁크 기반 개발** (Trunk-Based Development) 지향 | 기준선 불일치 건수 |

## Ⅵ. 형상관리에 대한 제언

- 핵심 요약 : 형상관리를 개인·도구의 관행이 아닌 조직 표준 절차와 자동화 파이프라인의 결합 체계로 내재화 필요.

1. 개발조직은 형상관리 계획을 표준 절차로 제정하고 항목·소유자·기준선 규칙을 문서화.
2. 플랫폼 조직은 빌드·배포 파이프라인에 기준선 태그와 승인 이력 기록을 자동 연동.
3. 품질·감사 조직은 릴리스 산출물과 승인 기록의 일치성을 주기적 표본 검증.

## Ⅶ. 결론

- 핵심 요약 : 형상관리는 소스 저장 기능이 아니라 승인된 제품 구성을 재현·감사하는 통제 체계.
- 도구 도입에 앞서 항목·기준선·승인 규칙의 정의가 선행 필요.
