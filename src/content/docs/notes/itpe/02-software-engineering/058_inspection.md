소프트웨어 공학 → 품질·검증 → **인스펙션(Inspection)**

## 30초 인출

- 본질: 인스펙션은 정해진 역할과 절차에 따라 소프트웨어 산출물을 사람이 검토해 결함을 찾는 정적 검토 기법
- 메커니즘: 계획·개관·개인 준비를 거쳐 검토 회의에서 역할별로 결함을 식별하고, 저자가 재작업한 뒤 후속 확인으로 종료
- 통찰: 회의가 해결책 논의로 흘러 시간이 소모되므로 회의는 결함 식별에 한정하고 진입·종료 조건과 체크리스트로 종료를 판정

<details>
<summary>핵심 용어</summary>

- **인스펙션(Inspection)** : 정해진 역할·절차·체크리스트로 산출물의 결함을 찾는 형식적 동료 검토. Fagan 제안
- **정적 검토** : 코드를 실행하지 않고 산출물을 읽어 결함을 찾는 방식
- **중재자(Moderator)** : 인스펙션을 이끌고 회의를 결함 식별에 집중시키는 역할
- **진입·종료 조건(Entry·Exit Criteria)** : 인스펙션을 시작하기 위한 조건과 종료를 인정하는 조건
- **워크스루(Walkthrough)** : 저자가 산출물을 설명하며 검토받는 덜 형식적인 검토

</details>

## 2~4교시 25점 답안

## Ⅰ. 인스펙션의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **인스펙션** 은 정해진 역할과 절차로 산출물의 결함을 사람이 찾아내는 형식적 정적 검토 |
| 목적 | 시험 이전 단계의 결함 조기 발견 |

## Ⅱ. 인스펙션의 특징

| 특징 | 의미 |
|---|---|
| 형식적 절차 | 계획·준비·회의·재작업·후속 확인 |
| 역할 분담 | 중재자·저자·낭독자·기록자·검토자 |
| 결함 식별 중심 | 해결책 논의는 회의 밖에서 수행 |
| 체크리스트 사용 | 검토 기준의 표준화 |

## Ⅲ. 인스펙션 프로세스

### 인스펙션 프로세스

```text
계획 (대상·참여자·일정)
    ↓
개관 (저자의 개요 설명)
    ↓
준비 (검토자의 개인 검토)
    ↓
검토 회의 (결함 식별·기록)
    ↓
재작업 (저자의 수정)
    ↓
후속 조치 (수정 확인·종료 판정)
```

### 확대: 종료 판정

```text
후속 조치
    ├─ 종료 조건 충족 → 종료
    └─ 결함 다수·조건 미충족 → 재인스펙션
```

## Ⅳ. 정적 검토 유형의 비교

| 구분 | 인스펙션 | 워크스루 | 기술 검토 |
|---|---|---|---|
| 형식성 | 높음 | 낮음 | 중간 |
| 진행 | 중재자 | 저자 | 검토 리더 |
| 목적 | 결함 식별 | 이해 공유·의견 수렴 | 기술적 적합성 판단 |
| 기록 | 결함 목록·통계 | 의견 | 검토 결과 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 회의가 해결책 논의로 길어짐 | 중재자가 결함 식별로 한정하고 해결은 회의 밖 |
| 준비 부족으로 결함 발견 저조 | 개인 준비 시간과 체크리스트 제공 |
| 검토 대상이 커서 집중 저하 | 회의 시간·검토 분량 제한 |

## Ⅵ. 제언

진입 조건 충족 후 인스펙션을 시작하고, 종료 조건으로 재작업 완료를 판정하며 회의는 결함 식별에 한정

### 조건 기반 진행

```text
진입 조건 확인 → 인스펙션 수행
    ↓
결함 목록 → 저자 재작업
    ↓
종료 조건 확인 → 종료
```

### 확대: 결함 기록

```text
결함 기록: 위치·심각도·유형 → 재작업 확인 → 통계 활용
```

### 선택 근거: 비형식 검토와의 비교

| 구분 | 비형식 검토 | 제언: 조건 기반 인스펙션 |
|---|---|---|
| 시작·종료 | 불명확 | 조건으로 판정 |
| 결함 기록 | 일부 | 표준 기록 |
| 시간 | 논의로 소모 | 식별에 집중 |
