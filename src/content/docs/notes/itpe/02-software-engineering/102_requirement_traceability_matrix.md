## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 요구공학 → **요구사항 추적표(Requirement Traceability Matrix)**

## 30초 인출

- 본질: 요구사항 추적표(RTM)는 요구사항과 설계·구현·시험 산출물의 대응 관계를 표로 정리해 반영 여부와 변경 영향을 추적하는 도구
- 메커니즘: 요구사항 ID를 설계 요소·코드·시험 케이스와 연결하고 정방향(요구→산출물)과 역방향(산출물→요구)으로 추적해 누락과 불필요한 구현을 확인
- 통찰: 요구 변경 때 관련 산출물을 사람이 찾으면 누락되므로 요구 ID 단위로 산출물을 연결해 두고 변경 시 영향받는 설계·시험을 추적표로 일괄 확인

<details>
<summary>핵심 용어</summary>

- **요구사항 추적표(RTM, Requirements Traceability Matrix)** : 요구사항과 하위 산출물의 대응을 나타낸 표
- **정방향 추적성(Forward Traceability)** : 요구사항에서 설계·구현·시험으로 따라가며 반영 여부를 확인
- **역방향 추적성(Backward Traceability)** : 산출물에서 근거 요구사항을 따라가며 불필요한 구현을 확인
- **영향 분석(Impact Analysis)** : 변경이 미치는 산출물의 범위를 파악하는 활동
- **골드 플레이팅(Gold Plating)** : 요구에 없는 기능을 임의로 추가하는 것

</details>

## 2~4교시 25점 답안

## Ⅰ. 요구사항 추적표의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **요구사항 추적표** 는 요구사항과 설계·구현·시험 산출물의 대응 관계를 표로 정리한 도구 |
| 목적 | 요구 반영 여부의 확인과 변경 영향의 파악 |

## Ⅱ. 추적표의 특징

| 특징 | 의미 |
|---|---|
| ID 기반 연결 | 요구사항 고유 ID로 산출물 연결 |
| 양방향 추적 | 요구에서 산출물로, 산출물에서 요구로 |
| 전 생명주기 | 요구·설계·구현·시험 전반 |

## Ⅲ. 추적표의 구성과 활용 흐름

### 추적표 구성 예

```text
요구 ID │ 설계 요소 │ 구현 모듈 │ 시험 케이스 │ 상태
REQ-01  │ DES-03    │ MOD-A     │ TC-01, TC-02 │ 검증 완료
REQ-02  │ DES-05    │ MOD-B     │ (없음)       │ 시험 누락
```

### 확대: 추적 방향

```text
정방향: 요구 → 설계 → 구현 → 시험  (누락 확인)
역방향: 시험·코드 → 요구            (근거 없는 구현 확인)
```

## Ⅳ. 활용 목적별 정리

| 활용 | 내용 |
|---|---|
| 누락 확인 | 시험 케이스가 없는 요구 식별 |
| 영향 분석 | 요구 변경 시 관련 설계·시험 파악 |
| 범위 통제 | 근거 없는 기능(골드 플레이팅) 식별 |
| 검수 근거 | 요구 충족 증빙 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 수작업 갱신으로 최신성 저하 | 도구 연동과 변경 시 갱신을 절차화 |
| 요구 ID 부재로 연결 불가 | 요구사항에 고유 ID 부여 |
| 과도한 상세화로 관리 부담 | 핵심 요구 위주의 연결 수준 정의 |

## Ⅵ. 제언

요구사항마다 고유 ID를 부여해 산출물을 연결하고, 변경 요청 시 추적표로 영향받는 설계·시험을 확인한 뒤 일괄 수정

### 변경 시 활용

```text
변경 요청
    ↓
추적표로 영향 산출물 식별
    ↓
승인 후 일괄 수정·재시험
```

### 확대: 누락 점검

```text
릴리스 전 추적표 점검
    ├─ 시험 없는 요구 → 시험 케이스 작성
    └─ 요구 없는 구현 → 근거 확인·제거
```

### 선택 근거: 문서별 개별 관리와의 비교

| 구분 | 문서별 개별 관리 | 제언: ID 기반 추적 |
|---|---|---|
| 변경 영향 | 사람이 탐색 | 추적표로 식별 |
| 누락 발견 | 후반 | 릴리스 전 점검 |
| 근거 | 분산 | 요구 ID 기준 |
