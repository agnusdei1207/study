## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 개발 관리 → **개발방법론 테일러링**

## 30초 인출

- 본질: 개발방법론 테일러링은 조직의 표준 개발 방법론을 프로젝트의 특성에 맞게 활동과 산출물을 추가·생략·조정하는 활동
- 메커니즘: 프로젝트 특성을 내부 기준(규모·기간·인력)과 외부 기준(법규·고객 요구)으로 분석해 테일러링 대상 활동·산출물을 정하고 승인 후 프로젝트 기준선으로 확정
- 통찰: 표준 방법론을 그대로 쓰면 소규모에는 과잉이고 대규모에는 부족하므로 프로젝트 특성 기준으로 필수 활동을 유지하고 나머지를 조정하되 조정 근거를 승인받아 기록

<details>
<summary>핵심 용어</summary>

- **테일러링(Tailoring)** : 표준 방법론을 프로젝트 특성에 맞게 조정하는 활동
- **내부적 기준** : 프로젝트 규모·기간·복잡도·투입 인력의 역량처럼 프로젝트 내부 특성
- **외부적 기준** : 관련 법령·고객 요구·표준·계약 조건처럼 프로젝트 외부 요구
- **테일러링 매트릭스** : 활동·산출물별로 필수·선택·생략을 정리한 표
- **프로세스 기준선** : 승인된 테일러링 결과로 프로젝트 수행 중 기준이 되는 프로세스

</details>

## 2~4교시 25점 답안

## Ⅰ. 개발방법론 테일러링의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **개발방법론 테일러링** 은 표준 개발 방법론을 프로젝트 특성에 맞게 활동과 산출물을 조정하는 활동 |
| 목적 | 프로젝트에 맞는 개발 절차 확립과 불필요한 관리 비용 감소 |

## Ⅱ. 표준 방법론 그대로 적용과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 특성 기반 조정 | 프로젝트 규모·기간·법규에 따른 조정 |
| 필수 활동 유지 | 품질 확보에 필요한 활동은 유지 |
| 승인·기록 | 조정 결과는 승인 후 기준선으로 관리 |

## Ⅲ. 테일러링 절차와 기준

### 테일러링 절차

```text
프로젝트 특성 분석
    ↓
테일러링 기준 적용
    ├─ 내부 기준: 규모·기간·복잡도·인력
    └─ 외부 기준: 법규·고객 요구·계약
    ↓
활동·산출물 조정 (테일러링 매트릭스)
    ↓
승인 → 프로세스 기준선 확정
```

### 확대: 테일러링 매트릭스 판단

```text
공정별 활동·산출물
    ├─ 필수 (법규·품질 확보) → 유지
    ├─ 선택 (규모·위험에 따라) → 적용 여부 판단
    └─ 불필요 → 생략 (근거 기록)
```

## Ⅳ. 조정 기준별 사례

| 특성 | 조정 방향 |
|---|---|
| 소규모·단기 | 산출물 통합·간소화, 검토 절차 축소 |
| 대규모·복잡 | 관리·검증 활동 강화, 단계별 산출물 상세화 |
| 법규·감리 대상 | 법정 산출물·검토 활동 유지 |
| 요구 변동 큼 | 반복·점진 방식 활동 추가 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 조정 근거 없이 활동 생략으로 품질 저하 | 생략 사유와 대체 활동 기록·승인 |
| 필수 활동까지 생략 | 필수 활동 목록을 매트릭스에 고정 |
| 프로젝트 도중 특성 변화로 조정안 부적합 | 변경 시 재테일러링과 기준선 갱신 |

## Ⅵ. 제언

프로젝트 특성을 분석해 필수 활동은 유지하고 나머지만 조정하며, 조정 근거를 승인받아 프로세스 기준선으로 기록

### 조정 통제 순서

```text
필수 활동 목록 고정
    ↓
특성별 선택·생략 항목 조정
    ↓
근거 승인 → 기준선 기록
```

### 선택 근거: 표준 그대로 적용과의 비교

| 구분 | 표준 그대로 적용 | 제언: 근거 기반 테일러링 |
|---|---|---|
| 소규모 적용 | 과잉 관리 | 간소화 |
| 필수 활동 | 유지 | 유지 |
| 조정 근거 | 없음 | 승인·기록 |
