## 연관 키워드
- 소프트웨어 아키텍처, 4+1 뷰, ISO/IEC/IEEE 42010, ATAM, ADR

### Ⅰ. 소프트웨어 아키텍처의 개요

- 핵심 요약 : 소프트웨어 아키텍처는 시스템의 주요 구성요소·관계·환경과 설계원칙을 표현해 품질속성과 변화요구를 만족시키는 구조적 결정.
- 개념 : 시스템의 주요 구성요소·관계·환경과 설계원칙을 표현해 품질속성과 변화요구를 만족시키는 구조적 결정(**소프트웨어 아키텍처**, Software Architecture).
- 배경 및 필요성 : 초기 구조 결정은 성능·보안·변경성·비용에 장기 영향을 줌.
- 주요 목적 : 이해관계자 관심사에 부합하는 품질속성과 구현방향을 조정.

### Ⅱ. 소프트웨어 아키텍처의 특징 및 장점

- 핵심 요약 : ISO/IEC/IEEE 42010의 아키텍처 설명 관점, 4+1 뷰, ADD·ATAM·CBAM·ADR 등 분석·기록수단.

1. ISO/IEC/IEEE 42010 : 아키텍처 설명 관점 → 이해관계자 관심사에 부합하는 품질속성과 구현방향 조정.
2. 4+1 뷰 : 논리·개발·프로세스·물리·사용자 뷰 → 다중 관점에서 구조 표현.
3. ADD·ATAM·CBAM·ADR : 분석·기록수단 → 구조결정을 검증하고 원칙을 갱신.

### Ⅲ. 소프트웨어 아키텍처의 구조 (흐름)

- 핵심 요약 : 이해관계자·관심사 → 품질속성 시나리오 → 후보구조·뷰 설계 → 트레이드오프 평가 → 결정기록·구현·검증.

```text
이해관계자·관심사
  ↓
품질속성 시나리오
  ↓
후보구조·뷰 설계
  ↓
트레이드오프 평가
  ↓
결정기록·구현·검증
```

```text
관심사·품질시나리오 → 뷰·대안 → 트레이드오프 분석 → ADR → 검증
```

### Ⅳ. 상세설계와 소프트웨어 아키텍처 비교

- 핵심 요약 : 상세설계는 구성요소·알고리즘의 내부 구현, 소프트웨어 아키텍처는 시스템의 주요 구조·관계·품질속성 결정.

| 비교 축 | 상세설계 | 소프트웨어 아키텍처 |
|---|---|---|
| 결정범위 | 구성요소·알고리즘의 내부 구현 | 시스템의 주요 구조·관계·품질속성 결정 |
| 목적 | 구현 가능성 | 이해관계자 관심사와 품질속성 조정 |

### Ⅴ. 소프트웨어 아키텍처의 한계와 방안

- 핵심 요약 : 상아탑 구조·아키텍처 침식·트레이드오프 은폐를 이해관계자 조기검토·ADR·정기리뷰로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 상아탑 구조 | 실제 요구·운영제약과 설계 단절 | 개발·운영·보안 이해관계자 조기검토 | 아키텍처 변경률 |
| 아키텍처 침식 | 구현이 결정·원칙과 점차 불일치 | ADR·정적 규칙·의존성검사·정기리뷰 | 규칙 위반 |
| 트레이드오프 은폐 | 한 품질속성 최적화가 다른 속성 훼손 | 시나리오·근거·대안·결과 기록 | 미검토 품질위험 |

### Ⅵ. 소프트웨어 아키텍처에 대한 제언

- 핵심 요약 : 아키텍트는 품질속성 시나리오와 ADR을 통해 구조결정을 검증하고 운영피드백으로 원칙을 갱신.

1. 아키텍트는 품질속성 시나리오와 ADR을 통해 구조결정을 검증하고 운영피드백으로 원칙을 갱신.
2. 아키텍처 변경률·규칙 위반·미검토 품질위험를 정기 측정하고 편차에 대한 원인분석·개선결과를 기록.

### Ⅶ. 결론

- 핵심 요약 : 소프트웨어 아키텍처는 시스템의 주요 구성요소·관계·환경과 설계원칙을 표현해 품질속성과 변화요구를 만족시키는 구조적 결정.
- 시사점 : 아키텍처는 그림이 아니라 품질요구와 변경을 반영하는 중요한 설계결정의 집합.
