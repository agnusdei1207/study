## 연관 키워드

- 성능 시험, 부하 시험, 스트레스 시험, 스파이크 시험, 내구성 시험, 기준선, 백분위 응답 시간

## Ⅰ. 성능 시험의 개요

- 핵심 요약 : 성능 시험은 정의된 부하 조건에서 응답 시간·처리량·자원 사용이 성능 요구를 충족하는지 검증하는 비기능 시험.
- 개념 : 대표적인 사용자 부하와 데이터 조건에서 응답 시간·처리량·자원 사용률 등 비기능 요구를 측정·진단하는 검증 활동인 **성능 시험** (Performance Testing).
- 배경 및 필요성 : 기능이 정상이어도 동시 사용자·데이터 증가 시 지연·오류·자원 포화가 발생해 서비스 품질 저하·장애로 이어짐.
- 주요 목적 : 성능 요구 충족 확인, 용량 한계·확장성 파악, 병목 식별, 배포·용량 계획의 판단 근거 확보.

## Ⅱ. 성능 시험의 특징 및 장점

- 핵심 요약 : 부하 프로파일별 시험 유형이 목적에 맞는 품질 확인과 잠재 장애의 사전 발견으로 연결.

1. **부하 시험** (Load Testing) : 예상 운영 수준 부하에서 성능 목표 확인 → 일상 피크 조건의 용량 적합성 판정.
2. **스트레스 시험** (Stress Testing) : 한계를 넘는 부하로 포화·붕괴·복구 확인 → 임계점과 장애 시 동작 특성 파악.
3. **스파이크 시험** (Spike Testing) : 급격한 부하 상승·하락 반복 → 자동 확장·큐 적체·복귀 능력 확인.
4. **내구성 시험** (Endurance Testing) : 장시간 지속 부하 → 메모리 누수·자원 고갈 같은 시간 의존 결함 탐지.
5. 지표 체계 : 응답 시간 분포·처리량(TPS)·오류율·CPU·메모리·DB 커넥션 풀 사용률 → 사용자 체감과 자원 원인의 동시 관찰.

## Ⅲ. 성능 시험의 구조 (흐름)

- 핵심 요약 : 목표 정의부터 기준선 측정·단계 부하 인가·병목 분석·재시험까지 반복 흐름으로 수행.
- **기준선** (Baseline)은 개선 판단의 비교점이 되는 동일 조건 초기 측정값이며, 부하 발생기(load generator)가 가상 사용자 부하를 재현.

```text
성능 목표·합격 기준 정의
   ↓ 시나리오·데이터 모델링
기준선 측정 - 단일 사용자 조건
   ↓ 단계적 부하 인가
지표 관측 - 응답·처리량·자원
   ↓
병목 분석·튜닝 → 재시험 반복
```

```text
가상 사용자 증가
   ↓
처리량 상승 - 응답 시간 완만 증가
   ↓ 자원 포화 도달
처리량 정체 - 응답 급증·오류 발생
```

- 시험 데이터 분포, 캐시 워밍 상태, 배포 버전, 외부 연계 처리 방식을 기록해 재현성 확보.

## Ⅳ. 성능 시험과 기능 시험의 비교

- 핵심 요약 : 기능 시험이 정상 경로의 결과 일치를 검증하는 반면, 성능 시험은 부하 조건의 속도·안정성·자원을 검증.

| 비교 축 | 성능 시험 | 기능 시험 |
| --- | --- | --- |
| 검증 초점 | 부하 조건의 응답·처리량·자원 | 요구된 기능의 정상 동작 |
| 입력 조건 | 대규모 동시 가상 사용자·대용량 데이터 | 단일 사용자·경계 값 |
| 판정 기준 | 임계치·백분위 응답 시간 | 예상 결과와의 일치 |
| 관측 대상 | 서버·네트워크·DB 자원 지표 | 화면 출력·데이터 처리 결과 |
| 수행 환경 | 전용 부하 환경·운영 유사 구성 | 개발·통합 환경 |

## Ⅴ. 성능 시험의 한계와 방안

- 핵심 요약 : 환경 격차·부하 모델 오차·평균 착시·캐시 왜곡을 기록·보정·백분위 분석으로 통제 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 환경 격차 | 운영 대비 축소 구성의 결과 왜곡 | 구성 차이 기록·스케일 보정 | 환경 일치율 |
| 부하 모델 부정확 | 실제 사용 경로·분포 미반영 | 운영 로그 기반 시나리오 설계 | 시나리오 일치율 |
| 평균 응답 착시 | 소수 지연 요청의 은폐 | **백분위 응답 시간** (p95·p99)·오류율 병행 | p95·p99 응답 시간 |
| 캐시 왜곡 | 워밍업 없는 측정의 운영 단차 | 워밍업 절차·캐시 상태 기록 | 워밍업 준수율 |
| 운영 부하 유입 | 실시간 트래픽 영향 | 격리 환경·시험 시간 창·중단 기준 | 중단 기준 준수율 |

## Ⅵ. 성능 시험에 대한 기술사적 제언

- 핵심 요약 : 성능 거버넌스로 설계 단계 성능 예산과 배포 전후 지속 관측 체계의 확립 필요.
- 개발 조직은 성능 예산을 아키텍처 설계·코드 리뷰 기준에 반영하고, 지속적 통합(CI) 파이프라인에 핵심 시나리오의 성능 회귀 시험을 상시화.
- 운영 조직은 용량 계획·피크 대응 기준을 수립하고 실측 지표를 시험 목표에 되먹임해 목표의 현실성 유지.

## Ⅶ. 결론

- 핵심 요약 : 성능 시험은 부하 조건에서의 응답·처리량·자원 특성을 수치 근거로 확인하는 비기능 검증 활동.
- 대표 부하 모델·꼬리 지연·자원 포화의 함께 평가만이 용량 판단과 사용자 경험 신뢰의 조건.
