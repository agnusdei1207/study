 ┃

 ┣━ Ⅱ 특징 ───── 최단 경로 탐색 · 최고 우선 탐색(Best-First Search) · 평가 함수 $f(n) = g(n) + h(n)$ · 완결성 및 최적성 보장
 ┣━ Ⅲ 구조 ───── 시작점까지 실제 비용 $g(n)$ + 목표점까지 추정 휴리스틱 $h(n)$ + 열린 목록(Open List) + 닫힌 목록(Closed List)

 ┗━ Ⅵ 실무 ───── 허용성(Admissibility) 위반 시 최적 경로 실패 / 대규모 맵에서의 메모리 폭증 / 게임 길찾기 및 내비게이션 활용

## 한 줄 본질
- 다익스트라 알고리즘이 목적지의 위치를 고려하지 않고 모든 방향으로 동심원을 그리며 탐색하는 공간·시간 낭비 병목 → 목적지까지의 추정 거리(휴리스틱)를 평가 함수에 결합하여 목표 방향으로 최단 경로를 고속 탐색하는 알고리즘 / 메모리 사용량 급증 한계

## 핵심 그림
```text
+-------------------------------------------------------------------------+
|                  A* 알고리즘 평가 함수 $f(n) = g(n) + h(n)$             |
+-------------------------------------------------------------------------+
|                                                                         |
|      [ 시작 노드 S ] ──────── g(n) ────────> [ 현재 노드 n ]            |
|      (출발점에서 n까지 이미 이동한 실제 누적 비용)                      |
|                                                     :                   |
|                                                     : h(n)              |
|                                                     v (예측 휴리스틱)   |
|                                              [ 목표 노드 G ]            |
|                                                                         |
|  * 휴리스틱 핵심 조건: 허용성 (Admissibility)                           |
|    - $h(n) \le h^*(n)$ : 실제 최단 거리 $h^*(n)$보다 작거나 같아야 함 |
|    - 과소 추정(Underestimation)해야 최적의 최단 경로를 보장함           |
|    - $h(n) = 0$ 이면 다익스트라(Dijkstra)와 완전히 동일해짐             |
+-------------------------------------------------------------------------+
```

## 핵심 용어
- 허용성(Admissibility): 휴리스틱 함수 $h(n)$이 실제 목표 도달 비용 $h^*(n)$을 절대 과대평가(Overestimate)하지 않는 성질 ($h(n) \le h^*(n)$)
- 일관성(Consistency/Monotonicity): 노드 $n$과 인접 노드 $n'$ 사이에서 $h(n) \le c(n, n') + h(n')$을 만족하여 한 번 방문한 노드를 재탐색하지 않게 보장하는 성질

## 핵심 통찰
- 휴리스틱 $h(n)$의 설계가 알고리즘의 성능을 지배하며, 유클리드 거리(직선 거리)나 맨해튼 거리는 삼각 부등식을 만족하므로 대표적인 허용적·일관적 휴리스틱임
- $h(n)$ 값이 실제 비용에 가까울수록 탐색 영역이 직선 형태로 좁아져 성능이 비약적으로 향상되지만, 단 1이라도 실제 비용을 초과 추정하면 최단 경로가 아닌 차선의 경로를 선택하는 오류가 발생함
- 대규모 오픈월드 맵이나 고해상도 그리드에서는 Open List(우선순위 큐)에 보관되는 노드 수가 수백만 개로 폭증하여 메모리 부족(OOM)이 발생하므로, 직선 이동을 건너뛰는 JPS(Jump Point Search)나 계층적 맵(HPA*) 기법을 결합해야 함

## 이웃 토픽과 구분
- A* 알고리즘 vs 다익스트라(Dijkstra): 다익스트라 = 목적지 정보 없이 시작점 기준 모든 노드로의 최단 거리 계산 / A* = 목적지 방향을 가리키는 나침반($h(n)$)을 탑재하여 탐색 범위를 목적지 방향으로 집약

## 문제·원인·대책
- 적용 상황: 실시간 물류 로봇(AGV) 창고 내 최단 이동 경로 생성
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 창고 맵 크기가 커지자 A* 경로 탐색 시 메모리 초과로 제어 서버 다운 | 그리드의 모든 빈 칸을 Open List에 노드로 추가하여 상태 공간 지수 폭증 | 불필요한 대각선/직선 노드를 건너뛰는 점프 포인트 탐색(JPS) 적용 | 메모리 사용량 90% 절감 및 탐색 속도 10배 향상 |

## 이렇게 출제된다
- 제98회 1교시: "A* 알고리즘의 평가함수 $f(n) = g(n) + h(n)$의 의미와 최단 경로를 보장하기 위한 조건을 설명하시오." → 요구 포인트: $g(n)$과 $h(n)$의 의미 + 허용성($h \le h^*$) 및 일관성 조건
- 제90회 2교시: "최단 경로 탐색에서 다익스트라 알고리즘과 A* 알고리즘의 동작 원리를 비교 설명하시오." → 요구 포인트: 평가 함수 유무 비교 + 탐색 공간(원형 vs 지향성 타원형) 시각화 비교

## 내 의견
- [휴리스틱 설계 오류로 인한 최단 경로 붕괴 위험 통제] 계산 속도를 높이겠다고 휴리스틱 가중치($\epsilon > 1$)를 임의로 키우는 가중치 A*(Weighted A*)를 적용했다가 안전거리를 벗어나는 경로 오류 발생 → 나라면: 기본 경로 생성에는 엄격한 허용성 휴리스틱을 준수하여 최적성을 담보하고, 실시간 반응성이 필요한 게임/로봇 제어 구간에는 맵을 사전에 구역화(Hierarchical Pathfinding)하여 탐색 노드 수 자체를 원천적으로 줄이는 2계층 경로 탐색 구조 채택
