## 30초 인출

- 본질: AJAX는 페이지 전체를 다시 불러오지 않고 자바스크립트로 서버와 비동기로 데이터를 주고받아 화면 일부만 갱신하는 웹 기술
- 메커니즘: 자바스크립트가 XMLHttpRequest나 Fetch로 서버에 요청을 보내고 응답(JSON 등)을 받아 DOM의 필요한 부분만 바꿈
- 통찰: 비동기 요청은 응답이 요청 순서대로 도착한다는 보장이 없어 오래된 응답이 최신 화면을 덮어쓸 수 있으므로 요청에 식별자를 붙이거나 이전 요청을 취소해 최신 응답만 반영

<details>
<summary>핵심 용어</summary>

- **AJAX(Asynchronous JavaScript and XML)** : 비동기 통신으로 화면 일부를 갱신하는 웹 기술
- **XMLHttpRequest(XHR)** : 브라우저에서 서버로 HTTP 요청을 보내는 객체
- **Fetch API** : Promise 기반의 최신 HTTP 요청 API
- **동일 출처 정책(SOP)** : 다른 출처의 자원 접근을 제한하는 브라우저 정책
- **CORS(Cross-Origin Resource Sharing)** : 서버가 다른 출처의 접근을 허용하는 방법
- **경쟁 상태(Race Condition)** : 응답 도착 순서에 따라 결과가 달라지는 상태

</details>

## 2~4교시 25점 답안

## Ⅰ. AJAX의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **AJAX** 는 비동기 통신으로 페이지 전체를 다시 불러오지 않고 일부만 갱신하는 웹 기술 |
| 목적 | 빠른 화면 반응과 사용자 경험 향상 |

## Ⅱ. 기존 방식과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 비동기 통신 | 응답을 기다리는 동안 화면 조작 가능 |
| 부분 갱신 | 필요한 영역만 변경 |
| 데이터 교환 | JSON·XML로 데이터만 주고받음 |

## Ⅲ. 동작 흐름

```text
브라우저(사용자 이벤트)
   │ ① 자바스크립트가 비동기 요청 (XHR·Fetch)
   ▼
서버 ── ② 데이터(JSON) 응답
   │
   ▼
브라우저 ── ③ DOM의 해당 영역만 갱신 (페이지 유지)
```

## Ⅳ. 전체 갱신 방식과의 비교

| 구분 | 전통 방식 | AJAX |
|---|---|---|
| 요청 | 페이지 전체 | 필요한 데이터만 |
| 화면 | 전체 다시 그림 | 일부 갱신 |
| 트래픽 | 큼 | 작음 |
| 기타 | 단순 | 뒤로가기·북마크 처리 필요 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 응답 순서 뒤바뀜으로 오래된 응답이 최신 화면을 덮어씀 | 요청 식별자 확인이나 이전 요청 취소 |
| 다른 출처 접근 제한 | 서버의 CORS 설정 |
| 뒤로가기·북마크 불일치 | 브라우저 이력 API 사용 |

## Ⅵ. 제언

연속 요청은 최신 요청의 응답만 반영하도록 이전 요청을 취소하거나 식별자로 구분

```text
새 요청 시작
   ├─ 이전 요청 진행 중 → 취소
   └─ 응답 도착 → 최신 요청의 응답인지 확인 후 화면 반영
```

| 구분 | 순서 가정 | 제언: 최신 응답만 반영 |
|---|---|---|
| 응답 뒤바뀜 | 오래된 화면 표시 | 방지 |
| 구현 | 단순 | 취소·식별자 필요 |
