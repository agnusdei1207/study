## 연관 키워드

- AJAX, XMLHttpRequest, Fetch API, 비동기 통신, DOM, JSON

## Ⅰ. AJAX의 개요

- 핵심 요약 : AJAX는 브라우저가 페이지 전체를 다시 불러오지 않고 서버와 비동기 데이터 통신을 수행하는 웹 개발 방식.
- 개념 : **AJAX**(Asynchronous JavaScript and XML)는 JavaScript의 비동기 요청·응답으로 화면 일부를 갱신하는 기법이며 데이터 형식은 XML에 한정되지 않고 JSON도 흔히 사용.
- 배경 및 필요성 : 전체 문서 재전송에 따른 지연과 불필요한 네트워크 사용을 줄이기 위한 요구.
- 주요 목적 : 사용자 상호작용을 유지하면서 필요한 데이터와 화면만 갱신.

## Ⅱ. AJAX의 특징 및 장점

- 핵심 요약 : 비동기 요청·부분 갱신·표현과 데이터 분리로 응답성과 대역폭 효율을 높이는 브라우저 통신 방식.

1. 비동기 요청 : 응답 대기 중에도 브라우저 상호작용 가능 → 지각 대기시간 감소.
2. 데이터 중심 응답 : JSON 등 필요한 데이터만 전달 → 전체 HTML 재전송 감소.
3. 부분 렌더링 : DOM 또는 프레임워크 상태 갱신 → 화면의 관련 영역만 업데이트.

## Ⅲ. AJAX의 구조 (흐름)

- 핵심 요약 : 사용자 이벤트에서 요청 생성·전송·서버 처리·응답 검증을 거쳐 화면 상태 갱신.

```text
사용자 이벤트
  ↓
JavaScript 비동기 요청(Fetch/XHR)
  ↓
서버 API 처리·JSON 응답
  ↓
상태·오류 검증
  ↓
DOM 또는 UI 상태 부분 갱신
```

- 주요 구성 : Promise 기반 Fetch API는 HTTP 오류 상태를 직접 확인해야 하며, XMLHttpRequest는 이벤트 기반 상태·진행률 처리가 가능.

```text
브라우저 UI ↔ 비동기 요청 ↔ HTTP API
     ↑                         ↓
화면 상태 갱신 ← 응답·오류 처리 ← 데이터(JSON 등)
```

## Ⅳ. AJAX와 전통적 페이지 요청의 비교

- 핵심 요약 : AJAX는 데이터 중심 부분 갱신, 전통적 요청은 서버가 만든 문서 전체를 다시 탐색·렌더링.

| 비교 기준 | AJAX 요청 | 전통적 페이지 요청 |
| --- | --- | --- |
| 응답 범위 | 필요한 데이터·일부 UI 갱신 | 전체 HTML 문서 재수신 |
| 사용자 경험 | 상태 유지·비동기 상호작용 | 페이지 전환·새로고침 발생 |
| 구현 고려 | 상태·오류·접근성·히스토리 관리 | 서버 렌더링 중심의 단순한 흐름 |

## Ⅴ. AJAX의 한계와 방안

- 핵심 요약 : 비동기 상태·브라우저 보안·검색·접근성 문제를 API와 UI 설계에서 함께 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 상태·오류 복잡성 | 요청 경쟁·실패·재시도 시 화면 불일치 | 취소·타임아웃·로딩·오류 상태를 명시적으로 관리 | 실패율·중복 요청률 |
| 보안 경계 | CORS·인증·CSRF 정책 오구성 | 허용 Origin 최소화, 쿠키 인증 시 CSRF 방어, 서버 권한검사 | 차단 요청·취약점 건수 |
| 접근성·검색·히스토리 | 클라이언트 렌더링으로 콘텐츠·URL 갱신 누락 | 의미 있는 URL·포커스 알림·SSR/사전 렌더링 검토 | 접근성 오류·색인 가능 페이지 |

## Ⅵ. AJAX의 제언

- 핵심 요약 : 프런트엔드·API 담당자는 비동기 상태와 보안 계약을 표준화하고 서버 권한 검증을 기준으로 운영.

1. API 설계자는 상태코드·오류 스키마·페이지네이션·멱등성 기준을 공통화.
2. 프런트엔드 팀은 요청 취소, 중복 방지, 재시도 가능 여부를 화면 상태 모델에 반영.
3. 보안 담당자는 CORS·인증·CSRF와 민감정보 노출을 배포 전 점검.

## Ⅶ. AJAX의 결론

- 핵심 요약 : AJAX는 웹 페이지의 전체 재탐색 없이 서버 데이터를 비동기로 교환하는 상호작용 패턴.
- 시사점 : 반응성의 이점은 정확한 상태관리·접근성·보안 경계가 갖춰질 때 사용자 가치로 전환.
