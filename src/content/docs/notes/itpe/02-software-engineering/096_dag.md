## 연관 키워드

- DAG(Directed Acyclic Graph), 방향성 비순환 그래프, 위상 정렬, 진입 차수
- Kahn 알고리즘, 의존성 관리, 사이클 탐지

## Ⅰ. DAG의 개요

- 핵심 요약 : DAG는 방향 간선과 순환 부재를 갖춰 의존 관계·실행 순서를 표현하는 그래프 구조.
- 개념 : 간선에 방향이 있으면서 같은 정점으로 되돌아오는 순환이 없는 그래프 (**DAG** (Directed Acyclic Graph), 방향성 비순환 그래프).
- 배경 및 필요성 : 빌드·배포·데이터 처리에서 작업 간 선행 관계가 존재하고, 순환 의존은 실행 순서 산출 자체를 불가능하게 하는 상태.
- 주요 목적 : 의존성 관리의 정합 검증, 실행 순서 도출, 병렬 실행 기회 식별을 통한 파이프라인·워크플로의 안정 운영.

## Ⅱ. DAG의 특징 및 장점

- 핵심 요약 : 순환 부재가 위상 정렬·병렬화·영향 분석의 근거가 되는 구조.

1. 순환 부재 보장 : 사이클이 없는 구조 → 모든 의존 관계가 선행·후행으로 정리, 실행 불능 의존의 원천 차단.
2. 위상 정렬 가능성 : **위상 정렬** (topological sort, 선후 관계를 모두 만족하는 선형 순서 도출)의 존재 → 작업 수행 순서의 유한 도출.
3. 진입 차수 기반 병렬화 : **진입 차수** (in-degree, 정점으로 들어오는 간선 수)가 0인 작업은 즉시 실행 가능 → 독립 작업의 동시 처리 효과.
4. 역방향 영향 분석 : 후속 정점 추적으로 변경 영향·임계 경로 파악 → 재실행 범위 최소화.

## Ⅲ. DAG의 위상 정렬 흐름

- 핵심 요약 : 진입 차수 0인 정점을 반복 제거하는 **Kahn 알고리즘** (진입 차수 0 정점을 순서대로 제거해 위상 순서를 만드는 방법)이 대표 절차.

```text
[ Kahn 알고리즘 ]

전 정점의 진입 차수 계산
   ↓
진입 차수 0 정점 → 큐 삽입
   ↓
정점 출력·후속 간선 제거
   ↓
후속 정점 진입 차수 감소
   ↓
0이 되면 큐 삽입(반복)
   ↓
출력 수 < 전체 정점 수 → 순환 존재
```

```text
[ DAG 예시 ]

A ──→ C ←── B
       ↓
       D

위상 순서 예 : A → B → C → D
(A·B는 상호 선후 관계 없음 → 병렬 가능)
```

- 응용 : 빌드 의존성, 워크플로 실행기, 데이터 파이프라인, 패키지 관리자의 의존성 해석.

## Ⅳ. DAG와 일반 방향성 그래프의 비교

- 핵심 요약 : DAG는 비순환 제약으로 실행 순서 산출에 적합, 일반 방향성 그래프는 순환 포함 관계 표현에 적합이라는 차이.

| 비교 축 | DAG | 일반 방향성 그래프 |
|---|---|---|
| 순환 허용 | 비순환 구조만 허용 | 순환 포함 가능 |
| 위상 정렬 | 항상 존재 | 순환 존재 시 불가능 |
| 의존성 해석 | 선행·후행 관계의 명확한 정리 | 상호 의존·순환 상태 표현 |
| 실행 순서 산출 | 작업 스케줄링·병렬화에 적합 | 순환 관계의 일반 모델링에 적합 |
| 대표 활용 | 빌드·워크플로·데이터 파이프라인 | 상태 전이·네트워크 경로·순환 관계 |
| 선택 기준 | 의존 기반 실행 자동화 대상 | 순환 관계 자체가 분석 대상일 때 |

## Ⅴ. DAG 활용의 한계와 방안

- 핵심 요약 : 순환 의존·그래프 규모 비용·부분 실패를 사이클 검증·계층 분할·실패 격리로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 순환 의존 발생 | 설계 오류·요구 충돌 → 실행 순서 부재 | **사이클 탐지** (순환 경로·강결합 성분 검출)·의존 분리 | 사이클 발견 건수 |
| 그래프 규모 비용 | 정점·간선 급증 → 탐색·저장 부담 | 인접 리스트·계층 분할·증분 갱신 | 탐색 시간 |
| 부분 실패 전파 | 후속 작업 오염 → 전체 재실행 비용 | 체크포인트·멱등 재시도·실패 격리 | 재실행 작업 수 |

## Ⅵ. DAG 기반 실행 체계에 대한 기술사적 제언

- 핵심 요약 : 플랫폼 조직·개발 표준·운영 정례의 체계로 DAG 기반 자동화의 정합성 확보.

- 플랫폼 조직 : 워크플로 실행기에 의존성 계약·사이클 검증·실패 정책을 내장한 실행 체계 구축.
- 개발 표준 : 의존성 선언 위치·버전 관리 규칙의 개발 표준 통일.
- 운영 정례 : 변경 시 영향 그래프 갱신과 병목 정점 분석의 정례화.

## Ⅶ. 결론

- 핵심 요약 : DAG는 순환 없는 의존 구조로 실행 순서·병렬화·영향 분석을 지원하는 그래프 기반 구조.
- 대규모 자동화의 정확성은 사이클 방지와 실패 격리 정책에 좌우.
