## 연관 키워드

- SW 안전 진단, 위험 기반 점검, FMEA, FTA, SPOF
- 정적 분석, 추적성, 시정 조치

## Ⅰ. SW 안전 진단의 개요

- 핵심 요약 : SW 안전 진단은 소프트웨어의 안전 요구·위험 통제 충족 여부를 절차·기준에 따라 점검·판정하는 평가 활동.
- 개념 : 안전 요구·규제·표준과 설계·구현·시험 결과의 일치 여부를 독립적 절차와 판정 기준으로 점검하는 체계적 평가 활동 (**SW 안전 진단**).
- 배경 및 필요성 : 기능 중심 시험만으로는 고장 시 인명·자산 피해로 이어질 수 있는 안전 요구의 누락이 발견되지 않는 상태 발생. 안전성 보증에 대한 사회적·규제 요구 증가.
- 주요 목적 : 안전 요구—설계—구현—시험 간 추적성 확보, 위험 통제 공백의 조기 발견, 잔존 위험의 투명한 관리.

## Ⅱ. SW 안전 진단의 특징 및 장점

- 핵심 요약 : 위험 기반 점검·독립성·다층 증거·추적성 판정이 신뢰할 수 있는 안전 판정으로 이어짐.

1. 위험 기반 점검 : 고장의 심각도·발생 가능성에 따라 점검 범위·깊이 결정 → 고위험 통제의 집중 점검 효과.
2. 독립성 : 개발 조직과 별개의 진단 수행 → 자기 평가 한계의 보완.
3. 다층 증거 점검 : 안전 분석·설계·코드·시험 증거의 교차 확인 → 단일 증거 의존에 따른 누락 방지.
4. 추적성 판정 : 위험 → 안전 요구 → 설계 → 시험의 연결 검토 → 누락·불일치의 조기 식별.

## Ⅲ. SW 안전 진단의 절차 (흐름)

- 핵심 요약 : 계획 수립 → 증거 수집 → 점검 수행 → 판정 → 보고·시정·재검증의 5단계 절차.
- 점검 기준 : 요구 추적성, 위험 분석 문서, **SPOF** (Single Point of Failure, 단일 고장점) 존재 여부, 안전 기능 시험 증거의 충족 수준.

```text
[ SW 안전 진단 절차 ]

진단 계획(범위·기준·독립성)
   ↓
증거 수집(요구·설계·시험)
   ↓
점검 수행
(추적성·정적 분석·시험 검토)
   ↓
지적 사항·위험 등급 판정
   ↓
시정 조치 → 재검증 → 종결
```

```text
[ 점검 기법의 조합 ]

위험 분석 : FMEA·FTA
   +
정적 검증 : 소스 코드 분석
   +
동적 검증 : 안전 기능 시험
```

- 대표 기법 : **FMEA** (Failure Mode and Effects Analysis, 고장 유형·영향 분석) — 구성 요소별 고장 유형과 영향의 체계적 분석. **FTA** (Fault Tree Analysis, 고장 나무 분석) — 상위 사건을 원인 사건의 논리 결합으로 전개. **정적 분석** — 실행 없이 소스 코드의 위험 요소 검출.

## Ⅳ. SW 안전 진단과 시험 중심 품질 평가의 비교

- 핵심 요약 : 안전 진단은 위험·안전 요구 전반의 판정, 시험 중심 품질 평가는 기능 동작·결함 검출 중심이라는 차이.

| 비교 축 | SW 안전 진단 | 시험 중심 품질 평가 |
|---|---|---|
| 평가 관점 | 고장 영향·위험 감소 중심 | 기능 정상 동작·결함 검출 중심 |
| 대상 범위 | 위험 분석·안전 요구·설계·시험 전체 | 요구 기능의 시험 결과 |
| 점검 기법 | FMEA·FTA·추적성 검토·안전 시험 | 단위·통합·시스템 시험 |
| 판정 산출 | 위험 등급·시정 과제·잔존 위험 | 결함 수·시험 통과율 |
| 안전 기준 | 위험 등급별 출시 판단 연계 | 안전성 특수 기준 미포함 |
| 선택 기준 | 인명·자산 영향 시스템일 때 | 일반 기능 품질 확인 목적일 때 |

## Ⅴ. SW 안전 진단의 한계와 방안

- 핵심 요약 : 안전 지식 부족·증거 미비·시정 이행 부진을 공동 진단·증거 보완·이행 통제로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 안전 도메인 지식 부족 | 위험 시나리오 오류·누락 → 진단 신뢰 저하 | 안전·운영 전문가 공동 진단 체계 | 전문가 참여율 |
| 레거시 증거 부족 | 요구·시험 추적 공백 → 판정 근거 미달 | 코드·장애 이력 보완, 잔존 위험 명시 | 증거 미비 항목 수 |
| 시정 이행 부진 | 지적 반복·위험 잔존 | 책임자·기한·재검증 조건 부여 | 미종결 지적 건수 |

## Ⅵ. 안전 진단 거버넌스에 대한 기술사적 제언

- 핵심 요약 : 진단 독립성·상향 보고·기준 갱신의 거버넌스 체계로 진단을 조직의 상시 제도로 정착.

- 진단 거버넌스 : 진단 조직의 독립성·이해 상충 통제 기준을 제도화.
- 상향 보고 체계 : 고위험 지적 사항을 출시·운영 의사결정 기구에 연계.
- 기준 갱신 : 표준·규제 개정에 맞춘 진단 기준·체크리스트의 주기 갱신.

## Ⅶ. 결론

- 핵심 요약 : SW 안전 진단은 위험 관점에서 안전 요구와 구현·시험·운영의 일치를 검증하는 활동.
- 진단의 가치는 지적 건수가 아니라 중대 위험의 시정·재검증 완결에 있음.
