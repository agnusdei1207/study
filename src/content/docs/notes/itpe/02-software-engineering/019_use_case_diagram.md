## 연관 키워드
- 유스케이스, 액터, 시스템 경계, include, extend, 일반화, 기본·대안 흐름

### Ⅰ. 유스케이스 모델의 개요

- 핵심 요약 : 유스케이스 모델은 외부 액터가 시스템을 이용해 달성하는 목표와 상호작용 범위를 표현.
- 개념 : 유스케이스 다이어그램은 액터·시스템 경계·목표·관계를 보여주며 명세서는 시나리오와 예외 흐름을 상세화(**유스케이스**, Use Case).
- 배경 및 필요성 : 기능 목록만으로 사용자 목적, 범위, 예외 조건이 모호해질 수 있음.
- 주요 목적 : 이해관계자와 기능 요구·시스템 경계를 합의하고 분석·시험의 추적 기준 제공.

### Ⅱ. 유스케이스 모델의 특징 및 장점

- 핵심 요약 : 사용자 목표 중심의 기능 범위를 시각화하고 명세·시험과 연결.

1. 액터 관점 : 사람·외부 시스템 등 시스템 외부 역할 식별 → 경계와 연계 명확화.
2. 목표 중심 : 사용자 가치 단위 기능 묶음 표현 → 요구 우선순위·수용시험 기반.
3. 시나리오 명세 : 사전조건·기본흐름·대안·예외·사후조건 → 기능 동작 검증 가능.

### Ⅲ. 관계와 명세 흐름 (구조)

- 핵심 요약 : 액터와 유스케이스를 시스템 경계 안에 배치하고 관계는 재사용·조건부 흐름일 때만 사용.

```text
액터 ─── (주문 생성)
          ├─ «include» 결제 승인(항상 포함되는 공통 하위 기능)
          └─ «extend» 쿠폰 적용(조건이 충족될 때 선택적으로 확장)
```

```text
목표·액터 식별 → 시스템 경계 확정 → 유스케이스 도출
    → 기본·대안·예외 흐름 명세 → 요구·테스트와 추적
```

- 관계 의미 : association은 참여 연결, include는 항상 재사용되는 필수 포함, extend는 조건부 확장, generalization은 행위자·유스케이스의 상속적 특수화.

### Ⅳ. 유스케이스 다이어그램과 명세서 비교

- 핵심 요약 : 다이어그램은 범위·관계 개관, 명세서는 시나리오별 입력·응답·예외를 상세화.

| 비교 축 | 다이어그램 | 명세서 |
|---|---|---|
| 표현 | 액터·목표·경계·관계 | 사전·사후조건, 기본·대안·예외 흐름 |
| 장점 | 이해관계자 간 범위 합의 | 구현·시험 가능한 행위 정의 |
| 한계 | 업무규칙·예외 세부 생략 | 문서량 증가·변경 동기화 필요 |

### Ⅴ. 유스케이스 모델의 한계와 방안

- 핵심 요약 : include·extend 남용과 비기능 요구 누락을 관계 규칙·보조 명세로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 기능 분해 과도 | 다이어그램 복잡·목표 흐림 | 사용자 목표 수준으로 묶고 세부는 명세로 관리 | 유스케이스 수 |
| include·extend 오용 | 흐름 의존관계 혼란 | 항상 포함·조건부 확장 의미를 기준으로 리뷰 | 관계 남용 건수 |
| 품질속성 누락 | 성능·보안·가용성 시험 누락 | 품질요구·제약을 별도 요구와 시나리오로 연결 | 품질 요구 연결률 |

### Ⅵ. 유스케이스 적용 제언

- 핵심 요약 : 분석가는 액터의 목표를 업무 시나리오로 확인하고 각 흐름을 수용기준·시험사례와 연결.

1. 현업 담당자는 액터가 얻는 결과와 시스템 책임 경계를 승인.
2. 분석가·설계자는 기본·대안·예외 흐름과 관련 규칙을 명세서에 기록.
3. QA는 유스케이스별 정상·예외 시나리오를 인수·회귀시험에 추적.

### Ⅶ. 결론

- 핵심 요약 : 유스케이스 다이어그램과 명세서는 기능 범위 합의부터 수용시험까지 이어지는 요구 모델.
- 시사점 : 다이어그램의 간결성과 시나리오의 검증 가능성을 함께 유지해야 함.
