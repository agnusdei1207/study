## 연관 키워드

- 시퀀스 다이어그램(순차 다이어그램), UML 상호작용 다이어그램, 생명선
- 메시지(동기·비동기·응답), 활성화, 복합 단편, 커뮤니케이션 다이어그램

## Ⅰ. 시퀀스 다이어그램의 개요

- 핵심 요약 : 객체 간 메시지 교환을 위에서 아래로의 시간 흐름에 따라 표현하는 상호작용 다이어그램.
- 개념 : **통합 모델링 언어**(UML, Unified Modeling Language)의 상호작용 다이어그램으로, 참여 객체와 메시지를 시간 순서에 따라 표현하는 **시퀀스 다이어그램**(Sequence Diagram, 순차 다이어그램).
- 배경 및 필요성 : 기능 명세만으로는 객체 간 호출 순서·응답·예외 흐름이 확정되지 않아 개발자마다 구현이 달라지는 문제 발생.
- 주요 목적 : 시나리오 단위의 객체 협력과 인터페이스 계약을 명확히 해 설계 합의 비용과 통합 오류 감소.

## Ⅱ. 시퀀스 다이어그램의 특징 및 장점

- 핵심 요약 : 생명선·메시지·활성화·복합 단편이 시간 순서 중심의 상호작용 표현을 완성하는 요소.

1. **생명선**(Lifeline) : 참여 객체를 상단 표기와 세로 점선으로 표시 → 상호작용 주체와 시간축의 구분.
2. **메시지**(Message) : **동기 메시지**(응답까지 대기하는 호출)·**비동기 메시지**(즉시 제어를 반환하는 전송)·**응답 메시지**(처리 결과의 반환)를 화살표 형태로 구분 표기 → 호출 순서와 인터페이스의 명세화.
3. **활성화**(Activation) : 객체가 작업을 수행하는 구간을 생명선 위의 직사각형으로 표시 → 처리 중 상태와 중첩 호출의 표현.
4. **복합 단편**(Combined Fragment) : alt(대안)·opt(선택)·loop(반복)·par(병렬) 프레임으로 조건·반복·병렬 흐름 표현 → 예외·대안 시나리오까지의 모델링.

## Ⅲ. 시퀀스 다이어그램의 구조 (흐름)

- 핵심 요약 : 시나리오 정의부터 메시지 전개·보강·검토까지 이어지는 작성 절차와 생명선 기반의 메시지 흐름 표현.

```text
시나리오·참여자 정의
   ↓
생명선 배치
   ↓
메시지 순서 전개
   ↓
활성화 구간 표시
   ↓
복합 단편으로 예외·반복 보강
   ↓
인터페이스·요구와 대조 검토
```

```text
사용자      시스템      저장소
   |           |           |
   | 주문 요청  |           |
   |---------->| 재고 조회  |
   |           |---------->|
   |           |<-재고 확인-|
   |<-주문 접수-|           |
```

## Ⅳ. 시퀀스 다이어그램과 커뮤니케이션 다이어그램의 비교

- 핵심 요약 : 시퀀스 다이어그램이 시간 순서를 강조하는 데 비해, **커뮤니케이션 다이어그램**(Communication Diagram, 객체 간 연결과 메시지 번호로 협력을 표현하는 상호작용 다이어그램)은 객체 구조를 강조.

| 비교 축 | 시퀀스 다이어그램 | 커뮤니케이션 다이어그램 |
| --- | --- | --- |
| 강조점 | 메시지의 시간 순서 | 객체 간 연결 구조 |
| 표현 방식 | 생명선·수직 시간축 | 객체 노드·링크·번호 |
| 순서 표기 | 배치 위치로 표현 | 번호(1, 1.1)로 표현 |
| 적합 용도 | 시나리오·인터페이스 상세 설계 | 협력 구조의 요약·검토 |
| 조건·병렬 | 복합 단편으로 표현 | 번호 체계만으로는 표현 한계 |

## Ⅴ. 시퀀스 다이어그램의 한계와 방안

- 핵심 요약 : 과도한 상세화·모델 진부화·예외 흐름 누락·책임 집중을 범위 합의·갱신 의무화·대안 표기·책임 검토로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 과도한 상세화 | 모든 호출·속성 표기 → 가독성·유지 보수 저하 | 핵심 시나리오 중심 범위 합의 | 다이어그램 규모 기준 초과 |
| 모델 진부화 | 코드 변경 미반영 → 문서 신뢰 상실 | 설계 변경 절차에 갱신 의무화·도구 자동 생성 | 모델-코드 불일치 발견 수 |
| 예외 흐름 누락 | 정상 경로만 표기 → 오류 처리 미정의 | 실패·타임아웃·취소를 복합 단편으로 표기 | 미정의 예외 경로 수 |
| 책임 집중 | 특정 객체에 호출 집중 → 결합도 증가 | 참여자별 책임·호출 소유자 검토 | 인터페이스 변경 빈도 |

## Ⅵ. 시퀀스 다이어그램 적용에 대한 기술사적 제언

- 핵심 요약 : 핵심 시나리오 중심의 표준 템플릿과 모델-코드 동기화 체계로 설계 소통 도구화 필요.
- 아키텍처 조직 : 사용자 시나리오·API(Application Programming Interface) 계약에서 다이어그램을 도출하는 표준 템플릿과 작성 수준 기준을 정함.
- 개발 조직 : 모델링 도구와 코드 저장소의 연동으로 변경 시 갱신을 자동화.
- 품질 조직 : 정상 경로 외 오류·타임아웃·비동기 처리 검토를 설계 리뷰 체크리스트에 포함.

## Ⅶ. 결론

- 핵심 요약 : 시퀀스 다이어그램은 기능 요구를 객체 간 메시지 계약으로 구체화하는 UML 모델임.
- 시간 순서와 예외 흐름의 명확성이 설계 합의와 구현 일관성의 기반.
