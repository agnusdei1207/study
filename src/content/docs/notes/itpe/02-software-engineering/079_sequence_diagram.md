## 연관 키워드
- 순차 다이어그램, UML(Unified Modeling Language), 생명선, 메시지, 활성화, 조합 프래그먼트, 시간 순서

### Ⅰ. 순차 다이어그램의 개요

- 핵심 요약 : 순차 다이어그램은 UML(Unified Modeling Language) 상호 작용 다이어그램으로 참여 객체와 메시지를 시간 순서대로 표현해 시나리오의 협력·호출 흐름을 나타냄.
- 개념 : UML(Unified Modeling Language) 상호 작용 다이어그램으로 참여 객체와 메시지를 시간 순서대로 표현해 시나리오의 협력·호출 흐름을 나타냄(**순차 다이어그램**, Sequence Diagram).
- 배경 및 필요성 : 기능 요구만으로 객체 간 호출 순서·응답·예외 흐름이 불명확하면 인터페이스 해석과 구현이 달라짐.
- 주요 목적 : 요구·설계 단계에서 객체 간 책임과 인터페이스를 명확히 해 구현·통합 오류를 줄임.

### Ⅱ. 순차 다이어그램의 특징 및 장점

- 핵심 요약 : 생명선·메시지·활성화·반환·조합 프래그먼트.

1. 생명선 : 참여자 인스턴스와 존재 기간을 수직선으로 표시 → 상호 작용 주체와 시간 축 명료화.
2. 메시지 : 호출·응답·비동기 전송을 화살표로 표현 → 인터페이스와 호출 순서 확인.
3. 활성화·반환 : 처리 수행 기간·제어 복귀 표시 → 동기 호출과 중첩 책임 표현.
4. 조합 프래그먼트 : alt·opt·loop·par로 조건·선택·반복·병렬을 모델링 → 예외·대안 시나리오 구조화.

### Ⅲ. 순차 다이어그램의 구조 (흐름)

- 핵심 요약 : 시나리오·경계 정의 → 참여자·생명선 선정 → 정상 메시지 순서 작성 → alt·opt·loop 등 대안 추가 → 반환·예외 검토 → 인터페이스와 요구 추적.

```text
시나리오·경계 정의
   ↓
참여자·생명선 선정
   ↓
정상 메시지 순서 작성
   ↓
alt·opt·loop 등 대안 추가
   ↓
반환·예외 검토
   ↓
인터페이스와 요구 추적
```

```text
사용자      화면      서비스      저장소
   |           |           |          |
   | 요청      |           |          |
   |---------->|           |          |
   |           | 호출      |          |
   |           |---------->| 조회     |
   |           |           |--------->|
   |           |           |<---------|
   |           |<----------| 결과     |
```

### Ⅳ. 순차 다이어그램과 통신 다이어그램 비교

- 핵심 요약 : 순차 다이어그램은 객체 간 시간 순 메시지·호출 관계, 통신 다이어그램은 객체 간 링크와 메시지 번호 중심.

| 비교 방법 | 주요 특성 | 적합한 적용 조건 |
|---|---|---|
| 순차 다이어그램 | 객체 간 시간 순 메시지·호출 관계 | 시나리오·인터페이스 협력 상세화 |
| 통신 다이어그램 | 객체 간 링크와 메시지 번호 중심 | 객체 구조·연결 강조 |
| 활동 다이어그램 | 행위·제어 흐름·분기 중심 | 업무·알고리즘 절차 표현 |

### Ⅴ. 순차 다이어그램의 한계와 방안

- 핵심 요약 : 과도한 상세·모델 노후화·비동기·예외 누락·객체 책임을 핵심 시나리오 범위 제한·대안 흐름 표현·역할 리뷰로 관리.

| 위험 | 원인·영향 | 대응 통제 | 지표 예시 |
|---|---|---|---|
| 과도한 상세·모델 노후화 | 코드 변화와 다이어그램 불일치 | 핵심 시나리오·인터페이스 수준으로 범위 제한, 변경 시 갱신 | 모델-구현 불일치 |
| 비동기·예외 누락 | 재시도·타임아웃·오류 처리 미정의 | 실패·시간 초과·취소 메시지와 대안 흐름 표현 | 미정의 응답·예외 |
| 객체 책임 모호 | 한 참여자가 과도한 책임을 맡음 | 경계·통제·엔티티 역할과 호출 소유자 리뷰 | 인터페이스 변경·결합도 |

### Ⅵ. 순차 다이어그램 적용에 대한 기술사적 제언

- 핵심 요약 : 요구·설계 단계에서 객체 간 책임과 인터페이스를 명확히 해 구현·통합 오류를 줄임.

- 실행 제언 : 아키텍트·분석가는 사용자 시나리오와 API 계약에서 순차 다이어그램을 도출하고, 정상 경로뿐 아니라 오류·타임아웃·비동기 처리까지 검토해 팀 간 공통 설계 근거로 활용.

### Ⅶ. 결론

- 핵심 요약 : 순차 다이어그램은 UML(Unified Modeling Language) 상호 작용 다이어그램으로 참여 객체와 메시지를 시간 순서대로 표현해 시나리오의 협력·호출 흐름을 나타냄.
- 시사점 : 순차 다이어그램은 기능 요구를 객체 간 협력과 메시지 계약으로 구체화하는 UML 모델이며, 시간 순서와 예외 흐름의 명료성이 핵심.
