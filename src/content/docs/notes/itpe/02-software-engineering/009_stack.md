## 30초 인출

- 본질: 스택은 가장 나중에 넣은 데이터를 가장 먼저 꺼내는 후입선출(LIFO) 선형 자료구조
- 메커니즘: 한쪽 끝의 Top 포인터를 기준으로 Push로 넣고 Pop으로 꺼내며, 가득 찬 상태의 Push와 빈 상태의 Pop을 검사
- 통찰: 함수 호출의 복귀 정보가 스택에 쌓이므로 재귀가 깊으면 스택 영역이 소진되어 오버플로가 나므로 재귀 깊이 상한을 두거나 반복문으로 전환

<details>
<summary>핵심 용어</summary>

- **스택(Stack)** : 삽입과 삭제가 한쪽 끝(Top)에서만 일어나는 LIFO 선형 자료구조
- **LIFO(Last In First Out)** : 나중에 들어온 원소가 먼저 나가는 입출력 규칙
- **Push·Pop** : Top에 원소를 넣는 연산과 Top의 원소를 꺼내는 연산
- **스택 오버플로(Stack Overflow)** : 스택 용량을 넘어 Push하거나 호출 스택 영역이 소진되는 오류
- **호출 스택(Call Stack)** : 함수 호출마다 복귀 주소·매개변수·지역 변수를 쌓는 프로그램 실행 영역
- **큐(Queue)** : 먼저 넣은 원소를 먼저 꺼내는 FIFO 선형 자료구조

</details>

## 2~4교시 25점 답안

## Ⅰ. 스택의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **스택** 은 삽입과 삭제가 한쪽 끝에서만 일어나는 후입선출(LIFO) 선형 자료구조 |
| 목적 | 나중에 처리할 작업의 역순 복귀와 되돌리기 관리 |

## Ⅱ. 큐·리스트와 구별되는 스택의 특징

| 특징 | 의미 |
|---|---|
| 한쪽 끝 접근 | Top에서만 삽입·삭제 |
| 후입선출 | 마지막 입력이 첫 출력 |
| 연산의 O(1) | Push·Pop이 원소 수와 무관한 상수 시간 |

## Ⅲ. 스택의 구조와 입출력 원리

### Top 기준의 스택 구조

```text
Push ↓   ↑ Pop
  ┌──────────┐
Top→│ Data 3 │
  ├──────────┤
  │ Data 2 │
  ├──────────┤
  │ Data 1 │
  └──────────┘
```

### 확대: Push·Pop 연산의 검사 흐름

```text
Push(x): 가득 참? ── 예 → 오버플로 처리
                  └ 아니오 → Top 증가 후 저장
Pop():   비어 있음? ── 예 → 언더플로 처리
                    └ 아니오 → Top의 값 반환 후 Top 감소
```

## Ⅳ. 구현 방식과 프로그램 메모리 영역의 스택

### 배열 기반과 연결 리스트 기반 구현

| 구분 | 배열 기반 | 연결 리스트 기반 |
|---|---|---|
| 크기 | 고정 또는 재할당 필요 | 동적 확장 |
| 메모리 | 연속 배치로 접근 빠름 | 노드마다 포인터 추가 |
| 용량 초과 | 오버플로 발생 | 메모리 한도까지 |

### 프로그램 메모리의 4영역

| 영역 | 저장 내용 | 특징 |
|---|---|---|
| 코드 | 실행할 명령어 | 읽기 전용 |
| 데이터 | 전역·정적 변수 | 프로그램 시작 시 할당 |
| 힙 | 동적 할당 객체 | 실행 중 할당·해제 |
| 스택 | 함수 호출 프레임(복귀 주소·지역 변수) | 호출 시 확장, 반환 시 축소 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 깊은 재귀로 호출 스택 영역이 소진되어 스택 오버플로 발생 | 재귀 깊이 상한 설정 또는 반복문·명시적 스택으로 전환 |
| 배열 기반의 고정 크기로 용량 초과 | 용량 초과 시 배열 확장 또는 연결 리스트 기반 사용 |
| Top이 아닌 중간 원소 접근 불가 | 임의 접근이 필요하면 배열·리스트 사용 |

## Ⅵ. 제언

재귀가 깊어질 수 있는 처리는 호출 스택에 맡기지 않고 반복문과 명시적 스택으로 바꾸어 스택 영역 소진 방지

### 재귀에서 반복문으로의 전환

```text
재귀 호출: 호출마다 스택 프레임 누적 → 깊이 초과 시 오버플로
    ↓ 전환
반복문 + 명시적 스택: 힙 메모리의 스택에서 상태를 관리
```

### 선택 근거: 재귀 유지와의 비교

| 구분 | 재귀 유지 | 제언: 명시적 스택 |
|---|---|---|
| 스택 소진 | 깊이에 따라 위험 | 힙 용량까지 |
| 코드 단순성 | 높음 | 낮음 |
| 오류 처리 | 프로세스 중단 | 제어 가능 |
