## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 알고리즘·자료구조 → **스택(Stack) 자료구조**

## 30초 인출

- 본질: 스택(Stack)은 한쪽 끝인 Top에서만 데이터 삽입과 삭제가 이루어지는 후입선출(LIFO: Last In First Out) 선형 자료구조
- 메커니즘: Top 포인터를 기준으로 Push(삽입), Pop(삭제), Peek(조회) 연산 수행, O(1) 시간복잡도로 최신 상태 관리
- 통찰: 재귀 호출 누적으로 인한 Call Stack 고갈과 고정 크기 스택의 Overflow 위험이 존재하므로 꼬리 재귀 최적화 및 동적 명시적 스택 구조 적용

<details>
<summary>핵심 용어</summary>

- **스택(Stack)** : 가장 나중에 삽입된 데이터가 가장 먼저 인출되는 LIFO 원칙을 따르는 선형 자료구조
- **LIFO(Last In First Out)** : 시간상 후입된 원소가 우선적으로 처리되는 입출력 제약 규칙
- **Top 포인터** : 스택의 최상단 유효 데이터 원소 위치를 지시하는 인덱스 또는 노드 포인터
- **Push / Pop** : Top 포인터를 이동하며 최상단에 데이터를 적재하거나 회수하는 기본 연산
- **Stack Overflow** : 할당된 스택 메모리 한도를 초과하여 Push를 시도할 때 발생하는 시스템 예외
- **Call Stack(호출 스택)** : 함수 호출 시 복귀 주소(Return Address), 매개변수, 로컬 변수를 보관하는 실행 런타임 스택

</details>

## 2~4교시 25점 답안

## Ⅰ. 스택의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **스택(Stack)** 은 한쪽 끝(Top)에서만 원소의 삽입과 삭제가 일어나는 후입선출(LIFO) 방식의 선형 자료구조 |
| 목적 | 최근 데이터의 우선 인출, 이전 상태로의 역순 복원(Undo) 및 계층적 호출 문맥 보존 |

## Ⅱ. 스택의 핵심 특징

| 특징 | 의미 |
|---|---|
| LIFO 제약성 | 가장 최근에 Push된 데이터가 가장 먼저 Pop되는 단일 통로 제약 |
| 고속 O(1) 연산 | 인덱스 계산 없이 Top 포인터 조작만으로 삽입·삭제를 상수 시간에 완결 |
| 경계 상태 의존 | 빈 스택(Underflow) 및 가득 찬 스택(Overflow)에 대한 엄격한 사전 예외 검증 요구 |

## Ⅲ. 스택의 핵심 연산 메커니즘

### Top 포인터 기반 스택 입출력 구조

```text
       Push(삽입)           Pop(추출)
           │                   ▲
           ▼                   │
       ┌──────────────────────────┐
Top ─→ │          Data 3          │ (최근 적재)
       ├──────────────────────────┤
       │          Data 2          │
       ├──────────────────────────┤
       │          Data 1          │
       ├──────────────────────────┤
Base ─→│          Data 0          │ (최초 적재)
       └──────────────────────────┘
```

### 기본 연산 상태 전이 및 경계 검증 흐름

```text
Push(Value):
    isFull() 확인 ── 참 ──→ Stack Overflow 예외 발생
        ↓ 거짓
    Top ← Top + 1 후 Stack[Top] ← Value 저장

Pop():
    isEmpty() 확인 ── 참 ──→ Stack Underflow 예외 발생
        ↓ 거짓
    Value ← Stack[Top] 후 Top ← Top - 1, Value 반환
```

| 비교 항목 | 배열(Array) 기반 스택 | 연결 리스트(Linked List) 기반 스택 |
|---|---|---|
| 메모리 할당 | 정적 연속 메모리 공간 또는 가변 배열 할당 | 노드 삽입 시 힙(Heap) 메모리 동적 할당 |
| 연산 성능 | Push/Pop 평균 O(1), 가변 확장 시 일시적 O(N) | 노드 동적 할당 오버헤드 동반, 순수 O(1) |
| 공간 효율성 | 크기 고정 시 메모리 낭비 또는 부족 위험 | 포인터 저장 오버헤드 발생하나 크기 제약 전무 |
| 캐시 친화도 | 연속 메모리 배치로 CPU 캐시 적중률(Locality) 우수 | 포인터 기반 분산 메모리로 캐시 미스 발생 가능 |

## Ⅳ. 스택의 시스템 소프트웨어 활용 분야

| 활용 분야 | 동작 원리 및 스택의 역할 |
|---|---|
| 함수 호출 스택 (Call Stack) | 함수 호출 시 스택 프레임(복귀 주소, 지역변수, 프레임 포인터) Push, 리턴 시 원복 |
| 컴파일러 수식 표기 변환 | 중위 표기법(Infix) 수식을 후위 표기법(Postfix)으로 변환 시 연산자 우선순위 스택 처리 |
| 괄호 쌍 검사기 (Parser) | 여는 괄호 Push, 닫는 괄호 만날 시 Pop하여 타입 일치 및 최종 비어있음 검증 |
| 브라우저 뒤로가기 / Undo | 사용자 인터랙션 이력을 역순으로 보관하여 직전 상태로의 안전한 롤백 지원 |
| 그래프 깊이 우선 탐색 (DFS) | 정점 탐색 시 인접 정점을 스택에 보관하거나 시스템 호출 스택을 이용한 백트래킹 구현 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 깊은 재귀 호출로 인해 시스템 스택 메모리 한계를 초과하는 Stack Overflow 발생 | 꼬리 재귀 최적화(Tail Call Optimization) 적용 및 반복문 기반 명시적 힙 스택 전환 |
| 정적 배열 기반 스택 사용 시 최대 용량 예측 실패로 인한 동적 확장 병목 | 초기 적정 크기 산정과 기하급수적 재할당(2배 확장)을 통한 상각 O(1) 시간 보장 |
| 멀티 스레드 동시 접근 시 Top 포인터 경합으로 인한 데이터 유실 및 덮어쓰기 | 뮤텍스 잠금 기반 동기화 또는 CAS(Compare-And-Swap) 기반 락프리 스택 구현 |

## Ⅵ. 제언

데이터 규모 예측성과 접근 패턴에 기반한 스택 구현체 선정 및 비재귀적 명시적 스택 표준화

### 스택 구현 방식 의사결정 체계

```text
시스템 요구조건 및 데이터 수명주기 분석
    ↓
판정 기준
    ├─ 데이터 상한 고정 및 극한의 속도 요구 → 정적 배열 스택
    ├─ 데이터 규모 가변적 및 힙 메모리 여유 → 동적 연결 리스트 스택
    └─ 다중 스레드 동시성 환경 → 원자적 CAS 기반 락프리 스택
    ↓
스택 크기 가드 페이지(Guard Page) 및 한도 감시 적용
```

### 재귀 함수를 비재귀 명시적 스택으로 전환하는 흐름

```text
재귀 호출 함수 식별
    ↓
힙 영역에 사용자 정의 스택 객체 할당
    ↓
반복문 루프 구조로 전환
    ├─ 호출 상태(매개변수, 단계)를 명시적 스택에 Push
    ├─ 루프 내에서 스택 Pop 후 로직 수행
    └─ 스택이 빌 때까지 반복 수행하여 OS Call Stack 소진 원천 차단
```

### 선택 근거: OS 암묵적 호출 스택과 사용자 정의 명시적 스택 비교

| 구분 | OS 런타임 호출 스택 (재귀) | 제언: 힙 기반 명시적 스택 (비재귀) |
|---|---|---|
| 메모리 공간 | OS 스레드 스택 영역 (통상 1~8MB 극소 제한) | 가용 힙 메모리 전체 활용 가능 (수 GB) |
| 안정성 | 입력 크기 폭증 시 프로세스 비정상 크래시 | 메모리 부족 시 제어 가능한 예외 처리 지원 |
| 디버깅 편의 | 호출 스택 깊이 폭증 시 추적 난해 | 스택 스냅샷 검사를 통한 상태 분석 용이 |
