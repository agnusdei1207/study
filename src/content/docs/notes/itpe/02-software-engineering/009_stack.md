## 연관 키워드

- 스택(Stack), LIFO(Last-In First-Out), Push/Pop/Peek, 콜 스택(Call Stack)
- 스택 오버플로우(Stack Overflow), 꼬리 재귀 최적화(Tail Call Optimization), 락프리 스택(Lock-Free Stack)

## Ⅰ. 스택(Stack)의 개요

- 핵심 요약 : 한쪽 끝(Top)에서만 삽입·삭제가 일어나는 후입선출 구조의 선형 자료구조.
- 개념 : 한쪽 끝(Top)에서만 데이터의 삽입(Push)과 삭제(Pop)가 일어나는 후입선출 LIFO(Last-In First-Out) 구조의 선형 자료구조.
- 배경 및 필요성 : 최근 진입 작업의 역순 처리, 함수 호출 복귀 주소 저장, 중첩 괄호 검사·수식 계산 등 역추적(Backtracking) 알고리즘 구현 필요.
- 핵심 연산 : Push(데이터 삽입), Pop(데이터 추출 및 반환), Peek/Top(최상단 데이터 조회), IsEmpty, IsFull.

## Ⅱ. 스택의 특징

- 핵심 요약 : 단일 끝점 접근과 O(1) 연산, 배열·연결 리스트 이원화 구현이 결합된 자료구조.

1. 삽입·삭제가 Top 단일 지점에서만 수행되는 후입선출(LIFO) 동작.
2. Push, Pop, Peek 연산의 $O(1)$ 상수 시간 보장.
3. 배열 기반과 연결 리스트 기반의 대체 가능한 구현 방식.
4. 함수 호출 시 시스템 런타임이 관리하는 콜 스택(Call Stack)의 기반 구조.
5. 깊이 우선 탐색 등 역추적(Backtracking) 알고리즘의 핵심 구성 요소.

## Ⅲ. 스택의 구조 (흐름)

- 핵심 요약 : Top 포인터 기준의 Push/Pop 동작과 함수 호출 시 스택 프레임 적재 구조.
- Push/Pop 동작 메커니즘.

```text
     Push(X)               Pop()
        │                   ▲
        ▼                   │
   ┌─────────┐         ┌─────────┐
   │    C    │ <- Top  │         │
   ├─────────┤         ├─────────┤
   │    B    │         │    B    │ <- Top
   ├─────────┤         ├─────────┤
   │    A    │         │    A    │
   └─────────┘         └─────────┘
    [ LIFO 상태 ]       [ 데이터 추출 ]
```

- 배열 기반 구현 : 고정 크기의 단순 구현과 우수한 캐시 지역성(Locality), 스택 용량 초과 시 스택 오버플로우(Stack Overflow) 또는 동적 재할당 오버헤드 존재.
- 연결 리스트 기반 구현 : 노드 동적 할당 기반의 오버플로우 위험 제거, 포인터 오버헤드 및 잦은 메모리 할당/해제 비용 발생.
- 콜 스택(Call Stack) 프레임 구조 : 함수 호출 시 복귀 주소(Return Address), 매개변수, 로컬 변수의 스택 프레임 적재 및 리턴 시 자동 해제.

```text
[ 콜 스택 프레임 적재 흐름 ]
main() 호출 → [ main 프레임 ] 적재
   └─ f() 호출 → [ f 프레임 : 복귀 주소 + 매개변수 + 로컬 변수 ] ← Top
        └─ g() 호출 → [ g 프레임 ] 적재 ← Top
리턴 시 역순 해제 : g → f → main
```

## Ⅳ. 스택의 응용 분야 및 구현 방식 비교

- 핵심 요약 : 응용 분야별 메커니즘과 구현 방식별 상충 관계의 구분.
- 구현 방식 비교.

| 구현 방식 | 장점 | 한계 |
|---|---|---|
| 배열 기반 | 단순 구현, 우수한 캐시 지역성(Locality) | 용량 초과 시 스택 오버플로우(Stack Overflow), 동적 재할당 오버헤드 |
| 연결 리스트 기반 | 노드 동적 할당으로 오버플로우 위험 제거 | 포인터 오버헤드, 잦은 메모리 할당/해제 비용 |

- 응용 분야별 메커니즘.

| 응용 분야 | 메커니즘 및 처리 방식 |
|---|---|
| 함수 호출 및 재귀 복귀 | 시스템 런타임의 호출 순서 스택 프레임 적재 및 종료 시 역순 해제 |
| 괄호 유효성 검사 | 여는 괄호 Push, 닫는 괄호 Pop 기반 일치 여부 판별(짝 불일치 시 오류) |
| 후위 표기법(Postfix) 계산 | 피연산자 Push, 연산자 만나면 2개 Pop 후 연산 결과 재 Push |
| DFS(Depth-First Search) 및 백트래킹 | 인접 노드 탐색 중 방문 경로의 스택 저장, 막다른 길 도달 시 Pop 복귀 |
| Undo/Redo 기능 | 사용자 실행 히스토리의 스택 적재를 통한 이전 상태 롤백 지원 |

## Ⅴ. 스택의 장점과 한계

- 핵심 요약 : O(1) 연산·역추적 지원의 장점, 오버플로우·크기 제약·동시성 경합의 한계.
- 장점
  1. Push, Pop, Peek의 $O(1)$ 상수 시간 연산.
  2. 역추적·재귀·이력 관리 등 다양한 알고리즘 지원.
  3. 단순한 구조 기반의 낮은 구현·검증 비용.
- 한계점 1 : 스레드 콜 스택 크기 제한으로 인한 스택 오버플로우(Stack Overflow)
  - 한계점 : 재귀 호출 깊이 증가 또는 무한 루프 진입 시 고정된 스레드 콜 스택 영역(통상 1MB 내외) 초과로 프로세스 비정상 종료(Crash) 유발.
  - 해결 방안 : 재귀 함수의 꼬리 재귀 최적화(Tail Call Optimization) 재구성, 힙(Heap) 영역에 할당되는 명시적 커스텀 스택 기반 반복문(Iteration) 변환.
- 한계점 2 : 정적 배열 스택의 크기 제약 및 동적 스택의 재할당 오버헤드
  - 한계점 : 고정 크기 배열의 용량 초과 오버플로우, 동적 배열(Vector 등)의 용량 증설(Doubling) 시 $O(N)$ 메모리 복사 및 지연 스파이크(Latency Spike) 발생.
  - 해결 방안 : 최대 요구 용량 사전 산정 기반의 초기 용량 예약(Pre-allocation), 청크 단위 메모리 블록을 연결 리스트로 묶는 언롤드 연결 리스트(Unrolled Linked List) 스택 구조 채택.
- 한계점 3 : 멀티스레드 환경에서 탑(Top) 포인터 락 경합 및 ABA 문제
  - 한계점 : 동시성 환경의 단일 Top 포인터 락킹 또는 단순 CAS(Compare-And-Swap) 연산 시 스레드 충돌 재시도 루프 과부하 및 ABA 문제 기반 메모리 오염 발생.
  - 해결 방안 : 버전 카운터 결합 태그 포인터(Tagged Pointer, AtomicStampedReference) 적용을 통한 ABA 문제 방지, Elimination Backoff Stack 기법 도입을 통한 충돌 스레드 간 쌍(Pair) 교환 기반 락 경합 분산.

## Ⅵ. 대규모 시스템에서의 기술사적 제언

- 핵심 요약 : 깊은 재귀의 오버플로우 방지와 락프리 동시성 구조 도입.
- 재귀 호출에 따른 스택 오버플로우 방지 : 깊은 재귀 탐색(Deep Recursion) 시 스레드 스택 한계 초과 크래시 방지를 위한 꼬리 재귀 최적화(Tail Call Optimization) 적용 또는 힙 기반 명시적 스택(Explicit Stack) 루프 리팩토링 권장.
- 멀티스레드 동시성 환경에서의 락 경합 완화 : 스택 최상단(Top) 포인터 동시 접근 병목 해소를 위한 CAS 원자적 연산 기반 Treiber 락프리 스택(Lock-Free Stack) 기법 적용 고려.

## Ⅶ. 결론

- 핵심 요약 : 스택은 O(1) 후입선출 연산으로 역추적·호출 관리의 기반이 되는 자료구조.
- 요약 : LIFO 구조와 콜 스택 프레임 메커니즘이 함수 호출·파싱·탐색 등 광범위 응용의 기반.
- 시사점 : 오버플로우 방지 설계와 동시성 락프리 구조 검토가 대규모 시스템 안정성 확보의 핵심.
