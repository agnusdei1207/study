## 연관 키워드

- 스택(Stack), LIFO(Last-In First-Out), Push/Pop/Peek, 콜 스택(Call Stack)
- 스택 오버플로우(Stack Overflow), 꼬리 재귀 최적화(Tail Call Optimization), 락프리 스택(Lock-Free Stack)

## Ⅰ. 스택(Stack)의 개요

- 핵심 요약 : 한쪽 끝에서만 삽입과 삭제가 일어나는 후입선출 구조의 선형 자료구조.
- 개념 : 한쪽 끝인 Top에서만 데이터를 넣고 빼는 **스택** (Stack)이며, 나중에 넣은 데이터가 먼저 나오는 **LIFO** (Last-In First-Out) 구조의 선형 자료구조.
- 배경 및 필요성 : 최근 작업의 역순 처리와 역추적(Backtracking) 알고리즘 구현에 필요하며, 함수 호출의 복귀 위치를 관리하는 기반이 됨.
- 핵심 연산 : **Push/Pop/Peek** (삽입, 추출과 반환, 최상단 조회)에 더해 빈 상태 확인(IsEmpty)과 가득 찬 상태 확인(IsFull)을 사용.

## Ⅱ. 스택의 특징 및 장점

- 핵심 요약 : 단일 끝점 접근에 따른 상수 시간 연산과, 두 가지 구현 방식이 결합된 자료구조.

1. 삽입·삭제가 Top 한 지점에서만 이뤄지는 LIFO 동작 → 접근 규칙이 단순해 상태 추적이 쉬움.
2. Push, Pop, Peek 연산의 $O(1)$ 상수 시간 보장 → 연산 시간이 데이터 개수와 무관함.
3. 배열 기반과 연결 리스트 기반의 대체 가능한 구현 → 용량 고정과 동적 할당 중에서 선택 가능.
4. 함수 호출 시 런타임이 관리하는 **콜 스택** (Call Stack)의 기반 구조 → 재귀 호출과 지역 변수 수명 관리의 토대.
5. 깊이 우선 탐색 등 역추적 알고리즘의 핵심 구성 요소 → 이전 상태로 되돌아가는 탐색 구현이 가능.

## Ⅲ. 스택의 구조 (흐름)

- 핵심 요약 : Top 위치를 기준으로 Push와 Pop이 일어나고, 함수 호출 시 스택 프레임이 차곡차곡 쌓이는 구조.

```text
[ 스택 Push·Pop 동작 ]

[ 초기 상태 ] A B C (Top = C)
     ↓ Push(D)
A B C D (Top = D)
     ↓ Pop()
A B C (Top = C)
```

```text
[ 콜 스택 적재 흐름 ]

main() 호출 → [ main 프레임 ]
   ↳ f() 호출 → [ f 프레임 ] ← Top
      ↳ g() 호출 → [ g 프레임 ] ← Top
리턴 시 역순 해제 : g → f → main
```

- 배열 기반 구현 : 고정 크기의 단순한 구현으로 캐시 지역성(Locality)이 좋지만, 용량을 넘으면 오버플로우가 나거나 동적 재할당 비용이 생김.
- 연결 리스트 기반 구현 : 노드를 동적으로 할당해 오버플로우 위험이 없지만, 포인터 오버헤드와 잦은 메모리 할당·해제 비용이 따름.
- 스택 프레임 : 함수 호출 시 복귀 주소, 매개변수, 지역 변수가 적재되고 리턴 시 자동으로 해제됨.

## Ⅳ. 스택의 구현 방식과 응용 분야 비교

- 핵심 요약 : 구현 방식별 장단점과 응용 분야별 동작 메커니즘을 구분해 설계 선택 기준을 세우는 체계.

| 구현 방식 | 장점 | 한계 |
| --- | --- | --- |
| 배열 기반 | 단순한 구현, 우수한 캐시 지역성 | 용량 초과 시 스택 오버플로우, 동적 재할당 오버헤드 |
| 연결 리스트 기반 | 노드 동적 할당으로 오버플로우 위험 제거 | 포인터 오버헤드, 잦은 메모리 할당·해제 비용 |

| 응용 분야 | 메커니즘 및 처리 방식 |
| --- | --- |
| 함수 호출과 재귀 복귀 | 호출 순서대로 스택 프레임을 적재하고 종료 시 역순 해제 |
| 괄호 유효성 검사 | 여는 괄호는 Push, 닫는 괄호는 Pop 후 짝 일치 여부 판별 |
| 후위 표기법 계산 | 피연산자를 Push하고, 연산자를 만나면 두 개를 Pop해 계산한 뒤 결과를 Push |
| 깊이 우선 탐색(DFS, Depth-First Search)과 백트래킹 | 방문 경로를 스택에 저장하고, 막다른 길에서 Pop으로 복귀 |
| 실행 취소와 다시 실행(Undo/Redo) | 사용자 실행 이력을 스택에 적재해 이전 상태로 롤백 |

## Ⅴ. 스택의 한계와 방안

- 핵심 요약 : O(1) 연산과 역추적 지원이라는 장점, 오버플로우와 동시성 경합이라는 한계.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **스택 오버플로우** (Stack Overflow) | 깊은 재귀나 무한 루프로 스레드 콜 스택 한도를 넘어 프로세스가 비정상 종료 | 언어와 런타임이 지원할 때 **꼬리 재귀 최적화** (Tail Call Optimization)를 적용하거나, 힙에 둔 명시적 스택으로 반복문 변환 | 최대 스택 깊이, 크래시 발생 건수 |
| 용량 제약과 재할당 비용 | 고정 배열은 용량 초과로 오버플로우, 동적 배열은 증설 때 메모리 복사로 지연 발생 | 최대 요구 용량을 미리 산정해 초기 용량을 예약하고, 청크 단위 블록을 연결한 언롤드 연결 리스트 스택 채택 | 증설 횟수, 지연 스파이크 |
| **ABA 문제** 와 멀티스레드 경합 | Top 포인터 락 경합과 CAS(Compare-And-Swap) 재시도 과부하, ABA 문제로 메모리 오염 | 버전 카운터를 결합한 태그 포인터(Tagged Pointer)로 ABA 방지, Elimination Backoff Stack으로 경합 분산 | CAS 재시도 횟수, 락 대기 시간 |

## Ⅵ. 대규모 시스템에서의 기술사적 제언

- 핵심 요약 : 깊은 재귀를 비재귀 구조로 바꾸고, 공유 자료구조의 동시성 경합을 설계 단계에서 줄이는 것이 기본 원칙.
- 재귀 깊이 통제 : 입력 규모에 따라 재귀 깊이가 예측되지 않는 탐색 로직은 힙 기반 명시적 스택 루프로 바꾸는 것이 필요함. 꼬리 재귀 최적화는 런타임 지원 여부를 확인한 뒤 보조 수단으로만 씀.
- 동시성 구조 선택 : 여러 스레드가 최상단을 함께 쓰는 병목은 CAS 원자 연산 기반의 **락프리 스택** (Lock-Free Stack, Treiber 스택 등)으로 해소할 수 있으나, 구현 복잡도와 ABA 방지 비용을 함께 평가하는 것이 현실적임.

## Ⅶ. 결론

- 핵심 요약 : 스택은 O(1) 후입선출 연산으로 역추적과 호출 관리의 기반이 되는 자료구조.
- 시사점 : 오버플로우 방지 설계와 동시성 구조 검토가 대규모 시스템 안정성 확보의 핵심임.
