## Ⅰ. 스택(Stack)의 개요

- **개념** : 한쪽 끝(Top)에서만 데이터의 삽입(Push)과 삭제(Pop)가 일어나는 후입선출(LIFO, Last-In First-Out) 구조의 선형 자료구조.
- **배경 및 필요성** : 최근에 진입한 작업을 먼저 역순으로 되돌리거나, 함수 호출 복귀 주소를 저장하고, 중첩된 괄호 검사나 수식 계산 등 역추적(Backtracking)이 필요한 알고리즘을 구현하기 위해 필수.
- **핵심 연산** : Push(데이터 삽입), Pop(데이터 추출 및 반환), Peek/Top(최상단 데이터 조회), IsEmpty, IsFull.

## Ⅱ. 스택의 동작 메커니즘 및 메모리 모델

```text
     Push(X)               Pop()
        │                   ▲
        ▼                   │
   ┌─────────┐         ┌─────────┐
   │    C    │ <- Top  │         │
   ├─────────┤         ├─────────┤
   │    B    │         │    B    │ <- Top
   ├─────────┤         ├─────────┤
   │    A    │         │    A    │
   └─────────┘         └─────────┘
    [ LIFO 상태 ]       [ 데이터 추출 ]
```

- **배열 기반 구현** : 고정 크기로 구현이 단순하고 캐시 지역성(Locality)이 우수하나, 스택 용량 초과 시 스택 오버플로우(Stack Overflow)가 발생하거나 동적 재할당 오버헤드 존재.
- **연결 리스트 기반 구현** : 노드 동적 할당으로 오버플로우 위험이 없으나 포인터 오버헤드와 잦은 메모리 할당/해제 비용 발생.
- **콜 스택(Call Stack) 프레임 구조** : 함수 호출 시 복귀 주소(Return Address), 매개변수, 로컬 변수를 스택 프레임에 적재하고 리턴 시 자동 해제.

## Ⅲ. 스택의 핵심 응용 분야 및 연산 시간복잡도

| 응용 분야 | 메커니즘 및 처리 방식 |
|---|---|
| 함수 호출 및 재귀 복귀 | 시스템 런타임에서 호출 순서대로 스택 프레임을 쌓고, 종료 시 역순 해제 |
| 괄호 유효성 검사 | 여는 괄호는 Push, 닫는 괄호는 Pop하여 일치 여부 판별 (짝 불일치 시 오류) |
| 후위 표기법(Postfix) 계산 | 피연산자는 Push, 연산자를 만나면 2개 Pop하여 연산 후 결과 다시 Push |
| DFS 및 백트래킹 | 인접 노드를 탐색하며 방문 경로를 스택에 저장하고 막다른 길 도달 시 Pop하여 복귀 |
| Undo/Redo 기능 | 사용자의 실행 히스토리를 스택에 적재하여 이전 상태로 롤백 지원 |

- **연산 복잡도** : Push, Pop, Peek 모두 최상단(Top) 위치에서 즉각 처리되므로 시간복잡도는 $O(1)$을 보장.

## Ⅳ. 스택(Stack) 자료구조의 주요 한계점 및 해결 방안

- **스레드 콜 스택 크기 제한으로 인한 스택 오버플로우(Stack Overflow)** :
  - **한계점** : 재귀 호출의 깊이가 깊어지거나 무한 루프에 진입할 경우 고정된 스레드 콜 스택 영역(통상 1MB 내외)을 초과하여 프로세스 비정상 종료(Crash) 유발.
  - **해결 방안** : 재귀 함수 호출을 꼬리 재귀 최적화(Tail Call Optimization)로 재구성하거나, 힙(Heap) 메모리 영역에 할당되는 명시적 커스텀 스택 자료구조 기반 반복문(Iteration)으로 변환.
- **정적 배열 스택의 크기 제약 및 동적 스택의 재할당 오버헤드** :
  - **한계점** : 고정 크기 배열은 용량 초과 시 오버플로우가 발생하고, 동적 배열(Vector 등) 스택은 용량 증설(Doubling) 시 $O(N)$의 메모리 복사 및 지연 스파이크(Latency Spike) 발생.
  - **해결 방안** : 최대 요구 용량을 사전 산정하여 초기 용량을 예약(Pre-allocation)하거나, 청크 단위 메모리 블록을 연결 리스트로 묶는 언롤드 연결 리스트(Unrolled Linked List) 스택 구조 채택.
- **멀티스레드 환경에서 탑(Top) 포인터 락 경합 및 ABA 문제** :
  - **한계점** : 동시성 환경에서 단일 Top 포인터에 대한 락킹 또는 단순 CAS(Compare-And-Swap) 연산 시 스레드 충돌로 인한 재시도 루프 과부하 및 ABA 문제로 인한 메모리 오염 발생.
  - **해결 방안** : 버전 카운터를 결합한 태그 포인터(Tagged Pointer / AtomicStampedReference)를 적용하여 ABA 문제를 방지하고, Elimination Backoff Stack 기법을 도입하여 충돌 스레드 간 쌍(Pair) 교환으로 락 경합 분산.

## Ⅴ. 대규모 시스템에서의 기술사적 제언

- **재귀 호출에 따른 스택 오버플로우 방지** : 깊은 재귀 탐색(Deep Recursion) 수행 시 스레드 스택 한계를 초과하여 크래시가 발생하므로, 꼬리 재귀 최적화(Tail Call Optimization)를 적용하거나 힙 기반의 명시적 스택(Explicit Stack) 루프로 리팩토링 권장.
- **멀티스레드 동시성 환경에서의 락 경합 완화** : 스택 최상단(Top) 포인터에 대한 동시 접근 시 성능 병목이 발생하므로, Compare-And-Swap(CAS) 원자적 연산을 활용한 Treiber의 락프리 스택(Lock-Free Stack) 기법 적용 고려.
