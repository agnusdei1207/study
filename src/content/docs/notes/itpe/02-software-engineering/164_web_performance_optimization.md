## 핵심 그림
```text
+-------------------------------------------------------------------------+
|                  브라우저 중요 렌더링 경로(CRP) 및 최적화 포인트         |
+-------------------------------------------------------------------------+
|                                                                         |
|  [ HTML 수신 ] ──> [ DOM 트리 생성 ] ──────┐                             |
|                           │                │                             |
|  [ CSS 수신  ] ──> [ CSSOM 트리 생성 ] ────┴─> [ 렌더 트리 (Render Tree) ]|
|                                                          │               |
|                                                          v               |
|                                                 [ 레이아웃 (Layout) ]    |
|                                                 - 위치 및 크기 계산      |
|                                                 - Reflow 방지 최적화     |
|                                                          │               |
|                                                          v               |
|                                                 [ 페인트 (Paint) ]       |
|                                                 - 픽셀 렌더링            |
|                                                 - Repaint 방지           |
|                                                          │               |
|                                                          v               |
|                                                 [ 합성 (Composite) ]     |
|                                                 - GPU 하드웨어 가속       |
|                                                                         |
|  * 구글 Core Web Vitals 3대 지표:                                        |
|    - LCP (Largest Contentful Paint) : 가장 큰 콘텐츠 표시 시간 (≤ 2.5s)   |
|    - INP (Interaction to Next Paint) : 사용자 인터랙션 반응성 (≤ 200ms)  |
|    - CLS (Cumulative Layout Shift) : 화면 깜빡임/레이아웃 밀림 (≤ 0.1)    |
+-------------------------------------------------------------------------+
```

## 핵심 용어
- 리플로우(Reflow)와 리페인트(Repaint): 리플로우는 DOM 요소의 크기나 위치가 바뀌어 전체 문서 구조를 재계산하는 고비용 연산이며, 리페인트는 색상 등 시각적 요소만 다시 픽셀로 그리는 연산
- 트리 셰이킹(Tree-Shaking): 번들러(Webpack, Rollup)가 ES 모듈(`import/export`)의 정적 의존성을 분석하여 실제로 사용되지 않는 죽은 코드(Dead Code)를 빌드 결과물에서 완전히 털어내는 최적화 기법

## 핵심 통찰
- 웹 성능의 성패는 백엔드 API 속도(20%)보다 브라우저가 화면을 파싱하고 렌더링하는 프론트엔드 최적화(80%)에서 갈림
- 자바스크립트 파일은 렌더링 차단 리소스(Render-blocking Resource)이므로, `<script>` 태그를 `async`나 `defer`로 비동기 로딩하거나 바디 태그 맨 끝에 배치해야 HTML 파싱이 멈추지 않음
- 구글 검색 엔진이 순위 산정 알고리즘에 Core Web Vitals를 반영함에 따라, 웹 성능 최적화는 단순한 기술 개선을 넘어 검색 엔진 최적화(SEO) 및 비즈니스 매출과 직결되는 핵심 엔지니어링 과제가 됨

## 이웃 토픽과 구분
- 리플로우(Reflow) vs 컴포지트(Composite): 리플로우 = CPU를 사용하여 전체 레이아웃을 다시 계산하는 무거운 연산 / 컴포지트 = `transform`, `opacity` 등을 GPU 레이어로 분리하여 CPU 리플로우 없이 부드럽게 화면을 합성

## 문제·원인·대책
- 적용 상황: 글로벌 전자상거래 웹사이트 모바일 첫 화면 렌더링 지연
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 모바일에서 첫 화면 진입 시 LCP(최대 콘텐츠 렌더링 시간)가 5.8초로 측정되어 전환율 급감 | 메인 배너 이미지가 고해상도 PNG 포맷이며 폰트 로딩 시 화면 텍스트가 블랭크됨 | WebP 변환, `<link rel="preload">` 적용 및 폰트 `font-display: swap` 지정 | LCP 5.8초에서 1.7초로 단축 및 구글 SEO 최적화 |
| 이미지 로딩이 늦어지면서 화면의 버튼 위치가 아래로 덜컥 밀려 오클릭 유발 (CLS 불합격) | `<img>` 태그에 명시적인 `width`와 `height` 속성을 주지 않아 자리 확보 실패 | 모든 이미지 및 광고 영역에 고정 가로세로 비율(Aspect Ratio) 사전 공간 예약 | CLS 수치 0.35에서 0.02로 개선 (시각적 안정성 확보) |
