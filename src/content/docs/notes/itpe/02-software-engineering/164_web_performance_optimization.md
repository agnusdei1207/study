## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 웹 기술 → **웹 성능 최적화(Web Performance Optimization)**

## 30초 인출

- 본질: 웹 성능 최적화는 사용자가 페이지를 빠르게 보고 조작하도록 로딩 속도·반응성·화면 안정성을 개선하는 활동
- 메커니즘: 핵심 지표(LCP·INP·CLS)를 측정해 병목을 찾고 자원 크기 축소·캐시·렌더링 차단 제거로 개선한 뒤 재측정
- 통찰: 감으로 개선하면 효과가 없는 곳에 노력이 쓰이므로 측정으로 병목을 먼저 찾고 성능 예산을 정해 배포마다 초과 여부를 검사

<details>
<summary>핵심 용어</summary>

- **Core Web Vitals** : 로딩·반응성·시각 안정성을 나타내는 세 가지 핵심 웹 성능 지표
- **LCP(Largest Contentful Paint)** : 가장 큰 콘텐츠가 표시되는 시간(로딩 속도)
- **INP(Interaction to Next Paint)** : 사용자 조작 후 화면이 반응하기까지의 시간(반응성)
- **CLS(Cumulative Layout Shift)** : 로딩 중 레이아웃이 예기치 않게 흔들리는 정도(시각 안정성)
- **성능 예산(Performance Budget)** : 자원 크기·지표의 허용 한도
- **주요 렌더링 경로(Critical Rendering Path)** : 브라우저가 HTML·CSS·JS를 받아 화면을 그리기까지의 과정

</details>

## 2~4교시 25점 답안

## Ⅰ. 웹 성능 최적화의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **웹 성능 최적화** 는 로딩 속도·반응성·화면 안정성을 개선하는 활동 |
| 목적 | 사용자 경험 향상과 이탈 감소 |

## Ⅱ. 웹 성능 최적화의 특징

| 특징 | 의미 |
|---|---|
| 측정 기반 | 지표로 병목 확인 |
| 전 구간 대상 | 서버·네트워크·브라우저 렌더링 |
| 지속 관리 | 배포마다 재측정 |

## Ⅲ. 페이지 로딩의 흐름과 병목

```text
요청 ─→ 서버 응답 ─→ HTML 파싱 ─→ CSS·JS 로드 ─→ 렌더링 ─→ 조작 가능
        (TTFB)                    (렌더링 차단)    (LCP)     (INP)
```

## Ⅳ. 지표와 개선 방법

### 핵심 지표

| 지표 | 의미 | 개선 방향 |
|---|---|---|
| LCP | 큰 콘텐츠 표시 시간 | 이미지 최적화, 서버 응답 단축 |
| INP | 조작 반응 시간 | 긴 스크립트 분할 |
| CLS | 레이아웃 흔들림 | 이미지·광고 영역 크기 지정 |

### 개선 기법

| 구간 | 기법 |
|---|---|
| 네트워크 | 압축, CDN, 캐시, 요청 수 감소 |
| 자원 | 이미지 최적화, 코드 분할, 불필요 스크립트 제거 |
| 렌더링 | 렌더링 차단 자원 지연 로딩 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 병목을 모르고 개선해 효과 없음 | 측정 후 병목 우선 개선 |
| 배포 후 성능이 점차 악화 | 성능 예산과 배포 시 자동 검사 |
| 실험실 측정과 실제 사용자 환경의 차이 | 실제 사용자 측정 병행 |

## Ⅵ. 제언

성능 예산을 정하고 배포마다 예산 초과 여부를 자동으로 검사해 악화를 막음

```text
성능 예산 정의 (LCP·자원 크기)
      ↓
빌드·배포 시 측정
      ├─ 예산 이내 → 배포
      └─ 초과 → 원인 개선 후 재측정
```

| 구분 | 사후 점검 | 제언: 예산 자동 검사 |
|---|---|---|
| 악화 발견 | 사용자 불만 이후 | 배포 시점 |
| 기준 | 없음 | 예산 |
