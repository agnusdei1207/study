```text

 ┃
 ┣━ Ⅰ 개요 ───── 테스트 종료 시점의 주관적 타협으로 인한 운영 참사 → 결함 발견 추세를 수학적 확률 과정으로 모델링하여 잔존 결함 예측
 ┣━ Ⅱ 특징 ───── 비동차 포아송 과정(NHPP) 기반 · 시간 경과에 따른 고장률 감소 모사 · MTTF 및 최적 릴리스 시점 산출
 ┣━ Ⅲ 구조 ───── 결함 분류 모델: 고장 간격 시간 모델(Jelinski-Moranda) vs 단위 시간당 결함 수 모델(Goel-Okumoto, Yamada S자형)
 ┣━ Ⅳ 흐름 ───── 테스트 결함 시계열 수집 → 모수 추정(최우도추정법 MLE) → 적합도 검정(Kolmogorov-Smirnov) → 신뢰도 지표 산출 → 릴리스 판정
 ┣━ Ⅴ 비교 ───── Goel-Okumoto(지수형, 단순 결함) vs Yamada S-shaped(S자형, 학습 지연) vs Musa 실행시간 모델
 ┗━ Ⅵ 실무 ───── 완전 디버깅 가정의 한계 / 결함 재유입률(Imperfect Debugging) 반영 / 안전필수(ISO 26262) 도메인 적용
```

## 한 줄 본질
- 테스트가 언제 끝나야 치명적 버그 없이 시장에 출시할 수 있는지 예측하지 못하는 일정-품질 딜레마 병목 → 결함 발견 시점과 빈도 데이터를 확률 모델(NHPP)에 대입하여 목표 신뢰도 도달 시점과 잔존 결함 수를 정량 계산하는 통계적 공학 기법 / 현실의 불완전 디버깅 오차

## 핵심 그림
```text
+-------------------------------------------------------------------------+
|                  SRGM 수학적 분류 체계 및 최적 릴리스 결정 공식         |
+-------------------------------------------------------------------------+
|                                                                         |
|                          [ SRGM 모델 분류 ]                             |
|                                   │                                     |
|         ┌─────────────────────────┴─────────────────────────┐           |
|         v                                                   v           |
|  [ 1. 고장 간격 시간 모델 ]                   [ 2. 단위 시간당 고장 수 모델 ]   |
|  - 고장과 다음 고장 사이의 시간 측정          - 특정 시간 간격 동안의 고장 수   |
|  - Jelinski-Moranda (JM 모델)                 - Goel-Okumoto (G-O 모델, NHPP)   |
|  - Schick-Wolverton (SW 모델)                 - Yamada 지연 S자형 (S-Shaped)    |
|                                               - Musa 기본 실행시간 모델         |
|                                                                         |
|  [ 최적 릴리스 시점 산정 공식: 비용 최적화 모델 ]                       |
|    총비용 C(T) = C1·T + C2·m(T) + C3·[a - m(T)]                         |
|    - C1: 단위 테스트 시간당 비용, C2: 테스트 중 결함 수정 비용          |
|    - C3: 출시 후 운영 중 결함 수정 비용 (C3 >> C2)                     |
|    - a: 시스템 내 잠재 총 결함 수, m(T): 시간 T까지 발견된 누적 결함 수 |
|    * dC(T)/dT = 0 이 되는 시점 T* 가 총비용을 최소화하는 최적 릴리스 시점|
+-------------------------------------------------------------------------+
```

## 핵심 용어
- Jelinski-Moranda 모델(JM 모델): 프로그램 내에 남아 있는 미발견 결함의 수에 비례하여 고장 발생률이 일정하게 감소한다고 가정한 최초의 고장 간격 시간 기반 신뢰도 모델
- 최우도 추정법(MLE, Maximum Likelihood Estimation): 수집된 실제 결함 발생 시계열 데이터가 관측될 확률(우도)을 최대로 만드는 모델의 미지 파라미터(잠재 결함 수 $a$, 결함 검출률 $b$)를 역산하는 통계 추정 기법

## 핵심 통찰
- 전통적인 SRGM 모델들은 "버그를 고치면 즉시 사라지고 다른 버그가 생기지 않는다(완전 디버깅)"고 가정하지만, 실무에서는 버그 수정 과정에서 신규 결함이 발생하는 "불완전 디버깅(Imperfect Debugging)" 모델로 확장해야 예측 신뢰도가 높아짐
- 캘린더 시간(달력 일수)을 기준으로 결함 데이터를 수집하면 주말이나 공휴일, 야근에 따라 데이터가 왜곡되므로, "실제 CPU 실행 시간(Execution Time)"을 축으로 측정하는 Musa 모델이 학술적으로 가장 정밀함
- 신뢰성 곡선에서 누적 결함 곡선 $m(t)$의 기울기(단위 시간당 결함 발견 수)가 완만해져서 한계선에 도달했을 때 릴리스를 결정해야 하며, 기울기가 여전히 가파른 상태에서 출시하면 운영 장애 비용 $C_3$가 기하급수적으로 폭발함

## 이웃 토픽과 구분
- SRGM vs 정적 분석 도구(SonarQube): 정적 분석 = 코드를 실행하지 않고 잠재 취약점과 코드 스멜을 규칙 기반으로 탐지 / SRGM = 실제 테스트를 수행하며 시간에 따라 발현되는 동적 고장 통계를 기반으로 미래 결함률 예측

## 문제·원인·대책
- 적용 상황: 의료기기 소프트웨어 및 원자력 제어 시스템 릴리스 검증
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 제품 출시 후 운영 환경에서 심각한 크래시가 빈발하여 환자 안전 위험 초래 | 결함 발견 건수만 단순 집계하고 신뢰성 성장 모델에 기반한 잔존 결함 예측 누락 | NHPP 기반 Yamada S자형 모델 피팅 및 잔존 결함률 99.9% 제거 입증 시에만 승인 | 운영 장애 위험 95% 차단 및 안전 무결성 확보 |
| 버그를 수정할 때마다 새로운 사이드 이펙트 버그가 유입되어 신뢰성 모델 예측 빗나감 | 완전 디버깅을 가정한 기본 G-O 모델의 한계 및 회귀 테스트 부재 | 결함 유입률 파라미터($\alpha$)를 포함한 불완전 디버깅 SRGM 적용 및 회귀 테스트 자동화 | 실제 결함 감소 추세 정확도 30% 향상 |

## 내 의견
- [수학적 공식에 갇힌 이론적 모델의 현장 실용화 방안] 복잡한 미분방정식과 MLE 계산을 테스터가 직접 수행할 수 없어 현장에서 외면받는 현실 극복 필요 → 나라면: CI/CD 테스트 파이프라인(Jenkins/GitHub Actions)에서 매일 밤 실행되는 자동화 테스트의 결함 발생 데이터를 수집하여, 오픈소스 통계 도구(R의 `Rsalvador` 패키지 등)로 매일 아침 최적 릴리스 권고일을 산출하는 "지속적 신뢰도 예측(Continuous Reliability Forecasting)" 자동화 체계 구축
