## 연관 키워드

- SRGM(Software Reliability Growth Model), NHPP(Non-Homogeneous Poisson Process), 고장 강도(Failure Intensity)
- MTBF(Mean Time Between Failures), Goel-Okumoto 모델, Yamada S자형 모델, 불완전 디버깅(Imperfect Debugging), 출시 기준(Release Criteria)

## Ⅰ. SW 신뢰성 성장 모델(SRGM)의 개요

- 핵심 요약 : 테스트 중 발견·제거되는 결함 데이터를 통계 모델로 분석해 잔존 결함과 출시 시점을 정량 예측하는 신뢰성 평가 모델.
- 개념 : 결함 발견과 제거의 시간적 추이를 **비동차 포아송 과정** (NHPP, Non-Homogeneous Poisson Process) 등 통계 모델로 표현해, 잔존 결함 수와 **고장 강도** (Failure Intensity)를 추정하는 **SW 신뢰성 성장 모델** (SRGM, Software Reliability Growth Model).
- 배경 및 필요성 : 출시를 언제 할지를 감이나 일정이 아닌 정량 신뢰성 지표로 판단해야 하는 요구가 커짐.
- 핵심 가정 : 결함이 발견되어 수정될수록 고장률이 점진적으로 낮아지고 신뢰도가 성장한다는 전제.
- 주요 목적 : 잔존 결함 수와 **MTBF** (Mean Time Between Failures, 평균 무고장 시간)를 예측하고, 출시 시점 결정의 근거를 제공.

## Ⅱ. SRGM의 특징 및 장점

- 핵심 요약 : NHPP 기반 통계 모델링, 모델별 곡선 형상 차이, 시간 기준의 선택 가능성이 결합된 정량 신뢰성 예측 체계.

1. NHPP 기반 모델링 : 결함 발견·제거 이력을 시간 함수로 표현 → 고장 추이의 수학적 예측 가능.
2. 정량 지표 산출 : 잔존 결함 수, 고장 강도, MTBF를 추정 → 품질 목표를 수치로 관리.
3. 출시 판단 근거 : 추정 결과를 출시 기준과 대조 → 경험이나 일정에만 의존하는 결정 감소.
4. 모델 선택 : 지수형(Goel-Okumoto)과 S자형(Yamada) 등 데이터 성격에 맞는 곡선 선택 → 예측 적합도 향상.
5. 가정의 구분 : 결함 수정이 완벽하다고 보는 완전 디버깅 모델과 **불완전 디버깅**(Imperfect Debugging, 수정 과정의 결함 유입을 반영) 모델을 구분 → 가정에 맞는 모델로 예측 보정.
6. 시간 기준 선택 : 달력 시간 대신 CPU(Central Processing Unit) 실행 시간을 쓰는 Musa 계열 모델 적용 가능 → 연속 가동 시스템에 맞는 측정.

## Ⅲ. SRGM의 구조 (흐름)

- 핵심 요약 : 누적 결함 곡선이 포화되는 형태와, 테스트에서 출시 판단까지 이어지는 순환 구조의 이중 체계.

```text
누적 고장 수 m(t)
  ↑
  │           ______ 잠재 총 결함 a
  │      _.-'
  │   .'   (지수형 곡선)
  │ .'
  +────────────────→ 테스트 시간 t
```

```text
[ 1. 테스트 수행 ]
        ↓
[ 2. 결함 발견·수정 ]
        ↓
[ 3. 고장률 점진 감소 ]
        ↓
[ 4. 신뢰도 지표 추정 ]
 (잔존 결함, MTBF)
        ↓
[ 5. 출시 기준 판정 ]
        ↓
[ 6. 출시 결정 ]
```

- **Goel-Okumoto 모델** (Goel-Okumoto Model) : 결함 수정이 완벽하다고 가정하는 지수형 모델로, 평균값 함수는 m(t) = a(1 - e^(-bt))로 표현.
- **Yamada S자형 모델** (Yamada S-shaped Model) : 테스트 초기에는 발견이 완만하고 중기에 급증한 뒤 포화되는 S자 곡선을 따르며, 테스터의 학습 효과를 반영한 모델.

## Ⅳ. 주요 신뢰성 성장 모델의 비교

- 핵심 요약 : 분포 유형과 가정, 시간 기준에 따라 모델마다 적합한 테스트 환경이 달라짐.

| 모델명 | 분포 유형 | 주요 가정 | 적합한 테스트 환경 |
| --- | --- | --- | --- |
| Goel-Okumoto | 지수형 NHPP | 단위 시간당 결함 검출률이 일정 비율로 감소 | 초기부터 정규 테스트가 체계적인 환경 |
| Yamada S-shaped | 지연 S자형 | 테스터의 학습 효과와 결함 격리 시간 반영 | 복잡한 대규모 시스템, 신규 도메인 |
| Jelinski-Moranda | 초기 이산형 | 잔존 결함 하나당 고장률 기여가 동일하다는 가정 | 이론 분석, 단순 모듈 |
| Musa 실행 시간 모델 | 실행 시간 기반 | 달력 시간이 아닌 CPU 실행 시간으로 측정 | 연속 가동 임베디드·통신 장비 |

## Ⅴ. SRGM의 한계와 대응 방안

- 핵심 요약 : 비현실적 가정, 운영 환경과의 괴리, 데이터 품질 결함을 모델 보정과 데이터 자동화로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 완전 디버깅 가정의 비현실성 | 수정 시 새 결함이 유입되지 않는다는 가정 → 신뢰도 예측 왜곡 | 불완전 디버깅 모델과 NHPP 확장 모델로 재유입 가능성 반영 | 예측과 실제 고장의 차이 |
| 테스트 환경과 운영 프로파일의 괴리 | 실험실 데이터의 지표가 실제 사용 패턴에서 맞지 않음 | 운영 로그 기반 사용 프로파일 가중치 적용, 카나리 릴리스로 운영 데이터 결합 | 운영 장애율, 프로파일 일치도 |
| 결함 데이터의 결측·왜곡 | 발생 시각과 수정 시간 누락 → 모델 추정 실패 | 결함 관리 도구와 CI/CD 파이프라인의 메트릭 자동 수집, 소표본에는 베이지안 추정 적용 | 결함 기록 완결률 |

## Ⅵ. 소프트웨어 출시 결정 관점의 기술사적 제언

- 핵심 요약 : 단일 모델 수치에 기대지 않고 신뢰도·잔존 위험·비용을 함께 보는 출시 기준과 불완전 디버깅 모델의 병행 적용.

1. 출시 기준의 복합 적용 : 품질 보증 조직은 SRGM 추정치만으로 출시를 승인하지 않고, 목표 MTBF 달성 여부, 잔존 결함의 위험도, 추가 테스트 비용과 미출시 손실의 균형을 함께 검토해야 한다.
2. 모델 가정 점검 : 데이터 분석 조직은 결함 수정 후 재유입이 관찰되는지 확인하고, 그 결과에 따라 완전 디버깅 모델과 불완전 디버깅 모델 중 하나를 선택해 예측 편차를 줄여야 한다.
3. 데이터 수집 체계화 : 개발 조직은 결함 발생과 수정 기록을 도구에서 자동 수집하여 모델 입력의 품질을 상시 확보해야 한다.

## Ⅶ. 결론

- 핵심 요약 : SRGM은 출시 시점 판단을 과학화하는 정량 신뢰성 체계이며, 가정 보정과 데이터 품질이 예측 정확도의 전제.
- 시사점 : NHPP 기반 추정은 출시 판단의 근거일 뿐이므로, 운영 데이터와 출시 기준을 결합해 해석할 때 의미가 큼.
