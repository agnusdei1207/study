## Ⅰ. SW 신뢰성 성장 모델(SRGM)의 개요

- 개념 : **소프트웨어 신뢰성 성장 모델** (SRGM) 이란 소프트웨어 테스트 단계에서 발견되어 제거되는 결함(고장) 데이터의 시간적 추이를 **비동차 포아송 과정** (NHPP) 등 통계적 수학 모델로 모델링하여, 소프트웨어의 잔존 결함 수, **고장 발생률** (Failure Intensity), **평균 무고장 시간** (MTBF)을 예측하고 최적의 소프트웨어 출시(Release) 시점을 결정하는 공학적 신뢰성 평가 모델.
- 배경 및 필요성 : '언제 테스트를 중단하고 제품을 출시할 것인가?'라는 경영진의 핵심 질문에 대해 감이나 일정이 아닌 과학적이고 정량적인 신뢰성 지표에 기반한 의사결정 기준 제공.
- 핵심 가정 : 테스트가 진행되고 결함이 발견되어 올바르게 수정될수록 소프트웨어의 고장률은 점진적으로 감소하고 신뢰도는 성장한다는 전제.

## Ⅱ. SRGM의 고장 누적 곡선 및 신뢰성 성장 메커니즘

```text
   [ 누적 고장 수 m(t) ]
    ▲
  a │───────────────────────────────────── 잠재 총 결함 수 (점근선 a)
    │                         . - - '
    │                   . - '
    │              . - '
    │          . -'  <지수형 성장 곡선: Goel-Okumoto 모델>
    │        .'      m(t) = a * (1 - e^(-b*t))
    │      .'
    │   .-'
    └──┴───────────────────────────────────> [ 테스트 시간 (t) ]
```

- **고엘-오쿠모토** (Goel-Okumoto) 모델 : 결함 수정 시 새로운 결함이 유입되지 않는다는 **완전 디버깅** (Perfect Debugging)을 가정한 지수형 모델 ($m(t) = a(1 - e^{-bt})$).
- **야마다 S자형** (Yamada S-shaped) 모델 : 테스트 초기에는 테스터의 도메인 숙련도 부족으로 결함 발견이 완만하다가, 중기에 급증하고, 후기에 점차 포화되는 S자 곡선 반영 (현실 프로젝트와 가장 유사).

## Ⅲ. 주요 신뢰성 성장 모델 비교

| 모델명 | 분포 유형 | 주요 특징 및 가정 | 적합한 테스트 환경 |
|---|---|---|---|
| Goel-Okumoto | 지수형 (Exponential NHPP) | 단위 시간당 결함 검출률이 일정 비율로 단순 감소 | 테스트 초기부터 전면적인 정규 테스트가 원활한 환경 |
| Yamada S-shaped | 지연 S자형 (Delayed S-shaped) | 테스터의 학습 효과(Learning Curve)와 결함 격리 시간 반영 | 복잡한 대규모 엔터프라이즈 시스템, 신규 도메인 |
| **Jelinski-Moranda** | 초기 이산형 모델 | 잔존 결함 하나당 고장률 기여도가 동일하다는 단순 가정 | 이론적/학술적 분석, 단순 알고리즘 모듈 |
| **Musa 실행 시간** | 실행 시간(CPU Time) 기반 | 달력 시간이 아닌 실제 시스템이 가동된 CPU 실행 시간 측정 | 24시간 연속 운용 임베디드, 고신뢰 통신 장비 |

## Ⅳ. SW 신뢰성 성장 모델(SRGM)의 주요 한계점 및 해결 방안

- 비현실적 가정(완전 디버깅)으로 인한 신뢰도 예측 왜곡 :
  - 한계점 : 결함을 수정하면 새로운 결함이 도입되지 않고 즉시 제거된다는 전통적 SRGM(Goel-Okumoto 등)의 가정이 실제 환경과 불일치.
  - 해결 방안 : 결함 수정 시 2차 결함이 유입될 확률을 고려하는 불완전 디버깅 모델(Imperfect Debugging Model) 및 비동질 포아송 과정(NHPP) 확장 적용.
- 테스트 환경과 실제 운영 환경 간의 **사용 프로파일** (Operational Profile) 괴리 :
  - 한계점 : 실험실 테스트 데이터 기반으로 도출된 신뢰도 지표가 실제 운영 환경의 불규칙한 사용자 트래픽 및 악의적 패턴 하에서는 무용지물화.
  - 해결 방안 : 실제 운영 로그 기반 사용 프로파일 가중치 적용, 카나리 릴리스 및 프로덕션 섀도잉(Shadowing) 데이터를 결합한 신뢰도 지속 추정.
- 수집된 결함 데이터의 품질 결여 및 결측치 :
  - 한계점 : 프로젝트 현장에서 결함 발생 시각, 수정 시간, 심각도 데이터가 누락되거나 왜곡 기록되어 모델의 수학적 수렴 실패.
  - 해결 방안 : Jira, GitHub Issues 등 결함 관리 도구와 CI/CD 파이프라인의 메트릭 수집 자동 연동, 베이지안 추정법을 활용한 소표본 신뢰성 모델링.

## Ⅴ. 소프트웨어 출시 결정 관점의 기술사적 제언

- 3대 **출시 기준** (Release Criteria)의 복합 적용 : 단일 모델 수치에만 의존하지 말고,
  1. 신뢰도 기준 (목표 MTBF 1,000시간 달성),
  2. 잔존 위험 기준 (목표 잔존 결함률 $95\%$ 이상 제거),
  3. 비용-신뢰성 최적화 기준 (추가 테스트 비용 = 미출시로 인한 장애 손실 비용 교차점)을 종합 평가하여 출시 승인.
- **불완전 디버깅** (Imperfect Debugging) 현실 반영 : 결함 수정 과정에서 새로운 버그가 유입되는 현실적인 상황을 감안하여, 고장률이 일시적으로 반등하는 S-형태의 결함 재유입 파라미터($\alpha$)를 보정한 복합 모델을 채택해야 예측 오차를 최소화할 수 있음.
