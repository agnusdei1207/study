## 30초 인출

- 본질: **소프트웨어 신뢰성 성장 모델(SRGM, Software Reliability Growth Model)** 은 시험 중 관측한 고장 자료로 신뢰도 변화를 추정하는 통계 모델
- 메커니즘: 시간별 고장 자료 수집 → 성장 곡선 모델 선택·적합 → 잔존 결함과 고장률 추정 → 가정·불확실성을 고려해 시험 및 출시 판단
- 통찰: 한계: 관측 고장 자료와 다른 성장 곡선을 맞추면 잔존 결함 추정이 왜곡됨 → 방안: 자료 적합도·모델 가정을 확인하고 출시 판단의 한 근거로만 사용

<details>
<summary>핵심 용어</summary>

- **SRGM(Software Reliability Growth Model)** : 시험 중 관측한 고장 자료에 따라 소프트웨어 신뢰도의 변화를 표현하는 모델
- **NHPP(Nonhomogeneous Poisson Process)** : 발생 강도가 시간에 따라 달라지는 비동질 포아송 과정
- **MLE(Maximum Likelihood Estimation)** : 관측 자료가 가장 그럴듯해지는 모수를 추정하는 최대우도법
- **LSE(Least Squares Estimation)** : 관측값과 모델값의 제곱 오차 합을 최소화하는 최소제곱법
- **MTTF(Mean Time To Failure)** : 수리 불가능한 대상으로 정의할 때 고장까지의 평균 시간
- **Goel-Okumoto 모델** : 테스트 초기부터 결함이 빠르게 발견되다가 시간이 지날수록 발견율이 지수 함수적으로 감소하여 포화되는 오목(Concave) 지수형 모델
- **Yamada S자형 모델** : 테스트 초기에는 테스터의 학습 및 환경 적응으로 결함 발견이 완만하다가, 적응 후 급증한 뒤 최종 포화되는 변곡점을 가진 지연 S자형(Delayed S-shaped) 모델
</details>

## 2~4교시 25점 답안

## Ⅰ. SRGM의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **SRGM** 은 시험 중 관측한 고장 자료로 소프트웨어 신뢰도 변화를 추정하는 통계 모델 |
| 목적 | 잔존 결함과 고장 추세를 추정해 시험 지속 및 출시 판단을 지원 |

## Ⅱ. SRGM의 특징

| 특징 | 해석상 의미 |
|---|---|
| 관측 자료 기반 | 시험의 고장 기록 품질이 추정의 신뢰도를 좌우 |
| 성장 곡선 선택 | 초기 발견 추세에 맞는 모형을 선택·적합 |
| 출시 판단의 보조 근거 | 잔여 결함 추정만으로 운영 위험을 확정할 수 없음 |

## Ⅲ. 고장 자료·모형 체계와 신뢰도 추정 프로세스

### SRGM 분석 및 적용 4대 핵심 절차

```text
시험 시간·고장 관측 자료
    ↓
신뢰도 성장 모델 선택
    ↓
모수 추정·적합도 확인
    ↓
고장 강도·잔여 결함 추정
    ↓
출시 판단의 한 근거로 사용
```

## Ⅳ. 대표 모형과 자료 검증 항목 비교

| 모형 | 관측 곡선 | 적용 판단 |
|---|---|---|
| Goel–Okumoto | 초기에 빠르고 점차 포화되는 오목형 | 누적 고장 추세의 적합도 확인 |
| Yamada 지연 S자형 | 초기 완만·이후 증가·포화 | 시험 초기 학습 지연의 적합도 확인 |


### 적용·검증 관점

### 가정과 자료 검증

모델별 가정과 관측 자료 품질의 동시 검토. 결함 수정 후 새 결함 유입 가능성과 추정 결과에 미치는 영향 확인. 시험 조건·수정 이력을 포함한 고장 자료 관리.

| 검증 항목 | 확인 내용 |
|---|---|
| 자료 적합성 | 고장 기록의 중복·누락과 시험 환경의 일관성 |
| 모델 적합도 | 선택한 성장 곡선이 관측 추세와 맞는지 여부 |
| 해석 범위 | 추정치의 불확실성과 시험·운영 환경의 차이 |

### 출시 판단 적용 범위

비용 기반 출시 시점 산정에는 시험 비용, 운영 후 고장 비용, 서비스 수준 등 별도 입력과 목적 함수 필요. SRGM 신뢰도 추정만으로 최적 출시 시점이 자동 산출된다는 해석은 배제.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 관측 고장 자료와 다른 성장 곡선을 맞추면 잔존 결함 추정이 왜곡됨 | 자료 적합도·모델 가정을 확인하고 출시 판단의 한 근거로만 사용 |
| 관측 환경·시험 강도가 실제 운영과 다를 수 있음 | 시험 조건과 운영 조건의 차이를 명시하고 외삽에 주의 |
| 수정 후 결함이 재유입될 수 있음 | 완전 디버깅 가정의 적합성을 점검하고 필요 시 대안 모델 검토 |
| 표본이 적거나 결함 기록이 불완전할 수 있음 | 자료 품질·모델 적합도를 확인하고 추정치의 불확실성 병기 |

## Ⅵ. 제언

고장 기록의 중복·누락과 모형 적합도를 먼저 확인하고, 추정 잔여 결함을 시험 범위·운영 위험과 함께 출시 심의에 제시한다.
