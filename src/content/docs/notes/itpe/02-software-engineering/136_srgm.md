소프트웨어 공학 → 소프트웨어 개발·운영 → SW 신뢰성 성장 모델(SRGM)

## 지식 위치

소프트웨어공학 > 테스팅·신뢰성 공학 > SW 신뢰성 성장 모델(SRGM)

## 30초 인출

- 본질: 소프트웨어 테스트 과정에서 관측된 고장 간격 시간 및 결함 발견 데이터를 통계적 확률 분포(NHPP 등)에 적합하여 시스템의 잔존 결함 수와 신뢰도 추세를 정량 예측하는 모델
- 메커니즘: 테스트 수행 중 고장 데이터(시간, 결함 수) 수집 → 비동질 포아송 과정(NHPP) 기반 모델(Goel-Okumoto, Yamada S-shaped) 선택 → 모수 추정(MLE/LSE) 및 잔존 결함/고장률 계산 → 최적 출시 시기 판정
- 통찰: 결함 수정 시 새로운 결함이 절대 유입되지 않는다는 완전 디버깅 가정이 실제 프로젝트와 괴리되므로 불완전 디버깅 모델(Imperfection Debugging) 병행 검토 및 위험 기반 테스트 전략 수립 필요

<details>
<summary>핵심 용어</summary>

- **SRGM (Software Reliability Growth Model)** : 시간 경과와 테스트 노력에 따라 소프트웨어 결함이 제거되며 신뢰성이 점진적으로 향상되는 과정을 모델링한 통계적 신뢰도 성장 모델
- **NHPP (Non-Homogeneous Poisson Process)** : 단위 시간당 고장 발생률(강도 함수)이 시간에 따라 변화하는 비동질 포아송 확률 과정
- **Goel-Okumoto 모델** : 테스트 초기에 결함이 급격히 발견되다가 점차 발견율이 지수적으로 감소하는 오목형(Concave) 지수 성장 모델
- **Yamada 지연 S자형 모델** : 테스터의 학습 효과와 초기 환경 적응으로 인해 완만하게 출발한 후 급증하여 포화되는 변곡점을 가진 S자형(S-Shaped) 모델
- **완전 디버깅 (Perfect Debugging)** : 발견된 모든 결함은 즉시 완벽하게 제거되며 새로운 결함이 추가 유입되지 않는다는 이상적 전제 조건
</details>

## 2~4교시 예상문제 (25점)

> 소프트웨어 신뢰성 성장 모델(SRGM)의 개념과 수학적 기본 전제를 설명하고, 대표적인 모형(Goel-Okumoto, Yamada S자형)의 특징 비교 및 최적 소프트웨어 출시 시기(Release Time) 결정 전략을 기술하시오. (25점)

---

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 소프트웨어 테스트 단계에서 발견된 결함 및 고장 발생 시간 데이터를 확률 통계 모델에 적용하여 소프트웨어의 신뢰도 향상 추세와 잠재 잔존 결함 수를 정량 예측하는 수학적 기법 |
| 목적 | 객관적 테스트 종료 기준 수립, 잔존 결함 수 추정을 통한 릴리즈 품질 위험 통제, 테스트 비용과 운영 유지보수 비용 간의 트레이드오프 분석을 통한 최적 출시 시점 결정 |

## Ⅱ. 핵심 특징

| 특징 | 세부 내용 |
|---|---|
| 통계적 확률 과정 기반 | 시간에 따라 결함 발생 강도가 감소하는 비동질 포아송 과정(NHPP)을 기본 프레임워크로 채택 |
| 정량적 품질 예측 | 테스트 실행 시간(CPU 시간, 달력 시간)과 결함 누적 건수를 기반으로 향후 평균 고장 간격(MTTF) 및 잔존 결함 산출 |
| 모수 추정 기법 활용 | 최대우도법(MLE) 또는 최소제곱법(LSE)을 활용하여 수집된 실측 데이터에 가장 적합한 모수($a, b$) 도출 |
| 출시 의사결정 지원 | 목표 신뢰도 도달 여부 및 테스트 연장 비용 vs 결함 미수정 운영 위험 비용을 비교하여 릴리즈 판정 근거 제공 |

주관적 경험이나 일정 압박에 의한 출시를 지양하고 수학적 근거 기반의 릴리즈 거버넌스를 제공하는 핵심 모델로 기능.

## Ⅲ. 체계·프로세스

```text
[1. 결함 관측 데이터 수집]
  - 테스트 수행 시간(t)별 발생 결함 수, 고장 발생 간격 시간 정밀 기록
       │
       ▼ 데이터 분포 패턴 분석
[2. 신뢰성 성장 모델(SRGM) 선정]
  - 초기 결함 급증 패턴: Goel-Okumoto (오목 지수형)
  - 초기 학습 지연 패턴: Yamada (지연 S자형)
       │
       ▼
[3. 통계적 모수 추정 및 적합도 검정]
  - MLE(최대우도법) 또는 LSE(최소제곱법)로 잠재 총 결함수(a), 결함 발견율(b) 추정
  - 카이제곱(Chi-Square) 또는 R² 검정을 통한 모델 적합도 평가
       │
       ▼
[4. 신뢰도 지표 산출 및 출시 시점 결정]
  - 잔존 결함 수: N(t) = a - m(t)
  - 고장 강도 함수: λ(t) = dm(t)/dt
  - 최적 출시 결정: 신뢰도 목표치(R(t) ≥ R_target) 및 총비용 최소화 지점 도출
```

결함 데이터 수집에서 출발하여 모델 선정, 모수 추정, 적합도 검증을 거쳐 잔존 결함 산출 및 최적 릴리즈 시점을 결정하는 단계별 프로세스.

## Ⅳ. 종류·비교

| 비교 항목 | Goel-Okumoto 모델 (지수형) | Yamada 지연 S자형 모델 (Delayed S-shaped) |
|---|---|---|
| **곡선 형태** | 오목형 (Concave Curve) | 변곡점을 가진 S자형 (S-Shaped Curve) |
| **평균 누적 결함 수 $m(t)$** | $m(t) = a(1 - e^{-bt})$ | $m(t) = a(1 - (1 + bt)e^{-bt})$ |
| **고장 강도 함수 $\lambda(t)$** | $\lambda(t) = ab \cdot e^{-bt}$ (단조 감소) | $\lambda(t) = ab^2 t \cdot e^{-bt}$ (증가 후 감소) |
| **초기 결함 발견 특성** | 테스트 초기에 결함이 가장 급격히 발견됨 | 테스터 학습 및 시스템 적응으로 초기 발견 완만 |
| **적합한 프로젝트 환경** | 테스트 도구/인력이 숙련되어 초기 즉시 결함 식별 가능한 환경 | 복잡한 도메인, 신규 테스터 투입, 초기 안정화 지연 환경 |

### 소프트웨어 최적 출시 시기(Release Time) 결정 기준

| 결정 기준 | 판단 메커니즘 | 적용 환경 |
|---|---|---|
| **신뢰도 목표 기준** | 고장 강도 $\lambda(t) \le \lambda_0$ 또는 신뢰도 $R(x\|t) \ge R_{target}$ 달성 시점 | 항공, 의료, 원자력 등 고안전성(Safety-Critical) 시스템 |
| **총비용 최소화 기준** | $C(t) = C_1(t) + C_2(t) + C_3(t)$ (테스트 비용 + 수정 비용 + 운영 결함 비용) 최소 지점 | 일반 엔터프라이즈, 상용 패키지, 웹/모바일 서비스 |
| **일정/예산 한도 기준** | 허용된 개발 기한 및 예산 범위 내에서 도달 가능한 최대 신뢰도 시점 | 납기가 고정된 공공 SI 및 계약 기반 외주 프로젝트 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 결함 수정 시 2차 결함이 발생하지 않는다는 '완전 디버깅' 가정의 비현실성 | 결함 재유입 확률을 반영한 불완전 디버깅 모델(Imperfection Debugging Model) 채택 |
| 테스트 환경(가상 데이터)과 실제 운영 환경(다양한 사용자 패턴)의 부하 차이로 인한 왜곡 | 운영 환경 유사 테스트베드(Staging) 구축 및 카나리/섀도우 트래픽 기반 실측 데이터 보정 |
| 소규모 프로젝트나 테스트 초기의 결함 표본 부족으로 인한 모수 추정 수렴 실패 | 초기 단계에는 정적 분석(소나큐브 등) 결함 지표를 활용하고 테스트 진척도 50% 이후 SRGM 적용 |

## Ⅵ. 제언

단일 통계 모델에 의존한 일방적 출시 결정을 지양하고, SRGM 기반 잔존 결함 예측치와 요구사항 기반 테스트 커버리지, 정적 코드 품질 지표를 통합한 다차원 품질 게이트(Quality Gate) 확립 권장.

```text
[릴리즈 품질 거버넌스 파이프라인]
  테스트 결함 데이터 수집 → SRGM 모수 추정 (잔존 결함 도출) → 비용/신뢰도 최적점 계산 → 통합 품질 게이트 심의
```

| 관리 영역 | 신뢰성 모델링 관점 (SRGM) | 종합 테스트 거버넌스 관점 |
|---|---|---|
| 통제 지표 | 고장 강도 $\lambda(t)$, 잔존 결함 수, MTTF | 구조적 커버리지(C0/C1/MC/DC), 미결 결함 심각도 |
| 의사결정 | 통계적 신뢰도 목표치 충족 여부 판정 | 비즈니스 출시 일정과 결함 리스크 간 최종 승인 |
