## 연관 키워드

- SRGM(Software Reliability Growth Model), 비동차 포아송 과정(NHPP, Non-Homogeneous Poisson Process), 고장 강도(Failure Intensity)
- 평균 무고장 시간(MTBF, Mean Time Between Failures), Goel-Okumoto 모델, Yamada S자형 모델, 불완전 디버깅(Imperfect Debugging), 출시 기준(Release Criteria)

## Ⅰ. SW 신뢰성 성장 모델(SRGM)의 개요

- 핵심 요약 : 테스트 중 발견·제거되는 결함 데이터를 통계 모델로 분석하여 잔존 결함과 출시 시점을 정량 예측하는 신뢰성 평가 모델.
- 개념 : SW 신뢰성 성장 모델(SRGM)이란 소프트웨어 테스트 단계에서 발견되어 제거되는 결함(고장) 데이터의 시간적 추이를 비동차 포아송 과정(NHPP) 등 통계적 수학 모델로 모델링하여, 소프트웨어의 잔존 결함 수, 고장 발생률(Failure Intensity), 평균 무고장 시간(MTBF)을 예측하고 최적의 소프트웨어 출시(Release) 시점을 결정하는 공학적 신뢰성 평가 모델.
- 배경 및 필요성 : '언제 테스트를 중단하고 제품을 출시할 것인가?'라는 경영진의 핵심 질문에 대해 감이나 일정이 아닌 과학적이고 정량적인 신뢰성 지표에 기반한 의사결정 기준 제공.
- 핵심 가정 : 테스트가 진행되고 결함이 발견되어 올바르게 수정될수록 소프트웨어의 고장률은 점진적으로 감소하고 신뢰도는 성장한다는 전제.

## Ⅱ. SRGM의 특징

- 핵심 요약 : NHPP 기반 통계 모델링과 모델별 곡선 형상 차이, 시간 기준 다양성으로 구성되는 정량 신뢰성 예측 체계.

1. 결함 발견·제거 이력의 시간적 추이에 대한 NHPP 기반 통계 모델링.
2. 잔존 결함 수, 고장 발생률, MTBF 등 정량 신뢰성 지표의 예측.
3. 최적 출시 시점(Release Time) 결정의 과학적 의사결정 기준 제공.
4. 지수형(Goel-Okumoto)과 S자형(Yamada) 등 데이터 성격에 따른 모델 선택.
5. 완전 디버깅(Perfect Debugging) 가정의 전통 모델과 불완전 디버깅 확장 모델의 구분.
6. 달력 시간이 아닌 CPU(Central Processing Unit) 실행 시간 기반 측정(Musa 모델)의 가능.

## Ⅲ. SRGM의 구조 (흐름)

- 핵심 요약 : 누적 고장 곡선의 포화 형태와 테스트→수정→신뢰도 성장→출시 판단의 순환 메커니즘.

```text
[ 누적 고장 수 m(t) ]
 ▲
a ─────────────── 잠재 총 결함 수
 │            . - - '
 │        . - '
 │    . - '  (지수형: Goel-Okumoto)
 │  .'        m(t) = a(1 - e^(-bt))
 │.-'
 └──────────────> [ 테스트 시간 (t) ]
```

- 신뢰성 성장 메커니즘의 흐름.

```text
[ 1. 테스트 수행 ]
   │
   ▼
[ 2. 결함 발견·수정 ]
   │
   ▼
[ 3. 고장률 점진 감소 ]
   │
   ▼
[ 4. 신뢰도 지표 추정 ]
 (잔존 결함, MTBF)
   │
   ▼
[ 5. 출시 기준 판정 ]
   │
   ▼
[ 6. 출시(Release) 결정 ]
```

- 고엘-오쿠모토(Goel-Okumoto) 모델 : 결함 수정 시 새로운 결함이 유입되지 않는다는 완전 디버깅(Perfect Debugging)을 가정한 지수형 모델(m(t) = a(1 - e^(-bt))).
- 야마다 S자형(Yamada S-shaped) 모델 : 테스트 초기에는 테스터의 도메인 숙련도 부족으로 결함 발견이 완만하다가, 중기에 급증하고, 후기에 점차 포화되는 S자 곡선 반영(현실 프로젝트와 가장 유사).

## Ⅳ. 주요 신뢰성 성장 모델의 비교

- 핵심 요약 : 분포 유형과 가정, 측정 시간 기준에 따른 모델별 적합 환경의 차별화.

| 모델명 | 분포 유형 | 주요 특징 및 가정 | 적합한 테스트 환경 |
|---|---|---|---|
| Goel-Okumoto | 지수형 (Exponential NHPP) | 단위 시간당 결함 검출률이 일정 비율로 단순 감소 | 테스트 초기부터 전면적인 정규 테스트가 원활한 환경 |
| Yamada S-shaped | 지연 S자형 (Delayed S-shaped) | 테스터의 학습 효과(Learning Curve)와 결함 격리 시간 반영 | 복잡한 대규모 엔터프라이즈 시스템, 신규 도메인 |
| Jelinski-Moranda | 초기 이산형 모델 | 잔존 결함 하나당 고장률 기여도가 동일하다는 단순 가정 | 이론적/학술적 분석, 단순 알고리즘 모듈 |
| Musa 실행 시간 | 실행 시간(CPU Time) 기반 | 달력 시간이 아닌 실제 시스템이 가동된 CPU 실행 시간 측정 | 24시간 연속 운용 임베디드, 고신뢰 통신 장비 |

## Ⅴ. SRGM의 장점과 한계

- 핵심 요약 : 정량적 출시 판단의 장점, 비현실적 가정·사용 프로파일 괴리·데이터 품질 결여 측면의 한계.

- 장점
  1. 감과 일정이 아닌 정량 신뢰성 지표 기반의 출시 의사결정.
  2. 잔존 결함과 MTBF의 수치적 예측을 통한 품질 목표 관리.
  3. 프로젝트 데이터 성격에 맞춘 다양한 모델 선택의 가능.

- 한계점 1 : 비현실적 가정(완전 디버깅)으로 인한 신뢰도 예측 왜곡
  - 한계점 : 결함을 수정하면 새로운 결함이 도입되지 않고 즉시 제거된다는 전통적 SRGM(Goel-Okumoto 등)의 가정이 실제 환경과 불일치.
  - 해결 방안 : 결함 수정 시 2차 결함이 유입될 확률을 고려하는 불완전 디버깅 모델(Imperfect Debugging Model) 및 NHPP 확장 적용.
- 한계점 2 : 테스트 환경과 실제 운영 환경 간의 사용 프로파일(Operational Profile) 괴리
  - 한계점 : 실험실 테스트 데이터 기반으로 도출된 신뢰도 지표가 실제 운영 환경의 불규칙한 사용자 트래픽 및 악의적 패턴 하에서는 무용지물화.
  - 해결 방안 : 실제 운영 로그 기반 사용 프로파일 가중치 적용, 카나리 릴리스 및 프로덕션 섀도잉(Shadowing) 데이터를 결합한 신뢰도 지속 추정.
- 한계점 3 : 수집된 결함 데이터의 품질 결여 및 결측치
  - 한계점 : 프로젝트 현장에서 결함 발생 시각, 수정 시간, 심각도 데이터가 누락되거나 왜곡 기록되어 모델의 수학적 수렴 실패.
  - 해결 방안 : Jira, GitHub Issues 등 결함 관리 도구와 CI/CD(Continuous Integration/Continuous Delivery) 파이프라인의 메트릭 수집 자동 연동, 베이지안 추정법을 활용한 소표본 신뢰성 모델링.

## Ⅵ. 소프트웨어 출시 결정 관점의 기술사적 제언

- 핵심 요약 : 신뢰도·잔존 위험·비용 최적화의 3대 출시 기준 복합 적용과 불완전 디버깅 반영 모델의 채택.
- 3대 출시 기준(Release Criteria)의 복합 적용 : 단일 모델 수치에만 의존하지 않고 아래 3가지 기준의 종합 평가를 통한 출시 승인.

  1. 신뢰도 기준 : 목표 MTBF 1,000시간 달성.
  2. 잔존 위험 기준 : 목표 잔존 결함률 95% 이상 제거.
  3. 비용-신뢰성 최적화 기준 : 추가 테스트 비용과 미출시로 인한 장애 손실 비용의 교차점 분석.
- 불완전 디버깅(Imperfect Debugging) 현실 반영 : 결함 수정 과정에서 새로운 버그가 유입되는 현실적인 상황을 감안하여, 고장률이 일시적으로 반등하는 S-형태의 결함 재유입 파라미터(alpha)를 보정한 복합 모델의 채택을 통한 예측 오차 최소화.

## Ⅶ. 결론

- 핵심 요약 : SRGM은 출시 시점 판단을 과학화하는 정량 신뢰성 체계이며, 현실적 가정 보정과 데이터 품질 확보가 정확도의 전제.
- 요약 : NHPP 기반 결함 추이 모델링을 통한 잔존 결함·MTBF 예측과 최적 출시 시점 결정의 체계화.
- 시사점 : 불완전 디버깅 모델 채택, 운영 프로파일 결합, 결함 데이터 자동 수집의 병행이 신뢰성 예측 신뢰도 확보의 핵심.
