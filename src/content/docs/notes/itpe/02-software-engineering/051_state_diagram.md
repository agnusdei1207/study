## 연관 키워드

- UML, 상태, 전이, 이벤트, 가드 조건
- entry/do/exit 활동, 상태 폭발, 하렐 상태차트, 사가 패턴, 상태 패턴

## Ⅰ. 상태 다이어그램의 개요

- 핵심 요약 : 객체의 생명주기를 이벤트에 따른 상태 전이로 모델링하는 UML 행위 다이어그램.
- 개념 : 객체의 생명주기를 상태와 전이의 관점에서 표현하는 **UML**(Unified Modeling Language) 행위 다이어그램 (**상태 다이어그램**, State Diagram).
- 배경 및 필요성 : 주문·결제처럼 생명주기가 복잡한 객체에서 허용되지 않는 상태 변화가 데이터 무결성을 훼손하는 위험의 상존.
- 주요 목적 : 유효 상태와 허용 전이의 명확한 정의를 통한 객체 생명주기의 검증 가능한 기준 모델 확보.

## Ⅱ. 상태 다이어그램의 특징 및 장점

- 핵심 요약 : 이벤트 구동 모델과 전이 표기법이 객체 생명주기의 규칙을 정밀하게 드러내는 특성.

1. 이벤트 구동 모델링 : 객체가 외부의 **이벤트**(Event)를 받아 **전이**(Transition)를 일으키는 구조 → 허용되지 않는 상태 변화의 설계 단계 점검.
2. 전이 표기법 : `이벤트 [가드 조건] / 액션` 형식으로 **가드 조건**(Guard Condition, 전이 허용의 판단 기준)과 부수 효과를 함께 명시 → 조건부 전이의 정밀한 정의.
3. 내부 활동 명시 : 상태 안에서 실행 시점을 구분하는 **entry/do/exit 활동**(진입·체류·이탈 동작)의 표기 → 자원 획득과 정리 시점의 명확화.
4. 계층·병렬 표현 : **하렐 상태차트**(Harel Statechart)에서 계승한 복합 상태와 직교 영역의 표기 → 대규모 상태 공간의 구조화와 상태 폭발(State Explosion)의 억제.
5. 구현 연계 기반 : 상태 모델이 상태 머신 프레임워크와 상태 패턴 구현의 설계 기준 → 모델과 코드의 정합성 유지.

## Ⅲ. 상태 다이어그램의 구조 (흐름)

- 핵심 요약 : 시작에서 종료까지의 상태 생명주기와, 이벤트에서 전이까지의 처리 순서라는 이중 구조.
- 주문 객체의 생명주기에 상태·이벤트·가드 조건·내부 활동이 배치된 예시.

```text
[ 상태 다이어그램 : 주문 생명주기 ]

● 시작
   ↓ 주문 접수 이벤트
결제 대기 상태
   entry / 결제 안내 발송
   ↓ 결제 완료 이벤트 [기한 이내]
배송 준비 상태
   do / 재고 할당 수행
   ↓ 출고 완료 이벤트
배송 중 상태
   exit / 배송 알림 발송
   ↓ 수령 확인 이벤트
◎ 종료
```

- 하나의 이벤트가 전이로 이어지는 내부 처리 순서.

```text
[ 전이 처리 순서 ]

이벤트 발생
   ↓
가드 조건 평가
   ↓ 참
액션 실행
   ↓
다음 상태로 전이
   (거짓이면 현재 상태 유지)
```

## Ⅳ. 상태 다이어그램과 활동 다이어그램의 비교

- 핵심 요약 : 객체의 체류 중심 모델과 절차의 흐름 중심 모델은 표현 초점과 기본 단위가 서로 다름.

| 비교 축 | 상태 다이어그램 | 활동 다이어그램 |
| --- | --- | --- |
| 표현 초점 | 단일 객체의 생명주기와 상태 변화 | 업무 절차와 활동의 흐름 |
| 기본 단위 | 상태(체류)와 전이 | 활동(작업)과 제어 흐름 |
| 분기 기준 | 이벤트와 가드 조건 | 조건 판단과 병렬 분기 |
| 진행 관점 | 외부 이벤트에 대한 반응 | 절차의 순차·병렬 진행 |
| 대표 활용 | 주문 상태 관리, 임베디드 제어 | 업무 프로세스, 알고리즘 흐름 |

## Ⅴ. 상태 다이어그램의 한계와 방안

- 핵심 요약 : 상태 공간의 팽창, 모델과 코드의 어긋남, 분산 환경의 상태 불일치가 주요 제약.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 상태 폭발 | 속성·동시성 요건의 증가 → 상태·전이 수의 급증과 가독성 저하 | 하렐 상태차트의 복합 상태·직교 영역으로 계층화 | 상태 수, 전이 수 |
| 모델과 코드의 불일치 | 설계 문서의 미갱신 → 기준 모델 신뢰 상실 | 상태 머신 프레임워크 기반 구현 | 모델-코드 불일치 건수 |
| 분산 환경의 상태 불일치 | 서비스 간 비동기 지연·장애 → 전역 상태의 어긋남 | **사가 패턴**(Saga Pattern, 보상 트랜잭션으로 분산 트랜잭션을 대체하는 설계)의 적용 | 보상 트랜잭션 발생 건수 |

## Ⅵ. 상태 모델 운영에 대한 기술사적 제언

- 핵심 요약 : 상태 모델을 설계 문서에 머무르지 않고 구현·검증·변경 관리의 공통 기준으로 운영하는 방향.
- 설계 : **상태 패턴**(State Pattern)으로 상태별 행위를 독립 클래스로 캡슐화하는 구현 표준의 채택.
- 검증 : 상태 전이 표 기반의 전이 커버리지 시험 자동화 체계 구축.
- 거버넌스 : 상태 정의와 전이 규칙의 변경을 아키텍처 검토 절차의 대상으로 편성.

## Ⅶ. 결론

- 핵심 요약 : 상태 다이어그램은 객체 생명주기를 검증 가능한 기준 모델로 만드는 UML 설계 도구.
- 이벤트와 전이 규칙의 명확화가 복잡 도메인 품질 확보의 전제.
