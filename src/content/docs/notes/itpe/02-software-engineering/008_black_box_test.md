## 연관 키워드
- 블랙박스 테스트, 명세 기반, 동등 분할, 경계값 분석, 결정표, 상태 전이

## Ⅰ. 블랙박스 테스트의 개요
- 핵심 요약 : 내부 구현을 보지 않고 입력·상태에 대한 명세와 기대 출력을 기준으로 시험.
- 개념 : 요구사항·인터페이스·업무 규칙에 비추어 관찰 가능한 동작을 검증하는 테스트.
- 필요성 : 사용자 관점 요구 충족을 구현 구조와 독립적으로 확인해야 함.
- 목적 : 명세 오류, 경계·조합 조건 결함 발견.

## Ⅱ. 명세 기반 테스트의 특징과 장점
- 핵심 요약 : 입력 공간을 동등 분할·경계 분석·결정표·상태 전이로 체계화해 대표 조건을 검증.
1. 구현 독립성 : 요구 명세 기준 유지 → 기술 변경에도 검증 관점 일관.
2. 동등 분할 : 같은 결과가 기대되는 입력군 대표값 선택 → 사례 수 감소.
3. 경계값 : 범위 경계 주변 시험 → 비교·오프바이원 오류 발견.
4. 결정표·상태 전이 : 조건 조합과 이력 의존 동작 확인 → 업무 규칙 검증.

## Ⅲ. 테스트 설계 흐름
- 핵심 요약 : 명세를 입력 도메인·조건 조합·상태로 모델링하고 기대 결과를 도출.
```text
명세 분석 → 입력·상태 분할 → 테스트 조건 도출 → 기대 결과 정의 → 실행·결함 기록
```
```text
min-1(무효) | min(유효) | min+1(유효)
max-1(유효) | max(유효) | max+1(무효)
```
- 기법 선택 : 값 범위는 동등분할·경계값, 규칙 조합은 결정표, 이력은 상태 전이.

## Ⅳ. 블랙박스와 화이트박스 비교
- 핵심 요약 : 블랙박스는 외부 명세의 누락·오류, 화이트박스는 코드 경로·조건의 미실행을 찾음.
| 기준 | 블랙박스 | 화이트박스 |
|---|---|---|
| 기준 | 요구·인터페이스 명세 | 코드·제어 흐름 |
| 관점 | 사용자·업무 외부 동작 | 내부 분기·경로 |
| 결함 유형 | 요구 누락, 값·상태 처리 | 미실행 분기, 구현 논리 |
| 보완 관계 | 구조 커버리지와 병행 | 명세 기반 사례와 병행 |

## Ⅴ. 한계와 대응
- 핵심 요약 : 명세가 낮은 품질이면 시험도 불완전하므로 요구 추적과 독립 리뷰를 병행.
| 한계 | 영향 | 대응 |
|---|---|---|
| 명세 누락·모호성 | 기대 결과 정의 불가 | 경계·예외·오류 응답 명세화 |
| 조합 폭발 | 전수 사례 불가 | 위험 기반 선택·pairwise 적용 |
| 내부 경로 미확인 | 미실행 코드 잔존 | 구조 기반 시험과 결합 |

## Ⅵ. 테스트 설계 제언
- 핵심 요약 : QA는 요구 추적표와 위험도를 활용해 기법별 사례와 기대 결과의 근거를 기록.
1. 분석가와 QA는 경계·예외·상태 규칙을 함께 확인.
2. 자동화 담당자는 결정표·상태 모델을 회귀 시험으로 변환.
3. 결함 분석자는 명세·구현 결함을 구분해 요구 품질로 환류.

## Ⅶ. 결론
- 핵심 요약 : 블랙박스 테스트는 사용자에게 보이는 계약을 검증하는 명세 기반 품질 활동.
- 시사점 : 사례의 명세 근거와 기대 결과가 입력값만큼 중요.
