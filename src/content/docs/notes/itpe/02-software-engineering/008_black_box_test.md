## 30초 인출

- 본질: 블랙박스 테스트(Black-box Testing)는 내부 소스코드를 참조하지 않고 요구사항 명세서를 기반으로 기능 및 입출력 동작을 검증하는 시험 기법
- 메커니즘: 입력 도메인을 유효·무효 동치 클래스로 나누는 동등 분할(Equivalence Partitioning)과 경계선 및 인접값을 검증하는 경계값 분석(Boundary Value Analysis)
- 통찰: 동등 분할 대표값만으로는 경계선 부등호 오작동(Off-by-one)을 검출할 수 없으므로 2-Value 및 3-Value 경계값 분석을 결합한 테스트 케이스 설계 적용

<details>
<summary>핵심 용어</summary>

- **블랙박스 테스트(Black-box Testing)** : 소스코드의 내부 논리 구조를 배제하고 외부 인터페이스 및 기능 명세를 기준으로 동작을 검증하는 기법
- **Equivalence Partitioning(동등 분할)** : 입력 도메인을 동일한 결과를 도출할 것으로 예상되는 유효/무효 동치 클래스로 분할하여 대표값을 추출하는 기법
- **Boundary Value Analysis(경계값 분석)** : 결함 발생 확률이 높은 동치 클래스의 경계선과 그 직전·직후 인접값을 테스트 케이스로 선정하는 기법
- **2-Value BVA** : 경계값과 경계 바로 바깥의 인접값을 포함하여 2개 값을 검증하는 표준 방식
- **3-Value BVA** : 경계값, 바로 안쪽 인접값, 바로 바깥 인접값 3개 값을 모두 검증하는 고신뢰성 도메인 검증 방식
- **Decision Table Testing(결정표 시험)** : 여러 복합 논리 조건의 조합과 이에 대응하는 시스템 동작을 매트릭스로 체계화한 기법

## 2~4교시 25점 답안

## Ⅰ. 블랙박스 테스트의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **블랙박스 테스트(Black-box Testing)** 는 내부 구현 코드를 보지 않고 요구사항 명세서에 명시된 기능 규격을 기준으로 입출력 동작을 검증하는 기법 |
| 목적 | 사용자 요구사항 부합성 확인, 비즈니스 로직 결함 식별 및 인터페이스 상호작용 검증 |

## Ⅱ. 블랙박스 테스트의 핵심 특징

| 특징 | 의미 |
|---|---|
| 명세 중심성 | 소스코드 미확보 상태에서도 요구사항 명세서만으로 조기 테스트 케이스 설계 가능 |
| 사용자 관점 검증 | 최종 사용자와 발주자의 관점에서 시스템의 외부 기능 동작 및 예외 처리 적정성 확인 |
| 결함 집중 타겟팅 | 오류 발생 빈도가 높은 도메인 경계와 비즈니스 규칙 조합을 집중 선별하여 테스트 효율화 |

## Ⅲ. 동등 분할과 경계값 분석 설계 메커니즘

### 입력 도메인 분할 및 경계선 식별 구조

```text
[무효 동치 클래스 1]      [유효 동치 클래스]      [무효 동치 클래스 2]
     x < 1                    1 ≤ x ≤ 10                  x > 10
─────────────┬────────────────────────────────────┬─────────────
             │                                    │
           (하한)                               (상한)
    경계값: 0, 1                          경계값: 10, 11
```

### 2-Value 및 3-Value 테스트 케이스 도출 절차

```text
요구사항 명세 분석 및 입력 도메인 식별 (예: 1 ≤ x ≤ 10)
    ↓
동치 분할: 유효 클래스 [1, 10], 무효 클래스 x < 1, x > 10
    ↓
경계값 식별: 하한(1), 상한(10)
    ↓
테스트 케이스 값 선정
    ├─ 동등 분할 대표값: 5 (유효), -3 (무효1), 15 (무효2)
    ├─ 2-Value BVA (경계 + 바깥): 하한(1, 0), 상한(10, 11)
    └─ 3-Value BVA (안쪽 + 경계 + 바깥): 하한(2, 1, 0), 상한(9, 10, 11)
```

| 기법 유형 | 검증 대상 클래스 | 테스트 입력값 | 기대 결과 |
|---|---|---|---|
| 동등 분할 | 유효 클래스 대표값 | 5 | 정상 승인 처리 |
| 동등 분할 | 무효 클래스 (하한 미만) | -3 | 오류 메시지 출력 및 차단 |
| 동등 분할 | 무효 클래스 (상한 초과) | 15 | 오류 메시지 출력 및 차단 |
| 2-Value BVA | 하한 경계선 검증 | 0, 1 | 0: 차단, 1: 승인 |
| 2-Value BVA | 상한 경계선 검증 | 10, 11 | 10: 승인, 11: 차단 |
| 3-Value BVA | 하한 정밀 경계선 | 0, 1, 2 | 0: 차단, 1: 승인, 2: 승인 |
| 3-Value BVA | 상한 정밀 경계선 | 9, 10, 11 | 9: 승인, 10: 승인, 11: 차단 |

## Ⅳ. 블랙박스 테스트와 화이트박스 테스트 비교

| 비교 항목 | 블랙박스 테스트 (Black-box) | 화이트박스 테스트 (White-box) |
|---|---|---|
| 주요 검증 기준 | 요구사항 명세서, 비즈니스 규칙 | 소스코드 구조, 제어 흐름, 데이터 흐름 |
| 적용 테스트 레벨 | 시스템 테스트, 인수 테스트 중심 | 단위 테스트, 모듈 통합 테스트 중심 |
| 주요 수행 주체 | 전문 테스터, QA 엔지니어, 최종 사용자 | 소프트웨어 개발자, 보안 코드 분석가 |
| 핵심 테스트 기법 | 동등 분할, 경계값 분석, 결정표 시험 | 구문 커버리지, 분기 커버리지, MC/DC |
| 발견 용이 결함 | 명세 미준수, 기능 누락, 인터페이스 결함 | 미사용 코드, 데드락, 메모리 누수, 내부 분기 오류 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 동등 분할의 대표값만 선정할 경우 경계 부등호 연산 오류(Off-by-one) 미검출 | 경계선 및 직전·직후 값을 전수 커버하는 2-Value 또는 3-Value 경계값 분석 필수 병행 |
| 다중 입력 파라미터 환경에서 조건 조합 수가 기하급수적으로 폭증(조합 폭발) | 직교배열표(Orthogonal Array) 또는 페어와이즈(Pairwise) 테스팅 기법 도입 |
| 자연어로 기술된 명세서의 모호성으로 인한 테스터별 케이스 편차 발생 | Given-When-Then 기반의 BDD 명세화 및 **RTM(Requirements Traceability Matrix)** 연계 |

## Ⅵ. 제언

도메인 위험도 기반 명세 테스트 기법 다각화와 페어와이즈 기반 테스트 케이스 최적화

### 명세 기반 기법 최적화 포트폴리오 선정 체계

```text
요구사항 명세 특성 분석
    ↓
입력 유형별 기법 매핑
    ├─ 연속형·순서형 단일 입력 → 동등 분할 + 3-Value 경계값 분석
    ├─ 복합 논리 규칙 및 상호작용 → 결정표 시험(Decision Table)
    ├─ 시간 경과 및 상태 전이 → 상태 전이 테스팅(State Transition)
    └─ 다차원 조합 변수 다수 → 페어와이즈(Pairwise) 테스팅
    ↓
테스트 케이스 중복 제거 및 커버리지 최적화
```

### 페어와이즈(Pairwise) 기반 조합 최적화 절차

```text
입력 변수 N개 및 요인별 수준(Level) 정의
    ↓
모든 2개 변수 쌍의 상호작용 전수 포함 조합 행렬 생성
    ↓
테스트 케이스 수 대폭 축소 (수만 개 → 수십 개)
    ↓
실행 우선순위 부여 후 테스트 자동화 도구 연계
```

### 선택 근거: 전수 조합과 페어와이즈 최적화 비교

| 구분 | 전수 조합 시험 (Full Combinatorial) | 제언: 페어와이즈 최적화 (Pairwise) |
|---|---|---|
| 케이스 규모 | 변수 수 증가 시 수만~수십만 개 폭증 | 모든 쌍(Pair) 검증으로 수십~수백 개 압축 |
| 결함 검출력 | 이론상 100%이나 수행 불가로 누락 발생 | 실무 결함의 80~90% 이상 조기 식별 |
| 비용 대비 효율 | 납기 지연 및 테스트 예산 초과 유발 | 최소 비용으로 최대 결함 검출 효율 달성 |
