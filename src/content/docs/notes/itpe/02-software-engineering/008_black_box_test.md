## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 테스트·검증 → **블랙박스 테스트(명세 기반 기법)**

## 30초 인출

- 본질: 블랙박스 테스트는 내부 코드를 보지 않고 요구 명세의 입력과 기대 출력만으로 기능을 검증하는 테스트
- 메커니즘: 입력 명세를 동일하게 처리되는 동치 클래스로 나누고(동등 분할) 클래스 경계에서 값을 추가로 선정(경계값 분석)해 테스트 케이스 도출
- 통찰: 입력 조합이 많아 전수 시험이 불가능하고 결함은 경계에 몰리므로 동등 분할로 클래스별 대표값을 줄이고 경계값 분석으로 경계 값을 보강

<details>
<summary>핵심 용어</summary>

- **블랙박스 테스트(Black-box Testing)** : 내부 구조를 배제하고 명세의 입력과 기대 출력으로 기능을 검증하는 테스트
- **동등 분할(Equivalence Partitioning)** : 입력 도메인을 같은 결과를 내는 클래스로 나누고 클래스마다 대표값을 시험하는 기법
- **경계값 분석(Boundary Value Analysis)** : 동치 클래스의 경계와 그 주변 값을 시험하는 기법
- **결정표(Decision Table)** : 조건 조합과 그에 대응하는 동작을 표로 정리해 케이스를 도출하는 기법
- **분류 트리(Classification Tree)** : 입력 특성을 트리로 분류하고 조합해 테스트 케이스를 도출하는 기법
- **오류 추측(Error Guessing)** : 경험으로 결함이 잘 생기는 입력을 추측해 시험하는 경험 기반 기법

</details>

## 2~4교시 25점 답안

## Ⅰ. 블랙박스 테스트의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **블랙박스 테스트** 는 내부 구조 없이 명세의 입력과 기대 출력만으로 기능을 검증하는 테스트 |
| 목적 | 요구사항 충족 여부의 확인과 명세 미준수·기능 누락의 발견 |

## Ⅱ. 화이트박스 테스트와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 명세 기반 | 요구사항·비즈니스 규칙에서 케이스 도출 |
| 구현 독립 | 코드 구조 변경과 무관하게 케이스 재사용 |
| 시스템·인수 단계 중심 | 사용자 관점의 기능 검증 |

## Ⅲ. 동등 분할과 경계값 분석의 설계

### 입력 명세의 클래스와 경계 (점수 0~100 정수 입력)

```text
무효 클래스      유효 클래스        무효 클래스
 x < 0          0 ≤ x ≤ 100         x > 100
       ↑ 하한 경계 0        상한 경계 100 ↑
(정수가 아닌 입력도 별도 무효 클래스)
```

### 테스트 케이스 도출 절차

```text
입력 명세 분석
    ↓
동등 분할: 유효·무효 클래스 식별, 클래스별 대표값 선정
    ↓
경계값 분석: 클래스 경계와 인접값 선정
    ↓
기대 결과와 함께 테스트 케이스 정리
```

| 기법 | 입력값 | 기대 결과 |
|---|---|---|
| 동등 분할(유효) | 50 | 정상 처리 |
| 동등 분할(무효) | -5, 105, 문자 | 오류 처리 |
| 경계값 분석(하한) | -1, 0, 1 | 오류, 정상, 정상 |
| 경계값 분석(상한) | 99, 100, 101 | 정상, 정상, 오류 |

## Ⅳ. 테스트 기법의 분류와 블랙박스·화이트박스의 비교

### 블랙박스와 화이트박스의 비교

| 비교 항목 | 블랙박스 | 화이트박스 |
|---|---|---|
| 기준 | 요구 명세 | 소스 코드 구조 |
| 주 적용 | 시스템·인수 테스트 | 단위·통합 테스트 |
| 대표 기법 | 동등 분할, 경계값 분석, 결정표 | 구문·결정·조건 커버리지 |
| 발견 결함 | 기능 누락, 명세 불일치 | 미실행 코드, 논리 오류 |

### 명세 기반·구조 기반·경험 기반 기법

| 분류 | 기법 |
|---|---|
| 명세 기반 | 동등 분할, 경계값 분석, 결정표, 상태 전이, 분류 트리, 원인-결과 그래프 |
| 구조 기반 | 구문·결정·조건 커버리지, MC/DC, 경로 시험 |
| 경험 기반 | 오류 추측, 탐색적 테스트, 체크리스트 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 입력 조합이 많아 전수 시험 불가 | 동등 분할로 클래스별 대표값 선정 |
| 경계가 명세에 모호하게 기술되어 경계값 누락 | 명세의 범위·포함 여부 확인 후 경계 양쪽 값 시험 |
| 여러 조건의 조합 결함 미검출 | 결정표로 조건 조합을 케이스화 |
| 내부 로직 결함 미확인 | 화이트박스 시험 병행 |

## Ⅵ. 제언

입력 명세마다 유효·무효 클래스와 경계를 먼저 표로 정리하고, 클래스 대표값과 경계 양쪽 값으로 케이스 구성

### 케이스 구성 순서

```text
입력 명세의 유효·무효 클래스 표 작성
    ↓
클래스별 대표값 1개 선정
    ↓
경계값 양쪽(경계·바깥·안쪽) 추가
```

### 확대: 조합 조건 처리

```text
입력 조건이 여럿
    ├─ 단일 입력 → 동등 분할·경계값
    └─ 조건 조합 → 결정표
```

### 선택 근거: 무작위 입력과의 비교

| 구분 | 무작위 입력 | 제언: 클래스·경계 기반 |
|---|---|---|
| 케이스 수 | 많음 | 클래스 수에 비례 |
| 경계 결함 발견 | 우연 | 경계값 선정 |
| 근거 추적 | 곤란 | 명세와 연결 |
