## 연관 키워드

- 블랙박스 테스트, 명세 기반 테스트(Specification-based Testing), 동등 분할(EP, Equivalence Partitioning)
- 경계값 분석(BVA, Boundary Value Analysis), 의사결정표(Decision Table), 상태 전이(State Transition), 유스케이스 테스팅

## Ⅰ. 블랙박스 테스트의 개요

- 핵심 요약 : 내부 구조와 무관하게 요구사항 명세 기반으로 기능적 정확성을 검증하는 테스트 기법 체계.
- 개념 : 소프트웨어의 내부 코드 구조를 들여다보지 않고 요구사항 명세서(SRS, Software Requirements Specification)와 입력/출력 사양을 바탕으로 기능적 정확성을 검증하는 명세 기반(Specification-based) 테스트 기법.
- 배경 및 필요성 : 코드 복잡성에 구애받지 않는 사용자 관점의 요구사항 충족 여부 판별, 단위·통합·시스템·인수 테스트 전 단계 적용 필요.
- 핵심 목적 : 기능 누락(Omission), 인터페이스 결함, 경계 영역 오류, 예외 처리 미흡 등 명세 불일치 결함의 검출.

## Ⅱ. 블랙박스 테스트의 특징

- 핵심 요약 : 명세 의존적 관점과 전 테스트 레벨 적용성, 최소 케이스 최대 커버리지 지향.

1. 내부 코드 구조에 의존하지 않는 명세 기반(Specification-based) 설계.
2. 사용자 관점의 요구사항 충족 여부 판별.
3. 단위·통합·시스템·인수 테스트 전 단계 적용 가능.
4. 동등 분할과 경계값 분석의 조합을 통한 최소 테스트 최대 커버리지.
5. 화이트박스 테스트와의 상호 보완적 결합(그레이박스) 지향.

## Ⅲ. 블랙박스 테스트의 구조 (흐름)

- 핵심 요약 : 명세 분석 → 도메인 분할 → 케이스 도출 → 결과 검증의 절차와 대표 기법의 동작 원리.
- 블랙박스 테스트 수행 절차.

```text
[ 요구사항 명세 분석 ]
   · 명세 기반 분석
      │
      ▼
[ 입력 도메인 분할 ]
   · 유효/무효 영역
      │
      ▼
[ 테스트 케이스 도출 ]
   · 입력값·예상 결과
      │
      ▼
[ 결과 비교·검증 ]
   · Pass/Fail 판정
```

- 동등 분할(EP, Equivalence Partitioning) : 입력 도메인을 결과가 동일할 것으로 예상되는 유효 동등 클래스(Valid Class)와 무효 동등 클래스(Invalid Class)로 분할, 각 클래스의 대표값 추출을 통한 최소 테스트 최대 커버리지 달성.
- 경계값 분석(BVA, Boundary Value Analysis) : 오류 발생 확률이 가장 높은 동등 분할 영역의 경계선(Boundary)에 집중하는 기법, 2-포인트(경계값, 경계값 바로 바깥값) 또는 3-포인트(경계값 바로 안쪽, 경계값, 경계값 바로 바깥값) 선정을 통한 $N-1, N, N+1$ 테스트 케이스 도출.

```text
[ 동등 분할 및 경계값 도식 ]
  무효 클래스            유효 클래스             무효 클래스
   ( N < 0 )          ( 0 ≤ N ≤ 100 )          ( N > 100 )
               │    │               │    │
       -1    0    1   ·····    99   100   101
        ▲    ▲                 ▲    ▲
       바깥값 안쪽값            경계값 바깥값   (3-포인트 기준)
```

## Ⅳ. 블랙박스 테스트 기법별 비교

- 핵심 요약 : 설계 원리와 검증 대상이 상이한 5대 명세 기반 기법의 활용 구분.

| 기법 | 설계 원리 | 주 검증 대상 및 장점 |
|---|---|---|
| 동등 분할(EP) | 입력 도메인의 상호 배타적 클래스 분할 후 대표값 추출 | 입력값 조합 폭발 방지, 전반적 기능 적합성 검증 |
| 경계값 분석(BVA) | 분할 영역의 최소/최대 경계값 및 인접값 추출 | 조건문 등호/부등호 오류, 오프바이원(Off-by-One) 결함 탐지 |
| 의사결정표(Decision Table) | 복잡한 조건(Condition)과 행동(Action)의 표 정형화 | 여러 조건이 얽힌 복합 비즈니스 룰의 누락 없는 검증 |
| 상태 전이(State Transition) | 시스템의 상태, 이벤트, 전이, 액션 관계 다이어그램 모델링 | 상태 기반 임베디드 기기, 인증/결제 프로세스 누락 검증 |
| 유스케이스 테스팅(Use Case) | 액터와 시스템 간 상호작용 시나리오 기반 케이스 작성 | 실제 비즈니스 흐름 및 통합 시나리오 정합성 검증 |

## Ⅴ. 블랙박스 테스트의 장점과 한계

- 핵심 요약 : 사용자 관점·전 레벨 적용의 장점, 내부 경로 미검증·조합 폭발·명세 품질 종속의 한계.
- 장점
  1. 코드 복잡성과 무관한 요구사항 충족 여부 검증.
  2. 단위부터 인수까지 전 테스트 레벨 적용 가능.
  3. 최소 케이스로 최대 커버리지를 달성하는 기법 체계.
- 한계점 1 : 내부 구현 경로 미검증으로 인한 데드코드 및 예외 로직 누락
  - 한계점 : 명세 기반 설계 특성상 소스코드 내부의 비정상 처리 분기문, 복잡한 중첩 루프, 미실행 데드 코드(Dead Code) 등 내부 구조적 결함 검출 불가.
  - 해결 방안 : 화이트박스 테스트(구문/조건 커버리지) 및 정적 코드 분석(SonarQube)과의 상호 연계 그레이박스 테스팅(Gray-Box Testing) 체계 구축을 통한 검증 사각지대 해소.
- 한계점 2 : 입력 도메인 조합 폭발(Combinatorial Explosion)로 인한 테스트 비효율
  - 한계점 : 다수 파라미터·조건의 상호작용 환경에서 동등 분할과 경계값 분석의 전수 조합 시 테스트 케이스 수 급증으로 현실적 일정 내 수행 불가.
  - 해결 방안 : 대부분의 결함이 2개 인자의 상호작용에서 기인한다는 원리 기반 페어와이즈(Pairwise/All-Pairs) 테스팅 및 직교 배열표(Orthogonal Array) 기법 적용을 통한 케이스 최적 축소.
- 한계점 3 : 요구사항 명세서(SRS)의 품질 종속성
  - 한계점 : 명세의 모호함, 누락, 잦은 변경 발생 시 테스트 설계 기준의 흔들림 및 유효하지 않은 테스트 케이스 양산.
  - 해결 방안 : BDD(Behavior Driven Development) 기반 Given-When-Then 문법의 실행 가능한 명세(Executable Specification) 작성, 요구사항 추적 매트릭스(RTM, Requirements Traceability Matrix) 기반 형상 연계 강화.

## Ⅵ. 블랙박스 테스트 효율화를 위한 기술사적 제언

- 핵심 요약 : 페어와이즈 조합 통제와 요구사항-테스트 케이스 양방향 추적성 의무화.
- 페어와이즈(Pairwise) 테스팅을 통한 조합 폭발 통제 : 전수 조합 테스트의 불가능성 전제, 대부분의 결함이 소수 인자의 상호작용에서 비롯된다는 원리 기반 페어와이즈 조합 기법 적용 권장.
- 요구사항 추적 매트릭스(RTM)와의 1:1 매핑 의무화 : 명세 누락 및 테스트 사각지대 방지를 위한 요구사항 ID와 블랙박스 테스트 케이스 ID 간 양방향 추적성 확보, 인수 테스트의 공학적 신뢰도 제고.

## Ⅶ. 결론

- 핵심 요약 : 블랙박스 테스트는 명세 기반 기능 검증의 기본 골격으로 화이트박스와 상호 보완.
- 요약 : 동등 분할·경계값 분석 중심의 명세 기반 기법이 사용자 관점 품질 검증의 골격.
- 시사점 : 그레이박스 연계, 조합 최적화 기법, 요구사항 추적성 확보가 테스트 효율·신뢰도 동시 제고의 핵심.
