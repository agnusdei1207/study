## 지식 위치

소프트웨어공학 > 소프트웨어 유지보수 > SW 유지보수 3R

## 30초 인출

- 본질: 레거시 시스템의 유지보수성 향상과 소프트웨어 위기 극복을 위해 기존 소프트웨어 자산을 분석(역공학), 구조 개선(재공학), 부품화하여 다시 활용(재사용)하는 3가지 공학적 생명주기 순환 체계
- 메커니즘: 원시 코드/DB로부터 상위 설계 사양 복원(역공학) → 비즈니스 로직 보존 및 아키텍처 현대화/리팩토링(재공학) → 컴포넌트화 및 표준 라이브러리 등록을 통한 타 시스템 적용(재사용)
- 통찰: 문서 부재 상태에서 무리한 빅뱅(Big-Bang) 재구축 시 비즈니스 룰 유실 및 대형 장애가 발생하므로 역공학 기반의 테스트베드 확보 후 스트랭글러 패턴(Strangler Fig Pattern)을 통한 점진적 재공학 추진 필수

<details>
<summary>핵심 용어</summary>

- **역공학 (Reverse Engineering)** : 이미 구현된 소스 코드나 바이너리를 분석하여 데이터 모델, 설계 명세서, 시스템 요구사항 등 상위 추상화 산출물을 도출하는 기술
- **재공학 (Re-engineering)** : 기존 시스템의 비즈니스 기능과 가치를 보존하면서 유지보수성, 성능, 확장성을 개선하기 위해 소프트웨어 구조를 전면 재구성하는 기술
- **재사용 (Reuse)** : 기 구축되어 신뢰성이 검증된 소프트웨어 모듈, 컴포넌트, 프레임워크, 아키텍처 설계를 새로운 시스템 구축에 다시 활용하는 행위
- **리팩토링 (Refactoring)** : 소프트웨어의 외부적 동작(기능)은 변경하지 않고 내부 코드 구조를 개선하여 가독성과 유지보수성을 극대화하는 재공학 기법
- **스트랭글러 패턴 (Strangler Fig Pattern)** : 노후화된 모놀리식 레거시 시스템의 기능을 마이크로서비스로 점진적으로 이전하여 무중단으로 신규 시스템으로 완전 대체하는 현대화 패턴
</details>

## 2~4교시 예상문제 (25점)

> 레거시 시스템 현대화 및 소프트웨어 유지보수를 위한 3R(역공학, 재공학, 재사용)의 개념과 유기적 연계 프로세스를 설명하고, 유지보수 4대 유형과의 매핑 및 성공적 레거시 전환 방안(스트랭글러 패턴)을 제시하시오. (25점)

---

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 레거시 소프트웨어의 노후화 및 유지보수 비용 급증 문제를 해결하기 위해 기존 자산을 분석하여 설계를 복원(역공학)하고, 현대적 기술 구조로 재구성(재공학)하며, 검증된 모듈을 표준 자산화(재사용)하는 일련의 공학적 기법 |
| 목적 | 유지보수 비용 절감, 시스템 복잡도 완화, 누적된 기술 부채 해소, 기존 비즈니스 자산의 가치 보존 및 개발 생산성 극대화 |

## Ⅱ. 핵심 특징

| 특징 | 세부 내용 |
|---|---|
| 상향식 지식 추출 (Bottom-Up) | 문서가 유실된 레거시 시스템의 코드와 데이터베이스로부터 상위 수준의 설계 모델(ERD, 클래스도)을 자동 복원 |
| 비즈니스 무결성 보존 | 재공학 과정에서 시스템의 핵심 비즈니스 로직과 데이터 정합성을 그대로 유지하면서 아키텍처만 현대화 |
| 자산 재활용의 선순환 | 재공학된 모듈을 표준 컴포넌트 저장소에 등록하여 향후 신규 프로젝트의 개발 비용과 기간 단축 |
| 점진적 위험 통제 | 전체를 일시에 뒤엎는 재개발의 위험성을 회피하고 모듈 단위로 점진적 분할 및 전환 가능 |

소프트웨어의 전체 수명주기 비용 중 70% 이상을 차지하는 유지보수 단계를 통제하는 핵심 체계로 기능.

## Ⅲ. 체계·프로세스

```text
[1. 레거시 시스템 (Legacy System)]
  - 소스코드(COBOL/C/기존 Java), DB 스키마, 화면 정의서
       │
       ▼ [역공학 (Reverse Engineering)]
[2. 상위 설계 산출물 복원]
  - 코드 정적 분석 ──► 호출 관계 그래프, 비즈니스 룰 추출
  - DB 역공학     ──► 논리 ERD 및 데이터 사전 복원
       │
       ▼ [재공학 (Re-engineering)]
[3. 현대화 및 구조 개선]
  - 리팩토링(Refactoring) 및 모듈화: 코드 스멜 제거
  - 플랫폼 마이그레이션: 온프레미스 레거시 ──► 클라우드 네이티브 MSA
  - 데이터 재구조화: 노후 DB 정규화 및 분산 DB 전환
       │
       ▼ [재사용 (Reuse)]
[4. 자산화 및 통합 활용]
  - 공통 비즈니스 컴포넌트 및 API 추출
  - 사내 컴포넌트 저장소(Repository) 등록 ──► 신규 시스템 구축 시 조립 활용
```

역공학을 통한 설계 복원, 재공학을 통한 클라우드 네이티브 현대화, 컴포넌트 재사용으로 이어지는 유기적 순환 프로세스.

## Ⅳ. 종류·비교

| 비교 항목 | 역공학 (Reverse Engineering) | 재공학 (Re-engineering) | 재사용 (Reuse) |
|---|---|---|---|
| **핵심 목적** | 현행 시스템의 설계 및 동작 원리 이해 | 시스템 품질 및 유지보수성 개선 | 개발 생산성 극대화 및 중복 투자 방지 |
| **추상화 방향** | 하향(코드) ──► 상향(설계/요구사항) | 현행 구조 ──► 개선된 신규 구조 | 기 구축 자산 ──► 타 시스템 적용 |
| **주요 활동** | 정적/동적 코드 분석, 데이터 복원 | 리팩토링, 플랫폼 이식, 데이터 정제 | 컴포넌트 검색, 적합성 평가, 어댑터 조립 |
| **핵심 기법/도구** | 디컴파일러, 소나큐브, ERD 리버스 도구 | 스트랭글러 패턴, 도메인 주도 설계(DDD) | CBD 저장소, 마이크로서비스 API, 라이브러리 |
| **산출물** | 논리 ERD, 클래스 다이어그램, API 명세서 | 클라우드 MSA 시스템, 최적화된 소스코드 | 재사용 컴포넌트 라이브러리, 표준 프레임워크 |

### 유지보수 4대 유형과 3R의 매핑 비교

| 유지보수 유형 | 주요 목적 | 3R 활동 연계 및 기여 |
|---|---|---|
| **수정 유지보수 (Corrective)** | 운영 중 발견된 잠재 결함 및 에러 수정 | 역공학을 통해 에러 발생 지점의 영향도 분석 및 디버깅 수행 |
| **적응 유지보수 (Adaptive)** | OS, 하드웨어, DBMS 등 외부 환경 변화 대응 | 재공학을 통해 최신 런타임 및 클라우드 플랫폼으로 이식 |
| **완전 유지보수 (Perfective)** | 사용자 신규 요구 수용 및 성능/기능 향상 | 검증된 컴포넌트 재사용 및 재공학 기반 기능 확장 |
| **예방 유지보수 (Preventive)** | 미래 결함 예방 및 유지보수성 향상 (기술부채 제거) | 리팩토링 기반 재공학을 통해 코드 가독성 향상 및 복잡도 제거 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 소스코드 난독화, 주석 부재, 개발자 퇴사로 인해 역공학을 통한 완벽한 비즈니스 로직 복원 한계 | 동적 트레이싱 도구(APM)를 활용한 런타임 트래픽 분석과 도메인 전문가 인터뷰(이벤트스토밍) 병행 |
| 재공학 수행 중 기존 레거시 시스템의 핵심 비즈니스 룰 유실 및 사이드 이펙트 발생 | 재공학 전 자동화된 E2E 블랙박스 회귀 테스트 케이스(Regression Test Suite)를 선행 구축 |
| 무분별한 재사용 시 서드파티 라이브러리의 보안 취약점 및 숨겨진 결함이 신규 시스템으로 전파 | 소프트웨어 자재명세서(SBOM) 점검 및 의존성 취약점 스캐너(OWASP Dependency-Check) 연계 |

## Ⅵ. 제언

빅뱅 방식의 전면 재구축을 지양하고, API 게이트웨이 뒷단에서 레거시 기능을 도메인 단위로 단계적 분리·전환하는 스트랭글러 피그(Strangler Fig) 패턴 기반의 안전한 재공학 거버넌스 확립 필요.

```text
[스트랭글러 패턴 기반 점진적 현대화 아키텍처]
  클라이언트 요청 → API Gateway (트래픽 라우팅)
                        ├─ 레거시 영역 : 구형 모놀리스 (역공학 기반 점진 축소)
                        └─ 신규 영역   : 신규 마이크로서비스 (재공학 및 재사용 컴포넌트 조립)
```

| 검증 단계 | 사전 준비 단계 (역공학) | 단계적 전환 단계 (재공학·재사용) |
|---|---|---|
| 핵심 통제 | 레거시 데이터 모델 및 인터페이스 전수 리버스 | 섀도우 트래픽(Shadowing) 기반 신·구 시스템 응답 정합성 검증 |
| 전환 목표 | 숨겨진 비즈니스 룰 100% 명세화 | 무중단 롤링 전환 및 최종 레거시 폐기(Decommissioning) |
