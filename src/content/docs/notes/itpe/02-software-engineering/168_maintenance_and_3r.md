## 연관 키워드

- 유지보수(Maintenance), 역공학(Reverse Engineering), 재공학(Re-engineering), 재사용(Reuse)
- ISO/IEC 14764 유지보수 4대 유형, 스트랭글러 피그 패턴(Strangler Fig Pattern), 레거시 시스템 현대화

## Ⅰ. SW 유지보수 및 3R의 개요

- 핵심 요약 : 인도 후 소프트웨어 생명주기를 연장하는 유지보수 활동과 그 실천 기술인 역공학·재공학·재사용의 3R 체계.
- 개념 : 소프트웨어(SW, Software)가 고객에게 인도된 후 발견된 결함의 수정, 변경 운영 환경에의 적응, 신규 기능 요구의 반영을 통해 생명주기를 연장하는 유지보수(Maintenance) 활동과, 이를 공학적으로 실천하기 위한 핵심 3대 기술인 역공학(Reverse Engineering), 재공학(Re-engineering), 재사용(Reuse)의 3R 체계.
- 배경 및 필요성 : 전체 소프트웨어 생명주기 비용의 대부분이 유지보수 단계에서 소모, 시간 경과에 따른 시스템 노후화와 아키텍처 침식을 설명하는 레만의 소프트웨어 진화 법칙(Lehman's Laws of Software Evolution) 대응 필요.
- 주요 목적 : ISO(International Organization for Standardization)/IEC(International Electrotechnical Commission) 14764의 유지보수 4대 분류(수정(Corrective), 적응(Adaptive), 완전(Perfective), 예방(Preventive)) 관리를 통한 레거시 자산의 지속 가치 확보.

## Ⅱ. 유지보수 3R의 특징

- 핵심 요약 : 코드로부터 설계를 복원하고 구조를 개선하며 검증 자산을 재활용하는 순환적 공학 체계.

1. 역공학(Reverse Engineering)의 소스코드 기반 상위 설계·아키텍처 복원(Design Recovery).
2. 재공학(Re-engineering)의 기능 유지 조건 하 내부 구조 개선(리팩토링, 마이그레이션).
3. 재사용(Reuse)의 검증된 컴포넌트·지식·테스트 스위트의 신규 개발 재활용.
4. ISO/IEC 14764 기준 수정·적응·완전·예방 유지보수의 4대 유형 분류 관리.
5. 레거시 시스템의 단계적 현대화(Modernization)를 지원하는 점진적 접근.
6. 도메인 지식과 문서화 자산의 지속 축적을 통한 유지보수성 향상.

## Ⅲ. 유지보수 3R의 구조 (흐름)

- 핵심 요약 : 레거시 코드에서 출발해 역공학→재공학→재사용으로 이어지는 자산화 순환 흐름.
- 3R(역공학·재공학·재사용) 순환 프로세스.

```text
[ 레거시 시스템 (Legacy Source Code) ]
    │
    ▼ (1. 역공학: Reverse Engineering)
[ 고수준 아키텍처 및 설계 복원 ]
  - Design Recovery
  - 소스코드로부터 DFD(Data Flow
    Diagram), ERD(Entity-Relationship
    Diagram), 클래스 추출
    │
    ▼ (2. 재공학: Re-engineering)
[ 구조 개선 및 리팩토링 ]
  - Restructuring / Redesign
  - 코드 스멜 제거, 클라우드
    아키텍처 현대화
    │
    ▼ (3. 재사용: Reuse)
[ 고품질 재사용 컴포넌트 자산화 ]
  - Core Asset
  - 신규 차세대 프로젝트 조립 재사용
```

- 역공학(Reverse Engineering) : 구현된 소스코드, 실행 파일, DB(Database) 스키마로부터 상위 수준의 분석·설계 명세서(문서)와 아키텍처를 복원하는 공학적 분석 기법.
- 재공학(Re-engineering) : 기존 시스템의 유지보수성 향상을 위해 기능은 유지하면서 시스템 내부 구조를 변경·개선(리팩토링, 마이그레이션)하는 작업.
- 재사용(Reuse) : 이미 검증된 기존 소프트웨어의 지식, 아키텍처, 컴포넌트, 테스트 스위트를 신규 소프트웨어 구축에 재활용하여 생산성을 높이는 기법.

## Ⅳ. ISO/IEC 14764 소프트웨어 유지보수 4대 유형 비교

- 핵심 요약 : 발생 원인과 공수 비중이 상이한 완전·적응·수정·예방 유지보수의 유형별 관리 필요.
- 유지보수 4대 유형의 분류 구조.

```text
[ 유지보수 4대 유형 (ISO/IEC 14764) ]
   ├─ 1. 완전 (Perfective) : 신규 요구 반영·개선
   ├─ 2. 적응 (Adaptive)   : 외부 환경 변화 대응
   ├─ 3. 수정 (Corrective) : 운영 중 결함 수정
   └─ 4. 예방 (Preventive) : 잠재 결함 사전 예방
```

| 유지보수 유형 | 발생 원인 및 목적 | 전체 공수 비중 | 구체적 사례 |
|---|---|---|---|
| 완전 유지보수 (Perfective) | 사용자의 신규 요구사항 반영 및 성능·기능 개선 | 가장 큼 | 보고서 기능 추가, 결제 처리 속도 개선 |
| 적응 유지보수 (Adaptive) | OS(Operating System), 하드웨어, DB 등 외부 운영 환경 변화 대응 | 큼 | Linux 커널 업그레이드 대응, 클라우드 이전 |
| 수정 유지보수 (Corrective) | 운영 중 발견된 버그 및 프로그램 오류 수정 | 중간 | 부가세 계산 오류 긴급 패치, 크래시 디버깅 |
| 예방 유지보수 (Preventive) | 잠재적 결함의 사전 예방 및 유지보수성 향상 | 작음 | 기술 부채 상환 리팩토링, 코드 정리 |

## Ⅴ. SW 유지보수 3R의 장점과 한계

- 핵심 요약 : 레거시 자산 가치 연장의 장점, 암묵지 소실·빅뱅 전환·재사용 결합도 측면의 한계.
- 장점
  1. 유실된 문서의 복원과 레거시 시스템 이해도 향상(가시화).
  2. 전면 재개발 대비 낮은 비용의 구조 개선과 품질 향상.
  3. 검증된 자산 재활용을 통한 개발 생산성·품질의 동시 확보.
- 한계점 1 : 역공학(Reverse Engineering) 시 암묵지 및 최신 구현 소실
  - 한계점 : 문서가 유실된 레거시 시스템을 소스코드와 바이너리로부터 역공학할 때, 비즈니스 규칙의 설계 배경(Why)과 예외 처리 맥락의 복원 불가.
  - 해결 방안 : LLM(Large Language Model) 기반 레거시 코드 의미론적 분석 도구 활용, 도메인 전문가(SME, Subject Matter Expert) 인터뷰와 운영 트랜잭션 로그 분석을 통한 유스케이스 재구성.
- 한계점 2 : 빅뱅 재공학(Re-engineering) 수행 중 사업 실패 및 서비스 중단 위험
  - 한계점 : 대규모 레거시의 일거에 신기술 재개발 접근의 일정 지연, 예산 초과, 기존 숨은 버그 픽스 누락에 따른 프로젝트 붕괴 초래.
  - 해결 방안 : 마틴 파울러의 스트랭글러 피그(Strangler Fig) 패턴 도입, 마이크로서비스 또는 모듈 단위의 점진적 분리 전환과 병렬 운영(Parallel Run) 검증.
- 한계점 3 : 재사용(Reuse) 컴포넌트의 맥락 불일치 및 유지보수 결합도 심화
  - 한계점 : 타 프로젝트 모듈의 무분별한 복사 재사용(Copy & Paste) 시 의존성 충돌과 패치 누락으로 전사 품질 저하.
  - 해결 방안 : 도메인 주도 설계(DDD, Domain-Driven Design) 기반 바운디드 컨텍스트 확립, 패키지 관리자 기반 공유 라이브러리 사내 배포, 명확한 API(Application Programming Interface) 계약(Contract) 체결.

## Ⅵ. 레거시 현대화 및 지속 가능한 진화를 위한 기술사적 제언

- 핵심 요약 : 스트랭글러 피그 기반 점진적 재공학과 역공학 도구 기반 자산 가시화의 선결 수행.
- 스트랭글러 피그 패턴(Strangler Fig Pattern) 기반 점진적 재공학 : 레거시 모놀리스의 일괄 재구축(빅뱅) 방식의 극도로 높은 실패 리스크를 감안하여, 외곽 독립 도메인부터 마이크로서비스로 하나씩 분리 이전하는 점진적 재공학 추진.
- 역공학 도구 기반의 소프트웨어 자산 가시화 : 개발자 퇴사 등으로 문서가 유실된 레거시 시스템의 경우, SonarQube, Doxygen, ArchUnit 등 역공학 도구를 통한 실제 컴포넌트 의존성 맵과 죽은 코드(Dead Code)의 정량 분석 후 재공학 착수.

## Ⅶ. 결론

- 핵심 요약 : 3R 체계는 레거시 자산의 생명주기 연장과 현대화를 겸비한 유지보수 공학의 핵심.
- 요약 : 역공학으로 가치를 복원하고, 재공학으로 구조를 개선하며, 재사용으로 자산을 확산하는 순환 체계.
- 시사점 : 빅뱅 전환 지양, 점진적 패턴·도구 기반 접근, 도메인 지식 보전이 유지보수 성숙도의 핵심.
