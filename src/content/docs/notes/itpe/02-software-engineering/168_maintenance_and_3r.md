## 연관 키워드
- 소프트웨어 유지보수, 역공학, 재공학, 재사용, ISO/IEC 14764

### Ⅰ. 소프트웨어 유지보수와 3R의 개요

- 핵심 요약 : 3R은 기존 소프트웨어를 분석하고 개선하며 자산을 재활용 하는 역공학·재공학·재사용 활동의 묶음.
- 개념 : 역공학(Reverse Engineering)은 구현 물에서 설계·요구 정보를 추출하고, 재공학(Reengineering)은 기존 시스템을 분석·변환 해 개선하며, 재사용(Reuse)은 기존 자산을 새 개발에 적용(**소프트웨어 유지보수 3R**, Software Maintenance 3R).
- 배경 및 필요성 : 운영 기간이 긴 시스템은 기술 노후화와 문서 부족, 변경 비용 누적을 겪으므로 기존 자산의 이해와 점진적 개선 필요.
- 주요 목적 : 시스템의 가치와 유지 가능성을 높이며 신규 개발 비용과 위험 절감.

### Ⅱ. 3R의 특징 및 장점

- 핵심 요약 : 분석·변환·재활용은 기존 시스템의 지식을 보존 하면서 현대화 범위를 선택 하도록 지원.

1. 역공학 : 소스·실행 흔적에서 구조와 의존성을 복원 → 문서화 되지 않은 레거시 이해.
2. 재공학 : 구조 개선, 언어·플랫폼 이관, 데이터 변환 → 기능을 유지 하며 변경 비용 완화.
3. 재사용 : 검증 된 컴포넌트·서비스·요구 자산 활용 → 중복 구현과 결함 위험 감소.
- 유지보수 분류와 혼동 하지 않으며, 3R은 개선 접근 이고 유지보수는 변경 목적 분류와 연관.

### Ⅲ. 적용 흐름 (구조)

- 핵심 요약 : 현행 시스템을 조사 해 목표 상태와 위험을 정하고 변환·검증을 반복.

```text
현행 시스템·요구 분석
   ↓ 역공학: 구조·데이터·의존 복원
개선 대상 및 목표 아키텍처 결정
   ↓ 재공학: 코드·플랫폼·데이터 변환
회귀 검증·점진 배포
   ↓ 자산 카탈로그화
재사용 후보 관리
```

```text
문제 발견 → 원인·영향 추적
         → 개선 후 호환성 검증
         → 운영 지표와 사용자 결과 확인
```

- ISO/IEC 14764의 유지보수 유형은 수정(Corrective), 적응(Adaptive), 완전(Perfective), 예방(Preventive)으로 구분 되며 3R과 별도 축.

### Ⅳ. 3R 활동 비교

- 핵심 요약 : 정보 추출이 역공학, 시스템 변환이 재공학, 새 맥락 에서 자산 활용이 재사용의 핵심.

| 비교 축 | 역공학 | 재공학 | 재사용 |
|---|---|---|---|
| 입력 | 기존 코드·실행 시스템 | 이해된 기존 시스템 | 검증 된 자산·컴포넌트 |
| 주된 작업 | 구조·설계 정보 복원 | 분석 후 개선·변환 | 선택·적응·통합 |
| 산출 | 모델·문서·의존성 지도 | 개선된 시스템·코드 | 통합된 재사용 결과 |
| 주된 위험 | 복원 정보의 불완전성 | 기능 회귀·데이터 손실 | 맥락 부적합·라이선스 문제 |

### Ⅴ. 3R의 한계와 방안

- 핵심 요약 : 변환 대상의 숨은 규칙과 데이터 의존을 발견 하고 단계별 검증으로 회귀를 제한.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 복원 모델의 불완전성 | 동적 동작·외부 연계가 소스에 드러나지 않음 | 로그·운영자 인터뷰·동적 분석 병행 | 복원 정확도 |
| 변환 중 기능 회귀 | 암묵 규칙·경계 조건 누락 | 특성화 시험·회귀 시험·점진 이행 | 회귀 결함 수 |
| 재사용 부적합 | 인터페이스·품질·라이선스 차이 | 적합성·보안·라이선스 심사 후 채택 | 재사용 부적합 건수 |
| 일괄 전환 실패 | 데이터와 서비스 전환 위험 집중 | 모듈 별 이행, 병행 운영, 롤백 기준 | 전환 중단 건수 |

### Ⅵ. 레거시 현대화 제언

- 핵심 요약 : 시스템 소유 자는 업무 가치·위험·기술 부채를 기준으로 유지·재공학·대체 선택을 기록.

1. 아키텍트와 운영 팀 은 의존성 지도를 공동 작성 하고 서비스 경계 부터 우선 순위화.
2. 재사용 자산은 소유자·버전·지원 상태·라이선스·보안 정보를 카탈로그로 관리.

### Ⅶ. 결론

- 핵심 요약 : 3R은 기존 소프트웨어의 지식을 추출하고 변환 하거나 재활용 해 수명을 연장 하는 현대화 접근.
- 시사점 : 전면 교체 만을 전제로 하지 않고 위험과 가치에 따라 점진적으로 적용 하는 것이 핵심.
