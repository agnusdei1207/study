## 연관 키워드

- 공공 소프트웨어 사업, 발주·수행, 과업심의, 요구사항, 검수, 법령 현행성

## Ⅰ. 공공 SW 사업관리 지침의 개요

- 핵심 요약 : 공공 SW 사업관리 지침은 공공기관 정보화 사업의 기획·발주·수행·검수 과정에서 법령과 절차 준수를 돕는 관리 기준.
- 개념 : **공공 SW 사업관리**는 국가계약 및 소프트웨어 관련 법령·고시와 기관 절차에 따라 사업 범위, 계약, 품질, 변경을 통제하는 활동.
- 배경 및 필요성 : 공공 사업은 예산·책임·서비스 연속성·공정성이 요구되어 사업 전 과정의 추적 가능한 의사결정 필요.
- 주요 목적 : 적정한 과업·계약 관리와 품질 확보, 공정한 사업 수행 및 공공서비스 성과 달성.

## Ⅱ. 관리 원칙과 장점

- 핵심 요약 : 사전 기획과 명확한 과업, 투명한 변경·검수 증거가 사업 분쟁과 납품 위험을 줄임.
- 계획·예산 연계 : 필요성·타당성·목표를 사업계획에 기록 → 중복 투자 방지.
- 과업 명확화 : 요구·범위·산출물·검수 기준을 문서화 → 책임과 변경 판단의 기준 확보.
- 절차 준수 : 과업 변경·하도급·보안·품질 관련 적용 법령 확인 → 법적·계약 위험 감소.
- 성과 중심 검수 : 계약 요구와 시험 증거를 연결 → 납품 승인 근거 확보.

## Ⅲ. 사업관리 흐름

- 핵심 요약 : 기획에서 계약·수행·검수·운영 이관까지 요구와 증거를 연속 추적.

```text
사업 기획·예산 검토
  ↓ 과업 범위·요구 명세
입찰·계약·수행자 선정
  ↓ 착수·진척·변경 관리
시험·검수·대금 지급
  ↓ 운영 이관·성과 평가
```

```text
요구 ID → 과업·계약 조항 → 산출물
       → 시험 결과·검수 근거 → 변경 이력
```

- 세부 의무와 절차는 사업 유형·규모 및 적용 시점의 법령과 고시를 확인해 결정.

## Ⅳ. 발주·수행 관점 비교

- 핵심 요약 : 발주기관은 요구·절차·검수 책임을, 수행자는 계약 범위 내 품질·보고·변경 근거를 관리.

| 비교 축 | 발주기관 | 수행사업자 |
| --- | --- | --- |
| 범위 정의 | 업무 목표·요구·검수 기준 제시 | 제안·계약 기준에 따른 수행계획 수립 |
| 변경 관리 | 법정 심의·계약 변경 절차 확인 | 영향·비용·일정 근거 제출 |
| 품질 확인 | 객관적 시험·검수 기준 운영 | 산출물·시험 증거와 결함 조치 제공 |
| 책임 | 사업 관리·대가 지급·공정성 | 품질·보안·인력·하도급 의무 준수 |

## Ⅴ. 한계와 방안

- 핵심 요약 : 불명확한 범위·잦은 변경·규정 개정은 최신 기준 확인과 변경 근거 관리로 통제.

| 한계 | 원인·영향 | 대응 방안 |
| --- | --- | --- |
| 요구 불명확 | 이해관계자 합의·현장 분석 부족 | 사전 조사·요구 추적·검수 기준 구체화 |
| 변경 분쟁 | 영향·승인 절차 미흡 | 변경 요청, 비용·일정 분석, 승인 기록 연결 |
| 지침 현행성 오류 | 법령·고시 개정 | 계약 시점의 공식 원문·시행일 확인 |
| 형식적 검수 | 산출물 제출 여부만 확인 | 요구별 시험 결과와 결함 종결 증거 검토 |

## Ⅵ. 공공기관 적용 제언

- 핵심 요약 : 사업 담당자는 특정 연도 매뉴얼에만 의존하지 않고 사업 착수 시 적용 법령·고시의 시행일과 예외를 확인.
- 발주기관 법무·계약·정보화 담당자는 최신 공식 원문과 기관 내규를 함께 검토하고, 과업심의·직접구매 등 적용 여부를 사업별로 판단.
- 사업관리 체계는 요구, 변경 승인, 검수 증거, 운영 이관 문서를 전자적으로 연결.

## Ⅶ. 결론

- 핵심 요약 : 공공 SW 사업 지침의 핵심은 공공 목적과 계약 요구를 투명하고 추적 가능한 관리로 연결하는 것.
- 구체 절차는 법령 개정과 사업 특성에 따라 달라지므로 현행 공식 기준 확인이 필수.
