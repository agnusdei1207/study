## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 설계·아키텍처 → **메시지 큐(Message Queue)**

## 30초 인출

- 본질: 메시지 큐는 생산자가 보낸 메시지를 큐에 보관했다가 소비자가 자기 속도로 가져가게 하는 비동기 통신 방식
- 메커니즘: 생산자가 브로커의 큐에 메시지를 넣으면 소비자가 꺼내 처리한 뒤 확인 응답(ACK)을 보내고, 처리 실패 시 재전송하며 반복 실패한 메시지는 별도 큐로 이동
- 통찰: 재전송 때문에 같은 메시지가 두 번 이상 전달될 수 있으므로 소비자를 멱등하게 만들고 반복 실패 메시지는 데드 레터 큐로 분리

<details>
<summary>핵심 용어</summary>

- **메시지 큐(Message Queue)** : 메시지를 임시 보관하며 생산자와 소비자를 비동기로 연결하는 구성요소
- **브로커(Broker)** : 큐를 관리하고 메시지를 전달하는 서버
- **ACK** : 소비자가 메시지를 정상 처리했음을 알리는 확인 응답
- **데드 레터 큐(DLQ, Dead Letter Queue)** : 재시도 횟수를 넘겨도 처리되지 않은 메시지를 옮겨 두는 큐
- **멱등성(Idempotency)** : 같은 메시지를 여러 번 처리해도 결과가 한 번 처리한 것과 같은 성질
- **피크 트래픽 완충** : 순간적으로 몰린 요청을 큐에 쌓아 후속 시스템 부하를 평탄화하는 효과

</details>

## 2~4교시 25점 답안

## Ⅰ. 메시지 큐의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **메시지 큐** 는 메시지를 큐에 보관해 생산자와 소비자를 비동기로 연결하는 통신 방식 |
| 목적 | 시스템 간 결합 감소와 트래픽 완충 |

## Ⅱ. 동기 호출과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 비동기 처리 | 생산자가 처리 완료를 기다리지 않음 |
| 결합도 감소 | 상대 시스템의 위치·상태를 몰라도 전달 |
| 트래픽 완충 | 몰린 요청을 큐에 쌓아 소비자 속도로 처리 |

## Ⅲ. 구조와 메시지 처리 흐름

### 큐를 사이에 둔 생산자와 소비자

```text
생산자 ─┐                             ┌─→ 소비자1
생산자 ─┼─→ [ ■ ■ ■ ■ ■ ■  ] ─────────┼─→ 소비자2   (큐: 순서대로 보관)
생산자 ─┘      브로커의 큐            └─→ 소비자3
   빠르게 유입 ─────────→ 소비자 속도로 배출
```

### 확대: 메시지 한 건의 처리와 실패 처리

```text
생산자      브로커        소비자
  │ 메시지 ──→│             │
  │          │── 전달 ────→│  처리
  │          │←── ACK ─────│  (성공: 큐에서 삭제)
  │          │
  │          │── 재전달 ──→│  처리 실패(ACK 없음)
  │          │── 재전달 ──→│  실패 반복 (재시도 한도 초과)
  │          │── DLQ로 이동 ──→ [ 데드 레터 큐 ]  → 사람이 원인 확인
```

## Ⅳ. 통신 방식과 전달 보장의 비교

### 동기 호출과 메시지 큐

| 구분 | 동기 호출 | 메시지 큐 |
|---|---|---|
| 호출 방식 | 응답을 기다림 | 큐에 넣고 진행 |
| 소비자 장애 | 호출자 오류 | 큐에 보관 후 복구 시 처리 |
| 트래픽 폭증 | 후속 시스템 과부하 | 큐가 완충 |

### 전달 보장 수준

| 수준 | 의미 | 비고 |
|---|---|---|
| 최대 한 번 | 유실 가능, 중복 없음 | 단순 알림 |
| 최소 한 번 | 유실 없음, 중복 가능 | 소비자 멱등 처리 필요 |
| 정확히 한 번 | 유실·중복 없음 | 구현 비용 큼 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 재전달로 같은 메시지가 중복 처리 | 메시지 ID로 처리 이력을 확인하는 멱등 소비 |
| 처리 불가 메시지가 큐를 막음 | 재시도 한도 후 데드 레터 큐로 분리 |
| 큐 자체의 장애 | 브로커 이중화와 메시지 영속 저장 |

## Ⅵ. 제언

소비자는 메시지 ID로 중복을 걸러내는 멱등 처리로 만들고, 재시도를 넘긴 메시지는 데드 레터 큐에서 별도로 확인

### 멱등 소비의 판단

```text
메시지 수신
   메시지 ID가 처리 이력에 있는가?
      ├─ 예  → 처리하지 않고 ACK
      └─ 아니오 → 처리 → 이력 기록 → ACK
```

### 확대: 데드 레터 큐 운영

```text
DLQ 적재 → 알림 → 원인 분석 → 수정 후 재투입 또는 폐기
```

### 선택 근거: 중복 방지 없는 소비와의 비교

| 구분 | 중복 방지 없음 | 제언: 멱등 소비 + DLQ |
|---|---|---|
| 재전달 시 결과 | 중복 반영 | 한 번만 반영 |
| 실패 메시지 | 큐 정체 | 분리 처리 |
| 운영 부담 | 낮음 | 이력·DLQ 관리 |
