## 연관 키워드
- 메시지 큐, MOM, 비동기 통신, 점대점, 발행-구독, ACK, Dead Letter Queue

### Ⅰ. 메시지 큐의 개요

- 핵심 요약 : 메시지 큐는 생산자와 소비자 사이에 메시지를 저장·전달해 비동기 통신과 결합 완화를 지원.
- 개념 : 메시지 브로커가 메시지를 큐·토픽에 보관하고 전달·확인·재시도를 관리하는 MOM(Message-Oriented Middleware) 구성 요소.
- 배경 및 필요성 : 동기 호출은 수신자 장애·처리 지연이 발신 요청으로 전파될 수 있음.
- 주요 목적 : 서비스 간 시간적 결합을 낮추고 부하 흡수·재처리·이벤트 전달 지원.

### Ⅱ. 메시지 큐의 특징 및 장점

- 핵심 요약 : 메시지 보존·비동기 전달·ACK·재시도는 탄력성을 높이나 전달의 중복·순서·지연을 고려해야 함.

1. 시간적 결합 완화 : 수신자가 나중에 처리 → 일시 장애에도 요청 수용.
2. 부하 평탄화 : 버퍼가 폭주를 흡수 → 소비 속도에 맞춘 처리.
3. 재전달·확인 : ACK·재시도·DLQ(Dead Letter Queue) → 유실·독성 메시지 관리 가능.

### Ⅲ. 큐와 발행-구독 흐름 (구조)

- 핵심 요약 : 점대점은 한 작업 소비자 그룹이 메시지를 분담하고 Pub/Sub는 여러 구독자가 이벤트를 독립 수신.

```text
생산자 → Queue → Consumer Group(한 작업을 분담)
```

```text
Publisher → Topic/Event Stream → Subscriber A
                              └──→ Subscriber B
```

- 전달 모델 : at-most-once, at-least-once, exactly-once는 브로커·범위·소비자 처리에 따라 보장 조건 상이.

### Ⅳ. 메시지 큐와 동기 API 비교

- 핵심 요약 : 동기 API는 즉시 응답·강한 요청 흐름, 큐는 시간 분리·완충·비동기 처리가 강점.

| 비교 축 | 메시지 큐 | 동기 API 호출 |
|---|---|---|
| 시간 결합 | 낮음 | 높음 |
| 응답 | 후속 처리·이벤트 기반 | 요청에 대한 즉시 응답 |
| 장애 영향 | 버퍼·재시도 가능, 적체 관리 필요 | 호출 실패·지연이 연쇄 전파 가능 |
| 적합 | 백그라운드 작업·이벤트 통합 | 즉시 결과가 필요한 조회·명령 |

### Ⅴ. 메시지 큐의 한계와 방안

- 핵심 요약 : 중복·순서·적체·독성 메시지를 멱등 소비·백프레셔·DLQ·관측으로 통제.

| 한계 | 영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 중복 전달 | 같은 업무 효과 중복 반영 | 멱등 키·중복 제거·Outbox/Inbox 패턴 | 중복 처리 건수 |
| 적체·독성 메시지 | 지연 증가·반복 실패 | 큐 깊이 경보·재시도 상한·DLQ 격리 | 큐 깊이, DLQ 메시지 수 |
| 메시지 순서 | 상태 갱신 역전 | 키별 파티셔닝·버전·순서 요구 명시 | 순서 위반 건수 |

### Ⅵ. 메시징 운영 제언

- 핵심 요약 : 서비스 오너는 메시지 계약·멱등성·보존·재처리 책임과 큐 운영 SLO를 설계.

1. 생산자는 스키마 버전·이벤트 ID·발행 원자성을 관리.
2. 소비자는 ACK 시점·멱등성·실패 재처리와 중복 안전성을 구현.
3. 운영자는 큐 깊이·처리 지연·재시도·DLQ를 관측하고 재처리 절차를 리허설.

### Ⅶ. 결론

- 핵심 요약 : 메시지 큐는 서비스 간 비동기 경계와 부하 완충을 제공하는 메시징 미들웨어.
- 시사점 : 신뢰성은 브로커뿐 아니라 소비자 멱등성과 재처리 정책까지 포함해 설계.
