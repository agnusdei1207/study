## 연관 키워드

- 칸반(Kanban), 시각화, WIP 한도, 풀 시스템
- 흐름 관리, 사이클 타임, 처리량, 리드 타임

## Ⅰ. 칸반의 개요

- 핵심 요약 : 칸반은 작업 흐름을 시각화하고 진행 중 작업을 제한해 흐름을 관리·개선하는 진화적 관리 방법.
- 개념 : 작업 흐름을 보드로 **시각화**(visualization)하고 진행 중 작업 수를 제한해 서비스 흐름을 관리·개선하는 진화적 관리 방법이 **칸반**(Kanban)임.
- 배경 및 필요성 : 지식 업무의 진행 상태·병목이 보이지 않기 쉽고, 과도한 동시 착수와 업무 전환이 납기·품질을 악화시키는 문제.
- 주요 목적 : 고객 가치의 예측 가능·지속 가능한 전달을 위한 **흐름 관리**(flow management)와 과부하·대기·재작업의 감소.

## Ⅱ. 칸반의 특징 및 장점

- 핵심 요약 : 시각화·작업 제한·풀 방식·지표 관찰이 병목 인식과 완료 집중, 예측 가능성으로 연결되는 구조.

1. 흐름 시각화 : 단계·정책·대기열을 칸반 보드에 표시 → 병목·막힘의 공동 인식.
2. WIP 한도 : 시작했으나 완료되지 않은 작업 수를 제한하는 **WIP 한도**(Work in Progress limit) → 문맥 전환·과부하 감소와 완료 집중.
3. 풀 시스템 : 후속 단계에 여력이 생길 때 작업을 당기는 **풀 시스템**(pull system) → 수요와 처리 능력의 정합.
4. 정책 명시 : 단계 통과 조건·우선순위 규칙의 공개 → 기대치 일치와 판단 분쟁 감소.
5. 흐름 지표 관찰 : **사이클 타임**(cycle time, 작업 착수부터 완료까지의 시간)·**처리량**(throughput, 단위 시간당 완료 작업 수)·**리드 타임**(lead time, 요청부터 전달까지의 시간) 검토 → 예측·진화적 개선 지원.

## Ⅲ. 칸반의 구조 (흐름)

- 핵심 요약 : 대기→진행→검토→완료의 단계 흐름과, 완료 여력에 맞춰 작업을 당겨오는 풀 구조.

```text
[ 칸반 보드와 WIP 한도 ]

요청 대기
   ↓
진행 중 (WIP 한도)
   ↓
검토 (WIP 한도)
   ↓
완료
   ← 완료 시 다음 작업을 당겨오는 풀
```

```text
[ 칸반 운영 흐름 ]

현재 프로세스·서비스 정의
   ↓
보드·정책 시각화
   ↓
단계별 WIP 한도 설정
   ↓
흐름 지표 관찰(사이클 타임·처리량)
   ↓
병목 제거·정책 조정의 반복
```

## Ⅳ. 칸반과 스크럼의 비교

- 핵심 요약 : 스크럼이 이터레이션·역할이 정해진 프레임워크인 반면, 칸반은 기존 프로세스 위에 시각화·한도·풀을 더하는 진화적 방법임.

| 비교 축 | 칸반 | 스크럼 |
| --- | --- | --- |
| 구조 | 기존 프로세스 위의 시각화·WIP 한도 적용 | 역할·이벤트·스프린트의 프레임워크 |
| 진행 주기 | 연속 흐름, 배포 시점의 자유 | 고정 스프린트·증분 단위 |
| 역할 변화 | 기존 역할·책임 유지 | 제품 책임자·스크럼 마스터 등 역할 신설 |
| 범위 변경 | 수시 반영 | 스프린트 중 범위 고정 |
| 주요 측정 | 사이클 타임·처리량·흐름 | 속도·스프린트 목표 달성 |
| 적합 상황 | 유입 변동·운영·유지보수 흐름 | 제품 개발의 반복 계획 |

## Ⅴ. 칸반의 한계와 방안

- 핵심 요약 : WIP 한도 부재·국지 최적화·정책 미명시·지표 오용을 단계별 한도, 종단 간 기준, 정책 공개로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| WIP 한도 부재 | 보드만 운영 → 동시 작업·대기 시간 그대로 | 단계별 한도와 예외 정책의 합의·실험 | 평균·백분위 WIP, 사이클 타임 |
| 국지적 속도 최적화 | 개별 단계 처리량만 개선 → 전체 흐름 악화 | 종단 간 완료와 병목 기준의 개선 | 전체 처리량, 대기 시간 |
| 정책 미명시 | 통과 기준 불명확 → 재작업·분쟁 | 단계 정책·완료 기준의 공개 | 재작업률 |
| 지표의 개인 평가 전용 | 서두름·품질 저하·데이터 왜곡 | 시스템 개선·예측 목적의 지표 사용 | 품질 결함률, 서비스 수준 |

## Ⅵ. 칸반 적용에 대한 제언

- 핵심 요약 : 서비스 책임 조직은 팀 경계를 넘는 흐름 관리, 정기 흐름 검토, 관리자의 코칭 전환으로 칸반을 조직 수준 체계로 확산.
- 조직 확장 : 서비스 책임 조직이 팀 간 의존을 포함한 조직 단위 보드를 두고 단계 간 인계 지연을 함께 관리.
- 검토 제도 : 병목·정책·우선순위를 다루는 정기 흐름 검토 회의를 운영하고 개선 실험의 결과를 기록.
- 역할 전환 : 관리자가 작업 배분자에서 흐름 코치로 전환하도록 기대 역할과 성과 기준 재정의.

## Ⅶ. 결론

- 핵심 요약 : 칸반은 보드 도구가 아니라 고객 가치 흐름을 관리하는 풀 기반 시스템.
- 시각화·한도·측정·개선의 결합이 예측성과 적응력을 높임.
