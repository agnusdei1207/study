## 연관 키워드
- 칸반, WIP(Work in Progress) 한도, 풀 시스템, 흐름 관리, 사이클 타임, 처리량

### Ⅰ. 칸반의 개요

- 핵심 요약 : 칸반은 현재 업무 방식을 바탕으로 작업 흐름을 시각화하고 진행 중 작업을 제한해 서비스 흐름을 관리·개선하는 진화적 관리 방법.
- 개념 : 현재 업무 방식을 바탕으로 작업 흐름을 시각화하고 진행 중 작업을 제한해 서비스 흐름을 관리·개선하는 진화적 관리 방법(**칸반**, Kanban).
- 배경 및 필요성 : 지식 업무의 진행 상태와 병목은 보이지 않기 쉽고, 과도한 착수와 업무 전환은 납기·품질을 악화시킴.
- 주요 목적 : 고객 가치를 예측 가능하고 지속 가능한 흐름으로 전달하며 과부하·대기·재작업을 줄임.

### Ⅱ. 칸반의 특징 및 장점

- 핵심 요약 : 업무 흐름 시각화·WIP 한도·풀 방식·흐름 측정·피드백.

1. 업무 흐름 시각화 : 단계·정책·대기열을 칸반 보드에 표시 → 병목과 막힘을 공동 인식.
2. WIP 한도 : 시작했으나 완료되지 않은 작업 수 제한 → 과부하·문맥 전환을 줄이고 완료에 집중.
3. 풀 방식 : 후속 단계에 여력이 생길 때 작업을 당김 → 수요와 처리 능력을 맞춤.
4. 흐름 측정·피드백 : 사이클 타임·처리량·WIP를 검토 → 예측과 진화적 개선 지원.

### Ⅲ. 칸반의 구조 (흐름)

- 핵심 요약 : 현재 업무·서비스 정의 → 흐름·완료 정의 시각화 → WIP 한도·풀 정책 설정 → 흐름 지표 관찰 → 피드백·실험적 개선.

```text
현재 업무·서비스 정의
   ↓
흐름·완료 정의 시각화
   ↓
WIP 한도·풀 정책 설정
   ↓
흐름 지표 관찰
   ↓
피드백·실험적 개선
```

```text
요청 대기 → 진행 중(WIP 한도) → 검토 → 완료
                  ↑
       완료 여력이 생길 때만 pull
                  ↓
    사이클 타임·처리량·WIP로 개선
```

### Ⅳ. 칸반과 스크럼 비교

- 핵심 요약 : 칸반은 기존 흐름에 시각화·WIP 한도·풀을 적용, 스크럼은 역할·이벤트·스프린트·목표가 정해진 프레임워크.

| 비교 대상 | 핵심 특성 | 적용·판단 기준 |
|---|---|---|
| 칸반 | 기존 흐름에 시각화·WIP 한도·풀을 적용 | 현재 프로세스를 점진적으로 개선 |
| 스크럼 | 역할·이벤트·스프린트·목표가 정해진 프레임워크 | 반복 주기·제품 목표·팀 리듬을 함께 도입 |
| 푸시형 프로젝트 계획 | 미리 작업을 배정하고 시작을 촉진 | 일정·범위 고정이 우선인 작업에 적합하나 과부하 위험 |

### Ⅴ. 칸반의 한계와 방안

- 핵심 요약 : WIP 한도 없는 보드·국지적 속도 최적화·지표의 개인 평가 전용을 단계별 한도·종단간 개선·시스템 개선으로 관리.

| 위험 | 원인·영향 | 대응 통제 | 지표 예시 |
|---|---|---|---|
| WIP 한도 없는 보드 | 시각화만 되고 동시 작업·대기 시간은 감소하지 않음 | 단계별 한도와 예외 정책 합의·실험 | 평균·백분위 WIP, 사이클 타임 |
| 국지적 속도 최적화 | 개별 단계 처리량이 전체 흐름을 악화 | 종단 간 완료와 병목을 기준으로 개선 | 전체 처리량, 대기 시간 |
| 지표의 개인 평가 전용 | 작업자 서두름·품질 저하·데이터 조작 | 시스템 개선과 예측에 지표 사용, 품질·재작업 동시 관찰 | 재작업률, 서비스 수준 |

### Ⅵ. 칸반 적용에 대한 기술사적 제언

- 핵심 요약 : 기존 역할을 무너뜨리기보다 흐름과 정책을 공동 시각화하고 WIP 한도를 실험하며, 사이클 타임·처리량을 고객 납기와 서비스 품질 개선에 연결.

- 실행 제언 : 서비스 책임자는 기존 역할을 무너뜨리기보다 흐름과 정책을 공동 시각화하고 WIP 한도를 실험하며, 사이클 타임·처리량을 고객 납기와 서비스 품질 개선에 연결.

### Ⅶ. 결론

- 핵심 요약 : 칸반은 현재 업무 방식을 바탕으로 작업 흐름을 시각화하고 진행 중 작업을 제한해 서비스 흐름을 관리·개선하는 진화적 관리 방법.
- 시사점 : 칸반은 보드가 아니라 고객 가치 흐름을 관리하는 풀 기반 시스템으로, 제한된 진행 작업과 피드백을 통해 예측성과 적응력을 높임.
