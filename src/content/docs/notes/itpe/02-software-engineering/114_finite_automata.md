- 본질: **유한 오토마타**는 유한한 상태로 입력 문자열의 정규언어 소속 여부를 판정하는 계산 모델
- 메커니즘: 입력 기호마다 상태를 전이하고, 입력 종료 후 수용 상태에 도달했는지 확인
- 핵심 관계: DFA는 다음 상태가 하나로 정해지고, NFA는 여러 가능 상태를 허용하지만 인식 언어는 같음

<details>
<summary>핵심 용어</summary>

- **유한 오토마타(Finite Automaton)**: 유한한 상태와 입력 기호 전이로 문자열을 수용하거나 거부하는 계산 모델
- **결정적 유한 오토마타(DFA, Deterministic Finite Automaton)**: 각 상태와 입력 기호의 조합에 다음 상태가 하나로 정해지는 오토마타
- **비결정적 유한 오토마타(NFA, Nondeterministic Finite Automaton)**: 한 입력에서 복수의 다음 상태 가능성을 허용하며, 하나 이상의 경로가 수용하면 문자열을 수용하는 오토마타
- **정규언어(Regular Language)**: 어떤 유한 오토마타가 인식할 수 있는 언어
- **전이 함수(Transition Function)**: 현재 상태와 입력 기호를 다음 상태 또는 상태 집합에 대응시키는 함수
</details>

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 유한 오토마타는 유한한 상태와 입력 기호 전이로 문자열의 정규언어 소속을 판정하는 계산 모델 |
| 목적 | 정규 패턴 인식과 유한 상태 기반 동작의 명세·구현 |

### Ⅱ. 구성과 수용 판정

```text
시작 상태 q₀
    ↓ 입력 기호 읽기
전이 함수 δ로 다음 상태 결정
    ├─ 입력 남음 → 다음 기호 처리
    └─ 입력 종료 → 현재 상태 판정

현재 상태 ∈ 수용 집합 F → 수용
현재 상태 ∉ 수용 집합 F → 거부
```

### Ⅲ. DFA와 NFA

| 구분 | DFA | NFA |
|---|---|---|
| 다음 상태 | 각 상태·입력마다 하나 | 상태 집합으로 표현 가능 |
| 수용 조건 | 유일한 실행 경로가 수용 상태에 도달 | 가능한 경로 중 하나가 수용 상태에 도달 |
| 인식 능력 | 정규언어 인식 | DFA와 동일한 정규언어 인식 |

- 제언: 상태·입력별 전이와 수용 조건을 빠짐없이 명세하는 유한 상태 모델 설계

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 유한 오토마타는 유한한 상태와 입력 기호 전이로 문자열의 정규언어 소속을 판정하는 계산 모델 |
| 목적 | 정규 패턴 인식과 유한 상태 기반 동작의 명세·구현 |

## Ⅱ. 형식적 구성요소

유한 오토마타의 형식 표기는 다섯 요소 `(Q, Σ, δ, q₀, F)`이며, 입력 기호마다 전이 함수를 적용하는 계산 과정

| 기호 | 의미 |
|---|---|
| `Q` | 유한한 상태 집합 |
| `Σ` | 입력 기호의 알파벳 |
| `δ` | 상태와 입력을 다음 상태(들)에 대응시키는 전이 함수 |
| `q₀` | 시작 상태 |
| `F` | 수용 상태 집합 |

## Ⅲ. 문자열 수용 과정

```text
시작 상태 q₀
    ↓ 입력 기호 읽기
전이 함수 δ로 다음 상태 결정
    ├─ 입력 남음 → 다음 기호 처리
    └─ 입력 종료 → 현재 상태 판정

현재 상태 ∈ 수용 집합 F → 수용
현재 상태 ∉ 수용 집합 F → 거부
```

| 판정 단계 | 수행 내용 | 결과 |
|---|---|---|
| 초기화 | 현재 상태를 `q₀`로 둠 | 시작 구성 |
| 입력 처리 | 입력 기호마다 `δ`를 적용 | 상태 또는 상태 집합 갱신 |
| 종료 판정 | 입력을 모두 소비한 뒤 수용 상태 여부 확인 | 수용 또는 거부 |

## Ⅳ. DFA와 NFA의 비교·동치

| 구분 | DFA | NFA |
|---|---|---|
| 전이 결과 | 각 상태·입력 조합에 다음 상태 하나 | 다음 상태가 없거나 여러 개일 수 있음; 변형에 따라 ε 전이 허용 |
| 실행 관점 | 한 시점에 한 상태 | 가능한 상태들의 집합으로 실행을 해석 |
| 인식 언어 | 정규언어 | 정규언어; DFA와 표현 능력 동치 |
| 변환 | 직접 실행에 적합한 결정적 표현 | 부분집합 구성으로 동등한 DFA 구성 가능 |

NFA는 간결한 표현에 적합하고, 부분집합 구성으로 동등한 DFA 변환 가능. 변환 상태 수는 최악에 원래 NFA 상태 수의 지수 규모까지 증가할 수 있어 구현 시 메모리·처리 특성 고려

## Ⅴ. 적용과 설계상 유의점

| 적용 예 | 오토마타의 역할 | 유의점 |
|---|---|---|
| 어휘 분석 | 토큰 패턴과 입력 문자열의 인식 | 토큰 우선순위 등 언어 규칙을 별도로 반영 |
| 프로토콜·업무 상태 | 유한한 상태와 허용 전이의 명세 | 상태 누락·불법 전이·오류 상태를 검토 |
| 입력 검증 | 허용 형식의 문자열 판정 | 복잡한 패턴 엔진의 시간 특성은 구현별 검증 필요 |

정규식의 성능·서비스거부 위험 검토 시 NFA 이론과 실제 엔진의 실행 전략 구분. 백트래킹 구현에서 특정 패턴은 높은 처리 비용을 유발할 수 있으나 모든 NFA 실행의 지수 시간 비용을 뜻하지 않음

## Ⅵ. 기술사적 제언

| 구분 | 제언 |
|---|---|
| 한계 | 상태와 전이 규칙이 코드·문서에 분산되면 누락된 상태나 허용되지 않은 동작을 검토하기 어려움 |
| 해결 방안 | 상태 집합·입력·전이·수용 조건을 명시하고, 전이표 기반 시험으로 경계와 예외 입력을 확인 |
