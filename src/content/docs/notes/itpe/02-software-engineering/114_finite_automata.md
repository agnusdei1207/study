소프트웨어 공학 → 자료구조·알고리즘 → **유한 오토마타와 정규 표현식**

## 30초 인출

- 본질: 유한 오토마타는 유한한 상태와 입력에 따른 전이 규칙으로 문자열을 받아들일지 판정하는 계산 모델이며 정규 표현식과 같은 표현력을 가짐
- 메커니즘: 초기 상태에서 입력 기호를 하나씩 읽으며 전이 함수에 따라 상태를 바꾸고 입력이 끝났을 때 수용 상태이면 문자열을 인식
- 통찰: NFA는 표현이 간결하나 실행이 비결정적이므로 DFA로 변환해 입력 길이에 비례한 시간에 매칭하되 상태 수가 최대 2^n으로 늘 수 있어 패턴 크기를 관리

<details>
<summary>핵심 용어</summary>

- **유한 오토마타(Finite Automata)** : 유한한 상태와 전이로 입력 문자열을 인식하는 계산 모델
- **5-튜플** : 상태 집합 Q, 입력 기호 집합 Σ, 전이 함수 δ, 초기 상태 q0, 수용 상태 집합 F
- **DFA(Deterministic Finite Automaton)** : 상태와 입력 기호마다 다음 상태가 하나로 정해진 오토마타
- **NFA(Nondeterministic Finite Automaton)** : 같은 입력에 여러 다음 상태를 가질 수 있는 오토마타
- **정규 표현식(Regular Expression)** : 문자열 패턴을 기호로 표현한 식. 정규 언어를 나타냄
- **부분집합 구성법(Subset Construction)** : NFA를 같은 언어를 인식하는 DFA로 바꾸는 방법

</details>

## 2~4교시 25점 답안

## Ⅰ. 유한 오토마타의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **유한 오토마타** 는 유한한 상태와 전이 규칙으로 문자열을 인식하는 계산 모델 |
| 목적 | 패턴 인식·어휘 분석 등 문자열 처리의 형식적 모델 제공 |

## Ⅱ. 유한 오토마타의 특징

| 특징 | 의미 |
|---|---|
| 유한 상태 | 기억 공간이 상태 수로 제한 |
| 입력 순차 처리 | 기호를 한 번씩 읽으며 전이 |
| 정규 언어 인식 | 정규 표현식으로 표현되는 언어 인식 |

## Ⅲ. 구조와 동작

### 오토마타의 구성과 전이 (예: 0으로 끝나는 이진 문자열)

```text
      1            0
   ┌────┐       ┌────┐
   ↓    │  0    ↓    │
→ (q0) ─┴──────→ ((q1)) ┘
   ↑              │ 1
   └──────────────┘
q0: 초기 상태, q1(이중 원): 수용 상태
```

### 확대: 5-튜플 정의

```text
M = (Q, Σ, δ, q0, F)
δ: Q × Σ → Q  (DFA)   /   δ: Q × Σ → 2^Q  (NFA)
```

## Ⅳ. DFA와 NFA, 정규 표현식의 관계

| 구분 | DFA | NFA |
|---|---|---|
| 전이 | 상태·입력당 하나 | 여러 개 가능 |
| 구현 | 단순, 입력 길이에 비례한 시간 | 상태 집합 추적 필요 |
| 표현 크기 | 상태 수가 커질 수 있음 | 간결 |
| 표현력 | 동일(같은 언어 인식) | 동일 |

| 관계 | 내용 |
|---|---|
| 정규 표현식 → NFA | 표현식을 NFA로 구성 |
| NFA → DFA | 부분집합 구성법으로 변환 |
| 활용 | 어휘 분석기, 문자열 검색, 입력 검증 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| NFA→DFA 변환 시 상태 수 폭증(최대 2^n) | 패턴 크기 제한과 상태 최소화 |
| 기억이 유한해 중첩 구조(괄호 균형) 인식 불가 | 스택을 쓰는 푸시다운 오토마타 등 상위 모델 사용 |
| 정규 표현식 과다 복잡화로 성능 저하 | 패턴 단순화와 실행 시간 제한 |

## Ⅵ. 제언

패턴은 정규 표현식으로 작성하고 DFA로 변환해 매칭하되, 패턴 크기를 제한해 상태 폭증을 방지

### 패턴 매칭 구성

```text
정규 표현식 → NFA → DFA(상태 최소화) → 입력 스캔
```

### 확대: 모델 선택

```text
인식 대상
    ├─ 정규 언어(토큰·형식 검증) → 유한 오토마타
    └─ 중첩·재귀 구조 → 푸시다운 오토마타·파서
```

### 선택 근거: NFA 직접 실행과의 비교

| 구분 | NFA 직접 실행 | 제언: DFA 변환 |
|---|---|---|
| 매칭 시간 | 상태 집합 추적 | 입력 길이에 비례 |
| 메모리 | 작음 | 상태 폭증 가능 |
| 적합 | 짧은 패턴 | 반복 매칭 |
