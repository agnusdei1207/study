## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 개발 방법론 → **소프트웨어 제품라인(SPL)**

## 30초 인출

- 본질: 소프트웨어 제품라인은 공통 기반 위에서 제품군을 체계적으로 재사용해 개발하는 공학 방법이며 공통성과 가변성을 관리
- 메커니즘: 도메인 공학에서 제품군의 공통성·가변성을 분석해 핵심 자산을 만들고, 애플리케이션 공학에서 고객 요구에 맞게 가변점을 선택해 제품을 도출
- 통찰: 공통 부분만 보고 재사용하면 고객별 요구에서 핵심 자산이 갈라져 유지가 어려워지므로 피처 모델로 공통성·가변성을 먼저 정의하고 가변점을 선택 방식으로 관리

<details>
<summary>핵심 용어</summary>

- **소프트웨어 제품라인(SPL, Software Product Line)** : 공통 핵심 자산으로 유사 제품군을 개발하는 방법
- **도메인 공학(Domain Engineering)** : 제품군의 공통성·가변성을 분석해 재사용 자산을 만드는 활동
- **애플리케이션 공학(Application Engineering)** : 재사용 자산으로 특정 제품을 도출하는 활동
- **공통성(Commonality)** : 제품군의 모든 제품이 공유하는 특성
- **가변성(Variability)** : 제품마다 달라지는 선택 가능한 특성
- **피처 모델(Feature Model)** : 필수·선택·대안 관계로 제품군의 기능을 표현한 모델

</details>

## 2~4교시 25점 답안

## Ⅰ. 제품라인의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **소프트웨어 제품라인** 은 공통 핵심 자산으로 유사한 제품군을 체계적으로 개발하는 방법 |
| 목적 | 재사용을 통한 개발 기간·비용 감소와 품질 향상 |

## Ⅱ. 개별 제품 개발과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 핵심 자산 재사용 | 제품 간 공통 자산의 공유 |
| 공통성·가변성 관리 | 공통과 차이의 체계적 관리 |
| 두 단계 공학 | 자산 개발과 제품 도출 분리 |

## Ⅲ. 제품라인의 구조와 제품 도출 흐름

### 제품라인의 두 공학

```text
도메인 공학 ── 공통성·가변성 분석 → 핵심 자산(컴포넌트·아키텍처)
        ↓ 자산 제공
애플리케이션 공학 ── 고객 요구 → 가변점 선택 → 제품 A·B·C
```

### 확대: 피처 모델

```text
결제 서비스 (필수)
    ├─ 결제 수단 (선택: 카드 / 계좌이체 중 하나 이상)
    ├─ 통계 리포트 (선택)
    └─ 인증 방식 (대안: 비밀번호 또는 생체 인증 중 하나)
```

## Ⅳ. 활용 기술과 고려사항

### 활용 기술

| 기술 | 내용 |
|---|---|
| 피처 모델링 | 공통·가변 특성의 표현 |
| 컴포넌트 기반 개발 | 재사용 가능한 단위 구성 |
| 아키텍처 설계 | 가변점을 수용하는 공통 아키텍처 |
| 바인딩 시점 관리 | 컴파일·설치·실행 시점의 가변점 결정 |

### 고려사항

| 고려사항 | 내용 |
|---|---|
| 초기 투자 | 자산 개발 비용 선투자 |
| 조직·프로세스 | 자산 개발과 제품 개발 조직의 협업 |
| 가변성 관리 | 가변점 증가에 따른 복잡도 통제 |
| 적용 대상 | 유사 제품이 여러 개 예상되는 도메인 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 고객별 요구로 핵심 자산이 갈라짐 | 피처 모델로 가변점을 선택 방식으로 관리 |
| 초기 자산 개발 비용 부담 | 재사용 가능성 높은 도메인부터 적용 |
| 가변점 증가로 복잡도 상승 | 가변점의 수와 조합 제한 |

## Ⅵ. 제언

피처 모델로 공통성·가변성을 먼저 정의하고, 재사용 가능성이 높은 영역부터 핵심 자산으로 개발해 제품 도출에 활용

### 적용 순서

```text
유사 제품군·도메인 선정
    ↓
피처 모델로 공통성·가변성 정의
    ↓
핵심 자산 개발 → 제품별 가변점 선택 도출
```

### 선택 근거: 제품별 개별 개발과의 비교

| 구분 | 제품별 개별 개발 | 제언: 제품라인 |
|---|---|---|
| 재사용 | 개별 복제 | 핵심 자산 공유 |
| 변경 반영 | 제품마다 수정 | 핵심 자산 한 곳 |
| 초기 비용 | 낮음 | 자산 개발 필요 |
