## 답안 골격
```text
[제품계열(Product Line) 방법론] ◀━━ 머리: Ⅶ 내 의견 (공통성과 가변성(FODA) 모델링 기반 핵심 자산 구축과 패밀리 제품 조기 시장 출시)
 ┃
 ┣━ Ⅰ 개요 ───── 유사 패밀리 제품군 개별 개발로 인한 중복 비용과 품질 편차 → 핵심 자산(Core Asset) 재사용 중심 개발
 ┣━ Ⅱ 특징 ───── 대규모 체계적 재사용 · 공통성(Commonality)과 가변성(Variability) 분리 · 2계층 공학(도메인/애플리케이션)
 ┣━ Ⅲ 구조 ───── 3대 필수 요소(핵심 자산 개발, 제품 개발, 관리/조직) / 피처 모델(FODA: Mandatory, Optional, Alternative, OR)
 ┣━ Ⅳ 흐름 ───── 도메인 공학(공통/가변 분석 → 핵심 자산 구축) ──> 애플리케이션 공학(요구사항 바인딩 → 개별 제품 조립 생산)
 ┣━ Ⅴ 비교 ───── 제품계열 공학(SPL/SPLE) vs 컴포넌트 기반 개발(CBD) vs 단순 코드 복사(Copy & Paste)
 ┗━ Ⅵ 실무 ───── 초기 핵심 자산 구축에 막대한 비용과 시간 소요 / 점진적(Extractive/Reactive) 도입 전략 채택
```
- 필수 키워드: 소프트웨어 제품계열(SPL/SPLE) · 핵심 자산(Core Asset) · 도메인 공학(Domain Engineering) · 애플리케이션 공학(Application Engineering) · 공통성/가변성 · 피처 모델링(FODA) · 바인딩 타임
- 배점 전략: 10점 = Ⅰ SPL 개념 및 2계층 구조 → Ⅲ FODA 피처 모델 표기법 → Ⅳ 도메인/앱 공학 순환도 / 25점 = Ⅰ~Ⅶ 전개, 136회 기출 제품계열 방법론의 개념, 2대 공학 체계, 가변성 메커니즘, 및 도입 전략(Proactive, Reactive, Extractive)
- 기출: 136회 2교시 4번 `소프트웨어 개발방법론 중 하나인 제품계열(Product Line) 방법론에 대하여 다음을 설명하시오.` → Ⅰ~Ⅵ

## 한 줄 본질
- 스마트폰 기종별, 자동차 ECU 라인업별 유사 소프트웨어를 복사-붙여넣기(Copy-Paste)로 개별 개발하여 버그 수정이 파편화되는 재앙 병목 → 패밀리 제품군의 공통성과 가변성을 체계적으로 분석하여 공통 핵심 자산을 먼저 만들고(도메인 공학), 개별 제품은 가변점을 조립하여 초고속 생산하는 방법론 / 초기 구축 투자 비용 수반

## 핵심 그림
```text
+-------------------------------------------------------------------------+
|                  SEI SPL 2계층 프레임워크 및 피처 모델                  |
+-------------------------------------------------------------------------+
| [ 도메인 공학 (Domain Engineering) ] - "핵심 자산 개발 (For Reuse)"     |
|   - 도메인 분석 (공통성, 가변성 분석)                                   |
|   - 피처 모델링 (FODA: Mandatory, Optional, Alternative)                |
|   - 핵심 아키텍처 및 재사용 컴포넌트, 테스트 케이스 구축                 |
|                               │ (Core Assets)                           |
|                               v                                         |
| [ 애플리케이션 공학 (Application Engineering) ] - "제품 생산 (With Reuse)"|
|   - 개별 고객 요구사항 분석                                             |
|   - 핵심 자산에서 가변점 선택 및 바인딩 (Compile/Link/Runtime Binding)  |
|   - 파생 제품 A, B, C 신속 조립 출시 (Time-to-Market 단축)              |
+-------------------------------------------------------------------------+
```

## 핵심 용어
- 공통성과 가변성(Commonality & Variability): 제품군 내 모든 제품이 공유하는 불변의 성질(공통성)과, 특정 모델이나 시장에 따라 달라지는 선택적/대체적 성질(가변성)을 식별하는 SPL의 기본 분석 축
- FODA(Feature Oriented Domain Analysis): 제품의 기능적 특징을 트리 계층으로 시각화하고, 필수(Mandatory), 선택(Optional), 배타적 대안(Alternative), 다중 선택(OR) 관계로 가변성을 명세하는 모델링 기법

## 핵심 통찰
- 단순한 컴포넌트 재사용(CBD)이 하향식 부품 라이브러리 구축이라면, 제품계열(SPL)은 "특정 비즈니스 도메인(예: 현대차 ADAS 소프트웨어 제품군) 전체를 공략하기 위한 전략적 생산 라인 공장 구축"임
- SPL 도입 시 모든 자산을 처음부터 완벽히 만들려는 '선제적(Proactive)' 접근은 십중팔구 실패하므로, 기존 성공 제품에서 공통점을 뽑아내는 '추출적(Extractive)' 접근이나 요구에 따라 점진 확장하는 '반응적(Reactive)' 접근이 실무 성공 공식임
- 가변성을 언제 결정하느냐(Compile-time vs Load-time vs Run-time Binding)에 따라 제품의 성능과 유연성의 트레이드오프가 결정됨

## 이웃 토픽과 구분
- 제품계열(SPL) vs 컴포넌트 기반 개발(CBD): CBD = 범용적이고 독립적인 개별 소프트웨어 부품의 재사용 / SPL = 명확한 패밀리 제품군 시장을 겨냥하여 아키텍처와 피처를 통째로 공유하는 체계적 생산 패러다임

## 문제·원인·대책
- 적용 상황: 수십 종의 보급형/고급형 차량용 인포테인먼트(IVI) 시스템 개발
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 신규 차종 IVI 개발 시마다 소스코드를 복제해 개발하여 동일한 통신 버그가 20개 차종에 반복 발생 | 소스코드 수준 Copy & Paste 개발로 인한 브랜치 파편화 | SPL 도메인 공학 기반 핵심 IVI 공통 플랫폼 구축 및 FODA 가변성 적용 | 신차종 개발 기간 12개월에서 3개월로 단축 및 결함 70% 감소 |
| 공통 컴포넌트 수정 시 특정 차종에서만 컴파일 에러 및 기능 충돌 발생 | 가변성 규칙(의존성 제약: Requires, Excludes) 검증 부재 | 피처 모델링 도구(pure::variants) 도입 및 형상 자동 바인딩 규칙 검증 | 파생 모델 빌드 불일치 오류 100% 사전 차단 |

## 이렇게 출제된다
- 제136회 2교시 4번: "소프트웨어 개발방법론 중 하나인 제품계열(Product Line) 방법론에 대하여 다음을 설명하시오." → 요구 포인트: SPL 개념 및 등장 배경 + 3대 구성요소(도메인 공학, 애플리케이션 공학, 관리) + 가변성 관리 기법(FODA 피처 모델) + 도입 전략 3가지(Proactive, Reactive, Extractive)
