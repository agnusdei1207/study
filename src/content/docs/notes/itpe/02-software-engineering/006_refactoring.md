## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 유지보수·품질 → **리팩토링(코드스멜)**

## 30초 인출

- 본질: 리팩토링은 외부 동작을 바꾸지 않고 코드 내부 구조를 개선하는 활동이며, 코드스멜은 그 개선이 필요한 코드의 징후
- 메커니즘: 코드스멜을 식별하고 시험으로 현재 동작을 고정한 뒤 작은 단위로 구조를 바꾸며 시험 통과를 확인
- 통찰: 시험 없이 구조를 바꾸면 동작이 달라져도 알 수 없으므로 변경 전 현재 동작을 기준선으로 고정하고 결함이 잦은 코드부터 리팩토링

<details>
<summary>핵심 용어</summary>

- **리팩토링(Refactoring)** : 외부 동작은 유지하면서 코드의 내부 구조를 이해하기 쉽고 바꾸기 쉽게 개선하는 활동
- **코드스멜(Code Smell)** : 설계 결함이나 기술부채가 있을 가능성을 나타내는 코드의 징후
- **기술부채(Technical Debt)** : 빠른 납기를 위해 선택한 임시 설계·코드가 이후 수정 비용으로 쌓이는 부담
- **회귀 테스트(Regression Test)** : 변경 후 기존 기능이 그대로 동작하는지 확인하는 시험
- **특성화 테스트(Characterization Test)** : 기존 코드의 현재 동작을 기록해 기준선으로 삼는 시험
- **메서드 추출(Extract Method)** : 긴 메서드의 일부를 별도 메서드로 분리하는 리팩토링 기법

</details>

## 2~4교시 25점 답안

## Ⅰ. 리팩토링의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **리팩토링** 은 외부 동작을 바꾸지 않고 코드 내부 구조를 개선하는 활동 |
| 목적 | 코드 이해·수정 용이성 향상과 **기술부채** 의 상환 |

## Ⅱ. 신규 기능 개발과 구별되는 리팩토링의 특징

| 특징 | 의미 |
|---|---|
| 외부 동작 불변 | 기능 추가·변경 없이 구조만 변경 |
| 작은 단계의 변경 | 한 번에 하나의 구조 변경 후 시험 |
| 시험 전제 | 회귀 시험으로 동작 불변을 확인 |

## Ⅲ. 리팩토링 수행 체계

### 리팩토링 실행 순환

```text
코드스멜 식별
    ↓
시험으로 현재 동작 고정
    ↓
작은 단위 리팩토링
    ↓
회귀 시험
    ├─ 실패 → 변경 취소·원인 분석
    └─ 통과 → 커밋 후 다음 코드스멜
```

### 확대: 메서드 추출 절차

```text
긴 메서드에서 분리할 블록 식별
    ↓
새 메서드로 분리 후 호출로 치환
    ↓
단위 시험 실행
    ├─ 통과 → 커밋
    └─ 실패 → 되돌림
```

## Ⅳ. 기술부채·코드스멜·리팩토링의 관계

### 세 개념의 관계

| 구분 | 의미 | 관계 |
|---|---|---|
| 기술부채 | 임시 설계·코드가 쌓은 수정 비용 | 불명확한 요구사항으로 인한 잦은 변경·임시 구현이 원인 |
| 코드스멜 | 부채가 있는 코드의 징후 | 부채의 발견 신호 |
| 리팩토링 | 구조 개선 활동 | 부채의 상환 수단 |

### 대표 코드스멜과 리팩토링 기법

| 코드스멜 | 문제 | 리팩토링 |
|---|---|---|
| 중복 코드 | 수정 위치 누락 | 메서드 추출 |
| 긴 메서드 | 이해·시험 곤란 | 메서드 추출 |
| 거대 클래스 | 책임 과다 | 클래스 추출 |
| 기능 편애 | 다른 클래스 데이터 과다 참조 | 메서드 이동 |
| 복잡한 분기문 | 조건 추가 시 전체 수정 | 다형성으로 대체 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 시험이 없어 리팩토링 후 동작 변경 여부 확인 불가 | 특성화 테스트로 현재 동작 기록 |
| 한 번의 큰 변경으로 결함 원인 추적 곤란 | 작은 단위 변경과 단위별 커밋 |
| 전체 코드 대상의 리팩토링으로 비용 과다 | 변경·결함이 잦은 코드부터 우선 적용 |

## Ⅵ. 제언

변경 전 특성화 테스트로 현재 동작을 고정하고, 결함과 변경이 잦은 코드부터 작은 단위로 리팩토링

### 우선순위 기반 적용 순서

```text
결함·변경 빈도가 높은 코드 선별
    ↓
특성화 테스트로 현재 동작 고정
    ↓
작은 단위 리팩토링과 회귀 시험
```

### 확대: 적용 여부 판정

```text
변경 요구 발생
    ├─ 테스트 없음 → 특성화 테스트 작성 후 진행
    └─ 테스트 있음 → 리팩토링 후 기능 변경
```

### 선택 근거: 일괄 재작성과의 비교

| 구분 | 일괄 재작성 | 제언: 우선순위 리팩토링 |
|---|---|---|
| 대상 | 전체 코드 | 결함·변경이 잦은 코드 |
| 동작 보장 | 새 결함 위험 | 시험으로 고정 |
| 위험 | 큼 | 단위별 취소 가능 |
