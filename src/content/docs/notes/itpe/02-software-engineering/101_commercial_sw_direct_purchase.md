## 연관 키워드

1. 상용SW(Software) 직접구매
2. 소프트웨어진흥법
3. SI(System Integration, 시스템 통합) 일괄 발주
4. 과업심의위원회
5. GS(Good Software) 인증
6. SW 통합비용(SW Integration Fee)
7. 디지털서비스 전문계약제도

## Ⅰ. 상용SW 직접구매의 개요

- 핵심 요약 : 공공 소프트웨어 사업의 상용SW를 제조사와 직접 계약하여 조달하도록 의무화한 공공 발주 제도.
- 개념 : 국가기관, 지방자치단체, 공공기관이 소프트웨어 개발 구축 사업을 발주할 때, 사업에 포함된 상용SW(Software)를 SI(System Integration, 시스템 통합) 주사업자에게 일괄 하청 발주하지 않고, 발주기관이 해당 상용SW 제조사와 직접 계약을 체결하여 조달·구매하도록 의무화한 공공 소프트웨어 발주 제도.
- 법적 근거 : 소프트웨어진흥법(상용소프트웨어 직접구매 관련 조항), 동법 시행령 관련 조항 및 과학기술정보통신부 고시.
- 도입 배경 : SI 주사업자의 상용SW 단가 후려치기(하도급 마진 착취), 대금 미지급, 라이선스 유지관리비 삭감 관행의 근절 필요.
- 주요 목적 : 정당한 가격 보장과 유지관리 품질 확보를 통한 국내 상용SW 생태계 육성.

## Ⅱ. 상용SW 직접구매의 특징

- 핵심 요약 : 일정 규모 이상 공공 사업의 상용SW 대상 제조사 직접 계약 의무화와 제한적 예외 심의 체계.

1. 의무 대상 요건 : 총 사업금액(추정가격) 3억 원 이상 소프트웨어 사업, 사업에 포함된 개별 상용 소프트웨어 추정가격 5천만 원 이상 대상 (단, GS(Good Software) 인증 제품 또는 조달청 우수조달물품은 의무 구매).
2. 예외 인정 사유의 제한성 : 다음 사유로 한정.
   1. 기 구축된 시스템과의 연계·호환 불가
   2. 국방·안보상 고도의 보안 요구
   3. 분리구매 시 사업비용 현저 증가 또는 납기 심각 지연
3. 사전 심의 의무 : 예외 적용 시 과업심의위원회 타당성 심의 통과 필수.
4. 계약 구조의 분리 : 나라장터 쇼핑몰 등 공공 조달 채널을 통한 제조사와의 별도 계약 체결.

## Ⅲ. 상용SW 직접구매의 구조 (흐름)

- 핵심 요약 : 발주 계획 수립, 요건 검토, 직접구매 추진 또는 예외 심의로 이어지는 절차 흐름.

```text
[ 공공 SW 사업 발주 계획 수립 ]
   │
   ▼
[ 직접구매 대상 요건 검토 ]
 - 사업금액 3억 원 이상
 - 상용SW 추정가격 5천만 원 이상
   │
   ├─ 요건 충족 (원칙) -> 직접구매 추진
   │   - 나라장터 쇼핑몰 직접구매
   │   - 제조사와 분리 계약 체결
   │
   └─ 예외 사유 발생 -> 제외 신청
       - 비용 상승, 일정 지연, 호환성 불가
       │
       ▼
   [ 과업심의위원회 타당성 심의 ]
       ├─ 예외 불인정 -> 직접구매
       └─ 예외 인정 -> SI 일괄 발주 허용
```

```text
[ 과거 : SI 일괄 발주 ]
발주기관 -> SI 주사업자 -> 상용SW 제조사 (하도급)

[ 현재 : 직접구매 ]
발주기관 -> SI 주사업자   (개발 용역 계약)
발주기관 -> 상용SW 제조사 (직접 계약, 정당 단가 보장)
```

- 계약 주체의 변화 : 상용SW 라이선스 계약을 SI 사업 계약에서 분리하여 발주기관과 제조사 간 직접 수행.
- 통합 관리 책임 : 발주자가 직접구매 SW와 SI 사업자 간의 통합 조정 책임 부담.

## Ⅳ. SI 일괄 발주와 상용SW 직접구매의 비교

- 핵심 요약 : 하도급 마진 차감 구조에서 정당 가격·품질 보증 구조로의 전환이 핵심 차별점.

| 비교 항목 | SI 일괄 발주 (과거 관행) | 상용SW 직접구매 (제도화) |
|---|---|---|
| 계약 주체 | 발주자와 SI 주사업자 간 단일 계약 (상용SW는 하도급) | 발주자와 SI 주사업자 계약 및 발주자와 상용SW 제조사 간 별도 계약 |
| 소프트웨어 대가 | SI 사업자의 마진 차감으로 원가 이하 납품 빈발 | 공공 조달 단가에 따른 정당한 제품 가격 보장 |
| 유지관리 및 기술지원 | SI 사업자가 영세 업체에 책임 전가, 지원 부실 | 제조사와 직접 유지관리요율 계약 체결로 품질 보증 |
| 통합 관리 책임 | SI 사업자가 시스템 전체에 대한 단일 책임 | 발주자가 직접구매 SW와 SI 사업자 간 통합 조정 책임 부담 |

## Ⅴ. 상용SW 직접구매의 장점과 한계

- 핵심 요약 : 가격 정당성과 생태계 육성 효과에 더해 통합 책임·행정 오버헤드 관리 과제 수반.

- 장점 :
  1. 공공 조달 단가 기반의 정당한 제품 가격 보장.
  2. 제조사 직접 유지관리요율 계약을 통한 품질 보증 및 기술지원 확보.
  3. 하도급 마진 착취 근절을 통한 국내 상용SW 생태계 육성.
- 한계 및 해결 방안 :
  1. 한계 : SI 주사업자와 상용SW 공급자 간 책임 회피 및 인터페이스 갈등으로, 연계 오류·성능 저하 발생 시 귀책 공방과 프로젝트 일정 지연 초래. / 해결 방안 : 발주 단계에서 주사업자의 통합 관리 책임 범위 명문화, 상용SW 공급자의 현장 기술지원 및 통합 테스트 참여 의무에 대한 SLA(Service Level Agreement) 계약 체결.
  2. 한계 : 분리발주 증가에 따른 발주기관의 개별 계약·검수·대가 지급 등 사업 관리 오버헤드 폭증. / 해결 방안 : PMO(Project Management Office, 전자정부사업관리자)의 분리발주 관리 지원 기능 강화, 디지털서비스 전문계약제도 및 종합쇼핑몰 조달 활성화를 통한 계약 절차 간소화.
  3. 한계 : 상용SW 간 비표준 연계로 인한 아키텍처 종속, 과도한 커스터마이징, 유지보수 비용 증가. / 해결 방안 : 전자정부 표준프레임워크 및 Open API(Application Programming Interface) 표준 인터페이스 준수 의무화, 제품 원형(Out-of-the-Box) 기능 중심의 요구사항 정의를 통한 커스터마이징 최소화.

## Ⅵ. 기술사적 제언

- 핵심 요약 : 통합비용 인정과 클라우드 구매 확장을 통한 제도 실효성 제고 필요.

- SW(Software) 통합비용(SW Integration Fee)의 정당 반영 : 발주기관이 직접구매한 상용SW를 SI 사업자가 연동하고 전체 시스템에 통합하는 과정의 개발 공수와 기술적 인터페이스 책임을 인정하고, 사업 예산에 'SW 커스터마이징 및 통합비용'의 공식적 책정·지급 필요.
- 클라우드 서비스 직접구매로의 제도적 확장 : 설치형 패키지 소프트웨어 중심의 직접구매 기준을 클라우드 전환 환경에 맞추어, 디지털서비스 전문계약제도를 통해 공공 검증된 클라우드 SaaS(Software as a Service)의 직접 수의계약·구독이 가능하도록 구매 절차의 패러다임 전환 가속화 필요.

## Ⅶ. 결론

- 핵심 요약 : 상용SW 직접구매는 하도급 관행을 개선한 공공 조달 제도로, 통합 책임 체계 보완이 성공의 관건.

- 상용SW 직접구매는 소프트웨어진흥법에 근거하여 제조사 직접 계약을 통한 가격 정당성 확보와 국내 상용SW 생태계 육성이라는 목적 지향.
- 제도의 실효성 제고를 위해 SI 사업자의 통합 책임 명확화, 표준 인터페이스 준수, 행정 절차 간소화, 클라우드 구매로의 확장 병행 필요.
