## 연관 키워드

1. 상용SW(Software) 직접구매
2. 소프트웨어진흥법
3. SI(System Integration, 시스템 통합) 일괄 발주
4. 과업심의위원회
5. GS(Good Software) 인증
6. SW 통합비용(SW Integration Fee)
7. 디지털서비스 전문계약제도

## Ⅰ. 상용SW 직접구매의 개요

- 핵심 요약 : 공공 소프트웨어 사업에 포함된 상용SW를 SI 주사업자를 거치지 않고 제조사와 직접 계약하도록 한 공공 조달 제도.
- 개념 : 국가기관, 지방자치단체, 공공기관이 소프트웨어 개발·구축 사업을 발주할 때, 사업에 포함된 **상용SW 직접구매** 대상 제품을 SI(System Integration, 시스템 통합) 주사업자에게 하도급으로 맡기지 않고 발주기관이 제조사와 직접 계약하여 조달하도록 한 제도.
- 법적 근거 : 소프트웨어진흥법과 하위 시행령·고시에 따라 운영되며, 대상 요건과 예외 기준은 해당 법령과 고시에서 확인한다.
- 도입 배경 : SI 주사업자가 상용SW 대금을 깎거나 하도급 과정에서 마진을 취하고, 유지관리 대금을 줄이는 관행을 바로잡을 필요가 있었다.
- 주요 목적 : 상용SW의 정당한 가격과 유지관리 품질을 보장하여 국내 상용SW 생태계를 육성.

## Ⅱ. 상용SW 직접구매의 특징 및 장점

- 핵심 요약 : 일정 규모 이상의 공공 사업에서 상용SW를 제조사와 직접 계약하는 것을 원칙으로 하고, 예외는 심의를 거치는 구조.

1. 직접구매 원칙 : 사업 규모와 개별 상용SW 금액 기준을 넘는 대상은 제조사와 직접 계약하는 것을 원칙으로 함.
2. 예외의 제한성 : 기존 시스템과의 연계·호환이 불가능하거나 국방·안보상 고도의 보안이 요구되는 등 명확한 사유에 한해 예외를 인정 → 원칙이 무너지는 것을 방지.
3. **과업심의위원회** (2020년 소프트웨어진흥법 개정으로 법제화된 심의 기구) : 예외를 적용하려면 위원회의 타당성 심의를 거치도록 함 → 예외 남용 방지.
4. 계약 구조 분리 : 제조사와 별도의 공공 조달 계약을 맺어 상용SW 대가를 SI 사업 대가와 분리 → 대가 투명성 확보.

## Ⅲ. 상용SW 직접구매의 구조 (흐름)

- 핵심 요약 : 발주 계획에서 요건 검토를 거쳐 직접구매를 추진하고, 예외 사유가 있을 때만 심의 절차로 들어가는 흐름.

```text
[ 발주 계획 수립 ]
          ↓
[ 상용SW 직접구매 요건 검토 ]
          ↓
  요건 충족 (원칙)
          ↓
[ 제조사와 직접 계약 ]
```

```text
[ 예외 사유 발생 ]
          ↓
[ 과업심의위원회 타당성 심의 ]
          ↓
  인정: SI 일괄 발주 허용
  불인정: 직접구매 추진
```

- 계약 주체의 변화 : 상용SW 계약을 SI 사업 계약에서 분리하여 발주기관과 제조사가 직접 계약한다.
- 통합 관리 책임 : 발주기관이 직접구매 SW와 SI 사업자 사이의 통합을 조정하는 책임을 진다.

```text
[ 과거 ] SI 일괄 발주
발주기관 → SI 주사업자 → 상용SW 제조사
                         (하도급)

[ 현재 ] 직접구매
발주기관 → SI 주사업자    (개발 용역)
발주기관 → 상용SW 제조사 (직접 계약)
```

## Ⅳ. SI 일괄 발주와 상용SW 직접구매의 비교

- 핵심 요약 : 하도급 마진을 거치는 구조에서 정당한 가격과 품질 보증이 담보되는 구조로 바뀐 것이 핵심 차이다.

| 비교 항목 | SI 일괄 발주 (과거 관행) | 상용SW 직접구매 (제도) |
| --- | --- | --- |
| 계약 주체 | 발주기관과 SI 주사업자 단일 계약, 상용SW는 하도급 | 발주기관과 SI 주사업자 계약, 발주기관과 제조사 별도 계약 |
| 소프트웨어 대가 | 주사업자의 마진 차감으로 원가 이하 납품이 빈발 | 공공 조달 단가에 따른 정당한 가격 보장 |
| 유지관리와 기술지원 | 영세 하청으로 책임이 넘어가 지원이 부실 | 제조사와 유지관리 계약을 맺어 품질 보증 |
| 통합 관리 책임 | 주사업자가 시스템 전체에 단일 책임 | 발주기관이 제조사와 주사업자 사이를 조정 |

## Ⅴ. 상용SW 직접구매의 장점과 한계

- 핵심 요약 : 가격 정당성과 생태계 육성이라는 장점에 통합 책임 공방과 행정 부담이라는 과제가 함께 따른다.

1. 공공 조달 단가에 기반한 정당한 제품 가격을 보장함.
2. 제조사와의 유지관리 계약과 GS(Good Software) 인증 같은 품질 인증을 통해 기술 지원 품질을 확보함.
3. 하도급 마진 구조를 줄여 국내 상용SW 생태계 육성에 기여함.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 책임 공방과 인터페이스 갈등 | 주사업자와 상용SW 공급자가 책임을 미뤄 연계 오류 시 귀책 공방과 일정 지연 발생 | 발주 단계에서 주사업자의 통합 관리 책임 범위를 명문화하고, 공급자의 현장 지원과 통합 테스트 참여를 SLA(Service Level Agreement)에 명시 | 연계 장애 처리 기간, 귀책 분쟁 건수 |
| 발주기관 관리 부담 | 분리 발주로 개별 계약, 검수, 대가 지급이 늘어 발주기관의 행정 부담 증가 | PMO(Project Management Office)의 분리 발주 관리 지원 강화, 계약 절차 간소화 | 계약 처리 기간, 발주기관 투입 인력 |
| 비표준 연계와 아키텍처 종속 | 상용SW 간 비표준 연계로 특정 제품에 묶이고 과도한 커스터마이징으로 유지비 증가 | 전자정부 표준프레임워크와 공개 API(Application Programming Interface) 준수, 제품 기본 기능 중심의 요구사항 정의 | 커스터마이징 비율, 표준 준수율 |

## Ⅵ. 기술사적 제언

- 핵심 요약 : 통합 공수를 사업 예산에 정당하게 반영하고, 직접구매의 범위를 클라우드 환경까지 넓혀 제도의 실효성을 높이는 방향.

1. 발주기관이 직접구매한 상용SW를 SI 사업자가 연동하고 전체 시스템에 통합하는 공수는 **SW 통합비용**(SW Integration Fee, 통합 개발 공수와 인터페이스 책임에 대한 대가)으로 인정하고, 사업 예산에 명시적으로 책정해야 한다.
2. 직접구매 기준이 설치형 패키지에 머물러 있으면 클라우드 전환 흐름을 따라가기 어려우므로, 공공 검증을 거친 SaaS(Software as a Service)도 디지털서비스 전문계약제도 같은 계약 수단으로 빠르게 구독할 수 있도록 구매 절차를 바꿔야 한다.

## Ⅶ. 결론

- 핵심 요약 : 상용SW 직접구매는 하도급 관행을 줄여 정당한 가격과 생태계 육성을 꾀하는 공공 조달 제도.
- 시사점 : 제도의 성패는 SI 주사업자의 통합 책임 명확화, 표준 인터페이스 준수, 행정 절차 간소화에 달려 있으며, 클라우드 구매로의 확장도 함께 검토할 과제다.
