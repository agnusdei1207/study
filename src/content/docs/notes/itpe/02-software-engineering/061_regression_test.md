## 연관 키워드
- 회귀테스트, 사이드 이펙트, 퇴보, 전체 재테스트, 회귀 테스트 선택, 테스트 케이스 우선순위화, Flaky 테스트, 테스트 영향도 분석

### Ⅰ. 회귀테스트의 개요

- 핵심 요약 : 코드 변경 후 기존에 정상 동작하던 기능이 깨지지 않았는지, 기존 테스트 케이스를 다시 실행해 확인하는 반복 검증 기법.
- 개념 : 결함 수정, 기능 추가, 리팩토링, 운영 환경 변경으로 소스코드가 바뀌었을 때, 기존에 정상 동작하던 영역에 사이드 이펙트(Side Effect)나 결함이 생기지 않았는지 기존 테스트 케이스를 재실행하는 회귀 테스트(Regression Test) 기법(**회귀테스트**, Regression Test).
- 배경 및 필요성 : 모듈 간 결합도가 높은 시스템에서는 한 줄의 수정이 무관한 기능의 장애로 이어질 수 있어, 변경 안전성을 입증하는 방어선이 필요.
- 주요 목적 : 기존 기능의 퇴보(Regression) 방지, 품질 안정성 유지, 빠른 릴리스 지원.

### Ⅱ. 회귀테스트의 특징 및 장점

- 핵심 요약 : 변경 영향을 막는 방어선으로서 3대 선정 전략을 상황에 맞게 쓰고, 조기 결함 발견을 위해 자동화를 전제로 반복 수행.

1. 변경 요인의 다양성 : 결함 수정, 기능 추가, 리팩토링, 운영 환경 변경 모두가 회귀 테스트의 발동 조건 → 변경 종류와 무관하게 안전성 확인.
2. 3대 선정 전략 : 전체 재테스트(Retest-All), 회귀 테스트 선택(RTS), 테스트 케이스 우선순위화 → 시간과 위험에 따라 조합.
3. 조기 결함 발견 : 중요도와 과거 결함 빈도를 기준으로 실행 순서 정해 Fail-Fast(실패를 빨리 드러내는 실행 순서) 달성.
4. 자동화 전제 : CI/CD(Continuous Integration/Continuous Delivery) 파이프라인에서 반복 실행 → 변경 직후 피드백 확보.

### Ⅲ. 회귀테스트의 구조 (흐름)

- 핵심 요약 : 코드 변경 감지부터 스위트 갱신까지의 순환 흐름.

```text
코드 변경 감지 (Git Diff)
   ↓
변경 영향도 분석
   ↓
테스트 케이스 선정과 우선순위화
   ↓
테스트 실행
   ↓
결과 분석
   ↓ 결함 발견
결함 보고와 수정
   ↓ Flaky 판정
격리 후 원인 분석
   ↓
테스트 스위트 갱신과 리팩토링
```

```text
전체 재테스트 (Retest-All)
회귀 테스트 선택 (RTS)
우선순위화 (Prioritization)
```

### Ⅳ. 회귀테스트 전략별 비교

- 핵심 요약 : 전체 재테스트는 안전성을, 선택과 우선순위화는 시간 효율을 극대화하는 트레이드오프 관계.

| 비교 축 | 전체 재테스트 (Retest-All) | 회귀 테스트 선택 (Selective) | 우선순위화 (Prioritization) |
|---|---|---|---|
| 장점 | 회귀 결함 누락 위험이 가장 낮음 | 실행 시간과 비용을 크게 줄임 | 제한된 시간 안에 위험도 높은 결함 먼저 발견 |
| 단점 | 빌드와 테스트 시간이 과다하게 듦 | 영향도 분석이 부정확하면 결함 누락 위험 | 우선순위 기준 수립과 유지보수 공수 |
| 적합 환경 | 소규모 프로젝트, 릴리스 직전 최종 QA | 일일 빌드, 잦은 소규모 배포 환경 | 야간 빌드, 대규모 회귀 스위트 |

### Ⅴ. 회귀테스트의 한계와 방안

- 핵심 요약 : 변경 안전성을 입증하는 방어선 효과와 스위트 비대화·Flaky 테스트·노후화 리스크가 공존.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 테스트 스위트 비대화 | 기능 확장에 따라 테스트가 수천에서 수만 개로 누적되어 배포 병목 발생 | RTS와 결함 이력 기반 우선순위화 적용 | 전체 실행 시간, 배포 대기 시간 |
| 불안정 테스트(Flaky Test) | 네트워크 지연·비동기 타이밍 등으로 간헐적 실패 | 실패한 테스트 자동 격리, 환경 격리, 명시적 대기 패턴 | 간헐 실패율, 격리 건수 |
| 테스트 케이스 노후화 | 폐기된 기능 테스트가 정리되지 않아 유지보수 공수 증가 | 정기 스위트 리팩토링·클린업, 뮤테이션 테스팅으로 검출력 없는 테스트 제거 | 유지보수 공수 비율, 뮤턴트 생존율 |

### Ⅵ. 지속적 배포(CD) 환경에서의 기술사적 제언

- 핵심 요약 : 변경 영향도 기반의 테스트 선택을 도구로 자동화하고, Flaky 테스트를 체계적으로 격리·관리하는 운영 체계 확립.

1. 테스트 영향도 분석(TIA, Test Impact Analysis) 도구를 CI/CD 파이프라인에 연계해 변경된 코드를 실행하는 테스트만 고름.
2. 불안정 테스트를 별도 격리 큐로 분리하고 담당 조직을 지정해 원인을 분석한 뒤 정기 클리닝 절차로 처리.

### Ⅶ. 결론

- 핵심 요약 : 회귀테스트는 코드 변경의 안전성을 입증하는 CI/CD 시대의 핵심 방어선이다.
- 시사점 : 3대 전략을 상황별로 조합하고, 영향도 분석 도구와 Flaky 테스트 정화를 병행해야 회귀 검증 체계가 지속 가능하다.
