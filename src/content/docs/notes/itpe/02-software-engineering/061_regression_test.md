## 지식 로드맵 내 현재 위치

지식 위치: 소프트웨어 공학 → 소프트웨어 테스트·품질 → 변경 관련 테스트 → 회귀테스트

## 30초 인출

- 본질: **회귀테스트**는 변경 뒤 기존 동작에 새 결함이 생기거나 드러났는지 확인하는 변경 관련 테스트
- 메커니즘: 변경 영향 분석 → 적절한 기존 테스트 선택·우선순위 지정 → 실행·결과 확인
- 핵심: 결함 수정 확인을 위한 재시험과 변경 영향에 따른 회귀 확인의 목적 구분

<details>
<summary>핵심 용어</summary>

- **회귀테스트(Regression Testing)**: 소프트웨어 변경 뒤 변경하지 않은 영역에 새 결함이 생기거나 드러났는지 확인하는 테스트
- **확인시험(Confirmation Testing, Retesting)**: 수정한 결함이 더 이상 재현되지 않는지 확인하는 시험
- **회귀 테스트 선택(RTS, Regression Test Selection)**: 변경 영향과 관련된 테스트를 골라 실행하는 전략
- **테스트 우선순위화(TCP, Test Case Prioritization)**: 테스트 실행 순서를 결함 위험·검출 가치 등에 따라 정하는 방법
- **테스트 영향 분석(TIA, Test Impact Analysis)**: 변경과 테스트 간 연관을 분석해 실행 대상·순서를 정하는 데 쓰는 활동

</details>

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **회귀테스트**는 소프트웨어 변경 뒤 변경하지 않은 영역에 새 결함이 생기거나 드러났는지 확인하는 변경 관련 테스트 |
| 목적 | 변경의 부작용으로 기존 동작이 손상되는 위험의 확인 |

### Ⅱ. 확인시험과 회귀테스트

| 구분 | 확인시험(재시험) | 회귀테스트 |
|---|---|---|
| 대상 | 수정된 결함과 실패했던 시험 | 변경으로 영향받을 수 있는 기존 기능·영역 |
| 목적 | 결함 수정 여부 확인 | 변경 영역 밖에 발생한 회귀 결함 확인 |
| 테스트 | 수정 전 실패한 사례 재실행 | 관련 테스트 또는 회귀 스위트 실행 |

### Ⅲ. 실행 방법

```text
코드·환경 변경
    ↓ 영향 범위 분석
관련 회귀 테스트 선정
    ↓ 위험도·실행시간 고려
우선순위에 따라 실행
    ↓
결함 조치·릴리스 판단
```

제언: 변경 영향과 위험도에 따라 선택·우선순위화한 테스트를 실행하고 미해결 실패를 검토.

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **회귀테스트**는 소프트웨어 변경 뒤 변경하지 않은 영역에 새 결함이 생기거나 드러났는지 확인하는 변경 관련 테스트 |
| 목적 | 변경의 부작용으로 기존 동작이 손상되는 위험의 확인 |

## Ⅱ. 확인시험과 회귀테스트의 구분

| 관점 | 확인시험(재시험) | 회귀테스트 |
|---|---|---|
| 검증 질문 | 수정했던 결함이 다시 발생하는가 | 이번 변경이 다른 기존 영역에 문제를 만들었는가 |
| 대상 선정 | 결함 재현 사례 | 변경·의존 영역과 기존 테스트 집합 |
| 결과 활용 | 수정 완료 여부 확인 | 변경의 영향 범위에 대한 신뢰도 판단 |

## Ⅲ. 회귀 테스트 스위트 운용 전략

| 전략 | 동작 | 적용 고려 |
|---|---|---|
| 전수 실행 | 저장된 회귀 테스트 전체 실행 | 충분한 실행 시간·자원이 확보될 때 |
| RTS(선택 실행) | 변경과 관련된 테스트를 분석해 일부 실행 | 변경-테스트 추적 정보의 품질이 중요할 때 |
| TCP(우선순위화) | 모든 대상의 실행 순서를 위험·가치 기준으로 정함 | 제한 시간 안에 높은 가치의 결과를 먼저 얻을 때 |

RTS는 무엇을 실행할지 선택하고, TCP는 실행 대상을 어떤 순서로 돌릴지 정하는 구분.

## Ⅳ. 변경 영향 분석과 자동 실행

```text
변경 파일·의존 관계 확인
    ↓
영향 받은 테스트 집합 구성
    ↓ 우선순위
CI에서 테스트 실행
    ↓ 실패·통과 증거
수정·릴리스 판단

변경·테스트 연결 → 다음 회귀 범위 갱신
```

테스트 영향 분석은 소스 변경·의존성·요구-테스트 추적 정보를 활용할 수 있으며, 분석 누락 위험을 고려해 중요 변경은 더 넓은 회귀 스위트로 확인.

## Ⅴ. 회귀테스트 운영 위험과 대응

| 위험 | 대응 |
|---|---|
| 선택 실행의 영향 분석 누락 | 변경-테스트 연결을 관리하고 위험도 높은 변경은 더 넓게 실행 |
| 테스트 집합 증가로 실행 지연 | 테스트 비용·실패 검출 가치에 따른 우선순위화와 불필요 사례 정리 |
| 간헐 실패로 결과 신뢰 하락 | 재현 조건 조사·격리·수정, 실패를 무조건 통과 처리하지 않음 |
| 변경 목적의 특정 결함 시험만 수행 | 확인시험과 회귀테스트를 함께 계획 |

## Ⅵ. 기술사적 제언 — 위험도와 검증 범위의 연계

| 한계 | 해결 방안 |
|---|---|
| 빠른 선택 실행만으로 테스트 영향 분석의 누락 가능성을 배제하기 어려움 | 변경 영향·업무 중요도·분석 신뢰도를 기준으로 PR 선택 테스트와 주기적 확대 회귀 실행을 병행하고, 중요 변경은 담당자 검토 대상으로 지정 |
