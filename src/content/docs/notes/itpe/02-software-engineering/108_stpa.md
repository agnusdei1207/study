## 30초 인출

- 본질: STPA는 사고를 부품 고장이 아닌 제어 구조에서의 불안전한 제어 행위로 보고 위험을 분석하는 시스템 이론 기반의 안전 분석 기법
- 메커니즘: 손실과 위험을 정의하고 제어 구조를 모델링한 뒤 불안전 제어 행위(UCA)를 식별하고 그 발생 원인을 손실 시나리오로 도출
- 통찰: 부품이 고장나지 않아도 제어 명령의 시점·순서가 잘못돼 사고가 나는 소프트웨어 사고는 고장 기반 분석으로 찾기 어려우므로 제어 구조에서 불안전 제어 행위를 식별해 원인 시나리오를 분석

<details>
<summary>핵심 용어</summary>

- **STPA(System-Theoretic Process Analysis)** : 제어 구조에서 불안전한 제어 행위와 손실 시나리오를 찾는 안전 분석 기법
- **STAMP(System-Theoretic Accident Model and Processes)** : 사고를 제어 결함의 결과로 보는 사고 모델. Leveson 제안
- **제어 구조(Control Structure)** : 제어기·제어 행위·피드백·제어 대상의 관계를 나타낸 모델
- **불안전 제어 행위(UCA, Unsafe Control Action)** : 특정 상황에서 위험을 일으키는 제어 행위
- **손실 시나리오(Loss Scenario)** : 불안전 제어 행위가 발생하는 원인을 서술한 시나리오

</details>

## 2~4교시 25점 답안

## Ⅰ. STPA의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **STPA** 는 제어 구조에서 불안전한 제어 행위를 찾아 위험을 분석하는 시스템 이론 기반 안전 분석 기법 |
| 목적 | 부품 고장 없이도 발생하는 소프트웨어·상호작용 위험의 식별 |

## Ⅱ. 고장 기반 분석과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 제어 관점 | 사고를 제어 결함으로 분석 |
| 상호작용 포함 | 구성요소 간 상호작용 결함 분석 |
| 설계 초기 적용 | 상세 설계 전에도 분석 가능 |

## Ⅲ. STPA 절차

### STPA 4단계

```text
1. 분석 목적 정의 ── 손실·위험·안전 제약
    ↓
2. 제어 구조 모델링 ── 제어기·제어 행위·피드백·제어 대상
    ↓
3. 불안전 제어 행위(UCA) 식별
    ↓
4. 손실 시나리오 도출 ── UCA 발생 원인
```

### 확대: 제어 구조와 UCA

```text
제어기(소프트웨어) ──제어 행위──→ 제어 대상(장치)
        ↑                             │
        └────────── 피드백 ───────────┘
UCA 유형: 제공 안 함 / 제공 시 위험 / 시점·순서 오류 / 너무 이르게·길게 지속
```

## Ⅳ. 기법 비교

| 구분 | FTA | FMEA | STPA |
|---|---|---|---|
| 관점 | 사고에서 원인 조합 | 부품 고장 영향 | 제어 행위와 상호작용 |
| 원인 범위 | 결함 조합 | 개별 고장 | 제어 결함·상호작용 |
| 소프트웨어 사고 | 결함 가정 필요 | 고장이 없으면 미검출 | 제어 로직 결함 식별 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 제어 구조 모델링 수준에 따라 결과 편차 | 분석 범위와 상세도 사전 합의 |
| UCA·시나리오 수가 많아 분석 부담 | 위험 큰 제어 행위 우선 분석 |
| 분석 결과의 요구사항 반영 누락 | UCA별 안전 제약을 요구사항으로 도출 |

## Ⅵ. 제언

위험이 큰 제어 행위부터 UCA를 식별하고, 손실 시나리오에서 도출한 안전 제약을 요구사항에 반영

### 적용 순서

```text
위험 큰 제어 행위 선별
    ↓
UCA 식별 → 손실 시나리오
    ↓
안전 제약 → 요구사항 반영
```

### 선택 근거: 고장 기반 분석만과의 비교

| 구분 | 고장 기반만 | 제언: STPA 병행 |
|---|---|---|
| 제어 로직 결함 | 미검출 가능 | 식별 |
| 상호작용 위험 | 곤란 | 분석 |
| 분석 시점 | 상세 설계 이후 | 설계 초기 |
