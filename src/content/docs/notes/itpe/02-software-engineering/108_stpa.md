## 연관 키워드
- STPA(System Theoretic Process Analysis), 제어 구조, 손실·위험 원, 안전 제약, 안전하지 않은 제어 행위(UCA), 시나리오

### Ⅰ. STPA의 개요

- 핵심 요약 : STPA(System Theoretic Process Analysis)는 시스템 구성 요소 간 제어와 피드백의 부적절성에서 사고·손실이 발생할 수 있다고 보고 위험을 분석하는 시스템 이론 기반 안전 분석 방법.
- 개념 : 시스템 구성 요소 간 제어와 피드백의 부적절성에서 사고·손실이 발생할 수 있다고 보고 위험을 분석하는 시스템 이론 기반 안전 분석 방법(**STPA**, System Theoretic Process Analysis).
- 배경 및 필요성 : 부품 고장 중심 분석만으로는 정상 구성 요소 간 상호 작용, 잘못된 제어, 정보·시간 맥락에 따른 위험을 충분히 찾기 어려움.
- 주요 목적 : 복잡한 상호 작용과 소프트웨어·사람·운영 조건에서 발생할 수 있는 손실을 예방하도록 안전 제약과 설계 요건 도출.

### Ⅱ. STPA의 특징 및 장점

- 핵심 요약 : 손실·위험 원 정의·제어 구조 모델링·UCA(Unsafe Control Action, 위험한 제어 행위) 분석·손실 시나리오.

1. 손실·위험 원 정의 : 손실과 시스템 위험 상태를 구체화 → 분석 경계와 안전 목표 설정.
2. 제어 구조 모델링 : 제어자·제어 행위·피드백·프로세스 모델 표현 → 안전 책임과 정보 흐름 확인.
3. UCA(위험한 제어 행위) 분석 : 제어 행위가 제공·미제공·시기·지속 측면에서 위험한 조건 식별 → 안전 제약 도출.
4. 손실 시나리오 : 제어기·피드백·환경·프로세스 모델의 결함 원인 분석 → 검증 가능한 안전 요건·완화책 도출.

### Ⅲ. STPA의 구조 (흐름)

- 핵심 요약 : 분석 목적·손실 정의 → 위험 원·안전 제약 초안 → 제어 구조 작성 → 안전하지 않은 제어 행위 분석 → 손실 시나리오 분석 → 안전 요건·통제 갱신.

```text
분석 목적·손실 정의
   ↓
위험 원·안전 제약 초안
   ↓
제어 구조 작성
   ↓
안전하지 않은 제어 행위 분석
   ↓
손실 시나리오 분석
   ↓
안전 요건·통제 갱신
```

```text
제어자 → 제어 행위 → 제어 대상 공정 → 결과
    ↑                           ↓
프로세스 모델 ← 피드백·센서 ← 상태 정보
           ↑
         환경·운영 조건
```

### Ⅳ. STPA와 FTA·FMEA 비교

- 핵심 요약 : STPA는 시스템 제어·피드백 상호 작용과 안전 제약을 분석, FMEA는 고장 모드 별 영향·심각도를 분석.

| 개념·방법 | 주요 특성 | 적합한 적용 조건 |
|---|---|---|
| STPA | 시스템 제어·피드백 상호 작용과 안전 제약 분석 | 소프트웨어·사람·운영이 얽힌 복합 시스템 |
| FMEA | 고장 모드 별 영향·심각도 분석 | 부품·기능 고장과 국소 영향 평가 |
| FTA | 정점 사건을 하위 원인 조합으로 분해 | 특정 사고의 원인 경로·논리 구조 분석 |

### Ⅴ. STPA의 한계와 방안

- 핵심 요약 : 제어 구조 경계 누락·UCA를 고장으로만 축소·안전 제약의 설계 미반영을 경계 검토·제어 행위별 4가지 위험 조건 분석·요구·설계·시험 추적으로 관리.

| 위험 | 원인·영향 | 통제·대응 | 지표 예시 |
|---|---|---|---|
| 제어 구조 경계 누락 | 외부 운영자·공급자·환경 제약 제외 | 시스템 경계·이해관계자·외부 통제 검토 | 검토되지 않은 인터페이스 |
| UCA를 고장으로만 축소 | 제공·시기·기간·순서의 제어 위험 누락 | 제어 행위별 4가지 위험 조건과 맥락 분석 | 미분석 제어 행위 |
| 안전 제약의 설계 미반영 | 분석 결과가 구현·시험으로 이어지지 않음 | 요구·설계·시험 추적과 변경 영향 검토 | 미추적 제약, 검증 누락 |

### Ⅵ. STPA 적용에 대한 기술사적 제언

- 핵심 요약 : 복잡한 상호 작용과 소프트웨어·사람·운영 조건에서 발생할 수 있는 손실을 예방하도록 안전 제약과 설계 요건 도출.

- 실행 제언 : 시스템 안전 책임자는 STPA를 개발 초기에 시스템 엔지니어링·운영·인간 요인·보안 분석과 함께 수행하고, 도출된 안전 제약의 요구·시험·운영 절차 반영을 추적.

### Ⅶ. 결론

- 핵심 요약 : STPA(System Theoretic Process Analysis)는 시스템 구성 요소 간 제어와 피드백의 부적절성에서 사고·손실이 발생할 수 있다고 보고 위험을 분석하는 시스템 이론 기반 안전 분석 방법.
- 시사점 : STPA는 구성 요소 고장만이 아니라 제어와 피드백의 구조적 불안전성을 분석해 복합 시스템의 안전 요건을 도출하는 방법.
