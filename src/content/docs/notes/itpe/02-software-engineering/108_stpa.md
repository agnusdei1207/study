지식 위치: 소프트웨어 공학 → 안전·위험 분석 → **STPA(System Theoretic Process Analysis)**

## 30초 인출

- 본질: **STPA(System-Theoretic Process Analysis)** 는 구성요소 상호작용에서 생기는 위험한 제어를 분석하는 시스템 이론 기반 기법
- 메커니즘: 손실·위험 정의 → 제어 구조 모델링 → 불안전 제어행위 식별 → 손실 시나리오와 안전 제약 도출
- 통찰: 한계: 부품 고장이 없어도 잘못된 제어 시점·누락으로 손실이 날 수 있음 → 방안: 제어·피드백 관계에서 UCA를 찾아 안전 제약으로 전환

<details>
<summary>핵심 용어</summary>

- **STPA(System-Theoretic Process Analysis)** : 제어 구조와 구성요소 상호작용을 분석해 손실을 예방하는 안전 분석 기법
- **STAMP(System-Theoretic Accident Model and Processes)** : 사고를 시스템 제어·제약의 문제로 모델링하는 시스템 이론 기반 사고 모델
- **불안전 제어행위(UCA, Unsafe Control Action)** : 제어행위의 제공 여부·시점·순서·지속이 안전하지 않은 상황
- **손실 시나리오(Loss Scenario)** : 제어행위가 불안전해지는 요인과 그 결과 손실에 이르는 상황 설명
- **안전 제약(Safety Constraint)** : 위험을 예방하기 위해 시스템이 지켜야 할 조건

</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **STPA(System-Theoretic Process Analysis)** 는 제어 구조와 구성요소 상호작용을 분석해 손실을 예방하는 안전 분석 기법 |
| 목적 | 부품 고장만으로 설명하기 어려운 위험한 제어와 상호작용을 찾아 안전 제약으로 전환 |

## Ⅱ. STPA의 특징

| 특징 | 분석 의미 |
|---|---|
| 시스템 제어 관점 | 부품 고장 외에 제어·상호작용의 위험 분석 |
| 상황 의존 UCA | 같은 제어행위도 조건·시점·지속에 따라 안전성 변화 |
| 제약 중심 결과 | 손실 시나리오를 안전 요구와 검증 조건으로 전환 |

## Ⅲ. 제어 구조와 STPA 분석 프로세스

```text
손실·위험 정의 → 제어 구조 모델링
                      ↓
제어기(공정 모델) ── 제어행위 ──→ 제어 대상·공정
       ↑                                  │
       └──────── 상태 피드백 ──────────────┘
                      ↓
행위의 누락·제공·시점·지속 UCA 식별
                      ↓
손실 시나리오 → 안전 제약 → 설계·시험 반영
```

제어기·제어 대상·피드백 정보의 식별과 제어기 내부 공정 모델 및 실제 공정 상태 간 불일치 가능성 분석

## Ⅳ. STPA 단계와 UCA 유형의 관계

| 순서 | 분석 활동 | 산출 내용 |
|---|---|---|
| 1 | 시스템 손실·위험·안전 제약 정의 | 분석 범위와 안전 목표 |
| 2 | 제어 구조 구성 | 제어기·행위·피드백 관계 |
| 3 | 제어행위별 제공 여부·시점·지속 조건 분석 | UCA 목록 |
| 4 | UCA가 발생하는 맥락·원인 분석 | 손실 시나리오 |
| 5 | 분석 결과를 설계·운영 요구에 반영 | 안전 제약·검증 근거 |

### 적용·검증 관점

| UCA 범주 | 위험 조건 |
|---|---|
| 제어 미제공 | 안전을 위해 필요한 제어의 누락 |
| 위험한 제어 제공 | 제어 제공 자체가 위험해지는 상황 |
| 잘못된 시점·순서 | 위험을 유발하는 제어 시점·순서 |
| 지속시간 오류 | 제어의 과도하거나 짧은 지속에 따른 손실 |

분석 경계·용어·제어 책임을 명확히 하고, 도출한 시나리오를 요구사항·설계·시험에서 추적 가능한 단위로 관리.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 부품 고장 없이도 제어 시점·누락으로 손실 가능 | 제어·피드백 관계에서 UCA를 식별하고 안전 제약으로 전환 |
| 제어기 내부 모델과 실제 공정 상태 불일치 | 피드백 누락·지연을 손실 시나리오에 포함해 감지·대응 조건 정의 |
| 분석 결과가 설계·시험과 분리되어 제약 실효성 미확인 | 제약마다 설계 요소·시험 사례를 연결하고 변경 때 재검증 |

## Ⅵ. 제언

우선 실행: 각 제약에 설계 요소와 시험 시나리오를 연결하고 변경 시 영향 분석과 재검증 범위를 검토.
