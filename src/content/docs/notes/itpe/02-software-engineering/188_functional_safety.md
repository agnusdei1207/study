## Ⅰ. 기능안전(Functional Safety)의 개요

- **개념** : 전기·전자·소프트웨어 기반 제어 시스템의 오작동, 내부 부품 결함 또는 예기치 못한 환경적 장애가 발생하더라도, 시스템이 이를 감지하여 안전 상태(Safe State)로 전이하거나 위험을 허용 가능한 잔존 위험(Tolerable Risk) 수준 이하로 억제하도록 보장하는 안전 공학 체계.
- **배경 및 필요성** : 자율주행차, 원자력 발전소, 항공기 비행제어, 의료 로봇 등 복잡한 임베디드 제어 시스템의 소프트웨어 오류가 대형 인명 피해(사망, 상해)로 직결되는 참사를 방지.
- **모태 및 도메인 표준** : 모태 표준 IEC 61508(전기/전자/프로그래밍 가능 전자 시스템의 기능안전), 자동차 도메인 ISO 26262, 철도 EN 50128, 항공 DO-178C.

## Ⅱ. 위험도 분석 및 안전 무결성 등급(ASIL / SIL) 결정 메커니즘

```text
   [ 위험원 분석 및 위험도 평가 (HARA: Hazard Analysis and Risk Assessment) ]
                                      │
         ┌────────────────────────────┼────────────────────────────┐
         ▼                            ▼                            ▼
   [ 심각도 (Severity, S) ]     [ 노출 확률 (Exposure, E) ]  [ 통제 가능성 (Controllability, C) ]
   - S0: 무상해                 - E1: 극히 희박              - C1: 통제 용이 (99% 운전자 대처)
   - S1: 경상/중상              - E2: 낮은 빈도              - C2: 보통 통제 (90% 대처)
   - S2: 중상/생명 위협         - E3: 중간 빈도              - C3: 통제 극난 (사고 회피 불가)
   - S3: 치명적 사망            - E4: 상시 주행
                                      │
                                      ▼
             [ 자동차 안전 무결성 등급 확정: ASIL = S x E x C ]
              (QM -> ASIL A -> ASIL B -> ASIL C -> ASIL D: 최고 안전 요구)
```

- **SIL (Safety Integrity Level - IEC 61508)** : 1단계부터 4단계까지 정의되며, SIL 4는 시간당 고장 확률 $10^{-9}$ 이하의 최고 안전 무결성을 요구.
- **ASIL (Automotive Safety Integrity Level - ISO 26262)** : 심각도(S0~S3), 노출 빈도(E1~E4), 운전자 통제 가능성(C1~C3)의 매트릭스 조합으로 QM(Quality Management)부터 ASIL A, B, C, D까지 5단계 등급 부여.

## Ⅲ. 무작위 하드웨어 고장과 체계적 소프트웨어 고장의 비교

| 비교 항목 | 무작위 하드웨어 고장 (Random Hardware Failure) | 체계적 소프트웨어 결함 (Systematic Failure) |
|---|---|---|
| 발생 원인 | 물리적 마모, 열화, 방사선에 의한 비트 플립(Bit-Flip) | 요구사항 명세 오해, 코딩 논리 오류, 설계 결함 |
| 예측 가능성 | 통계적 확률 분포(FIT, MTBF)로 고장률 정량 예측 가능 | 확률적 예측 불가 (동일 조건 입력 시 100% 동일 결함 재현) |
| 대응 방안 | 하드웨어 이중화(듀얼 코어 락스텝), ECC 메모리, 워치독 | 엄격한 프로세스 준수(V-모델), MISRA-C 정적 분석, MC/DC 검증 |
| 안전 메트릭 | SPFM(단일점 결함 메트릭), LFM(잠재 결함 메트릭) | 결함 밀도, 테스트 커버리지, 프로세스 성숙도(Automotive SPICE) |

## Ⅳ. 고신뢰성 제어 소프트웨어 구축을 위한 기술사적 제언

- **페일 세이프(Fail-Safe)에서 페일 오퍼레이셔널(Fail-Operational)로의 아키텍처 진화** : 레벨 3 이상의 자율주행 시스템에서는 제어기 고장 시 단순 전원 차단(Fail-Safe)만으로는 대형 사고를 유발하므로, 제어기가 고장 나더라도 보조(Secondary) 제어기가 최소 10초 이상 조향 및 제동을 유지하여 갓길에 안전 정차하는 Fail-Operational 아키텍처 필수 구축.
- **소프트웨어 안전 수명주기 전반의 A-SPICE 레벨 3 연계 인증** : 프로세스 결함이 곧 소프트웨어 결함으로 직결되므로, Automotive SPICE 레벨 3 인증을 획득하여 요구사항 추적성, 양방향 아키텍처 검증, 변경 영향도 분석 체계를 전사 프로세스에 의무 내재화해야 함.
