## 지식 로드맵 내 현재 위치

지식 위치: 소프트웨어공학 → 안전 관련 시스템 → **기능안전**

## 30초 인출

- 본질: **기능안전** 은 안전 관련 시스템이 위험한 상황에서 필요한 안전 기능을 수행해 위험을 허용 가능한 수준으로 줄이는 활동
- 메커니즘: 위험원 식별·평가 → 안전 목표·요구사항 도출 → 설계·구현 → 검증·확인 → 운영 중 변경 관리
- 통찰: 한계: 위험 분석과 안전 시험의 연결이 끊기면 통제의 충분성을 설명할 수 없음 → 방안: 위험원·안전 목표·요구·검증 증거를 추적

<details>
<summary>핵심 용어</summary>

- **기능안전(Functional Safety)** : 안전 관련 시스템의 안전 기능이 의도한 조건에서 제대로 작동하도록 위험을 관리하는 체계
- **IEC 61508** : 전기·전자·프로그래머블 전자 시스템의 기능안전 기본 표준
- **ISO 26262** : 도로 차량의 전기·전자 시스템을 대상으로 한 기능안전 표준
- **HARA(Hazard Analysis and Risk Assessment)** : 차량의 오작동에 따른 위험 상황을 분석하고 위험을 평가하는 활동
- **ASIL(Automotive Safety Integrity Level)** : ISO 26262에서 위험 평가 결과에 따라 정하는 차량 안전 무결성 등급
- **안전 케이스(Safety Case)** : 안전 주장을 뒷받침하는 논증과 증거의 집합
</details>

## 2~4교시 25점 답안

## Ⅰ. 기능안전의 개요

| 구분 | 내용 |
|---|---|
| 정의 | **기능안전** 은 안전 관련 시스템의 안전 기능으로 위험을 허용 가능한 수준으로 줄이는 활동 |
| 목적 | 고장·오작동이 위험 상황으로 이어질 가능성과 영향을 관리 |

## Ⅱ. 기능안전의 특징

| 특징 | 의미 |
|---|---|
| 위험 기반 | 위험원·오작동 분석으로 안전 목표 설정 |
| 요구 추적 | 안전 목표부터 설계·시험 증거까지 연결 |
| 생명주기 관리 | 개발 검증뿐 아니라 운영 중 변경·사고 정보 반영 |

## Ⅲ. 안전 생명주기와 요구 도출 체계

```text
위험 분석·안전 목표
    ↓ 안전 요구·설계·구현
검증·독립 확인
    ↓ 운영·변경 관리
변경·사고 정보 → 위험 재평가
```

### 위험 분석에서 요구사항으로

```text
위험원·오작동 식별
    ↓ 위험 상황 평가
안전 목표
    ↓
기능 안전 요구
    ↓
기술·소프트웨어 안전 요구
```

위 화살표는 **위험 분석에서 요구사항으로 이어지는 도출 관계** . 자동차 분야에서는 HARA 결과를 ASIL 판단과 안전 목표 설정에 사용.

## Ⅳ. 안전 활동과 적용 표준의 관계

| 단계 | 핵심 활동 | 확인할 증거 |
|---|---|---|
| 위험 분석 | 사용 상황과 고장으로 인한 위험 평가 | 위험 분석 결과 |
| 요구사항 | 안전 목표를 기능·기술 요구로 구체화 | 요구사항·추적 관계 |
| 구현·검증 | 안전 기능 설계와 단계별 시험 | 검증 결과·결함 조치 |
| 운영·변경 | 현장 결함 감시와 변경 영향 검토 | 변경 기록·재검증 |

### 소프트웨어 검증과 증거

| 검증 대상 | 방법 | 판단 |
|---|---|---|
| 안전 요구사항 | 추적성 검토 | 위험·목표·설계·시험의 연결 |
| 구현 | 정적 분석·코드 검토 | 결함과 개발 규칙 위반 발견 |
| 안전 기능 | 단위·통합·시스템 시험 | 요구한 조건에서 동작 확인 |
| 고장 상황 | 결함 주입 등 해당 시험 | 고장 탐지와 대응의 유효성 |

적용할 분석·시험 방법과 범위는 **산업별 표준, 위험 수준, 시스템 특성** 에 따라 결정. 특정 커버리지나 장비 시험을 모든 기능안전 프로젝트의 일률적 의무로 단정하지 않음.

### 표준의 역할과 적용 경계

| 표준 | 적용 관점 |
|---|---|
| IEC 61508 | 전기·전자·프로그래머블 전자 안전 관련 시스템의 기본 요구 |
| ISO 26262 | 도로 차량 전기·전자 시스템의 기능안전 활동 |

ISO 26262의 HARA·ASIL은 **자동차 도메인** 의 판단 틀이며, 모든 산업의 기능안전 등급을 ASIL로 부르지 않음.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 위험 분석과 시험 사이 추적 단절 | 위험원·목표·안전 요구·시험 결과를 식별자로 연결 |
| 안전 주장에 대한 근거 부족 | 설계·시험·결함 조치 증거를 안전 케이스로 연결 |
| 운영 변경 후 안전성 미확인 | 변경 영향에 따라 위험 재평가·관련 시험 재실행 |

## Ⅵ. 제언

우선 실행: 위험도가 높은 안전 요구부터 설계 통제와 시험·결함 조치 증거를 안전 케이스에 연결.
