## 핵심 용어
- 소프트웨어 위기(Software Crisis): 1968년 NATO 컨퍼런스에서 처음 언급된 용어로, 하드웨어 성능 급증에 비해 소프트웨어 개발 기술이 따라가지 못해 일정 지연, 비용 폭증, 품질 저하가 만연하던 상태
- 은총알은 없다(No Silver Bullet): 프레드 브룩스가 주창한 명제로, 소프트웨어 고유의 본질적 난제(복잡성, 일치성, 변경가능성, 비가시성)로 인해 소프트웨어 생산성을 단번에 10배 끌어올릴 수 있는 마법의 단일 기법은 존재하지 않는다는 원칙

## 핵심 통찰
- 소프트웨어는 건축이나 토목과 달리 물리적 마모가 없지만, 끊임없이 변화하는 비즈니스 환경과 기술 스택에 적응해야 하는 "지속적 진화(Software Evolution)"의 속성을 가짐
- 현대 소프트웨어 공학은 단순히 "어떻게 코딩할 것인가"를 넘어, 지속적 전달(CI/CD), 사이트 신뢰성 공학(SRE), 플랫폼 엔지니어링(IDP)을 포괄하는 "개발과 운영의 전주기 통합 거버넌스"로 확장됨
- 생성형 AI(GitHub Copilot, LLM)의 등장으로 코딩 자체의 비용은 0으로 수렴하고 있으나, 요구사항의 엄밀한 정의, 아키텍처 정합성 검증, 시스템 안전성 보장이라는 소프트웨어 공학의 본질적 역할은 오히려 중요성이 극대화됨

## 이웃 토픽과 구분
- 컴퓨터 과학(Computer Science) vs 소프트웨어 공학(Software Engineering): 컴퓨터 과학 = 알고리즘, 계산 이론 등 이론적 원리와 수학적 탐구 / 소프트웨어 공학 = 현실 세계의 비용, 일정, 품질 제약 내에서 시스템을 성공적으로 구축하는 실천적 응용 학문
