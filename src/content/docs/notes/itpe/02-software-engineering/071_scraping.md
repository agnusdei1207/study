## 30초 인출

- 본질: 스크래핑은 웹 페이지나 화면에 표시된 정보를 프로그램으로 읽어 필요한 데이터로 추출하는 기술
- 메커니즘: 페이지를 요청해 HTML의 DOM 구조에서 대상 요소를 선택하고 데이터를 추출·정제해 저장
- 통찰: 화면 구조에 의존하므로 페이지가 바뀌면 수집이 깨지고 약관·저작권·개인정보 문제도 있으므로 공식 API를 우선 사용하고 스크래핑은 허용 범위 내에서 제한적으로 적용

<details>
<summary>핵심 용어</summary>

- **스크래핑(Scraping)** : 화면에 표시된 정보를 프로그램으로 추출하는 기술
- **크롤링(Crawling)** : 링크를 따라가며 웹 페이지를 체계적으로 탐색·수집하는 활동
- **DOM(Document Object Model)** : HTML 문서를 트리 구조의 객체로 표현한 모델
- **헤드리스 브라우저(Headless Browser)** : 화면 없이 백그라운드에서 페이지를 실행하는 브라우저
- **robots.txt** : 사이트가 수집 로봇의 접근 허용 범위를 알리는 파일
- **API** : 프로그램이 서비스의 데이터와 기능을 호출하도록 제공하는 공식 인터페이스

## 2~4교시 25점 답안

## Ⅰ. 스크래핑의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **스크래핑** 은 화면에 표시된 정보를 프로그램으로 읽어 데이터로 추출하는 기술 |
| 목적 | API가 없는 서비스의 데이터 수집 자동화 |

## Ⅱ. API와 구별되는 스크래핑의 특징

| 특징 | 의미 |
|---|---|
| 화면 기반 추출 | 제공자가 공식 제공하지 않은 형태의 수집 |
| 구조 의존 | 화면 구조가 바뀌면 수집 실패 |
| 법적 쟁점 | 약관·저작권·개인정보 |

## Ⅲ. 스크래핑 절차

### 수행 절차

```text
대상 페이지 요청
    ↓
HTML 수신 → DOM 구조 분석
    ↓
대상 요소 선택·데이터 추출
    ↓
정제·저장
```

### 확대: 동적 페이지 처리

```text
정적 HTML → 직접 파싱
동적 렌더링(스크립트로 생성) → 헤드리스 브라우저로 실행 후 추출
```

## Ⅳ. 스크래핑·크롤링·API의 비교

| 구분 | 스크래핑 | 크롤링 | API |
|---|---|---|---|
| 목적 | 특정 데이터 추출 | 페이지 탐색·수집 | 공식 데이터 제공 |
| 안정성 | 화면 변경에 취약 | 구조 변경에 영향 | 명세로 안정 |
| 법적 위험 | 약관·저작권 이슈 | 접근 정책 위반 가능 | 이용 조건 준수 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 화면 변경 시 수집 실패 | 변경 감지와 선택자 관리 |
| 약관·저작권·개인정보 위반 위험 | 이용 약관과 robots.txt 확인, 개인정보 수집 회피 |
| 과도한 요청으로 서버 부담 | 요청 간격 제한 |

## Ⅵ. 제언

공식 API가 있으면 API를 우선 사용하고, 없을 때만 약관과 접근 정책의 허용 범위 안에서 스크래핑 적용

### 수집 방식 선택

```text
데이터 필요
    ├─ 공식 API 있음 → API 사용
    └─ 없음 → 약관·robots.txt 확인
                 ├─ 허용 → 제한적 스크래핑
                 └─ 금지 → 제공자와 협의
```

### 선택 근거: 무제한 스크래핑과의 비교

| 구분 | 무제한 스크래핑 | 제언: API 우선·허용 범위 |
|---|---|---|
| 안정성 | 낮음 | 높음 |
| 법적 위험 | 큼 | 낮음 |
| 제공자 관계 | 충돌 | 협력 |
