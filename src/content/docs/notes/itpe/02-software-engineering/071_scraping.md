## 한 줄 본질
- 제휴 API가 없는 웹사이트에서 데이터를 가져오기 위해 사용자 로그인 화면을 흉내 내어 HTML 태그를 긁어오는 과도기적 병목 → 헤드리스 브라우저로 DOM 구조를 파싱해 데이터를 추출하되 장기적으로 표준 API로 전환 → 신속한 데이터 연계 달성 / 원천 사이트 UI 변경 시 즉각 장애 및 인증정보 유출 위험

## 핵심 용어
- 스크린 스크래핑(Screen Scraping): 웹 서버가 렌더링한 HTML 화면 데이터에서 필요한 텍스트나 데이터를 소프트웨어가 자동으로 가공·추출하는 기술
- OAuth 2.0: 사용자 비밀번호를 직접 공유하지 않고, 접근 권한을 가진 토큰(Token)만을 발급받아 안전하게 자원에 접근하는 인증·인가 표준

## 핵심 통찰
- 스크래핑은 표준 API가 열리지 않았던 초기 핀테크 및 자산관리 시장을 태동시킨 혁신 동력이었으나, 태생적으로 보안성과 안정성의 치명적 한계를 안고 있음
- 스크래핑 방식은 원천 기관 웹사이트의 CSS 클래스명이나 HTML 태그 하나만 바뀌어도 전체 데이터 수집이 중단되므로 막대한 파서 유지보수 비용을 초래함
- 무엇보다 사용자의 공인인증서와 비밀번호를 핀테크 기업 서버에 저장(대리 로그인)해야 하므로, 금융보안 관점에서 마이데이터 표준 API 의무화로 전면 퇴출됨

## 이웃 토픽과 구분
- 스크래핑 vs 크롤링(Crawling): 크롤링 = 웹 페이지의 링크를 타고 다니며 사이트 전체를 탐색·수집(검색엔진 인덱싱) / 스크래핑 = 특정 웹페이지의 특정 데이터 필드만을 타겟팅하여 정밀 추출
