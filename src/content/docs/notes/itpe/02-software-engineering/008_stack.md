## 연관 키워드

- 스택(Stack), LIFO(Last In First Out), top, push, pop, peek
- 호출 스택(Call Stack), 오버플로우(Overflow), 깊이 우선 탐색(DFS, Depth-First Search), 큐(Queue)

## Ⅰ. 스택의 개요

- 핵심 요약 : 한쪽 끝에서만 삽입·삭제가 일어나 최근 입력이 먼저 출력되는 선형 자료구조.
- 개념 : 삽입과 삭제가 동일한 끝(top)에서만 수행되어 가장 나중에 넣은 원소가 가장 먼저 나오는, 즉 **LIFO** (Last In First Out) 순서를 따르는 선형 자료구조가 **스택** (Stack).
- 배경 및 필요성 : 함수 호출의 복귀 주소 관리, 괄호 짝 검사, 실행 취소(undo)처럼 가장 최근 항목부터 처리하는 작업의 체계적 지원 필요.
- 주요 목적 : 접근 지점을 한 곳으로 제한한 단순한 연산 집합으로 순서 의존 작업의 안전한 처리.

## Ⅱ. 스택의 특징 및 장점

- 핵심 요약 : 단일 접근점과 최소 연산 집합이 상수 시간과 구현 단순성을 보장.

1. 단일 접근점 : 모든 연산이 top이라는 한쪽 끝에서 수행 → 데이터 크기와 무관한 상수 시간 O(1) 보장.
2. 최소 연산 집합 : 삽입 **push** (삽입 연산)·삭제 **pop** (삭제 연산)·조회 **peek** (top 원소 조회 연산)의 세 연산만 공개 → 구현 단순·오류 여지 축소.
3. 역방향 추적 : 방문 순서를 역순으로 되돌리는 구조 → 실행 취소·백트래킹·경로 역추적 지원.
4. 구현 은닉 : 배열·연결 리스트 구현을 인터페이스 뒤에 숨김 → 내부 표현 교체의 자유로움.

## Ⅲ. 스택의 구조 (흐름)

- 핵심 요약 : 세 연산 모두 상태 검사 뒤 top 기준으로 수행되는 최소 절차.

```text
push(x) : 용량 확인 → x 저장 → top 이동
pop()   : 빈 상태 확인 → top 원소 제거·반환 → top 이동
peek()  : 빈 상태 확인 → top 원소 반환 (top 유지)
```

```text
top → C   (마지막 입력·첫 출력)
       B
       A   (bottom, 최초 입력)
pop 순서: C → B → A
```

- 구현 방식 : 배열 구현은 메모리 지역성과 고정 용량, 연결 리스트 구현은 동적 크기와 포인터 비용이 특징.
- 대표 응용 : 함수 호출 시 매개변수·지역변수·복귀 주소를 **호출 스택** (Call Stack) 프레임으로 관리, 그래프 **깊이 우선 탐색** (DFS, Depth-First Search)의 되돌아가기 경로 관리.

## Ⅳ. 스택(Stack)과 큐(Queue)의 비교

- 핵심 요약 : 스택이 최근 항목 우선의 LIFO 구조인 반면 큐는 도착 순서 우선의 FIFO 대기 구조.

| 비교 축 | 스택 (Stack) | 큐 (Queue) |
| --- | --- | --- |
| 처리 순서 | LIFO (Last In First Out) | FIFO (First In First Out) |
| 삽입·삭제 위치 | 같은 끝(top) | 뒤(rear) 삽입·앞(front) 삭제 |
| 대표 연산 | push·pop·peek | enqueue·dequeue |
| 대표 응용 | 호출 스택·실행 취소·깊이 우선 탐색 | 작업 대기열·메시지 버퍼·너비 우선 탐색 |

## Ⅴ. 스택의 한계와 방안

- 핵심 요약 : 용량 초과·빈 상태 접근·재귀 깊이·동시 접근이 오류 원인이므로 경계 검사와 자원 상한 관리 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **오버플로우** (Overflow, 가득 찬 스택의 저장 시도) | 고정 용량 초과 시점의 저장 시도 → 예외·데이터 손실 | 동적 확장 구조·저장 전 용량 검증 | 오버플로우 발생 건수 |
| **언더플로우** (Underflow, 빈 스택의 삭제 시도) | 빈 상태 접근 → 유효하지 않은 값 반환 | 삭제 전 상태 검사·명시적 오류 처리 | 언더플로우 발생 건수 |
| 깊은 재귀 | 함수 호출 누적으로 호출 스택 고갈 | 반복문 전환·재귀 깊이 상한 관리 | 최대 호출 깊이 |
| 동시 접근 경합 | 멀티스레드 환경의 push·pop 경합 → 원소 손실 | 잠금 기반 동기화·단일 소유자 설계 | 동시성 오류 건수 |

## Ⅵ. 스택 활용에 대한 제언

- 핵심 요약 : 연산 계약의 문서화와 경계 시험의 의무화로 구현·사용 양쪽의 오류를 예방.

1. 라이브러리 개발 조직은 push·pop·peek의 시간 복잡도와 예외 동작을 인터페이스 명세로 문서화.
2. 애플리케이션 개발 조직은 입력 크기와 최대 중첩 깊이를 시험 항목으로 등록하고 재귀 알고리즘의 깊이 상한을 설정 기준으로 관리.
3. 설계 검토에서 공유 자원의 스택 동시 접근 정책을 자료구조 선택 체크리스트에 포함.

## Ⅶ. 결론

- 핵심 요약 : 스택은 LIFO 순서가 자연스러운 작업을 최소 연산으로 표현하는 기초 자료구조.
- 시사점 : 단순한 구조일수록 용량·경계·호출 깊이 조건의 명시적 관리 필요.
