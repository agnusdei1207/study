## 연관 키워드
- 스택, LIFO, push, pop, peek, 호출 스택, 오버플로우

### Ⅰ. 스택의 개요

- 핵심 요약 : 스택은 마지막에 들어온 원소가 먼저 나가는 LIFO 순서의 선형 추상 자료형.
- 개념 : 한쪽 끝(top)에서 삽입·삭제를 수행하는 자료구조(**스택**, Stack).
- 배경 및 필요성 : 함수 호출, 괄호 검사, 되돌리기처럼 최근 항목 우선 처리가 필요.
- 주요 목적 : 제한된 연산으로 후입선출 작업을 표현.

### Ⅱ. 스택의 특징 및 장점

- 핵심 요약 : top 중심 연산은 O(1)이며 접근 순서가 제한되어 임의 탐색에는 부적합.

1. push/pop : top에서 삽입·삭제 → 단순한 상수시간 연산.
2. 캡슐화 : 내부 배열·연결 구현을 ADT 뒤에 숨김 → 표현 변경 용이.
3. 호출 관리 : 함수 문맥·복귀 주소 저장 → 재귀·중첩 처리 지원.

### Ⅲ. 스택 연산과 구현 (흐름)

- 핵심 요약 : 빈 스택·가득 찬 스택을 검사하고 top만 갱신.

```text
push(x): overflow 확인 → top 증가 → S[top]=x
pop(): underflow 확인 → x=S[top] → top 감소 → x 반환
peek(): 비어 있지 않으면 S[top] 반환
```

```text
top → [C]  ← 마지막 입력, 먼저 출력
       [B]
       [A]  ← bottom
pop 순서: C → B → A
```

- 구현 : 배열은 지역성과 고정 용량, 연결 리스트는 동적 크기와 포인터 비용이 특징.

### Ⅳ. 스택과 큐 비교

- 핵심 요약 : 스택은 LIFO, 큐는 FIFO로 대기·처리 순서를 다르게 표현.

| 비교 축 | 스택 | 큐 |
|---|---|---|
| 순서 | 후입선출 | 선입선출 |
| 삽입·삭제 | 같은 끝(top) | rear 삽입, front 삭제 |
| 응용 | 호출 스택, undo, DFS | 작업 대기열, BFS, 메시지 버퍼 |

### Ⅴ. 스택의 한계와 방안

- 핵심 요약 : 용량 초과·빈 자료 pop·재귀 깊이는 오류를 만들므로 경계와 자원 상한 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| Overflow | 쓰기 초과·예외 | 동적 확장 또는 용량 검증 | 오버플로우 건수 |
| Underflow | 유효하지 않은 삭제 | 사전 검사·명시적 오류 처리 | underflow 건수 |
| 깊은 재귀 | 호출 스택 고갈 | 반복형 알고리즘·깊이 제한 | 최대 재귀 깊이 |

### Ⅵ. 스택 적용 제언

- 핵심 요약 : 구현자는 ADT 계약, 예외 규칙, 동시 접근 여부를 사용 맥락에 맞게 정의.

1. 라이브러리 개발자는 push/pop의 시간·오류 계약을 문서화.
2. 애플리케이션 팀은 입력 크기와 최대 중첩을 시험하고 무한 재귀 방지.
3. 공유 스택은 잠금 또는 단일 소유자 모델 적용.

### Ⅶ. 결론

- 핵심 요약 : 스택은 LIFO가 자연스러운 작업을 간결하게 표현하는 기본 자료구조.
- 시사점 : 단순한 연산에도 용량·경계·호출 깊이와 동시성 조건이 필요.
