## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 설계·아키텍처 → **모듈성(결합도·응집도)**

## 30초 인출

- 본질: 모듈성은 소프트웨어를 독립적으로 개발·시험·수정할 수 있는 모듈로 나누는 성질이며 결합도는 모듈 간 의존의 강도, 응집도는 모듈 내부 요소의 관련성 정도
- 메커니즘: 좋은 설계는 결합도를 낮추고 응집도를 높여 한 모듈의 변경이 다른 모듈로 번지지 않게 함
- 통찰: 결합도와 응집도는 코드를 읽고 판단하기 어려우므로 설계 검토에서 모듈 간 의존 방식과 모듈 내부 관련성을 등급표 기준으로 점검해 개선 대상을 고름

<details>
<summary>핵심 용어</summary>

- **모듈성(Modularity)** : 시스템을 독립적으로 다룰 수 있는 모듈로 나눈 정도
- **결합도(Coupling)** : 모듈 간 상호 의존의 강도. 낮을수록 좋음
- **응집도(Cohesion)** : 모듈 내부 요소들이 하나의 목적으로 관련된 정도. 높을수록 좋음
- **팬인(Fan-in)·팬아웃(Fan-out)** : 모듈을 호출하는 모듈 수와 모듈이 호출하는 모듈 수
- **정보 은닉** : 변경 가능성이 큰 내부 구현을 모듈 안에 감추는 원칙

</details>

## 2~4교시 25점 답안

## Ⅰ. 모듈성의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **모듈성** 은 소프트웨어를 독립적으로 개발·수정할 수 있는 모듈로 나누는 성질 |
| 목적 | 변경 영향의 국소화와 유지보수성 향상 |

## Ⅱ. 특징

| 특징 | 의미 |
|---|---|
| 낮은 결합도 | 모듈 간 의존 최소화 |
| 높은 응집도 | 모듈 내부가 하나의 목적에 집중 |
| 정보 은닉 | 내부 구현 감춤 |

## Ⅲ. 결합도와 응집도의 등급

```text
결합도 (낮음이 좋음)               응집도 (높음이 좋음)
  자료 결합   ← 좋음                  기능적 응집   ← 좋음
  스탬프 결합                        순차적 응집
  제어 결합                          교환적 응집
  외부 결합                          절차적 응집
  공통 결합                          시간적 응집
  내용 결합   ← 나쁨                  논리적 응집
                                    우연적 응집   ← 나쁨
```

## Ⅳ. 등급의 의미

| 결합도 | 의미 |
|---|---|
| 자료 결합 | 필요한 데이터만 매개변수로 전달 |
| 스탬프 결합 | 자료 구조 전체를 전달 |
| 제어 결합 | 제어 신호로 상대의 동작을 지시 |
| 공통 결합 | 전역 데이터를 공유 |
| 내용 결합 | 다른 모듈의 내부를 직접 참조 |

| 응집도 | 의미 |
|---|---|
| 기능적 | 하나의 기능을 위한 요소로 구성 |
| 시간적 | 같은 시점에 실행되는 요소의 묶음 |
| 우연적 | 관련 없는 요소의 묶음 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 전역 데이터 공유로 높은 결합도 | 필요한 데이터만 매개변수로 전달 |
| 여러 기능이 섞인 모듈의 낮은 응집도 | 기능 단위로 분리 |
| 설계 시 등급 점검 누락 | 설계 검토에서 등급표 기준 점검 |

## Ⅵ. 제언

설계 검토에서 모듈 간 결합 방식과 모듈 내부 응집 유형을 등급표로 점검하고, 나쁜 등급을 개선 대상으로 선정

```text
모듈별 결합·응집 등급 평가
    ↓
나쁜 등급(공통·내용 결합, 우연·논리 응집) 선별 → 분리·재설계
```

| 구분 | 감으로 판단 | 제언: 등급표 점검 |
|---|---|---|
| 기준 | 불명확 | 등급 |
| 개선 대상 | 누락 | 선별 |
