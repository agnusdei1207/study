## 연관 키워드

- 모듈성(Modularity), 응집도(Cohesion), 결합도(Coupling), 고응집도(High Cohesion)·저결합도(Low Coupling)
- 순환 의존성(Circular Dependency), 의존성 역전 원칙(DIP), 바운디드 컨텍스트(Bounded Context), 산탄총 수술(Shotgun Surgery), 전략 패턴(Strategy Pattern)

## Ⅰ. 모듈성의 개요

- 핵심 요약 : 시스템을 모듈로 나누고 응집도와 결합도로 구조 품질을 측정하는 설계 척도.
- 개념 : 대규모 소프트웨어를 독립적인 기능 단위인 모듈(Module)로 나누어 복잡성을 통제하고 유지보수성을 높이는 구조적 설계 원리이며, 모듈 내부 요소 간 연관 강도인 **응집도** (Cohesion)와 모듈 간 상호 의존 강도인 **결합도** (Coupling)로 그 품질을 측정함.
- 설계 대원칙 : **고응집도** (High Cohesion)와 **저결합도** (Low Coupling)를 지향.
- 배경 및 필요성 : 기능이 얽힌 시스템에서는 한 곳의 수정이 여러 곳의 장애로 번지므로, 변경의 영향 범위를 모듈 단위로 가두는 구조적 기준이 필요함.
- 핵심 목표 : 변경 영향도의 국소화, 재사용성 증대, 독립적 테스트 용이성 확보.

## Ⅱ. 모듈성의 특징 및 장점

- 핵심 요약 : 고응집·저결합 원칙과 단계별 척도를 통해 변경 영향을 최소화하는 설계 체계.

1. 응집도와 결합도의 이중 척도 : 모듈 내부의 연관 강도와 모듈 간 의존 강도를 함께 봄 → 분할 품질을 객관적으로 평가.
2. 고응집·저결합 원칙 : 관련 기능을 한 모듈에 모으고 모듈 간 연결을 줄임 → 한 모듈의 변경이 다른 모듈에 미치는 파급 축소.
3. 변경 영향도 국소화 : 수정 범위가 한 모듈로 제한됨 → 유지보수 비용과 장애 확산 위험 감소.
4. 재사용과 테스트 : 독립된 단위로 떼어 쓰고 검증할 수 있음 → 개발 효율과 품질 보증 수준 향상.
5. 등급 체계 : 결합도 6단계와 응집도 7단계의 정성 등급으로 설계 문서를 검토 → 나쁜 구조를 조기에 발견.

## Ⅲ. 모듈성의 구조 (흐름)

- 핵심 요약 : 결합도는 낮을수록, 응집도는 높을수록 바람직한 반대 방향의 두 등급 체계.

```text
[ 결합도 : 낮을수록 바람직 ]
 자료 결합도 (Data Coupling)
       ↓ 파라미터로 단순 값만 교환
 스탬프 결합도 (Stamp Coupling)
       ↓ 데이터 구조 전체 전달
 제어 결합도 (Control Coupling)
       ↓ 제어 플래그로 내부 흐름 지시
 외부 결합도 (External Coupling)
       ↓ 공통 프로토콜과 파일 형식 공유
 공통 결합도 (Common Coupling)
       ↓ 전역 변수 공유
 내용 결합도 (Content Coupling)
```

```text
[ 응집도 : 높을수록 바람직 ]
 기능적 응집도 (Functional)
       ↓ 하나의 명확한 기능만 수행
 순차적 응집도 (Sequential)
       ↓ 출력이 다음 요소의 입력으로 연결
 통신적 응집도 (Communicational)
       ↓ 같은 데이터를 대상으로 작업
 절차적 응집도 (Procedural)
       ↓ 실행 순서에 따라 묶임
 시간적 응집도 (Temporal)
       ↓ 같은 시점에 실행되는 작업의 모임
 논리적 응집도 (Logical)
       ↓ 성격만 비슷한 기능의 모임
 우연적 응집도 (Coincidental)
```

- 해석 : 결합도 가장 낮은 자료 결합도와 응집도 가장 높은 기능적 응집도가 이상이며, 내용 결합도와 우연적 응집도가 최악의 상태.

## Ⅳ. 결합도와 응집도의 비교

- 핵심 요약 : 측정 대상과 바람직한 방향이 반대인 두 척도를 함께 적용하여 모듈 분할의 품질을 판단.

| 비교 항목 | 결합도 (Coupling) | 응집도 (Cohesion) |
| --- | --- | --- |
| 측정 대상 | 모듈과 모듈 사이의 상호 의존 강도 | 모듈 내부 구성요소 사이의 연관 강도 |
| 바람직 방향 | 낮을수록 좋음 (자료 결합도 지향) | 높을수록 좋음 (기능적 응집도 지향) |
| 등급 구성 | 자료 → 스탬프 → 제어 → 외부 → 공통 → 내용 (6단계) | 기능적 → 순차적 → 통신적 → 절차적 → 시간적 → 논리적 → 우연적 (7단계) |
| 최악 상태 | 내용 결합도 (타 모듈 내부의 직접 참조와 수정) | 우연적 응집도 (무관한 코드의 무작위 결합) |

- 선택 기준 : 모듈 간 인터페이스를 설계할 때는 결합도를, 모듈 내부 구성을 정할 때는 응집도를 먼저 점검함.

## Ⅴ. 모듈성의 한계와 방안

- 핵심 요약 : 과도한 세분화, 순환 의존, 경계 침식이 주요 한계이며 적정 경계 설정, 의존성 역전, 자동 점검으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 과도한 세분화 (나노서비스 안티패턴) | 응집도를 지나치게 높이려 쪼갠 결과 원격 호출과 분산 트랜잭션 비용 증가 | 비즈니스 트랜잭션과 일관성 요구에 맞춘 적정 크기의 **바운디드 컨텍스트** (Bounded Context) 도출 | 모듈 간 호출 횟수, 분산 트랜잭션 비율 |
| **순환 의존성** (Circular Dependency) | 모듈 A와 B가 서로 참조하여 독립 빌드와 배포가 불가능 | **의존성 역전 원칙** (DIP, Dependency Inversion Principle)에 따른 인터페이스 계층 도입, 중재자 패턴 또는 이벤트 기반 비동기 구조 전환 | 순환 참조 수, 빌드 실패율 |
| 아키텍처 경계 침식 | 일정 압박 속에서 타 모듈 내부를 직접 참조하여 의존성이 누적 | ArchUnit 등 정적 분석 도구를 CI(Continuous Integration)에 연동하여 비인가 접근 차단, 결합도 임계치 설정 | 경계 위반 건수, 구간별 결합도 |

## Ⅵ. 고품질 아키텍처 설계를 위한 기술사적 제언

- 핵심 요약 : 제어 결합도를 **전략 패턴** (Strategy Pattern)으로 걷어내고, 서비스 경계를 도메인 기준의 고응집 단위로 설계하는 방향.
- 제어 결합도 해소 : 개발 조직은 호출자가 `boolean isVip` 같은 플래그로 분기를 지시하는 구조를 전략 객체 주입 방식으로 바꾸고, **개방-폐쇄 원칙** (OCP, Open-Closed Principle)을 지키도록 리팩토링하는 것이 바람직하다.
- 서비스 경계의 고응집 설계 : 아키텍처 조직은 MSA(Microservice Architecture) 서비스 경계를 **도메인 주도 설계** (DDD, Domain-Driven Design)의 바운디드 컨텍스트 기준으로 잡아, 여러 서비스를 동시에 고쳐야 하는 **산탄총 수술** (Shotgun Surgery) 같은 증상을 조기에 감지하도록 해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 고응집·저결합 원칙을 상시 점검하고 경계 침식을 자동으로 막는 체계가 구조 품질의 전제 조건.
- 시사점 : 모듈성은 적정 크기 분할, 순환 의존 제거, 정적 분석 기반 경계 보호를 함께 관리할 때 실효가 있음.
