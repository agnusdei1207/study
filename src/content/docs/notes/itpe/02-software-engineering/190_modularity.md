## Ⅰ. 모듈성과 결합도·응집도의 개요

- 개념 : **모듈성** 이란 대규모 소프트웨어 시스템을 독립적인 기능 단위인 '모듈(Module)'로 분할하여 복잡성을 통제하고 유지보수성을 극대화하기 위한 구조적 설계 척도로, 모듈 내부 구성요소 간의 연관된 강도를 나타내는 **응집도** (Cohesion)와 모듈과 모듈 간의 상호 의존 강도를 나타내는 **결합도** (Coupling).
- 소프트웨어 공학의 대원칙 : **고응집도** (High Cohesion)와 **저결합도** (Low Coupling)
- 핵심 목표 : 변경 영향도의 국소화(Localization of Changes), 재사용성 증대, 독립적 테스트 용이성 확보.

## Ⅱ. 결합도(Coupling) 6단계 계층 (낮음/좋음 -> 높음/나쁨)

```text
   [ 바람직함: 결합도 낮음 ]
   1. 자료 결합도 (Data)     : 파라미터로 단순 데이터 값만 교환 (가장 이상적)
   2. 스탬프 결합도 (Stamp)   : 배열이나 구조체(DTO) 등 데이터 구조 전체를 전달
   3. 제어 결합도 (Control)   : 제어 플래그를 넘겨 모듈 내부의 실행 흐름을 지시
   4. 외부 결합도 (External)  : 외부 프로토콜, 통신 인터페이스, 파일 형식을 공유
   5. 공통 결합도 (Common)    : 여러 모듈이 동일한 전역 변수나 글로벌 상태를 공유
   6. 내용 결합도 (Content)   : 한 모듈이 다른 모듈의 내부 코드나 데이터를 직접 참조/수정 (최악)
   [ 위험함: 결합도 높음 ]
```

## Ⅲ. 응집도(Cohesion) 7단계 계층 (높음/좋음 -> 낮음/나쁨)

```text
   [ 바람직함: 응집도 높음 ]
   1. 기능적 응집도 (Functional)    : 모듈 내 모든 요소가 '단 하나의 명확한 기능' 수행 (이상적)
   2. 순차적 응집도 (Sequential)    : 한 요소의 출력이 다음 요소의 입력으로 직접 연결
   3. 통신적 응집도 (Communicational): 동일한 입력 데이터나 출력 데이터를 공유하여 작업
   4. 절차적 응집도 (Procedural)    : 순차적인 실행 순서에 따라 작업들이 그룹화됨
   5. 시간적 응집도 (Temporal)      : 특정 시점(예: 시스템 초기화)에 실행되는 작업들이 모임
   6. 논리적 응집도 (Logical)       : 유사한 성격의 기능(예: 모든 출력 관련 함수)을 모아둠
   7. 우연적 응집도 (Coincidental)  : 아무런 연관 관계 없이 무작위로 코드가 묶임 (최악)
   [ 위험함: 응집도 낮음 ]
```

## Ⅳ. 모듈성(결합도·응집도)의 주요 한계점 및 해결 방안

- 과도한 모듈 세분화로 인한 **나노서비스** (Nano-Services) 안티패턴 :
  - 한계점 : 응집도를 극대화하려는 의도로 모듈을 지나치게 잘게 쪼개어 모듈 간 네트워크 RPC 호출 오버헤드, 분산 트랜잭션 관리 비용 급증.
  - 해결 방안 : 비즈니스 트랜잭션 경계와 일관성 요구수준을 고려하여 적정 크기의 바운디드 컨텍스트 도출, 고응집-적정결합의 거시 모듈(Macro-module) 설계.
- 모듈 간 **순환 의존성** (Circular Dependency)으로 인한 빌드·배포 마비 :
  - 한계점 : 모듈 A가 모듈 B를 참조하고, 모듈 B가 다시 모듈 A를 참조하는 상호 의존 발생 시 독립적 테스트, 빌드 및 배포 불가.
  - 해결 방안 : **의존성 역전 원칙** (DIP)을 적용하여 인터페이스 계층 신설, 중간 **중재자** (Mediator) 패턴 도입 또는 이벤트 기반 비동기 발행/구독 모델 전환.
- 아키텍처 모듈 경계의 지속적 침식(Architectural Erosion) :
  - 한계점 : 초기에는 명확했던 모듈 경계가 긴급 패치와 일정 압박으로 인해 타 모듈의 내부 구현을 직접 참조하는 스파게티 의존성 누적.
  - 해결 방안 : Java 9+ JPMS(모듈 시스템), ArchUnit 등의 정적 분석 도구를 CI에 연동하여 모듈 간 비인가 접근 및 결합도(Afferent/Efferent Coupling) 임계치 초과 차단.

## Ⅴ. 고품질 아키텍처 설계를 위한 기술사적 제언

- 제어 결합도(Control Coupling) 제거를 위한 **전략 패턴** (Strategy Pattern) 도입 : 호출자가 메서드에 `boolean isVip` 같은 제어 플래그를 넘겨 내부 if-else를 분기시키면 두 모듈이 강하게 결합되므로, 다형성을 활용하여 VIPDiscountStrategy 객체를 주입받는 전략 패턴으로 리팩토링하여 **개방-폐쇄 원칙** (OCP) 준수.
- **마이크로서비스 도메인 경계** (Bounded Context)의 고응집 설계 : 클래스 수준의 결합도/응집도 개념을 MSA 서비스 경계 설계에 확장하여, 하나의 비즈니스 변경 요구가 여러 마이크로서비스에 걸쳐 동시 수정을 유발하는 산탄총 수술(Shotgun Surgery) 안티패턴을 감시하고, 도메인 주도 설계(DDD)를 통해 단일 서비스 내부로 응집도를 극대화해야 함.
