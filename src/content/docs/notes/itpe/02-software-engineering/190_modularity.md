## 연관 키워드

- 모듈성(Modularity), 응집도(Cohesion), 결합도(Coupling), 고응집도(High Cohesion)·저결합도(Low Coupling)
- 순환 의존성(Circular Dependency), 의존성 역전 원칙(DIP), 바운디드 컨텍스트(Bounded Context), 산탄총 수술(Shotgun Surgery), 전략 패턴(Strategy Pattern)

## Ⅰ. 모듈성(결합도·응집도)의 개요

- 핵심 요약 : 모듈 분할 체계에서 응집도·결합도로 구조 품질을 측정하는 설계 척도.
- 개념 : 대규모 소프트웨어 시스템을 독립적인 기능 단위인 모듈(Module)로 분할하여 복잡성을 통제하고 유지보수성을 극대화하기 위한 구조적 설계 척도로, 모듈 내부 구성요소 간 연관 강도를 나타내는 응집도(Cohesion)와 모듈과 모듈 간 상호 의존 강도를 나타내는 결합도(Coupling).
- 소프트웨어 공학의 대원칙 : 고응집도(High Cohesion)와 저결합도(Low Coupling).
- 핵심 목표 : 변경 영향도의 국소화(Localization of Changes), 재사용성 증대, 독립적 테스트 용이성 확보.

## Ⅱ. 모듈성의 특징

- 핵심 요약 : 고응집·저결합 대원칙과 단계별 척도를 통한 변경 영향 최소화 설계.

1. 모듈 내부 연관 강도인 응집도(Cohesion)와 모듈 간 의존 강도인 결합도(Coupling)의 구조적 척도.
2. 고응집도(High Cohesion)·저결합도(Low Coupling)의 소프트웨어 공학 대원칙.
3. 변경 영향도의 국소화(Localization of Changes).
4. 모듈 단위 재사용성 증대와 독립적 테스트 용이성 확보.
5. 결합도 6단계와 응집도 7단계의 정성 등급 체계.

## Ⅲ. 모듈성의 구조 (흐름)

- 핵심 요약 : 결합도는 낮을수록, 응집도는 높을수록 바람직한 반대 방향의 등급 체계.
- 결합도(Coupling) 6단계 계층 (낮음/좋음 → 높음/나쁨).

```text
[ 바람직함: 결합도 낮음 ]
 1. 자료 결합도 (Data)
    - 파라미터로 단순 데이터 값만
      교환 (가장 이상적)
 2. 스탬프 결합도 (Stamp)
    - 배열이나 구조체(DTO, Data
      Transfer Object) 등 데이터
      구조 전체 전달
 3. 제어 결합도 (Control)
    - 제어 플래그 전달을 통한 모듈
      내부 실행 흐름 지시
 4. 외부 결합도 (External)
    - 외부 프로토콜, 통신
      인터페이스, 파일 형식 공유
 5. 공통 결합도 (Common)
    - 여러 모듈의 동일한 전역
      변수나 글로벌 상태 공유
 6. 내용 결합도 (Content)
    - 한 모듈의 타 모듈 내부
      코드·데이터 직접
      참조/수정 (최악)
[ 위험함: 결합도 높음 ]
```

- 응집도(Cohesion) 7단계 계층 (높음/좋음 → 낮음/나쁨).

```text
[ 바람직함: 응집도 높음 ]
 1. 기능적 응집도 (Functional)
    - 모든 요소가 '단 하나의
      명확한 기능' 수행 (이상적)
 2. 순차적 응집도 (Sequential)
    - 한 요소의 출력이 다음
      요소의 입력으로 직접 연결
 3. 통신적 응집도 (Communicational)
    - 동일한 입력/출력 데이터
      공유 기반 작업
 4. 절차적 응집도 (Procedural)
    - 순차적 실행 순서에 따른
      작업들의 그룹화
 5. 시간적 응집도 (Temporal)
    - 특정 시점(예: 시스템 초기화)
      실행 작업들의 모임
 6. 논리적 응집도 (Logical)
    - 유사한 성격 기능(예: 모든
      출력 관련 함수)의 집합
 7. 우연적 응집도 (Coincidental)
    - 아무런 연관 관계 없는
      무작위 코드 결합 (최악)
[ 위험함: 응집도 낮음 ]
```

## Ⅳ. 결합도와 응집도의 비교

- 핵심 요약 : 측정 대상과 바람직 방향이 반대인 두 척도의 상호 보완적 적용.

| 비교 항목 | 결합도(Coupling) | 응집도(Cohesion) |
|---|---|---|
| 측정 대상 | 모듈과 모듈 간 상호 의존 강도 | 모듈 내부 구성요소 간 연관 강도 |
| 바람직 방향 | 낮을수록 좋음 (자료 결합도 지향) | 높을수록 좋음 (기능적 응집도 지향) |
| 등급 구성 | 자료 → 스탬프 → 제어 → 외부 → 공통 → 내용 (6단계) | 기능적 → 순차적 → 통신적 → 절차적 → 시간적 → 논리적 → 우연적 (7단계) |
| 최악 상태 | 내용 결합도 (내부 코드·데이터의 직접 참조/수정) | 우연적 응집도 (무관련 코드의 무작위 결합) |

## Ⅴ. 모듈성의 장점과 한계

- 핵심 요약 : 복잡성 통제·재사용·독립 테스트의 장점, 과잉 세분화·순환 의존·경계 침식의 한계.
- 장점
  1. 모듈 분할을 통한 대규모 시스템 복잡성 통제.
  2. 변경 영향도 국소화를 통한 유지보수성 극대화.
  3. 모듈 재사용을 통한 개발 효율 향상.
  4. 모듈 단위 독립적 테스트 용이성 확보.
- 한계점 1 : 과도한 모듈 세분화로 인한 나노서비스(Nano-Services) 안티패턴
  - 한계점 : 응집도 극대화 의도의 지나친 모듈 분할로 인한 모듈 간 네트워크 RPC(Remote Procedure Call) 호출 오버헤드 및 분산 트랜잭션 관리 비용 급증.
  - 해결 방안 : 비즈니스 트랜잭션 경계와 일관성 요구 수준을 고려한 적정 크기 바운디드 컨텍스트 도출, 고응집-적정결합의 거시 모듈(Macro-module) 설계.
- 한계점 2 : 모듈 간 순환 의존성(Circular Dependency)으로 인한 빌드·배포 마비
  - 한계점 : 모듈 A·B 간 상호 참조 발생 시 독립적 테스트, 빌드 및 배포 불가.
  - 해결 방안 : 의존성 역전 원칙 DIP(Dependency Inversion Principle) 적용 인터페이스 계층 신설, 중재자(Mediator) 패턴 도입 또는 이벤트 기반 비동기 발행/구독 모델 전환.
- 한계점 3 : 아키텍처 모듈 경계의 지속적 침식(Architectural Erosion)
  - 한계점 : 초기 명확한 모듈 경계의 긴급 패치·일정 압박 과정에서 타 모듈 내부 구현 직접 참조 스파게티 의존성 누적.
  - 해결 방안 : Java 9+ JPMS(Java Platform Module System), ArchUnit 등 정적 분석 도구의 CI(Continuous Integration) 연동, 모듈 간 비인가 접근 및 결합도(Afferent/Efferent Coupling) 임계치 초과 차단.

## Ⅵ. 고품질 아키텍처 설계를 위한 기술사적 제언

- 핵심 요약 : 전략 패턴 기반 제어 결합도 제거와 MSA 도메인 경계의 고응집 설계.
- 제어 결합도(Control Coupling) 제거를 위한 전략 패턴(Strategy Pattern) 도입 : 호출자의 `boolean isVip` 제어 플래그 기반 if-else 분기의 강한 결합 해소, 다형성 기반 VIPDiscountStrategy 객체 주입 리팩토링과 개방-폐쇄 원칙 OCP(Open-Closed Principle) 준수.
- 마이크로서비스 도메인 경계(Bounded Context)의 고응집 설계 : 클래스 수준 결합도·응집도 개념의 MSA(Microservice Architecture) 서비스 경계 확장, 여러 마이크로서비스 동시 수정을 유발하는 산탄총 수술(Shotgun Surgery) 안티패턴 감시, 도메인 주도 설계(DDD, Domain-Driven Design) 기반 단일 서비스 내부 응집도 극대화 필요.

## Ⅶ. 결론

- 핵심 요약 : 고응집·저결합 원칙의 상시 감시와 경계 침식 방지 도구화가 품질의 전제 조건.
- 요약 : 응집도·결합도 등급 체계 기반의 구조 품질 측정 및 모듈 분할 설계 원칙.
- 시사점 : 적정 모듈 크기, 순환 의존 제거, 정적 분석 기반 경계 보호의 지속적 관리 필요.
