## 30초 인출

- 본질: BST(Binary Search Tree)는 왼쪽 서브트리 키가 작고 오른쪽 서브트리 키가 큰 정렬 관계를 유지하는 이진 트리
- 메커니즘: 키 비교로 좌우 중 한쪽만 내려가며 탐색·삽입·삭제하고, 중위 순회로 키를 오름차순 출력
- 통찰: 정렬된 키가 연속 입력되면 한쪽으로 늘어진 편향 트리가 되어 탐색이 O(N)이므로 AVL·Red-Black 같은 자가 균형 트리로 높이를 O(log N)으로 제한

<details>
<summary>핵심 용어</summary>

- **BST(Binary Search Tree)** : 모든 노드에서 왼쪽 서브트리 키 < 노드 키 < 오른쪽 서브트리 키를 유지하는 이진 트리
- **중위 순회(In-order Traversal)** : 왼쪽 서브트리, 노드, 오른쪽 서브트리 순으로 방문해 키를 오름차순으로 얻는 순회
- **편향 트리(Skewed Tree)** : 키가 정렬된 순서로 삽입되어 한쪽 방향으로만 이어진 트리. 높이가 N
- **AVL Tree** : 모든 노드에서 좌우 서브트리 높이 차를 1 이하로 유지하는 자가 균형 트리
- **Red-Black Tree** : 노드 색상 규칙으로 루트에서 리프까지 가장 긴 경로를 가장 짧은 경로의 2배 이내로 제한하는 자가 균형 트리
- **최장 프리픽스 일치(Longest Prefix Match)** : 라우팅 테이블에서 목적지 주소와 가장 길게 일치하는 접두사 항목을 고르는 탐색

## 2~4교시 25점 답안

## Ⅰ. BST의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **BST(Binary Search Tree)** 는 왼쪽 서브트리 키가 작고 오른쪽 서브트리 키가 큰 정렬 관계를 유지하는 이진 트리 |
| 목적 | 키 비교에 따른 탐색·삽입·삭제 범위의 절반 축소 |

## Ⅱ. 배열·연결 리스트와 구별되는 BST의 특징

| 특징 | 의미 |
|---|---|
| 정렬 관계 유지 | 모든 노드에서 왼쪽 < 노드 < 오른쪽 |
| 높이 의존 성능 | 탐색·삽입·삭제가 루트에서 리프까지의 높이 h에 비례 |
| 정렬 출력 | **중위 순회** 결과가 오름차순 |

## Ⅲ. BST 구조와 연산 메커니즘

### BST 구조

```text
        [ 50 ]
       /      \
    [ 30 ]   [ 70 ]
    /    \       \
 [ 20 ] [ 40 ]  [ 80 ]
```

### 연산 확대: 삽입과 두 자식 노드 삭제

```text
삽입: 루트에서 시작
    ├─ 새 키 < 노드 키 → 왼쪽으로 이동
    └─ 새 키 > 노드 키 → 오른쪽으로 이동
    ↓
빈 자리에 새 노드 연결

삭제: 자식이 둘인 노드
    ↓
오른쪽 서브트리의 최소 노드(중위 후계자) 탐색
    ↓
삭제 노드에 후계자 키를 복사하고 후계자 삭제
```

| 연산 | 평균 | 최악(편향) |
|---|---|---|
| 탐색·삽입·삭제 | O(log N) | O(N) |

## Ⅳ. 자가 균형 트리와의 비교, 라우팅 테이블 탐색과의 관계

### 기본 BST와 자가 균형 트리

| 구분 | 기본 BST | AVL Tree | Red-Black Tree |
|---|---|---|---|
| 균형 조건 | 없음 | 높이 차 1 이하 | 색상 규칙으로 최장 경로 2배 이내 |
| 최악 탐색 | O(N) | O(log N) | O(log N) |
| 삽입·삭제 재균형 | 없음 | 회전이 잦음 | 회전 횟수가 적음 |
| 적합 환경 | 소규모·무작위 입력 | 조회 중심 | 삽입·삭제가 잦은 환경 |

### BST와 라우팅 테이블 탐색의 관계

| 구분 | BST | 라우팅 테이블 탐색 |
|---|---|---|
| 탐색 목표 | 키와 일치하는 노드 | 목적지 주소와 가장 길게 일치하는 접두사(Longest Prefix Match) |
| 분기 기준 | 키 전체의 크기 비교 | 주소 비트(Binary Trie) 또는 접두사 길이 |
| 공통점 | 비교 결과로 탐색 범위를 줄이는 트리 탐색 | 트리 높이가 탐색 시간을 좌우 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 정렬 키 연속 입력으로 편향 트리가 되어 탐색이 O(N)으로 저하 | AVL 또는 Red-Black Tree로 높이 균형 유지 |
| 디스크 등 대량 데이터에서 노드마다 접근이 발생해 높이 증가 | 노드당 키를 여러 개 두는 B-Tree 계열 적용 |
| 접두사 일치 탐색에 키 전체 비교 방식의 부적합 | 비트 단위로 분기하는 Trie 계열 적용 |

## Ⅵ. 제언

최악 탐색 시간 상한이 필요한 시스템은 조회 중심이면 AVL, 삽입·삭제가 잦으면 Red-Black Tree 선택

### 트리 선택 판단

```text
입력 순서 무작위·소규모?
    ├─ 예 → 기본 BST
    └─ 아니오 → 최악 탐색 시간 상한 필요
                    ├─ 조회 중심 → AVL Tree
                    └─ 삽입·삭제 빈번 → Red-Black Tree
```

### 선택 근거: 기본 BST와의 비교

| 구분 | 기본 BST | 제언: 자가 균형 트리 |
|---|---|---|
| 최악 탐색 | O(N) | O(log N) |
| 삽입·삭제 비용 | 재균형 없음 | 회전으로 균형 유지 |
| 입력 순서 영향 | 큼 | 없음 |
