## 지식 로드맵 내 현재 위치

<div class="itpe-topic-path" aria-label="자료구조에서 이진 탐색 트리까지의 지식 경로"><span>SW 공학·자료구조</span><span>트리 구조</span><strong>이진 탐색 트리(BST)</strong></div>

## 큰 그림과 30초 인출

```text
탐색키 < 노드키 → Left
탐색키 > 노드키 → Right
탐색키 = 노드키 → Found

평균: 높이 h에 비례 / 균형 시 O(log n)
최악: 정렬 입력으로 편향 → 높이 n, O(n)
대책: AVL·Red-Black 등 자가균형 트리
```

## 예상문제

> 이진 탐색 트리의 구조와 탐색·삽입·삭제 원리를 설명하고, AVL·Red-Black Tree와 비교한 후 편향 문제의 대응방안을 제시하시오. (25점)

## 답안 골격
```text
[BST] ◀━━ 머리: Ⅶ 내 의견 (정렬 입력 편향 방지를 위한 자가 균형 트리 전환 필수)
 ┃
 ┣━ Ⅰ 개요 ───── 순차 탐색 O(N) 비용 한계 → 좌소우대 정렬 분기로 평균 O(log N) 탐색 달성
 ┣━ Ⅱ 특징 ───── 중복 불허 · 중위 순회 시 오름차순 정렬 · 편향 트리 시 O(N) 퇴보
 ┣━ Ⅲ 구조 ───── Root 노드 · Left Subtree · Right Subtree · Key-Value 쌍
 ┣━ Ⅳ 흐름 ───── ① 탐색키와 노드 비교 → ② 작으면 좌측 이동 → ③ 크면 우측 이동 → ④ 일치 시 반환
 ┣━ Ⅴ 비교 ───── BST vs AVL 트리 vs Red-Black 트리
 ┗━ Ⅵ 실무 ───── 정렬 데이터 대량 삽입 시 편향 트리 형성 / 트리 재구성 및 자가 균형 전환
```
- 필수 키워드: 좌소우대 · O(log N) · 중위 순회 · 편향 트리 · AVL · Red-Black Tree
- 기출: 137회 1교시 `이진 탐색 트리` → Ⅰ·Ⅲ·Ⅳ / 139회 3교시 `BST와 라우팅 테이블 상관관계` → Ⅵ 실무 사례

## 한 줄 본질
- 선형 연결리스트의 느린 탐색 속도(O(N)) 한계 → 부모 기준으로 작은 값은 좌측, 큰 값은 우측에 배치해 탐색 범위를 매 단계 절반으로 축소 → 평균 O(log N) 고속 탐색 달성 / 정렬된 데이터 입력 시 한쪽으로 치우쳐 선형 리스트로 퇴보 위험

## 핵심 그림
```text
        [ 50 ]            * 탐색 규칙: Key < Node -> Left
       /      \                        Key > Node -> Right
    [ 30 ]    [ 70 ]      * 중위 순회(In-order):
    /    \    /    \        20 -> 30 -> 40 -> 50 -> 60 -> 70 -> 80
 [ 20 ] [ 40 ][ 60 ] [ 80 ] (항상 오름차순 정렬 결과 반환)
```

## 핵심 용어
- 편향 트리(Skewed Tree): 오름차순 또는 내림차순 데이터가 연속 삽입되어 높이가 N이 되고 탐색 시간이 O(N)으로 퇴보한 트리
- 자가 균형(Self-Balancing): 삽입·삭제 시 회전(Rotation) 연산으로 좌우 서브트리의 높이 균형을 유지해 O(log N) 성능을 보장하는 기제

## 핵심 통찰
- BST의 고속 탐색은 좌우 높이 균형이 유지될 때만 유효함 → 이미 정렬된 시계열 로그나 식별자가 들어오면 선형 탐색과 동일한 비용 발생
- 중위 순회(In-order Traversal)만으로 정렬 리스트를 얻을 수 있어 인덱스 순차 스캔에 구조적으로 적합함
- 라우팅 테이블의 최장 접두사 일치(LPM) 알고리즘도 BST 변형인 Radix Tree(Trie) 원리를 바탕으로 IP 검색 시간을 단축함

## 이웃 토픽과 구분
- BST vs Red-Black Tree: BST = 기본 분기 구조만 제공해 편향에 취약 / Red-Black Tree = 노드 색상과 회전으로 높이를 log N 이하로 강제 통제

## 문제·원인·대책
- 사례: 139회 기출 라우팅 테이블 IP 경로 검색 및 정렬 식별자 인메모리 색인
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 순차 증가 ID 입력 시 탐색 속도 급격 저하 | 오름차순 삽입으로 우측 서브트리 편향 형성 | AVL 또는 Red-Black Tree 같은 자가 균형 트리 도입 | 최악의 경우에도 높이를 O(log N)으로 유지해 탐색 지연 통제 |
| 노드 삭제 후 트리 분리 및 불균형 발생 | 차수가 2인 노드 삭제 시 후속자 대체 기준 부재 | 좌측 서브트리 최대값 또는 우측 서브트리 최소값 승계 규칙 적용 | 트리 정렬 속성 무결성 유지 |

- 제139회 3교시 5번: "이진 탐색 트리와 라우팅 테이블 탐색 알고리즘의 상관관계에 대하여 설명하시오." → 요구 포인트: Ⅲ 비트 분기 구조 + Ⅳ 프리픽스 트리(Trie) 탐색 흐름 + Ⅵ 고속 포워딩 최적화

## 내 의견
- [자가 균형 없는 기본 BST의 프로덕션 배포 위험] 자동 정렬 편의성만 보고 기본 BST를 사용하면 시계열·순차 키 누적으로 탐색 지연이 선형 수준으로 퇴보 가능 → 나라면: 표준 라이브러리의 자가 균형 트리 기반 컨테이너를 우선 적용하고, 정렬 배열로부터 구성할 때는 중간값 분할로 균형 높이를 확보

## Ⅰ. 정렬 규칙으로 탐색 범위를 줄이는 BST 개요

- 정의: **BST**는 각 노드의 왼쪽 서브트리에 더 작은 키, 오른쪽 서브트리에 더 큰 키를 배치하는 순서 규칙을 가진 이진트리
- 목적: 비교 결과에 따라 한쪽 서브트리를 제외해 탐색·삽입·삭제를 트리 높이에 비례하는 비용으로 수행
- 전제: 키 비교 순서가 일관되고, 중복 키 처리 정책과 트리 균형 전략이 명확해야 함

## Ⅱ. 순서성·동적 갱신·높이 의존성의 특징

| 특징 | 메커니즘 | 효과·제약 |
|---|---|---|
| **순서 불변식** | `Left < Node < Right` 유지 | 비교 기반 탐색 가능 |
| **중위순회 정렬** | Left-Node-Right 순회 | 오름차순 키 획득 |
| **동적 삽입·삭제** | 재배열 없이 포인터 변경 | 갱신 용이, 균형 깨질 수 있음 |
| **높이 의존 성능** | 연산비용 `O(h)` | 균형 시 `O(log n)`, 편향 시 `O(n)` |

## Ⅲ. 루트와 좌·우 서브트리의 구조

```text
          [50]
         /    \
      [30]    [70]
      /  \    /  \
   [20] [40][60] [80]

모든 서브트리에서도 Left < Root < Right 규칙 반복
```

| 구성 | 책임 |
|---|---|
| **Node** | 키·값과 좌우 자식 참조 보유 |
| **Root** | 전체 탐색 시작점 |
| **Left Subtree** | 현재 노드보다 작은 키 집합 |
| **Right Subtree** | 현재 노드보다 큰 키 집합 |

## Ⅳ. 탐색·삽입·삭제 동작

```text
탐색·삽입: Root부터 비교 → 작으면 Left / 크면 Right → 일치·NULL까지 반복

삭제:
자식 0개 → 노드 제거
자식 1개 → 자식을 부모에 직접 연결
자식 2개 → 중위 후속자 또는 선행자 키 승계 → 승계 노드 삭제
```

- 모든 연산은 순서 불변식을 보존해야 하며, 자가 균형 트리는 삽입·삭제 뒤 회전·색상 조정 등을 추가 수행

## Ⅴ. BST·AVL·Red-Black Tree 비교

| 기준 | 기본 BST | AVL | Red-Black Tree |
|---|---|---|---|
| 균형 보장 | 없음 | 높이 차 엄격 관리 | 색상 규칙으로 완화된 균형 |
| 최악 탐색 | `O(n)` | `O(log n)` | `O(log n)` |
| 갱신 비용 | 균형 작업 없음 | 회전 빈도 상대적 증가 | 탐색·갱신 균형 |
| 적합 | 입력 분포가 통제된 단순 구조 | 탐색 비중이 높은 환경 | 삽입·삭제가 빈번한 범용 맵·셋 |

## Ⅵ. 편향과 구현 오류의 대응

| 문제 | 원인 | 대책 | 검증 |
|---|---|---|---|
| **편향 트리** | 정렬·유사정렬 키 연속 삽입 | 자가 균형 트리 또는 균형 일괄구성 | 높이·평균 비교 횟수 |
| **삭제 후 불변식 훼손** | 두 자식 노드 승계 처리 오류 | 선행자·후속자 규칙과 단위테스트 | 중위순회 정렬성 |
| **중복 키 모호성** | 중복 저장 정책 부재 | 덮어쓰기·빈도·다중값 정책 명시 | 중복 입력 테스트 |
| **구조 선택 오류** | 접두사·범위 등 질의 특성 무시 | Trie·B-Tree·Hash와 질의별 비교 | 메모리·지연·범위질의 비용 |

## Ⅶ. 입력분포와 질의 특성으로 구조를 선택하는 결론

- BST의 성능은 노드 수보다 **트리 높이와 입력 순서**에 의해 결정되므로 최악복잡도 요구가 있으면 자가 균형 구조를 선택해야 함
- 정확성은 중위순회의 정렬성과 순서 불변식으로, 성능은 높이·비교 횟수·갱신비용으로 검증해야 함

## 1교시 10점 답안 발췌

```text
정의: Left < Node < Right 순서 규칙을 가진 이진트리
탐색: 비교 → Left/Right 분기 → 일치 또는 NULL
성능: O(h), 균형 O(log n), 편향 O(n)
대책: AVL·Red-Black Tree 등 자가 균형
```
