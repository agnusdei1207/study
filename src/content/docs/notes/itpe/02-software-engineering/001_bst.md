## 30초 인출

- 본질: BST(Binary Search Tree)는 왼쪽 서브트리 키는 작고 오른쪽 서브트리 키는 큰 정렬 불변식을 유지하는 이진 트리
- 메커니즘: 키 비교 기반 좌우 분기 탐색, In-order Traversal(중위 순회)을 통한 오름차순 키 추출
- 통찰: 정렬 데이터의 연속 입력 시 편향 트리로 퇴보하여 탐색 성능이 저하되므로 높이를 O(log N)으로 제한하는 자가 균형 트리 적용

<details>
<summary>핵심 용어</summary>

- **BST(Binary Search Tree)** : 부모 노드 키를 기준으로 왼쪽 서브트리의 모든 키 < 부모 키 < 오른쪽 서브트리의 모든 키를 유지하는 이진 트리
- **In-order Traversal(중위 순회)** : 왼쪽 서브트리, 루트, 오른쪽 서브트리 순으로 노드를 방문하여 정렬된 키 순서를 추출하는 순회 기법
- **Skewed Tree(편향 트리)** : 정렬된 키의 연속 삽입으로 한쪽 방향으로만 노드가 이어져 높이가 N으로 증가한 트리
- **In-order Successor** : 삭제 대상 노드의 오른쪽 서브트리에서 가장 작은 키를 가진 후계자 노드
- **AVL Tree** : 좌우 서브트리의 높이 차(Balance Factor)를 1 이하로 엄격히 제한하는 자가 균형 트리
- **Red-Black Tree** : 노드 색상과 5가지 규칙을 통해 루트-리프 간 최장 경로가 최단 경로의 2배를 넘지 않도록 제어하는 완화된 균형 트리

## 2~4교시 25점 답안

## Ⅰ. BST의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **BST(Binary Search Tree)** 는 부모 키를 기준으로 왼쪽 서브트리는 작은 키, 오른쪽 서브트리는 큰 키를 갖는 이진 트리 |
| 목적 | 순서 관계를 활용한 O(log N) 수준의 빠른 탐색·삽입·삭제 연산 지원 |

## Ⅱ. BST의 핵심 특징

| 특징 | 의미 |
|---|---|
| 순서 불변식 | 모든 노드에서 왼쪽 서브트리 키 < 부모 키 < 오른쪽 서브트리 키의 일관된 성립 |
| 높이 의존 성능 | 탐색·삽입·삭제 연산 복잡도가 루트에서 리프까지의 트리 높이(h)에 비례 |
| 정렬 데이터 인출 | **In-order Traversal(중위 순회)** 시 오름차순 데이터 정렬 출력 보장 |

## Ⅲ. BST 구조 및 주요 연산 메커니즘

### BST 전체 노드 배치 구조

```text
50
├─ 30
│  ├─ 20
│  └─ 40
└─ 70
   └─ 80
```

### 키 비교 기반 삽입 및 2자식 노드 삭제 메커니즘

```text
삽입: 루트 비교
    ├─ 새 키 < 부모 키 → 좌측 서브트리 이동
    └─ 새 키 > 부모 키 → 우측 서브트리 이동
    └─ 빈 리프 위치 확인 시 신규 노드 연결

삭제: 2자식 노드 대상
    ↓
우측 서브트리 최소 노드(In-order Successor) 탐색
    ↓
삭제 대상 위치로 키 복사
    ↓
원래 Successor 노드의 링크 해제
```

| 연산 | 평균 복잡도 | 최악 복잡도 | 핵심 통제 요소 |
|---|---|---|---|
| Search | O(log N) | O(N) | 키 비교 연산 일관성 유지 |
| Insert | O(log N) | O(N) | 중복 키 처리 정책 결정 |
| Delete | O(log N) | O(N) | **In-order Successor** 대체 후 서브트리 무결성 검증 |

## Ⅳ. 기본 BST와 자가 균형 트리 비교

| 비교 항목 | 기본 BST | AVL Tree | Red-Black Tree |
|---|---|---|---|
| 균형 조건 | 별도 균형 보장 기법 부재 | 좌우 서브트리 높이 차 1 이하 | 노드 색상과 5가지 규칙 유지 |
| 최악 탐색 복잡도 | O(N) | O(log N) | O(log N) |
| 회전 빈도 | 회전 없음 | 삽입·삭제 시 빈번한 회전 | 최대 2회(삽입), 최대 3회(삭제) 회전 |
| 적합 영역 | 데이터 입력 순서가 무작위인 기초 연산 | 읽기 연산 비중이 높은 탐색 집중 환경 | 삽입·삭제·탐색이 빈번한 표준 컨테이너 라이브러리 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 정렬 키 연속 입력 시 편향 트리(Skewed Tree) 발생으로 탐색 복잡도가 O(N)으로 퇴보 | **AVL Tree** 또는 **Red-Black Tree** 도입을 통한 높이 균형 유지 |
| 노드 포인터 오버헤드와 잦은 동적 메모리 할당으로 캐시 지역성 저하 | 노드 메모리 풀링 적용 및 대량 디스크 블록 접근 시 B-Tree 계열 전환 |
| 동시성 환경에서 다중 스레드 수정 시 트리 불변식 파괴 | 노드 단위 세분화 잠금(Fine-grained Locking) 또는 락프리 동시성 트리 적용 |

## Ⅵ. 제언

입력 데이터 특성과 최악 탐색시간 요구조건에 따른 자가 균형 트리 도입과 메모리 풀링 적용

### 트리 구조 선정 및 적용 절차

```text
데이터 특성 및 성능 요구 분석
    ↓
선정 판정
    ├─ 정적 대량 데이터 → 중간값 기준 정렬 후 기본 BST 일괄 빌드
    ├─ 읽기 중심 고속 탐색 → AVL Tree 선정
    └─ 삽입·삭제 빈번한 동적 환경 → Red-Black Tree 선정
    ↓
노드 메모리 풀링 및 동시성 제어 적용
```

### Red-Black Tree 균형 복원 메커니즘

```text
새 노드 Red 삽입
    ↓
연속 Red 위반 발생
    ├─ 삼촌 노드 Red → 부모·삼촌 Black 변경, 조부 Red 변경(Recoloring)
    └─ 삼촌 노드 Black → 단일/이중 회전(Rotation) 후 색상 재배치
```

### 선택 근거: 기본 BST와 Red-Black Tree 비교

| 구분 | 기본 BST | 제언: Red-Black Tree |
|---|---|---|
| 최악 탐색 보장 | 불가 (O(N) 편향 위험) | 보장 (O(log N) 상한 유지) |
| 쓰기 오버헤드 | 추가 회전 비용 없음 | 최대 2~3회 회전으로 비용 제한 |
| 적용 권장 환경 | 소규모 정적 데이터 | 대규모 동적 시스템 인덱스 |
