## 답안 골격
```text
[BST] ◀━━ 머리: Ⅶ 내 의견 (정렬 입력 편향 방지를 위한 자가 균형 트리 전환 필수)
 ┃
 ┣━ Ⅰ 개요 ───── 순차 탐색 O(N) 비용 한계 → 좌소우대 정렬 분기로 평균 O(log N) 탐색 달성
 ┣━ Ⅱ 특징 ───── 중복 불허 · 중위 순회 시 오름차순 정렬 · 편향 트리 시 O(N) 퇴보
 ┣━ Ⅲ 구조 ───── Root 노드 · Left Subtree · Right Subtree · Key-Value 쌍
 ┣━ Ⅳ 흐름 ───── ① 탐색키와 노드 비교 → ② 작으면 좌측 이동 → ③ 크면 우측 이동 → ④ 일치 시 반환
 ┣━ Ⅴ 비교 ───── BST vs AVL 트리 vs Red-Black 트리
 ┗━ Ⅵ 실무 ───── 정렬 데이터 대량 삽입 시 편향 트리 형성 / 트리 재구성 및 자가 균형 전환
```
- 필수 키워드: 좌소우대 · O(log N) · 중위 순회 · 편향 트리 · AVL · Red-Black Tree
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 구조 도식 → Ⅴ 균형 트리 비교 / 25점 = Ⅰ~Ⅶ 전개, Ⅳ 흐름과 Ⅵ 편향 해소 집중
- 기출: 137회 1교시 `이진 탐색 트리` → Ⅰ·Ⅲ·Ⅳ / 139회 3교시 `BST와 라우팅 테이블 상관관계` → Ⅵ 실무 사례

## 한 줄 본질
- 선형 연결리스트의 느린 탐색 속도(O(N)) 한계 → 부모 기준으로 작은 값은 좌측, 큰 값은 우측에 배치해 탐색 범위를 매 단계 절반으로 축소 → 평균 O(log N) 고속 탐색 달성 / 정렬된 데이터 입력 시 한쪽으로 치우쳐 선형 리스트로 퇴보 위험

## 핵심 그림
```text
        [ 50 ]            * 탐색 규칙: Key < Node -> Left
       /      \                        Key > Node -> Right
    [ 30 ]    [ 70 ]      * 중위 순회(In-order):
    /    \    /    \        20 -> 30 -> 40 -> 50 -> 60 -> 70 -> 80
 [ 20 ] [ 40 ][ 60 ] [ 80 ] (항상 오름차순 정렬 결과 반환)
```

## 핵심 용어
- 편향 트리(Skewed Tree): 오름차순 또는 내림차순 데이터가 연속 삽입되어 높이가 N이 되고 탐색 시간이 O(N)으로 퇴보한 트리
- 자가 균형(Self-Balancing): 삽입·삭제 시 회전(Rotation) 연산으로 좌우 서브트리의 높이 균형을 유지해 O(log N) 성능을 보장하는 기제

## 핵심 통찰
- BST의 고속 탐색은 좌우 높이 균형이 유지될 때만 유효함 → 이미 정렬된 시계열 로그나 식별자가 들어오면 선형 탐색과 동일한 비용 발생
- 중위 순회(In-order Traversal)만으로 정렬 리스트를 얻을 수 있어 인덱스 순차 스캔에 구조적으로 적합함
- 라우팅 테이블의 최장 접두사 일치(LPM) 알고리즘도 BST 변형인 Radix Tree(Trie) 원리를 바탕으로 IP 검색 시간을 단축함

## 이웃 토픽과 구분
- BST vs Red-Black Tree: BST = 기본 분기 구조만 제공해 편향에 취약 / Red-Black Tree = 노드 색상과 회전으로 높이를 log N 이하로 강제 통제

| 문제 | 원인 | 대책 | 효과 |
