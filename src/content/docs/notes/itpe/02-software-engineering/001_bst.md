## 연관 키워드

- BST(Binary Search Tree), 이진 탐색 트리, 탐색 트리 불변식, 중위 순회(In-order Traversal)
- 트리 높이, 편향 트리(Skewed Tree), AVL 트리, Red-Black 트리, 회전(Rotation)

## Ⅰ. BST의 개요

- 핵심 요약 : **BST**는 키의 대소 관계를 노드 배치에 반영하여 탐색·삽입·삭제를 트리 높이에 비례하는 시간에 수행하는 자료구조.
- 개념 : 각 노드의 왼쪽 서브트리에는 더 작은 키, 오른쪽 서브트리에는 더 큰 키를 두는 **탐색 트리 불변식**을 유지하는 이진 트리.
- 배경 및 필요성 : 정렬 배열의 빠른 탐색과 연결 리스트의 유연한 삽입·삭제를 함께 요구하는 동적 데이터 집합.
- 주요 목적 : 순서가 있는 키 집합의 탐색, 범위 질의, 순차 출력을 효율적으로 지원.

## Ⅱ. BST의 특징 및 장점

- 핵심 요약 : 키의 순서 관계를 트리 구조로 유지하므로 동적 갱신과 정렬 순회를 함께 제공하며, 균형이 잡힌 경우 연산 비용이 낮음.

1. 탐색 트리 불변식 : 현재 키와 목표 키를 비교해 한쪽 서브트리만 방문 → 불필요한 노드 탐색 감소.
2. **중위 순회** : 왼쪽→현재→오른쪽 순서 방문 → 별도 정렬 없이 키의 오름차순 출력.
3. 동적 연결 구조 : 새 키를 리프 위치에 삽입하고 삭제 후 링크를 재구성 → 배열 이동 없이 집합 변경.
4. 순서 기반 탐색 : 선행자·후속자와 범위 조건을 트리 경로에서 찾음 → 순서형 질의 지원.
5. 균형 상태의 높이 : 높이가 $O(\log N)$이면 탐색·삽입·삭제도 $O(\log N)$ → 데이터 증가에 따른 비용 완화.

## Ⅲ. BST의 구조와 연산 흐름

- 핵심 요약 : 루트부터 비교 방향을 결정하고, 삭제 시 자식 수에 따라 연결을 복구하는 구조.

```text
[ 탐색 트리와 중위 순회 ]
            50
          /    \
        30      70
       /  \    /  \
     20   40  60   80

중위 순회 : 20 → 30 → 40 → 50 → 60 → 70 → 80
탐색 60  : 50 → 70 → 60
```

```text
[ 삽입·삭제의 결정 흐름 ]
시작 → 루트에서 키 비교 → 왼쪽/오른쪽 이동
                         ├─ 빈 위치 : 새 노드 삽입
                         └─ 같은 키 : 탐색 완료 또는 삭제
삭제 → 자식 0개 : 제거
     ├─ 자식 1개 : 자식을 부모에 연결
     └─ 자식 2개 : 중위 후속자(또는 선행자)로 대체
```

- 탐색·삽입·삭제의 시간복잡도는 모두 **트리 높이** $h$에 비례하는 $O(h)$; 트리가 균형이면 $O(\log N)$, 편향되면 $O(N)$.
- 자식이 둘인 노드의 삭제에서는 오른쪽 서브트리의 최솟값인 **중위 후속자** 또는 왼쪽 서브트리의 최댓값인 선행자로 키를 대체한 뒤 해당 노드를 제거.

## Ⅳ. BST와 균형 탐색 트리의 비교

- 핵심 요약 : 기본 BST는 회전 비용이 없지만 높이를 보장하지 않으므로 최악 시간 보장이 필요한 경우 균형 트리 선택.

| 비교 항목 | 기본 BST | AVL 트리 | Red-Black 트리 |
|---|---|---|---|
| 균형 조건 | 별도 보장 없음 | 좌우 서브트리 높이 차이 최대 1 | 색상·흑높이 규칙 |
| 최악 탐색 | $O(N)$ | $O(\log N)$ | $O(\log N)$ |
| 삽입·삭제 후 복구 | 연결만 조정 | 높이 갱신과 회전 | 재색칠과 회전 |
| 선택 기준 | 입력 분포가 관리되거나 소규모 집합 | 읽기 빈도가 높은 순서형 집합 | 갱신·탐색이 혼합된 범용 집합 |

## Ⅴ. BST의 한계와 방안

- 핵심 요약 : **편향 트리**로 인한 성능 저하와 포인터 기반 구조의 비용을 균형 유지·자료구조 선택으로 완화.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 순차 입력 시 높이 증가 | 한쪽 자식으로만 이어져 $O(N)$ 탐색 | AVL·Red-Black 트리의 **회전**으로 균형 유지 | 높이, 탐색 단계 수 |
| 포인터·할당 비용 | 노드별 참조와 동적 할당으로 메모리·캐시 효율 저하 | 연속 저장 구조 또는 B-Tree 계열 검토 | 노드당 메모리, 캐시 미스 |
| 동시 갱신 충돌 | 공유 노드와 경로의 잠금 경합 | 잠금 범위 축소, 읽기 중심이면 적합한 동시성 자료구조 선택 | 잠금 대기, 처리량 |

## Ⅵ. BST에 대한 기술사적 제언

- 핵심 요약 : 정렬 질의와 갱신 빈도, 입력 분포, 저장 매체를 함께 평가하여 탐색 트리 종류를 결정할 필요.
- 설계 단계에서 **최악 시간복잡도** 요구를 명시하고, 순차 입력 시험으로 트리 높이와 지연시간 확인.
- 디스크·SSD 기반 대량 데이터는 페이지 단위 I/O에 맞춘 **B/B+ Tree**, 메모리 기반 순서형 집합은 균형 이진 트리 검토.
- 동시성 요구가 높으면 잠금·재시도 비용을 포함한 실제 작업 부하 측정 후 자료구조 선택.

## Ⅶ. 결론

- 핵심 요약 : BST는 순서가 있는 동적 탐색의 기본 구조이며, 실무 성능은 높이 관리와 저장 환경에 따라 결정.
- **탐색 트리 불변식**과 **중위 순회**가 정렬 탐색의 기반이고, 균형 유지가 최악 성능의 핵심.
