## 연관 키워드

- 회귀 시험, 사이드 이펙트, 전면 재시험, 회귀 테스트 선택(RTS)
- 테스트 케이스 우선순위화, 테스트 영향도 분석, CI, Flaky 테스트

## Ⅰ. 회귀 시험의 개요

- 핵심 요약 : 회귀 시험은 코드 변경 후 기존 기능이 깨지지 않았는지 기존 테스트 케이스의 재실행으로 확인하는 반복 검증.
- 개념 : 결함 수정·기능 추가·리팩토링·환경 변경 등 코드 변경 후, 기존에 정상 동작하던 기능에 **사이드 이펙트**(side effect, 변경이 의도치 않은 다른 부분에 미치는 영향)로 인한 결함이 없는지 기존 테스트 케이스를 재실행해 확인하는 기법(**회귀 시험**, Regression Test).
- 배경 및 필요성 : 모듈 간 결합된 시스템에서는 한 지점의 수정이 무관해 보이는 기능의 장애로 이어질 수 있어 변경 안전성의 입증 수단 필요.
- 주요 목적 : 기존 기능의 품질 저하(퇴행) 방지와 변경 후 빠른 릴리스 지원.

## Ⅱ. 회귀 시험의 특징 및 장점

- 핵심 요약 : 기존 스위트의 재사용·선정 전략·자동화가 변경 방어선 효과와 피드백 속도로 연결됨.

1. 변경 방어선 : 모든 변경을 발동 조건으로 기존 동작을 재검증 → 사이드 이펙트의 조기 발견.
2. 스위트 재사용 : 새 케이스 설계 없이 기존 **테스트 스위트**(test suite, 함께 실행되는 테스트 케이스의 집합)를 재실행 → 준비 비용 최소.
3. 선정 전략 : **전면 재시험**(retest-all, 전체 케이스를 모두 재실행하는 방식), **회귀 테스트 선택**(RTS, Regression Test Selection, 변경 영향 경로의 케이스만 고르는 기법), **테스트 케이스 우선순위화**(prioritization, 중요도 순으로 실행 순서를 정하는 기법)를 상황에 따라 조합 → 시간·위험의 균형.
4. 자동화 연계 : **CI**(Continuous Integration, 지속적 통합) 파이프라인에서 상시 실행 → 변경 직후 피드백 확보.

## Ⅲ. 회귀 시험의 구조 (흐름)

- 핵심 요약 : 변경 감지→영향도 분석→선정·우선순위화→실행→갱신의 순환과, 재테스트 범위를 단계적으로 좁히는 선택 기법.

```text
[ 회귀 시험 수행 흐름 ]

코드 변경 감지
   ↓
변경 영향도 분석
   ↓
케이스 선정·우선순위화
   ↓
테스트 실행·결과 판정
   ↓
결함 조치·스위트 갱신
```

```text
[ 재테스트 범위의 선택 ]

전면 재시험 (Retest-All)
   ↓ 범위 축소
영향도 기반 선택 (RTS)
   ↓ 순서 조정
우선순위화 실행
```

- 범위 선택 기준 : 변경 영향 경로의 커버리지, 과거 결함 이력, 비즈니스 중요도로 축소 범위를 판정.
- **테스트 영향도 분석**(TIA, Test Impact Analysis, 변경 코드와 케이스의 대응 관계로 영향 범위를 찾는 기법)의 도구 적용 시 선정 정밀도가 향상.

## Ⅳ. 신규 기능 시험과 회귀 시험의 비교

- 핵심 요약 : **신규 기능 시험**(new feature testing, 새로 개발된 기능의 요구 충족을 검증하는 시험)은 새 동작의 검증, 회귀 시험은 기존 동작의 보존 검증이라는 상보 역할.

| 비교 축 | 신규 기능 시험 | 회귀 시험 |
|---|---|---|
| 검증 목적 | 새 기능이 요구대로 동작하는지 | 기존 기능이 깨지지 않았는지 |
| 대상 | 신규 설계·구현 영역 | 변경 전까지 정상이던 기능 전반 |
| 케이스 기원 | 요구 분석 기반의 새 설계 | 기존 스위트의 재사용 |
| 수행 시점 | 기능 개발 완료 직후 | 모든 변경 후 상시 |
| 발견 결함 유형 | 미구현·오구현 결함 | 변경 파급 부작용 결함 |

## Ⅴ. 회귀 시험의 한계와 방안

- 핵심 요약 : 스위트 비대화·간헐 실패·노후화·선정 오류를 영향도 도구와 격리·정화 절차로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 스위트 비대화 | 케이스 누적으로 실행 시간 증가 → 배포 지연 | RTS·우선순위화와 스위트의 주기 정리 | 전체 실행 시간 |
| 간헐적 실패 | **Flaky 테스트**(flaky test, 동일 케이스가 실행마다 다른 결과를 내는 테스트)로 결과 신뢰 저하 | 실패 케이스 격리와 환경 고정·대기 명시화 | 간헐 실패율 |
| 스위트 노후화 | 폐기 기능의 케이스 잔존 → 유지 공수 증가 | 정기 정화와 검출력 평가 기반 제거 | 제거·갱신 케이스 수 |
| 선정 오류 | 영향도 분석 부정확 → 회귀 결함 누락 | 커버리지 기준 검증과 선정 정확도 측정 | 누락 회귀 결함 수 |

## Ⅵ. 회귀 시험에 대한 기술사적 제언

- 핵심 요약 : 영향도 분석 도구의 파이프라인 표준 내재화와 간헐 실패 관리 조직·지표 체계의 정례화 필요.

1. 도구 표준화 : 개발조직은 TIA 도구를 CI/CD(Continuous Integration/Continuous Delivery) 표준 파이프라인에 내재화해 선정·실행을 자동화.
2. 운영 제도 : 품질 조직은 간헐 실패 케이스의 격리 큐와 원인 분석 담당을 지정하고, 스위트 건전성 지표의 정기 점검 절차를 운영.

## Ⅶ. 결론

- 핵심 요약 : 회귀 시험은 변경 안전성을 입증하는 상시 방어선.
- 선정 전략·자동화·스위트 건전성 관리의 결합이 지속 가능한 회귀 검증 체계의 조건.
