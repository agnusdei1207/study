## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 안전·신뢰성 → **SW 안전 (SW안전 확보 지침)**

## 30초 인출

- 본질: SW 안전 확보 지침은 소프트웨어 오작동이 생명·재산 피해로 이어지지 않도록 위험 분석부터 운영까지 안전 확보 방법을 정한 「소프트웨어 진흥법」상의 고시 지침
- 메커니즘: 소프트웨어 안전 관련 위험을 분석하고 설계·구현 방법과 검증 방법으로 안전을 확보하며 운영 단계에서도 안전 확보 방안을 유지
- 통찰: 안전 문제를 시험 단계에서 발견하면 설계 변경 비용이 크므로 위험 분석에서 나온 안전 요구사항을 설계·구현·검증·운영 단계로 추적해 반영

<details>
<summary>핵심 용어</summary>

- **소프트웨어안전** : 소프트웨어의 오작동으로 인한 생명·신체·재산 피해가 없는 상태
- **소프트웨어안전 확보 지침** : 「소프트웨어 진흥법」 제30조제2항에 따라 과학기술정보통신부장관이 정해 고시하는 지침
- **위험원(Hazard)** : 사고로 이어질 수 있는 잠재적 상태나 조건
- **안전 요구사항** : 위험원을 허용 가능한 수준으로 낮추기 위한 요구
- **안전 검증** : 안전 요구사항이 충족됐는지 확인하는 활동

</details>

## 2~4교시 25점 답안

## Ⅰ. SW 안전 확보 지침의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **SW 안전 확보 지침** 은 소프트웨어 오작동으로 인한 피해를 막기 위한 안전 확보 방법을 정한 고시 지침 |
| 목적 | 소프트웨어 안전의 체계적 확보 |

## Ⅱ. 일반 품질 관리와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 피해 중심 | 생명·신체·재산 피해 방지 초점 |
| 전 생명주기 | 위험 분석에서 운영까지 |
| 법적 근거 | 「소프트웨어 진흥법」에 따른 지침 |

## Ⅲ. 지침의 구성과 안전 확보 흐름

### 지침 포함 사항

```text
소프트웨어안전 확보 지침
    ├─ 소프트웨어안전 관련 위험 분석
    ├─ 안전 확보를 위한 설계 및 구현 방법
    ├─ 소프트웨어안전 검증 방법
    ├─ 운영 단계의 소프트웨어안전 확보 방안
    └─ 그 밖에 안전 확보에 필요한 사항
```

### 확대: 안전 요구사항의 단계별 추적

```text
위험 분석 → 안전 요구사항
    ↓
설계·구현에 반영 → 검증 → 운영 중 유지
```

## Ⅳ. 지침 항목별 세부 내용

| 항목 | 세부 내용 |
|---|---|
| 위험 분석 | 위험원 식별과 위험 평가 |
| 설계·구현 | 안전 요구를 반영한 설계와 안전한 구현 방식 |
| 검증 | 안전 요구사항 충족 확인 시험 |
| 운영 | 변경·장애 시 안전 영향 분석과 대응 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 후반 시험에서 안전 문제 발견 | 초기 위험 분석과 안전 요구사항 도출 |
| 안전 요구의 설계·시험 반영 확인 곤란 | 안전 요구사항을 추적표로 연결 |
| 운영 중 변경으로 안전성 훼손 | 변경 시 안전 영향 분석 |

## Ⅵ. 제언

위험 분석에서 도출한 안전 요구사항에 ID를 부여해 설계·구현·검증·운영 변경까지 추적

### 추적 구조

```text
위험원 → 안전 요구사항(ID)
    ├─ 설계·구현 요소
    ├─ 검증 시험
    └─ 운영 변경 시 영향 분석
```

### 확대: 변경 시 확인

```text
운영 중 변경 요청
    ↓
안전 요구사항 추적으로 영향 확인
    ↓
영향 있으면 재검증
```

### 선택 근거: 사후 점검과의 비교

| 구분 | 사후 점검 | 제언: 안전 요구 추적 |
|---|---|---|
| 안전 문제 발견 | 후반 | 초기 |
| 반영 확인 | 곤란 | 추적표 |
| 변경 대응 | 개별 판단 | 영향 확인 후 재검증 |

## 출제 이력과 검증 출처

- 제132회 4교시 4번 나: 「소프트웨어 진흥법」 제30조제2항에 따른 소프트웨어안전 확보를 위한 지침에 포함되어야 할 사항
- 「소프트웨어 진흥법」 제30조제2항: 과학기술정보통신부장관이 고시하는 소프트웨어안전 확보 지침의 포함사항(위험 분석, 설계·구현 방법, 검증 방법, 운영 단계 확보 방안, 그 밖에 필요한 사항)
