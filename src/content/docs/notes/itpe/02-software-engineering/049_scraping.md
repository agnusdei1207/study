## 연관 키워드

- 스크래핑, HTML 파싱, DOM, 헤드리스 브라우저
- 웹 크롤링, Open API, robots.txt

## Ⅰ. 스크래핑의 개요

- 핵심 요약 : 웹 페이지의 화면 데이터를 프로그램으로 자동 추출해 분석 가능한 형태로 바꾸는 기술.
- 개념 : 웹 페이지를 이루는 HTML(HyperText Markup Language) 문서에서 필요한 데이터를 프로그램으로 자동 추출하는 기술 (**스크래핑**, Scraping).
- 배경 및 필요성 : 공식 **Open API**(Application Programming Interface)를 제공하지 않는 서비스가 많고, 가격 비교·시세 추적처럼 화면에만 존재하는 데이터에 대한 수요가 상시 발생하는 상황.
- 주요 목적 : 비정형 웹 문서를 정형 데이터로 변환하고 수집을 자동화하여, 분석과 서비스에 필요한 데이터 공급을 안정화하는 것.

## Ⅱ. 스크래핑의 특징 및 장점

- 핵심 요약 : 문서 요청, 구조 해석, 동적 화면 대응의 기술 조합이 사람 개입 없는 정밀 수집이라는 장점으로 연결되는 구조.

1. 정밀 필드 추출 : 문서를 **HTML 파싱**해 **DOM**(Document Object Model) 트리로 만든 뒤 CSS(Cascading Style Sheets) 선택자와 XPath(XML Path Language)로 탐색 → 필요한 필드만 정형 데이터로 추출.
2. 동적 화면 대응 : 화면 없이 브라우저 엔진을 구동하는 **헤드리스 브라우저**(Headless Browser)가 자바스크립트 실행 결과를 확보 → 동적 페이지의 데이터까지 수집 가능.
3. 대상 지정 수집 : 페이지 전체가 아닌 필요한 필드만 선택해 추출 → 전송·저장 비용과 후처리 부담 절감.
4. 수집 자동화 : 스케줄러와 연계한 주기 실행 → 데이터 최신성 유지와 운영 인력 투입 최소화.
5. 수집 허용 범위 준수 : 사이트가 수집 허용 범위를 알리는 **robots.txt** 확인과 요청 빈도 제한 → 대상 서비스 보호와 분쟁 예방.

## Ⅲ. 스크래핑의 구조 (흐름)

- 핵심 요약 : 문서 요청에서 정형 데이터 저장까지 이어지는 파이프라인과, 공급 방식을 고르는 판단 절차의 이중 구조.
- 수집 파이프라인은 HTTP(HyperText Transfer Protocol) 요청에서 시작해 정형 데이터 적재로 끝나는 단방향 흐름.

```text
[ 수집 파이프라인 ]

대상 URL 지정과 HTTP 요청
   ↓
HTML 소스 획득
   ↓
HTML 파싱 (DOM 트리 생성)
   ↓
선택자 기반 필드 추출
   ↓
정제와 정형 데이터 적재
```

- 데이터 공급 방식은 공식 Open API 제공 여부 확인부터 시작하는 절차로 선택.

```text
[ 데이터 공급 방식 선택 흐름 ]

Open API 제공 여부 확인
   ↓ 제공 시 : API 연동으로 종료
   ↓ 미제공 시
robots.txt 허용 범위 확인
   ↓
정적 파싱 가능 여부 판단
   ↓ 불가 시 : 헤드리스 브라우저
   ↓
요청 빈도 제한 후 수집 실행
```

## Ⅳ. 스크래핑과 웹 크롤링의 비교

- 핵심 요약 : 하이퍼링크를 따라 페이지를 순회하는 **웹 크롤링**(Web Crawling)과 필요한 데이터의 추출에 집중하는 스크래핑은 목적과 산출물이 서로 다름.

| 비교 축 | 스크래핑 | 웹 크롤링 |
| --- | --- | --- |
| 목적 | 특정 페이지의 필요 데이터 추출 | 페이지를 체계적으로 순회한 목록 확보 |
| 수집 범위 | 지정한 URL의 좁은 범위 | 링크를 따라 확장되는 넓은 범위 |
| 핵심 동작 | DOM 탐색과 필드 추출 | 링크 수집과 방문 URL 관리 |
| 산출물 | 정형 데이터(필드 단위의 값) | 페이지 URL 목록과 색인 대상 문서 |
| 대표 사례 | 상품 가격 비교, 뉴스 본문 수집 | 검색 엔진의 색인 수집 |

- 결합 관계 : 두 기술은 배타적이지 않고, 웹 크롤링으로 모은 URL 목록을 대상으로 스크래핑을 수행하는 방식의 결합이 일반적.

## Ⅴ. 스크래핑의 한계와 방안

- 핵심 요약 : 화면 변경, 서버 부하, 법적 제약의 세 위험이 수집의 지속성을 위협하므로 항목별 통제 장치 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 파서 파손 | 대상 화면의 태그·클래스명 변경 → 선택자 무효화와 수집 중단 | 선택자 정의의 코드 분리, 변경 감지 점검 운영 | 파싱 실패율 |
| 대상 서버 부하 | 고빈도 요청 → 대상 서비스 성능 저하와 IP 차단 | 요청 간 지연 부여, 비피크 시간대 실행 | 차단 응답 비율 |
| 법적 분쟁 | 허용 범위 밖 수집과 데이터 무단 재이용 → 저작권법 위반 소지 | 수집 전 적법성 검토, 권리자와의 이용 협의 | 적법성 검토 완료율 |

## Ⅵ. 스크래핑 활용에 대한 기술사적 제언

- 핵심 요약 : 수집 활동을 개별 개발자의 기법 수준에서 조직 표준과 데이터 거버넌스 수준으로 끌어올리는 체계 필요.
- 제도 : 데이터 획득 표준에 공식 Open API 우선 원칙을 명문화하고, 스크래핑은 사전 승인 대상으로 한정하는 절차 운영.
- 조직 : 개발 부서와 법무 부서가 함께 참여하는 수집 검토 체계의 상설화.
- 거버넌스 : 수집 데이터의 출처, 수집 시점, 이용 근거를 기록하는 데이터 계보(Data Lineage) 관리 체계로의 확산.

## Ⅶ. 결론

- 핵심 요약 : 스크래핑은 공식 공급로가 없는 데이터의 보완 수단이자 통제 대상인 이중적 위상을 가짐.
- 적법성과 상대 서버 보호라는 전제를 지킬 때만 데이터 확보 수단으로서의 가치가 유지되는 기술.
