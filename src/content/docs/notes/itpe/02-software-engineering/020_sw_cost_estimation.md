## 연관 키워드

- 소프트웨어 규모·비용 산정, FP(Function Point), LOC, COCOMO
- 상향식·하향식 산정, 비용 동인, 생산성, 불확실성

## Ⅰ. 소프트웨어 규모·비용 산정의 개요

- 핵심 요약 : 소프트웨어 규모·비용 산정은 기능량 또는 코드량의 규모 측정을 노력·기간·비용 추정으로 변환하는 관리 활동.
- 개념 : 개발 대상의 규모를 측정하고 생산성·위험 요소를 반영해 투입 노력과 비용을 추정하는 활동(**소프트웨어 규모·비용 산정**, Software Cost Estimation).
- 배경 및 필요성 : SW의 무형성과 초기 요구의 불확실성, 조직별 생산성 편차로 단일 추정치는 오차·예산 낭비·계약 분쟁의 원인.
- 주요 목적 : 객관적 근거에 기반한 예산·일정 수립과 대안 비교, 계약·검수 기준 제공.

## Ⅱ. 소프트웨어 규모·비용 산정기법의 특징 및 장점

- 핵심 요약 : FP는 사용자 기능, LOC는 코드량, COCOMO는 모형 기반 추정으로 각기 다른 측정 대상과 활용 조건을 가짐.

1. 기능점수 산정 : **FP**(Function Point, 기능점수)는 입력·출력·조회·내부논리파일·외부인터페이스를 사용자 기능 관점에서 측정 → 구현 전 산정과 언어 독립적 비교 가능.
2. 코드량 산정 : **LOC**(Line of Code)는 소스 코드 행 수로 규모를 측정 → 산정 절차 단순·생산성 데이터와 직결.
3. 모형 기반 산정 : **COCOMO**(Constructive Cost Model)는 규모와 **비용 동인**(cost driver, 노력에 영향을 주는 제품·인력·플랫폼·프로젝트 속성)으로 노력·기간을 추정 → 과거 실적 기반의 정량 보정 가능.
4. 상향식·하향식 교차 검증 : **상향식**(WBS(Work Breakdown Structure)의 세부 작업 공수 합산)과 **하향식**(유사 사업 전체 공수의 비례 배분)을 병행 → 단일 기법의 편향 완화.

## Ⅲ. 소프트웨어 규모·비용 산정의 구조 (흐름)

- 핵심 요약 : 범위·가정 정의에서 규모 측정, 노력 추정, 실적 보정까지의 환류 구조.

```text
[ 산정 절차 ]
범위·가정 정의
   ↓
규모 산정 : FP 또는 LOC 측정
   ↓
생산성·비용 동인 적용
   ↓
노력·기간·비용 추정
   ↓
불확실성 반영(구간 제시)
   ↓
실적 반영 후 모형 보정
```

```text
[ COCOMO 적용 흐름 ]
프로젝트 형태 구분(조직형·반분리형·내장형)
   ↓
규모 산정(코드 천 행 단위)
   ↓
비용 동인 평가
   ↓
노력·개발 기간 추정
   ↓
트루업(True-up)으로 실적 반영
```

- COCOMO 활용 : 규모는 코드 천 행(KLOC, Kilo Lines of Code) 단위로 표현. 산출 자료가 부족한 초기에는 간이법, 실적 데이터가 축적된 경우 정규법을 적용하고, 개발 종료 후 트루업으로 추정과 실적의 차이를 보정.

## Ⅳ. 모형 기반 산정과 경험칙 전문가 추정의 비교

- 핵심 요약 : 모형 기반 산정은 근거의 재현성, **경험칙**(rule of thumb) 기반 전문가 추정은 신속성이 강점이며, FP·LOC·COCOMO는 상호 보완적 교차 검증 대상.

| 비교 축 | 경험칙 전문가 추정 | 모형 기반 산정(FP·LOC·COCOMO) |
| --- | --- | --- |
| 판단 근거 | 경험·직관·유사 사업 기억 | 측정된 규모·수식·과거 실적 |
| 객관성·재현성 | 추정자마다 편차, 재현 곤란 | 절차·수식 공개로 재현 가능 |
| 소요 노력 | 신속·저비용 | 자료 수집·측정 노력 필요 |
| 불확실성 다루기 | 개인 편향(보수·낙관) 노출 | 구간 추정·민감도 분석 가능 |
| 적합 시점 | 규모·자료 부재의 초기 | 요구가 어느 정도 정의된 단계 |

- FP·LOC·COCOMO 상호 비교 :

| 비교 축 | FP | LOC | COCOMO |
| --- | --- | --- | --- |
| 측정 대상 | 사용자 기능 | 코드 행 수 | 규모·비용 동인 기반 노력·기간 |
| 강점 | 구현 전 측정·언어 독립 | 절차 단순·직관적 | 실적 기반 정량 보정 |
| 한계 | 복잡도 판정의 주관 개입 | 언어·코딩 스타일 의존 | 조직 적합 계수 필요 |
| 대표 활용 | 발주 검수·공수 산정 | 생산성·재작업 측정 | 인력·일정 계획 |

## Ⅴ. 소프트웨어 규모·비용 산정의 한계와 방안

- 핵심 요약 : 요구 불확실성·생산성 편차·점추정 오용을 구간 추정과 실적 환류로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 초기 요구 불완전 | 규모 변동·과소 추정 → 일정 지연·분쟁 | 구간 추정, 가정·제외 범위 문서화 | 추정 오차율 |
| 생산성 가정 편차 | 조직·도메인별 생산성 차이 무시 | 조직 실적 데이터로 생산성 보정 | 실적 대비 오차율 |
| 점추정 오용 | 단일 값을 확정 예산으로 취급 | 시나리오·민감도 분석, 재산정 조항 명시 | 예산 대비 실적 편차 |
| 과거 자료 부재 | 모형 계수의 신뢰 저하 | 유사 사업 비교·독립 이중 추정 | 보정 자료 축적률 |

## Ⅵ. 소프트웨어 규모·비용 산정에 대한 제언

- 핵심 요약 : 산정 근거의 표준화와 실적 환류 체계를 조직·계약 수준에서 구축.
- 발주 기관 : SW 비용 산정 가이드라인에 따라 규모·공수 산출 근거를 검수 자료로 표준화.
- 수행 조직 : 프로젝트 종료 시 실적을 수집해 생산성·계수 데이터베이스를 구축·갱신.
- 계약 당사자 : 범위 변경 시 재산정 조건과 불확실성 구간을 계약서에 명시해 분쟁 소지 차단.

## Ⅶ. 결론

- 핵심 요약 : 소프트웨어 규모·비용 산정은 단일 공식 계산이 아니라 규모·생산성·불확실성을 근거와 함께 다루는 관리 활동.
- 기법 간 교차 검증과 실적 환류가 추정 신뢰도를 결정.
