## 연관 키워드
- 방법론 테일러링, ISO/IEC/IEEE 12207, 생명주기, 위험기반 선택, Tailoring Record, CMMI

### Ⅰ. 개발방법론 테일러링의 개요

- 핵심 요약 : 테일러링은 프로젝트 맥락·위험·규제에 맞춰 생명주기와 프로세스·산출물·통제를 선택·조정하는 활동.
- 개념 : 표준·조직 프로세스의 목표와 제약을 유지하면서 적용범위·세부수준·책임·검증방법을 정당화해 맞춤화(**테일러링**, Methodology Tailoring).
- 배경 및 필요성 : 단일 방법론의 모든 산출물·승인절차를 모든 프로젝트에 그대로 적용하면 과잉 문서 또는 통제 공백이 생김.
- 주요 목적 : 필요한 품질·추적·규제 통제를 보존하면서 전달 효율과 현장 적합성 확보.

### Ⅱ. 테일러링의 특징 및 장점

- 핵심 요약 : 생명주기 선택과 프로세스 조정은 프로젝트 위험·규제·팀역량·요구 변동성에 근거.

1. 맥락 적합 : 규모·중요도·계약·안전/보안 요구 반영 → 과잉·과소 통제 축소.
2. 표준 기반 : ISO/IEC/IEEE 12207 등 프로세스 목적·결과 고려 → 필요한 활동을 식별.
3. 정당화·기록 : 적용·생략·변경 이유와 승인기록 → 감사·재사용 가능.

- 주의 : CMMI는 프로세스 개선·평가 모델이지 특정 프로젝트 개발방법론 자체가 아님.

### Ⅲ. 테일러링 절차 (흐름)

- 핵심 요약 : 프로젝트 속성 분석 → 기준 프로세스 선택 → 활동·산출물·통제 조정 → 승인·적용 → 모니터링·재사용.

```text
사업·위험·규제·팀역량 분석
       ↓
표준/조직 프로세스 기준선 선정
       ↓
적용·조정·제외 항목과 근거 기록
       ↓
품질·보안·고객 승인 → 실행·점검 → 개선
```

```text
요구: 고위험·규제강도 ↑ → 독립검증·추적성·승인활동 강화
요구: 불확실성·피드백 ↑ → 짧은 반복·시제품·현업검토 확대
```

- 산출물 : 적용 프로세스 목록, Tailoring Record, 책임·산출물 매트릭스, 승인·예외 기록.

### Ⅳ. Waterfall·Agile과 테일러링 비교

- 핵심 요약 : Waterfall과 Agile은 개발 흐름의 선택지, 테일러링은 그 흐름·통제를 맥락에 맞게 결정하는 상위 활동.

| 비교 축 | Waterfall | Agile | 테일러링 |
|---|---|---|---|
| 관리 흐름 | 단계·기준선 중심 | 반복·피드백 중심 | 위험·규제·요구특성에 따른 조합·조정 |
| 변경 대응 | 단계 승인 후 통제 변경 | 반복계획에 변경 반영 | 변경통제 수준과 증거를 선택 |
| 활용 | 요구 안정·승인추적 중요 | 요구변동·피드백 중요 | 프로젝트별 방법·산출물 구성 결정 |

### Ⅴ. 테일러링의 한계와 방안

- 핵심 요약 : 근거 없는 생략과 과도한 문서화가 통제 실패·비효율을 낳으므로 위험기반 승인·재평가 적용.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 통제 생략 편향 | 안전·보안·법규 요구 누락 | 필수 통제·독립 승인 목록 유지 | 필수 통제 누락 |
| 형식적 산출물 복제 | 가치 없는 문서 비용 | 산출물 목적·수신자·결정과 연결 | 불필요 문서 수 |
| 환경 변화 미반영 | 방법론 적합성 저하 | 단계관문·변경 시 Tailoring Record 재검토 | 재검토 주기 준수율 |

### Ⅵ. 테일러링 거버넌스 제언

- 핵심 요약 : 방법론 책임자는 최소기준을 정하고 프로젝트 책임자는 조정안을 위험·요구와 함께 승인.

1. PMO·품질조직은 표준 프로세스 자산, 필수 통제, 허용 조정범위를 제공.
2. 프로젝트 관리자는 방법·산출물·책임을 기록하고 고객·보안·품질 담당자의 승인 확보.
3. 조직은 실적·감사·결과를 분석해 프로세스 자산을 갱신.

### Ⅶ. 결론

- 핵심 요약 : 테일러링은 표준을 버리는 예외가 아니라 표준 목적을 프로젝트 상황에 맞춰 적용하는 통제된 설계.
- 시사점 : 각 조정은 근거·책임·승인·재검토 조건을 갖춰야 함.
