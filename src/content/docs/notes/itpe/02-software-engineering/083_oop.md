## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 객체지향·설계 → **객체지향 프로그래밍(OOP)과 절차지향(POP) 비교**

## 30초 인출

- 본질: 객체지향 프로그래밍은 데이터와 동작을 객체로 묶어 객체 사이의 메시지 교환으로 프로그램을 구성하는 방식이며 절차지향은 순서대로 실행되는 함수 중심 방식
- 메커니즘: 객체가 상태와 행위를 캡슐화하고 상속·다형성·추상화로 재사용과 확장을 지원하며, 절차지향은 데이터와 함수를 분리해 함수를 순서대로 호출
- 통찰: 객체를 만들어도 데이터와 처리 로직을 분리해 두면 절차지향과 다를 바 없어져 변경이 여러 곳에 퍼지므로 상태와 그 상태를 다루는 행위를 같은 객체에 두고 캡슐화

<details>
<summary>핵심 용어</summary>

- **절차지향 프로그래밍(POP)** : 함수(절차)를 순서대로 호출해 문제를 해결하는 방식
- **객체지향 프로그래밍(OOP)** : 상태와 행위를 가진 객체들의 협력으로 프로그램을 구성하는 방식
- **캡슐화(Encapsulation)** : 데이터와 연산을 묶고 내부 구현을 감추는 것
- **상속(Inheritance)** : 하위 클래스가 상위 클래스의 속성과 메서드를 물려받는 것
- **다형성(Polymorphism)** : 같은 메시지에 객체 타입에 따라 다르게 동작하는 성질
- **추상화(Abstraction)** : 핵심 특성만 드러내고 세부를 숨기는 것

</details>

## 2~4교시 25점 답안

## Ⅰ. 객체지향 프로그래밍의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **객체지향 프로그래밍** 은 상태와 행위를 가진 객체들의 협력으로 프로그램을 구성하는 방식 |
| 목적 | 재사용성·확장성·유지보수성 향상 |

## Ⅱ. 객체지향의 특징

| 특징 | 의미 |
|---|---|
| 캡슐화 | 상태와 행위를 묶고 내부 은닉 |
| 상속 | 공통 속성·행위의 재사용 |
| 다형성 | 같은 메시지에 다른 동작 |
| 추상화 | 핵심만 드러내는 모델링 |

## Ⅲ. 프로그램 구성 방식의 차이

### 절차지향과 객체지향의 구조

```text
절차지향:  데이터        함수1 → 함수2 → 함수3
           (공유)         (데이터를 받아 처리)

객체지향:  [객체A: 데이터+메서드] ⇄ 메시지 ⇄ [객체B: 데이터+메서드]
```

### 확대: 다형성 동작

```text
결제(pay) 메시지 → 카드결제 객체: 카드 승인
                 → 계좌이체 객체: 이체 요청
(호출자는 타입을 구분하지 않음)
```

## Ⅳ. 절차지향과 객체지향의 비교

| 구분 | 절차지향 | 객체지향 |
|---|---|---|
| 구성 단위 | 함수 | 객체(클래스) |
| 데이터와 로직 | 분리 | 결합(캡슐화) |
| 변경 영향 | 데이터 구조 변경이 여러 함수에 파급 | 객체 내부로 국소화 |
| 재사용 | 함수 단위 | 상속·구성 |
| 적합 조건 | 단순·순차적인 처리 | 복잡한 도메인·변경이 잦은 시스템 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 데이터와 로직을 분리한 객체(빈약한 도메인 모델)로 절차지향화 | 상태를 다루는 행위를 같은 객체에 배치 |
| 상속 남용으로 결합도 증가 | 상속 대신 구성 우선 |
| 단순 처리에 객체 설계 과다 | 규모에 맞는 설계 수준 선택 |

## Ⅵ. 제언

상태를 바꾸는 로직은 그 상태를 가진 객체 안에 두고, 단순한 순차 처리에는 절차지향 방식도 병용

### 책임 배치 원칙

```text
상태를 바꾸는 규칙 → 해당 상태를 가진 객체의 메서드
외부 서비스는 객체에 동작을 요청 (상태를 꺼내 판단하지 않음)
```

### 확대: 적용 판단

```text
처리 성격
    ├─ 도메인 규칙·변경 잦음 → 객체지향
    └─ 단순 순차 변환 → 절차지향
```

### 선택 근거: 데이터·로직 분리 구조와의 비교

| 구분 | 데이터·로직 분리 | 제언: 상태와 행위 결합 |
|---|---|---|
| 변경 파급 | 여러 함수·서비스 | 해당 객체 |
| 규칙 중복 | 발생 | 한 곳 |
| 시험 | 서비스 전체 | 객체 단위 |
