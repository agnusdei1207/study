## 연관 키워드

- OOP, 객체, 추상화, 캡슐화, 상속, 다형성, 조합

## Ⅰ. 객체지향 프로그래밍의 개요

- 핵심 요약 : OOP(Object-Oriented Programming)는 상태와 행위를 객체에 결합하고 추상화·캡슐화·상속·다형성을 활용하는 프로그래밍 패러다임.
- 개념 : OOP(Object-Oriented Programming)는 상태와 행위를 객체에 결합하고 추상화·캡슐화·상속·다형성을 활용하는 프로그래밍 패러다임.
- 배경 및 필요성 : 공유 상태·복잡한 도메인 규칙·변경 영향 관리를 위해 책임과 협력을 구조화할 필요.
- 주요 목적 : 변화 가능한 소프트웨어의 책임 분리·재사용·확장성 지원.

## Ⅱ. 객체지향 프로그래밍의 특징 및 장점

- 핵심 요약 : 객체·클래스, 추상화, 캡슐화, 상속, 다형성; 상속보다 조합이 적합한 경우 고려.

1. 구조 명시: 객체·클래스, 추상화, 캡슐화, 상속, 다형성; 상속보다 조합이 적합한 경우 고려 → 변화 가능한 소프트웨어의 책임 분리·재사용·확장성 지원.
2. 기대 효과 : OOP는 객체의 협력으로 복잡성을 관리하는 방식이며 모든 문제에 가장 단순하거나 빠른 패러다임은 아님.
3. 적용 원칙 : 아키텍트는 도메인 개념과 변화이유에 맞는 객체경계를 두고 함수형·절차형 기법과 조합해 단순한 설계 유지.

## Ⅲ. 객체지향 프로그래밍의 구조 (흐름)

- 핵심 요약 : 도메인 책임 식별 → 객체·인터페이스 모델링 → 협력·메시지 정의 → 구현·테스트 → 변경·확장 검증.

```text
도메인 책임 식별
  ↓
객체·인터페이스 모델링
  ↓
협력·메시지 정의
  ↓
구현·테스트
  ↓
변경·확장 검증
```

- 핵심 구성 : 객체·클래스, 추상화, 캡슐화, 상속, 다형성; 상속보다 조합이 적합한 경우 고려.

```text
도메인 객체 → 메시지·협력 → 상태·행위 캡슐화 → 다형적 확장
```

## Ⅳ. 유사 개념과의 비교

- 핵심 요약 : 절차지향 프로그래밍 — 절차·함수와 데이터 처리 흐름; 객체지향 프로그래밍 — 상태·행위를 가진 객체 간 협력.

| 비교 기준 | 절차지향 프로그래밍 | 객체지향 프로그래밍 |
| --- | --- | --- |
| 주요 분해단위 | 절차·함수와 데이터 처리 흐름 | 상태·행위를 가진 객체 간 협력 |

## Ⅴ. 객체지향 프로그래밍의 한계와 방안

- 핵심 요약 : 주요 한계는 취약한 기반 클래스·가변 공유상태·객체 과다 생성이며, 원인별 대응과 검증지표의 연계가 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 취약한 기반 클래스 | 상속 계층의 내부 변경 파급 | 구성·조합·계약 중심 설계 | 상속 변경영향 |
| 가변 공유상태 | 객체 간 상태변경 부작용 | 불변 객체·경계 캡슐화·명시적 명령 | 동시성·상태오류 |
| 객체 과다 생성 | 모든 값을 객체·패턴으로 감싸 복잡화 | 문제 도메인·성능에 맞는 추상화 | 할당량·인지복잡도 |

## Ⅵ. 객체지향 프로그래밍에 대한 제언

- 핵심 요약 : 변화 가능한 소프트웨어의 책임 분리·재사용·확장성 지원.

1. 주체·실행 : 아키텍트는 도메인 개념과 변화이유에 맞는 객체경계를 두고 함수형·절차형 기법과 조합해 단순한 설계 유지.
2. 성과 검토 : 상속 변경영향·동시성·상태오류·할당량·인지복잡도를 정기 측정하고 편차에 대한 원인분석·개선결과를 기록.

## Ⅶ. 객체지향 프로그래밍의 결론

- 핵심 요약 : OOP(Object-Oriented Programming)는 상태와 행위를 객체에 결합하고 추상화·캡슐화·상속·다형성을 활용하는 프로그래밍 패러다임.
- 시사점 : OOP는 객체의 협력으로 복잡성을 관리하는 방식이며 모든 문제에 가장 단순하거나 빠른 패러다임은 아님.
