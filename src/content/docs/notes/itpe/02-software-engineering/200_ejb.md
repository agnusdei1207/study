소프트웨어 공학 → 프레임워크 → **엔터프라이즈 자바 빈즈(EJB)**

## 30초 인출

- 본질: EJB는 자바 기반 기업용 업무 로직을 컴포넌트(빈)로 만들고 컨테이너가 트랜잭션·보안·수명주기를 관리하게 하는 서버 측 컴포넌트 모델
- 메커니즘: 개발자는 업무 로직을 빈으로 작성하고 컨테이너가 선언적 설정으로 트랜잭션·보안·자원 관리를 대신 처리
- 통찰: 컨테이너 종속과 복잡한 설정이 개발을 무겁게 하므로 인프라 서비스는 컨테이너에 맡기되 업무 로직은 가벼운 클래스로 작성해 컨테이너 의존을 줄임

<details>
<summary>핵심 용어</summary>

- **EJB(Enterprise JavaBeans)** : 자바 기업용 서버 측 컴포넌트 모델
- **EJB 컨테이너** : 빈의 수명주기와 트랜잭션·보안을 관리하는 실행 환경
- **세션 빈(Session Bean)** : 클라이언트 요청의 업무 로직을 수행하는 빈. 무상태와 상태 유지로 구분
- **메시지 구동 빈(Message-Driven Bean)** : 메시지 큐의 메시지를 비동기로 처리하는 빈
- **컨테이너 관리 트랜잭션(CMT)** : 컨테이너가 설정에 따라 트랜잭션을 처리하는 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. EJB의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **EJB** 는 기업용 업무 로직을 컴포넌트로 만들고 컨테이너가 인프라 서비스를 관리하는 자바 서버 컴포넌트 모델 |
| 목적 | 업무 로직과 인프라 서비스의 분리 |

## Ⅱ. 특징

| 특징 | 의미 |
|---|---|
| 컨테이너 관리 | 트랜잭션·보안·수명주기를 컨테이너가 처리 |
| 컴포넌트 재사용 | 표준 규약의 빈 |
| 분산 환경 | 원격 호출 지원 |

## Ⅲ. 구조

```text
클라이언트 ─▶ [ EJB 컨테이너 ]
               ├─ 세션 빈 (업무 로직)
               ├─ 메시지 구동 빈 (메시지 처리)
               └─ 컨테이너 서비스: 트랜잭션·보안·수명주기
```

## Ⅳ. 빈의 종류

| 유형 | 특징 | 용도 |
|---|---|---|
| 무상태 세션 빈 | 요청 사이 상태 미보관 | 일반 업무 서비스 |
| 상태 유지 세션 빈 | 클라이언트별 상태 보관 | 대화 형태 처리 |
| 메시지 구동 빈 | 메시지 큐 연동 | 비동기 처리 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 컨테이너 종속과 복잡한 설정 | 경량 프레임워크 활용과 표준 인터페이스 사용 |
| 시험이 어려움 | 업무 로직을 컨테이너와 분리된 클래스로 작성 |
| 무거운 개발·배포 | 필요한 서비스만 사용 |

## Ⅵ. 제언

인프라 서비스는 컨테이너에 맡기고 업무 로직은 컨테이너와 분리된 일반 클래스로 작성

```text
업무 로직(일반 클래스) ⇄ 컨테이너 서비스(트랜잭션·보안)
```

| 구분 | 로직이 컨테이너에 종속 | 제언: 로직 분리 |
|---|---|---|
| 시험 | 컨테이너 필요 | 단독 시험 |
| 이식 | 곤란 | 용이 |
