## 연관 키워드
- EJB, Enterprise JavaBeans, 세션 빈, 메시지 구동 빈, 컨테이너 관리 트랜잭션, JPA

### Ⅰ. EJB의 개요

- 핵심 요약 : EJB는 Jakarta EE 서버 컨테이너가 트랜잭션·보안·동시성 등 엔터프라이즈 서비스를 제공하는 서버 측 컴포넌트 모델.
- 개념 : 세션 빈과 메시지 구동 빈 등을 컨테이너에 배포해 비즈니스 로직과 공통 시스템 서비스를 분리하는 명세(**EJB**, Enterprise JavaBeans).
- 배경 및 필요성 : 분산 트랜잭션·보안·수명 주기 관리를 애플리케이션 마다 직접 구현하는 부담을 줄이기 위한 모델.
- 주요 목적 : 표준 컨테이너 서비스를 이용한 트랜잭션성·보안성·확장성 있는 서버 응용 구성.

### Ⅱ. EJB의 특징 및 장점

- 핵심 요약 : 컨테이너가 선언적 서비스와 컴포넌트 수명 주기를 관리해 업무 로직의 기반 기능 구현 부담을 감소.

1. 세션 빈 : Stateless·Stateful·Singleton 유형으로 업무 서비스와 상태 범위 표현 → 처리 유형에 맞는 컴포넌트 구조.
2. 컨테이너 관리 트랜잭션(CMT) : 선언적 트랜잭션 경계와 롤백 규칙 적용 → 반복적인 트랜잭션 코드 감소.
3. 메시지 구동 빈(MDB) : 비동기 메시지를 컨테이너가 수신·호출 → 메시지 기반 업무 처리와 시스템 간 결합 완화.

### Ⅲ. EJB의 구조 (흐름)

- 핵심 요약 : 클라이언트 호출 또는 메시지 수신을 컨테이너가 중개하고 보안·트랜잭션 서비스 아래 빈의 업무 로직 실행.

```text
클라이언트 / 메시지 브로커
           ↓
EJB 컨테이너 (보안·트랜잭션·풀·수명 주기)
           ↓
세션 빈 / 메시지 구동 빈
           ↓
데이터 접근(JPA)·외부 시스템
```

- 구성 구분 : 세션 빈은 동기 업무 서비스, MDB는 비동기 메시지 소비를 담당하며 영속성 모델은 현대 Jakarta EE에서 JPA로 분리.

```text
요청 → 컨테이너 인터셉터 → 업무 빈 → JPA·외부 자원
                ├ 인증·인가
                └ 트랜잭션 시작·커밋/롤백
```

### Ⅳ. EJB와 Spring 기반 컴포넌트 비교

- 핵심 요약 : EJB는 Jakarta EE 컨테이너 명세 중심, Spring은 애플리케이션 프레임워크의 IoC·모듈 생태계 중심.

| 비교 기준 | EJB | Spring 기반 컴포넌트 |
|---|---|---|
| 런타임 | Jakarta EE 애플리케이션 서버 컨테이너 | 선택 가능한 서블릿·애플리케이션 런타임 |
| 서비스 선언 | 표준 애노테이션·컨테이너 계약 | 프레임워크 애노테이션·설정 및 추상화 |
| 운영 적합성 | 표준 서버 환경·기존 기업 플랫폼에 적합 | 경량 배포·다양한 클라우드 구성이 용이 |

### Ⅴ. EJB의 한계와 방안

- 핵심 요약 : 컨테이너 결합·원격 호출 비용·시험 복잡성을 서비스 경계와 배포 환경 선택으로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 컨테이너 결합 | 런타임·버전·운영 기술에 종속될 수 있음 | 표준 API 준수, 업무 도메인과 어댑터 분리 | 컨테이너 종속 코드 비율 |
| 원격 호출 오버헤드 | 네트워크 호출은 로컬 호출보다 지연·실패 가능성이 큼 | 거친 서비스 경계, 배치 호출, 타임아웃·재시도 설계 | 호출 지연·실패율 |
| 단위 시험 복잡성 | 컨테이너 기능·자원 설정 없이는 재현이 어려운 로직 | 핵심 규칙을 POJO 도메인으로 분리하고 컨테이너 통합 시험 병행 | 단위 시험 비율·통합 결함 |

### Ⅵ. EJB의 제언

- 핵심 요약 : 아키텍트는 기존 Jakarta EE 역량·운영 환경·확장 요구를 기준으로 EJB 사용 범위를 정하고 도메인 모델은 기술에서 분리.

1. 플랫폼 책임 자는 지원 서버·명세 버전·패치 정책을 표준화.
2. 설계 자는 상태 없는 업무 서비스와 상태 보유 세션 빈을 목적에 맞게 선택.
3. 현대화 프로젝트는 새 기술로의 전면 전환보다 배포·운영 비용과 기존 서비스 연계를 포함한 총 소유 비용 비교 수행.

### Ⅶ. EJB의 결론

- 핵심 요약 : EJB는 엔터프라이즈 컨테이너가 횡단 서비스를 관리하는 서버 측 컴포넌트 모델.
- 시사점 : 컨테이너 서비스가 주는 생산성과 런타임 복잡성의 균형이 도입 판단의 핵심.
