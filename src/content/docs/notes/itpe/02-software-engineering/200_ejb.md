## 학습 위치

소프트웨어공학 → 서버 측 엔터프라이즈 컴포넌트 → Jakarta EE → **Enterprise Beans**

## 30초 인출

- **본질**: Enterprise Beans는 Jakarta EE 서버에서 실행되는 서버 측 컴포넌트 모델
- **메커니즘**: 빈 컴포넌트 구현 → 컨테이너가 생명주기·트랜잭션 등 서비스를 제공 → 애플리케이션이 업무 기능 호출

<details>
<summary>핵심 용어</summary>

- **Enterprise Beans(EJB)**: Jakarta EE 서버에서 실행되는 컴포넌트 아키텍처
- **컨테이너(Container)**: 빈의 실행·생명주기와 선언된 엔터프라이즈 서비스를 관리하는 실행 환경
- **세션 빈(Session Bean)**: 클라이언트 요청에 업무 처리를 제공하는 빈 유형
- **메시지 구동 빈(Message-Driven Bean, MDB)**: 메시지 기반 비동기 처리를 담당하는 빈 유형
- **Jakarta EE**: 엔터프라이즈 자바 애플리케이션을 위한 규격 집합

</details>

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **Enterprise Beans**: Jakarta EE 서버에서 실행되는 서버 측 컴포넌트 모델 |

### Ⅱ. 구성과 실행

```text
클라이언트 → Enterprise Bean → 데이터·외부 자원
                    │
                    └─ Jakarta EE 컨테이너 제공 서비스
                       (생명주기·트랜잭션·보안)
```

컨테이너 서비스의 실제 제공 범위는 규격 버전과 배포 환경에 따름.

### Ⅲ. 주요 빈 유형

| 유형 | 역할 |
|---|---|
| 세션 빈 | 클라이언트 요청에 업무 로직 제공 |
| 메시지 구동 빈 | 메시지 소비 기반의 비동기 업무 처리 |

**제언**: 빈의 업무 책임과 컨테이너에 위임하는 기능을 분리해 인터페이스와 배포 설정에 명시.

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **Enterprise Beans**: Jakarta EE 서버에서 실행되는 서버 측 컴포넌트 모델 |
| 목적 | 컨테이너 서비스를 활용해 엔터프라이즈 업무 기능을 구성 |

## Ⅱ. 아키텍처와 책임

```text
클라이언트 → 빈 인터페이스·업무 구현 → 저장소·연계 자원
                       │
                       └─ 컨테이너 서비스
                          (트랜잭션·보안·생명주기)
```

빈은 업무 기능을 구현하고 컨테이너는 규격과 구성에 따라 실행·생명주기·트랜잭션·보안 등의 서비스를 관리. 모든 서비스가 모든 빈에 자동 적용된다는 의미는 아니며 설정과 규격을 확인.

## Ⅲ. 빈 유형과 사용 관점

| 유형 | 핵심 역할 | 검토 지점 |
|---|---|---|
| Stateless Session Bean | 호출 간 클라이언트 상태를 빈에 보존하지 않는 업무 처리 | 요청 간 상태를 외부에 둘 필요 |
| Stateful Session Bean | 클라이언트와 관련한 상태를 유지하는 업무 흐름 | 동시성·상태 수명주기 관리 |
| Singleton Session Bean | 애플리케이션 내 공유되는 단일 세션 빈 인스턴스 모델 | 공유 상태 접근 동기화 |
| Message-Driven Bean | 메시지를 받아 비동기 업무 수행 | 중복 전달·재처리·오류 처리 |

세부 기능은 사용하는 Jakarta Enterprise Beans 규격 버전에 따라 확인.

## Ⅳ. 컨테이너 관리 기능

| 기능 | 역할 |
|---|---|
| 생명주기 | 빈 생성·초기화·종료 등 실행 관리 |
| 트랜잭션 | 선언적 설정 등에 따른 트랜잭션 경계 관리 |
| 보안 | 구성된 역할·접근 정책 적용 |
| 자원 연결 | 규격·환경에 따른 자원 참조와 연계 |

현재 Jakarta EE 규격은 패키지 접두어로 `jakarta.*` 사용. EJB 2.x API 일부는 호환 목적으로 선택 사항이며, 과거 분산 상호운용 기능을 현재 필수 기능으로 일반화하지 않음.

## Ⅴ. 적용 구조와 선택

```text
업무 처리 요구
  ├─ 동기 호출 중심 → 세션 빈 검토
  └─ 메시지 소비 중심 → 메시지 구동 빈 검토
                         ↓
                규격·컨테이너·운영 환경 확인
                  ├─ 적합 → 배포·통합 시험
                  └─ 부적합 → 다른 서버 구성 검토
```

Jakarta EE와 컨테이너 기반 모델의 적합성은 시스템 제약, 팀 역량, 배포·운영 환경과 함께 판단. 서버 제품이나 특정 기술 도입을 전제로 하지 않음.

## Ⅵ. 한계와 대응

| 한계 | 해결 방안 |
|---|---|
| 컨테이너 제공 기능을 무조건적 보장으로 오해 | 사용 규격 버전·빈 유형·설정별 지원 범위를 검증 |
| 빈 업무 로직과 외부 부작용이 강하게 결합 | 업무 경계와 트랜잭션·메시지 처리 경계를 명확히 설계 |
| 비동기 메시지 처리에서 중복·실패 누락 | 멱등성, 재시도, 실패 메시지 처리와 관측 기준 정의 |

## Ⅶ. 기술적 제언

| 구분 | 내용 |
|---|---|
| 한계 | 규격 버전과 실제 컨테이너 설정이 설계 문서와 다르면 배포 시 서비스 동작을 예측하기 어려움 |
| 해결 방안 | 적용 규격·빈 유형·컨테이너 서비스·배포 설정을 한 구성 기준으로 추적하고 통합 시험에서 확인 |
