## 30초 인출

- **본질**: EIP는 서로 다른 시스템을 메시지로 연결할 때 반복되는 전달·라우팅·변환·오류 처리 문제의 설계 패턴 모음
- **메커니즘**: 메시지 발행 → 채널 전달 → 목적지 선택·형식 변환 → 수신·오류 처리

<details>
<summary>핵심 용어</summary>

- **EIP(Enterprise Integration Patterns)**: 메시지 기반 시스템 통합 문제와 해법을 기술 독립적으로 정리한 패턴 언어
- **메시지 채널(Message Channel)**: 송신자와 수신자 사이에서 메시지를 전달하는 경로
- **내용 기반 라우터(Content-Based Router)**: 메시지 내용에 따라 수신 경로를 고르는 패턴
- **메시지 변환기(Message Translator)**: 수신자가 이해할 수 있도록 메시지 형식을 바꾸는 패턴
- **분할기(Splitter)**: 복합 메시지를 개별 메시지로 나누는 패턴
- **집계기(Aggregator)**: 관련 메시지를 모아 하나의 결과를 만드는 패턴
- **데드 레터 채널(Dead Letter Channel)**: 정상 처리할 수 없는 메시지를 별도로 보내 조사·재처리하는 채널
- **멱등 수신자(Idempotent Receiver)**: 같은 메시지가 반복 도착해도 업무 효과가 중복되지 않게 처리하는 패턴

</details>

## Ⅱ. 메시지 처리 구조

```text
송신 시스템
    ↓ 메시지 발행
메시지 채널
    ↓ 라우팅·변환
수신 시스템

처리 실패 → 오류·데드 레터 채널
```

| 계층 | 주된 판단 |
|---|---|
| 메시지·채널 | 무엇을 어떤 경로로 전달할 것인가? |
| 라우팅·변환 | 어느 수신자에게 어떤 형식으로 보낼 것인가? |
| 수신·오류 처리 | 중복·지연·실패를 어떻게 처리할 것인가? |

## Ⅲ. 대표 패턴과 역할

| 패턴 | 해결 문제 | 핵심 동작 |
|---|---|---|
| **내용 기반 라우터** | 메시지마다 수신자가 다름 | 내용에 따라 채널 선택 |
| **메시지 변환기** | 시스템 간 형식 불일치 | 데이터 형식·구조 변환 |
| **분할기·집계기** | 복합 요청의 개별 처리·결과 결합 | 분할 후 상관관계로 집계 |
| **데드 레터 채널** | 처리 불가 메시지의 반복 실패 | 격리·조사·재처리 |
| **멱등 수신자** | 중복 전달 시 중복 업무 처리 | 같은 메시지의 효과 중복 방지 |

패턴은 요구에 따라 조합하며 모든 통합 경로에 다섯 패턴을 넣어야 하는 것은 아님.

## Ⅳ. 분할·집계 및 오류 흐름

```text
복합 메시지
    ↓ 분할기
작업 1 · 작업 2
    ↓ 각 결과 도착
집계기 → 결과 메시지

처리 불가 메시지 → 오류 채널
```

| 설계 항목 | 확인 사항 |
|---|---|
| 상관관계 | 분할 결과가 원래 요청과 연결되는 식별자 |
| 완료 조건 | 모든 응답 수신, 시간 초과, 부분 결과 처리 기준 |
| 오류 처리 | 재시도·격리·수동 개입의 구분 |

## Ⅴ. 전달 보장과 중복 대응

| 상황 | 대응 |
|---|---|
| 재시도 후 중복 도착 | **멱등 수신자**와 업무 키를 이용한 중복 효과 방지 |
| 처리 중 실패 | 재시도 범위·횟수·오류 채널 분리 |
| 메시지 형식 변경 | 송수신 계약과 변환 규칙 버전 관리 |

**최소 1회 전달**만으로 업무 효과의 정확한 1회 처리가 보장되지는 않으며, 저장·중복 판정의 원자성까지 검토.

## Ⅵ. 문제와 해결 방안

| 한계 | 해결 방안 |
|---|---|
| 송수신 형식·목적지가 코드 곳곳에 흩어짐 | 메시지 계약과 라우팅·변환 패턴으로 통합 경로 명시 |
| 재시도 메시지가 중복 거래를 만듦 | 업무 키 기반 멱등 처리와 실패 재처리 절차 마련 |
| 처리 불가 메시지가 정상 흐름을 막음 | **데드 레터 채널**로 격리하고 원인·재처리 기준 운영 |
