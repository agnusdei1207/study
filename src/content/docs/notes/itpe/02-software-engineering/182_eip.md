## 30초 인출

- 본질: EIP는 시스템 간 메시지 기반 통합에서 반복되는 문제를 채널·라우터·변환기 같은 패턴으로 정리한 통합 설계 패턴 모음
- 메커니즘: 송신 시스템이 메시지 채널로 보낸 메시지를 라우터가 목적지로 나누고 변환기가 형식을 맞춰 수신 시스템에 전달하며 실패 메시지는 별도 채널로 분리
- 통찰: 시스템마다 데이터 형식과 처리 방식이 달라 직접 연결하면 결합이 커지므로 패턴을 조합해 메시지 흐름 안에서 변환·분기·오류 처리를 담당하게 하고 시스템은 채널로만 연결

<details>
<summary>핵심 용어</summary>

- **EIP(Enterprise Integration Patterns)** : 메시지 기반 시스템 통합의 설계 패턴 모음. Hohpe·Woolf 정리
- **메시지 채널(Message Channel)** : 송신자와 수신자를 연결하는 메시지 전달 통로
- **내용 기반 라우터(Content-Based Router)** : 메시지 내용에 따라 목적지를 나누는 패턴
- **메시지 변환기(Message Translator)** : 메시지 형식을 수신자가 이해하는 형식으로 바꾸는 패턴
- **분할기·집계기(Splitter·Aggregator)** : 하나의 메시지를 나누어 처리하고 결과를 다시 모으는 패턴
- **데드 레터 채널(Dead Letter Channel)** : 처리할 수 없는 메시지를 옮겨 두는 채널

</details>

## 2~4교시 25점 답안

## Ⅰ. EIP의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **EIP** 는 메시지 기반 시스템 통합에서 반복되는 문제의 해법을 패턴으로 정리한 것 |
| 목적 | 이기종 시스템 통합의 설계 재사용과 결합도 감소 |

## Ⅱ. 직접 연동과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 메시지 중심 | 시스템은 채널로만 연결 |
| 패턴 조합 | 라우팅·변환·분할 등을 조합 |
| 비동기 지향 | 송신과 수신의 시간 분리 |

## Ⅲ. 패턴 구성

```text
송신 시스템 ─▶ [채널] ─▶ [내용 기반 라우터] ─┬─▶ [변환기] ─▶ 수신 시스템 A
                                            └─▶ [변환기] ─▶ 수신 시스템 B
                                  (처리 실패) ─▶ [데드 레터 채널]
```

## Ⅳ. 대표 패턴

| 패턴 | 역할 |
|---|---|
| 메시지 채널 | 시스템 사이의 전달 통로 |
| 내용 기반 라우터 | 메시지 내용에 따른 목적지 분기 |
| 메시지 변환기 | 데이터 형식 변환 |
| 분할기·집계기 | 메시지 분할 처리와 결과 통합 |
| 데드 레터 채널 | 처리 불가 메시지의 분리 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 패턴이 많아 흐름 파악이 어려움 | 통합 흐름을 도식화해 문서화 |
| 처리 실패 메시지의 유실 | 데드 레터 채널과 재처리 절차 |
| 메시지 형식 변경의 파급 | 변환기에서 형식 변경을 흡수 |

## Ⅵ. 제언

시스템은 채널로만 연결하고 변환·분기·오류 처리는 통합 흐름 안의 패턴이 담당하도록 구성

```text
시스템 ⇄ 채널 (형식·분기·오류는 통합 흐름이 처리)
```

| 구분 | 시스템 직접 연결 | 제언: 채널·패턴 |
|---|---|---|
| 형식 변경 | 양쪽 수정 | 변환기만 수정 |
| 오류 처리 | 각 시스템 | 데드 레터 채널 |
