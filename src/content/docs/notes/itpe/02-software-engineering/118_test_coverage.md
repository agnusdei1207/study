소프트웨어공학 > 소프트웨어 테스팅·품질 > 테스트 커버리지

## 30초 인출

- 본질: **테스트 커버리지**는 정한 검증 항목 가운데 시험으로 다룬 항목의 정도
- 메커니즘: 커버리지 항목·기준 설정 → 시험 실행·측정 → 미검증 영역 분석 → 위험에 맞춰 보완
- 핵심 관계: 요구사항·코드·조건 등 측정 관점이 다르며, 높은 수치만으로 결함 부재를 증명하지는 못함

<details>
<summary>핵심 용어</summary>

- **테스트 커버리지(Test Coverage)**: 지정한 커버리지 항목 가운데 테스트 스위트가 실행하거나 만족한 정도
- **커버리지 항목(Coverage Item)**: 커버리지 측정 기준에서 시험 여부를 확인할 개별 요소
- **요구사항 커버리지(Requirements Coverage)**: 요구사항 중 테스트와 연결되어 검증된 항목의 범위
- **구문 커버리지(Statement Coverage)**: 실행 가능한 구문 가운데 테스트 중 실행된 구문의 비율
- **분기 커버리지(Branch Coverage)**: 제어 흐름의 분기 결과 가운데 테스트 중 실행된 결과의 비율
- **조건 커버리지(Condition Coverage)**: 개별 논리 조건의 참·거짓 결과를 시험한 정도
- **수정 조건/결정 커버리지(MC/DC, Modified Condition/Decision Coverage)**: 각 개별 조건이 다른 조건과 독립적으로 전체 결정 결과에 영향을 미침을 보이는 커버리지 기준
- **테스트 오라클(Test Oracle)**: 시험 결과가 기대 결과와 일치하는지 판정하는 기준이나 수단
</details>

## 1교시 예상문제 (10점)

> 테스트 커버리지의 정의와 목적, 주요 측정 관점을 설명하시오. (예상)

---

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 테스트 커버리지는 정한 검증 항목 가운데 시험으로 다룬 항목의 정도 |
| 목적 | 시험 범위와 미검증 영역을 파악해 보완 시험과 완료 판단을 지원 |

### Ⅱ. 측정 흐름

```text
측정 대상·커버리지 기준 정의
    ↓
테스트 실행·계측
    ↓
미검증 항목·잔여 위험 확인
    ↓
보완 시험 설계·재실행
```

### Ⅲ. 주요 측정 관점

| 관점 | 측정 대상 |
|---|---|
| 요구사항 | 테스트와 연결되어 검증된 요구사항 |
| 구조 | 실행된 구문·분기·조건 |
| 커버리지 해석 | 수치는 시험 범위의 지표이며 결함 부재의 증명은 아님 |

- 제언: 커버리지 결과를 요구사항 중요도·위험 및 기대 결과 검증과 함께 해석

---

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 테스트 커버리지는 정한 검증 항목 가운데 시험으로 다룬 항목의 정도 |
| 목적 | 시험 범위와 미검증 영역을 파악해 보완 시험과 완료 판단을 지원 |

## Ⅱ. 측정 절차

```text
시험 목표·위험 분석
    ↓
커버리지 항목·기준 선택
    ↓
시험 실행·실측 결과 수집
    ↓
미검증·미통과 항목 분석
    ↓
보완 시험 또는 잔여 위험 수용
```

| 단계 | 주요 활동 | 산출 정보 |
|---|---|---|
| 목표 설정 | 시험 목적과 위험에 맞는 커버리지 관점 선택 | 측정 대상·기준 |
| 시험·계측 | 사례 실행, 요구사항 추적 및 코드 실행 자료 수집 | 실행·추적 기록 |
| 분석·보완 | 공백의 원인과 중요도를 분석해 시험 보완 | 보완 시험·잔여 위험 기록 |

## Ⅲ. 측정 기준

| 기준 | 측정 내용 | 확인할 한계 |
|---|---|---|
| 요구사항 커버리지 | 시험과 연결되고 검증된 요구사항 | 요구사항 자체의 누락·모호성은 별도 검토 |
| 구문 커버리지 | 실행된 구문 | 분기 결과를 모두 시험했음을 보장하지 않음 |
| 분기 커버리지 | 조건 분기의 참·거짓 등 실행 결과 | 개별 조건 조합을 모두 검증했음을 보장하지 않음 |
| 조건 커버리지 | 개별 조건의 참·거짓 결과 | 전체 결정 결과에 대한 독립 영향을 반드시 보이지는 않음 |
| MC/DC | 각 조건이 독립적으로 결정 결과에 영향을 주는 사례 | 적용 필요성과 기준은 시스템 위험·도메인 요구로 결정 |

## Ⅳ. 측정과 해석

```text
커버리지 = 충족한 측정 항목 / 전체 대상 항목
    ↓
미충족 항목·원인 확인
    ↓
위험 기반 보완 시험·수용 근거 기록
```

커버리지 비율은 측정 대상 중 기준을 충족한 항목의 비율. 분모·제외 항목·도구 계측 범위를 명시해야 비교 가능한 결과이며, 실행 여부 중심의 커버리지 하나만으로 기대 결과의 확인 여부나 요구사항 누락까지 판단하기 어려움

| 해석 질문 | 점검 내용 |
|---|---|
| 무엇을 측정했는가 | 요구사항, 구문, 분기, 조건 등 기준과 범위 |
| 무엇이 빠졌는가 | 미실행 항목과 제외 사유, 위험 영향 |
| 시험이 유효한가 | 테스트 오라클과 검증 결과의 적절성 |

## Ⅴ. 품질 관리상 유의점

| 위험 | 관리 방안 |
|---|---|
| 높은 코드 커버리지를 결함 부재로 오해 | 요구사항 기반 시험, 기대 결과 확인, 결함·위험 분석을 함께 사용 |
| 도구·설정 차이로 수치 비교가 왜곡 | 분모·제외 규칙·계측 도구와 버전을 기록 |
| 수치 목표 달성에 시험이 편향 | 수치만으로 종료를 자동 승인하지 않고 중요 기능·잔여 위험 검토 |
| 고위험 기능의 충분한 시험 기준이 불명확 | 안전·업무 위험과 적용 표준·계약 요구에 맞춰 기준을 선택 |

## Ⅵ. 기술사적 제언

| 구분 | 제언 |
|---|---|
| 한계 | 하나의 커버리지 비율은 요구사항 누락, 실행 공백, 시험 결과의 타당성을 모두 나타내지 못함 |
| 해결 방안 | 요구사항 추적, 구조적 커버리지, 기대 결과 확인을 위험 기반 완료 검토에서 함께 판단 |
