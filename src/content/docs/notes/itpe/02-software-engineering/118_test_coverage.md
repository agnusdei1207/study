## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 테스트·검증 → **테스트 커버리지(Test Coverage)**

## 30초 인출

- 본질: 테스트 커버리지는 테스트가 코드나 요구사항의 어느 부분을 실행·검증했는지를 비율로 나타낸 테스트 충분성 지표
- 메커니즘: 코드를 계측해 테스트 실행 중 지나간 문장·분기·조건을 기록하고 전체 대비 실행 비율을 구문·결정·조건·MC/DC 기준으로 산출
- 통찰: 커버리지 수치 자체를 목표로 삼으면 검증이 약한 테스트로 수치만 채우므로 코드 위험도별로 요구 기준을 정하고 검증 강도는 뮤테이션 점수와 리뷰로 확인

<details>
<summary>핵심 용어</summary>

- **테스트 커버리지(Test Coverage)** : 테스트가 대상의 어느 부분을 실행·검증했는지 나타낸 비율
- **구문 커버리지(Statement Coverage)** : 실행된 문장의 비율
- **결정(분기) 커버리지(Decision Coverage)** : 조건문의 참·거짓 분기가 실행된 비율
- **조건 커버리지(Condition Coverage)** : 각 개별 조건의 참·거짓이 실행된 비율
- **MC/DC** : 각 조건이 다른 조건을 고정한 상태에서 결과를 독립적으로 바꾸는지 확인하는 기준
- **계측(Instrumentation)** : 실행 경로 기록을 위해 코드에 측정 코드를 넣는 것

</details>

## 2~4교시 25점 답안

## Ⅰ. 테스트 커버리지의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **테스트 커버리지** 는 테스트가 코드나 요구사항의 어느 부분을 실행했는지 비율로 나타낸 지표 |
| 목적 | 테스트 충분성의 정량적 판단과 미실행 영역 식별 |

## Ⅱ. 테스트 커버리지의 특징

| 특징 | 의미 |
|---|---|
| 정량 지표 | 비율로 충분성 표현 |
| 미실행 식별 | 테스트되지 않은 코드 발견 |
| 검증 강도 미반영 | 실행 여부만 측정, 결과 검증 여부는 별도 |

## Ⅲ. 커버리지 측정 절차

### 측정 절차

```text
코드 계측(측정 코드 삽입)
    ↓
테스트 실행 → 실행 경로 기록
    ↓
커버리지 산출 → 미실행 코드 확인
    ↓
케이스 추가 → 재측정
```

### 확대: 결정 커버리지 계산

```text
분기 8개 중 6개 실행 → 결정 커버리지 75%
미실행 분기 2개 → 해당 분기 실행 케이스 추가
```

## Ⅳ. 커버리지 기준의 비교

| 기준 | 판정 | 특징 |
|---|---|---|
| 구문 | 모든 문장 실행 | 가장 약함 |
| 결정 | 모든 분기의 참·거짓 실행 | 구문보다 강함 |
| 조건 | 각 조건의 참·거짓 실행 | 결정 결과 무관 가능 |
| 조건/결정 | 조건과 결정 함께 | 조건 간 영향 미확인 |
| MC/DC | 각 조건의 독립 영향 | 안전 요구 코드에 적용 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 100% 커버리지여도 결함 부재 미보장 | 결과 검증 강도를 뮤테이션 테스트로 확인 |
| 수치 채우기용 테스트 작성 | 위험도별 목표 설정과 테스트 리뷰 |
| 요구사항 대비 커버리지 미측정 | 요구사항 추적표로 요구 커버리지 병행 |

## Ⅵ. 제언

코드 위험도별로 커버리지 기준을 정하고, 수치와 함께 검증 강도를 뮤테이션 점수와 리뷰로 확인

### 위험도별 기준

```text
안전·핵심 코드 → MC/DC·높은 목표
일반 코드 → 결정 커버리지·중간 목표
```

### 확대: 판정

```text
커버리지 목표 충족
    ├─ 검증 강도 확인(뮤테이션·리뷰) 통과 → 인정
    └─ 미통과 → 테스트 보강
```

### 선택 근거: 단일 수치 목표와의 비교

| 구분 | 전 코드 동일 수치 | 제언: 위험도별 기준 |
|---|---|---|
| 자원 배분 | 비효율 | 위험 영역 집중 |
| 검증 강도 | 확인 불가 | 뮤테이션·리뷰 |
| 수치 왜곡 | 발생 | 완화 |
