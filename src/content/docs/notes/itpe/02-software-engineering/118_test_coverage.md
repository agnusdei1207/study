## 연관 키워드

- Test Coverage, 테스트 커버리지, 테스트 충실도 메트릭
- 구문 커버리지(Statement Coverage), 결정 커버리지(Decision/Branch Coverage)
- MC/DC(Modified Condition/Decision Coverage), 전 경로 커버리지(All-Path)
- ISO/IEC/IEEE 29119, DO-178C
- 뮤테이션 점수(Mutation Score), 커버리지 래칫(Coverage Ratchet)

## Ⅰ. 테스트 커버리지의 개요

- 핵심 요약 : 테스트가 코드 구조와 요구사항을 얼마나 실행하고 검증했는지를 백분율로 나타내는 테스트 충실도 메트릭.
- 개념 : 테스트 케이스 집합이 소스코드의 문장, 분기, 조건, 경로 같은 구조적 요소를 실행한 비율을 백분율(%)로 나타내는 **테스트 커버리지** (Test Coverage).
- 배경 및 필요성 : 테스트를 얼마나 충실히 했는지 객관적으로 판단할 척도가 없고, 실행되지 않은 영역이 사각지대로 남기 쉬워 이를 드러낼 기준이 필요.
- 주요 목적 : 테스트 충실도의 정량 평가, 사각지대 제거, 품질 게이트 기준 제공.
- 표준 체계 : 소프트웨어 테스트 국제 표준인 ISO/IEC/IEEE 29119(ISO, International Organization for Standardization / IEC, International Electrotechnical Commission / IEEE, Institute of Electrical and Electronics Engineers 공동 표준)와 항공 소프트웨어 표준 DO-178C.

## Ⅱ. 테스트 커버리지의 특징 및 장점

- 핵심 요약 : 구문에서 MC/DC까지 이어지는 구조적 커버리지 계층과, 백분율 기반의 정량 관리가 결합된 메트릭.

1. **구문 커버리지** (Statement Coverage) : 모든 실행 문장이 최소 1회 실행되었는지 측정(실행된 문장 수 ÷ 전체 문장 수 × 100%) → 실행되지 않은 코드 식별.
2. **결정 커버리지** (Decision/Branch Coverage) : 조건식 전체가 참과 거짓이 되는 분기를 각각 1회 이상 실행 → 분기 누락 식별.
3. **조건 커버리지** (Condition Coverage) : 복합 조건 안의 개별 조건이 참과 거짓 값을 각각 가지도록 실행 → 조건 단위의 검증.
4. **MC/DC** (Modified Condition/Decision Coverage) : 각 개별 조건이 다른 조건과 무관하게 결정 결과를 바꿀 수 있음을 입증 → 항공과 자동차 등 고신뢰 분야에서 요구.
5. 정량화 척도 : 백분율 기반 측정이라 품질 게이트 기준과 목표 관리에 바로 연결.

## Ⅲ. 테스트 커버리지의 구조 (흐름)

- 핵심 요약 : 구문에서 다중 조건으로 올라갈수록 검증 강도와 필요한 테스트 케이스 수가 함께 커지는 계층 구조.

```text
[ 커버리지 강도 계층 ]

       [ 다중 조건 커버리지 ]
         조건 조합 전부 실행 (2^N)
                ↑
       [ MC/DC ]
         조건별 독립 영향 입증 (최소 N+1)
                ↑
       [ 조건·결정 커버리지 ]
         개별 조건과 결정의 참·거짓
                ↑
       [ 분기 커버리지 ]
         조건문의 True·False 분기 실행
                ↑
       [ 구문 커버리지 ]
         모든 실행 문장 1회 실행
```

- CI 커버리지 측정 흐름 : 테스트 실행으로 계측된 결과가 품질 게이트에서 병합 여부를 결정한다.

```text
[ CI 커버리지 측정 흐름 ]

[ 테스트 실행 ]
  소스 코드 + 테스트 코드
      ↓
[ 계측 에이전트 (JaCoCo) ]
  라인·분기 실행 정보 수집
      ↓
[ 품질 게이트 (SonarQube) ]
  목표 미달 시 병합 차단
```

## Ⅳ. 주요 테스트 커버리지 유형의 비교

- 핵심 요약 : 검증 기준과 필요한 케이스 수, 적용 분야에 따라 커버리지 강도가 달라짐.

| 커버리지 유형 | 검증 기준 | 필요 케이스 수 | 주요 적용 분야 |
| --- | --- | --- | --- |
| 구문 커버리지 | 모든 실행 문장 1회 이상 실행 | 가장 적음 | 일반 상용 소프트웨어의 기본 기준 |
| 결정 커버리지 | 모든 분기 경로 1회 이상 실행 | 적음 | 일반 업무 시스템 |
| 조건 커버리지 | 개별 조건의 참과 거짓 각 1회 이상 | 적음 | 모듈 내부의 세부 조건 검증 |
| MC/DC 커버리지 | 개별 조건의 독립적 영향 입증 | 조건 수 N에 대해 최소 N+1 | 항공(DO-178C Level A), 자동차(ISO 26262 ASIL(Automotive Safety Integrity Level) D) |
| 전 경로 커버리지 | 실행 가능한 모든 경로 실행 | 조합 폭발(2^N 초과 가능) | 반복문이 없는 소형 고신뢰 알고리즘 |

- 선택 기준 : 결함의 비용이 낮은 일반 시스템은 구문이나 분기 커버리지, 결함이 인명과 직결되는 시스템은 MC/DC 이상을 적용.

## Ⅴ. 테스트 커버리지의 한계와 방안

- 핵심 요약 : 충실도의 정량화와 사각지대 식별이 장점이며, 허위 안도감, 무의미한 테스트 양산, 측정 사각지대가 한계.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 구문 커버리지의 허위 안도감 | 100% 문장 커버리지에도 경계값 오류, 예외 처리 누락을 잡지 못함 | 분기와 MC/DC를 병행 측정, **뮤테이션 점수** (Mutation Score)로 테스트의 결함 검출력 검증 | 뮤테이션 점수 |
| 단언 없는 테스트 양산 | 수치 달성을 위해 assert 없이 메서드만 호출하는 테스트가 늘어 유지보수 부담 증가 | 정적 분석 도구로 단언 검출 규칙 적용, 위험도 기반 테스트 우선순위 평가 | 단언 없는 테스트 비율 |
| 비동기와 분산 구간의 측정 한계 | 분산 서비스의 비동기 메시지와 외부 API 호출은 일반 커버리지 에이전트로 추적 불가 | 분산 추적(Distributed Tracing) 기반 시나리오 커버리지 측정, 컨트랙트 테스트(Pact)로 서비스 경계 보완 | 시나리오 커버리지율 |

## Ⅵ. 테스트 커버리지에 대한 기술사적 제언

- 핵심 요약 : 전체 평균 대신 변경 코드의 기준을 세우고, 커버리지가 후퇴하지 않도록 래칫 정책으로 고정하는 것이 필요.
- 기존 코드 전체의 커버리지 목표를 한꺼번에 높이려 하기보다, 이번에 바뀐 코드의 분기 커버리지를 목표로 정하면 기존 부채에 막히지 않고 개선 속도를 유지할 수 있다.
- 신규와 수정 코드가 기준에 미달하면 병합을 막고, 기준선 자체는 낮아지지 않도록 고정하는 **커버리지 래칫** (Coverage Ratchet) 정책을 빌드 파이프라인에 적용해야 한다.
- 고신뢰 분야에서는 ISO/IEC/IEEE 29119와 DO-178C가 요구하는 수준에 맞춰 커버리지 유형을 나누어 적용하고, 측정 결과를 감사 자료로 보관하는 절차를 함께 마련해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 테스트 커버리지는 테스트 충실도를 재는 표준 척도이나, 결함을 찾아내는 능력은 별도로 검증해야 함.
- 시사점 : 계층별 커버리지 선택, 뮤테이션 검증, 품질 게이트 연동을 함께 운영해야 수치 관리의 한계를 보완할 수 있음.
