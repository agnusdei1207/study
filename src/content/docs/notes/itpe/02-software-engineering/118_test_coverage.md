## 답안 골격
```text
[테스트 커버리지] ◀━━ 머리: Ⅶ 내 의견 (요구사항-코드 다차원 커버리지 통합 대시보드 구축과 테스트 완료 기준(Exit Criteria) 정량화)
 ┃
 ┣━ Ⅰ 개요 ───── 테스트 활동의 충분성 판단 부재로 인한 배포 불안 → 명세와 구현물 대비 테스트가 수행된 영역의 정량적 달성도
 ┣━ Ⅱ 특징 ───── 다차원 측정(기능, 구조, 리스크) · 테스트 완료 조건(Exit Criteria) 지표 · 테스트 결함 검출력과 상관관계
 ┣━ Ⅲ 구조 ───── 기능 커버리지(요구사항 추적) / 구조적 커버리지(코드, 분기) / 인터페이스 커버리지(API, 통신)
 ┣━ Ⅳ 흐름 ───── 테스트 대상 분석 → 기준 수립(목표치 설정) → 테스트 실행 및 계측 → 결과 분석 → 미달 구간 보완 테스트
 ┣━ Ⅴ 비교 ───── 기능 커버리지(명세 기반, 블랙박스) vs 구조적 코드 커버리지(구현 기반, 화이트박스)
 ┗━ Ⅵ 실무 ───── 테스트 불균형(일부 기능 과잉/일부 누락) / 커버리지와 결함률의 괴리 / 릴리스 승인 게이트 연계
```

## 한 줄 본질
- "테스트를 언제 멈춰야 하는가"에 대한 객관적 종료 기준 부재 병목 → 요구사항 명세 및 소스코드 구조를 기준으로 테스트 케이스가 커버한 범위를 백분율로 정량화하는 품질 평가 지표 / 100% 달성 집착 시 테스트 비용 급증

## 핵심 용어
- 테스트 완료 기준(Exit Criteria): 프로젝트 계획서에 정의된 품질 목표로, 일정 수준의 기능 커버리지와 코드 커버리지를 달성해야 테스트를 공식 종료하는 기준
- RTM(Requirements Traceability Matrix): 비즈니스 요구사항과 이를 검증하는 테스트 케이스를 1:1로 매핑하여 누락된 기능이 없는지 입증하는 추적 매트릭스

## 핵심 통찰
- 테스트 커버리지는 단순히 "코드 커버리지"만을 의미하지 않으며, 요구사항 대비 검증률(기능 커버리지)과 시스템 인터페이스 호출률을 포괄하는 상위 개념임
- 코드 커버리지가 100%여도 사용자가 요구한 기능 자체가 누락(Omission 결함)되었다면 코드가 아예 없으므로 코드 커버리지 도구로는 탐지 불가함
- 프로젝트 후반부에는 "커버리지 1% 상승을 위해 투입되는 테스트 비용"이 기하급수적으로 증가하므로, 위험도 기반 테스팅(RBT)과 연계하여 고위험 모듈에 커버리지 목표를 차등 부여해야 함

## 이웃 토픽과 구분
- 테스트 커버리지(범위) vs 테스트 효과성(결함 검출력): 커버리지 = 얼마나 많은 영역을 찔러보았는가(양적 지표) / 효과성 = 그 테스트가 실제 결함을 얼마나 잘 잡아내는가(질적 지표)

## 문제·원인·대책
- 적용 상황: 차세대 이커머스 결제/정산 시스템 오픈 전 테스트 완료 판정
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 단위 테스트 코드 커버리지는 85%였으나 오픈 첫날 미구현 요구사항 발생 | 소스코드 계측에만 의존하여 요구사항 명세 대비 테스트 누락(기능 커버리지 결여) | 요구사항 추적표(RTM) 기반 기능 커버리지 100% 달성을 인수 조건으로 지정 | 요구사항 누락 결함 원천 차단 |
| 테스트 종료 일정을 맞추기 위해 커버리지 목표를 충족하지 못한 채 졸속 배포 | 모듈별 동일한 커버리지 기준(일괄 80%)을 적용하여 저위험 모듈에 시간 낭비 | 리스크 기반 테스팅(RBT) 적용하여 결제 핵심 모듈 90%, 단순 조회 모듈 50% 차등화 | 핵심 비즈니스 리스크 집중 방어 및 납기 준수 |

## 이렇게 출제된다
- 제127회 1교시: "테스트 커버리지(Test Coverage)의 개념과 측정 관점 및 활용 방안을 설명하시오." → 요구 포인트: 테스트 커버리지 정의 + 다차원 측정 관점(기능, 구조, 환경) + 테스트 종료 기준 활용

## 내 의견
- [코드 커버리지에만 편향된 형식적 품질 관리 지양] 개발팀이 단위 테스트 라인 커버리지 달성에만 매몰되어 사용자 시나리오 및 통합 API 연계 검증을 등한시하는 문제 발생 → 나라면: CI 파이프라인에서 SonarQube(코드 커버리지)와 Jira/Zephyr(요구사항 추적 커버리지)를 통합하여, 기능 검증과 구조 검증이 동시에 임계치를 통과해야만 프로덕션 배포가 승인되는 통합 품질 게이트(Quality Gate) 구축
