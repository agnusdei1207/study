## 연관 키워드

- 스크럼(Scrum), 애자일(Agile), 스프린트(Sprint), 증분(Increment), 경험주의 3기둥
- 제품 책임자(Product Owner), 스크럼 마스터(Scrum Master), 제품 백로그, 완료의 정의(DoD), 벨로시티(Velocity)

## Ⅰ. 스크럼의 개요

- 핵심 요약 : 짧은 반복 주기(스프린트)를 통해 동작 가능한 소프트웨어 증분을 점진적으로 릴리스하는 대표적 애자일 프레임워크.
- 개념 : 요구사항이 불확실하고 빠르게 변화하는 비즈니스 환경에서, 크로스 펑셔널 팀이 1~4주의 짧은 반복 주기(Sprint)를 통해 동작 가능한 소프트웨어 증분(Increment)을 점진적으로 릴리스하는 대표적인 애자일(Agile) 프로젝트 관리 프레임워크.
- 배경 및 필요성 : 전통적 폭포수 모델의 긴 피드백 주기, 요구사항 변경에 따른 납기 지연, 최종 단계 인도 실패 리스크를 극복하고 빠른 시장 검증(Time-to-Market) 달성 필요.
- 주요 목적 : 투명성(Transparency), 점검(Inspection), 적응(Adaptation)의 경험주의 3대 기둥에 기반한 불확실성 관리 체계 구축.

## Ⅱ. 스크럼의 특징 (3-5-3 체계)

- 핵심 요약 : 3가지 역할, 5가지 이벤트, 3가지 산출물로 구성되는 3-5-3 체계.
1. 3가지 역할(Role) :
   - 제품 책임자(Product Owner) : 비즈니스 가치 극대화, 제품 백로그(Product Backlog) 우선순위 결정 및 관리.
   - 스크럼 마스터(Scrum Master) : 스크럼 원칙 수호, 팀의 장애물(Impediment) 제거 및 코칭.
   - 개발팀(Developers) : 교차 기능적이고 자기 조직화(Self-Organizing)된 다기능 개발 전문가 집단.
2. 5가지 이벤트(Event) :
   - 스프린트(Sprint) : 1~4주 고정 반복 주기.
   - 스프린트 계획(Planning) : 스프린트 목표 및 스프린트 백로그 도출.
   - 일일 스크럼(Daily Scrum) : 15분 스탠드업 미팅.
   - 스프린트 리뷰(Review) : 증분 데모 및 피드백.
   - 스프린트 회고(Retrospective) : 프로세스 지속 개선 도출.
3. 3가지 산출물(Artifact) :
   - 제품 백로그(Product Backlog) : 우선순위가 정렬된 요구사항 목록.
   - 스프린트 백로그(Sprint Backlog) : 스프린트 수행 작업 목록.
   - 증분(Increment) : 완료 정의(DoD, Definition of Done)를 충족한 인도 가능 제품.
4. 경험주의 3대 기둥 : 투명성(Transparency)·점검(Inspection)·적응(Adaptation)의 순환.
5. 자기 조직화(Self-Organizing) : 지시 기반이 아닌 팀 주도의 작업 분배 및 의사결정.

## Ⅲ. 스크럼의 구조 (흐름)

- 핵심 요약 : 제품 백로그에서 증분 릴리스까지의 스프린트 반복 흐름과 3-5-3 체계.

```text
[ 스프린트 반복 흐름 ]
[ 제품 백로그 ] (제품 책임자 관리)
   │
   ▼
[ 스프린트 계획회의 ]
   - 스프린트 백로그 도출
   │
   ▼
[ 스프린트 실행 (1~4주) ]
   - 일일 스크럼 (15분)
   │
   ▼
[ 완료된 증분 ] : 완료 정의(DoD) 충족
   │
   ▼
[ 스프린트 리뷰 (데모) ]
   │
   ▼
[ 스프린트 회고 (KPT) ]
```

```text
[ 스크럼 3-5-3 체계 ]
[ 역할 3 ]  제품 책임자 / 스크럼 마스터 / 개발팀
[ 이벤트 5 ]  스프린트 → 스프린트 계획 → 일일 스크럼
              → 스프린트 리뷰 → 스프린트 회고
[ 산출물 3 ]  제품 백로그 / 스프린트 백로그 / 증분
```

## Ⅳ. 스크럼 핵심 운영 메커니즘의 비교

- 핵심 요약 : 백로그 관리·일일 스크럼·완료의 정의·회고 각각의 성과 기준과 실패 증상의 구분.

| 구성요소 | 핵심 활동 및 성과 기준 | 실패 시 증상 |
|---|---|---|
| 제품 백로그 관리 | DEEP 원칙(Detailed, Estimated, Emergent, Prioritized) 준수 | 요구사항 우선순위 혼선, 일정 지연 |
| 일일 스크럼 | 15분 스탠드업 미팅: 어제 한 일, 오늘 할 일, 장애 요인 공유 | 단순 보고 자리로 변질, 시간 지연 |
| 완료의 정의(DoD, Definition of Done) | 빌드, 단위/통합 테스트, 정적 분석, 코드 리뷰, 배포 완료 기준 | 품질 미달 증분 릴리스, 회귀 버그 폭증 |
| 스프린트 회고 | Keep, Problem, Try(KPT) 관점의 프로세스 지속 개선 도출 | 팀 내부 불만 누적, 엔지니어링 성숙도 정체 |

## Ⅴ. 스크럼의 장점과 한계

- 핵심 요약 : 빠른 피드백·변경 수용의 장점, 지표 오용·PO 병목·세레머니 형식화의 한계.
- 장점
  1. 짧은 피드백 주기를 통한 요구사항 변경의 신속한 수용.
  2. 동작 가능한 증분의 점진 릴리스로 조기 가치 인도.
  3. 투명성 기반의 이해관계자 신뢰 및 리스크 조기 발견.
- 한계점 1 : 스토리 포인트의 개인 성과 지표 악용과 포인트 인플레이션
  - 한계점 : 팀의 작업 추정 도구인 스토리 포인트와 스프린트 속도(Velocity)를 경영진이 생산성 평가 지표로 오용함에 따라 점수 부풀리기 및 기술 부채 방치 초래.
  - 해결 방안 : 벨로시티의 팀 용량 산정(Capacity Planning) 용도 한정 및 조직 KPI(Key Performance Indicator) 배제, 번다운 차트 대신 리드타임/사이클타임 등 흐름(Flow) 메트릭 정착.
- 한계점 2 : 제품 책임자(PO, Product Owner)의 역량 부족 및 의사결정 병목(SPOF, Single Point of Failure)
  - 한계점 : PO가 비즈니스 전결권을 위임받지 못했거나 도메인 이해도가 부족하여 요구사항 정의 지연 및 개발팀 문의의 부적시 대응으로 스프린트 목표 달성 실패.
  - 해결 방안 : 실질적 의사결정 권한을 가진 전임 PO 임명, INVEST(Independent, Negotiable, Valuable, Estimable, Small, Testable) 원칙 기반 백로그 정제(Refinement) 세션 정례화, 제품 목표(Product Goal)와 스프린트 목표의 명확한 정렬.
- 한계점 3 : 스크럼 세레머니의 형식화 및 개발 집중도 저하
  - 한계점 : 데일리 스탠드업, 스프린트 계획, 리뷰, 회고 등이 형식적이고 장황한 보고 회의로 변질되어 개발자의 몰입 시간(Deep Work) 침해 및 회의 피로도 누적.
  - 해결 방안 : 데일리 스크럼 15분 타임박싱 엄수, 비동기 스탠드업 도구(Slack/Teams 봇) 혼용, 스크럼 마스터의 장애물 제거 중심 서번트 리더십(Servant Leadership) 강화.

## Ⅵ. 대규모 엔터프라이즈 환경에서의 기술사적 제언

- 핵심 요약 : 대규모 애자일 프레임워크 스케일업과 지표 맹신 방지·심리적 안전감 확보.
- 대규모 애자일(SAFe(Scaled Agile Framework), LeSS(Large-Scale Scrum)) 프레임워크로의 스케일업 : 여러 스크럼 팀이 동시에 참여하는 대형 공공/금융 차세대 사업에서 팀 간 의존성 조율을 위한 Scrum of Scrums, ART(Agile Release Train) 체계 구축 필수.
- 지표 맹신 방지와 심리적 안전감(Psychological Safety) 확보 : 스토리 포인트(Story Point)나 속도(Velocity)를 팀 간 실적 평가 지표로 오용하지 않고, 지속 가능한 개발 속도 유지와 자유로운 실패 공유 문화 정착이 핵심.
- 엔지니어링 실천의 병행 : DoD에 정적 분석·자동화 테스트·CI/CD 파이프라인을 포함하여 프로세스 프레임워크와 기술 품질 기준의 동시 확보.

## Ⅶ. 결론

- 핵심 요약 : 스크럼은 경험주의에 기반한 반복적 가치 인도의 애자일 프레임워크.
- 요약 : 3-5-3 체계와 완료의 정의(DoD)를 통한 품질 있는 증분의 점진적 릴리스.
- 시사점 : 지표의 목적(추정과 용량 산정) 준수와 세레머니의 실질화가 스크럼 성숙도의 핵심.
