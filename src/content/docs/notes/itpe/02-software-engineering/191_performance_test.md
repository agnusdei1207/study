## 연관 키워드

- 성능 테스트, 부하 테스트, 스트레스 테스트, 지구력 테스트, 지연시간 백분위

## Ⅰ. 성능 테스트의 개요

- 핵심 요약 : 성능 테스트는 정의된 부하 조건에서 응답시간·처리량·자원 사용과 확장 한계를 평가.
- 개념 : **성능 테스트**(Performance Testing)는 대표적인 사용자 부하와 데이터 조건에서 비기능 성능 요구를 측정하고 병목을 진단하는 검증 활동.
- 배경 및 필요성 : 기능이 맞아도 동시 사용자와 데이터가 증가하면 지연·오류·자원 포화로 서비스 품질이 악화 가능.
- 주요 목적 : 용량 적합성, 성능 목표 충족, 확장·장애 위험에 관한 배포 의사결정 근거 확보.

## Ⅱ. 유형과 측정 지표

- 핵심 요약 : 시험 목적에 맞게 부하 프로파일과 지속 시간을 정하고 사용자 체감·시스템 자원을 함께 관찰.
- 부하 테스트 : 예상 운영 부하에서 요구 성능 확인 → 일반 용량 적합성 평가.
- 스트레스 테스트 : 한계를 넘겨 포화·복구 특성 확인 → 실패 지점과 graceful degradation 파악.
- 스파이크 테스트 : 급격한 부하 변동 평가 → 자동 확장·큐 적체 확인.
- 지구력 테스트 : 장시간 실행 → 메모리 누수·자원 고갈 탐지.
- 주요 지표 : 응답시간 분포, 처리량, 오류율, CPU·메모리·DB 커넥션, 큐 길이.

## Ⅲ. 시험 설계 및 수행 흐름

- 핵심 요약 : 요구량과 사용자 행동을 모델링해 기준선·부하·관측·분석·재시험을 반복.

```text
성능 SLO·대표 업무 선정
  ↓ 부하·데이터·환경 모델링
기준선 측정
  ↓ 단계 부하 실행·모니터링
병목 분석·개선
  ↓ 동일 조건 재시험·승인
```

```text
가상 사용자 증가 → 요청률 상승
  ↓
응답시간·오류율·자원 포화 관측
  ↓
병목: 앱 / DB / 네트워크 / 외부 의존성
```

- 테스트 데이터 분포와 캐시 상태, 워밍업, 배포 버전, 외부 연계 대체 여부를 기록해 반복성 확보.

## Ⅳ. 성능 시험 유형 비교

- 핵심 요약 : 요구 성능 확인·한계 탐색·급변 대응·장기 안정성에 따라 시험 유형을 구분.

| 유형 | 부하 패턴 | 핵심 질문 |
| --- | --- | --- |
| 부하 | 예상 운영 수준 | 목표 응답·처리량을 만족하는가 |
| 스트레스 | 한계까지 단계 증가 | 포화 시 어떻게 실패하고 회복하는가 |
| 스파이크 | 급격한 상승·하락 | 급변 부하를 흡수하는가 |
| 지구력 | 일정 부하 장시간 | 누수·누적 자원 고갈이 있는가 |
| 용량 | 목표 지표를 유지하는 최대량 | 안전한 운영 용량은 얼마인가 |

## Ⅴ. 한계와 방안

- 핵심 요약 : 비현실적인 부하와 환경 차이, 평균 중심 해석은 현장 성능을 잘못 예측할 수 있음.

| 한계 | 원인·영향 | 대응 방안 |
| --- | --- | --- |
| 부하 모델 부정확 | 실제 사용 경로·데이터 분포와 차이 | 운영 로그 기반 시나리오·분포 구성 |
| 테스트 환경 차이 | 자원·네트워크·구성 불일치 | 차이 기록·환경 대표성 개선 |
| 평균 응답시간 착시 | 느린 요청 꼬리 숨김 | p95·p99와 오류율을 함께 분석 |
| 병목 오진 | 계층별 상관관계 부족 | 분산 추적·프로파일링·자원 지표 연계 |
| 과도한 운영 부하 | 생산 시스템에 부하 유입 | 격리 환경·제한된 시험 창·중단 조건 |

## Ⅵ. 성능 관리 제언

- 핵심 요약 : 서비스 책임자는 성능 목표를 업무 중요도와 사용자 여정에 연결하고 배포 전후 지속 관측.
- 성능 엔지니어는 성능 예산과 대표 시나리오를 유지하며 임계치 초과 시 원인 계층을 식별할 수 있는 관측성을 확보.
- 운영팀은 용량 예측과 피크 대비를 수행하고 실험 조건·결과·수정사항을 버전별로 기록.

## Ⅶ. 결론

- 핵심 요약 : 성능 테스트는 시스템의 부하 적합성과 포화·복구 특성을 수치와 관측 증거로 확인하는 검증 활동.
- 대표적인 실제 부하, 꼬리 지연, 자원 포화를 함께 평가해야 용량과 사용자 경험을 신뢰성 있게 판단.
