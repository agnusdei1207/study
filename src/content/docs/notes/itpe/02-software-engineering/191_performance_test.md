## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 테스트·검증 → **성능 테스트(Performance Test)**

## 30초 인출

- 본질: 성능 테스트는 부하를 가해 시스템의 응답 시간·처리량·자원 사용이 성능 요구를 만족하는지 확인하는 테스트
- 메커니즘: 부하 형태(정상·한계 초과·순간 폭증·장시간)를 달리해 가상 사용자를 발생시키고 응답시간·TPS·자원 사용을 측정해 병목을 찾음
- 통찰: 부하 형태마다 드러나는 문제가 달라 한 가지 시험만으로는 놓치므로 요구 성능에 맞는 부하 프로파일을 정해 여러 형태로 시험

<details>
<summary>핵심 용어</summary>

- **성능 테스트(Performance Test)** : 부하 상태에서 성능을 측정하는 테스트
- **부하 테스트(Load Test)** : 예상 사용자 수 수준의 부하에서 성능 확인
- **스트레스 테스트(Stress Test)** : 한계를 넘는 부하를 가해 한계와 회복을 확인
- **스파이크 테스트(Spike Test)** : 순간적으로 폭증하는 부하에서의 반응 확인
- **내구성 테스트(Endurance Test)** : 장시간 부하에서 메모리 누수 등을 확인
- **TPS** : 초당 처리 트랜잭션 수

</details>

## 2~4교시 25점 답안

## Ⅰ. 성능 테스트의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **성능 테스트** 는 부하를 가해 시스템의 성능이 요구를 만족하는지 확인하는 테스트 |
| 목적 | 성능 병목의 사전 발견과 용량 판단 |

## Ⅱ. 기능 테스트와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 부하 기반 | 가상 사용자로 부하 발생 |
| 지표 측정 | 응답시간·TPS·자원 사용률 |
| 운영 유사 환경 | 결과 신뢰를 위한 환경 |

## Ⅲ. 부하 형태별 유형

```text
부하
 │        ┌─ 스파이크(순간 폭증)
 │   ╱‾‾‾‾╲          스트레스(한계 초과) ╱
 │  ╱      ╲___     ╱
 │ ────────────  부하 테스트(예상 수준 유지)
 │ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ 내구성(장시간 유지)
 └────────────────────────────────── 시간
```

## Ⅳ. 유형별 비교

| 유형 | 부하 | 확인 대상 |
|---|---|---|
| 부하 테스트 | 예상 사용자 수준 | 요구 성능 충족 |
| 스트레스 테스트 | 한계 초과 | 한계점과 장애 후 회복 |
| 스파이크 테스트 | 순간 폭증 | 급증 대응과 회복 시간 |
| 내구성 테스트 | 정상 부하의 장시간 | 메모리 누수·자원 고갈 |
| 확장성 테스트 | 자원 증설 후 부하 | 증설에 따른 성능 증가 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 운영과 다른 환경에서 결과 신뢰 저하 | 운영과 유사한 환경 구성 |
| 부하 형태 하나만 시험해 문제 누락 | 요구에 맞는 여러 부하 프로파일 |
| 병목 원인 파악 곤란 | 응답시간과 자원 지표를 함께 수집 |

## Ⅵ. 제언

성능 요구사항에서 부하 프로파일을 도출해 부하·스파이크·내구성 시험을 조합하고 응답시간과 자원 지표를 함께 수집

```text
성능 요구 → 부하 프로파일 → 유형별 시험 → 병목 분석 → 개선·재시험
```

| 구분 | 단일 부하 시험 | 제언: 유형 조합 |
|---|---|---|
| 문제 발견 | 일부 | 폭넓음 |
| 근거 | 임의 부하 | 요구 기반 |

## 출제 이력과 검증 출처

- 제132~140회 정보관리기술사 공식 문제지에서 성능 테스트를 직접 묻는 문항 없음
- ISO/IEC 25010 성능 효율성
