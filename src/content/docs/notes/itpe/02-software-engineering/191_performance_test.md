소프트웨어공학 → 소프트웨어 테스트 → 비기능 테스트 → **성능 테스트**

## 30초 인출

- **본질**: 성능 테스트는 부하 조건에서 시스템의 응답성과 자원 사용을 측정해 성능 요구 충족 여부를 확인하는 테스트
- **메커니즘**: 목표·부하 조건 정의 → 부하 인가와 측정 → 병목 분석 → 개선 후 재검증

<details>
<summary>핵심 용어</summary>

- **성능 테스트(Performance Testing)**: 지정한 부하에서 응답 시간, 처리량, 자원 사용 등 성능 특성을 평가하는 테스트
- **부하 테스트(Load Testing)**: 예상 사용량 또는 피크 조건에서 성능을 평가하는 유형
- **스트레스 테스트(Stress Testing)**: 예상 범위를 넘는 부하에서 한계와 동작을 살피는 유형
- **내구성 테스트(Endurance Testing)**: 지속 부하에서 장시간 운용 특성을 확인하는 유형
- **스파이크 테스트(Spike Testing)**: 부하가 급격히 변할 때 시스템 반응을 확인하는 유형
- **TPS(Transactions Per Second)**: 초당 처리 트랜잭션 수를 나타내는 처리량 지표

</details>

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **성능 테스트**: 부하 조건에서 시스템의 응답성과 자원 사용을 측정·평가하는 테스트 |
| 목적 | 성능 요구 충족 여부와 병목 구간의 확인 |

### Ⅱ. 주요 측정 관점

| 관점 | 확인 내용 |
|---|---|
| 응답 시간 | 요청부터 응답까지 걸리는 시간과 분포 |
| 처리량 | 단위 시간당 처리한 요청·트랜잭션 수 |
| 자원 사용 | CPU·메모리·저장장치·네트워크 사용 양상 |

### Ⅲ. 유형과 수행 흐름

```text
성능 목표·부하 조건 정의
    ↓
부하 인가·응답 시간·처리량·자원 측정
    ↓
병목 원인 확인
    ↓
개선 후 동일 조건 재시험
```

| 유형 | 핵심 관점 |
|---|---|
| 부하 | 예상 사용량에서의 성능 |
| 스트레스 | 예상 범위를 넘는 부하에서의 한계 |
| 내구성 | 지속 부하에서의 장시간 동작 |
| 스파이크 | 급격한 부하 변화에 대한 반응 |

**제언**: 사용자 업무에서 중요한 응답 목표와 대표 부하 조건을 먼저 합의해 시험 기준으로 고정.

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **성능 테스트**: 부하 조건에서 시스템의 응답성과 자원 사용을 측정·평가하는 테스트 |
| 목적 | 성능 요구 충족 여부와 병목 구간의 확인 |

## Ⅱ. 성능 평가 관점

성능 목표는 시스템의 사용 맥락에 맞춰 응답 시간, 처리량, 자원 사용량으로 표현. 평균만으로 지연을 대표하기 어려운 경우 백분위 지표와 시험 구간을 함께 정의.

| 지표 | 해석 |
|---|---|
| 응답 시간 | 사용자 요청의 처리 지연 |
| 처리량 | 일정 시간 동안 완료한 작업량 |
| 자원 사용률 | 처리 중 사용한 계산·저장·통신 자원 |

## Ⅲ. 시험 유형과 선택

| 유형 | 시험 조건 | 확인 목적 |
|---|---|---|
| 부하 | 예상 업무량·피크 사용량 | 요구 수준에서의 성능 |
| 스트레스 | 정상 범위를 넘는 부하 | 한계와 과부하 시 동작 |
| 내구성 | 지속적인 부하 | 장시간 운용 중 성능 변화 |
| 스파이크 | 짧은 시간의 급격한 부하 변화 | 급증·급감에 대한 반응 |

## Ⅳ. 수행 절차와 분석

```text
요구·업무 시나리오 정의
    ↓
부하 모델·시험 환경 준비
    ↓
응답 시간·처리량·자원 사용량 측정
    ↓
기준 비교·병목 분석
    ↓
개선 후 동일 조건 재시험
    ↓
요구 충족·잔여 위험 판단
```

- **준비**: 업무 시나리오, 동시 사용자·요청 패턴, 시험 데이터와 환경 차이를 명시
- **측정**: 부하 발생기와 서버 측 관측을 함께 활용해 클라이언트 한계와 서버 병목을 구분
- **분석**: 느린 요청을 애플리케이션·데이터베이스·외부 연계·인프라 관점으로 추적
- **재검증**: 개선 전후 조건을 맞춰 효과와 부작용을 비교

## Ⅴ. 결과 해석과 활용

```text
시험 결과
  ├─ 요구 충족 → 기준선·운영 관측 항목에 반영
  └─ 요구 미충족 → 병목 분석 → 수정·재시험
```

시험 결과는 해당 환경과 부하 조건에서 얻은 증거로 해석. 운영 성능을 보장하는 절대값으로 일반화하지 않고, 환경·데이터·시나리오 차이를 기록.

## Ⅵ. 문제와 해결 방안

| 한계 | 해결 방안 |
|---|---|
| 시험 부하가 실제 업무를 대표하지 못함 | 업무 로그·사용자 여정에서 시나리오와 부하 분포를 도출 |
| 부하 발생기나 시험망이 먼저 한계에 도달 | 발생기·망의 자원 사용을 함께 관측하고 시험 용량 확인 |
| 평균 지표가 일부 사용자 지연을 가림 | 응답 시간 분포와 상위 백분위, 오류율을 함께 검토 |

## Ⅶ. 기술적 제언

| 구분 | 내용 |
|---|---|
| 한계 | 배포 판단이 단일 시험 수치에 의존하면 환경 차이와 업무별 중요도가 드러나지 않는 한계 |
| 해결 방안 | 업무 중요도별 성능 목표·대표 시나리오·운영 관측 항목을 연결한 기준선을 관리하고 변경 시 동일 조건으로 비교 |
