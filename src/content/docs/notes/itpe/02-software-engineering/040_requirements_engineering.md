## 연관 키워드
- 요구공학, 도출·분석·명세·검증, 기능·비기능 요구, RTM, CCB

### Ⅰ. 요구공학의 개요

- 핵심 요약 : 요구공학은 이해관계자의 필요를 분석·명세·검증·관리해 시스템 요구로 합의하는 전 과정.
- 개념 : 요구를 발견하고 우선순위·충돌·실현성을 분석해 추적 가능한 명세와 변경관리로 통제(**요구공학**, Requirements Engineering).
- 배경 및 필요성 : 모호·상충·변경 요구가 설계오류·재작업·수용분쟁으로 이어짐.
- 주요 목적 : 구현·시험 가능한 요구와 이해관계자 합의를 유지.

### Ⅱ. 요구공학의 특징 및 장점

- 핵심 요약 : 도출·분석·명세·검증·관리는 반복되며 요구변경을 기준선·영향분석으로 통제.

1. 이해관계자 중심 : 사용자·운영·보안·법무 관점 수집 → 요구 누락 감소.
2. 명세 품질 : 완전성·일관성·검증가능성·추적성 확보 → 구현·인수 기준 명확.
3. 변경관리 : 우선순위·영향·승인 이력 유지 → 비용·일정·품질 영향 통제.

### Ⅲ. 요구공학의 생명주기 (흐름)

- 핵심 요약 : 도출 → 분석·협상 → 명세·기준선 → 검증·승인 → 변경·추적 관리.

```text
이해관계자·업무맥락
     ↓
요구 도출 → 분류·분석·협상
     ↓             ↺ 충돌·공백 재도출
요구명세·기준선 → 검증·승인 → RTM·변경통제
```

```text
사업목표 → 사용자 요구 → 시스템 요구 → 설계요소 → 테스트·인수기준
      └──────────── RTM 양방향 추적 ────────────┘
```

- 산출물 : 요구명세, 우선순위, RTM, 검토·승인기록, 변경요청·영향평가.

### Ⅳ. 기능 요구와 비기능 요구 비교

- 핵심 요약 : 기능요구는 시스템이 제공할 동작, 비기능요구는 품질·제약 조건과 그 측정기준을 규정.

| 비교 축 | 기능 요구 | 비기능 요구 |
|---|---|---|
| 질문 | 무엇을 해야 하는가 | 어떤 수준·제약으로 제공해야 하는가 |
| 예 | 결제 승인·환불 처리 | 응답시간, 가용성, 보안, 접근성 |
| 검증 | 입력·상태·출력 시나리오 | 정량 임계값·환경·측정법 |
| 위험 | 예외·업무규칙 누락 | 모호한 형용사·측정조건 부재 |

### Ⅴ. 요구공학의 한계와 방안

- 핵심 요약 : 모호성·요구변동·추적 단절을 명확한 기준·협상·기준선과 변경영향분석으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 모호한 표현 | 구현·검수 해석차 | 측정가능 수용조건·용어사전 | 모호 요구 수 |
| 상충·변경 요구 | 범위·일정 불안정 | 이해관계자 협상·우선순위·CCB | 변경 빈도 |
| 추적 단절 | 변경 누락·시험 공백 | 요구-설계-시험 RTM 유지·자동 점검 | 추적 완결성 |

### Ⅵ. 요구공학 실행 제언

- 핵심 요약 : 요구 책임자는 요구별 출처·소유자·우선순위·검증방법과 변경승인자를 유지.

1. 제품책임자·현업은 요구의 가치·우선순위와 수용 기준 승인.
2. 분석가는 기능·품질·제약을 분리하고 모호성·충돌·실현성을 기록.
3. 개발·QA는 설계·코드·시험과 RTM을 연결하고 변경 때 영향범위를 재평가.

### Ⅶ. 결론

- 핵심 요약 : 요구공학은 이해관계자 필요를 검증 가능한 시스템 계약으로 만들고 변화 속에서도 추적성을 유지.
- 시사점 : 요구 품질이 설계·시험·인수의 품질과 사업성과를 좌우.
