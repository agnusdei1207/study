## 연관 키워드

- 사용성 평가, 사용성 시험(Usability Testing), ISO 9241-11, 효과성·효율성·만족도
- 사용 맥락, think-aloud, SUS(System Usability Scale), 휴리스틱 평가

## Ⅰ. 사용성 시험의 개요

- 핵심 요약 : 사용성 시험은 대표 사용자의 실제 과업 수행을 관찰·측정해 사용 문제를 발견하는 사용성 평가의 대표 방법.
- 개념 : 지정 사용자·목표·사용 맥락에서 효과성·효율성·만족도를 조사하는 활동이 **사용성 평가**(Usability Evaluation)이며, 대표 사용자의 과업 수행을 관찰·측정하는 **사용성 시험**(Usability Testing)은 그 대표 방법임.
- 배경 및 필요성 : 기능 요구의 충족만으로 업무 완료성·오류 수준·학습 부담이 보장되지 않아 실제 사용자와 맥락을 포함한 검증 필요.
- 주요 목적 : 사용자가 안전하고 부담 없이 목표를 달성하는 경험 확보를 통한 제품 채택·운영 품질 향상.

## Ⅱ. 사용성 시험의 특징 및 장점

- 핵심 요약 : 실제 사용자의 수행을 표준 기준·실제 맥락에서 정성·정량으로 측정하는 구조.

1. 실제 사용자 수행 : 대표 사용자가 정의된 과업을 수행 → 과업 완료율·소요 시간·오류·도움 요청 측정.
2. 표준 기준 측정 : **효과성**(effectiveness, 목표의 정확·완전한 달성)·**효율성**(efficiency, 투입 자원 대비 달성)·**만족도**(satisfaction, 사용 경험의 수용 정도)를 ISO 9241-11(사용성의 국제 표준 정의) 기준으로 측정 → 객관적 개선 판단.
3. 사용 맥락 반영 : 지정된 **사용 맥락**(context of use, 사용자·목표·장비·환경의 조건)에서 평가 → 실제 서비스 환경과 유사한 결과 확보.
4. 정성·정량 결합 : **think-aloud**(과업 수행 중 생각을 말하게 하는 관찰 기법)와 **SUS**(System Usability Scale, 시스템 사용성 척도 설문) 병행 → 문제 원인과 개선 방향 도출.
5. 단계별 운용 : 설계 중 개선용 **형성적 평가**(formative evaluation)와 완성품 판정용 **총괄적 평가**(summative evaluation) 구분 → 조기 발견·출시 판단 지원.

## Ⅲ. 사용성 시험의 구조 (흐름)

- 핵심 요약 : 목표·과업 정의부터 재평가까지 이어지는 절차와, 사용성을 판단하는 세 기준의 측정 구조.

```text
[ 사용성 시험 진행 흐름 ]

평가 목표·과업 정의
   ↓
참여자·환경 준비
   ↓
과업 수행 관찰·기록
   ↓
문제 심각도 분류
   ↓
설계 개선
   ↓
재평가
```

```text
[ 사용성 세 기준(ISO 9241-11) ]

효과성 : 목표 과업의 정확·완전한 달성
효율성 : 달성에 투입한 시간·노력
만족도 : 사용 경험의 편의·수용 정도
        ↓
지정 사용자·목표·사용 맥락에서 측정
```

## Ⅳ. 사용성 시험과 휴리스틱 평가의 비교

- 핵심 요약 : 실증 평가인 사용성 시험과 분석 평가인 **휴리스틱 평가**(heuristic evaluation, 전문가의 원칙 대비 점검)는 발견 문제와 비용이 상호 보완적임.

| 비교 축 | 사용성 시험 | 휴리스틱 평가 |
| --- | --- | --- |
| 평가 주체 | 대표 사용자(수행자) | 사용성 전문가 |
| 방법 | 실제 과업 수행의 관찰·측정 | 설계 원칙 목록 대비 점검 |
| 발견 문제 | 실제 사용 상황의 수행 문제 | 원칙 위반형 구조 문제 |
| 비용·시점 | 참여자 모집·환경 구성 비용, 프로토타입 이후 | 저비용, 설계 초기부터 가능 |
| 한계 | 소수 표본의 일반화 한계 | 실제 수행 데이터 부재 |

## Ⅴ. 사용성 시험의 한계와 방안

- 핵심 요약 : 비대표 참여자·관찰 편향·소수 집단 간과·결과 미반영을 표집 통제, 중립 진행, 이행 관리로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 비대표 참여자·과업 | 실제 사용자와 다른 결과 → 개선 방향 왜곡 | 사용자 세분화, 실제 과업·현장 맥락 표집 | 참여자 적합성, 과업 커버리지 |
| 관찰자·학습 효과 | 진행자 유도·반복 수행으로 결과 편향 | 중립 스크립트, 과업 순서 균형화, 독립 진행 | 도움 요청률, 재시험 편차 |
| 소수 집단 문제 간과 | 평균 점수가 접근성·안전 장벽을 가림 | 보조기술·위험 기반 별도 평가 | 집단별 완료율, 심각 결함 수 |
| 결과의 미반영 | 보고서로 종결 → 같은 문제 재발 | 문제별 책임자·일정 지정, 재평가로 이행 확인 | 개선 이행률 |

## Ⅵ. 사용성 시험 적용에 대한 제언

- 핵심 요약 : 제품 책임 조직은 요구·설계 초기부터 사용자 평가를 절차에 포함하고 사용성·접근성 결과를 제품 승인 기준에 반영.
- 절차 제도화 : 제품 책임 조직이 요구 정의·설계 단계에 사용자 조사와 프로토타입 평가를 표준 활동으로 포함.
- 승인 기준 연계 : 효과성·효율성·만족도와 접근성 결과를 출시 판단·인수 검증의 기준 항목으로 편성.
- 평가 인프라 : 사용성 시험 환경과 대표 사용자 패널을 공동 자원으로 구축해 반복 평가 비용 완화.

## Ⅶ. 결론

- 핵심 요약 : 사용성 시험은 화면의 미관이 아니라 지정 맥락에서의 과업 달성을 확인하는 실증 활동.
- 실증 평가와 전문가 평가의 조합이 제품 채택과 사용 안전을 뒷받침.
