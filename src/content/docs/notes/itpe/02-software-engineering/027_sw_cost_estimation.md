## 연관 키워드
- 소프트웨어 규모·비용 산정, FP, LOC, COCOMO, 상향식·하향식, 불확실성

## Ⅰ. 소프트웨어 규모·비용 산정의 개요
- 핵심 요약 : 소프트웨어 산정은 범위와 규모·복잡도·생산성 가정을 노력·비용·기간으로 변환하는 추정 활동.
- 개념 : 산정기법으로 기능 또는 코드 규모를 정하고 프로젝트 특성·생산성·위험을 반영해 자원과 일정을 추정.
- 필요성 : 초기 요구 불확실성과 생산성 편차로 단일 추정치는 오차·계약분쟁을 낳을 수 있음.
- 목적 : 예산·일정·대안 비교의 근거를 만들고 실제 실적으로 추정모형을 보정.

## Ⅱ. 산정기법의 특징 및 장점
- 핵심 요약 : FP는 사용자 기능, LOC는 구현량, COCOMO는 규모·비용동인에 기반해 서로 다른 오차와 활용조건을 가짐.
1. 기능점수(FP) : 입력·출력·조회·내부논리파일·외부인터페이스를 사용자 기능으로 측정 → 언어 독립적 비교.
2. LOC : 구현 코드량을 추정 → 언어·기술·개발팀 생산성 의존이 큼.
3. COCOMO : KLOC와 비용동인(EAF)으로 노력 추정 → 과거 프로젝트 자료와 모형 보정이 중요.
4. 상향식·하향식 : 세부 작업 합산과 유사규모·전문가 판단을 교차검증.

## Ⅲ. 산정 절차와 모형
- 핵심 요약 : 범위·가정 정의 → 규모 측정 → 노력·기간 모형 적용 → 비용·위험 조정 → 실적 보정.
```text
요구·범위 기준선 → 규모(FP/LOC) 산정 → 생산성·비용동인 적용
        → 노력·기간·비용 추정 → 위험범위·가정 승인 → 실적 환류
```
```text
COCOMO 기본 관계: 노력(PM) = a × (KLOC)^b × EAF
EAF: 제품·플랫폼·인력·프로젝트 비용동인의 보정계수
```
- 추정은 점추정치만 제시하지 말고 범위·신뢰도·제외사항을 기록.

## Ⅳ. FP·LOC·COCOMO 비교
- 핵심 요약 : FP는 기능규모의 언어 독립성, LOC는 구현량의 단순성, COCOMO는 모형·보정자료 활용이 강점.
| 기준 | FP | LOC | COCOMO |
|---|---|---|---|
| 측정대상 | 사용자 기능 | 소스 코드 행 | 규모와 비용동인 기반 노력 |
| 장점 | 구현 전 산정·언어 독립 | 구현량과 직관적으로 연결 | 조직 데이터로 정량 보정 가능 |
| 한계 | 경계·복잡도 판정 필요 | 언어·코딩스타일 의존 | 보정자료·비용동인 품질 의존 |

## Ⅴ. 산정의 한계와 대응
- 핵심 요약 : 요구변경·낙관편향·생산성 차이를 범위추정·실적자료·민감도 분석으로 관리.
| 한계 | 영향 | 대응 |
|---|---|---|
| 초기 요구 불완전 | 규모·비용 과소추정 | 구간추정, 가정·제외범위 공개 |
| 과거 실적 부족 | 모형 계수·생산성 불신 | 유사사업 선정근거와 독립 추정치 비교 |
| 점추정 오용 | 불확실성을 계약 확정값으로 오해 | P50/P80·시나리오·변경조건 명시 |

## Ⅵ. 산정관리 제언
- 핵심 요약 : 사업책임자는 산정근거와 불확실성을 계약 기준선에 연결하고 실적을 후속 추정에 반영.
1. 산정자는 규모·모형·비용동인·출처·제외사항을 재현 가능하게 기록.
2. 발주자·수행자는 범위와 가정을 공동 검증하고 변경 시 재산정 기준을 계약에 반영.
3. PMO는 계획 대비 실투입·완료규모를 수집해 조직 생산성 자료를 갱신.

## Ⅶ. 결론
- 핵심 요약 : 소프트웨어 산정은 하나의 공식이 아니라 범위·규모·생산성·위험을 근거와 함께 추정하는 과정.
- 시사점 : 방법 간 교차검증과 실적 환류가 추정 신뢰도를 높임.
