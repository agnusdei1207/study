## 연관 키워드
- UML, 클래스, 연관·집합·합성·일반화, 다중성

### Ⅰ. 클래스 다이어그램의 개요

- 핵심 요약 : 클래스 다이어그램은 UML(Unified Modeling Language) 정적 구조 다이어그램으로 클래스·속성·연산·관계·다중성을 표현.
- 개념 : 클래스 다이어그램은 UML(Unified Modeling Language) 정적 구조 다이어그램으로 클래스·속성·연산·관계·다중성을 표현(**클래스 다이어그램**, Class Diagram).
- 배경 및 필요성 : 객체·모듈의 책임과 의존관계가 복잡해지면 구조를 공유·검토할 공통 표기 필요.
- 주요 목적 : 설계 구조의 이해·의사소통·변경 영향 분석 지원.

### Ⅱ. 클래스 다이어그램의 특징 및 장점

- 핵심 요약 : 클래스 상자(이름·속성·연산), 연관·집합·합성·일반화·의존 관계와 다중성.

1. 구조 명시 : 클래스 상자(이름·속성·연산), 연관·집합·합성·일반화·의존 관계와 다중성 → 설계 구조의 이해·의사소통·변경 영향 분석 지원.
2. 정적 구조 모델 : 실행 순서가 아니라 시스템의 정적 구조와 관계를 전달하는 모델.
3. 적용 원칙 : 아키텍트는 구현세부를 과도하게 그리기보다 핵심 도메인 경계·책임·제약을 이해관계자와 합의.

### Ⅲ. 클래스 다이어그램의 구조 (흐름)

- 핵심 요약 : 도메인 개념 추출 → 클래스 책임·속성 정의 → 관계·다중성 설정 → 제약·접근수준 표시 → 설계·코드 검토.

```text
도메인 개념 추출
  ↓
클래스 책임·속성 정의
  ↓
관계·다중성 설정
  ↓
제약·접근수준 표시
  ↓
설계·코드 검토
```

```text
클래스
 ├ 이름·속성·연산
 └ 관계 → 다중성
```

### Ⅳ. 클래스 다이어그램과 상태 다이어그램 비교

- 핵심 요약 : 상태 다이어그램은 객체의 상태·이벤트 전이, 클래스 다이어그램은 클래스·속성·정적 관계 구조.

| 비교 축 | 상태 다이어그램 | 클래스 다이어그램 |
|---|---|---|
| 표현 초점 | 객체의 상태·이벤트 전이 | 클래스·속성·정적 관계 구조 |
| 활용 | 객체 생명주기·상태 변경 | 정적 설계 구조·관계 |

### Ⅴ. 클래스 다이어그램의 한계와 방안

- 핵심 요약 : 과도한 상속·다중성 오류·문서-코드 불일치를 합성·역할 인터페이스·관리 범위 축소로 완화.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 과도한 상속 | 구현 재사용을 이유로 강한 결합·취약한 기반형성 | 합성·역할 인터페이스 검토 | 상속 깊이·변경 영향 |
| 다중성 오류 | 업무 제약을 누락하거나 불가능한 상태 허용 | 도메인 규칙·키·제약과 대조 | 제약 위반 |
| 문서-코드 불일치 | 다이어그램 유지 책임 부재 | 중요 구조만 관리·코드리뷰와 변경연계 | 모델 최신성 |

### Ⅵ. 클래스 다이어그램에 대한 제언

- 핵심 요약 : 구현세부를 과도하게 그리기보다 핵심 도메인 경계·책임·제약을 이해관계자와 합의.

1. 아키텍트는 구현세부를 과도하게 그리기보다 핵심 도메인 경계·책임·제약을 이해관계자와 합의.
2. 상속 깊이·변경 영향·제약 위반·모델 최신성을 정기 측정하고 편차에 대한 원인분석·개선결과를 기록.

### Ⅶ. 결론

- 핵심 요약 : 클래스 다이어그램은 UML(Unified Modeling Language) 정적 구조 다이어그램으로 클래스·속성·연산·관계·다중성을 표현.
- 시사점 : 클래스 다이어그램은 실행 순서가 아니라 시스템의 정적 구조와 관계를 전달하는 모델.
