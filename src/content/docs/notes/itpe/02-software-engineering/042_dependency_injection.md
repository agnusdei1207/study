## 연관 키워드

- DI, IoC, 생성자 주입, DIP, 의존성 역전

## Ⅰ. 의존성 주입의 개요

- 핵심 요약 : 의존성 주입(Dependency Injection, DI)은 객체가 의존 객체를 직접 생성하지 않고 외부 조립기가 전달하도록 하는 설계기법.
- 개념 : 의존성 주입(Dependency Injection, DI)은 객체가 의존 객체를 직접 생성하지 않고 외부 조립기가 전달하도록 하는 설계기법.
- 배경 및 필요성 : 구현체 생성과 사용이 결합되면 교체·단위시험·구성 변경이 어려워짐.
- 주요 목적 : 모듈 간 결합도를 낮춰 구현교체·시험·변경 용이성 확보.

## Ⅱ. 의존성 주입의 특징 및 장점

- 핵심 요약 : IoC(Inversion of Control) 실천 방식; 생성자·세터·인터페이스 주입; DIP(Dependency Inversion Principle)와 연계.

1. 생성자 주입: 필수 의존성을 명시 → 객체의 불완전한 생성 방지.
2. 기대 효과 : DI는 객체 생성과 사용의 책임을 분리해 교체성과 시험성을 높이는 IoC 적용 방식.
3. 적용 원칙 : 도메인 계층은 생성 책임을 외부 조립 계층에 두고 필수 의존성을 생성자로 드러내는 기준을 팀 코딩표준으로 정착.

## Ⅲ. 의존성 주입의 구조 (흐름)

- 핵심 요약 : 객체·인터페이스 정의 → 조립기 등록·바인딩 → 생성자에 의존성 전달 → 실행·대역 교체 시험.

```text
객체·인터페이스 정의
  ↓
조립기 등록·바인딩
  ↓
생성자에 의존성 전달
  ↓
실행·대역 교체 시험
```

- 핵심 구성 : IoC(Inversion of Control) 실천 방식; 생성자·세터·인터페이스 주입; DIP(Dependency Inversion Principle)와 연계.

```text
상위 정책 → 추상 인터페이스 ← 저수준 구현; 조립기가 구현을 주입
```

## Ⅳ. 유사 개념과의 비교

- 핵심 요약 : 수동 객체생성 — 호출자가 구체 객체를 직접 생성; 의존성 주입 — 조립기가 인터페이스 구현을 선택해 전달.

| 비교 기준 | 수동 객체생성 | 의존성 주입 |
| --- | --- | --- |
| 구현 교체·시험 | 호출자가 구체 객체를 직접 생성 | 조립기가 인터페이스 구현을 선택해 전달 |

## Ⅴ. 의존성 주입의 한계와 방안

- 핵심 요약 : 주요 한계는 숨은 의존성·순환 의존성·컨테이너 종속이며, 원인별 대응과 검증지표의 연계가 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 숨은 의존성 | 세터·필드 주입·전역 서비스 로케이터 | 필수 의존성은 생성자 주입·생성 시 검증 | null 의존성·구성오류 |
| 순환 의존성 | 객체책임·계층 경계 불명확 | 순환 참조 제거·포트 경계 재설계 | 순환 그래프 수 |
| 컨테이너 종속 | 도메인 코드가 DI 프레임워크에 직접 결합 | 조립영역에서 프레임워크 사용·생성자 주입 테스트 | 도메인 모듈 종속성 |

## Ⅵ. 의존성 주입에 대한 제언

- 핵심 요약 : 모듈 간 결합도를 낮춰 구현교체·시험·변경 용이성 확보.

1. 주체·실행 : 아키텍트와 개발팀은 구체 구현이 아니라 역할 인터페이스에 의존하도록 모듈 경계를 설계하고 생성 시점에 구성 검증.
2. 성과 검토 : null 의존성·구성오류·순환 그래프 수·도메인 모듈 종속성를 정기 측정하고 편차에 대한 원인분석·개선결과를 기록.

## Ⅶ. 의존성 주입의 결론

- 핵심 요약 : 의존성 주입(Dependency Injection, DI)은 객체가 의존 객체를 직접 생성하지 않고 외부 조립기가 전달하도록 하는 설계기법.
- 시사점 : DI는 객체 생성과 사용의 책임을 분리해 교체성과 시험성을 높이는 IoC 적용 방식.
