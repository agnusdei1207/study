## 30초 인출

- 본질: 의존성 주입은 객체가 사용할 의존 객체를 내부에서 만들지 않고 외부에서 전달받게 하는 설계 방식
- 메커니즘: 컨테이너나 호출자가 인터페이스를 구현한 객체를 생성해 생성자·세터로 주입하므로 객체는 구체 클래스가 아닌 인터페이스에만 의존
- 통찰: 클래스 안에서 구체 클래스를 직접 생성하면 교체와 시험이 어려우므로 인터페이스에 의존하고 생성자 주입으로 필수 의존 객체를 외부에서 전달

<details>
<summary>핵심 용어</summary>

- **의존성 주입(DI, Dependency Injection)** : 객체가 사용할 의존 객체를 외부에서 전달하는 방식
- **제어의 역전(IoC, Inversion of Control)** : 객체 생성·연결의 제어를 프레임워크·컨테이너가 맡는 구조
- **의존관계 역전 원칙(DIP)** : 상위 모듈이 하위 모듈의 구체 구현이 아닌 추상화에 의존하는 원칙
- **생성자 주입(Constructor Injection)** : 생성자 매개변수로 의존 객체를 전달하는 방식
- **세터 주입(Setter Injection)** : 세터 메서드로 의존 객체를 전달하는 방식
- **목 객체(Mock)** : 시험에서 실제 의존 객체를 대신하는 가짜 객체

</details>

## 2~4교시 25점 답안

## Ⅰ. 의존성 주입의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **의존성 주입** 은 객체가 사용할 의존 객체를 외부에서 전달받게 하는 설계 방식 |
| 목적 | 객체 간 결합도 감소와 교체·시험 용이성 확보 |

## Ⅱ. 직접 생성과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 생성 책임 분리 | 사용하는 쪽과 만드는 쪽의 분리 |
| 추상화 의존 | 인터페이스에 의존해 구현 교체 가능 |
| 제어의 역전 | 컨테이너가 객체 생성·연결 |

## Ⅲ. 의존성 주입 구조와 주입 방식

### 의존성 주입 구조

```text
Client ──→ [Service 인터페이스]
                 ▲
           ┌─────┴─────┐
     [ServiceImpl]   [MockService]
Container: 구현 객체를 생성해 Client에 주입
```

### 확대: 주입 방식

```text
생성자 주입 ── 생성 시 필수 의존 객체 전달 (불변·필수)
세터 주입   ── 선택적·변경 가능한 의존 객체
필드 주입   ── 필드에 직접 주입 (시험·불변성 불리)
```

## Ⅳ. 직접 생성과 주입 방식의 비교

| 구분 | 직접 생성(new) | 의존성 주입 |
|---|---|---|
| 결합도 | 구체 클래스에 결합 | 인터페이스에 결합 |
| 구현 교체 | 코드 수정 | 설정 변경 |
| 단위 시험 | 실제 의존 객체 필요 | Mock 주입 가능 |
| 의존성 파악 | 내부 코드 확인 | 생성자로 명시 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 순환 의존으로 주입 실패 | 책임을 분리해 의존 방향 단방향화 |
| 필드 주입으로 시험 시 의존 객체 대체 곤란 | 생성자 주입 사용 |
| 컨테이너 설정 복잡도 증가 | 설정 규칙 표준화와 자동 주입 활용 |

## Ⅵ. 제언

필수 의존 객체는 인터페이스를 통해 생성자 주입으로 받도록 하고, 시험에서는 Mock을 주입

### 생성자 주입 적용

```text
Service 인터페이스 정의
    ↓
Client가 생성자로 Service를 받음
    ↓
운영: 실제 구현 주입 / 시험: Mock 주입
```

### 확대: 시험 시 대체

```text
운영 환경 ── ServiceImpl 주입
시험 환경 ── MockService 주입 (외부 시스템 없이 검증)
```

### 선택 근거: 직접 생성과의 비교

| 구분 | 직접 생성 | 제언: 생성자 주입 |
|---|---|---|
| 구현 교체 | 코드 수정 | 주입 변경 |
| 시험 | 외부 시스템 필요 | Mock 사용 |
| 의존 명시 | 숨겨짐 | 생성자에 드러남 |
