## 연관 키워드

- 오픈소스 프로젝트관리 소프트웨어(PM Software), 자체 구축(Self-Hosted), Redmine, OpenProject, Taiga
- 총소유비용(TCO, Total Cost of Ownership), 망분리, WBS(Work Breakdown Structure), 커밋 훅(Commit Hook)

## Ⅰ. 오픈소스 프로젝트관리 소프트웨어의 개요

- 핵심 요약 : 소스코드가 공개된 프로젝트관리 도구를 사내에 구축해 비용 부담을 줄이고 정보 유출 위험을 통제하는 협업 체계.
- 개념 : **오픈소스 프로젝트관리 소프트웨어** (PM, Project Management Software)란 일정, 작업, 이슈, 결함, 산출물, 형상관리 항목을 관리하며, 사내 서버나 프라이빗 클라우드에 **자체 구축** (Self-Hosted)할 수 있는 공개 소스 기반의 협업 도구.
- 배경 및 필요성 : 상용 SaaS(Software as a Service) 도구는 사용자 수에 따른 구독 부담이 누적되어 **총소유비용** (TCO, Total Cost of Ownership)이 커지고, 망분리 환경에서는 소스코드 메타데이터와 프로젝트 정보의 외부 유출을 막아야 함.
- 주요 목적 : Redmine, OpenProject, Taiga 같은 솔루션을 도입해 비용 효율적이고 자율적인 프로젝트 관리 기반을 확보.

## Ⅱ. 오픈소스 PM 소프트웨어의 특징

- 핵심 요약 : 라이선스 부담이 없는 자체 호스팅 구조, 애자일과 전통 방법론의 동시 지원, 외부 시스템과 연계하는 개방형 구조.

1. 소스 공개 : 커스터마이징이 자유롭고 특정 벤더에 대한 종속(Lock-in)이 줄어듦.
2. 자체 호스팅 : 데이터가 사내 인프라에 머물러 망분리와 정보 보호 요건에 대응.
3. 방법론 병행 : WBS(Work Breakdown Structure) 간트 차트와 스크럼·칸반 보드를 함께 운영.
4. 이슈 추적 : 티켓, 우선순위, 워크플로우로 결함과 작업을 추적.
5. 협업 기능 : 위키, 포럼, 파일 첨부로 문서와 회의 기록을 함께 관리.
6. 외부 연계 : REST API(Application Programming Interface)와 웹훅(Webhook)으로 메신저와 형상관리 시스템에 연결.

## Ⅲ. 오픈소스 PM 소프트웨어의 구조 (흐름)

- 핵심 요약 : 관리 기능 계층 위에서 REST API와 웹훅, 형상관리 시스템 연계가 이루어지는 통합 협업 구조.

```text
[ 오픈소스 PM 플랫폼 ]
  - 일정·작업: WBS 간트, 스크럼·칸반
  - 이슈·결함: 티켓, 우선순위, 워크플로우
  - 자원·원가: 투입 공수, 예산 추적
  - 협업·문서: 위키, 포럼, 파일 첨부
      ↓
[ 연계 계층 ]
  - REST API·웹훅 → 사내 메신저 알림
  - 버전 관리 동기화 → 형상관리 시스템
```

- 관리 기능 계층 : 일정, 작업, 이슈, 결함, 자원 관리를 한 화면 체계에서 통합 제공.
- 연계 계층 : 웹훅 기반의 메신저 알림 전파와 형상관리 시스템과의 커밋·이슈 양방향 동기화.

## Ⅳ. 주요 오픈소스 PM 솔루션과 상용 도구의 비교

- 핵심 요약 : 방법론 지원 폭과 비용 구조에서 자체 구축형 솔루션이 강점을 가지며, 상용 도구는 생태계 폭에서 우위.

| 비교 축 | Redmine | OpenProject | Taiga | 상용 Jira |
| --- | --- | --- | --- | --- |
| 방법론 중심 | 전통적 WBS와 간트 차트, 이슈 추적 | WBS와 애자일 보드의 결합 | 스크럼·칸반 중심의 애자일 | 애자일 보드와 광범위한 플러그인 |
| 비용 구조 | 오픈소스, 자체 구축 시 라이선스 비용 없음 | 커뮤니티 에디션 기준 자체 구축 가능 | 커뮤니티 에디션 기준 자체 구축 가능 | 사용자 수 기준의 구독 과금 |
| 사용자 경험 | 고전적인 인터페이스 | 현대적인 반응형 인터페이스 | 가볍고 직관적인 보드 중심 | 고도화된 화면과 복잡한 관리 설정 |
| 생태계 | 플러그인 풍부 | 연계 기능 확장 중 | 애자일 도구 중심 | 전 산업에서 검증된 연계 생태계 |

- 선택 기준 : 방법론의 중심(전통 또는 애자일), 사내 운영 인력, 외부 도구와의 연계 필요성에 따라 적용 범위를 정함.

## Ⅴ. 오픈소스 PM 소프트웨어의 한계와 방안

- 핵심 요약 : 비용 절감과 데이터 주권이라는 장점, 운영 공수와 연계 생태계, 세분화된 보안 통제의 한계.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 운영 공수 부담 | DB 백업, 버전 업그레이드, 플러그인 호환성 관리를 내부 인력이 전담 | 컨테이너 기반 표준 배포와 인프라 코드화(IaC, Infrastructure as Code), 무중단 백업 파이프라인 구성 | 패치 적용 주기, 복구 시간 |
| 서드파티 연계 부족 | 최신 CI/CD 도구, 메신저, 클라우드와의 기성 커넥터가 적음 | REST API와 웹훅으로 사내 이벤트 중계 서비스 구축 | 연계 장애 건수 |
| 세분화된 보안 통제 부족 | 프로젝트별 접근 분리, 필드 단위 통제, 관리자 감사 로그가 미흡 | Keycloak·LDAP(Lightweight Directory Access Protocol) 연동 SSO(Single Sign-On)와 RBAC(Role-Based Access Control) 강화, 접근 로그 중앙화 | 권한 위반 탐지 건수 |

## Ⅵ. 성공적인 사내 도입·정착을 위한 기술사적 제언

- 핵심 요약 : Git 커밋 훅 기반 이슈 연계와 백업·고가용성 운영 체계의 사전 확립.
- 개발 조직은 Git 커밋 메시지의 이슈 키워드를 훅으로 연결해, 상태 변경을 수작업이 아닌 커밋 흐름에서 처리하도록 하는 것이 바람직하다. 아래 도해처럼 커밋이 이슈 전이와 팀 알림으로 이어지게 구성하면 된다.

```text
[ 개발자 커밋 ]
  git commit -m "fixes #102"
      ↓
[ Git 커밋 훅 / 웹훅 ]
  이슈 키워드 파싱
      ↓
[ PM 소프트웨어 ]
  이슈 #102 '해결' 전이
  커밋 Diff 티켓 링크
      ↓
[ 팀 알림 (메신저) ]
```

- 인프라 조직은 자체 호스팅의 장애와 데이터 유실 책임을 사내에서 지므로, 일일 자동 DB 백업과 파일 저장소 복제, 대기 노드 구성을 사전에 갖추어 업무 연속성을 확보해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 오픈소스 PM 소프트웨어는 비용 효율과 데이터 통제를 함께 얻는 대안적 협업 인프라.
- 시사점 : 운영 자동화, API 연계, 접근 통제의 병행이 도입 성공의 관건.
