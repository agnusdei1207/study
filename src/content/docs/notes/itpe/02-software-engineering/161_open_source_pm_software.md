## 핵심 용어
- 레드마인(Redmine): Ruby on Rails 기반의 대표적인 오픈소스 프로젝트 관리 및 이슈 추적 도구로, 강력한 롤 기반 접근 제어(RBAC)와 수천 개의 커뮤니티 플러그인을 지원함
- 데이터 주권(Data Sovereignty): 기업이나 국가의 핵심 지적 자산(프로젝트 기획서, 결함 정보, 소스코드)이 해외 클라우드 업체의 데이터센터에 종속되지 않고 자체 관할 인프라 내에 보관되어야 한다는 원칙

## 핵심 통찰
- 오픈소스 PM 도구는 라이선스 비용이 무료이지만, 서버 인프라 비용, 정기 보안 패치, 데이터 백업, 플러그인 버전 충돌 해결 등 "자체 운영 인건비(TCO)"가 발생한다는 점을 냉정하게 계산해야 함
- 방산, 금융, 공공 등 망분리(망격리) 규제로 인해 외부 퍼블릭 SaaS를 일체 사용할 수 없는 폐쇄망 환경에서는 Redmine이나 OpenProject 같은 자체 호스팅 오픈소스 PM 소프트웨어가 사실상 유일한 대안임
- 단순한 이슈 게시판으로 쓰면 실패하며, 사내 GitLab/Gitea 저장소의 Git 커밋 메시지(예: `Fix #123`)와 연동하여 커밋 시점에 자동으로 이슈가 종결되고 테스트 결과가 기록되는 자동화 체인을 구축해야 가치가 발휘됨

## 이웃 토픽과 구분
- 오픈소스 PM 도구 vs 상용 SaaS PM 도구(Jira/Asana): 오픈소스 = 데이터 완전 통제, 폐쇄망 구축 가능, 무제한 사용자 / 상용 SaaS = 인프라 관리 불필요, 지속적 기능 업데이트, 고가의 사용자당 월 구독료

## 문제·원인·대책
- 적용 상황: 국가 보안 연구소 폐쇄망 내부 프로젝트 관리 시스템 구축
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 외부 인터넷이 차단된 망분리 환경에서 상용 클라우드 Jira 사용 불가로 엑셀로 일정 관리 | 데이터 보안 규정상 외부 SaaS 접속이 원천 차단된 특수 보안 환경 | 사내 가상머신에 오픈소스 OpenProject 설치 및 사내 SSO(LDAP) 연동 | 망분리 규정 준수 및 웹 기반 협업 체계 확립 |

## 내 의견
- [모던 협업 트렌드에 맞춘 GitLab CE 통합 활용] 전통적인 Redmine은 UI가 투박하여 MZ세대 개발자들의 자발적 참여도가 떨어지고 이슈 등록이 기피되는 문제 발생 → 나라면: 별도의 레거시 PM 도구를 따로 두지 않고, Git 소스코드 관리, 이슈 트래커, 칸반 보드, 위키, CI/CD가 단일 웹 화면에 완벽히 통합된 'GitLab Community Edition(오픈소스)'을 사내 프라이빗 인프라에 올인원으로 구축하여 개발 편의성과 프로젝트 관리 생산성을 동시 달성
