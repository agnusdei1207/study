소프트웨어 공학 → 프로젝트 관리 → **오픈소스 프로젝트관리 소프트웨어(Open Source PM Software)**

## 30초 인출

- 본질: 오픈소스 프로젝트관리 소프트웨어는 이슈·일정·문서를 관리하는 프로젝트 관리 도구 중 소스가 공개되어 자체 구축할 수 있는 것(Redmine·OpenProject 등)
- 메커니즘: 요구·작업·결함을 이슈로 등록해 담당자·상태를 추적하고 일정과 진척을 보고하며 역할에 따라 접근 권한을 제한
- 통찰: 도입 비용이 없어도 서버 운영·보안 패치·플러그인 관리 부담이 있으므로 총소유비용과 지원 체계를 비교해 도입하고 운영 담당자를 지정

<details>
<summary>핵심 용어</summary>

- **오픈소스 PM 소프트웨어** : 소스 코드가 공개되어 무료로 설치·수정할 수 있는 프로젝트 관리 도구
- **이슈 추적 시스템(ITS)** : 요구·작업·결함을 이슈로 등록하고 처리 상태를 추적하는 시스템
- **역할 기반 접근 제어(RBAC)** : 역할에 따라 조회·수정 권한을 나누는 방식
- **자가 호스팅(Self-Hosting)** : 조직이 자체 서버에 설치해 운영하는 방식
- **총소유비용(TCO)** : 도입 후 운영·유지에 드는 비용까지 합친 전체 비용

</details>

## 2~4교시 25점 답안

## Ⅰ. 오픈소스 PM 소프트웨어의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **오픈소스 PM 소프트웨어** 는 소스가 공개되어 자체 구축할 수 있는 프로젝트 관리 도구 |
| 목적 | 이슈·일정·진척 관리의 체계화와 도구 비용 절감 |

## Ⅱ. 상용 도구와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 라이선스 비용 없음 | 도입 비용 부담 감소 |
| 자체 설치 | 데이터를 조직 내부에 보관 |
| 확장 가능 | 플러그인·소스 수정 |
| 지원 자체 부담 | 운영·보안 패치의 자체 수행 |

## Ⅲ. 핵심 기능

```text
프로젝트 관리 도구
    ├─ 이슈 추적 ── 요구·작업·결함의 등록과 상태 관리
    ├─ 일정 관리 ── 간트 차트, 마일스톤
    ├─ 문서·위키 ── 산출물 공유
    └─ 권한 관리 ── 역할별 접근 제어
```

## Ⅳ. 도입 방식의 비교

| 구분 | 오픈소스 자체 구축 | 상용 SaaS |
|---|---|---|
| 도입 비용 | 낮음 | 사용료 발생 |
| 운영 부담 | 서버·패치·백업 자체 수행 | 제공사 수행 |
| 데이터 통제 | 내부 보관 | 외부 위탁 |
| 기능 확장 | 자유로움 | 제공 범위 내 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 운영·보안 패치의 자체 부담 | 운영 담당자 지정과 패치 주기 정의 |
| 플러그인 품질·호환 편차 | 검증된 플러그인만 사용 |
| 지원 체계 부재 | 커뮤니티·상용 지원 옵션 확인 |

## Ⅵ. 제언

라이선스 비용만 보지 않고 운영 인력·패치·백업까지 포함한 총소유비용으로 비교해 도입하고, 운영 담당자와 패치 주기를 정함

```text
후보 도구 비교
      ↓ TCO(도입 + 운영 + 지원)
도입 결정
      ↓
운영 담당자 지정 · 패치·백업 주기 정의
```

| 구분 | 라이선스 비용만 비교 | 제언: TCO 비교 |
|---|---|---|
| 비용 누락 | 운영 비용 미반영 | 반영 |
| 운영 책임 | 불명확 | 담당자 지정 |
