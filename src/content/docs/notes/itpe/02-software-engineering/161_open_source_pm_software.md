## 30초 인출

- 본질: 상용 솔루션의 라이선스 비용 및 벤더 종속(Lock-in)을 탈피하고 소스 코드 수준의 자유로운 커스터마이징과 내부 인프라 구축(On-Premise)을 지원하는 오픈소스 기반 프로젝트/이슈 협업 도구
- 메커니즘: 프로젝트 및 사용자 역할(RBAC) 정의 → WBS/간트차트 기반 일정 수립 → 작업/결함 이슈 티켓 발행 및 워크플로우 상태 전이 추적 → 형상관리(Git) 및 CI/CD 파이프라인 연동
- 통찰: 상용 SaaS 대비 라이선스 비용은 절감되나 자체 호스팅에 따른 보안 패치, 백업, 업그레이드 등 총소유비용(TCO)이 증가하므로 사내 엔지니어링 역량과 데이터 보안 규제에 기반한 도입 판단 필요

<details>
<summary>핵심 용어</summary>

- **오픈소스 PM 소프트웨어** : Redmine, OpenProject, Taiga 등 소스코드가 공개되어 무료 라이선스로 자체 호스팅 및 기능 확장이 가능한 프로젝트 관리 도구
- **이슈 추적 시스템 (ITS: Issue Tracking System)** : 요구사항, 작업, 버그, 개선 요청 등을 고유 티켓 ID로 발급하여 생성부터 종결까지의 상태 전이를 추적하는 기능
- **역할 기반 접근 제어 (RBAC)** : 프로젝트 관리자, 개발자, 테스터, 고객 등 역할에 따라 모듈 조회, 수정, 승인 권한을 차등 부여하는 보안 모델
- **자가 호스팅 (Self-Hosting / On-Premise)** : 외부 클라우드 SaaS에 데이터를 위탁하지 않고 기업 자체 프라이빗 인프라 또는 사내망에 서버를 직접 구축·운영하는 방식
- **총소유비용 (TCO: Total Cost of Ownership)** : 소프트웨어 도입 비용뿐만 아니라 인프라 유지보수, 백업, 장애 복구, 운영 인력 투입 비용을 포괄하는 총체적 비용
</details>

## 2~4교시 예상문제 (25점)

> 소프트웨어 프로젝트에서 오픈소스 프로젝트 관리(PM) 도구의 도입 배경과 핵심 기능 아키텍처를 설명하고, 상용 솔루션(Jira 등)과의 TCO/보안 비교 및 성공적 정착을 위한 엔터프라이즈 운영 방안을 제시하시오. (25점)

---

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 소프트웨어 개발 프로젝트의 일정, 작업(WBS), 결함, 산출물 및 인력 자원을 효과적으로 관리하기 위해 공개 소스코드 라이선스(GPL 등) 기반으로 배포되는 프로젝트 관리 및 협업 소프트웨어 |
| 목적 | 고가의 상용 라이선스 비용 절감, 데이터 주권(Data Sovereignty) 확보, 사내 고유 개발 프로세스에 맞춘 워크플로우 커스터마이징 및 ALM 도구 연계 |

## Ⅱ. 핵심 특징

| 특징 | 세부 내용 |
|---|---|
| 데이터 보안 및 완전한 통제권 | 온프레미스(On-Premise) 또는 프라이빗 클라우드에 직접 설치하여 기업의 핵심 기술 및 소스코드 유출 원천 차단 |
| 높은 커스터마이징 자유도 | 워크플로우 상태 전이 룰, 커스텀 필드, 플러그인 아키텍처를 통해 조직 맞춤형 환경 구성 가능 |
| 엔드투엔드 추적성 (Traceability) | Git/SVN 커밋 메시지에 이슈 번호를 연동하여 요구사항-코드-결함 간의 완벽한 상호 추적성 제공 |
| 다양한 관리 패러다임 지원 | 전통적 폭포수(WBS, 간트차트, 진척률) 방식과 애자일(스크럼 백로그, 칸반 보드) 방식을 단일 플랫폼에서 병행 지원 |

벤더 종속을 탈피하여 기업의 독자적 프로젝트 거버넌스를 구현할 수 있는 협업 플랫폼으로 기능.

## Ⅲ. 체계·프로세스

```text
[1. 조직 및 프로젝트 베이스라인 설정]
  - 프로젝트 생성, 상위/하위 프로젝트 계층 구조화
  - RBAC 권한 매트릭스(PM, PL, Dev, QA, Auditor) 정의
       │
       ▼
[2. 일정 계획 및 작업 분할 (WBS)]
  - 작업 패키지(Task) 생성 및 간트 차트(Gantt) 일정 수립
  - 스프린트 마일스톤 및 릴리즈 버전 할당
       │
       ▼
[3. 이슈 라이프사이클 및 워크플로우 추적]
  ┌────────────────────────────────────────────────────────┐
  │ [신규 등록] ──► [담당 배정] ──► [진행 중]              │
  │                                    │                   │
  │ [완료/종결] ◄── [검토/승인] ◄──────┴─ (코드 리뷰/테스트)│
  │       │                                                │
  │       └──► [재개방] (테스트 실패 시 피드백 루프)       │
  └────────────────────────────────────────────────────────┘
       │
       ▼
[4. ALM 파이프라인 연계 및 성과 분석]
  - Git Push 시 커밋 로그(#이슈ID) 기반 자동 상태 전이
  - 번다운 차트, 작업 진척률, 결함 밀도 대시보드 출력
```

초기 거버넌스 설정부터 WBS 기반 작업 분할, 이슈 티켓 워크플로우 전이, CI/CD 연동 및 대시보드 리포팅까지의 통합 프로세스.

## Ⅳ. 종류·비교

| 비교 항목 | 오픈소스 PM 도구 (Redmine, OpenProject) | 상용 SaaS PM 도구 (Atlassian Jira) |
|---|---|---|
| **라이선스 비용** | 무료 (GPL 등 오픈소스 라이선스) | 사용자 계정 수(Per-User) 기반 월/연 구독료 발생 |
| **호스팅 환경** | 사내 온프레미스 / 프라이빗 클라우드 중심 | 벤더 퍼블릭 클라우드 SaaS 중심 |
| **데이터 보안** | 완전한 사내 격리망 운영 가능 (망분리 환경 최적) | 외부 클라우드 위탁에 따른 보안 규제 이슈 검토 필요 |
| **유지보수 책임** | 기업 내부 엔지니어가 인프라, 백업, 패치 전담 | 벤더가 인프라 가용성(SLA), 백업, 보안 패치 전담 |
| **플러그인 생태계** | 커뮤니티 기반 오픈소스 플러그인 (호환성 검증 필요) | 방대한 상용 마켓플레이스 및 인증된 앱 연동 |
| **총소유비용 (TCO)** | 초기 도입비는 낮으나 인프라/운영 인건비 지속 소요 | 도입 구독료는 높으나 자체 인프라 관리 공수 최소화 |

### 주요 오픈소스 PM 소프트웨어 솔루션 비교

| 솔루션 | 주요 아키텍처 | 특징 및 강점 | 최적 적용 도메인 |
|---|---|---|---|
| **Redmine** | Ruby on Rails, MySQL/PostgreSQL | 가볍고 안정적이며 풍부한 플러그인 및 형상관리 연동 우수 | 금융/공공 망분리 환경, 전통적 SI 프로젝트 |
| **OpenProject** | Ruby on Rails + Angular SPA | 모던한 UI/UX, 간트차트 및 애자일 보드 동시 지원 | 엔터프라이즈 하이브리드(폭포수+애자일) 프로젝트 |
| **Taiga** | Python/Django + AngularJS | 직관적이고 미려한 스크럼/칸반 전용 애자일 인터페이스 | 순수 애자일 스타트업 및 소규모 스쿼드 팀 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 오픈소스 코어 버전 업그레이드 시 커뮤니티 서드파티 플러그인과의 호환성 충돌로 시스템 마비 | 플러그인 도입을 최소화하고 공식 지원 LTS 버전을 준수하며 스테이징 환경에서 사전 호환성 테스트 의무화 |
| 사내 운영 인력의 전문성 부족으로 인한 주기적 DB 백업 누락 및 데이터 영구 유실 위험 | Docker/Kubernetes 기반 컨테이너화 배포 및 스냅샷 자동 백업, 이중화(HA) 아키텍처 표준 템플릿 적용 |
| 사용자가 이슈 상태를 제때 업데이트하지 않아 실제 진척도와 도구 상의 수치 간 괴리 발생 | Git 커밋 훅 및 CI/CD 파이프라인과 연동하여 빌드/배포 성공 시 이슈 상태를 자동 갱신하는 자동화 트리거 구성 |

## Ⅵ. 제언

도구 자체의 도입에 매몰되지 않고 조직의 표준 개발 프로세스(SDR)와 이슈 템플릿을 명문화하며, DevSecOps 툴 체인과의 완전한 API 연계를 통한 워크플로우 자동화 정착 권장.

```text
[오픈소스 PM 기반 통합 ALM 아키텍처]
  OpenProject (이슈/WBS) ──► GitLab (코드 커밋 #이슈) ──► Jenkins/ArgoCD (빌드/배포) ──► SonarQube (품질 리포트 자동 등록)
```

| 관리 영역 | 전통적 수동 관리 체계 | 현대적 자동화 협업 체계 |
|---|---|---|
| 작업 현황 | 개발자가 주간 보고 시 수동 이슈 닫기 | Git 커밋 및 PR 승인 시 Webhook 기반 자동 상태 전이 |
| 추적성 관리 | 엑셀 기반 요구사항 추적표 수기 관리 | 이슈 티켓-커밋-빌드 번호 간 하이퍼링크 기반 자동 연결 |
