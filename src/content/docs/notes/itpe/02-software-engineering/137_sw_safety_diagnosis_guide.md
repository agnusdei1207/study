## 연관 키워드
- SW 안전진단, 위험기반 점검, FMEA, FTA, SPOF, SAST, 장애주입, 시정계획

## Ⅰ. SW 안전진단의 개요
- 핵심 요약 : SW 안전진단은 시스템 위험·요구·설계·구현·시험증거를 점검해 위험통제의 누락과 개선과제를 찾는 평가활동.
- 개념 : 안전 관련 소프트웨어가 안전요구와 도메인 규제·표준을 충족하는지 독립적으로 검토.
- 필요성 : 안전 요구의 구현·시험 누락은 소프트웨어 결함을 인명·환경·자산 피해로 연결할 수 있음.
- 목적 : 위험을 줄이고 안전요구·통제·증거 간 추적성을 확보.

## Ⅱ. 안전진단의 특징 및 장점
- 핵심 요약 : 요구·아키텍처·코드·검증·운영통제를 위험중심으로 교차 점검.
1. 위험기반 : 안전기능·고장결과·노출에 따라 점검 깊이 결정 → 고위험 통제 우선.
2. 독립증거 : 안전분석·검토·시험·구성기록 확인 → 자기선언 한계 보완.
3. 추적성 : 위험원→안전요구→설계·구현→시험결과 연결 → 누락·불일치 식별.

## Ⅲ. 진단 절차와 점검영역
- 핵심 요약 : 시스템 맥락·안전범위 확정 → 위험분석·요구추적 → 설계·코드·시험 검토 → 지적등급·개선 검증.
```text
안전기능·위험·규제기준 확인
   ↓ 요구·아키텍처·인터페이스 추적
설계·코드·구성·보안 점검
   ↓ 시험·장애대응·운영증거 확인
지적·위험등급 → 시정계획 → 재검증·종결
```
```text
정적분석(SAST) + FMEA/FTA 검토 + 단위·통합시험
            + 고장주입·복구시험 + 독립 안전검토
```
- 점검영역 예 : 안전요구·설계, 구현·형상, 검증·시험, 운영·변경·복구통제.

## Ⅳ. 안전진단과 안전인증 비교
- 핵심 요약 : 안전진단은 현재 설계·통제의 결함과 개선을 찾고, 인증은 정해진 평가기준 적합성을 공식 판정.
| 기준 | SW 안전진단 | 안전인증·적합성 평가 |
|---|---|---|
| 목적 | 위험·통제 공백 발견과 개선 | 정해진 표준·규정 적합성 판정 |
| 산출 | 지적사항·위험등급·개선계획 | 인증·적합성 결과와 증거 |
| 시점 | 생명주기 중 반복 가능 | 규정이 정한 단계·대상에서 수행 |
| 관계 | 인증준비·운영개선에 증거 제공 | 진단만으로 대체되지 않음 |

## Ⅴ. 안전진단의 한계와 대응
- 핵심 요약 : 독립성·도메인 지식·레거시 증거 부족을 다학제 참여와 위험기반 증거수집으로 보완.
| 한계 | 영향 | 대응 |
|---|---|---|
| 도메인 역량 부족 | 위험 시나리오·안전요구 오판 | 안전·SW·운영 전문가 공동진단 |
| 레거시 산출물 미흡 | 요구·시험 추적 공백 | 코드·로그·장애이력으로 증거 보완, 잔여위험 명시 |
| 개선 실행력 부족 | 지적 반복·위험 잔존 | 소유자·기한·예산·재검증 조건 지정 |

## Ⅵ. 진단 거버넌스 제언
- 핵심 요약 : 진단기관은 이해상충을 통제하고 사업책임자는 위험등급별 시정·잔여위험 승인 절차를 둠.
1. 진단책임자는 독립성·범위·기준·증거수준을 사전 합의.
2. 개발·운영 조직은 발견사항을 위험도·책임자·시정기한·재시험 조건에 연결.
3. 안전책임자는 미해결 고위험을 출시·운영 의사결정에 상향보고.

## Ⅶ. 결론
- 핵심 요약 : SW 안전진단은 안전요구와 실제 구현·시험·운영 통제가 일치하는지 위험중심으로 검증.
- 시사점 : 진단의 가치는 발견 건수가 아니라 중대 위험의 시정·검증과 잔여위험 투명성.
