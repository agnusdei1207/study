## 연관 키워드

- SW 안전진단 가이드, 과학기술정보통신부, NIPA(National IT Industry Promotion Agency), 4대 진단 영역
- FMEA(Failure Mode and Effects Analysis), FTA(Fault Tree Analysis), 단일 장애점(SPOF, Single Point of Failure), 결함 허용(Fault Tolerance), 정적 분석(SAST)

## Ⅰ. SW 안전진단 가이드의 개요

- 핵심 요약 : 소프트웨어 결함으로 인한 재난적 사고 예방을 위해 안전성을 체계적으로 진단하는 국가 표준 가이드라인.
- 개념 : SW(Software) 안전진단 가이드란 과학기술정보통신부와 NIPA(National IT Industry Promotion Agency)가 국민 생활 및 국가 핵심 기반시설에 도입된 소프트웨어의 오작동과 결함으로 인한 재난적 사고를 예방하기 위해, 소프트웨어 안전성을 객관적이고 체계적으로 진단할 수 있도록 정립한 국가 표준 가이드라인.
- 배경 및 필요성 : 전력, 교통, 의료, 수자원 등 사회 전반이 소프트웨어로 통제되는 초연결 사회에서 소프트웨어 오류가 대형 인명 피해나 국가 마비로 직결됨에 따라 체계적인 진단 프레임워크 필수.
- 진단 4대 영역 : 프로세스 안전성, 아키텍처 안전성, 소스코드 안전성, 시스템 실행환경 안전성.

## Ⅱ. SW 안전진단 가이드의 특징

- 핵심 요약 : 프로세스·아키텍처·소스코드·실행환경의 4대 영역과 위험도별 조치 권고로 구성되는 전 생애주기 안전 진단 체계.

1. 프로세스 안전성 : 안전 요구관리, 형상관리, 변경 통제 프로세스의 적정성 진단.
2. 아키텍처 안전성 : 단일 장애점(SPOF) 제거, Fail-Safe, 워치독 타이머 등 결함 허용 구조 진단.
3. 소스코드 안전성 : MISRA-C 규칙, CWE(Common Weakness Enumeration) 보안약점, 메모리 누수, 동시성 오류 진단.
4. 실행환경 안전성 : OS·미들웨어 패치, 하드웨어 이중화, 백업·복구 체계 진단.
5. 국가 표준 가이드라인으로서 과학기술정보통신부·NIPA 주관의 공신력 확보.
6. 위험도별(상/중/하) 개선 조치 권고 및 최종 안전진단 보고서 산출.

## Ⅲ. SW 안전진단 가이드의 구조 (흐름)

- 핵심 요약 : 진단 계획부터 개선 권고까지의 4단계 절차와 4대 핵심 영역의 이중 프레임워크.

```text
[ 1. 진단 계획 수립 ]
 - 진단 대상 시스템 선정
 - 인터뷰 일정 확정
   │
   ▼
[ 2. 현장 실사 및 데이터 수집 ]
 - 소스코드, 설계서, 형상 산출물
 - 운영 및 장애 이력 수집
   │
   ▼
[ 3. 4대 영역 심층 분석 ]
 - 도구 기반 정적/동적 진단
 - 전문가 정밀 인스펙션
   │
   ▼
[ 4. 개선 조치 권고 ]
 - 위험도별(상/중/하) 조치
 - 최종 안전진단 보고서
```

```text
[ SW 안전진단 4대 핵심 영역 ]
 1. 프로세스 영역
    - 안전 요구관리, 형상관리,
      변경 통제 프로세스
 2. 아키텍처 영역
    - 단일 장애점(SPOF) 제거,
      Fail-Safe, 워치독 타이머
 3. 소스코드 영역
    - MISRA, CWE 보안약점,
      메모리 누수, 동시성 오류
 4. 실행환경 영역
    - OS/미들웨어 패치, 하드웨어
      이중화, 백업/복구
```

- MISRA-C : 자동차 산업용 C 언어 코딩 표준(MISRA, Motor Industry Software Reliability Association)으로 소스코드 안전성 판정 기준으로 활용.
- 진단 방법론 : 도구 기반 정적·동적 진단과 전문가 정밀 인스펙션의 병행을 통한 객관성 확보.

## Ⅳ. SW 안전진단 점검 항목의 비교

- 핵심 요약 : 진단 영역별 점검 항목과 검증 방법의 차별화를 통한 4대 영역 커버리지 확보.

| 진단 영역 | 핵심 점검 항목 | 주요 검증 방법 |
|---|---|---|
| 프로세스 안전성 | 안전 요구사항 추적성, 위험원 분석(FMEA(Failure Mode and Effects Analysis)/FTA(Fault Tree Analysis)) 수행 여부 | 산출물(SRS(Software Requirements Specification), RTM(Requirements Traceability Matrix), 위험관리계획서) 정밀 감사 |
| 아키텍처 안전성 | 결함 허용(Fault Tolerance), 비상 정지 메커니즘, 모듈 격리 | 아키텍처 설계서(SAD, Software Architecture Description) 검토 및 전문가 인터뷰 |
| 소스코드 안전성 | 버퍼 오버플로우, Null 역참조, 데드락, MISRA-C 코딩 규칙 준수 | 정적 코드 분석(SAST, Static Application Security Testing) 도구(CodeScroll, Coverity) 전수 검사 |
| 실행환경 안전성 | 자원 고갈(CPU(Central Processing Unit)/메모리) 시 시스템 동작, 네트워크 단절 복원력 | 결함 주입 시험(Fault Injection), 스트레스 테스트 |

## Ⅴ. SW 안전진단 가이드의 장점과 한계

- 핵심 요약 : 객관적 국가 표준 진단 체계의 장점, 진단원 역량 격차·설계 산출물 부재·조치 실행력 부족 측면의 한계.

- 장점
  1. 국가 표준 가이드라인 기반의 객관적·일관된 진단 기준.
  2. 프로세스부터 실행환경까지를 아우르는 4대 영역 전수 커버.
  3. 위험도별 조치 권고를 통한 개선 우선순위의 명확화.

- 한계점 1 : 진단 수행원의 전문성 격차 및 체크리스트 중심의 표면적 진단
  - 한계점 : 진단원의 역량에 따라 정적 분석 도구 결과 보고서 수준에 그치며 아키텍처 레벨의 근본적 결함 및 동적 안전 위험원 식별 미흡.
  - 해결 방안 : SW 안전진단 자격 인증 제도화, 아키텍처 취약점 및 동적 레이스 컨디션을 심층 진단하는 고도화 실습형 진단 프레임워크 표준화.
- 한계점 2 : 레거시 시스템의 아키텍처 및 상세 설계 산출물 부재
  - 한계점 : 안전진단 대상인 노후화된 공공·산업 시스템의 최신 설계 문서가 전무하여 역공학 및 블랙박스 테스트에 과도한 공수 소모.
  - 해결 방안 : 바이너리 디컴파일러, 런타임 eBPF(extended Berkeley Packet Filter) 패킷 분석 도구를 활용한 반자동 아키텍처 리버스 엔지니어링 절차 표준 수립.
- 한계점 3 : 진단 결과 도출된 개선 권고사항의 실행력 담보 한계
  - 한계점 : 안전 취약점이 진단되었음에도 운영 예산 부족, 서비스 중단 불가 등의 이유로 실제 소스코드 및 인프라 조치가 장기 방치.
  - 해결 방안 : 진단 후 안전 조치 이행 여부를 감리 및 정보화 성과평가와 연계, 고위험 결함에 대한 긴급 예산 편성 및 가상 패치(WAF(Web Application Firewall)/IPS(Intrusion Prevention System)) 우선 조치 체계 확립.

## Ⅵ. 공공 기반시설 안전 확보를 위한 기술사적 제언

- 핵심 요약 : 진단 후속 조치 예산의 제도화와 국제 기능안전 표준과의 정합성 확보.
- 진단 결과를 반영한 소프트웨어 리팩토링 예산 공식 배정 : 많은 공공기관이 안전진단을 수행하고도 후속 결함 조치 예산이 없어 취약점을 방치하는 문제가 발생하므로, 진단 후 '안전성 개선 유지보수 사업'을 별도 예산으로 편성할 수 있는 제도적 근거 마련 필수.
- ISO(International Organization for Standardization) 26262 및 IEC(International Electrotechnical Commission) 61508 등 도메인 국제 표준과의 정합성 유지 : 철도(IEC 62278), 항공(DO-178C), 의료(IEC 62304) 등 각 산업별 특수 표준의 기능안전성 요구사항을 NIPA 가이드라인 체크리스트에 1:1 매핑하여 글로벌 수준의 안전성 달성 지원.

## Ⅶ. 결론

- 핵심 요약 : SW 안전진단 가이드는 사회기반시설 소프트웨어의 재난 예방을 위한 국가 표준 진단 체계.
- 요약 : 4대 영역 진단 프레임워크와 위험도별 조치 권고를 통한 소프트웨어 안전성의 객관적 확보.
- 시사점 : 진단원 전문성 제도화, 레거시 역공학 표준화, 조치 이행 연계 감리의 병행이 진단 실효성 담보의 핵심.
