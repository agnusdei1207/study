## 30초 인출

- 본질: **SW 안전진단**은 소프트웨어 오작동이 국민 생활·안전에 미칠 위험을 시스템·운영기반·프로세스 측면에서 점검하고 개선하는 활동
- 메커니즘: 대상·위험 확인 → 안전기능·품질·코드와 운영기반·관리체계 진단 → 개선·재확인

<details>
<summary>핵심 용어</summary>

- **SW(Software)**: 소프트웨어
- **안전기능**: 위험 상황을 감지·제어해 위해를 줄이도록 설계한 기능
- **운영기반 안전성**: 데이터베이스·웹 서비스·시스템 구조 등 운영 환경의 위험 통제 상태
- **프로세스 안전성**: 구축·유지관리·운영 절차가 위험 통제를 지속하는지 확인하는 영역
- **NIPA(National IT Industry Promotion Agency, 정보통신산업진흥원)**: SW 안전진단 지원 사업과 가이드 자료를 제공하는 기관
</details>

## 2~4교시 25점 답안

## Ⅰ. SW 안전진단의 개요

| 구분 | 내용 |
|---|---|
| 정의 | **SW 안전진단**은 오작동에 따른 위해를 줄이기 위해 시스템·운영기반·프로세스를 점검하는 활동 |
| 목적 | 잠재 안전 위협을 찾아 개선하고 운영 중 통제의 지속성 확보 |

## Ⅱ. 세 진단 영역

```text
SW 안전진단
  ├─ 시스템(SW) 안전성
  │    └─ 안전기능·SW 품질·소스코드
  ├─ 운영기반 안전성
  │    └─ DBMS·WEB/WAS·구조
  └─ 프로세스 안전성
       └─ 구축체계·유지관리 및 운영
```

위 구조는 NIPA의 **2024년 SW 안전진단 지원 사업**에서 제시한 3개 영역·8개 항목. 개별 산업의 안전 표준이나 법정 인증 체계와 동일한 것으로 취급하지 않음.

## Ⅲ. 진단과 개선 절차

```text
대상 시스템·운영 환경·위험 확인
    ↓
안전기능·품질·코드 / 운영기반 / 관리 절차 점검
    ↓
미흡 항목·영향 범위 기록
    ↓
개선 조치 → 시험·재진단으로 확인
```

## Ⅳ. 적용 한계와 확인 사항

| 한계 | 확인·대응 |
|---|---|
| 체크리스트 완료만으로 안전성이 입증되지 않음 | 위험 상황에 대한 안전기능과 고장 시 동작을 시험 |
| 운영기반 장애가 안전기능을 무력화할 수 있음 | DBMS·WEB/WAS·구조의 장애 대응 확인 |
| 진단 뒤 개선 조치가 누락될 수 있음 | 조치 책임·기한·재검증 결과 추적 |

## Ⅴ. 제언

```text
위험 상황 → 안전기능·운영기반 진단 결과
                    ↓
              개선 조치·책임 지정
                    ↓
              재시험·재진단 증거
```

**제언:** 진단 항목의 충족 여부보다 발견 위험의 조치와 재검증 증거를 관리.
