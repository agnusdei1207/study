## Ⅰ. SW 안전진단 가이드의 개요

- **개념** : 과학기술정보통신부와 정보통신산업진흥원(NIPA)이 국민 생활 및 국가 핵심 기반시설에 도입된 소프트웨어의 오작동과 결함으로 인한 재난적 사고를 예방하기 위해, 소프트웨어 안전성을 객관적이고 체계적으로 진단할 수 있도록 정립한 국가 표준 가이드라인.
- **배경 및 필요성** : 전력, 교통, 의료, 수자원 등 사회 전반이 소프트웨어로 통제되는 초연결 사회에서 소프트웨어 오류가 대형 인명 피해나 국가 마비로 직결됨에 따라 체계적인 진단 프레임워크 필수.
- **진단 4대 영역** : 프로세스 안전성, 아키텍처 안전성, 소스코드 안전성, 시스템 실행환경 안전성.

## Ⅱ. SW 안전진단 프레임워크 4대 영역 및 진단 절차

```text
   [ 1. 진단 계획 수립 ] ──> [ 2. 현장 실사 및 데이터 수집 ] ──> [ 3. 4대 영역 심층 분석 ] ──> [ 4. 개선 조치 권고 ]
    - 진단 대상 시스템 선정   - 소스코드, 설계서, 형상 산출물     - 도구 기반 정적/동적 진단    - 위험도별(상/중/하) 조치
    - 인터뷰 일정 확정        - 운영 및 장애 이력 수집            - 전문가 정밀 인스펙션        - 최종 안전진단 보고서
```

```text
   ┌────────────────────────────────────────────────────────────────────────┐
   │ [ SW 안전진단 4대 핵심 영역 ]                                          │
   │                                                                        │
   │  [ 1. 프로세스 영역 ] ─ 안전 요구관리, 형상관리, 변경 통제 프로세스     │
   │  [ 2. 아키텍처 영역 ] ─ 단일장애점(SPOF) 제거, Fail-Safe, 워치독 타이머│
   │  [ 3. 소스코드 영역 ] ─ MISRA, CWE 보안약점, 메모리 누수, 동시성 오류  │
   │  [ 4. 실행환경 영역 ] ─ OS/미들웨어 패치, 하드웨어 이중화, 백업/복구    │
   └────────────────────────────────────────────────────────────────────────┘
```

## Ⅲ. SW 안전진단 점검 항목 상세 분석

| 진단 영역 | 핵심 점검 항목 | 주요 검증 방법 |
|---|---|---|
| 프로세스 안전성 | 안전 요구사항 추적성, 위험원 분석(FMEA/FTA) 수행 여부 | 산출물(SRS, RTM, 위험관리계획서) 정밀 감사 |
| 아키텍처 안전성 | 결함 허용(Fault Tolerance), 비상 정지 메커니즘, 모듈 격리 | 아키텍처 설계서(SAD) 검토 및 전문가 인터뷰 |
| 소스코드 안전성 | 버퍼 오버플로우, Null 역참조, 데드락, MISRA-C 코딩 규칙 준수 | 정적 코드 분석 도구(SAST: CodeScroll, Coverity) 전수 검사 |
| 실행환경 안전성 | 자원 고갈(CPU/메모리) 시 시스템 동작, 네트워크 단절 복원력 | 결함 주입 시험(Fault Injection), 스트레스 테스트 |

## Ⅳ. 공공 기반시설 안전 확보를 위한 기술사적 제언

- **진단 결과를 반영한 소프트웨어 리팩토링 예산 공식 배정** : 많은 공공기관이 안전진단을 수행하고도 후속 결함 조치 예산이 없어 취약점을 방치하는 문제가 발생하므로, 진단 후 '안전성 개선 유지보수 사업'을 별도 예산으로 편성할 수 있는 제도적 근거 마련 필수.
- **ISO 26262, IEC 61508 등 도메인 국제 표준과의 정합성 유지** : 철도(IEC 62278), 항공(DO-178C), 의료(IEC 62304) 등 각 산업별 특수 표준의 기능안전성 요구사항을 NIPA 가이드라인 체크리스트에 1:1 매핑하여 글로벌 수준의 안전성 달성 지원.
