## 연관 키워드

- CMMI(Capability Maturity Model Integration), 성숙도 레벨(Maturity Level), 능력 레벨(Capability Level), 프로세스 영역(PA, Process Areas)
- 단계적 표현(Staged Representation), 연속적 표현(Continuous Representation), SEI(Software Engineering Institute), CMMI 2.0, ALM(Application Lifecycle Management)

## Ⅰ. CMMI의 개요

- 핵심 요약 : 조직의 프로세스 성숙도를 평가·개선하기 위해 개별 성숙도 모델을 통합한 세계적 프로세스 개선 모델.
- 개념 : 미국 카네기멜론 대학교 소프트웨어 공학 연구소 SEI(Software Engineering Institute)에서 조직의 소프트웨어 개발 및 엔지니어링 프로세스 성숙도를 평가하고 지속적으로 개선하기 위해, 기존의 개별 능력 성숙도 모델(SW(Software)-CMM, SE-CMM, IPD-CMM)을 하나로 통합한 세계적인 소프트웨어 프로세스 개선 및 성숙도 평가 모델.
- 배경 및 필요성 : 개발자의 개인적 영웅주의에 의존하던 혼돈 상태의 프로젝트 관행 탈피, 조직 차원의 표준화·반복 가능·정량 통제 기반 예측 가능한 엔지니어링 프로세스 확립 필요.
- 평가 구조 : 5단계 성숙도 레벨(Maturity Level) 기반 단계적 표현(Staged)과 능력 레벨(Capability Level) 기반 연속적 표현(Continuous)의 이중 체계.

## Ⅱ. CMMI의 특징

- 핵심 요약 : 모델 통합과 이중 표현 체계, 프로세스 영역 기반의 단계적 성숙도 관리.

1. SW-CMM, SE-CMM, IPD-CMM 등 개별 능력 성숙도 모델의 통합 체계.
2. 5단계 성숙도 레벨 기반의 단계적 표현(Staged Representation).
3. 능력 레벨(Capability Level) 기반의 연속적 표현(Continuous Representation).
4. 프로세스 영역(PA, Process Areas) 단위의 평가와 개선 활동.
5. 프로젝트 단위 관리에서 조직 표준 프로세스로의 관리 주체 확대.
6. 정량적 측정과 통계적 통제에 기반한 예측 가능한 품질 관리.

## Ⅲ. CMMI의 구조 (흐름)

- 핵심 요약 : 초기 단계부터 최적화 단계까지 상향하는 5단계 성숙도 계층 구조.
- 5단계 성숙도 레벨 계층 구조.

```text
[ Level 5: 최적화 단계 ]
 - Optimizing
 - 통계적 프로세스 제어 기반의
   지속적 혁신 및 결함 예방
    ▲
[ Level 4: 정량적 관리 ]
 - Quantitatively Managed
 - 프로세스와 제품 품질의
   정량적 측정 및 통계적 통제
    ▲
[ Level 3: 정의 단계 ]
 - Defined
 - 조직 차원의 전사 표준
   프로세스 정립 및 테일러링
    ▲
[ Level 2: 관리 단계 ]
 - Managed
 - 프로젝트 단위의 기본적 관리
   (요구관리, 계획, 형상관리)
    ▲
[ Level 1: 초기 단계 ]
 - Initial
 - 프로세스 부재, 혼돈(Chaos),
   개인의 역량에 전적 의존
```

- 레벨 상승 메커니즘 : 프로젝트 단위 기본 관리의 조직 표준화, 표준 프로세스의 정량 통제, 통계 기반 혁신의 단계적 확장.

## Ⅳ. 성숙도 레벨별 핵심 프로세스 영역의 비교

- 핵심 요약 : 레벨 2의 프로젝트 관리에서 레벨 5의 조직 최적화로 PA 초점의 단계적 확대.
- 단계적 표현과 연속적 표현의 판정 단위 차이.

```text
[ 단계적 표현 ]                     [ 연속적 표현 ]
 조직 전체 성숙도 레벨 판정           PA별 능력 레벨 산정
 (5단계 등급 일괄 부여)              (개별 프로세스 개선 추적)
```

| 성숙도 레벨 | 핵심 포커스 | 대표 프로세스 영역(PA, Process Areas) |
|---|---|---|
| Level 1: Initial | 예측 불가능한 결과, 위기 관리 | 특정 프로세스 영역 없음 |
| Level 2: Managed | 프로젝트 단위의 체계화 및 반복성 | REQM(요구관리), PP(프로젝트계획), PMC(프로젝트감시통제), CM(형상관리), PPQA(품질보증) |
| Level 3: Defined | 전사적 표준화 및 프로세스 자산화 | RD(요구개발), TS(기술솔루션), VER(검증), VAL(확인), DAR(의사결정분석), OT(Organizational Training, 조직훈련) |
| Level 4: Quantitatively Managed | 데이터에 기반한 통계적 통제 | QPM(정량적 프로젝트관리), OPP(조직 프로세스 성과) |
| Level 5: Optimizing | 지속적 혁신 및 프로세스 자가 최적화 | CAR(원인분석과 해결), OPM(조직 성과관리) |

## Ⅴ. CMMI의 장점과 한계

- 핵심 요약 : 프로세스 표준화·예측 가능성 확보의 장점, 형식적 서류·애자일 마찰·비용 부담의 한계.
- 장점
  1. 조직 차원의 표준화되고 반복 가능한 프로세스 확립.
  2. 정량적 측정 기반의 예측 가능한 품질·일정 관리.
  3. 레벨 기반 성숙도 로드맵을 통한 지속적 개선 체계.
  4. 국방·공공 발주 대응의 조직 신뢰도 및 수주 경쟁력.
- 한계점 1 : 인증 획득만을 위한 형식적 산출물 양산(Paperwork Overload)
  - 한계점 : 심사 통과 목적의 실무 개발 무관 형식 문서·증빙 급조로 인한 조직 생산성 급감 및 구성원 피로도 누적.
  - 해결 방안 : ALM(Application Lifecycle Management) 및 CI/CD(Continuous Integration/Continuous Delivery) 도구 산출물(커밋 로그, 코드 리뷰 이력, 빌드 보고서)의 심사 증적 자동 대체.
- 한계점 2 : 빠른 피드백 중시의 애자일·DevOps 엔지니어링 문화와의 마찰
  - 한계점 : 전통적 CMMI의 엄격한 프로세스 통제와 단계별 승인 절차의 자율적 팀 의사결정·신속 릴리스 주기와의 정면 충돌.
  - 해결 방안 : CMMI V2.0의 애자일/스크럼 통합 프랙티스 적극 수용, 가치 인도 속도를 저해하지 않는 경량화 품질 프로세스 테일러링.
- 한계점 3 : 프로세스 심사·컨설팅에 수반되는 막대한 비용과 시간
  - 한계점 : 공인 심사원 초빙, 갭 분석, 사전 심사 등 인증 획득까지의 막대한 비용과 수개월 기간으로 인한 중소 SW 기업 진입 장벽.
  - 해결 방안 : 전사 전면 도입 대신 핵심 프로젝트 중심 파일럿 도입, 정부 중소기업 CMMI 인증 지원 사업 연계, 필수 실무 영역(PA) 선별 개선.

## Ⅵ. 현대 엔지니어링 환경에서의 기술사적 제언

- 핵심 요약 : CMMI 2.0과 애자일·DevOps의 실용적 조화 및 도구 기반 실질 내재화.
- CMMI 2.0 버전과 애자일/DevOps의 실용적 조화 : CMMI 1.3의 무거운 문서주의·관료주의적 감사 비판 수용, 스크럼·CI/CD·자동화 테스트 연계 지향, '문서를 위한 프로세스'가 아닌 '품질과 속도를 높이는 엔지니어링 프로세스' 테일러링 필요.
- 국방 및 공공 SW 수주 경쟁력 확보와 실질적 프로세스 내재화 : 입찰 참여용 형식적 스펙 쌓기 지양, 형상관리(Git)와 ALM 도구(Jira)에 요구사항 추적성·리스크 관리 기준의 워크플로우 자동 구현을 통한 전사적 엔지니어링 성숙도 체질 개선.

## Ⅶ. 결론

- 핵심 요약 : 인증 중심 도입이 아닌 엔지니어링 성숙도 개선 수단으로의 CMMI 활용 필요.
- 요약 : 5단계 성숙도 체계와 PA 기반 평가를 통한 조직 프로세스 개선 모델.
- 시사점 : 증적 자동화, 경량 테일러링, 도구 워크플로우 내재화를 통한 실질적 성숙도 향상 필요.
