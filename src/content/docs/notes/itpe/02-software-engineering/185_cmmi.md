## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 프로세스 개선 → **CMMI(Capability Maturity Model Integration)**

## 30초 인출

- 본질: CMMI는 조직의 개발 프로세스 성숙도를 5단계로 평가하고 단계별 개선 방향을 제시하는 프로세스 개선 모델
- 메커니즘: 프로세스를 진단해 현재 성숙도 수준을 정하고 다음 수준의 프로세스 영역을 갖추어 초기에서 최적화까지 단계적으로 개선
- 통찰: 수준 인증 자체를 목표로 하면 문서만 갖춘 형식적 프로세스가 되므로 프로젝트의 실제 문제에 맞는 프로세스 영역부터 개선하고 실행 결과로 성과를 확인

<details>
<summary>핵심 용어</summary>

- **CMMI(Capability Maturity Model Integration)** : 프로세스 성숙도 모델을 통합한 프로세스 개선 모델
- **성숙도 수준(Maturity Level)** : 조직 전체 프로세스의 성숙 정도를 나타내는 단계
- **프로세스 영역(Process Area)** : 관련 실무를 묶은 프로세스 관리 단위
- **단계적 표현(Staged)** : 성숙도 수준을 순서대로 올려가는 표현 방식
- **연속적 표현(Continuous)** : 프로세스 영역별로 능력 수준을 따로 높이는 표현 방식
- **정량적 관리** : 통계 기법으로 프로세스 성과를 관리하는 활동

</details>

## 2~4교시 25점 답안

## Ⅰ. CMMI의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **CMMI** 는 조직의 프로세스 성숙도를 평가하고 개선 방향을 제시하는 모델 |
| 목적 | 예측 가능한 프로젝트 수행과 품질 향상 |

## Ⅱ. 특징

| 특징 | 의미 |
|---|---|
| 단계적 개선 | 낮은 수준에서 높은 수준으로 |
| 프로세스 영역 | 요구 관리·계획·검증 등 영역별 실무 |
| 평가 기반 | 진단으로 현재 수준 파악 |

## Ⅲ. 성숙도 5단계

```text
5 최적화        ─ 지속적 프로세스 개선
4 정량적 관리    ─ 통계 기반 성과 관리
3 정의          ─ 조직 표준 프로세스
2 관리          ─ 프로젝트 단위 계획·통제
1 초기          ─ 개인 역량에 의존
```

## Ⅳ. 표현 방식의 비교

| 구분 | 단계적 표현 | 연속적 표현 |
|---|---|---|
| 기준 | 조직 전체 성숙도 수준 | 프로세스 영역별 능력 수준 |
| 개선 방식 | 수준을 순서대로 상승 | 필요한 영역 선택 개선 |
| 적합 조건 | 조직 전반의 체계 확립 | 특정 영역 문제 해결 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 인증 목적의 형식적 문서화 | 실제 프로젝트 문제에 맞는 프로세스 영역부터 개선 |
| 도입 비용·기간 부담 | 필요한 영역·수준 선택 |
| 소규모·애자일 조직과의 부조화 | 조직 특성에 맞춘 적용 |

## Ⅵ. 제언

프로젝트의 실제 문제와 관련된 프로세스 영역부터 개선하고 실행 결과로 성과를 확인

```text
문제 진단 → 관련 프로세스 영역 개선 → 결과 측정 → 다음 영역
```

| 구분 | 수준 인증 목표 | 제언: 문제 중심 개선 |
|---|---|---|
| 개선 초점 | 문서 | 실행 결과 |
| 성과 확인 | 수준 획득 | 결함·일정 지표 |
