## 30초 인출

- 본질: 오픈소스 소프트웨어는 소스 코드를 공개해 누구나 사용·수정·배포할 수 있게 한 소프트웨어이며 거버넌스는 조직이 이를 안전하게 쓰도록 정한 정책과 통제 체계
- 메커니즘: 도입 전 라이선스·취약점을 검토·승인하고 SBOM과 SCA로 사용 현황을 관리하며 취약점·라이선스 변화를 지속적으로 감시
- 통찰: 부서별로 오픈소스를 자유롭게 도입하면 라이선스·취약점 관리가 분산되어 위험이 드러나지 않으므로 전사 도입 정책과 승인 절차를 두고 SBOM·SCA로 사용 현황을 통제

<details>
<summary>핵심 용어</summary>

- **오픈소스 소프트웨어(OSS, Open Source Software)** : 소스 코드를 공개하고 자유로운 사용·수정·배포를 허용하는 소프트웨어
- **오픈소스 라이선스** : 사용·수정·배포 조건을 정한 라이선스
- **SCA(Software Composition Analysis)** : 사용 중인 오픈소스 구성요소와 그 라이선스·취약점을 식별하는 분석
- **SBOM(Software Bill of Materials)** : 소프트웨어를 구성하는 구성요소 목록
- **OpenChain(ISO/IEC 5230)** : 오픈소스 컴플라이언스 프로세스의 국제 표준
- **오픈소스 거버넌스** : 도입·사용·기여를 통제하는 정책과 조직 체계

</details>

## 2~4교시 25점 답안

## Ⅰ. 오픈소스 소프트웨어의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **오픈소스 소프트웨어** 는 소스 코드를 공개해 자유로운 사용·수정·배포를 허용하는 소프트웨어 |
| 목적 | 개발 비용 절감과 협업을 통한 소프트웨어 발전 |

## Ⅱ. 상용 소프트웨어와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 소스 공개 | 코드 열람·수정 가능 |
| 조건부 사용 | 라이선스 조건 준수 |
| 커뮤니티 중심 | 다수 참여자의 개발·검증 |
| 공급자 지원 한계 | 기술 지원의 별도 확보 필요 |

## Ⅲ. 오픈소스 거버넌스 체계

### 거버넌스 체계

```text
오픈소스 거버넌스
    ├─ 정책 ── 허용 라이선스·도입 기준
    ├─ 절차 ── 도입 검토·승인
    ├─ 도구 ── SCA·SBOM
    └─ 조직 ── 검토 담당·교육
```

### 확대: 도입 승인 흐름

```text
도입 요청
    ↓
라이선스·취약점 점검 (SCA)
    ├─ 허용 기준 충족 → 승인·SBOM 등록
    └─ 미충족 → 대체안 또는 예외 승인
```

## Ⅳ. 활용의 이점과 위험

| 구분 | 내용 |
|---|---|
| 이점 | 비용 절감, 빠른 개발, 검증된 기술 재사용 |
| 라이선스 위험 | 소스 공개 의무, 조건 위반 |
| 보안 위험 | 알려진 취약점의 전파 |
| 유지 위험 | 프로젝트 중단·기술 지원 부재 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 부서별 개별 도입으로 사용 현황 파악 곤란 | SBOM으로 전사 사용 현황 관리 |
| 라이선스 위반·취약점 인지 지연 | SCA 자동 점검과 지속적 감시 |
| 프로젝트 중단 위험 | 핵심 오픈소스의 대체·지원 계획 |

## Ⅵ. 제언

전사 도입 정책과 승인 절차를 두고, SBOM과 SCA로 사용 현황과 위험을 지속적으로 확인

### 통제 순환

```text
도입 요청 → 승인 → SBOM 등록
    ↓
SCA로 취약점·라이선스 지속 점검
    ↓
이상 발견 → 조치·SBOM 갱신
```

### 확대: 지속 점검

```text
신규 취약점 공개
    ↓
SBOM으로 영향 시스템 식별 → 패치·대체
```

### 선택 근거: 부서별 자율 관리와의 비교

| 구분 | 부서별 자율 | 제언: 전사 정책·승인 |
|---|---|---|
| 사용 현황 | 파악 곤란 | SBOM 관리 |
| 위험 대응 | 지연 | 즉시 식별 |
| 통제 비용 | 낮음 | 체계 운영 필요 |
