## Ⅰ. 오픈소스 소프트웨어(OSS) 및 거버넌스의 개요

- **개념** : 소스코드가 대중에게 공개되어 누구나 자유롭게 사용, 수정, 재배포할 수 있는 오픈소스 소프트웨어(OSS)를 기업 시스템에 안전하고 효과적으로 도입하기 위해, 라이선스 법적 컴플라이언스, 보안 취약점 관리, 사내 기여 및 커뮤니티 협업을 전사적으로 통제하고 육성하는 종합 관리 체계.
- **배경 및 필요성** : 현대 소프트웨어의 80~90%가 오픈소스 라이브러리를 기반으로 조립되고 있으나, 무분별한 사용 시 카피레프트 전염(기업 지적재산권 강제 공개), Log4j 사태와 같은 공급망 보안 취약점(Supply Chain Attack) 위험에 직면.
- **핵심 관리 축** : 라이선스 컴플라이언스(Legal), 소프트웨어 공급망 보안(Security), 이너소스 및 기여(Culture).

## Ⅱ. 기업 오픈소스 거버넌스 프레임워크 및 OSPO 운영 체계

```text
   ┌────────────────────────────────────────────────────────────────────────┐
   │ [ 오픈소스 프로그램 오피스 (OSPO, Open Source Program Office) ]        │
   │  - 오픈소스 전략 수립, 법무/보안/개발 부서 간 협업 조율, 정책 수립    │
   └──────────────────┬──────────────────────────────────┬──────────────────┘
                      │                                  │
                      ▼                                  ▼
   ┌──────────────────────────────────┐┌──────────────────────────────────┐
   │ [ 1. 라이선스 컴플라이언스 ]     ││ [ 2. 공급망 보안 취약점 관리 ]   │
   │  - 오픈소스 식별 및 자재명세서   ││  - CVE/NVD 취약점 실시간 매핑    │
   │    (SBOM: SPDX, CycloneDX) 생성  ││  - 의존성 취약점 자동 패치(Snyk) │
   │  - 의무사항(고지문, 소스공개)준수 ││  - 악성 패키지 유입 차단         │
   └──────────────────────────────────┘└──────────────────────────────────┘
                      │                                  │
                      └────────────────┬─────────────────┘
                                       │
                                       ▼
   ┌────────────────────────────────────────────────────────────────────────┐
   │ [ DevSecOps CI/CD 파이프라인 자동화 (SCA 도구 연계) ]                  │
   │  커밋/빌드 시 FOSSID, Black Duck, Dependabot을 통한 자동 검증 및 차단   │
   └────────────────────────────────────────────────────────────────────────┘
```

- **OSPO (Open Source Program Office)** : 기업의 오픈소스 사용, 배포, 기여 활동을 전담 지원하는 전문 조직.
- **SBOM (Software Bill of Materials)** : 소프트웨어를 구성하는 모든 오픈소스 컴포넌트의 이름, 버전, 라이선스, 해시값을 명시한 디지털 자재명세서 (미국 행정명령 14028호 및 국내 가이드라인 의무화 추세).

## Ⅲ. 오픈소스 거버넌스 3대 관리 영역 비교

| 영역 | 핵심 목적 | 주요 통제 활동 | 대표 도구 |
|---|---|---|---|
| 컴플라이언스 (Legal) | 저작권 침해 방지 및 라이선스 의무사항 준수 | 카피레프트(GPL) 전염 방지, 오픈소스 고지문(Notice) 자동 생성 | Black Duck, FOSSID, FOSSA |
| 공급망 보안 (Security) | 기 알려진 취약점(CVE) 및 악의적 코드 유입 차단 | 취약 라이브러리 탐지, CVSS 점수 기반 차단, 패치 버전 자동 제안 | Snyk, Mend, GitHub Dependabot |
| 커뮤니티 & 기여 (Culture) | 사내 개발 문화 혁신 및 오픈소스 생태계 주도 | 이너소스(InnerSource) 활성화, 외부 오픈소스 프로젝트 컨트리뷰션 | GitHub Enterprise, CLA 관리 도구 |

## Ⅳ. 엔터프라이즈 오픈소스 거버넌스 구축을 위한 기술사적 제언

- **CI/CD 파이프라인 내 소프트웨어 구성 분석(SCA) 품질 게이트 의무화** : 개발자가 `pom.xml`이나 `package.json`에 신규 라이브러리를 추가할 때마다, 빌드 파이프라인에서 SCA 도구를 자동 구동하여 고위험 라이선스(AGPL)나 CVSS 7.0 이상의 심각한 보안 취약점 발견 시 빌드를 즉시 중단하는 자동화된 통제 체계 수립 필수.
- **표준 SBOM 생성 및 취약점 악용 가능성 교환(VEX) 연계** : CycloneDX 표준 포맷의 SBOM을 빌드 아티팩트와 함께 의무 생성하여 고객사에 납품하고, 실제 시스템에서 해당 취약 함수가 호출되는지 여부를 명시하는 VEX(Vulnerability Exploitability eXchange)를 연동하여 불필요한 보안 조치 오버헤드 최소화.
