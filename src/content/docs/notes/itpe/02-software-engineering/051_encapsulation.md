소프트웨어 공학 → 객체지향·모듈화 → **캡슐화(Encapsulation)**

## 30초 인출

- 본질: 캡슐화는 데이터와 그 데이터를 다루는 연산을 하나의 클래스로 묶고 접근 제어자로 외부 접근을 제한하는 객체지향 기법
- 메커니즘: 필드를 private으로 두고 공개 메서드로만 상태를 바꾸게 해 객체 스스로 불변식(항상 성립해야 하는 조건)을 지킴
- 통찰: 가변 객체(리스트 등)를 그대로 반환하면 외부에서 내부 상태를 바꿀 수 있어 캡슐화가 깨지므로 방어적 복사나 불변 객체로 반환

<details>
<summary>핵심 용어</summary>

- **캡슐화(Encapsulation)** : 데이터와 연산을 하나로 묶고 접근을 제한하는 기법
- **정보은닉(Information Hiding)** : 변경 가능성이 큰 내부 구현을 감추는 설계 원칙. 캡슐화가 그 수단
- **접근 제어자** : public·protected·default·private처럼 멤버의 접근 범위를 정하는 키워드
- **불변식(Invariant)** : 객체가 존재하는 동안 항상 참이어야 하는 조건
- **방어적 복사(Defensive Copy)** : 가변 객체를 주고받을 때 복사본을 사용해 내부 상태 노출을 막는 방법
- **묻지 말고 시켜라(Tell, Don't Ask)** : 객체의 상태를 꺼내 판단하지 않고 객체에 동작을 요청하라는 설계 지침

</details>

## 2~4교시 25점 답안

## Ⅰ. 캡슐화의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **캡슐화** 는 데이터와 연산을 하나의 클래스로 묶고 접근 제어자로 외부 접근을 제한하는 기법 |
| 목적 | 객체 상태의 무결성 보호와 내부 변경의 영향 차단 |

## Ⅱ. 캡슐화의 특징

| 특징 | 의미 |
|---|---|
| 데이터·연산 결합 | 상태와 그 상태를 다루는 메서드를 한 곳에 배치 |
| 접근 제한 | 외부는 공개 메서드로만 접근 |
| 불변식 보호 | 객체가 스스로 유효한 상태 유지 |

## Ⅲ. 캡슐화의 구조와 접근 제어

### 캡슐화 구조

```text
외부 코드
    ↓ 공개 메서드만 호출
┌───────────────────┐
│ Account            │
│ + deposit(amount)  │
│ + withdraw(amount) │
│ ────────────────── │
│ - balance (private)│
└───────────────────┘
```

### 확대: 접근 제어자의 범위

```text
private   ── 같은 클래스 안
default   ── 같은 패키지 안
protected ── 같은 패키지 + 하위 클래스
public    ── 모든 곳
```

## Ⅳ. 정보은닉과의 관계, 노출 수준별 결과

### 정보은닉과 캡슐화

| 구분 | 캡슐화 | 정보은닉 |
|---|---|---|
| 성격 | 묶고 제한하는 구현 기법 | 무엇을 숨길지 정하는 설계 원칙 |
| 관계 | 정보은닉을 구현하는 수단 | 캡슐화로 실현 |

### 상태 노출 방식별 결과

| 노출 방식 | 불변식 보호 | 예 |
|---|---|---|
| 필드 공개 | 불가 | public balance |
| getter·setter | 호출자 책임 | setBalance(x) |
| 행위 메서드 | 객체 내부 보장 | withdraw(amount) |
| 가변 객체 그대로 반환 | 불가 | 내부 List 반환 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| getter·setter 남용으로 내부 상태 노출 | 행위 메서드로 상태 변경 |
| 가변 객체 반환·전달로 내부 상태 변경 | 방어적 복사 또는 불변 객체 반환 |
| 상태를 꺼내 외부에서 판단하는 코드 확산 | 객체에 동작을 요청하는 구조(Tell, Don't Ask) |

## Ⅵ. 제언

내부 가변 객체를 반환할 때는 방어적 복사나 읽기 전용 형태로 제공하고, 상태 변경은 검증이 있는 메서드로만 허용

### 노출 통제 구조

```text
내부 가변 상태(List 등)
    ↓
반환 시 복사본 또는 읽기 전용 뷰
    ↓
변경은 검증이 있는 메서드(addItem 등)로만
```

### 확대: 반환 방식 비교

```text
getItems() → 내부 List 그대로 반환 → 외부에서 수정 가능 (불변식 훼손)
getItems() → 복사본 반환          → 외부 수정이 내부에 영향 없음
```

### 선택 근거: 가변 객체 직접 반환과의 비교

| 구분 | 직접 반환 | 제언: 복사·읽기 전용 |
|---|---|---|
| 내부 상태 보호 | 불가 | 가능 |
| 불변식 | 훼손 가능 | 유지 |
| 비용 | 없음 | 복사 비용 |
