## 연관 키워드

- Web 2.0, 사용자 생성 콘텐츠(UGC, User-Generated Content), 집단 지성(Collective Intelligence)
- AJAX, Open API(Application Programming Interface), 폭소노미(Folksonomy), 네트워크 효과, 롱테일(Long Tail)

## Ⅰ. Web 2.0의 개요

- 핵심 요약 : Web 2.0은 이용자가 콘텐츠 제작·공유·평가에 참여하는 웹 이용·사업 패러다임 용어.
- 개념 : 이용자가 콘텐츠와 서비스 가치 형성의 주체가 되는 참여·공유 중심의 웹 패러다임을 설명하는 용어가 **Web 2.0**.
- 배경 및 필요성 : 통신 속도와 브라우저 기술의 향상, 개인 게시 수단의 보급으로 일방향 게시 이상의 상호 작용 수요 확대.
- 주요 목적 : 개방된 웹에서 참여·연결을 통한 공동 가치 형성과 플랫폼 생태계 확장.

## Ⅱ. Web 2.0의 특징 및 장점

- 핵심 요약 : 참여 데이터 축적, 집단 지성, 동적 화면, 개방 플랫폼이 네트워크 효과로 연결.

1. 사용자 생성 콘텐츠 : 게시·평가·공유에 참여하는 **사용자 생성 콘텐츠** (UGC, User-Generated Content) → 콘텐츠 다양성·최신성 확대 효과.
2. 집단 지성과 폭소노미 : 태그·평판·협업 필터링의 집계인 **집단 지성** (Collective Intelligence)과 이용자 주도 태그 분류인 **폭소노미** (Folksonomy) → 전문 분류자 없는 자생적 정보 분류 효과.
3. 동적 인터페이스 : **AJAX** (Asynchronous JavaScript and XML) 기반의 비동기 화면 갱신 → 데스크톱급 조작성 효과.
4. 개방 플랫폼 : **Open API** (Application Programming Interface) 형태의 기능·데이터 개방과 서비스 결합인 **매시업** (Mashup) → 생태계 확장 효과.
5. 네트워크 효과와 롱테일 : 이용자 증가가 서비스 가치를 키우는 **네트워크 효과**와 소수 수요를 결합하는 **롱테일** (Long Tail) 수익 구조 → 플랫폼 가치의 자기 강화 효과.

## Ⅲ. Web 2.0의 구조 (흐름)

- 핵심 요약 : 참여 입력 → 데이터 축적 → 검색·추천·API 제공 → 새 참여로 이어지는 환류 구조.

```text
이용자 참여 (게시·태그·평가)
   ↓ 활동 데이터의 축적
플랫폼 (저장·연결·추천)
   ↓ 검색·추천·API 제공
다른 이용자의 발견·재이용
   ↺ 새로운 참여로 환류
```

```text
이용자 수 증가
   ↓ 콘텐츠·관계 데이터 증가
서비스 가치 증대
   ↓ 신규 이용자 유인
이용자 수 증가 (순환)
```

- Web 2.0은 정식 표준 버전 번호가 아니라 서비스 변화를 설명하는 용어.

## Ⅳ. Web 2.0과 정적 Web 1.0의 비교

- 핵심 요약 : 콘텐츠 생성 주체와 정보 흐름 방향이 Web 2.0과 정적 Web 1.0의 근본 구분.

| 비교 축 | Web 2.0 | 정적 Web 1.0 |
| --- | --- | --- |
| 콘텐츠 생성 | 이용자 생성·공동 편집 | 운영자의 일방향 게시 |
| 정보 흐름 | 쌍방향·참여형 | 게시자에서 방문자로 단방향 |
| 화면 조작 | AJAX 기반의 동적 갱신 | 문서 이동 중심 |
| 가치 원리 | 네트워크 효과·참여 데이터 | 게시물 수·방문 수 |
| 서비스 형태 | 플랫폼·API의 개방 | 폐쇄형 사이트 |

- Web 3.0은 시맨틱 웹·분산 서비스 등 정의가 갈리는 흐름 명칭이라 본 비교에서 제외.

## Ⅴ. Web 2.0의 한계와 방안

- 핵심 요약 : 데이터 집중, 허위 정보, 플랫폼 종속, 참여 편향을 이용자 권리·품질 체계로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 개인정보·데이터 집중 | 플랫폼의 활동 데이터 축적 → 권리 침해 위험 | 최소 수집·이동권·접근 통제 | 개인정보 점검 준수율 |
| 허위 정보·품질 편차 | 개방 게시·빠른 확산 → 오정보 피해 | 출처 표시·신고·검증 체계 | 허위 정보 조치율 |
| 플랫폼 종속 고착 | 네트워크 효과의 집중 → 이용자 이동 제약 | 상호 운용 API·데이터 이동 지원 | 데이터 이동 처리율 |
| 참여 편향 | 소수 적극 사용자 중심 반영 → 대표성 왜곡 | 접근성·다양한 피드백 경로 | 참여자 분포 점검 |

## Ⅵ. 플랫폼 운영에 대한 기술사적 제언

- 핵심 요약 : 플랫폼 운영 조직은 이용자 권리·콘텐츠 책임·개방 API 기준의 서비스 설계 원칙 제도화 필요.
1. 데이터 책임 조직은 목적 제한, 보존 기간, 삭제·이동 요청 절차의 제품 설계 반영.
2. 운영 조직은 신고·추천 정책의 투명성 제고와 개방 API의 보안·호환성 기준 공개.

## Ⅶ. 결론

- 핵심 요약 : Web 2.0은 이용자를 웹 가치 형성의 참여자로 보는 패러다임 용어.
- 시사점 : 참여 확대가 개방성을 자동 보장하지 않으므로 권리·책임 구조가 성숙도 판단 기준.
