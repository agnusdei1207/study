## 연관 키워드
- 로우코드, 노코드, 시민 개발자, 시각적 모델링, BPMN, 섀도우 IT, 벤더 종속

### Ⅰ. 로우코드·노코드의 개요

- 핵심 요약 : 로우코드·노코드는 시각적 모델과 사전 구축 컴포넌트로 애플리케이션을 구성해 수작업 코딩을 줄이는 개발 플랫폼 접근.
- 개념 : 드래그 앤 드롭·모델·설정 기반 개발로 각각 일부 또는 대부분의 직접 코딩을 줄이는 방식(**로우코드·노코드**, Low-Code/No-Code, LCNC).
- 배경 및 필요성 : 디지털 서비스 수요 증가와 개발 인력 제약으로 현업 요구의 빠른 구현 요구.
- 주요 목적 : 표준 업무 애플리케이션과 워크플로우의 개발 리드 타임 단축.

### Ⅱ. 로우코드·노코드의 특징 및 장점

- 핵심 요약 : 추상화된 구성 요소와 시각적 워크플로우가 반복 개발을 단순화하나 플랫폼의 실행 모델에 의존.

1. 시각적 모델링 : 화면·데이터·흐름을 모델로 조립 → 프로토타입과 단순 업무 앱의 구현 속도 향상.
2. 재사용 컴포넌트 : 플랫폼이 인증·UI·연계 모듈을 제공 → 반복 구현과 표준 편차 축소.
3. 현업 참여 : 시민 개발자가 업무 규칙을 직접 모델링 → 요구 전달 지연 감소와 업무 적합성 개선.

### Ⅲ. 로우코드·노코드 개발의 구조 (흐름)

- 핵심 요약 : 업무 요구와 데이터 경계 확인 → 플랫폼 모델 구성 → 표준 컴포넌트·API 연계 → 검증·승인 → 배포·모니터링.

```text
현업 요구·업무 규칙
   ↓
시각적 화면·데이터·워크플로우 모델
   ↓
표준 컴포넌트·API 연계
   ↓
보안·품질·업무 검증
   ↓
배포·권한 관리·운영 모니터링
```

- 거버넌스 : IT 부서는 플랫폼·보안·통합 기준을 제공하고 현업 개발 산출물은 정식 자산 목록과 변경 관리 대상에 포함.

```text
시민 개발자 ─ 업무 앱 모델 ─ LCNC 플랫폼
        │                    │
        └─ IT 가드레일 ─ 보안·API·운영 승인
```

### Ⅳ. 로우코드와 노코드 비교

- 핵심 요약 : 로우코드는 확장 개발을 일부 허용하고, 노코드는 비개발자 중심으로 추상화·통제를 더 높이는 경향.

| 비교 기준 | 로우코드 | 노코드 |
|---|---|---|
| 사용자 | 개발자·기술 숙련 현업 | 비개발 현업 사용자 중심 |
| 확장성 | 코드·커넥터 등으로 확장 가능 | 플랫폼이 제공하는 범위 내 구성 |
| 적합 업무 | 복합 연계·맞춤 로직 포함 업무 | 표준화된 양식·승인·간단 업무 앱 |

### Ⅴ. 로우코드·노코드의 한계와 방안

- 핵심 요약 : 벤더 종속·섀도우 IT·확장 한계를 아키텍처 검토와 현업·IT 공동 거버넌스로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 벤더 종속 | 전용 모델·런타임으로 이전 비용 증가 | 데이터·모델 내보내기 가능성, 종료 조항, 대체 경로 사전 검토 | 이전 소요 시간·전용 기능 비중 |
| 섀도우 IT | 현업 앱이 보안·개인 정보 검토 없이 확산 | 환경 승인·앱 등록·권한·데이터 분류 기준 마련 | 미등록 앱·정책 위반 |
| 성능·확장 제약 | 플랫폼 추상화가 고 부하·복잡 로직에 부적합 | 성능 시험, 외부 서비스 분리, 일반 개발 전환 기준 설정 | 응답 시간·처리량 한계 |

### Ⅵ. 로우코드·노코드의 제언

- 핵심 요약 : CIO와 현업 책임 자는 업무 복잡도와 데이터 민감도에 따른 허용 범위를 정하고 플랫폼 운영을 제품처럼 관리.

1. IT 아키텍처 위원회 는 LCNC 적용 적합 업무·금지 데이터·외부 연계 기준을 공표.
2. 현업 부서 는 업무 소유자와 앱 유지 관리자를 지정 하고 변경·폐기 책임을 명확화.
3. 플랫폼 팀 은 재사용 템플릿·보안 가드레일·교육·이관 경로를 제공.

### Ⅶ. 로우코드·노코드의 결론

- 핵심 요약 : LCNC는 코딩 추상화와 시각적 조립을 통해 일부 애플리케이션 개발을 가속하는 플랫폼 방식.
- 시사점 : 개발 민주화가 지속 가능한 혁신이 되려면 자율 개발과 기업 통제의 균형이 필수.
