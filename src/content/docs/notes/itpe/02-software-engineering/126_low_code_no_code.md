## 연관 키워드

- 로우코드, 노코드, LCNC, 시민 개발자, 시각적 모델링
- BPMN, 섀도우 IT, 벤더 종속

## Ⅰ. 로우코드·노코드의 개요

- 핵심 요약 : **로우코드**(Low-Code)와 **노코드**(No-Code)는 시각적 조립과 사전 구축 컴포넌트로 응용을 구성해 직접 코딩량을 줄이는 개발 플랫폼 방식.
- 개념 : 화면·데이터·절차를 모델과 설정으로 조립해 응용을 구성하는 플랫폼 개발 방식의 통칭 **LCNC**(Low-Code/No-Code)이며, 코드 보완형 로우코드와 비코딩형 노코드로 구분.
- 배경 및 필요성 : 디지털 전환으로 업무 응용 수요가 개발 인력 공급을 초과하고 표준 업무 자동화의 신속 구현 요구 증대.
- 주요 목적 : 표준 업무 응용·워크플로우의 개발 리드 타임 단축과 현업 주도 응용 개발의 확산.

## Ⅱ. 로우코드·노코드의 특징 및 장점

- 핵심 요약 : 시각적 조립·재사용 컴포넌트·업무 절차 자동화가 구현 속도와 표준 일관성이라는 이익으로 연결.

1. **시각적 모델링**(Visual Modeling, 화면·데이터·흐름을 그래픽 모델로 표현·조립하는 방식) : 드래그 앤 드롭 조립 → 구현 속도 향상·요구 검증 용이.
2. 재사용 컴포넌트·템플릿 : 인증·UI·시스템 연계 모듈의 사전 제공 → 반복 구현 제거·표준 편차 감소.
3. 워크플로우 자동화 : **BPMN**(Business Process Model and Notation, 업무 절차를 표준 기호로 모델링하는 표기법) 기반 절차 정의 → 승인·분기 절차의 신속 자동화.
4. 시민 개발자 참여 : **시민 개발자**(Citizen Developer, 전문 개발 교육 없이 플랫폼으로 응용을 구성하는 현업 인력)의 직접 모델링 → 요구 전달 지연 감소·업무 적합성 향상.

## Ⅲ. 로우코드·노코드 개발의 구조 (흐름)

- 핵심 요약 : 업무 요구·데이터 경계 확인에서 모델 구성·검증을 거쳐 배포·모니터링으로 이어지는 흐름.

```text
[ LCNC 응용 개발 흐름 ]

업무 요구·데이터 분류 확인
   ↓
화면·데이터·워크플로우 모델 구성
   ↓
표준 컴포넌트·API 연계
   ↓
보안·품질·업무 검증
   ↓
배포·자산 등록·운영 모니터링
```

- 운영 구분 : IT 조직의 플랫폼·보안·연계 기준 제공과 현업 산출물의 정식 자산 목록·변경 관리 편입 → 자율 개발과 통제의 병행.

```text
[ LCNC 운영 거버넌스 ]

시민 개발자 : 업무 응용 모델링
   ↓
IT 가드레일 : 권한·보안·연계 검토
   ↓
플랫폼 : 배포·자산 목록 등록
   ↓
운영 : 모니터링·변경 관리
```

## Ⅳ. 로우코드·노코드와 전통 코딩 중심 개발의 비교

- 핵심 요약 : 모델 조립 중심의 LCNC와 언어 직접 작성의 전통 코딩 중심 개발은 구현 방식·인력·리드 타임·제어 정밀도에서 차이.

| 비교 축 | 로우코드·노코드 | 전통 코딩 중심 개발 |
| --- | --- | --- |
| 구현 방식 | 시각적 모델·설정·컴포넌트 조립 | 프로그래밍 언어의 직접 작성 |
| 주요 인력 | 시민 개발자·현업 참여 | 전문 개발자 중심 |
| 리드 타임 | 표준 업무 응용의 신속 구현 | 설계·구현·시험 전 주기 소요 |
| 제어 정밀도 | 플랫폼 제공 범위 내 제한 | 로직·성능·아키텍처의 정밀 제어 |
| 적합 영역 | 양식·승인·연계형 표준 업무 | 고부하·고복잡도·핵심 시스템 |

## Ⅴ. 로우코드·노코드의 한계와 방안

- 핵심 요약 : 벤더 종속·섀도우 IT·확장 제약을 이관 검토·등록 체계·전환 기준으로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **벤더 종속**(Vendor Lock-in, 특정 플랫폼의 전용 모델·런타임 의존) | 이전 비용 증가·가격 협상력 약화 | 데이터·모델 내보내기 검증·계약 종료 조항·대체 경로 검토 | 이전 소요 비용·전용 기능 비중 |
| **섀도우 IT**(Shadow IT, 보안·품질 검토 없이 확산되는 현업 자체 응용) | 정보 유출·중복 투자·관리 공백 | 응용 등록·권한·데이터 분류 체계 운영 | 미등록 응용 수 |
| 확장·성능 제약 | 플랫폼 추상화로 고부하·복잡 로직 부적합 | 성능 기준 초과 시 일반 개발 전환 기준 운영 | 기준 초과 응용 수 |

## Ⅵ. 로우코드·노코드의 제언

- 핵심 요약 : 경영·IT 조직은 적용 범위·데이터 기준·운영 체계를 공표하고 플랫폼을 제품처럼 관리하는 거버넌스 필요.

1. IT 아키텍처 위원회는 LCNC 적용 업무·금지 데이터·외부 연계 기준의 공표.
2. 플랫폼 운영 조직은 재사용 템플릿·보안 가드레일·교육·이관 경로의 제공 체계 구축.
3. 현업 부서는 응용별 업무 소유자·유지 관리자 지정과 변경·폐기 책임의 명확화.

## Ⅶ. 로우코드·노코드의 결론

- 핵심 요약 : LCNC는 코딩 부담의 추상화로 응용 개발 참여를 확대하는 플랫폼 방식.
- 시사점 : 자율 개발의 이익은 거버넌스와 유지 책임이 확립된 조직에서 지속 가능.
