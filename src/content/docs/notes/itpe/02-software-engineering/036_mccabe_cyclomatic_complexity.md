## 연관 키워드

- McCabe 순환복잡도(Cyclomatic Complexity), 제어 흐름 그래프(CFG, Control Flow Graph), 기본 경로(Basis Path)
- 기본 경로 테스팅(Basis Path Testing), 인지 복잡도(Cognitive Complexity), 품질 게이트(Quality Gate), 정적 분석(Static Analysis)

## Ⅰ. McCabe 순환복잡도의 개요

- 핵심 요약 : 제어 흐름 그래프 위의 독립 경로 수를 정량화해 테스트 케이스의 하한과 리팩토링 기준을 제시하는 메트릭.
- 개념 : 토머스 맥케이브(Thomas McCabe)가 1976년 제안한 복잡도 측정 메트릭으로, **McCabe 순환복잡도** (Cyclomatic Complexity)는 프로그램의 **제어 흐름 그래프** (CFG, Control Flow Graph)에서 선형적으로 독립적인 **기본 경로** (Basis Path)의 수를 계산한 값.
- 배경 및 필요성 : 소스코드의 길이(LOC, Lines of Code)만으로는 논리적 난이도와 결함 위험을 측정할 수 없으므로, 테스트 케이스의 최소 수량과 리팩토링 기준을 객관적으로 세울 필요가 있음.
- 주요 목적 : 구조적 테스트의 케이스 수 산출, 코드 리뷰와 리팩토링 대상 선별.

## Ⅱ. McCabe 순환복잡도의 특징

- 핵심 요약 : 세 가지 상호 동등한 계산 방식을 갖는 구조적 복잡도 척도로, 테스트 하한과 품질 게이트에 직접 연결되는 특징.

1. 독립 경로 수 산출 : 제어 흐름 그래프에서 선형적으로 독립된 경로의 수를 셈 → 경로 기반 테스트의 기준선 확보.
2. 세 가지 계산 공식 : 간선과 노드, 영역, 술어 노드 기준으로 같은 값을 계산 → 도구와 상황에 따른 계산 방식 선택 가능.
3. **기본 경로 테스팅** (Basis Path Testing)의 하한 제시 : 복잡도 값만큼의 독립 경로를 덮는 테스트 케이스가 최소 기준 → 테스트 누락 방지.
4. 리팩토링 대상 선별 : 수치가 높은 모듈을 객관적으로 골라내 코드 리뷰 우선순위 결정.
5. 정적 분석 도구 연동 : **품질 게이트** (Quality Gate)에 임계치를 걸어 자동 검사 가능.

## Ⅲ. McCabe 순환복잡도의 구조 (흐름)

- 핵심 요약 : 분기 노드로 구성된 제어 흐름 그래프에서 간선·노드, 영역, 술어 노드 기준으로 V(G)를 산출하는 구조.
- 순환복잡도 V(G)의 세 가지 계산 공식은 다음과 같다.
  1. 간선·노드 기준 : V(G) = E − N + 2P (E는 간선 수, N은 노드 수, P는 연결된 컴포넌트 수로 단일 프로그램은 P=1이므로 E − N + 2).
  2. 영역 기준 : V(G) = R (그래프가 평면에서 둘러싸는 영역 수, 외부 영역 1개 포함).
  3. 술어 노드 기준 : V(G) = 술어 노드 수 + 1 (조건 분기가 일어나는 노드의 수에 1을 더함).

```text
[ 예시 : 조건문 2개의 순차 구조 ]

노드 1 : 진입
   ↓
노드 2 : 조건 A (술어 노드)
   ↓ True 또는 False
노드 3 또는 노드 4
   ↓
노드 5 : 두 분기 합류
   ↓
노드 6 : 조건 B (술어 노드)
   ↓ True 또는 False
노드 7 또는 노드 8
   ↓
노드 9 : 종료
```

- 위 예시는 간선 10개, 노드 9개이므로 V(G) = 10 − 9 + 2 = 3이고, 술어 노드가 2개이므로 2 + 1 = 3으로 세 공식의 값이 일치함.
- 순환복잡도 수치에 따른 코드 평가 기준은 다음 표와 같다.

| 순환복잡도 V(G) | 프로그램 구조 및 상태 | 리스크 등급 | 권장 조치 사항 |
| --- | --- | --- | --- |
| 1 ~ 10 | 단순하고 명확한 구조 | 낮음 (Low) | 테스트로 충분히 커버 가능, 현 상태 유지 |
| 11 ~ 20 | 다소 복잡하지만 통제 가능한 수준 | 보통 (Moderate) | 단위 테스트 케이스 보강과 주의 깊은 리뷰 |
| 21 ~ 50 | 이해하기 어렵고 결함 위험이 높음 | 높음 (High) | 메서드 분리와 리팩토링 필요 |
| 50 초과 | 통제하기 어렵고 테스트가 힘든 구조 | 극단적 (Very High) | 구조 재설계 및 재구현 검토 |

## Ⅳ. McCabe 순환복잡도와 인지 복잡도의 비교

- 핵심 요약 : 분기 개수를 세는 McCabe 방식과 중첩에 가중치를 두는 **인지 복잡도** (Cognitive Complexity) 방식은 측정 대상이 달라 상호 보완 관계.

| 비교 항목 | McCabe 순환복잡도 | 인지 복잡도 |
| --- | --- | --- |
| 측정 대상 | 제어 흐름 그래프의 독립 경로 수 | 코드를 읽고 이해할 때의 인지적 난이도 |
| 계산 방식 | if, while 등 분기 노드의 개수를 셈 | 중첩 깊이(Nesting Level)에 가중치를 부여 |
| 반영 범위 | 분기 개수 중심, 중첩 구조는 직접 반영하지 않음 | 중첩 구조 등 실제 코드 이해 부하를 반영 |
| 주요 활용 | 최소 테스트 케이스 수 산출, 품질 게이트 | 종합적인 리팩토링 기준 |

## Ⅴ. McCabe 순환복잡도의 한계와 방안

- 핵심 요약 : 인지 난이도 미반영, 기계적 분할에 따른 가독성 저하, 동적·비동기 구조 미반영이라는 세 한계를 복합 지표, 설계 개선, 런타임 분석으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 인지 복잡도 간과 | 분기 개수만 세므로 중첩 깊이 등 개발자가 체감하는 난이도를 온전히 반영하지 못함 | McCabe 순환복잡도와 함께 SonarQube의 인지 복잡도 지표를 병행 측정해 종합 기준으로 사용 | 메서드당 두 지표의 동시 임계치 초과 건수 |
| 수치 낮추기 목적의 기계적 분할 | 임계치를 맞추려고 의미 없는 작은 메서드로 쪼개 호출 흐름이 파편화되고 유지보수성이 악화 | 기계적 분리를 지양하고, 다형성(전략 패턴 등), 책임 분리(Tell, Don't Ask), 가드 클로즈(Guard Clause)로 구조를 근본적으로 개선 | 변경 용이성, 리뷰 소요 시간 |
| 동적·비동기 구조 미반영 | 정적 제어 흐름 그래프에 기반하므로 스트림 파이프라인, 비동기 콜백, 런타임 다형성의 복잡도를 평가하지 못함 | 정적 분석에만 의존하지 않고, APM(Application Performance Monitoring) 프로파일링으로 핫스팟을 찾고 JaCoCo 같은 커버리지 도구와 교차 분석 | 핫스팟 구간의 결함 발생률 |

## Ⅵ. 정적 분석 및 테스트 자동화 관점의 기술사적 제언

- 핵심 요약 : 기본 경로 하한을 테스트 설계의 기준으로 삼고, CI 파이프라인의 품질 게이트에 복잡도 검사를 연동하는 것이 필요.

1. 기본 경로 테스팅의 완전성 확보 : V(G)는 모든 분기 간선을 최소 한 번씩 지나는 독립 경로의 최소 개수이므로, 단위 테스트를 설계할 때 이 값을 케이스 도출의 하한으로 삼는 원칙을 세워야 한다.
2. CI 품질 게이트 연동 : **CI** (Continuous Integration) 파이프라인에서 SonarQube 같은 정적 분석 도구로 메서드별 V(G)를 측정하고, 조직이 정한 임계치를 넘으면 PR(Pull Request) 머지를 자동으로 차단하여 복잡한 코드의 유입을 막아야 한다.

```text
[ 복잡도 품질 게이트 흐름 ]

1. 정적 분석 도구로 V(G) 측정
   ↓
2. 메서드별 임계치 초과 여부 비교
   ↓ 초과 시
3. 빌드 중단 및 PR 머지 차단
```

## Ⅶ. 결론

- 핵심 요약 : McCabe 순환복잡도는 테스트 하한과 품질 게이트의 기준이 되는 정적 복잡도 척도.
- 시사점 : 인지 복잡도와 런타임 커버리지를 교차 분석하고 CI 품질 게이트에 연동해야 수치가 실질적 품질 관리 도구로 기능함.
