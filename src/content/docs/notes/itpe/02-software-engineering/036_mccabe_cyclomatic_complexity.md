## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 테스트·검증 → **McCabe 순환복잡도**

## 30초 인출

- 본질: 프로그램의 제어 흐름 그래프(CFG)를 바탕으로 선형적으로 독립적인 기본 실행 경로(Basis Path)의 수를 정량적으로 측정하는 소프트웨어 구조적 복잡도 메트릭
- 메커니즘: 그래프 이론 기반 계산 $V(G) = E - N + 2P$ (간선 $E$, 노드 $N$, 연결 성분 $P$), 단일 모듈 이진 분기 기준 $V(G) = D + 1$ ($D$: Predicate Node 수)
- 통찰: 높은 복잡도는 테스트 케이스 폭증과 유지보수성 저하를 초래하므로 CI/CD 정적 분석 단계에서 $V(G) \ge 10$ 초과 모듈에 대한 조기 리팩토링 강제 필수

<details>
<summary>핵심 용어</summary>

- **Cyclomatic Complexity(순환복잡도)** : Thomas McCabe가 제안한 메트릭으로 소프트웨어 제어 구조의 복잡성과 선형 독립 경로의 수를 수치화한 지표
- **CFG(Control Flow Graph)** : 노드(명령문 실행 블록)와 간선(제어 이동 경로)으로 프로그램의 논리적 실행 흐름을 표현한 방향 그래프
- **Basis Path(기본 경로)** : 기존 경로들의 조합으로 표현할 수 없으며 최소 1개 이상의 새로운 간선을 포함하는 독립적인 실행 경로
- **Predicate Node(분기 노드)** : 둘 이상의 간선으로 갈라지는 조건문(if, while, for 등)을 포함하는 노드
- **Complexity Threshold(복잡도 임계치)** : 결함 위험도를 관리하기 위해 설정하는 기준으로 일반적으로 10 이하를 안정적 코드로 분류

</details>

## 2~4교시 25점 답안

## Ⅰ. McCabe 순환복잡도의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 프로그램의 제어 흐름 그래프(CFG)에서 논리적으로 분기되는 선형 독립 경로(Basis Path)의 수를 그래프 이론 기반으로 정량화한 소프트웨어 복잡도 측정 메트릭 |
| 목적 | 화이트박스 테스트 케이스의 최소 상한선 결정, 결함 발생 위험 모듈 식별 및 리팩토링 우선순위 선정 기준 제공 |

## Ⅱ. McCabe 순환복잡도의 핵심 특징

| 특징 | 의미 |
|---|---|
| 제어 흐름 중심 측정 | 단순 코드 라인 수(LOC)가 아닌 프로그램의 조건 분기 복잡성을 객관적으로 수치화 |
| 테스트 완전성 기준 | 프로그램의 모든 실행 경로를 커버하기 위해 필요한 최소한의 기본 경로 테스트 케이스 수 제시 |
| 언어 독립적 메트릭 | C, Java, Python 등 모든 프로그래밍 언어의 제어문에 보편적으로 적용 가능 |
| 정적 분석 자동화 | SonarQube, Checkstyle 등 정적 코드 분석 도구와 연계하여 빌드 시점에 자동 측정 |

## Ⅲ. 제어 흐름 그래프(CFG) 및 순환복잡도 계산 체계

### CFG 모델링 구조 및 3대 계산 산식 메커니즘

```text
               ┌──────────┐
               │  Node 1  │ (시작)
               └────┬─────┘
                    │ Edge 1
                    ▼
               ┌──────────┐
               │  Node 2  │ ◄── 조건 분기 노드 D1 (if A)
               └────┬─────┘
            Edge 2  │  ＼ Edge 3
          (True)    │    ＼ (False)
                    ▼      ▼
         ┌──────────┐      ┌──────────┐
         │  Node 3  │      │  Node 4  │
         └────┬─────┘      └────┬─────┘
      Edge 4  │                 │ Edge 5
              └────────┬────────┘
                       ▼
                 ┌──────────┐
                 │  Node 5  │ ◄── 조건 분기 노드 D2 (if B)
                 └────┬─────┘
              Edge 6  │  ＼ Edge 7
            (True)    │    ＼ (False)
                      ▼      ▼
           ┌──────────┐      ┌──────────┐
           │  Node 6  │      │  Node 7  │
           └────┬─────┘      └────┬─────┘
        Edge 8  │                 │ Edge 9
                └────────┬────────┘
                         ▼
                   ┌──────────┐
                   │  Node 8  │ (종료)
                   └──────────┘
```

### 순환복잡도 $V(G)$ 3대 공식 계산 분석

| 계산 공식 | 수식 및 기호 정의 | 위 예시 그래프 적용 산출 ($N=8, E=9, P=1, D=2, R=3$) |
|---|---|---|
| **간선/노드 공식** | $V(G) = E - N + 2P$ ($E$: 간선, $N$: 노드, $P$: 연결 성분) | $V(G) = 9 - 8 + 2(1) = 3$ |
| **분기 노드 공식** | $V(G) = D + 1$ ($D$: 2개 이상의 출력을 갖는 분기 조건문 수) | $V(G) = 2 + 1 = 3$ (분기 노드 2, 5번) |
| **영역(Region) 공식** | $V(G) = R$ ($R$: 그래프의 닫힌 평면 영역 + 외부 개방 영역) | $V(G) = 2(\text{내부}) + 1(\text{외부}) = 3$ |

### 도출된 3대 선형 독립 경로 (Basis Path)
- **Path 1**: Node 1 → 2 → 3 → 5 → 6 → 8
- **Path 2**: Node 1 → 2 → 4 → 5 → 6 → 8
- **Path 3**: Node 1 → 2 → 3 → 5 → 7 → 8

## Ⅳ. 순환복잡도 수준별 평가 및 기본 경로 테스팅 비교

### McCabe 복잡도 구간별 위험도 및 조치 가이드라인

| 복잡도 $V(G)$ 수치 | 소프트웨어 구조적 상태 평가 | 잠재 결함 위험도 | 조치 가이드라인 |
|---|---|---|---|
| **1 ~ 10** | 매우 안정적이고 구조화된 단순 프로그램 | 매우 낮음 | 일반적인 단위 테스트 수행 및 유지 관리 |
| **11 ~ 20** | 중간 정도의 복잡도를 가진 모듈 | 다소 높음 | 기본 경로 테스팅 집중 적용, 집중 코드 리뷰 |
| **21 ~ 50** | 매우 복잡하고 제어 흐름이 얽힌 고위험 모듈 | 높음 | 즉각적인 메서드 분할 및 조건문 리팩토링 권고 |
| **50 초과** | 테스트가 사실상 불가능한 제어 불능 상태 | 극도로 위험 | 단위 모듈 전면 재작성(Rewrite) 필수 |

### 기본 경로 테스팅(Basis Path Testing) 4단계 절차

| 단계 | 활동 명칭 | 세부 수행 내용 |
|---|---|---|
| **1단계** | **제어 흐름 그래프(CFG) 도출** | 소스코드의 모든 실행문과 분기 조건을 노드와 간선으로 변환 |
| **2단계** | **순환복잡도 $V(G)$ 계산** | $V(G) = E - N + 2P$ 또는 $D + 1$ 공식을 적용하여 독립 경로 수 산출 |
| **3단계** | **기본 경로 집합(Basis Set) 식별** | 각 경로마다 최소 하나의 미방문 간선을 포함하는 독립 경로 집합 나열 |
| **4단계** | **테스트 케이스 설계 및 실행** | 식별된 각 기본 경로를 100% 실행시키는 입력값 및 기대 출력 작성 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 단순 중첩 루프나 switch-case 문의 경우 위험도가 낮음에도 복잡도 수치가 과도하게 상승 | 제어 구조 깊이를 반영하는 인지 복잡도(Cognitive Complexity) 메트릭을 병행 적용 |
| 순환복잡도가 낮더라도 데이터 의존성(Data Flow) 결함이나 동시성 병목을 탐지하지 못함 | 데이터 흐름 테스팅(DU-Chain) 및 정적 동시성 분석 도구를 결합하여 다각적 검증 |
| 복잡도 기준을 맞추기 위해 의미 없는 단순 래퍼 메서드로 분할하여 가독성 저하 유발 | 메서드 분할 시 단일 책임 원칙(SRP)과 높은 응집도를 보장하는 도메인 단위 리팩토링 강제 |

## Ⅵ. 제언

CI/CD 파이프라인 내 인지 복잡도(Cognitive Complexity) 병행 검증 및 품질 게이트(Quality Gate) 자동화

### CI/CD 품질 게이트 복잡도 통제 파이프라인

```text
[개발자 소스코드 커밋 및 PR 생성]
       ↓
[SonarQube 정적 분석 자동 실행]
  ├─ 1. McCabe 순환복잡도 측정 (분기 경로 수 기반)
  ├─ 2. 인지 복잡도(Cognitive Complexity) 측정 (코드 이해 난이도 기반)
  └─ 3. 단위 테스트 커버리지(Branch Coverage) 측정
       ↓
[품질 게이트 판정 규칙]
  ├─ 단일 메서드 V(G) > 15 ── (초과 시) ──→ PR 머지 차단 및 리팩토링 티켓 발급
  ├─ 파일당 인지 복잡도 > 25 ─ (초과 시) ──→ 리팩토링 권고
  └─ 모든 임계치 충족 시 ─────────────────→ 자동 머지 및 배포 파이프라인 진행
```

### 코드 복잡도 분석 의사결정 체계

```text
모듈 복잡도 측정 결과 분석
       ↓
[McCabe 순환복잡도 V(G) > 10 인가?]
       ├─ 아니오 ─→ 안정적 상태, 표준 테스트 수행
       └─ 예 ───→ [인지 복잡도(Cognitive)도 함께 높은가?]
                      ├─ 예 ──→ 중첩 분기 및 복합 조건문 제거 (메서드 추출 리팩토링)
                      └─ 아니오 (단순 Switch 문 등) ─→ 다형성(Strategy 패턴) 전환 검토
```

### 선택 근거: 전통적 McCabe 순환복잡도와 현대적 인지 복잡도 비교

| 구분 | McCabe 순환복잡도 (Cyclomatic) | 제언: 인지 복잡도 (Cognitive Complexity) |
|---|---|---|
| 측정 목표 | 화이트박스 테스트를 위한 **독립 경로의 수** | 인간 개발자가 코드를 **이해하는 인지적 난이도** |
| 중첩 구조 가중치 | 중첩 단계와 무관하게 동일한 가산 (+1) | 중첩 깊이(Depth)가 깊어질수록 가중치 누적 가산 |
| Switch-Case 평가 | Case 분기마다 무조건 +1 증가 (높은 복잡도) | Case 문 전체를 단일 구조로 평가 (+1만 가산) |
| 주 활용 분야 | 기본 경로 테스팅 설계 및 분기 커버리지 산정 | 코드 리뷰 통과 기준 및 유지보수성 품질 게이트 |
