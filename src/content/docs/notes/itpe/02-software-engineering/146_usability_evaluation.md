## 답안 골격
```text

 ┃
 ┣━ Ⅰ 개요 ───── 기능 중심 개발로 인한 사용자의 인지 과부하·이탈 한계 → 사용자가 시스템을 쉽고 효율적으로 사용하도록 측정·개선
 ┣━ Ⅱ 특징 ───── 사용자 중심 설계(UCD) 핵심 활동 · ISO 9241-11 표준(효과성, 효율성, 만족도) · 정성/정량 평가 결합
 ┣━ Ⅲ 구조 ───── 평가 방법 분류: 전문가 기반(휴리스틱 평가, 인지적 워크스루) vs 사용자 기반(사용성 테스트 UT, 설문 SUS, A/B 테스트)

 ┣━ Ⅴ 비교 ───── 닐슨 휴리스틱 평가(전문가 관점, 저비용) vs 실험실 사용성 테스트(UT, 실제 사용자 관점, 고비용)
 ┗━ Ⅵ 실무 ───── 표본 편향(Sample Bias) / 개발 후반부 형식적 평가 한계 / 프로토타입 단계 Shift-Left 평가
```

- 기출: 121회 1교시 `소프트웨어 사용성 평가(Usability Evaluation)의 개념 및 대표적 평가 방법` → Ⅰ~Ⅵ

## 한 줄 본질
- 소프트웨어 기능은 모두 구현되었으나 복잡한 UI와 불친절한 인터랙션으로 인해 사용자가 업무를 완수하지 못하고 이탈하는 병목 → 실제 사용자 또는 전문가가 시스템을 사용하면서 발생하는 마찰을 정량적·정성적으로 측정하고 직관적 인터페이스로 개선하는 공학적 평가 활동 / 평가자 주관성 개입 위험

## 핵심 용어
- 닐슨 10대 휴리스틱(Jakob Nielsen's Heuristics): 시스템 상태 가시성, 현실 세계와의 일치, 사용자 제어 및 자유, 일관성 및 표준 등 UI 설계의 10가지 경험적 가이드라인
- SUS(System Usability Scale): 10개의 표준 질문(리커트 5점 척도)으로 구성되어 소프트웨어의 전반적인 사용성을 0~100점의 단일 정량 점수로 신속하게 산출하는 신뢰도 높은 평가 설문

## 핵심 통찰
- 사용성 평가는 개발이 다 끝난 뒤 납품 전 체크리스트를 채우는 통과의례가 아니라, 기획/와이어프레임(Figma) 단계부터 5명 내외의 소수 사용자로 평가를 반복하는 것이 결함 수정 비용을 90% 아끼는 비결임
- 제이콥 닐슨의 법칙에 따르면, "단 5명의 실제 사용자 테스트만으로도 전체 사용성 문제의 85%를 발견할 수 있다"는 것이 입증되었으므로 대규모 설문보다 심층 인터뷰(Think Aloud)가 훨씬 효율적임
- 효과성(완수율)이 100%여도 효율성(클릭 수 20회, 5분 소요)이 떨어지면 사용자는 극심한 피로를 느끼고 경쟁 서비스로 이탈하므로 시간과 오류 횟수 등 정량 메트릭 관리가 필수임

## 이웃 토픽과 구분
- 사용성(Usability) vs 접근성(Accessibility): 사용성 = 일반 사용자가 얼마나 쉽고 빠르고 만족스럽게 시스템을 사용하는가 / 접근성 = 장애인이나 고령자 등 정보 취약 계층이 동등하게 웹/앱을 이용할 수 있도록 보장하는가

## 문제·원인·대책
- 적용 상황: 대국민 공공 모바일 민원 신청 서비스 개편
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 복지 민원 신청 과정에서 4단계 중 3단계에서 70%의 사용자가 이탈하여 민원 접수 실패 | 전문 용어 남발 및 입력 폼의 오류 메시지가 모호하여 사용자가 원인을 파악 못함 | 닐슨 휴리스틱 평가 기반 UI 전면 개편 및 실시간 유효성 인라인 피드백 제공 | 민원 신청 완수율(효과성) 35%에서 92%로 급증 |
| 사용성 평가 결과가 디자이너와 개발자의 주관적 취향 싸움으로 변질되어 개선 지연 | 정량적 평가 지표 없이 정성적 인터뷰 코멘트만으로 피드백을 전달한 오류 | 표준화된 SUS(System Usability Scale) 척도 도입 및 과업별 완수 시간(초) 정량 측정 | 객관적 데이터 기반의 개선 우선순위 합의 도출 |

## 이렇게 출제된다
- 제121회 1교시: "소프트웨어 사용성 평가(Usability Evaluation)의 개념과 ISO 9241-11에서 정의하는 3가지 품질 속성을 설명하시오." → 요구 포인트: 사용성 정의 + 효과성, 효율성, 만족도 정의 및 측정 지표 + 주요 평가 기법

## 내 의견
- [실험실 관찰 평가의 인위적 한계 극복] 관찰자가 지켜보는 실험실 환경에서는 사용자가 긴장하여 평소와 다르게 행동하는 호손 효과(Hawthorne Effect) 발생 → 나라면: 초기 와이어프레임 단계에서는 가벼운 휴리스틱 평가로 명백한 오류를 쳐내고, 프로덕션 릴리스 후에는 Amplitude/Hotjar 같은 제품 분석 도구로 실제 수만 명 사용자의 마우스 클릭 히트맵과 전환 퍼널 이탈 구간을 실시간 분석하는 "데이터 주도 UX 최적화" 체계 구축
