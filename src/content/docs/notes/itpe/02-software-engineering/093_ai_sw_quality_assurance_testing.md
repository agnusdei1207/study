- 입력에 대해 단 하나의 정답을 사전에 정의할 수 없는 테스트 오라클 문제(Test Oracle Problem)와 데이터 분포 변화(Drift) 병목 → 메타모픽 관계(MR) 검증, 뉴런 활성화 커버리지, 적대적 섭동 주입으로 모델의 일반화와 강건성 검증 / 수학적 완전성 증명 불가

## 핵심 용어
- 테스트 오라클 문제(Test Oracle Problem): 임의의 입력 데이터에 대해 모델이 산출한 예측 결과가 참인지 거짓인지 판정할 수 있는 완벽한 기준(오라클)이 존재하지 않는 현상
- 메타모픽 테스팅(Metamorphic Testing): 결과 자체의 정답 여부를 몰라도, 입력의 변형과 출력의 변화 사이에 성립해야 하는 불변의 메타모픽 관계(MR)를 설정하여 결함을 검출하는 기법

## 핵심 통찰
- 전통 SW 테스트는 코드 경로(Path Coverage)를 검증하지만, AI 테스트는 고차원 잠재 공간(Latent Space)의 표현력과 결정 경계(Decision Boundary)의 안정성을 검증함
- 테스트 데이터셋에서 정확도 99%를 기록한 모델이라도, 눈에 보이지 않는 미세한 적대적 노이즈(FGSM 등) 한 번에 전혀 엉뚱한 오분류를 유발할 수 있어 강건성 검증이 필수적임
- AI 모델은 배포하는 순간부터 현실 세계의 데이터 분포 변화로 인해 성능이 필연적으로 퇴화(Model Decay)하므로, 지속적인 온라인 드리프트 감시가 품질 보증의 완결점임

## 이웃 토픽과 구분
- AI SW 테스트 vs 전통적 SW 테스트: AI SW = 데이터 주도, 비결정론적, 통계적 오라클(메타모픽), 재학습 필요 / 전통 SW = 코드 주도, 결정론적, 명세 기반 오라클, 코드 패치 필요

## 문제·원인·대책
- 적용 상황: 자율주행 객체 인식 AI 모델의 운영 환경 배포
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 우천/야간 등 악천후 환경에서 보행자 인식 실패 사고 발생 | 맑은 날씨 주간 데이터로만 학습되어 엣지 케이스 데이터셋 편향 | 적대적 섭동 및 합성 데이터(디지털 트윈) 기반 데이터 증강 및 메타모픽 테스트 | 악천후 환경 객체 검출률 40%에서 95% 이상으로 향상 |
| 모델 배포 6개월 후 신규 유행어 및 사기 패턴 탐지율 급락 | 운영 환경 데이터 분포가 변화한 데이터/컨셉 드리프트 발생 | KS-Test, PSI(인구통계 지수) 실시간 감시 파이프라인 및 자동 재학습 파이프라인 트리거 | 드리프트 발생 후 24시간 이내 성능 자동 복구 |

## 이렇게 출제된다

## 내 의견
- [단순 성능 지표(Accuracy)에만 매몰된 형식적 검증 관행] 학술용 벤치마크 테스트셋 점수만 믿고 안전 필수(Safety-critical) 도메인에 AI를 직도입했다가 엣지 케이스 장애를 유발하는 위험 경계 → 나라면: 국제표준 ISO/IEC 25059(AI 시스템 품질 모델)를 도입하여 설명가능성(XAI)과 강건성 검증을 정량적 릴리스 게이트에 반영하고, 오분류 발생 시 규칙 기반 비상 제어로 넘어가는 2중 안전 장비(Safety Harness) 구축
