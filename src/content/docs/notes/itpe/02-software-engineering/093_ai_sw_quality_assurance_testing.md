## 30초 인출

- 본질: **AI SW 품질보증 테스트** 는 명시적 로직 대신 대규모 데이터와 딥러닝 신경망 가중치에 의해 동작하는 AI 소프트웨어의 신뢰성, 안전성, 윤리성을 검증하기 위해 데이터셋 적합성, 모델 추론 강건성(Robustness), 뉴런 커버리지(Neuron Coverage), 개념 표류(Concept Drift)를 생애주기 전반에 걸쳐 종합 평가하는 테스팅 체계
- 메커니즘: 학습 데이터 편향 검증 → 적대적 공격(FGSM) 및 변형 주입 시험 → 신경망 내부 활성화 수준(뉴런 커버리지) 계측 → 참 오라클 부재 극복을 위한 메타모픽 관계(MR) 검증 → 운영 환경 데이터 드리프트 실시간 감시
- 통찰: 기존 소프트웨어의 코드 구문/분기 커버리지로는 신경망 내부의 잠재적 사각지대를 측정할 수 없고 테스트 오라클 문제(Test Oracle Problem)가 상존하므로 DeepXplore 기반 뉴런 커버리지와 메타모픽 테스트 및 MLOps 연속 모니터링을 결합한 다차원 검증 파이프라인 수립이 필수적임

<details>
<summary>핵심 용어</summary>

- **테스트 오라클 문제 (Test Oracle Problem)** : 비결정적이고 복잡한 AI 추론 결과에 대해 특정 입력의 정답(Expected Output)을 사전에 명확히 알 수 없어 합격/불합격을 판정하기 극히 어려운 문제
- **뉴런 커버리지 (Neuron Coverage)** : 딥러닝 모델의 활성화 함수 출력값이 임계치($t$)를 초과하여 활성화된 뉴런의 비율을 측정하는 심층신경망 화이트박스 커버리지 지표
- **메타모픽 테스팅 (Metamorphic Testing)** : 입력 데이터를 특정 규칙으로 변환했을 때 기대되는 출력 간의 메타모픽 관계(Metamorphic Relation)를 검증하여 오라클 문제를 해결하는 기법
- **적대적 공격 시험 (Adversarial Testing)** : 인간의 눈에는 보이지 않는 미세한 노이즈(FGSM 등)를 입력에 추가하여 모델의 오분류를 유도하고 방어력을 검증하는 시험
- **데이터/개념 드리프트 (Drift)** : 실제 운영 환경의 데이터 분포($P(X)$)나 입력-출력 관계($P(Y|X)$)가 학습 시점과 달라져 모델 성능이 저하되는 현상

</details>

## 2~4교시 예상문제 (25점)

> 인공지능(AI) 기반 소프트웨어의 품질보증(QA) 및 테스팅 특수성을 전통적 SW와 비교하여 설명하고, 심층신경망 화이트박스 검증을 위한 뉴런 커버리지(Neuron Coverage) 메커니즘, 테스트 오라클 극복을 위한 메타모픽 테스팅(Metamorphic Testing) 및 전주기 MLOps 품질 관리 방안을 제시하시오.

---

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 머신러닝/딥러닝 모델이 내장된 소프트웨어를 대상으로 데이터 수집, 모델 학습, 시스템 통합, 실운영에 이르는 전 생애주기 동안 기능 정확성, 강건성, 편향성을 정량 평가하는 공학 활동 |
| 목적 | 블랙박스 모델의 불투명성(Explainability 부재) 해소, 예기치 못한 환각(Hallucination) 및 오동작 방지, ISO/IEC 25059 AI 품질 표준 준수 |

## Ⅱ. 핵심 특징

전통적 SW 테스팅의 '코드 중심 결정론적 검증'에서 탈피하여 '데이터-모델 중심 확률적 검증' 체계로 패러다임 전환.

| 비교 관점 | 전통적 SW 테스팅 | AI 기반 SW 테스팅 |
|---|---|---|
| **동작 메커니즘** | 규칙 기반 명시적 소스코드 ($f(x)$ 구현) | 대규모 데이터와 가중치 기반 확률적 추론 |
| **테스트 오라클** | 요구사항 명세서 기반 명확한 기대값 존재 | 결과 판정이 모호한 테스트 오라클 문제(Oracle Problem) 상존 |
| **품질 결정 요인** | 알고리즘 로직 및 코딩 무결성 | 학습 데이터의 품질, 편향성, 모델 하이퍼파라미터 |
| **테스트 커버리지** | 구문(Statement), 분기(Branch), MC/DC 커버리지 | 뉴런 커버리지(Neuron Coverage), K-다면체 커버리지 |
| **결함 지속성** | 코드가 불변이면 동작 영구 보존 | 시간이 지남에 따라 데이터 표류(Drift)로 모델 성능 자연 감쇠 |

## Ⅲ. 체계·프로세스

AI SW 전주기 품질보증 프로세스 및 뉴런 커버리지 계측 체계.

```text
[AI SW 전주기 품질보증 및 뉴런 커버리지 체계]
[1] 데이터 품질 검증 ──> [2] 모델 강건성 검증 ──> [3] 뉴런 커버리지 계측 ──> [4] 메타모픽 관계 검증 ──> [5] MLOps 감시

  ── [뉴런 커버리지(Neuron Coverage) 계측 메커니즘] ──────────────────────────────────────────────────────

  입력 이미지 (X)
       │
       ▼
  [입력 계층] ──────> [은닉 계층 1] ───────────────> [은닉 계층 2] ───────────────> [출력 계층]
  (Input Layer)      (Hidden Layer 1)              (Hidden Layer 2)              (Output Layer)

                     (○) f(z) = 0.85 (활성!)        (●) f(z) = 0.10 (비활성)
                     (●) f(z) = 0.20 (비활성)       (○) f(z) = 0.92 (활성!)        [ 클래스 예측 ]
                     (○) f(z) = 0.78 (활성!)        (○) f(z) = 0.80 (활성!)

  * 뉴런 활성화 판정 기준: 활성화 함수 출력값 > 임계치 threshold (예: t = 0.75)
  * 뉴런 커버리지 = (임계치를 초과하여 1회 이상 활성화된 뉴런 수) / (전체 뉴런 수)
```

- **뉴런 커버리지 정량 산출 수식**:
  $$\text{Neuron Coverage} = \frac{|\{n \in N \mid \exists x \in T, \, \text{act}(n, x) > t\}|}{|N|}$$
  - $N$: 딥러닝 신경망 내 전체 뉴런 집합.
  - $T$: 인가된 테스트 입력 데이터셋.
  - $\text{act}(n, x)$: 입력 $x$에 대한 뉴런 $n$의 활성화 함수(ReLU, Sigmoid 등) 출력값.
  - $t$: 뉴런 활성화 판정을 위한 임계값(Threshold, 통상 0.5~0.75).

## Ⅳ. 종류·비교

#### AI SW 4대 핵심 품질 테스트 기법 비교

| 테스트 기법 | 핵심 개념 및 검증 메커니즘 | 해결 과제 | 주요 도구 및 기법 |
|---|---|---|---|
| **뉴런 커버리지 (Neuron Coverage)** | 입력 데이터 인가 시 활성화 임계치를 넘는 뉴런의 비율 계측 | 딥러닝 내부 동작의 테스트 사각지대 식별 | DeepXplore, DeepGauge |
| **메타모픽 테스팅 (Metamorphic Test)** | 입력 변환($x \rightarrow x'$)에 따른 출력의 수학적/논리적 불변 관계 검증 | 정답을 모르는 테스트 오라클 문제 극복 | MR(Metamorphic Relation) 규칙 수립 |
| **적대적 공격 시험 (Adversarial Test)** | 미세 섭동(Perturbation) 노이즈를 주입하여 오분류 유도 및 방어력 측정 | 악의적 공격에 대한 추론 강건성(Robustness) 확보 | CleverHans, FGSM, PGD, CW Attack |
| **드리프트 감시 (Drift Monitoring)** | 운영 입력 데이터 분포와 모델 예측 신뢰도의 시계열 변화 감시 | 시간 경과에 따른 모델 노후화 및 정확도 저하 방지 | Evidently AI, Evidently, Arize AI |

#### ISO/IEC 25059 기반 AI 특화 품질 특성

| 품질 특성 | 세부 속성 | 실무 평가 내용 |
|---|---|---|
| **유연성 (Flexibility)** | 자율성, 적응성 | 환경 변화에 스스로 적응하여 재학습 없이도 일관된 성능 유지 |
| **강건성 (Robustness)** | 노이즈 내성, 적대적 저항성 | 불완전한 입력이나 적대적 왜곡 공격 시에도 성능 붕괴 방지 |
| **투명성 (Transparency)** | 설명가능성(XAI), 감사성 | 모델의 판단 근거를 사람이 이해할 수 있는 형태로 제공(SHAP, LIME) |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 뉴런 커버리지 100%를 달성해도 적대적 공격이나 실제 예외 상황에 대한 안전성을 보장하지 못함 | k-다면체 커버리지(DeepGauge) 및 결정 경계 커버리지(Boundary Coverage) 등 다계층 커버리지 병행 |
| 방대한 도메인 데이터에 대해 적절한 메타모픽 관계(MR)를 정의하기 어려움 | 도메인 전문가와 협업하여 물리 법칙 및 대칭성, 단조성 등 시스템 고유의 불변 관계(MR) 사전 표준화 |
| 운영 배포 후 실시간으로 발생하는 데이터 드리프트로 인한 침묵의 성능 저하(Silent Failure) | MLOps 파이프라인에 통계적 가설검정(KS-Test, PSI) 기반 실시간 드리프트 감시 및 자동 재학습 파이프라인 구축 |

## Ⅵ. 제언

AI SW의 품질 보증은 모델 개발 시점의 단위 테스트에 국한되지 않고, 데이터 전처리부터 모델 서빙, 실시간 모니터링까지 이어지는 지속적 MLOps 품질 게이트(Quality Gate)로 체계화

```text
[데이터 검증] ──> [모델 훈련] ──> [강건성/커버리지 시험] ──> [메타모픽 게이트] ──> [MLOps 드리프트 감시]
 (편향/완전성 검사)   (베이스라인)     (FGSM 노이즈 & DeepXplore)     (오라클 검증 통과)     (PSI 계측 & 자동 재학습)
```

| 검증 단계 | 적용 기술 | 품질 관리 지표 |
|---|---|---|
| **데이터 파이프라인** | Great Expectations / TFX Data Validation | 결측치, 이상치 제로 및 데이터 스키마 무결성 100% |
| **오프라인 모델 평가** | DeepXplore + CleverHans | 뉴런 커버리지 80% 이상, 적대적 공격 방어 성공률 90% 달성 |
| **운영 모니터링** | Prometheus + Evidently AI | 인구통계학적 지표(PSI < 0.1) 유지 및 추론 지연시간 50ms 이내 |
