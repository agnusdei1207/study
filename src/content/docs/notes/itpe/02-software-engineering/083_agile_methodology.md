## 연관 키워드

- 애자일 선언문, 애자일 원칙, 반복·점진 개발, 경험주의, 고객 피드백
- 익스트림 프로그래밍(XP), 스크럼, 칸반, 기술 부채

## Ⅰ. 애자일 방법론의 개요

- 핵심 요약 : 애자일 방법론은 짧은 반복 주기의 계획·개발·검토로 변화하는 요구에 맞는 동작하는 제품을 점진적으로 제공하는 개발 접근의 총칭.
- 개념 : 변화하는 요구를 짧은 반복 주기의 계획·개발·검토로 수용하며 고객 가치를 조기·지속 전달하는 소프트웨어 개발 방법론의 총칭(**애자일**, Agile).
- 배경 및 필요성 : 장기 선행 계획과 단계별 일괄 인도를 전제로 한 **폭포수 모델** (워터폴, Waterfall) 중심 절차로는 요구 불확실성과 사용자 피드백의 적시 반영이 어려워, 2001년 **애자일 선언문** (Agile Manifesto)에서 가치 중심의 경량 접근이 천명.
- 주요 목적 : 불확실한 요구 환경에서 고객 가치의 조기 전달, 변화 수용 능력과 제품·팀의 지속 개선 달성.

## Ⅱ. 애자일 방법론의 특징 및 장점

- 핵심 요약 : 반복·점진 개발·경험주의·고객 협업·작동 소프트웨어 중심·자율 팀이 변화 대응력과 조기 가치 전달로 연결.

1. 반복·점진 개발 : 고정된 짧은 주기로 계획→구현→검토를 되풀이 → 조기 위험 발견과 변화 수용.
2. 경험주의 (empiricism) : 작업 상태의 공개(투명성)·주기적 점검(검사)·개선(적응)의 순환 → 사실 기반 의사결정.
3. 고객 협업 : 고객 피드백을 반복마다 우선순위에 반영 → 실제 사용 가치에 자원 집중.
4. 작동하는 소프트웨어 중심 : 문서가 아닌 검증 가능한 제품 증분으로 진행 증명 → 진행 상황·품질의 실증 평가.
5. 자율·다기능 팀 : 계획·결정 권한의 팀 위임 → 승인 대기 시간 감소와 책임 강화.

- 애자일 선언문의 네 가치 : 선언문을 뒷받침하는 **애자일 원칙** 12개 항이 우선순위·품질·팀 운영의 실천 기준 제공.

    1. 프로세스·도구보다 개인과 상호작용
    2. 포괄적 문서보다 작동하는 소프트웨어
    3. 계약 협상보다 고객과의 협업
    4. 계획 따르기보다 변화에 대응

## Ⅲ. 애자일 방법론의 구조 (흐름)

- 핵심 요약 : 우선순위가 정렬된 백로그에서 증분을 만들고 피드백으로 되돌리는 반복 흐름과, 이를 구현하는 방법론 계열의 구조.

```text
제품 백로그 (우선순위 정렬)
   ↓ 반복 계획
반작업 목록 확정
   ↓ 설계·구현·시험
작동하는 제품 증분
   ↓ 검토 (고객 피드백)
학습·우선순위 재조정
   ↓
다음 반복으로 환류
```

```text
요구·가설
   ↓ 짧은 반복 주기
동작 제품 증분 인도
   ↓ 사용·검증
개선 사항 식별
   ↓ 백로그 반영
다음 반복 요구·가설
```

- 방법론 계열 : 애자일 가치·원칙을 각기 다른 초점으로 구현한 대표 방법론.

| 방법론 | 핵심 초점 | 대표 실천·구성 |
| --- | --- | --- |
| **익스트림 프로그래밍** (XP, Extreme Programming) | 기술 실천으로 품질 확보 | 테스트 주도 개발(TDD, Test-Driven Development), 페어 프로그래밍, 지속적 통합, 리팩토링 |
| **스크럼** (Scrum) | 정해진 역할·이벤트의 팀 실행 | 스프린트, 제품 백로그, 데일리 스크럼, 스프린트 리뷰, 회고 |
| **칸반** (Kanban) | 작업 흐름·진행량 제어 | 작업 가시화, 진행 중 작업(WIP, Work in Progress) 수 제한 |
| 린(Lean) | 낭비 제거·가치 흐름 | 낭비의 식별·제거, 신속 인도 |
| **기능 주도 개발** (FDD, Feature-Driven Development) | 기능 단위의 개발 주기 | 기능 목록 기반 설계·구현 |

## Ⅳ. 애자일과 워터폴 방법론의 비교

- 핵심 요약 : 애자일은 변화 수용·증분 인도·반복 피드백, 워터폴은 선행 확정·일괄 인도·단계 승인의 구조.

| 비교 축 | 애자일 | 워터폴 방법론 |
| --- | --- | --- |
| 요구 처리 | 변화를 전제로 반복마다 재조정 | 선행 확정 후 공식 변경 통제 |
| 인도 방식 | 증분의 조기·빈번한 인도 | 완성 후 일괄 인도 |
| 피드백 시점 | 반복마다 고객 검토 | 시험·인도 단계 이후 |
| 계획 방식 | 롤링·적응형 계획 | 전 단계 상세 선행 계획 |
| 적합 환경 | 요구 불확실성이 큰 신규·탐색형 제품 | 요구 안정·규제 문서·단계 승인 필요 사업 |

## Ⅴ. 애자일 방법론의 한계와 방안

- 핵심 요약 : 기술 부채·형식화된 시행·계약 불일치·확장 한계를 품질 기준 내재화·원칙 회복·제도 정비로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **기술 부채** 누적 | 빠른 인도 압박 하의 리팩토링·시험 생략 → 변경 비용 증가 | **완료 정의** (Definition of Done)에 품질 기준 포함, 개선 작업의 백로그 반영 | 재작업 비율 |
| **좀비 애자일** (Zombie Agile) | 회의·보드 형식만 남고 가치·피드백 상실 → 제도 실패 인식 확산 | 선언문 가치·원칙 재교육, 회고 산출물의 이행 확인 | 회고 개선 이행율 |
| 계약 제도 불일치 | 고정가격·일괄 인도 계약과 반복 방식의 충돌 → 범위·품질 갈등 | 반복 인도·성과 기반의 계약 구조 전환 | 변경 협상 지연 건수 |
| 대규모·규제 환경 한계 | 다수 팀 협업·감사 문서 요건과 팀 단위 방식의 충돌 | 스케일링 프레임워크 적용, 증거 산출물의 반복 주기 내 생성 설계 | 팀 간 의존 지연 |

## Ⅵ. 애자일 방법론 적용에 대한 기술사적 제언

- 핵심 요약 : 프레임워크 명칭이 아닌 가치·원칙 정렬을 기준으로 도입 거버넌스·계약 제도·역량 체계를 정비.
- 도입 거버넌스 : 경영 조직은 애자일 선언문 가치와 원칙의 정렬 수준을 평가하는 도입 성숙도 체계 운영.
- 제도 정비 : 조달·기획 부서는 반복 인도와 성과 기반 지불이 가능한 계약·평가 표준의 제도화 추진.
- 역량 확산 : 교육 기관·조직은 스크럼 마스터·제품 책임자 등 전문 역할의 역량 기준과 정기 교육 체계 확산.

## Ⅶ. 결론

- 핵심 요약 : 애자일 방법론은 선언문의 가치와 원칙을 짧은 반복·피드백 체계로 구현한 개발 접근.
- 스크럼·XP 등 어떤 프레임워크를 택하더라도 가치의 실질 이행 여부가 변화 대응력을 결정하는 구조.
