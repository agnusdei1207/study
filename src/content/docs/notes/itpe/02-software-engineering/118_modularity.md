## 연관 키워드

- 모듈화, 응집도, 결합도, 정보 은닉, 인터페이스, 모듈 경계

## Ⅰ. 모듈화의 개요

- 핵심 요약 : 모듈화는 시스템을 독립적 책임과 인터페이스를 가진 모듈로 분해해 변경 영향과 복잡성을 통제하는 설계 원칙.
- 개념 : 기능·데이터·책임을 응집된 단위로 묶고 모듈 간 의존을 계약으로 통제하는 구조화 기법인 **모듈화** (Modularity).
- 배경 및 필요성 : 시스템 규모 증가에 따라 전체 코드 이해·변경 영향 분석이 어려워져, 분해와 경계 설정 없이는 병렬 개발·품질 관리가 곤란.
- 주요 목적 : 변경 범위의 국소화, 병렬 개발·독립 시험·재사용성 확보, 복잡성 관리 가능 구조 실현.

## Ⅱ. 모듈화의 특징 및 장점

- 핵심 요약 : 높은 응집도·낮은 결합도·정보 은닉이 변경 국소화와 독립적 개발·시험으로 연결.

1. 높은 **응집도** (Cohesion) : 모듈 내부 기능의 단일 목적 집중(기능적 응집) → 변경 이유 단일화와 이해 용이성.
2. 낮은 **결합도** (Coupling) : 모듈 간 통신을 필요한 데이터 전달로 한정(데이터 결합 지향) → 변경 전파 최소화.
3. **정보 은닉** (Information Hiding) : 내부 표현·알고리즘 비공개와 공개 **인터페이스** 노출 → 내부 개선 자유와 안정 계약.
4. 명확한 **모듈 경계** : 책임·데이터 소유·의존 방향 명시 → 독립 시험·소유권 분리·병렬 개발 촉진.

## Ⅲ. 모듈화의 구조 (흐름)

- 핵심 요약 : 응집도는 기능적 방향으로, 결합도는 데이터 결합 방향으로 설계하며 계층적 분해·의존 규칙이 구조를 지탱.

```text
[ 응집도 단계 - 위일수록 높음 ]

기능적 응집 - 단일 기능의 완결 수행
순차적 응집 - 출력이 다음 처리의 입력
통신적 응집 - 동일 데이터에 대한 처리
절차적 응집 - 실행 순서의 연관
시간적 응집 - 동일 시점 수행
논리적 응집 - 유사 기능의 묶음
우연적 응집 - 무관 기능의 혼재
```

```text
[ 결합도 단계 - 위일수록 낮음 ]

데이터 결합 - 필요한 값만 계약 전달
스탬프 결합 - 자료 구조 전체 전달
제어 결합 - 제어 플래그로 동작 지시
외부 결합 - 외부 환경·프로토콜 참조
공통 결합 - 전역 데이터 공유
내용 결합 - 타 모듈 내부 직접 참조
```

```text
시스템
   ↓ 기능 분해
서브시스템
   ↓ 책임 분해
모듈 - 공개 인터페이스
   ↓ 구현 은닉
내부 데이터·로직
```

## Ⅳ. 모듈화와 저응집·고결합 구조의 비교

- 핵심 요약 : 고응집·저결합 구조가 변경 국소화·독립 시험을 가능케 하는 반면, 저응집·고결합 구조는 연쇄 수정·전파 장애 위험.

| 비교 축 | 고응집·저결합 (모듈화 지향) | 저응집·고결합 구조 |
| --- | --- | --- |
| 모듈 책임 | 단일 목적 기능의 집중 | 무관 기능의 혼재 |
| 의존 형태 | 인터페이스 계약 | 전역 변수·내부 직접 참조 |
| 변경 영향 | 해당 모듈 내 국소화 | 연쇄 수정·회귀 위험 |
| 시험 | 모듈 단위 독립 시험 | 결합 대상 일괄 준비 필요 |
| 재사용 | 단위별 재사용 가능 | 환경 의존으로 재사용 곤란 |

## Ⅴ. 모듈화의 한계와 방안

- 핵심 요약 : 과잉 세분화·순환 의존·경계 침식·인터페이스 불안정을 변경 응집 기준과 경계 검토로 통제 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 과잉 세분화 | 지나친 분할의 호출·조립 비용 | 변경 응집 기준의 재통합 | 경계 조정 빈도 |
| 순환 의존 | 책임 경계 불일치의 시험·배포 순서 붕괴 | 계층 의존 규칙·자동 검사 | 순환 의존 모듈 수 |
| 모듈 경계 침식 | 편의상 내부 노출 확산의 은닉 붕괴 | 접근 제한·경계 리뷰 | 내부 노출 건수 |
| 인터페이스 불안정 | 구현 변경마다 소비자 수정 | 계약 버전 관리·호환성 시험 | 파괴적 변경 건수 |

## Ⅵ. 모듈화에 대한 기술사적 제언

- 핵심 요약 : 아키텍처 거버넌스로 의존 규칙·모듈 소유권·경계 검토 절차를 제도화하고 조직 구조와의 정렬 필요.
- 개발 조직은 의존 방향 규칙을 정적 분석 도구로 상시 검사하고, 모듈별 소유 팀 지정으로 경계 변경을 설계 리뷰 의사결정으로 승격.
- 기술 리더십은 팀 구조와 모듈 구조의 정렬을 조직 설계에 반영해 경계 침식의 조직적 원인 완화.

## Ⅶ. 결론

- 핵심 요약 : 모듈화는 높은 응집도와 낮은 결합도로 변경 가능한 소프트웨어 구조를 만드는 설계 원칙.
- 효과의 원천은 분해 자체가 아니라 책임 경계와 인터페이스 계약의 안정성.
