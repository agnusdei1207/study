## 연관 키워드
- SQA, QC, 테스팅, ISO/IEC 25010, 품질 엔지니어링

### Ⅰ. 소프트웨어 품질보증의 개요

- 핵심 요약 : SQA(Software Quality Assurance)는 개발·유지보수 과정과 산출물이 품질요건·표준을 충족하도록 계획·감사·개선을 수행하는 예방 중심 활동.
- 개념 : 개발·유지보수 과정과 산출물이 품질요건·표준을 충족하도록 계획·감사·개선을 수행하는 예방 중심 활동(**SQA**, Software Quality Assurance).
- 배경 및 필요성 : 최종 검사에만 의존하면 결함이 늦게 발견되고 원인·재발을 막기 어려움.
- 주요 목적 : 생명주기 전반의 품질 위험 예방과 프로세스 적합성 확보.

### Ⅱ. 소프트웨어 품질보증의 특징 및 장점

- 핵심 요약 : 품질계획·표준·검토·감사·측정·시정조치; QC(Quality Control) 결과물 검사, 테스팅은 실행 기반 결함 발견.

1. 예방 중심 : 결함 발생 전 프로세스·표준으로 품질 위험 감소 → 사후 수정 비용 절감.
2. QC와의 구분 : 품질계획·표준·검토·감사·측정·시정조치 → 프로세스 적합성 확보.
3. 적용 원칙 : 품질 리더는 품질 엔지니어링을 초기 요구·설계·CI에 내재화하고 위험·결함 데이터를 개선 우선순위로 연결.

### Ⅲ. 소프트웨어 품질보증의 구조 (흐름)

- 핵심 요약 : 품질요건·계획 → 프로세스·표준 적용 → 리뷰·정적·동적 검증 → 결함·원인 분석 → 시정·예방 개선.

```text
품질요건·계획
  ↓
프로세스·표준 적용
  ↓
리뷰·정적·동적 검증
  ↓
결함·원인 분석
  ↓
시정·예방 개선
```

```text
품질계획 → 예방·표준 → 검토·시험 → 원인·개선
```

### Ⅳ. 품질보증(QA)과 품질관리(QC) 비교

- 핵심 요약 : SQA는 프로세스·품질체계의 적합성 보증·예방, QC는 제품·산출물의 검사·결함탐지.

| 비교 축 | 품질보증(QA) | 품질관리(QC) |
|---|---|---|
| 대상·목적 | 프로세스·품질체계의 적합성 보증·예방 | 제품·산출물의 검사·결함탐지 |
| 활동 | 표준·리뷰·감사·과정 개선 | 검사·시험·결함 기록 |

### Ⅴ. 소프트웨어 품질보증의 한계와 방안

- 핵심 요약 : 문서 중심화·독립성 부족·품질속성 누락을 현장성과 연결·독립감사·ISO/IEC 25010 검증계획으로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 문서 중심화 | 계획·감사 기록만 있고 개선 없음 | 결함·재작업·현장성과에 연결 | 재발률·시정완료 |
| 독립성 부족 | 개발조직이 자체 준수만 확인 | 역할 분리·독립감사·위험기반 표본 | 감사 미발견 |
| 품질속성 누락 | 기능시험만으로 성능·보안·접근성 검증 부족 | ISO/IEC 25010 특성 기반 검증계획 | 중대 품질결함 |

### Ⅵ. 소프트웨어 품질보증에 대한 제언

- 핵심 요약 : 품질 리더는 품질 엔지니어링을 초기 요구·설계·CI에 내재화하고 위험·결함 데이터를 개선 우선순위로 연결.

1. 품질 리더는 품질 엔지니어링을 초기 요구·설계·CI에 내재화하고 위험·결함 데이터를 개선 우선순위로 연결.
2. 재발률·시정완료·감사 미발견·중대 품질결함를 정기 측정하고 편차에 대한 원인분석·개선결과를 기록.

### Ⅶ. 결론

- 핵심 요약 : SQA(Software Quality Assurance)는 개발·유지보수 과정과 산출물이 품질요건·표준을 충족하도록 계획·감사·개선을 수행하는 예방 중심 활동.
- 시사점 : SQA는 제품을 마지막에 검사하는 활동이 아니라 결함 예방과 프로세스 개선을 통해 신뢰성을 확보하는 체계.
