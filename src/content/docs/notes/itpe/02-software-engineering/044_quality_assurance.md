## 연관 키워드

- 소프트웨어 품질 보증, SQA, 품질 관리(QC), 테스팅
- 품질계획, 감사, ISO/IEC 25010, 결함 예방, 독립성

## Ⅰ. 소프트웨어 품질 보증의 개요

- 핵심 요약 : SQA는 생명주기 전반에서 프로세스·표준 준수를 계획·감사·개선하는 결함 예방 중심 활동.
- 개념 : 소프트웨어의 개발·운영 과정과 산출물이 품질 요건·표준·계약 기준을 충족하는지 계획하고 감사·개선하는 예방 중심의 체계적 활동(소프트웨어 품질 보증(**SQA**, Software Quality Assurance)).
- 배경 및 필요성 : 완성품 검사에만 의존하면 결함이 늦게 발견되어 수정 비용이 커지고 원인 제거가 곤란 → 결함이 유입되기 전 프로세스를 통제하는 예방 활동 필요.
- 주요 목적 : 생명주기 전반의 품질 위험 예방, 프로세스·표준 적합성 확보, 고객 신뢰와 조직 품질 역량 향상.

## Ⅱ. 소프트웨어 품질 보증의 특징 및 장점

- 핵심 요약 : 예방 중심·전 주기 적용·독립성·표준 기반이 조기 결함 차단과 신뢰 확보로 연결됨.

1. 예방 중심 : **결함 예방**(defect prevention, 결함이 유입되기 전 프로세스에서 원인을 제거하는 활동)을 기본 원리로 삼음 → 사후 수정 비용 절감.
2. 전 생명주기 적용 : **품질계획**(quality planning, 품질 목표·기준·활동을 사전에 정하는 활동)에서 시험·운영까지 품질 활동을 배치 → 늦은 결함 발견 방지.
3. 독립성 : 개발 조직과 분리된 보증 담당의 객관적 **감사**(audit, 프로세스·산출물의 표준 준수 점검 활동) 수행 → 자체 확인의 맹점 보완.
4. 표준·측정 기반 : **ISO/IEC 25010**(시스템·소프트웨어 품질 모델의 국제 표준) 등 표준 기준과 결함 지표로 적합성을 판정 → 산출물 수용·개선의 객관 근거.

## Ⅲ. 소프트웨어 품질 보증의 구조 (흐름)

- 핵심 요약 : 계획→적용→점검→시정의 순환 구조이며, QA(프로세스 예방)가 QC(제품 검사)와 테스팅(실행 검증)을 포괄하는 계층.

```text
[ 품질 보증의 순환 흐름 ]

품질 목표·계획 수립
   ↓
표준·프로세스 적용
   ↓
검토·감사·측정
   ↓
부적합·결함 원인 분석
   ↓
시정·예방 조치와 개선
```

- 활동 계층 : **품질 보증**(QA, Quality Assurance)은 프로세스·체계 수준의 예방·감사를 담당하고, **품질 관리**(QC, Quality Control)는 산출물 수준의 검사·결함 제거를, **테스팅**(testing, 소프트웨어를 실행해 요구를 검증하는 활동)은 실행 기반 결함 발견을 담당.

```text
[ 품질 활동의 계층 구조 ]

품질 보증 (QA)
   ↓ 프로세스 기준 제공
품질 관리 (QC)
   ↓ 실행 수단
테스팅
```

## Ⅳ. 품질 관리(QC)와 품질 보증(QA)의 비교

- 핵심 요약 : QA는 프로세스·체계 중심의 예방·보증, QC는 제품·산출물 중심의 검사·결함 제거.

| 비교 축 | 품질 보증 (QA) | 품질 관리 (QC) |
|---|---|---|
| 초점 대상 | 프로세스·품질 체계 | 제품·산출물 |
| 활동 성격 | 예방 (결함 유입 차단) | 검사 (결함 발견·제거) |
| 대표 활동 | 표준 수립·품질계획·감사·검토 | 검사·테스팅·결함 추적 |
| 수행 주체 | 독립된 보증 조직 | 개발·시험 조직 |
| 적용 시점 | 생명주기 전반 | 산출물 완성 단계 중심 |
| 산출물 | 품질계획서·감사 보고서 | 결함 목록·시험 결과서 |

## Ⅴ. 소프트웨어 품질 보증의 한계와 방안

- 핵심 요약 : 문서 형식주의·독립성 결여·품질속성 누락·일정 압박 순응을 현장 연계와 독립 감사·표준 기반 검증으로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 문서 형식주의 | 계획·기록 작성에 머물러 개선이 없음 → 품질 효과 미달 | 결함·재작업 데이터의 프로세스 개선 연계 | 시정 조치 완료율 |
| 독립성 결여 | 개발 조직 내 자체 확인으로 감사 기능 약화 | 보증 조직의 조직적 분리와 위험 기반 감사 | 감사 지적 재발 건수 |
| 품질속성 누락 | 기능 검증만으로 성능·보안·신뢰성 미확인 | ISO/IEC 25010 특성 기준의 검증 계획 수립 | 특성별 검증 충족률 |
| 일정 압박 순응 | 납기 우선으로 검토·감사 생략 → 후속 비용 급증 | 단계별 품질 게이트(quality gate, 단계 진행의 품질 조건)와 예외 승인 절차 | 관문 미통과 진행 건수 |

## Ⅵ. 소프트웨어 품질 보증에 대한 기술사적 제언

- 핵심 요약 : 경영진 승인의 품질 정책·조직 표준 수립과 산업 표준 정합 체계, 품질 문화의 전사 확산 필요.

1. 품질 거버넌스 : 조직은 경영진 승인의 품질 정책과 조직 표준 프로세스를 수립하고, 보증 활동 결과를 경영 보고에 정식 편제.
2. 표준 정합·확산 : **CMMI**(Capability Maturity Model Integration, 프로세스 성숙도 통합 모델)와 ISO 9001 같은 산업 표준에 부합하는 품질 체계를 구축하고 교육으로 전사에 확산.

## Ⅶ. 결론

- 핵심 요약 : SQA는 최종 검사가 아니라 결함 예방과 프로세스 적합성으로 신뢰를 만드는 체계.
- QA·QC·테스팅의 계층적 배치가 품질 비용과 고객 신뢰의 동시 개선을 가능하게 함.
