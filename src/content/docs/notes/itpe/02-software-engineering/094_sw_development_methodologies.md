## 연관 키워드

- 개발 방법론(Software Development Methodology), 정형 방법론, 구조적 방법론, 정보공학 방법론
- 객체지향 방법론, 컴포넌트 기반 방법론, 애자일 방법론, 테일러링, DFD, ERD

## Ⅰ. SW 개발 방법론의 개요

- 핵심 요약 : 개발 방법론은 생명 주기 전반의 활동·산출물·역할을 체계화한 절차로, 전 방법론의 계보 이해가 선택의 기초.
- 개념 : 소프트웨어 생명 주기의 분석·설계·구현·검증 활동을 절차·산출물·역할로 체계화한 방법 (**소프트웨어 개발 방법론** (Software Development Methodology)).
- 배경 및 필요성 : 시스템 규모·복잡도 증가로 개인 역량 의존 개발의 품질 편차·요구 누락이 반복된 상태. 1970년대 이후 소프트웨어 위기 대응으로 방법론 발전.
- 주요 목적 : 개발 과정의 표준화·의사소통 체계화·품질 예측 가능성 확보, 프로젝트 특성에 맞는 관점 제공.

## Ⅱ. 주요 방법론의 계보 및 특징

- 핵심 요약 : 형식 명세 → 기능 분해 → 데이터 중심 → 객체·컴포넌트 → 반복·협업으로 추상화 단위와 관점이 진화.

1. 형식 명세와 검증 : **정형 방법론**이 수학적 표기로 요구·설계를 형식 명세화하고 논리 검증 → 안전·보안 필수 영역의 모호성 제거.
2. 기능 분해 관점 : **구조적 방법론**이 하향식 기능 분해와 **DFD** (Data Flow Diagram, 자료 흐름도)로 절차·자료 흐름 모델링 → 업무 처리 명확화.
3. 데이터 중심 관점 : **정보공학 방법론**이 **ERD** (Entity Relationship Diagram, 개체 관계도) 중심의 데이터 모델과 업무 정렬 → 전사 데이터 통합.
4. 추상화 단위의 진화 : **객체지향 방법론**이 클래스·캡슐화·상속·다형성과 **UML** (Unified Modeling Language, 통합 모델링 언어)로 상태·행위 모델링, **컴포넌트 기반 방법론**이 인터페이스 계약의 컴포넌트 조립 → 재사용성·변경 용이성 강화.
5. 반복·협업 관점 : **애자일 방법론**이 짧은 반복·점증적 전달·고객 협력 → 요구 변화 수용과 빠른 가치 제공.

## Ⅲ. 방법론의 모델과 산출물 흐름

- 핵심 요약 : 요구 분석에서 선택한 관점별 모델이 설계 산출물·구현·검증으로 이어지는 흐름.
- 관점별 대표 모델 : 구조적의 DFD·구조도, 정보공학의 ERD·업무 모델, 객체지향의 UML 클래스·시퀀스, 컴포넌트 기반의 인터페이스 명세.
- 테일러링 : **테일러링** (프로젝트 규모·위험·변화율에 맞춰 방법론의 활동·산출물을 조정하는 접근)으로 표준과 현장 적합성의 균형 확보.

```text
[ 방법론 발전 계보 ]

정형 방법론 (형식 명세·검증)
   ↓
구조적 방법론 (기능 분해·DFD)
   ↓
정보공학 방법론 (데이터 중심·ERD)
   ↓
객체지향 방법론 (객체·UML)
   ↓
컴포넌트 기반 방법론 (계약·조립)
   ↓
애자일 방법론 (반복·협업)
```

```text
[ 요구에서 산출물까지 ]

요구·도메인 분석
   ↓
방법론·모델 선택(테일러링)
   ↓
관점별 모델링
(DFD·ERD·UML·컴포넌트 명세)
   ↓
설계 → 구현·통합
   ↓
추적성 검증·시험
```

## Ⅳ. 테일러링 적용과 단일 방법론 고정 적용의 비교

- 핵심 요약 : 테일러링은 프로젝트 특성 기반의 조정 적용, 단일 방법론 고정은 관행 일괄 적용이라는 차이.

| 비교 축 | 테일러링 적용 | 단일 방법론 고정 적용 |
|---|---|---|
| 적용 기준 | 규모·위험·변화율에 따른 조합 | 조직 관행·문서 양식의 일괄 적용 |
| 산출물 | 필요한 모델·문서 수준 조정 | 전 단계 문서 부담·형식화 |
| 변화 대응 | 반복·계획 주도를 혼용해 대응 | 고정 절차로 요구 변경 대응 지연 |
| 자산화 | 회고로 적용 근거·개선 누적 | 동일 절차 반복으로 개선 동기 약화 |
| 선택 기준 | 특성이 다양한 프로젝트 포트폴리오 | 특성이 균일·규제 고정 업무 |

## Ⅴ. 방법론 적용의 한계와 방안

- 핵심 요약 : 모델 불일치·테일러링 남용·방법론 고착을 추적성·승인 기준·주기 갱신으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 모델 간 불일치 | 관점 혼용 시 요구·설계 추적 단절 | 공통 용어·요구 추적 매트릭스 운영 | 추적 누락 항목 수 |
| 테일러링 남용 | 절차 임의 생략 → 품질 편차 | 생략 가능 범위·승인 기준 명문화 | 무단 생략 건수 |
| 방법론 고착 | 기술·조직 변화 반영 지연 | 주기적 회고·표준 갱신 주기 운영 | 표준 미갱신 기간 |

## Ⅵ. 방법론 체계 정비에 대한 기술사적 제언

- 핵심 요약 : 조직 표준과 프로젝트 조정의 이원 체계, 회고 기반 자산화, 표준 동향 반영의 제도화.

1. 조직 : 조직 수준 방법론 표준과 프로젝트 테일러링 절차의 이원 체계 구축.
2. 자산화 : PMO가 적용·생략 근거와 품질 실적을 회고해 방법론 자산을 주기 갱신.
3. 융합 : DevOps·자동화 등 표준·기술 동향을 반영한 방법론 융합 검토.

## Ⅶ. 결론

- 핵심 요약 : 개발 방법론은 관점과 절차의 조합이며, 계보 총론 이해 위의 상황 적합한 선택·조정이 품질을 결정.
- 방법론의 가치는 문서 양식이 아니라 의사소통·품질·변화 대응의 실제 효과에서 평가.
