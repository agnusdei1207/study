## 30초 인출

- 본질: **AOP(Aspect Oriented Programming)** 는 트랜잭션, 보안, 로깅 등 여러 모듈에 산재하는 횡단 관심사(Cross-cutting Concerns)를 핵심 비즈니스 로직에서 분리하여 독립된 애스펙트(Aspect) 모듈로 구축하는 프로그래밍 패러다임
- 메커니즘: Pointcut 표현식으로 Joinpoint 지정 → 타깃 실행 전후 Advice 결합 → 바이트코드 변조 또는 런타임 프록시(JDK Dynamic Proxy/CGLIB)를 통한 Weaving 수행
- 통찰: 프록시 기반 런타임 AOP는 동일 객체 내부 메서드 직접 호출(Self-invocation) 시 프록시를 우회하여 부가 기능이 누락되므로 빈 분리 또는 로드타임 위빙(LTW) 구조를 설계에 반영해야 시스템 무결성을 유지할 수 있음

<details>
<summary>핵심 용어</summary>

- **횡단 관심사(Cross-cutting Concerns)** : 로깅, 트랜잭션, 보안 등 시스템의 여러 핵심 계층에 걸쳐 중복 출현하는 부가 기능
- **애스펙트(Aspect)** : 횡단 관심사를 모듈화한 단위로, 부가 기능(Advice)과 적용 위치(Pointcut)를 결합한 객체
- **조인포인트(Joinpoint)** : 메서드 실행, 생성자 호출, 필드 접근 등 어드바이스가 삽입될 수 있는 실행 지점
- **포인트컷(Pointcut)** : 수많은 조인포인트 중 실제 부가 기능이 적용될 대상을 선별하는 필터링 표현식
- **어드바이스(Advice)** : 특정 조인포인트에서 실행되는 실질적 부가 동작(@Before, @After, @Around 등)
- **위빙(Weaving)** : 포인트컷으로 선별된 조인포인트에 애스펙트를 결합하여 타깃 객체와 연결하는 전 과정

</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 핵심 업무 로직(Core Concerns)과 공통 부가 기능(Cross-cutting Concerns)을 분리하여 관점(Aspect) 단위로 모듈화하는 프로그래밍 패러다임 |
| 목적 | 공통 기능의 코드 중복(Code Tangling) 및 분산(Code Scattering) 해소, 단일 책임 원칙(SRP) 준수, 유지보수 생산성 극대화 |

## Ⅱ. 핵심 특징

핵심 비즈니스 코드의 침투적 수정을 방지하고, 선언적 설정을 통해 횡단 로직을 동적으로 주입.

| 특징 | 설계 의미 | 기술 구현체 |
|---|---|---|
| **관심사의 완벽한 분리** | 비즈니스 로직은 순수 도메인 연산만 담당하고 부가 기능은 격리 | `@Aspect`, `@Transactional`, XML 선언 |
| **선언적 포인트컷 지정** | 정규표현식이나 애너테이션 기반으로 적용 대상 클래스 및 메서드 동적 타깃팅 | AspectJ Pointcut Expression (`execution`, `@annotation`) |
| **다양한 결합 시점 지원** | 전처리, 후처리, 정상반환, 예외발생, 메서드 감싸기 등 실행 제어 | `@Before`, `@AfterReturning`, `@AfterThrowing`, `@Around` |
| **비침투적 아키텍처** | 대상 도메인 소스코드의 수정 없이 컴파일/로딩/런타임 단계에서 로직 결합 | CGLIB Proxy, Byte Buddy, AspectJ Compiler(ajc) |

## Ⅲ. 체계·프로세스

AOP의 아키텍처 동작 구조와 핵심 5대 구성요소의 유기적 결합 체계.

```text
[AOP 아키텍처 및 횡단 관심사 위빙 체계]
                                                                                                           
  클라이언트 요청                                                                                          
        │                                                                                                  
        ▼                                                                                                  
  +───────────────────────────────────────────────────────────────────────────+                            
  |                         AOP Proxy (런타임 대리 객체)                      |                            
  |                                                                           |                            
  |   +───────────────────────────────────+                                   |                            
  |   |        Aspect (횡단 관심사)       |                                   |                            
  |   |                                   |                                   |                            
  |   |   +---------------------------+   |                                   |                            
  |   |   |   Pointcut (위치 선별)    |   |                                   |                            
  |   |   +---------------------------+   |                                   |                            
  |   |                 │                 |                                   |                            
  |   |                 ▼                 |                                   |                            
  |   |   +---------------------------+   |                                   |                            
  |   |   |   Advice (부가 로직)      |   |                                   |                            
  |   |   |   @Around / @Before       |   |                                   |                            
  |   |   +---------------------------+   |                                   |                            
  |   +─────────────────┬─────────────────+                                   |                            
  |                     │ Joinpoint (실행 가로채기)                           |                            
  |                     ▼                                                     |                            
  |           +───────────────────+                                           |                            
  |           |   Target Method   | ───> [핵심 비즈니스 로직 실행]            |                            
  |           +───────────────────+                                           |                            
  |                     │                                                     |                            
  |                     ▼                                                     |                            
  |   +───────────────────────────────────+                                   |                            
  |   |   Advice (@After / @Returning)    |                                   |                            
  |   +───────────────────────────────────+                                   |                            
  +─────────────────────┬─────────────────────────────────────────────────────+                            
                        │                                                                                  
                        ▼                                                                                  
                  응답 반환                                                                                
```

- **AOP 5대 핵심 구성요소 상호작용 체계**:
  1. **Target** : 횡단 관심사가 적용될 핵심 비즈니스 로직 객체(Service, DAO).
  2. **Joinpoint** : Advice가 결합될 수 있는 애플리케이션 실행 흐름 상의 후보 지점(메서드 실행, 예외 발생 등).
  3. **Pointcut** : Joinpoint 중 실제 Advice를 적용할 위치를 지정하는 필터식(정규표현식 기반 타깃팅).
  4. **Advice** : 선별된 지점에서 실질적으로 실행될 횡단 기능의 구현체.
  5. **Weaving** : Pointcut에 의해 매핑된 타깃 객체와 Aspect를 결합하여 새로운 프록시를 생성하거나 바이트코드를 재구성하는 합성 프로세스.

## Ⅳ. 종류·비교

#### 3대 위빙(Weaving) 메커니즘 비교

| 비교 항목 | 컴파일 타임 위빙 (CTW) | 로드 타임 위빙 (LTW) | 런타임 위빙 (RTW) |
|---|---|---|---|
| **동작 시점** | 소스코드 컴파일 시점 | JVM 클래스 로더 메모리 로딩 시점 | 애플리케이션 런타임 객체 호출 시점 |
| **사용 도구** | AspectJ 전용 컴파일러(`ajc`) | AspectJ JVM Agent (`-javaagent`) | Spring AOP 프레임워크 |
| **바이트코드 조작** | `.class` 파일 생성 시 직접 코드 삽입 | 클래스 로딩 시점에 바이트코드 동적 변조 | 원본 바이트코드 불변 (Proxy 객체 동적 생성) |
| **결합 대상 범위** | 필드 접근, 생성자, static 메서드 등 전체 | 필드 접근, 생성자, static 메서드 등 전체 | 스프링 빈의 public 메서드 호출로 제한 |
| **실행 성능** | 무손실 네이티브 호출 수준 최고 속도 | 로딩 시 약간의 지연 후 고속 실행 | 프록시 체인 호출 및 리플렉션 오버헤드 미세 발생 |

#### 스프링 런타임 프록시 생성 방식 비교

| 구분 | JDK Dynamic Proxy | CGLIB Proxy |
|---|---|---|
| **기반 기술** | `java.lang.reflect.Proxy` 표준 API | ASM 기반 바이트코드 조작 라이브러리 |
| **타깃 요구조건** | 최소 1개 이상의 인터페이스 구현 필수 | 구체 클래스만으로 동작 가능 (상속 방식) |
| **프록시 구조** | 인터페이스를 구현한 독립 프록시 객체 | 타깃 클래스를 상속받은 하위(Subclass) 객체 |
| **제약 사항** | 인터페이스에 정의되지 않은 메서드 적용 불가 | final 클래스 및 final 메서드는 상속 불가로 적용 불가 |
| **스프링 부트 기본값** | 과거 Spring Boot 1.x 기본값 | Spring Boot 2.x 이상 공식 기본값 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 동일 클래스 내부 메서드 호출(Self-invocation) 시 프록시 객체를 거치지 않아 `@Transactional` 등 Advice 미적용 발생 | 서비스 클래스 책임 분리(리팩토링)를 적용하거나, `AopContext.currentProxy()` 참조 또는 AspectJ LTW 도입 |
| 과도하고 모호한 포인트컷 정규표현식 사용으로 인한 빌드 및 런타임 호출 성능 저하 | 패키지 경로를 최소화하고 `@annotation` 기반 명시적 타깃팅 방식을 적용하여 포인트컷 평가 비용 절감 |
| 다중 애스펙트 적용 시 Advice 간 실행 순서 충돌로 인한 트랜잭션 롤백 누락 및 로깅 오류 | `@Order` 애너테이션 또는 `Ordered` 인터페이스를 구현하여 Aspect 간 실행 우선순위를 명시적으로 통제 |

## Ⅵ. 제언

AOP 도입 시 횡단 관심사 특성에 따른 프록시와 전용 위빙 엔진(LTW) 분리 및 프록시 우회 방지 아키텍처 검증 체계화

```text
[요구사항 분석] (핵심 vs 횡단 관심사 분리)
         ↓
[AOP 방식 결정] (Spring AOP 프록시 vs AspectJ LTW)
         ↓
[순서·예외 통제] (@Order 기반 Advice 실행 우선순위 지정)
         ↓
[내부호출 검증] (ArchUnit 기반 Self-invocation 정적 검출)
```

| 검증 영역 | 점검 항목 | 통제 방안 |
|---|---|---|
| **호출 무결성** | Self-invocation 발생 여부 | ArchUnit 아키텍처 린터를 활용한 동일 빈 내부 트랜잭션 호출 정적 검출 |
| **실행 우선순위** | 보안, 트랜잭션, 로깅의 순서 | Security(@Order(1)) → Transaction(@Order(2)) → Logging(@Order(3)) 체계화 |
| **성능 오버헤드** | 포인트컷 복잡도 및 LTW 로딩 시간 | 와일드카드 축소 및 컴파일/로드타임 프로파일링 지표 상시 모니터링 |
