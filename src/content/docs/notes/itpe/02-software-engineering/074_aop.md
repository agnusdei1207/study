## 30초 인출

- 본질: AOP는 로깅·보안·트랜잭션처럼 여러 모듈에 걸치는 횡단 관심사를 핵심 업무 코드에서 분리해 별도 모듈(애스펙트)로 관리하는 프로그래밍 방식
- 메커니즘: 포인트컷으로 적용 위치를 정하고 어드바이스에 부가 기능을 작성해 위빙으로 대상 코드에 결합
- 통찰: 횡단 관심사가 흩어지면 중복과 수정 누락이 생기므로 애스펙트로 분리하되 프록시 방식은 객체 내부 자기 호출에 적용되지 않으므로 호출 경로를 확인

<details>
<summary>핵심 용어</summary>

- **AOP(Aspect Oriented Programming)** : 횡단 관심사를 분리해 모듈화하는 프로그래밍 패러다임
- **횡단 관심사(Cross-cutting Concern)** : 로깅·보안·트랜잭션처럼 여러 모듈에 공통으로 걸치는 기능
- **애스펙트(Aspect)** : 횡단 관심사를 모듈화한 단위
- **어드바이스(Advice)** : 지정한 지점에서 실행되는 부가 기능
- **포인트컷(Pointcut)** : 어드바이스를 적용할 대상을 선별하는 표현
- **조인포인트(Joinpoint)** : 어드바이스가 끼어들 수 있는 실행 지점(메서드 호출 등)
- **위빙(Weaving)** : 애스펙트를 대상 코드에 결합하는 과정

</details>

## 2~4교시 25점 답안

## Ⅰ. AOP의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **AOP** 는 여러 모듈에 걸치는 횡단 관심사를 별도 모듈로 분리해 관리하는 프로그래밍 방식 |
| 목적 | 업무 코드의 중복 제거와 공통 기능의 일관된 적용 |

## Ⅱ. 기존 방식과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 관심사 분리 | 핵심 업무와 부가 기능의 분리 |
| 코드 밖 적용 | 대상 코드를 수정하지 않고 부가 기능 삽입 |
| 일관성 | 공통 기능의 한 곳 관리 |

## Ⅲ. AOP의 구성과 동작

### AOP 구성 요소의 관계

```text
애스펙트
    ├─ 어드바이스 ── 부가 기능(로깅·트랜잭션)
    └─ 포인트컷 ── 적용 대상 선별
         ↓ 위빙
대상 객체의 조인포인트(메서드 실행)
```

### 확대: 메서드 호출 시 어드바이스 실행

```text
호출 → [Before 어드바이스] → 대상 메서드 → [After 어드바이스] → 반환
```

## Ⅳ. 적용 방식의 비교

| 구분 | 프록시 기반 | 위빙 기반(컴파일·로드 시) |
|---|---|---|
| 방식 | 대상 앞에 프록시를 두어 호출 가로채기 | 바이트코드에 직접 결합 |
| 적용 범위 | 프록시를 거치는 호출 | 내부 호출 포함 |
| 자기 호출 | 적용되지 않음 | 적용됨 |
| 부담 | 낮음 | 빌드·설정 복잡 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 프록시 방식에서 자기 호출 시 부가 기능 누락 | 호출 대상을 별도 객체로 분리 |
| 포인트컷 범위 오설정으로 의도하지 않은 적용 | 포인트컷을 좁게 정의하고 시험으로 확인 |
| 흐름이 코드에 드러나지 않아 디버깅 곤란 | 애스펙트 목록 문서화와 로깅 |

## Ⅵ. 제언

횡단 관심사는 애스펙트로 분리하고, 프록시 방식에서 자기 호출로 적용이 빠지지 않도록 호출 구조를 분리

### 적용 순서

```text
횡단 관심사 식별 (로깅·트랜잭션·보안)
    ↓
애스펙트·포인트컷 정의
    ↓
호출 경로 확인 (자기 호출 여부) → 시험
```

### 선택 근거: 코드 직접 삽입과의 비교

| 구분 | 각 코드에 직접 삽입 | 제언: 애스펙트 분리 |
|---|---|---|
| 중복 | 많음 | 없음 |
| 수정 | 모든 위치 | 애스펙트 한 곳 |
| 누락 위험 | 높음 | 포인트컷으로 통제 |
