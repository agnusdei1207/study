## 연관 키워드

- 기록·재생 테스트, 테스트 자동화, 회귀 테스트, UI 테스트
- 단언(Assertion), 테스트 데이터 마스킹

## Ⅰ. 기록·재생 테스트의 개요

- 핵심 요약 : **기록·재생 테스트**(Record and Replay Testing)는 사용자 조작·시스템 요청을 기록해 스크립트를 생성하고 재실행으로 결과를 검증하는 **테스트 자동화**(Test Automation) 기법.
- 개념 : 테스터의 조작·시스템 간 요청을 도구가 캡처해 스크립트로 저장하고 동일 흐름의 재실행으로 결과를 검증하는 자동화 기법.
- 배경 및 필요성 : 반복되는 **회귀 테스트**(Regression Testing, 변경 후 기존 기능을 재검증하는 시험)의 수작업 수행은 비용·누락이 크고, 자동화 스크립트의 직접 작성은 전문성·시간 부담 → 기록 기반의 자동화 진입 경로 필요.
- 주요 목적 : 실제 사용 흐름 기반의 재현 가능한 시나리오 확보와 회귀 검증의 신속화.

## Ⅱ. 기록·재생 테스트의 특징 및 장점

- 핵심 요약 : 실제 흐름의 자동 스크립트화가 도입 비용을 낮추고, 기대값 검증의 결합이 결함 탐지력을 결정하는 자동화 방식.

1. 스크립트 자동 생성 : 조작·요청 캡처의 스크립트 변환 → 자동화 도입 시간 단축.
2. 실사용 흐름 재현 : 실제 사용 경로의 그대로 재실행 → 시나리오의 현실성 확보.
3. 회귀 검증 : 코드·화면 변경 후 동일 시나리오 재생 → 결함의 조기 탐지.
4. 단언 결합 : 재생 결과에 **단언**(Assertion, 실행 결과가 기대값과 일치하는지 검사하는 명령) 지정 → 단순 실행 반복을 넘어선 결함 판정.

## Ⅲ. 기록·재생 테스트의 구조 (흐름)

- 핵심 요약 : 시나리오 선정에서 캡처·저장을 거쳐 재생·단언·차이 분석으로 이어지는 절차.

```text
[ 기록·재생 테스트 수행 절차 ]

기록 대상 시나리오 선정
   ↓
조작·요청 캡처
   ↓
민감 정보 제거·데이터 마스킹
   ↓
스크립트 저장·버전 관리
   ↓
격리 환경 재생·단언 판정
   ↓
차이 분석·보고
```

- **UI 테스트**(사용자 인터페이스를 통해 주요 시나리오를 검증하는 시험) 안정화 : 화면 구조 변경에 대비한 의미 기반 선택자와 **페이지 객체 패턴**(Page Object Model, 화면별 조작·식별자를 객체로 캡슐화하는 패턴) 적용 → 스크립트 유지보수성 확보.
- 기록 데이터 보호 : 캡처 데이터의 수집 최소화와 **테스트 데이터 마스킹**(Test Data Masking, 실제 값을 식별 불가 형태로 대체하는 처리) 적용.

```text
[ 기록 → 저장 → 재생 파이프라인 ]

조작·요청 캡처 (기록)
   ↓
스크립트·기록 데이터 저장
   ↓
재생 엔진의 대상 시스템 재실행
   ↓
단언·차이 보고
```

## Ⅳ. 기록·재생 테스트와 스크립트 직접 작성 방식의 비교

- 핵심 요약 : 관찰 흐름의 빠른 스크립트화인 기록·재생과 설계 기반의 정밀 작성 방식은 도입 속도·유지보수성·제어 정밀도에서 차이.

| 비교 축 | 기록·재생 방식 | 스크립트 직접 작성 방식 |
| --- | --- | --- |
| 스크립트 원천 | 도구가 조작·요청을 기록해 생성 | 테스터·개발자가 설계에 따라 작성 |
| 도입 속도 | 학습·작성 부담이 적은 신속 도입 | 프레임워크·작성 역량 필요로 지연 |
| 유지보수 | 화면 변경 시 재기록 부담 | 모듈화·추상화로 부분 수정 용이 |
| 데이터·로직 제어 | 기록 범위 내 제한적 구성 | 조건 분기·테스트 더블 등 정밀 제어 |
| 적합 용도 | 핵심 사용 여정의 회귀 검증 | 장기 운영되는 자동화 자산 구축 |

## Ⅴ. 기록·재생 테스트의 한계와 방안

- 핵심 요약 : UI 변경 취약성·간헐적 실패·단언 부재·민감 정보 노출을 선택자·대기·단언·마스킹 통제로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| UI 변경 취약 | 화면 구조·식별자 변경으로 스크립트 무효화 | 의미 기반 선택자·페이지 객체 패턴 적용 | 스크립트 원인 실패 비율 |
| 간헐적 실패 | 비동기 로딩·타이밍·환경 차이로 불안정 | 명시적 대기·재시도·격리 환경 구성 | 불안정 테스트 비율 |
| 단언 부재 | 결과 확인 없는 재생의 결함 미탐지 | 기대값 단언·비교 기준의 시나리오 포함 | 단언 미포함 시나리오 수 |
| 민감 정보 노출 | 기록 데이터의 토큰·개인 정보 포함 | 수집 최소화·마스킹·보존 기간 제한 | 민감 정보 탐지 건수 |

## Ⅵ. 기록·재생 테스트의 제언

- 핵심 요약 : 품질 조직은 적용 경계와 승인 체계를 정하고 플랫폼·데이터 거버넌스로 자동화 자산을 운영.

1. 품질 조직은 핵심 사용자 여정 선별 기준과 시나리오·단언의 승인 절차 수립.
2. 플랫폼 조직은 지속적 통합(CI, Continuous Integration) 연계·격리 시험 환경·시험 계정 체계 제공.
3. 데이터 관리 조직은 기록 데이터의 분류·보존 기간·접근 권한 정책 운영.

## Ⅶ. 기록·재생 테스트의 결론

- 핵심 요약 : 기록·재생 테스트는 자동화 진입 부담을 낮추는 회귀 검증 수단.
- 시사점 : 단언·유지보수성·기록 데이터 통제와 결합할 때 신뢰 가능한 테스트 자산으로 전환.
