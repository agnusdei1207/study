## 연관 키워드
- 요구공학, 도출, 분석, 명세, 확인, 기능 요구사항, 비기능 요구사항
- 요구사항 명세서(SRS), 추적성, 변경 관리, RTM, CCB

## Ⅰ. 요구공학의 개요

- 핵심 요약 : 요구공학은 이해관계자의 필요를 도출·분석·명세·확인하고 변경을 관리해 검증 가능한 요구 기준선을 확보하는 체계.
- 개념 : **요구공학**(Requirements Engineering)은 이해관계자의 필요를 시스템 요구로 정제하기 위해 **도출**(Elicitation)·**분석**(Analysis)·**명세**(Specification)·**확인**(Validation)을 수행하고 이후 변경을 관리하는 활동 체계.
- 배경 및 필요성 : 모호·상충·누락된 요구가 설계 결함·재작업·수용 분쟁으로 이어지고, 후반부에 발견된 요구 결함일수록 수정 비용이 급증하는 문제.
- 주요 목적 : 검증 가능한 요구 기준선 확보로 설계·시험·인수의 공통 기준과 이해관계자 합의 확립.

## Ⅱ. 요구공학의 특징 및 장점

- 핵심 요약 : 반복 단계 수행·검증 가능성·추적성·변경 관리가 요구 품질과 프로젝트 안정성을 높임.

1. 단계·반복 체계 : 4단계가 피드백 순환으로 반복 → 지식 축적에 따른 요구 정제.
2. 검증 가능성 : 측정 가능한 수용 기준 명시 → 시험·인수 판정의 객관 근거.
3. 추적성 확보 : **추적성**(요구가 설계·코드·시험 산출물과 연결되는 성질) 유지 → 변경 영향 분석·커버리지 점검.
4. 변경 관리 : **기준선**(Baseline, 승인된 요구 집합) 확정 이후 변경을 **변경통제위원회**(Change Control Board, CCB) 심의로 처리 → 범위·일정 영향 통제.
5. 이해관계자 합의 : 사용자·운영·보안·법무 관점의 조기 참여 → 요구 누락·분쟁 감소.

## Ⅲ. 요구공학의 구조 (흐름)

- 핵심 요약 : 4단계의 반복 순환과 기준선 이후 변경 관리 절차의 결합 구조.

```text
요구공학 4단계

도출 : 이해관계자로부터 요구 수집
   ↓
분석 : 분류·우선순위·상충 해소
   ↓
명세 : 요구사항 명세서 작성
   ↓
확인 : 검토·시제품으로 승인
   ↺ 결함 발견 시 이전 단계 재수행
```

- 분석의 내용 : **기능 요구사항**(Functional Requirement, 시스템이 수행할 동작)과 **비기능 요구사항**(Non-functional Requirement, 품질·제약 조건)의 분류·우선순위화.

```text
기준선 이후 변경 관리

변경 요청 접수
   ↓
영향 분석 (요구사항 추적표 활용)
   ↓
CCB 심의·승인
   ↓
기준선 갱신 → 산출물 반영
```

- 주요 산출물 : **요구사항 명세서**(Software Requirements Specification, SRS), **요구사항 추적표**(Requirements Traceability Matrix, RTM), 검토·승인 기록, 변경 요청서.

## Ⅳ. 요구공학과 코드 우선 개발의 비교

- 핵심 요약 : 요구공학은 합의된 요구 기준선을 먼저 확립하는 체계, 코드 우선 개발은 구현을 앞세워 변경 비용·분쟁 위험이 큰 접근.
- 비교 개요 : 코드 우선 개발은 요구 정의에 앞서 구현을 선행하고 요구를 진행 중에 보완하는 방식.

| 비교 축 | 요구공학 | 코드 우선 개발 |
|---|---|---|
| 출발점 | 요구 분석·합의 선행 | 구현 착수, 요구는 보완식 확정 |
| 요구 기록 | 명세서·기준선의 공식화 | 코드와 구두 합의에 분산 |
| 검증 기준 | 측정 가능한 수용 기준 | 완성물 시연 중 발견적 판단 |
| 변경 처리 | 영향 분석·CCB 절차 | 무통제 변경 누적 |
| 주요 위험 | 초기 분석 공수·지연 | 재작업·수용 분쟁·범위 확산 |

## Ⅴ. 요구공학의 한계와 방안

- 핵심 요약 : 모호성·상충·추적 단절·과잉 문서화를 측정 기준·협상·추적 관리로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 모호한 표현 | 정성 표현 기준 부재 → 검수 해석 차 | 측정 가능한 수용 기준·용어 사전 | 모호 요구 비율 |
| 요구 상충·변동 | 이해관계자 목표 차이 → 범위·일정 불안정 | 협상·우선순위 합의·CCB 절차 | 변경 요청 건수 |
| 추적 단절 | 산출물 간 연결 누락 → 변경 누락·시험 공백 | RTM 유지·자동 일관성 점검 | 추적 완결성 |
| 과잉 문서화 | 전 요구의 동일 깊이 기록 → 비용 낭비 | 위험 기반 상세 수준 조정 | 문서 유지 공수 |

## Ⅵ. 요구공학에 대한 제언

- 핵심 요약 : 발주 기관·개발 조직·품질 조직의 절차·도구·관문 제도화로 요구공학 성숙도 제고.

1. 발주 기관은 CCB 구성·심의 기준을 계약·과업 내용서에 명시해 변경 의사결정 책임 제도화.
2. 개발 조직은 요구 관리 도구로 명세·RTM·변경 이력을 통합 관리하고 추적성 상시 점검 체계 구축.
3. 품질 보증 조직은 요구 검토를 단계 품질 관문에 편성하고 요구 품질 지표를 경영 보고에 반영.

## Ⅶ. 결론

- 핵심 요약 : 요구공학은 이해관계자의 필요를 검증 가능한 요구 기준선으로 고정해 소프트웨어 품질의 출발점을 확보하는 체계.
- 요구 품질은 설계·시험·인수 전 단계의 품질과 사업 성과를 결정하는 기반.
