## 연관 키워드

- 화이트박스 테스트(White Box Test), 구조 기반 테스트(Structure-based Testing), 코드 커버리지(Code Coverage)
- 제어 흐름 그래프(CFG, Control Flow Graph), MC/DC(Modified Condition/Decision Coverage), Test Double

## Ⅰ. 화이트박스 테스트의 개요

- 핵심 요약 : 내부 소스코드 구조와 논리 경로를 직접 분석해 코드 커버리지 기반으로 검증하는 구조 기반 테스트.
- 개념 : 소프트웨어의 내부 소스코드 구조, 논리 경로, 제어 흐름 및 데이터 흐름을 직접 분석하여 논리적 정확성과 코드 커버리지를 검증하는 구조 기반(Structure-based) 테스트 기법.
- 배경 및 필요성 : 블랙박스 테스트만으로 발견이 어려운 미실행 코드(Dead Code), 숨겨진 논리적 오류, 메모리 누수, 예외 분기 누락의 조기 색출 필요.
- 주요 검증 도구 : JUnit, JaCoCo, SonarQube, BullseyeCoverage.

## Ⅱ. 화이트박스 테스트의 특징

- 핵심 요약 : 내부 구조 가시성과 커버리지 계측, 도구 기반 자동화가 결합된 검증 체계.

1. 소스코드의 제어 흐름·데이터 흐름 기반 논리 경로 검증.
2. 구문부터 MC/DC(Modified Condition/Decision Coverage)까지 단계적 강도의 커버리지 측정 체계.
3. JUnit, JaCoCo, SonarQube, BullseyeCoverage 등 도구 기반 자동화.
4. 블랙박스 테스트로 발견 불가능한 미실행 코드·예외 분기 결함의 조기 검출.
5. 명세 기반 블랙박스 테스트와의 상호 보완적 운용.

## Ⅲ. 화이트박스 테스트의 구조 (흐름)

- 핵심 요약 : 제어 흐름 그래프(CFG) 기반 경로 분석과 커버리지 계층의 단계적 강화.
- 제어 흐름 그래프(CFG, Control Flow Graph) 예시.

```text
        [ 노드 1 : Start ]
               │
               ▼
        [ 노드 2 : If (A > 0) ]
          /           \  (True / False 분기)
         ▼             ▼
   [ 노드 3 ]       [ 노드 4 ]
         \             /
          ▼           ▼
        [ 노드 5 : End ]
```

- 구문 커버리지(Statement, L1) : 코드 내 모든 실행 가능 문장의 최소 1회 실행 보장.
- 결정/분기 커버리지(Branch/Decision, L2) : 각 조건문의 전체 결과가 참(True)과 거짓(False)이 되는 경로의 최소 1회 실행.
- 조건 커버리지(Condition, L3) : 조건식 내부 개별 조건식들의 독립적 참/거짓 확보.
- 조건/결정 커버리지(Condition/Decision) : 개별 조건식의 참/거짓과 전체 조건문의 참/거짓의 동시 만족.
- 변경 조건/결정 커버리지(MC/DC, Modified Condition/Decision Coverage) : 각 개별 조건식이 타 조건식 영향 없이 전체 결정문 결과에 독립적으로 영향을 미치도록 설계, 항공/국방/철도 등 최고 안전성 요구 분야 적용.

```text
[ 커버리지 검증 강도 계층 ]
        ▲  다중 조건 커버리지 (최고 강도, 2^N 케이스)
       ▲▲  MC/DC (높음, N+1 케이스, DO-178C Level A)
      ▲▲▲  조건/결정 커버리지
     ▲▲▲▲  조건 커버리지 · 결정/분기 커버리지
    ▲▲▲▲▲  구문 커버리지 (최소 강도)
```

## Ⅳ. 커버리지 기법별 비교

- 핵심 요약 : 핵심 조건과 케이스 수, 검증 강도가 비례하는 커버리지 기법 체계.

| 커버리지 기법 | 핵심 조건 | 케이스 수 | 검증 강도 |
|---|---|---|---|
| 구문 커버리지 | 모든 문장 1회 이상 실행 | 최소 | 낮음 |
| 결정 커버리지 | 전체 조건문 True/False 1회 이상 | 적음 | 중간 |
| 조건 커버리지 | 개별 조건 True/False 1회 이상 | 적음 | 중간(결정 커버리지 미보장 가능) |
| MC/DC | 개별 조건의 전체 결과 독립적 영향 입증 | $N+1$개 | 높음(DO-178C Level A 의무) |
| 다중 조건 커버리지 | 개별 조건의 모든 진리표 조합 실행 | $2^N$개 | 최고(조합 폭발로 실무 적용 한계) |

## Ⅴ. 화이트박스 테스트의 장점과 한계

- 핵심 요약 : 논리 경로·구조 결함 검출의 장점, 커버리지 비용·취약 테스트·I/O 종속의 한계.
- 장점
  1. 미실행 코드, 숨겨진 논리 오류, 예외 분기 누락의 조기 검출.
  2. 커버리지 수치 기반의 객관적 테스트 충분성 판단.
  3. 도구 기반 자동화를 통한 회귀 테스트 효율화.
- 한계점 1 : 고차원 커버리지(MC/DC, 다중 조건) 달성을 위한 테스트 비용 폭증
  - 한계점 : 안전-임계(Safety-Critical) 시스템의 MC/DC 100% 달성을 위한 복합 조건식 논리 경로 수작업 설계 시 비용·공수의 기하급수적 폭증.
  - 해결 방안 : 소스코드 리팩토링 기반 조건문 순환 복잡도의 10 이하 축소, 기호 실행(Symbolic Execution) 및 유전 알고리즘 기반 자동 테스트 생성 도구(EvoSuite, KLEE) 활용을 통한 테스트 케이스 자동 합성.
- 한계점 2 : 내부 구현 결합으로 인한 취약한 테스트(Brittle Test) 양산
  - 한계점 : 클래스의 프라이빗 메서드·내부 알고리즘 세부와 강결합된 테스트의 비즈니스 로직 무변경 단순 리팩토링에서도 대량 실패 및 유지보수 비용 가중.
  - 해결 방안 : 내부 구현이 아닌 퍼블릭 API(Application Programming Interface) 계약 및 외부 관측 가능 상태 변화 검증 중심의 테스트 대상 추상화, BDD(Behavior-Driven Development) 스타일 단위 테스팅 표준 수립.
- 한계점 3 : 외부 I/O 종속성으로 인한 테스트 격리 난제
  - 한계점 : DB(Database), 외부 네트워크, 파일 시스템과 밀착된 코드의 순수 화이트박스 단위 테스트 불가 및 테스트 속도 저하.
  - 해결 방안 : 의존성 역전 원칙(DIP, Dependency Inversion Principle) 준수 기반 I/O 계층 인터페이스 추상화(헥사고날 아키텍처), 단위 테스트 시 Test Double(Mock, Stub, Fake) 주입을 통한 격리 실행.

## Ⅵ. 화이트박스 테스트 현장 적용 시 기술사적 제언

- 핵심 요약 : 커버리지 수치 맹신 지양과 CI/CD 품질 게이트·정적 분석 결합.
- 테스트 커버리지 수치에 대한 맹신 지양 : 100% 구문 커버리지가 결함 부재를 의미하지 않는 인식(요구사항 누락 탐지 불가), 경계값 분석 등 명세 기반 블랙박스 테스트와 병행하는 상호 보완적 테스팅 전략 수립.
- CI/CD(Continuous Integration/Continuous Delivery) 파이프라인과 정적 분석(SAST, Static Application Security Testing)의 결합 : 단위 테스트 실행 시 커버리지 임계치 미달 빌드 강제 중단 품질 게이트 설정을 통한 기술 부채 누적 차단.

## Ⅶ. 결론

- 핵심 요약 : 화이트박스 테스트는 코드 커버리지 기반 구조 결함 검출의 핵심 수단.
- 요약 : CFG 기반 경로 분석과 구문~MC/DC 커버리지 계층이 논리적 정확성 검증의 골격.
- 시사점 : 커버리지 맹신 지양과 블랙박스 병행, 품질 게이트 자동화가 실무 적용 성숙도의 핵심.
