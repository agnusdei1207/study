## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 테스트·검증 → **화이트박스 테스트(White Box Test)**

## 30초 인출

- 본질: 화이트박스 테스트는 소스 코드의 내부 구조(제어 흐름·조건식)를 보고 그 구조를 얼마나 실행했는지를 기준으로 케이스를 설계하는 테스트
- 메커니즘: 코드를 제어 흐름 그래프로 나타내 구문·결정·조건 커버리지로 실행 범위를 재고 순환 복잡도로 필요한 경로 수를 산정
- 통찰: 구문 커버리지 100%여도 조건의 참·거짓 조합이 시험되지 않을 수 있으므로 안전 요구가 큰 코드는 각 조건의 독립 영향을 확인하는 MC/DC까지 요구

<details>
<summary>핵심 용어</summary>

- **화이트박스 테스트(White-box Testing)** : 코드의 내부 구조를 기준으로 케이스를 설계하는 구조 기반 테스트
- **제어 흐름 그래프(CFG, Control Flow Graph)** : 코드의 실행 순서와 분기를 노드와 간선으로 표현한 그래프
- **구문 커버리지(Statement Coverage)** : 모든 문장을 한 번 이상 실행하는 기준
- **결정 커버리지(Decision Coverage)** : 모든 조건문의 참·거짓 분기를 한 번 이상 실행하는 기준
- **MC/DC(Modified Condition/Decision Coverage)** : 각 조건이 다른 조건을 고정한 상태에서 결과를 독립적으로 바꾸는지 확인하는 기준
- **순환 복잡도(Cyclomatic Complexity)** : CFG의 선형 독립 경로 수. 간선 수 − 노드 수 + 2

</details>

## 2~4교시 25점 답안

## Ⅰ. 화이트박스 테스트의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **화이트박스 테스트** 는 코드의 내부 구조를 기준으로 케이스를 설계하는 구조 기반 테스트 |
| 목적 | 코드 경로·조건의 미실행 부분과 논리 오류의 발견 |

## Ⅱ. 블랙박스 테스트와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 구조 기반 | 소스 코드의 분기·조건·경로 기준 |
| 커버리지 측정 | 코드 실행 비율의 정량 지표 |
| 단위·통합 단계 중심 | 개발자가 코드와 함께 수행 |

## Ⅲ. 제어 흐름 그래프와 커버리지

### 제어 흐름 그래프

```text
① 시작
    ↓
② 조건 판정 (x > 0 && y > 0)
    ├─ 참 → ③ 블록 A ─┐
    └─ 거짓 → ④ 블록 B ┤
                       ↓
                   ⑤ 종료
```

### 확대: 결정 커버리지의 경로 실행

```text
참 분기: ① → ② → ③ → ⑤  (케이스 1)
거짓 분기: ① → ② → ④ → ⑤  (케이스 2)
→ 모든 분기 결과를 1회 이상 실행하면 결정 커버리지 100%
```

## Ⅳ. 커버리지 기준의 비교와 경로 기반 기법

### 커버리지 기준

| 기준 | 판정 | 특징 |
|---|---|---|
| 구문 | 모든 문장 실행 | 가장 약함, 분기 결과 미확인 |
| 결정 | 모든 분기의 참·거짓 실행 | 조건별 영향 미확인 |
| 조건 | 각 조건의 참·거짓 실행 | 결정 결과와 무관할 수 있음 |
| 조건/결정 | 조건과 결정을 함께 만족 | 조건 간 영향 미확인 |
| MC/DC | 각 조건이 결과를 독립적으로 변경 | 케이스 수 N+1(조건 N개) |
| 다중 조건 | 조건의 모든 조합 | 케이스 수 2^N |

### 경로 기반 기법

| 기법 | 내용 |
|---|---|
| 기본 경로 시험 | 순환 복잡도만큼의 독립 경로를 모두 시험 |
| 경로 커버리지 | 모든 실행 경로를 시험. 루프가 있으면 경로 수 폭증 |
| 데이터 흐름 시험 | 변수의 정의와 사용 관계를 따라 시험 |
| 루프 시험 | 반복 0회·1회·최대 횟수 등 반복 횟수를 달리해 시험 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 구문 커버리지만으로 조건 조합 결함 미검출 | 결정·조건 커버리지 이상 적용 |
| 경로·다중 조건 커버리지의 케이스 수 폭증 | 순환 복잡도 기반 기본 경로와 MC/DC로 축소 |
| 코드에 없는 기능 누락 미발견 | 블랙박스 시험 병행 |

## Ⅵ. 제언

안전 요구가 큰 코드는 MC/DC로 각 조건의 독립 영향을 확인하고, 일반 코드는 결정 커버리지를 기준으로 적용

### 코드 중요도별 커버리지 기준

```text
코드 위험도 평가
    ├─ 안전·고신뢰 요구 → MC/DC
    └─ 일반 → 결정 커버리지
```

### 확대: MC/DC 케이스 도출

```text
조건 (A OR B) AND C
    ↓
조건마다 다른 조건을 고정하고 그 조건만 바꿔 결과 변화 확인
    ↓
케이스 수 N+1 = 4
```

### 선택 근거: 구문 커버리지와의 비교

| 구분 | 구문 커버리지 | 제언: 위험도별 커버리지 |
|---|---|---|
| 조건 영향 확인 | 없음 | MC/DC 적용 |
| 케이스 수 | 적음 | 위험도에 비례 |
| 적용 대상 | 전체 동일 | 안전 요구 코드에 강화 |
