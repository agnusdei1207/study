## 큰 그림과 30초 인출

```text
[소스코드] → [제어 흐름 그래프] → [커버리지 기준] → [테스트 케이스]
                              문장 → 분기 → 조건 → MC/DC

화이트박스 = 내부 구조를 보고 경로를 검증
V(G) = E - N + 2 = 독립 경로 수의 기준
```

## 예상문제

화이트박스 테스트의 개념과 절차를 설명하고, 주요 커버리지 기준 및 블랙박스 테스트와의 차이를 기술하시오.

## Ⅰ. 개요

- 화이트박스 테스트는 프로그램의 내부 제어 구조와 논리 경로를 바탕으로 테스트 케이스를 설계하는 구조 기반 시험이다.
- 실행되지 않은 코드, 잘못된 분기와 반복 경계 등 내부 결함을 조기에 발견하는 것이 목적이다.

## Ⅱ. 특징과 적용 절차

| 단계 | 활동 | 산출물 |
|---|---|---|
| 구조 분석 | 문장·분기·조건·반복 식별 | 코드 구조 목록 |
| 그래프화 | 노드와 간선으로 CFG 작성 | 제어 흐름 그래프 |
| 기준 선택 | 위험도에 맞는 커버리지 결정 | 시험 기준 |
| 케이스 설계 | 독립 경로와 경계값 도출 | 테스트 케이스 |
| 실행·측정 | 결과와 커버리지 수집 | 결함·측정 보고서 |

## Ⅲ. 커버리지 체계

| 기준 | 충족 조건 | 강도 |
|---|---|---|
| 문장 | 모든 실행 문장을 한 번 이상 수행 | 기본 |
| 분기·결정 | 각 결정 결과 True/False 수행 | 문장보다 강함 |
| 조건 | 각 개별 조건의 True/False 수행 | 조건 값 확인 |
| 조건·결정 | 조건과 결정 기준을 모두 충족 | 복합 논리 보강 |
| MC/DC | 각 조건이 결정 결과에 독립적으로 영향 | 안전 중요 영역 |

## Ⅳ. 기본 경로 테스트

```text
소스 → CFG 작성 → 순환 복잡도 계산 → 독립 경로 선정 → 케이스 실행
V(G) = E - N + 2 = 의사결정 노드 수 + 1 (단일 연결 그래프)
```

- 순환 복잡도는 모든 가능한 경로 수가 아니라 선형 독립 경로의 상한 기준이다.
- 반복문은 0회·1회·일반 횟수·경계 횟수로 나누어 점검한다.

## Ⅴ. 블랙박스 테스트와 비교

| 구분 | 화이트박스 | 블랙박스 |
|---|---|---|
| 관점 | 내부 구현 구조 | 요구사항과 입출력 |
| 설계 기준 | CFG, 경로, 조건 | 동등 분할, 경계값, 결정표 |
| 강점 | 숨은 분기·미실행 코드 탐지 | 누락 요구·기능 오류 탐지 |
| 한계 | 구현 의존, 경로 폭발 | 내부 경로 누락 가능 |

## Ⅵ. 적용 시 고려사항

- 커버리지 100%가 결함 부재를 의미하지 않으므로 요구 기반 시험과 병행한다.
- 위험도에 따라 목표 커버리지를 차등화하고 숫자 달성만을 위한 무의미한 테스트를 피한다.
- 외부 의존성은 테스트 대역으로 격리하되 실제 통합 시험으로 보완한다.
- 도달 불가능 코드와 과도한 복잡도는 리팩터링 대상으로 관리한다.

## Ⅶ. 결론

화이트박스 테스트는 내부 경로를 가시화하여 구조적 결함을 줄이는 수단이다. CFG와 위험 기반 커버리지를 적용하고 블랙박스 시험과 상호 보완해야 한다.

## 1교시 10점 발췌

```text
화이트박스 테스트 = 내부 구조 기반 시험
절차: 코드 분석 → CFG → 기준 선택 → 케이스 → 커버리지 측정
기준: 문장 < 분기 < 조건·결정 < MC/DC
보완: 요구 기반 블랙박스 테스트 병행
```
