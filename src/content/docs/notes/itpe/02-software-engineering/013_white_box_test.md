## Ⅰ. 화이트박스 테스트의 개요

- **개념** : 소프트웨어의 내부 소스코드 구조, 논리 경로, 제어 흐름 및 데이터 흐름을 직접 분석하여 논리적 정확성과 코드 커버리지를 검증하는 구조 기반(Structure-based) 테스트 기법.
- **배경 및 필요성** : 블랙박스 테스트만으로는 발견하기 어려운 미실행 코드(Dead Code), 숨겨진 논리적 오류, 메모리 누수, 예외 분기 누락을 조기에 색출.
- **주요 검증 도구** : JUnit, JaCoCo, SonarQube, BullseyeCoverage.

## Ⅱ. 제어 흐름 그래프(CFG) 및 커버리지 계층 구조

```text
        [ 노드 1: Start ]
               │
               ▼
        [ 노드 2: If (A > 0) ]
          /           \  (True / False 분기)
         ▼             ▼
   [ 노드 3 ]       [ 노드 4 ]
         \             /
          ▼           ▼
        [ 노드 5: End ]
```

- **구문 커버리지 (Statement, L1)** : 코드 내의 모든 실행 가능한 문장이 최소 한 번은 실행되도록 테스트.
- **결정/분기 커버리지 (Branch/Decision, L2)** : 각 조건문의 전체 결과가 참(True)과 거짓(False)이 되는 경로를 최소 한 번씩 실행.
- **조건 커버리지 (Condition, L3)** : 조건식 내부의 개별 조건식들이 독립적으로 참/거짓을 갖도록 테스트.
- **조건/결정 커버리지 (Condition/Decision)** : 개별 조건식의 참/거짓과 전체 조건문의 참/거짓을 모두 만족.
- **변경 조건/결정 커버리지 (MC/DC)** : 각 개별 조건식이 다른 조건식의 영향을 받지 않고 독립적으로 전체 결정문의 결과에 영향을 미치도록 설계 (항공/국방/철도 등 최고 안전성 요구).

## Ⅲ. 커버리지 기법별 검증 강도 및 테스트 케이스 수 비교

| 커버리지 기법 | 핵심 조건 | 케이스 수 | 검증 강도 |
|---|---|---|---|
| 구문 커버리지 | 모든 문장 1회 이상 실행 | 최소 | 낮음 |
| 결정 커버리지 | 전체 조건문 True/False 1회 이상 | 적음 | 중간 |
| 조건 커버리지 | 개별 조건 True/False 1회 이상 | 적음 | 중간 (결정 커버리지 미보장 가능) |
| MC/DC | 개별 조건이 전체 결과에 독립적 영향 입증 | $N+1$개 | 높음 (DO-178C Level A 의무) |
| 다중 조건 커버리지 | 개별 조건들의 가능한 모든 진리표 조합 실행 | $2^N$개 | 최고 (조합 폭발로 실무 적용 한계) |

## Ⅳ. 화이트박스 테스트 현장 적용 시 기술사적 제언

- **테스트 커버리지 수치에 대한 맹신 지양** : 100% 구문 커버리지가 결함 없음을 의미하지 않으므로(요구사항 누락은 탐지 불가), 경계값 분석 등 명세 기반 블랙박스 테스트와 병행하는 상호 보완적 테스팅 전략 수립.
- **CI/CD 파이프라인과 정적 분석(SAST)의 결합** : 단위 테스트 실행 시 커버리지 임계치(예: 브랜치 커버리지 80% 이상) 미달 시 빌드를 강제 중단하는 품질 게이트를 설정하여 기술 부채 누적 차단.
