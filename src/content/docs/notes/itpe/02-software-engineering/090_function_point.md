## 연관 키워드

- 기능점수(Function Point, FP), IFPUG, 미조정 기능점수(UFP), 조정 계수
- ILF, EIF, EI, EO, EQ, DET, RET, FTR, 시스템 경계

## Ⅰ. 기능점수의 개요

- 핵심 요약 : 기능점수는 사용자 관점의 데이터·트랜잭션 기능을 분류·가중 합산해 소프트웨어 규모를 산정하는 기법.
- 개념 : 사용자가 인식하는 기능을 데이터·트랜잭션 유형으로 분류하고 복잡도 가중치를 적용해 합산하는 규모 산정 기법 (**기능점수** (Function Point, FP)).
- 배경 및 필요성 : **LOC** (Line of Code) 기반 산정은 언어·구현 방식에 따라 값이 달라지고 요구 분석 단계의 측정이 곤란. 요구 수준에서 측정 가능한 기술 독립적 규모 척도 필요.
- 주요 목적 : 추정·계약·검사·생산성 평가와 요구 변경 관리에 공통으로 쓰이는 규모 기준 확보.

## Ⅱ. 기능점수의 특징 및 장점

- 핵심 요약 : 5개 기능 유형의 식별과 복잡도 가중 합산이 기술 독립적 규모 측정으로 이어짐.

1. 데이터 기능 : 시스템이 유지 관리하는 **ILF** (Internal Logical File)와 타 시스템 데이터를 참조하는 **EIF** (External Interface File) 식별 → 논리 데이터 규모 반영.
2. 트랜잭션 기능 : 데이터 변경의 **EI** (External Input), 처리 결과 전달의 **EO** (External Output), 단순 검색·회신의 **EQ** (External Inquiry) 식별 → 화면·인터페이스 기능 규모 반영.
3. 복잡도 가중 : 기능별 **DET** (Data Element Type, 데이터 요소 수)·**RET** (Record Element Type, 레코드 유형 수)·**FTR** (File Type Referenced, 참조 파일 유형 수) 판정 → 낮음·보통·높음 등급의 가중치 합산으로 규모 반영.
4. 기술 독립성 : 구현 언어·도구와 무관한 측정 → 대안 비교·수행사 선정·계약 산정의 공정성 확보.

## Ⅲ. 기능점수의 산출 절차 (흐름)

- 핵심 요약 : 경계 정의 → 기능 식별 → 복잡도 판정 → 미조정 FP → 조정 계수 적용의 절차로 산출.
- 표준 절차 : **IFPUG** (International Function Point Users Group)의 측정 표준을 기준으로 수행.
- 미조정 기능점수 (**UFP**, Unadjusted Function Point) : 5개 유형별 가중 합산의 조정 전 규모 값.
- 조정 계수 (**VAF**, Value Adjustment Factor) : 14개 일반 시스템 특성(GSC, General System Characteristics)의 점수를 반영해 UFP에 곱하는 계수.

```text
[ FP 산출 절차 ]

측정 목적·유형 확정
   ↓
시스템 경계 식별
   ↓
데이터 기능(ILF·EIF) 식별
   ↓
트랜잭션 기능(EI·EO·EQ) 식별
   ↓
DET·RET·FTR 복잡도 판정
   ↓
가중치 합산 → 미조정 FP
   ↓
조정 계수 적용 → 조정 FP
```

```text
[ 미조정 FP와 조정 구조 ]

미조정 FP(UFP)
 = Σ ( 기능 유형별 개수 × 가중치 )
   ↓
일반 시스템 특성 평가·합산
   ↓
조정 계수 산출
   ↓
조정 FP = UFP × 조정 계수
```

- 측정 산출물 : 측정 목적·경계 정의서, 기능 목록, 복잡도 판정 근거, 요구 추적 정보.

## Ⅳ. 기능점수와 LOC 기반 산정의 비교

- 핵심 요약 : FP는 요구 기능 기준의 기술 독립 규모, LOC는 구현 코드량 기준의 기술 의존 규모라는 차이.

| 비교 축 | 기능점수(FP) | LOC 기반 산정 |
|---|---|---|
| 측정 대상 | 데이터·트랜잭션 기능 | 소스 코드 행 수 |
| 산정 시점 | 요구 분석 단계부터 가능 | 언어·구현 방식 결정 이후 |
| 기술 의존성 | 언어·도구에 독립 | 언어·코딩 스타일에 종속 |
| 변경 추적 | 기능 추가·삭제 반영 용이 | 코드량 변동·생성 코드로 왜곡 가능 |
| 주요 활용 | 계약·검사·생산성 평가 | 일정·인력 추정의 보조 지표 |
| 선택 기준 | 초기 추정·대안 비교 필요 시 | 기존 코드 실적 기반 보정 시 |

## Ⅴ. 기능점수의 한계와 방안

- 핵심 요약 : 판정 주관성·비기능 미반영·경계 해석 오류를 기준 표준화와 보정 절차로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 측정자 판정 편차 | 경계·복잡도 판정의 주관성 → 산정값 불일치 | 측정 기준서·독립 검토·사례 축적 | 산정 불일치율 |
| 비기능 요구 미반영 | 성능·보안·기술 난이도 제외 → 공수 과소 추정 | 비용 동인 별도 보정·보조 모형 병행 | 추정 오차율 |
| 경계 해석 오류 | 연계 시스템 범위 혼동 → 규모 과대·과소 | 경계·연계 범위 사전 합의 문서화 | 경계 재조정 건수 |

## Ⅵ. 기능점수 활성화에 대한 기술사적 제언

- 핵심 요약 : 발주 기관·측정 전문 조직·PMO가 기준·인력·데이터 축적의 제도적 체계를 구축.

1. 발주 기관 : 공공·기업 IT 투자의 규모 산정·검사 기준에 FP 표준 도입 확산.
2. 측정 전문 조직 : 자격 보유 측정 인력 풀과 독립 검증 절차의 제도화.
3. PMO : 산정 FP·실적 공수 데이터베이스 축적으로 생산성 기준의 주기 갱신.

## Ⅶ. 결론

- 핵심 요약 : 기능점수는 요구 기능을 기준으로 규모를 측정하는 기술 독립적 산정 기법.
- 산정의 재현성과 신뢰는 경계·복잡도 판정 기준의 표준화 수준에 좌우.
