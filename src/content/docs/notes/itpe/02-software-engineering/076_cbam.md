## 1. CBAM의 개요 및 필요성

### (1) CBAM(Cost Benefit Analysis Method)의 정의
- 카네기 멜론 대학 SEI에서 제정한 **소프트웨어 아키텍처 평가 모델**로, ATAM을 통해 도출된 아키텍처 전략(Architectural Strategies)들에 대해 **투입 비용(Cost) 대비 비즈니스 편익(Benefit)을 유틸리티(Utility) 기반으로 정량화하여 투자수익률(ROI)에 따라 최적의 투자 우선순위를 결정하는 경제적 의사결정 기법**.

### (2) 핵심 필요성 (128회 기출)
- **ATAM의 한계 극복**: ATAM은 품질 속성 간의 기술적 트레이드오프(민감점, 절충점)는 식별하지만, "한정된 프로젝트 예산 내에서 어떤 아키텍처 전략을 먼저 구현해야 하는가"라는 경제적 답을 주지 못함.
- **공학과 비즈니스의 언어 통합**: 엔지니어의 기술적 용어(지연시간 50ms 감축 등)를 경영진과 발주자가 이해할 수 있는 '비용 대비 효용(ROI)'이라는 재무적 언어로 환산.

## 2. CBAM 핵심 메커니즘 및 수행 절차

### (1) CBAM 의사결정 프레임워크 구조도
```text
+-------------------------------------------------------------------------+
|                  CBAM (Cost Benefit Analysis Method) 의사결정 구조      |
+-------------------------------------------------------------------------+
| [ ATAM 산출물 ] : 품질 속성 시나리오 (가용성, 성능, 보안 등)            |
|         │                                                               |
|         v                                                               |
| +─────────────────────────────────────────────────────────────────────+ |
| │ 1. 시나리오 정제 및 유틸리티($U$) 할당 (현재값 대비 목표값의 만족도)  │ |
| │ 2. 아키텍처 전략($S_i$) 매핑 (분산 캐시, DB 샤딩, 서킷브레이커 등)  │ |
| │ 3. 편익($b_i$) 산정 : 시나리오 가중치($W_j$) $\times$ 유틸리티 증가분(Δ$U$) │ |
| │ 4. 투입 비용($C_i$) 산정 : 라이선스, 개발 인건비, 인프라 운영비     │ |
| +─────────────────────────────────────────────────────────────────────+ |
|         │                                                               |
|         v                                                               |
|   [ ROI 산출 공식 : $\text{ROI}_i = \frac{b_i}{C_i}$ ]                   |
|         │                                                               |
|         v                                                               |
|   [ 최종 의사결정 : 주어진 예산 한도 내에서 ROI 최상위 전략 선별 채택 ] |
+-------------------------------------------------------------------------+
```

### (2) CBAM 핵심 산출 수식
1. **아키텍처 전략 $S_i$의 총 편익 ($b_i$)**:
   $$b_i = \sum_j (W_j \times (U_{ij} - U_{current, j}))$$
   - $W_j$: 시나리오 $j$의 비즈니스 중요도 가중치.
   - $U_{ij} - U_{current, j}$: 전략 $S_i$ 적용 시 개선되는 유틸리티 증분.
2. **투자수익률 (ROI)**:
   $$\text{ROI}_i = \frac{b_i}{C_i} \quad (C_i: \text{전략 } S_i \text{ 도입에 드는 총비용})$$

### (3) CBAM 6단계 표준 수행 절차
| 단계 | 단계명 | 핵심 활동 및 산출물 |
|---|---|---|
| **1단계** | 시나리오 정리 (Collate Scenarios) | ATAM에서 도출된 품질 시나리오를 검토하고 비즈니스 목표와 연계 |
| **2단계** | 시나리오 정제 (Refine Scenarios) | 시나리오의 최악, 현재, 기대, 최선 품질 수준(Response Measure) 정의 |
| **3단계** | 유틸리티 우선순위화 | 이해관계자들이 각 품질 수준에 0~100 점수의 유틸리티를 부여 |
| **4단계** | 아키텍처 전략 도출 및 매핑 | 각 시나리오의 목표를 달성할 구체적 기술 전략(Design Tactics) 도출 |
| **5단계** | 비용 및 편익 산정 | 각 전략 구현에 드는 비용($C$)과 전략 적용 시 유틸리티 증가분(편익 $b$) 계산 |
| **6단계** | ROI 계산 및 전략 선정 | ROI를 기준으로 전략들을 정렬하고 예산 범위 내에서 실행 계획 확정 |

## 3. 주요 아키텍처 평가 모델 비교

| 비교 항목 | SAAM | ATAM | CBAM |
|---|---|---|---|
| **제정 기관** | SEI (1994) | SEI (2000) | SEI (2003) |
| **주요 목적** | 아키텍처 수정용이성(Modifiability) 중심 평가 | 비기능 품질 속성 간의 **트레이드오프 분석** | 아키텍처 전략의 **경제적 비용-편익(ROI) 분석** |
| **평가 관점** | 기술적 기능 구조 | 품질 속성 간 상충 관계 (민감점, 절충점) | **비즈니스 가치, 투자 비용, 예산 최적화** |
| **결과물** | 변경 시나리오 영향도 | 리스크 테마, 위험/비위험 요소 | **아키텍처 전략별 ROI 순위표 및 투자 우선순위** |

## 4. 실무 실패 시나리오 및 해결 방안

| 실패 시나리오 | 근본 원인 | 공학적 해결 방안 | 정량적 기대효과 |
|---|---|---|---|
| **성능 개선안 10개 중 예산 한도로 갈등**<br>(부서 간 자기 시스템 우선 투자 요구로 파행) | 객관적 경제성 평가 없이 목소리 큰 부서의 주관적 요구에 의존 | CBAM 유틸리티 곡선 기반 전략별 비용 대 편익(ROI) 매트릭스 도출 | 이해관계자 100% 합의 도출, 예산 내 최대 편익 달성 |
| **수십억 들인 Active-Active DR의 효용 미미**<br>(오버엔지니어링으로 인한 예산 낭비) | 비즈니스 중단 손실액 대비 과도한 인프라 투자 (RPO/RTO 과다 스펙) | CBAM의 한계 효용 체감 분석을 통해 RTO 1시간의 적정 절충안(Warm Standby) 채택 | 불필요한 인프라 투자 비용 40억 원 절감 |
| **아키텍처 변경 후 기대 성능 미달**<br>(비용만 쓰고 목표 TPS 개선 실패) | 아키텍처 전략 도입 비용만 계산하고 실제 유틸리티 증분을 과대평가 | 프로토타입 기반 PoC 실측 데이터와 CBAM 편익 산정을 연계 검증 | 아키텍처 투자 실패율 0% 격리 |

## 5. 기술사 답안 차별화 포인트 (기술사의 시각)

```text
[과거: 기술 지상주의 아키텍처]             [현대: 가치 주도형 아키텍처 (Value-Driven)]
- 최고 스펙, 최신 기술 무조건 도입 ──▶   - 한정된 예산과 비즈니스 ROI 기반 전략 선별
- "왜 그 기술을 썼는가?"에 비용 답변 부재 ──▶ - "비용 $C$ 대비 유틸리티 편익 $b$가 극대화됨"을 입증
- ATAM 기술 평가 단독 수행          ──▶   - ATAM(기술 위험 식별) + CBAM(경제적 실행 우선순위) 통합
```

- **ATAM과 CBAM의 파이프라인식 통합 거버넌스**: 아키텍처 평가는 기술과 경제성이 분리될 수 없음. **1단계에서 ATAM을 통해 아키텍처의 구조적 결함과 위험(Risk)을 식별하고 트레이드오프 전략을 도출한 후, 2단계에서 CBAM을 가동하여 예산 제약 내 ROI 1위~3위 전략을 최종 선정**하는 2단계 통합 거버넌스 프레임워크를 기술사 답안의 결론으로 제시해야 함.
- **클라우드 FinOps와의 실무적 접목**: 최근 클라우드 네이티브 환경에서 아키텍처 변경(서버리스 전환, 캐시 레이어 도입 등)은 즉각적인 월간 클라우드 비용 변동으로 이어짐. 따라서 CBAM의 비용($C$) 요소에 **FinOps의 총소유비용(TCO) 및 지속적 클라우드 과금 지표**를 결합하여 살아있는 경제성 평가 체계를 구축하는 것이 기술사로서 제시할 차별화 포인트임.
