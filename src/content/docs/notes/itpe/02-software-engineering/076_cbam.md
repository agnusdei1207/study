## 연관 키워드
- CBAM, ATAM, SEI, 효용 곡선, ROI, 아키텍처 전략, 시나리오 우선순위화, AHP

### Ⅰ. CBAM의 개요

- 핵심 요약 : 아키텍처 대안의 비용과 효용을 정량 분석해 투자 우선순위를 정하는 경제성 평가 방법론.
- 개념 : CBAM(Cost Benefit Analysis Method)은 SEI(Software Engineering Institute)가 개발한 아키텍처 경제성 평가 방법으로, ATAM(Architecture Tradeoff Analysis Method) 이후에 아키텍처 전략 대안의 비용과 효용, 불확실성을 정량 분석해 투자 우선순위를 정하는 의사결정 프레임워크.
- 배경 및 필요성 : ATAM으로 아키텍처의 위험과 절충점을 찾은 뒤에도, 제한된 예산에서 어떤 개선 전략을 먼저 실행할지 판단할 경제적 기준이 없음.
- 주요 목적 : 아키텍처 전략의 ROI(Return on Investment, 투자수익률)를 산출해 예산 배분과 비즈니스 목표 정렬의 근거를 확보하는 것.

### Ⅱ. CBAM의 특징 및 장점

- 핵심 요약 : ATAM 산출물을 입력으로 효용 곡선과 ROI를 계산해 투자 순위를 내는 구조.

1. 경제적 정량 분석 : 전략별 비용, 효용, 불확실성을 수치로 다룸 → 기술 판단을 예산 판단으로 연결.
2. ATAM 후속 연계 : ATAM의 유틸리티 트리와 품질 시나리오를 입력으로 재사용 → 분석을 처음부터 다시 하지 않음.
3. 효용 곡선(Utility Curve) : 품질 속성 척도별 이해관계자 만족도를 0~100 척도 함수로 표현 → 품질 수준에 따른 가치 변화를 드러냄.
4. ROI 중심 의사결정 : 전략별 ROI 순위를 산출 → 한정된 예산 배분의 근거 확보.
5. 비즈니스 정렬 : 기술 품질 목표와 경영 목표의 연결을 명시적으로 검증 → 경영진 설득에 유리한 근거 제공.

### Ⅲ. CBAM의 구조 (흐름)

- 핵심 요약 : 시나리오 정리에서 투자 우선순위 결정까지 이어지는 순차 분석 흐름.

```text
[ 시나리오 정리 ]
 - ATAM 품질 시나리오, 비즈니스 우선순위화
   ↓
[ 효용 곡선 도출 ]
 - 최악·목표·최상 응답별 효용 수치화
   ↓
[ 아키텍처 전략 선정 ]
 - 시나리오를 충족하는 전략 대안 도출
   ↓
[ 비용과 효용 산정 ]
 - 구축·운영 비용과 효용 증가분 계산
   ↓
[ ROI 산출과 우선순위 결정 ]
 - 한정된 예산 안에서 최적 조합 선택
```

- 효용 곡선의 개념은 응답 수준에 따른 효용 점수의 변화로 나타낸다.

```text
[ 효용 곡선 예시: 응답 시간 ]

응답 시간 : 최상 → 목표 → 최악
효용 점수 : 높음 → 중간 → 낮음
           (0~100 척도)
```

- ROI 계산 : 전략 Si를 적용해 얻는 전체 효용 증가분 ΔUi를 도입 총비용 Ci로 나눈다 (ROIi = ΔUi / Ci).

### Ⅳ. ATAM과 CBAM 비교

- 핵심 요약 : 기술적 타당성을 검증하는 ATAM과 경제적으로 최적안을 고르는 CBAM의 순차 연계 구조.

| 비교 항목 | ATAM (품질속성 평가) | CBAM (경제성 평가) |
|---|---|---|
| 주요 목적 | 아키텍처의 품질속성 충족 여부에 대한 기술적 타당성 검증 | 아키텍처 대안 중 경제적 ROI가 높은 최적안 결정 |
| 평가 관점 | 기술적 리스크, 민감점, 절충점(Trade-off) 식별 | 비용, 효용, 투자 회수율(ROI) |
| 분석 입력 | 비즈니스 드라이버, 소프트웨어 아키텍처 문서 | ATAM의 유틸리티 트리와 도출된 품질 시나리오 |
| 주요 산출물 | 리스크와 비리스크 목록, 절충점 매트릭스 | 아키텍처 전략별 ROI 순위표, 투자 로드맵 |
| 수행 시점 | 아키텍처 초기 설계와 변경 검증 시점 | ATAM 직후 구현 예산 집행 우선순위를 정하는 시점 |

### Ⅴ. CBAM의 한계와 방안

- 핵심 요약 : 예산 배분의 객관화라는 이점과 효용 산정의 주관성, 전략 간 상충 반영의 한계.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 효용과 비용 산정의 주관성 | 이해관계자별 품질 가치 평가와 구축 비용 추정의 편차가 커서 점수의 객관성 확보가 어려움 | 델파이(Delphi) 기법과 AHP(Analytic Hierarchy Process)를 결합해 가중치를 도출하고, 과거 프로젝트 실적과 교차 검증 | 추정치와 실적의 차이율 |
| 전략 간 상호작용 미반영 | 복수 전략을 동시에 적용할 때의 시너지와 충돌을 단순 합산 모델로는 포착하지 못함 | 전략 간 종속성 매트릭스 작성, 유틸리티 트리의 민감도와 절충점 분석 선행 | 종속성 검토 완료율 |
| 요구 변화에 따른 효용 진부화 | 1회성 분석 결과가 급변하는 요구와 기술 변화를 따라가지 못함 | 릴리스나 분기 단위의 롤링 재분석, 몬테카를로(Monte Carlo) 시뮬레이션 도입 | 재분석 주기 준수율 |

### Ⅵ. 엔터프라이즈 아키텍처 투자 결정에 대한 기술사적 제언

- 핵심 요약 : 기술 부채 상환과 아키텍처 투자를 ROI로 연결하고, 평가 점수의 공정성을 구조적으로 확보하는 방향.

1. 레거시 리팩터링이나 클라우드 전환처럼 당장 기능이 늘지 않는 투자는 경영진 승인을 얻기 어려우므로, 기술 부채 상환 계획을 CBAM 방식으로 장애 감소와 성능 향상의 효용과 ROI로 환산해 보고하는 체계를 둠.
2. 효용 점수가 특정 이해관계자의 편향에 치우치지 않도록, 비즈니스 담당자와 개발자, 인프라 엔지니어의 평가에 가중치를 나누어 반영하는 다속성 효용 이론(MAUT, Multi-Attribute Utility Theory)을 함께 적용하면 평가의 공정성을 높임.

### Ⅶ. 결론

- 핵심 요약 : CBAM은 아키텍처 의사결정을 기술 판단에서 경제적 합리성의 영역으로 넓히는 프레임워크.
- 시사점 : 효용 산정의 객관화, 전략 간 상충 분석, 주기적 재평가가 CBAM의 실효성을 좌우하는 핵심 조건.
