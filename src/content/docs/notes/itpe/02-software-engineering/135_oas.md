## 지식 위치

소프트웨어공학 > 웹 아키텍처·인터페이스 설계 > OpenAPI 명세

## 30초 인출

- 본질: RESTful 웹 서비스의 엔드포인트, 요청/응답 스키마, 인증 방식을 기계 판독 가능한 표준 포맷(YAML/JSON)으로 정의하는 인터페이스 기술 명세
- 메커니즘: Design-First 또는 Code-First 기반 명세 작성 → Spectral 기반 정적 린팅 → Swagger-UI/Redoc 문서화, Mock 서버(Prism) 생성, 클라이언트 SDK 자동 생성 및 Dredd 기반 계약 검증 수행
- 통찰: 문서화 전용으로만 취급할 경우 실제 백엔드 구현과의 불일치(Drift)가 발생하므로 CI/CD 파이프라인 상에서 스키마 유효성 검사 및 소비자 주도 계약 테스트(Pact)와 연계한 자동화 필수

<details>
<summary>핵심 용어</summary>

- **OAI (OpenAPI Initiative)** : OpenAPI Specification 표준을 관리 및 발전시키는 Linux Foundation 산하 컨소시엄
- **Design-First** : 코드 작성 전 OAS 명세서를 먼저 정의하고 프론트엔드/백엔드 간 계약 합의 후 병렬 개발을 진행하는 방식
- **Code-First** : 소스 코드에 애너테이션(@Operation 등)을 작성하여 런타임 또는 빌드 타임에 OAS 명세를 사후 추출하는 방식
- **Prism** : OAS 문서를 기반으로 실제 백엔드 동작을 모방하는 가상 Mock API 서버를 구동하는 도구
- **Spectral** : OAS 명세서가 사내 표준(kebab-case 경로, 설명 누락 방지 등)을 준수하는지 검증하는 API 린팅 도구
</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | RESTful API의 인터페이스 구조(엔드포인트, 파라미터, 페이로드, 응답 코드, 보안)를 프로그래밍 언어와 무관하게 JSON/YAML로 기술하는 글로벌 표준 명세 |
| 목적 | 인간과 컴퓨터가 별도 소스 코드 접근 없이 서비스 역량을 이해할 수 있도록 표준 계약을 제공하고, 문서화/테스트/코드 생성 자동화 달성 |

## Ⅱ. 핵심 특징

| 특징 | 세부 내용 |
|---|---|
| 벤더 및 언어 독립성 | 특정 클라우드 벤더나 개발 언어에 종속되지 않고 범용 JSON Schema 기반으로 API 계약 모델링 |
| 도구 생태계 호환성 | Swagger UI, Redoc, Postman, Prism 등 수많은 오픈소스 및 상용 툴 체인과 즉시 연동 |
| 기계 가독성 (Machine-Readable) | 파서 및 코드 생성기를 통해 클라이언트 SDK, 서버 스텁, API 게이트웨이 라우팅 룰을 자동 변환 |
| 재사용 및 모듈화 | `$ref` 구문을 활용하여 공통 데이터 모델(components/schemas) 및 에러 응답 재사용 지원 |

API 우선(API-First) 개발 환경에서 서비스 간 결합도를 낮추고 계약 기반 협업을 보장하는 핵심 인터페이스 자산으로 기능.

## Ⅲ. 체계·프로세스

```text
[1. API 계약 정의 (OAS)]
  - openapi.yaml (info, paths, components, security 정의)
       │
       ▼ Spectral 린팅 및 스타일 가이드 정적 검증
[2. 병렬 개발 및 도구 체인 가동]
  ┌─────────────────────────────────┬─────────────────────────────────┐
  │         프론트엔드 팀           │           백엔드 팀             │
  │  - Prism 기반 Mock 서버 구동     │  - 서버 스텁 코드 자동 생성     │
  │  - UI 컴포넌트 병렬 개발 착수   │  - 비즈니스 로직 구현 착수      │
  └─────────────────────────────────┴─────────────────────────────────┘
       │                                     │
       ▼                                     ▼
[3. CI/CD 파이프라인 및 계약 검증 (Contract Testing)]
  - Dredd / Schemathesis 기반 OAS 명세 vs 실제 응답 스키마 대조
  - 불일치 발생 시 빌드 실패 처리
       │
       ▼
[4. 배포 및 운영 자동화]
  - Swagger UI / Redoc 실시간 포털 배포
  - API Gateway (Kong, AWS API Gateway) 라우팅 및 유효성 검증 룰 자동 배포
```

명세 작성에서부터 정적 검증, Mock 서버를 통한 프론트/백엔드 병렬 개발, CI/CD 상의 계약 일치성 검증까지 이어지는 전 수명주기 프로세스.

## Ⅳ. 종류·비교

| 비교 항목 | Design-First 방식 | Code-First 방식 |
|---|---|---|
| **작업 흐름** | OAS 명세 설계 및 합의 ──► Mocking 및 병렬 구현 | 백엔드 코드 작성 ──► Swagger 애너테이션 사후 추출 |
| **장점** | 프론트/백엔드 완전한 병렬 개발, API 계약의 일관성 및 높은 완성도 | 개발 진입 장벽 낮음, 코드와 명세의 동기화 용이 |
| **단점** | 초기 명세 설계 및 합의 공수 소요, 명세 변경 시 구현 반영 오버헤드 | API 일관성 결여 가능, 클라이언트 개발 지연, 백엔드 프레임워크 종속 |
| **적합한 환경** | 대규모 엔터프라이즈, 마이크로서비스(MSA), 다자간 협업 | 소규모 프로토타입, 단일 풀스택 개발, 빠른 기능 검증 |

### OAS 3.x 주요 구성 객체

| 핵심 객체 | 설명 및 포함 내용 |
|---|---|
| **openapi / info** | OAS 버전 선언, API 제목, 설명, 버전, 라이선스 및 연락처 정보 |
| **servers** | API가 호스팅되는 베이스 URL 목록 (개발, 스테이징, 운영 환경 분리) |
| **paths** | 개별 엔드포인트 URI 경로 및 지원 HTTP 메서드(GET, POST 등), 요청/응답 정의 |
| **components** | `$ref`로 재사용 가능한 schemas, responses, parameters, securitySchemes 집합 |
| **security** | 전역 또는 엔드포인트별 적용되는 인증 방식 선언 (OAuth2, Bearer JWT, API Key) |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 코드 변경 후 OAS 명세가 갱신되지 않아 명세와 실제 API 응답 간 괴리(Schema Drift) 발생 | CI/CD 파이프라인에 Dredd, Prism Proxy, Pact 등 계약 테스트 도구를 연동하여 배포 게이트 강제 |
| 개발자별 작성 스타일 편차로 인한 네이밍 룰 및 에러 규격 불일치 | Spectral 린터를 Git 커밋 훅(pre-commit)에 등록하여 스타일 가이드 준수 강제화 |
| 대규모 시스템에서 단일 YAML 파일 비대화로 인한 가독성 및 유지보수성 저하 | openapi-cli 등을 활용하여 도메인별 YAML 분할 관리 후 빌드 타임 단일 번들링 기법 적용 |

## Ⅵ. 제언

API-First 거버넌스 체계를 수립하여 Design-First 원칙을 조직 표준으로 확립하고, API 카탈로그 및 게이트웨이와의 자동 동기화를 통한 완전 자동화 파이프라인 구축 권장.

```text
[API 수명주기 거버넌스 파이프라인]
  Git 저장소 (OAS PR) → Spectral 검증 → 승인 후 Mock 배포 → 백엔드 배포 시 계약 테스트 → API 게이트웨이 동기화
```

| 검증 단계 | 인터페이스 설계 단계 | 지속적 배포(CD) 단계 |
|---|---|---|
| 핵심 통제 | Spectral 린팅 및 개발자 간 RFC 리뷰 | Schemathesis 기반 스키마 적합성 및 퍼징 테스트 |
| 관리 목표 | 일관된 명명 규칙 및 보안 스키마 표준화 | 프로덕션 배포 시 Breaking Change 무중단 사전 방지 |
