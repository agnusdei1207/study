## 연관 키워드
- 소프트웨어 안전성, FTA, FMEA, HAZOP, STPA, 위험통제, 안전요구사항

### Ⅰ. 소프트웨어 안전성 분석의 개요

- 핵심 요약 : 안전성 분석은 시스템 위험과 안전 제약을 식별해 설계·시험·운영 통제로 연결하는 활동.
- 개념 : 고장·오작동·제어 결함이 인명·환경·자산에 미치는 위험을 분석하고 허용 가능한 수준으로 낮춤(**소프트웨어 안전성 분석**, Software Safety Analysis).
- 배경 및 필요성 : 복잡한 소프트웨어가 물리 시스템의 제어·보호 기능에 관여하면서 단일 결함의 결과가 중대해짐.
- 주요 목적 : 위험 시나리오, 안전요구사항, 검증증거를 추적 가능한 안전 논증으로 구성.

### Ⅱ. 안전성 분석기법의 특징 및 장점

- 핵심 요약 : FTA는 상위 사고에서 원인을 하향 추적, FMEA는 구성요소 고장을 상향 검토, HAZOP은 설계 의도 이탈을 탐색.

1. FTA : Top Event를 논리게이트로 분해 → 사고 조합과 절단집합 분석.
2. FMEA : 고장모드·영향·원인·통제 검토 → 부품·기능별 위험 선제 확인.
3. HAZOP : guide word와 변수 조합으로 편차 생성 → 운전·제어 시나리오 탐색.
4. STPA : 제어구조·안전제약과 unsafe control action 분석 → 구성요소 고장에 한정되지 않는 상호작용 위험 검토.

### Ⅲ. 분석 절차와 산출물 (흐름)

- 핵심 요약 : 시스템 경계·위험 정의 → 사고·위험 시나리오 분석 → 안전제약·요구 도출 → 통제·검증 증거 추적.

```text
시스템·운영맥락 정의 → 위험 식별(FTA/FMEA/HAZOP/STPA)
        → 안전요구·제약 → 설계 통제 → 시험·검증 → 잔여위험 승인
```

```text
위험원 → 위험상황 → 사고·손실
   ↓ 예방·탐지·완화 통제
안전요구 → 구현항목 → 검증사례·추적증거
```

- 안전요구는 시스템·소프트웨어 요구, 시험사례, 안전 케이스의 논증·증거와 연결.

### Ⅳ. FTA·FMEA·HAZOP·STPA 비교

- 핵심 요약 : 기법은 사고 원인 분해, 구성요소 고장, 설계편차, 제어 상호작용 등 서로 다른 위험 관점을 제공.

| 비교 축 | FTA | FMEA | HAZOP | STPA |
|---|---|---|---|---|
| 분석 출발점 | 상위 사고(Top Event) | 구성요소·기능 고장모드 | 설계 의도·공정 변수 | 제어구조·안전제약 |
| 대표 산출 | 논리 트리·최소 절단집합 | 영향·심각도·발생·검출성·조치 | guide word별 편차·원인·결과·보호조치 | unsafe control action·손실 시나리오 |
| 적합한 상황 | 사고 조합·원인 경로 분석 | 부품·기능별 예방 우선순위 | 공정·운전·인터페이스 위험 | 소프트웨어·인간·장치 상호작용 |

### Ⅴ. 안전성 분석의 한계와 방안

- 핵심 요약 : 단일 기법·RPN 점수에 의존하지 말고 독립 검토·시나리오 교차분석·요구 추적으로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 분석 경계·가정 누락 | 사고 경로가 트리 밖에 남음 | 운영·유지·외부 인터페이스 포함 경계검토 | 미포함 시나리오 수 |
| FMEA RPN 오용 | 동일 곱 점수의 위험 차이 은폐 | 심각도 기준 별도 게이트·전문가 판단 병행 | RPN 기준 위반 |
| 문서 중심 운영 | 통제가 코드·시험에 반영되지 않음 | 안전요구 추적과 독립 안전검토 | 통제 미반영 항목 수 |

### Ⅵ. 안전성 보증 제언

- 핵심 요약 : 안전책임자는 위험별 통제소유자·검증증거·잔여위험 승인권자를 지정.

1. 시스템 엔지니어는 도메인 기능안전 표준과 시스템 위험분석 기법을 조합.
2. 소프트웨어팀은 안전요구를 설계·코드·시험에 추적하고 변경 시 영향분석.
3. 독립 안전평가자는 분석 가정·통제효과·시험증거를 검토해 안전 케이스 갱신.

### Ⅶ. 결론

- 핵심 요약 : FTA·FMEA·HAZOP·STPA는 안전위험을 서로 다른 방향과 관점에서 찾아 통제요구로 바꾸는 분석기법.
- 시사점 : 안전성은 분석문서의 양보다 요구·구현·시험·잔여위험 승인 간 추적성으로 보증.
