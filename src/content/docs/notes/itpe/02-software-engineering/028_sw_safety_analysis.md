## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 품질·안전·신뢰성 → **SW 안전성 분석(FTA·FMEA·HAZOP)**

## 30초 인출

- 본질: 임베디드, 자동차, 의료 등 미션 크리티컬 시스템에서 소프트웨어 결함이 치명적 사고(Catastrophic Hazard)로 전이되는 경로를 식별하고 위험을 사전 통제하는 안전 공학 분석 체계
- 메커니즘: 연역적 톱다운 분석(FTA의 AND/OR 게이트 및 최소 컷셋) + 귀납적 바텀업 분석(FMEA의 고장 모드 및 RPN 평가) + 정성적 편차 분석(HAZOP의 가이드워드)
- 통찰: 전통적 단일 기법만으로는 복합 소프트웨어 오작동을 완벽히 방어할 수 없으므로 시스템 이론 기반의 STPA 기법 연계 및 결함 방지(Fail-Safe/Fail-Operational) 아키텍처 내재화 필수

<details>
<summary>핵심 용어</summary>

- **Software Safety(소프트웨어 안전성)** : 소프트웨어의 오작동이나 예기치 않은 동작이 인명 피해, 환경 파괴, 심각한 재산 손실을 유발하지 않도록 위험을 허용 수준 이하로 통제하는 품질 특성
- **FTA(Fault Tree Analysis)** : 시스템 최상위 사고(Top Event)로부터 출발하여 논리 게이트(AND/OR)를 통해 하위 기본 결함 원인을 추적하는 연역적(Top-down) 분석 기법
- **FMEA(Failure Mode and Effects Analysis)** : 개별 부품이나 소프트웨어 모듈의 잠재적 고장 모드가 상위 시스템에 미치는 영향을 분석하고 RPN으로 우선순위를 매기는 귀납적(Bottom-up) 기법
- **HAZOP(Hazard and Operability Study)** : 공정 파라미터(온도, 압력, 흐름)에 표준 가이드워드(No, More, Less, Reverse 등)를 조합하여 의도된 동작에서의 이탈(Deviation)을 탐색하는 기법
- **Minimal Cut Set(최소 컷셋)** : 최상위 사고(Top Event)를 유발하는 기본 결함 사건들의 최소 조합으로, 단일 사건으로 구성된 컷셋은 단일 고장점(SPOF)을 의미
- **RPN(Risk Priority Number)** : FMEA에서 고장의 심각도(S) × 발생도(O) × 검출도(D)의 곱으로 산출하여 조치 우선순위를 결정하는 정량 지표

</details>

## 2~4교시 25점 답안

## Ⅰ. SW 안전성 분석의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 안전 필수 시스템(Safety-Critical Systems)에서 소프트웨어의 오류나 예외 상황이 인명, 환경, 재산에 재앙적 사고를 일으키지 않도록 잠재 위험원을 체계적으로 식별, 분석, 통제하는 공학적 활동 |
| 목적 | 시스템 잠재 결함의 선제적 제거, 안전 무결성 수준(SIL/ASIL) 충족 및 Fail-Safe 기반 안전 아키텍처 설계 근거 확보 |

## Ⅱ. SW 안전성 분석의 핵심 특징

| 특징 | 의미 |
|---|---|
| 다각적 교차 검증 | 사고 중심 연역(FTA), 부품 중심 귀납(FMEA), 프로세스 편차(HAZOP)의 상호 보완적 분석 적용 |
| 인과 관계 가시화 | 불 대수(Boolean Logic)와 논리 게이트를 통해 복합 고장 경로를 직관적으로 도해화 |
| 안전 요구사항 직결 | 분석된 위험 요인을 시스템 및 소프트웨어 기능 안전 요구사항(SSR)으로 즉각 환류 |
| 국제 표준 준거성 | IEC 61508(기능안전 일반), ISO 26262(자동차), DO-178C(항공) 등 산업별 표준 규격 만족 |

## Ⅲ. SW 안전성 분석 체계 및 위험원 분석 프로세스

### 안전성 분석 전주기 프레임워크 및 FTA 논리 전개 구조

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [시스템 위험원 식별 및 정의]                    │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
           ┌────────────────────────┼────────────────────────┐
           ▼ (Top-down 연역 분석)    ▼ (Bottom-up 귀납 분석)  ▼ (Deviation 분석)
    [FTA (결함 수목 분석)]     [FMEA (고장 영향 분석)]    [HAZOP (가이드워드)]
     - 최상위 사고(Top Event)   - 단위 모듈 고장 모드    - 파라미터 + 가이드워드
     - AND / OR 논리 게이트     - 심각도/발생도/검출도    - 의도된 동작 이탈 탐색
     - 최소 컷셋(MCS) 도출      - RPN 우선순위 산출       - 원인 및 대응책 도출
           │                        │                        │
           └────────────────────────┼────────────────────────┘
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                [위험원 평가 및 안전 무결성 수준(SIL) 할당]             │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                    [FTA 논리 게이트 메커니즘]                          │
│                                                                        │
│                      [Top Event: 차량 급발진 사고]                     │
│                                   │                                    │
│                              (OR Gate) ◄─── 하나만 발생해도 사고 초래   │
│                        ┌──────────┴──────────┐                         │
│                        ▼                     ▼                         │
│               [브레이크 페달 고장]    [가속 제어 루프 오동작]          │
│                                              │                         │
│                                         (AND Gate) ◄── 동시 발생 시만 사고
│                                       ┌──────┴──────┐                  │
│                                       ▼             ▼                  │
│                                  [스로틀 센서오류] [Watchdog 무반응]   │
│                                                                        │
│   ★ 최소 컷셋(MCS): 1차 컷셋 {브레이크 고장} → SPOF로서 최우선 제거   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│         [안전 요구사항 명세 → Fail-Safe 아키텍처 설계 → V&V 안전 검증] │
└────────────────────────────────────────────────────────────────────────┘
```

### 3대 안전성 분석 기법의 핵심 구성요소

| 분석 기법 | 핵심 구성요소 | 주요 역할 및 분석 절차 |
|---|---|---|
| **FTA (결함 수목 분석)** | Top Event, 논리 게이트(AND, OR), 기본 사상(Basic Event), 최소 컷셋 | 시스템 사고로부터 하위 원인을 불 대수 트리로 분해하여 단일 고장점(SPOF) 식별 |
| **FMEA (고장 영향 분석)** | 잠재적 고장 모드, 고장 영향, 고장 원인, 심각도(S), 발생도(O), 검출도(D), RPN | 부품/코드 레벨의 결함이 상위 시스템에 미치는 영향을 시트 형태로 정량 평가 |
| **HAZOP (위험 및 운전성)** | 프로세스 파라미터(Flow, Temp, State), 가이드워드(No, More, Less, Other) | 정상 설계 의도에 가이드워드를 결합하여 공정 변수 이탈(Deviation) 시나리오 도출 |

## Ⅳ. FTA vs FMEA vs HAZOP 비교

### 안전성 분석 기법 간 특성 비교

| 비교 항목 | FTA (Fault Tree Analysis) | FMEA (Failure Mode and Effects) | HAZOP (Hazard & Operability) |
|---|---|---|---|
| **분석 접근법** | **연역적 (Deductive, Top-down)** | **귀납적 (Inductive, Bottom-up)** | **탐색적 (Exploratory, Matrix)** |
| **분석 출발점** | 시스템 최상위 사고 (Top Event) | 개별 하위 컴포넌트/모듈의 고장 모드 | 설계 의도 파라미터 및 프로세스 변수 |
| **분석 도구** | 불 논리 트리 다이어그램, 게이트 기호 | 정형화된 FMEA 표준 워크시트 | 가이드워드 조합 매트릭스 |
| **정량/정성** | 정량 분석 가능 (고장 확률 계산) | 정량화(RPN) 또는 정성 분석 | 정성적 분석 중심 |
| **도출 핵심** | 최소 컷셋(MCS), 단일 고장점(SPOF) | 심각도 높은 고장 모드 및 RPN 개선안 | 변수 이탈(Deviation)에 대한 방호책 |
| **최적 적용 단계** | 시스템 개념 설계 및 아키텍처 수립 단계 | 상세 설계, 구현 및 모듈 인터페이스 단계 | 요구사항 도출 및 공정/제어 프로세스 설계 |

### 안전 아키텍처 제어 메커니즘

| 메커니즘 | 동작 원리 | 적용 대상 시스템 |
|---|---|---|
| **Fail-Safe (고장 시 안전 정지)** | 고장 검출 시 시스템을 사전 정의된 무해한 안전 상태(정지, 전원 차단)로 전이 | 철도 신호 제어, 원자력 발전소 긴급 차단 |
| **Fail-Operational (고장 시 지속 운용)** | 고장이 발생해도 다중화된 백업 채널로 전환하여 정상 기능 지속 수행 | 자율주행 조향/제동 제어, 항공기 플라이 바이 와이어 |
| **Watchdog Timer (워치독 타이머)** | 하드웨어 타이머를 소프트웨어가 주기적 리셋하며, 루프 정지 시 시스템 재부팅 | 마이크로컨트롤러(MCU), 차량용 ECU 제어기 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 컴포넌트 개별 고장만 다루어 복잡한 시스템 간 상호작용 및 타이밍 위험 간과 | 시스템 이론 기반 사고 모델인 STPA(System-Theoretic Process Analysis) 병행 적용 |
| FTA 및 FMEA 작성 시 분석자의 주관적 판단에 따른 심각도/발생도 왜곡 발생 | 역사적 필드 결함 데이터베이스 기반 정량 척도 기준서 확립 및 다학제 팀 교차 검토 |
| 대규모 임베디드 소프트웨어에서 결함 트리와 고장 모드의 폭발적 조합 증가 | 안전성 분석 전용 CASE 도구(Ansys Medini Analyze 등)를 통한 모델 기반(MBSE) 분석 자동화 |

## Ⅵ. 제언

정형 기법(Formal Methods) 기반 모델 체킹과 안전성 분석 결과의 요구사항 추적성 매트릭스(RTM) 자동 연계

### 안전 요구사항 추적 및 검증 자동화 파이프라인

```text
[FTA / FMEA / HAZOP 위험원 분석]
       ↓
[안전 요구사항(Safety Requirements) 도출]
  ├─ SIL / ASIL 등급 할당
  └─ 추적성 링크(Traceability Link) 부여
       ↓
[SysML / AADL 모델링 및 정형 모델 체킹]
  ├─ TLA+ / UPPAAL: 데드락 및 안전 불변식(Invariant) 검증
  └─ Fail-Safe 상태 전이 로직 수학적 증명
       ↓
[HIL(Hardware-in-the-Loop) 시뮬레이션 기반 결함 주입 테스트(Fault Injection)]
       ↓
[안전 케이스(Safety Case, GSN) 문서 자동 생성 및 인증 획득]
```

### 안전성 분석 기법 선정 의사결정 체계

```text
소프트웨어 안전 위험 분석 대상 식별
       ↓
[최상위 재앙적 사고 경로를 파악해야 하는가?]
       ├─ 예 ──→ FTA (Fault Tree Analysis) 적용 → 단일 고장점(SPOF) 제거
       └─ 아니오 ─→ [단위 컴포넌트 및 모듈별 고장 영향 파악이 목적인가?]
                         ├─ 예 ──→ FMEA 적용 → RPN 산출 및 개선
                         └─ 아니오 ─→ HAZOP 적용 → 가이드워드 기반 편차 탐색
```

### 선택 근거: 전통적 문서 기반 안전 분석과 제언 모델 기반 안전 공학(MBSE) 비교

| 구분 | 전통적 스프레드시트 기반 분석 | 제언: 모델 기반 안전 공학 (MBSE/GSN) |
|---|---|---|
| 변경 추적성 | 엑셀 시트 수동 작성으로 설계 변경 시 누락 빈발 | 아키텍처 모델과 안전 요구사항의 실시간 1:1 양방향 추적 |
| 복합 오류 검증 | 인간의 직관에 의존하여 다중 결함 검출 한계 | 정형 검증 도구를 통한 수만 가지 상태 조합 수학적 탐색 |
| 인증 심사 효율 | 방대한 종이 문서 검토로 심사 지연 및 비용 증가 | GSN(Goal Structuring Notation) 기반 디지털 안전 케이스 자동 제출 |
