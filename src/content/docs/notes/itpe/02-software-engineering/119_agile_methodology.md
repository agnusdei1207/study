## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 개발 방법론 → **애자일(Agile) 방법론**

## 30초 인출

- 본질: 애자일은 짧은 반복 개발과 고객과의 협력으로 변화하는 요구에 빠르게 대응하며 동작하는 소프트웨어를 자주 전달하는 개발 접근
- 메커니즘: 짧은 반복(이터레이션)마다 우선순위가 높은 기능을 완성해 고객에게 보이고 피드백으로 다음 계획과 우선순위를 조정
- 통찰: 스탠드업·스프린트 같은 의식만 도입하고 협력과 피드백을 내재화하지 않으면 형식적 애자일이 되므로 반복 끝에 동작하는 결과로 고객 피드백을 받아 우선순위를 실제로 조정

<details>
<summary>핵심 용어</summary>

- **애자일 선언문(Agile Manifesto)** : 2001년에 발표된 애자일 소프트웨어 개발의 네 가지 가치와 열두 원칙
- **이터레이션(Iteration)** : 계획부터 시험까지 수행하는 짧은 개발 주기
- **사용자 스토리(User Story)** : 사용자 관점에서 기능 요구를 짧게 서술한 문장
- **제품 백로그(Product Backlog)** : 우선순위가 정해진 요구 항목 목록
- **XP(eXtreme Programming)** : 짝 프로그래밍·테스트 주도 개발 등의 실천을 강조한 애자일 방법론
- **완료의 정의(Definition of Done)** : 항목이 완료로 인정되기 위한 기준

</details>

## 2~4교시 25점 답안

## Ⅰ. 애자일 방법론의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **애자일 방법론** 은 짧은 반복 개발과 고객 협력으로 변화에 대응하며 동작하는 소프트웨어를 자주 전달하는 개발 접근 |
| 목적 | 요구 변화에 대한 대응력과 고객 가치의 조기 전달 |

## Ⅱ. 계획 주도 방식과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 짧은 반복 | 이터레이션마다 동작하는 결과 |
| 변화 수용 | 요구 변경을 정상으로 간주 |
| 협력 중시 | 고객·팀의 지속적 협력 |
| 자기 조직 팀 | 팀이 작업 방식을 결정 |

## Ⅲ. 애자일의 가치와 개발 흐름

### 애자일 선언문의 네 가지 가치

```text
개인과 상호작용  >  프로세스와 도구
동작하는 소프트웨어  >  포괄적인 문서
고객과의 협력  >  계약 협상
변화에 대한 대응  >  계획을 따르는 것
(왼쪽 항목에 더 높은 가치를 둠)
```

### 확대: 이터레이션 흐름

```text
백로그 우선순위 → 이터레이션 계획
    ↓
개발·시험 → 동작하는 결과
    ↓
고객 검토·피드백 → 우선순위 조정 → 다음 이터레이션
```

## Ⅳ. 대표 방법론과 계획 주도 방식의 비교

### 대표 방법론

| 방법론 | 특징 |
|---|---|
| 스크럼 | 스프린트·역할·이벤트 중심의 프레임워크 |
| XP | 짝 프로그래밍·TDD·지속적 통합 등 기술 실천 |
| 칸반 | 흐름 시각화와 WIP 제한 |

### 애자일과 계획 주도 방식

| 구분 | 계획 주도(폭포수) | 애자일 |
|---|---|---|
| 요구 | 초기에 확정 | 진행하며 변화 |
| 전달 | 마지막에 일괄 | 반복마다 |
| 변경 대응 | 통제 중심 | 수용 |
| 적합 조건 | 요구가 안정적 | 요구 변동이 큼 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 의식만 도입하는 형식적 애자일 | 반복 끝의 동작 결과로 고객 피드백을 받고 우선순위 조정 |
| 고정 범위·계약 사업과의 충돌 | 범위 우선순위 조정이 가능한 계약 방식 |
| 문서 부족으로 인한 지식 소실 | 필요한 문서의 최소 기준 정의 |
| 대규모 조직의 팀 간 조율 곤란 | 팀 간 동기화 방식 별도 정의 |

## Ⅵ. 제언

반복 끝마다 동작하는 결과를 고객에게 보여 주고, 그 피드백으로 백로그 우선순위를 실제로 조정하는 흐름을 유지

### 피드백 기반 순환

```text
동작하는 결과 시연
    ↓
고객 피드백 수집
    ↓
백로그 우선순위 재조정 → 다음 반복
```

### 확대: 피드백 반영 판단

```text
피드백
    ├─ 우선순위 변경 필요 → 백로그 재정렬
    └─ 현행 유지 → 계획대로 진행
```

### 선택 근거: 의식 중심 도입과의 비교

| 구분 | 의식 중심 도입 | 제언: 피드백 중심 |
|---|---|---|
| 초점 | 회의·도구 | 동작하는 결과와 피드백 |
| 우선순위 조정 | 형식적 | 실제 반영 |
| 가치 전달 | 지연 | 반복마다 |
