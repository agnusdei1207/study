<summary>핵심 용어</summary>

- **DAG(Directed Acyclic Graph)**: 방향 간선으로 관계를 나타내고 순환이 없는 그래프
- **위상 정렬(Topological Sort)**: 각 간선의 선행 정점이 후행 정점보다 앞에 오도록 정점을 나열하는 절차
- **진입 차수(In-degree)**: 특정 노드로 들어오는 방향성 간선의 개수로, 진입 차수가 0인 노드는 선행 작업이 완료되어 즉시 병렬 실행 가능한 상태를 의미
- **Kahn 알고리즘**: 진입 차수가 0인 노드를 큐에 넣고 꺼내며 인접 간선을 제거해 나가는 방식으로 위상 정렬과 사이클 존재 여부를 동시에 판별하는 알고리즘
- **ETL(Extract, Transform, Load)**: 데이터를 추출·변환해 적재하는 처리 과정
- **DOM(Document Object Model)**: 웹 문서를 객체 구조로 표현한 모델

## 2~4교시 25점 답안

### Ⅰ. 개요

### 순환 참조의 파멸과 인과관계 모델링의 필요성

방향성 비순환 그래프(DAG)는 방향 간선으로 작업 의존 관계를 나타내면서 순환을 금지하는 그래프 구조. 빌드·데이터 처리 계획 등 선행 조건이 있는 작업의 실행 순서 산출에 활용. 비순환 구조는 의존성 순환을 배제하지만 다른 원인에 따른 대기나 교착까지 막지는 않음.

| 구분 | 핵심 |
|---|---|
| 정의 | **DAG(Directed Acyclic Graph)**는 방향 간선으로 의존 관계를 나타내며 순환이 없는 그래프 |
| 목적 | 의존 작업의 유효한 실행 순서를 정하고 독립 작업을 찾는 데 활용 |

### 트리(Tree) vs DAG vs 일반 유향 그래프 비교

| 구분 | 일반 트리 (Tree) | 방향성 비순환 그래프 (DAG) | 일반 유향 그래프 (Directed Graph) |
|---|---|---|---|
| **간선 방향성** | 방향성 존재 (부모 $\rightarrow$ 자식) | **방향성 존재 (단방향 의존성)** | 방향성 존재 |
| **순환(Cycle) 유무** | 순환 없음 (Acyclic) | **순환 없음 (Acyclic)** | **순환 허용 (Cycle 존재 가능)** |
| **부모 노드 개수** | **오직 1개의 부모만 허용** | **복수의 부모 노드 허용 (합류 가능)** | 복수의 부모 노드 허용 |
| **위상 정렬 가능성** | 가능 | **항상 가능 ($O(V+E)$)** | 순환이 있으면 불가능 |
| **주요 활용 분야** | DOM 트리, 이진 탐색 트리, 파일 시스템 | **ETL 파이프라인, 빌드 시스템, Git 커밋** | 소셜 네트워크 친구 관계, 도로망 |

### Ⅱ. 위상 정렬과 순환 검사

### DAG 구조 및 Kahn 알고리즘 기반 위상 정렬

```mermaid
flowchart LR
    A["A · 진입차수 0"] --> B["B · 진입차수 1"]
    A --> C["C · 진입차수 2"]
    B --> C
    C --> D["D · 최종 합류"]
```

Kahn 알고리즘은 진입 차수 0인 정점을 선택해 제거하고, 새로 진입 차수 0이 된 정점을 반복 처리하는 방식. 모든 정점이 처리되면 위상 순서 완성, 미처리 정점이 남으면 순환 존재. 인접 리스트 구현의 시간 복잡도 $O(V+E)$.

### 의존성 검증에서 실행 순서 산출까지

```mermaid
flowchart LR
    G["작업·선행 관계 정의"] --> C{"순환 검사"}
    C -->|"없음"| T["위상 순서 산출"]
    T --> P["선행 조건이 충족된 작업 실행"]
    C -->|"있음"| E["의존 관계 수정"]
```

### Ⅲ. 적용과 유의점

| 사용 영역 | DAG가 나타내는 관계 |
|---|---|
| 빌드 계획 | 모듈 간 선행 의존성과 실행 순서 |
| 데이터 처리 파이프라인 | 작업 간 입력·출력 의존성 |
| 버전 관리 이력 | 커밋 간 부모 관계 |

### 구현 시 유의점

### 위험 대응 매트릭스

| 위험 | 대책 |
|---|---|
| 의존 관계 변경으로 순환이 유입 | 변경 시 순환 검사를 다시 수행 |
| 위상 순서만으로 작업 간 병렬성을 과대 추정 | 공유 자원·실행 용량 등 추가 제약을 별도로 고려 |
| 작업 의존성 누락으로 잘못된 실행 순서 | 작업 입력·출력과 선행 조건을 함께 검토 |

### Ⅳ. 설계·운영 제언

위상 순서는 작업 의존성만 반영. 실행 자원, 우선순위, 실패 재시도, 작업 비용은 별도 스케줄링 정책으로 관리하고 그래프 변경 뒤 의존성 재검증.

| DAG가 정하는 것 | 별도 관리할 것 |
|---|---|
| 작업 간 선행 제약과 유효한 순서 | 실행 자원과 동시 실행량 |
| 의존 간선의 순환 여부 | 작업 우선순위와 실패 복구 정책 |

### Ⅴ. 기술사적 제언

| 문제 | 해결 방안 |
|---|---|
| 의존 관계 변경 후 유효한 실행 순서를 확인하지 않은 채 반영 | 파이프라인 변경 검토와 배포 과정에 순환 검사 및 위상 정렬 검증 포함 |
