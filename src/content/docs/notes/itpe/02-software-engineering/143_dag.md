## 연관 키워드
- DAG, 방향성 비순환 그래프, 위상정렬, 진입차수, Kahn 알고리즘, 의존성 관리

## Ⅰ. DAG의 개요
- 핵심 요약 : DAG는 방향 간선이 있고 방향 순환이 없는 그래프로 선후관계·의존성을 표현.
- 개념 : 정점·간선으로 구성되며 위상정렬 순서는 모든 간선 u→v에서 u가 v보다 앞서도록 함.
- 필요성 : 작업·패키지·데이터 흐름의 선행조건과 병렬 실행 가능성을 계산해야 함.
- 목적 : 의존성 검증, 실행순서 생성, 병렬화·영향분석 지원.

## Ⅱ. DAG의 특징 및 장점
- 핵심 요약 : 순환이 없어 위상순서가 존재하며 독립 정점은 병렬 처리 가능.
1. 의존성 표현 : u→v는 u 완료 후 v 가능 → 빌드·워크플로 순서 보장.
2. 위상정렬 : 유효 순서 산출 → 작업 스케줄·컴파일 순서 결정.
3. 역방향 분석 : 후속 영향·경로 계산 → 변경 영향과 임계 경로 분석.

## Ⅲ. 위상정렬과 Kahn 알고리즘
- 핵심 요약 : 진입차수 0인 정점을 큐에서 반복 선택하고 간선을 제거해 위상순서를 만듦.
```text
진입차수 계산 → in-degree 0 정점 큐 삽입
→ 정점 출력 → 후속 간선 제거·진입차수 감소
→ 새 0차수 삽입 → 반복
```
```text
A → C ← B       위상순서 예: A, B, C, D
     ↓           (A와 B는 서로 선후관계 없음)
     D
```
- 복잡도 : 인접리스트 기준 O(V+E); 출력 정점 수가 V 미만이면 순환 존재.

## Ⅳ. DAG와 일반 방향 그래프 비교
- 핵심 요약 : DAG는 순환이 없는 의존성·실행순서에 적합하고 일반 방향 그래프는 순환 관계도 표현 가능.
| 기준 | DAG | 일반 방향 그래프 |
|---|---|---|
| 순환 | 허용하지 않음 | 허용 가능 |
| 위상정렬 | 존재(유일성은 별도 조건) | 순환 있으면 불가능 |
| 활용 | 빌드·워크플로·데이터 파이프라인 | 네트워크·상태전이·일반 관계 |

## Ⅴ. DAG 활용 한계와 대응
- 핵심 요약 : 순환 의존성·대규모 그래프의 부분실패를 사이클 탐지·계층화·증분 재계산으로 관리.
| 한계 | 영향 | 대응 |
|---|---|---|
| 순환 의존성 | 실행순서 산출 불가 | SCC·사이클 경로를 탐지해 의존성 분리 |
| 그래프 대규모 | 메모리·재계산 비용 증가 | 인접리스트·증분 갱신·파티셔닝 |
| 부분작업 실패 | 후속 단계 오염·재실행 비용 | 실패전파 정책·체크포인트·멱등 재시도 |

## Ⅵ. DAG 기반 시스템 제언
- 핵심 요약 : 플랫폼팀은 노드·간선 계약과 사이클·실패·재실행 정책을 워크플로 실행기에 포함.
1. 개발자는 의존성 생성 위치와 데이터 버전을 명시.
2. 스케줄러는 실행상태·실패원인·재실행 범위를 기록.
3. 운영자는 순환·고아노드·병목노드를 분석하고 변경 시 영향 그래프 갱신.

## Ⅶ. 결론
- 핵심 요약 : DAG는 비순환 의존관계에서 위상순서와 병렬 실행기회를 제공하는 그래프 구조.
- 시사점 : 사이클 탐지와 실패 전파 정책이 대규모 실행의 정확성·복구성을 좌우.
