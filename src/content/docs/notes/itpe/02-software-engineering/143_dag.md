## 30초 인출

- 본질: **DAG(Directed Acyclic Graph, 방향성 비순환 그래프)** 는 방향 간선으로 의존 관계를 나타내며 순환이 없는 그래프
- 메커니즘: 정점과 의존 간선 정의 → 순환 검사 및 위상 정렬 → 선행 조건이 충족된 작업 실행
- 통찰: 한계: 의존 작업에 순환이 생기면 시작 가능한 정점이 사라질 수 있음 → 방안: 위상 정렬에서 남은 정점을 검사해 실행 전에 순환을 차단

<details>
<summary>핵심 용어</summary>

- **DAG(Directed Acyclic Graph)** : 방향 간선으로 관계를 나타내고 순환이 없는 그래프
- **위상 정렬(Topological Sort)** : 각 간선의 선행 정점이 후행 정점보다 앞에 오도록 정점을 나열하는 절차
- **진입 차수(In-degree)** : 특정 정점으로 들어오는 방향 간선의 수. 선행 작업 완료를 반영한 그래프에서 진입 차수 0인 정점은 실행 후보이며, 실제 동시 실행은 자원·정책에 따름
- **Kahn 알고리즘** : 진입 차수가 0인 노드를 큐에 넣고 꺼내며 인접 간선을 제거해 나가는 방식으로 위상 정렬과 사이클 존재 여부를 동시에 판별하는 알고리즘
- **ETL(Extract, Transform, Load)** : 데이터를 추출·변환해 적재하는 처리 과정
- **DOM(Document Object Model)** : 웹 문서를 객체 구조로 표현한 모델

## 2~4교시 25점 답안

## Ⅰ. 방향성 비순환 그래프의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **DAG(Directed Acyclic Graph)** 는 방향 간선으로 의존 관계를 나타내며 순환이 없는 그래프 |
| 목적 | 의존 작업의 유효한 실행 순서를 정하고 독립 작업을 찾는 데 활용 |

## Ⅱ. 다중 의존과 비순환성의 특징

| 특징 | 실행상 의미 |
|---|---|
| 다중 선행 의존 | 여러 선행 작업이 완료돼야 후속 작업을 시작할 수 있음 |
| 순환 부재 | 모든 정점을 처리할 수 있는 위상 순서가 존재 |
| 실행 정책과 분리 | 위상 순서는 자원 용량·우선순위·실패 복구를 결정하지 않음 |

## Ⅲ. 진입 차수 기반 위상 정렬과 순환 검사

### Kahn 알고리즘으로 의존성 검증과 실행 순서 산출

```text
작업·의존 간선 정의 → 각 정점 진입 차수 계산
    ↓
진입 차수 0 정점을 큐에 넣고 꺼냄
    ↓ 완료 정점의 출력 간선을 제거하고 후속 정점 차수 감소
    ├─ 모든 정점 처리 → 위상 순서 확정·실행 후보 결정
    └─ 미처리 정점 존재 → 순환 의존성 수정
```

예를 들어 `A→B`, `A→C`, `B→C`, `C→D`라면 `A, B, C, D`가 유효한 순서다. 인접 리스트 구현의 시간 복잡도는 $O(V+E)$이다. 실제 동시 실행량은 자원·정책에 따른다.

## Ⅳ. 트리·DAG·일반 유향 그래프 비교

### 트리(Tree) vs DAG vs 일반 유향 그래프 비교

| 구분 | 일반 트리 (Tree) | 방향성 비순환 그래프 (DAG) | 일반 유향 그래프 (Directed Graph) |
|---|---|---|---|
| 순환 | 없음 | 없음 | 있을 수 있음 |
| 선행 관계 | 루트 외 정점의 부모 1개 | 여러 선행 정점이 한 정점으로 합류 가능 | 순환을 포함한 관계 표현 가능 |
| 위상 정렬 | 간선 방향을 부여한 경우 가능 | 가능 | 순환이 있으면 불가능 |

### DAG의 적용 영역과 선행 관계

| 사용 영역 | DAG가 나타내는 관계 |
|---|---|
| 빌드 계획 | 모듈 간 선행 의존성과 실행 순서 |
| 데이터 처리 파이프라인 | 작업 간 입력·출력 의존성 |
| 버전 관리 이력 | 커밋 간 부모 관계 |


위상 순서는 작업 의존성만 반영한다. 실행 자원, 우선순위, 실패 재시도와 작업 비용은 별도 스케줄링 정책으로 관리하며, 그래프 변경 뒤 순환을 다시 검사한다.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 의존 작업에 순환이 생기면 시작 가능한 정점이 사라질 수 있음 | 위상 정렬에서 남은 정점을 검사해 실행 전에 순환을 차단 |
| 의존 관계 변경으로 순환이 유입 | 변경 시 순환 검사를 다시 수행 |
| 위상 순서만으로 작업 간 병렬성을 과대 추정 | 공유 자원·실행 용량 등 추가 제약을 별도로 고려 |
| 작업 의존성 누락으로 잘못된 실행 순서 | 작업 입력·출력과 선행 조건을 함께 검토 |

## Ⅵ. 제언

**제언:** 의존 관계가 바뀔 때마다 위상 순서를 다시 계산하고, 배포 전 실행 용량·실패 복구 정책까지 함께 시험한다.
