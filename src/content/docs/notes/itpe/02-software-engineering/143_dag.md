## 30초 인출

- 본질: 간선에 방향성이 존재하며 임의의 정점에서 출발하여 다시 자기 자신으로 되돌아오는 순환(Cycle) 경로가 존재하지 않는 유향 그래프
- 메커니즘: 노드 간 의존 관계 모델링 → 진입 차수(In-degree) 계산 → Kahn 알고리즘 또는 DFS 기반 위상 정렬(Topological Sort) 수행 → 순환 여부 검증 및 최적 병렬 실행 스케줄링 도출
- 통찰: 파이프라인 확장 시 의도치 않은 순환 참조로 인한 교착상태(Deadlock)를 방지하기 위해 정적 분석 단계에서의 순환 감지 알고리즘과 실패 시 멱등적 재시도 정책 수립 필수

<details>
<summary>핵심 용어</summary>

- **DAG (Directed Acyclic Graph)** : 정점 간의 방향성(단방향)과 비순환성(Cycle 없음)을 동시에 만족하는 그래프 구조
- **위상 정렬 (Topological Sort)** : 모든 유향 간선 $(u, v)$에 대해 정점 $u$가 $v$보다 반드시 먼저 오도록 나열하는 선형 정렬 알고리즘
- **진입 차수 (In-degree)** : 특정 노드로 들어오는 방향 간선의 총 개수로, 선행 작업의 수를 의미
- **Kahn 알고리즘** : 진입 차수가 0인 노드를 큐에 삽입하고 간선을 점진적으로 제거하며 위상 정렬과 사이클 존재 여부를 동시에 판별하는 알고리즘
- **워크플로우 오케스트레이션 (Workflow Orchestration)** : Apache Airflow 등에서 복잡한 데이터 파이프라인의 작업 선후행 관계를 DAG로 모델링하여 실행 제어하는 기법
</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 정점(Vertex)과 방향을 가진 간선(Directed Edge)으로 구성되며, 어떤 정점에서 출발해도 다시 출발점으로 회귀하는 닫힌 루프(Cycle)가 존재하지 않는 그래프 구조 |
| 목적 | 작업(Task) 간의 명확한 선후행 의존 관계 표현, 위상 정렬을 통한 유효 실행 순서 결정 및 병렬 작업의 동시 처리 극대화 |

## Ⅱ. 핵심 특징

| 특징 | 세부 내용 |
|---|---|
| 단방향 의존성 | 모든 간선이 인과 관계(선행 → 후행)를 나타내며 역방향 흐름이 원천 배제 |
| 비순환성 (No Cycle) | 루프가 없으므로 무한 반복이나 데드락에 빠지지 않고 반드시 종료 지점(Sink)에 도달 |
| 부분 순서 집합 (Poset) | 모든 노드 간의 엄격한 전순서가 아니더라도 의존성이 없는 노드 간의 안전한 병렬 실행(Concurreny) 지원 |
| 위상 정렬 가능성 | DAG 구조에서는 최소 하나 이상의 진입 차수 0(Source)과 진출 차수 0(Sink) 노드가 존재하여 위상 정렬 100% 보장 |

컴파일러 빌드 의존성, 데이터 엔지니어링 파이프라인, 분산 원장(IOTA) 등 복잡한 인과 관계 제어의 표준 모델로 기능.

## Ⅲ. 체계·프로세스

```text
[1. 작업 의존성 모델링]
  - 정점 V(작업 단위) 및 방향 간선 E(선행 제약 조건) 정의
       │
       ▼
[2. 진입 차수(In-degree) 계산]
  - 각 노드로 들어오는 간선 수 카운팅
  - In-degree = 0 인 노드들을 선행 조건 충족 작업으로 식별
       │
       ▼
[3. Kahn 알고리즘 기반 위상 정렬]
  ┌────────────────────────────────────────────────────────┐
  │ 1) In-degree가 0인 노드들을 대기 큐(Queue)에 Push      │
  │ 2) 큐에서 노드 u를 Pop하여 실행 순서 리스트에 추가    │
  │ 3) u와 연결된 모든 후행 노드 v의 In-degree를 1씩 감소 │
  │ 4) v의 In-degree가 0이 되면 큐에 Push                  │
  │ 5) 큐가 빌 때까지 반복 수행                            │
  └────────────────────────────────────────────────────────┘
       │
       ▼
[4. 순환(Cycle) 검증 및 실행]
  - 방문 노드 수 == 전체 노드 수(V) ?
  ├─ [일치] ──► 유효한 DAG 확인: 위상 정렬 순서대로 병렬 워커에 작업 디스패치
  └─ [불일치] ─► 사이클(Cycle) 탐지: 빌드/파이프라인 중단 및 에러 리포팅
```

진입 차수 계산부터 큐 기반 간선 소거, 사이클 무결성 검증을 거쳐 최종 병렬 스케줄러로 전달되는 위상 정렬 프로세스.

## Ⅳ. 종류·비교

| 비교 항목 | 일반 트리 (Tree) | 방향성 비순환 그래프 (DAG) | 일반 유향 그래프 (Directed Graph) |
|---|---|---|---|
| **순환 (Cycle) 허용** | 불허 (순환 없음) | 불허 (순환 없음) | 허용 (순환 존재 가능) |
| **다중 부모 (합류)** | 불가 (루트 외 부모 1개) | 가능 (여러 선행 노드가 1개로 합류 가능) | 가능 (임의의 연결 허용) |
| **위상 정렬 가능 여부** | 항상 가능 | 항상 가능 | 사이클이 없을 때만 가능 |
| **시간 복잡도** | $O(V)$ 순회 | $O(V + E)$ (Kahn / DFS) | 사이클 탐지 시 $O(V + E)$ |
| **대표 응용 사례** | 파일 시스템, DOM 트리, 파스 트리 | Airflow 파이프라인, Git 커밋 그래프, 빌드 도구 | 소셜 네트워크 친구 관계, 웹 크롤링 링크망 |

### DAG 기반 주요 응용 프레임워크 비교

| 도구 / 도메인 | 정점 (Vertex) | 간선 (Edge) | 주요 특징 |
|---|---|---|---|
| **Apache Airflow** | 오퍼레이터 / 파이썬 태스크 | 작업 선후행 의존성 (`>>`) | 데이터 파이프라인 스케줄링 및 모니터링 표준 |
| **Make / Gradle / Bazel** | 빌드 타깃 / 소스코드 모듈 | 컴파일 의존성 | 증분 빌드(Incremental Build) 및 병렬 컴파일 극대화 |
| **Git 버전 관리** | 커밋 객체 (Snapshot) | 부모 커밋 해시 참조 | 브랜치 병합(Merge) 및 이력 추적의 기초 구조 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 작업 간 상호 참조나 간접 참조로 인한 런타임 사이클 발생 시 파이프라인 교착(Deadlock) 유발 | 파이프라인 정의 배포 전 CI 단계에서 Tarjan 또는 Kahn 알고리즘을 활용한 정적 사이클 유효성 검사 강제 |
| 선행 태스크 실패 시 후속 의존 태스크들이 연쇄적으로 중단되는 종속적 결함 전파 | 태스크별 재시도(Retry) 백오프 설정 및 조건부 분기(Short-Circuit / Trigger Rule) 메커니즘 적용 |
| 대규모 파이프라인에서 수천 개의 태스크 병렬 전개 시 CPU/메모리 및 DB 커넥션 풀 고갈 | Celery/Kubernetes Executor 기반 작업 풀(Worker Pool) 분리 및 동시 실행 제한(Concurrency Limit) 통제 |

## Ⅵ. 제언

데이터 엔지니어링 및 MLOps 환경에서는 DAG 기반 워크플로우를 선언적 코드로 관리(Workflow as Code)하고, 개별 작업의 멱등성(Idempotency)을 보장하는 재실행 거버넌스 확립 권장.

```text
[DAG 기반 지속적 데이터 파이프라인]
  Git (Python DAG 코드) → CI 정적 유효성(Lint/Cycle) 검사 → Airflow 배포 → Celery 병렬 실행 → 상태 모니터링
```

| 검증 단계 | 사전 검증 단계 (정적 분석) | 런타임 제어 단계 (동적 제어) |
|---|---|---|
| 핵심 통제 | 간선 사이클(Cycle) 검출, 미연결 고립 노드 검사 | 워커 풀 쿼터 관리, 태스크 타임아웃, 멱등 재처리 |
| 모니터링 지표 | 파이프라인 파싱 시간, DAG 구조 복잡도 | SLA 준수율, 태스크 지연시간, 실패 재시도 건수 |
