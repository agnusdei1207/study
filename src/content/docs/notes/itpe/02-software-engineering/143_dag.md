## 연관 키워드

- 방향성 비순환 그래프(DAG, Directed Acyclic Graph), 위상 정렬(Topological Sorting), 진입 차수(In-degree)
- 카안 알고리즘(Kahn's Algorithm), 사이클 검출, 워크플로우 오케스트레이션(Airflow), 지연 연산(Lazy Evaluation), 순환 의존성(Cyclic Dependency)

## Ⅰ. 방향성 비순환 그래프(DAG)의 개요

- 핵심 요약 : 방향성을 가지되 순환이 없는 그래프로, 선후 의존 관계와 처리 순서를 수학적으로 모델링하는 기반 구조.
- 개념 : 간선(Edge)에 방향이 있고, 어떤 정점(Vertex)에서 출발하든 간선을 따라가 자기 자신으로 돌아오는 사이클(Cycle)이 없는 **방향성 비순환 그래프** (DAG, Directed Acyclic Graph).
- 배경 및 필요성 : 작업 간 선후 의존, 데이터 파이프라인의 처리 순서, 빌드 의존성, 버전 이력처럼 모순 없는 순서가 필요한 대상을 표현하기 위한 구조.
- 핵심 알고리즘 : **위상 정렬** (Topological Sorting, 선후 관계를 지키는 선형 순서 도출), 사이클 검출, 최장 경로(임계 경로) 계산.
- 주요 목적 : 작업 순서의 모순을 사전에 검출하고, 독립 작업의 병렬 실행 기회를 찾는 것.

## Ⅱ. DAG의 특징 및 장점

- 핵심 요약 : 방향성, 비순환성, 위상 정렬 가능성이 맞물려 의존성을 검증하고 병렬 실행을 이끌어내는 모델링 특성.

1. 방향성 : 모든 간선에 방향이 있어 선행과 후행 관계를 명시 → 실행 순서를 혼동 없이 표현.
2. 비순환성 : 자기 자신으로 돌아오는 경로가 없음 → 실행이 끝없이 반복되는 상황을 구조적으로 배제.
3. 위상 정렬 : 모든 선후 관계를 만족하는 선형 순서를 도출 → 실행 가능한 작업 순서 확보.
4. **진입 차수** (In-degree, 정점으로 들어오는 간선 수) : 의존 관계 수를 정량적으로 표현 → 실행 가능 시점 판정.
5. 병렬 스케줄링 : 같은 단계의 독립 정점을 동시에 실행 → 전체 처리 시간 단축.
6. 응용 범위 : 데이터 파이프라인, 빌드 시스템, 버전 관리, 분산 원장 등으로 확장 가능.

## Ⅲ. DAG의 구조 (흐름)

- 핵심 요약 : 작업 의존성이 갈라졌다가 합류하는 비순환 분기 구조와, 진입 차수를 이용한 위상 정렬 절차의 이중 구조.

```text
[ 작업 A: 데이터 수집 ]
        ↓
[ 작업 B: 결측치 정제 ]   (병렬)
[ 작업 C: 이상치 필터링 ]  (병렬)
        ↓
[ 작업 D: 집계 리포트 ]
```

- **카안 알고리즘** (Kahn's Algorithm) : 진입 차수 0인 정점부터 큐에 넣어 차례로 꺼내는 BFS(Breadth-First Search) 기반 위상 정렬 방식.

```text
[ 1. 진입 차수 0 정점을 큐에 삽입 ]
        ↓
[ 2. 큐에서 정점을 꺼내 결과에 추가 ]
        ↓
[ 3. 인접 정점의 진입 차수 1 감소 ]
        ↓
[ 4. 진입 차수 0이 된 정점을 큐에 삽입 ]
        ↓
[ 5. 큐가 빌 때까지 반복 ]
 (모든 정점을 방문 못 하면 사이클 존재)
```

## Ⅳ. 주요 시스템에서의 DAG 응용 비교

- 핵심 요약 : 정점과 간선의 의미를 어떻게 정의하느냐에 따라 응용 시스템별 역할이 달라짐.

| 응용 분야 | 정점 (Vertex) | 간선 (Edge) | 시스템 상의 역할 |
| --- | --- | --- | --- |
| 데이터 파이프라인 (Airflow) | 실행 태스크 | 태스크 간 실행 의존성 | 워크플로우 오케스트레이션, 병렬 스케줄링 |
| 분산 연산 엔진 (Spark) | 데이터셋 변환 연산 | 셔플 등 연산 간 의존성 | 실행 계획 수립과 최적화 |
| 소스코드 관리 (Git) | 커밋 스냅샷 | 부모 커밋을 가리키는 포인터 | 분기와 병합 이력 관리 |
| 분산 원장 (IOTA Tangle) | 개별 거래 | 이전 거래에 대한 승인 링크 | 블록 없이 거래를 연결하는 원장 구조 |

## Ⅴ. DAG의 한계와 대응 방안

- 핵심 요약 : 숨은 순환 의존성, 스케줄러 파싱 부담, 부분 재실행의 어려움을 정적 검증, 경량 정의, 멱등 설계로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **순환 의존성** (Cyclic Dependency) 발생 | 런타임 조건 분기로 의도치 않은 루프가 생겨 스케줄러 교착 | 파싱 단계에서 위상 정렬과 Tarjan 강결합 요소 알고리즘으로 사이클을 사전 검증 | 사이클 검출 건수 |
| 스케줄러 파싱 부담 | DAG 파일 수 증가 → 반복 파싱으로 CPU 병목과 실행 지연 | DAG 파일에서 무거운 I/O 금지, YAML이나 JSON 같은 선언형 정의와 스케줄러 수평 분산 | 스케줄러 파싱 시간, 태스크 지연 |
| 부분 실패의 재실행 난제 | 중간 태스크 실패 시 전체 재실행이나 하위 데이터 불일치 | **멱등성**(Idempotency) 보장 설계, 실패 지점 이후만 재실행, 중간 산출물 캐싱과 계보(Lineage) 추적 | 재실행 소요 시간, 정합성 오류 건수 |

## Ⅵ. 대규모 파이프라인 엔지니어링을 위한 기술사적 제언

- 핵심 요약 : 등록 단계에서 사이클을 막는 검증 체계와, 지연 연산을 활용한 실행 계획 최적화를 함께 갖추는 것.

1. 파이프라인 등록 시 순환 검사 의무화 : 데이터 플랫폼 조직은 CI 단계에서 위상 정렬 검사를 자동 실행하고, 사이클이 발견되면 배포를 차단하도록 규칙을 두어야 한다.
2. 지연 연산 기반 실행 계획 활용 : 분산 연산 개발팀은 Spark처럼 실행을 미루는 **지연 연산** (Lazy Evaluation)을 이해하고, 연산을 내부 DAG로 모아 최적화기가 불필요한 셔플을 줄이도록 파이프라인을 설계해야 한다.

## Ⅶ. 결론

- 핵심 요약 : DAG는 의존성 기반 시스템의 수학적 뼈대이며, 사이클 검증과 멱등성 설계가 안정 운영의 전제.
- 시사점 : 위상 정렬 검사를 배포 관문에 두고 재실행 가능한 태스크를 설계하는 것이 대규모 파이프라인 신뢰성의 핵심.
