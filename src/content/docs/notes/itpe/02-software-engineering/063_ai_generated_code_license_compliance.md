## 한 줄 본질
- AI가 학습 데이터의 카피레프트 코드를 그대로 뱉거나 오픈웨이트 모델의 독소 조항을 인지하지 못해 발생하는 법적 분쟁 병목 → CI/CD 내 SCA 스캔 및 출처 역추적 기반 컴플라이언스 자동화 체계 수립 → 안전한 AI 가속 개발 보장 / 오탐(False Positive) 검증 비용 발생

## 핵심 용어
- 오픈웨이트(Open-weight): 모델의 가중치는 공개하나, 학습 데이터나 상업적 사용(예: MAU 한도, 경쟁 모델 학습 금지)에 제약을 두는 준개방형 라이선스
- 코드 스니펫 매칭(Snippet Matching): AI가 생성한 코드가 인터넷 상의 GPL 등 카피레프트 오픈소스와 100% 일치하는지 토큰 단위로 비교 탐색하는 기술

## 핵심 통찰
- 오픈웨이트 모델은 오픈소스 이니셔티브(OSI)가 정의하는 진정한 오픈소스(OSD)가 아니며, 라이선스에 명시된 '허용 사용 정책(AUP)' 위반 시 법적 배상 책임이 따름
- 생성형 AI 코딩 도구는 학습 데이터의 저작권 표시와 라이선스 헤더를 지운 채 순수 코드만 출력하므로, 고의 없는 무단 도용(License Infringement) 위험이 상존함
- 무조건적인 금지보다는 CI/CD에 SCA(Software Composition Analysis) 도구를 연동하여 스니펫 일치율을 정량화하고 차단 기준을 세우는 것이 실무적 해법임

## 이웃 토픽과 구분
- 오픈소스 라이선스 vs 오픈웨이트 라이선스: 오픈소스 = 소스코드 전체 공개 및 차별 없는 자유 이용(OSI 공인) / 오픈웨이트 = 가중치만 공개하고 용도·사용자 규모별 제약 조건 부과
