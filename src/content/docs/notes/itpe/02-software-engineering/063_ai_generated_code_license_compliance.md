## 1. AI 생성코드 및 오픈웨이트 모델의 개요와 리스크

### (1) AI 생성코드 및 오픈웨이트(Open-weight)의 개념
- **AI 생성코드**: GitHub Copilot, ChatGPT 등 LLM 기반 코딩 어시스턴트가 공개된 대규모 소스코드를 학습하여 자동 생성한 프로그램 코드.
- **오픈웨이트 모델**: 모델 가중치(Weight) 파라미터는 공개하지만, 라이선스에 상업적 용도 제한이나 허용 사용 정책(AUP, Acceptable Use Policy)을 부과하는 준개방형 모델 (예: Meta Llama 계열).

### (2) 대두되는 3대 법적·공학적 리스크
1. **저작권 침해 및 표절(Plagiarism)**: 학습 데이터에 포함된 저작권 표시(Notice)와 라이선스 전문이 누락된 채 원본 코드가 그대로 재생성되는 문제.
2. **카피레프트(GPL/AGPL) 오염 및 강제 공개 위험**: 독점 상용 소프트웨어에 강력한 카피레프트 코드가 침투하여 전체 독점 코드의 공개 의무 발생 위험.
3. **독소 조항 및 상업적 사용 제한 위반**: 오픈웨이트 모델의 사용자 수(예: MAU 7억 명 이상 라이선스 별도 취득) 및 특정 산업군 활용 금지 조항 위반.

## 2. 라이선스 유형 비교 및 핵심 점검 항목

### (1) 전통적 오픈소스 vs 오픈웨이트 vs AI 생성코드 비교
| 비교 항목 | 전통적 오픈소스 (OSI OSD) | 오픈웨이트 모델 (Open-weight) | AI 생성 코드 (LLM Generated) |
|---|---|---|---|
| **라이선스 정의** | OSI 공인 오픈소스 (MIT, Apache, GPL) | 개별 기업 자체 라이선스 (Llama Community 등) | 라이선스 부재 (프롬프트 결과물) |
| **공개 대상** | 소스코드 전체, 빌드 스크립트 | 사전 학습 가중치 파라미터 (학습데이터 제외) | 생성된 코드 스니펫 텍스트 |
| **이용 제약** | 특정 분야/사용자 차별 금지 (OSD 5, 6조) | 용도 제한(AUP), 특정 경쟁 모델 학습 금지 | 학습 데이터의 원저작권 종속 위험 |
| **카피레프트 영향** | GPL 계열 사용 시 파생 저작물 공개 의무 | 모델 파생물(파인튜닝)에 대한 라이선스 상속 | AI가 카피레프트 코드 복제 시 전파 위험 |

### (2) 컴플라이언스 주요 점검 항목 (140회 기출)
- **코드 레벨**: 공개 저장소 매칭 여부, 퍼블릭 코드 차단 필터 활성화, 코드 기여자의 AI 도구 사용 명시.
- **모델 레벨**: 모델 라이선스 허용 범위, 파인튜닝 가중치 배포 허용 여부, 상업적 매출/MAU 임계치 확인.
- **출처 추적성**: 모델 카드(Model Card), 학습 데이터 출처, 프롬프트 및 출력 로그 아카이빙.

## 3. 통합 거버넌스 프로세스 및 기술적 검증 아키텍처

### (1) CI/CD 파이프라인 내 컴플라이언스 검증 구조도
```text
+-------------------------------------------------------------------------+
|           AI 생성 코드 & 오픈웨이트 통합 컴플라이언스 파이프라인        |
+-------------------------------------------------------------------------+
| [ AI 도구 활용 개발 ] ──▶ IDE 레벨: 퍼블릭 코드 매칭 차단 필터 활성화  |
|           │                                                             |
|           v (Git Push / PR 생성)                                        |
| [ CI 파이프라인 진입 ]                                                  |
|   ├─ 1. 코드 스니펫 매칭  ──▶ Black Duck / FOSSID (GPL 오염 탐지)       |
|   ├─ 2. 모델 라이선스 점검 ──▶ Llama/Mistral 허용 정책(AUP) 위반 검증   |
|   ├─ 3. 정적 보안 분석(SAST) ──▶ 취약한 코드 패턴 및 하드코딩 키 검출    |
|   └─ 4. SBOM 자동 생성     ──▶ SPDX / CycloneDX 표준 메타데이터 패키징 |
|           │                                                             |
|     +─────┴─────────────────────────+                                   |
|     v (위반 발견 시)                 v (검증 통과 시)                   |
|  [ 머지 차단 (Block) ]           [ 배포 승인 (Release) ]                |
|  - 대체 라이선스 모델 교체        - SBOM 등록 및 법무 승인 완료         |
|  - 클린룸(Clean Room) 코드 재작성                                       |
+-------------------------------------------------------------------------+
```

### (2) 기술적 검증 도구 및 거버넌스 프레임워크
| 구분 | 핵심 도구 및 기술 | 기능 및 검증 방식 |
|---|---|---|
| **SCA 도구** | Black Duck, Mend, FOSSID, Snyk | 코드 토큰 기반 지문(Fingerprint) 매칭으로 GPL 코드 도용 여부 판별 |
| **SBOM 관리기** | Dependency-Track, Syft, Grype | 사용된 컴포넌트, 오픈웨이트 모델 버전, 라이선스 계보를 표준 포맷으로 자동 생성 |
| **IDE 가드레일** | Copilot Duplication Filter | 퍼블릭 GitHub 코드와 150글자 이상 일치 시 코드 생성을 원천 차단 |
| **조직 거버넌스** | 오픈소스 라이선스 심의회(OSRB) | 오픈웨이트 모델 상용 도입 전 법률 검토 및 라이선스 변경 감시 |

## 4. 실무 실패 시나리오 및 해결 방안

| 실패 시나리오 | 근본 원인 | 공학적 해결 방안 | 정량적 기대효과 |
|---|---|---|---|
| **상용 금융 솔루션에 GPL 코드 유입**<br>(지식재산권 분쟁 및 소스코드 공개 압박) | 개발자가 AI 코파일럿이 제안한 정렬 알고리즘을 그대로 승인하여 독점 코드 오염 | PR 머지 전 SCA 스니펫 정밀 스캔 게이트 의무화 및 카피레프트 탐지 시 빌드 중단 | 카피레프트 오염 코드 프로덕션 유입 0건 차단 |
| **오픈웨이트 모델 상업 배포 후 라이선스 위반**<br>(MAU 초과로 인한 모델 사용 중지 통보) | 모델 라이선스에 명시된 월간 활성 사용자(MAU) 한도 조항을 인지하지 못한 채 배포 | 도입 단계 모델 라이선스 사전 스크리닝 및 순수 Apache 2.0 라이선스 모델로 선별 전환 | 법적 분쟁 리스크 100% 해소, 서비스 중단 방지 |
| **AI 생성 코드의 보안 취약점 대량 노출**<br>(SQL 인젝션 및 레거시 API 취약점 유출) | LLM이 과거 오픈소스의 취약한 코드 패턴을 필터링 없이 그대로 학습·생성 | CI 단계 SAST(SonarQube) 및 시큐어 코딩 룰셋을 AI 생성 코드에 엄격 적용 | 보안 취약점 배포 전 98% 사전 차단 |

## 5. 기술사 답안 차별화 포인트 (기술사의 시각)

```text
[단순 AI 도입 (Shadow AI)]              [신뢰 가능한 AI 거버넌스 (Responsible AI)]
- 개발자 임의 사용 및 라이선스 무시 ──▶   - AI 도구 사용 정책 및 가드레일 확립
- 배포 후 소송 리스크 노출         ──▶   - SCA 기반 지속적 라이선스 감사 및 SBOM 의무화
- 오픈웨이트를 무조건 공짜로 인식  ──▶   - 상업적 제약(AUP)과 OSD의 본질적 차이 식별
```

- **오픈웨이트 라이선스의 이중성 직시**: 오픈웨이트는 진정한 오픈소스가 아니며, 빅테크 기업들이 생태계를 장악하면서도 법적 통제권을 유지하려는 **'전략적 오픈(Strategic Openness)'**의 산물임. 따라서 라이선스 본문의 사소한 제약 문구(AUP) 하나가 기업의 비즈니스 모델을 무너뜨릴 수 있음을 경고해야 함.
- **AI-SBOM 체계로의 확장 제언**: 단순 소프트웨어 컴포넌트 목록을 넘어, **사용된 기본 모델(Foundation Model), 파인튜닝 가중치, 학습 데이터셋의 저작권 상태, 생성 프롬프트 계보까지 추적 가능한 'AI-SBOM(AI Software Bill of Materials)'** 체계를 조기에 구축하는 것이 기술사로서 제시할 미래지향적 컴플라이언스 솔루션임.
