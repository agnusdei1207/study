## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 개발 도구·공급망 → **AI 생성 코드·오픈웨이트 라이선스 준수**

## 30초 인출

- 본질: 생성형 AI 도구가 출력한 소스코드의 저작권 침해 및 카피레프트(GPL 등) 감염 리스크와 가중치만 공개된 오픈웨이트(Open-weights) 모델의 상용 이용 제약을 선제적으로 검증하고 통제하는 소프트웨어 공급망 거버넌스 체계
- 메커니즘: AI 도구 약관 검토 → 코드 생성 시 유사도(Code Snippet Matching) 및 SCA 분석 → AI/ML-BOM(AIBOM) 명세서 생성 → 카피레프트 오염 격리 및 컴플라이언스 승인
- 통찰: 단순 가중치 공개 모델을 진정한 오픈소스로 오인하여 상용 제품에 탑재 시 라이선스 위반 소송에 직면하므로 OSAID 1.0 기준 대조 및 AI/ML-BOM 기반의 추적성 확보 필수

<details>
<summary>핵심 용어</summary>

- **AI-Generated Code Compliance** : LLM이 생성한 코드가 기존 오픈소스의 저작권, 특허, 라이선스 의무(GPL 등)를 침해하지 않도록 관리하는 법적·기술적 통제 활동
- **Open-weights (오픈웨이트)** : 모델의 가중치 파라미터는 공개되었으나 학습 데이터, 학습 코드, 상용 목적 이용이 제한될 수 있는 모델 제공 형태 (예: Llama의 사용자 수 제한)
- **OSAID (Open Source AI Definition 1.0)** : 오픈소스 이니셔티브(OSI)가 제정한 기준으로 학습 데이터 정보, 소스코드, 모델 파라미터가 모두 자유롭게 제공되어야 진정한 오픈소스 AI로 인정하는 규격
- **AI/ML-BOM (AIBOM)** : 소프트웨어 자재명세서(SBOM)를 확장하여 모델 출처, 학습 데이터셋, 파라미터 라이선스, 의존성 정보를 표준화한 CycloneDX 명세서
- **Copyleft Contamination (카피레프트 감염)** : AI가 GPL 계열의 코드를 무단 복제하여 기업의 독점(Proprietary) 소스코드에 삽입함으로써 전체 소스코드의 공개 의무가 발생하는 법적 위험

</details>

## 2~4교시 25점 답안

## Ⅰ. AI 생성 코드·오픈웨이트 라이선스 준수의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 생성형 AI가 산출한 소스코드의 오픈소스 라이선스 오염(GPL 등)과 오픈웨이트 모델에 부과된 이용 제한(상용 배포 제한, 파생 모델 명시)을 식별하고 지식재산권 분쟁을 사전 예방하는 소프트웨어 공급망 컴플라이언스 활동 |
| 목적 | 지식재산권 침해 소송 방지, 독점 소프트웨어의 소스코드 강제 공개 위험 차단, AI 도입에 따른 기업 법적 리스크 거버넌스 수립 |

## Ⅱ. AI 라이선스 준수관리의 핵심 특징

| 특징 | 의미 |
|---|---|
| 저작권 모호성 통제 | AI 생성물의 저작권 인정 여부와 학습 데이터 침해 소송에 대응하는 선제적 방어선 구축 |
| 오픈웨이트의 조건부 개방성 | 단순 가중치 공개(Open-weights)와 진정한 오픈소스(OSI Approved)의 법적 권한 차이 식별 |
| AI/ML-BOM 추적성 | 모델 버전, 데이터셋 출처, 파인튜닝 가중치, 라이선스 조건을 기계 판독형 자재명세서로 기록 |
| 자동화 검증 파이프라인 | IDE 및 CI/CD 파이프라인에서 코드 유사도 스캔 도구(Black Duck, FOSSA)를 통한 실시간 탐지 |

## Ⅲ. AI 컴플라이언스 전주기 프로세스 및 거버넌스 체계

### AI 코드 생성부터 배포까지의 공급망 검증 파이프라인

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 1단계: AI 도구 및 오픈웨이트 모델 도입 승인 (Procurement)             │
│   - 도구 이용약관 검토 (입력 프롬프트의 재학습 활용 여부 Opt-out 확인)│
│   - 오픈웨이트 라이선스 조건 분석 (상용 이용 허용, MAU 7억 명 제한 등) │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 승인된 모델만 배포
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 2단계: IDE 코드 생성 및 유사도 검증 (Development & Snippet Matching) │
│   - 개발자의 AI 코딩 에이전트 코드 수락                               │
│   - [GitHub Copilot 필터]: 공개 코드와 일치하는 150자 이상 스니펫 차단│
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 3단계: CI 파이프라인 SCA 및 라이선스 정적 분석 (Verification)         │
│   - Black Duck / FOSSA: AI 생성 코드의 오픈소스 지문(Fingerprint) 매칭│
│   - [GPL / AGPL 카피레프트 오염 검출 시 즉각 빌드 차단 및 알림]       │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 통과
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 4단계: AI/ML-BOM 발행 및 릴리스 거버넌스 (Compliance & Release)        │
│   - CycloneDX 기반 AIBOM 생성 (모델명, 파라미터, 데이터셋, 라이선스)   │
│   - 법무팀 최종 검토 및 오픈소스 고지문(Open Source Notice) 자동 생성  │
└────────────────────────────────────────────────────────────────────────┘
```

### AI 라이선스 관리 4대 핵심 활동

| 단계 | 주요 통제 활동 | 실무 검증 도구 | 핵심 확인 사항 |
|---|---|---|---|
| **도구/모델 평가** | 서비스 약관(ToS) 검토, 모델 라이선스 분류 | 내부 AI 심의위원회 | 상용 서비스 탑재 가능 여부, 프롬프트 데이터 유출 여부 |
| **코드 생성 통제** | 퍼블릭 코드 매칭 차단 필터 활성화 | Copilot Public Code Filter | 150자 이상의 기존 오픈소스 코드 복제 생성 차단 |
| **CI/CD 스캔** | 소스코드 유사도 분석, SCA 의존성 스캔 | Black Duck, Snyk, FOSSA | GPL, AGPL 등 강한 카피레프트 코드 포함 여부 |
| **자재명세 기록** | AI/ML-BOM 생성 및 고지의무 준수 | CycloneDX, SPDX | 모델 가중치 출처, 파인튜닝 데이터셋 라이선스 기록 |

## Ⅳ. 오픈소스 vs 오픈웨이트 vs Open Source AI(OSAID) 비교

### AI 모델 제공 형태별 법적 권한 비교

| 비교 항목 | 전통적 오픈소스 소프트웨어 (OSS) | 오픈웨이트 모델 (Open-weights) | 제언: Open Source AI (OSAID 1.0) |
|---|---|---|---|
| **정의 기준** | OSI 공인 오픈소스 라이선스 (MIT, Apache) | **가중치 파라미터만 공개된 모델** | **OSI가 제정한 진정한 오픈소스 AI 규격** |
| **공개 대상** | 전체 소스코드, 빌드 스크립트 | 사전 학습된 가중치(Weight) 바이너리 | **학습 데이터 정보 + 소스코드 + 가중치 전수** |
| **상용 이용 제약** | 원칙적으로 상용 이용 제한 없음 | **사용자 수 제한(Llama), 특정 분야 금지** | **어떠한 목적의 이용·수정·재배포도 완전 보장** |
| **대표 사례** | Linux, Kubernetes, Spring Framework | Meta Llama 3, Mistral, Gemma | TII Falcon(부분 준수), 완전 개방형 연구 모델 |
| **법적 위험도** | 라이선스 고지 의무 준수 시 안전 | **독점적 라이선스 위반으로 인한 라이선스 박탈 위험**| 가장 안전하고 투명한 공급망 거버넌스 제공 |

### AI 생성 코드의 주요 법적 분쟁 위험 유형

| 위험 유형 | 발생 메커니즘 | 기업에 미치는 파급 영향 |
|---|---|---|
| **저작권 침해 위험** | AI가 학습 데이터셋 내 특정 저작권 코드를 암기(Memorization)하여 그대로 출력 | 원저작자로부터 저작권 침해 금지 청구 및 손해배상 소송 피소 |
| **카피레프트 감염 위험** | GPL-3.0 코드가 기업 상용 독점 소프트웨어 모듈에 복제 삽입 | 회사 고유 지식재산권인 전체 소스코드의 강제 무료 공개 의무 발생 |
| **영업비밀 유출 위험** | 사내 핵심 기밀 알고리즘을 퍼블릭 AI 프롬프트로 입력 | 모델 재학습 데이터로 흡수되어 경쟁사에 기밀 노출 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 오픈웨이트 모델의 "Open" 명칭만 믿고 상용 솔루션에 무단 임베딩하여 라이선스 위반 발생 | 법무팀과 협력하여 모델의 엔드유저 라이선스 계약(EULA) 상용 제한 조건을 사전 검토 |
| AI 코딩 도구가 생성한 코드가 몇 줄 수준의 짧은 스니펫인 경우 전통적 SCA 도구로 탐지 불가 | AST 기반 구문 유사도 분석기 및 토큰 기반 딥 매칭(Deep Matching) 엔진 도입 |
| 개발자가 프라이빗 모드를 해제하고 회사 내부 코드를 외부 퍼블릭 LLM에 유출하는 사고 | 엔터프라이즈 프라이빗 LLM 인프라를 구축하고 프롬프트 외부 유출 방지 DLP 솔루션 적용 |

## Ⅵ. 제언

AI/ML-BOM 기반 공급망 투명성 확보 및 전사 AI 라이선스 품질 게이트 파이프라인

```text
└────────────────────────────────────────────────────────────────────────┘
```

### AI 라이선스 도입 심사 의사결정 체계

```text
신규 AI 모델 또는 AI 생성 코드 도입 검토
       ↓
[OSI 공인 오픈소스 라이선스인가, 단순 오픈웨이트(Open-weights)인가?]
       ├─ 오픈소스 (Apache/MIT) ──→ 고지의무 준수 후 자유롭게 상용 도입
       └─ 오픈웨이트 ──→ [상용 목적 사용 제한(월간 사용자 수 한도 등)이 존재하는가?]
                              ├─ 예 ──→ 법무팀 특별 승인 필요 (초과 시 라이선스 구매)
                              └─ 아니오 ─→ [AI 생성 코드에 GPL 카피레프트 오염이 있는가?]
                                                ├─ 예 ──→ 해당 코드 즉시 폐기 및 재작성
                                                └─ 아니오 ─→ AIBOM 등록 후 프로덕션 승인
```

### 선택 근거: 전통적 SBOM과 제언 AI/ML-BOM 비교

| 구분 | 전통적 소프트웨어 SBOM (SPDX/CycloneDX) | 제언: AI 공급망을 위한 AI/ML-BOM |
|---|---|---|
| 관리 대상 | 소스코드 라이브러리, 바이너리 패키지 | 코드 라이브러리 + **모델 가중치 + 학습 데이터셋 + 파라미터** |
| 취약점 통제 | 소프트웨어 보안 취약점 (CVE) 식별 | 소프트웨어 CVE + **프롬프트 인젝션 취약점 + 데이터 편향성** |
| 법적 준거성 | 오픈소스 라이선스 고지의무 충족 | EU AI Act, 미국 AI 행정명령 등 **글로벌 AI 규제 완벽 대응** |
