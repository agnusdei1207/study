## 지식 로드맵 내 현재 위치

지식 위치: 소프트웨어 공학 → 개발 도구·공급망 → AI 활용 컴플라이언스

## 30초 인출

- 본질: **AI 생성 코드·오픈웨이트 준수관리**는 AI 도구와 모델을 사용할 때 소스코드·모델별 이용 조건을 확인하는 활동
- 메커니즘: 도구·모델 승인 → 라이선스·제공조건 검토 → 생성 코드·구성요소 점검 → 기록·예외 처리
- 핵심: 오픈웨이트는 가중치 공개를 뜻하며 이용 조건이나 오픈소스 지위를 자동 보장하지 않음

<details>
<summary>핵심 용어</summary>

- **AI 생성 코드·오픈웨이트 준수관리**: AI 도구·모델의 이용 조건과 생성 산출물의 라이선스·출처 위험을 확인하는 활동
- **오픈웨이트(Open-weight)**: 학습된 모델 파라미터를 공개한 제공 형태로, 이용권한은 적용 라이선스·계약 조건에 따름
- **Open Source AI Definition(OSAID)**: AI 시스템의 이용·연구·수정·공유 자유와 수정에 필요한 구성요소 공개를 설명하는 OSI 정의
- **소프트웨어 구성 분석(SCA, Software Composition Analysis)**: 소프트웨어 구성요소와 관련 라이선스·취약점 정보를 식별하는 분석
- **AI/ML-BOM**: AI·머신러닝 모델과 관련 자산·구성 정보를 기록하는 CycloneDX 자재명세 형식

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **AI 생성 코드·오픈웨이트 준수관리**는 AI 도구·모델의 이용 조건과 생성 산출물의 라이선스·출처 위험을 확인하는 활동 |
| 목적 | 허용 범위에 맞는 AI 사용과 코드·모델 구성요소의 권리·의무 추적 |

### Ⅱ. 주요 위험과 확인 사항

| 대상 | 위험·의무 | 확인 사항 |
|---|---|---|
| AI 도구·모델 | 계약·라이선스·사용정책의 제한 | 사용·배포·수정·상업적 이용 조건 |
| 생성 코드 | 기존 코드와의 유사성·라이선스 고지 누락 | 코드 검토·유사도 점검·필요 시 법률 검토 |
| 포함 패키지 | 의존성 라이선스·취약점 | 구성요소 목록과 고지·양립성 검토 |

### Ⅲ. 통제 절차

```text
도구·모델의 이용 조건 확인
    ↓
허용된 입력·산출물 범위 설정
    ↓
생성 코드·의존성 검토
    ↓
라이선스 의무·유사성 검토
    ↓
사용 승인·근거 기록
```

제언: 모델별 허용 범위와 코드 점검 절차를 개발팀이 참조할 수 있는 목록으로 관리.

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **AI 생성 코드·오픈웨이트 준수관리**는 AI 도구·모델의 이용 조건과 생성 산출물의 라이선스·출처 위험을 확인하는 활동 |
| 목적 | 허용 범위에 맞는 AI 사용과 코드·모델 구성요소의 권리·의무 추적 |

AI 생성물의 법적 취급은 관할 법률·도구 계약·생성 내용에 따라 다를 수 있으므로, 도구 이용 조건과 코드 산출물 점검을 분리해 검토.

## Ⅱ. 모델 제공 형태와 이용 조건

| 제공 형태 | 공개·제공 내용 | 준수 검토 |
|---|---|---|
| 오픈소스 소프트웨어 | 소스와 라이선스상 이용·수정·재배포 권한 | 라이선스 의무·고지·재배포 조건 |
| 오픈웨이트 모델 | 학습된 파라미터 공개 | 모델별 라이선스·계약·사용정책 |
| Open Source AI | OSAID가 설명하는 이용·연구·수정·공유 자유와 필요한 구성요소 | 모델 설명·학습 관련 코드·데이터 정보·파라미터 제공 여부 |
| 관리형 상용 도구 | 서비스 접근과 계약상 권한 | 입력 데이터 처리·보존·출력 권리·보증·사용 제한 |

가중치 공개만으로 모델의 오픈소스 지위나 특정 이용 허가가 정해지지 않으며, 개별 조건 확인 필요.

## Ⅲ. 준수관리 생애주기

```text
도구·모델 도입 조건 확인
    ↓
입력 데이터·생성 코드 사용 범위 승인
    ↓
산출물·의존성·라이선스 점검
    ├─ 의무 명확 → 고지·출처 기록 후 배포 검토
    └─ 불명확 → 법무·보안 검토 후 결정
```

## Ⅳ. 소스코드와 모델 자산 점검

| 점검 대상 | 방법 | 한계·유의점 |
|---|---|---|
| 생성 코드 | 사람의 코드 리뷰와 유사 코드 탐지 | 결과만으로 저작권 침해 여부 단정 불가 |
| 오픈소스 의존성 | SCA를 통한 구성요소·라이선스·취약점 식별 | 직접·전이 의존성과 고지 조건 확인 필요 |
| 모델 파일 | 모델명·버전·출처·라이선스·다운로드 경로 기록 | “open” 표기만으로 사용권 판단 금지 |
| 입력·출력 자료 | 민감정보·비밀정보 입력 통제와 계약 조건 확인 | 제공자 보존·재학습 조건 확인 필요 |

## Ⅴ. 위험별 통제

| 위험 | 통제 |
|---|---|
| 도구·모델의 사용·배포 제한 위반 | 승인 전 라이선스·계약·정책과 사용 목적 대조 |
| 생성 코드에 기존 코드와 유사한 부분 포함 | 코드 리뷰·유사도 도구 활용, 출처·고지 필요성 검토 |
| 카피레프트 의무의 적용 범위 오판 | 실제 포함·결합 방식과 배포 형태를 검토하고 법률 자문 연결 |
| AI 서비스로 소스·개인정보 전송 | 입력 데이터 분류와 외부 전송·보존 조건 통제 |
| 모델·의존성의 추적 정보 유실 | 버전·출처·라이선스·변경 기록 관리와 적절한 BOM 활용 |

## Ⅵ. 기술사적 제언 — 모델별 승인 조건과 산출물 검토 연결

| 한계 | 해결 방안 |
|---|---|
| 모델 승인 시 검토한 조건이 실제 개발·배포 코드에서 지켜졌는지 연결해 확인하기 어려울 가능성 | 모델별 허용 목적·배포 조건·입력 금지자료를 승인 목록에 기록하고, 코드·의존성 검사 결과와 모델 자산 정보를 변경 이력에 연결하는 절차 운영 |
