## 연관 키워드

- AI 생성 코드(AI-Generated Code), 오픈웨이트(Open-Weight), LLM(Large Language Model)
- 카피레프트(Copyleft), GPL/AGPL, 라이선스 컴플라이언스
- 유령 작성(Ghostwriting), 스니펫 매칭, SBOM/AIBOM, Human-in-the-Loop

## Ⅰ. AI 생성 코드·오픈웨이트 라이선스 준수의 개요

- 핵심 요약 : LLM 기반 생성 코드와 오픈웨이트 모델 도입 시의 저작권·라이선스 리스크를 통제하는 거버넌스 체계.
- 개념 : 대형 언어 모델(LLM, Large Language Model) 기반 코딩 도우미가 생성한 소스코드와 Llama 등 오픈웨이트(Open-Weight) AI(Artificial Intelligence) 모델을 기업 시스템에 도입할 때 발생하는 저작권 침해, 오픈소스 카피레프트(Copyleft) 라이선스 전염, 모델 사용 조건 위반 리스크를 식별하고 법적·기술적 컴플라이언스를 확보하는 거버넌스 체계.
- 배경 및 필요성 : AI 모델이 GPL(GNU General Public License)·AGPL(GNU Affero General Public License) 등 엄격한 카피레프트 라이선스 코드를 학습한 후 그대로 암기·출력(Ghostwriting)하거나, 상업적 사용이 제한된 오픈웨이트 모델을 무단 배포로 인해 발생 가능한 저작권 소송과 기업 지적재산권(IP, Intellectual Property) 침해 위험 대두.
- 주요 통제 대상 : AI 생성 코드의 저작권 귀속 여부, 학습 데이터 내 라이선스 오염, 오픈웨이트 모델의 라이선스 제약(Community·Commercial Use 제약).

## Ⅱ. AI 생성 코드 컴플라이언스의 특징

- 핵심 요약 : 저작권 귀속·학습 데이터 오염·모델 사용 조건의 3중 통제 대상과 암묵적 오염 경로의 특수성.
1. 통제 대상의 3중 구조 : AI 생성 코드의 저작권 귀속, 학습 데이터 라이선스 오염, 오픈웨이트 모델 사용 조건.
2. 유령 작성(Ghostwriting) 리스크 : 학습 원본 오픈소스 코드의 그대로 출력 가능성.
3. 비(非) 오픈소스성 : LLaMA, Mistral 등 다수 모델의 OSI(Open Source Initiative) 비승인 자체 라이선스 채택(월간 활성 사용자 수 제한, 경쟁 AI 학습 금지 등).
4. 암묵적 오염 경로 : 개발자 프롬프트 응답을 통한 무의식적 스니펫 유입.
5. 추적성 요구 : 프롬프트·모델 버전·생성 일자 등 계보(Provenance) 관리 필요.

## Ⅲ. AI 생성 코드·오픈웨이트 라이선스 준수의 구조 (흐름)

- 핵심 요약 : 학습 데이터부터 코드베이스 병합까지의 위험 전파 경로와 다층 검증 파이프라인.

```text
[ 위험 전파 및 검증 파이프라인 ]
[ 오픈소스 학습 데이터 (GPL 등) ]
   ↓
[ LLM 모델 학습 ] → [ AI 코딩 도구 ]
                     ↓ (개발자 프롬프트)
              [ AI 생성 코드 제안 ]
                     │
   ┌─────────────────┴─────────────────┐
   ▼                                   ▼
[ 유사도·스니펫 매칭 검사 ]     [ SAST 보안 약점 진단 ]
 - Black Duck, FOSSID            - SonarQube, Snyk
   └─────────────────┬─────────────────┘
                     ▼
   [ 품질·라이선스 승인 ] → [ 코드베이스 병합 ]

 * SAST(Static Application Security Testing)
```

```text
[ 오픈웨이트 모델 도입 검토 흐름 ]
후보 모델 선정
   ↓
라이선스 약관 법률 검토
 (사용자 수 상한, 증류(Distillation) 금지 등)
   ↓
허용 용도 판정 (상용 서비스·내부 도구·파인튜닝)
   ↓
허용 모델 화이트리스트 등록 및 AIBOM 기록

 * AIBOM(AI Bill of Materials)
```

- 유령 작성 및 무단 복제 검출 : AI가 생성한 코드가 특정 오픈소스 원본과 100% 일치하는 경우에 대비한 공용 코드 매칭 필터(Public Code Match Filter) 작동.
- 오픈웨이트 라이선스의 비(非) 오픈소스성 인지 : 다수 모델의 OSI 비승인 자체 라이선스로 인한 상용 서비스 적용 시 법적 조건의 면밀 검토 필수.

## Ⅳ. 전통적 오픈소스 컴플라이언스와 AI 환경 컴플라이언스의 비교

- 핵심 요약 : 오염 경로의 암묵화, 비표준 라이선스 조건, 검증 방식의 유사도 기반 전환이 핵심 차이.

| 비교 항목 | 전통적 오픈소스 라이선스 | AI 생성 코드 및 오픈웨이트 모델 |
|---|---|---|
| 법적 저작권 인정 여부 | 인간 창작물로서의 명확한 저작권 인정 | 인간의 창작적 기여 없는 순수 AI 결과물의 저작권 불인정 추세 |
| 오염 경로 | 개발자가 명시적으로 다운로드 및 라이브러리 링크 | AI 프롬프트 응답을 통한 무의식적 스니펫 유입(암묵적 오염) |
| 라이선스 조건 | OSI 인증 표준(MIT, Apache, GPL 등) | 모델별 비표준 제약조건(예: Llama 3 Community License) |
| 검증 도구 | 패키지 의존성 파일(pom.xml, package.json) 분석 | 소스코드 유사도 비교(Snippet Matching) 및 프롬프트 추적 |
| 법적 분쟁 리스크 | 전염성 라이선스 기인 상용 소스코드 강제 공개 | 학습 데이터 저작권 침해 손해배상 및 영업비밀 유출 위험 |

## Ⅴ. AI 생성 코드·라이선스 준수의 장점과 한계

- 핵심 요약 : AI 활용 개발 생산성 혁신의 기회와 저작권·라이선스 리스크가 공존하므로 다층 통제 체계 필요.
- 장점
  1. AI 코딩 도구를 통한 개발 생산성 및 코드 품질 향상.
  2. 오픈웨이트 모델의 자체 호스팅을 통한 데이터 주권 확보.
  3. 컴플라이언스 파이프라인 자동화를 통한 감사 대응력 강화.
- 한계점 1 : AI 모델 학습 데이터의 블랙박스 특성 기인 저작권 침해 위험
  - 한계점 : LLM이 학습한 수십억 라인의 공개 코드 중 엄격한 카피레프트(GPL/AGPL) 코드 포함으로, AI 생성 코드의 원본 유사 출력 시 기업 소스코드 공개 의무 등 법적 분쟁 초래.
  - 해결 방안 : AI 코딩 도구 내 공개 코드 일치 제안 차단(Block suggestions matching public code) 설정의 강제 활성화, CI(Continuous Integration) 파이프라인에 코드 유사도 검색 엔진(Black Duck, GitHub Copilot Scanner) 전수 스캔 연동.
- 한계점 2 : 오픈웨이트(Open-Weight) 모델의 특수 사용 제약 조건 위반
  - 한계점 : Llama, DeepSeek 등 오픈웨이트 모델 라이선스 내 상용 사용자 수 상한(월간 활성 사용자 7억 명 등), 타 모델 증류(Distillation) 학습 금지 등 특수 조항 간과에 따른 라이선스 위반 발생.
  - 해결 방안 : 기업 내 AI 거버넌스 위원회의 도입 전 모델별 특수 라이선스 약관 법률 검토, 사내 활용 목적(상용 서비스, 내부 도구, 파인튜닝)별 허용 모델 화이트리스트 운영.
- 한계점 3 : 소프트웨어 자재명세서(SBOM, Software Bill of Materials) 내 AI 생성 자산 추적성 누락
  - 한계점 : AI 활용 코드 스니펫, 프롬프트 엔지니어링 이력, 활용 모델 버전의 기존 형상관리·SBOM 미기재로 향후 라이선스 감사 시 증빙 불가.
  - 해결 방안 : AI 생성 코드에 대한 메타데이터 태깅 의무화, AI 구성명세서(AIBOM) 생성 파이프라인 구축을 통한 프롬프트·LLM 버전·생성 일자·의존성 계보(Provenance) 추적성 확보.

## Ⅵ. 기업 AI 거버넌스 확립을 위한 기술사적 제언

- 핵심 요약 : 스니펫 매칭 필터·SCA 도구 통합과 Human-in-the-Loop 원칙의 제도화.
- 코드 스니펫 매칭 필터 활성화 및 SCA(Software Composition Analysis) 도구 통합 : GitHub Copilot의 'Match public code' 차단 설정의 전사 강제 활성화, 커밋 파이프라인에 Black Duck 등 스니펫 매칭 기능 연동을 통한 무단 복제 코드 유입 차단.
- AI 활용 가이드라인 수립 및 인체 개입(Human-in-the-Loop) 원칙 제도화 : AI 생성 코드의 초안(Draft) 취급 원칙, 숙련 개발자의 검토·수정·서명(Sign-off) 후 배포 의무화를 통한 저작권 인정 가능성 확보 및 품질 결함에 대한 인간 최종 책무성 확립.

## Ⅶ. 결론

- 핵심 요약 : AI 생성 코드와 오픈웨이트 모델의 활용은 다층 컴플라이언스 통제 없이는 법적 리스크로 전환.
- 요약 : 학습 데이터 오염 차단, 모델 라이선스 검토, AIBOM 기반 추적성의 3축 거버넌스 수행.
- 시사점 : 스니펫 매칭 자동 검증과 Human-in-the-Loop 검수의 병행으로 생산성과 법적 안전성의 동시 확보 필요.
