## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 오픈소스·라이선스 → **AI 생성 코드·오픈웨이트 라이선스 준수**

## 30초 인출

- 본질: AI 생성 코드·오픈웨이트 라이선스 준수는 AI가 만든 코드와 공개 가중치 모델을 쓸 때 오픈소스 라이선스와 모델 라이선스의 의무를 지키는 활동
- 메커니즘: 생성 코드의 출처·유사도와 의존 라이선스를 스캔하고 모델 라이선스의 사용 조건을 확인한 뒤 결과를 SBOM·AI BOM에 기록하고 승인
- 통찰: AI 생성 코드는 출처가 보이지 않아 카피레프트 코드가 섞여도 알기 어려우므로 생성 코드를 라이선스·유사도 스캔으로 검증한 뒤 병합하고 모델 라이선스 조건은 도입 전에 확인

<details>
<summary>핵심 용어</summary>

- **오픈웨이트(Open-weight) 모델** : 가중치는 공개하지만 학습 데이터·코드는 공개하지 않을 수 있는 AI 모델
- **모델 라이선스** : 모델의 사용 목적·규모·재배포 조건을 정한 라이선스
- **카피레프트 감염(Copyleft Contamination)** : 카피레프트 코드가 섞여 결합물 전체에 소스 공개 의무가 번지는 위험
- **SCA(Software Composition Analysis)** : 구성요소와 라이선스를 자동으로 식별하는 분석 도구
- **SBOM·AI BOM** : 소프트웨어 구성요소와 AI 모델·데이터의 출처·라이선스를 기록한 목록
- **OSAID(Open Source AI Definition)** : 오픈소스 이니셔티브(OSI)가 정한 오픈소스 AI의 정의

</details>

## 2~4교시 25점 답안

## Ⅰ. AI 생성 코드·오픈웨이트 라이선스 준수의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **AI 생성 코드 라이선스 준수** 는 AI 생성 코드와 오픈웨이트 모델 사용 시 라이선스 의무를 지키는 활동 |
| 목적 | 라이선스 위반 위험의 사전 통제 |

## Ⅱ. 일반 오픈소스 사용과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 출처 불투명 | 생성 코드가 어떤 학습 코드에서 나왔는지 불명 |
| 모델 라이선스 별도 | 코드가 아닌 모델의 사용 조건 존재 |
| 저작권 불확실 | 생성물의 권리 귀속 판단 곤란 |

## Ⅲ. 위험과 컴플라이언스 절차

### 위험 구조

```text
AI 생성 코드 ── 학습 코드와 유사 → 카피레프트 감염·고지 의무 누락
오픈웨이트 모델 ── 사용 조건(규모·목적) 위반, 학습 데이터 출처 불명
```

### 확대: 통합 컴플라이언스 프로세스

```text
정책 수립 (허용 라이선스·모델 조건)
    ↓
도입 전 검토 (모델 라이선스 확인)
    ↓
생성 코드 스캔 (라이선스·유사도)
    ↓
승인·기록 (SBOM·AI BOM) → 주기적 감사
```

## Ⅳ. 라이선스 의무·점검 항목·검증 도구

### 의무사항과 위험

| 대상 | 의무·위험 |
|---|---|
| 허용적 라이선스 코드 | 저작권·라이선스 고지 누락 |
| 카피레프트 코드 | 결합물 소스 공개 의무 발생 |
| 오픈웨이트 모델 | 상업 이용·규모·목적 제한 조건 위반 |

### 컴플라이언스 점검 항목

| 점검 항목 | 내용 |
|---|---|
| 생성 코드 출처 | 유사 코드·라이선스 스캔 결과 |
| 의존 라이선스 | 카피레프트·Source-Available 포함 여부 |
| 고지 의무 | 저작권·라이선스 고지 이행 |
| 모델 조건 | 사용 목적·규모 제한 확인 |
| 기록 | SBOM·AI BOM 갱신 |

### 기술적 검증 도구

| 도구 | 역할 |
|---|---|
| SCA 도구 | 구성요소·라이선스 식별 |
| 코드 유사도 검사 | 생성 코드와 공개 코드의 유사 여부 |
| SBOM·AI BOM | 출처·라이선스·모델 정보 관리 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 생성 코드 출처를 알 수 없어 라이선스 오염 미확인 | 병합 전 유사도·라이선스 스캔 |
| 모델 라이선스 조건 확인 누락 | 도입 전 모델 라이선스 검토 절차 |
| 기록 부재로 사후 감사 곤란 | SBOM·AI BOM 기록과 갱신 |

## Ⅵ. 제언

AI 생성 코드는 병합 전에 라이선스·유사도 스캔을 통과하도록 하고, 모델은 도입 전 라이선스 조건을 확인해 기록

### 병합 전 검증 흐름

```text
AI 생성 코드
    ↓
라이선스·유사도 스캔
    ├─ 통과 → 병합, SBOM 기록
    └─ 위험 → 대체 구현 또는 승인 절차
```

### 확대: 모델 도입 판단

```text
모델 라이선스 확인
    ├─ 사용 조건 충족 → 도입·AI BOM 기록
    └─ 제한 위반 → 다른 모델 검토
```

### 선택 근거: 사후 점검과의 비교

| 구분 | 배포 후 점검 | 제언: 병합·도입 전 검증 |
|---|---|---|
| 위반 발견 시점 | 배포 이후 | 병합 전 |
| 교체 비용 | 큼 | 작음 |
| 근거 | 개별 확인 | 기록으로 추적 |
