## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 데이터 공학·수집 → 웹 크롤링(Web Crawling)

## 지식 위치

소프트웨어공학 > 데이터 수집 > 웹 크롤링(Web Crawling)

## 30초 인출

- 본질: 초기 시드(Seed) URL로부터 하이퍼링크를 재귀적으로 추적하여 웹 페이지를 대규모로 탐색하고 HTML 문서를 자동 수집하는 분산 소프트웨어 에이전트 시스템
- 메커니즘: 시드 URL 주입 → URL 프론티어(Frontier) 우선순위 및 예절(Politeness) 큐잉 → HTML 다운로드 및 링크 추출 → 블룸 필터(Bloom Filter) 기반 중복 검증 → 신규 URL 재투입 및 데이터 저장
- 통찰: 무분별한 고속 수집 시 대상 서버 장애(DoS) 유발 및 저작권/약관 위반 위험이 발생하므로 robots.txt 준수, 요청 속도 제한(Rate Limiting), 분산 프록시 풀 관리 및 법적 컴플라이언스 준수 필수

<details>
<summary>핵심 용어</summary>

- **시드 URL (Seed URL)** : 크롤러가 전체 웹 탐색을 개시하기 위해 최초로 입력받는 시작 웹 페이지 주소 목록
- **URL 프론티어 (URL Frontier)** : 방문할 대상 URL들을 보관하며 크롤링 우선순위(Priority)와 대상 호스트별 예절(Politeness)을 제어하는 분산 큐
- **예절 정책 (Politeness Policy)** : 특정 도메인 서버에 부하를 주지 않기 위해 동일 호스트에 대한 동시 연결 수와 요청 간격(Delay)을 강제하는 정책
- **블룸 필터 (Bloom Filter)** : 대규모 URL(수십억 개)의 중복 방문 여부를 메모리 효율적으로 검사하기 위한 해시 기반 확률적 자료구조 (False Positive 허용)
- **robots.txt (REP: Robots Exclusion Protocol)** : 웹 사이트 관리자가 검색 엔진 크롤러에게 특정 경로의 수집 허용/차단 권한을 명시한 텍스트 규약
- **웹 스크래핑 (Web Scraping)** : 크롤링된 HTML 문서에서 정규표현식이나 파서(XPath/CSS Selector)를 통해 특정 정형 데이터(가격, 텍스트)를 추출·가공하는 행위
</details>

## 2~4교시 예상문제 (25점)

> 대규모 데이터 파이프라인 구축을 위한 웹 크롤링(Web Crawling) 시스템의 아키텍처와 URL 프론티어 동작 메커니즘을 설명하고, 수집 신뢰성 확보 방안(중복 제거, 예절 정책, 동적 렌더링) 및 법적/보안적 고려사항을 기술하시오. (25점)

---

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 인터넷 상의 방대한 월드와이드웹(WWW) 하이퍼링크 네트워크를 자동 순회하며 웹 페이지 콘텐츠를 체계적으로 수집, 색인(Indexing)하는 소프트웨어 봇(Bot) 시스템 |
| 목적 | 검색 엔진 인덱스 구축, 빅데이터 분석 및 생성형 AI 학습용 말뭉치(Corpus) 수집, 시장 가격 모니터링 데이터 확보 |

## Ⅱ. 핵심 특징

| 특징 | 세부 내용 |
|---|---|
| 재귀적 링크 탐색 | 시드 URL에서 추출한 하이퍼링크를 다시 탐색 대기열에 추가하며 웹 그래프를 지속적으로 확장 |
| 대규모 분산 확장성 | 수억 건 이상의 웹 페이지를 병렬 처리하기 위해 마스터-워커 분산 노드 및 메시지 큐 아키텍처 채택 |
| 호스트 예절 준수 | 대상 웹 서버의 가용성을 보호하기 위해 `robots.txt`를 해석하고 도메인별 초당 요청 수(RPS)를 엄격히 제한 |
| 데이터 신선도와 변경 감지 | 정기적인 재방문(Recrawl) 스케줄링을 통해 페이지 업데이트 여부(HTTP ETag/Last-Modified) 추적 |

현대 빅데이터 및 거대언어모델(LLM) 데이터 파이프라인의 가장 기초적인 원천 데이터 수집 인프라로 기능.

## Ⅲ. 체계·프로세스

```text
[1. 시드 URL 주입 및 초기화]
  - 고품질 루트 도메인 목록 입력 (Seed URLs)
       │
       ▼
[2. URL 프론티어 (URL Frontier) 스케줄링]
  ┌────────────────────────────────────────────────────────┐
  │ 1) 우선순위 큐 (Priority Queue): PageRank 높은 페이지 우선│
  │ 2) 예절 큐 (Politeness Queue)  : 도메인별 지연(Delay) 강제│
  └────────────────────────────────────────────────────────┘
       │
       ▼ (robots.txt 파싱 및 크롤링 허용 여부 판별)
[3. 분산 다운로더 (Fetcher Worker)]
  - DNS 확인(DNS Caching) 및 HTTP/HTTPS 페이지 다운로드
  - 동적 페이지(SPA)의 경우 Playwright/Puppeteer 헤드리스 브라우저 렌더링
       │
       ▼
[4. HTML 파싱 및 링크 추출 (Parser & Extractor)]
  - 본문 데이터 저장 (Storage Server / S3)
  - `<a href="...">` 태그에서 신규 URL 추출 및 표준화(Normalization)
       │
       ▼
[5. URL 중복 필터링 (Deduplication)]
  - Bloom Filter 및 Redis Set으로 기방문 URL 여부 판별
  ├─ [신규 URL] ──► URL 프론티어에 재투입 (루프 지속)
  └─ [기방문 URL] ─► 폐기
```

URL 스케줄링부터 예절 준수 다운로드, 동적 렌더링, 중복 필터링을 거쳐 신규 링크를 재귀 순환하는 엔드투엔드 파이프라인.

## Ⅳ. 종류·비교

| 비교 항목 | 웹 크롤링 (Web Crawling) | 웹 스크래핑 (Web Scraping) |
|---|---|---|
| **수행 목적** | 웹 그래프를 탐색하며 대량의 웹 페이지 링크를 발견하고 HTML 원본 수집 | 수집된 특정 페이지에서 비즈니스에 필요한 특정 데이터 필드만 선별 추출 |
| **작업 대상** | 전체 도메인 또는 인터넷 전반의 대규모 불특정 웹 페이지 | 특정 사이트의 상세 상품 페이지, 게시판 목록 등 제한된 페이지 |
| **핵심 기술** | URL 프론티어, 분산 스케줄러, robots.txt 준수, 블룸 필터 | DOM 파서, XPath, CSS Selector, 정규표현식, OCR |
| **결과 산출물** | 압축된 WARC 파일, 미가공 HTML 원본 데이터셋 | 데이터베이스에 적재되는 정형화된 JSON, CSV, DB 레코드 |

### 크롤링 렌더링 방식 비교 (정적 HTTP 요청 vs 동적 헤드리스 브라우저)

| 비교 항목 | HTTP 클라이언트 크롤링 (Requests, Scrapy) | 헤드리스 브라우저 크롤링 (Puppeteer, Playwright) |
|---|---|---|
| **동작 원리** | 단순 HTTP GET 요청 후 초기 수신된 HTML 텍스트만 파싱 | 실제 크로미움 브라우저를 백그라운드 구동하여 JS 실행 후 DOM 수집 |
| **처리 성능** | 초당 수백~수천 페이지 다운로드 (초고속, 극저자원) | 브라우저 인스턴스 구동으로 CPU/메모리 소모 큼 (상대적 저속) |
| **SPA 지원** | React, Vue 등 클라이언트 사이드 렌더링(CSR) 콘텐츠 수집 불가 | 무한 스크롤, 버튼 클릭, 복잡한 SPA 동적 렌더링 완벽 수집 가능 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 수십억 개 URL 저장 시 발생하는 막대한 메모리 오버헤드로 인한 서버 스케일 한계 | 확률적 비트 배열을 사용하는 블룸 필터(Bloom Filter)를 도입하고 분산 Redis 클러스터와 2계층 캐싱 적용 |
| Cloudflare, Akamai 등 WAF/Anti-Bot 솔루션의 IP 차단 및 CAPTCHA 챌린지 직면 | 분산 프록시 풀(Residential Proxy Pool) 회전, 요청 헤더(User-Agent) 랜덤화, 브라우저 핑거프린트 우회 기술 적용 |
| 무단 크롤링으로 인한 저작권 침해, 업무방해죄 및 서비스 이용약관 위반 법적 분쟁 | 대상 웹사이트의 이용약관 및 robots.txt를 철저히 검토하고 개인정보 비식별화 처리 및 API 우선 활용 |

## Ⅵ. 제언

공격적인 무단 스크래핑을 지양하고, 표준 robots.txt와 HTTP 응답 헤더를 준수하는 책임 있는 크롤링 거버넌스를 확립하며 데이터 계보(Lineage) 추적 체계 구축 필요.

```text
[책임 있는 엔터프라이즈 크롤링 파이프라인]
  robots.txt 검증 → 호스트별 Rate Limit (1 RPS 이하) → 데이터 수집 → 개인정보(PII) 마스킹 → 정제 데이터셋 적재
```

| 관리 영역 | 전통적 무차별 크롤링 | 엔터프라이즈 준법 크롤링 |
|---|---|---|
| 수집 정책 | 멀티스레드 최대 속도 요청 (DoS 유발 위험) | 도메인별 요청 지연 및 백오프(Backoff) 강제 |
| 보안 및 법률 | 저작권 및 약관 검토 결여 | 데이터 라이선스 검증 및 저작물 공정 이용(Fair Use) 준수 |
