## 연관 키워드

- 웹 크롤링(Web Crawling), URL(Uniform Resource Locator) 프론티어(URL Frontier), robots.txt
- 크롤링 예의 정책(Politeness Policy), 중복 제거(블룸 필터, SimHash), URL 정규화(Canonicalization), 적응형 백오프(Adaptive Backoff)

## Ⅰ. 웹 크롤링의 개요

- 핵심 요약 : 하이퍼링크를 따라 웹 문서를 대규모로 자동 수집하는 기술로, 검색 색인과 AI 학습 데이터 확보의 기반.
- 개념 : **웹 크롤링** (Web Crawling)이란 공개된 웹 페이지를 하이퍼링크를 따라 순회하며 문서를 자동으로 수집해, 검색 엔진의 색인 데이터베이스나 학습용 대규모 코퍼스를 만드는 분산 자동화 기술.
- 배경 및 필요성 : 웹 문서의 규모가 커져 사용자 검색에 응답하려면 사전 색인이 필요하고, 대규모 언어 모델(LLM, Large Language Model)의 사전 학습 데이터 확보 수요도 생김.
- 주요 목적 : **URL 프론티어** (URL Frontier), 다운로더, 파서, 중복 제거기로 구성된 수집 체계를 통해 품질 높은 웹 코퍼스를 구축.

## Ⅱ. 웹 크롤링의 특징

- 핵심 요약 : 링크 기반 자율 순회, 예의 정책 준수, 대규모 중복 통제가 결합된 분산 수집 체계.

1. 그래프 순회 : 시드(Seed) URL에서 출발해 링크를 따라 이동하는 방식.
2. **크롤링 예의 정책** (Politeness Policy) : 동일 호스트에 과도한 요청을 보내지 않도록 도메인별 지연을 강제 → 서버 과부하 방지.
3. **robots.txt** 준수 : 사이트가 공지한 수집 허용 범위를 따라 수집 대상을 제한.
4. 중복 검출 : **블룸 필터**(Bloom Filter)와 **SimHash** 기반으로 대량의 URL과 문서 중복을 판별.
5. 분산 수집 : 다운로더 워커 풀을 병렬로 운영해 수집 규모를 수평 확장.
6. URL 정규화(Canonicalization) : 같은 페이지를 가리키는 여러 URL을 하나로 통합 → 중복 수집 감소.

## Ⅲ. 웹 크롤링의 구조 (흐름)

- 핵심 요약 : 프론티어 큐에서 다운로더, 파서, 중복 검출을 거쳐 신규 링크가 다시 프론티어로 돌아오는 순환 구조.
- 시드 URL에서 출발한 문서가 HTTP(Hypertext Transfer Protocol) 요청으로 내려받아지고, 추출된 링크가 다시 큐에 들어가는 순환 흐름.

```text
[ 시드 URL (Seed URL) ]
          ↓
[ URL 프론티어 ]
  - 우선순위 큐 (Priority Queue)
  - 예의 큐 (Politeness Queue)
          ↓
[ robots.txt 확인 ]
  - 수집 허용 여부 판별
          ↓
[ 분산 다운로더 워커 ]
  - 비동기 HTTP 요청, DNS 캐싱
          ↓
[ 파서·중복 검출 ]
  - 링크 추출, SimHash·블룸 필터
          ↓
[ 신규 링크 → URL 프론티어 재입력 ]
```

- URL 프론티어 : 방문할 URL을 보관하는 큐로, 서버 과부하를 막는 예의 큐와 중요 페이지를 먼저 방문하는 우선순위 큐로 구성.
- 크롤링 예의 정책 : 같은 도메인에 연속 요청을 보내지 않도록 도메인별 지연 시간을 두는 규칙.

## Ⅳ. 웹 크롤링과 웹 스크래핑의 비교

- 핵심 요약 : 웹 전역을 링크로 확산하며 수집하는 크롤링과, 지정된 페이지에서 목표 데이터만 뽑는 스크래핑의 목적과 범위 차이.

```text
[ 웹 크롤링 : 링크 따라 확산 ]
  페이지A → 페이지B → 페이지C
     ↓          ↓
  페이지D    페이지E  (링크 재귀 순회)

[ 웹 스크래핑 : 목록 순차 방문 ]
  URL 목록 [P1, P2, P3]
          ↓
  지정 요소만 파싱해 추출
```

| 비교 항목 | 웹 크롤링 (Web Crawling) | 웹 스크래핑 (Web Scraping) |
| --- | --- | --- |
| 수집 목적 | 웹 전체 탐색과 검색 인덱싱 | 특정 페이지의 목표 데이터 추출 |
| 수집 범위 | 인터넷 전역의 대규모 페이지 | 사전에 정한 사이트의 상세 페이지 |
| 탐색 방식 | 링크를 따라 자율 이동 | 지정된 URL 목록을 순차 방문 |
| 중복 통제 | 대규모 URL과 콘텐츠 중복 검출이 필수 | 식별자 기반의 단순 검증 |
| 대표 도구 | Apache Nutch, Scrapy, Googlebot | BeautifulSoup, Playwright, Puppeteer |

## Ⅴ. 웹 크롤링의 장점과 한계

- 핵심 요약 : 대규모 데이터 확보라는 장점, 무한 루프와 서버 부하, 데이터 노이즈라는 한계.

1. 장점 : 검색 색인과 학습용 대규모 코퍼스를 자동으로 지속 확보.
2. 장점 : 분산 아키텍처로 수집 규모를 수평 확장.
3. 장점 : 링크 구조 분석으로 PageRank 같은 품질 평가 기반을 제공.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 스파이더 트랩(Spider Trap) | 캘린더 링크, 세션 ID 파라미터로 끝없이 중복 페이지가 생겨 자원 고갈 | URL 정규화, 블룸 필터 기반 방문 이력 판별, 최대 탐색 깊이 제한 | 중복 URL 비율 |
| 서버 과부하와 차단 | 무분별한 병렬 요청이 대상 서버에 부하를 주고 WAF(Web Application Firewall)나 IP 차단을 유발 | robots.txt 준수, 도메인별 예의 지연, 적응형 레이트 리미팅 | 서버 오류율, 차단 건수 |
| 비정형 데이터 노이즈 | 광고와 내비게이션 등 보일러플레이트와 유사 중복이 섞여 후속 분석 품질 저하 | 본문 추출 알고리즘 적용, SimHash·MinHash 기반 근사 중복 필터링 | 본문 추출 정밀도 |

## Ⅵ. 대규모 분산 크롤러 구축을 위한 기술사적 제언

- 핵심 요약 : 블룸 필터와 SimHash 기반 중복 제거, robots.txt 준수와 적응형 백오프의 의무화.

- 수집 플랫폼 팀은 수억 개 URL의 방문 이력을 모두 메모리에 담을 수 없으므로, 블룸 필터로 URL 중복을 판별하고 SimHash로 문서 유사도를 가려내는 구조를 기본으로 설계해야 한다. 블룸 필터는 오탐(False Positive)을 허용하는 대신 공간 효율이 높다는 점을 감안해 운영 기준을 세운다.
- 수집 정책 담당 조직은 robots.txt를 예외 없이 따르고, HTTP 429(Too Many Requests) 응답을 받으면 요청 주기를 자동으로 늦추는 적응형 백오프를 구현해야 한다. 상대 서버 가용성을 해치는 수집은 기술 문제이자 법적 분쟁의 원인이 되므로, 예의 준수를 수집 시스템의 기본 요건으로 둔다.

## Ⅶ. 결론

- 핵심 요약 : 웹 크롤링은 검색과 AI 시대의 데이터 확보 인프라이며, 예의와 품질 관리가 전제되는 기술.
- 시사점 : robots.txt 준수와 서버 예의, 중복과 노이즈 통제가 기술적·법적 리스크 관리의 출발점.
