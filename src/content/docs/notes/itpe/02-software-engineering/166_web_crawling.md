## 핵심 그림
```text
+-------------------------------------------------------------------------+
|                  대규모 분산 웹 크롤러(Web Crawler) 아키텍처            |
+-------------------------------------------------------------------------+
|                                                                         |
|      [ 시드 (Seed) URLs ]                                               |
|               │                                                         |
|               v                                                         |
|      +---------------------------------------------------------------+  |
|      | [ URL 프론티어 (URL Frontier) ]                               |  |
|      |  - 우선순위 큐 (PageRank 기반)                                 |  |
|      |  - 예의 큐 (Politeness: 동일 도메인 초당 요청 제한)           |  |
|      +───────────────────────┬───────────────────────────────────────+  |
|                              │ URL 인출                                 |
|                              v                                          |
|                     [ HTML 다운로더 (Fetcher) ]                         |
|                     - DNS 캐시 / HTTP 통신 / 헤드리스 브라우저(Playwright)|
|                              │                                          |
|                              v                                          |
|                     [ 문서 파서 (HTML Parser) ]                         |
|                              │                                          |
|             ┌────────────────┴────────────────┐                         |
|             v (데이터 추출)                   v (신규 링크 추출)         |
|      [ 데이터 저장소 ]                [ 중복 필터 (Bloom Filter) ]      |
|      (검색 색인, DB)                  - 이미 방문한 URL 필터링          |
|                                               │ (새로운 URL)            |
|                                               └──────> [ URL 프론티어 ] |
+-------------------------------------------------------------------------+
```

## 핵심 용어
- URL 프론티어(URL Frontier): 크롤러가 앞으로 다운로드해야 할 URL 목록을 보관하는 핵심 큐 모듈로, 탐색 우선순위(Priority)와 대상 서버에 과부하를 주지 않는 예의(Politeness)를 통제함
- 블룸 필터(Bloom Filter): 방문한 수억 개의 URL을 메모리 효율적으로 관리하기 위해 해시 함수와 비트 배열을 사용하여 "이미 수집된 URL인지" $O(1)$로 판별하는 확률적 자료구조

## 핵심 통찰
- 현대 웹은 React, Vue 기반의 SPA(Single Page Application)가 대세이므로, 단순 HTTP GET으로 HTML 텍스트만 긁으면 빈 껍데기(`<div></div>`)만 수집되며 반드시 V8 자바스크립트 엔진을 돌리는 헤드리스 브라우저(Puppeteer, Playwright)가 필요함
- 크롤러 엔지니어링의 핵심은 속도가 아니라 "예의(Politeness)"에 있으며, 대상 서버의 `robots.txt` 규약을 준수하고 동일 호스트에 대한 요청 딜레이를 두지 않으면 DoS 공격으로 간주되어 WAF에 IP가 차단되거나 형사 고발당함
- 국내 법원 판례(야놀자 vs 여기어때, 잡코리아 vs 사람인)에 따라 공개된 웹 데이터라 하더라도 경쟁사의 상당한 투자로 구축된 데이터베이스를 무단 크롤링하여 영업에 활용하면 부정경쟁방지법 위반으로 손해배상 책임이 인정됨

## 이웃 토픽과 구분
- 웹 크롤링(Web Crawling) vs 웹 스크래핑(Web Scraping): 크롤링 = 링크를 타고 웹 전체를 광범위하게 "탐색하고 인덱싱"하는 행위 / 스크래핑 = 특정 웹페이지의 특정 데이터 필드(상품 가격, 리뷰)를 "정밀 추출"하는 행위

## 문제·원인·대책
- 적용 상황: 대규모 이커머스 가격 비교 서비스 데이터 수집 엔진
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 크롤러가 타깃 사이트의 링크를 타고 돌다가 캘린더/무한 페이지 링크에 갇혀 무한 루프 | 크롤링 덫(Spider Trap) 및 동적 URL 파라미터 중복 탐색 방어 기제 부재 | URL 정규화(Canonicalization) 및 최대 탐색 깊이(Max Depth) 제한 설정 | 크롤러 자원 낭비 방지 및 안정적 순회 |
| 수집 대상 사이트의 Cloudflare/Akamai WAF에 의해 크롤러 IP가 전면 차단됨 | 짧은 시간에 단일 IP로 대량의 요청을 전송하여 비정상 봇으로 탐지됨 | 프록시 IP 로테이션 풀 구축, 요청 딜레이 랜덤화 및 User-Agent 헤더 회전 | 차단율 95% 감소 및 안정적 수집 지속 |
