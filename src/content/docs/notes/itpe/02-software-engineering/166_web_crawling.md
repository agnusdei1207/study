## 지식 로드맵 내 현재 위치

소프트웨어공학 → 데이터 수집 → **웹 크롤링**

## 30초 인출

- **본질** : 웹 크롤링은 시작 URL에서 페이지를 가져오고 링크를 따라가며 정해진 범위의 웹 자원을 자동 수집하는 활동
- **메커니즘** : 수집 대상 관리 → 접근 규칙 확인 → 페이지 요청·분석 → 신규 URL 선별 → 반복
- 통찰: 한계: 링크를 무제한 따라가면 중복·과도 요청이 발생함 → 방안: 방문 URL과 호스트별 요청 간격을 관리하며 허용 범위만 수집

<details>
<summary>핵심 용어</summary>

- **시드 URL(Seed URL)** : 크롤링을 시작할 때 입력하는 주소
- **URL 프론티어(URL Frontier)** : 앞으로 방문할 URL의 우선순위·요청 간격 등을 관리하는 대기열
- **중복 제거(Deduplication)** : 이미 방문했거나 같은 콘텐츠를 가리키는 URL의 재수집 억제
- **robots.txt** : 사이트가 크롤러에 접근 허용·제한 경로를 알리는 파일; 접근 통제·저작권 허가를 대신하지는 않음
- **웹 스크래핑(Web Scraping)** : 특정 페이지에서 필요한 데이터 항목을 추출하는 처리
- **블룸 필터(Bloom Filter)** : 적은 메모리로 집합 포함 가능성을 검사하는 확률적 자료구조; 거짓 양성 가능성 존재

</details>

## 2~4교시 25점 답안

## Ⅰ. 웹 크롤링의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **웹 크롤링** 은 시작 URL에서 페이지를 가져오고 링크를 따라가며 웹 자원을 자동 수집하는 활동 |
| 목적 | 정해진 범위의 웹 페이지를 검색·분석 등에 활용할 수 있도록 수집 |

## Ⅱ. 웹 크롤링의 특징

| 특징 | 수집상 의미 |
|---|---|
| 링크 기반 확장 | 시드 URL에서 발견한 링크가 다음 수집 후보가 됨 |
| 범위·순서 제어 | 프론티어에서 URL 우선순위와 호스트별 요청 간격 관리 |
| 반복과 중복 발생 | URL 별칭·순환 링크를 정규화와 방문 기록으로 통제 |
| 접근 정책 의존 | 사이트 접근 규칙과 데이터 활용 조건을 구분해 확인 |

## Ⅲ. URL 프론티어 중심 수집 체계와 순회 프로세스

```text
시드 URL → URL 프론티어 ─접근 규칙·요청 간격 확인→ 다운로더
                ↑                                      ↓
     신규 URL만 재투입 ← 링크 추출·정규화 ← 응답·페이지 저장
                └──────── 수집 범위·방문 여부 판정 ────────┘
```

| 구성요소 | 역할 |
|---|---|
| **URL 프론티어** | 방문 대상의 우선순위와 호스트별 요청 간격 관리 |
| 다운로더 | 허용된 URL에 요청하고 응답·오류 기록 |
| 파서·링크 추출기 | 문서에서 필요한 콘텐츠와 다음 URL 추출 |
| 중복·범위 판정기 | 이미 방문한 URL과 수집 범위 밖 URL 제외 |
| 저장소 | 페이지·메타데이터·수집 상태 보관 |

### URL 재투입과 호스트별 요청 통제

```text
발견 URL → 정규화 → 수집 범위 밖? ─예→ 제외
                       └아니요→ 방문 기록 있음? ─예→ 제외
                                            └아니요→ 호스트별 대기열
                                                     ↓ 요청 간격 도달
                                                  방문 예약·수집
```

호스트별 대기열을 나눠도 요청 간격과 동시성 제한은 모든 작업자에 일관되게 적용한다.

## Ⅳ. 웹 스크래핑과의 관계 및 규모별 선택

| 구분 | 웹 크롤링 | 웹 스크래핑 |
|---|---|---|
| 초점 | URL을 발견하고 페이지를 수집 | 수집한 페이지에서 필요한 데이터 추출 |
| 연결 | 수집 결과를 추출 단계에 전달 | 수집한 문서에서 항목을 가공; 같은 파이프라인에서 함께 사용 가능 |

### 규모 확장 시 선택

| 요구 | 설계 선택 | 유의점 |
|---|---|---|
| 대상 URL 증가 | 프론티어 분할·작업자 병렬화 | 호스트별 요청 제한의 일관성 |
| 동적 페이지 수집 | 필요한 경우 브라우저 렌더링 | 실행 비용과 접근 정책 확인 |
| 반복 수집 | 변경된 페이지 우선 방문 | 최신성·수집 비용의 균형 |

모든 사이트에 헤드리스 브라우저를 적용하거나 특정 저장소·도구를 필수 구성으로 고정하지 않고 수집 대상에 맞게 선택.

**블룸 필터** 는 방문 URL의 중복 후보를 메모리 효율적으로 찾지만 거짓 양성이 있다. **robots.txt** 는 접근 경로를 알리는 수단이며 데이터 이용 허가와 구분한다.

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 링크를 무제한 따라가 중복·무관 페이지가 증가 | URL 정규화·방문 기록·범위 정책으로 재투입 전 제외 |
| 병렬 수집으로 특정 사이트에 요청 집중 | 호스트별 요청 간격·동시성 제한과 오류율 감시 |
| 블룸 필터 거짓 양성으로 일부 URL 누락 가능 | 누락이 허용되지 않으면 정확한 URL 저장소 조회와 조합 |
| 수집 성공을 데이터 활용 허가로 오인 | 접근 규칙과 저장·재이용 조건을 별도로 확인 |

## Ⅵ. 제언

중복과 요청 집중은 수집 규모가 커질수록 증폭된다. 먼저 수집 범위·URL 정규화·호스트별 요청 상한을 프론티어에 적용하고, 누락·오류·응답 지표를 확인하며 대상을 확대한다.
