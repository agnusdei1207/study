## 핵심 용어
- RUM(Real User Monitoring): 실제 웹사이트에 접속한 수많은 최종 사용자의 브라우저에서 발생하는 로딩 속도, 지연, 에러 데이터를 자바스크립트 SDK로 실시간 수집하여 분석하는 기법
- 성능 예산(Performance Budget): 웹 페이지가 초과해서는 안 되는 성능 지표의 상한선(예: 총 번들 크기 250KB 이하, LCP 2.0초 이하)을 사전 합의하고 이를 넘으면 배포를 차단하는 규칙

## 핵심 통찰
- 웹 성능 최적화(Optimization)가 특정 시점의 "일회성 튜닝 기술"이라면, 웹 성능관리(Management)는 튜닝된 성능이 훼손되지 않도록 프로세스와 모니터링을 통해 지속적으로 통제하는 "상시적 거버넌스"임
- Synthetic(가상 모니터링)은 동일한 네트워크/기기 조건에서 베이스라인 추세를 측정하여 배포 전후의 회귀(Regression)를 잡는 데 탁월하고, RUM은 다양한 실제 통신망과 기기를 쓰는 고객의 현장 문제를 파악하는 데 필수적이므로 두 기법을 반드시 병행해야 함
- 프론트엔드 모니터링(RUM)과 백엔드 모니터링(APM)이 분리되어 있으면 "서버는 빠른데 사용자는 느리다고 항의하는" 사각지대가 발생하므로 W3C Trace Context를 통해 단일 트랜잭션으로 통합 추적해야 함

## 이웃 토픽과 구분
- 웹 성능 최적화 vs 웹 성능관리: 최적화 = 기술적 코드 튜닝 및 리소스 경량화 행위 / 관리 = 지표 수립, 상시 모니터링, 성능 예산 통제, 조직적 개선 프로세스 운영
