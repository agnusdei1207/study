## 한 줄 본질
- 디바이스마다 PC용 웹(`www.site.com`)과 모바일용 웹(`m.site.com`)을 따로 개발하여 발생하는 콘텐츠 이중 관리 비용과 SEO 점수 분산 병목 → 단일 HTML 소스에서 CSS3 미디어 쿼리와 가변 비율(%, vw/vh)을 활용하여 화면 크기에 따라 UI 레이아웃이 유연하게 리플로우(Reflow)되도록 하는 웹 프론트엔드 기법 / 모바일 리소스 과다 로딩 제어 필요

## 핵심 그림
```text
+-------------------------------------------------------------------------+
|                  반응형 웹 디자인(RWD) 3대 핵심 기술 메커니즘           |
+-------------------------------------------------------------------------+
| [ 1. 뷰포트 (Viewport Meta Tag) ]                                       |
|    <meta name="viewport" content="width=device-width, initial-scale=1.0">|
|                                    │                                    |
| [ 2. 가변 그리드 (Fluid Grid) ]    │ [ 3. 유연한 이미지 (Fluid Image) ]  |
|    - 픽셀(px) 대신 백분율(%),     │    - max-width: 100%;              |
|      CSS Grid, Flexbox 사용        │      height: auto;                 |
|                                    │    - 컨테이너 너비에 맞춰 자동 축소|
|                                    v                                    |
| [ 4. 미디어 쿼리 (Media Queries) - 화면 중단점(Breakpoints) 제어 ]       |
|    @media screen and (max-width: 768px) {                               |
|        /* 모바일 레이아웃: 1컬럼 수직 스택, 햄버거 메뉴 */              |
|    }                                                                    |
|    @media screen and (min-width: 769px) and (max-width: 1024px) {       |
|        /* 태블릿 레이아웃: 2컬럼 그리드 */                              |
|    }                                                                    |
|    @media screen and (min-width: 1025px) {                              |
|        /* 데스크톱 레이아웃: 3~4컬럼, 상단 네비게이션 풀 펼침 */        |
|    }                                                                    |
+-------------------------------------------------------------------------+
```

## 핵심 용어
- 미디어 쿼리(Media Query): 디바이스의 화면 해상도(width, height), 화면 비율, 방향(가로/세로) 등의 미디어 특성을 감지하여, 특정 조건이 만족될 때만 해당 CSS 스타일 블록을 적용하는 CSS3 모듈
- 중단점(Breakpoints): 화면 레이아웃이 구조적으로 바뀌는 기준 해상도(예: 모바일 < 768px, 태블릿 768~1024px, 데스크톱 > 1024px)를 의미하며, 디바이스 기종이 아닌 콘텐츠의 자연스러운 흐름을 기준으로 설정

## 핵심 통찰
- 데스크톱 화면을 먼저 만들고 화면을 줄여나가는 '데스크톱 우선' 방식은 모바일에서 불필요한 무거운 CSS와 스크립트를 다운로드하게 만드므로, 가장 제약이 큰 모바일을 먼저 설계하고 점진적으로 향상시키는 '모바일 우선(Mobile First)'이 원칙임
- 반응형 웹은 단일 URL을 공유하므로 구글 검색 엔진(Googlebot) 크롤링 효율이 극대화되고 백링크가 집중되어 검색 엔진 최적화(SEO)에서 적응형 웹(AWD)을 압도함
- 하지만 CSS로 화면에서 이미지를 `display: none`으로 숨기더라도 브라우저는 네트워크상에서 해당 고해상도 이미지를 그대로 다운로드하므로, HTML5 `<picture>` 태그와 `srcset` 속성을 통한 반응형 이미지 서빙이 필수적임

## 이웃 토픽과 구분
- 반응형 웹(RWD) vs 적응형 웹(AWD): RWD = 클라이언트 브라우저가 화면 크기에 맞춰 CSS로 유연하게 리사이징(단일 HTML) / AWD = 웹 서버가 User-Agent를 판별하여 모바일 전용 HTML/CSS와 PC 전용 템플릿을 완전히 분리 전달

## 문제·원인·대책
- 적용 상황: 글로벌 사용자 대상의 반응형 이커머스 쇼핑몰 구축
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 3G/LTE 환경의 모바일 사용자가 첫 페이지 진입 시 로딩 시간이 5초 이상 소요 | PC용 4K 고용량 배너 이미지를 모바일에서도 그대로 다운로드 | HTML5 `<picture>` 태그 및 `srcset`으로 디바이스 해상도별 WebP 서빙 | 모바일 초기 데이터 전송량 75% 절감 및 LCP 1.5초 달성 |
