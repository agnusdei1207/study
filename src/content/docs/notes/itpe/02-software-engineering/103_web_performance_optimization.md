## 연관 키워드

- 웹 성능 최적화(Web Performance Optimization), Core Web Vitals, LCP, INP, CLS
- 중요 렌더링 경로, 지연 로딩, CDN(Content Delivery Network), RUM(Real User Monitoring)

## Ⅰ. 웹 성능 최적화의 개요

- 핵심 요약 : 웹 성능 최적화는 로딩 속도·입력 반응성·화면 안정성을 측정 기반으로 개선하는 활동.
- 개념 : 페이지 자원의 전송·로딩·실행 방식을 조정해 빠른 표시와 안정적인 화면을 만드는 작업을 **웹 성능 최적화** (Web Performance Optimization)라 하고, 사용자 경험을 대표하는 지표 묶음인 **Core Web Vitals** (구글이 정의한 사용자 경험 핵심 성능 지표 체계)에 **LCP** (Largest Contentful Paint), **INP** (Interaction to Next Paint), **CLS** (Cumulative Layout Shift)가 포함된다.
- 배경 및 필요성 : 페이지당 자원 수·스크립트 규모가 증가하면서 느린 로딩과 레이아웃 이동이 이탈 증가·전환 저하·접근성 문제로 이어지는 상황이 존재.
- 주요 목적 : 사용자 체감 반응성 확보를 통한 이탈 감소와 전환 개선, 배포 이후에도 성능 수준을 유지하는 조직 성과 달성.

## Ⅱ. 웹 성능 최적화의 특징 및 장점

- 핵심 요약 : 전송·로딩·렌더링·실행의 계층별 개선 기법이 체감 반응성이라는 장점으로 연결.

1. 전송 최적화 : 압축·캐시·**CDN** (Content Delivery Network, 사용자 인근 지점에서 자원을 전달하는 배포망) 적용 → 자원 도착 시간 단축 효과.
2. 중요 렌더링 경로 단축 : **중요 렌더링 경로** (Critical Rendering Path, 브라우저가 첫 화면을 표시까지 거치는 자원 처리 경로)의 차단 자원 최소화 → 첫 표시 시점 앞당김 효과.
3. 자원 로딩 제어 : **지연 로딩** (Lazy Loading, 필요 시점에 자원을 불러오는 방식)·코드 분할·이미지 형식·크기 조정 → 초기 불필요 자원 감소 효과.
4. 실행 비용 관리 : 긴 작업 분할과 메인 스레드 점유 감소 → 입력에 대한 반응 지연 감소 효과.
5. 레이아웃 안정화 : 이미지·광고 영역의 공간 사전 확보 → 화면 요소 이동 감소 효과.

## Ⅲ. 웹 성능 최적화의 구조 (흐름)

- 핵심 요약 : 목표 정의→측정→병목 식별→개선→재측정·회귀 감시의 순환과, 로딩·반응·안정성 세 지표의 대응 구조.

```text
[측정·개선 순환]

사용자 경험 목표 정의
   ↓
현장·실험실 측정
   ↓
병목 식별 (전송·렌더링·실행)
   ↓
개선 기법 적용
   ↓
재측정·회귀 감시
```

```text
[Core Web Vitals 지표 구조]

로딩 - LCP (주요 콘텐츠 표시)
   ↓
반응 - INP (입력부터 다음 갱신)
   ↓
안정성 - CLS (레이아웃 이동 누적)
```

- 측정은 실제 사용자 데이터인 **RUM** (Real User Monitoring)과 재현 가능한 실험실 측정을 병행하며, 평균만 보면 느린 구간 사용자의 경험이 가려지므로 분포 기준으로 판단한다.

## Ⅳ. 웹 성능 최적화 적용 화면과 최적화 없는 기본 구현의 비교

- 핵심 요약 : 측정과 기법이 적용된 구현과 자원 위주의 기본 구현 사이의 대척 비교.

| 비교 축 | 웹 성능 최적화 적용 화면 | 최적화 없는 기본 구현 |
| --- | --- | --- |
| 자원 전송 | 압축·캐시·CDN 활용 | 원본 자원 반복 전송 |
| 초기 표시 | 중요 자원 우선 로딩 | 전체 자원 직렬 로딩 |
| 입력 반응성 | 긴 작업 분할로 메인 스레드 여유 확보 | 스크립트 점유로 입력 지연 |
| 화면 안정성 | 공간 사전 예약 | 표시 시점마다 레이아웃 이동 |
| 관측 체계 | 지표 측정·회귀 감시 | 문제 발견이 사용자 불만 의존 |

## Ⅴ. 웹 성능 최적화의 한계와 방안

- 핵심 요약 : 기법 상충·회귀·측정 격차·제3자 스크립트를 통합 측정과 예산 관리로 통제하는 원칙.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 기법 상충 | 지연 로딩·분할이 요청 연쇄를 늘림 → 체감 개선 제한 | 대표 화면 기준 통합 측정 후 적용 | LCP |
| 성능 회귀 | 배포마다 자원·작업 증가 → 개선 상실 | 성능 예산과 배포 게이트 운영 | 예산 초과 배포 건수 |
| 측정 격차 | 실험실·현장 조건 차이 → 판단 왜곡 | RUM과 실험실 측정 병행 대조 | 현장-실험실 격차 |
| 제3자 스크립트 | 광고·분석 태그의 메인 스레드 점유 | 로딩 정책·소유자별 부담 관리 | 메인 스레드 점유 시간 |

## Ⅵ. 웹 성능 최적화에 대한 기술사적 제언

- 핵심 요약 : 성능 예산·배포 게이트·관측 표준을 제품 개발 체계에 제도화하는 방향.
- 제도화 : 개발 조직이 페이지별 성능 예산을 정의하고 빌드·배포 파이프라인에 회귀 검사 게이트를 편입.
- 관측 표준 : 운영 조직이 RUM 수집 표준(개인정보 최소화·표본 기준)과 대시보드·알림 체계를 상시 운영.
- 변경 통제 : 제품 조직이 성능 목표를 기능 요구사항과 동일한 검토·승인 대상으로 관리하는 개발 문화 정착.

## Ⅶ. 결론

- 핵심 요약 : 웹 성능은 로딩을 넘어 반응성과 화면 안정성을 포함하는 사용자 경험 품질.
- 시사점 : 실사용 관측과 원인 재현을 결합한 지속 측정 체계가 최적화의 근거.
