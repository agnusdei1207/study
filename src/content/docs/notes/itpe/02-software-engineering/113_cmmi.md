## 연관 키워드

- CMMI, 능력 성숙도 통합 모델, 성숙도 수준, 능력 수준, 프로세스 영역, SCAMPI, 단계 표현, 연속 표현

## Ⅰ. CMMI의 개요

- 핵심 요약 : CMMI는 조직의 프로세스 역량을 수준으로 진단하고 단계적 개선으로 연결하는 통합 모델이자 평가 체계.
- 개념 : 조직의 프로세스 성숙도와 프로세스 수행 능력을 수준으로 정의하고 개선 경로를 제시하는 프로세스 개선 모델이자 평가 체계인 능력 성숙도 통합 모델 (**CMMI**, Capability Maturity Model Integration).
- 배경 및 필요성 : 프로젝트별 임기응변에 의존하면 품질·일정·비용의 편차가 커지므로, SW-CMM 등 분야별 성숙도 모델을 통합한 조직 차원의 공통 기준 필요, 현재 전문 협회 ISACA가 모델을 관리하며 V3.0 등으로 지속 개정.
- 주요 목적 : 프로세스의 예측 가능성과 제품·서비스 품질 확보, 조직 성과의 지속적 개선 제도화.

## Ⅱ. CMMI의 특징 및 장점

- 핵심 요약 : 수준 정의·영역 구조·공식 평가의 결합이 개선 방향 제시와 객관적 진단이라는 장점으로 연결.

1. **성숙도 수준** (Maturity Level) : 조직 전체 프로세스를 다섯 단계로 구분해 발전 정도를 판정 → 조직 개선 로드맵과 대외 신뢰 확보.
2. **능력 수준** (Capability Level) : 개별 **프로세스 영역** (Process Area)의 수행 역량을 별도 척도로 평가 → 전면 평가 이전의 선택적 개선 가능.
3. 영역별 실천 구조 : 요구사항 관리·계획·측정·품질 보증 같은 개선 주제를 목표와 실천 항목으로 구조화 → 개선 활동의 추진 체계 제공.
4. 공식 평가 방법 : **SCAMPI** (Standard CMMI Appraisal Method for Process Improvement) 방식으로 표본 프로젝트의 문서·수행 증거를 검증 → 등급의 객관성·재현성 확보.

## Ⅲ. CMMI의 구조 (흐름)

- 핵심 요약 : 단계 표현은 조직 전체를 성숙도 수준으로, 연속 표현은 영역별 능력 수준으로 판독하며 개선은 진단→실행→재평가 순환.

```text
[ 성숙도 수준 단계 구조 ]

L5 최적화 - 개선 프로세스의 정량 관리
   ↑
L4 정량적 관리 - 성과의 통계적 통제
   ↑
L3 정의 - 조직 표준 프로세스 자산화
   ↑
L2 관리 - 프로젝트 단위 계획·통제
   ↑
L1 초기 - 결과의 예측·재현 곤란
```

```text
사업 목표·성과 문제 정의
   ↓ 개선 범위·적용 영역 확정
증거 기반 갭 진단
   ↓ 우선순위 지정
개선 실행 - 교육·시범 프로젝트
   ↓ 수행 증거 축적
공식 평가 - 수준 판정
   ↓ 미충족 항목 개선 루프
```

- **단계 표현** (Staged Representation)과 **연속 표현** (Continuous Representation)은 같은 모델을 조직의 단계와 영역별 역량으로 읽는 두 관점이며, 적용 버전에 따라 제공 형태가 다름.
- 평가는 문서의 존재가 아니라 실제 수행과 성과를 뒷받침하는 증거 검토를 전제.

## Ⅳ. CMMI와 성숙도 미평가 프로세스 관행의 비교

- 핵심 요약 : 성숙도 미평가 관행이 경험 의존의 개선인 반면, CMMI는 수준 정의와 객관 평가로 개선을 체계화.

| 비교 축 | CMMI 성숙도 기반 관리 | 성숙도 미평가 프로세스 관행 |
| --- | --- | --- |
| 개선 기준 | 모델의 수준 정의·실천 항목 | 담당자 경험·프로젝트별 시행착오 |
| 수준 판단 | 공식 평가에 의한 객관적 등급 | 자체 판단, 검증 절차 부재 |
| 경영 활용 | 수준 갭 기반 투자·개선 우선순위 | 사례 보고 중심, 비교 기준 부재 |
| 지속성 | 수준 갭 로드맵의 반복 운영 | 인력 교체 시 개선 단절 위험 |

## Ⅴ. CMMI의 한계와 방안

- 핵심 요약 : 등급 취득형 형식주의와 절차 부담은 성과 연계·경량 적용·릴리스 리드타임 관리로 완화 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 등급 취득형 형식주의 | 평가 대비 문서 양산이 실질 개선 대체 | 개선 목표를 결함·재작업·납기 성과와 연결 | 성과 지표 달성률 |
| 절차 부담·애자일 마찰 | 일률적 문서 요구의 가중 | 리스크 기반 범위·경량 산출물 허용 | 산출물 유지 비용 |
| 릴리스 리드타임 증가 | 승인·증거 계층의 누적 | 병렬 승인·증거의 상시 축적 전환 | 릴리스 소요 기간 |
| 평가 시점 편향 | 단기 준비 활동이 평소 수행을 가림 | 표본 선정 투명화·상시 증거 운영 | 표본·상시 증거 일치도 |
| 버전·범위 혼용 | 모델 버전과 평가 기준 불일치 | 계약서에 버전·적용 범위 명시 | 기준 불일치 건수 |

## Ⅵ. CMMI에 대한 기술사적 제언

- 핵심 요약 : 경영진 주도의 개선 조직과 수명 주기 통합으로 CMMI를 등급 취득이 아닌 상시 운영 체계로 내재화 필요.
- 발주·수주 조직은 공급망 전체의 프로세스 역량을 계약·협력사 평가 요건에 반영해 개선 문화를 확산.
- 개선 전담 조직(EPG, Engineering Process Group)은 수주→개발→운영을 잇는 애플리케이션 수명 주기 관리(ALM, Application Lifecycle Management) 도구와 프로세스 자산을 연계해 개선 활동을 일상 업무에 통합.

## Ⅶ. 결론

- 핵심 요약 : CMMI는 조직의 프로세스 역량을 수준으로 진단하고 지속적 개선을 구조화하는 통합 모델·평가 체계.
- 성공의 판단 기준은 등급 자체가 아니라 실무에 정착한 프로세스와 측정 가능한 성과 개선.
