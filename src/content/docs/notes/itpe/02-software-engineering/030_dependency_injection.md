## 연관 키워드
- 의존성 주입(DI), IoC, 생성자 주입, 세터 주입
- DIP, 테스트 대역, 결합도

## Ⅰ. 의존성 주입의 개요

- 핵심 요약 : 의존성 주입은 객체가 의존 객체를 외부에서 전달받도록 해 생성 책임과 사용 책임을 분리하는 설계 기법.
- 개념 : **의존성 주입**(Dependency Injection, DI)은 객체가 필요한 의존 객체를 내부에서 생성하지 않고 외부 조립기가 생성자·세터 등으로 전달하는 설계 기법.
- 배경 및 필요성 : 객체 내부의 직접 생성은 구현 클래스와의 강한 **결합도**(Coupling, 모듈 간 상호 의존 정도)를 유발해 교체·시험·구성 변경 비용 증가.
- 주요 목적 : 낮은 결합도 기반의 변경 용이성과 시험 용이성 확보.

## Ⅱ. 의존성 주입의 특징 및 장점

- 핵심 요약 : 제어 역전 실천·주입 방식 선택·추상 의존·대역 교체가 변경 용이성의 원천.

1. 제어 역전 실천 : 생성·조립 책임을 사용자 코드에서 조립기로 이동 → **IoC**(Inversion of Control, 제어 역전) 원칙의 구체적 구현.
2. 주입 방식 선택 : **생성자 주입**(필수 협력자를 생성 시점에 확정)·**세터 주입**(선택적 의존성 변경) → 객체 성격에 맞는 연결.
3. 추상 의존 : **DIP**(Dependency Inversion Principle, 의존성 역전 원칙)에 따라 고수준 정책이 인터페이스에 의존 → 구현 교체가 정책에 영향 없음.
4. 시험 용이성 : 인터페이스 자리에 **테스트 대역**(Test Double, 실제 구현을 대신하는 시험용 객체) 주입 → 외부 시스템 격리 단위 시험.

## Ⅲ. 의존성 주입의 구조 (흐름)

- 핵심 요약 : 인터페이스 정의·바인딩 등록·생성 시점 전달의 절차와 추상 경계의 의존 구조.

```text
DI 적용 절차

인터페이스·구현 클래스 정의
   ↓
컨테이너에 구현체 바인딩 등록
   ↓
생성자로 의존성 전달·조립
   ↓
실행 시점 의존성 해결
```

```text
DIP 기반 의존 구조

상위 정책 (서비스 계층)
   ↓ 의존
추상 인터페이스 (역할 경계)
   ↓ 구현
하위 구현 (데이터 접근 계층)
```

- 주입 지점 : 조립기가 애플리케이션 기동 시점에 하위 구현을 인터페이스 자리에 연결.

## Ⅳ. 하드코딩 의존성과 의존성 주입의 비교

- 핵심 요약 : 하드코딩 의존성은 사용 객체가 구현을 직접 생성·결합하는 방식, 의존성 주입은 조립기가 추상 구현을 전달하는 방식.
- 비교 개요 : 하드코딩 의존성은 객체가 사용할 구현 클래스를 내부에서 직접 생성해 결합하는 관행.

| 비교 축 | 하드코딩 의존성 | 의존성 주입 |
|---|---|---|
| 생성 책임 | 사용 객체가 직접 생성 | 조립기·컨테이너가 생성·전달 |
| 결합 대상 | 구체 구현 클래스 | 추상 인터페이스 |
| 구현 교체 | 코드 수정·재컴파일 필요 | 설정·바인딩 변경으로 교체 |
| 단위 시험 | 실제 구현 강제·격리 곤란 | 테스트 대역 주입으로 격리 시험 |
| 의존성 가시성 | 객체 내부에 은닉 | 생성자 시그니처로 명시 |

## Ⅴ. 의존성 주입의 한계와 방안

- 핵심 요약 : 숨은 의존성·순환 의존·컨테이너 종속·구성 오류 지연을 주입 규칙과 구성 검증으로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 숨은 의존성 | 필드 주입·서비스 로케이터 사용 → 필수 협력자 불명확 | 필수 의존성의 생성자 주입 통일 | 생성자 주입 적용률 |
| 순환 의존 | 계층·책임 경계 붕괴 → 기동 오류 | 순환 참조 금지·계층 재설계 | 순환 의존 발견 건수 |
| 컨테이너 종속 | 도메인 코드의 프레임워크 API 사용 → 이식성 저하 | 프레임워크 사용을 조립 영역으로 격리 | 도메인 모듈 외부 의존 수 |
| 구성 오류 지연 노출 | 바인딩 오류가 실행 도중 발견 → 장애 확대 | 기동 시점 구성 검증·조기 실패 | 구성 오류 조기 발견율 |

## Ⅵ. 의존성 주입에 대한 제언

- 핵심 요약 : 설계 표준·조립 책임 단일화·역량 확산으로 DI를 조직 표준 관행으로 내재화.

1. 아키텍처 검토 조직은 인터페이스 중심 모듈 경계와 DI 적용 규칙을 코딩 표준·설계 가이드에 명문화.
2. 개발 조직은 객체 생성·설정 책임을 진입점의 단일 조립 영역으로 집중해 구성 관리 지점 최소화.
3. 교육·코드 리뷰 체계로 DIP 기반 설계 역량을 조직 차원에서 확산.

## Ⅶ. 결론

- 핵심 요약 : 의존성 주입은 생성과 사용의 책임 분리로 변경·시험 비용을 낮추는 제어 역전의 대표적 실천 기법.
- 추상에 대한 의존과 조립 책임의 분리가 유연한 모듈 구조의 기본 조건.
