## 연관 키워드

- EIP(Enterprise Integration Patterns), 메시지 채널(Message Channel), 메시지 라우터(Message Router)
- 메시지 변환기(Message Translator), 데드 레터 채널(Dead Letter Channel), 점대점 커스텀 인터페이스

## Ⅰ. EIP의 개요

- 핵심 요약 : EIP는 이기종 시스템을 메시지 기반으로 연결할 때 반복되는 통합 문제와 해법을 정리한 패턴 카탈로그.
- 개념 : 시스템 연계의 메시징 설계 문제와 검증된 해법을 패턴 언어로 정리한 카탈로그가 **EIP** (Enterprise Integration Patterns).
- 배경 및 필요성 : 시스템 쌍별 직접 연계는 형식 변환, 전송 보증, 오류 처리가 연동마다 중복되는 상태로 결합 확대와 운영 복잡성 증가.
- 주요 목적 : 메시지 흐름의 명시적 설계를 통한 시스템 간 결합 완화와 전달·오류 처리의 관리.

## Ⅱ. EIP의 특징 및 장점

- 핵심 요약 : 채널·엔드포인트·라우팅·변환·오류 격리 패턴의 조합이 메시지 흐름의 분리와 재사용으로 연결.

1. 메시지 채널 : 송신자와 수신자를 **메시지 채널** (Message Channel)로 분리 → 전송 기술 교체와 비동기 연계 효과.
2. 메시지 엔드포인트 : 애플리케이션과 메시징 계층의 접점인 **메시지 엔드포인트** (Message Endpoint)의 분리 → 통신 세부 사항의 캡슐화 효과.
3. 메시지 라우터 : 내용·헤더 조건으로 수신 경로를 결정하는 **메시지 라우터** (Message Router) → 분기 규칙의 명시적 관리 효과.
4. 메시지 변환기 : 이기종 형식·구조를 바꾸는 **메시지 변환기** (Message Translator) → 데이터 계약 연결 효과.
5. 데드 레터 채널 : 전달 불능 메시지를 격리·보존하는 **데드 레터 채널** (Dead Letter Channel) → 오류 조사·재처리 근거 확보 효과.

## Ⅲ. EIP의 구조 (흐름)

- 핵심 요약 : 송신 엔드포인트 → 채널 → 라우팅·변환 → 수신 엔드포인트의 흐름과 실패 메시지의 격리 경로.

```text
송신 애플리케이션
   ↓ 메시지 엔드포인트
메시지 채널
   ↓ 라우터의 수신 경로 선택
메시지 변환기
   ↓ 형식·구조 변환
수신 엔드포인트 → 수신 시스템
```

```text
전달 실패 메시지
   ↓ 재시도 한도 초과
데드 레터 채널 격리
   ↓ 원인 분석·수정
재처리 후 정상 경로 복귀
```

- 채널은 1:1 전달과 발행-구독(Publish-Subscribe) 방식으로 나뉘고, 최소 한 번(at-least-once) 전달 같은 보증 수준은 패턴이 아니라 메시징 미들웨어와의 계약으로 별도 정의.

## Ⅳ. EIP 기반 통합과 점대점 커스텀 인터페이스의 비교

- 핵심 요약 : 패턴 기반 통합은 채널·계약 경계로 결합을 낮추고 점대점 커스텀 인터페이스는 연동 수 증가에 따라 결합·중복이 확대.

| 비교 축 | EIP 기반 통합 | 점대점 커스텀 인터페이스 |
| --- | --- | --- |
| 연결 구조 | 공용 채널·패턴의 역할 분리 | 시스템 쌍별 전용 연동 |
| 결합도 | 채널 경계의 낮은 결합 | 연동 수 증가에 따른 결합 확대 |
| 변경 영향 | 계약·변환 경계의 격리 | 양쪽 시스템의 동시 수정 필요 |
| 오류 처리 | 데드 레터·재처리의 표준화 | 연동별 개별 구현 |
| 자산 재사용 | 채널·패턴 자산의 재사용 | 연동별 중복 구현 |

## Ⅴ. EIP의 한계와 방안

- 핵심 요약 : 비동기 메시징의 중복·순서·변환·추적 문제를 전달 의미 명시와 식별 체계로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 중복 전달 | 재시도·소비자 장애 → 처리 중복 | 멱등 처리·중복 제거 키 | 중복 처리 건수 |
| 순서 역전 | 병렬 소비·파티션 분산 → 정합성 훼손 | 키 기반 순서 범위 설계 | 순서 위반 건수 |
| 변환 오류 | 스키마 진화·필수값 불일치 → 메시지 폐기 | 스키마 버전 관리·검증·격리 큐 | 변환 실패 건수 |
| 장애 원인 추적 곤란 | 비동기 경계의 요청 맥락 분단 | 상관 식별자·분산 추적·재처리 이력 | 추적 미확보 건수 |

## Ⅵ. 통합 아키텍처에 대한 기술사적 제언

- 핵심 요약 : 플랫폼 조직은 데이터 계약·전달 보증·오류 큐 소유권의 표준화로 메시지 통합을 거버넌스 대상으로 관리 필요.
1. 플랫폼 조직은 메시지 스키마 호환 규칙, 전달 보증 수준, 재처리 승인 절차의 표준 정의.
2. 업무 시스템 소유 팀은 라우팅·변환 규칙마다 책임자를 두고 메시지 흐름의 관측 가능한 자산 등록.

## Ⅶ. 결론

- 핵심 요약 : EIP는 메시지 연계 문제를 공통 어휘와 검증된 설계 패턴으로 표현하는 통합 설계 지식.
- 시사점 : 전달·변환·오류 처리의 의미가 계약으로 명시될 때 결합 완화 효과의 실현.
