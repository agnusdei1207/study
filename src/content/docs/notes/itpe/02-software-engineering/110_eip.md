## 연관 키워드
- Enterprise Integration Patterns, 메시지 채널, 메시지 라우터, 변환기, Dead Letter Channel

### Ⅰ. 엔터프라이즈 통합 패턴의 개요

- 핵심 요약 : EIP는 이기종 시스템을 메시지 기반으로 연결 할 때 반복 되는 통합 문제와 해법을 정리한 패턴 카탈로그.
- 개념 : 이기종 시스템을 메시지 기반으로 연결 할 때 반복 되는 통합 문제와 해법을 정리한 패턴 카탈로그(**EIP**, Enterprise Integration Patterns).
- 배경 및 필요성 : 독립 시스템 간 데이터 형식·전송·오류 처리 차이는 점대점 연계의 결합과 운영 복잡성을 높임.
- 주요 목적 : 통합 흐름을 명시적 으로 설계 해 시스템 결합을 낮추고 메시지 전달을 관리.

### Ⅱ. 핵심 패턴과 장점

- 핵심 요약 : 채널·엔드포인트·라우팅·변환 패턴을 조합 해 메시지 흐름을 분리 하고 재사용.

1. Message Channel : 송신자와 수신자를 물리적으로 분리 → 전송 기술 교체와 비동기 연계 가능.
2. Message Router : 내용·조건에 따라 경로 선택 → 분기 규칙 중앙화.
3. Message Translator : 메시지 형식 변환 → 이기종 계약 연결.
4. Dead Letter Channel : 전달 불능 메시지 격리 → 오류 조사와 재처리 근거 보존.
5. Message Endpoint : 애플리케이션과 메시징 시스템의 접점 → 통신 세부 사항 캡슐화.

### Ⅲ. 패턴 조합 흐름 (구조)

- 핵심 요약 : 송신 애플리케이션의 엔드포인트가 채널에 메시지를 보내고 라우터·변환기·수신 엔드포인트가 처리.

```text
송신 애플리케이션
   ↓ Message Endpoint
Message Channel
   ↓ Router → Translator
수신 Endpoint → 대상 시스템
   ↓ 실패 메시지
Dead Letter Channel
```

```text
발행자 → 채널 → 구독자
           ↓ 필터·라우팅
        조건 별 소비자
```

- 패턴은 메시지 전달 보증, 순서, 중복, 재시도 정책을 대체 하지 않으므로 브로커와 애플리케이션 계약에서 함께 정의.

### Ⅳ. 통합 방식 비교

- 핵심 요약 : EIP는 패턴 언어 이며, 점대점·ESB·브로커는 연결 구조 또는 제품 아키텍처 선택.

| 비교 축 | 점대점 연계 | 메시지 패턴 기반 통합 | 중앙 ESB 중심 |
|---|---|---|---|
| 연결 구조 | 시스템 별 직접 연결 | 채널과 패턴으로 역할 분리 | 공통 버스에 연계 집약 |
| 결합·확장 | 연결 수 증가 시 결합 확대 | 패턴 재사용으로 흐름 분리 | 공통 기능 재사용, 중앙 의존 |
| 변경 영향 | 양쪽 시스템 연동 수정 필요 | 계약과 변환 경계에서 격리 | ESB 설정·용량 영향 주의 |
| 운영 초점 | 연결 별 모니터링 | 메시지 추적·재처리 | 중앙 장애·거버넌스 관리 |

### Ⅴ. EIP의 한계와 방안

- 핵심 요약 : 비동기 메시징은 중복·순서·추적 문제를 수반 하므로 전달 의미와 실패 경로를 명시.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 중복 전달 | 재시도·소비자 장애 | 멱등 처리와 중복 제거 키 | 중복 메시지 건수 |
| 순서 역전 | 병렬 소비·파티션 | 키 기반 순서 범위와 재정렬 전략 | 순서 위반 건수 |
| 변환 오류 | 스키마 진화·필수 값 불일치 | 스키마 버전·검증·격리 큐 | 변환 오류 건수 |
| 장애 원인 추적 곤란 | 비동기 경계에서 요청 맥락 분리 | 상관 ID·분산 추적·재처리 이력 | 추적 미확보 건수 |

### Ⅵ. 통합 아키텍처 제언

- 핵심 요약 : 아키텍트는 패턴 명칭 보 다 데이터 계약·전달 의미·운영 책임을 먼저 표준화.

1. 플랫폼 팀 은 메시지 스키마 호환 규칙, 오류 큐 소유자, 재처리 승인 절차를 정의.
2. 업무 팀 은 각 라우팅·변환 규칙에 책임자를 두고 메시지 흐름을 관측 가능한 자산으로 관리.

### Ⅶ. 결론

- 핵심 요약 : EIP는 메시지 연계 문제를 공통 어휘와 검증 된 설계 패턴으로 표현 하는 통합 설계 지식.
- 시사점 : 전달·변환·오류 처리 의 의미를 계약으로 명시 할 때 시스템 간 결합 완화에 기여.
