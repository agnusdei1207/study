## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 빌드·배포·DevOps → **데이터옵스(DataOps)**

## 30초 인출

- 본질: 데이터옵스는 데이터 파이프라인의 개발·시험·배포·운영에 DevOps의 자동화와 협업 원칙을 적용해 신뢰할 수 있는 데이터를 빠르게 제공하는 방식
- 메커니즘: 파이프라인 코드를 버전 관리하고 CI/CD로 시험·배포하면서 데이터 품질 검사와 모니터링을 파이프라인에 넣어 이상 데이터를 조기에 감지
- 통찰: 코드가 바뀌지 않아도 데이터 자체가 바뀌어 결과가 어긋나므로 코드 검증에 더해 데이터 품질 검사와 관측을 파이프라인에 넣어 이상을 소비자에게 닿기 전에 차단

<details>
<summary>핵심 용어</summary>

- **데이터옵스(DataOps)** : 데이터 파이프라인에 DevOps 원칙을 적용한 데이터 운영 방식
- **데이터 파이프라인(Data Pipeline)** : 데이터를 수집·변환·적재하는 처리 흐름
- **데이터 품질 검사** : 완전성·정확성·최신성 등을 자동으로 확인하는 검사
- **데이터 관측성(Data Observability)** : 데이터의 신선도·분포·볼륨 변화를 감시해 이상을 감지하는 역량
- **데이터 계보(Data Lineage)** : 데이터의 원천에서 최종 사용까지의 흐름 이력
- **데이터 계약(Data Contract)** : 생산자와 소비자가 데이터 형식·품질을 합의한 약속

</details>

## 2~4교시 25점 답안

## Ⅰ. 데이터옵스의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **데이터옵스** 는 데이터 파이프라인에 DevOps 원칙을 적용해 신뢰할 수 있는 데이터를 빠르게 제공하는 방식 |
| 목적 | 데이터 제공 주기 단축과 데이터 품질 확보 |

## Ⅱ. 데이터옵스의 특징

| 특징 | 의미 |
|---|---|
| 파이프라인 자동화 | 데이터 처리 흐름의 CI/CD |
| 데이터 품질 내장 | 품질 검사를 파이프라인에 포함 |
| 협업 | 데이터 엔지니어·분석가·운영자의 협업 |

## Ⅲ. 데이터옵스 구조와 운영 흐름

### 데이터옵스 파이프라인

```text
소스 데이터 → 수집 → 변환 → 품질 검사 → 적재 → 소비(분석·서비스)
          ↑                        │
          └── 관측·경보 (이상 시 차단·알림)
```

### 확대: 변경 반영 흐름

```text
파이프라인 코드 변경
    ↓ CI: 코드 시험 + 샘플 데이터 검증
    ↓ CD: 배포
    ↓ 운영: 데이터 품질 모니터링
```

## Ⅳ. 데브옵스와의 비교

| 구분 | 데브옵스 | 데이터옵스 |
|---|---|---|
| 대상 | 애플리케이션 코드 | 데이터 파이프라인과 데이터 |
| 품질 초점 | 코드 결함 | 코드 결함과 데이터 품질 |
| 검증 | 단위·통합 시험 | 코드 시험과 데이터 검사 |
| 운영 감시 | 서비스 지표 | 데이터 신선도·분포·볼륨 |
| 참여자 | 개발·운영 | 데이터 엔지니어·분석가·운영 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 코드는 정상이나 데이터 변화로 결과 이상 | 파이프라인 내 데이터 품질 검사 |
| 이상 원인 추적 곤란 | 데이터 계보 기록 |
| 생산자와 소비자 간 형식 변경 충돌 | 데이터 계약 합의 |

## Ⅵ. 제언

파이프라인 단계마다 데이터 품질 검사를 넣어 이상 데이터가 소비자에게 닿기 전에 차단하고, 계보로 원인 추적

### 품질 게이트

```text
변환 결과
    ↓
품질 검사 (완전성·범위·최신성)
    ├─ 통과 → 적재
    └─ 실패 → 적재 차단·알림·계보로 원인 추적
```

### 선택 근거: 사후 발견과의 비교

| 구분 | 사용자 신고로 사후 발견 | 제언: 파이프라인 내 검사 |
|---|---|---|
| 이상 발견 시점 | 소비 이후 | 적재 전 |
| 영향 범위 | 큼 | 차단 |
| 원인 추적 | 곤란 | 계보 활용 |
