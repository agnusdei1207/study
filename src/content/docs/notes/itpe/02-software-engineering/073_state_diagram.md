## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 모델링 → **상태 다이어그램(State Diagram)**

## 30초 인출

- 본질: 상태 다이어그램은 객체가 가질 수 있는 상태와 이벤트에 따른 상태 전이를 나타내는 UML 행위 다이어그램
- 메커니즘: 초기 상태에서 시작해 이벤트가 발생하면 가드 조건이 참일 때 액션을 수행하며 다음 상태로 전이하고 종료 상태에서 끝남
- 통찰: 전이 조건을 정하지 않으면 허용되지 않는 상태 변화가 생기므로 이벤트와 가드 조건으로 전이를 정의하고 상태별 가능한 전이를 표로 점검해 누락을 확인

<details>
<summary>핵심 용어</summary>

- **상태(State)** : 객체가 어떤 조건을 만족하며 머무는 시점
- **전이(Transition)** : 이벤트로 한 상태에서 다른 상태로 바뀌는 것
- **이벤트(Event)** : 전이를 일으키는 사건
- **가드 조건(Guard Condition)** : 전이가 일어나기 위해 참이어야 하는 조건
- **액션(Action)** : 전이나 상태에서 수행하는 동작
- **복합 상태(Composite State)** : 여러 하위 상태를 묶은 상위 상태
- **상태 폭발** : 상태와 전이 수가 조합으로 늘어나는 문제

</details>

## 2~4교시 25점 답안

## Ⅰ. 상태 다이어그램의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **상태 다이어그램** 은 객체의 상태와 이벤트에 따른 전이를 나타내는 UML 행위 다이어그램 |
| 목적 | 상태에 따라 동작이 달라지는 객체의 행위 규칙 명확화 |

## Ⅱ. 활동 다이어그램과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 객체 중심 | 한 객체의 생명주기 표현 |
| 이벤트 기반 | 이벤트가 상태 전이를 유발 |
| 조건부 전이 | 가드 조건으로 전이 제한 |

## Ⅲ. 구성 요소와 전이 구조

### 주문 객체의 상태 다이어그램

```text
(●) → [접수] ──결제 완료──→ [결제됨] ──출고──→ [배송 중] ──수령──→ [완료] → (◉)
        │                      │
        └────취소────────────→ [취소] → (◉)
```

### 확대: 전이의 표기

```text
이벤트 [가드 조건] / 액션
예) 결제 요청 [잔액 ≥ 금액] / 결제 처리
```

## Ⅳ. 구성 요소와 복잡한 상태의 표현

### 구성 요소

| 요소 | 의미 |
|---|---|
| 초기 상태 | 객체 생성 시 시작점(●) |
| 종료 상태 | 생명주기의 끝(◉) |
| 상태 | 객체가 머무는 시점 |
| 전이 | 이벤트·가드 조건·액션으로 표기한 상태 변경 |

### 복잡한 상태의 표현

| 기법 | 내용 |
|---|---|
| 복합 상태 | 공통 전이를 상위 상태로 묶어 표현 |
| 이력 상태 | 복합 상태 재진입 시 직전 하위 상태 복귀 |
| 병행 상태 | 동시에 유지되는 독립 상태 표현 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 허용되지 않는 전이의 누락·오류 | 상태별 가능한 이벤트를 표로 점검 |
| 상태·전이가 늘어 다이어그램 복잡 | 복합 상태로 계층화 |
| 가드 조건 누락으로 동작 모호 | 전이마다 이벤트와 조건을 명시 |

## Ⅵ. 제언

상태별로 발생 가능한 이벤트를 표로 점검해 허용·금지 전이를 확정하고, 복합 상태로 계층화해 복잡도 관리

### 전이 점검 절차

```text
상태 목록 작성
    ↓
상태 × 이벤트 표 작성
    ↓
허용 전이 정의, 금지 전이 확인
    ↓
다이어그램 반영
```

### 선택 근거: 다이어그램만 작성하는 방식과의 비교

| 구분 | 다이어그램만 | 제언: 상태×이벤트 표 병행 |
|---|---|---|
| 전이 누락 | 발견 곤란 | 표로 점검 |
| 금지 전이 | 불명확 | 명시 |
| 시험 케이스 | 추정 | 표에서 도출 |
