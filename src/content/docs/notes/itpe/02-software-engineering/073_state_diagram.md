## 30초 인출

- 본질: **상태 다이어그램(State Diagram)** 은 단일 객체가 생애주기 동안 수신하는 이벤트에 반응하여 상태를 변경하고 동작을 수행하는 과정을 유한 상태 머신(FSM) 기반으로 가시화한 UML 동적 행위 다이어그램
- 메커니즘: 외부 이벤트 발생 → 가드 조건 `[Guard]` 평가 → 유효 전이 실행 → 상태 전이 효과 및 액션(Entry/Do/Exit) 수행
- 통찰: 이벤트 중심 설계 시 가드 조건 누락으로 인한 불법 상태 전이와 상태 폭발 위험이 존재하므로 상태 전이표 기반 검증과 복합 상태 및 상태 패턴을 통한 계층적 캡슐화를 적용해야 안정적인 상태 전이 무결성을 확보할 수 있음

<details>
<summary>핵심 용어</summary>

- **유한 상태 머신(FSM)** : 유한한 수의 상태와 외부 입력에 따른 전이 및 동작을 수학적으로 정형화한 상태 전이 모델
- **가드 조건(Guard Condition)** : 전이 촉발 전 평가되어 반드시 참(True)이어야만 상태 변경을 허용하는 사전 논리식
- **상태 폭발(State Explosion)** : 시스템 복잡도 및 병렬 조건 증가로 인해 상태와 전이선의 조합 수가 기하급수적으로 폭증하는 현상
- **복합 상태(Composite State)** : 공통 전이와 내부 세부 동작을 묶어 상위 계층으로 캡슐화한 서브머신 상태
- **이력 의사 상태(History Pseudostate)** : 복합 상태 재진입 시 초기 상태 대신 직전의 활성 하위 상태를 기억하여 복원하는 의사 상태(H, H*)

</details>

## 2~4교시 예상문제 (25점)

> 상태 다이어그램의 개념과 상태·전이·이벤트·가드·액션의 관계를 설명하고, 대규모 복합 시스템 모델링 시 발생하는 상태 폭발(State Explosion) 문제 해결을 위한 계층적 상태 확장 기법 및 설계 고려사항을 제시하시오.

---

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 단일 객체의 생애주기 동안 외부 자극(Event)에 의해 발생하는 상태 변화와 제약 조건을 유한 상태 머신(FSM)으로 표현한 UML 행위 다이어그램 |
| 목적 | 상태 의존적 비즈니스 로직의 허용 조건 정형화, 불법 전이 방지, 이벤트 수신에 따른 생애주기 행위 검증 |

## Ⅱ. 핵심 특징

상태 다이어그램은 객체 내부의 데이터 변경을 단순 속성 수정이 아닌 시스템 상태 전이로 엄격히 통제하여 무결성을 보장.

| 구성요소 | 표기법 및 형식 | 역할 및 동작 규칙 |
|---|---|---|
| **상태 (State)** | 모서리가 둥근 사각형 | 객체가 특정 조건을 만족하거나 활동을 지속하는 존속 기간 (Entry, Do, Exit 명시) |
| **전이 (Transition)** | 실선 화살표 | 특정 이벤트 발생 시 활성 상태를 변경시키는 단방향 이동 경로 |
| **이벤트 (Event)** | 전이선 위 레이블 | 상태 전이를 유발하는 외부 자극 (Call, Signal, Time, Change Event) |
| **가드 조건 (Guard)** | `[Boolean 조건식]` | 전이가 실행되기 위해 참(True)이어야 하는 판정 조건 (거짓일 경우 이벤트 무시) |
| **액션 (Action)** | `/ Action()` | 전이 순간 즉시 실행되는 비인터럽트성 원자적 동작 |

- **상태 내부 활동 분리** : 진입 시 1회 실행되는 `entry /`, 지속적인 백그라운드 활동인 `do /`, 탈출 시 1회 실행되는 `exit /`로 구분하여 처리.
- **의사 상태(Pseudostate) 제어** : 시작(Initial), 종료(Final), 분기(Choice/Junction), 이력(History) 등의 제어 노드를 통해 복합 흐름 구조화.

## Ⅲ. 체계·프로세스

주문 처리 시스템을 예시로 한 상태 전이 체계 및 모델링 절차.

```text
[주문 객체 상태 머신 (Order FSM)]
                                                                                                           
  (●) 시작                                                                                                 
    │                                                                                                      
    │ 주문생성()                                                                                           
    ▼                                                                                                      
+-------------------+       결제승인 [재고유효] / 재고차감()        +-------------------+                  
|     주문대기      | ───────────────────────────────────────────> |     결제완료      |                  
| entry: 타이머시작 |                                              | entry: 영수증발행 |                  
+-------------------+                                              +-------------------+                  
    │                                                                        │                             
    │ 결제타임아웃 [미결제]                                                  │ 출고지시()                  
    │ / 주문취소()                                                           ▼                             
    │                                                              +-------------------+                  
    │                                                              |     배송준비      |                  
    │                                                              +-------------------+                  
    │                                                                        │                             
    │                                                                        │ 발송완료()                  
    │                                                                        ▼                             
    │                                                              +-------------------+                  
    │                                                              |      배송중       |                  
    │                                                              +-------------------+                  
    │                                                                        │                             
    │                                                                        │ 고객수령()                  
    │                                                                        ▼                             
    │                                                              +-------------------+                  
    │                                                              |     수령완료      |                  
    │                                                              +-------------------+                  
    │                                                                        │                             
    ▼                                                                        ▼                             
+-------------------+                                                      (◎) 종료                       
|     주문취소      | ───────────────────────────────────────────────────────┘                             
| entry: 자원반납   |                  반품승인() / 환불처리()                                             
+-------------------+                                                                                      
```

- **상태 다이어그램 설계 4단계 프로세스**:
  1. **대상 객체 식별** : 비즈니스 흐름 중 상태 변화가 중요하고 복잡한 핵심 도메인 객체 선정.
  2. **상태 및 이벤트 도출** : 객체의 생애주기 동안 가질 수 있는 안정적 상태와 자극 이벤트 정의.
  3. **가드 조건 및 액션 정의** : 각 전이의 성립 조건(`[Guard]`)과 상태 진입/탈출 시 실행될 부수 효과 명시.
  4. **상태 전이표 작성 및 정합성 검증** : 모든 상태와 이벤트의 교차 행렬을 통해 누락되거나 모순된 전이 검증.

## Ⅳ. 종류·비교

#### UML 주요 행위 다이어그램 간 비교

| 비교 항목 | 유스케이스 다이어그램 (Use Case) | 활동 다이어그램 (Activity) | 상태 다이어그램 (State Machine) |
|---|---|---|---|
| **모델링 관점** | 시스템 외부 요구사항 및 상호작용 (What) | 업무 처리 절차 및 제어 흐름 (How-Flow) | 단일 객체의 생애주기 및 상태 전이 (How-Lifecycle) |
| **핵심 초점** | 액터와 시스템 간의 기능적 경계 도출 | 작업 단계(Action), 분기, 병렬 동기화 | 이벤트, 가드 조건, 상태 의존적 동작 제약 |
| **적용 단위** | 시스템 전체 또는 서브시스템 단위 | 비즈니스 프로세스, 유스케이스 실체화 | 상태 의존성이 높은 특정 도메인 객체 |
| **주요 산출물** | 유스케이스 명세서 | 워크플로우 명세서, 트랜잭션 흐름도 | 상태 전이표(State Transition Matrix), FSM 코드 |

#### 대규모 상태 모델링 확장 기법 비교

| 확장 기법 | 메커니즘 | 해결 문제 | 적용 예시 |
|---|---|---|---|
| **복합 상태 (Composite State)** | 연관된 하위 상태들을 하나의 상위 상태로 묶어 계층화 | 전이선 중복 제거 및 관심사 분리 | '배송중' 상태 내 '간선수송', '집화처리' 캡슐화 |
| **직교 영역 (Orthogonal Region)** | 점선 구획을 통해 여러 하위 상태 머신을 병렬로 동시 수행 | 동시성 표현 및 조합 상태 폭발 방지 | 기기 동작 중 '전원 상태'와 '네트워크 연결 상태' 동시 표현 |
| **이력 의사 상태 (History State)** | 복합 상태 탈출 후 재진입 시 직전 활성 하위 상태로 복귀 | 상태 초기화 방지 및 인터럽트 복구 | 일시정지 후 작업 재개 시 이전 진행 세부 단계 복원 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 도메인 복잡도 증가 시 상태와 전이선의 수가 기하급수적으로 폭증하는 상태 폭발(State Explosion) 발생 | 복합 상태 계층화 및 직교 영역(Orthogonal Region) 분할을 통해 모델의 가독성과 유지보수성 확보 |
| 설계 단계의 상태 다이어그램과 실제 소스코드 간 불일치로 인한 전이 누락 및 불법 전이 버그 유발 | Spring StateMachine, XState 등의 상태 머신 프레임워크를 도입하여 상태 전이표와 코드를 동기화 |
| 복합 상태 내 다중 이벤트 경합 시 비결정적(Non-deterministic) 전이 발생 위험 | 이벤트 우선순위 정책 정의 및 상호 배타적 가드 조건 설계를 통해 결정론적 전이 규칙 보장 |

## Ⅵ. 제언

도메인 설계 초기 단계부터 상태 전이표를 기반으로 허용·불가 전이를 전수 검증하고, State 패턴 및 상태 머신 프레임워크 연계를 통한 모델-코드 일치성 확보

```text
[상태 다이어그램 설계] (UML FSM)
         ↓
[상태 전이 행렬 검증] (허용/예외 전이 전수 확인)
         ↓
[상태 머신 구현] (State 패턴 / Spring StateMachine)
         ↓
[전이 커버리지 테스트] (N-Switch Coverage 달성)
```

| 검증 및 구현 단계 | 수행 활동 | 핵심 관리 지표 |
|---|---|---|
| **설계 정형화** | 상태 전이표(State Transition Matrix) 매트릭스 도출 | 모든 상태-이벤트 쌍의 전이 유효성 100% 정의 |
| **코드 연계** | GoF State Pattern 또는 상태 머신 엔진 기반 구현 | if-else 분기 제거 및 상태별 행위 캡슐화 달성 |
| **테스트 검증** | 상태 전이 기반 테스트 설계(0-Switch, 1-Switch) | 상태 커버리지 및 유효/무효 전이 경로 전수 달성 |
