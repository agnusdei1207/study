## 30초 인출

- 본질: 알고리즘 복잡도는 입력 크기에 따라 알고리즘이 쓰는 시간과 메모리가 늘어나는 정도이며 O-notation은 그 증가율의 상한을 표기하는 방법
- 메커니즘: 연산 횟수를 입력 크기 n의 함수로 나타내고 상수와 낮은 차수를 버려 가장 빠르게 증가하는 항의 차수로 표기
- 통찰: 입력이 커지면 상수 차이보다 증가율의 차이가 결정적이므로 알고리즘은 증가율로 비교해 선택하되 실제 입력 규모에서 측정해 검증

<details>
<summary>핵심 용어</summary>

- **시간 복잡도(Time Complexity)** : 입력 크기에 따른 연산 수행 횟수의 증가 정도
- **공간 복잡도(Space Complexity)** : 입력 크기에 따른 추가 메모리 사용량의 증가 정도
- **빅오(Big-O, O)** : 증가율의 점근적 상한(최악 경계)
- **빅오메가(Big-Omega, Ω)** : 증가율의 점근적 하한
- **빅세타(Big-Theta, Θ)** : 상한과 하한이 같은 정확한 증가율
- **최선·평균·최악 복잡도** : 입력 조건에 따른 수행 시간의 경우 구분

</details>

## 2~4교시 25점 답안

## Ⅰ. 알고리즘 복잡도의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **알고리즘 복잡도** 는 입력 크기에 따라 알고리즘이 쓰는 시간과 메모리가 늘어나는 정도 |
| 목적 | 알고리즘 성능의 비교와 확장성 예측 |

## Ⅱ. 복잡도의 특징

| 특징 | 의미 |
|---|---|
| 입력 크기 기준 | 실행 환경이 아닌 입력 크기 n의 함수 |
| 증가율 중심 | 상수·낮은 차수 무시 |
| 경우별 구분 | 최선·평균·최악 |

## Ⅲ. O-Notation의 개념과 표기

### 표기 방법

```text
연산 횟수 f(n) = 3n² + 5n + 2
    ↓ 상수·낮은 차수 제거
O(n²)
```

### 확대: 점근 표기의 구분

```text
O(g): 상한  ── f(n)이 g(n)보다 빠르게 증가하지 않음
Ω(g): 하한  ── f(n)이 g(n)보다 느리게 증가하지 않음
Θ(g): 상한과 하한이 같음
```

## Ⅳ. O-Notation의 유형과 연산시간 차이

| 유형 | 이름 | 예 | n=10 | n=1,000 |
|---|---|---|---|---|
| O(1) | 상수 | 배열 인덱스 접근 | 1 | 1 |
| O(log n) | 로그 | 이진 탐색 | 약 3 | 약 10 |
| O(n) | 선형 | 순차 탐색 | 10 | 1,000 |
| O(n log n) | 선형 로그 | 병합 정렬 | 약 33 | 약 10,000 |
| O(n²) | 제곱 | 삽입 정렬(최악) | 100 | 1,000,000 |
| O(2ⁿ) | 지수 | 부분집합 전수 탐색 | 1,024 | 천문학적 크기 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 상수·저차항을 무시해 작은 입력에서 실제 성능과 불일치 | 실제 입력 규모에서 측정 |
| 최악 기준만으로 평균 성능 오판 | 최선·평균·최악을 함께 확인 |
| 시간만 고려해 메모리 사용 간과 | 공간 복잡도 병행 평가 |

## Ⅵ. 제언

알고리즘은 입력 규모가 커질 때의 증가율로 후보를 좁히고, 실제 입력 규모에서 측정해 최종 선택

### 선택 절차

```text
후보 알고리즘의 복잡도 비교 (증가율)
    ↓
예상 최대 입력 규모 대입
    ↓
실제 데이터 측정 → 선택
```

### 확대: 입력 규모별 판단

```text
입력 규모
    ├─ 작음 → 단순한 알고리즘도 무방
    └─ 큼 → 낮은 증가율의 알고리즘 필수
```

### 선택 근거: 이론 복잡도만 사용과의 비교

| 구분 | 이론만 | 제언: 이론 + 측정 |
|---|---|---|
| 작은 입력 | 오판 가능 | 측정으로 보정 |
| 대규모 입력 | 예측 | 확인 |
| 비용 | 낮음 | 측정 필요 |
