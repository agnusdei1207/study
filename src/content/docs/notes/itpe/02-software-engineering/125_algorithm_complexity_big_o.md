## 30초 인출

- 본질: 빅오 표기법은 입력 크기가 커질 때 함수의 점근적 상한을 나타내는 표기법
- 메커니즘: 입력 크기별 기본 연산을 함수로 표현 → 상수배·저차항을 무시해 성장률 비교
- 통찰: 한계: 작은 입력의 실행 시간만 비교하면 규모 증가에 따른 자원 폭증을 놓침 → 방안: 지배항의 성장률과 실제 입력 한도를 함께 평가

<details>
<summary>핵심 용어</summary>

- **빅오 표기법(Big-O, $O$)** : 충분히 큰 모든 입력 크기에서 $f(n) \le c \cdot g(n)$을 만족하는 점근적 상한 표기법. 분석 대상이 최악 실행시간일 때만 최악 경우 상한으로 해석
- **빅오메가 표기법(Big-Omega, $\Omega$)** : 충분히 큰 모든 입력 크기에서 $f(n) \ge c \cdot g(n)$을 만족하는 점근적 하한 표기법. 알고리즘의 최선 실행시간과 자동으로 같은 뜻은 아님
- **빅세타 표기법(Big-Theta, $\Theta$)** : 상한($O$)과 하한($\Omega$)이 동시에 일치하여 알고리즘의 연산 차수가 정확히 $g(n)$과 같음을 나타내는 정확한 차수 표기법
- **시간 복잡도(Time Complexity)** : 입력 데이터 크기 $n$에 비례하여 알고리즘이 수행해야 하는 기본 연산 횟수의 수학적 함수
- **공간 복잡도(Space Complexity)** : 입력 크기에 따라 알고리즘 실행에 필요한 메모리 사용량이 증가하는 양상
</details>

## 2~4교시 25점 답안

## Ⅰ. 알고리즘 복잡도의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 알고리즘 복잡도(O-notation)는 입력 크기에 따른 시간·공간 자원의 증가율을 점근 표기법으로 나타내는 척도 |
| 목적 | 알고리즘의 시간·공간 자원 증가율을 비교 |

## Ⅱ. 알고리즘 복잡도의 특징

| 특징 | 해석상 의미 |
|---|---|
| 입력 규모 의존 | 충분히 큰 입력에서 지배항의 증가 추세를 비교 |
| 자원별 구분 | 시간과 공간 사용량을 각각 분석 |
| 실측과 병행 | 상수 비용·입력 분포·하드웨어 효과는 시험으로 확인 |

## Ⅲ. 연산량 모델과 점근 분석 프로세스

```text
입력 크기·분포·상한 → 기본 연산 수 T(n)·추가 공간 S(n)
                           ↓ 지배항·경계 분석
                    O·Θ·Ω 성장률
                           ↓ 운영 입력과 자원 한도 대조
                    대표 데이터로 실측 검증
```

```text
연산 횟수 T(n)=3n²+5n+2
                  ↓ 큰 n에서 n² 지배
O(n²) 상한으로 비교
n → 2n이면 지배항 비용은 약 4배
```

## Ⅳ. 점근 표기법과 대표 성장률 비교

| 표기법 | 경계 의미 | 기본 조건 |
|---|---|---|
| $O(g(n))$ | 점근적 상한 | 충분히 큰 $n$에서 $f(n) \le c g(n)$ |
| $\Theta(g(n))$ | 점근적으로 같은 차수 | 양쪽 상·하한을 동시에 만족 |
| $\Omega(g(n))$ | 점근적 하한 | 충분히 큰 $n$에서 $f(n) \ge c g(n)$ |

### Big-O 복잡도 계층별 증가 추세

| 증가율(낮음 → 높음) | 상수 | 로그 | 선형 | 선형 로그 | 다항 | 지수·계승 |
|---|---|---|---|---|---|---|
| 대표 표기 | $O(1)$ | $O(\log n)$ | $O(n)$ | $O(n\log n)$ | $O(n^2)$ | $O(2^n)$ · $O(n!)$ |

### 대표 복잡도와 적용 조건

| 차수 | 증가 양상 | 대표 사례 | 조건·유의점 |
|---|---|---|---|
| $O(1)$ | 입력 크기와 무관한 제한 연산 | 배열 인덱스 접근 | 해시 조회는 평균 상수시간이며 최악 보장은 별도 검토 |
| $O(\log n)$ | 단계마다 탐색 범위를 일정 비율로 축소 | 정렬 배열의 이진 탐색 | 입력 정렬과 비교 비용을 전제로 함 |
| $O(n)$ | 입력 항목을 한 번씩 확인 | 선형 탐색 | 입력 길이에 비례하는 처리 |
| $O(n\log n)$ | 분할·병합 등과 선형 처리의 결합 | 병합 정렬·힙 정렬 | 비교 기반 정렬의 일반적 최악 차수 |
| $O(n^2)$ | 항목 쌍을 중첩 비교 | 단순 이중 반복·단순 정렬 | 입력 증가에 따라 연산량이 빠르게 커질 수 있음 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 작은 입력의 실행 시간만 비교하면 규모 증가에 따른 자원 폭증을 놓침 | 지배항의 성장률과 실제 입력 한도를 함께 평가 |
| 중첩 전수 비교 비용이 빠르게 증가 | 자료구조를 바꾸고 평균·최악 시간과 공간 사용량 비교 |
| 실제 입력 특성이 분석 전제와 다름 | 정렬·분포·중복·최대 크기를 운영 데이터로 확인 |
| 점근 차수만으로 실측 성능을 단정 | 대표 데이터로 응답시간·메모리·캐시 영향 측정 |

## Ⅵ. 제언

실제 입력 상한과 자원 한도를 먼저 정하고 후보 알고리즘의 평균·최악 차수와 대표 데이터의 시간·메모리를 함께 비교한다.
