- 본질: 빅오 표기법은 입력 크기가 커질 때 함수의 점근적 상한을 나타내는 표기법
- 메커니즘: 입력 크기별 기본 연산을 함수로 표현 → 상수배·저차항을 무시해 성장률 비교
- 산출물: 시간 복잡도 수식 · 공간 복잡도 수식 · 점근 분석 그래프 · 3대 점근 표기($O$, $\Omega$, $\Theta$)

<details>
<summary>핵심 용어</summary>

- **빅오 표기법(Big-O, $O$)**: 충분히 큰 모든 입력 크기에서 $f(n) \le c \cdot g(n)$을 만족하는 점근적 상한 표기법. 분석 대상이 최악 실행시간일 때만 최악 경우 상한으로 해석
- **빅오메가 표기법(Big-Omega, $\Omega$)**: 충분히 큰 모든 입력 크기에서 $f(n) \ge c \cdot g(n)$을 만족하는 점근적 하한 표기법. 알고리즘의 최선 실행시간과 자동으로 같은 뜻은 아님
- **빅세타 표기법(Big-Theta, $\Theta$)**: 상한($O$)과 하한($\Omega$)이 동시에 일치하여 알고리즘의 연산 차수가 정확히 $g(n)$과 같음을 나타내는 정확한 차수 표기법
- **시간 복잡도(Time Complexity)**: 입력 데이터 크기 $n$에 비례하여 알고리즘이 수행해야 하는 기본 연산 횟수의 수학적 함수
- **공간 복잡도(Space Complexity)**: 입력 크기에 따라 알고리즘 실행에 필요한 메모리 사용량이 증가하는 양상
</details>

## 2~4교시 25점 답안

### Ⅰ. 개요 및 필요성

| 구분 | 핵심 |
|---|---|
| 정의 | 알고리즘 복잡도(O-notation)는 입력 크기에 따른 시간·공간 자원의 증가율을 점근 표기법으로 나타내는 척도 |
| 목적 | 알고리즘의 시간·공간 자원 증가율을 비교 |

### 물리적 실행 시간의 한계와 점근 표기법의 대두

알고리즘의 성능을 "초(Second)" 단위의 실제 수행 시간으로 측정하면, 서버 하드웨어 성능(CPU 클록, RAM 대역폭), 운영체제의 스케줄링, 프로그래밍 언어의 런타임 환경에 따라 측정값이 완전히 달라진다. 동일한 코드라도 슈퍼컴퓨터에서는 0.01초에 끝나지만 구형 임베디드 단말에서는 1분이 걸릴 수 있다.

빅오 표기법(Big-O)은 이러한 물리적 환경의 종속성을 배제하고, **입력 데이터 크기 $n$이 무한히 커질 때 연산 횟수가 증가하는 기울기(점근적 증가율)**만을 순수하게 수학적으로 추상화하여 알고리즘 간의 효율성을 객관적으로 비교·평가한다.

### 3대 점근 표기법 비교

| 구분 | 빅오 표기법 ($O$) | 빅세타 표기법 ($\Theta$) | 빅오메가 표기법 ($\Omega$) |
|---|---|---|---|
| **수학적 의미** | **점근적 상한 (Upper Bound)** | **점근적 동등 (Tight Bound)** | **점근적 하한 (Lower Bound)** |
| **수학적 정의** | $f(n) \le c \cdot g(n)$ | $c_1 \cdot g(n) \le f(n) \le c_2 \cdot g(n)$ | $f(n) \ge c \cdot g(n)$ |
| **직관적 해석** | 성장률이 이 함수보다 빠르지 않음 | 위·아래 경계가 같은 차수 | 성장률이 이 함수보다 느리지 않음 |
| **실무적 의의** | 분석 대상 함수의 상한 비교 | 타이트한 성장률 비교 | 분석 대상 함수의 하한 비교 |

### Ⅱ. 점근 분석과 성장률 구조

### Big-O 복잡도 계층별 증가 추세

| 증가율(낮음 → 높음) | 상수 | 로그 | 선형 | 선형 로그 | 다항 | 지수·계승 |
|---|---|---|---|---|---|---|
| 대표 표기 | $O(1)$ | $O(\log n)$ | $O(n)$ | $O(n\log n)$ | $O(n^2)$ | $O(2^n)$ · $O(n!)$ |

### 대표 복잡도 4대 유형 상세 분석

| 적용 전 | 변경 근거 | 적용 후 |
|---|---|---|
| 모든 주문과 결제를 중첩 비교하는 $O(nm)$ 방식 | 한쪽 자료를 해시 인덱스로 구성해 키 검색 | 평균 $O(n+m)$ 조회 방식 |

| 차수 | 증가 양상 | 대표 사례 | 조건·유의점 |
|---|---|---|---|
| $O(1)$ | 입력 크기와 무관한 제한 연산 | 배열 인덱스 접근 | 해시 조회는 평균 상수시간이며 최악 보장은 별도 검토 |
| $O(\log n)$ | 단계마다 탐색 범위를 일정 비율로 축소 | 정렬 배열의 이진 탐색 | 입력 정렬과 비교 비용을 전제로 함 |
| $O(n)$ | 입력 항목을 한 번씩 확인 | 선형 탐색 | 입력 길이에 비례하는 처리 |
| $O(n\log n)$ | 분할·병합 등과 선형 처리의 결합 | 병합 정렬·힙 정렬 | 비교 기반 정렬의 일반적 최악 차수 |
| $O(n^2)$ | 항목 쌍을 중첩 비교 | 단순 이중 반복·단순 정렬 | 입력 증가에 따라 연산량이 빠르게 커질 수 있음 |

### Ⅲ. 실무 적용 및 고려사항

### 위험 대응 매트릭스

| 위험 | 대응 | 확인할 결과 |
|---|---|---|
| 입력 규모가 커질수록 중첩 전수 비교의 비용이 빠르게 증가 | 해시 기반 자료구조 등으로 조회 구조를 바꾸고 평균·최악 조건을 함께 검토 | 실제 입력 분포에서 시간·공간 사용량 비교 |
| 선택한 알고리즘의 입력 전제와 실제 데이터 특성이 다름 | 정렬 여부·키 분포·중복·최대 크기를 측정하고 적절한 탐색 구조 선택 | 운영 입력과 시험 입력 간 차이 확인 |
| 점근 차수만 보고 상수 비용·메모리 압박·캐시 영향을 간과 | 대표 데이터로 벤치마크하고 메모리·응답시간을 함께 측정 | 모델 분석과 실제 성능의 차이 확인 |

### Ⅳ. 점검 기준

### 알고리즘 복잡도 및 확장성 체크리스트

| 점검 영역 | 상세 검증 항목 | 합격 기준 |
|---|---|---|
| **시간 복잡도** | 입력 상한과 응답 목표에 대한 최악·평균 분석 | 요구사항에 맞는 상한과 가정 기록 |
| **공간 복잡도** | 인덱스·캐시·재귀 스택의 추가 메모리 | 허용 메모리 예산 안에서 동작 확인 |

| **실측 검증** | 대표 입력 규모별 응답시간·메모리 측정 | 측정 조건과 결과 기록 |
