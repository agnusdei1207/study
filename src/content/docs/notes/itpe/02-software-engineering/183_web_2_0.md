## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 웹 아키텍처·인터넷 기술 → Web 2.0

## 지식 위치

소프트웨어공학 > 웹 서비스 발전 > Web 2.0

## 30초 인출

- 본질: 사용자가 단순히 정보를 소비하던 일방향 웹(Web 1.0)을 넘어, 사용자가 직접 콘텐츠를 생산하고 상호작용하는 참여·공유·개방 철학 기반의 차세대 플랫폼 지향 웹 패러다임
- 메커니즘: 사용자 참여(UGC 생성) → 플랫폼으로서의 웹(Web as a Platform) 데이터 축적 → 오픈 API(Open API) 및 RSS/Atom 배포 → AJAX 기반 비동기 매시업(Mashup) 서비스 창출
- 통찰: 무분별한 개방 및 사용자 데이터 독점으로 인한 가짜 뉴스, 플랫폼 락인 및 개인정보 침해 한계를 극복하기 위해 데이터 주권과 시맨틱 웹/분산 원장(Web 3.0) 기술 연계 필수

<details>
<summary>핵심 용어</summary>

- **Web 2.0** : 팀 오라일리(Tim O'Reilly)가 주창한 개념으로 개방, 참여, 공유를 3대 가치로 하는 사용자 중심의 웹 생태계
- **플랫폼으로서의 웹 (Web as a Platform)** : PC 운영체제 대신 웹 브라우저 자체가 애플리케이션 실행 및 서비스 조합의 기반 인프라로 작동하는 개념
- **사용자 생성 콘텐츠 (UGC / UCC)** : 기업이나 운영자가 아닌 일반 사용자가 자발적으로 제작하고 공유하는 텍스트, 이미지, 동영상 콘텐츠
- **폭소노미 (Folksonomy)** : 전문가가 부여하는 정형화된 분류(Taxonomy)와 대비되는, 일반 대중이 자유롭게 태그(Tag)를 달아 지식을 분류하는 집단지성 분류 체계
- **매시업 (Mashup)** : 웹 상에 공개된 여러 오픈 API(지도, 결제, 날씨 등)를 결합하여 완전히 새로운 융합 서비스를 창출하는 개발 기법
- **AJAX (Asynchronous JavaScript and XML)** : 페이지 전체 리로드 없이 백그라운드 비동기 통신을 통해 화면의 일부만을 동적으로 갱신하는 웹 기술
</details>

## 2~4교시 예상문제 (25점)

> Web 2.0의 3대 철학(개방, 참여, 공유)과 기술적 구현 아키텍처를 설명하고, Web 1.0과의 비교 및 현대 인터넷 서비스에 미친 영향과 데이터 독점 한계 극복 방안(Web 3.0 연계)을 제시하시오. (25점)

---

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 단방향 정보 제공 중심의 정적 웹에서 탈피하여, 사용자가 직접 정보를 생산하고(참여), 누구나 자유롭게 소통하며(공유), 인터페이스와 데이터를 외부에 투명하게 제공(개방)하는 양방향 웹 플랫폼 패러다임 |
| 목적 | 집단지성(Collective Intelligence)의 발현, 비즈니스 롱테일(Long Tail) 법칙 실현, 오픈 API 기반의 서비스 융합 생태계 구축 |

## Ⅱ. 핵심 특징

| 특징 | 세부 내용 |
|---|---|
| 참여 (Participation) | 사용자가 단순 수용자를 넘어 지식 생산자(Prosumer)로 전환되어 위키, 블로그, SNS를 통해 콘텐츠 직접 생성 |
| 공유 (Sharing) | 축적된 지식과 데이터를 RSS, 소셜 그래프, 크리에이티브 커먼즈(CCL)를 통해 사회적 자산으로 확산 |
| 개방 (Openness) | 사일로화된 시스템을 열어젖히고 Open API(RESTful) 및 공개 표준 규격을 통해 누구나 서비스와 데이터를 결합 가능 |
| 풍부한 사용자 경험 (Rich UX) | 브라우저 리프레시 없는 AJAX 비동기 인터랙션을 통해 데스크톱 네이티브 앱에 준하는 반응성 제공 |

단순한 기술적 진보를 넘어 인터넷 사회의 경제적, 문화적 상호작용 패러다임을 근본적으로 재편한 역사적 전환점.

## Ⅲ. 체계·프로세스

```text
[Web 2.0 생태계 아키텍처]

[사용자 계층: 집단지성 (Collective Intelligence)]
  - 글 작성, 태그(Folksonomy) 부여, 댓글/좋아요 평가 ──► UGC (User Generated Content)
       │
       ▼
[플랫폼 계층: Web as a Platform]
  ┌────────────────────────────────────────────────────────┐
  │ 1) 데이터베이스 (지속적으로 성장하는 데이터 자산)       │
  │ 2) 비동기 인터페이스 (AJAX / REST API)                │
  │ 3) 오픈 신디케이션 (RSS / Atom 피드)                  │
  └────────────────────────────────────────────────────────┘
       │
       ├─ [내부 UI 렌더링] ──► Single Page Application (SPA / AJAX)
       │
       └─ [외부 개방 및 결합 (Mashup)]
            ▼
[생태계 계층: 서비스 결합 및 확장]
  - 구글 지도 API + 부동산 매물 데이터 ──► 부동산 매시업 서비스
  - 트위터 피드 + AI 감성 분석      ──► 소셜 트렌드 모니터링 서비스
```

사용자 참여로부터 시작되어 데이터베이스 축적, 오픈 API 노출, 타 서비스와의 매시업을 통해 네트워크 효과를 극대화하는 선순환 구조.

## Ⅳ. 종류·비교

| 비교 항목 | Web 1.0 (정적 웹) | Web 2.0 (소셜/참여 웹) | Web 3.0 (지능형/탈중앙 웹) |
|---|---|---|---|
| **통신 패러다임** | 단방향 (Read-Only) | 양방향 (Read-Write) | 다방향 탈중앙 (Read-Write-Own) |
| **핵심 철학** | 정보 전달 및 브라우징 | 참여, 공유, 개방 | 탈중앙화, 데이터 주권, 시맨틱 |
| **콘텐츠 생산 주체** | 웹마스터, 기업, 사이트 운영자 | 일반 사용자 (UGC, 프로슈머) | 사용자 + AI 에이전트 협업 |
| **데이터 소유권** | 사이트 구축 기업 | 거대 빅테크 플랫폼 (중앙 집중) | 사용자 개인 (탈중앙 지갑/DID) |
| **핵심 기술** | 정적 HTML, CGI, 넷스케이프 | AJAX, REST API, RSS, 클라우드 | 블록체인, 스마트 컨트랙트, RDF/OWL |
| **비즈니스 모델** | 웹사이트 디렉토리, 배너 광고 | 타깃 맞춤형 광고, 플랫폼 수수료 | 토큰 이코노미, 프로토콜 기여 보상 |

### Web 2.0의 핵심 구성 기술 요소

| 구성 요소 | 기술적 정의 | 비즈니스적 가치 |
|---|---|---|
| **AJAX** | JavaScript와 XML/JSON을 이용한 비동기 HTTP 통신 | 페이지 새로고침 없는 매끄러운 UX 제공 및 트래픽 절감 |
| **Open API** | 자사 서비스의 기능과 데이터를 외부에 프로그래밍 인터페이스로 공개 | 서드파티 개발자 생태계 구축 및 서비스 영향력 확대 |
| **매시업 (Mashup)** | 둘 이상의 오픈 API를 조합하여 새로운 서비스 창출 | 개발 비용 최소화 및 혁신적 융복합 비즈니스 모델 발굴 |
| **폭소노미 (Folksonomy)** | 사용자들이 자발적으로 부여한 태그 기반의 집단 분류 체계 | 자연스러운 사용자 관심사 군집화 및 검색 추천 고도화 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 소수 거대 플랫폼 기업(구글, 메타 등)의 데이터 독점 및 알고리즘 기반 여론 왜곡/확증편향 유발 | 오픈 데이터 규제(GDPR) 강화 및 데이터 이동권(Data Portability) 보장을 통한 플랫폼 독점 완화 |
| 사용자가 생산한 콘텐츠의 저작권과 광고 수익을 중앙 플랫폼이 독점하는 불공정 수익 분배 | 블록체인 기반의 창작자 보상 시스템(Web 3.0 토큰 이코노미) 및 분산 소셜 프로토콜(ActivityPub) 도입 |
| 검증되지 않은 가짜 뉴스(Fake News), 딥페이크 및 악성 어뷰징 콘텐츠의 무분별한 확산 | AI 기반 팩트체크 시스템 구축, 신뢰도 평판 알고리즘 적용 및 이용자 신고/모니터링 강화 |

## Ⅵ. 제언

Web 2.0이 확립한 참여와 연결의 사용자 경험을 계승하되, 빅테크 플랫폼의 중앙 집중형 폐해를 극복하기 위해 탈중앙화 식별자(DID)와 시맨틱 지식 그래프를 융합한 개방형 데이터 프로토콜 체계로의 진화 추진 필요.

```text
[웹 아키텍처의 진화 경로]
  Web 1.0 (디렉토리/포털) → Web 2.0 (빅테크 플랫폼/SNS) → Web 3.0 (분산 프로토콜/사용자 주권 데이터)
```

| 검증 단계 | Web 2.0 플랫폼 거버넌스 | 차세대 웹(Web 3.0) 거버넌스 |
|---|---|---|
| 데이터 통제 | 중앙 서버 RDBMS 집중 보관 | 분산 원장(IPFS/블록체인) 및 사용자 로컬 저장 |
| 신원 인증 | 플랫폼 종속 소셜 로그인 (OAuth2) | 자주적 신원 증명 (Verifiable Credentials / DID) |
