## Ⅰ. Web 2.0의 개요

- 개념 : **Web 2.0** 이란 팀 오라일리(Tim O'Reilly)가 2004년에 제시한 웹의 진화적 패러다임으로, 웹을 단순한 정보의 일방적 열람 공간(Read-Only)에서 벗어나 사용자가 직접 콘텐츠를 생산하고, 공유하며, 자유롭게 참여하는 개방·참여·공유 기반의 양방향 플랫폼(Read-Write Web)으로 전환시킨 기술 및 비즈니스 혁명.
- 배경 및 필요성 : 2000년대 초 닷컴 버블 붕괴 이후 살아남은 기업들의 공통적 성공 방정식을 분석하고, 브로드밴드 인터넷 보급과 **AJAX** 등 웹 기술 혁신을 배경으로 탄생.
- 3대 핵심 철학 : **개방** (Openness), **참여** (Participation), **공유** (Sharing)

## Ⅱ. Web 1.0, Web 2.0, Web 3.0의 진화 비교

```text
   [ Web 1.0 (1990s) ] ────────── [ Web 2.0 (2000s) ] ────────── [ Web 3.0 (2020s+) ]
    - 읽기 전용 (Read-Only)        - 읽기/쓰기 (Read-Write)       - 읽기/쓰기/소유 (Read-Write-Own)
    - 정적 HTML 웹페이지           - 동적 플랫폼 (AJAX, SNS)      - 탈중앙화 (블록체인, DApp)
    - 소수 관리자가 콘텐츠 발행     - 사용자 생성 콘텐츠 (UGC)     - 데이터 주권 및 토큰 경제
    - 포털 중심 (Yahoo, 네이버)    - 플랫폼 중심 (YouTube, Meta)  - 분산 네트워크 (시맨틱, 탈중앙)
```

- **네트워크 효과** (Network Effects) : 사용자가 플랫폼을 많이 사용할수록 데이터가 축적되고 서비스의 가치가 기하급수적으로 증가.
- **롱테일 법칙** (The Long Tail) : 상위 20%의 대중적 히트작뿐만 아니라 하위 80%의 비인기 틈새 상품(Niche)들이 결합하여 거대한 전체 시장을 형성 (아마존의 도서 판매 전략).

## Ⅲ. Web 2.0의 핵심 기술 및 비즈니스 요소

| 기술/비즈니스 요소 | 핵심 개념 및 역할 | 대표 사례 |
|---|---|---|
| AJAX | 페이지 전체 새로고침 없이 백그라운드 비동기 통신으로 부드러운 UX 제공 | Google Maps, Gmail |
| 사용자 생성 콘텐츠 (UGC) | 사용자가 직접 글, 영상, 지식을 창작하여 플랫폼을 채움 | 위키백과, 유튜브, 블로그 |
| **Open API 및 매시업** (Mashup) | 기업의 핵심 데이터를 외부 개방하고 제3자가 결합하여 신규 서비스 창출 | 구글 맵 API 기반 부동산 서비스 |
| **폭소노미** (Folksonomy) | 전문가의 고정된 분류 체계 대신 사용자가 자유롭게 태그(#)를 달아 분류 | 해시태그, 소셜 북마크 |
| 플랫폼으로서의 웹 | PC 설치 소프트웨어를 웹 브라우저 기반의 서비스(SaaS)로 대체 | 구글 닥스, 웹 메일 |

## Ⅳ. Web 2.0의 주요 한계점 및 해결 방안

- **사용자 생성 콘텐츠** (UGC) 폭증에 따른 인프라 스케일링 한계 :
  - 한계점 : 텍스트, 이미지, 비디오 등 비정형 UGC가 기하급수적으로 유입되어 기존 관계형 데이터베이스(RDB)의 수직적 확장 한계 봉착.
  - 해결 방안 : NoSQL(MongoDB, Cassandra) 및 분산 오브젝트 스토리지(S3 등) 기반 수평 확장(Scale-Out) 아키텍처, 글로벌 CDN 에지 캐싱 구축.
- 클라이언트 비동기 인터랙션 증가에 따른 보안 취약점 확대 :
  - 한계점 : 동적 DOM 조작 및 REST API 통신의 보편화로 크로스 사이트 스크립팅(XSS), CSRF, API 비인가 접근 등 웹 보안 위협 급증.
  - 해결 방안 : 엄격한 **콘텐츠 보안 정책** (CSP) 수립, 입출력 데이터의 컨텍스트 기반 자동 인코딩/살균(Sanitization), OAuth 2.0/OIDC 기반 보안 인증 표준화.
- 플랫폼 기업의 데이터 독점 및 프라이버시 침해 우려 :
  - 한계점 : 개방과 공유의 기치로 시작했으나 소수 빅테크 플랫폼에 데이터와 트래픽이 종속되어 사용자 데이터 주권 상실 및 알고리즘 폐쇄성 초래.
  - 해결 방안 : **데이터 이동권** (Data Portability) 및 마이데이터 표준 연계 의무화, **탈중앙화 식별자** (DID) 및 Web3 기반 데이터 주권 회복 기술 융합 검토.

## Ⅴ. 웹 진화 관점에서의 기술사적 제언

- 데이터 독점 폐해 극복과 탈중앙화 Web 3.0으로의 점진적 전환 : Web 2.0 거대 빅테크 플랫폼들이 사용자의 개인정보와 행동 데이터를 독점하여 수익화하는 감시 자본주의 문제를 극복하기 위해, 탈중앙 신원증명(DID)과 자기주권 신원(Self-Sovereign Identity)을 결합한 데이터 주권 회복 아키텍처 모색 필요.
- **PWA** (프로그레시브 웹 앱)를 통한 플랫폼 개방성 계승 : 특정 모바일 앱스토어(구글/애플)의 독점 수수료(30%) 정책에 대응하여, Web 2.0의 개방 정신을 이어받은 PWA 표준을 적극 채택함으로써 웹 표준 기반의 자유로운 멀티 플랫폼 서비스 지속 배포 권장.
