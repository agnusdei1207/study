## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 웹 기술 → **Web 2.0**

## 30초 인출

- 본질: Web 2.0은 사용자가 콘텐츠를 만들고 공유하며 웹이 플랫폼으로 동작하는 참여형·개방형 웹
- 메커니즘: 사용자 참여로 만든 콘텐츠를 공개 API로 개방하고 비동기 통신(AJAX)으로 화면을 갱신해 서비스와 콘텐츠를 결합
- 통찰: 참여와 개방이 커질수록 사용자 생성 콘텐츠의 품질·저작권과 공개 API 남용 문제가 생기므로 이용 정책과 API 접근 통제를 함께 설계

<details>
<summary>핵심 용어</summary>

- **Web 2.0** : 개방·참여·공유를 특징으로 하는 웹. Tim O'Reilly가 확산
- **사용자 생성 콘텐츠(UGC)** : 운영자가 아닌 사용자가 만든 콘텐츠
- **폭소노미(Folksonomy)** : 사용자가 붙인 태그로 이루어지는 자유로운 분류
- **매시업(Mashup)** : 공개 API로 여러 서비스를 결합해 새 서비스를 만드는 것
- **AJAX** : 페이지 전체를 다시 불러오지 않고 비동기로 데이터를 주고받는 기술
- **플랫폼으로서의 웹** : 웹 자체가 애플리케이션 실행 환경으로 쓰이는 개념

</details>

## 2~4교시 25점 답안

## Ⅰ. Web 2.0의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **Web 2.0** 은 개방·참여·공유를 특징으로 하는 웹 |
| 목적 | 사용자 참여를 통한 콘텐츠·서비스 가치 창출 |

## Ⅱ. Web 1.0과 구별되는 특징

| 구분 | Web 1.0 | Web 2.0 |
|---|---|---|
| 콘텐츠 | 제공자가 생산 | 사용자가 생산·공유 |
| 웹의 역할 | 정보 열람 | 플랫폼 |
| 분류 | 운영자가 분류 | 사용자가 태그로 분류 |

## Ⅲ. 구성

```text
사용자 참여 (UGC·태그) ─▶ 공개 API ─▶ 매시업 서비스
                    ▲
                AJAX 비동기 화면 갱신
```

## Ⅳ. 핵심 기술과 개념

| 요소 | 내용 |
|---|---|
| AJAX | 비동기 통신으로 부분 갱신 |
| Open API | 서비스 기능·데이터의 개방 |
| 매시업 | API 결합으로 새 서비스 생성 |
| 폭소노미 | 사용자 태그 기반 분류 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 사용자 콘텐츠의 품질·저작권 문제 | 이용 정책과 신고·검수 체계 |
| 공개 API 남용과 보안 위험 | 인증·호출 제한 |
| 정보 과잉으로 신뢰성 저하 | 평판·추천 체계 |

## Ⅵ. 제언

사용자 참여와 API 개방을 열어 두되 이용 정책과 API 접근 통제를 함께 설계

```text
참여 확대 ─ 이용 정책·검수
개방 확대 ─ API 인증·호출 제한
```

| 구분 | 통제 없는 개방 | 제언: 정책·통제 병행 |
|---|---|---|
| 콘텐츠 품질 | 저하 | 유지 |
| API 남용 | 위험 | 제한 |
