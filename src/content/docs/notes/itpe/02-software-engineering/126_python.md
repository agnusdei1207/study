## 핵심 용어
- GIL(Global Interpreter Lock): CPython 인터프리터가 한 번에 하나의 스레드만 파이썬 바이트코드를 실행하도록 메모리 스레드 안전성을 강제하는 뮤텍스(Mutex)
- 참조 카운팅(Reference Counting): 파이썬 객체를 참조하는 변수의 수를 세어 0이 되는 즉시 메모리를 회수하고, 순환 참조는 세대별 가비지 컬렉터로 보완하는 메모리 관리 기법

## 핵심 통찰
- 파이썬에서 멀티스레딩은 I/O 바운드 작업(네트워크 요청 대기)에서는 컨텍스트 스위칭으로 유용하지만, CPU 바운드 연산(대규모 수치 계산)에서는 GIL 경합 오버헤드로 인해 단일 스레드보다 오히려 느려짐
- 대규모 AI/머신러닝 분야에서 파이썬이 표준이 된 이유는 파이썬 자체의 연산 속도가 빨라서가 아니라, PyTorch/TensorFlow처럼 핵심 연산 커널이 C/C++/CUDA로 구현되어 GIL 밖에서 동작하기 때문임
- 대규모 소프트웨어 시스템에서 파이썬을 유지보수할 때 런타임 타입 에러가 최대 위험 요소이므로, Python 3.5+부터 도입된 타입 힌트(`typing`)와 정적 타입 검사기(Mypy) 도입이 필수적임

## 이웃 토픽과 구분
- 파이썬(Python) vs 자바(Java): 파이썬 = 동적 타입·인터프리터·빠른 프로토타이핑 및 데이터 과학 강점 / 자바 = 정적 타입·JIT 컴파일·대규모 엔터프라이즈 트랜잭션 및 멀티스레딩 성능 강점
