## 30초 인출

- 본질: 파이썬은 간결한 문법과 풍부한 라이브러리를 가진 인터프리터 방식의 범용 고급 프로그래밍 언어
- 메커니즘: 소스를 바이트코드로 컴파일해 가상 머신이 실행하고 동적 타이핑과 자동 메모리 관리로 개발 속도를 높임
- 통찰: 전역 인터프리터 락(GIL) 때문에 CPU 집약 작업은 스레드로 병렬화되지 않으므로 CPU 바운드는 멀티프로세스나 네이티브 확장으로, I/O 바운드는 스레드·비동기로 구분해 적용

<details>
<summary>핵심 용어</summary>

- **파이썬(Python)** : 가독성이 높은 문법의 인터프리터 방식 범용 언어
- **동적 타이핑(Dynamic Typing)** : 변수의 타입을 실행 시점에 결정하는 방식
- **바이트코드(Bytecode)** : 소스를 컴파일한 중간 코드로 가상 머신이 실행
- **GIL(Global Interpreter Lock)** : CPython에서 한 시점에 하나의 스레드만 바이트코드를 실행하게 하는 잠금
- **참조 카운팅(Reference Counting)** : 객체를 참조하는 수를 세어 0이 되면 메모리를 해제하는 방식
- **타입 힌트(Type Hints)** : 타입 정보를 표기해 정적 검사 도구가 오류를 찾도록 하는 기능

</details>

## 2~4교시 25점 답안

## Ⅰ. 파이썬의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **파이썬** 은 간결한 문법과 풍부한 라이브러리를 가진 인터프리터 방식의 범용 프로그래밍 언어 |
| 목적 | 개발 생산성과 가독성 향상 |

## Ⅱ. 파이썬의 특징

| 특징 | 의미 |
|---|---|
| 인터프리터 방식 | 즉시 실행과 대화식 개발 |
| 동적 타이핑 | 변수 타입 선언 불필요 |
| 풍부한 라이브러리 | 데이터·웹·AI 분야의 폭넓은 생태계 |
| 자동 메모리 관리 | 참조 카운팅과 가비지 컬렉션 |

## Ⅲ. 실행 구조

### 실행 과정

```text
소스 코드(.py)
    ↓ 컴파일
바이트코드
    ↓
파이썬 가상 머신 실행
```

### 확대: GIL의 영향

```text
멀티스레드 실행
    ├─ I/O 대기 중 → 다른 스레드로 전환되어 효과 있음
    └─ CPU 연산 중 → 한 시점에 한 스레드만 실행 (병렬화 제한)
```

## Ⅳ. 다른 언어와의 비교와 병행 처리 방식

### 컴파일 언어와의 비교

| 구분 | 파이썬 | 컴파일 언어(C·Java 등) |
|---|---|---|
| 실행 | 인터프리터·가상 머신 | 컴파일 후 실행 |
| 타입 | 동적 | 정적 |
| 속도 | 상대적으로 느림 | 빠름 |
| 개발 속도 | 빠름 | 상대적으로 느림 |

### 병행 처리 방식의 선택

| 작업 유형 | 적합한 방식 |
|---|---|
| I/O 바운드 | 스레드·비동기 |
| CPU 바운드 | 멀티프로세스, 네이티브 확장 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| GIL로 CPU 집약 작업의 스레드 병렬화 제한 | 멀티프로세스 또는 C 확장 사용 |
| 동적 타이핑으로 실행 시점에 오류 발견 | 타입 힌트와 정적 검사 도구 |
| 실행 속도가 느림 | 핵심 연산을 최적화된 라이브러리·네이티브 코드로 대체 |

## Ⅵ. 제언

작업이 I/O 바운드인지 CPU 바운드인지 먼저 구분해 병행 처리 방식을 선택하고, 타입 힌트로 오류를 조기에 점검

### 방식 선택

```text
작업 특성 확인
    ├─ I/O 바운드 → 스레드·비동기
    └─ CPU 바운드 → 멀티프로세스·네이티브 확장
코드 품질: 타입 힌트 + 정적 검사
```

### 확대: 성능 병목 처리

```text
프로파일링으로 병목 확인
    ↓
병목 구간만 라이브러리·확장으로 대체
```

### 선택 근거: 일률적 스레드 사용과의 비교

| 구분 | 모두 스레드 | 제언: 작업별 선택 |
|---|---|---|
| CPU 작업 | 병렬화 제한 | 프로세스로 병렬화 |
| I/O 작업 | 효과 있음 | 스레드·비동기 |
| 복잡도 | 낮음 | 선택 필요 |
