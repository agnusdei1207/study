## 30초 인출

- 본질: 파이썬은 동적 객체 모델과 간결한 문법을 갖춘 고급 범용 프로그래밍 언어
- 메커니즘: 소스 코드 → 구현체의 실행 모델에 따른 해석·실행 → 객체 메모리 관리와 라이브러리 활용
- 산출물: 파이썬 바이트코드(.pyc) · 패키지 의존성 명세(pyproject.toml) · 가상환경 격리 스펙 · 정적 타입 분석 리포트(Mypy)

<details>
<summary>핵심 용어</summary>

- **CPython**: C 언어로 구현된 Python의 대표 구현체로, 소스 코드를 바이트코드로 컴파일한 뒤 인터프리터에서 실행
- **PVM(Python Virtual Machine)**: 바이트코드를 명령어 단위로 해석 실행하는 스택 기반 가상머신
- **GIL(Global Interpreter Lock)**: GIL이 활성화된 CPython 빌드에서 Python 객체 접근을 조정하는 전역 잠금. 기본 빌드는 한 번에 하나의 스레드만 Python 코드를 실행하며, 선택 가능한 free-threaded 빌드는 GIL을 비활성화
- **동적 타이핑(Dynamic Typing)**: 변수의 데이터 타입을 코드 작성 시 선언하지 않고, 프로그램 런타임에 변수에 할당되는 객체의 타입에 따라 동적으로 결정되는 방식
- **참조 카운팅(Reference Counting)**: 객체를 가리키는 포인터 수를 실시간 카운트하여 0이 되는 즉시 메모리를 즉시 해제하는 CPython의 기본 가비지 컬렉션 기법
</details>

## Ⅰ. 개요 및 필요성

| 구분 | 핵심 |
|---|---|
| 정의 | 파이썬은 동적 객체 모델과 간결한 문법을 갖춘 고급 범용 프로그래밍 언어 |
| 목적 | 범용 소프트웨어와 자동화 도구의 신속한 개발을 지원 |

**핵심:** 파이썬은 간결한 문법·동적 타입·모듈 생태계를 갖춘 범용 언어. 데이터 분석·자동화·웹 개발 등 적용 범위가 넓지만, 실행 모델과 라이브러리 구현에 따라 성능 특성이 달라짐.

### 파이썬 vs 자바 vs C++ 핵심 비교

| 구분 | 파이썬 (Python) | 자바 (Java) | C++ |
|---|---|---|---|
| 타입 | 동적 타입, 타입 힌트 지원 | 정적 타입 | 정적 타입 |
| 실행 환경의 예 | CPython 바이트코드 실행 | JVM 바이트코드·JIT | 구현·빌드 환경에 따른 기계어 실행 |
| 병렬 처리 유의점 | 일반 CPython 빌드의 GIL, 별도 free-threaded 빌드 존재 | 스레드와 JVM 설정에 따른 동작 | 언어·라이브러리의 동시성 모델 활용 |

## Ⅱ. 실행 모델과 핵심 메커니즘

### CPython 실행 구조와 GIL

```text
Python 소스(.py)
    ↓ 컴파일
바이트코드
    ↓ 실행
CPython 런타임
    ├─ 일반 빌드: GIL 동작
    └─ free-threaded 빌드: GIL 비활성화
```

### 언어와 대표 구현의 주요 특성

| 구성요소 | 핵심 판단 |
|---|---|
| 객체 모델 | 함수·클래스를 포함한 값이 객체이며, 함수도 인자로 전달 가능 |
| 모듈 | 기능을 파일·패키지 단위로 구성하고 import로 재사용 |
| CPython 실행 | 소스를 바이트코드로 컴파일해 실행, 일반 빌드에서는 GIL 사용 |
| 타입 힌트 | 정적 분석·편집 도구에 타입 정보를 제공, 기본적으로 런타임 타입 강제 없음 |

## Ⅲ. 실무 적용 및 고려사항

### 위험 대응 매트릭스

| 위험 | 대책 |
|---|---|---|
| CPU 집약 작업에서 GIL이 활성화된 CPython 스레드의 병렬 실행에 제약 | 작업 특성에 따라 멀티프로세싱, 네이티브 확장, 선택형 free-threaded 빌드 등을 검토하고 성능 측정 | 처리량과 자원 사용량을 목표 조건에서 검증 |
| 동적 타입 사용으로 일부 타입 오류가 실행 시점에 드러날 수 있음 | 타입 힌트와 정적 분석을 적용하고 중요 경로에 자동 시험 추가 | 정적 분석·시험으로 발견한 결함을 배포 전에 수정 |
| 전역 환경의 패키지 설치로 의존성 충돌 또는 실행 환경 차이가 발생 | 프로젝트별 가상환경과 의존성 잠금 파일을 사용하고 배포 환경에서 재현성 확인 | 개발·검증·운영 환경의 차이를 줄임 |

## Ⅳ. 점검 기준

### 파이썬 애플리케이션 품질 점검 체크리스트

| 점검 영역 | 상세 검증 항목 | 합격 기준 |
|---|---|---|
| 타입·시험 | 중요 경로의 타입 분석과 자동 시험 | 합의한 품질 기준 충족 |
| 동시성 | CPU·I/O 작업 구분과 빌드의 GIL 여부 확인 | 대상 환경에서 처리량 검증 |
| 의존성 | 가상환경·버전 고정과 설치 재현성 | 배포 환경에서 설치·실행 확인 |

## Ⅴ. 기술사적 제언

```text
작업 특성 구분: CPU 집약 / I/O 대기
              ↓
실행 방식·라이브러리 선택
              ↓
타입·시험·의존성 검증 + 실제 성능 측정
```

**제언:** 언어의 간결함과 실행 성능을 혼동하지 말고 대상 환경에서 검증.
