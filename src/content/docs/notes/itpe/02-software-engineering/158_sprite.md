## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 웹 기술 → **스프라이트(Sprite)**

## 30초 인출

- 본질: 스프라이트는 여러 작은 이미지를 한 장의 이미지 파일로 합치고 화면에는 필요한 부분만 잘라 보여 주는 이미지 최적화 기법
- 메커니즘: 합친 이미지를 배경으로 지정하고 CSS의 배경 위치(좌표 오프셋)로 표시할 영역을 선택해 여러 이미지 요청을 한 번으로 줄임
- 통찰: 이미지를 합치면 요청 수는 줄지만 일부만 바뀌어도 전체를 다시 받고, HTTP/2에서는 요청 수 부담이 작아지므로 프로토콜과 이미지 변경 빈도를 보고 적용 여부를 판단

<details>
<summary>핵심 용어</summary>

- **이미지 스프라이트(Image Sprite)** : 여러 작은 이미지를 한 파일로 합친 이미지
- **스프라이트 시트(Sprite Sheet)** : 합쳐 놓은 이미지 묶음 파일
- **background-position** : 배경 이미지의 표시 위치를 지정하는 CSS 속성
- **HTTP 요청 수** : 페이지 로딩 중 서버로 보내는 요청의 개수
- **HTTP/2 다중화** : 하나의 연결로 여러 요청·응답을 동시에 처리하는 기능
- **SVG 스프라이트** : 여러 벡터 아이콘을 한 파일에 정의해 필요한 것만 참조하는 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. 스프라이트의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **스프라이트** 는 여러 작은 이미지를 한 파일로 합쳐 필요한 부분만 보여 주는 기법 |
| 목적 | 이미지 요청 수 감소와 로딩 시간 단축 |

## Ⅱ. 개별 이미지 방식과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 요청 수 감소 | 여러 이미지를 한 번에 내려받음 |
| 좌표 기반 표시 | 배경 위치로 표시 영역 선택 |
| 한 번 캐시 | 한 파일이 캐시되어 재사용 |

## Ⅲ. 동작 원리

### 스프라이트 시트와 표시 영역

```text
스프라이트 시트 (icons.png, 96 x 32)
┌────────┬────────┬────────┐
│ 홈     │ 검색   │ 설정   │   각 아이콘 32 x 32
│ (0,0)  │ (-32,0)│ (-64,0)│   ← background-position 값
└────────┴────────┴────────┘
```

### CSS 적용 예

| 아이콘 | width·height | background-position |
|---|---|---|
| 홈 | 32px × 32px | 0 0 |
| 검색 | 32px × 32px | -32px 0 |
| 설정 | 32px × 32px | -64px 0 |

## Ⅳ. 적용 판단과 대안 비교

| 구분 | 개별 이미지 | 스프라이트 | SVG 스프라이트 |
|---|---|---|---|
| 요청 수 | 이미지 수만큼 | 1회 | 1회 |
| 수정 | 해당 이미지만 교체 | 시트 전체 재배포 | 시트 전체 재배포 |
| 확대 품질 | 형식에 따라 | 래스터라 확대 시 저하 | 벡터라 유지 |
| 적합 조건 | HTTP/2, 변경 잦음 | HTTP/1.1, 변경 적음 | 아이콘·확대 필요 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 일부 아이콘 변경에도 시트 전체를 다시 내려받음 | 변경 빈도별로 시트를 분리 |
| 좌표 관리의 어려움 | 빌드 도구로 시트와 CSS 자동 생성 |
| HTTP/2에서 요청 수 절감 효과 감소 | 프로토콜 확인 후 적용 여부 결정 |

## Ⅵ. 제언

사용하는 프로토콜(HTTP/1.1 또는 HTTP/2)과 이미지 변경 빈도를 확인해 적용 여부를 정하고, 적용 시 시트와 CSS는 빌드 도구로 자동 생성

### 적용 여부 판단

```text
프로토콜 확인
   ├─ HTTP/1.1 + 이미지 변경 적음 → 스프라이트 적용
   └─ HTTP/2 또는 변경 잦음 → 개별 이미지·SVG 유지
```

### 확대: 유지 관리

```text
아이콘 추가·변경 → 빌드 도구가 시트와 좌표 CSS를 함께 생성
```

### 선택 근거: 항상 스프라이트 사용과의 비교

| 구분 | 항상 스프라이트 | 제언: 조건 판단 |
|---|---|---|
| HTTP/2 환경 | 이득 작음 | 불필요한 적용 회피 |
| 변경 대응 | 시트 전체 재배포 | 조건별 선택 |
| 유지 부담 | 좌표 관리 | 자동 생성 |
