## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 테스트·검증 → **메타모픽 테스트(Metamorphic Test)**

## 30초 인출

- 본질: 기대 출력값(Test Oracle)을 사전에 정의하기 어려운 인공지능, 자율주행, 빅데이터 분야에서 원본 입력과 변형된 후속 입력 간의 수학적·논리적 관계를 검증하는 소프트웨어 테스트 기법
- 메커니즘: 원본 테스트 케이스($x$) 실행 → 도메인 규칙 기반 메타모픽 관계(MR) 정의 → 변형 함수($T$)를 통한 후속 케이스($x'$) 생성 및 실행 → 두 출력 간의 메타모픽 관계($f(x) \sim f(x')$) 일치 여부 판정
- 통찰: 잘못 정의된 메타모픽 관계는 심각한 오탐과 미탐을 초래하므로 도메인 불변식 정형화와 다중 MR 교차 검증 파이프라인 수립 필수

<details>
<summary>핵심 용어</summary>

- **Test Oracle Problem(테스트 오라클 문제)** : 주어진 입력에 대해 소프트웨어가 출력해야 할 올바른 정답을 알지 못하거나, 계산 비용이 너무 커서 합격 여부를 판정하기 어려운 근본적 한계
- **Metamorphic Testing(메타모픽 테스트)** : 개별 실행 결과의 절대적 정답 대신, 복수 실행 결과 간의 상대적 관계(MR)를 검증하여 결함을 탐색하는 기법
- **Metamorphic Relation (MR, 메타모픽 관계)** : 원본 입력과 후속 변형 입력 사이에서 프로그램의 실행 결과가 반드시 유지해야 하는 필수 불변식 또는 대수적 성질
- **Source Test Case (원본 케이스)** : 최초로 시스템에 인가하는 기준 입력값
- **Follow-up Test Case (후속 케이스)** : 메타모픽 변형 함수를 통해 원본 케이스로부터 파생 생성된 입력값

</details>

## 2~4교시 25점 답안

## Ⅰ. 메타모픽 테스트의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 테스트 오라클 부재(Oracle Problem) 환경에서 개별 결과의 절대적 정답을 검증하는 대신, 복수의 입력과 출력 간에 성립해야 하는 불변적 관계인 **메타모픽 관계(MR)** 의 성립 여부를 검증하는 소프트웨어 테스트 기법 |
| 목적 | 머신러닝, 검색엔진, 수치해석, 컴퓨터 비전 등 정답 계산이 불가능한 복잡계 소프트웨어의 결함 검출 |

## Ⅱ. 메타모픽 테스트의 핵심 특징

| 특징 | 의미 |
|---|---|
| 테스트 오라클 극복 | 사전 기대 결과값 없이도 소프트웨어의 논리적 모순과 이상 결함을 검출 가능 |
| 후속 케이스 자동 생성 | 메타모픽 변형 함수($T$)를 통해 무수히 많은 파생 테스트 케이스를 자동화 양산 |
| 도메인 지식의 공식화 | 시스템이 만족해야 할 대칭성, 단조성, 동등성, 불변성 등의 비즈니스 규칙을 수식화 |
| AI/자율주행 특화 | 자율주행 영상 인식, LLM 응답 일관성 등 확률적 비결정론적 시스템 검증에 최적화 |

## Ⅲ. 메타모픽 테스트 메커니즘 및 4단계 수행 프로세스

### 메타모픽 테스트 구조 및 판정 흐름

```text
                        ┌─────────────────────────────────────┐
                        │ 1단계: 도메인 기반 메타모픽 관계 정의 │
                        │  (MR: f(T(x)) == g(f(x)))           │
                        └──────────────────┬──────────────────┘
                                           │
         ┌─────────────────────────────────┴─────────────────────────────────┐
         ▼                                                                   ▼
┌────────────────────────┐                                         ┌────────────────────────┐
│ 원본 테스트 케이스 (x)  │ ── [입력 변형 함수 T(x) 적용] ──────────→ │ 후속 테스트 케이스 (x') │
└───────────┬────────────┘                                         └───────────┬────────────┘
            │                                                                  │
            ▼ (프로그램 실행 f)                                                 ▼ (프로그램 실행 f)
┌────────────────────────┐                                         ┌────────────────────────┐
│ 원본 실행 결과 f(x)    │                                         │ 후속 실행 결과 f(x')   │
└───────────┬────────────┘                                         └───────────┬────────────┘
            │                                                                  │
            └──────────────────────────────┬───────────────────────────────────┘
                                           ▼
                        ┌─────────────────────────────────────┐
                        │ 4단계: 메타모픽 관계(MR) 충족 검증    │
                        │  - 관계 만족 (PASS) : 테스트 성공   │
                        │  - 관계 위반 (FAIL) : 소프트웨어 결함 │
                        └─────────────────────────────────────┘
```

### 4단계 수행 절차 및 세부 활동

| 단계 | 활동 명칭 | 세부 수행 내용 |
|---|---|---|
| **1단계** | **MR 식별 및 정의** | 대상 시스템 도메인의 수학적 성질(동등, 단조, 대칭) 및 불변 법칙을 기반으로 검증 공식 수립 |
| **2단계** | **원본 케이스 생성 및 실행** | 기본 입력값($x$)을 무작위 생성(Random) 또는 경계값 분석으로 준비하고 실행하여 결과 $f(x)$ 획득 |
| **3단계** | **후속 케이스 도출 및 실행** | 정의된 입력 변환 함수($T$)를 $x$에 적용하여 파생 입력값 $x'=T(x)$를 생성하고 실행하여 $f(x')$ 획득 |
| **4단계** | **메타모픽 관계 검증** | 원본 결과와 후속 결과가 사전 정의한 관계($MR$)를 만족하는지 검사하고 위반 시 결함 리포트 발행 |

## Ⅳ. 메타모픽 관계(MR) 4대 유형 및 전통적 테스팅 비교

### 메타모픽 관계(MR)의 4대 핵심 분류

| MR 분류 | 핵심 성질 및 수식 | 구체적 입력 변형 및 기대 결과 | 적용 도메인 |
|---|---|---|---|
| **동등성 (Equivalence)** | $f(T(x)) = f(x)$ | 검색 쿼리에서 공백 추가나 대소문자 변환 후 검색 결과 건수 불변 | 검색엔진, 데이터베이스 |
| **대칭성 (Symmetry)** | $f(x, y) = f(y, x)$ | 무방향 그래프에서 출발지와 도착지를 바꾸어도 최단 경로 비용 동일 | 내비게이션, 최단경로 알고리즘 |
| **단조성 (Monotonicity)** | $x_1 \le x_2 \implies f(x_1) \le f(x_2)$ | 대출 심사에서 연소득 조건을 상향했을 때 신용 한도는 감소하지 않아야 함 | 금융 심사 시스템, 추천 모델 |
| **불변성 (Invariance)** | $Class(T(x)) = Class(x)$ | 자율주행 카메라 영상에 가벼운 노이즈(비, 안개)를 합성해도 표지판 분류 동일 | 자율주행 비전 인식, 딥러닝 |

### 전통적 테스트 vs 메타모픽 테스트 비교

| 비교 항목 | 전통적 테스트 (Traditional Testing) | 메타모픽 테스트 (Metamorphic Testing) |
|---|---|---|
| **테스트 오라클 의존성** | 각 입력에 대한 **절대적 정답(기대값) 사전 정의 필수** | 절대적 정답 불필요, **실행 결과 간의 상대적 관계 검증** |
| **테스트 케이스 생성** | 테스터가 입력과 기대값을 수작업으로 1:1 매핑 | 하나의 원본 케이스로부터 수많은 후속 케이스 자동 파생 |
| **적용 제약** | 복잡한 수치 계산 및 AI 등 정답 산출 불가 시 적용 불가 | 오라클이 없는 비결정론적 복잡계 소프트웨어에 탁월 |
| **주요 한계** | 오라클 작성에 막대한 시간과 비용 소모 | 잘못된 MR 정의 시 결함 누락 위험, 도메인 전문성 필수 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 부적절하거나 지나치게 단순한 MR 설정으로 인해 시스템 내부 심각 결함 미검출 | 독립된 복수의 MR(대칭성+단조성+불변성)을 체인 형태로 교차 적용하는 복합 MR 구성 |
| 변형 함수 적용 시 후속 테스트 케이스의 무한 증식으로 인한 실행 시간 폭증 | 입력 도메인 커버리지 기반 선별적 샘플링 및 위험도 기반 후속 케이스 실행 제한 |
| 머신러닝 부동소수점 연산 및 확률적 추론에 따른 미세한 결과 편차로 인한 오탐 발생 | 완전 일치가 아닌 도메인 허용 오차 범위($\epsilon$-Tolerance)를 허용하는 통계적 판정 기준 수립 |

## Ⅵ. 제언

CI/CD 파이프라인 연계 메타모픽 테스트 자동화 및 생성형 AI 기반 MR 도출 프레임워크

### CI/CD 연계 메타모픽 자동화 파이프라인

```text
[AI 모델 / 알고리즘 코드 커밋]
       ↓
[CI 파이프라인 트리거]
  ├─ 1. 원본 테스트 데이터셋 로드 및 실행
  ├─ 2. Data Augmentation 기법 활용 후속 케이스 자동 변형
  ├─ 3. 분산 클러스터에서 원본/후속 병렬 추론 실행
  └─ 4. MR 판정 엔진: 통계적 허용 오차(Tolerance) 기반 불변식 검증
       ↓
[MR 위반율 0% 달성 시 모델 레지스트리 자동 승인 및 배포]
```

### 메타모픽 관계(MR) 설계 의사결정 체계

```text
소프트웨어 검증 대상 분석
       ↓
[단일 입력에 대한 명확한 테스트 오라클이 존재하는가?]
       ├─ 예 ──→ 전통적 단정문(Assertion) 기반 단위/통합 테스트 수행
       └─ 아니오 (AI, 비전, 수치해석) ─→ 메타모픽 테스팅 적용 결정
                                            ↓
                               [입력 도메인 특성 분석]
                                ├─ 대칭성 관계 도출 가능? ──→ Symmetry MR 설계
                                ├─ 노이즈 무관성 요구? ────→ Invariance MR 설계
                                └─ 입력 증가에 비례? ─────→ Monotonicity MR 설계
```

### 선택 근거: 수작업 오라클 검증과 메타모픽 테스트 자동화 비교

| 구분 | 수작업 오라클 구축 (Human-in-the-Loop) | 제언: 메타모픽 테스팅 자동화 |
|---|---|---|
| 테스트 비용 | 대규모 데이터 라벨링에 막대한 인력과 비용 발생 | 변형 함수 기반으로 수만 개의 테스트 케이스 자동 생성 |
| 지속적 검증 속도 | 모델 재학습 시마다 수작업 재검증으로 배포 병목 초래 | CI 파이프라인에서 수 분 내에 대규모 회귀 검증 완료 |
| 검증 커버리지 | 사람이 예측 가능한 일반적 시나리오에 국한 | 극단적 입력 변형을 통한 에지 케이스(Corner Case) 발굴 |
