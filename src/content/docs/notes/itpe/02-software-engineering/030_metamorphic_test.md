## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 테스트·검증 → **메타모픽 테스트(Metamorphic Test)**

## 30초 인출

- 본질: 메타모픽 테스트는 정답(오라클)을 알 수 없을 때 입력을 바꾼 결과들 사이에 성립해야 하는 관계(메타모픽 관계)로 오류를 찾는 테스트
- 메커니즘: 메타모픽 관계를 정의하고 원본 입력을 실행한 뒤 관계에 따라 후속 입력을 만들어 실행하고 두 결과가 관계를 만족하는지 검증
- 통찰: 메타모픽 관계가 하나뿐이면 관계를 만족하는 결함을 놓치므로 입력 유형별로 여러 관계를 정의하고 기존 테스트와 병행

<details>
<summary>핵심 용어</summary>

- **테스트 오라클 문제(Test Oracle Problem)** : 입력에 대한 정확한 기대 출력을 알 수 없어 결과의 옳고 그름을 판정하기 어려운 문제
- **메타모픽 테스트(Metamorphic Testing)** : 개별 결과의 정답 대신 입력 변화와 출력 변화 사이의 관계로 검증하는 기법
- **메타모픽 관계(MR, Metamorphic Relation)** : 입력을 변형했을 때 출력 사이에 성립해야 하는 관계
- **원본 테스트 케이스(Source Test Case)** : 처음 실행하는 기준 입력
- **후속 테스트 케이스(Follow-up Test Case)** : 메타모픽 관계로 원본에서 만든 변형 입력

</details>

## 2~4교시 25점 답안

## Ⅰ. 메타모픽 테스트의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **메타모픽 테스트** 는 입력을 바꿨을 때 출력 사이에 성립해야 하는 관계로 오류를 찾는 테스트 |
| 목적 | 테스트 오라클을 알 수 없는 소프트웨어의 검증 |

## Ⅱ. 전통적 테스트와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 오라클 불필요 | 정답 없이 결과 간 관계로 판정 |
| 입력 자동 생성 | 원본에서 후속 입력을 규칙으로 생성 |
| 적용 대상 | 머신러닝·과학 계산·검색 등 정답 판정이 어려운 소프트웨어 |

## Ⅲ. 등장 배경과 수행 절차

### 등장 배경: 테스트 오라클 문제

```text
입력 → 소프트웨어 → 출력
                     ↓
              정답을 알 수 없음 → 옳고 그름 판정 불가
                     ↓
              결과 간 관계로 검증하는 메타모픽 테스트
```

### 메타모픽 테스트 수행 절차

```text
메타모픽 관계 정의
    ↓
원본 케이스 실행 → 결과 기록
    ↓
관계에 따라 후속 케이스 생성·실행
    ↓
두 결과의 관계 검증
    ├─ 만족 → 통과
    └─ 위반 → 결함 후보
```

## Ⅳ. 메타모픽 관계 사례와 전통적 테스트의 비교

### 메타모픽 관계 사례

| 대상 | 변형 | 성립 관계 |
|---|---|---|
| 사인 함수 | x를 π−x로 변환 | sin(x)와 sin(π−x) 동일 |
| 이미지 분류 모델 | 밝기를 약간 조정 | 분류 결과 동일 |
| 검색 | 조건을 추가 | 결과가 기존 결과의 부분집합 |

### 전통적 테스트와의 비교

| 구분 | 전통적 테스트 | 메타모픽 테스트 |
|---|---|---|
| 판정 기준 | 기대 출력(오라클) | 결과 간 관계 |
| 케이스 작성 | 케이스별 기대값 필요 | 관계 정의 후 자동 생성 |
| 적합 대상 | 정답이 명확한 기능 | 정답 판정이 어려운 소프트웨어 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 메타모픽 관계 도출의 난이도 | 도메인 전문가와 함께 입력 유형별 관계 목록 작성 |
| 관계를 만족하는 결함의 미검출 | 여러 관계를 조합하고 기존 테스트 병행 |
| 관계 위반의 원인 파악 곤란 | 위반 케이스의 원본·후속 입력 기록과 재현 |

## Ⅵ. 제언

입력 유형마다 서로 다른 메타모픽 관계를 여러 개 정의하고, 정답이 있는 영역의 기존 테스트와 병행

### 관계 확장 절차

```text
입력 유형 분류
    ↓
유형별 메타모픽 관계 2개 이상 정의
    ↓
후속 케이스 자동 생성·검증
```

### 선택 근거: 단일 관계 적용과의 비교

| 구분 | 단일 관계 | 제언: 다수 관계 |
|---|---|---|
| 결함 검출 범위 | 좁음 | 넓음 |
| 작성 비용 | 낮음 | 높음 |
| 오탐 위험 | 관계 오류에 민감 | 상호 확인 |
