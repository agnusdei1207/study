## 연관 키워드

- 메타모픽 테스트(Metamorphic Testing), 테스트 오라클 문제(Test Oracle Problem), 메타모픽 관계(MR, Metamorphic Relation)
- 소스·후속 테스트 케이스, 속성 기반 테스팅(Property-Based Testing), SBFL(Spectrum-Based Fault Localization), 퍼징(Fuzzing), MLOps(Machine Learning Operations)

## Ⅰ. 메타모픽 테스트의 개요

- 핵심 요약 : 기대 출력을 사전에 정의하기 어려운 환경에서, 입력 변형에 따른 출력 간 불변 관계로 결함을 찾는 테스팅 기법.
- 개념 : 개별 입력의 기대 출력값(테스트 오라클)을 미리 정하기 어려운 **테스트 오라클 문제** (Test Oracle Problem)를 해결하기 위해, 입력을 변형했을 때 출력 사이에 성립해야 하는 불변 관계인 **메타모픽 관계** (MR, Metamorphic Relation)를 기준으로 결함을 찾는 **메타모픽 테스트** (Metamorphic Testing) 기법.
- 배경 및 필요성 : AI(Artificial Intelligence) 모델, 검색 엔진, 컴파일러, 복잡한 수치 시뮬레이션은 특정 입력의 정답을 사람이 미리 알기 어려워, 입출력 매칭 방식의 전통적 테스트로는 검증에 한계가 있음.
- 주요 목적 : 오라클이 없는 환경에서 자동화된 결함 검출과 AI 시스템의 품질 검증.

## Ⅱ. 메타모픽 테스트의 특징 및 장점

- 핵심 요약 : 소스 입력과 후속 입력의 쌍을 관계로 비교하여 오라클 의존성을 제거하는 방식.

1. 오라클 대체 : 기대 출력을 몰라도 두 출력의 관계만 검증하면 되므로 테스트 오라클 문제를 우회 → 정답이 없는 시스템도 테스트 가능.
2. 테스트 케이스 쌍 구성 : 원본 입력 x와 변형 입력 x'을 쌍으로 만들어 같은 시스템의 두 출력 f(x), f(x')를 비교 → 비교 기준의 객관성 확보.
3. 변형 규칙 기반 관계 검증 : 입력 변형 규칙에 따라 f(x)와 f(x') 사이에 MR이 성립하는지 확인 → 결함 판정 기준 확보.
4. 도메인 지식 활용 : 변형 규칙과 MR을 해당 분야의 지식으로 도출 → 결함 검출력이 도메인 이해도에 비례.
5. 테스트 규모 확장 : 기존 입력을 재활용해 후속 입력을 대량 생성 → 무인 자동화 테스트로 확장 용이.

## Ⅲ. 메타모픽 테스트의 구조 (흐름)

- 핵심 요약 : 변형 규칙으로 후속 입력을 만들고, 두 출력이 MR을 만족하는지로 결함을 판정하는 흐름.

```text
[ 메타모픽 테스트의 검증 구조 ]

소스 입력 x ──실행──> f(x)
   ↓ 변형 규칙 적용
후속 입력 x' ──실행──> f(x')
   ↓
f(x)와 f(x')의 MR 만족 여부 검증
```

```text
[ 메타모픽 테스트 실행 흐름 ]

1. 소스 입력 생성 (x)
   ↓
2. 변형 규칙 적용으로 후속 입력 생성 (x')
   ↓
3. 시스템 실행 (f(x), f(x'))
   ↓
4. MR 만족 여부 검증
   ↓
5. MR 위반 시 결함 보고
```

MR의 구체적 예시는 다음과 같다.

1. 삼각함수 : sin(x)와 sin(π−x)의 값은 같아야 함.
2. 정렬 알고리즘 : 입력 원소의 순서를 바꾸어도 정렬 결과가 동일해야 함.
3. 검색 엔진 : 검색어 '머신러닝'의 결과 집합은 '머신러닝 AND 인공지능'의 결과 집합을 반드시 포함(f(A) ⊇ f(A∧B)).
4. 자율주행 영상인식 : 원본 주간 영상에 약한 조명 변화를 준 영상에서도 보행자 인식 결과가 유지되어야 함.

## Ⅳ. 전통적 테스트와 메타모픽 테스트의 비교

- 핵심 요약 : 오라클과 입출력을 매칭하는 방식에서 출력 간 관계를 검증하는 방식으로의 패러다임 전환.

| 비교 항목 | 전통적 테스트 기법 | 메타모픽 테스트 |
| --- | --- | --- |
| 정답 판별 기준 | 테스트 오라클 (사전 정의된 기대값 y) | 메타모픽 관계 (출력 간 일관성 관계 MR) |
| 오라클 의존성 | 오라클이 없으면 테스트 수행 불가 | 오라클이 없어도 자동 테스트 가능 |
| 테스트 케이스 도출 | 경계값 분석, 동등 분할 등 입력 중심 | 소스 입력과 도메인 지식 기반 변형 규칙 |
| 결함 탐지 방식 | f(x) = y 여부 비교 | MR(f(x), f(x')) 만족 여부 검증 |
| 주 활용 분야 | 계좌 입출금, CRUD(Create, Read, Update, Delete) 등 정형 업무 | AI, LLM(Large Language Model), 그래픽 렌더링, 과학 연산 |

## Ⅴ. 메타모픽 테스트의 한계와 방안

- 핵심 요약 : MR 도출의 난이도, 입력 유효성 훼손, 결함 위치 추적의 어려움을 도메인 협업, 제약 필터, 스펙트럼 분석으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 도메인 특화 MR 도출 난이도 | 참값 기준이 없는 AI, 자율주행, 물리 시뮬레이션에서 결함 검출력이 높은 변형 규칙 정의에 고도의 도메인 지식이 필요 | 속성 기반 테스팅(Property-Based Testing) 프레임워크와 결합하고, 과거 결함 패턴 분석과 LLM을 활용해 MR 후보를 보조 생성 | MR 후보의 채택률 |
| 입력 유효성 훼손 | 변형 과정에서 입력 도메인의 제약을 벗어나 무의미한 실패가 생기고 거짓 양성(False Positive) 발생 | 제약 조건 솔버(Constraint Solver)와 스키마 검증기를 파이프라인에 넣어 변형 결과가 도메인 불변식을 지키도록 필터링 | 거짓 양성 비율 |
| 결함 위치 추적의 복잡성 | MR 위반이 감지되어도 원본과 변형 실행 중 어디서 오류가 시작되었는지 찾기 어려움 | SBFL(Spectrum-Based Fault Localization)을 메타모픽 실행 프로파일에 적용해 의심도가 높은 코드 블록을 우선 표시 | 상위 순위 결함 위치 적중률 |

## Ⅵ. AI 시스템 테스팅 관점에서의 기술사적 제언

- 핵심 요약 : 도메인 전문가와 함께 MR을 체계적으로 정형화하고, 퍼징과 연결된 자동화 파이프라인을 구축하는 방향이 필요.

1. 도메인 특화 MR의 체계적 정형화 : 테스트의 성패가 올바른 MR 발굴에 달려 있으므로, 도메인 전문가와 협업해 대칭성, 불변성, 가법성, 단조성 같은 관계 유형을 기준으로 MR 목록을 체계화해야 한다.
2. 자동화 파이프라인 구축 : **퍼징** (Fuzzing) 도구의 변이 엔진으로 후속 입력을 대량 생성하고 MR 위반을 지속 모니터링하는 MLOps(Machine Learning Operations) 품질 게이트를 두는 것이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : 메타모픽 테스트는 테스트 오라클 문제를 관계 검증으로 전환해 AI 시스템의 품질 검증을 가능하게 하는 기법.
- 시사점 : MR 정형화의 품질이 기법의 효과를 좌우하므로, 퍼징과 결함 위치 추적을 묶은 검증 체계로 확장하는 것이 필요함.
