## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 테스트·검증 → **임베디드 소프트웨어 테스트 및 X-in-the-Loop(MIL·SIL·PIL·HIL)**

## 30초 인출

- 본질: 임베디드 소프트웨어 테스트는 특정 하드웨어에서 실시간으로 동작하는 소프트웨어를 실제 장비 없이도 단계적으로 검증하는 테스트이며 MIL·SIL·PIL·HIL이 대표
- 메커니즘: 제어 모델(MIL)에서 생성 코드(SIL)로, 타깃 프로세서(PIL)에서 실제 제어기와 모사 환경(HIL)으로 검증 대상을 실제에 가깝게 옮겨 가며 시험
- 통찰: 실제 하드웨어와 위험 상황은 시험하기 어렵고 늦게 발견한 결함의 수정 비용이 크므로 모델·코드 단계에서 먼저 시험하고 실제 제어기는 HIL에서 결함 주입으로 검증

<details>
<summary>핵심 용어</summary>

- **임베디드 소프트웨어** : 특정 하드웨어에 내장되어 정해진 기능을 실시간으로 수행하는 소프트웨어
- **XiL(X-in-the-Loop)** : 모델·소프트웨어·프로세서·하드웨어를 시뮬레이션 루프에 넣어 검증하는 방식의 총칭
- **MIL(Model-in-the-Loop)** : 제어 알고리즘 모델을 시뮬레이션으로 검증하는 단계
- **SIL(Software-in-the-Loop)** : 생성·작성한 코드를 개발 PC에서 시뮬레이션과 함께 검증하는 단계
- **PIL(Processor-in-the-Loop)** : 실제 타깃 프로세서에 코드를 올려 검증하는 단계
- **HIL(Hardware-in-the-Loop)** : 실제 제어기를 모사한 환경(센서·액추에이터)과 연결해 검증하는 단계
- **WCET(Worst-Case Execution Time)** : 태스크의 최악 실행 시간

</details>

## 2~4교시 25점 답안

## Ⅰ. 임베디드 소프트웨어 테스트의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **임베디드 소프트웨어 테스트** 는 하드웨어에 내장되어 실시간으로 동작하는 소프트웨어를 검증하는 테스트 |
| 목적 | 하드웨어 종속·실시간 제약에서 발생하는 결함의 조기 발견 |

## Ⅱ. 일반 소프트웨어 테스트와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 하드웨어 종속 | 타깃 장비의 프로세서·입출력에 의존 |
| 실시간 제약 | 시간 내 응답(WCET)의 검증 필요 |
| 시험 환경 제약 | 실제 장비·위험 상황의 시험 곤란 |

## Ⅲ. XiL 검증 단계

### XiL 단계의 흐름

```text
MIL: 제어 알고리즘 모델 시뮬레이션
    ↓ 코드 생성
SIL: 생성 코드를 PC에서 시뮬레이션과 시험
    ↓ 타깃에 탑재
PIL: 실제 프로세서에서 코드 실행 시험
    ↓ 제어기 연결
HIL: 실제 제어기 + 센서·액추에이터 모사 환경
```

### 확대: HIL 구성

```text
시험 시나리오 → HIL 시뮬레이터(센서 신호 모사)
                    ↓
              실제 제어기(ECU)
                    ↓ 제어 출력
              HIL 시뮬레이터(플랜트 모델) → 응답 판정
```

## Ⅳ. 단계별 비교와 테스트 유형

### XiL 단계의 비교

| 단계 | 검증 대상 | 실행 환경 | 발견 결함 |
|---|---|---|---|
| MIL | 제어 알고리즘 모델 | 시뮬레이션 도구 | 설계 오류 |
| SIL | 소스 코드 | 개발 PC | 코드 오류 |
| PIL | 타깃 프로세서 코드 | 실제 프로세서 | 컴파일러·프로세서 차이 |
| HIL | 실제 제어기와 통합 | 모사 환경 | 하드웨어 통합·타이밍 결함 |

### 임베디드 특화 테스트

| 테스트 | 내용 |
|---|---|
| 실시간 성능 | WCET·데드라인 준수 |
| 결함 주입 | 센서 단선·메모리 오류 주입 후 대응 확인 |
| 자원 사용 | 메모리·CPU 사용량 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 실제 장비·위험 상황 시험 곤란 | HIL에서 모사 환경으로 시험 |
| 후반 통합 단계에서 결함 발견 | MIL·SIL 단계에서 조기 시험 |
| 하드웨어 종속으로 시험 환경 구축 비용 | 시뮬레이터 재사용과 단계별 시험 자동화 |

## Ⅵ. 제언

모델과 코드 단계(MIL·SIL)에서 결함을 먼저 제거하고, 실제 제어기는 HIL에서 결함 주입과 실시간 성능을 검증

### 단계 배분

```text
MIL·SIL: 알고리즘·코드 결함 제거 (저비용)
    ↓
PIL·HIL: 타깃·통합·실시간 검증 (고비용)
```

### 확대: HIL 검증 항목

```text
정상 시나리오 → 결과 확인
결함 주입(센서 단선·메모리 오류) → 안전 동작 확인
실시간 성능 → WCET·데드라인 확인
```

### 선택 근거: 후반 통합 시험 집중과의 비교

| 구분 | 후반 통합 시험 집중 | 제언: 단계별 XiL |
|---|---|---|
| 결함 발견 시점 | 후반 | 초기 |
| 수정 비용 | 큼 | 작음 |
| 위험 상황 시험 | 곤란 | HIL에서 모사 |
