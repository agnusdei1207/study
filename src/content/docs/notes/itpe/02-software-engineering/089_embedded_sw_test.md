## 30초 인출

- 본질: **임베디드 소프트웨어 테스트** 는 마이크로컨트롤러(MCU), 센서, 액추에이터 등 물리적 하드웨어와 강결합되어 동작하는 임베디드 시스템의 기능 정확성, 실시간 제어 주기, 최악 실행 시간(WCET), 결함 내구성을 가상 모델부터 실물 제어기 단계까지 점진적으로 검증하는 테스팅 체계
- 메커니즘: 모델 기반 알고리즘 검증(MIL) → 호스트 PC 소스코드 실행 검증(SIL) → 타깃 프로세서 컴파일 바이트코드 검증(PIL) → 실시간 플랜트 시뮬레이터 결합 실물 제어기 검증(HIL)
- 통찰: 호스트 시뮬레이션 환경만으로는 타깃 MCU의 컴파일러 최적화 차이, 인터럽트 지연, 버스 병목을 완벽히 포착하기 어려우므로 ISO 26262 기능안전 규격에 따라 결함 주입(FIT)과 HIL 기반 실시간 계측 테스트베드를 통합 구축할 필요가 있음

<details>
<summary>핵심 용어</summary>

- **XiL (X-in-the-Loop)** : 모델, 소프트웨어, 프로세서, 하드웨어를 시뮬레이션 루프에 연결하여 단계별로 검증하는 V-모델 테스트 프레임워크
- **MIL (Model-in-the-Loop)** : Simulink 등 모델링 도구에서 수학적 제어 알고리즘의 동작 타당성을 가상 시뮬레이션하는 기법
- **SIL (Software-in-the-Loop)** : 자동 생성되거나 수동 작성된 C/C++ 소스코드를 개발 호스트 PC 환경에서 기능 검증하는 기법
- **PIL (Processor-in-the-Loop)** : 실제 타깃 보드(DSP/MCU) 환경에 코드를 다운로드하여 명령어 세트와 컴파일러 최적화 영향을 검증하는 기법
- **HIL (Hardware-in-the-Loop)** : 실제 ECU(제어기) 하드웨어에 센서/모터/엔진을 모사한 실시간 플랜트 시뮬레이터를 연결하여 검증하는 시험
- **WCET (Worst-Case Execution Time)** : 특정 태스크가 최악의 실행 조건에서 데드라인을 위반하지 않는지 보증하는 최대 실행 시간
- **결함 주입 테스트 (FIT: Fault Injection Testing)** : 센서 단선, 단락, 메모리 비트 반전 등 하드웨어 고장 상황을 강제로 유발하여 안전 상태(Safe State) 전이를 확인하는 기법

</details>

## 2~4교시 예상문제 (25점)

> 안전-치명적(Safety-Critical) 임베디드 시스템의 신뢰성 검증을 위한 임베디드 소프트웨어 테스트의 특수성을 설명하고, X-in-the-Loop(MIL, SIL, PIL, HIL)의 단계별 검증 대상, 환경 및 메커니즘을 비교하며 실시간성(WCET) 및 결함 주입(FIT) 검증 방안을 제시하시오.

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 제한된 하드웨어 자원(CPU, 메모리)과 물리적 외부 환경(센서, 액추에이터)과 상호작용하는 제어 소프트웨어의 기능적 정합성, 시간 제약성, 안전성을 검증하는 공학 활동 |
| 목적 | 물리적 시제품 제작 전 조기 결함 발견(Shift-Left), 하드웨어 종속 결함(타이밍, 인터럽트) 격리, ISO 26262/DO-178C 기능안전 인증 획득 |

## Ⅱ. 핵심 특징

일반 엔터프라이즈 소프트웨어 테스트와 달리 하드웨어와의 강결합 및 결정론적 실시간성 보장이 필수적.

| 핵심 속성 | 공학적 세부 특징 | 검증 메커니즘 |
|---|---|---|
| **하드웨어 제약성 (Resource Constraint)** | 메모리(ROM/RAM) 부족, 저전력 MCU 아키텍처 환경 | 정적 메모리 누수 분석, 스택 오버플로우 한계치 측정 |
| **엄격한 실시간성 (Hard Real-time)** | 정해진 주기(Period)와 데드라인(Deadline) 위반 시 시스템 재난 발생 | 오실로스코프 계측, 최악 실행 시간(WCET) 정적/동적 분석 |
| **환경 상호작용 (Physical Interaction)** | 연속적 아날로그 신호, PWM 제어, CAN/LIN 차량 통신 연동 | AD/DA 컨버터 계측, 통신 버스 트래픽 모니터링 |
| **비결정적 동시성 (Concurrency)** | 비동기 하드웨어 인터럽트(ISR)와 멀티태스크 간 경합 | 레이스 컨디션, 데드락, 공유 자원 원자성 검증 |

## Ⅲ. 체계·프로세스

V-모델 기반의 X-in-the-Loop(MIL $\rightarrow$ SIL $\rightarrow$ PIL $\rightarrow$ HIL) 단계적 검증 체계.

```text
[임베디드 XiL(X-in-the-Loop) 단계적 검증 아키텍처]
[1] MIL (Model-in-the-Loop)
  +─────────────────────────+          가상 신호 교환          +─────────────────────────+
  | 제어 알고리즘 모델      | <──────────────────────────────> | 수학적 플랜트 시뮬레이션|
  | (Simulink Block Model)  |                                  | (가상 물리 차량/엔진)   |
  +─────────────────────────+                                  +─────────────────────────+
               │
               ▼ C/C++ 자동 코드 생성 (Auto-coding)
  [2] SIL (Software-in-the-Loop)
  +─────────────────────────+          소프트웨어 루프         +─────────────────────────+
  | 호스트 실행 소스코드    | <──────────────────────────────> | 가상 환경 모사기        |
  | (x86/x64 환경 컴파일)   |                                  | (Host PC Simulation)    |
  +─────────────────────────+                                  +─────────────────────────+
               │
               ▼ 타깃 크로스 컴파일러 빌드 (Cross-compilation)
  [3] PIL (Processor-in-the-Loop)
  +─────────────────────────+          JTAG / 디버거 통신      +─────────────────────────+
  | 실제 타깃 프로세서/보드 | <──────────────────────────────> | 호스트 플랜트 모델      |
  | (ARM Cortex / TriCore)  |                                  | (비실시간 가상 신호)    |
  +─────────────────────────+                                  +─────────────────────────+
               │
               ▼ 실제 제어기 롬 플래싱 (ECU Flashing)
  [4] HIL (Hardware-in-the-Loop)
  +─────────────────────────+          물리 전기 신호 (실시간) +─────────────────────────+
  | 완성된 실물 ECU 제어기   | <──────────────────────────────> | 실시간 플랜트 시뮬레이터|
  | (실제 하드웨어 & 회로)  |     (CAN / 전압 / 전류 / PWM)    | (dSPACE / NI PXI 등)    |
  +─────────────────────────+                                  +─────────────────────────+
```

- **XiL 4단계 프로세스 동작 규칙**:
  1. **MIL 단계** : 요구사항 명세를 바탕으로 알고리즘 제어 로직을 블록 다이어그램으로 설계하고 요구 정합성 검증.
  2. **SIL 단계** : 자동 생성된 소스코드가 모델과 100% 동일하게 동작하는지 역-대-역(Back-to-Back) 비교 테스트 수행.
  3. **PIL 단계** : 타깃 프로세서 환경에 코드를 탑재하여 부동소수점 오차, 컴파일러 최적화 부작용, 스택 사용량 검증.
  4. **HIL 단계** : 실물 ECU에 I/O 인터페이스를 연결하고 가상 주행 조건 및 전기적 결함(센서 단선 등)을 인가하여 종합 안전성 검증.

## Ⅳ. 종류·비교

#### X-in-the-Loop (MIL vs SIL vs PIL vs HIL) 4대 단계 비교

| 비교 항목 | MIL (Model) | SIL (Software) | PIL (Processor) | HIL (Hardware) |
|---|---|---|---|---|
| **제어기 대상** | 제어 알고리즘 모델 | 호스트 컴파일 C/C++ | 타깃 보드 탑재 바이너리 | **완성된 실물 ECU 하드웨어** |
| **플랜트 환경** | 수식 기반 가상 모델 | 소프트웨어 모사 환경 | 소프트웨어 모사 환경 | **실시간 하드웨어 시뮬레이터** |
| **실행 플랫폼** | 개발 PC 시뮬레이터 | 호스트 개발 PC (x86) | 타깃 평가 보드 (EVB) | 실제 상용 제어기 (ECU) |
| **통신 인터페이스**| 가상 메모리 변수 교환 | 프로세스 간 통신 (IPC)| JTAG, UART, CAN | **실제 전기 배선 (전압/전류/CAN)** |
| **시간 정확도** | 가상 시간 (No Real-time)| 가상 시간 (No Real-time)| 타깃 실행 시간 측정 가능| **완벽한 하드 실시간 (Real-time)** |
| **핵심 검증 항목**| 제어 이론 및 수학적 오류| 코딩 결함 및 모델 일치성| 컴파일러 오류, WCET 분석| I/O 타이밍, 결함 주입, 안전성 |
| **구축 비용** | 매우 낮음 | 낮음 | 보통 | 매우 높음 (억 단위 전용 장비) |

#### 임베디드 핵심 동적 테스트 기법 비교

| 테스트 기법 | 핵심 개념 및 검증 방식 | 주요 검출 결함 |
|---|---|---|
| **최악 실행 시간(WCET) 분석** | 정적 제어 흐름 그래프(CFG) 분석 및 하드웨어 타이머 실측 결합 | 태스크 데드라인 초과, 주기 지연, 스케줄링 불능 |
| **결함 주입 테스트 (FIT)** | 전원 급단절, 신호 쇼트/단선, 메모리 비트 플립(SEU) 인위적 유발 | Fail-Safe 상태 천이 실패, 워치독 타이머 미동작 |
| **경계값 및 등가분할 시험** | 센서 입력 전압(0~5V)의 최소/최대/경계값 인가 | ADC 변환 언더플로우/오버플로우, 비정상 클램핑 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 호스트 환경(SIL)에서 정상 동작하던 로직이 타깃 MCU(PIL/HIL) 탑재 시 타이밍 오차로 오작동 | 타깃 프로세서 명령어 세트 시뮬레이터(ISS)를 조기 도입하고 정적 WCET 도구(aiT)로 실행 시간 상한 검증 |
| HIL 시뮬레이터 장비의 고가 비용과 제한된 수량으로 인한 개발 병목 현상 | 클라우드 기반 가상 가상화(Virtual ECU, vECU) 환경을 구축하여 SIL/PIL 단계에서 검증 커버리지 80% 사전 달성 |
| 물리적 환경의 센서 노이즈 및 간헐적 하드웨어 결함 재현 불가 | 자동화된 프로그래머블 결함 주입 하드웨어(Fault Injection Unit)를 HIL에 통합하여 재현성 확보 |

## Ⅵ. 제언

임베디드 소프트웨어의 신뢰성을 극대화하기 위해서는 V-모델 좌측의 모델/소프트웨어 단계에서 조기 검증을 강화(Shift-Left)하고, HIL 기반 자동화 회귀 테스트를 파이프라인으로 연결할 필요가 있음.

```text
[요구사항/제어모델] ──> [MIL 가상 시뮬레이션] ──> [SIL 자동코드 검증] ──> [PIL 타깃 타이밍] ──> [HIL 실시간 종합시험]
                           (알고리즘 결함 70% 제거)    (Back-to-Back 일치)     (WCET 마진 확보)        (결함주입 & 안전인증)
```

| 검증 단계 | 표준 준수 지침 | 핵심 관리 지표 |
|---|---|---|
| **모델 및 소스 검증** | MISRA-C/C++ 코딩 표준 준수 | 정적 분석 룰 위반 0건, MC/DC 커버리지 100% 달성 |
| **타깃 프로세서 검증** | 프로세서 의존적 데이터 타입/부동소수점 검증 | 타깃-호스트 간 연산 오차 제로 및 스택 점유율 70% 이하 |
| **실시간 통합 검증** | ISO 26262 ASIL-D 기능안전 시험 절차 이행 | 고장 주입 시 FTTI(Fault Tolerant Time Interval) 내 안전 복구 |
