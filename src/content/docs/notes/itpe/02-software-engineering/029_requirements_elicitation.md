## 연관 키워드
- 요구사항 도출, 이해관계자, 인터뷰, 설문조사
- 브레인스토밍, 워크숍(JAD), 관찰, 프로토타이핑

## Ⅰ. 요구사항 도출의 개요

- 핵심 요약 : 요구사항 도출은 이해관계자·문서·업무 현장에서 시스템 요구와 제약을 발견·수집하는 요구공학의 첫 단계.
- 개념 : **요구사항 도출**(Requirements Elicitation)은 **이해관계자**(Stakeholder, 이해당사자)·기존 문서·업무 현장에서 시스템에 대한 요구 후보와 제약을 발견·수집하는 활동.
- 배경 및 필요성 : 이해관계자가 요구를 완전·일관되게 표현하지 못하고 실무 지식은 진술 없이 내재되는 문제.
- 주요 목적 : 분석·명세 단계의 입력 품질 확보로 요구 누락·왜곡 최소화.

## Ⅱ. 요구사항 도출 기법의 특징 및 장점

- 핵심 요약 : 질문·협업·현장·시각화 계열의 조합이 다양한 요구 원천과 편향을 상호 보완.

1. 인터뷰·설문조사 : **인터뷰**(Interview)의 개별 심층 질의와 **설문조사**(Survey)의 다수 대상 수집 → 동기·예외 확인과 대상 확장.
2. 브레인스토밍·워크숍 : **브레인스토밍**(Brainstorming, 비판 보류의 자유 발상)과 **JAD**(Joint Application Development, 사용자·개발자 합동 세션) → 상충 요구 조정·합의 형성.
3. 관찰·문서 분석 : **관찰**(Observation)과 기존 규정·장표 확인 → 진술되지 않은 예외·우회 절차 발견.
4. 프로토타이핑 : **프로토타이핑**(Prototyping)의 시제품 피드백 → 추상 요구의 구체화.

## Ⅲ. 요구사항 도출의 구조 (흐름)

- 핵심 요약 : 대상·기법 선택부터 결과 검증·인계까지의 절차와 시제품 피드백 순환의 결합.

```text
도출 수행 절차

이해관계자·문제 영역 식별
   ↓
기법 선택 (인터뷰·관찰·워크숍 등)
   ↓
요구 수집·기록 (출처·맥락 포함)
   ↓
결과 검증 → 분석 단계 인계
```

```text
프로토타이핑 피드백 순환

초기 시제품 제시
   ↓
사용자 피드백 수집
   ↓
시제품 수정·재제시
   ↺ 요구 안정 시까지 반복
```

- 기록 항목 : 요구 내용, 출처, 발견 기법, 확인 상태.

## Ⅳ. 요구사항 도출과 요구사항 분석의 비교

- 핵심 요약 : 도출은 요구 후보와 근거를 넓히는 수집 단계, 분석은 모호성·상충을 정제하는 이후 단계.
- 비교 개요 : 요구사항 분석은 도출 결과를 분류·협상·모델링하는 요구공학의 다음 단계 활동.

| 비교 축 | 요구사항 도출 | 요구사항 분석 |
|---|---|---|
| 단계 위치 | 요구공학의 앞 단계 | 도출 이후 단계 |
| 목적 | 요구 후보·근거 확보 | 모호성·상충·실현성 해소 |
| 주요 활동 | 인터뷰·관찰·워크숍·프로토타이핑 | 분류·우선순위·모델링·협상 |
| 산출물 | 원시 요구 목록·기록 | 합의된 요구·우선순위·모델 |
| 품질 위험 | 누락·편향 | 모호성·불일관·비검증성 |

- 기법 구분 : **MoSCoW**(Must have·Should have·Could have·Won't have) 같은 우선순위 기법은 분석 단계의 활동으로 도출 기법과 구분.

## Ⅴ. 요구사항 도출의 한계와 방안

- 핵심 요약 : 대상 편중·진술 편향·시제품 고착·집단 압력을 표본 구성과 교차 확인으로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 이해관계자 편중 | 소수 직무 의견 반영 → 업무 공백 | 역할·빈도 기반 표본 구성 | 이해관계자 커버리지 |
| 진술·회상 편향 | 진술과 실무 불일치 → 왜곡된 요구 | 관찰·로그·문서 교차 확인 | 교차 확인 비율 |
| 시제품 고착 | 외형 중심 요구·품질 요구 누락 | 시제품 범위·미구현 항목 명시 | 비기능 요구 도출률 |
| 집단 압력 | 워크숍 소수 의견 억눌림 | 중립 진행자·익명 수집 병행 | 참여 직무 다양성 |

## Ⅵ. 요구사항 도출에 대한 제언

- 핵심 요약 : 기법 표준·참여 제도화·요구 저장소 체계로 도출 품질을 조직 수준에서 관리.

1. 요구 분석 조직은 기법 선택 기준과 요구 기록 양식(출처·확인 상태)을 방법론 표준에 수록.
2. 발주 기관은 현장 사용자 참여를 계약·일정 계획에 명시해 도출 참여 제도화.
3. 조직은 도출 결과를 요구 저장소로 통합 관리해 분석·명세 단계와의 인계 품질 추적 체계 운영.

## Ⅶ. 결론

- 핵심 요약 : 요구사항 도출은 다양한 원천의 교차 검증으로 잠재 요구를 발굴하는 협업 활동.
- 도출 결과는 이후 분석·명세·확인 단계의 입력이 되는 요구공학의 출발점.
