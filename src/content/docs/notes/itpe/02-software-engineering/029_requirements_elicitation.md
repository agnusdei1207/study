## 연관 키워드
- 요구사항 도출, 인터뷰, 설문, JAD, 관찰, 프로토타입, 브레인스토밍

### Ⅰ. 요구사항 도출의 개요

- 핵심 요약 : 요구사항 도출은 이해관계자·문서·업무환경에서 시스템 필요와 제약을 찾아 확인하는 활동.
- 개념 : 질문·관찰·워크숍·시제품 등 적합한 기법으로 명시적·잠재적 요구를 수집하고 근거를 기록(**요구사항 도출**, Requirements Elicitation).
- 배경 및 필요성 : 이해관계자는 요구를 완전하게 표현하지 못하거나 서로 다른 목표·용어를 사용할 수 있음.
- 주요 목적 : 업무문제·기대성과·예외·제약을 요구공학의 분석·명세 입력으로 확보.

### Ⅱ. 요구사항 도출 기법의 특징 및 장점

- 핵심 요약 : 직접질문·협업·시각화·현장관찰 기법을 조합해 다양한 요구 원천과 편향을 보완.

1. 인터뷰·설문 : 개인·집단 의견을 수집 → 심층 확인·대상 확장.
2. JAD·워크숍 : 이해관계자가 함께 충돌·우선순위 협의 → 합의 형성.
3. 프로토타입·유스케이스 : 화면·시나리오로 추상 요구 구체화 → 피드백 촉진.
4. 관찰·문서분석 : 실제 업무·기존 규정 확인 → 말로 표현되지 않은 예외 발견.

### Ⅲ. 기법 조합과 도출 흐름 (구조)

- 핵심 요약 : 준비·대상선정 → 자료수집 → 확인·우선순위화 → 결과검증·요구기록.

```text
문제·목표·이해관계자 식별
       ↓
인터뷰/설문 + 현장관찰/문서분석
       ↓
워크숍으로 충돌·우선순위 협의
       ↓
프로토타입·유스케이스 검증 → 요구기록·확인
```

```text
추상 요구 → 화면·프로토타입 → 사용자 피드백
      → 업무규칙·예외·품질요구 보강 → 검증된 요구
```

- MoSCoW는 도출기법이 아니라 수집 후 우선순위 분류에 쓰는 방법.

### Ⅳ. 요구사항 도출 기법 비교

- 핵심 요약 : 인터뷰는 심층·개별 맥락, 워크숍은 집단 합의, 관찰은 실제행동, 프로토타입은 시각적 피드백에 강점.

| 비교 축 | 인터뷰 | JAD/워크숍 | 관찰 | 프로토타입 |
|---|---|---|---|---|
| 강점 | 동기·예외·세부사항 탐색 | 상충 요구·우선순위 공동 합의 | 현장 실제업무·암묵지 확인 | 화면·흐름을 통한 구체 피드백 |
| 한계·적합조건 | 진행자 편향·시간 부담 | 참석자 권력차·인원 조정 필요 | 접근·표본·관찰자 영향 | 사용자가 시제품을 완성품으로 오해 가능 |

### Ⅴ. 요구사항 도출의 한계와 방안

- 핵심 요약 : 대표성·기억편향·집단압력·시제품 편향을 기법 다변화와 근거확인으로 줄임.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 특정 사용자 편중 | 일부 업무·접근성 요구 누락 | 역할·빈도·취약사용자별 표본 구성 | 사용자 대표성 |
| 회상·발언 편향 | 실제 업무와 진술 불일치 | 관찰·문서·시스템 로그 교차확인 | 교차검증률 |
| 프로토타입 고착 | 외형에 집중, 품질요구 누락 | 목적·범위·미구현 항목을 명시하고 비기능 요구 별도 질문 | 품질 요구 연결률 |

### Ⅵ. 요구 도출 제언

- 핵심 요약 : 분석가는 기법을 상황별로 조합하고 출처·맥락·확인상태를 요구기록에 남김.

1. 이해관계자 분석으로 역할·의사결정권·현장 사용자 범위를 확정.
2. 업무 관찰과 인터뷰를 병행해 정상·예외·우회절차를 검증.
3. 워크숍에서 우선순위를 합의하고 프로토타입·시나리오로 요구를 재확인.

### Ⅶ. 결론

- 핵심 요약 : 요구 도출은 단일 질문기법이 아니라 다양한 원천을 교차검증해 실제 필요를 발견하는 협업과정.
- 시사점 : 도출 결과는 분석·명세·검증을 통해 요구 기준선으로 정제되어야 함.
