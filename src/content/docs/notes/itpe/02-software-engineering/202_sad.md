## Ⅰ. 소프트웨어 아키텍처 기술서(SAD)의 개요

- **개념** : 시스템이 달성해야 하는 비즈니스 목표와 품질속성 요구사항을 충족시키기 위해 결정된 소프트웨어 아키텍처의 전반적인 구조, 컴포넌트 간의 상호작용, 설계 원칙, 기술 스택, 배포 토폴로지 및 트레이드오프 근거를 다양한 이해관계자의 관점(Viewpoint)에 맞추어 공식적으로 문서화한 최상위 아키텍처 설계 명세서.
- **배경 및 필요성** : 개발자, 아키텍트, 발주자, 운영자 간의 시스템 구조에 대한 오해를 방지하고, 프로젝트 전반의 기술적 의사결정의 기준선(Baseline)을 제공하여 아키텍처 침식(Erosion) 방지.
- **국제 표준** : ISO/IEC/IEEE 42010 (아키텍처 기술 표준 프레임워크).

## Ⅱ. IEEE 42010 기반 SAD 표준 프레임워크 및 크루첸 4+1 뷰 연계

```text
   ┌────────────────────────────────────────────────────────────────────────┐
   │ [ 아키텍처 기술서 (SAD) 핵심 목차 구조 ]                              │
   │                                                                        │
   │  1. 시스템 개요 및 비즈니스 배경 (Context & Mission)                   │
   │  2. 아키텍처 드라이버 (Architectural Drivers: 품질속성 유틸리티 트리)  │
   │  3. 이해관계자 및 관심사 (Stakeholders & Concerns)                    │
   │  4. 아키텍처 뷰 (Architectural Views: 4+1 View Model 연계)             │
   │     - 유스케이스 뷰 : 시스템 핵심 시나리오                             │
   │     - 논리 뷰       : 도메인 모델, 클래스 다이어그램, 계층 구조        │
   │     - 프로세스 뷰   : 동시성, 비동기 스레드, 성능, 트랜잭션 흐름       │
   │     - 구현 뷰       : 소스코드 디렉터리 구조, 빌드 모듈 의존성         │
   │     - 배포 뷰       : 클라우드 인프라, K8s 파드 배치, 망구성도         │
   │  5. 아키텍처 결정 기록 (ADR, Architectural Decision Records)          │
   └────────────────────────────────────────────────────────────────────────┘
```

## Ⅲ. SAD의 핵심 3대 구성요소 비교

| 구성요소 | 핵심 내용 및 기술 방식 | 주요 이해관계자 |
|---|---|---|
| 아키텍처 드라이버 (Drivers) | 시스템 설계에 결정적 영향을 미치는 고우선순위 기능/비기능 품질 시나리오 | 경영진, 발주자, 시스템 아키텍트 |
| 아키텍처 뷰 (Views) | 특정 관점(Viewpoint)에서 시스템의 관심사를 모델링한 다이어그램 및 설명 | 개발자, 인프라 엔지니어, 테스터 |
| 아키텍처 결정 기록 (ADR) | 기술 스택, 프레임워크, 패턴 선택의 이유와 탈락 대안, 트레이드오프 기록 | 후임 아키텍트, 신규 입사 개발자 |

## Ⅳ. 애자일 및 클라우드 환경에서의 기술사적 제언

- **수백 페이지의 '죽은 문서' 지양 및 마크다운 기반 Doc-as-Code 전환** : 프로젝트 초기에 한 번 쓰고 방치되는 두꺼운 워드 문서를 탈피하여, Git 저장소 내에 마크다운과 PlantUML/Mermaid 텍스트로 SAD를 작성하고 CI 파이프라인에서 HTML 문서로 자동 렌더링하는 살아있는 문서(Living SAD) 체계 확립.
- **공공 정보시스템 감리 시 기술적 아키텍처 증적 확립** : 정보시스템 감리 시 설계 적합성을 입증하기 위해, SAD 내에 비기능 요구사항(성능, 고가용성, 보안)과 배포 뷰 간의 매핑 관계를 명확히 제시하여 아키텍처 감리 지적 사항을 선제 방어해야 함.
