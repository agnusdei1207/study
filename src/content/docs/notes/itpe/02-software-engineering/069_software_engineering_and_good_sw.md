## 30초 인출

- 본질: 소프트웨어 공학은 소프트웨어를 체계적이고 계량 가능한 방법으로 개발·운영·유지보수하는 공학 분야이며 좋은 소프트웨어는 유지보수성·신뢰성과 보안성·효율성·사용 적합성을 갖춘 소프트웨어
- 메커니즘: 요구·설계·구현·시험·유지보수의 체계적 활동으로 품질 특성을 만들어 넣고 각 특성을 측정해 확인
- 통찰: 개발 후반에 품질 특성을 확인하면 수정 비용이 크므로 좋은 소프트웨어의 특성을 요구 단계에서 측정 가능한 기준으로 정하고 단계별로 검증

<details>
<summary>핵심 용어</summary>

- **소프트웨어 공학(Software Engineering)** : 소프트웨어의 개발·운영·유지보수에 체계적이고 정량적인 접근을 적용하는 학문
- **소프트웨어 위기(Software Crisis)** : 소프트웨어 규모·복잡도 증가로 일정·비용·품질 문제가 커진 현상
- **유지보수성(Maintainability)** : 변경 요구에 맞춰 소프트웨어를 수정하기 쉬운 정도
- **신뢰성과 보안성(Dependability and Security)** : 장애 없이 동작하고 악의적 접근으로부터 보호되는 정도
- **효율성(Efficiency)** : 자원을 낭비하지 않고 응답하는 정도
- **사용 적합성(Acceptability)** : 대상 사용자가 이해하고 사용할 수 있으며 다른 시스템과 호환되는 정도

</details>

## 2~4교시 25점 답안

## Ⅰ. 소프트웨어 공학의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **소프트웨어 공학** 은 소프트웨어를 체계적이고 정량적인 방법으로 개발·운영·유지보수하는 공학 분야 |
| 목적 | 일정·비용·품질 문제(소프트웨어 위기)의 해결 |

## Ⅱ. 소프트웨어의 특징과 소프트웨어 공학의 필요성

| 특징 | 의미 |
|---|---|
| 비가시성 | 물리적 형태가 없어 진척·품질 파악 곤란 |
| 복잡성 | 규모가 커질수록 구성요소 관계 증가 |
| 변경 용이성 | 쉽게 바뀌지만 변경 관리 필요 |

## Ⅲ. 소프트웨어 공학의 활동과 좋은 소프트웨어의 구조

### 소프트웨어 공학의 활동

```text
요구 분석 → 설계 → 구현 → 시험 → 운영·유지보수
        └── 프로젝트 관리·품질 보증·형상 관리 ──┘
```

### 확대: 좋은 소프트웨어의 특성

```text
좋은 소프트웨어
    ├─ 유지보수성 ── 변경 요구에 맞춰 수정
    ├─ 신뢰성·보안성 ── 장애·위협에 안전
    ├─ 효율성 ── 자원·응답 성능
    └─ 사용 적합성 ── 사용자 이해·호환
```

## Ⅳ. 좋은 소프트웨어의 4가지 특징

| 특징 | 의미 | 확보 수단 |
|---|---|---|
| 유지보수성 | 요구 변화에 맞춘 수정 용이 | 모듈화·문서화·시험 |
| 신뢰성과 보안성 | 장애가 없고 위협으로부터 보호 | 결함 관리·보안 설계 |
| 효율성 | 메모리·처리 자원의 절약과 응답성 | 알고리즘·아키텍처 설계 |
| 사용 적합성 | 사용자 이해·사용과 시스템 호환 | 사용성 설계·표준 인터페이스 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 품질 특성이 요구에 명시되지 않아 후반에 누락 | 요구 단계에서 특성별 측정 기준 정의 |
| 특성 간 상충(효율성과 유지보수성) | 우선순위를 정해 절충 |
| 품질을 시험 단계에서만 확인 | 단계별 검토와 시험 |

## Ⅵ. 제언

좋은 소프트웨어의 4가지 특성을 요구 단계에서 측정 가능한 기준으로 정하고, 단계별 검토로 확인

### 특성 기준 정의와 검증

```text
특성별 기준 정의 (예: 응답 2초, 변경 반영 1일)
    ↓
단계별 검토·시험으로 확인
    ↓
미충족 → 조기 시정
```

### 확대: 상충 판단

```text
특성 간 상충
    ├─ 우선 특성 지정 → 다른 특성은 허용 범위 설정
    └─ 합의 곤란 → 이해관계자 조정
```

### 선택 근거: 후반 확인과의 비교

| 구분 | 후반 확인 | 제언: 요구 단계 기준·단계별 검증 |
|---|---|---|
| 기준 | 불명확 | 측정 가능 |
| 결함 발견 | 후반 | 조기 |
| 수정 비용 | 큼 | 작음 |
