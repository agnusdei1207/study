## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 개발 방법론 → **CBD(Component-Based Development)**

## 30초 인출

- 본질: CBD는 독립적으로 배포·교체할 수 있는 컴포넌트를 만들고 이를 조립해 시스템을 개발하는 소프트웨어 개발 방법
- 메커니즘: 컴포넌트가 제공 인터페이스와 요구 인터페이스로만 상호작용하도록 정의하고 저장소의 컴포넌트를 검색·조립해 시스템을 구성
- 통찰: 컴포넌트의 경계와 인터페이스가 불명확하면 재사용과 교체가 어려우므로 인터페이스를 먼저 정의하고 그 규약을 지키는 컴포넌트만 저장소에 등록해 조립

<details>
<summary>핵심 용어</summary>

- **컴포넌트(Component)** : 명확한 인터페이스를 가지며 독립적으로 배포·교체할 수 있는 소프트웨어 단위
- **제공 인터페이스(Provided Interface)** : 컴포넌트가 외부에 제공하는 기능의 규약
- **요구 인터페이스(Required Interface)** : 컴포넌트가 동작하기 위해 외부에서 필요로 하는 기능의 규약
- **컴포넌트 저장소** : 재사용할 컴포넌트를 등록·검색하는 저장소
- **재사용(Reuse)** : 기존 컴포넌트를 새 시스템에 다시 사용하는 것

</details>

## 2~4교시 25점 답안

## Ⅰ. CBD의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **CBD** 는 독립적으로 배포·교체할 수 있는 컴포넌트를 조립해 시스템을 개발하는 방법 |
| 목적 | 재사용을 통한 개발 생산성과 품질 향상 |

## Ⅱ. 개별 코드 개발과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 인터페이스 중심 | 규약으로만 상호작용 |
| 재사용 | 저장소의 컴포넌트를 반복 사용 |
| 교체 용이 | 같은 인터페이스의 컴포넌트로 교체 |

## Ⅲ. 컴포넌트 구조와 개발 흐름

### 컴포넌트 구조

```text
[컴포넌트 A]
  ○ 제공 인터페이스 ── 외부에 기능 제공
  ⊂ 요구 인터페이스 ── 외부 기능 필요
       ↓ 조립 (제공 ↔ 요구 연결)
[컴포넌트 B] ○──⊃ [컴포넌트 A]
```

### 확대: 개발 흐름

```text
컴포넌트 개발 ── 인터페이스 정의·구현·시험 → 저장소 등록
    ↓
시스템 개발 ── 요구 분석 → 컴포넌트 검색 → 조립·연동 시험
```

## Ⅳ. 개발 방식과 다른 방식과의 비교

| 구분 | 재사용을 위한 개발 | 재사용에 의한 개발 |
|---|---|---|
| 목적 | 재사용 가능한 컴포넌트 제작 | 기존 컴포넌트로 시스템 구성 |
| 초점 | 인터페이스·일반화 | 검색·조립 |

| 비교 | CBD | 객체지향 개발 | 서비스 지향(SOA) |
|---|---|---|---|
| 단위 | 컴포넌트 | 클래스·객체 | 서비스 |
| 결합 | 인터페이스 조립 | 상속·구성 | 표준 프로토콜 통신 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 컴포넌트 경계 불명확으로 재사용 곤란 | 인터페이스를 먼저 정의하고 규약 검증 |
| 저장소의 컴포넌트를 찾기 어려움 | 메타데이터·분류 체계 정비 |
| 컴포넌트 버전 변경 시 호환 문제 | 인터페이스 버전 관리와 하위 호환 유지 |

## Ⅵ. 제언

컴포넌트는 인터페이스를 먼저 정의하고 규약을 시험으로 검증한 뒤 저장소에 등록해 조립

### 등록 전 검증

```text
인터페이스 정의 → 구현 → 규약 시험
    ↓
통과 → 저장소 등록 → 시스템에서 조립
```

### 확대: 변경 판단

```text
컴포넌트 변경
    ├─ 인터페이스 유지 → 교체 가능
    └─ 인터페이스 변경 → 새 버전 등록·영향 확인
```

### 선택 근거: 규약 없는 재사용과의 비교

| 구분 | 규약 없는 재사용 | 제언: 인터페이스 규약 |
|---|---|---|
| 교체 | 내부 수정 필요 | 인터페이스 유지 시 교체 |
| 품질 | 편차 | 규약 시험 통과 |
| 조립 | 연동 오류 | 규약으로 연동 |
