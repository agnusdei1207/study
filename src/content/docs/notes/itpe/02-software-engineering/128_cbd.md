## 연관 키워드

- CBD(Component-Based Development), 컴포넌트 기반 개발
- COTS(Commercial Off-the-Shelf), 상용 컴포넌트
- 3C(Component, Container, Connector)
- 제공 인터페이스(Provided Interface), 요구 인터페이스(Required Interface)
- 도메인 공학(Domain Engineering), 응용 공학(Application Engineering)

## Ⅰ. 컴포넌트 기반 개발(CBD)의 개요

- 핵심 요약 : 명확한 인터페이스를 갖춘 컴포넌트를 부품처럼 조립해 애플리케이션을 구축하는 재사용 중심 방법론.
- 개념 : **컴포넌트 기반 개발** (CBD, Component-Based Development) 란 독립적인 비즈니스 기능을 수행하도록 명확한 인터페이스를 갖추어 패키징된 소프트웨어 모듈인 컴포넌트(Component)를 사전에 개발하거나 기성 **상용 컴포넌트** (COTS, Commercial Off-the-Shelf)로 확보한 후, 이들을 부품처럼 레고 블록식으로 조립(Assembly)하여 새로운 애플리케이션을 신속하게 구축하는 재사용 중심의 소프트웨어 공학 방법론.
- 배경 및 필요성 : 객체지향(OOP, Object-Oriented Programming)의 소스코드 레벨 재사용 한계 극복, 실행 가능한 바이너리 단위의 블랙박스 재사용성 확보.
- 주요 목적 : 개발 생산성 향상, 유지보수 비용 절감, 검증된 부품 조립 기반의 신속한 시스템 구축.
- 컴포넌트의 3대 핵심 속성(3C) : 컴포넌트(Component), 컨테이너(Container: 실행 환경), 커넥터(Connector: 연동 인터페이스).

## Ⅱ. 컴포넌트 기반 개발(CBD)의 특징

- 핵심 요약 : 3C 속성과 제공·요구 인터페이스 계약, 블랙박스 재사용이 핵심인 개발 체계.
1. **3C 속성** : 컴포넌트(Component), 컨테이너(Container), 커넥터(Connector)의 3요소 구성.
2. **제공 인터페이스** (Provided Interface) : 컴포넌트가 외부에 제공하는 서비스 메서드 규약 (롤리팝 표기법: 실선 끝에 원).
3. **요구 인터페이스** (Required Interface) : 컴포넌트의 정상 동작을 위해 외부 타 컴포넌트로부터 제공받아야 하는 규약 (소켓 표기법: 실선 끝에 반원).
4. **블랙박스 재사용** : 내부 구현을 은닉한 바이너리 단위(.jar, .dll)의 재사용.
5. **2대 트랙 프로세스** : 재사용 자산을 생산하는 도메인 공학과 이를 조립하는 응용 공학의 병행 수행.

## Ⅲ. 컴포넌트 기반 개발(CBD)의 구조 (흐름)

- 핵심 요약 : 도메인 공학의 재사용 자산 생산과 응용 공학의 검색·조립·릴리스 흐름.
- 도메인 공학 → 응용 공학의 2대 트랙과 컴포넌트 조립 단계.

```text
[ 도메인 공학 (Domain Engineering) ]
 - 컴포넌트 개발
 - 도메인 분석, 공통 로직 식별
 - 컴포넌트 설계, 구현, 단위 테스트
 - 저장소(Repository) 등록 및 배포
   │
   ▼ (재사용 자산 라이브러리 제공)
[ 응용 공학 (Application Engineering) ]
 - 컴포넌트 조립
 - 고객 요구 분석, 컴포넌트 검색
 - 인터페이스 결합, 어댑터 작성
 - 통합 테스트 및 애플리케이션 릴리스
```

```text
[ 컴포넌트 조립 흐름 ]
 고객 요구 분석
        ↓
 컴포넌트 검색 (저장소)
        ↓
 제공/요구 인터페이스 결합
  - 롤리팝(제공) ↔ 소켓(요구)
        ↓
 어댑터 작성 및 통합 테스트
        ↓
 애플리케이션 릴리스
```

## Ⅳ. 객체지향(OOP)·CBD·마이크로서비스(MSA)의 비교

- 핵심 요약 : 재사용 단위·결합 방식·배포 독립성·실행 환경의 진화 단계 차이.
- 재사용 단위, 결합 방식, 배포 독립성, 실행 환경, 주 활용 시대 축 비교.

| 비교 항목 | 객체지향 개발 (OOP) | 컴포넌트 기반 개발 (CBD) | 마이크로서비스 아키텍처 (MSA, Microservice Architecture) |
|---|---|---|---|
| 재사용 단위 | 클래스, 객체 (소스코드 수준) | 바이너리 컴포넌트 (.jar, .dll) | 독립 실행 프로세스 / 서비스 단위 |
| 결합 방식 | 언어 레벨의 상속, 합성, 컴파일 링크 | 컨테이너 기반 인터페이스 바인딩 | 네트워크 기반 경량 API(Application Programming Interface) (REST(Representational State Transfer), gRPC) |
| 배포 독립성 | 단일 애플리케이션으로 통합 빌드/배포 | 컴포넌트 단위 교체 배포 가능 | 완전한 무중단 독립 서비스 배포 |
| 실행 환경 | 프로세스 메모리 내부 | EJB(Enterprise JavaBeans) 컨테이너, COM+, Spring IoC(Inversion of Control) | Docker 컨테이너, Kubernetes 클러스터 |
| 주 활용 시대 | 1990년대 전산화 초기 | 2000년대 엔터프라이즈 프레임워크 | 현대 클라우드 네이티브 분산 환경 |

## Ⅴ. 컴포넌트 기반 개발(CBD)의 장점과 한계

- 핵심 요약 : 바이너리 재사용·교체 배포의 장점, 인터페이스 복잡성·은닉 의존성·버전 호환성의 한계.
- 장점
  1. 바이너리 단위 재사용에 따른 개발 기간·비용 절감.
  2. 기성 상용 컴포넌트(COTS) 활용에 따른 초기 품질 신뢰성 확보.
  3. 컴포넌트 단위 교체 배포에 따른 유지보수성 향상.
- 한계점 1 : 과도한 컴포넌트 일반화에 따른 인터페이스 복잡성 증가
  - 한계점 : 컴포넌트의 범용 재사용성을 지나치게 추구하면 매개변수와 구성 옵션이 비대해져 개별 프로젝트 적용 시 생산성 저하.
  - 해결 방안 : 도메인 분석 기반 핵심 공통 기능의 최소 캡슐화, **인터페이스 분리 원칙** (ISP, Interface Segregation Principle) 준수에 따른 얇고 명확한 계약(Contract) 인터페이스 설계.
- 한계점 2 : 컴포넌트 간 **은닉된 의존성** (Hidden Dependency)에 따른 통합 장애
  - 한계점 : 컴포넌트 내부 참조 서드파티 라이브러리의 버전 불일치, 전역 상태 의존성으로 통합 단계 런타임 충돌 발생.
  - 해결 방안 : 의존성 주입(DI, Dependency Injection) 컨테이너 기반 외부 의존성 명시적 주입, 컴포넌트 계약 테스트(Consumer-Driven Contract Testing) 체계 구축.
- 한계점 3 : 컴포넌트 버전 진화 시 하위 호환성 관리 부담
  - 한계점 : 컴포넌트 업그레이드 시 다수 애플리케이션의 영향도 파악 곤란으로 버전 고착화 및 기술 부채화.
  - 해결 방안 : **시맨틱 버저닝** (SemVer, Semantic Versioning) 준수, 컴포넌트 저장소(Repository) 기반 API 브레이킹 체인지 자동 검출 도구의 CI(Continuous Integration) 연동.

## Ⅵ. 컴포넌트 기반 개발(CBD)에 대한 기술사적 제언

- 핵심 요약 : 도메인 주도 설계 기반의 MSA 점진 전환과 계약 테스트 자동화 강화.
- CBD에서 MSA로의 점진적 전환 아키텍처 수립 : 레거시 엔터프라이즈의 EJB/CBD 컴포넌트들은 비즈니스 도메인 단위로 이미 응집되어 있으므로, 빅뱅 방식의 전면 재작성 대신 컴포넌트 경계를 **도메인 주도 설계** (DDD, Domain-Driven Design)의 **바운디드 컨텍스트** (Bounded Context)로 매핑하여 마이크로서비스로 점진적 분리 권장.
- 컴포넌트 명세 표준화 및 **계약 테스트** (Contract Test) 강화 : 컴포넌트 내부 구현이 변경되더라도 외부 제공 인터페이스 규약이 깨지지 않도록 Pact 등 소비자 주도 계약(Consumer-Driven Contract) 테스트를 자동화하여 통합 파손 방지.

## Ⅶ. 결론

- 핵심 요약 : CBD는 인터페이스 계약 기반 컴포넌트 조립으로 생산성·재사용성을 확보하는 방법론.
- 요약 : CBD는 명확한 인터페이스 규약을 갖춘 컴포넌트의 조립으로 신속한 애플리케이션 구축을 실현하는 재사용 중심 방법론.
- 시사점 : 인터페이스 복잡성·은닉 의존성·버전 호환성 통제와 MSA로의 점진적 진화가 실무 적용의 성공 조건.
