## 연관 키워드

- 테스팅 7원리, ISTQB, 결함 존재 증명, 완전 시험 불가능
- 조기 테스팅, 결함 집중, 살충제 역설, 정황 의존성, 오류-부재의 궤변

## Ⅰ. 소프트웨어 테스팅 7원리의 개요

- 핵심 요약 : 테스팅의 본질적 한계를 인정한 뒤 위험 중심의 자원 배분을 안내하는 국제 자격 체계의 7가지 기본 원리.
- 개념 : 국제 소프트웨어 테스팅 자격 위원회(ISTQB, International Software Testing Qualifications Board)가 정리한 **테스팅 7원리**(seven testing principles, 테스팅의 한계와 효과를 규정하는 기본 원칙) 체계.
- 배경 및 필요성 : 모든 입력 조합의 실행이 불가능하므로, 한정된 시간·자원 안에서 테스팅의 효과와 경제성을 높일 판단 기준 필요.
- 주요 가치 : 완전성 환상에서 벗어나 위험 기반 선별과 전 주기 검증으로 품질 리스크를 관리하는 사고의 기준 제공.

## Ⅱ. 테스팅 7원리의 특징 및 장점

- 핵심 요약 : 한계 인정·시점과 자원·지속 갱신·가치 기준의 네 축이 테스팅 효율로 연결됨.

1. 한계 인정 : **결함 존재 증명**(테스팅은 결함의 존재만 보일 뿐 부재는 증명하지 못한다는 원리)과 **완전 시험 불가능**(모든 입력·조건 조합의 검증이 불가능하다는 원리) → 무결점 선언 경계와 위험 기반 선별의 근거.
2. 시점·자원 배분 : **조기 테스팅**(요구·설계 단계부터 검증을 시작한다는 원리)과 **결함 집중**(결함이 소수 모듈에 몰리는 경향) → 수정 비용 절감·자원 집중 효과.
3. 지속 갱신·정황 적응 : **살충제 역설**(pesticide paradox, 같은 테스트의 반복이 새 결함을 못 찾게 되는 현상)과 **정황 의존성**(context dependency, 도메인·환경에 따라 적합한 테스팅이 달라진다는 원리) → 케이스 정기 개정·도메인별 전략 차등.
4. 가치 기준 : **오류-부재의 궤변**(absence-of-errors fallacy, 결함 제거만으로 요구·가치를 충족하지 못할 수 있다는 원리) → 사용자 관점 검증의 병행 근거.

## Ⅲ. 테스팅 7원리의 구조 (흐름)

- 핵심 요약 : 원리가 전 주기 검증 배치와 케이스 개정 순환을 이끄는 구조.

```text
[ 원리가 이끄는 전 주기 검증 ]

요구·설계 검토 (조기 테스팅)
   ↓
위험 모듈 우선 검증 (결함 집중)
   ↓
시스템·인수 테스트
   ↓
사용자 가치 확인 (오류-부재 궤변 대응)
```

```text
[ 살충제 역설 대응 순환 ]

동일 케이스 반복 실행
   ↓
새 결함 검출력 저하
   ↓
케이스 개정·신규 추가
   ↓
검출력 회복
```

- 원리 간 연결 : 한계 인정 원리가 선별 기준을, 가치 기준 원리가 검증 범위를 규정.

## Ⅳ. 무계획 테스팅 관행과 원리 기반 테스팅의 비교

- 핵심 요약 : 즉흥 실행·소진 기반 종료의 무계획 관행과 달리, 원리 기반 테스팅은 위험 선별과 종료 기준으로 효율을 확보.

| 비교 축 | 무계획(임의) 테스팅 관행 | 원리 기반 테스팅 |
|---|---|---|
| 케이스 설계 근거 | 즉흥 입력·담당자 감 | 요구·위험 분석 기반 설계 |
| 자원 배분 | 전 모듈 균등 소진 | 결함 집중 모듈 우선 배분 |
| 수행 시점 | 코딩 완료 후 일괄 | 요구·설계 단계부터 조기 |
| 케이스 관리 | 기존 케이스의 무기한 재사용 | 정기 개정으로 검출력 유지 |
| 종료 판정 | 시간·예산 소진 기준 | 종료 기준·잔존 위험 평가 |

## Ⅴ. 테스팅 7원리 적용의 한계와 방안

- 핵심 요약 : 원리의 면책 악용·검출력 감쇠·집중 대상 오판·가치 불일치를 위험 기반 운영과 측정으로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 면책 수단 악용 | 완전 시험 불가능 원리를 책임 회피에 사용 | 사전 합의된 종료 기준과 잔존 위험 보고 | 종료 기준 달성률 |
| 검출력 감쇠 | 동일 자동화 케이스의 반복 실행 → 신규 결함 놓침 | 케이스 정기 개정과 검출력 평가 | 신규 결함 검출 건수 |
| 집중 대상 오판 | 과거 결함 위치가 미래를 보장하지 않음 → 자원 오배분 | 결함 이력·변경 복잡도의 병합 분석 | 모듈별 결함 밀도 편차 |
| 가치 불일치 | 명세 충족에도 사용자 요구 미달 | 명세 검증과 사용자 관점 검증 병행 | 사용자 불만·이탈 지표 |

## Ⅵ. 테스트 프로세스 정착을 위한 기술사적 제언

- 핵심 요약 : 품질 조직의 테스트 정책·위험 기반 표준 수립과 자격·측정 체계의 조직적 정착 필요.

1. 정책·표준 : 품질 보증 조직은 **위험 기반 테스팅**(risk-based testing, 비즈니스 위험도에 따라 테스팅 자원을 배분하는 접근)을 테스트 정책의 기본 원칙으로 채택하고 종료 기준을 표준화.
2. 역량·측정 체계 : ISTQB 자격 기반의 테스터 역량 관리와 원리 준수 지표(검출률·개정 주기)의 정기 점검으로 전사 테스팅 성숙도를 확산.

## Ⅶ. 결론

- 핵심 요약 : 7원리는 테스팅의 한계를 전제로 자원을 위험 중심에 배치하는 운영 원칙.
- 원리에 근거한 선별·개정·가치 검증이 테스팅의 경제성과 신뢰를 함께 결정.
