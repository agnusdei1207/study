소프트웨어 공학 → 애자일 → **칸반(Kanban)**

## 30초 인출

- 본질: 칸반은 작업을 보드에 시각화하고 단계별 진행 중 작업 수(WIP)를 제한해 작업 흐름을 끊김 없이 관리하는 방식
- 메커니즘: 작업을 대기·진행·완료 열의 카드로 표시하고 열마다 WIP 한도를 두어 후속 단계가 여유 있을 때 작업을 당겨(Pull) 진행하며 리드타임을 측정
- 통찰: 진행 중 작업이 많으면 작업 전환 비용과 대기가 늘어 처리 시간이 길어지므로 WIP 한도로 동시 작업 수를 제한하고 병목 열의 흐름을 개선

<details>
<summary>핵심 용어</summary>

- **칸반(Kanban)** : 작업을 시각화하고 WIP를 제한해 흐름을 관리하는 방식
- **WIP 제한(Work In Progress Limit)** : 단계별로 동시에 진행할 수 있는 작업 수의 상한
- **풀 시스템(Pull System)** : 후속 단계가 처리 여력이 있을 때 앞 단계 작업을 가져오는 방식
- **리드타임(Lead Time)** : 요청이 접수된 시점부터 완료까지 걸린 시간
- **사이클 타임(Cycle Time)** : 작업에 착수한 시점부터 완료까지 걸린 시간
- **누적 흐름도(CFD, Cumulative Flow Diagram)** : 단계별 작업 수의 누적 추이를 보여 병목을 찾는 도표

</details>

## 2~4교시 25점 답안

## Ⅰ. 칸반의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **칸반** 은 작업을 시각화하고 WIP를 제한해 작업 흐름을 관리하는 방식 |
| 목적 | 병목의 조기 발견과 리드타임 단축 |

## Ⅱ. 스크럼과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 시각화 | 보드로 작업 상태 공유 |
| WIP 제한 | 동시 진행 작업 수 제한 |
| 지속적 흐름 | 고정 반복 주기 없이 연속 처리 |
| 흐름 측정 | 리드타임·사이클 타임 관리 |

## Ⅲ. 칸반 보드와 흐름 제어

### 칸반 보드

```text
 대기 │ 분석(WIP 2) │ 개발(WIP 3) │ 시험(WIP 2) │ 완료
  □   │    □ □      │   □ □ □     │    □ □      │  □ □
  □   │             │             │             │
(WIP 한도에 도달하면 앞 단계는 새 작업 착수 중단)
```

### 확대: 풀 시스템 동작

```text
시험 열에 여유 발생
    ↓
개발 열의 완료 작업을 시험으로 당김
    ↓
개발 열에 여유 → 분석 열에서 당김
```

## Ⅳ. 칸반과 스크럼의 비교, 흐름 지표

### 칸반과 스크럼의 비교

| 구분 | 칸반 | 스크럼 |
|---|---|---|
| 주기 | 없음(연속 흐름) | 고정 길이 스프린트 |
| 역할 | 별도 규정 없음 | 제품 책임자·스크럼 마스터 |
| 제한 | WIP 제한 | 스프린트 범위 |
| 변경 | 언제든 우선순위 조정 | 스프린트 중 변경 제한 |

### 흐름 지표

| 지표 | 의미 |
|---|---|
| 리드타임 | 요청 접수부터 완료까지 |
| 사이클 타임 | 착수부터 완료까지 |
| 처리량 | 단위 기간의 완료 작업 수 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| WIP 한도 없이 보드만 운영 | 열별 WIP 한도 설정 |
| 병목 열 파악 곤란 | 누적 흐름도로 병목 확인 |
| 계획성 부족 | 리드타임 분포로 납기 예측 |

## Ⅵ. 제언

열별 WIP 한도를 설정하고 누적 흐름도로 병목을 찾아 그 열의 흐름을 우선 개선

### 병목 개선 순환

```text
WIP 한도 설정 → 운영
    ↓
누적 흐름도·사이클 타임 측정
    ↓
병목 열 식별 → 개선
```

### 확대: 병목 판정

```text
열별 대기 작업 수
    ├─ 특정 열에 누적 → 병목, 한도·인력 조정
    └─ 고르게 흐름 → 현행 유지
```

### 선택 근거: WIP 제한 없는 보드와의 비교

| 구분 | WIP 제한 없음 | 제언: WIP 한도 |
|---|---|---|
| 동시 작업 | 과다 | 제한 |
| 병목 발견 | 곤란 | 즉시 드러남 |
| 리드타임 | 장기화 | 단축 |
