## 답안 골격
```text
[삽입정렬] ◀━━ 머리: Ⅶ 내 의견 (소규모 배열 및 거의 정렬된 데이터 처리를 위한 팀소트(Timsort) 하이브리드 활용)
 ┃
 ┣━ Ⅰ 개요 ───── 2번째 원소부터 앞선 정렬 부분과 비교하여 올바른 위치에 삽입하는 기본 정렬 알고리즘
 ┣━ Ⅱ 특징 ───── 안정 정렬(Stable) · 제자리 정렬(In-place, O(1)) · 거의 정렬된 경우 최선 O(N) · 단순성
 ┣━ Ⅲ 구조 ───── 정렬된 부분(Sorted subarray) / 미정렬 부분(Unsorted) / 타깃 키(Key) / 원소 시프트(Shift)
 ┣━ Ⅳ 흐름 ───── 2번째 원소 선택(Key) → 정렬 부분 역방향 탐색 → 큰 원소 우측 시프트 → 빈 자리에 Key 삽입 → N번째까지 반복
 ┣━ Ⅴ 비교 ───── 삽입정렬(거의 정렬 시 O(N), 안정) vs 선택정렬(항상 O(N^2), 불안정) vs 버블정렬(인접 교환, O(N^2))
 ┗━ Ⅵ 실무 ───── 대규모 데이터 역순 정렬 시 O(N^2) 성능 폭망 / 셸 정렬(Shell Sort) 및 팀소트(Timsort) 전환
```
- 필수 키워드: 삽입정렬 · 안정 정렬 · 제자리 정렬 · 최선 $O(N)$ · 최악 $O(N^2)$ · 원소 시프트 · 팀소트(Timsort)
- 배점 전략: 10점 = Ⅰ 정의 및 손카드 비유 → Ⅲ 정렬 단계별 포인터 이동 도해 → Ⅴ 기본 3대 정렬(선택/버블/삽입) 비교 / 25점 = Ⅰ~Ⅶ 전개, 최선/평균/최악 시간복잡도 증명 및 실무 하이브리드 정렬(Timsort) 내 삽입정렬의 역할
- 기출: 131회 4교시 6번 `정렬 알고리즘의 동작 과정과 복잡도 비교` → Ⅰ~Ⅴ / 90회 1교시 `기본 정렬 알고리즘` → Ⅰ·Ⅲ·Ⅴ

## 한 줄 본질
- 원소 수가 적거나 이미 대부분 정렬되어 있는 배열에 퀵소트나 병합정렬을 쓰면 재귀 호출과 분할 오버헤드가 더 큰 병목 → 정렬된 부분 배열을 역순으로 훑으며 자기 자리를 찾아 끼워 넣는 단순 시프트 반복 → 거의 정렬된 데이터에서 $O(N)$의 초고속 처리 달성 / 역순 배열 시 $O(N^2)$ 성능 저하

## 핵심 그림
```text
+-------------------------------------------------------------------+
|               삽입정렬(Insertion Sort)의 동작 메커니즘            |
+-------------------------------------------------------------------+
| 초기 배열: [ 5, 2, 4, 6, 1, 3 ]                                   |
|                                                                   |
| Step 1: Key = 2 (인덱스 1) -> 5와 비교 -> 5를 뒤로 밀고 2 삽입   |
|         [ 2, 5, | 4, 6, 1, 3 ] (정렬 영역: 2, 5)                  |
|                                                                   |
| Step 2: Key = 4 (인덱스 2) -> 5와 비교 후 2 뒤에 4 삽입           |
|         [ 2, 4, 5, | 6, 1, 3 ] (정렬 영역: 2, 4, 5)               |
|                                                                   |
| Step 3: Key = 6 (인덱스 3) -> 5보다 크므로 즉시 제자리 안착       |
|         [ 2, 4, 5, 6, | 1, 3 ] (단 1회 비교로 통과!)             |
|                                                                   |
| * 최선의 경우(이미 정렬됨): 모든 원소가 1회 비교로 끝나 O(N) 달성!|
+-------------------------------------------------------------------+
```

## 핵심 용어
- 안정 정렬(Stable Sort): 정렬 대상 배열에 키(Key) 값이 동일한 원소가 둘 이상 있을 때, 정렬 전의 상대적 순서가 정렬 후에도 그대로 유지되는 정렬 알고리즘
- 팀소트(Timsort): 병합 정렬(Merge Sort)과 삽입 정렬(Insertion Sort)을 결합하여, 작은 런(Run, 크기 32~64) 구간은 삽입정렬로 처리하는 실무 표준 고속 정렬(Python, Java 기본 정렬)

## 핵심 통찰
- 단순 정렬 3대장(버블, 선택, 삽입) 중 유일하게 실무에서 상용 라이브러리의 핵심 모듈로 살아남아 쓰이는 알고리즘은 '삽입정렬'뿐임
- 데이터가 이미 거의 정렬되어 있는 상태(Nearly Sorted)라면, 복잡한 퀵소트($O(N \log N)$)보다 삽입정렬($O(N)$)이 훨씬 빠르며 CPU 캐시 친화적임
- 원소 수가 32개 이하인 소규모 데이터에서는 $O(N \log N)$ 알고리즘의 함수 호출 및 메모리 할당 오버헤드 때문에 삽입정렬의 단순 반복문 루프가 상수 계수(Constant Factor) 면에서 압승함

## 이웃 토픽과 구분
- 삽입정렬 vs 선택정렬(Selection Sort): 선택정렬 = 아직 정렬 안 된 영역에서 '최솟값을 찾아' 앞으로 가져옴 / 삽입정렬 = 아직 정렬 안 된 원소를 가져와 '앞선 정렬 영역 속 제자리로 끼워 넣음'

## 문제·원인·대책
- 사례: 131회 기출 100만 건 역순 로그 정렬 시 삽입정렬 사용으로 CPU 100% 점유 및 행 걸림
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 역순 정렬된 10만 건 데이터 처리 시 수십 초 소요되며 서버 타임아웃 | 역순 입력 시 매 원소마다 정렬 영역 전체를 시프트하여 최악 $O(N^2)$ 발생 | 간격(Gap)을 두고 듬성듬성 삽입정렬하는 셸 정렬(Shell Sort) 또는 퀵소트 전환 | 정렬 시간 밀리초 단위로 단축 |
| 자바 배열 정렬 시 객체 참조의 상대적 순서가 뒤바뀌어 데이터 정합성 파괴 | 불안정 정렬(Quick Sort)을 사용하여 동일 값 원소의 순서 파괴 | 안정 정렬인 삽입정렬 기반의 팀소트(`Arrays.sort(Object[])`) 적용 | 동일 키 값 객체의 본래 순서 100% 보존 |

## 내 의견
- [빅오 복잡도만 보고 $O(N^2)$ 알고리즘을 맹목적으로 무시하는 편견] 교과서의 $O(N^2)$ 표기만 보고 삽입정렬은 절대 쓰면 안 되는 저열한 기술로 취급하는 이론적 교조주의 경계 → 나라면: 실무 고성능 정렬 엔진 구축 시 데이터 크기가 32개 미만으로 쪼개지는 리프 노드 구간에서는 분할 정복을 멈추고 삽입정렬로 전환하는 컷오프(Cutoff) 기법을 적용하여 퀵소트 단독 대비 15% 이상의 성능 향상 달성
