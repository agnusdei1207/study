## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 소프트웨어 개발·운영 → 기능점수(Function Point)

## 지식 위치

소프트웨어공학 > 프로젝트 관리·비용 산정 > 기능 규모 측정

## 30초 인출

- 본질: 기능점수는 사용자가 요구한 기능의 크기를 측정하는 소프트웨어 기능 규모 측정법
- 메커니즘: 측정 경계 설정 → 사용자 기능 식별 → 기능별 복잡도 평가 → 기능점수 산출
- 통찰: 한계: 측정 경계를 다르게 잡으면 같은 기능도 중복·누락 산정될 수 있음 → 방안: 경계와 ILF·EIF·EI·EO·EQ 분류 근거를 먼저 합의

<details>
<summary>핵심 용어</summary>

- **ILF(Internal Logical File)** : 애플리케이션 내부에서 유지·관리되며 비즈니스 로직에 의해 지속적으로 등록, 수정, 삭제되는 논리적 데이터 그룹
- **EIF(External Interface File)** : 타 시스템에서 유지·관리되지만, 현재 애플리케이션에서 오직 참조(Read-only) 목적으로 사용하는 외부 연계 데이터 그룹
- **EI / EO / EQ** : 외부입력(EI, 외부에서 들어온 데이터·제어 정보로 ILF를 유지하거나 시스템 동작을 변경), 외부출력(EO, 파생 데이터 계산·출력 등 처리 논리 포함), 외부조회(EQ, 조회 결과를 보여 주는 기본 처리)
- **DET(Data Element Type)** : 사용자가 식별할 수 있는 고유하고 반복되지 않는 필드(컬럼) 단위 데이터 항목
- **RET(Record Element Type)** : ILF나 EIF 내부에서 사용자가 인식 가능한 하위 레코드 데이터 서브그룹(예: 마스터-디테일 테이블)
- **FTR(File Type Referenced)** : 트랜잭션 기능(EI, EO, EQ)을 수행하는 과정에서 읽거나 갱신하는 ILF 또는 EIF의 개수
</details>

## 2~4교시 25점 답안

## Ⅰ. 기능점수의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 기능점수는 사용자가 요구한 기능의 크기를 측정하는 소프트웨어 기능 규모 측정법 |
| 목적 | 구현 방식과 분리된 기능 규모를 개발 노력·사업 대가 추정의 입력값으로 활용 |

## Ⅱ. 기능점수의 특징

| 특징 | 산정상 의미 |
|---|---|
| 사용자 관점 | 코드 줄 수 대신 논리적 데이터·트랜잭션 기능을 계수 |
| 경계 의존 | 애플리케이션 경계와 유지 주체에 따라 분류 결과가 달라짐 |
| 추정 단계 차이 | 상세 자료 수준에 따라 정규·간이 방식을 구분 |

## Ⅲ. 기능 분류 체계와 산정 프로세스

```text
사용자 요구 → 애플리케이션 경계 확정
                 ├→ 데이터 기능 ILF·EIF
                 └→ 트랜잭션 EI·EO·EQ
                    ↓ 개수·복잡도·가중치
                    UFP 산출 → 적용 지침의 대가 기준 검토
```

### 기능점수 산정 공식 및 보정 체계

1. **미조정 기능점수(UFP) 계산** :
   $$UFP = \sum (\text{기능 유형별 개수} \times \text{복잡도 가중치})$$
2. **산정 지침 반영** : 계약·대가 산정에 사용할 조정 항목과 기준은 적용 중인 공공 SW 대가산정 지침에서 확인
3. **사업 대가 산정** : 기능점수 결과와 지침이 정한 공수·단가·보정 기준을 적용

## Ⅳ. 기능 분류와 산정 방식 비교

| 구분 | 정규법 | 간이법 |
|---|---|---|
| 적용 | 기능별 상세 정보가 확보된 경우 | 초기 추정에서 상세 정보가 부족한 경우 |
| 계산 | 기능별 복잡도 판정 | 기능 유형별 평균 가중치 |
| 주의 | 경계·논리 파일 식별 근거 유지 | 가정과 상세 산정 시점 기록 |

### 기능 분류 확인

| 검증 영역 | 판정 기준 |
|---|---|
| 경계 | 배치·인터페이스·서브시스템 간 중복 정의 방지 |
| 데이터 | 논리적 그룹과 유지 주체로 ILF·EIF 식별 |
| 트랜잭션 | 처리 논리로 EI·EO·EQ 식별 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 측정 경계를 다르게 잡으면 같은 기능도 중복·누락 산정될 수 있음 | 경계와 ILF·EIF·EI·EO·EQ 분류 근거를 먼저 합의 |
| 물리 테이블 수를 논리 파일 수로 간주 | 사용자 관점의 논리 데이터 그룹과 유지 주체 확인 |
| 화면 이름으로 조회·출력을 구분 | 처리 논리·파생 데이터 여부로 EO·EQ 분류 |
| 초기 추정과 상세 요구의 차이 | 가정과 변경 기능을 대조해 재산정·계약 협의 |

## Ⅵ. 제언

발주 전 애플리케이션 경계와 논리적 기능 분류 근거를 먼저 합의하고, 요구 변경 시 같은 기준으로 기능점수 차이를 다시 계산한다.
