## 연관 키워드

- Function Point, 기능점수, SW 규모 산정
- IFPUG, ISO/IEC 20926, LOC(Lines of Code)
- ILF(Internal Logical File), EIF(External Interface File)
- EI(External Input), EO(External Output), EQ(External Inquiry)
- RET/DET/FTR, 간이·정규 기능점수법, 사후 정산

## Ⅰ. 기능점수(Function Point)의 개요

- 핵심 요약 : 사용자 관점의 논리적 업무 기능을 언어 중립적으로 정량 측정하는 국제 표준 규모 산정 척도.
- 개념 : **기능점수** (FP, Function Point) 란 앨런 알브레히트(Allan Albrecht)가 창안하고 IFPUG(International Function Point Users Group, 국제기능점수사용자그룹)에서 표준화한 소프트웨어 규모 측정 기법으로, 구현에 사용된 프로그래밍 언어나 기술 스택에 관계없이 최종 사용자의 관점에서 소프트웨어가 제공하는 논리적 업무 기능을 정량적으로 측정하는 국제 표준 소프트웨어 규모 및 대가 산정 척도.
- 배경 및 필요성 : 소스코드 라인 수(LOC, Lines of Code) 방식의 언어별 편차와 사전 예측 불가능성 극복, 프로젝트 기획 단계부터의 객관적·일관된 사업 규모 및 예산 산정.
- 주요 목적 : 사업 규모의 객관화, 예산·대가 산정의 공정성 확보, 생산성·품질 측정 기준 제공.
- 국제 표준 및 국내 지침 : ISO(International Organization for Standardization)/IEC(International Electrotechnical Commission) 20926 및 한국소프트웨어산업협회(KOSA) '소프트웨어사업 대가산정 가이드'.

## Ⅱ. 기능점수(Function Point)의 특징

- 핵심 요약 : 데이터 기능과 트랜잭션 기능의 5대 구성요소로 규모를 측정하는 언어 중립 체계.
1. **데이터 기능** (Data Functions) : 내부논리파일과 외부연계파일로 구성되는 데이터 보유·참조 기능.
2. **트랜잭션 기능** (Transaction Functions) : 외부입력, 외부출력, 외부조회로 구성되는 기능 처리 기능.
3. **복잡도 결정 기준** : RET(Record Element Type, 레코드요소타입), DET(Data Element Type, 데이터요소타입), FTR(File Type Referenced) 개수에 따른 낮음·보통·높음 차등.
4. **언어·기술 중립성** : 프로그래밍 언어와 무관한 논리적 기능 기준 측정.
5. **이원 측정 체계** : 신속 견적용 간이 기능점수법과 정밀 정산용 정규 기능점수법의 병행 운용.

- **ILF** (Internal Logical File, 내부논리파일) : 시스템 내부에서 생성, 갱신, 관리되는 논리적 데이터 그룹 (RDB(Relational Database)의 관리 테이블). RET와 DET 수에 따라 복잡도 결정.
- **EIF** (External Interface File, 외부연계파일) : 타 시스템에서 유지관리되지만 해당 시스템에서 참조하여 읽어오는 데이터 그룹.
- **EI** (External Input, 외부입력) : 시스템 내부로 데이터를 들여와 ILF를 등록·수정·삭제하는 기능 (회원가입, 주문등록).
- **EO** (External Output, 외부출력) : 데이터를 가공, 계산, 변환하여 외부로 내보내는 기능 (통계 리포트, 집계 화면).
- **EQ** (External Inquiry, 외부조회) : 단순 검색 및 데이터 조회 기능 (단순 목록 조회, 상세 조회).

## Ⅲ. 기능점수(Function Point)의 구조 (흐름)

- 핵심 요약 : 5대 구성요소 식별 → 복잡도 판정 → 가중치 적용 → 점수 합산의 산정 흐름.
- 5대 기능 구성요소 체계와 기능점수 산정 단계 흐름.

```text
[ 전체 기능점수 (FP) ]
   ├─ [ 데이터 기능 (Data Functions) ]
   │    - 내부논리파일 (ILF)
   │    - 외부연계파일 (EIF)
   └─ [ 트랜잭션 기능 (Transaction Functions) ]
        - 외부입력 (EI)
        - 외부출력 (EO)
        - 외부조회 (EQ)
 * ILF(Internal Logical File),
   EIF(External Interface File)
 * EI(External Input), EO(External Output),
   EQ(External Inquiry)
```

```text
[ 기능점수 산정 흐름 ]
 기능 식별
  - ILF, EIF, EI, EO, EQ 분류
        ↓
 복잡도 판정
  - RET/DET/FTR 개수 카운팅
        ↓
 가중치 적용
  - 간이법: 평균 가중치
  - 정규법: 복잡도 매트릭스
        ↓
 기능점수(FP) 합산
  - 총 규모 및 대가 산정
```

## Ⅳ. 간이 기능점수법과 정규 기능점수법의 비교

- 핵심 요약 : 적용 시점·데이터 수집 수준·가중치·공수·오차율의 차이.
- 적용 시점, 데이터 수집 수준, 가중치, 산정 공수, 오차율 축 비교.

| 비교 항목 | 간이 기능점수법 (평균 복잡도 적용) | 정규 기능점수법 (상세 복잡도 매트릭스) |
|---|---|---|
| 적용 시점 | 기획, 예산 수립, 발주 공고 단계 | 상세 분석 및 설계 완료 후 개발 단계 |
| 데이터 수집 수준 | 기능 식별만 수행 (RET/DET/FTR(File Type Referenced) 미측정) | RET, DET, FTR의 개수를 전수 카운팅 |
| 기능별 가중치 | 고정된 평균 가중치 적용 (ILF: 7.5, EIF: 5.4, EI: 4.0, EO: 5.2, EQ: 3.9) | 복잡도(Low, Average, High) 매트릭스에 따른 차등 가중치 적용 |
| 산정 소요 공수 | 매우 적음 (신속한 예산 견적 가능) | 많은 시간과 전문 인력 필요 (정밀 정산) |
| 오차율 | $\pm 10\sim 15\%$ 수준 오차 존재 가능 | 오차 최소화 (가장 정확한 규모 확정) |

## Ⅴ. 기능점수(Function Point)의 장점과 한계

- 핵심 요약 : 언어 중립·사전 산정의 장점, 측정자 주관성·비기능 반영 한계·초기 오차 리스크.
- 장점
  1. 프로그래밍 언어·기술 스택과 무관한 객관적 규모 측정.
  2. 기획 단계부터의 예산·대가 사전 산정 가능.
  3. 국제 표준 기반 대가 협의의 공정성·일관성 확보.
- 한계점 1 : 측정자의 주관성에 따른 산정 결과의 변동성(편차)
  - 한계점 : 데이터 기능(ILF/EIF)과 트랜잭션 기능(EI/EO/EQ) 식별 시 분석가의 도메인 이해도와 해석 기준에 따른 상당한 오차 발생.
  - 해결 방안 : **공인 기능점수 전문가** (CFPS, Certified Function Point Specialist) 참여 의무화, 내부 산정 표준 가이드라인 구체화, 다자간 교차 검증(Cross-check) 프로세스 제도화.
- 한계점 2 : 현대 클라우드 네이티브 및 비기능 아키텍처 복잡도 반영 한계
  - 한계점 : 사용자 인터페이스 중심의 논리적 기능 측정 방식으로 MSA(Microservice Architecture), 데이터 파이프라인, AI(Artificial Intelligence) 모델 학습, 고가용성 인프라 엔지니어링 공수 과소 계상.
  - 해결 방안 : 공공 SW(Software) 대가산정 가이드라인의 비기능·아키텍처 보정계수 현실화, 인프라·신기술 요소에 대한 별도 **실비정액가산** 방식 복합 적용.
- 한계점 3 : 사업 초기 요구사항 불명확 시 간이법의 오차 리스크
  - 한계점 : 제안·기획 단계에서 평균 복잡도를 적용하는 간이 기능점수법과 상세 분석·설계 후 도출되는 정규 기능점수 간 심각한 예산 괴리 유발.
  - 해결 방안 : 사업 단계별 **점진적 상세화** (Rolling Wave) 예산 조정 제도 도입, 과업 변경 시 객관적 정규 FP 기반 계약금액 증액 거버넌스 확립.

## Ⅵ. 기능점수(Function Point)에 대한 기술사적 제언

- 핵심 요약 : 정규 FP 기반 사후 정산제 정착과 분산 아키텍처 대응 측정 기준 고도화.
- 설계 완료 후 정규 기능점수 기반의 사후 정산제 정착 : 공공 발주 시 기획 단계의 간이법으로 확정된 예산과 실제 상세 설계 후 도출된 정규 FP 간에 차이가 발생할 경우, 과업심의위원회를 거쳐 계약금액을 공식적으로 증감 정산하는 사후 정산 거버넌스 제도화 필수.
- 클라우드 및 마이크로서비스 환경에 부합하는 FP 측정 기준 고도화 : 기존 모놀리식 단일 DB(Database) 중심의 ILF/EIF 산정 기준은 서비스별로 DB가 분리된 MSA 환경에서 EIF가 폭증하거나 복잡한 이벤트 브로커 연계가 누락되는 왜곡이 발생하므로, 분산 아키텍처 특성을 반영한 현대적 FP 가이드라인 개정 필요.

## Ⅶ. 결론

- 핵심 요약 : 기능점수는 언어 중립적 소프트웨어 규모 산정의 국제 표준 척도.
- 요약 : 기능점수는 5대 기능 구성요소 기반으로 사용자 관점의 논리적 업무 기능을 정량 측정.
- 시사점 : 측정자 주관성 통제, 비기능·분산 아키텍처 보정, 단계별 정산 거버넌스로 산정 신뢰성 확보.
