## 연관 키워드
- Function Point, IFPUG, ILF, EIF, EI, EO, EQ, DET, RET, FTR

### Ⅰ. 기능 점수의 개요

- 핵심 요약 : 기능 점수(FP)는 사용자가 인식하는 데이터·트랜잭션 기능을 측정해 소프트웨어 기능 규모를 산정하는 기법.
- 개념 : 기술·언어와 독립적으로 논리 데이터와 사용자 기능을 분류·복잡도화 해 규모를 계산(**기능 점수**, Function Point).
- 배경 및 필요성 : LOC는 설계·언어 선택 전 산정이 어렵고 구현 방식에 따라 값이 달라짐.
- 주요 목적 : 초기 규모·비용·생산성 비교와 사업 범위 변경 추적의 공통 기준 제공.

### Ⅱ. 기능 점수 구성과 장점

- 핵심 요약 : 5 대 기능 유형과 복잡도 가중치로 사용자 관점의 기능량을 산출.

1. 데이터 기능 : 내부 논리 파일(ILF), 외부 연계 파일(EIF) → 시스템이 유지하거나 참조하는 논리 데이터 규모 반영.
2. 트랜잭션 기능 : 외부 입력(EI), 외부 출력(EO), 외부 조회(EQ) → 입력·계산·조회 기능 규모 반영.
3. 기술 독립성 : 구현 언어·코드 량에 직접 의존하지 않음 → 대안·업체 간 규모 비교 지원.

### Ⅲ. FP 측정 절차

- 핵심 요약 : 측정 목적·경계 정의 → 기능 식별 → DET·RET·FTR 복잡도 판정 → 가중 합·조정 → 검증.

```text
시스템 경계·측정 유형 확정
    ↓
ILF/EIF와 EI/EO/EQ 식별
    ↓
DET·RET·FTR 산정 → 낮음/보통/높음 복잡도 결정
    ↓
기능 별 가중치 합산 → 검토·기록
```

```text
조정 전 기능 점수(UFP) = Σ[기능 유형 별 개수 × 복잡도 가중치]
유형·버전 별 보정 규칙은 적용하는 측정 표준에 따라 명시
```

- 산출물 : 기능 목록, 경계·측정 유형, 복잡도 근거, 요구 사항 추적 정보.

### Ⅳ. 기능 점수와 LOC 비교

- 핵심 요약 : FP는 요구 기능·언어 독립 규모, LOC는 구현 코드 량·기술 및 코딩 스타일 의존 규모.

| 기준 | FP | LOC |
|---|---|---|
| 측정 기준 | 사용자 기능·데이터 | 소스 코드 행 |
| 산정 시점 | 요구·설계 단계 부터 가능 | 구현 방식·언어 결정 이후 용이 |
| 장점 | 언어·구현 독립 비교 | 코드 규모와 직접 연결 |
| 한계 | 경계·복잡도 판정 자 편차 | 재사용·생성 코드·언어 별 편차 |

### Ⅴ. 기능 점수의 한계와 방안

- 핵심 요약 : 기능 경계·요구 품질·분산 구조가 판정과 비용으로 이어지는 정도를 측정 가이드와 보조 모형으로 보완.

| 한계 | 영향 | 대응 |
|---|---|---|
| 측정 자 판정 차이 | 기능 유형·복잡도 편차 | 기준 서·독립 검토·측정 사례 축적 |
| 비 기능·기술 복잡도 미반영 | 같은 FP라도 공수 상이 | 품질 요구·기술 위험·비용 동인 별도 보정 |
| 분산·재사용 구조 | 기능 경계·외부 연계 해석 곤란 | 경계·재사용 범위·인터페이스 규칙 사전 합의 |

### Ⅵ. FP 운영 제언

- 핵심 요약 : 산정 책임 자는 기준·근거·버전을 기록하고 요구·계약 변경 시 영향 분석과 재 측정.

1. 발주 자·수행 자는 측정 경계와 포함·제외 기능을 합의.
2. 측정 자는 ILF/EIF와 트랜잭션 분류·DET/RET/FTR 판정 근거를 보존.
3. PMO는 추정·실적 FP와 공수를 축적해 조직 별 생산성 자료를 보정.

### Ⅶ. 결론

- 핵심 요약 : FP는 사용자 관점의 기능 규모를 구현 기술과 분리해 측정하는 산정 기법.
- 시사점 : 일관된 경계·복잡도 판정과 비 기능 위험 보정이 산정의 재현성을 좌우.
