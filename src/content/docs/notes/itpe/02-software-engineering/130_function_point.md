## 연관 키워드

- Function Point, 기능점수, SW 규모 산정
- IFPUG, ISO/IEC 20926, LOC(Lines of Code)
- ILF(Internal Logical File), EIF(External Interface File)
- EI(External Input), EO(External Output), EQ(External Inquiry)
- RET/DET/FTR, 간이·정규 기능점수법, 사후 정산

## Ⅰ. 기능점수(Function Point)의 개요

- 핵심 요약 : 사용자 관점의 논리적 업무 기능을 구현 언어와 무관하게 정량 측정하는 국제 표준 규모 산정 척도.
- 개념 : 구현에 쓰인 프로그래밍 언어나 기술 스택과 관계없이 최종 사용자 관점에서 소프트웨어가 제공하는 논리적 업무 기능을 수치로 측정하는 **기능점수** (FP, Function Point). 앨런 알브레히트(Allan Albrecht)가 창안하고 IFPUG(International Function Point Users Group, 국제기능점수사용자그룹)가 표준화하였으며, 국제 표준 ISO/IEC 20926으로 제정됨.
- 배경 및 필요성 : 소스코드 라인 수(LOC, Lines of Code) 방식은 언어에 따라 편차가 크고 개발 전에는 측정할 수 없으므로, 기획 단계부터 객관적이고 일관된 규모 산정 기준이 필요.
- 주요 목적 : 사업 규모의 객관화, 예산과 대가 산정의 공정성 확보, 생산성과 품질 측정 기준 제공.
- 국내 적용 : 국내 공공 SW 사업의 대가 산정 가이드라인에서도 기능점수 기반 산정 방식을 활용.

## Ⅱ. 기능점수(Function Point)의 특징 및 장점

- 핵심 요약 : 데이터 기능과 트랜잭션 기능의 5대 구성요소를 복잡도별로 측정하여 언어에 중립적인 규모 값을 얻는 체계.

1. **데이터 기능** (Data Functions) : 내부논리파일과 외부연계파일로 이루어진 데이터 보유·참조 기능 → 시스템이 관리하는 데이터 자산의 규모 반영.
2. **트랜잭션 기능** (Transaction Functions) : 외부입력, 외부출력, 외부조회로 이루어진 데이터 처리 기능 → 사용자와의 상호작용 규모 반영.
3. 복잡도 결정 기준 : RET(Record Element Type, 레코드 요소 타입), DET(Data Element Type, 데이터 요소 타입), FTR(File Types Referenced, 참조 파일 타입) 개수에 따라 낮음·보통·높음으로 차등 → 같은 기능이라도 내부 구조 차이를 가중치에 반영.
4. 언어·기술 중립성 : 프로그래밍 언어와 무관한 논리적 기능을 기준으로 측정 → 기술이 바뀌어도 규모 비교가 가능.
5. 이원 측정 체계 : 신속한 견적용 간이 기능점수법과 정밀 정산용 정규 기능점수법을 병행 → 단계별 목적에 맞는 산정 방식 선택.

- **ILF** (Internal Logical File, 내부논리파일) : 시스템 내부에서 생성·갱신·관리되는 논리적 데이터 그룹으로, RET와 DET 수로 복잡도를 판정.
- **EIF** (External Interface File, 외부연계파일) : 다른 시스템이 관리하고 해당 시스템은 참조만 하는 데이터 그룹.
- **EI** (External Input, 외부입력) : 외부 데이터를 받아 ILF를 등록·수정·삭제하는 기능(예: 회원 가입, 주문 등록).
- **EO** (External Output, 외부출력) : 데이터를 가공·계산해 외부로 내보내는 기능(예: 통계 리포트).
- **EQ** (External Inquiry, 외부조회) : 가공 없이 검색하여 보여주는 기능(예: 목록 조회, 상세 조회).

## Ⅲ. 기능점수(Function Point)의 구조 (흐름)

- 핵심 요약 : 5대 구성요소로 기능을 식별하고, 복잡도 판정과 가중치 적용을 거쳐 기능점수를 합산하는 흐름.

```text
[ 기능점수 (FP) 구성 ]

데이터 기능 (Data Functions)
  - 내부논리파일 (ILF)
  - 외부연계파일 (EIF)
트랜잭션 기능 (Transaction Functions)
  - 외부입력 (EI)
  - 외부출력 (EO)
  - 외부조회 (EQ)
```

```text
[ 기능점수 산정 흐름 ]

기능 식별 (ILF, EIF, EI, EO, EQ 분류)
      ↓
복잡도 판정 (RET, DET, FTR 개수 집계)
      ↓
가중치 적용 (간이법은 평균, 정규법은 매트릭스)
      ↓
기능점수 합산 → 총 규모 및 대가 산정
```

## Ⅳ. 간이 기능점수법과 정규 기능점수법의 비교

- 핵심 요약 : 간이법은 빠른 견적을, 정규법은 정확한 정산을 목표로 하여 데이터 수집 수준과 가중치 적용 방식이 다름.

| 비교 항목 | 간이 기능점수법 | 정규 기능점수법 |
| --- | --- | --- |
| 적용 시점 | 기획, 예산 수립, 발주 공고 단계 | 상세 분석과 설계 완료 후 개발 단계 |
| 데이터 수집 수준 | 기능 식별 중심, RET·DET·FTR 개수는 생략 | RET, DET, FTR 개수를 전수 집계 |
| 가중치 적용 | 유형별 평균 가중치 적용 (ILF 7.5, EIF 5.4, EI 4.0, EO 5.2, EQ 3.9, SW사업 대가산정 가이드 기준) | 복잡도(낮음, 보통, 높음)별 매트릭스로 차등 적용 |
| 산정 소요 공수 | 짧아 신속한 예산 견적 가능 | 전문 인력과 시간이 많이 필요 |
| 정확도 | 측정 시점의 요구사항 명확도에 따라 편차가 큼 | 상세 자료에 근거하여 규모를 확정하기에 적합 |

## Ⅴ. 기능점수(Function Point)의 한계와 방안

- 핵심 요약 : 언어 중립성과 사전 산정이라는 장점 이면에 측정자 주관성, 비기능·분산 아키텍처 미반영, 초기 요구사항 불명확에 따른 예산 괴리의 한계가 존재.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 측정자 주관성에 따른 편차 | ILF·EIF와 EI·EO·EQ 식별 시 분석가의 도메인 이해와 해석 기준에 따라 결과가 달라짐 | 공인 기능점수 전문가(CFPS, Certified Function Point Specialist)의 참여와 교차 검증 절차 제도화 | 산정자 간 편차율 |
| 비기능·분산 아키텍처 반영 한계 | 사용자 기능 중심 측정이라 MSA, 데이터 파이프라인, AI(Artificial Intelligence) 모델 학습, 고가용성 인프라 공수가 과소 계상됨 | 비기능·아키텍처 보정 기준의 현실화와 인프라·신기술 요소의 **실비정액가산** 방식 병행 | 보정 항목별 공수 실적 대비 계상 차이 |
| 간이법과 정규법 간 예산 괴리 | 요구사항이 불명확한 단계의 평균 복잡도 적용 결과가 상세 설계 후 규모와 크게 달라짐 | 사업 단계별로 예산을 나누어 확정하는 **점진적 상세화** (Rolling Wave) 방식과 과업 변경 시 정규 기능점수 기반 계약 조정 | 과업 변경 건수, 계약 금액 조정률 |

## Ⅵ. 기능점수(Function Point)에 대한 기술사적 제언

- 핵심 요약 : 상세 설계 후 정규 기능점수로 정산하는 제도를 정착시키고, 분산 아키텍처를 반영한 측정 기준으로 개정하는 방향.
- 공공 발주에서는 기획 단계의 간이법으로 정한 예산과 상세 설계 후의 정규 기능점수 사이에 차이가 생기기 쉬우므로, 차이가 일정 범위를 넘으면 심의를 거쳐 계약 금액을 증감하는 사후 정산 절차를 제도로 두는 것이 필요하다.
- 기존 측정 기준은 단일 데이터베이스를 쓰는 모놀리식 구조를 전제로 하므로, 서비스마다 데이터베이스가 분리된 MSA 환경에서는 EIF가 과다하게 집계되거나 이벤트 브로커를 통한 연계가 누락되는 왜곡이 생긴다. 분산 아키텍처의 연계 구조를 반영한 측정 가이드라인 개정이 뒤따라야 한다.

## Ⅶ. 결론

- 핵심 요약 : 기능점수는 언어에 중립적인 소프트웨어 규모 산정의 국제 표준 척도.
- 5대 구성요소로 사용자 관점의 업무 기능을 정량화하는 이 척도는 측정자 주관성을 통제하고 비기능·분산 아키텍처를 보정하며 단계별 정산 절차와 결합할 때 산정 신뢰성을 확보한다.
