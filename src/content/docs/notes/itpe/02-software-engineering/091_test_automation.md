## 연관 키워드
- 테스트 자동화, 테스트 피라미드, 단위·서비스·UI 테스트, 자동화 프레임워크, 회귀 테스트, 신뢰성

### Ⅰ. 테스트 자동화의 개요

- 핵심 요약 : 테스트 자동화는 반복 가능한 테스트 실행·결과 검증·보고를 도구와 스크립트로 수행해 개발 피드백과 회귀 검증을 빠르게 하는 활동.
- 개념 : 반복 가능한 테스트 실행·결과 검증·보고를 도구와 스크립트로 수행해 개발 피드백과 회귀 검증을 빠르게 하는 활동(**테스트 자동화**, Test Automation).
- 배경 및 필요성 : 수동 회귀 시험은 반복 비용·실행 시간이 커져 지속적 변경과 잦은 배포를 뒷받침하기 어려움.
- 주요 목적 : 변경 때마다 신뢰할 수 있는 검증을 반복해 결함 유출을 줄이고 안전한 릴리스 속도를 높임.

### Ⅱ. 테스트 자동화의 특징 및 장점

- 핵심 요약 : 테스트 피라미드·안정된 검증 대상·테스트 오라클·파이프라인 연계.

1. 테스트 피라미드 : 빠르고 격리된 단위 시험을 넓게, 통합·UI 시험은 필요한 범위로 구성 → 빠른 피드백과 유지비 균형.
2. 안정된 검증 대상 : 명확한 요구·수용 조건·결정적 데이터에 자동화 적용 → 결과 재현성 향상.
3. 테스트 오라클 : 기대 결과·불변식·계약을 코드화 → 단순 실행이 아닌 결함 판정 가능.
4. 파이프라인 연계 : 변경 이벤트에 빌드·테스트·결과 보고 실행 → 회귀 오류 조기 탐지.

### Ⅲ. 테스트 자동화의 구조 (흐름)

- 핵심 요약 : 테스트 대상·위험 선택 → 자동화 가능성·오라클 설계 → 스크립트·데이터 작성 → CI(Continuous Integration, 지속적 통합)에서 실행 → 실패 분류·조치 → 유지·정리.

```text
테스트 대상·위험 선택
   ↓
자동화 가능성·오라클 설계
   ↓
스크립트·데이터 작성
   ↓
CI에서 실행
   ↓
실패 분류·조치
   ↓
유지·정리
```

```text
피라미드: 실행량·속도
        UI·시나리오 테스트 (소수)
      서비스·통합 테스트 (중간)
    단위·컴포넌트 테스트 (다수)
        빠른 피드백 →
```

### Ⅳ. 테스트 자동화와 다른 테스트 방식 비교

- 핵심 요약 : 수동 테스트는 사람이 탐색·판단·결과 확인, 자동화 테스트는 스크립트가 반복 입력·검증·기록.

| 비교 대상 | 핵심 특성 | 적용·판단 기준 |
|---|---|---|
| 수동 테스트 | 사람이 탐색·판단·결과 확인 | 사용성·탐색·비정형 판단에 적합 |
| 자동화 테스트 | 스크립트가 반복 입력·검증·기록 | 회귀·계약·반복 검증에 적합 |
| 기록 재생 UI 자동화 | 화면 상호 작용을 재생 | 실사용 흐름 확인에 유용하나 UI 변경에 취약 |

### Ⅴ. 테스트 자동화의 한계와 방안

- 핵심 요약 : 취약한 UI 자동화·잘못된 테스트 오라클·과도한 자동화 범위를 테스트 레벨 하향·독립 오라클 검토·우선순위화로 관리.

| 위험 | 원인·영향 | 대응 통제 | 지표 예시 |
|---|---|---|---|
| 취약한 UI 자동화 | 선택자·타이밍 변화로 잦은 오탐 | 테스트 레벨을 낮추고 안정된 API·접근성 선택자 활용 | 불안정률, 유지 시간 |
| 잘못된 테스트 오라클 | 자동화가 잘못된 기대값을 반복 확인 | 독립 요구·불변식·계약 검증으로 기대값 검토 | 결함 탐지율, false positive |
| 과도한 자동화 범위 | 초기·유지비가 가치보다 커짐 | 빈도·위험·재현성으로 후보 우선순위화 | 자동화 투자 대비 절감 시간 |

### Ⅵ. 테스트 자동화 적용에 대한 기술사적 제언

- 핵심 요약 : 변경 때마다 신뢰할 수 있는 검증을 반복해 결함 유출을 줄이고 안전한 릴리스 속도를 높임.

- 실행 제언 : 테스트 리더는 실행 속도만 목표로 삼지 말고 테스트 계층별 비용·결함 검출 가치를 관리하며, 테스트 데이터·환경·오라클을 제품 코드와 함께 버전 관리.

### Ⅶ. 결론

- 핵심 요약 : 테스트 자동화는 반복 가능한 테스트 실행·결과 검증·보고를 도구와 스크립트로 수행해 개발 피드백과 회귀 검증을 빠르게 하는 활동.
- 시사점 : 테스트 자동화는 테스트 인력 대체가 아니라 반복 가능한 검증을 개발 흐름에 내재화하는 수단이며, 자동화 가능성은 안정성과 가치로 판단.
