## 지식 로드맵 내 현재 위치

지식 위치: 소프트웨어공학 → 테스트 및 검증 → 테스트 자동화

## 30초 인출

- **본질**: 테스트 자동화는 반복 시험의 실행과 결과 판정을 도구로 수행해 변경 후 검증을 빠르고 일관되게 하는 방법
- **메커니즘**: 시험 조건·기대 결과를 코드로 표현하고, 변경 때 실행해 결과를 비교·기록

<details>
<summary>핵심 용어</summary>

- **테스트 자동화(Test Automation)**: 시험 실행·비교·보고 중 반복 가능한 활동을 도구로 수행하는 방법
- **회귀 테스트(Regression Testing)**: 변경으로 기존 기능이 손상되지 않았는지 확인하는 테스트
- **테스트 오라클(Test Oracle)**: 시험 결과가 기대값에 맞는지 판단하는 기준이나 방법
- **플래키 테스트(Flaky Test)**: 동일한 코드·조건에서도 실행 결과가 일관되지 않은 테스트
- **DDT(Data-Driven Testing)**: 테스트 로직과 입력·기대값 데이터를 분리하는 방식
- **KDT(Keyword-Driven Testing)**: 테스트 동작을 정해진 키워드로 표현하는 방식
- **BDD(Behavior-Driven Development)**: 이해관계자가 공유할 행위 시나리오를 개발·테스트 명세로 연결하는 접근
- **POM(Page Object Model)**: 화면 요소 접근 코드를 페이지 단위 객체로 분리하는 UI 테스트 설계 패턴
- **CI(Continuous Integration)**: 코드 변경을 자주 통합하고 자동 빌드·검증하는 개발 방식

|---|---|

### Ⅱ. 기본 수행 흐름

```text
시험 조건·기대 결과 정의
```

| 우선순위 | 자주 반복되고 결과를 객관적으로 판정할 수 있는 시험부터 자동화 |
| 유지관리 | 테스트 데이터·환경·스크립트를 제품 변경과 함께 관리 |

## 2~4교시 25점 답안

## Ⅰ. 테스트 자동화의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 반복 시험의 실행·결과 비교·기록을 도구로 수행하는 방법 |
| 목적 | 변경 후 회귀 검증의 반복 비용과 수작업 편차를 줄이는 것 |

## Ⅱ. 자동화 수행 흐름

```text
시험 조건·기대 결과 정의
    ↓
자동화 스크립트 실행
    ↓
실제·기대 결과 비교
    ↓
실패 기록·알림
    ↓
결함 수정 후 재검증
```

시험은 빌드·배포 흐름에 연결할 수 있으며, 단계와 차단 기준은 제품 위험과 팀 운영에 맞춰 설정.

## Ⅲ. 대표 접근 방식

| 접근 방식 | 구분 기준 | 적합한 사용 |
|---|---|---|
| 단위·서비스·UI 테스트 | 검증 대상의 범위 | 작은 단위부터 외부 인터페이스와 사용자 흐름까지 서로 다른 위험 확인 |
| DDT | 데이터와 테스트 로직 분리 | 여러 입력·기대값 조합을 같은 로직으로 검증 |
| KDT | 동작을 키워드로 표현 | 재사용 동작으로 시나리오를 구성할 때 |
| BDD | 행위 시나리오를 공유 명세로 표현 | 요구 이해를 개발·테스트 간에 맞출 때 |
| POM | 화면 접근 코드를 페이지 객체로 분리 | UI 선택자 변경의 영향 범위를 줄일 때 |

접근 방식은 서로 배타적인 테스트 종류가 아니며, 제품 구조와 팀의 유지관리 여건에 따라 조합.

## Ⅳ. 신뢰할 수 있는 자동화 운영

| 위험 | 대응 |
|---|---|
| 비결정적 데이터·환경으로 인한 플래키 테스트 | 테스트 데이터와 외부 의존성을 격리하고 실행 조건을 기록 |
| 결과 비교 기준 부재 | 요구사항·명세·독립 계산 등 적절한 테스트 오라클을 정의 |
| UI 변경에 따른 잦은 스크립트 수정 | UI 접근 로직을 분리하고 안정적인 접근 식별자를 사용 |
| 실패 알림 누적과 장기 방치 | 실패 원인을 구분하고 담당·수정·재검증 상태를 추적 |

## Ⅴ. 적용 제언

| 한계 | 해결 방안 |
|---|---|
| 자동화 범위가 넓어지지만 유지비와 실패 신뢰도가 함께 악화될 가능성 | 반복 빈도·결함 영향·판정 가능성을 기준으로 우선순위를 정하고, 신뢰도와 유지비를 주기적으로 검토해 범위를 조정 |

- 연계: CI/CD, 테스트 오라클, 테스트 데이터 관리
