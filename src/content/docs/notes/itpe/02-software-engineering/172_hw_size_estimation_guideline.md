## 한 줄 본질
- 주관적 감으로 서버를 발주하여 오픈 당일 용량 부족으로 서버가 뻗거나 과도한 고스펙 도입으로 국가 예산이 낭비되는 병목 → TTA 표준 공식에 따라 동시 접속자 수, 트랜잭션 수, 데이터 증가량을 수식에 대입하여 최적 하드웨어 스펙을 도출하는 국가 표준 가이드 / 클라우드 탄력성 미반영 한계

## 핵심 용어
- tpmC(Transactions Per Minute C): TPC-C 벤치마크 표준에 따른 분당 트랜잭션 처리 건수로, 데이터베이스(DB) 서버의 OLTP 연산 처리 성능을 나타내는 대표 지표
- 보정계수: 시스템 인터페이스 복잡도, 데이터베이스 크기, 클러스터링(이중화), 시스템 여유율 등 실제 운영 환경의 비기능적 오버헤드를 반영하기 위해 기본 용량에 곱하는 가중치 계수

## 핵심 통찰
- 전통적인 TTA 하드웨어 규모산정 지침은 물리적 온프레미스 서버를 일괄 발주하던 시절에 제정된 수식 모형이므로, CPU 코어 수를 동적으로 늘릴 수 있는 클라우드 가상 인스턴스(vCPU) 환경에서는 과대 산정되는 경향이 있음
- 2023년 개정판(R3)에서는 최신 CPU 클록과 멀티코어 성능 향상을 반영하여 기본 트랜잭션 가중치를 현실화하고, 불필요한 과다 보정계수를 통폐합함
- 규모산정 수식은 초기 예산 수립을 위한 "가이드라인"일 뿐이며, 최종 도입 단계에서는 실제 애플리케이션 프로토타입을 올려놓고 측정하는 벤치마크 테스트(BMT/PoC) 결과와 반드시 대조해야 함

## 이웃 토픽과 구분
- TTA HW 규모산정 vs BMT(Benchmark Test): TTA 공식 = 과거 표준 계수 기반의 수학적 추정(발주/예산용) / BMT = 실제 하드웨어에 소프트웨어를 탑재해 부하를 걸어보는 실측 검증(도입/검수용)
