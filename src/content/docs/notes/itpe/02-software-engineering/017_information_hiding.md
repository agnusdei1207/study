## 연관 키워드

- 정보은닉, Parnas 원리, 비밀(Secret), 모듈화
- 캡슐화, 결합도, 응집도, 변경 파급 최소화

## Ⅰ. 정보은닉의 개요

- 핵심 요약 : 정보은닉은 변경 가능성이 높은 설계 결정을 모듈 내부에 감추고 안정된 인터페이스만 공개하는 모듈화 원리.
- 개념 : 각 모듈이 자신만 책임지는 설계 결정을 외부에 감추고 정의된 인터페이스를 통해서만 상호작용하도록 하는 원리(**정보은닉**, Information Hiding). 감추는 대상을 **비밀**(Secret)로 부름.
- 배경 및 필요성 : **Parnas 원리**(모듈 분해 기준을 실행 순서가 아닌 변경 가능성이 높은 설계 결정에 두는 원칙)에 따르면, 구현 세부가 모듈 간에 공유되면 한 곳의 수정이 여러 모듈로 전파되어 수정·시험 비용이 증가하는 상태가 됨.
- 주요 목적 : 변경 영향을 모듈 경계 안에 국한하는 변경 파급 최소화와 낮은 결합도·높은 응집도의 모듈 독립성 확보.

## Ⅱ. 정보은닉의 특징 및 장점

- 핵심 요약 : 변하기 쉬운 결정은 비밀로 감추고 외부에는 계약 역할의 인터페이스만 공개하는 구조가 유지보수성으로 연결.

1. 비밀 중심 분해 : 모듈 분할 기준을 업무 절차가 아니라 변경 가능성이 높은 설계 결정에 둠 → 요구 변화를 모듈 내부에 흡수하는 변경 파급 최소화.
2. 인터페이스-구현 분리 : 연산 명세(공개)와 자료구조·알고리즘(비공개)을 분리 → 구현 교체가 타 모듈 수정 없이 가능.
3. 모듈 독립성 향상 : 내부 세부 접근 차단으로 모듈 간 의존 강도인 **결합도**(Coupling)를 낮추고 모듈 내 기능 밀집도인 **응집도**(Cohesion)를 높임 → 병렬 개발·단위 시험 용이.
4. 캡슐화와의 결합 : 데이터와 연산을 하나로 묶어 접근을 제한하는 **캡슐화**(Encapsulation)가 정보은닉의 대표 구현 수단 → 객체지향 언어의 접근 제한자가 원리를 언어 차원에서 지원.

## Ⅲ. 정보은닉의 구조 (흐름)

- 핵심 요약 : 외부는 공개 인터페이스만 보고, 자료구조·알고리즘·정책 같은 비밀은 모듈 경계 안쪽에 위치.

```text
외부 모듈(클라이언트)
   ↓ 인터페이스 경유 호출만 허용
공개 인터페이스 : 연산 명세·계약
   ↓ 직접 접근 차단
모듈 내부 비밀 : 자료구조·알고리즘·정책
```

```text
[ 정보은닉 적용 절차 ]
변동 요인 식별 → 비밀 배정(모듈 분해)
   ↓
인터페이스 정의 → 내부 구현 캡슐화
   ↓
요구 변경 발생
   ↓
모듈 내부만 수정 → 회귀시험
```

- 은닉 대상 : 데이터 표현, 외부 시스템 연동 방식, 저장소 접근, 업무 정책, 플랫폼 종속 코드.

## Ⅳ. 정보은닉과 데이터 노출형 설계의 비교

- 핵심 요약 : 정보은닉 설계는 접근을 인터페이스로 제한해 변경을 국소화하는 반면, 데이터 노출형 설계는 모듈 간 자유 접근으로 변경이 전체로 확산.

| 비교 축 | 정보은닉 설계 | 데이터 노출형 설계 |
| --- | --- | --- |
| 접근 방식 | 인터페이스 경유 접근만 허용 | 모듈 간 자료·세부 자유 접근 |
| 변경 파급 범위 | 모듈 내부에 국소화 | 표현 변경이 다수 모듈로 확산 |
| 결합도 수준 | 낮음(자료·제어 결합 수준) | 높음(내용·공통 결합 유발) |
| 시험·책임 | 모듈 단위 시험, 책임 경계 명확 | 원인 추적·책임 경계 모호 |

## Ⅴ. 정보은닉의 한계와 방안

- 핵심 요약 : 과도한 은닉은 추상화·간접화 비용을 늘리므로 실제 변경 빈도와 계약 필요성에 맞춘 경계 설계가 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 과도한 추상화 | 모든 결정을 은닉 대상화 → 간접 호출·추적 비용 증가 | 변경 빈도가 높은 결정 위주로 경계화 | 경계당 추상화 층 수 |
| 불완전한 인터페이스 | 공개 명세 누락 → 내부 노출 요구 증가 | 사용 사례·불변 조건 기반 계약 리뷰 | 인터페이스 변경 건수 |
| 은닉 위반 확산 | 전역 변수·내부 구조 직접 참조 | 정적 분석·코드 리뷰로 접근 위반 차단 | 접근 위반 지적 건수 |

## Ⅵ. 정보은닉에 대한 제언

- 핵심 요약 : 아키텍처 거버넌스 차원에서 변경 이유별 책임 경계와 공개 범위를 조직 표준으로 관리.
- 개발 조직 : 변경 이유가 다른 책임을 별개 모듈로 배분하는 설계 가이드를 표준화.
- 아키텍처 검토 회의 : 공개 인터페이스와 내부 구현의 분리 수준을 상시 검증.
- 플랫폼팀 : 공개 인터페이스 범위와 내부 모듈 접근 규칙을 빌드 정책·정적 분석 도구로 강제.

## Ⅶ. 결론

- 핵심 요약 : 정보은닉은 변화를 감당하기 위한 설계 원리이며, 비밀을 어디에 둘 것인가가 유지보수성을 결정.
- 은닉 경계의 품질이 변경 비용·병렬 개발·시험 용이성을 좌우하는 설계 기본기.
