## 핵심 용어
- 정보공학 방법론(Information Engineering): 기업의 경영 전략과 전사적 데이터 모델(ISP/BAA)을 먼저 정립한 후 정보시스템을 공학적으로 구축하는 데이터 중심 방법론
- CRUD 매트릭스: 비즈니스 프로세스(업무)와 데이터 엔티티 간의 관계(Create, Read, Update, Delete)를 2차원 표로 검증하여 데이터 누락 및 프로세스 무결성을 점검하는 도구

## 핵심 통찰
- 4대 방법론은 앞선 세대를 완전히 버리고 대체하는 관계가 아니라, 앞선 세대의 통찰을 내부에 흡수하며 추상화 단위를 키워온 역사적 발전 과정임
- 현대 시스템에서도 배치 처리나 스트리밍 파이프라인은 "구조적(DFD)", 전사 마스터 데이터 관리는 "정보공학(ERD)", 비즈니스 도메인 엔티티는 "객체지향(DDD)", 배포 단위 패키징은 "CBD(컨테이너/MSA)"의 철학을 융합하여 사용함
- 방법론 선택 시 가장 중요한 기준은 "변경의 주기가 무엇인가"이며, 프로세스가 자주 바뀌면 정보공학이나 객체지향이 우수하고, 모듈 간 결합도를 끊어 독립 배포해야 한다면 CBD가 우수함

## 이웃 토픽과 구분
- 4대 방법론 vs 애자일(Agile): 4대 방법론 = "소프트웨어를 어떻게 모델링하고 모듈화할 것인가(아키텍처/엔지니어링 패러다임)" / 애자일 = "팀이 어떻게 소통하고 점진적으로 출시할 것인가(프로세스/협업 프레임워크)"

## 문제·원인·대책
- 적용 상황: 대규모 공공 금융 차세대 통합 구축 아키텍처 수립
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 객체지향만 강요하여 대규모 데이터 일괄 정산 배치 프로그램의 성능이 극도로 저하됨 | 대량 데이터 연산에는 객체 인스턴스 생성 오버헤드가 없는 절차적/집합적 모델이 유리함 | 데이터 파이프라인 배치에는 구조적/SQL 집합 모델을 적용하는 하이브리드 테일러링 | 배치 처리 속도 5배 향상 및 자원 절감 |
| 전사 데이터 표준이 없는 상태에서 서브시스템별 객체 모델링으로 인한 데이터 중복 및 불일치 | 정보공학적 관점의 전사 데이터 아키텍처(DA) 및 거버넌스 부재 | 정보공학의 전사적 데이터 모델링(ISP/BAA)을 선행하여 공통 엔티티 및 코드 정립 | 전사 데이터 정합성 100% 확보 및 사일로 방지 |
