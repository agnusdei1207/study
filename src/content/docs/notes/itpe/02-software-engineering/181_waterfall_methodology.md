## 연관 키워드
- 폭포수 모델, 요구 사항 베이스라인, 단계 별 검토, 순차 개발, 변경 통제

### Ⅰ. 폭포수 방법론의 개요

- 핵심 요약 : 폭포수 모델은 요구 분석 부터 운영·유지 보수 까지 개발 단계를 순차적으로 진행 하는 생명 주기 접근.
- 개념 : 단계 별 산출물을 검토·승인 한 뒤 다음 단계로 넘어 가는 선형 순차 개발 모델(**폭포수 모델**, Waterfall Model).
- 배경 및 필요성 : 범위와 요구가 안정적이고 승인·문서·추적성이 중요한 프로젝트에 계획과 책임 구분 필요.
- 주요 목적 : 단계 별 산출물과 의사 결정 관문을 통해 예측·통제 가능한 개발 수행.

### Ⅱ. 폭포수 방법론의 특징 및 장점

- 핵심 요약 : 단계·산출물·승인 기준을 명확히 해 일정과 요구 추적을 관리 하기 쉬움.

1. 순차 진행 : 앞 단계 결과가 다음 단계 입력 → 역할과 검토 책임 명확.
2. 베이스라인 : 요구·설계 승인 후 변경을 통제 → 변경 영향 분석 가능.
3. 문서 중심 : 요구 부터 시험 까지 추적 → 규제·계약 감사에 유리.
4. 단계 종료 게이트 : 진입·종료 기준을 확인 → 미완료 산출물의 조기 발견.

### Ⅲ. 단계 및 산출물 흐름 (구조)

- 핵심 요약 : 요구 사항 승인 이후 설계·구현·시험·인수·운영 순으로 산출물과 검증을 연결.

```text
요구 분석·명세
   ↓ 승인된 요구 베이스라인
시스템·상세 설계
   ↓ 설계 검토
구현·단위 시험
   ↓ 통합·시스템 시험
인수·배포 → 운영·유지 보수
```

```text
요구 ID → 설계 요소 → 코드 구성 요소
       → 시험 사례 → 결과·결함
```

- 각 단계 전환은 계획서의 종료 기준과 변경 승인 절차에 따라 수행.

### Ⅳ. 순차형과 반복형 비교

- 핵심 요약 : 요구 안정성·피드백 주기·변경 비용에 따라 순차형과 반복형 접근의 적합성이 갈림.

| 비교 축 | 폭포수 | 반복·애자일 접근 |
|---|---|---|
| 요구 변화 | 변경 절차를 통해 통제 | 반복 계획에 반영 가능 |
| 피드백 | 주로 단계·인수 시점 | 짧은 주기로 기능 검증 |
| 산출·문서 | 사전 산출물과 승인 비중 큼 | 작동 결과와 지속 문서 병행 |
| 적합 조건 | 안정 요구·엄격한 계약·승인 | 불확실성·빠른 학습·우선 순위 변화 |

### Ⅴ. 폭포수 방법론의 한계와 방안

- 핵심 요약 : 늦은 사용자 피드백과 변경 누적은 단계 별 검증·시제품·변경 영향 분석으로 완화.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 요구 오해의 후반 발견 | 동작 제품을 늦게 확인 | 초기 프로토타입·요구 검토·사용자 확인 | 요구 변경 건수 |
| 변경 비용 증가 | 이전 단계 재작업과 승인 반복 | 영향 추적·변경 통제 위원회·단계 적 기준선 | 변경 영향 범위 |
| 통합 위험 집중 | 구현 이후 연계 확인 | 지속 통합·수직 프로토타입·조기 인터페이스 검증 | 통합 결함 수 |
| 문서 완성도 착시 | 승인 문서가 실제 동작과 불일치 | 추적성·시험 증거로 산출물 유효성 검증 | 산출물 불일치 건수 |

### Ⅵ. 적용 제언

- 핵심 요약 : 발주자와 수행 자는 요구 안정성·규제·피드백 가능성을 근거로 생명 주기 모델과 게이트를 선택.

1. 계약 단계에 변경 절차, 승인 자, 검증 가능한 산출물, 인수 기준을 함께 정의.
2. 불확실성이 큰 기능은 전체 계약 구조를 유지 하더라도 시제품·점진적 통합으로 조기 학습.

### Ⅶ. 결론

- 핵심 요약 : 폭포수 모델은 단계 통제와 산출물 추적에 강하지만 변화가 큰 요구 에는 늦은 피드백이 위험.
- 시사점 : 프로젝트 특성에 맞춰 순차 통제와 반복 검증을 조합 하는 것이 현실적인 적용 방향.
