소프트웨어 공학 → 개발 방법론 → **폭포수 개발 방법론(Waterfall)**

## 30초 인출

- 본질: 폭포수 모델은 요구·설계·구현·시험·운영 단계를 위에서 아래로 순서대로 진행하며 각 단계의 산출물 승인 후 다음 단계로 넘어가는 개발 모델
- 메커니즘: 단계마다 산출물을 검토·승인해 기준선으로 확정하고 이후 변경은 통제 절차로만 허용
- 통찰: 앞 단계에서 확정한 요구가 뒤늦게 틀렸음이 드러나면 되돌리는 비용이 크므로 요구가 안정적이고 범위가 고정된 사업에 적용하고 요구 변동이 큰 부분은 반복 방식을 병행

<details>
<summary>핵심 용어</summary>

- **폭포수 모델(Waterfall Model)** : 단계를 순서대로 진행하는 순차적 개발 모델
- **기준선(Baseline)** : 승인되어 이후 변경을 공식 절차로만 허용하는 산출물 상태
- **요구사항 명세서(SRS)** : 요구사항을 문서로 정리한 산출물
- **추적성(Traceability)** : 요구가 설계·구현·시험으로 이어짐을 확인할 수 있는 성질
- **변경통제위원회(CCB)** : 변경 요청을 검토해 승인 여부를 결정하는 조직

</details>

## 2~4교시 25점 답안

## Ⅰ. 폭포수 모델의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **폭포수 모델** 은 개발 단계를 순서대로 진행하며 산출물 승인 후 다음 단계로 넘어가는 개발 모델 |
| 목적 | 단계별 산출물 통제를 통한 체계적 개발 |

## Ⅱ. 반복 방식과 구별되는 특징

| 특징 | 의미 |
|---|---|
| 순차 진행 | 이전 단계 완료 후 다음 단계 |
| 문서 중심 | 단계 산출물의 검토·승인 |
| 늦은 동작 확인 | 시험 단계에서야 동작하는 제품 확인 |

## Ⅲ. 단계와 흐름

```text
요구 분석
    └─▶ 설계
          └─▶ 구현
                └─▶ 시험
                      └─▶ 운영·유지보수
```

각 단계는 산출물 검토·승인 후 기준선으로 확정

## Ⅳ. 폭포수와 반복 방식의 비교

| 구분 | 폭포수 | 반복·애자일 |
|---|---|---|
| 진행 | 순차 | 반복 |
| 요구 변경 | 통제·비용 큼 | 수용 |
| 동작 제품 확인 | 후반 | 반복마다 |
| 적합 조건 | 요구가 안정적·범위 고정 | 요구 변동이 큼 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 초기 요구 오류가 후반에 발견되어 수정 비용 큼 | 요구 검토·프로토타입으로 초기에 확인 |
| 변경에 경직 | 변경통제위원회와 영향 분석 절차 |
| 사용자 확인이 늦음 | 중간 검토 시점에 시연·검토 추가 |

## Ⅵ. 제언

요구가 안정적이고 범위가 고정된 사업에 적용하고, 요구 변동이 큰 부분은 반복 방식을 병행

```text
사업 특성
    ├─ 요구 안정·범위 고정 → 폭포수
    └─ 요구 변동 큼 → 반복 방식 병행
```

| 구분 | 무조건 폭포수 | 제언: 특성별 적용 |
|---|---|---|
| 변경 대응 | 경직 | 변동 부분은 유연 |
| 통제 | 강함 | 필요한 곳에 유지 |
