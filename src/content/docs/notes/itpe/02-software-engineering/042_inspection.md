## 연관 키워드

- 인스펙션, 파건 인스펙션, 정적 검토, 동적 시험
- 워크스루, 기술 리뷰, 사회자, 결함 기록, 심리적 안전성

## Ⅰ. 인스펙션의 개요

- 핵심 요약 : 인스펙션은 산출물을 실행 없이 읽어 결함을 찾고 기록·조치 완료까지 추적하는 정형 정적 검토 기법.
- 개념 : 완성 단계의 산출물을 실행하지 않고 정해진 절차·역할로 읽어 결함을 발견·기록하고 재작업 완료까지 확인하는 정형 검토 기법(**인스펙션**, Inspection)으로, **정적 검토**(static review, 실행 없이 산출물을 읽어 품질을 판단하는 검증 활동)의 대표 형태.
- 배경 및 필요성 : 마이클 파건(Michael Fagan)이 1976년 IBM에서 **파건 인스펙션**(Fagan Inspection)으로 체계화했고, 개발 초기의 결함 제거가 후속 단계의 수정·장애 비용을 낮추는 필요에서 정착.
- 주요 목적 : 산출물 결함의 조기 제거, 참가자 간 산출물에 대한 공통 이해 형성, 프로세스 개선용 결함 데이터 축적.

## Ⅱ. 인스펙션의 특징 및 장점

- 핵심 요약 : 정형 절차·역할 분리·사전 준비·결함 기록이 결함 발견율과 추적성이라는 장점으로 연결됨.

1. 정형 절차 : 계획→개요→준비→검사 회의→재작업→후속 조치의 6단계 진행 → 결함 제거의 누락 방지와 진행 상태 추적.
2. 역할 분리 : **사회자**(moderator, 검사 회의의 주도·중재 담당), **낭독자**(reader, 산출물을 구간별로 읽어 주는 역할), **기록자**(recorder, 결함을 로그로 남기는 역할), 검사자, 저자의 분담 → 저자 편향 배제와 중립적 판정.
3. 사전 준비·체크리스트 : 참가자가 개별 준비 시간에 결함 후보를 표시하고 체크리스트로 초점을 맞춤 → 회의 시간 통제·발견율 향상.
4. 결함 기록·데이터화 : 결함의 유형·심각도·발견 단계를 기록·축적 → 재발 방지와 프로세스 개선의 입력.

## Ⅲ. 인스펙션의 구조 (흐름)

- 핵심 요약 : 계획부터 후속 조치까지 6단계 절차와, 발견 결함이 기록→판정→재작업→재검증으로 이어지는 처리 흐름.

```text
[ 파건 인스펙션 6단계 ]

계획 (Planning)
   ↓
개요 (Overview)
   ↓
준비 (Preparation)
   ↓
검사 회의 (Inspection)
   ↓
재작업 (Rework)
   ↓
후속 조치 (Follow-up)
```

```text
[ 결함 처리 흐름 ]

결함 발견·기록
   ↓
심각도 판정 (치명·중대·경미)
   ↓
저자의 재작업
   ↓
후속 조치에서 재검증
   ↓
종료 기준 충족 시 종료
```

- 종료 기준 : **종료 기준**(exit criteria, 검사를 종료해도 되는 합의된 판단 기준)을 두어 재작업 미완료 산출물의 다음 단계 진행을 차단.

## Ⅳ. 동적 시험과 인스펙션의 비교

- 핵심 요약 : 인스펙션은 실행 없이 논리·표준 적합성을 판정하고, **동적 시험**(dynamic testing, 입력을 넣어 실행하고 결과를 관찰하는 검증 활동)은 실행상 오작동을 관찰하는 상보 수단.

| 비교 축 | 인스펙션 (정적 검토) | 동적 시험 |
|---|---|---|
| 결함 발견 방식 | 산출물 읽기·판정, 실행 없음 | 입력 인가 후 실행·결과 관찰 |
| 발견 대상 | 논리 오류·표준 부적합·요구 누락 | 실행 경로상의 오작동·성능 문제 |
| 적용 시점 | 산출물 작성 직후부터 | 단위·통합·시스템 단계 |
| 결함 정보 | 위치·원인까지 함께 판정 | 증상 관찰 후 별도 원인 분석 |
| 상보 한계 | 실행 오류·성능 확인 불가 | 요구 누락·설계 결함 직접 확인 불가 |

- 정적 검토 기법 간 구분 : **워크스루**(walkthrough, 저자가 주도해 산출물을 설명하고 의견을 수집하는 비정형 검토)와 **기술 리뷰**(technical review, 기술 전문가가 기술 적합성을 판단하는 준정형 검토)는 인스펙션보다 형식성·기록 기준이 낮음.

| 비교 축 | 워크스루 | 기술 리뷰 | 인스펙션 |
|---|---|---|---|
| 주도 주체 | 저자 | 기술 전문가 팀 | 훈련된 사회자 |
| 형식성 | 비정형 | 준정형 | 정형 (절차·역할·기록) |
| 주요 목적 | 이해 공유·의견 수집 | 기술 적합성 판단 | 결함 발견·기록·조치 확인 |

## Ⅴ. 인스펙션의 한계와 방안

- 핵심 요약 : 요식 행위·심리적 위축·준비 부족·검사 범위 과다를 기록 의무와 심리적 안전성·표본 조정으로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 요식 행위 | 회의 형식만 갖추고 결함·조치 기록 생략 → 검사 효과 상실 | 결함 기록 의무화와 종료 기준·후속 확인 절차 | 조치 미완료 건수 |
| 심리적 위축 | 결함 지적을 개인 평가로 인식 → 방어적 태도·결함 은폐 | 산출물 중심 발언 규칙과 사회자 중재로 **심리적 안전성** (psychological safety, 결함 지적이 처벌로 이어지지 않는 집단 분위기) 확보 | 발언 편중도 |
| 준비 부족 | 일정 압박으로 사전 검토 생략 → 표면 결함만 발견 | 준비 시간 표준과 준비 완료 확인 | 준비 완료율 |
| 검사 범위 과다 | 과대 문서를 한 회의에서 처리 → 집중력 저하 | 작은 단위 분할과 위험도 기준 표본 검사 | 시간당 발견 결함 수 |

## Ⅵ. 인스펙션에 대한 기술사적 제언

- 핵심 요약 : 품질 보증 조직이 검사 표준·교육·데이터 체계를 제도로 정착시켜 개인 역량 의존을 벗어난 검토 체계 구축.

1. 표준·제도화 : 품질 보증 조직은 검사 대상·절차·역할·종료 기준을 사내 표준으로 제정하고 검사 결과를 품질 기록으로 형상 관리.
2. 역량·데이터 확산 : 검사자 교육·자격 기준으로 진행 역량을 확보하고, 축적된 결함 데이터를 개발 프로세스 개선과 교육으로 연계하는 순환 체계 구축.

## Ⅶ. 결론

- 핵심 요약 : 인스펙션은 실행 이전에 결함을 제거하는 정적 검토의 정형 체계.
- 동적 시험을 대체하지 않고 앞 단계에 상보 배치될 때 품질 비용의 효과가 극대화.
