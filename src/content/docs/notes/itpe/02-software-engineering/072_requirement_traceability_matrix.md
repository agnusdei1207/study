## 연관 키워드
- 요구사항 추적표(RTM, Requirements Traceability Matrix), 양방향 추적성, 요구사항 기준선, 설계·코드·시험 연결, 변경 영향 분석

### Ⅰ. 요구사항 추적표의 개요

- 핵심 요약 : 요구사항 추적표(RTM, Requirements Traceability Matrix)는 요구사항을 출처·설계·구현·시험·결함과 연결해 완전성과 변경 영향을 확인하는 관리 산출물.
- 개념 : 요구사항을 출처·설계·구현·시험·결함과 연결해 완전성과 변경 영향을 확인하는 관리 산출물(**요구사항 추적표**, Requirements Traceability Matrix).
- 배경 및 필요성 : 요구가 여러 산출물과 버전에 흩어지면 설계·코드·시험의 누락과 변경 영향 미반영을 발견하기 어려움.
- 주요 목적 : 요구 누락·중복·무단 변경을 줄이고 계약·품질·검수 요구의 충족을 입증.

### Ⅱ. 요구사항 추적표의 특징 및 장점

- 핵심 요약 : 전방 추적·역방향 추적·속성·상태 관리·변경 영향 분석.

1. 전방 추적 : 요구에서 설계·코드·시험으로 연결 → 모든 요구가 구현·검증되는지 확인.
2. 역방향 추적 : 산출물·시험에서 승인된 요구로 연결 → 근거 없는 기능·시험 식별.
3. 속성·상태 관리 : 출처·우선순위·검증 방법·버전·승인 상태 기록 → 담당과 변경 이력 파악.
4. 변경 영향 분석 : 요구 변경 시 연결된 설계·코드·시험·문서 확인 → 재작업 범위와 회귀 시험 결정.

### Ⅲ. 요구사항 추적표의 구조 (흐름)

- 핵심 요약 : 요구 식별자·출처 확정 → 요구 기준선 승인 → 설계·구현·시험 링크 생성 → 변경·결함 반영 → 전방·역방향 누락 분석 → 검수·감사 증거 제공.

```text
요구 식별자·출처 확정
   ↓
요구 기준선 승인
   ↓
설계·구현·시험 링크 생성
   ↓
변경·결함 반영
   ↓
전방·역방향 누락 분석
   ↓
검수·감사 증거 제공
```

```text
출처·이해관계자 요구
         ↓
요구사항 ID·기준선
  ↙       ↓       ↘
설계     코드     시험 케이스
          ↓
      결함·변경 기록
```

### Ⅳ. 요구사항 목록과 요구사항 추적표 비교

- 핵심 요약 : 요구사항 목록은 요구 문장·상태만 관리, 요구사항 추적표는 요구와 생명 주기 산출물 간의 관계를 관리.

| 비교 대상 | 핵심 특성 | 적용·판단 기준 |
|---|---|---|
| 요구사항 목록 | 요구 문장·상태만 관리 | 요구 검토·승인 기준 |
| 요구사항 추적표 | 요구와 생명 주기 산출물 간 관계 관리 | 누락·영향·검증 완료 분석 |
| 테스트 커버리지 보고서 | 시험이 요구·코드 구조를 얼마나 검증하는지 측정 | 실행·검증 결과 확인, 추적표 대체 불가 |

### Ⅴ. 요구사항 추적표의 한계와 방안

- 핵심 요약 : 링크 누락·거짓 연결·기준선·버전 불일치·표 관리 수작업을 식별자 표준·형상관리·ALM 자동화로 관리.

| 위험 | 원인·영향 | 대응 통제 | 지표 예시 |
|---|---|---|---|
| 링크 누락·거짓 연결 | 요구 완전성·검증 여부를 잘못 판단 | 식별자 표준·링크 검토·독립 샘플 감사 | 고아 요구·산출물 수 |
| 기준선·버전 불일치 | 변경 전후 요구와 시험 결과가 혼재 | 형상 관리·승인된 변경과 링크 버전 연동 | 미승인 변경, 최신성 |
| 표 관리 수작업 | 중복·오래된 링크로 관리 비용 증가 | ALM(Application Lifecycle Management, 애플리케이션 생명 주기 관리) 도구 연계·자동 검증과 책임자 지정 | 링크 자동 검사 오류율 |

### Ⅵ. 요구사항 추적표 적용에 대한 기술사적 제언

- 핵심 요약 : 요구 누락·중복·무단 변경을 줄이고 계약·품질·검수 요구의 충족을 입증.

- 실행 제언 : 요구 사항 책임자는 추적 표를 제출용 문서로 끝내지 말고 요구 수용 기준·변경 심의·시험 결과와 ALM 도구에서 연결하고, 검수 시 양방향 누락과 안전·보안 요구를 별도 확인.

### Ⅶ. 결론

- 핵심 요약 : 요구사항 추적표(RTM, Requirements Traceability Matrix)는 요구사항을 출처·설계·구현·시험·결함과 연결해 완전성과 변경 영향을 확인하는 관리 산출물.
- 시사점 : 요구사항 추적성은 요구가 설계·구현·시험을 거쳐 검증됐다는 근거이며, 변경·계약·검수 의사 결정의 신뢰성을 좌우.
