## 연관 키워드

- 요구사항 추적 매트릭스(RTM, Requirements Traceability Matrix), 양방향 추적
- 전방·후방 추적, 변경 영향 분석, 요구 기준선, 커버리지, ALM

## Ⅰ. 요구사항 추적 매트릭스의 개요

- 핵심 요약 : RTM은 요구와 설계·구현·시험의 연결을 관리해 완전성·검증 여부·변경 영향을 입증하는 추적 산출물.
- 개념 : 요구사항을 출처·설계·코드·시험·결함과 연결해 누락·중복·변경 영향을 관리하는 행렬형 관리 산출물 (**요구사항 추적 매트릭스**, Requirements Traceability Matrix, RTM).
- 배경 및 필요성 : 요구가 다수 산출물·버전에 흩어지면 설계·시험 누락과 변경 영향 누락이 발견되지 않음.
- 주요 목적 : 요구 충족의 입증과 변경 통제로 계약·품질·검수 요구의 신뢰 확보.

## Ⅱ. 요구사항 추적 매트릭스의 특징 및 장점

- 핵심 요약 : 양방향 추적·변경 영향 분석·커버리지 관리가 요구 충족 입증과 변경 통제의 근거로 연결.

1. **전방 추적** (Forward Traceability) : 요구에서 설계·코드·시험으로 연결 → 모든 요구의 구현·검증 확인.
2. **후방 추적** (Backward Traceability) : 산출물·시험에서 요구로 연결 → 근거 없는 기능·시험 식별.
3. **변경 영향 분석** (Impact Analysis) : 요구 변경 시 연결 산출물 파악 → 재작업·회귀 시험 범위 결정.
4. 검증 커버리지 관리 : 요구별 시험 수행 상태 추적 → 미검증 요구의 잔존 방지.
5. 검수·감사 증거 : 요구 충족 입증 자료 제공 → 계약 이행·품질 보증 대응.

## Ⅲ. 요구사항 추적 매트릭스의 구조 (흐름)

- 핵심 요약 : 요구 식별부터 변경 갱신까지 링크를 유지하는 운영 흐름과 요구-산출물의 행렬 구조.
- **요구 기준선** (Baseline, 승인된 요구의 변경 기준점) : 추적 링크의 판단 기준이 되는 승인 상태.
- 양방향 추적 : 전방·후방 추적의 결합으로 요구→산출물, 산출물→요구의 누락을 동시 점검.

```text
RTM 구성·운영 흐름

요구 수집·식별자 부여
   ↓
요구 기준선 확정
   ↓
설계·코드·시험 링크 생성
   ↓
시험 결과·결함 기록
   ↓
양방향 커버리지 점검
   ↓
변경 시 영향 분석·갱신
```

```text
추적 행렬 구조 예시

            설계  코드  시험
REQ-001      O     O     O
REQ-002      O     O     X
REQ-003      X     X     X

X = 누락·미검증 항목
```

## Ⅳ. RTM과 요구 목록 중심 관리의 비교

- 핵심 요약 : 요구 목록 관리는 요구 문장·상태만 담당해 누락·영향 파악이 곤란한 반면, RTM은 산출물 연결로 검증·입증 가능.

| 비교 축 | 요구사항 추적 매트릭스(RTM) | 요구 목록 중심 관리 (추적 문서 없음) |
| --- | --- | --- |
| 관리 대상 | 요구와 산출물 간 연결 관계 | 요구 문장·상태만 |
| 누락 탐지 | 전방·후방 추적으로 점검 | 검토자 경험 의존 |
| 변경 대응 | 영향 범위·회귀 시험 산출 | 영향 파악 곤란 |
| 검증 입증 | 요구별 시험 커버리지 제시 | 충족 여부 입증 곤란 |
| 검수·감사 | 객관적 증거 자료 | 근거 제시 부족 |

- 선택 기준 : 계약·규제·안전 관련 사업은 RTM 필수, 소규모 내부 개발도 핵심 요구 추적 권장.

## Ⅴ. 요구사항 추적 매트릭스의 한계와 방안

- 핵심 요약 : 링크 갱신 누락·관리 비용·거짓 추적·애자일 부조화를 형상 관리 연동·도구 자동화·독립 감사·백로그 연계로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 링크 갱신 누락 | 변경 후 추적표 미갱신 → 오래된 정보로 판단 | 형상 관리 연동·변경 절차에 갱신 포함 | 최신성 만족률 |
| 관리 비용 증가 | 대규모 사업의 링크 유지 부담 → 형식화 | ALM(Application Lifecycle Management) 도구 자동화 | 링크 자동 검사 오류율 |
| 거짓 추적 | 링크 존재가 실제 검증을 의미하지 않음 → 안도 심리 | 시험 결과와 링크 일치 검토·독립 감사 | 미검증 요구 수 |
| 애자일 환경 충돌 | 문서 중심 관리가 반복 개발 흐름과 충돌 | 백로그 항목을 요구로 연계한 도구 기반 관리 | 백로그 연계율 |

## Ⅵ. 요구사항 추적 매트릭스 적용에 대한 기술사적 제언

- 핵심 요약 : 요구 관리 조직은 RTM을 제출 문서가 아닌 상시 추적 체계로 정착시키고 표준·도구·역량으로 내재화.
- 제도화 : 요구 기준선·변경 심의·검수 기준에 양방향 커버리지 요건 포함.
- 표준 지정 : 조직 공통 요구 관리 도구와 식별자 체계를 단일 표준으로 지정.
- 역량 확보 : 요구 분석가·품질 보증 인력 대상 추적 관리 표준 교육 운영.

## Ⅶ. 결론

- 핵심 요약 : RTM은 요구가 구현·검증되었다는 객관적 근거로 변경·검수 의사결정의 신뢰를 담보하는 산출물.
- 추적성은 문서 형식이 아니라 요구-검증 연결의 품질로 평가되어야 함.
