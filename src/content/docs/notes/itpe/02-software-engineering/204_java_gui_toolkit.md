소프트웨어 공학 → 프로그래밍 언어 → **Java GUI 툴킷(AWT·Swing)**

## 30초 인출

- 본질: Java GUI 툴킷은 자바로 데스크톱 화면을 만드는 라이브러리이며 AWT는 운영체제 위젯을 쓰고 Swing은 자바가 직접 그리는 경량 위젯을 제공
- 메커니즘: 컴포넌트를 컨테이너에 배치해 화면을 만들고 사용자 조작은 이벤트로 발생해 이벤트 처리기(리스너)가 처리
- 통찰: 화면 갱신과 이벤트는 하나의 이벤트 스레드가 처리하므로 오래 걸리는 작업을 그 스레드에서 실행하면 화면이 멈추어 작업은 별도 스레드에서 수행하고 결과만 화면에 반영

<details>
<summary>핵심 용어</summary>

- **AWT(Abstract Window Toolkit)** : 운영체제의 네이티브 위젯을 사용하는 자바 GUI 라이브러리
- **Swing** : 자바로 직접 그리는 경량 컴포넌트를 제공해 플랫폼 독립적인 외양을 가진 GUI 라이브러리
- **JavaFX** : 선언적 UI와 CSS 스타일링을 지원하는 현대적 자바 GUI 플랫폼
- **이벤트 처리기(Listener)** : 사용자 조작 이벤트를 받아 처리하는 객체
- **이벤트 디스패치 스레드(EDT)** : Swing에서 화면과 이벤트를 처리하는 전용 스레드
- **레이아웃 매니저** : 컴포넌트의 배치를 자동으로 정하는 객체

</details>

## 2~4교시 25점 답안

## Ⅰ. Java GUI 툴킷의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **Java GUI 툴킷** 은 자바로 데스크톱 화면을 만드는 라이브러리 |
| 목적 | 플랫폼 독립적인 GUI 개발 |

## Ⅱ. 특징

| 특징 | 의미 |
|---|---|
| 컴포넌트 기반 | 버튼·입력창 등을 조합 |
| 이벤트 기반 | 조작이 이벤트로 전달 |
| 레이아웃 관리 | 배치를 자동 계산 |

## Ⅲ. 이벤트 처리 구조

```text
사용자 조작 ─▶ 이벤트 발생 ─▶ 이벤트 스레드 ─▶ 리스너 실행 ─▶ 화면 갱신
                                     ▲
                        오래 걸리는 작업이 여기서 실행되면 화면이 멈춤
```

## Ⅳ. AWT·Swing·JavaFX의 비교

| 구분 | AWT | Swing | JavaFX |
|---|---|---|---|
| 그리기 방식 | OS 네이티브 위젯 | 자바가 직접 그림 | 씬 그래프 기반 |
| 외양 | 플랫폼별 상이 | 플랫폼 독립 | CSS로 정의 |
| 무게 | 중량 | 경량 | 경량 |
| 특징 | 기본 라이브러리 | AWT 위에 구축 | 선언적 UI(FXML) |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 긴 작업으로 화면 멈춤 | 작업은 별도 스레드에서 수행 |
| 이벤트 스레드 외부에서 화면 변경 오류 | 화면 변경은 이벤트 스레드에서 수행 |
| 구식 외양·기능 | 새 프로젝트는 JavaFX 검토 |

## Ⅵ. 제언

오래 걸리는 작업은 별도 스레드에서 수행하고 결과만 이벤트 스레드에서 화면에 반영

```text
버튼 클릭 → 작업 스레드에서 처리 → 완료 → 이벤트 스레드에서 화면 갱신
```

| 구분 | 이벤트 스레드에서 처리 | 제언: 작업 스레드 분리 |
|---|---|---|
| 화면 | 멈춤 | 반응 유지 |
| 구현 | 단순 | 스레드 관리 |
