## 연관 키워드
- AI 생성 코드, 오픈웨이트, LLM, 카피레프트, 라이선스 컴플라이언스, Ghostwriting, AIBOM

### Ⅰ. AI 생성 코드·오픈웨이트 라이선스 준수의 개요

- 핵심 요약 : LLM 기반 생성 코드와 오픈웨이트 모델 도입 시의 저작권·라이선스 리스크를 통제하는 거버넌스 체계.
- 개념 : AI 생성 코드(AI-Generated Code)와 오픈웨이트(Open-Weight) 모델을 기업 시스템에 들일 때 생기는 저작권 침해, 카피레프트(Copyleft) 라이선스 전염, 모델 사용 조건 위반을 식별하고 라이선스 컴플라이언스(License Compliance)를 확보하는 거버넌스 체계.
- 배경 및 필요성 : 대형 언어 모델(LLM, Large Language Model)의 학습 데이터에 GPL(GNU General Public License), AGPL(GNU Affero General Public License) 같은 강한 카피레프트(Copyleft) 코드가 섞여 있으면, 생성물이 원본을 그대로 옮기는 유령 작성(Ghostwriting) 위험이 생긴다.
- 주요 통제 대상 : AI 생성 코드의 저작권 귀속, 학습 데이터의 라이선스 오염, 오픈웨이트 모델의 사용 조건.

### Ⅱ. AI 생성 코드 컴플라이언스의 특징 및 장점

- 핵심 요약 : 저작권 귀속·학습 데이터 오염·모델 사용 조건의 3중 통제 대상과, 드러나지 않게 유입되는 오염 경로의 특수성.

1. 3중 통제 구조 : 생성 코드의 저작권 귀속, 학습 데이터 오염, 모델 사용 조건을 각각 점검 → 한 축의 누락이 전체 법적 리스크로 이어짐을 막음.
2. 유령 작성 리스크 : 학습 원본 오픈소스 코드가 그대로 출력될 가능성 → 공개 코드 일치 검사로 차단.
3. 비(非) 오픈소스 라이선스 : Llama, Mistral 등 다수 오픈웨이트 모델은 OSI(Open Source Initiative)가 승인하지 않은 자체 라이선스를 쓰며, 사용자 수 상한이나 경쟁 모델 학습 금지 같은 조건을 둠 → 상용 적용 전 조건 검토 필수.
4. 암묵적 오염 경로 : 개발자가 프롬프트 응답을 확인 없이 붙여 넣으며 스니펫(Snippet)이 유입 → 출처 추적이 어려움.
5. 추적성 요구 : 프롬프트, 모델 버전, 생성 일자 같은 계보(Provenance)를 AIBOM(AI Bill of Materials, AI 구성 명세서)에 기록해야 사후 증빙이 가능.

### Ⅲ. AI 생성 코드·오픈웨이트 라이선스 준수의 구조 (흐름)

- 핵심 요약 : 학습 데이터에서 코드베이스 병합까지 위험이 전파되는 경로와, 이를 막는 다층 검증 파이프라인.

```text
[ 위험 전파 경로와 검증 ]

오픈소스 학습 데이터 (GPL 등 포함)
   ↓
LLM 모델 학습
   ↓
AI 코딩 도구 (개발자 프롬프트)
   ↓
AI 생성 코드 제안
   ↓
유사도·스니펫 매칭 검사
   ↓
SAST(Static Application Security Testing) 보안 약점 진단
   ↓
품질·라이선스 승인 후 병합
```

```text
[ 오픈웨이트 모델 도입 검토 ]

후보 모델 선정
   ↓
라이선스 약관 법률 검토
   (사용자 수 상한, 증류 학습 제한 등)
   ↓
허용 용도 판정
   (상용 서비스, 내부 도구, 파인튜닝)
   ↓
허용 모델 화이트리스트 등록
   ↓
AIBOM 기록
```

- 유령 작성과 무단 복제 검출 : AI 생성 코드가 특정 오픈소스 원본과 일치하면 AI 코딩 도구의 공개 코드 일치 제안 차단 설정과 별도의 스니펫 검사로 걸러낸다.
- 오픈웨이트 라이선스의 비 오픈소스성 인지 : OSI 비승인 자체 라이선스는 상용 서비스에 적용하기 전에 조건을 법적으로 검토해야 한다.

### Ⅳ. 전통적 오픈소스 컴플라이언스와 AI 환경 컴플라이언스 비교

- 핵심 요약 : 오염 경로가 암묵화되고, 라이선스 조건이 비표준화되며, 검증 방식이 의존성 분석에서 유사도 기반으로 바뀌는 것이 핵심 차이.

| 비교 항목 | 전통적 오픈소스 | AI 생성 코드 및 오픈웨이트 모델 |
|---|---|---|
| 저작권 인정 | 인간 창작물로서 저작권 인정 | 인간의 창작적 기여가 없는 AI 산출물은 저작물로 보지 않는 입장이 일반적 |
| 오염 경로 | 개발자가 명시적으로 내려받아 링크 | 프롬프트 응답을 통한 무의식적 스니펫 유입 (암묵적 오염) |
| 라이선스 조건 | OSI 승인 표준 라이선스 (MIT, Apache, GPL 등) | 모델별 비표준 제약 조건 (예: Llama 계열 커뮤니티 라이선스) |
| 검증 도구 | 의존성 파일(pom.xml, package.json) 분석 | 소스코드 유사도 비교(스니펫 매칭)와 프롬프트 추적 |
| 법적 리스크 | 전염성 라이선스로 인한 상용 코드 공개 의무 | 학습 데이터 저작권 침해 손해배상, 영업비밀 유출 |

### Ⅴ. AI 생성 코드·라이선스 준수의 한계와 방안

- 핵심 요약 : AI 활용의 생산성 혁신 기회와 저작권·라이선스 리스크가 공존하므로 다층 통제 체계가 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 학습 데이터 블랙박스에 따른 저작권 침해 | 학습 데이터에 강한 카피레프트 코드가 섞여 있어, 원본과 유사한 출력이 나오면 소스 공개 의무 등 분쟁으로 번짐 | 공개 코드 일치 제안 차단 설정을 강제 활성화하고, CI 파이프라인에 유사도 검색 도구의 전수 스캔 연동 | 유사 코드 검출 건수, 차단 설정 준수율 |
| 오픈웨이트 모델의 특수 조건 위반 | 상용 사용자 수 상한, 다른 모델 학습에 출력을 쓰는 것(증류) 제한 같은 조항을 간과 | AI 거버넌스 위원회의 사전 약관 검토, 용도별 허용 모델 화이트리스트 운영 | 승인 전 검토 완료율, 위반 건수 |
| SBOM 내 AI 생성 자산 추적성 누락 | 프롬프트, 모델 버전, AI 생성 스니펫이 형상관리와 SBOM(소프트웨어 자재 명세서)에 빠져 감사 때 증빙 불가 | AI 생성 코드에 메타데이터 태깅 의무화, AIBOM 생성 파이프라인으로 프롬프트·모델 버전·생성 일자 추적 | AIBOM 기록 누락률 |

### Ⅵ. 기업 AI 거버넌스 확립을 위한 기술사적 제언

- 핵심 요약 : 스니펫 매칭 필터와 SCA 도구를 파이프라인에 통합하고, 사람의 검토를 의무화하는 원칙을 제도로 세우는 것이 핵심.

1. 스니펫 매칭 필터와 SCA(Software Composition Analysis, 소프트웨어 구성 분석) 연동 : 공개 코드 일치 제안 차단 설정을 전사 기본값으로 강제하고, 커밋 파이프라인에 SCA 도구의 스니펫 매칭 기능을 연결해 무단 복제 코드가 병합 전에 걸러지도록 함.
2. 인간 개입(Human-in-the-Loop) 원칙의 제도화 : AI 생성 코드는 초안으로만 취급하고, 숙련 개발자가 검토·수정한 뒤 서명해야 배포되도록 규정 → 창작적 기여를 입증할 근거를 남기고 품질 결함에 대한 책임 주체를 사람으로 분명히 함.

### Ⅶ. 결론

- 핵심 요약 : AI 생성 코드와 오픈웨이트 모델의 활용은 다층 컴플라이언스 통제 없이는 법적 리스크로 바뀐다.
- 시사점 : 학습 데이터 오염 차단, 모델 라이선스 검토, AIBOM 추적성의 3축을 스니펫 자동 검증과 사람의 검수로 병행해야 생산성과 법적 안전을 함께 확보할 수 있다.
