## 연관 키워드

- AI 생성 코드, 오픈웨이트, LLM, 카피레프트, 라이선스 컴플라이언스
- 암기, 공개 코드 일치 검사, AIBOM, SBOM, 인간 개입

## Ⅰ. AI 생성 코드·오픈웨이트 라이선스 준수의 개요

- 핵심 요약 : LLM 코드 생성과 오픈웨이트 모델 도입의 저작권·라이선스 리스크를 통제하는 거버넌스 체계.
- 개념 : **AI 생성 코드**(AI-generated code, 생성형 AI가 작성한 소스코드)와 **오픈웨이트**(open-weight, 모델 가중치를 공개 배포하는 형태) 모델 도입에서 발생하는 저작권 침해·라이선스 조건 위반을 식별·통제해 라이선스 컴플라이언스(License Compliance, 라이선스 약관의 준수 상태)를 확보하는 거버넌스 체계.
- 배경 및 필요성 : **대형 언어 모델**(LLM, Large Language Model)의 학습 데이터에 **카피레프트**(copyleft, 이차적 창작물에 같은 라이선스 상속을 요구하는 조항) 코드가 포함될 수 있고, 원본이 그대로 출력되는 **암기**(memorization, 학습 데이터의 원본을 기억해 그대로 출력하는 현상) 위험이 존재.
- 주요 목적 : 개발 생산성과 법적 안전의 동시 확보, AI 자산 이용의 분쟁 예방.

## Ⅱ. AI 생성 코드 준수 체계의 특징 및 장점

- 핵심 요약 : 3중 통제 대상·암묵적 유입 경로·비표준 조건·계보 추적이 리스크 조기 차단으로 연결됨.

1. 3중 통제 대상 : 생성 코드의 저작권 귀속, 학습 데이터 오염, 모델 사용 조건을 분리 점검 → 한 축 누락이 만드는 전체 리스크 차단.
2. 암묵적 유입 통제 : 개발자가 프롬프트 응답을 검증 없이 붙여 넣는 경로에 **공개 코드 일치 검사**(생성 코드가 공개 저장소 원본과 동일한지 비교하는 검사)를 적용 → 무단 복제 코드의 저장소 유입 차단.
3. 비표준 조건 검토 : 오픈웨이트 모델은 **OSI**(Open Source Initiative, 오픈소스 정의를 관리하는 단체) 승인 라이선스가 아닌 자체 약관으로 사용자 규모 상한·학습 제한 같은 조건을 둠 → 상용 적용 전 조건 판정 필요.
4. 계보 추적 : 프롬프트·모델 버전·생성 일자를 **AIBOM**(AI Bill of Materials, AI 구성 명세)에 기록 → 사후 감사 증빙과 영향 범위 추적.

## Ⅲ. AI 생성 코드·오픈웨이트 라이선스 준수의 구조 (흐름)

- 핵심 요약 : 학습 데이터에서 배포까지의 위험 전파 경로와, 프롬프트 기록부터 병합 승인까지의 다층 검증 통로.

```text
[ 위험 전파 경로 ]

학습 데이터 (공개 코드 포함)
   ↓
모델 학습·가중치 배포
   ↓
AI 코딩 도구의 코드 제안
   ↓
개발자가 검증 없이 채택
   ↓
저장소 병합·서비스 배포
```

```text
[ 병합 전 검증 통로 ]

프롬프트·모델 버전 기록
   ↓
공개 코드 일치 검사
   ↓
라이선스·보안 검토
   ↓
개발자의 인간 검토·서명
   ↓
AIBOM 등록 후 병합
```

- 도구적 기반 : 의존성 분석의 **SCA**(Software Composition Analysis, 소프트웨어 구성 분석) 도구와 코드 유사도 검사 도구의 병행 적용.
- 오픈웨이트 도입 절차 : 후보 모델의 약관 검토→허용 용도 판정→허용 목록 등록 순의 사전 심사 수행.

## Ⅳ. 전통 오픈소스 준수 체계와 AI 코드·오픈웨이트 준수의 비교

- 핵심 요약 : 코드 복사 중심의 전통 준수 체계와 달리, 암묵적 유입·비표준 약관·귀속 불명이 추가된 다층 통제 필요.

| 비교 축 | 전통 오픈소스 준수 체계 | AI 코드·오픈웨이트 준수 |
|---|---|---|
| 코드 유입 경로 | 개발자가 명시적으로 복사·의존성 추가 | 프롬프트 응답의 암묵적 유입 |
| 식별 수단 | 의존성 명세 파일 기반 SCA 스캔 | 유사도 비교·프롬프트 계보 기록 |
| 라이선스 문서 | OSI 승인 표준 라이선스 | 모델별 자체 약관 (비표준 조건) |
| 저작권 판단 | 인간 창작물로 귀속 명확 | 인간 기여 없는 산출물의 귀속 불명 |
| 통제 지점 | 빌드·배포 전 스캔 | 프롬프트·병합·모델 도입 전 다층 검증 |

## Ⅴ. AI 생성 코드·라이선스 준수의 한계와 방안

- 핵심 요약 : 학습 데이터 불투명·약관 해석 모호·비공식 도구 사용·추적 공백을 다층 통제와 기록 의무로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 학습 데이터 불투명 | 오염 여부를 사전 검증 불가 → 침해 분쟁 시 입증 곤란 | 공개 코드 일치 검사의 전수 적용과 결과 보존 | 검출·차단 건수 |
| 약관 해석 모호 | 모델별 비표준 조건의 해석 분기 → 위반 리스크 | 법무 협의의 사전 검토와 허용 모델 목록 운영 | 승인 전 검토 완료율 |
| 비공식 도구 사용 | 승인되지 않은 AI 도구의 무단 사용 → 통제 우회 | 허용 도구 목록·접근 통제와 사용 신고 절차 | 미승인 도구 적발 건수 |
| 추적성 공백 | 계보 기록 누락으로 감사 증빙 불가 | 소프트웨어 구성 명세(SBOM, Software Bill of Materials)에 생성 자산 편제, AIBOM 자동 생성 | AIBOM 기록 누락률 |

## Ⅵ. 기업 AI 거버넌스 확립을 위한 기술사적 제언

- 핵심 요약 : 정보보호·법무·개발의 공동 정책 제정과 인간 개입 원칙의 제도화로 준수 체계의 조직적 확립 필요.

1. 정책·거버넌스 : 정보보호·법무·개발 부서의 협의체가 AI 사용 정책(허용 도구·용도·검증 절차)을 제정하고, 모델·코드 자산의 라이선스 승인 절차를 구매·개발 프로세스에 공식 편제.
2. 인간 개입 원칙 : **인간 개입**(Human-in-the-Loop, AI 산출물에 사람의 검증·판단을 개입시키는 원칙)을 제도화해 AI 생성 코드를 초안으로만 취급하고, 개발자의 인간 검토·서명을 배포 조건으로 규정.

## Ⅶ. 결론

- 핵심 요약 : AI 생성 코드와 오픈웨이트 도입은 다층 준수 통제 없이 법적 리스크로 전환됨.
- 오염 차단·약관 검토·계보 추적의 축이 갖춰질 때 생산성과 법적 안전의 동시 확보 가능.
