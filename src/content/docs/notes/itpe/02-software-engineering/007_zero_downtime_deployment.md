## 연관 키워드

- 무중단 배포, 롤링 배포(Rolling Update), 블루/그린 배포(Blue/Green), 카나리 배포(Canary)
- 롤백(Rollback), 확장 및 축소(Expand & Contract), 이중 쓰기(Dual Write), 그레이스풀 셧다운(Graceful Shutdown)

## Ⅰ. 무중단 배포의 개요

- 핵심 요약 : 서비스 중단 없이 신규 버전을 안정적으로 배포하고 신속 롤백을 보장하는 배포 전략 체계.
- 개념 : 24시간 무중단 서비스 환경에서 서비스 중단(Downtime)이나 사용자 요청 유실 없이 신규 버전 애플리케이션을 안정적으로 배포하는 엔지니어링 전략.
- 배경 및 필요성 : 대규모 트래픽 처리 글로벌 웹/모바일 서비스의 확산, 야간 점검에 따른 비즈니스 손실 방지, 빈번한 마이크로 릴리스 지원 필요.
- 핵심 목적 : 무중단 서비스 연속성 HA(High Availability) 확보, 신속한 롤백(Rollback) 능력 확보, 배포 리스크 분산.

## Ⅱ. 무중단 배포의 특징

- 핵심 요약 : 버전 공존 관리와 점진적 트래픽 전환, 즉시 롤백 능력이 결합된 가용성 중심 배포 체계.

1. 배포 중 서비스 연속성 유지 및 사용자 요청 유실 방지.
2. 전략별로 상이한 구·신버전 공존 방식(순차 교체, 병행 전환, 의도적 공존).
3. 트래픽 가중치 제어 기반의 점진적 노출 및 오류율·지연시간 모니터링.
4. 라우팅 스위칭 또는 가중치 재설정 기반의 신속 롤백.
5. 상태 비저장(Stateless) 설계와 세션 외부화가 전제 조건.

## Ⅲ. 무중단 배포의 구조 (흐름)

- 핵심 요약 : 롤링·블루/그린·카나리 3대 전략과 데이터베이스 확장 및 축소(Expand & Contract) 마이그레이션 흐름.
- 3대 배포 전략 동작 개요.

```text
[ 롤링 ]      v1 v1 → v1 v2 → v2 v2  순차 교체
[ 블루/그린 ] 구·신버전 병행 구축, 라우터 일괄 전환
[ 카나리 ]    트래픽 일부 적용 후 점진 확대
```

- 롤링 배포(Rolling Update) : 인스턴스의 구버전에서 신버전으로 순차 교체, 추가 인프라 비용은 적으나 배포 도중 구·신버전 공존에 따른 호환성 문제 발생 가능.
- 블루/그린 배포(Blue/Green) : 동일 규모 신규 환경(Green)의 사전 구축 및 테스트 완료 후 로드밸런서 라우팅 즉각 스위칭, 롤백은 즉시 가능하나 2배의 인프라 자원 소모.
- 카나리 배포(Canary) : 극소수 사용자(또는 특정 가중치) 우선 노출 후 오류율·지연시간 모니터링 및 점진적 트래픽 이전을 통한 실운영 리스크 최소화.
- DB(Database) 무중단 마이그레이션 확장 및 축소(Expand & Contract) 패턴.
  1. 1단계(Expand) : 구버전 호환 신규 컬럼/테이블 추가(Nullable 또는 기본값 설정) 및 이중 쓰기(Dual Write) 수행.
  2. 2단계(Transition) : 신규 버전 앱 배포 완료 후 신규 스키마의 단독 읽기/쓰기 전환.
  3. 3단계(Contract) : 구버전 앱 완전 제거 후 미사용 레거시 컬럼/테이블 최종 삭제.

## Ⅳ. 무중단 배포 전략 비교

- 핵심 요약 : 인프라 요구량, 롤백 속도, 버전 공존, 적합 환경이 상이한 3대 전략의 선택 기준.
- 카나리 배포의 점진적 트래픽 확대 흐름.

```text
[ 카나리 배포 트래픽 전환 흐름 ]
 신버전 1% → 10% → 50% → 100%
   │         │       │       │
 오류율·지연시간 모니터링 → 이상 감지 시 가중치 0% 즉시 롤백
```

| 구분 | 롤링 배포 | 블루/그린 배포 | 카나리 배포 |
|---|---|---|---|
| 인프라 요구량 | 추가 자원 최소(기존 자원 활용) | 2배의 인프라 필요 | 미세한 추가 자원 필요 |
| 롤백 속도 | 지연(역순 롤링 재수행) | 즉시(라우팅 스위칭 복원) | 신속(가중치 0% 재설정) |
| 버전 공존 여부 | 공존(이종 버전 동시 실행) | 비공존(단절 전환) | 의도적 공존(A/B 검증 형태) |
| 적합 환경 | 일반 웹 앱, 자원 제약 환경 | 미션 크리티컬 시스템, 즉시 롤백 필수 환경 | 대규모 사용자 대상 B2C(Business-to-Consumer) 서비스 |

## Ⅴ. 무중단 배포의 장점과 한계

- 핵심 요약 : 가용성·신속 롤백의 장점, 스키마 호환성·인프라 비용·롤백 데이터 정합성의 한계.
- 장점
  1. 24시간 서비스 연속성 및 배포 중 요청 유실 방지.
  2. 전략별 롤백 체계를 통한 배포 리스크 최소화.
  3. 점진적 노출을 통한 실운영 기반 품질 검증.
- 한계점 1 : 데이터베이스 스키마 마이그레이션 시 하위 호환성 단절
  - 한계점 : 신구 버전 공존 과도기의 DB 컬럼 삭제·타입 변경 시 이전 버전 인스턴스의 런타임 쿼리 예외 발생.
  - 해결 방안 : 병렬 변경(Expand-Contract/Parallel Run) 패턴 기반의 컬럼 추가 → 이중 쓰기(Dual Write) → 과거 데이터 동기화 → 구 컬럼 제거 단계 진행, Liquibase/Flyway 기반 무중단 마이그레이션 파이프라인 구성.
- 한계점 2 : 블루/그린 배포의 인프라 비용 2배 증가 및 유저 세션 단절
  - 한계점 : 전체 환경 복제에 따른 클라우드 리소스 비용 일시 100% 증가, 상태 저장(Stateful) 애플리케이션의 인스턴스 전환 시 사용자 인메모리 세션 유실 발생.
  - 해결 방안 : Redis 등 외부 인메모리 분산 세션 클러스터 구축을 통한 무상태(Stateless) 아키텍처 전환, 비용 효율적 카나리(Canary) 배포 병행 및 Spot 인스턴스 활용.
- 한계점 3 : 비정상 배포 시 데이터 불일치 및 롤백 복잡도
  - 한계점 : 신규 버전의 DB 커밋 트랜잭션 존재 상태에서의 롤백 수행 시 신구 버전 데이터 정합성 붕괴 및 역방향 마이그레이션 불가.
  - 해결 방안 : 카나리 구간의 Prometheus 기반 에러율·레이턴시 자동 감지 즉시 롤백 체계 구축, 비즈니스 보상 트랜잭션(Saga Pattern) 로직 사전 구비.

## Ⅵ. 무중단 배포 아키텍처 구축 시 기술사적 제언

- 핵심 요약 : 상태 비저장 설계·그레이스풀 셧다운 기본화와 서비스 메시 기반 정밀 트래픽 제어.
- 세션 불연속성 방지 및 상태 비저장(Stateless) 설계 : 배포 중 인스턴스 종료 시 세션 단절 방지를 위한 인메모리 Redis 기반 외장 세션 클러스터링 기본 채택 및 그레이스풀 셧다운(Graceful Shutdown) 설정 필수.
- 서비스 메시(Service Mesh) 기반 세밀한 트래픽 제어 : Istio/Envoy 활용 HTTP(Hypertext Transfer Protocol) 헤더, 쿠키, 사용자 지역 기반 L7(Layer 7) 라우팅 룰 적용을 통한 비즈니스 영향도 통제형 카나리 배포 체계 고도화.

## Ⅶ. 결론

- 핵심 요약 : 무중단 배포는 전략 선택과 스키마·세션·롤백 설계가 결합된 가용성 엔지니어링.
- 요약 : 롤링·블루/그린·카나리 전략의 특성 비교 선택과 확장 및 축소(Expand & Contract) 기반 데이터 정합성 확보가 골격.
- 시사점 : 상태 비저장 아키텍처와 자동 롤백 체계의 사전 구축이 무중단 서비스 연속성의 선결 조건.
