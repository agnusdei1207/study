## 연관 키워드
- 무중단 배포, Rolling, Blue-Green, Canary, Expand-and-Contract, readiness

### Ⅰ. 무중단 배포의 개요

- 핵심 요약 : 무중단 배포는 사용자 요청을 처리하면서 신·구 버전을 전환하는 배포 설계.
- 개념 : 인스턴스·트래픽·데이터 변경을 조정해 배포 중 서비스 가용성을 유지하는 기법(**무중단 배포**, Zero-Downtime Deployment).
- 배경 및 필요성 : 점검 창이 제한된 서비스는 변경 중단과 장애 영향을 최소화해야 함.
- 주요 목적 : 가용성 유지, 점진 검증, 빠른 복구.

### Ⅱ. 무중단 배포의 특징 및 장점

- 핵심 요약 : 트래픽 분할·인스턴스 교체·버전 공존으로 배포 위험을 제한.

1. Rolling : 일부 인스턴스씩 교체 → 추가 인프라 비용 절감.
2. Blue-Green : 별도 환경 검증 후 라우팅 전환 → 신속한 원복.
3. Canary : 소수 트래픽에 신버전 노출 → 위험 조기 발견.
4. Expand-and-Contract : DB 스키마를 호환 단계로 변경 → 앱 버전 공존.

### Ⅲ. 배포 전략과 전환 흐름 (구조)

- 핵심 요약 : 준비·호환성 확인 → 단계적 트래픽 이동 → 지표 관측 → 승격 또는 롤백.

```text
구버전 운영 → 신버전 배포·readiness 확인 → 일부 인스턴스/트래픽 전환
           → 오류율·지연 관측 → 전체 전환 또는 구버전 복구
```

```text
DB Expand(새 구조 추가) → 호환 앱 배포 → 데이터 이행 → Contract(구 구조 제거)
```

### Ⅳ. 무중단 배포 전략 비교

- 핵심 요약 : 트래픽 제어 정밀도와 추가 자원·운영 복잡성의 균형으로 전략 선택.

| 비교 축 | Rolling | Blue-Green | Canary |
|---|---|---|---|
| 전환 방식 | 인스턴스 순차 교체 | 전체 환경 간 라우팅 | 소수부터 트래픽 확대 |
| 강점 | 추가 자원 적음 | 빠른 전환·롤백 | 실사용 조건 검증 |
| 주의점 | 버전 공존·원복 복잡 | 환경 비용·데이터 호환 | 세밀한 관측·라우팅 필요 |

### Ⅴ. 무중단 배포의 한계와 방안

- 핵심 요약 : 세션·DB·캐시 호환성과 감지 지연이 중단 원인이므로 앱 외 의존성까지 설계.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| DB 비호환 변경 | 신·구 버전 동시 실행 실패 | Expand-and-Contract와 마이그레이션 시험 | 호환 실패 건수 |
| 상태 기반 세션 | 인스턴스 교체 중 로그인 단절 | 외부 세션 저장소·무상태화 | 세션 단절 건수 |
| 관측·롤백 미흡 | 오류 확산 후 대응 | 자동 중단 임계치와 복구 런북 | 평균 복구 시간 |

### Ⅵ. 배포 거버넌스 제언

- 핵심 요약 : 배포 담당자는 단계별 성공 기준·중단 조건·복구 책임을 자동화에 포함.

1. 개발팀은 API·메시지·DB의 하위 호환 기간을 명시.
2. SRE는 SLO를 기준으로 Canary 확대·중단 판단 자동화.
3. 운영자는 데이터 복구·롤백 절차를 정기 리허설.

### Ⅶ. 결론

- 핵심 요약 : 무중단 배포는 트래픽·상태·데이터 호환성을 함께 다룰 때 성립.
- 시사점 : 안전한 전환은 빠른 배포와 자동 복구의 조합으로 확보.
