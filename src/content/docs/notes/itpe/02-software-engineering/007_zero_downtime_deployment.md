## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 빌드·배포·DevOps → **무중단 배포·배포 전략**

## 30초 인출

- 본질: 무중단 배포는 서비스를 멈추지 않고 새 버전으로 교체하는 배포 방식이며, 배포 전략은 그 교체 방법(Rolling·Blue/Green·Canary 등)의 선택
- 메커니즘: 신·구 버전을 동시에 두고 트래픽을 순차 또는 일괄로 신버전에 옮기며 오류 지표로 진행·롤백을 판단
- 통찰: 신버전 오류를 전체 사용자가 겪기 전에 잡아야 하므로 카나리로 일부 트래픽에서 오류율·지연을 확인한 뒤 확대하고 이상 시 구버전으로 즉시 복귀

<details>
<summary>핵심 용어</summary>

- **무중단 배포(Zero-Downtime Deployment)** : 서비스 중단 없이 새 버전으로 교체하는 배포 방식
- **Recreate 배포** : 구버전을 모두 내린 뒤 신버전을 올리는 방식. 중단 시간 발생
- **Rolling 배포** : 인스턴스를 하나씩 순차적으로 신버전으로 교체하는 방식
- **Blue/Green 배포** : 구버전(Blue)과 신버전(Green) 환경을 나란히 두고 트래픽을 한 번에 전환하는 방식
- **Canary 배포** : 일부 트래픽만 신버전으로 보내 확인한 뒤 확대하는 방식
- **A/B 테스트** : 사용자 그룹별로 다른 버전을 제공해 지표를 비교하는 방식
- **롤백(Rollback)** : 문제가 생긴 신버전을 구버전으로 되돌리는 동작

</details>

## 2~4교시 25점 답안

## Ⅰ. 무중단 배포·배포 전략의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **무중단 배포** 는 서비스를 멈추지 않고 새 버전으로 교체하는 배포 방식 |
| 목적 | 배포 중 서비스 중단 방지와 신버전 오류의 영향 범위 제한 |

## Ⅱ. 중단 배포와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 신·구 버전 공존 | 교체 중 두 버전이 동시에 트래픽 처리 |
| 트래픽 제어 | 라우터·로드밸런서로 요청의 분배 비율 조정 |
| 즉시 복귀 | 이상 시 구버전으로 트래픽 환원 |

## Ⅲ. 배포 전략별 트래픽 제어와 카나리 판정

### 배포 전략 구조

```text
배포 전략
    ├─ Recreate ── 구버전 전체 종료 후 신버전 기동 (중단 발생)
    ├─ Rolling ── 인스턴스를 N개씩 순차 교체
    ├─ Blue/Green ── 신버전 환경 준비 후 트래픽 일괄 전환
    └─ Canary ── 일부 트래픽부터 단계적으로 확대
```

### 확대: 카나리 배포 판정 흐름

```text
일부 트래픽을 신버전으로 유입
    ↓
오류율·응답 지연·자원 사용률 모니터링
    ├─ 임계치 초과 → 트래픽 회수·롤백
    └─ 정상 → 트래픽 비율 확대 → 전면 교체
```

## Ⅳ. 배포 전략의 비교와 배포 시 테스트 전략

### 배포 전략 비교

| 전략 | 중단 | 추가 자원 | 롤백 | 적합 조건 |
|---|---|---|---|---|
| Recreate | 있음 | 낮음 | 재배포 필요 | 점검 시간이 허용되는 내부 시스템 |
| Rolling | 없음 | 낮음 | 순차적이라 느림 | 신·구 버전 호환이 되는 서비스 |
| Blue/Green | 없음 | 높음(환경 2배) | 즉시 | 즉시 복귀가 필요한 핵심 서비스 |
| Canary | 없음 | 낮음 | 빠름 | 영향 범위를 제한하며 검증할 서비스 |

### 배포 시 테스트 전략

| 전략 | 방식 | 확인 대상 |
|---|---|---|
| 카나리 검증 | 일부 실사용 트래픽으로 신버전 확인 | 오류율·지연 |
| 섀도 테스트 | 실제 요청을 복제해 신버전에만 전달, 응답은 사용하지 않음 | 부하·결과 차이 |
| A/B 테스트 | 사용자 그룹별 다른 버전 제공 | 사용자 지표 비교 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 신·구 버전 공존 중 DB 스키마 불일치로 오류 | 스키마를 신·구 버전이 모두 읽을 수 있게 단계적으로 변경 |
| Blue/Green의 이중 환경으로 인프라 비용 증가 | 핵심 서비스에만 적용하고 나머지는 Rolling·Canary 적용 |
| 확대 판정 기준 부재로 이상 감지 지연 | 오류율·지연 임계치를 배포 전에 정하고 자동 롤백 연계 |

## Ⅵ. 제언

신버전 배포는 카나리로 시작해 오류율·응답 지연이 사전 임계치 이내일 때만 트래픽을 확대하고 초과 시 자동 롤백

### 카나리 확대 절차

```text
임계치 사전 정의 (오류율·응답 지연)
      ↓
소량 트래픽 유입
      ↓
지표 판정
      ├─ 임계치 초과 → 자동 롤백
      └─ 정상 → 비율 확대 → 전면 교체
```

### 선택 근거: 일괄 전환과의 비교

| 구분 | 일괄 전환 | 제언: 카나리·자동 롤백 |
|---|---|---|
| 오류 영향 범위 | 전체 사용자 | 일부 사용자 |
| 복귀 | 수동 판단 | 임계치 기반 자동 |
| 확대 판단 | 배포 완료 여부 | 지표 기준 |
