## 연관 키워드

- 비선형 구조(Non-Linear Structure), 트리(Tree), 그래프(Graph), DFS(Depth-First Search), BFS(Breadth-First Search)
- 자가 균형 트리(AVL·Red-Black), B+Tree, 트라이(Trie), 인접 리스트, 위상 정렬(Topological Sort), DAG(Directed Acyclic Graph)

## Ⅰ. 비선형 구조의 개요

- 핵심 요약 : 1:N 계층 관계와 N:M 망형 관계로 데이터 원소 간 복합 연결을 표현하는 자료구조.
- 개념 : 원소 간 관계가 선형적 순서를 갖지 않고, 계층적인 **트리**(Tree)나 망형인 **그래프**(Graph)처럼 1:N 또는 N:M으로 연결된 자료구조.
- 배경 및 필요성 : 현실 세계의 다대다 관계를 자료구조로 옮겨 연산해야 할 때 선형 구조로는 관계 표현과 탐색 효율을 함께 얻기 어렵다. 대표 사례는 파일 시스템의 디렉터리 계층, 조직도, 네트워크 라우팅 경로, 소셜 네트워크(SNS, Social Networking Service) 관계망이다.
- 주요 목적 : 계층·망형 관계를 자연스럽게 표현하면서 탐색과 경로 계산을 효율적으로 수행하는 것.

## Ⅱ. 비선형 구조의 특징 및 장점

- 핵심 요약 : 트리는 유일 경로의 계층 구조, 그래프는 순환을 허용하는 망형 구조이며 두 구조 모두 DFS와 BFS로 순회.

1. 트리 : 루트(Root) 노드에서 간선(Edge)으로 계층을 이루며 노드가 N개면 간선은 정확히 N-1개이고, 임의의 두 노드 사이 경로가 하나뿐임 → 계층 관계의 중복 없는 표현.
2. 그래프 : 정점(Vertex)과 간선의 집합 G = (V, E)로 표현하며, 방향성과 가중치 유무로 구성을 달리함 → 임의의 N:M 관계 모델링.
3. 깊이 우선 탐색(DFS, Depth-First Search) : 스택 또는 재귀로 한 경로를 끝까지 내려간 뒤 되돌아오는 방식이며 시간 복잡도는 O(V+E) → 사이클 탐지와 위상 정렬 등에 활용.
4. 너비 우선 탐색(BFS, Breadth-First Search) : 큐로 시작 정점에서 가까운 정점부터 레벨 단위로 방문하며 시간 복잡도는 O(V+E) → 간선 가중치가 없을 때 최단 경로 탐색에 활용.

## Ⅲ. 비선형 구조의 구조 (흐름)

- 핵심 요약 : 트리는 사이클 없는 1:N 계층, 그래프는 N:M 망형이며, 그래프 순회는 DFS와 BFS 두 흐름으로 나뉨.

```text
[ 트리 (Tree) : 1:N, 사이클 없음 ]

        [ A ]  Root
       ↙     ↘
    [ B ]   [ C ]
    ↙   ↘        ↘
 [ D ]  [ E ]   [ F ]
```

```text
[ 그래프 (Graph) : N:M, 사이클 허용 ]

 [ 1 ] ─── [ 2 ]
   │         │
   │         │
 [ 3 ] ─── [ 4 ]
```

```text
[ 그래프 순회 흐름 ]

DFS : 시작 정점
        ↓ 미방문 인접 정점으로 깊이 진입
        ↓ 더 갈 곳이 없으면 백트래킹(스택/재귀)

BFS : 시작 정점
        ↓ 레벨 1 인접 정점 전부 방문
        ↓ 레벨 2 인접 정점 순차 확장(큐)
```

## Ⅳ. 주요 비선형 자료구조의 비교

- 핵심 요약 : 트리와 그래프의 변형은 목적에 따라 균형 유지, 디스크 입출력, 문자열 접두사, 망형 연결 중 무엇을 우선하느냐로 선택.

| 구분 | 주요 특징 및 구조 | 주 활용 분야 |
| --- | --- | --- |
| 이진 트리(Binary Tree) | 각 노드가 최대 2개의 자식을 가짐 | 수식 트리, 허프만 코딩 |
| 자가 균형 트리(AVL, Red-Black) | 삽입·삭제 시 회전으로 높이를 로그 수준으로 유지 | C++ STL의 std::map, Java TreeMap |
| B-Tree, B+Tree | 한 노드에 많은 키를 담아 디스크 블록 단위 입출력을 줄임 | 관계형 데이터베이스(RDBMS, Relational Database Management System) 인덱스(MySQL InnoDB의 B+Tree) |
| 트라이(Trie) | 문자열의 접두사를 공유하는 트리 구조 | 검색어 자동 완성, IP 라우팅의 최장 접두사 일치 |
| 그래프(Graph) | 정점 간 N:M 연결, 인접 행렬 또는 인접 리스트로 표현 | 길찾기(Dijkstra, A*), 의존성 분석 |

## Ⅴ. 비선형 구조의 한계와 방안

- 핵심 요약 : 탐색 공간 폭증, 캐시 비효율, 순환 참조를 탐색 제한, 메모리 배치 개선, 방문 관리로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 탐색 공간 폭증 | 정점·간선 수가 커지면 DFS·BFS와 경로 탐색의 시간·메모리 비용이 급증해 메모리 고갈 위험 | 가지치기(Pruning)와 분기 한계(Branch and Bound), 휴리스틱 기반 A* 적용 | 탐색 노드 수, 메모리 사용량 |
| 포인터 기반 노드의 캐시 비효율 | 노드가 메모리에 흩어져 공간 지역성이 낮고 캐시 미스가 잦아 처리 성능 저하 | 인접 리스트를 연속 배열로 적재하는 CSR(Compressed Sparse Row) 구조 채택 | 캐시 미스율 |
| 순환 참조와 무한 루프 | 방문 표시가 빠지면 무한 재귀가 생기고, 순환 객체가 메모리 회수에서 누락 | 방문 플래그 관리, Tarjan 알고리즘으로 강결합 컴포넌트(SCC, Strongly Connected Components) 탐지 | 순환 탐지 건수, 누수 발생 건수 |

## Ⅵ. 시스템 엔지니어링 관점에서의 기술사적 제언

- 핵심 요약 : 데이터 규모와 저장 위치에 맞춰 트리를 고르고, 의존 관계 그래프는 DAG로 제한해 순환을 원천 차단.

1. 데이터 규모에 맞는 트리 선택 : 데이터가 메모리에 상주하는 서비스는 포인터 연산이 단순한 자가 균형 트리를, 디스크 입출력이 큰 데이터베이스는 블록 단위 접근에 맞춘 B+Tree를 쓰도록 설계 표준을 정한다.
2. 의존 관계의 비순환 제약 : 마이크로서비스 이벤트나 빌드 파이프라인처럼 작업 순서가 중요한 그래프는 DAG(Directed Acyclic Graph)로 제한하고, 위상 정렬(Topological Sort)로 실행 순서를 정해 교착 상태를 막는다.

## Ⅶ. 결론

- 핵심 요약 : 비선형 구조는 복잡한 관계를 표현하는 기본 틀이며, 트리와 그래프 중 무엇을 어떤 변형으로 쓸지가 설계의 핵심.
- 시사점 : 계층은 트리, 망형은 그래프로 구분하되, 규모와 하드웨어 특성에 맞춰 변형과 순환 제약을 함께 설계해야 한다.
