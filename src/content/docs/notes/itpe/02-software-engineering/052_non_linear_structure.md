소프트웨어 공학 → 자료구조·알고리즘 → **비선형 구조(Non-Linear Structure)**

## 30초 인출

- 본질: 데이터 원소 간의 관계가 1:1 순차적 관계가 아닌 1:N(계층 관계) 또는 N:M(망 관계)으로 연결되어 복잡한 상호작용과 다차원적 데이터를 모델링하는 자료구조
- 메커니즘: 계층형 트리(루트, 부모, 자식, 이진트리, 순회) 및 네트워크형 그래프(정점 V, 간선 E, 인접 행렬, 인접 리스트, DFS/BFS 탐색)
- 통찰: 사이클이 존재하는 관계망에 무분별한 트리 순회를 적용하면 무한 루프와 스택 오버플로우가 발생하므로 방문 배열 관리 기반의 그래프 탐색 및 위상 정렬 적용 필수

<details>
<summary>핵심 용어</summary>

- **Non-Linear Structure(비선형 구조)** : 데이터 항목들이 연속적인 단일 선형 순서가 아니라 다대다 또는 계층적 분기 형태로 배치되는 자료구조
- **Tree(트리)** : 하나의 루트 노드로부터 부모-자식 관계의 가지가 뻗어나가며 사이클(Cycle)이 존재하지 않는 연결 그래프
- **Graph(그래프)** : 사물을 나타내는 정점(Vertex)과 이들 간의 관계를 나타내는 간선(Edge)의 집합으로 표현되는 망형 자료구조
- **DFS (Depth-First Search)** : 한 방향으로 갈 수 있을 때까지 깊게 탐색하다가 막히면 되돌아오는 스택/재귀 기반의 그래프 탐색 알고리즘
- **BFS (Breadth-First Search)** : 시작 정점으로부터 인접한 이웃 정점들을 먼저 모두 방문한 후 다음 레벨로 확장하는 큐(Queue) 기반 탐색 알고리즘
- **Adjacency List / Matrix** : 그래프의 연결 상태를 연결 리스트의 배열(희소 그래프에 유리) 또는 2차원 불리언 배열(밀집 그래프에 유리)로 표현하는 기법

</details>

## 2~4교시 25점 답안

## Ⅰ. 비선형 구조의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 하나의 데이터 뒤에 다수의 데이터가 올 수 있는 구조로, 원소들 간의 관계가 1:N 계층 관계(Tree) 또는 N:M 네트워크 망 관계(Graph)를 형성하는 비순차적 자료구조 |
| 목적 | 파일 시스템의 디렉터리 계층, 소셜 네트워크 관계망, 통신 라우팅 경로 등 현실 세계의 복합 연결 관계를 효과적으로 모델링하고 고속 탐색 지원 |

## Ⅱ. 비선형 구조의 핵심 특징

| 특징 | 의미 |
|---|---|
| 다대다(N:M) 연결성 | 단일 선형 목록과 달리 하나의 노드에서 여러 경로로 분기 및 합류가 자유롭게 발생 |
| 비순차적 탐색 경로 | 정해진 1차원 순서가 없으므로 전위/중위/후위 순회 또는 DFS/BFS와 같은 탐색 전략 필수 |
| 수학적 모델링 적합성 | 그래프 이론(Graph Theory)에 기반하여 최단 경로, 최소 신장 트리, 위상 정렬 등 고난도 알고리즘 적용 가능 |
| 동적 메모리 활용 | 포인터 기반 노드 링크를 활용하여 실행 시간에 자유롭게 노드 추가 및 삭제 수행 |

## Ⅲ. 트리 및 그래프 체계와 탐색 메커니즘

### 비선형 구조 2대 축(트리 vs 그래프) 및 탐색 흐름도

```text
[1. 트리 (Tree) 계층 구조]              [2. 그래프 (Graph) 망형 구조]
           (A) [루트 노드]                         (1) ─────── (2)
          /   \                                    │  ＼       │
        (B)   (C)                                  │    ＼     │
       /   \     \                                 │      ＼   │
     (D)   (E)   (F) [리프 노드]                   (3) ─────── (4)
  - 특징: 사이클 없음, 단일 부모                  - 특징: 사이클 존재 가능, 다중 연결
  - 순회: In-order, Pre-order, Post-order         - 탐색: DFS (깊이우선), BFS (너비우선)

────────────────────────────────────────────────────────────────────────
[그래프 탐색 메커니즘 상세]
  시작 정점 (1) 방문
       │
       ├─ [DFS: 깊이 우선 탐색 (Stack / 재귀 활용)]
       │    (1) → (2) → (4) → (3) : 한 경로를 끝까지 파고든 후 백트래킹
       │
       └─ [BFS: 너비 우선 탐색 (Queue 활용)]
            (1) 방문 후 인접 정점 [(2), (3)] 큐 인큐 → 차례로 디큐하여 다음 레벨 탐색
            최단 홉(Hop) 거리 계산 및 레벨 단위 순회에 최적화
```

### 트리 순회 및 그래프 탐색 기법 상세 분석

| 분류 | 기법 명칭 | 데이터 처리 순서 및 메커니즘 | 주요 활용 분야 |
|---|---|---|---|
| **트리 순회** | **전위 순회 (Pre-order)** | Root → Left → Right (루트를 먼저 방문) | 트리 복제, 수식 트리의 전위 표기식 생성 |
| 트리 순회 | **중위 순회 (In-order)** | Left → Root → Right (루트를 중간에 방문) | 이진탐색트리(BST)의 오름차순 정렬 데이터 인출 |
| 트리 순회 | **후위 순회 (Post-order)** | Left → Right → Root (루트를 마지막에 방문) | 트리 노드 메모리 해제, 수식 트리의 후위 연산 |
| **그래프 탐색** | **DFS (깊이 우선)** | 방문 여부 체크 배열 + 재귀 호출로 경로 심화 | 미로 찾기, 사이클 검출, 단절점/단절선 탐색 |
| 그래프 탐색 | **BFS (너비 우선)** | 방문 여부 체크 배열 + FIFO 큐 기반 동심원 탐색 | 가중치 없는 최단 경로, 소셜 네트워크 촌수 계산 |

## Ⅳ. 선형 vs 비선형 및 트리 vs 그래프 비교

### 선형 자료구조 vs 비선형 자료구조 비교

| 비교 항목 | 선형 자료구조 (Linear Structure) | 비선형 자료구조 (Non-Linear Structure) |
|---|---|---|
| **데이터 관계** | 원소 간 **1:1 순차적 관계** | 원소 간 **1:N (계층) 또는 N:M (망형) 관계** |
| **순회 및 탐색** | 단일 루프 기반 단순 순차 탐색 | 재귀 호출, 스택/큐 기반의 복합 탐색 (DFS, BFS) |
| **구현 난이도** | 직관적이고 비교적 단순함 | 링크 포인터 관리, 사이클 방지 등 복잡도 높음 |
| **대표 자료구조** | **배열(Array), 연결리스트(Linked List), 스택, 큐** | **트리(Tree), 이진탐색트리, 힙, 그래프(Graph)** |
| **주요 적용 분야** | 버퍼링, 실행 취소(Undo), 순차 데이터 파이프라인 | 파일 디렉터리, 지도 내비게이션, 네트워크 라우팅 |

### 그래프 표현 방식 비교: 인접 행렬 vs 인접 리스트

| 비교 항목 | 인접 행렬 (Adjacency Matrix) | 인접 리스트 (Adjacency List) |
|---|---|---|
| **저장 공간** | $O(V^2)$ (정점 수의 제곱에 비례) | $O(V + E)$ (정점 수 + 간선 수에 비례) |
| **간선 연결 확인** | $O(1)$ (`matrix[i][j]` 즉시 확인) | $O(\text{degree}(v))$ (연결 리스트 노드 순차 순회) |
| **정점의 모든 이웃 탐색**| $O(V)$ (해당 행의 모든 열 검사) | $O(\text{degree}(v))$ (실제 연결된 간선만 방문) |
| **최적 적용 상황** | **간선이 많은 밀집 그래프(Dense Graph)** | **간선이 적은 희소 그래프(Sparse Graph)** |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 그래프 탐색 시 방문 노드 체크 누락으로 인해 순환 참조(Cycle) 발생 및 무한 루프/스택 오버플로우 | 방문 여부를 기록하는 불리언 배열(`visited[]`) 및 Set 자료구조를 필수적으로 유지 |
| 희소 그래프 환경에서 인접 행렬 사용 시 $O(V^2)$의 심각한 메모리 낭비 발생 | 간선 수에 비례하는 메모리만 사용하는 인접 리스트(Adjacency List)로 구현 변경 |
| 노드 삽입 순서에 따라 이진탐색트리가 한쪽으로 치우쳐 선형 리스트($O(n)$)로 전락 | AVL 트리 또는 Red-Black 트리 기반 자가 균형 회전(Rotation) 메커니즘 강제 |

## Ⅵ. 제언

도메인 특성에 따른 지능형 그래프 데이터베이스(Neo4j) 전환 및 대규모 분산 그래프 처리 엔진 도입

### 대규모 그래프 데이터 처리 파이프라인

```text
[실시간 금융 거래 / 소셜 네트워크 이벤트]
       ↓
[분산 그래프 데이터베이스 (Neo4j / Amazon Neptune)]
  ├─ 정점(Node)과 간선(Edge), 속성(Property) 레이블링
  └─ Cypher 쿼리 기반 관계 탐색
       ↓
[분산 그래프 분석 엔진 (Apache Spark GraphX)]
  ├─ PageRank: 핵심 영향력 노드 랭킹 산출
  ├─ Louvain: 커뮤니티 클러스터링 분석
  └─ Connected Components: 자금 세탁 및 대포통장 사기 네트워크 탐지
       ↓
[실시간 이상 금융거래(FDS) 차단 시스템 연계]
```

### 비선형 자료구조 선택 의사결정 체계

```text
표현 대상 도메인 관계 분석
       ↓
[데이터 간의 관계에 사이클(Cycle)이 존재하는가?]
       ├─ 예 ──→ 그래프(Graph) 채택
       │           ↓
       │      [간선 밀도가 높은가?]
       │       ├─ 예 ──→ 인접 행렬(Matrix) 표현
       │       └─ 아니오 ─→ 인접 리스트(List) 표현
       └─ 아니오 ─→ [단일 루트를 중심으로 계층 분기가 발생하는가?]
                         ├─ 예 ──→ 트리(Tree) / 이진탐색트리 채택
                         └─ 아니오 ─→ 방향성 비순환 그래프 (DAG, 작업 스케줄링) 채택
```

### 선택 근거: 전통적 관계형 DB 테이블과 그래프 모델링 비교

| 구분 | RDBMS 조인(JOIN) 테이블 방식 | 제언: 네이티브 그래프 데이터 모델 |
|---|---|---|
| 다대다 관계 탐색 | N:M 조인 테이블 증가로 다중 Join 시 성능 급락 | 포인터 기반 즉각 탐색(Index-free Adjacency)으로 초고속 |
| 스키마 유연성 | 복합 계층 변경 시 스키마 변경 마이그레이션 필수 | 노드와 간선에 동적으로 속성을 추가하는 유연한 확장 |
| 패턴 매칭 질의 | 복잡한 계층 질의 시 수십 줄의 재귀 SQL 작성 | Cypher 등 선언적 패턴 매칭 언어로 간결한 질의 작성 |
