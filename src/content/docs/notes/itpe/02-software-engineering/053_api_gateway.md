## 연관 키워드

- API Gateway, MSA, 단일 진입점, 리버스 프록시
- 동적 라우팅, BFF, Rate Limiting, 서킷 브레이커, SPOF, JWT

## Ⅰ. API Gateway의 개요

- 핵심 요약 : 외부의 모든 서비스 요청을 한 계층에서 수용해 공통 정책을 집행하는 진입 계층.
- 개념 : 외부 클라이언트의 모든 API(Application Programming Interface) 요청을 수용해 백엔드 서비스로 전달하는 **리버스 프록시**(Reverse Proxy) 기반 중간 계층 (**API Gateway**).
- 배경 및 필요성 : 마이크로서비스 아키텍처(**MSA**, Microservice Architecture)에서 클라이언트가 각 서비스를 직접 호출하면 인증의 중복 구현, 내부 엔드포인트의 노출, 호출 경로의 복잡화가 발생하는 상황.
- 주요 목적 : **단일 진입점**(Single Point of Entry)의 확보를 통한 공통 정책 집행과 내부 구조 은닉.

## Ⅱ. API Gateway의 특징 및 장점

- 핵심 요약 : 보안·트래픽·장애·경로·응답의 공통 처리가 입구 계층의 일원화라는 장점으로 연결되는 구조.

1. 공통 보안의 집행 : 인증·인가를 입구 계층에서 **JWT**(JSON Web Token) 검증으로 일괄 수행 → 백엔드별 보안 로직 중복의 제거.
2. 트래픽 제어 : **Rate Limiting**(일정 시간당 요청 수의 제한)의 적용 → 요청 폭주로부터 백엔드 가용성 보호.
3. 장애 격리 : **서킷 브레이커**(Circuit Breaker, 실패 누적 서비스 호출의 차단 장치)의 적용 → 연쇄 장애의 확산 방지.
4. 경로의 실시간 갱신 : 서비스 디스커버리 연동 기반의 **동적 라우팅**(Dynamic Routing) → 인스턴스 변동에도 경로 설정 변경의 불필요.
5. 클라이언트별 최적화 : 웹·모바일별 응답을 조합하는 **BFF**(Backend For Frontend) 패턴의 적용 → 클라이언트별 호출 수와 응답 크기의 축소.

## Ⅲ. API Gateway의 구조 (흐름)

- 핵심 요약 : 외부 요청이 공통 기능 계층을 순차 통과한 뒤 내부 서비스로 분기되는 흐름.
- 요청 처리의 단계별 통과 순서.

```text
[ 게이트웨이 요청 처리 흐름 ]

클라이언트 요청
   ↓
인증·인가 (JWT 검증)
   ↓
트래픽 제어 (Rate Limiting)
   ↓
동적 라우팅 (서비스 디스커버리 연동)
   ↓
백엔드 마이크로서비스
```

- 진입 계층의 단일화에 따른 내부 구조의 은닉.

```text
[ 단일 진입점과 내부 은닉 ]

외부 클라이언트
   ↓
단일 진입점 (API Gateway)
   ↓
주문·결제 등 내부 서비스
   (직접 노출 없이 진입점 경유만 허용)
```

## Ⅳ. API Gateway와 서비스 직접 호출 구조의 비교

- 핵심 요약 : 클라이언트가 각 서비스를 직접 호출하는 구조와 진입 계층을 경유하는 구조는 인증·노출·장애 처리 방식이 다름.

| 비교 축 | API Gateway 경유 구조 | 서비스 직접 호출 구조 |
| --- | --- | --- |
| 진입 경로 | 단일 진입점으로의 집중 | 클라이언트가 각 서비스 주소를 보유 |
| 인증 처리 | 게이트웨이의 일괄 집행 | 서비스별 중복 구현 |
| 내부 노출 | 내부 엔드포인트의 은닉 | 서비스 엔드포인트의 외부 노출 |
| 장애 대응 | 서킷 브레이커·라우팅 전환의 격리 | 클라이언트가 장애 서비스를 그대로 호출 |
| 클라이언트 복잡도 | BFF 조합으로 호출 수의 축소 | 서비스 수만큼 호출 로직의 증가 |

## Ⅴ. API Gateway의 한계와 방안

- 핵심 요약 : 입구 집중 구조의 특성상 장애 확산, 계층 비대화, 인증 병목의 세 위험이 상존.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 단일 장애점(**SPOF**, Single Point of Failure) | 모든 트래픽의 입구 집중 → 게이트웨이 장애 시 전체 서비스 중단 | 다중 인스턴스·가용 영역 이중화 | 가용성, 응답 지연 시간 |
| 계층 비대화(Fat Gateway) | 비즈니스 로직의 게이트웨이 유입 → 변경·배포 지연 | 역할의 인프라 공통 기능 한정, 화면 조합은 BFF로 분리 | 게이트웨이 변경 빈도 |
| 중앙 인증 병목 | 요청마다 인증 서버의 동기 검증 → 인증 지연과 부하 집중 | 공개키 기반 JWT의 게이트웨이 로컬 검증 | 인증 지연 시간 |

## Ⅵ. API Gateway 운영에 대한 기술사적 제언

- 핵심 요약 : 게이트웨이를 공통 플랫폼으로 정의하고 정책·설정·소유권의 기준을 제도화하는 방향.
- 표준 : 인증·트래픽 제어·라우팅 정책을 선언적 설정과 코드로 관리하는 표준의 채택.
- 조직 : 플랫폼 조직의 게이트웨이 운영 전담과 서비스 팀의 BFF 소유라는 역할 분담 체계.
- 확산 : 관리형 솔루션과 자체 구축의 선택 기준을 비용·운영 역량 평가 절차로 정례화.

## Ⅶ. 결론

- 핵심 요약 : API Gateway는 MSA의 진입 계층이자 공통 정책의 집행 지점.
- 이중화된 진입 계층과 명확한 역할 경계가 MSA 안정성의 전제.
