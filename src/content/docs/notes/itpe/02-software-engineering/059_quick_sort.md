## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 자료구조·알고리즘 → 정렬 알고리즘 → **퀵 정렬(Quick Sort)**

## 30초 인출

- 본질: 찰스 앤터니 리처드 호어(C.A.R. Hoare)가 고안한 알고리즘으로 기준 원소(Pivot)를 선택하여 피벗보다 작은 값과 큰 값의 두 부분 배열로 분할하고 재귀적으로 정렬하는 고속 분할 정복(Divide and Conquer) 알고리즘
- 메커니즘: 피벗 선택(Median-of-Three 등) → 파티셔닝(Hoare 또는 Lomuto 방식)을 통한 원소 재배치 → 좌우 하위 배열에 대한 독립 재귀 호출 및 제자리(In-place) 결합
- 통찰: 이미 정렬된 데이터나 역순 데이터에서 단순 첫 원소를 피벗으로 삼을 경우 편향 트리 분할로 $O(n^2)$ 최악 성능에 빠지므로 삼수 중앙값 피벗과 재귀 깊이 초과 시 힙 정렬로 전환하는 인트로소트(Introsort) 도입 필수

<details>
<summary>핵심 용어</summary>

- **Quick Sort(퀵 정렬)** : 피벗을 기준으로 리스트를 둘로 나누어 각각을 독립 재귀 정렬하는 평균 $O(n \log n)$ 속도의 대표적 비교 정렬
- **Pivot(피벗)** : 부분 배열을 두 개의 하위 그룹으로 분할할 때 기준이 되는 키 원소
- **Partitioning(파티셔닝)** : 피벗을 기준으로 작은 값은 좌측에, 큰 값은 우측에 배치하도록 원소를 스왑하는 핵심 연산 과정
- **Hoare Partition** : 양쪽 끝에서 시작하여 안쪽으로 이동하는 투 포인터를 사용하여 원소 교환 횟수를 최소화하는 전통적 파티션 방식
- **Lomuto Partition** : 단방향으로 순회하며 피벗보다 작은 영역의 경계 인덱스를 유지하는 단순하고 직관적인 파티션 방식
- **Introsort (인트로소트)** : 퀵 정렬로 시작하되 재귀 깊이가 $2 \log n$을 초과하면 최악 시간 $O(n \log n)$을 보장하는 힙 정렬로 전환하는 하이브리드 정렬

## 2~4교시 25점 답안

## Ⅰ. 퀵 정렬의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 하나의 기준 원소(Pivot)를 정하여 피벗보다 작은 원소들은 왼쪽으로, 큰 원소들은 오른쪽으로 분할한 후 각 하위 배열을 재귀적으로 정렬하는 제자리(In-place) 분할 정복 알고리즘 |
| 목적 | 내부 캐시 적중률(Spatial Locality)을 극대화하여 실제 하드웨어 환경에서 평균적으로 가장 빠른 정렬 속도 달성 |

## Ⅱ. 퀵 정렬의 핵심 특징

| 특징 | 의미 |
|---|---|
| 분할 정복(Divide & Conquer) | 병합 단계가 별도로 필요 없으며 분할(Partition) 과정 자체에서 원소의 최종 위치가 결정 |
| 뛰어난 캐시 지역성 | 인접한 메모리 블록을 연속적으로 순회 및 교환하므로 하드웨어 CPU 캐시 적중률 극대화 |
| 제자리 비안정 정렬 | 추가 메모리 공간이 거의 필요 없는 제자리 정렬($O(\log n)$ 스택)이나 동일 키 상대 순서 보존 불가(Unstable) |
| 입력 데이터 민감성 | 이상적 분할 시 $O(n \log n)$이나 최악 편향 분할 시 $O(n^2)$으로 성능 급락 위험 내포 |

## Ⅲ. 퀵 정렬 분할 정복 체계 및 파티셔닝 프로세스

### 분할 정복 구조 및 파티셔닝 메커니즘

```text
초기 원시 배열: [ 5,  3,  8,  4,  9,  1,  6,  2,  7 ]
                              │
                              ▼ (1단계: 피벗 Pivot = 5 선정)
┌────────────────────────────────────────────────────────────────────────┐
│ 파티셔닝(Partitioning) 실행: 피벗 5를 기준으로 원소 재배치            │
│                                                                        │
│   [ 3,  4,  1,  2 ]    < 5 (Pivot) <    [ 8,  9,  6,  7 ]              │
│   (피벗보다 작은 부분)                    (피벗보다 큰 부분)            │
│   ★ 피벗 5는 최종 정렬 위치에 확정 완료!                              │
└──────────────────┬─────────────────────────────────┬───────────────────┘
                   │                                 │
                   ▼ (2단계: 좌측 하위 배열 재귀)      ▼ (3단계: 우측 하위 배열 재귀)
           [ 3,  4,  1,  2 ]                 [ 8,  9,  6,  7 ]
                   │                                 │
                   ▼ (하위 피벗 선정 및 분할)         ▼ (하위 피벗 선정 및 분할)
           [ 1, 2 ]  3  [ 4 ]                [ 6, 7 ]  8  [ 9 ]
                   │                                 │
                   └────────────────┬────────────────┘
                                    ▼ (최종 정렬 완료)
             [ 1,  2,  3,  4,  5,  6,  7,  8,  9 ]
```

### 파티셔닝 알고리즘 2대 기법 상세 동작

```text
[1. Lomuto 파티션: 단방향 탐색]
  - 피벗을 항상 맨 끝 원소(arr[high])로 설정
  - i = low - 1 포인터: 피벗보다 작은 원소들의 경계 지점
  - j가 low부터 high-1까지 전진하며 arr[j] < pivot이면 i++ 후 swap(arr[i], arr[j])
  - 마지막에 swap(arr[i+1], arr[high]) 수행하여 피벗의 정확한 경계 인덱스 반환

[2. Hoare 파티션: 양방향 탐색]
  - 피벗을 arr[low] 등으로 설정
  - 왼쪽 포인터 i는 오른쪽으로 전진하며 arr[i] >= pivot인 원소 탐색
  - 오른쪽 포인터 j는 왼쪽으로 후진하며 arr[j] <= pivot인 원소 탐색
  - i < j이면 swap(arr[i], arr[j]) 수행, 교차 시점의 분할점 j 반환
  - Lomuto 대비 평균적으로 교환(Swap) 횟수가 약 3배 적어 성능 우수
```

## Ⅳ. Hoare 파티션 vs Lomuto 파티션 비교 및 복잡도 분석

### 두 파티셔닝 방식 간의 세부 비교

| 비교 항목 | 호어 파티션 (Hoare Partition) | 로무토 파티션 (Lomuto Partition) |
|---|---|---|
| **순회 방식** | **양쪽 끝에서 중앙으로 좁혀오는 투 포인터** | 한쪽 방향(Left to Right)으로만 이동하는 단방향 포인터 |
| **원소 교환 횟수** | **매우 적음 (불필요한 스왑을 최소화)** | 상대적으로 많음 (작은 원소를 만날 때마다 지속적 스왑) |
| **피벗 위치 보장** | 분할 경계 인덱스만 반환, 피벗 확정 위치 불일치 | **피벗이 정확히 두 하위 배열 경계 사이에 안착** |
| **동일 키 다수 배열** | 피벗과 같은 값들을 양쪽으로 균형 분할 | 피벗과 같은 값들을 한쪽으로 쏠리게 하여 편향 분할 유발 |
| **구현 난이도** | 인덱스 경계 예외(Infinite loop) 처리가 까다로움 | 코드가 직관적이고 매우 단순함 |

### 퀵 정렬 시간 및 공간 복잡도 분석

| 수행 조건 | 재귀 분할 점화식 | 시간 복잡도 | 호출 스택 공간 복잡도 |
|---|---|---|---|
| **최선의 경우 (Best)** | $T(n) = 2T(n/2) + \Theta(n)$ (피벗이 정확히 중앙 분할) | **$\Theta(n \log n)$** | $\Theta(\log n)$ |
| **평균의 경우 (Average)** | 일반적인 무작위 입력 데이터 분포 | **$\Theta(n \log n)$** | $\Theta(\log n)$ |
| **최악의 경우 (Worst)** | $T(n) = T(n-1) + \Theta(n)$ (이미 정렬/역순 정렬된 경우) | **$\Theta(n^2)$** | $\Theta(n)$ (스택 오버플로우) |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 이미 정렬된 배열이나 역순 배열에서 고정 피벗(첫/끝 원소) 사용 시 $O(n^2)$으로 성능 퇴화 | 첫 번째, 중간, 마지막 원소 중 중앙값을 선택하는 '삼수 중앙값(Median-of-Three)' 피벗 적용 |
| 동일한 키 값을 가진 원소가 대량으로 존재하는 경우 한쪽으로 편향 분할 발생 | 피벗보다 작음, 같음, 큼의 세 영역으로 분할하는 3-Way Partitioning(네덜란드 국기 문제) 적용 |
| 편향 분할 발생 시 재귀 호출 깊이가 $O(n)$에 달하여 콜 스택 오버플로우(Stack Overflow) 유발 | 재귀 깊이가 $2 \log n$을 초과할 때 최악 $O(n \log n)$ 보장 힙 정렬로 전환하는 인트로소트 채택 |

## Ⅵ. 제언

C++ STL `std::sort`의 표준 구현체인 인트로소트(Introsort) 도입 및 최적 퀵 정렬 파이프라인

### 산업 표준 Introsort(퀵+힙+삽입) 하이브리드 파이프라인

```text
[입력 데이터 배열 인입]
       ↓
[크기 검사: 원소 수 N <= 16 인가?] ── (예) ──→ [삽입 정렬 (Insertion Sort) 실행 및 완료]
       ↓ 아니오
[재귀 깊이 검사: Depth > 2 * log(N) 초과?] ── (예) ──→ [힙 정렬 (Heap Sort) 전환: O(n log n) 보장]
       ↓ 정상 범위
[삼수 중앙값(Median-of-Three) 피벗 선정]
       ↓
[호어(Hoare) 파티셔닝 수행]
       ↓
[좌/우 하위 배열에 대해 Introsort 재귀 호출]
```

### 정렬 파티션 및 피벗 선정 의사결정 체계

```text
퀵 정렬 구현 시 설계 검토
       ↓
[고성능 최적화가 필수적인가?]
       ├─ 예 ──→ 호어 파티션 (Hoare Partition) 채택 (스왑 최소화)
       └─ 아니오 ─→ 로무토 파티션 (Lomuto Partition) 채택 (단순성 확보)
                      ↓
           [중복 키 원소가 대량으로 발생하는 도메인인가?]
                      ├─ 예 ──→ 3-Way Partitioning (Dijkstra) 강제
                      └─ 아니오 ─→ Median-of-Three 피벗 기법 적용
```

### 선택 근거: 순수 퀵 정렬과 제언 인트로소트(Introsort) 비교

| 구분 | 순수 퀵 정렬 (Pure Quick Sort) | 제언: 하이브리드 인트로소트 (Introsort) |
|---|---|---|
| 최악 시간 보장 | 악의적 입력 패턴(Killer Sequence) 주입 시 $O(n^2)$ 파탄 | 재귀 깊이 초과 시 힙 정렬 전환으로 **최악 $O(n \log n)$ 절대 보장** |
| 소규모 구간 성능 | 크기 1~2 원소까지 재귀 분할 지속으로 함수 오버헤드 발생 | 원소 16개 이하 구간은 삽입 정렬로 조기 처리하여 20% 속도 향상 |
| 보안 안정성 | 서비스 거부(DoS) 공격용 입력에 취약 | 최악 시간 보장으로 알고리즘 복잡도 공격(Algorithmic DoS) 방어 |
