## 연관 키워드
- Apache Iceberg, 오픈 테이블 포맷, 메타데이터, 매니페스트, 스냅샷, 스키마·파티션 진화, 원자적 커밋

### Ⅰ. Apache Iceberg / 오픈 테이블 포맷의 개요

- 핵심 요약 : Apache Iceberg는 데이터 파일과 분리된 테이블 메타데이터·스냅샷으로 대규모 분석 테이블의 상태·변경을 관리하는 오픈 테이블 포맷.
- 개념 : 데이터 파일과 분리된 테이블 메타데이터·스냅샷으로 대규모 분석 테이블의 상태·변경을 관리하는 오픈 테이블 포맷(**Apache Iceberg**, Apache Iceberg).
- 배경 및 필요성 : 데이터 레이크의 파일 디렉터리만으로는 동시 쓰기·스키마 변경·시점 복구·엔진 간 일관성 관리가 어려움.
- 주요 목적 : 다양한 저장소·엔진에서 일관된 테이블 의미와 안정적인 대규모 분석 데이터 관리를 지원.

### Ⅱ. Apache Iceberg / 오픈 테이블 포맷의 특징 및 장점

- 핵심 요약 : 메타데이터 계층·매니페스트·스냅샷·원자적 커밋·스키마·파티션 진화.

1. 메타데이터 계층 : 메타데이터 파일이 현재 스키마·파티션 사양·스냅샷을 가리킴 → 디렉터리 목록에 의존하지 않는 테이블 상태 관리.
2. 매니페스트 : 데이터 파일의 파티션·통계·위치를 기록 → 쿼리 계획에서 불필요 파일 제거.
3. 스냅샷·원자적 커밋 : 변경 후 새 메타데이터를 커밋 → 일관된 시점 읽기와 동시 작성 충돌 감지.
4. 스키마·파티션 진화 : 열 추가·이름 변경과 파티션 전략 변경을 메타데이터로 관리 → 데이터 전체 재작성 부담 완화.

### Ⅲ. Apache Iceberg / 오픈 테이블 포맷의 구조 (흐름)

- 핵심 요약 : 파일 작성 → 매니페스트 생성 → 새 스냅샷·메타데이터 구성 → 원자적 커밋 → 엔진이 스냅샷을 읽고 파일 선택 → 보존 정책에 따라 만료·정리.

```text
파일 작성
   ↓
매니페스트 생성
   ↓
새 스냅샷·메타데이터 구성
   ↓
원자적 커밋
   ↓
엔진이 스냅샷을 읽고 파일 선택
   ↓
보존 정책에 따라 만료·정리
```

```text
카탈로그 포인터
     ↓
테이블 메타데이터
  ├ 스키마·파티션 사양
  └ 현재 스냅샷
         ↓
매니페스트 목록 → 파일 매니페스트 → 데이터 파일
```

### Ⅳ. 디렉터리형 데이터 레이크와 Apache Iceberg 비교

- 핵심 요약 : 디렉터리형 데이터 레이크는 경로·파일 목록을 테이블 상태로 간주, Apache Iceberg는 명시적 메타데이터·매니페스트·스냅샷을 사용.

| 비교 대상 | 핵심 특성 | 적용·판단 기준 |
|---|---|---|
| 디렉터리형 데이터 레이크 | 경로·파일 목록을 테이블 상태로 간주 | 단순 파일 교환·저장 시나리오 |
| Apache Iceberg | 명시적 메타데이터·매니페스트·스냅샷 | 대규모 분석·스키마 진화·동시 쓰기·시점 질의 |
| Apache Hudi·Delta Lake | 각 포맷 고유 로그·메타데이터 프로토콜 | 엔진 호환성·수집·트랜잭션 요구를 비교해 선택 |

### Ⅴ. Apache Iceberg / 오픈 테이블 포맷의 한계와 방안

- 핵심 요약 : 동시 커밋 충돌·스냅샷·파일 누적·엔진 호환성 편차를 충돌 재시도·보존 정책·호환성 표로 관리.

| 위험 | 원인·영향 | 대응 통제 | 지표 예시 |
|---|---|---|---|
| 동시 커밋 충돌 | 여러 작성자가 같은 기준 스냅샷을 갱신 | 충돌 재시도·작업 단위 분리·카탈로그 동시성 확인 | 커밋 재시도·충돌률 |
| 스냅샷·파일 누적 | 오래된 파일·메타데이터가 저장 공간과 계획 비용 증가 | 스냅샷 만료·고아 파일 정리의 보존 정책 운영 | 고아 파일·메타데이터 크기 |
| 엔진 호환성 편차 | 엔진별 포맷 기능·커밋 지원 차이 | 프로토콜 버전·기능 지원 표를 테스트·운영 표준에 반영 | 엔진별 읽기·쓰기 적합성 |

### Ⅵ. Apache Iceberg / 오픈 테이블 포맷 적용에 대한 기술사적 제언

- 핵심 요약 : 다양한 저장소·엔진에서 일관된 테이블 의미와 안정적인 대규모 분석 데이터 관리를 지원.

- 실행 제언 : 데이터 플랫폼 팀은 포맷을 저장 계층으로만 도입하지 말고 카탈로그·엔진의 호환성, 동시성, 스냅샷 보존·정리 책임을 데이터 거버넌스에 포함.

### Ⅶ. 결론

- 핵심 요약 : Apache Iceberg는 데이터 파일과 분리된 테이블 메타데이터·스냅샷으로 대규모 분석 테이블의 상태·변경을 관리하는 오픈 테이블 포맷.
- 시사점 : 오픈 테이블 포맷은 데이터 파일 위에 트랜잭션 가능한 테이블 메타데이터를 제공해 레이크하우스의 상호 운용성과 진화를 높이는 기반.
