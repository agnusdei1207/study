## 비교·연결 (유사 개념 간 차이점)

### 오픈 테이블 포맷 3대 기술 비교

| 비교 항목 | Apache Iceberg | Delta Lake | Apache Hudi |
|---|---|---|---|
| **주도 기업/커뮤니티** | **넷플릭스, 애플 / Apache 재단** | Databricks / 오픈소스화 | Uber / Apache 재단 |
| **메타데이터 구조** | **계층적 Avro 트리 (3계층 분리)** | JSON 트랜잭션 로그 + 체크포인트 | 타임라인(Timeline) + 메타데이터 파일 |
| **엔진 독립성** | **완전 독립 (Spark, Trino, Flink 동등)**| Spark 최적화 (타 엔진 어댑터 의존) | Spark 중심 (Flink 점진 지원) |
| **파티셔닝 유연성** | **히든 파티셔닝 & 파티션 진화 지원** | 명시적 디렉터리 파티션 기반 | 디렉터리 파티션 기반 |
| **주요 활용 워크로드** | 대규모 대화형 분석, 멀티 엔진 OLAP | Databricks 중심 통합 분석 파이프라인 | 스트리밍 빈번한 Upsert/Delete CDC |

### Apache Iceberg vs 전통적 Apache Hive

| 구분 | 전통적 하이브(Hive) | Apache Iceberg |
|---|---|---|
| **테이블 관리 단위** | 디렉터리(Directory) 레벨 | **파일(File) 레벨** |
| **디렉터리 리스팅** | S3/HDFS 파일 전체 목록화 $O(N)$ 병목 | **메타데이터 파일 직접 지정 $O(1)$ 스캔** |
| **트랜잭션(ACID)** | 원자성 없음 (동시 쓰기 시 정합성 파괴) | **완전한 ACID 지원 (스냅샷 격리)** |
| **스키마/파티션 변경** | 테이블 재성성 또는 대규모 마이그레이션 | **데이터 파일 재작성 없는 즉각적 진화** |

## 실무 적용과 트레이드오프

- 적용 상황: 수 페타바이트 규모의 실시간 금융 거래 로그 및 빅데이터 레이크하우스 구축

| 실패 증상 (위험) | 근본 원인 | 엔지니어링 대책 | 기대 효과 |
|---|---|---|---|
| **스트리밍 데이터 적재 시 1KB 미만 소형 파일 수천만 개 양산** | Flink의 잦은 마이크로 배치 커밋으로 인한 파편화(Small File Problem) | Iceberg 내장 비동기 컴팩션(`rewriteDataFiles`) 및 빈 패킹(Bin-packing) 스케줄러 가동 | 쿼리 스캔 속도 4배 향상 및 메타데이터 크기 75% 압축 |
| **수개월 운영 후 쿼리 플래닝 지연시간이 수초 대로 급증** | 만료되지 않은 과거 스냅샷과 불필요한 고아 파일(Orphan Files) 무한 누적 | 주기적 `expireSnapshots` 프로시저 실행 및 고아 파일 자동 정화 파이프라인 수립 | 쿼리 플래닝 레이턴시 50ms 미만 안정 유지 |
| **사용자의 잘못된 쿼리 조건으로 스토리지 전체 풀스캔 발생** | 기존 파티션 컬럼명과 변환 함수를 개발자가 일일이 외워야 하는 제약 | 히든 파티셔닝(Hidden Partitioning)을 적용하여 원천 타임스탬프 질의 시 자동 파티션 프루닝 | 비효율적 전체 스캔 방지 및 클라우드 I/O 비용 60% 절감 |

## 기술사의 눈 (주체적 차별화 제언)

- **[클라우드 독점 레이크하우스 종속의 병목과 한계]**: 과거 대다수 엔터프라이즈는 클라우드 벤더의 독점 스토리지 포맷이나 특정 DW 엔진에 데이터를 종속시킴으로써, 향후 멀티 클라우드 전환이나 타 엔진 도입 시 막대한 데이터 마이그레이션 비용과 벤더 락인(Lock-in) 문제에 직면함.
- **[나라면: 스토리지-컴퓨트 완전 분리 기반 개방형 레이크하우스 아키텍처 구축]**:
  1. **스토리지 레이어**: 오브젝트 스토리지(S3, GCS)에 Apache Iceberg 오픈 테이블 포맷을 공통 표준으로 채택하여 데이터 단일 사본(Single Source of Truth) 유지.
  2. **오픈 카탈로그 레이어**: 오픈소스 REST 카탈로그(Apache Polaris 또는 Gravitino)를 중앙에 배치하여 RBAC 기반 데이터 접근 제어 및 테이블 메타데이터 통합 관리.
  3. **멀티 엔진 컴퓨팅 레이어**: 실시간 스트리밍 적재는 Flink, 대규모 ETL/배치 처리는 Spark, 대고객 비즈니스 인텔리전스(BI) 대화형 질의는 Trino를 자유롭게 조합하여, 단일 데이터 사본 위에서 락(Lock) 없이 동시 작업을 수행하는 고효율·저비용 데이터 레이크하우스 플랫폼을 완성하겠음.
