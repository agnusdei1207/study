## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 소프트웨어 테스팅·품질 → 기록·재생 테스트(Record and Replay Testing)

## 지식 위치

소프트웨어공학 > 테스트 자동화 > 기록·재생 테스트

## 30초 인출

- 본질: 사용자의 실제 조작 행위(GUI 이벤트)나 운영 환경의 실시간 네트워크 트래픽(HTTP 요청/응답)을 캡처하여 저장(Record)한 후, 이를 신규 버전 시스템에 동일하게 재실행(Replay)하여 회귀 결함을 검출하는 테스트 자동화 기법
- 메커니즘: 트래픽 캡처/기록 → 개인정보(PII) 비식별화 및 동적 데이터(UUID, 타임스탬프) 정규화 → 스테이징/격리 환경 대상 요청 재생(Replay) → 이전 결과(Golden Master)와 응답 Diff 비교 판정
- 통찰: 실제 운영 쓰기(POST/PUT/DELETE) 요청을 무분별하게 재생할 경우 결제 승인, 외부 메일 발송 등 파괴적 부작용이 발생하므로 외부 I/O 가상화(Mocking) 및 섀도우 테스팅(Shadow Testing) 안전 통제 필수

<details>
<summary>핵심 용어</summary>

- **기록·재생 테스트 (Record & Replay Testing)** : 사용자의 입력 이벤트나 네트워크 패킷을 파일로 녹화한 후 재생하여 소프트웨어의 정상 동작과 회귀 여부를 검증하는 기법
- **트래픽 미러링 (Traffic Mirroring / Shadowing)** : 운영 환경에 인입되는 실제 사용자 HTTP 트래픽을 복제하여 신규 배포 대상 서비스로 비동기 포워딩하는 기법
- **골든 마스터 (Golden Master / Snapshot Testing)** : 검증된 구버전 시스템의 실행 결과(응답 JSON, 화면 스냅샷)를 기준선으로 저장하고 신규 결과와 비교하는 기법
- **테스트 오라클 (Test Oracle)** : 테스트 수행 결과가 참인지 거짓인지를 판단하기 위해 사전에 정의된 기대 결과와 검증 규칙
- **Gor (GoReplay)** : 실제 운영 네트워크 트래픽을 캡처하여 QA 및 스테이징 환경으로 실시간 재생하거나 파일로 저장해 재현하는 오픈소스 도구
</details>

## 2~4교시 예상문제 (25점)

> 소프트웨어 회귀 테스트 자동화를 위한 기록·재생(Record and Replay) 테스트의 개념과 두 가지 유형(GUI 조작 기반, 네트워크 트래픽 기반)을 비교하고, 엔터프라이즈 환경에서의 수행 절차 및 안전한 적용 방안(개인정보 보호, 멱등성, Mocking)을 제시하시오. (25점)

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 사용자의 화면 인터랙션(키보드/마우스 입력)이나 분산 시스템 간의 실시간 API 통신 패킷을 캡처하여 데이터로 저장(Record)한 뒤, 이를 테스트 대상 시스템에 그대로 재전송·재현(Replay)하여 이전 동작과의 일치성을 비교하는 테스트 자동화 방식 |
| 목적 | 수작업 테스트 케이스 작성 공수 절감, 실제 운영 환경의 복잡한 사용자 행동 패턴 및 대규모 실 트래픽 모사, 시스템 변경 후 예상치 못한 회귀(Regression) 결함 조기 발굴 |

## Ⅱ. 핵심 특징

| 특징 | 세부 내용 |
|---|---|
| 테스트 케이스 자동 생성 | 별도의 스크립트 코딩 없이 실제 사용자의 사용 데이터 자체를 테스트 케이스로 즉각 자산화 |
| 골든 마스터(Golden Master) 비교 | 이전 정상 버전의 출력값과 신규 버전의 출력값을 자동 비교(Diff)하여 오차 여부를 기계적으로 판별 |
| 미지의 결함 발견 (Edge Case) | 테스트 엔지니어가 미처 예상하지 못한 복잡한 파라미터 조합과 운영 트래픽 엣지 케이스 완벽 재현 |
| 비결정적(Non-Deterministic) 요소 제어 | 시스템 시간(Date), 고유 식별자(UUID), 시퀀스 번호 등 동적 변수로 인한 오탐(False Positive) 필터링 필요 |

코드 변경에 따른 사이드 이펙트를 가장 적은 비용으로 대규모 검증할 수 있는 회귀 검증의 핵심 기법.

## Ⅲ. 체계·프로세스

```text
[네트워크 트래픽 기반 기록·재생(Traffic Shadowing) 아키텍처]

[실제 사용자 (Production User)]
       │
       ▼ (1) 실제 운영 요청 (HTTP Request)
[API Gateway / L7 로드밸런서]
  ┌────────────────────────────────────────────────────────┐
  │ 고성능 패킷 미러링 엔진 (GoReplay / Envoy Proxy)       │
  └────────────────────────────────────────────────────────┘
       │                                     │
       │ (2) 정상 운영 트래픽 전송            │ (3) 트래픽 복제 (Shadow Mirroring)
       ▼                                     ▼
[운영 서비스 (Live Service v1.0)]     [전처리 필터 (Sanitizer)]
  - 실제 결제 및 DB 커밋                - 개인정보(주민번호/비번) 마스킹
  - 응답 반환 (Response A)              - 타임스탬프/토큰 동적 정규화
       │                                     │
       ▼                                     ▼ (4) 비동기 재전송 (Replay)
[골든 마스터 (Golden Master)]         [검증 서비스 (Test Service v2.0)]
  - Response A 저장                     - DB Mocking / 가상 샌드박스
       │                                - 응답 생성 (Response B)
       │                                     │
       ▼                                     ▼
  ┌────────────────────────────────────────────────────────┐
  │ (5) 응답 차이 비교 엔진 (Diff Engine)                  │
  │     Compare(Response A, Response B)                    │
  │     ├─ [Diff == 0] ──► 완벽한 하위 호환성 검증 성공    │
  │     └─ [Diff != 0] ──► 회귀 결함 발견 및 리포팅        │
  └────────────────────────────────────────────────────────┘
```

운영 트래픽 복제, 민감 정보 마스킹, 스테이징 재전송, 골든 마스터 기반 응답 차이 비교로 이어지는 엔드투엔드 파이프라인.

## Ⅳ. 종류·비교

| 비교 항목 | GUI 조작 기반 기록·재생 (Record & Replay) | 네트워크 트래픽 기반 기록·재생 (Traffic Mirroring) |
|---|---|---|
| **기록 대상** | 브라우저/앱 화면 상의 클릭, 타이핑, 스크롤 이벤트 | L7 HTTP/HTTPS 요청 패킷, 헤더, 페이로드 바디 |
| **대표 도구** | Selenium IDE, Cypress Studio, Playwright Codegen | GoReplay (Gor), Envoy Shadowing, Diffy, Speedscale |
| **주요 적용 수준** | 웹/모바일 프론트엔드 E2E 기능 테스트 | 백엔드 API 마이크로서비스, 대규모 시스템 현대화 |
| **취약점/단점** | UI 레이아웃, CSS 클래스명 변경 시 스크립트 깨짐 | 외부 쓰기(DB Write, 결제) 호출 시 사이드 이펙트 유발 |
| **테스트 속도** | 브라우저 렌더링 대기로 상대적 저속 | 수천 RPS 이상의 실 트래픽 고속 대량 검증 가능 |

### 전통적 스크립트 테스트 vs 기록·재생 테스트 비교

| 비교 항목 | 전통적 테스트 케이스 작성 (Manual / Script) | 기록·재생 테스트 (Record & Replay) |
|---|---|---|
| **구축 공수** | 엔지니어가 시나리오, 입력값, 기대값을 수기 코딩 (과다 공수) | 실제 사용자 트래픽 또는 조작 녹화를 통해 즉시 확보 (최소 공수) |
| **테스트 현실성** | 기획된 정형 시나리오에 한정 (현실 트래픽과 괴리) | 실제 고객의 불규칙한 입력, 헤더, 파라미터 완벽 반영 |
| **유지보수 비용** | API 스펙 변경 시 테스트 코드 수기 수정 필요 | 신규 기준선(Golden Master) 재녹화로 빠른 업데이트 가능 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 운영 트래픽 내 고객 개인정보(비밀번호, 카드번호, 주민번호)가 테스트 환경으로 유출 | 미러링 전단에서 정규식 기반 PII(개인식별정보) 자동 마스킹 및 토큰화(Tokenization) 필터 강제 |
| 주문, 결제 등 상태를 변경하는 POST/PUT 트래픽 재생 시 결제 승인 등 치명적 중복 부작용 | 타사 연계 API 및 외부 I/O를 격리된 가상 모의 서버(WireMock)로 리다이렉트하고 읽기 전용 트래픽 우선 재생 |
| 동적 타임스탬프, 랜덤 세션 ID 등으로 인해 실제 비즈니스 로직은 동일함에도 무수한 Diff 오탐 발생 | JSON Diff 엔진에 무시 필드(Ignore Path: `timestamp`, `traceId`) 룰셋을 정의하여 비즈니스 데이터만 선별 비교 |

## Ⅵ. 제언

레거시 차세대 전환이나 마이크로서비스 대규모 리팩토링 시, 카나리 배포 단계에서 Envoy 트래픽 섀도잉(Traffic Shadowing)을 적용하여 실제 사용자 영향 없이 백그라운드 무결성을 사전 검증하는 무장애 전환 체계 확립 필요.

```text
[안전한 섀도우 트래픽 검증 아키텍처]
  Live Users → Envoy Gateway ──┬──► Production v1 (100% 실서빙)
                               └──► Shadow Pod v2 (0% 비동기 검증 / DB Mocking) ──► Datadog Diff 대시보드
```

| 검증 단계 | 사전 준비 단계 | 섀도우 검증 및 승인 단계 |
|---|---|---|
| 핵심 통제 | 민감 정보 필터링 및 서드파티 결제 Mocking | 프로덕션 대비 섀도우 서비스의 응답 지연 및 에러 Diff 검증 |
| 전환 목표 | 실서빙 트래픽 성능 오버헤드 0% 유지 | 무결함 확인 후 가동률 100%로 트래픽 안전 스위칭 |
