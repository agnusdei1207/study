소프트웨어공학 → 소프트웨어 테스트 → 테스트 자동화 → **기록·재생 테스트**

## 30초 인출

- **본질** : 기록·재생 테스트는 실행 입력·행위·결과를 기록하고 이후 같은 조건 또는 정의된 변형 조건에서 다시 실행해 동작을 확인하는 테스트 방식
- **메커니즘** : 대상 행위·입출력 기록 → 재생 환경 구성 → 재실행 → 기대 결과와 비교
- 통찰: 한계: 실서비스 요청을 그대로 재생하면 결제·메일 같은 외부 부작용이 반복될 수 있음 → 방안: 재생 환경을 격리하고 동적 값의 판정 규칙을 정함

<details>
<summary>핵심 용어</summary>

- **기록·재생 테스트(Record and Replay Testing)** : 테스트 행위나 통신 데이터를 기록하고 이후 재실행하는 테스트 기법의 총칭
- **GUI 기록·재생(GUI Record and Replay)** : 사용자 인터페이스 조작을 기록해 화면에서 재수행하는 방식
- **트래픽 기록·재생(Traffic Record and Replay)** : 요청·응답 통신을 기록하고 시험 환경에서 재생하는 방식
- **테스트 오라클(Test Oracle)** : 실행 결과의 정확성을 판정하는 기대 결과·규칙
- **Golden Master** : 기준 실행 결과를 저장하고 후속 결과와 비교하는 회귀 테스트 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **기록·재생 테스트** : 테스트 행위나 통신 데이터를 기록하고 다시 실행해 동작을 확인하는 방식 |
| 목적 | 반복 가능한 시험 입력을 재사용해 회귀 검증을 지원 |

## Ⅱ. 기록·재생 테스트의 특징

| 특징 | 의미 |
|---|---|
| 실행 증거 재사용 | 조작·트래픽을 기록해 반복 입력으로 활용 |
| 환경 통제 필요 | 데이터·시간·외부 서비스 차이가 재생 결과에 영향 |
| 오라클 분리 | 기록과 별도로 기대 결과·동적 값 판정 규칙 정의 |

## Ⅲ. 기록·재생과 결과 판정 체계

```text
시험 목적·기록 범위 정의
    ↓
대상 조작·트래픽 기록 → 기준 시나리오 구성
    ↓
환경·데이터 통제 후 재생
    ↓
기대 결과와 비교 → 차이 분석·시나리오 갱신
```

기록 파일 자체가 테스트 오라클은 아님. 결과가 달라졌을 때 결함인지 환경 변동인지 구분할 기대 결과와 판정 기준이 필요.

### 유형별 안전한 재생 구조

```text
GUI 기록 → 테스트 계정·화면 구성 → UI 환경에서 재생
통신 기록 → 민감정보 제거·주소 변경 → 격리 환경에서 재생
                                          ↓
                                     결과 수집·판정
```

운영 트래픽 재생이나 그림자 실행은 별도의 위험 분석 필요. 쓰기 요청, 개인정보, 외부 서비스 부작용을 통제하지 않은 채 실제 운영 대상으로 재생하지 않음.

## Ⅳ. 기록 대상별 유형과 적용 관계

| 관점 | 내용 |
|---|---|
| 효과 | 반복 입력 재사용, 회귀 확인의 자동화 지원 |
| 한계 | 환경·시간·외부 서비스 변화로 재생 실패 또는 무관한 차이 발생 |
| 유지관리 | UI/API 변화에 따라 기록 시나리오와 기대 결과 갱신 필요 |

Golden Master는 기준 결과 비교를 활용하는 접근 중 하나이며, 모든 기록·재생 시험에 자동 적용되는 판정법은 아님.

| 유형 | 기록 내용 | 재생 특성 |
|---|---|---|
| GUI 기록·재생 | 클릭·입력·화면 전이 등의 사용자 조작 | 화면 구조·대기 시간·브라우저 환경 변화에 민감 |
| 트래픽 기록·재생 | 애플리케이션 요청·응답 데이터 | 요청 재현에 유용하나 데이터·인증·외부 효과 관리 필요 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| UI 변경마다 기록 시나리오가 불안정 | 의미 있는 화면 식별자와 명시적 대기 조건을 사용하고 변경 시 재검증 |
| 동적 응답 차이가 오탐을 유발 | 시간·식별자 등 비결정 값의 정규화 규칙과 오라클 기준 마련 |
| 재생으로 업무 데이터·외부 시스템 변경 | 가상화·샌드박스·모의 응답과 초기화 가능한 시험 데이터 적용 |

## Ⅵ. 제언

우선 실행: 핵심 업무 경로에 한정해 안정된 계약·시험 데이터를 갖춘 시나리오부터 유지하고, 실패 원인을 환경·제품·오라클로 분류.
