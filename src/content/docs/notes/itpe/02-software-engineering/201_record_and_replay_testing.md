## 연관 키워드

- 기록·재생 테스트(Record and Replay Testing), 테스트 자동화(Test Automation), 회귀 테스트(Regression Testing)
- UI(User Interface) 기록, 네트워크 트래픽 미러링(Traffic Shadowing), 결정론적 재현(Deterministic Replay)
- Playwright Codegen, Cypress Studio, WireMock, GoReplay, Flaky Test

## Ⅰ. 기록·재생 테스트의 개요

- 핵심 요약 : 사용자 조작이나 네트워크 트래픽을 기록한 뒤 같은 조건으로 재생해 결함을 반복 검증하는 테스트 자동화 기법.
- 개념 : 브라우저에서 이루어진 클릭·입력·스크롤이나 서비스 간 HTTP(Hypertext Transfer Protocol) 요청·응답을 캡처해 저장(Record)하고, 테스트 시점에 같은 순서로 재생(Replay)하여 회귀 결함을 확인하는 **기록·재생 테스트** (Record and Replay Testing)로, 테스트 자동화의 한 방식이자 회귀 테스트(Regression Testing)의 실행 수단이다.
- 배경 및 필요성 : 복잡한 UI 시나리오를 수작업으로 코딩하는 공수가 크고, 운영 환경에서만 드러나는 장애나 외부 API 장애는 로컬에서 재현하기 어려워 디버깅이 지연됨.
- 주요 목적 : 테스트 스크립트 작성 공수를 줄이고, 운영에서 발생한 상황을 테스트 환경에서 같은 조건으로 재현.
- 대표 도구
  1. UI 계층 : Playwright Codegen, Cypress Studio, Selenium IDE
  2. 네트워크 계층 : WireMock(녹화·재생 모드), VCR, GoReplay

## Ⅱ. 기록·재생 테스트의 특징 및 장점

- 핵심 요약 : UI와 네트워크 두 계층에서 기록한 상호작용을 재생하여 스크립트 작성 속도와 재현성을 확보하는 방식.

1. UI 기록 : 브라우저 도구가 사용자의 클릭 경로를 추적해 XPath(XML Path Language)나 CSS(Cascading Style Sheets) 선택자를 가진 테스트 코드를 자동 생성 → 작성 시간 단축.
2. **네트워크 트래픽 미러링** (Traffic Shadowing, 운영 서버로 들어오는 실제 요청을 복사해 검증 서버에 재생하는 기법) : 실제 부하와 데이터 흐름을 운영 영향 없이 검증 → 실환경에 가까운 회귀 검증.
3. **결정론적 재현** (Deterministic Replay, 같은 입력과 응답 조건에서 같은 결과를 얻도록 하는 재생) : 기록한 외부 응답을 고정해 희귀 결함을 로컬에서 반복 재현 → 디버깅 효율 향상.
4. 낮은 진입 장벽 : 화면 조작만으로 스크립트가 생성되어 기획자나 수동 QA(Quality Assurance) 담당자도 참여 가능 → 자동화 참여 인력 확대.
5. CI(Continuous Integration) 파이프라인에 연계되어 무인으로 회귀 테스트를 반복 실행 → 배포 전 검증 주기 단축.

## Ⅲ. 기록·재생 테스트의 구조 (흐름)

- 핵심 요약 : UI 계층의 스크립트 생성 흐름과 네트워크 계층의 트래픽 저장 흐름이 병렬로 놓이는 이중 구조.

```text
[ UI 계층 : 기록 → 재생 ]
[ 테스터의 브라우저 조작 ]
      ↓ 이벤트 캡처
[ 테스트 스크립트 자동 생성 ]
      ↓ 헤드리스 브라우저 재생
[ CI 파이프라인 무인 실행 ]
```

```text
[ 네트워크 계층 : 기록 → 재생 ]
[ 운영 서버의 실제 트래픽 ]
      ↓ 패킷 미러링 또는 프록시 캡처
[ 트래픽 기록 저장소 ]
      ↓ 모의 응답 재생 주입
[ 테스트·스테이징 서버 ]
```

## Ⅳ. 수작업 테스트 스크립트와의 비교

- 핵심 요약 : 생성 속도와 진입 장벽은 기록·재생이 앞서고, 유지보수 안정성과 단언 설계는 수작업이 앞서는 상호 보완 관계.

| 비교 항목 | 수작업 테스트 코딩 | 기록·재생 테스트 |
| --- | --- | --- |
| 생성 속도 | 선택자 조사와 단언 작성에 시간이 걸림 | 화면을 조작하면 스크립트가 즉시 생성됨 |
| 진입 장벽 | 테스트 프레임워크와 프로그래밍 지식 필요 | 비개발자도 작성 가능 |
| 유지보수 | POM(Page Object Model) 패턴으로 모듈화하면 비교적 견고함 | UI 변경 시 녹화 스크립트가 쉽게 깨짐 |
| 실행 결정론 | 외부 상태에 따라 결과가 달라질 수 있음 | 응답을 고정하면 재현성이 높지만 시간·동시성은 별도 통제 필요 |
| 적합 단계 | 핵심 비즈니스 로직의 단위·통합 테스트 | 대규모 회귀 스위트 생성과 운영 결함 재현 |

- 선택 기준 : 변경이 잦은 화면은 수작업 모듈로, 안정된 주요 흐름과 운영 재현은 기록·재생으로 나누어 적용.

## Ⅴ. 기록·재생 테스트의 한계와 방안

- 핵심 요약 : 선택자 취약성, 비동기 타이밍 오탐, 단언 누락을 선택자 표준·명시적 대기·단언 의무화로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 선택자 취약성 | 클래스명·DOM 구조 변경으로 녹화 선택자가 깨져 대량 실패 | 테스트 전용 속성(`data-testid`) 기반 선택자 표준화 | 선택자 파손 건수 |
| 비결정적 타이밍 오탐 (Flaky Test) | 응답 지연으로 요소가 준비되기 전에 클릭되어 간헐적 실패 | 고정 대기(sleep) 제거, **명시적 대기** (Explicit Wait, 특정 조건이 성립할 때까지 기다리는 방식) 적용 | 간헐 실패율 |
| 단언 누락 | 동작만 재생하고 결과 검증이 없어 겉핥기 테스트가 됨 | 핵심 지점에 화면 값·API 응답 검증 단언 추가 | 단언 포함 시나리오 비율 |

## Ⅵ. 테스트 신뢰성 확보에 대한 기술사적 제언

- 핵심 요약 : 선택자 표준과 개인정보 비식별화를 도입 기준으로 세워, 기록 도구를 안정적으로 쓸 수 있는 조건을 먼저 갖추는 방향이 바람직하다.
- 품질 조직은 테스트 전용 속성 규격을 개발 표준에 포함시켜, 빌드마다 바뀌는 무작위 CSS 클래스 대신 고정된 식별자로 녹화 결과가 유지되도록 해야 한다.
- 보안 조직은 운영 트래픽을 스테이징으로 복제하기 전에 주민등록번호, 비밀번호, 카드번호 같은 민감정보를 프록시 계층에서 마스킹하는 절차를 의무화해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 기록·재생 테스트는 빠른 자동화와 결함 재현을 제공하지만, 선택자와 단언 통제가 전제된 보조 기법.
- 시사점 : 수작업 스크립트와 기록·재생을 역할에 따라 나누고, 민감정보 보호를 함께 설계하는 것이 실무 신뢰성의 핵심.
