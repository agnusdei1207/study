<summary>핵심 용어</summary>

- `LCNC(Low-Code / No-Code)`: 시각적 추상화와 사전 제작 부품으로 코딩량을 최소화하거나 없앤 개발 플랫폼
- `Citizen Developer(시민 개발자)`: 전문 프로그래머가 아니지만 비즈니스 도메인 지식을 바탕으로 직접 현업 앱을 구축하는 실무자
- `CoE(Center of Excellence)`: LCNC 도입 시 표준 템플릿, 보안 가드레일, 컴포넌트 재사용 정책을 수립하고 통제하는 전담 조직
- `Shadow IT`: IT 전담 부서의 공식 승인과 통제를 벗어나 현업 부서에서 임의로 구축·운영하는 비인가 정보시스템
- `Vendor Lock-in(벤더 종속)`: 특정 LCNC 상용 플랫폼에 데이터와 비즈니스 로직이 종속되어 타 환경으로의 이관이 제한되는 위험
- `Exit Plan(퇴구 전략)`: 벤더 종속 탈피를 위해 데이터 표준 스키마 반출, 소스코드 변환, 마이그레이션 방안을 사전에 수립하는 전략

</details>

## 예상문제

> 최근 기업 내 디지털 전환(DX) 가속화 및 IT 개발 인력 부족 해소를 위한 방안으로 로우코드·노코드(LCNC) 플랫폼이 확산되고 있다. LCNC의 개념, 플랫폼 핵심 아키텍처 구성요소를 설명하고, 엔터프라이즈 환경 도입 시 발생할 수 있는 주요 위험요인과 이에 대한 거버넌스 통제 방안을 제시하시오. (25점)

## 딸려 나오는 하위 토픽

| 하위 토픽 | 핵심 키워드 | 통합 답안 위치 |
|---|---|---|
| 노코드(No-Code) | 시민 개발자, 사전 정의 템플릿, 시각적 설정·조합, 단순 업무 자동화 | Ⅰ·Ⅲ·Ⅴ |
| 로우코드(Low-Code) | 전문 개발자, 커스텀 코드 확장, OpenAPI 연계, 엔터프라이즈 코어 연동 | Ⅰ·Ⅲ·Ⅴ |
| LCNC 거버넌스 | CoE, Shadow IT 통제, RBAC/DLP, 앱 카탈로그, Exit Plan | Ⅳ·Ⅵ·Ⅶ |

## Ⅰ. 개발 민주화와 소프트웨어 생산성 혁신, LCNC 개요

> LCNC는 소프트웨어 개발 진입장벽을 낮춰 비즈니스 민첩성을 극대화하며, 성공 여부는 무분별한 개발 허용이 아닌 체계적인 전사 거버넌스 가드레일에 의해 좌우됨.

- 정의: 시각적 모델링(GUI), 사전 제작 컴포넌트, 드래그 앤 드롭 방식을 통해 최소한의 코딩(Low-Code) 또는 무코딩(No-Code)으로 애플리케이션을 신속히 개발·배포하는 플랫폼 기술
- 목적: 현업 부서의 IT 백로그 해소 및 시장 출시 시간(Time-to-Market) 단축
- 배경: 전문 개발 인력의 공급 부족과 급증하는 비즈니스 자동화 수요 간의 불균형 해소 필요

## Ⅱ. LCNC 적용 효과와 업무 영역별 적합도

> 업무의 복잡도와 위험도에 따라 No-Code, Low-Code, Pro-Code를 명확히 분리 적용해야 투자 대 효율(ROI)과 안정성을 동시에 확보할 수 있음.

| 관점 | 적용 효과 | 적합 업무 영역 | 핵심 검증 지표 |
|---|---|---|---|
| 개발 속도 | 반복적 CRUD 화면 및 결재 워크플로우 자동 생성 | 부서 내 서식 신청, 프로토타입 검증 | 리드타임 단축률, 배포 주기 |
| 협업 강화 | 현업 실무자가 직접 모델을 보며 요구사항 즉시 반영 | 요구사항 명세 가시화, 업무 자동화 | 재작업률(Rework Rate), 만족도 |
| 컴포넌트 재사용 | 사전 검증된 표준 UI 블록 및 SaaS 커넥터 활용 | ERP/CRM 연계, 사내 포털 연동 | 재사용률, 초기 결함 밀도 |
| 핵심 집중 | 전문 개발자는 고난도 백엔드 및 코어 알고리즘에 집중 | 복합 엔터프라이즈 시스템 구축 | 개발자 백로그 대기 시간 |

## Ⅲ. LCNC 플랫폼 핵심 아키텍처 구성요소

> LCNC 플랫폼은 시각적 개발 환경, 백엔드 연계 계층, 자동화된 ALM 런타임이 유기적으로 결합된 3계층 구조로 동작함.

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. 시각적 모델링 계층 (Visual Modeling Layer)              │
│    - WYSIWYG UI 빌더, 시각적 데이터 모델러, BPMN 워크플로우 엔진 │
└──────────────────────────────┬──────────────────────────────┘
                               │ Metadata Schema
┌──────────────────────────────▼──────────────────────────────┐
│ 2. 통합 및 연계 계층 (Integration & Connector Layer)       │
│    - 표준 REST/OpenAPI, DB 커넥터, 레거시 시스템 어댑터      │
└──────────────────────────────┬──────────────────────────────┘
                               │ Containerized Runtime
┌──────────────────────────────▼──────────────────────────────┐
│ 3. 런타임 및 ALM 통제 계층 (Runtime & ALM Control Layer)   │
│    - 원클릭 자동 빌드·배포, IAM/RBAC, 앱 카탈로그, 감사 로그   │
└─────────────────────────────────────────────────────────────┘
```

- **시각적 UI·데이터 모델러**: 드래그 앤 드롭으로 반응형 웹·모바일 UI를 생성하고, 관계형 엔티티를 그래픽으로 설계
- **비즈니스 로직·워크플로우 엔진**: 분기 조건, 유효성 검증, 승인 결재선을 코딩 없이 BPMN 기반 상태 머신으로 구성
- **표준 커넥터 및 API 계층**: SAP, Salesforce, 사내 RDBMS 등과 별도 코딩 없이 플러그인 방식으로 데이터 연동
- **ALM 및 자동 배포 파이프라인**: 브랜치 버전 관리, 자동 의존성 패키징, 컨테이너 기반 샌드박스 배포 자동화

## Ⅳ. 도입 선정부터 운영·폐기까지의 엔터프라이즈 라이프사이클

> 단계별 명확한 통제 기준(Gate)을 수립하여 플랫폼 도입의 초기 리스크를 최소화하고 지속 가능한 운영 체계를 확립함.

```text
[1단계: 업무 분류] ──> [2단계: 플랫폼 PoC] ──> [3단계: CoE 가드레일] ──> [4단계: 개발·검증] ──> [5단계: 운영·Exit]
  데이터 민감도 및       성능·보안·확장성       표준 템플릿·권한정책       ALM 파이프라인 연계       앱 카탈로그 등록
  복잡도 기준 분류       벤더 지속가능성 평가   개발 허용 범위 정의       정적 보안 취약점 점검     데이터 반출 훈련
```

1. **업무 분류(Classification)**: 업무 중요도, 트랜잭션 빈도, 규제 준수 요건을 평가하여 LCNC 적합 영역을 선별
2. **플랫폼 평가(Evaluation)**: 지원 기능뿐 아니라 컴포넌트 커스터마이징 자유도, 소스코드 반출 가능 여부 등을 종합 검증
3. **CoE 가드레일 수립(Governance Setup)**: 시민 개발자 권한 부여 기준, 허용 데이터 소스, 보안 승인 체크리스트 제정
4. **개발 및 ALM 검증(Build & Verification)**: 버전 관리, 환경 분리(Dev/Stage/Prod), 자동 보안 게이트를 통한 배포 승인
5. **운영 및 퇴구 전략(Operation & Exit)**: 전사 앱 카탈로그 등록, 사용률 모니터링, 폐기 시 데이터 마이그레이션 수행

## Ⅴ. No-Code · Low-Code · Pro-Code 핵심 비교

> 세 개발 방식은 대체 관계가 아닌 업무 도메인의 복잡도와 보안 요구에 따라 상호 보완적으로 운용되어야 함.

| 비교 항목 | No-Code | Low-Code | Pro-Code |
|---|---|---|---|
| 주 개발 주체 | 현업 실무자 (시민 개발자) | 현업 파워유저 + 전문 개발자 | 전문 소프트웨어 엔지니어 |
| 구현 메커니즘 | 100% 사전 제작 블록 및 설정 | 드래그 앤 드롭 + 스크립트 확장 | 범용 언어(Java, TS 등) 직접 코딩 |
| 아키텍처 유연성 | 제한적 (플랫폼 제공 기능 한정) | 중간~높음 (API 및 플러그인 확장) | 무제한 (시스템 아키텍처 전면 제어) |
| 적합 시스템 | 단순 승인, 부서 서식, 개인 생산성 | 통합 업무 포털, 고객 대면 앱 | 고성능 코어 뱅킹, 분산 대용량 처리 |
| 핵심 관리 위험 | 섀도우 IT 및 데이터 유출 | 플랫폼 종속 및 아키텍처 복잡화 | 긴 개발 기간 및 높은 유지보수 비용 |

## Ⅵ. 엔터프라이즈 LCNC 위험 관리 및 거버넌스 통제

> 플랫폼의 민첩성을 저해하지 않으면서도 보안 침해와 아키텍처 난립을 방지하는 정밀한 가드레일 설계가 필수적임.

| 위험 | 대책 | 효과 |
|---|---|---|
| 섀도우 IT 확산 (미승인 시스템 난립) | CoE 기반 개발 권한 승인제 및 전사 통합 앱 카탈로그 운영 | 미인가 시스템 실시간 식별 및 비인가 데이터 처리 원천 차단 |
| 벤더 종속 (Vendor Lock-in) | 표준 OpenAPI/SQL 연계 원칙 준수 및 메타데이터 반출(Exit Plan) 수립 | 플랫폼 교체 시 데이터·로직 재활용 보장 및 전환 비용 최소화 |
| 보안 취약점 및 데이터 유출 | SSO/RBAC 기반 세분화된 접근 통제 및 ALM 정적 분석(SAST) 게이트 강제 | 비인가 권한 상승 방지 및 컴포넌트 내 잠재 결함 사전 제거 |
| 소유자 부재로 인한 레거시화 | 앱 소유권(Owner) 명시 및 연간 사용률 기반 수명주기(Retirement) 감사 | 유휴 시스템 방치 예방 및 불필요한 클라우드 라이선스 낭비 절감 |

## Ⅶ. 기술사적 제언: 속도 중심에서 통제된 자율성(Guarded Agility)으로

> LCNC는 단순히 코딩을 없애는 도구가 아니라, 현업과 IT 조직의 역할 분담을 재정의하는 조직적 운영 모델의 전환임.

### 학습자 통찰 메모 — 답안 밖
- `[핵심 통찰]`: LCNC 도입의 실패는 도구의 기술적 결함 때문이 아니라 현업 개발자가 만든 수백 개의 앱이 누구의 관리도 받지 않는 섀도우 IT로 변질되기 때문에 발생함. CoE의 철저한 승인 체계가 선행되어야 함.
- `나라면`: 무조건적인 전사 개방을 피하고, 1단계 파일럿으로 부서별 서식 업무에 노코드를 적용한 뒤, 성숙도에 따라 CoE 주관의 로우코드 확장형 하이브리드 개발 모델로 전환하겠음.

### 실전 답안용 기술사적 제언
- 판정: LCNC 성공의 핵심은 개발 속도의 가속화가 아니라, CoE 조직을 통한 **보안 가드레일과 수명주기 통제력** 확보에 있음
- 대안: 전사 CoE 조직 구성 $\rightarrow$ 앱 카탈로그 의무 등록 $\rightarrow$ 샌드박스 격리 ALM 파이프라인 $\rightarrow$ Exit Plan 정례 훈련
- 검증: 미승인 앱 제로(0건), 보안 게이트 100% 통과, 연간 미사용 앱 회수율 모니터링
- 효과: IT 백로그 조기 해소와 동시에 섀도우 IT 및 보안 규정 위반 리스크 완벽 차단

```text
[현행 한계] ─────────> [개선 방안] ─────────> [검증 기준] ─────────> [실행 효과]
통제 없는 도입         CoE 거버넌스 수립      보안 게이트 준수        개발 백로그 단축
섀도우 IT 급증         전사 앱 카탈로그 운영  정기 라이선스 감사      데이터 유출 원천 차단
```

## 1교시 10점 답안 발췌

```text
1. 로우코드·노코드(LCNC)의 정의 및 목적
- 정의: 시각적 드래그 앤 드롭 모델링과 사전 정의 컴포넌트를 활용하여 최소 코딩 또는 무코딩으로 앱을 구축하는 개발 플랫폼
- 목적: 현업 요구사항의 신속한 소프트웨어화(Time-to-Market 단축) 및 IT 백로그 해소

2. LCNC 플랫폼 구성요소 및 동작 구조
┌─────────────────────────────────────────────────────────────┐
│ Visual UI / Data Modeler (드래그 앤 드롭, WYSIWYG)          │
│ Workflow & Business Logic Engine (BPMN 상태 머신)          │
│ Integration Connector (표준 REST/OpenAPI, DB 어댑터)       │
│ Automated ALM Pipeline (원클릭 빌드, 격리 샌드박스, RBAC)   │
└─────────────────────────────────────────────────────────────┘

3. 엔터프라이즈 도입 리스크 통제 대책
- 섀도우 IT: CoE 조직 주도 하에 전사 통합 앱 카탈로그 등록 의무화
- 벤더 종속: 표준 데이터 스키마 분리 및 Exit Plan(퇴구 전략) 사전 수립
- 보안 취약: SSO/IAM 연계, 정적 보안 분석(SAST) 품질 게이트 통과 후 프로덕션 배포
```
