## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 개발 방법론·도구 → 로우코드·노코드(LCNC)

## 지식 위치

소프트웨어공학 > 개발 방식·도구 > 로우코드·노코드

## 30초 인출

- 본질: 복잡한 전통적 텍스트 코딩(Pro-Code) 대신 시각적 드래그 앤 드롭(Drag-and-Drop) GUI 모델러와 사전 구축된 컴포넌트 블록을 활용하여 애플리케이션을 신속히 개발하는 패러다임
- 메커니즘: 시각적 UI/데이터 모델링 → 비즈니스 워크플로우 룰 설정 → 사전 정의된 커넥터(Connector)를 통한 외부 API 연계 → 원클릭 빌드 및 배포 자동화
- 통찰: 현업 부서의 무분별한 앱 개발로 인한 섀도우 IT(Shadow IT) 확산과 데이터 유출을 방지하기 위해 전문 IT 조직(CoE) 기반의 중앙 거버넌스, 보안 RBAC 및 ALM 파이프라인 수립 필수

<details>
<summary>핵심 용어</summary>

- **LCNC (Low-Code / No-Code)** : 비전문가도 최소한의 코딩(Low-Code) 또는 코딩 없이(No-Code) 애플리케이션을 신속히 개발할 수 있도록 지원하는 플랫폼
- **시민 개발자 (Citizen Developer)** : 전산/소프트웨어 전공자가 아니지만 승인된 LCNC 도구를 활용하여 실무 업무용 앱을 직접 제작하는 현업 실무자
- **섀도우 IT (Shadow IT)** : 기업 중앙 IT 부서의 승인, 통제, 보안 검토를 거치지 않고 사내에서 무단 도입되어 운영되는 소프트웨어 및 클라우드 자산
- **커넥터 (Connector)** : ERP, CRM, 데이터베이스 등 엔터프라이즈 시스템과 LCNC 앱을 코드 없이 클릭만으로 연동해 주는 표준 연계 모듈
- **CoE (Center of Excellence)** : 사내 LCNC 플랫폼의 아키텍처 가이드라인, 보안 표준, 재사용 템플릿을 지원하고 관리하는 IT 전문 조직
</details>

## 2~4교시 예상문제 (25점)

> 엔터프라이즈 디지털 전환(DX) 가속화를 위한 로우코드/노코드(LCNC)의 개념과 아키텍처 구성요소를 설명하고, 프로코드(Pro-Code)와의 비교 및 섀도우 IT 방지를 위한 엔터프라이즈 거버넌스(CoE) 구축 방안을 제시하시오. (25점)

---

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 복잡한 프로그래밍 언어 문법을 숙지하지 않아도 시각적인 그래픽 사용자 인터페이스(GUI) 환경에서 드래그 앤 드롭 방식으로 화면, 비즈니스 로직, 데이터베이스를 조립·배포하는 고생산성 개발 플랫폼 |
| 목적 | 전문 개발자 인력 부족(구인난) 해소, 현업 비즈니스 요구사항의 즉각적 IT 구현(Time-to-Market 단축), 기업 전반의 디지털 전환(DX) 내재화 |

## Ⅱ. 핵심 특징

| 특징 | 세부 내용 |
|---|---|
| 시각적 모델 주도 개발 (MDD) | 텍스트 코딩 대신 플로우차트와 블록 형태로 비즈니스 프로세스 및 데이터 흐름을 직관적 설계 |
| 사전 구축된 컴포넌트 생태계 | 로그인, 결제 연동, 차트 시각화, 모바일 푸시 등 표준 기능이 모듈화되어 즉시 재사용 가능 |
| 멀티 플랫폼 반응형 자동 생성 | 단 1회 설계로 PC 웹, iOS, 안드로이드 모바일 하이브리드 앱을 크로스 플랫폼 형태로 자동 빌드 |
| 시민 개발자와 프로 개발자의 협업 | 노코드로 기본 UI/프로토타입을 빠르게 제작하고, 고난도 비즈니스 로직이나 알고리즘은 로우코드로 확장 |

개발의 진입 장벽을 파괴하여 IT 부서와 현업 비즈니스 부서 간의 협업 간극을 해소하는 촉매제로 기능.

## Ⅲ. 체계·프로세스

```text
[LCNC 플랫폼 아키텍처 및 개발·운영 프로세스]

[사용자 계층: 시민 개발자 & 전문 개발자]
       │
       ▼ (웹 브라우저 기반 GUI 접속)
[LCNC 통합 개발 스튜디오 (Studio)]
  ┌────────────────────────────────────────────────────────┐
  │ 1. 시각적 UI 빌더     : 드래그 앤 드롭 컴포넌트 배치   │
  │ 2. 워크플로우 엔진    : BPMN 기반 조건 분기/결재선 정의 │
  │ 3. 데이터 모델러      : 노코드 엔티티/테이블 스키마 생성│
  │ 4. 코드 확장 영역     : JavaScript / Java 커스텀 플러그인│
  └────────────────────────────────────────────────────────┘
       │
       ▼ [사전 구축된 커넥터 (Pre-built Connectors)]
[엔터프라이즈 백엔드 및 외부 클라우드]
  - SAP ERP, Salesforce CRM, 사내 RDBMS, OpenAI API
       │
       ▼ [원클릭 자동화 배포 파이프라인 (ALM)]
[멀티 플랫폼 실행 환경 (Runtime)]
  - 클라우드 컨테이너 / 웹 포털 / 모바일 앱 자동 퍼블리싱
```

시각적 모델링, 데이터 연계 커넥터, 코드 확장 영역, 원클릭 ALM 자동 배포로 이어지는 라이프사이클.

## Ⅳ. 종류·비교

| 비교 항목 | 노코드 (No-Code) | 로우코드 (Low-Code) | 프로코드 (Pro-Code / 전통적 개발) |
|---|---|---|---|
| **대상 사용자** | 비개발 현업 실무자 (시민 개발자) | 현업 파워 유저 및 전문 개발자 | 전문 소프트웨어 엔지니어 |
| **코딩 요구량** | **0% (완전 무코딩)** | **10~20% (선택적 스크립트 작성)** | **100% (완전 수기 코딩)** |
| **개발 속도** | 수 시간 ~ 수 일 (초고속) | 수 일 ~ 수 주 (매우 빠름) | 수 개월 이상 소요 |
| **커스터마이징** | 플랫폼이 제공하는 템플릿에 한정 | 플러그인 및 스크립트로 확장 가능 | 무제한의 완전한 자유도 |
| **적합한 영역** | 단순 신청/승인 결재, 사내 설문, 대시보드 | 부서별 비즈니스 앱, 고객용 포털 | 대규모 트랜잭션 코어 뱅킹, 고성능 AI 엔진 |
| **대표 플랫폼** | Bubble, Zapier, Airtable, Notion | OutSystems, Mendix, Power Apps | Java/Spring, Python, React, Go |

### LCNC 도입 시의 트레이드오프 분석

| 획득 가치 (Pros) | 수반되는 위험 및 비용 (Cons) |
|---|---|
| - 개발 기간 70% 이상 단축 및 생산성 극대화<br>- 비즈니스 현업 부서의 주도적 DX 역량 확보<br>- 초기 프로토타이핑 및 MVP 검증 비용 절감 | - 플랫폼 벤더 종속(Vendor Lock-in) 및 라이선스 비용 증가<br>- 비인가 앱 양산으로 인한 **섀도우 IT** 및 보안 취약점<br>- 대용량 배치 및 마이크로초 단위 고성능 처리 한계 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 현업 부서가 IT 보안 검토 없이 고객 개인정보를 포함한 앱을 무단 배포하는 섀도우 IT 위험 | 사내 LCNC 전용 마켓플레이스 등록을 의무화하고 중앙 IT 부서의 배포 승인 워크플로우(Quality Gate) 강제 |
| 플랫폼 벤더의 서비스 중단 또는 라이선스 정책 급변 시 타 플랫폼으로의 마이그레이션 불가 | 소스코드(Java, C# 등) 추출(Code Export)이 지원되는 플랫폼을 선정하고 표준 REST API 연계 원칙 준수 |
| 복잡한 데이터베이스 조인 및 대규모 동시 접속 발생 시 심각한 응답 지연 발생 | OLTP 핵심 고성능 트랜잭션은 프로코드로 구축하고, LCNC는 조회/신청 등 프론트엔드 워크플로우로 역할 분담 |

## Ⅵ. 제언

현업의 자율성과 IT 부서의 통제력을 조화시키기 위해 'LCNC CoE(Center of Excellence)' 조직을 구축하고, 데이터 거버넌스 및 RBAC 인가 정책을 결합한 하이브리드 개발 문화 확립 권장.

```text
[엔터프라이즈 LCNC 거버넌스 운영 체계]
  현업 시민개발자 (앱 기획/조립) ──► IT CoE 조직 (보안/데이터 아키텍처 검토) ──► 승인 후 엔터프라이즈 배포
```

| 관리 영역 | 통제 없는 방치 상태 (섀도우 IT) | CoE 기반 엔터프라이즈 거버넌스 |
|---|---|---|
| 데이터 보안 | 무단 공공 클라우드 저장 및 유출 위험 | 엔터프라이즈 사내망 격리 및 역할 기반 접근 제어(RBAC) |
| 품질 관리 | 테스트 부재로 인한 업무 오작동 | 표준 템플릿 제공 및 스테이징 환경 사전 검증 의무화 |
