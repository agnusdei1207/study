## 연관 키워드

- 로우코드·노코드(LCNC, Low-Code/No-Code), 시민 개발자(Citizen Developer), 드래그 앤 드롭(Drag-and-Drop)
- 비주얼 개발 환경, 워크플로우 엔진(BPMN, Business Process Model and Notation), API(Application Programming Interface)
- 섀도우 IT(Shadow IT), 벤더 락인(Vendor Lock-in), 2-스피드 IT(Two-Speed IT), CoE(Center of Excellence)

## Ⅰ. 로우코드·노코드(LCNC)의 개요

- 핵심 요약 : 시각적 개발 환경으로 개발 장벽을 낮추는 노코드와 전문 개발 생산성을 높이는 로우코드의 결합 방식.
- 개념 : 시각적 모델링과 설정으로 애플리케이션을 만드는 **로우코드·노코드** (LCNC, Low-Code/No-Code) 방식은 다음 두 갈래로 나뉜다.
  1. 노코드(No-Code) : 프로그래밍 지식이 없는 현업 실무자가 드래그 앤 드롭 인터페이스와 GUI(Graphical User Interface) 설정만으로 앱을 구축하는 방식. 이때 현업 실무자를 **시민 개발자** (Citizen Developer)라 부른다.
  2. 로우코드(Low-Code) : 전문 개발자가 UI(User Interface)와 기본 로직을 자동 생성받고, 복잡한 비즈니스 규칙과 외부 연동에 한해서만 직접 코드를 작성하는 방식.
- 배경 및 필요성 : 소프트웨어 전문 개발 인력이 부족한 상황에서 현업의 신규 요구를 빠르게 반영해야 하는 필요가 커짐.
- 대표 솔루션 : Microsoft Power Apps, OutSystems, Mendix, AppSheet 등.

## Ⅱ. 로우코드·노코드(LCNC)의 특징 및 장점

- 핵심 요약 : 비주얼 빌더, 워크플로우 엔진, 커넥터, 자동 배포를 묶은 기능 추상화가 개발 기간 단축으로 이어지는 구조.

1. 드래그 앤 드롭 UI 빌더 : 화면을 부품 배치로 구성 → 화면 개발 기간 단축.
2. **워크플로우 엔진** (BPMN, Business Process Model and Notation, 업무 절차를 표준 기호로 모델링하는 표기법 기반의 실행 엔진) : 업무 흐름을 도식으로 정의 → 현업과 개발자 간 요구 해석 차이 감소.
3. 데이터 모델링 자동화 : 테이블 구조를 시각적으로 정의하면 저장소가 생성됨 → 초기 데이터 설계 부담 완화.
4. 사전 구축된 커넥터 : 외부 시스템과 API(Application Programming Interface, 응용 프로그램 간 호출 규약) 연동을 기본 제공 → 연동 개발 공수 절감.
5. 자동 배포 : 웹과 모바일 화면을 관리형 클라우드 런타임에 한 번에 배포 → 운영 준비 기간 단축.

## Ⅲ. 로우코드·노코드(LCNC)의 구조 (흐름)

- 핵심 요약 : 비주얼 개발 환경에서 만든 앱이 관리형 런타임으로 배포되는 흐름과, 코어 시스템과 API로 연결되는 2계층 구조.

```text
[ 시민 개발자 (No-Code) ]
[ 전문 개발자 (Low-Code) ]
      ↓
[ LCNC 비주얼 개발 환경 ]
      ↓ 원클릭 자동 배포
[ 관리형 클라우드 런타임 ]
```

- **2-스피드 IT** (Two-Speed IT, 안정성이 중요한 코어와 변화가 잦은 현업 영역을 나누어 운영하는 IT 방식) 하이브리드 구조.

```text
[ 코어 시스템 : 전문 개발팀 ]
 - 고성능 트랜잭션과 분산 인프라
      ↓ API 연계
[ LCNC 플랫폼 : 현업 ]
 - 화면과 업무 흐름 오케스트레이션
```

## Ⅳ. 전통적 개발, 로우코드, 노코드의 비교

- 핵심 요약 : 주요 사용자, 개발 방식, 유연성, 종속성이 단계적으로 달라지는 3개 개발 방식.

| 비교 축 | 전통적 개발 (High-Code) | 로우코드 (Low-Code) | 노코드 (No-Code) |
| --- | --- | --- | --- |
| 주요 사용자 | 전문 소프트웨어 엔지니어 | 전문 개발자와 IT(Information Technology) 실무자 | 현업 실무자 (시민 개발자) |
| 개발 방식 | IDE(Integrated Development Environment)에서 텍스트 코딩 | 시각적 모델링과 커스텀 코드 확장 | 드래그 앤 드롭 설정 중심 |
| 개발 기간 | 긴 개발 주기 | 짧은 개발 주기 | 가장 짧은 개발 주기 |
| 아키텍처 유연성 | 제약 없는 자유도 | 플랫폼이 허용하는 범위에서 확장 | 플랫폼 템플릿에 제한 |
| **벤더 락인** (Vendor Lock-in) | 표준 기술 채택 시 낮음 | 플랫폼 런타임 종속이 높음 | 플랫폼 종속이 가장 높음 |

- 선택 기준 : 업무의 변경 빈도, 필요한 확장성, 데이터 이전 가능성을 기준으로 방식을 고른다.

## Ⅴ. 로우코드·노코드(LCNC)의 장점과 한계

- 핵심 요약 : 개발 기간 단축과 인력 보완의 장점과 벤더 종속, 섀도우 IT, 확장성 한계가 공존.

- 장점
  1. 개발 기간 단축으로 출시 속도(Time-to-Market)를 높임.
  2. 개발 인력 부족을 보완하고 현업 주도의 업무 자동화를 가능하게 함.
  3. 반복 코드 제거로 전문 개발자의 생산성을 높임.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **섀도우 IT** (Shadow IT) 발생 | 현업이 IT 승인 없이 앱을 만들어 개인정보 유출과 인증 미비 우려 | 전사 거버넌스 체계, 배포 전 보안 점검 자동화, SSO(Single Sign-On) 연동과 승인 절차 의무화 | 미승인 앱 수, 보안 점검 통과율 |
| 플랫폼 종속 | 독자 메타데이터와 런타임에 묶여 이전이 어렵고 라이선스 비용에 취약 | 표준 언어와 컨테이너 이미지 내보내기를 지원하는 플랫폼 선별, 핵심 데이터의 표준 RDB(Relational Database) 분리 저장 | 이전 소요 공수, 종속 기능 비율 |
| 확장성 한계 | 고난도 알고리즘과 대규모 동시 요청에서 빌더만으로는 병목 발생 | 코어 도메인은 전문 개발자가 API로 구현하고, LCNC는 화면과 워크플로우에만 활용 | 응답 지연, 동시 처리량 |

## Ⅵ. 엔터프라이즈 도입에 대한 기술사적 제언

- 핵심 요약 : 중앙 거버넌스 조직과 2-스피드 IT 역할 분담을 함께 세워야 도입이 지속 가능함.
- 기업은 **CoE** (Center of Excellence, 플랫폼 표준과 승인 기준을 중앙에서 관리하는 전담 조직)를 두어 데이터 접근 권한과 배포 전 보안 검수를 한곳에서 통제하는 것이 바람직하다. 현업이 자유롭게 앱을 만들되 보안 기준은 중앙이 쥐는 구조여야 섀도우 IT가 억제된다.
- 핵심 코어 트랜잭션과 고성능 분산 인프라는 전문 개발팀이 맡고, 자주 바뀌는 업무 자동화와 이벤트 화면은 현업이 LCNC로 직접 만드는 역할 분담이 현실적이다. 이 분담이 있어야 빠른 변화와 시스템 안정성이 함께 확보된다.

## Ⅶ. 결론

- 핵심 요약 : LCNC는 개발의 문턱을 낮추는 생산성 수단이지만 거버넌스와 하이브리드 설계가 전제되어야 하는 기술.
- 시사점 : CoE 중앙 통제, 개방형 플랫폼 선별, 전문 개발과의 역할 분리가 도입 성패를 가름.
