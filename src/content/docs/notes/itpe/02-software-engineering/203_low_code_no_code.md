## Ⅰ. 로우코드·노코드(LCNC)의 개요

- 개념 : 로우코드·노코드(LCNC, Low-Code/No-Code)의 두 방식은 다음과 같다.
  - **노코드** (No-Code) : 프로그래밍 언어에 대한 지식이 전혀 없는 현업 실무자(시민 개발자, Citizen Developer)가 시각적인 드래그 앤 드롭(Drag-and-Drop) 인터페이스와 GUI(Graphical User Interface) 설정만으로 애플리케이션을 즉시 구축하는 플랫폼.
  - **로우코드** (Low-Code) : 전문 개발자가 복잡한 보일러플레이트 코딩 없이 기본 로직과 UI(User Interface)를 시각적으로 자동 생성하고, 복잡한 비즈니스 규칙과 외부 연동에 한해서만 최소한의 핸드 코딩(Hand-coding)을 결합하는 생산성 극대화 개발 플랫폼.
- 배경 및 필요성 : 전 세계적인 소프트웨어 전문 개발 인력 부족 해소, 비즈니스 현업의 신규 요구사항 출시 속도(Time-to-Market) 획기적 단축.
- 대표 솔루션 : **Microsoft Power Apps** / **OutSystems** / **Mendix** / **AppSheet**

## Ⅱ. LCNC 플랫폼의 아키텍처 및 작업 흐름

```text
   [ 시민 개발자 (No-Code) ]     [ 전문 개발자 (Low-Code) ]
              │                               │
              ▼                               ▼
   ┌────────────────────────────────────────────────────────┐
   │ [ LCNC 비주얼 개발 환경 ]                              │
   │  - 드래그 앤 드롭 UI 빌더 (Visual Form Builder)         │
   │  - 비주얼 비즈니스 로직 및 워크플로우 엔진 (BPMN)      │
   │  - 원클릭 데이터 모델링 (Dataverse / RDB 자동 생성)     │
   │  - 사전 구축된 커넥터 (Open API, SAP, Salesforce 연동) │
   └──────────────────────────┬─────────────────────────────┘
                              │
                              ▼ (원클릭 자동 배포)
   [ 완전 관리형 클라우드 런타임 (웹, iOS, Android 동시 서빙) ]
```

## Ⅲ. 전통적 코딩, 로우코드, 노코드의 비교

| 비교 항목 | 전통적 개발 (High-Code) | 로우코드 (Low-Code) | 노코드 (No-Code) |
|---|---|---|---|
| 주요 사용자 | 숙련된 전문 소프트웨어 엔지니어 | 전문 개발자 및 IT(Information Technology) 실무자 | 현업 비즈니스 실무자 (시민 개발자) |
| 개발 방식 | IDE(Integrated Development Environment)에서 수작업 텍스트 코딩 | 시각적 모델링 + 커스텀 코드 확장 | 순수 100% 드래그 앤 드롭 비주얼 설정 |
| 개발 속도 | 수개월 소요 (느림) | 수일 ~ 수주 (매우 빠름) | 수시간 ~ 수일 (가장 빠름) |
| 아키텍처 유연성 | 완벽한 자유도 (어떤 복잡 로직도 구현) | 플랫폼이 허용하는 범위 내에서 확장 가능 | 극도로 제한적 (플랫폼 템플릿에 종속) |
| 벤더 락인 (Lock-in) | 오픈소스 표준 채택 시 락인 없음 | 플랫폼 전용 런타임 종속성 높음 | 완벽한 플랫폼 종속 (이전 불가) |

## Ⅳ. 로우코드·노코드(LCNC)의 주요 한계점 및 해결 방안

- 특정 상용 플랫폼에의 강력한 종속(Vendor Lock-in) :
  - 한계점 : LCNC 플랫폼 고유의 메타데이터와 독자적 런타임에 결속되어, 타 플랫폼으로의 마이그레이션이 불가능하고 라이선스 비용 인상에 취약.
  - 해결 방안 : 표준 언어(Java, JS) 및 컨테이너(Docker) 이미지 추출을 지원하는 개방형 플랫폼 선별, 핵심 데이터베이스는 표준 RDB에 독립 격리 저장.
- **섀도우 IT** (Shadow IT) 발생 및 보안·컴플라이언스 통제 불능 :
  - 한계점 : 현업 부서가 IT 부서의 승인 없이 독자적으로 앱을 개발하여 개인정보 유출, 인증 미비, 사내 데이터 거버넌스 위반 등 보안 사각지대 양산.
  - 해결 방안 : 전사 LCNC 거버넌스 프레임워크 수립, 배포 전 보안 취약점 점검 자동화, 사내 SSO(Single Sign-On) 연동 및 **시민 개발자** (Citizen Developer) 승인 프로세스 의무화.
- 복잡한 비즈니스 로직 및 대규모 트래픽 처리 시 확장성 한계 :
  - 한계점 : 시각적 드래그 앤 드롭 빌더만으로는 고난도 알고리즘 구현이 불가능하며, 대규모 동시 요청 시 런타임 성능 병목 발생.
  - 해결 방안 : 복잡한 계산 및 코어 도메인은 전문 개발자가 Pro-Code(REST(Representational State Transfer) API(Application Programming Interface))로 개발하고, LCNC는 UI/워크플로우 오케스트레이션에만 활용하는 2계층 하이브리드 아키텍처 적용.

## Ⅴ. 엔터프라이즈 도입을 위한 기술사적 제언

- 섀도우 IT(Shadow IT) 방지를 위한 전사 거버넌스 체계 수립 : 현업 부서가 IT 부서의 통제 없이 제각각 LCNC 앱을 만들어 사내에 배포하면 보안 취약점, 개인정보 유출, 데이터 사일로가 심화되므로, 사내 LCNC **CoE** (Center of Excellence) 조직을 구축하여 데이터 접근 권한과 보안 검수를 중앙 통제해야 함.
- LCNC와 전문 개발팀의 **2-스피드 IT** (Two-Speed IT) 협력 모델 구축 : 핵심 코어 트랜잭션과 고성능 분산 인프라는 전문 개발팀이 전통적인 고품질 코딩(High-Code)으로 구축하고, 변경이 빈번한 사내 업무 자동화나 고객 설문 이벤트 페이지는 LCNC로 현업이 자체 개발하도록 역할을 구조적으로 분담.
