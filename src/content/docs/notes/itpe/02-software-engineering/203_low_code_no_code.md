## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 개발 방법론 → **로우코드·노코드(LCNC)**

## 30초 인출

- 본질: 로우코드·노코드는 시각적 화면 구성과 미리 만들어진 구성요소로 코딩을 최소화하거나 없이 애플리케이션을 만드는 개발 플랫폼
- 메커니즘: 개발자가 화면·데이터·업무 흐름을 끌어다 놓아 구성하면 플랫폼이 실행 코드를 만들고 복잡한 부분은 로우코드에서 코드로 보완
- 통찰: 현업이 통제 없이 앱을 만들면 보안·데이터·유지보수 문제가 생기므로 플랫폼 표준과 승인 기준을 정하고 규모가 커진 앱은 전문 조직으로 이관

<details>
<summary>핵심 용어</summary>

- **로우코드(Low-Code)** : 시각적 개발과 최소한의 코딩으로 앱을 만드는 방식
- **노코드(No-Code)** : 코딩 없이 시각적 구성만으로 앱을 만드는 방식
- **시민 개발자(Citizen Developer)** : 비전문가이면서 승인된 플랫폼으로 앱을 만드는 현업 사용자
- **섀도 IT(Shadow IT)** : IT 부서의 승인·통제 없이 부서가 도입·개발한 시스템
- **커넥터(Connector)** : 기존 시스템·데이터와 연결하는 구성요소
- **플랫폼 종속(Vendor Lock-in)** : 특정 플랫폼에 묶여 이전이 어려운 상태

</details>

## 2~4교시 25점 답안

## Ⅰ. 로우코드·노코드의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **로우코드·노코드** 는 시각적 구성으로 코딩을 최소화하거나 없이 앱을 만드는 개발 플랫폼 |
| 목적 | 개발 속도 향상과 현업 참여 확대 |

## Ⅱ. 로우코드 플랫폼의 주요 특징

| 특징 | 의미 |
|---|---|
| 시각적 개발 | 화면·흐름을 끌어다 놓아 구성 |
| 재사용 구성요소 | 템플릿·커넥터 활용 |
| 코드 보완 | 필요한 부분만 직접 코딩 |
| 빠른 배포 | 플랫폼 기반의 자동 배포 |

## Ⅲ. 구성

```text
시각적 편집기 ─▶ 플랫폼(실행 코드 생성) ─▶ 배포
     │                  ▲
   커넥터 ── 기존 시스템·데이터 ─┘   (복잡한 부분은 코드로 보완)
```

## Ⅳ. 노코드와 로우코드의 비교

| 구분 | 노코드 | 로우코드 |
|---|---|---|
| 코딩 | 없음 | 일부 필요 |
| 사용자 | 현업(비전문가) | 개발자·현업 |
| 유연성 | 제한 | 높음 |
| 적합 대상 | 단순 업무 앱·양식 | 업무 시스템·연동이 있는 앱 |

## Ⅴ. 적용 시 한계와 방안

| 한계 | 방안 |
|---|---|
| 통제 없는 개발로 보안·데이터 관리 문제 | 플랫폼 표준과 승인 기준 |
| 특정 플랫폼 종속 | 데이터 이전 방안 사전 확인 |
| 복잡한 요구에서 성능·기능 한계 | 규모가 커진 앱은 전문 개발로 이관 |
| 유지보수 책임 불명확 | 앱별 소유자와 운영 책임 지정 |

## Ⅵ. 제언

플랫폼 표준과 승인 기준을 정하고, 이용 범위와 데이터 민감도가 기준을 넘는 앱은 전문 조직으로 이관

```text
앱 이용 범위·데이터 민감도 판정
    ├─ 기준 이내 → 현업 운영
    └─ 초과 → 전문 조직 이관·보안 점검
```

| 구분 | 통제 없는 개방 | 제언: 표준·이관 기준 |
|---|---|---|
| 보안 | 위험 | 점검 |
| 유지보수 | 불명확 | 책임 지정 |
