소프트웨어 공학 → 웹 기술 → **서비스 워커(Service Worker)**

## 30초 인출

- 본질: 서비스 워커는 웹 페이지와 네트워크 사이에서 요청을 가로채는 브라우저 백그라운드 스크립트로 오프라인 동작과 캐시 제어를 가능하게 함
- 메커니즘: 페이지가 등록한 서비스 워커가 설치·활성화된 뒤 fetch 이벤트로 요청을 받아 캐시 전략에 따라 캐시나 네트워크에서 응답
- 통찰: 캐시된 옛 파일이 계속 제공되면 사용자가 갱신을 못 받으므로 버전 이름을 붙인 캐시를 쓰고 활성화 단계에서 이전 캐시를 삭제하며 갱신 시점을 명확히 관리

<details>
<summary>핵심 용어</summary>

- **서비스 워커(Service Worker)** : 페이지와 별도로 백그라운드에서 실행되며 네트워크 요청을 가로채는 브라우저 스크립트
- **캐시 스토리지(Cache Storage)** : 서비스 워커가 요청·응답 쌍을 저장하는 저장소
- **fetch 이벤트** : 페이지의 네트워크 요청이 서비스 워커로 전달되는 이벤트
- **PWA(Progressive Web App)** : 오프라인·설치·푸시를 지원하는 웹 애플리케이션
- **앱 셸(App Shell)** : UI 골격을 미리 캐시해 즉시 표시하고 데이터는 따로 불러오는 구조
- **웹 워커(Web Worker)** : 화면 처리와 분리해 계산을 수행하는 스크립트. 네트워크 가로채기는 하지 않음

</details>

## 2~4교시 25점 답안

## Ⅰ. 서비스 워커의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **서비스 워커** 는 웹 페이지와 네트워크 사이에서 요청을 가로채는 브라우저의 백그라운드 스크립트 |
| 목적 | 오프라인 동작과 캐시 기반의 빠른 응답 |

## Ⅱ. 일반 스크립트와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 요청 가로채기 | 페이지의 네트워크 요청을 대신 처리 |
| 별도 실행 | 페이지를 닫아도 이벤트 처리 가능 |
| HTTPS 필요 | 보안 컨텍스트에서만 동작 |
| 이벤트 기반 | 설치·활성화·fetch 이벤트로 동작 |

## Ⅲ. 구조와 동작 방식

### 페이지·서비스 워커·네트워크의 관계

```text
┌────────────────────── 브라우저 ──────────────────────┐
│  [웹 페이지]                                           │
│      │ fetch 요청                                      │
│      ▼                                                 │
│  [서비스 워커] ──── 캐시 조회 ───→ [캐시 스토리지]      │
│      │                                                 │
└──────┼─────────────────────────────────────────────────┘
       │ 캐시에 없거나 최신 필요 시
       ▼
   [ 네트워크·서버 ]
```

### 생명주기

```text
등록(register) ──→ 설치(install: 필요한 파일 사전 캐시)
                        │
                        ▼
                 대기(waiting) ──→ 활성화(activate: 이전 캐시 정리) ──→ 요청 처리(fetch)
```

## Ⅳ. 캐시 전략과 관련 기술의 비교

### 캐시 전략

| 전략 | 동작 | 적합 대상 |
|---|---|---|
| 캐시 우선 | 캐시에 있으면 사용, 없으면 네트워크 | 정적 자원(CSS·JS·이미지) |
| 네트워크 우선 | 네트워크 시도 후 실패 시 캐시 | 최신성이 중요한 데이터 |
| 오래된 것 사용 후 갱신 | 캐시 응답 후 백그라운드에서 갱신 | 갱신이 잦지 않으나 최신 반영 필요한 자원 |

### 유사 기술과의 비교

| 구분 | 서비스 워커 | 웹 워커 | HTTP 캐시 |
|---|---|---|---|
| 역할 | 요청 가로채기·캐시 제어 | 화면과 분리한 계산 | 브라우저의 기본 캐시 |
| 오프라인 | 가능 | 해당 없음 | 제한적 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 옛 캐시가 남아 갱신 미반영 | 버전 이름 캐시 사용, 활성화 시 이전 캐시 삭제 |
| 잘못된 서비스 워커가 사이트 전체에 영향 | 단계적 배포와 해제 수단 확보 |
| 동적 데이터의 오래된 응답 제공 | 데이터 성격별 캐시 전략 선택 |

## Ⅵ. 제언

캐시에 버전 이름을 붙이고 활성화 단계에서 이전 버전 캐시를 삭제하며, 정적 자원은 캐시 우선·동적 데이터는 네트워크 우선으로 구분

### 갱신 관리

```text
새 서비스 워커 배포 (캐시 이름 v2)
    ↓ 설치·대기
기존 페이지가 모두 닫히면 활성화
    ↓
활성화에서 v1 캐시 삭제 → v2로 응답
```

### 선택 근거: 단일 캐시 전략과의 비교

| 구분 | 모든 자원 캐시 우선 | 제언: 자원별 전략·버전 캐시 |
|---|---|---|
| 데이터 최신성 | 오래된 응답 | 성격별 보장 |
| 갱신 반영 | 지연 | 활성화 시 정리 |
| 오프라인 | 가능 | 가능 |
