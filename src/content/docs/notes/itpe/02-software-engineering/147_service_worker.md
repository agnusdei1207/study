## 핵심 그림
```text
+-------------------------------------------------------------------------+
|                  서비스 워커(Service Worker) 네트워크 프록시 아키텍처   |
+-------------------------------------------------------------------------+
|                                                                         |
|  [ 브라우저 웹 페이지 ]                                                 |
|         │ (fetch 요청: 이미지, CSS, API 데이터)                         |
|         v                                                               |
|  +--------------------------------------------------------------------+ |
|  | [ 서비스 워커 (Service Worker) ] (백그라운드 독립 스레드)          | |
|  |   - 이벤트 리스너: fetch, push, sync                               | |
|  |   - 캐싱 전략: Cache First, Network First, Stale-While-Revalidate | |
|  +──────┬─────────────────────────────────────────────────────────────+ |
|         │                                          │                    |
|         v (오프라인 / 캐시 적중 시)                v (네트워크 연결 시) |
|  [ Cache Storage / IndexedDB ]              [ 원격 웹 서버 / API ]      |
|  (브라우저 로컬 저장소)                     (Cloud / Origin Server)     |
|                                                                         |

+-------------------------------------------------------------------------+
```

## 핵심 용어
- Cache First(캐시 우선 전략): 네트워크 요청 시 먼저 로컬 Cache Storage를 확인하여 캐시가 존재하면 즉시 반환하고, 없을 때만 네트워크를 호출하여 성능을 극대화하는 정적 자산 캐싱 기법
- Stale-While-Revalidate: 캐시된 오래된 데이터(Stale)를 화면에 즉시 반환하여 렌더링 속도를 높이면서, 백그라운드에서 네트워크 요청을 날려 캐시를 최신화(Revalidate)하는 하이브리드 캐싱 기법

## 핵심 통찰
- 서비스 워커는 일반 자바스크립트와 완전히 다른 독립된 워커 스레드에서 실행되므로, 메인 스레드의 DOM 객체에 직접 접근할 수 없으며 `postMessage` API를 통해 페이지와 통신해야 함
- 중간자 공격(Man-in-the-Middle)에 악용될 경우 모든 네트워크 트래픽과 사용자 민감 정보를 가로챌 수 있는 막강한 권한을 가지므로, `localhost` 개발 환경을 제외하고는 오직 HTTPS 프로토콜에서만 동작하도록 보안이 강제됨
- 실무에서 서비스 워커 구현 시 가장 까다로운 점은 "새로운 코드를 배포했는데 사용자의 브라우저에 구버전 서비스 워커가 캐시를 쥐고 있어 화면이 갱신되지 않는 고착 현상"이며, `skipWaiting()`과 버전별 캐시 키 관리가 필수적임

## 이웃 토픽과 구분
- 서비스 워커(Service Worker) vs 웹 워커(Web Worker): 웹 워커 = 메인 UI 스레드를 차단하지 않고 대규모 수학 연산이나 이미지 처리를 돌리는 순수 연산용 / 서비스 워커 = 네트워크 요청을 가로채 캐싱하고 푸시 알림과 오프라인을 지원하는 프록시용

## 문제·원인·대책
- 적용 상황: 현장 점검용 모바일 웹 앱의 지하/엘리베이터 음영 지역 오프라인 지원
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 지하 현장에서 통신 단절 시 점검 양식이 열리지 않고 브라우저 공룡 화면 에러 노출 | 웹 브라우저가 정적 자산 및 오프라인 상태 처리를 브라우저 캐시에만 의존 | 서비스 워커 기반 Cache Storage 정적 자산 캐싱 및 오프라인 대체 페이지 제공 | 완전 오프라인 환경에서도 앱 100% 실행 보장 |
| 서버에 신규 자바스크립트 버전을 배포했으나 사용자들이 여전히 버그가 있는 구버전 사용 | 서비스 워커가 구버전 정적 자산을 영구 캐시하고 새 워커가 대기(Waiting) 상태에 머묾 | 활성화 단계에서 구버전 캐시 삭제 및 `self.skipWaiting()` 호출 강제화 | 신규 배포 즉시 클라이언트 갱신 완결 |
