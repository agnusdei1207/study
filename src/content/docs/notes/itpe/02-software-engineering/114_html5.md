## 연관 키워드

- HTML5, 시맨틱 요소, 멀티미디어, Canvas, Web Storage, WebSocket, 웹 표준, 기능 탐지

## Ⅰ. HTML5의 개요

- 핵심 요약 : HTML5는 문서의 의미 구조와 멀티미디어·애플리케이션 기능을 플러그인 없이 브라우저 표준으로 제공하는 HTML 세대.
- 개념 : 웹 문서의 구조와 의미를 마크업으로 기술하고 미디어·그래픽·저장·통신 기능을 표준 요소와 API로 확장한 HTML 표준의 한 세대 (**HTML5**, HyperText Markup Language 5).
- 배경 및 필요성 : 이전 세대 웹은 표 기반 배치와 외부 플러그인 의존으로 문서 의미·보안·이식성이 저하되어 개방형 웹 플랫폼의 표준 필요.
- 주요 목적 : 브라우저·기기에 관계없이 호환되는 웹 표준 문서와 웹 애플리케이션 기반 구축.

## Ⅱ. HTML5의 특징 및 장점

- 핵심 요약 : 시맨틱 구조·내장 미디어·표준 API가 플러그인 의존 축소와 접근성·상호 운용성 향상으로 연결.

1. **시맨틱 요소** (Semantic Elements) : header·nav·main·article·section·aside·footer로 영역 역할 명시 → 기계 판독·검색·접근성 향상.
2. 멀티미디어 내장 : audio·video 요소로 브라우저 자체 재생 → 플러그인 설치 부담과 보안 취약점 감소.
3. 그래픽 표준 : **Canvas** (스크립트로 비트맵을 직접 그리는 요소)와 SVG 벡터 그래픽 → 게임·차트 등 시각화의 표준 구현.
4. 클라이언트 기능 API : **웹 스토리지** (Web Storage)의 키-값 저장, **웹 워커** (Web Worker)의 백그라운드 처리, 지리 위치 제공 → 설치형 앱 수준의 기능 확보.
5. 통신 표준 : **웹 소켓** (WebSocket)으로 서버와의 양방향 연결 유지 → 폴링 대비 실시간성·통신 효율 향상.

## Ⅲ. HTML5의 구조 (흐름)

- 핵심 요약 : 시맨틱 마크업이 문서 골격을 정의하고 브라우저의 파싱·렌더링 과정에서 구조 정보가 접근성과 화면으로 연결.

```text
[ 시맨틱 문서 구조 ]

header - 제목·로고
nav - 주 메뉴
   ↓
main - 본문 영역
  article · section · aside
   ↓
footer - 부가 정보
```

```text
HTML5 문서 수신
   ↓ 파싱
DOM 트리 생성 - 시맨틱 해석
   ↓ 구조 정보 반영
접근성 트리·CSS·스크립트 결합
   ↓
화면 렌더링·상호작용
```

- 웹 스토리지는 localStorage(영속 저장)와 sessionStorage(세션 범위)로 구분되며, 미디어는 플러그인 호출 없이 브라우저 디코더로 재생.

## Ⅳ. HTML5와 구판 HTML의 비교

- 핵심 요약 : 구판 HTML의 표 레이아웃·플러그인 의존 방식에서 의미 구조·표준 API 중심으로 전환.

| 비교 축 | 구판 HTML (HTML 4.01 시대) | HTML5 |
| --- | --- | --- |
| 레이아웃 | table·div 중첩 배치 | 시맨틱 요소 기반 구조 |
| 멀티미디어 | 외부 플러그인 재생 | audio·video 내장 |
| 그래픽 | 이미지·플러그인 | Canvas·SVG |
| 클라이언트 저장 | 쿠키 위주 | Web Storage 등 표준 API |
| 실시간 통신 | 폴링·플러그인 | WebSocket 양방향 |
| 표준 관리 | 버전별 권고안 | WHATWG Living Standard 지속 갱신 |

## Ⅴ. HTML5의 한계와 방안

- 핵심 요약 : 브라우저 편차·시맨틱 오용·저장소 보안·그래픽 접근성을 표준 확인과 설계 규칙으로 통제 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 브라우저별 구현 차이 | 명세 반영 시점·정책 상이 | **기능 탐지** (feature detection)·폴백 제공 | 호환성 결함 건수 |
| 시맨틱 오용 | 화면 배치 기준의 요소 선택 | 의미 기준 마크업 가이드·검토 | 시맨틱 오용 건수 |
| 저장소 정보 노출 | 스크립트 삽입(XSS, Cross-Site Scripting) 시 웹 스토리지 접근 가능 | 민감 정보 미저장·입출력 검증 | 저장소 위반 건수 |
| Canvas 접근성·자원 | 픽셀 기반의 의미 전달 곤란·메모리 부담 | 대체 콘텐츠 제공·적정 해상도 관리 | 접근성 결함 건수 |

## Ⅵ. HTML5에 대한 기술사적 제언

- 핵심 요약 : 웹 표준 거버넌스로 명세 확인·접근성 지침 연계·호환성 검증을 개발 절차에 내재화 필요.
- 개발 조직은 WHATWG HTML 표준과 API 명세를 근거 문서로 지정하고, 웹 콘텐츠 접근성 지침(**WCAG**, Web Content Accessibility Guidelines)을 수용 기준에 반영.
- 품질 조직은 주요 브라우저·보조 기기 조합의 호환성 시험을 릴리스 게이트에 포함해 웹 표준 준수를 검증.

## Ⅶ. 결론

- 핵심 요약 : HTML5는 웹 문서의 의미 구조와 브라우저 내장 기능을 표준으로 확장한 개방형 웹 기반.
- 표준 요소의 의미에 맞는 사용과 접근성·보안 설계가 지속 가능한 웹 애플리케이션의 조건.
