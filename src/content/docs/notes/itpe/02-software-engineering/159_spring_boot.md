현재 위치: 소프트웨어 공학 → 애플리케이션 프레임워크 → **스프링 부트**

## 30초 인출

- 본질: **스프링 부트** 는 스프링 애플리케이션의 의존성·설정·실행을 간편하게 구성하는 도구
- 메커니즘: Starter 의존성 선택 → 환경에 맞는 조건부 자동 설정 → 내장 서버와 애플리케이션 실행
- 통찰: 한계: 자동 설정을 기본값 그대로 신뢰하면 의도하지 않은 Bean·서버 설정이 적용될 수 있음 → 방안: 조건부 적용 결과를 확인하고 필요한 부분만 재정의

<details>
<summary>핵심 용어</summary>

- **Spring Boot(스프링 부트)** : 스프링 애플리케이션의 의존성 관리·자동 설정·독립 실행을 지원하는 프레임워크
- **Starter** : 특정 기능에 필요한 의존성을 함께 제공하는 Spring Boot 의존성 묶음
- **Auto-configuration(자동 설정)** : 클래스 경로·설정값·사용자 정의 구성에 따라 필요한 Bean을 조건부로 등록하는 기능
- **내장 웹 서버(Embedded Web Server)** : 애플리케이션과 함께 실행되는 웹 서버 구성
- **Actuator** : 애플리케이션의 상태·측정값 등 운영 정보를 확인하는 Spring Boot 기능

</details>

## 2~4교시 25점 답안

## Ⅰ. 스프링 부트의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **Spring Boot** 는 스프링 애플리케이션의 의존성·설정·실행을 간편하게 구성하는 프레임워크 |
| 목적 | 반복 설정의 감소와 애플리케이션 실행·배포 준비의 단순화 |

## Ⅱ. 의존성 묶음과 조건부 설정의 특징

| 특징 | 적용 의미 |
|---|---|
| Starter 의존성 | 기능별 라이브러리 묶음으로 반복 설정 감소 |
| 조건부 자동 설정 | 클래스 경로·설정값·사용자 Bean에 따라 기본 구성을 선택 |
| 독립 실행·운영 확장 | 내장 서버로 실행하고 Actuator 의존성 추가 시 상태·지표 확인 |

## Ⅲ. Starter 선택과 조건부 Bean 등록 프로세스

### 의존성 선택에서 실행까지

```text
Starter 선택 → 라이브러리·클래스 경로 구성
    ↓ 설정값·기존 사용자 Bean과 조건 비교
조건 충족 → 기본 Bean 등록 / 불충족 → 기본 등록 건너뜀
    ↓ 필요한 사용자 정의 설정 반영
내장 서버와 애플리케이션 실행
```

## Ⅳ. Actuator 상태·측정값·관리 엔드포인트 비교

### 운영 기능과 노출 통제

| 운영 요소 | 제공 정보 | 확인할 점 |
|---|---|---|
| **Actuator** 상태 | 애플리케이션 상태·준비 여부 | 상태 점검의 대상과 의미 |
| 측정값 | 요청·JVM 등 운영 지표 | 필요한 메트릭과 수집 범위 |
| 관리 엔드포인트 | 운영 조회·관리 기능 | 인증·접근 경로·민감 정보 노출 |

**Actuator** 는 별도 의존성을 추가해 사용하는 기능이며, 모든 관리 정보를 기본으로 외부에 공개한다는 뜻은 아닌 구분

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 자동 설정 결과를 모르고 기능 충돌 | 조건 평가 내용과 적용 Bean을 확인해 의도한 구성인지 검증 |
| 의존성·설정 판본 불일치 | 프로젝트에 맞는 의존성 관리와 업그레이드 기동·기능 시험 수행 |
| 관리 엔드포인트의 과다 노출 | 필요한 항목만 공개하고 접근 권한 제한 |

## Ⅵ. 제언

배포 전 설정 결과와 노출 엔드포인트를 확인하는 점검표를 만들고, 환경별 차이를 기동 시험으로 검증.
