## 연관 키워드
- 선형 구조, 배열, 연결 리스트, 스택, 큐
- 덱, 시간복잡도, 캐시 지역성

## Ⅰ. 선형 구조의 개요

- 핵심 요약 : 선형 구조는 원소가 하나의 논리적 순서로 앞·뒤 연결되어 순차 처리에 적합한 자료구조.
- 개념 : 각 원소가 하나의 선행 원소와 하나의 후행 원소를 갖는 단일 순서로 배열되는 자료구조가 **선형 구조** (Linear Structure)임.
- 배경 및 필요성 : 순차 데이터 처리·버퍼링·작업 대기 같은 요구마다 접근·삽입·삭제 비용 특성이 달라 용도에 맞는 구조 선택이 필요.
- 주요 목적 : 연산 패턴에 부합하는 메모리·접근 구조 선택을 통한 성능·안정성 확보.

## Ⅱ. 선형 구조의 특징 및 장점

- 핵심 요약 : 접근 방식(임의 접근·포인터 연결·끝 제한)별 구조가 서로 다른 연산 효율을 제공.

1. **배열** (Array) : 연속 메모리에 할당하고 인덱스로 임의 접근 O(1) → 빠른 조회와 **캐시 지역성** (참조 데이터가 근처에 모여 캐시 적중률을 높이는 성질) 활용 효과.
2. **연결 리스트** (Linked List) : 노드가 포인터로 이웃을 가리킴 → 위치를 아는 노드의 삽입·삭제 O(1)과 동적 크기 변화 수용.
3. **스택** (Stack) : 한쪽 끝에서만 삽입·삭제하는 후입선출 **LIFO** (Last-In First-Out) → 함수 호출 관리·실행 취소 처리에 적합.
4. **큐** (Queue) : 한쪽 삽입·반대쪽 제거의 선입선출 **FIFO** (First-In First-Out) → 작업 대기열·버퍼링 처리에 적합.
5. **덱** (Deque, Double-Ended Queue) : 양쪽 끝 삽입·삭제 허용 → 양방향 버퍼·작업 분배 등 유연한 순서 제어.

## Ⅲ. 선형 구조의 구조 (흐름)

- 핵심 요약 : 접근 방식에 따라 구조를 분류하며, 대표 처리 흐름은 큐 기반 작업 처리로 확인 가능.

```text
[ 선형 구조의 분류 ]

선형 구조
    배열 : 인덱스 임의 접근
    연결 리스트 : 포인터 연결
    접근 제한 구조
        스택 : LIFO
        큐 : FIFO
        덱 : 양끝 삽입·삭제
```

```text
작업 발생
   ↓
큐 후단 삽입 (대기)
   ↓
작업자가 전단 제거·처리
   ↓
완료·응답 반환
```

## Ⅳ. 선형 구조와 비선형 구조의 비교

- 핵심 요약 : 단일 순서·순차 접근 중심의 선형 구조와 다중 관계·관계 탐색 중심의 비선형 구조로 역할이 구분.

| 비교 축 | 선형 구조 | 비선형 구조 |
| --- | --- | --- |
| 원소 관계 | 앞·뒤 하나의 이웃 | 계층·망의 다중 이웃 |
| 대표 구조 | 배열·연결 리스트·스택·큐·덱 | 트리·그래프·힙 |
| 접근 방식 | 순차·양끝 접근 | 루트·정점에서의 순회·탐색 |
| 메모리 배치 | 연속 할당에 유리 | 포인터·인접 구조 중심 |
| 적용 예 | 대기열·버퍼·실행 취소 | 계층 분류·경로 탐색·우선순위 |

## Ⅴ. 선형 구조의 한계와 방안

- 핵심 요약 : 선택 오류·용량 한계·캐시 비효율·경계·동시성 오류를 패턴 분석·동적 정책·검증으로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 구조 선택 오류 | 중간 삽입이 잦은 목록에 배열 사용 → O(n) 이동 비용 | 접근·변경 패턴 분석 후 구조 결정 | 연산별 응답 시간 |
| 용량 한계 | 고정 크기 버퍼의 포화 → 오버플로·재할당 비용 | 동적 확장 정책·용량 모니터링 | 오버플로 발생 횟수 |
| 캐시·메모리 비효율 | 연결 구조의 포인터 추적 → 캐시 미스·할당 부담 | 블록 기반 연결 구조·메모리 풀 검토 | 캐시 미스율·할당량 |
| 경계·동시성 오류 | 인덱스 범위·빈 구조 제거·다중 스레드 접근 → 장애 | 경계 검사·불변조건 정의·동기화 설계 | 런타임 오류 건수 |

## Ⅵ. 선형 구조에 대한 제언

- 핵심 요약 : 개발 조직은 이론적 **시간복잡도** (입력 크기에 따른 연산량 증가 추세)와 실측 성능을 함께 보는 자료구조 결정 절차를 표준으로 운영해야 함.

1. 결정 절차 : 성능 요구 모듈의 설계 단계에서 접근 패턴·데이터 규모·동시성 조건을 기록하고 구조 선택 근거를 문서화.
2. 실측 검증 : 프로파일링으로 연산별 지연·메모리 사용을 측정해 이론적 기대와의 차이를 설계 검토에 반영.
3. 재사용 원칙 : 표준 라이브러리·검증된 구현 우선 사용으로 자체 자료구조 구현 축소.

## Ⅶ. 결론

- 핵심 요약 : 선형 구조는 순서 기반 데이터 처리의 기본 자료구조로, 연산 패턴과 메모리 특성에 맞는 선택이 성능의 전제.
- 시사점 : 시간복잡도 표기와 실측 프로파일의 균형이 자료구조 설계 품질을 결정.
