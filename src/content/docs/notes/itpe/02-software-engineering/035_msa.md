소프트웨어 공학 → 설계·아키텍처 → **MSA(모놀리식과 비교)**

## 30초 인출

- 본질: MSA는 애플리케이션을 업무 기능별로 독립 배포할 수 있는 작은 서비스로 나누고 API로 연결하는 아키텍처
- 메커니즘: 서비스마다 자체 코드·데이터베이스를 두고 API 게이트웨이와 서비스 간 API·메시징으로 통신하며 독립적으로 배포·확장
- 통찰: 서비스 경계를 업무 기준으로 나누지 않으면 서로 강하게 얽힌 분산 모놀리스가 되므로 업무 도메인 경계별로 서비스와 데이터를 분리

<details>
<summary>핵심 용어</summary>

- **MSA(Microservices Architecture)** : 업무 기능별로 독립 배포 가능한 작은 서비스의 집합으로 구성하는 아키텍처
- **모놀리식 아키텍처(Monolithic Architecture)** : UI·업무 로직·데이터 접근이 하나의 배포 단위로 묶인 구조
- **서비스별 데이터베이스(Database per Service)** : 서비스가 자기 데이터를 소유하고 다른 서비스는 API로만 접근하는 방식
- **API 게이트웨이(API Gateway)** : 클라이언트 요청을 받아 인증·라우팅을 처리하는 진입점
- **사가(Saga) 패턴** : 여러 서비스에 걸친 트랜잭션을 로컬 트랜잭션과 보상 작업의 연쇄로 처리하는 방식
- **분산 모놀리스(Distributed Monolith)** : 서비스로 나뉘었으나 서로 강하게 결합해 함께 배포해야 하는 구조

</details>

## 2~4교시 25점 답안

## Ⅰ. MSA의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **MSA** 는 업무 기능별로 독립 배포 가능한 작은 서비스를 API로 연결한 아키텍처 |
| 목적 | 서비스 단위의 독립 변경·배포·확장 |

## Ⅱ. 모놀리식과 구별되는 MSA의 특징

| 특징 | 의미 |
|---|---|
| 독립 배포 | 서비스별 빌드·배포 |
| 서비스별 데이터 | 서비스가 자체 데이터베이스 소유 |
| API 통신 | 서비스 간 API·메시지로 협업 |
| 기술 다양성 | 서비스별 다른 기술 사용 가능 |

## Ⅲ. MSA의 구성과 서비스 호출 흐름

### MSA 구성

```text
클라이언트
    ↓
API 게이트웨이 ── 인증·라우팅
    ├─ 주문 서비스 ── 주문 DB
    ├─ 결제 서비스 ── 결제 DB
    └─ 재고 서비스 ── 재고 DB
서비스 간 통신: API·메시지 큐
```

### 확대: 여러 서비스에 걸친 트랜잭션(사가)

```text
주문 생성(로컬 트랜잭션)
    ↓
결제 처리 (실패 시 → 주문 취소 보상)
    ↓
재고 차감 (실패 시 → 결제 취소·주문 취소 보상)
```

## Ⅳ. 모놀리식과 MSA의 비교

| 구분 | 모놀리식 | MSA |
|---|---|---|
| 배포 단위 | 애플리케이션 전체 | 서비스별 |
| 확장 | 전체 확장 | 필요한 서비스만 확장 |
| 데이터 | 하나의 데이터베이스 | 서비스별 데이터베이스 |
| 트랜잭션 | 로컬 트랜잭션 | 분산 트랜잭션(사가) |
| 운영 복잡도 | 낮음 | 높음(서비스 수 증가) |
| 적합 조건 | 소규모·변경이 적은 시스템 | 대규모·변경이 잦은 시스템 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 서비스 경계를 잘못 나눠 서비스 간 결합이 커진 분산 모놀리스 | 업무 도메인 경계 기준으로 서비스와 데이터 분리 |
| 서비스 간 트랜잭션의 정합성 유지 곤란 | 사가 패턴과 보상 트랜잭션 |
| 호출 장애의 연쇄 전파 | 타임아웃·서킷 브레이커 적용 |
| 서비스 수 증가로 장애 원인 추적 곤란 | 분산 추적·로그 통합 |

## Ⅵ. 제언

서비스 경계를 업무 도메인 단위로 먼저 정하고, 결합이 낮은 기능부터 점진적으로 분리

### 도메인 기반 분리 순서

```text
업무 도메인·경계 식별
    ↓
결합이 낮은 도메인 선정
    ↓
서비스·전용 데이터 분리
    ↓
API로 연결 → 운영 결과 확인
```

### 확대: 분리 후보 판단

```text
기능
    ├─ 다른 기능과 데이터 결합 큼 → 경계 재검토
    └─ 결합 작고 변경 잦음 → 우선 분리
```

### 선택 근거: 기술 계층별 분리와의 비교

| 구분 | 기술 계층별 분리 | 제언: 업무 도메인별 분리 |
|---|---|---|
| 서비스 결합 | 기능 하나에 여러 서비스 연계 | 기능이 한 서비스에 응집 |
| 변경 영향 | 여러 서비스 | 해당 서비스 |
| 데이터 소유 | 공유 | 서비스별 |
