## 연관 키워드

- AJAX, XMLHttpRequest, Fetch API, 비동기 통신
- DOM, JSON, SPA

## Ⅰ. AJAX의 개요

- 핵심 요약 : **AJAX**(Asynchronous JavaScript and XML)는 페이지 전체 재로딩 없이 브라우저와 서버가 비동기로 데이터를 교환해 화면 일부를 갱신하는 웹 개발 기법.
- 개념 : JavaScript가 서버와 비동기로 데이터를 주고받고 수신 데이터로 화면 일부만 갱신하는 웹 개발 기법.
- 배경 및 필요성 : 전통 웹은 사용자 동작마다 HTML 문서 전체를 재전송·재렌더링하므로 지연·대역폭 낭비·화면 깜빡임이 반복 → 상호 작용의 연속성 확보 필요.
- 주요 목적 : 응답성 높은 사용자 경험과 네트워크·서버 자원의 효율화, 화면 전환 없이 동작하는 **SPA**(Single Page Application, 최초 로딩 후 하나의 페이지에서 동작하는 웹 응용) 구현의 기반 확보.

## Ⅱ. AJAX의 특징 및 장점

- 핵심 요약 : 비동기 요청·부분 갱신·데이터 중심 교환이 응답성과 자원 효율이라는 장점으로 연결되는 브라우저 통신 방식.

1. **비동기 통신**(Asynchronous Communication, 응답 대기 없이 요청과 후속 처리를 진행하는 통신 방식) : 요청의 백그라운드 처리·완료 시점의 결과 반영 → 대기 없는 화면 조작.
2. 부분 갱신 : 수신 데이터를 **DOM**(Document Object Model, 문서 구조를 객체 트리로 표현하는 인터페이스)에 반영한 필요 영역의 갱신 → 전체 재렌더링 제거.
3. 데이터 중심 교환 : **JSON**(JavaScript Object Notation, 속성·값 쌍으로 구성된 경량 데이터 형식) 등 필요 데이터만 송수신 → 문서 전체 전송 대비 전송량 감소.
4. 표준 API 기반 : **XMLHttpRequest**(브라우저에서 HTTP 요청·응답을 비동기로 주고받는 표준 객체)와 **Fetch API**(비동기 결과를 Promise로 전달하는 표준 HTTP 요청 인터페이스)만으로 구현 → 플러그인 불필요·브라우저 호환성 확보.

```text
[ 동기·비동기 처리 시간축 ]

동기 : 요청 → 전체 응답 대기 → 전체 갱신
비동기 : 요청 → 대기 중 조작 가능
          ↓ 데이터 도착
       부분 갱신
```

## Ⅲ. AJAX의 구조 (흐름)

- 핵심 요약 : 사용자 이벤트의 비동기 요청 생성에서 서버 처리·데이터 검증을 거쳐 DOM 부분 갱신으로 이어지는 흐름.

```text
[ AJAX 요청·응답 흐름 ]

사용자 이벤트 발생
   ↓
JavaScript 비동기 요청 생성
(XMLHttpRequest·Fetch API)
   ↓
서버 API 처리
   ↓
JSON 등 데이터 응답
   ↓
상태·오류 검증 후 DOM 부분 갱신
```

- 처리 규칙 : 요청 취소·타임아웃·재시도 여부와 로딩·오류 표시를 화면 상태 모델에 명시 → 비동기 실패의 예측 가능한 처리.

## Ⅳ. AJAX와 전통 동기 페이지 갱신 방식의 비교

- 핵심 요약 : 필요 데이터의 부분 갱신인 AJAX와 문서 전체 재전송인 전통 동기 페이지 갱신은 사용자 경험·자원 효율·구현 복잡도에서 차이.

| 비교 축 | AJAX 비동기 통신 | 전통 동기 페이지 갱신 |
| --- | --- | --- |
| 교환 단위 | 필요 데이터(JSON 등)의 송수신 | HTML 문서 전체의 재전송 |
| 화면 갱신 | 관련 영역의 부분 갱신 | 전체 페이지 재로딩·깜빡임 |
| 사용자 경험 | 대기 없는 연속 조작 | 요청마다 화면 전환·대기 |
| 서버 부담 | 경량 데이터 처리 중심 | 매 요청 문서 재생성·재전송 |
| 상태·URL 관리 | 클라이언트 상태·히스토리 처리 필요 | URL·서버 세션 중심의 단순 구조 |

## Ⅴ. AJAX의 한계와 방안

- 핵심 요약 : 히스토리·색인·비동기 상태·보안 경계의 문제를 라우팅·렌더링·상태 관리·보안 설정의 통제로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 히스토리·URL 불일치 | 화면만 전환되고 주소·뒤로 가기 미반영 | History API 기반 라우팅·상태 복원 처리 | 새로 고침 복원 실패율 |
| 검색 색인·접근성 | 클라이언트 렌더링 콘텐츠의 수집·포커스 관리 누락 | **SSR**(Server-Side Rendering, 서버에서 페이지를 미리 그려 제공하는 방식) 검토·포커스 이동 처리 | 색인 가능 페이지 비율 |
| 비동기 상태 복잡성 | 경쟁 요청·실패·재시도로 화면 불일치 | 로딩·오류·취소 상태의 명시적 관리 | 비동기 오류율 |
| 보안 경계 | **CORS**(Cross-Origin Resource Sharing, 교차 출처 자원 공유 정책) 오구성·**CSRF**(Cross-Site Request Forgery, 교차 사이트 요청 위조) 위험 | 허용 출처 최소화·위조 방어 토큰·서버 권한 검사 | 보안 점검 위반 건수 |

## Ⅵ. AJAX의 제언

- 핵심 요약 : 웹 조직은 비동기 통신 계약의 표준화와 SPA 적용 정책, 공통 모듈·교육 체계로 프런트엔드 역량을 내재화.

1. API 설계 조직은 상태 코드·오류 응답 형식·재시도 규격의 표준 문서 공표.
2. 아키텍처 조직은 SPA 적용 대상 화면과 렌더링 방식(SSR·클라이언트 렌더링)의 선택 정책 수립.
3. 프런트엔드 조직은 요청 래퍼·상태 관리 공통 모듈과 비동기 처리 교육 체계 운영.

## Ⅶ. AJAX의 결론

- 핵심 요약 : AJAX는 페이지 재로딩 없는 비동기 데이터 교환으로 현대 웹 사용자 경험의 기반이 된 기법.
- 시사점 : 응답성의 이익은 상태 관리·색인·보안 통제가 갖춰진 조건에서 사용자 가치로 전환.
