## 연관 키워드

- 테스트 자동화, Test Automation
- 테스트 피라미드, 테스트 프레임워크, 회귀 테스트, 테스트 오라클, 아이스크림 콘 안티패턴, 자동화 사각지대, ROI

## Ⅰ. 테스트 자동화의 개요

- 핵심 요약 : 테스트 자동화는 반복 시험을 스크립트와 도구로 실행해 회귀 검증의 속도·재현성을 높이는 품질 활동.
- 개념 : 시험 설계·실행·결과 판정·보고를 도구와 스크립트로 수행해 사람 개입을 최소화하는 품질 활동 (**테스트 자동화**, Test Automation).
- 배경 및 필요성 : 릴리스 주기 단축으로 매 변경마다 수동 시험을 반복하는 방식은 비용·시간의 한계에 도달했고, 회귀 검증 누락이 운영 장애로 이어짐.
- 주요 목적 : 반복 검증의 신뢰성 확보와 피드백 단축으로 결함 조기 발견·안정적 릴리스 실현.

## Ⅱ. 테스트 자동화의 특징 및 장점

- 핵심 요약 : 계층적 시험 배치·프레임워크 기반 재사용·명확한 판정 기준이 빠른 피드백과 낮은 유지비로 연결.

1. **테스트 피라미드** (Test Pyramid) : 실행이 빠르고 격리된 단위 시험을 다수, 서비스·통합·UI 시험을 소수로 배치 → 전체 실행 시간과 유지비의 균형.
2. **테스트 프레임워크** : 시험 로직·데이터·화면 객체를 분리하는 데이터 주도·키워드 주도 설계 → 스크립트 재사용으로 작성·유지 비용 절감.
3. **회귀 테스트** (Regression Test) : 변경 때마다 동일 시험 세트를 재실행 → 기존 기능 파손의 조기 탐지.
4. **테스트 오라클** (Test Oracle) : 기대 결과·불변 조건을 코드로 정의 → 단순 실행을 넘어 합격·불합격의 자동 판정 가능.
5. 파이프라인 연계 : CI(Continuous Integration, 지속적 통합) 빌드 이벤트에 시험을 자동 실행 → 개발자 피드백 주기 단축.

## Ⅲ. 테스트 자동화의 구조 (흐름)

- 핵심 요약 : ROI 기준의 대상 선정에서 프레임워크 구축·CI 실행·결과 보고로 이어지는 절차와 피라미드형 자원 배치.

```text
[ 테스트 피라미드 ]

        UI 시험 (소수)
      ──────────────────
      서비스·통합 시험
     ─────────────────────
        단위 시험 (다수)

  하위일수록 빠르고 저렴하고 안정적
```

```text
자동화 적용 절차

대상 선정 (반복 빈도·안정성 기준)
   ↓
프레임워크·설계 방식 결정
   ↓
시험 스크립트·데이터 작성
   ↓
CI 파이프라인 연계 실행
   ↓
결과 판정·보고
```

- 대상 선정은 ROI(Return on Investment, 투자 회수) 관점에서 반복 빈도·안정성·수동 시험 비용을 기준으로 수행.

## Ⅳ. 테스트 자동화와 수동 테스트의 비교

- 핵심 요약 : 자동화는 반복·정형 검증에서 속도·재현성·비용 효율이 우수하고, 수동은 탐색·사용성 같은 판단 영역을 담당하는 상호 보완 관계.

| 비교 축 | 테스트 자동화 | 수동 테스트 |
| --- | --- | --- |
| 실행 주체 | 스크립트·도구 | 시험 인력 |
| 비용 구조 | 초기 개발 후 반복 실행 비용 낮음 | 실행 횟수에 비례해 증가 |
| 적합 영역 | 회귀·반복·정형 데이터 검증 | 탐색적 시험·사용성·비정형 판단 |
| 결과 재현성 | 동일 입력에 동일 판정 | 실행자·조건에 따른 편차 |
| 피드백 속도 | 분 단위 실행 가능 | 시간·일 단위 소요 |

- 선택 기준 : 반복 빈도·판정 명확성이 높은 시험은 자동화, 사람의 관찰·직관이 필요한 영역은 수동 시험 유지.

## Ⅴ. 테스트 자동화의 한계와 방안

- 핵심 요약 : UI 중심 왜곡·불안정 시험·검증 공백·유지 비용을 레벨 하향·격리·수동 병행·추상화로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **아이스크림 콘 안티패턴** (Ice Cream Cone Anti-pattern) | UI 시험 중심의 역피라미드 구조 → 실행 시간·유지비 증가 | 자동화 비중을 단위·서비스 레벨로 하향 배치 | 레벨별 시험 비율 |
| 불안정 시험 (flaky test) | 타이밍·환경 의존으로 오탐·미탐 발생 → 시험 신뢰 하락 | 원인 분리·안정적 선택자·시험 데이터 격리 | 재실행률 |
| **자동화 사각지대** | 탐색·사용성 등 사람 판단 영역이 검증 밖에 존재 → 품질 착시 | 탐색적 수동 시험 세션 병행·커버리지 한계 명시 | 탐색 시험 시간 비중 |
| 스크립트 유지 비용 | 화면·인터페이스 변경마다 스크립트 수정 → 투자 회수 지연 | **POM** (Page Object Model)으로 화면 객체 추상화 | 스크립트 수정 공수 |

## Ⅵ. 테스트 자동화 적용에 대한 기술사적 제언

- 핵심 요약 : 품질 조직은 자동화를 도구 도입이 아니라 시험 전략·표준·성과 측정을 갖춘 운영 체계로 정착.
- 정책 : 테스트 리더는 자동화 대상 선정 기준·레벨별 비중·승인 절차를 시험 정책으로 명문화.
- 표준 : 조직 공통 프레임워크와 시험 데이터·환경 관리 규칙을 형상 관리 체계에 통합.
- 성과 : 자동화 커버리지·결함 탐지 효과·유지 비용을 지표로 정기 평가하고 정책에 환류.

## Ⅶ. 결론

- 핵심 요약 : 테스트 자동화는 반복 검증을 개발 흐름에 내재화해 릴리스 속도와 품질을 동시에 확보하는 수단.
- 자동화의 범위와 한계를 인정하고 수동 시험과의 균형을 유지할 때 자동화 투자의 효과가 지속.
