## 연관 키워드

- 화이트박스 시험, 구조 기반 테스트, 제어 흐름 그래프(CFG)
- 문장·분기·조건 커버리지, 수정 조건/결정 커버리지(MC/DC), 블랙박스 시험

## Ⅰ. 화이트박스 시험의 개요

- 핵심 요약 : 화이트박스 시험은 코드의 내부 구조와 제어 흐름을 기준으로 시험 케이스를 설계하는 구조 기반 테스트.
- 개념 : 프로그램 내부 논리를 분석해 문장·분기·조건·경로의 실행을 검증하는 시험(**화이트박스 시험**, White Box Test), **구조 기반 테스트** (Structural Testing)의 대표 기법.
- 배경 및 필요성 : 명세만 검증하는 시험으로는 구현된 분기와 예외 흐름의 미실행 영역 확인 불가.
- 주요 목적 : 논리 구현 오류와 미검증 구조 영역의 식별.

## Ⅱ. 화이트박스 시험의 특징 및 장점

- 핵심 요약 : 문장→분기→조건→MC/DC 순으로 강도가 높아지며 커버리지 수치가 시험 충분성의 객관 판단 근거.

1. **문장 커버리지** (Statement Coverage) : 모든 문장을 최소 1회 실행 → 미실행 코드 탐지.
2. **분기 커버리지** (Branch Coverage) : 결정의 참·거짓 결과를 모두 실행 → 숨은 분기 오류 검출.
3. **조건 커버리지** (Condition Coverage) : 복합 조건의 개별 항목 참·거짓을 각각 평가 → 조건별 영향 확인.
4. **수정 조건/결정 커버리지** (MC/DC, Modified Condition/Decision Coverage) : 각 조건이 결정 결과에 독립적으로 영향을 주는 경우를 실행 → 안전 필수 로직의 정밀 검증.

## Ⅲ. 화이트박스 시험의 구조 (흐름)

- 핵심 요약 : 코드 분석으로 제어 흐름 그래프를 만들고 커버리지 기준에 맞춰 시험 케이스를 설계·보완.
- **제어 흐름 그래프** (CFG, Control Flow Graph) : 문장을 노드로, 분기를 간선으로 표현해 시험 경로 분석의 기초가 되는 그래프.

```text
[ 시험 수행 절차 ]

소스 코드 분석
   ↓
CFG 작성(노드·간선·분기)
   ↓
커버리지 기준 선택
   ↓
시험 케이스 설계·실행
   ↓
미실행 구간 보완
```

```text
[ 커버리지 강도 계층 ]

문장 커버리지
   ↓ 강도 증가
분기 커버리지
   ↓ 강도 증가
조건 커버리지
   ↓ 강도 증가
MC/DC
```

- 설계 예시 : (A AND B) 조건에서 B를 고정한 채 A만 바꿔 결정 결과의 변화를 확인하는 방식이 MC/DC 시험 케이스 설계의 기본.

## Ⅳ. 화이트박스 시험과 블랙박스 시험의 비교

- 핵심 요약 : 화이트박스 시험은 내부 구조의 실행 검증, 블랙박스 시험은 명세 대비 기능 동작 검증에 강점.
- **블랙박스 시험** (Black Box Test) : 내부 구조를 보지 않고 명세·요구를 기준으로 입출력을 검증하는 시험.

| 비교 축 | 화이트박스 시험 | 블랙박스 시험 |
| --- | --- | --- |
| 설계 기준 | 코드 구조·내부 논리 | 명세·요구사항 |
| 수행 주체 | 주로 개발자 | 시험 전문가·사용자 관점 |
| 검증 초점 | 분기·조건·경로의 실행 | 기능 동작과 입출력 일치 |
| 강점 | 구조적 미실행 영역 발견 | 요구 누락·기능 오류 발견 |
| 한계 | 요구 충족 보장 불가 | 내부 논리 결함 탐지 불가 |

## Ⅴ. 화이트박스 시험의 한계와 방안

- 핵심 요약 : 경로 조합 폭발과 커버리지 수치 오용을 위험 기반 선정·명세 기반 보완으로 완화.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 경로 조합 폭발 | 반복·분기 조합의 전 경로 실행 불가 | 위험도·복잡도 기반 경로 선정 | 미실행 분기 수 |
| 커버리지 수치 오용 | 달성 수치의 품질 확대해석 | 결함 검출률·요구 추적 병행 | 커버리지 대비 결함 비율 |
| 부실한 입력 설계 | 구조 도달만으로 경계·예외 누락 | 동등분할·경계값 분석 병행 | 경계 결함 검출 비율 |

## Ⅵ. 화이트박스 시험에 대한 제언

- 핵심 요약 : 위험도별 커버리지 목표를 시험 정책으로 제정하고 구조 시험과 명세 시험의 결합 체계로 운영 필요.

1. 개발 조직은 코드 리뷰에 분기·예외 경로의 검토 항목 포함.
2. 품질 조직은 안전·규제 중요도에 따른 커버리지 기준과 결과 보존 절차 수립.
3. 품질 책임자는 커버리지와 결함 유출·요구 추적 지표의 동시 해석 체계 운영.

## Ⅶ. 결론

- 핵심 요약 : 화이트박스 시험은 구조 실행 여부의 측정 수단이지 정확성의 증명이 아님.
- 명세 기반 시험과의 결합을 통해 검증의 완결성 확보.
