## 연관 키워드

- 인간-컴퓨터 상호작용(HCI, Human-Computer Interaction), 인간중심 설계, 사용성, 접근성
- 실행 간극·평가 간극, 닐슨 10대 휴리스틱, WCAG(Web Content Accessibility Guidelines)

## Ⅰ. HCI의 개요

- 핵심 요약 : HCI는 사람과 컴퓨터 시스템 간 상호작용을 사용자의 인지·과업·환경에 맞춰 설계·평가하는 인간중심 공학 분야.
- 개념 : 사람과 컴퓨터 시스템 사이의 상호작용 방식을 설계·평가·구현을 통해 다루는 분야가 **인간-컴퓨터 상호작용**(HCI, Human-Computer Interaction)임.
- 배경 및 필요성 : 기능의 동작만으로 사용자의 목표 달성이 보장되지 않고, 조작 오류·학습 부담·이용 포기가 지원 비용 증가와 신뢰 하락으로 이어지는 문제.
- 주요 목적 : 효과적·효율적·만족스럽고 포용적인 상호작용의 제공을 통한 제품 채택, 운영 오류 감소, 접근 권리 보장 확보.

## Ⅱ. HCI의 특징 및 장점

- 핵심 요약 : 사용자 관점의 설계 원칙과 측정 가능한 평가 기준이 오류 감소·학습 부담 축소·이용 범위 확대로 연결되는 구조.

1. 인간중심 설계 : 사용자·과업·환경 분석에서 설계·평가까지 사용자 관점을 반영하는 **인간중심 설계**(human-centred design, ISO 9241-210) 절차 적용 → 오용과 재작업 감소.
2. 간극 해소 : 사용자가 조작 방법을 찾는 **실행 간극**(Gulf of Execution)과 결과를 해석하는 **평가 간극**(Gulf of Evaluation)을 피드백·대응 관계 설계로 축소 → 학습 부담·조작 오류 감소.
3. 사용성 기준 측정 : 지정 사용자·목표·맥락에서 효과성·효율성·만족도를 다루는 **사용성**(usability) 지표로 개선 판단 → 주관적 취향에 의존한 설계 논쟁 감소.
4. 원칙 기반 점검 : 일관성·오류 방지·오류 회복 등 열 개 설계 원칙인 **닐슨 10대 휴리스틱**(Nielsen's 10 Usability Heuristics)으로 초기 설계 점검 → 사용자 시험 이전의 저비용 결함 발견.
5. 접근성·포용 설계 : 웹 콘텐츠의 장애 유무 무관 이용을 위한 **접근성**(accessibility) 기준 **WCAG**(Web Content Accessibility Guidelines) 반영 → 이용자 범위 확대와 법·지침 준수.

## Ⅲ. HCI의 구조 (흐름)

- 핵심 요약 : 분석에서 평가·개선으로 되돌아가는 반복 주기와, 사용자 목표와 시스템 사이의 간극을 좁히는 상호작용 구조가 중심.

```text
[ 인간중심 설계 주기 ]

사용자·과업·환경 분석
   ↓
요구·설계 원칙 반영
   ↓
프로토타입 제작
   ↓
사용자 기반 평가
   ↓
결함 해소 후 분석 단계로 반복
```

```text
[ 실행 간극과 평가 간극 ]

사용자 목표 : 문서를 안전하게 저장
      ↓ 실행 간극(조작 방법의 차이)
인터페이스 : 저장 명령·진행 표시 제공
      ↓ 시스템 동작
시스템 상태 : 저장 완료·오류 안내
      ↓ 평가 간극(결과 해석의 차이)
사용자 해석 : 목표 달성 여부 판단
```

## Ⅳ. HCI와 기술 중심 인터페이스 설계의 비교

- 핵심 요약 : 기능 배치 위주의 기술 중심 설계와 달리, HCI는 사용자의 목표·인지·접근성을 설계와 평가의 출발점으로 둠.

| 비교 축 | HCI(사용자 중심 설계) | 기술 중심 인터페이스 설계 |
| --- | --- | --- |
| 설계 출발점 | 사용자의 목표·과업·맥락 분석 | 시스템 기능·데이터 흐름 중심 화면 배치 |
| 평가 기준 | 사용성(효과성·효율성·만족도)·접근성 | 기능 동작 여부·기능 완성도 |
| 개선 방식 | 프로토타입과 사용자 평가의 반복 | 개발 완료 후 매뉴얼·교육으로 보완 |
| 오류 대응 | 오류 방지·회복을 인터페이스에 내장 | 사용자 숙달에 의존 |
| 성과 초점 | 채택률·운영 오류 감소·이용 범위 확대 | 기능 제공 자체 |

## Ⅴ. HCI의 한계와 방안

- 핵심 요약 : 사용자 다양성·요구 상충·접근성 지연·결과 만료를 대표 사용자 정의, 기준 선행 반영, 정기 재평가로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 사용자 주관성·다양성 | 취향·숙련도 차이로 소수 의견이 설계를 좌우하거나 결과 일반화가 어려움 | 대표 사용자·과업 정의, 정량 지표와 정성 관찰 병행 | 과업 완료율, 오류율 |
| 사용성·보안 상충 | 인증 강화·자동화 차단이 편의를 낮춰 우회·포기 유발 | 위험 등급별 인증 정책, 대체 인증 수단 제공 | 인증 실패율, 도움 요청률 |
| 접근성 사후 보완 | 설계 후반의 보조기술 요구 반영으로 구조 변경 비용 증가 | 요구 정의 단계에서 WCAG 기준 포함, 키보드·스크린리더 검증 | 접근성 결함 수 |
| 평가 결과 만료 | 기기·환경·사용자 집단 변화로 과거 결과의 유효성 저하 | 정기 재평가, 현장 관찰 병행 | 재평가 주기 준수율 |

## Ⅵ. HCI에 대한 제언

- 핵심 요약 : 제품 책임 조직은 인간중심 설계를 개인 기량이 아닌 개발 절차·인수 기준에 내장하는 체계로 확산.
- 조직 체계 : 제품 책임 조직이 사용자 조사와 프로토타입 평가를 개발 생명주기의 표준 단계로 제도화하고 사용성 전문가를 프로젝트에 상시 배치.
- 기준 제도 : 접근성·사용성 기준을 완료 정의(DoD, Definition of Done)와 인수 검증 항목에 포함해 품질 게이트로 운영.
- 역량·거버넌스 : 대표 사용자 패널과 접근성 시험 환경을 공동 인프라로 구축하고, 국가·업계 접근성 지침 개정을 조직 표준에 반영하는 절차 운영.

## Ⅶ. 결론

- 핵심 요약 : HCI는 인터페이스의 외형이 아니라 사용자 과업 달성·인지 부담·접근 권리를 다루는 인간중심 공학.
- 사용성·접근성 결과를 설계·검증 기준에 두는 조직이 제품 채택과 서비스 신뢰를 확보.
