## Ⅰ. 요구사항 도출 기법의 개요

- 개념 : 소프트웨어 개발 프로젝트 초기 단계에서 사용자, 고객, 운영자 등 다양한 이해관계자의 잠재적 니즈, 비즈니스 목표, 시스템 제약조건을 효과적으로 이끌어내고 발굴하는 체계적인 엔지니어링 활동.
- 배경 및 필요성 : 사용자는 자신이 진정으로 원하는 것을 명확히 표현하지 못하는 '암묵지(Tacit Knowledge)' 상태에 있거나, 부서 간 상충된 이해관계로 인해 요구사항 누락 및 왜곡이 빈번히 발생하기 때문에 구조화된 도출 기법 적용 필수.
- 핵심 목표 : 숨은 요구사항 발굴, 이해관계자 간 공감대 형성, 프로젝트 범위 조기 명확화.

## Ⅱ. 주요 요구사항 도출 기법의 분류 및 상호 연계

```text
   [ 전통적 기법 ] ──── 인터뷰 (1:1 심층 질문), 설문조사 (다수 의견 통계)
          │
   [ 협업/합의 기법 ] ── JAD (Joint Application Development), 브레인스토밍
          │
   [ 시각화/검증 기법 ] ─ 프로토타이핑 (Throwaway / Evolutionary)
          │
   [ 관찰/인류학 기법 ] ─ 작업 관찰 (Observation), 직무 섀도잉 (Job Shadowing)
```

- **JAD (Joint Application Development)** : 사용자, 개발자, 관리자, 중재자(Facilitator)가 한자리에 모여 집중 워크숍을 통해 요구사항을 신속하게 합의하고 도출하는 기법.
- **프로토타이핑** : 핵심 UI와 워크플로우를 실제 동작하는 모델로 신속하게 구현하여 피드백을 수렴하는 기법 (요구사항 불확실성 해소에 탁월).
- **작업 관찰 및 섀도잉** : 사용자가 말로 설명하지 못하는 실제 업무 수행 절차와 숨겨진 불편 사항(Pain Point)을 현장에서 직접 관찰하여 발굴.

## Ⅲ. 요구사항 도출 기법별 특성 및 장단점 비교

| 기법 | 적합한 상황 | 주요 장점 | 주요 단점 |
|---|---|---|---|
| **인터뷰** (Interview) | 소수의 핵심 의사결정자 및 도메인 전문가 대상 | 깊이 있는 정성적 요구 및 배경 맥락 파악 | 다수 인원 적용 불가, 인터뷰어 역량 편차 |
| **설문지** (Questionnaire) | 다수의 광범위한 최종 사용자 의견 수렴 | 시간/비용 대비 대량 데이터 수집 용이 | 질문의 모호성, 깊이 있는 세부 요구 파악 불가 |
| JAD 워크숍 | 부서 간 이해관계 상충이 심하고 빠른 합의 필요 시 | 의사결정 기간 단축, 갈등 조기 조율 | 전문가 일정 조율 난항, 진행자 역량 의존 |
| 프로토타이핑 | 사용자가 요구사항을 구체화하지 못할 때 | 시각적 피드백으로 요구사항 오해 원천 차단 | 프로토타입 제작 공수 발생, 과도한 기대감 유발 |
| **현장 관찰** (Observation) | 복잡한 수작업 공정이나 전문 조작 시스템 | 암묵적 지식 및 숨겨진 절차 발굴 | 관찰 대상자의 심리적 부담(호손 효과), 시간 소요 |

## Ⅳ. 요구사항 도출 기법의 주요 한계점 및 해결 방안

- 현업 담당자의 소극적 참여 및 숨겨진 니즈(Tacit Needs) 발굴 실패 :
  - 한계점 : 인터뷰나 설문조사 시 현업의 본업 부담으로 단답형 답변에 그치거나, 현행 수작업 프로세스를 무비판적으로 전산화하려는 관성에 갇혀 진정한 혁신 요구 도출 실패.
  - 해결 방안 : 사용자의 실제 업무를 밀착 관찰하는 관찰법(Job Shadowing)과 에스노그래피(Ethnography)를 도입하고, 디자인 씽킹(Design Thinking) 워크숍을 통해 사용자의 잠재적 통증점(Pain Point) 가시화.
- 다수 이해관계자 간 상충 요구(Conflicting Requirements)의 조율 병목 :
  - 한계점 : 부서 간 이해관계(예: 영업부의 빠른 화면 vs 보안부의 다단계 인증)가 첨예하게 대립하여 요구사항 우선순위 합의가 교착 상태에 빠짐.
  - 해결 방안 : MoSCoW(Must/Should/Could/Won't) 분석, 카노(Kano) 모델, AHP(계층화 분석법) 기법을 활용하여 비즈니스 가치와 기술적 난이도를 정량 평가하고 스폰서 전결 체계 마련.
- 범위의 무한 확장(Gold Plating) 및 비핵심 요구 난립 :
  - 한계점 : 초기 브레인스토밍 단계에서 비즈니스 목표와 무관한 개인적 희망 사항(Nice-to-have)이 무분별하게 유입되어 프로젝트 본질이 왜곡됨.
  - 해결 방안 : 프로젝트 헌장의 비즈니스 목표(OKRs/KPIs)와 유의미하게 연계된 항목만을 선별하는 스코프 필터링 기준을 확립하고 조기 사용자 스토리 백로그 기반 정제.

## Ⅴ. 요구사항 도출 현장 적용 시 기술사적 제언

- 다양한 기법의 하이브리드 조합 전략 : 단일 기법에 의존하지 않고, 설문조사로 거시적 니즈를 파악한 후 핵심 실무자 인터뷰 -> 프로토타이핑을 통한 화면 피드백 -> JAD 워크숍을 통한 최종 조율의 파이프라인식 결합 권장.
- 생성형 AI 기반 사용자 인터뷰 요약 및 시나리오 증강 : 방대한 사용자 인터뷰 녹취록과 현장 기록을 LLM을 활용하여 페르소나(Persona) 및 유저 스토리(User Story)로 자동 구조화하여 도출 누락을 최소화하는 최신 AI 지원 공학 기법 적극 도입.
