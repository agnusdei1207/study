## 1. 사용성 평가·테스트의 개요 및 필요성

### (1) 사용성 평가(Usability Evaluation)의 정의
- 소프트웨어가 제공하는 기능적 완성도를 넘어, **특정 맥락(Context of Use)에서 특정 사용자가 명시된 목표를 얼마나 효과적이고 효율적이며 만족스럽게 달성할 수 있는지를 정량적·정성적으로 측정하고 인터페이스를 개선하는 활동(ISO 9241-11)**.

### (2) 핵심 필요성 (121회 4교시 기출)
- **사용자 이탈 방지 및 전환율(Conversion Rate) 극대화**: 복잡한 UI로 인한 인지 마찰(Cognitive Friction)을 제거하여 목표 과업 완수율 제고.
- **개발 후반부 재작업 비용 절감**: 와이어프레임 및 프로토타입 단계에서 소수(5명) 피험자 테스트로 사용성 결함의 85%를 조기 색출.
- **데이터 기반의 객관적 의사결정**: 이해관계자나 경영진의 주관적 취향 다툼을 방지하고 SUS 점수 및 완수 시간 데이터를 근거로 UI 개선 우선순위 확립.

## 2. ISO 9241-11 3대 핵심 평가 프레임워크

### (1) 사용성 측정 프레임워크 구조도
```text
+-------------------------------------------------------------------------+
|                  ISO 9241-11 사용성(Usability) 측정 프레임워크           |
+-------------------------------------------------------------------------+
|  [ 사용 맥락 (Context of Use) ] : 특정 사용자 + 특정 과업(Task) + 환경   |
|                                    │                                    |
|                                    v                                    |
|  +───────────────────────────────────────────────────────────────────+  |
|  |                    [ 사용성 평가 3대 품질 속성 ]                  |  |
|  |                                                                   |  |
|  |  1. 효과성 (Effectiveness)  2. 효율성 (Efficiency)   3. 만족도    |  |
|  |  - 과업을 얼마나 정확하고    - 완수에 투입된 자원     - 주관적     |  |
|  |    완전하게 달성했는가?        (시간, 노력, 클릭)의     편안함과     |  |
|  |                                비용 대비 성과           수용성       |  |
|  |  * 과업 성공률 (%)          * 완수 소요시간 (초)     * SUS 점수   |  |
|  |  * 오류 발생 건수           * 불필요 클릭/이탈 수    * NPS (추천도)| |
|  +───────────────────────────────────────────────────────────────────+  |
|                                    │                                    |
|                                    v                                    |
|  [ 정량 지표 산출 + 발성 사고법(Think Aloud) 정성 피드백 결합 ──▶ UI 개선 ]|
+-------------------------------------------------------------------------+
```

### (2) 사용성 평가 핵심 측정 지표 상세
| 평가 속성 | 측정 지표 (Metrics) | 측정 방법 및 공식 | 기준 목표치 예시 |
|---|---|---|---|
| **효과성** | 과업 성공률 (Completion Rate) | $\frac{\text{성공한 사용자 수}}{\text{전체 참가자 수}} \times 100$ | 핵심 과업 90% 이상 |
| | 오류 발생률 (Error Rate) | 과업당 사용자가 범한 오작동/재시도 횟수 | 과업당 0.5회 미만 |
| **효율성** | 과업 완수 시간 (Time on Task) | 과업 시작부터 성공적 완료까지의 초(sec) 단위 시간 | 벤치마크 대비 30% 단축 |
| | 클릭 횟수 (Click Count) | 목표 도달까지 발생한 최소 클릭 경로 대 실측 클릭 | 최적 경로 대비 1.2배 이내 |
| **만족도** | SUS (System Usability Scale) | 10문항 5점 리커트 설문 점수 변환 (0~100점) | 68점 이상 (우수 등급) |
| | NPS (Net Promoter Score) | "지인에게 추천하시겠습니까?" 10점 척도 | 양수(+) 유지 |

## 3. 사용성 평가 방법론 비교

| 비교 항목 | 휴리스틱 평가 (Heuristic) | 실험실 사용성 테스트 (UT) | A/B 테스트 (A/B Testing) |
|---|---|---|---|
| **평가 주체** | **UI/UX 전문가 (3~5명)** | **실제 사용자 (5명 내외)** | **실제 운영 서비스 전 사용자 (대규모)** |
| **수행 시점** | 기획, 와이어프레임, 초기 프로토타입 | 개발 중인 프로토타입, MVP 단계 | 실서버 배포 후 라이브 운영 단계 |
| **핵심 기법** | 닐슨 10대 휴리스틱 가이드라인 체크 | **발성 사고법 (Think Aloud)**, 화면 녹화 | 무작위 트래픽 분할, 통계적 유의성 검정 |
| **수집 데이터**| 전문가 관점의 잠재 사용성 문제 목록 | 과업 완수 시간, 오류 행동, 정성 피드백 | 클릭률(CTR), 전환율(CVR), 이탈률 |
| **비용 및 기간**| **매우 저렴, 1~2일 내 완료** | 피험자 섭외 비용, 1~2주 소요 | 트래픽 확보 필수, A/B 인프라 필요 |

## 4. 실무 실패 시나리오 및 해결 방안

| 실패 시나리오 | 근본 원인 | 공학적 해결 방안 | 정량적 기대효과 |
|---|---|---|---|
| **모바일 앱 개편 후 펀드 가입 전환율 45% 급감**<br>(사용자가 약관 동의 체크박스를 못 찾음) | 기획자의 주관적 판단에만 의존하여 실제 사용자 과업 관찰(UT) 생략 | 5명 대상 Think-Aloud UT 실시로 병목 구간 식별 및 원클릭 통합 동의 UI 개편 | 펀드 가입 완수율 93%로 반등, 이탈률 60% 감소 |
| **디자이너와 개발자 간 주관적 취향 다툼 파행**<br>("내 눈엔 이쁜데" 식의 소모적 논쟁) | 객관적인 정량 지표 없이 정성적 의견으로만 화면을 평가한 부실 거버넌스 | 표준 SUS 척도 및 과업별 완수 시간(초) 실측 데이터를 기반으로 우선순위 결정 | 개선안 의사결정 기간 3주에서 1일로 단축 |
| **실험실 환경의 인위성으로 왜곡된 피드백 수집**<br>(피험자가 관찰자를 의식하는 호손 효과) | 관찰자가 옆에서 지켜보는 경직된 대면 실험실 환경의 한계 | Maze/UserTesting 비대면 비동기 원격 UT 도구 및 실제 프로덕션 히트맵 연계 | 자연스러운 실제 사용자 조작 행동 데이터 100% 수집 |

## 5. 기술사 답안 차별화 포인트 (기술사의 시각)

```text
[과거: 출시 직전 1회성 요식 검사]         [현대: 지속적 데이터 주도 사용성 엔지니어링]
- 납품 직전 만족도 설문지 작성으로 때움 ──▶  - Figma 단계부터 5명 피험자 마이크로 UT 반복
- "이쁘다/불편하다" 주관적 품평회        ──▶  - ISO 9241-11 정량 지표(완수율, 시간, SUS) 관리
- 출시 후 사후 피드백 수집 불가          ──▶  - 프로덕션 A/B 테스트 및 제품 분석(Amplitude) 파이프라인 연계
```

- **제이콥 닐슨 법칙의 경제적 가치**: "단 5명의 사용자 테스트로 사용성 문제의 85%를 발견할 수 있다($1 - (1-L)^n$ 곡선)"는 닐슨의 원리를 답안에 명시해야 함. 즉, 대규모 인원과 예산이 없더라도 소수 인원으로 개발 스프린트마다 빠르게 UT를 돌리는 **'애자일 사용성 엔지니어링'**이 가장 비용 효율적임을 강조해야 함.
- **A/B 테스트와 프로덕션 피드백 루프의 결합**: 실험실 UT에서 검증된 가설을 라이브 환경에서 무작위 트래픽(50:50)으로 분할 검증하는 **A/B 테스팅 인프라**를 프론트엔드 아키텍처에 내재화하여, 최고 의사결정권자의 직관(HiPPO: Highest Paid Person's Opinion)이 아닌 순수 데이터 기반으로 인터페이스를 지속 진화시키는 거버넌스를 제시해야 함.
