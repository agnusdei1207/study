## 연관 키워드

- 사용성 평가(Usability Evaluation), 사용성 테스트(UT, Usability Testing), ISO(International Organization for Standardization) 9241-11, 싱크 얼라우드(Think-Aloud Protocol)
- 휴리스틱 평가(Heuristic Evaluation), 인지적 워크스루(Cognitive Walkthrough), SUS(System Usability Scale), 형성적/총괄적 평가, 웹 접근성(Accessibility)

## Ⅰ. 사용성 테스트의 개요

- 핵심 요약 : 실제 사용자의 과업 수행을 관찰하여 인터페이스 문제점을 발견·개선하는 사용자 중심 평가 기법.
- 개념 : 사용자가 제품이나 서비스를 사용하는 과정에서 겪는 편의성, 직관성, 만족도를 측정하고, 실제 사용자가 주어진 과업(Task)을 수행하는 모습을 관찰·기록하여 인터페이스 상의 문제점을 발견하고 개선하는 사용자 중심(User-Centered) 평가 기법.
- 배경 및 필요성 : 개발자 관점의 기능 구현만으로는 복잡한 사용 시나리오에서의 사용자 이탈(Churn Rate) 방지 불가, 디지털 서비스 경쟁력 확보를 위한 고객 경험(UX, User Experience) 최적화 요구.
- 표준 근거 : ISO(International Organization for Standardization) 9241-11의 사용성 정의(효과성, 효율성, 만족도).

## Ⅱ. 사용성 테스트의 특징

- 핵심 요약 : 실사용자 관찰 기반의 정성·정량 병행 평가와 평가 시점별 형성적·총괄적 평가의 구분 체계.

1. 실제 표본 사용자의 과업 수행 관찰과 행동 데이터 수집 중심의 평가 방식.
2. 싱크 얼라우드(Think-Aloud Protocol)를 통한 인지적 마찰 지점 포착.
3. 과업 성공률, 소요 시간 등 정량 지표와 정성 관찰 결과의 병행 기록.
4. 프로토타입 단계 반복 수행의 형성적 평가(Formative Evaluation)와 완료 시점 목표 달성 검증의 총괄적 평가(Summative Evaluation) 구분.
5. 전문가 평가(휴리스틱, 인지적 워크스루)와 사용자 참여 평가(UT, SUS 설문)의 상호 보완 구조.

## Ⅲ. 사용성 테스트의 구조 (흐름)

- 핵심 요약 : 계획 수립부터 개선 보고까지 이어지는 4단계 테스트 세션 운영 흐름.
- 사용성 테스트(UT) 수행 절차.

```text
[ 1. 테스트 계획 수립 ]
 - 테스트 목표, 과업 시나리오
 - 정량/정성 평가 지표 수립
   │
   ▼
[ 2. 참가자 모집 ]
 - 타깃 사용자 5~8명, 페르소나 매칭
   │
   ▼
[ 3. 테스트 세션 실행 ]
 - 싱크 얼라우드(Think-Aloud)
 - 과업 성공률, 소요 시간 측정
   │
   ▼
[ 4. 분석 및 개선 보고 ]
 - 문제점 우선순위 도출
 - UI 개선 권고사항 제시
```

- 테스트 계획 수립 : 테스트 목표와 과업 시나리오 정의, 정량·정성 평가 지표 설계.
- 참가자 모집 : 타깃 사용자 5~8명 표본 모집과 페르소나 매칭.
- 세션 실행 : 싱크 얼라우드 적용 관찰, 과업 성공률과 소요 시간 측정.
- 분석 및 보고 : 문제점 우선순위 도출과 UI(User Interface) 개선 권고 제시.

## Ⅳ. 주요 사용성 평가 방법의 비교

- 핵심 요약 : 수행 주체와 시점, 비용·정확도의 상충 관계에 따른 평가 방법 선택 구조.
- 개발 단계별 평가 기법 배치 비교.

```text
[ 설계 초기 ] ────▶ [ 프로토타입 ] ────▶ [ 완성·배포 ]
 휴리스틱 평가        형성적 평가(UT)      총괄적 평가(UT)
 인지적 워크스루      반복 개선 루프        SUS 설문
```

| 평가 방법 | 수행 주체 | 수행 시점 | 장점 | 단점 |
|---|---|---|---|---|
| 사용자 테스트(UT) | 실제 표본 사용자 | 프로토타입 및 완성 단계 | 실제 사용자의 행동 데이터 및 숨은 마찰 지점 정확히 포착 | 환경 구축 및 모집 비용 발생 |
| 휴리스틱 평가(Heuristic) | UX 전문 평가자(3~5명) | 설계 초기~전 단계 | 닐슨의 원칙을 바탕으로 빠르고 경제적으로 광범위한 결함 검출 | 실제 사용자의 감성적 반응 반영 한계 |
| 인지적 워크스루(Cognitive) | 설계자 및 개발팀 | 초기 상세 설계 단계 | 초보 사용자의 학습 용이성(Learnability) 검증에 탁월 | 복합적이고 전문적인 숙련 과업 평가 한계 |
| SUS 설문(System Usability Scale) | 사용자(사후 설문) | 테스트 직후 | 10문항 표준 설문으로 0~100점의 객관적 사용성 점수 정량화 | 구체적인 UI 결함 위치 파악 불가 |

## Ⅴ. 사용성 테스트의 장점과 한계

- 핵심 요약 : 실사용자 행동 기반의 높은 문제 발견 정확도, 관찰자 효과·객관화·수행 공수 측면의 한계.
- 장점
  1. 실제 사용자 행동 데이터 기반의 숨은 마찰 지점 정확 포착.
  2. SUS(System Usability Scale) 표준 설문을 통한 사용성 점수의 객관적 정량화.
  3. 프로토타입 단계 조기 검증을 통한 재설계 비용 절감.
- 한계점 1 : 실험실 환경의 관찰자 효과(Hawthorne Effect) 및 표본 편향
  - 한계점 : 참여자의 관찰 인지에 따른 과도하게 정돈된 행동, 특정 인구통계학적 편향 발생.
  - 해결 방안 : 실제 사용 환경 기반 비동기 원격 비간섭 테스트(Unmoderated Remote Testing) 병행, 정량 로그(GA, Hotjar)와의 교차 검증을 통한 이상치 필터링.
- 한계점 2 : 정성적 발견의 객관화 및 엔지니어링 티켓 전환 난제
  - 한계점 : '사용자가 결제 화면에서 머뭇거림' 등 모호한 관찰 결과의 시스템 결함·기능 요구사항 직결 실패, 개선 작업 누락.
  - 해결 방안 : 심각도 평가 매트릭스(영향도, 빈도, 지속성) 기반 이슈 점수화, 화면별 과업 성공률과 완료 시간(TCT, Task Completion Time)의 SLA(Service Level Agreement) 지표 관리.
- 한계점 3 : 애자일 릴리스 주기 대비 높은 평가 수행 공수
  - 한계점 : 사용자 모집, 시나리오 설계, 세션 진행 및 분석의 장기 소요, 짧은 스프린트 주기 내 피드백 반영 불가.
  - 해결 방안 : 5명 내외 소규모 표본 대상 게릴라 테스팅과 RITE(Rapid Iterative Testing and Evaluation) 방법론 도입, 프로토타입 단계 선행 검증.

## Ⅵ. 현대 UX 엔지니어링을 위한 기술사적 제언

- 핵심 요약 : 정량 로그 분석과 정성 UT의 융합, 접근성 기반 평가 패널의 필수화.
- 정량 분석과 정성 테스트의 융합 : 클릭스트림 데이터(Google Analytics, Hotjar 히트맵)와 A/B 테스팅으로 이탈 지점(Where)을 파악하고, 심층 사용성 테스트로 이탈 원인(Why)을 규명하는 데이터 기반 UX 개선 체계 정립.
- 접근성(Accessibility) 기반 사용성 평가의 필수화 : 고령자, 시각·지체 장애인 등 디지털 취약계층의 평가 패널 필수 포함, 전자정부 웹 접근성 지침 및 장애인차별금지법 컴플라이언스의 선제 달성.

## Ⅶ. 결론

- 핵심 요약 : 사용성 테스트는 사용자 이탈 방지와 고객 경험 최적화의 공학적 검증 수단.
- 요약 : 실사용자 관찰 기반의 형성적·총괄적 평가와 전문가 평가 기법의 조합이 인터페이스 품질 확보의 골격.
- 시사점 : 정량 로그 교차 검증, 원격 비간섭 테스트, 접근성 평가의 내재화가 지속 가능한 사용성 개선의 조건.
