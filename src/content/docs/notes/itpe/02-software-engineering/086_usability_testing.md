## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 사용자 인터페이스 → **사용성 평가 및 사용성 테스트(Usability Testing)**

## 30초 인출

- 본질: 사용성 평가는 사용자가 목표를 효과적이고 효율적이며 만족스럽게 달성하는 정도를 측정해 인터페이스 문제를 찾는 활동
- 메커니즘: 대표 사용자에게 핵심 과업을 수행하게 하고 과업 성공률·소요 시간·만족도를 측정해 사용성 문제를 도출
- 통찰: 개발 후반에 평가하면 수정 비용이 크므로 프로토타입 단계에서 핵심 과업 기준의 사용성 테스트를 반복하고 완료율·오류·시간 기준으로 개선 여부를 판정

<details>
<summary>핵심 용어</summary>

- **사용성(Usability)** : ISO 9241-11이 효과성·효율성·만족도로 정의한, 특정 사용자가 목표를 달성하는 정도
- **효과성(Effectiveness)** : 목표를 정확하고 완전하게 달성한 정도
- **효율성(Efficiency)** : 목표 달성에 든 시간·조작 등 자원 대비 성과
- **만족도(Satisfaction)** : 사용 중과 후에 느끼는 긍정적 수용도
- **발성 사고법(Think-Aloud)** : 사용자가 과업 중 생각을 소리 내어 말하게 하는 관찰 방법
- **휴리스틱 평가(Heuristic Evaluation)** : 전문가가 사용성 원칙에 비춰 문제를 찾는 평가

</details>

## 2~4교시 25점 답안

## Ⅰ. 사용성 평가의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **사용성 평가** 는 사용자가 목표를 달성하는 효과성·효율성·만족도를 측정해 인터페이스 문제를 찾는 활동 |
| 목적 | 사용자 오류·이탈의 원인 발견과 설계 개선 |

## Ⅱ. 기능 테스트와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 사용자 중심 | 실제 사용자의 과업 수행 관찰 |
| 정량·정성 병행 | 완료율·시간과 발언·표정 관찰 |
| 반복 평가 | 설계 개선마다 재평가 |

## Ⅲ. 사용성의 구성과 테스트 절차

### 사용성의 세 요소

```text
사용성 (ISO 9241-11)
    ├─ 효과성 ── 과업 완료율·정확도
    ├─ 효율성 ── 소요 시간·조작 수
    └─ 만족도 ── 설문·평가 점수
```

### 확대: 사용성 테스트 절차

```text
평가 목표·핵심 과업 정의
    ↓
대표 사용자 모집
    ↓
과업 수행 관찰 (발성 사고법)·측정
    ↓
문제 분석·개선안 도출
```

## Ⅳ. 평가 방법의 비교

| 방법 | 수행 주체 | 강점 | 약점 |
|---|---|---|---|
| 사용성 테스트 | 실제 사용자 | 실제 문제 발견 | 모집·시간 비용 |
| 휴리스틱 평가 | 전문가 | 빠르고 저렴 | 실제 사용자와 차이 |
| 설문 | 다수 사용자 | 만족도 정량화 | 원인 파악 곤란 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 후반 평가로 수정 비용 증가 | 프로토타입 단계에서 평가 |
| 소수 사용자로 결과 일반화 곤란 | 대표 사용자군 구성과 반복 평가 |
| 평가 기준 불명확 | 과업 성공률·시간·오류 목표 기준 사전 설정 |

## Ⅵ. 제언

핵심 과업별 목표 기준(완료율·시간·오류 수)을 정하고, 프로토타입 단계부터 사용성 테스트를 반복해 기준 충족 여부로 개선을 판정

### 기준 기반 반복 평가

```text
핵심 과업·목표 기준 설정
    ↓
프로토타입 사용성 테스트
    ↓
기준 대비 판정 → 미충족 시 개선·재평가
```

### 확대: 판정

```text
완료율·시간·오류
    ├─ 기준 충족 → 다음 단계
    └─ 미충족 → 문제 원인 분석 후 개선
```

### 선택 근거: 개발 후 일회성 평가와의 비교

| 구분 | 개발 후 일회성 | 제언: 기준 기반 반복 |
|---|---|---|
| 문제 발견 | 후반 | 초기 |
| 수정 비용 | 큼 | 작음 |
| 판정 | 주관적 | 목표 기준 |
