## Ⅰ. 사용성 평가 및 사용성 테스트의 개요

- 개념 : 사용자가 제품이나 서비스를 사용하는 과정에서 겪는 편의성, 직관성, 만족도를 측정하고, 실제 사용자가 주어진 과업(Task)을 수행하는 모습을 관찰·기록하여 인터페이스 상의 문제점을 발견하고 개선하는 사용자 중심(User-Centered) 평가 기법.
- 배경 및 필요성 : 개발자 관점의 기능 구현만으로는 복잡한 사용 시나리오에서 사용자 이탈(Churn Rate)을 막을 수 없으며, 디지털 서비스의 성공을 위해 고객 경험(UX) 최적화 필수.
- 국제 표준 : **ISO 9241-11** (사용성 정의: 효과성, 효율성, 만족도).

## Ⅱ. 사용성 테스트(UT)의 수행 절차 및 측정 프레임워크

```text
   [ 1. 테스트 계획 수립 ] ──> [ 2. 참가자 모집 ] ──> [ 3. 테스트 세션 실행 ] ──> [ 4. 분석 및 개선 보고 ]
    - 테스트 목표, 과업 시나리오  - 타깃 사용자 5~8명      - 싱크 얼라우드(Think-Aloud)  - 문제점 우선순위 도출
    - 정량/정성 평가 지표 수립    - 페르소나 매칭          - 과업 성공률, 시간 측정      - UI 개선 권고사항 제시
```

- **형성적 평가 (Formative Evaluation)** : 개발 초기 프로토타입 단계에서 UI 결함을 조기에 발견하고 설계를 수정하기 위해 반복적으로 수행.
- **총괄적 평가 (Summative Evaluation)** : 개발 완료 시점에 이전 버전이나 경쟁사 대비 사용성 목표(성공률 목표치 등)를 달성했는지 정량적으로 검증.
- **싱크 얼라우드 (Think-Aloud Protocol)** : 사용자가 과업을 수행하면서 머릿속으로 떠오르는 생각과 감정을 말로 소리 내어 표현하게 하여 인지적 마찰 지점 포착.

## Ⅲ. 주요 사용성 평가 방법 비교

| 평가 방법 | 수행 주체 | 수행 시점 | 장점 | 단점 |
|---|---|---|---|---|
| **사용자 테스트** (UT) | 실제 표본 사용자 | 프로토타입 및 완성 단계 | 실제 사용자의 행동 데이터 및 숨은 마찰 지점 정확히 포착 | 환경 구축 및 모집 비용 발생 |
| **휴리스틱 평가** (Heuristic) | UX 전문 평가자 (3~5명) | 설계 초기~전 단계 | 닐슨의 원칙을 바탕으로 빠르고 경제적으로 광범위한 결함 검출 | 실제 사용자의 감성적 반응 반영 한계 |
| **인지적 워크스루** (Cognitive) | 설계자 및 개발팀 | 초기 상세 설계 단계 | 초보 사용자의 학습 용이성(Learnability) 검증에 탁월 | 복합적이고 전문적인 숙련 과업 평가 한계 |
| **SUS 설문** (System Usability Scale) | 사용자 (사후 설문) | 테스트 직후 | 10문항 표준 설문으로 0~100점의 객관적 사용성 점수 정량화 | 구체적인 UI 결함 위치 파악 불가 |

## Ⅳ. 사용성 테스트(Usability Testing)의 주요 한계점 및 해결 방안

- 실험실 환경에서의 관찰자 효과(Hawthorne Effect) 및 표본 편향 :
  - 한계점 : 테스트 참여자가 관찰당하고 있음을 인지하여 자연스러운 사용 패턴 대신 과도하게 정돈된 행동을 보이거나 특정 인구통계학적 편향 발생.
  - 해결 방안 : 실제 사용 환경에서의 비동기 원격 비간섭 테스트(Unmoderated Remote Testing) 병행, 정량적 로그(GA, Hotjar)와의 교차 검증을 통한 이상치 필터링.
- 정성적 발견점의 객관화 및 엔지니어링 티켓 전환 난제 :
  - 한계점 : '사용자가 결제 화면에서 머뭇거림'과 같은 모호한 관찰 결과는 구체적인 시스템 결함이나 기능 요구사항으로 직결되지 못해 개선 작업 누락.
  - 해결 방안 : 심각도 평가 매트릭스(영향도, 빈도, 지속성) 기반 이슈 점수화, 화면별 표준 태스크 성공률 및 완료 시간(TCT)을 정량 SLA 지표로 관리.
- 빠른 애자일 릴리스 주기 대비 높은 평가 수행 공수 :
  - 한계점 : 사용자 모집, 시나리오 설계, 세션 진행 및 분석에 상당한 기간이 소요되어 짧은 스프린트 주기 내 사용성 피드백 반영 불가.
  - 해결 방안 : 5명 내외 소규모 표본을 대상으로 하는 게릴라 테스팅(RITE 방법론, Rapid Iterative Testing and Evaluation) 도입 및 프로토타입 단계 선행 검증.

## Ⅴ. 현대 UX 엔지니어링을 위한 기술사적 제언

- 정량적 로그 분석(A/B 테스팅)과 정성적 UT의 융합 : 정량적 클릭스트림 데이터(Google Analytics, Hotjar 히트맵)를 통해 '어디서 이탈하는가(Where)'를 파악하고, 심층 사용성 테스트(UT)를 통해 '왜 이탈하는가(Why)'를 밝혀내는 데이터 기반 UX 개선 체계 정립.
- 다양성을 고려한 접근성(Accessibility) 기반 사용성 평가 필수화 : 고령자, 시각/지체 장애인 등 다양한 디지털 취약계층을 사용성 평가 패널에 필수 포함하여 전자정부 웹 접근성 지침 및 장애인차별금지법 컴플라이언스 선제 달성.
