## 연관 키워드
- 기술 부채, 부채 원금·이자, 의도성·신중성 4분면, SQALE, 부채 등록부

### Ⅰ. 기술 부채의 개요

- 핵심 요약 : 기술 부채는 빠른 선택이나 구조적 결함이 미래 변경 비용을 높이는 누적된 기술적 부담.
- 개념 : 단기 개발 편의로 인해 발생한 향후 수정·운영 비용을 부채의 원금과 이자에 비유한 개념(**기술 부채**, Technical Debt).
- 배경 및 필요성 : 일정 압박·설계 부족·노후 의존성으로 품질 저하가 장기 생산성을 잠식.
- 주요 목적 : 부채를 가시화·우선순위화해 기능 개발과 상환을 균형 관리.

### Ⅱ. 기술 부채의 특징 및 장점

- 핵심 요약 : 부채 원금은 개선 비용, 이자는 부채로 인해 반복되는 추가 작업·장애·변경 지연.

1. 의도적·신중 : 검증된 단기 선택 → 명시된 상환 계획 필요.
2. 의도적·무모 : 품질 활동 생략 → 결함과 재작업 증가.
3. 비의도적·신중 : 학습·요구 변화로 뒤늦게 발견 → 설계 재평가 필요.
4. 비의도적·무모 : 역량·통제 부족 → 지속적 위험·운영 비용 확대.

### Ⅲ. 기술 부채 관리 흐름 (구조)

- 핵심 요약 : 식별·분류 → 비용·위험 추정 → 우선순위화 → 상환·수용 결정 → 지표로 재평가.

```text
코드·아키텍처·테스트 분석
   ↓ 부채 항목·소유자 등록
원금·이자·위험 추정 → 우선순위 결정
   ↓ 상환 / 수용 / 회피
품질 게이트·SQALE·지표 모니터링
```

```text
신규 기능·장애 처리량
        ↑ 부채 이자 증가 시 감소
부채 원금 투자 → 구조 개선 → 변경 비용·결함률 감소
```

### Ⅳ. 기술 부채와 결함·리팩토링 비교

- 핵심 요약 : 결함은 잘못된 동작, 부채는 미래 변경 비용을 키우는 설계 선택·상태, 리팩토링은 개선 수단.

| 비교 축 | 결함 | 기술 부채 | 리팩토링 |
|---|---|---|---|
| 성격 | 요구와 다른 실행 결과 | 향후 비용·위험을 낳는 부담 | 구조를 개선하는 활동 |
| 조치 | 수정·검증 | 상환·수용·회피 결정 | 부채 상환에 활용 가능 |
| 관계 | 부채의 결과일 수 있음 | 결함 없이도 존재 | 부채 관리 방법 중 하나 |

### Ⅴ. 기술 부채 관리 한계와 대응

- 핵심 요약 : 주관적 점수와 기능 압박이 상환을 미루므로 근거·소유자·수용기간을 등록.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 부채 정의 모호 | 목록 과다·비교 불가 | 유형·근거·영향 표준화 | 부채 항목 수 |
| 기능 우선 압박 | 이자 누적·속도 저하 | 일정 용량의 상환 작업 반영 | 상환 작업 비율 |
| 상환 성과 불명 | 투자 가치 설명 어려움 | 리드타임·결함·변경 실패 추적 | 상환 효과 지표 |

### Ⅵ. 기술 부채 제언

- 핵심 요약 : 제품 책임자는 부채 등록부와 품질 게이트를 로드맵·아키텍처 의사결정에 연결.

1. 개발팀은 원인·영향·상환안·소유자를 부채 항목에 기록.
2. PO는 기능 편익과 미래 이자를 비교해 상환 우선순위를 결정.
3. 아키텍트는 SQALE 등 측정법을 보조 근거로 사용하고 수치만으로 판단하지 않음.

### Ⅶ. 결론

- 핵심 요약 : 기술 부채는 제거 대상만이 아니라 비용·위험을 알고 관리해야 하는 기술 자산 상태.
- 시사점 : 지속 가능한 속도는 신규 기능과 부채 상환의 균형에서 형성.
