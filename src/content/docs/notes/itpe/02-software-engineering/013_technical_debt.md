## 연관 키워드

- 기술 부채, 부채 원금·부채 이자, 의도성·신중성 4분면
- 부채 등록부, SQALE, 품질 게이트, 리팩토링

## Ⅰ. 기술 부채의 개요

- 핵심 요약 : 기술 부채는 단기 개발 속도를 얻기 위해 생략·지연한 품질 활동이 미래 변경 비용으로 누적되는 상태.
- 개념 : 빠른 출시를 위한 설계·품질 생략이 장기적으로 추가 비용을 발생시키는 상태를 부채에 비유한 개념(**기술 부채**, Technical Debt), 워드 커닝엄(Ward Cunningham)의 비유에서 유래.
- 배경 및 필요성 : 일정 압박 속 임시 해결과 테스트·문서 생략의 누적이 변경 비용과 장애 빈도의 증가로 이어지는 상황.
- 주요 목적 : 부채의 가시화와 의사결정 대상화를 통한 지속 가능한 개발 속도 확보.

## Ⅱ. 기술 부채의 특징 및 장점

- 핵심 요약 : 원금·이자 구조와 4분면 분류가 부채를 경영 판단의 대상으로 전환하는 장점.

1. **부채 원금** (Debt Principal) 구조 : 구조 개선에 필요한 일회성 상환 비용 → 상환 여부의 투자 판단 가능.
2. **부채 이자** (Debt Interest) 구조 : 상환 전까지 반복되는 추가 작업·장애 대응 비용 → 미상환 비용의 정량화.
3. **의도성·신중성 4분면** 분류 : 선택의 의도와 신중함에 따른 유형 구분 → 유형별 차등 관리 전략 수립.
4. 측정 기반 관리 : 정적 분석과 **부채 등록부** 기록 → 부채를 로드맵·예산 논의의 대상으로 전환.

## Ⅲ. 기술 부채의 구조 (흐름)

- 핵심 요약 : 식별→추정→우선순위→상환·수용→재평가의 순환과 4분면별 대응으로 운영.
- **SQALE** (Software Quality Assessment based on Lifecycle Expectations) : 소스 코드 품질을 생애주기 비용 관점에서 정량 평가하는 방법론.
- **품질 게이트** (Quality Gate) : 정해진 품질 기준 통과를 다음 단계 진행 조건으로 두는 차단 기준.

```text
[ 기술 부채 관리 흐름 ]

부채 식별(정적 분석·등록부 기록)
   ↓
원금·이자·위험 추정
   ↓
우선순위 결정
   ↓
상환 / 수용 / 회피 선택
   ↓
지표 추적·재평가
```

```text
[ 의도성·신중성 4분면 대응 ]

의도적 + 신중한 부채
   → 상환 일정을 약속한 선택
의도적 + 무모한 부채
   → 품질 활동 생략, 즉시 교정
비의도적 + 신중한 부채
   → 지식 습득 후 재설계
비의도적 + 무모한 부채
   → 검토 절차·역량 보강
```

- 상환 수단 : **리팩토링** (Refactoring, 동작 변경 없이 내부 구조를 개선하는 활동)과 재설계·문서 보강을 상황별로 선택.

## Ⅳ. 기술 부채와 선제적 설계 투자의 비교

- 핵심 요약 : 기술 부채가 사후 상환·이자 누적의 부담이라면 선제적 설계 투자는 구현 전 품질 기반 마련의 선택.
- 선제적 설계 투자 : 품질 비용을 로드맵에 명시하고 구현 전에 구조·자동화에 투입하는 접근.

| 비교 축 | 기술 부채 | 선제적 설계 투자 |
| --- | --- | --- |
| 지출 시점 | 문제 인식 후 상환 | 구현 전·진행 중 투입 |
| 비용 성격 | 이자 형태의 반복 비용 | 원금 형태의 일회성 투자 |
| 의사결정 | 긴급 대응·암묵적 선택이 많음 | 로드맵·예산의 명시적 반영 |
| 결과 | 변경 비용·장애 누적 위험 | 변경 용이성·품질 기반 확보 |

## Ⅴ. 기술 부채 관리의 한계와 방안

- 핵심 요약 : 정의 모호성과 기능 개발 압박이 상환 지연을 낳으므로 기준 표준화·상환 용량·효과 추적 필요.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 부채 정의 모호 | 항목 과다·우선순위 판단 불가 | 유형·근거·영향 기준 표준화 | 등록 항목 기준 충족률 |
| 기능 개발 압박 | 상환 지연 → 이자 누적 | 일정 비율의 상환 용량 확보 | 상환 작업 비율 |
| 상환 효과 불명 | 투자 가치 설명 곤란 | 리드타임·결함·변경 실패 추적 | 상환 전후 지표 비교 |

## Ⅵ. 기술 부채에 대한 제언

- 핵심 요약 : 부채 관리를 품질 조직 단위 활동이 아닌 제품·아키텍처 거버넌스 절차로 통합 필요.

1. 제품 책임 조직은 상환 항목을 로드맵에 기능과 동등한 항목으로 편성.
2. 아키텍처 조직은 신규 부채 유입을 차단하는 품질 게이트를 개발 파이프라인에 내장.
3. 경영 협의 체계는 상환 투자의 편익을 기능 투자와 동일 기준으로 심의.

## Ⅶ. 결론

- 핵심 요약 : 기술 부채는 제거 대상이 아니라 비용·위험을 알고 운용하는 경영 판단 대상.
- 기능 개발과 상환의 균형이 조직의 지속 가능한 속도를 결정하는 요소.
