## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 테스트·검증 → **통합 테스트(Integration Test)**

## 30초 인출

- 본질: 통합 테스트는 단위 테스트를 마친 모듈을 결합해 모듈 사이의 인터페이스와 상호작용의 결함을 찾는 테스트
- 메커니즘: 하향식은 상위 모듈부터 시험하며 아직 없는 하위 모듈을 스텁으로, 상향식은 하위 모듈부터 시험하며 없는 상위 모듈을 드라이버로 대신
- 통찰: 한꺼번에 결합하면 결함 원인을 찾기 어려우므로 모듈을 단계적으로 결합하되 핵심 흐름이 상위에 있으면 하향식, 하위 공통 모듈이 중요하면 상향식으로 선택

<details>
<summary>핵심 용어</summary>

- **통합 테스트(Integration Test)** : 결합한 모듈 사이의 인터페이스 결함을 찾는 테스트
- **테스트 스텁(Test Stub)** : 아직 없는 하위 모듈을 대신해 정해진 값을 돌려주는 임시 모듈
- **테스트 드라이버(Test Driver)** : 아직 없는 상위 모듈을 대신해 시험 대상을 호출하는 임시 모듈
- **하향식 통합** : 상위 모듈에서 하위 모듈 방향으로 결합하며 시험하는 방식
- **상향식 통합** : 하위 모듈에서 상위 모듈 방향으로 결합하며 시험하는 방식
- **빅뱅 통합** : 모든 모듈을 한꺼번에 결합해 시험하는 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. 통합 테스트의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **통합 테스트** 는 결합한 모듈 사이의 인터페이스와 상호작용의 결함을 찾는 테스트 |
| 목적 | 모듈 간 연동 결함의 조기 발견 |

## Ⅱ. 단위 테스트와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 모듈 간 관계 | 개별 모듈이 아닌 연동 검증 |
| 인터페이스 결함 | 데이터 전달·호출 규약 오류 발견 |
| 임시 모듈 사용 | 미완성 모듈을 스텁·드라이버로 대체 |

## Ⅲ. 하향식 통합과 스텁

```text
        [A] 상위 모듈 (실제)
        /    \
   [B] 실제  [C] 스텁 (아직 없는 하위 모듈의 임시 응답)
```

상향식은 반대로 하위 모듈부터 시험하며, 없는 상위 모듈 자리에 드라이버가 시험 대상을 호출

## Ⅳ. 통합 방식의 비교

| 구분 | 빅뱅 | 하향식 | 상향식 |
|---|---|---|---|
| 순서 | 한꺼번에 결합 | 상위 → 하위 | 하위 → 상위 |
| 임시 모듈 | 없음 | 스텁 | 드라이버 |
| 결함 원인 파악 | 어려움 | 쉬움 | 쉬움 |
| 강점 | 단순 | 핵심 제어 흐름을 먼저 검증 | 하위 공통 모듈을 먼저 검증 |
| 약점 | 원인 추적 곤란 | 스텁 작성 부담 | 전체 흐름은 마지막에 확인 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 한꺼번에 결합해 결함 원인 추적 곤란 | 단계적 결합 |
| 스텁·드라이버 작성 부담 | 간단한 응답부터 작성해 점차 실제 모듈로 교체 |
| 모듈 간 계약 변경으로 연동 오류 | 인터페이스 규약(계약) 시험 병행 |

## Ⅵ. 제언

핵심 흐름이 상위 모듈에 있으면 하향식, 하위 공통 모듈의 비중이 크면 상향식으로 단계적 통합

```text
시스템 특성
    ├─ 상위 제어 흐름이 핵심 → 하향식(스텁)
    └─ 하위 공통 모듈이 핵심 → 상향식(드라이버)
```

| 구분 | 빅뱅 | 제언: 단계적 통합 |
|---|---|---|
| 결함 위치 | 불명확 | 결합 단계로 좁힘 |
| 조기 발견 | 늦음 | 결합 시점마다 |
