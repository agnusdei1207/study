## Ⅰ. 통합 테스트의 개요

- **개념** : 단위 테스트(Unit Test)를 통과한 개별 소프트웨어 모듈, 컴포넌트 또는 마이크로서비스들을 서로 결합하여 통합하는 과정에서 발생하는 인터페이스 불일치, 데이터 교환 오류, 통신 프로토콜 장애를 식별하고 검증하는 소프트웨어 테스팅 단계.
- **배경 및 필요성** : 각 모듈이 독립적으로는 완벽하게 동작하더라도 모듈들이 결합되는 접점(Interface)에서 매개변수 타입 불일치, 데이터 포맷 오해, 동기화 타이밍 결함이 집중적으로 발생하므로 필수.
- **V-모델 위치** : 상세 설계(Detailed Design) 단계와 1:1로 대응하여 인터페이스 정합성 검증.

## Ⅱ. 통합 테스트의 주요 접근 전략

```text
   [ 1. 빅뱅 통합 (Big-Bang) ] ──────── 모든 모듈을 한꺼번에 일괄 결합 후 테스트 (결함 격리 난해)

   [ 2. 하향식 통합 (Top-Down) ] ────── 상위 제어 모듈부터 결합 (테스트 스텁: Stub 사용)
    [ Main Module ] ──> [ Stub A ] / [ Stub B ] (아직 미개발된 하위 모듈을 임시 가짜 객체로 대체)

   [ 3. 상향식 통합 (Bottom-Up) ] ───── 최하위 단위 모듈부터 결합 (테스트 드라이버: Driver 사용)
    [ Driver ] ──> [ Lower Module C ] / [ Lower Module D ] (상위 제어기 역할을 모의 호출)

   [ 4. 샌드위치 통합 (Sandwich) ] ──── 상향식과 하향식을 결합하여 중간 핵심 계층을 중심으로 동시 통합
```

- **테스트 스텁 (Stub)** : 하향식 통합 시 아직 개발되지 않은 하위 모듈의 역할을 흉내 내어 고정된 값을 반환해 주는 가짜 임시 프로그램.
- **테스트 드라이버 (Driver)** : 상향식 통합 시 아직 개발되지 않은 상위 제어 모듈을 대신하여 하위 모듈에 입력을 전달하고 출력을 확인하는 가짜 호출 프로그램.

## Ⅲ. 하향식, 상향식, 빅뱅 통합 테스트의 비교

| 비교 항목 | 빅뱅 통합 (Big-Bang) | 하향식 통합 (Top-Down) | 상향식 통합 (Bottom-Up) |
|---|---|---|---|
| 통합 방식 | 전 모듈을 일괄 결합 후 일시 검증 | 최상위 메인 모듈부터 하향식 점진 통합 | 최하위 기능 모듈부터 상향식 점진 통합 |
| 결함 위치 파악 | 극도로 난해 (원인 모듈 특정 불가) | 모듈 결합 시마다 즉시 특정 가능 | 즉시 특정 가능 |
| 필요 보조 도구 | 없음 | 테스트 스텁(Stub) 다수 작성 필요 | 테스트 드라이버(Driver) 다수 작성 필요 |
| 주요 장점 | 소규모 시스템에서 빠른 수행 | 시스템 전반의 제어 흐름과 UI 조기 검증 | 하위 핵심 알고리즘 및 데이터 처리 조기 검증 |
| 주요 단점 | 디버깅 비용 폭증, 결함 격리 실패 | 하위 모듈의 정밀한 계산 검증 지연 | 상위 제어 흐름 검증이 후반부로 지연 |

## Ⅳ. 현대 마이크로서비스 환경에서의 기술사적 제언

- **Mock 서버 및 Testcontainers를 활용한 격리 통합 테스트** : 실제 외부 결제 PG사나 서드파티 API에 의존하는 통합 테스트는 비용과 네트워크 불안정성을 유발하므로, WireMock을 활용한 API 가상화 및 Docker 기반의 Testcontainers로 실제 DB(PostgreSQL/Redis) 인스턴스를 컨테이너로 띄워 격리 검증하는 현대적 통합 테스트 아키텍처 수립.
- **소비자 주도 계약 테스팅(CDC, Consumer-Driven Contract Testing)** : 여러 팀이 분산 개발하는 MSA 환경에서 API 인터페이스 파손을 방지하기 위해, Pact 프레임워크를 도입하여 API 소비자가 기대하는 요청/응답 규약을 사전에 정의하고 제공자의 CI 파이프라인에서 자동 검증 강제.
