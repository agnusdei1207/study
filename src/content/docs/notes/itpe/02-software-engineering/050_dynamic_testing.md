## 연관 키워드

- 동적 테스트, 정적 테스트, 테스트 오라클
- 블랙박스 테스트, 화이트박스 테스트, 경험 기반 테스트, DAST

## Ⅰ. 동적 테스트의 개요

- 핵심 요약 : 소프트웨어를 실제로 실행해 결함을 검출하는 실행 기반 시험.
- 개념 : 대상 소프트웨어를 실행 환경에서 구동하면서 입력을 주입하고 출력을 관찰해 결함을 검출하는 기법 (**동적 테스트**, Dynamic Testing).
- 배경 및 필요성 : 코드 검토만으로는 확인이 불가능한 런타임 결함, 즉 메모리 누수·교착 상태(Deadlock)·성능 저하가 실행 시점에 존재하는 상황.
- 주요 목적 : 실제 동작 상태에서의 결함 조기 발견과 소프트웨어 품질의 객관적 입증.

## Ⅱ. 동적 테스트의 특징 및 장점

- 핵심 요약 : 실제 실행이라는 원리가 실행 시점 결함의 발견과 품질 입증이라는 효과로 연결되는 시험 체계.

1. 실행 기반 검증 : 운영과 유사한 환경에서 입력을 주입하고 출력을 관찰 → 실행 중에만 드러나는 결함의 발견.
2. 명세 기반 검증 : 기능 명세에서 도출한 입력으로 수행하는 **블랙박스 테스트**(내부 구조를 보지 않는 시험)의 적용 → 동등 분할·경계값 분석으로 명세 충족 여부의 확인.
3. 구조 기반 검증 : 코드의 실행 경로를 기준으로 삼는 **화이트박스 테스트**(내부 구조를 보는 시험)의 적용 → 문장·분기 커버리지 확보와 미검증 경로의 최소화.
4. 경험 기반 검증 : 테스터의 경험과 직관에 의존하는 **경험 기반 테스트**(오류 추정, 탐색적 테스팅)의 적용 → 명세에 없는 결함의 발견.
5. 객관적 판정 : 기대 결과를 정의한 **테스트 오라클**(Test Oracle)과 실측 결과의 대조 → 합격 여부의 객관적 판정과 결함 보고의 일관성.

## Ⅲ. 동적 테스트의 구조 (흐름)

- 핵심 요약 : 계획에서 재시험까지 이어지는 수행 흐름과, 정적 테스트 뒤에 동적 테스트를 배치하는 단계 구조.
- 수행 흐름은 준비 단계와 실행·판정 단계의 순차 진행을 전제.

```text
[ 동적 테스트 수행 흐름 ]

테스트 계획과 환경 구축
   ↓
테스트 케이스 설계
   ↓
입력 주입과 소프트웨어 실행
   ↓
실측 결과의 기록
   ↓
테스트 오라클과의 대조
   ↓
결함 보고와 재시험
```

- 개발 전 주기에서 정적 테스트가 선행하고, 실행 가능한 빌드 이후 동적 테스트가 이어지는 배치.

```text
[ 개발 단계별 시험 배치 ]

요구사항 검토 (정적 테스트)
   ↓
코드 검토·정적 분석 (정적 테스트)
   ↓
단위 시험 (동적 테스트)
   ↓
통합·시스템 시험 (동적 테스트)
   ↓
인수 시험 (동적 테스트)
```

## Ⅳ. 동적 테스트와 정적 테스트의 비교

- 핵심 요약 : 프로그램 실행 여부를 기준으로 나뉘는 두 시험은 발견 결함의 유형이 달라 상호 보완 관계.

| 비교 축 | 동적 테스트 | 정적 테스트 |
| --- | --- | --- |
| 실행 여부 | 프로그램을 실제로 구동 | 코드·문서를 실행 없이 검토 |
| 검증 대상 | 실행 결과와 런타임 상태 | 코드, 설계 문서, 요구사항 명세 |
| 대표 기법 | 블랙박스·화이트박스·경험 기반 테스트 | 동료 검토, 인스펙션, 정적 분석 도구 |
| 발견 결함 | 런타임 예외, 성능 저하, 교착 상태 | 코딩 표준 위반, 논리 오류, 명세 모순 |
| 수행 시점 | 실행 가능한 빌드 확보 이후 | 요구분석·설계·코딩 전 단계부터 |

## Ⅴ. 동적 테스트의 한계와 방안

- 핵심 요약 : 환경 준비, 간헐적 실패, 실행 시간의 세 부담이 시험의 신뢰성과 신속성을 제약하는 상황.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 환경 구축 부담 | 운영과 유사한 환경·테스트 데이터의 준비 공수 → 시험 착수 지연 | 컨테이너 기반 환경의 자동 구성 | 환경 구축 소요 시간 |
| 간헐적 실패 | 비동기 타이밍·외부 의존에 따른 비결정적 결과 → 재시험 증가와 판정 신뢰성 저하 | 외부 의존의 격리, 실패 재현 로그의 확보 | 간헐 실패율 |
| 실행 시간 증가 | 회귀 시험의 축적 → 피드백 지연과 배포 지체 | 위험도 기반 선별 실행, 병렬 실행 | 전체 실행 시간 |

## Ⅵ. 동적 테스트 체계화에 대한 기술사적 제언

- 핵심 요약 : 시험 활동을 개발 파이프라인과 품질 거버넌스 안에 통합하는 수준으로 제도화 필요.
- 체계 : CI(Continuous Integration) 파이프라인에 동적 테스트를 상시 단계로 편성하는 시험 자동화 체계의 구축.
- 보안 : 운영과 유사한 환경에서 **DAST**(Dynamic Application Security Testing)를 연계해 런타임 웹 취약점을 배포 전에 점검하는 절차의 정례화.
- 거버넌스 : 정적 검토와 동적 시험의 역할 분담 기준과 수행 시점을 품질 표준으로 제정.

## Ⅶ. 결론

- 핵심 요약 : 동적 테스트는 실행 상태의 품질을 입증하는 최종 검증 수단.
- 정적 테스트와의 결합이 소프트웨어 전 단계 품질 확보의 정석.
