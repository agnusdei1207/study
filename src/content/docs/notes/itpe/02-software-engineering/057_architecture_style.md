## 연관 키워드

- 아키텍처 스타일(Architecture Style), 구성요소(Components), 커넥터(Connectors)
- 계층형(Layered), 이벤트 기반(EDA), 마이크로커널(Plugin), 마이크로서비스(MSA), 공간 기반(Space-Based)
- 품질속성 트레이드오프, 모놀리식 퍼스트(MonolithFirst), 스트랭글러 피그(Strangler Fig), ADR(Architecture Decision Record)

## Ⅰ. 아키텍처 스타일의 개요

- 핵심 요약 : 시스템의 기본 구조를 결정하는 구성요소와 커넥터의 배치 패턴으로, 검증된 설계 유형의 재사용을 통해 비기능 품질속성의 조기 달성을 지원하는 체계.
- 개념 : 소프트웨어 시스템의 기본 구조와 동작 방식을 결정하는 구성요소(Components)와 커넥터(Connectors)의 배치 유형 및 시스템 설계 제약조건의 집합적 패턴.
- 배경 및 필요성 : 개발팀 간의 공통된 아키텍처 어휘 확립과 이미 검증된 패턴의 재사용을 통한 비기능 품질속성(성능, 가용성, 확장성, 변경용이성)의 조기 달성 요구.
- 주요 목적 : 시스템 특성에 적합한 구조 유형의 선정을 통해 품질·비용·일정의 균형 확보와 아키텍처 의사결정의 표준화 달성.

## Ⅱ. 아키텍처 스타일의 특징

- 핵심 요약 : 각 스타일은 고유한 구성요소 배치와 데이터 흐름을 통해 서로 다른 품질속성 트레이드오프를 제공하는 설계 유형.
1. 계층형(Layered) : 가장 보편적인 구조로 각 계층이 명확한 책임을 가지며, 단방향 호출 원칙과 관심사의 분리를 달성. 단순 CRUD(Create, Read, Update, Delete) 작업에서도 모든 계층을 관통하는 싱크홀(Sinkhole) 안티패턴 위험 존재.
2. 이벤트 기반(EDA, Event-Driven Architecture) : 비동기 이벤트를 매개로 생산자와 소비자가 완전 격리되어 고도의 수평 확장성과 반응성을 제공하나, 분산 트랜잭션 관리와 에러 추적의 복잡성 수반.
3. 마이크로커널(Microkernel, Plugin) : 최소한의 코어 시스템에 독립적인 플러그인을 동적으로 장착하여 확장하며, IDE(Integrated Development Environment)와 브라우저 확장에 적합.
4. 마이크로서비스(MSA, Microservice Architecture) : 도메인 단위의 독립 서비스 조합으로 극도의 배포 용이성과 확장성을 제공하나, 네트워크 홉 오버헤드와 분산 데이터 일관성 문제 수반.
5. 공간 기반(Space-Based) : 인메모리 데이터 그리드를 통한 처리 분산으로 스파이크 트래픽 상황에서 극도의 성능과 확장성 확보.

## Ⅲ. 아키텍처 스타일의 구조 (흐름)

- 핵심 요약 : 스타일별로 상이한 구성요소 배치와 단방향·비동기 데이터 흐름 구조.

```text
[ 계층형 (Layered) ]
Presentation(프레젠테이션)
   ↓ 단방향 호출
Business Logic(비즈니스 로직)
   ↓
Persistence(영속성)
   ↓
Database(데이터베이스)
```

```text
[ 이벤트 기반 (EDA) ]
[ Producer ] ──(이벤트 발행)──> [ Event Broker ]
                     │
          ┌──────────┴──────────┐
          ▼                     ▼
    [ Consumer ]          [ Consumer ]

[ 마이크로커널 (Plugin) ]
[ Core System ] ──(플러그인 등록)──> [ Plugin A | Plugin B | Plugin C ]
```

- 계층형 흐름의 핵심 : 상위 계층의 하위 계층 단독 호출 규칙을 통한 관심사의 분리.
- 이벤트 기반 흐름의 핵심 : 브로커 경유의 비동기 발행·구독을 통한 생산자와 소비자 간 결합도 제거.

## Ⅳ. 대표 아키텍처 스타일의 품질속성 트레이드오프 비교

- 핵심 요약 : 민첩성·배포 용이성·성능·확장성·개발 용이성의 축에서 스타일별 강점이 상이하므로, 비즈니스 드라이버 기반의 선택 기준 수립 필요.

| 아키텍처 스타일 | 전반적 민첩성(Agility) | 배포 용이성 | 성능(Performance) | 확장성(Scalability) | 개발 용이성 |
|---|---|---|---|---|---|
| 계층형(Layered) | 낮음 | 낮음(모놀리식) | 보통(계층 오버헤드) | 낮음 | 높음(친숙함) |
| 마이크로커널(Plugin) | 높음 | 높음(플러그인별) | 높음 | 낮음 | 높음 |
| 이벤트 기반(EDA) | 높음 | 높음 | 높음(비동기 처리) | 극도로 높음 | 복잡함 |
| 마이크로서비스(MSA) | 극도로 높음 | 극도로 높음 | 보통(네트워크 홉) | 극도로 높음 | 복잡함 |
| 공간 기반(Space-Based) | 높음 | 높음 | 극도로 높음(인메모리) | 극도로 높음 | 복잡함 |

```text
[ 스타일 선정 흐름 ]
비즈니스 드라이버 정의
   ↓
후보 스타일 도출
   ↓
품질속성 시나리오 평가
   ↓
트레이드오프 절충
   ↓
하이브리드 구성 및 ADR 기록
```

## Ⅴ. 아키텍처 스타일 적용의 장점과 한계

- 핵심 요약 : 검증된 패턴의 재사용 효과와 유행 추종·전환 실패 리스크가 공존하므로, 도메인 적합성 평가와 점진적 전환 전략의 병행 필요.
- 장점
  1. 검증된 패턴의 재사용을 통한 비기능 품질속성의 조기 달성.
  2. 공통 아키텍처 어휘를 통한 이해관계자 의사소통 효율화.
  3. 스타일별 트레이드오프의 사전 인지를 통한 합리적 설계 의사결정.
- 한계점 1 : 유행 추종형 아키텍처 선정(Resume-Driven Architecture)의 폐해
  - 한계점 : 비즈니스 도메인의 복잡도와 트래픽 규모가 단순함에도 최신 유행만을 좇아 MSA나 EDA를 도입하여 막대한 네트워크 지연과 운영 비용 초래.
  - 해결 방안 : 마틴 파울러의 모놀리식 퍼스트(MonolithFirst) 전략 채택으로 초기에는 모듈러 모놀리스(Modular Monolith)로 출발하고, 비즈니스 규모 성장에 따른 분산 스타일로의 점진적 진화(Evolutionary Architecture) 추구.
- 한계점 2 : 아키텍처 스타일 고유의 품질 속성 트레이드오프 간과
  - 한계점 : 마이크로서비스의 독립 배포성에만 매몰되어 분산 트랜잭션 데이터 일관성 결여, 복잡한 네트워크 장애 추적 등 스타일 고유의 대가에 대한 사전 대비 부재.
  - 해결 방안 : 품질 속성 시나리오 매트릭스 기반의 각 스타일 페널티 요소 사전 정량 평가, 이벤트 주도 비동기 통신과 서비스 메시 등 보완 패턴의 세트 구성.
- 한계점 3 : 레거시 스타일에서 신규 스타일로의 전환(Migration) 실패
  - 한계점 : 기존 계층형 모놀리식 시스템의 분산 스타일 일괄 전환(Big-Bang) 시도 시 업무 공백, 데이터 불일치 및 예산 고갈로 프로젝트 좌초.
  - 해결 방안 : 스트랭글러 피그(Strangler Fig) 패턴 기반의 외곽 도메인 점진 분리, 변경 데이터 캡처(CDC, Change Data Capture)를 통한 무중단 데이터 동기화 체계 구축.

## Ⅵ. 엔터프라이즈 아키텍처 선정을 위한 기술사적 제언

- 핵심 요약 : 비즈니스 드라이버 기반의 도메인 적합성 평가 선행과 하이브리드 아키텍처의 통합 거버넌스 확립.
- 시스템 핵심 비즈니스 드라이버에 기반한 스타일 결정 : 단일 스타일의 고집을 지양하고, 빠른 시장 출시와 도메인 격리 요구 시 MSA, 예측 불가능한 스파이크 트래픽 대응 시 공간 기반 아키텍처를 선택하는 도메인 적합성 평가 선행.
- 하이브리드 아키텍처의 통합 거버넌스 수립 : 코어 모놀리스(계층형) 주변에 비동기 이벤트 파이프라인(Kafka)과 마이크로커널 플러그인이 결합된 혼합 형태가 보편적이므로, ADR을 통한 각 영역의 스타일 선택 근거 문서화 필요.

## Ⅶ. 결론

- 핵심 요약 : 아키텍처 스타일은 품질속성 트레이드오프의 카탈로그이며, 도메인 적합성과 점진적 진화 관점의 선택이 성패의 분기점.
- 요약 : 계층형, 이벤트 기반, 마이크로서비스 등 각 스타일은 고유한 품질속성 강점과 대가를 지니므로, 비즈니스 드라이버 기반 평가와 ADR 거버넌스를 통한 선정 필요.
- 시사점 : 모놀리식 퍼스트 전략과 스트랭글러 피그 기반 점진 전환으로 유행 추종 리스크와 일괄 전환 실패 리스크의 동시 통제 필요.
