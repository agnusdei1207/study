## 연관 키워드

- OpenTelemetry, 관측 가능성(Observability), 텔레메트리(Telemetry)
- 트레이스, 메트릭, 로그, 컨텍스트 전파, OTLP, Collector, 시맨틱 규약

## Ⅰ. OpenTelemetry의 개요

- 핵심 요약 : OpenTelemetry는 트레이스·메트릭·로그를 표준 방식으로 생성·수집·전송하는 벤더 중립 관측 가능성 프레임워크.
- 개념 : 분산 시스템의 **텔레메트리** (Telemetry, 시스템 상태를 관측 가능한 형태로 만드는 측정 데이터) 생성·수집·처리를 표준 규격으로 정의한 벤더 중립 관측 표준 (**OpenTelemetry**).
- 배경 및 필요성 : 마이크로서비스·클라우드 환경에서 벤더별 계측 방식이 서로 달라 요청 경로 연결·도구 교체 비용 증가.
- 주요 목적 : **관측 가능성** (Observability, 시스템의 외부 출력으로 내부 상태를 파악하는 능력) 향상과 도구 종속 없는 관측 체계 실현.

## Ⅱ. OpenTelemetry의 특징 및 장점

- 핵심 요약 : 3대 신호의 표준화·계측과 분석 도구의 분리·표준 컨텍스트 전파가 상호 운용 가능한 관측 체계로 연결.

1. 3대 신호 통합 : **트레이스** (Trace)·**메트릭** (Metrics)·로그(Logs)를 공통 규격으로 생성 → 요청 경로 기반 상관 분석 가능.
2. 벤더 중립 계측 : 계측 API와 SDK(Software Development Kit) 구현의 분리 → 백엔드 교체 시 재계측 불필요.
3. Collector 파이프라인 : 수신(receivers) → 처리(processors) → 내보내기(exporters) 구성 → 필터·샘플링 같은 공통 처리와 계측·분석 도구의 결합 완화.
4. **컨텍스트 전파** (Context Propagation) : W3C Trace Context 표준 헤더로 trace ID 전달 → 서비스 간 분산 요청의 경로 연결.
5. **시맨틱 규약** (Semantic Convention) : 속성 명명·의미의 표준화 → 서비스 간 일관된 질의·분석 지원.

## Ⅲ. OpenTelemetry의 구조 (흐름)

- 핵심 요약 : API·SDK 계측에서 OTLP 전송·Collector 처리·백엔드 내보내기로 이어지는 표준 파이프라인과 스팬 연결의 트레이스 구조.
- OTLP(OpenTelemetry Protocol) : 텔레메트리 전송용 공개 프로토콜로 백엔드·언어에 독립적인 데이터 교환 담당.

```text
텔레메트리 파이프라인

애플리케이션 계측 (API·SDK)
   ↓
트레이스·메트릭·로그 생성
   ↓
OTLP 전송
   ↓
Collector (수신→처리→내보내기)
   ↓
분석 백엔드 (대시보드·경보)
```

```text
분산 트레이스 구조

요청 수신 (root span 시작)
   ↓
서비스 A 호출 (child span)
   ↓
데이터베이스·외부 서비스 조회
   ↓
동일 trace ID로 경로 병합·응답
```

## Ⅳ. OpenTelemetry와 벤더별 모니터링 에이전트의 비교

- 핵심 요약 : 벤더별 에이전트는 전용 SDK·포맷에 결합되는 반면, OpenTelemetry는 공개 규격으로 계측과 분석 도구를 분리.

| 비교 축 | OpenTelemetry | 벤더별 전용 에이전트·포맷 |
| --- | --- | --- |
| 규격 | 공개 표준·커뮤니티 거버넌스 | 공급자 고유 규격 |
| 계측 방식 | 공통 API·SDK·자동 계측 | 벤더 제공 에이전트 설치 |
| 데이터 형식 | OTLP 등 공개 프로토콜 | 전용 프로토콜·SDK 결합 |
| 백엔드 교체 | 내보내기 대상 변경만 수행 | 재계측·재구축 필요 |
| 신호 연결 | 표준 규약 기반 상관 분석 | 벤더 범위 내 연결 |

- 선택 기준 : 다중 백엔드·장기 이식성이 필요하면 OpenTelemetry, 단일 벤더 전용 기능이 중요하면 전용 에이전트도 유효.

## Ⅴ. OpenTelemetry의 한계와 방안

- 핵심 요약 : 데이터 비용·민감 정보 노출·계측 불균형·전파 단절을 샘플링·마스킹·자동 계측·전파 규약으로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 데이터 비용·카디널리티 폭발 | 고유 속성 과다 → 저장 비용·질의 지연 | 샘플링·카디널리티 한도·속성 최소화 | 시계열 수·수집량 |
| 민감 정보 노출 | 요청 데이터가 계측 데이터에 포함 → 개인정보·보안 위험 | 마스킹·속성 허용 목록 | 유출 점검 건수 |
| 계측 불균형 | 서비스별 미계측 → 관측 사각지대 | 자동 계측·계측 표준 점검 | 서비스 계측률 |
| 전파 단절 | 비동기 경계·미지원 라이브러리 → trace 끊김 | 전파 규약 준수·비동기 컨텍스트 처리 | trace 연결률 |

## Ⅵ. OpenTelemetry 적용에 대한 기술사적 제언

- 핵심 요약 : 플랫폼 조직은 시맨틱 규약·수집 정책·비용 한도를 공통 표준으로 제공하고 신뢰성 운영 체계와 연계.
- 표준 운영 : 플랫폼 팀이 공통 계측 라이브러리·Collector 정책을 중앙 관리해 팀별 편차 제거.
- 비용 거버넌스 : 데이터 보존 기간·샘플링 정책을 예산·한도와 연동한 관리 체계 운영.
- 신뢰성 연계 : SLO(Service Level Objective, 서비스 수준 목표) 정의와 텔레메트리 지표를 연결해 관측 결과가 경보·개선으로 이어지는 체계 구축.

## Ⅶ. 결론

- 핵심 요약 : OpenTelemetry는 계측 데이터를 표준화해 도구 종속 없는 관측 가능성의 기반이 되는 개방형 프레임워크.
- 표준 계측은 분산 시스템 문제를 사용자 요청의 전체 경로로 분석하게 하는 운영 기반 자산.
