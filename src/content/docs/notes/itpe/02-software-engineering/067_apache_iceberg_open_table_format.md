## 연관 키워드

- Apache Iceberg, 오픈 테이블 포맷(Open Table Format)
- 스냅샷, 매니페스트, 원자적 커밋, 숨겨진 파티셔닝, 스키마 진화, 타임트래블

## Ⅰ. Apache Iceberg의 개요

- 핵심 요약 : Apache Iceberg는 데이터 레이크 파일 위에 메타데이터·스냅샷으로 테이블 상태를 관리하는 오픈 테이블 포맷 표준.
- 개념 : 데이터 레이크 파일 위에 트랜잭션·메타데이터를 부여하는 **오픈 테이블 포맷** (Open Table Format)의 대표 표준 (**Apache Iceberg**).
- 배경 및 필요성 : Hive 메타스토어(Hive Metastore) 방식은 디렉터리 나열에 의존해 동시 쓰기 충돌·스키마 변경 부담·시점 조회 불가의 한계 보유.
- 주요 목적 : 저장소·엔진에 독립적인 테이블 의미 부여와 대규모 분석 데이터의 일관된 관리·상호 운용 실현.

## Ⅱ. Apache Iceberg의 특징 및 장점

- 핵심 요약 : 메타데이터 트리·원자적 커밋·파티션·스키마의 유연성이 안정적인 대규모 분석 운영으로 연결.

1. 트리형 메타데이터 계층 : 카탈로그 → 메타데이터 파일 → **매니페스트** (Manifest) 목록 → 데이터 파일 순의 참조 구조 → 디렉터리 나열 없는 빠른 질의 계획.
2. **스냅샷** (Snapshot) 격리 : 변경마다 새 스냅샷 생성 후 **원자적 커밋** (Atomic Commit)으로 포인터 교체 → 트랜잭션 일관성·동시 작업 충돌 통제.
3. **타임트래블** (Time Travel) : 과거 스냅샷 기준의 조회·롤백 → 오류 복구·재현 가능한 분석 지원.
4. **숨겨진 파티셔닝** (Hidden Partitioning) : 파티션 값을 쿼리 작성에 노출하지 않는 구조 → 잘못된 파티션 쿼리 방지·파티션 전략 변경 부담 완화.
5. **스키마 진화** (Schema Evolution) : 열 추가·이름 변경을 메타데이터에만 반영 → 데이터 재작성 없는 테이블 구조 변경.

## Ⅲ. Apache Iceberg의 구조 (흐름)

- 핵심 요약 : 카탈로그 포인터가 메타데이터·매니페스트를 거쳐 데이터 파일을 가리키는 참조 구조와 원자적 커밋의 쓰기 절차.

```text
메타데이터 계층 구조

카탈로그 (현재 위치 포인터)
   ↓
메타데이터 파일
   ↓
매니페스트 리스트
   ↓
매니페스트 파일
   ↓
데이터 파일 (Parquet 등)
```

```text
쓰기 절차

변경 데이터 파일 작성
   ↓
매니페스트 등록·새 스냅샷 생성
   ↓
카탈로그 포인터 원자적 교체
   ↓
다른 엔진의 최신 스냅샷 조회
```

## Ⅳ. Apache Iceberg와 Hive 기반 데이터 레이크의 비교

- 핵심 요약 : Hive 방식은 디렉터리·파일 나열로 테이블을 간주하는 하둡 시대 방식이고, Iceberg는 메타데이터·스냅샷으로 테이블 상태를 명시 관리.

| 비교 축 | Apache Iceberg | Hive 메타스토어 방식 |
| --- | --- | --- |
| 테이블 상태 | 메타데이터 트리·스냅샷으로 명시 관리 | 디렉터리 경로·파일 나열에 의존 |
| 트랜잭션 | 원자적 커밋 기반 ACID(Atomicity·Consistency·Isolation·Durability) 트랜잭션 | 파일 수준 보장 부재 |
| 파티션 관리 | 숨겨진 파티셔닝·전략 진화 가능 | 경로 기반·변경 시 재작성 부담 |
| 스키마 변경 | 메타데이터 반영 | 데이터 불일치·재작성 위험 |
| 시점 조회 | 타임트래블·롤백 지원 | 미지원 |
| 동시 쓰기 | 충돌 감지·재시도 | 충돌 통제 부재 |

- 선택 기준 : 동시 쓰기·스키마 진화·시점 조회가 필요한 분석 플랫폼은 Iceberg, 단순 파일 교환은 기존 방식도 유효.

## Ⅴ. Apache Iceberg의 한계와 방안

- 핵심 요약 : 소형 파일·스냅샷 누적·커밋 충돌·엔진 편차를 정기 최적화·보존 정책·재시도·호환성 관리로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 소형 파일 누적 | 잦은 커밋으로 파일·메타데이터 비대 → 질의 지연 | 정기 컴팩션(Compaction, 파일 병합)·쓰기 크기 조정 | 평균 파일 크기 |
| 스냅샷·고아 파일 누적 | 만료되지 않은 스냅샷·미참조 파일 잔존 → 저장 비용 증가 | 스냅샷 만료·고아 파일 정리 주기 운영 | 보존 스냅샷 수 |
| 동시 커밋 충돌 | 여러 작업의 같은 기준 스냅샷 경합 → 작업 실패·재작업 | 재시도 정책·작업 분리·카탈로그 동시성 확인 | 커밋 실패율 |
| 엔진·버전 편차 | 포맷 기능 지원 수준의 차이 → 운영 불일치 | 호환성 매트릭스 관리·엔진 버전 표준화 | 엔진별 검증 현황 |

## Ⅵ. Apache Iceberg 적용에 대한 기술사적 제언

- 핵심 요약 : 데이터 플랫폼 조직은 오픈 테이블 포맷을 저장 계층 표준으로 지정하고 카탈로그·보존·호환성 정책을 거버넌스에 통합.
- 표준화 : 벤더 종속을 피하는 공개 포맷·카탈로그 선정 기준을 플랫폼 표준으로 지정.
- 운영 체계 : 컴팩션·스냅샷 보존·정리 작업을 정기 운영 절차와 담당 책임 체계로 편성.
- 거버넌스 : 테이블 스키마·접근 권한·데이터 계보를 메타데이터 기반으로 관리해 데이터 자산 품질 확보.

## Ⅶ. 결론

- 핵심 요약 : Apache Iceberg는 데이터 레이크를 트랜잭션 가능한 테이블로 승격시키는 오픈 테이블 포맷 표준.
- 포맷 표준은 저장·분석 엔진 선택의 자유라는 전략적 가치를 가지며 레이크하우스(Lakehouse) 전환의 기반이 됨.
