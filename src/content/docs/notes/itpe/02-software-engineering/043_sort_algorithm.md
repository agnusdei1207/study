## 30초 인출

- 본질: 정렬 알고리즘은 데이터를 키 순서로 재배열하는 방법이며 삽입 정렬은 원소를 정렬된 앞부분에 끼워 넣고 트리 정렬은 이진 탐색 트리에 넣은 뒤 중위 순회로 꺼냄
- 메커니즘: 삽입 정렬은 각 원소를 앞부분의 알맞은 위치까지 이동해 삽입하고, 트리 정렬은 BST 삽입 후 중위 순회로 오름차순 출력
- 통찰: 삽입 정렬은 거의 정렬된 소량 데이터에는 빠르지만 일반 입력에서는 O(n²)이고 트리 정렬은 입력이 정렬돼 있으면 편향되어 O(n²)이므로 데이터 크기와 정렬 정도로 알고리즘을 선택하고 트리는 균형 트리로 구성

<details>
<summary>핵심 용어</summary>

- **삽입 정렬(Insertion Sort)** : 원소를 하나씩 꺼내 이미 정렬된 앞부분의 알맞은 위치에 삽입하는 정렬
- **트리 정렬(Tree Sort)** : 원소를 이진 탐색 트리에 삽입한 뒤 중위 순회로 정렬 결과를 얻는 정렬
- **안정 정렬(Stable Sort)** : 같은 키를 가진 원소의 상대 순서가 유지되는 정렬
- **제자리 정렬(In-place Sort)** : 입력 배열 외에 추가 메모리를 거의 쓰지 않는 정렬
- **중위 순회(In-order Traversal)** : 왼쪽 서브트리, 노드, 오른쪽 서브트리 순으로 방문하는 순회

</details>

## 2~4교시 25점 답안

## Ⅰ. 정렬 알고리즘의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **정렬 알고리즘** 은 데이터를 키 순서로 재배열하는 방법 |
| 목적 | 탐색·병합·중복 제거의 효율 향상 |

## Ⅱ. 삽입 정렬과 트리 정렬의 특징

| 특징 | 삽입 정렬 | 트리 정렬 |
|---|---|---|
| 방식 | 앞부분에 끼워 넣기 | BST 삽입 후 중위 순회 |
| 안정성 | 안정 | 구현에 따라 다름 |
| 추가 메모리 | 거의 없음 | 노드 저장 공간 필요 |

## Ⅲ. 두 알고리즘의 동작

### 삽입 정렬 동작

```text
[5, 2, 4, 1]
2를 5 앞에 삽입 → [2, 5, 4, 1]
4를 5 앞에 삽입 → [2, 4, 5, 1]
1을 맨 앞에 삽입 → [1, 2, 4, 5]
```

### 트리 정렬 동작

```text
삽입: 5 → 2 → 4 → 1 (BST 구성)
        5
       /
      2
     / \
    1   4
중위 순회: 1, 2, 4, 5
```

## Ⅳ. 삽입 정렬과 트리 정렬의 비교

| 구분 | 삽입 정렬 | 트리 정렬 |
|---|---|---|
| 최선 | O(n)(이미 정렬) | O(n log n) |
| 평균 | O(n²) | O(n log n) |
| 최악 | O(n²) | O(n²)(정렬 입력 시 편향) |
| 공간 | O(1) | O(n) |
| 적합 조건 | 소량·거의 정렬된 데이터 | 삽입과 정렬이 함께 필요한 데이터 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 삽입 정렬의 큰 입력에서 O(n²) 지연 | 큰 데이터는 O(n log n) 정렬 사용 |
| 트리 정렬의 정렬된 입력에서 편향 | AVL·Red-Black 등 균형 트리 사용 |
| 트리 정렬의 추가 메모리 사용 | 메모리 제약 환경은 제자리 정렬 선택 |

## Ⅵ. 제언

데이터 크기와 정렬 정도를 확인해 소량·거의 정렬된 경우 삽입 정렬, 일반 대용량은 O(n log n) 정렬을 선택

### 알고리즘 선택 기준

```text
데이터 크기·정렬 정도 확인
    ├─ 소량 또는 거의 정렬 → 삽입 정렬
    ├─ 삽입과 정렬 병행 → 균형 트리 기반 정렬
    └─ 대용량 일반 → O(n log n) 정렬
```

### 선택 근거: 단일 알고리즘 고정과의 비교

| 구분 | 하나로 고정 | 제언: 데이터 특성별 선택 |
|---|---|---|
| 소량 정렬 데이터 | 과잉 | 삽입 정렬로 충분 |
| 대용량 | 지연 가능 | O(n log n) |
| 최악 성능 | 입력 의존 | 입력 특성 반영 |
