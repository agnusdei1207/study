## 연관 키워드
- 웹 크롤러, URL Frontier, robots.txt, 중복 제거, 크롤링 정책, 색인

### Ⅰ. 웹 크롤링의 개요

- 핵심 요약 : 웹 크롤링은 시작 URL에서 링크를 따라 웹 자원을 자동 수집해 검색 색인이나 분석 데이터의 입력을 만드는 과정.
- 개념 : 시작 URL에서 링크를 따라 웹 자원을 자동 수집해 검색 색인이나 분석 데이터의 입력을 만드는 과정(**웹 크롤러**, Web Crawler).
- 배경 및 필요성 : 웹 문서의 규모와 갱신 빈도 때문에 수작업 수집 만으로 최신 자료와 연결 관계를 파악하기 어려움.
- 주요 목적 : 범위와 정책이 정해진 웹 자료를 재현 가능하고 책임 있게 수집.

### Ⅱ. 주요 구성과 특성

- 핵심 요약 : URL 우선 순위와 접근 정책, 중복 제거를 관리해 확장 가능한 수집 흐름 구성.

1. URL Frontier : 방문 대기 URL과 우선 순위 관리 → 도메인 별 요청 속도 조절.
2. Fetcher·Parser : HTTP 응답 취득과 문서 파싱 → 링크 및 메타데이터 추출.
3. 중복 제거 : 정규화 URL·콘텐츠 지문 활용 → 재수집·색인 중복 감소.
4. 정책 준수 : robots.txt와 이용 조건, 개인 정보·저작권 요구를 확인 → 운영 위험 관리.

### Ⅲ. 크롤링 처리 흐름 (구조)

- 핵심 요약 : URL 선택부터 응답 저장과 새 링크 확장까지 반복 하며 오류·재시도 정책도 관리.

```text
시드 URL
   ↓
URL Frontier → 정책·중복 검사
   ↓ 허용된 요청
Fetcher → Parser → 문서 저장
   ↓ 추출 링크 정규화
Frontier에 후보 URL 추가
```

```text
요청 전: 도메인 별 속도·robots 확인
응답 후: 상태 코드·콘텐츠 유형 검사
실패 시: 제한 재시도·백오프·오류 기록
```

- robots.txt는 크롤러에 대한 표준화된 접근 지침이며 인증·접근 통제 수단이나 법적 이용 허가로 간주할 수 없음.

### Ⅳ. 크롤링과 스크래핑 비교

- 핵심 요약 : 크롤링은 링크 탐색·수집 과정, 스크래핑은 특정 페이지에서 목적 데이터를 추출하는 행위로 중첩 가능.

| 비교 축 | 크롤링 | 스크래핑 |
|---|---|---|
| 중심 작업 | URL 발견·방문 순회 | 페이지 내 값·구조 추출 |
| 입력 범위 | 시드에서 확장 되는 다수 URL | 특정 페이지·사이트 범위 |
| 대표 산출물 | 문서 저장소·검색 색인 입력 | 정형화된 필드·레코드 |
| 주요 통제 | Frontier, 예절 정책, 중복 | DOM 변화, 권리·개인 정보, 정확성 |

### Ⅴ. 웹 크롤링의 한계와 방안

- 핵심 요약 : 확장성과 최신성은 서버 부하·동적 페이지·수집 적법성의 제약과 함께 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 서버 부하 | 과도한 동시 요청 | 도메인 별 속도 제한·백오프·캐시 | 도메인 별 요청 수 |
| 크롤링 함정 | 무한 달력·매개 변수 조합 | URL 정규화·깊이·범위 상한 | 함정 URL 차단 비율 |
| 동적 콘텐츠 누락 | 브라우저 렌더링 의존 | API·렌더링 필요성 평가 후 제한 수집 | 누락 콘텐츠 비율 |
| 권리·개인 정보 침해 | 공개 웹 이라는 이유 만으로 이용 허용이라 오해 | 이용 조건·법률·보존 기간·삭제 절차 검토 | 준법 검토 완료율 |

### Ⅵ. 수집 거버넌스 제언

- 핵심 요약 : 수집 목적·허용 범위·보존·삭제 책임을 먼저 정하고 운영 중 준수 증거를 남김.

1. 데이터 책임 자는 URL 범위, 수집 필드, 목적 외 이용 금지, 보존 기간을 승인.
2. 운영 자는 식별 가능한 크롤러, 연락 경로, 요청 속도 정책과 중단 절차를 문서화.

### Ⅶ. 결론

- 핵심 요약 : 웹 크롤링은 대규모 웹 자료 발견과 수집을 자동화하는 기반 기술.
- 시사점 : 기술적 확장성과 함께 서버 부담, 데이터 권리, 개인 정보 보호를 설계 단계부터 고려해야 함.
