## 연관 키워드
- ATAM, 품질속성 시나리오, Utility Tree, 민감점, 절충점, 리스크, CBAM

### Ⅰ. ATAM의 개요

- 핵심 요약 : ATAM은 아키텍처가 품질속성 요구와 상충관계를 만족하는지 시나리오 기반으로 평가하는 방법.
- 개념 : 이해관계자 요구와 아키텍처 결정의 영향을 분석해 위험·절충·민감점을 찾는 SEI 평가 기법(**ATAM**, Architecture Tradeoff Analysis Method).
- 배경 및 필요성 : 아키텍처 선택은 성능·수정성·가용성 등 품질속성 간 상충을 만듦.
- 주요 목적 : 구현 전에 아키텍처 위험을 노출하고 의사결정 근거를 확보.

### Ⅱ. ATAM의 특징 및 장점

- 핵심 요약 : Utility Tree로 품질 요구를 우선순위화하고 시나리오를 추적해 설계 민감성과 위험을 파악.

1. 시나리오 기반 : 자극·환경·응답·측정값 명시 → 모호한 품질 요구를 평가 가능하게 변환.
2. 이해관계자 참여 : 다양한 관점 통합 → 숨은 전제·상충 요구 발견.
3. 구조 결정 분석 : 전술·구성요소가 품질 응답에 미치는 영향 → 민감점·절충점·리스크 도출.

### Ⅲ. ATAM 평가 절차 (흐름)

- 핵심 요약 : 평가자와 이해관계자가 아키텍처·업무 목표를 확인한 뒤 시나리오와 설계 결정을 반복 분석.

```text
1 평가 소개·목표 → 2 업무 동인 → 3 아키텍처 설명 → 4 접근법 식별
→ 5 Utility Tree → 6 시나리오 브레인스토밍·우선순위
→ 7 아키텍처 분석 → 8 결과 보고
```

```text
품질속성 → 시나리오(자극·환경·응답·측정) → 설계 전술/결정
                                           ↓
                                   민감점·절충점·위험
```

- 산출 : 위험 목록, 비위험 목록, 민감점, 절충점, 아키텍처 접근법.

### Ⅳ. ATAM과 CBAM 비교

- 핵심 요약 : ATAM은 품질 위험과 절충을 식별하고, CBAM은 비용·편익 관점에서 전략을 선택.

| 비교 축 | ATAM | CBAM(Cost Benefit Analysis Method) |
|---|---|---|
| 초점 | 품질속성·아키텍처 위험 | 아키텍처 전략의 경제적 가치 |
| 주요 입력 | 품질 시나리오·설계 결정 | ATAM 분석·비용·편익 추정 |
| 결과 | 위험·민감점·절충점 | ROI·전략 우선순위 |
| 관계 | 기술적 분석 기반 | 경제적 의사결정으로 확장 |

### Ⅴ. ATAM의 한계와 방안

- 핵심 요약 : 평가 결과는 시나리오 품질과 참여자 가정에 좌우되므로 근거·측정기준·불확실성 기록.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 모호한 시나리오 | 평가자별 해석 차이 | 정량 응답·환경·자극 명시 | 시나리오 검토 건수 |
| 설계정보 부족 | 분석의 추정 의존 | 아키텍처 산출물 사전 준비 | 설계 산출물 완결성 |
| 이해관계자 편중 | 중요 품질 요구 누락 | 역할별 참여자 균형화 | 참여자 대표성 |

### Ⅵ. ATAM 적용 제언

- 핵심 요약 : 아키텍트는 핵심 품질 시나리오를 설계 결정·시험계획·위험 소유자와 연결.

1. 발주·사업 책임자는 평가 시점과 의사결정 권한을 초기 설정.
2. 아키텍트는 위험 항목에 대응 전술, 검증 방법, 책임자를 등록.
3. 평가팀은 아키텍처 변경 시 영향 시나리오를 재평가하고 기록 갱신.

### Ⅶ. 결론

- 핵심 요약 : ATAM은 아키텍처의 품질속성 상충과 위험을 구현 전 구조화하는 평가 방법.
- 시사점 : Utility Tree의 우선순위는 실제 업무 목표와 측정 가능한 시나리오를 반영해야 함.
