## 지식 로드맵 내 현재 위치

<div class="itpe-topic-path" aria-label="소프트웨어 아키텍처에서 ATAM까지의 지식 경로"><span>SW 공학·아키텍처</span><span>품질속성 평가</span><strong>ATAM</strong></div>

## 큰 그림과 30초 인출

```text
[비즈니스 동인] → [품질속성 시나리오] → [아키텍처 접근법]
         └──────── [Utility Tree·우선순위] ────────┘
                              ↓
             [민감점·상충점·위험·비위험·위험주제]

ATAM = 복수 품질속성의 상충관계를 이해관계자가 함께 평가
```

## 예상문제

ATAM의 개념, 수행 절차와 핵심 산출물을 설명하고 SAAM 및 CBAM과 비교하시오.

## Ⅰ. 개요

- ATAM은 아키텍처 결정이 성능·가용성·보안·변경용이성 등 품질속성에 미치는 영향과 상충관계를 시나리오 기반으로 평가하는 방법이다.
- 구축 전에 고비용 위험을 드러내고 이해관계자의 공통 판단 근거를 만드는 것이 목적이다.

## Ⅱ. 평가 입력과 참여자

| 입력 | 내용 |
|---|---|
| 비즈니스 동인 | 목표, 제약, 핵심 이해관계 |
| 아키텍처 | 구조, 기술, 주요 설계 결정 |
| 품질속성 시나리오 | 자극·환경·대상·응답·측정치 |
| 참여자 | 평가팀, 의사결정자, 설계자, 사용자·운영자 |

## Ⅲ. 수행 절차

```text
발표: ATAM 소개 → 비즈니스 동인 → 아키텍처 소개
조사: 접근법 식별 → Utility Tree 생성 → 접근법 분석
시험: 시나리오 도출·우선순위화 → 접근법 재분석
보고: 결과 정리·공유
```

- 우선순위가 높은 시나리오를 중심으로 아키텍처 결정을 추적한다.
- “빠르게” 대신 측정 가능한 응답과 응답측정치를 작성한다.

## Ⅳ. 핵심 산출물

| 산출물 | 의미 |
|---|---|
| 민감점 | 한 결정이 특정 품질속성에 크게 영향을 주는 지점 |
| 상충점 | 한 결정이 여러 품질속성에 서로 다른 영향을 주는 지점 |
| 위험 | 요구 품질 달성을 위협하는 결정 또는 미결정 |
| 비위험 | 분석 근거로 수용 가능한 결정 |
| 위험주제 | 여러 위험에 반복되는 구조적 원인 |

## Ⅴ. 유사 기법 비교

| 구분 | SAAM | ATAM | CBAM |
|---|---|---|---|
| 중심 | 변경 시나리오 | 복수 품질속성 상충 | 경제적 가치 |
| 결과 | 변경 영향 | 위험·민감점·상충점 | 비용·효익 우선순위 |
| 활용 | 단일 속성 중심 초기 평가 | 아키텍처 위험 평가 | 투자 대안 선택 |

## Ⅵ. 적용 시 고려사항

- 경영·개발·운영·보안 등 다양한 이해관계자를 참여시켜 시나리오 편향을 줄인다.
- 평가는 합격 판정이 아니라 위험 발견 활동이며 결과를 백로그와 아키텍처 의사결정 기록에 연결한다.
- 운영 데이터와 프로토타입 측정으로 분석 가정을 검증한다.
- 설계 변경 후 민감점과 상충점을 지속적으로 재평가한다.

## Ⅶ. 결론

ATAM은 최상의 구조를 선언하는 방법이 아니라 중요한 품질속성의 상충을 조기에 드러내는 합의 과정이다. 시나리오와 측정 근거를 설계·시험에 추적해야 효과가 지속된다.

## 1교시 10점 발췌

```text
ATAM = 품질속성 시나리오 기반 아키텍처 상충 분석
입력: 비즈니스 동인 + 아키텍처 + 이해관계자 시나리오
절차: 발표 → 조사 → 시험 → 보고
결과: 위험·비위험·민감점·상충점·위험주제
```
