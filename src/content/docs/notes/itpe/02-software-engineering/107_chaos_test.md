## 연관 키워드
- 카오스 엔지니어링, 정상 상태, 가설, 장애 주입, 폭발 반경, 중단 조건

### Ⅰ. 카오스 테스트의 개요

- 핵심 요약 : 카오스 테스트는 통제 된 장애를 주입 해 분산 시스템의 복원력 가정을 검증 하는 실험.
-概念 : 카오스 엔지니어링(Chaos Engineering)은 정상 상태를 측정 하고 실제 장애를 안전하게 모사 해 시스템이 예상 대로 견디는지 확인하는 실험 규율.
- 배경 및 필요성 : 분산 서비스는 네트워크 단절·지연, 프로세스 종료, 자원 고갈을 완전히 예방 하기 어려워 복구 동작을 검증 해야 함.
- 주요 목적 : 장애 전파와 복구 결함을 고객 영향 전에 발견 하고 복원력 근거를 확보.

### Ⅱ. 원칙 및 효과

- 핵심 요약 : 관측 가능한 정상 상태와 명시적 가설을 기준으로 실험 범위를 제한 하고 결과를 측정.

1. 정상 상태 : 서비스 수준 지표로 안정성 기준 수립 → 실험 결과 판단 근거 확보.
2. 가설 기반 : 장애 조건과 예상 복구 결과 사전 기술 → 실험의 검증 가능성 향상.
3. 폭발 반경 제한 : 작은 대상·낮은 영향 부터 시작 → 사용자 위험 최소화.
4. 운영 환경과 유사한 조건 : 실제 의존성과 제어 경로 검증 → 테스트 환경의 과도한 낙관 감소.

### Ⅲ. 실험 절차 (흐름)

- 핵심 요약 : 기준선·가설·장애 주입·관측·복구·학습의 반복 절차로 실험.

```text
정상 상태 지표·기준선 확보
   ↓ 장애 가설과 대상 선정
실험 승인·범위·중단 조건 설정
   ↓ 통제된 장애 주입
영향 관측 → 즉시 중단 또는 복구 확인
   ↓
결함 개선·재 실험·기록
```

```text
예: 캐시 노드 중단
가설: 캐시 장애에도 요청은 저장소로 우회
측정: 오류 율·지연·저장소 포화
안전 장치: 임계치 초과 시 주입 자동 중단
```

- 장애 유형은 인스턴스 종료, 지연·패킷 손실, 의존 서비스 실패, CPU·메모리 압박 등을 목표 가설에 맞게 선택.

### Ⅳ. 검증 방식 비교

- 핵심 요약 : 카오스 실험은 특정 복원력 가설을 검증 하며, 부하·재해 복구 시험과 목표가 다름.

| 비교 축 | 카오스 테스트 | 부하 테스트 | 재해 복구 훈련 |
|---|---|---|---|
| 주된 질문 | 장애 조건 에서 서비스가 견디는가 | 부하 증가 에서 용량·성능이 어떠한가 | 대규모 장애 후 복구 절차가 작동하는가 |
| 자극 | 통제 된 장애 주입 | 사용자 부하·트래픽 | 사이트·데이터 손실 시나리오 |
| 관측 | 복원 동작·오류 전파 | 처리량·지연·자원 | RTO·RPO·복구 절차 |

### Ⅴ. 카오스 테스트의 한계와 방안

- 핵심 요약 : 실험 자체가 장애를 만들 수 있으므로 승인·격리·중단 장치를 먼저 검증.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 고객 영향 확대 | 범위·중단 신호가 부적절 | 점진 실험, 표적 제한, 자동 중단 | 실험 중단 건수 |
| 가설 부실 | 정상 상태·기대 동작 불명확 | SLI 기반 가설·성공 기준 사전 정의 | 가설 불명확 건수 |
| 테스트 환경 과신 | 실제 토폴로지·트래픽과 차이 | 제한된 운영 실험과 스테이징 검증 조합 | 환경 일치율 |
| 발견 후 미조치 | 담당자·기한 없는 실험 기록 | 결함 소유자·개선 일정·재검증 연결 | 미조치 실험 건수 |

### Ⅵ. 운영 제언

- 핵심 요약 : SRE와 서비스 소유 자는 영향 허용 범위와 의사 소통·롤백 권한을 명확히 하고 작은 실험을 상시화.

1. 실험 책임 자는 고객 영향, 개인 정보, 복구 인력 확보를 점검 하고 변경 관리 및 온콜 절차에 연결.
2. 조직 은 장애를 개인 평가에 이용 하지 않고 시스템 가정 개선과 운영 학습 자료로 관리.

### Ⅶ. 결론

- 핵심 요약 : 카오스 테스트는 장애의 부재를 보장 하는 것이 아니라 시스템 복원력 가정을 실증 하는 접근.
- 시사점 : 안전한 범위 에서 반복 실험 하고 결함 조치와 재검증을 연결 해야 운영 신뢰성 향상.
