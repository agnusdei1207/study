소프트웨어 공학 → 소프트웨어 시험·품질 → 몽키 테스트(Monkey Test)

## 지식 위치

소프트웨어공학 > 동적 테스팅 기법 > 몽키 테스트

## 30초 인출

- 본질: 몽키 테스트는 무작위 입력과 이벤트를 주입해 예기치 않은 오류·비정상 동작을 찾는 테스트 기법
- 메커니즘: 의사 난수 시드(Seed) 기반 이벤트 스트림 생성 → UI 컴포넌트 및 API 무작위 주입 → 크래시(Crash) 및 무응답(ANR) 감지 → 시드 기반 이벤트 리플레이를 통한 결함 재현 디버깅
- 통찰: 한계: 무작위 장애는 입력 순서를 남기지 않으면 재현하기 어려움 → 방안: 시드·환경·이벤트 로그를 기록해 크래시를 재실행·분류

<details>
<summary>핵심 용어</summary>

- **덤 몽키(Dumb Monkey)** : 대상 시스템의 내부 상태나 UI 구조에 대한 정보 없이 완전히 무작위로 클릭, 터치, 키 입력을 쏟아붓는 가장 단순한 형태의 무작위 테스팅
- **스마트 몽키(Smart Monkey)** : 화면 구조나 앱 상태 정보를 이용해 유효 이벤트를 선택하는 구현 방식으로, 표준화된 단일 분류명은 아님
- **재현성(Reproducibility)** : 무작위 테스트에서 결함이 터졌을 때 동일한 입력 순서를 재현할 수 있는 능력으로, 난수 발생기의 고정 시드(Seed) 관리가 핵심
- **ANR(Application Not Responding)** : Android가 앱의 주 스레드가 사용자 입력에 응답하지 않는 상태로 판단해 표시하는 오류 상태
</details>

## 2~4교시 25점 답안

## Ⅰ. 몽키 테스트의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 몽키 테스트는 무작위 입력과 이벤트를 주입해 예기치 않은 오류·비정상 동작을 찾는 테스트 기법 |
| 목적 | 정형 시나리오로 놓치기 쉬운 입력 조합과 예외 동작을 탐색 |

## Ⅱ. 몽키 테스트의 특징

| 특징 | 검증상 의미 |
|---|---|
| 입력 조합 탐색 | 정형 시나리오 밖의 이벤트 순서와 예외 상태 확인 |
| 안정성 중심 | Crash·ANR 등 실패를 관찰하되 기능 정합성은 별도 시험 |
| 재현 조건 의존 | 시드·앱 상태·버전·이벤트 순서가 있어야 결함 분석 가능 |

## Ⅲ. 이벤트 생성·관찰 체계와 재현 프로세스

### 이벤트 생성과 실패 관찰

```text
자동 이벤트 생성
    ├─ 무작위: 임의 조작·순서
    └─ 상태 인식: 화면 요소·전이 고려

이벤트 기록 → Crash·ANR 등 실패 감지
```

### 실행·재현 절차

```text
시드·실행 환경 기록
    ↓
이벤트 생성·주입
    ↓
Crash·ANR·로그 감시
    ↓
동일 조건 재생·원인 분석
```

| 단계 | 핵심 내용 |
|---|---|
| 실행 설정 | 이벤트 종류·빈도·실행 조건을 설정하고, 도구가 지원하면 난수 시드를 보존 |
| 이벤트 주입 | UI 입력과 시스템 이벤트를 앱에 주입 |
| 결함 관찰 | 크래시·ANR·자원 이상을 로그와 함께 기록 |
| 재현·회귀 검증 | 입력 이력과 앱 버전을 사용해 결함을 재현하고, 수정 후 회귀시험에 추가 |

## Ⅳ. 몽키 테스트와 기능시험·검증 항목 비교

| 구분 | 몽키 테스트 | 요구사항 기반 기능시험 |
|---|---|---|
| 입력 | 무작위 또는 상태를 고려한 UI 이벤트 | 사전 설계한 입력과 기대 결과 |
| 주된 확인 | 비정상 종료·응답 중단 등 안정성 | 요구사항 충족 여부 |
| 한계 | 실행만으로 기능 정합성 입증 곤란 | 설계하지 않은 입력 조합 누락 가능 |

### 결함 재현 확인 항목

| 점검 영역 | 검증 항목 |
|---|---|
| 안정성 | 발견한 비정상 종료의 원인과 조치 상태 |
| 응답성 | 주 스레드 블로킹에 따른 ANR 여부 |
| 자원 | 반복 실행 전후 메모리·파일 자원 추세 |
| 재현성 | 시드·상태·버전·이벤트 이력 기록 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 무작위 장애는 입력 순서를 남기지 않으면 재현하기 어려움 | 시드·환경·이벤트 로그를 기록해 크래시를 재실행·분류 |
| 난수 이벤트가 핵심 화면에 도달하지 못함 | 상태와 위험 경로를 확인해 필요한 화면 전이·입력 조건 추가 |
| 테스트 중 운영 데이터 변경 | 테스트 계정·샌드박스를 사용하고 비가역 동작 차단 |
| 무작위 탐색을 기능시험 대체물로 오해 | 기능·보안시험을 병행하고 발견 결함을 회귀시험으로 전환 |

## Ⅵ. 제언

실패 한 건의 시드·환경·이벤트 순서를 보존해 재실행한 뒤, 재현된 결함을 정형 회귀시험에 우선 편입한다.
