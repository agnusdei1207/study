## 지식 위치

소프트웨어공학 > 동적 테스팅 기법 > 몽키 테스트

## 큰 그림과 30초 인출

- 본질: 몽키 테스트는 무작위 입력과 이벤트를 주입해 예기치 않은 오류·비정상 동작을 찾는 테스트 기법
- 메커니즘: 의사 난수 시드(Seed) 기반 이벤트 스트림 생성 → UI 컴포넌트 및 API 무작위 주입 → 크래시(Crash) 및 무응답(ANR) 감지 → 시드 기반 이벤트 리플레이를 통한 결함 재현 디버깅
- 산출물: 몽키 테스트 실행 로그(Seed 번호 포함) · 크래시/ANR 스택 트레이스 보고서 · 복원력 분석서

<details>
<summary>핵심 용어</summary>

- **덤 몽키(Dumb Monkey)**: 대상 시스템의 내부 상태나 UI 구조에 대한 정보 없이 완전히 무작위로 클릭, 터치, 키 입력을 쏟아붓는 가장 단순한 형태의 무작위 테스팅
- **스마트 몽키(Smart Monkey)**: 화면 구조나 앱 상태 정보를 이용해 유효 이벤트를 선택하는 구현 방식으로, 표준화된 단일 분류명은 아님
- **재현성(Reproducibility)**: 무작위 테스트에서 결함이 터졌을 때 동일한 입력 순서를 재현할 수 있는 능력으로, 난수 발생기의 고정 시드(Seed) 관리가 핵심
- **ANR(Application Not Responding)**: Android가 앱의 주 스레드가 사용자 입력에 응답하지 않는 상태로 판단해 표시하는 오류 상태
</details>

## 2~4교시 25점 답안

## Ⅰ. 개요 및 필요성

| 구분 | 핵심 |
|---|---|
| 정의 | 몽키 테스트는 무작위 입력과 이벤트를 주입해 예기치 않은 오류·비정상 동작을 찾는 테스트 기법 |
| 목적 | 정형 시나리오로 놓치기 쉬운 입력 조합과 예외 동작을 탐색 |

**적용 맥락:** 정해진 사용자 경로만 반복하는 시험에서 놓친 입력 순서와 예외 상태를 탐색. 발견한 결함은 재현 조건을 기록해 정형 회귀시험에 편입.

| 구분 | 몽키 테스트 | 요구사항 기반 기능시험 |
|---|---|---|
| 입력 | 무작위 또는 상태를 고려한 UI 이벤트 | 사전에 설계한 입력과 기대 결과 |
| 주된 확인 | 비정상 종료·응답 중단 등 안정성 | 요구사항 충족 여부 |
| 한계 | 실행만으로 기능의 정합성을 입증하기 어려움 | 설계하지 않은 입력 조합을 놓칠 수 있음 |

## Ⅱ. 아키텍처 및 핵심 메커니즘

### 이벤트 생성과 실패 관찰

```text
자동 이벤트 생성
    ├─ 무작위: 임의 조작·순서
    └─ 상태 인식: 화면 요소·전이 고려

이벤트 기록 → Crash·ANR 등 실패 감지
```

### 실행·재현 절차

```text
시드·실행 환경 기록
    ↓
이벤트 생성·주입
    ↓
Crash·ANR·로그 감시
    ↓
동일 조건 재생·원인 분석
```

| 단계 | 핵심 내용 |
|---|---|
| 실행 설정 | 이벤트 종류·빈도·실행 조건을 설정하고, 도구가 지원하면 난수 시드를 보존 |
| 이벤트 주입 | UI 입력과 시스템 이벤트를 앱에 주입 |
| 결함 관찰 | 크래시·ANR·자원 이상을 로그와 함께 기록 |
| 재현·회귀 검증 | 입력 이력과 앱 버전을 사용해 결함을 재현하고, 수정 후 회귀시험에 추가 |

## Ⅲ. 실무 적용 및 고려사항

### 위험 대응 매트릭스

| 위험 | 대책 |
|---|---|---|
| 난수 이벤트가 핵심 화면에 도달하지 못해 입력 범위가 편중될 수 있음 | 앱 상태와 위험 경로를 확인해 필요한 화면 전이·입력 조건을 추가 |
| 테스트 중 운영 데이터 변경이나 파괴적 이벤트가 발생할 수 있음 | 테스트 계정·샌드박스를 사용하고 비가역 동작을 차단 |
| 무작위 탐색을 요구사항 기반 기능시험의 대체물로 오해할 수 있음 | 기능·보안시험과 함께 사용하고 발견 결함을 회귀시험으로 전환 |

## Ⅳ. 점검 기준

### 결함 재현 확인 항목

| 점검 영역 | 검증 항목 |
|---|---|---|
| **안정성 검증** | 합의한 실행 조건에서 발견한 비정상 종료의 원인과 조치 상태 |
| **응답성 검증** | 메인 스레드 블로킹으로 인한 ANR 발생 여부와 영향 |
| **자원 누수** | 반복 실행 전후 메모리·파일 자원의 추세 |
| **재현성 검증** | 시드·앱 상태·버전·이벤트 이력 등 재현 조건의 기록 여부 |

## Ⅴ. 기술사적 제언

```text
무작위 이벤트에서 실패 발견
          ↓
시드·상태·버전·이벤트 순서 기록
          ↓
실패를 재현 가능한 회귀시험으로 전환
```

**제언:** 무작위 실행 횟수보다 실패 재현성과 회귀시험 편입 여부를 관리.
