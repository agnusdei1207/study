## 지식 로드맵 내 현재 위치

소프트웨어 공학 → 테스트·검증 → **몽키 테스트(Monkey Test)**

## 30초 인출

- 본질: 몽키 테스트는 정해진 시나리오 없이 무작위 입력과 조작을 반복해 소프트웨어의 비정상 종료와 예외 처리 결함을 찾는 경험 기반 테스트
- 메커니즘: 임의의 클릭·입력·이벤트를 자동으로 발생시켜 애플리케이션이 충돌·멈춤 없이 견디는지 관찰하고 발견한 오류를 재현해 수정
- 통찰: 무작위 실행은 오류가 나도 같은 조작을 다시 만들기 어려우므로 난수 시드와 이벤트 로그를 기록해 재현 가능하게 하고 화면 구조를 아는 스마트 몽키로 유효 입력 비중을 높임

<details>
<summary>핵심 용어</summary>

- **몽키 테스트(Monkey Test)** : 무작위 입력·조작으로 소프트웨어의 안정성을 확인하는 테스트
- **덤 몽키(Dumb Monkey)** : 화면 구조를 모르고 완전히 무작위로 조작하는 방식
- **스마트 몽키(Smart Monkey)** : 화면 구조와 유효 입력을 파악해 의미 있는 조작을 무작위로 수행하는 방식
- **시드(Seed)** : 난수 생성의 초기값. 같은 시드로 같은 조작 순서를 재현
- **퍼즈 테스트(Fuzz Testing)** : 비정상적인 입력 데이터를 대량으로 넣어 결함을 찾는 테스트
- **ANR(Application Not Responding)** : 모바일 앱이 일정 시간 응답하지 않는 상태

</details>

## 2~4교시 25점 답안

## Ⅰ. 몽키 테스트의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **몽키 테스트** 는 무작위 입력과 조작으로 소프트웨어의 안정성을 확인하는 테스트 |
| 목적 | 예상하지 못한 사용에서 발생하는 충돌·멈춤의 발견 |

## Ⅱ. 시나리오 기반 테스트와 구별되는 특징

| 특징 | 의미 |
|---|---|
| 무작위 입력 | 정해진 시나리오 없음 |
| 자동 실행 | 도구가 장시간 반복 |
| 안정성 중심 | 충돌·멈춤·비정상 종료 확인 |

## Ⅲ. 몽키 테스트 수행과 유형

### 수행 절차

```text
테스트 대상·실행 시간 설정 (시드 지정)
    ↓
무작위 이벤트 생성·실행
    ↓
충돌·멈춤 감시·로그 기록
    ↓
오류 재현(같은 시드) → 수정
```

### 확대: 덤 몽키와 스마트 몽키

```text
덤 몽키:    화면 구조 무시 → 무작위 좌표 클릭·입력
스마트 몽키: 화면 요소·상태 인식 → 유효한 조작을 무작위 선택
```

## Ⅳ. 유형과 유사 기법의 비교

| 구분 | 덤 몽키 | 스마트 몽키 | 퍼즈 테스트 |
|---|---|---|---|
| 입력 | 완전 무작위 | 화면 인식 기반 무작위 | 비정상 데이터 대량 |
| 도달 깊이 | 얕음 | 깊음 | 입력 처리부 집중 |
| 도입 비용 | 낮음 | 높음 | 중간 |
| 초점 | UI 안정성 | UI 안정성 | 입력 처리 결함·보안 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 발견한 오류의 재현 곤란 | 시드와 이벤트 로그 기록 |
| 무의미한 입력이 많아 도달 범위 제한 | 스마트 몽키로 유효 조작 비중 확대 |
| 결과 판정이 충돌·멈춤 위주 | 화면 상태·로그의 오류 판정 규칙 추가 |

## Ⅵ. 제언

몽키 테스트는 시드와 이벤트 로그를 기록하며 수행하고, 충돌·멈춤 발견 시 같은 시드로 재현해 수정하도록 운영

### 재현 중심 운영

```text
시드 지정 실행 → 로그 기록
    ↓
오류 발생 → 같은 시드로 재현 → 원인 분석·수정
```

### 선택 근거: 시드 없는 실행과의 비교

| 구분 | 시드·로그 없음 | 제언: 시드·로그 기록 |
|---|---|---|
| 오류 재현 | 곤란 | 가능 |
| 원인 분석 | 추정 | 로그 기반 |
| 수정 검증 | 어려움 | 같은 시드로 재실행 |
