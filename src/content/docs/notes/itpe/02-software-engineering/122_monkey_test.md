---

## 30초 인출

- 본질: **몽키 테스트(Monkey Testing)** 는 원숭이가 키보드를 무작위로 두드리는 것처럼 아무런 사전 지식이나 정형화된 시나리오 없이 의사 난수(Pseudorandom) 기반의 클릭, 터치, 제스처, 시스템 이벤트를 대량으로 주입하여 소프트웨어의 비정상 종료(Crash), 무응답(ANR), 메모리 누수 등 예외적 결함을 탐색하는 무작위 동적 테스팅 기법
- 메커니즘: 난수 발생기 시드(Seed) 설정 → 무작위 사용자 이벤트 스트림 생성 → 대상 애플리케이션(UI/API)에 초고속 주입 → Logcat/시스템 로그 크래시 감지 → 시드 기반 재현(Replay) 및 원인 분석
- 통찰: 완전 무작위 방식(Dumb Monkey)은 로그인 화면조차 통과하지 못해 깊은 도메인 로직에 도달하지 못하고 결함 재현이 어려우므로 상태 인식 기반 스마트 몽키(Smart Monkey) 도입과 고정 시드(Seed) 기반 이벤트 로깅 체계를 필수적으로 결합할 필요가 있음

<details>
<summary>핵심 용어</summary>

- **덤 몽키 (Dumb Monkey)** : 시스템의 상태나 UI 컴포넌트 구조를 전혀 인지하지 못하고 화면 좌표에 무차별적인 난수 터치를 인가하는 단순 무작위 방식
- **스마트 몽키 (Smart Monkey)** : 현재 UI 위젯 트리(DOM/View)의 활성화 상태와 유효 입력 필드를 인식하여 문법적으로 유효한 이벤트를 인가하는 지능형 방식
- **시드 (Seed)** : 의사 난수 생성기의 초기값으로, 동일한 시드를 입력하면 동일한 무작위 이벤트 시퀀스를 100% 재현(Reproducibility)할 수 있는 핵심 키
- **ANR (Application Not Responding)** : 안드로이드 등 모바일 OS에서 메인 UI 스레드가 일정 시간(5초) 이상 블로킹되어 먹통이 되는 오류 상태
- **퍼즈 테스팅 (Fuzz Testing)** : 유효하지 않거나 예기치 않은 기형적 데이터(Malformed Data)를 프로토콜/API에 주입하여 보안 취약점을 찾는 유사 기법

</details>

## 2~4교시 예상문제 (25점)

> 모바일 및 임베디드 소프트웨어의 강건성(Robustness) 검증을 위한 몽키 테스트(Monkey Test)의 개념과 도입 필요성을 설명하고, 덤 몽키(Dumb Monkey)와 스마트 몽키(Smart Monkey)의 비교, 무작위 결함의 재현성(Reproducibility) 확보 메커니즘 및 실무 적용 시의 한계 극복 방안을 제시하시오.

---

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 테스트 케이스 명세서 없이 의사 난수 생성기를 통해 생성된 무작위 이벤트 스트림을 애플리케이션에 맹목적으로 주입하여 예외 상황을 탐색하는 블랙박스 스트레스 시험 |
| 목적 | 인간 테스터가 상상하기 어려운 기형적인 사용자 조작 경로 발굴, 시스템 크래시(Crash) 및 메모리 누수 조기 검출, 애플리케이션 복원력(Resilience) 확보 |

## Ⅱ. 핵심 특징

정형화된 기능 테스트의 사각지대(Blind Spot)를 초고속 무작위 자동화로 보완.

| 핵심 영역 | 메커니즘 | 실무 효과 |
|---|---|---|
| **시나리오 무의존성** | 사전 테스트 케이스 작성 비용이 들지 않고 즉시 대규모 실행 가능 | 테스트 설계 공수 제로화 및 비용 효율적 버그 탐색 |
| **초고속 대량 인가** | 초당 수십~수백 건의 터치/키 이벤트를 쉼 없이 인가 | 동시성 경합(Race Condition) 및 메모리 누수 촉발 |
| **의사 난수 시드 기반** | 동일한 난수 시드(Seed) 번호 부여 시 동일 이벤트 시퀀스 재실행 | 무작위 테스트 결함의 치명적 단점인 재현 불가 문제 극복 |
| **시스템 복원력 계측** | 비정상 종료 시 즉각적인 덤프 파일 생성 및 오류 빈도수 측정 | MTBF(평균 고장 간격) 산출 및 안정성 지표 확보 |

## Ⅲ. 체계·프로세스

몽키 테스트의 실행 및 결함 재현(Seed Replay) 아키텍처 체계.

```text
+---------------------------------------------------------------------------------------------------------+
|                                    몽키 테스트 실행 및 시드 기반 결함 재현 체계                         |
+---------------------------------------------------------------------------------------------------------+
                                                                                                           
  [1] 테스트 파라미터 설정 (시드: --seed 12345, 이벤트 수: -v 50000, 쓰로틀: --throttle 100)              
           │                                                                                               
           ▼                                                                                               
  +───────────────────────────────────────────────────+                                                    
  | 의사 난수 이벤트 생성기 (Monkey Engine)           |                                                    
  | - 터치(Touch), 모션(Motion), 트랙볼, 키 이벤트    |                                                    
  +─────────────────────────┬─────────────────────────+                                                    
                            │ ADB 연결을 통한 초고속 이벤트 스트림 주입                                    
                            ▼                                                                              
  +───────────────────────────────────────────────────+                                                    
  | 대상 디바이스 / 애플리케이션 (Android App / Web)  |                                                    
  | - 비정상 동작 및 UI 렌더링 스트레스 인가          |                                                    
  +─────────────────────────┬─────────────────────────+                                                    
                            │ 실시간 모니터링 (Logcat / Crash Reporter)                                    
                            ▼                                                                              
  ─────────────────────────────────────────────────────────────────────────────────────────────────────────
  [2] 결함 판정 및 재현 프로세스                                                                           
                                                                                                           
  ┌─────────────────────────┴─────────────────────────┐                                                    
  ▼ (정상 실행 완료)                                  ▼ (결함 발생: Crash 또는 ANR 감지)                   
  [ 안정성 통과 (Pass) ]                              +───────────────────────────────────+                
                                                      | 크래시 로그 및 스택 트레이스 수집 |                
                                                      | 당시 Seed(12345) & 이벤트 번호 기록|                
                                                      +─────────────────┬─────────────────+                
                                                                        │                                  
                                                                        ▼ 동일 Seed로 100% 동일 재현       
                                                      +───────────────────────────────────+                
                                                      | 회귀 테스트 스위트화 및 결함 수정 |                
                                                      +───────────────────────────────────+                
```

- **몽키 테스트 4단계 실행 프로세스**:
  1. **실행 환경 및 파라미터 정의** : 난수 시드 번호, 이벤트 발생 간격(Throttle ms), 대상 패키지명을 커맨드로 지정.
  2. **무작위 이벤트 스트림 주입** : 안드로이드 UI Exerciser Monkey 도구가 터치, 화면 회전, 홈버튼 등 무작위 이벤트 인가.
  3. **실시간 이상 감지 및 로깅** : Logcat 로그를 실시간 필터링하여 NullPointerException, ANR 발생 시 즉시 프로세스 중단 및 스택 덤프 저장.
  4. **시드 기반 결함 재현 및 수정** : 동일 시드 번호로 디버거를 연결하여 문제를 재현하고, 확인된 버그를 자동화 회귀 테스트 케이스로 등록.

## Ⅳ. 종류·비교

#### 덤 몽키(Dumb Monkey) vs 스마트 몽키(Smart Monkey) 상세 비교

| 비교 항목 | 덤 몽키 (Dumb Monkey) | 스마트 몽키 (Smart Monkey) |
|---|---|---|
| **시스템 인지 수준** | 대상 소프트웨어의 상태, 화면 구조를 전혀 모름 | 화면 레이아웃, 클릭 가능 위젯, 활성 필드 인지 |
| **이벤트 생성 방식** | 순수 난수 좌표 기반 클릭 및 무차별 키 입력 | 현재 화면 맥락에 적합한 유효 이벤트 선별 인가 |
| **진입 심도** | 초기 로그인 화면이나 오류 팝업에 갇혀 탐색 중단 | 로그인 우회, 팝업 닫기 등을 수행하여 심층 화면 탐색 |
| **구축 및 실행 비용** | 도구 설치 즉시 실행 가능 (극도로 저렴) | 위젯 트리 분석 및 상태 모델링 학습 필요 (고비용) |
| **결함 발견 유형** | 단순 메모리 누수, UI 스레드 락, 시스템 크래시 | 복합 상태 전이 오류, 업무 로직 결함, 유효성 누락 |
| **대표 도구** | Android UI/Application Exerciser Monkey | Google App Crawler, DroidBot, Fastbot |

#### 몽키 테스트 vs 기능 테스트 vs 퍼즈 테스팅 비교

| 비교 항목 | 몽키 테스트 (Monkey Testing) | 기능 테스트 (Functional Testing) | 퍼즈 테스팅 (Fuzz Testing) |
|---|---|---|---|
| **입력 데이터** | 무작위 UI 인터랙션 이벤트 스트림 | 사전에 엄격히 설계된 테스트 케이스 | 기형적(Malformed) 프로토콜/바이너리 입력 |
| **검증 목적** | 시스템 크래시, ANR 등 안정성 검증 | 요구사항 명세서 기능 부합성 검증 | 버퍼 오버플로우, 메모리 오염 등 보안 취약점 |
| **테스트 오라클** | 비정상 종료(Crash) 유무로 단순 판정 | 참 오라클(기대값과의 1:1 비교) 판정 | 프로세스 강제 종료 및 세그멘테이션 폴트 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 수만 번의 무작위 클릭 중 크래시가 발생했을 때 정확한 재현 경로를 추적하기 어려움 | 고정된 난수 시드(`--seed`) 옵션을 반드시 지정하고 타임스탬프 기반의 화면 캡처 및 이벤트 로깅 결합 |
| 무작위 조작으로 인해 테스트용 결제 진행, 계정 탈퇴, 운영 DB 데이터 오염 등 비가역적 사고 유발 | 결제/탈퇴 등 파괴적 API는 Mocking 처리하고 격리된 샌드박스(Sandbox) 스테이징 환경에서만 실행 |
| 버튼 클릭 확률이 낮아 핵심 비즈니스 로직(장바구니 $\rightarrow$ 결제) 화면에 전혀 도달하지 못함 | 스마트 몽키(Smart Monkey)를 도입하거나 사전 인증 스크립트를 통해 특정 화면으로 강제 이동 후 테스트 실행 |

## Ⅵ. 제언

몽키 테스트는 기능 테스트를 대체할 수 없으므로, 정규 기능 검증이 완료된 야간 배치 파이프라인에서 앱의 피로도 및 장기 안정성을 계측하는 보완적 복원력 스트레스 검증 수단으로 운영할 필요가 있음.

```text
[CI 주간: 기능/단위 테스트 (100%)] ──> [야간 배치: 몽키 테스트 50만 회] ──> [Crash 발생 시 Seed 로깅] ──> [회귀 TC 편입]
      (DoD 충족 및 기능 검증)             (메모리 누수 & ANR 스트레스)          (재현 경로 자동 추출)         (안정성 극대화)
```

| 운영 영역 | 권장 실천 지침 | 핵심 관리 지표 |
|---|---|---|
| **배치 자동화** | 야간 CI 파이프라인(Jenkins)에서 에뮬레이터 대상 5만 회 몽키 실행 | 몽키 테스트 크래시 프리 세션(Crash-free Sessions) 99.5% 달성 |
| **재현성 보증** | 크래시 발생 시 당시 사용된 Seed 번호와 Logcat 자동 리포팅 | 크래시 재현 및 원인 분석 소요 시간 2시간 이내 단축 |
| **스마트화** | 덤 몽키 대신 상태 기반 Fastbot 머신러닝 탐색기 점진 도입 | 앱 화면 액티비티(Activity) 탐색 커버리지 70% 이상 달성 |
