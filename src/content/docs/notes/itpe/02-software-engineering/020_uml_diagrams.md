## 연관 키워드
- UML 2.x, 구조·행위 다이어그램, 클래스, 시퀀스, 상태, 활동

### Ⅰ. UML의 개요

- 핵심 요약 : UML은 객체지향 시스템의 구조와 행위를 시각적으로 명세·의사소통하는 표준 모델링 언어.
- 개념 : 시스템 이해관계자가 같은 관점으로 설계를 표현하도록 정의된 표기법과 다이어그램 체계(**UML**, Unified Modeling Language).
- 배경 및 필요성 : 복잡한 요구·구조·상호작용을 자연어만으로 공유하기 어렵다.
- 주요 목적 : 분석·설계·검증·문서화의 일관성 확보.

### Ⅱ. UML 다이어그램의 특징 및 장점

- 핵심 요약 : 구조 다이어그램은 정적 구성, 행위 다이어그램은 동작·상호작용을 표현.

1. 구조 관점 : 클래스·컴포넌트·배치 등 → 정적 의존·배포 구조 전달.
2. 행위 관점 : 활동·상태·시퀀스 등 → 흐름·상태 전이·메시지 순서 표현.
3. 다중 관점 : 동일 시스템을 목적별 모델로 분리 → 이해관계자 소통 지원.

### Ⅲ. UML 다이어그램 구성과 활동 흐름 (구조)

- 핵심 요약 : 구조·행위 다이어그램 중 질문에 맞는 관점을 선택하고 필요한 수준만 모델링.

```text
UML 다이어그램
├─ 구조: 클래스, 객체, 컴포넌트, 배치, 패키지, 복합구조, 프로파일
└─ 행위: 유스케이스, 활동, 상태기계, 시퀀스, 통신, 상호작용개요, 타이밍
```

```text
활동 시작 → 동작 → 분기(조건) → 포크(병렬 분기)
                          → 조인(동기화) → 종료
```

- 모델 자동화 : PlantUML·Mermaid 등 Diagrams as Code는 변경 이력·리뷰에 유리.

### Ⅳ. 구조·행위 다이어그램 비교

- 핵심 요약 : 클래스·컴포넌트는 무엇으로 구성되는지, 시퀀스·활동·상태는 어떻게 동작하는지 설명.

| 비교 축 | 구조 다이어그램 | 행위 다이어그램 |
|---|---|---|
| 초점 | 정적 요소·관계 | 시간에 따른 동작·상태 |
| 예 | 클래스, 컴포넌트, 배치 | 시퀀스, 활동, 상태기계 |
| 활용 | 모듈 경계·배포 구조 | 시나리오·프로세스·수명주기 |

### Ⅴ. UML 활용 한계와 방안

- 핵심 요약 : 과잉 상세화·모델과 코드 불일치가 문서 부채를 만들므로 의사결정에 필요한 모델만 유지.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
|---|---|---|---|
| 표기 복잡성 | 이해관계자 진입장벽 | 목적·독자별 최소 표기 | 모델 학습 시간 |
| 모델 노후화 | 코드와 문서 불일치 | 코드 생성·검증 또는 주기적 동기화 | 불일치 건수 |
| 범용 남용 | 한 장에 과다 정보 | 관점·추상화 수준 분리 | 다이어그램당 요소 수 |

### Ⅵ. UML 적용 제언

- 핵심 요약 : 아키텍트는 모델의 독자·질문·유지 책임을 정하고 설계 리뷰에 연결.

1. 요구분석가는 유스케이스·활동 모델로 업무 경계와 예외 흐름을 확인.
2. 개발팀은 클래스·시퀀스 모델로 책임과 협력 방식을 검토.
3. 플랫폼팀은 Diagrams as Code와 저장소 검증으로 최신 상태 유지.

### Ⅶ. 결론

- 핵심 요약 : UML은 시스템을 완전하게 그리는 목적이 아니라 구조·행위를 명료하게 공유하는 언어.
- 시사점 : 다이어그램은 설계 질문에 답하는 최소 범위로 작성하고 변경과 함께 관리.
