## 연관 키워드

- UML(Unified Modeling Language), OMG(Object Management Group), 구조 다이어그램, 행위 다이어그램
- 활동 다이어그램(Activity Diagram), 포크/조인(Fork/Join), 스윔레인(Swimlane), Diagrams as Code

## Ⅰ. UML 다이어그램 체계의 개요

- 핵심 요약 : 객체지향 시스템의 분석·설계·구현·배포 과정을 시각적으로 모델링하는 OMG 표준 모델링 언어.
- 개념 : 객체지향 소프트웨어 시스템의 분석, 설계, 구현, 배포 과정을 시각적으로 모델링하기 위해 OMG(Object Management Group)에서 표준화한 범용 통합 모델링 언어 (**UML**, Unified Modeling Language).
- 배경 및 필요성 : 개발자, 설계자, 발주자 간의 시각적 의사소통 표준화, 복잡한 시스템의 아키텍처 가시화, 모델 기반 개발(MDD, Model-Driven Development)의 청사진 제공 필요.
- 주요 목적 : 정적 구조와 동적 행위를 아우르는 표준 표기법을 통한 설계 의사소통의 일관성 확보.
- UML 2.x 분류 : 시스템의 정적 구조를 나타내는 구조 다이어그램(7종)과 동적 변화를 나타내는 행위 다이어그램(7종, 상호작용 포함)의 총 14종 구성.

## Ⅱ. UML 다이어그램의 특징

- 핵심 요약 : 정적 구조 7종과 동적 행위 7종의 이원 분류 체계.
1. 구조 다이어그램(7종) : 클래스·객체·패키지·컴포넌트·복합체 구조·배치·프로파일 다이어그램의 정적 구조 표현.
2. 행위 다이어그램(7종) : 유스케이스·활동·상태 머신 다이어그램과 상호작용 4종(순차·통신·타이밍·상호작용 개요)의 동적 변화 표현.
3. 표준화 : OMG 표준 표기법에 따른 도구·조직 간 모델 호환성 확보.
4. 시각적 의사소통 : 이해관계자별 관점 차이를 줄이는 공통 모델링 언어.
5. 모델 기반 개발 기반 : MDD의 설계 청사진 및 코드 생성 근거 제공.
6. 활동 다이어그램의 역할 : 비즈니스 프로세스, 유스케이스 실행 흐름, 객체 간 제어 흐름과 데이터 흐름의 워크플로우 형태 정밀 모델링.

## Ⅲ. UML 다이어그램의 구조 (흐름)

- 핵심 요약 : 14종 분류 체계와 활동 다이어그램의 분기·병렬 흐름 모델링.

```text
[ UML 2.x 다이어그램 (총 14종) ]
   ├─ 구조 다이어그램 (7종, 정적)
   │    클래스, 객체, 패키지, 컴포넌트,
   │    복합체 구조, 배치, 프로파일
   └─ 행위 다이어그램 (7종, 동적)
        유스케이스, 활동, 상태 머신 +
        상호작용 4종 (순차, 통신, 타이밍,
        상호작용 개요)
```

```text
[ 활동 다이어그램 예시: 주문 프로세스 ]
(● 시작) -> [ 주문 접수 ] -> < 재고 확인 >
                                   │
             ┌───────────────┴──────────┐
             ▼                          ▼
       [재고 있음]                 [재고 없음]
             │                          │
             ▼                          ▼
   ══ 포크(Fork) ══               [ 품절 안내 ]
      /            \                   │
     ▼              ▼                  ▼
  [ 결제 승인 ]  [ 배송 준비 ]     (◎ 종료)
      \            /
   ══ 조인(Join) ══
             │
             ▼
     [ 주문 완료 ] -> (◎ 종료)
```

- 활동 다이어그램의 핵심 구성요소 :

| 핵심 구성요소 | 표기법 및 의미 |
|---|---|
| 액션/액티비티 (Action/Activity) | 둥근 사각형. 실행 가능한 원자적 단위의 작업이나 복합 프로세스 |
| 분기 및 병합 (Decision/Merge) | 마름모꼴. 조건문([Guard])에 따른 흐름 분기와 다수 흐름의 단일 결합 |
| 포크 및 조인 (Fork/Join) | 굵은 가로선. 단일 흐름의 병렬 흐름 동시 분기(Fork) 및 모든 병렬 흐름 완료 대기(Join) |
| 스윔레인 (Swimlane) | 세로/가로 구분선. 작업을 수행하는 담당 조직, 시스템, 객체의 역할 경계 명시 |
| 객체 노드 (Object Node) | 직사각형. 액션 간에 주고받는 데이터 또는 객체 상태 명시 |

## Ⅳ. 구조 다이어그램과 행위 다이어그램의 비교

- 핵심 요약 : 구조 다이어그램은 정적 구성, 행위 다이어그램은 동적 동작의 표현 담당.

| 비교 항목 | 구조 다이어그램 (7종) | 행위 다이어그램 (7종) |
|---|---|---|
| 표현 대상 | 시스템의 정적 구조 (정적 모델링) | 시스템의 동적 변화 (동적 모델링) |
| 대표 종류 | 클래스, 객체, 패키지, 컴포넌트, 복합체 구조, 배치, 프로파일 | 유스케이스, 활동, 상태 머신, 순차, 통신, 타이밍, 상호작용 개요 |
| 답하는 질문 | 시스템이 무엇으로 구성되는가 | 시스템이 어떻게 동작하는가 |
| 활용 단계 | 분석·설계 초기 (도메인 모델링) | 상세 설계·프로세스 검증 |

- 실무 핵심 3대 다이어그램 : 클래스, 시퀀스, 상태 다이어그램의 선택적 집중 활용 권장.

## Ⅴ. UML 모델링의 장점과 한계

- 핵심 요약 : 표준화된 시각 소통의 장점, 모델-코드 단절·과도한 상세화·표기법 모호성의 한계.
- 장점
  1. 이해관계자 간 시각적 의사소통의 표준화.
  2. 복잡한 시스템 아키텍처의 가시화.
  3. MDD 기반 설계 청사진 및 코드 생성 근거 제공.
- 한계점 1 : 모델과 실제 코드 간 동기화 단절 및 문서의 형식화(Shelfware)
  - 한계점 : 프로젝트 초기 작성된 UML 다이어그램이 개발 진행 중 빈번한 코드 변경을 제때 반영하지 못해 실제 구현과 괴리되며 아무도 보지 않는 문서로 전락.
  - 해결 방안 : 다이어그램-애즈-코드(Diagrams as Code: PlantUML, Mermaid) 도입을 통한 설계 문서의 Git 형상 관리, CI(Continuous Integration) 파이프라인에서 코드 기반 리버스 엔지니어링 다이어그램 자동 갱신.
- 한계점 2 : 과도한 상세화로 인한 커뮤니케이션 오버헤드와 분석 마비(Analysis Paralysis)
  - 한계점 : 사소한 프라이빗 멤버와 세부 구현 알고리즘까지 모든 UML 메타모델 규격을 엄격히 작성하다 설계 작성 및 검토 공수가 과다 소모되어 개발 일정 지연.
  - 해결 방안 : 애자일 모델링(Agile Modeling) 원칙 적용을 통한 핵심 아키텍처 개념 및 복잡한 비즈니스 규칙 검증 중심의 스케치(Sketch) 용도 경량화, C4 모델 등 현대적 아키텍처 다이어그램 병행.
- 한계점 3 : UML 정규 표기법 해석의 모호성 및 팀원 간 숙련도 편차
  - 한계점 : 집약(Aggregation)과 합성(Composition), 실체화(Realization) 등 세부 표기법에 대한 이해도가 개발자마다 달라 설계 의도의 왜곡 전달 발생.
  - 해결 방안 : 조직 표준 UML 스타일 가이드라인과 레퍼런스 카탈로그 정립, 실무 핵심 3대 다이어그램(클래스, 시퀀스, 상태) 중심의 선택적 모델링 표준화 교육 수행.

## Ⅵ. 모델링 효율화를 위한 기술사적 제언

- 핵심 요약 : 적정 모델링 지향과 텍스트 기반 UML 도구의 형상관리 일원화.
- 애자일 환경에서의 적정 모델링(Just Enough Modeling) 지향 : 모든 코드를 UML로 작성하는 과도한 엔지니어링을 지양하고, 복잡한 비즈니스 워크플로우(활동 다이어그램), 도메인 엔티티 관계(클래스 다이어그램), 중요 시퀀스에 집중.
- PlantUML 및 Text-to-UML을 통한 형상관리 일원화 : 바이너리 모델 파일의 머지 충돌 방지를 위한 텍스트 기반 UML 도구 채택, Git 소스코드와의 통합 버전 관리 체계 구축 권장.
- 모델-코드 동기화 자동화 : CI 파이프라인 연동 리버스 엔지니어링을 통한 다이어그램의 최신성 유지.

## Ⅶ. 결론

- 핵심 요약 : UML은 14종 표준 다이어그램으로 정적 구조와 동적 행위를 모두 표현하는 모델링 표준.
- 요약 : 구조 7종과 행위 7종의 이원 분류 체계, 활동 다이어그램의 분기·병렬 흐름 모델링 활용.
- 시사점 : 과도한 상세화를 지양하는 적정 모델링과 Diagrams as Code 기반의 최신성 유지가 모델 가치의 핵심.
