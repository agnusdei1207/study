## 연관 키워드

- M2M(Machine-to-Machine), oneM2M, CSE(Common Services Entity), 사물 간 통신
- NB-IoT(Narrowband IoT), LTE-M(Cat-M1), LoRaWAN, 5G RedCap
- PSM(Power Saving Mode), eDRX(extended Discontinuous Reception), ACB(Access Class Barring), eSIM(embedded SIM), FOTA(Firmware Over-The-Air)

## Ⅰ. M2M(Machine-to-Machine) 통신의 개요

- 핵심 요약 : 사람의 개입 없이 기기가 망을 통해 데이터를 주고받아 무인 자동화를 실현하는 통신 체계.
- 개념 : 센서, 계측기, 기계 등 사물이 유무선 망을 매개로 상호 간에 정보를 수집·전달·처리하는 **M2M** (Machine-to-Machine, 기계 간 통신).
- 배경 및 필요성 : 원격 검침, 차량 관제, 시설물 감시 등 산업 전반에서 무인 자동화 수요가 늘고, 저비용 무선 모듈과 클라우드 인프라가 보급되면서 대량의 기기를 원격으로 묶어 관리할 필요가 커짐.
- 주요 목적 : 무인 자율 제어와 데이터 수집으로 인적 오류를 줄이고 운영 비용(OPEX, Operating Expenditure)을 낮추며, 이후 사물인터넷(IoT, Internet of Things)으로 확장될 기반 인프라를 마련.

## Ⅱ. M2M의 특징 및 장점

- 핵심 요약 : 기기 중심의 자율 데이터 교환과 표준 플랫폼이 운영 효율과 확장성을 함께 확보하는 방식.

1. 무인 자율 수집 : 기기가 주기적으로 측정값을 보내고 임계치를 넘으면 이벤트를 올림 → 현장 점검 인력과 방문 비용 절감.
2. 전력 절감 모드 : **PSM** (Power Saving Mode, 전송 후 깊은 동면에 들어가는 절전 상태)과 **eDRX** (extended Discontinuous Reception, 페이징 청취 주기를 길게 늘리는 기능)을 적용 → 배터리 교체 주기를 늘려 장기 현장 운용 가능.
3. 표준 공통 플랫폼 : **oneM2M** (사물 통신 국제 표준 아키텍처)의 CSE(Common Services Entity, 공통 서비스 엔티티)가 기기 등록, 보안, 데이터 저장을 공통 제공 → 응용별 개발 중복 감소와 기기 상호운용성 확보.
4. 원격 관리 : 원격 펌웨어 업데이트(FOTA, Firmware Over-The-Air)와 원격 진단으로 현장 방문 없이 기기를 유지 → 유지보수 비용 감소.

## Ⅲ. M2M의 구조 (흐름)

- 핵심 요약 : 디바이스 도메인에서 올라온 데이터가 네트워크와 공통 서비스 계층을 거쳐 응용으로 전달되는 세 단계 구조.
- 디바이스 도메인 : 센서, 액추에이터, 근거리 무선(Zigbee, 블루투스 저전력 BLE(Bluetooth Low Energy)) 모듈이 환경 데이터를 수집하고 게이트웨이로 전달.
- 네트워크 도메인 : 셀룰러(**NB-IoT** (Narrowband IoT), LTE-M, 5G)와 저전력 광역망(LPWAN, Low-Power Wide-Area Network)이 기기와 중앙 플랫폼을 잇는 백홀 역할.
- 서비스 도메인 : CSE가 장치 관리, 데이터 브로커링, 식별자 변환, 보안 제어를 일원화 수행.

```text
[ 디바이스 도메인 ]
센서 · 계량기 · 게이트웨이
        ↓ 근거리 무선 (Zigbee, BLE)
[ 네트워크 도메인 ]
NB-IoT · LTE-M · 5G · LoRa
        ↓ 백홀
[ 서비스 도메인 ]
CSE (등록·보안·데이터 브로커링)
        ↓
[ 응용 ]
관제·검침·헬스케어 서비스
```

```text
데이터 전송 완료
        ↓
PSM 진입 (등록 유지, 최소 전류)
        ↓
eDRX 주기로만 호출 대기
        ↓
다음 전송 시점에 깨어남
```

## Ⅳ. M2M 무선 기술의 비교

- 핵심 요약 : 면허 대역 셀룰러 계열과 비인가 대역 LPWAN 계열이 속도, 이동성, 전력, 보안 요구에 따라 나뉨.

| 비교 축 | NB-IoT | LTE-M (Cat-M1) | LoRaWAN | 5G RedCap |
| --- | --- | --- | --- | --- |
| 주파수 | 면허 대역 (LTE 대역 내) | 면허 대역 | 비인가 대역 (Sub-GHz) | 면허 대역 (5G NR 대역) |
| 전송 속도 | 수십 kbps 수준 | 약 1Mbps 수준 | 수십 kbps 이하 | 수백 Mbps급 |
| 이동성 | 정지형 위주 | 핸드오버 지원 | 제한적 | 지원 |
| 전력 특성 | PSM·eDRX로 장기 운용 | 장기 운용 가능 | 극저전력 | 상대적으로 높음 |
| 주요 활용 | 검침, 주차 센서 | 자산 추적, 웨어러블 | 농업, 환경 모니터링 | 산업용 센서, 영상 감시 |

- 선택 기준 : 데이터 양, 이동성, 배터리 요구를 먼저 정하고, 그다음 면허·비인가 대역 중 사용 가능한 망을 고른다.

## Ⅴ. M2M의 한계와 방안

- 핵심 요약 : 동시 접속 폭주, 현장 단말 보안, 펌웨어 관리의 세 한계를 접속 제어, 보안 칩, 원격 갱신으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 동시 접속 폭주 | 정전 복구 등 특정 시점에 대량 단말이 동시에 접속해 무선 접속 채널(RACH, Random Access Channel)이 포화 | ACB(Access Class Barring)로 접속을 제한하고, 송신 시점을 무작위로 분산 | 접속 성공률, 재시도 횟수 |
| 현장 단말 위변조 | 외부 노출 단말의 펌웨어 추출, 유심 복제, 미라이(Mirai) 계열 봇넷 감염 | 보안 칩(Secure Element) 내장, 보안 부팅(Secure Boot) 적용 | 무결성 검증 실패 건수 |
| 장기 운용 중 펌웨어 결함 | 현장 단말을 수동으로 갱신하기 어려움 | 전자서명 검증을 거친 원격 펌웨어 업데이트(FOTA) 체계 | 업데이트 성공률, 롤백 건수 |

## Ⅵ. M2M 적용 및 발전을 위한 기술사적 제언

- 핵심 요약 : 공공 조달에 oneM2M 호환을 명시하고, eSIM 원격 프로비저닝과 단말 TinyML 에지 판별을 도입해 상호운용성, 유지보수, 망 트래픽을 개선하는 것.

1. 공공 기관이 조달 기준에 oneM2M 호환을 명시하면 제조사별 사설 프로토콜이 줄어들어 데이터 사일로가 해소된다.
2. 기기 제조사는 eSIM(embedded SIM, 내장형 가입자 식별 모듈)을 탑재하고 통신사 프로파일을 원격으로 내려받는 구조를 설계해, 해외 출하 기기도 현장 교체 없이 유지보수할 수 있어야 한다.
3. 센서 단말에 TinyML을 탑재해 원시 데이터 대신 이상 징후만 전송하도록 설계하면 망 트래픽과 단말 전력 소모를 함께 줄일 수 있다.

## Ⅶ. 결론

- 핵심 요약 : M2M은 기기 간 자율 통신으로 무인 운영을 가능하게 하는 IoT의 기반 계층.
- 시사점 : 망 선택은 데이터량, 이동성, 배터리 조건에 맞춰야 하며, 접속 제어와 보안 설계가 대규모 운용의 성패를 가른다.
