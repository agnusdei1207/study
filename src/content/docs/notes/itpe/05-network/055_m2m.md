## Ⅰ. M2M(Machine-to-Machine) 통신의 개요

- 개념 : 인간의 직접적인 개입 없이 기계, 센서, 계측기기 등 지능화된 사물들이 유무선 통신망을 매개로 상호 간에 정보를 수집, 전달, 처리하는 지능형 통신 패러다임.
- 배경 및 필요성 : 원격 검침(AMR), 차량 관제(Telematics), 시설물 안전 감시 등 산업 전반의 무인 자동화 요구 증대와 저비용 무선 모뎀 및 클라우드 인프라의 보급 확산.
- 핵심 목적 : 무인 자율 제어 및 데이터 수집, 인적 오류 최소화, 운영 비용(OPEX) 절감 및 사물인터넷(IoT/AIoT)으로의 진화를 위한 기반 인프라 구축.

## Ⅱ. M2M의 핵심 아키텍처 및 동작 메커니즘

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ oneM2M / ETSI 표준 M2M 3계층 아키텍처 ]             │
│                                                                        │
│   [ 응용 계층 (Application Layer) ]                                    │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ 스마트시티 관제, 원격 검침, 커넥티드카, 헬스케어, 스마트팩토리 │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   ▼ Mca 인터페이스                     │
│   [ 공통 서비스 계층 (Common Service Layer) ]                          │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ oneM2M CSE (Common Services Entity)                            │   │
│   │  - 기기 등록  - 데이터 저장/공유  - 그룹 관리  - 보안/인증     │   │
│   │  - 구독/통지(Sub/Notify)          - 장치 원격 진단/펌웨어      │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   ▼ Mcn 인터페이스                     │
│   [ 네트워크 및 단말 계층 (Network & Device Layer) ]                    │
│   ┌───────────────────────┐              ┌─────────────────────────┐   │
│   │ 통신망 인프라         │              │ M2M 기기 및 게이트웨이  │   │
│   │ LTE-M / NB-IoT / 5G   │ ◄──────────► │ Zigbee, BLE, LoRa 센서  │   │
│   │ 위성 통신 / 유선망    │              │ 스마트 계량기, 환경센서 │   │
│   └───────────────────────┘              └─────────────────────────┘   │
└────────────────────────────────────────────────────────────────────────┘
```

- **디바이스 도메인 (Device Domain)** : 센서, 액추에이터 및 근거리 무선(Zigbee, BLE, Modbus) 모듈로 구성되어 환경 데이터를 수집하고 M2M 게이트웨이로 전달.
- **네트워크 도메인 (Network Domain)** : 셀룰러(NB-IoT, LTE-M, 5G), 저전력 광역망(LPWAN) 또는 유선망을 통해 디바이스와 중앙 플랫폼 간의 원거리 통신 백홀 제공.
- **애플리케이션 및 서비스 플랫폼 (Service Domain)** : oneM2M 표준 기반 공통 서비스 엔티티(CSE)가 장치 관리, 데이터 브로커링, 식별자 변환 및 보안 제어를 일원화 수행.

## Ⅲ. M2M 무선 통신 기술의 세부 유형 및 특성 비교 분석

| 비교 항목 | NB-IoT (Narrowband IoT) | LTE-M (Cat-M1) | LoRaWAN / Sigfox | 5G RedCap (Release 17+) |
|---|---|---|---|---|
| 주파수 대역 | 인가 대역 (Cellular In-band) | 인가 대역 (1.4 MHz 대역) | 비인가 대역 (920MHz Sub-GHz)| 인가 대역 (5G NR 대역) |
| 최대 전송속도 | ~ 100 kbps (초소용량) | ~ 1 Mbps (음성/FOTA 가능) | ~ 50 kbps (초협대역) | ~ 150 Mbps (고속 비디오) |
| 통신 거리 | 실외 10~15km (지하실 투과) | 5 ~ 10 km | 10 ~ 20 km (도심 5km) | 일반 5G 셀 커버리지 |
| 배터리 수명 | 10년 이상 (PSM/eDRX 적용) | 5 ~ 10년 | 10년 이상 (극저전력) | 수년 (고성능 센서용) |
| 단말 이동성 | 정지형 위주 (핸드오버 제약) | 완전 이동성 지원 (핸드오버) | 불가 / 제한적 | 초고속 이동성 지원 |
| 주요 서비스 | 수도/가스 검침, 주차 센서 | 자산 트래커, 웨어러블 | 스마트 농업, 환경 모니터링| 산업용 로봇, 무선 CCTV |

- **PSM (Power Saving Mode)** : 패킷 전송 후 깊은 동면(Deep Sleep)에 진입하여 등록 상태를 유지한 채 나노암페어(nA) 수준의 최소 전류만 소모.
- **eDRX (extended Discontinuous Reception)** : 페이징 청취 주기를 수십 분~수 시간으로 대폭 늘려 단말 대기 전력을 절감.

## Ⅳ. M2M 통신의 주요 한계점 및 해결 방안

- 수백만 대 단말 동시 접속 시 셀룰러 기지국 RACH 프리앰블 충돌 :
  - 한계점 : 재난 복구나 정전 복구 등 특정 시점에 대량의 M2M 단말이 동시에 접속 시도를 감행하여 무선 접속 채널(RACH) 붕괴 및 통신 마비 초래.
  - 해결 방안 : 기지국 ACB(Access Class Barring) 제어, 그룹 기반 페이징 및 패킷 송신 시간을 무작위 분산(Random Backoff)시키는 스케줄링 기법 강제.
- 현장 단말 보안 취약성 및 원격 펌웨어 위변조 위험 :
  - 한계점 : 단말이 외딴 현장에 물리적으로 노출되어 펌웨어 덤프, 유심(eSIM) 복제, DDoS 봇넷(Mirai 등) 감염 위협 상존.
  - 해결 방안 : 하드웨어 보안 칩(HSM / Secure Element) 내장, 부트로더 전자서명 검증(Secure Boot) 및 원격 무선 무결성 업데이트(FOTA) 표준 체계 의무화.

## Ⅴ. M2M 적용 및 발전을 위한 기술사적 제언

- oneM2M 국제 표준 플랫폼 중심의 상호운용성 확립 : 통신사 및 제조사별 파편화된 사설 프로토콜을 배제하고, 공공·민간 인프라 전체에 oneM2M 표준 아키텍처를 도입하여 데이터 사일로(Silo) 철폐.
- eSIM(embedded SIM) 기반의 글로벌 제로터치 프로비저닝 : 물리적 SIM 교체 없이 원격 통신사 프로파일 다운로드(RSP: Remote SIM Provisioning) 체계를 구축하여 글로벌 수출 기기의 유지보수 공수 절감.
- 단말 에지 AI(TinyML) 탑재를 통한 네트워크 트래픽 절감 : 센서 단말에서 원시(Raw) 데이터를 무조건 전송하지 않고, 초저전력 NPU를 통해 이상 징후만을 현장 판별하여 알람 이벤트만 상위로 전송하는 효율화 추구.
