## 30초 인출

- 본질: **M2M(Machine-to-Machine) 통신** : 사람의 직접적인 개입 없이 기계와 기계, 센서와 서버 간에 유무선 네트워크를 통해 자율적으로 정보를 수집, 전달, 처리하여 원격 모니터링 및 지능형 제어를 수행하는 통신 기술
- 메커니즘: M2M 디바이스 및 게이트웨이가 취합한 데이터를 코어망을 거쳐 공통 서비스 계층(oneM2M의 CSE) 및 애플리케이션(AE)으로 전달하며 표준 참조점(Mca, Mcc, Mcn) 기반 자원 모델로 상호작용
- 통찰: 대규모 단말 동시 접속 시 기지국 랜덤 액세스 채널(RACH) 혼잡 및 무인 기기 배터리 고갈 한계 극복을 위해 EAB 접속 제어와 PSM/eDRX 절전 스케줄링 연계 필수

<details>
<summary>핵심 용어</summary>

- **oneM2M** : 통신 서비스 계층의 파편화를 방지하고 글로벌 상호운용성을 제공하기 위해 설립된 국제 사실 표준화 기구
- **AE (Application Entity)** : 원격 검침, 스마트 홈 등 M2M 응용 서비스 로직을 탑재하고 CSE의 공통 기능을 호출하는 엔티티
- **CSE (Common Services Entity)** : 데이터 저장, 장치 관리, 구독/통지 등 M2M 공통 서비스 기능(CSF) 세트를 제공하는 핵심 엔티티
- **NSE (Network Services Entity)** : 하부 통신망(이동통신 코어망, 위성망 등)이 제공하는 메시지 전달 및 위치 조회 기능을 CSE에 중계하는 엔티티
- **PSM (Power Saving Mode)** : 단말이 기지국과 페이징 연결을 해제하고 극저전력 수면 상태로 진입하여 배터리 수명을 10년 이상 연장하는 기술
- **EAB (Extended Access Barring)** : 망 혼잡 시 일반 음성/데이터 트래픽 보호를 위해 M2M 저우선순위 단말의 기지국 접속을 선별 차단하는 3GPP 표준 기술

</details>

## 2~4교시 25점 답안

## Ⅰ. M2M 통신의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 인간의 개입을 배제하거나 최소화하여 기계 장치들이 센싱한 데이터를 유무선 통신망을 통해 상호 교환하고 자율적으로 제어 명령을 실행하는 지능형 통신 패러다임 |
| 목적 | 원격 무인 검침, 스마트 팩토리 설비 예지정비, 물류 자산 실시간 관제 등 산업 전반의 운영 자동화 및 데이터 기반 생산성 혁신 |

## Ⅱ. M2M 통신의 특징 및 3대 핵심 구조

| 계층 구조 | 구성 요소 | 핵심 역할 및 특징 |
|---|---|---|
| **디바이스/게이트웨이 계층** | 센서, 액추에이터, M2M 모뎀, 로컬 게이트웨이 | 주변 환경 데이터 계측, 단거리 통신(Zigbee/BLE) 트래픽 취합 및 상위 프로토콜 변환 |
| **네트워크 전달 계층** | 이동통신망(LTE-M/NB-IoT), 인터넷망, 전용 유선망 | 디바이스와 서버 간의 엔드투엔드 보안 터널링 및 대규모 M2M 트래픽의 QoS 보장 전달 |
| **서비스/플랫폼 계층** | M2M 서버, 데이터베이스, 응용 서비스(AE) | 디바이스 등록, 원격 펌웨어 업데이트(FOTA), 실시간 이벤트 분석 및 비즈니스 로직 실행 |

## Ⅲ. oneM2M 표준 기능 아키텍처 및 참조점 메커니즘

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ oneM2M 표준 기능 아키텍처 및 참조점 ]              │
│                                                                        │
│   [디바이스/게이트웨이 노드]                    [인프라/클라우드 노드]  │
│   ┌────────────────────┐                        ┌────────────────────┐ │
│   │ Application Entity │                        │ Application Entity │ │
│   │       (AE)         │                        │       (AE)         │ │
│   └─────────┬──────────┘                        └─────────┬──────────┘ │
│             │ Mca                                         │ Mca        │
│   ┌─────────┴──────────┐       Mcc 참조점       ┌─────────┴──────────┐ │
│   │  Common Services   ├───────────────────────►│  Common Services   │ │
│   │    Entity (CSE)    │                        │    Entity (CSE)    │ │
│   └─────────┬──────────┘                        └─────────┬──────────┘ │
│             │ Mcn                                         │ Mcn        │
│   ┌─────────┴─────────────────────────────────────────────┴──────────┐ │
│   │                   Network Services Entity (NSE)                  │ │
│   │             (하부 3GPP 셀룰러망, 유선망, 위성망 연계)             │ │
│   └──────────────────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────────┘
```

| 엔티티 및 참조점 | 역할 및 기능 명세 |
|---|---|
| **AE (Application Entity)** | 특정 도메인의 애플리케이션 비즈니스 로직 실행 (예: 스마트 미터링 클라이언트, 관제 UI) |
| **CSE (Common Services Entity)**| 등록(REG), 데이터 관리(DMG), 구독/통지(SUB), 보안(SEC) 등 공통 서비스 기능(CSF) 인스턴스 |
| **NSE (Network Services Entity)**| 기저의 통신 사업자 네트워크가 제공하는 메시징, 로케이션, 디바이스 트리거링 기능 추상화 |
| **Mca 참조점** | AE와 CSE 간의 표준 통신 인터페이스 (자원 생성, 조회, 수정, 삭제 RESTful CRUDN API) |
| **Mcc 참조점** | 서로 다른 노드에 위치한 CSE와 CSE 간의 분산 공통 서비스 정보 교환 인터페이스 |
| **Mcn 참조점** | CSE가 NSE의 하부 네트워크 서비스(예: 3GPP T8 인터페이스)를 제어하고 활용하는 인터페이스 |

## Ⅳ. M2M(사물 간 통신) vs 사물인터넷(IoT) 비교

| 비교 항목 | M2M (Machine-to-Machine) | 사물인터넷 (IoT: Internet of Things) |
|---|---|---|
| **개념 범위** | 특정 목적의 기계 간 단대단(Point-to-Point) 통신 | 인터넷 프로토콜(IP) 기반 개방형 만물 연결 생태계 |
| **통신 구조** | 폐쇄형 수직 사일로(Silo) 구조, 하드웨어 종속적 | 개방형 수평 계층 구조, 클라우드 및 오픈 API 연계 |
| **네트워크 프로토콜**| 통신사 전용망, 독자 프로토콜, 모듈 기반 통신 | 표준 인터넷 스택(IPv6/6LoWPAN, MQTT, CoAP, HTTP) |
| **비즈니스 모델** | 원격 검침, 차량 관제 등 단일 솔루션 중심 | 빅데이터 분석, 인공지능 융합 등 서비스 혁신 플랫폼 |
| **표준화 체계** | 3GPP MTC, ETSI M2M 중심 | oneM2M, OCF, IEEE, IETF 표준 공존 |

## Ⅴ. M2M 통신의 한계와 방안

| 한계 | 방안 |
|---|---|
| 동일 기지국 커버리지 내 수만 대의 M2M 단말이 동시에 데이터를 송신할 경우 3GPP 물리 랜덤 액세스 채널(PRACH 프리앰블) 충돌 및 코어망 제어 시그널링 폭증(Signaling Storm) 발생 | 기지국에서 M2M 단말 그룹별로 무선 접속 확률을 제어하는 EAB(Extended Access Barring) 표준을 활성화하고, 각 단말 송신 주기에 무작위 지연(Random Jitter)을 부가하여 피크 부하 분산 |
| 전력망이 공급되지 않는 원격지에 설치된 배터리 구동 무인 센서 단말이 잦은 무선 페이징 및 재전송으로 인해 1~2년 이내 조기 방전되는 전력 한계 | 3GPP 표준의 PSM(전력 절감 모드) 및 eDRX(주기적 간헐 수신) 타이머를 수 시간에서 수일 단위로 최적화하고, CoAP/CBOR 등 바이너리 압축 경량 프로토콜을 적용하여 무선 패킷 크기 극소화 |
| 원격지에 분산 배치된 수만 대 단말에 펌웨어 업데이트(FOTA) 배포 중 무선 패킷 유실 또는 전원 단절로 인한 단말 먹통(Bricking) 현상 발생 | A/B 파티션 구조의 듀얼 뱅크 플래시 메모리 설계를 채택하여 다운로드 무결성 및 암호학적 서명 검증 실패 시 기존 안정 펌웨어로 즉각 자동 롤백되는 Fail-safe 아키텍처 구현 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
이기종 M2M 단말을 수용하는 대규모 스마트 인프라 구축 시, 특정 벤더에 종속된 독자 프로토콜을 배제하고 글로벌 표준인 oneM2M 기반의 공통 서비스 플랫폼(CSE)을 백본에 배치하며, 원격 무인 장비의 사이버 보안을 위해 단말 하드웨어 레벨의 암호화 칩(eSE/TPM) 기반 디바이스 상호 인증(Mutual Authentication) 및 통신 구간 TLS 1.3 암호화 의무화 권장

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ oneM2M 스마트 시티 M2M 데이터 파이프라인 ]         │
│                                                                        │
│   [원격 M2M 센서]        [현장 게이트웨이]          [클라우드 CSE 서버]  │
│   (가속도/온습도)        (MN-CSE 노드)              (IN-CSE 노드)       │
│          │                      │                          │           │

│          ├─────────────────────►│                          │           │
│          │                      │ (프로토콜 바인딩 변환)   │           │
```

### 3. 기술 유형 및 비교 평가
| 구분 | 셀룰러 M2M (LTE-M / NB-IoT) | 사설 LPWAN (LoRaWAN / Sigfox) | 근거리 사설망 (Zigbee / BLE Mesh) |
|---|---|---|---|
| **사용 주파수** | 면허 대역 (통신사 전용 대역) | 비면허 대역 (ISM 920 MHz 등) | 비면허 대역 (2.4 GHz ISM) |
| **통신 거리** | 10 ~ 15 km (셀룰러 기지국) | 5 ~ 15 km (전용 게이트웨이) | 10 ~ 100 m (근거리 홉 통신) |
| **전송 속도** | 200 kbps ~ 1 Mbps | 0.3 ~ 50 kbps (저속) | 250 kbps ~ 2 Mbps |
| **망 구축 비용** | 인프라 구축 불필요 (월 회선료) | 자체 사설 기지국 구축 필요 | 메시 라우터 다수 구축 필요 |
| **주요 적합 영역**| 전국 단위 스마트 미터링, 커넥티드 카 | 대규모 농장 관개, 사설 공장 센서망 | 스마트 빌딩 조명 제어, 홈 네트워크 |
