## Ⅰ. Ultra Ethernet (UEC)의 개요

- **개념** : 대규모 인공지능(AI) 학습 및 고성능 컴퓨팅(HPC) 클러스터에서 폭증하는 이스트-웨스트(East-West) 트래픽을 처리하기 위해 리눅스 재단 산하 글로벌 빅테크 연합(UEC)이 개발한 차세대 초고성능 이더넷 기술 표준 규격.
- **배경 및 필요성** : 생성형 AI 및 LLM 모델 파라미터 폭증으로 수만 개의 GPU 간 올투올(All-to-All) 통신이 필수적이나, 기존 인피니밴드(InfiniBand)의 독점적 생태계·고비용 구조와 기존 RoCEv2(RDMA over Converged Ethernet)의 혼잡 제어 한계 봉착.
- **핵심 목적** : 개방형 표준 이더넷 기반의 초고대역폭·초저지연 패킷 전송, 대규모 인캐스트(Incast) 혼잡 붕괴 방지, RoCEv2를 능가하는 유연한 패킷 스프레이(Packet Spraying) 구현.

## Ⅱ. Ultra Ethernet의 핵심 아키텍처 및 동작 메커니즘

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ Ultra Ethernet 프로토콜 스택 아키텍처 ]             │
│                                                                        │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │          AI/HPC 응용 계층 (PyTorch, Megatron-LM, MPI)           │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   ▼                                    │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ UEC 소프트웨어 레이어 : libfabric / OpenFabrics Interfaces     │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   ▼                                    │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ UET (Ultra Ethernet Transport) 계층                            │   │
│   │  - 패킷 스프레잉 (비순서 패킷 전송) - 신속 패킷 트림 (Packet Trim) │   │
│   │  - 수신자 주도 신용 기반 흐름 제어  - 종단간 원격 측정 (Telemetry)│   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   ▼                                    │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ 물리/링크 계층 : 400G / 800G / 1.6T 고속 이더넷 + LL-FEC       │   │
│   └────────────────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────────────────┘
```

- **멀티패스 패킷 스프레잉 (Packet Spraying)** : 단일 플로우를 플로우 단위가 아닌 개별 패킷 단위로 잘게 쪼개어 가용한 모든 ECMP 네트워크 경로로 동시 분산 전송 (로드밸런싱 극대화).
- **비순서 패킷 수신 (Out-of-Order Delivery)** : 패킷이 서로 다른 지연의 경로를 거쳐 비순서로 도착해도 네트워크 스위치가 멈추지 않고, 종단 수신 NIC(하드웨어)가 직접 재정렬.
- **패킷 트림 (Packet Trimming)** : 스위치 버퍼가 혼잡할 때 전체 패킷을 버리지 않고 페이로드를 잘라낸 뒤 헤더만 즉시 송신단에 회신하여 초고속 재전송 유도.
- **수신자 주도 흐름 제어 (Receiver-Driven Credit Flow Control)** : 송신자가 무차별 푸시하는 대신, 수신자가 가용 버퍼를 고려하여 송신 권한(Credit)을 허여할 때만 전송.

## Ⅲ. Ultra Ethernet의 세부 구성 요소 및 경쟁 기술 비교 분석

| 비교 항목 | 인피니밴드 (InfiniBand NDR) | RoCEv2 (Lossless Ethernet) | Ultra Ethernet (UEC) |
|---|---|---|---|
| **표준화 주체** | IBTA (단일 벤더 독점 구조) | IBTA / IEEE 확장 | UEC (리눅스 재단 개방형 표준) |
| **네트워크 특성** | 신용 기반 완전 무손실 (Lossless) | 무손실 추구 (PFC/ECN 기반) | 손실 허용형 유연 전송 (Loss-tolerant) |
| **패킷 전송 방식**| 정적 단일 경로 또는 어댑티브 | 단일 경로 고정 (해시 기반) | 전 패킷 멀티패스 스프레잉 |
| **혼잡 제어** | 크레딧 기반 하드웨어 플로우 제어| PFC 데드락 및 인캐스트 위험 | 패킷 트림, 종단 텔레메트리, 수신자 신용 |
| **스위치 인프라** | 전용 인피니밴드 스위치 필수 | 표준 데이터센터 이더넷 스위치| 표준 고속 이더넷 스위치 및 UEC NIC |
| **확장성** | 수만 개 GPU 확장 시 비용 폭증 | 수천 개 이상 규모에서 성능 저하 | 10만 개 이상 초대규모 GPU 클러스터 |

- **LL-FEC (Low Latency Forward Error Correction)** : 물리 계층 비트 에러를 초저지연 알고리즘으로 즉시 정정하여 재전송 지연 방지.
- **하드웨어 직접 연동 API** : 커널 개입 없는 제로 카피(Zero-Copy) 및 OS 바이패스 메모리 직접 접근(RDMA) 최적화.

## Ⅳ. Ultra Ethernet의 주요 한계점 및 해결 방안

- **비순서 패킷 처리에 따른 수신단 NIC 버퍼 및 리오더링(Reordering) 오버헤드** :
  - **한계점** : 경로별 도착 시간 편차(Jitter)가 클 경우 수신 스마트 NIC의 재정렬 버퍼가 고갈되어 메모리 병목 및 CPU 개입 발생.
  - **해결 방안** : NIC 실리콘 내에 고속 하드웨어 리오더링 엔진 직접 내장 및 경로 지연 편차를 실시간 모니터링하여 스프레잉 비율 동적 조절.
- **신규 하드웨어(UEC 호환 NIC 및 스위치) 교체 비용 및 생태계 미성숙** :
  - **한계점** : 표준화 초기 단계로 인피니밴드 대비 상용 검증 레퍼런스 부족 및 인프라 교체 주기 요구.
  - **해결 방안** : 기존 RoCEv2 지원 스위치와의 소프트웨어 호환 계층 제공 및 주요 클라우드 CSP(Meta, MS 등) 주도의 검증된 오픈소스 스택 우선 보급.

## Ⅴ. Ultra Ethernet 적용 및 발전을 위한 기술사적 제언

- **AI 소버린(Sovereign) 데이터센터의 네트워크 종속 탈피** : 엔비디아 인피니밴드 일변도의 벤더 종속(Lock-in)을 타파하고, 이종 가속기(NPU) 클러스터를 수용하기 위해 UEC 기반 패브릭 선제 도입.
- **광 인터페이스(CPO: Co-Packaged Optics)와의 결합** : 800G/1.6T 시대로 진입함에 따라 구리선 한계를 극복하기 위해 UEC 표준 스위치에 CPO 및 광 상호연결 기술 융합 추진.
- **분산 학습 통신 라이브러리(NCCL) 최적화 연계** : All-Reduce, All-to-All 통신 기본 프리미티브가 UET 계층의 패킷 스프레잉과 직결되도록 Collective 통신 라이브러리 커스터마이징 필수.
