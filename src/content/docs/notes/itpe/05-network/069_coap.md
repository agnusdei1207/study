## 한 줄 본질
- 수십 KB 메모리와 건전지로 구동되는 초소형 센서 노드에 수백 바이트의 텍스트 헤더와 무거운 TCP 3-Way Handshake를 요구하는 HTTP의 구조적 부적합성 → 4바이트 이진 헤더와 UDP를 기반으로 2계층 분리(메시지 전송 + RESTful 요청/응답) 설계 → 초저전력 IoT 노드의 웹 표준 자원 접근 실현 / UDP 특성상 패킷 유실 시 자체 타이머 재전송 필요

## 핵심 용어
- CON(Confirmable Message): 수신자로부터 반드시 ACK(수신 확인) 응답을 받아야 하는 신뢰성 보장 메시지 타입으로, 타임아웃 내 미수신 시 지수 백오프로 자동 재전송
- Piggybacked Response: 클라이언트의 CON 요청에 대해 센서가 별도의 ACK를 먼저 보내지 않고, 수신 확인(ACK) 패킷 페이로드 안에 즉시 처리 결과 데이터(Response)를 함께 실어 보내 패킷 수를 1회로 줄이는 고효율 응용 기법
- Observe 옵션(RFC 7641): 클라이언트가 주기적으로 센서에 GET 폴링을 보내지 않고 단 1회 구독(Observe 등록)해 두면, 센서 값에 변화가 생길 때마다 센서가 비동기적으로 클라이언트에 최신 상태를 자동 푸시하는 확장 규격

## 핵심 통찰
- 웹의 RESTful 철학을 포기하지 않고 바이너리로 압축: HTTP의 URL 주소 체계와 상태 코드(2.05 Content, 4.04 Not Found), CRUD 메서드를 그대로 보존하면서, 텍스트 문자열을 이진 코드(Code 필드 8비트)로 치환해 패킷 크기를 극단적으로 축소
- TCP 연결 유지(Keep-Alive)의 족쇄에서 센서를 해방: TCP는 주기적으로 세션을 유지하기 위해 킵얼라이브 패킷을 주고받아야 하므로 센서가 잠들 수 없지만, CoAP는 비연결성 UDP 기반이므로 센서가 평소에 완전 수면(Deep Sleep)에 들어가 배터리를 수년간 보존
- MQTT와의 가장 결정적인 차이는 '중앙 브로커'의 존재 여부: MQTT는 모든 패킷이 중앙 서버(브로커)를 거쳐야 하지만, CoAP는 센서 노드 자체가 초소형 웹서버 역할을 수행하여 외부 게이트웨이나 다른 노드와 1:1 직접 통신(P2P)이 가능

## 이웃 토픽과 구분
- CoAP vs MQTT: CoAP는 UDP 기반의 1:1 RESTful 요청/응답 모델(단말이 직접 웹 자원 서빙, 분산 환경 유리) / MQTT는 TCP 기반의 중앙 브로커 발행/구독(Pub/Sub) 모델(지속 연결 필요, 중앙 집중 제어 유리)

## 문제·원인·대책
- 적용 상황: 배터리로 가동되는 산림 화재 감시 무선 센서망(6LoWPAN) 구축
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 수면 노드의 잦은 깨어남으로 인한 배터리 조기 방전 | 상태 확인을 위한 서버의 주기적 GET 폴링 요청 수신 | CoAP Observe 패턴 적용 및 센서 임계값 초과 시 비동기 통보(Event-driven) | 무의미한 폴링 트래픽을 차단해 센서 배터리 수명 5배 연장 |
| 1KB 이상의 펌웨어 전송 시 6LoWPAN 패킷 단편화 유실 | 802.15.4 MTU(127B) 한계로 IP 계층 단편화 시 1개 손실로 전체 폐기 | CoAP 블록 전송 옵션(Block-wise Transfer, RFC 7959) 적용 | 애플리케이션 계층에서 64B 단위 독립 블록 분할 및 손실 블록만 선별 재전송 |

## 이렇게 출제된다
- 제108회 1교시: "CoAP(Constrained Application Protocol)의 특징과 메시지 유형을 설명하시오." → 요구 포인트: 등장 배경(저전력 센서 제약), 4가지 메시지 유형(CON, NON, ACK, RST), HTTP와의 변환 게이트웨이 구조

## 내 의견
- [원시 DTLS 핸드셰이크의 배터리 고갈 방지와 OSCORE 종단 암호화 채택] CoAP 보안을 위해 전송 계층 DTLS를 기본 적용하면 다단계 핸드셰이크 패킷으로 인해 저전력 노드의 배터리가 급속히 소모되고 프록시를 거칠 때 종단 간 보안이 깨짐 → 나라면: 경량 IoT 보안 표준인 RFC 8613 OSCORE(Object Security for Constrained RESTful Environments)를 도입하여 CoAP 페이로드 자체만을 애플리케이션 계층에서 암호화함으로써, 중간 프록시 캐시를 자유롭게 경유하면서도 센서의 암호화 연산 오버헤드를 60% 이상 절감
