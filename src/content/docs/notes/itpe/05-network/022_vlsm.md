## Ⅰ. VLSM(Variable Length Subnet Mask)의 개요

- **개념** : 하나의 IP 네트워크 주소 공간 내에서 모든 서브넷이 동일한 크기의 고정 마스크를 사용하는 단점을 극복하고, 조직 내 각 서브넷별 호스트 규모에 맞추어 서로 다른 길이의 서브넷 마스크(/24, /27, /30 등)를 가변적으로 적용하는 계층적 주소 할당 기법.
- **배경 및 필요성** : 전통적 고정 길이 서브넷 마스크(FLSM)는 가장 큰 서브넷 기준으로 마스크를 통일해야 하므로, 단 2개의 IP만 필요한 Point-to-Point WAN 링크에도 수십~수백 개의 주소가 낭비되는 비효율을 해결하기 위해 개발됨.
- **핵심 목적** : 한정된 IPv4 사설/공인 주소 자원의 낭비 최소화, 조직 계층 구조에 부합하는 유연한 IP 플래닝, 최상위 라우터로의 깔끔한 경로 요약(Route Summarization) 지원.

## Ⅱ. VLSM(Variable Length Subnet Mask)의 핵심 아키텍처 및 동작 메커니즘

VLSM은 가장 큰 호스트 수를 요구하는 서브넷부터 내림차순으로 IP 블록을 우선 할당한 뒤, 남은 여여 주소를 재차 더 작은 서브넷으로 쪼개어 나가는 계층적 2진 트리 분할 메커니즘으로 동작함.

```text
[ VLSM 계층적 주소 분할 트리 메커니즘 ]

기준 네트워크 블록: 192.168.1.0/24 (총 256개 주소)

1단계: 대규모 부서 할당 (호스트 100개 필요 -> /25 선택: 128개 주소)
 192.168.1.0/25 (192.168.1.0 ~ 192.168.1.127) =======> [ 영업부: 사용 ]
 192.168.1.128/25 (잔여 블록) ───┐
                                  │ (재분할)
2단계: 중규모 부서 할당           ▼
 192.168.1.128/26 (호스트 50개 필요 -> 64개 주소) ====> [ 개발부: 사용 ]
 192.168.1.192/26 (잔여 블록) ───┐
                                  │ (재분할)
3단계: 소규모 및 WAN 링크 할당    ▼
 192.168.1.192/27 (호스트 20개 필요 -> 32개 주소) ====> [ 인사부: 사용 ]
 192.168.1.224/28 (잔여 블록) ───┐
                                  ▼
 192.168.1.224/30 (호스트 2개 필요 -> 4개 주소) ======> [ 라우터 P2P 링크 ]
 192.168.1.228/30 (호스트 2개 필요 -> 4개 주소) ======> [ 백업 P2P 링크 ]
```

- **내림차순 할당 원칙** : 주소 중복과 단편화를 방지하기 위해 반드시 가장 많은 호스트를 요구하는 서브넷부터 가장 적은 서브넷 순서로 블록을 순차 분할.
- **가용 호스트 계산 공식** : 서브넷 마스크의 호스트 비트 수가 $h$일 때, 유효 호스트 수는 $2^h - 2$ (네트워크 주소 및 브로드캐스트 주소 제외).
- **Point-to-Point 링크 최적화** : 라우터 간 1:1 연결에는 2개 호스트만 필요하므로 /30 마스크(4개 주소, 2개 호스트) 또는 RFC 3021 /31 마스크(2개 호스트) 적용.
- **클래스리스 라우팅 프로토콜 필수** : 라우팅 업데이트 패킷 내에 서브넷 마스크 정보를 명시적으로 전송하는 프로토콜(OSPF, EIGRP, RIPv2, BGP) 환경에서만 정상 작동.

## Ⅲ. VLSM(Variable Length Subnet Mask)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 고정 길이 서브넷팅 (FLSM) | 가변 길이 서브넷팅 (VLSM) | 도메인 간 라우팅 (CIDR) |
|---|---|---|---|
| **서브넷 마스크 길이**| 모든 서브넷이 동일한 마스크 | 서브넷마다 서로 다른 마스크 허용 | 마스크 길이에 제한 없음 |
| **주소 공간 분할** | 1단계 단일 분할 | 다단계 계층적 재분할 | 다중 네트워크 경로 집약 (슈퍼네팅)|
| **주소 낭비율** | 매우 높음 (작은 링크도 큰 마스크) | 매우 낮음 (필요 규모 맞춤 할당) | 글로벌 차원의 주소 고갈 지연 |
| **설계 복잡도** | 단순 (암산 및 계산 용이) | 복잡 (치밀한 비트 계산 필요) | BGP 라우팅 정책 수립 필요 |
| **프로토콜 요구** | RIPv1 등 Classful 프로토콜 가능| OSPF 등 Classless 프로토콜 필수 | BGPv4 등 CIDR 지원 장비 필수 |

- FLSM이 초기 네트워크의 단순성에 기여했다면, VLSM은 조직 내부 주소 설계의 표준이 되어 한정된 서브넷 공간을 100%에 가깝게 최적화하는 토대를 제공함.

## Ⅳ. VLSM(Variable Length Subnet Mask)의 주요 한계점 및 해결 방안

- **수동 비트 계산 실수로 인한 서브넷 중복(Overlap) 및 충돌** :
  - **한계점** : 비연속적 주소 할당이나 호스트 계산 실수 시 동일 IP 범위가 복수 부서에 중복 할당되어 라우팅 불가.
  - **해결 방안** : 중앙 집중식 IPAM(IP Address Management) 자동화 도구 도입 및 주소 할당 트리 전산화.
- **비연속적 서브넷 분할 시 상위 라우터 경로 요약(Route Summarization) 실패** :
  - **한계점** : 주소를 무분별하게 쪼개어 배치하면 상위 ABR 라우터에서 단일 프리픽스로 묶지 못하고 세부 라우팅 테이블 엔트리 폭증.
  - **해결 방안** : 지역 및 본부 단위로 상위 비트를 묶어 블록을 사전 배정한 후 그 내부에서만 VLSM 분할 수행.
- **Classful 레거시 라우팅 프로토콜과의 비호환성** :
  - **한계점** : 서브넷 마스크를 전달하지 않는 구형 장비나 RIPv1 망에서 서브넷 정보를 인식하지 못하고 기본 클래스로 축약 처리.
  - **해결 방안** : OSPF, IS-IS 등 완벽한 Classless 라우팅 프로토콜로의 백본 라우팅 인프라 전면 교체.

## Ⅴ. VLSM(Variable Length Subnet Mask) 적용 및 발전을 위한 기술사적 제언

- **클라우드 멀티 VPC/VNet 아키텍처 상의 VLSM 표준 템플릿 정립** : 퍼블릭 서브넷(/24), 프라이빗 WAS 서브넷(/23), DB 전용 서브넷(/26), 관리용 TGW 링크(/28) 등 규모별 표준 CIDR 템플릿 사전 수립 권장.
- **IaC(Infrastructure as Code) 기반 서브넷 프로비저닝 자동화** : Terraform 및 Ansible 코드 내에 VLSM 계산 로직을 내재화하여 인프라 생성 시 사람의 실수(Human Error)에 의한 IP 충돌 원천 배제.
- **사설 IP(RFC 1918) 고갈 대응을 위한 CGNAT 및 IPv6 전환 준비** : 기업 규모 확장에 따른 10.0.0.0/8 대역 고갈에 대응하여 마이크로 세그멘테이션과 함께 IPv6 서브넷(/64) 설계를 병행 추진.
