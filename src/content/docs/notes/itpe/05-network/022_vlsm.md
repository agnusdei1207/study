## 답안 골격
```text
[VLSM] ◀━━ 머리: Ⅶ 내 의견 (호스트 요구량 내림차순 정렬 배분 및 라우트 요약 결합)
 ┃
 ┣━ Ⅰ 개요 ───── 고정 마스크(FLSM)의 내부 단편화·IP 낭비 → 서브넷별 가변 마스크 적용
 ┣━ Ⅱ 특징 ───── 서브넷별 마스크 길이 상이, IP 낭비 최소화, 계층적 주소 할당, 라우트 요약 가능
 ┣━ Ⅲ 구조 ───── 대규모 서브넷(/24) + 중규모(/26) + 소규모(/28) + 점대점 WAN 링크(/30 또는 /31)
 ┣━ Ⅳ 흐름 ───── ① 필요 호스트 수 기준 내림차순 정렬 → ② 큰 서브넷부터 연속 할당 → ③ 미사용 대역 보존
 ┣━ Ⅴ 비교 ───── FLSM vs VLSM (단일 고정 마스크 vs 가변 마스크, RIPv1 지원 vs 클래스리스 필수)
 ┗━ Ⅵ 실무 ───── 서브넷 대역 오버랩(중복) 오류 / 라우팅 테이블 복잡성 / 주소 관리 난이도
```
- 필수 키워드: 가변 길이 서브넷 마스크 · FLSM · 내부 단편화 · 클래스리스 라우팅 · CIDR · 점대점 링크(/30)
- 기출: 139회 4교시 6번 `네트워크 서브네팅(Subnetting)과 관련하여 다음을 설명하시오. 개발팀 500명이 사용할 수 있도록 4개의 VLSM으로 분할한 각각의 Subnet Mask 값과 할당 가능한 Host IP 대역` → Ⅳ·Ⅵ

## 한 줄 본질
- 모든 서브넷에 동일한 크기의 마스크를 강제하는 고정 서브넷(FLSM)의 심각한 IP 내부 단편화 → 부서나 링크별 실제 필요 호스트 수에 맞춰 서로 다른 길이의 서브넷 마스크를 쪼개어 계층적으로 배분 → 공인/사설 IP 자원 효율 극대화 / 서브넷 마스크 정보를 교환하지 못하는 레거시 클래스풀 라우팅 프로토콜(RIPv1) 사용 불가

## 핵심 그림
```text
[ 192.168.1.0/24 대역을 요구 규모에 맞춘 VLSM 분할 트리 ]

                    192.168.1.0/24 (전체 256개 IP)
                                 |
                 +---------------+---------------+
                 |                               |
       [서브넷 A: 본사 개발팀]             192.168.1.128/25 (128개 잔여)
        192.168.1.0/25 (128개)                    |
        (가용 호스트: 126개)             +--------+--------+
                                         |                 |
                               [서브넷 B: 마케팅팀]   192.168.1.192/26 (64개 잔여)
                                192.168.1.128/26           |
                                (가용: 62개)       +-------+-------+
                                                  |               |
                                        [서브넷 C: 서버실]  [서브넷 D: WAN링크]
                                         192.168.1.192/28   192.168.1.252/30
                                         (가용: 14개)       (가용: 2개)
```

## 핵심 용어
- FLSM(Fixed Length Subnet Mask): 네트워크 전체에 단 하나의 서브넷 마스크만을 일률적으로 적용하여, 2개 IP만 필요한 WAN 링크에도 254개 대역을 낭비하는 전통적 방식
- 클래스리스 라우팅 프로토콜: 라우팅 정보 패킷을 보낼 때 IP 주소뿐만 아니라 해당 주소의 서브넷 마스크 길이까지 함께 전송하는 프로토콜 (OSPF, RIPv2, IS-IS, BGP)
- 내부 단편화(Internal Fragmentation): 할당된 서브넷 블록의 크기에 비해 실제 사용하는 호스트 수가 훨씬 적어 남는 IP 주소가 영원히 버려지는 현상

## 핵심 통찰
- VLSM 설계의 절대 제1원칙은 "가장 많은 호스트를 요구하는 서브넷부터 내림차순으로 우선 할당"해야 주소 공간의 쪼개짐과 중복 충돌을 방지할 수 있음
- 라우터 간 1:1 직결(Point-to-Point) WAN 구간은 호스트가 2개만 필요하므로, VLSM을 통해 반드시 `/30`(유효 2개) 또는 RFC 3021 기반 `/31`(유효 2개)을 적용해 낭비 차단
- 서브넷 마스크 길이가 제각각이 되므로, 라우터는 패킷을 전달할 때 목적지 IP와 가장 길게 일치하는 마스크를 가진 경로를 최우선 선택하는 "최장 일치 원칙(Longest Prefix Match)"을 필수 수행

## 이웃 토픽과 구분
- VLSM vs CIDR: VLSM은 단일 AS 조직 내부에서 서브넷을 서로 다른 크기로 쪼개는 기술 / CIDR은 전 세계 인터넷 백본에서 여러 클래스 네트워크를 하나로 묶어 라우팅 테이블을 요약(Supernetting)하는 기술

## 문제·원인·대책
- 적용 상황: 제139회 기출 500명 규모 개발팀 4개 서브넷 분할 요구 (총 500명 분할: 예 200명, 150명, 100명, 50명)
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 고정 /24 FLSM 적용 시 주소 고갈 또는 낭비 | 200명 부서와 50명 부서에 일률적으로 /24 마스크 적용 | 부서별 인원 기준 VLSM 차등 적용 (/24, /24, /25, /26) | 최소 주소 블록 소모로 잔여 IP 확보 및 단편화 제거 |
| 서브넷 간 대역 침범(IP Overlap)으로 라우팅 마비 | 2진수 비트 경계를 맞추지 않고 임의 숫자로 서브넷 시작 IP 지정 | 2의 거듭제곱($2^n$) 블록 경계 기반 계층적 서브네팅 | 서브넷 간 완벽한 독립 도메인 격리 및 정상 라우팅 보장 |

## 이렇게 출제된다
- 제139회 4교시 6번: "네트워크 서브네팅(Subnetting)과 관련하여 다음을 설명하시오. 개발팀 500명이 사용할 수 있도록 4개의 VLSM(Variable Length Subnet Mask)으로 분할한 각각의 Subnet Mask 값과 할당 가능한 Host IP 대역" → 요구 포인트: 서브넷별 호스트 요구량 산정, 서브넷 마스크(십진수/CIDR), 네트워크 주소, 사용 가능 IP 범위, 브로드캐스트 주소 표 작성

## 내 의견
- [수작업 서브네팅 계산의 휴먼 에러 방지] 엑셀이나 수작업으로 VLSM을 쪼개다 보면 비트 경계 오차로 인해 인접 서브넷과 주소가 겹치는 대형 장애 발생 빈발 → 나라면: 테라폼(Terraform)이나 앤서블(Ansible)의 IP 계산 모듈(`cidrsubnet()`)을 IaC 파이프라인에 내장하여, 조직 요구 인원수만 입력하면 수학적으로 검증된 VLSM 블록이 자동 생성되도록 표준화
