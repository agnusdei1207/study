## 30초 인출

- 본질: **VLSM(Variable Length Subnet Mask)** : 각 서브넷의 요구 규모에 맞춰 서로 다른 프리픽스 길이를 배정하는 주소 설계 기법
- 메커니즘: 호스트 수를 주소 블록 크기로 환산 → 큰 블록부터 정렬된 경계에 배치 → 중복·잔여 범위 확인
- 통찰: 조직 내 서브넷마다 상이한 호스트 규모를 갖는 현실을 반영하여 동일 네트워크 주소 공간 내에 서로 다른 서브넷 마스크를 중첩 적용함으로써 IPv4 주소 낭비를 원천적으로 최소화하는 가변 서브네팅 기법임.

<details>
<summary>핵심 용어</summary>

- **VLSM(Variable Length Subnet Mask)** : 네트워크별 주소 요구에 따라 서로 다른 길이의 서브넷 마스크를 적용하는 기법
- **FLSM(Fixed Length Subnet Mask)** : 모든 서브넷에 같은 길이의 마스크를 적용하는 설계
- **CIDR(Classless Inter-Domain Routing)** : 주소를 클래스 대신 네트워크 프리픽스 길이로 표현·라우팅하는 방식
- **프리픽스 길이(Prefix Length)** : 주소에서 네트워크 부분을 나타내는 비트 수
- **LPM(Longest Prefix Match)** : 목적지 주소와 일치하는 경로 중 가장 긴 프리픽스를 선택하는 규칙

## 2~4교시 25점 답안

## Ⅰ. VLSM(Variable Length Subnet Mask)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 하나의 동일한 클래스 네트워크 공간 안에서 서브넷별 호스트 요구 대수에 맞추어 서로 다른 길이의 서브넷 마스크(예: /24, /26, /28, /30)를 가변적으로 적용하는 주소 할당 기법 |
| 목적 | 호스트 수가 적은 구간(예: WAN P2P 링크)의 주소 낭비 방지, 주소 자원 이용률 극대화 및 계층적 라우팅 요약(Route Summarization) 기반 마련 |

## Ⅱ. VLSM(Variable Length Subnet Mask)의 특징

| 특징 | 상세 내용 |
|---|---|
| 가변적 마스크 적용 | 서브넷마다 필요한 IP 대수를 2의 거듭제곱으로 계산하여 최적 크기의 프리픽스(Prefix) 부여 |
| Classless 라우팅 필수| 라우팅 업데이트 패킷에 서브넷 마스크 정보를 함께 실어 나르는 Classless 라우팅 프로토콜 전제 |
| 계층적 주소 블록 | 대형 블록을 먼저 분할하고 남은 잔여 공간을 소형 블록으로 재분할하는 하향식(Top-down) 설계 |
| 서브넷 간 격리성 | 서브넷 마스크가 상이하더라도 주소 영역이 상호 중첩(Overlap)되지 않도록 엄격한 비트 경계 유지 |

## Ⅲ. VLSM(Variable Length Subnet Mask)의 체계·프로세스

**VLSM 하향식 계층 분할 메커니즘 및 주소 맵 트리**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ VLSM 하향식 서브넷 분할 트리 ]                │
│                                                                        │
│   [ 원본 네트워크: 192.168.10.0/24 (총 256개 IP) ]                     │
│   │                                                                    │
│   ├─── 1차 분할: /25 (128개 단위 분할)                                 │
│   │     ├─ Subnet A (192.168.10.0/25) ──► 영업부 (필요 호스트: 100대)  │
│   │     └─ [ 잔여 블록: 192.168.10.128/25 ]                           │
│   │           │                                                        │
│   │           ├─── 2차 분할: /26 (64개 단위 분할)                      │
│   │           │     ├─ Subnet B (192.168.10.128/26) ──► 개발부 (50대)  │
│   │           │     └─ [ 잔여 블록: 192.168.10.192/26 ]                │
│   │           │           │                                            │
│   │           │           ├─── 3차 분할: /27 (32개 단위 분할)          │
│   │           │           │     ├─ Subnet C (192.168.10.192/27) (20대) │
│   │           │           │     └─ [ 잔여 블록: 192.168.10.224/27 ]   │
│   │           │           │           │                                │
│   │           │           │           └─── 4차 분할: /30 (4개 단위)    │
│   │           │           │                 ├─ WAN P2P-1 (.224/30) (2) │
│   │           │           │                 └─ WAN P2P-2 (.228/30) (2) │
└────────────────────────────────────────────────────────────────────────┘
```

| 설계 단계 | 수행 작업 내용 | 핵심 고려사항 |
|---|---|---|
| **1단계: 호스트 수요 파악** | 각 부서/구간별 필요 호스트 수를 내림차순(가장 큰 요구부터) 정렬 | 향후 증설 여유율(20~30%) 사전 반영 |
| **2단계: 마스크 비트 산출** | `2^h - 2 >= 필요호스트 수` 공식을 만족하는 최소 호스트 비트 h 산출 | 서브넷 마스크 프리픽스 `n = 32 - h` 결정 |
| **3단계: 큰 블록부터 할당** | 가장 큰 서브넷부터 차례대로 연속된 IP 블록을 배치 | 서브넷 시작 주소는 반드시 블록 크기의 배수여야 함 |
| **4단계: 초소형 블록 세분화**| WAN 라우터 간 Point-to-Point 구간은 `/30` 마스크로 잔여 블록 할당 | 가용 IP 2개만 할당하여 주소 낭비 완벽 차단 |

## Ⅳ. VLSM(Variable Length Subnet Mask)의 종류·비교

| 비교 항목 | 고정 길이 서브네팅 (FLSM) | 가변 길이 서브네팅 (VLSM) |
|---|---|---|
| **서브넷 마스크 크기** | 모든 서브넷에 단일 마스크 일괄 적용 | 서브넷마다 서로 다른 마스크 가변 적용 |
| **주소 낭비율** | 매우 높음 (WAN P2P 링크에서도 /24나 /26 사용)| 극히 낮음 (필요 수량에 정확히 맞춤 할당) |
| **설계 난이도** | 단순 (동일 간격 산술 분할) | 높음 (비트 중첩 검증 및 트리형 계산 필요) |
| **경로 집약 (CIDR)** | 제한적 요약 | 완벽한 계층형 슈퍼네팅(Supernetting) 구현 가능 |
| **필수 라우팅 프로토콜**| RIPv1, IGRP 등 Classful 프로토콜 지원 가능 | RIPv2, OSPF, EIGRP, BGP 등 Classless 전용 |

## Ⅴ. VLSM(Variable Length Subnet Mask)의 한계와 방안

| 한계 | 방안 |
|---|---|
| 주소 계산 실수 시 인접 서브넷 간 IP 영역 중첩(Overlap)으로 통신 단절 장애 발생 | IPAM(IP Address Management) 자동화 솔루션 도입 및 넷마스크 유효성 검증 스크립트 실행 |
| 비계층적 할당 시 라우팅 테이블 파편화로 인해 상위 라우터 경로 축약 불가 | 지리적/조직적 계층 구조에 맞추어 대형 프리픽스를 사전 배분한 후 내부에서 VLSM 분할 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
VLSM 설계 시 반드시 **가장 많은 호스트를 요구하는 서브넷부터 먼저 할당** 하는 원칙을 엄수해야 함. 만약 작은 블록을 먼저 중간에 할당하면 큰 연속 블록이 쪼개져 대규모 서브넷 할당이 물리적으로 불가능해지는 '주소 파편화' 현상 발생.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ WAN Point-to-Point 구간 주소 최적화 비교 : /24 vs /30 vs /31 ]      │
│                                                                        │
│   [ Router A ] ════════════════════════════════════════ [ Router B ]   │
│                                                                        │
│   1. FLSM /24 적용 시 : 총 256개 중 2개만 사용 ──► 254개 IP 낭비 (0.7%)│
│   2. VLSM /30 적용 시 : 총 4개 중 2개 사용 ────► 2개 IP 낭비 (50.0%)  │
│   3. RFC 3021 /31 적용시: 네트워크/BC 없이 2개 전부 사용 ──► 낭비 0개  │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 프리픽스 길이 | 서브넷 마스크 | 블록 크기 | 가용 호스트 수 | 주 용도 |
|---|---|---|---|---|
| **/24** | 255.255.255.0 | 256 | 254 | 대규모 본사 공용 LAN, 클라우드 VPC |
| **/26** | 255.255.255.192 | 64 | 62 | 중간 규모 지사, 부서별 독립 네트워크 |
| **/28** | 255.255.255.240 | 16 | 14 | 소규모 서버 팜, DMZ 구간 |
| **/30** | 255.255.255.252 | 4 | 2 | 라우터 간 WAN Point-to-Point 링크 |
