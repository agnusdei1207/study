## 연관 키워드

- VLSM(Variable Length Subnet Mask), 가변 길이 서브넷 마스크, 고정 길이 서브네팅(FLSM, Fixed Length Subnet Mask)
- 프리픽스 길이(Prefix Length), 호스트 비트, 라우트 요약(Route Summarization)
- 클래스리스 라우팅 프로토콜, IPAM(IP Address Management)

## Ⅰ. VLSM의 개요

- 핵심 요약 : 하나의 상위 주소 블록을 서브넷별 수요 규모에 맞춰 서로 다른 프리픽스 길이로 배정하는 주소 설계 기법.
- 개념 : 서브넷마다 요구 호스트 수에 맞는 마스크 길이를 달리 적용하는 **가변 길이 서브넷 마스크** (VLSM, Variable Length Subnet Mask) 기법.
- 배경 및 필요성 : 모든 서브넷을 같은 크기로 나누는 고정 길이 서브네팅(FLSM, Fixed Length Subnet Mask)은 최대 서브넷 기준의 균등 분할이라 호스트 2개짜리 링크에도 대형 블록이 배정되는 낭비가 발생.
- 주요 목적 : 제한된 주소 공간의 활용률 향상과 조직 구조에 맞는 계층적 주소 체계 구축.

## Ⅱ. VLSM의 특징 및 장점

- 핵심 요약 : 수요 기반 프리픽스와 계층 분할이 주소 절약과 경로 집약으로 이어지는 설계 방식.

1. 수요 기반 배정 : 서브넷별 필요 호스트 수에 맞춘 마스크 길이 선택 → 소규모 링크의 주소 낭비 제거.
2. 계층적 재분할 : 상위 블록을 단계적으로 나누어 배치 → 주소 구조가 조직 구조와 일치하는 관리 용이성.
3. 경로 집약 지향 : 인접 서브넷을 같은 상위 블록 안에 모아 배치 → **라우트 요약** (Route Summarization, 여러 경로를 한 프리픽스로 묶어 광고) 가능.
4. 증설 유연성 : 신규 서브넷을 잔여 블록에서 분할 → 전체 재설계 없는 확장.

## Ⅲ. VLSM의 구조 (흐름)

- 핵심 요약 : 수요 정렬 → 프리픽스 산정 → 내림차순 배정 → 잔여 재분할의 반복 절차.
- **프리픽스 길이** (Prefix Length) : 주소 중 네트워크 부분의 비트 수로, 서브넷 크기를 결정하는 표기.
- **호스트 비트** : 서브넷 내 가용 주소를 만드는 비트로, h비트일 때 사용 가능 호스트 수는 2^h − 2개 (네트워크 주소·브로드캐스트 주소 제외).
- **내림차순 배정 원칙** : 필요 주소가 큰 서브넷부터 상위 블록 앞쪽에 배치해야 프리픽스 경계가 맞고 중복 배정이 방지됨.

```text
[ VLSM 할당 절차 ]

부서별 필요 호스트 수 조사
   ↓ 규모 내림차순 정렬
서브넷별 프리픽스 길이 산정
   ↓
대형 서브넷부터 상위 블록 배치
   ↓
잔여 블록 재분할 반복
   ↓
할당표 문서화·주소 관리 등록
```

```text
[ 내림차순 배정 예시 ]

상위 블록 /24
   ↓ 필요 100호스트 → /25 배정
잔여 /25
   ↓ 필요 50호스트 → /26 배정
잔여 /26
   ↓ 필요 20호스트 → /27 배정
잔여 /27 : 소형 링크·예비용
```

## Ⅳ. VLSM과 고정 길이 서브네팅의 비교

- 핵심 요약 : 고정 길이는 계산이 단순하고 가변 길이는 주소 효율과 확장성이 우수한 상보적 기법.

| 비교 축 | FLSM (고정 길이) | VLSM (가변 길이) |
| --- | --- | --- |
| 마스크 길이 | 모든 서브넷 동일 | 서브넷마다 상이 |
| 분할 방식 | 1단계 균등 분할 | 다단계 계층 분할 |
| 주소 활용률 | 최대 서브넷 기준 낭비 발생 | 수요 맞춤 낭비 최소 |
| 계산 복잡도 | 단순 | 정렬·경계 계산 필요 |
| 요구 라우팅 | 별도 제약 없음 | 마스크 전달형 프로토콜 |

- 선택 기준 : 균등한 소규모 내부망은 고정 길이로 충분하고, 부서 규모와 링크 유형이 다양한 조직망은 가변 길이 배정을 적용.

## Ⅴ. VLSM의 한계와 방안

- 핵심 요약 : 계산·기록 오류, 요약 불가 배치, 프로토콜 제약을 주소 관리 도구·사전 블록 설계·클래스리스 전환으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 배정 중복 오류 | 수작업 경계 계산 실수로 같은 대역이 이중 배정되어 라우팅 혼란 | **IPAM** (IP Address Management, 주소 할당의 중앙 관리 도구) 도입과 자동 중복 검사 | 중복 배정 건수 |
| 요약 불가 배치 | 서브넷이 여러 상위 블록에 흩어지면 경로 항목이 늘어남 | 지역·본부 단위 상위 블록 사전 배정 후 그 안에서만 분할 | 광고 경로 수 |
| 프로토콜 제약 | 마스크를 전달하지 않는 구형 라우팅 프로토콜에서 서브넷 정보 손실 | **클래스리스 라우팅 프로토콜** (서브넷 마스크를 함께 교환하는 프로토콜) 사용 | 미대응 장비 수 |

## Ⅵ. VLSM에 대한 기술사적 제언

- 핵심 요약 : 주소 설계를 개인 계산에 맡기지 않고 표준 템플릿과 절차 체계로 관리할 필요.
- 네트워크 설계 조직 : 업무 유형별 표준 프리픽스 템플릿을 수립해 신규 구간 설계의 일관성 확보.
- 인프라 운영 조직 : 주소 할당·회수를 변경 관리 프로세스와 연계해 무단 배정과 잔여 블록 방치 방지.
- 전사 IT 기획 조직 : 주소 공간 여유 진단을 정기화하고 IPv6 전환을 위한 주소 계획 원칙 병행 수립.

## Ⅶ. 결론

- 핵심 요약 : VLSM은 수요 규모에 맞춘 가변 프리픽스 배정으로 주소 효율을 높이는 계층적 설계 기법.
- 주소 효율은 계산 정확성과 경로 집약 설계가 함께 뒷받침될 때 실현됨.
