## Ⅰ. CDN(Content Delivery Network)의 개요

- 개념 : 전 세계 주요 ISP(인터넷 서비스 제공자) 네트워크 에지(Edge)에 분산 캐시 서버 팜을 배치하여, 사용자가 요청한 콘텐츠를 물리적으로 가장 가까운 에지 서버에서 즉시 전송하는 분산 콘텐츠 전송 네트워크 기술.
- 배경 및 필요성 : 원거리 단일 오리진(Origin) 서버에 글로벌 트래픽이 집중될 경우 대륙 간 왕복 지연 시간(RTT) 급증, 회선 대역폭 포화, 서버 다운 및 서비스 체감 품질(QoE) 악화 발생.
- 핵심 목적 : 최종 사용자 응답 지연 시간(Latency) 극소화, 원본 오리진 서버 부하 및 네트워크 회선 비용 절감, 대규모 디도스(DDoS) 공격 트래픽의 에지단 분산 흡수.

## Ⅱ. CDN의 핵심 아키텍처 및 동작 메커니즘

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ CDN 사용자 요청 라우팅 및 캐싱 절차 ]              │
│                                                                        │
│   [ 사용자 (User) ]                                                    │
│          │                                                             │
│          │ 1. DNS 쿼리 (www.service.com)                               │
│          ▼                                                             │
│   [ GSLB / DNS 라우팅 ] ──► Anycast BGP / Geo-DNS 기반 최적 에지 선별   │
│          │                                                             │
│          │ 2. 최적 에지 IP 반환 (예: Edge Server A)                    │
│          ▼                                                             │
│   [ 사용자 (User) ] ───────── 3. HTTP GET 콘텐츠 요청 ────────────────┐│
│                                                                       ││
│   ┌──────────────────────────────────────────────────────────┐        ││
│   │              CDN 에지 서버 (Edge Server A)                │◄───────┘│
│   │                                                          │         │
│   │ [ Cache Hit ]  ──► 4. 캐시된 콘텐츠 즉시 반환 (초저지연)  │         │
│   │                                                          │         │
│   │ [ Cache Miss ] ──► 5. 원본 서버로 요청 포워딩 (Origin)    │         │
│   └──────────────────────────────┬───────────────────────────┘         │
│                                  │                                     │
│                                  │ 6. 원본 데이터 인출 및 에지 캐싱    │
│                                  ▼                                     │
│                     ┌──────────────────────────┐                       │
│                     │    원본 서버 (Origin)     │                       │
│                     └──────────────────────────┘                       │
└────────────────────────────────────────────────────────────────────────┘
```

- **GSLB (Global Server Load Balancing) 기반 요청 라우팅** :
  - **GeoDNS 방식** : 클라이언트의 Local DNS IP 주소를 기반으로 지리적으로 가장 근접한 에지 PoP의 IP 주소를 반환.
  - **Anycast BGP 방식** : 전 세계 모든 에지 서버가 동일한 단일 IP 주소를 BGP로 공통 광고하고, 인터넷 라우터가 네트워크 최단 홉 경로의 에지로 자동 라우팅.
- **캐시 처리 라이프사이클 (Cache Hit vs Miss)** :
  - **Cache Hit** : 요청된 리소스가 에지에 유효한 상태(TTL 내)로 존재하면 즉시 클라이언트로 서빙.
  - **Cache Miss** : 에지에 리소스가 없거나 만료된 경우, 오리진 서버로 원본을 요청하여 클라이언트에 응답함과 동시에 로컬 디스크/메모리에 캐시 저장.
- **동적 콘텐츠 가속 (DSA: Dynamic Site Acceleration)** : 캐싱이 불가능한 동적 API 트래픽에 대해 에지와 오리진 간 사전 수립된 TCP 커넥션 풀(Persistent Connection), 최적 라우팅 경로 탐색, TLS 핸드셰이크 단축 기법 적용.

## Ⅲ. 세부 구성 기술 및 캐시 무효화 전략 비교 분석

| 비교 항목 | TTL 기반 자동 만료 | 즉각 무효화 (Instant Purge) | 서로게이트 키 (Cache-Tags) | Stale-While-Revalidate |
|---|---|---|---|---|
| 동작 원리 | `Cache-Control: max-age` 설정 시간이 지나면 만료 | 관리자 API 호출로 특정 URL 캐시 즉시 강제 삭제 | 연관된 리소스 그룹에 태그를 부여하여 일괄 무효화 | 백그라운드에서 비동기 갱신 중 구 버전 즉시 응답 |
| 반영 속도 | 설정된 TTL 경과 후에만 갱신 | 수 초~수 분 내 글로벌 반영 | 수 초 내 전 세계 에지 일괄 삭제 | 사용자 체감 지연 0ms 즉각 응답 |
| 오리진 부하 | 만료 주기마다 규칙적 인출 | 대규모 Purge 시 오리진 트래픽 폭증 | 변경된 엔티티 관련 페이지만 정밀 타격 | 오리진에 스파이크 부하 원천 차단 |
| 적합한 대상 | 정적 이미지, JS, CSS 번들 | 긴급 오류 수정, 보안 패치 | 이커머스 상품 상세, 카테고리 페이지 | 뉴스 기사, 피드 리스트, 가격 정보 |

- **에지 컴퓨팅 (Edge Workers)** : 단순 정적 캐싱을 넘어 Cloudflare Workers, AWS Lambda@Edge처럼 에지 서버 상에서 V8 자바스크립트 엔진 또는 Wasm(WebAssembly) 코드를 구동하여 사용자 인증, A/B 테스팅, 동적 HTML 조립을 에지에서 직접 완결.

## Ⅳ. CDN 운영 시 주요 한계점 및 엔지니어링 해결 방안

- 대규모 캐시 만료 시 캐시 스탬피드(Cache Stampede / Thundering Herd) :
  - 한계점 : 핫딜 오픈이나 인기 콘텐츠의 TTL 만료 시 수십만 명의 동시 요청이 일시에 오리진 서버로 전달되어 오리진 데이터베이스 붕괴.
  - 해결 방안 : `Request Collapsing`(에지 서버가 오리진으로 단 1개의 요청만 보내고 나머지 클라이언트는 해당 응답을 대기 공유) 및 `Stale-While-Revalidate` 패턴 필수 적용.
- Anycast BGP 라우팅 불안정에 따른 TCP 세션 단절 :
  - 한계점 : 인터넷 백본 라우팅 경로 변동 시 진행 중이던 다운로드 패킷이 다른 국가의 에지 서버로 튀어 TCP 연결 리셋(RST) 발생.
  - 해결 방안 : 에지 서버 클러스터 간 분산 상태 공유(Consistent Hashing) 또는 클라이언트-에지 간 터널링 복구 기술 도입.

## Ⅴ. CDN 적용 및 발전을 위한 기술사적 제언

- 멀티 CDN(Multi-CDN) 아키텍처 구축을 통한 무장애성 확보 : 특정 글로벌 CDN 벤더(Fastly, Cloudflare 등)의 글로벌 장애 발생 시 서비스 마비를 방지하기 위해 RUM(Real User Monitoring) 성능 기반 실시간 DNS 트래픽 스위칭 체계 구축.
- 보안과 네트워크의 융합: WAAP(Web App and API Protection) 내재화 : 전통적 CDN 에지에 WAF, API 이상 탐지, DDoS 방어, 봇 관리(Bot Management)를 단일 서비스형 소프트웨어로 통합 제공하는 SASE/WAAP 체계 수용.
- 초저지연 라이브 스트리밍(LL-HLS / WebRTC-HTTP) 최적화 : 1초 미만 실시간 인터랙티브 방송 구현을 위해 청크 전송 인코딩(Chunked Transfer)과 에지 기반 분산 시그널링 아키텍처 적극 도입.
