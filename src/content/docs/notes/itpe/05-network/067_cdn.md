## 30초 인출

- 본질: **CDN(Content Delivery Network)** 은 사용자 가까운 분산 서버에서 콘텐츠를 전달하는 네트워크 서비스
- 메커니즘: 캐시 가능한 콘텐츠를 에지에 저장하고, 요청을 적절한 에지로 보내 응답 지연과 원본 부하를 낮춤

<details>
<summary>핵심 용어</summary>

- **CDN(Content Delivery Network):** 분산된 캐시·복제 서버를 이용해 사용자에게 콘텐츠를 전달하는 네트워크 서비스
- **에지(Edge):** 사용자 요청을 가까운 네트워크 지점에서 처리하는 CDN 서버
- **원본(Origin):** 배포 콘텐츠의 기준 데이터를 제공하는 원본 서버
- **캐시 적중(Cache Hit):** 요청 콘텐츠가 에지 캐시에 있어 원본 조회 없이 응답하는 상태
- **캐시 미스(Cache Miss):** 에지에 콘텐츠가 없어 원본에서 가져와야 하는 상태
- **애니캐스트(Anycast):** 같은 서비스 주소를 여러 네트워크 위치에서 알리고 라우팅 체계가 요청을 한 위치로 전달하는 방식
- **GSLB(Global Server Load Balancing):** 네트워크·서비스 상태와 정책에 따라 여러 서비스 거점으로 요청을 분산하는 방식

## Ⅰ. 개요

## Ⅱ. 콘텐츠 전달

```text
사용자 요청
    ↓ 거점 선택
가까운 CDN 에지
    ├─ 캐시 적중 → 에지에서 응답
    └─ 캐시 미스 → 원본에서 가져와 응답·캐시
```

| 역할 | 기능 |
|---|---|
| 트래픽 분산 | DNS 응답·애니캐스트 등으로 거점 선택 |
| 에지 캐시 | 저장 가능한 콘텐츠의 재사용 응답 |
| 원본 서버 | 캐시 미스·동적 요청에 기준 콘텐츠 제공 |

제언: 캐시 대상과 사용자별 응답의 분리 기준을 콘텐츠 정책에 반영

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **CDN(Content Delivery Network)** 은 분산된 캐시·복제 서버를 이용해 사용자에게 콘텐츠를 전달하는 네트워크 서비스 |
| 목적 | 사용자 응답 지연과 원본 서버 부하 감소 |

## Ⅱ. 구성과 요청 처리

```text
사용자
  ↓ 이름 해석·라우팅
CDN 에지
  ├─ 캐시 적중 → 저장 응답 전달
  └─ 캐시 미스 → 원본 조회 → 응답 전달·저장
```

| 구성 | 책임 |
|---|---|
| 요청 분산 계층 | 정책·라우팅에 따라 CDN 거점 선택 |
| 에지 노드 | 캐시·전달 정책 적용과 사용자 응답 |
| 원본 서버 | 캐시 미스와 동적 콘텐츠 요청 처리 |

## Ⅲ. 캐시 적중·미스와 원본 연계

| 요청 상태 | 처리 경로 | 핵심 판단 |
|---|---|---|
| 적중 | 사용자 ↔ 에지 | 유효기간·캐시 키에 맞는 응답 재사용 |
| 미스 | 사용자 ↔ 에지 ↔ 원본 | 원본 조회 후 응답 전달, 허용된 콘텐츠 캐시 |
| 만료·무효화 | 에지 캐시 재검증 또는 원본 갱신 | 콘텐츠 변경 시점과 전달 일관성 |

## Ⅳ. 운영 한계와 대응

| 한계 | 대응 |
|---|---|
| 캐시 키·유효기간 오류로 오래된 내용이나 사용자별 정보 노출 가능 | 민감·개인화 응답은 기본 비캐시로 두고, 키·유효기간·무효화 규칙 검토 |
| 캐시 미스 집중으로 원본에 요청이 몰릴 수 있음 | 원본 보호 한도·요청 제한·적절한 사전 배포와 캐시 계층 운영 |
| DNS 선택이나 애니캐스트 경로가 실제 사용자 체감 최적점과 다를 수 있음 | 지연·오류·거점 상태를 지역별로 측정하고 라우팅 정책 조정 |

## Ⅴ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 캐시 효율을 우선하면 개인화 응답·콘텐츠 갱신의 오류가 서비스 신뢰를 해칠 수 있음 | 콘텐츠를 정적·변경 빈도·개인정보 기준으로 나누고, 각 그룹에 캐시 키·유효기간·무효화 책임을 지정 |
