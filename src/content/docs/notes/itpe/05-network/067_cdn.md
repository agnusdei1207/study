## 지식 로드맵 내 현재 위치

네트워크 → 분산 콘텐츠 전달 및 웹 인프라 → **CDN(Content Delivery Network)**

## 30초 인출

- 본질: **CDN(Content Delivery Network)** : 대용량 웹 리소스, 미디어 스트리밍, 동적 API 응답을 지리적으로 분산 배치된 전 세계 엣지(Edge/PoP) 캐시 서버에 복제 분산하여 사용자에게 최단 경로로 전송하는 네트워크 인프라
- 메커니즘: BGP Anycast 및 지능형 GSLB를 통해 클라이언트 요청을 최근접 엣지 노드로 자동 라우팅하고, Cache Hit 시 로컬 즉시 응답, Cache Miss 시 오리진 쉴드(Origin Shield)를 통해 원본 서버 부하를 보호하며 스트리밍
- 통찰: 대규모 동시 캐시 만료 시 원본 서버로 요청이 폭증하는 캐시 스탬피드 및 동적 개인화 데이터 오캐싱 한계 극복을 위해 오리진 쉴드 계층화와 뮤텍스 기반 요청 결합(Request Collapsing) 연계 필수

<details>
<summary>핵심 용어</summary>

- **Edge PoP (Point of Presence)** : 통신사(ISP) 망 접점에 분산 배치되어 최종 사용자에게 초저지연으로 캐시 콘텐츠를 전달하는 분산 거점 서버군
- **Origin Server (원본 서버)** : 콘텐츠의 원본 마스터 데이터를 보유하고 있으며 캐시 미스 발생 시 신규 데이터를 공급하는 중앙 웹/스토리지 서버
- **BGP Anycast** : 전 세계 모든 PoP가 동일한 단일 공인 IP 주소를 BGP 라우팅으로 광고하여 인터넷 라우터가 네트워크상 가장 가까운 PoP로 패킷을 자동 전달하는 기법
- **GSLB (Global Server Load Balancing)** : DNS 질의 시 클라이언트의 지역, 엣지 서버의 헬스체크 및 트래픽 부하 상태를 종합 분석하여 최적 PoP IP를 동적으로 반환하는 기술
- **Cache Stampede (Thundering Herd)** : TTL 만료 순간 다수의 요청이 동시 유입되어 엣지가 아닌 원본 서버로 직접 트래픽이 쏠려 백엔드가 마비되는 현상
- **Origin Shield (오리진 쉴드)** : 원본 서버 바로 앞단에 배치되는 대용량 중앙 집중형 중간 캐시 계층으로 분산 엣지들의 캐시 미스를 1차 흡수하는 보호막

</details>

## 2~4교시 25점 답안

## Ⅰ. CDN의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 웹 콘텐츠(HTML, 이미지, 비디오, 스크립트 등)를 중앙 원본 서버 대신 전 세계 주요 ISP 접점에 분산 배치된 엣지 캐시 서버 풀(Edge PoP)에 사전 복제하여 사용자에게 물리적 최근접 거리에서 고속 전달하는 분산 전달 네트워크 |
| 목적 | 사용자 체감 레이턴시(RTT) 극소화, 중앙 데이터센터 원본 서버의 대역폭 및 트래픽 병목 해소, 대규모 DDoS 공격에 대한 대역폭 분산 방어 |

## Ⅱ. CDN의 특징 및 핵심 구성 요소

| 핵심 구성 요소 | 주요 역할 및 특징 | 세부 기술 명세 |
|---|---|---|
| **엣지 서버 (Edge PoP)** | 사용자와 가장 가까운 네트워크 거점에서 정적/동적 리소스 캐싱 및 전달 | Nginx/ATS 기반 고성능 메모리/NVMe 캐시, TLS 암복호화 가속 |
| **요청 라우팅 계층** | 사용자를 지연시간과 대역폭이 가장 최적화된 PoP로 유도 | **BGP Anycast** (라우팅 기반 자동 최단 경로) 또는 **GSLB DNS** |
| **오리진 쉴드 (Origin Shield)**| 수십 개 분산 PoP의 캐시 미스를 중앙에서 1차 집약하는 2차 캐시 계층 | 원본 서버에 도달하는 트래픽을 90% 이상 추가 절감하는 보호막 |
| **퍼징 및 무효화 엔진** | 원본 데이터 갱신 시 전 세계 분산 엣지의 캐시를 밀리초 단위로 강제 폐기 | Fast Purge API, 태그 기반(Surrogate-Key) 무효화 지원 |

## Ⅲ. CDN 콘텐츠 전달 아키텍처 및 캐시 적중/미스 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ CDN 분산 콘텐츠 전달 및 오리진 보호 아키텍처 ]     │
│                                                                        │
│   [전 세계 사용자 클라이언트]                                           │
│          │                                                             │
│          ▼ 1. Anycast BGP 기반 최단 경로 라우팅                        │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │                 최근접 엣지 서버 (Edge PoP)                    │   │
│   │  - 2. 캐시 조회 (Cache Key: URL + Query String)                │   │
│   └───────┬────────────────────────────────────────────────┬───────┘   │
│           │ [Cache Hit! (95%)]                             │ [Cache Miss]│
│           ▼ (초저지연 즉시 응답)                           ▼             │
│   [클라이언트로 10ms 내 응답]               ┌──────────────────────┐   │
│                                             │ 오리진 쉴드 (Shield) │   │
│                                             │ - 요청 합치기(Lock)  │   │
│                                             └──────────┬───────────┘   │
│                                                        │ [Shield Miss] │
│                                                        ▼               │
│                                             ┌──────────────────────┐   │
│                                             │ 원본 서버 (Origin)   │   │
│                                             │ (IDC / Cloud S3/WAS) │   │
│                                             └──────────────────────┘   │
└────────────────────────────────────────────────────────────────────────┘
```

| 처리 시나리오 | 동작 흐름 | 세부 처리 메커니즘 |
|---|---|---|
| **캐시 적중 (Cache Hit)** | 클라이언트 ↔ Edge PoP | 엣지 서버의 메모리/SSD에 저장된 사본을 즉시 반환; 원본 서버 네트워크 트래픽 발생 전무 |
| **캐시 미스 (Cache Miss)** | Edge ↔ Shield ↔ Origin | 엣지가 오리진 쉴드로 질의, 쉴드에도 없으면 원본 서버에서 데이터를 페치하여 캐싱 후 클라이언트에 회신 |
| **캐시 재검증 (Revalidation)**| If-Modified-Since 헤더 | TTL 만료 시 원본에 변경 여부를 확인(304 Not Modified 수신 시 TTL 연장 및 트래픽 낭비 방지) |

## Ⅳ. DNS 기반 GSLB vs BGP Anycast 라우팅 비교

| 비교 항목 | DNS 기반 GSLB (Global Server Load Balancing) | BGP Anycast 라우팅 |
|---|---|---|
| **동작 계층** | 응용 계층 (L7 DNS 프로토콜 기반) | 네트워크 계층 (L3 BGP 라우팅 프로토콜 기반) |
| **경로 결정 기준**| 로컬 DNS(LDNS)의 IP 주소 기반 지리적 추정 | 전 세계 BGP 라우터의 최단 AS 경로(AS-Path) 메트릭 |
| **장애 복구 시간** | DNS TTL 캐싱으로 인해 장애 PoP 우회에 수십 초~수분 지연 | BGP 라우팅 철회(Withdraw)를 통해 **수초 이내 즉각 자동 우회** |
| **라우팅 정밀도** | 퍼블릭 DNS(8.8.8.8 등) 사용 시 실제 사용자 위치 오판 가능 | 실제 패킷의 물리적 최단 경로를 보장하여 정확도 극상 |
| **DDoS 방어력** | 중간 수준 (DNS 질의 부하 발생) | **최고 수준 (전 세계 수백 개 PoP로 공격 트래픽 흡수 분산)** |

## Ⅴ. CDN 구축 및 운영 시 핵심 엔지니어링 한계와 방안

| 한계 | 방안 |
|---|---|
| 대규모 프로모션이나 인기 라이브 방송 시 특정 인기 콘텐츠의 TTL 만료 순간 수만 개의 요청이 동시에 원본으로 쏠려 백엔드가 다운되는 캐시 스탬피드(Cache Stampede) 발생 | 엣지 서버에서 동일 URI에 대한 최초 단 1개의 요청만 원본으로 전달하고 후속 요청은 로컬 뮤텍스 락(Mutex Lock)으로 대기시켜 원본 응답 완료 시 일괄 회신하는 요청 결합(Request Collapsing) 및 원본 앞단 오리진 쉴드(Origin Shield) 필수 구성 |
| 정적 리소스 URL 경로 뒤에 악의적 경로를 붙여 요청함으로써 사용자 세션 쿠키, 계정 정보가 포함된 민감한 동적 응답이 공개 엣지에 잘못 캐싱되는 웹 캐시 속임수(Web Cache Deception) 보안 취약성 발생 | `Set-Cookie` 헤더가 포함되거나 `Authorization` 헤더가 존재하는 응답은 엣지에서 기본 캐싱을 원천 차단하고, 캐시 키 구성 시 URL뿐만 아니라 헤더 파라미터까지 엄격히 검증하는 정규화 규칙 강제 적용 |
| 전 세계 분산 엣지 노드로 인해 긴급 보안 패치나 가격 오류 수정 시 신규 콘텐츠가 전 세계 PoP에 즉각 반영되지 않고 구 버전이 지속 노출되는 캐시 불일치(Stale Data) 발생 | 콘텐츠 URL 뒤에 해시값을 부가하는 캐시 버스팅(Cache Busting, 예: `app.v2.js`)을 파이프라인에 적용하고, Surrogate-Key 기반의 150ms 이내 초고속 전역 무효화(Instant Purge) API 파이프라인 가동 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
현대 엔터프라이즈 환경에서 CDN은 단순 정적 파일 전송을 넘어 동적 API 가속과 보안의 최전선이므로, 단일 CDN 사업자에 종속되지 않고 네트워크 성능과 비용을 실시간 비교하여 최적 CDN으로 분기하는 멀티 CDN(Multi-CDN) 아키텍처를 수립하고, 클라우드플레어 Workers나 AWS CloudFront Functions와 같은 엣지 컴퓨팅을 연계하여 인증 및 A/B 테스트를 엣지에서 완결 권장

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│               [ 멀티 CDN 및 엣지 컴퓨팅 기반 지능형 분산 아키텍처 ]    │
│                                                                        │
│                       [ 전 세계 사용자 트래픽 ]                        │
│                                │                                       │
│                                ▼ 스마트 DNS 분기 (실시간 RTT 측정)     │
│          ┌─────────────────────┴─────────────────────┐                 │
│          ▼                                           ▼                 │
│   ┌───────────────┐                           ┌───────────────┐        │
│   │ CDN A (엣지)  │                           │ CDN B (엣지)  │        │
│   │ - 엣지 서버리스│ (JWT 인증, 헤더 변조)    │ - 엣지 WAF    │        │
│   │ - 정적/동적   │                           │ - 미디어 스트림│       │
│   └──────┬────────┘                           └───────┬───────┘        │
│          │                                            │                │
│          └─────────────────────┬──────────────────────┘                │
│                                │ Origin Shield 캐시 집약               │
│                                ▼                                       │
│                 ┌─────────────────────────────┐                        │
│                 │   오리진 쉴드 (중앙 캐시)   │                        │
│                 └──────────────┬──────────────┘                        │
│                                │ 무중단 Keep-Alive 세션                │
│                                ▼                                       │
│                 ┌─────────────────────────────┐                        │
│                 │   엔터프라이즈 원본 서버    │                        │

```

### 3. 기술 유형 및 비교 평가
| 구분 | 전통적 정적 CDN | 동적 가속 CDN (DSA) | 엣지 컴퓨팅 CDN (Serverless) |
|---|---|---|---|
| **캐싱 대상** | 이미지, JS, CSS, 비디오 파일 | 동적 HTML, REST API 응답 | 코드 자체를 엣지에서 직접 실행 |
| **가속 원리** | 엣지 스토리지 캐싱 후 전달 | 경로 최적화, TCP 윈도우 튜닝 | 사용자 최근접 PoP에서 로직 완결 |
| **원본 부하 절감** | 정적 트래픽 90% 이상 절감 | 연결 재사용으로 TCP 핸드셰이크 절감 | 데이터베이스 질의 외 백엔드 도달 0% |
| **주 활용 분야** | 대용량 파일 다운로드, OTT 스트리밍 | 금융 거래, 전자상거래 쇼핑몰 API | 전역 인증(Auth), 이미지 실시간 리사이징 |
