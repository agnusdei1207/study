## 연관 키워드

- CDN(Content Delivery Network), 오리진(Origin), 에지(Edge), PoP(Point of Presence), GSLB(Global Server Load Balancing)
- GeoDNS, Anycast BGP, 캐시 히트(Cache Hit), 캐시 미스(Cache Miss), TTL(Time to Live)
- 서로게이트 키(Surrogate Key), Stale-While-Revalidate, 요청 병합(Request Collapsing), 캐시 스탬피드(Cache Stampede)
- 동적 콘텐츠 가속(DSA, Dynamic Site Acceleration), 에지 컴퓨팅, WAAP, 멀티 CDN

## Ⅰ. CDN의 개요

- 핵심 요약 : 사용자와 가까운 에지 서버에서 콘텐츠를 응답하여 지연과 오리진 부하를 함께 줄이는 분산 전송 네트워크.
- 개념 : 전 세계 주요 **ISP** (Internet Service Provider, 인터넷 서비스 제공자) 네트워크의 가장자리에 캐시 서버를 분산 배치하여, 사용자 요청을 가장 가까운 에지에서 처리하는 **콘텐츠 전송 네트워크** (CDN, Content Delivery Network).
- 배경 및 필요성 : 원거리의 단일 **오리진** (Origin, 원본 콘텐츠 서버)에 전 세계 트래픽이 몰리면 왕복 지연 (RTT, Round-Trip Time)이 커지고 회선 대역이 포화되며, 서버 장애와 체감 품질 저하가 함께 발생한다. 원본 서버의 용량을 늘리는 방식은 비용이 계속 늘어나므로, 응답 위치를 사용자 쪽으로 옮기는 방식이 필요해졌다.
- 주요 목적 : 최종 사용자의 응답 지연 최소화, 오리진 서버와 회선 비용 절감, 대규모 **DDoS** (Distributed Denial of Service, 분산 서비스 거부) 공격 트래픽의 에지 흡수.

## Ⅱ. CDN의 특징 및 장점

- 핵심 요약 : 에지 캐싱과 지능형 요청 라우팅이 결합되어 응답 지연과 오리진 부하를 동시에 낮추는 구조.

1. 에지 캐싱 : 자주 쓰이는 콘텐츠를 사용자 근처에 저장 → 왕복 지연 감소와 오리진 요청 감소.
2. 요청 라우팅 : **GSLB** (Global Server Load Balancing, 전역 서버 부하 분산) 방식으로 최적 에지를 선택 → 사용자별 경로 단축.
3. 공격 흡수 : 트래픽을 여러 에지로 분산 → 단일 지점에 집중되는 공격 부하를 줄임.
4. 동적 콘텐츠 가속 : **DSA** (Dynamic Site Acceleration, 캐시하기 어려운 동적 요청의 전송을 빠르게 하는 기법) → 에지와 오리진 사이의 연결 재사용과 경로 최적화로 API 응답 시간 단축.

## Ⅲ. CDN의 구조 (흐름)

- 핵심 요약 : DNS 기반 라우팅으로 에지를 고른 뒤, 에지의 캐시 적중 여부에 따라 응답 경로가 갈리는 두 단계 구조.
- **GeoDNS** : 사용자의 로컬 DNS 주소를 기준으로 지리적으로 가까운 에지 주소를 응답한다.
- **Anycast BGP** (Border Gateway Protocol 기반 애니캐스트) : 여러 에지가 같은 IP 주소를 광고하고, 인터넷 라우팅이 가장 가까운 에지로 트래픽을 보낸다.

```text
[ 요청 라우팅 흐름 ]

1. 사용자가 도메인을 DNS로 질의
   ↓
2. GSLB가 최적 에지 IP를 반환
   ↓
3. 사용자가 해당 에지에 HTTP 요청
```

```text
[ 캐시 처리 분기 ]

에지 서버 캐시 확인
   ↓ 유효한 캐시 존재
캐시 히트 : 저장된 콘텐츠 즉시 응답
   ↓ 없거나 만료
캐시 미스 : 오리진에서 가져와 저장 후 응답
```

- 캐시 판정 : 캐시 히트는 TTL 안에 유효한 콘텐츠가 있는 경우이고, 캐시 미스는 콘텐츠가 없거나 만료된 경우다.

## Ⅳ. 캐시 무효화 전략의 비교

- 핵심 요약 : 무효화 방식은 반영 속도, 오리진 부하, 적합 대상이 서로 달라 콘텐츠 성격에 따라 조합해 쓴다.

| 비교 축 | TTL 기반 만료 | 즉시 무효화 (Purge) | 서로게이트 키 | Stale-While-Revalidate |
| --- | --- | --- | --- | --- |
| 동작 원리 | max-age 시간이 지나면 만료 | API 호출로 특정 URL 캐시를 강제 삭제 | 관련 리소스에 태그를 붙여 묶음 무효화 | 만료된 구버전을 먼저 주고 백그라운드에서 갱신 |
| 반영 속도 | TTL 경과 후에만 갱신 | 수 초에서 수 분 내 전 세계 반영 | 수 초 내 관련 에지 일괄 삭제 | 사용자는 대기 없이 응답 |
| 오리진 부하 | 만료 주기마다 규칙적 인출 | 대량 Purge 시 오리진 요청 급증 | 변경된 엔티티 관련 페이지만 정밀 갱신 | 갱신 요청이 분산되어 스파이크 완화 |
| 적합 대상 | 정적 이미지, JS(JavaScript), CSS(Cascading Style Sheets) | 긴급 오류 수정, 보안 패치 | 상품 상세, 카테고리 페이지 | 뉴스 기사, 피드, 가격 정보 |

- **에지 컴퓨팅** (Edge Computing, 에지 서버에서 코드를 실행하는 방식) : 단순 캐싱을 넘어 Cloudflare Workers, Lambda@Edge처럼 에지에서 인증, A/B 테스트, 동적 HTML 조립을 처리한다.

```text
[ 요청 병합 (Request Collapsing) ]

만료 직후 동시 요청 다수
   ↓ 에지 서버
오리진 요청은 1건만 전송
   ↓
응답을 대기 중인 나머지 요청에 공유
```

## Ⅴ. CDN 운영의 한계와 방안

- 핵심 요약 : 만료 시점의 요청 집중과 라우팅 변동에 따른 세션 단절이 주요 한계이며, 요청 병합과 연결 복구로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 캐시 스탬피드 (Cache Stampede) | 인기 콘텐츠 만료 시 동시 요청이 오리진에 몰려 데이터베이스 과부하 | 요청 병합(Request Collapsing)과 Stale-While-Revalidate 패턴 적용 | 오리진 요청 수, 만료 직후 응답 지연 |
| 애니캐스트 경로 변동에 따른 TCP 세션 단절 | 인터넷 경로가 바뀌면 진행 중인 전송이 다른 에지로 넘어가 연결 재설정 발생 | 클라이언트 재연결 로직 구현, 연결 이동을 지원하는 QUIC 활용 | 세션 재설정 비율, 전송 중단 시간 |

## Ⅵ. CDN 적용 및 발전을 위한 기술사적 제언

- 핵심 요약 : 멀티 CDN과 에지 보안, 초저지연 방송으로 CDN의 가용성과 품질을 높이는 방향.

1. 특정 CDN 사업자의 장애에 대비하여 멀티 CDN(Multi-CDN) 구조를 두고, 실사용자 성능 측정 (RUM, Real User Monitoring) 결과에 따라 DNS 트래픽을 실시간으로 전환해야 한다.
2. 보안 체계는 에지 위에서 함께 운영하는 방향으로 옮겨 가는 것이 바람직하다. WAF(Web Application Firewall), API 이상 탐지, DDoS 방어, 봇 관리를 한 서비스로 묶는 WAAP(Web Application and API Protection) 체계를 도입하면 보안과 전송을 같은 지점에서 관리할 수 있다.
3. 실시간 방송은 청크 단위 전송과 에지 기반 시그널링을 결합하여 지연을 낮춰야 한다.

## Ⅶ. 결론

- 핵심 요약 : CDN은 콘텐츠를 사용자 가까이 두어 지연과 오리진 부하를 함께 줄이는 분산 전송 기반.
- 시사점 : 캐시 정책과 무효화 설계가 응답 품질을 좌우하므로, 콘텐츠 성격별 무효화 전략을 분리해 설계하는 것이 운영의 핵심이다.
