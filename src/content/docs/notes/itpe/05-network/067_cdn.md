## 연관 키워드

- CDN(Content Delivery Network), 오리진(Origin), 에지(Edge), GSLB(Global Server Load Balancing), Anycast
- 캐시 히트(Cache Hit), 캐시 미스(Cache Miss), TTL(Time to Live), 즉시 무효화(Purge), 서로게이트 키(Surrogate Key)
- Stale-While-Revalidate, 캐시 스탬피드(Cache Stampede), 요청 병합(Request Collapsing), 에지 컴퓨팅(Edge Computing)

## Ⅰ. CDN의 개요

- 핵심 요약 : 사용자 인근의 에지 서버에서 콘텐츠를 응답해 지연과 원본 서버 부하를 함께 낮추는 분산 전송 체계.
- 개념 : 인터넷 가장자리에 캐시 서버를 분산 배치하고 사용자 요청을 가장 가까운 위치에서 처리하게 하는 **콘텐츠 전송 네트워크** (CDN, Content Delivery Network).
- 배경 및 필요성 : 원본 콘텐츠 서버인 **오리진** (Origin)에 전 세계 요청이 집중하면 왕복 지연(RTT, Round-Trip Time) 증가, 회선 포화, 단일 장애점 위험이 함께 발생. 서버 증설만으로는 거리에서 오는 지연을 해소할 수 없어 응답 위치를 사용자 쪽으로 옮기는 구조가 필요.
- 주요 목적 : 응답 지연 최소화, 오리진과 회선 비용 절감, 급증 트래픽과 공격 트래픽의 분산 흡수.

## Ⅱ. CDN의 특징 및 장점

- 핵심 요약 : 에지 캐싱과 지능형 요청 라우팅, 연결 최적화가 지연 감소와 오리진 보호로 이어지는 구조.

1. 에지 캐싱 : 수요가 높은 콘텐츠를 사용자 인근 에지에 복제 → 왕복 거리 단축과 오리진 요청 감소.
2. 요청 라우팅 : **GSLB** (Global Server Load Balancing, 전역 서버 부하 분산)와 **Anycast** (동일 주소를 여러 지점이 광고해 라우팅상 가장 가까운 지점으로 유입되는 방식)로 최적 에지 선택 → 사용자별 최단 경로 접속.
3. 연결 최적화 : 에지-오리진 구간의 연결 재사용과 프로토콜 튜닝으로 캐시 불가 요청도 가속 → 동적 콘텐츠 응답 시간 단축.
4. 공격 흡수 : 트래픽을 전 세계 에지로 분산 배치 → 단일 지점 공격 부하 완화와 가용성 확보.

## Ⅲ. CDN의 구조 (흐름)

- 핵심 요약 : DNS 기반 라우팅으로 에지를 결정한 뒤 캐시 적중 여부에 따라 응답 경로가 갈리는 2단계 구조.
- 라우팅 기반 : DNS(Domain Name System) 질의 응답 단계에서 에지 주소가 선택됨.
- **에지** (Edge) : 사용자 근거리 접속 거점(PoP, Point of Presence) 단위의 캐시 서버군.
- **캐시 히트** (Cache Hit) : 에지에 유효한 저장본이 있어 즉시 응답하는 경우.
- **캐시 미스** (Cache Miss) : 저장본이 없거나 만료되어 오리진에서 인출하는 경우.
- **TTL** (Time to Live) : 저장본의 유효 기간을 지정하는 캐시 지시자.

```text
[ 요청 라우팅 흐름 ]

사용자 : 도메인 DNS 질의
   ↓
GSLB : 지리·부하 기준 에지 선택
   ↓
사용자 : 선택된 에지로 요청 전송
   ↓
에지 : 콘텐츠 응답
```

```text
[ 캐시 판정 분기 ]

에지 캐시 존재·유효 확인
   ↓ 유효 저장본 존재
캐시 히트 : 저장본 즉시 응답
   ↓ 없음 또는 TTL 만료
캐시 미스 : 오리진 인출 후 저장·응답
```

## Ⅳ. 캐시 무효화 전략의 비교

- 핵심 요약 : 무효화 방식에 따라 반영 속도와 오리진 부하가 달라지므로 콘텐츠 성격별 조합 적용 필요.
- 전략 유형 :
  1. TTL 기반 만료 : 유효 기간 경과 후 자연 갱신.
  2. **즉시 무효화** (Purge) : 지정 URL의 저장본을 강제 삭제하는 API(Application Programming Interface) 호출 방식.
  3. **서로게이트 키** (Surrogate Key, 관련 리소스에 붙여 묶음 삭제를 가능하게 하는 태그 식별자) : 태그 단위 일괄 무효화.
  4. **Stale-While-Revalidate** : 만료 본문을 우선 응답하고 백그라운드로 갱신하는 방식.

| 비교 축 | TTL 기반 만료 | 즉시 무효화 | 서로게이트 키 | Stale-While-Revalidate |
| --- | --- | --- | --- | --- |
| 동작 원리 | TTL 경과 후 재인출 | 지정 URL 강제 삭제 | 태그 단위 묶음 삭제 | 구버전 제공 후 갱신 |
| 반영 속도 | TTL 경과 시점 | 호출 즉시 진행 | 호출 즉시 진행 | 사용자 응답과 무관 |
| 오리진 부하 | 만료 주기마다 인출 | 대량 호출 시 요청 급증 | 관련 페이지만 갱신 | 갱신 요청 분산 |
| 적합 콘텐츠 | 정적 이미지·스크립트 | 긴급 수정·보안 패치 | 상품 상세·목록 | 뉴스·피드·가격 정보 |

- 선택 기준 :
  1. 변경이 드문 정적 자원은 TTL 상향으로 인출 횟수 축소.
  2. 배포 즉시 반영이 필요한 페이지는 즉시 무효화를 보조 수단으로 운용.
  3. 신선도와 응답 속도를 함께 요구하는 피드성 콘텐츠는 Stale-While-Revalidate 적용.

## Ⅴ. CDN 운영의 한계와 방안

- 핵심 요약 : 만료 시점의 요청 집중과 경로 변동에 따른 세션 단절이 주요 한계이며, 요청 통합과 연결 복구로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **캐시 스탬피드** (Cache Stampede, 만료 직후 동시 요청이 오리진에 집중되는 현상) | 인기 콘텐츠 만료와 트래픽 급증의 겹침 → 오리진·데이터베이스 과부하 | **요청 병합** (Request Collapsing, 동일 콘텐츠의 다수 요청을 1건의 오리진 인출로 통합하는 기법)과 만료 여유 지정 적용 | 오리진 요청 수, 만료 직후 응답 지연 |
| 애니캐스트 경로 변동에 따른 세션 단절 | 라우팅 변경 시 진행 중 연결이 다른 에지로 이동 → 재전송·지연 | 애플리케이션 재연결 로직 보강, 연결 이동에 유리한 QUIC(RFC 9000) 검토 | 세션 재설정 비율, 전송 중단 시간 |

## Ⅵ. CDN에 대한 기술사적 제언

- 핵심 요약 : 멀티 CDN 운영, 에지 통합 보안, 에지 컴퓨팅 확장으로 전송과 보안을 한 지점에서 운영하는 방향.

1. 서비스 운영 조직은 복수 CDN 사업자를 병용하는 멀티 CDN 구조로 전환하고, 실사용자 모니터링(RUM, Real User Monitoring) 지표에 따라 트래픽 비중을 조정해 특정 사업자 장애의 영향을 제한해야 한다.
2. 보안 운영 조직은 WAF(Web Application Firewall), API 보호, DDoS(Distributed Denial of Service) 방어를 에지에서 통합 제공하는 WAAP(Web Application and API Protection) 체계로 전환해 전송과 보안의 책임 지점을 일치시켜야 한다.
3. 플랫폼 개발 조직은 인증·개인화 같은 경량 로직을 **에지 컴퓨팅** (Edge Computing, 에지 서버에서 코드를 실행하는 방식)으로 확장해 오리진 왕복 없이 응답을 완성하는 구조를 검토해야 한다.

## Ⅶ. 결론

- 핵심 요약 : CDN은 콘텐츠를 사용자 가까이 이동시켜 지연·부하·가용성 문제를 동시에 다루는 전송 기반.
- 캐시 정책과 무효화 전략의 설계 품질이 체감 성능을 좌우하므로 콘텐츠 성격별 전략 분리가 운영의 핵심.
