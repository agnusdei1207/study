## 30초 인출

- 본질: 원거리 단일 오리진 서버에 전 세계 트래픽이 몰릴 때 발생하는 네트워크 왕복 지연(RTT)과 서버 다운 위험
- 메커니즘: 사용자 인근의 전 세계 거점(POP)에 대용량 정적 콘텐츠를 사전 복제하고 GSLB로 최단 에지로 라우팅

## 핵심 용어

- GSLB(Global Server Load Balancing): 클라이언트의 지리적 위치(클라이언트 IP 서브넷)와 각 대륙 에지 서버의 헬스 상태, 네트워크 혼잡도를 종합 평가하여 가장 가깝고 빠른 에지 서버의 IP를 DNS 응답으로 돌려주는 지능형 라우팅 기술
- 애니캐스트(Anycast): 전 세계 수백 개의 서로 다른 에지 서버에 동일한 단일 IP 주소를 부여하고, 인터넷 BGP 라우팅 프로토콜이 패킷을 물리적으로 가장 가까운 노드로 자동 안내하도록 설계된 전송 기술
- 캐시 스탬피드(Cache Stampede): 인기 있는 콘텐츠의 캐시 수명(TTL)이 만료되는 순간, 수만 개의 동시 요청이 에지를 뚫고 오리진 서버로 일시에 쏟아져 원본 서버가 다운되는 현상

## 1교시 10점 답안

### Ⅰ. 정의·목적

- 정의: CDN은/는 사용자 인근의 전 세계 거점(POP)에 대용량 정적 콘텐츠를 사전 복제하고 GSLB로 최단 에지로 라우팅 방식이다.
- 목적: 웹 응답 속도 단축 및 서버 부하 90% 이상 절감에 기여한다.

### Ⅱ. 핵심 구조와 작동

```text
[ CDN 아키텍처 및 트래픽 요청 처리 흐름 ]

[ 글로벌 사용자 ] ── 1. DNS 요청 ──> [ GSLB / Anycast DNS ]
                                      (사용자 위치 기반 최인접 에지 IP 응답)
       │
       v 2. HTTP 요청
+--------------------------------------------------------------+
| 최인접 에지 POP (Edge Server)                                  |
| - [ 캐시 적중 (Cache Hit) ]  ───> 즉시 사용자에게 초고속 응답    |
| - [ 캐시 실패 (Cache Miss) ] ──┐                             |
+--------------------------------┼-----------------------------+
                                 │ 3. 캐시 부하 완화
                                 v
                 +-------------------------------+
                 | 오리진 실드 (Origin Shield)    |
                 | (중간 집중 캐싱 계층)          |
                 +---------------+---------------+
                                 │ 4. 최종 오리진 호출 (최소화)
                                 v
                 +-------------------------------+
                 | 원본 서버 (Origin Server)      |
                 +-------------------------------+
```

```text
                                 v
                 +-------------------------------+

                 +-------------------------------+
```

### Ⅱ. 핵심 특성

- 단순 파일 복사기가 아닌 전송 계층(L4/L7) 프로토콜 가속기: 정적 이미지 캐싱뿐만 아니라, 클라이언트와 에지 간의 TCP 3-Way Handshake 및 TLS 1.3 핸드셰이크를 지리적으로 가까운 에지에서 즉시 종단하고, 에지와 오리진 간에는 연결 풀링(Connection Pooling)과 BBR 혼잡 제어로 통신 지연을 극복
- 캐시 무효화(Purge) 아키텍처가 CDN 운영의 최대 난제: "컴퓨터 과학에서 가장 어려운 두 가지는 캐시 무효화와 이름 짓기"라는 말처럼, 파일 단위 전면 삭제(Hard Purge)는 오리진 서버를 폭파시키므로 특정 태그(Surrogate-Key) 단위의 선별적 소프트 무효화 체계가 필수
- 에지 컴퓨팅(Serverless Edge)으로의 진화: 단순 스토리지 캐시에서 벗어나 Cloudflare Workers, AWS Lambda@Edge처럼 가벼운 V8 자바스크립트 코드를 에지에서 직접 실행하여 A/B 테스팅, 개인화 헤더 변조, 봇 탐지를 0ms에 가깝게 처리

### Ⅲ. 관련 개념과 구분

- CDN vs 로컬 캐시: 로컬 캐시(브라우저 캐시, Redis)는 단일 단말이나 내부 시스템 메모리에 데이터를 보관 / CDN은 글로벌 지리적 분산 네트워크를 통해 전 세계 다수 사용자에게 대규모 데이터를 분산 공급

### Ⅳ. 적용 문제와 대응

- 적용 상황: 글로벌 신제품 런칭 시 이벤트 페이지 트래픽 폭증
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 캐시 만료 시 수십만 건의 동시 오리진 요청 발생(캐시 스탬피드) | TTL 만료 시점의 비동기 갱신 락(Lock) 부재 | 오리진 실드(Origin Shield) 도입 및 `stale-while-revalidate` HTTP 헤더 적용 | 백그라운드에서 1건만 오리진 갱신하고 기존 캐시 즉시 반환 |
| 상품 가격 긴급 수정 시 일부 국가에 구 가격 노출 | 글로벌 에지 서버로의 캐시 무효화 전파 지연 | 서러게이트 키(Surrogate-Key) 기반 태그 무효화 API 연동 | 150ms 이내에 전 세계 에지의 관련 상품 캐시만 정밀 타겟 삭제 |
