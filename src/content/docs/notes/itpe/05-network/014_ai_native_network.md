## 연관 키워드

- AI-native Network, AI for Network, AIOps, 폐쇄 루프, 규칙 기반 제어
- 신경망 에어 인터페이스, INT, 디지털 트윈 네트워크, 제로 터치 운영
- XAI, Safe RL, 지식 증류, 연합 학습, DPU, 텔레메트리
- YANG, OpenConfig, 적대적 섭동, 사이버 레질리언스

## Ⅰ. AI-native Network의 개요

- 핵심 요약 : 프로토콜 설계부터 운영까지 AI를 내장해 스스로 관측하고 제어하는 차세대 네트워크 구조.
- 개념 : AI 솔루션을 기존 망에 덧붙이던 'AI for Network' 방식을 넘어, 프로토콜 설계, 물리 계층 신호 처리, 라우팅, 인프라 운영 전반에 AI(Artificial Intelligence)와 머신러닝(ML, Machine Learning)을 내재화한 **AI 네이티브 네트워크**(AI-native Network).
- 배경 및 필요성 : 5G-Advanced와 6G로 진화하면서 무선 빔과 네트워크 슬라이스가 매우 많아지고 토폴로지가 수시로 바뀌어, 사람이 수동으로 튜닝하고 **규칙 기반**(Rule-based) 제어로 운영하기에는 복잡도가 한계를 넘음.
- 핵심 목적 : 제어 평면의 **무인 운영**(Zero-Touch Operations) 실현, 무선 신호 처리의 적응성 향상, 이상 징후의 선제 감지와 장애 자가 치유(Self-Healing).

## Ⅱ. AI-native Network의 특징 및 장점

- 핵심 요약 : 세 평면이 하나의 학습 파이프라인으로 연결되어, 관측과 제어가 사람 개입 없이 짧은 주기로 반복되는 구조.

1. **신경망 에어 인터페이스**(Neural Air Interface) : 채널 추정, 변복조, 피드백 같은 L1 신호 처리를 종단 간 심층 신경망으로 대체 → 복잡한 채널 환경에서도 링크 품질 개선 가능.
2. **폐쇄 루프 자율 제어**(Closed-Loop Control) : 관측, 분석, 의사결정, 실행의 루프를 사람 개입 없이 짧은 주기로 반복 → 장애와 혼잡에 즉시 대응.
3. **인밴드 텔레메트리**(INT, In-band Network Telemetry) : 데이터 패킷에 큐 지연과 패킷 드롭 정보를 실어 AI 학습 엔진에 고속 피드백 → 학습 데이터의 실시간성 확보.
4. **디지털 트윈 네트워크**(Digital Twin Network) : 물리 망과 동기화된 가상 환경에서 제어 정책을 사전에 검증 → 실제 망 적용 시 위험 감소.

## Ⅲ. AI-native Network의 구조 (흐름)

- 핵심 요약 : 운영 자동화(AIOps, AI for IT Operations), 제어, 데이터 평면이 위에서 아래로 정책을 내려보내고 아래에서 위로 상태를 올려보내는 계층 구조, 그리고 각 평면 안에서 돌아가는 폐쇄 루프.

```text
[ AI-native Network 3계층 구조 ]

관리 평면 (AIOps, 인텐트 제어)
   ↓  폐쇄 루프 오케스트레이션
제어 평면 (강화학습 에이전트)
   ↓  초저지연 정책 주입
데이터 평면 (신경망 수신기, INT)
```

```text
[ 폐쇄 루프 자율 제어 ]

상태 관측 (Observe)
   ↓
분석 (Orient)
   ↓
의사결정 (Decide)
   ↓
정책 실행 (Act)
   ↓  결과가 다시 관측으로
상태 관측 (Observe)
```

## Ⅳ. AI-native Network와 기존 망의 비교

- 핵심 요약 : 규칙 기반 망에서 AI 부가형 망을 거쳐 AI 네이티브 망으로 옮겨 가며, AI의 위치가 분석 도구에서 제어 구조로 바뀜.
- 비교 대상 : 전통 규칙 기반 망, AI를 외장 기능으로 붙인 AI 부가형 망, AI 네이티브 망. 표의 인터페이스 항목은 CLI(Command-Line Interface), SNMP(Simple Network Management Protocol), REST(Representational State Transfer) API(Application Programming Interface) 등을 가리킴.

| 비교 축 | 전통 규칙 기반 망 | AI 부가형 망 | AI 네이티브 망 |
| --- | --- | --- | --- |
| AI의 위상 | AI 없음, 사람이 수동 제어 | 외장 부가 기능 | 프로토콜과 하드웨어에 내재화 |
| 제어 주기 | 사람 개입이 필요한 느린 주기 | 비실시간 자동 제어 | 밀리초 이하의 실시간 제어 |
| L1 신호 처리 | 고정된 수학적 채널 모델 | 고정 알고리즘 유지 | 종단 간 신경망 수신기 |
| 운영 방식 | 장애 발생 후 사후 조치 | 임계치 알람 기반 대응 | 예측 기반 선제 제어 |
| 인터페이스 | CLI, SNMP, 벤더 전용 프로토콜 | REST API, OpenFlow | 표준 텔레메트리와 AI 에이전트 인터페이스 |

- 선택 기준 : 망의 규모와 제어 요구 주기에 따라 단계적으로 옮겨 가되, 실시간 제어가 필요한 구간부터 AI 네이티브 요소를 우선 도입하는 판단이 현실적임.

## Ⅴ. AI-native Network의 한계와 방안

- 핵심 요약 : 블랙박스 모델의 설명 불가능성, 추론 지연, 텔레메트리 부하를 설명 가능성 기법, 경량화와 가속, 연합 학습으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 블랙박스 모델의 설명 불가능성 (XAI, Explainable AI 부재) | 심층 강화학습이 비정상 라우팅을 결정해도 원인을 설명하지 못해 백본 장애로 이어질 위험 | 설명 가능한 AI 기법을 결합하고, 안전 강화학습(Safe RL, Safe Reinforcement Learning) 기반의 제약 가드레일 설정 | 정책 변경 사유 기록률, 제약 위반 횟수 |
| 실시간 제어와 AI 추론 지연의 괴리 | 복잡한 모델의 추론 지연이 무선 슬롯 주기를 넘어 스케줄링이 실패 | 지식 증류(Knowledge Distillation)로 경량 모델을 만들고, DPU(Data Processing Unit)·스마트 NIC(SmartNIC) 가속기를 탑재 | 추론 지연 분포, 슬롯 내 처리 완료율 |
| 텔레메트리 수집의 대역폭 잠식 | 전체 노드의 고빈도 상태 수집이 서비스 데이터 대역폭을 잠식 | 에지에서 연합 학습(Federated Learning)을 수행해 원시 데이터 전송을 줄이고, 상태가 바뀔 때만 보내는 이벤트 기반 텔레메트리 적용 | 텔레메트리 트래픽 비율, 이벤트 발생 빈도 |

## Ⅵ. AI-native Network에 대한 기술사적 제언

- 핵심 요약 : 디지털 트윈 검증, 데이터 표준화, 사이버 방어를 운영 체계의 기본 단계로 편입해야 자율 망이 신뢰를 얻을 수 있음.
- 통신사와 엔터프라이즈 네트워크 조직은 AI 모델을 실제 망에 배포하기 전 디지털 트윈 환경에서 이상 동작을 충분히 검증하는 절차를 운영 체계의 필수 단계로 편입하는 것이 바람직하다.
- 멀티벤더 환경을 운영하는 조직은 YANG(Yet Another Next Generation) 데이터 모델과 OpenConfig 같은 표준으로 텔레메트리 형식을 통일하는 정책을 세워, AI 학습 데이터의 품질과 이식성을 보장해야 한다.
- 자율 망을 설계하는 조직은 적대적 섭동(Adversarial Perturbation) 공격에 대비해 AI 모델의 입력 검증과 이상 행위 모니터링을 포함한 사이버 레질리언스 체계를 운영 전반에 적용하는 것이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : AI 네이티브 네트워크는 AI를 분석 도구에서 망의 제어 구조로 바꾸는 설계 전환임.
- 시사점 : 자율화의 효익은 설명 가능성과 검증 체계가 뒷받침될 때 현실화되므로, 기술 도입과 안전 체계를 함께 설계하는 것이 핵심 과제가 됨.
