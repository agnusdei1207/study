## 연관 키워드

- IntServ(Integrated Services), RSVP(Resource Reservation Protocol), 마이크로 플로우(Micro-flow), PATH·RESV 메시지
- 소프트 상태(Soft-State), 수락 제어(Admission Control), 보장형 서비스(Guaranteed Service), 통제 부하 서비스(Controlled-Load Service)

## Ⅰ. IntServ의 개요

- 핵심 요약 : 응용이 흐름 단위로 대역과 지연 상한을 요청하면 경로상 모든 라우터가 자원을 예약해 절대 품질을 보장하는 모델.
- 개념 : 지연에 민감한 실시간 응용의 **마이크로 플로우**(Micro-flow, 개별 송수신 쌍의 트래픽 흐름)마다 **RSVP**(Resource Reservation Protocol)로 경로상 전 라우터에 대역폭과 버퍼를 명시 예약하는 **통합 서비스** (IntServ, Integrated Services) 모델. IETF(Internet Engineering Task Force)의 RFC 1633에서 아키텍처 정의.
- 배경 및 필요성 : 최선형 전송 구조에서는 혼잡 시 무차별 폐기와 지연 변동이 발생하여 전용 회선 수준의 결정론적 품질을 패킷망에서 재현할 수 없는 문제.
- 주요 목적 : 흐름별 대역 보장과 지연 상한 제공, 과잉 수용 방지, 예약 자원의 회수와 재사용.

## Ⅱ. IntServ의 특징 및 장점

- 핵심 요약 : 명시 예약, 수락 제어, 흐름 스케줄링, 소프트 상태의 조합이 결정론적 품질과 자원 회수의 효율로 연결.

1. 명시적 예약 : 흐름 특성을 전달하는 **PATH 메시지**와 예약을 요청하는 **RESV 메시지**의 교환 → 데이터 전송 전에 경로 전체의 자원 확보.
2. 보장형 서비스 : **보장형 서비스**(Guaranteed Service, 지연 상한과 대역을 수학적으로 보장하는 등급) → 회화형 음성·제어 신호의 엄격한 품질 확보.
3. 통제 부하 서비스 : **통제 부하 서비스**(Controlled-Load Service, 한산한 망과 유사한 품질을 제공하는 등급) → 과부하 구간에서도 기본 품질 유지.
4. 수락 제어 : 잔여 자원이 부족하면 신규 예약 거절 → 기존 흐름의 품질 붕괴 방지.
5. 소프트 상태 : **소프트 상태**(Soft-State, 갱신이 없으면 자동 해제되는 상태 유지 방식) → 세션 종료 후 자원의 신속 회수.

## Ⅲ. IntServ의 구조 (흐름)

- 핵심 요약 : RSVP 양방향 시그널링으로 경로 상태를 구성하고, 라우터 내부에서는 분류기와 스케줄러가 예약을 집행하는 구조.

```text
[ RSVP 예약 절차 ]

송신자 : PATH 메시지 발송 (흐름 특성 전달)
    ↓ 경로상 라우터가 경로 상태 생성
수신자 : RESV 메시지 회송 (예약 요청)
    ↑ 역방향 경로를 따라 이동
각 라우터 : 수락 제어 후 자원 예약
    ↓
보장된 데이터 전송 개시
```

```text
[ 라우터 내부 집행 구조 ]

패킷 인입
    ↓
패킷 분류기 (흐름 식별)
    ↓
패킷 스케줄러 (흐름별 대역 보장)
    ↓
출력 링크
    ※ 수락 제어·예약 상태 관리가 병행
```

- 스케줄러는 가중 공정 큐잉(WFQ, Weighted Fair Queuing) 계열의 알고리즘으로 흐름별 예약 대역을 집행하는 구성이 대표적.

## Ⅳ. IntServ와 DiffServ의 비교

- 핵심 요약 : 절대 보장·상태 보유의 IntServ와 상대 보장·상태 비보유의 DiffServ(Differentiated Services)가 확장성과 보장 수준에서 대비되는 관계.
- 선택 기준 : 소규모 폐쇄망의 엄격한 지연 상한이면 IntServ, 대규모 공용 백본의 등급 차등이면 DiffServ.

| 비교 축 | IntServ (통합 서비스) | DiffServ (차등 서비스) |
| --- | --- | --- |
| 제어 단위 | 개별 마이크로 플로우 | 클래스 단위 집약 |
| 보장 형태 | 결정론적 절대 보장 | 통계적 상대 보장 |
| 라우터 상태 | 경로 전체가 흐름 상태 보유 | 코어는 상태 비보유 |
| 시그널링 부담 | RSVP 주기 갱신 부하 | 헤더 표시만 수행 |
| 핵심 한계 | 백본 확장성 붕괴 | 엄격한 지연 상한 미보장 |
| 적합 환경 | 소규모 인트라넷·방송망 | 대규모 백본·기업 WAN |

## Ⅴ. IntServ의 한계와 방안

- 핵심 요약 : 상태 폭증, 갱신 부하, 비대칭 경로의 세 한계를 역할 분리, 갱신 축소, 명시 경로로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 코어 상태 폭증 | 흐름 수에 비례하는 버퍼·타이머 유지 → 백본 과부하 | 흐름 예약을 접속 경계로 한정하는 계층화 설계 | 라우터당 흐름 상태 수 |
| 갱신 메시지 부하 | 예약 세션마다 주기적 PATH·RESV 교환 → 연산·제어 대역 낭비 | 갱신 축소 확장(RFC 2961)의 메시지 묶음·요약 갱신 적용 | 제어 메시지 비율 |
| 비대칭 경로 | 송·수신 경로의 불일치 → 한 방향 예약 실패 | MPLS(Multiprotocol Label Switching) RSVP-TE 기반 명시적 터널로 양방향 경로 고정 | 예약 실패율 |

## Ⅵ. IntServ에 대한 기술사적 제언

- 핵심 요약 : 절대 보장이 필수인 폐쇄망의 한정 적용과 예약 기반 트래픽 엔지니어링의 결합이라는 역할 분담 제안.
- 군 전술망·항공 관제망·원전 제어망처럼 노드 수가 제한되고 무손실 전송이 필수인 폐쇄망 운영 조직은 IntServ와 RSVP 방식을 구간 단위로 한정 적용하는 설계 기준 수립.
- 사업자 백본 조직은 RSVP-TE 기반 대역 예약과 고속 우회(FRR, Fast Reroute)를 결합하여 회선 장애 시에도 보장 품질이 유지되는 구성 적용.
- 산업 제어 분야 조직은 시간 민감 네트워킹(TSN, Time-Sensitive Networking)과 결정론적 네트워킹(DetNet, Deterministic Networking) 표준을 검토하여 지연 보장 구간에 표준 기반 설계 적용.

## Ⅶ. 결론

- 핵심 요약 : IntServ는 흐름 단위 절대 보장의 기술적 완성도를 보인 반면 확장성이 대규모 적용을 가른 모델.
- 현재 실무는 절대 보장이 필요한 한정 구간과 예약 기반 트래픽 엔지니어링의 조합으로 이어지는 흐름.
