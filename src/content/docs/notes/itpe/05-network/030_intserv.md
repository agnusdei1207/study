```text
 ┃
 ┣━ Ⅰ 개요 ───── Best Effort 인터넷의 지연·손실 한계 → 종단 간 플로우별 엄격한 자원 예약(Hard QoS)
 ┣━ Ⅱ 특징 ───── 플로우(Flow) 단위 관리, RSVP 시그널링, 절대적 QoS 보장, 연결 지향적 상태 유지
 ┣━ Ⅲ 구조 ───── RSVP(자원예약 프로토콜) + 수락 제어(Admission Control) + 분류기 + 패킷 스케줄러
 ┣━ Ⅳ 흐름 ───── ① 송신측 PATH 메시지 전송 → ② 수신측 RESV 메시지 역방향 전송 → ③ 경로 라우터 자원 예약 확정
 ┣━ Ⅴ 비교 ───── IntServ vs DiffServ (Hard QoS vs Soft QoS, 플로우별 상태 vs 클래스 집합, 확장성 낮음 vs 높음)
 ┗━ Ⅵ 실무 ───── 수백만 개 플로우 상태 저장으로 백본 라우터 메모리 고갈 / RSVP 주기적 갱신 부하
```

## 한 줄 본질
- 패킷 손실과 지연이 무작위로 발생하는 최선형(Best Effort) 망의 실시간 음성/화상 서비스 한계 → RSVP 프로토콜을 통해 출발지부터 목적지까지 경로상의 모든 라우터에 플로우별 대역폭을 물리적으로 사전 예약 → 절대적이고 결정론적인 전송 품질(Hard QoS) 보장 / 코어 라우터가 수많은 개별 세션 정보를 모두 기억해야 하는 확장성 붕괴 발생

## 핵심 용어
- RSVP(Resource ReSerVation Protocol): 수신자 주도(Receiver-driven) 방식으로 네트워크 경로상의 라우터들에게 대역폭 및 버퍼 자원 예약을 요청하는 시그널링 프로토콜
- 수락 제어(Admission Control): 라우터가 새로운 세션의 예약 요청을 받았을 때, 기존 예약된 세션들의 품질을 깨뜨리지 않고 수용할 수 있는지 판단해 승인/거절하는 메커니즘
- Soft State: 한 번 예약된 자원이 영구 지속되지 않고, 주기적인 RSVP 갱신(Refresh) 메시지가 오지 않으면 자동으로 타임아웃되어 자원이 회수되는 상태 관리 기법

## 핵심 통찰
- IntServ는 전화망(PSTN)의 서킷 스위칭 개념을 인터넷 패킷망에 그대로 이식하려 했던 기술로, "단 1개의 패킷도 지연 없이 보내겠다"는 이상주의적 접근
- 그러나 수백만 명의 사용자가 동시에 유튜브와 웹 서핑을 하는 인터넷 백본망 라우터에 세션당 수 킬로바이트의 상태 테이블을 유지시키는 것은 물리학적으로 불가능(스케일아웃 불가)
- 결국 대규모 인터넷 망에서는 퇴출당하고, 오늘날에는 엔터프라이즈 사설망이나 군용 특수 통신망, 또는 데이터센터 내부 특정 소수 고신뢰 경로 제어에만 제한적으로 사용

## 이웃 토픽과 구분
- IntServ vs DiffServ: IntServ는 통신 전 사전 예약과 라우터 상태 유지가 필수인 Hard QoS / DiffServ는 예약 없이 패킷별 태그(DSCP)만 보고 차등 전달하는 Soft QoS

## 문제·원인·대책
- 적용 상황: 수만 명 동시 접속 환경에서 RSVP IntServ 적용 실패
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 코어 라우터 CPU 100% 포화 및 라우팅 중단 | 세션 수 증가에 따른 RSVP 주기적 갱신 패킷 폭증 및 메모리 고갈 | 코어망 구간을 DiffServ나 MPLS-TE(트래픽 엔지니어링)로 전환 | 라우터 상태 저장을 제거하여 백본망 안정성 회복 |
| 수락 제어 거절로 인한 신규 세션 연결 차단 | 엄격한 피크 대역폭(Peak Rate) 예약으로 인한 회선 유휴 낭비 | 보장형 서비스(Guaranteed)에서 제어 부하(Controlled-load) 서비스로 완화 | 통계적 다중화 이득을 활용해 동시 수용 세션 수 3배 확대 |

## 이렇게 출제된다
- 제125회 1교시: "인터넷 QoS 보장 기술인 IntServ와 DiffServ를 비교 설명하시오." → 요구 포인트: RSVP 시그널링 원리, 서비스 모델(Guaranteed vs Controlled Load), 확장성 한계 분석

## 내 의견
- [DiffServ-aware MPLS-TE(DS-TE)로의 진화적 수용] IntServ의 엄격한 자원 보장 장점과 DiffServ의 확장성 장점을 융합하는 실무 표준 아키텍처 필요 → 나라면: 엣지 구간에서는 RSVP-TE를 사용해 필요한 터널에 대역폭을 예약하되, 코어망 내부에서는 MPLS 라벨과 EXP 비트(DiffServ)를 결합한 트래픽 엔지니어링(MPLS-TE)을 적용하여 코어 라우터의 세션 오버헤드 없이 결정론적 QoS를 달성
