<details>
<summary>핵심 용어</summary>

- **소켓(Socket):** 응용 프로세스가 네트워크 통신에 사용하는 운영체제 제공 종단점
- **TCP(Transmission Control Protocol):** 연결 지향 바이트 스트림 전송 프로토콜
- **UDP(User Datagram Protocol):** 비연결 데이터그램 전송 프로토콜
- **소켓 주소(Socket Address):** IP 주소와 전송 계층 포트 등 통신 종단을 지정하는 정보
- **I/O 다중화(I/O Multiplexing):** 한 실행 흐름이 여러 입출력 대상의 준비 상태를 감시하는 방식

## Ⅱ. 연결·데이터 전달

```text
서버: socket → bind → listen
                  ▲
클라이언트: socket → connect
                  │ 연결 수락
                  ▼
             연결 소켓
                  │ 데이터 전달
                  ▼
             응용 처리
```

| 전송 방식 | 통신 특성 |
|---|---|
| TCP 소켓 | 연결을 설정하고 순서 있는 바이트 스트림 제공 |
| UDP 소켓 | 연결 설정 없이 데이터그램 단위 송수신 |

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **소켓(Socket)** 은 응용 프로세스가 네트워크 통신을 위해 운영체제에 요청하는 통신 종단점 |
| 목적 | 응용 프로그램에 표준화된 송수신 인터페이스 제공 |

## Ⅱ. 서버·클라이언트 처리 흐름

```text
서버: socket → bind → listen ─┐
                              ├─ 연결 요청 수락 → 연결 소켓
클라이언트: socket → connect ─┘                    │
                                                   ▼
                                          데이터 송수신
                                                   │
                                                   ▼
                                            close·정리
```

| 식별 요소 | 기능 |
|---|---|
| 로컬·원격 IP 주소 | 송수신 네트워크 종단 식별 |
| 로컬·원격 포트 | 호스트 내 전송 계층 종단 식별 |
| 전송 프로토콜 | TCP 또는 UDP 처리 방식 구분 |

## Ⅲ. TCP·UDP 소켓 비교

| 구분 | TCP | UDP |
|---|---|---|
| 전달 단위 | 순서 있는 바이트 스트림 | 독립 데이터그램 |
| 연결 | 연결 설정·상태 유지 | 연결 설정 없이 전송 |
| 응용 고려 | 메시지 경계는 응용 계층이 정의 | 데이터그램 경계와 크기 고려 |

## Ⅳ. 동시성·오류 처리

| 운영 요소 | 고려사항 |
|---|---|
| 블로킹 처리 | 대기 중 실행 흐름이 다른 요청을 처리하지 못할 수 있음 |
| I/O 다중화 | 다수 소켓 상태 감시로 연결 처리 효율을 높일 수 있으나 응용 상태 관리 필요 |
| 연결 해제·시간초과 | 정상 종료와 비정상 단절을 구분하고 자원 회수 기준 설정 |
| 스트림 메시지 경계 | 길이 접두부나 구분자 등 응용 프레이밍 정의 |

## Ⅴ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 동시 접속 수만 기준으로 모델을 고르면 메시지 처리량·대기시간·자원 고갈을 놓칠 수 있음 | 예상 연결·메시지 크기·지연 목표를 부하 모델로 만들고, 블로킹·이벤트 방식의 자원 사용과 장애 회복을 함께 시험 |
