## Ⅰ. IBN(Intent-Based Networking)의 개요

- 개념 : 네트워크 관리자가 개별 장비의 저수준 CLI 명령어나 복잡한 라우팅 설정을 일일이 입력하지 않고 고수준의 비즈니스 목적(의도: Intent)을 정의하면, 소프트웨어가 이를 자동 번역·구성하고 실시간 **검증** 및 **폐쇄 루프(Closed-Loop)** 자가 치유를 수행하는 지능형 네트워크 아키텍처.
- 배경 및 필요성 : 클라우드, 마이크로서비스, 원격 근무 확산으로 기업 네트워크 복잡도가 인간의 관리 역량을 초과했으며, 네트워크 장애의 상당수가 사람의 수동 CLI 설정 실수(Human Error)에서 비롯되는 구조적 문제를 해결하기 위해 출현함.
- 핵심 목적 : 비즈니스 의도 기반의 네트워크 운영 자동화(NoOps 지향), 배포 전 수학적 정형 검증을 통한 무장애 보장, 실시간 텔레메트리와 AI 결합을 통한 **서비스 수준 협약(SLA)** 능동 보증.

## Ⅱ. IBN(Intent-Based Networking)의 핵심 아키텍처 및 동작 메커니즘

IBN은 가트너(Gartner)의 정의에 따라 1. 번역(Translation), 2. 검증(Validation), 3. 활성화(Activation), 4. 보증(Assurance)의 4대 핵심 라이프사이클 단계로 지속 순환 동작함.

```text
[ IBN (Intent-Based Networking) 4대 라이프사이클 및 Closed-Loop 구조 ]

+-----------------------------------------------------------------+
| 비즈니스 의도 (Business Intent): "연구소 트래픽은 재무망과 격리하라" |
+---------------------------------│────────────────---------------+
                                  │
                                  ▼
+-----------------------------------------------------------------+
| 1. 번역 (Translation / Ingestion)                               |
|    - 자연어/비즈니스 정책을 기계가 읽을 수 있는 선언적 정책 변환 |
+---------------------------------│────────────────---------------+
                                  │
                                  ▼
+-----------------------------------------------------------------+
| 2. 검증 (Validation / Simulation)                               |
|    - 배포 전 네트워크 디지털 트윈에서 수학적 정형 검증           |
|    - "격리 정책 적용 시 기존 연구소 ERP 접속 영향 여부 확인"     |
+---------------------------------│────────────────---------------+
                                  │ (이상 없음 확인 시)
                                  ▼
+-----------------------------------------------------------------+
| 3. 활성화 (Activation / Provisioning)                           |
|    - SDN 컨트롤러 및 장비 API(NETCONF/YANG)를 통해 일괄 자동 배포|
+---------------------------------│────────────────---------------+
                                  │
                                  ▼
+-----------------------------------------------------------------+
| 4. 보증 (Assurance / Continuous Verification)                   |
|    - 스트리밍 텔레메트리로 실시간 SLA 및 정책 일치 여부 연속 감시 |
|    - 정책 불일치 감지 시 -> 자동 롤백 또는 재구성 (Closed-Loop)   |
+-----------------------------------------------------------------+
```

- **번역(Translation)** : 비즈니스 관리자의 선언적 의도(Declarative Policy)를 구체적인 L2~L7 네트워크 엔지니어링 설정(VLAN, ACL, QoS, BGP 정책)으로 자동 컴파일.
- **검증(Validation)** : 실제 물리망에 배포하기 전 수학적 정형 검증(Formal Verification) 및 네트워크 디지털 트윈 모델을 통해 정책 충돌 및 보안 홀 유무를 사전 시뮬레이션.
- **활성화(Activation)** : SDN 컨트롤러 및 자동화 오케스트레이터가 OpenConfig, **NETCONF/YANG** 표준 프로토콜을 사용하여 수천 대의 물리/가상 스위치에 구성을 원자적(Atomic)으로 배포.
- **보증(Assurance) 및 폐쇄 루프(Closed-Loop)** : **gNMI** 기반 고속 스트리밍 텔레메트리를 통해 실제 망 상태를 관측하고, 원래 의도와 편차가 발생하면 AI가 스스로 설정을 수정하여 원상 복구.

## Ⅲ. IBN(Intent-Based Networking)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 전통적 네트워크 운영 (Traditional) | 소프트웨어 정의 네트워킹 (SDN) | 의도 기반 네트워킹 (IBN) |
|---|---|---|---|
| 운영 방식 | 장비별 수동 CLI 설정 (명령형) | 중앙 컨트롤러 프로그래밍 (명령형) | 비즈니스 목적 선언적 정의 (선언형) |
| 정책 수준 | 저수준 (IP, Port, VLAN) | API 수준 (Flow Table, OpenFlow) | 고수준 (보안 격리, SLA 대역 보장) |
| 검증 메커니즘 | 운영자의 육안 검토 및 사후 핑 테스트 | 스크립트 기반 수동 테스트 | 수학적 정형 검증 및 시뮬레이션 |
| 장애 복구 | 인력 호출 후 수동 트러블슈팅 (수 시간)| 관리자가 스크립트 재실행 | AI 기반 폐쇄 루프 자동 자가 치유 |
| 핵심 기술 | SNMP, CLI, Syslog | OpenFlow, 분산 컨트롤러 | AI/ML, 디지털 트윈, 스트리밍 텔레메트리 |

- SDN이 네트워크의 '제어 평면을 프로그래밍 가능하게 분리'했다면, IBN은 그 위에 '비즈니스 인텔리전스와 자동 검증 루프를 탑재'하여 진정한 자율 운영을 완성함.

## Ⅳ. IBN(Intent-Based Networking)의 주요 한계점 및 해결 방안

- 비즈니스 의도의 모호성으로 인한 정책 오역 및 부작용(Misconfiguration) :
  - 한계점 : 자연어로 표현된 고수준 의도가 네트워크 엔지니어링 파라미터로 번역되는 과정에서 해석 오류 발생 가능.
  - 해결 방안 : 도메인 특화 네트워크 언어(DSL) 정립, 정형 검증 엔진의 사전 영향도 시뮬레이션 리포트 승인 절차 필수화.
- 멀티벤더 이종 네트워크 장비 간 API 및 기능 모델 파편화 :
  - 한계점 : 시스코, 주니퍼, 아리스타 등 제조사별 독자 기능 모델 차이로 인해 이기종 통합 IBN 구성 난항.
  - 해결 방안 : IETF 표준 YANG 데이터 모델 및 벤더 중립적 OpenConfig 인터페이스 준수 의무화.
- 폐쇄 루프(Closed-Loop) 자동 제어 시 피드백 플래핑(Flapping) 위험 :
  - 한계점 : 망 상태 불안정 시 자동 치유 알고리즘이 설정을 연속해서 변경하며 전체 망의 진동 및 서비스 불안정 유발.
  - 해결 방안 : 댐핑(Damping) 타이머 적용, 점진적 카나리 롤아웃 및 최종 위기 시 인간 승인(Human-in-the-Loop) 모드 전환.

## Ⅴ. IBN(Intent-Based Networking) 적용 및 발전을 위한 기술사적 제언

- NetOps 자동화를 위한 CI/CD GitOps 파이프라인 통합 : 네트워크 설정을 Git 리포지토리에 선언적 코드로 관리하고 변경 시 IBN 검증 엔진을 자동 트리거하는 NetDevOps 체계 구축 권장.
- 네트워크 디지털 트윈(Digital Twin)의 실시간 상태 동기화 고도화 : 물리 인프라의 라우팅 상태 및 패킷 포워딩 플로우를 1초 이내로 가상 트윈에 동기화하여 변경 영향도 검증의 정확도 극대화.
- 제로 트러스트(Zero Trust) 보안 아키텍처 연계 비즈니스 인텐트 정책 강제 : 사용자 ID와 단말 신원 기반의 동적 인텐트 정책을 수립하여 부서 이동 시 물리 네트워크 재설정 없는 자동 격리 실현.
