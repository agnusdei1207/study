## 연관 키워드

- 의도 기반 네트워킹(IBN, Intent-Based Networking), 의도(Intent), 번역(Translation), 검증(Validation), 활성화(Activation), 보증(Assurance)
- 폐루프(Closed-Loop), 디지털 트윈(Digital Twin), NETCONF(Network Configuration Protocol), YANG, 스트리밍 텔레메트리(Streaming Telemetry)

## Ⅰ. 의도 기반 네트워킹의 개요

- 핵심 요약 : 운영자가 선언한 의도를 설정으로 변환하고, 배포 전 검증과 배포 후 보증으로 의도와 실제 상태의 일치를 유지하는 자율 운영 방식.
- 개념 : 보안 격리, 서비스 품질 보장 같은 상위 목표를 결과 상태로 선언하는 **의도**(Intent)를 입력받아, 시스템이 장비 설정으로 변환·배포하고 운영 결과를 지속 감시·교정하는 **의도 기반 네트워킹** (IBN, Intent-Based Networking). IETF(Internet Engineering Task Force)의 RFC 9315가 개념과 용어를 정의한 문서.
- 배경 및 필요성 : 장비별 CLI(Command-Line Interface) 수동 설정 방식은 정책 수 증가와 다벤더 환경에서 설정 불일치와 휴먼 에러가 누적되는 구조.
- 주요 목적 : 운영 자동화, 배포 이전의 오류 차단, 의도와 실제 상태의 지속 일치.

## Ⅱ. 의도 기반 네트워킹의 특징 및 장점

- 핵심 요약 : 선언형 명세, 자동 변환, 사전 검증, 폐루프 보증의 네 속성이 설정 오류 감소와 대응 시간 단축으로 연결되는 구조.

1. 선언형 명세 : 원하는 결과 상태를 정책 문장으로 기술 → 구현 절차를 몰라도 정책 변경 가능 → 운영 인력 부담 완화.
2. 자동 변환 : **번역**(Translation, 의도를 장비 설정으로 바꾸는 단계)을 데이터 모델 기반으로 수행 → 장비 간 설정 편차 제거.
3. 사전 검증 : **검증**(Validation, 배포 전 정책 충돌과 영향을 따지는 단계)을 디지털 트윈(실제 망을 복제한 소프트웨어 모델)에서 수행 → 장애를 배포 이전에 차단.
4. 폐루프 보증 : **폐루프**(Closed-Loop, 관측 결과가 다시 제어 입력으로 돌아오는 구조) 안에서 **보증**(Assurance, 운영 결과가 의도에 부합하는지 감시하는 단계)을 상시 수행 → 사람 개입 이전의 장애 교정.
5. 배포의 자동화 : **활성화**(Activation, 변환된 설정을 다수 장비에 일괄 적용하는 단계)를 표준 인터페이스로 수행 → 수작업 배포의 편차 소멸.

## Ⅲ. 의도 기반 네트워킹의 구조 (흐름)

- 핵심 요약 : 명세 → 번역 → 검증 → 활성화 → 보증이 순환하고, 보증의 편차가 다시 번역으로 돌아가는 폐루프 구조.

```text
[ IBN 순환 단계 ]

의도 명세 (결과 상태 선언)
    ↓
번역 (의도 → 장비 설정)
    ↓
검증 (충돌·영향 시뮬레이션)
    ↓
활성화 (다수 장비 일괄 배포)
    ↓
보증 (상태 감시·편차 교정)
```

```text
[ 폐루프 보증 루프 ]

장비 상태 수집 (텔레메트리)
    ↓
의도와의 비교 (편차 판정)
    ↓ 편차 존재 시
원인 분석 → 재구성·롤백
    ↓
감시 재개 (루프 반복)
```

- 상태 수집은 NETCONF나 gNMI(gRPC Network Management Interface) 기반의 **스트리밍 텔레메트리**(장비 상태를 요청 없이 상시 전송하는 방식)로 수행하고, 설정 전달은 YANG 데이터 모델로 정형화하는 조합이 표준적 구성.

## Ⅳ. 전통 운영, SDN, IBN의 비교

- 핵심 요약 : 운영의 추상화 수준이 수동 명령 → 컨트롤러 프로그래밍 → 의도 선언으로 상승하는 단계적 관계.
- SDN(Software-Defined Networking)이 제어 평면을 중앙 컨트롤러로 모은 반면, IBN은 그 위에 의도의 번역·검증·보증 체계를 얹은 상위 단계.

| 비교 축 | 전통적 운영 | SDN | IBN |
| --- | --- | --- | --- |
| 운영 방식 | 장비별 수동 CLI (명령형) | 컨트롤러 프로그래밍 (명령형) | 결과 상태 선언 (선언형) |
| 정책 수준 | IP·포트·VLAN(Virtual Local Area Network) 같은 저수준 | 플로우·경로 수준 | 격리·품질 보장 같은 고수준 |
| 검증 시점 | 배포 후 육안·사후 점검 | 스크립트 기반 수동 테스트 | 배포 전 정형 검증·시뮬레이션 |
| 장애 대응 | 인력 호출 후 수동 조치 | 스크립트 재실행 | 폐루프 자동 교정 |
| 핵심 구성 요소 | CLI·Syslog | 컨트롤러·오픈 API | 정책 언어·디지털 트윈·텔레메트리 |

- 선택 기준 : 장비 수가 적고 정책 변경이 드물면 전통 운영으로 충분하고, 중앙 제어가 필요하면 SDN, 정책 규모와 변경 빈도가 모두 크면 IBN이 적합.

## Ⅴ. 의도 기반 네트워킹의 한계와 방안

- 핵심 요약 : 의도 해석의 모호성, 이기종 장비 모델 차이, 자동 교정 진동의 세 한계를 정형 정책 언어, 표준 데이터 모델, 변경 통제로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 의도 해석 오류 | 추상적 선언이 번역 과정에서 의미가 어긋남 → 오류 정책의 대량 배포 | 도메인 특화 정책 언어 사용, 시뮬레이션 결과의 승인 절차 의무화 | 정책 오류 건수 |
| 이기종 모델 차이 | 벤더별 독자 확장 모델 → 통합 자동화 난항 | 표준 YANG 모델과 OpenConfig 인터페이스 준수 장비의 선정 | 표준 모델 지원률 |
| 자동 교정 진동 | 불안정 상태에서 설정의 반복 변경 → 플래핑과 서비스 불안 | 변경 속도 제한, 일부 구간 우선 적용, 고위험 변경의 사람 승인 | 롤백 횟수 |

## Ⅵ. 의도 기반 네트워킹에 대한 기술사적 제언

- 핵심 요약 : 설정의 코드화를 기반으로 자동화 범위를 검증 가능한 영역부터 단계적으로 확대하는 운영 체계 제안.
- 네트워크 운영 조직은 설정을 버전 관리 저장소의 선언형 코드로 관리하고, 변경 요청 시 검증 파이프라인이 자동 수행되는 NetDevOps 체계를 우선 구축하는 방안.
- 보안 조직은 사용자·단말의 신원에 따라 격리 정책이 따라가는 신원 기반 의도 정책을 도입하여 제로 트러스트(Zero Trust) 구조와의 연계를 설계에 반영할 필요.
- 기술 거버넌스 차원에서는 장애 이력과 검증 통과율을 근거로 자동화 권한을 단계 확대하는 심의 절차를 두어 무단 자동 교정의 위험을 통제하는 체계 마련.

## Ⅶ. 결론

- 핵심 요약 : IBN은 네트워크 운영을 장비 조작의 자동화에서 의도 관리로 옮기는 선언형 운영 방식.
- 도입의 성패는 의도를 정확하게 기술하는 정책 언어와 검증 체계의 성숙도에 달려 있는 과제.
