## 연관 키워드

- 의도 기반 네트워킹(IBN, Intent-Based Networking), 소프트웨어 정의 네트워킹(SDN, Software-Defined Networking), 폐쇄 루프(Closed-Loop), 디지털 트윈(Digital Twin)
- NETCONF, YANG, OpenConfig, gNMI(gRPC Network Management Interface), 스트리밍 텔레메트리(Streaming Telemetry), 보증(Assurance)

## Ⅰ. 의도 기반 네트워킹의 개요

- 핵심 요약 : 관리자의 비즈니스 의도를 선언하면 시스템이 설정으로 번역해 배포하고 결과를 검증·보증하는 네트워크 운영 방식.
- 개념 : 장비별 CLI(Command-Line Interface) 명령을 일일이 입력하는 대신 **의도**(Intent)를 선언하면, 소프트웨어가 이를 설정으로 번역하여 배포하고 실제 상태를 감시해 편차를 교정하는 **의도 기반 네트워킹**(IBN, Intent-Based Networking).
- 배경 및 필요성 : 클라우드와 마이크로서비스, 원격 근무 확산으로 정책 수가 늘어 사람이 장비마다 설정을 맞추기 어려워졌고, 수동 설정 실수가 장애로 이어지는 문제를 줄이기 위해 등장함.
- 주요 목적 : 설정 작업의 자동화, 배포 전 검증을 통한 장애 예방, 서비스 수준 협약(SLA, Service Level Agreement) 준수의 지속 감시.

## Ⅱ. 의도 기반 네트워킹의 특징 및 장점

- 핵심 요약 : 선언형 의도, 사전 검증, 자동 배포, 폐쇄 루프 보증이 운영 실수를 줄이고 대응 시간을 단축하는 구조.

1. 선언형 의도 : 보안 격리나 대역 보장 같은 목적을 정책으로 기술 → 저수준 설정을 몰라도 정책 변경이 가능해져 운영 인력의 부담 완화.
2. 사전 검증 : 디지털 트윈 모델에서 배포 전 정책 충돌과 영향을 시뮬레이션 → 장애를 배포 이전에 차단.
3. 자동 배포 : NETCONF(Network Configuration Protocol)와 YANG(Yet Another Next Generation) 모델로 다수 장비에 일관된 설정 전달 → 수작업 편차 제거.
4. 폐쇄 루프 보증 : gNMI(gRPC Network Management Interface) 기반 스트리밍 텔레메트리로 상태를 관측하고 편차가 생기면 재구성이나 롤백 수행 → 사람의 대응 전에 서비스 품질 회복.

## Ⅲ. 의도 기반 네트워킹의 구조 (흐름)

- 핵심 요약 : 번역, 검증, 활성화, 보증의 순환 단계와, 보증 결과가 다시 번역으로 돌아가는 폐쇄 루프의 이중 구조.
- 흐름의 단계 명칭과 구분은 자료에 따라 다르며, 번역·활성화·보증을 핵심 축으로 두고 검증을 배포 전 단계로 따로 설명하는 경우가 많음.

```text
[ IBN 순환 흐름 ]

비즈니스 의도 (선언)
      ↓
1. 번역 (정책 → 설정 변환)
      ↓
2. 검증 (디지털 트윈 시뮬레이션)
      ↓
3. 활성화 (자동 배포)
      ↓
4. 보증 (실시간 감시)
      ↓ 편차 발생 시
   재구성 또는 롤백 → 1단계 재진입
```

```text
[ 폐쇄 루프 보증 ]

장비 상태 수집 (텔레메트리)
      ↓
의도와 비교 (편차 판정)
      ↓ 편차 있음
정책 재계산 (자동 교정)
      ↓
설정 재배포
      ↓
다시 상태 수집 (루프 반복)
```

## Ⅳ. 전통 운영, SDN과의 비교

- 핵심 요약 : 전통 운영은 수동 명령형, 소프트웨어 정의 네트워킹(SDN, Software-Defined Networking)은 컨트롤러 프로그래밍, 의도 기반 네트워킹은 의도 선언형이라는 운영 추상화 수준의 차이.
- 선택 기준 : 장비 수가 적고 정책 변경이 드물면 전통 운영으로 충분하며, 정책이 자주 바뀌고 장비 규모가 크면 IBN의 자동화 효과가 커짐.

| 비교 축 | 전통적 운영 | SDN | IBN |
| --- | --- | --- | --- |
| 운영 방식 | 장비별 수동 CLI 설정 (명령형) | 중앙 컨트롤러 프로그래밍 (명령형) | 비즈니스 목적 선언 (선언형) |
| 정책 수준 | IP, 포트, VLAN 같은 저수준 | 플로우 테이블 수준 (OpenFlow) | 보안 격리, 대역 보장 같은 고수준 |
| 검증 방식 | 운영자 육안 검토와 사후 점검 | 스크립트 기반 수동 테스트 | 정형 검증과 시뮬레이션 |
| 장애 대응 | 인력 호출 후 수동 점검 | 스크립트 재실행 | 폐쇄 루프 자동 교정 |
| 핵심 기술 | CLI, Syslog | OpenFlow, 분산 컨트롤러 | 인공지능·머신러닝, 디지털 트윈, 스트리밍 텔레메트리 |

- SDN이 제어 평면을 프로그래밍 가능하게 분리했다면, IBN은 그 위에 의도 번역과 검증 루프를 얹어 운영을 자율화하는 방식.

## Ⅴ. 의도 기반 네트워킹의 한계와 방안

- 핵심 요약 : 의도 해석 오류, 장비 이기종성, 자동 교정의 진동이라는 세 한계를 정책 언어 표준화, 표준 모델, 댐핑과 사람 승인으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 의도 해석 오류 | 자연어 의도가 설정 파라미터로 번역되며 의미가 어긋나 잘못된 정책 배포 | 정책을 기술하는 도메인 특화 언어 정립과 영향도 시뮬레이션 보고서의 승인 절차 필수화 | 정책 오류 건수, 검증 통과율 |
| 이기종 장비 모델 차이 | 제조사별 독자 기능 모델로 통합 자동화 난항 | IETF(Internet Engineering Task Force) 표준 YANG 데이터 모델과 벤더 중립 OpenConfig 인터페이스 준수 | 표준 모델 지원률 |
| 자동 교정의 진동 | 불안정한 상태에서 설정이 연속 변경되어 플래핑(Flapping)과 서비스 불안정 발생 | 댐핑 타이머, 점진적 카나리 배포, 위험 시 사람 승인으로 전환 | 설정 변경 빈도, 롤백 횟수 |

## Ⅵ. 의도 기반 네트워킹에 대한 기술사적 제언

- 핵심 요약 : 설정을 코드로 관리하는 NetDevOps 기반 위에서 자동화 범위를 검증 가능한 영역부터 단계적으로 넓히는 운영 방식.
- 네트워크 설정을 Git 저장소의 선언형 코드로 관리하고, 변경이 올라올 때 검증 엔진이 자동으로 돌도록 파이프라인을 구축하는 것이 실무 적용의 출발점이다.
- 사용자 신원과 단말 신원에 기반한 의도 정책을 두면 부서를 옮겨도 물리 설정을 바꾸지 않고 격리를 바꿀 수 있어, 제로 트러스트(Zero Trust) 보안 구조와 연계하는 설계가 유효하다.
- 자동 교정 기능에는 댐핑 임계치와 사람 승인 단계를 함께 두고, 장애 이력이 쌓이는 만큼 자동화 권한을 넓히는 거버넌스가 필요하다.

## Ⅶ. 결론

- 핵심 요약 : 의도 기반 네트워킹은 SDN의 프로그래밍 가능한 제어 평면 위에 의도 번역과 검증 루프를 얹은 자율 운영 방식.
- 시사점 : 효과는 정책의 정확성과 검증 체계가 전제될 때 나타나므로, 자동화는 검증 가능한 범위에서 점진적으로 넓히는 것이 현실적.
