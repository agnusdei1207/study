## 30초 인출

- 본질: **IBN(Intent-Based Networking)** : 운영자가 네트워크가 달성할 목표와 결과를 선언적으로 제시하고 구현 세부를 네트워크 관리 시스템에 맡기는 관리 방식
- 메커니즘: 의도 수용·정제 → 정책·구성으로 구체화 → 네트워크 적용 → 텔레메트리로 결과 확인·조정
- 통찰: 복잡한 CLI 기반의 개별 장비 설정 방식을 탈피하여 운영자의 비즈니스 의도(Intent)를 자연어로 선언하면 AI와 SDN 오케스트레이터가 자율적으로 구성·검증하고 실시간 폐루프(Closed-loop)로 유지하는 차세대 자율 네트워킹 패러다임임.

<details>
<summary>핵심 용어</summary>

- **IBN(Intent-Based Networking)** : 목표·결과를 선언적으로 입력해 네트워크를 관리하는 방식
- **의도(Intent)** : 달성할 운영 목표와 결과를 구현 방법을 지정하지 않고 표현한 명세
- **의도 이행(Intent Fulfillment)** : 의도를 네트워크 동작·구성으로 실현하는 기능
- **의도 보증(Intent Assurance)** : 실제 네트워크 상태가 의도한 목표에 부합하는지 확인하는 기능
- **의도 기반 시스템(IBS, Intent-Based System)** : 의도에 따른 네트워크 관리 기능을 지원하는 시스템
- **의도 드리프트(Intent Drift)** : 시간이 지나며 실제 네트워크 동작이 의도한 결과에서 벗어나는 현상
- **텔레메트리(Telemetry)** : 운영 상태·측정 데이터를 수집해 시스템 상태를 파악하는 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. IBN(Intent-Based Networking)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 네트워크 운영자의 고수준 비즈니스 의도(Intent, '무엇을 할 것인가')를 입력받아 AI/알고리즘이 하위 네트워크 장비의 세부 설정('어떻게 할 것인가')으로 자동 변환하고 실시간 폐루프(Closed-loop)로 검증·유지하는 자율 네트워킹 기술 |
| 목적 | 수작업 CLI 설정에 따른 휴먼 에러(오설정) 원천 차단, 대규모 엔터프라이즈 망의 설정 배포 시간(수주 -> 수분) 단축 및 무중단 SLA 자율 보장 |

## Ⅱ. IBN(Intent-Based Networking)의 특징

| 특징 | 상세 내용 |
|---|---|
| 선언적 모델(Declarative)| 구체적 명령어가 아닌 운영자가 원하는 최종 목표 상태(Desired State)만 정의 |
| 자동 변환 및 컴파일 | 자연어/REST API 의도를 구체적인 방화벽 ACL, QoS 큐, 라우팅 정책으로 자동 생성 |
| 지속적 검증(Assurance)| 네트워크 텔레메트리 데이터를 실시간 수집하여 실제 망 상태가 의도와 일치하는지 수학적 검증 |
| 폐루프 자율 치유 | 네트워크 병목이나 장애로 의도 위반(Drift) 감지 시 인간 개입 없이 자율적으로 설정 재조정 |

## Ⅲ. IBN(Intent-Based Networking)의 체계·프로세스

**IBN 4대 빌딩 블록 및 폐루프(Closed-loop) 아키텍처**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ IBN 4대 핵심 빌딩 블록 ]                      │
│                                                                        │
│   운영자 / 애플리케이션                                                │
│   └─► [ 비즈니스 의도 입력 ] : "영상회의 트래픽 지연 10ms 이하 보장"   │
│            │                                                           │
│            ▼ [ 1. Translation & Validation ]                           │
│   의도 번역 엔진 (NLP / 정책 컴파일러) ──► 디지털 트윈 검증 (충돌 사전 방지)│
│            │                                                           │
│            ▼ [ 2. Activation ]                                         │
│   네트워크 정책 배포 (SDN Controller, NETCONF/YANG 기반 스위치/라우터 반영)│
│            │                                                           │
│            ▼                                                           │
│   물리 / 가상 네트워크 인프라 (스위치, 라우터, 방화벽, 무선 AP)          │
│            │                                                           │
│            ▼ [ 3. Continuous Assurance ]                               │
│   실시간 텔레메트리 수집 (eBPF, 스트리밍 텔레메트리, AI 이상 탐지)     │
│            │                                                           │
│            ▼ [ 4. Closed-loop Automation ]                             │
│   [ 의도 위반(Drift) 감지 시 자율 치유 및 재라우팅 명령 피드백 ] ───────┘│
└────────────────────────────────────────────────────────────────────────┘
```

| 빌딩 블록 | 영문 명칭 | 핵심 동작 및 기술 요소 |
|---|---|---|
| **변환 (Translation)** | Translation & Validation | 고수준 비즈니스 의도를 파싱하고 기존 정책과의 충돌 여부를 수학적 정형 검증(Formal Verification) |
| **활성화 (Activation)** | Automated Activation | 검증된 정책을 인프라 구성 템플릿으로 변환하여 SDN 컨트롤러를 통해 전 장비에 일괄 원자적(Atomic) 배포 |
| **보증 (Assurance)** | Continuous Assurance | 스트리밍 텔레메트리로 전송 지연, 손실률, 보안 상태를 실시간 감시하여 의도와의 괴리(Drift) 분석 |
| **자동화 (Automation)** | Closed-loop Remediation | 트래픽 폭증이나 링크 단절 시 AI 에이전트가 최적 대안 경로를 찾아 자율적으로 복구 조치 실행 |

## Ⅳ. IBN(Intent-Based Networking)의 종류·비교

| 비교 항목 | 전통적 네트워킹 (CLI) | SDN (Software-Defined) | IBN (Intent-Based) |
|---|---|---|---|
| **제어 방식** | 장비별 명령적(Imperative) CLI | 중앙 집중식 프로그래밍 제어 | **선언적(Declarative) 비즈니스 의도**|
| **추상화 수준**| 하드웨어 장비 레벨 | 네트워크 토폴로지/플로우 레벨 | **비즈니스 서비스 및 보안 요구 레벨**|
| **장애 조치** | 운영자 수동 알람 확인 및 개입 | 관리자 스크립트 기반 대응 | **실시간 폐루프 기반 자가 치유(Self-healing)**|
| **검증 메커니즘**| 배포 후 사후 핑/트레이스 테스트| 플로우 룰 상태 확인 | **수학적 정형 검증 및 디지털 트윈 사전 검증**|
| **주요 동인** | 하드웨어 연결성 확보 | 제어와 데이터 평면 분리 | **운영 완전 자동화 및 자율 주행 네트워크**|

## Ⅴ. IBN(Intent-Based Networking)의 한계와 방안

| 한계 | 방안 |
|---|---|
| 복잡한 비즈니스 의도 번역 시 모호성으로 인한 오설정 및 다중 의도 간 정책 충돌(Policy Conflict) | 정형 검증(Formal Verification) 엔진 및 그래프 신경망(GNN) 기반 사전 시뮬레이션 의무화 |
| 멀티벤더 이종 장비 환경에서 각 벤더별 사양 차이로 인한 표준화된 의도 적용 난해 | OpenConfig 및 IETF 표준 YANG 데이터 모델 기반 오픈 오케스트레이션 어댑터 구축 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
엔터프라이즈 IBN 도입 시, 처음부터 전사 망에 자율 폐루프(Full Automation)를 적용하면 위험하므로, 1단계: '읽기 전용 Assurance(의도 위반 알람)', 2단계: '인간 승인 기반 배포', 3단계: '검증된 영역(지사 WAN)부터 폐루프 활성화'의 3단계 로드맵으로 추진.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ IBN 정형 검증 (Formal Verification) 및 디지털 트윈 동작 구조 ]       │
│                                                                        │
│   운영자 의도: "연구소 DB망은 외부 인터넷에서 절대 도달 불가능해야 함" │
│        │                                                               │
│        ▼                                                               │
│   [ 수학적 네트워크 모델 (Data Plane Model) ]                          │
│   - 모든 헤더 공간(Header Space)에 대한 도달 가능성 그래프 행렬 연산   │
│        │                                                               │
│        ├─► [ 정책 충돌 감지! ] "게스트 Wi-Fi 정책과 라우팅 누수 발견"  │
│        │   (실제 물리 장비 배포 전 컴파일 에러로 사전 차단)            │
│        │                                                               │
│        ▼ (검증 통과 시에만)                                            │
│   [ 실제 물리 망 배포 (Zero Outage Deployment) ]                       │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 솔루션 영역 | 대표 상용 제품 | 핵심 강점 | 주 적용 영역 |
|---|---|---|---|
| **데이터센터 IBN** | Cisco Nexus Dashboard, Apstra | 마이크로 세그멘테이션, EVPN-VXLAN 자동화 | 대규모 프라이빗 클라우드 |
