## 30초 인출

- 본질: **IBN(Intent-Based Networking)** : 운영자가 네트워크가 달성할 목표와 결과를 선언적으로 제시하고 구현 세부를 네트워크 관리 시스템에 맡기는 관리 방식
- 메커니즘: 의도 수용·정제 → 정책·구성으로 구체화 → 네트워크 적용 → 텔레메트리로 결과 확인·조정

<details>
<summary>핵심 용어</summary>

- **IBN(Intent-Based Networking)** : 목표·결과를 선언적으로 입력해 네트워크를 관리하는 방식
- **의도(Intent)** : 달성할 운영 목표와 결과를 구현 방법을 지정하지 않고 표현한 명세
- **의도 이행(Intent Fulfillment)** : 의도를 네트워크 동작·구성으로 실현하는 기능
- **의도 보증(Intent Assurance)** : 실제 네트워크 상태가 의도한 목표에 부합하는지 확인하는 기능
- **의도 기반 시스템(IBS, Intent-Based System)** : 의도에 따른 네트워크 관리 기능을 지원하는 시스템
- **의도 드리프트(Intent Drift)** : 시간이 지나며 실제 네트워크 동작이 의도한 결과에서 벗어나는 현상
- **텔레메트리(Telemetry)** : 운영 상태·측정 데이터를 수집해 시스템 상태를 파악하는 방식

</details>

## 1교시 10점 답안

### Ⅰ. IBN의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **IBN** : 운영 목표·결과를 선언적으로 제시해 네트워크 관리를 지원하는 방식 |
| 목적 | 장비별 세부 설정보다 서비스·운영 목표 중심의 네트워크 관리 |

### Ⅱ. 의도 관리 흐름

```text
운영 목표·결과 선언
      ↓
의도 해석·실현 계획
      ↓
네트워크 구성·동작
      ↓
상태·결과 관측
      ↓ 편차 확인·조정
의도 실현 계획으로 환류
```

- 제언: 목표 명세와 실제 상태의 지속 비교를 포함한 의도 관리.

## 2~4교시 25점 답안

### Ⅰ. IBN의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **IBN** : 운영 목표·결과를 선언적으로 제시해 네트워크 관리를 지원하는 방식 |
| 목적 | 장비별 세부 설정보다 서비스·운영 목표 중심의 네트워크 관리 |

### Ⅱ. 의도 이행·보증 폐루프

```text
운영 목표·결과 선언
      ↓
의도 해석·실현 계획
      ↓
네트워크 구성·동작
      ↓
상태·결과 관측
      ↓ 편차 확인·조정
의도 실현 계획으로 환류
```

운영 목표는 의도로 받아들여 실현 계획과 네트워크 동작으로 이어지고, 관측 결과가 의도와 맞는지 비교해 필요하면 계획을 조정. 자동 보정의 범위와 권한은 구현마다 다르며 IBN이라는 명칭만으로 AI 사용이나 완전 자율 복구를 전제하지 않음.

### Ⅲ. 주요 기능

| 기능 | 역할 | 확인 항목 |
|---|---|---|
| 의도 수용·정제 | 목표·범위·제약을 해석 가능한 명세로 정리 | 모호성, 우선순위, 권한 |
| 의도 이행 | 실현 계획을 네트워크 정책·구성으로 반영 | 지원 능력, 충돌, 변경 이력 |
| 의도 보증 | 실제 상태·서비스 결과를 의도와 비교 | 관측 범위, 기준 시점, 편차 |
| 피드백·조정 | 편차 원인과 조치 결과에 따라 후속 동작 선택 | 승인·롤백·예외 처리 |

### Ⅳ. IBN과 관련 개념

| 구분 | 중심 초점 |
|---|---|
| 정책 기반 관리 | 조건·규칙에 따라 수행할 동작 지정 |
| SDN(Software-Defined Networking) | 제어 평면과 전달 평면의 분리·소프트웨어 제어 |
| IBN | 목표·결과를 선언하고 실현·준수 여부를 관리 |

IBN은 특정한 중앙집중 SDN 구조와 동의어가 아니며, 정책 기반 관리 기능과 구현상 겹칠 수 있음.

### Ⅴ. 한계와 대응

| 한계 | 대응 |
|---|---|
| 모호하거나 상충하는 의도 명세 | 목표·범위·우선순위·예외를 명시하고 적용 전 검토 |
| 장비 기능과 의도 사이 변환 오류 | 지원 능력·구성 결과를 사전 검증하고 변경 이력 보존 |
| 관측 데이터 부족으로 의도 준수 확인 곤란 | 서비스 지표·텔레메트리 범위와 측정 품질 확보 |
| 자동 조정이 장애를 확대할 가능성 | 승인 수준·롤백 조건·안전한 변경 범위 설정 |

### Ⅵ. 기술사적 제언

| 우선 적용 | 운영 설계 |
|---|---|
| 의도 자동화 범위는 검증 가능한 목표부터 단계 적용 | 관측 지표·권한·변경 승인·롤백 기준을 의도 명세와 함께 관리 |
