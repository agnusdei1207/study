## 지식 로드맵 내 현재 위치

지식 위치: 네트워크 → 데이터 통신 → **전송 오류 검출·복구**

## 30초 인출

- 본질: **오류제어** : 전송 중 손상되거나 손실된 데이터를 검출하고 정정 또는 재전송으로 복구하는 체계
- 메커니즘: 검사 정보로 오류 판정 → **FEC** 수신 측 정정, **ARQ** 확인 응답·시간 초과 기반 재전송
- 통찰: 전송 선로의 잡음과 왜곡으로 인한 비트 변조를 방지하기 위해 단방향 저지연 환경에는 FEC를, 양방향 대화형 고신뢰 환경에는 ARQ 기반 BEC를 적용하거나 채널 상태에 따라 HARQ로 동적 절충하는 것이 필수적임.

<details>
<summary>핵심 용어</summary>

- **오류제어(Error Control)** : 전송 중 발생한 데이터 오류·손실을 검출하고 복구하는 체계
- **CRC(Cyclic Redundancy Check)** : 다항식 연산으로 만든 검사값을 비교해 오류를 검출하는 기법
- **FEC(Forward Error Correction)** : 추가 부호를 전송해 수신 측에서 일정 범위의 오류를 정정하는 기법
- **ARQ(Automatic Repeat reQuest)** : 수신 확인과 시간 초과 등을 근거로 전송 데이터를 다시 보내는 기법
- **ACK(Acknowledgement)** : 데이터 수신 상태를 송신 측에 알리는 확인 응답
- **RTT(Round-Trip Time)** : 송신 측에서 보낸 신호가 수신 측을 거쳐 응답으로 돌아오는 왕복 시간
- **Go-Back-N ARQ** : 오류나 손실이 난 프레임부터 이후 송신분까지 다시 보내는 방식
- **Selective Repeat ARQ** : 손실·오류가 있는 프레임을 선택해 다시 보내는 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. 에러 제어(Error Control)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 통신 채널 상의 감쇠, 왜곡, 잡음 등으로 인해 수신된 데이터에 발생한 비트 왜곡 및 패킷 손실을 검출(Detection)하고 정정(Correction)하여 전송 신뢰성을 보장하는 통신 제어 기법 |
| 목적 | 데이터 무결성 보장, 오류 프레임 전파 방지 및 채널 대역폭 대비 전송 처리율(Throughput) 최적화 |

## Ⅱ. 에러 제어(Error Control)의 특징

| 특징 | 상세 내용 |
|---|---|
| 잉여 비트(Redundancy) | 순수 데이터에 부가적인 검사 비트(Parity, CRC, 부호어)를 추가하여 오류 판정 근거 확보 |
| 순방향 오류 정정(FEC) | 수신측이 자체적으로 오류 위치를 식별하고 비트를 반전 정정하여 역방향 피드백 불필요 |
| 후방향 오류 정정(BEC) | 오류 검출 시 송신측에 재전송(ARQ)을 요청하여 신뢰성을 확보하는 양방향 대화형 메커니즘 |
| 하이브리드 결합(HARQ)| FEC와 ARQ를 융합하여 채널 품질에 따라 정정 불능 시에만 재전송을 요청하는 현대 이동통신 표준 |

## Ⅲ. 에러 제어(Error Control)의 체계·프로세스

**에러 제어 기술 분류 체계 및 처리 메커니즘**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ 에러 제어 기법 분류 ]                         │
│                                                                        │
│   ┌───────────────────────────────┴───────────────────────────────┐     │
│   ▼                                                               ▼     │
│ [ 에러 검출 (Error Detection) ]                 [ 에러 정정 (Error Correction) ] │
│   ├─ 패리티 검사 (Parity Check)                   ├─ 전진 에러 정정 (FEC)        │
│   │  - 1비트 검출, 홀수/짝수 패리티              │  - 재전송 불필요, 잉여율 큼 │
│   ├─ 체크섬 (Checksum)                           │  - Hamming Code, BCH, LDPC  │
│   │  - 16비트 합산 후 1의 보수 계산              ├─ 후진 에러 정정 (BEC / ARQ) │
│   └─ 순환 중복 검사 (CRC)                        │  - 재전송 기반 오류 복구    │
│      - 생성 다항식 기반 2진 모듈로 2 나눗셈      │  - Stop-and-Wait, GBN, SR   │
│                                                  └─ 결합 방식 (HARQ)           │
│                                                     - Type I (FEC + ARQ)       │
│                                                     - Type II/III (Chase/IR)   │
└────────────────────────────────────────────────────────────────────────┘
```

| 기법 구분 | 대표 기술 | 동작 원리 및 특성 |
|---|---|---|
| **패리티 검사** | Odd/Even Parity | 데이터 끝에 1비트 추가하여 '1'의 개수를 짝/홀수로 유지. 2비트 짝수 오류 검출 불가 |
| **체크섬** | IP/TCP/UDP Checksum | 16비트 워드 단위 합산 후 오버플로를 더하고 1의 보수화. 프로토콜 헤더 오류 검증 |
| **CRC** | CRC-32, CRC-CCITT | 생성 다항식(Generator Polynomial)을 모듈로-2 나눗셈 연산하여 나머지를 FCS로 전송 |
| **해밍 코드** | Hamming (7,4) | 2^p >= m + p + 1 공식 만족하는 검사 비트를 특정 비트 위치에 삽입하여 1비트 정정 |

## Ⅳ. 에러 제어(Error Control)의 종류·비교

| 비교 항목 | 전진 에러 정정 (FEC) | 후진 에러 정정 (BEC / ARQ) | 하이브리드 ARQ (HARQ) |
|---|---|---|---|
| **재전송 요구** | 재전송 불필요 (단방향) | 수신측 NAK/타임아웃 기반 재전송 | 복호 실패 시에만 재전송 요청 |
| **지연 특성** | 실시간 저지연 (우수) | 왕복 지연시간(RTT) 발생 | 평균 지연 시간 양호 |
| **대역폭 오버헤드**| 부호화 잉여 비트로 오버헤드 높음| 오류 없을 시 오버헤드 극소 | 채널 상태 적응형 오버헤드 |
| **적용 영역** | 위성 통신, 실시간 멀티미디어, 심우주 통신| TCP 계층, HDLC 데이터링크 계층 | 4G LTE, 5G NR, Wi-Fi 6/7 물리 계층 |

## Ⅴ. 에러 제어(Error Control)의 한계와 방안

| 한계 | 방안 |
|---|---|
| 무선 채널 페이딩 및 버스트(Burst) 오류 발생 시 단일 비트 FEC 정정 한계 초과 | 인터리빙(Interleaving) 기법을 병행하여 연집 오류를 랜덤 비트 단일 오류로 분산 |
| 고속 통신망에서 단순 ARQ 재전송 시 대기 지연 누적으로 인한 네트워크 처리율 급감 | 슬라이딩 윈도우 기반 Selective Repeat ARQ 및 버퍼 결합형 HARQ-IR(Incremental Redundancy) 적용 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
대용량 트래픽을 처리하는 차세대 네트워크 인프라 설계 시, 무선 링크는 LDPC/Polar 부호 기반 FEC와 HARQ를 L1/L2에 배치하고, L4 종단 간에는 패킷 손실에 대해 BBR/CUBIC 알고리즘 기반 TCP ARQ를 분리 적용하는 다계층 방어 전략 수립.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 이동통신 HARQ 결합 복호화 메커니즘 (Chase Combining vs IR) ]         │
│                                                                        │
│   Tx ──► [ 패킷 전송 (Data + FEC) ] ──► 무선 채널 (잡음 왜곡 발생)      │
│                                                    │                   │
│   Rx ◄── [ 복호화 실패 (CRC Error) ] ◄─────────────┘                   │
│   │                                                                    │
│   ├─► 수신 버퍼에 실패 패킷 임시 보관 (Drop하지 않음)                  │
│   └─► 송신측에 NAK 신호 전송                                          │
│                                                                        │
│   Tx ──► [ 재전송 패킷 송신 ]                                          │
│            - Chase Combining : 동일 비트 재전송 (SNR 이득 합성)        │
│            - Incremental Redundancy : 추가 잉여 패리티 비트만 전송     │
│                                                                        │
│   Rx ──► [ 버퍼 내 기존 데이터 + 재전송 데이터 결합(Soft Combining) ] │
│            └──► 복호 성공 (CRC OK -> ACK 회신)                         │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 채널 환경 | 권장 에러 제어 방식 | 선정 근거 |
|---|---|---|
| **심우주 / 위성 통신 (고지연 단방향)** | 강력한 FEC (Turbo Code, LDPC) | 수 초~수 분에 달하는 RTT로 인해 ARQ 재전송 불가 |
| **LAN 유선 통신 (저지연 저오류)** | 에러 검출 (CRC) + TCP ARQ | 물리 선로 오류율이 매우 낮아 에러 발생 시에만 재전송이 효율적 |
| **5G/6G 초고속 이동통신 (동적 페이딩)** | HARQ-IR + Polar/LDPC | 채널 상태 변동에 따라 부호율을 적응적으로 조정하여 무선 자원 극대화 |

## 출제 이력과 검증 출처

- 3GPP TS 38.212: NR Multiplexing and Channel Coding (LDPC & Polar Codes)
