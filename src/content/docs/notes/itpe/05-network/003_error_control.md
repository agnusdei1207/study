## 연관 키워드

- 오류제어, 오류검출, 오류정정, ARQ(Automatic Repeat reQuest)
- FEC(Forward Error Correction), CRC(Cyclic Redundancy Check), Stop-and-Wait, Go-Back-N, Selective Repeat

## Ⅰ. 오류제어의 개요

- 핵심 요약 : 오류제어는 전송 중 손상·손실된 데이터를 검출하고 재전송하거나 정정해 신뢰성 있는 전달을 보장하는 통신 기능.
- 개념 : 송수신기가 오류검출 부호·확인응답·타임아웃·재전송·정정 부호를 조합해 데이터 단위의 전달 오류를 처리하는 절차.
- 배경 및 필요성 : 잡음·간섭·충돌·혼잡과 장비 오류로 비트 손상이나 프레임 손실이 발생해 응용 데이터의 정확성과 순서 보장이 필요.
- 주요 목적 : 오류가 있는 전달을 검출·복구하고 신뢰도, 지연, 처리량 사이의 균형 확보.

## Ⅱ. 오류제어의 특징 및 장점

- 핵심 요약 : 오류검출은 손상 여부를 찾고, ARQ는 재전송으로 복구하며, FEC는 여분 비트로 수신 측에서 오류를 정정.

1. 오류검출 : 패리티·체크섬·CRC로 수신 데이터의 오류를 식별 → 손상 데이터의 상위 계층 전달 방지.
2. ARQ : ACK/NACK와 타임아웃을 이용해 재전송 → 낮은 오류율 환경에서 부호 오버헤드를 줄이면서 신뢰성 확보.
3. FEC : 해밍·컨볼루션·LDPC 등 정정 부호로 여분 정보를 전송 → 재전송이 어려운 무선·실시간 링크의 복구 가능.
4. 적응 결합 : HARQ(Hybrid ARQ)가 재전송과 FEC를 결합 → 채널 상태에 따라 오류 복구와 처리량 절충.

## Ⅲ. 오류제어의 구조 (흐름)

- 핵심 요약 : 송신 측 부호화·순번 부여 후 수신 측 검증 결과에 따라 수락, 정정, 재전송을 결정.

```text
데이터 분할·순번 부여
        ↓
검출/정정용 중복정보 추가
        ↓
프레임 전송
        ↓
수신 검증 ─ 오류 없음 → ACK·상위계층 전달
        └ 오류/손실 → NACK 또는 타임아웃
                         ↓
                   재전송·정정
```

```text
ARQ: 검출 → ACK/NACK·타이머 → 재전송
FEC: 부호화 → 오류검출·정정 → 재전송 생략 가능
HARQ: FEC 복호 실패 → 재전송 결합 → 재복호
```

## Ⅳ. 오류제어 방식의 비교

- 핵심 요약 : ARQ는 재전송 가능한 링크에 적합하고, FEC는 왕복지연·재전송 비용이 큰 링크에 유리하며, HARQ는 두 방식의 절충.

| 비교 기준 | ARQ | FEC | HARQ |
| --- | --- | --- | --- |
| 복구 방법 | 검출 후 재전송 | 여분 부호로 수신 측 정정 | FEC 복호와 선택적 재전송 결합 |
| 대역폭 비용 | 재전송 시 추가 전송 | 항상 부호 오버헤드 발생 | 부호 오버헤드와 제한 재전송 |
| 지연 특성 | 왕복 응답·타임아웃에 좌우 | 재전송 왕복 없이 처리 가능 | 재전송 횟수·결합 방식에 좌우 |
| 적용 예 | 유선 데이터링크·파일전송 | 위성·방송·실시간 무선 링크 | 이동통신 무선 접속 |

## Ⅴ. 오류제어의 한계와 방안

- 핵심 요약 : 과도한 재전송과 부호 오버헤드가 지연·처리량을 낮추므로 채널 오류율과 서비스 요구에 맞춰 방식을 선택.

| 위험 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 재전송 폭증 | 손실·간섭·혼잡으로 유효 처리량 감소 | 재전송 한도·혼잡제어·채널 적응 적용 | 재전송률·Goodput |
| 지연 증가 | ACK 대기·타임아웃·재전송 반복 | RTT·타이머 조정, 지연민감 트래픽에 FEC 검토 | 왕복지연·복구지연 |
| 부호 오버헤드 | 강한 FEC로 유효 페이로드 감소 | 목표 BER·SNR과 지연 예산에 맞춰 부호율 조정 | 유효 전송률·오류율 |
| 순서·중복 오류 | 재전송 프레임의 지연·중복 수신 | 순번·중복제거·재정렬 버퍼 관리 | 중복 프레임·재정렬 대기 |

## Ⅵ. 오류제어 설계에 대한 기술사적 제언

- 핵심 요약 : 네트워크 설계자는 링크 특성과 애플리케이션 지연 허용치를 바탕으로 검출·ARQ·FEC 조합을 결정.

1. 링크 설계자 : 채널 오류율·RTT·대역폭을 측정하고 유선·무선·위성 링크별 복구 방식을 구분.
2. 프로토콜 운영자 : 재전송 한도·타이머·순번공간을 튜닝하고 혼잡제어와 중복제거 동작을 검증.
3. 서비스 책임자 : 파일전송·음성·영상 등 서비스별 손실·지연 목표를 정하고 성능시험에서 Goodput과 체감품질을 함께 평가.

## Ⅶ. 결론

- 핵심 요약 : 오류제어는 검출·정정·재전송을 조합해 전송 신뢰성과 지연·대역폭 효율을 균형화하는 통신 기능.
- 시사점 : 단일 방식의 일괄 적용보다 채널 품질과 서비스 지연 요구에 맞춘 적응형 조합이 효과적.
