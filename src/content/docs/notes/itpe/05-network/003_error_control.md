## 연관 키워드

- 오류제어(Error Control), 오류 검출(Error Detection), 오류 정정(Error Correction)
- ARQ(Automatic Repeat Request), FEC(Forward Error Correction), HARQ(Hybrid ARQ), CRC(Cyclic Redundancy Check)
- 인터리빙(Interleaving), 적응형 변조 및 코딩(AMC), 비트 오류율(BER), 정정 전 BER(Pre-FEC BER)

## Ⅰ. 오류제어(Error Control)의 개요

- 핵심 요약 : 채널에서 생긴 비트 오류를 검출하거나 정정하여 신뢰성 있는 전송을 보장하는 전송 제어 기술.
- 개념 : 통신 채널의 감쇠, 잡음, 간섭으로 송신 비트열이 왜곡되었을 때, 수신단에서 **오류 검출** (Error Detection, 오류 존재 여부 확인)하거나 **오류 정정** (Error Correction, 오류 위치를 찾아 바로잡음)하는 전송 제어 기술.
- 배경 및 필요성 : 통신 매체가 불완전하여 왜곡이 생기면 상위 계층 데이터가 오염되고 파일이 파손되며 전체 재전송 부담이 커지므로, 물리·데이터링크·전송 계층 전반의 신뢰성 보장이 필요.
- 주요 목적 : 무손실 무결성 전송 달성, 잔여 **비트 오류율** (BER, Bit Error Rate) 최소화, 채널 환경에 맞는 처리량과 지연의 균형 유지.

## Ⅱ. 오류제어(Error Control)의 특징 및 장점

- 핵심 요약 : 재전송 기반의 ARQ, 자체 정정 기반의 FEC, 둘을 결합한 HARQ가 각각 정확성, 저지연, 효율이라는 장점으로 나뉨.

1. **ARQ** (Automatic Repeat Request, 자동 반복 요청) : 수신단이 오류를 검출하면 송신단에 재전송을 요구하는 방식(역방향 오류 정정, BEC(Backward Error Correction)) → 확실한 전달이 가능하나 재전송 시 왕복 지연이 생김.
2. **FEC** (Forward Error Correction, 순방향 오류 정정) : 정정용 잉여 비트를 함께 보내 수신단이 역채널 없이 오류를 스스로 고침 → 왕복 지연이 없어 실시간 전송과 단방향 방송에 적합.
3. **HARQ** (Hybrid ARQ, 하이브리드 자동 반복 요청) : FEC 복호에 실패한 패킷을 버리지 않고 재전송 패킷과 결합 → 재전송 횟수를 줄여 무선 링크의 효율을 높임.
4. **CRC** (Cyclic Redundancy Check, 순환 중복 검사) : 생성 다항식으로 나눈 나머지를 프레임에 실어 보내 수신단이 같은 연산으로 검증 → 버스트 오류 검출에 강하며 이더넷 프레임 검사에 쓰임.

## Ⅲ. 오류제어(Error Control)의 구조 (흐름)

- 핵심 요약 : 오류는 먼저 검출되고, 정정은 재전송과 자체 정정 중 채널 조건에 맞는 방식으로 선택되는 구조.

```text
[ 오류 제어 분류 ]

오류 제어
   ↓
검출 (패리티, 체크섬, CRC)
   ↓
정정 방식 선택
   ↓                    ↓
재전송 (ARQ)      자체 정정 (FEC)
```

- ARQ 방식은 Stop-and-Wait, Go-Back-N(GBN), Selective Repeat(SR)로 나뉘며, 재전송 범위와 버퍼 요구량이 서로 다름.
- FEC 방식은 블록 부호(Hamming, Reed-Solomon)와 합성 부호(Turbo, LDPC(Low-Density Parity-Check), Polar)로 나뉘며, 잉여 비트를 많이 줄수록 정정 능력이 커지고 전송 효율은 떨어짐.

```text
[ HARQ 처리 흐름 ]

수신 패킷 (FEC 복호 시도)
   ↓ 복호 실패
버퍼에 보관 (폐기하지 않음)
   ↓ 재전송 패킷 수신
소프트 결합 (Chase 결합 또는 증분 잉여)
   ↓
복호 성공률 향상
```

## Ⅳ. 오류제어(Error Control) 방식의 비교

- 핵심 요약 : ARQ는 재전송으로 정확도를 얻고, FEC는 지연 없는 자체 정정을 얻으며, HARQ는 두 장점을 절충하는 방식.

| 비교 축 | ARQ | FEC | HARQ |
| --- | --- | --- | --- |
| 정정 주체 | 송신단 (재전송으로 정정) | 수신단 (자체 연산으로 정정) | 수신단 연산과 송신단 재전송 결합 |
| 역방향 채널 | 필요 (ACK(Acknowledgment)·NAK 신호) | 불필요 (단방향 전송 가능) | 필요 (물리 계층 빠른 피드백) |
| 전송 지연 | 재전송에 따른 RTT(Round-Trip Time) 왕복 지연 | 추가 왕복 없음 | 재전송이 빨라 지연 최소화 |
| 대역폭 부담 | 오류 발생 시에만 재전송 트래픽 소비 | 항상 잉여 비트를 보내 유효 전송률 저하 | 초기 잉여를 최소로 두고 필요할 때 추가 |
| 주요 적용 분야 | 유선 인터넷의 TCP(Transmission Control Protocol), 파일 전송 | 위성 통신, 광전송망 OTN(Optical Transport Network) | 4G LTE(Long-Term Evolution), 5G NR(New Radio) 무선 링크 |

- 선택 기준 : 통신 지연이 길거나 역채널이 없는 위성·심우주 통신은 FEC가 적합하고, 채널 상태가 자주 변하는 무선망은 HARQ가 스펙트럼 효율을 보장하는 데 유리함.

## Ⅴ. 오류제어(Error Control)의 한계와 방안

- 핵심 요약 : 잉여 비트로 인한 전송률 저하, 버스트 오류, 고속 복호기의 복잡도가 주요 한계이며, 적응형 부호율, 인터리빙, 하드웨어 가속으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 유효 전송률(Goodput) 저하 | 채널이 양호한데도 낮은 부호율을 쓰면 잉여 비트만큼 대역폭이 낭비됨 | 채널 품질 지시자(CQI, Channel Quality Indicator)에 따라 변조 방식과 부호율을 바꾸는 적응형 변조 및 코딩(AMC, Adaptive Modulation and Coding) 적용 | 유효 전송률, 재전송률 |
| 버스트 오류에 대한 블록 부호 한계 | 연속된 비트가 한꺼번에 손상되면 BCH(Bose-Chaudhuri-Hocquenghem) 같은 단일 정정 부호의 정정 능력을 넘어섬 | 인터리빙으로 연속 비트를 시간·주파수 축에 분산 배치하여 버스트 오류를 랜덤 오류로 바꿈 | 블록 오류율 |
| 초고속 전송의 복호기 복잡도와 발열 | 400Gbps급 전송에서 LDPC(Low-Density Parity-Check)와 연판정 복호의 반복 연산으로 지연과 전력 소비가 급증 | 파이프라인 하드웨어 가속 엔진을 탑재하고, 전송 규격에 맞는 RS-FEC(KR4, KP4 등) 부호를 선택 | 복호 지연 시간, 소비 전력 |

## Ⅵ. 오류제어(Error Control)의 기술사적 제언

- 핵심 요약 : 신경망 복호, 예측형 광전송 감시, 계층 간 튜닝을 결합하여 오류 제어를 사후 대응에서 예측 운영으로 전환하는 방향.

1. 차세대 이동통신 연구 조직은 수치 해석 기반 복호기를 AI(Artificial Intelligence) 기반 신경망 디코더로 대체하는 방안을 검증하여, 6G 수준의 극초저지연 요구를 맞출 복호 연산량을 줄여야 한다.
2. 광전송망 운영 조직은 정정 전 BER(Pre-FEC BER) 추이를 상시 수집하여 회선 열화를 장애 이전에 감지하고, 필요하면 트래픽을 미리 우회시키는 예방 정비 체계를 갖춰야 한다.
3. 무선 네트워크 설계 조직은 무선 계층의 HARQ와 전송 계층의 TCP 재전송 타이머가 서로 중복 재전송을 일으키지 않도록 계층 간 상호작용을 함께 튜닝하는 절차를 두어야 한다.

## Ⅶ. 결론

- 핵심 요약 : 오류 제어는 검출, 재전송, 자체 정정을 채널 조건에 맞춰 조합하는 전송 신뢰성 기술임.
- 시사점 : 지연과 대역폭의 상충 관계를 채널 상태에 따라 조정하는 적응형 제어가 신뢰성과 효율을 함께 확보하는 방향임.
