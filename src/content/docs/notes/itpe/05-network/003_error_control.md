## 연관 키워드

- 오류제어(Error Control), 오류 검출(Error Detection), 오류 정정(Error Correction), 비트 오류율(BER, Bit Error Rate)
- ARQ(Automatic Repeat Request), FEC(Forward Error Correction), HARQ(Hybrid ARQ)
- 패리티 검사(Parity Check), 체크섬(Checksum), CRC(Cyclic Redundancy Check), 인터리빙(Interleaving), 적응형 변조 및 코딩(AMC)

## Ⅰ. 오류제어(Error Control)의 개요

- 핵심 요약 : 전송 중 왜곡된 비트 오류를 검출하고 정정해 종단 간 데이터 무결성을 보장하는 전송 제어 기술의 총칭.
- 개념 : 통신 채널의 감쇠, 잡음, 간섭으로 송신 비트열이 왜곡될 때 오류의 존재를 확인하는 **오류 검출** (Error Detection)과 오류를 바로잡는 **오류 정정** (Error Correction)을 수행하는 기술 체계 (**오류제어**, Error Control).
- 배경 및 필요성 : 어떤 전송 매체도 완전하지 않아 임의 위치의 랜덤 오류와 연속 구간이 한꺼번에 손상되는 버스트 오류가 발생하고, 이를 통제하지 않으면 상위 계층 데이터 오염과 반복 재전송으로 신뢰성과 효율이 모두 저하됨.
- 주요 목적 : 데이터 무결성 보장, 잔여 **비트 오류율** (BER, Bit Error Rate) 최소화, 채널 조건에 맞는 처리량과 지연의 균형 확보.

## Ⅱ. 오류제어(Error Control)의 특징 및 장점

- 핵심 요약 : 재전송 기반 ARQ, 자체 정정 기반 FEC, 두 방식의 결합인 HARQ가 정확성·저지연·효율이라는 상보적 장점을 구성.

1. ARQ 기반 신뢰성 : 수신단이 오류를 검출하면 송신단에 재전송을 요구하는 **ARQ** (Automatic Repeat Request, 자동 반복 요청) 방식 → 확실한 무오류 전달이 가능하나 재전송 시 왕복 지연 비용 발생.
2. FEC 기반 저지연 : 정정용 잉여 비트를 함께 전송해 수신단이 역방향 채널 없이 스스로 고치는 **FEC** (Forward Error Correction, 순방향 오류 정정) 방식 → 왕복 지연이 없어 실시간·단방향 전송에 적합.
3. HARQ 기반 효율 : FEC 복호에 실패한 패킷을 버리지 않고 재전송 패킷과 결합하는 **HARQ** (Hybrid ARQ, 하이브리드 자동 반복 요청) 방식 → 재전송 횟수 감소로 무선 링크 효율 향상.
4. 오류 유형별 설계 : 임의 위치의 랜덤 오류와 연속 구간의 버스트 오류를 구분해 부호와 **인터리빙** (Interleaving, 비트 전송 순서 재배치)을 선택 → 채널 특성에 맞는 정정 능력 확보.

## Ⅲ. 오류제어(Error Control)의 구조 (흐름)

- 핵심 요약 : 검출 부호가 오류의 존재를 확인하고, 정정은 재전송(ARQ)과 자체 정정(FEC) 중 채널 조건에 맞는 방식으로 선택되는 분류 구조.
- 검출 기법의 3계열:
  1. 패리티 검사(Parity Check) : 비트열에 1비트를 추가해 1의 개수를 홀·짝으로 맞추는 가장 단순한 검출.
  2. 체크섬(Checksum) : 데이터를 고정 길이 단어로 더한 보수를 검사 필드에 실어 헤더 오류를 검출.
  3. **CRC** (Cyclic Redundancy Check, 순환 중복 검사) : 생성 다항식 나눗셈의 나머지를 검사 필드로 사용하며 버스트 오류 검출에 강함.
- ARQ의 3유형 : 정지 대기(Stop-and-Wait), Go-Back-N, Selective Repeat로 나뉘며 재전송 범위와 수신 버퍼 요구량이 서로 상이함.
- FEC 부호의 계열 : 해밍·리드-솔로몬 같은 블록 부호와 컨볼루션 부호, 터보·LDPC(Low-Density Parity-Check)·Polar 같은 근대 부호로 분류됨.

```text
[ 오류제어 처리 흐름 ]

송신단 : 잉여 비트 첨부 전송
    ↓ 채널의 왜곡·잡음
수신단 : 오류 검출 수행
    ↓ 오류 발견 시
정정 방식 선택
  1. ARQ : 재전송 요구
  2. FEC : 자체 정정
    ↓
정상 프레임의 상위 계층 전달
```

```text
[ HARQ 결합 복호 흐름 ]

FEC 복호 시도
    ↓ 복호 실패
패킷을 버퍼에 보관
    ↓ 재전송 패킷 수신
소프트 결합 후 재복호
    ↓
복호 성공률 향상
```

## Ⅳ. 오류제어(Error Control) 방식의 비교

- 핵심 요약 : ARQ는 재전송으로 정확도를 얻고, FEC는 지연 없는 자체 정정을 얻으며, HARQ는 두 장점을 절충하는 방식.

| 비교 축 | ARQ | FEC | HARQ |
| --- | --- | --- | --- |
| 정정 주체 | 송신단 (재전송으로 정정) | 수신단 (자체 연산으로 정정) | 수신단 연산과 송신단 재전송의 결합 |
| 역방향 채널 | 필요 (ACK·NAK 신호) | 불필요 (단방향 전송 가능) | 필요 (물리 계층의 빠른 피드백) |
| 전송 지연 | 재전송에 따른 RTT(Round-Trip Time) 왕복 지연 | 추가 왕복 없음 | 빠른 재전송으로 지연 최소화 |
| 대역폭 부담 | 오류 발생 시에만 재전송 트래픽 소비 | 항상 잉여 비트를 전송해 유효 전송률 저하 | 초기 잉여를 최소로 두고 필요 시 추가 |
| 주요 적용 분야 | 유선 인터넷의 TCP(Transmission Control Protocol), 파일 전송 | 위성 통신, 광전송망 | 이동통신 무선 링크 (4G·5G) |

- 선택 기준 : 지연이 길거나 역채널이 없는 위성·심우주 통신은 FEC가, 채널 상태가 자주 변하는 무선망은 HARQ가, 확실한 무결성이 우선인 유선 전송은 ARQ가 적합함.

## Ⅴ. 오류제어(Error Control)의 한계와 방안

- 핵심 요약 : 잉여 비트로 인한 전송률 저하, 버스트 오류, 복호 복잡도가 주요 한계이며 적응형 부호율, 인터리빙, 하드웨어 가속으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 유효 전송률 저하 | 채널이 양호한데도 낮은 부호율을 고정 사용하면 잉여 비트만큼 대역폭 낭비 | **적응형 변조 및 코딩** (AMC, Adaptive Modulation and Coding)으로 채널 품질에 따라 변조·부호율 조정 | 유효 전송률, 재전송률 |
| 버스트 오류의 정정 한계 | 연속 비트 손상이 단일 부호의 정정 능력을 초과 | 인터리빙으로 연속 비트를 시간·주파수 축에 분산해 랜덤 오류로 변환 후 정정 | 블록 오류율 |
| 고속 전송의 복호 부담 | 초고속 링크에서 반복 복호 연산이 지연과 전력 소비를 증가 | 부호 형태의 규격별 선택과 파이프라인 하드웨어 가속 엔진 적용 | 복호 지연 시간, 소비 전력 |

## Ⅵ. 오류제어(Error Control)에 대한 기술사적 제언

- 핵심 요약 : 계층 간 협력 설계, 예방 정비, 신뢰성 검증 체계를 결합해 오류 제어를 사후 대응이 아닌 예측 운영으로 전환하는 방향.

1. 무선 설계 조직은 링크 계층의 HARQ 재전송과 전송 계층의 재전송 타이머가 중복 동작하지 않도록 계층 간 상호작용을 함께 튜닝하는 크로스 레이어 설계 기준을 수립해야 한다.
2. 광전송망 운영 조직은 정정 전 BER(Pre-FEC BER) 추이를 상시 수집해 회선 열화를 장애 이전에 감지하고, 트래픽 우회를 포함한 예방 정비 체계를 갖춰야 한다.
3. 품질·표준 관리 조직은 서비스 클래스별 목표 BER과 부호 프로파일을 정의한 신뢰성 시험 인증 절차를 운영해 장비·망 도입 시 오류 제어 성능을 객관 검증해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 오류 제어는 검출, 재전송, 자체 정정을 채널 조건에 맞춰 조합하는 전송 신뢰성 기술임.
- 시사점 : 지연과 대역폭의 상충 관계를 채널 상태에 따라 조정하는 적응형 제어가 신뢰성과 효율을 함께 확보하는 방향임.
