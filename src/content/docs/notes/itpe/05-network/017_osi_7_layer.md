## 30초 인출

- 본질: **OSI 7계층** : 네트워크 통신 기능을 일곱 계층의 책임으로 나누어 설명하는 참조 모델
- 메커니즘: 각 계층이 위 계층에 서비스를 제공하고, 송신·수신 과정에서 계층별 제어 정보를 붙이거나 해석

<details>
<summary>핵심 용어</summary>

- **OSI(Open Systems Interconnection) 7계층** : ISO/IEC 7498-1이 정의한 통신 시스템의 기능 분리 참조 모델
- **계층(Layer)** : 특정 통신 기능의 책임과 인접 계층 간 서비스 관계를 구분한 단위
- **PDU(Protocol Data Unit)** : 한 계층에서 교환하는 제어 정보와 사용자 데이터를 포함한 데이터 단위
- **캡슐화(Encapsulation)** : 하위 계층으로 내려가며 필요한 제어 정보를 데이터에 추가하는 과정
- **역캡슐화(Decapsulation)** : 수신 측에서 계층별 제어 정보를 해석·제거하는 과정
- **TCP/IP(Transmission Control Protocol/Internet Protocol)** : 인터넷 통신의 핵심 프로토콜 집합

</details>

### Ⅱ. 계층 구조

```text

  │

  │

  │

  │

  │
1 물리 ── 비트 신호
```

## 2~4교시 25점 답안

## Ⅰ. OSI 7계층의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **OSI 7계층** : 통신 기능을 일곱 계층의 책임으로 분리한 참조 모델 |
| 목적 | 통신 기능의 역할 구분과 이기종 시스템의 상호운용 기준 마련 |

## Ⅱ. 일곱 계층의 책임

```text
7 응용 ── 사용자 서비스
  │
6 표현 ── 데이터 표현·변환
  │
5 세션 ── 대화·동기화
  │
4 전송 ── 종단 간 데이터 전달
  │
3 네트워크 ── 논리 주소·경로
  │
2 데이터링크 ── 인접 노드 간 프레임
  │
1 물리 ── 매체의 비트 신호
```

상위 계층은 아래 계층이 제공하는 서비스를 이용. 실제 인터넷 프로토콜이 언제나 OSI의 한 계층에 일대일로 대응하는 것은 아님.

## Ⅲ. 캡슐화와 역캡슐화

```text
송신: 응용 데이터
  ↓ 전송 계층 제어 정보 추가
세그먼트
  ↓ 네트워크 계층 제어 정보 추가
패킷
  ↓ 링크 계층 제어 정보 추가
프레임 → 비트 신호

수신: 계층별 제어 정보 해석·제거 ↑
```

계층별 **PDU** 이름은 대표 예시이며 프로토콜마다 세부 단위가 다를 수 있음.

## Ⅳ. TCP/IP와의 관계

| OSI 관점 | 인터넷 통신의 대응 관점 | 주의점 |
|---|---|---|
| 응용·표현·세션 | 응용 프로토콜과 관련 기능 | 세 계층을 물리적으로 합쳤다는 의미 아님 |
| 전송 | TCP·UDP 등 | 신뢰성 제공은 프로토콜별 차이 |
| 네트워크 | IP 계층 | 경로·주소 역할 |
| 데이터링크·물리 | 링크 기술 | 매체·프레임 방식별 차이 |

**OSI**는 기능을 설명하는 참조 모델이며 인터넷 구현 전체가 OSI 규격을 그대로 따른다는 뜻은 아님.

## Ⅴ. 장애 범위 축소

| 관측 증상 | 먼저 확인할 기능 | 예 |
|---|---|---|
| 링크 자체 연결 실패 | 물리·데이터링크 | 신호·포트·프레임 오류 |
| 목적지까지 경로 실패 | 네트워크 | 주소·경로·필터 |
| 연결·재전송 문제 | 전송 | 포트·TCP 상태 |
| 요청 응답 오류 | 응용 | DNS·HTTP·서비스 상태 |

계층만 보고 원인을 단정하지 않고, 관측 지점에서 실제 패킷·로그를 확인.

## Ⅵ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| “L3 장애”처럼 계층명만으로 원인을 단정 | 물리 연결에서 응용 응답까지 관측값을 순서대로 확인해 실패 구간 특정 |
