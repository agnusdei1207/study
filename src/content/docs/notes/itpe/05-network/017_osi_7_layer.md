## 연관 키워드

- OSI 7계층(Open Systems Interconnection), ISO(International Organization for Standardization), 캡슐화(Encapsulation), 역캡슐화(Decapsulation)
- 물리 계층, 데이터링크 계층, 네트워크 계층, 전송 계층, 세션 계층, 표현 계층, 응용 계층
- TCP/IP(Transmission Control Protocol/Internet Protocol), 제로 카피(Zero-Copy), 크로스 레이어(Cross-Layer), 심층 방어(Defense-in-Depth)

## Ⅰ. OSI 7계층 참조 모델의 개요

- 핵심 요약 : 통신 기능을 7개 계층으로 분할·표준화한 참조 모델로, 이기종 시스템 간 상호 접속의 기준 틀.
- 개념 : 국제표준화기구(ISO, International Organization for Standardization)가 제정한 **개방형 시스템 상호 연결** (OSI, Open Systems Interconnection) 참조 모델은 통신 과정을 물리 계층부터 응용 계층까지 7단계로 나눈 개념 표준.
- 배경 및 필요성 : 제조사마다 독자 프로토콜 체계를 사용하던 환경에서는 이기종 장비 간 접속이 막혔으므로, 제조사와 무관한 공통 참조 기준이 필요했음.
- 주요 목적 : 계층별 기능 분리를 통한 상호 운용성 확보와 한 계층의 기술 변경이 타 계층에 미치는 영향 최소화.

## Ⅱ. OSI 7계층 참조 모델의 특징 및 장점

- 핵심 요약 : 계층 분할과 캡슐화 구조가 기술 독립성과 장애 격리라는 장점으로 이어지는 참조 체계.

1. 데이터 단위 형성 : 송신 측 **캡슐화** (Encapsulation, 상위 데이터에 계층별 헤더 부착 과정)와 수신 측 **역캡슐화** (Decapsulation, 헤더를 계층 순으로 벗기는 과정) → 해석 책임이 계층별로 분담.
2. 대등 구조 : 각 계층 프로토콜이 상대 노드의 동일 계층과 **대등 통신** (Peer-to-Peer, 동일 계층 간 논리 통신)을 수행 → 계층 단위의 표준 프로토콜 제정 가능.
3. 서비스 경계 규정 : 상위 계층이 하위 서비스를 이용하는 접점인 **서비스 접근점** (SAP, Service Access Point)으로 계층 경계를 정의 → 계층 간 결합의 명확성 확보.
4. 계층화(Layering) : 각 계층은 바로 아래 계층이 제공하는 서비스만 이용 → 한 계층의 내부 구현 교체가 타 계층에 영향을 주지 않는 독립성.

## Ⅲ. OSI 7계층 참조 모델의 구조 (흐름)

- 핵심 요약 : 송신 측은 상위에서 하위로 헤더를 덧붙이고, 수신 측은 하위에서 상위로 헤더를 벗기는 상반 흐름.

- **물리 계층** (Physical Layer) : 비트열을 전기·광·전파 신호로 바꿔 전송 매체로 실어 보내는 계층(리피터, 허브).
- **데이터링크 계층** (Data Link Layer) : 인접 노드 간 프레임 전송과 물리 주소(MAC, Media Access Control) 지정, 오류 검출을 담당하는 계층(스위치).
- **네트워크 계층** (Network Layer) : 논리 주소 기반의 경로 선택과 패킷 전달을 담당하는 계층(라우터).
- **전송 계층** (Transport Layer) : 종단 간 프로세스 연결과 신뢰성·흐름 제어를 담당하는 계층.
- **세션 계층** (Session Layer) : 응용 프로세스 간 대화의 수립·유지·동기화·종료를 관리하는 계층.
- **표현 계층** (Presentation Layer) : 문자 코드·압축·암호화 등 데이터 표현 형식의 변환을 담당하는 계층.
- **응용 계층** (Application Layer) : 사용자 서비스와 맞닿아 통신 인터페이스를 제공하는 최상위 계층.

```text
[ 송신 측 캡슐화 흐름 ]

7~5 응용·표현·세션 : 메시지
   ↓ 전송 계층 헤더 부착
4 전송 계층 : 세그먼트
   ↓ 네트워크 계층 헤더 부착
3 네트워크 계층 : 패킷
   ↓ 프레임 헤더·후미 부착
2 데이터링크 계층 : 프레임
   ↓ 신호 변환
1 물리 계층 : 비트 전송
```

```text
[ 수신 측 역캡슐화 흐름 ]

1 비트 신호 수신
   ↓ 프레임 재구성
2 MAC 주소 판정·오류 검출
   ↓ 패킷 헤더 제거
3 목적지 네트워크 확인
   ↓ 세그먼트 헤더 제거
4 포트 번호로 프로세스 전달
   ↓ 세션·표현 처리
7 응용 데이터 해석
```

## Ⅳ. OSI 7계층과 TCP/IP 모델의 비교

- 핵심 요약 : OSI는 기능 분류의 개념적 참조 틀이고, TCP/IP(Transmission Control Protocol/Internet Protocol)는 실제 인터넷을 구동하는 구현 중심 프로토콜군.

| 비교 축 | OSI 7계층 | TCP/IP 모델 |
| --- | --- | --- |
| 성격 | 기능 분류의 참조 틀 | 실제 동작하는 프로토콜군 |
| 계층 구성 | 하위 4개 + 상위 3개 계층 | 링크·인터넷·전송·응용 4계층 |
| 상위 계층 처리 | 세션·표현·응용 분리 | 응용 계층 통합 |
| 전송 계층 | 연결형·비연결형 개념 병존 | TCP(신뢰성)·UDP(User Datagram Protocol, 비연결형) 분담 |
| 주요 활용 | 교육·설계 검토·장애 분석 | 인터넷 표준 구동 |

- 선택 기준 : 장애 원인을 계층 단위로 귀속하는 분석과 조직 교육에는 OSI 틀을, 프로토콜 동작·구현 논의에는 TCP/IP 기준을 적용.

## Ⅴ. OSI 7계층 참조 모델의 한계와 방안

- 핵심 요약 : 상위 계층 경계의 모호성, 계층 통과 처리 부담, 계층 간 정보 단절을 단순화·오프로드·정보 공유로 통제하는 원칙.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 상위 3계층 경계 모호성 | 세션·표현 기능이 실제 응용 코드에 흡수되어 계층 구분의 실무성 저하 | 실무 아키텍처는 TCP/IP 4계층 기준으로 기술하고 암호화·직렬화는 별도 모듈로 관리 | 계층별 장애 귀속률 |
| 계층 통과 오버헤드 | 커널 스택 통과 시 버퍼 복사와 문맥 전환이 누적되어 고속 처리 병목 | **제로 카피** (Zero-Copy, 메모리 복사 최소화 기법)와 NIC(Network Interface Card) 오프로드 적용 | 패킷당 CPU 사용률 |
| 계층 간 정보 단절 | 하위 계층의 회선 품질 정보를 상위 계층이 알지 못해 전송 제어 최적화에 한계 | **크로스 레이어** (Cross-Layer, 계층 간 상태 공유 설계) 도입 | 재전송률·전송 지연 |

## Ⅵ. OSI 7계층 참조 모델에 대한 기술사적 제언

- 핵심 요약 : 계층 모델을 장애 진단 절차와 보안 통제 배치의 조직 표준으로 내재화할 필요.
- 네트워크 운영 조직 : 물리 계층부터 응용 계층까지 순차 점검하는 장애 격리 절차를 매뉴얼로 표준화하고 계층별 담당 체계를 지정.
- 보안 설계 조직 : **심층 방어** (Defense-in-Depth, 여러 계층에 통제를 겹쳐 배치하는 원칙)에 따라 링크·네트워크·응용 계층별 접근 통제를 배치하는 설계 기준 수립.
- 정보시스템 품질 조직 : 요구사항·설계서를 계층별 관점으로 검증하는 체크리스트를 감리 표준 템플릿에 반영.

## Ⅶ. 결론

- 핵심 요약 : OSI 7계층은 통신 기능을 계층으로 분해해 설계·진단·보안을 체계화하는 기준 틀.
- 실제 인터넷은 TCP/IP로 구동되지만, 계층 분리 원리는 업계 공통의 분석 언어로 유지될 가치.
