## 30초 인출

- 본질: **OSI 7계층** : 네트워크 통신 기능을 일곱 계층의 책임으로 나누어 설명하는 참조 모델
- 메커니즘: 각 계층이 위 계층에 서비스를 제공하고, 송신·수신 과정에서 계층별 제어 정보를 붙이거나 해석
- 통찰: 이기종 컴퓨터 시스템 간의 원활한 상호 접속을 위해 통신 기능을 7개 계층으로 모듈화하고 계층 간 독립성과 표준 인터페이스를 정의하여 통신 프로토콜 설계 및 장애 격리의 기준을 제공하는 참조 모델임.

<details>
<summary>핵심 용어</summary>

- **OSI(Open Systems Interconnection) 7계층** : ISO/IEC 7498-1이 정의한 통신 시스템의 기능 분리 참조 모델
- **계층(Layer)** : 특정 통신 기능의 책임과 인접 계층 간 서비스 관계를 구분한 단위
- **PDU(Protocol Data Unit)** : 한 계층에서 교환하는 제어 정보와 사용자 데이터를 포함한 데이터 단위
- **캡슐화(Encapsulation)** : 하위 계층으로 내려가며 필요한 제어 정보를 데이터에 추가하는 과정
- **역캡슐화(Decapsulation)** : 수신 측에서 계층별 제어 정보를 해석·제거하는 과정
- **TCP/IP(Transmission Control Protocol/Internet Protocol)** : 인터넷 통신의 핵심 프로토콜 집합

</details>

## 2~4교시 25점 답안

## Ⅰ. OSI 7계층 참조 모델의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | ISO(국제표준화기구)가 이기종 시스템 간의 네트워크 통신을 표준화하기 위해 통신 기능을 7개의 논리적 계층으로 분할하여 정의한 네트워크 참조 모델 |
| 목적 | 벤더 종속성 탈피, 통신 기능의 모듈화를 통한 독립적 기술 발전 보장 및 네트워크 장애 발생 시 계층별 원인 격리(Troubleshooting) 기준 제공 |

## Ⅱ. OSI 7계층 참조 모델의 특징

| 특징 | 상세 내용 |
|---|---|
| 계층적 캡슐화 | 상위 계층 데이터에 해당 계층의 고유 제어 정보(Header/Trailer)를 덧붙여 하위 계층으로 전달 |
| 계층 간 독립성 | 특정 계층의 프로토콜이나 기술 변경이 상위 또는 하위 계층의 동작에 영향을 주지 않음 |
| 서비스 접근점(SAP) | 인접 계층 간에는 SAP(Service Access Point)를 통해 서비스 요청과 응답을 정형화하여 교환 |
| 동등 계층 간 프로토콜| 송신측의 N 계층은 가상적으로 수신측의 동등한 N 계층(Peer-to-Peer)과 정의된 프로토콜로 대화 |

## Ⅲ. OSI 7계층 참조 모델의 체계·프로세스

**OSI 7계층 구조 및 데이터 캡슐화/역캡슐화 흐름**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ OSI 7계층 및 PDU 구조 ]                       │
│                                                                        │
│ 계층 (Layer)                 PDU 명칭      핵심 역할                   │
│ ────────────────────────────────────────────────────────────────────── │
│ 7. 응용 계층 (Application)    Data (메시지) 사용자 인터페이스, HTTP/DNS │
│ 6. 표현 계층 (Presentation)   Data          데이터 암호화, 압축, 인코딩 │
│ 5. 세션 계층 (Session)        Data          동기화, 세션 수립/유지/종료 │
│ 4. 전송 계층 (Transport)      Segment       종단간 신뢰성, 포트(Port)   │
│ 3. 네트워크 계층 (Network)    Packet        경로 배정(Routing), IP 주소 │
│ 2. 데이터링크 (Data Link)     Frame         인접 노드 전송, MAC, 오류검출│
│ 1. 물리 계층 (Physical)       Bit (신호)    전기/광 신호 변환, 케이블   │
│                                                                        │
│ [ 송신측 캡슐화 (Encapsulation) ]  ──►  [ 수신측 역캡슐화 (Decapsulation)]│
│  Data                                    Data                          │
│  [H4] Data                               [H4] Data                     │
│  [H3][H4] Data                           [H3][H4] Data                 │
│  [H2][H3][H4] Data [T2]                  [H2][H3][H4] Data [T2]        │
│  1 0 1 1 0 0 1 0 1 ── 물리 매체 전송 ──► 1 0 1 1 0 0 1 0 1            │
└────────────────────────────────────────────────────────────────────────┘
```

| 계층 번호 | 계층 명칭 | 프로토콜 데이터 단위 (PDU) | 핵심 기능 및 대표 프로토콜 |
|---|---|---|---|
| **Layer 7** | 응용 계층 | Data | 최종 사용자와 네트워크 간 인터페이스 제공 (HTTP, DNS, SMTP, FTP) |
| **Layer 6** | 표현 계층 | Data | 데이터 형식 변환, 구문 분석, 암호화(TLS), 압축 (JPEG, ASCII) |
| **Layer 5** | 세션 계층 | Data | 종단 호스트 간 응용 프로그램 세션 수립, 관리, 반이중/전이중 동기점 제어 |
| **Layer 4** | 전송 계층 | Segment | 종단 간(End-to-End) 투명한 데이터 전송, 흐름/혼잡 제어 (TCP, UDP) |
| **Layer 3** | 네트워크 계층| Packet | 논리 주소(IP) 기반 패킷 라우팅 및 최적 전송 경로 결정 (IP, ICMP, OSPF)|
| **Layer 2** | 데이터링크 계층| Frame | 인접 노드 간 물리 주소(MAC) 기반 프레임 전송, 흐름/에러 제어 (Ethernet)|
| **Layer 1** | 물리 계층 | Bit | 비트 스트림을 전송 매체에 적합한 전기적·광학적 신호로 변환 (RS-232, UTP)|

## Ⅳ. OSI 7계층 참조 모델의 종류·비교

| 비교 항목 | OSI 7계층 모델 | TCP/IP 4계층 모델 |
|---|---|---|
| **제정 주체** | ISO (국제표준화기구) | 미국 국방부 (DoD / DARPA) |
| **접근 철학** | 개념적 이론 모델 중심 (Top-down 표준화) | 실용적 구현 및 상용 프로토콜 중심 (Bottom-up) |
| **상위 계층 통합**| 응용, 표현, 세션 계층을 3개로 엄격 분리 | 응용 계층(Application Layer) 단일 계층으로 통합 |
| **하위 계층 통합**| 데이터링크 계층과 물리 계층 분리 | 네트워크 액세스 계층(Network Access)으로 통합 |
| **통신 시장 현실**| 개념적 교육 및 참조 모델로 정착 | 전 세계 인터넷의 실질적인 사실상 표준(De-facto) |

## Ⅴ. OSI 7계층 참조 모델의 한계와 방안

| 한계 | 방안 |
|---|---|
| 세션 및 표현 계층의 경계가 모호하여 실제 네트워크 스택 구현 시 불필요한 계층 오버헤드 유발 | 상위 3개 계층을 단일 사용자 공간 애플리케이션 라이브러리(TLS/HTTP 프레임워크)로 통합 구현 |
| 계층 간 엄격한 분리로 인해 크로스 레이어 최적화(예: 무선 채널 상태에 따른 TCP 윈도우 조절) 불가 | eBPF 커널 프로그래밍 기술을 적용하여 계층 간 메트릭을 안전하게 실시간 교환 및 통제 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
엔터프라이즈 네트워크 장애 처리(Troubleshooting) 시, 물리 계층(L1 링크 LED, 케이블) 점검 ──► 데이터링크(L2 MAC 학습, VLAN) ──► 네트워크(L3 IP 핑, 게이트웨이) ──► 전송(L4 포트 오픈, 텔넷) ──► 응용(L7 HTTP 응답코드)의 상향식(Bottom-up) 접근법을 표준 절차로 수립.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 네트워크 장비 계층별 배치 및 데이터 처리 심도 ]                      │
│                                                                        │
│   [ L7 스위치 / WAF ] ── HTTP URL / Cookie / 페이로드까지 검사 및 스위칭│
│           ▲                                                            │
│   [ L4 스위치 / 로드밸런서 ] ── TCP/UDP 포트 번호 기반 부하 분산       │
│           ▲                                                            │
│   [ L3 라우터 / L3 스위치 ] ── IP 주소 기반 라우팅 및 패킷 포워딩      │
│           ▲                                                            │
│   [ L2 스위치 ] ── MAC 주소 테이블 기반 프레임 스위칭 (VLAN 격리)       │
│           ▲                                                            │
│   [ L1 허브 / 리피터 ] ── 단순 전기 신호 증폭 및 재생                  │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 계층 | 대표 주소 체계 | 주소 길이 | 핵심 동작 장비 | 주요 장애 증상 |
|---|---|---|---|---|
| **L2 데이터링크** | MAC Address | 48 비트 (6 바이트) | L2 Switch, 브리지 | 브로드캐스트 스톰, MAC 플러딩 |
| **L3 네트워크** | IPv4 / IPv6 Address | 32 비트 / 128 비트 | L3 Router, L3 Switch | 라우팅 루프, 서브넷 마스크 불일치 |
| **L4 전송** | Port Number | 16 비트 (0~65535) | L4 Switch, 방화벽 | 포트 블로킹, SYN Flooding 지연 |
