## 연관 키워드

- OSI 7계층(Open Systems Interconnection), ISO, 캡슐화(Encapsulation), 역캡슐화(Decapsulation)
- 물리 계층, 데이터링크 계층, 네트워크 계층, 전송 계층, 세션 계층, 표현 계층, 응용 계층
- TCP/IP, SAP(Service Access Point), 제로 카피(Zero-Copy), 커널 바이패스(Kernel Bypass), 크로스 레이어(Cross-Layer), 심층 방어(Defense-in-Depth)

## Ⅰ. OSI 7계층 참조 모델의 개요

- 핵심 요약 : 이종 시스템 간 통신을 7개 계층으로 나누어 기능과 인터페이스를 표준화한 개념적 참조 모델.
- 개념 : ISO가 제정한 **개방형 시스템 상호 연결** (OSI, Open Systems Interconnection) 참조 모델로, 네트워크 통신 기능을 물리부터 응용까지 7단계로 구분함.
- 배경 및 필요성 : 제조사마다 독자적인 네트워크 프로토콜을 쓰던 시기에는 이종 시스템 간 통신이 어려웠으므로, 공통 기준으로 기능을 나눌 필요가 생김.
- 주요 목적 : 계층별 모듈화와 캡슐화로 기능을 분리하고, 계층 간 독립성을 확보하여 한 계층의 기술 변경이 다른 계층에 주는 영향을 줄임.

## Ⅱ. OSI 7계층 참조 모델의 특징 및 장점

- 핵심 요약 : 계층 분리와 캡슐화가 기능 독립성과 장애 격리로 이어지는 구조.

1. 계층 분리 : 각 계층이 맡은 기능과 인터페이스를 명확히 정의 → 한 계층의 프로토콜을 교체해도 다른 계층 수정이 최소화.
2. 캡슐화 : 상위 계층 데이터에 계층별 헤더를 덧붙여 하위로 전달 → 수신 측이 헤더를 차례로 해석하며 기능을 분담.
3. 표준 참조 틀 : 제품과 프로토콜을 같은 기준으로 비교 → 장애 진단과 설계 검토의 공통 언어로 쓰임.

## Ⅲ. OSI 7계층 참조 모델의 구조 (흐름)

- 핵심 요약 : 송신 측은 상위에서 하위로 헤더를 붙이며 내려가고, 수신 측은 하위에서 상위로 헤더를 떼며 올라가는 구조.

```text
[ 송신 측 캡슐화 ]

7. 응용 계층 : 데이터
   ↓ 헤더 부착
4. 전송 계층 : 세그먼트 (TCP/UDP)
   ↓ 헤더 부착
3. 네트워크 계층 : 패킷 (IP)
   ↓ 헤더·트레일러 부착
2. 데이터링크 계층 : 프레임
   ↓
1. 물리 계층 : 비트 신호
```

- **물리 계층** (Physical Layer) : 원시 비트를 전기·광·전파 신호로 변환하여 매체로 전송(케이블, 리피터, 허브).
- **데이터링크 계층** (Data Link Layer) : 인접 노드 간 프레이밍, MAC 주소 기반 전달, 오류 검출(CRC), 흐름 제어 수행(L2 스위치).
- **네트워크 계층** (Network Layer) : IP 주소 기반 경로 설정과 패킷 전달(라우터, L3 스위치).
- **전송 계층** (Transport Layer) : 종단 간 프로세스 간 신뢰성 있는 전달과 포트 기반 식별, 흐름·혼잡 제어(TCP, UDP).
- **세션 계층** (Session Layer) : 응용 간 대화의 수립, 유지, 동기화, 종료 관리(RPC 등).
- **표현 계층** (Presentation Layer) : 데이터 형식 변환, 인코딩, 압축, 암호화 담당(예: TLS/SSL).
- **응용 계층** (Application Layer) : 사용자 서비스와 직접 맞닿는 프로토콜(HTTP, DNS, SMTP, FTP).

```text
[ 수신 측 역캡슐화 ]

1. 물리 계층 : 비트 신호 수신
   ↓ 프레임 헤더 제거
2. 데이터링크 계층 : MAC 주소 확인, 오류 검사
   ↓ IP 헤더 제거
3. 네트워크 계층 : IP 주소 확인, 경로 판단
   ↓ TCP 헤더 제거
4. 전송 계층 : 포트 번호로 프로세스 식별
   ↓ 세션·표현 계층 처리 후 전달
7. 응용 계층 : 데이터 사용
```

## Ⅳ. OSI 7계층 참조 모델의 비교

- 핵심 요약 : OSI는 학술적 참조 모델이고 TCP/IP는 실제 인터넷에서 구현된 프로토콜 스택이라는 점에서 역할이 다름.

| 비교 축 | OSI 7계층 | TCP/IP 모델 |
| --- | --- | --- |
| 제정 주체 | ISO | 미 국방고등연구계획국(DARPA)에서 시작, 표준화는 IETF |
| 설계 성격 | 개념적·학술적 참조 모델 | 구현 중심의 실제 프로토콜 스택 |
| 상위 계층 | 세션, 표현, 응용을 각각 분리 | 응용 계층 하나로 통합 |
| 네트워크 계층 | 연결형과 비연결형을 모두 정의 | 비연결형 IP 중심 |
| 계층 간 인터페이스 | SAP 기반 엄격한 정의 | 소켓(Socket) API 중심 |
| 주요 활용 | 설계 교육, 장애 분석의 기준 틀 | 실제 인터넷 통신 |

- 선택 기준 : 장애 원인을 계층별로 나누어 분석할 때는 OSI 7계층을, 실제 구현과 프로토콜 동작을 설명할 때는 TCP/IP를 기준으로 삼음.

## Ⅴ. OSI 7계층 참조 모델의 한계와 방안

- 핵심 요약 : 상위 계층 구분의 모호성, 계층 통과에 따른 처리 오버헤드, 계층 간 정보 단절이 주요 한계이며, 계층 단순화와 전용 경로 처리, 계층 간 정보 공유로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 세션·표현 계층의 모호함 | 실제 애플리케이션에서 세션과 표현 기능이 코드 안에 흡수되어 계층 구분이 불분명 | 실무 아키텍처는 TCP/IP 기준으로 단순화하고 암호화는 전송 계층 위의 보안 모듈로 관리 | 계층별 장애 귀속률 |
| 계층 통과 오버헤드 | 커널 스택을 계층마다 거치며 버퍼 복사와 문맥 전환 비용 발생 | 제로 카피 적용, 커널 바이패스(DPDK), 네트워크 카드 오프로드(TOE, SmartNIC) | 패킷당 CPU 사이클 |
| 계층 간 정보 단절 | 무선 채널 품질을 상위 계층이 알지 못해 전송 최적화 한계 | **크로스 레이어** (Cross-Layer) 설계로 계층 간 파라미터 공유 | 전송 지연, 재전송률 |

## Ⅵ. OSI 7계층 참조 모델에 대한 기술사적 제언

- 핵심 요약 : 계층 모델을 장애 진단과 보안 통제의 공통 틀로 삼고, 계층별 책임을 명확히 나누는 운영 체계가 필요함.
- 네트워크 운영 조직은 물리부터 응용까지 순서대로 점검하는 장애 격리 절차를 표준화해 두면, 장애 발생 시 담당 계층을 빠르게 특정할 수 있음.
- 보안 조직은 제로 트러스트 원칙에 따라 데이터링크 계층의 포트 인증(802.1X), 네트워크 계층의 IPsec과 방화벽, 응용 계층의 웹 방화벽을 겹쳐 적용하는 심층 방어를 설계함.
- 클라우드 인프라 조직은 서비스 메시에서 전송 계층 프록시와 응용 계층 라우팅의 역할을 분리하여, 사이드카 구간의 지연을 관리할 수 있도록 설계 기준을 마련함.

## Ⅶ. 결론

- 핵심 요약 : OSI 7계층은 실제 인터넷 표준은 아니지만, 통신 기능을 계층으로 나누어 설계와 진단을 체계화하는 기준 틀이다.
- 시사점 : 계층 분리의 원리를 유지하되 성능과 보안을 위해 계층 간 정보 공유를 설계에 함께 반영하는 것이 현실적 방향이다.
