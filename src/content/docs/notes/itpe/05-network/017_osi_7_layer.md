## 핵심 용어
- PDU(Protocol Data Unit): 각 계층에서 데이터와 해당 계층의 제어 헤더(PCI)를 합친 전송 단위 (Bit, Frame, Packet, Segment, Data)
- 캡슐화(Encapsulation): 상위 계층의 데이터를 하위 계층의 페이로드(Payload)로 담고, 앞뒤에 제어 정보(Header/Trailer)를 덧붙여 내려보내는 과정
- SAP(Service Access Point): 상위 계층이 하위 계층이 제공하는 통신 서비스를 호출하기 위해 접근하는 논리적 인터페이스 접점 (포트 번호, IP 프로토콜 번호 등)

## 핵심 통찰
- OSI 7계층은 실무에서 프로토콜을 그대로 코딩해 쓰는 "구현 모델"이 아니라, 통신 장애 발생 시 문제를 L1~L7 중 어디로 좁힐지 판단하는 "개념적 참조 프레임워크"
- 실제 인터넷 시장을 지배한 TCP/IP는 세션·표현 계층을 응용 계층에 합쳐 4개 계층으로 간소화함으로써 빠른 상용 보급과 구현 단순성 달성
- 계층화의 대가는 "헤더 오버헤드"와 "중복 처리"임 → L2의 CRC, L3의 IP 체크섬, L4의 TCP 체크섬이 각각 중복 검증을 수행하는 비효율 내포

## 이웃 토픽과 구분
- OSI 7계층 vs TCP/IP: OSI 모델은 엄격한 인터페이스와 계층 책임을 정의한 이론적 표준 / TCP/IP는 IETF RFC를 기반으로 시장에서 검증된 실용 프로토콜 스택

## 문제·원인·대책
- 적용 상황: 웹 서비스 접속 장애 트러블슈팅
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 특정 서버 간 통신 두절 시 원인 파악 지연 | 무작위 패킷 덤프 분석으로 트러블슈팅 범위 발산 | Bottom-Up 계층별 점검(L1 링크 불빛 → L2 ARP → L3 Ping → L4 Telnet/Port) | 장애 원인 계층을 5분 이내 신속 특정 |
| 작은 패킷 전송 시 유효 대역폭 낭비 | L2(18B)+L3(20B)+L4(20B) = 최소 58B 고정 헤더 부착 | 헤더 압축(ROHC) 또는 점보 프레임(9000B) 적용 | 전체 전송 대역폭 중 실제 데이터 페이로드 비율 향상 |
