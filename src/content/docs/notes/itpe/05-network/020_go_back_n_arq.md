## 지식 로드맵 내 현재 위치

지식 위치: 네트워크 → 데이터 링크 오류 제어 → **Go-Back-N ARQ**

## 30초 인출

- 본질: **Go-Back-N ARQ(Automatic Repeat reQuest)** : 순서대로 받는 수신 창을 유지하고, 손실 프레임부터 미확인 프레임을 재전송하는 오류 제어 방식
- 메커니즘: 송신 창으로 여러 프레임 전송 → 누적 ACK 수신 → 손실 또는 타임아웃 시 가장 이른 미확인 프레임부터 재전송
- 통찰: 슬라이딩 윈도우를 활용해 확인 응답(ACK) 대기 없이 복수 프레임을 연속 전송하여 파이프라이닝 효율을 높이되 오류 발생 시 해당 프레임 이후 전송된 모든 프레임을 일괄 폐기하고 재전송하는 슬라이딩 윈도우 ARQ 기법임.

<details>
<summary>핵심 용어</summary>

- **Go-Back-N ARQ(Go-Back-N Automatic Repeat reQuest)** : 손실·오류 프레임부터 후속 미확인 프레임까지 다시 보내는 오류 제어 방식
- **송신 창(Sender Window)** : 확인 응답을 기다리지 않고 연속 전송할 수 있는 프레임 범위
- **누적 확인 응답(Cumulative ACK)** : 지정 순서까지 연속 수신했음을 알리는 응답
- **수신 창(Receiver Window)** : 수신기가 순서가 맞는 프레임을 받아들일 수 있는 범위; Go-Back-N의 수신 창 크기는 1
- **시퀀스 번호(Sequence Number)** : 프레임 순서와 재전송 여부를 구분하는 번호
- **ARQ(Automatic Repeat reQuest)** : 오류 검출, 확인 응답과 재전송으로 전송 신뢰성을 높이는 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. Go-Back-N ARQ의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 송신측이 수신측의 ACK 수신 전이라도 송신 윈도우 크기(N)만큼 프레임을 연속 송신하되, 오류나 손실이 발생하면 오류 프레임부터 이후 송신된 N개의 프레임을 모두 되돌아가서(Go-Back) 재전송하는 ARQ 프로토콜 |
| 목적 | Stop-and-Wait 방식의 유휴 대기 시간(Idle Time) 해소 및 수신측 버퍼 구조 단순화(수신 윈도우 크기=1) |

## Ⅱ. Go-Back-N ARQ의 특징

| 특징 | 상세 내용 |
|---|---|
| 누적 확인 응답(Cumulative ACK)| ACK n은 'n번 프레임까지 오류 없이 모두 잘 수신하였으며, n+1번 프레임을 대기함'을 의미 |
| 수신 윈도우 크기 1 | 수신측은 오직 순서 번호가 정확히 일치하는 프레임만 수락하고 순서가 어긋난 프레임은 무조건 폐기 |
| 단일 타이머 운용 | 송신측은 가장 오래된 미확인 프레임(Oldest Unacknowledged Frame)에 대해 단 1개의 재전송 타이머 구동 |
| 윈도우 크기 제약 | 시퀀스 번호 비트 수가 m비트일 때 송신 윈도우 크기는 반드시 `2^m - 1` 이하로 제한 |

## Ⅲ. Go-Back-N ARQ의 체계·프로세스

**Go-Back-N ARQ 오류 발생 시 프레임 폐기 및 재전송 동작**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ Go-Back-N ARQ 오류 복구 메커니즘 ]            │
│                                                                        │
│   [ 송신측 (Window Size = 4) ]                 [ 수신측 (Window Size = 1) ]│
│         │                                            │                 │
│   Frame 0 ──────────────────────────────────────────►│ (정상 수신)     │
│         │◄──────── ACK 1 (Next 기대: 1) ─────────────┤                 │
│   Frame 1 ───────X (네트워크 상에서 패킷 손실)       │                 │
│   Frame 2 ──────────────────────────────────────────►│ (순서 불일치 폐기)│
│   Frame 3 ──────────────────────────────────────────►│ (순서 불일치 폐기)│
│   Frame 4 ──────────────────────────────────────────►│ (순서 불일치 폐기)│
│         │                                            │                 │
│         │ [ Frame 1 재전송 타이머 만료 (Timeout) ]   │                 │
│         │                                            │                 │
│   (Go-Back: Frame 1부터 윈도우 내 전 프레임 일괄 재전송 시작)          │
│   Frame 1 ──────────────────────────────────────────►│ (수신 성공)     │
│   Frame 2 ──────────────────────────────────────────►│ (수신 성공)     │
│   Frame 3 ──────────────────────────────────────────►│ (수신 성공)     │
│   Frame 4 ──────────────────────────────────────────►│ (수신 성공)     │
└────────────────────────────────────────────────────────────────────────┘
```

| 구성 요소 | 동작 파라미터 | 세부 설명 및 제약 조건 |
|---|---|---|
| **송신 윈도우 (Ws)** | `Ws <= 2^m - 1` | 시퀀스 번호 모듈로 연산 시 중복 패킷 오인 방지 (m=3비트 시 최대 7) |
| **수신 윈도우 (Wr)** | `Wr = 1` 고정 | 순서가 틀린 패킷은 버퍼링하지 않고 폐기하므로 버퍼 메모리 불필요 |
| **재전송 트리거** | Timeout 또는 중복 ACK | 미확인 선두 패킷의 타이머 만료 시 윈도우 내 미승인 전 패킷 일괄 재전송 |
| **전송 효율 공식** | `E = Ws / (1 + 2a)` | 단, 프레임 오류율 p=0일 때. 오류율 증가 시 효율 급격 저하 |

## Ⅳ. Go-Back-N ARQ의 종류·비교

| 비교 항목 | Stop-and-Wait ARQ | Go-Back-N ARQ | Selective Repeat ARQ |
|---|---|---|---|
| **송신 윈도우 크기**| 1 | N (최대 `2^m - 1`) | N (최대 `2^(m-1)`) |
| **수신 윈도우 크기**| 1 | **1 (버퍼 불필요)** | **N (재정렬 버퍼 필수)** |
| **오류 시 재전송** | 손실된 1개 프레임 | **오류 이후 전송된 N개 프레임 전체**| **오류가 발생한 특정 프레임만** |
| **수신 확인 방식** | 개별 ACK | 누적 ACK (Cumulative) | 개별 ACK / SACK 결합 |
| **하드웨어 복잡도**| 극히 단순 | 비교적 단순 | 복잡 (프레임별 개별 타이머/버퍼) |
| **선로 오류 시 처리율**| 극히 낮음 | 대역-지연곱 클수록 급락 | 대역-지연곱 커도 높은 처리율 유지 |

## Ⅴ. Go-Back-N ARQ의 한계와 방안

| 한계 | 방안 |
|---|---|
| 대역폭-지연 곱(BDP)이 큰 위성/광통신망에서 1개 패킷 오류로 정상 패킷까지 N개 재전송되어 대역폭 극심 낭비 | 정상 수신된 블록은 버퍼링하고 손실 블록만 재전송 요청하는 Selective Repeat ARQ 또는 TCP SACK으로 전환 |
| 송신 윈도우 크기가 `2^m`으로 잘못 설정될 경우 모든 ACK 분실 시 송신측의 재전송 프레임을 수신측이 신규 프레임으로 오인 | 송신 윈도우 상한을 `2^m - 1`로 엄격 제한하는 알고리즘 검증 로직 반영 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
선로 오류율이 매우 낮은 유선 LAN 환경이나 초저전력 사물인터넷(IoT) 센서 노드 설계 시에는 수신 버퍼 메모리 제약이 심하므로 Go-Back-N 방식을 채택하여 수신단 하드웨어 단가를 절감하고, WAN 및 무선 구간에는 SACK을 결합 적용.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ Go-Back-N 윈도우 크기 Ws <= 2^m - 1 수학적 증명 메커니즘 ]          │
│                                                                        │
│   조건: 2비트 시퀀스 번호 (m=2 -> 번호: 0, 1, 2, 3 총 4개)            │
│                                                                        │
│   [ 잘못된 설계: Ws = 4 (= 2^2) 설정 시 재앙 시나리오 ]                │
│   1. 송신측이 Frame 0, 1, 2, 3 송신                                    │
│   2. 수신측이 모두 정상 수신 후 ACK 0, 1, 2, 3 송출                    │
│      (수신측 기대 번호는 다음 주기의 Frame 0으로 변경됨)               │
│   3. 망 장애로 모든 ACK가 분실되어 송신측 타임아웃 발생                │
│   4. 송신측이 이전 주기의 Frame 0, 1, 2, 3 재전송                      │
│   5. 수신측: 기다리던 '새로운 Frame 0'이 도착한 것으로 오판하여        │
│      중복 데이터를 상위 계층에 중복 전달하는 치명적 데이터 왜곡 발생!  │
│                                                                        │
│   [ 올바른 설계: Ws = 3 (= 2^2 - 1) 적용 시 ]                          │
│   송신 가능 범위(0,1,2)와 수신 기대 범위가 겹치지 않아 완벽 분리 판정   │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 계층 프로토콜 | GBN 적용 방식 | 특징 |
|---|---|---|
| **HDLC (데이터링크)** | REJ (Reject) 프레임 기반 | 오류 감지 즉시 NAK 성격의 REJ 프레임을 보내 즉각 GBN 재전송 유도 |
| **표준 TCP (전송 계층)**| 누적 ACK 기반 유사 GBN | 패킷 폐기 후 정상 패킷에 대해 중복 ACK(Duplicate ACK) 반복 회신 |
| **TFTP (응용 계층)** | Stop-and-Wait 채택 | GBN의 복잡도조차 배제한 극단적 단순 파일 전송 프로토콜 |
