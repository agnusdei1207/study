## 연관 키워드

- Go-Back-N ARQ, 자동 재전송 요구(ARQ, Automatic Repeat reQuest), 슬라이딩 윈도우(Sliding Window), 송신 윈도우(Send Window)
- 수신 윈도우(Receive Window), 누적 확인 응답(Cumulative ACK), 재전송 타이머, 순서 번호(Sequence Number)
- 정지-대기 ARQ(Stop-and-Wait ARQ), 선택적 재전송 ARQ(Selective Repeat ARQ)

## Ⅰ. Go-Back-N ARQ의 개요

- 핵심 요약 : 오류 프레임부터 윈도우 내 전송분을 모두 되돌아가 재전송하는 슬라이딩 윈도우 기반 오류 제어 방식.
- 개념 : 프레임 분실·오류 시 재전송으로 신뢰성을 확보하는 **자동 재전송 요구** (ARQ, Automatic Repeat reQuest) 가운데, **슬라이딩 윈도우** (Sliding Window) 기반으로 오류 지점부터 이후 전송분 전체를 다시 보내는 **Go-Back-N ARQ** 프로토콜.
- 배경 및 필요성 : 프레임마다 응답을 기다리는 정지-대기 ARQ(Stop-and-Wait ARQ)는 효율이 낮고, 오류 프레임만 골라 재전송하는 선택적 재전송 ARQ(Selective Repeat ARQ)는 수신 버퍼 부담이 큼 → 두 방식 사이의 절충안 필요.
- 주요 목적 : 연속 전송의 전송 효율 확보와 수신 측 구현의 단순화 동시 달성.

## Ⅱ. Go-Back-N ARQ의 특징 및 장점

- 핵심 요약 : 수신 윈도우 1개의 단순 수신 구조가 낮은 메모리 비용과 구현 용이성으로 이어지는 방식.

1. 파이프라인 전송 : 응답을 기다리지 않고 윈도우 크기 N만큼 연속 전송 → 정지-대기 방식 대비 전송 효율 향상.
2. 단순 수신 구조 : 기대한 순서 번호의 프레임만 수용하고 나머지는 폐기 → **수신 윈도우** (Receive Window) 1개로 구현 가능.
3. 응답 절약 : **누적 확인 응답** (Cumulative ACK, 특정 번호 이전 전체의 수신 완료를 함께 뜻하는 응답) 사용 → 일부 응답 유실에도 복구 가능.
4. 타이머 관리 : 가장 오래된 미확인 프레임에만 **재전송 타이머** (Retransmission Timer) 운영 → 송신 측 관리 부담 최소화.

## Ⅲ. Go-Back-N ARQ의 구조 (흐름)

- 핵심 요약 : 순서 번호 검사와 타이머 만료가 재전송 출발점을 정하는 제어 구조.
- **송신 윈도우** (Send Window) : 미확인 상태로 보낼 수 있는 프레임 수의 상한 N.
- **수신 윈도우** (Receive Window) : 크기 1로 고정되어 순서가 맞는 프레임만 수락하는 창.
- **순서 번호** (Sequence Number) : 프레임에 붙는 일련 번호로, m비트일 때 송신 윈도우 크기는 2^m − 1 이하로 설계.

```text
[ 정상 전송 흐름 ]

F0 F1 F2 연속 전송
   ↓
ACK 1 도착 (F0 정상 의미)
   ↓
윈도우 전진 → F3 전송
   ↓
누적 응답으로 순서 관리
```

```text
[ 오류 시 재전송 흐름 ]

F2 프레임 수신 실패
   ↓
F3·F4는 순서 불일치로 폐기
   ↓
F2 응답 부재 → 타이머 만료
   ↓
F2부터 윈도우 내 전체 재전송
```

## Ⅳ. Go-Back-N ARQ와 유사 방식의 비교

- 핵심 요약 : 재전송 범위와 수신 버퍼 요구량의 균형점이 세 방식의 선택 기준.

| 비교 축 | 정지-대기 ARQ | Go-Back-N ARQ | 선택적 재전송 ARQ |
| --- | --- | --- | --- |
| 송신 윈도우 | 1 | N | N |
| 수신 윈도우 | 1 | 1 | N |
| 오류 시 재전송 | 해당 프레임 1개 | 오류점부터 전체 | 오류 프레임만 |
| 수신 버퍼 요구 | 최소 | 낮음 | 높음 (재정렬 버퍼) |
| 적합 환경 | 저속·저오류 링크 | 저오류·자원 제약 장치 | 고오류·장거리 링크 |

- 선택 기준 : 오류율이 낮고 메모리가 제한된 장치 간 통신에는 Go-Back-N을, 오류율이 높아 재전송 낭비를 줄여야 하는 링크에는 선택적 재전송을 적용.

## Ⅴ. Go-Back-N ARQ의 한계와 방안

- 핵심 요약 : 재전송 낭비, 순서 번호 설계 오류, 조기 타임아웃을 방식 전환·설계 상수·적응형 타이머로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 재전송 낭비 | 1개 프레임 오류가 정상 수신된 뒤 프레임의 폐기·재전송으로 확대되어 대역폭 손실 | 오류율이 높은 구간은 선택적 재전송 계열로 전환 | 재전송 데이터 비율 |
| 순서 번호 모호성 | 윈도우 크기가 번호 공간을 초과하면 신규·재전송 프레임 구분 불가 | 설계 상수 준수 (윈도우 ≤ 2^m − 1) | 설계 검증 통과율 |
| 조기 타임아웃 | 지연 변동에 타이머가 만료되어 불필요한 재전송 유발 | 왕복 지연 측정 기반의 적응형 타임아웃 | 불필요 타임아웃 횟수 |

## Ⅵ. Go-Back-N ARQ에 대한 기술사적 제언

- 핵심 요약 : 자원 제약 환경 중심의 적용과 오류 조건 기반의 방식 전환 기준 마련.
- 임베디드·센서 시스템 설계 조직 : 메모리 제약 노드의 링크 계층에 Go-Back-N을 채택하고 오류율 임계값에 따른 전환 지침 문서화.
- 무선 표준 개발 조직 : 재전송 방식을 물리 계층 하이브리드 재전송 기술과 결합한 계층별 역할 분담 설계 검토.
- 통신 장비 검증 조직 : 오류 주입 시험으로 재전송 동작과 타이머 설정의 적합성을 확인하는 시험 항목 운영.

## Ⅶ. 결론

- 핵심 요약 : Go-Back-N ARQ는 수신 버퍼 1개로 연속 전송을 구현하되 오류 시 되돌아가는 재전송을 감수하는 방식.
- 오류율과 수신 자원 조건에 따른 방식 선택이 링크 효율의 핵심 판단 기준.
