## 연관 키워드

- Go-Back-N ARQ, ARQ(Automatic Repeat reQuest), 슬라이딩 윈도우(Sliding Window), 송신 윈도우 N
- 수신 윈도우 1, 누적 확인 응답(Cumulative ACK), 단일 재전송 타이머, 순서 번호(Sequence Number)
- Stop-and-Wait ARQ, Selective Repeat ARQ, 순서 역전(Out-of-order), RTO(Retransmission Timeout)

## Ⅰ. Go-Back-N ARQ의 개요

- 핵심 요약 : 연속 전송 후 오류가 나면 오류 프레임부터 전부 되돌아가 재전송하여 수신 버퍼를 1개로 줄인 자동 재전송 방식.
- 개념 : **슬라이딩 윈도우** (Sliding Window) 기반의 **자동 재전송** (ARQ, Automatic Repeat reQuest) 프로토콜로, 송신 측이 윈도우 크기 N만큼 프레임을 연속 전송하고, 수신 측이 오류 프레임을 발견하면 그 뒤의 프레임을 모두 버리며, 송신 측은 오류 프레임부터 윈도우 안의 프레임 전체를 다시 보냄.
- 배경 및 필요성 : **정지-대기** (Stop-and-Wait) 방식은 프레임마다 응답을 기다려 전파 지연이 큰 링크에서 효율이 낮고, Selective Repeat는 수신단에 정렬용 버퍼가 필요하므로 구현 비용이 커짐. 이 사이에서 수신 버퍼를 1개로 유지하면서 파이프라이닝을 얻으려는 요구에서 출발함.
- 주요 목적 : 파이프라인 전송으로 처리율을 높이고, 수신단 버퍼 구현을 단순하게 유지하며, 누적 확인 응답으로 제어 메시지 수를 줄임.

## Ⅱ. Go-Back-N ARQ의 특징 및 장점

- 핵심 요약 : 수신단의 단순함과 송신단의 윈도우 관리가 구현 비용 절감과 처리율 확보로 이어지는 방식.

1. 수신 버퍼 불필요 : 수신단은 기대하는 순서 번호 하나만 기억 → 임베디드 기기에서도 메모리 부담 없음.
2. 파이프라이닝 : 확인 응답을 기다리지 않고 N개를 연속 전송 → Stop-and-Wait보다 링크 활용률 향상.
3. 누적 확인 응답 : ACK k가 k번까지 정상 수신을 뜻함 → 일부 ACK가 유실돼도 뒤의 ACK로 복구되어 제어 오버헤드 감소.
4. 단일 타이머 : 윈도우 안의 가장 오래된 미확인 프레임에만 타이머를 둠 → 송신 측 상태 관리가 단순.

## Ⅲ. Go-Back-N ARQ의 구조 (흐름)

- 핵심 요약 : 정상 프레임은 순서대로 받아들이고, 오류가 나면 뒤 프레임을 버린 뒤 오류 지점부터 되돌아가 재전송하는 구조.
- **송신 윈도우** (Send Window) : 미확인 상태로 보낼 수 있는 최대 프레임 수 N이며, 가장 오래된 미확인 프레임에 대해서만 타이머를 가동.
- **수신 윈도우** (Receive Window) : 크기 1로 고정되어 정확히 기대한 순서 번호의 프레임만 수락하고 나머지는 폐기.

```text
[ 오류 발생 시 송신 흐름 ]

F0, F1 정상 수신 → ACK 1 반환
   ↓
F2 손실, F3·F4·F5는 수신 측에서 폐기
   ↓
F2 응답 없음 → 재전송 타이머 만료
   ↓
F2, F3, F4, F5 순서대로 재전송
```

- **단일 재전송 타이머** (Single Retransmission Timer) : 송신 측이 가장 오래된 미확인 프레임 기준으로 한 개의 타이머만 유지하는 방식.

```text
[ 수신 측 판정 기준 ]

도착 프레임 번호 = 기대 번호
   ↓ 수락, 기대 번호 +1, ACK 반환
도착 프레임 번호 ≠ 기대 번호
   ↓ 버퍼링 없이 폐기, 마지막 정상 ACK 재전송
```

## Ⅳ. Go-Back-N ARQ의 비교

- 핵심 요약 : Go-Back-N은 수신 버퍼를 아끼는 대신 오류 시 재전송 낭비를 감수하는 중간 지점에 위치함.

| 비교 축 | Stop-and-Wait ARQ | Go-Back-N ARQ | Selective Repeat ARQ |
| --- | --- | --- | --- |
| 송신 윈도우 | 1 | N (N ≤ 2^m − 1) | N (N ≤ 2^(m-1)) |
| 수신 윈도우 | 1 | 1 | N |
| 순서 역전 프레임 | 발생하지 않음 | 즉시 폐기 | 버퍼에 저장 후 재정렬 |
| 오류 시 재전송 | 해당 프레임 하나 | 오류 프레임 이후 전부 | 오류 프레임만 |
| 오류율이 높을 때 | 처리량이 낮지만 안정적 | 처리량이 크게 떨어짐 | 처리량 유지 |
| 메모리 비용 | 최소 | 낮음 | 높음 |

- 선택 기준 : 오류율이 낮고 메모리가 제한된 장치 간 통신에는 Go-Back-N이 적합하며, 오류율이 높거나 긴 링크에서 재전송 낭비를 줄여야 하면 Selective Repeat가 낫다.

## Ⅴ. Go-Back-N ARQ의 한계와 방안

- 핵심 요약 : 프레임 하나의 오류가 뒤 프레임 전체의 재전송으로 번지는 점, 윈도우 설계 오류, 타이머 부정확성이 주요 한계이며, 재전송 범위 축소와 설계 상한 준수, 적응형 타이머로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 재전송 낭비 | 정상으로 도착한 뒤 프레임까지 폐기·재전송되어 대역폭 소모 | 수신 버퍼를 늘려 Selective Repeat로 전환, TCP의 SACK 활용 | 재전송률 |
| 순서 번호 모호성 | 윈도우가 순서 번호 공간을 넘으면 신규와 재전송 프레임을 구분하지 못함 | 설계 상한 N ≤ 2^m − 1 준수 | 설계 검증 결과 |
| 타이머 부정확성 | 지연이 일시 증가하면 불필요한 타임아웃으로 윈도우 전체가 재전송 | 지수 가중 이동 평균(EWMA) 기반 RTO 계산 | 불필요 타임아웃 수 |

## Ⅵ. Go-Back-N ARQ에 대한 기술사적 제언

- 핵심 요약 : Go-Back-N은 자원 제약 장치와 누적 확인 응답 설계에 맞춰 선택하고, 고속 무선이나 긴 링크에서는 재전송 범위를 좁히는 방식으로 옮겨가는 것이 바람직함.
- 저전력 센서 네트워크를 설계하는 조직은 메모리가 제한된 노드에 Go-Back-N을 적용하고, 오류율 기준을 정해 전환 시점을 운영 지침으로 명시함.
- 5G나 LTE 같은 무선 구간은 Selective Repeat 계열 재전송과 물리 계층 HARQ를 결합한 구조를 기본으로 두는 것이 현실적임.
- 누적 확인 응답을 쓰는 전송 프로토콜을 구현하는 개발 조직은 ACK 전송 주기를 튜닝하여 상향 트래픽을 줄이는 방향을 검토함.

## Ⅶ. 결론

- 핵심 요약 : Go-Back-N ARQ는 수신 버퍼 1개와 슬라이딩 윈도우로 파이프라이닝을 얻는 대신, 오류 시 뒤 프레임을 되돌아가 재전송하는 방식이다.
- 시사점 : 구현 단순성과 재전송 낭비 사이의 균형점이므로, 오류율과 지연 조건을 함께 보고 Selective Repeat와의 선택을 정하는 것이 핵심이다.
