## 지식 로드맵 내 현재 위치

지식 위치: 네트워크 → 데이터 링크 오류 제어 → **Go-Back-N ARQ**

## 30초 인출

- 본질: **Go-Back-N ARQ(Automatic Repeat reQuest)** : 순서대로 받는 수신 창을 유지하고, 손실 프레임부터 미확인 프레임을 재전송하는 오류 제어 방식
- 메커니즘: 송신 창으로 여러 프레임 전송 → 누적 ACK 수신 → 손실 또는 타임아웃 시 가장 이른 미확인 프레임부터 재전송

<details>
<summary>핵심 용어</summary>

- **Go-Back-N ARQ(Go-Back-N Automatic Repeat reQuest)** : 손실·오류 프레임부터 후속 미확인 프레임까지 다시 보내는 오류 제어 방식
- **송신 창(Sender Window)** : 확인 응답을 기다리지 않고 연속 전송할 수 있는 프레임 범위
- **누적 확인 응답(Cumulative ACK)** : 지정 순서까지 연속 수신했음을 알리는 응답
- **수신 창(Receiver Window)** : 수신기가 순서가 맞는 프레임을 받아들일 수 있는 범위; Go-Back-N의 수신 창 크기는 1
- **시퀀스 번호(Sequence Number)** : 프레임 순서와 재전송 여부를 구분하는 번호
- **ARQ(Automatic Repeat reQuest)** : 오류 검출, 확인 응답과 재전송으로 전송 신뢰성을 높이는 방식

</details>

> Go-Back-N ARQ의 개념과 송신 창·재전송 동작을 설명하시오. (예상·10점)

---

## 1교시 10점 답안

### Ⅰ. Go-Back-N ARQ의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **Go-Back-N ARQ** : 수신 창 크기를 1로 두고, 손실 프레임부터 후속 미확인 프레임까지 재전송하는 방식 |
| 목적 | 여러 프레임을 연속 전송하면서 오류·손실을 확인 응답과 재전송으로 복구 |

### Ⅱ. 윈도우와 재전송

```text
송신 창: 프레임 0, 1, 2 전송
              ↓
프레임 1 손실 → 프레임 2 폐기
              ↓ 타임아웃
프레임 1부터 미확인 프레임 재전송
              ↓
연속 수신 뒤 누적 ACK
```

- 제언: 시퀀스 번호 비트 수와 송신 창 상한을 함께 검증하는 재전송 설계.

---

## 2~4교시 25점 답안

### Ⅰ. Go-Back-N ARQ의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **Go-Back-N ARQ** : 수신 창 크기를 1로 두고, 손실 프레임부터 후속 미확인 프레임까지 재전송하는 방식 |
| 목적 | 여러 프레임을 연속 전송하면서 오류·손실을 확인 응답과 재전송으로 복구 |

### Ⅱ. 송수신 동작

```text
송신 창: 프레임 0, 1, 2 전송
              ↓
프레임 1 손실 → 프레임 2 폐기
              ↓ 타임아웃
프레임 1부터 미확인 프레임 재전송
              ↓
연속 수신 뒤 누적 ACK
```

수신 창 크기 1은 순서가 맞지 않는 프레임을 보관하지 않음을 뜻함. ACK 번호의 표현과 손실 감지 절차는 프로토콜 명세에 따름.

### Ⅲ. 창 크기와 시퀀스 번호

| 항목 | 원리 |
|---|---|
| 번호 공간 | `m`비트 번호의 순환 범위는 `0`부터 `2^m−1`까지 |
| 송신 창 상한 | Go-Back-N에서는 `W_s ≤ 2^m−1` |
| 이유 | 창이 번호 공간 전체와 같으면 순환 뒤 이전 프레임과 새 프레임을 구분하기 어려움 |
| 수신 창 | `W_r = 1` |

### Ⅳ. ARQ 방식 비교

| 방식 | 수신 창 | 손실 시 동작 | 주요 자원 |
|---|---:|---|---|
| Stop-and-Wait | 1 | 해당 프레임 재전송 | 낮은 버퍼, 왕복 대기 |
| Go-Back-N | 1 | 손실분부터 후속 미확인분까지 재전송 | 송신 버퍼·누적 ACK |
| Selective Repeat | 여러 프레임 | 손실 프레임만 선택 재전송 | 수신 버퍼·재정렬 |

### Ⅴ. 적용 한계와 대응

| 한계 | 대응 |
|---|---|
| 한 프레임 손실이 후속 정상 프레임 재전송으로 이어짐 | 손실률·왕복 지연·버퍼 여건에 따라 Selective Repeat 계열과 비교 |
| 왕복 지연이 길어 창이 작으면 링크 활용이 낮아질 수 있음 | 대역폭·전파 지연과 시퀀스 번호 공간을 고려해 송신 창 설정 |
| ACK 손실·중복 수신이 순서 판단을 복잡하게 함 | 누적 ACK 규칙·타임아웃·중복 제거 동작을 상호운용 시험 |

### Ⅵ. 기술사적 제언

| 우선 선택 | 적용·확인 |
|---|---|
| 오류율과 재전송 비용에 맞는 ARQ 유형 선정 | 링크 오류·RTT·버퍼 한도를 시험하고 Go-Back-N과 선택 재전송의 지연·전송량 비교 |
