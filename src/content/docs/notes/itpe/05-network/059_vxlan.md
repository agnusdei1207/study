## Ⅰ. VXLAN(Virtual eXtensible LAN)의 개요

- **개념** : 기존의 확장성 높은 L3 IP 네트워크(언더레이)를 기반으로 하여, 그 위에 L2 이더넷 프레임을 UDP 패킷으로 캡슐화(MAC-in-UDP)하여 전송함으로써 논리적인 대규모 L2 오버레이 네트워크를 구축하는 네트워크 가상화 표준 프로토콜 (RFC 7348).
- **배경 및 필요성** : 대규모 클라우드 데이터센터 환경에서 기존 VLAN의 ID 한계(4,094개)로 인한 멀티테넌시 수용 불가, 물리 스위치 L2 확장 시 STP 루프로 인한 대역폭 낭비 및 VM의 L3 서브넷 간 무중단 라이브 마이그레이션 요구 증대.
- **핵심 목적** : 24비트 VNI를 통한 1,600만 개 가상 세그먼트 확장, L3 ECMP(Equal-Cost Multi-Path) 언더레이를 통한 풀 대역폭 활용, 데이터센터 전역의 자유로운 L2 이동성 보장.

## Ⅱ. VXLAN의 핵심 아키텍처 및 동작 메커니즘

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ VXLAN 패킷 캡슐화 및 터널링 구조 ]                 │
│                                                                        │
│   [ 테넌트 VM 프레임 (Original L2 Frame) ]                             │
│   ┌────────┬────────┬────────┬───────────────────────────────┬───────┐ │
│   │ Inner  │ Inner  │ Type   │            Payload            │ FCS   │ │
│   │ DMAC   │ SMAC   │ 2 Byte │                               │ 4 Byte│ │
│   └────────┴────────┴────────┴───────────────────────────────┴───────┘ │
│                                   │                                    │
│   ▼ VTEP 캡슐화 (총 50바이트 오버헤드 추가)                             │
│   ┌────────┬────────┬────────┬────────┬────────┬─────────────────────┐ │
│   │ Outer  │ Outer  │ Outer  │ UDP    │ VXLAN  │ Original L2 Frame   │ │
│   │ MAC    │ IP     │ IP     │ (4789) │ Header │ (FCS 제외)          │ │
│   │ Header │ SIP    │ DIP    │ 8 Byte │ 8 Byte │                     │ │
│   └────────┴────────┴────────┴────────┴────────┴─────────────────────┘ │
│                                            │                           │
│              ┌─────────────────────────────┴────────────────────────┐  │
│              │ Flags (8bit: I-Flag=1) │ Reserved (24bit)             │  │
│              ├────────────────────────┬─────────────────────────────┤  │
│              │ VNI (24bit: 16M 가상망) │ Reserved (8bit)              │  │
│              └────────────────────────┴─────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────────┘
```

- **MAC-in-UDP 캡슐화** : 가상머신이 전송한 원본 이더넷 프레임을 VTEP(VXLAN Tunnel End Point)이 가로채어 8바이트 VXLAN 헤더, 8바이트 UDP 헤더(목적지 포트 4789), 20바이트 외부 IP 헤더 및 이더넷 헤더(총 50바이트)로 포장하여 L3 언더레이망으로 라우팅.
- **24비트 VNI (VXLAN Network Identifier)** : $2^{24} = 16,777,216$개의 고유한 가상 세그먼트를 정의하여 초대규모 클라우드 멀티테넌트 완벽 격리.
- **VTEP (VXLAN Tunnel End Point)** : 하이퍼바이저 가상 스위치(OVS 등) 또는 ToR(Top-of-Rack) 하드웨어 스위치에 위치하여 캡슐화(Encapsulation) 및 역캡슐화(Decapsulation)를 수행하는 터널 종단점.
- **외부 UDP 소스 포트 해싱** : 내부 이더넷 헤더를 해싱하여 외부 UDP Source Port로 설정함으로써, 언더레이 라우터들이 L4 해시 기반 ECMP(Equal-Cost Multi-Path)로 트래픽을 모든 물리 링크에 균등 분산.

## Ⅲ. VXLAN과 전통적 VLAN의 세부 비교 분석

| 비교 항목 | VLAN (IEEE 802.1Q) | VXLAN (RFC 7348) |
|---|---|---|
| **세그먼트 식별자** | 12비트 VID (최대 4,094개) | 24비트 VNI (최대 16,777,216개) |
| **캡슐화 계층** | L2 이더넷 태그 삽입 (4 Byte) | L4 UDP 오버레이 캡슐화 (50 Byte) |
| **물리망(언더레이) 요건**| 순수 L2 스위칭망 강제 | 표준 L3 IP 라우팅망 (OSPF, BGP 기반) |
| **루프 방지 및 대역폭**| Spanning Tree (STP)로 링크 일부 차단 | L3 ECMP 라우팅으로 전 물리 경로 동시 활용 |
| **VM 마이그레이션** | 동일 L2 도메인 내부로 엄격히 제한 | L3 라우팅을 넘어 데이터센터/리전 간 이동 가능 |
| **제어 평면 메커니즘**| 데이터 평면 Flooding & MAC Learning | 멀티캐스트 또는 BGP EVPN (RFC 7432) |

- **BGP EVPN (Ethernet VPN) 제어 평면 연동** : 초기 멀티캐스트 기반 Flood-and-Learn의 비효율을 제거하고, MP-BGP를 통해 VTEP 간 MAC/IP 도달 정보를 사전에 배포함으로써 ARP 플러딩 억제 및 분산 애니캐스트 게이트웨이(Distributed Anycast Gateway) 구현.

## Ⅳ. VXLAN의 주요 한계점 및 해결 방안

- **50바이트 캡슐화 오버헤드로 인한 패킷 단편화(Fragmentation)** :
  - **한계점** : 표준 이더넷 MTU(1500바이트) 환경에서 50바이트가 추가되면 1550바이트가 되어 L3 언더레이에서 단편화가 발생, 라우터 CPU 폭증 및 성능 급락.
  - **해결 방안** : 언더레이 물리 네트워크 전 구간의 MTU를 점보 프레임(Jumbo Frame, 최소 1600~9000바이트 이상)으로 증설 구성.
- **초기 멀티캐스트 의존성에 따른 언더레이 설정 복잡도** :
  - **한계점** : BUM(Broadcast, Unknown Unicast, Multicast) 트래픽 처리를 위해 언더레이 IP 망에 PIM-SM/SSM 멀티캐스트 라우팅 설정이 강제되어 운영 부담 가중.
  - **해결 방안** : 표준 BGP EVPN을 제어 평면으로 전면 도입하여 인그레스 복제(Ingress Replication) 및 헤드엔드 복제(Head-End Replication)로 유니캐스트 전환.

## Ⅴ. VXLAN 적용 및 발전을 위한 기술사적 제언

- **하드웨어 VTEP(ToR 스위치) 기반 오프로딩** : 소프트웨어 vSwitch의 CPU 캡슐화 오버헤드를 경감하기 위해 상용 ASIC 스위치 칩셋(Broadcom 등) 또는 스마트 NIC(DPU) 기반 하드웨어 가속 의무화.
- **데이터센터 리프-스파인(Leaf-Spine) 아키텍처와의 표준 결합** : 스파인 스위치는 단순 초고속 IP 패킷 포워딩만 전담하고, 리프 스위치가 하드웨어 VTEP 및 BGP EVPN 게이트웨이를 수행하는 모던 패브릭 표준 정착.
- **DCI (Data Center Interconnect) 멀티 클라우드 연계** : 서로 다른 지리적 리전이나 이종 클라우드 데이터센터 간에 VXLAN 오버레이 터널을 연장하여 단일 L2 VPC 풀 구축 및 재해 복구(DR) 시 IP 변경 없는 서비스 즉시 절체 보장.
