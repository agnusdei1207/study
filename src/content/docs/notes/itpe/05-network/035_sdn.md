## 답안 골격
```text
[SDN] ◀━━ 머리: Ⅶ 내 의견 (클러스터링 컨트롤러 이중화 및 마이크로서비스 CNI 기반 SDN 오버레이 통합)
 ┃
 ┣━ Ⅰ 개요 ───── 장비별 분산 제어의 복잡성·비효율 극복 → 제어 평면과 데이터 평면의 분리
 ┣━ Ⅱ 특징 ───── 중앙 집중 제어, 네트워크 가상화, 개방형 인터페이스, 프로그래머블 자동화
 ┣━ Ⅲ 구조 ───── 응용 계층 + 노스바운드 API(REST) + 제어 계층(컨트롤러) + 사우스바운드 API(OpenFlow) + 인프라 계층(화이트박스)
 ┣━ Ⅳ 흐름 ───── ① 비즈니스 앱 정책 생성 → ② 노스바운드 전달 → ③ 컨트롤러 글로벌 뷰 경로 연산 → ④ 사우스바운드 플로우 주입
 ┣━ Ⅴ 비교 ───── 전통 네트워크 vs SDN vs NFV (분산 하드웨어 vs 제어 분리 vs 기능 소프트웨어화)
 ┗━ Ⅵ 실무 ───── 중앙 컨트롤러 단일 장애점(SPOF) / 컨트롤러-스위치 지연 / 대규모 세션 확장성 한계
```
- 필수 키워드: 제어/데이터 평면 분리 · 중앙 집중 컨트롤러 · 노스바운드 API · 사우스바운드 API · OpenFlow · 화이트박스 스위치
- 기출: 107회 `SDN 개념과 도입 효과` → Ⅰ·Ⅱ, 127회 `SDN 3계층 아키텍처, 인터페이스 및 전통망 비교` → Ⅲ·Ⅳ·Ⅴ

## 한 줄 본질
- 수백 대 네트워크 장비마다 일일이 접속해 분산 설정하던 운영 비효율과 벤더 락인 한계 → 라우팅 두뇌(제어 평면)를 중앙 소프트웨어 컨트롤러로 떼어내고 하드웨어 스위치는 단순 전달(데이터 평면)만 수행하도록 분리 → 네트워크 전체의 소프트웨어 프로그래밍 및 민첩한 자동화 달성 / 중앙 컨트롤러 장애 시 전체 망 마비 위험과 확장성 한계 발생

## 핵심 그림
```text
[ ONF 표준 SDN 3계층 참조 아키텍처 ]

  +-------------------------------------------------------------------+
  | 1. 응용 계층 (Application Layer)                                  |
  |    (클라우드 오케스트레이터, 보안 모니터링, 비즈니스 네트워크 앱) |
  +-------------------------------------------------------------------+
                                    | (노스바운드 API : RESTful, JSON)
                                    v
  +-------------------------------------------------------------------+
  | 2. 제어 계층 (Control Layer / SDN Controller)                     |
  |    (네트워크 글로벌 뷰 유지, 경로 연산, 플로우 테이블 규칙 생성)   |
  +-------------------------------------------------------------------+
                                    | (사우스바운드 API : OpenFlow, NETCONF, P4)
                                    v
  +-------------------------------------------------------------------+
  | 3. 인프라 계층 (Infrastructure Layer / Data Plane)                |
  |    (화이트박스 스위치, vSwitch, ASIC 기반 와이어스피드 패킷 포워딩)|
  +-------------------------------------------------------------------+
```

## 핵심 용어
- 제어 평면(Control Plane): 패킷이 어느 경로로 가야 할지 라우팅 알고리즘을 수행하고 포워딩 테이블을 계산하는 네트워크의 두뇌
- 데이터 평면(Data Plane / Forwarding Plane): 제어 평면이 내려준 규칙에 따라 실제 물리 포트 간에 패킷을 1초에 수억 개씩 고속 전달하는 손발
- 노스바운드 API(Northbound API): SDN 컨트롤러와 상위 비즈니스 응용 프로그램(클라우드 포털, 보안 관제)을 연결하는 표준 RESTful 인터페이스

## 핵심 통찰
- 전통 네트워크는 각 장비가 "자기 앞가림(분산 라우팅)"만 하므로 전체 네트워크 최적화가 불가능했으나, SDN은 중앙 컨트롤러가 "전체 망의 지도(Global Topology)"를 한눈에 보고 최적 경로를 한 번에 지시
- 고가의 독점 벤더(시스코 등) 어플라이언스 대신 저렴한 대만산 COTS 하드웨어("화이트박스 스위치")를 도입할 수 있어 인프라 구축비(CapEx) 획기적 절감
- 데이터센터 가상화에서 가상머신(VM)과 컨테이너가 이리저리 라이브 마이그레이션할 때, SDN 컨트롤러가 가상 오버레이 네트워크(VXLAN)를 즉시 재설정함으로써 클라우드 인프라의 필수 기반 제공

## 이웃 토픽과 구분
- SDN vs NFV: SDN은 제어권(Control)과 전달(Data)을 분리하여 중앙 관제 / NFV는 하드웨어 장비(방화벽, 라우터)를 가상머신/컨테이너 소프트웨어로 변환

## 문제·원인·대책
- 적용 상황: 대규모 멀티테넌트 데이터센터 SDN 인프라 장애
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 중앙 컨트롤러 다운 시 전체 네트워크 신규 통신 두절 | 컨트롤러 단일 장애점(SPOF) 및 집중화 리스크 | 분산 컨트롤러 클러스터링(Raft 합의 알고리즘 기반 HA) | 무중단 페일오버 및 컨트롤러 부하 분산 달성 |
| 수만 개 가상머신 생성 시 컨트롤러 응답 지연 | 대규모 패킷 인(Packet-In) 요청 집중으로 인한 병목 | 에이전트 기반 로컬 결정 및 BGP-EVPN 기반 분산 제어 결합 | 컨트롤러 부하를 엣지로 분산시켜 10만 노드 확장성 확보 |

## 이렇게 출제된다
- 제107회 1교시: "SDN(Software Defined Networking)의 개념과 특징을 설명하시오." → 요구 포인트: Ⅰ 개념 + Ⅱ 분리 특징
- 제127회 1교시: "SDN의 구성요소 및 인터페이스를 설명하시오." → 요구 포인트: Ⅲ 3계층 아키텍처 다이어그램 + 노스바운드/사우스바운드 API 역할 서술

## 내 의견
- [순수 OpenFlow 중앙 집중형에서 BGP-EVPN 실용적 SDN으로의 진화] 모든 패킷을 중앙에서 소프트웨어로 통제하려던 초기 SDN은 대규모망에서 제어 채널 지연과 복잡도로 실무 정착에 고전 → 나라면: 표준 BGP 프로토콜을 제어 평면으로 재활용하는 BGP-EVPN 기술을 데이터센터 패브릭에 적용하고, 컨트롤러는 선언형 정책 배포에 집중하는 "하이브리드 SDN" 아키텍처를 도입하여 엔터프라이즈 안정성 극대화
