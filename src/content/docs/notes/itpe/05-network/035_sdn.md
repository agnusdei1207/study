## 30초 인출

- 본질: **SDN(Software-Defined Networking)** : 네트워크 제어 기능과 패킷 전달 기능을 분리해 소프트웨어 기반으로 관리하는 구조
- 메커니즘: 응용 정책 → 컨트롤러의 제어 로직 → 제어 인터페이스로 네트워크 장비 구성·전달 동작 제어
- 통찰: 전통적 하드웨어 장비에 밀결합되어 있던 제어 평면(Control Plane)과 데이터 평면(Data Plane)을 물리적으로 분리하고, 소프트웨어 기반 중앙 집중형 컨트롤러를 통해 전사 네트워크를 동적으로 프로그래밍하는 네트워크 혁신 아키텍처임.

<summary>핵심 용어</summary>

- **SDN(Software-Defined Networking)** : 제어·관리 기능과 네트워크 자원 전달 기능을 분리·프로그래밍 가능하게 구성하는 접근
- **제어 평면(Control Plane)** : 경로·정책을 결정하고 전달 상태를 제어하는 기능
- **데이터 평면(Data Plane)** : 패킷을 수신·처리·전달하는 기능
- **SDN 컨트롤러(SDN Controller)** : 응용 요구와 네트워크 자원 사이에서 제어 로직·상태를 관리하는 기능
- **노스바운드 인터페이스(Northbound Interface)** : SDN 응용과 컨트롤러 간 추상화·제어 인터페이스
- **사우스바운드 인터페이스(Southbound Interface)** : 컨트롤러와 네트워크 요소 간 제어 인터페이스
- **OpenFlow(OpenFlow Switch Protocol)** : 플로우 테이블을 관리하는 컨트롤러-스위치 프로토콜의 한 종류
- **P4(P4 Programming Language)** : 패킷 처리 데이터 평면을 정의하는 프로그래밍 언어; 컨트롤러 인터페이스 자체와 구별

## 2~4교시 25점 답안

## Ⅰ. SDN(Software Defined Network)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 네트워크 장비의 패킷 전달 기능(데이터 평면)과 경로 제어 기능(제어 평면)을 물리적으로 분리하고, 개방형 표준 API를 통해 소프트웨어 컨트롤러가 네트워크 전체를 중앙 집중식으로 제어하는 아키텍처 |
| 목적 | 벤더 종속 탈피, 복잡한 분산 라우팅 프로토콜 설정 비용 절감, 애플리케이션 요구에 맞춘 실시간 네트워크 가상화 및 프로그래밍 자동화 |

## Ⅱ. SDN(Software Defined Network)의 특징

| 특징 | 상세 내용 |
|---|---|
| 제어/전달 평면 분리 | 값비싼 전용 라우터 대신 단순화된 화이트박스 스위치와 고성능 x86 서버 상의 컨트롤러로 이원화 |
| 중앙 집중식 논리 제어| 전사 네트워크의 전체 토폴로지 정보를 컨트롤러가 실시간 유지하여 전역 최적 라우팅 수행 |
| 개방형 인터페이스 | 사우스바운드(OpenFlow, P4, NETCONF) 및 노스바운드(RESTful API)를 통해 이기종 연동 보장 |
| 네트워크 가상화 | 단일 물리 인프라 위에 서로 다른 정책과 격리도를 갖는 논리적 가상 네트워크(슬라이스) 구축 |

## Ⅲ. SDN(Software Defined Network)의 체계·프로세스

**SDN 3계층 아키텍처 및 인터페이스 체계**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ SDN 3계층 표준 아키텍처 ]                     │
│                                                                        │
│ [ 응용 계층 (Application Layer) ]                                      │
│   - 비즈니스 앱, 방화벽/보안 정책, 트래픽 엔지니어링, 클라우드 CMP      │
│                                │                                       │
│                                ▼ Northbound API (RESTful, Intent API)  │
│ [ 제어 계층 (Control Layer) : SDN Controller ]                         │
│   - 네트워크 운영체제 (NOS: ONOS, OpenDaylight)                        │
│   - 전역 토폴로지 관리, 최적 경로 연산, 플로우 룰 생성/스케줄링        │
│                                │                                       │
│                                ▼ Southbound API (OpenFlow, P4, gNMI)   │
│ [ 인프라 계층 (Infrastructure / Data Layer) ]                          │
│   - 화이트박스 스위치, 가상 스위치(OVS) : 순수 패킷 포워딩 전용        │
│   - Flow Table 기반 와이어스피드 패킷 스위칭                           │
└────────────────────────────────────────────────────────────────────────┘
```

| 계층 구분 | 주요 구성요소 | 핵심 역할 및 기능 |
|---|---|---|
| **응용 계층** | 비즈니스 애플리케이션, 클라우드 포털 | 네트워크를 사용하는 상위 서비스 요구를 컨트롤러에 정책으로 전달 |
| **Northbound API** | REST API, gRPC, Java API | 컨트롤러의 기능을 애플리케이션이 프로그래밍할 수 있도록 추상화 제공 |
| **제어 계층** | SDN Controller (NOS) | 네트워크의 두뇌로서 전역 뷰 유지, 플로우 룰 계산 및 인프라 상태 수집 |
| **Southbound API** | OpenFlow, P4, NETCONF/YANG, OVSDB | 컨트롤러의 명령을 스위치에 주입하고 스위치의 이벤트(Packet-in)를 수신 |
| **인프라 계층** | 물리/가상 스위치 (COTS Hardware)| 상위 지시(Flow Table)에 따라 패킷을 매칭하고 고속 포워딩만 수행 |

## Ⅳ. SDN(Software Defined Network)의 종류·비교

| 비교 항목 | 전통적 네트워크 (Traditional) | 소프트웨어 정의 네트워크 (SDN) |
|---|---|---|
| **제어 구조** | 장비마다 개별 분산 제어 (Decentralized) | **중앙 집중형 논리적 제어 (Centralized)** |
| **평면 구조** | 제어 평면과 데이터 평면이 단일 박스에 밀결합| **제어 평면과 데이터 평면의 완전한 물리적 분리**|
| **장비 종속성** | 벤더 전용 블랙박스 OS 종속 | **상용 화이트박스 스위치(COTS) 활용 가능** |
| **설정 방식** | 관리자가 장비마다 개별 CLI 접속 수동 설정 | **컨트롤러 API를 통한 전사 일괄 자동 프로그래밍** |
| **트래픽 제어** | 홉 바이 홉(Hop-by-hop) 분산 최적화 | **전역 토폴로지 맵 기반 E2E 최적 트래픽 엔지니어링**|

## Ⅴ. SDN(Software Defined Network)의 한계와 방안

| 한계 | 방안 |
|---|---|
| 중앙 집중형 제어 구조로 인해 대규모 망에서 초당 수백만 개 신규 플로우 요청 시 컨트롤러 CPU 포화 및 제어 평면 병목 현상 | P4(Programming Protocol-independent Packet Processors) 기반 데이터 평면 자체 프로그래밍 및 인라인 상태 유지(Stateful In-network Processing) 분산화 |
| 제어 평면(Control Plane) API 침해 또는 가짜 플로우 룰 주입 공격 시 전사 망 트래픽의 대규모 도청·블랙홀링 발생 | 사우스바운드 TLS 상호 인증 강제, 제어 채널 전용 OOB(Out-of-Band) 물리 격리망 구축 및 제로 트러스트 플로우 무결성 검증 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
엔터프라이즈 데이터센터 및 클라우드 패브릭 구축 시, 컨트롤러 단일 장애점(SPOF)을 방지하기 위해 최소 3노드 이상의 분산 컨트롤러 클러스터를 Raft 분산 합의 알고리즘으로 구성하고, 물리 언더레이(Underlay)망은 BGP EVPN 기반 표준 패브릭으로 견고화.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ SDN과 NFV의 상호 보완 협력 아키텍처 ]                                │
│                                                                        │
│   NFV : "가상 네트워크 기능을 어디에 띄울 것인가?" (기능 가상화)        │
│          vFirewall, vRouter, vLoadBalancer를 범용 서버에 VM/컨테이너로 배포│
│                                │                                       │
│                                ▼ 상호 협력                             │
│   SDN : "가상화된 기능들 사이로 트래픽을 어떻게 보낼 것인가?" (경로 제어)│
│          서비스 기능 체이닝(SFC)을 통해 vFW ──► vWAF ──► vLB로 패킷 안내 │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| SDN 컨트롤러 오픈소스 | 주 개발 언어 | 핵심 특징 | 주 적용 분야 |
|---|---|---|---|
| **ONOS** | Java | 통신사 수준 고가용성, 분산 확장성, 고성능 | 텔코 코어망, 5G 백홀 |
| **OpenDaylight (ODL)**| Java | 방대한 플러그인, 레거시 프로토콜(BGP/SNMP) 지원 | 엔터프라이즈, 멀티벤더 데이터센터 |
| **Ryu** | Python | 경량화, 빠른 프로토타이핑, 학습 용이성 | 연구소, 학술망, 소규모 PoC |
