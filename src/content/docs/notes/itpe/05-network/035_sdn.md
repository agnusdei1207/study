## 연관 키워드

- SDN(Software-Defined Networking), 제어 평면, 데이터 평면
- SDN 컨트롤러, 노스바운드 API, 사우스바운드 API
- 화이트박스 스위치, 오버레이 가상화, NFV, 마이크로 세그멘테이션

## Ⅰ. SDN의 개요

- 핵심 요약 : 장비에 묶인 경로 결정 기능을 중앙 소프트웨어로 분리해 네트워크 전체를 프로그래밍하는 아키텍처.
- 개념 : 각 장비 내부에 통합되어 있던 **제어 평면** (Control Plane, 경로 결정 기능)과 **데이터 평면** (Data Plane, 패킷 전달 기능)을 분리하고, 중앙의 소프트웨어 컨트롤러가 개방형 인터페이스로 전체 망을 동적으로 제어하는 **SDN** (Software-Defined Networking) 아키텍처.
- 배경 및 필요성 : 제조사별 폐쇄 CLI(Command-Line Interface)와 독점 하드웨어로 벤더 종속이 고착됐고, 클라우드에서 가상 머신과 컨테이너가 빠르게 생성·이동하는 트래픽을 수동 설정 기반의 정적 망으로는 수용할 수 없었음.
- 주요 목적 : 정책 변경의 자동화와 프로그래밍 가능성 확보, 범용 장비 기반 구성에 따른 장비 종속 완화와 비용 절감.

## Ⅱ. SDN의 특징 및 장점

- 핵심 요약 : 평면 분리, 개방형 인터페이스, 중앙 제어, 범용 하드웨어가 정책 자동화와 장비 선택의 자유로 이어지는 구조.

1. 평면 분리 : 경로 결정은 컨트롤러가, 패킷 전달은 스위치가 각각 전담 → 정책 변경을 소프트웨어로 일괄 적용.
2. 개방형 인터페이스 : 상위 응용은 **노스바운드 API** (Northbound API)로 망 자원을 요청하고, 하위 장비는 **사우스바운드 API** (Southbound API)로 포워딩 규칙을 수신 → 응용과 장비 양단에서 자동화 가능.
3. 중앙 제어의 전역 시야 : **SDN 컨트롤러**가 전체 토폴로지와 트래픽 상태를 통합 파악 → 장비 단위 설정의 불일치 해소와 일관된 정책 집행.
4. 범용 하드웨어 활용 : 개방형 네트워크 OS를 얹은 **화이트박스 스위치** (White-box Switch) 구성 → 특정 벤더 종속 완화와 장비 선택 폭 확대.
5. 오버레이 연계 : VXLAN(Virtual Extensible LAN) 같은 **오버레이 가상화** (Overlay Virtualization) 터널을 필요 시점에 생성 → 테넌트별 격리와 자원 배포 속도 향상.

## Ⅲ. SDN의 구조 (흐름)

- 핵심 요약 : 응용·제어·인프라 3계층이 노스바운드·사우스바운드 인터페이스로 수직 연동하는 구조.

```text
[ SDN 3계층 구조 ]

응용 계층 (오케스트레이터·모니터링·보안 앱)
    ↓ 노스바운드 API (REST 등)
제어 계층 (SDN 컨트롤러 클러스터)
    ↓ 사우스바운드 API (OpenFlow·NETCONF 등)
인프라 계층 (스위치의 전달 평면)
```

- SDN 컨트롤러 : OpenDaylight, ONOS 같은 오픈소스 플랫폼이 대표적이며, 클러스터 구성으로 전역 상태를 공유하는 망 운영체제 역할을 수행함.

```text
[ 정책 변경 처리 흐름 ]

응용의 정책 요청 접수
    ↓ 전역 토폴로지 기반 경로 계산
포워딩 규칙 산출
    ↓ 규칙의 장비 배포
각 스위치 규칙 설치 후 고속 전달
```

## Ⅳ. SDN과 전통 네트워크·NFV의 비교

- 핵심 요약 : SDN은 경로의 프로그래밍을, NFV는 경로 위 기능의 가상화를 담당해 상호 보완 관계.

| 비교 항목 | 전통적 네트워크 | SDN | NFV(Network Functions Virtualisation) |
| --- | --- | --- | --- |
| 제어 위치 | 각 장비에 분산 | 중앙 컨트롤러 | 가상 인프라 관리자와 연동 |
| 장비 기반 | 벤더 전용 하드웨어·OS | 개방형 화이트박스 | 범용 서버 가상화 |
| 제어 수단 | 벤더별 CLI 수동 설정 | 개방형 API 자동화 | 가상 기능의 자동 배포 |
| 주요 초점 | L2~L3 패킷 전달 | L2~L4 경로 프로그래밍 | 방화벽·로드밸런서 등 L4~L7 기능 |
| 변경 주기 | 장비 단위 수동 작업 | 정책 기반 일괄 변경 | 인스턴스 단위 신속 교체 |

- 선택 기준 : 경로 제어의 자동화가 목적이면 SDN을, 보안·전달 기능의 소프트웨어화가 목적이면 NFV를 적용하고, 두 기술의 결합으로 가상망을 완성함.

## Ⅴ. SDN의 한계와 방안

- 핵심 요약 : 컨트롤러 단일 장애점, 제어 채널 병목, 제어 평면 보안 위협을 클러스터링과 규칙 선주입, 상호 인증으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 컨트롤러 단일 장애점 | 컨트롤러 장애 시 신규 흐름 처리와 망 관리가 전면 중단 | 다중 노드 클러스터링과 합의 알고리즘 기반 이중화 | 컨트롤러 가용률 |
| 제어 채널 병목 | 다수 스위치의 동시 규칙 요청으로 제어 트래픽 집중 | 컨트롤러 계층 분할과 사전 규칙 주입으로 요청량 절감 | 플로우 설정 지연 시간 |
| 제어 채널 침해 | 포워딩 규칙 조작으로 트래픽 탈취·유출 | 컨트롤러-스위치 상호 인증과 관리망 분리 | 인증서 적용률 |

## Ⅵ. SDN에 대한 기술사적 제언

- 핵심 요약 : 데이터센터 패브릭을 시작점으로 개방형 운영체계를 확산하고, 자동화의 전제 조건을 설계 원칙으로 고정하는 방향.

1. 데이터센터 운영 조직은 BGP(Border Gateway Protocol) 기반 EVPN(Ethernet VPN)과 VXLAN을 패브릭 기반으로 두고, SDN 오케스트레이션으로 테넌트 가상망을 자동 배포하는 체계를 구축할 필요가 있음.
2. 인프라 담당 부서는 화이트박스 스위치와 SONiC(Software for Open Networking in the Cloud) 같은 개방형 네트워크 OS를 시험 환경에서 검증한 뒤 단계 도입해 총소유비용(TCO, Total Cost of Ownership)을 낮춰야 함.
3. 보안 조직은 SDN의 세밀한 플로우 제어를 활용해 동일 세그먼트 안의 워크로드 간 통신에도 정책을 적용하는 마이크로 세그멘테이션(micro-segmentation)을 제로 트러스트 전환의 수단으로 채택해야 함.

## Ⅶ. 결론

- 핵심 요약 : SDN은 제어와 전달의 분리를 통해 네트워크를 소프트웨어 자산으로 전환하는 아키텍처임.
- 시사점 : 망의 민첩성은 컨트롤러의 신뢰성과 제어 채널 보안이 뒷받침될 때 비로소 성과로 이어짐.
