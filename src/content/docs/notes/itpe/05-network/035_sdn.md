## 연관 키워드

- SDN(Software-Defined Networking), 제어 평면, 데이터 평면, 노스바운드 API, 사우스바운드 API
- 화이트박스 스위치, 오버레이 가상화, NETCONF, SONiC, NFV, 마이크로 세그멘테이션

## Ⅰ. SDN(Software-Defined Networking)의 개요

- 핵심 요약 : 제어 평면을 중앙 소프트웨어 컨트롤러로 분리하고 개방형 API로 네트워크 전체를 프로그래밍하는 아키텍처.
- 개념 : 장비 내부에 묶여 있던 **제어 평면** (Control Plane)과 **데이터 평면** (Data Plane)을 분리하고, 중앙 소프트웨어 컨트롤러가 개방형 API로 네트워크 전체를 동적으로 프로그래밍·관리하는 **소프트웨어 정의 네트워킹** (SDN, Software-Defined Networking) 아키텍처.
- 배경 및 필요성 : 제조사별 독점 CLI(Command-Line Interface)와 폐쇄형 하드웨어로 벤더 락인이 고착되었고, 클라우드 환경에서 가상 머신과 컨테이너가 빠르게 생성·이동하는 트래픽을 수동 설정의 정적 네트워크로는 수용할 수 없게 되었음.
- 주요 목적 : 제어의 중앙 집중화와 프로그래밍 가능성 확보, 인프라 민첩성 향상, **화이트박스 스위치** (White-box Switch) 도입을 통한 자본적 지출(CAPEX, Capital Expenditure)과 운영 비용(OPEX, Operating Expenditure) 절감.

## Ⅱ. SDN(Software-Defined Networking)의 특징 및 장점

- 핵심 요약 : 제어와 전달의 분리, 개방형 API, 범용 하드웨어가 정책 변경의 자동화와 장비 종속 완화로 이어지는 구조.

1. 제어·전달 분리 : 라우팅 결정은 중앙 컨트롤러가 전담하고 스위치는 전달 규칙만 수행 → 정책 변경을 소프트웨어로 일괄 적용.
2. 개방형 API : **노스바운드 API** (Northbound API)로 상위 응용이 네트워크 자원을 요청하고, **사우스바운드 API** (Southbound API)로 장비에 포워딩 규칙을 설치(OpenFlow, P4(Programming Protocol-independent Packet Processors) 등) → 응용과 장비 양쪽에서 자동화가 가능.
3. 범용 하드웨어 기반 : 소프트웨어를 얹은 범용 장비를 사용하는 화이트박스 구성 → 특정 벤더 종속 완화와 장비 선택 폭 확대.
4. 동적 가상화 연계 : VXLAN(Virtual Extensible LAN), Geneve 같은 **오버레이 가상화** (Overlay Virtualization) 터널을 필요할 때 생성 → 테넌트별 격리와 클라우드 자원의 신속한 배포.

## Ⅲ. SDN(Software-Defined Networking)의 구조 (흐름)

- 핵심 요약 : 응용 계층, 제어 계층, 인프라 계층의 3계층이 노스바운드와 사우스바운드 API로 수직 연동되는 구조.

```text
[ 응용 계층 ]
  클라우드 오케스트레이터, 모니터링, 보안 앱
      ↓ 노스바운드 API (RESTful)
[ 제어 계층 ]
  SDN 컨트롤러 (전역 토폴로지·경로 계산)
      ↓ 사우스바운드 API (OpenFlow, P4 등)
[ 인프라 계층 ]
  화이트박스 스위치 (전달 평면)
```

- **SDN 컨트롤러** (NOS, Network Operating System) : 네트워크 전체의 토폴로지와 상태를 중앙에서 추상화하여 관리하고, 하위 스위치에 포워딩 규칙을 실시간으로 주입하는 소프트웨어.
- 인프라 계층은 ASIC(Application-Specific Integrated Circuit) 기반의 고속 패킷 전달만 맡으며, 실제 구현에서는 OVS(Open vSwitch)나 스마트NIC도 이 계층에 포함됨.

```text
[ 정책 변경 요청 ]
      ↓ 노스바운드 API
[ SDN 컨트롤러 ] 전역 토폴로지에서 경로 계산
      ↓ 사우스바운드 API
[ 스위치 ] 규칙 설치 후 고속 전달
```

## Ⅳ. SDN(Software-Defined Networking)의 비교

- 핵심 요약 : SDN은 경로 프로그래밍을, NFV는 경로 위 기능의 가상화를 담당하여 두 기술이 상호 보완하는 관계.

| 비교 항목 | 전통적 네트워크 | SDN | NFV(Network Functions Virtualisation) |
| --- | --- | --- | --- |
| 제어 평면 구조 | 각 장비에 분산 탑재 | 중앙 집중식 소프트웨어 컨트롤러 | 가상 인프라 관리자(VIM, Virtualised Infrastructure Manager) 연동 |
| 장비 종속성 | 특정 벤더 하드웨어와 OS(Operating System)에 종속 | 개방형 화이트박스 스위치 활용 | 범용 COTS(Commercial Off-the-Shelf) 서버 가상화 |
| 제어 프로토콜 | BGP(Border Gateway Protocol), OSPF(Open Shortest Path First) | OpenFlow, P4, NETCONF, REST(Representational State Transfer) API | OpenStack, Kubernetes CNI(Container Network Interface) |
| 주요 초점 | L2~L3 패킷 전달 | L2~L4 스위칭과 라우팅의 중앙 프로그래밍 | 방화벽(FW, Firewall), 로드 밸런서(LB, Load Balancer) 같은 L4~L7 기능 가상화 |
| 변경 방식 | 수동 CLI 적용으로 변경 주기가 김 | API 기반 동적 자동화 | VM과 컨테이너의 자동 배포 |

- 상호 보완 : SDN이 트래픽 경로를 소프트웨어로 프로그래밍하면, NFV는 그 경로 위에서 실행되는 보안과 L4 기능 자체를 가상화하여 유연성을 완성함.

## Ⅴ. SDN(Software-Defined Networking)의 한계와 방안

- 핵심 요약 : 컨트롤러 단일 장애점, 제어 채널 확장성, 제어 평면 보안 문제를 클러스터링, 규칙 선주입, 상호 인증으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 컨트롤러 단일 장애점 (SPoF, Single Point of Failure) | 단일 컨트롤러 다운 시 신규 흐름 처리가 멈추고 망 관리가 전면 단절 | ONOS, OpenDaylight 같은 클러스터링과 Raft 합의 알고리즘 기반 HA(High Availability) 구성 | 컨트롤러 가용률 |
| 제어 채널 확장성 병목 | 대규모 스위치가 동시에 Packet-In을 보내 제어 트래픽이 몰리고 응답이 지연 | 계층적 컨트롤러 분할, 사전(Proactive) 규칙 주입, P4 기반 분산 처리 도입 | 플로우 셋업 지연 |
| 제어 평면 도청과 위변조 | 제어 채널이 침해되면 포워딩 규칙이 조작되어 트래픽 탈취와 중간자 공격(MITM, Man-in-the-Middle) 발생 | 컨트롤러와 스위치 간 상호 TLS(Mutual TLS) 인증 강제, 제어 전용 대역 외(Out-of-band) 관리망 분리 | 인증서 적용률 |

## Ⅵ. SDN(Software-Defined Networking)에 대한 기술사적 제언

- 핵심 요약 : 데이터센터 패브릭부터 자동화를 단계적으로 넓히되, 컨트롤러 가용성과 제어 채널 보안을 설계 원칙으로 고정하는 것이 바람직함.
- Leaf-Spine 데이터센터 패브릭에는 BGP(Border Gateway Protocol) 기반 EVPN(Ethernet VPN)과 VXLAN을 기반 제어로 두고, SDN 오케스트레이션으로 테넌트 가상 네트워크를 자동 배포하면 운영 자동화 효과를 얻을 수 있음.
- 화이트박스 스위치와 SONiC(Software for Open Networking in the Cloud) 같은 개방형 네트워크 OS를 검증한 뒤 도입하면 특정 벤더 종속을 줄이고 총소유비용(TCO, Total Cost of Ownership)을 낮출 수 있음.
- SDN의 세밀한 플로우 제어를 활용해 동일 서브넷 안의 워크로드 사이에도 L4 정책을 적용하면, 제로 트러스트 원칙에 맞는 마이크로 세그멘테이션 구현이 가능함.

## Ⅶ. 결론

- 핵심 요약 : SDN은 제어와 전달을 분리해 네트워크를 소프트웨어로 프로그래밍하는 체계이며, NFV와 결합해 인프라 전반의 민첩성을 완성하는 기반 기술임.
- 시사점 : 자동화의 이득은 컨트롤러의 가용성과 제어 채널 보안이 전제될 때만 유지되므로, 도입 범위를 넓히기 전에 이 두 조건을 먼저 검증하는 것이 타당함.
