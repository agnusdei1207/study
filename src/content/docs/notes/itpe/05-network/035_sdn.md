## 30초 인출

- 본질: **SDN(Software-Defined Networking)** : 네트워크 제어 기능과 패킷 전달 기능을 분리해 소프트웨어 기반으로 관리하는 구조
- 메커니즘: 응용 정책 → 컨트롤러의 제어 로직 → 제어 인터페이스로 네트워크 장비 구성·전달 동작 제어

<details>
<summary>핵심 용어</summary>

- **SDN(Software-Defined Networking)** : 제어·관리 기능과 네트워크 자원 전달 기능을 분리·프로그래밍 가능하게 구성하는 접근
- **제어 평면(Control Plane)** : 경로·정책을 결정하고 전달 상태를 제어하는 기능
- **데이터 평면(Data Plane)** : 패킷을 수신·처리·전달하는 기능
- **SDN 컨트롤러(SDN Controller)** : 응용 요구와 네트워크 자원 사이에서 제어 로직·상태를 관리하는 기능
- **노스바운드 인터페이스(Northbound Interface)** : SDN 응용과 컨트롤러 간 추상화·제어 인터페이스
- **사우스바운드 인터페이스(Southbound Interface)** : 컨트롤러와 네트워크 요소 간 제어 인터페이스
- **OpenFlow(OpenFlow Switch Protocol)** : 플로우 테이블을 관리하는 컨트롤러-스위치 프로토콜의 한 종류
- **P4(P4 Programming Language)** : 패킷 처리 데이터 평면을 정의하는 프로그래밍 언어; 컨트롤러 인터페이스 자체와 구별

</details>

## 1교시 10점 답안

### Ⅰ. SDN의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **SDN** : 제어 기능과 패킷 전달 기능을 분리해 소프트웨어 기반으로 관리하는 네트워크 구조 |
| 목적 | 네트워크 제어·운영의 추상화와 자동화 지원 |

### Ⅱ. 주요 계층·인터페이스

```text
SDN 응용
    │ 노스바운드 인터페이스

네트워크 요소 · 데이터 평면
```

- 제언: 제어 기능의 추상화와 전달 장비의 역할을 구분하는 SDN 설계.

---

## 2~4교시 25점 답안

### Ⅰ. SDN의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **SDN** : 제어 기능과 패킷 전달 기능을 분리해 소프트웨어 기반으로 관리하는 네트워크 구조 |
| 목적 | 네트워크 제어·운영의 추상화와 자동화 지원 |

### Ⅱ. 주요 계층·인터페이스

```text
SDN 응용
    │ 노스바운드 인터페이스
SDN 컨트롤러 · 제어 평면
    │ 사우스바운드 인터페이스
네트워크 요소 · 데이터 평면
```

논리적으로 제어 기능을 분리하더라도 컨트롤러의 물리 배치는 중앙형·분산형 등 여러 구현 가능. 인터페이스도 반드시 REST/JSON 또는 OpenFlow 한 가지로 한정되지 않음.

### Ⅲ. 계층별 역할

| 구성 | 역할 | 예시 |
|---|---|---|
| 응용 평면 | 업무·운영 목적과 네트워크 정책 표현 | 트래픽 엔지니어링, 보안 정책 |
| 제어 평면 | 네트워크 상태·정책에 따라 제어 동작 계산 | 경로·플로우·자원 관리 |
| 데이터 평면 | 실제 패킷 처리·전달 | 물리 스위치, 가상 스위치, 라우터 |

### Ⅳ. 인터페이스와 제어 흐름

```text
응용 요구·정책
       ↓
컨트롤러 상태·정책 처리
       ↓ 장비별 제어
네트워크 요소 ──→ 패킷 전달
       ↑ 상태·측정 보고
컨트롤러
```

노스바운드·사우스바운드 인터페이스의 구체 프로토콜은 구현에 따라 달라지며, P4 언어와 P4Runtime API처럼 역할이 서로 다른 기술을 혼동하지 않아야 함.

### Ⅴ. SDN과 NFV 비교

| 관점 | SDN | NFV |
|---|---|---|
| 분리·가상화 초점 | 제어·전달 기능 분리와 소프트웨어 제어 | 네트워크 기능과 전용 장비의 분리 |
| 핵심 대상 | 제어 로직·네트워크 자원 | 가상 네트워크 기능·실행 인프라 |
| 관계 | 정책에 따라 NFV 기능을 연결·제어 가능 | SDN 기반 네트워크를 이용할 수 있음 |

### Ⅵ. 한계와 대응

| 한계 | 대응 |
|---|---|
| 컨트롤러·제어 채널 장애 영향 | 분산·이중화 구조, 로컬 지속 동작·복구 정책 시험 |
| 서로 다른 장비·인터페이스의 기능 차이 | 지원 기능·버전·추상화 수준에 대한 상호운용 시험 |
| 중앙 정책 오류의 넓은 영향 범위 | 변경 검증·승인·롤백과 제한된 배포 단위 운영 |
| 운영 자동화가 기존 장애 도메인과 맞지 않음 | 토폴로지·권한·장애 시 경계를 반영한 운영 모델 설계 |

### Ⅶ. 기술사적 제언

| 우선 적용 | 실행·확인 |
|---|---|
| 통합 제어의 실익이 명확한 네트워크 영역부터 SDN 전환 | 장비 호환성·제어 채널 복구·정책 오류 범위를 시험하고 점진 확대 |
