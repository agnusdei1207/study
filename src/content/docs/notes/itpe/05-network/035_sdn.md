## Ⅰ. SDN(Software Defined Network)의 개요

- 개념 : 전통적인 네트워크 라우터 및 스위치 하드웨어에 강결합되어 있던 제어 평면(Control Plane)과 데이터 전달 평면(Data Plane)을 물리적으로 분리하고, 개방형 표준 API(Application Programming Interface)를 통해 **중앙 집중식 소프트웨어 컨트롤러**로 네트워크 전체를 동적으로 프로그래밍·관리하는 네트워크 아키텍처.
- 배경 및 필요성 : 장비 제조사별 독점적 CLI(Command-Line Interface)와 폐쇄형 하드웨어로 인한 벤더 락인(Lock-in), 클라우드 가상화 환경에서 수천 대의 VM(Virtual Machine)/컨테이너가 초단위로 생성·이동하는 동적 트래픽을 정적 네트워크 설정으로 수용할 수 없는 구조적 한계를 극복하기 위해 등장함.
- 핵심 목적 : 네트워크 제어의 중앙 집중화 및 **프로그래밍 가능성(Programmability)** 확보, 인프라 민첩성(Agility) 향상, **화이트박스(White-box)** 스위치 도입을 통한 하드웨어 CAPEX(Capital Expenditure)/OPEX(Operating Expenditure) 절감.

## Ⅱ. SDN(Software Defined Network)의 핵심 아키텍처 및 동작 메커니즘

SDN(Software-Defined Networking)은 응용 계층, 제어 계층, 인프라 계층의 3단계 구조로 구성되며, 노스바운드 API(RESTful)와 사우스바운드 API(OpenFlow, P4, NETCONF)를 통해 수직적으로 연동 동작함.

```text
[ SDN 3계층 아키텍처 및 인터페이스 체계 ]

+-----------------------------------------------------------------+
| 응용 계층 (Application Layer): 비즈니스 네트워크 앱             |
| - 클라우드 오케스트레이터 (OpenStack, K8s), 모니터링, L4~L7 보안|
+---------------------------------│────────────────---------------+
                                  │ 노스바운드 API (Northbound: RESTful)
                                  ▼
+-----------------------------------------------------------------+
| 제어 계층 (Control Layer): 중앙 집중식 SDN 컨트롤러            |
| - 네트워크 운영체제 (NOS: ONOS, OpenDaylight)                   |
| - 전역 토폴로지 유지, 최적 경로 계산, 정책 제어 엔진            |
+---------------------------------│────────────────---------------+
                                  │ 사우스바운드 API (Southbound: OpenFlow, P4)
                                  ▼
+-----------------------------------------------------------------+
| 인프라 계층 (Infrastructure Layer): 전달 평면 (Data Plane)      |
| - 순수 고속 패킷 포워딩만 수행 (ASIC 기반 라인레이트 포워딩)   |
| - COTS 화이트박스 스위치, OVS(Open vSwitch), 스마트NIC           |
+-----------------------------------------------------------------+
```

- **제어 평면과 데이터 평면 분리** : 라우팅 결정(Routing Logic)은 중앙의 소프트웨어 컨트롤러가 전담하고, 물리 스위치는 오직 전달 규칙(Forwarding Engine)만 수행.
- **SDN 컨트롤러(Network Operating System)** : 네트워크 전체의 토폴로지와 상태 정보를 중앙에서 추상화하여 관리하며, 하위 스위치에 플로우 포워딩 테이블을 실시간 주입.
- **노스바운드 API(Northbound API)** : 상위 비즈니스 애플리케이션 및 클라우드 관리 플랫폼이 네트워크 자원을 온디맨드로 동적 요청할 수 있는 RESTful 표준 인터페이스.
- **사우스바운드 API(Southbound API)** : 컨트롤러가 하위 인프라 스위치와 통신하여 포워딩 규칙을 프로그래밍하는 프로토콜(OpenFlow, NETCONF/YANG, P4Runtime, OVSDB).
- **오버레이 가상화(Overlay Network)** : 언더레이 물리 네트워크 위에 VXLAN(Virtual Extensible LAN), Geneve 터널을 SDN으로 동적 생성하여 대규모 멀티테넌시 완벽 격리.

## Ⅲ. SDN(Software Defined Network)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 전통적 네트워크 (Traditional) | 소프트웨어 정의 네트워킹 (SDN) | 네트워크 기능 가상화 (NFV, Network Functions Virtualisation) |
|---|---|---|---|
| 제어 평면 구조 | 각 스위치/라우터에 분산 탑재 | 중앙 집중식 소프트웨어 컨트롤러 | 가상 인프라 관리자 (VIM) 연동 |
| 장비 종속성 | 특정 벤더 하드웨어/OS(Operating System) 종속 | 개방형 화이트박스 스위치 활용 | 범용 COTS(Commercial Off-the-Shelf) x86 서버 가상화 |
| 제어 프로토콜 | BGP(Border Gateway Protocol), OSPF(Open Shortest Path First), 분산 시그널링 | OpenFlow, P4, NETCONF, REST(Representational State Transfer) API| OpenStack, Kubernetes CNI |
| 초점 영역 | L2~L3 포워딩 패킷 전달 | L2~L4 스위칭/라우팅 중앙 프로그래밍| L4~L7 어플라이언스 (FW, LB) 가상화|
| 구성 변경 속도 | 수동 CLI 적용 (수 일~수 주) | API 기반 동적 자동화 (수 초) | VM/컨테이너 자동 배포 (수 분) |

- SDN과 NFV는 상호 보완적 관계로, SDN이 네트워크 트래픽 경로를 소프트웨어로 프로그래밍한다면 NFV는 그 경로 상에서 실행되는 보안/L4 기능 자체를 가상화하여 유연성을 완성함.

## Ⅳ. SDN(Software Defined Network)의 주요 한계점 및 해결 방안

- 중앙 집중식 컨트롤러 장애 시 전체 망 마비 위험(단일 장애점 SPoF) :
  - 한계점 : 단일 컨트롤러 다운 시 신규 플로우 처리 불가 및 네트워크 관리 전면 단절.
  - 해결 방안 : 분산 아키텍처 기반의 컨트롤러 클러스터링(ONOS, OpenDaylight) 및 Raft 합의 알고리즘 기반 고가용성(HA, High Availability) 구성.
- 컨트롤러와 대규모 스위치 간 제어 채널 확장성(Scalability) 병목 :
  - 한계점 : 수천 대 스위치가 동시에 패킷 인(Packet-In) 요청을 보낼 때 제어 트래픽 폭증으로 응답 지연.
  - 해결 방안 : 계층적 컨트롤러(Root-Local) 분할, Proactive 사전 규칙 주입, 프로그래머블 P4 분산 처리 도입.
- 사우스바운드 제어 플레인 도청 및 위변조 보안 취약성 :
  - 한계점 : 제어 채널 침해 시 공격자가 스위치 포워딩 규칙을 조작하여 트래픽 탈취 및 중간자 공격(MITM) 수행.
  - 해결 방안 : 컨트롤러-스위치 간 TLS(Transport Layer Security) 상호 인증(Mutual TLS) 강제화 및 제어 트래픽 전용 대역 외(Out-of-band) 관리망 분리.

## Ⅴ. SDN(Software Defined Network) 적용 및 발전을 위한 기술사적 제언

- 하이퍼스케일 클라우드 데이터센터 Clos 패브릭 SDN 자동화 구축 : Leaf-Spine 물리망 위에 BGP-EVPN과 VXLAN을 연동한 SDN 오케스트레이션으로 테넌트 가상 네트워크 즉시 배포 구현 권장.
- 화이트박스 스위치 및 SONiC(오픈소스 NOS) 생태계 도입 추진 : 특정 벤더 종속을 탈피하고 TCO(Total Cost of Ownership)를 절감하기 위해 마이크로소프트 주도의 오픈소스 네트워크 OS인 SONiC 검증 및 도입.
- 제로 트러스트 마이크로 세그멘테이션(Micro-segmentation) 구현 : SDN의 세밀한 플로우 제어 역량을 활용하여 동일 서브넷 내부의 워크로드 간에도 L4 방화벽 규칙을 적용하는 동적 보안 격리 체계 수립.
