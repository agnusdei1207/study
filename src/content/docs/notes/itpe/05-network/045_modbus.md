## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 산업 통신 프로토콜 → MODBUS

## 30초 인출

- 본질: **MODBUS** 는 산업 장치가 기능 코드와 데이터 주소를 사용해 요청·응답 메시지를 주고받는 응용 계층 프로토콜
- 메커니즘: Client 요청의 기능 코드·주소·데이터 → Server의 처리·응답 → 전송 방식별 프레임으로 전달
- 통찰: PLC 및 산업용 센서 제어를 위해 마스터/슬레이브 구조로 요청-응답을 수행하는 사실상 표준 산업용 필드버스 프로토콜로서, 보안 취약점 극복을 위해 Modbus TCP Security(TLS)와 심층 패킷 검사(DPI) 결합이 필수적임.

<details>
<summary>핵심 용어</summary>

- **MODBUS** : 산업 장치 사이에서 기능 코드로 읽기·쓰기 요청과 응답을 교환하는 응용 계층 프로토콜.
- **Client / Server** : 요청을 시작하는 장치와 요청을 처리해 응답하는 장치.
- **PDU (Protocol Data Unit)** : 기능 코드와 기능별 데이터를 담는 MODBUS 프로토콜 데이터 단위.
- **Coil** : 1비트 단위의 읽기·쓰기 데이터 항목.
- **Discrete Input** : 1비트 단위의 읽기 전용 데이터 항목.
- **Input Register** : 16비트 단위의 읽기 전용 데이터 항목.
- **Holding Register** : 16비트 단위의 읽기·쓰기 데이터 항목.
- **MBAP (Modbus Application Protocol) Header** : Modbus TCP에서 트랜잭션·길이·장치 식별 정보를 PDU 앞에 담는 헤더.
- **Modbus Security** : TLS와 X.509 인증서를 이용해 Modbus 통신을 보호하는 프로토콜.
- **TLS (Transport Layer Security)** : 통신 구간의 인증·기밀성·무결성을 지원하는 보안 프로토콜.

</details>

## 2~4교시 25점 답안

## Ⅰ. MODBUS의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 모디콘(Modicon, 현 슈나이더 일렉트릭)이 1979년 발표한 이래 스마트 팩토리, 발전소, 수처리 시설 등 산업 자동화 제어 기기 간의 데이터 통신을 위해 사용되는 마스터/슬레이브 기반 애플리케이션 계층 필드버스 프로토콜 |
| 목적 | 산업 현장의 PLC, RTU, HMI, 센서, 계측기 간의 단순하고 신뢰성 있는 측정 데이터 수집 및 제어 명령 전달 |

## Ⅱ. MODBUS의 특징

| 특징 | 상세 내용 |
|---|---|
| 마스터/슬레이브 구조 | 단일 마스터(HMI/SCADA)만이 질의(Query)를 시작할 수 있고 슬레이브(PLC)는 응답(Response)만 수행 |
| 4대 데이터 모델 | 비트 단위(Coil, Discrete Input)와 16비트 워드 단위(Holding/Input Register)의 4개 주소 영역 정의 |
| 단순성과 개방성 | 프로토콜 헤더 구조가 극히 간결하여 8비트 저사양 마이크로컨트롤러에서도 손쉽게 펌웨어 구현 가능 |
| 보안 기능 결여 | 초기 설계 시 폐쇄망을 전제하여 인증, 인가, 데이터 암호화 메커니즘이 전혀 없는 평문 통신 구조 |

## Ⅲ. MODBUS의 체계·프로세스

**MODBUS 프로토콜 프레임 구조 및 4대 데이터 모델**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ MODBUS 프로토콜 프레임 구조 ]                 │
│                                                                        │
│   [ Modbus RTU / ASCII (직렬 시리얼 RS-232/485) ]                      │
│   ┌────────────┬──────────────┬────────────────────────┬───────────┐   │
│   │ Slave 주소 │ 기능 코드    │ 데이터 페이로드        │ 오류 검사 │   │
│   │ (1 바이트) │ (Function 1B)│ (가변 바이트)          │ (CRC/LRC) │   │
│   └────────────┴──────────────┴────────────────────────┴───────────┘   │
│                                                                        │
│   [ Modbus TCP (이더넷 포트 502) ]                                     │
│   ┌────────────────────────┬────────────┬──────────────────────────┐   │
│   │ MBAP 헤더 (7 바이트)   │ 기능 코드  │ 데이터 페이로드          │   │
│   │ (트랜잭션ID, 프로토콜ID│ (1 바이트) │ (CRC 제거: TCP 체크섬 대체)│   │
│   └────────────────────────┴────────────┴──────────────────────────┘   │
└────────────────────────────────────────────────────────────────────────┘
```

| 데이터 모델 | 입출력 방향 | 데이터 크기 | 기능 코드 예시 | 실제 적용 예시 |
|---|---|---|---|---|
| **Discretes Input** | 읽기 전용 (Read-Only) | 1 비트 (On/Off) | FC 02 (Read Discrete Inputs) | 도어 열림 감지 센서, 비상 스위치 |
| **Coils** | 읽기/쓰기 (Read/Write) | 1 비트 (On/Off) | FC 01 (Read), FC 05 (Write) | 모터 기동 릴레이, 밸브 개폐 지시 |
| **Input Registers** | 읽기 전용 (Read-Only) | 16 비트 (2 바이트) | FC 04 (Read Input Registers)| 배관 압력계, 실시간 온도 센서값 |
| **Holding Registers**| 읽기/쓰기 (Read/Write) | 16 비트 (2 바이트) | FC 03 (Read), FC 06/16 (Write)| PLC 제어 목표 설정값(PID 파라미터)|

## Ⅳ. MODBUS의 종류·비교

| 비교 항목 | Modbus ASCII | Modbus RTU | Modbus TCP |
|---|---|---|---|
| **물리 계층 전송** | 시리얼 (RS-232/422/485) | 시리얼 (RS-485 중심) | 이더넷 (Ethernet, TCP 포트 502)|
| **데이터 인코딩** | 7비트 ASCII 16진수 문자 | 8비트 순수 바이너리(Binary)| 8비트 바이너리 + MBAP 헤더 |
| **오류 검출 방식** | LRC (Longitudinal Redundancy) | CRC-16 (Cyclic Redundancy) | TCP 헤더 자체 체크섬에 위임 |
| **프레임 경계 구분**| 시작 콜론(:), 끝 CRLF | 3.5 문자 시간(Silent Interval)| MBAP 헤더 내 길이(Length) 필드 |
| **전송 처리 효율** | 낮음 (바이트당 2문자 소모)| 높음 (바이너리 압축 전송) | 최고 (100Mbps/1Gbps 고속 통신) |

## Ⅴ. MODBUS의 한계와 방안

| 한계 | 방안 |
|---|---|
| 평문 통신 및 송신자 인증 부재로 인해 공격자가 허위 Coil 쓰기(FC 05) 명령을 주입하여 원전/화학 플랜트 폭발 유도 가능 | TLS 암호화 및 X.509 상호 인증서를 결합한 Modbus TCP Security(포트 802) 표준 도입 및 OT 전용 방화벽 배치 |
| 마스터/슬레이브 폴링 방식으로 인해 슬레이브 기기 수가 증가할수록 데이터 수집 주기 지연 및 네트워크 병목 발생 | 이벤트 발생 시에만 게시-구독(Pub/Sub) 방식으로 전송하는 MQTT-Sparkplug B 또는 OPC-UA 프로토콜로 마이그레이션 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
스마트 팩토리 레거시 Modbus 라인 보안 강화 시, 구형 PLC 장비의 펌웨어 교체가 불가능한 경우가 대부분이므로, PLC 전면에 OT 산업용 심층 패킷 검사(DPI) 방화벽을 인라인 브리지로 배치하여 비인가 IP에서의 Holding Register 쓰기 명령(FC 06, 16)을 강제 차단.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 산업 제어망(OT) Modbus 심층 패킷 검사 (DPI) 방화벽 방어 구조 ]       │
│                                                                        │
│   [ 제어실 HMI / SCADA ] ──► 허용 정책: Read 전용 (FC 03, 04만 허가)   │
│             │                                                          │
│             ▼ Modbus TCP 패킷                                          │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ [ OT 전용 DPI 방화벽 (산업용 보안 게이트웨이) ]                │   │
│   │   - L7 Modbus Function Code 검사                               │   │
│   │   - 정상 조회 (FC 03 Read) ──► 통과 (Pass)                     │   │
│   │   - 악의적 변조 (FC 06/16 Write) ──► 즉시 차단 및 SIEM 경보    │   │
│   └────────────────────────┬───────────────────────────────────────┘   │
│                            │                                           │
│                            ▼ (인가된 안전 조회 명령만 인입)            │
│                 [ 현장 PLC / 생산 모터 설비 ]                          │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 보안 모델 | 통신 포트 | 보안 수준 | 적용 난이도 |
|---|---|---|---|
| **레거시 Modbus TCP** | TCP 502 | 보안 제로 (스니핑/변조 무방비) | 설정 불필요 (기본 동작) |
| **OT 방화벽 DPI 가드** | TCP 502 | 높음 (L7 기능코드 화이트리스트) | 중간 (네트워크 인라인 장비 추가) |
| **Modbus TCP Security** | TCP 802 | 최상 (TLS 상호 인증 및 암호화) | 높음 (기기 전면 인증서 발급 필요) |
