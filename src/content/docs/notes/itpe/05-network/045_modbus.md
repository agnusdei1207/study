```text
 ┃
 ┣━ Ⅰ 개요 ───── 산업용 PLC·센서 간 단순 상호 연동을 위한 사실상 표준(De facto) 프로토콜
 ┣━ Ⅱ 특징 ───── 마스터-슬레이브(클라이언트-서버), 단순 프레임, 기능 코드(Function Code) 기반, 오픈 표준
 ┣━ Ⅲ 구조 ───── Modbus PDU(기능 코드 + 데이터) + 통신 변형(Modbus RTU, Modbus ASCII, Modbus TCP)
 ┣━ Ⅳ 흐름 ───── ① 마스터 요청(슬레이브 ID + 기능 코드 + 레지스터 주소) → ② 슬레이브 실행 → ③ 응답 반환
 ┣━ Ⅴ 비교 ───── Modbus RTU vs Modbus TCP (시리얼 RS-485 vs 이더넷 TCP 502, CRC vs MBAP 헤더)
 ┗━ Ⅵ 실무 ───── 평문 전송 및 인증 부재(스푸핑 취약) / 서비스 거부(DoS) / 잘못된 제어 명령 주입
```

## 한 줄 본질
- 공장 설비(PLC, 센서, 계측기) 간 상호 연결 규격 부재로 인한 시스템 통합 난제 → 마스터가 슬레이브 장비의 메모리 번지(코일/레지스터)를 기능 코드로 읽고 쓰는 극도로 단순한 요청-응답 프로토콜 제정 → 공장 자동화의 범용 호환성 달성 / 암호화와 사용자 인증이 전혀 없어 해커가 임의로 기계 정지 및 밸브 조작 가능

## 핵심 그림
```text
[ MODBUS 통신 구조 및 프레임 형식 ]

1. Modbus RTU (시리얼 RS-485 통신):
   +---------------+---------------+-------------------+---------------+
   | 슬레이브 주소 | 기능 코드     | 데이터            | CRC 체크섬    |
   | (Slave ID, 1B)| (Func Code, 1B)| (Data, N Bytes)   | (CRC-16, 2B)  |
   +---------------+---------------+-------------------+---------------+

2. Modbus TCP (이더넷 통신, 포트 502):
   +------------------------------------+---------------+---------------+
   | MBAP 헤더 (7바이트)                | 기능 코드     | 데이터        |
   | (트랜잭션 ID + 프로토콜 ID + 길이)| (Func Code, 1B)| (Data, N Bytes|
   +------------------------------------+---------------+---------------+
                                        <------- Modbus PDU ---------->
```

## 핵심 용어
- 기능 코드(Function Code): 마스터가 슬레이브에게 수행을 지시하는 명령어 번호 (01: 코일 읽기, 03: 홀딩 레지스터 읽기, 05: 단일 코일 쓰기, 06: 단일 레지스터 쓰기 등)
- 코일(Coil) vs 레지스터(Register): 코일은 1비트 ON/OFF 디지털 I/O 값(릴레이 상태 등) / 레지스터는 16비트 정수 아날로그 I/O 값(온도, 압력 등)
- MBAP 헤더(Modbus Application Protocol Header): Modbus TCP에서 기존 시리얼 슬레이브 주소와 CRC를 대체하여 트랜잭션 식별과 패킷 길이를 나타내는 7바이트 헤더

## 핵심 통찰
- 1979년 모디콘(Modicon)사에서 개발된 MODBUS는 40년이 지난 지금까지도 스마트팩토리 현장에서 가장 많이 쓰이는데, 그 이유는 "마이크로컨트롤러 칩셋에 단 며칠 만에 코딩해 올릴 수 있을 정도로 단순하기 때문"
- 원래 폐쇄된 공장 구내 RS-485 구리선 통신을 전제로 만들어졌기 때문에 암호화, 무결성 검증, 발신자 인증 장치가 아예 설계에 존재하지 않음
- 최근 이 신호들이 Modbus TCP로 변환되어 공장 IT망 및 외부 인터넷과 연결되면서, 랜섬웨어나 국가 배후 해커의 ICS/SCADA 기반 시설 사이버 공격 표적으로 급부상

## 이웃 토픽과 구분
- Modbus RTU vs Modbus TCP: RTU는 RS-485 시리얼 버스에서 바이너리 원시 데이터와 CRC로 전송 / TCP는 표준 이더넷 L4 TCP 502번 포트 위에서 MBAP 헤더를 붙여 전송

## 문제·원인·대책
- 적용 상황: 수처리 시설 및 스마트 팩토리 제어망 침해 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 비인가 해커의 밸브 개방 쓰기 명령(05/06) 주입 | MODBUS 프로토콜의 패킷 인증 및 서명 부재 | 산업용 방화벽 기반 기능 코드 화이트리스트 필터링 | 쓰기 명령을 원천 차단하고 읽기(01/03) 전용 모드로 격리 |
| 네트워크 패킷 도청을 통한 설비 가동 정보 유출 | 평문(Cleartext) 전송으로 패킷 스니핑 취약 | Modbus Security(TLS 1.3 암호화 래핑, 포트 802) 적용 | 상호 인증서 교환 및 전 구간 암호화로 도청 차단 |

## 내 의견
- [레거시 설비 교체 없이 보안을 확보하는 OT 망 분리 아키텍처] 수십 년 된 산업용 PLC 장비를 최신 암호화 프로토콜(Modbus Security)로 전면 교체하는 것은 비용과 설비 중단 리스크로 불가능 → 나라면: 기존 PLC는 순수 폐쇄망에 그대로 두고, 제어망과 상위 IT망 사이에 물리적 일방향 데이터 전송 장비(Data Diode) 또는 Modbus 트래픽 심층 패킷 검사(DPI) 지원 전용 보안 게이트웨이를 전진 배치하여 레거시 자산 보호
