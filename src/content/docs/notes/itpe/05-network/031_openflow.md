## 30초 인출

- 본질: **OpenFlow** : 컨트롤러가 스위치의 플로우 테이블을 관리하고 패킷 처리 규칙을 제어하는 프로토콜
- 메커니즘: 플로우 엔트리의 매칭 필드·우선순위·명령으로 처리 결정 → Table-Miss 동작 또는 컨트롤러 통지

<details>
<summary>핵심 용어</summary>

- **OpenFlow** : ONF 규격에 따라 컨트롤러와 스위치 간 플로우 규칙·상태를 관리하는 프로토콜
- **플로우 테이블(Flow Table)** : 패킷 매칭과 처리 명령을 담은 스위치 테이블
- **플로우 엔트리(Flow Entry)** : 매칭 필드, 우선순위, 카운터, 명령·시간 초과 등으로 구성되는 규칙
- **Table-Miss** : 테이블의 일반 엔트리와 일치하지 않는 패킷의 처리 규칙
- **OpenFlow 채널(OpenFlow Channel)** : 컨트롤러와 스위치가 프로토콜 메시지를 주고받는 통신 경로
- **Packet-In** : 스위치가 설정된 동작에 따라 패킷 정보를 컨트롤러에 알리는 메시지
- **SDN(Software-Defined Networking)** : 제어 기능과 패킷 전달 기능을 소프트웨어로 분리·관리하는 네트워크 구조

```text
패킷 유입
```

## 2~4교시 25점 답안

### Ⅰ. OpenFlow의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **OpenFlow** : 컨트롤러가 스위치 플로우 테이블의 규칙·상태를 관리하는 프로토콜 |
| 목적 | 표준화된 인터페이스를 통해 스위치 패킷 전달 동작의 소프트웨어 제어 지원 |

### Ⅱ. 패킷 처리 흐름

```text
패킷 유입
    ↓
플로우 테이블 조회
  ├─ 일치 → 우선순위·명령 실행
  └─ 불일치 → Table-Miss 동작
                  ├─ 폐기
                  ├─ 다음 테이블
                  └─ 컨트롤러 통지
```

Table-Miss는 반드시 Packet-In을 뜻하지 않으며 테이블 설정에 따라 폐기·컨트롤러 통지·다음 테이블 진행 등으로 처리.

### Ⅲ. 논리 스위치 구성

| 구성 | 역할 |
|---|---|
| OpenFlow 채널 | 컨트롤러와 프로토콜 메시지 교환 |
| 플로우 테이블 | 매칭 필드·카운터·명령 기반 패킷 처리 |
| 그룹 테이블 | 여러 포트·동작을 묶는 전달 처리 지원 |
| 파이프라인 | 테이블 간 이동을 포함한 순차 패킷 처리 |

### Ⅳ. 컨트롤 메시지 흐름

```text
컨트롤러 정책 ── Flow-Mod ─→ 스위치 규칙 갱신
       ↑                              ↓
       └──── Packet-In·상태 통지 ← 패킷 처리
```

컨트롤러는 proactive하게 규칙을 설치하거나 reactive하게 Packet-In 처리 후 규칙을 넣을 수 있음. 비동기 통지는 설정된 메시지 종류·이벤트에 따름.

### Ⅴ. SDN과 OpenFlow

| 관점 | SDN | OpenFlow |
|---|---|---|
| 개념 | 제어·전달 기능의 분리 등을 포괄하는 구조·접근 방식 | 컨트롤러-스위치 제어에 쓰일 수 있는 구체적 프로토콜 |
| 범위 | 아키텍처·운영·API 등 다양한 구현 | 규격 버전별 메시지·테이블·동작 |
| 관계 | 특정 프로토콜에 한정되지 않음 | SDN 구현에서 선택 가능한 구성요소 |

### Ⅵ. 한계와 대응

| 한계 | 대응 |
|---|---|
| Table-Miss 다량 발생 시 컨트롤러 부하 | 기본 경로·와일드카드 규칙·패킷 인 비율을 정책별 조정 |
| 장비별 테이블·매칭 능력 차이 | 대상 장비의 지원 기능·테이블 자원을 사전 검증 |
| 중앙 제어 채널 장애·지연 | 컨트롤러 이중화·장애 시 로컬 규칙·복구 절차 시험 |
| 과도한 세부 규칙으로 테이블 자원 소진 | 규칙 집계·우선순위·만료 정책을 설계하고 실제 용량 측정 |

### Ⅶ. 기술사적 제언

| 우선 선정 | 검증·운영 |
|---|---|
| 지원 기능·운영 요구에 맞는 OpenFlow 버전과 제어 방식을 선정 | 장비 적합성, Table-Miss, 채널 장애, 규칙 규모를 상호운용 시험 |
