## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 라우팅 프로토콜 → 자율 시스템 간 경로 교환

## 30초 인출

- 본질: **EGP (Exterior Gateway Protocol)** 는 서로 다른 자율 시스템 사이에서 네트워크 도달 경로를 교환하는 라우팅 프로토콜 범주
- 메커니즘: AS 경계의 BGP 세션으로 접두사와 AS 경로를 교환 → 수신 정책에 따라 경로를 선택·광고
- 통찰: 단일 관리 도메인 내부를 제어하는 IGP와 달리 서로 다른 자율시스템(AS) 간에 라우팅 정보를 교환하기 위한 외부 게이트웨이 프로토콜로서, 인터넷 글로벌 백본에서는 정책 기반 경로 벡터 프로토콜인 BGP-4로 완전히 표준화됨.

<details>
<summary>핵심 용어</summary>

- **EGP (Exterior Gateway Protocol)** : 서로 다른 자율 시스템 사이에서 도달성 정보를 교환하는 외부 게이트웨이 프로토콜 범주.
- **IGP (Interior Gateway Protocol)** : 하나의 자율 시스템 내부에서 라우팅 정보를 교환하는 프로토콜 범주.
- **AS (Autonomous System)** : 공통 라우팅 정책 아래 관리되는 네트워크 집합.
- **BGP (Border Gateway Protocol)** : 인터넷의 자율 시스템 간 도달성 정보를 교환하는 대표적인 경로 벡터 프로토콜.
- **AS_PATH** : 경로가 거친 AS 번호를 담는 BGP 경로 속성. 자신의 AS 번호가 이미 있는 경로를 거부하는 데 활용.
- **RPKI (Resource Public Key Infrastructure)** : 인터넷 번호 자원의 할당 정보를 검증 가능한 공개키 기반 구조로 표현하는 체계.
- **ROA (Route Origin Authorization)** : 접두사를 원점 AS가 광고할 권한을 나타내는 서명 객체.
- **역사적 EGP** : RFC 904에 규정된 초기 외부 게이트웨이 프로토콜. 오늘날의 BGP와 구별되는 구형 프로토콜.

## 2~4교시 25점 답안

## Ⅰ. EGP(Exterior Gateway Protocol)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 서로 독립적인 관리 체계와 라우팅 정책을 갖는 자율시스템(AS, Autonomous System) 상호 간에 네트워크 도달 가능성(Reachability) 정보를 교환하는 외부 게이트웨이 라우팅 프로토콜의 총칭 |
| 목적 | 단일 라우팅 알고리즘으로 수용할 수 없는 글로벌 인터넷 전역의 계층적 경로 배정 및 통신사(ISP) 간 경제적·정치적 트래픽 전송 정책 통제 |

## Ⅱ. EGP(Exterior Gateway Protocol)의 특징

| 특징 | 상세 내용 |
|---|---|
| 자율시스템(AS) 간 연결| 전 세계 고유의 AS 번호(ASN, 16비트/32비트)를 기반으로 ISP 및 대형 엔터프라이즈 간 연결 |
| 경로 벡터(Path Vector)| 단순 비용이 아닌 지나온 AS 번호들의 목록(AS-Path)을 전달하여 도메인 간 라우팅 루프 원천 방지 |
| 정책 기반 라우팅(PBR) | 최단 경로보다 계약 관계(트랜짓 Transit, 피어링 Peering) 및 상업적 비용에 따른 정책 경로 우선 선택 |
| TCP 기반 신뢰성 전송 | 현대 사실상 표준 EGP인 BGP-4는 TCP 포트 179번을 통해 피어 간 안정적인 갱신 패킷 교환 |

## Ⅲ. EGP(Exterior Gateway Protocol)의 체계·프로세스

**글로벌 인터넷 AS 구조 및 EGP(BGP-4) 경로 벡터 동작**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ 인터넷 AS 간 EGP (BGP-4) 연동 구조 ]          │
│                                                                        │
│   [ AS 100 : KT 백본 ]                    [ AS 200 : SKB 백본 ]        │
│   ┌────────────────────┐   eBGP (TCP 179) ┌────────────────────┐       │
│   │ 라우터 A ──────────┼─────────────────►│ 라우터 B           │       │
│   │ (네트워크: 10.1.0/24)│                 │ (AS-Path: 100 기록)│       │
│   └────────────────────┘                  └─────────┬──────────┘       │
│                                                     │ eBGP             │
│                                                     ▼                  │
│                                           [ AS 300 : LGU+ 백본 ]       │
│                                           ┌────────────────────┐       │
│                                           │ 라우터 C           │       │
│                                           │ (AS-Path: 200, 100)│       │
│                                           └────────────────────┘       │
│                                                                        │
│   * 루프 감지: 만약 AS-Path 내에 자신의 ASN이 포함되어 있으면 즉각 폐기 │
└────────────────────────────────────────────────────────────────────────┘
```

| AS 연결 유형 | 관계 정의 | 트래픽 및 과금 정책 |
|---|---|---|
| **트랜짓 (Transit)** | 하위 고객 ISP가 상위 글로벌 Tier-1 ISP에게 요금을 지불하고 인터넷 전 세계 경로를 구매하는 관계 | 종량제/정액제 대역폭 요금 지불 |
| **피어링 (Peering)** | 동등한 규모의 두 ISP가 상호 고객 간의 트래픽을 정산 없이 무상으로 직접 교환(Settlement-Free) | 상호 비용 정산 없음 (IXP 연동) |
| **eBGP (External)** | 서로 다른 AS의 BGP 스피커 간 직접 세션 수립 | 기본 TTL=1 (직접 연결 링크 전제) |
| **iBGP (Internal)** | 동일한 AS 내부의 BGP 스피커 간 정보 공유 | 풀메시 연결 또는 Route Reflector 필수 |

## Ⅳ. EGP(Exterior Gateway Protocol)의 종류·비교

| 비교 항목 | 초기 EGP (RFC 904) | 현대 EGP 사실상 표준: BGP-4 (RFC 4271) |
|---|---|---|
| **네트워크 토폴로지** | 트리형 단일 백본 구조만 지원 | **임의의 메시(Mesh) 형태 멀티홈 백본 지원** |
| **루프 방지 메커니즘**| 루프 감지 기능 없음 (루프 취약) | **AS-Path 속성을 통한 완벽한 루프 감지** |
| **서브넷 마스크** | Classful 주소 체계만 지원 | **CIDR(VLSM, 슈퍼네팅) 완벽 지원** |
| **전송 계층** | IP 직접 캡슐화 (신뢰성 낮음) | **TCP 포트 179번 기반 고신뢰성 전송** |
| **경로 결정 기준** | 단순 도달 가능성 여부 | **Local-Pref, AS-Path, MED 등 복합 속성 정책** |

## Ⅴ. EGP(Exterior Gateway Protocol)의 한계와 방안

| 한계 | 방안 |
|---|---|
| 제3자가 타 기관 소유의 공인 IP 대역을 허위로 BGP 발표 시 전 세계 트래픽이 납치되는 BGP 하이재킹(Hijacking) 위험 | 암호학적 서명 기반의 RPKI(Resource Public Key Infrastructure) 및 ROA(Route Origin Authorization) 엄격 검증 |
| 불안정한 인터페이스로 인해 경로 유입/삭제가 초당 수천 번 반복 전파되는 BGP 경로 플래핑(Route Flapping) 폭증 | 플래핑 경로에 페널티를 부여하여 일정 시간 전파를 동결하는 BGP 댐프닝(Route Dampening) 알고리즘 적용 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
멀티홈(Multi-homed) 엔터프라이즈 BGP 구축 시, 송신 트래픽 경로는 `Local Preference`(높을수록 우선)로 조정하고, 수신 인바운드 트래픽은 특정 회선으로 몰리지 않도록 타 ISP 대상 `AS-Path Prepending`(자기 ASN을 인위적으로 3~4회 중복 삽입하여 경로 길이 늘림) 기법을 적용하여 회선 부하 분산.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ BGP 최적 경로 선출 (Best Path Selection) 순차적 알고리즘 ]          │
│                                                                        │
│ 1. 최고 Weight (Cisco 독점 속성, 로컬 라우터 유효)                     │
│ 2. 최고 Local Preference (AS 내부 공통 선호도, 디폴트 100)              │
│ 3. 자사 라우터가 직접 생성한 경로 우선 (Next Hop 0.0.0.0)             │
│ 4. 최단 AS-Path (지나온 AS 번호 개수가 가장 짧은 경로)                 │
│ 5. 최저 Origin Code (IGP < EGP < Incomplete)                           │
│ 6. 최저 MED (Multi-Exit Discriminator, 타 AS 유입 지표)                │
│ 7. eBGP 경로 우선 (iBGP보다 외부 직접 경로 우선)                       │
│ 8. 최저 IGP Cost (Next Hop에 도달하기 위한 내부 메트릭)                 │
│ 9. 최저 Router ID (동점 시 최종 동점 파괴 기준)                       │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| BGP 속성 | 적용 범위 | 전파 규칙 | 핵심 제어 목적 |
|---|---|---|---|
| **Weight** | 로컬 라우터 단독 | 타 라우터 전파 안 됨 | 해당 라우터의 단독 아웃바운드 선택 |
| **Local-Pref** | AS 내부 전체 | iBGP로 전파, eBGP로 전파 안 됨| 전사 아웃바운드 경로 통일 결정 |
| **AS-Path** | 글로벌 전 세계 | eBGP 전파 시마다 ASN 추가 | 루프 방지 및 인바운드 트래픽 제어 |
| **MED** | 인접 타 AS | AS 경계를 넘어 1홉만 전파 | 타 AS가 자사로 유입될 입구 포트 지정 |
