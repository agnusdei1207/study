## 연관 키워드

- EGP(Exterior Gateway Protocol), 자율 시스템(AS), 도달 가능성(Reachability)
- 이웃 획득, Hello와 I-H-U, Poll과 Update, 트리 구조 백본
- BGP(Border Gateway Protocol), 경로 벡터(Path Vector), AS-Path, CIDR, 정책 라우팅
- RPKI, BGP 하이재킹

## Ⅰ. EGP의 개요

- 핵심 요약 : 서로 다른 자율 시스템의 경계 라우터 사이에서 도달 가능한 네트워크 정보를 교환한 초기 외부 라우팅 프로토콜.
- 개념 : 독립된 관리 주체의 네트워크인 **자율 시스템** (AS, Autonomous System) 경계 라우터 사이에서 **도달 가능성** (Reachability) 정보를 교환하도록 정의된 외부 게이트웨이 프로토콜(EGP, Exterior Gateway Protocol), 정식 명세는 RFC(Request for Comments) 904.
- 배경 및 필요성 : 초기 인터넷이 중앙 코어 게이트웨이를 중심으로 각 기관의 외부 게이트웨이를 연결하는 구조로 성장하면서, 기관 내부 경로는 감추고 경계에서만 도달 정보를 주고받을 공통 규약의 필요가 제기.
- 주요 목적 :
  1. AS 경계에서 도달 네트워크 목록의 상호 통보
  2. 코어 백본과 외부 AS를 계층 구조로 연결하는 경로 제공
  3. 내부 라우팅 정보의 은닉과 외부 도달 정보의 분리

## Ⅱ. EGP의 특징 및 장점

- 핵심 요약 : 단순한 상태 전이와 질의-응답 갱신이 구현 부담을 낮추지만, 단일 트리 가정이 확장성의 한계가 되는 구조.

1. **이웃 획득** (Neighbor Acquisition) : 이웃 후보 라우터와 Request·Confirm을 주고받아 이웃 관계 성립 → 경계 라우터 간 관계의 명시적 관리.
2. **이웃 도달성 확인** (Neighbor Reachability) : Hello 메시지에 I-H-U(I Hear You) 응답을 주기적으로 교환 → 상대 라우터 생존 여부의 상시 감시.
3. **도달 정보 갱신** (Network Reachability) : Poll 요청에 Update 응답으로 도달 네트워크 목록 회신 → 변경이 없는 구간의 전송량 억제.
4. **트리 구조 백본**(단일 코어를 뿌리로 하는 계층 토폴로지) 가정 : 설계와 구성 관리가 단순 → 다중 경로와 루프 환경에는 부적합.

## Ⅲ. EGP의 구조 (흐름)

- 핵심 요약 : 이웃 관계 수립 → 생존 확인 → 도달 정보 갱신의 3단계가 주기적으로 반복되는 동작 구조.

```text
[ EGP 3단계 동작 ]

이웃 획득 : Request → Confirm 합의
   ↓
이웃 도달성 확인 : Hello → I-H-U
   ↓
도달 정보 갱신 : Poll → Update
```

```text
[ 트리 구조 백본 가정 ]

중앙 코어 백본 (뿌리)
   ↓
하위 AS 1 · AS 2 · AS 3
루프 없는 계층 구조 전제
```

- 운영 주기 : 생존 확인은 헬로 주기로, 도달 목록 갱신은 별도 질의 간격으로 수행되는 주기형 동작.

## Ⅳ. EGP와 BGP의 비교

- 핵심 요약 : 단일 트리와 정수 거리값 중심의 EGP를, 메시 구조와 경로 속성 기반 정책 라우팅의 BGP가 대체한 관계.
- 구분 : AS 내부 경로는 내부 게이트웨이 프로토콜(IGP, Interior Gateway Protocol)이 담당하고, AS 경계의 외부 경로는 BGP(Border Gateway Protocol)가 담당하는 이원 구조가 현행 표준.

| 비교 항목 | EGP | BGP-4 |
| --- | --- | --- |
| 표준 명세 | RFC 904 | RFC 4271 |
| 토폴로지 | 단일 백본 트리 | 임의의 메시 구조 |
| 루프 방지 | 트리 구조에 의존 | AS-Path에 경유 AS 기록으로 차단 |
| 경로 결정 | 정수 거리값 | 경로 속성 (AS-Path, Local Preference 등) |
| 정책 라우팅 | 불가 | 접속 계약·트래픽 엔지니어링 지원 |
| 주소 체계 | 클래스풀 주소 | CIDR(Classless Inter-Domain Routing) |
| 전송 방식 | IP(Internet Protocol) 직접 탑재 (프로토콜 번호 8) | TCP(Transmission Control Protocol) 179 포트 |

- 선택 기준 : 현행 인터넷의 AS 간 경로 교환은 BGP가 유일한 표준이므로, EGP는 트리 가정과 단순 거리값 설계의 한계를 이해하는 사례로 활용.

## Ⅴ. EGP의 한계와 방안

- 핵심 요약 : 루프 탐지 기능 부재, 클래스풀 주소 고착, 정책 표현력 부족이 핵심 한계이며 경로 벡터 기반 BGP로 해소.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 루프 탐지 불능 | 단일 트리 가정 설계 → 다중 연결 환경에서 경로 루프 차단 불가 | 경유 AS 목록을 기록하는 **경로 벡터**(Path Vector) 방식의 BGP 적용 | 루프 발생 건수 |
| 클래스풀 주소 고착 | 서브넷 마스크 교환 불가 → 주소 고갈과 경로 폭증 대응 불가 | 마스크 길이 포함 광고와 CIDR 기반 경로 집계를 지원하는 BGP-4 전환 | 라우팅 테이블 크기 |
| 정책 라우팅 불가 | 경로 선택 기준이 거리값뿐 → 접속 계약의 라우팅 반영 불가 | Local Preference 등 경로 속성 기반의 정책 설정 | 정책 적용 경로 비율 |

## Ⅵ. EGP에 대한 기술사적 제언

- 핵심 요약 : EGP의 설계 교훈을 확장성·루프 방지·정책 자율 요건으로 일반화하고 현행 BGP 운용의 경로 신뢰성을 보강하는 방향.

1. 아키텍처 검토 조직 : 시스템 설계 단계에 확장성·루프 방지·정책 자율성을 초기 요건으로 명시하는 검토 절차 운영.
2. 인터넷 운용 기관 : **RPKI**(Resource Public Key Infrastructure)로 경로 광고의 출처 검증을 상시화해 **BGP 하이재킹**(부정한 경로 광고로 트래픽을 가로채는 공격) 대응력 확보.
3. 클라우드 운영 조직 : 트랜짓 게이트웨이 설계에 계층적 도메인 분리 원칙을 적용해 경로 오류의 영향 범위 제한.

## Ⅶ. 결론

- 핵심 요약 : EGP는 트리 가정과 단순 거리값 설계의 한계로 BGP에 자리를 내준 초기 AS 간 라우팅 프로토콜.
- 라우팅 프로토콜의 확장성·루프 방지·정책 표현력이 인터넷 규모 성장을 좌우하는 설계 요소.
