## Ⅰ. EGP(Exterior Gateway Protocol)의 개요

- **개념** : 서로 다른 자율 시스템(AS: Autonomous System) 간에 네트워크 도달 가능성(Reachability) 정보를 교환하기 위해 개발된 최초의 외장 게이트웨이 라우팅 프로토콜 (RFC 904).
- **배경 및 필요성** : 초기 인터넷(ARPANET 시절) 환경에서 여러 기관이 관리하는 독립된 네트워크(AS)들이 출현함에 따라, 내부 라우팅 정보를 은폐하면서 AS 경계 라우터 간 상호 라우팅을 지원할 표준 프로토콜 필요.
- **핵심 목적** : 이종 AS 간의 네트워크 도달 정보 통보, 인터넷 초기 중앙 코어 라우터와 외부 AS 간 계층적 트리 구조 라우팅 경로 제공.

## Ⅱ. EGP의 핵심 아키텍처 및 동작 메커니즘

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ EGP 3단계 상태 전이 및 동작 절차 ]                 │
│                                                                        │
│   [ 단계 1: 이웃 획득 ]                                                │
│   Router A (AS 100) ────── Neighbor Acquisition Request ─────► Router B│
│                     ◄───── Neighbor Acquisition Confirm ────── (AS 200)│
│                                                                        │
│   [ 단계 2: 이웃 도달성 확인 (지속 헬로 폴링) ]                         │
│   Router A          ────── Hello (Hello/I-H-U Polling) ──────► Router B│
│                     ◄───── I-H-U (I Hear You) ────────────────         │
│                                                                        │
│   [ 단계 3: 네트워크 도달 가능성 업데이트 ]                             │
│   Router A          ────── Poll Request ─────────────────────► Router B│
│                     ◄───── Network Reachability Update ───────         │
│                            (도달 가능 네트워크 목록 및 거리)           │
└────────────────────────────────────────────────────────────────────────┘
```

- **이웃 획득 (Neighbor Acquisition)** : 2-way 핸드셰이크를 통해 상대 라우터와 이웃 관계(Peering)를 맺을 것에 합의하고 통신 파라미터 교환.
- **이웃 도달성 검증 (Neighbor Reachability)** : 주기적인 Hello 메시지와 I-H-U(I Hear You) 응답을 교환하여 링크 및 상대방 프로세스의 생존 여부 감시.
- **네트워크 도달성 폴링 (Network Reachability)** : Poll 요청 메시지에 대한 응답으로 자신의 AS 내부에서 도달 가능한 네트워크 IP 주소 목록을 Update 메시지로 회신.

## Ⅲ. EGP의 세부 구성 요소 및 후속 프로토콜 BGP와의 비교 분석

| 비교 항목 | EGP (Exterior Gateway Protocol) | BGP (Border Gateway Protocol, BGP-4) |
|---|---|---|
| **토폴로지 구조** | 엄격한 단일 백본 트리 구조 (Tree Topology) | 임의의 복합 메시 구조 (Arbitrary Mesh Topology) |
| **라우팅 루프 방지** | 토폴로지 상 루프 방지 기법 부재 (트리 강제) | AS-Path 속성을 통한 루프 원천 차단 |
| **경로 결정 기준** | 단순 정수 거리값 (Distance Metric, 의미 모호) | 풍부한 Path Attribute (AS-Path, Local-Pref 등) |
| **정책 라우팅** | 정책 기반 라우팅 제어 불가 | 상호 접속 계약 및 트래픽 엔지니어링 완벽 지원 |
| **CIDR 지원** | 미지원 (Classful 네트워크 A, B, C만 처리) | 완벽 지원 (VLSM, Route Aggregation/슈퍼네팅) |
| **전송 계층 프로토콜**| IP 직접 탑재 (프로토콜 번호 8) | TCP 포트 179 (신뢰성 있는 연결 기반 전송) |

- **Acquisition Message** : Request, Confirm, Refuse, Cease 등의 제어 코드로 이웃 상태 머신 제어.
- **Reachability Poll/Update** : 질의-응답 방식으로 동작하여 백본의 부담 가중 (이벤트 발생 시 즉각 브로드캐스팅 미지원).

## Ⅳ. EGP의 주요 한계점 및 BGP로의 대체 원인

- **메시 토폴로지에서의 라우팅 루프(Routing Loop) 탐지 불능** :
  - **한계점** : 단일 중앙 집중식 백본을 가정하여 설계되었으므로 다중 백본이나 멀티홈드(Multi-homed) 환경에서 루프를 탐지하거나 방지할 알고리즘 전무.
  - **해결 방안** : 경로가 거쳐간 AS 목록 전체를 패킷에 기록하여 전달하는 패스 벡터(Path Vector) 알고리즘 기반 BGP 개발 및 전면 대체.
- **클래스풀 어드레싱 고착 및 인터넷 경로 폭증** :
  - **한계점** : 서브넷 마스크 정보를 교환하지 못해 서브네팅 및 슈퍼네팅(CIDR)을 수용할 수 없어 인터넷 라우팅 테이블 포화 가속.
  - **해결 방안** : 마스크 길이를 포함하는 BGP-4 도입 및 최장 접두사 일치(LPM) 기반의 경로 축약 체계 확립.

## Ⅴ. EGP 적용 및 발전을 위한 기술사적 제언

- **인터넷 라우팅 발전사의 아키텍처적 교훈** : EGP의 구조적 실패는 초기 설계 시 분산 시스템의 확장성(Scalability), 정책 자율성(Policy Autonomy), 루프 방지 알고리즘이 결여될 때 발생하는 시스템 붕괴를 입증.
- **현대 인터도메인 라우팅(BGP)의 거버넌스 유지** : EGP를 계승한 BGP 역시 태생적 평문 신뢰 구조로 인해 BGP 하이재킹 위험에 노출되어 있으므로 RPKI(리소스 공개키 기반구조) 및 BGPsec 도입을 통한 신뢰성 복원 필수.
- **클라우드 멀티 리전 백본 아키텍처 설계 활용** : EGP가 시도했던 계층적 도메인 분리 사상을 현대의 클라우드 Transit Gateway 및 인터도메인 라우팅 정책 설계에 참조하여 경로 격리 최적화 달성.
