## 연관 키워드

- EGP(Exterior Gateway Protocol), 자율 시스템(AS), 도달 가능성(Reachability), 트리 구조 백본
- 이웃 획득, Hello와 I-H-U, Poll과 Update, 정책 라우팅
- BGP(Border Gateway Protocol), 경로 벡터(Path Vector), CIDR, RPKI, BGP 하이재킹

## Ⅰ. EGP(Exterior Gateway Protocol)의 개요

- 핵심 요약 : 서로 다른 자율 시스템 사이에서 도달 가능한 네트워크 정보를 교환하기 위한 초기 외부 라우팅 프로토콜.
- 개념 : 독립된 관리 주체의 네트워크인 **자율 시스템** (AS, Autonomous System) 경계 라우터끼리 **도달 가능성** (Reachability) 정보를 주고받도록 정의된 외장 게이트웨이 라우팅 프로토콜(EGP, Exterior Gateway Protocol)이며, 정식 명세는 RFC(Request for Comments) 904에 기술됨.
- 배경 및 필요성 : 초기 인터넷에서 여러 기관이 독립적으로 운영하는 네트워크가 늘어나면서, 각 기관의 내부 라우팅 정보는 감추면서 경계 라우터 사이에서만 도달 정보를 교환할 표준이 필요해짐.
- 주요 목적 : 이기종 AS 사이의 도달 정보를 통보하고, 중앙 코어 라우터와 외부 AS를 계층적 트리 구조로 연결하는 경로를 제공.

## Ⅱ. EGP의 특징 및 장점

- 핵심 요약 : 단순한 상태 머신과 질의-응답 방식이 구현을 쉽게 하지만, 트리 구조 전제가 확장성의 한계가 됨.

1. 이웃 상태 관리 : 이웃 획득, 도달성 확인, 도달 정보 갱신의 세 단계로 나뉜 상태 머신 → 경계 라우터 간 관계를 단계별로 명확히 관리.
2. 주기적 생존 확인 : Hello와 I-H-U(I Hear You) 응답을 교환 → 상대 라우터의 생존 여부를 주기적으로 감시.
3. 질의-응답 갱신 : Poll 요청에 대한 Update 응답으로 도달 목록을 회신 → 변경이 없을 때 전송량을 줄임.
4. 트리 구조 전제 : 백본을 하나의 트리로 두어 설계가 단순 → 구성 관리는 쉬우나 다중 경로와 루프 처리가 불가능함.

## Ⅲ. EGP의 구조 (흐름)

- 핵심 요약 : 이웃 관계를 맺고 생존을 확인한 뒤 도달 정보를 갱신하는 3단계 동작이 반복되는 구조.

```text
[ EGP 3단계 동작 ]

이웃 획득 (Neighbor Acquisition)
  Request → Confirm (2-way 합의)
          ↓
이웃 도달성 확인 (Neighbor Reachability)
  Hello → I-H-U 응답 (주기 점검)
          ↓
네트워크 도달성 갱신 (Reachability)
  Poll → Update (도달 목록 회신)
```

```text
[ EGP가 가정한 토폴로지 ]

        중앙 코어 백본
       /       |       \
    AS 1     AS 2     AS 3
   (트리 구조, 루프 없음 가정)
```

## Ⅳ. EGP와 BGP의 비교

- 핵심 요약 : EGP의 트리 구조와 거리 값 중심 설계를 BGP의 임의 메시 구조와 경로 속성 기반 정책 라우팅이 대체함.

| 비교 항목 | EGP | BGP (Border Gateway Protocol, BGP-4) |
| --- | --- | --- |
| 토폴로지 | 단일 백본 트리 구조 | 임의의 메시 구조 |
| 루프 방지 | 트리 구조에 의존, 루프 탐지 기능 없음 | 경로 벡터(Path Vector)로 AS 목록을 기록해 루프 차단 |
| 경로 결정 | 정수 거리값 (의미가 단순함) | 다양한 경로 속성 (AS-Path, Local-Pref 등) |
| 정책 라우팅 | 제어 불가 | 상호 접속 계약과 트래픽 엔지니어링 지원 |
| 주소 체계 | 클래스풀 (A, B, C 클래스) | CIDR (Classless Inter-Domain Routing) 지원 |
| 전송 방식 | IP(Internet Protocol) 직접 탑재 (프로토콜 번호 8) | TCP(Transmission Control Protocol) 포트 179 기반 신뢰성 있는 연결 |

- 선택 기준 : 현재 인터넷 간 라우팅은 BGP만 사용되므로 EGP는 이력과 설계 교훈을 이해하는 용도로 의미가 있음.

## Ⅴ. EGP의 한계와 방안

- 핵심 요약 : 루프 방지 부재와 클래스풀 주소 고착이 EGP의 핵심 한계이며, BGP의 경로 벡터와 CIDR로 해결됨.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 메시 구조에서의 루프 탐지 불능 | 단일 백본을 가정해 설계되어 다중 백본과 다중 연결 환경에서 루프를 막을 알고리즘이 없음 | 경로가 거친 AS 목록을 기록하는 경로 벡터 방식의 BGP로 교체 | 루프 발생 건수 |
| 클래스풀 주소와 경로 폭증 | 서브넷 마스크를 교환하지 못해 CIDR과 경로 집계를 수용할 수 없음 | 마스크 길이를 포함하는 BGP-4 도입, 최장 접두사 일치(LPM, Longest Prefix Match) 기반 경로 집계 | 라우팅 테이블 크기 |
| 정책 라우팅 불가 | 경로 선택 기준이 거리 값뿐이라 상호 접속 계약을 반영할 수 없음 | 경로 속성 기반의 BGP 정책 설정 | 정책 적용 경로 비율 |

## Ⅵ. EGP에 대한 기술사적 제언

- 핵심 요약 : EGP의 실패에서 얻은 교훈을 바탕으로, 현재의 BGP 신뢰 구조를 보강하고 클라우드 라우팅 설계에 분리 원칙을 적용하는 방향.

1. 분산 시스템 설계 교훈의 반영 : 확장성, 정책 자율성, 루프 방지를 설계 초기 요건으로 명시하는 아키텍처 검토 절차를 두어야 함.
2. BGP 경로 신뢰성 보강 : BGP는 평문 신뢰 구조라 BGP 하이재킹에 노출되므로, 자원 공개키 기반 구조인 RPKI(Resource Public Key Infrastructure)를 적용해 경로 출처를 검증할 필요가 있음.
3. 클라우드 멀티 리전 경로 격리 : 계층적 도메인 분리 원칙을 클라우드 전송 게이트웨이(Transit Gateway) 설계에 적용하여 경로 영향 범위를 제한할 필요가 있음.

## Ⅶ. 결론

- 핵심 요약 : EGP는 트리 구조와 거리 값 중심 설계의 한계로 BGP에 자리를 내준 초기 외부 라우팅 프로토콜.
- 시사점 : 라우팅 프로토콜의 확장성과 루프 방지, 정책 표현력이 인터넷 규모의 성장을 좌우하며, 이 원칙은 현재의 BGP 운용에도 그대로 적용됨.
