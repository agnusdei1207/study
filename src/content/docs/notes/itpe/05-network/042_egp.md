<details>
<summary>핵심 용어</summary>

- **EGP (Exterior Gateway Protocol)** : 서로 다른 자율 시스템 사이에서 도달성 정보를 교환하는 외부 게이트웨이 프로토콜 범주.
- **IGP (Interior Gateway Protocol)** : 하나의 자율 시스템 내부에서 라우팅 정보를 교환하는 프로토콜 범주.
- **AS (Autonomous System)** : 공통 라우팅 정책 아래 관리되는 네트워크 집합.
- **BGP (Border Gateway Protocol)** : 인터넷의 자율 시스템 간 도달성 정보를 교환하는 대표적인 경로 벡터 프로토콜.
- **AS_PATH** : 경로가 거친 AS 번호를 담는 BGP 경로 속성. 자신의 AS 번호가 이미 있는 경로를 거부하는 데 활용.
- **RPKI (Resource Public Key Infrastructure)** : 인터넷 번호 자원의 할당 정보를 검증 가능한 공개키 기반 구조로 표현하는 체계.
- **ROA (Route Origin Authorization)** : 접두사를 원점 AS가 광고할 권한을 나타내는 서명 객체.
- **역사적 EGP** : RFC 904에 규정된 초기 외부 게이트웨이 프로토콜. 오늘날의 BGP와 구별되는 구형 프로토콜.

## 1교시 10점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **EGP (Exterior Gateway Protocol)** 는 서로 다른 자율 시스템 사이에서 네트워크 도달 경로를 교환하는 프로토콜 범주 |
| 목적 | 자율 시스템 간 네트워크 도달성 제공 |

### Ⅱ. 적용 범위와 대표 프로토콜

```text
AS 내부 라우터
      ↓ IGP로 내부 경로 교환
AS 경계 라우터
      ↓ BGP로 외부 경로 교환
다른 AS 경계 라우터
      ↓ 수신 정책 적용
외부 목적지 경로 선택
```

IGP는 AS 내부, EGP는 AS 사이의 라우팅 범주. 인터넷의 대표적인 EGP는 BGP.

### Ⅲ. 역사 용어 구분

초기 프로토콜 이름인 EGP와 오늘날의 프로토콜 범주 EGP 구별. RFC 904의 EGP는 역사적 프로토콜이며, BGP와 같은 의미가 아님.

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **EGP (Exterior Gateway Protocol)** 는 서로 다른 자율 시스템 사이에서 네트워크 도달 경로를 교환하는 프로토콜 범주 |
| 목적 | 자율 시스템 간 네트워크 도달성 제공 |

## Ⅱ. IGP와 EGP 적용 범위

| 구분 | IGP | EGP |
|---|---|---|
| 범위 | 단일 AS 내부 | 서로 다른 AS 사이 |
| 대표 프로토콜 | OSPF, IS-IS, RIP | BGP |
| 주된 기준 | 프로토콜별 비용·메트릭으로 내부 경로 계산 | 도달성 정보와 관리 정책에 따른 경로 선택 |

## Ⅲ. BGP 경로 교환

```text
AS 100 내부 IGP 경로
      ↓ 경계까지 도달
AS 100의 BGP 경계 라우터
      ↓ 접두사·AS_PATH 광고
이웃 AS의 BGP 라우터
      ↓ 정책 검사·경로 선택
선택 경로를 내부에 전달
```

BGP는 경로 벡터 방식. AS_PATH는 경로가 지난 AS를 기록하고, 라우터의 정책은 수신 경로의 허용·선호·재광고를 제어.

## Ⅳ. 경로 신뢰성과 운영 한계

| 한계 | 대응 |
|---|---|
| 오접속·오설정 경로 광고가 잘못된 도달성으로 이어질 수 있음 | 이웃·접두사 필터, 경로 정책, 변경 감시 적용 |
| 원점 AS가 잘못된 접두사를 광고할 수 있음 | RPKI 기반 원점 검증 결과를 정책에 반영 |
| 원점 검증만으로 AS 경로 전체의 진위를 보장할 수 없음 | AS 경로·피어 정책 등 추가 통제와 사고 대응 절차 병행 |

```text
BGP 접두사 경로
      ↓ ROA와 원점 AS 비교
원점 검증 상태
    ├─ 정책에 따라 허용·선호 → 경로 수용
    └─ 정책에 따라 제한 → 보류·거부·조사
```

RPKI 원점 검증은 광고 원점과 ROA의 권한 관계를 확인하는 범위. AS 경로 중간 구간의 모든 위변조를 검증하는 기능은 아님.

## Ⅴ. 기술사적 제언 — 정책과 경로 유효성의 함께 관리

| 한계 | 해결 방안 |
|---|---|
| 기술적으로 유효한 경로도 사업 정책·보안 조건에 맞지 않을 수 있음 | 접두사·이웃 기반 필터와 원점 검증 결과를 공통 경로 정책에 반영하고 변경 이력을 감사 |
