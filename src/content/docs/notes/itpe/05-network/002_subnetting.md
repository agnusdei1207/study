## 연관 키워드

- 서브네팅(Subnetting), 슈퍼네팅(Supernetting), CIDR(Classless Inter-Domain Routing), VLSM(Variable Length Subnet Mask)
- 서브넷 마스크(Subnet Mask), 라우트 집약(Route Aggregation), 클래스풀(Classful), BGP(Border Gateway Protocol)
- IPAM(IP Address Management), Null0 경로, 블랙홀 라우팅(Blackhole Routing), CGNAT(Carrier-Grade NAT)

## Ⅰ. 서브네팅·슈퍼네팅(CIDR·VLSM)의 개요

- 핵심 요약 : 비트 경계를 임의 길이로 옮겨 주소 공간을 나누거나 묶는 가변 길이 마스크 기반의 주소 관리 체계.
- 개념 : **서브네팅** (Subnetting, 호스트 비트를 빌려 하나의 네트워크를 여러 서브네트워크로 나누는 기법)과 **슈퍼네팅** (Supernetting, 연속된 네트워크를 묶어 라우팅 항목을 줄이는 기법)은 클래스 경계 없이 비트 단위로 주소를 다루며, 그 기반이 **CIDR** (Classless Inter-Domain Routing, 클래스 없는 도메인 간 라우팅)과 **VLSM** (Variable Length Subnet Mask, 가변 길이 서브넷 마스크)임.
- 배경 및 필요성 : 클래스풀(Classful) 주소 체계는 블록 크기가 A·B·C 세 가지로 고정되어 IPv4(Internet Protocol version 4) 주소가 크게 낭비되었고, 인터넷 백본의 BGP 라우팅 테이블이 폭증(Prefix Explosion)하여 새로운 주소 관리 방식이 필요해짐.
- 주요 목적 : 한정된 IPv4 주소의 이용 효율 극대화, 브로드캐스트 도메인 분할을 통한 보안과 성능 확보, 계층적 경로 집약을 통한 라우터 부하 경감.

## Ⅱ. 서브네팅·슈퍼네팅(CIDR·VLSM)의 특징 및 장점

- 핵심 요약 : 비트 경계를 자유롭게 옮기는 마스킹 방식이 주소 낭비 감소와 경로 집약이라는 장점으로 이어짐.

1. 가변 길이 분할 : 한 주소 블록을 부서나 링크 규모에 따라 서로 다른 길이로 나눔 → 필요한 만큼만 주소를 할당하여 주소 낭비 감소.
2. 비트 단위 표기 : CIDR 표기(/22, /28 등)로 임의 길이 경계를 표현 → 클래스 제약 없이 설계 가능.
3. 경로 집약 : 연속된 블록의 공통 상위 비트를 묶어 단일 프리픽스로 광고 → 라우팅 테이블 축소와 수렴 속도 향상.
4. 브로드캐스트 분할 : 서브넷 경계 단위로 브로드캐스트 영역을 제한 → 트래픽 격리와 보안 경계 설정.

## Ⅲ. 서브네팅·슈퍼네팅(CIDR·VLSM)의 구조 (흐름)

- 핵심 요약 : 32비트 주소에서 네트워크 영역과 호스트 영역의 경계를 마스크로 옮기는 비트 조작이 서브네팅과 슈퍼네팅의 공통 구조.
- **서브넷 마스크** (Subnet Mask) : 연속된 1 비트로 네트워크 영역을, 0 비트로 호스트 영역을 지정하고 AND 연산으로 목적지 네트워크를 식별.
- CIDR 표기법 : IP 주소 뒤에 프리픽스 길이(예: /22, /28)를 붙여 임의 길이 마스크를 표현.
- 라우트 집약 : 연속된 블록의 공통 상위 비트를 묶어 상위 라우터에 단일 슈퍼넷 프리픽스로 광고.

```text
[ 서브네팅: 호스트 비트를 네트워크로 ]

기본 /24 : 네트워크 24비트 | 호스트 8비트
   ↓ 2비트 차용
/26 서브넷 4개 (서브넷당 주소 64개)
   ↓
서브넷당 가용 호스트 62개
```

```text
[ 슈퍼네팅: 4개 /24를 1개 /22로 집약 ]

192.168.0.0/24
192.168.1.0/24
192.168.2.0/24
192.168.3.0/24
   ↓ 공통 상위 22비트로 묶음
192.168.0.0/22 (라우팅 항목 1개)
```

## Ⅳ. 서브네팅·슈퍼네팅(CIDR·VLSM)의 비교

- 핵심 요약 : 서브네팅은 조직 내부의 격리와 주소 최적화, 슈퍼네팅은 인터넷 전역의 라우팅 확장성 유지에 초점을 둔 기술.

| 비교 축 | 서브네팅 (Subnetting) | 슈퍼네팅 (Supernetting, CIDR) | 클래스풀 주소 (Classful) |
| --- | --- | --- | --- |
| 비트 조작 방향 | 호스트 비트를 네트워크 비트로 차용 | 네트워크 비트를 줄여 여러 블록을 집약 | A·B·C 고정 경계 (8·16·24비트) |
| 주요 목적 | 주소 낭비 방지, 브로드캐스트 분할 | 백본 BGP 라우팅 테이블 축소 | 초기 단순 주소 할당 |
| 적용 범위 | 사내망, 데이터센터, 클라우드 VPC | 백본 라우터, ISP 간 BGP 연동 | 레거시 네트워크 (현재 비표준) |
| 필요 프로토콜 | 클래스리스 지원 프로토콜 (OSPF(Open Shortest Path First), RIPv2(Routing Information Protocol version 2), BGP) | BGPv4, OSPFv3 등 CIDR 지원 라우터 | RIPv1, IGRP 등 마스크 미전송 프로토콜 |
| 주요 부작용 | 서브넷마다 네트워크·브로드캐스트 주소 손실 | 집약 범위 안 미할당 주소로 가는 트래픽이 대역 낭비 | 극심한 주소 고갈 (A·B 클래스 낭비) |

## Ⅴ. 서브네팅·슈퍼네팅(CIDR·VLSM)의 한계와 방안

- 핵심 요약 : 작은 서브넷의 주소 손실, 집약 경로의 블랙홀, IPv4 고갈을 점대점 /31 적용, Null0 폐기 경로, 듀얼스택 전환으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 작은 서브넷의 주소 손실 | /30 서브넷은 4개 주소 중 네트워크·브로드캐스트 주소 2개를 빼고 호스트 2개만 쓰므로 점대점 링크에서 50% 낭비 | 점대점 링크에 RFC 3021 기반 /31 서브넷 적용 (주소 2개를 호스트로 직접 할당) | 서브넷당 가용 호스트 비율 |
| 집약 경로의 블랙홀 라우팅 | 집약 범위 안의 미할당 목적지로 간 패킷이 버려지지 않고 상위 경로를 따라 되돌아가며 대역을 낭비 | 집약 경로와 같은 범위에 Null0 정적 폐기 경로를 두어 미할당 트래픽을 즉시 폐기 | 폐기 패킷 수, 대역 사용률 |
| IPv4 주소 고갈 | IoT와 5G 단말이 폭증하여 공인 IPv4 주소가 부족 | 사설 IP(RFC 1918)와 CGNAT(Carrier-Grade NAT) 병행, IPv6(Internet Protocol version 6) 듀얼스택 전환 | 공인 주소 사용률, IPv6 전환율 |

## Ⅵ. 서브네팅·슈퍼네팅(CIDR·VLSM)의 기술사적 제언

- 핵심 요약 : 주소 계획을 중앙에서 관리하고, 계층형 주소 설계와 경계 기반 보안을 함께 설계하는 주소 운영 체계.

1. 기업은 온프레미스와 여러 퍼블릭 클라우드의 VPC를 아우르는 중앙 IPAM(IP Address Management) 체계를 세워, 서로 다른 환경 사이에서 서브넷이 겹치는 문제를 사전에 막는 거버넌스를 확립해야 한다.
2. 백본 설계 조직은 지역, 센터, 기능 단위의 계층형 주소 블록을 설계하여 경로 집약 효과를 극대화하고, 최장 일치 검색(LPM, Longest Prefix Match) 부담을 줄이는 주소 계획을 수립해야 한다.
3. 보안 조직은 물리적 서브넷 경계에만 기대지 않고 소프트웨어 정의 네트워킹(SDN, Software-Defined Networking) 기반 마이크로 세그멘테이션(Micro-segmentation)을 결합하여, 제로 트러스트 원칙에 따라 워크로드 단위의 동적 격리 정책을 적용해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 서브네팅과 슈퍼네팅은 같은 비트 마스킹 원리를 반대 방향으로 쓰는 주소 관리 기술로서, 내부 효율과 외부 확장성을 함께 떠받침.
- 시사점 : 주소 계획을 중앙에서 관리하는 체계가 있어야 IPv4 잔여 자원을 아끼면서 IPv6 전환을 함께 감당할 수 있음.
