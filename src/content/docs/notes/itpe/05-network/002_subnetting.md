## 연관 키워드

- 서브네팅(Subnetting), 슈퍼네팅(Supernetting), CIDR, VLSM, prefix length
- 네트워크 주소, 브로드캐스트 주소, 라우트 집계, 주소 할당

## Ⅰ. 서브네팅·슈퍼네팅의 개요

- 핵심 요약 : 서브네팅은 주소 블록을 작은 네트워크로 나누고, 슈퍼네팅은 연속된 네트워크를 더 큰 CIDR 블록으로 묶는 주소 설계 기법.
- 개념 : CIDR은 클래스 경계 대신 `/prefix`로 네트워크 비트를 표시하며, VLSM은 요구 호스트 수에 따라 서로 다른 prefix 길이를 같은 주소 공간에 적용.
- 배경 및 필요성 : 클래스 기반 주소 할당은 주소 낭비와 라우팅 테이블 증가를 일으켜 유연한 할당·집계가 필요.
- 주요 목적 : 주소 공간을 효율적으로 배분하고 계층적 경로 요약으로 라우팅 확장성과 관리성을 높임.

## Ⅱ. 서브네팅·슈퍼네팅의 특징 및 장점

- 핵심 요약 : prefix 경계를 명시해 주소 블록을 규모에 맞게 분할하고, 정렬된 연속 블록을 요약해 주소·라우팅 자원을 절약.

1. 가변 prefix : 네트워크·호스트 비트 경계를 `/n`으로 지정 → 클래스 경계에 묶이지 않는 주소 할당.
2. VLSM : 큰 서브넷부터 수요에 맞는 크기로 배정 → 지점별 호스트 규모 차이에 따른 주소 낭비 감소.
3. 라우트 집계 : 연속된 정렬 블록을 공통 prefix로 요약 → 상위 라우터 경로 수와 전파량 감소.
4. 계층 설계 : 사이트·지역별 주소 블록을 계층적으로 배치 → 장애 격리와 라우팅 정책 관리 용이.

## Ⅲ. 주소 분할과 집계 흐름

- 핵심 요약 : 요구 호스트 수를 블록 크기로 변환하고 prefix 정렬에 맞춰 할당한 뒤, 연속 블록은 공통 prefix로 집계.

```text
주소 공간·사이트 수요 파악
        ↓
각 서브넷의 필요한 주소 수 산정
        ↓
필요 규모에 맞는 prefix 선택
        ↓
큰 블록부터 경계 정렬·할당
        ↓
네트워크·브로드캐스트·호스트 범위 검증
        ↓
연속 블록의 라우트 요약 검토
```

```text
IPv4 /n 블록 주소 수 = 2^(32-n)
일반 LAN 사용 호스트 수 = 블록 주소 수 - 네트워크/브로드캐스트 주소
예외: /31은 점대점 링크에서 양 주소 사용 가능, /32는 단일 주소 경로
```

## Ⅳ. FLSM과 VLSM의 비교

- 핵심 요약 : FLSM은 모든 서브넷 크기를 같게 유지해 단순하고, VLSM은 수요별 prefix를 써 주소 효율을 높이는 대신 설계·검증이 복잡.

| 비교 기준 | FLSM(Fixed Length Subnet Mask) | VLSM(Variable Length Subnet Mask) |
| --- | --- | --- |
| prefix 길이 | 모든 서브넷에 동일 | 서브넷 수요마다 다르게 설정 |
| 주소 효율 | 가장 큰 요구에 맞추면 작은 구간 낭비 | 각 구간 규모에 맞춰 사용량 절감 |
| 관리 난이도 | 계산·운영이 단순 | 주소 중첩·경계 오류 방지를 위한 계획 필요 |
| 적합한 경우 | 사이트 규모가 비슷하고 단순성이 중요한 경우 | 지점별 규모 차이가 크고 주소가 제한된 경우 |

## Ⅴ. 주소 설계의 한계와 방안

- 핵심 요약 : 중첩·정렬 오류는 블록 경계 검증으로, 과도한 집계는 장애·정책 경계를 확인해 예방.

| 위험 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 주소 중첩·누락 | 비트 경계 계산 오류로 통신 충돌 | IPAM(IP Address Management, IP 주소 관리) 도구와 예약 주소대장 사용 | 중복·미할당 주소 건수 |
| 과도한 주소 낭비 | 과대 prefix 할당과 성장 가정 오류 | 실제 사용량·증설 전망 기반 VLSM 적용 | 주소 활용률 |
| 잘못된 라우트 집계 | 비연속·정렬 불일치 블록을 잘못 요약 | 공통 prefix·경로 도달성·정책 검증 | 요약 경로 도달성 시험 |
| 보안 경계 약화 | 요약 경로가 세부 분리를 숨김 | ACL·방화벽 정책과 라우트 경계 동시 검토 | 정책 누락·우회 시험 |

## Ⅵ. 주소 계획에 대한 기술사적 제언

- 핵심 요약 : 네트워크 설계자는 주소를 계층적으로 예약하고 IPAM·라우팅·보안 정책을 동일한 기준선으로 관리.

1. 주소 설계자 : 사이트·환경·서비스별 블록을 미리 예약하고 네트워크 수요·성장률에 따라 VLSM을 적용.
2. 운영자 : 주소 변경을 IPAM·DHCP·DNS·라우팅 설정과 함께 승인·배포하고 자동 중복 검사를 수행.
3. 보안 담당자 : 슈퍼넷 집계 전 세부 라우트·ACL·방화벽 경계가 유지되는지 도달성·정책 시험으로 확인.

## Ⅶ. 결론

- 핵심 요약 : CIDR 기반 서브네팅·슈퍼네팅은 주소를 효율적으로 분할하고 경로를 계층적으로 집계하는 네트워크 설계 기법.
- 시사점 : 주소 효율만 보지 말고 확장, 라우팅 도달성, 보안 경계가 함께 유지되는 계층 구조를 설계해야 함.
