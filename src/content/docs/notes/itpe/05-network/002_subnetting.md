## 지식 로드맵 내 현재 위치

지식 위치: 네트워크 → IP 주소 설계 → **프리픽스 분할·집계**

## 30초 인출

- 본질: **서브네팅** : 주소 블록을 작은 네트워크로 분할, **슈퍼네팅** : 여러 블록을 공통 상위 경로로 집계
- 메커니즘: 프리픽스 길이를 늘리면 분할, 줄이면 집계. 주소 범위의 연속성과 경계 정렬 확인
- 통찰: 클래스풀 주소 체계의 극심한 IP 낭비를 방지하고 라우팅 테이블 크기를 최적화하기 위해 VLSM 기반 가변 분할과 CIDR 기반 경로 집약(Supernetting)을 병행 설계하는 것이 엔터프라이즈 IP 주소 관리의 정석임.

<details>
<summary>핵심 용어</summary>

- **서브네팅(Subnetting)** : IP 주소 블록을 더 긴 프리픽스의 작은 네트워크로 나누는 기법
- **슈퍼네팅(Supernetting)** : 인접한 주소 블록을 더 짧은 공통 프리픽스로 묶는 기법
- **CIDR(Classless Inter-Domain Routing)** : 클래스 경계 대신 주소와 프리픽스 길이로 네트워크를 표현·집계하는 방식
- **VLSM(Variable Length Subnet Mask)** : 네트워크별 요구 크기에 맞춰 서로 다른 길이의 서브넷 마스크를 쓰는 방식
- **프리픽스(Prefix)** : IP 주소의 네트워크를 식별하는 앞부분의 비트
- **LPM(Longest Prefix Match)** : 목적지 주소에 가장 길게 일치하는 경로를 선택하는 규칙

</details>

## 2~4교시 25점 답안

## Ⅰ. 서브네팅(Subnetting, CIDR 및 VLSM)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 할당된 하나의 네트워크 주소 공간을 서브넷 마스크(Subnet Mask)를 이용하여 복수 개의 작고 독립적인 논리 네트워크로 분할(Subnetting)하거나 집약(Supernetting)하는 기법 |
| 목적 | IPv4 유한 자원의 주소 낭비 최소화, 브로드캐스트 도메인 분할에 따른 대역폭 절감 및 라우팅 테이블 크기 축소 |

## Ⅱ. 서브네팅(Subnetting, CIDR 및 VLSM)의 특징

| 특징 | 상세 내용 |
|---|---|
| 호스트 비트 차용 | 네트워크 ID 영역을 확장하기 위해 기존 호스트 ID 비트의 상위 비트를 서브넷 ID로 차용 |
| 브로드캐스트 분할 | 대규모 단일 LAN을 격리된 복수 브로드캐스트 도메인으로 쪼개어 ARP 플러딩 트래픽 차단 |
| 가변 길이 할당(VLSM)| 고정 크기 분할(FLSM)과 달리 조직의 서브넷별 실제 호스트 수요에 맞춤형 마스크 적용 |
| 계층적 라우팅 축약| CIDR 기반 비트 일치 접두사(Prefix) 병합으로 인터넷 백본 라우팅 테이블 폭증 억제 |

## Ⅲ. 서브네팅(Subnetting, CIDR 및 VLSM)의 체계·프로세스

**서브넷 분할 및 비트 마스크 동작 메커니즘**

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ C 클래스 표준 주소 (192.168.1.0/24) ]                                │
│   네트워크 비트 (24비트)              호스트 비트 (8비트)              │
│   [ 11000000.10101000.00000001 ] . [ 0 0 0 0 0 0 0 0 ]                 │
│                                                                        │
│   ▼ 호스트 최상위 2비트 차용 (Subnetting -> /26 마스크 변환)          │
│                                                                        │
│ [ 서브넷 마스크 (255.255.255.192, /26) ]                               │
│   네트워크 비트 (24비트)        서브넷비트(2)   가용호스트비트(6)      │
│   [ 11000000.10101000.00000001 ] . [ 1 1 ]   [ 0 0 0 0 0 0 ]          │
│                                                                        │
│   분할 결과: 4개 서브넷 생성 (2^2 = 4), 각 서브넷당 64개 주소         │
│   ├─ Subnet #0: 192.168.1.0/26   (가용 호스트: .1 ~ .62,    BC: .63)   │
│   ├─ Subnet #1: 192.168.1.64/26  (가용 호스트: .65 ~ .126,  BC: .127)  │
│   ├─ Subnet #2: 192.168.1.128/26 (가용 호스트: .129 ~ .190, BC: .191)  │
│   └─ Subnet #3: 192.168.1.192/26 (가용 호스트: .193 ~ .254, BC: .255)  │
└────────────────────────────────────────────────────────────────────────┘
```

| 계산 요소 | 산출 공식 | 192.168.1.0/26 적용 예시 |
|---|---|---|
| **서브넷 개수** | 2^(차용한 서브넷 비트 수) | 2비트 차용 -> 2^2 = 4개 서브넷 |
| **블록 크기(간격)** | 256 - 마스크 10진수 값 | 256 - 192 = 64단위 증가 (0, 64, 128, 192) |
| **서브넷당 총 IP** | 2^(남은 호스트 비트 수) | 6비트 잔여 -> 2^6 = 64개 |
| **가용 호스트 수** | 2^(남은 호스트 비트 수) - 2 | 네트워크 주소 및 브로드캐스트 주소 제외 -> 62대 |

## Ⅳ. 서브네팅(Subnetting, CIDR 및 VLSM)의 종류·비교

| 비교 항목 | 고정 길이 서브네팅 (FLSM) | 가변 길이 서브네팅 (VLSM) |
|---|---|---|
| **마스크 길이** | 모든 서브넷에 동일한 마스크 적용 | 서브넷 호스트 규모별 상이한 마스크 적용 |
| **주소 효율성** | 소규모 망(예: WAN P2P)에서도 주소 낭비 발생 | 호스트 요구량에 맞추어 /30, /28 등 할당 극대화 |
| **설계 복잡도** | 단순 계산 및 균일 배치 가능 | 계층형 설계 및 중복 방지 정밀 계산 필요 |
| **지원 라우팅** | 모든 라우팅 프로토콜 (RIPv1 등 Classful 포함)| Classless 라우팅 프로토콜(OSPF, RIPv2, BGP) 필수 |

## Ⅴ. 서브네팅(Subnetting, CIDR 및 VLSM)의 한계와 방안

| 한계 | 방안 |
|---|---|
| 비트 단위 서브넷 계산 실수로 인한 IP 대역 충돌 및 기본 게이트웨이 할당 오류 | IPAM(IP Address Management) 솔루션 도입 및 자동화된 서브넷 할당 파이프라인 구축 |
| VLSM 남용 시 라우팅 테이블 파편화로 인한 코어 라우터 포워딩 성능 저하 | 서브넷 할당 단계부터 지리적·조직적 계층형 어드레싱 체계 수립 후 CIDR 집약(Supernetting) 적용 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
WAN 점대점(Point-to-Point) 링크 구간은 2개 가용 IP만 요구되므로 반드시 `/30` 마스크(4개 IP) 또는 RFC 3021 기반 `/31` 마스크(Point-to-Point 주소 지정)를 적용하여 주소 낭비 원천 차단.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ CIDR 기반 슈퍼네팅 (Supernetting / Route Summarization) 구조 ]       │
│                                                                        │
│   지사 서브넷 목록                                                     │
│   ├─ 10.1.0.0/24 [ 00001010.00000001.000000 00.00000000 ]             │
│   ├─ 10.1.1.0/24 [ 00001010.00000001.000000 01.00000000 ]             │
│   ├─ 10.1.2.0/24 [ 00001010.00000001.000000 10.00000000 ]             │
│   └─ 10.1.3.0/24 [ 00001010.00000001.000000 11.00000000 ]             │
│                                                                        │
│   ▼ 공통 비트 22자리 추출 집약 (Prefix Length: /22)                     │
│                                                                        │
│   [ 본사 코어 라우터 전파 경로 ]                                       │
│   = 10.1.0.0/22 (255.255.252.0) 단일 라우팅 엔트리로 압축 전파        │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 구분 | 서브네팅 (Subnetting) | 슈퍼네팅 (Supernetting / CIDR) |
|---|---|---|
| **마스크 조작** | 네트워크 비트 확장 (마스크 길이 증가: /24 -> /26) | 네트워크 비트 축약 (마스크 길이 감소: /24 -> /22) |
| **주요 목적** | 큰 네트워크를 작게 분할하여 브로드캐스트 격리 | 여러 작은 연속 네트워크를 단일 경로로 요약 전파 |
| **영향 범위** | 조직 내부 인트라넷 IP 배치 및 서브넷 라우팅 | 인터넷 백본(BGP) 라우팅 테이블 경량화 및 부하 절감 |
