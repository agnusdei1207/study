## 지식 로드맵 내 현재 위치

지식 위치: 네트워크 → IP 주소 설계 → **프리픽스 분할·집계**

## 30초 인출

- 본질: **서브네팅** : 주소 블록을 작은 네트워크로 분할, **슈퍼네팅** : 여러 블록을 공통 상위 경로로 집계
- 메커니즘: 프리픽스 길이를 늘리면 분할, 줄이면 집계. 주소 범위의 연속성과 경계 정렬 확인

<details>
<summary>핵심 용어</summary>

- **서브네팅(Subnetting)** : IP 주소 블록을 더 긴 프리픽스의 작은 네트워크로 나누는 기법
- **슈퍼네팅(Supernetting)** : 인접한 주소 블록을 더 짧은 공통 프리픽스로 묶는 기법
- **CIDR(Classless Inter-Domain Routing)** : 클래스 경계 대신 주소와 프리픽스 길이로 네트워크를 표현·집계하는 방식
- **VLSM(Variable Length Subnet Mask)** : 네트워크별 요구 크기에 맞춰 서로 다른 길이의 서브넷 마스크를 쓰는 방식
- **프리픽스(Prefix)** : IP 주소의 네트워크를 식별하는 앞부분의 비트
- **LPM(Longest Prefix Match)** : 목적지 주소에 가장 길게 일치하는 경로를 선택하는 규칙

</details>

## 1교시 10점 답안

### Ⅰ. 서브네팅·슈퍼네팅의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **서브네팅** : 프리픽스를 늘려 주소 블록 분할 / **슈퍼네팅** : 프리픽스를 줄여 인접 블록 집계 |
| 목적 | 요구 크기에 맞는 주소 배정과 요약 경로의 운영 |

### Ⅱ. 프리픽스 길이의 방향

| 방향 | 예시 | 결과 |
|---|---|---|
| 분할 | `192.0.2.0/24 → 192.0.2.0/25, 192.0.2.128/25` | 더 작은 두 네트워크 |
| 집계 | 두 인접 `/25 → 192.0.2.0/24` | 하나의 상위 경로 |

- 제언: 분할은 주소 중복·크기, 집계는 연속성·경계 정렬·경로 정책 확인.

## 2~4교시 25점 답안

## Ⅰ. 서브네팅·슈퍼네팅의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **서브네팅** : 프리픽스를 늘려 주소 블록 분할 / **슈퍼네팅** : 프리픽스를 줄여 인접 블록 집계 |
| 목적 | 요구 크기에 맞는 주소 배정과 요약 경로의 운영 |

## Ⅱ. 프리픽스와 주소 크기

| IPv4 프리픽스 | 주소 수 | 분할·집계에서의 의미 |
|---|---:|---|
| `/24` | 256 | 예시 상위 블록 |
| `/25` | 128 | `/24`를 2개로 분할 |
| `/26` | 64 | `/24`를 4개로 분할 |

IPv4 `/p`의 주소 수는 `2^(32-p)`. 일반적인 서브넷의 호스트 수는 네트워크·브로드캐스트 주소를 제외하되, 점대점 링크 `/31` 등은 별도 규칙 적용.

## Ⅲ. VLSM 주소 배정 예시

상위 블록 `192.0.2.0/24`, 필요 호스트 100·50·20·10개를 큰 요구부터 배정.

| 요구 호스트 | 선택 블록 | 할당 범위 | 사용 가능 호스트 |
|---:|---|---|---|
| 100 | `192.0.2.0/25` | .0–.127 | .1–.126 |
| 50 | `192.0.2.128/26` | .128–.191 | .129–.190 |
| 20 | `192.0.2.192/27` | .192–.223 | .193–.222 |
| 10 | `192.0.2.224/28` | .224–.239 | .225–.238 |

잔여 `192.0.2.240/28`. 각 블록의 시작 주소는 선택한 블록 크기의 경계와 일치.

## Ⅳ. 주소 설계·경로 집계 절차

```text
상위 프리픽스·요구 규모 확인
    ↓
큰 요구부터 VLSM 분할
    ↓
경계·중복·잔여 범위 검증
    ↓
연속·정렬된 블록 집계 검토
    ↓
실제 경로·도달성 확인
```

집계는 주소 수만 맞으면 가능한 작업이 아님. 인접 범위·상위 경계·하위 경로의 실제 도달성을 함께 확인.

## Ⅴ. 분할과 집계의 비교

| 관점 | 서브네팅·VLSM | 슈퍼네팅 |
|---|---|---|
| 프리픽스 길이 | 증가 | 감소 |
| 주된 결과 | 작은 네트워크의 주소 배정 | 더 큰 경로의 광고 |
| 핵심 검증 | 요구 크기·범위 중복·경계 | 연속성·정렬·집계 뒤 도달성 |
| 한계 | 주소 단편화·관리 복잡도 | 과잉 집계에 따른 잘못된 경로 유도 |

## Ⅵ. 한계와 대응

| 한계 | 대응 |
|---|---|
| 작은 블록부터 배치해 큰 블록의 정렬 공간 부족 | 큰 요구부터 할당하고 성장 공간 예약 |
| 주소 범위 중복 | IP 주소 관리 대장과 경계 계산으로 검증 |
| 비연속 블록을 하나로 과잉 집계 | 공통 프리픽스 범위와 미할당 구간 확인 |
| 집계 후 세부 경로가 빠져 접근 실패 | 요약 경로와 예외 세부 경로의 도달성 시험 |

## Ⅶ. 기술사적 제언

| 우선 제언 | 실행·확인 |
|---|---|
| 주소 배정과 경로 요약을 함께 설계 | 조직·서비스별 상위 블록을 정하고 VLSM 결과를 상위 프리픽스에 정렬 |
| 요약 경로의 범위 오인을 방지 | 광고 전 실제 소유 범위·정책·도달성을 확인 |
