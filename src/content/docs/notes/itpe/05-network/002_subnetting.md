## 연관 키워드

- 서브네팅(Subnetting), 슈퍼네팅(Supernetting), CIDR(Classless Inter-Domain Routing), VLSM(Variable Length Subnet Mask)
- 서브넷 마스크(Subnet Mask), AND 연산, 프리픽스 표기법, 라우트 집약(Route Aggregation)
- 브로드캐스트 도메인(Broadcast Domain), 클래스풀(Classful) 주소 체계, Null0 경로, IPAM(IP Address Management)

## Ⅰ. 서브네팅·슈퍼네팅(CIDR·VLSM)의 개요

- 핵심 요약 : 마스크의 비트 경계를 임의 길이로 옮겨 하나의 주소 블록을 나누거나 여러 블록을 묶는 가변 길이 주소 관리 기술.
- 개념 : 호스트 비트를 차용해 하나의 네트워크를 여러 작은 네트워크로 나누는 **서브네팅** (Subnetting)과, 연속된 복수 네트워크를 공통 상위 비트로 묶어 단일 경로로 표현하는 **슈퍼네팅** (Supernetting). 두 기술은 클래스 경계를 두지 않는 **CIDR** (Classless Inter-Domain Routing)과 길이가 다른 마스크의 혼용을 허용하는 **VLSM** (Variable Length Subnet Mask) 위에서 동작함.
- 배경 및 필요성 : A·B·C 세 크기로 고정된 클래스풀(Classful) 주소 체계는 주소 낭비가 극심했고 인터넷 백본의 라우팅 테이블 급증 위기가 있었음. 이에 따라 1993년 RFC 1519로 CIDR이 도입됨.
- 주요 목적 : 한정된 IPv4(Internet Protocol version 4) 주소의 이용 효율 극대화, **브로드캐스트 도메인** (Broadcast Domain, 브로드캐스트 프레임이 도달하는 범위) 분할을 통한 성능·보안 확보, 계층적 경로 집약으로 라우터 부하 경감.

## Ⅱ. 서브네팅·슈퍼네팅(CIDR·VLSM)의 특징 및 장점

- 핵심 요약 : 비트 경계를 자유로이 옮기는 마스킹 방식이 주소 절약, 설계 유연성, 라우팅 효율이라는 장점으로 이어짐.

1. 가변 길이 분할 : 같은 상위 블록 안에서도 용도별로 마스크 길이를 다르게 두는 VLSM 적용 → 링크·부서 규모에 맞는 최소 할당으로 주소 낭비 감소.
2. 비트 단위 표기 : 주소 뒤에 프리픽스 길이를 붙이는 프리픽스 표기법(/24, /26) 사용 → 클래스 제약 없는 자유로운 주소 설계.
3. 경로 집약 : 연속 블록의 공통 상위 비트를 단일 프리픽스로 광고하는 라우트 집약(Route Aggregation) → 라우팅 테이블 축소와 수렴 속도 향상.
4. 브로드캐스트 도메인 분할 : 서브넷 경계를 기준으로 브로드캐스트 전파 범위를 제한 → 트래픽 격리와 보안 경계 확보.

## Ⅲ. 서브네팅·슈퍼네팅(CIDR·VLSM)의 구조 (흐름)

- 핵심 요약 : 32비트 주소에서 네트워크 영역과 호스트 영역의 경계를 마스크로 옮기는 비트 연산이 두 기술의 공통 구조.
- **서브넷 마스크** (Subnet Mask) : 연속된 1비트는 네트워크 영역, 0비트는 호스트 영역을 뜻하며 목적지 주소와의 **AND 연산** (비트별 논리곱)으로 목적지 네트워크를 식별.
- 서브넷의 경계 주소 : 각 서브넷의 첫 주소는 네트워크 주소, 마지막 주소는 브로드캐스트 주소로 예약되며 그 사이가 가용 호스트 범위임.

```text
[ 서브네팅 : 호스트 비트 2비트 차용 ]

/24 (네트워크 24비트 + 호스트 8비트)
    ↓ 마스크를 /26으로 연장
서브넷 4개 생성 (각 64개 주소)
    ↓
서브넷당 가용 호스트 62개
```

```text
[ 슈퍼네팅 : 4개의 /24를 하나의 /22로 ]

192.168.0.0/24
192.168.1.0/24
192.168.2.0/24
192.168.3.0/24
    ↓ 공통 상위 22비트 추출
192.168.0.0/22 단일 경로 광고
```

## Ⅳ. 서브네팅·슈퍼네팅(CIDR·VLSM)의 비교

- 핵심 요약 : 서브네팅은 조직 내부의 격리와 절약, 슈퍼네팅은 인터넷 전역의 라우팅 확장성을 담당하는 상반 방향의 기술.

| 비교 축 | 서브네팅 (Subnetting) | 슈퍼네팅 (Supernetting) | 클래스풀 주소 (Classful) |
| --- | --- | --- | --- |
| 비트 조작 방향 | 호스트 비트를 네트워크 영역으로 차용 | 네트워크 비트를 줄여 여러 블록을 집약 | A·B·C 고정 경계(8·16·24비트) |
| 주요 목적 | 주소 절약, 브로드캐스트 도메인 분할 | 백본 라우팅 테이블 축소 | 초기의 단순 주소 할당 |
| 적용 범위 | 사내망, 데이터센터, 클라우드 가상망 | 백본 라우터, 사업자 간 경로 광고 | 레거시 장비(현재는 비표준) |
| 필요 조건 | 가변 마스크 지원 라우팅 프로토콜 | 연속 블록과 CIDR 지원 라우팅 | 마스크 미전송 프로토콜 |
| 부작용 | 서브넷마다 2개의 예약 주소 손실 | 집약 범위 내 미할당 주소 트래픽 문제 | 극심한 주소 낭비 |

- 선택 기준 : 내부 망의 격리와 주소 절약이 과제이면 서브네팅을, 상위 라우터의 경로 수 줄이기가 과제이면 슈퍼네팅을 적용하고, 두 기술은 계층형 주소 계획 안에서 함께 설계함.

## Ⅴ. 서브네팅·슈퍼네팅(CIDR·VLSM)의 한계와 방안

- 핵심 요약 : 점대점 링크의 주소 낭비, 집약 경로의 블랙홀, IPv4 고갈을 /31 서브넷, Null0 폐기 경로, 사설 주소·듀얼스택으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 점대점 링크의 주소 낭비 | /30 서브넷은 4개 주소 중 네트워크·브로드캐스트 2개가 예약되어 링크당 절반이 버려짐 | RFC 3021 기반 /31 서브넷 적용으로 주소 2개를 호스트에 직접 할당 | 링크당 가용 주소 비율 |
| 집약 경로의 블랙홀 | 집약 범위 안 미할당 목적지 트래픽이 상위 경로를 따라 순환하며 대역 낭비 | 집약 라우터에 Null0 경로를 두어 미할당 트래픽 즉시 폐기 | 폐기 패킷 비율 |
| IPv4 주소 고갈 | 단말·서비스 폭증으로 공인 주소가 부족 | 사설 주소(RFC 1918)와 NAT(Network Address Translation) 병행, IPv6(Internet Protocol version 6) 듀얼스택 전환 | 공인 주소 사용률, IPv6 전환율 |

## Ⅵ. 서브네팅·슈퍼네팅(CIDR·VLSM)의 기술사적 제언

- 핵심 요약 : 중앙 주소 관리, 계층형 주소 설계, 세그멘테이션 연계를 갖춘 주소 운영 체계로 발전시키는 방향.

1. 기업의 네트워크 운영 조직은 온프레미스와 복수 클라우드의 VPC(Virtual Private Cloud)를 아우르는 중앙 IPAM(IP Address Management) 체계를 구축해, 환경 간 서브넷 중복 할당을 사전에 차단하는 거버넌스를 확립해야 한다.
2. 백본 설계 조직은 지역·센터·기능 단위의 계층형 주소 블록을 설계해 경로 집약 효과를 극대화하고, 최장 프리픽스 일치(Longest Prefix Match) 검색 부담을 완화하는 주소 계획 절차를 표준화해야 한다.
3. 보안 아키텍처 조직은 물리적 서브넷 경계에만 의존하지 않도록 워크로드 단위의 마이크로 세그멘테이션(Micro-segmentation)과 제로 트러스트 정책을 결합한 동적 격리 체계를 설계해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 서브네팅과 슈퍼네팅은 같은 마스킹 원리를 나누는 방향과 묶는 방향으로 쓰는 주소 관리 기술의 양면임.
- 시사점 : 중앙 주소 관리 체계와 계층형 설계가 뒷받침될 때 잔여 IPv4 자원의 효율과 IPv6 전환의 안정성이 함께 확보됨.
