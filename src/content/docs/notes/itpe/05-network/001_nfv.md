## Ⅰ. NFV(Network Functions Virtualisation)의 개요

- **개념** : 라우터, 방화벽, EPC/5GC 등 기존에 전용 하드웨어 어플라이언스에 종속되어 동작하던 네트워크 기능을 범용 COTS(Commercial Off-The-Shelf) x86/ARM 서버 상의 가상머신(VM) 및 컨테이너 소프트웨어 인스턴스로 분리 실행하는 가상화 아키텍처.
- **배경 및 필요성** : 통신 사업자의 신규 네트워크 서비스 도입 시 장비 구매와 상면 확보에 따른 막대한 CAPEX/OPEX 부담을 해소하고, 수개월 이상 소요되던 서비스 출시 기간(Time-to-Market)을 단축하며 유연한 트래픽 스케일링을 달성하기 위해 ETSI 주도로 출현함.
- **핵심 목적** : 네트워크 기능의 소프트웨어화(Softwarization), 인프라 자원의 풀링 및 동적 오케스트레이션, 벤더 종속성(Lock-in) 탈피를 통한 운영 민첩성 극대화.

## Ⅱ. NFV(Network Functions Virtualisation)의 핵심 아키텍처 및 동작 메커니즘

NFV는 ETSI 표준 프레임워크에 기반하여 가상 네트워크 기능(VNF), 하드웨어 및 가상화 계층을 포괄하는 인프라(NFVI), 그리고 자원 생명주기를 총괄하는 오케스트레이션 체계(NFV-MANO)로 구성됨.

```text
[ ETSI NFV 표준 아키텍처 프레임워크 ]

+-----------------------------------------------------------------+
|                    NFV-MANO (관리 및 오케스트레이션)            |
|  +-----------------------------------------------------------+  |
|  | NFVO (NFV Orchestrator): E2E 네트워크 서비스 조정/생명주기 |  |
|  +-----------------------------------------------------------+  |
|         │ (Or-Vnfm)                         │ (Or-Vi)           |
|         ▼                                   ▼                   |
|  +---------------------------+       +-----------------------+  |
|  | VNFM (VNF Manager)        |       | VIM (Virtualised      |  |
|  | - VNF 인스턴스 생명주기   |       |   Infrastructure Mgr) |  |
|  |   (생성, 확장, 치유, 종료)|       | - NFVI 가상 자원 할당 |  |
|  +---------------------------+       +-----------------------+  |
+-----------------│───────────────────────────────│───────────────+
                  │ (Ve-Vnfm)                     │ (Nf-Vi)
                  ▼                               ▼
+------------------------------------+ +--------------------------+
| VNF 계층 (Virtual Network Function)| | NFVI (NFV 인프라 계층)   |
| +------------+  +------------+     | | [가상 자원: VM, CNI, vSwitch]|
| | VNF 1 (vFW)|  | VNF 2 (vEPC)|    | | ------------------------ |
| +------------+  +------------+     | | [가상화 계층: KVM, Docker] |
|                                    | | ------------------------ |
| +--------------------------------+ | | [물리 자원: COTS Server, |
| | Element Management (EMS)       | | |   스토리지, COTS L2/L3]  |
| +--------------------------------+ | +--------------------------+
+------------------------------------+
```

- **NFV-MANO(Management and Orchestration)** : NFVO, VNFM, VIM의 3개 핵심 계층으로 구성되어 물리/가상 인프라 및 네트워크 서비스의 전주기 자동화를 담당.
- **NFVO(NFV Orchestrator)** : 전체 네트워크 서비스 템플릿(NSD)을 기반으로 여러 VNF 간의 체이닝(SFC)과 전역 자원 할당을 총괄 조정.
- **VNFM(VNF Manager)** : 개별 VNF 인스턴스의 인스턴스화, 동적 스케일 인/아웃, 장애 복구(Auto-Healing), 소프트웨어 업그레이드 등 수명주기 전담 관리.
- **VIM(Virtualised Infrastructure Manager)** : OpenStack, Kubernetes 등 NFVI 내 컴퓨트, 스토리지, 가상 네트워크 자원의 실시간 제어 및 할당 수행.
- **NFVI(NFV Infrastructure)** : COTS 하드웨어 자원(COTS 서버, 고속 NIC, 플래시 스토리지)과 가상화 계층(KVM, DPDK, OVS)을 결합한 통합 실행 기반.

## Ⅲ. NFV(Network Functions Virtualisation)의 세부 구성 요소 및 비교 분석

| 비교 항목 | NFV (네트워크 기능 가상화) | SDN (소프트웨어 정의 네트워킹) | 클라우드 컴퓨팅 (Cloud Computing) |
|---|---|---|---|
| **핵심 목적** | L4~L7 네트워크 어플라이언스 소프트웨어화 | L2~L3 패킷 제어 평면과 전달 평면 분리 | 범용 컴퓨트·스토리지 애플리케이션 가상화 |
| **표준화 기구** | ETSI NFV ISG | ONF (Open Networking Foundation) | NIST, IEEE, CNCF |
| **운영 대상** | v라우터, v방화벽, 5G vEPC, vIMS | 오픈플로우 스위치, 라우터 포워딩 테이블 | 웹 애플리케이션, 빅데이터, 데이터베이스 |
| **핵심 기술** | DPDK, SR-IOV, SFC, NFV-MANO | OpenFlow, NETCONF, P4, 중앙 컨트롤러 | Hypervisor, K8s, Microservices, IaaS/PaaS |
| **상호 관계** | SDN을 NFVI 네트워크 전달 계층으로 활용 가능 | NFV 환경의 트래픽 조향 및 SFC 구축 지원 | NFV를 클라우드 네이티브 컨테이너(CNF)로 구현 |

- NFV와 SDN은 상호 배타적이지 않으며, NFV로 가상화된 VNF 간의 복잡한 패킷 포워딩 및 서비스 기능 체이닝(SFC)을 SDN 제어기가 동적으로 구성함으로써 완전한 통신 자동화를 완성함.

## Ⅳ. NFV(Network Functions Virtualisation)의 주요 한계점 및 해결 방안

- **가상화 계층 경유에 따른 I/O 패킷 처리 지연 및 오버헤드** :
  - **한계점** : COTS 서버의 범용 OS 커널 네트워크 스택을 거치는 과정에서 잦은 컨텍스트 스위칭과 인터럽트 지연으로 고속 회선(100GbE+) 패킷 드롭 발생.
  - **해결 방안** : 커널 바이패스 기술인 DPDK(Data Plane Development Kit), 하드웨어 직접 매핑 SR-IOV, eBPF/XDP 기반 고속 데이터 패스 엔진 전면 적용.
- **멀티벤더 VNF 간 상호운용성 결여 및 MANO 복잡성** :
  - **한계점** : 서로 다른 통신 장비 벤더의 VNF 패키징 포맷 및 EMS 관리 체계가 상이하여 통합 오케스트레이션 구축 시 막대한 커스터마이징 비용 유발.
  - **해결 방안** : TOSCA 기반 VNF 서술자(VNFD) 표준화, 오픈소스 MANO(OSM) 프레임워크 준수, 클라우드 네이티브 CNF(Container Network Function) 표준 채택.
- **캐리어 그레이드(99.999%) 고가용성 및 실시간 장애 복구 난제** :
  - **한계점** : 물리 장비 대비 VM/컨테이너 인스턴스의 불시 장애 발생 시 세션 단절 없는 무손실 장애 복구 시간(50ms 이하) 보장 곤란.
  - **해결 방안** : 액티브-스탠바이 VNF 상태 동기화 엔진, 텔레메트리 기반 이상 감지, 쿠버네티스 CNI 레벨의 고속 힐링 자동화 구축.

## Ⅴ. NFV(Network Functions Virtualisation) 적용 및 발전을 위한 기술사적 제언

- **VNF에서 CNF(Cloud-native Network Function)로의 구조적 전환** : 마이크로서비스 아키텍처와 경량 컨테이너를 기반으로 5G 코어 및 vRAN을 배포하여 배포 속도와 자원 효율을 극대화해야 함.
- **AIOps 기반의 Closed-Loop 자율 제어 체계 도입** : 실시간 스트리밍 텔레메트리 데이터를 머신러닝 엔진과 연계하여 트래픽 예측 기반의 선제적 오토스케일링 및 장애 자가 치유를 실현해야 함.
- **5G SA 네트워크 슬라이싱 연계 E2E 서비스 체이닝 구현** : URLLC, eMBB 등 서비스 유형별 엄격한 SLA를 만족할 수 있도록 NSSF 및 3GPP 표준 슬라이싱과 연계된 동적 VNF 체이닝을 설계해야 함.
