<details><summary>핵심 용어</summary>

- `NFV(Network Functions Virtualisation)`: 기능과 전용 장비의 결합을 끊어 소프트웨어 생명주기로 전환함
- `VNF(Virtualised Network Function)`: NFVI 위에서 실행되는 소프트웨어 네트워크 기능임
- `NFVI(NFV Infrastructure)`: VNF에 계산·저장·네트워크 자원을 제공함
- `NFV-MANO(NFV Management and Orchestration)`: 서비스·기능·자원의 생명주기를 연결함
- `NFVO(NFV Orchestrator)·VNFM(VNF Manager)·VIM(Virtualised Infrastructure Manager)`: 서비스·VNF·인프라를 각각 통제함
</details>

## 1교시 10점 답안
### Ⅰ. 정의·목적
- 정의: **NFV(Network Functions Virtualisation)** 는 네트워크 기능을 전용 장비에서 분리해 **NFVI(NFV Infrastructure)** 위의 소프트웨어로 실행하는 아키텍처다.
- 목적: 기능의 배치·확장·복구를 자동화해 서비스 변경에 대응한다.

| 구성 | 역할 |
|---|---|
| **NFVO** | 네트워크 서비스 조합과 자원 오케스트레이션 |
| **VNFM** | VNF 생명주기 관리 |
| **VIM** | NFVI 자원 관리 |
| **VNF / NFVI** | 네트워크 기능 실행 / 계산·저장·네트워크 기반 제공 |

- 제언: Descriptor와 운영 지표를 연결해 배치 성공이 실제 서비스 품질로 이어지는지 확인한다.

## 2~4교시 25점 답안

## Ⅰ. 전용 장비 종속성을 해소하는 NFV 개요
> NFV는 기능의 실행 위치와 규모를 소프트웨어 생명주기로 바꾸며, 성패는 가상화보다 서비스 요구사항과 실측 품질의 연결에서 갈림.

- 정의: **NFV(Network Functions Virtualisation)**는 **네트워크 기능**을 전용 장비에서 분리하여 **NFVI** 위의 소프트웨어로 실행하는 아키텍처임
- 목적: 기능 배치·확장·복구 자동화 → 서비스 변경 속도와 자원 탄력성 확보

## Ⅱ. NFVI·VNF·MANO 구성과 동작
> NFVO는 서비스를, VNFM은 기능을, VIM은 자원을 책임지며 Descriptor가 세 관리 범위의 일관성을 묶음.

  <div class="itpe-flow__node"><strong>서비스 설계</strong><small><b>활동:</b> NSD(Network Service Descriptor)·VNFD(VNF Descriptor)와 정책 온보딩</small><small><b>산출:</b> 검증된 Descriptor</small></div><div class="itpe-flow__arrow">↓</div>
  <div class="itpe-flow__node"><span class="itpe-keyword"><strong>NFVO</strong></span><small><b>활동:</b> 서비스 조합 · 배치 결정</small><small><b>산출:</b> 서비스 그래프</small></div><div class="itpe-flow__arrow">↓</div>
  <div class="itpe-flow__node"><span class="itpe-keyword"><strong>VNFM · VIM</strong></span><small><b>활동:</b> VNF 생명주기 · 자원 할당</small><small><b>산출:</b> 연결된 VNF</small></div><div class="itpe-flow__arrow">↓</div>
  <div class="itpe-flow__node"><strong>폐루프 운영</strong><small><b>활동:</b> 감시 · Scale · Heal · 종료</small><small><b>산출:</b> 정책에 수렴한 서비스</small></div>
</div>

## Ⅲ. NFV와 SDN 비교
> NFV는 기능 실행을, SDN은 패킷 경로를 소프트웨어화하므로 서비스 체인을 공동 완성하는 보완 관계임.

| 축 | NFV | SDN |
|---|---|---|
| 대상 | **네트워크 기능** | **제어 평면** |
| 분리 | 기능 SW vs 전용 HW | Control Plane vs Data Plane |
| 제어 | VNF·서비스 생명주기 | Flow·경로·정책 |
| 구조 | NFVI·VNF·**MANO** | Application·Controller·Switch |

## Ⅳ. 성능·복원력·상호운용성 대책
> 평균 처리량보다 데이터 평면 병목·상태 복구·Descriptor 상호운용성을 함께 검증해야 운영 품질이 확보됨.

| 문제 | 원인 | 대책 | 판정 |
|---|---|---|---|
| 지연 증가 | 가상 스위치·복사 | **DPDK(Data Plane Development Kit)**·SR-IOV(Single Root I/O Virtualization)·NUMA(Non-Uniform Memory Access) 정렬 | 꼬리 지연·손실 |
| 장애 확대 | MANO·상태 집중 | 장애영역 분산·상태 백업 | 복구·서비스 지속 |
| 연동 실패 | Descriptor·API 차이 | 적합성 시험·버전 Baseline | 온보딩·LCM 성공 |
| 공급망 위험 | 패키지 위변조 | 서명·SBOM(Software Bill of Materials)·격리 | 무결성·영향 범위 |

| 문제 | 해결 방안 |
