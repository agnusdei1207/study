## 연관 키워드

- NFV(Network Functions Virtualisation), VNF(Virtual Network Function), NFVI(NFV Infrastructure), NFV-MANO
- NFVO(NFV Orchestrator), VNFM(VNF Manager), VIM(Virtualised Infrastructure Manager)
- SDN(Software-Defined Networking), SFC(Service Function Chaining), CNF(Cloud-native Network Function), DPDK(Data Plane Development Kit)

## Ⅰ. NFV(Network Functions Virtualisation)의 개요

- 핵심 요약 : 전용 장비에 묶여 있던 네트워크 기능을 범용 서버 위 소프트웨어로 분리하여 도입과 운영의 민첩성을 확보하는 가상화 아키텍처.
- 개념 : 라우터, 방화벽, 5G 코어처럼 전용 하드웨어 장비에 종속되어 있던 네트워크 기능을 **네트워크 기능 가상화** (NFV, Network Functions Virtualisation)를 통해 COTS(Commercial Off-The-Shelf, 상용 범용 제품) 서버 위의 가상머신(VM, Virtual Machine)이나 컨테이너 형태의 소프트웨어 인스턴스로 실행하는 기술.
- 배경 및 필요성 : 통신 사업자가 신규 서비스를 도입할 때 장비 구매와 설치 공간에 드는 CAPEX(Capital Expenditure, 자본적 지출) 부담이 크고 출시까지 수개월이 걸려, 장비 교체 없이 소프트웨어로 기능을 추가하고 트래픽에 맞춰 늘리는 방식이 필요해짐. 이 요구를 바탕으로 ETSI(European Telecommunications Standards Institute)가 표준화를 주도함.
- 주요 목적 : 네트워크 기능의 소프트웨어화, 인프라 자원의 풀링과 동적 오케스트레이션, 벤더 종속(Lock-in) 완화를 통한 운영 민첩성 확보.

## Ⅱ. NFV(Network Functions Virtualisation)의 특징 및 장점

- 핵심 요약 : 기능의 소프트웨어화와 자원 풀링이 빠른 배포, 탄력적 확장, 벤더 중립성의 장점으로 이어지는 구조.

1. 소프트웨어화 : 네트워크 기능을 가상머신이나 컨테이너 이미지로 배포 → 장비 설치 없이 기능 추가와 업그레이드가 가능해 서비스 출시 기간 단축.
2. 자원 풀링 : 범용 서버 자원을 공유 풀로 묶어 필요한 기능에 동적으로 배정 → 트래픽 변화에 맞춘 탄력적 확장과 자원 이용률 향상.
3. 자동 오케스트레이션 : 기능의 생성, 확장, 자동 복구, 종료를 표준 절차로 자동화 → 운영 인력 부담 감소와 장애 대응 속도 향상.
4. 벤더 중립성 : 표준 인터페이스를 따르는 기능 교체가 가능 → 특정 벤더 종속 완화와 구매 협상력 확보.

## Ⅲ. NFV(Network Functions Virtualisation)의 구조 (흐름)

- 핵심 요약 : 기능(VNF), 인프라(NFVI), 관리(NFV-MANO)의 세 층으로 나뉘고, 관리 계층이 전체 생명주기를 제어하는 구조.
- **VNF** (Virtual Network Function, 가상 네트워크 기능) : 방화벽, 라우터, 5G 코어 기능을 소프트웨어로 구현한 인스턴스.
- **NFVI** (NFV Infrastructure, NFV 인프라 계층) : COTS 서버, 고속 NIC, 스토리지와 가상화 계층(KVM(Kernel-based Virtual Machine), DPDK(Data Plane Development Kit), Open vSwitch 등)을 묶은 실행 기반.
- **NFV-MANO** (Management and Orchestration) : NFVO, VNFM, VIM으로 구성되어 기능과 인프라의 전주기 자동화를 담당하는 관리 체계.
- **NFVO** (NFV Orchestrator) : 네트워크 서비스 템플릿을 바탕으로 VNF 간 **서비스 기능 체이닝** (SFC, Service Function Chaining)과 전역 자원 할당을 조정.
- **VNFM** (VNF Manager) : 개별 VNF의 생성, 확장, 장애 복구, 종료 등 생명주기를 전담 관리.
- **VIM** (Virtualised Infrastructure Manager) : OpenStack, Kubernetes 같은 도구로 NFVI의 컴퓨트, 스토리지, 네트워크 자원을 할당하고 제어.

```text
[ 제어 흐름 ]

NFVO (서비스 조정, 전역 자원)
   ↓
VNFM (VNF 생명주기 관리)
   ↔ VNF 계층 (vFW, vEPC 등)
   ↓
VIM (NFVI 자원 할당)
   ↔ NFVI 계층 (COTS 자원)
```

```text
[ NFVI 계층의 실행 구조 ]

VNF (소프트웨어 네트워크 기능)
   ↓ 가상 자원 위에서 실행
VM·컨테이너·가상 스위치
   ↓ 가상화 계층 (KVM, DPDK 등)
COTS 서버·스토리지·스위치
```

## Ⅳ. NFV(Network Functions Virtualisation)의 비교

- 핵심 요약 : NFV는 네트워크 기능의 소프트웨어화, SDN은 제어와 전달의 분리, 클라우드 컴퓨팅은 범용 애플리케이션 가상화에 초점을 둔 기술이며 서로 보완 관계임.

| 비교 축 | NFV | SDN (Software-Defined Networking) | 클라우드 컴퓨팅 |
| --- | --- | --- | --- |
| 핵심 목적 | L4~L7 네트워크 기능의 소프트웨어화 | L2~L3 제어 평면과 전달 평면의 분리 | 범용 컴퓨트·스토리지 애플리케이션 가상화 |
| 표준화 주체 | ETSI NFV ISG | ONF(Open Networking Foundation) | NIST, CNCF |
| 운영 대상 | 가상 라우터, 가상 방화벽, 5G vEPC | OpenFlow 스위치, 라우터 포워딩 테이블 | 웹 애플리케이션, 빅데이터, 데이터베이스 |
| 핵심 기술 | DPDK, SFC, NFV-MANO | OpenFlow, NETCONF, 중앙 컨트롤러 | 하이퍼바이저, 쿠버네티스, 마이크로서비스 |
| 상호 관계 | SDN을 NFVI의 전달 계층으로 활용 가능 | NFV 환경의 트래픽 조향과 SFC 구성 지원 | NFV를 컨테이너 기반 CNF로 구현 |

- 선택 기준 : 전용 장비를 대체할 기능 자체의 소프트웨어화가 목표이면 NFV, 망의 경로 제어 자동화가 목표이면 SDN을 중심에 두고, 두 기술을 결합하면 VNF 간 SFC를 SDN 컨트롤러가 동적으로 구성하는 완전한 통신 자동화에 도달함.

## Ⅴ. NFV(Network Functions Virtualisation)의 한계와 방안

- 핵심 요약 : 가상화 계층의 패킷 처리 지연, 멀티벤더 상호운용성, 고가용성 확보가 주요 한계이며, 가속 기술과 표준 서술자, 상태 동기화로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 패킷 처리 지연과 손실 | 범용 OS 커널 네트워크 스택을 거치며 컨텍스트 전환과 인터럽트가 잦아 고속 회선에서 패킷 드롭 발생 | 커널 우회 기술 DPDK, 하드웨어 직접 할당 SR-IOV(Single Root I/O Virtualization), XDP(eXpress Data Path) 기반 데이터 경로 | 패킷 드롭률, 처리량 |
| 멀티벤더 상호운용성 부족 | 벤더마다 VNF 패키징과 EMS(Element Management System) 체계가 달라 통합 오케스트레이션 비용 증가 | TOSCA(Topology and Orchestration Specification for Cloud Applications) 기반 VNF 서술자(VNFD) 표준화, 오픈소스 MANO(OSM) 준수, CNF 채택 | 연동 공수, 표준 준수율 |
| 고가용성과 장애 복구 | 가상 인스턴스의 불시 장애 시 세션 단절 없이 복구하기 어려움 | 액티브-스탠바이 상태 동기화, 텔레메트리 기반 이상 감지, 자동 치유 체계 | 장애 전환 시간, 세션 단절률 |

## Ⅵ. NFV(Network Functions Virtualisation) 적용을 위한 기술사적 제언

- 핵심 요약 : 컨테이너 기반 전환, 자율 운영, 슬라이싱 연계를 함께 추진하여 NFV를 일회성 가상화가 아닌 상시 운영 기반으로 발전시키는 방향.

1. 사업자는 VNF를 마이크로서비스 기반의 CNF로 전환하는 로드맵을 세워, 5G 코어와 가상화 무선접속망(vRAN, virtualized Radio Access Network)의 배포 속도와 자원 효율을 함께 높여야 한다.
2. 통신 운영 조직은 실시간 텔레메트리를 머신러닝 분석과 연결하여 트래픽을 미리 예측하고 장애를 스스로 복구하는 폐루프 운영 체계를 도입하고, 그 기준을 AIOps(Artificial Intelligence for IT Operations) 거버넌스로 관리해야 한다.
3. 5G 네트워크 슬라이싱을 도입할 때는 URLLC(Ultra-Reliable Low-Latency Communications)와 eMBB(Enhanced Mobile Broadband) 같은 서비스 유형별 SLA(Service Level Agreement)를 3GPP(3rd Generation Partnership Project) 표준 슬라이스와 연계된 VNF 체이닝으로 보장해야 한다.

## Ⅶ. 결론

- 핵심 요약 : NFV는 네트워크 기능을 소프트웨어로 분리하여 인프라 자원 풀링과 자동 운영을 가능하게 하는 가상화 아키텍처임.
- 시사점 : 가상화 계층의 성능 확보와 클라우드 네이티브 전환이 함께 이뤄질 때 비용 절감과 민첩성 효과가 지속됨.
