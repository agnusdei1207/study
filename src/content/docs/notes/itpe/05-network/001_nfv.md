## 연관 키워드

- NFV(Network Functions Virtualisation), VNF(Virtualised Network Function), NFVI(NFV Infrastructure)
- ETSI NFV-MANO, VIM(Virtualised Infrastructure Manager), 오케스트레이션, 서비스 체이닝

## Ⅰ. NFV의 개요

- 핵심 요약 : NFV는 전용 네트워크 장비에 결합된 통신 기능을 범용 컴퓨팅·가상화 인프라의 소프트웨어 기능으로 분리하는 구조.
- 개념 : 방화벽·라우터·EPC 등 네트워크 기능을 VNF로 구현하고 NFVI와 관리·오케스트레이션 체계에서 배치·운영하는 기술.
- 배경 및 필요성 : 기능별 전용장비 증설은 조달주기가 길고 용량이 고정되어 서비스 변화와 트래픽 변동에 신속히 대응하기 어려움.
- 주요 목적 : 네트워크 기능의 소프트웨어화와 자원 풀링으로 서비스 도입 민첩성, 운영 유연성, 비용 효율을 높임.

## Ⅱ. NFV의 특징 및 장점

- 핵심 요약 : 기능과 하드웨어의 결합을 풀어 자원을 공유하고, 자동 배치·확장으로 서비스 변경 속도와 자원 활용도를 개선.

1. 기능·장비 분리 : VNF를 범용 서버·가상화 계층에서 실행 → 전용 장비 종속과 기능 도입 리드타임 감소.
2. 자원 풀링 : CPU·메모리·스토리지를 NFVI 자원 풀로 제공 → 서비스별 고정 용량과 유휴 장비 축소.
3. 자동화된 수명주기 : NFV-MANO가 인스턴스 생성·확장·복구를 조정 → 운영 일관성과 서비스 민첩성 향상.
4. 서비스 체이닝 : VNF를 순서와 정책에 따라 연결 → 방화벽·부하분산·침입방지를 논리적 경로로 구성.

## Ⅲ. NFV의 구조 (흐름)

- 핵심 요약 : NFV-MANO가 서비스 요구를 VNF 배치·연결·감시로 변환하고, VIM을 통해 NFVI 자원을 할당.

```text
서비스 요구·정책
      ↓
NFV 오케스트레이터: 서비스·자원 조정
      ↓
VNF 관리자: 생성·구성·확장·복구
      ↓
VIM: 컴퓨팅·저장·네트워크 자원 할당
      ↓
NFVI: 서버·가상화·가상 네트워크
      ↓
VNF 실행·서비스 체인 구성
```

```text
VNF Descriptor·서비스 템플릿
      ↓ 배치·연결 계획
NFV-MANO ── VIM 자원 요청
      ↓
VNF 인스턴스화 → 서비스 연결 → 성능·장애 감시
```

## Ⅳ. NFV와 SDN의 비교

- 핵심 요약 : NFV는 네트워크 기능을 소프트웨어로 실행하고, SDN은 제어와 전달을 분리해 네트워크 경로를 프로그래밍.

| 비교 항목 | NFV | SDN(Software-Defined Networking) |
| --- | --- | --- |
| 분리 대상 | 네트워크 기능과 전용 장비 | 제어 평면과 데이터 전달 평면 |
| 핵심 구성 | VNF, NFVI, NFV-MANO | SDN 컨트롤러, 스위치, 제어 인터페이스 |
| 주요 효과 | 기능 배치·확장·서비스 조합의 유연성 | 경로·정책의 중앙 제어와 프로그래밍 |
| 관계 | VNF를 가상 인프라에 배치 | NFV 서비스의 가상 연결·트래픽 경로에 활용 가능 |

## Ⅴ. NFV의 한계와 방안

- 핵심 요약 : 가상화 성능·연동 복잡성·공격면 확대를 워크로드별 성능검증, 표준 인터페이스, 보안 분리로 통제.

| 위험 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 패킷 처리 지연·성능 편차 | 가상화 오버헤드와 자원 경합 | 고성능 패킷 처리, CPU 고정, 부하별 벤치마크 | 지연·처리량·손실률 |
| 공급자 종속·연동 장애 | VNF·관리도구 간 인터페이스 차이 | 개방 인터페이스와 다중 VNF 호환성 시험 | 이식성·연동시험 통과율 |
| 관리 복잡성 | VNF·인프라·서비스 체인 동시 운영 | 템플릿·정책 자동화, 구성·변경 이력 관리 | 배포 실패율·복구시간 |
| 공격면 확대 | 공용 인프라와 관리 API 집중 | 테넌트 분리, 최소권한, 이미지 서명·취약점 관리 | 격리 위반·취약점 조치율 |

## Ⅵ. NFV 도입에 대한 기술사적 제언

- 핵심 요약 : 통신사업자는 트래픽 특성에 맞는 기능부터 가상화하고, 운영·보안·장애복구까지 포함한 전환 기준을 마련.

1. 네트워크 설계자 : 상태저장·고속패킷 처리 여부를 기준으로 가상화 적합성을 분류하고 VNF 서비스 체인을 설계.
2. 플랫폼 운영자 : NFVI 용량·성능·격리 기준과 NFV-MANO 연동을 검증하고 배포·롤백 자동화를 구축.
3. 보안·운영 책임자 : 관리 API·이미지·테넌트 경계를 보호하고 장애 시 우회·복구 절차를 정기 시험.

## Ⅶ. 결론

- 핵심 요약 : NFV는 통신 기능을 소프트웨어화해 범용 인프라에서 유연하게 배치·운영하는 네트워크 구조.
- 시사점 : 전용 장비 대체 자체보다 서비스 민첩성, 성능 보장, 수명주기 자동화의 총효과를 기준으로 적용해야 함.
