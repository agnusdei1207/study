## 30초 인출

- 본질: **NFV** : 네트워크 기능을 전용 장비에서 분리해 범용 인프라의 소프트웨어로 실행하는 아키텍처
- 메커니즘: **VNF** 기능 실행, **NFVI** 인프라 자원, **NFV-MANO** 배치·확장·복구 생명주기 관리
- 통찰: 전용 하드웨어 종속 탈피로 CAPEX/OPEX 절감 및 서비스 민첩성을 제공하나 가상화 오버헤드와 MANO 오케스트레이션 복잡성이 수반되므로 DPDK 기반 패킷 가속과 표준 인터페이스 기반 E2E 연동 체계 수립이 필수적임.

<details>
<summary>핵심 용어</summary>

- **NFV(Network Functions Virtualisation)** : 네트워크 기능을 전용 하드웨어와 분리해 소프트웨어로 실행하는 아키텍처
- **VNF(Virtualised Network Function)** : 가상화된 인프라 위에서 실행되는 소프트웨어 네트워크 기능
- **NFVI(NFV Infrastructure)** : VNF 실행에 필요한 컴퓨트·저장·네트워크 자원과 가상화 계층
- **NFV-MANO(NFV Management and Orchestration)** : NFV 서비스·기능·인프라 자원의 생명주기를 관리·조정하는 체계
- **NFVO(NFV Orchestrator)** : 네트워크 서비스 구성과 필요한 자원의 조정을 담당하는 기능
- **VNFM(VNF Manager)** : VNF의 생성·변경·종료 등 생명주기를 관리하는 기능
- **VIM(Virtualised Infrastructure Manager)** : NFVI의 가상화 자원을 관리하는 기능
- **WIM(Wide Area Network Infrastructure Manager)** : 사이트 간 광역 네트워크 자원을 관리하는 기능
- **SDN(Software-Defined Networking)** : 제어 평면과 전달 평면을 분리하고 네트워크를 소프트웨어로 제어하는 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. NFV(Network Functions Virtualisation)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 전용 하드웨어 어플라이언스에 종속되던 네트워크 기능을 범용 COTS(Commercial Off-The-Shelf) 서버의 가상머신 및 컨테이너 상에 소프트웨어 인스턴스로 분리 실행하는 가상화 기술 |
| 목적 | 전용 장비 도입 비용(CAPEX) 및 상면·전력 운영비(OPEX) 절감, 네트워크 기능의 유연한 동적 프로비저닝 및 신규 서비스 타임투마켓 단축 |

## Ⅱ. NFV(Network Functions Virtualisation)의 특징

| 특징 | 상세 내용 |
|---|---|
| 하드웨어 독립성 | 상용 x86/ARM 기반 범용 서버 인프라 풀(NFVI) 상에서 가상화 계층을 통해 물리 자원을 추상화 |
| 탄력적 확장성 | 트래픽 부하 변동에 따라 가상 네트워크 기능(VNF)을 동적으로 Scale-out/Scale-in 수행 |
| 오케스트레이션 | NFV-MANO 프레임워크를 기반으로 인프라, 기능 인스턴스, E2E 서비스의 전 주기 자동화 관리 |
| 오픈 인터페이스 | ETSI 표준 참조점(Or-Vnfm, Vi-Vnfm 등)을 통해 이기종 솔루션 간 상호운용성 보장 |

## Ⅲ. NFV(Network Functions Virtualisation)의 체계·프로세스

**NFV 아키텍처 프레임워크 및 서비스 프로비저닝 흐름**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ NFV-MANO 계층 ]                               │
│  ┌──────────────────────────────────────────────────────────────────┐  │
│  │ NFVO (NFV Orchestrator) : E2E 네트워크 서비스 조정 및 글로벌 자원│  │
│  └──────────────────┬─────────────────────────────┬─────────────────┘  │
│                     │ Or-Vnfm                     │ Or-Vi              │
│  ┌──────────────────┴─────────────┐  ┌────────────┴─────────────────┐  │
│  │ VNFM (VNF Manager)             │  │ VIM (Virtualized Infra Mgr)  │  │
│  │ - VNF 수명주기(생성/변경/종료) │  │ - 컴퓨팅/스토리지/네트워크    │  │
│  └──────────────────┬─────────────┘  │   가상 자원 할당 및 풀링     │  │
│                     │                └────────────┬─────────────────┘  │
└─────────────────────┼─────────────────────────────┼────────────────────┘
                      │ Ve-Vnfm-Vnf                 │ Nf-Vi
┌─────────────────────┼─────────────────────────────┼────────────────────┐
│ [ VNF 계층 ]        │                             │                    │
│   ┌───────────────┐ │   ┌───────────────┐         │                    │
│   │  VNF 1 (vFW)  │◄┘   │  VNF 2 (vRouter)        │                    │
│   └───────┬───────┘     └───────┬───────┘         │                    │
├───────────┼─────────────────────┼─────────────────┼────────────────────┤
│ [ NFVI 계층 ]                                     │                    │
│   가상화 계층 (Hypervisor, Container Engine, DPDK/SR-IOV 가속)         │
│   ─────────────────────────────────────────────────────────────────    │
│   물리 인프라 (COTS x86 Server, COTS Switch, NVMe/SAN Storage)         │
└────────────────────────────────────────────────────────────────────────┘
```

| 구성요소 | 핵심 역할 및 기능 |
|---|---|
| **NFVO** | 서비스 카탈로그 기반 E2E 네트워크 서비스 배포, VNFM 및 VIM 간 글로벌 오케스트레이션 |
| **VNFM** | 개별 VNF 인스턴스의 인스턴스화, 구성 갱신, 스케일링, 장애 치유(Healing), 종료 라이프사이클 통제 |
| **VIM** | NFVI 물리 및 가상 자원(OpenStack, Kubernetes) 제어, 자원 풀 관리, 인프라 메트릭 수집 |
| **VNF** | 가상 방화벽, 가상 라우터, vEPC/5G Core UPF 등 순수 소프트웨어로 구동되는 네트워크 기능 |
| **NFVI** | 하드웨어(서버/스위치/스토리지)와 가상화 계층으로 구성된 통합 가상 인프라 실행 환경 |

## Ⅳ. NFV(Network Functions Virtualisation)의 종류·비교

| 비교 항목 | NFV (Network Functions Virtualisation) | SDN (Software-Defined Networking) |
|---|---|---|
| **추진 표준화** | ETSI ISG NFV | ONF (Open Networking Foundation) |
| **핵심 목적** | 네트워크 기능의 하드웨어 종속 분리 및 가상화 | 제어 평면(Control Plane)과 데이터 평면 분리 |
| **동작 위치** | 범용 서버(x86) 상의 VM 및 컨테이너 환경 | 네트워크 스위치 및 라우터 전송 계층 |
| **제어 프로토콜** | NETCONF, YANG, RESTCONF, ETSI SOL APIs | OpenFlow, P4, gNMI, BGP-LS |
| **핵심 이점** | 상면비/전력 절감, 빠른 서비스 온보딩 | 전송 경로 중앙 집중 제어, 트래픽 엔지니어링 |
| **상호 관계** | NFV 환경의 서비스 체이닝(SFC) 트래픽 경로 제어 시 SDN 컨트롤러 연계 활용 |

## Ⅴ. NFV(Network Functions Virtualisation)의 한계와 방안

| 한계 | 방안 |
|---|---|
| 가상화 계층(Hypervisor) 경유로 인한 패킷 I/O 지연 및 처리 성능 저하 | DPDK(Data Plane Development Kit), SR-IOV 커널 바이패스 적용 및 SmartNIC 오프로드 구현 |
| 대규모 멀티벤더 VNF 간 오케스트레이션 복잡도 및 장애 전파 추적 난해 | eBPF 기반 서비스 메시 관측성 체계 도입 및 분산 트레이싱(Jaeger/OpenTelemetry) 적용 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
통신사 코어망 및 엔터프라이즈 데이터센터 구축 시 기존 VM 기반 중량형 VNF에서 경량 컨테이너 기반 CNF(Cloud-native Network Function)로 아키텍처 진화 수립. 특히 패킷 프로세싱 집약적 VNF(vUPF, vFW)에는 CPU 핀닝 및 NUMA 아키텍처 정렬을 필수 적용.

### 2. 아키텍처 및 상세 메커니즘

┌────────────────────────────────────────────────────────────────────────┐
│ [ NFV 기반 서비스 기능 체이닝 (Service Function Chaining, SFC) ]       │
│                                                                        │
│ Ingress Packet ──► [ SDN Switch ]                                      │
│                           │ (NSH: Network Service Header 기반 분류)    │
│            ┌──────────────┴──────────────┐                             │
│            ▼                             ▼                             │
│   ┌─────────────────┐           ┌─────────────────┐                    │
│   │ [ SF 1: vDDoS ] │           │ [ SF 2: vFW ]   │                    │
│   │  (L3/L4 필터링) │──(Chaining)─► (L7 침입 차단)│                    │
│   └─────────────────┘           └────────┬────────┘                    │
│                                          │                             │
│                                          ▼                             │

### 3. 기술 유형 및 비교 평가
| 가상화 유형 | 실행 단위 | 부팅 속도 | I/O 가속 기술 | 적합 워크로드 |
|---|---|---|---|---|
| **VM 기반 VNF** | Hypervisor (KVM, ESXi) | 수 분 단위 | SR-IOV, PCI Passthrough | 레거시 방화벽, 대용량 트래픽 라우팅 |
| **컨테이너 기반 CNF** | OCI Container (K8s) | 수 초 단위 | DPDK, Calico eBPF, Multus CNI | 마이크로서비스형 5G 코어(AMF, SMF), 로드밸런서 |
