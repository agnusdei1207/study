## 연관 키워드

- NFV(Network Functions Virtualisation), VNF(Virtual Network Function), NFVI(NFV Infrastructure)
- NFV-MANO(Management and Orchestration), NFVO(NFV Orchestrator), VNFM(VNF Manager), VIM(Virtualised Infrastructure Manager)
- ETSI(European Telecommunications Standards Institute), COTS(Commercial Off-The-Shelf), SFC(Service Function Chaining)
- SDN(Software-Defined Networking), DPDK(Data Plane Development Kit), CNF(Cloud-native Network Function)

## Ⅰ. NFV(Network Functions Virtualisation)의 개요

- 핵심 요약 : 전용 장비에 종속된 네트워크 기능을 범용 서버 위 소프트웨어로 분리해 배포 속도와 운영 효율을 확보하는 가상화 아키텍처.
- 개념 : 라우터, 방화벽, 5G 코어 같은 네트워크 기능을 전용 하드웨어에서 분리해 범용 서버의 가상 자원 위에서 소프트웨어로 실행하는 아키텍처 (**네트워크 기능 가상화**, NFV(Network Functions Virtualisation)).
- 배경 및 필요성 : 서비스마다 전용 장비를 구매·설치하는 방식은 자본 지출과 전력·설치 공간 부담이 크고 신규 서비스 출시가 수개월 단위로 지연되는 한계가 있었음. 이를 해소하기 위해 ETSI(European Telecommunications Standards Institute)가 백서를 발간하며 표준화를 주도.
- 주요 목적 : 네트워크 기능의 신속한 배포, 하드웨어 자원의 공유를 통한 비용 절감, 벤더 종속 완화와 운영 자동화 확보.

## Ⅱ. NFV(Network Functions Virtualisation)의 특징 및 장점

- 핵심 요약 : 기능의 소프트웨어화와 자원 풀링, 생명주기 자동화가 배포 속도·자원 효율·운영 자동화의 장점으로 연결되는 구조.

1. 기능 소프트웨어화 : 네트워크 기능을 가상 네트워크 기능인 **VNF** (Virtual Network Function) 형태의 소프트웨어 인스턴스로 구현 → 장비 설치 없이 기능 추가와 업그레이드가 가능해 서비스 출시 기간 단축.
2. 범용 하드웨어 기반 : 상용 범용 제품(COTS, Commercial Off-The-Shelf) 서버 위에서 기능이 구동 → 장비 수명 주기와 무관한 운영과 도입 비용 절감.
3. 자원 풀링 : 컴퓨트, 스토리지, 네트워크 자원을 공유 풀로 묶어 기능별로 동적 배분 → 트래픽 변화에 따른 탄력적 확장과 자원 이용률 향상.
4. 생명주기 자동화 : 생성·확장·복구·종료를 오케스트레이션이 표준 절차로 수행 → 운영 인력 부담 감소와 장애 대응 속도 향상.

## Ⅲ. NFV(Network Functions Virtualisation)의 구조 (흐름)

- 핵심 요약 : 기능(VNF)·인프라(NFVI)·관리(NFV-MANO)의 세 영역이 표준 참조점으로 연결되고, 관리 영역이 전체 생명주기를 제어하는 구조.
- **NFVI** (NFV Infrastructure) : COTS 컴퓨트·스토리지와 하이퍼바이저 같은 가상화 계층을 묶은 실행 기반.
- **NFV-MANO** (Management and Orchestration) : 기능과 인프라의 전주기를 자동화하는 관리 체계이며 다음 세 요소로 구성.
  1. **NFVO** (NFV Orchestrator) : 네트워크 서비스 템플릿을 기준으로 VNF 배치와 전역 자원 할당을 조정.
  2. **VNFM** (VNF Manager) : 개별 VNF의 인스턴스화, 확장, 복구, 종료 같은 생명주기를 전담.
  3. **VIM** (Virtualised Infrastructure Manager) : NFVI의 가상 자원을 할당·제어하는 도구(OpenStack, Kubernetes 등).
- **서비스 기능 체이닝** (SFC, Service Function Chaining) : 방화벽→침입차단→주소 변환처럼 기능을 정해진 순서로 통과시키는 경로 구성 기법이며 NFVO가 VNF 간 연결로 구현.

```text
[ NFV 참조 아키텍처 ]

NFV-MANO (관리·오케스트레이션)
    ↓ 생명주기 제어
VNF 계층 (방화벽, 라우터, 5G 코어)
    ↓ 실행 기반
NFVI (가상화 계층 + COTS 자원)
```

```text
[ 네트워크 서비스 인스턴스화 흐름 ]

서비스 템플릿 등록 (NFVO)
    ↓
VNF 배치·자원 계획 수립
    ↓
VNF 인스턴스 생성 (VNFM)
    ↓
가상 자원 할당 (VIM)
    ↓
기능 체이닝으로 서비스 개시
```

## Ⅳ. NFV(Network Functions Virtualisation)의 비교

- 핵심 요약 : NFV는 네트워크 기능의 소프트웨어화, SDN은 제어와 전달의 분리, 전용 장비는 하드웨어 내장 기능이라는 초점의 차이가 있으며 앞 둘은 보완 관계임.

| 비교 축 | NFV | SDN(Software-Defined Networking) | 전용 네트워크 장비 |
| --- | --- | --- | --- |
| 초점 | 기능 자체의 소프트웨어화 | 제어 평면과 전달 평면의 분리 | 하드웨어에 내장된 기능 |
| 표준화 주체 | ETSI NFV ISG | ONF(Open Networking Foundation) | 벤더별 자체 구현 |
| 확장 방식 | 소프트웨어 인스턴스 증설 | 중앙 컨트롤러의 경로 제어 | 장비 교체·추가 설치 |
| 강점 | 배포 유연성, 비용 절감 | 경로 자동화, 정책 일관성 | 검증된 성능과 안정성 |
| 상호 관계 | SDN을 VNF 간 연결 계층으로 활용 | NFV 환경의 트래픽 경로를 동적 구성 | 가상화 대상이자 전환 출발점 |

- 선택 기준 : 기능의 신속한 도입과 자원 효율이 과제이면 NFV를, 망 전반의 경로 제어 자동화가 과제이면 SDN을 중심에 두고, 둘을 결합하면 컨트롤러가 SFC 경로를 동적으로 구성하는 통합 자동화가 가능함.

## Ⅴ. NFV(Network Functions Virtualisation)의 한계와 방안

- 핵심 요약 : 가상화 계층의 패킷 처리 성능, 멀티벤더 상호운용성, 가상 인스턴스의 가용성이 주요 한계이며 가속 기술·표준 서술자·이중화 설계로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 패킷 처리 성능 저하 | 범용 OS 커널 네트워크 스택을 거치며 컨텍스트 전환과 인터럽트가 잦아 고속 회선에서 지연·손실 발생 | 커널 우회 가속 기술 DPDK(Data Plane Development Kit), SR-IOV(Single Root I/O Virtualization) 장치 직접 할당 | 처리량, 패킷 손실률 |
| 멀티벤더 상호운용성 부족 | 벤더별 VNF 패키징과 관리 인터페이스가 달라 통합 오케스트레이션 공수 증가 | TOSCA(Topology and Orchestration Specification for Cloud Applications) 기반 표준 VNF 서술자(VNFD) 준수 | 연동 소요 시간, 표준 준수율 |
| 가상 인스턴스 장애의 동시 확산 | 한 호스트 장애가 그 위의 여러 VNF에 동시 영향 → 서비스 광역 단절 위험 | 안티 어피니티 배치, 액티브-스탠바이 상태 동기화, 텔레메트리 기반 자동 복구 | 장애 전환 시간, 세션 단절률 |

## Ⅵ. NFV(Network Functions Virtualisation)에 대한 기술사적 제언

- 핵심 요약 : 컨테이너 기반 전환, 자율 운영 체계, 네트워크 슬라이싱 연계를 통해 NFV를 상시 운영 기반으로 내재화하는 방향.

1. 통신 사업자는 가상머신 중심의 VNF를 마이크로서비스 기반의 CNF(Cloud-native Network Function)로 전환하는 로드맵을 수립해, 배포 속도와 자원 효율을 단계적으로 높이는 전환 체계를 마련해야 한다.
2. 망 운영 조직은 실시간 텔레메트리 수집과 분석을 트래픽 예측, 자원 재배치, 자동 복구로 이어지는 폐루프 자율 운영 체계로 구축하고, 기준을 AIOps(Artificial Intelligence for IT Operations) 거버넌스로 명문화해야 한다.
3. 서비스 설계 조직은 5G 네트워크 슬라이싱 도입 시 서비스 유형별 SLA(Service Level Agreement)를 슬라이스별 VNF 체이닝 정책과 연계해 보장하고, 검증 절차를 표준 설계 문서로 정례화해야 한다.

## Ⅶ. 결론

- 핵심 요약 : NFV는 네트워크 기능을 소프트웨어로 분리해 자원 공유와 자동 운영을 가능하게 하는 가상화 아키텍처임.
- 시사점 : 성능 가속과 표준 준수라는 실무 과제를 함께 풀어야 클라우드 네이티브 시대의 통신 인프라 경쟁력이 유지됨.
