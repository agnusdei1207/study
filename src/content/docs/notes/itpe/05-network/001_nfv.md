## 큰 그림과 30초 인출

```text
[OSS/BSS · 서비스 요구]
            │
            ▼
┌──────────── NFV-MANO ────────────┐
│ NFVO ─ 서비스·자원 오케스트레이션 │
│  ├─ VNFM ─ VNF 생명주기 관리      │
│  └─ VIM  ─ 가상 자원 관리         │
└──────────────┬───────────────────┘
               ▼
       [VNF/CNF: FW·Router·5GC]
               ▼
 [NFVI: Compute · Storage · Network]
```

- 본질: 전용 네트워크 장비의 기능을 소프트웨어로 분리하여 범용 인프라에서 배치·확장·복구하는 구조
- 구조: `NFVI - VNF/CNF - MANO`, 관리 주체는 `NFVO - VNFM - VIM`
- 동작: `서비스 요청 → descriptor 해석 → 자원 할당 → 기능 생성·연결 → 감시·확장·복구`
- 구분: NFV는 **기능 가상화**, SDN은 **제어·전달 평면 분리와 경로 프로그래밍**

## 예상문제

> NFV의 개념과 아키텍처, NFV-MANO의 구성과 동작을 설명하고, SDN과의 차이 및 클라우드 네이티브 전환 시 고려사항을 논하시오. (25점)

## Ⅰ. 장비 종속 기능을 소프트웨어화하는 NFV 개요

- 정의: **NFV(Network Functions Virtualisation)**는 방화벽·라우터·코어망 같은 네트워크 기능을 전용 장비에서 분리하여 가상화된 컴퓨팅·저장·네트워크 자원 위의 소프트웨어 기능으로 실행하는 구조
- 목적: 기능과 하드웨어의 결합을 낮추고, 서비스 요구에 따라 네트워크 기능을 신속히 배치·확장·복구
- 필요성: 전용 장비 중심 구조는 기능 추가마다 장비 도입·연결·검증이 필요하여 서비스 변경 속도와 자원 탄력성을 제한

#### 한줄 요약

- NFV는 네트워크 기능의 실행 위치와 규모를 소프트웨어 생명주기로 제어하게 하는 기술임

## Ⅱ. 소프트웨어화·탄력성·자동화를 결합하는 NFV 특징

| 특징 | 구현 수단 | 기대효과 | 전제 조건 |
|---|---|---|---|
| **기능·장비 분리** | VNF/CNF와 표준화된 NFVI | 장비 종속성 완화 | 이식성·상호운용성 검증 |
| **자원 추상화** | VIM·가상 컴퓨팅/저장/네트워크 | 자원 공유와 탄력 할당 | NUMA·NIC·가속기 인지 |
| **생명주기 자동화** | NFVO·VNFM·descriptor·정책 | 배치·확장·복구 자동화 | 상태·정책·패키지 일관성 |
| **서비스 체이닝** | Network Service와 연결 그래프 | 기능 조합의 신속한 변경 | 경로·순서·대칭성 보장 |
| **클라우드 네이티브 진화** | microservice·container·declarative 운영 | 회복성·배포 속도 향상 | 관측성·상태 관리·보안 |

#### 한줄 요약

- NFV의 가치는 VM 사용 자체가 아니라 기능·자원·생명주기를 분리해 자동화하는 데 있음

## Ⅲ. NFVI·VNF/CNF·MANO로 구성되는 NFV 아키텍처

```text
                         [OSS/BSS]
                             │ Os-Ma-nfvo
                  ┌──────────▼──────────┐
                  │ NFVO                │
                  │ NS 조합·전역 자원조정│
                  └──────┬───────┬──────┘
                    Or-Vnfm      Or-Vi
              ┌──────────▼─┐   ┌─▼──────────┐
 [EM] ───────▶│ VNFM       │   │ VIM        │
              │ VNF LCM    │   │ 자원 제어   │
              └──────┬─────┘   └────┬───────┘
                     │              │ Nf-Vi
              ┌──────▼─────┐   ┌────▼────────────────┐
              │ VNF / CNF  │   │ NFVI                │
              │ FW·UPF·DPI │   │ Compute·Storage·NW  │
              └────────────┘   └─────────────────────┘
```

선의 의미: 서비스 의도가 MANO의 생명주기·자원 명령으로 변환되고, VNF/CNF와 NFVI의 실제 상태가 다시 관리 계층으로 피드백되는 폐루프

| 구성 | 책임 | 대표 객체·산출물 |
|---|---|---|
| **NFVI** | 물리·가상 컴퓨팅, 저장, 네트워크 자원 제공 | VM·container cluster·virtual link |
| **VNF/CNF** | 네트워크 기능 실행 | VNF instance·CNF workload |
| **NFVO** | Network Service 생명주기와 다중 자원 조정 | NS descriptor·서비스 그래프 |
| **VNFM** | VNF 생성·설정·확장·복구·종료 | VNF descriptor·LCM operation |
| **VIM** | NFVI 자원 발견·할당·회수 | resource inventory·allocation |
| **WIM/CISM** | WAN 연결 또는 container infrastructure 관리 | WAN connectivity·CIS cluster |

#### 한줄 요약

- NFVO는 서비스를, VNFM은 기능을, VIM은 인프라 자원을 각각 관리하며 descriptor가 세 계층을 연결함

## Ⅳ. 요청에서 종료까지 이어지는 NFV-MANO 동작

```text
① 서비스 요청·정책 입력
          ↓
② NFVO: NS/VNF descriptor 해석, 배치·연결 계획
          ↓
③ VIM/WIM/CISM: 계산·저장·망·컨테이너 자원 확보
          ↓
④ VNFM: VNF/CNF 생성·설정, 서비스 체인 연결
          ↓
⑤ 상태·성능 감시 ── 임계/장애 ──▶ 확장·치유·재배치
          ↓
⑥ 서비스 종료, 자원 회수, 이력·정책 갱신
```

| 단계 | 제어 포인트 | 검증 항목 |
|---|---|---|
| **설계·온보딩** | package·descriptor·image 등록 | 서명, 호환성, 자원 요구량 |
| **배치** | 위치·가속기·affinity 정책 | 지연, 장애영역, 가용 자원 |
| **연결** | virtual link·WAN·service chain | 순서, 대칭 경로, 격리 |
| **운영** | scale·heal·upgrade | KPI, 상태 일관성, 롤백 |
| **종료** | instance·resource 해제 | 잔존 자원, 로그, 비용 정산 |

#### 한줄 요약

- MANO는 descriptor와 정책을 실제 자원·기능·연결 상태로 변환하고 감시 결과로 지속 보정함

## Ⅴ. 기능 가상화와 경로 제어를 구분하는 NFV·SDN 비교

| 구분 | NFV | SDN | 결합 시 역할 |
|---|---|---|---|
| **핵심 대상** | 네트워크 기능 | 네트워크 제어와 전달 | 기능과 경로의 동시 자동화 |
| **분리 축** | 기능 SW와 전용 HW | Control Plane과 Data Plane | 서비스 의도와 실행 인프라 분리 |
| **핵심 구조** | NFVI·VNF/CNF·MANO | Application·Controller·Data Plane | MANO-Controller 연계 |
| **제어 단위** | 기능 instance·Network Service | flow·route·policy | 서비스 체인별 경로 설정 |
| **주요 표준 축** | ETSI NFV | IETF·ONF·표준 southbound API | 다중 벤더 상호운용 |
| **독립성** | SDN 없이도 기능 가상화 가능 | NFV 없이도 중앙 정책 제어 가능 | 상호 보완 관계 |

#### 한줄 요약

- NFV가 어디서 어떤 기능을 실행할지 정하면 SDN은 그 기능을 통과하는 패킷 경로를 프로그래밍함

## Ⅵ. 성능·가용성·상호운용성을 확보하는 실무 고려사항

| 문제 | 원인 | 대책 | 검증 효과 |
|---|---|---|---|
| **데이터 평면 성능 저하** | 가상 스위치·커널·메모리 복사 경로 증가 | DPDK, SR-IOV, NUMA/CPU pinning을 부하 특성별 적용 | 처리량뿐 아니라 p95/p99 지연·손실 확인 |
| **MANO 장애의 영향 확대** | 중앙 관리 기능과 상태 저장소 집중 | 기능 이중화, 장애영역 분산, 상태 백업·복구 훈련 | 제어 장애 시 서비스 지속성 확인 |
| **다중 벤더 연동 실패** | descriptor·API·생명주기 해석 차이 | 표준 인터페이스, onboarding 적합성 시험, 버전 고정 | 패키지·LCM 상호운용성 확보 |
| **VNF→CNF 전환 실패** | 상태 저장형 기능을 무상태 microservice로 단순 변환 | 상태 외부화, readiness/liveness, 단계적 병행 전환 | 확장·치유·롤백 가능성 확보 |
| **공급망·격리 위험** | image·package 위변조, 공유 인프라의 tenant 간 영향 | 서명·SBOM·취약점 점검, 네트워크/자원 격리 | 배포 무결성과 영향 범위 통제 |

#### 한줄 요약

- NFV 운영은 평균 처리량이 아니라 꼬리 지연·장애영역·상태 복구·패키지 신뢰를 함께 검증해야 함

## Ⅶ. 서비스 품질 기반 폐루프 운영으로 완성하는 NFV 결론

- **[descriptor-telemetry-policy 추적성 확보]**: 배치 자동화만 도입하면 잘못된 정책과 자원 추정도 빠르게 확산하므로 서비스 요구, descriptor, 배치 결과, 실측 KPI를 하나의 추적 체계로 관리
- 나라면: 신규 기능을 작은 트래픽 구간에 배포하고 `지연·손실·가용성·복구시간·자원사용률`을 관찰한 뒤, SLO 충족 시 단계 확장하고 미충족 시 자동 롤백

#### 한줄 요약

- NFV의 완성 기준은 기능의 가상화가 아니라 서비스 품질을 측정해 배치·확장·복구 정책을 지속 보정하는 상태임

## 1교시 10점 답안 발췌

### 1. 정의

- NFV는 네트워크 기능을 전용 장비에서 분리하여 범용 NFVI 위의 VNF/CNF로 실행하고 MANO로 생명주기를 자동화하는 구조

### 2. 아키텍처

```text
OSS/BSS → NFVO → VNFM → VNF/CNF
             └→ VIM  → NFVI
```

| 구성 | 역할 |
|---|---|
| NFVI | 계산·저장·네트워크 자원 |
| VNF/CNF | 소프트웨어 네트워크 기능 |
| NFVO/VNFM/VIM | 서비스·기능·자원 생명주기 관리 |

### 3. 차별화 제언

- NFV는 기능, SDN은 경로를 소프트웨어로 제어하며 결합 시 서비스 체인 자동화
- 평균 처리량 외 p99 지연·손실·복구시간으로 품질을 검증하고 정책 기반 scale/heal/rollback 폐루프 구성
