## Ⅰ. IGP(Interior Gateway Protocol)의 개요

- **개념** : 동일한 관리 주체에 의해 운영되는 단일 자율 시스템(AS: Autonomous System) 내부에서 라우터 간에 최적의 라우팅 경로를 학습하고 패킷을 포워딩하기 위해 사용되는 내부 게이트웨이 라우팅 프로토콜.
- **배경 및 필요성** : 기업, 대학, 통신사 백본 내부의 네트워크 규모 확대에 따라 정적 라우팅(Static Routing) 구성의 한계를 해소하고, 링크 장애 발생 시 자동으로 우회 경로를 계산하는 동적 라우팅 필수화.
- **핵심 목적** : AS 내부 토폴로지 변경 시 신속한 경로 수렴(Convergence), 라우팅 루프 방지, 최적 대역폭 활용 및 네트워크 자원 관리 자동화.

## Ⅱ. IGP의 핵심 알고리즘별 분류 및 동작 메커니즘

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ IGP 프로토콜 2대 분류 체계 ]                  │
│                                                                        │
│   [ 거리 벡터 (Distance Vector) ]       [ 링크 상태 (Link State) ]     │
│   알고리즘: Bellman-Ford                알고리즘: Dijkstra SPF         │
│   대표: RIP v1/v2                       대표: OSPF, IS-IS              │
│                                                                        │
│   ┌──────────────┐                      ┌──────────────┐               │
│   │ Neighbor-    │ 이웃에게 라우팅      │ Full Topology│ 전체 지도 공유 │
│   │ Based View   │ 테이블 통째로 복사   │ Database     │ 각자 최단 경로 │
│   └──────┬───────┘ (By Rumor)           └──────┬───────┘ 독립 계산     │
│          ▼                                     ▼                       │
│     수렴 속도 느림                       수렴 속도 즉각적 (초 단위)    │
│     홉 수(Hop) 기준 (최대 15)            비용(Cost: 대역폭 반비례)     │
│     소규모 네트워크용                    대규모 엔터프라이즈/백본용    │
└────────────────────────────────────────────────────────────────────────┘
```

- **거리 벡터 (Distance Vector)** : 목적지까지의 방향(Vector)과 거리(Distance: 홉 수) 정보만을 인접 라우터와 주기적으로 교환하며 벨만-포드(Bellman-Ford) 알고리즘으로 최단 경로 갱신.
- **링크 상태 (Link State)** : 각 라우터가 자신과 직접 연결된 인터페이스 상태(LSA: Link State Advertisement)를 AS 전체에 플러딩하여 동일한 LSDB를 구축한 후, 다익스트라(Dijkstra) SPF 알고리즘으로 루프 없는 최단 경로 트리 구성.
- **하이브리드 / 고급 거리 벡터 (EIGRP)** : 시스코 독자(후에 공개) 규격으로 DUAL 알고리즘을 채택하여 백업 경로(Feasible Successor)를 사전 계산해 준실시간 수렴 달성.

## Ⅲ. IGP 주요 프로토콜의 세부 비교 분석

| 비교 항목 | RIPv2 | OSPFv2 / OSPFv3 | IS-IS | EIGRP |
|---|---|---|---|---|
| **알고리즘** | Bellman-Ford | Dijkstra SPF | Dijkstra SPF | DUAL |
| **라우팅 메트릭** | 홉 카운트 (최대 15) | Cost ($10^8/\text{대역폭}$) | Cost (임의 설정 가능) | 대역폭 + 지연시간 (복합) |
| **계층 구조** | 단일 평면 (Flat) | Area 기반 (Backbone Area 0) | Level 1, Level 2 Area | 단일 평면 / 자율 시스템 |
| **수렴 속도** | 매우 느림 (수십 초~수 분) | 빠름 (수 초 이내) | 매우 빠름 (ISP 백본 최적) | 즉각적 (Sub-second) |
| **자원 소모 (CPU/메모리)**| 매우 낮음 | 높음 (SPF 트리 계산) | 높음 (SPF 계산) | 중간 |
| **전송 계층 프로토콜**| UDP 520 | IP 직접 (프로토콜 89) | L2 데이터링크 계층 직접 | IP 직접 (프로토콜 88) |
| **VLSM/CIDR** | 지원 | 지원 | 지원 | 지원 |

- **계층적 Area 분할 (OSPF)** : 백본 Area 0을 중심으로 일반 Area를 스타형으로 연결하여 LSA 플러딩 범위를 제한함으로써 라우터 메모리 및 CPU 보존.
- **DUAL 유한 상태 머신 (EIGRP)** : Feasible Condition($\text{RD} < \text{FD}$)을 만족하는 사전 대체 경로를 유지하여 링크 단절 시 재계산 없이 밀리초 단위 즉시 절체.

## Ⅳ. IGP의 주요 한계점 및 해결 방안

- **대규모 망에서 SPF 연산 부하 및 플래핑에 따른 CPU 폭주** :
  - **한계점** : 단일 링크가 반복적으로 업/다운(Flapping)될 때마다 전체 라우터가 LSA 플러딩 및 SPF 재계산을 수행하여 라우터 CPU 과부하 및 패킷 드롭 유발.
  - **해결 방안** : SPF 지연 타이머(SPF Throttle Timer) 튜닝, Area 분할 세분화 및 ABR에서의 서브넷 경로 요약(Summarization) 강제.
- **거리 벡터 프로토콜의 무한 계수(Count-to-Infinity) 및 라우팅 루프** :
  - **한계점** : 단절된 네트워크 정보가 인접 라우터 간에 왜곡 전파되어 메트릭이 16까지 순차 증가하는 동안 라우팅 루프 발생.
  - **해결 방안** : Split Horizon(수평 분할), Poison Reverse(독성 역전), Triggered Update(즉각 갱신), Holddown Timer 복합 적용.

## Ⅴ. IGP 적용 및 발전을 위한 기술사적 제언

- **백본 망에서의 OSPF vs IS-IS 전략적 선정** : 순수 엔터프라이즈 환경은 성숙된 OSPF를 우선하되, 통신사 및 대규모 데이터센터 백본은 L2 기반 동작으로 IP 스택 장애에 독립적인 IS-IS를 적극 검토.
- **세그먼트 라우팅(SR-MPLS / SRv6)과의 연동** : 기존 LDP, RSVP-TE 등 복잡한 시그널링을 배제하고, OSPF/IS-IS 확장 TLV를 활용해 경로 라벨(SID)을 분배하는 Segment Routing으로 진화 필수.
- **BFD(Bidirectional Forwarding Detection) 연동 표준화** : IGP 고유의 수 초 단위 헬로 주기를 극복하기 위해 하드웨어 기반 30ms급 BFD를 연동하여 링크 장애 감지 즉시 서브세컨드 우회 보장.
