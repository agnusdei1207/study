## 연관 키워드

- IGP(Interior Gateway Protocol), 자율 시스템(AS), 거리 벡터(Distance Vector), 링크 상태(Link State)
- Bellman-Ford, Dijkstra SPF, RIP, OSPF, IS-IS, EIGRP, DUAL
- 수렴(Convergence), Area 0, 무한 계수(Count-to-Infinity), 수평 분할(Split Horizon)
- 세그먼트 라우팅(SR), BFD(Bidirectional Forwarding Detection), 플래핑(Flapping)

## Ⅰ. IGP(Interior Gateway Protocol)의 개요

- 핵심 요약 : 하나의 관리 주체가 운영하는 **자율 시스템** (AS, Autonomous System) 내부에서 최적 경로를 자동으로 학습하는 내부 게이트웨이 라우팅 프로토콜.
- 개념 : 같은 관리 주체의 AS 내부 라우터끼리 경로를 학습하고 패킷을 전달하는 데 쓰이는 내부 게이트웨이 라우팅 프로토콜(IGP, Interior Gateway Protocol).
- 배경 및 필요성 : 기업, 대학, 통신사 백본의 규모가 커지면서 정적 라우팅(Static Routing)의 수작업 구성이 한계에 이르렀고, 링크 장애 시 우회 경로를 자동으로 계산할 동적 라우팅이 필수가 됨.
- 주요 목적 :
  1. 토폴로지 변경 시 빠른 경로 수렴(Convergence)
  2. 라우팅 루프 방지
  3. 대역폭을 고려한 최적 경로 선택과 네트워크 자원 관리 자동화

## Ⅱ. IGP의 특징 및 장점

- 핵심 요약 : 경로 정보를 전달하는 방식에 따라 거리 벡터와 링크 상태로 나뉘며, 각 방식이 수렴 속도와 자원 소모의 상충 관계를 가짐.

1. **거리 벡터** (Distance Vector) : 인접 라우터와 라우팅 테이블을 주기적으로 교환하며 Bellman-Ford 알고리즘으로 경로를 갱신하며, 대표 프로토콜은 RIP(Routing Information Protocol) → 구성이 단순하고 자원 소모가 낮음.
2. **링크 상태** (Link State) : 라우터가 자신의 인터페이스 상태를 AS 전체에 알리고, 모든 라우터가 같은 토폴로지 데이터베이스를 바탕으로 Dijkstra SPF(Shortest Path First) 알고리즘을 실행하며, 대표 프로토콜은 OSPF와 IS-IS(Intermediate System to Intermediate System) → 변경 시 빠른 수렴과 루프 없는 경로 확보.
3. **하이브리드 방식** (EIGRP, Enhanced Interior Gateway Routing Protocol) : 거리 벡터 계열이지만 DUAL(Diffusing Update Algorithm)로 백업 경로를 미리 계산 → 장애 시 재계산 없이 즉시 절체.

## Ⅲ. IGP의 구조 (흐름)

- 핵심 요약 : 거리 벡터는 이웃의 정보를 중계받고, 링크 상태는 전체 지도를 공유해 각자 계산하는 방식의 차이.

```text
[ IGP 2대 분류 ]

거리 벡터 (RIP)
이웃에게 표 복사 (By Rumor)
          ↓
수렴 느림 (수십 초 이상)

링크 상태 (OSPF, IS-IS)
전체 토폴로지 공유, 각자 SPF 계산
          ↓
수렴 빠름 (수 초 이내)
```

- Area 구조 (OSPF, Open Shortest Path First) : 백본 Area 0을 중심으로 일반 Area를 연결하여 LSA(Link State Advertisement) 플러딩 범위를 제한함.

```text
[ OSPF Area 구조 ]

Area 1 ─→ Area 0 (백본) ←─ Area 2
(일반 Area끼리는 직접 연결하지 않음)
```

## Ⅳ. IGP 주요 프로토콜의 비교

- 핵심 요약 : 소규모 망은 거리 벡터 계열로 충분하지만, 대규모 백본에서는 링크 상태나 DUAL 계열이 수렴과 확장성에서 유리.

| 비교 항목 | RIPv2 | OSPFv2 / OSPFv3 | IS-IS | EIGRP |
| --- | --- | --- | --- | --- |
| 알고리즘 | Bellman-Ford | Dijkstra SPF | Dijkstra SPF | DUAL |
| 메트릭 | 홉 수 (최대 15홉) | 비용 (기준 대역폭 ÷ 대역폭) | 설정 가능한 비용 | 대역폭과 지연의 복합 값 |
| 계층 구조 | 단일 평면 | Area 기반 (백본 Area 0) | Level 1 / Level 2 | 단일 평면 또는 AS 구성 |
| 수렴 속도 | 느림 (수십 초 이상) | 빠름 (수 초 이내) | 빠름 (통신사 백본에 적합) | 빠름 (백업 경로 사용) |
| 자원 소모 | 낮음 | 높음 (SPF 계산) | 높음 (SPF 계산) | 중간 |
| 전송 방식 | UDP 520 | IP 직접 탑재 (프로토콜 89) | 데이터링크 계층 직접 | IP 직접 탑재 (프로토콜 88) |

- 선택 기준 : 소규모 사이트는 RIPv2 또는 EIGRP로 충분하며, 대규모 엔터프라이즈는 OSPF, 통신사 백본은 IS-IS를 우선 검토.

## Ⅴ. IGP의 한계와 방안

- 핵심 요약 : 플래핑에 따른 SPF 부하, 거리 벡터의 루프, 장애 감지 지연이 핵심 한계이며, 타이머 조정과 루프 방지 기법, BFD로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| SPF 계산 부하와 플래핑 | 링크가 반복적으로 오르내리면 LSA 플러딩과 SPF 재계산이 반복되어 CPU 과부하 | SPF 지연 타이머 조정, Area 분할 세분화, 영역 경계 라우터(ABR, Area Border Router)에서 경로 요약 | CPU 사용률, SPF 실행 횟수 |
| 무한 계수와 라우팅 루프 | 단절 정보가 왜곡 전파되어 메트릭이 최대값까지 증가하는 동안 루프 발생 | 수평 분할(Split Horizon), 독성 역전(Poison Reverse), 즉시 갱신(Triggered Update), 보류 타이머(Holddown Timer) 복합 적용 | 루프 탐지 건수 |
| 장애 감지 지연 | 라우팅 프로토콜의 헬로 주기가 길어 장애 인지가 늦음 | BFD(Bidirectional Forwarding Detection) 연동으로 밀리초 단위 장애 감지 | 장애 감지 시간 |

## Ⅵ. IGP에 대한 기술사적 제언

- 핵심 요약 : 백본 프로토콜 선택과 라벨 기반 시그널링의 단순화를 통해 IGP를 운영 부담이 낮은 구조로 발전시키는 방향.

1. 백본 프로토콜 선정 : 순수 엔터프라이즈 환경은 운영 경험이 많은 OSPF를 우선하고, 통신사와 대규모 데이터센터 백본은 IP 스택 장애와 독립적으로 동작하는 IS-IS를 적극 검토할 필요가 있음.
2. 세그먼트 라우팅(SR, Segment Routing) 전환 : LDP(Label Distribution Protocol)나 RSVP-TE(Resource Reservation Protocol-Traffic Engineering) 같은 복잡한 시그널링을 줄이고, OSPF와 IS-IS의 확장 정보로 경로 식별자를 배포하는 방식으로 옮겨 가는 계획을 세워야 함.

## Ⅶ. 결론

- 핵심 요약 : IGP는 내부 망의 경로를 자동으로 찾고 장애에 대응하는 라우팅의 기반 계층.
- 시사점 : 수렴 속도와 자원 소모의 상충 관계를 이해하고 규모에 맞는 프로토콜을 고르는 것이 안정적인 내부 망 운영의 출발점이 됨.
