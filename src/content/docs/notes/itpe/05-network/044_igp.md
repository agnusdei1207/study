## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 라우팅 프로토콜 → 자율 시스템 내부 경로 교환

## 30초 인출

- 본질: **IGP (Interior Gateway Protocol)** 는 하나의 자율 시스템 내부에서 라우팅 정보를 교환하고 경로를 계산하는 프로토콜 범주
- 메커니즘: 라우터 간 토폴로지·거리 정보 교환 → 프로토콜별 메트릭 계산 → 목적지 경로 설치
- 통찰: 단일 기업이나 기관이 관리하는 독립된 단일 자율시스템(AS) 내부에서 라우터 간 최단 경로를 신속하게 계산하고 수렴하기 위해 거리 벡터 또는 링크 상태 알고리즘을 사용하는 내부 게이트웨이 프로토콜임.

<details>
<summary>핵심 용어</summary>

- **IGP (Interior Gateway Protocol)** : 하나의 자율 시스템 안에서 라우팅 정보를 교환하는 프로토콜 범주.
- **AS (Autonomous System)** : 공통 라우팅 정책 아래 운영되는 네트워크 집합.
- **거리벡터 (Distance Vector)** : 이웃에게 목적지까지의 거리 정보를 주고받아 경로를 계산하는 라우팅 방식.
- **링크 상태 (Link State)** : 링크 상태 정보를 배포해 토폴로지 데이터베이스를 만들고 경로를 계산하는 방식.
- **SPF (Shortest Path First)** : 링크 상태 데이터베이스에 최단 경로 우선 계산을 적용하는 알고리즘 계열.
- **RIP (Routing Information Protocol)** : 홉 수를 메트릭으로 사용하는 거리벡터 IGP.
- **OSPF (Open Shortest Path First)** : 링크 상태 기반 IGP. 영역과 링크 상태 정보를 이용해 경로 계산.
- **IS-IS (Intermediate System to Intermediate System)** : 링크 상태 기반 내부 라우팅 프로토콜.
- **BFD (Bidirectional Forwarding Detection)** : 전달 경로의 장애를 빠르게 감지하기 위한 프로토콜.

## 2~4교시 25점 답안

## Ⅰ. IGP(Interior Gateway Protocol)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 단일 자율시스템(AS, Autonomous System) 내부의 라우터들이 상호 간에 네트워크 토폴로지 및 라우팅 경로 정보를 교환하기 위해 사용하는 내부 라우팅 프로토콜 |
| 목적 | 조직 내부 IP 네트워크의 최적 패킷 전송 경로 배정, 링크 장애 시 초고속 수렴(Fast Convergence) 및 라우터 자원의 효율적 배분 |

## Ⅱ. IGP(Interior Gateway Protocol)의 특징

| 특징 | 상세 내용 |
|---|---|
| 단일 관리 도메인 | 단일 기업, 금융사, ISP 내부 전산망 등 일관된 관리 정책이 적용되는 동일 AS 영역 내에서만 동작 |
| 신속한 수렴성 | 외부 EGP와 달리 복잡한 정책 검증 없이 알고리즘에 기반하여 변경된 토폴로지를 초/밀리초 단위로 수렴 |
| 세부 링크 메트릭 반영 | 단순 도달 가능성을 넘어 대역폭, 지연시간, 인터페이스 Cost 등 물리적 선로 특성을 경로 계산에 반영 |
| 2대 알고리즘 분류 | 분산 벨만-포드에 기반한 거리 벡터 방식과 전역 다익스트라에 기반한 링크 상태 방식으로 양분 |

## Ⅲ. IGP(Interior Gateway Protocol)의 체계·프로세스

**IGP 2대 알고리즘(거리 벡터 vs 링크 상태) 동작 메커니즘 비교**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ IGP 2대 알고리즘 비교 ]                       │
│                                                                        │
│   [ 1. 거리 벡터 (Distance Vector) ]                                   │
│   "이웃 라우터의 소문(Rumor)에 의한 라우팅"                            │
│   Router A ──► (자신의 라우팅 테이블 전체 복사) ──► Router B           │
│   - 네트워크 전체 지도를 모름                                          │
│   - 이웃이 알려준 '어느 방향(Vector)으로 몇 홉(Distance)'만 믿고 기록  │
│                                                                        │
│   [ 2. 링크 상태 (Link State) ]                                        │
│   "전체 토폴로지 지도(LSDB)를 직접 보고 계산하는 라우팅"               │
│   Router A ──► (자체 인터페이스 연결 상태 LSA 플러딩) ──► 전 라우터    │
│   - 모든 라우터가 동일한 전역 토폴로지 데이터베이스(LSDB) 구축         │
│   - 다익스트라(Dijkstra) SPF 알고리즘으로 자신을 루트로 최단 경로 도출 │
└────────────────────────────────────────────────────────────────────────┘
```

| 비교 항목 | 거리 벡터 (Distance Vector) | 링크 상태 (Link State) |
|---|---|---|
| **동작 알고리즘** | Bellman-Ford 알고리즘 | Dijkstra SPF 알고리즘 |
| **교환 정보 내용** | 자신의 전체 라우팅 테이블 내용 | 자신의 인접 링크 연결 상태(LSA/LSP) |
| **정보 전송 대상** | 인접한 이웃(Neighbor) 라우터에게만 | 네트워크(Area) 내의 모든 라우터에게 플러딩 |
| **전체 토폴로지 인지**| 인지 불가 (이웃이 준 경로만 인지) | **완벽 인지 (모든 라우터가 동일 지도 보유)**|
| **메모리/CPU 부하** | 낮음 (단순 덧셈 연산) | 높음 (SPF 트리 연산 메모리 집약) |
| **수렴 속도** | 느림 (주기적 전파에 의존) | **매우 빠름 (변경 시 즉시 플러딩)** |
| **대표 프로토콜** | RIP v1/v2 | **OSPF, IS-IS** |

## Ⅳ. IGP(Interior Gateway Protocol)의 종류·비교

| 대표 프로토콜 | RIP v2 | EIGRP (고급 거리벡터) | OSPF v2/v3 | IS-IS |
|---|---|---|---|---|
| **알고리즘** | Bellman-Ford | DUAL (Diffusing Update) | Dijkstra SPF | Dijkstra SPF |
| **메트릭** | 홉 수 (최대 15) | 대역폭 + 지연 (복합) | 비용 (10^8 / Bandwidth) | 링크 비용 (Default Metric) |
| **계층 구조** | 단일 평면 | 단일 / 요약 | 계층적 (Backbone Area 0) | 계층적 (Level 1 / Level 2)|
| **수렴 속도** | 매우 느림 | 매우 빠름 (백업 Feasible)| 매우 빠름 | 매우 빠름 |
| **표준화** | IETF 표준 | Cisco 독점 -> RFC 7868 | IETF 개방형 표준 | ISO / IETF 표준 |
| **주 적용 환경** | 소규모 SOHO 지사 | 대형 엔터프라이즈 사내망 | 대규모 엔터프라이즈/IDC | 대형 통신사 IP 백본망 |

## Ⅴ. IGP(Interior Gateway Protocol)의 한계와 방안

| 한계 | 방안 |
|---|---|
| 대규모 링크 상태(OSPF) 망에서 잦은 인터페이스 플래핑(Flapping) 발생 시 전 전산망 라우터의 SPF 재연산 폭증으로 CPU 마비 | 계층적 Area 분할로 LSA 전파 범위를 격리하고, SPF 연산 지연 타이머(SPF Throttle Timer)를 점증(Exponential) 설정 |
| 이종 IGP 간 상호 경로 재분배(Redistribution) 구성 시 라우팅 루프 및 준최적 경로(Suboptimal Routing) 선택 발생 | 라우트 태그(Route Tag) 및 프리픽스 필터링을 통해 원천 도메인 재유입을 차단하고 메트릭을 명시적 정규화 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
엔터프라이즈 백본 코어 프로토콜 선정 시, 벤더 종속(Lock-in)을 방지하기 위해 개방형 표준인 OSPF를 기본 채택하고, Area 0(백본)과 지사 Area 간 경계 라우터(ABR)에서 반드시 `area range` 경로 요약을 적용하여 라우팅 테이블 파편화를 사전 예방.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 이종 IGP 상호 재분배 시 라우팅 태그(Route Tag) 기반 루프 방지 ]     │
│                                                                        │
│   [ OSPF 도메인 ]                                   [ EIGRP 도메인 ]   │
│         │                                                 │            │
│         ▼                                                 ▼            │
│   ┌─────────────┐   재분배 시 Tag=100 부여          ┌─────────────┐    │
│   │ [ 라우터 1 ] ├─────────────────────────────────►│ [ 라우터 2 ] │    │
│   └─────────────┘                                   └──────┬──────┘    │
│          ▲                                                 │           │
│          │ Tag=100 확인 시 재유입 차단 (Filter Out)        │           │
│          └─────────────────────────────────────────────────┘           │
│   (도메인 간 상호 재분배 시 경로가 핑퐁 순환하는 루프 원천 차단 성공)  │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 망 규모 및 특성 | 권장 IGP | 선정 근거 |
|---|---|---|
| **소규모 지사 (라우터 10대 미만)** | RIPv2 또는 정적 라우팅 | 관리 설정이 극히 단순하고 장비 메모리 부담 제로 |
| **대규모 멀티캠퍼스 (수백 대)** | OSPF | 계층적 Area 분할 및 멀티벤더 이종 장비 완벽 호환 |
| **초대형 통신사 코어망 (수천 대)** | IS-IS | IP 외 다중 프로토콜 지원, OSPF보다 대규모 토폴로지 확장성 우수 |
