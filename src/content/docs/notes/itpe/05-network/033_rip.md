지식 위치: 네트워크 → 내부 게이트웨이 라우팅 → **RIP**

## 30초 인출

- 본질: **RIP(Routing Information Protocol)** : 거리 벡터 알고리즘으로 목적지까지의 홉 메트릭을 교환하는 내부 게이트웨이 라우팅 프로토콜
- 메커니즘: 이웃 라우터의 경로·메트릭 수신 → 수신 링크 비용을 더해 경로 선택 → 주기·변경 기반 갱신
- 통찰: 벨만-포드 거리 벡터 알고리즘을 채택하여 단순 홉 수(Hop Count)만으로 최적 경로를 판단하는 소규모 자율시스템(AS) 내부 라우팅 프로토콜로, 라우팅 루프 방지를 위해 스플릿 호라이즌과 포이즌 리버스를 결합 운영 체계 구축.

<details>
<summary>핵심 용어</summary>

- **RIP(Routing Information Protocol)** : 홉 메트릭 기반 거리 벡터 내부 게이트웨이 프로토콜
- **거리 벡터(Distance Vector)** : 목적지까지의 거리·다음 홉을 이웃과 교환하는 라우팅 방식
- **홉 카운트(Hop Count)** : RIP가 경로 선택에 쓰는 라우터 홉 단위 메트릭
- **무한대(Infinity)** : RIP에서 16으로 표현하는 도달 불가 메트릭
- **스플릿 호라이즌(Split Horizon)** : 경로를 학습한 인터페이스로 같은 경로 정보를 다시 알리지 않는 루프 완화 기법
- **포이즌 리버스(Poison Reverse)** : 학습한 인터페이스로 경로를 광고하되 도달 불가 메트릭으로 알리는 기법
- **RIPv1(RIP Version 1)** : 서브넷 마스크를 포함하지 않는 클래스풀 형식의 초기 RIP 버전
- **RIPv2(RIP Version 2)** : 서브넷 마스크·다음 홉·경로 태그·인증 확장을 지원하는 RIP 버전
- **RIPng(RIP next generation)** : IPv6를 위한 RIP 확장

## 2~4교시 25점 답안

## Ⅰ. RIP(Routing Information Protocol)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 벨만-포드(Bellman-Ford) 거리 벡터(Distance Vector) 알고리즘에 기반하여 오직 목적지까지 거쳐가는 라우터 수(홉 수, Hop Count)만을 메트릭으로 최적 경로를 계산하는 내부 게이트웨이 프로토콜(IGP) |
| 목적 | 소규모 독립 네트워크에서 라우터 설정 및 관리의 극단적 단순화, 저사양 CPU/메모리 라우터 환경에서의 자율적 동적 경로 배정 |

## Ⅱ. RIP(Routing Information Protocol)의 특징

| 특징 | 상세 내용 |
|---|---|
| 홉 수 메트릭 | 링크의 대역폭·지연과 무관하게 통과하는 라우터 개수(1~15)만으로 경로 비용 계산 (16은 도달 불능) |
| 주기적 전체 전파 | 30초마다 자신의 전체 라우팅 테이블 정보를 인접한 이웃 라우터에게만 브로드캐스트/멀티캐스트 전송 |
| 벨만-포드 수렴 | `D_x(y) = min_v { c(x,v) + D_v(y) }` 분산 연산 공식을 통해 점진적으로 전역 최단 경로 도출 |
| 카운트 투 인피니티| 네트워크 단절 시 이웃 간 잘못된 경로 정보를 상호 갱신하여 홉 수가 16까지 무한 증가하는 루프 위험 |

## Ⅲ. RIP(Routing Information Protocol)의 체계·프로세스

**RIP 벨만-포드 거리 벡터 갱신 및 테이블 구조**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ RIP 라우팅 테이블 갱신 메커니즘 ]             │
│                                                                        │
│   [ Router A ]                 [ Router B ]                 [ Router C ]│
│        │                            │                            │     │
│        ├─ 30초 주기 라우팅 갱신 ───►│                            │     │
│        │  (Dest: 10.1.1.0/24,       ├─ 30초 주기 라우팅 갱신 ───►│     │
│        │   Metric: 1 홉)            │  (Dest: 10.1.1.0/24,       │     │
│        │                            │   Metric: 1+1 = 2 홉)      │     │
│                                                                        │
│   [ Router C 의 최종 라우팅 테이블 ]                                   │
│   ┌────────────────────┬───────────┬──────────────┬──────────────┐     │
│   │ 목적지 네트워크    │ 메트릭(홉)│ 다음 홉 (GW) │ 인터페이스   │     │
│   ├────────────────────┼───────────┼──────────────┼──────────────┤     │
│   │ 10.1.1.0 /24       │ 2         │ Router B     │ FastEth 0/1  │     │
│   └────────────────────┴───────────┴──────────────┴──────────────┘     │
└────────────────────────────────────────────────────────────────────────┘
```

| 동작 타이머 | 기본 설정 시간 | 핵심 역할 및 기능 |
|---|---|---|
| **Update Timer** | 30초 | 전체 라우팅 테이블을 이웃 라우터로 주기적 브로드캐스트/멀티캐스트 전송 |
| **Invalid Timer** | 180초 | 특정 경로에 대해 갱신 정보를 받지 못하면 해당 경로의 메트릭을 16(Unreachable)으로 마킹 |
| **Holddown Timer** | 180초 | 장애 발생 경로에 대해 더 나쁜 메트릭 정보 유입 시 루프 방지를 위해 일정 시간 수락 보류 |
| **Flush Timer** | 240초 | 무효화된 경로를 라우팅 테이블에서 물리적으로 완전히 삭제(Delete) |

## Ⅳ. RIP(Routing Information Protocol)의 종류·비교

| 비교 항목 | RIP v1 | RIP v2 | OSPF v2 |
|---|---|---|---|
| **라우팅 유형** | 거리 벡터 (Classful) | 거리 벡터 (Classless) | **링크 상태 (Link State)** |
| **서브넷 마스크 전송**| 미전송 (FLSM만 지원) | 전송 (VLSM / CIDR 지원) | **전송 (VLSM / CIDR 완벽 지원)** |
| **업데이트 방식** | 브로드캐스트 (255.255.255.255)| 멀티캐스트 (224.0.0.9) | **멀티캐스트 (224.0.0.5, 224.0.0.6)**|
| **인증 기능** | 미지원 (보안 취약) | 지원 (Cleartext, MD5) | **지원 (MD5, SHA 암호화 인증)** |
| **최대 네트워크 크기**| 최대 15홉 (16은 불능) | 최대 15홉 (16은 불능) | **홉 수 제한 없음 (Area 분할)** |
| **수렴 속도** | 느림 (30초 주기 전파) | 느림 (30초 주기 전파) | **매우 빠름 (변화 시 즉시 LSA)** |

## Ⅴ. RIP(Routing Information Protocol)의 한계와 방안

| 한계 | 방안 |
|---|---|
| 단순 홉 수(최대 15) 기반 메트릭으로 인해 100Mbps 고속 링크와 56kbps 저속 링크를 동일 비용으로 취급하여 심각한 비효율 경로 선택 | 링크 대역폭과 지연시간을 메트릭으로 복합 반영하는 OSPF(Cost) 또는 EIGRP(Composite Metric)로 전면 마이그레이션 |
| 네트워크 장애 발생 시 루프 경로를 따라 홉 수가 16(Unreachable)에 도달할 때까지 수 분간 갱신 패킷이 무한 순환하는 카운트 투 인피니티(Count-to-Infinity) 문제 | 스플릿 호라이즌(Split Horizon), 포이즌 리버스(Poison Reverse), 홀드다운 타이머(Holddown Timer) 결합 적용 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
RIP 운용망에서 네트워크 루프를 차단하기 위해 모든 인터페이스에 `Split Horizon with Poison Reverse`를 기본 활성화하고, 경로 단절 감지 시 즉각 장애 정보를 알리는 트리거드 업데이트(Triggered Update)를 설정하여 수렴 시간을 단축.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ RIP 4대 루프 방지 메커니즘 상호작용 ]                                │
│                                                                        │
│ 1. 스플릿 호라이즌 (Split Horizon)                                     │
│    - 특정 인터페이스를 통해 수신한 라우팅 정보는 동일 인터페이스로 역전송 금지 │
│                                                                        │
│ 2. 포이즌 리버스 (Poison Reverse)                                      │
│    - 정보를 보내준 인터페이스로 해당 경로의 메트릭을 '16'으로 표기하여 역전송   │
│                                                                        │
│ 3. 홀드다운 타이머 (Holddown Timer)                                    │
│    - 경로 장애 통보 수신 시 180초간 해당 경로에 대한 타 라우터의 갱신을 동결   │
│                                                                        │
│ 4. 트리거드 업데이트 (Triggered Update)                                │
│    - 30초 타이머 만료를 기다리지 않고 토폴로지 변경 즉시 갱신 패킷 송출        │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 루프 방지 기술 | 동작 원리 | 장점 | 단점 |
|---|---|---|---|
| **스플릿 호라이즌** | 수신 포트로 해당 경로 역전송 배제 | 2-노드 루프 원천 방지 | 3개 이상 노드 간 간접 루프 미해결 |
| **포이즌 리버스** | 수신 포트로 Metric 16(무한) 통보 | 루프 가능성을 적극적 무효화 | 갱신 패킷 크기 증가 |
| **홀드다운 타이머**| 장애 경로 갱신 180초간 접수 보류 | 잘못된 갱신 정보 침투 차단 | 정상적인 대체 경로 학습까지 지연 |
