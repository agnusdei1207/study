## 연관 키워드

- RIPv1, RIPv2, RIPng, 홉 수(Hop Count), 16(도달 불능 표시)
- 갱신 타이머, 무효 타이머, 삭제 타이머, Split Horizon, Poison Reverse
- Triggered Update, Holddown Timer, Count-to-Infinity, MD5 인증

## Ⅰ. RIP의 개요

- 핵심 요약 : 라우터 통과 횟수를 유일한 비용으로 삼아 주기적으로 경로 테이블을 교환하는 소규모 망용 라우팅 프로토콜.
- 개념 : 자율 시스템(AS, Autonomous System) 내부에서 인접 라우터와 경로 정보를 주기적으로 주고받는 **내부 게이트웨이 프로토콜** (IGP, Interior Gateway Protocol)의 하나인 **RIP** (Routing Information Protocol).
- 배경 및 필요성 : 초기 인터넷 시기의 라우터는 연산·기억 자원이 빈약하여 복잡한 연산 없이 경로를 자동 학습하는 단순한 프로토콜이 필요했고, RIPv1이 RFC 1058로 표준화됨.
- 주요 목적 : 최소한의 자원과 설정으로 경로 학습을 자동화하고, 장애 시 대체 경로로의 수렴을 구현.

## Ⅱ. RIP의 특징 및 장점

- 핵심 요약 : 단일 메트릭의 단순함, 주기적 전체 광고, 버전 보완, 루프 방지 기법이 쉬운 구현과 운영으로 이어지는 구조.

1. **홉 수** (Hop Count) 메트릭 : 목적지까지 거치는 라우터 수를 비용으로 사용하며 1~15가 유효하고 16은 도달 불능을 뜻함 → 계산과 해석이 단순해 소형 장비에서도 동작.
2. 주기적 전체 광고 : 30초 주기의 **갱신 타이머** (Update Timer)마다 테이블 전체를 UDP(User Datagram Protocol) 520번 포트로 전송 → 별도의 인접 수립 절차 없이 상태 동기화가 단순.
3. 버전별 보완 : RIPv1(RFC 1058)의 브로드캐스트·클래스풀 방식을 RIPv2(RFC 2453)의 멀티캐스트·클래스리스·인증으로, RIPng(RFC 2080)의 IPv6(Internet Protocol version 6) 지원으로 확장 → 버전 교체만으로 요구 수용.
4. 루프 방지 기법 : 거리 벡터 방식 고유의 경로 루프를 억제하는 네 가지 규칙 → 수렴 안정성 확보.
   1. **Split Horizon** : 인접 라우터에서 학습한 경로를 같은 인터페이스로 재광고하지 않는 규칙
   2. **Poison Reverse** : 학습 출처 경로를 홉 수 16으로 되돌려 광고하는 규칙
   3. **Triggered Update** : 경로 변화 시 주기를 기다리지 않고 즉시 광고하는 규칙
   4. **Holddown Timer** : 다운 경로의 갱신을 일정 시간 보류하는 규칙

## Ⅲ. RIP의 구조 (흐름)

- 핵심 요약 : 세 종류의 타이머로 경로의 생명주기를 관리하고, 장애 시 루프 방지 기법을 순서대로 동작시키는 구조.
- 타이머 체계 : **무효 타이머** (Timeout Timer) 180초와 **삭제 타이머** (Garbage Collection Timer) 120초가 RFC 2453의 기본값이며, Triggered Update에는 1~5초의 무작위 지연을 두어 여러 라우터의 동시 전송이 겹치는 현상을 방지함.

```text
[ 정상 상태 광고 흐름 ]

라우터 A 테이블 전체 전송 (30초 주기)
    ↓ UDP 520번 포트
인접 라우터 B 수신
    ↓ 수신 경로 홉 수 +1 후 비교
더 짧은 경로면 테이블 갱신
    ↓ 무반응 180초 경과 시 무효 판정
120초 후 테이블에서 삭제
```

```text
[ 링크 장애 시 루프 방지 흐름 ]

장애 경로 감지
    ↓ 홉 수 16 역광고 (Poison Reverse)
주기 무시 즉시 광고 (Triggered Update)
    ↓ 학습 인터페이스 재광고 금지 (Split Horizon)
Holddown 동안 해당 경로 갱신 보류
    ↓
낡은 정보에 의한 경로 복귀 차단
```

- **Count-to-Infinity** (무한 계수) : 링크 단절 후 라우터들이 서로의 낡은 정보를 주고받으며 홉 수가 16에 도달할 때까지 늘어나는 현상으로, 위 기법들이 억제 대상.

## Ⅳ. RIPv1과 RIPv2·RIPng의 비교

- 핵심 요약 : 버전이 올라갈수록 서브넷 마스크 전달과 인증, 멀티캐스트가 보강되었으나 홉 수 메트릭과 15홉 한계는 그대로 유지됨.

| 비교 항목 | RIPv1 (RFC 1058) | RIPv2 (RFC 2453) | RIPng (RFC 2080) |
| --- | --- | --- | --- |
| 주소 체계 | 클래스풀 주소 | 클래스리스, VLSM(Variable Length Subnet Mask) 지원 | IPv6 프리픽스 길이 포함 |
| 업데이트 주소 | 255.255.255.255 브로드캐스트 | 224.0.0.9 멀티캐스트 | FF02::9 멀티캐스트 |
| UDP 포트 | 520 | 520 | 521 |
| 인증 | 없음 | 평문, MD5(Message Digest 5), HMAC-SHA 계열 | IPsec에 위임 |
| 최대 홉 수 | 15 | 15 | 15 |

- 선택 기준 : 신규 구축은 RIPv2 이상만 검토하고, IPv6 전용 구간은 RIPng를, 규모 확장이 예상되는 망은 링크 상태 방식인 OSPF(Open Shortest Path First)를 적용함.

## Ⅴ. RIP의 한계와 방안

- 핵심 요약 : 15홉 한계와 회선 품질 무시, 느린 수렴, 경로 위조를 프로토콜 전환과 루프 방지 기법, 인증 강제로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 최대 15홉 제한 | 16홉을 도달 불능으로 간주해 광역 구성 불가 | 대규모 구간의 OSPF 전환 또는 영역 분할 | 15홉 초과 목적지 수 |
| 홉 수 단일 메트릭 | 대역폭·지연 미반영으로 저속 경로 선택 병목 | 대역폭 기반 코스트의 OSPF나 복합 메트릭의 EIGRP(Enhanced Interior Gateway Routing Protocol) 도입 | 링크 이용률 편차 |
| 느린 수렴과 Count-to-Infinity | 낡은 경로 정보의 순환으로 루프와 패킷 손실 발생 | 루프 방지 기법의 활성화와 타이머 튜닝 병행 | 수렴 소요 시간 |
| 경로 정보 위조 | 인증 없는 구간의 악의적 광고로 트래픽 탈취 | RIPv2의 MD5 이상 암호 인증 강제 | 미인증 업데이트 차단 건수 |

## Ⅵ. RIP에 대한 기술사적 제언

- 핵심 요약 : 잔존 RIP 구간을 표준 설정과 인증으로 정리하고, 전환 절차와 감시 체계를 조직 차원에서 정례화하는 방향.

1. 네트워크 운영 조직은 라우팅 표준 문서에 RIP 적용 범위를 소규모·폐쇄 구간으로 한정하고, RIPv2 암호 인증과 타이머 기본값을 설정 표준으로 명문화할 필요가 있음.
2. 전환 담당 부서는 OSPF 병행 과도기의 상호 재분배 구간을 사전에 목록화하고, 경로 태깅과 필터링 정책을 설계 단계에 반영해 이중 광고로 인한 루프를 차단해야 함.
3. 관제 조직은 수렴 지표와 루프 징후를 상시 모니터링 항목으로 등록하고, 장애 시나리오 기반의 정기 검증으로 잔존 구간의 이상 동작을 조기에 식별해야 함.

## Ⅶ. 결론

- 핵심 요약 : RIP는 홉 수와 주기 광고의 단순함으로 자동 라우팅을 대중화했으나, 규모와 수렴의 한계로 잔존 구간 관리 대상이 된 프로토콜임.
- 시사점 : 단순한 메트릭은 규모 확장과 경로 품질을 보장하지 못하므로, 망 규모에 연동한 프로토콜 선정 기준의 정의가 필요함.
