## 연관 키워드

- RIP, 거리 벡터, 벨만-포드, 홉 수, 자율 시스템, 내부 게이트웨이 프로토콜
- Split Horizon, Poison Reverse, Triggered Update, Holddown Timer, Count-to-Infinity
- RIPv2, VLSM, OSPF, EIGRP

## Ⅰ. RIP(Routing Information Protocol)의 개요

- 핵심 요약 : 홉 수 하나만으로 최단 경로를 고르는 소규모 망용 거리 벡터 라우팅 프로토콜.
- 개념 : **RIP** (Routing Information Protocol)는 자율 시스템(AS, Autonomous System) 내부에서 **벨만-포드** 알고리즘으로 최단 경로를 계산하고, 목적지까지의 홉 수를 유일한 메트릭으로 삼아 라우팅 정보를 주기적으로 교환하는 **내부 게이트웨이 프로토콜** (IGP, Interior Gateway Protocol)이다.
- 배경 및 필요성 : 초기 인터넷(ARPANET) 시기에는 라우터의 CPU(Central Processing Unit)와 메모리가 빈약하여, 복잡한 연산 없이 인접 라우터끼리 테이블을 교환하는 단순한 자동 라우팅이 필요했다. 이에 RFC 1058(RIPv1)로 표준화되었다.
- 주요 목적 : 적은 라우터 자원으로 경로를 자동 학습하고, 초기 설정을 간소화하며, 링크 장애 시 대체 경로로 수렴하는 것.

## Ⅱ. RIP(Routing Information Protocol)의 특징 및 장점

- 핵심 요약 : 단순한 거리 벡터 계산, 홉 수 메트릭, 루프 방지 장치가 적은 자원과 쉬운 설정으로 이어지는 구조.

1. **거리 벡터** (Distance-Vector) 방식 : 인접 라우터가 알려 준 정보만 신뢰하여 벨만-포드 식 D_x(y) = min_v{c(x,v) + D_v(y)}로 자신의 테이블을 갱신 → 구현이 단순해 소형 장비에서도 동작.
2. **홉 수** (Hop Count) 메트릭 : 거쳐 가는 라우터 개수를 비용으로 사용하며 1~15가 유효하고 16은 도달 불능을 뜻함 → 계산이 쉬우나 회선 속도는 반영하지 않음.
3. 주기적 전체 광고 : 매 30초마다 UDP(User Datagram Protocol) 520번 포트로 테이블 전체를 전송(RIPv1은 255.255.255.255 브로드캐스트, RIPv2는 224.0.0.9 멀티캐스트) → 상태 동기화가 단순함.
4. 루프 방지 4대 장치 : **Split Horizon** (수신한 인터페이스로 같은 정보를 되돌려 보내지 않음), **Poison Reverse** (장애 경로의 홉 수를 16으로 설정해 역광고), **Triggered Update** (토폴로지 변화 시 주기를 기다리지 않고 즉시 송출), **Holddown Timer** (다운 신호 수신 후 180초 동안 해당 경로 갱신을 보류).

## Ⅲ. RIP(Routing Information Protocol)의 구조 (흐름)

- 핵심 요약 : 정기 광고로 테이블을 맞추고, 장애가 생기면 Poison Reverse와 Triggered Update로 알리며 Holddown Timer로 잘못된 복귀를 막는 두 흐름의 결합.

```text
[ 정기 광고 (30초 주기) ]
[ 라우터 A ] 테이블 전체 전송
      ↓ UDP 520
[ 인접 라우터 B ] 홉 수 +1 후 비교
      ↓
[ 더 짧은 경로면 테이블 갱신 ]
```

```text
[ 링크 장애 발생 ]
      ↓
[ 홉 수 16 설정 (Poison Reverse) ]
      ↓
[ Triggered Update 즉시 전파 ]
      ↓
[ Holddown Timer 180초 동안 갱신 보류 ]
```

- **Count-to-Infinity** (무한대 계수) 문제 : 링크가 끊겼을 때 라우터들이 서로의 잘못된 정보를 참조하여 홉 수를 16에 도달할 때까지 1씩 늘리며 루프를 도는 현상. 위 장치들이 이를 억제한다.

## Ⅳ. RIP(Routing Information Protocol)의 비교

- 핵심 요약 : RIP는 버전이 올라갈수록 서브넷과 인증을 보강했지만, 홉 수 기반 경로 선택과 15홉 한계는 OSPF에 자리를 내주는 원인이 됨.

| 비교 항목 | RIPv1 (RFC 1058) | RIPv2 (RFC 2453) | IPv6용 RIP (RIPng, RFC 2080) | OSPFv2 (RFC 2328) |
| --- | --- | --- | --- | --- |
| 라우팅 유형 | Classful 거리 벡터 | Classless 거리 벡터 | IPv6(Internet Protocol version 6) 거리 벡터 | Classless 링크 상태 |
| 서브넷 마스크 | 전송하지 않아 VLSM(Variable Length Subnet Mask) 불가 | 패킷에 마스크 포함, VLSM 지원 | 프리픽스 길이 포함 | 패킷에 마스크 포함, VLSM 지원 |
| 업데이트 방식 | 255.255.255.255 브로드캐스트 | 224.0.0.9 멀티캐스트 | FF02::9 멀티캐스트 | 224.0.0.5/6 멀티캐스트 |
| 인증 | 인증 기능 없음 | 단순 텍스트, MD5(Message Digest 5) 인증 | IPsec(Internet Protocol Security) 기반 | 단순 텍스트, MD5 등 암호 인증 |
| 최대 네트워크 크기 | 최대 15홉 | 최대 15홉 | 최대 15홉 | 영역(Area) 분할로 대규모 구성 가능 |
| 경로 결정 기준 | 홉 수 | 홉 수 | 홉 수 | 링크 코스트(대역폭 기반) |

- 선택 기준 : 소규모이고 설정을 최소화해야 하는 레거시 구간에만 RIP를 유지하고, 확장이 필요한 망에는 OSPF를 적용함.

## Ⅴ. RIP(Routing Information Protocol)의 한계와 방안

- 핵심 요약 : 15홉 한계, 홉 수 단일 메트릭, 느린 수렴을 프로토콜 전환과 인증, 루프 방지 규칙 강제로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 최대 15홉 제한 | 16홉 이상 목적지를 도달 불능으로 간주하여 광역 기업망 구축 불가 | 링크 상태 프로토콜인 OSPF 또는 계층적 영역 분할이 가능한 프로토콜로 전환 | 15홉 초과 경로 수 |
| 홉 수 기반 경로 선택 | 회선 대역폭과 지연을 반영하지 않아 저속 1홉 전용선이 고속 다홉 경로보다 선택되는 병목 | 대역폭과 지연을 고려하는 OSPF 코스트 또는 EIGRP(Enhanced Interior Gateway Routing Protocol) 복합 메트릭 도입 | 링크 이용률 편중도 |
| 느린 수렴과 Count-to-Infinity | 장애 시 전체 수렴에 수 분 이상 걸리고 잘못된 정보로 패킷 루프 발생 | Split Horizon, Poison Reverse, Triggered Update 규칙 강제와 타이머 최적화 | 수렴 시간, 루프 발생 건수 |

## Ⅵ. RIP(Routing Information Protocol)에 대한 기술사적 제언

- 핵심 요약 : 신규 구축에서는 RIP를 배제하고, 남은 구간은 인증과 재분배 통제를 갖춘 상태로 OSPF에 점진적으로 옮기는 것이 바람직함.
- 소규모 지사망에 남아 있는 RIPv1 구간은 계층 구조를 갖춘 OSPF 단일 영역으로 재구성하면 수렴 속도와 대역폭 효율을 함께 얻을 수 있음.
- 전환 전까지 운영해야 하는 RIP 구간은 RIPv2로 올려 224.0.0.9 멀티캐스트를 사용하고 MD5 인증을 강제하면, 브로드캐스트 부하와 경로 위조를 함께 막을 수 있음.
- OSPF와 RIP가 혼재하는 과도기에는 재분배 경로에 Route-map 태깅을 적용해 상호 재분배로 생기는 루프를 차단하는 정책을 먼저 수립하는 것이 안전함.

## Ⅶ. 결론

- 핵심 요약 : RIP는 거리 벡터와 홉 수라는 단순함으로 자동 라우팅의 출발점을 열었으나, 규모와 수렴의 한계로 현대 대규모 망에서는 사용 범위가 줄어든 프로토콜임.
- 시사점 : 단순한 메트릭은 경로 품질을 보장하지 못하며, 이 교훈이 대역폭과 지연을 반영하는 링크 상태 프로토콜 선택의 근거가 됨.
