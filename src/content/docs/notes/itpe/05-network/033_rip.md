## 30초 인출

- 본질: **RIP(Routing Information Protocol)** : 거리 벡터 알고리즘으로 목적지까지의 홉 메트릭을 교환하는 내부 게이트웨이 라우팅 프로토콜
- 메커니즘: 이웃 라우터의 경로·메트릭 수신 → 수신 링크 비용을 더해 경로 선택 → 주기·변경 기반 갱신

<details>
<summary>핵심 용어</summary>

- **RIP(Routing Information Protocol)** : 홉 메트릭 기반 거리 벡터 내부 게이트웨이 프로토콜
- **거리 벡터(Distance Vector)** : 목적지까지의 거리·다음 홉을 이웃과 교환하는 라우팅 방식
- **홉 카운트(Hop Count)** : RIP가 경로 선택에 쓰는 라우터 홉 단위 메트릭
- **무한대(Infinity)** : RIP에서 16으로 표현하는 도달 불가 메트릭
- **스플릿 호라이즌(Split Horizon)** : 경로를 학습한 인터페이스로 같은 경로 정보를 다시 알리지 않는 루프 완화 기법
- **포이즌 리버스(Poison Reverse)** : 학습한 인터페이스로 경로를 광고하되 도달 불가 메트릭으로 알리는 기법
- **RIPv1(RIP Version 1)** : 서브넷 마스크를 포함하지 않는 클래스풀 형식의 초기 RIP 버전
- **RIPv2(RIP Version 2)** : 서브넷 마스크·다음 홉·경로 태그·인증 확장을 지원하는 RIP 버전
- **RIPng(RIP next generation)** : IPv6를 위한 RIP 확장

</details>

## 1교시 예상문제 (10점)

> RIP의 개념과 거리 벡터 경로 선택·갱신 원리를 설명하시오. (예상·10점)

---

## 1교시 10점 답안

### Ⅰ. RIP의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **RIP** : 홉 카운트 메트릭을 이웃과 교환해 경로를 결정하는 거리 벡터 라우팅 프로토콜 |
| 목적 | 이웃 라우팅 정보 교환을 통한 목적지별 다음 홉 결정 |

### Ⅱ. 경로 갱신

```text
이웃 경로·메트릭 수신
         ↓ 홉 메트릭 + 1
목적지별 다음 홉 비교
         ↓
라우팅 테이블 갱신
         ↓
주기·변경 시 갱신 전파
```

- 제언: 홉 수 외에 링크 용량·수렴 요구를 고려한 라우팅 프로토콜 선정.

## 2~4교시 25점 답안

### Ⅰ. RIP의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **RIP** : 홉 카운트 메트릭을 이웃과 교환해 경로를 결정하는 거리 벡터 라우팅 프로토콜 |
| 목적 | 이웃 라우팅 정보 교환을 통한 목적지별 다음 홉 결정 |

### Ⅱ. 거리 벡터 경로 갱신

```text
이웃 경로·메트릭 수신
         ↓ 홉 메트릭 + 1
목적지별 다음 홉 비교
         ↓
라우팅 테이블 갱신
         ↓
주기·변경 시 갱신 전파
```

### Ⅲ. 메트릭과 도달 가능 범위

| 홉 메트릭 | 의미 |
|---:|---|
| 1–15 | 도달 가능한 경로 비용 |
| 16 | 도달 불가를 나타내는 무한대 값 |

경로 선택은 링크 대역폭·지연을 직접 평가하지 않음. RFC 2453의 정기 갱신 주기는 기본적으로 30초이며, 경로 변경 시 트리거 갱신도 사용.

### Ⅳ. 루프 완화

| 기법 | 동작 | 한계 |
|---|---|---|
| Split Horizon | 학습 인터페이스 방향으로 경로를 광고하지 않음 | 모든 다중 라우터 루프 제거를 보장하지 않음 |
| Poisoned Reverse | 해당 방향에 무한대 메트릭으로 경로 광고 | 갱신 메시지·토폴로지에 따른 한계 |
| Triggered Update | 경로 변화 시 갱신 전파 | 동시 변화·지연된 정보 영향을 받을 수 있음 |

### Ⅴ. 버전별 비교

| 항목 | RIPv1 | RIPv2 | RIPng |
|---|---|---|---|
| 주소 체계 | IPv4 | IPv4 | IPv6 |
| 프리픽스 정보 | 서브넷 마스크 미포함 | 서브넷 마스크 포함 | IPv6 프리픽스·라우트 태그 등 |
| 전송 방식 | 브로드캐스트 | 멀티캐스트 `224.0.0.9` 등 | 멀티캐스트 `FF02::9` |
| 인증·확장 | 제한적 | 확장·인증 필드 | IPv6 환경의 별도 인증 설계 |

### Ⅵ. 한계와 대응

| 한계 | 대응 |
|---|---|
| 15홉 최대 메트릭으로 대규모 망에 부적합 | 망 규모·경로 요구에 맞춰 OSPF 등 다른 IGP 검토 |
| 홉 수만 반영해 링크 품질 차이를 반영하지 못함 | 필요한 지연·대역폭 기준과 경로 정책을 비교 |
| 거리 벡터 수렴 중 오래된 경로로 루프 가능 | 스플릿 호라이즌·포이즌 리버스·트리거 갱신 적용과 장애 시험 |
| 주기 갱신·경로 수 증가의 운영 부담 | 규모·갱신 트래픽·수렴 요구를 기준으로 적용 범위 제한 |

### Ⅶ. 기술사적 제언

| 우선 선택 | 적용·확인 |
|---|---|
| 소규모·단순 토폴로지에서 요구 적합성을 우선 검토 | 경로 수·홉 수·장애 수렴·운영 복잡도를 실측하고 확대 한계 도달 시 IGP 전환 계획 수립 |
