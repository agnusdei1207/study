## Ⅰ. RIP(Routing Information Protocol)의 개요

- 개념 : 자율 시스템(AS) 내부의 소규모 네트워크에서 라우터 간 최단 경로를 결정하기 위해 **벨만-포드(Bellman-Ford)** 거리 벡터 알고리즘을 사용하며, 목적지 네트워크까지 도달하는 홉 수(Hop Count)를 유일한 메트릭으로 삼아 주기적으로 라우팅 정보를 교환하는 내부 게이트웨이 프로토콜(IGP).
- 배경 및 필요성 : 초기 인터넷(ARPANET) 환경에서 라우터 하드웨어 성능(CPU, 메모리)이 극히 열악했던 시절, 복잡한 연산 없이 인접 라우터 간의 단순 테이블 교환만으로 자동 라우팅을 구현하기 위해 RFC 1058(RIPv1)로 표준화됨.
- 핵심 목적 : 단순한 알고리즘을 통한 최소한의 라우터 리소스 소모, 초기 설정의 극단적 간소화, 소규모 네트워크 환경에서의 자동 경로 학습 및 링크 장애 시 대체 경로 수렴.

## Ⅱ. RIP(Routing Information Protocol)의 핵심 아키텍처 및 동작 메커니즘

RIP은 매 30초마다 자신의 라우팅 테이블 전체를 인접 라우터에 브로드캐스트/멀티캐스트로 전송하며, 홉 수 기반 최단 경로 선택 및 루프 방지 메커니즘을 통해 동작함.

```text
[ RIP 라우팅 정보 교환 및 홉 수(Hop Count) 메커니즘 ]

[ 라우터 A ] <── 10Gbps 광케이블 (1 Hop) ──> [ 라우터 B ]
     │                                            ▲
     │ (1 Hop)                                    │ (1 Hop)
     ▼                                            │
[ 라우터 C ] <── 100Gbps 백본 (1 Hop) ────────────┘

* RIP의 경로 선택 결과:
  - 경로 1: A -> B (총 10Gbps, 홉 수 = 1) =====> [ RIP 최적 경로 선택! ]
  - 경로 2: A -> C -> B (총 100Gbps, 홉 수 = 2) ==> [ 배제됨 (홉 수가 큼) ]
  => 문제점: 회선 속도가 10배 빠른 광대역 경로를 두고 느린 단일 홉 선택!

[ RIP 루프 방지 4대 핵심 메커니즘 ]
1. Split Horizon     : 특정 인터페이스로 수신한 라우팅 정보는 동일 인터페이스로 되돌려 보내지 않음
2. Poison Reverse    : 장애 발생 경로에 대해 홉 수를 즉시 16(도달 불가)으로 설정하여 역광고
3. Triggered Update  : 30초 정기 주기를 기다리지 않고 토폴로지 변화 즉시 업데이트 패킷 송출
4. Holddown Timer    : 네트워크 다운 신호 수신 시 일정 시간(180초) 동안 해당 경로의 갱신 보류
```

- **거리 벡터(Distance-Vector) 알고리즘** : 벨만-포드 공식($D_x(y) = \min_v \{ c(x,v) + D_v(y) \}$)에 따라 인접 이웃 라우터의 정보만 신뢰하여 자신의 경로 테이블을 갱신.
- **홉 수(Hop Count) 메트릭** : 거쳐가는 라우터의 개수를 비용으로 사용하며, 최소 1부터 최대 15까지 유효하고 16은 '도달 불능(Unreachable / Infinity)'을 의미.
- **주기적 전체 광고** : 매 30초마다 UDP 포트 520을 통해 라우팅 테이블 전체를 인접 라우터에 전송(RIPv1: 255.255.255.255 브로드캐스트, RIPv2: 224.0.0.9 멀티캐스트).
- **무한대 계수(Count-to-Infinity) 문제** : 링크 단절 시 라우터들이 서로의 잘못된 정보를 참조하여 홉 수를 16에 도달할 때까지 점진적으로 1씩 증가시키며 루프를 도는 현상.

## Ⅲ. RIP(Routing Information Protocol)의 세부 구성 요소 및 비교 분석

| 비교 항목 | RIPv1 (RFC 1058) | RIPv2 (RFC 2453) | RIPng (RFC 2080) | OSPFv2 (RFC 2328) |
|---|---|---|---|---|
| 라우팅 유형 | Classful Distance-Vector | Classless Distance-Vector | IPv6 Distance-Vector | Classless Link-State |
| **서브넷 마스크** | 전송 안 함 (VLSM 불가)| 패킷에 마스크 포함 (VLSM) | Prefix 길이 포함 (IPv6) | 패킷에 마스크 포함 (VLSM) |
| 업데이트 방식 | 255.255.255.255 브로드캐스트| 224.0.0.9 멀티캐스트 | FF02::9 멀티캐스트 | 224.0.0.5/6 멀티캐스트 |
| 인증(Security) | 인증 기능 전혀 없음 | 단순 텍스트 & MD5 인증 | IPsec 기반 인증 | 단순 텍스트, MD5, SHA |
| 최대 네트워크 크기 | 최대 15홉 | 최대 15홉 | 최대 15홉 | 무제한 (Area 분할) |
| 경로 결정 기준 | 단순 홉 수 | 단순 홉 수 | 단순 홉 수 | 링크 코스트 (대역폭 역수)|

- RIPv2는 VLSM 지원과 멀티캐스트, MD5 인증을 보강하여 편의성을 높였으나, 최대 15홉 제한과 단순 홉 수 기반 경로 선택의 한계로 인해 현대 대규모 망에서는 OSPF에 자리를 내어줌.

## Ⅳ. RIP(Routing Information Protocol)의 주요 한계점 및 해결 방안

- 최대 15홉 제한으로 인한 중대규모 네트워크 확장 불가 :
  - 한계점 : 16홉 이상 떨어진 목적지는 도달 불능으로 간주되므로 라우터가 15대를 초과하는 광역 기업망 구축 불가.
  - 해결 방안 : 링크 상태 프로토콜인 OSPF 또는 계층적 Area 분할이 가능한 프로토콜로 전면 마이그레이션.
- 회선 대역폭 및 지연을 무시한 단순 홉 수 경로 선택의 비효율 :
  - 한계점 : 100G 고속 회선 2홉보다 64Kbps 저속 전용선 1홉을 최적 경로로 선택하여 심각한 병목 유발.
  - 해결 방안 : 대역폭, 딜레이를 종합 고려하는 EIGRP 복합 메트릭이나 OSPF 코스트 기반 라우팅 도입.
- 느린 수렴(Convergence) 속도와 Count-to-Infinity 라우팅 루프 :
  - 한계점 : 링크 장애 시 전체 라우터가 수렴할 때까지 수 분 이상 소요되며 패킷이 핑퐁 루프 발생.
  - 해결 방안 : Split Horizon, Poison Reverse, Triggered Update 표준 규칙 강제 및 타이머 최적화.

## Ⅴ. RIP(Routing Information Protocol) 적용 및 발전을 위한 기술사적 제언

- 현대 엔터프라이즈 환경에서의 RIP 사용 지양 및 OSPF 전환 가속 : 소규모 레거시 지사망에 남아있는 RIPv1/v2를 계층적 OSPF 단일 영역으로 재구성하여 수렴 속도 및 대역폭 효율 극대화.
- 레거시 RIP 유지보수 시 필수적 RIPv2 전환 및 MD5 인증 강제 : 브로드캐스트 플러딩으로 인한 단말 부하를 방지하기 위해 224.0.0.9 멀티캐스트를 사용하고 경로 위조 방지를 위한 MD5 해시 인증 강제화.
- 경로 재분배(Route Redistribution) 시 상호 라우팅 루프 방지 필터링 수립 : OSPF와 RIP이 혼용되는 과도기 환경에서 상호 재분배 시 홉 수 왜곡으로 인한 라우팅 루프를 막기 위해 Route-map 태깅 정책 철저 수립 권장.
