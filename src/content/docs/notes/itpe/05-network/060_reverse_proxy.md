- 메커니즘: 요청을 정책에 따라 검사·라우팅하고 응답을 다시 클라이언트에 전달하며, TLS 종단·캐시·부하 분산을 선택적으로 수행

<details>
<summary>핵심 용어</summary>

- **리버스 프록시(Reverse Proxy):** 서버 측에 배치되어 클라이언트 요청을 받아 백엔드로 전달하는 프록시
- **TLS(Transport Layer Security) 종단(Termination):** 프록시에서 클라이언트 TLS 연결을 종료하고 별도 백엔드 연결을 여는 구성
- **X-Forwarded-For(XFF):** 프록시가 전달 경로의 클라이언트 주소 정보를 나타내는 데 사용하는 HTTP 헤더
- **Forwarded:** 프록시 경유로 바뀌거나 사라지는 요청 정보를 전달하는 표준 HTTP 헤더 필드
- **백엔드(Backend):** 프록시가 요청을 전달하는 응용 서버

</details>

## 1교시 10점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **리버스 프록시(Reverse Proxy)** 는 클라이언트와 백엔드 사이에서 서버를 대신해 요청·응답을 중계하는 서버 |
| 목적 | 백엔드 직접 노출을 줄이고 요청 라우팅과 공통 전달 기능을 제공 |

## Ⅱ. 요청·응답 구조

```text
클라이언트
    │ 요청
    ▼
리버스 프록시 ── 정책 검사·라우팅 ──▶ 백엔드 서버
    ▲                                  │
    └────────────── 응답 전달 ─────────┘
```

| 기능 | 역할 |
|---|---|
| TLS 종단 | 외부 TLS 연결을 종료하고 백엔드 연결을 별도로 관리 |
| 부하 분산 | 정책에 따라 요청을 여러 백엔드로 전달 |
| 캐시 | 캐시 가능한 응답을 저장해 백엔드 요청을 줄임 |

제언: 백엔드의 직접 접근을 제한하고 전달 헤더의 신뢰 경계를 명확히 설정

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **리버스 프록시(Reverse Proxy)** 는 클라이언트와 백엔드 사이에서 서버를 대신해 요청·응답을 중계하는 서버 |
| 목적 | 백엔드 직접 노출을 줄이고 요청 라우팅과 공통 전달 기능을 제공 |

## Ⅱ. 프록시 배치와 요청 흐름

```text
                 ┌── 정책 경로 1 ──▶ 백엔드 A
외부 클라이언트 ──▶ 리버스 프록시
                 └── 정책 경로 2 ──▶ 백엔드 B
                       ▲                 │
                       └── 응답 취합 ◀───┘
         ◀──────────── 응답 전달
```

| 구분 | 포워드 프록시 | 리버스 프록시 |
|---|---|---|
| 대리 대상 | 클라이언트 | 서버 |
| 요청 방향 | 내부 사용자에서 외부 서비스 | 외부 사용자에서 내부 백엔드 |
| 대표 기능 | 접근 정책·캐시 | 라우팅·TLS 종단·부하 분산 |

## Ⅲ. 전달·보안 기능

| 기능 | 동작 | 운영상 확인점 |
|---|---|---|
| TLS 종단 | 외부 연결 종료 후 백엔드와 별도 연결 | 내부 구간 암호화와 인증서 수명 관리 |
| 원본 주소 전달 | 전달 헤더 등에 클라이언트 주소 기록 | 신뢰 프록시에서 온 헤더만 사용하도록 제한 |
| 부하 분산 | 상태·가중치 등 정책으로 백엔드 선택 | 헬스체크와 장애 시 제외 동작 |
| 캐시 | 정책에 맞는 응답 재사용 | 사용자별 응답의 캐시 격리와 무효화 |

## Ⅳ. 운영 한계와 대응

| 한계 | 대응 |
|---|---|
| 프록시 장애가 여러 백엔드 접근을 막을 수 있음 | 프록시 노드 이중화와 상태 점검 적용 |
| 전달 헤더를 무조건 신뢰하면 주소 위조 가능 | 신뢰할 수 있는 프록시 경계에서 헤더를 덮어쓰고 백엔드 직접 접근 차단 |
| TLS를 프록시에서 종료하면 내부 구간이 평문이 될 수 있음 | 보안 요구에 따라 백엔드 구간도 TLS로 보호 |
| 캐시 설정 오류가 오래되거나 다른 사용자 응답을 노출할 수 있음 | 캐시 키·민감 응답 제외·무효화 정책 시험 |

## Ⅴ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 서비스별 전달·보안 정책이 제각각이면 설정 누락과 장애 분석 지연이 발생 | 서비스 경로·신뢰 프록시·TLS 정책을 공통 구성으로 관리하고, 변경 전 요청 추적과 장애 전환을 검증 |
