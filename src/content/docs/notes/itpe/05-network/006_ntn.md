지식 위치: 네트워크 → 이동통신 접속 → **비지상 네트워크**

## 30초 인출

- 본질: **NTN** : 위성이나 공중 플랫폼을 통신 경로에 활용해 지상망이 닿기 어려운 지역의 접속을 보완하는 네트워크
- 메커니즘: 단말·비지상 플랫폼·게이트웨이·지상망을 연결하고, 긴 전파 지연·도플러·이동 빔에 맞춰 무선 절차 조정
- 통찰: 지상 기지국 중심 통신의 지리적 한계를 해소하기 위해 3GPP 표준 5G NR 무선 프로토콜을 저궤도 위성 및 HAPS 플랫폼에 직접 적용하고 지연·도플러 천이를 동적으로 보상하는 비지상 통신 아키텍처 구축이 필수적임.

<details>
<summary>핵심 용어</summary>

- **NTN(Non-Terrestrial Network)** : 위성·공중 플랫폼 등을 통신 경로에 사용하는 비지상 네트워크
- **UE(User Equipment)** : 이동통신망에 접속하는 이용자 단말
- **서비스 링크(Service Link)** : 단말과 비지상 플랫폼 사이의 무선 연결
- **피더 링크(Feeder Link)** : 비지상 플랫폼과 지상 게이트웨이 사이의 연결
- **투명 페이로드(Transparent Payload)** : 위성이 무선 신호를 중계하고 기지국 기능은 지상에 두는 구성
- **재생 페이로드(Regenerative Payload)** : 위성이 일부 또는 전체 기지국 신호 처리 기능을 수행하는 구성
- **TA(Timing Advance)** : 상향 송신 시점을 조정해 기지국 수신 타이밍을 맞추는 기법
- **도플러 편이(Doppler Shift)** : 송신자·수신자 상대 운동으로 수신 주파수가 달라지는 현상

</details>

## 2~4교시 25점 답안

## Ⅰ. NTN(Non-Terrestrial Network)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 정지궤도(GEO)·저궤도(LEO) 인공위성, 성층권 통신 플랫폼(HAPS) 등 공중 및 우주 비행체를 기지국 또는 무선 중계기로 활용하는 3GPP 표준 기반 비지상 네트워크 |
| 목적 | 지상망 구축이 불가능한 해상·항공·산악 지역의 100% 전 지구적 무선 커버리지 확보 및 재난 상황 백업망 제공 |

## Ⅱ. NTN(Non-Terrestrial Network)의 특징

| 특징 | 상세 내용 |
|---|---|
| 3GPP 표준 NR 적용 | 전용 위성 모뎀 없이 표준 3GPP 5G NR 프로토콜을 수정하여 일반 상용 스마트폰 직접 연결 지원 |
| 초광역 셀 커버리지 | 단일 위성 빔이 직경 수백 km의 거대 셀(Giant Cell)을 형성하여 극지방 및 해양 전역 도달 |
| 큰 전파 지연 보상 | 지상 대비 수십 배 긴 RTT(LEO 20~40ms, GEO 250ms) 극복을 위해 타이밍 어드밴스(TA) 대폭 확장 |
| 급격한 도플러 천이 | 저궤도 위성의 초고속 공전(약 7.5km/s)으로 인한 반송파 주파수 편차를 기지국/단말이 상호 예측 보상 |

## Ⅲ. NTN(Non-Terrestrial Network)의 체계·프로세스

**NTN 네트워크 아키텍처 및 페이로드 유형 비교**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ NTN 네트워크 구조 ]                          │
│                                                                        │
│   ┌───────────────────────────┐      ┌───────────────────────────┐     │
│   │ [ 투명 모드 (Transparent) ]│      │ [ 재생 모드 (Regenerative)│     │
│   │   위성은 단순 RF 중계     │      │   위성 내 gNodeB 기능 탑재│     │
│   │   (Bent-pipe Relay)       │      │   (On-board Processing)   │     │
│   └─────────────┬─────────────┘      └─────────────┬─────────────┘     │
│                 │                                  │                   │
│   [위성] ── RF 주파수 변환/증폭 ──      [위성] ── L1/L2/L3 패킷 복호/스위칭│
│      │                  │                   │                          │
│      ▼ (Service Link)   ▼ (Feeder Link)     ▼ (Service Link)           │
│   [단말 (UE)]       [지상 NTN 게이트웨이] [단말 (UE)] ── ISL(위성간 링크) │
│                             │                                          │
│                             ▼                                          │
│                     [지상 gNodeB / 5GC]                                │
└────────────────────────────────────────────────────────────────────────┘
```

| 구성 요소 | 주요 역할 및 기능 |
|---|---|
| **NTN UE** | GNSS(위성항법) 칩셋을 연동하여 자체 위치/속도를 기반으로 도플러 및 지연을 사전 보상하는 단말 |
| **비지상 플랫폼** | LEO/GEO 위성 또는 HAPS. 투명 페이로드(Transponder) 또는 재생 페이로드(gNodeB DU/CU) 탑재 |
| **게이트웨이** | 지상국에 위치하며 위성과 피더 링크(Feeder Link, Ka/Q/V 대역)를 형성하여 코어망과 인터페이스 연결 |
| **5G 코어망 (5GC)** | AMF, SMF, UPF 등으로 구성되며 지상망과 비지상망 가입자의 단일 통합 인증 및 세션 관리 수행 |

## Ⅳ. NTN(Non-Terrestrial Network)의 종류·비교

| 비교 항목 | 투명 모드 (Transparent Payload) | 재생 모드 (Regenerative Payload) |
|---|---|---|
| **위성 역할** | 단순 아날로그 RF 중계 (Bent-pipe) | 온보드 디지털 처리 및 gNodeB 기능 수행 |
| **위성 탑재 복잡도**| 낮음 (무게, 전력 소모 적음) | 높음 (고성능 방사선 내성 프로세서 필요) |
| **전파 지연 (RTT)** | 2홉 경유 (단말-위성-지상국 왕복 4배) | 1홉 경유 (단말-위성 직접 처리) 지연 단축 |
| **위성 간 링크(ISL)**| 미지원 (반드시 지상 게이트웨이 가시권 필요)| 위성 간 레이저 링크(ISL)를 통한 우주 라우팅 지원 |
| **3GPP 표준화** | Release 17 선제 상용화 완료 | Release 18/19 고도화 표준화 진행 |

## Ⅴ. NTN(Non-Terrestrial Network)의 한계와 방안

| 한계 | 방안 |
|---|---|
| LEO 위성의 빠른 궤도 이동으로 인한 핸드오버 폭증 및 신호 시그널링 오버헤드 | 단말 위치 기반 고정 서비스 영역을 비추는 지구 고정 빔(Earth-fixed Beam) 및 사전 승인 조건부 핸드오버(CHO) 구현 |
| 큰 RTT로 인한 HARQ 재전송 프로세스 정체 및 피드백 대기 지연 누적 | 3GPP 표준 기반 HARQ 피드백 비활성화(Disabling) 옵션 적용 및 대용량 버퍼 기반 블라인드 재전송 구현 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
스마트폰 직접 연결(Direct-to-Cell) 서비스 설계 시, 링크 버짓(Link Budget) 마진이 극도로 부족하므로 서브 2GHz 대역(3GPP n255, n256 등)을 우선 채택하고, 음성 및 데이터보다 재난 긴급 문자(IoT-NTN)를 선행 적용한 후 순차적으로 광대역 NR-NTN으로 확장.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 3GPP NTN 도플러 및 타이밍 어드밴스(TA) 사전 보상 메커니즘 ]        │
│                                                                        │
│ 1. 위성이 방송 정보(SIB19)로 위성 궤도력(Ephemeris Data) 전송         │
│ 2. 단말이 내장 GNSS로 단말 좌표 계산 + SIB19 위성 위치/속도 계산      │
│ 3. 단말이 기지국 전파 거리(Propagation Delay) 및 상대 속도 벡터 산출 │
│ 4. 단말이 업링크 송신 시 주파수 편차(-f_doppler) 및 TA를 사전 오프셋  │
│                                                                        │
│    Tx Packet ──► [ -Δf (Doppler 보상) + 사전 TA 앞당김 ] ──► 위성 안테나 │
│                                                                 │      │
│   결과: 위성 수신단에 주파수 편차 '0' 및 완벽한 심볼 정렬 달성 ◄───────┘      │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 구분 | IoT-NTN (NB-IoT/eMTC 기반) | NR-NTN (5G NR 기반) |
|---|---|---|
| **대상 서비스** | 긴급 SOS 문자 메시지, 원격 자산 추적, 센서 검침 | 음성 통화, 모바일 웹 서핑, 실시간 원격 제어 |
| **전송 속도** | 수 kbps ~ 수십 kbps | 수 Mbps ~ 수십 Mbps |
| **단말 요구 조건**| 기존 단말에 경미한 펌웨어 패치 수준 가능 | RF 송신 출력 증대 및 고감도 안테나 필요 |
| **표준화 시기** | 3GPP Release 17 핵심 규격 정의 | 3GPP Release 17/18 지속 진화 |
