## 한 줄 본질
- TCP의 단일 IP 종속(단일 회선 장애 시 연결 단절)과 1개 패킷 유실 시 전체 스트림이 멈추는 HoL 블로킹 한계 → 하나의 연결 안에 여러 독립 스트림을 분리하고 단말의 복수 IP(멀티호밍)를 묶어 회선 단절 시 무중단 자동 전환 → 통신망 신뢰성 극대화 / 인터넷 공유기(NAT) 및 레거시 보안 장비의 SCTP 패킷 미인식에 따른 터널링 필요

## 핵심 그림
```text
[ SCTP 핵심 2대 기능 : 멀티스트리밍 & 멀티호밍 ]

1. 멀티스트리밍 (Multi-streaming): 단일 결합(Association) 내 다중 독립 큐
   [ 스트림 0 (음성) ] ======> (패킷 유실 시 스트림 0만 잠시 재전송 대기)
   [ 스트림 1 (영상) ] ==============================================> (영향 없이 정상 통과!)
   [ 스트림 2 (제어) ] ==============================================> (HoL 블로킹 원천 차단!)

2. 멀티호밍 (Multi-homing): 단일 결합에 여러 IP 동시 바인딩
   [ 호스트 A ]                                          [ 호스트 B ]
   IP 1 (유선)   ================ (주 경로) ============>  IP 3
   IP 2 (LTE/5G) -------------- (보조 경로) ------------> IP 4
   (주 경로 케이블 절단 시 하트비트 실패 감지 후 보조 경로로 밀리초 무중단 스위칭!)
```

## 핵심 용어
- 멀티호밍(Multi-homing): 하나의 SCTP 연결(Association) 양 끝단에 여러 개의 IP 주소를 등록해 두고, 기본 경로에 장애가 발생하면 세션 재연결 없이 백업 IP 경로로 즉각 우회하는 기능
- 청크(Chunk): SCTP 패킷 내부에 포함되는 정보 블록. 하나의 SCTP 패킷 안에 제어 신호 청크(INIT, SACK 등)와 여러 개의 데이터 청크를 함께 묶어(Bundling) 전송 가능
- 4-way 핸드셰이크: TCP의 SYN Flooding 공격을 방어하기 위해 서버가 초기 연결 요청 시 상태를 저장하지 않고 암호화된 "상태 쿠키(State Cookie)"를 클라이언트에 돌려보낸 뒤 검증하는 연결 절차

## 핵심 통찰
- TCP는 바이트 단위 스트림(Byte Stream)이라 애플리케이션이 메시지 경계를 직접 파싱해야 하지만, SCTP는 UDP처럼 "메시지 프레임 경계"를 보존하면서도 TCP의 신뢰성(재전송/흐름제어)을 제공
- 인터넷 공유기(NAT)와 방화벽이 TCP/UDP 포트 번호만 파싱할 수 있어 공용 인터넷 망에서는 SCTP 패킷이 차단됨 → WebRTC에서는 SCTP를 UDP 패킷 안에 감싸는 "SCTP over DTLS over UDP" 터널링으로 극복
- 5G 이동통신 코어망의 제어 인터페이스(NGAP, N2) 및 통신사 간 시그널링(Diameter) 백본 전송의 사실상 단일 표준 프로토콜로 자리잡음

## 이웃 토픽과 구분
- TCP vs SCTP: TCP는 단일 IP 쌍(싱글홈)과 1개 스트림으로 HoL 블로킹 발생 / SCTP는 다중 IP 바인딩(멀티호밍)과 독립 스트림(멀티스트리밍)으로 통신 중단 차단

## 문제·원인·대책
- 적용 상황: 금융 거래 및 통신사 기지국 관제망의 단일 회선 절단 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 통신사 전용선 단절 시 세션 종료 및 거래 중단 | TCP의 단일 IP 바인딩 특성으로 인한 경로 페일오버 불가 | SCTP 멀티호밍(Multi-homing) 적용 및 이종 통신사 IP 바인딩 | 세션 재연결 없이 백업 회선으로 서브세컨드 무중단 전환 |
| 대용량 데이터 패킷 오류 시 실시간 제어 명령 지연 | 단일 TCP 파이프라인의 Head-of-Line 블로킹 | 제어 명령과 데이터 페이로드를 별도 SCTP 스트림으로 분리 | 데이터 재전송 중에도 제어 스트림은 0ms 즉시 전송 |

## 이렇게 출제된다
- 제132회 3교시 4번: "SCTP(Stream Control Transmission Protocol)에 대하여 다음을 설명하시오." → 요구 포인트: Ⅰ 개념 + Ⅲ 청크 기반 패킷 구조 + 핵심 기능 3종(멀티호밍, 멀티스트리밍, 4-way 핸드셰이크) + TCP/UDP와의 비교

## 내 의견
- [WebRTC 데이터 채널에서의 SCTP 최적화] 웹 브라우저 P2P 통신에서 비디오(RTP) 외에 바이너리 파일이나 실시간 텍스트를 안전하게 전송할 때 SCTP 필수 활용 → 나라면: 신뢰성 있는 전송(Reliable)과 비신뢰성 저지연 전송(Unreliable)을 스트림별로 선택할 수 있는 SCTP의 특성을 살려, 게임 상태 동기화 패킷은 재전송 없는 Unordered 모드로 설정하여 네트워크 지연을 극단적으로 단축
