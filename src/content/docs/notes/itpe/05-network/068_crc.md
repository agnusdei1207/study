## 연관 키워드

- CRC(Cyclic Redundancy Check), 생성 다항식(Generator Polynomial), 모듈로-2(Modulo-2) 연산, FCS(Frame Check Sequence)
- 군집 오류(Burst Error), 패리티 검사(Parity Check), 체크섬(Checksum), LFSR(Linear Feedback Shift Register)
- FEC(Forward Error Correction), HMAC(Hash-based Message Authentication Code), T10 DIF(Data Integrity Field)
- CRC-16-CCITT, CRC-16-IBM, CRC-32, CRC-64-ECMA

## Ⅰ. CRC의 개요

- 핵심 요약 : 데이터를 생성 다항식으로 나눈 나머지를 체크 비트로 붙여 비트 왜곡을 검출하는 기법.
- 개념 : 송신 데이터를 생성 다항식으로 모듈로-2 나눗셈한 나머지를 뒤에 덧붙여 보내고, 수신측이 같은 나눗셈으로 오류 여부를 판정하는 **순환 중복 검사** (CRC, Cyclic Redundancy Check).
- 배경 및 필요성 : 단순 패리티 검사는 짝수 개의 비트가 동시에 뒤집히면 오류를 놓치고, 단순 합산 체크섬은 비트 순서가 바뀐 오류를 잡지 못한다. 연속으로 발생하는 군집 오류를 높은 확률로 잡아내는 검사가 링크 계층의 신뢰성을 위해 필요해졌다.
- 주요 목적 : 이더넷 프레임과 저장 장치 블록의 무결성 검증, 하드웨어 LFSR로 고속 연산 구현.

## Ⅱ. CRC의 특징 및 장점

- 핵심 요약 : 나눗셈 나머지라는 단순한 수학 구조가 검출 능력과 하드웨어 구현 효율을 함께 제공하는 방식.

1. 나머지 기반 검출 : 송신측이 나머지를 FCS로 부착 → 수신측이 같은 생성 다항식으로 다시 나누어 0인지 확인 → 비트 왜곡 여부를 즉시 판정.
2. 군집 오류 검출 : 연속된 비트 오류를 높은 확률로 검출 → 이더넷과 무선 링크처럼 오류가 뭉쳐 발생하는 환경에 적합.
3. XOR 기반 구현 : 모듈로-2 연산은 XOR (Exclusive OR, 배타적 논리합) 회로와 시프트 레지스터로 구현 → 고속 전송에서도 처리 지연이 낮음.

```text
[ 송신측 ]

데이터 M = 101001
   ↓ 생성 다항식 차수 r = 3 만큼 0 추가
101001000
   ↓ G = 1101 로 모듈로-2 나눗셈
나머지 R = 001
   ↓ 데이터 뒤에 R 부착
전송 프레임 T = 101001001
```

```text
[ 수신측 ]

수신 프레임 T' 를 같은 G 로 나눔
   ↓
나머지 = 0 : 정상 수락
나머지 ≠ 0 : 비트 왜곡으로 보고 폐기
```

## Ⅲ. CRC의 구조 (수학 모델)

- 핵심 요약 : 메시지 다항식에 r차 항을 곱한 뒤 생성 다항식으로 나눈 나머지가 체크 비트가 되는 구조.
- **모듈로-2** (Modulo-2) **연산** : 자리올림과 자리빌림이 없는 연산으로, 덧셈과 뺄셈이 모두 XOR과 같다.
- **생성 다항식** (Generator Polynomial) G(x) : 최고차와 최저차 계수가 항상 1인 r차 다항식.
- 수식 : M(x)에 x의 r제곱을 곱한 뒤 G(x)로 나눈 나머지를 R(x)라 하면, 전송 다항식은 T(x) = M(x)·x^r + R(x)이다.
- 수신 판정 : T(x)를 G(x)로 나눈 나머지가 0이면 오류가 없다고 판단한다.

## Ⅳ. 표준 생성 다항식과 검출 능력 비교

- 핵심 요약 : 표준마다 다항식과 FCS 길이가 정해져 있으며, 길이가 길수록 검출 확률이 높아져 적용 분야가 나뉜다.

| 표준 명칭 | 생성 다항식 G(x) | FCS 길이 | 적용 분야 |
| --- | --- | --- | --- |
| CRC-16-CCITT | x^16 + x^12 + x^5 + 1 | 16비트 | X.25, HDLC, 블루투스 |
| CRC-16-IBM | x^16 + x^15 + x^2 + 1 | 16비트 | MODBUS RTU, USB 토큰 |
| CRC-32 (IEEE 802.3) | x^32 + x^26 + x^23 + x^22 + x^16 + x^12 + x^11 + x^10 + x^8 + x^7 + x^5 + x^4 + x^2 + x + 1 | 32비트 | 이더넷 FCS, Wi-Fi, ZIP, PNG, SATA |
| CRC-64-ECMA | x^64 + x^62 + x^57 + x^55 + ... + 1 | 64비트 | 대용량 저장 장치와 데이터 블록 무결성 |

- 검출 능력 :
  1. 생성 다항식의 차수 r 이하의 모든 단일 및 연속 군집 오류를 100% 검출한다.
  2. 길이 r+1인 군집 오류는 약 1-(1/2)^(r-1)의 확률로 검출하며, CRC-32는 이 값이 매우 높다.
  3. G(x)가 x+1을 인수로 가지면 모든 홀수 개의 비트 반전 오류를 검출한다.
- 선택 기준 : 링크 계층 프레임에는 표준이 정한 다항식을 그대로 쓰고, 저장 블록처럼 데이터가 큰 경우에는 FCS가 긴 다항식을 고른다.

## Ⅴ. CRC의 한계와 방안

- 핵심 요약 : 검출만 가능하고 암호학적 강도가 없다는 두 가지 한계가 있으며, 정정 부호와 암호 해시로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 오류 정정 불가 | 1비트 오류에도 프레임 전체를 폐기하여 재전송이 많아지고 긴 지연 채널에서 부하 증가 | FEC(Forward Error Correction, 해밍 부호, 리드-솔로몬, LDPC)를 결합하여 수신측에서 직접 정정 | 재전송률, 정정 성공률 |
| 선형 구조로 인한 위변조 취약성 | CRC는 키를 쓰지 않는 체크섬이므로 공격자가 값을 맞춰 데이터를 위조할 수 있음 | 보안이 필요한 무결성 검증은 HMAC-SHA256 같은 암호학적 해시 또는 전자서명 사용 | 무결성 검증 실패 건수 |

## Ⅵ. CRC 적용 및 발전을 위한 기술사적 제언

- 핵심 요약 : CRC 가속, 종단 간 무결성 보호, FEC 결합을 계층별로 설계하는 방향.

1. 고속 네트워크 스위치와 DPDK (Data Plane Development Kit) 환경에서는 CPU의 SIMD (Single Instruction, Multiple Data) 명령과 PCLMULQDQ 명령을 활용하여 CRC 연산을 하드웨어 가속으로 처리하는 것이 바람직하다.
2. 메모리, 스위치, 저장 장치 컨트롤러를 거치는 동안 생기는 무음 데이터 손상(Silent Data Corruption)을 막기 위해, 저장 구간에는 T10 DIF (Data Integrity Field) 같은 블록 단위 보호 정보를 끝까지 유지하는 설계가 필요하다.
3. AI 데이터센터의 고속 전송 구간에서는 저지연 FEC와 CRC를 나란히 배치하여 재전송을 줄이면서도 오류 검출을 놓치지 않는 파이프라인을 구성해야 한다.

## Ⅶ. 결론

- 핵심 요약 : CRC는 나눗셈 나머지로 비트 왜곡을 빠르게 검출하는 링크와 저장 무결성의 기본 기법.
- 시사점 : 검출 전용이라는 성격이 분명하므로, 정정은 FEC가, 위변조 방어는 암호 해시가 맡도록 계층을 나누는 설계가 핵심이다.
