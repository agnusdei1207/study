## 연관 키워드

- CRC(Cyclic Redundancy Check), 생성 다항식(Generator Polynomial), 모듈로-2(Modulo-2) 연산, FCS(Frame Check Sequence)
- 군집 오류(Burst Error), 패리티 검사(Parity Check), 체크섬(Checksum), LFSR(Linear Feedback Shift Register)
- CRC-16-CCITT, CRC-32, CRC-64-ECMA, T10 DIF(Data Integrity Field), HMAC(Hash-based Message Authentication Code)

## Ⅰ. CRC의 개요

- 핵심 요약 : 데이터를 약속된 다항식으로 나눈 나머지를 체크 비트로 붙여 비트 왜곡을 검출하는 기법.
- 개념 : 송신 데이터를 **생성 다항식** (Generator Polynomial, 송수신 양측이 공유하는 나눗셈용 다항식)으로 나눈 나머지를 프레임 끝에 덧붙이고, 수신측이 같은 나눗셈의 나머지 0 여부로 오류를 판정하는 **순환 중복 검사** (CRC, Cyclic Redundancy Check).
- 배경 및 필요성 : **패리티 검사** (Parity Check, 비트 1의 개수 홀짝만 확인하는 가장 단순한 검사)는 짝수 개 비트가 동시에 뒤집히면 오류를 놓치고, 단순 합산 **체크섬** (Checksum, 데이터 값의 합을 검사 코드로 보내는 방식)은 값의 순서가 바뀐 오류를 잡지 못함. 연속 비트 오류인 **군집 오류** (Burst Error)에 강한 검출 수단이 링크 계층 신뢰성의 전제가 됨.
- 주요 목적 : 이더넷 프레임과 저장 블록의 무결성 검증, 하드웨어 회로로 실현 가능한 고속 오류 검출.

## Ⅱ. CRC의 특징 및 장점

- 핵심 요약 : 나눗셈 나머지라는 단순 수학 구조가 높은 검출 능력과 하드웨어 구현 효율을 동시에 제공하는 방식.

1. 나머지 판정 구조 : 송신측이 나머지를 **FCS** (Frame Check Sequence, 프레임 검사 비트열)로 부착하고 수신측이 재나눗셈의 나머지 0 여부를 확인 → 오류 프레임의 즉시 폐기 판정.
2. 군집 오류 검출 : 생성 다항식 차수 이하의 연속 오류를 전부 검출 → 오류가 뭉쳐 발생하는 이더넷·무선 링크에 적합.
3. 회로 구현 효율 : 나눗셈이 XOR(Exclusive OR, 배타적 논리합)과 시프트뿐이므로 **LFSR** (Linear Feedback Shift Register, 선형 피드백 시프트 레지스터) 회로로 실현 → 고속 전송에서도 낮은 처리 지연.
4. 상호운용 보장 : 다항식과 파라미터가 표준으로 고정 → 이기종 장비 간 동일한 판정 결과 확보.

## Ⅲ. CRC의 구조 (수학 모델)

- 핵심 요약 : 메시지 다항식에 차수만큼 자릿수를 이동한 뒤 생성 다항식으로 나눈 나머지가 체크 비트가 되는 구조.
- **모듈로-2 연산** (Modulo-2 Arithmetic, 자리올림·자리내림이 없어 덧셈과 뺄셈이 모두 XOR과 같은 연산) : CRC 나눗셈의 기본 연산.
- 생성 다항식 G(x) : 최고차항과 상수항의 계수가 1인 다항식으로 검출 능력을 결정하는 약속 값.
- 수식 : 전송 다항식은 T(x) = M(x)·x^r + R(x)이며, R(x)는 M(x)·x^r을 G(x)로 나눈 나머지, r은 G(x)의 차수.
- 수신 판정 : T(x)를 G(x)로 나눈 나머지가 0이면 정상, 0이 아니면 오류.

```text
[ 송신측 FCS 생성 절차 ]

메시지에 x^r 곱셈 (하위 r비트 0 추가)
   ↓
G(x)로 모듈로-2 나눗셈
   ↓ XOR 반복
나머지 R(x) 산출
   ↓ 부착
전송 프레임 T(x) 확정
```

```text
[ 수신측 오류 판정 흐름 ]

수신 프레임 T'(x) 입력
   ↓ 동일 G(x)로 나눗셈
나머지 = 0 : 정상 수락
나머지 ≠ 0 : 비트 왜곡으로 폐기
```

## Ⅳ. 표준 생성 다항식과 검출 능력의 비교

- 핵심 요약 : FCS 길이와 다항식 구조에 따라 검출 능력과 적용 분야가 나뉘므로 표준 규격의 약속을 그대로 따르는 것이 원칙.

| 표준 명칭 | 생성 다항식 G(x) | FCS 길이 | 적용 분야 |
| --- | --- | --- | --- |
| CRC-16-CCITT | x^16 + x^12 + x^5 + 1 | 16비트 | HDLC(High-level Data Link Control), X.25 |
| CRC-16-IBM | x^16 + x^15 + x^2 + 1 | 16비트 | MODBUS RTU, USB(Universal Serial Bus) |
| CRC-32 (IEEE(Institute of Electrical and Electronics Engineers) 802.3) | x^32 + x^26 + x^23 + x^22 + x^16 + x^12 + x^11 + x^10 + x^8 + x^7 + x^5 + x^4 + x^2 + x + 1 | 32비트 | 이더넷 FCS, Wi-Fi, ZIP, PNG(Portable Network Graphics) |
| CRC-64-ECMA | x^64 + x^62 + x^57 + x^55 + … + 1 | 64비트 | 대용량 저장 블록 무결성 |

- 검출 능력 :
  1. 차수 r 이하 길이의 군집 오류 : 전부 검출.
  2. 길이 r+1인 군집 오류 : 2^-(r-1)의 확률만 통과.
  3. 그보다 긴 군집 오류 : 2^-r의 확률만 통과.
  4. G(x)가 (x+1)을 인수로 가지면 홀수 개 비트 오류 전부 검출.
  5. 상수항 1 보유 시 단일 비트 오류 전부 검출.
- 선택 기준 :
  1. 통신 규격은 표준이 지정한 다항식과 파라미터(초기값, 입출력 비트 반사)를 그대로 적용.
  2. 저장 블록처럼 데이터 단위가 큰 경우 FCS가 긴 다항식으로 잔여 오류율 축소.
  3. 자원이 작은 임베디드는 짧은 FCS로 연산 부담 절감.

## Ⅴ. CRC의 한계와 방안

- 핵심 요약 : 잔여 오류 통과, 위변조 내성 부재, 고속 처리 부담의 세 한계를 용도별 설계로 분리 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 초과 길이 군집 오류의 통과 | FCS 길이가 짧으면 긴 오류열이 확률적으로 검출을 우회 | 데이터 단위에 맞는 FCS 길이 상향, 오류 환경에 따른 다항식 재선택 | 잔여 오류율 |
| 키 없는 선형 구조의 위변조 취약 | 데이터와 FCS를 함께 다시 계산하면 위조 가능 | 보안 무결성은 **HMAC** (Hash-based Message Authentication Code, 해시 기반 메시지 인증 코드) 등 암호학적 수단으로 역할 분리 | 무결성 검증 실패 건수 |
| 고속 링크의 연산 부담 | 소프트웨어 비트 연산은 처리율 병목 | 룩업 테이블과 SIMD(Single Instruction, Multiple Data)·전용 명령 기반 하드웨어 가속 | 처리 지연, CPU(Central Processing Unit) 점유율 |

## Ⅵ. CRC에 대한 기술사적 제언

- 핵심 요약 : 발주 규격의 파라미터 명시, 저장 구간의 종단 무결성 유지, 검출과 가속의 계층별 배치를 제안.

1. 조달·발주 조직은 장비 도입 규격에 다항식, 초기값, 비트 반사 여부 같은 CRC 파라미터를 명시하여 이기종 장비 간 판정 불일치를 사전에 차단해야 한다.
2. 스토리지 운영 조직은 블록 단위 무결성 필드인 T10 DIF(Data Integrity Field)를 컨트롤러 구간 전체에서 유지하여 장비 내부의 무음 데이터 손상(Silent Data Corruption)을 검출 체계에 포함해야 한다.
3. 네트워크 설계 조직은 고속 전송 구간에서 오류 검출과 전송 가속을 나누어 배치하고, CRC 연산은 전용 회로·명령으로 위임하여 처리율을 확보해야 한다.

## Ⅶ. 결론

- 핵심 요약 : CRC는 나눗셈 나머지 구조로 비트 왜곡을 빠르게 검출하는 링크·저장 무결성의 기본 기법.
- 검출 전용이라는 성격이 명확하므로 파라미터의 표준 준수와 암호 무결성과의 역할 분리가 설계의 핵심 조건이 됨.
