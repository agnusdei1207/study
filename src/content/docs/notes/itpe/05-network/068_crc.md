## 30초 인출

- 본질: 단순 패리티 비트나 체크섬 방식이 짝수 개의 비트 반전이나 연속된 잡음(연집 오류)을 걸러내지 못하는 취약점
- 메커니즘: 데이터 비트열을 생성 다항식으로 모듈로-2(XOR) 나눗셈하여 구한 나머지(FCS)를 패킷 끝에 붙여 수신단에서 무오류 검증

## 핵심 용어

- 모듈로-2 연산(Modulo-2 Arithmetic): 자리올림(Carry)이나 빌림(Borrow)을 고려하지 않고 순수하게 비트 간 배타적 논리합(XOR)만을 수행하는 이진 다항식 연산
- 생성 다항식($G(x)$, Generator Polynomial): 송수신 양단이 사전에 약속한 $r$차수의 이진 다항식으로, 최고차항과 최저차항(상수항 $x^0 = 1$)이 반드시 1이어야 모든 단일 비트 오류 검출 가능
- 연집 오류(Burst Error): 통신 선로의 순간적 충격 잡음(Impulse Noise) 등으로 인해 연속된 다수의 비트가 한꺼번에 훼손되는 오류로, CRC는 다항식 차수 $r$ 이하의 모든 연집 오류를 100% 검출

## 1교시 10점 답안

### 정의·목적

- 정의: CRC은/는 데이터 비트열을 생성 다항식으로 모듈로-2(XOR) 나눗셈하여 구한 나머지(FCS)를 패킷 끝에 붙여 수신단에서 무오류 검증 방식이다.
- 목적: 고신뢰성 에러 검출 및 단순 하드웨어 회로 구현 달성에 기여한다.

### 핵심 구조와 작동

```text
[ CRC 송신단 부호화 및 수신단 오류 검증 원리 ]

1. 송신단 (FCS 생성) :
   - 원본 데이터 M(x) 뒤에 생성 다항식 차수(r)만큼 '0'을 r개 덧붙임
   - 생성 다항식 G(x)로 Modulo-2 나눗셈 (뺄셈 대신 XOR 연산)
   - 나누고 남은 r비트 나머지 R(x)가 바로 FCS(Frame Check Sequence)!
   - 전송 프레임 = [ 원본 데이터 M(x) ] + [ FCS R(x) ]

2. 수신단 (오류 검출) :
   - 수신된 전체 프레임을 동일한 생성 다항식 G(x)로 Modulo-2 나눗셈
   - [ 나머지 == 0 ]  ──> 오류 없음 (정상 수락)
   - [ 나머지 != 0 ]  ──> 전송 중 비트 반전 오류 발생! (프레임 즉시 폐기)

3. 하드웨어 구현 (LFSR : Linear Feedback Shift Register) :
   입력 비트열 ──>(+)──[ 플립플롭 ]──>(+)──[ 플립플롭 ]──> 출력
                   ▲                    ▲
                   └──── G(x) 피드백 ───┘ (XOR 게이트와 레지스터로 구성)
```

## 2~4교시 25점 답안

### Ⅰ. 핵심 구조와 작동

```text
[ CRC 송신단 부호화 및 수신단 오류 검증 원리 ]

1. 송신단 (FCS 생성) :
   - 원본 데이터 M(x) 뒤에 생성 다항식 차수(r)만큼 '0'을 r개 덧붙임
   - 생성 다항식 G(x)로 Modulo-2 나눗셈 (뺄셈 대신 XOR 연산)
   - 나누고 남은 r비트 나머지 R(x)가 바로 FCS(Frame Check Sequence)!
   - 전송 프레임 = [ 원본 데이터 M(x) ] + [ FCS R(x) ]

2. 수신단 (오류 검출) :
   - 수신된 전체 프레임을 동일한 생성 다항식 G(x)로 Modulo-2 나눗셈
   - [ 나머지 == 0 ]  ──> 오류 없음 (정상 수락)
   - [ 나머지 != 0 ]  ──> 전송 중 비트 반전 오류 발생! (프레임 즉시 폐기)

3. 하드웨어 구현 (LFSR : Linear Feedback Shift Register) :
   입력 비트열 ──>(+)──[ 플립플롭 ]──>(+)──[ 플립플롭 ]──> 출력
                   ▲                    ▲
                   └──── G(x) 피드백 ───┘ (XOR 게이트와 레지스터로 구성)
```

### Ⅱ. 핵심 특성

- 완벽한 수학적 다항식 설계가 만드는 압도적 오류 검출력: 생성 다항식 $G(x)$에 $(x+1)$을 인수로 포함하면 홀수 개의 모든 비트 오류를 100% 잡아내며, CRC-32는 32비트 이하의 모든 연집 오류를 100%, 그 이상의 오류도 99.99999997% 확률로 검출
- 소프트웨어로는 무겁지만 하드웨어로는 극도로 가벼운 구조: CPU 소프트웨어로 비트 단위 나눗셈 루프를 돌리면 성능이 크게 떨어지지만, 하드웨어 계층에서는 몇 개의 플립플롭과 XOR 게이트(LFSR)만으로 클록 사이클마다 패킷이 통과하면서 지연 없이 즉시 FCS가 계산됨
- 에러를 검출(Detection)만 할 뿐 정정(Correction)하지 않는 경제적 분업: 통신 선로가 안정된 환경에서는 복잡한 수학적 오류 정정 부호(해밍 코드 등)로 페이로드를 낭비하는 대신, 가벼운 CRC로 에러 패킷을 즉시 버리고 L4 TCP에 재전송을 맡기는 것이 전체 처리량에 유리

### Ⅲ. 관련 개념과 구분

- 체크섬(Checksum) vs CRC: 체크섬은 16비트 단위로 단순 1의 보수 덧셈을 수행(L3 IP, L4 TCP 헤더 보호, 연산 가벼움, 오류 검출력 낮음) / CRC는 비트 다항식 나눗셈을 수행(L2 이더넷 FCS, 연집 오류 검출력 우수, 하드웨어 특화)

### Ⅳ. 적용 문제와 대응

- 적용 상황: 10Gbps 고속 이더넷 인터페이스 카드(NIC)의 패킷 처리
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 고속 통신 시 CPU의 CRC-32 계산 부하 급증 | 운영체제 네트워크 스택에서 소프트웨어 루프로 Modulo-2 계산 수행 | NIC 하드웨어의 체크섬/CRC 오프로딩(Checksum Offload) 활성화 | 호스트 CPU 점유율 0% 유지 및 회선 속도(Line Rate) 10Gbps 달성 |
| 전송 중 악의적인 패킷 변조를 감지하지 못함 | CRC는 무작위 잡음 검출용이며 암호학적 해시가 아니므로 공격자가 데이터와 FCS를 동시 조작 가능 | 상위 계층에 HMAC-SHA256 또는 TLS 암호화 무결성 계층 결합 | 전송 선로 물리 에러는 CRC로, 악의적 위변조는 HMAC으로 이중 방어 |
