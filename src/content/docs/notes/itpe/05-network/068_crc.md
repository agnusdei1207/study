네트워크 → 링크 계층 오류 검출 및 신뢰성 전송 → **CRC(Cyclic Redundancy Check)**

## 30초 인출

- 본질: **CRC(Cyclic Redundancy Check)** : 통신 및 스토리지 분야에서 비트 전송 오류를 검출하기 위해 데이터 비트열을 생성 다항식(Generator Polynomial)으로 모듈로-2(XOR) 나눗셈을 수행하여 그 나머지를 FCS로 프레임에 부가하는 순환 중복 검사 기술
- 메커니즘: 송신단에서 데이터 $M(x) \cdot x^r$을 생성 다항식 $G(x)$로 나눈 나머지 $R(x)$(FCS)를 덧붙여 전송하고, 수신단은 수신 프레임을 동일한 $G(x)$로 나누어 나머지가 0인지 검사하여 오류 판별
- 통찰: LFSR 기반의 초고속 하드웨어 연산과 강력한 연집 오류 검출력 이면에 선형성에 따른 악의적 위변조 탐지 불가 및 오류 정정 불능 한계 극복을 위해 HMAC 서명과 HARQ 재전송 체계 구축 필수

<details>
<summary>핵심 용어</summary>

- **생성 다항식 (Generator Polynomial, $G(x)$)** : 송수신 양단이 사전에 약속하여 모듈로-2 나눗셈의 제수로 사용하는 $r$차 기약 다항식
- **모듈로-2 연산 (Modulo-2 Arithmetic)** : 자리올림(Carry)이나 자리빌림(Borrow)이 전혀 없이 비트 단위 배타적 논리합(XOR)으로만 수행되는 이진 다항식 연산
- **FCS (Frame Check Sequence)** : 모듈로-2 나눗셈 결과 발생한 $r$비트의 나머지 다항식 $R(x)$로 프레임의 맨 뒤에 부가되는 검사 비트열
- **LFSR (Linear Feedback Shift Register)** : 직렬 비트 스트림을 클록 단위로 시프트하면서 특정 탭(Tap)의 출력을 XOR 피드백하여 하드웨어로 CRC를 즉각 연산하는 회로
- **연집 오류 (Burst Error)** : 물리적 노이즈나 페이딩에 의해 연속된 여러 비트가 한꺼번에 반전 손상되는 오류 형태

</details>

## 2~4교시 25점 답안

## Ⅰ. CRC의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 전송할 데이터 비트열 뒤에 $r$비트의 0을 덧붙인 후 미리 정의된 $r$차 이진 생성 다항식 $G(x)$로 모듈로-2 나눗셈을 수행하여 도출된 나머지(FCS)를 프레임 끝에 결합 전송하는 강력한 오류 검출 기법 |
| 목적 | 유무선 채널 전송 중 잡음, 간섭으로 인해 발생하는 단일 비트, 이중 비트, 홀수 비트 및 연집 오류(Burst Error)를 하드웨어 수준에서 초고속 검출 |

## Ⅱ. CRC의 특징 및 수학적 연산 원리

| 특징 항목 | 세부 원리 및 수식 명세 |
|---|---|
| **모듈로-2 산술 연산** | 가산과 감산이 동일하게 XOR 연산($0 \oplus 0 = 0, 0 \oplus 1 = 1, 1 \oplus 1 = 0$)으로 수행되며 캐리/보로우 없음 |
| **송신 인코딩 수식** | 송신 프레임 $T(x) = M(x) \cdot x^r \oplus R(x)$, 여기서 $R(x) = \text{remainder}\left[\frac{M(x) \cdot x^r}{G(x)}\right]$ |
| **수신 디코딩 판정** | 수신 프레임 $T'(x) = T(x) \oplus E(x)$를 $G(x)$로 나눈 나머지 산출; 나머지가 0이면 무오류 합격, 0이 아니면 오류 검출 |
| **오류 검출 범위 보장** | - $G(x)$가 $x^0$ 항을 포함하면: 모든 단일 비트 오류($E(x)=x^i$) 100% 검출<br/>- $G(x)$가 $(x+1)$을 인수로 가지면: 모든 홀수 개 비트 오류 100% 검출<br/>- 차수 $r$ 이하의 모든 연집 오류(Burst Error): 100% 무조건 검출 |

## Ⅲ. CRC 인코딩/디코딩 아키텍처 및 LFSR 하드웨어 구현 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ CRC 모듈로-2 나눗셈 및 LFSR 하드웨어 회로 ]         │
│                                                                        │
│   [송신측 모듈로-2 나눗셈 과정 예시]                                    │
│   - 데이터 M = 101001, 생성 다항식 G = 1101 (3차, r=3)                 │
│   - M 뒤에 0을 3개 추가: 101001000                                     │
│                                                                        │
│        1101 ) 101001000 ( 111101 (몫)                                  │
│               1101                                                     │
│               ────                                                     │
│                1110                                                    │
│                1101                                                    │
│                ────                                                    │
│                 0111 -> 1110 ... (XOR 반복) -> 나머지 R = 001 (FCS)    │
│   * 최종 송신 프레임: 101001 001                                       │
│                                                                        │
│   [수신측 LFSR (선형 피드백 시프트 레지스터) 하드웨어 회로]            │
│   입력 비트열 ──► (XOR) ──► [Flip-Flop 0] ──► [Flip-Flop 1] ──► ...    │
│                     ▲                               │                  │
│                     └────────── (탭 피드백) ────────┘                  │
│   * 모든 비트 통과 후 레지스터 내부 잔여값이 모두 0이면 정상 수신 판정 │
└────────────────────────────────────────────────────────────────────────┘
```

| 처리 단계 | 주관 엔터티 | 세부 수행 메커니즘 |
|---|---|---|
| **1. 비트 패딩** | 송신단 전처리 | $k$비트 원본 데이터 뒤에 생성 다항식의 최고 차수 $r$개만큼 '0' 비트 패딩 ($M(x) \cdot x^r$) |
| **2. 다항식 나눗셈** | 송신 LFSR 엔진 | 패딩된 비트열을 생성 다항식 $G(x)$로 비트 단위 XOR 나눗셈하여 $r$비트 나머지 $R(x)$ 산출 |
| **3. 프레임 합성** | 송신 MAC 계층 | 원본 데이터의 패딩된 0 자리에 나머지 $R(x)$를 덮어써서 FCS 완성 후 물리 계층 송출 |
| **4. 수신 검증 판정**| 수신 LFSR 엔진 | 수신된 프레임 전체를 동일한 $G(x)$로 나눔; 나머지가 '0'이면 프레임 승인, '0'이 아니면 즉시 폐기 |

## Ⅳ. 패리티 검사 vs 인터넷 체크섬 vs CRC 비교

| 비교 항목 | 패리티 검사 (Parity Check) | 인터넷 체크섬 (Internet Checksum) | 순환 중복 검사 (CRC) |
|---|---|---|---|
| **연산 메커니즘** | 단순 비트 1의 개수 홀짝 검사 | 16비트 워드 단위 1의 보수 덧셈 | **이진 다항식 모듈로-2 나눗셈 (XOR)** |
| **오류 검출 능력**| 극히 낮음 (2개 비트 오류 시 미검출)| 중간 (비트 반전, 바이트 순서 변경에 취약)| **매우 높음 (모든 단일/홀수/연집 오류 검출)** |
| **하드웨어 구현** | 단순 XOR 게이트 1개 | CPU 소프트웨어 연산에 최적화 | **LFSR 회로로 초고속 와이어스피드 처리** |
| **오류 정정 여부**| 불가 (2차원 패리티만 1비트 정정) | 불가 (검출 전용) | 불가 (검출 전용, 상위 재전송 요구) |
| **주요 적용 계층**| 컴퓨터 내부 버스, 시리얼 통신 | 전송 계층 (TCP, UDP, IPv4 헤더) | **데이터링크 계층 (이더넷, Wi-Fi, HDLC)** |

## Ⅴ. CRC의 핵심 엔지니어링 한계와 방안

| 한계 | 방안 |
|---|---|
| CRC는 선형 대수학적(Linearity) 특성을 갖는 비암호학적 해시이므로, 중간자 공격(MITM)자가 데이터 페이로드를 악의적으로 변조한 뒤 변조된 데이터에 맞춰 CRC를 재계산하여 송출하면 수신단에서 위변조를 전혀 감지하지 못하는 무결성 붕괴 발생 | 링크 계층 CRC는 채널 노이즈 검출 전용으로 한정하고, 상위 보안 계층(TLS, IPsec)에서 사전 공유 비밀키 기반의 메시지 인증 코드(HMAC-SHA256) 또는 타원곡선 전자서명(ECDSA)을 결합하여 암호학적 위변조 원천 차단 |
| CRC는 오류의 존재 유무만 검출할 뿐 오류가 발생한 비트의 위치를 특정하거나 복원할 수 없어 단 1비트 오류에도 거대한 이더넷 프레임 전체를 폐기해야 하므로 패킷 손실률이 높은 장거리 무선/위성 통신에서 막대한 재전송 대역폭 낭비 발생 | 전송 프레임 전단에 해밍 부호, 리드 솔로몬, 또는 LDPC 등 순방향 오류 정정(FEC) 코드를 결합하여 경미한 비트 오류는 수신단에서 즉시 자체 복구하고, 복구 불가한 프레임만 CRC로 드롭 후 재전송 요청하는 HARQ 기법 적용 |
| 100Gbps/400Gbps 초고속 이더넷 인터페이스에서 단일 비트 직렬 LFSR 회로로는 클록 주파수 한계(수백 MHz)로 인해 와이어 스피드 실시간 CRC 연산 불가 | 32비트 또는 64비트 병렬 데이터를 단일 클록 사이클 내에서 일괄 모듈로-2 연산하는 병렬화된 LFSR 매트릭스 룩업 테이블(LUT) 하드웨어 ASIC 설계 적용 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
네트워크 프로토콜 및 임베디드 통신 프레임 설계 시, 데이터 크기에 적합한 표준 다항식을 채택해야 하며(이더넷 및 Wi-Fi는 IEEE 802.3 CRC-32 필수 채택), 송수신 시스템 간 엔디언(Little-Endian vs Big-Endian) 및 비트 역전(Bit Reflection) 플래그 설정 불일치로 인한 오검출 사고를 방지하기 위해 상호 연동 적합성 시험 선행 권장

### 3. 기술 유형 및 비교 평가
| 표준 규격 | 생성 다항식 비트수 | 대표 생성 다항식 (Hex) | 연집 오류 검출 보장 길이 | 주요 적용 시스템 |
|---|---|---|---|---|
| **CRC-8** | 8 bits | $x^8 + x^2 + x + 1$ (`0x07`) | 최대 8비트 이하 연집 오류 | ATM 셀 헤더 (HEC), 1-Wire 버스 |
| **CRC-16** | 16 bits | $x^{16} + x^{15} + x^2 + 1$ (IBM, `0x8005`)| 최대 16비트 이하 연집 오류 | Modbus, USB 토큰, HDLC/프레임릴레이 |
| **CRC-32** | 32 bits | IEEE 802.3 규격 (`0x04C11DB7`) | 최대 32비트 이하 연집 오류 | **IEEE 802.3 이더넷, Wi-Fi, ZIP, PNG** |
| **CRC-64** | 64 bits | ECMA-182 규격 (`0x42F0E1EBA9EA3693`)| 최대 64비트 이하 연집 오류 | 대용량 분산 파일시스템, Redis 캐시 |
