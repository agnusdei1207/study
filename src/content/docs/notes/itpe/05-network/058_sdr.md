## Ⅰ. SDR(Software Defined Radio)의 개요

- 개념 : 전통적으로 믹서, 필터, 변조기, 복조기 등 **고정 하드웨어(ASIC)** 회로로 구현되던 무선 통신 신호 처리 기능을 **범용 프로세서(DSP, FPGA, CPU/GPU)** 상의 소프트웨어 프로그래밍으로 대체 구현하는 무선 통신 기술.
- 배경 및 필요성 : 4G, 5G, Wi-Fi, 블루투스, 위성 등 다양한 무선 통신 표준이 공존하는 환경에서 새로운 표준이 등장할 때마다 하드웨어를 전면 재설계·교체해야 하는 막대한 비용과 유연성 부재 극복 필요.
- 핵심 목적 : 펌웨어/SW 업데이트만으로 **다중 표준(Multi-Standard)** 지원, 기지국 하드웨어 범용화를 통한 **TCO** 절감 및 인지 무선(Cognitive Radio)으로의 진화 기반 제공.

## Ⅱ. SDR의 핵심 아키텍처 및 동작 메커니즘

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ SDR 송수신 하드웨어/소프트웨어 아키텍처 ]           │
│                                                                        │
│   [ RF 전단부 (RF Front-End: 고정 하드웨어) ]                          │
│   안테나 ──► 저잡음증폭기(LNA) ──► 주파수 하향 혼합기(Mixer) ──► 필터  │
│   (광대역)     (수신 신호 증폭)        (기저대역/IF 변환)               │
│                                           │                            │
│   [ 데이터 변환 계층 (Data Conversion) ]  ▼                            │
│   초고속 ADC (아날로그-디지털 변환) / 고속 DAC (디지털-아날로그 변환)   │
│                                           │ (디지털 IQ 샘플 데이터)   │
│   [ 소프트웨어 처리 엔진 (Digital Baseband) ] ▼                         │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ FPGA / DSP 계층 : 고속 병렬 처리 (DDC/DUC, 동기화, 채널화)    │   │
│   ├────────────────────────────────────────────────────────────────┤   │
│   │ GPP (범용 CPU / GPU) 계층 : GNU Radio, OAI, srsRAN, AI 추론   │   │
│   │  - 채널 코딩/디코딩 (LDPC/Polar)   - 변복조 (QAM, OFDM)        │   │
│   │  - 프로토콜 스택 처리 (MAC, RLC, PDCP, IP 라우팅)              │   │
│   └────────────────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────────────────┘
```

- **디지털 직접 변환 (Direct Digital Conversion)** : 고속 ADC를 통해 IF(중간 주파수) 또는 RF 대역에서 바로 아날로그 신호를 양자화하여 디지털 기저대역(Baseband)으로 직결.
- **DDC (Digital Down Converter) / DUC (Digital Up Converter)** : 디지털 영역에서 수치 제어 발진기(NCO)와 디지털 필터를 이용해 주파수 천이 및 데시메이션(Decimation) 수행.
- **소프트웨어 모듈화 처리** : 변복조, 등화(Equalization), 오류 정정 부호화 알고리즘이 C/C++, Python 라이브러리(GNU Radio, srsRAN) 블록으로 체인 연결되어 유연한 파이프라인 구성.

## Ⅲ. SDR의 세부 구성 요소 및 하드웨어 무선기와의 비교 분석

| 비교 항목 | 전통적 무선 하드웨어 (Hardware Radio) | 소프트웨어 정의 라디오 (SDR) |
|---|---|---|
| 기능 구현 | 고정 ASIC 및 아날로그 아날로그 믹서/필터 | 범용 프로세서(FPGA, DSP, GPP) 소프트웨어 |
| 표준 변경 | 하드웨어 보드 전면 재설계 및 교체 | 소프트웨어 알고리즘 및 펌웨어 다운로드 |
| 다중 대역 수용 | 협대역 전용 회로로 한정 대역만 처리 | 광대역 RF 전단과 디지털 튜닝으로 전 대역 수용 |
| 개발 주기 | 수개월~수년 (실리콘 팹 제작 필수) | 수일~수주 (소프트웨어 코드 수정 및 컴파일) |
| 전력 소모 | 특정 기능 전용화로 전력 효율 극대화 | 범용 프로세싱 오버헤드로 전력 소모 상대적 큼 |
| 단위 원가 | 대량 생산 시 칩셋 단가 매우 저렴 | 고성능 ADC/DAC 및 고사양 프로세서로 단가 높음 |

- **인지 무선 (Cognitive Radio: CR)** : SDR 플랫폼 위에 스펙트럼 센싱(Spectrum Sensing) 엔진을 결합하여, 유휴 주파수 대역(White Space)을 실시간 자동 탐색하고 동적으로 간섭 없이 통신하는 지능형 기술로 진화.

## Ⅳ. SDR의 주요 한계점 및 해결 방안

- 초고속 ADC/DAC의 샘플링 속도 및 분해능(Resolution) 한계 :
  - 한계점 : 광대역(수백 MHz~수 GHz) 고주파 신호를 왜곡 없이 디지털화하기 위한 초고속 ADC의 양자화 잡음 및 전력 소모 폭증.
  - 해결 방안 : 대역통과 샘플링(Bandpass Sampling), 서브 나이키스트 압축 센싱(Compressive Sensing) 도입 및 RFSoC(RF-Sampling SoC) 칩 채택.
- 범용 CPU 상에서의 실시간성(Real-Time) 및 지연 시간 보장 난제 :
  - 한계점 : 범용 OS(Linux 등)의 비결정론적 스케줄링 및 인터럽트 지연으로 인해 5G NR의 서브밀리초(0.5ms 이하) 슬롯 타이밍 충족 실패.
  - 해결 방안 : 실시간 리눅스 커널(PREEMPT_RT), DPDK(Data Plane Development Kit)를 통한 커널 바이패스, GPU 가속(NVIDIA Aerial) 인라인 오프로딩.

## Ⅴ. SDR 적용 및 발전을 위한 기술사적 제언

- 오픈랜(O-RAN) 생태계의 핵심 기반 기술화 : 통신 장비 벤더 독점 구조를 타파하고, 범용 COTS(Commercial Off-The-Shelf) 서버 상에 vRAN/Cloud-RAN 소프트웨어를 구동하는 통신사 인프라 표준 주도.
- 국방 전술 통신망의 다기능 단일화(TMMR) : 육·해·공군이 서로 다른 무전기를 사용하던 군 통신 환경을 SDR 기반 전술 다대역 다기능 무전기로 단일화하여 전시 합동 작전 상호운용성 보장.
- AI 기반 뉴럴 리시버(Neural Receiver) 융합 : 기존의 복잡한 채널 추정, 등화기, 복조 알고리즘을 단일 딥러닝 신경망으로 대체하는 AI-SDR 아키텍처를 선제 연구하여 무선 물리 계층 성능 극대화.
