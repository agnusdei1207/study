## 30초 인출

- 본질: **ARQ** : 송신 데이터의 손실·오류를 확인 응답과 재전송으로 복구하는 오류 제어 방식
- 메커니즘: 순서 번호·ACK·타이머로 미확인 데이터를 추적하고 필요할 때 재전송
- 통찰: 통신 채널에서 오류가 검출되었을 때 송신측에 재전송을 요청하여 데이터 무결성을 보장하는 기법으로, 링크 대역폭과 왕복 지연시간(RTT) 특성에 따라 Stop-and-Wait, Go-Back-N, Selective Repeat 및 물리 계층 결합 HARQ로 진화함.

<details>
<summary>핵심 용어</summary>

- **ARQ(Automatic Repeat reQuest)** : 확인 응답 또는 타임아웃을 통해 손실·오류 데이터를 다시 보내는 방식
- **ACK(Acknowledgment)** : 수신 성공 또는 수신 위치를 송신자에게 알리는 확인 응답
- **타임아웃(Timeout)** : 정해진 시간까지 확인을 받지 못하면 재전송을 시작하는 조건
- **Stop-and-Wait** : 한 프레임을 보낸 뒤 확인 응답을 기다리는 ARQ 방식
- **Go-Back-N** : 여러 프레임을 연속 송신하다 미확인 위치부터 다시 보내는 방식
- **Selective Repeat** : 수신되지 않은 프레임을 선택해 다시 보내고 정상 수신 프레임은 보관하는 방식
- **FEC(Forward Error Correction)** : 재전송 없이 수신자가 오류를 정정할 수 있도록 여분 정보를 보내는 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. ARQ(Automatic Repeat reQuest)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 수신측에서 에러 검출 기법(CRC 등)을 통해 수신 프레임의 오류를 감지하면 송신측에 재전송을 요청(NAK 또는 ACK 미회신 타임아웃)하여 신뢰성 있는 전송을 보장하는 후진 오류 정정(BEC) 프로토콜 |
| 목적 | 전송 선로 상의 잡음 및 간섭으로 인한 데이터 손실과 왜곡 복구, 상위 계층에 무오류(Error-free) 투명 데이터 스트림 제공 |

## Ⅱ. ARQ(Automatic Repeat reQuest)의 특징

| 특징 | 상세 내용 |
|---|---|
| 확인 응답 메커니즘 | 정상 수신을 알리는 ACK(Positive ACK)와 오류를 알리는 NAK(Negative ACK) 기반 피드백 제어 |
| 타임아웃 타이머 | ACK/NAK 패킷 자체의 분실에 대비하여 송신측에 재전송 타이머(Timer)를 구동하여 무한 대기 방지 |
| 프레임 순서 번호 | 중복 프레임 수신을 식별하고 순서 역전을 정렬하기 위해 헤더에 시퀀스 번호(Sequence Number) 부여 |
| 파이프라이닝 제어 | 링크 대역폭 지연 곱(BDP)을 극대화하기 위해 ACK 수신 전 복수 프레임을 연속 송신하는 윈도우 기법 연동 |

## Ⅲ. ARQ(Automatic Repeat reQuest)의 체계·프로세스

**ARQ 3대 방식 동작 메커니즘 비교 흐름도**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ ARQ 3대 방식 동작 비교 ]                      │
│                                                                        │
│ [ 1. Stop-and-Wait ]       [ 2. Go-Back-N ]        [ 3. Selective Repeat]│
│   Tx          Rx             Tx          Rx          Tx          Rx    │
│   │─ Frame 0 ─►│             │─ Frame 0 ─►│          │─ Frame 0 ─►│    │
│   │◄── ACK 0 ──│             │─ Frame 1 ─►X (오류)   │─ Frame 1 ─►X    │
│   │─ Frame 1 ─►│             │─ Frame 2 ─►│ (폐기)   │─ Frame 2 ─►│    │
│   │◄── ACK 1 ──│             │─ Frame 3 ─►│ (폐기)   │─ Frame 3 ─►│    │
│   (1개 전송 후 대기)         │            │          │ (버퍼 임시보관) │
│                              │ (타임아웃 발생)       │ (NAK 1 수신)    │
│                              │─ Frame 1 ─►│ (재전송) │─ Frame 1 ─►│    │
│                              │─ Frame 2 ─►│ (재전송) │ (오류 프레임만) │
│                              │─ Frame 3 ─►│ (재전송) │ (선택 재전송)   │
└────────────────────────────────────────────────────────────────────────┘
```

| 방식 | 송신 윈도우 크기 | 수신 윈도우 크기 | 오류 발생 시 동작 특성 |
|---|---|---|---|
| **Stop-and-Wait** | 1 | 1 | 1개 프레임 송신 후 ACK 수신까지 대기. 구현 극단적 단순, 전송 효율 극히 낮음 |
| **Go-Back-N (GBN)** | N (최대 2^m - 1) | 1 | 오류 발생 프레임 이후 전송된 모든 정상 프레임까지 일괄 폐기 후 N개 재전송 |
| **Selective Repeat** | N (최대 2^(m-1)) | N (송신과 동일) | 오류가 발생한 특정 프레임만 선별 재전송. 수신측 재정렬 버퍼 필요 |

## Ⅳ. ARQ(Automatic Repeat reQuest)의 종류·비교

| 비교 항목 | Stop-and-Wait | Go-Back-N (GBN) | Selective Repeat (SR) |
|---|---|---|---|
| **전송 효율** | 매우 낮음 (RTT 영향 극대) | 중간 (오류율 낮을 시 우수) | 높음 (오류율 높아도 대역폭 보존) |
| **수신 버퍼 요구**| 1개 (단순 버퍼) | 1개 (순서 틀리면 즉각 폐기)| N개 (순서 어긋난 프레임 보관 버퍼) |
| **로직 복잡도** | 가장 단순 | 비교적 단순 | 복잡 (개별 타이머 및 재정렬 로직) |
| **시퀀스 번호 공간(m비트)**| 1비트 (0과 1 교번) | 최소 송신 윈도우 크기 + 1 | 최소 송신 윈도우 크기 * 2 |
| **대표 적용 사례**| TFTP, 저속 센서 통신 | HDLC REJ 모드 | TCP SACK, 고성능 무선 링크 |

## Ⅴ. ARQ(Automatic Repeat reQuest)의 한계와 방안

| 한계 | 방안 |
|---|---|
| Go-Back-N 방식에서 고속 광대역 링크 장애 시 불필요한 후속 프레임 대량 재전송으로 링크 낭비 | TCP SACK(Selective Acknowledgment, RFC 2018) 옵션 적용으로 수신 성공 블록 명시적 보고 |
| Selective Repeat 방식에서 윈도우 크기가 순서 번호 공간의 절반을 초과할 경우 신구 패킷 오인 발생 | 수신 윈도우 크기를 순서 번호 공간의 절반 이하(`Window Size <= 2^(m-1)`)로 엄격 제한 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
WAN 전송 지연이 큰 해저 케이블 및 클라우드 인터커넥트 환경에서는 표준 TCP의 누적 ACK(Cumulative ACK) 한계를 극복하기 위해 양단 호스트의 커널 파라미터에서 `net.ipv4.tcp_sack=1` 설정을 필수 활성화하여 손실 패킷만 정밀 재전송.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ ARQ 시퀀스 번호 중복 오인 방지 윈도우 크기 제약 (SR 기준) ]         │
│                                                                        │
│   시퀀스 번호 공간: 0, 1, 2, 3 (2비트, 총 4개)                         │
│                                                                        │
│   [ 잘못된 설계: Window Size = 3 (초과) ]                              │
│   Tx: Frame 0, 1, 2 전송 ──► Rx: 수신 성공, ACK 0,1,2 회신              │
│                              (모든 ACK가 망에서 분실)                  │
│   Tx: 타임아웃으로 이전 Frame 0 재전송                                 │
│   Rx: 새로운 주기(New)의 Frame 0으로 오인하여 중복 수신 오류 발생!     │
│                                                                        │
│   [ 올바른 설계: Window Size <= 2^(2-1) = 2 ]                          │
│   송신 윈도우와 수신 윈도우의 겹침이 원천 배제되어 신구 패킷 완벽 분리 │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 프로토콜 계층 | 채택 ARQ 메커니즘 | 채택 이유 |
|---|---|---|
| **L2 데이터링크 (HDLC/Wi-Fi)**| Stop-and-Wait / Block ACK | 하드웨어 칩셋 구현 경량화 및 신속한 홉간 오류 복구 |
| **L4 전송 계층 (TCP)** | Sliding Window 기반 GBN/SACK | 종단 간(E2E) 신뢰성 및 가변 네트워크 경로 버퍼링 최적화 |
| **L1/L2 이동통신 (LTE/5G)** | PHY HARQ + MAC ARQ 이중 구조 | 극저지연 물리 계층 고속 복구 후 잔여 오류만 상위 계층 완벽 처리 |
