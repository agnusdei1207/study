## 연관 키워드

- ARQ(Automatic Repeat reQuest), 정지-대기(Stop-and-Wait) ARQ, Go-Back-N ARQ, 선택적 재전송(Selective Repeat) ARQ
- 슬라이딩 윈도우(Sliding Window), ACK/NAK, 타임아웃 타이머, HARQ(Hybrid ARQ)
- Chase Combining, 증분 중복(IR, Incremental Redundancy), SACK(Selective Acknowledgment), 순서 번호

## Ⅰ. ARQ(Automatic Repeat reQuest)의 개요

- 핵심 요약 : 오류가 난 프레임을 수신 확인 응답과 타이머로 찾아 자동 재전송하여 무손실 전달을 보장하는 오류 제어 방식.
- 개념 : 수신 측이 오류 검출 결과에 따라 ACK(긍정 응답)나 NAK(부정 응답)를 돌려보내고, 송신 측은 응답이 없거나 NAK가 오면 해당 프레임을 다시 보내는 **자동 반복 요청** (ARQ, Automatic Repeat reQuest) 방식.
- 배경 및 필요성 : 물리 매체는 잡음, 페이딩, 간섭으로 전송 오류를 완전히 막을 수 없으므로, 오류를 감지하는 것만으로는 부족하고 복구까지 수행하는 계층이 필요함.
- 주요 목적 : 프레임 유실과 오류를 복구하여 데이터 무결성을 확보하고, 순서가 뒤바뀌지 않게 전달하며, 회선 용량을 가능한 한 활용.

## Ⅱ. ARQ(Automatic Repeat reQuest)의 특징 및 장점

- 핵심 요약 : 확인 응답 기반 재전송과 윈도우 제어가 신뢰성과 처리율 사이의 균형을 만드는 방식.

1. 오류 복구 자동화 : 송신 측이 응답 부재를 타이머로 감지하여 재전송 → 사람의 개입 없이 무손실 전달 달성.
2. 확인 응답 기반 신뢰성 : ACK/NAK로 수신 상태를 송신 측에 알림 → 송신 측이 전달 성공 여부를 확정.
3. 윈도우 기반 파이프라이닝 : 슬라이딩 윈도우로 확인 응답을 기다리지 않고 여러 프레임을 연속 전송 → 대역폭 활용률 향상.
4. 계층 적용 범위 : 링크 계층(L2)의 프레임 단위와 전송 계층(L4, TCP)의 세그먼트 단위에서 모두 쓰여 상황에 맞춰 선택 가능.

## Ⅲ. ARQ(Automatic Repeat reQuest)의 구조 (흐름)

- 핵심 요약 : 세 가지 기본 유형은 윈도우 크기와 재전송 범위의 차이로 나뉘며, 무선망에서는 물리 계층 FEC와 결합한 HARQ로 발전함.
- **정지-대기 ARQ** (Stop-and-Wait ARQ) : 윈도우 크기 1로 프레임 하나를 보내고 ACK를 받은 뒤에야 다음 프레임을 보냄.
- **Go-Back-N ARQ** : 송신 윈도우 N으로 연속 전송하고, 오류가 나면 오류 프레임부터 뒤의 프레임을 모두 다시 보냄(수신 윈도우 1).
- **선택적 재전송** (Selective Repeat ARQ) : 송신 윈도우와 수신 윈도우를 모두 N으로 두고, 손실된 프레임만 골라 다시 보냄.

```text
[ 정지-대기 ARQ ]

송신: Frame 0 전송
   ↓
수신: 정상 수신 → ACK 0 반환
   ↓
송신: ACK 확인 후 Frame 1 전송
   ↓
Frame 1 손실 → 타이머 만료 → Frame 1 재전송
```

```text
[ Go-Back-N ARQ ]

송신: F0, F1, F2(손실), F3 연속 전송
   ↓
수신: F2 누락 감지 → F3 폐기
   ↓
송신: F2부터 F3 포함 전부 재전송
```

- **HARQ** (Hybrid ARQ) : L1의 FEC(순방향 오류 정정)와 L2의 ARQ를 결합하여, 오류 프레임을 버리지 않고 수신 측 소프트 버퍼에 보관해 재전송분과 합쳐 복호하는 방식이며, 합치는 방법에 따라 **Chase Combining**과 **증분 중복** (IR, Incremental Redundancy)으로 나뉨.

## Ⅳ. ARQ(Automatic Repeat reQuest)의 비교

- 핵심 요약 : 윈도우가 커질수록 채널 효율은 올라가지만 수신 버퍼 비용과 재정렬 복잡도가 함께 늘어남.

| 비교 축 | Stop-and-Wait | Go-Back-N | Selective Repeat | HARQ |
| --- | --- | --- | --- | --- |
| 송신 윈도우 | 1 | N | N | 복수 프로세스 (다중 Stop-and-Wait) |
| 수신 윈도우 | 1 | 1 | N (재정렬 버퍼) | 1 (소프트 버퍼 보유) |
| 오류 시 재전송 범위 | 해당 프레임 하나 | 오류 프레임 이후 전부 | 손실 프레임만 | 재전송분(증분 비트) |
| 채널 효율 | 전파 지연이 크면 급락 | 오류율이 높으면 저하 | 높음 | 무선에서 높음 |
| 버퍼 비용 | 최소 | 낮음 | 높음 | 높음 (LLR 저장) |

- 선택 기준 : 전파 지연이 짧고 프레임 수가 적으면 구현이 단순한 Stop-and-Wait나 Go-Back-N으로 충분하고, 지연이 크거나 고속 링크에서는 Selective Repeat 계열, 무선 링크에서는 HARQ를 택함.

## Ⅴ. ARQ(Automatic Repeat reQuest)의 한계와 방안

- 핵심 요약 : 긴 지연 링크의 중복 재전송, 순서 번호 모호성, 계층 간 재전송 경쟁이 주요 한계이며, 재전송 범위 축소와 계층 간 조정으로 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 긴 지연 링크의 중복 재전송 | Go-Back-N은 프레임 하나의 손실로 뒤의 정상 프레임까지 재전송 → 처리율 급감 | 재전송 범위를 손실 프레임으로 한정하는 Selective Repeat 적용, TCP의 SACK 옵션 활성화 | 재전송률, 유효 처리율 |
| 순서 번호 모호성 | 윈도우 크기가 순서 번호 공간의 절반을 넘으면 신규와 이전 프레임을 구분하지 못함 | Selective Repeat 윈도우를 순서 번호 공간의 절반 이하로 설계 (W ≤ 2^(m-1)) | 설계 검증 결과 |
| 계층 간 재전송 경쟁 | L2 HARQ 재전송 중 L4 TCP 타이머가 먼저 만료되어 불필요한 상위 재전송 발생 | TCP 재전송 타임아웃(RTO) 산정에 무선 재전송 지연 반영, 계층 간 상태 정보 공유 | 불필요 재전송 수 |

## Ⅵ. ARQ(Automatic Repeat reQuest)에 대한 기술사적 제언

- 핵심 요약 : ARQ는 계층마다 재전송 책임이 겹치지 않도록 설계하는 것이 성능과 안정성의 핵심임.
- 고속 데이터센터에서 재전송 자체를 줄이려면 손실을 전제하지 않는 무손실 이더넷 패브릭을 우선 검토하고, 우선순위 흐름 제어(PFC, Priority Flow Control)와 혼잡 명시 통지(ECN, Explicit Congestion Notification)를 함께 설계하는 편이 현실적임.
- 초저지연 무선 서비스는 HARQ 피드백 시점을 물리 계층 프레임 구조에 맞춰 조정하고, 상위 계층의 TCP 타이머와 값을 맞추는 운영 절차를 함께 마련해야 함.
- 신규 전송 프로토콜을 도입할 때는 QUIC처럼 재전송 패킷에 새 패킷 번호를 부여하여 재전송 모호성을 구조적으로 없애는 설계를 검토할 만함.

## Ⅶ. 결론

- 핵심 요약 : ARQ는 확인 응답과 재전송으로 무손실 전달을 보장하는 오류 제어의 기본 원리이다.
- 시사점 : 윈도우 크기와 재전송 범위의 조합이 효율을 결정하므로, 링크의 지연과 오류 특성에 맞춰 유형을 고르는 것이 설계의 출발점이다.
