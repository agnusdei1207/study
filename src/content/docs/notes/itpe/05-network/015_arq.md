## Ⅰ. ARQ(Automatic Repeat reQuest)의 개요

- 개념 : 신뢰성이 보장되지 않는 전송 채널에서 데이터 프레임의 전송 손실이나 비트 오류가 발생했을 때, 수신 측의 오류 검출(CRC)과 **제어 메시지(ACK/NAK)** 및 **타이머** 메커니즘을 결합하여 송신 측이 오류 패킷을 자동으로 재전송하는 **오류 제어** 프로토콜.
- 배경 및 필요성 : 물리적 전송 매체는 열잡음, 페이딩, 간섭 등으로 인해 완벽한 무오류 전송을 보장할 수 없으므로, 상위 계층 애플리케이션에 무손실·순차적 데이터 전달을 보장하기 위한 링크(L2) 및 전송(L4) 계층의 핵심 메커니즘으로 자리잡음.
- 핵심 목적 : 무결성 데이터 전송 달성, 프레임 유실 및 역전 방지, 통신 회선의 대역폭 지연 곱(BDP)에 부합하는 전송 처리율(Throughput) 최적화.

## Ⅱ. ARQ(Automatic Repeat reQuest)의 핵심 아키텍처 및 동작 메커니즘

ARQ는 전송 방식과 윈도우 버퍼링 구조에 따라 정지-대기(Stop-and-Wait), Go-Back-N, 선택적 재전송(Selective Repeat)으로 분류되며, 최신 무선망에서는 물리 계층 FEC와 결합한 HARQ로 진화함.

```text
[ ARQ 3대 기본 유형 동작 메커니즘 ]

1. Stop-and-Wait ARQ (윈도우 크기 = 1)
   송신단                       수신단
     │──── Frame 0 ──────────────>│
     │<─── ACK 1 ─────────────────│ (매 프레임마다 대기)
     │──── Frame 1 (오류 손실) ──>X
     │    [타임아웃 발생!]
     │──── Frame 1 (재전송) ─────>│

2. Go-Back-N ARQ (송신 윈도우 = N, 수신 윈도우 = 1)
   송신단                       수신단
     │──── F0, F1, F2(손실), F3 ─>│
     │                            │ 수신단: F2 누락 감지, F3 폐기!
     │<─── NAK 2 (또는 타임아웃) ─│
     │──── F2, F3 재전송 ────────>│ (손실된 F2부터 N개 일괄 재전송)

3. Selective Repeat ARQ (송신 윈도우 = N, 수신 윈도우 = N)
   송신단                       수신단
     │──── F0, F1, F2(손실), F3 ─>│ 수신단: F3 버퍼링!
     │<─── SACK 2 (F2만 요청) ────│
     │──── F2 (손실분만 단독 전송)│ (수신단: 버퍼 정렬 후 상위 전달)
```

- **정지-대기(Stop-and-Wait) ARQ** : 1개 프레임을 송신 후 ACK가 올 때까지 대기하며, 구조가 가장 단순하나 전파 지연이 긴 환경에서 채널 효율이 극히 낮음.
- **Go-Back-N(GBN) ARQ** : 송신단은 확인 응답 없이 $N$개 프레임을 연속 전송하되, 오류 발생 시 오류 프레임 이후 전송된 모든 정상 프레임까지 되돌아가서 전부 재전송(수신 버퍼 1).
- **선택적 재전송(Selective Repeat) ARQ** : 오류가 발생한 특정 프레임만을 선별하여 재전송하며, 수신단에 정렬용 버퍼를 두어 채널 효율을 극대화함.
- **HARQ(Hybrid ARQ)** : L1 물리 계층의 FEC(순방향 오류 정정)와 L2 ARQ를 결합하여 오류 프레임을 폐기하지 않고 재전송 데이터와 합성(Chase Combining / IR) 복호.

## Ⅲ. ARQ(Automatic Repeat reQuest)의 세부 구성 요소 및 비교 분석

| 비교 항목 | Stop-and-Wait ARQ | Go-Back-N ARQ | Selective Repeat ARQ | 하이브리드 HARQ |
|---|---|---|---|---|
| 송신 윈도우 크기 | 1 | $N$ ($N > 1$) | $N$ | 복수 프로세스 (Stop-and-Wait 다중화) |
| 수신 윈도우 크기 | 1 | 1 | $N$ (버퍼링 및 재정렬) | 1 (소프트 버퍼 유지) |
| 오류 시 재전송 | 해당 단일 프레임 재전송 | 손실 프레임 이후 $N$개 전체 | 손실된 특정 프레임만 | 잉여 증분(IR) 비트만 재전송 |
| 전송 채널 효율 | 매우 낮음 ($RTT$에 반비례) | 보통 (오류율 높으면 급락) | 매우 높음 (대역폭 최적화) | 극대화 (스펙트럼 효율 최고) |
| 버퍼 구현 비용 | 최소 (버퍼 불필요) | 낮음 (수신 버퍼 불필요) | 높음 (수신단 정렬 큐 필요)| 높음 (물리 계층 LLR 버퍼 필요) |

- 단순 센서 통신에는 Stop-and-Wait이나 GBN이 적합하지만, 대용량 및 고속 네트워크 환경에서는 **SACK** 기반의 Selective Repeat와 무선의 HARQ가 필수 표준으로 사용됨.

## Ⅳ. ARQ(Automatic Repeat reQuest)의 주요 한계점 및 해결 방안

- 긴 지연시간(Long RTT) 환경에서 GBN의 중복 재전송으로 인한 대역폭 낭비 :
  - 한계점 : 위성 통신이나 해저 케이블 통신에서 단 1개의 패킷 손실로 수십 개의 정상 패킷을 재전송하여 처리율 급감.
  - 해결 방안 : TCP SACK(Selective Acknowledgement) 옵션 활성화 및 Selective Repeat ARQ 전면 적용.
- 수신 윈도우와 송신 윈도우 크기 불일치로 인한 순서 번호 모호성(Ambiguity) :
  - 한계점 : 순서 번호 공간 $M$에 대해 윈도우 크기가 $2^{M-1}$을 초과할 경우 이전 프레임과 신규 프레임의 중복 혼선 발생.
  - 해결 방안 : 순서 번호 공간 $M$에 대하여 송수신 윈도우 크기 $W \le 2^{M-1}$ 수학적 설계 제약 준수.
- L2 무선 계층 HARQ와 L4 TCP 계층 ARQ 간의 이중 재전송 경쟁 :
  - 한계점 : L2 무선 링크에서 재전송을 시도하는 도중 L4 TCP 타이머가 먼저 만료되어 상위 계층의 불필요한 중복 재전송 폭증.
  - 해결 방안 : L2 HARQ 재전송 완료 시간을 감안한 TCP RTO(Retransmission Timeout) 추정 계수 튜닝 및 크로스 레이어 최적화.

## Ⅴ. ARQ(Automatic Repeat reQuest) 적용 및 발전을 위한 기술사적 제언

- 초고속 클라우드 데이터센터를 위한 무손실 RoCE v2 패브릭 설계 : ARQ 재전송 지연을 원천 차단하기 위해 스위치 우선순위 기반 흐름 제어(PFC)와 ECN을 결합한 하드웨어 무손실 전송 구현 권장.
- 초저지연(URLLC) 통신을 위한 HARQ 프로세스 최적화 : 0.5ms 이하의 TTI(전송 시간 간격) 환경에서 미니 슬롯(Mini-slot) 기반 빠른 HARQ 피드백 파이프라인 구축 필수.
- QUIC 프로토콜의 패킷 번호 단조 증가(Monotonic Increase) 메커니즘 채택 : 레거시 TCP의 재전송 모호성을 해소하기 위해 재전송 패킷에 항상 신규 시퀀스를 부여하는 QUIC 전송 엔진 도입 검토.
