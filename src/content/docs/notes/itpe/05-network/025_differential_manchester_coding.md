## 30초 인출

- 본질: **차동 맨체스터 부호화(Differential Manchester Encoding)** : 비트 중앙의 전이로 동기화하고 비트 경계 전이의 유무로 데이터를 표현하는 라인 코드
- 메커니즘: 모든 비트 중앙에서 전이, 비트 시작 전이 유무 판정, 규격의 비트값 대응에 따라 복호
- 통찰: 신호의 절대 레벨이 아닌 이전 비트 상태 대비 상대적 신호 전이 유무로 비트를 부호화하고 중앙 전이로 클록 동기를 보장하여 산업용 잡음 환경 및 케이블 극성 왜곡에 강건한 디지털 전송 기법임.

<details>
<summary>핵심 용어</summary>

- **차동적 맨체스터 부호화** : Differential Manchester Encoding; 비트 중앙 전이를 동기 기준으로 삼고 비트 경계 전이로 비트값을 표현하는 라인 코드
- **라인 코드(Line Code)** : 디지털 비트열을 물리 전송 신호로 나타내는 부호 방식
- **자가 클로킹(Self-clocking)** : 신호의 주기적 전이에서 수신기가 타이밍 정보를 얻는 성질
- **비트 경계 전이(Bit-boundary Transition)** : 비트 구간 시작에서 신호 레벨이 바뀌는 현상
- **맨체스터 부호화(Manchester Encoding)** : 비트 중앙 전이 방향으로 값을 표현하는 라인 코드
- **NRZ(Non-Return-to-Zero)** : 비트 구간 내 신호 레벨을 유지하고 매 비트마다 기준 레벨로 돌아오지 않는 계열의 부호

</details>

## 2~4교시 25점 답안

## Ⅰ. 차동 맨체스터 코딩의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 2단계(Biphase) 신호 체계 기반으로 비트 시간의 전반부와 후반부 경계에서 위상 반전을 통해 클록을 제공하고, 비트의 시작 시점의 전이 유무로 2진 정보를 부호화하는 디지털 기저대역 전송 코딩 기술 |
| 목적 | 전송 매체의 직류 차단(DC Blocking) 특성 극복, 수신단 비동기 상태 방지 및 왜곡 선로에서의 비트 에러율(BER) 최소화 |

## Ⅱ. 차동 맨체스터 코딩의 특징

| 특징 | 상세 내용 |
|---|---|
| 상대적 전이 코딩 | 비트 시작점의 상태 변화(Edge) 유무로 '0'과 '1'을 식별하여 전송 선로의 극성 반전에 영향 없음 |
| 지속적 클록 추출 | 모든 심볼의 정중앙에 반드시 엣지 전이가 존재하므로 수신측 DPLL이 강력한 클록 동기 유지 |
| 직류 성분 배제 | 1 비트 주기 내에서 +V와 -V가 정확히 동일 시간 체류하여 신호의 직류 평균 전압이 영(0)으로 수렴 |
| 대역폭 페널티 | 심볼당 2개의 신호 간격(Interval)을 소모하여 데이터 속도 대비 2배의 전송 대역폭이 소요됨 |

## Ⅲ. 차동 맨체스터 코딩의 체계·프로세스

**차동 맨체스터 부호화 상태 천이 및 복호화 메커니즘**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ 차동 맨체스터 상태 천이 규칙 ]                │
│                                                                        │
│ 현재 레벨 상태 ──► 입력 비트 '0' ──► [ 시작점 전이 발생 ] ──► [ 중앙 전이 ]│
│                ──► 입력 비트 '1' ──► [ 시작점 전이 없음 ] ──► [ 중앙 전이 ]│
│                                                                        │
│   입력 데이터 스트림: 0  1  1  0                                       │
│                                                                        │
│   클록 (Clock)  :  ┌─┐ ┌─┐ ┌─┐ ┌─┐                                     │
│                    └─┘ └─┘ └─┘ └─┘                                     │
│                                                                        │
│   부호화 신호   :  ┌┐┌─┐ ┌─┐ ┌┐┌─┐                                     │
│   (Encoding)       └┘  └─┘ └─┘└┘                                       │
│                    ▲   ▲   ▲   ▲                                       │
│                    │   │   │   │                                       │
│   시작점 전이 분석: 전이 무전이 무전이 전이                            │
│   판정 비트 결과 : '0'  '1'  '1'  '0' (정확한 데이터 복호화 완료)       │
└────────────────────────────────────────────────────────────────────────┘
```

| 비트 입력 | 시작점 전이 동작 | 중앙점 전이 동작 | 최종 파형 특성 |
|---|---|---|---|
| **비트 '0'** | 직전 레벨과 반대로 **전이 발생** | 비트 중앙에서 **강제 반전** | 전반부와 후반부의 전압 극성이 서로 반대 |
| **비트 '1'** | 직전 레벨을 그대로 **유지** | 비트 중앙에서 **강제 반전** | 시작점 변화 없이 중앙에서만 반전 발생 |
| **동기 클록**| 데이터 판정용 기준 제공 | 수신단 위상 동기화 제공 | 별도의 클록 채널 포설 비용 제로화 |

## Ⅳ. 차동 맨체스터 코딩의 종류·비교

| 비교 항목 | 차동 맨체스터 (Diff Manchester) | 표준 맨체스터 (Manchester) | 바이폴라 (AMI) |
|---|---|---|---|
| **부호화 방식** | 상대적 전이 유무 판정 | 절대적 레벨 전이 방향 판정 | 3레벨 (+V, 0, -V) 교번 전이 |
| **신호 레벨** | 2 레벨 | 2 레벨 | 3 레벨 |
| **극성 반전 영향**| **영향 없음 (정상 동작)** | **오류 발생 (0과 1 반전)** | 오류 발생 |
| **연속 '0' 동기** | **동기 유지 (중앙 전이 존재)**| **동기 유지** | **동기 상실 (0V 지속)** |
| **요구 대역폭** | 데이터율의 2배 | 데이터율의 2배 | 데이터율과 동일 |

## Ⅴ. 차동 맨체스터 코딩의 한계와 방안

| 한계 | 방안 |
|---|---|
| 전송 매체의 고주파 감쇠로 인해 고속 전송(100Mbps 이상) 시 심볼 간 간섭(ISI) 발생 | 100Base-FX 및 기가비트 이더넷 표준처럼 멀티레벨 부호(MLT-3) 및 스크램블러(Scrambler) 적용 |
| 수신단 시작 시점에서 첫 비트의 기준 전이 상태가 부정확할 경우 초기 동기화 지연 발생 | 패킷 전송 전 8바이트의 교번 비트 프리앰블(101010...)을 선행 전송하여 초기 위상 고정 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
토큰링 및 항공/철도 통신 프로토콜(MIL-STD-1553B) 하드웨어 설계 시, 케이블 접속 단자의 접속 불량이나 역배선 시에도 통신이 중단되지 않는 차동 맨체스터 방식을 적용하고 선로 트랜스포머의 누설 인덕턴스로 인한 신호 왜곡을 방지하기 위해 정합 종단 저항(110Ω)을 필수 체결.

### 2. 아키텍처 및 상세 메커니즘

│   수신 RF/선로 신호 ──► [ 대역 통과 필터 ]                             │

### 3. 기술 유형 및 비교 평가
| 물리 계층 평가 지표 | 차동 맨체스터 | NRZ-I | 4B/5B + NRZ-I |
|---|---|---|---|
| **잡음 면역성 (Noise Margin)** | 최우수 | 보통 | 우수 |
| **동기화 신뢰도** | 100% 보장 | 조건부 보장 | 100% 보장 (연속 0 제한) |
| **대역폭 오버헤드** | 100% 증가 (2 Baud/bit) | 0% (1 Baud/bit) | 25% 증가 (1.25 Baud/bit) |
| **회로 복잡도** | 단순 (XOR 게이트 기반) | 극단적 단순 | 중간 (LUT 테이블 필요) |
