## 지식 로드맵 내 현재 위치

네트워크 → 패킷 교환 광역망(WAN) → **프레임릴레이(Frame Relay)**

## 30초 인출

- 본질: **프레임릴레이(Frame Relay)** : 광섬유 전송로의 높은 신뢰성을 전제로 X.25의 3계층 패킷 처리 및 홉별(Hop-by-hop) 오류·흐름 제어를 대폭 생략하고 OSI 2계층 데이터링크에서 가상 회선 기반으로 프레임을 고속 교환하는 광역망(WAN) 기술
- 메커니즘: 10비트 DLCI(Data Link Connection Identifier)를 통해 논리 가상 회선(PVC/SVC)을 식별하고, 혼잡 발생 시 FECN/BECN 비트로 전후방 혼잡을 통지하며 초과 패킷에 DE(Discard Eligibility) 비트를 마킹하여 선별 폐기
- 통찰: 노드 간 오류 정정을 생략하여 전송 지연을 줄였으나 버스트 트래픽 집중 시 스위치 버퍼 오버플로로 대량 폐기되는 한계 극복을 위해 CIR 기반 토큰 버킷 트래픽 쉐이핑과 MPLS-VPN 마이그레이션 연계 필수

<details>
<summary>핵심 용어</summary>

- **DLCI (Data Link Connection Identifier)** : 프레임릴레이 망에서 단일 물리 인터페이스 내의 개별 가상 회선(VC)을 식별하는 10비트 로컬 식별자
- **CIR (Committed Information Rate)** : 통신 사업자가 가입자에게 정상적인 네트워크 상태에서 보장하기로 계약한 약정 정보 전송률 (bps)
- **FECN (Forward Explicit Congestion Notification)** : 데이터가 이동하는 순방향 프레임의 헤더에 비트를 1로 설정하여 수신측 DTE에 경로 혼잡을 알리는 메커니즘
- **BECN (Backward Explicit Congestion Notification)** : 혼잡이 발생한 교환기가 송신측으로 되돌아가는 역방향 프레임에 비트를 1로 설정하여 송신측에 송출 속도 감축을 유도하는 메커니즘
- **DE (Discard Eligibility)** : 약정된 버스트 대역폭을 초과하여 망에 인입된 프레임에 마킹하여 망 혼잡 발생 시 교환기가 최우선 폐기할 수 있도록 지정하는 1비트 플래그

</details>

## 2~4교시 25점 답안

## Ⅰ. 프레임릴레이의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 광통신 인프라의 저오류율 특성을 활용하여 X.25의 복잡한 3계층 기능과 중간 노드 재전송 절차를 생략하고, OSI 2계층 데이터링크 수준에서 가변 길이 프레임을 고속으로 스위칭하는 패킷 교환 광역망(WAN) 프로토콜 |
| 목적 | 기존 X.25 대비 네트워크 전달 지연 단축 및 처리율 극대화, 전용선 대비 가상 회선 다중화를 통한 기업 본-지사 간 광역 통신 비용 대폭 절감 |

## Ⅱ. 프레임릴레이의 특징 및 ITU-T Q.922 프레임 구조

| 프레임 헤더 필드 | 비트 크기 | 세부 기능 및 엔지니어링 특징 |
|---|---|---|
| **Flag (플래그)** | 8 bits | 프레임의 시작과 끝을 식별하는 고정 비트열 (`01111110`, 0x7E) |
| **DLCI (상위 6비트 + 하위 4비트)** | 10 bits | 논리적 가상 회선 식별자 (총 1024개 중 사용자 회선은 16~1007 가용) |
| **C/R (Command/Response)** | 1 bit | 상위 애플리케이션 계층의 명령 또는 응답 구분 비트 |
| **EA (Address Extension)** | 2 bits | 주소 필드 확장 비트 (0이면 다음 바이트까지 주소 확장, 1이면 최종 주소 바이트) |
| **FECN (순방향 혼잡 통지)** | 1 bit | 목적지 수신 노드 방향으로 전송 경로 상에 혼잡이 발생했음을 통지 |
| **BECN (역방향 혼잡 통지)** | 1 bit | 패킷을 송출한 출발지 노드 방향으로 회선 혼잡을 통지하여 송출 속도 억제 유도 |
| **DE (폐기 적격성 플래그)** | 1 bit | 1로 설정된 프레임은 스위치 혼잡 시 우선 폐기 대상(약정률 초과 트래픽)으로 지정 |
| **FCS (프레임 체크 시퀀스)** | 16 bits | 전송 중 비트 오류 검출을 위한 CRC-16 필드 (오류 검출 시 재전송 없이 즉시 폐기) |

## Ⅲ. 프레임릴레이 가상 회선 아키텍처 및 혼잡 제어 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ 프레임릴레이 네트워크 및 FECN/BECN 제어 ]          │
│                                                                        │
│   [가입자 DTE: 송신 라우터]                        [가입자 DTE: 수신 라우터]│
│   (본사: DLCI 100)                                 (지사: DLCI 200)   │
│          │                                                ▲            │
│          ▼ 프레임 송출 (데이터 트래픽)                     │ 프레임 수신│
│   ┌──────────────┐    (FECN=1 순방향 전파)        ┌──────┴───────┐     │
│   │ FR Switch A  ├───────────────────────────────►│ FR Switch B  │     │
│   └──────┬───────┘                                └──────▲───────┘     │
│          │                 [ 스위치 내부 ]               │             │
│          │                 (버퍼 임계치 초과!)            │             │
│          ▼ (BECN=1 역방향)  - FECN=1 마킹 (수신측)        │             │
│   [송신 속도 즉시 감축!]    - BECN=1 마킹 (송신측)        │             │
│   (전송 윈도우 축소)        - 초과분 DE=1 우선 드롭       │             │
└────────────────────────────────────────────────────────────────────────┘
```

| 혼잡 제어 단계 | 주관 요소 | 세부 동작 메커니즘 |
|---|---|---|
| **1. 정상 전송 및 대역폭 감시** | 진입 스위치 (Ingress) | 가입자 트래픽을 측정하여 계약된 CIR 이내는 DE=0, 초과분은 DE=1로 마킹 |
| **2. 망 내부 혼잡 감지** | 중간 프레임 스위치 | 내부 송신 큐의 버퍼 사용률이 임계값(예: 80%)을 초과할 때 혼잡 상태 진입 |
| **3. 혼잡 비트 설정 및 통지** | 중간 프레임 스위치 | 지나가는 프레임 헤더에 FECN=1 설정, 역방향 프레임에 BECN=1 설정 송출 |
| **4. 엔드투엔드 속도 조절** | 종단 라우터 (DTE) | 송신측은 BECN 수신 시 전송률을 25~50% 강제 축소, 수신측은 TCP ACK 지연 전송 |

## Ⅳ. X.25 vs 프레임릴레이(Frame Relay) vs ATM 비교

| 비교 항목 | X.25 | 프레임릴레이 (Frame Relay) | ATM (Asynchronous Transfer Mode) |
|---|---|---|---|
| **프로토콜 계층** | 1~3계층 (패킷 계층 포함) | **1~2계층 (데이터링크 계층 전담)** | 1~2계층 (ATM 셀 계층) |
| **전송 단위** | 가변 길이 패킷 (최대 4KB) | **가변 길이 프레임 (최대 4KB, 통상 1.5KB)**| **53바이트 고정 셀 (헤더 5B + 페이로드 48B)**|
| **오류 및 흐름 제어** | **각 홉별(Node-to-Node) 전수 수행** | **망 내부 생략 (종단 간 상위 계층 위임)** | **망 내부 생략 (HEC로 헤더 오류만 복구)** |
| **가상 회선 식별자** | LCN (Logical Channel Number) | **DLCI (10 bits)** | VPI (8/12 bits) + VCI (16 bits) |
| **전송 속도 및 지연** | 저속 (수십 kbps ~ 2 Mbps), 고지연| **중고속 (1.544M ~ 45 Mbps), 저지연** | **초고속 (155M ~ 622 Mbps 이상), 극저지연** |
| **주요 적용 전송 매체** | 아날로그 전화망, 구리선 회선 | 디지털 T1/E1 회선, 광역 전용선 | B-ISDN 광전송망, 백본 통신망 |

## Ⅴ. 프레임릴레이의 핵심 엔지니어링 한계와 방안

| 한계 | 방안 |
|---|---|
| 망 내부 노드에서 패킷 오류 정정 및 홉별 재전송을 수행하지 않으므로, 버스트 트래픽 폭주 시 스위치 버퍼가 고갈되어 DE=1 마킹 프레임이 대량 폐기되고 상위 TCP 계층의 연쇄 재전송 폭풍(Retransmission Storm) 발생 | 가입자단 라우터(CPE)에서 계약된 CIR(약정률), Bc(약정 버스트 크기), Be(초과 버스트 크기) 파라미터를 기반으로 토큰 버킷(Token Bucket) 트래픽 쉐이핑 알고리즘을 구현하여 물리 회선 속도를 초과하지 않도록 선제적 트래픽 평활화 집행 |
| 다수 지사를 보유한 기업망에서 완전 그물형(Full Mesh) 영구 가상 회선(PVC) 구축 시 $N(N-1)/2$개의 가상 회선이 필요하여 DLCI 관리 복잡도가 폭증하고 라우팅 프로토콜의 Split Horizon으로 인한 라우팅 갱신 실패 발생 | 물리 인터페이스를 복수의 점대점(Point-to-Point) 서브인터페이스로 논리 분할하여 개별 서브넷을 부여하거나, 허브 앤 스포크(Hub-and-Spoke) 구조로 단순화하고 종국에는 엔터프라이즈 MPLS-VPN 또는 SD-WAN으로 전환 |
| 45Mbps(T3) 이상의 광대역 전송 한계 및 멀티미디어(음성/화상) 트래픽 인입 시 가변 길이 대형 데이터 프레임에 의해 음성 패킷이 지연되는 지터(Jitter) 발생 | 대형 데이터 프레임을 작은 조각으로 잘게 분할하여 음성 패킷 사이에 끼워 넣는 FRF.12 프레임 단편화(Fragmentation) 및 저지연 큐잉(LLQ) 우선순위 스케줄링 적용 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
프레임릴레이는 2000년대 광역 통신의 핵심 기술이었으나 현재는 서비스 단종 및 유지보수 비용 급증 추세에 있으므로, 레거시 프레임릴레이를 운용 중인 시스템은 통신사 전용선 대비 비용 절감과 품질 보증(SLA)이 우수한 통신사 MPLS L3VPN 또는 공용 인터넷 상의 IPsec 터널 기반 소프트웨어 정의 광역망(SD-WAN)으로의 전환 계획 수립 권장

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ 프레임릴레이 토큰 버킷 트래픽 쉐이핑 메커니즘 ]     │
│                                                                        │
│   토큰 유입 (속도: CIR bps)                                            │
│          │                                                             │
│          ▼                                                             │
│   ┌────────────────────────────────┐                                   │
│   │  토큰 버킷 (최대 용량: Bc + Be) │                                   │
│   └──────────────┬─────────────────┘                                   │
│                  │ 토큰 차감                                           │
│                  ▼                                                     │
│   [인입 트래픽 패킷] ──► (트래픽 적합성 검사)                           │
│                            │                                           │
│             ┌──────────────┼──────────────┐                            │
│             ▼ (토큰 < Bc)   ▼ (Bc < 토큰 < Be) ▼ (토큰 초과)           │
│        [그린 프레임]    [옐로우 프레임]    [레드 프레임]               │
│        - DE = 0 설정    - DE = 1 설정      - 즉시 폐기 (Drop)          │
│        - 무조건 전송    - 혼잡 시 폐기 대상 - 또는 버퍼링 쉐이핑        │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 구분 | 영구 가상 회선 (PVC) | 교환 가상 회선 (SVC) | 현대적 대안 (MPLS L3VPN) |
|---|---|---|---|
| **연결 수립 방식** | 통신 사업자가 사전 정적 매핑 설정 | 필요 시 Q.933 호 시그널링으로 동적 연결 | BGP 제어 평면 기반 자동 터널링 |
| **회선 구축 시간** | 초기 구성 후 상시 연결 유지 | 데이터 전송 시에만 연결 수립 | 중앙 집중형 정책 기반 즉시 배포 |
| **운영 비용** | 상시 가상 회선 점유로 고정 비용 | 통신 시간에 비례한 종량 요금제 | 대역폭 대비 가장 경제적이고 확장 우수 |
| **QoS 및 SLA** | CIR 기반의 제한적 대역폭 보장 | 호 수락 제어(CAC) 기반 보장 | DiffServ 6단계 CoS 및 지연 보증 완벽 |
