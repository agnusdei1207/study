## Ⅰ. 프레임릴레이(Frame Relay)의 개요

- 개념 : 기존 X.25의 무거운 오류 제어 및 흐름 제어 오버헤드를 대폭 축소하여, 신뢰성 높은 디지털 전송 선로 상에서 고속으로 패킷을 교환하는 L2 데이터 링크 계층 기반의 광역 통신망(WAN) 프로토콜 (ITU-T I.122 / Q.922).
- 배경 및 필요성 : 과거 잡음이 많던 아날로그 회선 시절 개발된 X.25는 노드마다 홉 바이 홉(Hop-by-Hop) 오류 확인을 수행하여 전송 지연이 극심했으나, 1990년대 광케이블 등 전송 매체의 품질이 획기적으로 개선되면서 고속 패킷 스위칭 요구 대두.
- 핵심 목적 : 통신망 오버헤드 최소화를 통한 고속 WAN 데이터 전송, 단일 물리 회선에 복수의 논리적 가상 회선(VC) 다중화, 저비용 엔터프라이즈 지사 간 메시 망 구축.

## Ⅱ. 프레임릴레이의 핵심 아키텍처 및 동작 메커니즘

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ 프레임릴레이 헤더 구조 및 혼잡 제어 ]              │
│                                                                        │
│   ┌───────┬──────────────────────────┬──────────────┬─────────┬───────┐│
│   │ 플래그│     프레임릴레이 헤더     │ 사용자 데이터│   FCS   │ 플래그││
│   │ 1 Byte│          2 Byte          │ (가변 길이)  │ 2 Byte  │ 1 Byte││
│   └───────┴──────────────────────────┴──────────────┴─────────┴───────┘│
│                               │                                        │
│           ┌───────────────────┴───────────────────┐                    │
│           │ DLCI (상위 6bit) │ C/R (1bit) │ EA (1bit) │                    │
│           ├──────────────────┴────────────┴───────────┤                    │
│           │ DLCI (하위 4bit) │ FECN │ BECN │ DE │ EA  │                    │
│           └───────────────────────────────────────────┘                    │
│                                                                        │
│   [ 주요 제어 비트 동작 메커니즘 ]                                     │
│   - DLCI (10bit) : 가상 회선 식별자 (총 1024개, 로컬 유의미)          │
│   - FECN (Forward) : 수신측 방향으로 경로 상에 혼잡 발생 통보          │
│   - BECN (Backward) : 송신측 방향으로 역방향 전송률 감축 통보          │
│   - DE (Discard Eligibility) : 혼잡 시 스위치가 우선 폐기 가능한 비트  │
└────────────────────────────────────────────────────────────────────────┘
```

- **가상 회선 다중화 (Virtual Circuit)** : 단일 물리 인터페이스 상에 여러 개의 영구 가상 회선(PVC) 또는 교환 가상 회선(SVC)을 설정하여 점대다(Point-to-Multipoint) 연결.
- **오류 제어의 상위 계층 위임** : 스위치 노드에서 손상된 프레임을 발견하면 재전송 요구 없이 즉시 폐기(Drop)하고, 오류 복구 및 흐름 제어는 종단의 L4(TCP) 계층이 전담.
- **대역폭 할당 및 SLA 파라미터** :
  - **CIR (Committed Information Rate)** : 통신 사업자가 평상시 보장하는 최소 보장 대역폭.
  - **EIR (Excess Information Rate)** : 망에 여유가 있을 때 초과 전송 가능한 버스트 대역폭 (해당 프레임에는 DE=1 세팅).
  - **혼잡 시 폐기 우선순위** : 망 혼잡 발생 시 스위치는 $DE=1$로 마킹된 초과 트래픽을 가장 먼저 폐기.

## Ⅲ. X.25, 프레임릴레이, 현대 MPLS 기술의 세부 비교 분석

| 비교 항목 | X.25 | 프레임릴레이 (Frame Relay) | MPLS (Multiprotocol Label) |
|---|---|---|---|
| 동작 계층 | L3 (네트워크 계층) | L2 (데이터 링크 계층) | L2.5 (레이블 스위칭) |
| 오류 제어 방식 | 노드 간(Hop-by-Hop) 전수 검사 | 에러 검출 시 단순 폐기 (종단 전담) | 하드웨어 기반 빠른 포워딩 |
| 흐름/혼잡 제어 | 홉 단위 엄격한 윈도우 흐름 제어| FECN / BECN 명시적 혼잡 통보 | RSVP-TE 트래픽 엔지니어링, QoS |
| 최대 전송 속도 | 수십 Kbps ~ 최대 2 Mbps | 일반적으로 T1/E1 (1.54~2Mbps) ~ 45Mbps | 수십 Gbps ~ 수백 Gbps 초고속 |
| 주요 식별자 | LCN (Logical Channel Number) | DLCI (10비트 가상 회선 식별자) | 20비트 MPLS 라벨 (Label) |
| 현재의 위상 | 완전 단종 (레거시 박물관) | MPLS 및 SD-WAN으로 전면 대체 | 현재 통신사 백본의 핵심 중추 |

- **LMI (Local Management Interface)** : 라우터(DTE)와 프레임릴레이 스위치(DCE) 간에 PVC의 활성 상태(`Active`, `Inactive`, `Deleted`)를 동기화하고 Keepalive를 유지하는 확장 관리 규격.

## Ⅳ. 프레임릴레이의 주요 한계점 및 퇴출 원인

- 비보증 대역폭(EIR) 구간에서의 패킷 폐기율 및 지터 불안정 :
  - 한계점 : 망 혼잡 시 백본 스위치에서 DE=1 트래픽이 무차별 폐기되어 VoIP 음성 통화 끊김 및 실시간 트래픽 품질 보장 불가.
  - 해결 방안 : 엄격한 하드웨어 QoS 큐잉과 대역폭 보장을 지원하는 ATM 및 차등화 서비스(DiffServ) 기반 IP-VPN으로 전환.
- 인터넷 광대역 통신망 및 SD-WAN 대비 터무니없이 높은 회선 비용 :
  - 한계점 : 전용선 기반의 복합 계약 구조로 인해 일반 인터넷 브로드밴드 대비 대역폭 대비 비용이 극도로 비효율적.
  - 해결 방안 : 저비용 공용 초고속 인터넷 회선 다수를 소프트웨어적으로 묶어 암호화 오버레이를 구축하는 SD-WAN(Software-Defined WAN) 전면 도입.

## Ⅴ. 프레임릴레이 적용 및 발전을 위한 기술사적 제언

- 네트워크 진화론적 아키텍처 관점의 시사점 : '신뢰성 높은 물리 계층 환경에서는 중복된 하위 계층 제어를 제거하고 단순화할수록 처리 성능이 극대화된다'는 엔드투엔드 원칙(End-to-End Argument)의 성공적 증명 사례.
- 레거시 인프라의 완전한 SD-WAN 마이그레이션 추진 : 아직 일부 공공·금융 및 해외 지사에 남아있는 프레임릴레이 및 구형 전용회선을 제로터치 프로비저닝(ZTP)과 IPsec 터널링을 지원하는 SD-WAN 패브릭으로 100% 현대화.
- SLA 기반 트래픽 엔지니어링 교훈의 클라우드 적용 : CIR/EIR의 보장-초과 트래픽 제어 사상을 클라우드 네이티브 네트워크(AWS Direct Connect, Azure ExpressRoute)의 대역폭 셰이핑 및 버스트 폴리싱 설계에 응용.
