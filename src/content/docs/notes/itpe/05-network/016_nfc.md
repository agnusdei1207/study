## 30초 인출

- 본질: **NFC** : 가까이 댄 기기·태그가 13.56MHz 근거리 무선으로 데이터를 주고받는 통신 기술
- 메커니즘: 리더가 태그를 읽거나, 단말이 카드처럼 동작하거나, 두 단말이 직접 정보를 교환
- 통찰: 13.56MHz 고주파 대역의 전자기 유도 결합을 이용하여 10cm 이내의 초근거리에서 기기 간 페어링 절차 없이 직관적인 터치만으로 보안 결제, 데이터 교환 및 태그 인식을 수행하는 근거리 무선 통신 기술임.

<details>
<summary>핵심 용어</summary>

- **NFC(Near Field Communication)** : 13.56MHz 대역을 사용하는 근거리 비접촉 통신 기술
- **리더/라이터(Reader/Writer)** : 단말이 NFC 태그의 데이터를 읽거나 쓰는 동작 방식
- **카드 에뮬레이션(Card Emulation)** : 단말이 비접촉 카드처럼 리더에 응답하는 동작 방식
- **P2P(Peer-to-Peer)** : 두 NFC 단말이 직접 데이터를 교환하는 동작 방식
- **NDEF(NFC Data Exchange Format)** : NFC 기기·태그 간 애플리케이션 데이터를 표현하는 공통 형식
- **SE(Secure Element)** : 비밀 정보·보안 연산을 격리하는 보안 구성 요소
- **HCE(Host Card Emulation)** : 카드 에뮬레이션 처리를 단말의 호스트 소프트웨어에서 수행하는 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. NFC(Near Field Communication)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 13.56MHz 주파수 대역을 사용하여 10cm 이내의 비접촉 근거리에서 단말 간 양방향 데이터 통신을 지원하는 비접촉식 무선 통신 표준(ISO/IEC 18092) |
| 목적 | 복잡한 사전 페어링 절차 없는 직관적 터치 기반 간편 결제(모바일 페이), 출입 통제, 스마트 태그 정보 획득 및 IoT 기기 간 간편 연동 |

## Ⅱ. NFC(Near Field Communication)의 특징

| 특징 | 상세 내용 |
|---|---|
| 전자기 유도 결합 | 송신측 코일의 고주파 전류로 유도 기전력을 발생시켜 무전원 수동형 태그까지 구동 |
| 초근거리 전송(10cm) | 물리적 도달 거리가 극히 짧아 제3자의 무선 도청(Eavesdropping)을 공간적으로 원천 차단 |
| 3대 동작 모드 지원 | 카드 에뮬레이션, 읽기/쓰기(Reader/Writer), 단말 간 통신(P2P)을 단일 칩셋에서 모두 지원 |
| 상호 호환성 보장 | 기존 교통카드 인프라인 ISO 14443 Type A/B 및 Sony FeliCa 표준과 완벽한 하위 호환성 유지 |

## Ⅲ. NFC(Near Field Communication)의 체계·프로세스

**NFC 3대 동작 모드 및 데이터 통신 아키텍처**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ NFC 3대 동작 모드 체계 ]                      │
│                                                                        │
│   [ 1. 카드 에뮬레이션 모드 ]  [ 2. 리더 / 라이터 모드 ]  [ 3. P2P 모드 ] │
│                                                                        │
│     스마트폰 ──► 외부 리더기      스마트폰 ──► 무전원 태그    스마트폰 ◄──► 스마트폰│
│   (교통카드, 모바일 결제)     (포스터 태그 정보 읽기)     (명함, 사진, 연락처) │
│                                                                        │
│   ┌───────────────────────────┐                 ┌──────────────────┐   │
│   │ [ 스마트폰 호스트 OS ]    │                 │ [ 스마트폰 B ]   │   │
│   │   - 애플리케이션 (Pay)    │                 │                  │   │
│   │   - NFC 서비스 프레임워크 │                 │                  │   │
│   └─────────────┬─────────────┘                 └────────┬─────────┘   │
│                 │                                        │             │
│   ┌─────────────┴─────────────┐                          │             │
│   │ NFC 컨트롤러 (13.56MHz)   │◄═════ 13.56MHz RF ═══════┘             │
│   │   - 루프 안테나           │                                        │
│   └─────────────┬─────────────┘                                        │
│                 │                                                      │
│   ┌─────────────┴─────────────┐                                        │
│   │ 보안 요소 (SE: eSE, USIM) │ (HCE 적용 시 소프트웨어 에뮬레이션)     │
│   └───────────────────────────┘                                        │
└────────────────────────────────────────────────────────────────────────┘
```

| 동작 모드 | 데이터 통신 방향 | 능동/수동 상태 | 주요 적용 분야 |
|---|---|---|---|
| **카드 에뮬레이션** | 스마트폰 ──► POS 리더기 | 단말이 수동 태그처럼 동작 | 모바일 교통카드, 애플페이/삼성페이 결제, 도어록 출입증 |
| **리더 / 라이터** | 스마트폰 ──► NFC 태그 | 단말이 능동 송신기로 동작 | 스마트 포스터 정보 인식, 전자제품 Wi-Fi 간편 설정 태그 |
| **P2P 모드** | 스마트폰 ◄──► 스마트폰 | 두 단말이 교대로 능동 동작 | 연락처 교환, 블루투스/Wi-Fi 다이렉트 간편 페어링 유도 |

## Ⅳ. NFC(Near Field Communication)의 종류·비교

| 비교 항목 | NFC | 블루투스 (BLE) | 지그비 (Zigbee) |
|---|---|---|---|
| **표준 규격** | ISO/IEC 18092 | IEEE 802.15.1 | IEEE 802.15.4 |
| **동작 주파수** | 13.56 MHz | 2.4 GHz ISM 대역 | 2.4 GHz / 868 / 915 MHz |
| **통신 도달 거리** | 10 cm 이내 (접촉 수준) | 10 m ~ 100 m | 10 m ~ 70 m |
| **데이터 전송 속도**| 최대 424 kbps | 1 ~ 3 Mbps (BLE 최대 2M) | 250 kbps |
| **페어링 시간** | 즉시 (< 0.1초, 터치 방식) | 약 수 초 (탐색 및 PIN 인증)| 네트워크 조인 시간 소요 |
| **핵심 목적** | 결제, 보안 출입, 직관적 터치| 개인 영역 기기 연결 (이어폰, 워치)| 스마트홈 센서 저전력 메시 네트워킹 |

## Ⅴ. NFC(Near Field Communication)의 한계와 방안

| 한계 | 방안 |
|---|---|
| 전자기 유도 특성상 고주파 안테나 근접 시 지향성 도청 및 릴레이 공격(Relay Attack) 위험 | 트랜잭션 왕복 시간(RTT)을 측정하는 거리 측정(Distance Bounding) 프로토콜 및 토큰화(Tokenization) 적용 |
| 하드웨어 기반 SE(Secure Element) 칩셋 탑재 시 통신사/제조사 간 주도권 갈등 및 발급 비용 증가 | 호스트 CPU 메모리에서 암호화 토큰을 동적 처리하는 HCE(Host Card Emulation) 기술 도입 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
금융 모바일 결제 및 기업 사원증 시스템 구축 시, 하드웨어 eSE(embedded SE) 방식은 최고 수준의 물리적 보안을 제공하나 배포가 복잡하므로, 클라우드 토큰화 서버와 연계된 HCE 방식을 표준으로 채택하고 앱 위변조 방지 및 1회용 결제 토큰(Dynamic CVV)을 결합 적용.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ NFC 모바일 결제 보안 모델 비교 : 하드웨어 SE vs 소프트웨어 HCE ]     │
│                                                                        │
│   [ 하드웨어 SE 방식 (Secure Element) ]                                │
│   NFC Controller ──(물리 배선)──► [ 하드웨어 SE (eSE / USIM) ]         │
│                                   (OS 침해 시에도 암호키 완벽 보호)    │
│                                                                        │
│   [ 소프트웨어 HCE 방식 (Host Card Emulation) ]                        │
│   NFC Controller ──► [ Android OS Kernel ] ──► [ HCE 서비스 앱 ]       │
│                                                      │                 │
│                                                      ▼ (TLS 전송)      │
│                                            [ 결제사 클라우드 토큰 서버] │
│                                            (1회용 일회성 가상 카드번호)│
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 보안 모델 | 암호키 저장 위치 | 보안성 수준 | 서비스 배포 유연성 | 대표 적용 서비스 |
|---|---|---|---|---|
| **UICC/USIM (SE)** | 통신사 발급 스마트카드 | 최상 (EAL5+ 하드웨어) | 낮음 (통신사 인프라 종속) | 모바일 티머니, 캐시비 |
| **Embedded SE (eSE)** | 스마트폰 메인보드 칩셋 | 최상 (EAL5+ 하드웨어) | 중간 (제조사 제휴 필요) | Apple Pay, 삼성페이 |
| **HCE (Host-based)** | 스마트폰 메모리 및 클라우드 | 높음 (토큰화 보안 결합) | 최우수 (순수 소프트웨어 앱)| 구글 월렛, 신용카드사 자체 앱 |
