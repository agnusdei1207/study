## 핵심 용어

- NDEF(NFC Data Exchange Format): NFC 포럼이 제정한 가볍고 이진화된 공통 데이터 포맷. URL, 텍스트, MIME 미디어 등을 캡슐화
- SE(Secure Element): 금융 결제 시 카드 정보, 개인 암호화 키를 하드웨어적으로 격리된 안전 칩셋(eSE, USIM, microSD)에 저장해 보호하는 보안 영역
- 릴레이 공격(Relay Attack): 공격자가 피해자의 NFC 카드와 실제 결제 단말기 사이의 신호를 원거리에서 무선 중계하여 피해자 모르게 결제를 유발하는 중간자 공격

## 1교시 10점 답안

### 정의·목적

- 정의: NFC은/는 13.56MHz 전자기 유도 방식을 채택해 10cm 이내 접근만으로 양방향 통신 및 단말 에뮬레이션 수행 방식이다.
- 목적: 직관적 터치 결제와 데이터 교환에 기여한다.

### 핵심 구조와 작동

```text
[ NFC 3대 동작 모드 (Operating Modes) ]

1. 카드 에뮬레이션 모드 (Card Emulation)
   스마트폰 (SE 내장) =============> 결제 단말기 (POS/교통카드 게이트)
   (스마트폰이 교통카드나 신용카드처럼 수동형 태그로 동작)

2. 리더 / 라이터 모드 (Reader / Writer)
   스마트폰 (능동형 리더) =========> 스마트 포스터 / NFC 스티커 (수동 태그)
   (스마트폰이 태그의 URL, 텍스트 NDEF 데이터를 읽거나 쓰기)

3. P2P 모드 (Peer-to-Peer, ISO 18092)
   스마트폰 A <=====================> 스마트폰 B
   (두 단말이 능동적으로 링크를 맺고 연락처, 사진, 와이파이 인증 정보 교환)
```

## 2~4교시 25점 답안

### Ⅰ. 핵심 구조와 작동

```text
[ NFC 3대 동작 모드 (Operating Modes) ]

1. 카드 에뮬레이션 모드 (Card Emulation)
   스마트폰 (SE 내장) =============> 결제 단말기 (POS/교통카드 게이트)
   (스마트폰이 교통카드나 신용카드처럼 수동형 태그로 동작)

2. 리더 / 라이터 모드 (Reader / Writer)
   스마트폰 (능동형 리더) =========> 스마트 포스터 / NFC 스티커 (수동 태그)
   (스마트폰이 태그의 URL, 텍스트 NDEF 데이터를 읽거나 쓰기)

3. P2P 모드 (Peer-to-Peer, ISO 18092)
   스마트폰 A <=====================> 스마트폰 B
   (두 단말이 능동적으로 링크를 맺고 연락처, 사진, 와이파이 인증 정보 교환)
```

### Ⅱ. 핵심 특성

- 통신 거리가 10cm 이내로 극히 짧다는 물리적 특성 자체가 "사용자의 결제 의도"를 증명하는 강력한 1차 보안 장치 역할을 수행
- 전파 도달 거리가 짧아 도청이 불가능하다는 통념은 오해이며, 고성능 지향성 안테나를 사용하면 수 미터 밖에서도 13.56MHz 유도 기전력 신호 도청 가능
- 최신 스마트폰 결제(애플페이, 삼성페이)는 고정된 카드 번호를 보내지 않고 1회용 결제 토큰(Tokenization)과 생체 인증을 결합해 도청 및 재전송 공격을 무력화

### Ⅲ. 관련 개념과 구분

- NFC vs RFID: RFID는 주로 수 미터 거리에서 단방향 태그 식별 위주 / NFC는 10cm 이내에서 1:1 양방향 통신, 단말 카드 에뮬레이션, 태그 읽기/쓰기를 모두 지원

### Ⅳ. 적용 문제와 대응

- 적용 상황: 모바일 비접촉 결제 환경의 무단 결제 공격
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 원거리 릴레이 공격으로 무단 결제 발생 | 공격자가 중계기를 통해 카드와 POS 간 물리적 거리 검증을 우회 | RTT 기반 거리 측정(Distance Bounding) 및 생체 인증 필수화 | 허용 응답 시간(수 ms) 초과 시 결제 즉시 거절 |
| 전자기장 도청에 의한 카드 번호 탈취 | 13.56MHz 통신 패킷의 평문 노출 | Secure Element(SE) 내 HCE 토큰화 및 AES 세션 암호화 | 노출된 데이터가 1회용 토큰이므로 재사용 공격 차단 |

### Ⅴ. 기술사적 제언

| 문제 | 해결 방안 |
|---|---|
| 적용 환경에서 발생하는 핵심 제약 | 기존 대책을 적용하고 핵심 운영 지표를 확인해 개선한다. |
