## 연관 키워드

- 슬라이딩 윈도우(Sliding Window), 흐름 제어(Flow Control), 송신 윈도우(Send Window), 수신 윈도우(Receive Window)
- 파이프라이닝(Pipelining), 누적 확인 응답(Cumulative ACK), 0 윈도우(Zero Window)
- 정지-대기 방식(Stop-and-Wait), 윈도우 확장 옵션(Window Scale), 대역폭-지연 곱(BDP, Bandwidth-Delay Product)

## Ⅰ. 슬라이딩 윈도우의 개요

- 핵심 요약 : 확인 응답 대기 없이 윈도우 범위만큼 연속 전송하면서 수신 능력에 맞춰 전송량을 조절하는 흐름 제어 기법.
- 개념 : 확인 응답 없이 보낼 수 있는 데이터 범위인 **윈도우** (Window)를 두고, 응답 도착에 따라 윈도우를 앞으로 옮겨 가며 전송하는 **흐름 제어** (Flow Control) 방식인 **슬라이딩 윈도우** (Sliding Window) 기법.
- 배경 및 필요성 : 프레임 하나마다 응답을 기다리는 정지-대기 방식(Stop-and-Wait)은 회선 대역폭과 왕복 지연이 큰 장거리 고속 회선에서 전송 능력 대부분을 유휴 상태로 두는 문제가 있었음.
- 주요 목적 : 연속 전송을 통한 회선 이용률 향상과 수신 버퍼 용량 초과 전송의 방지.

## Ⅱ. 슬라이딩 윈도우의 특징 및 장점

- 핵심 요약 : 연속 전송과 가변 윈도우 통지가 회선 활용과 수신 측 보호를 동시에 실현하는 제어 구조.

1. 연속 전송 : **파이프라이닝** (Pipelining, 응답 대기 없는 연속 전송)으로 윈도우 크기만큼 송출 → 왕복 지연 구간에도 회선이 가동되는 전송 효율 향상.
2. 동적 조절 : 수신 측이 남은 버퍼 크기를 데이터에 실어 통지 → 수신 처리 능력에 맞춘 전송량 조절.
3. 응답 절약 : **누적 확인 응답** (Cumulative ACK, 특정 번호까지의 수신 완료를 한 번에 알리는 응답) 사용 → 역방향 응답 트래픽 감소.
4. 오류 제어 연계 : 윈도우 내 미확인 데이터만 추적 → 재전송 대상이 명확해 오류 제어와의 결합이 단순.

## Ⅲ. 슬라이딩 윈도우의 구조 (흐름)

- 핵심 요약 : ACK 도착분만큼 송신 윈도우가 전진하고, 수신 측 통지 값이 전진 폭의 상한이 되는 이중 구조.
- **송신 윈도우** (Send Window) : 확인 응답 없이 보낼 수 있는 데이터의 범위로, 전송 후 미확인 구간과 전송 대기 구간을 포함.
- **수신 윈도우** (Receive Window) : 수신 측이 버퍼 여유분을 송신 측에 통지하는 크기 값으로, 송신 윈도우의 실질 상한.

```text
[ 송신 윈도우의 이동 ]

전송 가능 : F1~F4 (윈도우 크기 4)
   ↓ F1·F2 전송 → 미확인 상태
F1 ACK 도착
   ↓
윈도우 전진 → F5 신규 전송
   ↓
ACK마다 전진 반복
```

```text
[ 수신 버퍼 포화 절차 ]

수신 버퍼 가득 참
   ↓
윈도우 크기 0 통지
   ↓
송신 측 전송 중지
   ↓
주기 확인으로 여유 감지
   ↓
윈도우 재통지 → 전송 재개
```

- **0 윈도우** (Zero Window) : 수신 버퍼 포화를 알리는 윈도우 크기 0의 통지 상태.

## Ⅳ. 슬라이딩 윈도우와 대안 방식의 비교

- 핵심 요약 : 정지-대기는 단순하지만 회선을 유휴로 두고, 크레딧 기반은 손실 없는 링크용이며, 슬라이딩 윈도우는 광역 데이터 전송의 표준 해법.

| 비교 축 | 정지-대기 방식 | 슬라이딩 윈도우 | 크레딧 기반 방식 |
| --- | --- | --- | --- |
| 연속 전송 | 불가 (1프레임당 응답) | 가능 | 가능 |
| 제어 정보 | 응답 도착 여부 | 가용 윈도우 크기 | 크레딧(버퍼 슬롯 수) |
| 회선 이용률 | 왕복 지연에 비례해 저하 | 높음 | 높음 |
| 요구 버퍼 | 최소 | 양단 완충 버퍼 | 고정 슬롯 버퍼 |
| 대표 적용 | 단순 저속 링크 | TCP 전송 계층 | 파이버 채널(Fibre Channel) 등 고속 패브릭 |

- 선택 기준 : 대역폭-지연 곱(BDP, Bandwidth-Delay Product)이 큰 데이터 회선에는 슬라이딩 윈도우를, 손실이 없고 자원 배분이 엄격한 장치 간 링크에는 크레딧 기반을 적용.

## Ⅴ. 슬라이딩 윈도우의 한계와 방안

- 핵심 요약 : 윈도우 크기 표현 한계, 0 윈도우 대기, 과대 윈도우 지연을 확장 옵션·프로브·자동 튜닝으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 크기 표현 한계 | 헤더 필드의 비트 수로 표현 가능한 윈도우가 제한되어 고속·장거리 회선을 다 쓰지 못함 | **윈도우 확장 옵션** (Window Scale, 실질 윈도우 배율을 지정하는 TCP 헤더 옵션) 적용 | 회선 이용률 |
| 0 윈도우 대기 지속 | 여유 통지가 유실되면 송신 측이 정지 상태로 머무는 위험 | 주기적 확인 프로브로 수신 상태 재질의 | 회복 지연 시간 |
| 과대 윈도우 지연 | 윈도우가 네트워크 수용 능력을 초과하면 중간 장비 큐 적체로 지연 증가 | 버퍼 자동 튜닝으로 대역폭-지연 곱 수준에 맞춤 | 큐 지연·재전송률 |

## Ⅵ. 슬라이딩 윈도우에 대한 기술사적 제언

- 핵심 요약 : 윈도우·버퍼 파라미터를 망 조건 기반의 관리 대상으로 격상하는 운영 체계 필요.
- 인프라 운영 조직 : 회선 속도와 지연 측정값에 근거한 윈도우·버퍼 기준값을 수립하고 변경 이력을 문서화.
- 응용 개발 조직 : 대용량 전송 서비스의 성능 시험 항목에 윈도우 설정 검증을 포함해 회선 투자 대비 효과를 확인.
- 클라우드 사업 조직 : 인스턴스 등급별 네트워크 버퍼 기본값과 튜닝 가이드를 제공해 고객 장애 예방.

## Ⅶ. 결론

- 핵심 요약 : 슬라이딩 윈도우는 연속 전송의 효율과 수신 측 보호를 한 장치로 결합한 흐름 제어의 기본형.
- 망의 대역폭-지연 곱에 맞춘 윈도우 운영이 고속 회선 성능의 성패를 가름.
