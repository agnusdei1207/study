## Ⅰ. 거리벡터 라우팅(Distance Vector Routing)의 개요

- 개념 : 분산형 **벨만-포드(Bellman-Ford)** 최단 경로 알고리즘을 기반으로, 각 라우터가 인접한 이웃 라우터들과 주기적으로 자신의 전체 라우팅 테이블을 교환하며 목적지까지의 방향(Vector)과 거리(Distance)를 계산하는 동적 라우팅 기법.
- 배경 및 필요성 : 인터넷 초기 복잡한 중앙 제어기나 고성능 CPU/메모리 없이도 각 노드가 이웃과의 최소 정보 교환만으로 자율 분산 라우팅 경로를 수립하기 위해 고안.
- 핵심 목적 : 단순한 연산과 저용량 메모리 환경에서의 자동 경로 학습, 소규모 네트워크에서의 신속한 동적 토폴로지 반영.

## Ⅱ. 거리벡터 라우팅의 핵심 아키텍처 및 동작 메커니즘

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ 거리벡터 벨만-포드 갱신 메커니즘 ]                  │
│                                                                        │
│   공식: D_x(y) = min_v { c(x,v) + D_v(y) }                             │
│   (x에서 y까지의 최단거리는 인접이웃 v로 가는 비용 + v에서 y까지 거리) │
│                                                                        │
│   [ Router A ]                    [ Router B ]          [ Dest Net Y ] │
│   ┌──────────────┐                ┌──────────────┐      ┌────────────┐ │
│   │ Routing Table│ 주기적 브로드캐스트│ Routing Table│      │            │ │
│   │ Dest Metric  ├───────────────►│ Dest Metric  ├───►  │  10.1.1.0  │ │
│   │  Y     1     │ (전체 복사 전달)│  Y   1+1=2   │      │            │ │
│   └──────────────┘ "소문에 의한   └──────────────┘      └────────────┘ │
│                     라우팅"                                            │
│                                                                        │
│   [ 링크 장애 발생 시 무한 루프 위험 : Count-to-Infinity ]             │
│   A-Y 링크 단절 ──► B가 A에게 "내가 Y까지 2홉에 간다"고 거짓 전파       │
│   ──► A는 3홉으로 갱신 ──► B는 4홉으로 갱신 ──► 홉수 무한 증가 폭주   │
└────────────────────────────────────────────────────────────────────────┘
```

- **벨만-포드 알고리즘 기반 계산** : 인접 이웃이 광고한 목적지 거리($D_v(y)$)에 이웃 노드까지의 링크 비용($c(x,v)$)을 더한 값 중 최소값을 자신의 다음 홉(Next Hop) 및 거리로 채택.
- **소문에 의한 라우팅 (Routing by Rumor)** : 전체 네트워크 토폴로지 지도를 보지 못하고, 인접 이웃 라우터가 알려준 요약 거리 벡터 정보만을 맹목적으로 신뢰하여 경로 결정.
- **주기적 전체 광고 (Periodic Update)** : RIP의 경우 기본 30초 주기로 자신의 전체 라우팅 테이블을 브로드캐스트 또는 멀티캐스트로 전파.

## Ⅲ. 세부 구성 요소 및 루프 방지 메커니즘 비교 분석

| 루프 방지 기술 | 동작 메커니즘 | 기술적 한계 및 보완 |
|---|---|---|
| **최대 홉 수 제한 (Hop Count Limit)** | 최대 홉 수를 15로 제한하고, 16을 도달 불가(Unreachable) 무한대로 정의 | 네트워크 규모가 직경 15홉 이내로 극단적 제한 |
| **수평 분할 (Split Horizon)** | 특정 인터페이스를 통해 학습한 경로 정보는 동일 인터페이스로 다시 광고 금지 | 단순 직렬망에서만 유효, 삼각 루프 토폴로지 방어 한계 |
| **독성 역전 (Poison Reverse)** | 특정 경로 수신 인터페이스로 해당 경로 광고 시 메트릭을 16(무한대)으로 역송출 | 대역폭 오버헤드 다소 증가하나 명시적 경로 무효화 달성 |
| **유지 타이머 (Holddown Timer)** | 다운된 경로 정보를 수신하면 일정 시간(RIP 180초) 동안 더 나쁜 메트릭 업데이트 수용 거부 | 라우팅 수렴 속도가 비약적으로 느려지는 역효과 초래 |
| **즉각 갱신 (Triggered Update)** | 토폴로지 변경 감지 즉시 주기적 30초 대기 없이 즉각 업데이트 패킷 송출 | 일시적 네트워크 폭주(Broadcast Storm) 유발 가능 |

- 거리벡터 vs 링크상태 핵심 비교 :
  - 거리벡터(RIP)는 연산 부하가 극히 낮으나 수렴 속도가 느리고 대규모 망에 부적합.
  - 링크상태(OSPF)는 전체 토폴로지 LSDB를 유지하고 다익스트라 연산을 수행하여 초 단위로 수렴하며 루프가 원천 배제됨.

## Ⅳ. 거리벡터 라우팅의 주요 한계점 및 해결 방안

- 무한 계수(Count-to-Infinity) 현상 및 느린 수렴(Slow Convergence) :
  - 한계점 : 링크 단절 시 상호 간의 낡은 라우팅 정보가 순환 참조되며 홉 수가 16에 도달할 때까지 수 분간 패킷 핑퐁 루프 지속.
  - 해결 방안 : Split Horizon과 Poison Reverse를 병행 적용하고, EIGRP와 같이 Feasibility Condition을 검증하는 DUAL 알고리즘 또는 링크상태 프로토콜로 전환.
- 홉 수 메트릭의 대역폭 미반영에 따른 비효율적 경로 선택 :
  - 한계점 : 1Gbps 초고속 링크 2홉보다 64Kbps 저속 시리얼 링크 1홉을 더 최적 경로로 오판단하는 치명적 맹점.
  - 해결 방안 : 홉 수 대신 회선 대역폭, 지연시간, MTU, 신뢰도를 복합 계산하는 EIGRP 복합 메트릭이나 OSPF 인터페이스 Cost 체계 도입.

## Ⅴ. 거리벡터 라우팅 적용 및 발전을 위한 기술사적 제언

- 원격 소규모 브랜치 및 레거시 망에서의 선별적 유지 : 단말 수가 적고 토폴로지 변화가 거의 없는 단순 허브앤스포크 말단 지선망에서는 CPU 점유가 적은 거리벡터(RIPv2)를 최소한으로 운용.
- BGP(Path Vector)로의 알고리즘 철학 계승 : 거리벡터의 무한 루프 한계를 극복하기 위해 거리 대신 경유 AS 경로 목록 전체를 기록하는 패스 벡터(Path Vector) 알고리즘으로 발전하여 인터넷 백본의 중추로 정착.
- SDN 기반 센트럴 컨트롤러로의 전환 : 분산 노드 간의 불완전한 소문 기반 라우팅을 지양하고, 중앙 컨트롤러가 글로벌 토폴로지를 실시간 수집하여 최적 흐름 경로를 하향 주입하는 소프트웨어 정의 라우팅 체계 구축.
