## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 네트워크 라우팅 → **거리벡터 라우팅(Distance Vector Routing)**

## 30초 인출

- 본질: **거리벡터 라우팅(Distance Vector Routing)** : 벨만-포드(Bellman-Ford) 알고리즘을 기반으로 인접한 이웃 라우터와 주기적으로 라우팅 테이블(목적지, 거리/비용, 다음 홉)을 교환하여 최적 경로를 분산 결정하는 라우팅 방식
- 메커니즘: 점화식 $D_x(y) = \min_v \{ c(x,v) + D_v(y) \}$를 적용하여 최소 비용 경로를 반복 갱신하며, RIP(홉 수 메트릭), BGP(경로 벡터) 등의 기반 이론으로 활용
- 통찰: 전체 망 토폴로지를 파악하지 않고 이웃의 전언(Routing by Rumor)에만 의존하므로 링크 장애 시 무한 계수(Count-to-Infinity) 및 라우팅 루프가 발생하여 Split Horizon, Poison Reverse, Triggered Update 등 다층 루프 방지책 연계 필수

<details>
<summary>핵심 용어</summary>

- **벨만-포드 알고리즘 (Bellman-Ford Algorithm)** : 그래프에서 단일 출발지로부터 모든 정점까지의 최단 경로를 구하는 동적 계획법 기반 알고리즘
- **Count-to-Infinity (무한 계수 현상)** : 경로 단절 시 이웃 간에 구 정보가 상호 참조되어 메트릭 값이 무한히 증가하며 패킷이 순환하는 라우팅 루프 현상
- **Split Horizon (수평 분할)** : 특정 인터페이스를 통해 학습한 라우팅 정보는 동일한 인터페이스로 되돌려 보내지 않는 루프 방지 기법
- **Poison Reverse (독 역전)** : 특정 인터페이스로 수신한 경로를 해당 인터페이스로 회신할 때 메트릭 값을 '도달 불가(무한대)'로 명시하여 즉시 무효화하는 기법
- **Triggered Update (긴급 갱신)** : 정기 광고 주기(30초)를 기다리지 않고 토폴로지 변경 감지 즉시 이웃에게 갱신 정보를 전송하는 신속 수렴 기법

</details>

## 2~4교시 25점 답안

## Ⅰ. 거리벡터 라우팅의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 각 라우터가 인접 라우터와 방향(Vector)과 거리(Distance/Cost) 정보만을 주기적으로 교환하여 분산적으로 최적 경로를 계산하는 동적 라우팅 방식 |
| 목적 | 라우터의 CPU·메모리 자원 소모를 최소화하면서 소규모 자율 시스템(AS) 내에서 자동화된 경로 설정 및 장애 우회 경로 확보 |

## Ⅱ. 거리벡터 라우팅의 특징 및 핵심 메커니즘

| 특징 항목 | 상세 내용 |
|---|---|
| **분산 계산 (Distributed)** | 각 라우터는 전체 네트워크 지도를 갖지 않고 오직 직접 연결된 이웃 라우터의 계산 결과만 수집하여 로컬에서 갱신 |
| **반복 수행 (Iterative)** | 이웃 라우터로부터 새 벡터를 수신할 때까지 대기하며, 비용 변경이 없을 때까지 지속적으로 교환·수렴 |
| **비동기 동작 (Asynchronous)** | 모든 라우터가 동시에 정보를 교환할 필요 없이 로컬 타이머(예: 30초 주기)에 따라 독자적으로 브로드캐스트/멀티캐스트 전송 |
| **전언 기반 라우팅 (Routing by Rumor)** | 직접 확인한 링크 상태가 아닌 이웃 라우터가 알려준 간접 정보를 신뢰하여 포워딩 테이블을 구축하므로 잘못된 정보 전파에 취약 |

## Ⅲ. 거리벡터 경로 계산 아키텍처 및 갱신 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ 거리벡터 라우팅 최단 경로 계산 메커니즘 ]          │
│                                                                        │
│                   [이웃 라우터 V]                                      │
│                      ▲       \ D_v(Y) = 2                              │
│         c(X, V) = 1  │        \                                        │
│                      │         ▼                                       │
│   [라우터 X] ────────┴───────► [목적지 Y]                              │
│                      │         ▲                                       │
│         c(X, W) = 5  │        /                                        │
│                      ▼       / D_w(Y) = 1                              │
│                   [이웃 라우터 W]                                      │
│                                                                        │
│   * 라우터 X의 목적지 Y 최단 거리 계산:                                │
│     - 경유 V: c(X,V) + D_v(Y) = 1 + 2 = 3                             │
│     - 경유 W: c(X,W) + D_w(Y) = 5 + 1 = 6                             │
│     => D_x(Y) = min{3, 6} = 3 (Next-Hop: Router V 선택)               │
└────────────────────────────────────────────────────────────────────────┘
```

| 계산 및 갱신 단계 | 세부 동작 메커니즘 |
|---|---|
| **초기화 (Init)** | 각 라우터는 자신과 직접 연결된 이웃 링크 비용(Hop=1 등)만 라우팅 테이블에 등록하고 원격지는 도달 불가(무한대) 설정 |
| **벡터 광고 (Advertise)** | 자신의 라우팅 테이블 전체를 인접 이웃에게 정기적(예: RIP 30초)으로 브로드캐스트 또는 멀티캐스트로 전송 |
| **테이블 갱신 (Update)** | 수신한 이웃 벡터에 자신의 인터페이스 비용을 더한 뒤, 기존 등록 경로보다 비용이 작으면 테이블을 새 정보로 교체 |
| **수렴 (Convergence)** | 토폴로지 변경이 없을 때까지 정보 교환이 반복되며 모든 라우터의 최단 경로 정보가 일치 상태에 도달 |

## Ⅳ. 거리벡터(Distance Vector) vs 링크상태(Link State) 라우팅 비교

| 비교 항목 | 거리벡터 (Distance Vector) | 링크상태 (Link State) |
|---|---|---|
| **기반 알고리즘** | 벨만-포드(Bellman-Ford) 알고리즘 | 다익스트라(Dijkstra / SPF) 알고리즘 |
| **교환 정보 범위** | 자신의 전체 라우팅 테이블 (목적지, 거리, 다음 홉) | 자신과 연결된 인터페이스의 링크 상태(LSA/LSP) |
| **전송 대상** | 오직 직접 인접한 이웃(Neighbor) 라우터 | 영역(Area) 내의 전체 라우터로 Flooding |
| **토폴로지 인식** | 네트워크 전체 구조 모름 (Routing by Rumor) | 전체 네트워크의 완벽한 토폴로지 데이터베이스(LSDB) 보유 |
| **수렴 속도** | 느림 (경로 갱신이 홉별로 순차 전파됨) | 빠름 (변경 발생 즉시 전역 플러딩 후 개별 SPF 재계산) |
| **자원 소모량** | CPU 및 메모리 소모 매우 적음 | CPU 및 메모리(LSDB 유지) 소모 큼 |
| **대표 프로토콜** | RIP v1/v2, IGRP, BGP(Path Vector) | OSPF v2/v3, IS-IS |

## Ⅴ. 거리벡터 라우팅의 한계와 방안

| 한계 | 방안 |
|---|---|
| 링크 단절 장애 발생 시 이웃 간에 과거 정보를 상호 재학습하여 메트릭이 1씩 끝없이 증가하고 패킷이 순환하는 무한 계수(Count-to-Infinity) 발생 | 최대 홉 수를 엄격히 제한(RIP의 경우 15홉 제한, 16은 도달 불가로 규정)하고, 특정 인터페이스로 수신한 경로는 동일 인터페이스로 송출하지 않는 Split Horizon 및 무한대 비용으로 즉시 응답하는 Poison Reverse 적용 |
| 30초 주기의 정기 갱신에만 의존하여 링크 장애 전파 지연 및 수렴 시간 동안 라우팅 블랙홀 또는 일시 루프 지속 | 토폴로지 변화 감지 즉시 갱신 패킷을 브로드캐스트하는 Triggered Update와 장애 경로 광고 수신 시 일정 시간(Hold-down Timer, 보통 180초) 동안 대체 경로 학습을 동결하는 홀드다운 기법 병행 |
| 홉 수(Hop Count) 단일 메트릭 사용으로 링크의 물리적 대역폭, 패킷 지연, 패킷 손실률을 반영하지 못해 저속 링크로 트래픽이 집중되는 비최적 경로(Sub-optimal Routing) 형성 | 대역폭(Bandwidth)과 지연(Delay)을 복합 연산하고 DUAL 알고리즘으로 무루프(Loop-free)를 보장하는 EIGRP나 링크 코스트 기반의 OSPF 등 링크상태 라우팅으로 전환 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
RIP과 같은 전통적 거리벡터는 구성이 극히 단순하여 소규모 망이나 백업 링크에 적합하나, 대규모 엔터프라이즈 환경에서는 홉 수 한계(15홉)와 느린 수렴 속도로 인해 서비스 장애를 초래하므로, 네트워크 규모가 50개 라우터 이상일 경우 반드시 OSPF 또는 IS-IS 계층형 구조(Area 분할)로 마이그레이션 권장

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│              [ Count-to-Infinity 문제 및 루프 완화 기법 비교 ]         │
│                                                                        │
│   [Router A] ═══════ [Router B] ────X──── [Subnet C (단절!)]           │
│                                                                        │
│   1. 문제 상황 (Count-to-Infinity):                                    │
│      - B는 C 단절 감지 -> 그러나 A가 과거 B에게 배운 "C(거리 2)" 광고   │
│      - B는 A를 경유해 C로 갈 수 있다고 착각하여 "C(거리 3)" 등록        │
│      - A는 다시 B의 "C(거리 3)"를 수신하여 "C(거리 4)" 등록 -> 무한 반복│
│                                                                        │
│   2. 해결 메커니즘 (Split Horizon & Poison Reverse):                   │
│      - Split Horizon : A는 B에게 수신한 Subnet C 경로를 B에게 재광고 금지│
│      - Poison Reverse: A가 B에게 보낼 때 Subnet C 홉수를 16(무한대) 전송│
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 프로토콜 | 알고리즘 유형 | 메트릭 기준 | 최대 홉 수 | 수렴 속도 및 루프 방지 기법 |
|---|---|---|---|---|
| **RIP v1** | 거리벡터 | 홉 수 (Hop Count) | 15 (16=무한대) | 매우 느림 / Classful, Split Horizon |
| **RIP v2** | 거리벡터 | 홉 수 (Hop Count) | 15 (16=무한대) | 느림 / Classless(CIDR), 멀티캐스트(224.0.0.9) |
| **EIGRP** | 고급 거리벡터 | 대역폭 + 지연 (복합) | 224 (기본 100) | 매우 빠름 / DUAL 알고리즘(FC 조건 무루프) |
| **OSPF** | 링크상태 | 코스트 (참조대역폭/인터페이스대역폭) | 무제한 | 빠름 / 계층형 Area 분할, LSA 플러딩 |
