- 메커니즘: 각 이웃이 광고한 목적지 비용에 직접 링크 비용을 더해 최소 비용 경로를 선택

<details>
<summary>핵심 용어</summary>

- **거리벡터 라우팅**: 이웃 라우터로부터 받은 목적지별 비용 정보를 이용해 다음 홉을 선택하는 라우팅 방식
- **Count-to-Infinity**: 경로 단절 뒤 이웃의 오래된 광고를 서로 다시 전달해 비용이 점차 증가하는 라우팅 루프 현상
- **Split Horizon**: 특정 이웃에서 배운 경로를 같은 이웃에게 다시 광고하지 않는 루프 완화 기법
- **Triggered Update**: 경로 변경을 다음 주기 광고까지 기다리지 않고 변경 시점에 알리는 갱신 방식
- **RIP (Routing Information Protocol)**: 홉 수를 메트릭으로 사용하는 거리벡터 라우팅 프로토콜
- **OSPF (Open Shortest Path First)**: 링크 상태 정보를 사용해 경로를 계산하는 라우팅 프로토콜

  경유 v: 링크비용 1 + 이웃 광고 2 = 3 ─┐

### Ⅲ. 거리벡터의 특성

| 항목 | 핵심 설명 |
|---|---|
| 정보 범위 | 라우터는 목적지별 비용·다음 홉을 보유하며 전체 링크 토폴로지를 저장하지 않음 |
| 수렴 한계 | 오래된 광고가 순환하면 Count-to-Infinity가 발생할 수 있음 |
| 완화 기법 | Split Horizon·Poisoned Reverse·Triggered Update 등; 적용 가능 여부와 동작은 프로토콜별 차이 |
| 예시 | RIP은 홉 수를 메트릭으로 사용하고 16을 도달 불가로 정의; 다른 거리벡터 계열에 일반화하지 않음 |

### Ⅳ. 관련 개념과 구분

| 구분 | 거리벡터 | 링크상태 |
|---|---|---|
| 교환 정보 | 목적지별 비용·다음 홉 | 링크 상태 광고 |
| 계산 | 이웃 광고와 링크 비용을 조합 | 토폴로지 데이터베이스에서 경로 계산 |
| 대표 예 | RIP (Routing Information Protocol) | OSPF (Open Shortest Path First) |

### Ⅴ. 적용 한계와 대응

| 한계 | 대응 |
|---|---|
| 경로 단절 뒤 이웃의 옛 광고를 다시 학습할 수 있음 | RIP에서는 split horizon·poisoned reverse·triggered update 등 설정과 규격 동작 확인 |
| 홉 수 기반 메트릭은 대역폭·지연 차이를 직접 표현하지 않음 | 요구 품질에 맞는 라우팅 메트릭과 경로 정책을 선택하고 수렴 결과를 검증 |

### Ⅵ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 완화 기능만으로 모든 토폴로지의 수렴 시간을 보장하지 못함 | 장애·복구 시 경로 광고와 포워딩을 함께 관찰하고 망 규모에 맞는 프로토콜을 선택 |
