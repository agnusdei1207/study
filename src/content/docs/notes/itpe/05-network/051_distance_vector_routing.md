## 연관 키워드

- 거리벡터 라우팅, 벨만-포드(Bellman-Ford), RIP, 동적 라우팅
- 무한 계수(Count-to-Infinity), 수평 분할, 독성 역전, 홀드다운 타이머, 즉각 갱신
- 링크상태 라우팅, OSPF, 경로벡터, BGP, EIGRP, SDN

## Ⅰ. 거리벡터 라우팅의 개요

- 핵심 요약 : 이웃 라우터와 라우팅 테이블을 주기적으로 교환해 최단 경로를 분산 계산하는 동적 라우팅 방식.
- 개념 : 각 라우터가 이웃과 자신의 라우팅 테이블을 교환하며, 목적지까지의 거리(Distance)와 방향(Vector)을 **벨만-포드** (Bellman-Ford) 최단 경로 알고리즘으로 계산하는 **거리벡터 라우팅** (Distance Vector Routing).
- 배경 및 필요성 : 중앙 제어기나 전체 토폴로지를 볼 수 있는 노드 없이도, 각 노드가 이웃과의 최소 정보 교환만으로 경로를 자율적으로 세워야 하는 환경이 있었음.
- 주요 목적 : 단순한 연산과 적은 메모리에서 경로를 자동으로 학습하고, 소규모 망에서 토폴로지 변화를 빠르게 반영.

## Ⅱ. 거리벡터 라우팅의 특징 및 장점

- 핵심 요약 : 이웃 정보만으로 경로를 계산하는 단순한 구조가 낮은 연산 부하라는 장점으로 이어지지만, 전체 토폴로지를 모르므로 수렴이 느린 특징을 가짐.

1. 벨만-포드 갱신 : 이웃이 광고한 목적지 거리에 이웃까지의 링크 비용을 더한 값 중 최소값을 채택 (D_x(y) = min_v { c(x,v) + D_v(y) }) → 연산이 단순해 저사양 장비에서도 동작.
2. **소문에 의한 라우팅** (Routing by Rumor) : 전체 지도가 아니라 이웃이 전한 요약 정보만 신뢰 → 저장 공간이 작지만, 이웃 정보가 틀리면 그대로 전파되는 위험.
3. 주기적 전체 광고 : RIP(Routing Information Protocol)는 기본 30초 주기로 전체 테이블을 광고 → 구현이 단순하고 장애 후에도 주기 갱신으로 정보가 복구됨.

```text
[ 거리벡터 갱신 과정 ]

라우터 B가 이웃 A에게 테이블 광고
        ↓
A가 "B 경유 거리" 계산
(B까지 비용 + B가 알린 목적지 거리)
        ↓
더 짧으면 A의 라우팅 테이블 갱신
```

## Ⅲ. 거리벡터 라우팅의 구조와 루프 방지 메커니즘

- 핵심 요약 : 광고 방향과 타이머를 조절하는 다섯 가지 기법이 루프를 완화하지만, 각 기법에는 적용 범위의 한계가 있음.

| 기법 | 동작 메커니즘 | 기술적 한계 |
| --- | --- | --- |
| 최대 홉 수 제한 | RIP은 최대 15홉까지만 허용하고 16홉을 도달 불가(무한대)로 정의 | 직경 15홉 이내의 소규모 망에만 적합 |
| 수평 분할 (Split Horizon) | 경로를 배운 인터페이스로 같은 경로를 다시 광고하지 않음 | 삼각 루프 같은 복잡한 토폴로지는 방어하지 못함 |
| 독성 역전 (Poison Reverse) | 경로를 배운 인터페이스에도 해당 경로를 메트릭 16으로 광고 | 광고 정보가 늘어 대역폭 오버헤드가 증가 |
| 홀드다운 타이머 (Holddown Timer) | 경로 장애를 알린 뒤 일정 시간(RIP 기본 180초) 더 나쁜 경로 정보를 받지 않음 | 수렴 속도를 떨어뜨리는 부작용 |
| 즉각 갱신 (Triggered Update) | 토폴로지 변화를 감지하면 주기를 기다리지 않고 즉시 광고 | 짧은 시간에 갱신 패킷이 몰려 일시적 폭주 가능 |

## Ⅳ. 거리벡터 라우팅과 링크상태 라우팅의 비교

- 핵심 요약 : 거리벡터는 이웃 요약 정보로 계산해 가볍지만 느리고, 링크상태는 전체 토폴로지를 유지해 빠르고 루프가 없지만 연산과 메모리 부담이 큼.

| 비교 축 | 거리벡터 (RIP) | 링크상태 (OSPF, Open Shortest Path First) |
| --- | --- | --- |
| 보유 정보 | 이웃이 알려준 거리와 방향 | 전체 토폴로지 (LSDB, Link-State Database) |
| 계산 알고리즘 | 벨만-포드 | 다익스트라(Dijkstra) |
| 수렴 속도 | 느림 (분 단위 가능) | 빠름 (초 단위) |
| 루프 처리 | 루프 방지 기법에 의존 | 토폴로지 기반으로 루프 원천 배제 |
| 자원 부담 | 낮음 | 중간 이상 |
| 적합 규모 | 소규모 말단 망 | 기업·통신사 내부망 |

- 선택 기준 : 토폴로지 변화가 적고 장비 자원이 제한되면 거리벡터를, 변화가 잦고 망이 크면 링크상태를 택함. 고급 거리벡터인 EIGRP(Enhanced Interior Gateway Routing Protocol)는 DUAL 알고리즘으로 루프 없는 경로를 보장.

## Ⅴ. 거리벡터 라우팅의 한계와 방안

- 핵심 요약 : 무한 계수와 메트릭 한계는 프로토콜 보완이나 상위 방식 전환으로 대응하는 구조.

```text
[ 링크 단절 후 무한 계수 ]

A-Y 링크 단절
      ↓
B가 "Y까지 2홉" 광고 (실제로는 A 경유)
      ↓
A가 "B 경유 3홉"으로 갱신
      ↓
B가 4홉으로 갱신 → 홉 수가 계속 증가
```

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **무한 계수** (Count-to-Infinity) | 링크 단절 시 낡은 정보가 순환 참조되어 홉 수가 계속 증가 → 수렴까지 긴 루프 지속 | 수평 분할과 독성 역전 병행, 또는 DUAL 기반 EIGRP나 링크상태 프로토콜로 전환 | 수렴 시간, 루프 발생 건수 |
| 홉 수 메트릭의 대역폭 미반영 | 홉 수만 보면 저속 링크 1홉이 고속 링크 2홉보다 우선 선택될 수 있음 | 대역폭·지연을 반영하는 복합 메트릭(EIGRP) 또는 인터페이스 비용(OSPF Cost) 사용 | 선택 경로의 실제 처리량 |
| 직경 제한 | RIP은 15홉을 넘는 목적지에 도달할 수 없어 대규모 망에 부적합 | 링크상태나 경로벡터 프로토콜로 이전 | 최대 홉 수, 도달 불가 경로 수 |

## Ⅵ. 거리벡터 라우팅에 대한 기술사적 제언

- 핵심 요약 : 거리벡터는 말단의 제한된 범위에서 인증과 필터링을 갖춰 쓰고, 상위 망은 경로벡터나 중앙 집중 구조로 옮겨 가는 방향.

토폴로지 변화가 거의 없는 소규모 지선망에서는 거리벡터 프로토콜을 제한적으로 유지하되, 광고에 인증을 적용하고 인접 정보를 필터링해 잘못된 경로가 퍼지지 않도록 하는 것이 안전하다. 인터넷 백본은 거리 대신 경유 AS(Autonomous System) 목록을 기록하는 BGP(Border Gateway Protocol)의 경로벡터 방식으로 루프를 판별하는 구조가 정착되어 있으므로, 상위 망 설계도 이 원리를 따르는 것이 바람직하다. 대규모 기업망은 분산 소문 방식 대신 중앙 컨트롤러가 전역 토폴로지를 관리하는 SDN(Software-Defined Networking) 구조로 점진 전환하는 것을 검토할 만하다.

## Ⅶ. 결론

- 핵심 요약 : 거리벡터 라우팅은 이웃 정보만으로 경로를 세우는 단순·경량 방식이며, 수렴 지연과 루프 위험을 감수하는 대신 낮은 자원으로 동작하는 특성을 가짐.
- 시사점 : 망이 커지면 링크상태, 경로벡터, SDN 구조로 옮겨 가고, 거리벡터는 소규모 말단에 국한해 운용하는 것이 기본 원칙이다.
