```text
 ┃
 ┣━ Ⅰ 개요 ───── 전체 토폴로지 파악 없이 이웃과의 거리(Distance)와 방향(Vector)만 교환하는 라우팅
 ┣━ Ⅱ 특징 ───── 벨만-포드(Bellman-Ford) 알고리즘, 분산 연산, 주기적 전체 전송, 이웃 소문 의존(Routing by Rumor)
 ┣━ Ⅲ 구조 ───── 거리 벡터(목적지, 메트릭, 넥스트홉) + 주기적 타이머 + 라우팅 루프 방지 메커니즘
 ┣━ Ⅳ 흐름 ───── ① 이웃 벡터 수신 → ② $D_x(y) = \min_v \{ c(x,v) + D_v(y) \}$ 계산 → ③ 자신의 표 갱신 후 재전파
 ┣━ Ⅴ 비교 ───── 거리벡터 vs 링크상태 (이웃 벡터 교환 vs 전체 링크 상태 플러딩, 벨만포드 vs 다익스트라)
 ┗━ Ⅵ 실무 ───── 무한 계수(Count-to-Infinity) 라우팅 루프 / 느린 수렴(Slow Convergence)
```

## 한 줄 본질
- 라우터가 전체 네트워크 구조를 파악할 연산 능력이 없던 환경에서 이웃 라우터가 알려준 방향과 거리 정보만 믿고 길을 찾는 기법 → 벨만-포드 점화식에 따라 표를 주기적으로 갱신해 최소 비용 경로 도출 → 라우터 메모리와 연산 부담 최소화 / 특정 경로 단절 시 홉 수가 1씩 끝없이 증가하며 패킷이 갇히는 무한 루프(Count-to-Infinity) 발생

## 핵심 그림
```text
[ 벨만-포드(Bellman-Ford) 점화식 및 거리벡터 갱신 원리 ]

라우터 x에서 목적지 y까지의 최단 거리 D_x(y):
    D_x(y) = min_v { c(x,v) + D_v(y) }
    (단, v는 x의 모든 인접 이웃 라우터, c(x,v)는 x에서 v까지의 직접 링크 비용)

   [라우터 v] ------ D_v(y) = 2 -------> [목적지 y]
      ^
      | c(x,v) = 1
      |
   [라우터 x] =========================> D_x(y) = 1 + 2 = 3 결정!
      |
      | c(x,w) = 5
      v
   [라우터 w] ------ D_w(y) = 1 -------> [목적지 y]
```

## 핵심 용어
- Routing by Rumor(소문에 의한 라우팅): 라우터가 실제 물리 망의 토폴로지를 눈으로 직접 검증하지 않고, 이웃 라우터가 "내가 거기까지 몇 홉에 갈 수 있다"고 전해준 소문(벡터)만을 맹신하는 특성
- 무한 계수(Count-to-Infinity): 목적지 네트워크가 끊어졌을 때 인접 라우터들이 서로의 옛 정보를 참조하며 홉 수를 1씩 계속 증가시켜 결국 무한대(16)에 도달할 때까지 루프가 도는 현상
- 트리거드 업데이트(Triggered Update): 30초 주기를 기다리지 않고, 네트워크 상태 변화가 감지되는 즉시 변경된 경로 정보를 이웃에 번개처럼 전파하는 루프 완화 기법

## 핵심 통찰
- 거리벡터는 "내비게이션에 전국 지도가 없고, 교차로마다 서 있는 표지판(이정표)만 보고 따라가는 운전"과 같음
- 이정표가 잘못 적혀 있으면 영원히 뺑뺑이를 돌 수밖에 없으므로, 이를 막기 위해 "스플릿 호라이즌(온 길로는 되돌려 알리지 않음)", "포이즌 리버스(끊긴 길은 16으로 못 박음)", "홀드다운 타이머(의심스러우면 180초 대기)"의 3중 방어막을 쳐야만 망이 붕괴하지 않음
- 이러한 한계를 극복하기 위해 시스코는 DUAL(Diffusing Update Algorithm)을 적용해 루프가 원천 배제되는 고급 거리벡터 프로토콜인 EIGRP를 개발

## 이웃 토픽과 구분
- 거리벡터 vs 링크상태: 거리벡터는 "이웃에게만 내 전체 표를 준다" / 링크상태는 "망 전체에 내 이웃과의 연결 상태만 알린다"

## 문제·원인·대책
- 적용 상황: 라우터 간 회선 단절 시 대규모 루프 트래픽 폭증
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 홉 수가 16까지 치솟으며 3분간 패킷 핑퐁 루프 발생 | 이웃 라우터의 옛 경로 광고를 새로운 우회 경로로 오인 | 포이즌 리버스(Poison Reverse) + 트리거드 업데이트(Triggered Update) | 장애 즉시 메트릭을 16으로 강제 전파해 루프 즉시 소멸 |
| 네트워크 회선 품질(지연, 대역폭) 미반영 | 단순 홉 수(Hop Count) 단일 메트릭에 의한 비효율 경로 선택 | EIGRP 복합 메트릭(대역폭, 지연, 신뢰도, 부하) 적용 | 100M 고속 링크를 우선 선택해 실질적 네트워크 전송 품질 향상 |
