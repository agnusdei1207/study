## 지식 로드맵 내 현재 위치

지식 위치: 네트워크 → 패킷 전달 → **라우팅 테이블 탐색**

## 30초 인출

- 본질: **라우팅 테이블 탐색** : 목적지 IP에 맞는 포워딩 경로를 찾아 다음 홉·출력 인터페이스를 결정하는 과정
- 메커니즘: 목적지 주소에 일치하는 프리픽스 중 가장 긴 경로를 선택하는 **LPM(Longest Prefix Match)** 수행

<details>
<summary>핵심 용어</summary>

- **FIB(Forwarding Information Base)** : 패킷 전달에 쓰이는 목적지 프리픽스와 다음 홉·출력 인터페이스 정보
- **LPM(Longest Prefix Match)** : 목적지와 일치하는 경로 중 가장 긴 프리픽스를 선택하는 규칙
- **트라이(Trie)** : 키의 비트·문자 단위 분기를 따라 탐색하는 트리 자료구조
- **패트리샤 트리(Patricia Trie)** : 분기 없는 단일 경로를 압축한 트라이 변형
- **TCAM(Ternary Content-Addressable Memory)** : 0·1·무관값 비교를 병렬 수행하는 메모리; 용량·전력·비용 제약 고려
- **RIB(Routing Information Base)** : 라우팅 정보와 경로 선택 결과를 관리하는 제어 평면의 정보 기반

</details>

## 2~4교시 25점 답안

### Ⅰ. 라우팅 테이블 탐색의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **라우팅 테이블 탐색** : 목적지 IP에 맞는 포워딩 경로를 선택하는 과정 |
| 목적 | 패킷을 다음 홉·출력 인터페이스로 전달할 경로 결정 |

### Ⅱ. LPM 처리 과정

```text
목적지 IP 주소
      ↓
일치하는 프리픽스 탐색
      ↓ 가장 긴 일치 경로
다음 홉·출력 인터페이스
```

예를 들어 `192.0.2.0/24`와 `192.0.2.128/25`가 모두 목적지와 일치하면 더 긴 `/25` 선택. 일치 경로가 없으면 기본 경로가 있는지 확인하고, 기본 경로도 없으면 장비의 폐기·도달 불가 처리에 따름. 같은 길이·동일 프리픽스의 경로는 프로토콜 비용 등 별도 경로 선택 규칙에 따름.

### Ⅲ. 탐색 자료구조

| 구조 | 탐색 방식 | 장점 | 고려점 |
|---|---|---|---|
| 순차 비교 | 엔트리별 프리픽스 검사 | 단순 | 경로 수에 따라 비교 증가 |
| 트라이·패트리샤 | 주소 비트 경로를 따라 분기 | 프리픽스 구조를 직접 표현 | 메모리 배치·갱신 비용 |
| TCAM | 다수 엔트리 병렬 비교 | 고속 탐색에 활용 가능 | 용량·전력·비용·엔트리 특성 |

### Ⅳ. 제어 평면과 전달 평면

```text
라우팅 갱신 → RIB 경로 선택 → FIB 갱신
패킷 목적지 → FIB의 LPM 탐색 → 다음 홉·출력
```

RIB는 경로 정보·선택을 다루고 FIB는 실제 패킷 전달에 필요한 조회 정보를 제공. 구체적인 구현·갱신 방식은 장비와 운영체제에 따라 다름.

### Ⅴ. 한계와 대응

| 한계 | 대응 |
|---|---|
| 경로 증가로 테이블 탐색·갱신 부담 | 하드웨어 규모와 갱신 성능을 실측하고 적합한 자료구조 선택 |
| TCAM 사용에 따른 자원 부담 | 프리픽스 집계와 메모리 계층화를 검토하되 경로 정확성 확인 |
| 제어 평면 정보와 FIB 반영 지연 | 경로 수렴·FIB 반영 시간을 장애 시험으로 검증 |

### Ⅵ. 기술사적 제언

| 우선 선택 | 적용·확인 |
|---|---|
| 경로 규모·갱신 특성에 맞는 탐색 구조 선정 | 실제 경로 집합으로 처리율·갱신 시간·자원 사용량을 측정 |
