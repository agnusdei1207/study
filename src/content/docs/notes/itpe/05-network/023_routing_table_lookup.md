## 연관 키워드

- 라우팅 테이블 탐색, 최장 프리픽스 일치(LPM, Longest Prefix Match)
- 포워딩 정보 베이스(FIB, Forwarding Information Base), 라우팅 정보 베이스(RIB, Routing Information Base)
- TCAM(Ternary Content Addressable Memory), 트라이(Trie), 제어 평면(Control Plane), 전달 평면(Data Plane)

## Ⅰ. 라우팅 테이블 탐색의 개요

- 핵심 요약 : 패킷 목적지 주소를 경로 테이블과 대조해 다음 홉과 출력 인터페이스를 정하는 라우팅의 핵심 절차.
- 개념 : 라우터가 수신 패킷의 목적지 주소를 전달용 경로 테이블에서 찾아 최적 항목을 고르는 **라우팅 테이블 탐색** 과정으로, 일치 항목이 여러 개일 때 프리픽스가 가장 긴 항목을 택하는 **최장 프리픽스 일치** (LPM, Longest Prefix Match) 규칙을 따름.
- 배경 및 필요성 : 인터넷 경로 수의 지속 증가와 회선 속도 향상으로 패킷 하나당 탐색이 회선 전송 시간보다 빨라야 하는 요구가 생김.
- 주요 목적 : 경로 선택의 정확성 확보와 회선 속도를 견디는 저지연 탐색 구현.

## Ⅱ. 라우팅 테이블 탐색의 특징 및 장점

- 핵심 요약 : 최장 일치 규칙과 평면 분리 구조가 정확성과 고속 전달로 이어지는 탐색 체계.

1. 최장 일치 판정 : 일치 항목 중 네트워크 부분이 가장 긴 경로 선택 → 가장 구체적인 경로로의 정확한 전달.
2. 평면 분리 : 경로 계산을 담당하는 **제어 평면** (Control Plane)과 패킷 전달을 담당하는 **전달 평면** (Data Plane)의 분리 → 경로 재계산 없는 상시 고속 처리.
3. 경로 정보 2단 구조 : 계산 결과를 담는 **라우팅 정보 베이스** (RIB, Routing Information Base)와 전달용으로 단순화한 **포워딩 정보 베이스** (FIB, Forwarding Information Base)의 분리 → 정보 완전성과 탐색 속도의 병행 확보.
4. 탐색 구조 다양화 : 소프트웨어 **트라이** (Trie, 주소 비트열을 트리 경로로 따라가는 자료 구조)와 하드웨어 병렬 비교의 선택 → 장비 가격·성능 구간에 맞는 구현.

## Ⅲ. 라우팅 테이블 탐색의 구조 (흐름)

- 핵심 요약 : 목적지 주소 대조 → 최장 일치 선택 → 다음 홉 결정의 판정 흐름과 RIB-FIB 변환 흐름의 결합.
- **TCAM** (Ternary Content Addressable Memory) : 0·1·무관의 세 비트 상태를 비교해 프리픽스 전체를 동시 조회하는 하드웨어 메모리.

```text
[ 패킷 경로 결정 흐름 ]

패킷 도착 → 목적지 주소 추출
   ↓
FIB 탐색 (프리픽스 대조)
   ↓
일치 항목 중 최장 프리픽스 선택
   ↓
다음 홉·출력 인터페이스 결정
   ↓
헤더 갱신 후 출력
```

```text
[ 제어 평면에서 전달 평면까지 ]

라우팅 프로토콜 경로 교환
   ↓
RIB (최적 경로 계산)
   ↓ FIB 변환·배포
TCAM·트라이에 탑재된 FIB
   ↓
패킷별 고속 탐색
```

## Ⅳ. 라우팅 테이블 탐색 방식의 비교

- 핵심 요약 : 순차 탐색·알고리즘 탐색·하드웨어 탐색이 속도·비용·전력의 축에서 갈리는 구조.

| 비교 축 | 순차 탐색 | 트라이 탐색 | TCAM 병렬 탐색 |
| --- | --- | --- | --- |
| 탐색 방식 | 항목을 차례 대조 | 비트 단위 트리 순회 | 전체 항목 동시 비교 |
| 지연 특성 | 항목 수에 비례해 증가 | 메모리 접근 횟수에 비례 | 항목 수와 무관하게 짧음 |
| 하드웨어 비용 | 최소 | 낮음 (일반 메모리) | 높음 (전용 메모리) |
| 전력 소모 | 낮음 | 낮음 | 높음 |
| 주요 적용 | 소규모·저가 장비 | 소프트웨어 라우터 | 고성능 코어 장비 |

- 선택 기준 : 회선 속도 보장이 우선인 백본 장비는 하드웨어 탐색을, 비용·유연성이 우선인 소프트웨어 기반 장비는 트라이 계열을 적용.

## Ⅴ. 라우팅 테이블 탐색의 한계와 방안

- 핵심 요약 : 경로 폭증, 전력 부담, 갱신 시 불일치를 경로 집약·하이브리드 구성·원자적 교체로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 경로 수 폭증 | 글로벌 경로 증가가 탐색 하드웨어 용량을 압박해 신규 경로 수용 실패 | 경로 집약·필터링 정책과 FIB 압축 기술 적용 | FIB 사용률 |
| 전력·발열 부담 | 전체 항목 동시 비교 방식의 높은 소모 전력 | 알고리즘 탐색과 하드웨어 탐색의 하이브리드 구성 | 장비당 소모 전력 |
| 갱신 중 불일치 | 경로 갱신 도중 탐색이 신규·구경로를 혼용해 순간 오전송 | 갱신본을 따로 만들어 테이블 포인터를 원자적으로 교체 | 갱신 소요 시간 |

## Ⅵ. 라우팅 테이블 탐색에 대한 기술사적 제언

- 핵심 요약 : 탐색 부담을 낮추는 경로 정책과 용량 관리 체계의 상시 운영 필요.
- 백본 운영 조직 : 불필요한 세부 경로의 유입을 걸러내는 경로 필터 정책을 수립하고 FIB 용량을 상시 모니터링.
- 장비 설계 조직 : 성능·전력·비용의 균형 평가를 탐색 구조 선정 기준으로 문서화.
- 인터넷 보안 조직 : 경로 출처 검증(RPKI, Resource Public Key Infrastructure) 절차를 도입해 무효 경로의 탐색 테이블 유입 차단.

## Ⅶ. 결론

- 핵심 요약 : 라우팅 테이블 탐색은 최장 일치 규칙을 회선 속도로 실현하는 알고리즘·하드웨어의 균형 문제.
- 경로 수 증가가 계속되는 만큼 집약과 원자적 갱신이 탐색 체계의 기본 전제.
