## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 핵심 개념 → 라우팅 테이블 탐색

## 30초 인출

- 본질: 수십만 개 접두사를 가진 라우팅 테이블에서 순차 검색($O(N)$) 시 100Gbps 회선 속도를 맞추지 못하는 포워딩 병목
- 메커니즘: IP 비트열(0/1)의 공통 접두사를 트리 형태로 색인화한 트라이(Trie) 및 하드웨어 TCAM으로 최장 일치(LPM) 경로를 고속 탐색

## 핵심 용어

- LPM(Longest Prefix Match): 목적지 IP 주소와 라우팅 테이블 엔트리 중 서브넷 마스크 비트 길이가 가장 길게(구체적으로) 일치하는 경로를 최우선 선택하는 라우팅 원칙
- 패트리샤 트리(Patricia / Radix Tree): 중간에 분기가 없는 단일 자식 노드들을 하나로 합쳐(Path Compression) 트리 깊이를 줄이고 메모리 낭비를 줄인 압축 트라이
- TCAM(Ternary Content Addressable Memory): 0과 1뿐만 아니라 "Don't Care(X, 와일드카드)" 비트까지 지원하여 단 1클록 사이클($O(1)$) 만에 전체 테이블에서 최장 일치 경로를 병렬 검색하는 고성능 메모리 반도체

## 1교시 10점 답안

### Ⅰ. 정의·목적

- 정의: 라우팅 테이블 탐색은/는 IP 비트열(0/1)의 공통 접두사를 트리 형태로 색인화한 트라이(Trie) 및 하드웨어 TCAM으로 최장 일치(LPM) 경로를 고속 탐색 방식이다.
- 목적: 실시간 패킷 전달 속도 보장에 기여한다.

### Ⅱ. 핵심 구조와 작동

```text
[ 이진 트라이(Binary Trie) 기반 라우팅 접두사 탐색 ]

목적지 IP 접두사 등록:
A: 0*      (/1, 인터페이스 1)
B: 010*    (/3, 인터페이스 2)
C: 0101*   (/4, 인터페이스 3)
D: 1*      (/1, 인터페이스 4)

                      [ 루트 (Root) ]
                       /            \
                   비트 0          비트 1
                     /                \
                [ (A) /1 ]         [ (D) /1 ]
                 /      \
             비트 0    비트 1
             (비어있음)   \
                         [ 노드 ]
                         /
                     비트 0
                       /
                  [ (B) /3 ]
                     \
                    비트 1
                       \
                    [ (C) /4 ]  <=== 패킷 목적지가 01011 이면 최장 일치인 (C) 선택!
```

## 2~4교시 25점 답안

### Ⅰ. 핵심 구조와 작동

```text
[ 이진 트라이(Binary Trie) 기반 라우팅 접두사 탐색 ]

목적지 IP 접두사 등록:
A: 0*      (/1, 인터페이스 1)
B: 010*    (/3, 인터페이스 2)
C: 0101*   (/4, 인터페이스 3)
D: 1*      (/1, 인터페이스 4)

                      [ 루트 (Root) ]
                       /            \
                   비트 0          비트 1
                     /                \
                [ (A) /1 ]         [ (D) /1 ]
                 /      \
             비트 0    비트 1
             (비어있음)   \
                         [ 노드 ]
                         /
                     비트 0
                       /
                  [ (B) /3 ]
                     \
                    비트 1
                       \
                    [ (C) /4 ]  <=== 패킷 목적지가 01011 이면 최장 일치인 (C) 선택!
```

### Ⅱ. 핵심 특성

- 일반 이진 탐색 트리(BST)는 "정확한 단일 키(Exact Match)"를 찾는 데는 $O(\log N)$으로 최적이지만, 가변 마스크 길이를 가진 "범위 접두사(Prefix Range)"를 찾는 데는 구조적으로 부적합
- 이진 트라이는 IPv4 주소 길이 32비트에 대해 최대 32번의 메모리 참조($O(W)$, $W=32$)가 걸리므로, 한 번에 여러 비트(4비트씩)를 검사하는 멀티비트 트라이(Multi-bit Trie)로 분기 횟수를 단축
- 코어 백본 라우터의 포워딩 평면(ASIC)은 소프트웨어 알고리즘의 한계를 넘어 TCAM 하드웨어를 직접 장착하여 1초에 10억 패킷 이상을 지연 없이 처리

### Ⅲ. 관련 개념과 구분

- 이진 탐색 트리(BST) vs 트라이(Trie): BST는 키 값의 대소 비교(Left < Node < Right)로 이동 / 트라이는 키 값의 구성 비트열(0이면 좌측, 1이면 우측)에 따라 경로를 탐색

### Ⅳ. 적용 문제와 대응

- 적용 상황: 글로벌 BGP 풀 라우팅 테이블(100만 경로 돌파) 라우터의 룩업 지연
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 소프트웨어 트라이 룩업 지연으로 버퍼 오버플로 | 1비트씩 순차 비교로 인한 메모리 접근 병목 ($O(32)$ 또는 $O(128)$) | 멀티비트 트라이(Tree-Bitmap) 알고리즘 적용 | 메모리 접근 횟수를 4~5회로 단축하여 검색 속도 6배 가속 |
| 고속 스위칭 장비의 전력 소모 및 발열 심화 | 대용량 TCAM 칩셋의 병렬 비교 동작에 따른 전력 과소비 | TCAM + SRAM 분산 캐싱 하이브리드 아키텍처 | 상위 10% 핫스팟 트래픽을 SRAM 캐시로 흡수해 전력 40% 절감 |

### Ⅴ. 기술사적 제언

| 문제 | 해결 방안 |
|---|---|
| 적용 환경에서 발생하는 핵심 제약 | 기존 대책을 적용하고 핵심 운영 지표를 확인해 개선한다. |
