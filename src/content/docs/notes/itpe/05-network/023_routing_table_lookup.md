## 연관 키워드

- 라우팅 테이블 탐색, 최장 일치 규칙(LPM, Longest Prefix Match), 포워딩 정보 베이스(FIB, Forwarding Information Base), 라우팅 정보 베이스(RIB, Routing Information Base)
- TCAM(Ternary Content Addressable Memory), 트라이(Trie), 멀티비트 트라이, 섀도우 FIB(Shadow FIB), RCU(Read-Copy Update)

## Ⅰ. 라우팅 테이블 탐색의 개요

- 핵심 요약 : 목적지 IP 주소를 포워딩 테이블과 대조해 다음 홉과 출력 인터페이스를 정하는 L3 포워딩의 핵심 단계.
- 개념 : 라우터나 L3 스위치가 수신한 IP(Internet Protocol) 패킷의 목적지 주소를 **포워딩 정보 베이스** (FIB, Forwarding Information Base) 엔트리와 대조하여, **최장 일치 규칙** (LPM, Longest Prefix Match)에 따라 다음 홉(Next Hop)과 송출 인터페이스를 결정하는 과정.
- 배경 및 필요성 : 전역 BGP(Border Gateway Protocol) 경로 수가 대규모로 늘고 회선 속도가 높아지면서, 패킷마다 테이블을 나노초 단위에 가깝게 탐색하지 못하면 회선 속도를 유지하기 어려운 병목이 생김.
- 주요 목적 : 정확한 최장 일치 판정, 회선 속도를 수용하는 저지연 탐색, 메모리와 전력 비용의 최적화.

## Ⅱ. 라우팅 테이블 탐색의 특징 및 장점

- 핵심 요약 : 최장 일치 규칙과 제어·전달 평면의 분리가 정확한 경로 선택과 고속 포워딩으로 이어지는 구조.

1. 최장 일치 규칙 : 여러 경로가 목적지와 일치하면 프리픽스 길이가 가장 긴 경로를 선택 → 가장 구체적인 경로로 정확히 전달.
2. 제어·전달 평면 분리 : 라우팅 프로토콜이 만든 라우팅 정보 베이스(RIB, Routing Information Base)를 전달용 FIB로 컴파일해 하드웨어에 올림 → 패킷 처리 중 경로 계산을 배제하여 처리 속도 확보.
3. 하드웨어 병렬 탐색 : **TCAM**(Ternary Content Addressable Memory)이 전체 엔트리를 동시에 비교 → 엔트리 수가 늘어도 탐색 시간을 짧게 유지.
4. 소프트웨어 트라이 탐색 : 주소 비트열을 트리로 따라가며 탐색 → 고가 메모리 없이 일반 메모리로 구현 가능하여 저가 장비와 가상 스위치에 적용.

## Ⅲ. 라우팅 테이블 탐색의 구조 (흐름)

- 핵심 요약 : 엔트리 전체를 비교하는 LPM 판정 흐름과, 계산된 경로가 하드웨어 전달 테이블로 내려가는 두 흐름의 결합.
- 아래 도해는 LPM 판정 순서를 보여 준다. 엔트리 3(/26)이 선택되는 예가 핵심이다.

```text
[ LPM 탐색 흐름 ]

목적지 IP 주소 수신
      ↓
FIB 엔트리와 프리픽스 비교
      ↓
일치 엔트리 집합 생성
      ↓
프리픽스 길이 최대 엔트리 선택
      ↓
다음 홉·출력 인터페이스 결정
```

```text
[ 예: 목적지 192.168.1.130 ]

192.168.0.0/16     일치 (16비트)
192.168.1.0/24     일치 (24비트)
192.168.1.128/26   일치 (26비트) ← 선택
0.0.0.0/0          일치 (0비트)
```

- 아래 도해는 RIB가 FIB로 내려가 전달 평면에서 쓰이는 흐름이다.

```text
[ 제어 평면 → 전달 평면 ]

BGP 등 경로 계산
      ↓
RIB (경로 전체 정보)
      ↓ 컴파일
FIB (전달용 단순 테이블)
      ↓
ASIC·TCAM 탑재
      ↓
패킷 포워딩 (전달 평면)
```

## Ⅳ. 라우팅 테이블 탐색 방식의 비교

- 핵심 요약 : 선형 탐색은 단순하고, 멀티비트 트라이는 균형형, TCAM은 속도 최우선이라는 선택 기준 차이를 가짐.

| 비교 축 | 선형 순차 탐색 | 소프트웨어 멀티비트 트라이 | 하드웨어 TCAM 병렬 탐색 |
| --- | --- | --- | --- |
| 탐색 복잡도 | $O(N)$ (엔트리 수에 비례) | $O(W / k)$ ($k$비트 단위 점프) | $O(1)$ (한 번의 병렬 비교) |
| 지연 특성 | 엔트리 증가에 따라 크게 늘어남 | 메모리 접근 횟수에 비례 | 엔트리 수와 무관하게 짧음 |
| 메모리 비용 | 최소 (단순 배열) | 낮음 (일반 메모리 활용) | 매우 높음 (고가 전용 메모리) |
| 전력·발열 | 낮음 | 낮음 | 높음 (전체 엔트리 동시 구동) |
| 주요 적용 장비 | 저가형 공유기, 임베디드 | 리눅스 커널, VPP(Vector Packet Processing) 기반 라우터 | 엔터프라이즈 백본 코어 라우터 |

- 선택 기준 : 회선 속도와 전력 예산이 우선이면 TCAM, 비용과 유연성이 우선이면 소프트웨어 트라이를 택함. 백본은 라인 레이트 보장을 위해 TCAM을, 클라우드 가상 스위치는 캐시 친화적인 멀티비트 트라이를 주로 사용.

## Ⅴ. 라우팅 테이블 탐색의 한계와 방안

- 핵심 요약 : 경로 폭증, 전력, 경로 변동이라는 세 한계를 경로 집약, 하이브리드 탐색, 원자적 갱신으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| TCAM 용량 고갈 | 전역 경로 수 증가가 TCAM 용량을 앞지르면 신규 경로 설치 실패 | FIB 집약·압축, 코어 장비의 디폴트 경로 활용과 에지 라우터와 역할 분담 | TCAM 사용률, 경로 설치 실패 건수 |
| 전력·발열 집중 | 전체 엔트리 병렬 비교로 소모 전력이 커져 고밀도 랙의 냉각 부담 증가 | 소프트웨어 고속 탐색 알고리즘과 온칩 캐시를 결합한 하이브리드 포워딩 | 장비당 전력, 랙 발열 지표 |
| 경로 변동 시 갱신 지연 | 경로 플래핑 때 FIB 재배치로 일시적 루프나 패킷 폐기 발생 | 섀도우 FIB를 백그라운드에서 갱신한 뒤, RCU(Read-Copy Update) 방식으로 포인터를 원자적으로 교체 | FIB 갱신 소요 시간, 플래핑 횟수 |

## Ⅵ. 라우팅 테이블 탐색에 대한 기술사적 제언

- 핵심 요약 : 소프트웨어 고속 경로와 경로 필터링, 세그먼트 기반 포워딩을 결합하는 방향으로 탐색 비용을 구조적으로 낮추는 것이 필요.
- 고성능 소프트웨어 라우터를 운영하는 환경에서는 DPDK(Data Plane Development Kit)와 VPP 위에 CPU 캐시 라인 크기에 맞춘 멀티비트 트라이를 적용해 캐시 미스를 줄이는 설계가 필요하다.
- 백본의 BGP 경로 정책에서는 불필요한 세부 경로 광고를 걸러내고 RPKI(Resource Public Key Infrastructure) 검증을 결합해, 무효 경로가 FIB에 올라가지 않도록 막는 절차가 필요하다.
- 장기적으로는 SRv6(Segment Routing over IPv6) 기반 포워딩을 검토하여 홉마다 테이블을 조회하는 부담을 헤더 내 세그먼트 리스트 처리로 옮기는 것이 유리하다.

## Ⅶ. 결론

- 핵심 요약 : 라우팅 테이블 탐색은 LPM 규칙을 회선 속도로 구현하는 하드웨어와 알고리즘의 균형 문제임.
- 시사점 : 경로 수 증가는 피할 수 없으므로, 경로 집약과 원자적 갱신을 함께 갖춘 탐색 구조가 확장성의 조건이 됨.
