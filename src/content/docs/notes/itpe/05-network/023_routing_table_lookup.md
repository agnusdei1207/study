## 지식 로드맵 내 현재 위치

지식 위치: 네트워크 → 패킷 전달 → **라우팅 테이블 탐색**

## 30초 인출

- 본질: **라우팅 테이블 탐색** : 목적지 IP에 맞는 포워딩 경로를 찾아 다음 홉·출력 인터페이스를 결정하는 과정
- 메커니즘: 목적지 주소에 일치하는 프리픽스 중 가장 긴 경로를 선택하는 **LPM(Longest Prefix Match)** 수행
- 통찰: IP 패킷 전달 시 수백만 개의 라우팅 엔트리 중 목적지 IP와 가장 길게 일치하는 경로를 찾는 최장 일치 접두사(LPM) 규칙을 하드웨어 TCAM 및 소프트웨어 Trie 알고리즘으로 테라비트급 고속 처리하는 기법임.

<details>
<summary>핵심 용어</summary>

- **FIB(Forwarding Information Base)** : 패킷 전달에 쓰이는 목적지 프리픽스와 다음 홉·출력 인터페이스 정보
- **LPM(Longest Prefix Match)** : 목적지와 일치하는 경로 중 가장 긴 프리픽스를 선택하는 규칙
- **트라이(Trie)** : 키의 비트·문자 단위 분기를 따라 탐색하는 트리 자료구조
- **패트리샤 트리(Patricia Trie)** : 분기 없는 단일 경로를 압축한 트라이 변형
- **TCAM(Ternary Content-Addressable Memory)** : 0·1·무관값 비교를 병렬 수행하는 메모리; 용량·전력·비용 제약 고려
- **RIB(Routing Information Base)** : 라우팅 정보와 경로 선택 결과를 관리하는 제어 평면의 정보 기반

</details>

## 2~4교시 25점 답안

## Ⅰ. 라우팅 테이블 탐색의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 라우터가 수신한 패킷의 헤더에서 목적지 IP 주소를 추출하여 포워딩 정보 베이스(FIB) 테이블과 대조하고 다음 홉(Next Hop) 및 출력 인터페이스를 결정하는 탐색 프로세스 |
| 목적 | 인터넷 백본의 수십만 개 라우팅 엔트리 환경에서 와이어 스피드(Wire-speed) 패킷 포워딩 및 경로 모호성 제거 |

## Ⅱ. 라우팅 테이블 탐색의 특징

| 특징 | 상세 내용 |
|---|---|
| 최장 일치 접두사(LPM)| 목적지 주소와 네트워크 프리픽스가 가장 길게(가장 구체적으로) 일치하는 경로를 최우선 선택 |
| 제어/포워딩 평면 분리| 느린 RIB(Routing Info Base)와 고속 포워딩 전용 FIB(Forwarding Info Base)를 물리/논리 분리 |
| 하드웨어 병렬 검색 | TCAM(Ternary Content Addressable Memory)을 통해 단 1 클록 사이클 내에 LPM 완전 검색 수행 |
| 재귀적 조회(Recursive)| 다음 홉 IP가 물리 인터페이스에 직접 매핑될 때까지 반복 탐색하거나 CEF로 단일 평탄화(Flat) |

## Ⅲ. 라우팅 테이블 탐색의 체계·프로세스

**라우팅 테이블 탐색 구조 및 LPM 매칭 메커니즘**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ LPM (Longest Prefix Match) 동작 예시 ]        │
│                                                                        │
│   목적지 IP 패킷 도착: 192.168.1.130                                  │
│   (2진수: 11000000.10101000.00000001.10000010)                        │
│                                                                        │
│   [ 라우팅 테이블 후보 엔트리 ]                                        │
│   Route 1: 0.0.0.0/0          (Default Route) ──► 일치 길이: 0 비트    │
│   Route 2: 192.168.0.0/16     (Class B 요약)  ──► 일치 길이: 16 비트   │
│   Route 3: 192.168.1.0/24     (C 클래스 망)   ──► 일치 길이: 24 비트   │
│   Route 4: 192.168.1.128/26   (서브넷)        ──► 일치 길이: 26 비트   │
│                                                                        │
│   ▼ 최장 일치 판정: Route 4 선택 (26비트 일치로 가장 구체적인 경로)   │
│                                                                        │
│   [ 하드웨어 처리 엔진 (TCAM / FIB) ] ──► Next Hop: 10.1.1.2 포워딩     │
└────────────────────────────────────────────────────────────────────────┘
```

| 탐색 기법 | 구현 형태 | 탐색 시간 복잡도 | 핵심 메커니즘 및 특징 |
|---|---|---|---|
| **선형 탐색 (Linear Scan)** | 소프트웨어 | O(N) | 테이블의 첫 줄부터 끝까지 순차 비교. 실무 적용 불가 |
| **바이너리 트라이 (Trie)** | 소프트웨어 | O(W) (W=32비트) | 비트 단위 0/1 분기로 트리 탐색. 메모리 접근 32회 소요 |
| **패트리샤 트라이 (Patricia)**| 소프트웨어 | O(W) | 단일 자식 노드를 압축하여 트리의 높이 및 메모리 절감 |
| **TCAM (하드웨어 ASIC)** | 하드웨어 ASIC | **O(1) (단 1 사이클)** | 0, 1, Don't Care(X) 3진 비트 병렬 하드웨어 검색 |

## Ⅳ. 라우팅 테이블 탐색의 종류·비교

| 비교 항목 | 소프트웨어 기반 탐색 (Process/Interrupt) | 하드웨어 가속 탐색 (Cisco CEF / TCAM) |
|---|---|---|
| **동작 위치** | 메인 CPU 및 시스템 DRAM | 전용 네트워크 프로세서(NPU) 및 ASIC TCAM |
| **패킷 처리 방식** | 첫 패킷 CPU 인터럽트 조회 후 캐싱 | 제어 평면에서 FIB/Adjacency 테이블 사전 완성 |
| **처리 속도** | 수십 Mbps ~ 수백 Mbps (CPU 병목) | 수백 Gbps ~ 수 Tbps (와이어 스피드) |
| **지연 시간 (Latency)**| 밀리초(ms) 단위 지연 및 지터 발생 | 마이크로초(μs) 단위 고정 지연 보장 |
| **대규모 경로 변경** | 캐시 무효화 시 성능 급락 (Cache Thrashing)| FIB 테이블 즉각 갱신으로 성능 저하 없음 |

## Ⅴ. 라우팅 테이블 탐색의 한계와 방안

| 한계 | 방안 |
|---|---|
| TCAM 반도체 칩의 극심한 전력 소모, 발열 및 높은 부품 단가로 인한 용량 확장 제약 | Multi-bit Trie 및 Pipelined Tree 알고리즘 기반 고속 SRAM 하드웨어 검색 엔진 혼용 |
| 글로벌 BGP 풀 라우팅 테이블(100만 라우트 초과) 증가로 인한 엔트리 오버플로 발생 | FIB 필터링, 공격적 경로 집약(Aggregation) 및 코어망 MPLS/SRv6 터널링 도입 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
코어 및 백본 라우터 운용 시, 라우팅 엔진(Route Processor) 장애가 데이터 포워딩에 전파되지 않도록 논스톱 포워딩(NSF, Non-Stop Forwarding) 및 상태 보존 전환(SSO)을 구성하고, CEF(Cisco Express Forwarding) 인접성(Adjacency) 테이블의 해시 불균형을 주기적 점검.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 현대 고속 라우터의 2대 테이블 구조 (FIB & Adjacency Table) ]        │
│                                                                        │
│   [ 제어 평면 (Control Plane) ]                                        │
│     OSPF / BGP / Static ──► [ RIB (Routing Information Base) ]         │
│     ARP 프로토콜 ─────────► [ ARP Cache (L3 IP -> L2 MAC 매핑) ]      │
│                                  │                                     │
│                                  ▼ 사전 컴파일 (Pre-computed)          │
│   [ 포워딩 평면 (Data Plane) : 하드웨어 ASIC / TCAM ]                  │
│     ┌────────────────────────┐      ┌───────────────────────────────┐  │
│     │ FIB (LPM 탐색 전용)    │      │ Adjacency Table (L2 프레이밍) │  │
│     │ - 목적지 IP Prefix     │─────►│ - 출력 인터페이스 포트       │  │
│     │ - 최적 포인터 인덱스   │      │ - 사전 완성된 L2 헤더(MAC)    │  │
│     └────────────────────────┘      └───────────────────────────────┘  │
│     (추가적 재귀 조회나 ARP 요청 없이 단 1회 룩업으로 패킷 변환 송출)  │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 가속 기술 | 동작 메커니즘 | 장점 | 단점 |
|---|---|---|---|
| **Process Switching** | 매 패킷마다 CPU가 전체 RIB 조회 | 가장 완벽한 제어 가능 | 성능 최하 (실시간 트래픽 불가) |
| **Fast Switching** | 첫 패킷만 CPU 조회 후 경로 캐시 | 후속 패킷 고속화 | 첫 패킷 지연, 캐시 오염 취약 |
| **CEF (FIB 기반)** | 모든 경로와 L2 헤더를 사전에 FIB화 | 패킷 무관 최고속 포워딩 | 메모리 사용량 증가 |
