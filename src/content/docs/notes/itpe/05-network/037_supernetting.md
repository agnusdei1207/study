## 연관 키워드

- 슈퍼네팅, 경로 요약, CIDR, 서브네팅, 최장 접두사 일치(LPM)
- 클래스풀 어드레싱, 라우팅 테이블, 플래핑, 블랙홀링, 경로 누수, 계층적 IP 설계
- Null0, BGP, TCAM, FIB

## Ⅰ. 슈퍼네팅(Supernetting)의 개요

- 핵심 요약 : 연속된 소규모 네트워크를 하나의 공통 접두사로 묶어 라우팅 정보를 줄이는 경로 요약 기법.
- 개념 : 연속된 여러 소규모 IP 네트워크(주로 C 클래스)를 비트 연산으로 공통 접두사(Prefix)에 맞춰 하나의 대형 네트워크처럼 광고하는 **경로 요약** (Route Aggregation) 기법이며, **CIDR** (Classless Inter-Domain Routing) 체계 위에서 동작함.
- 배경 및 필요성 : 클래스풀(Classful) 어드레싱에서 발생하는 IP 주소 낭비를 완화하고, 인터넷 백본의 BGP(Border Gateway Protocol) 라우터에서 라우팅 테이블 엔트리가 폭증하는 것을 억제하기 위해 도입됨.
- 주요 목적 : 고속 포워딩 메모리인 TCAM(Ternary Content Addressable Memory) 부담 완화, 라우팅 테이블 크기 축소, 하위 네트워크의 **링크 플래핑** (Flapping) 전파 차단과 관리 단순화.

## Ⅱ. 슈퍼네팅(Supernetting)의 특징 및 장점

- 핵심 요약 : 비트 연산으로 만든 공통 접두사와 최장 접두사 일치 포워딩이 라우팅 규모를 줄이면서도 정확한 전달을 유지하는 구조.

1. **프리픽스 축약** (Prefix Aggregation) : 서브넷 마스크의 네트워크 비트를 줄여 공통 상위 비트만 남김 → 여러 대역을 하나의 경로로 광고.
2. **최장 접두사 일치** (LPM, Longest Prefix Match) : 라우터가 요약 경로보다 구체적인 내부 서브넷 경로를 우선 매칭 → 요약 이후에도 정확한 포워딩 보장.
3. 플래핑 격리 : 내부 서브넷의 링크 변동이 요약 경로 뒤에 가려져 외부 백본으로 전파되지 않음 → 백본 경로의 안정성 향상.
4. 라우팅 자원 절감 : 테이블 엔트리가 줄어 메모리 사용과 경로 갱신 부담이 감소 → 고속 포워딩 자원을 여유 있게 확보.

## Ⅲ. 슈퍼네팅(Supernetting)의 구조 (흐름)

- 핵심 요약 : 공통 상위 비트를 찾아 마스크를 줄이는 연산과, 대상 개수·연속성·정렬이라는 세 가지 규칙으로 성립하는 구조.

```text
[ 병합 대상 서브넷 (연속 4개) ]
Net 0 : 192.168.0.0/24
Net 1 : 192.168.1.0/24
Net 2 : 192.168.2.0/24
Net 3 : 192.168.3.0/24
      ↓ 3번째 옥텟 상위 6비트 공통
[ 슈퍼넷 마스크 /22 (255.255.252.0) ]
      ↓
[ 대표 경로 192.168.0.0/22 단일 광고 ]
```

- 비트 연산 기반 축약 : 통합 대상 주소들의 최상위 공통 비트열을 찾고, 그 길이만큼 마스크의 네트워크 비트를 남겨 슈퍼넷 마스크를 도출함.
- 개수 제약 : 통합하는 서브넷 수는 2의 n제곱(2, 4, 8, ...)이어야 하며, 주소 블록이 수치상 연속되어야 함.
- 정렬 규칙 : 대표 네트워크 주소는 병합 블록 크기의 정수 배수여야 요약이 성립함.

## Ⅳ. 슈퍼네팅(Supernetting)의 비교

- 핵심 요약 : 서브네팅은 네트워크 비트를 늘려 주소를 쪼개고, 슈퍼네팅은 네트워크 비트를 줄여 주소를 묶는 반대 방향의 기법.

| 비교 항목 | 서브네팅 (Subnetting) | 슈퍼네팅 (Supernetting) |
| --- | --- | --- |
| 마스크 조작 | 네트워크 비트 확장 (예: /24에서 /26으로 증가) | 네트워크 비트 축약 (예: /24에서 /22로 감소) |
| 적용 목적 | IP 주소 낭비 방지, 브로드캐스트 도메인 분할 | 라우팅 테이블 축소, 백본 메모리 보존 |
| 적용 위치 | 조직 내부 캠퍼스망, LAN(Local Area Network) | ISP(Internet Service Provider) 경계, ABR(Area Border Router)과 ASBR(Autonomous System Boundary Router), 글로벌 BGP 백본 |
| 주소 수 변화 | 서브넷당 가용 호스트 수 감소 | 병합 대역의 전체 주소 수 증가 |
| 플래핑 격리 | 세그먼트 단위로 장애가 전파될 수 있음 | 내부 서브넷 변동이 외부 백본으로 전파되지 않음 |

## Ⅴ. 슈퍼네팅(Supernetting)의 한계와 방안

- 핵심 요약 : 미할당 대역의 루프와 비연속 서브넷의 오라우팅을 Null0 방어 경로와 계층적 설계, 경로 필터링으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 비할당 대역 포함에 따른 블랙홀링과 루프 | 요약 범위 안의 미할당 주소 목적지 패킷이 기본 경로와 요약 경로 사이를 오가며 루프와 대역폭 낭비 발생 | 요약 라우터에 집약 프리픽스를 가리키는 정적 Null0 경로를 두어 미할당 트래픽을 즉시 폐기 (`ip route 192.168.0.0 255.255.252.0 Null0`) | 폐기 패킷 수 |
| 비연속 서브넷 요약에 따른 경로 누수와 오라우팅 | 원격지나 타 ISP에 흩어진 서브넷을 묶으면 엉뚱한 트래픽이 흘러 서비스가 끊어짐 | 계층적(Hierarchical) IP 설계를 강제하고, BGP Prefix-list와 Route-map으로 광고 경로를 엄격히 필터링 | 잘못 광고된 경로 수 |

```text
[ 슈퍼네팅 요약 경로 방어 흐름 ]

요약 경로 광고 (예: /22 집약)
   ↓ 미할당 대역 목적지 패킷 유입
Null0 정적 경로로 즉시 폐기
   ↓ 비연속 서브넷은 계층 설계로 제한
BGP 필터로 광고 경로 통제
   ↓
잘못된 경로 광고 차단
```

## Ⅵ. 슈퍼네팅(Supernetting)에 대한 기술사적 제언

- 핵심 요약 : 주소 계획을 처음부터 계층적으로 설계하고, 요약 경로에는 방어적 폐기 경로를 함께 등록하는 것이 기본 원칙임.
- 지역과 기능 단위로 주소 블록을 2의 거듭제곱 크기로 미리 나누어 배정해 두면, BGP 피어링 구간에서 충돌 없이 경로를 집약할 수 있음.
- ABR과 ASBR 같은 경계 장비의 구성 템플릿에 Null0 방어 경로를 포함시켜 요약과 동시에 자동 등록되도록 표준화하면, 백본 루프 위험을 설정 단계에서 막을 수 있음.
- IPv6(Internet Protocol version 6) 환경에서도 /48, /32 단위의 계층적 집약을 일관되게 적용해야 글로벌 BGP의 FIB(Forwarding Information Base) 테이블 확장성을 유지할 수 있음.

## Ⅶ. 결론

- 핵심 요약 : 슈퍼네팅은 주소 구조가 계층적일 때만 라우팅 규모를 안전하게 줄이는 경로 요약 기법임.
- 시사점 : 요약 효과는 주소 설계의 질에 비례하므로, 사후에 묶기보다 할당 단계에서 계층을 정해 두는 것이 운영 위험을 낮춤.
