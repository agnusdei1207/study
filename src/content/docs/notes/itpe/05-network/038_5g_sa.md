## 30초 인출

- 본질: **5G 단독모드 (5G Standalone, SA)** 는 5G 무선 접속망과 5G 코어를 함께 사용해 5G 시스템 기능을 제공하는 배치 방식
- 메커니즘: UE의 NR 접속 → gNB → 5GC의 제어·사용자 평면 기능 → 외부 데이터망

<details>
<summary>핵심 용어</summary>

- **5G SA (5G Standalone)** : 5G New Radio 접속망을 5G Core에 연결하는 독립형 5G 시스템 배치 방식.
- **5G NSA (5G Non-Standalone)** : LTE와 5G NR을 함께 사용하는 5G 배치 방식. 구성 옵션에 따라 LTE 코어를 이용.
- **NR (New Radio)** : 3GPP가 정의한 5G 무선 접속 기술.
- **gNB (Next Generation Node B)** : 5G NR 기지국.
- **5GC (5G Core)** : 5G 시스템의 제어·사용자 평면 기능을 제공하는 코어망.
- **SBA (Service-Based Architecture)** : 5GC 네트워크 기능이 서비스 인터페이스를 통해 상호 작용하는 구조.
- **AMF (Access and Mobility Management Function)** : 접속·이동성 관리 기능.
- **SMF (Session Management Function)** : 세션 관리와 사용자 평면 자원 제어 기능.
- **UPF (User Plane Function)** : 사용자 데이터 패킷의 전달·처리 기능.
- **EPS Fallback (Evolved Packet System Fallback)** : 음성 서비스 연결을 위해 LTE/EPS로 전환하는 절차.

### Ⅱ. 구성과 연결

```text
UE
 ↓ NR 무선 접속
gNB
 ↓ 제어 신호·사용자 데이터
5GC
 ↓ 데이터 전달
외부 데이터망
```

SA는 NR 접속과 5GC를 한 시스템으로 구성. 지연 시간·슬라이싱 등 서비스 특성은 무선 환경, 망 구성과 정책에 좌우.

### Ⅲ. 주요 특징

| 항목 | 설명 |
|---|---|
| 코어 구조 | SBA 기반 5GC 기능 활용 |
| 서비스 구성 | 네트워크 슬라이싱 등 5GC 기능 구성 가능 |
| 적용 조건 | 단말·기지국·코어·전송망의 호환성과 운영 준비 필요 |

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **5G 단독모드 (5G Standalone, SA)** 는 5G NR 무선 접속망을 5G Core에 연결하는 독립형 5G 시스템 배치 방식 |
| 목적 | 5G 코어 기능을 이용한 서비스·접속 구조의 제공 |

## Ⅱ. 망 구성과 데이터 경로

```text
UE
 ↓ NR 접속
gNB
 ├─ 제어 신호 → 5GC의 AMF·SMF
 └─ 사용자 데이터 → 5GC의 UPF
                       ↓ 패킷 전달
데이터 네트워크
```

5GC는 제어 기능과 사용자 평면 기능을 분리해 구성 가능. 실제 배치는 사업자 설계와 서비스 요구에 따름.

## Ⅲ. NSA와 SA의 구조 차이

| 구분 | NSA | SA |
|---|---|---|
| 무선 접속 | LTE와 NR 조합 등 옵션별 구성 | NR 접속 |
| 코어망 | 옵션 3 계열은 EPC 이용 | 5GC 이용 |
| 주요 의미 | 기존 LTE 기반 위에 NR 추가 가능 | 5GC 기능 활용 가능 |

```text
NSA 옵션 3 계열 ── LTE 접속·EPC 기반
SA               ── NR 접속·5GC
```

정적 관계 표기. NSA는 여러 옵션이 있어 모든 NSA가 동일한 EPC·LTE 구조라는 뜻은 아님.

## Ⅳ. 서비스 기능과 도입 고려

| 기능·요소 | 5GC와의 관계 | 운영 확인 |
|---|---|---|
| SBA | 네트워크 기능 간 서비스 기반 상호 작용 | 기능·인터페이스 호환성 |
| 네트워크 슬라이싱 | 서비스 요구에 맞는 논리 네트워크 구성 기능 | 단말·RAN·코어의 지원 범위와 정책 |
| 음성 | IMS 기반 VoNR 또는 EPS Fallback 등 구성 | 커버리지·단말·음성 연동 |

SA 지원만으로 초저지연이나 슬라이싱 품질이 자동 보장되는 것은 아님. 종단 간 구성과 서비스 정책 검증 필요.

## Ⅴ. 기술사적 제언 — 서비스 기반 우선 전환

| 한계 | 해결 방안 |
|---|---|
| SA 구축 범위와 투자 규모가 서비스 수요보다 앞서면 자원 활용이 낮을 수 있음 | 우선 서비스의 커버리지·단말·코어 요구를 확인하고, 기능 검증이 끝난 지역·서비스부터 전환 |
