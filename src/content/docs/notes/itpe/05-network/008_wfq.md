## 30초 인출

- 본질: **WFQ** : 흐름별 큐에 가중치를 주고 출력 링크의 전송 기회를 배분하는 패킷 스케줄링
- 메커니즘: 패킷을 흐름별로 분류 → 길이·가중치에 따른 가상 완료시간 계산 → 가장 이른 패킷 전송
- 통찰: 단순 선입선출(FIFO) 방식의 특정 트래픽 독점 폐단을 방지하고 서비스 등급(CoS)에 따른 대역폭을 수학적으로 보장하기 위해 GPS 모델을 이산 패킷 환경에 근사한 가상 마감시간(Virtual Finish Time) 스케줄링이 본질임.

- **WFQ(Weighted Fair Queuing)** : 흐름·클래스별 가중치를 반영해 패킷 전송 순서를 정하는 큐 스케줄링
- **FIFO(First In First Out)** : 패킷이 큐에 들어온 순서대로 내보내는 방식
- **흐름(Flow)** : 분류 규칙에 따라 같은 연결·트래픽으로 묶인 패킷 집합
- **GPS(Generalized Processor Sharing)** : 여러 흐름을 가중치에 비례해 연속적으로 서비스한다고 가정하는 이상적 모델
- **가상 완료시간(Virtual Finish Time)** : 패킷이 가상 서비스 모델에서 전송을 마칠 시각을 나타내는 순서 결정 값
- **QoS(Quality of Service)** : 서비스별 지연·손실·처리량 등 네트워크 품질을 관리하는 개념

## 2~4교시 25점 답안

## Ⅰ. WFQ(Weighted Fair Queuing)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 트래픽 플로우별 가중치(Weight)에 비례하여 링크 대역폭을 공평하게 분배하고, 패킷의 가상 완료 시간(Virtual Finish Time) 순으로 스케줄링하여 전송하는 공정 큐잉 알고리즘 |
| 목적 | 대용량 트래픽의 전송 링크 독점 방지, 플로우 간 엄격한 자원 격리 및 음성·영상 등 지연 민감 트래픽의 종단 지연시간 보장 |

## Ⅱ. WFQ(Weighted Fair Queuing)의 특징

| 특징 | 상세 내용 |
|---|---|
| 플로우별 독립 큐 | 수신 패킷의 5-Tuple(IP/Port/Protocol)을 해싱하여 트래픽 플로우별 개별 큐에 격리 저장 |
| 비트 단위 공정성 근사 | 이론적인 비트 단위 라운드로빈(GPS) 모델을 패킷 단위 환경에서 가상 시간(Virtual Time)으로 근사 |
| 가중치 비례 대역폭 | IP Precedence 또는 DSCP 값에 기반한 가중치를 부여하여 고우선순위 큐에 더 많은 대역폭 할당 |
| 기아 현상(Starvation) 방지| 저우선순위 트래픽이라도 활성 플로우 수에 비례하여 최소한의 전송 기회를 보장 |

## Ⅲ. WFQ(Weighted Fair Queuing)의 체계·프로세스

**WFQ 가상 완료 시간(Virtual Finish Time) 산출 및 패킷 서비스 메커니즘**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ WFQ 큐잉 및 스케줄링 체계 ]                  │
│                                                                        │
│ Ingress Packet ──► [ 플로우 분류기 ]                                   │
│                           │                                            │
│            ┌──────────────┼──────────────┐                             │
│            ▼              ▼              ▼                             │
│       ┌─────────┐    ┌─────────┐    ┌─────────┐                        │
│       │ Queue 1 │    │ Queue 2 │    │ Queue 3 │                        │
│       │ (Weight)│    │ (Weight)│    │ (Weight)│                        │
│       │   w1    │    │   w2    │    │   w3    │                        │
│       └────┬────┘    └────┬────┘    └────┬────┘                        │
│            │              │              │                             │
│            ▼              ▼              ▼                             │
│       [ F(1,k) ]     [ F(2,k) ]     [ F(3,k) ]  (가상 마감시간 태깅)   │
│            └──────────────┼──────────────┘                             │
│                           ▼                                            │
│              [ 최소 F(i,k) 선택기 (Scheduler) ]                        │
│                           │                                            │
│                           ▼                                            │
│                     Egress Link (전송)                                 │
└────────────────────────────────────────────────────────────────────────┘
```

| 계산 파라미터 | 산출 공식 및 수식 정의 | 의미 및 역할 |
|---|---|---|
| **가상 시작 시간 (S)** | `S(i,k) = max(V(a_i^k), F(i,k-1))` | 패킷 k가 도착한 시점의 시스템 가상 시간 또는 이전 패킷의 완료 시간 |
| **가상 완료 시간 (F)** | `F(i,k) = S(i,k) + (L_i^k / w_i)` | 가상 시작 시간에 (패킷 길이 L / 가중치 w)를 합산하여 서비스 마감시간 결정 |
| **가상 시간 갱신 (V)** | `dV/dt = 1 / sum(w_active)` | 활성 상태인 플로우들의 가중치 총합에 반비례하여 시스템 시계 진척 |
| **스케줄링 규칙** | `Packet = argmin(F(i,k))` | 버퍼의 모든 선두 패킷 중 가상 완료 시간 F가 가장 작은 패킷을 먼저 서비스 |

## Ⅳ. WFQ(Weighted Fair Queuing)의 종류·비교

| 비교 항목 | FIFO (First-In First-Out) | PQ (Priority Queuing) | FQ (Fair Queuing) | WFQ (Weighted Fair Queuing) |
|---|---|---|---|---|
| **큐 분리 여부** | 단일 공용 큐 | 우선순위별 복수 큐 | 플로우별 복수 큐 | 플로우별 복수 큐 |
| **대역폭 보장** | 미보장 (버스트 독점) | 미보장 (상위 큐 독점) | 모든 활성 플로우 균등 분배 | 가중치(Weight)에 비례 분배 |
| **기아 현상** | 발생 가능 | 저우선순위 기아 발생 | 기아 현상 없음 | 기아 현상 없음 |
| **연산 복잡도** | O(1) (단순 처리) | O(1) (우선순위 큐 검색)| O(log N) (가상시간 정렬)| O(log N) (가중치 연산 수반) |

## Ⅴ. WFQ(Weighted Fair Queuing)의 한계와 방안

| 한계 | 방안 |
|---|---|
| 패킷 도착/출력 시마다 O(log N)의 정렬 연산이 요구되어 초고속 코어 라우터 적용 한계 | 연산 복잡도를 O(1)로 단순화한 결함 허용 적자 가중 라운드로빈(DWRR) 알고리즘으로 대체 |
| 플로우 분류를 위한 5-Tuple 해시 충돌 시 서로 다른 트래픽이 동일 큐에 할당되어 공정성 훼손 | 해시 버킷 크기 확장 및 암호학적 다중 해싱 기법을 적용하여 플로우 격리도 보장 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
엔터프라이즈 완(WAN) 에지 라우터 및 금융사 전용선 장비 구축 시, 음성 VoIP 트래픽은 LLQ(Low Latency Queuing, PQ+CBWFQ 결합)의 엄격한 우선순위 큐로 바이패스하고, 핵심 업무 ERP 데이터는 CBWFQ(Class-Based WFQ)에 최소 50%의 대역폭 가중치를 예약 할당.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 실무 엔터프라이즈 QoS 아키텍처 : LLQ (Strict PQ + CBWFQ) ]          │
│                                                                        │
│   Ingress Traffic                                                      │
│     │                                                                  │
│     ├─── VoIP (EF) ──────────► [ Strict Priority Queue (PQ) ] ──────┐  │
│     │                                  (지연에 극도로 민감)         │  │
│     ├─── ERP/DB (AF31) ──────► [ Class 1 Queue (WFQ w1=50%) ] ───┐  │  │
│     │                                                             │  │ │
│     ├─── Web/Email (AF11) ───► [ Class 2 Queue (WFQ w2=30%) ] ──┐ │  │ │
│     │                                                           │ │  │ │
│     └─── Best Effort (BE) ───► [ Default Queue (WFQ w3=20%) ] ─┐│ │  │ │
│                                                                 ││ │  │ │
│                                                                 ▼▼ ▼  ▼ │
│                                         [ 스케줄러: PQ 우선 비우기 후  ]│
│                                         [ 나머지 가중치 비례 서비스    ]│
│                                                                 │      │
│                                                                 ▼      │
│                                                          WAN Interface │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 스케줄링 방식 | 하드웨어 구현 복잡도 | 지연 보장성 (Jitter) | 공평성 보장 | 주 적용 위치 |
|---|---|---|---|---|
| **WFQ** | 높음 (정밀 부동소수점 연산) | 우수 | 완벽한 수학적 공평 | WAN 에지 라우터, 브로드밴드 가입자망 |
| **DWRR (Deficit WRR)** | 낮음 (정수 적자 카운터 연산) | 보통 | 패킷 크기 무관 공평 | 100Gbps/400Gbps 백본 코어 라우터 |
| **LLQ (Low Latency Q)** | 중간 | 최우수 (음성 지연 10ms 이하) | 계격 분리 보장 | VoIP 게이트웨이, 화상회의 에지 장비 |
