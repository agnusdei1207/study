## Ⅰ. WFQ(Weighted Fair Queuing)의 개요

- **개념** : 패킷 교환 네트워크의 라우터/스위치에서 각 플로우(Flow)마다 서로 다른 가중치(Weight)를 부여하여 대역폭을 비례적으로 공정하게 분배하고, 패킷 크기의 가변성에 구애받지 않도록 지연시간을 보장하는 패킷 스케줄링 알고리즘.
- **배경 및 필요성** : 단순 FIFO 큐잉은 대용량 패킷을 보내는 공격적 트래픽이 큐를 독점하여 소형 패킷(VoIP, 대화형 트래픽)의 지연을 초래하고, 고정 우선순위(PQ)는 하위 우선순위 큐의 기아(Starvation) 현상을 유발하므로 대역폭 보장과 공정성의 조화가 요구됨.
- **핵심 목적** : 플로우 간 대역폭 격리 및 최소 보장, 소형 패킷 플로우에 대한 우선 전송(저지연 서비스), 패킷 크기에 따른 편향 왜곡 제거.

## Ⅱ. WFQ(Weighted Fair Queuing)의 핵심 아키텍처 및 동작 메커니즘

WFQ는 모든 플로우가 비트 단위로 동시에 서비스받는 이상적인 GPS(Generalized Processor Sharing) 모델을 패킷 단위 환경에서 모사하기 위해 가상 시간(Virtual Time)과 가상 완료 시간(Finish Time)을 계산하여 동작함.

```text
[ WFQ (Weighted Fair Queuing) 가상 시간 기반 스케줄링 메커니즘 ]

각 플로우별 가중치: Flow 1 (Weight = 2), Flow 2 (Weight = 1)

1. 패킷 도착 시 가상 완료 시간 ($F_i^k$) 계산:
   $F_i^k = \max(F_i^{k-1}, V(a_i^k)) + \frac{L_i^k}{w_i}$
   (V: 시스템 가상 시간, L: 패킷 길이, w: 플로우 가중치)

2. 큐잉 및 정렬 구조:
   +-------------+
   | Flow 1 Queue| ---> [P1, L=1000, w=2] => Fi = 500
   +-------------+
   +-------------+
   | Flow 2 Queue| ---> [P2, L=1000, w=1] => Fi = 1000
   +-------------+
         │
         ▼ (가장 작은 가상 완료 시간 우선 선택: Fi 최소 힙 정렬)
   +---------------------------------------------------------------+
   | 출구 스케줄러: P1 (Fi=500) 먼저 전송 -> 이후 P2 (Fi=1000) 전송 |
   +---------------------------------------------------------------+
```

- **GPS(Generalized Processor Sharing) 유체 모델** : 여러 플로우의 비트가 가중치에 비례하여 유체처럼 동시에 흐른다고 가정한 수학적 이상 모델.
- **가상 시간($V(t)$)** : 네트워크 활성 플로우들의 가중치 합에 반비례하여 흐르는 시스템 논리 시계로, 새로운 패킷 도착 시점의 기준점 제공.
- **가상 완료 시간($F_i^k$)** : 해당 패킷이 GPS 시스템에서 서비스를 완료했을 시점의 가상 시간을 의미하며, 패킷 길이가 짧고 가중치가 클수록 완료 시간이 앞당겨짐.
- **가중 대역폭 보장** : 플로우 $i$는 총 대역폭 $C$ 중 $\frac{w_i}{\sum w_j} \times C$ 만큼의 대역폭을 항상 최소 보장받아 기아 상태 방지.

## Ⅲ. WFQ(Weighted Fair Queuing)의 세부 구성 요소 및 비교 분석

| 비교 항목 | FIFO | PQ (우선순위 큐잉) | WRR (가중 라운드로빈) | WFQ (가중 공정 큐잉) |
|---|---|---|---|---|
| **스케줄링 원리** | 도착 순서대로 처리 | 최상위 큐 소진 시까지 처리 | 가중치만큼 패킷 수 분배 | 가상 완료 시간 순서 처리 |
| **대역폭 공정성** | 전혀 없음 (독점 가능) | 없음 (하위 큐 기아 발생) | 패킷 크기 동일 시 공정 | 패킷 크기 가변에도 완전 공정 |
| **지연 보장** | 지연 예측 불가 | 고우선순위만 지연 보장 | 보통 수준 | 수학적으로 엄격한 지연 상한 보장 |
| **구현 복잡도** | $O(1)$ (극도로 단순) | $O(1)$ (단순) | $O(1)$ (단순한 순환 큐) | $O(\log N)$ (힙 정렬 및 역산 필요) |
| **하드웨어 적합성** | 초고속 백본 최적 | 코어 라우터 기본 탑재 | 하드웨어 ASIC 구현 용이 | 고속(100G+) 구현 비용 매우 높음 |

- WRR이 패킷 크기 변동에 취약한 반면, WFQ는 가변 길이 패킷 환경에서도 이상적인 공정 대역폭 분배와 엄격한 지연 바운드를 제공하는 고품질 QoS 알고리즘임.

## Ⅳ. WFQ(Weighted Fair Queuing)의 주요 한계점 및 해결 방안

- **패킷 도착/출발 시 $O(\log N)$ 정렬 연산 복잡도와 하드웨어 오버헤드** :
  - **한계점** : 활성 플로우 수($N$)가 수천 개 이상인 고속 코어 라우터에서 매 패킷마다 가상 시간 계산 및 우선순위 큐 정렬 불가.
  - **해결 방안** : $O(1)$의 복잡도를 가지는 DRR(Deficit Round Robin) 또는 하드웨어 P4 기반 PIFO(Push-In First-Out) 데이터 구조 도입.
- **최악의 경우 발생할 수 있는 패킷 완료 지연(Worst-case Fair Deficit)** :
  - **한계점** : 큰 패킷이 막 전송을 시작한 직후 도착한 지연 민감형 고가중치 패킷이 즉시 서비스되지 못하는 지터 발생.
  - **해결 방안** : 패킷의 가상 시작 시간까지 고려하는 $WF^2Q$(Worst-case Fair Weighted Fair Queueing) 알고리즘 적용.
- **플로우 식별(Classification) 오버헤드** :
  - **한계점** : IP 5-Tuple 기반의 마이크로 플로우 단위 WFQ 적용 시 메모리 및 상태 유지 부하 극대화.
  - **해결 방안** : DiffServ DSCP 클래스 기반으로 플로우를 사전 집약하여 관리하는 CBWFQ(Class-Based WFQ) 구성.

## Ⅴ. WFQ(Weighted Fair Queuing) 적용 및 발전을 위한 기술사적 제언

- **엔터프라이즈 WAN 및 SD-WAN 에지에서의 CBWFQ 필수 구현** : 음성(EF), 비즈니스 핵심 데이터(AF), 일반 트래픽 간의 SLA 보장을 위해 CBWFQ와 LLQ(Low Latency Queue) 결합 아키텍처 채택 권장.
- **AI/ML 대규모 분산 패브릭(RoCE v2) 스케줄러 고도화** : GPU 간 All-to-All 통신 시 버스트 트래픽 격리를 위해 최신 프로그래머블 스위치에 공정 큐잉 알고리즘 탑재 검토.
- **네트워크 가상화 환경(vSwitch) 내 소프트웨어 스케줄러 튜닝** : Linux TC(Traffic Control) 및 OVS(Open vSwitch) 환경에서 HFSC(Hierarchical Fair Service Curve) 또는 FQ_Codel과 결합한 통합 대역폭 제어 정책 수립 필요.
