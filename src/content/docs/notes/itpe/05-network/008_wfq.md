## 큰 그림과 30초 인출

- 본질: FIFO가 전체 도착 순서를 보존한다면 **WFQ**는 Flow별 큐와 가중치로 출력 링크의 서비스를 공정하게 배분함
- 메커니즘: Flow 분류 → 패킷 길이·가중치 기반 Virtual Finish Time 계산 → 가장 이른 완료시간 패킷 전송
- 산출: 대역폭 차등과 Flow 격리를 얻지만 분류·상태·정렬 비용이 증가함

<summary>핵심 용어</summary>

- `FIFO(First In First Out)`: 전체 도착 순서만 보존하는 Queue Discipline → 크기·Flow·긴급도는 판단하지 않음
- `WFQ(Weighted Fair Queuing)`: Flow별 Queue와 Weight로 GPS를 패킷 단위 근사 → 대역폭 차등과 기아 방지
- `GPS(Generalized Processor Sharing)`: Bit 단위로 여러 Flow를 동시에 서비스하는 이상적 기준 모델
- `Virtual Finish Time`: 패킷 길이와 Weight로 계산한 가상 완료시각 → 다음 전송 패킷 선택 기준
- `DWRR(Deficit Weighted Round Robin)`: Deficit Counter로 가중 공정을 근사 → 고속 링크의 정렬 비용 완화
- `AQM(Active Queue Management)`: Buffer 포화 전에 Queue를 능동 통제 → 체류시간과 동기 손실 억제

</details>

## 예상문제

- FIFO 방식과 WFQ 방식의 구조·동작을 설명하고, 두 방식을 비교한 후 지연 민감 트래픽의 큐 스케줄링 개선방안을 제시하시오.

## Ⅰ. 순서 규율과 가중 공정 큐잉 개요

> FIFO는 순서 보존, WFQ는 서비스 몫의 공정성을 목표로 하므로 동질 부하인지 차등 QoS 부하인지가 선택을 가름함.

- 정의: **FIFO**는 전체 도착 순서로 Head를 처리하고, **WFQ(Weighted Fair Queuing)**는 Flow별 가상 완료시간과 Weight로 출력 순서를 정하는 큐 스케줄링 기법
- 목적: Flow별 **대역폭 배분**, **지연 격리**, **기아 방지** → 혼합 트래픽의 QoS 제공
- 속성 구분: FIFO는 순서 규율이며 그 자체가 비선점을 뜻하지 않음. 비선점은 CPU FCFS처럼 선택된 항목을 완료까지 서비스하는 적용 모델의 속성임

## Ⅱ. FIFO 호위 효과와 WFQ 동작

> FIFO의 긴 선두 패킷·Burst는 후속 Flow에 지연을 전파하지만, WFQ는 Flow를 분리하고 패킷 길이까지 반영해 서비스 기회를 배분함.

## Ⅲ. FIFO와 WFQ 비교

> 구현 비용은 FIFO가 낮고 차등 QoS는 WFQ가 강하므로, 단순성과 서비스 격리 사이의 트레이드오프를 명시해야 함.

| 축 | FIFO | WFQ |
|---|---|---|
| Queue | 단일 | Flow별 |
| 기준 | 전체 도착 순서 | 가상 완료시간·Weight |
| 길이 | 판단하지 않음 | Packet Length 반영 |
| 대역폭 | 차등 없음 | Weight 비례 배분 |
| 격리 | 선두 Flow 영향 전파 | Flow 간 영향 완화 |
| 지연 | 별도 보장 없음 | 저용량 Flow 지연 완화 |
| 복잡도 | 낮음 | 분류·상태·정렬 필요 |
| 적합 | 동질 부하·단순 장치 | 혼합 QoS 트래픽 |

## Ⅳ. 고속망 큐잉의 한계와 개선

> WFQ도 Flow 수가 커지면 상태·정렬 비용이 병목이 되므로 Edge 정밀 분류와 Core 단순 스케줄링을 계층화해야 함.

| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| FIFO 지연 | 단일 Queue·Burst 혼재 | WFQ·Class 분리 | Flow 영향 격리 |
| Bufferbloat | 과도한 Buffer·Tail Drop | AQM 결합 | 체류시간 억제 |
| WFQ 계산부하 | Flow별 Tag·정렬 | DWRR·Class 기반 WFQ | 고속 링크 확장 |
| 하위 Class 기아 | 절대 Priority만 적용 | 최소 대역폭·Aging | 진행 기회 보장 |

## Ⅴ. SLA 기반 큐 스케줄링 결론

> 큐 스케줄링은 처리량 최적화만이 아니라 혼잡 시 지연과 대역폭을 어느 Flow에 배분할지 정하는 정책임.
