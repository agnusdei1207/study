## 연관 키워드

- WFQ, Weighted Fair Queuing, 패킷 스케줄링, 가중치, 가상 시간, 가상 완료 시간
- GPS, FIFO, PQ, WRR, 기아, 대역폭 보장
- DRR, WF2Q, PIFO, CBWFQ, LLQ, DiffServ

## Ⅰ. WFQ의 개요

- 핵심 요약 : 플로우별 가중치로 대역폭을 비례 분배하고 패킷 크기와 무관하게 공정성을 보장하는 스케줄링 기법.
- 개념 : 라우터·스위치에서 플로우(Flow)마다 가중치(Weight)를 부여해 대역폭을 비례 분배하는 **패킷 스케줄링**(Packet Scheduling) 알고리즘 (**WFQ**, Weighted Fair Queuing).
- 배경 및 필요성 : 단순 **FIFO**(First In, First Out) 큐는 대용량 패킷을 보내는 트래픽이 큐를 독점해 음성(VoIP, Voice over Internet Protocol)처럼 짧은 패킷의 지연을 키우고, 고정 우선순위 방식은 하위 큐의 **기아**(Starvation)를 유발하므로, 대역폭 보장과 공정성을 함께 충족하는 방식이 필요해짐.
- 핵심 목적 : 플로우 간 대역폭 격리와 최소 보장, 지연 민감 트래픽의 저지연 전송, 패킷 크기에 따른 편향 제거.

## Ⅱ. WFQ의 특징 및 장점

- 핵심 요약 : 이상적 유체 모델을 패킷 단위로 모사해 가상 완료 시간 순서로 전송함으로써, 공정한 대역 분배와 기아 방지를 함께 얻는 방식.
- 기준 모델 : **GPS**(Generalized Processor Sharing) 유체 모델은 플로우들의 비트가 가중치에 비례해 동시에 흐른다고 가정한 이상 모델이며, WFQ는 **가상 시간**(Virtual Time)을 기준점으로 이를 패킷 단위로 모사함.

1. 가상 시간 : 활성 플로우 가중치 합에 반비례해 흐르는 시스템 논리 시계 → 패킷 도착 시점의 기준점 제공.
2. **가상 완료 시간**(Virtual Finish Time) : 패킷이 GPS에서 전송을 마칠 가상 시간이며, F = max(이전 F, 도착 시 V) + L/w로 계산 (L 패킷 길이, w 가중치) → 길이가 짧고 가중치가 클수록 값이 작아 먼저 전송.
3. 가중 대역폭 보장 : 플로우 i는 전체 대역폭 C 중 w_i / Σw 비율만큼 항상 최소 보장받아 기아 상태를 피함.

```text
[ 가중치 예시: Flow 1(w=2), Flow 2(w=1) ]

Flow 1 패킷 L=1000 → F = 500
Flow 2 패킷 L=1000 → F = 1000
   ↓
F가 작은 Flow 1 패킷 먼저 출력
```

## Ⅲ. WFQ의 구조 (흐름)

- 핵심 요약 : 플로우별 큐 분류와 가상 시간 계산기, 그리고 가상 완료 시간 기준의 출구 스케줄러가 맞물린 두 단계 구조.

```text
[ WFQ 구성 요소 관계 ]

플로우 분류기 (IP 5-Tuple 등)
   ↓
가중치별 플로우 큐
   ↓
가상 시간 V 계산기
   ↓
출구 스케줄러 (최소 F 선택)
```

```text
[ WFQ 처리 흐름 ]

패킷 도착 → 플로우 분류
   ↓
플로우별 큐에 적재
   ↓
가상 완료 시간 F 계산
   ↓
F 기준 최소 힙 정렬
   ↓
F가 가장 작은 패킷부터 전송
```

- 정렬 : 우선순위 큐를 최소 힙(Min-Heap)으로 유지하므로 F 값의 비교와 삽입 비용이 패킷 수에 따라 늘어남.

## Ⅳ. WFQ와 다른 큐잉 방식의 비교

- 핵심 요약 : 단순성과 공정성, 지연 보장이 서로 맞바꿔지는 관계에서, WFQ는 공정성과 지연 상한을 우선하는 위치에 놓임.
- 비교 대상 : 단순 큐잉인 FIFO와 우선순위 방식인 PQ(Priority Queuing), 가중 순환 방식인 **WRR**(Weighted Round Robin, 가중 라운드 로빈), 그리고 WFQ.

| 비교 축 | FIFO | PQ | WRR | WFQ |
| --- | --- | --- | --- | --- |
| 스케줄링 원리 | 도착 순서대로 처리 | 최상위 큐를 비운 뒤 하위 큐 처리 | 가중치만큼 패킷 수를 분배 | 가상 완료 시간 순서로 처리 |
| 대역폭 공정성 | 전혀 없음, 독점 가능 | 없음, 하위 큐 기아 발생 | 패킷 크기가 같을 때 공정 | 패킷 크기가 달라도 공정 |
| 지연 보장 | 지연 예측 불가 | 고우선순위만 보장 | 보통 수준 | 지연 상한을 이론적으로 보장 |
| 구현 복잡도 | O(1) | O(1) | O(1) | O(log N) |
| 하드웨어 적합성 | 초고속 백본에 적합 | 코어 라우터에 기본 탑재 | 전용 칩 구현이 용이 | 고속 링크 구현 비용이 높음 |

- 선택 기준 : 패킷 크기가 가변이고 지연 상한 보장이 필요하면 WFQ가 맞고, 단순한 고속 전달이 우선이면 FIFO나 PQ가 적합함. WRR은 패킷 크기가 달라지면 공정성이 깨짐.

## Ⅴ. WFQ의 한계와 방안

- 핵심 요약 : 패킷당 정렬 비용, 지연 지터, 플로우 식별 부담을 근사 알고리즘과 클래스 집약으로 통제.
- 대응 기법 : 정렬 부담은 **DRR**(Deficit Round Robin)으로, 지연 지터는 **WF2Q**(Worst-case Fair Weighted Fair Queueing)로, 식별 부담은 **CBWFQ**(Class-Based WFQ)로 완화할 수 있음.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 패킷당 정렬 연산과 하드웨어 부담 | 활성 플로우가 매우 많은 고속 코어 라우터에서 매 패킷의 가상 시간 계산과 정렬이 병목 → 처리율 저하 | DRR 같은 O(1) 근사 기법 또는 PIFO(Push-In First-Out) 구조를 지원하는 프로그래머블 스위치 활용 | 패킷당 처리 지연, 정렬 큐 깊이 |
| 지연 지터 | 큰 패킷 전송 중 도착한 지연 민감 패킷이 즉시 나가지 못함 → 음성·영상 품질 저하 | 가상 시작 시간까지 고려하는 WF2Q 계열 적용 | 플로우별 지터, 지연 상한 위반 횟수 |
| 플로우 식별 오버헤드 | IP 5-Tuple(출발·도착 주소, 포트, 프로토콜) 단위 마이크로 플로우 상태 관리로 메모리 부하 증가 | 차등 서비스(DiffServ, Differentiated Services) 클래스로 플로우를 묶는 CBWFQ 구성 | 클래스별 큐 점유율, 상태 테이블 크기 |

## Ⅵ. WFQ에 대한 기술사적 제언

- 핵심 요약 : 엔터프라이즈 WAN, AI 패브릭, 가상화 계층 세 영역에서 클래스 기반 설계와 검증 절차를 갖추는 것이 WFQ 계열 스케줄링을 운영 역량으로 내재화하는 길임.
- 엔터프라이즈 WAN과 SD-WAN 에지를 운영하는 네트워크 조직은 음성과 핵심 업무 데이터 같은 트래픽 클래스별 SLA(Service Level Agreement)를 보장하도록, CBWFQ에 LLQ(Low Latency Queuing)를 결합한 구조를 기본 설계로 삼는 것이 바람직하다.
- GPU(Graphics Processing Unit) 간 집합 통신이 많은 AI 클러스터 패브릭에서는 버스트 트래픽 격리를 위해 공정 큐잉 기능을 갖춘 스위치를 도입 전에 실제 통신 패턴으로 검증하는 절차를 두어야 한다.
- 가상화 환경의 소프트웨어 스케줄러는 계층형 대역 정책과 지연 정책이 서로 충돌하지 않도록 플랫폼 운영 조직이 정책 템플릿을 표준화하고 주기적으로 점검하는 것이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : WFQ는 가중치와 가상 완료 시간으로 대역폭 공정성과 지연 상한을 함께 얻는 패킷 스케줄링 기법임.
- 시사점 : 가변 길이 패킷이 일반화된 망에서 QoS의 기준 알고리즘으로 자리 잡았으며, 고속화에 따라 근사형과 계층형 변형과 함께 쓰이는 방향으로 발전함.
