## 지식 로드맵 내 현재 위치

컴퓨터 시스템 및 네트워크 → 데이터 통신 → **통신 프로토콜 기본 요소**

## 30초 인출

- 본질: **통신 프로토콜(Communication Protocol)** : 서로 다른 이기종 통신 시스템 간에 원활하고 신뢰성 있는 정보 교환을 위해 규정한 통신 규약
- 메커니즘: 구문(Syntax, 데이터 형식), 의미(Semantics, 제어 정보 및 동작), 타이밍(Timing, 전송 속도 및 순서 제어)의 3대 요소가 유기적으로 결합하여 동작
- 통찰: 단순 패킷 구문 파싱 일치에 그치지 않고 프로토콜 상태 기계(FSM) 기반의 의미론적 일관성과 RTT/타이머 기반 타이밍 제어를 통합 설계해야 이기종 간 완벽한 상호운용성을 달성함.

<details>
<summary>핵심 용어</summary>

- **구문 (Syntax)** : 전송되는 데이터의 형식(Format), 비트 배치 순서, 부호화 방식, 패킷 길이 규약
- **의미 (Semantics)** : 각 필드가 나타내는 제어 정보의 해석 기준 및 오류 처리, 제어 동작 규칙
- **타이밍 (Timing)** : 송수신 개체 간의 전송 속도 조절, 메시지 교환 순서, 타임아웃 및 동기화 제어
- **유한 상태 기계 (FSM)** : 프로토콜 엔터티가 이벤트 수신에 따라 상태를 전이하고 동작을 수행하는 수학적 모델
- **상호운용성 (Interoperability)** : 서로 다른 제조사 및 플랫폼에서 구현된 프로토콜 스택이 표준 규격에 따라 무오류 동작하는 능력

</details>

## 2~4교시 25점 답안

## Ⅰ. 통신 프로토콜 기본 요소의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 컴퓨터 네트워크에서 상이한 기기 간에 데이터와 제어 정보를 정확하고 신뢰성 있게 송수신하기 위해 정의된 통신 규약 체계 |
| 목적 | 이기종 시스템 간 표준 인터페이스 제공, 통신 채널 오류 제어, 흐름 및 혼잡 제어를 통한 네트워크 전송 무결성 보장 |

## Ⅱ. 프로토콜 3대 기본 요소의 특징

| 기본 요소 | 영문 명칭 | 정의 및 핵심 역할 | 주요 포함 항목 |
|---|---|---|---|
| **구문** | Syntax | 데이터의 구조, 포맷, 비트 배치 순서 정의 | 패킷 헤더 길이, 체크섬 필드 위치, 주소 비트 수, 데이터 인코딩 규격 |
| **의미** | Semantics | 각 제어 필드가 뜻하는 정보의 해석 및 동작 규칙 | 플래그 비트(SYN, ACK, FIN) 의미, 에러 검출 시 동작, 상태 천이 규칙 |
| **타이밍** | Timing | 데이터 송수신 속도 조절 및 메시지 교환 순서 제어 | 패킷 송신 간격, 왕복시간(RTT) 측정, 타임아웃 타이머, 세션 연결 순서 |

## Ⅲ. 프로토콜 3대 요소의 상호작용 체계·프로세스

**3대 요소 기반 패킷 파싱 및 유한 상태 기계(FSM) 동작 흐름**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ 프로토콜 3대 요소 상호작용 체계 ]             │
│                                                                        │
│ Ingress Packet 비트 스트림 도착                                        │
│     │                                                                  │
│     ▼ [ 1. 구문 (Syntax) 계층 분석 ]                                   │
│     ┌──────────────────────────────────────────────────────────────┐   │
│     │ 패킷 파서(Parser): 헤더 길이, 포트 번호, 시퀀스 번호 파싱   │   │
│     │ 비트 정렬 및 CRC 체크섬 유효성 검증                         │   │
│     └──────────────────────────────┬───────────────────────────────┘   │
│                                    │                                   │
│                                    ▼ 파싱 성공                         │
│     ▼ [ 2. 의미 (Semantics) 계층 판정 ]                                │
│     ┌──────────────────────────────────────────────────────────────┐   │
│     │ 제어 플래그 확인: "SYN=1, ACK=0" -> 신규 연결 수립 요청 판정 │   │
│     │ 상태 검사: 현재 LISTEN 상태인가? -> TCB 할당 결정            │   │
│     └──────────────────────────────┬───────────────────────────────┘   │
│                                    │                                   │
│                                    ▼ 동작 결정                         │
│     ▼ [ 3. 타이밍 (Timing) 계층 집행 ]                                 │
│     ┌──────────────────────────────────────────────────────────────┐   │
│     │ SYN-ACK 패킷 즉시 회신 (속도 일치화)                         │   │
│     │ 재전송 타이머(RTO = 1s) 구동 및 시퀀스 순서 동기화           │   │
│     └──────────────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────────────────┘
```

| 상호작용 단계 | 주관 요소 | 핵심 수행 작업 |
|---|---|---|
| **프레이밍 및 파싱** | 구문 (Syntax) | 수신된 0과 1의 비트열을 규정된 필드 경계(헤더/페이로드)로 분리 추출 |
| **명령 해석 및 판정** | 의미 (Semantics) | 추출된 코드값(기능 코드, 오류 코드)의 동작 의미를 해석하고 FSM 상태 전이 |
| **순서 동기 및 전송률 제어**| 타이밍 (Timing) | 수신단 버퍼 상황(슬라이딩 윈도우)과 전송 선로 딜레이에 맞추어 ACK 송출 시점 결정 |

## Ⅳ. 프로토콜 3대 요소의 표준 프로토콜별 구현 비교

| 프로토콜 | 구문 (Syntax) 구현 | 의미 (Semantics) 구현 | 타이밍 (Timing) 구현 |
|---|---|---|---|
| **TCP (전송 계층)** | 20바이트 고정 헤더, 시퀀스/ACK 번호 | SYN(연결), FIN(종료), RST(리셋) 플래그 | 슬라이딩 윈도우 흐름 제어, RTO 재전송 타이머 |
| **HTTP/2 (응용 계층)** | 바이너리 프레임(길이 3B, 타입 1B, 플래그 1B)| HEADERS(메타데이터), DATA(본문), PING | 스트림 다중화 우선순위 가중치, 흐름 제어 창 |
| **Modbus TCP (산업용)**| MBAP 헤더(7B) + 기능 코드(1B) + 데이터 | FC 03(Holding Read), FC 05(Coil Write) | 마스터-슬레이브 폴링 간격, 응답 대기 타임아웃 |

## Ⅴ. 프로토콜 설계·구현 시의 한계와 방안

| 한계 | 방안 |
|---|---|
| 구문(Syntax) 파싱 단계에서 가변 길이 필드 경계 미검증 시 버퍼 오버플로 및 정수 오버플로로 인한 원격 코드 실행(RCE) 취약점 발생 | ASN.1, Protocol Buffers 등 정형 스키마 컴파일러를 활용한 엄격한 길이 경계 검사(Bounds Checking) 및 메모리 안전 언어(Rust) 도입 |
| 네트워크 패킷 지연 및 순서 역전 시 송수신 상태 기계(FSM) 간 타이밍 불일치로 세션이 영구 정체되는 교착상태(Deadlock) 발생 | 페트리넷(Petri-Net) 기반 정형 검증을 통한 상태 누락 차단 및 카른/제이콥슨(Karn/Jacobson) 알고리즘 기반 적응형 재전송 타이머(RTO) 적용 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
신규 엔터프라이즈 사내 통신 프로토콜 설계 시, 텍스트 기반 구문(JSON/XML)은 디버깅이 쉬우나 파싱 CPU 부하와 대역폭 낭비가 심하므로, 내부 통신은 바이너리 구문(gRPC/Protobuf)을 채택하고 클라이언트-서버 간 상태 전이를 엄격한 유한 상태 기계(FSM)로 명세화하여 예외 상태(Unexpected Packet) 수신 시 즉각 세션 초기화(RST) 처리.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 프로토콜 유한 상태 기계 (FSM) 정형 검증 아키텍처 ]                  │
│                                                                        │
│   [ 상태: CLOSED ]                                                     │
│          │ Active Open (이벤트: SYN 전송)                              │
│          ▼                                                             │
│   [ 상태: SYN_SENT ] ── (Timeout 발생 시) ──► 재전송 타이머 2배 증가   │
│          │                                                             │
│          │ 수신: SYN-ACK (의미 검증 통과)                              │
│          ▼                                                             │
│   [ 상태: ESTABLISHED ] (타이밍: 윈도우 크기 교환 완료, 정상 데이터 송수신)│
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 검증 기법 | 검증 대상 요소 | 주요 점검 항목 | 적용 도구 |
|---|---|---|---|
| **퍼징 테스트 (Fuzzing)** | 구문 (Syntax) | 비정상 패킷, 경계값 파괴 시 충돌 여부 | AFL, Peach Fuzzer |
| **정형 기법 검증 (Formal)** | 의미 (Semantics) | FSM 교착상태(Deadlock), 도달 불능 상태 | SPIN, TLA+ |
| **지연 시뮬레이션 (Chaos)**| 타이밍 (Timing) | 극단적 패킷 지연, 순서 역전 시 복구력 | Chaos Mesh, NetEm |
