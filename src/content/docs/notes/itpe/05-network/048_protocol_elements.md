- 직렬화(Serialization), 제로 트러스트

## Ⅰ. 통신 프로토콜 기본 요소의 개요

- 핵심 요약 : 구문·의미·타이밍 세 요소의 명세 체계가 이기종 시스템 간 상호운용성과 통신 신뢰성을 확보하는 구조.
- 개념 : 서로 다른 시스템 간 데이터 교환을 위해 미리 합의한 규칙의 집합인 **통신 프로토콜**(Communication Protocol)의 기본 구성 요소는 **구문**(Syntax), **의미**(Semantics), **타이밍**(Timing)의 세 가지.
- 배경 및 필요성 : 하드웨어·운영체제·전송 매체가 다른 노드가 공통 규칙 없이 통신하면 신호 해석 오류, 패킷 충돌, **교착 상태**(Deadlock, 서로가 상대 응답만 기다리며 멈춘 상태)가 발생하는 환경.
- 주요 목적 :
  1. **상호운용성**(Interoperability, 이기종 제품의 상호 동작 능력) 확보
  2. 오류 검출·복구를 포함한 신뢰성 있는 전송
  3. 전송 순서·속도의 동기화를 통한 세션 안정성 확보

## Ⅱ. 통신 프로토콜 기본 요소의 특징 및 장점

- 핵심 요약 : 세 요소를 분리해 명세함으로써 구현체가 달라져도 메시지 해석과 동작이 일치하는 구조.

1. 구문 : 데이터의 형식·필드 배치·부호화 방식을 고정 → 파서 구현이 단순해지고 형식 해석 오류 감소.
2. 의미 : 제어 정보의 뜻과 상태 전이 규칙을 규정 → 같은 메시지에 대한 벤더별 동작의 일치.
3. 타이밍 : 전송 순서·속도·재전송 시점의 규칙 정의 → 유실·지연 상황에서도 세션 복구 가능.
4. 검증 가능성 : 세 요소의 분리 명세가 상태 모델 검증과 적합성 시험을 가능하게 함 → 결함의 조기 발견.

## Ⅲ. 통신 프로토콜 기본 요소의 구조 (흐름)

- 핵심 요약 : 3요소 명세를 상태 모델로 정식화하고 검증·시험을 거쳐 구현에 반영하는 흐름.
- **유한 상태 머신**(FSM, Finite State Machine) : 이벤트와 조건에 따른 상태 전이를 정의하는 모델링 방식.

```text
[ 프로토콜 3대 구성 요소 ]

통신 프로토콜
   구문 : 데이터의 형식·배치·부호화
   의미 : 제어 정보의 해석·동작 규정
   타이밍 : 순서·속도·재전송 규칙
```

```text
[ 명세에서 구현까지 ]

프로토콜 명세 (표준 문서)
   ↓
FSM 상태 모델링
   ↓
정형 검증 (Formal Verification)
   ↓
상호운용성·적합성 시험
   ↓
구현과 보급
```

| 기본 요소 | 세부 항목 | 기능 | 대표 사례 |
| --- | --- | --- | --- |
| 구문 (Syntax) | 프레임 구조 | 필드 길이·순서·경계 정의 | 이더넷 프레임 (프리앰블, MAC(Media Access Control) 주소, 타입, FCS) |
|  | 부호화 | 비트열과 신호의 변환 규칙 | 맨체스터, 64b/66b |
|  | 데이터 표현 | 자료 구조와 **직렬화**(Serialization) 형식 정의 | JSON, ASN.1(Abstract Syntax Notation One) |
| 의미 (Semantics) | 제어 정보 | 연결 수립·해제 등 상태 전이 규정 | TCP(Transmission Control Protocol) 플래그 (SYN, ACK, FIN) |
|  | 오류 제어 | 비트 손상의 감지와 복구 | CRC(Cyclic Redundancy Check), ARQ(Automatic Repeat reQuest) |
|  | 주소 지정 | 단말·프로세스 식별 | IP(Internet Protocol) 주소, MAC 주소, 포트 번호 |
| 타이밍 (Timing) | 속도 정합 | 송수신 속도 차이의 조절 | 슬라이딩 윈도우, 크레딧 기반 흐름 제어 |
|  | 순서 제어 | 역전·중복 수신 방지 | TCP 시퀀스 번호 |
|  | 세션 관리 | 단절 감지와 세션 유지 | Keep-Alive, 재전송 타이머(RTO, Retransmission Timeout) |

## Ⅳ. 구문·의미·타이밍의 비교

- 핵심 요약 : 구문은 형식 오류, 의미는 해석 오류, 타이밍은 순서·시간 오류를 막는 역할 분담 구조.

| 비교 축 | 구문 (Syntax) | 의미 (Semantics) | 타이밍 (Timing) |
| --- | --- | --- | --- |
| 다루는 질문 | 어떤 형식으로 보내는가 | 그 비트가 무엇을 뜻하는가 | 언제·얼마나 빨리 보내는가 |
| 방지하는 오류 | 필드 길이 불일치, 파싱 실패 | 플래그 오해석, 잘못된 상태 전이 | 순서 역전, 시간 초과, 교착 상태 |
| 점검 수단 | 구문·스키마 검증 | 상태 머신 검증, 적합성 시험 | 타이머 검증, 부하·지연 시험 |

- 선택 기준 : 파서 안정성 문제는 구문 명세를, 장비 간 동작 차이는 의미·상태 명세를, 재현되는 지연·멈춤 문제는 타이밍 명세를 우선 점검.

## Ⅴ. 통신 프로토콜 기본 요소의 한계와 방안

- 핵심 요약 : 자연어 명세의 모호성과 비정상 입력 취약점, 독자 확장의 누적을 정형 기법과 입력 검증으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 명세 모호성에 따른 상호운용성 결함 | 표준 문서(RFC, Request for Comments)의 자연어 해석 차이 → 벤더 간 예외 처리 불일치 | 정형 검증 적용, 상호운용성 시험 행사의 정례화 | 시험 불합격률, 예외 누락 건수 |
| 비정상 입력에 따른 보안 취약점 | 비정상 길이·플래그 조합 → 버퍼 오버플로우·서비스 거부 | 엄격한 입력 검증, 메모리 안전 언어 구현, **프로토콜 퍼징**(Protocol Fuzzing, 비정상 메시지 반복 주입 시험)의 상시 수행 | 퍼징 결함 발견 수 |
| 독자 확장의 누적 | 검증되지 않은 벤더 확장 → 상호운용성 저하 | 확장 등록 절차와 표준 준수 검증 게이트 운영 | 비표준 확장 사용 비율 |

## Ⅵ. 통신 프로토콜 기본 요소에 대한 기술사적 제언

- 핵심 요약 : 설계·보안·표준 조직이 명세·검증·보안 통제를 한 묶음으로 다루는 프로토콜 설계 문화의 정착.

1. 플랫폼 설계 조직 : 텍스트 기반 REST(Representational State Transfer) 구간의 파싱 부담이 큰 경로에 gRPC·Protocol Buffers 같은 바이너리 직렬화 전환 검토.
2. 보안 아키텍처 조직 : 전송 구간마다 TLS(Transport Layer Security) 상호 인증을 적용하고 스위치 수준 헤더 검사로 제로 트러스트 원칙 구현.
3. 표준 전략 조직 : 신규 프로토콜 도입 시 구문·의미·타이밍 명세와 정형 검증·상호운용성 시험 계획을 일괄 산출물로 확정.

## Ⅶ. 결론

- 핵심 요약 : 통신 프로토콜의 기본 요소는 구문·의미·타이밍의 명세와 검증 체계로 정리.
- 상호운용성과 보안은 명세 모호성의 제거와 입력 검증에서 출발하는 설계 과제.
