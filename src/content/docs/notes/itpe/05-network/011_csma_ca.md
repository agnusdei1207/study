## 지식 로드맵 내 현재 위치

네트워크 → 무선 LAN → **CSMA/CA**

## 30초 인출

- 본질: **CSMA/CA** : 무선 매체를 감지하고 무작위 대기해 동시 송신 충돌 가능성을 줄이는 접근 방식
- 메커니즘: 채널 감지 → 유휴 구간 확인 → 백오프 → 송신 → ACK 확인; RTS/CTS는 선택적 보조 절차
- 통찰: 무선 매체의 반이중(Half-Duplex) 특성상 송신 중 충돌 감지(CD)가 불가능하므로 사전에 반송파를 감지하고 임의 백오프 시간 및 RTS/CTS 핸드셰이크를 통해 충돌을 능동적으로 회피하는 무선랜 매체 접근 제어 방식임.

<details>
<summary>핵심 용어</summary>

- **CSMA/CA(Carrier Sense Multiple Access with Collision Avoidance)** : 채널 사용 여부를 감지하고 전송을 분산해 충돌을 회피하는 무선 매체 접근 방식
- **DCF(Distributed Coordination Function)** : IEEE 802.11의 분산형 매체 접근 기능
- **DIFS(DCF Interframe Space)** : DCF의 송신 경쟁 전에 확인하는 프레임 간 간격
- **백오프(Backoff)** : 선택한 슬롯 수만큼 유휴 시간을 기다려 송신 시점을 분산하는 절차
- **RTS/CTS(Request to Send/Clear to Send)** : 데이터 송신에 앞서 매체 사용 시간을 알리는 선택적 제어 프레임 교환
- **NAV(Network Allocation Vector)** : 수신한 프레임의 지속시간 정보에 따라 매체 점유를 가상으로 추적하는 값
- **ACK(Acknowledgment)** : 수신 성공을 알리는 확인 응답

</details>

## 2~4교시 25점 답안

## Ⅰ. CSMA/CA의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 무선 채널의 상태를 사전에 감지(Carrier Sense)하여 유휴(Idle)할 때만 프레임을 송신하고 충돌 위험을 임의 지연(Random Backoff)으로 회피(Collision Avoidance)하는 다중 접속 제어 프로토콜 |
| 목적 | 송수신 동시 수행 불가(Self-Interference)로 인한 충돌 감지 한계 극복 및 다수 무선 단말 간 공평한 공유 매체 접근 보장 |

## Ⅱ. CSMA/CA의 특징

| 특징 | 상세 내용 |
|---|---|
| 반이중 통신 대응 | 자신의 송신 신호 전력이 수신 감도보다 수만 배 커서 송신 중 타 신호 충돌 감지 불가(CD 대체) |
| 계층적 IFS 간격 | SIFS, PIFS, DIFS, EIFS 등 프레임 유형별 대기 시간 차등화로 중요 제어 패킷 우선권 부여 |
| 지수 백오프 알고리즘| 충돌 발생 시 경쟁 윈도우(CW) 크기를 2배씩 늘려 재충돌 확률을 수학적으로 분산 억제 |
| RTS/CTS 가상 반송파| 송신 전 RTS/CTS 제어 프레임을 교환하고 NAV(Network Allocation Vector)를 설정하여 무선 매체 예약 |

## Ⅲ. CSMA/CA의 체계·프로세스

**CSMA/CA 기본 전송 절차 및 랜덤 백오프 타이밍도**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ CSMA/CA 전송 메커니즘 ]                       │
│                                                                        │
│ 매체 상태                                                              │
│ ──[ Busy ]──►│                                                         │
│               │ DIFS 대기                                              │
│               ├────────►│                                              │
│                         │ 랜덤 백오프 슬롯 카운트다운 (Slot Time 단위) │
│                         ├─────┬─────┬─────┬─────►│                     │
│                         │ Slot│ Slot│ Slot│ Slot│ [ 프레임 전송 시작 ]  │
│                         └─────┴─────┴─────┴─────┴──────────────────────►│
│                                                  │ SIFS 대기           │
│                                                  ├────►│               │
│                                                        │ [ ACK 수신 ]  │
│                                                        └──────────────►│
└────────────────────────────────────────────────────────────────────────┘
```

| IFS 구분 | 간격 명칭 | 지속 시간 크기 | 주요 용도 및 우선순위 |
|---|---|---|---|
| **SIFS** | Short IFS | 가장 짧음 (16μs, 5GHz) | 즉각적 ACK 프레임, CTS 프레임, 블록 전송 시 최우선 접근 |
| **PIFS** | PCF IFS | 중간 (SIFS + 1 슬롯) | 중앙 집중식 무경쟁 제어(PCF) 환경에서 폴링 프레임 전송용 |
| **DIFS** | DCF IFS | 기본 (SIFS + 2 슬롯) | 일반 분산 경쟁 제어(DCF) 환경에서 데이터 프레임 전송 전 대기 |
| **EIFS** | Extended IFS | 가장 긺 | 이전 프레임 수신 중 CRC 오류 발생 시 타 노드 전송 보호용 대기 |

## Ⅳ. CSMA/CA의 종류·비교

| 비교 항목 | 유선 이더넷 (CSMA/CD) | 무선랜 (CSMA/CA) |
|---|---|---|
| **표준 규격** | IEEE 802.3 | IEEE 802.11 a/b/g/n/ac/ax/be |
| **전송 방식** | 전이중/반이중 케이블 전송 | 반이중(Half-Duplex) 공간 RF 전파 |
| **충돌 처리** | 충돌 감지(Collision Detection) 후 Jam 신호 송출 | 사전 회피(Collision Avoidance) 및 임의 백오프 |
| **확인 응답** | 물리적 신호 감지로 불필요 | 수신측 명시적 L2 ACK 프레임 필수 회신 |
| **전송 효율** | 높음 (충돌 즉시 중단) | 오버헤드 큼 (IFS, 백오프, ACK, RTS/CTS 교환) |

## Ⅴ. CSMA/CA의 한계와 방안

| 한계 | 방안 |
|---|---|
| 두 단말이 장애물로 서로를 감지하지 못해 AP에 동시 송신 시 발생하는 숨은 결절점(Hidden Node) 충돌 | 물리적 반송파 감지 외에 RTS/CTS 프레임 교환 기반 가상 반송파 감지(NAV 타이머 설정) 강제 |
| 서로 다른 BSS 간 주파수 중첩으로 불필요하게 대기하여 처리율이 급감하는 노출 결절점(Exposed Node) 문제 | Wi-Fi 6/7 BSS Coloring 기술 도입으로 공간 주파수 재사용(Spatial Reuse) 구현 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
고밀도 엔터프라이즈 AP 환경 구축 시, 모든 패킷에 RTS/CTS를 적용하면 프로토콜 오버헤드로 인해 망 처리율이 급감하므로 `RTS Threshold` 임계치를 2347바이트(기본값)에서 1000바이트 수준으로 현장 실측 조정하여 대용량 프레임에만 선택 적용.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ RTS/CTS 기반 숨은 결절점 해결 및 NAV 설정 메커니즘 ]                │
│                                                                        │
│   [ 단말 A ]               [ AP ]               [ 단말 B (Hidden) ]     │
│       │                      │                          │              │
│       ├─── RTS 전송 ────────►│                          │ (A 감지 불가)│
│       │                      ├──── CTS 브로드캐스트 ───►│              │
│       │                      │                          ├─► NAV 타이머 │
│       │                      │                          │   설정 후    │
│       ├─── Data 전송 ───────►│                          │   전송 보류  │

```

### 3. 기술 유형 및 비교 평가
| 매체 접근 방식 | 통제 주체 | 충돌 발생 가능성 | 실시간성 보장 | 주 적용 규격 |
|---|---|---|---|---|
| **DCF (분산 제어)** | 각 단말 자체 경쟁 (CSMA/CA) | 있음 (경쟁 기반) | 보장 불가 (Best Effort) | 범용 상용 무선랜 전체 |
| **PCF (중앙 제어)** | AP의 순차적 폴링 (Polling) | 없음 (무경쟁 구간) | 지연 보장 가능 | 특수 산업용 무선 환경 |
| **EDCA (QoS 확장)** | 트래픽 범주(AC)별 차등 백오프 | 낮음 (우선순위 분리) | 음성/영상 QoS 보장 | IEEE 802.11e/n/ac/ax/be |
