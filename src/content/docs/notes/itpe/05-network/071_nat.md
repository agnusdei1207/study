## 연관 키워드

- NAT(Network Address Translation), 사설 IP, 공인 IP, NAPT(Network Address Port Translation)
- 정적 NAT, 동적 NAT, CGNAT(Carrier-Grade NAT), 변환 테이블(Translation Table)
- NAT 통과(NAT Traversal), STUN, TURN, ICE, IPv6, 세션 로그

## Ⅰ. NAT의 개요

- 핵심 요약 : 사설 주소망과 공인 인터넷 사이에서 주소·포트를 치환해 주소 고갈과 내부 노출 문제를 함께 다루는 변환 계층.
- 개념 : RFC(Request for Comments) 1918의 사설 IP 주소 대역을 쓰는 내부 호스트가 공인 IP 주소로 외부와 통신하도록 IP(Internet Protocol) 패킷의 주소와 포트를 바꾸는 **네트워크 주소 변환** (NAT, Network Address Translation).
- 배경 및 필요성 : IPv4(Internet Protocol version 4)의 주소 공간은 2^32개로 한정되어 공인 주소 고갈이 진전되었고, 내부 호스트를 외부에 직접 노출하지 않으려는 요구도 함께 커짐.
- 주요 목적 : 공인 주소의 절약과 재사용, 내부 망 구조의 은폐, 인터넷 회선 교체 시 내부 주소 재설계 회피.

## Ⅱ. NAT의 특징 및 장점

- 핵심 요약 : 헤더 재작성과 변환 테이블의 결합으로 공인 주소를 나누어 쓰고 내부 구조를 감추는 방식.

1. 헤더 재작성 : 출발지 IP와 TCP(Transmission Control Protocol)·UDP(User Datagram Protocol) 포트를 공인 값으로 치환하고 체크섬을 재계산 → 내부 호스트의 인터넷 세션 성립.
2. **변환 테이블** (Translation Table) : 내부 주소·포트와 공인 주소·포트의 대응을 세션 동안 기억 → 응답 패킷의 원래 호스트 복원.
3. 포트 다중화 : **NAPT** (Network Address Port Translation, 하나의 공인 주소에 포트 번호를 더해 다수 호스트를 수용하는 방식) 적용 → 공인 주소 소모 억제.
4. 내부 구조 은폐 : 사설 주소의 외부 노출 차단으로 내부 토폴로지 정찰 제한 → 방화벽 정책과 병행하는 보완적 경계 효과.
5. 세션 자원 회수 : TCP는 FIN·RST 수신 시, UDP는 유휴 타이머 만료 시 테이블 항목 삭제 → 포트 자원의 순환 사용.

## Ⅲ. NAT의 구조 (흐름)

- 핵심 요약 : 송신 시 출발지 치환과 테이블 등록, 응답 시 테이블 역조회에 따른 목적지 복원의 2단계 흐름.

```text
[ NAPT 송수신 흐름 ]

내부 호스트 192.168.1.10:5000
   ↓ 송신 (사설 출발지)
NAT 장비 (공인 203.0.113.1)
   ↓ 출발지 치환 → 203.0.113.1:10001
외부 서버
   ↓ 응답 (목적지 포트 10001)
NAT 장비 (테이블 역조회)
   ↓ 목적지 복원
내부 호스트 192.168.1.10:5000
```

- NAT 통과(NAT Traversal) : 외부에서 내부로 먼저 연결할 수 없는 제약을 우회하는 기법군.
  1. **STUN** (Session Traversal Utilities for NAT, RFC 5389) : 공인 반사 주소와 NAT 유형 확인.
  2. **TURN** (Traversal Using Relays around NAT, RFC 5766) : 직접 연결 불가 시 릴레이 서버 경유.
  3. **ICE** (Interactive Connectivity Establishment, RFC 8445) : 후보 경로를 모아 우선순위로 접속 경로 확정.

```text
[ ICE 연결 수립 절차 ]

후보 수집 (로컬 주소, STUN 반사 주소)
   ↓
TURN 릴레이 후보 추가
   ↓
우선순위 순 연결 점검
   ↓ 직접 경로 실패 시
릴레이 경로로 전환·확정
```

## Ⅳ. NAT 유형의 비교

- 핵심 요약 : 공인 주소를 아낄수록 외부 접근이 어려워지는 상충 관계에 따라 용도별 유형을 선택.
- 유형 정의 :
  1. **정적 NAT** (Static NAT) : 내부 주소와 공인 주소의 고정 1:1 매핑.
  2. **동적 NAT** (Dynamic NAT) : 공인 주소 풀에서 세션 단위로 주소 할당.
  3. **CGNAT** (Carrier-Grade NAT) : 통신사 계층에서 수행하는 대규모 NAT로 RFC 6598 공유 주소 사용.

| 비교 축 | 정적 NAT | 동적 NAT | NAPT | CGNAT |
| --- | --- | --- | --- | --- |
| 변환 방식 | 1:1 고정 매핑 | 공인 주소 풀에서 할당 | 공인 주소 1개의 포트 다중화 | 통신사 계층의 대규모 NAT |
| 동시 수용 | 공인 주소 수와 동일 | 공인 주소 풀 크기가 상한 | 포트 자원 범위 내 다수 | 가입자 단위 대규모 수용 |
| 외부 접근 | 가능 | 제한적 | 인바운드 기본 차단 | 사실상 불가 |
| 주요 적용 | DMZ 공개 서버 | 소규모 지사 회선 | 가정용 공유기, 사내망 | 이동통신 가입자망 |

- 선택 기준 :
  1. 외부 공개 서버는 정적 NAT로 고정 경로 확보.
  2. 다수 내부 호스트의 인터넷 접속은 NAPT가 기본.
  3. 공인 주소가 극도로 제한된 이동통신 가입자망은 CGNAT 적용.

## Ⅴ. NAT의 한계와 방안

- 핵심 요약 : 종단 간 연결 제약, 페이로드 주소 불일치, 추적 곤란을 기법·설정·기록으로 분리 대응.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 인바운드 P2P(Peer-to-Peer) 접속 차단 | 외부 주도 연결 불가 → 화상회의·VoIP(Voice over IP) 실패 | STUN·TURN·ICE 조합, 필요 서비스 한정의 포트 포워딩 명시 설정(UPnP(Universal Plug and Play) 자동 개방 제한) | 연결 성공률, 릴레이 사용 비율 |
| 페이로드 내 주소 불일치 | FTP(File Transfer Protocol)·SIP(Session Initiation Protocol) 본문의 사설 주소가 변환 후 연결 실패 유발 | **ALG** (Application Layer Gateway, 응용 계층에서 페이로드 주소를 함께 수정하는 기능)를 필요 프로토콜에 한정 활성화 | 세션 실패율 |
| 공유 주소의 추적 곤란 | 다수 호스트가 공인 주소 공유 → 공격 출처 특정 지연 | 시각·공인 포트·내부 주소를 묶은 세션 로그 보관 | 로그 보관 적합성, 추적 소요 시간 |

## Ⅵ. NAT에 대한 기술사적 제언

- 핵심 요약 : IPv6 전환 병행, 클라우드 트래픽 비용 관리, 내부 무신뢰 보안 체계의 3축 제안.

1. 망 운영 조직은 IPv6(Internet Protocol version 6) 전환 일정을 망 계획에 포함하고 듀얼 스택(Dual Stack) 구성을 단계적으로 확대하여 NAT 의존도를 낮춰야 한다.
2. 클라우드 운영 조직은 관리형 NAT 게이트웨이의 처리량 비용이 커지는 대용량 트래픽을 프라이빗 엔드포인트 방식으로 우회시켜 변환 비용 구조를 관리해야 한다.
3. 보안 조직은 NAT 내부 호스트를 신뢰하지 않는다는 제로 트러스트 관점에서 출구 필터링(Egress Filtering)과 DNS(Domain Name System) 보안 필터링을 적용해 명령제어(C2, Command and Control) 통신을 차단해야 한다.

## Ⅶ. 결론

- 핵심 요약 : NAT는 주소 고갈 시대의 실용적 해법이자 종단 간 원칙에 제약을 더하는 과도기 변환 기술.
- 편익과 제약의 상충을 인지한 설계와 운영이 NAT 활용의 본질 조건이 됨.
