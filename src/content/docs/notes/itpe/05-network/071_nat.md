## 지식 로드맵 내 현재 위치

네트워크 → IP 전달·주소 변환 → NAT

## 30초 인출

- 본질: **NAT(Network Address Translation)** 은 패킷이 네트워크 경계를 지날 때 IP 주소·포트 정보를 다른 값으로 변환하는 기능
- 메커니즘: 변환 매핑을 기록하고 응답 패킷에 역변환을 적용해 내부 종단으로 전달

<details>
<summary>핵심 용어</summary>

- **NAT(Network Address Translation):** IP 패킷의 주소 정보를 네트워크 경계에서 변환하는 기능
- **NAPT(Network Address and Port Translation):** 주소와 전송 계층 포트를 함께 바꿔 다수 내부 연결을 공인 주소에 매핑하는 방식
- **ALG(Application-Level Gateway):** 응용 프로토콜 내용을 분석해 주소·포트가 실린 페이로드와 NAT 매핑을 연계하는 기능
- **NAT-T(NAT Traversal):** IPsec 트래픽을 UDP로 캡슐화해 NAT 경유를 지원하는 기술
- **IPsec(Internet Protocol Security):** IP 계층 통신에 인증·무결성·기밀성 보호를 제공하는 프로토콜 모음
- **AH(Authentication Header):** IPsec에서 패킷 인증·무결성을 제공하는 확장 헤더
- **ESP(Encapsulating Security Payload):** IPsec에서 페이로드 보호 기능을 제공하는 프로토콜
- **UDP(User Datagram Protocol):** 비연결 데이터그램 전송 프로토콜
- **STUN(Session Traversal Utilities for NAT):** 클라이언트가 NAT 경계에서 관측되는 주소·포트 정보를 알아내는 프로토콜
- **TURN(Traversal Using Relays around NAT):** 직접 통신이 어려울 때 중계 주소를 제공하는 프로토콜
- **ICE(Interactive Connectivity Establishment):** 후보 주소를 교환·검사해 통신 경로를 선택하는 절차

## Ⅱ. NAPT 매핑

```text
내부 단말 192.168.1.10:5000
          ↓ 송신 주소·포트 변환
NAT 매핑 192.168.1.10:5000 ↔ 192.0.2.10:40001
          ↓ 외부 서버로 전달
응답 패킷 → 매핑 조회 → 내부 주소·포트로 역변환
```

| 유형 | 변환 관계 |
|---|---|
| 정적 NAT | 내부·외부 주소의 고정 매핑 |
| 동적 NAT | 주소 풀에서 외부 주소를 동적으로 매핑 |
| **NAPT(Network Address and Port Translation)** | 주소와 포트 매핑으로 다수 연결을 구분 |

제언: 외부에서 시작되는 연결과 내부에서 시작되는 연결의 매핑·접근 정책을 분리

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **NAT(Network Address Translation)** 은 네트워크 경계를 통과하는 IP 패킷의 주소 정보를 변환하는 기능 |
| 목적 | 주소 체계 연계와 내부·외부 네트워크 간 패킷 전달 |

## Ⅱ. 변환 유형과 패킷 경로

```text
내부 패킷
   ↓ NAT 장비의 주소·포트 매핑
변환된 외부 패킷 ── 인터넷 전달 ──▶ 상대 호스트
   ▲                                  │ 응답
   └──────────── 매핑 역조회 ◀────────┘
```

| 유형 | 매핑 방식 | 활용 특성 |
|---|---|---|
| 정적 주소 NAT | 사전에 정한 주소 간 고정 변환 | 외부 공개 주소가 필요한 내부 서비스 |
| 동적 NAT | 주소 풀에서 주소 할당 | 풀의 사용 가능 주소 수에 영향 |
| NAPT | IP 주소와 전송 계층 포트를 함께 변환 | 여러 내부 연결의 외부 주소 공유 |

## Ⅲ. 종단 간 통신 영향

| 영향 | 발생 이유 | 대응 예 |
|---|---|---|
| 외부에서 내부 서비스로 새 연결 어려움 | 동적 매핑만으로는 내부 대상 매핑이 정해지지 않음 | 필요한 서비스에 한해 명시적 정적 매핑·방화벽 정책 설정 |
| 주소·포트가 응용 페이로드에 들어간 프로토콜의 연결 실패 | NAT가 IP 헤더만 바꿔도 페이로드 주소는 그대로 남을 수 있음 | 응용 프로토콜 인식 중계 또는 NAT 인지형 모드 사용 |
| 단말 간 직접 연결 실패 | 양쪽 NAT 매핑·필터링 동작이 서로 달라 직접 경로 성립이 어려울 수 있음 | **STUN(Session Traversal Utilities for NAT)** / **ICE(Interactive Connectivity Establishment)** 로 후보 경로 검사, 필요 시 **TURN(Traversal Using Relays around NAT)** 중계 |

## Ⅳ. **IPsec(Internet Protocol Security)** 경유와 보안 고려

| 항목 | NAT와의 관계 | 설계 고려 |
|---|---|---|
| **AH(Authentication Header)** | IP 헤더 무결성 검증과 주소 변경이 충돌 가능 | NAT 경유 요건과 IPsec 모드·정책 검토 |
| **ESP(Encapsulating Security Payload)** | 일반 NAT가 암호화된 전송 포트를 직접 식별하기 어려움 | **NAT-T(NAT Traversal)** **UDP(User Datagram Protocol)** 캡슐화 지원 여부 확인 |
| NAT 매핑 상태 | 변환 자체가 접근 통제 정책은 아님 | 방화벽 규칙·로그·세션 제한을 별도 구성 |

## Ⅴ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| NAT를 내부망 보안 경계로 간주하면 새 연결 허용·매핑 오설정에 따른 노출을 놓침 | NAT 매핑과 방화벽 접근 규칙을 별도 검토하고, 서비스별 외부 개방·로그·만료 정책을 함께 관리 |
