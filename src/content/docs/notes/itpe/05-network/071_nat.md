 ┃
 ┣━ Ⅰ 개요 ───── IPv4 공인 주소 고갈과 내부 보안 위협 → 사설 IP와 공인 IP 간 L3/L4 주소 동적 변환
 ┣━ Ⅱ 특징 ───── 사설 IP(RFC 1918) 재사용, NAPT(포트 기반 다중화), 내부 토폴로지 은닉(보안), 종단간 투명성 훼손

## 한 줄 본질
- 43억 개에 불과한 IPv4 공인 주소의 전 세계적 고갈과 사내망 직접 침입 위협 → 라우터 경계에서 수천 대의 내부 사설 IP(RFC 1918)를 단 1개의 공인 IP와 임의의 L4 포트 번호로 묶어 변환 전송 → 공인 IP 절약 및 내부망 은닉 보호 / 인터넷의 대원칙인 종단 간 직접 연결성(End-to-End) 훼손

## 핵심 용어
- NAPT(Network Address Port Translation, PAT): 단 1개의 공인 IP 뒤에 16비트 TCP/UDP 포트 번호(최대 65,535개)를 다중화하여 수천 대의 사설 IP 호스트가 동시에 인터넷에 접속할 수 있도록 지원하는 실무 표준 기술
- 응용 계층 게이트웨이(ALG, Application Layer Gateway): IP/TCP 헤더뿐만 아니라 애플리케이션 페이로드 내부에도 자신의 사설 IP와 포트를 적어 보내는 프로토콜(FTP PORT 명령, SIP/SDP 등)을 인식해 페이로드 내부 IP까지 공인 IP로 능동 치환해 주는 지능형 NAT 엔진
- NAT-T(NAT Traversal): 패킷 헤더가 바뀌면 무결성 해시가 깨지는 IPSec 암호화 패킷(ESP)을 표준 L4 UDP 포트 4500번으로 한 번 더 감싸서(UDP 캡슐화) NAT 장비를 안전하게 통과시키는 표준 기술

## 핵심 통찰
- IPv4의 수명을 수십 년 연장시킨 구원투수이자 IPv6 확산을 가로막은 주역: 1990년대에 이미 고갈되었어야 할 IPv4가 오늘날까지 버틴 일등공신이지만, 역설적으로 NAT의 높은 편의성 때문에 기업들이 차세대 IPv6 도입을 계속 미루는 원인을 제공
- 의도치 않게 얻은 1차 방화벽(보안) 효과: 외부 인터넷의 공격자가 내부 사설망 호스트의 사설 IP(192.168.x.x)로 직접 패킷을 보낼 수 있는 라우팅 경로가 존재하지 않으며, 내부에서 먼저 나간 세션에 대해서만 응답이 허용되므로 강력한 침입 차단 기능 발휘
- P2P 통신(음성통화, 파일공유)의 최대 걸림돌: 양쪽 단말이 모두 NAT 뒤 사설망에 갇혀 있으면 서로의 공인 IP와 포트를 알 수 없어 연결이 불가능하므로, 중간 중계 서버를 거쳐 홀펀칭(Hole Punching)을 수행하는 STUN, TURN, ICE 기술이 불가피하게 동원됨

## 이웃 토픽과 구분
- 프록시(Proxy) vs NAT: 프록시는 7계층 응용 프로그램 수준에서 클라이언트 요청을 완전히 끊고 자신이 새로 요청을 생성하는 L7 중계 / NAT는 3계층(IP)과 4계층(Port) 헤더만 고속으로 바꿔치기하여 전송하는 L3/L4 네트워크 계층 기술

## 문제·원인·대책
- 적용 상황: 사설망 내부 클라이언트의 액티브 FTP(Active Mode FTP) 파일 전송
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 액티브 FTP 접속 시 제어 세션은 맺어지나 파일 다운로드 실패 | FTP 클라이언트가 페이로드 데이터 안에 사설 IP를 적어 보내 서버가 역접속 불가 | 라우터에 FTP 전용 ALG(Application Layer Gateway) 모듈 활성화 또는 패시브 모드(Passive FTP) 전환 | 페이로드 내부 사설 IP가 공인 IP로 자동 변환되어 데이터 세션 정상 개통 |
| NAT 환경 경유 시 원격 재택근무자의 IPSec VPN 접속 실패 | NAT가 IP 헤더를 변환함에 따라 IPSec AH 무결성 검증 실패 및 암호화된 ESP 헤더 변환 불가 | IKEv2 NAT-T(NAT Traversal) 활성화로 ESP 패킷을 UDP 4500 포트로 캡슐화 | NAT 라우터가 일반 UDP 패킷으로 인식하여 암호화 세션 무손실 통과 |

## 이렇게 출제된다
- 제105회 1교시: "NAT(Network Address Translation)의 유형 및 문제점과 해결 방안을 설명하시오." → 요구 포인트: Static/Dynamic/NAPT 3대 유형 비교, 종단간 투명성 훼손으로 발생하는 프로토콜 장애(FTP, VoIP SIP, IPSec), 해결 기술(ALG, NAT-T, STUN)

## 내 의견
- [임시방편 NAT의 한계 직시와 IPv6(NAT64/DNS64) 네이티브 전환 추진] 통신사 및 클라우드 사업자의 통신망에 대규모 Carrier-Grade NAT(CGNAT)를 중첩 적용하는 것은 세션 테이블 폭증과 포트 고갈, P2P 서비스 장애를 양산하는 미봉책에 불과함 → 나라면: 신규 대규모 모바일 및 IoT 백본망 구축 시 순수 IPv6 싱글 스택을 전면 채택하고, 기존 레거시 IPv4 서비스와의 연동은 NAT64 및 DNS64 게이트웨이를 경유하도록 구성하여 주소 고갈 문제를 근본적으로 영구 해결

## 찾아볼 것
- 순수 IPv6 단말이 레거시 IPv4 서버와 통신할 수 있도록 주소를 자동 합성·변환해 주는 NAT64(RFC 6146) 및 DNS64(RFC 6147) 표준 규격
