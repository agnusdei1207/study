## Ⅰ. NAT(Network Address Translation)의 개요

- **개념** : 사설 IP 주소 공간(RFC 1918)을 사용하는 내부 네트워크의 호스트가 공인 IP 주소를 사용하는 외부 인터넷과 통신할 수 있도록 라우터나 방화벽 계층에서 IP 패킷 헤더의 IP 주소와 포트 번호를 변환하는 네트워크 주소 변환 기술 (RFC 3022).
- **배경 및 필요성** : 32비트 IPv4 주소 체계(약 43억 개)의 급격한 고갈 위기를 지연시키고, 공인 IP 할당 비용 절감 및 외부 공격자로부터 내부 사설 호스트를 직접 노출하지 않고 은폐할 필요성 대두.
- **핵심 목적** : 한정된 공인 IPv4 주소 자원의 절약 및 재사용, 내부 네트워크 토폴로지 은폐를 통한 보안성 향상, ISP 회선 변경 시 내부 주소 재구성 없는 유연성 확보.

## Ⅱ. NAT의 핵심 아키텍처 및 동작 메커니즘

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ NAPT / PAT 주소 및 포트 변환 메커니즘 ]            │
│                                                                        │
│   [ 내부 사설망 (Private LAN) ]          [ NAT 게이트웨이 / 공유기 ]   │
│   Client A: 192.168.1.10:5000            공인 IP: 203.0.113.1          │
│   Client B: 192.168.1.20:5000                   │                      │
│        │                                        │                      │
│        │ 1. 패킷 송출 (SIP: 192.168.1.10:5000)  │                      │
│        ├───────────────────────────────────────►│                      │
│        │                                        │                      │
│        │                        [ NAT 변환 테이블 매핑 ]                │
│        │                        192.168.1.10:5000 ◄-► 203.0.113.1:10001│
│        │                        192.168.1.20:5000 ◄-► 203.0.113.1:10002│
│        │                                        │                      │
│        │                                        │ 2. 변환 후 인터넷 송출│
│        │                                        ├─────────────────────►│
│        │                                        │ (SIP: 203.0.113.1:10001)
│        │                                        │                      │
│        │                                        │ 3. 응답 패킷 수신    │
│        │                                        │◄─────────────────────┤
│        │                                        │ (DIP: 203.0.113.1:10001)
│        │ 4. 사설 주소 복원 전달                  │                      │
│        │◄───────────────────────────────────────┤                      │
│        │ (DIP: 192.168.1.10:5000)               │                      │
└────────────────────────────────────────────────────────────────────────┘
```

- **L3/L4 헤더 재작성 및 체크섬 재계산** : 라우터는 송출되는 IP 헤더의 송신지 IP를 공인 IP로 바꾸고, L4(TCP/UDP) 헤더의 송신 포트를 미사용 중인 고유 포트로 매핑 변경 후 IP 및 TCP/UDP 체크섬을 재계산.
- **NAT 상태 테이블 (NAT Translation Table)** : 내부 IP:Port와 외부 공인 IP:Port 간의 1:1 매핑 튜플을 세션 동안 유지하며, 패킷 반환 시 해당 테이블을 조회하여 원래 사설 IP로 역변환.
- **세션 타임아웃** : TCP 세션은 `FIN/RST` 수신 또는 유휴 시간 경과 시 테이블에서 삭제되며, UDP는 짧은 유휴 타이머(보통 30초~2분) 후 자동 만료.

## Ⅲ. NAT의 주요 유형 및 NAT Traversal 기술 비교 분석

| 기술 구분 | 변환 방식 및 특성 | 특징 및 장단점 | 주요 적용 분야 |
|---|---|---|---|
| **Static NAT (정적)** | 내부 사설 IP 1개 ◄-► 공인 IP 1개 고정 1:1 매핑 | IP 절감 효과 없음, 외부에서 내부 접근 가능 | DMZ 공개 웹 서버, 메일 서버 |
| **Dynamic NAT (동적)**| 내부 사설 IP ◄-► 가용 공인 IP 풀(Pool)에서 동적 할당 | 공인 IP 개수만큼만 동시 접속 가능 | 소규모 지사 업무용 회선 |
| **NAPT / PAT (포트 변환)**| 단일 공인 IP에 포트 번호를 결합하여 수천 대 동시 수용 | IP 절감 극대화, 가장 널리 사용 | 가정용 공유기, 기업 사무실 LAN |
| **CGNAT (대규모)** | ISP 통신사 레벨에서 수행하는 2중 NAT (RFC 6598)| 가입자 IP 절감, P2P 통신 방해 심각 | 모바일 LTE/5G 가입자망 |

- **NAT 통과 (NAT Traversal) 메커니즘** (P2P, WebRTC, VoIP용) :
  - **STUN (Session Traversal Utilities for NAT, RFC 5389)** : 클라이언트가 외부에 위치한 STUN 서버에 질의하여 자신의 공인 반사 주소(Mapped Address)와 NAT 타입을 확인.
  - **TURN (Traversal Using Relays around NAT, RFC 5766)** : Symmetric NAT 등 직접 P2P 연결이 불가능한 경우 외부 릴레이 서버를 경유하여 미디어 스트림 중계.
  - **ICE (Interactive Connectivity Establishment, RFC 8445)** : STUN, TURN, 로컬 IP 등 가용한 모든 후보(Candidates) 경로를 수집하여 우선순위 기반 최적 연결 수립.

## Ⅳ. NAT의 주요 한계점 및 해결 방안

- **IP 종단 간 원칙(End-to-End Principle) 파괴 및 인바운드 P2P 접속 차단** :
  - **한계점** : 외부에서 내부 사설망 호스트로의 선제적 세션 연결이 불가능하여 P2P 파일 공유, 화상 회의(WebRTC), VoIP 음성 통화 연결 실패.
  - **해결 방안** : STUN/TURN/ICE 프로토콜 체계 구축, UPnP 포트 포워딩 자동화 또는 순수 종단 간 연결을 복원하는 IPv6로의 전환.
- **애플리케이션 계층 페이로드에 IP가 포함된 프로토콜 오류 (FTP, SIP)** :
  - **한계점** : FTP의 PORT 명령이나 SIP 시그널링 등 L7 페이로드 내에 사설 IP가 텍스트로 박혀 있는 경우 통신 실패.
  - **해결 방안** : 라우터/방화벽에 L7 페이로드 내부의 IP 주소까지 함께 파싱·변환해 주는 응용 계층 게이트웨이(ALG: Application Layer Gateway) 기능 활성화.

## Ⅴ. NAT 적용 및 발전을 위한 기술사적 제언

- **IPv6로의 완전한 마이그레이션 추진** : NAT는 IPv4 고갈을 연장하기 위한 과도기적 미봉책에 불과하므로, 듀얼 스택(Dual Stack) 및 NAT64/DNS64 기술을 통해 글로벌 IPv6 인프라 전환 가속화.
- **클라우드 VPC 환경에서의 NAT 게이트웨이 비용 최적화** : 퍼블릭 클라우드(AWS/Azure)의 관리형 NAT Gateway는 데이터 처리량에 비례해 막대한 비용이 발생하므로, S3/DynamoDB 트래픽은 게이트웨이 VPC 엔드포인트(PrivateLink)로 우회 분리.
- **Zero Trust 보안 아키텍처 연계** : 사설 IP에 의한 암묵적 신뢰를 배제하고, 아웃바운드 NAT 트래픽에 대해서도 Egress 필터링과 DNS 보안 필터링을 강제하여 악성코드 C&C 통신 차단.
