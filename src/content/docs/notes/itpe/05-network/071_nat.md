## 연관 키워드

- NAT(Network Address Translation), 사설 IP, 공인 IP, NAPT(Network Address Port Translation), PAT(Port Address Translation)
- 정적 NAT, 동적 NAT, CGNAT(Carrier-Grade NAT), 변환 테이블, NAT 통과(NAT Traversal)
- STUN, TURN, ICE, ALG, IPv6, 듀얼 스택(Dual Stack), 세션 로그

## Ⅰ. NAT의 개요

- 핵심 요약 : 사설 주소망과 공인 인터넷 사이에서 주소와 포트를 바꿔 주는 IP 주소 변환 계층.
- 개념 : RFC(Request for Comments) 1918의 사설 주소 대역을 쓰는 내부 호스트가 공인 주소로 외부와 통신하도록, 라우터나 방화벽이 IP(Internet Protocol) 패킷의 주소와 포트를 바꾸는 **네트워크 주소 변환** (NAT, Network Address Translation).
- 배경 및 필요성 : IPv4(Internet Protocol version 4)의 주소 공간은 약 43억 개(2^32)로 한정되어 공인 주소가 고갈되었고, 여러 내부 호스트가 공인 주소를 나눠 쓸 방법과 내부 호스트를 외부에 직접 노출하지 않으려는 요구가 함께 커짐.
- 주요 목적 : 한정된 공인 주소의 절약과 재사용, 내부 망 구조의 은폐, ISP(Internet Service Provider) 교체 시 내부 주소 재설계 회피.

## Ⅱ. NAT의 특징 및 장점

- 핵심 요약 : 헤더 재작성과 변환 테이블을 결합해 공인 주소를 나누고 내부 구조를 감추는 방식.

1. 헤더 재작성 : 출발지 IP와 TCP(Transmission Control Protocol)·UDP(User Datagram Protocol) 포트를 공인 값으로 바꾸고 체크섬을 다시 계산 → 내부 호스트가 인터넷과 세션을 맺을 수 있음.
2. **변환 테이블** (Translation Table) : 내부 주소·포트와 외부 공인 주소·포트의 대응을 세션 동안 기억 → 응답 패킷을 원래 내부 호스트로 되돌림.
3. **NAPT** (Network Address Port Translation, 흔히 PAT(Port Address Translation)로도 부름) : 하나의 공인 IP에 포트 번호를 더해 다수 호스트를 수용 → 공인 주소 소모 억제.
4. 내부 구조 은폐 : 외부에서 사설 주소를 볼 수 없어 내부 토폴로지 정찰이 어려워짐 → 보안 경계를 한 겹 더하는 효과. 다만 은폐는 방화벽 정책을 대신하지 않으므로 접근 통제와 함께 적용.
5. 망 변경 유연성 : ISP를 바꿔도 공인 주소 측만 바뀌고 내부 주소 체계는 유지 → 재구성 비용 절감.
6. 세션 정리 : TCP는 FIN 또는 RST 수신 시, UDP는 유휴 타이머 만료 시 테이블 항목을 삭제 → 포트 자원 회수.

## Ⅲ. NAT의 구조 (흐름)

- 핵심 요약 : 송신 때 출발지를 치환하고, 응답 때 변환 테이블을 역조회해 목적지를 복원하는 두 단계 흐름.

```text
[ NAPT 송수신 흐름 ]

내부 호스트 192.168.1.10:5000
   ↓ 1. 송신 (사설 출발지)
NAT 장비 (공인 203.0.113.1)
   ↓ 2. 출발지 → 203.0.113.1:10001
인터넷 서버
   ↓ 3. 응답 (목적지 10001)
NAT 장비 (테이블 역조회)
   ↓ 4. 목적지 → 192.168.1.10:5000
내부 호스트
```

- NAT 통과(NAT Traversal)는 외부에서 내부로 먼저 연결할 수 없는 문제를 우회하는 기법이며, 그 절차는 **ICE** (Interactive Connectivity Establishment, RFC 8445)가 맡는다.
- **STUN** (Session Traversal Utilities for NAT, RFC 5389) : 외부 STUN 서버에 질의해 자신의 공인 반사 주소와 NAT 유형을 확인하는 단계.
- **TURN** (Traversal Using Relays around NAT, RFC 5766) : 직접 연결이 불가능할 때 외부 릴레이 서버를 경유해 미디어를 중계하는 단계.

```text
[ ICE 연결 수립 절차 ]

후보 수집 (로컬 주소, STUN 반사 주소)
   ↓
TURN 릴레이 후보 추가
   ↓
우선순위 순으로 연결 점검
   ↓ 직접 경로 실패 시 릴레이 전환
연결 확정 (미디어 전송)
```

## Ⅳ. NAT의 비교

- 핵심 요약 : 공인 주소를 아낄수록 외부 접근이 어려워지므로, 용도에 맞게 유형을 고르고 통과 기술로 P2P 제약을 보완하는 구도.

1. **정적 NAT** (Static NAT) : 내부 주소 1개와 공인 주소 1개의 고정 1:1 매핑 → 외부에서 내부 서버 접근 가능.
2. **동적 NAT** (Dynamic NAT) : 공인 주소 풀에서 세션 단위로 할당 → 공인 주소 수만큼만 동시 접속.
3. **CGNAT** (Carrier-Grade NAT) : 통신사 계층에서 수행하는 대규모 NAT(RFC(Request for Comments) 6598 공유 주소 사용) → 가입자 주소 절감, 대신 P2P 통신 제약 심화.

| 비교 축 | 정적 NAT | 동적 NAT | NAPT | CGNAT |
| --- | --- | --- | --- | --- |
| 변환 방식 | 1:1 고정 매핑 | 공인 주소 풀에서 할당 | 공인 IP 1개의 포트 다중화 | 통신사 계층의 다단 NAT |
| 동시 수용 | 내부 호스트 수만큼 공인 주소 필요 | 공인 주소 수가 상한 | 포트 자원 범위 내 다수 | 가입자 단위 대규모 수용 |
| 외부 접근 | 가능 | 제한적 | 인바운드 기본 차단 | 사실상 불가 |
| 주요 적용 | DMZ 공개 서버 | 소규모 지사 회선 | 가정용 공유기, 기업 LAN | 모바일 LTE·5G 가입자망 |

| 기술 | 역할 | 한계 |
| --- | --- | --- |
| STUN (Session Traversal Utilities for NAT) | 공인 반사 주소와 NAT 유형 확인 | 중계 기능이 없어 Symmetric NAT에서는 직접 연결 실패 |
| TURN (Traversal Using Relays around NAT) | 릴레이 서버로 미디어 중계 | 서버 비용과 지연 발생 |
| ICE (Interactive Connectivity Establishment) | 가용 후보 경로를 모아 최적 경로 선택 | 후보 수집과 연결 점검에 시간 소요 |

## Ⅴ. NAT의 한계와 방안

- 핵심 요약 : 종단 간 연결 원칙의 훼손, 페이로드 내 주소 불일치, 공유 주소로 인한 추적 곤란을 나눠 통제해야 함.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 인바운드 P2P 접속 차단 | 외부 주도 연결을 열 수 없어 화상회의·VoIP·P2P 실패 | STUN·TURN·ICE 구성, 필요한 서비스에만 포트 포워딩을 명시 설정(UPnP 자동 개방은 제한) | P2P 연결 성공률, 릴레이 사용 비율 |
| 페이로드 내 IP 불일치 | FTP(File Transfer Protocol)·SIP(Session Initiation Protocol) 본문에 사설 주소가 적혀 변환 후 연결 실패 | **ALG** (Application Layer Gateway) 기능을 필요한 프로토콜에만 활성화 | 세션 실패율 |
| 공유 주소에 따른 추적 곤란 | 다수 호스트가 공인 주소를 공유해 공격 출처 특정이 어려움 | 시각·공인 포트·내부 주소를 묶은 세션 로그 보관 | 로그 보관 적합성, 추적 소요 시간 |

## Ⅵ. NAT에 대한 기술사적 제언

- 핵심 요약 : NAT를 IPv4 고갈을 늦추는 과도기 수단으로 보고, IPv6 전환과 로그·접근 통제를 함께 설계하는 방향.

1. IPv6(Internet Protocol version 6) 전환 일정을 망 운영 계획에 포함하고, 듀얼 스택(Dual Stack) 구성을 단계적으로 넓혀 NAT 의존도를 낮추는 것이 필요.
2. 클라우드 환경에서는 관리형 NAT 게이트웨이의 처리량 비용이 커지므로, S3(Simple Storage Service) 같은 대용량 서비스 트래픽은 게이트웨이형 VPC(Virtual Private Cloud) 엔드포인트로 우회시키는 설계가 필요.
3. NAT 뒤의 내부 호스트도 암묵적으로 신뢰하지 않는 제로 트러스트(Zero Trust) 원칙에 따라, 출구 필터링(Egress Filtering)과 DNS 보안 필터링을 함께 적용하여 명령제어(C2, Command and Control) 통신을 차단하는 것이 필요.

## Ⅶ. 결론

- 핵심 요약 : NAT는 공인 주소를 아끼고 내부 구조를 감추는 과도기적 주소 변환 기술.
- 시사점 : 종단 간 연결성과 추적 가능성은 IPv6 전환과 세션 로그 관리로 보완해야 하며, 보안은 NAT 자체가 아니라 접근 통제에서 확보.
