- **QoS(Quality of Service)** : 네트워크가 트래픽별 품질 요구를 다루기 위한 측정·자원 관리 정책과 기능
- **대역폭(Bandwidth)** : 링크가 전달할 수 있는 비트율 용량; 응용 처리율과 구별
- **지연(Delay/Latency)** : 패킷이 출발지에서 목적지까지 전달되는 시간
- **지터(Jitter)** : 패킷 지연의 변동
- **패킷 손실률(Packet Loss Rate)** : 보낸 패킷 중 목적지에 도달하지 못한 비율
- **폴리싱(Policing)** : 트래픽 프로파일 초과분을 표시·폐기하는 속도 제어 기능
- **셰이핑(Shaping)** : 트래픽을 버퍼에 보관해 설정된 프로파일에 맞춰 송출하는 기능
- **스케줄링(Scheduling)** : 혼잡 큐에서 패킷 전송 순서·자원을 배분하는 기능
- **WRED(Weighted Random Early Detection)** : 큐 혼잡이 심해지기 전에 설정된 조건·확률로 패킷을 조기 폐기하는 혼잡 회피 기법

## 2~4교시 25점 답안

## Ⅰ. QoS(Quality of Service)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 통신망에서 전송되는 다양한 유형의 데이터 트래픽에 대해 사전에 합의된 수준의 서비스 품질을 차등적·보장적으로 제공하기 위한 네트워크 제어 및 자원 관리 기술 체계 |
| 목적 | 망 혼잡 시 실시간 음성/영상 트래픽의 끊김 및 왜곡 방지, 미션 크리티컬 업무 데이터의 대역폭 보장 및 네트워크 전체 전송 자원의 공평한 활용 |

## Ⅱ. QoS(Quality of Service)의 특징

| 특징 | 상세 내용 |
|---|---|
| 4대 품질 지표 제어 | 전송 대역폭(Bandwidth), 종단 지연(Delay), 지연 변이(Jitter), 패킷 손실률(Loss)을 복합 관리 |
| 다단계 제어 파이프라인| 트래픽 유입부터 전송까지 '분류/마킹 ──► 규제/정형 ──► 혼잡 방지/폐기 ──► 큐잉/스케줄링' 절차 적용 |
| 상대적/절대적 보장 | 완전한 자원 예약을 제공하는 Hard QoS(IntServ)와 우선순위 차등을 제공하는 Soft QoS(DiffServ)로 구분 |
| SLA(서비스 수준 협약)| 서비스 제공자와 이용자 간에 서비스 품질 지표를 정량적으로 계약하고 미달 시 페널티 부과 |

## Ⅲ. QoS(Quality of Service)의 체계·프로세스

**QoS 트래픽 제어 4단계 파이프라인 및 핵심 기술 메커니즘**

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        [ QoS 트래픽 제어 4단계 파이프라인 ]            │
│                                                                        │
│ Ingress Packet                                                         │
│     │                                                                  │
│     ▼ [ 1단계: 분류 및 마킹 (Classification & Marking) ]              │
│     - ACL, 5-Tuple, NBAR 기반 패킷 식별                                │
│     - L2 CoS(802.1p) 또는 L3 ToS/DSCP 비트 마킹 태깅                  │
│     │                                                                  │
│     ▼ [ 2단계: 트래픽 컨디셔닝 (Policing & Shaping) ]                  │
│     - Policing: 토큰 버킷 초과 시 즉각 폐기 (Drop)                    │
│     - Shaping : 버퍼를 활용하여 지연 송출 (Smoothing)                  │
│     │                                                                  │
│     ▼ [ 3단계: 혼잡 회피 (Congestion Avoidance) ]                      │
│     - 큐 오버플로 전 능동적 조기 폐기: RED, WRED, CoDel                │
│     │                                                                  │
│     ▼ [ 4단계: 큐잉 및 스케줄링 (Queuing & Scheduling) ]              │
│     - 다중 큐 분할 적재 후 알고리즘별 인출 송출                       │
│     - FIFO, PQ, CQ, FQ, WFQ, CBWFQ, LLQ (Strict PQ + CBWFQ)           │
│     │                                                                  │
│     ▼                                                                  │
│ Egress Link (포워딩 전송)                                              │
└────────────────────────────────────────────────────────────────────────┘
```

| 4대 품질 지표 | 단위 및 정의 | 민감한 서비스 유형 | 핵심 개선 메커니즘 |
|---|---|---|---|
| **대역폭 (Bandwidth)** | bps (초당 전송 비트 수) | 대용량 파일 전송, 4K/8K 스트리밍 | CBWFQ 대역폭 예약, 트래픽 셰이핑 |
| **지연 (Delay)** | ms (출발지에서 목적지까지 시간)| 음성 통화, 실시간 원격 제어 | Strict Priority(PQ), LLQ 큐잉 최우선 처리 |
| **지터 (Jitter)** | ms (지연 시간의 불규칙한 편차)| 실시간 VoIP, 화상 회의 | 수신단 지터 버퍼(Jitter Buffer), 고정 지연 스케줄링 |
| **손실률 (Packet Loss)**| % (전송 대비 유실된 패킷 비율) | 금융 트랜잭션, 의료 데이터 | WRED 사전 혼잡 회피, TCP 재전송 최적화 |

## Ⅳ. QoS(Quality of Service)의 종류·비교

| 비교 항목 | 트래픽 폴리싱 (Traffic Policing) | 트래픽 셰이핑 (Traffic Shaping) |
|---|---|---|
| **초과 패킷 처리** | 임계 대역폭 초과 즉시 **폐기(Drop) 또는 리마킹** | **메모리 버퍼에 임시 보관 후 완만하게 전송** |
| **버퍼 사용 여부** | 버퍼 미사용 (메모리 부담 없음) | **대용량 큐 버퍼 필수 사용** |
| **지연 시간 영향** | 지연 추가 없음 (살아남은 패킷 즉시 전송)| **버퍼링 대기로 인한 추가 전송 지연 발생** |
| **출력 트래픽 파형**| 울퉁불퉁한 버스트성 트래픽 유지 | **균일하고 완만한(Smoothed) 파형으로 변환** |
| **주요 적용 위치** | 인바운드 인그레스(Ingress) 인터페이스 | 아웃바운드 이그레스(Egress) 인터페이스 |

## Ⅴ. QoS(Quality of Service)의 한계와 방안

| 한계 | 방안 |
|---|---|
| 버퍼를 무제한 확장하면 패킷 손실은 줄어드나 큐 대기 시간만 폭증하여 대화형 트래픽 품질이 괴멸되는 버퍼블로트(Bufferbloat) 발생 | FQ-CoDel(Fair Queuing Controlled Delay) 및 PIE 등 현대 능동 큐 관리(AQM) 알고리즘을 라우터 인터페이스에 기본 활성화 |
| 암호화 트래픽(TLS 1.3, QUIC)의 급증으로 L4 포트 및 L7 페이로드 검사가 불가능해져 정확한 플로우 분류(Classification) 불가 | 패킷 크기 시퀀스, 도착 간격(IAT), 방향성 등 트래픽 행동 메타데이터 기반 머신러닝/eBPF 인라인 트래픽 분류 체계 도입 |

## Ⅵ. 도입/구축/운영 관점 제언

### 1. 실무 적용 가이드 및 핵심 고려사항
엔터프라이즈 멀티서비스 망 구축 시, 음성 VoIP 트래픽은 총 링크 대역폭의 33%를 초과하지 않도록 엄격한 우선순위 큐(LLQ)에 제한 할당하여 비정상 음성 패킷 폭증 시 타 업무 데이터가 완전 굶주리는 기아(Starvation) 현상을 원천 방지.

### 2. 아키텍처 및 상세 메커니즘
```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 능동 큐 관리(AQM) WRED의 평균 큐 길이 기반 선제적 폐기 메커니즘 ]  │
│                                                                        │
│ 패킷 폐기 확률 (Drop Probability)                                     │
│   ▲                                                                    │
│ 1 ┼─────────────────────────────────────────────────── [ Max Drop ]    │
│   │                                                  / (Tail Drop)     │
│   │                                                 /                  │
│ P ┼────────────────────────────────────────────────/                   │
│   │                                               /                    │
│   │                                              / (WRED 선제 폐기)    │
│   │                                             /                      │
│ 0 ┼───────────────────────┬────────────────────┴───────────────────────│
│   0                    Min 임계치           Max 임계치   평균 큐 길이  │
│   (무손실 정상 전송)   (패킷 확률적 드롭 시작) (이후 전량 테일드롭)     │
└────────────────────────────────────────────────────────────────────────┘
```

### 3. 기술 유형 및 비교 평가
| 큐잉 방식 | 동작 방식 | 장점 | 단점 |
|---|---|---|---|
| **FIFO** | 선착순 단순 서비스 | 오버헤드 최저 | 특정 버스트 트래픽의 링크 독점 |
| **PQ (Priority)** | 절대 우선순위 큐 우선 비우기 | 최우선순위 지연 제로화 | 저우선순위 기아 현상 발생 |
| **CBWFQ** | 클래스별 대역폭 최소 보장 | 플로우 간 자원 공평 격리 | 가상시간 계산 연산 부하 |
| **LLQ (PQ+CBWFQ)**| PQ와 CBWFQ의 결합 | 음성 지연 단축 + 타 업무 보장 | 음성 트래픽 Policing 미적용 시 위험 |
