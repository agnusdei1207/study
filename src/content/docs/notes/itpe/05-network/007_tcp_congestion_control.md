## 지식 로드맵 내 현재 위치

지식 위치: 네트워크 → 전송 계층 → **TCP 혼잡제어**

## 30초 인출

- 본질: **TCP 혼잡제어** : 송신자가 경로의 혼잡 신호에 맞춰 미확인 데이터 양을 조절하는 피드백 제어
- 메커니즘: **cwnd** 증가로 경로 용량 탐색 → 손실·혼잡 표시 시 감소·복구 → 이후 다시 탐색

<details>
<summary>핵심 용어</summary>

- **TCP(Transmission Control Protocol)** : 순서·확인 응답·재전송을 제공하는 연결형 전송 프로토콜
- **혼잡 윈도(cwnd, Congestion Window)** : 송신자가 경로 혼잡을 고려해 허용하는 미확인 데이터의 상한
- **수신 윈도(rwnd, Receive Window)** : 수신자가 버퍼 용량을 근거로 광고하는 수용 한도
- **느린 시작(Slow Start)** : 초기 경로 용량을 탐색하며 혼잡 윈도를 빠르게 늘리는 단계
- **혼잡 회피(Congestion Avoidance)** : 경로를 더 조심스럽게 탐색하는 단계
- **빠른 재전송(Fast Retransmit)** : 중복 ACK 등으로 손실을 추정해 타이머 전에 재전송하는 기법
- **빠른 회복(Fast Recovery)** : 빠른 재전송 뒤 혼잡 윈도를 조정하며 데이터 전송을 재개하는 기법
- **ECN(Explicit Congestion Notification)** : 패킷 손실 전에 네트워크 혼잡을 표시할 수 있는 기법
- **CUBIC** : 혼잡 윈도 증가에 3차 함수를 사용하는 TCP 혼잡제어 알고리즘

</details>

## 2~4교시 25점 답안

## Ⅰ. TCP 혼잡제어의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **TCP 혼잡제어** : 경로 혼잡 신호에 따라 송신 측 혼잡 윈도를 조절하는 피드백 제어 |
| 목적 | 경로의 과도한 혼잡을 줄이면서 가용 용량 활용 |

## Ⅱ. 송신 한도와 보호 대상

```text
미확인 데이터의 송신 한도
  ├─ cwnd: 경로 혼잡 상태
  └─ rwnd: 수신 버퍼 여유

적용 한도 ── min(cwnd, rwnd)
```

기본적으로 송신 측은 `min(cwnd, rwnd)`를 넘는 미확인 데이터를 보내지 않음. cwnd는 네트워크 경로, rwnd는 수신 버퍼를 보호하는 서로 다른 제어.

## Ⅲ. 탐색·회피·복구

| 단계 | 기본 원리 | 전환 단서 |
|---|---|---|
| 느린 시작 | 초기 혼잡 윈도를 빠르게 확대 | `ssthresh` 도달·혼잡 감지 |
| 혼잡 회피 | 완만하게 경로 용량 탐색 | 손실·ECN 등 혼잡 신호 |
| 빠른 재전송 | 손실 추정 시 타이머 전에 재전송 | 중복 ACK 등 |
| 빠른 회복 | 감소한 혼잡 윈도로 전송 재개 | 손실 복구 진행 |

이 표는 RFC 5681의 기본 알고리즘을 학습용으로 압축한 것. 증가·감소 수식과 상태 전이는 사용하는 알고리즘에 따라 다름.

## Ⅳ. 기본 피드백 과정

```text
송신·ACK 수신
    ↓
cwnd 조정·경로 탐색
    ├→ 혼잡 없음: 탐색 지속
    └→ 손실·ECN: 전송량 감소·복구
```

혼잡 신호를 바탕으로 송신률을 조정하므로 경로의 상태가 바뀌면 다시 적응. 손실이 모두 혼잡 때문인 것은 아니므로 무선 오류 등에서는 원인 구분이 필요.

## Ⅴ. 기본 알고리즘과 CUBIC

| 관점 | RFC 5681의 기본 혼잡 회피 | CUBIC |
|---|---|---|
| 창 증가 | 기본적으로 선형적 증가 | 3차 함수 기반 증가 |
| 적용 이유 | 안정적인 경로 용량 탐색 | 긴 지연·큰 대역폭 경로에서 확장성 개선 |
| 공통점 | 혼잡 신호 시 창 감소·복구 | 혼잡 신호 시 창 감소·복구 |

CUBIC은 혼잡제어 알고리즘의 한 예. TCP 자체를 CUBIC 하나로 정의하지 않음.

## Ⅵ. 한계와 대응

| 한계 | 대응 |
|---|---|
| 경로 큐 증가로 지연·손실 확대 | RTT·손실·큐 지연과 처리량 함께 관찰 |
| 무선 손실을 혼잡으로만 해석 | 링크 오류·경로 혼잡 신호 구분 |
| 송신 측 cwnd만 조정하고 수신 측 병목 간과 | rwnd·애플리케이션 수신 속도 확인 |
| 한 알고리즘의 효과를 모든 경로에 일반화 | 실제 RTT·손실·공유 흐름 조건에서 검증 |

## Ⅶ. 기술사적 제언

| 우선 제언 | 실행·확인 |
|---|---|
| 흐름제어와 혼잡제어를 함께 진단 | `rwnd`·`cwnd`·RTT·재전송을 같은 구간에서 측정 |
| 알고리즘보다 경로 반응을 평가 | 부하 변화와 손실 시 송신량·지연의 회복 과정 확인 |
