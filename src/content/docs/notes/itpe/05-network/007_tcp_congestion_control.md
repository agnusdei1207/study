## 연관 키워드

- TCP 혼잡제어, CWND, 슬로우 스타트, 혼잡 회피, 빠른 재전송, 빠른 복구
- AIMD, 버퍼블로트, 혼잡 붕괴, 공평성, BDP, RTT
- BBR, CUBIC, DCTCP, ECN, AQM

## Ⅰ. TCP 혼잡제어의 개요

- 핵심 요약 : 라우터 버퍼 과부하를 막기 위해 송신 측이 전송 윈도우를 동적으로 조절하는 종단 간 제어 기법.
- 개념 : 송신 측이 네트워크 혼잡을 감지해 **혼잡 윈도우**(CWND, Congestion Window) 크기를 조절하는 전송 계층(L4) 트래픽 제어 기법 (**TCP 혼잡제어**, TCP Congestion Control).
- 배경 및 필요성 : 1986년 인터넷에서 손실된 패킷을 맹목적으로 재전송하다 망 전체 처리량이 급락하는 **혼잡 붕괴**(Congestion Collapse)가 보고되었고, 이후 자원을 공정하게 나누고 안정적으로 수렴시키는 제어가 필수가 됨.
- 주요 목적 : 가용 대역폭의 최대 활용, 연결 간 **공평성**(Fairness) 보장, 큐 적체로 생기는 **버퍼블로트**(Bufferbloat) 방지.

## Ⅱ. TCP 혼잡제어의 특징 및 장점

- 핵심 요약 : 손실과 지연 신호에 따라 윈도우를 조절하는 원리가 망의 안정성과 연결 간 공평성으로 이어지는 구조.

1. **가산 증가·승법 감소**(AIMD, Additive Increase Multiplicative Decrease) : 정상 상태에서 왕복 시간(RTT, Round-Trip Time)마다 1 MSS(Maximum Segment Size)씩 완만히 늘리고, 손실 시 윈도우를 절반으로 줄임 → 여러 연결이 대역을 나눠 쓰며 공평하게 수렴.
2. **슬로우 스타트**(Slow Start) : 연결 초기나 타임아웃 시 CWND를 1 MSS에서 시작해 RTT마다 두 배로 키움 → 비어 있는 대역을 짧은 시간에 탐색.
3. **빠른 재전송**(Fast Retransmit)과 **빠른 복구**(Fast Recovery) : 확인 응답(ACK, Acknowledgment)이 중복 3회(3 Dup ACKs) 도착하면 손실로 보고 즉시 재전송하며, CWND를 절반으로 낮춰 전송을 이어감 → 타임아웃 대기로 인한 처리량 급락 방지.
4. **혼잡 회피**(Congestion Avoidance) : CWND가 혼잡 임계치에 닿으면 선형 증가로 전환 → 과부하 직전에서 속도를 완만하게 조절.

## Ⅲ. TCP 혼잡제어의 구조 (흐름)

- 핵심 요약 : 슬로우 스타트, 혼잡 회피, 손실 복구가 CWND 변화를 이끄는 상태 전이와, 큐 상태가 ACK를 통해 송신 측에 되돌아오는 피드백 루프의 이중 구조.

```text
[ 전통 TCP 혼잡제어 상태 전이 ]

연결 시작 또는 타임아웃
   ↓
슬로우 스타트 (CWND 지수 증가)
   ↓  CWND가 임계치 도달
혼잡 회피 (CWND 선형 증가)
   ↓  중복 ACK 3회 감지
빠른 재전송 → 빠른 복구
   ↓  CWND 절반, 임계치 갱신
혼잡 회피로 복귀
```

```text
[ 혼잡 피드백 루프 ]

송신 측 전송 (CWND 만큼)
   ↓
라우터 큐 적체 또는 패킷 손실
   ↓
ACK 지연·중복 ACK 수신
   ↓
송신 측이 CWND 재조정
```

- 피드백 : 네트워크 상태가 ACK 타이밍과 손실 신호로만 송신 측에 전달되므로, 송신 측은 간접 신호만으로 윈도우를 판단해야 함.

## Ⅳ. TCP 혼잡제어 알고리즘의 비교

- 핵심 요약 : 혼잡 신호가 패킷 손실에서 대역폭·지연 측정과 스위치 큐 표시로 옮겨 가며 알고리즘이 다변화.
- 비교 대상 : 손실 기반 **TCP Reno**와 CUBIC, 대역폭·지연 기반 **BBR**(Bottleneck Bandwidth and Round-trip propagation time), 큐 표시 기반 **DCTCP**.

| 비교 축 | TCP Reno | TCP CUBIC | BBR | DCTCP |
| --- | --- | --- | --- | --- |
| 혼잡 신호 | 패킷 손실 | 패킷 손실 | 대역폭과 최소 RTT 측정 | 스위치 큐 표시 |
| 윈도우 증가 | 선형 증가 (AIMD) | 시간 기준 3차 함수 곡선 | 전송률 모델 기반 | 표시 비율에 비례한 감소 |
| 고속·장거리망 적응 | 회복이 느려 취약 | 빠른 대역폭 회복 | 손실과 무관하게 대역폭 추정 | 데이터센터 내부에 특화 |
| 버퍼블로트 내성 | 취약 | 취약 | 큐 적체를 줄이는 편 | 우수 |
| 주요 사용 환경 | 레거시·교육용 기준 | 리눅스 기본 알고리즘 | 대형 웹·영상 서비스 | 사설 데이터센터 내부망 |

- 용어 : **명시적 혼잡 통지**(ECN, Explicit Congestion Notification)는 스위치가 큐 임계치를 넘을 때 패킷에 표시를 남겨 손실 전에 송신 측에 알리는 방식.
- 선택 기준 : 망의 **대역폭 지연 곱**(BDP, Bandwidth-Delay Product) 환경에서는 Reno보다 CUBIC·BBR이 유리하고, 데이터센터 내부에서는 DCTCP가 적합함.

## Ⅴ. TCP 혼잡제어의 한계와 방안

- 핵심 요약 : 큐 적체, 무선 구간의 오판, 고속 장거리망의 느린 회복을 큐 관리와 알고리즘 전환, 측정 기반 모델로 통제.
- 대응 기법 : **능동 큐 관리**(AQM, Active Queue Management)를 라우터에 두면 큐 지연을 송신 측 알고리즘과 별개로 줄일 수 있음.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 손실 기반 알고리즘의 버퍼블로트 | 대용량 버퍼가 찰 때까지 윈도우를 키워 손실은 없고 지연만 증가 → 실시간 서비스 품질 저하 | CoDel, FQ-CoDel, PIE 같은 AQM 도입, 송신 측 BBR 전환 | 큐 지연과 RTT 변동폭 |
| 무선 구간의 랜덤 손실 오인 | 무선 페이딩 손실을 혼잡으로 판단해 윈도우가 급감 → 처리량 저하 | 손실 대신 대역폭·지연 모델을 추정하는 BBR 적용, 링크 계층 재전송과 연계 | 재전송률, 처리량 추이 |
| 고속 장거리망의 느린 회복 | 손실 후 AIMD의 선형 증가가 원래 속도를 회복하는 데 긴 시간 소요 → 대역 활용률 저하 | CUBIC의 시간 기반 3차 함수 증가, 패킷 페이싱(Packet Pacing) 적용 | 대역 활용률, 손실 후 회복 시간 |

## Ⅵ. TCP 혼잡제어에 대한 기술사적 제언

- 핵심 요약 : 알고리즘 표준화, 계측 기반 교체 판단, 프로토콜 유연성 확보의 세 방향으로 혼잡제어를 운영 역량으로 관리.
- 운영 조직은 서비스 유형별로 허용 혼잡제어 알고리즘을 표준화하고, 지연과 재전송 지표를 근거로 교체 여부를 판단하는 거버넌스를 갖추는 것이 바람직하다.
- 데이터센터 내부망에서는 네트워크 팀과 AI 인프라 팀이 스위치의 ECN 임계치와 송신 측 혼잡제어 파라미터를 공동으로 관리하는 체계를 두어야 한다.
- 장기적으로는 사용자 공간에서 알고리즘을 교체할 수 있는 QUIC 계열 전송 방식의 확산을 주시하고, 신규 서비스 설계 시 전송 프로토콜 선택 기준에 혼잡제어의 유연성을 포함하는 것이 바람직하다.

## Ⅶ. 결론

- 핵심 요약 : TCP 혼잡제어는 네트워크 상태 신호를 읽어 윈도우를 조절하는 분산형 대역 배분 메커니즘임.
- 시사점 : 손실 신호만으로는 지연과 대역폭 특성이 다른 현대 망을 설명하기 어려워, 측정 기반 모델과 큐 관리를 함께 쓰는 방향으로 진화하고 있음.
