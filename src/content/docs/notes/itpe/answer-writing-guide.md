## 목적

정보관리기술사 필기 답안을 **일관된 뼈대**로 작성하기 위한 표준 규칙이다.
모든 답안은 아래 7개 프레임을 로마숫자(Ⅰ~Ⅶ)로 표기하고, **각 프레임마다 핵심 요약을 한 줄**로 먼저 제시한 뒤 본문을 전개한다.

## 표준 뼈대 구조 (7프레임)

| 프레임 | 로마숫자 | 제목        | 역할                         |
| ------ | -------- | ----------- | ---------------------------- |
| 1      | Ⅰ        | 개요        | 개념·배경·필요성·목적 정의   |
| 2      | Ⅱ        | 특징 및 장점 | 핵심 속성과 그로 인한 효익   |
| 3      | Ⅲ        | 구조 (흐름) | 구성요소·프로세스·단계 흐름  |
| 4      | Ⅳ        | 비교        | 유사 개념·대안과의 비교 분석 |
| 5      | Ⅴ        | 한계와 방안 | 제약·리스크와 대응 방안      |
| 6      | Ⅵ        | 제언        | 기술사적 개선·적용 방안      |
| 7      | Ⅶ        | 결론        | 핵심 정리 및 시사점          |

답안 최상단에는 **연관 키워드** 섹션을 먼저 배치하여 핵심 키워드를 명시한다.

## 각 프레임 작성 규칙

### Ⅰ. 개요

- 개념 : 대상의 정의를 한 문장으로 제시.
- 배경 및 필요성 : 등장 배경과 문제 상황.
- 주요 목적 : 해결하려는 목표.
- 핵심 요약 : 위 세 요소를 한 줄로 압축한 문장.

### Ⅱ. 특징 및 장점

- 핵심 속성·원리·차별점과 그로 인한 장점을 하나의 논리로 연결하여 제시.
- 각 항목은 `특징 : 작동 원리 → 기대효과` 형태로 작성하여 장점의 근거가 드러나게 구성.
- 핵심 요약 : 특징과 장점을 한 문장으로 요약.

### Ⅲ. 구조 (흐름)

- 구성요소, 프로세스, 단계별 흐름을 도식·표로 제시.
- 핵심 요약 : 구조/흐름의 핵심을 한 문장으로 요약.

### Ⅳ. 비교

- 비교 대상, 비교 축, 선택 기준을 표로 정리.
- 핵심 요약 : 비교 결과의 핵심을 한 문장으로 요약.

### Ⅴ. 한계와 방안

- 한계의 원인과 영향을 제시하고 실행 가능한 대응 방안을 일대일로 병기.
- 가능하면 `한계 | 원인·영향 | 대응 방안 | 관리 지표` 표로 정리.
- 핵심 요약 : 주요 한계와 대응 원칙을 한 문장으로 요약.

### Ⅵ. 제언

- 기술사적 관점의 개선·적용·정책 제안.
- 핵심 요약 : 제언의 핵심을 한 문장으로 요약.

### Ⅶ. 결론

- 핵심 정리와 시사점.
- 핵심 요약 : 결론의 핵심을 한 문장으로 요약.

## 공통 작성 규칙

1. **로마숫자 표기** : 모든 프레임 제목은 `## Ⅰ. <주제>의 개요` 형식의 로마숫자(Ⅰ~Ⅶ)로 표기한다.
2. **핵심 요약** : 각 프레임의 첫 불릿(또는 첫 줄)은 반드시 `- 핵심 요약 : ...` 한 줄로 작성한다.
3. **명사형 종결** : 설명 문장은 명사형(예: ~체계, ~필요, ~효과)으로 끝내고, "~다", "~함/~됨" 남발을 피한다.
4. **불릿 라벨 비볼드** : 불릿 라벨(개념, 배경, 특징, 목적 등)은 굵게 표시하지 않는다.
5. **채점 키워드 강조** : 점수와 연결되는 핵심 용어는 연관 키워드뿐 아니라 본문에서도 굵게(`**`) 표시하여 프라이머리 색상으로 강조한다. 한 문장에 1~3개를 선별하고, 불릿 라벨이나 문장 전체는 강조하지 않는다.
6. **굵게 표기 규칙** : 굵게(`**`)는 여는/닫는 `**`가 정확히 쌍을 이루어야 하며, 강조 안쪽에 공백이나 문장부호를 두지 않는다.
7. **비교는 표로** : 비교 항목은 반드시 표(Table)로 정리한다.
8. **흐름은 도식으로** : 구조·흐름은 텍스트 도식(````text`) 또는 표로 제시한다.
9. **블록 경계** : 인용(`>`), HTML 블록(`</div>` 등), 표(`|`), 목록(`-`) 사이에는 반드시 빈 줄을 둔다.
10. **근거 없는 정량 수치 금지** : 출처가 없는 수치는 정성 효과 또는 측정 KPI로 표현한다.
11. **도식·도해 최소 2개** : 모든 답안에는 흐름도·구조도·비교도 등 도식과 도해를 **최소 2개 이상** 포함한다. ASCII 텍스트 도식(````text`)으로 표현하며, 노드는 7~12개, 라벨은 짧게, 단방향 흐름을 원칙으로 한다.
12. **장문 나열은 콤마 대신 번호 들여쓰기** : 3개 이상의 항목을 나열할 때는 콤마로 이어 쓰지 않고 번호(1., 2., ...)와 들여쓰기로 분리한다. 문장 내 자연스러운 나열은 콤마 허용.
13. **핵심 키워드 포함** : 기술사 시험은 핵심 키워드 등장 시 가점이 부여된다. 답안 상단에 "연관 키워드"로 핵심 키워드를 먼저 나열하고, 본문 각 프레임에서 해당 키워드를 명시적으로 사용한다. 누락된 키워드는 감점 요인이다.
14. **약어는 풀네임 병기** : 약어(Acronym/Abbreviation)는 최초 등장 시 반드시 풀네임을 괄호로 병기한다 (예: IT(Information Technology), SLA(Service Level Agreement)). 이후에는 약어만 사용 가능.
15. **용어 창작 금지** : 존재하지 않는 약어·키워드·용어를 지어내지 않는다. 검증된 표준 용어와 공식 명칭만 사용한다.
16. **외래어·전문 용어 허용, 조어·비표준어 금지** : 외래어나 전문 용어(예: psychological safety, MVP, A/B 테스트)는 공식 명칭·표준 번역으로 사용할 수 있다. 그러나 "안전감"처럼 존재하지 않는 조어·비표준어는 사용하지 않는다. 표준국어대사전에 등재되지 않은 단어를 새로운 복합어로 만들어 쓰면 독자에게 큰 혼란을 준다. 표준어가 없으면 원어를 괄호로 병기하거나(예: 심리적 안전성 (psychological safety)) 표준어로 대체한다.

## 체크리스트

- [ ] 7개 프레임(Ⅰ~Ⅶ)이 모두 존재하는가?
- [ ] 각 프레임이 로마숫자로 표기되었는가?
- [ ] 각 프레임에 핵심 요약이 있는가?
- [ ] 채점 핵심 키워드가 본문에서도 선별적으로 굵게 강조되었는가?
- [ ] 특징과 그로 인한 장점이 하나의 논리로 연결되었는가?
- [ ] 비교 항목이 표로 정리되었는가?
- [ ] 흐름이 도식/표로 제시되었는가?
- [ ] 한계마다 대응 방안이 일대일로 제시되었는가?
- [ ] 제언(Ⅵ)이 포함되었는가?
- [ ] 결론(Ⅶ)이 포함되었는가?
- [ ] 도식·도해가 최소 2개 포함되었는가?
- [ ] 핵심 키워드가 포함되었는가? (연관 키워드 + 본문 명시)
- [ ] 외래어·전문 용어는 공식 명칭·표준 번역으로 사용하고, "안전감"처럼 존재하지 않는 조어·비표준어를 지어내지 않았는가?

## 예시 (그로스해킹)

### Ⅰ. 그로스해킹의 개요

- 개념 : 제품·데이터·실험을 결합해 성장을 만드는 방법론.
- 배경 및 필요성 : 스타트업의 자원 제약 하에서 빠른 성장 요구.
- 주요 목적 : 지속 가능한 성장 시스템 구축.
- 핵심 요약 : 제품 자체를 성장 엔진으로 만드는 데이터 기반 실험적 성장 방법론.

### Ⅱ. 그로스해킹의 특징 및 장점

1. 제품 중심(Product-Led) : 제품 자체가 유입·활성화를 유도하여 고객 획득비용 절감.
2. 데이터 기반(Data-Driven) : 행동 데이터로 의사결정하여 실패 비용 최소화.
3. 실험 문화(Experimentation) : 작은 가설을 빠르게 검증하여 학습 속도 향상.
4. 기능 융합(Cross-functional) : 부서 간 인계 지연을 줄여 실행 주기 단축.

- 핵심 요약 : 제품·데이터·실험의 특성이 비용 절감과 빠른 학습이라는 장점으로 연결되는 성장 운영체계.

### Ⅲ. 그로스해킹의 구조 (흐름)

- AARRR 퍼널과 Growth Loop의 이중 구조.
- 핵심 요약 : 획득→활성화→유지→매출→추천 흐름과 복리 성장 루프.

```text
[ AARRR 퍼널 흐름 ]
Acquisition(획득)
        ↓
Activation(활성화) ── "아하 모먼트"
        ↓
Retention(유지)
        ↓
Revenue(매출)
        ↓
Referral(추천) ──┐
        ↑        │
        └────────┘  (Growth Loop 복리 순환)
```

```text
[ Growth Loop 구조 ]
Input(입력) → Action(행동) → Output(출력) → 재입력
   │                                      │
   └────────────── 복리 성장 ─────────────┘
```

### Ⅳ. 그로스해킹과 전통 마케팅의 비교

- 초점, 조직, 의사결정, 채널, 성과 측정 비교.
- 핵심 요약 : 광고비 중심에서 제품·데이터·실험 중심으로의 전환.

### Ⅴ. 그로스해킹의 한계와 방안

- 한계 : 허상 지표 의존, 성장 부채(Growth Debt), 다크 패턴(Dark Pattern) 유혹.
- 대응 방안 : 북극성 지표·리텐션 중심 관리, 기술 부채 상환, 윤리적 UX 검토.
- 핵심 요약 : 단기 전환율보다 지속 가능한 고객 가치와 신뢰 중심의 통제 필요.

### Ⅵ. 그로스해킹에 대한 기술사적 제언

- 그로스팀 독립 운영, 데이터 인프라 투자, 윤리 가이드라인 제정.
- 핵심 요약 : 지속 가능한 성장을 위한 조직·기술·윤리 체계 구축.

### Ⅶ. 결론

- 측정 가능한 가설 검증을 통한 지속 가능한 성장 시스템.
- 핵심 요약 : 그로스해킹은 성장 운영체계(Growth OS)이다.
