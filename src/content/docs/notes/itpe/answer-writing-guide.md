## 목적

정보관리기술사 필기 답안을 **일관된 뼈대**로 작성하기 위한 표준 규칙이다.
모든 답안은 아래 7개 프레임을 로마숫자(Ⅰ~Ⅶ)로 표기하고, **각 프레임마다 핵심 요약을 한 줄**로 먼저 제시한 뒤 본문을 전개한다.

## 표준 뼈대 구조 (7프레임)

| 프레임 | 로마숫자 | 제목        | 역할                         |
| ------ | -------- | ----------- | ---------------------------- |
| 1      | Ⅰ        | 개요        | 개념·배경·필요성·목적 정의   |
| 2      | Ⅱ        | 특징        | 핵심 속성·원리·차별점        |
| 3      | Ⅲ        | 구조 (흐름) | 구성요소·프로세스·단계 흐름  |
| 4      | Ⅳ        | 비교        | 유사 개념·대안과의 비교 분석 |
| 5      | Ⅴ        | 장점과 한계 | 기대효과와 제약·리스크       |
| 6      | Ⅵ        | 제언        | 기술사적 개선·적용 방안      |
| 7      | Ⅶ        | 결론        | 핵심 정리 및 시사점          |

답안 최상단에는 **딸려 나오는 키워드** 섹션을 먼저 배치하여 핵심 키워드를 명시한다.

## 각 프레임 작성 규칙

### Ⅰ. 개요

- 개념 : 대상의 정의를 한 문장으로 제시.
- 배경 및 필요성 : 등장 배경과 문제 상황.
- 주요 목적 : 해결하려는 목표.
- 핵심 요약(1줄) : 위 세 요소를 한 줄로 압축한 문장.

### Ⅱ. 특징

- 핵심 속성, 원리, 차별점을 불릿으로 나열.
- 핵심 요약(1줄) : 특징을 한 문장으로 요약.

### Ⅲ. 구조 (흐름)

- 구성요소, 프로세스, 단계별 흐름을 도식·표로 제시.
- 핵심 요약(1줄) : 구조/흐름의 핵심을 한 문장으로 요약.

### Ⅳ. 비교

- 비교 대상, 비교 축, 선택 기준을 표로 정리.
- 핵심 요약(1줄) : 비교 결과의 핵심을 한 문장으로 요약.

### Ⅴ. 장점과 한계

- 장점과 한계를 각각 구분하여 제시, 한계에는 해결 방안 병기.
- 핵심 요약(1줄) : 장단점의 균형을 한 문장으로 요약.

### Ⅵ. 제언

- 기술사적 관점의 개선·적용·정책 제안.
- 핵심 요약(1줄) : 제언의 핵심을 한 문장으로 요약.

### Ⅶ. 결론

- 핵심 정리와 시사점.
- 핵심 요약(1줄) : 결론의 핵심을 한 문장으로 요약.

## 공통 작성 규칙

1. **로마숫자 표기** : 모든 프레임 제목은 `## Ⅰ. <주제>의 개요` 형식의 로마숫자(Ⅰ~Ⅶ)로 표기한다.
2. **핵심 요약 1줄** : 각 프레임의 첫 불릿(또는 첫 줄)은 반드시 `- 핵심 요약 : ...` 한 줄로 작성한다.
3. **명사형 종결** : 설명 문장은 명사형(예: ~체계, ~필요, ~효과)으로 끝내고, "~다", "~함/~됨" 남발을 피한다.
4. **불릿 라벨 비볼드** : 불릿 라벨(개념, 배경, 특징, 목적 등)은 굵게 표시하지 않는다.
5. **굵게 표기 규칙** : 굵게(`**`)는 여는/닫는 `**`가 정확히 쌍을 이루어야 하며, 강조 안쪽에 공백이나 문장부호를 두지 않는다.
6. **비교는 표로** : 비교 항목은 반드시 표(Table)로 정리한다.
7. **흐름은 도식으로** : 구조·흐름은 텍스트 도식(````text`) 또는 표로 제시한다.
8. **블록 경계** : 인용(`>`), HTML 블록(`</div>` 등), 표(`|`), 목록(`-`) 사이에는 반드시 빈 줄을 둔다.
9. **근거 없는 정량 수치 금지** : 출처가 없는 수치는 정성 효과 또는 측정 KPI로 표현한다.
10. **도식·도해 최소 2개** : 모든 답안에는 흐름도·구조도·비교도 등 도식과 도해를 **최소 2개 이상** 포함한다. ASCII 텍스트 도식(````text`)으로 표현하며, 노드는 7~12개, 라벨은 짧게, 단방향 흐름을 원칙으로 한다.
11. **장문 나열은 콤마 대신 번호 들여쓰기** : 3개 이상의 항목을 나열할 때는 콤마로 이어 쓰지 않고 번호(1., 2., ...)와 들여쓰기로 분리한다. 문장 내 자연스러운 나열은 콤마 허용.
12. **핵심 키워드 포함** : 기술사 시험은 핵심 키워드 등장 시 가점이 부여된다. 답안 상단에 "딸려 나오는 키워드"로 핵심 키워드를 먼저 나열하고, 본문 각 프레임에서 해당 키워드를 명시적으로 사용한다. 누락된 키워드는 감점 요인이다.

## 체크리스트

- [ ] 7개 프레임(Ⅰ~Ⅶ)이 모두 존재하는가?
- [ ] 각 프레임이 로마숫자로 표기되었는가?
- [ ] 각 프레임에 핵심 요약 1줄이 있는가?
- [ ] 비교 항목이 표로 정리되었는가?
- [ ] 흐름이 도식/표로 제시되었는가?
- [ ] 제언(Ⅵ)이 포함되었는가?
- [ ] 결론(Ⅶ)이 포함되었는가?
- [ ] 도식·도해가 최소 2개 포함되었는가?
- [ ] 핵심 키워드가 포함되었는가? (딸려 나오는 키워드 + 본문 명시)

## 예시 (그로스해킹)

### Ⅰ. 그로스해킹의 개요

- 개념 : 제품·데이터·실험을 결합해 성장을 만드는 방법론.
- 배경 및 필요성 : 스타트업의 자원 제약 하에서 빠른 성장 요구.
- 주요 목적 : 지속 가능한 성장 시스템 구축.
- 핵심 요약 : 제품 자체를 성장 엔진으로 만드는 데이터 기반 실험적 성장 방법론.

### Ⅱ. 그로스해킹의 특징

1. 제품 중심(Product-Led)
2. 데이터 기반(Data-Driven)
3. 실험 문화(Experimentation)
4. 채널·기능 융합(Cross-functional)

- 핵심 요약 : 제품·데이터·실험을 통합한 성장 운영체계.

### Ⅲ. 그로스해킹의 구조 (흐름)

- AARRR 퍼널과 Growth Loop의 이중 구조.
- 핵심 요약 : 획득→활성화→유지→매출→추천 흐름과 복리 성장 루프.

```text
[ AARRR 퍼널 흐름 ]
Acquisition(획득)
        ↓
Activation(활성화) ── "아하 모먼트"
        ↓
Retention(유지)
        ↓
Revenue(매출)
        ↓
Referral(추천) ──┐
        ↑        │
        └────────┘  (Growth Loop 복리 순환)
```

```text
[ Growth Loop 구조 ]
Input(입력) → Action(행동) → Output(출력) → 재입력
   │                                      │
   └────────────── 복리 성장 ─────────────┘
```

### Ⅳ. 그로스해킹과 전통 마케팅의 비교

- 초점, 조직, 의사결정, 채널, 성과 측정 비교.
- 핵심 요약 : 광고비 중심에서 제품·데이터·실험 중심으로의 전환.

### Ⅴ. 그로스해킹의 장점과 한계

- 장점 : 높은 ROI, 실패 비용 최소화. 한계 : Growth Debt, 윤리 리스크.
- 핵심 요약 : 빠른 성장과 지속성 사이의 균형 관리 필요.

### Ⅵ. 그로스해킹에 대한 기술사적 제언

- 그로스팀 독립 운영, 데이터 인프라 투자, 윤리 가이드라인 제정.
- 핵심 요약 : 지속 가능한 성장을 위한 조직·기술·윤리 체계 구축.

### Ⅶ. 결론

- 측정 가능한 가설 검증을 통한 지속 가능한 성장 시스템.
- 핵심 요약 : 그로스해킹은 성장 운영체계(Growth OS)이다.
