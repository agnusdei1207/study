## Ⅰ. Self-RAG의 개요

- 개념 : 사전학습된 LLM이 검색 필요 여부를 자율 판정하고, 검색 문서의 적합성과 생성 텍스트의 사실성을 반성 토큰(Reflection Tokens)으로 자가 비평(Self-Critique)하며 답변을 생성하는 능동형 RAG 기술
- 배경 및 필요성 : 매 문장 단위 반성 토큰 생성과 병렬 빔 서치로 인한 추론 레이턴시 및 연산 비용 증가가 심각하므로 질의 복잡도 기반 적응형 반성 스킵 게이트웨이 및 투-티어 라우팅 파이프라인 구축 필수
- 핵심 목적 : 무조건적 검색에 따른 불필요한 레이턴시 및 잡음 주입을 방지하고 생성 답변의 환각(Hallucination)을 수학적으로 검증·억제

## Ⅱ. Self-RAG의 핵심 아키텍처 및 동작 메커니즘

Self-RAG은 [Retrieve] 토큰으로 검색 실행 여부를 동적 결정하고 병렬 검색 문서별 관련도([IsRel]) 및 생성 세그먼트의 지지성([IsSup]), 유용성([IsUse]) 점수를 가중 합산하는 세그먼트 단위 빔 서치(Beam Search) 수행 메커니즘을 기반으로 동작하며, 세부적인 아키텍처와 핵심 컴포넌트 간 상호작용 프로세스는 다음과 같음.

```text
┌────────────────────────────────────────────────────────────────────────┐
│             Self-RAG 세그먼트 단위 빔 서치(Beam Search) 파이프라인    │
└────────────────────────────────────────────────────────────────────────┘
 [ 입력 질의 x 및 현재까지 생성된 문맥 y_<t ]
                      │
                      ▼
 [ [Retrieve] 토큰 예측 (Predict Retrieval Need) ]
          ├─────────────────────────────────────────────────┐
          ▼ [Retrieve] = no                                 ▼ [Retrieve] = yes
 [ 내부 지식 기반 표준 디코딩 ]                        [ 다중 외부 문서 병렬 검색 ]
  - 외부 검색 없이 즉시 y_t 생성                       - K개 문서 회수: {d_1, ..., d_k}
          │                                                 │
          │                                                 ▼
          │                                    ┌────────────────────────┐
          │                                    │ 각 문서별 [IsRel] 판별 │
          │                                    └────────────┬───────────┘
          │                                                 │
          │                                  ┌──────────────┴──────────────┐
          │                                  ▼                             ▼
          │                            [ d_1: relevant ]            [ d_2: irrelevant ]
          │                                  │ (문서 채택)                 │ (폐기)
          │                                  ▼                             ▼
          │                            ┌────────────────────────┐         X
          │                            │ 후보 세그먼트 병렬 생성│
          │                            │ (Candidate y_t^1)      │
          │                            └────────────┬───────────┘
          │                                         │
          │                                         ▼
          │                            ┌────────────────────────┐
          │                            │ [IsSup] 및 [IsUse] 평가│
          │                            └────────────┬───────────┘
          │                                         │
          └─────────────────────┬───────────────────┘
                                │
                                ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 최적 세그먼트 점수 집계 및 빔 탐색 (Segment Scoring & Pruning)        │
 │ Score = P(y_t) + w_rel*P([IsRel]) + w_sup*P([IsSup]) + w_use*P([IsUse])│
 └──────────────────────────────┬───────────────────────────────────────┘
                                │
                                ▼
                 [ 최적 세그먼트 y_t* 확정 및 다음 단계 반복 ]
```

- **[Retrieve]** : 매 토큰마다 검색 여부 판정, 파라미터 지식으로 충분할 경우 검색 스킵
- **[IsRel]** : 검색된 다중 문서 중 질의와 무관한 노이즈 문서를 생성 전 즉시 필터링
- **[IsSup]** : 생성된 문장이 검색 문서에 그라운딩되어 있는지 팩트체크 수행

## Ⅲ. Self-RAG의 세부 구성 요소 및 비교 분석

| 비교 항목 | Naive RAG (고정형) | CRAG (Corrective RAG) | Self-RAG (본 토픽) |
|---|---|---|---|
| **검색 시점** | 질의 입력 시 무조건 1회 실행 | 질의 입력 시 1회 실행 | 모델이 [Retrieve] 토큰으로 동적 결정 |
| **평가 주체** | 평가 메커니즘 부재 | 외부 경량 평가기 (Retrieval Evaluator) | 생성 모델 자체 (반성 토큰 내재화) |
| **모델 요구사항** | 일반 COTS LLM 사용 가능 | 일반 COTS LLM 사용 가능 | 반성 토큰으로 사전 튜닝된 전용 LLM |
| **검증 단위** | 문서 전체 수준 | 문서 및 지식 스트립 수준 | 문장 및 단락 단위 세그먼트 수준 |
| **환각 차단력** | 낮음 (검색 오류 전파) | 중간~높음 (웹 폴백 교정) | 최상 (문장 단위 [IsSup] 사실 검증) |

- Self-RAG은 상기 비교 지표를 바탕으로 비즈니스 요구사항과 운영 인프라 환경을 고려한 최적의 아키텍처를 선정하고, 확장성과 안정성을 균형 있게 확보해야 함.

## Ⅳ. Self-RAG의 주요 한계점 및 해결 방안

- 문장 단위 빔 서치와 다중 반성 토큰 연산에 따른 서빙 지연(Latency) :
  - 한계점 : 문장 단위마다 빔 서치와 다중 반성 토큰 확률을 계산함에 따라 발생하는 심각한 서빙 지연(Latency).
  - 해결 방안 : 단순 단답형 사실 질의는 Greedy 단일 경로 디코딩을 적용하고 복합 논증 질의에만 선택적 빔 서치 적용.
- 반성 토큰 학습을 위한 전용 파인튜닝 모델 강제 종속성 :
  - 한계점 : 특수 반성 토큰을 학습하기 위해 GPT-4 기반 데이터 생성 및 전용 파인튜닝 모델이 강제되는 종속성.
  - 해결 방안 : 비지도 LoRA 어댑터 형태로 반성 토큰 모듈을 모듈화하여 상용 오픈소스 베이스 모델과 분리 결합.
- 검색 문서 전체가 불합격 판정될 때 생성 마비 발생 :
  - 한계점 : 검색기(Retriever) 성능 부족으로 K개 문서 전체가 [IsRel=irrelevant]로 판정될 때 생성 마비 발생.
  - 해결 방안 : 모든 검색 문서 불합격 시 [Retrieve]=no 모드로 자동 롤백하여 모델 내부 파라미터 지식 기반 답변 강제 유도.

## Ⅴ. Self-RAG 적용 및 발전을 위한 기술사적 제언

- 평균 응답 속도 중심 엔터프라이즈 고도화 : 느린 응답 (사용자 경험 저하)의 한계를 탈피하고, 빠른 응답 (단순 질의 가속화)를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- GPU 컴퓨팅 자원 절감 및 최적화 체계 구축 : 상시 고부하 빔 서치 클러스터 필요의 한계를 탈피하고, 고난도 트래픽에만 집중 할당을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- 답변 신뢰성 강화 및 신뢰성 확보 방안 : 전 영역 팩트체크 수행의 한계를 탈피하고, 고위험 업무(금융/법률) 무오류 달성을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
