## 30초 인출

- 본질: **Self-RAG (Self-Reflective Retrieval-Augmented Generation)** 는 언어모델이 스스로 검색 필요성을 판단하고 검색된 문서의 관련성 및 생성된 문장의 근거성과 유용성을 특수 반성 토큰(Reflection Tokens)으로 자가 평가하는 적응형 RAG 프레임워크
- 메커니즘: [Retrieve] 토큰으로 검색 실행 여부를 동적 결정하고 병렬 검색 문서별 관련도([IsRel]) 및 생성 세그먼트의 지지성([IsSup]), 유용성([IsUse]) 점수를 가중 합산하는 세그먼트 단위 빔 서치(Beam Search) 수행
- 통찰: 매 문장 단위 반성 토큰 생성과 병렬 빔 서치로 인한 추론 레이턴시 및 연산 비용 증가가 심각하므로 질의 복잡도 기반 적응형 반성 스킵 게이트웨이 및 투-티어 라우팅 파이프라인 구축 필수

<details><summary>핵심 용어</summary>

- **Self-RAG** : 검색의 필요성 판정부터 문서 선별, 생성 문장의 사실 검증까지 모델 내부 반성 토큰으로 통제하는 자율 교정형 생성 모델.
- **반성 토큰 (Reflection Tokens)** : 검색 및 생성 단계의 품질을 평가하기 위해 사전 정의된 특수 토큰군([Retrieve], [IsRel], [IsSup], [IsUse]).
- **[Retrieve] 토큰** : 현재 컨텍스트에서 외부 지식 검색이 필요한지 여부({yes, no, continue})를 나타내는 제어 토큰.
- **[IsRel] 토큰** : 검색되어 유입된 외부 문서가 입력 질의와 실질적으로 관련이 있는지({relevant, irrelevant}) 판별하는 토큰.
- **[IsSup] 토큰** : 생성된 답변 문장이 검색된 외부 문서의 내용에 의해 충분히 뒷받침(Fully Supported)되는지 검증하는 토큰.
- **세그먼트 빔 서치 (Segment-level Beam Search)** : 문장 또는 단락 단위로 복수의 후보 세그먼트를 생성하고 반성 토큰 확률 점수로 최적 경로를 탐색하는 디코딩 기법.

</details>

## 2~4교시 25점 답안

## Ⅰ. Self-RAG의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **Self-RAG** 는 사전학습된 LLM이 검색 필요 여부를 자율 판정하고, 검색 문서의 적합성과 생성 텍스트의 사실성을 반성 토큰(Reflection Tokens)으로 자가 비평(Self-Critique)하며 답변을 생성하는 능동형 RAG 기술 |
| 목적 | 무조건적 검색에 따른 불필요한 레이턴시 및 잡음 주입을 방지하고 생성 답변의 환각(Hallucination)을 수학적으로 검증·억제 |

## Ⅱ. Self-RAG의 4대 반성 토큰 및 동작 특징

| 반성 토큰 명칭 | 평가 대상 및 생성 시점 | 값의 범주 (Token Values) | 공학적 기능 및 특징 |
|---|---|---|---|
| **[Retrieve]** | 검색 필요성 (질의 입력 직후 또는 문장 생성 중) | `{yes, no, continue}` | 매 토큰마다 검색 여부 판정, 파라미터 지식으로 충분할 경우 검색 스킵 |
| **[IsRel]** | 검색 문서의 관련성 (문서 검색 완료 직후) | `{relevant, irrelevant}` | 검색된 다중 문서 중 질의와 무관한 노이즈 문서를 생성 전 즉시 필터링 |
| **[IsSup]** | 문장의 근거성 (텍스트 세그먼트 생성 직후) | `{fully supported, partially supported, no support}` | 생성된 문장이 검색 문서에 그라운딩되어 있는지 팩트체크 수행 |
| **[IsUse]** | 응답의 유용성 (세그먼트 생성 완료 시점) | `{5, 4, 3, 2, 1}` | 생성된 내용이 사용자 질의 해결에 실질적으로 도움이 되는지 점수화 |

## Ⅲ. Self-RAG의 적응형 추론 파이프라인 및 빔 서치 체계

```text
┌────────────────────────────────────────────────────────────────────────┐
│             Self-RAG 세그먼트 단위 빔 서치(Beam Search) 파이프라인    │
└────────────────────────────────────────────────────────────────────────┘
 [ 입력 질의 x 및 현재까지 생성된 문맥 y_<t ]
                      │
                      ▼
 [ [Retrieve] 토큰 예측 (Predict Retrieval Need) ]
          ├─────────────────────────────────────────────────┐
          ▼ [Retrieve] = no                                 ▼ [Retrieve] = yes
 [ 내부 지식 기반 표준 디코딩 ]                        [ 다중 외부 문서 병렬 검색 ]
  - 외부 검색 없이 즉시 y_t 생성                       - K개 문서 회수: {d_1, ..., d_k}
          │                                                 │
          │                                                 ▼
          │                                    ┌────────────────────────┐
          │                                    │ 각 문서별 [IsRel] 판별 │
          │                                    └────────────┬───────────┘
          │                                                 │
          │                                  ┌──────────────┴──────────────┐
          │                                  ▼                             ▼
          │                            [ d_1: relevant ]            [ d_2: irrelevant ]
          │                                  │ (문서 채택)                 │ (폐기)
          │                                  ▼                             ▼
          │                            ┌────────────────────────┐         X
          │                            │ 후보 세그먼트 병렬 생성│
          │                            │ (Candidate y_t^1)      │
          │                            └────────────┬───────────┘
          │                                         │
          │                                         ▼
          │                            ┌────────────────────────┐
          │                            │ [IsSup] 및 [IsUse] 평가│
          │                            └────────────┬───────────┘
          │                                         │
          └─────────────────────┬───────────────────┘
                                │
                                ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 최적 세그먼트 점수 집계 및 빔 탐색 (Segment Scoring & Pruning)        │
 │ Score = P(y_t) + w_rel*P([IsRel]) + w_sup*P([IsSup]) + w_use*P([IsUse])│
 └──────────────────────────────┬───────────────────────────────────────┘
                                │
                                ▼
                 [ 최적 세그먼트 y_t* 확정 및 다음 단계 반복 ]
```

| 추론 단계 | 세부 수행 프로세스 | 제어 파라미터 및 알고리즘 |
|---|---|---|
| **동적 검색 판정** | 문맥을 기반으로 [Retrieve] 토큰의 로짓(Logit) 임계치 검사 | 검색 임계치 하이퍼파라미터 ($\tau_R$) |
| **병렬 문서 평가** | 검색된 K개 문서 각각에 대해 질의 관련성([IsRel]) 병렬 추론 | 관련성 임계치 ($\tau_{rel}$) |
| **세그먼트 디코딩** | 채택된 문서와 질의를 결합하여 문장 단위 세그먼트 다중 생성 | 빔 크기 (Beam Width: B) |
| **비평 점수 결합** | 언어모델 생성 확률과 [IsSup], [IsUse] 토큰 확률의 가중 선형 결합 | 가중치 벡터 ($w_{rel}, w_{sup}, w_{use}$) |
| **최적 텍스트 선택** | 최종 복합 점수가 가장 높은 상위 세그먼트를 선택하고 문맥 누적 | 조기 가지치기(Pruning) 적용 |

## Ⅳ. RAG 진화 아키텍처 비교

| 비교 항목 | Naive RAG (고정형) | CRAG (Corrective RAG) | Self-RAG (본 토픽) |
|---|---|---|---|
| **검색 시점** | 질의 입력 시 무조건 1회 실행 | 질의 입력 시 1회 실행 | 모델이 [Retrieve] 토큰으로 동적 결정 |
| **평가 주체** | 평가 메커니즘 부재 | 외부 경량 평가기 (Retrieval Evaluator) | 생성 모델 자체 (반성 토큰 내재화) |
| **모델 요구사항** | 일반 COTS LLM 사용 가능 | 일반 COTS LLM 사용 가능 | 반성 토큰으로 사전 튜닝된 전용 LLM |
| **검증 단위** | 문서 전체 수준 | 문서 및 지식 스트립 수준 | 문장 및 단락 단위 세그먼트 수준 |
| **환각 차단력** | 낮음 (검색 오류 전파) | 중간~높음 (웹 폴백 교정) | 최상 (문장 단위 [IsSup] 사실 검증) |
| **추론 레이턴시** | 매우 낮음 (1회 생성) | 중간 (경량 판별기 1회) | 높음 (다단계 빔 서치 연산) |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 문장 단위마다 빔 서치와 다중 반성 토큰 확률을 계산함에 따라 발생하는 심각한 서빙 지연(Latency) | 단순 단답형 사실 질의는 Greedy 단일 경로 디코딩을 적용하고 복합 논증 질의에만 선택적 빔 서치 적용 |
| 특수 반성 토큰을 학습하기 위해 GPT-4 기반 데이터 생성 및 전용 파인튜닝 모델이 강제되는 종속성 | 비지도 LoRA 어댑터 형태로 반성 토큰 모듈을 모듈화하여 상용 오픈소스 베이스 모델과 분리 결합 |
| 검색기(Retriever) 성능 부족으로 K개 문서 전체가 [IsRel=irrelevant]로 판정될 때 생성 마비 발생 | 모든 검색 문서 불합격 시 [Retrieve]=no 모드로 자동 롤백하여 모델 내부 파라미터 지식 기반 답변 강제 유도 |

## Ⅵ. 제언

서빙 인프라의 처리량(Throughput)과 답변 신뢰도를 동시에 보장하기 위해 질의 난이도 기반 듀얼 패스(Dual-Pass) 적응형 Self-RAG 아키텍처 구축 권고.

```text
[ 사용자 질의 유입 ]
          │
          ▼
[ 프론트엔드 질의 라우터 (Query Complexity Classifier) ]
          ├─ 단순 사실 질의 (70%) ──> [ 고속 Naive RAG / 캐시 패스 (Greedy) ]
          │                                          │
          └─ 복합 추론/고위험 (30%)                  │
                   │                                 │
                   ▼                                 ▼
┌────────────────────────────────────────────────────────┐   │
│ Self-RAG 심층 반성 엔진 (Segment Beam Search)          │   │
│  ├── [Retrieve] 동적 트리거                            │   │
│  ├── 병렬 [IsRel] 필터링                               │   │
│  └── 문장 단위 [IsSup] 사실 검증                       │   │
└──────────────────────────┬─────────────────────────────┘   │
                           │                                 │
                           ▼                                 ▼
                     [ 최종 고품질 응답 조립 및 서빙 ] <─────┘
```

| 구분 | 전면적 Self-RAG 적용 | 제언: 질의 복잡도 기반 듀얼 패스 Self-RAG |
|---|---|---|
| **평균 응답 속도** | 3.5 ~ 5.0초 (사용자 경험 저하) | 0.8 ~ 1.2초 (단순 질의 가속화) |
| **GPU 컴퓨팅 자원** | 상시 고부하 빔 서치 클러스터 필요 | 고난도 30% 트래픽에만 집중 할당 |
| **답변 신뢰성** | 전 영역 팩트체크 수행 | 고위험 업무(금융/법률) 무오류 달성 |
| **운영 유연성** | 단일 병목 구조 | 부하 급증 시 반성 임계치 동적 조절 가능 |
