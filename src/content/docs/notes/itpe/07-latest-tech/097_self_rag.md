## 연관 키워드

- Self-RAG, 반성 토큰, RAG, Retrieve, IsRel, IsSup, IsUse, 세그먼트, 빔 탐색, 근거 지지, 환각

## Ⅰ. Self-RAG의 개요

- 핵심 요약 : 검색 필요성과 생성 근거를 반성 토큰으로 스스로 평가하며 답을 만드는 자기 반성형 RAG.
- 개념 : 대규모 언어모델(LLM, Large Language Model)이 **반성 토큰**(Reflection Token)을 생성해 검색 필요성, 문서 관련성, 근거 지지, 답변 유용성을 평가하면서 답하는 방법 **Self-RAG**(Self-Reflective Retrieval-Augmented Generation).
- 배경 및 필요성 : 검색 증강 생성(RAG, Retrieval-Augmented Generation)은 입력마다 정해진 수의 문서를 검색하므로, 불필요한 검색과 관련 없는 문서가 답변 품질을 낮출 수 있다.
- 주요 목적 : 필요한 시점에만 검색하고 근거를 평가해 사실성과 인용 정확도를 높이는 것. 학습된 평가가 환각을 완전히 없앤다는 뜻은 아니다.

## Ⅱ. Self-RAG의 특징 및 장점

- 핵심 요약 : 반성 토큰이 검색과 생성의 결정을 세그먼트 단위로 내리므로, 필요한 근거만 골라 쓰는 선택적 생성 구조.

1. **Retrieve**(검색 필요성) : 다음 세그먼트 생성 전에 검색이 필요한지 예측 → 불필요한 검색을 줄여 지연과 비용 절감.
2. **IsRel**(관련성) : 검색 문서가 질의와 관련 있는지 평가 → 무관한 문서가 생성에 들어가는 것을 차단.
3. **IsSup**(근거 지지) : 생성 문장이 문서에 의해 지지되는지 평가 → 주장과 인용의 일치도 점검. 문서 자체의 진실성까지 보증하지는 않는다.
4. **IsUse**(유용성) : 답변이 사용자에게 유용한지 평가 → 근거는 맞지만 쓸모없는 답변을 걸러냄.

## Ⅲ. Self-RAG의 구조 (흐름)

- 핵심 요약 : 학습 단계에서 생성 모델이 반성 토큰을 익히고, 추론 단계에서 반성 점수로 후보 세그먼트를 고르는 두 단계 구조.

```text
학습: 비평 모델로 반성 토큰 주석 생성
      ↓
생성 모델이 문장과 반성 토큰을 함께 학습
```

```text
[ 질의 + 이전 생성 내용 ]
          ↓
[ Retrieve: 검색 필요 여부 예측 ]
          ↓ 필요 시
[ 문서 검색 → 문서별 후보 세그먼트 ]
          ↓
[ IsRel · IsSup · IsUse 점수 산출 ]
          ↓
[ 점수 기반 후보 선택 후 반복 생성 ]
```

- 세그먼트 단위 빔 탐색 : 후보의 생성 확률과 반성 점수를 조합해 선택하며, 반성 점수의 가중치와 검색 임계값으로 동작을 조정.

## Ⅳ. Self-RAG와 고정 검색 RAG의 비교

- 핵심 요약 : 고정 검색 RAG는 검색과 평가를 외부 규칙으로 처리하고, Self-RAG는 생성 모델 내부의 반성 토큰으로 처리한다.

| 비교 축 | 고정 검색 RAG | Self-RAG |
| --- | --- | --- |
| 검색 | 입력마다 정해진 검색 실행 | 반성 토큰과 임계값으로 검색 필요성 판단 |
| 모델 | 일반 생성 모델과 검색기 조합 가능 | 반성 토큰을 학습한 생성 모델 필요 |
| 근거 평가 | 별도 평가기나 프롬프트로 추가 가능 | 생성 모델 내부의 학습된 비평 활용 |
| 품질 의존성 | 검색기·문서·생성기 품질에 의존 | 같은 의존성에 더해 반성 평가의 오류 가능성 존재 |

원 논문은 비평 데이터 생성에 사용한 모델을 모든 구현의 필수 요소로 제시하지 않으므로, 추론 시 외부 비평 모델을 매번 호출하는 구조와는 구별해서 이해해야 한다.

## Ⅴ. Self-RAG의 한계와 방안

- 핵심 요약 : 학습 비용, 추론 지연, 자기평가 오류가 주요 한계이며 데이터 검증, 파라미터 조정, 외부 검증으로 제어.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 추가 학습 비용 | 반성 토큰 주석과 근거 평가 데이터를 만들고 파인튜닝해야 함 | 주석 데이터 품질 검증, 학습 환경과 라이선스 확인 | 주석 품질 점검 비율 |
| 추론 지연 | 검색과 후보 세그먼트 생성이 반복되어 응답이 느려짐 | 문서 수, 검색 임계값, 빔 폭을 업무별 평가셋으로 조정 | 응답 지연 시간, 검색 호출 횟수 |
| 자기평가의 오류 | 반성 점수가 틀린 근거를 통과시키거나 정상 근거를 버릴 수 있음 | 출처·최신성·인용 일치를 별도 검증하고, 근거 부족 시 답변 보류 또는 사람 검토 | 근거 불일치율, 보류 건수 |

## Ⅵ. Self-RAG에 대한 기술사적 제언

- 핵심 요약 : 기존 RAG와의 정량 비교를 거친 뒤 도입하고, 고위험 업무에서는 반성 점수를 확정 판정으로 쓰지 않는 원칙의 확립.

같은 질의와 검색 자료, 평가 기준으로 기존 RAG와 비교해 품질 향상과 추가 비용을 함께 측정한 뒤 도입을 결정하는 것이 바람직하다. 고위험 업무에서는 반성 점수를 사실 판정으로 취급하지 않고, 출처 검증과 사람의 판단 절차를 결합하는 것을 기본으로 한다.

## Ⅶ. 결론

- 핵심 요약 : Self-RAG는 생성 모델이 검색 필요성과 근거를 스스로 평가하는 자기 반성형 RAG임.
- 검색을 필요할 때만 쓰는 선택성은 얻지만, 자기평가가 사실을 보증하지는 않으므로 외부 검증과 함께 설계해야 실효가 있다.
