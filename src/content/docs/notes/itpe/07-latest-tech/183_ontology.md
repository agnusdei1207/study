## 30초 인출

- 본질: 특정 관심 도메인의 개념, 관계, 제약조건을 컴퓨터가 해석하고 추론할 수 있도록 합의된 형태로 기술한 '공유된 개념화의 명시적 정형 명세(Explicit Formal Specification of Shared Conceptualization)'.
- 메커니즘: 도메인 범위 선정 → 클래스/속성/공리(Axiom) 모델링 → 인스턴스 인스턴스화 → Description Logic 기반 추론기(Pellet/HermiT) 모순 검사 및 관계 확장.
- 통찰: 표현력이 높을수록 추론 연산 복잡도가 지수적으로 증가(NP-Hard)하므로 질의 요구에 부합하는 OWL 2 경량 프로파일(EL/QL/RL)을 선별 적용하는 실용적 모델링 필수.

<details><summary>핵심 용어</summary>

- **개념화의 정형 명세 :** 사람의 머릿속 지식 체계(개념화)를 기계가 논리적으로 파싱 가능한 문법(정형성)으로 명확히 표현(명시성)한 모델.
- **클래스/인스턴스/프로퍼티 :** 온톨로지를 구성하는 3대 핵심 엔티티로 범주 집합, 구체적 개체, 개체 간의 관계 속성을 정의.
- **공리(Axiom) :** 항상 참으로 간주되는 논리적 제약 명제로 클래스의 상속, 배타성(Disjoint), 속성의 추이성(Transitive) 등을 규정.
- **기술 논리(Description Logic) :** 1차 술어 논리의 결정 가능한(Decidable) 부분집합으로 온톨로지 추론기의 수학적 이론 기반.

</details>

## 2~4교시 25점 답안

## Ⅰ. 온톨로지(Ontology)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 특정 관심 영역(도메인)에 존재하는 개념들과 그들 간의 관계를 컴퓨터가 이해하고 추론할 수 있도록 기계 가독성 있는 형태로 표준화한 공유된 지식 모델. |
| 목적 | 시스템 간 의미적 상호운용성 보장, 지식 재사용 및 공유 극대화, 분산 환경에서의 지능형 의미 검색 및 자율 추론(Automated Reasoning) 지원. |

## Ⅱ. Gruber 교수의 온톨로지 4대 정의 요소 및 특성

### 1. 온톨로지 4대 정의 요소 (Thomas Gruber, 1993)

- **개념화(Conceptualization) :** 현실 세계의 사물과 현상을 추상화하여 모델링한 지식의 표상.
- **명시적 명세(Explicit Specification) :** 개념의 정의, 범위, 제약조건을 암묵적 가정이 아닌 명확한 규칙으로 선언.
- **정형성(Formal) :** 자연어가 아닌 기계가 자동으로 파싱하고 처리할 수 있는 수학적 논리 문법 준수.
- **공유성(Shared) :** 개인의 주관적 견해가 아닌 특정 커뮤니티나 도메인 전문가 그룹 간에 합의된 공통 지식.

### 2. 온톨로지 기술적 특징

- **논리적 무결성 검증 :** 지식 모델 내에 상호 모순되는 명제가 존재하는지 추론기를 통해 자동 탐지(Consistency Checking).
- **숨겨진 지식 발견 :** 명시적으로 입력되지 않은 사실이라도 공리와 상속 관계를 결합하여 새로운 지식을 연역 도출(Entailment).

## Ⅲ. 온톨로지 핵심 구성요소 및 모델링 아키텍처

### 1. 온톨로지 구성요소 간 상호작용 아키텍처

```text
+-------------------------------------------------------------------------------+
|                             [ 온톨로지 지식 모델 ]                             |
+-------------------------------------------------------------------------------+
| [Classes]         '사람', '의사', '환자', '질병', '처방' (개념의 범주 집합)   |
|                         │ is-a 상속 계층                                      |
+-------------------------------------------------------------------------------+
                          ▼
| [Properties]      개체 속성(Object): '치료하다(의사->환자)'                   |
|                   데이터 속성(Data): '혈압치(환자->정수값)'                   |
+-------------------------------------------------------------------------------+
                          ▼
| [Axioms]          '치료하다'의 역관계는 '치료받다'                             |
|                   '의사'와 '환자'는 배타적 집합 (Disjoint Classes)            |
+-------------------------------------------------------------------------------+
                          ▼ (실제 데이터 매핑)
| [Instances]       의사 인스턴스: [김기술], 환자 인스턴스: [이고객]            |
+-------------------------------------------------------------------------------+
                                      │
                                      ▼ (Reasoning Engine: Pellet / HermiT)
+-------------------------------------------------------------------------------+
| [추론 결과]       [이고객]은 [김기술]에게 '치료받다' 자동 유추 및 분류 완료     |
+-------------------------------------------------------------------------------+
```

### 2. 4대 구성요소 세부 기능

| 구성요소 | 기술적 명세 (OWL 표기) | 핵심 역할 및 엔지니어링 기능 |
|---|---|---|
| **클래스 (Class)** | `owl:Class`, `rdfs:subClassOf` | 도메인 내 공통 속성을 지닌 개체들의 집합 및 다중 계층 상속 구조 형성. |
| **인스턴스 (Instance)** | `owl:NamedIndividual`, `rdf:type` | 클래스에 소속된 실세계의 구체적인 개별 데이터 객체(개체). |
| **프로퍼티 (Property)** | `owl:ObjectProperty`, `owl:DatatypeProperty` | 개체 간의 의미적 관계 간선(Link) 및 개체가 보유한 원시 속성값 지정. |
| **공리 (Axiom)** | `owl:disjointWith`, `owl:TransitiveProperty` | 도메인의 절대적 제약조건을 선언하여 비논리적 인스턴스 생성을 원천 차단. |

## Ⅳ. 지식 체계의 진화: 분류(Taxonomy), 시소러스(Thesaurus), 온톨로지(Ontology) 비교

| 비교 항목 | 분류 체계 (Taxonomy) | 시소러스 (Thesaurus) | 온톨로지 (Ontology) |
|---|---|---|---|
| **지식 구조** | 단방향 트리(Tree) 계층 구조 | 동의어·유의어 네트워크 | 다차원 방향성 그래프(Graph) |
| **관계 표현** | 단순 상하위 포함 관계 (is-a) | 동의어(Synonym), 관련어(RT), 상하위(BT/NT) | 임의의 도메인 특화 관계(Object Property) |
| **기계 해석도** | 낮음 (단순 목차 수준) | 중간 (용어 사전 수준) | 최고 (완전한 기계 가독성 및 형식 명세) |
| **논리 추론** | 단순 계층 필터링 | 단순 연관어 확장 | 복합 공리 기반의 새로운 관계 자동 연역 |
| **표준 언어** | 폴더 구조, 도서관 십진분류 | ISO 25964, SKOS | OWL 2, RDF Schema, RIF |
| **대표 사례** | 생물 분류학, 쇼핑몰 카테고리 | 의학 용어 시소러스(MeSH) | SNOMED-CT, Gene Ontology, Wikidata |

## Ⅴ. 온톨로지 엔지니어링 한계와 해결 방안

| 한계 | 방안 |
|---|---|
| **풍부한 공리 사용 시 추론 연산 복잡도 폭증 (NP-Hard)**<br />- OWL Full 수준의 고표현력 공리 사용 시 대규모 인스턴스 검증에서 메모리 초과 및 무한 대기. | **도메인 목적에 부합하는 OWL 2 서브 프로파일 채택**<br />- 대규모 개념 분류: 다항식 시간 복잡도를 보장하는 OWL 2 EL 적용.<br />- 대용량 RDB 연동: 질의 변환(Rewriting) 중심의 OWL 2 QL 적용.<br />- 규칙 기반 시스템: 프로로그/포워드 체이닝과 호환되는 OWL 2 RL 채택. |
| **도메인 간 용어 불일치 및 온톨로지 이질성(Heterogeneity)**<br />- 서로 다른 조직에서 구축한 온톨로지 간에 동일 개념의 클래스명이 상이하여 데이터 결합 불가. | **온톨로지 매칭 및 정렬(Ontology Alignment) 프레임워크 구축**<br />- 어휘 유사도(Levenshtein)와 구조 유사도(Graph Kernel)를 결합한 자동 매핑 엔진 도입.<br />- `owl:equivalentClass`, `owl:sameAs` 링크를 통한 점진적 의미 통합. |
| **최신 도메인 지식 갱신의 지연 및 유지보수 비용**<br />- 새로운 학술 논문 및 실시간 데이터의 발생 속도를 수작업 모델링이 따라가지 못하는 병목. | **LLM 기반 온톨로지 자동 파퓰레이션(Ontology Population)**<br />- 비정형 텍스트에서 신규 인스턴스와 관계를 추출하여 온톨로지 초안 자동 생성.<br />- 도메인 전문가의 승인 워크플로우를 결합한 휴먼 인 더 루프(HITL) 체계 운영. |

## Ⅵ. 실용적 온톨로지 기반 지식 시스템 구축을 위한 제언

처음부터 완벽한 전사적 온톨로지를 구축하려 하지 말고, 비즈니스 핵심 엔티티 중심의 미니멀 온톨로지로 시작하여 추론 복잡도를 모니터링하며 점진적 확장하는 애자일 모델링 필수.

```text
[도메인 범위 정의] ──► [어휘 재사용 검토] ──► [경량 OWL 2 모델링] ──► [추론 정합성 검증] ──► [LOD 개방 및 연계]
- 핵심 유스케이스 도출   - FOAF, Schema.org      - EL/QL 프로파일 준수    - Pellet 무모순 검증     - SPARQL 엔드포인트
```

| 검증 단계 | 중점 점검 항목 | 기준 요건 |
|---|---|---|
| **논리 무모순성** | 온톨로지 모델 내 논리적 모순 클래스 존재 여부 | Unsatisfiable Class 0건 달성 |
| **추론 지연시간** | 10만 개 트리플 대상 일관성 검사 완료 시간 | 10초 이내 연산 수렴 |
| **공유 재사용성** | 기존 표준 어휘(W3C, Dublin Core 등) 재사용 비율 | 전체 클래스/속성의 40% 이상 재사용 |
