## 연관 키워드

- DSML 플랫폼, MLOps(Machine Learning Operations), DataOps, 피처 스토어(Feature Store), 모델 레지스트리(Model Registry)
- 실험 추적(Experiment Tracking), 모델 카드(Model Card), 역할 기반 접근 제어(RBAC), 벤더 종속(Vendor Lock-in)
- 쿠버네티스(Kubernetes), 재현성(Reproducibility), 섀도우 IT(Shadow IT)

## Ⅰ. DSML(Data Science and Machine Learning) 플랫폼의 개요

- 핵심 요약 : 데이터 준비부터 모델 배포와 운영 감시까지 AI 라이프사이클 전 주기를 하나의 환경에서 관리하는 통합 플랫폼.
- 개념 : **DSML 플랫폼** (DSML Platform, 데이터 준비, 모델 개발, 분산 학습, 실험 추적, 서빙, 운영 감시를 한 환경에서 제공하는 통합 플랫폼)은 AI 라이프사이클 전 과정을 하나의 체계로 묶음.
- 배경 및 필요성 : 팀마다 도구를 따로 쓰면 승인 없이 부서가 독자적으로 쓰는 IT 도구, 즉 **섀도우 IT** (Shadow IT)가 생기고 거버넌스 공백이 커짐. 그래서 단일 메타데이터 카탈로그와 **역할 기반 접근 제어** (RBAC, Role-Based Access Control, 역할에 따라 데이터와 기능의 접근 권한을 나누는 방식)를 갖춘 전사 공통 환경이 필요함.
- 주요 목적 : 데이터 과학자와 엔지니어 간 협업 단절 제거, **재현성** (Reproducibility, 같은 코드·데이터·환경으로 같은 결과를 다시 얻는 능력) 확보, 모델 출시 기간 단축과 AI 거버넌스 확립.

## Ⅱ. DSML(Data Science and Machine Learning) 플랫폼의 특징 및 장점

- 핵심 요약 : 라이프사이클 통합, 다차원 재현성, 사용자 수준별 도구, 거버넌스 기능이 결합되어 협업 단절과 감사 부담을 줄이는 구조.

1. 라이프사이클 통합 : **MLOps** (Machine Learning Operations, 모델 개발과 운영을 자동화하는 실천 체계)와 **DataOps** (Data Operations, 데이터 파이프라인을 자동화하고 관리하는 실천 체계)를 한 환경에 결합 → 수집부터 모니터링까지 인계 단절 감소.
2. 다차원 재현성 : 코드 커밋, 데이터 해시, 컨테이너 이미지, 파라미터를 하나의 실행(Run) ID에 묶음 → 결과 재현과 원인 추적 가능.
3. 사용자 수준별 도구 : **AutoML** (Automated Machine Learning, 모델 선택과 하이퍼파라미터 탐색을 자동화하는 기술)과 GUI 도구를 현업용으로, 주피터와 VS Code 기반 환경을 개발자용으로 함께 제공 → 같은 모델 자산을 공유.
4. 거버넌스 기능 : RBAC, 감사 로그, **모델 카드** (Model Card, 모델의 용도·성능·한계를 기록한 문서) 자동 생성 → 규제 대응 증빙 비용 절감.

## Ⅲ. DSML(Data Science and Machine Learning) 플랫폼의 구조 (흐름)

- 핵심 요약 : 데이터, 개발·학습, 실험·레지스트리, 서빙·감시의 4계층이 순서대로 이어지는 구조.
- 개발·학습 계층 : **쿠버네티스** (Kubernetes, 컨테이너 작업을 자동으로 배치하고 확장하는 오케스트레이션 시스템) 위에서 분산 학습 작업을 스케줄링하고, GPU(Graphics Processing Unit) 자원을 필요한 만큼 할당함.
- 실험 계층 : **피처 스토어** (Feature Store, 학습과 서빙이 같은 피처를 공유하도록 관리하는 저장소)에서 입력 변수를 받고, **실험 추적** (Experiment Tracking)으로 지표와 아티팩트를 기록함.

```text
[1. 데이터·피처 계층]
  데이터 레이크하우스, 스트림 연계, 피처 스토어
        ↓
[2. 모델 개발·분산 학습 계층]
  노트북 환경, AutoML, 분산 학습 스케줄러
        ↓
[3. 실험 추적·모델 레지스트리]
  지표와 아티팩트 기록, 단계별 승인
        ↓
[4. 서빙·감시 계층]
  추론 서버, 점진 배포, 드리프트 대시보드
```

```text
실험 실행 (Run ID 발급)
        ↓
평가 지표 기준 통과
        ↓
레지스트리 Staging 등록
        ↓ 승인자 검토
Production 전환 후 서빙
```

## Ⅳ. 통합 DSML(Data Science and Machine Learning) 플랫폼과 자체 구축 방식의 비교

- 핵심 요약 : 빠른 도입과 일관된 관리는 통합 플랫폼이, 기술 통제권과 이식성은 자체 구축이 강점을 가짐.

| 비교 항목 | 통합 DSML 플랫폼 (클라우드 매니지드 서비스) | 자체 오픈소스 조합 (DIY MLOps Stack) |
| --- | --- | --- |
| 초기 구축 속도 | 프로비저닝이 빨라 단기간 도입 가능 | 여러 오픈소스 연동과 검증에 긴 기간 필요 |
| 운영 유지보수 | 벤더가 관리하는 서비스로 부담이 적음 | 쿠버네티스와 컴포넌트 버전 호환성을 자체 해결 |
| 도구 일관성 | 통합 웹 UI, 싱글 사인온(SSO, Single Sign-On)과 일원화된 RBAC | 도구별 UI와 계정 관리가 분산됨 |
| 비용 구조 | 플랫폼 이용료와 클라우드 구독 비용 발생 | 라이선스 비용은 낮지만 전담 인력 비용이 큼 |
| 벤더 종속성 | 특정 클라우드 종속(Lock-in) 위험 | 기술 통제권과 하이브리드 구성의 유연성 확보 |

- 선택 기준 : 인력 규모, 규제 요구 수준, 특정 클라우드 종속을 허용할 범위에 따라 방식을 정함.

## Ⅴ. DSML(Data Science and Machine Learning) 플랫폼의 한계와 방안

- 핵심 요약 : 벤더 종속과 비용 증가, 자산 사일로, 민감 데이터 노출을 이식성 설계, 단일 레지스트리, 접근 통제로 관리해야 함.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 벤더 종속과 비용 증가 | 특정 클라우드 전용 API로 타 환경 이전이 어렵고, GPU(Graphics Processing Unit) 인스턴스 과금이 커짐 | 오픈 표준(MLflow, Docker, Kubernetes) 기반 설계, 유휴 자원의 자동 축소 정책 | 월간 자원 비용, 이식 가능 구성 비율 |
| 자산 사일로와 섀도우 IT | 팀별 도구로 모델과 피처가 중복 개발되거나 유실됨 | 전사 단일 모델 레지스트리와 피처 스토어 등록 의무화, 플랫폼 외 배포 차단 | 중복 피처 수, 플랫폼 외 배포 건수 |
| 민감 데이터 노출 | 연구용 학습 환경에 운영 개인정보가 가명화 없이 적재됨 | RBAC 적용, 가명·익명화 파이프라인 자동화, 변경 불가 감사 로그 보존(WORM, Write Once Read Many) | 비식별 처리되지 않은 데이터셋 수 |

## Ⅵ. DSML(Data Science and Machine Learning) 플랫폼에 대한 기술사적 제언

- 핵심 요약 : 인프라 자원 공유, 운영 조직 설계, 규제 대응 자동화를 함께 설계해 플랫폼을 조직 역량으로 정착시켜야 함.

1. 개별 가상머신과 분산 노트북 환경을 줄이고, 쿠버네티스 기반으로 GPU 자원을 공유 풀로 운영하는 방향이 바람직하다.
2. 플랫폼 운영을 데이터, 인프라, 보안 담당이 공동으로 맡는 전담 조직을 두고, 권한 설계와 비용 배분 기준을 조직 정책으로 확정해야 한다.
3. 규제 대응을 사후 보고서 작성이 아닌 **설명 가능한 AI** (XAI, Explainable Artificial Intelligence, 모델 판단의 근거를 설명하는 기술) 보고서의 자동 산출로 바꾸는 방향이 장기적으로 운영 부담을 낮춘다.

## Ⅶ. 결론

- 핵심 요약 : DSML 플랫폼은 라이프사이클 전 주기를 한 환경에서 묶어 재현성과 거버넌스를 확보하는 통합 기반임.
- 시사점 : 도입 자체보다 권한, 승인, 이식성을 어떻게 설계하는지가 협업 효율과 벤더 종속 위험을 결정함.
