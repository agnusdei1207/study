## 지식 로드맵 내 현재 위치

최신 기술 → 기술 개념·적용 → IoT(Internet of Things)

## 30초 인출

- 본질: 사물의 상태를 센서로 수집하고 네트워크·플랫폼을 거쳐 서비스를 제공하는 연결 구조. 사물의 상태를 원격에서 수집·활용하고 필요할 때 제어.
- 메커니즘: 기기 센싱 → 연결·게이트웨이 → 플랫폼 처리 → 응용·관리.
- 통찰: 한계: 연결 기기 수를 늘려도 기기 인증·업데이트·데이터 해석이 빠지면 서비스가 불안정하다 → 방안: 기기부터 플랫폼까지 신원·데이터 형식·운영 상태를 끝단 시험한다.

<details><summary>핵심 용어</summary>

- **사물인터넷:** 물리 사물을 네트워크에 연결해 상태 수집·제어에 활용하는 체계
- **게이트웨이:** 기기와 플랫폼 사이의 프로토콜·데이터 연결 장치

</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 사물의 상태를 센서로 수집하고 네트워크·플랫폼을 거쳐 서비스를 제공하는 연결 구조. |
| 목적 | 사물의 상태를 원격에서 수집·활용하고 필요할 때 제어 |

## Ⅱ. 사물에서 서비스까지의 경로

```text
센서·액추에이터 → 로컬 연결·게이트웨이
                             ↓
                        플랫폼 수집·처리
                             ↓
                      응용 서비스·원격 제어
                             ↓ 기기 상태 확인
```

1. **구조:** 센서·MCU → 로컬 게이트웨이 → MQTT 브로커 또는 CoAP 서버 → 스트림 처리·저장 → 운영 대시보드·제어.
2. **통신 선택:** 메시지 패턴·전원·네트워크 손실·단말 규모에 따라 프로토콜과 QoS를 결정하고 중복 수신에 대비한 응용 멱등성 설계.
3. **보안:** 기기별 신원, 초기 암호 변경, 안전한 부팅·업데이트, 전송 암호화, 수명 종료와 폐기 절차.
4. **검증:** 배터리 수명, 연결 복구 시간, 데이터 유실·중복, 취약점 조치 시간을 실제 설치 환경에서 측정.

## Ⅲ. MQTT와 CoAP의 통신 관계

| 구분 | MQTT | CoAP |
|---|---|---|
| 교환 방식 | 브로커 중심 발행·구독 | 요청·응답과 관측 |
| 적용 판단 | 다수 구독자 배포 | 제한된 기기와 자원 접근 |

## Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 지하·외곽 계량기의 통신 두절 — 설치 위치별 전파 감쇄·망 음영 | 현장 측정 뒤 LoRaWAN·NB-IoT 등 적합한 망과 재전송 정책 선택 |
| 배터리 교체 비용 증가 — 보고 주기·무선 연결·전력 상태 관리 부족 | PSM·eDRX 등 절전 기능과 보고 주기 최적화 |
| 계량기 펌웨어 변조와 부정 접속 — 기본 인증·무결성 검증 부족 | 보안 부팅, 서명된 업데이트, 고유 자격정보 적용 |

## Ⅴ. 제언

- 중요 인프라 IoT 도입 시 해당 사업의 현행 보안·조달 기준을 확인하고, 장치 식별·업데이트·네트워크 분리·이상 징후 대응을 운영 계약에 반영. MAC 주소만으로 단말 신원을 신뢰하지 않는 설계

## 출제 이력과 검증 출처

- **출제 상태:** 위 문항은 학습용 예상문제이며, 공식 기출 원문과 동일하다고 단정하지 않는다.
- [OASIS MQTT Version 5.0](https://docs.oasis-open.org/mqtt/mqtt/v5.0/mqtt-v5.0.html): 발행·구독과 QoS 프로토콜 의미
- [IETF RFC 7252, CoAP](https://www.rfc-editor.org/rfc/rfc7252): 제한된 환경의 웹 전송 모델
