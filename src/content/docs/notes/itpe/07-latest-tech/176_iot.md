## 답안 골격
### 1교시 예상문제 (10점)
IoT의 구성 계층과 MQTT·CoAP 통신 방식의 차이를 설명하시오.

### 1교시 10점 답안
- **정의:** 사물의 상태를 센서로 수집하고 네트워크·플랫폼을 거쳐 서비스를 제공하는 연결 구조.
- **계층:** 기기·센서 → 유무선 연결·게이트웨이 → 데이터 저장·처리 → 응용·관리.
- **프로토콜:** MQTT는 브로커 기반 발행·구독, CoAP는 제한된 장치의 요청·응답에 적합한 웹 전송 방식. 실제 전송 보장은 설정·구현·응용 처리에 종속.

### 2~4교시 예상문제 (25점)
대규모 IoT 센서 서비스의 아키텍처와 보안·전력·메시지 신뢰성 대응책을 설명하시오.

### 2~4교시 25점 답안
1. **구조:** 센서·MCU → 로컬 게이트웨이 → MQTT 브로커 또는 CoAP 서버 → 스트림 처리·저장 → 운영 대시보드·제어.
2. **통신 선택:** 메시지 패턴·전원·네트워크 손실·단말 규모에 따라 프로토콜과 QoS를 결정하고 중복 수신에 대비한 응용 멱등성 설계.
3. **보안:** 기기별 신원, 초기 암호 변경, 안전한 부팅·업데이트, 전송 암호화, 수명 종료와 폐기 절차.
4. **검증:** 배터리 수명, 연결 복구 시간, 데이터 유실·중복, 취약점 조치 시간을 실제 설치 환경에서 측정.

 ┣━ Ⅴ 비교 ───── MQTT vs CoAP (TCP기반/브로커중심Pub-Sub/QoS지원/연결지속 vs UDP기반/클라이언트-서버Request-Response/경량헤더/비연결)
 ┗━ Ⅵ 실무 ───── 미라이(Mirai) 봇넷 등 IoT 보안 취약점 / 배터리 수명 및 전력 소모 한계 / 기기별 통신 규격 파편화

## 한 줄 본질
- IoT는 센서·액추에이터가 있는 사물을 네트워크와 서비스에 연결해 데이터를 수집·교환·활용하는 체계. 사람의 감독이나 실시간 통신이 항상 필요한 것은 아님

## 핵심 용어
- MQTT(Message Queuing Telemetry Transport): 대역폭이 제한된 저전력 네트워크 환경을 위해 설계된 발행-구독(Publish-Subscribe) 기반의 초경량 메시징 프로토콜
- CoAP(Constrained Application Protocol): 8비트 마이크로컨트롤러 등 극단적으로 자원이 제약된 IoT 노드에서 HTTP RESTful 아키텍처를 UDP 상에서 가볍게 구현한 바이너리 프로토콜
- LPWAN(Low-Power Wide-Area Network): 배터리 하나로 수년 이상 동작하며, 낮은 대역폭으로 수십 km 반경까지 데이터를 전송할 수 있는 저전력 장거리 무선 통신망 (LoRa, NB-IoT)

## 핵심 통찰
- "단순 모니터링에서 지능형 사물(AIoT)로의 진화": 과거에는 센서 값을 중앙 서버로 올리기 바빴으나, 이제는 기기 자체에 초경량 NPU를 탑재해 현장에서 1차 이상을 감지하고 판단하는 지능형 사물로 진화
- 기기 주소 체계는 네트워크 구조에 따라 IPv6·게이트웨이·비IP 통신 등을 선택하며, 모든 센서에 고유한 공인 IP를 부여할 필요는 없음
- 보안이 생략된 기기의 비극: 단말 원가를 낮추기 위해 보안 칩과 암호화 모듈을 빼버린 수백만 대의 홈 CCTV, 공유기가 해킹되어 사상 최대의 디도스(DDoS) 봇넷으로 악용됨

## 이웃 토픽과 구분
- MQTT vs CoAP:
| 구분 | MQTT | CoAP |
|---|---|---|
| 전송 프로토콜 | TCP (연결 지향) | UDP (비연결 지향) |
| 아키텍처 | 중앙 브로커 기반 Pub/Sub | P2P 클라이언트/서버 (RESTful) |
| 헤더 크기 | 고정 헤더 최소 2바이트 | 고정 헤더 최소 4바이트 |
| 전송 품질(QoS) | QoS 0·1·2의 프로토콜 메시지 전달 수준; 업무 처리의 정확히 1회 보장은 별도 설계 | Confirmable(ACK 응답) / Non-confirmable |
| 적합 통신 | 1:N 대규모 실시간 푸시 이벤트 브로드캐스팅 | 1:1 센서 데이터 즉시 요청/응답 질의 |

## 문제·원인·대책
- 적용 상황: 전국 단위 상수도 원격 스마트 검침 IoT 인프라 구축
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 지하·외곽 계량기의 통신 두절 | 설치 위치별 전파 감쇄·망 음영 | 현장 측정 뒤 LoRaWAN·NB-IoT 등 적합한 망과 재전송 정책 선택 | 위치별 수신률·배터리 소비 측정 |
| 배터리 교체 비용 증가 | 보고 주기·무선 연결·전력 상태 관리 부족 | PSM·eDRX 등 절전 기능과 보고 주기 최적화 | 대상 온도·망 조건에서 수명 추정·시험 |
| 계량기 펌웨어 변조와 부정 접속 | 기본 인증·무결성 검증 부족 | 보안 부팅, 서명된 업데이트, 고유 자격정보 적용 | 변조 차단과 안전한 복구 절차 시험 |

## 내 의견
- 중요 인프라 IoT 도입 시 해당 사업의 현행 보안·조달 기준을 확인하고, 장치 식별·업데이트·네트워크 분리·이상 징후 대응을 운영 계약에 반영. MAC 주소만으로 단말 신원을 신뢰하지 않는 설계
