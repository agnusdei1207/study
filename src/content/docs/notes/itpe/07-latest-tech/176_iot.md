## 30초 인출

- **본질:** 사물의 상태를 센서로 수집하고 네트워크·플랫폼을 거쳐 서비스를 제공하는 연결 구조. 사물의 상태를 원격에서 수집·활용하고 필요할 때 제어.
- **메커니즘:** 기기 센싱 → 연결·게이트웨이 → 플랫폼 처리 → 응용·관리.

- **게이트웨이:** 기기와 플랫폼 사이의 프로토콜·데이터 연결 장치


---

## 2~4교시 25점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 사물의 상태를 센서로 수집하고 네트워크·플랫폼을 거쳐 서비스를 제공하는 연결 구조. |
| 목적 | 사물의 상태를 원격에서 수집·활용하고 필요할 때 제어 |

### Ⅱ. 핵심 구조와 적용

```text
기기 센싱 → 연결·게이트웨이 → 플랫폼 처리 → 응용·관리
```

1. **구조:** 센서·MCU → 로컬 게이트웨이 → MQTT 브로커 또는 CoAP 서버 → 스트림 처리·저장 → 운영 대시보드·제어.
2. **통신 선택:** 메시지 패턴·전원·네트워크 손실·단말 규모에 따라 프로토콜과 QoS를 결정하고 중복 수신에 대비한 응용 멱등성 설계.
3. **보안:** 기기별 신원, 초기 암호 변경, 안전한 부팅·업데이트, 전송 암호화, 수명 종료와 폐기 절차.
4. **검증:** 배터리 수명, 연결 복구 시간, 데이터 유실·중복, 취약점 조치 시간을 실제 설치 환경에서 측정.

### Ⅲ. 유사 개념과 구분

- MQTT vs CoAP:
| 구분 | MQTT | CoAP |
|---|---|---|
| 전송 프로토콜 | TCP (연결 지향) | UDP (비연결 지향) |
| 아키텍처 | 중앙 브로커 기반 Pub/Sub | P2P 클라이언트/서버 (RESTful) |
| 헤더 크기 | 고정 헤더 최소 2바이트 | 고정 헤더 최소 4바이트 |
| 전송 품질(QoS) | QoS 0·1·2의 프로토콜 메시지 전달 수준; 업무 처리의 정확히 1회 보장은 별도 설계 | Confirmable(ACK 응답) / Non-confirmable |
| 적합 통신 | 1:N 대규모 실시간 푸시 이벤트 브로드캐스팅 | 1:1 센서 데이터 즉시 요청/응답 질의 |

### Ⅳ. 문제·원인·대책

- 적용 상황: 전국 단위 상수도 원격 스마트 검침 IoT 인프라 구축
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 지하·외곽 계량기의 통신 두절 | 설치 위치별 전파 감쇄·망 음영 | 현장 측정 뒤 LoRaWAN·NB-IoT 등 적합한 망과 재전송 정책 선택 | 위치별 수신률·배터리 소비 측정 |
| 배터리 교체 비용 증가 | 보고 주기·무선 연결·전력 상태 관리 부족 | PSM·eDRX 등 절전 기능과 보고 주기 최적화 | 대상 온도·망 조건에서 수명 추정·시험 |
| 계량기 펌웨어 변조와 부정 접속 | 기본 인증·무결성 검증 부족 | 보안 부팅, 서명된 업데이트, 고유 자격정보 적용 | 변조 차단과 안전한 복구 절차 시험 |

### Ⅴ. 제언

- 중요 인프라 IoT 도입 시 해당 사업의 현행 보안·조달 기준을 확인하고, 장치 식별·업데이트·네트워크 분리·이상 징후 대응을 운영 계약에 반영. MAC 주소만으로 단말 신원을 신뢰하지 않는 설계
