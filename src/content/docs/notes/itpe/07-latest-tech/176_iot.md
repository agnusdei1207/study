## Ⅰ. 사물인터넷(IoT)의 개요

- **개념** : 유무선 통신망으로 연결된 사물들이 센서와 액추에이터를 통해 데이터를 상호 공유하고, 클라우드 및 엣지 플랫폼과 연계하여 자율적 인지와 제어를 수행하는 지능형 인프라.
- **배경 및 필요성** : 대규모 단말 확장에 따른 전력 소모 및 보안 취약점 병목을 극복하기 위해 하드웨어 기반 신뢰 루트(RoT)와 저전력 슬립 모드(PSM/eDRX)를 결합한 전주기 기기 생애주기 관리 체계 필수.
- **핵심 목적** : 실시간 원격 상태 감시, 분산 자산 관리, 공정 최적화 및 스마트홈·시티·공장 등 지능형 융합 서비스 제공.

## Ⅱ. 사물인터넷(IoT)의 핵심 아키텍처 및 동작 메커니즘

사물인터넷은 신뢰할 수 있는 데이터 파이프라인과 고도화된 추론 메커니즘을 기반으로 동작하며, 세부적인 아키텍처와 핵심 컴포넌트 간 상호작용 프로세스는 다음과 같음.

```text
+-------------------------------------------------------------------------------+
| [서비스 계층]  스마트 팩토리, 원격 헬스케어, 스마트 시티, 지능형 에너지 관리  |
|               - 실시간 운영 대시보드, 이상 탐지 알람, AI 예지 보전 모델 연동  |
+-------------------------------------------------------------------------------+
                                      ▲
| [플랫폼 계층]  데이터 수집/브로커, 디바이스 관리, 시계열 저장소, 스트림 처리  |
|               - MQTT Broker, Kafka Cluster, InfluxDB, FOTA 오케스트레이터     |
+-------------------------------------------------------------------------------+
                                      ▲
| [네트워크 계층] 초저전력 광역망(LPWAN), 5G RedCap, Wi-Fi, BLE, 산업용 이더넷  |
|               - LoRaWAN, NB-IoT, Cellular 5G/6G, IPv6 over 6LoWPAN, Routing   |
+-------------------------------------------------------------------------------+
                                      ▲
| [디바이스 계층] 스마트 센서, 액추에이터, 저전력 마이크로컨트롤러(MCU), 엣지   |
|               - 온·습도/진동/전류 계측, 릴레이/서보 제어, 하드웨어 RoT 보안 칩|
+-------------------------------------------------------------------------------+
```

- **디바이스 계층** : MEMS 센서, Cortex-M MCU, TPM/HSM, BLE/Zigbee 모듈 - 물리 신호의 디지털 변환, 원천 데이터 샘플링, 하드웨어 보안 부팅 수행.
- **네트워크 계층** : LoRaWAN, NB-IoT, 6LoWPAN, 5G NR RedCap, RPL - 패킷 크기 압축, 저전력 라우팅, 유무선 게이트웨이 간 프로토콜 중계.
- **플랫폼 계층** : EMQX, Apache Pulsar, Redis, TimescaleDB, ThingsBoard - 수천만 동시 접속 세션 관리, 메시지 QoS 제어, 데이터 파이프라인 정제.
- **서비스 계층** : Open API, RESTful API, Grafana, ML 추론 엔진 - 산업 도메인별 규칙 엔진 실행, 원격 명령 하달, 분석 결과 시각화.

## Ⅲ. 사물인터넷(IoT)의 세부 구성 요소 및 비교 분석

| 비교 항목 | MQTT (Message Queuing Telemetry Transport) | CoAP (Constrained Application Protocol) |
|---|---|---|
| **전송 계층 프로토콜** | TCP (Transmission Control Protocol) | UDP (User Datagram Protocol) |
| **통신 아키텍처** | 발행/구독 (Pub/Sub, 중앙 브로커 중계) | 클라이언트/서버 (RESTful 요청/응답, P2P 지원) |
| **메시지 헤더 크기** | 최소 2 Byte (매우 경량화) | 고정 4 Byte (옵션 필드 포함 시 가변) |
| **서비스 품질 (QoS)** | 3단계 보장 (QoS 0: 최대 1회, QoS 1: 최소 1회, QoS 2: 정확히 1회) | 2단계 보장 (Confirmable: ACK 요구, Non-Confirmable: ACK 없음) |
| **상태 관리** | 연결 지향적 (Keep-Alive 세션 유지) | 비연결형 (Stateless 트랜잭션, 메모리 소모 극소화) |
| **보안 메커니즘** | TLS/SSL 기반 전송 계층 암호화 | DTLS (Datagram TLS) 기반 암호화 |
| **주요 적용 도메인** | 지속적 상태 스트리밍, 대규모 데이터 모니터링 | 초저전력 배터리 노드, 간헐적 보고 및 직접 기기 제어 |

- 사물인터넷은 상기 비교 지표를 바탕으로 비즈니스 요구사항과 운영 인프라 환경을 고려한 최적의 아키텍처를 선정하고, 확장성과 안정성을 균형 있게 확보해야 함.

## Ⅳ. 사물인터넷(IoT)의 주요 한계점 및 해결 방안

- **배터리 수명 고갈 및 현장 교체 유지보수 한계** :
  - **한계점** : 잦은 네트워크 폴링 및 무선 송수신(Tx) 상태 유지로 배터리 조기 소진.
  - **해결 방안** : 무선 절전 프로파일 및 이벤트 트리거 전송 적용 - 3GPP 표준 PSM(Power Saving Mode) 및 eDRX(extended Discontinuous Reception) 파라미터 최적화. - 주기적 전송 대신 임계치 초과 시에만 전송하는 이벤트 기반 인터럽트 구동.
- **하드웨어 제약으로 인한 암호화 및 보안 엔진 부재** :
  - **한계점** : 단말 MCU의 계산 및 메모리 제약으로 무거운 RSA/TLS 연산 불가, 패킷 스니핑 노출.
  - **해결 방안** : 경량 암호 알고리즘 및 하드웨어 RoT 칩 실장 - 국내 표준 경량 암호 LEA, HIGHT 및 경량 해시 LSH 도입. - 기기 고유 물리적 복제 방지 기능(PUF: Physically Uncloneable Function) 내장 보안 칩 채택.
- **대규모 단말의 안전한 펌웨어 업데이트 및 무결성 보증 실패** :
  - **한계점** : 배포 중 패킷 유실로 단말 벽돌(Bricking) 현상 발생 및 악성 펌웨어 주입 위험.
  - **해결 방안** : A/B 듀얼 뱅크 파티셔닝 및 디지털 서명 FOTA 구축 - 롤백 가능한 듀얼 뱅크 플래시 메모리 구조 설계로 업데이트 실패 시 즉시 자동 복원. - ECDSA 전자서명 검증을 통한 무결성 확인 후 설치하는 보안 부트로더 적용.

## Ⅴ. 사물인터넷(IoT) 적용 및 발전을 위한 기술사적 제언

- **배터리 수명 고도화 및 장기 배터리 수명 추진** : 보고 주기 기준 배터리 소모 전력 계측의 한계를 탈피하고, 단일 배터리로 장기 동작 보장을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- **통신 복원력 고도화 및 지수 백오프 적용 추진** : 기지국 일시 단절 후 재연결 및 백오프(Backoff) 알고리즘의 한계를 탈피하고, 지수 백오프 적용, 브로드캐스트 스톰 방지를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- **데이터 정합성 고도화 및 메시지 ID 기반 추진** : QoS 1/2 적용 시 중복 수신 메시지의 멱등성(Idempotency)의 한계를 탈피하고, 메시지 ID 기반 중복 처리 방지를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
