## 연관 키워드

- MoE(Mixture of Experts), 전문가 혼합 모델, 희소 모델(Sparse Model)
- 게이팅 네트워크(Gating Network), Top-k 라우팅, 공유 전문가(Shared Expert)
- 로드 밸런싱(Load Balancing), 라우팅 붕괴(Routing Collapse), 전문가 병렬성(Expert Parallelism)
- Mixtral 8x7B, DeepSeek-V3, 활성 파라미터(Active Parameter)

## Ⅰ. MoE(Mixture of Experts)의 개요

- 핵심 요약 : 토큰마다 일부 전문가만 활성화해 전체 용량은 키우고 연산량은 낮추는 희소 신경망 구조.
- 개념 : 트랜스포머의 피드포워드 네트워크(FFN, Feed-Forward Network) 계층을 여러 **전문가** (Expert) 서브 네트워크로 나누고, **게이팅 네트워크** (Gating Network)가 입력 토큰마다 상위 소수의 전문가만 골라 계산에 참여시키는 **조건부 연산** (Conditional Computation) 구조.
- 배경 및 필요성 : 모든 파라미터가 매 토큰에 쓰이는 고밀도(Dense) 모델은 규모를 키울수록 연산량과 GPU(Graphics Processing Unit) 메모리 비용이 함께 늘어난다. 이를 피하면서 모델 용량을 키우려는 요구에 따라 MoE가 확산되었다.
- 대표 사례 : Mixtral 8x7B(Mistral AI)는 총 약 46.7B 파라미터 중 토큰당 약 13B만 활성화한다고 알려져 있다. DeepSeek-V3는 총 671B 파라미터 중 토큰당 약 37B를 활성화하는 구조로 기술 보고서에 공개되었다.
- 주요 목적 : 용량 확대와 추론 연산 절감의 동시 달성, 전문가별 분업을 통한 성능 향상.

## Ⅱ. MoE(Mixture of Experts)의 특징 및 장점

- 핵심 요약 : 희소 활성화가 연산 절감으로, 전문가 분업이 성능 다양성으로 이어지는 구조.

1. 희소 활성화 : 토큰마다 Top-k 전문가만 계산 → 전체 파라미터 대비 적은 연산으로 추론 가능.
2. 용량 확장 : 전문가 수를 늘려 총 파라미터를 키움 → 지식 저장 용량이 커져 다방면 과제 대응력 향상.
3. 전문가 분업 : 입력 유형에 따라 다른 전문가가 처리 → 특화 영역에서 품질 개선 기대.
4. 공유 전문가 : 모든 토큰이 거치는 공통 전문가를 둠 → 공통 지식의 중복 학습 감소.

```text
[ 토큰 한 개의 경로 ]

입력 토큰
   ├─ 공유 전문가 → 항상 계산
   └─ 라우터 → 상위 k개 전문가만 계산
          ↓
      출력 합산
```

## Ⅲ. MoE(Mixture of Experts)의 구조 (흐름)

- 핵심 요약 : 어텐션 뒤 FFN 자리에서 라우터가 점수를 매겨 상위 전문가의 출력을 가중 합산하는 구조.

```text
[ 입력 토큰 벡터 x ]
          ↓
[ 게이팅 네트워크 ]
  점수 = Softmax(W_g · x)
  상위 k개 전문가 선택
          ↓
[ 선택된 전문가만 계산 ]
  Expert 1 (가중치 g1)
  Expert 3 (가중치 g3)
          ↓
[ 가중 합산 ]
  y = Σ g_i · E_i(x)
```

- **Top-k 희소 활성화** : N개 전문가 중 점수가 높은 1~2개만 계산하고 나머지는 생략한다.
- **보조 로드 밸런싱 손실** (Auxiliary Load Balancing Loss) : 특정 전문가에게 토큰이 쏠리지 않도록 할당을 균등화하는 정규화 항.
- **전문가 병렬성** (Expert Parallelism) : 전문가를 여러 GPU에 나눠 두고, 토큰을 All-to-All 통신으로 해당 전문가에게 보낸다.

## Ⅳ. MoE(Mixture of Experts)와 고밀도 모델의 비교

- 핵심 요약 : MoE는 연산 효율에서 강하지만, 메모리와 통신 인프라에서 부담이 커 시스템 설계가 성패를 가른다.

| 비교 항목 | 고밀도 모델 (Dense) | 희소 MoE (Sparse) |
| --- | --- | --- |
| 파라미터 활성화 | 모든 토큰이 전체 파라미터 사용 | 토큰마다 일부 전문가만 사용 |
| 연산량 | 파라미터 수에 비례해 증가 | 총 파라미터 대비 적은 연산 |
| 메모리 요구 | 활성 파라미터 크기만큼 필요 | 전체 전문가 가중치를 메모리에 상주 |
| 학습 안정성 | 수렴 예측이 비교적 쉬움 | 라우팅 붕괴 위험, 튜닝 복잡 |
| 대표 모델 | Llama 3 70B | Mixtral 8x7B, DeepSeek-V3 |

- DeepSeek-V3는 세분화된 전문가와 공유 전문가를 함께 쓰고, 보조 손실 없이 부하를 조절하는 방식을 채택했다고 보고되었다.

## Ⅴ. MoE(Mixture of Experts)의 한계와 방안

- 핵심 요약 : 라우팅 쏠림, 메모리 병목, 노드 간 통신 지연을 부하 제어와 양자화, 통신 중첩으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 라우팅 붕괴 | 일부 전문가만 학습되고 나머지는 사장됨 | 보조 로드 밸런싱 손실, 전문가 용량 제한 **Capacity Factor**, 공유 전문가 분리 | 전문가별 토큰 점유율 |
| 메모리 병목 | 전체 전문가를 메모리에 올려야 함 → 고가 GPU 필요 | 가중치 양자화(INT4, FP8), 비활성 전문가의 CPU 메모리 오프로딩 | GPU 메모리 사용량 |
| 통신 병목 | 전문가가 여러 노드에 분산되어 All-to-All 지연 발생 | 노드 내 고속 링크 활용, 연산과 통신 중첩(**DualPipe** 류) | 토큰당 통신 시간 |

## Ⅵ. MoE(Mixture of Experts)의 기술사적 제언

- 핵심 요약 : 서빙 비용과 인프라 여건에 따라 MoE와 고밀도 모델을 고르고, 미세 조정 전략도 구조에 맞춰야 한다.

1. 서빙 비용 기준 선택 : 동일 품질에서 토큰당 연산 비용이 더 낮은 쪽을 기준으로, 대형 고밀도 모델 대신 MoE 계열을 후보에 둔다. 단, 메모리 용량 검토를 함께 한다.
2. 인프라 선행 점검 : 전체 전문가를 상주시킬 메모리와 노드 간 고속 통신 환경을 먼저 확인하고, 온프레미스에서는 양자화 배포를 전제로 설계한다.
3. 파인튜닝 전략 : 사내 특화 학습 시 라우터는 고정하고 전문가 내부에만 LoRA(Low-Rank Adaptation) 같은 경량 어댑터를 붙여 학습 안정성을 확보한다.

## Ⅶ. 결론

- 핵심 요약 : MoE는 희소 활성화로 모델 용량과 연산 효율을 함께 얻는 구조다.
- 시사점 : 연산 절감의 대가로 메모리와 통신 부담이 커지므로, 모델 선택은 연산과 인프라를 합친 **총소유비용** (TCO, Total Cost of Ownership) 관점에서 이루어져야 한다.
