## 답안 골격
```text
[MoE] ◀━━ 머리: Ⅶ 내 의견 (부하 균형 보조 손실과 공유 전문가(Shared Expert)를 결합한 초고효율 추론 인프라)
 ┃
 ┣━ Ⅰ 개요 ───── 모든 파라미터를 활성화하는 밀집(Dense) 모델의 연산 비용 폭증 → 조건부 희소 연산으로 효율화
 ┣━ Ⅱ 특징 ───── 희소 활성화(Sparsity) · 총 파라미터 대비 저연산량(FLOPs 절감) · 게이팅 네트워크 기반 동적 라우팅
 ┣━ Ⅲ 구조 ───── 라우터(Gating Network) + 다중 전문가 FFN(Experts) + 공유 전문가(Shared Experts)
 ┣━ Ⅳ 흐름 ───── ① 입력 토큰 수신 → ② 라우터가 토큰별 최적 Top-K 전문가 선정 → ③ 선택된 FFN만 연산 → ④ 출력 가중합
 ┣━ Ⅴ 비교 ───── 밀집 모델(Dense) vs 희소 MoE 모델 (모든 가중치 연산 vs 10~20% 활성 가중치만 연산)
 ┗━ Ⅵ 실무 ───── 라우팅 부하 불균형(Load Imbalance) / VRAM 메모리 상주 요구량(Footprint) 과다 / All-to-All 통신 지연
```
- 필수 키워드: 희소 활성화(Sparse Activation) · 게이팅 네트워크(Router) · Top-K 라우팅 · 전문가 FFN · 부하 불균형(Load Imbalance) · 보조 손실
- 기출: 137회 1교시 7번 `트랜스포머(Transformer)와 MoE(Mixture of Experts)를 설명하시오.` → Ⅰ~Ⅴ

## 한 줄 본질
- 모델 파라미터를 늘릴수록 비례하여 치솟는 추론 연산량(FLOPs)과 전기세 한계 → 입력 토큰의 성격에 따라 가장 적합한 소수의 전문가(Top-K FFN) 서브네트워크만 선별 활성화 → 거대 파라미터 용량과 초고속 추론 속도 동시 달성 / 전체 가중치를 VRAM에 유지해야 하는 메모리 비용 수반

## 핵심 그림
```text
[MoE 레이어 동작 구조]
                   [ 입력 토큰 (Token x) ]
                             |
         +-------------------+-------------------+
         |                                       |
         v                                       v
+------------------+                    +------------------+
| 게이팅 네트워크  |                    | 공유 전문가      |
| (Router Gating)  |                    | (Shared Expert)  |
+------------------+                    +--------+---------+
         | Top-2 확률 가중치 (G_1, G_2)          |
         v                                       |
  +--------------+  (나머지 비활성화)            |
  | Expert 1 FFN | <--- 활성화                   |
  +--------------+                               |
  | Expert 2 FFN | <--- 비활성 (연산 생략)       |
  +--------------+                               |
  | Expert 3 FFN | <--- 활성화                   |
  +--------------+                               |
         \                                      /
          \---> [ 가중 합산: G_1*E_1 + G_2*E_3 + Shared ] ===> 출력
```

## 핵심 용어
- 활성 파라미터(Active Parameters): 전체 모델 가중치 중 특정 토큰을 처리하기 위해 실제로 순전파 연산에 참여하는 파라미터 수(예: Mixtral 8x7B는 총 47B 중 활성 13B)
- Top-K 게이팅(Gating): 입력 벡터와 라우터 가중치의 내적에 소프트맥스를 취해 가장 점수가 높은 상위 $K$개의 전문가에만 토큰을 할당하는 기법
- 부하 불균형(Load Imbalance): 라우터가 특정 소수의 전문가에게만 대부분의 토큰을 몰아주어 다른 전문가들이 놀고 병목이 생기는 붕괴 현상

## 핵심 통찰
- MoE는 모델의 "지식 용량(Memory Capacity)"과 "연산 비용(Compute Cost)"을 디커플링(Decoupling)한 혁신
- 연산량(FLOPs)은 활성 파라미터만큼만 들지만, 모델 서빙을 위해서는 총 파라미터(Total Parameters) 전체가 VRAM에 적재되어야 하므로 GPU 메모리 요구량은 Dense 모델과 동일
- 분산 GPU 환경에서 서로 다른 노드에 분산된 전문가로 토큰을 보내고 모으는 All-to-All 통신 오버헤드가 추론 지연을 유발하므로 네트워크 패브릭(InfiniBand)이 필수

## 이웃 토픽과 구분
- MoE vs 앙상블(Ensemble): 앙상블은 독립적으로 학습된 여러 모델의 전체 출력을 결합 / MoE는 단일 신경망 모델 내부의 FFN 계층을 전문가 단위로 나누어 엔드투엔드로 동시 학습

## 문제·원인·대책
- 적용 상황: MoE 기반 거대 LLM 분산 서빙 클러스터 운영 중 특정 GPU 병목 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 특정 1~2개 전문가로 토큰 쏠림(과부하) | 라우터의 초기 학습 편향 및 Winner-Take-All 붕괴 | 보조 손실(Auxiliary Loss: 전문가 간 균등 분배 페널티) 적용 | 전문가별 처리 부하 균등화 및 연산 자원 낭비 제거 |
| 분산 GPU 간 토큰 전송 시 네트워크 병목 | Expert Parallelism 적용 시 노드 간 All-to-All 통신 폭증 | DeepSeek 식 무손실 라우팅 및 노드 내 전문가 집중 배치 | 노드 간 통신량 최소화 및 추론 지연시간 단축 |
| 일반 상식 및 공통 지식의 분산 유실 | 모든 토큰을 전문화된 FFN으로만 분기하여 공통 기반 지식 부족 | 공유 전문가(Shared Experts)를 상시 활성화하여 병행 연산 | 도메인 전문성과 일반 언어 표현력 동시 확보 |
