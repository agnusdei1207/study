## 30초 인출

- 본질: **MoE(Mixture of Experts, 전문가 혼합)** 는 전체 신경망 파라미터를 고정적으로 모두 계산하지 않고, 게이팅 라우터(Gating Router)가 입력 토큰마다 가장 적합한 소수의 상위 전문가(Expert FFN) 네트워크만을 동적으로 선택해 활성화하는 조건부 희소 연산(Sparse Computation) 기술
- 메커니즘: 토큰 임베딩 입력 시 라우터 소프트맥스 확률로 Top-K 전문가를 선별하고, 선택된 전문가 FFN 연산 결과를 라우팅 가중치로 가중합하여 다음 레이어로 전파
- 통찰: 특정 전문가로의 토큰 쏠림(Expert Bottleneck)과 분산 GPU 간 All-to-All 통신 지연이 발생하므로 보조 손실(Auxiliary Loss) 기반 부하 분산 및 전문가 병렬성(EP) 최적화 필수

<details><summary>핵심 용어</summary>

- **MoE (Mixture of Experts)** : 전체 모델 용량(Capacity)은 조 단위로 키우면서도 실제 추론 시의 FLOPs 연산 비용은 소형 모델 수준으로 유지하는 희소 신경망 구조.
- **게이팅 네트워크 (Gating/Router)** : 입력 토큰 벡터를 분석하여 $N$개의 전문가 중 가장 관련성이 높은 Top-K 전문가 인덱스와 가중치를 결정하는 분류기.
- **전문가 (Expert FFN)** : 트랜스포머 블록 내의 피드포워드 신경망(FFN)을 독립적인 $N$개의 병렬 모듈로 분할한 하위 신경망.
- **희소 활성화 (Sparse Activation)** : 전체 전문가 중 1~2개(예: Top-2)만 선택적으로 가동하여 추론 전력과 연산량을 획기적으로 절감하는 메커니즘.
- **All-to-All 통신** : 다중 GPU 클러스터에서 각 GPU에 분산 배치된 전문가에게 토큰을 라우팅하고 수합하기 위해 노드 간에 전송하는 대규모 All-to-All 통신 프리미티브.

</details>

## 2~4교시 25점 답안

## Ⅰ. MoE의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **MoE(Mixture of Experts)** 는 트랜스포머의 무거운 피드포워드 신경망(FFN) 층을 다수의 독립된 전문가(Expert) 서브 네트워크로 분할하고, 게이팅 네트워크(Router)를 통해 입력 토큰별로 가장 적합한 일부 전문가만 조건부 활성화(Conditional Activation)하는 딥러닝 아키텍처 |
| 목적 | 총 파라미터 수(지식 저장 용량)를 수천억~조 단위로 극대화하면서도 추론 시 활성 파라미터(Active Parameters)와 연산량을 수십억 단위로 억제하여 비용 대비 성능 극대화 |

## Ⅱ. MoE의 핵심 특징 및 밀집(Dense) 모델 대비 차별점

| 구분 | MoE의 핵심 특징 | 세부 공학적 메커니즘 및 속성 |
|---|---|---|
| **파라미터와 연산량의 디커플링** | 용량 확장 대비 저연산 유지 | 총 파라미터는 671B(DeepSeek)이나 실제 토큰당 활성 파라미터는 37B에 불과하여 고속 추론 가능 |
| **전문성 분업화 (Specialization)** | 도메인별 가중치 특화 | 코딩, 수학, 번역, 문법 등 토큰 유형에 따라 서로 다른 전문가 FFN이 분담 처리 |
| **조건부 계산 (Conditional Computation)** | 입력 적응형 동적 경로 | 모든 입력에 동일한 가중치를 통과시키는 정적 구조를 탈피하여 토큰별 최적의 연산 경로 동적 결정 |
| **확장성 (Scalability)** | 전문가 수 $N$의 선형 확장 | 전문가 개수를 8개, 64개, 256개로 늘릴수록 추가 연산 부하 없이 모델 지식 표현력 선형적 증가 |

## Ⅲ. MoE 조건부 희소 연산 아키텍처 및 라우팅 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ MoE 트랜스포머 레이어 및 라우팅 체계도 ]             │
└────────────────────────────────────────────────────────────────────────┘
                                    │
 [ 입력 토큰 임베딩 x ] ──► [ Multi-Head Self-Attention ] ──► [ 토큰 벡터 x' ]
                                                               │
                                ┌──────────────────────────────┴──────────────┐
                                ▼                                             ▼
                 [ 게이팅 네트워크 (Router) ]                       [ 토큰 디스패치 ]
                 - 게이팅 확률 G(x) = Softmax(TopK(x·W_g + ε))                │
                 - 상위 2개 전문가 선별 (Top-2: Expert 1, Expert 4)            │
                                │                                             │
                                └──────────────────────┬──────────────────────┘
                                                       │
 ┌─────────────────────────────────────────────────────┴─────────────────────────────────────────────────────┐
 │ [ 분산 배치된 N개의 전문가 (Expert FFN Pool) ]                                                           │
 │  ┌─────────────────┐   ┌─────────────────┐   ┌─────────────────┐   ┌─────────────────┐                    │
 │  │ Expert 1 (활성) │   │ Expert 2 (비활성)│  │ Expert 3 (비활성)│  │ Expert 4 (활성) │   ... Expert N     │
 │  │ FFN_1(x')       │   │ (연산 생략: 0)  │   │ (연산 생략: 0)  │   │ FFN_4(x')       │   (비활성)         │
 │  └────────┬────────┘   └─────────────────┘   └─────────────────┘   └────────┬────────┘                    │
 └───────────┼─────────────────────────────────────────────────────────────────┼─────────────────────────────┘
             │                                                                 │
             ▼ (가중치 G_1)                                                    ▼ (가중치 G_4)
┌────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ [ 출력 가중 결합 (Weighted Combination) ]                                                                 │
│   최종 출력 y = G_1 · FFN_1(x') + G_4 · FFN_4(x') ──> [ 다음 트랜스포머 블록으로 전파 ]                   │
└────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

| 라우팅 컴포넌트 | 수학적 수식 | 공학적 의미 및 역할 |
|---|---|---|
| **게이팅 점수 계산** | $H(x)_i = (x \cdot W_g)_i + \text{StandardNormal}() \cdot \text{Softplus}((x \cdot W_{\text{noise}})_i)$ | 가우시안 노이즈를 결합하여 탐색 다양성 확보 |
| **Top-K 선택** | $\text{KeepTopK}(v, k)_i = v_i \text{ if } v_i \in \text{TopK}(v) \text{ else } -\infty$ | 상위 $K$개(통상 $K=1 \text{ or } 2$)를 제외한 나머지 소프트맥스 입력 음의 무한대화 |
| **최종 가중치** | $G(x) = \text{Softmax}(\text{KeepTopK}(H(x), k))$ | 선택된 전문가 간의 가중치 합이 1이 되도록 정규화 |
| **최종 출력 산출** | $y = \sum_{i \in \text{TopK}} G(x)_i \cdot E_i(x)$ | 비활성 전문가의 연산을 완전 생략하여 하드웨어 가속 달성 |

## Ⅳ. 밀집(Dense) 모델 vs 희소(Sparse) MoE 모델 비교

| 비교 항목 | 전통적 밀집 모델 (Dense Model) | 희소 전문가 혼합 모델 (Sparse MoE) |
|---|---|---|
| **연산 방식** | 모든 토큰이 100% 모든 가중치 통과 | 토큰별로 상위 $K$개(약 5~10%) 전문가만 통과 |
| **파라미터 효율** | 모델 크기 증가 시 추론 FLOPs 정비례 증가 | 총 파라미터는 수배 증가해도 추론 FLOPs는 고정 |
| **GPU 메모리 요구** | 모델 가중치에 비례하는 정직한 VRAM 소모 | 활성 연산은 적으나 전체 가중치 적재용 대용량 VRAM 필수 |
| **분산 병렬성** | 텐서 병렬성(TP), 파이프라인 병렬성(PP) | 전문가 병렬성(EP) 및 극심한 All-to-All 통신 발생 |
| **대표 모델** | Llama 3 70B, GPT-3 175B | Mixtral 8x7B, Mixtral 8x22B, DeepSeek-V3 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 특정 전문가에게만 대부분의 토큰이 몰려 병목이 발생하고 나머지 전문가는 유휴화되는 전문가 붕괴(Expert Collapse) | 전문가별 토큰 할당 빈도의 분산을 최소화하는 보조 부하 균형 손실(Auxiliary Load Balancing Loss)을 목적함수에 추가 |
| 다중 GPU 클러스터 환경에서 전문가 간 토큰을 전송할 때 발생하는 막대한 All-to-All 네트워크 통신 병목 | 노드 간 토큰 이동을 최소화하는 계층적 라우팅(Hierarchical Routing) 및 InfiniBand RoCEv2 기반 통신-연산 오버랩(Overlap) 적용 |

## Ⅵ. 제언

추론 서빙 시 VRAM 점유 한계를 극복하기 위해, 빈번히 호출되는 핫(Hot) 전문가는 고속 GPU HBM에 상주시키고 콜드(Cold) 전문가는 호스트 메모리에 오프로딩하는 동적 전문가 캐싱(Expert Caching) 아키텍처 구축.

```text
[ 입력 토큰 스트림 인입 ]
             │
             ▼
[ 라우터 예측 및 전문가 캐시 관리자 (Dynamic Expert Cache) ]
   ├── Step 1: 상위 20% 빈출 전문가는 GPU VRAM에 고정 상주 (Hot Experts)
   ├── Step 2: 하위 80% 희귀 전문가는 PCIe 5.0 기반 호스트 NVMe에서 동적 프리페치
   └── Step 3: vLLM 연계 전문가 단위 PagedAttention 스케줄링
             │
             ▼
[ 단일 노드 4-GPU 환경에서 8x7B MoE 모델의 초당 100 토큰 초고속 서빙 달성 ]
```

| 구분 | 전체 전문가 VRAM 무조건 적재 | 제언: 동적 전문가 캐싱 서빙 |
|---|---|---|
| **필요 하드웨어** | 80GB H100 8장 필수 (수억 원 소요) | 24GB RTX 4090 4장으로 서빙 가능 |
| **서빙 처리량** | 메모리 부족으로 동시 배치(Batch) 제약 | VRAM 절감으로 대규모 동시 요청 배치 처리 |
| **에너지 효율** | 8개 GPU 상시 풀가동 전력 낭비 | 활성 GPU만 선별 가동하여 TCO 60% 절감 |
