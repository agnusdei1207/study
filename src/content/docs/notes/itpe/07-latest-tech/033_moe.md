## Ⅰ. MoE(Mixture of Experts)의 개요

- **개념** : 심층 신경망 트랜스포머의 피드포워드 네트워크(FFN) 계층을 다수의 독립적인 전문가(Expert) 서브 네트워크로 분할하고, 입력 토큰마다 라우팅 게이팅 네트워크(Gating Network)가 최적의 소수 전문가(Top-k)만 동적으로 선택하여 연산에 참여시키는 조건부 연산(Conditional Computation) 희소(Sparse) 모델 아키텍처.
- **배경 및 필요성** : 모델의 모든 파라미터가 매 토큰마다 활성화되는 고밀도(Dense) 모델은 파라미터를 키울수록 연산량(FLOPs)과 GPU VRAM 비용이 지수적으로 증가하므로, 모델 용량(Capacity)은 조 단위로 확장하면서도 추론 연산 비용을 획기적으로 낮추기 위해 Mixtral, GPT-4, DeepSeek-V3 등 프론티어 AI의 핵심 구조로 채택됨.
- **핵심 목적** : 모델 파라미터 용량의 극대화, 토큰당 추론 연산량(FLOPs) 및 서빙 지연 시간 대폭 절감, 도메인별 특화 전문가 분업을 통한 다방면 태스크 성능 향상.

## Ⅱ. MoE(Mixture of Experts)의 핵심 아키텍처 및 동작 메커니즘

MoE는 셀프 어텐션 계층 이후 FFN 계층에서 라우터가 입력 벡터를 평가하여 상위 k개의 전문가를 선별하고 가중 합산하는 방식으로 동작함.

```text
[ Sparse MoE 트랜스포머 레이어 및 라우팅 구조 ]

                      입력 토큰 벡터 (x)
                             │
         ┌───────────────────┴───────────────────┐
         │                                       │
         ▼                                       │
+-----------------------------------+            │
| 라우터 / 게이팅 네트워크 (Gating) |            │
|  - G(x) = TopK( Softmax(W_g · x) )|            │
|  - 상위 Top-2 전문가 선별          │            │
+-----------------┬-----------------+            │
                  │ 게이팅 가중치 (g_1, g_2)     │
                  ▼                              ▼
+-----------------------------------------------------------------+
| 전문가 풀 (Expert FFN Pool : E_1, E_2, ... E_N)                 |
|                                                                 |
|   [ Expert 1 ]      [ Expert 2 ]      [ Expert 3 ] ... [ Expert N ]
|   (활성화: g_1)     (비활성화 0)      (활성화: g_2)    (비활성화 0)
|        │                                   │                    |
|        ▼                                   ▼                    |
|    E_1(x)                                E_3(x)                 |
+--------┬───────────────────────────────────┬────────────────----+
         │                                   │
         └─────────────────►(+)◄─────────────┘
                            ▲
                            │ 최종 출력 y = Σ g_i * E_i(x)
```

- **소프트맥스 게이팅(Softmax Gating)** : 입력 토큰 `x`와 라우터 가중치 `W_g`의 내적 후 소프트맥스를 취해 각 전문가에 대한 확률 점수 산출.
- **Top-k 희소 활성화(Sparse Activation)** : 전체 N개의 전문가(예: 8개 또는 64개) 중 가장 점수가 높은 1~2개(Top-1 또는 Top-2) 전문가만 활성화하고 나머지는 계산을 생략하여 FLOPs 절감.
- **보조 로드 밸런싱 손실(Auxiliary Load Balancing Loss)** : 특정 스타 전문가에게만 모든 토큰이 몰리는 쏠림 현상을 방지하기 위해 전문가별 토큰 할당량을 균등하게 분산시키는 정규화 손실 추가.
- **전문가 병렬성(Expert Parallelism, EP)** : 수십 개의 전문가 FFN을 여러 GPU 노드에 분산 배치하고 All-to-All 통신을 통해 토큰을 라우팅.

## Ⅲ. MoE(Mixture of Experts)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 고밀도 모델 (Dense Model) | 희소 MoE 모델 (Sparse MoE) | 최신 파인그레인 MoE (DeepSeek-V3) |
| --- | --- | --- | --- |
| **파라미터 활성화 방식** | 모든 토큰에 대해 100% 파라미터 활성화 | 입력 토큰마다 상위 1~2개 전문가만 선택 활성화 | 다수의 소형 전문가(Fine-grained) + 공유 전문가(Shared) |
| **추론 속도 및 FLOPs** | 파라미터 수에 정비례하여 연산량 증가 | 총 파라미터 대비 1/4 ~ 1/8 수준의 연산량만 소비 | 극도로 세분화된 전문가 라우팅으로 연산 효율 극대화 |
| **메모리(VRAM) 요구량** | 활성 파라미터 크기만큼의 VRAM 필요 | 전체 전문가 가중치를 모두 GPU VRAM에 로드 필요 | 대규모 분산 메모리 필요, 양자화(FP8) 필수 결합 |
| **학습 안정성** | 안정적이고 손실 곡선 수렴 예측 용이 | 라우팅 붕괴(Routing Collapse) 위험, 튜닝 복잡 | 로드 밸런싱 프리 알고리즘으로 안정적 대규모 학습 |
| **대표 모델** | Llama 3 70B, GPT-3 | Mixtral 8x7B, Mixtral 8x22B | DeepSeek-V3 (671B 총, 37B 활성화) |

- MoE는 '연산 효율성' 측면에서는 Dense 모델을 압도하지만, '메모리 대역폭 및 VRAM 용량' 측면에서는 전체 전문가를 상주시켜야 하므로 시스템 인프라 엔지니어링이 성패를 가름.

## Ⅳ. MoE(Mixture of Experts)의 주요 한계점 및 해결 방안

- **특정 인기 전문가로 토큰이 집중되는 라우팅 붕괴(Routing Collapse)** :
  - **한계점** : 학습 초기에 우연히 잘 학습된 소수 전문가에게만 라우터가 토큰을 몰아주어 나머지 전문가가 사장됨.
  - **해결 방안** : 보조 로드 밸런싱 손실 함수 적용, 전문가 용량 한계(Capacity Factor) 강제 설정 및 공유 전문가(Shared Experts) 분리.
- **추론 연산량은 낮으나 전체 파라미터를 VRAM에 올려야 하는 메모리 병목** :
  - **한계점** : 예컨대 총 671B 모델 서빙 시 수백 GB 이상의 고가 GPU 클러스터가 필수적이어서 온프레미스 배포 난제.
  - **해결 방안** : 비활성 전문가의 호스트 CPU RAM 동적 오프로딩, INT4/FP8 가중치 양자화, vLLM의 전문가 병렬성 최적화.
- **분산 노드 간 토큰 교환 시 발생하는 All-to-All 네트워크 통신 병목** :
  - **한계점** : 서로 다른 GPU에 분산된 전문가에게 토큰을 전달하는 과정에서 인피니밴드/RoCE 통신 지연 발생.
  - **해결 방안** : 노드 내 NVLink 활용 극대화, 통신과 연산을 중첩(Overlap)하는 DualPipe 아키텍처 적용.

## Ⅴ. MoE(Mixture of Experts) 적용 및 발전을 위한 기술사적 제언

- **Fine-Grained MoE 및 공유 전문가(Shared Expert) 하이브리드 설계 채택** : 모든 태스크의 공통 기초 지식은 공유 FFN이 처리하고 특화 지식만 세분화된 전문가에게 라우팅하는 구조 도입.
- **클라우드 서빙 비용(TCO) 절감을 위한 MoE 아키텍처 우선 검토** : Dense 70B 모델 대신 Mixtral 계열을 배포하여 동일 성능 대비 추론 API 서빙 비용 50% 이상 절감 달성.
- **사내 특화 태스크 튜닝 시 라우터 동결(Router Freezing) PEFT 기법 적용** : 다운스트림 파인튜닝 시 라우터 가중치를 동결하고 개별 전문가 내부에만 LoRA를 삽입하여 학습 안정성 확보.
