## 30초 인출

- 본질: **핀테크(FinTech, Financial Technology)** 는 오픈 API, 인공지능, 블록체인, 클라우드 등 첨단 IT 기술을 금융 서비스 전반에 결합하여 비대면 금융 거래의 편의성·효율성을 혁신하는 디지털 금융 패러다임
- 메커니즘: 표준 오픈뱅킹 API 및 금융 마이데이터를 통해 계좌·신용 데이터를 연계하고, AI 기반 실시간 FDS 및 간편인증을 거쳐 맞춤형 금융 트랜잭션 처리
- 통찰: 제3자 핀테크 앱의 API 토큰 탈취와 비대면 금융 사기(FDS) 위험이 급증하므로 mTLS 기반 보안 API 게이트웨이 및 이상거래 AI 실시간 차단망 구축 필수

<details><summary>핵심 용어</summary>

- **핀테크 (FinTech)** : 금융(Finance)과 기술(Technology)의 결합으로 기존 금융 업무를 디지털·모바일 환경으로 재창조하는 서비스.
- **오픈뱅킹 (Open Banking)** : 은행이 보유한 송금·결제·조회 기능을 표준 API 형태로 제3자 핀테크 기업에 개방하는 금융 공동망 인프라.
- **금융 마이데이터 (MyData)** : 정보주체의 전송요구권 행사를 통해 분산된 금융 자산 데이터를 중앙 집중 조회·관리하는 본인신용정보관리업.
- **임베디드 파이낸스 (Embedded Finance)** : 비금융 플랫폼(유통, 모빌리티) 내에 결제, 대출, 보험 등 금융 상품을 심리스하게 내재화하는 방식.
- **FDS (Fraud Detection System)** : 전자금융거래 시 수집된 단말 및 접속 정보를 AI/머신러닝으로 분석하여 이상금융거래를 실시간 차단하는 보안 시스템.

</details>

## 2~4교시 25점 답안

## Ⅰ. 핀테크의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **핀테크(FinTech)** 는 금융(Finance)과 정보기술(Technology)의 융합을 통해 지급결제, 대출, 자산관리, 보험 등 전통 금융 비즈니스를 모바일 및 데이터 기반으로 재구성한 혁신 금융 서비스 |
| 목적 | 금융 소비자 접근성 및 편의성 극대화, 금융 거래 중개 수수료 절감, 금융 포용성(Financial Inclusion) 확대 및 개인화된 자산관리 제공 |

## Ⅱ. 핀테크의 핵심 특징 및 금융 혁신 4대 속성

| 구분 | 핀테크의 핵심 특징 | 세부 공학적 및 비즈니스 속성 |
|---|---|---|
| **탈중개화 (Disintermediation)** | 직접 P2P/API 거래 | 전통 은행 지점 창구를 배제하고 스마트폰과 플랫폼을 통한 금융 소비자와 공급자 직접 매칭 |
| **언번들링 & 리번들링** | 서비스 모듈화 및 재구성 | 복합 금융상품을 쪼개어 단일 기능(간편송금 등)으로 특화(Unbundling) 후 마이데이터로 재통합(Rebundling) |
| **데이터 주도성 (Data-driven)** | 비금융 대안정보 신용평가 | 통신료 납부 내역, 이커머스 매출 등 비금융 빅데이터 기반 신용평가(CSS) 모델 적용 |
| **임베디드화 (Embedded)** | 플랫폼 내재형 금융 | 포털, 배달, 커머스 등 일상 서비스 앱 내부에서 이탈 없이 간편결제 및 분할결제(BNPL) 완결 |

## Ⅲ. 핀테크 서비스 아키텍처 및 오픈 API 연계 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ 핀테크 오픈 API 통합 금융 에코시스템 ]                │
└────────────────────────────────────────────────────────────────────────┘
                                    │
 [ 1. 금융 소비자 (사용자 인터페이스) ] : 모바일 앱 (간편송금, 자산관리, 결제)
                                    │
                                    ▼ (OAuth 2.0 인가 및 생체인증)
┌────────────────────────────────────────────────────────────────────────┐
│ [ 2. 핀테크 서비스 플랫폼 (API Gateway) ]                              │
│  - mTLS 상호 인증, API 트래픽 제한(Rate Limiting), 토큰 유효성 검증   │
│  - AI 기반 실시간 이상거래 탐지 시스템 (FDS Engine) 결합               │
└────────────────────────────────────────────────────────────────────────┘
                                    │
 ┌──────────────────────────────────┴──────────────────────────────────┐
 │                                                                     │
 ▼                                                                     ▼
[ 오픈뱅킹 중계 센터 ]                                        [ 금융 마이데이터 중계망 ]
- 잔액조회 / 거래내역조회 API                                 - 통합 계좌 / 카드 / 대출 전송요구
- 출금이체 / 입금이체 API                                     - 정기적 배치 동기화 및 실시간 조회
 └──────────────────────────────────┬──────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [ 3. 계정계 및 금융 원천 기관 ] : 시중은행, 카드사, 증권사, 보험사, 빅테크│
└────────────────────────────────────────────────────────────────────────┘
```

| 아키텍처 계층 | 핵심 기술 요소 | 공학적 통제 방안 |
|---|---|---|
| **클라이언트** | FIDO 생체인증, 앱 위변조 방지, 난독화 | 디바이스 지문(Fingerprinting) 추출 및 스크린 캡처 차단 |
| **API 게이트웨이** | OAuth 2.0, OpenID Connect, JWT 토큰 | API 스코프(Scope) 최소화 및 만료 시간 짧게 설정 |
| **중계망 및 코어** | Kafka 이벤트 스트리밍, HSM(하드웨어 보안 모듈) | 전송 구간 종단간 암호화(E2E) 및 대용량 트랜잭션 무손실 큐잉 |

## Ⅳ. 전통 금융 vs 핀테크 vs 빅테크 금융 비교

| 비교 항목 | 전통 금융 (Traditional Banking) | 핀테크 (FinTech 스타트업) | 빅테크 금융 (BigTech / TechFin) |
|---|---|---|---|
| **사업 출발점** | 금융 라이선스 기반 지점망 | 특정 금융 페인포인트 기술 해결 | 방대한 플랫폼 유저 및 데이터 |
| **핵심 경쟁력** | 자본력, 건전성, 규제 대응 노하우 | UI/UX 혁신, 민첩한 개발, 편의성 | 막강한 락인(Lock-in) 효과, 자본력 |
| **인프라 환경** | 온프레미스 메인프레임, 폐쇄망 | 퍼블릭 클라우드, 마이크로서비스 | 하이퍼스케일 분산 클라우드 |
| **신용평가 방식** | 금융 이력 정보(CB사 점수) 위주 | 대안 데이터 머신러닝 스코어링 | 플랫폼 활동 로그 기반 AI 스코어링 |
| **대표 기업** | KB국민, 신한, 우리, 하나 | 토스, 뱅크샐러드, 와디즈 | 카카오페이, 네이버페이, 애플 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 오픈 API 토큰 탈취 및 피싱 앱 설치를 통한 비대면 무단 대출·이체 사고 빈발 | 비정상 기기 접속 및 급격한 금융 거래 발생 시 즉시 FDS를 통해 이체를 지연시키는 지연인출제 및 추가 안면 인증 강제 |
| 핀테크 기업의 클라우드 인프라 장애 발생 시 연계된 전 금융 서비스가 연쇄 마비되는 단일 장애점(SPOF) 리스크 | 멀티 리전 액티브-액티브(Active-Active) 클라우드 구성 및 서킷 브레이커(Circuit Breaker)를 통한 장애 격리 |

## Ⅵ. 제언

전자금융사고 방지를 위해 사후 감사가 아닌 거래 인입 시점의 실시간 AI-FDS와 제로 트러스트(Zero Trust) API 보안 체계 구축.

```text
[ 오픈뱅킹 거래 요청 ]
          │
          ▼
[ 제로 트러스트 보안 게이트웨이 (API Gateway) ]
   ├── Step 1: mTLS 상호 인증 및 단말 무결성 검증
   ├── Step 2: AI-FDS 모델의 이상 징후 스코어링 (0 ~ 100점)
   └── Step 3: 고위험(80점 이상) 시 즉시 거래 중단 및 영상 통화 인증 요구
          │
          ▼ (정상 판정 시)
[ 금융 코어 트랜잭션 실행 및 감사 로그 WORM 스토리지 불변 기록 ]
```

| 구분 | 룰(Rule) 기반 기존 FDS | 제언: 머신러닝 기반 실시간 AI-FDS |
|---|---|---|
| **탐지 기법** | 정적인 금액/시간 조건문(if-else) 판별 | 사용자 행동 패턴(타이핑 속도, 접속 패턴) 이상 탐지 |
| **신종 사기 대응** | 신종 사기 발생 후 사후 룰 추가 | 비지도학습 군집화를 통한 미지의 이상 패턴 사전 포착 |
| **오탐률(FP)** | 정상적인 야간 고액 결제 오차단 빈발 | 정밀도-재현율 최적화로 고객 불편 최소화 |
