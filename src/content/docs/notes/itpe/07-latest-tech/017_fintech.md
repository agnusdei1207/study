## 연관 키워드

- 핀테크(FinTech), 오픈뱅킹(Open Banking), 마이데이터(MyData), 오픈 API(Open API)
- FDS(Fraud Detection System), 대안신용평가(Alternative CSS), XAI(Explainable Artificial Intelligence)
- BaaS(Banking-as-a-Service), MSA(Microservice Architecture), 토큰증권(STO, Security Token Offering), CBDC(Central Bank Digital Currency)
- 금융 규제 샌드박스, 망분리, 금융 포용성, 크레덴셜 스터핑(Credential Stuffing)

## Ⅰ. 핀테크의 개요

- 핵심 요약 : 금융과 IT의 융합으로 금융 서비스 프로세스 전반을 재구성하는 디지털 금융 기술 패러다임.
- 개념 : 금융(Finance)과 정보기술(Technology)의 융합으로, 인공지능(AI, Artificial Intelligence), 클라우드, 빅데이터, 오픈 API(Application Programming Interface), 분산원장 같은 기술을 금융 프로세스에 적용해 기존 서비스를 재구성하는 패러다임 (**핀테크**, FinTech).
- 배경 및 필요성 : 스마트폰 보급으로 비대면 채널이 늘고, **마이데이터** 제도화로 금융 데이터 독점이 완화되며, 전통 금융의 오프라인 비용과 레거시 시스템의 한계가 드러나면서 등장함.
- 핵심 목적 : 거래 비용 절감, 금융 포용성 확대, 실시간 초개인화 자산관리 제공, 금융 서비스의 민첩성 향상.

## Ⅱ. 핀테크의 특징 및 장점

- 핵심 요약 : 개방형 API와 데이터 연계, 이상거래 탐지, 비금융 데이터 신용평가가 비용 절감과 보안, 포용성 향상으로 이어지는 방식.

1. **오픈뱅킹** (Open Banking) : 계좌 조회, 이체, 결제를 표준 API로 개방 → 제3자 핀테크 기업도 금융 서비스 구현 가능.
2. 마이데이터 : 고객 동의 아래 흩어진 금융 자산과 거래 내역을 통합 수집 → 맞춤형 자산관리와 비교 서비스 제공.
3. AI 기반 이상거래탐지(FDS, Fraud Detection System) : 접속 IP, 단말기 정보, 결제 패턴을 실시간 점수화 → 부정 결제를 즉시 차단.
4. 대안신용평가(Alternative CSS, Credit Scoring System) : 통신료 납부 등 비금융 데이터로 금융 이력이 적은 씬파일러를 평가 → 금융 포용성 확대.
5. 클라우드 네이티브 MSA(Microservice Architecture)와 BaaS(Banking-as-a-Service) : 코어 기능을 독립 서비스로 나눔 → 금융 상품 출시 기간 단축.

## Ⅲ. 핀테크의 구조 (흐름)

- 핵심 요약 : 고객 접점, 개방 API, 지능형 코어, 백엔드 인프라가 위에서 아래로 연결되는 4계층 구조.

```text
[ 핀테크 4계층 레퍼런스 구조 ]

1. 고객 접점 : 간편결제, 로보어드바이저 UI
   ↓ 표준 통신으로 요청 전달
2. 오픈 API·데이터 교환 : 오픈뱅킹, 마이데이터
   ↓ 금융 트랜잭션 위임
3. 지능형 코어 : AI-FDS, 대안신용평가, 스마트 컨트랙트
   ↓ 계정계 처리
4. 백엔드 인프라 : 클라우드 MSA, BaaS, 원장 DB
```

```text
[ 오픈뱅킹 호출 흐름 ]

제3자 핀테크 앱 (고객 동의 확보)
   ↓ 표준 API 요청
오픈 API 게이트웨이 (인증·보안 확인)
   ↓ 계정계 트랜잭션 위임
코어뱅킹 원장 처리
   ↓
결과 응답 후 앱 화면 반영
```

## Ⅳ. 전통 금융과 핀테크의 비교

- 핵심 요약 : 전통 금융이 폐쇄형 메인프레임과 안정성 중심이었다면, 핀테크는 개방형 API와 고객 경험 중심으로 전환됨.

| 비교 축 | 전통 금융 | 핀테크 |
| --- | --- | --- |
| 기반 시스템 | 폐쇄형 메인프레임 | 클라우드 네이티브, 마이크로서비스 |
| 채널 | 영업점과 대면 중심 | 모바일과 비대면 중심 |
| 데이터 | 금융사 내부에 폐쇄 | 마이데이터와 오픈 API로 개방 |
| 신용 판단 | 담보와 신용 등급 중심 | 비금융 데이터와 AI 활용 |
| 리스크 성향 | 안정성과 회피 중심 | 고객 경험과 실험 중심 |

| 세부 영역 | 핵심 기술 요소 | 서비스 예시 | 해결 과제 |
| --- | --- | --- | --- |
| 지급결제 (PayTech) | 간편결제, 토큰화, 오픈 API | 간편결제, PG(Payment Gateway) 혁신 | 가맹점 수수료 압박, 결제 사기 |
| 대출·보험 (Lend/Insur) | 머신러닝, GNN(Graph Neural Network), 마이데이터 | P2P(Peer-to-Peer) 대출, 중금리 대출 | 신용평가 공정성, 연체율 관리 |
| 자산관리 (WealthTech) | 현대포트폴리오이론(MPT, Modern Portfolio Theory), 강화학습 | 로보어드바이저, 자동 리밸런싱 | 시장 변동성, 알고리즘 설명 책임 |

## Ⅴ. 핀테크의 한계와 방안

- 핵심 요약 : 비대면 사기, 망분리 규제 충돌, 신용평가의 설명 불가능성을 인증 강화, 규제 샌드박스, XAI로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 비대면 사기 확산 (보이스피싱, 명의도용, 크레덴셜 스터핑) | 간편 인증을 악용한 악성 앱 감염과 계정 탈취 피해 빈발 | 3D 라이브니스(Liveness) 검증, 단말기 이상 행위 실시간 감지, 공동 FDS 정보 공유 | 사기 탐지율, 피해 건수 |
| 망분리 규제와 클라우드·생성형 AI 도입 충돌 | 개발망과 운영망 분리로 SaaS(Software as a Service)와 외부 LLM(Large Language Model) API 활용이 제약됨 | **금융 규제 샌드박스**의 적극 활용, 개인신용정보 가명·익명 처리 게이트웨이 구축 | 샌드박스 과제 수 |
| 대안신용평가의 설명 불가능성 | 대출 거절 사유를 고객에게 소명하지 못하면 금융소비자보호 위반 위험 | **XAI**(Explainable Artificial Intelligence) 기법인 SHAP(SHapley Additive exPlanations), LIME(Local Interpretable Model-agnostic Explanations)을 파이프라인에 통합해 거절 사유 리포트 자동 생성 | 소명 리포트 제공률 |

## Ⅵ. 핀테크에 대한 기술사적 제언

- 핵심 요약 : 코어 시스템의 모듈화, 개방형 금융 데이터 활용, 신규 원장 체계 대비를 함께 추진하는 방향.

1. 모놀리식 계정계를 Kafka 같은 이벤트 브로커 기반 아키텍처로 분리해 금융 상품의 출시 주기를 줄이는 것이 필요함.
2. 마이데이터 확산에 맞춰 고객의 재무 상태를 분석하고 상품을 추천하는 금융 비서를 설계하되, 최종 거래 실행에는 고객의 명시적 확인 절차를 두어야 함.
3. 2026년 1월 국회 본회의를 통과한 토큰증권 관련 법 체계와 CBDC(Central Bank Digital Currency, 중앙은행 디지털화폐)에 대비해, 분산원장과 기존 원장 사이의 결제 완결성을 보장하는 상호운용 인터페이스를 확보하는 것이 필요함.

## Ⅶ. 결론

- 핵심 요약 : 핀테크는 금융과 IT의 융합으로 금융 서비스를 개방형 API와 데이터 중심으로 재구성하는 기술 패러다임임.
- 시사점 : 망분리, 설명 가능성, 사기 대응을 함께 풀어야 혁신이 신뢰를 얻으며, 그 전제 위에서 금융 포용성이 확대됨.
