## 30초 인출

- 본질: 대규모 범용 데이터로 사전학습(Pre-training)된 파운데이션 모델의 가중치를 특정 도메인 데이터나 다운스트림 과업(Downstream Task)에 맞추어 추가 미세 조정하는 전이 학습 기법
- 메커니즘: 도메인 고품질 데이터셋 구축 → 기본 모델 가중치 로드 및 동결/가중치 튜닝 전략 수립 → 지도 미세조정(SFT/PEFT/LoRA) 실행 → 도메인 벤치마크 평가 및 파괴적 망각 검증 → 서빙 경량화 배포
- 통찰: 파인튜닝은 고정된 도메인 스타일과 응답 양식 최적화에 탁월하나 최신 지식 반영에는 한계가 있으므로 검색 증강 생성(RAG) 및 RAFT 기법과의 상호보완적 하이브리드 아키텍처 결합 필수

<details>
<summary>핵심 용어</summary>

- **파인튜닝(Fine-tuning)** : 기학습된 범용 모델(Foundation Model)에 도메인별 라벨링 데이터를 입력하여 파라미터를 추가 갱신하는 미세조정 기법
- **지도 미세조정(SFT, Supervised Fine-Tuning)** : 질문과 이상적인 답변 쌍으로 구성된 데이터셋을 통해 지시 사항을 준수하도록 유도하는 학습
- **매개변수 효율적 미세조정(PEFT, Parameter-Efficient Fine-Tuning)** : 원본 모델 파라미터는 동결하고 극소수의 추가 파라미터만 학습하여 연산 비용을 대폭 절감하는 기법군
- **저순위 적응(LoRA, Low-Rank Adaptation)** : 가중치 변화 행렬을 두 개의 저차원 저순위 행렬 곱(A·B)으로 분해하여 학습 파라미터를 0.1% 미만으로 축소하는 대표적 PEFT 기술
- **RAFT(Retrieval-Augmented Fine-Tuning)** : 검색된 관련 문서와 노이즈(방해) 문서가 혼합된 컨텍스트 속에서 필요한 근거를 정확히 인용하도록 특화 학습시키는 기법
</details>

## 2~4교시 예상문제 (25점)

> 거대 언어 모델(LLM)의 도메인 특화 적용을 위한 파인튜닝(Fine-tuning)의 개념과 주요 학습 기법을 설명하고, 전체 파인튜닝(Full Fine-Tuning)과 매개변수 효율적 파인튜닝(PEFT)의 비교, RAFT(Retrieval-Augmented Fine-Tuning) 아키텍처 및 RAG와의 전략적 선택 기준을 논하시오. (25점)

## 2~4교시 25점 답안

## Ⅰ. 도메인 특화 모델 최적화, 파인튜닝(Fine-tuning)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 방대한 코퍼스로 사전학습된 대규모 모델(Foundation Model)을 특정 산업군, 사내 지식 또는 특정 과업 목적에 맞추어 **가중치를 추가 학습·정렬하는 미세조정 기법** |
| 목적 | 범용 모델의 도메인 지식 습득, 기업 고유 응답 톤앤매너 확립, 프롬프트 입력 비용 절감 및 환각 억제 |

- 파운데이션 모델의 일반화 능력(Transfer Learning)을 유지하면서 전문 과업(의료, 금융, 법률 등)에서의 작업 정확도를 극대화하는 핵심 전략.

## Ⅱ. 파인튜닝의 학습 유형 및 주요 특징

### (1) 파인튜닝의 진화 단계별 학습 유형

```text
[ Full Fine-Tuning ] ===> [ PEFT (LoRA/QLoRA) ] ===> [ Alignment & Domain-RAG ]
- 모든 가중치 100% 갱신   - 원본 가중치 동결 (Freeze)   - 인간 선호도 정렬(RLHF/DPO)
- 수백 GB 고비용 GPU 필요 - 어댑터 파라미터 < 1% 학습   - 오픈북 시험 훈련(RAFT)
- 파괴적 망각 위험 높음   - 단일 GPU 파인튜닝 실현      - 환각 억제 및 근거 인용 극대화
```

### (2) 파인튜닝의 주요 특징

| 특징 | 설명 | 세부 구현 요소 |
|---|---|---|
| **도메인 행동 내재화** | 반복적인 지시 없이도 일관된 출력 포맷(JSON, 코드)과 언어 스타일 유지 | SFT(Supervised Fine-Tuning) 템플릿 |
| **추론 효율성 극대화** | 긴 프롬프트(Few-shot) 없이 Zero-shot 질의만으로 고품질 결과 도출 | 시스템 프롬프트 토큰 절감, 서빙 지연 최소화 |
| **경량 어댑터 서빙** | 하나의 기본 모델에 작업별 경량 가중치(LoRA Adapter)만 동적 스왑 | Multi-LoRA 서빙(vLLM, S-LoRA) |
| **지속적 정렬 가능** | 사용자 피드백 데이터를 반영하여 지속적으로 모델 선호도 업데이트 | DPO(Direct Preference Optimization), KTO |

## Ⅲ. 파인튜닝의 체계·프로세스 및 RAFT 학습 파이프라인

### (1) 일반 파인튜닝 vs RAFT 파이프라인 아키텍처

```text
+-----------------------------------------------------------------------------------+
|                        파인튜닝 파이프라인 비교 아키텍처                          |
+-----------------------------------------------------------------------------------+
| [일반 파인튜닝 (SFT) - 폐쇄형 지식 암기 방식]                                    |
|   Prompt (Q) + Golden Answer (A)                                                  |
|         |                                                                         |
|         v                                                                         |
|   +-----------------------+      Loss Backprop      +-----------------------+     |
|   | Domain Dataset (Q, A) | ---------------------> | Foundation Model (LLM)|     |
|   +-----------------------+                         +-----------------------+     |
|   * 한계: 지식의 갱신이 불가능하며 최신 정보 질의 시 이전 가중치 기반 오답 발생   |
+-----------------------------------------------------------------------------------+
                                         vs
+-----------------------------------------------------------------------------------+
| [RAFT (Retrieval-Augmented Fine-Tuning) - 오픈북 시험 적응 방식]                  |
|   Prompt (Q) + Context [Relevant Docs(D*) + Distractor Docs(D)] + CoT Answer (A*) |
|         |                                                                         |
|         v                                                                         |
|   +-----------------------------------------------------------------------+       |
|   | RAFT Dataset Generator: 관련 정답 문서 + 무관한 방해 문서 혼합 주입   |       |
|   +-----------------------------------------------------------------------+       |
|         |                                                                         |
|         v                                                                         |
|   +-----------------------------------------------------------------------+       |
|   | LLM 학습: 방해 문서 무시 + 정답 문서 추출 + 단계별 인용(CoT) 출력    |       |
|   +-----------------------------------------------------------------------+       |
|   * 장점: 실제 RAG 검색 환경과 동일한 노이즈 환경에서 정밀 근거 추출 능력 체화    |
+-----------------------------------------------------------------------------------+
```

### (2) 파인튜닝 엔지니어링 4단계 핵심 프로세스

| 단계 | 주요 작업 내용 | 핵심 기법 및 도구 |
|---|---|---|
| **1. 데이터셋 큐레이션** | 고품질 도메인 질의-응답 쌍 구축, 중복 제거, PII 마스킹 | Synthetic Data Generation, LLM-as-a-Judge |
| **2. 모델 및 기법 선정** | 베이스 모델 크기(SLM vs LLM) 및 튜닝 기법(LoRA, QLoRA) 확정 | HuggingFace PEFT, bitsandbytes 4-bit 양자화 |
| **3. 가중치 훈련 실행** | 하이퍼파라미터(lr, epoch, rank) 최적화 및 체크포인트 평가 | DeepSpeed ZeRO, FSDP, FlashAttention-2 |
| **4. 파괴적 망각 평가** | 도메인 성능 향상 여부 및 범용 벤치마크(MMLU, GSM8K) 회귀 검증 | lm-evaluation-harness, RAGAS |

## Ⅳ. Full Fine-Tuning vs PEFT(LoRA) vs RAG 비교

### (1) 기법별 종합 비교

| 비교 항목 | 전체 파인튜닝 (Full FT) | 파라미터 효율적 튜닝 (LoRA) | 검색 증강 생성 (RAG) |
|---|---|---|---|
| **수정 대상** | 모델의 모든 가중치 (100%) | 추가 어댑터 가중치 (< 1%) | 가중치 불변 (외부 프롬프트 주입) |
| **학습 컴퓨팅 비용** | 수십~수백 대 GPU 클러스터 | 단일 또는 수 대의 GPU | GPU 학습 불필요 (인덱싱 연산) |
| **최신 지식 갱신** | 모델 전체 재학습 필요 (느림) | 어댑터 재학습 필요 (보통) | 실시간 문서 벡터 색인 갱신 (즉시) |
| **응답 스타일 제어** | 매우 뛰어남 | 매우 뛰어남 | 프롬프트 길이에 의존하여 한계 |
| **환각(Hallucination)**| 여전히 발생 가능 | 여전히 발생 가능 | 검색 문서 기반 인용으로 극소화 |
| **파괴적 망각 위험** | 매우 높음 (기존 상식 손실) | 매우 낮음 (베이스 모델 고정) | 없음 (가중치 변경 없음) |

### (2) 기업 환경 내 LLM 최적화 선택 매트릭스

```text
지식 변경 주기 ^
 (동적/최신)   |      [ Pure RAG ]             [ Hybrid: RAFT / RAG+LoRA ]
              |   - 일 단위/실시간 규정 갱신    - 복잡한 도메인 문서 심층 이해
              |   - 고객 개인화 데이터 검색     - 엄격한 규제 문서 인용 및 서식 준수
              |
 (정적/고정)   |      [ Few-shot Prompting ]   [ PEFT (LoRA/QLoRA) ]
              |   - 단순 포맷 변환             - 사내 특화 톤앤매너 확립
              |   - 임시 일회성 작업           - 특화 도메인 용어 및 전문 분류
              +---------------------------------------------------------->
                 스타일/포맷 고정성 요구 (낮음 ------------------> 높음)
```

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **파괴적 망각(Catastrophic Forgetting)**<br />- 특정 도메인 과업 집중 학습 시 사전 학습된 일반 추론 능력 상실 | **PEFT 기법 채택 및 일반 데이터 믹싱**<br />- 베이스 가중치를 동결하는 LoRA 적용 및 도메인 데이터셋에 일반 상식 데이터 10~20% 혼합 학습 |
| **고비용 데이터셋 라벨링 병목**<br />- 고품질 도메인 전문 질의-응답 쌍 구축에 막대한 전문가 비용 소요 | **합성 데이터 생성(Synthetic Data) 및 LLM 정제**<br />- 프론티어 LLM을 활용한 고품질 데이터 증강 및 엄격한 규칙 기반 필터링 파이프라인 도입 |
| **최신 지식 반영의 불연속성**<br />- 학습 완료 직후부터 신규 정보 반영 불가, 지식 노후화 발생 | **RAG와 결합한 상호보완 아키텍처 구축**<br />- 모델 스타일과 추론 문맥 처리는 파인튜닝으로, 사실적 최신 데이터는 벡터 검색으로 주입 |
| **서빙 메모리 오버헤드**<br />- 태스크마다 수십 GB의 모델 전체를 개별 인스턴스로 서빙 시 비용 급증 | **Multi-LoRA 동적 스와핑 서빙 프레임워크 도입**<br />- 베이스 모델 1기를 상주시키고 요청 태스크별로 수 MB 수준의 LoRA 가중치를 실시간 매핑 |

## Ⅵ. 제언

파인튜닝은 '지식의 저장고'가 아닌 '행동 양식과 전문 추론 메커니즘의 내재화 도구'로 인식해야 하며, 엔터프라이즈 환경에서는 최신 정보 접근을 담당하는 RAG와 모델의 도메인 이해도를 극대화하는 RAFT/PEFT를 융합한 듀얼 전략 실행 필수.

```text
[엔터프라이즈 최적 도메인 LLM 아키텍처]

User Query ---> [ Hybrid Router ]
                      |
        +-------------+-------------+
        | (Dynamic Knowledge)       | (Style & Domain Reasoning)
        v                           v
  [ Enterprise Vector DB ]    [ Domain Specialized LoRA ]
  - 최신 사내 규정/DB          - 도메인 전문 용어 이해
        \                           /
         \                         /
          v                       v
      [ RAFT-tuned Foundation Model Engine ]
      - 방해 문서 필터링 + 단계별 근거 인용
                      |
                      v
            [ Fact-Checked Output ]
```

| 도입 추진 축 | 중점 추진 과제 | 기대 효과 |
|---|---|---|
| **기술적 구현** | RAFT 기반 RAG-특화 파인튜닝 파이프라인 구축 | 검색 노이즈 환경에서도 환각 없는 정확한 답변 도출 |
| **비용 최적화** | QLoRA 및 Multi-LoRA 서빙 체계 표준화 | 온프레미스 GPU 인프라 도입 비용 80% 이상 절감 |
