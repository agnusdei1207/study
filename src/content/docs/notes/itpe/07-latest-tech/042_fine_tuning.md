## 연관 키워드

- 파인튜닝(Fine-tuning), 전이 학습(Transfer Learning), 파운데이션 모델(Foundation Model), 사전 학습(Pre-training)
- 풀 파인튜닝(Full Fine-tuning), PEFT, LoRA, QLoRA, 프롬프트 튜닝(Prompt Tuning)
- 치명적 망각(Catastrophic Forgetting), 리플레이(Experience Replay), 합성 데이터, Self-Instruct
- RAG, 회귀 평가(Regression Testing), 가중치 병합(Merge)

## Ⅰ. 파인튜닝(Fine-tuning)의 개요

- 핵심 요약 : 사전 학습된 파운데이션 모델을 도메인 데이터로 추가 학습시켜 특정 작업에 맞추는 전이 학습 기법.
- 개념 : 대규모 코퍼스로 사전 학습된 **파운데이션 모델** (Foundation Model)의 가중치를 출발점으로 삼아, 특정 도메인이나 작업(분류, 요약, 질의응답)의 데이터셋으로 일부 또는 전체 파라미터를 추가로 미세 조정하는 **파인튜닝** (Fine-tuning, 전이 학습의 한 방식).
- 배경 및 필요성 : 처음부터 사전 학습하려면 막대한 GPU 자원과 긴 시간이 필요하므로, 이미 언어 구조를 익힌 모델을 목표 작업에 적응시키는 방식이 기업 AI 구축의 표준적 접근으로 자리 잡음.
- 핵심 목적 : 도메인 용어와 어투 체화, 정형 출력 형식 준수, 프롬프트 없이도 안정된 작업 성능 확보, 추론 시 프롬프트 길이 축소.

## Ⅱ. 파인튜닝(Fine-tuning)의 특징 및 장점

- 핵심 요약 : 기존 모델의 일반 능력을 재활용하면서 소량의 도메인 데이터로 성능을 끌어올리는 효율적 적응 방식.

1. **전이 학습 기반 적응** : 사전 학습된 언어 능력을 그대로 가져와 도메인 데이터만 추가 학습 → 학습 비용과 기간 절감.
2. **파라미터 효율적 기법** (PEFT, Parameter-Efficient Fine-Tuning) : 전체가 아닌 소수 파라미터만 갱신 → 자원이 적은 환경에서도 학습 가능.
3. **LoRA** (Low-Rank Adaptation) : 원 가중치를 동결하고 저차원 행렬 두 개로 변화량만 학습 → 학습 파라미터와 저장 용량 대폭 감소.
4. **가중치 병합** (Merge) : 학습된 변화량을 원 가중치에 더해 배포 → 추론 시 추가 지연 없이 서빙 가능.

## Ⅲ. 파인튜닝(Fine-tuning)의 구조 (흐름)

- 핵심 요약 : 원 가중치는 고정하고 저차원 어댑터만 학습한 뒤, 추론 시 결과를 더해 하나의 모델처럼 쓰는 구조.

```text
[ LoRA 동작 원리 ]

  입력 벡터 x
     ├──► 사전학습 가중치 W0 (동결)
     └──► 저차원 행렬 A (차원 축소)
              ↓
          행렬 B (차원 복원, 학습)
              ↓
  출력 h = W0·x + B·A·x
```

- **QLoRA** (Quantized LoRA) : 기본 모델을 4비트 정규 부동소수점(NF4, NormalFloat 4)으로 양자화해 동결하고, 그 위에 LoRA 어댑터를 올려 단일 GPU에서도 대형 모델을 학습하는 방식.

```text
[ 파인튜닝 방식 선택 흐름 ]

  자원과 성능 목표 확인
        ↓ 자원 제약이 큼
  QLoRA (4비트 백본 + 어댑터)
        ↓ 자원 여유, 최고 성능 필요
  풀 파인튜닝 (전체 파라미터 갱신)
```

## Ⅳ. 파인튜닝(Fine-tuning)의 비교

- 핵심 요약 : 풀 파인튜닝은 성능 상한이 높지만 비용이 크고, LoRA와 QLoRA는 가성비가 좋아 실무 표준으로 자리 잡음.

| 파인튜닝 방식 | 학습 대상 | GPU 메모리 요구 | 장점 | 단점 및 병목 |
| --- | --- | --- | --- | --- |
| 풀 파인튜닝 (Full Fine-tuning) | 전체 파라미터 | 모델 크기 대비 매우 큼 | 적응력과 성능 상한 최고 | 치명적 망각, 높은 인프라 비용 |
| LoRA | 소수의 어댑터 | 모델 크기 수준 | 메모리 절감, 작업별 어댑터 교체 가능 | 하이퍼파라미터(랭크, 스케일) 튜닝 필요 |
| QLoRA | 4비트 백본 위 어댑터 | 단일 GPU에서 대형 모델 가능 | 학습 비용 대폭 절감 | 4비트 양자화에 따른 미세한 오차 |
| 프롬프트 튜닝 (Prompt Tuning) | 가상 소프트 토큰만 | 매우 낮음 | 가볍고 모델 본체 불변 | 복합 추론과 스타일 체화에 한계 |

- 실무 원칙 : 인프라 효율과 안정성을 고려하면 LoRA 또는 QLoRA가 기본 선택지가 됨.

## Ⅴ. 파인튜닝(Fine-tuning)의 한계와 방안

- 핵심 요약 : 범용 능력 상실, 최신 지식 부재, 학습 데이터 구축 비용을 어댑터 기법, 리플레이, RAG 분업, 합성 데이터로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 치명적 망각 (Catastrophic Forgetting) | 특정 도메인만 학습해 기본 코딩이나 번역 능력이 저하 | 기본 가중치를 고정하는 PEFT 적용, 학습 데이터에 일반 대화 데이터를 섞는 **리플레이** (Experience Replay) | 범용 벤치마크 점수 변화 |
| 지식의 최신성 부재와 환각 잔존 | 파인튜닝은 통계 패턴과 스타일을 학습하며 변동하는 사실 지식 저장에는 비효율 | 파인튜닝은 형식과 어투에 집중하고, 최신 사실은 **RAG** (검색 증강 생성)에 위임 | 사실 정확도, 출처 일치율 |
| 고품질 지도 학습 데이터 구축 비용 | 수많은 입출력 쌍을 사람이 작성해야 함 | 고성능 모델로 **합성 데이터** (Synthetic Data)를 생성하고 **Self-Instruct** 기법 적용 후 사람이 검수 | 데이터 검수 통과율, 라벨링 시간 |

## Ⅵ. 파인튜닝(Fine-tuning)에 대한 기술사적 제언

- 핵심 요약 : 지식과 형식의 역할 분담, 단일 GPU 기반 표준 파이프라인, 배포 전 회귀 평가 자동화로 운영하는 것이 바람직함.

1. 새로운 지식은 RAG로, 응답 형식과 도메인 어투는 파인튜닝으로 맡기는 역할 분담 원칙을 세워 중복 투자를 피하는 것이 바람직함.
2. 고가의 대규모 클러스터가 없어도 QLoRA 기반 학습 절차를 템플릿으로 표준화해 사내 MLOps 파이프라인에 올리는 것이 필요함.
3. 배포 전에 도메인 성능뿐 아니라 안전성 기준과 범용 벤치마크 유지 여부를 함께 평가하는 회귀 평가 절차를 자동화함.

## Ⅶ. 결론

- 핵심 요약 : 파인튜닝은 사전 학습 모델에 도메인 형식과 어투를 입히는 전이 학습 기법으로, 지식 갱신 수단이 아님.
- 시사점 : 파인튜닝과 RAG를 목적에 따라 나누어 쓰는 것이 비용과 정확도를 함께 잡는 실무 기준이 됨.
