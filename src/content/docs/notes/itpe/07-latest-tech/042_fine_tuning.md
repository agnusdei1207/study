## 답안 골격
```text
[파인튜닝] ◀━━ 머리: Ⅶ 내 의견 (LoRA/PEFT 경량 기법과 RAFT 파이프라인 결합을 통한 도메인 적응 최적화)
 ┃
 ┣━ Ⅰ 개요 ───── 일반 사전학습 모델의 특정 도메인 지식·말투·태스크 적응 한계 → 타깃 데이터셋 기반 추가 가중치 미세조정
 ┣━ Ⅱ 특징 ───── 도메인 적응성(Domain Adaptation) · 파라미터 업데이트 · RAG 대비 고정 지식화 · 서빙 비용 동일
 ┣━ Ⅲ 구조 ───── 사전학습 가중치 계층 + 미세조정 어댑터(LoRA/QLoRA) + 지도 미세조정(SFT) 데이터셋
 ┣━ Ⅳ 흐름 ───── ① 고품질 도메인 QA/지시 데이터 구축 → ② 파라미터 동결 및 어댑터 부착 → ③ 역전파 학습 → ④ 가중치 병합/서빙
 ┣━ Ⅴ 비교 ───── 전면 파인튜닝(Full Fine-tuning) vs PEFT(LoRA/QLoRA) vs RAG (전체 갱신 vs 저랭크 어댑터 vs 외부 검색)
 ┗━ Ⅵ 실무 ───── 파괴적 망각(Catastrophic Forgetting) / 고비용 GPU 자원 요구 / 최신 지식 실시간 갱신 불가
```
- 필수 키워드: 전이 학습(Transfer Learning) · 지도 미세조정(SFT) · PEFT(Parameter-Efficient Fine-Tuning) · LoRA(Low-Rank Adaptation) · 파괴적 망각 · RAFT

## 한 줄 본질
- 수조 개 토큰으로 학습된 범용 파운데이션 모델의 전문 도메인 어휘·출력 서식 미흡 한계 → 목적에 맞게 정제된 소규모 데이터셋으로 모델 가중치를 추가 갱신 → 도메인 특화 태스크 완벽 수행 및 일관된 스타일 획득 / 학습 데이터 외 최신 사실 갱신 한계와 파괴적 망각 위험

## 핵심 그림
```text
[PEFT: LoRA(Low-Rank Adaptation) 가중치 분해 원리]
               [ 입력 벡터 x (d 차원) ]
                         |
           +-------------+-------------+
           |                           |
           v (동결된 원래 가중치 W_0)   v (저랭크 행렬 분해)
    [ W_0 (d x k) ]              [ 행렬 A (d x r) ] (초기값: 가우시안)
      (학습 안함, Freeze)              |
           |                           v
           |                     [ 행렬 B (r x k) ] (초기값: 0)
           |                           | (r << min(d, k), 예: r=8)
           |                           v
           |                     [ Delta W = B * A * scale ]
           \                          /
            \---> [ 합산: h = W_0*x + Delta W*x ] ===> [ 출력 h ]
```

## 핵심 용어
- SFT(Supervised Fine-Tuning): 입력 지시문(Prompt)과 이상적인 답변(Completion) 쌍으로 구성된 정답 데이터셋을 통해 모델의 대화·지시 수행 방식을 학습시키는 절차
- LoRA(Low-Rank Adaptation): 사전학습 가중치는 완전히 동결(Freeze)하고, 가중치 변화량($\Delta W$)을 랭크가 매우 작은 두 저차원 행렬($A, B$)로 분해하여 파라미터의 0.1% 미만만 학습시키는 경량 기법
- 파괴적 망각(Catastrophic Forgetting): 새로운 도메인 지식을 집중적으로 파인튜닝하는 과정에서 모델이 사전에 알고 있던 일반 상식이나 언어 능력을 상실하는 현상

## 핵심 통찰
- 파인튜닝은 모델에게 "새로운 사실(Fact)"을 주입하는 용도로는 부적합하며(지식 암기에는 RAG가 우세), "말투, 출력 포맷(JSON), 특정 추론 절차(Style/Behavior)"를 각인시키는 데 최적
- Full Fine-tuning은 70B 모델 기준 수천만 원의 GPU 비용과 다중 노드가 필요하지만, QLoRA(4비트 양자화 결합)를 사용하면 단일 상용 GPU(24GB VRAM)에서도 충분히 튜닝 가능
- 최신 트렌드는 RAG와 Fine-tuning의 대립이 아닌 결합(RAFT): 모델이 검색된 문맥(Context)을 바탕으로 정답을 추출하고 노이즈 문서를 무시하는 훈련을 파인튜닝 단계에 포함

## 이웃 토픽과 구분
- 파인튜닝 vs RAG: 파인튜닝은 모델 내부의 "가중치(Synapse)"를 변경하여 행동 양식을 바꾸는 기법 / RAG는 가중치는 그대로 두고 "프롬프트 컨텍스트(Short-term Memory)"에 최신 문서를 끼워 넣는 기법

## 문제·원인·대책
- 적용 상황: 사내 ERP 질의응답을 위해 14B 오픈소스 모델 파인튜닝 후 검증 중 이상 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 사내 지식은 잘 대답하나 일반적인 번역·코딩 능력 상실 | 특정 데이터 편중 학습에 따른 파괴적 망각(Catastrophic Forgetting) | 일반 도메인 지시 데이터 10~20% 혼합 학습(Replay Strategy) | 사전 지식 보존 및 도메인 특화 동시 달성 |
| 수천 건의 지시 데이터로 학습 후에도 환각 지속 | 파인튜닝 가중치에만 최신 규정 암기 의존 | RAFT(Retrieval Augmented Fine-Tuning) 파이프라인 도입 | 문맥 참조 역량 극대화 및 환각 억제 |
| 멀티 테넌트 서빙 시 모델별 GPU 인스턴스 과다 소모 | 파인튜닝 모델마다 전체 가중치를 개별 VRAM 적재 | 베이스 모델 공유 + 테넌트별 LoRA 어댑터 동적 스왑(S-LoRA) | VRAM 비용 80% 절감 및 수십 개 특화 모델 동시 서빙 |
