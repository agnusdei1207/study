## 30초 인출

- 본질: **온디바이스 AI(On-Device AI)** 는 원격 중앙 클라우드 서버의 연산 자원에 의존하지 않고 스마트폰, PC, 자율주행차, 가전 등 사용자 단말 내부의 전용 NPU 가속기를 통해 데이터를 직접 처리·추론하는 엣지 지능화 기술
- 메커니즘: 모델 양자화(INT4/INT8) 및 프루닝 후 모바일 전용 런타임(ONNX, TensorRT, CoreML)을 통해 저전력 NPU/DSP 하드웨어에 최적화하여 오프라인 자율 추론 수행
- 통찰: 모바일 기기의 엄격한 배터리 및 발열 스로틀링(Throttling) 제약이 존재하므로 단말 처리와 클라우드 대규모 연산을 유기적으로 결합하는 하이브리드 AI 라우팅 필수

<details><summary>핵심 용어</summary>

- **온디바이스 AI (On-Device AI)** : 외부 통신망 연결 없이 로컬 디바이스 내의 프로세서에서 AI 알고리즘을 독립 실행하는 기술.
- **NPU (Neural Processing Unit)** : 딥러닝 텐서 행렬곱(MAC) 연산을 극단적인 저전력·고효율로 처리하도록 특화된 전용 반도체.
- **양자화 (Quantization)** : 모델의 32비트/16비트 부동소수점 파라미터를 8비트/4비트 정수로 변환하여 모바일 DRAM 대역폭 요구량을 축소하는 기술.
- **가지치기 (Pruning)** : 신경망 내부에서 추론 정확도에 기여도가 낮은 미세 가중치 연결을 제거하여 연산량을 줄이는 경량화 기법.
- **하이브리드 AI (Hybrid AI)** : 가벼운 개인화 태스크는 온디바이스에서 즉시 처리하고, 무거운 복합 추론은 보안 클라우드로 오프로딩하는 협력 모델.

</details>

## 2~4교시 25점 답안

## Ⅰ. 온디바이스 AI의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **온디바이스 AI(On-Device AI)** 는 원격 중앙 클라우드 데이터센터와의 네트워크 통신 없이, 사용자 단말기(스마트폰, 노트북, 자율주행 제어기)에 내장된 모바일 NPU/AP 프로세서를 활용하여 현장에서 실시간으로 인공지능 추론을 완결하는 기술 |
| 목적 | 제로 레이턴시(Zero Latency) 실시간 반응성 달성, 민감 개인정보의 디바이스 외부 유출 원천 차단, 통신 음영 지역 오프라인 가용성 보장 및 클라우드 통신·서버 비용 절감 |

## Ⅱ. 온디바이스 AI의 핵심 특징 및 4대 가치 속성

| 구분 | 온디바이스 AI의 핵심 특징 | 세부 공학적 메커니즘 및 속성 |
|---|---|---|
| **개인정보 완벽 격리 (Privacy)** | 단말 로컬 데이터 처리 | 음성, 사진, 건강 데이터가 기기 외부로 일절 전송되지 않아 프라이버시 침해 원천 배제 |
| **초저지연 즉각 응답 (Zero Latency)** | 네트워크 왕복 시간(RTT) 제거 | 4G/5G 패킷 전송 및 큐잉 지연이 없어 10ms 이하의 실시간 동시통역 및 카메라 보정 가능 |
| **오프라인 서비스 연속성** | 통신망 비의존성 | 비행기 모드, 지하 터널, 산간 오지 등 네트워크 단절 환경에서도 100% 동일한 기능 제공 |
| **클라우드 TCO 절감** | 분산 엣지 컴퓨팅 | 수억 명 사용자의 추론 연산 부하가 개별 단말기로 분산되어 중앙 AIDC 서버 증설 비용 0원화 |

## Ⅲ. 온디바이스 AI HW-SW 통합 아키텍처 및 추론 파이프라인

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ 온디바이스 AI 하드웨어-소프트웨어 스택 체계 ]             │
└────────────────────────────────────────────────────────────────────────┘
                                    │
 [ 응용 서비스 계층 ] : 실시간 통번역, AI 사진 편집, 온디바이스 에이전트
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [ 모델 경량화 및 최적화 계층 (Model Optimization) ]                   │
│  - 채널 프루닝(Pruning), 지식 증류(Distillation), AWQ/GPTQ 4비트 양자화│
│  - 계산 그래프 융합 (Operator Fusion: Conv + BatchNorm + ReLU 단일화)   │
└────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [ 온디바이스 AI 런타임 프레임워크 (Execution Runtime) ]                 │
│  - ONNX Runtime Mobile, Qualcomm QNN, Apple CoreML, ExecuTorch        │
│  - 연산자 매핑 및 CPU / GPU / NPU 동적 오프로딩 스케줄러                │
└────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [ 실리콘 하드웨어 가속 계층 (Mobile Silicon Architecture) ]             │
│  - NPU (INT4/INT8 고속 시스톨릭 어레이 MAC 텐서 코어)                 │
│  - 모바일 통합 메모리 (LPDDR5X 고대역폭 공유 메모리 버스)               │
└────────────────────────────────────────────────────────────────────────┘
```

| 아키텍처 계층 | 핵심 엔지니어링 기술 | 공학적 효과 |
|---|---|---|
| **모델 압축** | 양자화 인식 훈련(QAT), AWQ 4-bit | 모델 가중치 크기 75% 절감, 메모리 대역폭 점유 최소화 |
| **그래프 컴파일러** | TVM, MLIR, 모바일 전용 런타임 | 모바일 NPU 하드웨어 명령어셋(ISA)에 맞춘 커널 최적화 |
| **하드웨어 (SoC)** | 40~50 TOPS급 모바일 NPU 가속기 | 와트당 연산 효율 극대화로 배터리 소모 80% 절감 |
| **메모리 버스** | 온칩 SRAM 및 통합 LPDDR5X 메모리 | CPU-NPU 간 무복사(Zero-Copy) 고속 텐서 전달 |

## Ⅳ. 클라우드 AI vs 엣지 AI vs 온디바이스 AI 비교

| 비교 항목 | 클라우드 AI (Cloud AI) | 엣지 AI (Edge Computing) | 온디바이스 AI (On-Device AI) |
|---|---|---|---|
| **연산 위치** | 원격 초대형 데이터센터 (AIDC) | 기지국, 공장 로컬 엣지 게이트웨이 | 스마트폰, 노트북, 차량 단말 AP |
| **모델 크기** | 70B ~ 1T+ 초대형 LLM | 14B ~ 70B 중소형 모델 | 1B ~ 7B 경량 sLLM |
| **네트워크 연결** | 필수 (인터넷 상시 연결) | 필요 (로컬 인트라넷 연결) | 완전 불필요 (오프라인 구동) |
| **응답 지연(Latency)**| 500ms ~ 2초 (네트워크 지연 포함) | 50ms ~ 100ms 내외 | 10ms 이하 (즉각 응답) |
| **주요 한계** | 개인정보 유출, 서버 트래픽 비용 | 엣지 서버 구축·관리 비용 | 배터리 소모, 단말 발열 스로틀링 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 모바일 단말의 물리적 폼팩터 한계로 인한 발열 누적 및 NPU 동작 클록 강제 저하(스로틀링) | 어텐션 캐시 압축 및 양자화 인식 훈련(QAT)을 통해 연산 FLOPs를 줄이고 방열 베이퍼 챔버 설계 결합 |
| 단말 모델의 파라미터 용량 한계로 인한 고난도 논리 추론 및 방대한 상식 지식의 결손 | 단말과 클라우드가 협력하는 하이브리드 AI 구조를 도입하여 질의 복잡도에 따라 유기적 분기 처리 |

## Ⅵ. 제언

단말의 자원 제약과 클라우드의 보안·비용 문제를 동시에 해결하기 위해, 작업 복잡도를 로컬에서 1차 판정하여 동적 오프로딩하는 하이브리드 온디바이스-클라우드 오케스트레이션 아키텍처 구축.

```text
[ 단말 사용자 질의 인입 ]
             │
             ▼
[ 단말 로컬 NPU 경량 판정기 (On-Device Classifier) ]
   ├── 조건 1: 실시간 카메라 보정, 음성 자막, 민감 금융 거래 ──> [ 단말 NPU 즉시 완결 (오프라인) ]
   └── 조건 2: 다단계 논리 추론, 수백 장 문서 요약, 복합 코딩 ──> [ 종단간 암호화(E2EE) 클라우드 전송 ]
             │                                                                │
             ▼                                                                ▼
      [ 즉각 응답 완료 ]                                              [ 고성능 LLM 추론 후 응답 수신 ]
```

| 구분 | 전면 클라우드 전송 방식 | 제언: 하이브리드 AI 오케스트레이션 |
|---|---|---|
| **보안성** | 민감 사생활 데이터 외부 유출 위험 | 개인 민감 데이터는 단말에서 100% 로컬 처리 |
| **통신 비용** | 모든 요청에 모바일 데이터 과금 | 일상 작업 70%를 단말에서 해결하여 데이터 소모 0원화 |
| **서비스 품질** | 네트워크 단절 시 앱 전체 마비 | 기본 필수 기능은 통신 두절 상태에서도 무중단 제공 |
