## 연관 키워드

- 온디바이스 AI(On-Device AI), 엣지 AI(Edge AI), 신경망처리장치(NPU), sLM
- 양자화(Quantization), 프루닝(Pruning), 계층 융합(Layer Fusion), ONNX Runtime
- 하이브리드 AI(Hybrid AI), 지능형 오프로딩, 온디바이스 RAG, DVFS
- 네트워크 지연(Latency), 개인정보 보호, 이기종 SoC

## Ⅰ. 온디바이스 AI(On-Device AI)의 개요

- 핵심 요약 : 중앙 클라우드 대신 스마트폰, 노트북 같은 단말의 NPU로 모델을 직접 추론하는 탈중앙화 엣지 AI 기술.
- 개념 : 클라우드 서버에 의존하지 않고 사용자 단말 내부의 **신경망처리장치** (NPU, Neural Processing Unit)와 엣지 가속기로 인공지능 모델을 직접 연산·추론하는 기술 (**온디바이스 AI** (On-Device AI)).
- 배경 및 필요성 : 클라우드 호출에 따른 네트워크 지연, 개인정보와 생체 데이터의 외부 전송 위험, 오프라인 환경에서의 서비스 단절, 대규모 서버 운영 비용을 줄이기 위해 하드웨어와 경량 알고리즘을 결합하는 방식이 확산됨.
- 주요 목적 : 네트워크 없이 동작하는 오프라인 서비스 확보, 개인정보 보호, 즉각적인 반응성 확보, 클라우드 호출 비용 절감.

## Ⅱ. 온디바이스 AI(On-Device AI)의 특징 및 장점

- 핵심 요약 : 하드웨어 가속, 경량 모델, 로컬 추론이 결합되어 지연, 프라이버시, 비용 측면의 장점을 만드는 구조.

1. **이기종 SoC** (Heterogeneous SoC) : CPU가 제어를 맡고, GPU가 병렬 연산을, NPU가 텐서 연산을 나누어 처리 → 전력 효율과 처리량 동시 확보.
2. **양자화** (Quantization) : 부동소수점 가중치를 INT8이나 INT4 같은 정수 형식으로 줄여 적재 → 메모리 대역폭과 전력 소모 절감.
3. **계층 융합** (Layer Fusion) : 연속된 연산 계층을 하나의 커널로 묶음 → 메모리 간 데이터 복사 오버헤드 감소.
4. **로컬 추론** (On-Device Inference) : 데이터가 단말 밖으로 나가지 않고 처리 → 개인정보 노출 위험 감소와 네트워크 의존성 제거.

## Ⅲ. 온디바이스 AI(On-Device AI)의 구조 (흐름)

- 핵심 요약 : 애플리케이션, 경량 모델, 컴파일러와 런타임, 하드웨어가 계층으로 쌓인 풀스택 구조.

```text
[ 온디바이스 AI 풀스택 구조 ]

  응용 계층 (Application)
   실시간 통역, 사진 편집, AI 비서
        ↓
  초경량 모델 계층 (sLM, 비전 모델)
        ↓
  컴파일러 · 런타임 (ONNX Runtime 등)
        ↓
  이기종 하드웨어 (NPU + GPU + CPU)
```

```text
[ 하이브리드 AI 라우팅 ]

  사용자 요청 입력
        ↓
  복잡도와 단말 자원 판정
     ↓ 단순             ↓ 복합
  로컬 NPU에서 즉시 처리   클라우드 LLM으로 전달
```

## Ⅳ. 온디바이스 AI(On-Device AI)의 비교

- 핵심 요약 : 클라우드 AI는 모델 규모, 온디바이스 AI는 지연과 프라이버시, 하이브리드 AI는 두 장점의 절충으로 정리됨.

| 비교 항목 | 클라우드 AI | 온디바이스 AI | 하이브리드 AI |
| --- | --- | --- | --- |
| 연산 장소 | 데이터센터 GPU 클러스터 | 사용자 단말의 NPU와 SoC | 로컬 NPU와 클라우드 상호 보완 |
| 네트워크 의존성 | 필수 | 불필요 | 로컬 기능은 오프라인 유지 |
| 지연 시간 | 네트워크 왕복과 서버 대기 | 네트워크 없이 즉각 처리 | 작업 유형에 따라 결정 |
| 개인정보 보호 | 외부 서버 전송 위험 | 단말 내부에서만 처리 | 민감 정보는 단말에서 가공 후 전송 |
| 모델 규모 | 초대형 모델 가능 | 소형 모델로 제한 | 단말 소형 모델과 서버 대형 모델 병행 |
| 서버 비용 | 사용자 수에 비례하여 증가 | 서버 비용 거의 없음 | 비용과 품질의 절충 |

- 선택 기준 : 개인정보 민감도와 응답 즉시성이 높으면 온디바이스, 최신 지식과 대형 추론이 필요하면 클라우드, 둘 다 필요하면 하이브리드를 택함.

## Ⅴ. 온디바이스 AI(On-Device AI)의 한계와 방안

- 핵심 요약 : 메모리와 전력 제약, 소형 모델의 지식 한계, 칩셋 파편화를 경량화, 오프로딩, 표준 런타임으로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 메모리와 배터리 제약 | KV 캐시와 가중치가 시스템 메모리를 점유, 발열과 전력 소모 증가 | **4비트 양자화** (AWQ, Activation-aware Weight Quantization), **프루닝** (Pruning), **DVFS** (Dynamic Voltage and Frequency Scaling) 전력 제어 | 메모리 점유율, 전력 소모량 |
| 소형 모델의 지식과 추론 한계 | 경량 모델은 복잡한 추론과 전문 질의에서 환각 발생 | 기기 내 **온디바이스 RAG** (기기 내 벡터 DB 결합), 고난도 질의는 클라우드로 오프로딩 | 정답률, 오프로딩 비율 |
| 이기종 칩셋 파편화 | 벤더마다 런타임과 연산자 지원이 달라 유지보수 비용 증가 | **ONNX Runtime** 등 크로스 플랫폼 추론 엔진 채택, 모델 변환 자동화 파이프라인 구축 | 기종별 호환 실패율 |

## Ⅵ. 온디바이스 AI(On-Device AI)에 대한 기술사적 제언

- 핵심 요약 : 민감 데이터의 로컬 처리 원칙, 모델 배포 자동화, 지능형 스케줄러를 갖춘 하이브리드 운영이 바람직함.

1. 사내 메일, 문서 요약, 통화 기록처럼 보안 등급이 높은 데이터는 온디바이스 처리를 기본 원칙으로 정해 두는 것이 바람직함.
2. 공개된 오픈 모델을 단말용 최적화 바이너리로 변환하고 배포하는 과정을 MLOps 파이프라인으로 자동화하는 것이 필요함.
3. 사용자 의도의 복잡도, 배터리 잔량, 네트워크 상태를 함께 판단해 로컬과 클라우드 연산을 전환하는 지능형 스케줄러를 둠.

## Ⅶ. 결론

- 핵심 요약 : 온디바이스 AI는 지능을 단말과 클라우드가 나누어 맡는 하이브리드 AI의 물리적 기반.
- 시사점 : 프라이버시와 응답성의 가치가 커질수록 단말 자원을 얼마나 잘 쓰는지가 경쟁력이 되므로, 경량화와 라우팅 설계가 핵심 과제임.
