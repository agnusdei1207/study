## Ⅰ. 온디바이스 AI(On-Device AI)의 개요

- 개념 : 대규모 중앙 클라우드 데이터센터의 서버 인프라에 의존하지 않고, 스마트폰, 노트북, 태블릿, 스마트 가전, 자율주행차 등 사용자 물리 단말(Device) 내부에 탑재된 **신경망처리장치** (NPU, Neural Processing Unit) 및 **엣지 가속기**를 활용하여 인공지능 모델을 직접 연산·추론하는 탈중앙화 **엣지 AI**(Artificial Intelligence) 기술.
- 배경 및 필요성 : 클라우드 API(Application Programming Interface) 호출 시 발생하는 **네트워크 전송 지연** (Latency), 민감한 개인정보 및 생체 데이터의 외부 유출 위험, 네트워크 음영 지역에서의 서비스 단절, 빅테크의 천문학적 클라우드 서버 운영 비용 한계를 극복하기 위해 하드웨어와 경량 알고리즘의 결합으로 급부상함.
- 핵심 목적 : 네트워크 연결 없는 오프라인 동작 보장, 완벽한 개인정보 프라이버시 보호, **초저지연** (Zero-Latency) 실시간 반응성 확보, 클라우드 서버 비용(TCO, Total Cost of Ownership) 제로화.

## Ⅱ. 온디바이스 AI(On-Device AI)의 핵심 아키텍처 및 동작 메커니즘

온디바이스 AI는 NPU 하드웨어 가속기, 온디바이스 딥러닝 런타임/컴파일러, 초경량화 모델 최적화 기술의 풀스택(Full-Stack) 결합으로 구동됨.

```text
[ 온디바이스 AI 하드웨어-소프트웨어 풀스택 아키텍처 ]

+-----------------------------------------------------------------+
| 4. 온디바이스 애플리케이션 계층 (Applications)                  |
|  - 실시간 통번역, 온디바이스 사진 편집, AI 비서, 생체 보안 인증 |
+--------------------------------┬--------------------------------+
                                 │ 고속 인라인 API 호출
                                 ▼
+-----------------------------------------------------------------+
| 3. 초경량 AI 모델 계층 (Lightweight Models)                    |
|  - sLM(small Language Model) (1B ~ 3B), 모바일 비전 (MobileNet), 오디오 인코더 |
|  - 최적화 기법: AWQ/INT4 양자화, 구조적 가지치기, 지식 증류     |
+--------------------------------┬--------------------------------+
                                 │ 그래프 최적화 및 연산자 매핑
                                 ▼
+-----------------------------------------------------------------+
| 2. 온디바이스 AI 컴파일러 및 런타임 (Compiler & Runtime)       |
|  - ONNX Runtime Mobile, Apple CoreML, Qualcomm QNN SDK          |
|  - 메모리 재사용, 계층 융합(Layer Fusion), 커널 오토튜닝       |
+--------------------------------┬--------------------------------+
                                 │ 저전력 이기종 병렬 가속 명령
                                 ▼
+-----------------------------------------------------------------+
| 1. 온디바이스 이기종 하드웨어 계층 (Heterogeneous SoC Hardware)  |
|  - NPU (전용 텐서 가속기, 40+ TOPS, Tera Operations Per Second) + GPU (병렬 연산) + CPU |
|  - 초고속 LPDDR5X 통합 메모리 (Unified Memory, 고대역폭 확보)   |
+-----------------------------------------------------------------+
```

- **이기종 SoC(System on Chip) 아키텍처** : 범용 CPU(Central Processing Unit)는 제어를 담당하고, 고병렬 GPU(Graphics Processing Unit)는 렌더링 및 대규모 배치 연산을, 전력 효율이 극대화된 NPU(MAC(Multiply-Accumulate) 어레이)는 인공신경망 텐서 연산을 전담.
- **하드웨어 친화적 양자화(Hardware-Aware Quantization)** : 부동소수점(FP32/FP16) 가중치를 NPU의 정수 연산 유닛에 최적화된 INT8/INT4로 변환하여 메모리 대역폭과 전력 소모를 획기적으로 절감.
- **계층 융합(Layer Fusion)** : Convolution, BatchNorm, ReLU(Rectified Linear Unit) 등 연속된 다수의 연산 계층을 단일 GPU/NPU 커널로 결합하여 SRAM(Static Random-Access Memory)과 DRAM(Dynamic Random-Access Memory) 간의 데이터 복사 오버헤드 최소화.
- **하이브리드 AI 라우팅** : 단말 성능으로 충분한 작업은 로컬 NPU에서 즉시 처리하고, 복합 추론이나 최신 웹 검색이 필요한 고난도 작업만 클라우드로 안전하게 분기.

## Ⅲ. 온디바이스 AI(On-Device AI)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 클라우드 AI (Cloud-based AI) | 온디바이스 AI (On-Device AI) | 하이브리드 AI (Hybrid AI) |
| --- | --- | --- | --- |
| **연산 장소** | 대규모 데이터센터 GPU 클러스터 | 사용자 단말 내부 NPU / SoC | 로컬 NPU + 클라우드 GPU 상호 보완 |
| **네트워크 의존성** | 필수 (오프라인 시 서비스 완전 불가) | 불필요 (비행기, 터널 등 완전 독립 동작) | 필수이나 로컬 기능은 오프라인 유지 |
| **지연 시간 (Latency)**| 네트워크 RTT(Round-Trip Time) + 서버 대기 시간 (수백 ms) | 네트워크 제로, 즉각적 실시간 처리 (수 ms) | 태스크 유형에 따라 동적 결정 |
| **개인정보 보호** | 단말 외부 서버로 전송, 유출 리스크 | 기기 내부 메모리에서만 처리 및 소멸 | 민감 정보는 온디바이스에서 마스킹 후 전송 |
| **모델 파라미터 크기**| 수백억 ~ 수조 개 (무제한급) | 수억 ~ 수십억 개 (1B ~ 7B로 제한) | 소형 sLM (단말) + 프론티어 LLM (Large Language Model, 서버) |
| **서버 인프라 비용** | 사용자 수에 비례하여 클라우드 비용 급증 | 0원 (사용자의 단말 연산 자원 소비) | 비용과 품질 간의 최적 트레이드오프 달성 |

- 온디바이스 AI는 단순한 독립 기술이 아니라, 클라우드와 단말이 지능을 분담하는 **하이브리드 AI** (Hybrid AI) 생태계의 핵심 물리적 기반으로 발전하고 있음.

## Ⅳ. 온디바이스 AI(On-Device AI)의 주요 한계점 및 해결 방안

- 단말 하드웨어의 엄격한 메모리 용량 및 배터리 전력 한계 :
  - 한계점 : LLM 구동 시 KV(Key-Value) 캐시와 가중치가 시스템 메모리를 과도하게 점유하여 타 앱 강제 종료 및 급격한 배터리 소모 유발.
  - 해결 방안 : **4비트 양자화** (AWQ), **프루닝** (Pruning), KV 캐시 양자화(FP8) 및 NPU 클럭을 동적으로 제어하는 **DVFS**(Dynamic Voltage and Frequency Scaling) 전력 관리.
- 소형 모델 탑재로 인한 범용 지식 부족 및 복잡한 추론 성능 한계 :
  - 한계점 : 1B~3B 파라미터 수준의 경량 모델은 복잡한 논리 추론이나 전문 지식 질의 시 환각 및 부정확한 결과 출력.
  - 해결 방안 : **온디바이스 RAG** (기기 내 SQLite/경량 벡터 DB(Database)) 결합 및 고난도 질의는 클라우드 LLM으로 토스하는 지능형 오프로딩.
- 안드로이드, iOS, 윈도우 등 이기종 단말 칩셋(NPU) 파편화로 인한 배포 복잡도 :
  - 한계점 : 퀄컴, 애플, 삼성, 인텔 등 벤더마다 전용 런타임과 연산자 지원 범위가 달라 앱 개발사의 유지보수 비용 폭증.
  - 해결 방안 : **ONNX(Open Neural Network Exchange) Runtime** 및 ExecuTorch 등 크로스 플랫폼 표준 추론 엔진 채택 및 CI(Continuous Integration)/CD(Continuous Delivery) 자동 변환 파이프라인 수립.

## Ⅴ. 온디바이스 AI(On-Device AI) 적용 및 발전을 위한 기술사적 제언

- Privacy-First 원칙 기반의 제로트러스트 엔터프라이즈 모바일 환경 구축 : 사내 이메일, 문서 요약, 통화 녹음 등 최고 수준의 보안이 요구되는 데이터는 온디바이스 AI 처리를 기본 원칙으로 수립.
- 신경망 컴파일러(ExecuTorch, MLC-LLM) 기반의 빌드 파이프라인 자동화 : 최신 오픈소스 가중치를 모바일 NPU용 최적화 바이너리로 자동 변환·배포하는 MLOps(Machine Learning Operations) 체계 정립.
- 온디바이스-클라우드 연계 하이브리드 오케스트레이션 게이트웨이 설계 : 사용자 의도의 복잡도, 현재 배터리 잔량, 와이파이 연결 상태를 종합 판단하여 로컬과 클라우드 연산을 실시간 스위칭하는 지능형 스케줄러 구현.
