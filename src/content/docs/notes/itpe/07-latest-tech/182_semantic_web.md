## 연관 키워드

- 시맨틱 웹(Semantic Web), RDF(Resource Description Framework), OWL(Web Ontology Language), SPARQL
- 트리플(Triple), 지식 그래프(Knowledge Graph), 온톨로지(Ontology), 링크드 오픈 데이터(LOD)
- URI(Uniform Resource Identifier), JSON-LD, SKOS, 개체 정합(Entity Resolution), GraphRAG

## Ⅰ. 시맨틱 웹의 개요

- 핵심 요약 : 웹 자원에 의미 메타데이터를 부여해 기계가 연계와 추론을 수행하게 하는 웹이며, 수작업 구축 비용은 LLM 기반 추출과 검증 절차로 보완하는 것이 핵심.
- 개념 : 웹 자원에 표준화된 의미 정보를 부여해 기계가 정보를 자율적으로 연결하고 **논리적 추론** (Logical Inference)을 수행하도록 설계한 분산 웹 체계 (**시맨틱 웹**, Semantic Web).
- 배경 및 필요성 : **온톨로지** (Ontology, 도메인의 개념과 관계를 기계가 읽을 수 있게 명세한 지식 모델)를 사람이 수작업으로 구축하면 비용과 시간이 많이 들고, 기관마다 용어가 달라 연계가 막힘. 이 병목을 줄이기 위해 **거대언어모델** (LLM, Large Language Model)로 **지식 그래프** (Knowledge Graph)를 자동 추출하고, 질의 시 **GraphRAG** (Graph-based Retrieval-Augmented Generation)와 결합하는 방식이 대안으로 검토되고 있음.
- 주요 목적 : 이종 시스템 간 데이터 상호운용성 확보, 기계 간 데이터 자동 연계, 지능형 에이전트의 의사결정 지원.

## Ⅱ. 시맨틱 웹의 특징 및 장점

- 핵심 요약 : 전역 식별, 트리플 모델, 추론, 표준 질의가 결합되어 시스템 간 의미 충돌을 줄이고 암묵적 지식을 자동으로 드러내는 구조.

1. 전역 식별 : 모든 개체에 **URI** (Uniform Resource Identifier, 웹 자원의 전역 고유 식별자)를 부여 → 여러 시스템이 같은 개체를 같은 주소로 지칭해 연계 오류 감소.
2. 트리플 그래프 모델 : 주어-술어-목적어 구조로 관계를 명시 → 연결 경로를 따라 간접 관계까지 탐색 가능.
3. 의미 기반 추론 : 클래스 계층과 속성 정의에 따라 상속, 역관계, 대칭 관계를 자동 유추 → 명시되지 않은 지식을 발견.
4. 표준 질의 : **SPARQL 질의 언어** (SPARQL Protocol and RDF Query Language)로 그래프 패턴을 질의 → 시스템이 달라도 같은 질의 방식을 사용.
5. 기계 가독 직렬화 : **JSON-LD** (JavaScript Object Notation for Linked Data, JSON 형식의 의미 표현)로 웹 문서에 의미 정보를 포함 → 검색엔진과 에이전트가 내용을 해석.

```text
[ 시맨틱 웹 계층 구조 ]

신뢰와 증명 (Trust, Proof)
        ↑
규칙 추론 (SWRL, RIF)
        ↑
온톨로지 어휘 (OWL)
        ↑
스키마와 질의 (RDFS, SPARQL)
        ↑
데이터 모델 (RDF)
        ↑
문법과 직렬화 (XML, JSON-LD, Turtle)
        ↑
식별자와 문자셋 (URI/IRI, Unicode)
```

```text
[ RDF 트리플 구조 ]

주어 (Subject) : 기관 A
        ↓ 술어 (Predicate)
소재지
        ↓ 목적어 (Object)
서울
```

## Ⅲ. 시맨틱 웹의 구조 및 구성 요소

- 핵심 요약 : 식별자와 직렬화 위에 RDF 데이터 모델, 온톨로지 어휘, 규칙 추론, 신뢰 계층이 순서대로 쌓이는 층위 구조.
- **자원 기술 틀** (RDF, Resource Description Framework) : 주어-술어-목적어 **트리플** (Triple)로 자원을 기술하는 W3C 표준 데이터 모델.
- **RDF 스키마** (RDFS, RDF Schema) : 클래스 계층과 속성의 정의역, 치역을 선언하는 기초 어휘 체계.
- **웹 온톨로지 언어** (OWL, Web Ontology Language) : 클래스 간 관계와 공리를 기술하는 언어로, 프로파일에 따라 추론 복잡도가 달라짐.
- **트리플 저장소** (Triple Store) : RDF 트리플을 그대로 저장하고 SPARQL 질의를 처리하는 데이터베이스.
- **SWRL** (Semantic Web Rule Language) : 온톨로지 공리로 표현하기 어려운 조건부 규칙을 기술하는 규칙 언어.

## Ⅳ. 전통적 문서 웹과 시맨틱 웹의 비교

- 핵심 요약 : 문서 웹은 사람이 읽는 링크 중심 구조이고, 시맨틱 웹은 기계가 해석하고 추론하는 개체 중심 구조.
- 비교 대상은 **전통적 문서 웹** (HTML 기반 문서 웹)과 RDF·OWL 기반 시맨틱 웹.

| 비교 축 | 전통적 문서 웹 (HTML) | 시맨틱 웹 (RDF, OWL) |
| --- | --- | --- |
| 데이터 단위 | 사람이 읽는 문서 단위 | 기계가 처리하는 자원과 개체 단위 |
| 링크 의미 | 의미가 없는 하이퍼링크 | 관계 종류가 명시된 간선 |
| 데이터 구조 | 비정형 또는 반정형 텍스트 | 그래프 구조와 트리플 |
| 검색 방식 | 키워드 매칭과 역색인 | 개념 식별자 기반 검색과 논리 추론 |
| 상호운용성 | 사람의 화면 해석에 의존 | 표준 질의 엔드포인트로 기계 간 연계 |
| 추론 가능 여부 | 불가능 (텍스트 파싱만 가능) | 상속, 동치, 대칭, 역관계 추론 가능 |

- 선택 기준 : 문서 열람이 목적이면 문서 웹으로 충분하고, 데이터 간 의미 연계와 추론이 필요하면 시맨틱 웹 구조를 택하는 것이 합리적.

## Ⅴ. 시맨틱 웹의 한계와 방안

- 핵심 요약 : 수작업 구축 비용, 대규모 조인 성능, 기관 간 어휘 불일치, 논리 모순을 자동 추출, 저장 구조 변환, 표준 매핑, 추론기 검사로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 수작업 온톨로지 구축의 비용과 한계 | 도메인 전문가가 모델링해야 해 지식베이스 구축 기간과 비용이 커짐 | **개체명 인식** (NER, Named Entity Recognition)과 트리플 자동 추출로 초안 생성, 추출 신뢰도 점수 부여 후 **휴먼 인 더 루프** (HITL, Human in the Loop) 검증 | 자동 추출 정확도, 검수 반려율 |
| 대규모 트리플의 조인 성능 저하 | 다자간 조인이 많은 SPARQL 질의가 트리플 저장소의 메모리 병목을 일으킴 | **속성 그래프** (Property Graph) 모델로 변환하고, 자주 쓰이는 질의 경로에 사전 인덱싱 적용 | 질의 응답 지연, 메모리 사용량 |
| 기관별 어휘 불일치와 스키마 충돌 | 같은 대상을 기관마다 다른 URI와 네임스페이스로 표현해 데이터 연계가 끊김 | **SKOS** (Simple Knowledge Organization System) 기반 대응 관계 정의, owl:sameAs·skos:exactMatch 매핑, 공공 링크드 오픈 데이터(LOD) 허브 참조 | 개체 정합률, 미매핑 개체 수 |
| 온톨로지 논리 모순 | 공리가 서로 충돌해 어떤 인스턴스도 들어갈 수 없는 클래스가 생김 | 추론기(HermiT, Pellet)로 일관성 검사를 주기적으로 수행하고 모순 클래스 제거 | 모순 클래스 수, 일관성 검사 소요 시간 |

## Ⅵ. 시맨틱 웹에 대한 기술사적 제언

- 핵심 요약 : 생성형 AI의 추출 속도와 사람의 검증, 표준 어휘의 재사용을 함께 묶어 지식 그래프를 신뢰할 수 있는 공공 자산으로 관리.

1. 데이터 관리 조직은 LLM이 추출한 트리플을 그대로 쓰지 않고, 신뢰도 점수와 도메인 전문가의 검수를 거친 뒤에 지식 그래프에 반영하는 절차를 둘 필요가 있다.
2. 정보 기획 조직은 새로 만드는 온톨로지를 **Dublin Core** 같은 기존 표준 어휘 위에 정의해 재사용성과 상호운용성을 확보하는 것이 바람직하다.
3. 정보보호 조직은 생성형 모델이 만든 지식의 출처와 근거를 기록하는 추적 체계를 두어, GraphRAG 응답의 근거를 사후에 검증할 수 있게 할 필요가 있다.
4. 품질 조직은 추론 결과와 개체 연계 정확도를 정답 집합으로 주기 평가해, 어휘 매핑과 추론 규칙을 개선하는 순환 체계를 운영하는 것이 필요하다.

## Ⅶ. 결론

- 핵심 요약 : 시맨틱 웹은 URI, RDF, 온톨로지, 추론을 층으로 쌓아 웹 자원의 의미를 기계가 다루게 하는 표준 체계.
- 수작업 구축의 한계는 LLM 추출과 사람의 검증으로 보완하는 방향이 현실적이므로, 의미 표준과 검증 체계를 함께 갖추는 것이 핵심 과제임.
