## 답안 골격
```text
[에이전틱 AI] ◀━━ 머리: Ⅶ 내 의견 (목표 지향 자율 루프에 인간 개입(HITL) 가드레일을 결합한 신뢰성 확보)
 ┃
 ┣━ Ⅰ 개요 ───── 단발성 질의응답(Prompt-Response) 한계 → 복합 목표를 자율 분해·계획·도구사용·반조하는 지능체
 ┣━ Ⅱ 특징 ───── 자율적 목표 지향성 · 다단계 계획(Planning) · 외부 도구 활용(Tool Use) · 환경 피드백 반영(Self-Reflection)
 ┣━ Ⅲ 구조 ───── 두뇌(LLM/LRM) + 메모리(단기/장기) + 도구 세트(Tools/API) + 계획기(Planner)
 ┣━ Ⅳ 흐름 ───── ① 목표 수신 → ② 태스크 분해·계획 수립 → ③ 도구 실행(Action) → ④ 관찰(Observation) → ⑤ 자가 반조·완료
 ┣━ Ⅴ 비교 ───── 생성형 AI(Chatbot) vs 에이전틱 AI (수동적 텍스트 생성 vs 환경과 상호작용하는 능동적 과업 완수)
 ┗━ Ⅵ 실무 ───── 무한 루프(Infinite Loop) / 도구 실행 권한 남용(Privilege Abuse) / 환각 누적으로 인한 복합 오류
```

## 한 줄 본질
- 사람이 매 단계 프롬프트를 입력해야 하는 수동적 챗봇의 생산성 한계 → LLM이 스스로 목표를 하위 태스크로 쪼개고 API·도구를 호출하며 결과를 검증하는 자율 루프(Perception-Plan-Action-Reflection) 구축 → 엔드투엔드 복합 업무 자동화 / 통제 불능 및 예기치 못한 API 부작용 리스크 수반

```text
[에이전틱 AI의 자율 제어 루프 아키텍처]
                    +-------------------------------------+
                    |       목표 입력 (Goal Prompt)       |
                    +-------------------+-----------------+
                                        |
                                        v
                    +-------------------------------------+
                    |   [두뇌] LLM / 추론 엔진 (Core)      |
                    |   - ReAct 사고 (Thought)            |
                    |   - 의사결정 및 자가 반조(Reflection) |
                    +---------+-----------------+---------+
                              ^                 |
           (지식 검색/맥락)   |                 | (도구 호출 의도)
                              v                 v
+-------------------------------+             +-------------------------------+
|      [메모리] Memory          |             |       [도구 세트] Tools       |
| - 단기: 컨텍스트/스크래치패드 |             | - 웹 브라우징 / 코드 실행기   |

+-------------------------------+             +---------------+---------------+
                              ^                               |
                              |        (실행 결과 피드백)     |
                              +-------------------------------+
                                      [관찰 (Observation)]
```

## 핵심 용어
- ReAct(Reasoning + Acting): 모델이 다음 행동을 결정하기 전에 "생각(Thought) → 행동(Action) → 관찰(Observation)"의 순환 루프를 거치도록 유도하는 프롬프트 및 실행 프레임워크
- 도구 사용(Tool Use / Function Calling): 텍스트 생성에 갇힌 LLM이 외부 계산기, DB 쿼리, 웹 검색, 터미널 명령 등의 API 규격을 인식하고 파라미터를 생성해 호출하는 메커니즘
- 자가 반조(Self-Reflection): 도구 실행 결과가 실패하거나 비정상일 때 에러 로그를 분석하여 자신의 이전 계획을 스스로 수정(Plan Update)하는 자기 교정 역량

## 핵심 통찰
- 에이전틱 AI의 본질은 "더 똑똑한 모델"이 아니라, 모델을 감싸고 있는 "제어 루프(Control Loop)와 상태 관리 아키텍처"에 있음
- 계획 수립 단계가 길어질수록 초반 사소한 판단 착오가 눈덩이처럼 불어나는 "오차 복합(Compounding Errors)" 문제가 발생하므로, 주기적인 상태 리셋과 검증 지점 설정이 필수
- 완전 자율(Full Autonomy)보다는 고위험 작업(DB 삭제, 금융 결제, 이메일 발송) 직전에 사람의 승인을 요구하는 HITL(Human-in-the-Loop)이 실무 도입의 선결 과제

## 이웃 토픽과 구분
- 에이전틱 AI vs 생성형 AI: 생성형 AI는 텍스트·이미지를 만들어 내는 생성 엔진(Content Generation) / 에이전틱 AI는 생성 엔진을 두뇌로 삼아 외부 세계의 상태를 변경하는 행동 주체(Task Execution)

## 문제·원인·대책
- 적용 상황: 클라우드 인프라 자율 장애 복구 에이전트 운영 중 비정상 종료 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 에이전트가 동일 실패 명령을 반복 호출(무한 루프) | 도구 에러 메시지에 대한 반조 및 종료 조건 누락 | 최대 재시도(Max Iteration) 한도 설정 및 에러 요약 반조 주입 | 자원 낭비 차단 및 조기 안전 종료 |
| 테스트 데이터 삭제 명령이 프로덕션 DB에 실행됨 | 도구 권한 분리 부재 및 실행 전 검증 절차 누락 | 최소 권한 원칙(RBAC) 적용 및 파괴적 명령 시 HITL 승인 게이트 연동 | 인프라 오작동 방지 및 데이터 무결성 보장 |
| 컨텍스트 윈도우 한도 초과로 이전 작업 기억 상실 | 장시간 루프 실행에 따른 관찰(Observation) 로그 누적 | 스크래치패드 중간 요약(Compaction) 및 계층형 메모리(LangGraph) 도입 | 토큰 비용 절감 및 장기 컨텍스트 일관성 유지 |
