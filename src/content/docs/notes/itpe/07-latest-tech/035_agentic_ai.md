## Ⅰ. 에이전틱 AI(Agentic AI)의 개요

- 개념 : 사용자의 단일 입력에 대해 수동적으로 텍스트를 출력하는 일회성 챗봇을 넘어, 복합적인 **상위 목표** (Goal)를 부여받았을 때 스스로 하위 작업들을 계획(Planning)하고, 외부 **도구** (Tool)를 직접 실행하며, 환경의 피드백을 **관찰** (Observation)하여 중간 오류를 자체 수정(Self-Reflection)하면서 자율적으로 문제를 완수하는 능동형 인공지능 패러다임.
- 배경 및 필요성 : 단순 LLM은 최신 정보 검색, 실제 시스템 명령 실행, 장기적인 다단계 워크플로우 수행이 불가능한 한계가 존재하여, 소프트웨어 개발, 업무 자동화, 로봇 제어 등 실질적 현실 행동을 대행하는 에이전트 기술이 핵심 트렌드로 대두됨.
- 핵심 목적 : 복잡한 엔드투엔드 비즈니스 프로세스의 완전 자율화, 인간 개입 최소화를 통한 생산성 비약적 향상, 환경 변화에 동적으로 적응하는 **회복 탄력성** (Resilience) 확보.

## Ⅱ. 에이전틱 AI(Agentic AI)의 핵심 아키텍처 및 동작 메커니즘

에이전틱 AI는 목표 계획 수립, 메모리(단기/장기), 도구 실행, 자기 반성 루프의 **4대 핵심 컴포넌트** 가 결합된 자율 사이클로 동작함.

```text
[ 에이전틱 AI 핵심 4대 구성 요소 및 자율 행동 루프 ]

+-----------------------------------------------------------------+
|               에이전트 두뇌 (Agent Core / LLM Brain)            |
|  - 페르소나/역할 정의 (System Prompt) - 상태 머신 제어 (State) |
+--------------------------------┬--------------------------------+
                                 │
         ┌───────────────────────┼───────────────────────┐
         ▼                       ▼                       ▼
+-----------------+     +-----------------+     +-----------------+
| 계획 (Planning) |     | 메모리 (Memory) |     | 도구 (Tools)    |
| - 서브골 분해   |     | - 단기: Context |     | - 웹 브라우저   |
| - CoT / ToT 탐색|     | - 장기: 벡터 DB |     | - Python 샌드박스|
| - 우선순위 결정 |     | - 에피소딕 기억 |     | - 사내 REST API |
+--------┬--------+     +--------┬--------+     +--------┬--------+
         │                       │                       │
         └───────────────────────┼───────────────────────┘
                                 ▼
+-----------------------------------------------------------------+
| 실행 및 환경 관찰 루프 (ReAct Loop)                             |
|  1. 생각 (Thought)   : 현재 상태 분석 및 다음 취할 조치 결정    |
|  2. 행동 (Action)    : 외부 도구(API) 호출 파라미터 생성        |
|  3. 관찰 (Observation): 도구 실행 결과 및 에러 코드 수신       |
|  4. 반성 (Reflection): 결과 검증 ──► 오류 시 계획 수정 재시도  |
+-----------------------------------------------------------------+
```

- **계획 수립(Planning)** : 복잡한 사용자 요청(예: "경쟁사 재무제표를 분석하여 보고서 작성")을 10개 이상의 원자적 서브 태스크로 분해하고 의존성 트리 생성.
- **메모리 아키텍처** : 대화 컨텍스트 윈도우 기반의 **단기 메모리** 와, 이전 세션의 경험 및 사내 지식을 보관하는 벡터 DB 기반 **장기 메모리** (Episodic Memory) 통합.
- **도구 호출(Tool Calling / Function Calling)** : 모델이 자연어 대신 계산기, SQL 쿼리기, 깃허브 API 등 외부 인터페이스를 정형 JSON 규격으로 자율 호출.
- **자기 반성(Self-Reflection)** : 코드 컴파일 에러나 API 실패 응답을 받으면 포기하지 않고 에러 트레이스를 분석하여 코드를 스스로 수정(Self-Debugging)하여 재실행.

## Ⅲ. 에이전틱 AI(Agentic AI)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 규칙 기반 자동화 (RPA) | 전통적 생성형 AI (LLM 챗봇) | 에이전틱 AI (Agentic AI) |
| --- | --- | --- | --- |
| **동작 방식** | 사전에 정의된 고정 스크립트 순차 실행 | 프롬프트 입력에 대한 1회성 확률적 텍스트 생성 | 목표 달성을 위해 계획, 도구 호출, 수정을 자율 반복 |
| **예외 상황 처리** | UI 좌표 변경이나 에러 발생 시 즉각 셧다운 | 사용자가 추가 프롬프트로 지시해야 수정 | 스스로 에러 메시지를 읽고 대안 경로를 탐색하여 극복 |
| **도구 활용 능력** | 지정된 애플리케이션만 기계적 매크로 제어 | 도구 사용 불가 (순수 텍스트 생성에 국한) | 수십 개의 API, DB, 셸 스크립트를 상황에 맞게 자율 호출 |
| **추론 능력** | 추론 능력 없음 | 언어적 추론 가능하나 행동 불가 | 추론(Reasoning)과 행동(Action)이 상호 결합(ReAct) |
| **대표 기술/도구** | UiPath, Automation Anywhere | ChatGPT 기본 웹 UI | LangGraph, AutoGen, CrewAI, Claude Computer Use |

- 에이전틱 AI는 RPA의 실행력과 LLM의 지능적 판단력을 완벽히 융합하여 '소프트웨어 자율 대리인'을 구현하는 차세대 표준임.

## Ⅳ. 에이전틱 AI(Agentic AI)의 주요 한계점 및 해결 방안

- 도구 호출 실패 및 잘못된 추론으로 인한 무한 루프(Deadlock) 및 연쇄 오류 :
  - 한계점 : 에러 발생 시 동일한 잘못된 행동을 반복하며 API 토큰을 소진하고 시스템이 멈추는 현상.
  - 해결 방안 : **상태 기반 그래프** (StateGraph) 워크플로우를 통한 명시적 분기 제어, 최대 재시도 횟수 제한 및 서킷 브레이커 도입.
- 과도한 권한 대리(Excessive Agency)로 인한 치명적 시스템 파괴 위험 :
  - 한계점 : 에이전트가 파일 삭제(`rm -rf`), 대규모 송금, 비인가 DB 변경 명령을 자율적으로 실행할 위험.
  - 해결 방안 : 고위험 액션에 대한 **Human-in-the-Loop** (HITL) 관리자 승인 게이트 필수화, **도구 권한 최소화** (PoLP).
- 다단계 도구 호출에 따른 긴 응답 지연(Latency) 및 API 비용 폭증 :
  - 한계점 : 하나의 태스크를 해결하기 위해 수십 번의 LLM 왕복 호출이 발생하여 수 분의 대기 시간과 수 달러의 비용 소모.
  - 해결 방안 : 도구 호출 전용 초경량 파인튜닝 sLM 분기, **병렬 도구 호출** (Parallel Tool Calling) 및 시맨틱 캐싱 적용.

## Ⅴ. 에이전틱 AI(Agentic AI) 적용 및 발전을 위한 기술사적 제언

- Anthropic Model Context Protocol(MCP) 표준 인터페이스 적극 수용 : 레거시 엔터프라이즈 시스템과 사내 데이터베이스를 표준화된 MCP 서버로 노출하여 에이전트 호환성 확보.
- 상태 영속화(Stateful Persistence) 기반 장애 복구 아키텍처 수립 : 네트워크 단절이나 노드 장애 시에도 에이전트의 이전 실행 상태를 복원할 수 있는 체크포인팅(Checkpointer) 인프라 구축.
- Wasm/컨테이너 기반 마이크로 샌드박스 격리 환경 강제 : 에이전트가 생성하고 실행하는 Python 코드 및 셸 스크립트를 완벽히 격리된 일회성 샌드박스 내에서만 구동하도록 보안 설계.
