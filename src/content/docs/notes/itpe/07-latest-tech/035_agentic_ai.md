## 연관 키워드

- 에이전틱 AI(Agentic AI), 자율 에이전트, 대규모 언어 모델(LLM)
- 계획 수립(Planning), 메모리(Memory), 도구 호출(Tool Calling), 자기 반성(Self-Reflection)
- ReAct, MCP(Model Context Protocol), 사람 개입 승인(HITL), 최소 권한 원칙(PoLP)
- 상태 기반 그래프(StateGraph), 서킷 브레이커, 샌드박스

## Ⅰ. 에이전틱 AI(Agentic AI)의 개요

- 핵심 요약 : 목표를 받으면 계획, 도구 실행, 자기 교정을 스스로 반복하는 자율형 인공지능 패러다임.
- 개념 : 한 번 질문에 답하는 챗봇과 달리, 상위 목표를 받아 하위 작업을 계획하고 외부 도구를 직접 실행하며 관찰 결과로 오류를 고쳐 목표를 완수하는 능동형 인공지능 (**에이전틱 AI** (Agentic AI)).
- 배경 및 필요성 : 대규모 언어 모델(LLM, Large Language Model)만으로는 최신 정보 조회, 실제 시스템 명령 실행, 다단계 업무 수행이 어려워, 업무를 대신 수행하는 에이전트 기술이 주목받음.
- 주요 목적 : 복합 업무 프로세스의 자율화로 사람의 개입을 줄이고, 환경 변화에 적응하는 회복 탄력성 확보.

## Ⅱ. 에이전틱 AI(Agentic AI)의 특징 및 장점

- 핵심 요약 : 계획, 메모리, 도구, 자기 반성이 맞물려 사람의 세부 지시 없이 작업을 끝까지 수행하는 능력.

1. **계획 수립** (Planning) : 복잡한 요청을 하위 작업으로 분해하고 의존 관계를 정함 → 목표 누락 감소.
2. **메모리** (Memory) : 대화 문맥을 담는 단기 메모리와 벡터 데이터베이스(Vector DB)에 쌓는 장기 메모리를 결합 → 과거 경험과 사내 지식 재활용.
3. **도구 호출** (Tool Calling) : 계산기, SQL, API 같은 외부 기능을 정형 JSON 형식으로 호출 → 텍스트 생성을 넘는 실행력 확보.
4. **자기 반성** (Self-Reflection) : 실행 오류 메시지를 읽고 스스로 수정해 재시도 → 사람의 중간 개입 감소.

## Ⅲ. 에이전틱 AI(Agentic AI)의 구조 (흐름)

- 핵심 요약 : 네 가지 구성 요소가 에이전트 두뇌 아래에서 ReAct 실행 루프를 반복하는 구조.
- **ReAct** (Reasoning and Acting) : 추론한 내용을 바탕으로 행동하고, 그 결과를 다시 추론에 반영하는 실행 패턴.

```text
[ 에이전트 핵심 구성 요소 ]

  목표 (Goal) 입력
        ↓
  에이전트 두뇌 (LLM, 역할과 상태 제어)
        ↓
  계획 · 메모리 · 도구 (3요소 결합)
```

```text
[ ReAct 실행 루프 ]

  생각 (Thought) : 다음 행동 결정
        ↓
  행동 (Action) : 도구 호출 생성
        ↓
  관찰 (Observation) : 실행 결과 수신
        ↓
  반성 (Reflection) : 오류면 계획 수정
        ↓ (목표 미달성 시 반복)
  목표 달성 시 종료
```

## Ⅳ. 에이전틱 AI(Agentic AI)의 비교

- 핵심 요약 : 규칙 기반 자동화와 단순 생성형 AI의 한계를 넘어, 추론과 행동을 함께 수행하는 점이 차별점.

| 비교 항목 | 규칙 기반 자동화 (RPA, Robotic Process Automation) | 생성형 AI 챗봇 (LLM 단독) | 에이전틱 AI (Agentic AI) |
| --- | --- | --- | --- |
| 동작 방식 | 정해진 스크립트 순차 실행 | 프롬프트에 대한 1회 텍스트 생성 | 계획, 도구 호출, 수정을 목표 달성까지 반복 |
| 예외 상황 처리 | 화면 변경이나 오류 시 중단 | 사용자가 추가 프롬프트로 수정 지시 | 오류 메시지를 읽고 대안 경로 탐색 |
| 도구 활용 | 지정된 애플리케이션 매크로 제어 | 도구 사용 불가 | API, DB, 셸 등을 상황에 맞게 호출 |
| 추론 능력 | 없음 | 언어적 추론은 가능하나 행동 불가 | 추론과 행동의 결합 (ReAct) |
| 대표 도구 | UiPath, Automation Anywhere | 일반 대화형 챗봇 웹 UI | LangGraph, AutoGen, CrewAI |

- 선택 기준 : 절차가 고정되고 예외가 적으면 RPA, 문서 생성과 질의응답이 목적이면 LLM, 목표 달성 경로가 가변적이면 에이전틱 AI를 적용함.

## Ⅴ. 에이전틱 AI(Agentic AI)의 한계와 방안

- 핵심 요약 : 무한 루프, 과도한 권한, 지연과 비용 문제를 상태 제어, 권한 통제, 비용 최적화로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 무한 루프와 연쇄 오류 | 같은 실패 행동 반복 → 토큰 소진, 시스템 정지 | **상태 기반 그래프** (StateGraph)로 분기 명시, **서킷 브레이커** (Circuit Breaker) 도입 | 재시도 횟수, 중단 건수 |
| 과도한 권한 행사 (Excessive Agency) | 파일 삭제, 송금, DB 변경을 자율 실행할 위험 | **사람 개입 승인 게이트** (HITL, Human-in-the-Loop), **최소 권한 원칙** (PoLP, Principle of Least Privilege) 적용 | 승인 대기 건수, 권한 위반 탐지 건수 |
| 다회 호출에 따른 지연과 비용 | 한 작업에 LLM 왕복 호출이 여러 번 발생 | **병렬 도구 호출** (Parallel Tool Calling), 시맨틱 캐싱, 단순 분기의 소형 모델 활용 | 작업당 응답 시간, 토큰 비용 |

## Ⅵ. 에이전틱 AI(Agentic AI)에 대한 기술사적 제언

- 핵심 요약 : 표준 인터페이스, 상태 복구, 실행 격리를 먼저 갖춘 뒤 권한을 단계적으로 넓히는 도입이 바람직함.

1. 사내 레거시 시스템과 데이터베이스는 **MCP** (Model Context Protocol, 모델과 외부 도구를 잇는 개방형 연결 규격) 서버로 노출하여 에이전트 연결 방식을 표준화하는 것이 바람직함.
2. 네트워크 단절이나 노드 장애에도 실행 상태를 되살릴 수 있도록 체크포인트 기반 상태 저장을 인프라 기본 요건으로 둠.
3. 에이전트가 생성한 코드와 셸 명령은 일회성 샌드박스 안에서만 실행하도록 격리 정책을 강제함.

## Ⅶ. 결론

- 핵심 요약 : 에이전틱 AI는 RPA의 실행력과 LLM의 판단력을 결합한 소프트웨어 자율 대리인 체계.
- 시사점 : 자율성의 폭은 권한 통제와 상태 복구 설계로 정해지므로, 이 설계의 완성도가 도입 성패를 가름.
