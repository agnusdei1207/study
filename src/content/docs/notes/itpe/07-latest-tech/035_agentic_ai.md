## 30초 인출

- 본질: **에이전틱 AI(Agentic AI)** 는 단순한 질의응답 텍스트 생성을 넘어 사용자가 부여한 상위 목표(Goal)를 스스로 하위 작업으로 분해하고, 외부 도구(API)를 호출하며, 결과를 관찰·반성(Reflection)하여 자율적으로 완수하는 지능형 실행 시스템
- 메커니즘: 프로파일링 및 장단기 메모리(Memory)를 기반으로 목표를 계획(Planning)하고, ReAct 루프를 통해 도구(Tool)를 실행한 뒤 비평(Critic)을 통해 정책을 자가 수정
- 통찰: 자율적 외부 시스템 조작으로 인한 무한 루프 비용 발생과 비가역적 데이터 삭제 위험이 존재하므로 단계별 승인(HITL) 및 멱등성(Idempotency) 보장 게이트웨이 구축 필수

<details><summary>핵심 용어</summary>

- **에이전틱 AI (Agentic AI)** : 환경과 상호작용하며 목표 지향적 행동을 자율적으로 기획·실행·조정하는 차세대 AI 패러다임.
- **ReAct (Reasoning and Acting)** : 생각(Thought)-행동(Action)-관찰(Observation)의 삼위일체 순환을 통해 복잡한 과업을 해결하는 에이전트 핵심 패턴.
- **자기 반성 (Self-Reflection / Reflexion)** : 에이전트가 이전 실행의 실패 원인을 자체 평가하여 메모리에 교훈을 기록하고 후속 계획을 수정하는 메커니즘.
- **인간 개입 (Human-in-the-Loop, HITL)** : 금융 결제, 데이터 삭제 등 치명적인 비가역적 액션 실행 전 인간의 명시적 승인을 거치도록 통제하는 안전장치.
- **함수 호출 (Function Calling / Tool Use)** : LLM이 정형화된 JSON 포맷으로 외부 REST API 호출 인수를 생성하고 시스템이 이를 실행하는 인터페이스.

</details>

## 2~4교시 25점 답안

## Ⅰ. 에이전틱 AI의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **에이전틱 AI(Agentic AI)** 는 수동적인 단답형 질의응답에 머무르지 않고, 인간의 복합적인 지시를 스스로 해석하여 구체적인 실행 계획을 수립하고, 다양한 소프트웨어 도구(API, DB, 웹 브라우저)를 능동적으로 제어하여 최종 목적을 완수하는 자율 실행형 인공지능 |
| 목적 | 인간의 개입이 최소화된 엔드투엔드 업무 자동화 달성, 다단계 복잡 문제의 자율 해결, 지식 노동 생산성의 획기적 도약 |

## Ⅱ. 에이전틱 AI의 4대 핵심 구성요소 및 특징

| 구분 | 4대 구성요소 | 세부 공학적 기능 및 특징 |
|---|---|---|
| **프로파일 (Profile)** | 역할 및 페르소나 정의 | 에이전트의 성격, 전문 도메인, 행동 지침, 권한 범위 및 금지 사항 명시 |
| **메모리 (Memory)** | 맥락 및 경험의 축적 | 단기 메모리(작업 컨텍스트/대화 버퍼)와 장기 메모리(벡터 DB 기반 과거 경험 회상) 운용 |
| **계획 (Planning)** | 작업 분해 및 자기 반성 | 복합 과업의 하위 단계 분해(Decomposition), 생각의 사슬(CoT), 실패 시 경로 재수정 |
| **행동 (Action)** | 외부 도구 실행 및 피드백 | 웹 브라우징, SQL 쿼리, 파일 생성, 외부 SaaS API 호출 및 실행 결과(Observation) 수집 |

## Ⅲ. 에이전틱 AI 4계층 아키텍처 및 자율 루프 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ 에이전틱 AI 자율 의사결정 및 실행 아키텍처 ]           │
└────────────────────────────────────────────────────────────────────────┘
                                    │
 [ 사용자 목표 주입 (High-Level Goal) ]
  예: "경쟁사 신제품 가격을 조사하여 엑셀 리포트로 정리하고 이메일 발송해"
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [ 1. 계획 및 오케스트레이션 계층 (Planning & State Engine) ]           │
│  - Task 분해: 웹 스크래핑 ──> 데이터 정제 ──> 엑셀 생성 ──> 메일 발송  │
│  - 서브골 우선순위 큐(Queue) 및 DAG 실행 그래프 생성                  │
└────────────────────────────────────────────────────────────────────────┘
                                    │
 ┌──────────────────────────────────┴──────────────────────────────────┐
 │                                                                     │
 ▼                                                                     ▼
[ 2. 인지 및 추론 루프 (ReAct) ]                              [ 3. 도구 실행 및 환경 계층 ]
 - Thought: "경쟁사 웹사이트의 가격 테이블 확인 필요"            - Web Browser (Playwright)
 - Action: `call_api(fetch_url, url="...")` ──────────────────► - Code Interpreter (Python)
 - Observation: "HTTP 200 반환, 데이터 수집 완료" ◄──────────── - SQL Database / ERP API
 └──────────────────────────────────┬──────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [ 4. 자가 반성 및 안전 통제 계층 (Reflection & HITL Gate) ]             │
│  - 자기 평가: 수집된 데이터의 결측 여부 및 엑셀 수식 무결성 검증        │
│  - HITL 승인 게이트: "이메일 외부 발송 전 담당자 승인 팝업 대기"        │
└────────────────────────────────────────────────────────────────────────┘
```

| 자율 루프 단계 | 에이전트 내부 활동 | 제어 및 안전 통제 |
|---|---|---|
| **1. 의도 분해** | 사용자 목표를 단위 실행 가능한 하위 액션들로 쪼갬 | 허용되지 않은 비인가 액션 사전 차단 |
| **2. 도구 디스패치** | LLM Function Calling을 통한 JSON 파라미터 생성 | 파라미터 스키마 밸리데이션(Pydantic) |
| **3. 환경 상호작용** | 샌드박스 내부에서 안전하게 스크립트 실행 | 실행 시간(Timeout=30s) 및 자원 격리 |
| **4. 결과 관찰·반성** | 실행 결과가 목표에 부합하는지 비평(Critic) | 실패 시 이전 단계로 롤백 및 대체 경로 재탐색 |

## Ⅳ. 단순 챗봇 vs Copilot vs 자율 에이전트(Agentic AI) 비교

| 비교 항목 | 단순 생성형 챗봇 (Chatbot) | 증강형 비서 (Copilot) | 자율형 에이전트 (Agentic AI) |
|---|---|---|---|
| **상호작용 방식** | 1문 1답 단답형 턴(Turn) | 인간의 작업 도중 실시간 추천/완성 | 상위 목표 부여 후 자율 다단계 완결 |
| **도구 활용성** | 텍스트 생성에 국한 (No Tool) | 사전 정의된 전용 도구 보조 활용 | 수십 개 이종 도구 자율 조합 호출 |
| **자율성 수준** | 레벨 1 (인간 전적 의존) | 레벨 2 (인간 주도, AI 보조) | 레벨 4~5 (AI 주도 자율 실행) |
| **오류 수정** | 사용자가 다시 질문해야 함 | 사용자가 수정 코드 직접 선택 | 실패 시 스스로 오류 원인 분석 후 재시도 |
| **대표 사례** | 초기 ChatGPT, 검색 챗봇 | GitHub Copilot, MS 365 Copilot | Devin, AutoGPT, Claude Computer Use |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 도구 호출 오류나 환각으로 인해 실패한 단계를 무한 반복하여 토큰과 API 비용이 폭증 | 최대 실행 스텝 수(Max Steps=15) 및 루프 감지기(Loop Detector)를 배치하여 동일 행동 3회 반복 시 즉시 중단 |
| 에이전트가 외부 시스템의 금융 결제나 데이터베이스 영구 삭제 명령을 무단 실행 | 중요 비즈니스 쓰기(Write/Delete) API 호출 직전 인간의 승인을 강제하는 Human-in-the-Loop(HITL) 게이트웨이 의무화 |

## Ⅵ. 제언

안전한 에이전트 자율성을 구현하기 위해 모든 도구 호출을 격리된 도커(Docker) 샌드박스에서 구동하고, 상태 롤백이 가능한 트랜잭션 메모리 아키텍처 구축.

```text
[ 에이전트 Action 명령 발행 ]
               │
               ▼
[ 에이전트 보안 샌드박스 게이트웨이 ]
   ├── Step 1: 조회(Read) 작업 ──> [ 즉시 샌드박스 API 자동 실행 ]
   ├── Step 2: 변경(Write) 작업 ──> [ 트랜잭션 스냅샷 저장 후 시뮬레이션 ]
   └── Step 3: 고위험(Payment/Drop) ──> [ Slack/이메일 기반 관리자 원클릭 승인 ]
               │
               ▼ (승인 완료 시)
[ 실제 엔터프라이즈 시스템 반영 및 세부 감사 증적 로깅 ]
```

| 구분 | 무통제 자율 에이전트 실행 | 제언: HITL 결합 보안 샌드박스 |
|---|---|---|
| **실행 안전성** | 잘못된 쿼리로 실서버 DB 테이블 손실 | 읽기/쓰기 권한 분리 및 샌드박스 격리 검증 |
| **비용 통제** | 무한 루프로 1회 작업에 수백 달러 과금 | 작업별 최대 토큰 예산 캡핑으로 비용 보장 |
| **책임성 (Audit)** | 어떤 근거로 도구가 실행되었는지 불명 | Thought-Action-Observation 전 과정 WORM 감사 기록 |
