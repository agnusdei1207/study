## 한 줄 본질
- 언어 모델이 단어를 생성할 때마다 기억해야 하는 KV 캐시를 위해 최대 길이만큼 통째로 연속 메모리를 잡아두면 VRAM의 80%가 허공에 날아감 → 운영체제(OS)의 가상 메모리 페이징처럼 KV 캐시를 작은 블록 단위로 쪼개 비연속적인 빈 메모리에 자유롭게 배치 → GPU 메모리 낭비 4% 미만 압축 및 동시 처리량 4배 폭증

## 핵심 용어
- KV 캐시(Key-Value Cache): 이전 생성된 토큰들의 어텐션 Key, Value 행렬을 메모리에 저장해 두어, 다음 토큰을 생성할 때 과거 토큰들을 매번 중복 연산하지 않게 하는 필수 캐시
- 블록 테이블(Block Table): 프로세스의 논리적 토큰 시퀀스 블록 번호를 물리적 GPU VRAM의 페이지 번호와 일대일로 연결해 주는 매핑 색인 테이블
- 쓰기 시 복사(Copy-on-Write, CoW): 빔 서치(Beam Search)나 병렬 생성 시, 동일한 프롬프트의 KV 캐시 블록을 여러 요청이 읽기 전용으로 공유하다가, 서로 다른 토큰이 생성되는 분기점에서만 물리 블록을 새로 복사하여 메모리를 아끼는 기술

## 핵심 통찰
- "컴퓨터 구조의 고전적 지혜가 AI의 병목을 풀다": 1960년대 운영체제가 물리 메모리 단편화를 해결하기 위해 고안한 '가상 메모리 페이징'을 60년 뒤 최신 LLM의 KV 캐시 서빙 병목에 그대로 적용하여 대성공을 거둠
- 배치 크기(Batch Size)의 기적: GPU의 연산 코어는 놀고 있는데 KV 캐시가 VRAM을 다 차지해 동시 요청을 4개밖에 못 받던 환경에서, PagedAttention을 통해 낭비 메모리를 없애자 동시 배치 크기를 16~32개로 늘려 전체 처리량이 4배 급증함
- 프롬프트 공유의 효율화: 챗봇에서 수천 명의 사용자가 동일한 4,000토큰짜리 사내 규정 시스템 프롬프트를 조회할 때, 해당 시스템 프롬프트의 물리 블록을 단 하나만 띄워두고 모든 사용자가 참조하므로 VRAM 사용량이 극적으로 감소함

## 이웃 토픽과 구분
- 플래시 어텐션(FlashAttention) vs 페이지드 어텐션(PagedAttention): FlashAttention은 훈련 및 단일 추론 시 GPU SRAM-HBM 간 IO 대역폭을 최적화하는 하드웨어 가속 알고리즘 / PagedAttention은 다중 사용자 서빙 시 VRAM 단편화를 없애는 메모리 가상화 아키텍처

## 문제·원인·대책
- 적용 상황: 수만 명의 직원이 동시 접속하는 사내 LLM 추론 클러스터 서빙 최적화
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| GPU 메모리가 90% 이상 점유되었음에도 실제 동시 처리 요청 수가 5건 미만에 불과 | 요청별 최대 출력 길이를 가정한 연속 메모리 사전 할당으로 인한 내부 단편화 | vLLM 프레임워크 기반 PagedAttention 서빙 엔진 전면 교체 | 동일 GPU 클러스터에서 동시 처리량 3.8배 향상 |
| 블록 크기를 8로 설정 시 블록 테이블 조회 오버헤드가 증가하여 지연시간 발생 | 지나치게 작은 블록 단위로 인한 메타데이터 관리 부하 | 워크로드 특성에 맞춰 블록 크기를 16 또는 32로 최적화 튜닝 | 메타데이터 오버헤드 50% 절감 및 처리량 극대화 |
| 긴 프롬프트를 공유하는 챗봇 환경에서 메모리 중복 적재 발생 | 다중 세션 간 공통 시스템 프롬프트의 개별 인스턴스화 | PagedAttention의 접두사 캐싱(Prefix Caching) 활성화 | 공통 프롬프트 메모리 90% 절감 및 초기 응답 5배 가속 |
