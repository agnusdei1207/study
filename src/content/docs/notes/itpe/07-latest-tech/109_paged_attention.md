## 30초 인출

- 본질: **페이지드 어텐션 (PagedAttention)** 은 OS의 가상 메모리 페이징(Virtual Memory Paging) 원리를 LLM 서빙에 도입하여, 동적으로 팽창하는 KV 캐시(Key-Value Cache)를 비연속적 물리 GPU 메모리 블록에 동적 할당·매핑하는 고효율 메모리 관리 어텐션 알고리즘
- 메커니즘: 연속적인 시퀀스 토큰을 고정 크기 논리 블록으로 분할하고 블록 테이블(Block Table)을 통해 물리 메모리 블록과 사상한 후 전용 CUDA 어텐션 커널이 비연속 포인터를 순회하며 연산 수행
- 통찰: 기존 연속 메모리 사전 예약에 따른 내부/외부 단편화(Fragmentation) 낭비를 4% 미만으로 억제하여 배치 크기(Batch Size)를 2~4배 확장함으로써 서빙 처리량(Throughput) 극대화

<details><summary>핵심 용어</summary>

- **PagedAttention** : 운영체제의 페이징 기법을 차용해 KV 캐시를 고정 크기 블록 단위로 비연속 GPU VRAM에 분산 저장하고 연산하는 vLLM의 핵심 알고리즘.
- **KV 캐시 (Key-Value Cache)** : 트랜스포머의 자기회귀(Autoregressive) 생성 시 이전 토큰들의 Key, Value 벡터를 재계산하지 않도록 VRAM에 저장하는 캐시 메모리.
- **블록 테이블 (Block Table)** : 논리적 토큰 시퀀스 블록 번호를 실제 비연속 물리 GPU 메모리 블록 주소로 변환해 주는 페이지 테이블 역할의 자료구조.
- **메모리 단편화 (Memory Fragmentation)** : 요청의 최대 길이를 알 수 없어 과도하게 연속 메모리를 사전 예약함으로써 발생하는 내부/외부 VRAM 낭비 현상.
- **Copy-on-Write (CoW)** : 병렬 샘플링이나 빔 서치 시 공통 프롬프트 블록을 읽기 전용으로 공유하다가 새 토큰 생성 시점에만 물리 블록을 복제 분기하는 기법.

</details>

## 2~4교시 25점 답안

## Ⅰ. 페이지드 어텐션의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **페이지드 어텐션** 은 전통적 OS의 가상 메모리 페이징 기법을 트랜스포머 어텐션 연산에 적용하여, 동적으로 증가하는 토큰별 KV 캐시를 비연속 물리 메모리 블록에 유연하게 매핑하고 계산하는 고성능 추론 최적화 기술 |
| 목적 | 사전 최대 길이 예약으로 인한 심각한 메모리 단편화(Fragmentation: 60~80% 낭비)를 제거하고 GPU 동시 배치 처리량(Throughput) 극대화 |

## Ⅱ. 페이지드 어텐션의 핵심 메커니즘 및 메모리 가상화 특징

| 아키텍처 특징 | 세부 메커니즘 | 기술적 효과 및 성능 개선 |
|---|---|---|
| **논리-물리 블록 분리** | 가상 메모리처럼 논리 토큰 블록을 물리 블록 주소로 분리 매핑 | 물리적으로 연속된 거대 VRAM 공간 확보 강박 완전 해소 |
| **온디맨드 동적 할당** | 새로운 토큰이 생성되어 블록이 가득 찰 때만 새 물리 블록 추가 할당 | 미래 토큰 예약에 따른 메모리 낭비 제로화 (낭비율 4% 미만) |
| **블록 테이블 관리** | 논리 블록 인덱스와 물리 슬롯 주소를 관리하는 Block Table 유지 | 요청별 시퀀스 길이의 동적 팽창 완벽 지원 |
| **프리픽스 메모리 공유** | 시스템 프롬프트 등 공통 접두부를 여러 요청이 단일 물리 블록으로 공유 | 퓨샷(Few-shot) 및 챗봇 서빙 시 KV 캐시 메모리 점유율 50% 절감 |
| **Copy-on-Write (CoW)** | 빔 서치(Beam Search) 시 분기 전까지 동일 물리 블록 참조 유지 | 중복 캐시 복사 오버헤드 원천 차단 및 지연시간 단축 |

## Ⅲ. 논리-물리 블록 매핑 및 어텐션 연산 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│             페이지드 어텐션 (PagedAttention) 메모리 사상 구조          │
└────────────────────────────────────────────────────────────────────────┘
 [ 논리적 KV 캐시 시퀀스 (Logical Sequence: "인공지능 발전과 응용 기술...") ]
 ┌─────────────────────────┬─────────────────────────┬──────────────────┐
 │ Logical Block 0 (토큰 0~3)│ Logical Block 1 (토큰 4~7)│ Logical Block 2  │
 └────────────┬────────────┴────────────┬────────────┴────────┬─────────┘
              │                         │                     │
              ▼                         ▼                     ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 블록 테이블 (Block Table: Request A)                                  │
 │   Logical Block 0  ───>  Physical Block 7                            │
 │   Logical Block 1  ───>  Physical Block 3                            │
 │   Logical Block 2  ───>  Physical Block 12                           │
 └────────────┬─────────────────────────┬─────────────────────┬─────────┘
              │                         │                     │
              ▼                         ▼                     ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 비연속 물리 GPU VRAM 메모리 풀 (Physical Memory Block Pool)           │
 │  ┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐       │
 │  │ Physical Block 3 │  │ Physical Block 7 │  │ Physical Block 12│ ...   │
 │  │ [ 토큰 4~7 KV ]  │  │ [ 토큰 0~3 KV ]  │  │ [ 토큰 8~11 KV] │       │
 │  └─────────────────┘  └─────────────────┘  └─────────────────┘       │
 └──────────────────────────────────┬───────────────────────────────────┘
                                    │ Block Pointers 전달
                                    ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ PagedAttention 전용 CUDA 커널                                        │
 │  - 쿼리 벡터 Q_i와 비연속 물리 블록 내 K, V 벡터를 주소 변환하며 연산│
 │  - 중간 소프트맥스 정규화를 거쳐 최종 어텐션 출력 도출               │
 └──────────────────────────────────────────────────────────────────────┘
```

| 처리 단계 | 상세 동작 내용 | 제어 모듈 |
|---|---|---|
| **토큰 유입 및 블록 검사** | 새 토큰 생성 시 현재 논리 블록의 빈 슬롯(Slot) 여부 확인 | 스케줄러 (Scheduler) |
| **물리 블록 할당** | 마지막 블록이 가득 찼다면 글로벌 프리 블록 풀에서 1개 블록 할당 | 블록 매니저 (Block Manager) |
| **블록 테이블 갱신** | 요청의 Block Table에 신규 물리 블록 ID를 매핑 등록 | 가상 주소 변환 모듈 |
| **비연속 어텐션 연산** | 커널이 Block Table을 참조하며 물리적으로 흩어진 KV 블록 순회 계산 | 커스텀 CUDA 커널 |

## Ⅳ. LLM 추론 가속 기법 비교

| 비교 항목 | 전통적 연속 할당 (HuggingFace) | FlashAttention (v1/v2) | PagedAttention (본 토픽) | Speculative Decoding |
|---|---|---|---|---|
| **최적화 대상** | 기본 텐서 연속 메모리 | GPU 메모리 I/O 대역폭 (IO-Aware) | VRAM 단편화 및 동적 용량 | 순차 생성 연산 지연시간 |
| **핵심 원리** | 고정 크기 연속 배열 사전 할당 | SRAM 타일링 및 소프트맥스 온라인화 | OS 가상 페이징 기반 블록 분할 | 초경량 모델 제안 + 대형 모델 검증 |
| **메모리 단편화** | 심각함 (60~80% 미사용 낭비) | 미해결 (여전히 연속 할당 요구) | 거의 전무 (4% 미만) | 해당 없음 |
| **처리량(Throughput)** | 낮음 (배치 크기 극히 제한) | 중간 (단일 요청 속도 개선) | 최상 (배치 크기 2~4배 확장) | 중간~높음 (토큰당 레이턴시 개선) |
| **결합 가능 여부** | 단독 사용 | PagedAttention과 결합 사용 | FlashAttention 커널 내부 결합 | PagedAttention 엔진 위 탑재 가능 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 블록 크기($B$) 선택에 따른 트레이드오프: 블록이 너무 작으면 테이블 오버헤드 증가, 너무 크면 내부 단편화 발생 | 최신 GPU 아키텍처(H100/A100)의 메모리 버스 및 워크로드 평균 길이에 최적화된 블록 크기($B=16$ 또는 $32$) 표준 채택 |
| 긴 프롬프트 처리(Prefill)와 짧은 토큰 생성(Decode) 요청이 혼재될 때 디코딩 단계의 일시 정지 및 지연 급증 | 긴 프롬프트를 청크 단위로 쪼개어 디코딩 요청과 동일 배치에서 교차 실행하는 청크 프리필(Chunked Prefill) 기법 결합 |
| 다중 GPU 텐서 병렬화(TP) 환경에서 노드 간 KV 캐시 블록 동기화 및 네트워크 패브릭 병목 발생 | 텐서 병렬화 계층별로 블록 매니저를 로컬 분산화하고 NCCL 올리듀스(All-Reduce) 통신 최적화 적용 |

## Ⅵ. 제언

프로덕션 LLM 서빙 환경에서 SLA 지연시간 준수와 서버 처리량을 극대화하기 위해 vLLM 기반 PagedAttention과 청크 프리필 및投機적 디코딩(Speculative Decoding)을 결합한 통합 서빙 파이프라인 구축 권고.

```text
[ 실시간 멀티 테넌트 API 요청 스트림 ]
                   │
                   ▼
┌────────────────────────────────────────────────────────┐
│ 지속적 배치 스케줄러 (Continuous Batching Scheduler)   │
│  - 새 요청 도착 즉시 기존 진행 중인 배치에 동적 삽입   │
└──────────────────┬─────────────────────────────────────┘
                   │
                   ▼
┌────────────────────────────────────────────────────────┐
│ vLLM 초고속 추론 엔진 (Unified Engine)                 │
│                                                        │
│  ┌──────────────────────────────────────────────────┐  │
│  │ Chunked Prefill: 512 토큰 단위 분할 실행         │  │
│  ├──────────────────────────────────────────────────┤  │
│  │ PagedAttention: 공유 프리픽스 캐싱 + 비연속 블록  │  │
│  ├──────────────────────────────────────────────────┤  │
│  │ FlashAttention-2 통합 CUDA 커널 가속             │  │
│  └──────────────────────────────────────────────────┘  │
└──────────────────┬─────────────────────────────────────┘
                   │
                   ▼
       [ 4배 향상된 초당 토큰 처리량 (Tokens/sec) 반환 ]
```

| 구분 | 기본 서빙 아키텍처 (TGI 기본형) | 제언: vLLM PagedAttention 통합 체계 |
|---|---|---|
| **GPU 단편화율** | 60% 이상 낭비 (OOM 빈번) | 4% 미만 유지 (메모리 완전 활용) |
| **동시 수용 배치 수** | GPU당 4~8개 세션 | GPU당 24~32개 세션 (4배 확장) |
| **TTFT 지연시간** | 배치 대기로 인해 수 초 지연 | 지속적 배치(Continuous)로 즉각 시작 |
| **인프라 비용** | 서버 증설로 인한 클라우드 비용 급증 | 동일 하드웨어 대비 서빙 비용 70% 절감 |
