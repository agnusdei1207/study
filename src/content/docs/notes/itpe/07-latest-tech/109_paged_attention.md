## 지식 로드맵 내 현재 위치
IT 인공지능 → LLM 추론 서빙 → KV 캐시 메모리 관리 → PagedAttention

## 30초 인출
- **본질**: PagedAttention은 요청별 KV 캐시를 블록 단위로 관리해 물리 메모리에서 비연속적으로 배치할 수 있게 한 어텐션·메모리 관리 기법이다.
- **메커니즘**: 논리 KV 블록을 블록 테이블로 실제 메모리 블록에 연결하고, 커널이 해당 매핑을 참조한다.
- **효과 범위**: 단편화·중복 저장을 줄일 수 있지만 성능 향상 폭은 모델·워크로드·서빙 설정에 따라 달라진다.

<details><summary>핵심 용어</summary>

- **PagedAttention**: 요청별 KV 캐시의 논리 블록을 물리 블록에 매핑하는 어텐션·메모리 관리 기법
- **KV 캐시(Key-Value Cache)**: 이전 토큰의 키·값 표현을 저장해 자기주의 계산의 반복을 줄이는 메모리다.
- **FlashAttention**: GPU 메모리 이동을 줄이도록 타일 기반으로 주의 계산을 최적화하는 알고리즘 계열이다.
- **블록 테이블**: 요청의 논리 블록이 실제 저장 블록 어디에 있는지 기록하는 자료구조다.
</details>

### Ⅲ. 관련 기술과 구분
| 기법 | 주된 최적화 대상 |
|---|---|
| PagedAttention | KV 캐시 배치·할당과 서빙 중 메모리 관리 |

## 2~4교시 25점 답안
## Ⅰ. 배경과 문제
| 구분 | 핵심 |
|---|---|
| 정의 | **PagedAttention**은 KV 캐시를 블록으로 나눠 비연속 메모리에 매핑하고 이를 참조해 어텐션을 계산하는 기법 |
| 목적 | 동적 캐시의 메모리 낭비를 줄여 동시 서빙 효율 개선 |

자기회귀 생성에서 KV 캐시는 요청이 진행되면서 커지므로 요청 길이를 사전에 알기 어렵다. 최대 길이를 가정한 예약이나 비효율적 연속 할당은 메모리 단편화·미사용 공간·중복 저장을 만들고 배치 가능 요청 수를 제한할 수 있다.

| 관리 방식 | 특징 |
|---|---|
| 큰 연속 공간 예약 | 단순하지만 길이 예측·단편화 부담 |
| 블록 기반 할당 | 필요한 블록을 연결해 동적으로 확장 |

## Ⅱ. 블록 매핑과 어텐션
```text
[요청 내 토큰 위치]
         | 논리 KV 블록 계산
         v
[논리 블록 번호]
         | 블록 테이블 조회
         v
[물리 블록 주소]
         | KV 자료 읽기
         v
[어텐션 커널]
         | 주의 계산
         v
[다음 토큰 출력]
```

요청별 논리 순서를 실제 저장 위치와 분리하므로 물리 블록이 연속일 필요가 없다. 이를 위해 어텐션 커널은 블록 매핑에 따라 KV 데이터를 읽는다.

## Ⅲ. 메모리 공유와 평가
| 기능·평가 | 설명 |
|---|---|
| 동적 블록 할당 | 토큰이 추가될 때 필요한 저장 블록 할당 |
| 접두부 공유 | 공통 토큰의 KV 캐시를 조건에 따라 여러 요청이 공유 |
| 분기 생성 | 공유 블록을 읽고, 변경이 생기면 별도 블록을 사용하도록 관리 가능 |
| 성능 측정 | 메모리 사용·대기 시간·처리량을 동일 조건에서 비교 |

원 논문은 평가한 vLLM 워크로드에서 기존 시스템 대비 처리량 2~4배 향상을 보고했지만, 이는 모든 모델·하드웨어·부하에서 보장되는 수치가 아니다.

## Ⅳ. 기술사적 제언
| 한계 | 대응 |
|---|---|
| 요청 길이·공유 패턴과 메모리 압박에 따라 실제 효율이 달라짐 | 운영 워크로드를 재현해 블록 크기·배치 정책을 튜닝하고, PagedAttention과 연산 커널 최적화를 별도 지표로 검증한다. |
