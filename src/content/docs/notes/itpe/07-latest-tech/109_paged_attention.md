## 연관 키워드

- 페이지드 어텐션(PagedAttention), KV 캐시(Key-Value Cache), 블록 테이블(Block Table)
- 메모리 단편화(Fragmentation), 배치 크기(Batch Size), 서빙 처리량(Throughput)
- 청크 프리필(Chunked Prefill), 연속 배칭(Continuous Batching), 프리픽스 공유(Prefix Sharing)

## Ⅰ. 페이지드 어텐션(PagedAttention)의 개요

- 핵심 요약 : OS의 가상 메모리 페이징을 KV 캐시 관리에 적용해 GPU 메모리 낭비를 줄이고 동시 처리량을 높이는 추론 최적화 기술.
- 개념 : **페이지드 어텐션** (PagedAttention)은 생성되는 토큰의 **KV 캐시** (Key-Value Cache)를 고정 크기 블록으로 나누어 비연속 물리 메모리에 매핑하고, 전용 커널이 이 블록을 따라 어텐션을 계산하는 기법이다. 이 기법은 vLLM 추론 엔진의 핵심으로 소개됐다.
- 배경 및 필요성 : 요청마다 최대 길이만큼 연속 메모리를 미리 잡아 두면 메모리 단편화로 GPU 자원이 대량 낭비되므로, 필요한 블록만 그때그때 할당하는 방식이 있어야 동시 요청을 더 받을 수 있다. vLLM 논문은 기존 시스템이 KV 캐시 메모리의 60~80%를 낭비한다고 보고했다.
- 주요 목적 : 단편화 낭비를 없애 동시 배치 처리량을 높이고 GPU당 수용 세션 수를 늘리는 것.

## Ⅱ. 페이지드 어텐션(PagedAttention)의 특징 및 장점

- 핵심 요약 : 논리와 물리 메모리의 분리가 낭비 감소와 처리량 향상으로 이어지는 구조.

1. 논리-물리 블록 분리 : 토큰 블록을 임의의 물리 블록에 매핑 → 연속된 큰 VRAM 공간 없이도 캐시 적재 가능.
2. 온디맨드 할당 : 블록이 가득 찰 때만 새 블록을 할당 → 미리 예약한 공간의 낭비 감소.
3. 프리픽스 공유 : 시스템 프롬프트 같은 공통 접두부를 여러 요청이 한 블록으로 공유 → 챗봇 서빙의 KV 캐시 점유 감소.

## Ⅲ. 페이지드 어텐션(PagedAttention)의 구조 (흐름)

- 핵심 요약 : 논리 블록을 블록 테이블로 사상해 물리 블록에서 읽는 두 단계 주소 변환 구조.
- **블록 테이블** (Block Table) : 요청별로 논리 블록 번호와 물리 블록 주소의 대응을 기록하는 표.
- **PagedAttention 커널** : 블록 테이블의 포인터를 따라 비연속 블록의 K, V 벡터를 읽어 어텐션을 계산하는 GPU 연산 커널.

```text
[ 논리 시퀀스 ]
Block 0 (토큰 0~3)
Block 1 (토큰 4~7)
        ↓
[ 블록 테이블 (Request A) ]
Block 0 → Physical 7
Block 1 → Physical 3
        ↓
[ 물리 GPU 메모리 풀 ]
Physical 3, Physical 7 (비연속)
        ↓
[ 전용 CUDA 커널이 블록 순회 ]
```

```text
[ 요청 처리 흐름 ]
새 토큰 생성
        ↓
마지막 블록에 빈 슬롯 있음?
   있음 → 빈 슬롯에 KV 기록
   없음 → 새 물리 블록 할당
        ↓
블록 테이블 갱신 후 어텐션 계산
```

## Ⅳ. 기존 방식과 페이지드 어텐션의 비교

- 핵심 요약 : 연속 할당과 달리 블록 단위 가상 페이징은 단편화를 거의 없애 처리량 측면에서 우위를 가진다.

| 비교 축 | 연속 할당 방식 | FlashAttention | PagedAttention |
| --- | --- | --- | --- |
| 최적화 대상 | 텐서의 연속 메모리 | GPU 메모리 입출력 대역폭 | VRAM 단편화와 용량 |
| 핵심 원리 | 최대 길이만큼 연속 사전 할당 | SRAM 타일링과 온라인 소프트맥스 | 블록 분할과 블록 테이블 |
| 메모리 단편화 | 심각 (미사용 공간 다수) | 연속 할당 요구로 여전히 존재 | 거의 없음 (블록 단위 관리) |
| 처리량 | 배치 크기가 크게 제한됨 | 단일 요청 연산 속도 개선 | 동시 배치 처리량 향상 |

- 선택 기준 : 요청 길이가 들쭉날쭉하고 동시 요청이 많은 서빙 환경에는 페이지드 어텐션을, 단일 요청의 연산 속도가 중요하면 FlashAttention 계열을 우선 검토한다.

## Ⅴ. 페이지드 어텐션(PagedAttention)의 한계와 방안

- 핵심 요약 : 블록 크기, 긴 프롬프트 간섭, 다중 GPU 동기화 문제를 블록 크기 규칙, 청크 프리필, 분산 블록 관리로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 블록 크기 상충 | 블록이 작으면 테이블 오버헤드, 크면 내부 단편화 발생 | 워크로드 평균 길이에 맞춰 블록 크기를 표준값으로 고정 | 블록 활용률, 내부 단편화율 |
| 긴 프롬프트와 디코딩 간섭 | 긴 프리필이 짧은 디코딩 요청을 오래 멈춤 | 긴 프롬프트를 청크로 나눠 디코딩과 같은 배치에서 실행하는 **청크 프리필** (Chunked Prefill) 적용 | 토큰 간 지연 시간 |
| 다중 GPU 동기화 병목 | 텐서 병렬 환경에서 노드 간 블록 정보 동기화 비용 증가 | 블록 매니저를 계층별로 분산하고 집단 통신 최적화 | GPU 간 통신 시간 |

## Ⅵ. 페이지드 어텐션(PagedAttention)에 대한 기술사적 제언

- 핵심 요약 : 메모리 활용률과 지연 시간을 함께 관리하는 서빙 운영 체계를 갖추는 것이 바람직하다.

1. 인프라 조직은 GPU당 KV 캐시 활용률과 단편화율을 상시 계측하여, 메모리 부족 오류가 나기 전에 용량 계획에 반영해야 한다.
2. 서비스 조직은 요청 유형별 지연 목표를 정하고, 연속 배칭과 청크 프리필 설정을 목표에 맞춰 조정해야 한다.
3. 플랫폼 조직은 공통 시스템 프롬프트를 표준화하여 프리픽스 공유가 최대한 일어나도록 프롬프트 설계 기준을 정해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 페이지드 어텐션은 KV 캐시를 블록 단위로 관리해 GPU 메모리를 효율적으로 쓰는 서빙 기반 기술이다.
- 시사점 : 생성형 AI 서비스의 단위 비용은 모델 크기보다 메모리 관리 효율에 크게 좌우되므로, 서빙 계층의 메모리 설계가 핵심 과제가 된다.
