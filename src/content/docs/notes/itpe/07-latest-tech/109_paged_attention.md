## Ⅰ. 페이지드 어텐션(Paged Attention)의 개요

- 개념 : 전통적 OS의 가상 메모리 페이징 기법을 트랜스포머 어텐션 연산에 적용하여, 동적으로 증가하는 토큰별 KV 캐시를 비연속 물리 메모리 블록에 유연하게 매핑하고 계산하는 고성능 추론 최적화 기술
- 배경 및 필요성 : 기존 연속 메모리 사전 예약에 따른 내부/외부 단편화(Fragmentation) 낭비를 4% 미만으로 억제하여 배치 크기(Batch Size)를 2~4배 확장함으로써 서빙 처리량(Throughput) 극대화
- 핵심 목적 : 사전 최대 길이 예약으로 인한 심각한 메모리 단편화(Fragmentation: 60~80% 낭비)를 제거하고 GPU 동시 배치 처리량(Throughput) 극대화

## Ⅱ. 페이지드 어텐션(Paged Attention)의 핵심 아키텍처 및 동작 메커니즘

페이지드 어텐션은 연속적인 시퀀스 토큰을 고정 크기 논리 블록으로 분할하고 블록 테이블(Block Table)을 통해 물리 메모리 블록과 사상한 후 전용 CUDA 어텐션 커널이 비연속 포인터를 순회하며 연산 수행 메커니즘을 기반으로 동작하며, 세부적인 아키텍처와 핵심 컴포넌트 간 상호작용 프로세스는 다음과 같음.

```text
┌────────────────────────────────────────────────────────────────────────┐
│             페이지드 어텐션 (PagedAttention) 메모리 사상 구조          │
└────────────────────────────────────────────────────────────────────────┘
 [ 논리적 KV 캐시 시퀀스 (Logical Sequence: "인공지능 발전과 응용 기술...") ]
 ┌─────────────────────────┬─────────────────────────┬──────────────────┐
 │ Logical Block 0 (토큰 0~3)│ Logical Block 1 (토큰 4~7)│ Logical Block 2  │
 └────────────┬────────────┴────────────┬────────────┴────────┬─────────┘
              │                         │                     │
              ▼                         ▼                     ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 블록 테이블 (Block Table: Request A)                                  │
 │   Logical Block 0  ───>  Physical Block 7                            │
 │   Logical Block 1  ───>  Physical Block 3                            │
 │   Logical Block 2  ───>  Physical Block 12                           │
 └────────────┬─────────────────────────┬─────────────────────┬─────────┘
              │                         │                     │
              ▼                         ▼                     ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 비연속 물리 GPU VRAM 메모리 풀 (Physical Memory Block Pool)           │
 │  ┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐       │
 │  │ Physical Block 3 │  │ Physical Block 7 │  │ Physical Block 12│ ...   │
 │  │ [ 토큰 4~7 KV ]  │  │ [ 토큰 0~3 KV ]  │  │ [ 토큰 8~11 KV] │       │
 │  └─────────────────┘  └─────────────────┘  └─────────────────┘       │
 └──────────────────────────────────┬───────────────────────────────────┘
                                    │ Block Pointers 전달
                                    ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ PagedAttention 전용 CUDA 커널                                        │
 │  - 쿼리 벡터 Q_i와 비연속 물리 블록 내 K, V 벡터를 주소 변환하며 연산│
 │  - 중간 소프트맥스 정규화를 거쳐 최종 어텐션 출력 도출               │
 └──────────────────────────────────────────────────────────────────────┘
```

- **논리-물리 블록 분리** : 가상 메모리처럼 논리 토큰 블록을 물리 블록 주소로 분리 매핑 - 물리적으로 연속된 거대 VRAM 공간 확보 강박 완전 해소
- **온디맨드 동적 할당** : 새로운 토큰이 생성되어 블록이 가득 찰 때만 새 물리 블록 추가 할당 - 미래 토큰 예약에 따른 메모리 낭비 제로화 (낭비율 4% 미만)
- **블록 테이블 관리** : 논리 블록 인덱스와 물리 슬롯 주소를 관리하는 Block Table 유지 - 요청별 시퀀스 길이의 동적 팽창 완벽 지원
- **프리픽스 메모리 공유** : 시스템 프롬프트 등 공통 접두부를 여러 요청이 단일 물리 블록으로 공유 - 퓨샷(Few-shot) 및 챗봇 서빙 시 KV 캐시 메모리 점유율 절감

## Ⅲ. 페이지드 어텐션(Paged Attention)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 전통적 연속 할당 (HuggingFace) | FlashAttention (v1/v2) | PagedAttention (본 토픽) | Speculative Decoding |
|---|---|---|---|---|
| **최적화 대상** | 기본 텐서 연속 메모리 | GPU 메모리 I/O 대역폭 (IO-Aware) | VRAM 단편화 및 동적 용량 | 순차 생성 연산 지연시간 |
| **핵심 원리** | 고정 크기 연속 배열 사전 할당 | SRAM 타일링 및 소프트맥스 온라인화 | OS 가상 페이징 기반 블록 분할 | 초경량 모델 제안 + 대형 모델 검증 |
| **메모리 단편화** | 심각함 (60~80% 미사용 낭비) | 미해결 (여전히 연속 할당 요구) | 거의 전무 (4% 미만) | 해당 없음 |
| **처리량(Throughput)** | 낮음 (배치 크기 극히 제한) | 중간 (단일 요청 속도 개선) | 최상 (배치 크기 2~4배 확장) | 중간~높음 (토큰당 레이턴시 개선) |

- 페이지드 어텐션은 상기 비교 지표를 바탕으로 비즈니스 요구사항과 운영 인프라 환경을 고려한 최적의 아키텍처를 선정하고, 확장성과 안정성을 균형 있게 확보해야 함.

## Ⅳ. 페이지드 어텐션(Paged Attention)의 주요 한계점 및 해결 방안

- 블록 크기($B$) 선택에 따른 테이블 오버헤드와 내부 단편화 상충 :
  - 한계점 : 블록 크기($B$) 선택에 따른 트레이드오프: 블록이 너무 작으면 테이블 오버헤드 증가, 너무 크면 내부 단편화 발생.
  - 해결 방안 : 최신 GPU 아키텍처(H100/A100)의 메모리 버스 및 워크로드 평균 길이에 최적화된 블록 크기($B=16$ 또는 $32$) 표준 채택.
- 긴 프롬프트(Prefill)와 짧은 디코드 요청 혼재 시 디코딩 일시 정지 및 지연 :
  - 한계점 : 긴 프롬프트 처리(Prefill)와 짧은 토큰 생성(Decode) 요청이 혼재될 때 디코딩 단계의 일시 정지 및 지연 급증.
  - 해결 방안 : 긴 프롬프트를 청크 단위로 쪼개어 디코딩 요청과 동일 배치에서 교차 실행하는 청크 프리필(Chunked Prefill) 기법 결합.
- 다중 GPU 텐서 병렬화(TP) 환경에서 노드 간 KV 블록 동기화 병목 :
  - 한계점 : 다중 GPU 텐서 병렬화(TP) 환경에서 노드 간 KV 캐시 블록 동기화 및 네트워크 패브릭 병목 발생.
  - 해결 방안 : 텐서 병렬화 계층별로 블록 매니저를 로컬 분산화하고 NCCL 올리듀스(All-Reduce) 통신 최적화 적용.

## Ⅴ. 페이지드 어텐션(Paged Attention) 적용 및 발전을 위한 기술사적 제언

- GPU 단편화율 중심 엔터프라이즈 고도화 : 60% 이상 낭비 (OOM 빈번)의 한계를 탈피하고, 4% 미만 유지 (메모리 완전 활용)를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- 동시 수용 배치 수 중심 엔터프라이즈 고도화 : GPU당 소수 세션의 한계를 탈피하고, GPU당 동시 세션 수 확대를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- TTFT 지연시간 절감 및 최적화 체계 구축 : 배치 대기로 인해 수 초 지연의 한계를 탈피하고, 지속적 배치(Continuous)로 즉각 시작을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
