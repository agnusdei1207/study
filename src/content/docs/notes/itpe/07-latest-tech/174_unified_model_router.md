## 핵심 용어
- 시맨틱 라우터(Semantic Router): 사용자의 입력 프롬프트를 벡터 임베딩한 뒤, 사전 정의된 라우트(Route) 앵커 벡터들과의 코사인 유사도를 밀리초 단위로 계산하여 최적 목적지로 전달하는 기술
- 모델 캐스케이딩(Model Cascading): 먼저 가장 저렴하고 빠른 소형 모델에게 답변을 생성하게 한 뒤, 생성된 답변의 신뢰도(Confidence)가 기준치 이하일 때만 상위 거대 모델을 순차 호출하는 기법
- MoA(Mixture of Agents): 단일 거대 모델 대신, 서로 다른 장점을 가진 여러 소형 및 전문 모델들이 단계별로 초안을 작성하고 비판·취합하여 최고 품질의 답을 도출하는 다중 에이전트 구조

## 핵심 통찰
- "단일 거대 모델(Monolithic)의 경제적 한계": 모든 프롬프트를 수천억 개 파라미터의 GPT-4/GPT-5로 처리하면 기업의 AI API 청구서가 감당 불가능해지며, 쿼리의 70%는 사실 소형 모델로도 충분함
- 라우터 자체의 제로 오버헤드: 라우터가 고민하느라 1초를 쓴다면 의미가 없으므로, 라우터는 5ms 이내에 동작하는 바이너리 임베딩 분류기나 수십만 개 파라미터 수준의 초소형 판별기를 사용
- 오픈AI의 모델 패밀리 통합 전략: 사용자가 수동으로 o1, GPT-4o, mini를 고르는 번거로움을 없애고, 단일 엔드포인트 뒤에서 쿼리 난이도에 따라 최적 모델을 백엔드에서 투명하게 자동 배분

## 이웃 토픽과 구분
- MoE vs 통합 모델 라우터: MoE(Mixture of Experts)는 단일 신경망 '내부'에서 토큰 단위로 전문가 피드포워드 계층을 분기 / 통합 모델 라우터는 시스템 '외부'에서 프롬프트 단위로 서로 다른 독립 모델을 분기

## 문제·원인·대책
- 적용 상황: 하루 500만 건 질의가 인입되는 대형 엔터프라이즈 AI 서비스 서빙 인프라
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 프론티어 LLM 전면 사용으로 월간 API 호출 비용이 수억 원 발생 | 인사말, 단순 사실 확인 등 저난이도 질의까지 최고가 모델 호출 | 질의 복잡도 스코어러 기반 통합 모델 라우터 도입 (SLM 70% 분기) | 월간 API 추론 비용 75% 절감 |
| 라우터가 복잡한 수학 코딩 질의를 소형 모델로 오분기하여 오답 반환 | 단순 키워드 매칭 기반 라우팅의 문맥 이해 실패 | 코사인 유사도 기반 시맨틱 라우팅 및 LLM 답변 신뢰도(Confidence) 검증 | 라우팅 정확도 99% 달성 |
| 소형 모델 응답 실패 시 사용자가 처음부터 다시 질문해야 하는 불편 | 단일 분기 후 에러 복구 파이프라인 결여 | 모델 캐스케이딩(Cascading) 기반 신뢰도 미달 시 상위 모델 자동 에스컬레이션 | 무응답 및 품질 불만률 제로화 |
