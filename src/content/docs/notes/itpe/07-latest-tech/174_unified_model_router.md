## 지식 로드맵 내 현재 위치

최신 기술 → 기술 개념·적용 → 통합 모델 라우터(Unified Model Router)

## 30초 인출

- **본질:** 입력의 유형과 품질·비용·지연 요구에 따라 여러 모델 중 처리 경로를 선택하는 정책 계층. 요청별 품질·지연·비용 조건에 맞는 처리 모델 선택.
- **메커니즘:** 입력 분류 → 정책 확인 → 모델 선택 → 결과 검증·대체 경로.

<details><summary>핵심 용어</summary>

- **모델 라우팅:** 요청 조건에 맞는 처리 모델을 선택하는 기능
- **폴백:** 선택 모델이 실패하거나 기준을 못 맞출 때 대체 경로로 전환하는 절차

---

## 2~4교시 25점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 입력의 유형과 품질·비용·지연 요구에 따라 여러 모델 중 처리 경로를 선택하는 정책 계층. |
| 목적 | 요청별 품질·지연·비용 조건에 맞는 처리 모델 선택 |

### Ⅱ. 핵심 구조와 적용

```text
입력 분류 → 정책 확인 → 모델 선택 → 결과 검증·대체 경로
```

1. **요구:** 질의 유형·민감도·허용 지연·정확도·예산을 명시하고 모델별 기능·데이터 처리 경계 정의.
2. **구조:** 라우팅 분류기 → 정책 엔진 → 모델 풀 → 응답 검증·캐시·폴백 → 관측 로그. 고위험 요청은 보수적 경로와 인적 검토.
3. **평가:** 동일 과제군의 정답 품질, 지연 분포, 비용, 라우터 오판율, 폴백 빈도와 보안 정책 위반율 비교.
4. **운영:** 모델 업데이트·프롬프트 변경 시 회귀 시험, 데이터 국외 이전·보존 조건 확인, 장애 시 기본 경로 및 롤백 계획.

### Ⅲ. 유사 개념과 구분

- MoE vs 통합 모델 라우터: MoE(Mixture of Experts)는 단일 신경망 '내부'에서 토큰 단위로 전문가 피드포워드 계층을 분기 / 통합 모델 라우터는 시스템 '외부'에서 프롬프트 단위로 서로 다른 독립 모델을 분기

### Ⅳ. 문제·원인·대책

- 적용 상황: 하루 500만 건 질의가 인입되는 대형 엔터프라이즈 AI 서비스 서빙 인프라
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 모든 질의를 고비용 모델로 처리 | 질의별 난이도·품질 차이를 반영하지 않음 | 평가 집합에서 작은 모델로 처리 가능한 유형을 식별 | 비용·품질·지연의 전후 비교 |
| 어려운 질의를 작은 모델로 잘못 분기 | 분류기의 오판과 답변 품질 추정 오류 | 보수적 라우팅과 품질 실패 시 상위 모델 재시도 | 오분기율과 재시도 비용 측정 |
| 소형 모델 실패 뒤 응답 중단 | 폴백 경로 부재 | 시간 제한과 캐스케이딩 조건 설계 | 무응답률과 추가 지연 확인 |

### Ⅴ. 제언

- 모델별 정확도·지연·비용을 같은 평가 집합에서 측정하고, 라우터 정책 변경 시 소수 트래픽에서 오분기와 품질 저하를 확인. 적응형 정책은 보안·안전 요구를 우선 제한 조건으로 설정
