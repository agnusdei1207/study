## 연관 키워드

- 연합학습(Federated Learning), 원시 데이터(Raw Data), 연합 평균(FedAvg), 비독립·비동일분포(Non-IID), 차분 프라이버시(DP)
- 보안 집계(Secure Aggregation), FedProx, 모델 역전 공격, 포이즈닝 공격(Poisoning), 강건 집계, 영지식 증명(ZKP)
- 수평 연합학습, 수직 연합학습, 연합 전이학습, 로컬 차분 프라이버시(LDP), 스트래글러(Straggler), 섀플리 값(Shapley Value), TEE

## Ⅰ. 연합학습의 개요

- 핵심 요약 : 원시 데이터를 외부로 반출하지 않고, 로컬에서 학습한 가중치만 모아 전역 모델을 만드는 분산 기계학습 체계.
- 개념 : 기기나 기관이 보유한 **원시 데이터** (Raw Data)를 옮기지 않고, 로컬에서 학습한 모델 가중치만 교환해 중앙의 전역 모델을 최적화하는 **연합학습** (Federated Learning, 데이터를 이동시키지 않고 분산 학습하는 방식).
- 배경 및 필요성 : 데이터를 옮기지 않더라도 전송된 가중치로부터 원본을 추정하는 **모델 역전 공격** (Model Inversion, 가중치나 기울기로 학습 데이터를 복원하려는 공격)이 남고, 참여자마다 데이터 분포가 달라 학습이 불안정해지는 **비독립·비동일분포** (Non-IID, Non-Independent and Identically Distributed) 문제가 생긴다. 이를 막으려면 **차분 프라이버시** (DP, Differential Privacy, 개별 데이터의 영향을 통계적 노이즈로 가리는 기법), 보안 집계, 분포 편차를 보정하는 알고리즘을 함께 설계해야 한다.
- 주요 목적 : GDPR(General Data Protection Regulation)과 국내 데이터 3법 등 개인정보 규제 준수, 민감 데이터 사일로 해소, 원시 데이터 전송 비용과 대역폭 한계 극복.

## Ⅱ. 연합학습의 특징 및 장점

- 핵심 요약 : 데이터 잔류, 파라미터 통신, 이종 환경 수용이 개인정보 보호와 통신 효율로 이어지는 구조.

1. **온디바이스 로컬 학습** (On-device Local Training, 원시 데이터가 기기나 기관의 경계 안에 머무르며 학습하는 방식) : 원본이 이동하지 않음 → 노출 면적 축소와 규제 대응 부담 감소.
2. **모델 파라미터 통신** (Parameter Communication, 원시 데이터 대신 가중치 텐서만 주고받는 방식) : 양자화와 **Top-k 희소화** (Top-k Sparsification, 중요도가 큰 상위 k개 기울기만 전송하는 압축 기법)를 적용 → 통신량 감소.
3. **비동기·이종 환경 대응** (Heterogeneity Handling, 참여자의 연결 상태와 연산 능력 차이를 수용하는 방식) : 참여 클라이언트를 무작위로 샘플링하고, **스트래글러** (Straggler, 응답이 극단적으로 느린 참여자)를 제외 → 일부 장치의 지연이 전체 학습을 멈추지 않음.
4. **수학적 프라이버시 보장** (Mathematical Privacy Guarantee, 암호화와 노이즈로 개별 기여를 식별하기 어렵게 만드는 방식) : **보안 집계** (Secure Aggregation, 서버가 개별 가중치 없이 합계만 얻도록 하는 암호 프로토콜)과 **로컬 차분 프라이버시** (LDP, Local Differential Privacy) 적용 → 서버도 개별 기여를 알 수 없음.

## Ⅲ. 연합학습의 구조 (흐름)

- 핵심 요약 : 중앙 서버가 전역 모델을 배포하고 클라이언트가 로컬 학습 결과를 보내면, 서버가 **연합 평균** (FedAvg, Federated Averaging, 클라이언트 가중치를 데이터 양에 따라 평균하는 집계 알고리즘)으로 합치는 라운드 반복 구조.
- 한 라운드 : 전역 모델 배포 → 로컬 학습 → 노이즈를 더하고 마스킹한 가중치 업로드 → 서버 집계 → 갱신된 전역 모델 재배포.
- 원시 데이터는 각 참여자 경계 안에 남고, 서버는 가중치의 합만 다룬다.

```text
[ 중앙 서버: 전역 모델 w_t 배포 ]
          ↓
[ 클라이언트 A·B·C: 로컬 데이터로 학습 ]
          ↓  DP 노이즈·마스킹 후 가중치만 업로드
[ 중앙 서버: 보안 집계 (FedAvg) ]
          ↓
[ 갱신된 전역 모델 w_t+1 ] → 다음 라운드
```

```text
[ 병원 A 데이터 ] --> 가중치만 --\
[ 은행 B 데이터 ] --> 가중치만 ---> [ 중앙 서버 ]
[ 모바일 C 데이터 ] --> 가중치만 --/
원시 데이터는 각 참여자 경계 안에 남음
```

## Ⅳ. 수평·수직·연합 전이 연합학습의 비교

- 핵심 요약 : 참여자 간 사용자와 피처의 중복 구조에 따라 세 유형으로 나뉘며, 어떤 중복이 있는지가 적용 방식을 결정.

| 분류 유형 | 사용자(ID) 중복성 | 데이터 특징(Feature) 중복성 | 대표 적용 사례 |
| --- | --- | --- | --- |
| 수평 연합학습 (Horizontal FL) | 낮음 (서로 다른 사용자) | 동일 (같은 피처 공간) | 여러 지역 병원의 같은 질환 기록, 키보드 예측 모델 |
| 수직 연합학습 (Vertical FL) | 동일 (같은 사용자 집합) | 다름 (서로 다른 속성 보유) | 같은 지역의 은행과 이커머스 간 신용평가 모델 |
| 연합 전이학습 (Federated TL) | 다름 (서로 다른 사용자) | 다름 (서로 다른 도메인) | 국내 은행과 해외 의료기관 간 소량 샘플 전이 학습 |

- 선택 기준 : 참여자들이 같은 속성의 데이터를 서로 다른 사용자에 대해 가지면 수평, 같은 사용자에 대해 서로 다른 속성을 가지면 수직, 둘 다 다르면 연합 전이학습을 검토한다.

## Ⅴ. 연합학습의 한계와 방안

- 핵심 요약 : 데이터 분포 편향, 역추적 공격, 악의적 제출을 알고리즘 보정, 프라이버시 노이즈, 강건 집계와 검증으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| Non-IID 데이터 편향 | 참여자별 분포가 달라 전역 모델이 수렴하지 못하고 진동 | **FedProx** (로컬 손실에 전역 모델과의 거리 페널티를 더하는 알고리즘), 클라이언트별 맞춤 레이어를 두는 개인화 연합학습 | 전역 모델 수렴 추이 |
| 모델 역전 공격 (Model Inversion) | 전송된 가중치나 기울기 변화로 원본 훈련 데이터를 복원 | 차분 프라이버시 노이즈 주입과 보안 집계 프로토콜 적용 | 프라이버시 예산 소진량 |
| **포이즈닝 공격** (Poisoning) | 악의적 참여자가 오염된 가중치를 제출해 전역 모델을 훼손 | **강건 집계** (Robust Aggregation, Krum, Trimmed-Mean 등 이상치 가중치를 걸러내는 방식)과 **영지식 증명** (ZKP, Zero-Knowledge Proof, 내용을 공개하지 않고 계산의 정당성을 증명하는 기법) 검증 | 이상 제출 탐지율 |

## Ⅵ. 연합학습 도입을 위한 기술사적 제언

- 핵심 요약 : 연합학습을 프라이버시 도구에 그치지 않고 협업 인프라로 보고, 알고리즘, 보안, 기여 보상을 함께 관리할 필요.

1. 단계적 아키텍처 도입 : 참여 기관이 적은 파일럿에서 시작해 집계 서버와 보안 프로토콜을 표준화한 뒤 참여자를 넓혀 가는 로드맵을 수립한다.
2. 알고리즘과 통신 최적화 : FedAvg의 한계를 FedProx와 통신 압축으로 먼저 보완하고, 참여자별 기여도를 공정하게 나누는 **섀플리 값** (Shapley Value, 각 참여자의 한계 기여를 평균내는 게임이론 기반 값)에 근거한 보상 모델은 중장기 과제로 설계한다.
3. 집계 신뢰 기반 구성 : 집계를 **TEE** (Trusted Execution Environment, 하드웨어로 격리된 신뢰 실행 환경) 안에서 수행하는 구조를 우선 적용하고, 탈중앙화 구성은 검증 비용과 운영 주체를 따져 단계적으로 검토한다.

## Ⅶ. 결론

- 핵심 요약 : 연합학습은 데이터를 이동시키지 않고 협업 모델을 만드는 분산 학습 체계.
- 시사점 : 프라이버시 보호와 모델 성능은 집계 보안과 분포 보정이 함께 갖춰질 때 양립하므로, 규제 대응을 넘어 참여자 간 신뢰 인프라를 함께 설계하는 것이 전제된다.
