## 30초 인출

- 본질: **CRAG (Corrective Retrieval-Augmented Generation)** 은 검색된 문서의 신뢰도를 평가하여 지식 정제 또는 외부 웹 검색 보완을 능동적으로 수행하는 RAG 아키텍처
- 메커니즘: 경량 검색 평가자가 적합도를 채점하여 3단계(Correct·Ambiguous·Incorrect)로 분기하고 지식 스트립 분할 필터링 및 웹 검색 쿼리 확장을 거쳐 생성기에 전달
- 통찰: 검색 평가자의 신뢰도 오판정으로 인한 잘못된 외부 검색 의존 및 컨텍스트 오염을 막기 위해 평가기 임계치 보정과 도메인 특화 화이트리스트 기반 폴백 통제 체계 구축 필수

<details><summary>핵심 용어</summary>

- **CRAG (Corrective Retrieval-Augmented Generation)** : 검색 문서의 신뢰성을 사전 평가하여 정제 또는 보완 검색을 거치는 교정형 검색 증강 생성 기술.
- **검색 평가자 (Retrieval Evaluator)** : 질의와 검색된 문서 간의 의미적 적합도 점수를 산출하는 경량 판정 신경망.
- **지식 정제 (Knowledge Refinement)** : 검색 문서를 미세 지식 스트립 단위로 분할한 뒤 무관한 노이즈를 제거하는 필터링 기법.
- **지식 스트립 (Knowledge Strips)** : 긴 문서를 문장 또는 의미 단위의 작은 텍스트 블록으로 나눈 세부 정보 단위.
- **웹 검색 폴백 (Web Search Fallback)** : 내부 문서가 부정확하거나 모호할 때 외부 검색 엔진 쿼리로 확장하여 최신 근거를 확보하는 우회 처리.

</details>

## 2~4교시 25점 답안

## Ⅰ. CRAG의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **CRAG (Corrective Retrieval-Augmented Generation)** 은 검색된 문서의 질적 수준을 경량 평가자로 판정하여 문서 정제 또는 대체 웹 검색을 수행한 후 생성기에 주입하는 교정형 RAG 기술 |
| 목적 | 무관하거나 부정확한 검색 문서로 인한 LLM의 환각(Hallucination) 방지 및 지식 신뢰성 보장 |

## Ⅱ. CRAG의 핵심 메커니즘 및 차별 특징

| 특징 요소 | 세부 메커니즘 | 기술적 차별성 및 효과 |
|---|---|---|
| **검색 결과 자체 평가** | 경량 T5/BERT 기반 검색 평가자 적용 | 단순 벡터 유사도 순위를 넘어 질의 적합도 신뢰 점수(Confidence Score) 정량화 |
| **3단계 트리거 분기** | 임계치 기준 Correct, Ambiguous, Incorrect 분기 | 검색 품질에 따른 차등적 교정 파이프라인 가동으로 컴퓨팅 자원 최적화 |
| **지식 스트립 정제** | 문서를 지식 스트립 단위 분할 및 필터링 | 문서 내 포함된 불필요한 배경 잡음 제거 및 생성기 프롬프트 토큰 효율 극대화 |
| **적응형 웹 폴백** | 신뢰도 저하 시 외부 검색 엔진 자동 연계 | 사내 지식 베이스의 지식 공백(Knowledge Hole)을 실시간 외부 정보로 자동 보완 |

## Ⅲ. CRAG의 체계 및 교정 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│             CRAG (Corrective RAG) 엔드투엔드 파이프라인                │
└────────────────────────────────────────────────────────────────────────┘
 [ 사용자 질의 (Query) ]
          │
          ▼
 [ 1차 내부 검색 (Internal Retrieval) ] ──> Vector DB / BM25
          │
          ▼
 [ 검색 평가자 (Retrieval Evaluator) ]
          │ ── Confidence Score 산출 및 임계치 판정
          ├──────────────────────────┬──────────────────────────┐
          ▼                          ▼                          ▼
 [ Correct: 적합 ]           [ Ambiguous: 모호 ]        [ Incorrect: 부적합 ]
  (Confidence ≥ Upper)      (Lower ≤ Conf < Upper)        (Confidence < Lower)
          │                          │                          │
          │                          ├────────────────┐         │
          ▼                          ▼                ▼         ▼
┌──────────────────┐       ┌──────────────────┐ ┌──────────────────────────┐
│ 내부 문서 정제   │       │ 내부 문서 정제   │ │ 질의 재작성(Query Rewrite)│
│ (Strip & Filter) │       │ (Strip & Filter) │ │ & 외부 웹 검색 (Web Search)│
└─────────┬────────┘       └─────────┬────────┘ └─────────────┬────────────┘
          │                          └────────────────┐       │
          ▼                                           ▼       ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 지식 재구성 (Recomposed Knowledge Context)                             │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
          ┌──────────────────────────────────────────────────┐
          │ 생성 모델 (LLM Generator) ──> 정밀 응답(Answer)  │
          └──────────────────────────────────────────────────┘
```

| 파이프라인 단계 | 수행 작업 및 핵심 알고리즘 | 입출력 산출물 |
|---|---|---|
| **검색 평가 단계** | 질의와 검색 문서 쌍의 유사도 및 관련성 신뢰도 점수 산출 | 질의-문서 신뢰 점수 (Score) |
| **지식 분할 단계** | 검색 문서를 고정 토큰 또는 문장 기반 지식 스트립으로 세분화 | 세부 지식 스트립 목록 |
| **스트립 필터 단계** | 각 스트립별 관련도를 재평가하여 임계치 미달 스트립 완전 제거 | 노이즈 제거된 핵심 지식 스트립 |
| **외부 검색 보완** | 질의 키워드를 기반으로 웹 검색 API 호출 및 최신 지식 수집 | 외부 웹 스니펫 검색 결과 |
| **지식 병합 및 생성** | 정제된 내부 지식과 외부 보완 지식을 결합하여 LLM 프롬프트 생성 | 최종 그라운딩된 답변 |

## Ⅳ. RAG 진화 유형 비교 (Standard RAG vs Self-RAG vs CRAG)

| 비교 항목 | Standard RAG | Self-RAG | CRAG (본 토픽) |
|---|---|---|---|
| **평가 주체** | 평가 메커니즘 부재 | 생성 LLM 자체 (반성 토큰 학습) | 경량 독립 평가 모델 (Retrieval Evaluator) |
| **모델 의존성** | 임의의 LLM 사용 가능 | 특화 파인튜닝된 전용 LLM 필요 | 임의의 상용/오픈소스 LLM과 결합 가능 |
| **교정 방식** | 교정 없음 (Top-k 단순 주입) | 자체 비평 토큰 기반 동적 재검색 | 스트립 단위 정제 및 외부 웹 검색 폴백 |
| **계산 오버헤드** | 가장 낮음 (단일 추론) | 높음 (LLM의 다중 반성 토큰 생성) | 중간 (경량 판별기 추론 1회 추가) |
| **보안/망분리 환경** | 우수 (내부망 내 완결) | 우수 (외부망 연계 불필요) | 웹 검색 폴백 시 외부 유출 통제 필요 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 경량 검색 평가자의 오분류로 인해 정확한 내부 문서가 폐기되거나 모호 상태로 오판정되는 병목 | 도메인 특화 질의-문서 정답 데이터셋 기반 평가기 파인튜닝 및 이중 교차 검증 점수 체계 도입 |
| Incorrect 분기 시 외부 공용 웹 검색 호출로 인한 사내 기밀 프롬프트 유출 및 보안 규제 위반 | 폐쇄망 내 보조 백업 지식 저장소 구축 및 허용된 사내 엔터프라이즈 화이트리스트 도메인만 폴백 허용 |
| 지식 스트립 세분화 시 문서 내 문맥적 전후 관계(Context Coherence) 훼손 및 핵심 조건 누락 | 문장 단위 분할 대신 의미 기반 슬라이딩 윈도우(Sliding Window) 기법 및 메타데이터 계보 보존 적용 |

## Ⅵ. 제언

외부 공용 웹 엔진 의존을 배제하고 사내 엔터프라이즈 검색 시스템과 폐쇄망 보안 프레임워크를 융합한 엔터프라이즈 특화 듀얼 게이트 CRAG 아키텍처 구축 필요.

```text
[ 사용자 비즈니스 질의 ]
          │
          ▼
[ 1차 온프레미스 벡터/키워드 하이브리드 검색 ]
          │
          ▼
[ 듀얼 게이트 경량 평가기 (Domain-tuned Evaluator) ]
          ├─ 적합 (Score ≥ 0.75) ──> [ 스트립 분할 및 잡음 필터 ] ─────────┐
          ├─ 모호 (0.4 ≤ Score < 0.75) ──> [ 내부 위키/사규 보조 검색 ] ──┤
          └─ 부적합 (Score < 0.4) ──> [ 사내 엔터프라이즈 통합 검색 ] ─────┤
                                                                            │
                                                                            ▼
                                                [ 문맥 재구성기 & 로컬 LLM 생성 ]
```

| 비교 항목 | 오픈 웹 기반 기본 CRAG | 제언: 엔터프라이즈 듀얼 게이트 CRAG |
|---|---|---|
| **폴백 대상** | 구글·빙 등 퍼블릭 웹 검색 엔진 | 사내 정형 EDMS, 통합 사규 저장소, 로컬 캐시 |
| **데이터 기밀성** | 질의 외부 유출 및 컴플라이언스 위반 위험 | 망분리 완결형 아키텍처로 제로 트러스트 달성 |
| **검색 평가 모델** | 일반 도메인 사전학습 모델 | 산업·기업 특화 용어 사전 학습 파인튜닝 모델 |
| **운영 인프라** | 인터넷 아웃바운드 트래픽 필수 | 순수 온프레미스 / VPC 프라이빗 클라우드 완결 |
