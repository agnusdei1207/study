## Ⅰ. CRAG (Corrective RAG)의 개요

- 개념 : 검색된 문서의 질적 수준을 경량 평가자로 판정하여 문서 정제 또는 대체 웹 검색을 수행한 후 생성기에 주입하는 **교정형 RAG** 기술
- 배경 및 필요성 : 검색 평가자의 신뢰도 오판정으로 인한 잘못된 외부 검색 의존 및 컨텍스트 오염을 막기 위해 평가기 임계치 보정과 도메인 특화 **화이트리스트** 기반 **폴백** 통제 체계 구축 필수
- 핵심 목적 : 무관하거나 부정확한 검색 문서로 인한 LLM의 **환각** (Hallucination) 방지 및 지식 신뢰성 보장

## Ⅱ. CRAG (Corrective RAG)의 핵심 아키텍처 및 동작 메커니즘

CRAG는 경량 검색 평가자가 적합도를 채점하여 3단계(Correct·Ambiguous·Incorrect)로 분기하고 지식 스트립 분할 필터링 및 웹 검색 쿼리 확장을 거쳐 생성기에 전달 메커니즘을 기반으로 동작하며, 세부적인 아키텍처와 핵심 컴포넌트 간 상호작용 프로세스는 다음과 같음.

```text
┌────────────────────────────────────────────────────────────────────────┐
│             CRAG (Corrective RAG) 엔드투엔드 파이프라인                │
└────────────────────────────────────────────────────────────────────────┘
 [ 사용자 질의 (Query) ]
          │
          ▼
 [ 1차 내부 검색 (Internal Retrieval) ] ──> Vector DB / BM25
          │
          ▼
 [ 검색 평가자 (Retrieval Evaluator) ]
          │ ── Confidence Score 산출 및 임계치 판정
          ├──────────────────────────┬──────────────────────────┐
          ▼                          ▼                          ▼
 [ Correct: 적합 ]           [ Ambiguous: 모호 ]        [ Incorrect: 부적합 ]
  (Confidence ≥ Upper)      (Lower ≤ Conf < Upper)        (Confidence < Lower)
          │                          │                          │
          │                          ├────────────────┐         │
          ▼                          ▼                ▼         ▼
┌──────────────────┐       ┌──────────────────┐ ┌──────────────────────────┐
│ 내부 문서 정제   │       │ 내부 문서 정제   │ │ 질의 재작성(Query Rewrite)│
│ (Strip & Filter) │       │ (Strip & Filter) │ │ & 외부 웹 검색 (Web Search)│
└─────────┬────────┘       └─────────┬────────┘ └─────────────┬────────────┘
          │                          └────────────────┐       │
          ▼                                           ▼       ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 지식 재구성 (Recomposed Knowledge Context)                             │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
          ┌──────────────────────────────────────────────────┐
          │ 생성 모델 (LLM Generator) ──> 정밀 응답(Answer)  │
          └──────────────────────────────────────────────────┘
```

- 검색 결과 자체 평가 : 경량 **T5/BERT** 기반 검색 평가자 적용 - 단순 벡터 유사도 순위를 넘어 질의 적합도 **신뢰 점수** (Confidence Score) 정량화
- **3단계 트리거 분기** : 임계치 기준 Correct, Ambiguous, Incorrect 분기 - 검색 품질에 따른 차등적 교정 파이프라인 가동으로 컴퓨팅 자원 최적화
- **지식 스트립 정제** : 문서를 지식 스트립 단위 분할 및 필터링 - 문서 내 포함된 불필요한 배경 잡음 제거 및 생성기 프롬프트 토큰 효율 극대화

## Ⅲ. CRAG (Corrective RAG)의 세부 구성 요소 및 비교 분석

| 비교 항목 | Standard RAG | Self-RAG | CRAG (본 토픽) |
|---|---|---|---|
| **평가 주체** | 평가 메커니즘 부재 | 생성 LLM 자체 (반성 토큰 학습) | 경량 독립 평가 모델 (Retrieval Evaluator) |
| **모델 의존성** | 임의의 LLM 사용 가능 | 특화 파인튜닝된 전용 LLM 필요 | 임의의 상용/오픈소스 LLM과 결합 가능 |
| **교정 방식** | 교정 없음 (Top-k 단순 주입) | 자체 비평 토큰 기반 동적 재검색 | 스트립 단위 정제 및 외부 웹 검색 폴백 |
| **계산 오버헤드** | 가장 낮음 (단일 추론) | 높음 (LLM의 다중 반성 토큰 생성) | 중간 (경량 판별기 추론 1회 추가) |

- CRAG는 상기 비교 지표를 바탕으로 비즈니스 요구사항과 운영 인프라 환경을 고려한 최적의 아키텍처를 선정하고, 확장성과 안정성을 균형 있게 확보해야 함.

## Ⅳ. CRAG (Corrective RAG)의 주요 한계점 및 해결 방안

- 경량 검색 평가자의 오분류로 인한 내부 문서 폐기 및 모호성 판정 :
  - 한계점 : 경량 검색 평가자의 오분류로 인해 정확한 내부 문서가 폐기되거나 모호 상태로 오판정되는 병목.
  - 해결 방안 : 도메인 특화 질의-문서 정답 데이터셋 기반 평가기 파인튜닝 및 이중 교차 검증 점수 체계 도입.
- Incorrect 분기 시 외부 공용 웹 검색 호출에 따른 기밀 유출 위험 :
  - 한계점 : Incorrect 분기 시 외부 공용 웹 검색 호출로 인한 사내 기밀 프롬프트 유출 및 보안 규제 위반.
  - 해결 방안 : 폐쇄망 내 보조 백업 지식 저장소 구축 및 허용된 사내 엔터프라이즈 화이트리스트 도메인만 폴백 허용.
- 지식 스트립 세분화 시 문서 내 문맥적 전후 관계 훼손 :
  - 한계점 : 지식 스트립 세분화 시 문서 내 문맥적 전후 관계(Context Coherence) 훼손 및 핵심 조건 누락.
  - 해결 방안 : 문장 단위 분할 대신 의미 기반 슬라이딩 윈도우(Sliding Window) 기법 및 메타데이터 계보 보존 적용.

## Ⅴ. CRAG (Corrective RAG) 적용 및 발전을 위한 기술사적 제언

- 폴백 대상 중심 엔터프라이즈 고도화 : 구글·빙 등 퍼블릭 웹 검색 엔진의 한계를 탈피하고, 사내 정형 EDMS, 통합 사규 저장소, 로컬 캐시를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- 데이터 기밀성 중심 엔터프라이즈 고도화 : 질의 외부 유출 및 컴플라이언스 위반 위험의 한계를 탈피하고, 망분리 완결형 아키텍처로 제로 트러스트 달성을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- 검색 평가 모델 중심 엔터프라이즈 고도화 : 일반 도메인 사전학습 모델의 한계를 탈피하고, 산업·기업 특화 용어 사전 학습 파인튜닝 모델을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
