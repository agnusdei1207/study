## 연관 키워드

- CRAG, 교정형 RAG, RAG, 검색 평가자, 임계값, 지식 스트립, 웹 검색 폴백, 환각, Self-RAG

## Ⅰ. CRAG의 개요

- 핵심 요약 : 검색된 문서의 적합도를 평가해 정제하거나 외부 검색으로 보완한 뒤 생성하는 교정형 RAG.
- 개념 : 검색 문서의 질을 경량 **검색 평가자**(Retrieval Evaluator)가 판정하고, 그 결과에 따라 문서를 정제하거나 웹 검색으로 보완한 뒤 생성기에 주입하는 **교정형 RAG** (CRAG, Corrective Retrieval-Augmented Generation).
- 배경 및 필요성 : 기존 RAG(Retrieval-Augmented Generation)는 검색 문서의 품질을 따지지 않고 생성기에 그대로 넘기므로, 무관한 문서가 섞이면 답변이 흐려지거나 **환각**(Hallucination)이 생길 수 있다. 내부 문서에 근거가 없을 때 외부 경로로 보완하는 절차가 필요해졌다.
- 주요 목적 : 검색 결과의 신뢰도를 평가해 잘못된 문맥이 생성으로 전파되는 것을 막고 답변의 근거 품질을 높이는 것.

## Ⅱ. CRAG의 특징 및 장점

- 핵심 요약 : 검색 결과를 세 단계로 판정해 상황별 교정 경로를 나누므로, 정확도와 자원 효율을 함께 얻는 구조.

1. 3단계 판정(Correct·Ambiguous·Incorrect) : 평가 점수를 상한·하한 **임계값**(Threshold)과 비교해 분기 → 상황에 맞는 교정만 수행해 불필요한 외부 검색 감소.
2. **지식 스트립**(Knowledge Strip) 정제 : 문서를 의미 단위 조각으로 나눠 관련 조각만 남김 → 생성기 입력의 잡음과 토큰 사용량 감소.
3. **웹 검색 폴백**(Web Search Fallback) : 내부 문서가 부적합하다고 판정되면 질의를 재작성해 외부 검색으로 대체 → 내부 자료에 없는 근거 확보.

```text
[ 사용자 질의 ]
      ↓
[ 1차 내부 검색 ]
      ↓
[ 검색 평가자 점수 산출 ]
      ↓
[ 임계값 기준 3단계 분기 ]
      ↓
[ 지식 재구성 후 생성 ]
```

```text
Correct    ──> 내부 문서 정제 후 사용
Ambiguous  ──> 내부 정제 + 웹 검색 결합
Incorrect  ──> 질의 재작성 후 웹 검색
```

## Ⅲ. CRAG의 구조 (흐름)

- 핵심 요약 : 내부 검색 결과의 판정이 교정 경로를 결정하고, 교정된 문맥만 생성기에 전달되는 단일 흐름.
- 구성요소 : 1차 검색기(벡터 DB(Database), BM25), 경량 검색 평가자, 지식 스트립 정제기, 질의 재작성기, 웹 검색 모듈, 생성 모델.
- 처리 순서 : 평가자가 문서별 적합도를 채점 → 분기별 정제 또는 웹 보완 → 지식 재구성 → 생성기가 최종 답변 작성.
- 평가 주체 : 생성 모델과 별개의 경량 모델이 맡으므로, 생성기를 재학습하지 않고 파이프라인 단계만 추가하는 방식.

## Ⅳ. CRAG와 대안 기법의 비교

- 핵심 요약 : CRAG는 생성 모델을 고치지 않고 독립 평가기로 검색 결과를 교정하는 방식이다.

비교 대상은 고정 검색을 쓰는 표준 RAG와 생성 모델이 스스로 반성 토큰을 생성하는 Self-RAG(Self-Reflective Retrieval-Augmented Generation)다.

| 비교 축 | Standard RAG | Self-RAG | CRAG |
| --- | --- | --- | --- |
| 평가 주체 | 평가 메커니즘 없음 | 생성 LLM 자체 (반성 토큰 학습) | 독립 경량 평가기 |
| 모델 의존성 | 임의의 LLM(Large Language Model) 사용 | 반성 토큰을 학습한 전용 모델 필요 | 임의의 LLM과 결합 가능 |
| 교정 방식 | 교정 없이 상위 문서 주입 | 반성 결과에 따라 재검색·재생성 | 문서 정제와 웹 검색 폴백 |
| 추가 연산 | 없음 | 생성 과정의 반성 토큰 부담 | 평가기 추론 1회 추가 |

## Ⅴ. CRAG의 한계와 방안

- 핵심 요약 : 평가기 오판, 외부 검색 기밀 유출, 문맥 훼손 세 가지 한계를 각각 통제해야 운영 가능.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 평가기 오분류 | 경량 평가기가 정확한 내부 문서를 폐기하거나 모호로 판정 | 도메인 질의-문서 쌍으로 평가기 보정, 점수 체계 교차 검증 | 폐기 문서 비율 |
| 외부 검색 기밀 유출 | Incorrect 분기에서 사내 질의가 외부 웹으로 전송 | 폐쇄망 내 백업 지식 저장소, 허용 도메인 화이트리스트만 폴백 | 외부 전송 질의 건수 |
| 지식 스트립 문맥 훼손 | 문장 단위 절단으로 조건과 전후 관계 누락 | 의미 단위 분할, 원문 위치 메타데이터 보존 | 근거 누락 검수 비율 |

## Ⅵ. CRAG에 대한 기술사적 제언

- 핵심 요약 : 사내 지식 체계를 1차 근거로 삼고, 외부 검색은 통제된 보조 경로로 두는 운영 원칙의 확립.

사내 문서 저장소와 사규 체계를 정비해 교정형 RAG의 1차 근거로 쓰고, 외부 웹 검색은 정책으로 허용된 범위에서만 보완 수단으로 두는 것이 바람직하다. 평가 임계값과 폴백 허용 범위는 보안 담당과 지식관리 조직이 함께 주기적으로 검토하는 거버넌스 체계로 관리해야 한다.

## Ⅶ. 결론

- 핵심 요약 : CRAG는 검색 결과를 판정하고 교정하는 단계를 파이프라인에 더한 교정형 RAG임.
- 생성 모델을 바꾸지 않고 검색 단계에서 환각 위험을 줄이는 실무적 선택지로, 근거 품질과 보안 통제를 함께 설계할 때 효과가 드러난다.
