## 지식 로드맵 내 현재 위치
IT 인공지능 → 검색 증강 생성(RAG) → 검색 결과 평가·교정 → CRAG

## 30초 인출
- 본질: **CRAG**는 검색 결과의 품질을 평가해 생성 전에 보완하는 RAG 방식
- 메커니즘: 검색 결과 신뢰도 평가 → 정제·보완 검색·실패 응답 분기 → 근거 확인 후 생성
- 통찰: 한계: 외부 검색을 기본 경로로 두면 내부 자료로 충분한 질의도 외부에 의존 → 방안: 내부 근거의 충분성을 먼저 확인하고 부족할 때 허용 자료원으로 확장
- **추가 단서:** 원 논문은 외부 웹 검색을 보완 경로로 사용하지만, 운영 환경에서는 허용된 자료원으로 대체·제한할 수 있다.

<details><summary>핵심 용어</summary>

- **CRAG(Corrective Retrieval-Augmented Generation):** 검색 결과의 적합성을 평가하고 필요할 때 검색을 보완한 뒤 답변을 생성하는 RAG 방식이다.
- **검색 평가자(Retrieval Evaluator):** 질의와 검색 자료를 비교해 검색 결과의 신뢰도를 추정하는 구성요소다.
- **지식 정제(Knowledge Refinement):** 검색 자료를 세분해 질문과 관련 있는 내용을 다시 구성하는 처리다.
- **검색 폴백(Fallback):** 내부 검색 자료가 부족하거나 신뢰하기 어려울 때 정해진 대체 자료원으로 검색을 넘기는 동작이다.
</details>

## 2~4교시 25점 답안
## Ⅰ. 개요
| 구분 | 핵심 |
|---|---|
| 정의 | CRAG는 검색 결과의 신뢰도를 평가해 지식을 정제하거나 검색을 보완한 뒤 응답을 생성하는 RAG 접근이다 |
| 목적 | 부정확하거나 무관한 검색 자료가 생성 답변을 오염시키는 위험을 줄인다 |

기본 RAG는 검색 품질에 크게 좌우된다. CRAG는 검색 자료의 질을 평가해 질의와 관련된 정보만 정제하거나, 부족한 경우 검색을 보완하는 접근이다.

| 단계 | 기본 RAG | CRAG |
|---|---|---|
| 검색 후 처리 | 결과를 생성기에 전달 | 결과를 평가해 정제·보완 여부 결정 |
| 생성 조건 | 검색 성공 여부를 별도 판정하지 않을 수 있음 | 평가 결과가 후속 자료 처리에 반영 |

## Ⅱ. 평가·교정 구조
```text
[질의] → [검색 결과] → [검색 품질 평가]
                           ├─ 적합 → [검색 자료 정제]
                           ├─ 모호 → [정제 + 허용된 보완 검색]
                           └─ 부적합 → [대체 검색 또는 실패 응답]
                                      ↓
                              [근거 확인 후 생성]
```

원 CRAG는 내부 자료만으로 품질을 확보하기 어려운 경우 웹 검색을 확장 자료원으로 사용했다. 3단계 신뢰도 판정과 각 분기 임계값은 구체 구현에 따라 정한다.

## Ⅲ. 분기 동작과 운영 고려
| 평가 결과 | 처리 | 점검할 점 |
|---|---|---|
| 적합 | 검색 자료를 세분·정제해 생성에 제공 | 정제 중 문맥·조건 누락 여부 |
| 모호 | 내부 자료를 정제하고 승인된 보완 자료원도 검색 | 자료 간 충돌·시점 차이 |
| 부적합 | 검색 결과를 근거로 쓰지 않고 대체 검색·실패 응답 선택 | 외부 반출 허용 여부, 대체 자료 신뢰도 |

검색 평가자도 오류를 낼 수 있으므로 최종 생성 답변의 근거·인용 검증이 필요하다.

## Ⅳ. 한계와 방안
| 한계 | 방안 |
|---|---|
| 외부 검색을 기본 경로로 쓰면 내부 지식만으로 충분한 질의까지 외부 서비스에 의존할 수 있음 | 내부 검색 결과의 충분성 기준을 먼저 정하고, 불충분한 경우에만 허용된 외부 자료원으로 확장하는 경로를 우선 적용한다. |

## Ⅴ. 제언

우선 내부 검색만으로 답할 수 있는 대표 질의를 모아 근거 충분성의 판정 기준을 검증.
