<summary>핵심 용어</summary>

- **퍼블릭 블록체인(Public Blockchain)** : 공개 네트워크 규칙에 따라 참여·검증하는 블록체인 유형
- **허가형 네트워크(Permissioned Network)** : 확인된 신원·정책으로 참여와 행위를 관리하는 네트워크
- **프라이빗 블록체인(Private Blockchain)** : 한 조직이 운영을 주도하는 허가형 네트워크 형태
- **컨소시엄 블록체인(Consortium Blockchain)** : 복수 조직이 참여·운영 책임을 나누는 허가형 네트워크 형태
- **하이브리드 블록체인(Hybrid Blockchain)** : 공개·허가형 요소를 요구에 맞춰 연계하는 설계 명칭. 단일 구현 표준을 뜻하지 않음
- **앵커링(Anchoring)** : 한 시스템의 요약값·증명을 다른 원장에 기록해 나중에 대조할 수 있게 하는 방식


| 기준 | 검토 질문 |

| 정보 공개 | 원장 내용과 증명을 어떤 범위에 공개할 것인가 |

**제언:** 분산원장 도입 전에 공동 검증이 필요한 업무와 운영 책임을 먼저 확인하는 아키텍처 판단.

## 2~4교시 25점 답안

### Ⅰ. 블록체인 유형의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **블록체인 유형**은 참여 허가, 검증 권한, 데이터 공개와 거버넌스 방식으로 나눈 네트워크 설계 |
| 목적 | 공개 검증·참여와 접근 통제·공동 운영 요구에 맞는 원장 구조 선택 |

### Ⅱ. 구분 축과 유형

```text
참여·검증 기준
├─ 공개 규칙 기반 ── 퍼블릭
└─ 신원·정책 기반 ── 허가형
                      ├─ 단일 조직 주도 ── 프라이빗
                      └─ 복수 조직 공동 ── 컨소시엄

공개·허가형 요소를 연계 ── 하이브리드 설계
```

| 유형 | 참여·검증 | 거버넌스 |
|---|---|---|
| 퍼블릭 | 공개 프로토콜 규칙에 따라 폭넓게 참여·검증 가능 | 네트워크 프로토콜·합의에 따름 |
| 프라이빗 | 한 조직 정책으로 참여·권한 제한 | 단일 조직이 주도 |
| 컨소시엄 | 복수 조직 정책으로 참여·권한 제한 | 참여기관이 공동 운영 |
| 하이브리드 | 공개 요소와 허가 요소를 함께 사용 | 연계 범위·책임을 구현별로 설계 |

퍼블릭/허가형은 참여 통제 축, 프라이빗/컨소시엄은 운영 주체 축. 데이터 열람 범위와 검증 권한은 이름만으로 단정하지 않고 프로토콜·설정 확인.

### Ⅲ. 하이브리드 연계 예

```text
허가형 업무 원장
       │ 공개 가능한 요약값·증명 선택
       ▼
퍼블릭 원장에 앵커 기록
       │ 기록값 대조
       ▼
외부 검증자

업무 원문·접근 권한 ── 허가형 정책 안에서 관리
```

앵커링은 가능한 연계 패턴 가운데 하나이며 하이브리드 블록체인의 필수 정의가 아님. 공개 자료의 민감성과 검증 방식, 수수료·지연을 따져야 함.

### Ⅳ. 유형 선택과 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 공개·허가형 유형 선택이 실제 다자간 신뢰 요구보다 기술 유행에 좌우될 수 있음 | 참여기관 간 공동 검증·변경 이력이 필요한지 먼저 확인하고, 기존 공유 데이터베이스로 충족되는 요구는 원장 도입을 보류 |
