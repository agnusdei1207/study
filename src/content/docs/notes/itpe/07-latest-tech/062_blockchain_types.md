## 연관 키워드

- 퍼블릭 블록체인(Public), 프라이빗 블록체인(Private), 컨소시엄 블록체인(Consortium), 하이브리드 블록체인(Hybrid)
- 분산원장 기술(DLT), 허가형(Permissioned), 무허가형(Permissionless)
- 합의 알고리즘(PoW, PoS, PBFT, Raft), 영지식 증명(ZKP), 롤업(Rollup)
- 블록체인 트릴레마, 상호운용성, DAO, DID

## Ⅰ. 블록체인 유형의 개요

- 핵심 요약 : 참여 자격과 검증 권한, 열람 범위에 따라 블록체인을 네 가지 아키텍처로 나누어 업무 요건에 맞게 선택하는 분류 체계.
- 개념 : **분산원장 기술** (DLT, Distributed Ledger Technology)에서 네트워크 참여 자격(Permission), 거래 검증 권한, 원장 열람 범위, 합의 거버넌스에 따라 나뉘는 퍼블릭, 프라이빗, 컨소시엄, 하이브리드 블록체인의 네 가지 유형.
- 배경 및 필요성 : 모든 업무를 단일 유형으로 해결할 수 없고, 서비스가 요구하는 탈중앙성, 처리 속도, 데이터 기밀성, 규제 준수 요건에 따라 아키텍처를 골라야 함.
- 주요 목적 : 비즈니스 목표에 맞는 아키텍처 선정, **블록체인 트릴레마** (탈중앙성, 보안성, 확장성 간의 상충)의 전략적 조율, 기업 데이터 보호와 결제 완결성 확보.

## Ⅱ. 블록체인 유형의 특징 및 장점

- 핵심 요약 : 유형별 참여 통제 수준이 속도와 기밀성, 신뢰성의 상충 관계를 만들며, 하이브리드는 이 상충을 절충하는 구조.

1. 무허가형 퍼블릭 : 누구나 검증에 참여하는 개방 구조 → 중개자 없이 위변조 방지 효과를 얻지만 처리 속도와 거래 비용의 제약이 따름.
2. 허가형 프라이빗 : 승인된 노드만 참여하는 구조 → 빠른 처리와 기밀 보호가 가능하지만 운영자에 대한 신뢰가 전제됨.
3. 연합형 컨소시엄 : 사전 승인된 복수 기관이 공동 운영 → 특정 기관의 독점을 막으면서 업계 표준 거래를 구현함.
4. 복합형 하이브리드 : 민감 거래는 사설 영역에서 처리하고 무결성 증명만 공개 체인에 기록 → 속도, 기밀성, 외부 검증 가능성을 함께 확보함.

## Ⅲ. 블록체인 유형의 구조 (흐름)

- 핵심 요약 : 완전 탈중앙화에서 완전 중앙화로 이어지는 거버넌스 스펙트럼 위에 네 유형이 놓이고, 하이브리드는 사설 처리와 공개 앵커링을 잇는 구조.
- **퍼블릭 블록체인** (Public) : 누구나 노드로 참여하며 데이터가 공개되는 무허가형 원장.
- **프라이빗 블록체인** (Private) : 단일 기관이 네트워크를 관리하며 승인된 노드만 참여하는 허가형 원장.
- **컨소시엄 블록체인** (Consortium) : 동일 산업군의 사전 승인된 복수 기관이 공동으로 노드를 운영하고 합의하는 연합형 원장.
- **하이브리드 블록체인** (Hybrid) : 사설 체인에서 민감 거래를 처리하고 결과의 증명만 공개 체인에 앵커링하는 복합형 구조.

```text
[ 거버넌스 스펙트럼 ]

완전 탈중앙화 (무허가형)
      ↓
퍼블릭 블록체인 (누구나 참여, 공개)
      ↓
컨소시엄 블록체인 (사전 승인 기관 연합)
      ↓
프라이빗 블록체인 (단일 기관 통제)
      ↓
완전 중앙화 (허가형)
```

```text
[ 하이브리드 상호 연동 ]

사설 영역 (프라이빗 또는 컨소시엄)
  - 고속 트랜잭션 실행, 기밀 데이터 보관
  - 영지식 증명과 머클 루트 생성
      ↓ 브릿지 또는 릴레이어 전달
공개 영역 (퍼블릭 메인넷)
  - 머클 루트 영구 기록 (앵커링)
  - 누구나 무결성 검증 가능
```

## Ⅳ. 블록체인 유형별 비교

- 핵심 요약 : 참여 자격과 합의 방식이 열람 범위, 처리 속도, 수수료, 불변성을 함께 결정하므로 유형 선택은 이 축들의 우선순위로 판단.

| 비교 축 | 퍼블릭 (Public) | 프라이빗 (Private) | 컨소시엄 (Consortium) | 하이브리드 (Hybrid) |
| --- | --- | --- | --- | --- |
| 참여 자격 | 누구나 참여 (무허가) | 단일 기관의 승인 | 인가된 복수 기관 | 내부는 허가형, 외부는 무허가 |
| 열람 범위 | 전 세계 공개 | 내부 인가자 한정 | 연합 기관 한정 | 기밀은 비공개, 증명은 공개 |
| 합의 방식 | 작업증명(PoW, Proof of Work), 지분증명(PoS, Proof of Stake) 등 경쟁적 합의 | Raft, Paxos 등 단일 오더링 | **PBFT** (Practical Byzantine Fault Tolerance) 등 정족수 투표 | 내부 PBFT 합의 후 공개 체인 앵커링 |
| 처리 속도 | 상대적으로 느림 | 매우 빠름 | 빠름 | 내부 처리는 빠르고 앵커링은 느림 |
| 거래 비용 | 네트워크 수수료 필수 | 내부 자원 외 수수료 없음 | 운영비 분담 | 내부는 무료, 앵커링 시 수수료 |
| 불변성 | 변조가 사실상 불가능 | 관리자가 수정 가능 | 연합 과반 합의 시 수정 | 공개 체인 앵커링으로 외부 검증 |
| 대표 플랫폼 | Bitcoin, Ethereum | Hyperledger Fabric | R3 Corda, Hyperledger Besu | Klaytn(Kaia), Polygon CDK |

- 선택 기준 : 참여 주체가 한 기관이면 프라이빗, 산업 내 여러 기관이 신뢰를 나눠 가지면 컨소시엄, 외부 검증과 내부 기밀이 함께 필요하면 하이브리드를 검토함.

## Ⅴ. 블록체인 유형의 한계와 방안

- 핵심 요약 : 공개 체인의 확장성 제약, 체인 간 단절, 연합 내 거버넌스 갈등을 하이브리드 구조, 상호운용성 프로토콜, 운영 협약으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 공개 체인의 확장성과 프라이빗의 신뢰 결여 | 공개 체인은 느리고 비용이 크며, 프라이빗은 관리자의 임의 수정 가능성 | 내부에서 고속 처리한 뒤 영지식 증명을 공개 체인에 기록하는 하이브리드 구조 | 앵커링 주기, 외부 검증 성공률 |
| 이기종 체인 간 상호운용성 단절 | 서로 다른 체인 간 토큰과 상태 데이터를 직접 교환하기 어려움 | **CCIP** (Cross-Chain Interoperability Protocol) 등 체인 간 메시징 프로토콜 활용 | 체인 간 전송 실패율 |
| 연합 내 이해관계 충돌 | 주도권과 비용 분담 갈등으로 업그레이드가 지연 | 스마트 컨트랙트 기반 온체인 투표(**DAO**, Decentralized Autonomous Organization)와 운영 SLA(Service Level Agreement) 협약 | 업그레이드 소요 기간, 의사결정 지연 건수 |

## Ⅵ. 블록체인 유형에 대한 기술사적 제언

- 핵심 요약 : 업무 요건에 맞는 유형을 고르고, 규제 준수와 신원 체계를 설계 단계부터 결합해 블록체인을 운영 가능한 인프라로 정착.

1. 기업이 Web3 서비스를 도입할 때는 사내 데이터를 사설 롤업에서 처리하고 최종 보안은 공개 메인넷에 위탁하는 구조를 우선 검토하는 것이 합리적이다.
2. 금융 결제와 중앙은행 디지털화폐 인프라는 컨소시엄 방식으로 구축하고, 자금세탁방지(AML, Anti-Money Laundering)와 고객확인(KYC, Know Your Customer) 절차를 합의 구조에 포함하는 것이 바람직하다.
3. 개인이 자신의 신원 정보를 직접 통제하도록 분산 식별자(DID, Decentralized Identifier)와 자기주권신원(SSI, Self-Sovereign Identity) 체계를 공개 체인과 연계하면, 기관 중심 신원 인증의 한계를 보완할 수 있다.

## Ⅶ. 결론

- 핵심 요약 : 블록체인 유형은 탈중앙성과 기밀성, 처리 속도 사이의 상충을 업무 요건에 맞게 배치하는 설계 선택지.
- 시사점 : 단일 정답이 없으므로 참여 주체와 규제 요건을 먼저 정의한 뒤 유형을 고르는 순서가 실패를 줄이는 핵심이다.
