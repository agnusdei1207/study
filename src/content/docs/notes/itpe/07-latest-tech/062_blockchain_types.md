## 30초 인출

- 본질: **블록체인 유형** 은 네트워크 참여 권한(무허가 vs 허가), 검증 합의 주체, 데이터 공개 범위 및 거버넌스 구조에 따라 퍼블릭, 프라이빗, 컨소시엄, 하이브리드로 분류한 분산원장 아키텍처 체계
- 메커니즘: 비즈니스 요구 분석 → 신원 인증 필요성 판정 → 트랜잭션 성능(TPS) 및 데이터 기밀성 요구 매핑 → 최적 블록체인 토폴로지(단독 체인 또는 하이브리드 앵커링) 선택
- 통찰: 단일 블록체인 유형만으로는 기밀성과 탈중앙 신뢰성을 동시 만족하기 어려우므로 엔터프라이즈 내부 처리는 컨소시엄 체인, 최종 증명은 퍼블릭 체인에 앵커링하는 하이브리드 아키텍처 구축 필수

<details><summary>핵심 용어</summary>

- **퍼블릭 블록체인(Public Blockchain)** : 누구든지 자유롭게 네트워크에 참여하여 트랜잭션을 발생시키고 합의에 기여하는 무허가형 원장.
- **프라이빗 블록체인(Private Blockchain)** : 단일 조직이 중앙 집중적으로 노드 승인과 데이터 접근 권한을 엄격히 통제하는 폐쇄형 원장.
- **컨소시엄 블록체인(Consortium Blockchain)** : 사전 승인된 복수의 동일/이종 산업체 연합이 합의와 원장 운영 책임을 분담하는 B2B 원장.
- **하이브리드 블록체인(Hybrid Blockchain)** : 프라이빗/컨소시엄의 고성능·기밀성과 퍼블릭의 불변 신뢰성을 연계한 상호운용 아키텍처.
- **해시 앵커링(Hash Anchoring)** : 프라이빗 체인의 블록 상태 머클 루트 해시를 퍼블릭 체인의 스마트 계약에 주기적으로 기록하여 사후 위변조를 증명하는 기법.

</details>

## 2~4교시 25점 답안

## Ⅰ. 블록체인 유형의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **블록체인 유형** 은 네트워크의 참여 허가 여부(Permissionless vs Permissioned), 합의 주체, 원장 열람 권한 및 운영 거버넌스 형태에 따라 분류한 분산원장 토폴로지 |
| 목적 | 비즈니스 목적에 부합하는 트랜잭션 처리 속도(TPS), 데이터 기밀성(Privacy), 규제 준수(Compliance) 및 탈중앙화 신뢰 수준 간의 최적 균형 달성 |

## Ⅱ. 블록체인 유형별 핵심 특징

| 구분 | 참여 및 검증 권한 | 핵심 특징 및 엔지니어링 메커니즘 |
|---|---|---|
| **퍼블릭 (Public)** | 완전 개방 (무허가형) | 암호경제학적 보상(토큰) 기반 분산 합의(PoW/PoS), 절대적 데이터 불변성과 검열 저항성 보장 |
| **프라이빗 (Private)** | 단일 조직 허가형 | 중앙화된 단일 관리자가 노드 통제, PBFT/Raft 기반의 수만 TPS 고속 처리 및 즉각적 완결성 |
| **컨소시엄 (Consortium)** | 복수 인가 조직 연합 | 미리 합의된 파트너 기업 노드들이 지분/투표 기반 합의, 다자간 B2B 공급망 및 금융 정산 최적화 |
| **하이브리드 (Hybrid)** | 프라이빗 + 퍼블릭 결합 | 내부 트랜잭션은 고속 프라이빗망에서 기밀 처리하고, 위변조 방지 머클 증명만 퍼블릭망에 앵커링 |

## Ⅲ. 블록체인 유형 분류 및 하이브리드 체계

```text
┌────────────────────────────────────────────────────────────────────────┐
│             [ 엔터프라이즈 하이브리드 블록체인 앵커링 아키텍처 ]             │
└────────────────────────────────────────────────────────────────────────┘
 [ 기업 컨소시엄 영역 (허가형 프라이빗/컨소시엄 체인) ]
   ├── 참여자: 제조사, 유통사, 금융사 (MSP 인증 기반 참여)
   ├── 고속 B2B 계약 및 정산 실행 (Raft 합의, 5,000+ TPS)
   └── 원본 거래 데이터 및 PII 기밀 유지 (채널 및 프라이빗 데이터 컬렉션)
          │
          ▼ (주기적 에폭마다 머클 루트 해시 추출: 매 100블록)
 [ 크로스체인 릴레이어 (Relayer Bridge) ] ── (영지식 증명 ZKP 생성)
          │
          ▼ (온체인 트랜잭션 제출: 최소 가스비 발생)
 [ 글로벌 신뢰 앵커 영역 (퍼블릭 블록체인: 이더리움 L1) ]
   ├── 스마트 계약: VerifyAndAnchor(MerkleRoot, Timestamp, Proof)
   └── 전 세계 분산 노드를 통한 불변의 타임스탬프 공증 (위변조 불가 증명)
          │
          ▼
 [ 대외 감사관 및 일반 소비자 ] ── (퍼블릭 체인 해시 조회를 통해 원본 무결성 즉시 검증)
```

| 유형 축 | 결정 기준 | 공학적 설계 고려사항 |
|---|---|---|
| **참여 권한 축** | 무허가(Permissionless) vs 허가(Permissioned) | PKI X.509 인증서 및 멤버십 관리(MSP) 필요 여부 |
| **운영 주체 축** | 단일 기업 vs 컨소시엄 연합 vs 전 세계 대중 | 노드 인프라 유지비용 분담 및 거버넌스 룰 확립 |
| **데이터 공개 축** | 원장 전체 공개 vs 채널별 암호화 격리 | 개인정보보호법(GDPR 잊힐 권리) 및 영업비밀 보호 |

## Ⅳ. 블록체인 4대 유형 종합 비교

| 비교 항목 | 퍼블릭 블록체인 | 프라이빗 블록체인 | 컨소시엄 블록체인 | 하이브리드 블록체인 |
|---|---|---|---|---|
| **참여 자격** | 누구나 자유 참여 | 단일 조직 승인 노드 | 인가된 연합체 노드 | 내부: 인가 노드 / 외부: 누구나 |
| **합의 방식** | PoW, PoS, DPoS 등 | Raft, Kafka, Paxos | PBFT, IBFT, QBFT | 프라이빗 합의 + 퍼블릭 검증 |
| **트랜잭션 속도** | 낮음 (15 ~ 1,000 TPS) | 매우 높음 (10,000+ TPS)| 높음 (1,000 ~ 5,000 TPS)| 고속 실행 + 주기적 앵커링 |
| **완결성 (Finality)**| 확률적 완결성 | 즉각적 결정론적 완결 | 즉각적 결정론적 완결 | 내부 즉각 확정 + 외부 최종 공증 |
| **데이터 기밀성** | 매우 취약 (전체 공개) | 매우 우수 (완전 격리) | 우수 (참여사 간 공유) | 탁월 (원문 격리, 해시만 공증) |
| **네이티브 토큰** | 필수 (채굴/가스 보상) | 불필요 | 불필요 (선택적 발행) | 퍼블릭 앵커링 수수료용 최소 보유 |
| **대표 사례** | Bitcoin, Ethereum | Hyperledger Fabric | R3 Corda, BCOS | Hedera, L1-L2 Rollup, Dragonchain |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 퍼블릭 블록체인은 모든 데이터가 공개되어 기업 기밀 유출 및 GDPR의 개인정보 삭제권(잊힐 권리) 충돌 발생 | 원본 데이터는 사내 DB 또는 오프체인 분산 스토리지(IPFS)에 암호화 보관하고, 온체인에는 익명화된 해시값과 영지식 증명(ZKP)만 기록 |
| 프라이빗 블록체인은 소수 관리자의 담합(Collusion)이나 관리자 키 탈취 시 원장 조작 가능성이 존재하여 대외 공신력 결여 | 주기적으로 머클 트리의 최상위 루트 해시를 퍼블릭 L1 체인에 타임스탬프와 함께 트랜잭션으로 공증하는 해시 앵커링(Anchoring) 결합 |
| 컨소시엄 블록체인 구축 시 참여 기업 간 노드 호스팅 비용 분담 갈등 및 표준 인터페이스 부재로 거버넌스 교착 | 중립적 운영 재단 설립, 오픈소스 표준 API 채택 및 스마트 계약 기반의 거버넌스 투표(DAO) 규칙 사전 명문화 |

## Ⅵ. 제언

고속 B2B 업무 처리는 컨소시엄 블록체인 채널에서 수행하고, 외부 감사 및 신뢰 공증은 퍼블릭 체인에 앵커링하는 이원화 하이브리드 아키텍처 구축.

```text
[ 기업 간 대규모 비즈니스 거래 ]
               │
               ▼
[ 1단계: 컨소시엄 블록체인 실행 계층 (Hyperledger Fabric) ]
   ├── 고성능 스마트 계약 체인코드 실행 (초당 3,000건 처리)
   └── 거래 당사자 간 프라이빗 데이터 컬렉션(PDC) 암호화 저장
               │
               ▼ (일 단위 / 1,000건 단위 집계 머클 루트 도출)
[ 2단계: 신뢰 앵커링 인터페이스 (ZKP State Anchor) ]
   ├── 머클 루트 해시 + 유효성 영지식 증명(Validity Proof) 생성
   └── 퍼블릭 L1 체인(이더리움) 스마트 계약으로 최소 가스비 커밋
               │
               ▼
[ 3단계: 대외 공증 완료 (위변조 불가 신뢰성 확보) ]
```

| 구분 | 단일 퍼블릭/프라이빗 고집 | 제언: 이원화 하이브리드 아키텍처 |
|---|---|---|
| **처리 성능** | 퍼블릭 채택 시 극심한 병목 | 컨소시엄 채널을 통해 수천 TPS 고속 처리 |
| **운영 비용** | 매 트랜잭션마다 가스 수수료 낭비 | 수천 건 묶음 앵커링으로 가스비 99% 절감 |
| **대외 공신력** | 프라이빗 채택 시 내부 조작 의혹 잔존 | 글로벌 퍼블릭 체인 앵커링으로 완벽한 법적 증거력 |
