## 한 줄 본질
- 구글, 메타 등 거대 플랫폼 기업이 사용자의 행동 데이터를 독점하여 막대한 광고 수익을 창출하고 검열을 행사하던 Web 2.0의 중앙집중 병목 → 블록체인 분산 원장, 스마트 계약, 탈중앙 스토리지(IPFS)를 통해 데이터의 소유권과 수익을 사용자에게 직접 환원하는 분산형 인터넷 / 처리 속도(TPS) 한계 및 사용성 난점 존재

## 핵심 용어
- 스마트 계약(Smart Contract): 블록체인 네트워크에 배포되어 특정 조건이 충족되면 제3자의 개입 없이 자동으로 코드가 실행되어 계약 내용이 이행되는 불변의 프로그램
- 탈중앙 신원증명(Decentralized Identifier, DID): 포털 기업의 계정(OAuth) 대신, 사용자가 자신의 공개키/개인키 암호학 쌍으로 자신의 신원을 직접 생성하고 증명하는 자기주권형 신원 규격
- IPFS(InterPlanetary File System): 대용량 파일을 중앙 웹 서버가 아닌 전 세계 P2P 노드들에 파일의 해시값(CID)을 기반으로 분산 저장하고 중복 없이 콘텐츠 주소로 불러오는 분산 파일 시스템

## 핵심 통찰
- 웹 3.0의 본질은 "읽기(Web 1.0) → 읽기/쓰기(Web 2.0) → 읽기/쓰기/소유(Web 3.0)"로의 인터넷 패러다임 전환: 사용자가 작성한 글, 구매한 아이템, 생성한 데이터가 플랫폼 DB에 종속되지 않고 블록체인 지갑에 귀속됨
- 과거 버너스 리(Tim Berners-Lee)가 제안한 "시맨틱 웹(Semantic Web)" 관점의 기계가 이해하는 데이터 웹과, 개빈 우드(Gavin Wood)가 제안한 "블록체인 분산 웹"이 현재는 지능형 에이전트와 암호화폐 경제로 상호 결합
- 트릴레마(Trilemma) 극복이 대중화의 관건: 보안성, 탈중앙성을 유지하면서 초당 수천 건의 속도(확장성)를 내기 위해, 핵심 합의는 L1에서 하고 대량의 트랜잭션은 영지식 증명(ZK-Rollup)으로 L2에서 묶어 처리하는 모듈러 블록체인이 핵심 인프라

## 이웃 토픽과 구분
- Web 2.0 vs Web 3.0: Web 2.0은 중앙 기업 서버(AWS, RDBMS)에 계정과 데이터를 저장하고 기업이 통제 / Web 3.0은 P2P 분산 원장과 스마트 계약에 상태를 저장하고 개인이 개인키로 직접 소유 및 서명

## 문제·원인·대책
- 적용 상황: 웹3 기반 글로벌 음원 스트리밍 DApp에서 신규 사용자 가입률 저조 및 이탈
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 사용자가 24개 시드 구문(개인키)을 외우지 못해 분실하고 계정 영구 상실 | 비가역적 개인키 보관 방식의 높은 UX 진입 장벽 | ERC-4337 계정 추상화(Account Abstraction) 및 소셜 복구(Social Recovery) 도입 | 이메일/생체인증 기반 간편 가입 및 계정 복구 가능 |
| 곡을 재생할 때마다 수천 원의 온체인 가스비가 발생하여 서비스 지속 불가 | 레이어1 메인넷의 비싼 수수료 및 낮은 처리량(15 TPS) | 이더리움 L2 ZK-Rollup 및 가스비 대납(Paymaster) 아키텍처 적용 | 트랜잭션 수수료 99% 절감 및 수천 TPS 처리 |
| 스마트 계약 코드의 재진입(Reentrancy) 결함으로 100억 원 상당 토큰 탈취 | 온체인 배포 후 수정이 불가능한 불변성 코드의 로직 버그 | 배포 전 정적 분석(Slither), 형식 검증(Formal Verification) 및 다중 서명 타임락 | 스마트 계약 보안 결함 제로화 및 자산 탈취 차단 |
