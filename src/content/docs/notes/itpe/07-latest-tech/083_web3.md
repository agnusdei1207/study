## 30초 인출

- 본질: 거대 빅테크 플랫폼의 데이터 독점과 중개 수수료 한계를 극복하고, 블록체인·스마트 계약·분산 스토리지를 기반으로 데이터의 소유권과 거래 주권을 사용자에게 환원하는 탈중앙화 분산 웹 생태계.
- 메커니즘: 사용자 비수탁 지갑(Wallet) 서명 $\rightarrow$ 프론트엔드 DApp 상호작용 $\rightarrow$ 스마트 계약 실행 및 온체인 합의 $\rightarrow$ IPFS/Arweave 기반 탈중앙 분산 스토리지 연동 $\rightarrow$ 토큰 이코노미 보상.
- 통찰: 무조건적인 온체인화는 트릴레마(확장성 병목, 높은 가스비)와 영구 개인키 분실 위험을 초래하므로 계정 추상화(ERC-4337), 롤업(Rollup) 레이어 2, 오프체인 분산 인덱싱(The Graph) 결합 필수.

<details><summary>핵심 용어</summary>

- **웹 3.0(Web 3.0):** 읽기(1.0), 쓰기(2.0)를 넘어 '소유(Read-Write-Own)'를 핵심 가치로 삼는 탈중앙화 분산 인터넷 패러다임.
- **DApp(Decentralized Application):** 단일 중앙 서버 대신 블록체인 스마트 계약을 백엔드 비즈니스 로직으로 채택하여 구동되는 탈중앙화 애플리케이션.
- **스마트 계약(Smart Contract):** 서면 계약 대신 코드 형태로 블록체인에 배포되어 특정 조건 충족 시 사전 정의된 상태 전이가 강제 집행되는 불변의 프로그램.
- **콘텐츠 주소 지정(Content Addressing):** 파일의 물리적 위치(IP/URL) 대신 데이터 자체의 암호학적 해시값(CID)으로 검색 및 무결성을 검증하는 방식(IPFS).
- **계정 추상화(Account Abstraction, ERC-4337):** 복잡한 개인키·시드 구문 대신 스마트 계약 기반 지갑을 통해 소셜 복구, 가스비 대납, 멀티시그를 구현하는 표준.
</details>

## 2~4교시 25점 답안

## Ⅰ. 탈중앙화 가치 인터넷의 태동, 웹 3.0의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 블록체인 분산원장, 스마트 계약, 탈중앙 신원증명(DID), 분산 파일 시스템을 융합하여 사용자가 데이터와 디지털 자산의 소유권을 직접 통제하는 탈중앙 분산 웹 패러다임 |
| 목적 | 중앙 집중형 플랫폼의 데이터 독점 및 단일 장애점(SPOF) 탈피, 중개자 없는 P2P 가치 교환, 프라이버시 보장 및 검열 저항성 확보 |

- Web 1.0의 일방향 정보 소비, Web 2.0의 참여와 공유 기반 플랫폼 독점 시대를 지나 데이터의 직접 소유와 수익 배분을 지향하는 가치 인터넷으로 진화.
- 불변성(Immutability)과 투명성을 보장하는 탈중앙 프로토콜을 기반으로 금융(DeFi), 자율조직(DAO), 소유권 증명(NFT) 생태계 형성.

## Ⅱ. 웹 3.0의 핵심 특징 및 구성요소

| 핵심 특징 | 세부 내용 | 구현 메커니즘 |
|---|---|---|
| 탈중앙화 (Decentralization) | 중앙 통제 기관 없이 분산 합의 알고리즘을 통해 네트워크 상태 관리 | PoS(Proof of Stake), BFT 기반 분산 노드 간 합의 |
| 신뢰 최소화 (Trustless) | 제3의 신뢰 기관 없이 암호학적 검증과 스마트 계약 코드로 신뢰 담보 | 불변의 EVM 바이트코드 및 영지식 증명(ZKP) |
| 사용자 데이터 주권 | 사용자 스스로 개인키 기반 신원과 데이터를 관리하고 접근 권한 통제 | W3C DID(탈중앙 신원) 및 검증 가능한 자격증명(VC) |
| 상호운용성 및 개방성 | 특정 플랫폼에 종속되지 않고 프로토콜 표준에 따라 자유로운 자산 이전 | 크로스체인 브리지, ERC-20/721 토큰 표준 인터페이스 |

| 4대 핵심 구성요소 | 주요 역할 | 대표 기술 스택 |
|---|---|---|
| 분산 원장 계층 (L1/L2) | 트랜잭션 검증, 상태 전이 기록, 스마트 계약 실행 환경 | Ethereum, Solana, Arbitrum, Optimism |
| 분산 저장소 계층 | 온체인 저장 비용 극복을 위한 대용량 콘텐츠 P2P 분산 저장 | IPFS(InterPlanetary File System), Arweave, Filecoin |
| 탈중앙 신원·인증 계층 | 중앙 포털 로그인 탈피, 암호화 키 기반 자체 주권 신원 | W3C DID, MetaMask, Soulbound Token(SBT) |
| 분산 인덱싱·오라클 | 블록체인 상태 데이터의 고속 쿼리 및 외부 현실 데이터 공급 | The Graph(서브그래프 인덱싱), Chainlink(Decentralized Oracle) |

## Ⅲ. 웹 3.0 탈중앙화 아키텍처 및 DApp 서비스 프로세스

```text
+-------------------------------------------------------------------------------------------------+
|                                 Web 3.0 Full-Stack Architecture                                 |
+-------------------------------------------------------------------------------------------------+
 [User Client] ---> [Non-Custodial Wallet (MetaMask / Privy)] ---> [ECDSA / ERC-4337 Sign]
        |
        +---> [DApp Frontend (Next.js / React)] <---+ (GraphQL Query)
                     |                              |
        +------------+------------+                 |
        v                         v                 |
 [Smart Contract Call]    [CID Request]             |
        |                         |                 |
        v                         v                 |
 [Blockchain (Layer 1/2)]  [IPFS / Arweave] ---> [The Graph Indexer]
  - State Transition        - Content Addressing  (Decentralized Cache)
  - EVM Execution           - P2P File Pinning
```

| 프로세스 단계 | 주요 수행 내용 | 핵심 기술 요소 |
|---|---|---|
| 1. 지갑 연결 및 인증 | 사용자가 비수탁 지갑을 DApp에 연결하고 전자서명으로 신원 증명 | Web3.js, Ethers.js, EIP-712 구조화 서명 |
| 2. 트랜잭션 생성 및 서명 | 사용자 행동(거래, 투표)을 스마트 계약 호출 트랜잭션으로 구성 후 서명 | RPC 노드 엔드포인트(Infura, Alchemy) 호출 |
| 3. 온체인 합의 및 실행 | 검증인 노드들이 트랜잭션을 블록에 포함하고 EVM 런타임에서 상태 변경 | 가스비(Gas Fee) 소진, 블록 확정성(Finality) |
| 4. 오프체인 자산 저장 | 고용량 이미지나 메타데이터는 IPFS에 업로드 후 암호화 해시(CID)만 온체인 기록 | SHA-256 기반 Content Identifier(CID), Pinning |
| 5. 분산 인덱싱 쿼리 | 블록체인에 발생한 이벤트를 인덱서가 추출하여 프론트엔드에 고속 제공 | The Graph Subgraph, GraphQL API |

## Ⅳ. 웹 세대별(Web 1.0 vs Web 2.0 vs Web 3.0) 비교

| 비교 항목 | Web 1.0 (정적 웹) | Web 2.0 (소셜·플랫폼 웹) | Web 3.0 (분산·시맨틱·가치 웹) |
|---|---|---|---|
| 핵심 행위 패러다임 | 읽기 (Read-only) | 읽기 및 쓰기 (Read-Write) | 읽기, 쓰기, 소유 (Read-Write-Own) |
| 인프라 구조 | 중앙 집중식 웹 서버 | 중앙 클라우드 및 대형 데이터센터 | 블록체인 분산 원장 및 P2P 스토리지 |
| 데이터 통제 주체 | 사이트 운영자 | 플랫폼 기업 (구글, 메타, 네이버) | 개별 사용자 (자체 주권 신원) |
| 수익 배분 모델 | 배너 광고, 단순 유료화 | 플랫폼 독점 광고 모델, 수수료 | 토큰 이코노미 기반 프로토콜 기여자 직접 분배 |
| 계정 및 인증 방식 | 사이트별 개별 ID/PW | 소셜 로그인 (OAuth 연동) | 암호학적 개인키 기반 지갑 (DID) |
| 검색 및 연동 기술 | 단순 하이퍼링크, 디렉터리 | 중앙 REST API, 검색 알고리즘 | 시맨틱 온톨로지, 스마트 계약, GraphQL |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 블록체인의 낮은 처리량(TPS)과 네트워크 혼잡 시 발생하는 극심한 가스비(Gas Fee) 폭증 병목 | 트랜잭션 연산을 오프체인에서 묶어 처리하고 L1에 증명만 제출하는 롤업(Optimistic, ZK-Rollup) 레이어 2 도입 |
| 개인키(Private Key) 분실 시 자산 및 신원 영구 상실 위험과 복잡한 UX 진입 장벽 | 스마트 계약 지갑 기반의 계정 추상화(ERC-4337), 소셜 복구(Social Recovery) 및 가스비 대납(Paymaster) 구현 |
| IPFS 등 분산 스토리지에서 노드가 핀(Pin)을 해제하면 데이터가 영구 유실되는 가용성 부재 | 파일코인(Filecoin), 알위브(Arweave) 등 영구 저장 인센티브 프로토콜 및 다중 피닝(Pinning) 서비스 결합 |

## Ⅵ. 제언

웹 3.0은 완전한 탈중앙화만을 고집하기보다 Web 2.0의 고성능 UX와 Web 3.0의 소유권 신뢰를 융합하는 실용적 하이브리드 아키텍처 필수.

```text
[Web2 Seamless UX] ---> [ERC-4337 Account Abstraction] ---> [Layer 2 Scalable Rollup]
  - Social Login Shell      - Seedless Social Recovery         - Ultra Low Gas Fee
  - Fast Client Caching     - Gasless Transactions             - ZK-Proof Instant Finality
```

| 진화 관점 | 엔지니어링 실행 방안 | 기술적 기대효과 |
|---|---|---|
| 사용자 경험(UX) | Passkey(WebAuthn) 및 MPC(다자간 계산) 키 분할 복구 적용 | 시드 문구 없는 직관적 지갑 생성 및 보안성 확보 |
| 확장성·상호운용성 | EVM 호환 ZK-Rollup 및 체인 추상화(Chain Abstraction) 프로토콜 구축 | 이종 체인 간 매끄러운 트랜잭션 실행 및 초고속 확정 |
