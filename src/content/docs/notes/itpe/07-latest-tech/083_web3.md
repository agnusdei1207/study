## 연관 키워드

- 웹 3.0(Web 3.0), 탈중앙 신원증명, 비수탁 지갑, 스마트 계약, DApp
- 롤업, 계정 추상화, 토큰 이코노미, 검열 저항성, IPFS, 신뢰 최소화

## Ⅰ. 웹 3.0(Web 3.0)의 개요

- 핵심 요약 : 블록체인과 분산 저장소 위에서 사용자가 데이터와 디지털 자산의 소유권을 직접 쥐는 탈중앙 웹 패러다임.
- 개념 : 블록체인 분산원장, 스마트 계약, **탈중앙 신원증명** (DID, Decentralized Identifier), 분산 파일 저장소를 결합해 사용자가 데이터와 자산을 직접 통제하는 **웹 3.0**(Web 3.0)의 기술 체계.
- 배경 및 필요성 : Web 2.0 플랫폼에 사용자 데이터와 수익이 집중되고 단일 장애점(SPOF, Single Point of Failure)이 생기면서 사용자 주권과 검열 저항성에 대한 요구가 커짐. 다만 모든 연산을 블록체인에 올리면 처리량과 비용 문제가 생기므로 **롤업** (Rollup) 같은 레이어 2와 오프체인 연동이 함께 쓰이는 것이 전제임.
- 주요 목적 : 중개자 없는 P2P(Peer-to-Peer) 가치 교환, 프라이버시 보장, 플랫폼 독점 구조 완화.

## Ⅱ. 웹 3.0(Web 3.0)의 특징 및 장점

- 핵심 요약 : 탈중앙화, 신뢰 최소화, 데이터 주권, 상호운용성이 중개 비용 감소와 사용자 통제권 확대로 이어지는 구조.

1. **탈중앙화** (Decentralization) : 중앙 기관 없이 분산 합의로 네트워크 상태를 관리 → 단일 장애점 제거와 검열 저항성 확보.
2. **신뢰 최소화** (Trustless) : 암호학적 검증과 스마트 계약 코드로 제3자 신뢰를 대체 → 중개 비용과 신뢰 위험 감소.
3. 사용자 데이터 주권 : 개인키 기반 신원과 검증 가능한 자격증명(VC, Verifiable Credential)으로 접근 권한을 사용자가 통제 → 플랫폼 종속 탈피.
4. 상호운용성과 개방성 : ERC(Ethereum Request for Comments)-20, ERC-721 같은 토큰 표준과 크로스체인 브리지로 자산 이전 → 특정 플랫폼 종속 완화.
5. **토큰 이코노미** (Token Economy) : 네트워크 기여자에게 토큰으로 보상을 분배하는 구조 → 프로토콜 참여 동기 강화.

## Ⅲ. 웹 3.0(Web 3.0)의 구조 (흐름)

- 핵심 요약 : 비수탁 지갑 서명에서 DApp, 스마트 계약, 분산 저장소, 인덱서로 이어지는 다계층 구조.
- **비수탁 지갑** (Non-Custodial Wallet) : 개인키를 사용자가 직접 보관하고 트랜잭션에 서명하는 지갑으로, 웹 3.0 진입점 역할 수행.
- **DApp** (Decentralized Application) : 프론트엔드가 스마트 계약과 분산 저장소를 호출하는 탈중앙 애플리케이션.

```text
[ 사용자 (비수탁 지갑 서명) ]
          ↓
[ DApp 프론트엔드 ]
     ↓            ↓
[ 스마트 계약 ]  [ 콘텐츠 주소 요청 ]
     ↓            ↓
[ 블록체인 L1/L2 ] [ IPFS·Arweave 저장 ]
     ↓            ↓
[ 인덱서 (GraphQL 조회) ]
```

```text
[ 계정 추상화 흐름 ]

개인키 단일 보관 (분실 시 복구 불가)
          ↓
스마트 계약 지갑 (ERC-4337)
          ↓
소셜 복구 · 가스비 대납 (Paymaster)
          ↓
사용자 경험 개선
```

- **IPFS** (InterPlanetary File System) : 파일 내용의 해시로 주소를 매기는 분산 파일 저장 체계이며, 콘텐츠 식별자(CID, Content Identifier)로 조회.
- **합의 계층** : PoS(Proof of Stake)와 BFT(Byzantine Fault Tolerance) 계열 알고리즘으로 노드 간 상태 일치를 확보.

## Ⅳ. 웹 1.0·2.0과 웹 3.0의 비교

- 핵심 요약 : 읽기 중심의 정적 웹, 플랫폼 중심의 쓰기 웹에서 소유와 가치 분배까지 포함하는 웹으로 확장.

| 비교 축 | Web 1.0 (정적 웹) | Web 2.0 (플랫폼 웹) | Web 3.0 (분산 가치 웹) |
| --- | --- | --- | --- |
| 행위 패러다임 | 읽기 | 읽기·쓰기 | 읽기·쓰기·소유 |
| 인프라 | 중앙 웹 서버 | 중앙 클라우드·데이터센터 | 블록체인 원장과 P2P 저장소 |
| 데이터 통제 주체 | 사이트 운영자 | 플랫폼 기업 | 개별 사용자 |
| 수익 분배 | 배너 광고, 단순 유료화 | 플랫폼 독점 광고·수수료 | 토큰 기반 기여자 직접 분배 |
| 계정 인증 | 사이트별 ID·비밀번호 | 소셜 로그인 (OAuth 연동) | 개인키 기반 지갑 (DID) |

- 선택 기준 : 데이터 소유권과 가치 분배가 핵심 요구인지, 처리 성능과 UX가 우선인지에 따라 적용 범위를 정함.

## Ⅴ. 웹 3.0(Web 3.0)의 한계와 방안

- 핵심 요약 : 처리량, 키 관리, 데이터 가용성 문제를 레이어 2, 계정 추상화, 영구 저장 인센티브로 나눠 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 낮은 처리량과 가스비 급등 | 온체인 연산 집중 → 혼잡 시 비용과 지연 증가 | 롤업 기반 레이어 2로 연산 오프체인화 | 트랜잭션당 비용, 확정 지연 |
| 개인키 분실과 높은 진입장벽 | 키가 곧 자산·신원이므로 분실 시 복구 경로 없음 | 계정 추상화 (ERC-4337), 소셜 복구 | 복구 성공률, 지갑 이탈률 |
| 분산 저장소 데이터 유실 | 노드가 핀(Pin)을 해제하면 데이터 보관 중단 | 영구 저장 인센티브 프로토콜과 다중 피닝 결합 | 콘텐츠 가용성 점검률 |

## Ⅵ. 웹 3.0(Web 3.0)에 대한 기술사적 제언

- 핵심 요약 : 완전 탈중앙화보다 Web 2.0의 UX와 Web 3.0의 소유 신뢰를 섞는 하이브리드 아키텍처를 단계적으로 도입하는 방향.

1. 전사 아키텍처 표준에 하이브리드 구조를 명시하고, 온체인과 오프체인의 역할 경계를 정책으로 정의하는 것이 필요함.
2. 키 관리 측면에서는 계정 추상화와 소셜 복구를 기본 제공하여 사용자가 키 분실 위험을 체감하지 않도록 설계하는 것이 바람직함.
3. 확장성과 상호운용성은 EVM 호환 롤업과 체인 간 연결 표준을 기준으로 검증하고, 파일럿 단계의 성과 지표를 바탕으로 확산 범위를 넓히는 방식이 현실적임.

## Ⅶ. 결론

- 핵심 요약 : 웹 3.0은 데이터와 자산의 소유권을 사용자에게 돌려주는 탈중앙 웹 패러다임.
- 시사점 : 처리량과 키 관리의 한계가 기술로 상당 부분 보완되고 있으나, 성공 여부는 사용자가 실제로 체감하는 편의성에 달려 있음.
