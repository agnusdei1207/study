## 큰 그림과 30초 인출

```text
                  [이사회·경영진: 위험선호·책임]
                              │
         ┌────────────────────┼────────────────────┐
         ▼                    ▼                    ▼
   [원칙·정책]           [조직·RACI]          [법·표준 준거]
 공정·안전·투명성       소유자·검토자·승인자   AI기본법·42001·RMF
         └────────────────────┬────────────────────┘
                              ▼
 기획 → 데이터 → 개발 → 검증 → 배포 → 운영 → 변경·폐기
  │       │       │       │       │       │
  └──── 위험분류·영향평가·gate·monitoring·incident·증적 ────┘
```

- 본질: AI 원칙을 선언하는 문서가 아니라 생명주기별 의사결정권·통제·증적을 연결하는 경영 체계
- 인출: `원칙-조직-프로세스-기술-증적`
- 실행: `Govern → Map → Measure → Manage`, ISO/IEC 42001은 PDCA 기반 관리시스템
- 현행성: 국내 인공지능기본법은 시행 중이며 고영향 AI·투명성·안전성·신뢰성 의무를 반영해야 함

## 예상문제

> AI 거버넌스의 개념과 구성체계, 생명주기 통제 프로세스를 설명하고 IT 거버넌스와의 차이 및 고영향 AI 운영 시 고려사항을 논하시오. (25점)

## Ⅰ. AI 가치와 위험을 책임 있게 조정하는 AI 거버넌스 개요

- 정의: **AI 거버넌스**는 조직의 전략·법규·위험선호에 맞춰 AI 시스템의 기획부터 폐기까지 의사결정권, 책임, 정책, 통제, 성과와 위험을 관리하는 체계
- 목적: AI의 업무 가치를 확보하면서 유효성·안전성·보안·공정성·투명성·프라이버시 위험을 수용 가능한 수준으로 통제
- 필요성: AI는 데이터·모델·외부 공급망·사용 맥락에 따라 출력이 변하고 운영 중 drift와 오용이 발생하므로 전통적 SW 승인만으로 잔여 위험을 설명하기 어려움

#### 한줄 요약

- AI 거버넌스는 누가 어떤 근거로 AI를 승인·감시·중단하는지 정하고 그 판단 증적을 남기는 체계임

## Ⅱ. 생명주기·위험기반·증적중심의 AI 거버넌스 특징

| 특징 | 구현 수단 | 판단 산출물 | 기대효과 |
|---|---|---|---|
| **위험기반 차등통제** | 영향·용도·사용자별 위험분류 | AI inventory·risk tier | 고위험 대상에 통제 집중 |
| **전 생명주기** | 단계별 gate와 변경관리 | 영향평가·검증·승인·폐기 기록 | 개발 후 뒷수습 방지 |
| **다학제 책임** | 경영·법무·보안·데이터·현업 RACI | model/system owner 지정 | 책임 공백 방지 |
| **사회기술 평가** | 성능뿐 아니라 사람·사회 영향 평가 | TEVV·human oversight 결과 | 맥락별 위해 식별 |
| **감사가능성** | lineage·log·model card·incident 기록 | 재현 가능한 증적 | 설명·감사·분쟁 대응 |
| **지속개선** | 지표·사건·법규 변화의 PDCA | 시정조치·재평가 이력 | 운영 중 위험 갱신 |

#### 한줄 요약

- AI 거버넌스는 모든 AI를 동일 통제하지 않고 영향도에 따라 gate와 증적의 깊이를 달리함

## Ⅲ. 원칙·조직·프로세스·기술·준거로 구성되는 체계

```text
┌──────────────── AI Governance ────────────────┐
│ ① 원칙·정책 : 유효·안전·보안·공정·투명·privacy │
│ ② 조직·책임 : 위원회·system owner·3 lines      │
│ ③ 프로세스   : 분류·영향평가·gate·사고·폐기      │
│ ④ 기술통제   : registry·lineage·TEVV·monitoring │
│ ⑤ 준거·증적 : 법령·표준·계약·audit evidence     │
└───────────────────┬───────────────────────────┘
                    ▼
        AI portfolio의 가치·위험·준수 상태
```

| 계층 | 핵심 질문 | 대표 통제 |
|---|---|---|
| **경영** | 어떤 AI 위험을 왜 수용하는가 | 위험선호·금지용도·성과지표 |
| **포트폴리오** | 어떤 시스템이 어디서 사용되는가 | AI inventory·영향/고영향 분류 |
| **프로젝트** | 배포 기준을 충족했는가 | data/model/system 검증 gate |
| **운영** | 성능·안전·법규 상태가 유지되는가 | drift·incident·human override |
| **감사** | 판단과 변경을 재현할 수 있는가 | 독립검토·log·시정조치 추적 |

#### 한줄 요약

- 원칙은 정책으로, 정책은 gate와 기술통제로, 통제 결과는 감사 증적으로 연결되어야 함

## Ⅳ. 등록부터 폐기까지 이어지는 생명주기 거버넌스

```text
① AI use case 등록·owner 지정
          ↓
② 용도·영향·법적 의무 Map / 위험등급 결정
          ↓
③ 데이터·모델·공급망 위험 Measure / TEVV
          ↓
④ 잔여위험 승인·조건부 배포·금지 Manage
          ↓
⑤ 운영 monitoring·human oversight·incident 대응
          ↓
⑥ 변경 시 재평가 / 폐기·data/model·권한 회수
          └──────── 결과를 정책·위험기준에 환류
```

| Gate | 필수 질문 | 통과 증적 |
|---|---|---|
| **기획** | 허용 용도이며 책임자가 있는가 | use case·RACI·위험분류 |
| **데이터** | 권리·대표성·품질·lineage가 적정한가 | dataset card·품질/편향 결과 |
| **모델** | 목표 성능과 안전·보안 기준을 충족하는가 | model card·red team·TEVV |
| **배포** | 사람의 감독·fallback·고지 수단이 있는가 | 승인서·runbook·사용자 고지 |
| **운영** | drift·사고·오용을 감지하고 중지 가능한가 | dashboard·incident log·kill switch 시험 |

#### 한줄 요약

- 거버넌스는 위원회 회의가 아니라 각 단계 전환을 증적 기반으로 허용·제한·거부하는 gate의 연속임

## Ⅴ. IT 자산 관리와 AI 영향 통제를 구분하는 비교

| 구분 | IT 거버넌스 | AI 거버넌스 |
|---|---|---|
| **주요 대상** | IT 투자·자원·서비스·통제 | 데이터·모델·AI 시스템·사용 맥락·영향 |
| **핵심 위험** | 정렬·가치·자원·서비스·보안 | 편향·불투명성·오용·자율성·drift·사회적 위해 |
| **품질 판정** | 기능 요구·SLA·통제 준수 | 확률적 성능·강건성·공정성·안전·사람 감독 |
| **변경 특성** | 코드·설정·인프라 변경 중심 | 데이터 분포·모델·prompt·provider·사용 맥락 변화 포함 |
| **대표 준거** | COBIT·ISO/IEC 38500·27001 | ISO/IEC 42001·NIST AI RMF·AI 관련 법령 |
| **관계** | 상위 기업·IT 의사결정 기반 | IT 거버넌스 안의 AI 특화 통제체계 |

#### 한줄 요약

- AI 거버넌스는 IT 거버넌스를 대체하지 않고 확률적 모델과 인간 영향에 필요한 특화 통제를 추가함

## Ⅵ. 고영향 AI의 형식적 준수를 막는 실무 고려사항

| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| **AI inventory 누락** | 현업 SaaS·외부 API·shadow AI 미등록 | 구매·계약·배포 gateway와 registry 연계 | 통제 대상과 책임자 식별 |
| **고영향 여부 오판** | 모델 종류만 보고 실제 사용 맥락·영향을 미평가 | 용도·대상·결정 영향 기반 영향평가와 확인 절차 | 법적·사회적 의무 누락 방지 |
| **검증 결과 왜곡** | 평균 정확도만 보고 하위집단·edge case를 누락 | subgroup·stress·security·human factors TEVV | 위해 집중 구간 식별 |
| **외부 모델 책임 공백** | provider와 deployer 의무·변경 통지 불명확 | 계약상 역할·version·incident·audit 권리 명시 | 공급망 변경 추적 |
| **증적과 실제 운영 불일치** | 배포 후 prompt·data·정책 변경이 감사 문서에 미반영 | CI/CD/LLMOps gate와 evidence store 자동 연계 | 지속적 감사가능성 확보 |

#### 한줄 요약

- 고영향 AI 통제는 문서 제출보다 use case·모델 version·데이터·평가·승인·운영 상태가 일치해야 실효성이 생김

## Ⅶ. 위험-통제-증적 추적성으로 완성하는 결론

- **[정책을 실행가능한 guardrail로 전환]**: 원칙과 체크리스트만 두면 현업 변경 속도를 따라가지 못하므로 registry·pipeline·monitoring·incident 시스템에 의무 통제를 내재화
- 나라면: `AI use case → 영향/법적 의무 → 위험 → 통제 → 평가결과 → 승인자 → 운영지표·사고` 추적표를 기준선으로 삼고, 중대한 변경이나 임계치 이탈 시 자동 재승인·중지 절차 실행

#### 한줄 요약

- AI 거버넌스의 완성 기준은 선언문이 아니라 위험·통제·승인·운영 증적이 추적되고 중지 결정까지 실행되는 상태임

## 1교시 10점 답안 발췌

### 1. 정의

- AI 거버넌스는 조직의 전략·법규·위험선호에 맞춰 AI 전 생명주기의 의사결정권·책임·정책·통제·성과와 위험을 관리하는 체계

### 2. 구성과 흐름

```text
원칙 → 조직/RACI → 생명주기 gate → 기술통제 → 증적/감사
          Govern → Map → Measure → Manage → Monitor
```

| 구성 | 핵심 |
|---|---|
| 원칙·조직 | 위험선호, 금지용도, owner·승인자 |
| 프로세스 | 영향평가, TEVV, 배포 gate, 사고·폐기 |
| 기술·증적 | registry, lineage, monitoring, audit log |

### 3. 차별화 제언

- AI use case·데이터·모델·평가·승인·운영지표를 추적하고 변경 시 재승인
- 고영향 AI는 실제 사용 맥락과 사람의 권리·안전에 미치는 영향 기준으로 분류
