## 30초 인출

- 본질: **A2A(Agent-to-Agent)** 는 서로 다른 벤더와 환경에서 동작하는 독립적인 AI 에이전트들이 상호 역량을 탐색(Discovery)하고, 태스크를 위임하며, 아티팩트를 안전하게 교환할 수 있도록 정의된 개방형 통신 프로토콜
- 메커니즘: Agent Card 기반 메타데이터 탐색 후 mTLS/DID 상호 인증을 거쳐 Task 상태 머신과 구조화된 Message/Artifact를 비동기 스트리밍 방식으로 교환
- 통찰: 에이전트 간 연쇄적 무한 루프 호출과 권한 상승 위험이 존재하므로 명시적인 최대 홉 수(TTL), 예산 캡핑 및 스키마 검증 기반의 샌드박스 격리 필수

<details><summary>핵심 용어</summary>

- **A2A (Agent-to-Agent)** : 이기종 지능형 에이전트 간의 자동화된 상호작용과 협업을 지원하는 표준화된 통신 규약.
- **Agent Card** : 에이전트의 고유 식별자, 제공 기능, 입출력 스키마, 인증 정책을 명시한 기계 판독 가능한 JSON 메타데이터 문서.
- **Task** : 특정 목표 달성을 위해 에이전트 간에 생성, 실행, 추적되는 작업의 생애주기 단위 (Pending, Running, Completed, Failed).
- **Message** : 지시문, 상황 보고, 매개변수 등을 교환하기 위해 정의된 표준화된 통신 페이로드.
- **Artifact** : Task 수행 결과물로 생성되는 파일, 코드, 데이터베이스 덤프, 구조화 문서 등의 최종 전달 산출물.

</details>

## 2~4교시 25점 답안

## Ⅰ. A2A의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **A2A(Agent-to-Agent)** 는 이기종 AI 에이전트들이 상호 간의 기능과 도구를 동적으로 발견하고, 분업화된 태스크를 할당·조정하며, 그 결과물을 안전하게 수수할 수 있도록 설계된 차세대 에이전트 간 표준 통신 프로토콜 |
| 목적 | 단일 거대 모델의 문맥 한계 및 환각 극복, 전문화된 도메인 에이전트 간 유기적 자율 협업 실현, 멀티 벤더 에이전트 생태계의 상호운용성 보장 |

## Ⅱ. A2A 프로토콜의 4대 핵심 객체 및 통신 특징

| 구분 | 핵심 객체 | 세부 공학적 기능 및 특징 |
|---|---|---|
| **역량 명세** | Agent Card | 에이전트의 엔드포인트 URL, 지원 스킬, 모델 정보, 인증 요건을 기술한 메타데이터 |
| **작업 추적** | Task | 요청된 작업의 생애주기 상태(State Machine)와 진행률, 우선순위 관리 |
| **통신 페이로드** | Message | 에이전트 간 추론 과정, 질문-답변, 오류 코드를 실시간 스트리밍(SSE/WebSocket) 전송 |
| **산출물 인계** | Artifact | 작업 완료 시 생성되는 바이너리 파일, 정형 JSON, 보고서 등의 무결성 해시 보증 산출물 |

## Ⅲ. A2A 프로토콜 아키텍처 및 에이전트 간 협업 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ A2A 분산 에이전트 상호작용 아키텍처 ]                │
└────────────────────────────────────────────────────────────────────────┘
                                    │
 [ 클라이언트 / 오케스트레이터 ]     │ [ 전문 서비스 에이전트 (Worker Agent) ]
                                    │
 1. Agent Discovery ───────────────┼────────► [ Agent Card 레지스트리 ]
    (Agent Card 역량 조회 및 파싱)   │            (기능, 비용, 인증 방식 확인)
                                    │
 2. Task 생성 및 위임 ─────────────┼────────► [ Task 매니저 ]
    (Task ID 발급, 초기 파라미터 주입)│            (State: Pending ──> Running)
                                    │
 3. Message 상호 통신 ◄─────────────┼────────► [ 추론 및 도구 실행 엔진 ]
    (실시간 진행 상황, 중간 피드백) │            (Tool Execution / Sub-Task)
                                    │
 4. Artifact 산출물 전달 ◄──────────┼───────── [ 결과 패키징 및 해시 서명 ]
    (최종 산출물 검증 및 Task 완료)  │            (State: Completed)
```

| 상호작용 단계 | 프로토콜 동작 | 핵심 데이터 포맷 |
|---|---|---|
| **1. 탐색 (Discovery)** | 디렉터리 서비스에서 대상 에이전트의 Agent Card JSON 수신 | `/.well-known/agent.json` |
| **2. 협상 및 생성** | 상호 mTLS 인증 후 작업 위임 POST 요청 발행 | `POST /v1/tasks` (Payload, Budget) |
| **3. 진행 및 모니터링** | Server-Sent Events(SSE) 스트림을 통한 진행 상태 수신 | `text/event-stream` (Status, Log) |
| **4. 결과 인계** | 생성된 아티팩트 다운로드 및 전자서명 유효성 검증 | `GET /v1/tasks/{id}/artifacts` |

## Ⅳ. 단일 에이전트 vs A2A 분산 에이전트 비교

| 비교 항목 | 단일 에이전트 (Single Agent) | A2A 분산 에이전트 (Multi-Agent A2A) |
|---|---|---|
| **역할 분담** | 1개 에이전트가 모든 도구와 작업 독점 | 전문 영역별 특화 에이전트 간 분업 협업 |
| **컨텍스트 부하** | 도구와 대화 기록 누적으로 토큰 한계 도달 | 서브 태스크별 컨텍스트 분리로 토큰 절감 |
| **확장성 (Scalability)** | 새로운 기능 추가 시 프롬프트 복잡도 폭증 | 신규 Agent Card 등록만으로 즉시 생태계 확장 |
| **오류 격리성** | 단일 단계 환각 시 전체 작업 즉시 실패 | 개별 태스크 실패 시 재시도 및 대체 에이전트 라우팅 |
| **보안 경계** | 모든 권한이 단일 실행기에 집중 | 에이전트별 최소 권한(Least Privilege) 부여 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 에이전트 간 재귀적 상호 호출로 인한 토큰 낭비 및 시스템 멈춤(무한 루프) | 메시지 헤더에 최대 호출 깊이(TTL: Time-To-Live)를 명시하고 태스크별 최대 토큰 예산 캡핑 강제 |
| 검증되지 않은 악의적 서드파티 에이전트가 변조된 산출물(Artifact)을 주입 | 탈중앙 신원증명(DID) 기반 에이전트 서명 검증 및 반환된 아티팩트의 자동 샌드박스 격리 검사 |

## Ⅵ. 제언

A2A 프로토콜 기반의 전사 에이전트 게이트웨이를 수립하고, 에이전트 간 트랜잭션을 실시간 감사 추적하는 에이전틱 서비스 메시(Agentic Service Mesh) 아키텍처 구축.

```text
[ 오케스트레이터 에이전트 ]
            │ (A2A Task 요청)
            ▼
[ 에이전트 서비스 메시 (A2A Gateway) ]
   ├── Step 1: Agent Card 및 DID 서명 진위 확인
   ├── Step 2: 호출 깊이(Max Hop=3) 및 토큰 예산 할당
   └── Step 3: PII 필터링 및 악의적 프롬프트 인젝션 차단
            │
       ┌────┴─────────────────────────────┐
       ▼ (정상 라우팅)                     ▼ (정상 라우팅)
[ 회계 전문 에이전트 ]               [ 법률 전문 에이전트 ]
```

| 구분 | 직접 Point-to-Point 에이전트 통신 | 제언: A2A 서비스 메시 기반 중계 |
|---|---|---|
| **보안 통제** | 각 에이전트별 개별 인증 구현 부담 | 중앙 게이트웨이에서 일괄 mTLS 및 권한 제어 |
| **장애 대응** | 상대 에이전트 장애 시 전체 프로세스 중단 | 서킷 브레이커를 통한 장애 격리 및 대체 에이전트 자동 전환 |
| **가시성** | 에이전트 간 대화 로그 추적 불가 | 전체 A2A 트래픽 분산 추적(OpenTelemetry) 및 감사 |
