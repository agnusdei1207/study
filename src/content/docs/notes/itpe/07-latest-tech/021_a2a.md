## 지식 로드맵 내 현재 위치

지식 위치: 에이전트 간 상호운용 → 작업·결과 교환 프로토콜 → **A2A**

## 30초 인출

- 본질: **A2A(Agent-to-Agent)** 는 서로 다른 에이전트가 역량을 찾고 작업·상태·결과를 교환하는 상호운용 프로토콜
- 메커니즘: Agent Card 탐색 → 상대 인증 → Task·Message 교환 → Artifact 인계·통합
- 통찰: 한계: 발견 정보나 결과를 그대로 신뢰하면 권한 밖 작업 실행 가능 → 방안: 상대 역량·인증·결과를 검증하고 작업별 종료 조건 설정

<details>
<summary>핵심 용어</summary>

- **A2A(Agent-to-Agent)** : 에이전트 간 역량 발견과 작업·결과 교환을 위한 상호운용 프로토콜
- **Agent Card** : 에이전트의 역량·접속 방법·인증 요구 정보를 나타내는 문서
- **Task** : 요청 작업과 진행 상태를 추적하는 단위
- **Message** : 요청·상태·응답 등 상호작용 내용을 전달하는 단위
- **Artifact** : Task 결과로 반환되는 파일·텍스트·구조화 자료
</details>

## 2~4교시 25점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **A2A(Agent-to-Agent)** 는 서로 다른 에이전트가 역량을 찾고 작업·상태·결과를 교환하는 상호운용 프로토콜 |
| 목적 | 구현이 다른 에이전트 사이의 작업 협업 지원 |

### Ⅱ. Task 상호작용 흐름

```text
상대 역량 탐색(Agent Card)
            ↓
에이전트 인증·Task 요청
            ↓
Message로 상태 교환
            ↓
Artifact 결과 수신
            ↓
요청 작업에 결과 통합
```

### Ⅲ. 프로토콜 객체

| 객체 | 상호작용에서의 기능 |
|---|---|
| Agent Card | 역량·접속·인증 요구를 알려 요청 에이전트가 대상 선택 |
| Task | 요청 작업의 상태를 추적 |
| Message | 요청·진행·완료 정보를 전달 |
| Artifact | 작업 산출물을 요청 측으로 전달 |

### Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 상대 에이전트나 도구에 과도한 권한이 전달될 수 있음 | 신원 확인과 작업별 최소 권한 적용 |
| 반복 호출·장기 실행으로 작업이 끝나지 않을 수 있음 | 시간·호출 한도, 재시도 기준, 종료 조건 설정 |
| 일부 에이전트의 지연·실패가 전체 작업을 막을 수 있음 | 타임아웃·부분 실패 처리와 대체 경로 정의 |

### Ⅴ. 제언

에이전트 사이 Task 상태·Artifact 스키마·인수 조건을 먼저 합의하고 각 인계 단계에서 검증.
