## Ⅰ. A2A(Agent-to-Agent)의 개요

- 개념 : 복수의 독립적인 **자율 인공지능 에이전트** (Autonomous AI Agent)들이 표준화된 통신 프로토콜과 인터페이스를 통해 자연어 및 구조화된 데이터를 상호 교환하며, 단일 에이전트로는 해결 불가능한 복잡한 목표를 달성하기 위해 자율적으로 협상, 작업 분할, 위임 및 결과를 종합하는 **분산 협업** 아키텍처.
- 배경 및 필요성 : 단일 거대언어모델(LLM)에 모든 도구와 역할을 부여할 경우 컨텍스트 윈도우 과부하, 환각 누적, **단일 실패점** (SPOF)이 발생하므로, 기능별로 전문화된 도메인 에이전트 간의 분업 및 통신 체계가 필수적으로 요구됨.
- 핵심 목적 : 에이전트 시스템의 모듈화 및 확장성 극대화, 복잡한 비즈니스 프로세스의 분산 자율 처리, 이기종 에이전트 간의 **상호운용성** (Interoperability) 확보.

## Ⅱ. A2A(Agent-to-Agent)의 핵심 아키텍처 및 동작 메커니즘

A2A 아키텍처는 서비스 디스커버리, 통신 프로토콜, 작업 중재 및 분산 오케스트레이션 메커니즘을 기반으로 유기적으로 동작함.

```text
[ A2A 자율 협업 및 메시지 교환 아키텍처 ]

+-----------------------------------------------------------------+
| 1. 에이전트 디스커버리 & 레지스트리 (Registry & Discovery)      |
|  - 에이전트 기능 명세서 (Capability Schema), 엔드포인트 등록    |
+--------------------------------┬--------------------------------+
                                 │ 기능 조회 및 라우팅
                                 ▼
+-----------------------------------------------------------------+
| 2. 표준 통신 프로토콜 계층 (Protocol & Context Sharing)         |
|  - A2A 프로토콜, JSON-RPC, FIPA-ACL                             |
|  - 보안 통신 (mTLS, 에이전트 서명, DID 분산신원)                |
+--------------------------------┬--------------------------------+
                                 │ 구조화된 메시지 전송
                                 ▼
+-----------------------------------------------------------------+
| 3. 협업 토폴로지 및 오케스트레이션 (Collaboration Topologies)   |
|                                                                 |
|   [ 마스터-워커 ]               [ 피어투피어 (P2P) ]            |
|   Supervisor Agent              Agent A <=======> Agent B       |
|    ┌─────┴─────┐                   ▲                 ▲          |
|    ▼           ▼                   └───────┬─────────┘          |
| Worker 1    Worker 2                       ▼                    |
| (코딩전문)  (보안전문)                  Agent C (검증)          |
+--------------------------------┬--------------------------------+
                                 │ 작업 실행 및 결과 통합
                                 ▼
+-----------------------------------------------------------------+
| 4. 분산 트랜잭션 및 옵저버빌리티 (Tracing & Guardrails)         |
|  - OpenTelemetry 분산 추적, 교착상태(Deadlock) 방지 서킷브레이커|
+-----------------------------------------------------------------+
```

- **에이전트 디스커버리(Agent Discovery)** : 각 에이전트가 처리 가능한 작업(예: DB 조회, 코드 작성, 수학 연산)의 입출력 스키마를 중앙 레지스트리에 등록하고 동적 바인딩.
- **에이전트 간 통신 프로토콜(A2A Protocol)** : 독립된 에이전트끼리 자신의 기능을 공개하고 작업을 요청·응답하기 위한 표준 통신 규격이며, 에이전트와 도구 연결을 다루는 MCP와 구분됨.
- **마스터-워커 패턴(Supervisor Pattern)** : 상위 계획 수립 에이전트가 복잡한 태스크를 하위 작업으로 쪼개어 전문 워커 에이전트들에게 병렬 분배하고 취합.
- **P2P 자율 협상 패턴** : 에이전트들이 동등한 위치에서 메시지를 주고받으며 견해 차이를 조율(Consensus)하고 교차 검증 수행.

## Ⅲ. A2A(Agent-to-Agent)의 세부 구성 요소 및 비교 분석

| 협업 토폴로지 | 제어 방식 및 구조 | 장점 및 특징 | 단점 및 병목 | 대표 프레임워크 |
| --- | --- | --- | --- | --- |
| **중앙 집중형 (Supervisor)** | 총괄 에이전트가 모든 워커의 상태를 관리하고 태스크 할당 | 흐름 제어가 명확하고 결과 검증이 용이함 | 총괄 에이전트의 병목 현상 및 단일 실패점(SPOF) | LangGraph, AutoGen (GroupChat) |
| **계층형 트리 (Hierarchical)** | 다단계 감독관이 피라미드 형태로 하위 서브에이전트 지휘 | 대규모 엔터프라이즈 조직 구조 모사 가능 | 지연 시간(Latency) 누적 및 계층 간 정보 왜곡 | CrewAI Hierarchical Process |
| **피어투피어 (P2P Mesh)** | 모든 에이전트가 브로커 없이 자유롭게 직접 대화 | 뛰어난 유연성과 자율적 창의성 발현 | 무한 루프, 메시지 폭증, 교착 상태(Deadlock) 위험 | Semantic Kernel, Swarm |
| **게시판형 (Blackboard)** | 공유 메모리 공간에 정보를 게시하고 필요한 에이전트가 소비 | 비동기 작업 처리에 최적화, 결합도 최소화 | 공유 메모리 동기화 및 락(Lock) 경합 발생 | Ray, Redis 기반 분산 에이전트 |

- 엔터프라이즈 환경에서는 제어 가능성과 결정론적 안정성을 확보하기 위해 Supervisor 계층형 토폴로지가 우선 채택됨.

## Ⅳ. A2A(Agent-to-Agent)의 주요 한계점 및 해결 방안

- 에이전트 간 핑퐁 대화로 인한 무한 루프(Infinite Loop) 및 토큰 비용 폭증 :
  - 한계점 : 에이전트 A와 B가 서로의 결과에 만족하지 못하고 질문과 수정을 무한히 반복하여 시스템 멈춤 및 요금 폭탄 발생.
  - 해결 방안 : **최대 대화 턴 수** (Max Turns) 강제 제한, 그래프 기반 상태 머신(State Machine) 종료 조건 명시, **서킷 브레이커** 도입.
- 악의적 에이전트의 허위 정보 주입 및 연쇄 오작동(Cascading Failure) :
  - 한계점 : 단 하나의 에이전트가 탈옥되거나 환각 정보를 출력할 경우 이를 참조한 후속 에이전트들이 연쇄적으로 잘못된 행동 실행.
  - 해결 방안 : 에이전트 간 통신에 **mTLS** 및 전자서명 강제, 에이전트별 독립 샌드박스 격리, 중간 결과물 평가자(Critic Agent) 배치.
- 이기종 프레임워크 간 표준 통신 프로토콜 부재로 인한 사일로화 :
  - 한계점 : LangGraph로 만든 에이전트와 CrewAI로 만든 에이전트가 통신할 수 없는 프레임워크 파편화 발생.
  - 해결 방안 : 에이전트 간 표준 통신 프로토콜(A2A 등) 및 REST/JSON Schema 기반의 프레임워크 중립적 표준 API 도입.

## Ⅴ. A2A(Agent-to-Agent) 적용 및 발전을 위한 기술사적 제언

- 표준 에이전트 통신 프로토콜 채택을 통한 개방형 에이전트 생태계 구축 : 사내 모든 레거시 시스템과 신규 AI 에이전트를 표준 프로토콜 기반 구조로 패키징하여 재사용성 극대화.
- OpenTelemetry 기반 에이전트 분산 트레이싱(Distributed Tracing) 인프라 구축 : 에이전트 간 주고받은 모든 프롬프트, 도구 실행 로그, 사고 과정을 단일 Trace ID로 엮어 시각화 관제 필수화.
- 에이전트 자율 권한에 대한 최소 권한(PoLP) 및 Human-in-the-Loop 통제선 수립 : 파일 삭제, 결제 승인, DB 영구 변경 등 고위험 도구 호출은 반드시 인간 관리자의 인라인 승인을 거치도록 강제.
