## 연관 키워드

- A2A(Agent-to-Agent), Agent Card, 에이전트 디스커버리, 상호운용성(Interoperability)
- 마스터-워커 패턴, P2P 협업, 블랙보드, 서킷 브레이커, 교착 상태, MCP

## Ⅰ. A2A(Agent-to-Agent)의 개요

- 핵심 요약 : 서로 다른 자율 AI 에이전트가 표준 프로토콜로 작업을 위임하고 결과를 주고받는 분산 협업 방식.
- 개념 : 독립된 **자율 AI 에이전트** (Autonomous AI Agent)들이 표준 통신 규격을 통해 작업을 나누고 위임·종합하여, 단일 에이전트로 풀기 어려운 목표를 달성하는 **A2A** (Agent-to-Agent) 협업 구조.
- 배경 및 필요성 : 하나의 거대언어모델에 모든 도구와 역할을 맡기면 컨텍스트 과부하, 환각 누적, 단일 실패점(SPOF, Single Point of Failure)이 생겨 기능별 전문 에이전트의 분업과 통신 체계가 요구됨.
- 주요 목적 : 에이전트 시스템의 모듈화와 확장성 확보, 이기종 프레임워크 간 **상호운용성** (Interoperability) 확보.
- 도입 경과 : Google이 2025년 4월 Cloud Next에서 A2A를 공개한 뒤, 2025년 6월 Linux Foundation에 기증되어 Agent2Agent 프로젝트로 출범함 (Google 및 Linux Foundation 발표 기준, 100여 개 기술 기업이 지지).

## Ⅱ. A2A(Agent-to-Agent)의 특징 및 장점

- 핵심 요약 : 공개 명세 기반 탐색, 표준 작업 요청, 작업 상태 추적이 결합해 이기종 에이전트를 안전하게 묶는 구조.

1. **Agent Card** (에이전트의 기능과 엔드포인트를 기술한 공개 명세) : 에이전트가 자신의 능력을 공개 → 요청 측이 적합한 에이전트를 자동으로 찾아 연결.
2. 표준 작업 요청 : JSON-RPC 기반으로 작업을 요청하고 응답 → 프레임워크가 달라도 같은 규격으로 협업 가능.
3. 작업 수명주기 관리 : 작업의 진행, 완료, 실패 상태를 추적 → 장시간 작업의 중간 결과와 실패 지점 확인 가능.
4. 인증과 신뢰 경계 : 에이전트 간 통신에 인증 체계를 두어 신원이 확인된 상대와만 작업 교환 → 오작동과 탈취의 전파 범위 축소.

## Ⅲ. A2A(Agent-to-Agent)의 구조 (흐름)

- 핵심 요약 : 에이전트 등록과 탐색 후 작업 위임, 결과 통합으로 이어지는 요청 중심의 흐름.

```text
[ A2A 작업 위임 흐름 ]

에이전트 명세(Agent Card) 등록
          ↓
요청 측이 기능 기준으로 탐색
          ↓
표준 규격으로 작업 요청
          ↓
대상 에이전트가 작업 수행 (상태 보고)
          ↓
결과 취합 후 최종 응답
```

```text
[ 협업 토폴로지 두 방향 ]

마스터-워커 (Supervisor)
     총괄 에이전트
     ↓           ↓
  워커 A      워커 B

P2P 협업 (Peer-to-Peer)
  에이전트 A ⇄ 에이전트 B
       ⇅           ⇅
  에이전트 C ⇄ 에이전트 D
```

- **MCP** (Model Context Protocol, 에이전트와 도구·데이터 원천을 잇는 프로토콜)는 에이전트와 도구의 연결을 다루고, A2A는 에이전트와 에이전트의 연결을 다루므로 역할이 구분됨.

## Ⅳ. A2A(Agent-to-Agent)의 비교

- 핵심 요약 : 제어 가능성은 중앙 집중형이, 유연성은 P2P형이 우세하며 엔터프라이즈에서는 통제 가능한 구조가 우선됨.

| 협업 토폴로지 | 제어 방식 | 장점 | 단점·병목 | 대표 구현 예 |
| --- | --- | --- | --- | --- |
| 중앙 집중형 (Supervisor) | 총괄 에이전트가 워커에 작업 할당 | 흐름 제어 명확, 결과 검증 용이 | 총괄 에이전트 병목과 단일 실패점 | LangGraph, AutoGen |
| 계층형 (Hierarchical) | 다단계 감독자가 하위 에이전트 지휘 | 조직 구조 모사, 대규모 업무 분할 | 계층 지연 누적, 정보 왜곡 | CrewAI 계층 프로세스 |
| P2P 메시 | 브로커 없이 직접 대화 | 유연성, 자율적 협상 | 무한 루프, 메시지 폭증, 교착 상태 | Swarm 계열 실험 구현 |
| 블랙보드 (Blackboard) | 공유 저장소에 게시하고 소비 | 비동기 처리, 결합도 최소화 | 공유 상태 동기화와 잠금 경합 | Redis 기반 구현 |

- 엔터프라이즈에서는 결정론적 안정성을 위해 Supervisor 계층형 구조를 우선 채택하는 경향임.

| 비교 축 | MCP | A2A |
| --- | --- | --- |
| 연결 대상 | 에이전트 ↔ 도구·데이터 | 에이전트 ↔ 에이전트 |
| 핵심 질문 | 무엇을 쓸 수 있는가 | 누구에게 맡길 수 있는가 |

## Ⅴ. A2A(Agent-to-Agent)의 한계와 방안

- 핵심 요약 : 무한 루프, 연쇄 오작동, 프레임워크 사일로를 턴 제한, 신원 검증, 표준 프로토콜로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 핑퐁 대화로 인한 무한 루프와 비용 폭증 | 에이전트끼리 수정 요청을 반복해 시스템 정지와 토큰 비용 증가 | 최대 대화 턴 수 제한, 상태 머신의 종료 조건 명시, **서킷 브레이커** (Circuit Breaker, 반복 실패 시 호출을 차단하는 장치) 도입 | 턴 수, 작업당 토큰 사용량 |
| 악성 또는 환각 정보의 연쇄 전파 | 하나의 에이전트가 오류를 내면 후속 에이전트가 연쇄 오작동 | **mTLS** (mutual Transport Layer Security, 상호 인증 전송 계층 보안)와 전자서명 강제, 에이전트별 샌드박스 격리, 평가 에이전트 배치 | 비정상 메시지 차단 건수 |
| 프레임워크 간 표준 부재에 따른 사일로 | 서로 다른 프레임워크의 에이전트가 통신 불가 | 개방형 표준 프로토콜 채택, JSON Schema 기반 중립 인터페이스 도입 | 연동 가능한 에이전트 비율 |

## Ⅵ. A2A(Agent-to-Agent)에 대한 기술사적 제언

- 핵심 요약 : 표준 명세 기반 카탈로그, 추적 인프라, 최소 권한 설계를 도입의 전제로 제시.

1. 표준 프로토콜 기반 에이전트 카탈로그 : 사내 레거시 시스템과 신규 에이전트를 공개 명세로 감싸 등록하면, 부서 간 재사용과 연계 비용을 함께 낮출 수 있음.
2. 분산 추적 인프라 선행 구축 : 에이전트 간 주고받은 프롬프트, 도구 호출, 결과를 하나의 추적 ID로 묶는 OpenTelemetry 기반 관측 체계를 도입 초기부터 마련함.
3. 최소 권한과 사람의 승인 지점 : 파일 삭제, 결제 승인, 데이터베이스 변경 같은 고위험 작업은 PoLP (Principle of Least Privilege, 최소 권한 원칙)에 따라 권한을 좁히고, 사람의 승인을 거치도록 설계함.

## Ⅶ. 결론

- 핵심 요약 : A2A는 에이전트를 연결하는 표준 협업 계층이며, 자율성은 통제 가능한 프로토콜 위에서만 확장됨.
- 시사점 : 에이전트 수가 늘수록 기능 연결보다 신원 확인, 추적, 종료 조건의 설계가 운영 신뢰를 좌우함.
