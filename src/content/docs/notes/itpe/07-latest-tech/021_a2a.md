 ┣━ Ⅰ 개요 ───── 단일 에이전트 연산 한계 → 자율 에이전트 간 협력·협상·위임을 통한 복합 목표 달성

## 핵심 용어
- AP2(Agent Payment Protocol): 사람의 개입 없이 AI 에이전트가 부여받은 예산 범위 내에서 다른 에이전트 서비스 비용을 암호학적으로 결제하는 자율 결제 규약
- Confused Deputy(혼동된 대리인): 악의적인 에이전트가 높은 권한을 가진 정상 에이전트에 속임수 요청을 보내 권한을 남용하도록 만드는 보안 취약점
- 에이전트 레지스트리(Agent Registry): 네트워크 내 활동 중인 에이전트의 정체성, 지원 기능, 가격 정책, 신뢰도를 등록하고 검색하는 디스커버리 서비스

## 핵심 통찰
- A2A는 기존 마이크로서비스(MSA)의 API 호출과 본질적으로 다름 → API는 고정된 스키마의 결정론적 호출이지만, A2A는 자연어 또는 유연한 프로토콜 기반의 "목표 지향적 협상"
- 에이전트 수가 증가할수록 통신 복잡도는 $O(N^2)$으로 폭증하므로, 중앙 브로커 기반 라우팅 또는 계층적(Hierarchical) 트리 구조 도입이 필수
- 에이전트가 다른 에이전트에 자원을 위임할 때 권한 범위를 좁히는 최소 권한 원칙(PoLP)과 타임아웃 세션 관리가 핵심 통제 요소

## 이웃 토픽과 구분
- A2A vs 마이크로서비스 REST API: REST는 고정된 엔드포인트와 정적 데이터 교환 / A2A는 에이전트 간 실시간 상태 인식과 역량 타진을 통한 동적 작업 계약(Contract) 체결

## 문제·원인·대책
- 적용 상황: 공급망 최적화 멀티 에이전트 시스템에서 에이전트 간 무한 협상 루프 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 견적 에이전트와 구매 에이전트의 무한 반복 대기 | 협상 종료 조건 및 최대 홉(Max Hop) 카운트 부재 | TTL(Time-to-Live) 기반 홉 제한 및 에이전트 간 타임아웃 강제 | 무한 루프 차단 및 자원 고갈 방지 |
| 하위 에이전트를 통한 사내 기밀 유출 | A2A 통신 구간의 상호 인증 부재 및 권한 전파 취약 | 에이전트 전용 mTLS 및 JWT 기반 작업별 스코프 서명(OAuth for Agents) | 비인가 에이전트 차단 및 위임 권한 한정 |
| 부분 실패 시 전체 워크플로우 롤백 불가 | 분산 비결정론적 작업의 트랜잭션 ACID 미지원 | 사가 패턴(Saga Pattern) 기반 보상 트랜잭션(Compensating Action) 설계 | 분산 에이전트 간 최종 일관성(Eventual Consistency) 확보 |

## 내 의견
- [에이전트 권한 위임 추적을 위한 분산 감사 원장 도입] 에이전트 간 자율 연쇄 호출(Agent Chain)이 발생하면 장애나 보안 사고 발생 시 어떤 에이전트가 잘못된 결정을 내렸는지 추적 불가능 → 나라면: OpenTelemetry 기반으로 A2A 호출 트레이스(Span)를 표준화하고, W3C DID(탈중앙 신원증명)를 에이전트에 부여하여 호출 체인 전 구간의 암호학적 비부인 감사 로그 유지
