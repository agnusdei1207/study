## 30초 인출

- 본질: **QR코드 (Quick Response Code)** 는 흑백 격자 모듈(Module)의 2차원 매트릭스 배열로 숫자, 문자, 바이너리 데이터를 고밀도 인코딩하고 세 모서리의 위치 검출 패턴을 통해 360도 전방향 초고속 광학 인식이 가능한 국제 표준(ISO/IEC 18004) 심볼로지
- 메커니즘: 파인더 패턴(1:1:3:1:1) 검출로 기울기 보정 → 타이밍/얼라인먼트 패턴으로 모듈 좌표 격자화 → 마스킹 해제 및 리드-솔로몬(Reed-Solomon) 부호 기반 오류 정정 및 원본 데이터 복원
- 통찰: 물리적 스티커 바꿔치기나 악성 피싱 URL로 유도하는 큐싱(Quishing) 보안 위협이 급증하므로 도메인 화이트리스트 사전 검증 및 암호학적 전자서명을 결합한 시큐어 QR 아키텍처 구축 필수

<details><summary>핵심 용어</summary>

- **QR코드 (Quick Response Code)** : 덴소웨이브가 개발한 2차원 매트릭스 심볼로지로 대용량 데이터 저장과 고속 판독이 특징인 국제 표준 코드.
- **위치 검출 패턴 (Finder Pattern)** : QR코드의 세 모서리에 배치된 이중 사각형 구조로 흑·백·흑·백·흑의 폭 비율이 1:1:3:1:1을 이루어 회전 각도를 감지하는 패턴.
- **리드-솔로몬 부호 (Reed-Solomon Code)** : 코드 일부가 오염되거나 훼손되어도 원본 데이터를 완벽 복원할 수 있도록 지원하는 비트 단위 에러 정정 수학 알고리즘.
- **큐싱 (Quishing, QR + Phishing)** : 정상 QR코드 위에 악성 URL이 담긴 스티커를 덧붙여 개인정보나 금융 정보를 탈취하는 신종 피싱 공격.
- **마스킹 (Data Masking)** : 흑백 모듈이 특정 영역에 편중되어 인식 오류가 발생하는 것을 방지하기 위해 8가지 패턴의 XOR 연산을 적용하는 분산 기술.

</details>

## 2~4교시 25점 답안

## Ⅰ. QR코드의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **QR코드** 는 가로와 세로 2차원 방향의 정방형 흑백 격자 모듈(Module)을 매트릭스 형태로 배열하여 숫자, 영문, 한글, 한자 및 바이너리 데이터를 대용량 저장하는 광학 인식 심볼로지 |
| 목적 | 1차원 바코드의 용량 한계 극복, 360도 전방향 초고속 인식 및 심볼 훼손 시 복원력 확보를 통한 오프라인-온라인(O2O) 상호작용 매개 |

## Ⅱ. QR코드의 심볼 구조 및 오류 정정 특징

| 구성 영역 | 기하학적 형태 및 배치 | 공학적 기능 및 특징 |
|---|---|---|
| **위치 검출 패턴 (Finder)** | 좌상, 우상, 좌하 3개 모서리 배치 사각형 | 1:1:3:1:1의 흑백 폭 비율로 360도 어느 방향에서 스캔해도 즉각적인 회전각 및 크기 검출 |
| **정렬 패턴 (Alignment)** | 버전 2 이상에서 내부 분산 배치 | 카메라 왜곡(렌즈 굴곡)이나 인쇄면 곡면에 따른 모듈 위치 편차 자동 보정 |
| **타이밍 패턴 (Timing)** | 파인더 패턴 사이를 잇는 흑백 교차선 | 심볼 내 개별 모듈의 물리적 좌표 격자 기준선(Grid Coordinate) 제공 |
| **포맷 및 버전 정보** | 파인더 패턴 주변 모듈 배치 | 사용된 오류 정정 레벨(L/M/Q/H) 및 적용된 마스크 패턴 번호(0~7) 기록 |
| **오류 정정 (Reed-Solomon)** | 4단계(L:7%, M:15%, Q:25%, H:30%) 복원율 | 코드 일부가 찢기거나 오염되어도 다항식 연산으로 원본 데이터 100% 무손실 복구 |

## Ⅲ. QR코드 인식·디코딩 프로세스 및 영역별 구성

```text
┌────────────────────────────────────────────────────────────────────────┐
│             QR코드 (ISO/IEC 18004) 심볼 구조 및 디코딩 파이프라인      │
└────────────────────────────────────────────────────────────────────────┘
 [ 광학 카메라 영상 취득 (Camera Frame Capture) ]
                       │
                       ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 1단계: 파인더 패턴 탐색 및 원근 왜곡 보정 (Finder Detection)          │
 │  - 가로/세로 주사선에서 1:1:3:1:1 흑백 비율 매칭 ──> 세 모서리 특정   │
 │  - 아핀 변환(Affine Transform)을 통한 2차원 정방형 평면 투영 복원    │
 └─────────────────────┬────────────────────────────────────────────────┘
                       │
                       ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 2단계: 격자 샘플링 및 마스크 해제 (Grid Sampling & Unmasking)        │
 │  - 타이밍 패턴 기반 모듈 그리드 분할 (0: White, 1: Black 이진화)     │
 │  - 포맷 정보 읽기 ──> 적용된 8개 마스크 중 해당 패턴 XOR 역연산      │
 └─────────────────────┬────────────────────────────────────────────────┘
                       │
                       ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 3단계: 리드-솔로몬 에러 정정 (Reed-Solomon Error Correction)         │
 │  - 갈루아 필드(Galois Field GF(2^8)) 기반 오류 위치 및 크기 계산     │
 │  - 손상된 코드워드 복구 (정정 가능 용량 범위 내 무손실 복원)         │
 └─────────────────────┬────────────────────────────────────────────────┘
                       │
                       ▼
 [ 4단계: 모드별 디코딩 ──> 최종 데이터 스트링 복원 (URL, 텍스트, 결제 토큰) ]
```

| 디코딩 처리 단계 | 알고리즘 및 세부 기술 | 산출 데이터 |
|---|---|---|
| **이진화 (Binarization)** | 국소 적응형 임계화(Adaptive Thresholding)로 조명 반사 제거 | 흑백 1비트 비트맵 |
| **지오메트리 보정** | 3개 파인더 중심점을 잇는 삼각형 기하 계산으로 회전각 산출 | 정규화된 매트릭스 격자 |
| **신드롬 계산 (Syndrome)** | 수신된 다항식을 원시 다항식으로 나누어 오류 유무 판정 | 오류 증후군 벡터 |
| **데이터 스트림 파싱** | 숫자(10비트/3자), 영숫자(11비트/2자), 8비트 바이트 디코딩 | 원본 텍스트/바이너리 |

## Ⅳ. 1차원 바코드 vs 2차원 바코드 비교

| 비교 항목 | 1차원 바코드 (EAN-13 / Code 128) | PDF417 (스택형 2D) | QR코드 (본 토픽 - 매트릭스 2D) |
|---|---|---|---|
| **데이터 표현 축** | 수평 1차원 (선과 공백의 폭) | 수평 바코드를 수직 다단 적재 | 수평/수직 2차원 격자 매트릭스 |
| **최대 저장 용량** | 숫자 20~30자 내외 | 텍스트 약 1,800자 | 숫자 최대 7,089자, 영숫자 4,296자 |
| **인식 방향성** | 단방향 또는 레이저 라인 정렬 필수 | 수평 주사선 정렬 필요 | 360도 전방향 (Omni-directional) |
| **오류 정정 능력** | 체크디지트 검증 (복원 불가) | 리드-솔로몬 (최대 50% 복원) | 리드-솔로몬 (최대 30% 복원) |
| **심볼 크기 대비 밀도** | 데이터 증가 시 가로 길이 무한 확장 | 비교적 큰 면적 요구 | 초소형 면적에 고밀도 집약 가능 |
| **주요 활용 분야** | 유통 상품 계산(POS), 물류 택배 | 신분증, 항공권 탑승권 | 모바일 결제, 웹 접속, O2O 인증 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 시각적으로 정상적인 QR코드와 악성 피싱 URL이 담긴 QR코드를 육안으로 전혀 구별할 수 없어 큐싱(Quishing)에 무방비 노출 | 스캔 즉시 웹 브라우저를 자동 실행하지 않고 목적지 도메인의 신뢰 등급을 사전 검사하여 사용자에게 경고하는 보안 프리뷰 게이트웨이 강제 |
| 결제용 정적 QR(Static QR)을 인쇄물로 부착할 경우 스티커 덧붙이기 조작을 통한 결제 대금 가로채기 위협 | 일회용 결제 토큰과 유효시간(TOTP, 30~60초)이 적용된 동적 QR(Dynamic QR) 화면 표시 방식으로 전면 전환 |
| 야외 금속 명판이나 곡면 부품 인쇄 시 빛 반사 및 오염으로 인한 광학 카메라 스캔 실패율 증가 | 오류 정정 등급을 H레벨(30%)로 상향 인코딩하고 무반사 매트 코팅 및 DPM(Direct Part Marking) 전용 리더기 도입 |

## Ⅵ. 제언

안전한 디지털 금융 결제 및 공공 행정 처리를 위해 공개키 기반구조(PKI) 전자서명을 QR 내부에 내장하는 위변조 방지 시큐어 QR코드(Signed Secure QR) 아키텍처 구축 권고.

```text
[ QR코드 생성 서버 ]
          │
          ▼
┌────────────────────────────────────────────────────────┐
│ 전자서명 생성 (ECDSA / Ed25519)                        │
│  - Payload: [ 가맹점 ID + 결제 금액 + 타임스탬프 ]     │
│  - Signature: 서버 개인키(Private Key)로 서명 생성     │
│  - QR 인코딩: [ Payload + Signature ] 2차원 심볼화     │
└──────────────────────────┬─────────────────────────────┘
                           │ 동적 QR 화면 렌더링
                           ▼
[ 사용자 스마트폰 보안 카메라 스캔 ]
          │
          ▼
┌────────────────────────────────────────────────────────┐
│ 온디바이스 보안 검증 게이트 (Secure Scanner App)       │
│  ├── 1. 도메인 평판 조회: KISA/구글 세이프브라우징 대조 │
│  └── 2. 공개키 전자서명 검증: 가맹점 서명 위변조 확인  │
│            ├── 검증 성공 ──> [ 결제 승인 완료 ]        │
│            └── 위변조 감지 ──> [ 즉시 차단 및 큐싱 신고]│
└────────────────────────────────────────────────────────┘
```

| 구분 | 일반 정적 QR코드 | 제언: PKI 전자서명 기반 시큐어 QR |
|---|---|---|
| **위조 방어** | 스티커 덧붙이기에 완전 무력화 | 전자서명 불일치로 스캐너에서 즉각 거부 |
| **피싱(큐싱) 대응** | 악성 웹사이트 자동 리다이렉트 | 안전 도메인 화이트리스트 사전 검증 |
| **결제 무결성** | 송금 대상 계좌 변조 위험 | 금액 및 수취인 암호화 서명으로 변조 불가 |
| **부인 방지** | 거래 당사자 확인 불가 | 디지털 서명 증적으로 법적 부인 방지 달성 |
