## Ⅰ. QR코드(QR Code)의 개요

- 개념 : 가로와 세로 2차원 방향의 정방형 흑백 격자 모듈(Module)을 매트릭스 형태로 배열하여 숫자, 영문, 한글, 한자 및 바이너리 데이터를 대용량 저장하는 광학 인식 심볼로지
- 배경 및 필요성 : 물리적 스티커 바꿔치기나 악성 피싱 URL로 유도하는 큐싱(Quishing) 보안 위협이 급증하므로 도메인 화이트리스트 사전 검증 및 암호학적 전자서명을 결합한 시큐어 QR 아키텍처 구축 필수
- 핵심 목적 : 1차원 바코드의 용량 한계 극복, 360도 전방향 초고속 인식 및 심볼 훼손 시 복원력 확보를 통한 오프라인-온라인(O2O) 상호작용 매개

## Ⅱ. QR코드(QR Code)의 핵심 아키텍처 및 동작 메커니즘

QR코드는 파인더 패턴(1:1:3:1:1) 검출로 기울기 보정 → 타이밍/얼라인먼트 패턴으로 모듈 좌표 격자화 → 마스킹 해제 및 리드-솔로몬(Reed-Solomon) 부호 기반 오류 정정 및 원본 데이터 복원 메커니즘을 기반으로 동작하며, 세부적인 아키텍처와 핵심 컴포넌트 간 상호작용 프로세스는 다음과 같음.

```text
┌────────────────────────────────────────────────────────────────────────┐
│             QR코드 (ISO/IEC 18004) 심볼 구조 및 디코딩 파이프라인      │
└────────────────────────────────────────────────────────────────────────┘
 [ 광학 카메라 영상 취득 (Camera Frame Capture) ]
                       │
                       ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 1단계: 파인더 패턴 탐색 및 원근 왜곡 보정 (Finder Detection)          │
 │  - 가로/세로 주사선에서 1:1:3:1:1 흑백 비율 매칭 ──> 세 모서리 특정   │
 │  - 아핀 변환(Affine Transform)을 통한 2차원 정방형 평면 투영 복원    │
 └─────────────────────┬────────────────────────────────────────────────┘
                       │
                       ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 2단계: 격자 샘플링 및 마스크 해제 (Grid Sampling & Unmasking)        │
 │  - 타이밍 패턴 기반 모듈 그리드 분할 (0: White, 1: Black 이진화)     │
 │  - 포맷 정보 읽기 ──> 적용된 8개 마스크 중 해당 패턴 XOR 역연산      │
 └─────────────────────┬────────────────────────────────────────────────┘
                       │
                       ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 3단계: 리드-솔로몬 에러 정정 (Reed-Solomon Error Correction)         │
 │  - 갈루아 필드(Galois Field GF(2^8)) 기반 오류 위치 및 크기 계산     │
 │  - 손상된 코드워드 복구 (정정 가능 용량 범위 내 무손실 복원)         │
 └─────────────────────┬────────────────────────────────────────────────┘
                       │
                       ▼
 [ 4단계: 모드별 디코딩 ──> 최종 데이터 스트링 복원 (URL, 텍스트, 결제 토큰) ]
```

- **위치 검출 패턴 (Finder)** : 좌상, 우상, 좌하 3개 모서리 배치 사각형 - 1:1:3:1:1의 흑백 폭 비율로 360도 어느 방향에서 스캔해도 즉각적인 회전각 및 크기 검출
- **정렬 패턴 (Alignment)** : 버전 2 이상에서 내부 분산 배치 - 카메라 왜곡(렌즈 굴곡)이나 인쇄면 곡면에 따른 모듈 위치 편차 자동 보정
- **타이밍 패턴 (Timing)** : 파인더 패턴 사이를 잇는 흑백 교차선 - 심볼 내 개별 모듈의 물리적 좌표 격자 기준선(Grid Coordinate) 제공
- **포맷 및 버전 정보** : 파인더 패턴 주변 모듈 배치 - 사용된 오류 정정 레벨(L/M/Q/H) 및 적용된 마스크 패턴 번호(0~7) 기록

## Ⅲ. QR코드(QR Code)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 1차원 바코드 (EAN-13 / Code 128) | PDF417 (스택형 2D) | QR코드 (본 토픽 - 매트릭스 2D) |
|---|---|---|---|
| **데이터 표현 축** | 수평 1차원 (선과 공백의 폭) | 수평 바코드를 수직 다단 적재 | 수평/수직 2차원 격자 매트릭스 |
| **최대 저장 용량** | 숫자 20~30자 내외 | 텍스트 약 1,800자 | 숫자 최대 7,089자, 영숫자 4,296자 |
| **인식 방향성** | 단방향 또는 레이저 라인 정렬 필수 | 수평 주사선 정렬 필요 | 360도 전방향 (Omni-directional) |
| **오류 정정 능력** | 체크디지트 검증 (복원 불가) | 리드-솔로몬 (행 단위 오류 정정) | 리드-솔로몬 (최대 30% 복원) |
| **심볼 크기 대비 밀도** | 데이터 증가 시 가로 길이 무한 확장 | 비교적 큰 면적 요구 | 초소형 면적에 고밀도 집약 가능 |

- QR코드는 상기 비교 지표를 바탕으로 비즈니스 요구사항과 운영 인프라 환경을 고려한 최적의 아키텍처를 선정하고, 확장성과 안정성을 균형 있게 확보해야 함.

## Ⅳ. QR코드(QR Code)의 주요 한계점 및 해결 방안

- 정상 QR코드와 악성 피싱 URL 식별 불가에 따른 큐싱(Quishing) 노출 :
  - 한계점 : 시각적으로 정상적인 QR코드와 악성 피싱 URL이 담긴 QR코드를 육안으로 전혀 구별할 수 없어 큐싱(Quishing)에 무방비 노출.
  - 해결 방안 : 스캔 즉시 웹 브라우저를 자동 실행하지 않고 목적지 도메인의 신뢰 등급을 사전 검사하여 사용자에게 경고하는 보안 프리뷰 게이트웨이 강제.
- 정적 QR 인쇄물 스티커 조작을 통한 결제 대금 가로채기 위협 :
  - 한계점 : 결제용 정적 QR(Static QR)을 인쇄물로 부착할 경우 스티커 덧붙이기 조작을 통한 결제 대금 가로채기 위협.
  - 해결 방안 : 일회용 결제 토큰과 유효시간(TOTP, 30~60초)이 적용된 동적 QR(Dynamic QR) 화면 표시 방식으로 전면 전환.
- 야외 금속 명판이나 곡면 인쇄 시 빛 반사로 인한 광학 스캔 실패율 증가 :
  - 한계점 : 야외 금속 명판이나 곡면 부품 인쇄 시 빛 반사 및 오염으로 인한 광학 카메라 스캔 실패율 증가.
  - 해결 방안 : 오류 정정 등급을 H레벨(30%)로 상향 인코딩하고 무반사 매트 코팅 및 DPM(Direct Part Marking) 전용 리더기 도입.

## Ⅴ. QR코드(QR Code) 적용 및 발전을 위한 기술사적 제언

- 위조 방어 중심 엔터프라이즈 고도화 : 스티커 덧붙이기에 완전 무력화의 한계를 탈피하고, 전자서명 불일치로 스캐너에서 즉각 거부를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- 피싱(큐싱) 대응 중심 엔터프라이즈 고도화 : 악성 웹사이트 자동 리다이렉트의 한계를 탈피하고, 안전 도메인 화이트리스트 사전 검증을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- 결제 무결성 중심 엔터프라이즈 고도화 : 송금 대상 계좌 변조 위험의 한계를 탈피하고, 금액 및 수취인 암호화 서명으로 변조 불가를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
