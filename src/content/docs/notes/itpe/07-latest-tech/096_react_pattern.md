## 연관 키워드

- ReAct, Thought, Action, Observation, 추론, 도구 호출, CoT, 최대 반복 횟수, 샌드박스, HITL, RBAC, 환각

## Ⅰ. ReAct 패턴의 개요

- 핵심 요약 : LLM이 추론과 도구 호출을 번갈아 수행하며 관측 결과로 답을 보강하는 에이전트 상호작용 패턴.
- 개념 : LLM(Large Language Model)이 **추론**(Reasoning)과 **도구 호출**(Acting)을 교대로 수행하는 에이전트 패턴 **ReAct**(Reasoning and Acting).
- 배경 및 필요성 : 모델은 학습 시점 이후의 정보를 알지 못하고, 자율 반복 호출은 토큰 비용을 키우며, 권한 밖의 민감 API를 실행할 위험이 있다. 따라서 반복 횟수 상한, **샌드박스**(Sandbox) 격리, HITL(Human-in-the-Loop) 승인 절차가 함께 필요하다.
- 주요 목적 : 정적 파라미터 지식의 한계를 넘어 최신 외부 정보를 얻고, 외부 시스템을 단계적으로 다루는 능력 확보.

## Ⅱ. ReAct 패턴의 특징 및 장점

- 핵심 요약 : 생각, 행동, 관측의 순환이 다음 행동을 정하고 결과로 다시 교정하는 구조가 근거 기반 답변으로 이어짐.

1. **Thought**(사고·추론) : 현재 상황 진단과 목표 분해 → 복합 질의를 하위 작업으로 나눠 단계별 계획을 세우고 오류 시 궤도 수정.
2. **Action**(행동·호출) : 도구를 고르고 인자를 JSON으로 구성해 호출 → 검색 엔진, SQL 데이터베이스, ERP(Enterprise Resource Planning), 계산기 등 이종 시스템과 실시간 연결.
3. **Observation**(관측) : 도구 실행 결과를 컨텍스트에 편입 → 실제 데이터에 근거한 답변으로 모델 고유의 환각 억제.

```text
[ 사용자 복합 질의 ]
          ↓
[ Thought: 상태 분석과 다음 목표 ]
          ↓
[ Action: 도구 호출 명세 작성 ]
          ↓
[ 외부 도구 실행 (샌드박스) ]
          ↓
[ Observation: 실행 결과 편입 ]
          ↓
      목표 달성 여부 판단
     ↓ 미달성             ↓ 달성
 Thought로 순환    최종 응답 (Final Answer)
```

```text
Thought: 환율 정보 필요, 환율 API 조회
Action: Currency(from="USD", to="KRW")
Observation: 환산 결과 값 수신
```

## Ⅲ. ReAct 패턴의 구조 (흐름)

- 핵심 요약 : 추론 단계와 도구 실행 단계가 관측 결과를 매개로 반복되며, 목표 달성 시점에 최종 응답으로 종료되는 루프 구조.
- 구성요소 : 에이전트 코어(LLM), 도구 목록(검색, DB, ERP, 계산기 등), 실행 환경(샌드박스), 종료 조건 판정기.
- 처리 순서 : 추론 → 도구 선택·호출 → 관측 편입 → 종료 여부 판정. 종료 조건이 없으면 같은 루프가 무한히 돌 수 있어 상한 설정이 필수.

## Ⅳ. ReAct와 대안 패턴의 비교

- 핵심 요약 : 추론 없이 도구만 쓰거나 내부 지식만으로 추론하는 방식과 달리, 추론이 행동을 정하고 관측이 추론을 바로잡는 점이 ReAct의 차별점.

비교 대상은 표준 프롬프팅, 추론 과정만 쓰는 CoT(Chain-of-Thought), 추론 없이 도구만 호출하는 Act-only 방식이다.

| 비교 축 | 표준 프롬프팅 | CoT | Act-only | ReAct |
| --- | --- | --- | --- | --- |
| 내부 추론 | 없음 | 있음 (다단계 추론) | 없음 | 있음 (행동 전후 추론) |
| 외부 도구 호출 | 없음 | 없음 (내부 지식 의존) | 있음 (고정 파이프라인) | 있음 (관측 기반 호출) |
| 최신 정보 반영 | 불가능 | 불가능 | 가능하나 흐름이 정적 | 가능하며 관측에 따라 적응 |
| 사실 근거 보강 | 약함 | 약함 | 중간 | 관측 결과로 강화 |

## Ⅴ. ReAct 패턴의 한계와 방안

- 핵심 요약 : 무한 반복, 위험 호출, 관측 비대화가 주요 한계이며 상한 설정, 승인 절차, 요약 배치로 제어.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 종료 조건 없는 무한 반복 | 추론이 끝나지 않고 도구를 계속 호출해 토큰 비용과 지연이 폭증 | 최대 반복 횟수(Max Hops) 상한과 동일 호출 반복 감지 시 폴백 전환 | 평균 반복 횟수, 호출당 토큰 비용 |
| 프롬프트 주입에 의한 위험 호출 | 오염된 입력이나 탈옥 공격으로 삭제 같은 민감 API가 실행될 수 있음 | 읽기 전용 샌드박스 격리, 쓰기·삭제 호출 전 HITL 승인 | 승인 거절 건수, 위험 호출 시도 건수 |
| 관측 결과의 컨텍스트 초과 | 도구 응답이 길면 LLM의 컨텍스트 창 한도를 넘음 | 응답 요약기 배치와 핵심 필드 추출 스키마 강제 | 응답 평균 길이, 잘림 발생 건수 |

## Ⅵ. ReAct 패턴에 대한 기술사적 제언

- 핵심 요약 : 도구 실행을 최소 권한으로 통제하고 민감 작업에는 승인을 거치는 실행 통제 체계의 상시 운영.

에이전트가 쓸 수 있는 도구는 역할 기반 접근 제어(RBAC, Role-Based Access Control)에 맞춘 화이트리스트로 관리하고, 쓰기 작업은 관리자 승인을 거치게 하는 것이 바람직하다. 여기에 반복 횟수와 예산의 상한을 함께 걸어 두면 자율성과 운영 통제를 동시에 확보할 수 있다.

## Ⅶ. 결론

- 핵심 요약 : ReAct는 추론과 도구 호출을 교대로 수행해 정적 지식의 한계를 넘는 에이전트 패턴임.
- 자율성의 이득은 실행 권한과 종료 조건을 어떻게 설계하느냐에 따라 달라지므로, 통제 장치를 처음부터 함께 설계해야 한다.
