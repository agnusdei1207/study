## 30초 인출

- 본질: **ReAct (Reasoning and Acting)** 는 대형 언어모델(LLM)이 문제 해결을 위해 내재적 추론(Thought)과 외재적 도구 실행(Action), 환경 피드백 관측(Observation)을 번갈아 수행하는 자율 에이전트 오케스트레이션 패턴
- 메커니즘: 질의 유입 시 모델이 중간 추론 경로를 생성(Thought)하고 적합한 외부 API/도구를 호출(Action)한 뒤 반환된 실행 결과(Observation)를 프롬프트에 누적하여 다음 판단 루프를 반복
- 통찰: 무한 루프 반복 호출로 인한 토큰 비용 폭증과 권한을 초과하는 민감 API 무단 실행 위험이 상존하므로 최대 홉 수(Max Hops) 제한과 샌드박스 격리 및 인간 개입 승인(HITL) 게이트웨이 구축 필수

<details><summary>핵심 용어</summary>

- **ReAct (Reasoning + Acting)** : 언어모델의 다단계 논리적 사고와 외부 환경 상호작용 도구 호출을 결합한 에이전트 행동 프레임워크.
- **Thought (추론)** : 현재 달성 상태를 평가하고 다음 행동 방향과 세부 전략을 수립하는 모델의 내부 독백(Internal Reasoning).
- **Action (행동)** : 계산기, 검색 엔진, 데이터베이스 등 외부 도구 API에 전달할 함수명과 인자(Arguments)를 명시하는 호출 행위.
- **Observation (관측)** : 외부 도구가 Action을 실행한 후 에이전트 컨텍스트 윈도우로 반환하는 실행 결과 데이터.
- **환각 전파 차단 (Grounded Reasoning)** : 관측된 외부 사실을 추론의 근거로 실시간 반영하여 모델 내부 기억의 거짓 생성(Hallucination)을 억제하는 원리.

</details>

## 2~4교시 25점 답안

## Ⅰ. ReAct 패턴의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **ReAct** 는 LLM이 복잡한 질의를 해결하기 위해 언어적 추론(Reasoning) 생성과 도구 호출(Acting)을 동적으로 교차 수행하는 에이전트 상호작용 패턴 |
| 목적 | 폐쇄된 정적 파라미터 지식의 한계를 극복하고 최신 외부 정보 획득 및 능동적 시스템 제어 능력 확보 |

## Ⅱ. ReAct 패턴의 3대 핵심 요소 및 특징

| 핵심 구성요소 | 역할 및 동작 메커니즘 | 기술적 특징 및 효과 |
|---|---|---|
| **Thought (사고·추론)** | 현재 상황 진단, 목표 분해(Decomposition), 다음 행동 계획 수립 | 복잡한 다단계 문제를 하위 태스크로 쪼개고 추론 오류 시 자체 궤도 수정(Self-Correction) |
| **Action (행동·호출)** | 외부 도구 API 선택, 호출 파라미터 JSON 구성 및 실행 요청 | 검색 엔진, SQL DB, 사내 ERP, 계산기 등 이종 시스템과의 실시간 인터페이싱 |
| **Observation (관측·수용)** | 외부 도구 실행 결과값 수신 및 컨텍스트 메모리 편입 | 사실 기반 그라운딩(Grounding) 데이터 확보로 모델 고유의 환각 현상 원천 억제 |
| **순환 루프 (Looping)** | 목표 달성(Final Answer) 조건 충족 시까지 T-A-O 시퀀스 반복 | 정적인 1회성 응답을 넘어선 동적 환경 적응형 자율 문제 해결 |

## Ⅲ. ReAct 패턴의 체계 및 순환 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│             ReAct (Thought-Action-Observation) 오케스트레이션           │
└────────────────────────────────────────────────────────────────────────┘
 [ 사용자 복합 질의 (User Complex Goal) ]
                     │
                     ▼
┌────────────────────────────────────────────────────────────────────────┐
│ LLM 에이전트 코어 (Agent Runtime)                                      │
│                                                                        │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ [1] Thought: 현재 상태 분석 및 다음 목표 도출                 │   │
│   │     "현재 주가와 환율이 필요하므로 먼저 환율 API를 조회하자"   │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   │                                    │
│   ┌───────────────────────────────▼────────────────────────────────┐   │
│   │ [2] Action: 외부 도구 호출 명세 작성                           │   │
│   │     Action: CurrencyConverter(from="USD", to="KRW")            │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
└───────────────────────────────────┼────────────────────────────────────┘
                                    │ Tool Call (API 요청)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 외부 실행 환경 (External Tools & Sandbox)                              │
│  - Financial API, Web Search, Python REPL, Enterprise DB               │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Tool Response (반환값)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [3] Observation: 실행 결과 관측 및 프롬프트 주입                       │
│     Observation: 1 USD = 1,350.50 KRW                                  │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                  ┌─────────────────┴─────────────────┐
                  ▼ (목표 미달성 시)                  ▼ (목표 달성 시)
        [ [1] Thought로 순환 ]              [ 최종 정밀 응답 (Final Answer) ]
```

| 프로세스 단계 | 상세 수행 작업 | 제어 및 점검 항목 |
|---|---|---|
| **입력 및 프롬프트 조립** | 사용자 질의에 사용 가능 도구 목록 및 입출력 스키마 명세를 결합 | 도구 정의 JSON Schema 무결성 검증 |
| **추론 (Thought)** | 이전 관측 결과를 기반으로 현재 해결해야 할 단일 과업 결정 | 무의미한 반복 추론 여부 감시 |
| **행동 (Action)** | 호출할 함수명과 파라미터 값을 정확한 포맷(JSON/Text)으로 생성 | 인자 유효성(Validation) 및 타입 체킹 |
| **도구 실행 및 관측** | 런타임이 격리된 환경에서 도구를 구동하고 결과를 수집 | 실행 시간초과(Timeout) 및 예외 처리 |
| **종료 판정** | 추론 결과 최종 해답을 생성할 수 있는 상태인지 검사 | 최대 반복 횟수(Max Iteration) 초과 여부 확인 |

## Ⅳ. LLM 추론 및 실행 패러다임 비교

| 비교 항목 | Standard Prompting | CoT (Chain-of-Thought) | Act-only (단순 도구 호출) | ReAct (본 토픽) |
|---|---|---|---|---|
| **내부 추론(Thought)** | 부재 (즉시 생성) | 존재 (다단계 추론) | 부재 (호출만 수행) | 존재 (동적 추론 생성) |
| **외부 상호작용(Action)** | 부재 | 부재 (정적 지식 의존) | 존재 (정형 파이프라인) | 존재 (피드백 기반 호출) |
| **최신 정보 반영력** | 불가능 | 불가능 | 가능 (그러나 정적) | 최상 (관측값 기반 적응) |
| **환각(Hallucination)** | 매우 높음 | 다소 감소 | 중간 | 최소화 (사실 기반 교정) |
| **적용 적합 분야** | 단순 질의응답 | 수학·논리 단독 추론 | 정형화된 업무 자동화 | 다단계 조사, 심층 리서치 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 모델의 추론 루프가 종료 조건을 찾지 못하고 무한히 도구를 재호출하며 토큰 비용과 지연을 폭증시키는 문제 | 최대 홉 수(Max Hops: 5~10회) 강제 제한 및 동일 Action 2회 이상 연속 호출 시 폴백(Fallback) 강제 차단 |
| 에이전트가 오염된 프롬프트나 탈옥 공격에 의해 DB 삭제 등 위험 API를 무단 호출하는 보안 취약성 | 읽기 전용 샌드박스 격리와 민감 작업(CUD) 수행 전 인간 승인(HITL) 2단계 인증 필수 연계 |
| 도구 실행 결과(Observation)의 텍스트 길이가 과도하여 LLM의 컨텍스트 윈도우 한도를 초과하는 병목 | 도구 반환 결과에 대한 실시간 요약기(Compressor) 배치 및 핵심 필드 추출 스키마 강제화 |

## Ⅵ. 제언

안전한 엔터프라이즈 에이전트 운영을 위해 정책 기반 가드레일과 실시간 모니터링을 결합한 보안 강화형 ReAct 에이전트 게이트웨이 아키텍처 구축 권고.

```text
[ 사용자 요청 ] ──> [ 입력 보안 가드레일 (Prompt Injection 필터) ]
                               │
                               ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 에이전트 런타임 (Sandboxed ReAct Core)                                  │
│                                                                        │
│   Thought ──> Action 요청 ──> [ 도구 실행 정책 엔진 (Policy Engine) ]  │
│                                  ├── 비인가 도구 / 인자 오류: 즉시 거부 │
│                                  ├── 쓰기/삭제 작업: [ HITL 인간 승인 ]│
│                                  └── 읽기 작업: [ 전용 샌드박스 실행 ] │
│                                            │                           │
│   최종 응답 <── Observation 수신 <────────┘                           │
└──────────────────────────────┬─────────────────────────────────────────┘
                               │
                               ▼
                 [ 실시간 토큰 및 트레이스 감사 로깅 ]
```

| 구분 | 기본 ReAct 오픈소스 구현 | 제언: 보안 강화형 에이전트 게이트웨이 |
|---|---|---|
| **실행 권한** | 모델이 생성한 모든 Action 무조건 실행 | 세분화된 RBAC 권한 기반 도구 화이트리스트 |
| **민감 작업 제어** | 자율적 데이터 변경 위험 | 관리자 승인 게이트웨이(HITL) 통과 필수 |
| **비용 및 자원** | 무한 루프로 인한 요금 폭탄 노출 | 예산 상한선(Budget Cap) 및 홉 수 하드 리밋 |
| **감사 추적성** | 콘솔 텍스트 출력으로 휘발 | LangSmith/OpenTelemetry 연동 트레이스 저장 |
