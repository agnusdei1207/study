## Ⅰ. ReAct 패턴의 개요

- **개념** : LLM이 복잡한 질의를 해결하기 위해 언어적 추론(Reasoning) 생성과 도구 호출(Acting)을 동적으로 교차 수행하는 에이전트 상호작용 패턴
- **배경 및 필요성** : 무한 루프 반복 호출로 인한 토큰 비용 폭증과 권한을 초과하는 민감 API 무단 실행 위험이 상존하므로 최대 홉 수(Max Hops) 제한과 샌드박스 격리 및 인간 개입 승인(HITL) 게이트웨이 구축 필수
- **핵심 목적** : 폐쇄된 정적 파라미터 지식의 한계를 극복하고 최신 외부 정보 획득 및 능동적 시스템 제어 능력 확보

## Ⅱ. ReAct 패턴의 핵심 아키텍처 및 동작 메커니즘

ReAct 패턴은 질의 유입 시 모델이 중간 추론 경로를 생성(Thought)하고 적합한 외부 API/도구를 호출(Action)한 뒤 반환된 실행 결과(Observation)를 프롬프트에 누적하여 다음 판단 루프를 반복 메커니즘을 기반으로 동작하며, 세부적인 아키텍처와 핵심 컴포넌트 간 상호작용 프로세스는 다음과 같음.

```text
┌────────────────────────────────────────────────────────────────────────┐
│             ReAct (Thought-Action-Observation) 오케스트레이션           │
└────────────────────────────────────────────────────────────────────────┘
 [ 사용자 복합 질의 (User Complex Goal) ]
                     │
                     ▼
┌────────────────────────────────────────────────────────────────────────┐
│ LLM 에이전트 코어 (Agent Runtime)                                      │
│                                                                        │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ [1] Thought: 현재 상태 분석 및 다음 목표 도출                 │   │
│   │     "현재 주가와 환율이 필요하므로 먼저 환율 API를 조회하자"   │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   │                                    │
│   ┌───────────────────────────────▼────────────────────────────────┐   │
│   │ [2] Action: 외부 도구 호출 명세 작성                           │   │
│   │     Action: CurrencyConverter(from="USD", to="KRW")            │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
└───────────────────────────────────┼────────────────────────────────────┘
                                    │ Tool Call (API 요청)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 외부 실행 환경 (External Tools & Sandbox)                              │
│  - Financial API, Web Search, Python REPL, Enterprise DB               │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Tool Response (반환값)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [3] Observation: 실행 결과 관측 및 프롬프트 주입                       │
│     Observation: 1 USD = 1,350.50 KRW                                  │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                  ┌─────────────────┴─────────────────┐
                  ▼ (목표 미달성 시)                  ▼ (목표 달성 시)
        [ [1] Thought로 순환 ]              [ 최종 정밀 응답 (Final Answer) ]
```

- **Thought (사고·추론)** : 현재 상황 진단, 목표 분해(Decomposition), 다음 행동 계획 수립 - 복잡한 다단계 문제를 하위 태스크로 쪼개고 추론 오류 시 자체 궤도 수정(Self-Correction)
- **Action (행동·호출)** : 외부 도구 API 선택, 호출 파라미터 JSON 구성 및 실행 요청 - 검색 엔진, SQL DB, 사내 ERP, 계산기 등 이종 시스템과의 실시간 인터페이싱
- **Observation (관측·수용)** : 외부 도구 실행 결과값 수신 및 컨텍스트 메모리 편입 - 사실 기반 그라운딩(Grounding) 데이터 확보로 모델 고유의 환각 현상 원천 억제

## Ⅲ. ReAct 패턴의 세부 구성 요소 및 비교 분석

| 비교 항목 | Standard Prompting | CoT (Chain-of-Thought) | Act-only (단순 도구 호출) | ReAct (본 토픽) |
|---|---|---|---|---|
| **내부 추론(Thought)** | 부재 (즉시 생성) | 존재 (다단계 추론) | 부재 (호출만 수행) | 존재 (동적 추론 생성) |
| **외부 상호작용(Action)** | 부재 | 부재 (정적 지식 의존) | 존재 (정형 파이프라인) | 존재 (피드백 기반 호출) |
| **최신 정보 반영력** | 불가능 | 불가능 | 가능 (그러나 정적) | 최상 (관측값 기반 적응) |
| **환각(Hallucination)** | 매우 높음 | 다소 감소 | 중간 | 최소화 (사실 기반 교정) |

- ReAct 패턴은 상기 비교 지표를 바탕으로 비즈니스 요구사항과 운영 인프라 환경을 고려한 최적의 아키텍처를 선정하고, 확장성과 안정성을 균형 있게 확보해야 함.

## Ⅳ. ReAct 패턴의 주요 한계점 및 해결 방안

- **추론 루프가 종료 조건을 찾지 못하는 무한 반복 및 토큰 비용 폭증** :
  - **한계점** : 모델의 추론 루프가 종료 조건을 찾지 못하고 무한히 도구를 재호출하며 토큰 비용과 지연을 폭증시키는 문제.
  - **해결 방안** : 최대 홉 수(Max Hops: 5~10회) 강제 제한 및 동일 Action 2회 이상 연속 호출 시 폴백(Fallback) 강제 차단.
- **오염된 프롬프트나 탈옥 공격에 의한 위험 API 무단 호출 취약성** :
  - **한계점** : 에이전트가 오염된 프롬프트나 탈옥 공격에 의해 DB 삭제 등 위험 API를 무단 호출하는 보안 취약성.
  - **해결 방안** : 읽기 전용 샌드박스 격리와 민감 작업(CUD) 수행 전 인간 승인(HITL) 2단계 인증 필수 연계.
- **도구 실행 관찰(Observation) 텍스트 비대화로 인한 컨텍스트 초과** :
  - **한계점** : 도구 실행 결과(Observation)의 텍스트 길이가 과도하여 LLM의 컨텍스트 윈도우 한도를 초과하는 병목.
  - **해결 방안** : 도구 반환 결과에 대한 실시간 요약기(Compressor) 배치 및 핵심 필드 추출 스키마 강제화.

## Ⅴ. ReAct 패턴 적용 및 발전을 위한 기술사적 제언

- **실행 권한 최적화 및 신뢰성 확보 방안** : 모델이 생성한 모든 Action 무조건 실행을 선제적으로 구현하여 세분화된 RBAC 권한 기반 도구 화이트리스트를 체계적으로 달성하고 실무 운영 안정성을 완성해야 함.
- **민감 작업 제어 최적화 및 신뢰성 확보 방안** : 자율적 데이터 변경 위험을 선제적으로 구현하여 관리자 승인 게이트웨이(HITL) 통과 필수를 체계적으로 달성하고 실무 운영 안정성을 완성해야 함.
- **비용 및 자원 최적화 및 신뢰성 확보 방안** : 무한 루프로 인한 요금 폭탄 노출을 선제적으로 구현하여 예산 상한선(Budget Cap) 및 홉 수 하드 리밋을 체계적으로 달성하고 실무 운영 안정성을 완성해야 함.
