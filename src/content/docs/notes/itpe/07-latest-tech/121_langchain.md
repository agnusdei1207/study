최신 기술 → 생성형 AI 응용 → 언어모델 응용 프레임워크 → LangChain

## 30초 인출
- **본질:** LangChain은 모델·도구·검색 등을 조합해 언어모델 응용과 에이전트를 만드는 프레임워크.
- **메커니즘:** 입력을 프롬프트·검색·모델·도구 처리와 연결하고, 각 단계 결과로 다음 동작을 구성.
- **선택:** 단순 연쇄에는 Runnable 조합, 상태·분기·승인이 복잡한 워크플로에는 LangGraph 활용.

<details><summary>핵심 용어</summary>

- **LangChain:** 모델·메시지·도구·미들웨어 등 구성요소와 에이전트 패턴을 제공하는 응용 프레임워크.
- **Runnable:** 입력을 받아 정해진 처리를 수행하고 결과를 반환하는 LangChain 구성 단위.
- **LCEL(LangChain Expression Language):** Runnable을 선언적으로 연결하는 표현 방식.
- **RAG(Retrieval-Augmented Generation, 검색 증강 생성):** 외부 자료 검색 결과를 생성 모델의 문맥에 제공하는 응용 구조.
- **도구 호출(Tool Calling):** 모델이 도구 이름과 인자를 제안하고 응용프로그램이 실행 결과를 대화에 되돌리는 연계 방식.
- **LangGraph:** 상태·노드·전이를 바탕으로 분기와 반복을 포함한 에이전트 워크플로를 구성하는 프레임워크.
- **HITL(Human-in-the-Loop, 사람 개입):** 특정 실행이나 판단 전에 사람의 확인·승인을 받는 절차.

</details>

### Ⅰ. 개요

| 정의 | **LangChain**은 언어모델 응용에 필요한 모델·도구·검색 구성요소와 연결 방식을 제공하는 프레임워크 |
| 목적 | 언어모델과 업무 데이터·도구를 조합한 응용의 구성·운영 지원 |

### Ⅱ. 구성과 흐름
```text
사용자 입력
    |
    v
프롬프트·업무 문맥 구성
    |
    +--> 필요 자료 검색
    |
    v
모델의 응답 또는 도구 호출 제안
    |
    +--> 응용프로그램이 도구 실행·결과 전달
    |
    v
응답 구성·사용자 제공
```

Runnable 조합은 단계별 처리를 연결하는 방식. 모델이 제안한 도구 호출의 실행 권한과 결과 검증은 응용프로그램이 담당.

### Ⅲ. 적용 범위
| 요구 | 구성 접근 |
|---|---|
| 고정된 처리 순서 | 프롬프트·모델·파서 등의 Runnable 조합 |
| 외부 자료 참조 | 검색기와 RAG 문맥 구성 |
| 도구 실행 | 허용 도구 등록, 인자 검증, 실행 결과 전달 |
| 상태·분기·승인 | LangGraph 등 상태 기반 워크플로 검토 |

**제언:** 작업 범위와 도구 권한을 먼저 정하고 단계별 입력·출력 검증

## 2~4교시 25점 답안
## Ⅰ. 개요
| 구분 | 핵심 |
|---|---|
| 정의 | **LangChain**은 언어모델 응용에 필요한 모델·도구·검색 구성요소와 연결 방식을 제공하는 프레임워크 |
| 목적 | 언어모델과 업무 데이터·도구를 조합한 응용의 구성·운영 지원 |

## Ⅱ. 핵심 구조
LangChain의 역할은 언어모델 자체를 대체하는 것이 아니라, 모델 호출을 검색·업무 로직·도구와 조합하는 응용 계층.

```text
사용자 입력
    |
    v
프롬프트·업무 문맥 구성
    |
    +--> 필요 자료 검색
    |
    v
모델의 응답 또는 도구 호출 제안
    |
    +--> 응용프로그램이 도구 실행·결과 전달
    |
    v
응답 구성·사용자 제공
```

## Ⅲ. 주요 구성요소
| 구성 | 역할 |
|---|---|
| 모델·프롬프트 | 입력 문맥과 모델 응답 형식 구성 |
| Runnable | 개별 처리 단위와 처리 순서의 연결 |
| 검색기·RAG | 관련 업무 자료를 찾아 모델 문맥에 제공 |
| 도구 | 검색 외 API·계산 등 제한된 기능의 실행 요청 |
| 미들웨어·검증 | 권한, 입력·출력, 승인 등 업무 통제 적용 |

## Ⅳ. 도구 호출과 상태 관리
```text
모델의 도구 요청
       |
       v
응용프로그램의 이름·인자 검증
       |
       v
허용된 도구만 실행
       |
       v
실행 결과를 모델 문맥에 전달
       |
       +--> 최종 응답 또는 다음 판단
```

도구 호출은 모델이 제안한 요청이 곧바로 실행되는 구조가 아님. 권한 확인, 부작용 작업의 승인, 시간 초과·실패 처리를 응용 계층에 둠.

| 워크플로 특성 | 적용 방식 |
|---|---|
| 선형·짧은 연쇄 | Runnable 조합과 LCEL |
| 분기·반복·상태 보존 | LangGraph의 그래프 워크플로 |
| 중요한 변경·외부 실행 | 사람 승인, 도구 권한 제한, 실행 기록 |

## Ⅴ. 업무 적용과 통제
| 단계 | 예지정비 응용 예 |
|---|---|
| 자료 검색 | 설비 매뉴얼·정비 이력의 관련 항목 검색 |
| 데이터 조회 | 권한이 제한된 센서 요약 API 호출 |
| 응답 구성 | 근거 자료와 함께 점검 후보 제시 |
| 업무 조치 | 작업 지시 등록 전 담당자 검토·승인 |

적용 효과는 자료 품질, 모델, 도구 설계와 운영 검증에 좌우되며, 프레임워크 자체가 정확한 판단이나 안전한 실행을 보장하지 않음.

## Ⅵ. 기술사적 제언
| 한계 | 해결 방안 |
|---|---|
| 모델 출력과 도구 실행을 한 경로에 두면 잘못된 인자나 과도한 권한이 실제 업무 변경으로 이어질 수 있음 | 도구별 최소 권한·인자 검증·실행 로그를 두고, 되돌리기 어려운 업무는 사람 승인 후 실행하는 단계적 적용 |
