## 한 줄 본질
- 언어 모델 하나만 달랑 호출해서는 회사 문서 검색도 못 하고 외부 API도 못 부름 → 모델, 프롬프트, 벡터 데이터베이스, 파이썬 코드 실행기를 파이프(`|`) 기호 하나로 엮어 복잡한 자동화 봇을 순식간에 조립해 주는 소프트웨어 라이브러리 / 디버깅이 어렵고 무거움

## 핵심 용어
- LCEL(LangChain Expression Language): 유닉스 파이프 스타일(`chain = prompt | model | output_parser`)로 컴포넌트들을 연결하여, 스트리밍, 비동기 호출, 병렬 실행, 중간 단계 추적을 코드 수정 없이 자동 지원하는 선언적 문법
- 도구 호출(Tool Calling): 언어 모델이 필요에 따라 계산기, 데이터베이스 SQL 쿼리, 웹 검색, 이메일 발송 등 등록된 파이썬 함수를 스스로 판단하여 인자값을 채워 호출하는 인터페이스
- 설비예지정비(PdM, Predictive Maintenance): 설비의 진동, 온도 등 IoT 센서 데이터를 실시간 감시하여 고장 발생 전 징후를 예측하고 사전 정비하는 체계

## 핵심 통찰
- "복잡한 코드를 3줄로 줄여주는 추상화의 마법": OpenAI, Anthropic, HuggingFace 등 모델 벤더가 바뀌어도 코드 한 줄(`model = ChatOpenAI()`)만 바꾸면 모든 파이프라인이 그대로 돌아가는 벤더 중립적 추상화 계층 제공
- 132회 기출(예지정비) 적용 맥락: 예지정비 시스템에서 랭체인은 단순히 말을 주고받는 챗봇이 아니라, ① 센서 데이터베이스를 SQL 체인으로 조회하고, ② 두꺼운 설비 정비 매뉴얼을 RAG로 찾아내며, ③ ERP 시스템에 수리 부품 발주 티켓을 끊는 에이전트 '미들웨어' 역할을 수행함
- LangChain에서 LangGraph로의 무게 중심 이동: 복잡한 비즈니스 로직에서 단순 선형 체이닝(DAG)은 무한 루프나 조건부 분기 처리가 어려워, 순환 그래프 기반 상태 관리를 지원하는 LangGraph가 차세대 표준으로 정착함

## 이웃 토픽과 구분
- LlamaIndex vs LangChain: LlamaIndex는 데이터 인덱싱, 고급 검색 알고리즘 등 RAG 파이프라인 자체에 극도로 특화 / LangChain은 외부 도구 연계, 다단계 액션 에이전트 오케스트레이션에 특화

## 문제·원인·대책
- 적용 상황: 대규모 발전소 설비 예지정비 시스템에 랭체인 프레임워크 연동
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 랭체인 내부 다단계 체인 실행 중 특정 단계에서 멈췄으나 에러 원인 파악 불가 | 고수준 추상화 래퍼로 인한 스택 트레이스 불투명성 | 랭스미스(LangSmith) 또는 오픈텔레메트리(OpenTelemetry) 분산 추적 연동 | 체인 호출 단계별 토큰 및 입출력 완벽 가시화 |
| SCADA 실시간 센서 시계열 데이터 수만 포인트를 프롬프트에 넣어 컨텍스트 오버플로 | 정형 시계열 데이터를 텍스트로 무차별 주입 | 센서 통계 요약 툴(Pandas Agent)을 분리하여 에이전트가 이상 구간만 요약 질의 | 토큰 소비량 90% 절감 |
| 랭체인 패키지 마이너 버전 업데이트 시 기존 체인 코드 파괴적 에러 발생 | 빠른 라이브러리 진화에 따른 API Deprecation | LCEL 표준 문법 준수 및 핵심 파이프라인 컨테이너 버전 핀(Lock) 고정 | 라이브러리 의존성 장애 제로화 |

## 내 의견
- [LangGraph 기반의 결정론적 예지정비 상태 머신 구축] 랭체인의 기본 AgentExecutor는 비결정론적으로 동작하여 위험 설비 제어 시 예측할 수 없는 도구 호출을 유발할 위험이 있음 → 나라면: 센서 이상 감지 단계, 매뉴얼 검색 단계, 작업 승인 단계를 LangGraph의 노드와 조건부 엣지로 엄격히 정의하고, 실제 발전기 가동 중단이나 밸브 조작 같은 물리적 명령 단계에는 현장 관리자의 모바일 전자서명을 요구하는 HITL 인터럽트를 강제하는 안전 최우선 예지정비 아키텍처 구축
