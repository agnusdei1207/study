## 핵심 용어
- 텐서(Tensor): 스칼라(0차원), 벡터(1차원), 행렬(2차원)을 3차원 이상의 다차원 실수 배열로 일반화한 데이터 구조로, 딥러닝 연산의 기본 단위
- 즉시 실행(Eager Execution): 그래프 빌드 및 세션 실행(`sess.run()`) 없이, 파이썬 명령어를 실행하는 즉시 텐서 연산 결과가 반환되어 직관적 디버깅을 가능케 한 TF 2.0의 기본 모드
- TFLite(TensorFlow Lite): 모바일, IoT, 스마트워치 등 자원이 제한된 엣지 기기에서 모델을 초경량 구동할 수 있도록 8비트 정수 양자화(INT8)와 모델 경량화를 지원하는 실행 런타임

## 핵심 통찰
- "연구는 PyTorch, 대규모 산업 배포는 TensorFlow": 학계 연구자들은 직관적이고 논문 코드가 풍부한 파이토치를 선호하지만, 수백 대의 서버에서 모델을 무중단 서빙하고 모바일 앱에 포팅하는 엔터프라이즈 양산 환경에서는 검증된 TF Serving과 TFLite 생태계가 강력함
- TF 1.x의 실패와 2.x의 대혁신: 과거 TF 1.x는 'Define-and-Run' 정적 그래프 방식으로 디버깅이 지옥 같았으나, TF 2.x에서 Keras를 공식 API로 흡수하고 'Define-by-Run' 즉시 실행 모드를 채택하여 개발자 경험(DX)을 극대화함
- `@tf.function`의 양면성: 개발할 때는 파이썬 함수처럼 편하게 작성하고, 함수 위에 데코레이터(`@tf.function`) 한 줄만 붙이면 구글의 AutoGraph 엔진이 C++ 정적 계산 그래프로 자동 변환하여 프로덕션 실행 속도를 2배 이상 가속함

## 이웃 토픽과 구분
- TensorFlow vs PyTorch: TensorFlow는 엔터프라이즈 프로덕션 서빙, 모바일 TFLite, TFX 파이프라인에 강점 / PyTorch는 직관적 파이써닉 코드, 동적 그래프, 학계 연구 생태계에서 압도적 우위

## 문제·원인·대책
- 적용 상황: 안드로이드 스마트폰 카메라 앱에 실시간 얼굴 인식 모델 온디바이스 배포
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 원본 TensorFlow 모델 용량이 200MB에 달해 모바일 앱 설치 패키지 한도 초과 | 32비트 부동소수점(FP32) 가중치의 비대한 메모리 점유 | TFLite Converter 기반 8비트 정수 사후 양자화(PTQ) 적용 | 모델 크기 75% 압축(50MB) 및 VRAM 절감 |
| 모바일 CPU에서 실시간 추론 시 배터리 발열이 심하고 초당 프레임이 10fps로 저하 | 모바일 NPU 가속기 미활용 | TFLite NNAPI 위임자(Delegate) 연동을 통한 스마트폰 NPU 하드웨어 가속 | 추론 속도 60fps 달성 및 전력 소비 50% 절감 |
| 개발 서버(Python 3.10)에서 잘 돌아가던 모델이 C++ TF Serving 배포 시 타입 에러 | 파이썬 동적 타이핑과 TF 정적 그래프 입출력 텐서 스키마 불일치 | SavedModel 포맷 내보내기 시 `@tf.function(input_signature=...)` 타입 강제 | 프로덕션 배포 런타임 오류 제로화 |
