## 한 줄 본질
- 실제 공장 가동을 멈추거나 위험한 실험을 물리적으로 직접 수행할 수 없던 제약 → 센서 IoT 데이터를 통해 물리 자산의 상태와 거동을 가상 세계에 1:1로 실시간 복제하여 시뮬레이션 → 사전 결함 예측과 최적 운영 조건 자율 제어 / 데이터 모델링 복잡도 및 통신 지연시간 제약

## 핵심 용어
- What-If 시뮬레이션: 물리 설비에 실제로 파괴적 부하나 가혹 조건을 가하지 않고, 가상 트윈 모델 상에서 가상으로 다양한 변수를 변경하여 결과를 사전에 검증하는 분석 기법
- ISO 23247: 제조 분야의 디지털 트윈 구현을 위한 국제 표준 참조 아키텍처로, 사용자, 애플리케이션, 디지털 트윈, 디바이스 4개 서브시스템으로 구성
- 상태 감시 및 예지보전(PdM, Predictive Maintenance): 설비의 고장이 발생한 후 수리하거나 정기적으로 교체하는 것이 아니라, 센서 데이터의 미세 이상 징후를 감지하여 고장 직전 최적 시점에 정비하는 기술

## 핵심 통찰
- 단순 3D 그래픽 모델(메타버스)과 디지털 트윈을 가르는 단 하나의 기준은 "물리 데이터와의 실시간 양방향 동기화(Live Data Sync)" 여부임
- 형상(Geometry) 트윈에서 시작하여, 물리 법칙(Physics) 트윈, 예측(Predictive) 트윈, 자율 최적화(Autonomous) 트윈으로 단계별 고도화가 진행됨
- 공장뿐만 아니라 도심 항공 교통(UAM), 국가 스마트 시티, 심장 모사 의료 트윈 등 복합 시스템 제어의 필수 기반 기술로 확산

## 이웃 토픽과 구분
- 디지털 트윈 vs 메타버스: 메타버스는 인간 사용자의 몰입과 소셜 상호작용이 목적 / 디지털 트윈은 실제 물리 기기의 성능 최적화, 예측, 자율 제어가 목적으로 물리 현실에 종속

## 문제·원인·대책
- 적용 상황: 대규모 제철 플랜트 연속 주조 라인에 디지털 트윈 구축 후 동기화 지연 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 물리 설비의 고속 동작과 3D 가상 모델 간 2초 이상의 시각적 불일치 | 수천 개 센서의 중앙 클라우드 전송에 따른 네트워크 레이턴시 | 엣지 컴퓨팅 노드 배치 및 센서 데이터 사전 집계(Edge Preprocessing) | 가상-물리 동기화 지연 50ms 이내 단축 |
| 벤더별 PLC 및 센서 통신 프로토콜 파편화로 통합 불가 | 폐쇄형 독점 산업용 프로토콜 혼재 | OPC UA(Open Platform Communications) 표준 데이터 모델 적용 | 이기종 데이터 단일 인터페이스 통합 |
| 실제 설비 노후화에 따른 열화 거동을 가상 모델이 미반영 | 정적 물리 공식에만 의존한 가상 시뮬레이션 | 물리 기반 모델과 머신러닝 시계열 잔차 모델의 결합(Physics-Informed ML) | 1년 경과 후에도 예지보전 정확도 95% 유지 |

## 이렇게 출제된다

## 내 의견
- [OPC UA와 ISO 23247을 결합한 개방형 디지털 트윈 플랫폼 표준화] 특정 상용 벤더의 독점 디지털 트윈 소프트웨어를 도입하면 추후 신규 라인 확장 시 라이선스 비용과 벤더 락인이 심각함 → 나라면: 오픈 프로토콜인 OPC UA를 전사 데이터 백본으로 깔고, ISO 23247 4계층 아키텍처를 준수하여 센서 수집부와 3D 시뮬레이션 엔진(Unreal/Unity)을 분리 구축함으로써 설비 변경에 유연한 확장형 플랫폼 확보
