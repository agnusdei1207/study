## 답안 골격
```text
[파라미터] ◀━━ 머리: Ⅶ 내 의견 (데이터 학습 과정에서 손실 함수 최적화를 통해 스스로 갱신되며 모델의 지식과 표현력을 결정하는 내부 가중치 변수)
 ┃
 ┣━ Ⅰ 개요 ───── 하드코딩된 규칙 기반 시스템의 한계 → 입력 데이터와 손실 함수의 최적화(역전파)를 통해 기계가 스스로 학습하는 내부 변수(파라미터) 태동
 ┣━ Ⅱ 특징 ───── 데이터 주도적 자동 학습 · 손실 함수 최소화 최적화 대상 · 모델 표현력(Capacity) 결정 · 사후 저장 및 추론 재사용(가중치 파일)
 ┣━ Ⅲ 구조 ───── 가중치 행렬(Weight, $W$) + 편향 벡터(Bias, $b$) + 임베딩 룩업 벡터 + 배치 정규화 파라미터($\gamma, \beta$)
 ┣━ Ⅳ 흐름 ───── ① 초기화(He/Xavier) → ② 순전파(출력 계산: $y = Wx + b$) → ③ 손실 계산 및 오차 역전파 → ④ 옵티마이저 기반 파라미터 갱신($W \leftarrow W - \eta \nabla L$) → ⑤ 수렴 후 고정
 ┣━ Ⅴ 비교 ───── 파라미터(Parameter) vs 하이퍼파라미터(Hyperparameter) (내부 변수 vs 외부 설정값 / 데이터 자동 학습 vs 개발자 수동 지정 / 가중치·편향 vs 학습률·배치크기)
 ┗━ Ⅵ 실무 ───── 파라미터 수 폭증에 따른 GPU VRAM 고갈 / 과적합(Overfitting) 발생 / 그래디언트 소실 및 폭주
```

## 한 줄 본질
- 사람이 손으로 규칙을 코딩해 넣는 것이 아니라, 수백만 건의 데이터를 보여주며 틀릴 때마다 컴퓨터가 스스로 숫자를 미세하게 돌려가며 정답을 맞히도록 학습되는 딥러닝 신경망 내부의 수십억 개 가중치(Weight)와 편향(Bias) / 파라미터가 커질수록 엄청난 GPU 메모리 요구

## 핵심 그림
```text
[인공신경망의 단일 뉴런 내부 파라미터(가중치 W, 편향 b) 연산 및 갱신 흐름]

     입력 벡터 x                   학습 파라미터 (가중치 W)
    ┌───────────┐                         ┌───────────┐
    │ x_1, x_2  │ ──────────────────────> │  W_1, W_2 │
    └───────────┘                         └─────┬─────┘
                                                │
                                                ▼ (선형 결합: Σ W_i·x_i)
                                          ┌───────────┐
  학습 파라미터 (편향 b) ───────────────> │     +     │
                                          └─────┬─────┘
                                                ▼
                                          ┌───────────┐
                                          │ 활성화 함수│ ──> 출력 y = σ(Wx + b)
                                          │ (ReLU 등) │
                                          └─────┬─────┘
                                                │
       [역전파 손실 경사] ──> W_new = W_old - η · (∂L/∂W)  (경사하강법 갱신)
```

## 핵심 용어
- 가중치(Weight, $W$): 입력 신호가 다음 뉴런의 출력에 미치는 상대적 중요도 또는 영향력의 크기를 나타내는 핵심 파라미터 행렬
- 편향(Bias, $b$): 활성화 함수가 얼마나 쉽게 발화(Fire)할 수 있는지를 조절하여 원점을 이동시키는 오프셋 파라미터
- 모델 용량(Model Capacity): 파라미터의 수가 많을수록 복잡하고 비선형적인 고차원 데이터 함수를 완벽히 모사할 수 있는 표현력의 척도

## 핵심 통찰
- "학습이란 파라미터라는 수십억 개의 다이얼을 최적으로 돌리는 과정": 손실 함수라는 채점표를 기준으로 경사하강법을 사용해 가중치 다이얼을 0.001씩 돌리며 오차가 0에 가까워지도록 수렴시킴
- 파라미터 규모와 메모리 계산의 법칙: 70B(700억) 파라미터 모델을 띄우려면, FP16(16비트=2바이트) 기준 순수 가중치만 $70 \times 10^9 \times 2 \text{ byte} = 140\text{GB}$의 VRAM이 필요하며, Adam 옵티마이저 학습 시에는 상태 변수 때문에 4배(560GB)가 필요함
- 과적합의 함정: 훈련 데이터 샘플 수에 비해 파라미터 수가 너무 많으면, 데이터의 본질적 규칙을 배우는 대신 훈련 데이터 전체를 통째로 암기(Memorization)해 버려 새로운 데이터에 무용지물이 됨

## 이웃 토픽과 구분
- 파라미터 vs 하이퍼파라미터: 파라미터는 데이터로부터 기계가 '자동 학습'하는 내부 가중치 / 하이퍼파라미터는 학습을 시작하기 전 인간 엔지니어가 '수동 설정'하는 학습률, 배치 크기 등의 환경 설정값

## 문제·원인·대책
- 적용 상황: 수십억 파라미터 거대 모델 학습 중 그래디언트 소실 및 GPU 메모리 부족 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 신경망 층이 깊어질수록 입력층 근처 파라미터의 그래디언트가 0에 수렴하여 학습 중단 | Sigmoid 활성화 함수 사용으로 인한 그래디언트 소실(Vanishing Gradient) | ReLU 활성화 함수 적용 및 잔차 연결(Residual Connection) 아키텍처 도입 | 깊은 층에서도 안정적인 파라미터 갱신 달성 |
| 70B 파라미터 모델의 가중치를 단일 GPU(80GB)에 로딩 시 즉시 OOM 에러 발생 | FP16 기준 140GB에 달하는 막대한 파라미터 메모리 점유 | AWQ/GPTQ 기반 4비트 정수 가중치 양자화(INT4) 적용 | 모델 메모리 35GB로 압축하여 단일 GPU 서빙 실현 |
| 파라미터 수가 너무 많아 훈련 손실은 0에 도달했으나 검증 데이터 손실이 급증 | 모델 용량 과다에 따른 훈련 데이터 단순 암기(과적합) | 가중치 감쇠(Weight Decay, L2 정규화) 및 드롭아웃(Dropout 0.3) 적용 | 가중치 절대값 억제 및 일반화 성능 15% 향상 |

## 내 의견
- [파라미터 효율화(PEFT)와 선택적 가중치 프루닝(Pruning) 표준 수립] 파라미터를 무조건 늘리는 것은 전력망과 하드웨어 비용 측면에서 한계에 도달함 → 나라면: 사전학습된 거대 가중치 중 실제 추론에 기여도가 낮은 하위 30%의 파라미터를 0으로 잘라내는 구조적 가지치기(Structural Pruning)를 적용하고, 도메인 파인튜닝 시에는 LoRA를 통해 0.1% 미만의 파라미터만 학습시키는 경량화 파이프라인을 구축하여 엔터프라이즈 AI TCO 80% 절감
