## 연관 키워드

- RLHF(인간 피드백 강화학습), 보상 모델(Reward Model), PPO(Proximal Policy Optimization), DPO(Direct Preference Optimization)
- RLAIF(AI 피드백 강화학습), 정렬(Alignment), 보상 해킹(Reward Hacking), KL 발산(KL Divergence)
- SFT(Supervised Fine-Tuning), 얼라인먼트 세금(Alignment Tax)

## Ⅰ. RLHF의 개요

- 핵심 요약 : 인간의 선호 피드백으로 학습한 보상 신호를 써서 언어 모델을 사람의 의도와 가치에 맞추는 정렬 기술.
- 개념 : 사전학습된 거대언어모델(LLM, Large Language Model)의 응답을 인간 선호에 맞추기 위해, 선호 데이터로 보상 모델을 학습하고 그 보상으로 모델 가중치를 강화학습하는 방법 (**RLHF** (Reinforcement Learning from Human Feedback, 인간 피드백 강화학습)).
- 배경 및 필요성 : 원시 텍스트만으로 학습한 모델은 유해하거나 거짓된 응답을 생성하므로, 지도 미세조정(SFT, Supervised Fine-Tuning)만으로는 유용하고 정직하며 무해한 응답을 확보하기 어려움.
- 주요 목적 : 모델의 인간 가치 정렬, 환각과 유해 응답 억제, 모호한 질문에 정중하고 유용하게 답하도록 유도.

## Ⅱ. RLHF의 특징 및 장점

- 핵심 요약 : 인간 선호를 학습 가능한 보상으로 바꾸고 KL 제약으로 원래 모델의 능력을 지키는 구조가 정렬 효과와 학습 안정성으로 이어짐.

1. 선호 기반 라벨링 : 절대 점수 대신 응답 간 순위를 매김 → 평가 기준을 일관되게 유지하기 쉬움.
2. **보상 모델** (Reward Model) 분리 : 선호를 스칼라 보상 값으로 압축 → 대량의 응답 평가에 재사용 가능.
3. **KL 발산** (Kullback-Leibler divergence) 제약 : 초기 모델과의 출력 분포 차이에 벌점을 부과 → 언어 능력이 무너지는 현상 방지.

## Ⅲ. RLHF의 구조 (흐름)

- 핵심 요약 : 지도 미세조정, 보상 모델 학습, 강화학습 정책 갱신의 3단계가 순차로 이어지는 파이프라인.

```text
[ RLHF 3단계 파이프라인 ]

1단계 지도 미세조정 (SFT)
   ↓ 모범 답변 데이터로 기본 학습
2단계 보상 모델 학습
   ↓ 인간 선호 순위로 보상 학습
3단계 PPO 강화학습
   ↓ 보상 최대화, KL 벌점으로 제한
정렬된 모델
```

- 1단계 : 프롬프트에 대한 모범 답변으로 모델을 튜닝해 기본적인 지시 준수 능력을 확보.
- 2단계 : 같은 프롬프트에 대한 여러 응답을 사람이 순위로 정렬하고, 쌍별 비교 모델로 스칼라 보상을 출력하도록 학습.
- 3단계 : **PPO** (Proximal Policy Optimization, 근접 정책 최적화)로 보상을 최대화하되, 초기 모델과의 차이를 KL 벌점으로 제한.

```text
[ 3단계 PPO 루프 ]

프롬프트 x 입력
   ↓
정책 모델이 응답 y 생성
   ↓
보상 모델이 r(x, y) 산출
   ↓
R = r(x, y) - β·KL(정책 ∥ 초기 모델)
   ↓
R이 커지도록 정책 가중치 갱신
```

## Ⅳ. RLHF와 DPO, RLAIF의 비교

- 핵심 요약 : 복잡한 PPO 파이프라인을 단순화한 DPO와, 사람 대신 AI가 피드백을 주는 RLAIF가 실무 대안으로 부상.
- 실무에서는 PPO의 4개 모델 동시 구동 부담을 피하려고 **DPO** (Direct Preference Optimization, 직접 선호 최적화)를 많이 쓴다.
- AI 피드백 강화학습(RLAIF, Reinforcement Learning from AI Feedback)은 고성능 LLM이 헌법 같은 원칙에 따라 선호를 생성하는 방식이다.

| 비교 축 | RLHF (PPO 기반) | DPO | RLAIF |
| --- | --- | --- | --- |
| 보상 모델 | 별도 신경망으로 필요 | 불필요, 선호 손실로 정책 직접 갱신 | 필요하거나 DPO와 결합 |
| 학습 방식 | 강화학습 (Actor, Critic, Reference, RM 동시 구동) | 분류형 손실 기반 학습 | PPO 또는 DPO 활용 |
| 메모리 부담 | 가장 큼 | 상대적으로 작음 | PPO 사용 시 큼 |
| 학습 안정성 | 하이퍼파라미터에 민감 | 상대적으로 안정적 | 평가자 편향이 적음 |
| 피드백 원천 | 사람 라벨러 | 사람 라벨러 | 고성능 LLM |

## Ⅴ. RLHF의 한계와 방안

- 핵심 요약 : 라벨러 편향, 보상 해킹, 과잉 거부를 AI 피드백, 계수 튜닝, 데이터 균형으로 보완하는 체계.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 라벨러 주관성과 비용 | 평가자의 편향이 모델에 주입되고 숙련 라벨링 비용이 큼 | 헌법 기반 RLAIF로 AI 피드백을 보완 | 라벨 일치도, 라벨링 단가 |
| 보상 해킹 | 보상 모델이 높게 주는 장황하거나 무익한 어투를 모델이 반복 | KL 계수 정밀 튜닝, 다중 보상 모델 앙상블 | 실제 품질 평가 점수 |
| 과잉 거부 (Over-refusal) | 무해한 질문까지 거부하는 과잉 방어로 유용성 저하 | 유용성과 무해성 데이터의 비율 조정, 문맥 인지형 정렬 | 부당 거부율 |

## Ⅵ. RLHF에 대한 기술사적 제언

- 핵심 요약 : 무거운 PPO를 기본값으로 두지 않고, DPO 기반 정렬과 자동화된 레드팀 평가를 묶은 운영 체계를 갖추는 방향.

1. 기업 환경에서는 PPO의 메모리 부담과 학습 불안정성을 피하기 위해 DPO 파이프라인을 우선 채택하는 것이 현실적이다.
2. 보안 지침과 브랜드 가치를 담은 헌법 문서를 만들고, 이를 근거로 AI 피드백을 생성하는 자동 평가 루프를 운영하는 것이 바람직하다.
3. 정렬이 끝난 모델도 JailbreakBench 같은 탈옥 벤치마크로 주기적으로 스트레스 테스트해야 방어선이 유지된다.

## Ⅶ. 결론

- 핵심 요약 : RLHF는 인간 선호를 모델 행동으로 옮기는 정렬의 기준선임.
- 실무는 학습 방식을 단순화하고 평가를 자동화하는 쪽으로 이동하고 있으며, 정렬의 품질은 피드백 데이터의 질과 지속적인 레드팀 검증에 달려 있음.
