## 연관 키워드

- ANI(Artificial Narrow Intelligence), AGI, ASI, 약인공지능, 복합 AI 시스템
- 과업 특화 최적화, OOD, 서킷 브레이커, LoRA, PEFT, 경량화

## Ⅰ. ANI(Artificial Narrow Intelligence)의 개요

- 핵심 요약 : 특정 도메인의 한정된 과업을 고정밀도로 수행하도록 최적화된 약인공지능으로, 복합 AI 시스템의 구성 요소가 되는 기술 범주.
- 개념 : 인간 수준의 지능을 목표로 하는 **AGI** (Artificial General Intelligence, 범용 인공지능)와 달리, 특정 도메인이나 단일 과업만 고정밀로 수행하도록 설계·최적화된 **약인공지능** (ANI, Artificial Narrow Intelligence).
- 배경 및 필요성 : 거대 범용 모델은 추론 비용이 크고 환각 위험이 있어, 고정밀·저비용 ANI 모듈을 조합하는 **복합 AI 시스템** (Compound AI System) 방식이 주목받음.
- 주요 목적 : 실시간 추론 달성, 미션 크리티컬 환경의 결정론적 신뢰성 확보, 서빙 비용 최소화 (TCO, Total Cost of Ownership).

## Ⅱ. ANI(Artificial Narrow Intelligence)의 특징 및 장점

- 핵심 요약 : 과업 특화, 제한된 경계, 고효율, 검증 가능성이 맞물려 예측 가능하고 운영 부담이 낮은 AI 모듈을 만드는 속성.

1. **과업 특화 최적화** : 정의된 입력과 출력 관계에 맞춘 데이터와 신경망 구조 → 해당 과업에서 높은 정확도와 낮은 지연 시간 확보.
2. 결정론적 경계 : 정해진 과업 밖의 일은 수행하지 못하고 일반화 능력이 낮음 → 입출력 스키마를 고정해 예측 가능성 확보.
3. **고효율 자원 소비** : 거대 모델보다 적은 파라미터로 구동 → 엣지 기기 탑재가 쉬움. **가지치기** (Pruning)와 **양자화** (Quantization)로 경량화.
4. 검증 가능성 : IoU(Intersection over Union)나 F1-score 같은 지표로 성능을 정량 평가 → 통제된 테스트셋으로 안전성 근거 확보.

## Ⅲ. ANI(Artificial Narrow Intelligence)의 구조 (흐름)

- 핵심 요약 : 범용 모델이 과업을 나누어 ANI 모듈을 도구처럼 호출하고, 결과를 검증기가 걸러내는 복합 구조.
- **OOD** (Out-of-Distribution, 학습 데이터 분포 밖의 입력) : 모델이 익숙하지 않은 입력을 탐지하여 안전 경로로 돌리는 점검 대상.
- **도구 호출** (Tool Calling) : 범용 모델이 특정 ANI 모듈의 기능을 외부 도구처럼 호출하는 방식.

```text
[ 사용자 복합 요청 ]
            ↓
[ 범용 모델 (라우터) ]
            ↓ 과업 분배
[ 전문 ANI 모듈 호출 ]
            ↓
[ 비전 | 계산 | 검색 모듈 ]
            ↓ 결과 취합
[ 품질 검증기 (규칙 기반) ]
```

```text
[ 입력 데이터 ]
      ↓
[ OOD 탐지 (분포 이탈 점검) ]
      ↓ 정상           ↓ 이탈 또는 불확실
[ ANI 예측 ]     [ 안전 대체 경로 ]
```

## Ⅳ. ANI, AGI, ASI의 비교

- 핵심 요약 : ANI는 제한된 과업에서 실제로 상용화된 단계이며, AGI와 ASI는 범위와 실현 시점이 아직 정해지지 않은 개념임.

| 비교 축 | ANI (약인공지능) | AGI (범용 인공지능) | ASI (Artificial Super Intelligence, 초인공지능) |
| --- | --- | --- | --- |
| 정의 | 특정 영역의 과업만 수행 | 인간 수준의 범용 지적 과업 수행 | 대부분의 영역에서 인간 지능을 넘어서는 가설적 개념 |
| 지식 전이 | 새 과업에는 재학습이 필요 | 새로운 영역으로 학습을 전이 | 자율적 발견과 개선을 전제 |
| 구현 방식 | 과업 전용 신경망과 머신러닝 모델 | 대규모 멀티모달 모델과 복합 시스템 | 확정된 구현 방식 없음 |
| 실현 상태 | 상용 서비스로 널리 활용 | 연구 개발 진행 중 | 개념 단계 |

- 선택 기준 : 과업 범위가 명확하고 검증 기준이 있으면 ANI 모듈을, 과업 범위가 넓고 유연한 추론이 필요하면 범용 모델을 조합하는 방식을 검토함.

## Ⅴ. ANI(Artificial Narrow Intelligence)의 한계와 방안

- 핵심 요약 : 분포 이탈 시 침묵 오류, 모델 파편화, 모듈 장애 전파를 이탈 탐지, 공통 백본, 장애 격리로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **침묵 오류** (Silent Error) | 학습 분포 밖 입력에서 모델이 확신 있게 틀린 결과를 냄 | 마할라노비스 거리(Mahalanobis Distance) 기반 OOD 탐지, 불확실성 임계치 초과 시 안전 대체 경로 | 탐지율, 대체 경로 전환 비율 |
| 과업별 모델 파편화 | 과업마다 독립 모델을 구축해 MLOps(Machine Learning Operations) 유지보수 비용 급증 | 공통 백본에 **LoRA** (Low-Rank Adaptation) 어댑터만 교체하는 **PEFT** (Parameter-Efficient Fine-Tuning) 구조 | 운영 모델 수, 배포 소요 시간 |
| 캐스케이딩 실패 | 단일 모듈의 오작동이 복합 시스템 전체로 전파 | **서킷 브레이커** (Circuit Breaker) 패턴, 규칙 기반 검증기의 최종 필터링 | 장애 격리 소요 시간 |

## Ⅵ. ANI(Artificial Narrow Intelligence)에 대한 기술사적 제언

- 핵심 요약 : 모듈 단위의 독립 교체와 라우팅 정책, 서비스 수준 관리를 갖춘 복합 AI 아키텍처로 운영하는 방향.

1. 전사 AI 아키텍처 표준에 복합 AI 시스템과 **MCP** (Model Context Protocol) 같은 표준 도구 인터페이스를 채택하여 모듈을 독립적으로 교체하고 업그레이드할 수 있도록 하는 것이 바람직함.
2. 반복되는 단순 과업은 고비용 LLM 대신 도메인 ANI나 소형 언어 모델(SLM, Small Language Model)로 라우팅하는 기준을 세우고, 비용과 정확도를 함께 측정하여 정책을 갱신하는 것이 현실적임.
3. 미션 크리티컬 영역에서는 모듈별 **서비스 수준 협약** (SLA, Service Level Agreement) 준수율을 운영 지표로 삼아 장애 책임과 복구 기준을 명확히 하는 것이 필요함.

## Ⅶ. 결론

- 핵심 요약 : ANI는 특정 과업에서 정확도와 효율을 확보하는 약인공지능으로, 현재 실용 AI 시스템의 기본 구성 요소임.
- 시사점 : 범용 모델의 한계를 보완하는 방법은 모델을 키우는 것이 아니라 검증된 ANI 모듈을 조합하고 통제하는 설계에 있음.
