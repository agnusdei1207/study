## 연관 키워드

- 도메인 특화 언어모델(DSLM, Domain-Specific Language Model), DAPT, PEFT, 토크나이저 확장, SFT, DPO
- 환각, RAG, 온프레미스 서빙, 합성 데이터, 총소유비용

## Ⅰ. 도메인 특화 언어모델(DSLM)의 개요

- 핵심 요약 : 범용 LLM을 특정 산업의 전문 코퍼스로 추가 학습시켜 전문성과 기밀성을 확보한 맞춤형 모델.
- 개념 : 범용 파운데이션 모델에 의료, 법률, 금융, 반도체 등 산업 도메인의 전문 코퍼스와 용어 사전을 추가 학습시키고, 지도 미세조정을 더해 해당 산업의 추론과 업무 양식에 맞춘 언어모델 (**도메인 특화 언어모델** (DSLM, Domain-Specific Language Model)).
- 배경 및 필요성 : 범용 LLM은 전문 판례와 의학 용어에 약해 환각이 잦고, 외부 API 호출은 기밀 유출 위험과 토큰당 누적 과금 비용을 만들며, 산업 규제 준수도 어려움. 이 비용을 줄이려면 사내에서 구동 가능한 전문 모델로 전환하는 방향이 필요해짐.
- 주요 목적 : 전문 업무의 정확도 향상, 환각 억제, 사내 온프레미스 경량 서빙, 기업 고유 데이터의 모델 자산화.

## Ⅱ. 도메인 특화 언어모델(DSLM)의 특징 및 장점

- 핵심 요약 : 도메인 지식의 가중치 내재화, 사내 구동, 검색 증강이 정확도·보안·비용의 이점으로 이어지는 구조.

1. **도메인 적응 사전학습** (DAPT, Domain-Adaptive Pre-training) : 대규모 비지도 전문 코퍼스를 계속 학습 → 전문 문맥과 관계 지식을 가중치에 내재화해 전문 질의 정확도 향상.
2. **온프레미스 서빙** (On-premise Serving) : 사내 GPU 서버에서 모델을 구동 → 기밀 데이터가 외부 API로 나가지 않아 유출 위험 차단.
3. **검색 증강 생성** (RAG, Retrieval-Augmented Generation) : 개정되는 법령과 약관을 벡터 검색으로 주입 → 지식 최신성 확보와 답변의 근거 제공.
4. 기업 고유 지식의 축적 : 특허, 연구개발 문서, 결재 문서를 학습 자산으로 전환 → 외부 모델로 대체하기 어려운 경쟁 우위 형성.

## Ⅲ. 도메인 특화 언어모델(DSLM)의 구조 (흐름)

- 핵심 요약 : 토크나이저 확장, 계속 사전학습, 지도 미세조정, 정렬과 서빙의 4단계 파이프라인에 검색 증강이 결합된 구조.

```text
[ DSLM 구축 4단계 파이프라인 ]

오픈 파운데이션 모델 가중치
            ↓
1. 도메인 데이터 정제, 토크나이저 확장
            ↓
2. 도메인 적응 사전학습 (DAPT)
            ↓
3. 도메인 지도 미세조정
            ↓
4. 정렬과 온프레미스 서빙
```

- **토크나이저 확장** (Tokenizer Adaptation) : 의학·법률 용어가 여러 토큰으로 쪼개지는 현상을 줄이도록 도메인 어휘를 추가 → 토큰 낭비 감소.
- **지도 미세조정** (SFT, Supervised Fine-Tuning) : 전문가가 검증한 질의응답과 업무 문서로 실제 업무 양식에 맞춰 답변을 정렬.
- **직접 선호 최적화** (DPO, Direct Preference Optimization) : 도메인 윤리와 컴플라이언스 기준이 반영된 선호 데이터로 응답을 정렬.

```text
[ DSLM과 RAG의 하이브리드 결합 ]

사용자 질의
      ↓
벡터 검색 (최신 법령·약관 조회)
      ↓
DSLM 추론 (전문 지식 + 검색 근거)
      ↓
근거가 붙은 응답
```

## Ⅳ. 범용 LLM, 순수 RAG, DSLM의 비교

- 핵심 요약 : 범용 LLM의 전문성 부족과 순수 RAG의 문맥 오독을 DSLM과 검색 증강의 결합이 함께 보완.

| 비교 축 | 범용 거대 LLM | 순수 RAG 시스템 | DSLM과 RAG 결합 |
| --- | --- | --- | --- |
| 전문 용어 이해도 | 일반 상식 수준, 뉘앙스 오해석 가능 | 검색은 되나 LLM의 문맥 오독 가능 | 도메인 지식과 어투를 가중치에 내재화 |
| 지식 최신성 | 사전학습 시점에 고정 | 외부 검색으로 즉시 갱신 | 검색 결합으로 최신 지식 반영 |
| 사내 데이터 보안 | 외부 API 호출 시 유출 위험 | 사내 벡터 DB 구축으로 양호 | 사내 폐쇄망 구동 가능 |
| 서빙 비용 (TCO, Total Cost of Ownership) | 토큰당 누적 과금으로 높음 | 벡터 DB와 상용 API 비용 | 사내 GPU 서버 중심으로 관리 가능 |
| 환각 발생률 | 전문 질의에서 빈번 | 검색 문맥에 의존하나 발생 가능 | 도메인 지식과 검색 근거로 억제 |

- 선택 기준 : 데이터 외부 반출이 불가능하고 전문 질의가 반복되는 영역일수록 DSLM과 RAG 결합의 적용 효과가 큼.

## Ⅴ. 도메인 특화 언어모델(DSLM)의 한계와 방안

- 핵심 요약 : 전문 학습에 따른 일반 능력 저하, 라벨링 병목, 법령 개정 지연을 혼합 학습, 합성 데이터, 검색 증강으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 치명적 망각 (Catastrophic Forgetting) | 도메인 코퍼스 집중 학습 → 일반 요약과 타 분야 질의 응답 품질 저하 | 계속 사전학습에 일반 코퍼스를 일정 비율로 혼합하고, **매개변수 효율적 미세조정** (PEFT, Parameter-Efficient Fine-Tuning)인 LoRA(Low-Rank Adaptation) 채택 | 일반 과제 성능 유지율 |
| 전문가 라벨링 병목 | 고임금 전문가의 수작업 검수 → 데이터 구축 비용과 기간 증가 | 고성능 LLM으로 **합성 데이터** (Synthetic Data)를 생성하고 전문가가 표본을 검수 | 검수 통과율, 데이터 구축 리드타임 |
| 법령 개정 반영 지연 | 가중치가 학습 시점에 고정 → 개정 조문을 즉시 반영하지 못함 | DSLM을 추론 백본으로 두고, 최신 조문은 RAG로 프롬프트에 동적 주입 | 최신 문서 색인 지연 시간, 근거 인용률 |

## Ⅵ. 도메인 특화 언어모델(DSLM)에 대한 기술사적 제언

- 핵심 요약 : 데이터 전처리 표준, 사내 자산의 체계화, 도메인 전문가 평가 체계를 갖춰 DSLM을 일회성 실험이 아닌 지속 운영 자산으로 정착.

1. 도메인 텍스트를 수집하는 단계에서 토크나이저 확장을 선행하는 전처리 표준을 두면, 토큰 생성 속도와 그래픽 처리 장치(GPU, Graphics Processing Unit) 메모리 사용 효율을 함께 개선할 수 있다.
2. 외부에 공개할 수 없는 사내 자산을 학습 데이터로 체계화하면, 기업 고유의 DSLM이 외부 모델로 대체하기 어려운 기술 장벽을 쌓는다.
3. 학술 지표에 의존하지 않고 전문 자격시험 수준의 문항을 전문가 평가단이 채점하는 벤치마크를 마련하여, 모델을 교체하더라도 같은 기준으로 도메인 성능을 비교하도록 한다.

## Ⅶ. 결론

- 핵심 요약 : DSLM은 범용 LLM의 환각과 순수 RAG의 한계를 전문 지식 내재화와 사내 구동으로 함께 보완하는 엔터프라이즈 모델 방향.
- 시사점 : 모델 성능은 전문 데이터의 품질과 평가 체계에 좌우되므로, 데이터 거버넌스 선행이 성과 유지의 전제.
