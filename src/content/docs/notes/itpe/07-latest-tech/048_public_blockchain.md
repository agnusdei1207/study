- **퍼블릭 블록체인(Public Blockchain)** : 공개된 프로토콜로 거래·원장 상태를 검증하고 공유하는 블록체인 네트워크
- **합의(Consensus)** : 네트워크가 유효한 거래 순서·원장 상태를 정하는 절차
- **스마트 계약(Smart Contract)** : 블록체인 실행 환경에서 정해진 조건·규칙을 수행하는 프로그램
- **가스(Gas)** : 일부 블록체인에서 거래·계산의 실행 자원을 측정·비용화하는 단위
- **무허가형(Permissionless)** : 별도 관리자의 사전 허가 없이 공개 규칙에 따라 참여할 수 있는 네트워크 방식

| 목적 | 운영 주체를 하나로 두지 않고 공개 규칙에 따른 검증·기록 지원 |

### Ⅱ. 거래 처리 흐름

```text
사용자 거래 작성·서명
          ↓ 전파

          ↓ 유효 거래 후보

```

### Ⅲ. 참여·합의 구조

| 설계 축 | 검토 질문 |
|---|---|
| 열람 권한 | 원장·거래를 누가 확인할 수 있는가 |
| 거래 제출 | 거래 생성·제출에 어떤 조건이 있는가 |
| 검증자 참여 | 블록 검증 권한을 누가 어떤 기준으로 얻는가 |
| 합의 규칙 | 거래 순서와 상태를 어떻게 확정하는가 |

퍼블릭은 공개 접근·검증을 가리키는 성격이며, 검증자 참여의 허가 여부와 데이터 공개 범위는 구체적 프로토콜별 확인 필요.

### Ⅳ. 적용상 장단점

| 관점 | 기대·고려 |
|---|---|
| 공개 검증 | 공동 참여자의 상태 확인 지원 |
| 운영 구조 | 여러 주체의 검증이 가능하나 거버넌스·업그레이드 책임 필요 |
| 확장·비용 | 합의 방식·부하에 따른 처리량·비용 평가 |
| 정보보호 | 공개 원장에 개인·기밀 원문을 직접 기록하지 않도록 설계 |

### Ⅴ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 공개 원장 사용이 참여·검증 이점보다 기밀·운영 비용을 키울 수 있음 | 검증을 공개해야 하는 업무를 먼저 정하고, 민감 자료는 외부 저장·암호화·최소 기록으로 분리한 뒤 비용·합의 조건을 평가 |
