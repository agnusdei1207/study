<summary>핵심 용어</summary>

- **퍼블릭 블록체인(Public Blockchain)** : 공개된 프로토콜로 거래·원장 상태를 검증하고 공유하는 블록체인 네트워크
- **합의(Consensus)** : 네트워크가 유효한 거래 순서·원장 상태를 정하는 절차
- **스마트 계약(Smart Contract)** : 블록체인 실행 환경에서 정해진 조건·규칙을 수행하는 프로그램
- **가스(Gas)** : 일부 블록체인에서 거래·계산의 실행 자원을 측정·비용화하는 단위
- **무허가형(Permissionless)** : 별도 관리자의 사전 허가 없이 공개 규칙에 따라 참여할 수 있는 네트워크 방식

## 2~4교시 25점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **퍼블릭 블록체인(Public Blockchain)** 은 원장·거래를 공개된 프로토콜로 공동 검증·기록하는 네트워크 |
| 목적 | 운영 주체를 하나로 두지 않고 공개 규칙에 따른 검증·기록 지원 |

### Ⅱ. 거래 처리 흐름

```text
사용자 거래 작성·서명
          ↓ 전파
노드별 형식·상태 검증
          ↓ 유효 거래 후보
합의 절차로 순서·블록 결정
          ↓ 확정 블록 공유
노드 원장·상태 갱신
```

### Ⅲ. 참여·합의 구조

| 설계 축 | 결정할 내용 |
|---|---|
| 열람 권한 | 원장·거래의 열람 주체 |
| 거래 제출 | 거래 생성·제출 조건 |
| 검증자 참여 | 블록 검증 권한의 부여 기준 |
| 합의 규칙 | 거래 순서와 상태의 확정 방식 |

퍼블릭은 공개 접근·검증을 가리키는 성격이며, 검증자 참여의 허가 여부와 데이터 공개 범위는 구체적 프로토콜별 확인 필요.

### Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 공개 원장에 기밀 원문을 기록하면 삭제·접근 제한 곤란 | 민감 자료는 외부 저장·암호화하고 원장에는 최소 검증 정보만 기록 |
| 참여자가 많아 합의 비용·처리 지연 증가 가능 | 목표 부하에서 처리량·거래 비용·확정 시간을 평가 |
| 공개 검증의 이점보다 운영 책임이 불분명 | 네트워크 거버넌스·업그레이드 책임을 참여자 간 합의 |

### Ⅴ. 제언

공개 검증이 필요한 업무부터 식별하고 민감 자료의 원장 외 보관과 거래 비용을 먼저 검증.
