## 연관 키워드

- 퍼블릭 블록체인(Public Blockchain), 비허가형(Permissionless), 합의 알고리즘(Consensus), 머클 트리(Merkle Tree)
- 레이어 2(L2), 롤업(Rollup), 계정 추상화(Account Abstraction), 분산 검증자 기술(DVT)
- 블록체인 트릴레마(Blockchain Trilemma), 모듈러 블록체인(Modular Blockchain), 가스(Gas), 스마트 컨트랙트(Smart Contract)

## Ⅰ. 퍼블릭 블록체인의 개요

- 핵심 요약 : 누구나 허가 없이 참여해 합의로 블록을 검증하고 원장을 공개 열람하는 탈중앙 분산원장.
- 개념 : 중앙 관리자 없이 누구나 노드로 참여해 **합의** (Consensus)로 블록을 확정하고 원장 전체를 열람할 수 있는 비허가형(Permissionless) 분산원장 (**퍼블릭 블록체인** (Public Blockchain)).
- 배경 및 필요성 : 중개기관의 신뢰 비용, 데이터 위변조 위험, 단일 실패점(SPOF, Single Point of Failure), 검열 문제를 줄이려는 요구에서 2008년 비트코인이 등장했고, 이후 이더리움의 **스마트 컨트랙트** (Smart Contract)로 범용 플랫폼이 됨.
- 주요 목적 : 중개자 없는 신뢰(Trustless) 구현, 기록의 불변성 확보, 검열 저항성과 탈중앙 경제 생태계 구축.

## Ⅱ. 퍼블릭 블록체인의 특징 및 장점

- 핵심 요약 : 공개 P2P 네트워크, 해시 체이닝, 경제적 인센티브가 맞물려 중앙 없이도 원장의 신뢰가 유지되는 구조.

1. 공개 P2P 전파 : 트랜잭션을 가십(Gossip) 방식으로 퍼뜨림 → 특정 기관이 거래를 막기 어려워 검열 저항성 확보.
2. **머클 트리** (Merkle Tree) 와 해시 체이닝 : 블록 내 거래를 해시 트리로 묶고 이전 블록 해시로 연결 → 위변조 시 체인 검증이 실패하고, 머클 증명으로 로그 규모의 검증이 가능.
3. 합의 알고리즘 : 지분증명(PoS, Proof of Stake)이나 작업증명(PoW, Proof of Work)으로 정직한 다수 참여자가 단일한 체인을 유지 → 악의적 노드가 섞여도 원장이 갈라지지 않음.
4. 가스(Gas)와 인센티브 : 연산 자원에 비용을 물리고 검증자에게 보상 → 무한 루프와 스팸을 막고 참여를 유도.

## Ⅲ. 퍼블릭 블록체인의 구조 (흐름)

- 핵심 요약 : 트랜잭션이 전파되어 대기열에 모이고, 합의로 블록이 확정되어 상태가 바뀌고 원장에 기록되는 순차 파이프라인.
- 확정된 블록에서 스마트 컨트랙트 바이트코드가 이더리움 가상 머신(EVM, Ethereum Virtual Machine)에서 실행되고, 상태 트리가 갱신됨.

```text
[ 트랜잭션 처리 파이프라인 ]

사용자 트랜잭션 (전자서명)
   ↓ P2P 가십 전파
트랜잭션 풀 (Mempool)
   ↓ 수수료 기준 선별
블록 제안 (검증자·채굴자)
   ↓ 합의와 최종성 확정
상태 전이와 원장 기록
```

```text
[ 모듈러 계층 구조 ]

실행 계층 (L2 롤업)
   ↓ 압축 데이터와 증명 제출
합의·정산 계층 (L1 메인넷)
   ↓ 데이터 가용성 보장
블록체인 보안의 기반
```

## Ⅳ. 레이어 1과 레이어 2의 비교

- 핵심 요약 : L1은 합의와 정산을, L2는 대량 실행을 맡아 역할을 나누는 방식으로 확장성 문제를 완화하는 흐름.
- **블록체인 트릴레마** (Blockchain Trilemma)는 탈중앙성, 보안성, 확장성을 동시에 최대화하기 어렵다는 제약을 가리키며, 이를 피하려고 **모듈러 블록체인** (Modular Blockchain) 구조가 확산되는 중이다.

| 비교 축 | L1 메인넷 (Ethereum, Solana 등) | L2 롤업 (Arbitrum, Optimism 등) |
| --- | --- | --- |
| 핵심 역할 | 합의, 데이터 가용성, 최종 정산 | 대량 트랜잭션 실행과 오프체인 압축 |
| 처리량 | 상대적으로 낮음 | L1 대비 크게 높음 |
| 보안 원천 | 자체 검증자 네트워크 | L1 합의와 암호학적 증명에 위탁 |
| 확장 기술 | 샤딩, 지분증명 최적화 | 낙관적 롤업(사기 증명), 영지식(ZK, Zero Knowledge) 롤업(유효성 증명) |
| 수수료 | 혼잡 시 상승 | L1 대비 낮은 편 |

## Ⅴ. 퍼블릭 블록체인의 한계와 방안

- 핵심 요약 : 처리량과 프라이버시, 검증 권한 집중의 문제를 롤업, 계정 추상화, 분산 검증으로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 낮은 처리량과 긴 확정 시간 | 기본 계층의 처리량이 제한되어 대량 결제에 부적합 | 영지식 롤업 기반 L2 확장, EIP(Ethereum Improvement Proposal)-4844 블롭 데이터로 L2 데이터 비용 절감 | 평균 처리량, 최종 확정 시간 |
| 전면 공개로 인한 프라이버시 침해 | 잔고와 계약 상호작용이 공개되어 기업 급여와 대금 결제에 부적합 | 영지식 증명 기반 프라이빗 트랜잭션과 계정 추상화(ERC-4337) 결합 | 기밀 거래 비중 |
| 검증 권한의 집중 | 대형 스테이킹 풀에 검증 권한이 쏠려 탈중앙성 약화 | 분산 검증자 기술(DVT, Distributed Validator Technology)과 스테이킹 분산 인센티브 | 상위 검증 권한 점유율 |

## Ⅵ. 퍼블릭 블록체인에 대한 기술사적 제언

- 핵심 요약 : 실행은 L2, 정산과 보안은 L1에 두는 모듈러 구조를 기본으로 하고, 계정 추상화로 사용자 경험을 개선하는 방향.

1. 합의, 데이터 가용성, 실행 계층을 분리하는 모듈러 설계를 채택해 상호운용성과 확장성을 함께 확보하는 것이 바람직하다.
2. 계정 추상화를 적용해 시드 문구 대신 소셜 로그인과 수수료 대납을 지원하는 지갑 체계를 표준으로 삼는 것이 좋다.
3. 부동산과 채권 같은 실물자산을 토큰화하려는 기관은 증권형 토큰(STO, Security Token Offering) 요건을 갖춘 인프라를 공공 L2 위에 설계하는 방안을 검토해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 퍼블릭 블록체인은 중개자 없는 신뢰를 만드는 기반 기술.
- 실사용의 성패는 확장성과 프라이버시를 얼마나 해결하느냐에 달려 있으며, 그 해법은 계층 분리와 암호학적 증명으로 모이고 있음.
