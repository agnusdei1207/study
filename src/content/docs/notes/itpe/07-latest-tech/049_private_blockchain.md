## 30초 인출

프라이빗 블록체인은 참여자와 거래 권한을 운영 정책으로 제한하는 분산 원장이다. 기관들은 신원·검증 규칙·운영 책임을 합의해 공유 기록을 갱신한다.

<details>
<summary>핵심 용어</summary>

- **프라이빗 블록체인(Private Blockchain)**: 참여자와 원장 작업을 허가 정책으로 제한하는 블록체인 네트워크.
- **허가형 네트워크(Permissioned Network)**: 검증된 신원과 역할에 따라 가입·작업 권한을 관리하는 네트워크.
- **MSP(Membership Service Provider)**: Hyperledger Fabric에서 조직 신원과 인증서를 네트워크 정책에 연결하는 구성.
- **채널(Channel)**: Fabric에서 지정된 조직들이 공유하는 독립 원장과 통신 경계.
- **체인코드(Chaincode)**: Fabric의 업무 규칙을 실행하는 스마트 계약 프로그램.
- **순서화 서비스(Ordering Service)**: Fabric 거래를 순서에 따라 블록으로 묶어 채널 피어에 배포하는 서비스.

</details>

## 2~4교시 25점 답안

### Ⅰ. 프라이빗 블록체인의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **프라이빗 블록체인(Private Blockchain)**은 허가된 참여자와 정책에 따라 원장을 갱신하는 분산 원장 네트워크 |
| 목적 | 여러 기관이 공유 기록을 공동 검증하면서 참여·데이터 접근을 통제하는 기반 |

### Ⅱ. 네트워크 구성과 권한

```text
참여 조직
   │ 신원·역할 등록
   ▼
허가 정책 ── 참여·거래 권한 결정
   │ 승인된 거래
   ▼
공유 원장 ── 합의된 기록 유지
```

| 구성 | 역할 |
|---|---|
| MSP | 조직·사용자 인증 정보를 네트워크 정책과 연결 |
| 피어(Peer) | 거래 제안 실행, 보증, 원장 사본 유지 |
| 채널(Channel) | 지정 조직 간 독립적인 원장 공유 경계 |
| 체인코드(Chaincode) | 거래에 적용할 업무 규칙 실행 |
| 순서화 서비스 | 보증된 거래를 순서화해 블록으로 배포 |

```text
조직 신원 ── MSP·인증서 ── 역할·정책
                          │ 허가된 조직만 채널 참여
                          ▼
                    채널별 원장 공유
```

채널은 원장 공유 범위를 나누는 기능이며, 채널 참여자 사이의 세부 데이터 비밀성은 프라이빗 데이터 기능·정책 등으로 별도 구성.

### Ⅲ. 거래 처리

```text
클라이언트 제안
      │ 보증 정책에 지정된 피어가 실행·서명
      ▼
보증 응답 수집
      │ 순서화 서비스가 거래 순서 결정
      ▼
블록 배포
      │ 피어가 검증 후 유효 거래를 원장에 반영
      ▼
채널 원장 갱신
```

```text
검증 기준       피어 검증 내용
보증 정책   ──  필요한 조직의 보증 충족 여부
거래 순서   ──  블록 내 순서와 중복 반영 여부
상태 조건   ──  실행 시점의 읽기 집합 유효성
```

보증 정책에 따른 실행과 순서화, 피어의 최종 검증은 서로 다른 처리 단계. 정책·구성에 따라 필요한 보증 조직과 합의 방식이 달라짐.

### Ⅳ. 도입 판단과 기술적 제언

| 한계 | 해결 방안 |
|---|---|
| 다자간 원장이 필요한지 검토하지 않으면 기존 데이터베이스보다 운영 복잡도만 커질 가능성 | 단일 DB와 비교해 공동 검증·변경 이력의 실익을 확인하고, 참여·장애·키 관리 책임에 합의한 업무부터 적용 |
| 접근 통제를 익명성·기밀성의 자동 보장으로 오해할 우려 | 채널 경계, 프라이빗 데이터 범위, 암호화·보존·삭제 정책을 위협 모델과 함께 검증 |
