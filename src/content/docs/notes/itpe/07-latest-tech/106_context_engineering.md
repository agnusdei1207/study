## 연관 키워드

- 컨텍스트 엔지니어링(Context Engineering), 컨텍스트 윈도우(Context Window), 프롬프트 엔지니어링(Prompt Engineering)
- RAG(Retrieval-Augmented Generation), 프롬프트 캐싱(Prompt Caching), KV 캐싱(Key-Value Caching), TTFT(Time to First Token)
- Lost in the Middle, 프롬프트 압축(Prompt Compression), LLMLingua, 환각(Hallucination), PII 마스킹

## Ⅰ. 컨텍스트 엔지니어링의 개요

- 핵심 요약 : 모델에 들어가는 지침, 검색 문서, 대화 기록, 도구 결과를 선별, 압축, 배치하여 비용과 정확도를 함께 관리하는 체계.
- 개념 : **LLM**(Large Language Model)에 주입되는 시스템 지침, 검색 지식, 대화 메모리, 도구 호출 결과를 모델의 주의 집중 특성에 맞추어 동적으로 수집, 선별, 구조화, 압축, 배치하는 **컨텍스트 엔지니어링**(Context Engineering).
- 배경 및 필요성 : 컨텍스트 윈도우를 무작정 늘리면 토큰 비용이 커지고, 긴 입력의 중간에 놓인 정보를 모델이 놓치는 현상이 나타난다. 그래서 고정 부분의 캐싱 계층화와, 핵심 근거의 배치 순서를 설계하는 절차가 필요하다.
- 주요 목적 : 토큰 비용 낭비를 줄이고, 응답 지연을 낮추며, 핵심 근거 누락으로 생기는 환각을 줄이는 것.

## Ⅱ. 컨텍스트 엔지니어링의 특징 및 장점

- 핵심 요약 : 입력을 고정 부분과 가변 부분으로 나누어 캐싱과 배치를 설계하면, 비용과 지연, 정확도를 동시에 개선하는 구조.

1. 고정 프리픽스 캐싱 : 불변 지침과 참조 문서를 앞부분에 고정 → 캐시 적중 시 비용 절감과 첫 토큰 응답 단축.
2. 근거 재배치 : 검색된 근거 중 핵심을 입력의 앞뒤 끝에 두는 배치 → 중간 정보 망각 현상 완화.
3. 선별과 압축 : 민감 정보를 마스킹하고 중복 토큰을 줄임 → 불필요한 입력 비용과 개인정보 노출 감소.

```text
[ 입력의 고정·가변 구분 ]

고정 프리픽스 (캐시 가능)
  시스템 지침 + 정적 참조 문서
      ↓
가변 중간부
  대화 기록, 보조 컨텍스트
      ↓
가변 꼬리부
  핵심 근거 + 최종 질문
```

## Ⅲ. 컨텍스트 엔지니어링의 구조 (흐름)

- 핵심 요약 : 질의 분석 후 외부 지식을 수집하고, 정제와 압축을 거쳐, 주의 집중에 맞게 배치한 뒤 모델에 전송하는 흐름.
- **프롬프트 캐싱**(Prompt Caching) : 입력 앞부분이 이전 요청과 같으면 계산 결과를 재사용하는 기능. 고정 템플릿과 정적 코퍼스를 앞에 둘수록 적중률이 높아진다.
- **Lost in the Middle** : 긴 입력에서 가운데 위치한 정보의 활용률이 떨어지는 현상.

```text
[ 사용자 질의 ]
      ↓
문맥 수집 (지침 + 메모리 + RAG 문서)
      ↓
문맥 정제 (PII 마스킹, 토큰 압축)
      ↓
배치 (고정 프리픽스 → 중간 → 핵심 근거 + 질문)
      ↓
LLM 추론 (캐시 적중 시 빠른 첫 토큰)
```

## Ⅳ. 프롬프트 엔지니어링, RAG와 컨텍스트 엔지니어링의 비교

- 핵심 요약 : 프롬프트 엔지니어링은 문구를 다루고, 단순 RAG는 검색 결과를 붙이며, 컨텍스트 엔지니어링은 전체 입력의 선별과 비용, 배치를 다룬다.

| 비교 항목 | 프롬프트 엔지니어링 | 단순 RAG | 컨텍스트 엔지니어링 |
| --- | --- | --- | --- |
| 주요 초점 | 질문 문구, 어조, 예시 작성 | 벡터 DB 문서 검색과 주입 | 입력 전체의 선별, 압축, 배치, 캐싱 |
| 접근 방식 | 정적 프롬프트 템플릿 | 상위 k개 청크 결합 주입 | 주의 분산과 비용을 고려한 동적 조립 |
| 처리 토큰 규모 | 수백에서 수천 토큰 | 수천에서 수만 토큰 | 긴 입력의 정밀 제어 |
| Lost in the Middle | 고려 대상 아님 | 순위대로 주입하여 노출 | 배치 순서를 설계하여 완화 |

- 선택 기준 : 입력이 짧고 단순하면 프롬프트 엔지니어링, 외부 지식이 필요하면 RAG, 긴 입력과 반복 호출이 많으면 컨텍스트 엔지니어링을 적용한다.

## Ⅴ. 컨텍스트 엔지니어링의 한계와 방안

- 핵심 요약 : 중간 정보 누락, 반복 입력 비용, 압축에 따른 의미 왜곡을 근거 재배치, 캐시 구조 설계, 보호 구간 지정으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 초장문 입력 중간의 결정적 정보 간과 | 가운데 위치 정보의 활용 저하 → 답변 누락 | 재정렬 후 가장 관련성 높은 문서를 입력 앞과 질문 직전에 배치 | 핵심 근거 활용률 |
| 매 호출마다 긴 문맥 전송에 따른 비용과 지연 | 반복 전송 → 토큰 비용 증가와 첫 토큰 지연 | 고정 템플릿과 정적 코퍼스를 앞에 두어 캐시 적중률 유지 | 캐시 적중률, TTFT |
| 압축 과정의 수치·부정어 누락 | 축약 중 수치나 부정어가 빠짐 → 의미 왜곡 | 압축률 보수적 설정, 수치와 코드 블록은 압축 제외 보호 태그 적용 | 수치 보존 검증 통과율 |

## Ⅵ. 컨텍스트 엔지니어링에 대한 기술사적 제언

- 핵심 요약 : 입력을 자원으로 보고 비용, 지연, 정확도를 함께 측정하여 관리하는 운영 체계를 세우는 방향.

1. 플랫폼 조직이 턴당 토큰 비용과 캐시 적중률을 함께 보는 지표를 정하고, 대화가 길어질 때의 메모리 정책을 표준화한다.
2. 서비스 개발 조직이 고정 지침과 정적 문서를 캐시 가능한 앞부분에 모으는 입력 템플릿을 설계하여 지연 시간을 관리한다.
3. 품질 조직이 압축 전후의 수치와 부정 표현을 자동 검증하는 시험 세트를 운영하여 압축에 따른 의미 왜곡을 점검한다.

## Ⅶ. 결론

- 핵심 요약 : 컨텍스트 엔지니어링은 모델에 무엇을 얼마나, 어떤 순서로 넣을지 설계하는 입력 설계 체계.
- 시사점 : 컨텍스트 윈도우가 커져도 선별과 배치가 정확도를 좌우하므로, 모델 성능과 함께 입력 구성 절차가 운영 역량으로 관리되어야 한다.
