## 연관 키워드

- 복합 AI(Composite AI), 딥러닝, 지식 그래프(Knowledge Graph), 온톨로지(Ontology), 룰 엔진(Rule Engine)
- 혼합정수계획법(MILP, Mixed-Integer Linear Programming), 수리 최적화, 심볼릭 추론, 환각(Hallucination)
- 캐스케이딩 에러, HITL(Human in the Loop), BRMS(Business Rules Management System), GitOps

## Ⅰ. 복합 AI (Composite AI)의 개요

- 핵심 요약 : 딥러닝, 지식 그래프, 룰 엔진, 수리 최적화를 하나의 파이프라인으로 묶어 설명 가능하고 제약을 지키는 판단을 만드는 융합 아키텍처.
- 개념 : 단일 신경망에 의존하지 않고, 패턴 인식(딥러닝), 상관관계 추론(**지식 그래프** (Knowledge Graph)), 명시적 규범(**룰 엔진** (Rule Engine)), 자원 배분(수리 최적화)을 오케스트레이션하는 융합 아키텍처.
- 배경 및 필요성 : 모듈을 이어 붙이면 앞 단계의 오류가 뒤 단계로 증폭되는 **캐스케이딩 에러** (Cascading Error)가 생긴다. 그래서 모듈 경계마다 신뢰도를 점검하고, 기준에 못 미치면 다른 경로나 사람에게 넘기는 게이트 구조가 필요하다.
- 주요 목적 : 딥러닝의 **환각** (Hallucination)과 블랙박스 문제를 줄이고, 학습 데이터가 적어도 업무 규칙을 지키며, 근거를 설명할 수 있는 최적 판단을 얻는 것.

## Ⅱ. 복합 AI (Composite AI)의 특징 및 장점

- 핵심 요약 : 계층마다 맡는 기술이 달라 인식의 유연성과 규칙의 엄격성이 함께 확보되는 구조.

1. 인식 계층 : 비정형 텍스트와 영상에서 설비 상태 같은 속성을 추출 → 사람이 읽기 어려운 입력을 구조화.
2. 추론 계층 : 온톨로지로 개체 간 의존 관계를 연역적으로 연결 → 설명 가능한 연쇄 판단 제공.
3. 규범 계층 : 법정 근로시간과 안전 기준을 하드 제약으로 검증 → 규정 위반 해가 처음부터 제외됨.
4. 최적화 계층 : 제약 아래 비용과 손실을 수리적으로 최소화 → 근거가 있는 실행안 도출.

## Ⅲ. 복합 AI (Composite AI)의 구조 (흐름)

- 핵심 요약 : 인식, 추론, 규범 검증, 최적화가 순차로 이어지며 각 단계가 앞 단계의 출력을 제약으로 받는 흐름.

```text
[ 복합 AI 인식-추론-최적화 흐름 ]

비정형 입력 (센서, 문서, 예보)
        ↓
신경망 기반 패턴 인식
        ↓
지식 그래프와 온톨로지 추론
        ↓
룰 엔진의 제약 조건 검증
        ↓
수리 최적화 (MILP 등)
        ↓
실행 처방 산출
```

```text
[ 계층별 역할 분리 ]

인식 계층  : 무엇이 일어났는가
추론 계층  : 무엇과 연결되는가
규범 계층  : 무엇이 허용되는가
최적화 계층: 무엇을 하는 것이 최선인가
```

- **혼합정수계획법** (MILP, Mixed-Integer Linear Programming) : 정수 변수와 선형 제약을 함께 두고 목적 함수를 최소화하는 수리 최적화 기법.
- **온톨로지** (Ontology) : 개체와 관계를 정의한 도메인 지식 체계로, OWL 같은 표현 언어로 기술한다.
- **비즈니스 룰 관리 시스템** (BRMS, Business Rules Management System) : 규칙을 별도로 관리하고 실행하는 체계.

## Ⅳ. 단일 딥러닝, 앙상블, 복합 AI의 비교

- 핵심 요약 : 확률 기반 모델을 아무리 결합해도 제약 보장은 어렵고, 규칙과 최적화를 결합해야 제약 준수와 설명이 가능.

| 비교 축 | 단일 딥러닝 (End-to-End) | 앙상블 (Ensemble) | 복합 AI (Composite AI) |
| --- | --- | --- | --- |
| 결합 대상 | 단일 신경망 | 동일 목적의 다수 모델 | 딥러닝, 그래프, 규칙, 최적화 |
| 설명 가능성 | 낮음 (블랙박스) | 낮음 (결과 투표) | 높음 (규칙과 제약식 근거) |
| 제약 조건 준수 | 보장 어려움 | 보장 어려움 | 하드 제약으로 보장 |
| 데이터 요구량 | 대규모 필요 | 대규모 필요 | 규칙과 지식으로 보완해 상대적으로 적음 |
| 연산 특성 | GPU 중심 병렬 연산 | 다수 모델 연산 | GPU(추론)와 CPU(그래프·최적화) 혼합 |

- 선택 기준 : 규칙 위반이 허용되지 않는 업무일수록 복합 구조를, 예측 정확도만 중요하면 단일 모델이나 앙상블을 택한다.

## Ⅴ. 복합 AI (Composite AI)의 한계와 방안

- 핵심 요약 : 캐스케이딩 오류, 이종 시스템 통신 부담, 규칙 변경 충돌을 신뢰도 게이트, 공통 데이터 계층, 규칙 버전 관리로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 캐스케이딩 에러 | 앞 단계의 오분류가 뒤 단계의 해를 훼손 | 모듈 간 신뢰도 임계치 설정, 불확실하면 **HITL** (Human in the Loop) 에스컬레이션 | 임계치 미달 비율 |
| 이종 컴포넌트 간 데이터 형식 차이 | 런타임 통신과 변환 오버헤드 발생 | 공통 인메모리 데이터 계층과 gRPC 기반 서비스 분리 | 호출 지연 시간 |
| 현업 규칙 변경에 따른 충돌 | 지식 그래프와 룰 엔진의 규칙이 어긋나 교착 발생 | 규칙의 버전 관리(GitOps)와 자동 일관성 검증기 | 규칙 충돌 건수 |

## Ⅵ. 복합 AI (Composite AI)에 대한 기술사적 제언

- 핵심 요약 : 생성 모델이 계산과 규정을 직접 떠맡지 않도록 역할을 나누고, 그 경계를 조직의 설계 원칙으로 세우는 방향.
- 기업은 정확한 수치 계산과 규정 준수를 최적화 솔버와 규칙 엔진에 맡기고, 언어 모델은 입력 해석과 설명 생성에 집중하도록 아키텍처를 정해야 한다.
- 현장 규정은 프롬프트에 기대지 않고 규칙 엔진에 명시해, 규정 변경이 코드 배포 수준의 통제 절차를 거치게 해야 한다.
- 추론 경로와 제약식을 감사 기록으로 남기는 체계를 갖춰야, 결정의 근거를 사후에 검증할 수 있다.

## Ⅶ. 결론

- 핵심 요약 : 복합 AI는 학습된 패턴과 명시된 규범, 수학적 최적화를 결합해 설명 가능한 판단을 만드는 구조임.
- 업무 규칙과 법규가 엄격한 영역에서 복합 구조가 실용적 가치를 가장 크게 가진다.
