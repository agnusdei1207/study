## 30초 인출
- **본질:** 오픈뱅킹은 이용자 동의를 바탕으로 금융기관 기능을 표준 API로 연계하는 금융 인프라.
- **메커니즘:** 핀테크·금융회사 응용이 권한과 계좌 등록 절차에 따라 중계 API를 호출하고 제공기관이 업무를 처리.
- **핵심 통제:** 동의·권한·토큰·거래기록과 이용기관 보안 관리.

<details><summary>핵심 용어</summary>

- **오픈뱅킹(Open Banking):** 금융기관 기능을 표준 API로 제공해 허용된 이용기관이 금융서비스를 구성하도록 지원하는 인프라.
- **API(Application Programming Interface):** 응용프로그램이 다른 시스템의 기능·데이터를 정해진 방식으로 요청하는 접점.
- **금융결제원(Korea Financial Telecommunications and Clearings Institute, KFTC):** 국내 오픈뱅킹 공동업무와 API 포털 등 금융 공동 인프라를 운영하는 기관.
- **Access Token(접근 토큰):** 등록·동의된 범위에서 보호된 API를 호출할 때 사용하는 권한 증표.
- **스크래핑(Screen Scraping):** 화면·웹페이지를 읽어 데이터를 추출하는 방식으로, API 연계와 다른 기술 방식.
- **FDS(Fraud Detection System, 이상금융거래탐지시스템):** 거래 행태를 분석해 의심 거래를 찾는 금융 보안 체계.

</details>

## Ⅱ. 참여자와 처리 흐름
```text
이용자 동의·계좌 등록
          |
          v
이용기관의 권한 있는 API 요청

          v
금융결제원 공동 중계 인프라
```

이용기관은 허용된 요청으로 조회·이체 기능을 구성하며, 공동 인프라는 이용기관 요청과 제공기관 처리를 연결. 실제 대상 API와 적용 조건은 최신 금융결제원 개발자 문서에서 확인.

## Ⅲ. API 기능 범위
| 기능 유형 | 처리 예 | 주요 확인 |
|---|---|---|
| 조회 | 계좌 잔액·거래 내역 확인 | 등록 계좌, 이용자 권한, 요청 범위 |
| 계좌 확인 | 계좌 정보·수취 가능 여부 확인 | 목적에 필요한 항목과 동의 |
| 이체 | 출금·입금 요청 | 이용자 인증, 거래 한도, 중복·오류 처리 |
| 기타 공동 기능 | 포털이 제공하는 서비스별 API | 지원 API·이용 자격·약관 버전 |

## Ⅴ. 도입·운영 고려사항
| 항목 | 점검 방향 |
|---|---|
| API 변화 | 버전·약관 변경을 추적하고 호환성 시험 |
| 개인정보 | 이용 목적에 필요한 최소 데이터와 보유 기간 적용 |
| 연계 장애 | 타임아웃·재시도·중복 처리 방지·복구 절차 |
| 이용기관 관리 | 보안성·개인정보 처리·하위 수탁자 관리 |

오픈뱅킹은 금융서비스 연계 인프라로, 계좌 정보와 자금 이동의 보안을 자동 보장하지 않음. 이용기관·중계 인프라·제공기관의 각 통제와 이용자 보호 절차 필요.

## Ⅵ. 기술사적 제언
| 한계 | 해결 방안 |
|---|---|
| 서비스가 여러 금융기관 API에 의존하면 각 기관 변경·장애가 이용자 거래에 영향을 줄 수 있음 | 기관별 API 어댑터와 공통 오류 처리 기준을 두고, 변경 시험·장애 알림·거래 대사·복구 절차를 함께 운영 |
