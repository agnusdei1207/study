## 답안 골격
```text
[오픈뱅킹] ◀━━ 머리: Ⅶ 내 의견 (표준 오픈 API와 금융결제원 공동 중계망을 통해 은행 폐쇄망을 개방하고 핀테크 혁신을 촉진하는 금융 플랫폼 인프라)
 ┃
 ┣━ Ⅰ 개요 ───── 개별 은행의 독점적 폐쇄망 운영에 따른 핀테크 혁신 지연 및 스크래핑 보안 위협 → 은행 결제·조회 기능을 표준 API로 개방하는 오픈뱅킹 태동
 ┣━ Ⅱ 특징 ───── 표준 오픈 API(RESTful) · 금융결제원 중앙 중계망 구축 · 계좌 조회 및 이체 기능 단일화 · 저렴한 수수료 체계
 ┣━ Ⅲ 구조 ───── 참가 기관(은행, 핀테크, 증권사) + 금융결제원 오픈뱅킹 공동업무 중계센터 + 보안/인증 계층(OAuth 2.0) + 금융보안원 FDS
 ┣━ Ⅳ 흐름 ───── ① 핀테크 앱에서 계좌 등록 요청 → ② 사용자 본인 확인 및 계좌 점유 인증 → ③ OAuth 2.0 인가 코드 및 접근 토큰(Access Token) 발급 → ④ 금결원 중계센터 API 호출 → ⑤ 참가 은행 코어 뱅킹 처리 및 결과 반환
 ┣━ Ⅴ 비교 ───── 스크래핑(Scraping) 방식 vs 개별 은행 제휴 API vs 오픈뱅킹 공동망 (비표준/화면파싱/보안취약 vs 개별계약/고비용 vs 단일표준/저비용/안전한토큰)
 ┗━ Ⅵ 실무 ───── 핀테크 보안 사고 발생 시 연대 책임 및 2차 피해 / 계좌 탈취(ATO)를 통한 부정 이체 / 대용량 트래픽 집중에 따른 중계망 병목
```
- 필수 키워드: 오픈뱅킹(Open Banking) · 오픈 API · 금융결제원 · OAuth 2.0 · 계좌 조회 · 출금이체 · FDS(이상금융거래탐지) · 스크래핑 대체
- 기출: 120회 `오픈뱅킹` → Ⅰ~Ⅴ

## 한 줄 본질
- 하나의 은행 앱에서 다른 모든 은행의 통장 잔고를 확인하고 송금할 수 있도록, 금융결제원이 중앙에서 표준 API 중계망을 깔아 모든 금융기관과 핀테크에게 문을 열어준 개방형 금융 고속도로 / 핀테크 해킹 시 연쇄 피해 위험

## 핵심 용어
- 출금이체 API: 이용자의 동의를 얻은 핀테크 기업이 금융결제원을 거쳐 이용자의 특정 은행 계좌에서 자금을 출금하여 핀테크 선불충전금이나 지정 계좌로 이체하는 핵심 API
- 스크래핑(Screen Scraping): 오픈뱅킹 도입 전, 핀테크 앱이 이용자의 공인인증서 비밀번호를 넘겨받아 은행 인터넷뱅킹 화면에 가상 접속한 뒤 HTML 텍스트를 긁어오던 비표준·보안 취약 방식
- FDS(Fraud Detection System): 오픈뱅킹 API를 통한 다수의 계좌 동시 이체나 심야 시간 이상 출금 패턴을 인공지능 규칙으로 실시간 탐지하여 차단하는 보안 시스템

## 핵심 통찰
- "화면 긁어오기(Scraping)에서 정규 고속도로(API)로의 문명화": 스크래핑은 은행 화면 UI가 1글자만 바뀌어도 장애가 났고 개인 인증서 정보가 탈취될 위험이 컸으나, 오픈뱅킹 API 도입으로 보안성과 전송 속도가 100배 향상됨
- 수수료 10분의 1 파격 인하: 기존 펌뱅킹 출금이체 수수료(건당 400~500원)를 10분의 1 수준(건당 30~50원)으로 인하시켜 핀테크 기업의 원가 부담을 없애고 '평생 무료 송금' 시대를 염
- 은행의 플랫폼화(BaaS) 가속: 단순히 통장 계좌를 보관하던 은행이 이제는 서비스형 뱅킹(Banking-as-a-Service) 인프라 제공자로 재정의되었으며, 마이데이터와 결합하여 초개인화 자산관리 생태계로 확장됨

## 이웃 토픽과 구분
- 오픈뱅킹 vs 마이데이터(MyData): 오픈뱅킹은 '계좌 조회 및 이체 결제'를 위한 거래 지향 서비스 / 마이데이터는 신용정보법에 근거하여 금융, 통신, 전자상거래 전반의 '본인 정보 전송요구권'을 행사하는 데이터 분석 지향 서비스

## 문제·원인·대책
- 적용 상황: 오픈뱅킹 API를 연동한 간편결제 서비스에서 계좌 탈취(ATO) 부정 송금 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 피싱으로 탈취된 스마트폰에서 오픈뱅킹을 통해 타 은행 예금까지 일괄 털려나가는 연쇄 피해 | 계좌 개설 은행과 오픈뱅킹 이용 앱 간의 단말 이상 징후 정보 미공유 | 금융결제원 중앙 집중형 오픈뱅킹 공동 FDS 구축 및 이상 탐지 시 실시간 동시 차단 | 연쇄 부정 이체 사고 90% 예방 |
| 대규모 트래픽 이벤트(월급날, 타임세일) 시 금결원 중계 게이트웨이 지연 발생 | 특정 시간대 API 호출 집중에 따른 큐 적체 | 비동기 메시징 큐(Kafka) 분산 처리 및 참가 기관별 서킷 브레이커 도입 | 트래픽 피크 시 99.99% 가용성 유지 |
| 보안 점검 역량이 취약한 영세 핀테크사를 통한 은행 계좌 번호 대량 유출 | 서드파티 핀테크 내부 DB 암호화 미흡 | 금융보안원의 보안성 심사 의무화 및 실제 계좌번호 대신 일회용 가상 토큰 사용 강제 | 원천 계좌 정보 유출 원천 차단 |

## 이렇게 출제된다
- 제120회 1교시: "금융 오픈 플랫폼의 핵심인 오픈뱅킹(Open Banking)의 개념, 시스템 구성도, 주요 제공 API 및 기존 스크래핑 방식 대비 개선점을 설명하시오." → 요구 포인트: Ⅰ 폐쇄망 한계 + Ⅲ 금결원 중계 아키텍처 및 5대 API + Ⅴ 스크래핑 vs API 비교

## 내 의견
- [오픈뱅킹과 탈중앙화 신원인증(DID)의 결합을 통한 무인증 계좌 점유 검증 체계 도입] 현재의 오픈뱅킹 최초 등록 시 요구되는 1원 계좌 인증이나 SMS 문자인증은 심스왑(SIM Swap)이나 스미싱 공격에 뚫리기 쉬움 → 나라면: W3C 표준 기반의 분산신원증명(DID)과 생체 FIDO를 결합하여, 사용자의 스마트폰 보안 영역(SE)에 보관된 서명키로 오픈뱅킹 계좌 연동을 암호학적으로 인가하는 'Passwordless Open Banking' 아키텍처를 도입하여 피싱으로 인한 계좌 탈취 원천 봉쇄
