## 30초 인출
- 본질: 핀테크 기업 및 은행이 금융결제원의 오픈 API를 통해 모든 은행의 자금 결제 및 조회 기능을 단일 접점으로 통합 제공하는 금융 공동 결제망 인프라
- 메커니즘: 이용자 권한 위임(OAuth 2.0) → 토큰 발급 → 이용기관 API 호출 → 금융결제원 오픈뱅킹 중계망 라우팅 → 참가 금융기관 원장 처리 및 결과 반환
- 통찰: 다수 금융기관 분산 트랜잭션 의존으로 인한 단일 장애점(SPOF) 및 비인가 API 탈취 위험이 상존하므로 제로 트러스트 API 게이트웨이와 24/7 실시간 거래 대사 및 이상거래탐지(FDS) 연계 체계 필수

<details><summary>핵심 용어</summary>

- **오픈뱅킹(Open Banking):** 핀테크 기업과 은행이 개별 제휴 없이 표준화된 오픈 API를 통해 금융 서비스를 개발·제공할 수 있도록 개방한 공동 금융 인프라
- **OAuth 2.0:** 이용자 금융 계좌 접근 권한을 비밀번호 노출 없이 안전하게 이용기관에 위임하는 개방형 표준 인증·인가 프로토콜
- **금융결제원(KFTC):** 오픈뱅킹 중계 시스템 및 오픈 API 통합포털을 구축·운영하는 지급결제 전문 청산 기관
- **화면 스크래핑(Screen Scraping):** 웹페이지 화면 데이터를 비정형 파싱하여 추출하던 과거 방식으로, 트래픽 유발 및 보안 취약점으로 인해 표준 API 방식으로 전면 전환
- **FDS(Fraud Detection System):** 오픈뱅킹 API 호출 패턴과 단말 정보를 실시간 분석하여 이상 금융 거래를 차단하는 지능형 탐지 시스템

</details>

## 2~4교시 25점 답안

## Ⅰ. 오픈뱅킹의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 은행과 핀테크 기업이 개별 연동 없이 단일 표준 API로 모든 참가 금융기관의 결제·조회 기능을 활용하도록 지원하는 금융 공동 인프라 |
| 목적 | 금융 결제망 독점 해소, 금융 혁신 서비스 출시 기간 단축, 스크래핑 탈피를 통한 개인정보 보호 및 시스템 안정성 확보 |

## Ⅱ. 오픈뱅킹의 핵심 특징

| 특징 영역 | 주요 특성 | 기술적 구현 내용 |
|---|---|---|
| **상호 개방성** | 은행-핀테크 간 양방향 인프라 개방 | 모든 은행과 허가된 핀테크 기업이 동일한 조건으로 계좌 조회 및 이체 망 이용 |
| **표준 인터페이스** | RESTful JSON 기반 표준 API | 금융결제원 표준 규격에 따라 규격화된 메시지 전송 및 단일 연동 개발 환경 제공 |
| **안전한 권한 위임** | OAuth 2.0 기반 토큰 제어 | 공인인증서나 비밀번호 직접 저장 배제, 명시적 스코프(Scope)별 접근 토큰(Access Token) 발급 |
| **비용 절감 및 확장** | 펌뱅킹 대비 망 이용 수수료 대폭 절감 | 기존 펌뱅킹 대비 약 1/10 수준 수수료 체계 및 단일 게이트웨이 연계로 확장 비용 절감 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **단일 장애점(SPOF) 위험**<br />모든 트랜잭션이 금융결제원 중계 인프라를 경유하므로 허브 장애 시 전 금융권 연계 마비 | Active-Active 멀티 리전 클라우드 중계망 구축, 기관 간 서킷 브레이커(Circuit Breaker) 및 대체 경로 자동 폴백(Failover) 구현 |
| **비인가 API 악용 및 부정 이체**<br />탈취된 Access Token 또는 핀테크 앱 위변조를 통한 대규모 무단 출금 위험 상존 | mTLS(상호 TLS) 강제, 디바이스 핑거프린팅, API 이상 트래픽 실시간 FDS 차단 및 이상 거래 실시간 지급정지 공조망 가동 |
| **이용기관과 은행 간 분쟁 책임 모호**<br />이체 트랜잭션 오류 및 지연 발생 시 사고 발생 주체 규명 곤란 | 분산 트레이싱(OpenTelemetry 기반 고유 추적 ID 부여), 블록체인 기반 거래 이력 불변 저장 및 표준 분쟁 처리 가이드라인 제정 |

## Ⅵ. 제언

오픈뱅킹은 단순한 조회·이체 API 개방을 넘어 마이데이터 및 BaaS(Banking as a Service)와의 결합을 통해 지능형 임베디드 파이낸스로의 진화 필수.

```text
[오픈뱅킹] (지급결제/조회) + [마이데이터] (초개인화 자산관리) + [BaaS] (비금융 융합)
                              │
                              ▼
        [실시간 제로 트러스트 보안 + 지능형 FDS 통제 플랫폼]
```

| 진화 단계 | 오픈뱅킹 1.0 (공동망 개방) | 오픈뱅킹 2.0 (상호 개방 및 BaaS) |
|---|---|---|
| **인프라 초점** | 1금융권 중심 표준 API 조회/이체 | 2금융권 포함 전 금융권 상호 개방 및 클라우드 BaaS |
| **보안 통제** | 정적 OAuth 2.0 토큰 및 개별 FDS | FAPI(Financial-grade API) 보안 규격 및 실시간 AI FDS |
| **비즈니스 모델** | 단순 송금 수수료 절감 및 잔액 모아보기 | 비금융 플랫폼 결합 임베디드 금융 및 초개인화 여신 추천 |
