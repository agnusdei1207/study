## Ⅰ. 오픈뱅킹(Open Banking)의 개요

- **개념** : 은행과 핀테크 기업이 개별 연동 없이 단일 표준 API로 모든 참가 금융기관의 결제·조회 기능을 활용하도록 지원하는 금융 공동 인프라.
- **배경 및 필요성** : 다수 금융기관 분산 트랜잭션 의존으로 인한 단일 장애점(SPOF) 및 비인가 API 탈취 위험이 상존하므로 제로 트러스트 API 게이트웨이와 24/7 실시간 거래 대사 및 이상거래탐지(FDS) 연계 체계 필수.
- **핵심 목적** : 금융 결제망 독점 해소, 금융 혁신 서비스 출시 기간 단축, 스크래핑 탈피를 통한 개인정보 보호 및 시스템 안정성 확보.

## Ⅱ. 오픈뱅킹(Open Banking)의 핵심 아키텍처 및 동작 메커니즘

오픈뱅킹은 신뢰할 수 있는 데이터 파이프라인과 고도화된 추론 메커니즘을 기반으로 동작하며, 세부적인 아키텍처와 핵심 컴포넌트 간 상호작용 프로세스는 다음과 같음.

```text
+-----------------------------------------------------------------------------------+
|                        오픈뱅킹 통합 에코시스템 아키텍처                          |
+-----------------------------------------------------------------------------------+
|  [이용자(스마트폰/Web)]                                                            |
|          | (1) 이용자 인증 및 동의 (OAuth 2.0 User Consent)                       |
|          v                                                                        |
|  +-----------------------------------------------------------------------------+  |
|  | 이용기관 (핀테크 기업 / 참가 은행 웹·앱 서비스)                             |  |
|  |   - 토큰 관리 엔진 (Access / Refresh Token Storage)                         |  |
|  |   - 금융 비즈니스 로직 및 UX 인터페이스                                     |  |
|  +-----------------------------------------------------------------------------+  |
|          | (2) 표준 REST API 요청 (Bearer Token, 디지털 서명)                     |
|          v                                                                        |
|  +-----------------------------------------------------------------------------+  |
|  | 금융결제원 오픈뱅킹 중계 시스템 (Open Banking Hub Platform)                  |  |
|  |   +-----------------------------------------------------------------------+ |  |
|  |   | [API Gateway] : mTLS 종단, 인증/인가(Token 검증), Rate Limiting       | |  |
|  |   | [보안·모니터링] : 실시간 FDS 연계, 트래픽 제어, 감사 로그 적재        | |  |
|  |   | [전문 변환/라우팅] : JSON Restful 전문 <-> 참가기관 대외계 전문 변환   | |  |
|  |   +-----------------------------------------------------------------------+ |  |
|  +-----------------------------------------------------------------------------+  |
|          | (3) 전용 결제망 연계 (대외계 / FEP 전문 통신)                          |
|          v                                                                        |
|  +-----------------------------------------------------------------------------+  |
|  | 참가 금융기관 (시중은행 / 증권사 / 저축은행 등 원장 보유 기관)              |  |
|  |   - 계좌 원장 시스템 (계좌 잔액 확인, 입출금 처리, 출금이체 원천 검증)      |  |
|  |   - 기관 자체 FDS 및 사후 정산/대사 데이터 생성                            |  |
|  +-----------------------------------------------------------------------------+  |
+-----------------------------------------------------------------------------------+
```

- **상호 개방성** : 은행-핀테크 간 양방향 인프라 개방 - 모든 은행과 허가된 핀테크 기업이 동일한 조건으로 계좌 조회 및 이체 망 이용.
- **표준 인터페이스** : RESTful JSON 기반 표준 API - 금융결제원 표준 규격에 따라 규격화된 메시지 전송 및 단일 연동 개발 환경 제공.
- **안전한 권한 위임** : OAuth 2.0 기반 토큰 제어 - 공인인증서나 비밀번호 직접 저장 배제, 명시적 스코프(Scope)별 접근 토큰(Access Token) 발급.
- **비용 절감 및 확장** : 펌뱅킹 대비 망 이용 수수료 대폭 절감 - 기존 펌뱅킹 대비 약 1/10 수준 수수료 체계 및 단일 게이트웨이 연계로 확장 비용 절감.

## Ⅲ. 오픈뱅킹(Open Banking)의 세부 구성 요소 및 비교 분석

| API 분류 | 세부 API 명칭 | 처리 기능 및 전송 파라미터 |
|---|---|---|
| **조회 서비스 API** | 잔액조회 API | 핀테크 이용번호, 계좌별 실시간 잔액 및 출금 가능액 조회 |
| | 거래내역조회 API | 계좌 거래 일시, 거래점, 입출금액, 적요 내역 다건 조회 |
| | 계좌실명조회 API | 수취인 주민등록번호 암호화값 일치 및 계좌 유효성 검증 |
| **이체 서비스 API** | 출금이체 API | 고객 동의 기반 타행 고객 계좌에서 이용기관 집금계좌로 인출 |
| | 입금이체 API | 오픈뱅킹 참가 기관 고객 계좌로 실시간 송금 및 자금 정산 |
| **관리/보안 API** | 토큰 발급/갱신 API | 인가 코드(Authorization Code) 기반 Access/Refresh 토큰 갱신 |
| | 동의해지 API | 이용자의 계좌 연결 및 정보제공 동의 철회 실시간 동기화 |

- 오픈뱅킹은 상기 비교 지표를 바탕으로 비즈니스 요구사항과 운영 인프라 환경을 고려한 최적의 아키텍처를 선정하고, 확장성과 안정성을 균형 있게 확보해야 함.

## Ⅳ. 오픈뱅킹(Open Banking)의 주요 한계점 및 해결 방안

- **단일 장애점(SPOF) 위험** :
  - **한계점** : 모든 트랜잭션이 금융결제원 중계 인프라를 경유하므로 허브 장애 시 전 금융권 연계 마비.
  - **해결 방안** : Active-Active 멀티 리전 클라우드 중계망 구축, 기관 간 서킷 브레이커(Circuit Breaker) 및 대체 경로 자동 폴백(Failover) 구현.
- **비인가 API 악용 및 부정 이체** :
  - **한계점** : 탈취된 Access Token 또는 핀테크 앱 위변조를 통한 대규모 무단 출금 위험 상존.
  - **해결 방안** : mTLS(상호 TLS) 강제, 디바이스 핑거프린팅, API 이상 트래픽 실시간 FDS 차단 및 이상 거래 실시간 지급정지 공조망 가동.
- **이용기관과 은행 간 분쟁 책임 모호** :
  - **한계점** : 이체 트랜잭션 오류 및 지연 발생 시 사고 발생 주체 규명 곤란.
  - **해결 방안** : 분산 트레이싱(OpenTelemetry 기반 고유 추적 ID 부여), 블록체인 기반 거래 이력 불변 저장 및 표준 분쟁 처리 가이드라인 제정.

## Ⅴ. 오픈뱅킹(Open Banking) 적용 및 발전을 위한 기술사적 제언

- **인프라 초점 고도화 및 2금융권 포함 전 추진** : 1금융권 중심 표준 API 조회/이체의 한계를 탈피하고, 2금융권 포함 전 금융권 상호 개방 및 클라우드 BaaS를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- **보안 통제 강화 및 신뢰성 확보 방안** : 정적 OAuth 2.0 토큰 및 개별 FDS의 한계를 탈피하고, FAPI(Financial-grade API) 보안 규격 및 실시간 AI FDS를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- **비즈니스 모델 고도화 및 비금융 플랫폼 결합 추진** : 단순 송금 수수료 절감 및 잔액 모아보기의 한계를 탈피하고, 비금융 플랫폼 결합 임베디드 금융 및 초개인화 여신 추천을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
