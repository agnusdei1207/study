## 지식 로드맵 내 현재 위치

지식 위치: 인공지능 → 언어 모델 활용 구조 → **RAG**

## 30초 인출

- 본질: **RAG(Retrieval-Augmented Generation, 검색 증강 생성)** 는 질문과 관련된 외부 자료를 찾아 생성 모델의 답변에 반영하는 방법
- 메커니즘: 문서 청킹·색인 → 질문으로 검색 → 관련 자료 선별 → 자료를 근거로 답변 생성.
- 통찰: 한계: 검색 자료가 무관하거나 오래되면 생성 답변의 근거가 약화 → 방안: 검색 품질과 출처·갱신 시점을 확인하고 답변 근거 대조

<details>
<summary>핵심 용어</summary>

- **RAG(Retrieval-Augmented Generation)** : 외부 자료를 찾아 생성 모델의 답변에 반영하는 방법
- **청킹(Chunking)** : 문서를 검색·인용에 적합한 단위로 나누는 처리
- **하이브리드 검색(Hybrid Search)** : 키워드 검색과 의미 기반 검색을 결합하는 검색 방식
- **리랭커(Re-ranker)** : 1차 검색 결과를 질문 관련성에 따라 재정렬하는 구성요소
- **모듈형 RAG(Modular RAG)** : 검색·재정렬·생성 등을 교체하거나 분기할 수 있게 구성한 RAG 설계 방식

</details>

## 2~4교시 25점 답안

### Ⅰ. RAG의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **RAG** 는 질문과 관련된 외부 자료를 검색해 생성 모델의 답변에 반영하는 방법 |
| 목적 | 모델 내부 지식만으로 답할 때 부족한 최신 근거와 출처 제공 |

### Ⅱ. 기본 처리 흐름

```text
질문
  ↓ 검색어 구성
외부 자료 검색
  ↓ 관련 자료 선별
근거 문맥 구성
  ↓ 생성 모델에 전달
답변 생성·출처 제시
```

검색된 근거는 생성 모델의 입력에 추가되는 외부 지식이며, 자료의 정확성이나 답변의 사실성을 자동으로 보장하지 않음.

### Ⅲ. 구성 방식 비교

| 방식 | 구성 특징 | 검토할 점 |
|---|---|---|
| Naive RAG | 색인된 자료를 검색해 문맥으로 넣고 답변 생성 | 검색 누락·무관한 문맥·긴 문서 처리 |
| Advanced RAG | 질의 변환, 청킹·검색 개선, 리랭킹 등으로 기본 흐름 보강 | 개선 단계별 품질과 지연·비용 |
| Modular RAG | 검색·재정렬·생성 등의 모듈을 과업에 따라 조합·분기 | 모듈 간 계약과 전체 경로 평가 |

이 분류는 구현 방식의 설명 축이며 세 방식이 서로 배타적인 표준 등급을 뜻하지 않는다.

**검색 구성요소와 선택**

| 구성요소 | 역할 | 확인 기준 |
|---|---|---|
| 청킹(Chunking) | 문서를 검색 단위로 분할 | 문맥이 끊기거나 중복되지 않는 단위 |
| 하이브리드 검색(Hybrid Search) | 키워드·의미 검색 결과 결합 | 도메인 용어와 의미 유사성의 균형 |
| 리랭커(Re-ranker) | 후보 자료를 질문 관련성으로 재정렬 | 검색 품질과 처리 지연의 균형 |

### Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 질문어·문서 표현 차이나 청킹 손실로 질문과 다른 자료 검색 | 키워드·의미 검색과 재정렬 적용 후 대표 질의로 평가 |
| 문서 변환 과정에서 표 구조 손실로 맥락 누락 | 구조 보존 변환과 원문 대조 |
| 모델이 검색 문맥 밖의 내용을 생성해 근거와 답변 불일치 | 근거 범위를 명시하고 불충분한 경우 답변 보류 |

### Ⅴ. 제언

업무별 대표 질문과 정답 근거를 먼저 구축하고 자료 갱신마다 검색 적합성을 재평가.
