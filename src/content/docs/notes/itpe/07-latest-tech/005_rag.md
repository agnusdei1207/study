## Ⅰ. RAG(Retrieval-Augmented Generation)의 개요

- 핵심 요약 : LLM이 답변 생성 전에 외부 지식베이스에서 근거 문맥을 검색해 프롬프트에 주입하여, 재학습 없이 최신·사내 지식을 반영하는 아키텍처.
- 개념 : 거대언어모델(LLM, Large Language Model)이 사전 학습된 가중치에만 기대지 않고, 외부 지식베이스에서 질의와 관련된 문서를 검색(Retrieval)해 프롬프트에 증강(Augmentation)한 뒤 답변을 생성(Generation)하는 **검색 증강 생성** (RAG, Retrieval-Augmented Generation) 아키텍처.
- 배경 및 필요성 : LLM은 학습 시점에 지식이 동결되는 지식 단절(Knowledge Cutoff)과 그럴듯한 거짓을 생성하는 **환각** (Hallucination) 문제가 있어, 파인튜닝 비용 없이 사내 최신 데이터를 안전하게 활용할 방법이 요구됨.
- 주요 목적 : 답변의 사실성과 출처 제시 확보, 사내 데이터 접근 통제, 데이터 갱신 비용 절감.

## Ⅱ. RAG(Retrieval-Augmented Generation)의 특징 및 장점

- 핵심 요약 : 오프라인 인덱싱과 온라인 추론을 분리한 구조가 최신성과 근거성을 확보하는 방식.

1. 지식 분리 : 지식을 모델 가중치가 아닌 **벡터 DB** (Vector Database) 등 외부 저장소에 두고 인덱스만 갱신 → 재학습 없이 즉시 반영되어 갱신 비용 절감.
2. 근거 기반 생성 : 검색된 문맥을 프롬프트에 주입하고 답변을 그 범위로 제한 → 환각 억제와 출처 명시 가능.
3. 접근 통제 : 검색 단계에서 RBAC(Role-Based Access Control) 같은 권한 정책을 적용 → 사용자 권한에 맞는 문서만 모델에 전달.
4. 설명가능성 : 답변마다 원문 청크와 페이지를 연결 → 감사와 사실 검증이 가능.

## Ⅲ. RAG(Retrieval-Augmented Generation)의 구조 (흐름)

- 핵심 요약 : 문서를 미리 인덱싱하는 오프라인 파이프라인과, 질의마다 검색과 생성을 거치는 온라인 파이프라인의 이중 구조.
- **청킹** (Chunking) : 문서를 의미 단위로 나누고 오버랩이나 계층 구조를 두어 문맥 단절을 줄임.
- **밀집 검색** (Dense Retrieval) : 질의와 청크를 임베딩 벡터로 바꾸고 HNSW(Hierarchical Navigable Small World) 색인으로 유사도 상위 k개를 추출.
- **리랭킹** (Re-ranking) : Cross-Encoder가 질의와 문맥을 함께 보고 점수를 다시 매겨 최종 문맥을 고름.

```text
[ 오프라인 인덱싱 파이프라인 ]

원시 문서 (PDF, DB 등)
   ↓
청킹 (Chunking)
   ↓
임베딩 모델로 벡터 변환
   ↓
벡터 DB 적재
```

```text
[ 온라인 추론 파이프라인 ]

사용자 질의
   ↓
유사도 검색 (Top-k)
   ↓
리랭킹 (Cross-Encoder)
   ↓
프롬프트 증강 (검색 문맥 주입)
   ↓
LLM 생성 (출처 명시 답변)
```

## Ⅳ. RAG(Retrieval-Augmented Generation)의 비교

- 핵심 요약 : 파인튜닝은 말투와 추론 양식을, RAG는 변동이 잦은 사실 지식을 다루는 데 각각 강점이 있음.

| 비교 항목 | 순수 LLM (Vanilla LLM) | 파인튜닝 (Fine-Tuning) | RAG (검색 증강 생성) |
| --- | --- | --- | --- |
| 지식 최신성 | 학습 시점에 동결 | 갱신 주기마다 재학습 필요 | 외부 지식베이스 갱신 시 즉시 반영 |
| 환각 | 빈번하며 억제 어려움 | 도메인 정렬로 완화되나 잔존 | 검색된 근거로 억제 |
| 사내 데이터 연동 | 모델 내부 노출 위험 | 모델 내 암기(Memorization) 위험 | 검색 단계의 권한 제어 가능 |
| 구축·유지 비용 | API 호출 비용 중심 | 대규모 연산과 데이터셋 구축 비용 | 벡터 DB와 임베딩 파이프라인 비용 |
| 출처 제공 | 불가능 | 불가능 | 원본 문서와 위치 제시 가능 |

- 선택 기준 : 파인튜닝은 말투, 도메인 문체, 특정 추론 양식의 체화에, RAG는 가변적이고 방대한 사실 지식의 정확한 참조에 적합.

## Ⅴ. RAG(Retrieval-Augmented Generation)의 한계와 방안

- 핵심 요약 : 검색 노이즈, 문맥 파편화, 간접 프롬프트 주입을 검색 설계와 격리 장치로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 의미 검색의 노이즈 | 고유명사·코드 검색에서 밀집 임베딩이 실패해 무관한 청크 유입 | BM25 희소 검색과 밀집 검색을 결합한 **하이브리드 검색** (Hybrid Search), **RRF** (Reciprocal Rank Fusion) 적용 | 검색 적중률(Recall@k) |
| 고정 청킹과 중간 정보 유실 | 청크가 작으면 문맥이 잘리고 크면 임베딩이 희석되며, 긴 프롬프트 중간 문서는 주의에서 누락 (Lost-in-the-Middle) | **부모-자식 계층 청킹** (Parent Document Retriever) 적용, 중요 문맥을 프롬프트 양 끝에 배치 | 근거 누락률 |
| 간접 프롬프트 주입 | 문서 속 악성 지시문을 LLM이 명령으로 오인 실행 | 검색 문맥을 XML 태그로 데이터와 격리하고 NeMo Guardrails 같은 가드레일 적용 | 주입 시도 탐지 건수 |

## Ⅵ. RAG(Retrieval-Augmented Generation)에 대한 기술사적 제언

- 핵심 요약 : RAG 품질을 정량 평가 루프로 상시 관리하고, 지식 구조와 검색 흐름을 확장해 복합 추론 역량을 넓히는 방향.
- 평가 체계 : **RAG Triad** (문맥 적합성, 근거성, 답변 적합성)를 Ragas나 TruLens로 상시 측정하여 품질 저하를 운영 단계에서 감지하도록 구성.
- 지식 구조 : 단순 유사도 검색을 넘어 **GraphRAG** (Graph-based Retrieval-Augmented Generation)로 엔터티 관계를 활용하면 여러 문서를 잇는 다단계 추론이 가능해짐.
- 검색 흐름 : 검색 결과가 불충분하면 질의를 재작성해 추가 검색하는 **에이전틱 RAG** (Agentic RAG) 구조를 도입하여 1회성 정적 검색의 한계를 보완.

## Ⅶ. 결론

- 핵심 요약 : RAG는 모델을 다시 학습하지 않고 외부 근거로 답변을 묶는 방식이며, 최신성과 출처 확보에 가장 실용적인 선택지.
- 시사점 : 검색 품질이 답변 품질을 좌우하므로 검색 설계와 평가 체계를 함께 갖춘 조직이 RAG의 효과를 지속적으로 확보함.
