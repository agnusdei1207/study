## 30초 인출

- 본질: **RAG(Retrieval-Augmented Generation)** 는 LLM의 환각(Hallucination)과 최신성 한계를 극복하기 위해 사용자 질의와 관련된 외부 지식을 검색하여 프롬프트 컨텍스트에 주입 후 증강 생성하는 아키텍처
- 메커니즘: 도메인 문서를 청킹·임베딩하여 벡터 DB에 색인하고, 사용자 질의 인입 시 하이브리드 검색과 리랭킹을 거쳐 최적 컨텍스트를 LLM에 전달하여 근거 기반 답변 생성
- 통찰: 단순 의미 검색(Naive RAG)은 청크 단절과 도메인 키워드 누락으로 검색 실패를 유발하므로 쿼리 재작성, 하이브리드 검색, 크로스 인코더 리랭커 및 GraphRAG 연계 필수

<details><summary>핵심 용어</summary>

- **RAG (Retrieval-Augmented Generation)** : 외부 지식 베이스 검색과 생성 모델의 추론 역량을 결합하여 사실성과 신뢰성을 증강하는 AI 설계 패턴.
- **청킹 (Chunking)** : 장문 문서를 검색 정확도와 LLM 컨텍스트 윈도우 한계에 맞춰 적절한 의미 단위 토큰으로 분할하는 전처리 기법.
- **하이브리드 검색 (Hybrid Search)** : 의미론적 유사도를 측정하는 벡터 검색(Dense)과 정확한 키워드 일치를 포착하는 BM25(Sparse) 검색을 상호 결합하는 기법.
- **리랭커 (Re-ranker)** : 1차 검색된 다수의 후보 청크를 질의와의 심층 문맥 연관성에 따라 Cross-Encoder 신경망으로 재정렬·선별하는 모듈.
- **Advanced RAG** : 검색 전(Pre-Retrieval), 검색 중(Retrieval), 검색 후(Post-Retrieval) 파이프라인 전반에 질의 확장 및 리랭킹을 추가한 고도화 구조.

</details>

## 2~4교시 25점 답안

## Ⅰ. RAG의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **RAG(Retrieval-Augmented Generation)** 는 대규모 언어모델(LLM)이 파라메트릭 지식(내부 가중치)에만 의존하지 않고, 외부 비파라메트릭 지식 베이스에서 관련 정보를 실시간 검색하여 신뢰성 있는 답변을 생성하도록 돕는 프레임워크 |
| 목적 | 생성형 AI의 치명적 환각(Hallucination) 억제, 도메인 최신 데이터 즉시 반영, 파인튜닝 대비 비용 절감 및 출처 인용(Attribution) 확보 |

## Ⅱ. RAG의 핵심 특징 및 기존 LLM의 한계 극복 속성

| 구분 | RAG의 특징 | 세부 공학적 메커니즘 |
|---|---|---|
| **환각 억제 (Anti-Hallucination)** | 사실적 지식 그라운딩 | 검색된 실제 문서 청크만을 바탕으로 답변을 작성하도록 시스템 프롬프트 제약 부과 |
| **지식 최신성 (Freshness)** | 무중단 데이터베이스 갱신 | 모델의 무거운 재학습 없이도 외부 벡터 DB 색인 업데이트만으로 최신 정보 즉시 반영 |
| **비용 효율성 (Cost-Efficiency)** | 저비용 인프라 운영 | 대규모 GPU 파인튜닝 비용 대비 극히 저렴한 임베딩 생성 및 벡터 인덱싱 비용 |
| **설명가능성 (Explainability)** | 명확한 근거 출처 제공 | 생성된 문맥마다 인용한 원문 페이지 번호, URL, 저자 등 명시적 메타데이터 표기 |

## Ⅲ. RAG 시스템 아키텍처 및 단계별 엔지니어링 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ 엔터프라이즈 RAG 통합 파이프라인 ]                  │
└────────────────────────────────────────────────────────────────────────┘
                                    │
 [ 사전 색인 파이프라인 (Offline) ]  │  [ 실시간 검색·생성 파이프라인 (Online) ]
 원천 도메인 문서 (PDF, DB, Web)     │  사용자 입력 질의 (User Query)
        │                           │              │
        ▼                           │              ▼
 [ 문서 정제 및 청킹 (Chunking) ]   │  [ 질의 변환 (HyDE, Sub-Query 확장) ]
        │                           │              │
        ▼                           │              ▼
 [ 임베딩 생성 (Dense Embedding) ]  │  [ 하이브리드 검색 (Dense + Sparse BM25) ]
        │                           │              │ (RRF 결합)
        ▼                           │              ▼
 [ 벡터 DB 색인 (Pinecone/Milvus) ] ───> [ 상위 Top-K 후보 청크 검색 ]
                                    │              │
                                    │              ▼
                                    │  [ 크로스 인코더 리랭커 (Re-ranker) ]
                                    │              │ (관련성 재정렬)
                                    │              ▼
                                    │  [ 프롬프트 컨텍스트 압축 및 주입 ]
                                    │              │
                                    │              ▼
                                    │  [ LLM 추론 및 근거 기반 답변 생성 ]
```

| 파이프라인 단계 | 엔지니어링 활동 | 핵심 기술 및 통제 방안 |
|---|---|---|
| **문서 전처리·청킹** | 텍스트 추출, 메타데이터 부착, 의미 기반 분할 | 시맨틱 청킹(Semantic Chunking), 슬라이딩 윈도우, 마크다운 파서 |
| **색인 및 검색** | 다차원 벡터화 및 하이브리드 색인 구축 | BGE-M3 임베딩, BM25, HNSW 인덱스, RRF(Reciprocal Rank Fusion) |
| **리랭킹 및 최적화** | 무관한 청크 제거, 컨텍스트 압축 | Cross-Encoder (bge-reranker-large), Contextual Compression |
| **프롬프트 증강·생성** | 가드레일 프롬프트 구성, 인용 출처 매핑 | Few-Shot 예시, CoT(Chain-of-Thought), 출처 강제 템플릿 |

## Ⅳ. RAG 아키텍처 진화 단계 비교

| 비교 항목 | Naive RAG (전통적) | Advanced RAG (고도화) | Modular RAG (차세대) |
|---|---|---|---|
| **처리 구조** | 단순 순차 (색인-검색-생성) | 전/후처리 추가 보강 파이프라인 | 유연한 모듈형 오케스트레이션 |
| **질의 처리** | 원본 사용자 질의 그대로 검색 | HyDE(가상문서), 질의 분해, 재작성 | 라우팅 모듈 기반 의도별 질의 분기 |
| **검색 기법** | 단일 코사인 벡터 검색 | Dense + Sparse 하이브리드 검색 | 다중 지식 소스 검색, GraphRAG 결합 |
| **정렬 기법** | 벡터 유사도 기반 상위 반환 | 딥러닝 Cross-Encoder 리랭킹 | 압축, 재구성, 적응형 청크 재배치 |
| **주요 한계** | 낮은 정확도, 무관한 청크 유입 | 파이프라인 고정, 연산 지연 증가 | 오케스트레이션 복잡도 급증 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 고정 크기 청킹으로 인한 문맥 단절(Lost in the Middle) 및 문서 간 상호 관계 파악 불가 | 부모-자식(Parent-Document) 청킹 기법 도입 및 지식 그래프와 결합한 GraphRAG 아키텍처 구축 |
| 사용자 질의 표현과 문서 청크 간 어휘적 괴리로 인한 의미 검색의 오매칭 | 질의를 다각도로 확장하는 HyDE(가상 답변 생성) 적용 및 도메인 맞춤형 임베딩 모델 미세조정 |

## Ⅵ. 제언

단순 RAG를 넘어 에이전트가 검색 필요 여부를 스스로 판단하고 반성(Self-Reflection)하는 Agentic RAG 및 GraphRAG 하이브리드 아키텍처 구축.

```text
[ 사용자 질의 ] ──> [ 라우터 에이전트 ] ──(자체 지식 충분 시)──> [ 즉시 LLM 응답 ]
                          │ (외부 지식 필요 시)
                          ▼
            [ 하이브리드 검색 & GraphRAG ]
                          │
                          ▼
            [ 검색 결과 자체 평가 (Self-RAG) ]
              ├── 관련성 부족 시 ──> [ 질의 재작성 후 재검색 ]
              └── 관련성 충족 시 ──> [ Re-ranker 및 컨텍스트 압축 ]
                          │
                          ▼
            [ 근거 기반 최종 답변 생성 및 팩트체크 검증 ]
```

| 구분 | 초기 Naive RAG 방식 | 제언: 자기반성형 Agentic RAG |
|---|---|---|
| **검색 결정** | 모든 입력 질의에 대해 무조건 검색 수행 | 질의 난이도 및 모델 내부 지식 기반 선택적 검색 |
| **검색 검증** | 검색된 상위 청크를 무비판적 프롬프트 주입 | 검색된 청크의 질의 부합도를 에이전트가 자체 채점 |
| **오류 수정** | 검색 실패 시 환각성 엉뚱한 답변 출력 | 검색 부적합 판정 시 검색어를 스스로 수정하여 재탐색 |
