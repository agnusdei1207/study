## 연관 키워드

- QR코드 결제, MPM, CPM, 동적 QR, 정적 QR, 가맹점 제시형, 소비자 제시형
- TOTP, EMVCo, TLV, 큐싱(Qshing), 화면 캡처 재사용(Replay), 1회용 결제 토큰
- FDS, 전자서명, 오프라인 서명 토큰, BLE, NFC, Shoulder Surfing

## Ⅰ. QR코드 결제의 개요

- 핵심 요약 : 2차원 바코드에 결제 정보를 담아 스캔으로 대금을 정산하는 모바일 간편결제 방식이며, 위변조와 재사용을 막는 설계가 핵심 과제.
- 개념 : 2차원 매트릭스 바코드에 가맹점 식별자와 결제 정보를 담아 스캔으로 대금을 정산하는 **QR코드 결제** (QR Code Payment) 방식으로, 소비자 앱과 가맹점 단말이 함께 쓰이는 모바일 간편결제의 한 형태임.
- 배경 및 필요성 : 고정형 QR 스티커는 덧씌우기(큐싱)에 노출되고, 화면 캡처본은 재사용될 수 있어, 일회용 동적 QR 생성과 실시간 **FDS** (Fraud Detection System, 이상거래 탐지 시스템) 연계, 전자서명 검증이 필요함.
- 주요 목적 : POS(Point of Sale)·VAN(Value-Added Network) 단말 설치 부담을 낮춰 소상공인의 결제 접근성을 넓히고, 부정 결제를 차단하며 결제 처리 속도를 높임.

## Ⅱ. QR코드 결제의 특징 및 장점

- 핵심 요약 : 제시 주체에 따라 MPM과 CPM으로 나뉘며, 표준 데이터 구조와 일회용 토큰이 상호운용성과 보안을 함께 뒷받침.

1. **MPM** (Merchant-Presented Mode, 가맹점 제시형) : 가맹점 QR을 소비자 앱이 스캔하고 금액을 확정 → 단말기 없이 도입할 수 있어 초기 비용 최소화.
2. **CPM** (Customer-Presented Mode, 소비자 제시형) : 소비자 앱이 일회용 QR을 만들고 POS가 스캔 → 스캔 즉시 승인되어 결제 속도 향상.
3. **TLV** (Tag-Length-Value) 구조 : 결제 항목을 태그, 길이, 값으로 인코딩하는 EMVCo QR 규격 → 카드사와 간편결제 사업자 간 상호운용성 확보.
4. **TOTP** (Time-based One-Time Password) 토큰 : 짧은 시간 동안만 유효한 값을 사용 → 캡처한 화면의 재사용 위험 감소.

## Ⅲ. QR코드 결제의 구조 (흐름)

- 핵심 요약 : MPM은 소비자 앱에서 금액을 확정해 승인하고, CPM은 가맹점 POS를 거쳐 VAN과 PG망으로 승인되는 흐름의 차이.
- **PG** (Payment Gateway, 전자결제 대행) : 가맹점과 금융 결제망 사이에서 승인 요청을 중계하는 사업자.

```text
[ MPM : 가맹점 제시형 ]

가맹점 QR (정적 또는 동적)
   ↓ 카메라 스캔
소비자 결제 앱
   ↓ 금액 입력 · 생체인증
PG (전자결제 대행)
   ↓
금융 결제망 → 승인 알림
```

```text
[ CPM : 소비자 제시형 ]

소비자 앱 (TOTP 일회용 QR 생성)
   ↓ 바코드 리더 스캔
가맹점 POS 단말
   ↓ 결제 전문 전송
VAN · PG사
   ↓ 토큰 검증
카드사 · 은행 → 승인 응답
```

## Ⅳ. QR코드 결제의 방식별 비교

- 핵심 요약 : MPM은 도입 비용이 낮고 CPM은 처리 속도가 빠르며, 두 방식의 위협 면이 서로 달라 보안 대책도 달라짐.

| 비교 축 | MPM 가맹점 제시형 | CPM 소비자 제시형 |
| --- | --- | --- |
| 스캔 주체 | 소비자 스마트폰 카메라 | 가맹점 POS 바코드 리더 |
| QR 생성 주체 | 가맹점 (출력물 또는 단말 화면) | 소비자 모바일 결제 앱 |
| 금액 확정 | 소비자가 앱에서 입력 | POS가 스캔 즉시 확정 |
| 인프라 비용 | 낮음 (스티커 한 장으로 구축 가능) | POS 단말과 스캐너 필요 |
| 처리 속도 | 상대적으로 느림 | 빠름 |
| 주요 위협 | 큐싱, 악성 URL 연결 | 화면 캡처 재사용, 어깨너머 엿보기 |

- 선택 기준 : 단말 도입 여력이 적은 소형 매장에는 MPM, 결제 처리량이 많은 매장에는 CPM이 맞는 방식으로 정리되며, 두 방식의 보안 통제를 함께 적용하는 것이 일반적.

## Ⅴ. QR코드 결제의 한계와 방안

- 핵심 요약 : 정적 QR의 위변조, 캡처본 재사용, 네트워크 음영 지역의 승인 실패를 동적 토큰과 오프라인 보조 수단으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 정적 MPM QR 위변조 (큐싱) | 매장 스티커 위에 악성 QR을 덧씌워 금융사기 유도 | 거래 건별로 생성되는 동적 QR 적용, 소비자 앱에서 가맹점 정보를 실시간 대조 표시 | 위변조 신고 건수 |
| CPM 화면 캡처 재전송 | 탈취한 캡처본으로 재전송해 부정 결제 발생 | 화면 캡처 방지(DRM, Digital Rights Management) 모듈, 짧은 유효 시간의 TOTP, 1회 사용 후 즉시 폐기 | 재사용 시도 차단 건수 |
| 음영 지역 승인 실패 | 지하 매장 등에서 결제 서버와 통신이 끊겨 거래 실패 | 타임스탬프 기반 오프라인 서명 토큰 캐싱, **BLE** (Bluetooth Low Energy)·**NFC** (Near Field Communication) 보조 채널 전환 | 승인 실패율 |

## Ⅵ. QR코드 결제에 대한 기술사적 제언

- 핵심 요약 : 정적 수단을 줄이고 일회용 토큰과 전자서명 검증을 기본값으로 삼는 설계 전환이 간편결제 신뢰의 출발점.

1. 결제 사업자는 정적 QR의 사용 범위를 단계적으로 줄이고 거래 건별 동적 QR을 기본 방식으로 삼는 전환 로드맵 수립 필요.
2. 결제 토큰은 가맹점 계좌 정보를 노출하지 않는 일회용 값으로 설계하고, 사용 즉시 폐기되는 검증 체계를 표준으로 정착시킬 필요.
3. 금융 소비자 보호 측면에서는 가맹점 식별 정보의 디지털 표출과 전자서명 무결성 검증을 결합한 이용자 확인 절차 도입 방향 추진 필요.

## Ⅶ. 결론

- 핵심 요약 : QR코드 결제의 가치는 편의성보다 일회성과 검증 가능성을 설계하는 데서 결정됨.
- 시사점 : 간편결제 확산은 단말 비용 절감만으로 이뤄지지 않으며, 토큰 수명과 서명 검증이 신뢰를 좌우함.
