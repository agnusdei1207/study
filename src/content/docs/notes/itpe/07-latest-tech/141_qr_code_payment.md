## Ⅰ. QR코드 결제의 개요

- 개념 : **2차원 매트릭스 바코드** 규격에 가맹점 식별자, 거래 계좌 또는 **일회용 결제 토큰** 정보를 인코딩하여 광학 스캐너 판독으로 대금을 정산하는 **모바일 간편결제** 기술.
- 배경 및 필요성 : 정적 MPM 스티커 위변조(큐싱) 및 CPM 화면 캡처 재사용 공격 위험이 상존하므로 일회용 동적 QR(One-Time Token) 생성과 실시간 **FDS** 연계 및 전자서명 검증 체계 구축 필요.
- 핵심 목적 : 고가의 POS·VAN 단말기 설치 부담 제거를 통한 소상공인 결제 접근성 향상, 카드 복제 방지 및 결제 처리 속도 단축.

## Ⅱ. QR코드 결제의 핵심 아키텍처 및 동작 메커니즘

QR코드 결제는 신뢰할 수 있는 데이터 파이프라인과 고도화된 추론 메커니즘을 기반으로 동작하며, 세부적인 아키텍처와 핵심 컴포넌트 간 상호작용 프로세스는 다음과 같음.

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ QR코드 결제 아키텍처: MPM vs CPM 트랜잭션 파이프라인 ]              │
└────────────────────────────────────────────────────────────────────────┘

  [ MPM: 가맹점 제시 모드 ]
  가맹점 정적/동적 QR ──(카메라 스캔)──> [ 소비자 결제 앱 ]
                                                │ 금액 입력 및 생체인증
                                                ▼
                                         [ 결제 서비스사 / PG ] ──> [ 금융 결제망 ]
                                                │
                                                ▼ (승인 알림 푸시)
                                         가맹점 스마트폰 / 태블릿

  [ CPM: 소비자 제시 모드 ]
  [ 소비자 결제 앱 ] ──(TOTP 일회용 QR 생성)
         │
         │ (바코드 리더기 스캔)
         ▼
  [ 가맹점 POS 단말 ] ──(결제 전문 전송)──> [ VAN / PG 사 ] ──────> [ 카드사 / 은행 ]
                                                  │                 (토큰 검증 및 승인)
                                                  ▼ (승인 응답)
                                            영수증 출력 / POS 완료
```

- **MPM (가맹점 제시형)** : 가맹점 비치 QR 스캔 → 소비자 앱에서 금액 입력 및 승인 - 단말기 불필요로 도입 비용 극소화, 정적 QR의 물리적 위변조 노출 위험.
- **CPM (소비자 제시형)** : 소비자 앱의 결제 QR 생성 → POS 광학 스캐너로 리딩 - 빠른 결제 속도(대형 마트·편의점 적합), 캡처 방지 보안 키패드 및 **TOTP** 토큰 필수.
- **EMVCo 규격 호환성** : **TLV** (Tag-Length-Value) 구조 기반 정형 데이터 인코딩 - 글로벌 카드사(Visa, Master 등) 및 국내 제로페이 규격 간 상호운용성 제공.

## Ⅲ. QR코드 결제의 세부 구성 요소 및 비교 분석

| 비교 항목 | 가맹점 제시형 (MPM) | 소비자 제시형 (CPM) |
|---|---|---|
| **스캔 주체** | 소비자 스마트폰 카메라 | 가맹점 POS / 바코드 리더기 |
| **QR 생성 주체** | 가맹점 (출력물 또는 POS 화면) | 소비자 모바일 뱅킹 / 간편결제 앱 |
| **결제 정보 입력** | 소비자가 직접 금액 입력 (정적 QR 기준) | 가맹점 POS가 스캔 즉시 결제 금액 확정 |
| **인프라 비용** | 제로 (종이 스티커 1장으로 구축 가능) | POS 단말기 및 2D 광학 스캐너 구비 필요 |
| **처리 속도** | 느림 (스캔 후 수기 금액 입력) | 빠름 (단순 스캔 즉시 승인) |
| **주요 위협** | 큐싱(스티커 덧붙이기), 악성 URL 리다이렉트 | 화면 캡처본 재사용, 단말기 주변 도청(Shoulder Surfing) |

- QR코드 결제는 상기 비교 지표를 바탕으로 비즈니스 요구사항과 운영 인프라 환경을 고려한 최적의 아키텍처를 선정하고, 확장성과 안정성을 균형 있게 확보해야 함.

## Ⅳ. QR코드 결제의 주요 한계점 및 해결 방안

- 정적 MPM QR코드 위변조 큐싱(Qshing) 사기 위협 :
  - 한계점 : 오프라인 매장에 부착된 정적 MPM 스티커 위에 악성 QR을 덧씌우는 큐싱(Qshing) 금융사기 빈발.
  - 해결 방안 : 가맹점 단말기 화면에 거래 건별로 생성되는 동적 QR(Dynamic MPM) 의무화 및 소비자 앱 내 가맹점 상호 실시간 음성/화면 팝업 검증.
- 동적 CPM 결제 화면 캡처본 재전송(Replay) 부정 결제 :
  - 한계점 : 소비자 앱의 결제 QR 화면 캡처 및 탈취본을 이용한 재전송(Replay) 부정 결제 위험.
  - 해결 방안 : 화면 캡처 방지(DRM) 모듈 적용, 30~60초 유효기간의 TOTP 동적 토큰 사용 및 1회 사용 즉시 토큰 폐기 처리.
- 네트워크 음영 지역에서의 실시간 결제 승인 실패 :
  - 한계점 : 지하 매장이나 네트워크 음영 지역에서 결제 서버 통신 불가로 인한 결제 지연 및 거래 실패.
  - 해결 방안 : 타임스탬프 기반 오프라인 서명 토큰(Offline Token) 캐싱 기술 및 로컬 근거리 블루투스(BLE)/NFC 보조 결제 채널 전환 지원.

## Ⅴ. QR코드 결제 적용 및 발전을 위한 기술사적 제언

- 코드 형태 고도화 및 거래 건별·시간별 변동 추진 : 인쇄된 영구 고정형 QR의 한계를 탈피하고, 거래 건별·시간별(60초) 변동 동적 QR을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- 토큰 유효성 고도화 및 1회용 TOTP 결제 추진 : 정적 가맹점 계좌 정보 노출의 한계를 탈피하고, 1회용 TOTP 결제 토큰 (사용 즉시 만료)를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- 사기 방어 고도화 및 디지털 디스플레이 표출 추진 : 스티커 덧붙이기(큐싱)에 무방비의 한계를 탈피하고, 디지털 디스플레이 표출 및 전자서명 무결성 검증을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
