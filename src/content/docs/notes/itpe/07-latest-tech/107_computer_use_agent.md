## Ⅰ. 컴퓨터 유즈 에이전트 (Computer Use)의 개요

- 개념 : **멀티모달 비전-언어 모델** (VLM)이 모니터 화면의 스크린샷을 분석하여 인간의 마우스 클릭, 드래그, 키보드 타건 명령을 생성하고 OS 인터페이스를 통해 직접 조작하는 자율 GUI 에이전트
- 배경 및 필요성 : 웹페이지나 이메일 화면 내 은닉된 텍스트로 인한 **간접 프롬프트 인젝션** (Indirect Prompt Injection) 및 파괴적 시스템 조작 위험이 상존하므로 **컨테이너 샌드박스** 격리와 민감 작업 **HITL 승인 게이트** 구축 필수
- 핵심 목적 : 전용 API가 제공되지 않는 레거시 데스크톱 소프트웨어 및 비정형 웹 환경에서 인간 수준의 범용 업무 자동화 실현

## Ⅱ. 컴퓨터 유즈 에이전트 (Computer Use)의 핵심 아키텍처 및 동작 메커니즘

컴퓨터 유즈 에이전트는 **화면 캡처** (Screenshot) 취득 → **시각적 접지** (Visual Grounding)로 대상 좌표($(x, y)$) 산출 → OS 레벨 입력 도구 호출(Mouse/Keyboard API) → 변경된 화면 재관측 및 목표 달성 검증의 순환 루프 메커니즘을 기반으로 동작하며, 세부적인 아키텍처와 핵심 컴포넌트 간 상호작용 프로세스는 다음과 같음.

```text
┌────────────────────────────────────────────────────────────────────────┐
│             컴퓨터 유즈 에이전트 (Computer Use) 순환 실행 루프          │
└────────────────────────────────────────────────────────────────────────┘
 [ 사용자 자연어 업무 지시 (예: "지난달 영업 실적 엑셀을 열고 요약본 이메일 발송") ]
                             │
                             ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 에이전트 추론 루프 (Agent Reasoning & Execution Loop)                 │
│                                                                        │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ [1] 화면 관측: 가상 OS 데스크톱 스크린샷 취득                  │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   │ Base64 Image
│                                   ▼
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ [2] VLM 시각 추론: 화면 분석 및 목표 UI 좌표 도출              │   │
│   │     "엑셀 아이콘이 (x=240, y=510)에 위치함, 더블클릭 결정"     │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   │ Tool Call: mouse_click(x=240, y=510)
│                                   ▼
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ [3] 보안 가드레일 검증: 대상 윈도우 및 액션 위험성 판정         │   │
│   │     - 안전한 작업 ──> 즉시 인젝션 실행                         │   │
│   │     - 위험한 작업(외부 전송 등) ──> [ HITL 관리자 승인 대기 ]  │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   │ 승인된 입력 이벤트
│                                   ▼
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ [4] OS 입력 주입 (xdotool / PyAutoGUI Action Execution)        │   │
│   │     가상 마우스 커서 이동 및 클릭 발생 ──> OS 윈도우 반응      │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
└───────────────────────────────────┼────────────────────────────────────┘
                                    │ 화면 상태 갱신 (1초 대기)
                                    └─> [ [1] 화면 관측으로 재순환 ]
```

- **화면 관측기** (Screen Capturer) : 가상 디스플레이(X11 / VNC) 화면을 실시간 캡처하여 PNG/JPEG 전송 - 1024x768 또는 1280x800 해상도 정규화로 토큰 소모 최소화
- **시각 추론 코어** (VLM Core) : 화면 내 UI 요소(아이콘, 텍스트, 폼) 인식 및 다음 액션 결정 - CoT(Chain-of-Thought)를 거쳐 목표 지점의 픽셀 좌표($(x, y)$) 계산
- **OS 액션 실행기** (Action Executor) : PyAutoGUI, xdotool 기반 마우스/키보드 하드웨어 이벤트 인젝션 - `mouse_move`, `left_click`, `type`, `key_combination` 등 프리미티브 실행

## Ⅲ. 컴퓨터 유즈 에이전트 (Computer Use)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 전통적 RPA (UiPath / AutomationAnywhere) | 스크립트/API 자동화 (Python/Selenium) | 컴퓨터 유즈 에이전트 (본 토픽) |
|---|---|---|---|
| **동작 기반** | UI 셀렉터(Selector), DOM 트리 매핑 | 내부 REST API, 전용 라이브러리 | 순수 화면 픽셀 시각 인식(VLM) |
| **UI 변경 적응력** | 극도로 취약 (버튼 위치 변경 시 스크립트 중단) | API 변경 없으면 유지 (UI 무관) | 최상 (인간처럼 눈으로 보고 변경된 위치 재탐색) |
| **비정형 업무 처리** | 불가 (정형화된 규칙 경로만 가능) | 불가 (사전 코딩된 로직만 실행) | 최상 (자연어 지시 해석 및 자율 경로 탐색) |
| **개발 및 유지보수** | 화면 요소마다 정밀 셀렉터 튜닝 필요 | 엔드포인트 연동 개발 공수 | 프롬프트 지시만으로 즉각 수행 |

- 컴퓨터 유즈 에이전트는 상기 비교 지표를 바탕으로 비즈니스 요구사항과 운영 인프라 환경을 고려한 최적의 아키텍처를 선정하고, 확장성과 안정성을 균형 있게 확보해야 함.

## Ⅳ. 컴퓨터 유즈 에이전트 (Computer Use)의 주요 한계점 및 해결 방안

- 웹페이지나 피싱 문서 내 은닉 텍스트에 의한 간접 프롬프트 인젝션 :
  - 한계점 : 브라우저로 열람한 외부 웹페이지나 피싱 문서 내에 은닉된 텍스트가 에이전트를 조종하는 간접 프롬프트 인젝션 위험.
  - 해결 방안 : 에이전트가 읽는 웹 화면 콘텐츠를 비신뢰(Untrusted) 데이터로 격리하고 샌드박스 밖 호스트 접근 네트워크를 완전 차단.
- 에이전트의 파일 삭제 및 비인가 송금 등 파괴적 오동작 위험 :
  - 한계점 : 에이전트가 시스템 파일 삭제, 민감 DB 테이블 드롭(Drop) 또는 비인가 외부 송금을 자율적으로 저지르는 파괴적 오동작.
  - 해결 방안 : CUD(생성·수정·삭제) 및 네트워크 전송 등 비가역적 액션에 대해 실행 전 인간 승인(HITL) 팝업 의무화.
- 고해상도 전체 화면 반복 전송에 따른 토큰 비용 및 네트워크 지연 :
  - 한계점 : 고해상도 전체 화면을 매 스텝마다 LLM에 이미지로 전송함에 따라 발생하는 막대한 토큰 비용 및 네트워크 지연.
  - 해결 방안 : 변화가 발생한 화면 국소 영역만 잘라내어 전송하는 차분 캡처(Delta Cropping) 기법 및 클릭 전용 경량 비전 모델 분리.

## Ⅴ. 컴퓨터 유즈 에이전트 (Computer Use) 적용 및 발전을 위한 기술사적 제언

- 호스트 시스템 영향 중심 엔터프라이즈 고도화 : PC 전체 파일 유출 및 악성코드 감염 위험의 한계를 탈피하고, 컨테이너 격리로 종료 시 샌드박스 완전 폐기를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- 인젝션 방어 중심 엔터프라이즈 고도화 : 사내 인트라넷 내부망 감염 확산의 한계를 탈피하고, 아웃바운드 인터넷 화이트리스트 차단을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- 금융/민감 결제 중심 엔터프라이즈 고도화 : 에이전트 자율 오결제 위험의 한계를 탈피하고, 2차 관리자 모바일 MFA 승인 결합을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
