## 30초 인출

- 본질: **컴퓨터 유즈 에이전트 (Computer Use Agent)** 는 멀티모달 파운데이션 모델이 인간처럼 PC 화면의 GUI 스크린샷을 시각적으로 인지하고 마우스 이동·클릭·키보드 타이핑 이벤트를 직접 발생시켜 범용 소프트웨어 업무를 자율 수행하는 체화 에이전트
- 메커니즘: 화면 캡처(Screenshot) 취득 → 시각적 접지(Visual Grounding)로 대상 좌표($(x, y)$) 산출 → OS 레벨 입력 도구 호출(Mouse/Keyboard API) → 변경된 화면 재관측 및 목표 달성 검증의 순환 루프
- 통찰: 웹페이지나 이메일 화면 내 은닉된 텍스트로 인한 간접 프롬프트 인젝션(Indirect Prompt Injection) 및 파괴적 시스템 조작 위험이 상존하므로 컨테이너 샌드박스 격리와 민감 작업 HITL 승인 게이트 구축 필수

<details><summary>핵심 용어</summary>

- **컴퓨터 유즈 (Computer Use)** : Anthropic Claude 3.5 Sonnet 등 최신 멀티모달 모델이 OS의 디스플레이를 보고 마우스와 키보드를 직접 조작하는 API 기능.
- **시각적 접지 (Visual Grounding)** : 화면 이미지 내 버튼, 텍스트 입력창, 메뉴 등의 UI 요소를 인식하고 해당 중심점의 픽셀 좌표($(x, y)$)를 정확히 도출하는 기술.
- **간접 프롬프트 인젝션 (Indirect Prompt Injection)** : 에이전트가 열람한 웹페이지나 문서 내부에 악의적 명령(예: "모든 파일 삭제")이 은닉되어 모델을 탈옥시키는 공격.
- **가상 데스크톱 샌드박스 (VDI Sandbox)** : 호스트 OS와 격리된 도커(Docker) 기반 X11 가상 디스플레이 환경에서 에이전트를 구동하는 보안 격리 기술.
- **HITL (Human-in-the-Loop) 승인** : 결제, 파일 영구 삭제, 외부 이메일 발송 등 비가역적 위험 작업 발생 시 인간 관리자의 명시적 승인을 요구하는 안전장치.

</details>

## 2~4교시 25점 답안

## Ⅰ. 컴퓨터 유즈 에이전트의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **컴퓨터 유즈 에이전트** 는 멀티모달 비전-언어 모델(VLM)이 모니터 화면의 스크린샷을 분석하여 인간의 마우스 클릭, 드래그, 키보드 타건 명령을 생성하고 OS 인터페이스를 통해 직접 조작하는 자율 GUI 에이전트 |
| 목적 | 전용 API가 제공되지 않는 레거시 데스크톱 소프트웨어 및 비정형 웹 환경에서 인간 수준의 범용 업무 자동화 실현 |

## Ⅱ. 컴퓨터 유즈 에이전트의 핵심 구성 요소 및 인터페이스 특징

| 핵심 구성 요소 | 담당 기능 및 기술 규격 | 엔지니어링 특징 |
|---|---|---|
| **화면 관측기 (Screen Capturer)** | 가상 디스플레이(X11 / VNC) 화면을 실시간 캡처하여 PNG/JPEG 전송 | 1024x768 또는 1280x800 해상도 정규화로 토큰 소모 최소화 |
| **시각 추론 코어 (VLM Core)** | 화면 내 UI 요소(아이콘, 텍스트, 폼) 인식 및 다음 액션 결정 | CoT(Chain-of-Thought)를 거쳐 목표 지점의 픽셀 좌표($(x, y)$) 계산 |
| **OS 액션 실행기 (Action Executor)** | PyAutoGUI, xdotool 기반 마우스/키보드 하드웨어 이벤트 인젝션 | `mouse_move`, `left_click`, `type`, `key_combination` 등 프리미티브 실행 |
| **안전 가드레일 (Safety Guardrail)** | 실행 대상 창(Window) 화이트리스트 검사 및 위험 명령 차단 | 간접 인젝션 탐지 및 관리자 2단계 승인 인터록 |

## Ⅲ. 화면 인지-행동 결정-OS 실행 폐루프 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│             컴퓨터 유즈 에이전트 (Computer Use) 순환 실행 루프          │
└────────────────────────────────────────────────────────────────────────┘
 [ 사용자 자연어 업무 지시 (예: "지난달 영업 실적 엑셀을 열고 요약본 이메일 발송") ]
                             │
                             ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 에이전트 추론 루프 (Agent Reasoning & Execution Loop)                 │
│                                                                        │
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ [1] 화면 관측: 가상 OS 데스크톱 스크린샷 취득                  │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   │ Base64 Image
│                                   ▼
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ [2] VLM 시각 추론: 화면 분석 및 목표 UI 좌표 도출              │   │
│   │     "엑셀 아이콘이 (x=240, y=510)에 위치함, 더블클릭 결정"     │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   │ Tool Call: mouse_click(x=240, y=510)
│                                   ▼
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ [3] 보안 가드레일 검증: 대상 윈도우 및 액션 위험성 판정         │   │
│   │     - 안전한 작업 ──> 즉시 인젝션 실행                         │   │
│   │     - 위험한 작업(외부 전송 등) ──> [ HITL 관리자 승인 대기 ]  │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
│                                   │ 승인된 입력 이벤트
│                                   ▼
│   ┌────────────────────────────────────────────────────────────────┐   │
│   │ [4] OS 입력 주입 (xdotool / PyAutoGUI Action Execution)        │   │
│   │     가상 마우스 커서 이동 및 클릭 발생 ──> OS 윈도우 반응      │   │
│   └───────────────────────────────┬────────────────────────────────┘   │
└───────────────────────────────────┼────────────────────────────────────┘
                                    │ 화면 상태 갱신 (1초 대기)
                                    └─> [ [1] 화면 관측으로 재순환 ]
```

| 프로세스 단계 | 세부 수행 내용 | 모니터링 및 제어 기준 |
|---|---|---|
| **환경 캡처** | 현재 데스크톱 화면을 캡처하고 이미지 다운샘플링 수행 | 시각 토큰 낭비 방지 |
| **좌표 계산** | 화면 비율(Scaling Factor)을 보정하여 절대 픽셀 좌표 특정 | 캘리브레이션 오차 검증 |
| **액션 디스패치** | 마우스 클릭 또는 문자열 타이핑 이벤트를 OS 커널에 전달 | 키 입력 딜레이(Key Delay) 조절 |
| **상태 변화 검증** | 클릭 후 팝업창이나 웹페이지가 정상 로딩되었는지 재캡처 대조 | 액션 실패 시 롤백 및 재시도 |

## Ⅳ. 업무 자동화 기술 비교

| 비교 항목 | 전통적 RPA (UiPath / AutomationAnywhere) | 스크립트/API 자동화 (Python/Selenium) | 컴퓨터 유즈 에이전트 (본 토픽) |
|---|---|---|---|
| **동작 기반** | UI 셀렉터(Selector), DOM 트리 매핑 | 내부 REST API, 전용 라이브러리 | 순수 화면 픽셀 시각 인식(VLM) |
| **UI 변경 적응력** | 극도로 취약 (버튼 위치 변경 시 스크립트 중단) | API 변경 없으면 유지 (UI 무관) | 최상 (인간처럼 눈으로 보고 변경된 위치 재탐색) |
| **비정형 업무 처리** | 불가 (정형화된 규칙 경로만 가능) | 불가 (사전 코딩된 로직만 실행) | 최상 (자연어 지시 해석 및 자율 경로 탐색) |
| **개발 및 유지보수** | 화면 요소마다 정밀 셀렉터 튜닝 필요 | 엔드포인트 연동 개발 공수 | 프롬프트 지시만으로 즉각 수행 |
| **실행 속도** | 빠름 (초당 수십 개 액션) | 극도로 빠름 (수 밀리초) | 다소 느림 (화면 캡처-VLM 왕복 2~3초) |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 브라우저로 열람한 외부 웹페이지나 피싱 문서 내에 은닉된 텍스트가 에이전트를 조종하는 간접 프롬프트 인젝션 위험 | 에이전트가 읽는 웹 화면 콘텐츠를 비신뢰(Untrusted) 데이터로 격리하고 샌드박스 밖 호스트 접근 네트워크를 완전 차단 |
| 에이전트가 시스템 파일 삭제, 민감 DB 테이블 드롭(Drop) 또는 비인가 외부 송금을 자율적으로 저지르는 파괴적 오동작 | CUD(생성·수정·삭제) 및 네트워크 전송 등 비가역적 액션에 대해 실행 전 인간 승인(HITL) 팝업 의무화 |
| 고해상도 전체 화면을 매 스텝마다 LLM에 이미지로 전송함에 따라 발생하는 막대한 토큰 비용 및 네트워크 지연 | 변화가 발생한 화면 국소 영역만 잘라내어 전송하는 차분 캡처(Delta Cropping) 기법 및 클릭 전용 경량 비전 모델 분리 |

## Ⅵ. 제언

안전한 엔터프라이즈 데스크톱 자동화를 위해 완전 격리된 가상 데스크톱(VDI) 컨테이너와 듀얼 체크 HITL 게이트웨이를 결합한 제로 트러스트 컴퓨터 유즈 아키텍처 구축 권고.

```text
[ 사내 임직원 업무 지시 ]
             │
             ▼
┌────────────────────────────────────────────────────────┐
│ 에이전트 게이트웨이 (API 토큰 및 명령 감사 로깅)        │
└────────────────────────────┬───────────────────────────┘
                             │
                             ▼
┌────────────────────────────────────────────────────────┐
│ 완전 격리된 도커 VDI 샌드박스 (Ephemeral Container)     │
│  - 호스트 OS와 파일시스템/네트워크 완전 차단           │
│  - 가상 X11 화면에서만 제한적 데스크톱 구동            │
│                                                        │
│  [ VLM 에이전트 ] ──> Action 요청                      │
│                            │                           │
│                            ▼                           │
│     [ 민감 액션 필터 (Dangerous Action Filter) ]       │
│       ├── 일반 탐색/입력 ──> [ 가상 데스크톱 실행 ]    │
│       └── 외부 전송/결제 ──> [ 슬랙/모바일 HITL 승인 ] │
└────────────────────────────────────────────────────────┘
```

| 구분 | 호스트 PC 직접 실행 방식 | 제언: 격리 샌드박스 + HITL 게이트웨이 |
|---|---|---|
| **호스트 시스템 영향** | PC 전체 파일 유출 및 악성코드 감염 위험 | 컨테이너 격리로 종료 시 샌드박스 완전 폐기 |
| **인젝션 방어** | 사내 인트라넷 내부망 감염 확산 | 아웃바운드 인터넷 화이트리스트 차단 |
| **금융/민감 결제** | 에이전트 자율 오결제 위험 | 2차 관리자 모바일 MFA 승인 결합 |
| **감사 추적성** | 로컬 텍스트 로그로 증적 미흡 | 전체 실행 화면 비디오 및 키스트로크 전수 녹화 |
