## 연관 키워드

- 컴퓨터 유즈 에이전트(Computer Use), VLM(Vision-Language Model), 시각적 접지(Visual Grounding)
- 간접 프롬프트 인젝션(Indirect Prompt Injection), 샌드박스(Sandbox), HITL(Human-in-the-Loop), RPA(Robotic Process Automation)

## Ⅰ. 컴퓨터 유즈 에이전트(Computer Use)의 개요

- 핵심 요약 : 화면을 보고 마우스·키보드를 조작하는 자율 GUI 에이전트로, API가 없는 프로그램까지 업무 자동화 범위를 넓히는 기술.
- 개념 : **컴퓨터 유즈 에이전트** (Computer Use)는 **멀티모달 비전-언어 모델** (VLM, Vision-Language Model)이 화면 스크린샷을 해석해 클릭·타이핑 명령을 만들고, 운영체제 입력 장치를 통해 직접 조작하는 GUI(Graphical User Interface) 에이전트다. Anthropic은 2024년 10월 API 베타로 이 기능을 처음 공개했다.
- 배경 및 필요성 : 자율 조작은 오동작 한 번의 비용이 크고, 열람한 웹 페이지의 숨은 문장이 에이전트를 조종하는 **간접 프롬프트 인젝션** (Indirect Prompt Injection) 위험도 있어, 실행 환경을 격리하는 계층과 민감 작업을 사람이 승인하는 계층이 먼저 갖춰져야 한다.
- 주요 목적 : 전용 API가 없는 레거시 데스크톱과 웹 화면에서 사람이 하던 반복 조작을 자동화하는 것.

## Ⅱ. 컴퓨터 유즈 에이전트(Computer Use)의 특징 및 장점

- 핵심 요약 : 화면 픽셀을 직접 읽는 방식이 연동 공수 절감과 UI 변화 대응으로 이어지는 구조.

1. 화면 기반 조작 : 스크린샷을 입력으로 쓰므로 API가 없는 프로그램도 조작 가능 → 레거시 시스템 연동 공수 절감.
2. 시각적 접지 (Visual Grounding, 화면 속 UI 요소의 위치 좌표를 찾아 대응시키는 능력) : 버튼 위치가 바뀌어도 화면을 다시 보고 재탐색 → 셀렉터 유지보수 감소.
3. 자연어 지시 해석 : 업무 지시를 읽고 실행 경로를 스스로 구성 → 지시 문장만 바꿔도 업무 변경에 즉시 대응.

## Ⅲ. 컴퓨터 유즈 에이전트(Computer Use)의 구조 (흐름)

- 핵심 요약 : 관측, 추론, 위험 판정, 입력 주입이 순환하며, 위험 작업은 사람 승인을 거치는 루프 구조.
- 화면 관측기 (Screen Capturer) : 가상 데스크톱 화면을 캡처해 모델 입력으로 전달.
- 시각 추론 코어 (VLM Core) : 화면의 UI 요소를 인식하고 다음 행동과 목표 좌표를 결정.
- OS 액션 실행기 (Action Executor) : 마우스 이동, 클릭, 타이핑 같은 입력 이벤트를 OS에 주입.

```text
[ 자연어 업무 지시 ]
        ↓
[1] 화면 관측 (스크린샷)
        ↓
[2] VLM 시각 추론 (좌표 산출)
        ↓
[3] 위험 작업 판정
        ↓ (위험 작업이면)
[사람 승인 대기]
        ↓
[4] OS 입력 주입 (마우스·키보드)
        ↓
[1] 화면 재관측 (순환)
```

```text
[ 에이전트 (VLM 추론 코어) ]
        ↓ 스크린샷 입력
[ 격리된 가상 데스크톱 ]
        ↓ 마우스·키보드 이벤트
[ 실제 애플리케이션 UI ]
```

## Ⅳ. 컴퓨터 유즈 에이전트(Computer Use)와 기존 자동화의 비교

- 핵심 요약 : 정형 규칙에 묶인 RPA와 달리 화면 인식 에이전트는 UI 변화와 비정형 업무에 강하지만, 판단을 통제하는 비용이 크다.

| 비교 축 | 전통적 RPA | 스크립트·API 자동화 | 컴퓨터 유즈 에이전트 |
| --- | --- | --- | --- |
| 동작 기준 | UI 셀렉터, DOM 트리 매핑 | 내부 API 호출 | 화면 픽셀의 시각 인식 |
| UI 변경 대응 | 취약 (요소 위치 변경 시 중단) | API가 바뀌지 않으면 유지 | 화면을 보고 재탐색 |
| 비정형 업무 | 불가 (정해진 경로만 실행) | 불가 (사전 코딩된 로직만 실행) | 자연어 지시로 경로 탐색 |
| 유지보수 | 요소별 셀렉터 튜닝 | 엔드포인트 연동 개발 | 지시문 수정 중심 |

- 선택 기준 : 안정적인 API가 있으면 스크립트, 정형 반복이면 RPA, 화면만 남은 비정형 업무에만 컴퓨터 유즈 에이전트를 적용한다.

## Ⅴ. 컴퓨터 유즈 에이전트(Computer Use)의 한계와 방안

- 핵심 요약 : 인젝션, 파괴적 오동작, 토큰 비용 문제를 격리, 승인, 화면 축소로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 간접 프롬프트 인젝션 | 열람한 웹·문서의 숨은 문장이 에이전트 지시를 가로채 내부망으로 확산 | 화면 콘텐츠를 비신뢰 데이터로 격리하고 **샌드박스**(Sandbox) 밖 외부 통신을 화이트리스트로 제한 | 인젝션 탐지 건수, 차단 건수 |
| 파괴적 오동작 | 파일 삭제, 비인가 송금 등 되돌리기 어려운 조작 | 삭제·송신 같은 비가역 작업 전 **HITL**(Human-in-the-Loop, 사람 승인 단계) 의무화 | 승인 거절률, 롤백 건수 |
| 전체 화면 반복 전송 | 매 단계 전체 화면을 전송해 토큰 비용과 응답 지연 증가 | 변경된 영역만 잘라 보내는 차분 캡처 적용 | 단계당 토큰 사용량 |

## Ⅵ. 컴퓨터 유즈 에이전트(Computer Use)에 대한 기술사적 제언

- 핵심 요약 : 실행 환경, 권한, 승인 체계를 도입 전 거버넌스로 정하고 적용 범위를 단계적으로 넓히는 것이 바람직하다.

1. 정보보안 조직과 현업 조직이 함께 자동화 대상 업무의 위험 등급표를 만들고, 등급에 따라 승인 수준을 달리 적용하는 거버넌스를 세워야 한다.
2. 도입 초기에는 조작 로그와 화면 기록을 빠짐없이 보관하고 사고 분석 절차를 갖춘 뒤, 검증된 업무부터 적용 범위를 넓히는 방식이 바람직하다.
3. 에이전트가 쓰는 계정은 사람 계정과 분리하고 최소 권한만 부여하는 신원 관리 정책을 적용해야 한다.

## Ⅶ. 결론

- 핵심 요약 : 컴퓨터 유즈 에이전트는 사람의 화면 조작을 모사하는 범용 업무 자동화 계층이다.
- 시사점 : 편의성은 격리와 승인이 갖춰질 때 신뢰할 수 있는 자산이 되므로, 보안 통제를 기능 도입의 전제로 둔다.
