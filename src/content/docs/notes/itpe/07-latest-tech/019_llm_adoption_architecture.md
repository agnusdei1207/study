## 지식 로드맵 내 현재 위치

지식 위치: AI 서비스 설계·운영 → 언어모델 연계 → **LLM 도입 아키텍처**

## 30초 인출

- 본질: **LLM 도입 아키텍처** 는 업무 요청·데이터·모델·통제를 연결해 언어모델 서비스를 운영하는 구성
- 메커니즘: 인증·정책 확인 → 검색·모델 실행 → 응답 검증 → 품질·비용·오류 관찰

<details>
<summary>핵심 용어</summary>

- **대규모 언어 모델(Large Language Model, LLM)** : 대규모 언어 자료에서 학습해 언어 입력을 처리하고 텍스트 등을 생성하는 모델
- **LLM 도입 아키텍처(LLM Adoption Architecture)** : 업무 요청·데이터·모델·보안·운영 구성요소를 연결한 서비스 구조
- **첫 토큰 지연시간(Time To First Token, TTFT)** : 요청 이후 첫 응답 토큰이 전달되기까지의 시간
- **시맨틱 캐싱(Semantic Caching)** : 의미가 유사한 요청의 결과를 재사용하는 캐시 방식; 재사용 적합성 검사가 필요
- **가드레일(Guardrail)** : 입력·출력·도구 사용에 정책 검사를 적용하는 통제 장치
</details>

### Ⅴ. 제135회 기출 요구에 맞춘 확장

실제 문항은 공공기관의 LLM 적용 고려사항 **5가지**와 현재 구현 가능한 아키텍처 **5가지**를 요구. 아래 구분은 문제지에 제시된 공식 정답 분류가 아니라, 데이터 통제와 모델 운용 방식으로 구분한 답안 예시.

| 적용 고려사항 | 확인 내용 |
|---|---|
| 데이터·보안 | 개인정보·기밀정보의 입력, 저장, 국외 이전, 접근 통제 |
| 응답 품질 | 업무별 정확성·근거·편향 평가와 사람 검토 |
| 성능·가용성 | 지연시간, 처리량, 장애 대응과 서비스 수준 |
| 비용 | 구축·호출·학습·운영 비용과 사용량 변화 |
| 책임·운영 | 모델·프롬프트 변경관리, 기록, 담당자와 조달 조건 |

| 구현 아키텍처 예 | 모델·데이터 운영 방식 | 선택 조건 |
|---|---|---|
| 외부 모델 API | 기관 애플리케이션에서 외부 모델 호출 | 빠른 도입과 외부 전송 허용 범위 검토 |
| 기관 운영 모델 | 기관 통제 인프라에서 모델 직접 추론 | 높은 데이터 통제와 운영 역량 필요 |
| 외부 모델 API + RAG | 기관 자료 검색 후 필요한 문맥만 외부 모델에 전달 | 검색 품질과 외부 전송 범위 통제 |
| 기관 운영 모델 + RAG | 기관 내부 자료 검색과 모델 추론을 같은 통제 경계에서 수행 | 검색·추론 인프라 운영 비용 검토 |
| 과업 맞춤 모델 | 허용된 학습 자료로 모델을 미세조정해 배포 | 학습 자료 권리·품질·갱신 비용 검토 |

### Ⅵ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 업무 전체에 일괄 도입하면 응답 품질·비용·책임 조건을 실제 사용 전에 판단하기 어려움 | 측정 가능한 한정 업무에서 품질·지연·비용·위험 기준선을 비교하고, 조건을 충족한 사용 경로부터 운영 범위를 넓힘 |
