## 30초 인출

- 본질: **LLM 도입 아키텍처** 는 기업 및 공공기관의 비즈니스 애플리케이션과 대규모 언어모델을 결합하기 위해 보안 게이트웨이, RAG 오케스트레이션, 모델 서빙, 관측성을 계층화한 통합 참조 아키텍처
- 메커니즘: 사용자 질의 인입 시 PII 필터링과 시맨틱 캐시를 거쳐, 지식 검색기(Vector DB)와 적응형 라우터(Router)를 통해 프라이빗 sLLM 또는 상용 API로 분기 추론 후 가드레일 검증 수행
- 통찰: 무분별한 외부 API 호출은 기밀 유출과 토큰 비용 급증을 초래하므로 작업 난이도 기반의 동적 라우팅 및 시맨틱 캐싱(Semantic Cache) 결합 필수

<details><summary>핵심 용어</summary>

- **LLM 도입 아키텍처 (LLM Adoption Architecture)** : 보안, 성능, 비용, 정확성을 고려하여 LLM을 엔터프라이즈 시스템에 안전하게 연계하는 계층형 아키텍처.
- **TTFT (Time To First Token)** : 사용자의 요청이 전달된 후 LLM이 첫 번째 스트리밍 토큰을 출력하기까지 소요되는 지연시간.
- **시맨틱 캐싱 (Semantic Caching)** : 기존 질의와 의미적으로 유사한 새 질의가 인입될 경우 LLM 추론을 생략하고 캐시된 응답을 즉시 반환하여 비용을 절감하는 기법.
- **스마트 라우터 (Model Router)** : 질의의 복잡도, 보안 민감도, 비용 예산을 평가하여 최적의 모델(온프레미스 sLLM vs 외부 고성능 LLM)로 자동 분기하는 엔진.
- **LLMOps (LLM Operations)** : LLM 기반 애플리케이션의 프롬프트 템플릿, 파인튜닝 데이터셋, 벡터 인덱스, 배포 및 성능을 관리하는 전주기 운영 프레임워크.

</details>

## 2~4교시 25점 답안

## Ⅰ. LLM 도입 아키텍처의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **LLM 도입 아키텍처** 는 대규모 언어모델(LLM)을 기업의 비즈니스 로직, 데이터베이스, 레거시 시스템과 안전하게 결합하기 위해 보안, 검색 증강, 오케스트레이션, 서빙 인프라를 표준화한 엔터프라이즈 소프트웨어 아키텍처 |
| 목적 | 내부 기밀 유출 방지 및 규제 준수, 환각 억제를 통한 응답 신뢰성 확보, 추론 지연시간(Latency) 및 토큰 운영 비용의 최적화 |

## Ⅱ. LLM 도입 시 5대 핵심 고려사항 및 기술적 특징

| 구분 | 5대 핵심 고려사항 | 세부 공학적 검토 기준 및 특징 |
|---|---|---|
| **보안 및 규제 준수** | 데이터 프라이버시 | 개인정보(PII) 외부 유출 차단, 망 분리 규제 준수, 역할 기반 접근 제어(RBAC) |
| **정확도 및 환각 제어** | 도메인 사실성 그라운딩 | 최신 사내 지식 기반 RAG 결합, 인용 출처(Attribution) 표기 및 할루시네이션 가드레일 |
| **응답 성능 (Latency)** | 서비스 사용자 경험 | 첫 토큰 생성 지연(TTFT) 최소화, 스트리밍 서빙 지원, vLLM/TensorRT-LLM 가속 |
| **TCO 비용 최적화** | 지속 가능한 토큰 경제 | 질의 캐싱(Semantic Cache), 프롬프트 압축, 저비용 소형 모델(sLLM) 동적 라우팅 |
| **운영 및 관측성** | 지속적 품질 관리(LLMOps) | 프롬프트 버전 관리, 입출력 토큰 감사 로깅, 사용자 피드백(Thumbs up/down) 수집 |

## Ⅲ. 엔터프라이즈 LLM 도입 참조 아키텍처 및 요청 처리 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ 엔터프라이즈 LLM 4계층 참조 아키텍처 ]                │
└────────────────────────────────────────────────────────────────────────┘
                                    │
 [ 1. 엔터프라이즈 접점 계층 (Enterprise Gateway) ]
  - API 게이트웨이, OAuth 2.0 / SSO 인증, 속도 제한(Rate Limiting)
  - PII 자동 마스킹 (개인식별정보 차단) & 시맨틱 캐시 (Redis/GPTCache)
                                    │
                                    ▼ (캐시 미스 시)
┌────────────────────────────────────────────────────────────────────────┐
│ [ 2. 지식 및 오케스트레이션 계층 (Orchestration & RAG) ]               │
│  - 사용자 질의 분석 및 의도 분류 (Intent Classification)               │
│  - 엔터프라이즈 벡터 DB 하이브리드 검색 (Milvus / Pinecone)            │
│  - Re-ranker 및 동적 프롬프트 조립 (System Prompt + Search Chunks)     │
└────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [ 3. 스마트 모델 라우팅 및 추론 계층 (Model Serving) ]                 │
│  - 스마트 라우터 ──┬──(사내 기밀/경량 작업)──> [ 사내 온프레미스 sLLM ]   │
│                   └──(고난도 범용 추론)────> [ 전용 가상망 상용 LLM ]   │
└────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [ 4. 출력 가드레일 및 관측성 계층 (Guardrails & LLMOps) ]               │
│  - 환각 감지, JSON 스키마 유효성 검사, 유해성 필터링                   │
│  - LangSmith / OpenTelemetry 기반 토큰 비용, 지연시간, 드리프트 모니터링 │
└────────────────────────────────────────────────────────────────────────┘
```

| 아키텍처 계층 | 핵심 컴포넌트 | 공학적 기여 및 역할 |
|---|---|---|
| **게이트웨이** | PII 마스킹 프록시, 시맨틱 캐시 | 민감정보 외부 유출 원천 차단 및 반복 질의 API 비용 0원화 |
| **오케스트레이션** | LangChain / LlamaIndex, 하이브리드 검색 | 사내 최신 규정·문서를 검색하여 프롬프트에 동적 결합 |
| **모델 서빙** | vLLM, Triton Server, PagedAttention | GPU 메모리 단편화 제거 및 다중 사용자 동시 추론 처리량 3배 향상 |
| **관측성** | Tracing 엔진, 피드백 수집기 | 프롬프트 버전별 F1-Score 추적 및 이상 입출력 감사 증적 보존 |

## Ⅳ. 엔터프라이즈 구현 가능한 LLM 5대 아키텍처 패턴 비교

| 패턴 구분 | 아키텍처 구성 방식 | 데이터 보안 수준 | 구축 및 운영 비용 | 적합한 업무 영역 |
|---|---|---|---|---|
| **1. 외부 상용 API** | 공용 클라우드 LLM API 호출 | 낮음 (외부 유출 우려) | 초기 비용 0 (종량제) | 일반 공개 문서 요약, 대외 마케팅 |
| **2. 전용 가상망 API** | CSP 전용 테넌트(Azure OpenAI 등) | 보통 (전용망 격리) | 중-고 (인스턴스 약정) | 기업 내부 일반 챗봇, 사내 비서 |
| **3. 외부 API + RAG** | 사내 지식 검색 후 외부 LLM 추론 | 보통 (검색 청크 유출) | 중간 (벡터 DB + API) | 사내 규정 조회, IT 헬프데스크 |
| **4. 온프레미스 sLLM** | 사내 서버에 오픈소스 모델 구축 | 매우 높음 (에어갭 폐쇄망) | 고 (초기 GPU 인프라 투자) | 금융 계정계, 국방, 핵심 R&D |
| **5. 특화 미세조정(FT)** | 사내 코퍼스로 파라미터 파인튜닝 | 매우 높음 (완전 내재화) | 최고 (데이터 가공 + 학습) | 의료 진단, 법률 전문 분석, 코드 생성 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 고성능 상용 LLM API 호출 증가 시 월간 토큰 비용이 기하급수적으로 폭증 | 유사 질의를 코사인 유사도로 즉시 반환하는 시맨틱 캐시(Semantic Cache) 및 단순 분류용 경량 sLLM 우선 배치 |
| 사용자 질의 내에 악의적인 프롬프트 인젝션이 유입되어 사내 RAG 문서의 기밀이 외부로 누출 | 시스템 프롬프트 보호 샌드박스, NeMo Guardrails 입력 검증 및 권한 기반 문서 필터링(ACL RAG) 적용 |

## Ⅵ. 제언

단일 거대 모델 의존에서 탈피하여 질의의 복잡도와 보안 등급에 따라 모델을 동적으로 선택하는 스마트 모델 라우터(Router) 기반 하이브리드 아키텍처 구축.

```text
[ 사용자 비즈니스 질의 인입 ]
               │
               ▼
[ 스마트 모델 라우터 (Semantic Router) ]
   ├── 조건 1: 보안 민감 데이터(개인정보/기밀) 포함 ──> [ 사내 온프레미스 sLLM (vLLM) ]
   ├── 조건 2: 단순 요약 / 정형 분류 / 엔티티 추출 ───> [ 경량 오픈소스 모델 (Llama 3 8B) ]
   └── 조건 3: 고난도 다단계 논리 추론 / 코드 작성 ──> [ 상용 대형 LLM (GPT-4o / Claude) ]
               │
               ▼
[ 응답 수합 및 비용/지연 모니터링 대시보드 기록 ]
```

| 구분 | 단일 상용 LLM 일괄 호출 | 제언: 스마트 라우터 하이브리드 |
|---|---|---|
| **토큰 비용** | 모든 요청에 최고가 모델 적용으로 비용 낭비 | 단순 작업의 소형 모델 분기로 운영 비용 70% 절감 |
| **보안 격리** | 민감 데이터가 외부 CSP로 전송되는 위험 | 기밀 데이터는 사내 에어갭 인프라에서 완결 처리 |
| **응답 지연** | 외부 네트워크 호출 지연 발생 | 경량 모델 및 시맨틱 캐시 활용으로 평균 응답 시간 대폭 단축 |
