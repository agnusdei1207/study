## 답안 골격
```text
[추론 모델(LRM)] ◀━━ 머리: Ⅶ 내 의견 (테스트 타임 컴퓨팅 기반 자가 검증 추론과 도메인 특화 경량 증류 모델 구축)
 ┃
 ┣━ Ⅰ 개요 ───── 다음 토큰 통계적 예측(System 1) 한계 → 답안 산출 전 긴 생각의 사슬(System 2)을 수행하는 대형 추론 모델
 ┣━ Ⅱ 특징 ───── 테스트 타임 컴퓨트 스케일링 · 긴 생각의 사슬(Long CoT) · 자가 오류 수정(Self-Correction) · 규칙 기반 보상
 ┣━ Ⅲ 구조 ───── 사전학습 백본 + 순수/대규모 강화학습 엔진(GRPO/PPO) + 규칙 기반 검증기(Verifier) + 숨겨진 CoT 버퍼
 ┣━ Ⅳ 흐름 ───── ① 복합 질의 수신 → ② 내부 `<think>` 단계 진입(가설 탐색·분기·검증) → ③ 오류 발견 시 백트래킹 → ④ 최종 응답 생성
 ┣━ Ⅴ 비교 ───── 전통 LLM(System 1) vs 추론 모델(LRM, System 2) (즉시 직관적 생성 vs 다단계 숙고 및 자가 검증)
 ┗━ Ⅵ 실무 ───── 응답 지연(수십 초 소요) / 과도한 추론 토큰에 따른 서빙 비용 / 주관식 창의성 평가 적용 한계
```
- 필수 키워드: 추론 모델(LRM) · 테스트 타임 컴퓨트(Test-time Compute) · 긴 생각의 사슬(Long CoT) · 시스템 1 vs 시스템 2 · 자가 반조(Self-Reflection) · 검증기(Verifier)
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 시스템 2 아키텍처 및 CoT 버퍼 구조 → Ⅴ 전통 LLM vs LRM 비교표 / 25점 = Ⅰ~Ⅶ 전개, 테스트 타임 컴퓨팅 스케일링 법칙 수식 및 OpenAI o1/DeepSeek-R1 메커니즘 집중
- 기출: 미출제. 예상: "최근 복합 추론과 수학/코딩 영역에서 혁신을 일으키고 있는 대형 추론 모델(LRM, Large Reasoning Model)의 개념, System 2 인지 아키텍처, 테스트 타임 컴퓨팅 스케일링 원리를 설명하시오."

## 한 줄 본질
- 질문 즉시 다음 단어를 확률적으로 뱉어내는 기존 LLM의 논리 비약과 복합 추론 한계 → 최종 답변 전에 보이지 않는 내부 토큰을 소모하며 오류를 스스로 수정하는 긴 추론(System 2 Thinking) 수행 → 수학·코딩·과학 난제 해결력의 비약적 향상 / 응답 대기시간(Latency)과 추론 비용 급증

## 핵심 용어
- System 1 vs System 2: 노벨상 수상자 대니얼 카너먼의 인지 이론으로, System 1은 빠르고 직관적인 사고(전통 LLM), System 2는 느리고 논리적이며 검증을 거치는 숙고(LRM 추론 모델)를 의미
- 테스트 타임 컴퓨트(Test-time Compute): 모델 학습(Pre-training) 때뿐만 아니라, 추론(Inference) 단계에서 더 많은 연산 자원과 토큰을 소모할수록 정답률이 지수적으로 올라가는 새로운 스케일링 법칙
- 프로세스 보상 모델(PRM, Process Reward Model): 최종 결과뿐만 아니라 생각의 사슬(CoT)의 각 단계별 타당성에 점수를 매겨 올바른 추론 경로를 강화하는 기법

## 핵심 통찰
- 기존 LLM의 스케일링 법칙(사전 학습 데이터와 파라미터 증대)이 데이터 고갈로 둔화되는 시점에서, "추론 시간 연산량(Inference-time Compute)"을 늘려 성능을 올리는 새로운 지평을 개척
- 추론 모델의 핵심은 사람이 작성한 정답 풀이(SFT)를 단순히 흉내 내는 것이 아니라, 규칙 기반 검증기(컴파일러, 수학 엔진)와의 강화학습을 통해 모델이 "스스로 생각하고 의심하는 방법"을 깨우치게 하는 데 있음
- 모든 업무에 LRM을 쓰는 것은 비효율적이며, 즉답이 필요한 챗봇에는 전통 LLM을, 계약서 분석·코드 리팩토링·금융 모델링 등 오류 비용이 치명적인 영역에 LRM을 배치해야 함

## 이웃 토픽과 구분
- LRM vs 전통 LLM: 전통 LLM은 토큰당 일정한 FLOPs를 소모하며 즉시 출력 / LRM은 난이도에 따라 수백~수천 개의 생각 토큰(Thinking Tokens)을 동적으로 소모하며 최적 해 도출

## 문제·원인·대책
- 적용 상황: 고객 실시간 대화 서비스에 추론 모델(LRM) 도입 시 사용자 이탈 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 단순 질문에도 15초 이상 생각 토큰을 생성하며 응답 지연 | 질문 복잡도와 무관하게 고정된 긴 CoT 루프 진입 | 쿼리 난이도 분류 라우터 배치 및 적응형 추론 깊이(Adaptive Compute) 제어 | 단순 질의 즉시 반환 및 서버 비용 60% 절감 |
| 생각의 사슬 내에서 결론을 내리지 못하고 맴도는 오버씽킹(Overthinking) | 종료 조건 판정 기준 미비 및 무한 자가 수정 루프 | 최대 사고 토큰(Max Thinking Budget) 강제 상한 설정 | 무한 루프 차단 및 지연시간 상한 보장 |
| 내부 생각 과정(CoT)에서 사내 비밀 및 비속어 노출 | 모델의 내부 탐색 과정이 여과 없이 스트리밍됨 | 생각 토큰 버퍼 숨김 처리 및 가드레일 필터 통과 후 최종 답변만 노출 | 보안 유출 방지 및 정제된 사용자 경험 제공 |
