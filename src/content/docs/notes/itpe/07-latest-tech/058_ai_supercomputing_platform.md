## 연관 키워드

- AI 슈퍼컴퓨팅 플랫폼, 고성능 컴퓨팅(HPC), 3D 병렬화, NVLink, GPUDirect Storage, 토폴로지 인지 스케줄링
- MFU, 인메모리 체크포인팅, Ultra Ethernet, 직접 칩 액체 냉각(DLC), 핫 스페어, PUE

## Ⅰ. AI 슈퍼컴퓨팅 플랫폼의 개요

- 핵심 요약 : 수만 개의 가속기와 고속 네트워크, 스토리지, 스케줄러를 수직 통합해 거대 AI 모델을 학습하고 서빙하는 고성능 인프라.
- 개념 : 거대언어모델(LLM)과 대규모 파운데이션 모델의 분산 학습과 저지연 서빙을 위해, GPU·NPU 같은 이기종 가속기, **고대역폭 메모리** (HBM, High Bandwidth Memory), 무손실 고속 인터커넥트, 병렬 스토리지, 컨테이너 오케스트레이션을 통합한 **고성능 컴퓨팅** (HPC, High-Performance Computing) 플랫폼.
- 배경 및 필요성 : 단일 서버 용량을 넘는 거대 모델이 등장해 수천 대의 노드가 하나의 컴퓨터처럼 협업해야 하고, 노드 간 통신 지연으로 연산 장치가 기다리는 지연 노드(Straggler) 현상이 학습 효율을 떨어뜨리므로 인프라 전체를 함께 설계할 필요가 생김.
- 주요 목적 : 분산 학습의 확장 효율 확보, 노드 간 통신 병목 최소화, 체크포인트 입출력 가속, 장애 발생 시 중단을 줄이는 복구 체계 확보.

## Ⅱ. AI 슈퍼컴퓨팅 플랫폼의 특징 및 장점

- 핵심 요약 : 3D 병렬화, 노드 내부 고속 연결, 직접 스토리지 접근, 토폴로지 인지 배치가 결합되어 노드 증설에 따른 효율 저하를 줄이는 구조.

1. **3D 병렬화** (3D Parallelism) : 데이터 병렬(DP, Data Parallelism), 텐서 병렬(TP, Tensor Parallelism), 파이프라인 병렬(PP, Pipeline Parallelism)을 결합 → 단일 GPU에 들어가지 않는 모델을 수만 개 GPU로 확장.
2. **NVLink** 연결 : 랙 내부 GPU가 PCIe 버스를 거치지 않고 고속 메시 형태로 메모리를 직접 공유 → 노드 내 통신 지연 감소.
3. **GPUDirect Storage** (GDS) : CPU 메모리를 거치지 않고 NVMe 스토리지와 GPU 메모리 사이에서 직접 데이터를 전송 → 체크포인트 저장 시간 단축.
4. **토폴로지 인지 스케줄링** (Topology-Aware Scheduling) : 네트워크 스위치 연결 구조를 고려해 물리적으로 가까운 GPU를 우선 할당 → 통신 거리와 혼잡 감소.

## Ⅲ. AI 슈퍼컴퓨팅 플랫폼의 구조 (흐름)

- 핵심 요약 : 가속 컴퓨팅부터 분산 학습 프레임워크까지 다섯 층이 쌓인 풀스택 구조이며, 병렬화는 세 축의 역할 분담으로 수행됨.

```text
[ AI 슈퍼컴퓨팅 플랫폼 풀스택 구조 ]

5. 분산 학습·서빙 프레임워크
          ↓
4. 클러스터 오케스트레이션
          ↓
3. 초저지연 무손실 네트워크
          ↓
2. 고속 병렬 파일 스토리지
          ↓
1. 가속 컴퓨팅과 랙 인프라
```

```text
[ 3D 병렬화의 역할 분담 ]

데이터 병렬 (DP)
   → 데이터 묶음을 나눠 복제본 여럿이 학습
텐서 병렬 (TP)
   → 레이어 내부의 행렬을 여러 GPU에 분할
파이프라인 병렬 (PP)
   → 레이어 묶음을 노드별로 나눠 순차 처리
```

- **MFU** (Model FLOPs Utilization) : 실제 모델 연산량을 장치의 이론상 최대 연산량으로 나눈 값으로, 인프라 활용 효율을 보는 핵심 지표.

## Ⅳ. 전통적 HPC와 AI 슈퍼컴퓨팅 플랫폼의 비교

- 핵심 요약 : 전통 HPC는 64비트 정밀도와 지점 간 통신이 중심이고, AI 슈퍼컴퓨팅은 저정밀 행렬 연산과 집합 통신, 대역폭 중심 구조가 중심.

| 비교 항목 | 전통적 과학계산 HPC | AI 슈퍼컴퓨팅 플랫폼 |
| --- | --- | --- |
| 핵심 워크로드 | 기상 예보, 유체역학, 분자 시뮬레이션 | 초거대 언어 모델 사전학습, 멀티모달 텐서 연산 |
| 주요 연산 정밀도 | 배정밀도 부동소수점 (FP64) | 저정밀도 부동소수점 (FP8, FP16, BF16) |
| 주요 가속기 | 멀티코어 CPU 중심, 일부 가속기 | 대규모 병렬 GPU·NPU와 고대역폭 메모리 |
| 통신 패턴 | 지점 간 메시지 전송 위주 | 전역 집합 통신 (All-Reduce, All-to-All) |
| 스토리지 I/O | 대용량 결과 파일의 순차 쓰기 | 무작위 미니배치 읽기와 대규모 체크포인트 쓰기 |
| 목표 성능 지표 | LINPACK 기반 FLOPS | MFU, FP8 기준 연산 처리량 |

- AI 슈퍼컴퓨터는 정밀한 64비트 연산보다 저정밀 행렬 곱셈, 메모리 대역폭, 노드 간 집합 통신 대역폭에 특화된 구조임.

## Ⅴ. AI 슈퍼컴퓨팅 플랫폼의 한계와 방안

- 핵심 요약 : 노드 고장에 따른 학습 중단, 집합 통신 병목, 고밀도 발열과 전력 부담의 세 한계를 체크포인트와 자동 복구, 개방형 고속 패브릭, 액체 냉각으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 노드 하나의 고장으로 전체 학습 중단 | 대규모 클러스터에서 평균 고장 간격(MTBF, Mean Time Between Failures)이 짧아져 학습이 자주 멈춤 | 인메모리 체크포인팅, 고장 노드 자동 격리와 **핫 스페어** (Hot Spare) 자동 대체 | 평균 복구 시간, 학습 중단 횟수 |
| 집합 통신 병목 | 연산 속도를 네트워크 대역폭이 따라가지 못해 지연 노드 증가 | 통신과 연산을 겹치는 파이프라인 최적화, **Ultra Ethernet** 기반 무손실 패브릭 도입 (Ultra Ethernet Consortium의 1.0 사양은 2025년 6월 공개, Linux Foundation 발표 기준) | 통신 대기 시간 비율, 대역폭 활용률 |
| 고밀도 발열과 전력 부담 | 랙당 전력 밀도가 높아 전통적 공랭 방식으로는 냉각이 어려움 | 직접 칩 액체 냉각(DLC, Direct Liquid Cooling) 도입, 2상 액침 냉각 검토, 장기 전력 공급 계획 수립 | 랙당 전력 밀도, 냉각 효율 |

## Ⅵ. AI 슈퍼컴퓨팅 플랫폼에 대한 기술사적 제언

- 핵심 요약 : 개방형 패브릭 표준, 소프트웨어 생태계, 전력 효율 설계를 함께 고려하여 AI 인프라를 특정 기술에 종속되지 않는 자산으로 운영.

1. 특정 벤더의 독점 연결 기술에 종속되지 않도록 개방형 AI 패브릭 표준을 선제적으로 검토하고, 비용 효율이 높은 이더넷 기반 고속 통신 구조를 준비하는 것이 바람직하다.
2. 국산 가속기를 도입할 때는 하드웨어 성능보다 주요 딥러닝 프레임워크와 호환되는 컴파일러와 통신 라이브러리 생태계를 함께 육성하는 전략이 중요하다.
3. 대규모 설비를 설계할 때는 전력 변환 손실과 폐열 재활용을 함께 고려하고, 전력 사용 효율(PUE, Power Usage Effectiveness)을 설계 단계의 관리 기준으로 두는 것이 필요하다.

## Ⅶ. 결론

- 핵심 요약 : 수만 개의 가속기를 하나의 컴퓨터처럼 묶는 풀스택 인프라로서 거대 AI 모델 학습과 서빙의 물리적 기반.
- 시사점 : 연산 장치 성능보다 통신, 스토리지, 냉각을 함께 설계하는 역량이 AI 인프라 경쟁력을 결정함.
