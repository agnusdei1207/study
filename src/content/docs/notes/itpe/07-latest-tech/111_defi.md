## 연관 키워드

- DeFi(Decentralized Finance), 스마트 계약(Smart Contract), AMM(Automated Market Maker), 유동성 풀(Liquidity Pool)
- 플래시론(Flash Loan), 오라클(Oracle), TWAP(Time-Weighted Average Price), 결합성(Composability)
- 스테이블코인(Stablecoin), 롤업(Rollup), CeFi(Centralized Finance), 자금세탁방지(AML, Anti-Money Laundering)

## Ⅰ. DeFi(Decentralized Finance)의 개요

- 핵심 요약 : 중개자 없이 블록체인 위의 스마트 계약으로 대출, 거래, 파생상품을 제공하는 개방형 금융 체계.
- 개념 : **탈중앙화 금융** (DeFi, Decentralized Finance)은 중앙 중개자의 개입 없이 퍼블릭 블록체인의 분산 원장과 **스마트 계약** (Smart Contract, 조건이 충족되면 자동 실행되는 블록체인 코드)을 기반으로 대출, 결제, 거래, 파생상품을 제공하는 개방형 금융 서비스 체계다.
- 배경 및 필요성 : 코드 취약점을 노린 재진입 공격과, **플래시론** (Flash Loan, 담보 없이 한 트랜잭션 안에서 빌려 쓰고 갚는 대출)을 악용한 가격 조작 위험이 있으므로, 여러 출처의 가격을 합산하는 오라클 설계와 코드 감사 체계가 먼저 필요하다.
- 주요 목적 : 금융 중개 비용을 줄이고, 계좌 개설 없이 지갑만으로 금융에 접근할 수 있게 하며, 서비스를 조합하는 결합성을 실현하는 것.

## Ⅱ. DeFi(Decentralized Finance)의 특징 및 장점

- 핵심 요약 : 무허가성과 결합성, 자기 보관 구조가 접근성과 혁신 속도로 이어지는 체계.

1. 무허가성 (Permissionless) : 누구나 지갑 주소만으로 참여 → 금융 소외 계층의 접근 장벽 완화.
2. 결합성 (Composability) : 프로토콜끼리 레고 블록처럼 연결 → 새 금융 상품을 빠르게 조합.
3. 자기 보관 (Non-custodial) : 사용자가 개인 키로 자산을 직접 보관 → 중앙 기관의 자산 몰수 위험 제거.

## Ⅲ. DeFi(Decentralized Finance)의 구조 (흐름)

- 핵심 요약 : 사용자의 서명이 스마트 계약 풀과 상호작용해 온체인 수식으로 교환이 완결되는 구조.
- **AMM** (Automated Market Maker, 자동 시장 조성자) : 호가창 대신 수식으로 교환 가격을 정하는 스마트 계약.
- **유동성 풀** (Liquidity Pool) : 유동성 공급자가 예치한 두 자산의 묶음으로, AMM의 거래 상대 역할을 한다.
- **상수곱 공식** : 거래 전후 풀의 곱 $x \times y = k$가 유지되도록 교환량을 정하는 방식.

```text
[ 유동성 공급자 ]
  자산 X, Y 예치
        ↓
[ 유동성 풀 (스마트 계약) ]
  x × y = k 유지
        ↓
[ 트레이더 스왑 요청 ]
  X 투입 → Y 수령
        ↓
[ 수수료 적립 후 정산 완료 ]
```

```text
[ 대표 응용 영역 ]
DEX (탈중앙화 거래소)
        ↓
Lending (담보 기반 대출)
        ↓
Stablecoin (가치 고정 자산)
```

## Ⅳ. 전통 금융, CeFi, DeFi의 비교

- 핵심 요약 : 중개자와 자산 보관 주체, 투명성의 차이가 세 체계를 구분하는 핵심 축이다.

| 비교 축 | 전통 금융 (TradFi) | 중앙화 가상자산 금융 (CeFi) | 탈중앙화 금융 (DeFi) |
| --- | --- | --- | --- |
| 중개자 | 은행, 증권사 등 금융기관 | 가상자산 거래소 | 스마트 계약 코드 |
| 자산 보관 | 금융기관 위탁 | 거래소 지갑 위탁 | 사용자 개인 지갑 보관 |
| 신원 확인 | 실명 확인 필수 | 거래소 가입 시 확인 | 지갑 주소 기반 (무허가성) |
| 거래 투명성 | 내부 감사 중심 | 거래소 내부 기록 | 온체인 공개 검증 |

- 선택 기준 : 규제 준수와 고객 자산 보호가 최우선이면 전통 금융이나 CeFi, 투명성과 개방성이 중요하면 DeFi의 적용 범위를 검토한다.

## Ⅴ. DeFi(Decentralized Finance)의 한계와 방안

- 핵심 요약 : 코드 취약점, 가격 조작, 확장성, 자금세탁 문제를 감사, 다중 오라클, 롤업, 규제 기술로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 스마트 계약 취약점 | 재진입, 정수 오버플로우 등을 노린 해킹으로 예치 자산 탈취 | 복수 전문 기관의 코드 감사와 형식 검증 적용 | 감사 완료 비율, 취약점 발견 수 |
| 플래시론 기반 오라클 조작 | 단일 거래소의 순간 가격을 참조해 가격 왜곡 | 탈중앙화 오라클 네트워크와 **TWAP**(Time-Weighted Average Price, 시간가중평균가격)을 결합 | 가격 편차율 |
| 거래 집중 시 처리 지연 | 메인넷 혼잡으로 수수료 급등과 처리 지연 | **롤업** (Rollup, 거래를 묶어 하위 체인에서 처리하는 확장 기술) 같은 레이어 2 확장 | 평균 수수료, 처리 지연 시간 |

## Ⅵ. DeFi(Decentralized Finance)에 대한 기술사적 제언

- 핵심 요약 : 기술 안전장치와 규제 준수 체계를 함께 설계해야 DeFi가 금융 인프라로 신뢰받을 수 있다.

1. 규제 당국과 사업자는 익명성 높은 거래의 자금세탁 위험을 줄이기 위해, 신원 정보를 공개하지 않고 자격만 증명하는 영지식 증명 기반 확인 방식을 함께 검토해야 한다.
2. 프로토콜 설계 조직은 담보 자산을 변동성이 큰 코인에서 안정성이 검증된 자산 중심으로 점진적으로 전환하는 리스크 정책을 세워야 한다.
3. 보안 조직은 오라클 설계를 단일 소스에 의존하지 않도록 점검하고, 정기 감사 결과를 공개하여 이용자의 판단 근거를 제공해야 한다.

## Ⅶ. 결론

- 핵심 요약 : DeFi는 스마트 계약으로 중개 기능을 대체하는 개방형 금융 인프라다.
- 시사점 : 개방성의 가치는 코드 신뢰성과 규제 대응이 뒷받침될 때 실현되므로, 보안과 규제 설계가 DeFi 확산의 전제가 된다.
