## Ⅰ. DeFi(Decentralized Finance)의 개요

- 개념 : 중앙 중개자(은행, 중개소)의 개입 없이 퍼블릭 블록체인의 분산 원장과 튜링 완전한 스마트 계약을 기반으로 대출, 결제, 거래, 파생상품을 제공하는 **개방형 금융 서비스 체계**
- 배경 및 필요성 : 스마트 계약 코드 취약점(재진입 공격)과 **플래시론** (Flash Loan)을 악용한 오라클 시세 조작 위험이 존재하므로 다중 **시간가중평균가격** (TWAP) 오라클 적용 및 정적 코드 감사 체계 구축 필수
- 핵심 목적 : 금융 중개 수수료 절감, 금융 소외 계층의 **무허가성** (Permissionless) 접근 보장 및 금융 레고 블록 형태의 **결합성** (Composability) 실현

## Ⅱ. DeFi(Decentralized Finance)의 핵심 아키텍처 및 동작 메커니즘

DeFi는 사용자 지갑 서명 → **AMM** (자동 시장 조성자) **유동성 풀** (Liquidity Pool) 상호작용 → 온체인 알고리즘 수식($x \times y = k$) 기반 실시간 자산 교환 및 정산 완결 메커니즘을 기반으로 동작하며, 세부적인 아키텍처와 핵심 컴포넌트 간 상호작용 프로세스는 다음과 같음.

```text
┌────────────────────────────────────────────────────────────────────────┐
│             DeFi 상수곱 AMM (Constant Product Market Maker) 구조       │
└────────────────────────────────────────────────────────────────────────┘
 [ 유동성 공급자 (LP) ] ────────── 자산 쌍 1:1 예치 ────────┐
                                                             │
                                                             ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 스마트 계약 유동성 풀 (Liquidity Pool: Token X & Token Y)             │
 │                                                                      │
 │  상수곱 공식: x * y = k (k는 거래 전후 항상 불변)                     │
 │   - x: 풀 내 토큰 X 보유량 / y: 풀 내 토큰 Y 보유량                  │
 │                                                                      │
 │  [ 거래 실행 메커니즘 ]                                              │
 │   트레이더가 Δx 만큼의 토큰 X를 풀에 투입:                            │
 │   (x + Δx) * (y - Δy) = k ──> 교환 수령 토큰: Δy = y - (k / (x + Δx)) │
 └──────────────────────────────┬───────────────────────────────────────┘
                                │
                                ▼
 [ 토큰 스왑 요청 (Swap Order) ] ──> [ 트레이더에게 Δy 지급 및 수수료 적립 ]
```

- **탈중앙화 거래소** (DEX) : Uniswap, Curve - 호가창 대신 유동성 풀 기반 AMM(상수곱 수식)을 통한 실시간 P2P 토큰 스왑
- **대출 및 차입** (Lending) : Aave, Compound - 과담보(Over-collateralization) 기반 암호화폐 예치 대출 및 실시간 이자율 자동 산정
- **스테이블코인** (Stablecoin) : DAI, USDC - 법정화폐 담보, 암호자산 과담보 또는 알고리즘 소각/발행을 통한 1달러 페깅(Pegging)

## Ⅲ. DeFi(Decentralized Finance)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 전통 금융 (TradFi) | 중앙화 가상자산 금융 (CeFi) | 탈중앙화 금융 (DeFi - 본 토픽) |
|---|---|---|---|
| **중개자** | 상업은행, 증권사, 중앙은행 | 가상자산 거래소 (업비트, 바이낸스) | 무인 스마트 계약 코드 |
| **자산 수탁** (Custody) | 금융기관 완전 위탁 (수탁) | 거래소 중앙 지갑 위탁 (사설 키 미보유) | 사용자 개인 지갑 자체 보관 (Non-custodial) |
| **신원 확인** (KYC) | 엄격한 실명 확인 필수 | 거래소 회원가입 KYC 필수 | 불필요 (지갑 주소 기반 무허가성) |
| **거래 투명성** | 폐쇄형 원장 (내부 감사만 가능) | 거래소 내부 오프체인 DB 기록 | 온체인 공개 및 실시간 검증 |

- DeFi는 상기 비교 지표를 바탕으로 비즈니스 요구사항과 운영 인프라 환경을 고려한 최적의 아키텍처를 선정하고, 확장성과 안정성을 균형 있게 확보해야 함.

## Ⅳ. DeFi(Decentralized Finance)의 주요 한계점 및 해결 방안

- 스마트 계약 소스코드 취약점(재진입성 등) 악용 예치 자산 탈취 위험 :
  - 한계점 : 스마트 계약 소스코드의 취약점(재진입성, 정수 오버플로우)을 노린 해킹으로 인한 예치 자산 탈취 위험.
  - 해결 방안 : CertiK, OpenZeppelin 등 복수 전문 기관의 공식 코드 오디트(Audit) 의무화 및 형식 검증(Formal Verification) 적용.
- 스팟 시세 참조 프로토콜을 노린 플래시론 기반 가격 오라클 조작 :
  - 한계점 : 단일 탈중앙화 거래소의 스팟 시세를 참조하는 프로토콜을 노린 플래시론 기반 가격 오라클 조작 공격.
  - 해결 방안 : 체인링크(Chainlink) 등 탈중앙화 오라클 네트워크(DON)와 시간가중평균가격(TWAP)을 결합하여 순간 가격 왜곡 방어.
- 거래 집중 시 이더리움 메인넷 가스비 폭증 및 느린 TPS 병목 :
  - 한계점 : 대규모 거래 유입 시 발생하는 이더리움 메인넷 가스비 폭증 및 느린 트랜잭션 처리 속도(TPS) 병목.
  - 해결 방안 : 옵티미스틱 롤업(Arbitrum, Optimism) 및 영지식 롤업(ZK-Rollup) 등 레이어 2(L2) 스케일링 네트워크로 마이그레이션.

## Ⅴ. DeFi(Decentralized Finance) 적용 및 발전을 위한 기술사적 제언

- 규제 준수 중심 엔터프라이즈 고도화 : 익명성으로 자금세탁(AML) 취약의 한계를 탈피하고, 영지식 증명(ZK) 기반 글로벌 자금세탁 방지를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- 담보 자산 중심 엔터프라이즈 고도화 : 변동성 극심한 알트코인 담보의 한계를 탈피하고, 미국 국채, 상업용 부동산 등 안전 RWA 담보를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- 오라클 보안 강화 및 신뢰성 확보 방안 : 단순 AMM 스팟 가격 참조의 한계를 탈피하고, 체인링크 분산 오라클 + TWAP 다중 검증을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
