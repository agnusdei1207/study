## 답안 골격
```text
[DeFi] ◀━━ 머리: Ⅶ 내 의견 (중앙 중개자 없는 금융 혁신과 코드 결합성을 제공하되 플래시론 공격과 오라클 조작을 차단하는 온체인 보안 가드레일 확립)
 ┃
 ┣━ Ⅰ 개요 ───── 전통 중앙화 금융(CeFi)의 중개 수수료, 심사 지연, 검열 위험 극복 → 블록체인 스마트 계약 기반 탈중앙화 금융(DeFi) 태동
 ┣━ Ⅱ 특징 ───── 무허가성(Permissionless) · 무신뢰 P2P(Trustless) · 머니 레고 결합성(Composability) · 전 과정 투명한 온체인 공개
 ┣━ Ⅲ 구조 ───── 결제/원장 계층(이더리움 등) + 자산 계층(ERC-20, 스테이블코인) + 프로토콜 계층(DEX, 대출, 파생) + 응용 계층(애그리게이터)
 ┣━ Ⅳ 흐름 ───── ① 사용자 지갑 연결(Web3) → ② 스마트 계약 자산 예치(담보/유동성 풀) → ③ AMM/대출 풀 자동 체결 → ④ 수익/이자 자동 정산
 ┣━ Ⅴ 비교 ───── 전통 금융(TradFi) vs 중앙화 가상자산 거래소(CeFi) vs 탈중앙화 금융(DeFi) (중앙은행/인허가 vs 거래소 서버/수탁 vs 스마트 계약/비수탁 무중개)
 ┗━ Ⅵ 실무 ───── 스마트 계약 재진입(Reentrancy) 결함 / 플래시론(Flash Loan) 기반 시세 조작 / 비영구적 손실(Impermanent Loss)
```

## 한 줄 본질
- 은행이나 증권사 같은 중개 기관이 서류를 검토하고 수수료를 떼어가는 대신, 블록체인에 올라간 자동화된 코드(스마트 계약)로 예금, 대출, 환전을 24시간 실시간 무인 처리 → 금융 민주화와 글로벌 접근성 실현 / 코드 취약점 및 해킹 시 구제 불가

## 핵심 그림
```text
[DeFi의 AMM(Automated Market Maker) 유동성 풀 및 거래 메커니즘]

     [유동성 공급자 (LP)]                       [일반 트레이더 (사용자)]
              │ (토큰 A + 토큰 B 1:1 예치)                 │ (토큰 A 10개 입력)
              ▼                                            ▼
   ┌─────────────────────────────────────────────────────────────┐
   │ 스마트 계약: AMM 유동성 풀 (Constant Product: x · y = k)   │
   │                                                             │
   │  [토큰 A 풀 (x개)]           <───────>         [토큰 B 풀 (y개)]  │
   │                                                             │
   │  * 가격 결정: 풀 내부의 토큰 상대적 비율로 자동 산출        │
   │  * x가 늘어나면 곱 k를 유지하기 위해 y를 사용자에게 지급     │
   └──────────────────────────────┬──────────────────────────────┘
                                  │
                                  ▼ (토큰 B 수령)
                         [트레이더 지갑으로 전송]
```

## 핵심 용어
- AMM(Automated Market Maker): 매수·매도 호가창(Order Book) 없이, 수학 공식($x \times y = k$, Constant Product)에 따라 유동성 풀의 자산 비율로 가격을 자동 결정하고 거래를 즉시 체결하는 알고리즘
- 플래시론(Flash Loan): 담보를 전혀 맡기지 않고도 단 하나의 트랜잭션 블록 안에서 대출금을 빌리고 거래를 마친 뒤 즉시 상환하는 조건부 무담보 초고속 대출
- 비영구적 손실(Impermanent Loss): 유동성 풀에 자산을 예치했을 때, 외부 시장 가격 변동으로 인해 풀 내부 자산 구성비가 바뀌어 단순 지갑 보유(HODL) 대비 발생하는 기회 손실

## 핵심 통찰
- "머니 레고(Money Legos)의 폭발력": 오픈소스 코드로 공개된 DeFi 프로토콜들은 레고 블록처럼 서로 조립 가능함 → Uniswap에서 환전한 토큰을 Aave에 담보로 맡겨 스테이블코인을 빌리고, 이를 다시 Curve에 넣어 이자를 받는 복합 금융이 단 한 줄의 코드로 결합됨
- 오라클 문제(Oracle Problem)가 아킬레스건: 블록체인은 외부 현실 세계의 주가나 환율을 스스로 알지 못하므로 외부 데이터 피드(Oracle)에 의존하는데, 해커가 탈중앙 거래소의 순간 유동성을 왜곡해 오라클 가격을 조작한 뒤 담보 대출을 털어가는 취약점이 빈번함
- 비수탁(Non-Custodial)의 양날의 검: FTX처럼 거래소 운영자가 고객 돈을 횡령할 위험은 없지만, 사용자가 개인키를 분실하거나 악성 계약에 서명(Approve)하면 그 어떤 기관도 자산을 복구해 줄 수 없음

## 이웃 토픽과 구분
- CeFi vs DeFi: CeFi(업비트, 바이낸스)는 거래소 중앙 서버 DB에 잔고를 기록하고 자산을 수탁 / DeFi(유니스왑, 에이브)는 블록체인 스마트 계약에 자산을 묶어두고 개인이 지갑으로 직접 통제

## 문제·원인·대책
- 적용 상황: 탈중앙 대출 프로토콜 운영 중 플래시론을 이용한 가격 조작 해킹 공격 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 단일 DEX의 순간 현물 가격을 청산 기준으로 삼았다가 플래시론 조작으로 1,000억 원 탈취 | 담보 평가 시 스팟(Spot) 가격을 그대로 사용한 오라클 취약점 | 시간가중평균가격(TWAP) 및 Chainlink 다중 노드 탈중앙 오라클 도입 | 순간 가격 왜곡 공격 원천 차단 |
| 계약 함수 간 상호 호출 중 상태 갱신 전에 자금을 재인출해 가는 재진입(Reentrancy) 해킹 | Checks-Effects-Interactions 패턴 미준수 및 상태 잠금 부재 | 뮤텍스 가드(ReentrancyGuard) 적용 및 잔고 갱신 후 자금 전송 강제 | 재진입 취약점 완벽 방어 |
| 급격한 암호화폐 폭락 시 자동 청산(Liquidation) 지연으로 인한 프로토콜 악성 부채 발생 | 이더리움 메인넷의 가스비 폭증 및 트랜잭션 병목 | 레이어2(Rollup) 분산 청산 봇 인프라 구축 및 담보 완충 비율(LTV) 보수적 상향 | 대규모 청산 지연 부채 제로화 |

## 내 의견
- [DeFi 프로토콜의 정적 정형 검증(Formal Verification) 및 실시간 방화벽 도입] 배포 후 수정이 불가능한 스마트 계약의 불변성(Immutability)은 취약점 발생 시 치명적인 재앙이 됨 → 나라면: 솔리디티 코드 배포 전 수학적으로 무결성을 증명하는 정형 검증(Certora 등)을 필수 통과시키고, 멤풀(Mempool)에서 악의적인 플래시론 트랜잭션을 실시간 감지하여 해당 블록에서 프로토콜을 자동 일시 중지(Circuit Breaker)시키는 런타임 보안 가드레일 수립
