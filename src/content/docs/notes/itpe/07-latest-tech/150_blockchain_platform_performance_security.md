## 핵심 용어
- 블록체인 트릴레마(Blockchain Trilemma): 탈중앙성(Decentralization), 확장성(Scalability), 보안성(Security)의 3요소를 하나의 계층에서 동시에 완벽히 만족하기 어렵다는 이론적 한계
- 레이어 2 롤업(L2 Rollup): 트랜잭션 실행은 오프체인(L2)에서 대량으로 묶어 처리하고, 그 결과 데이터와 암호학적 증명만을 메인체인(L1)에 기록하여 성능을 수십 배 끌어올리는 기술
- 재진입 공격(Reentrancy Attack): 스마트 컨트랙트가 외부 컨트랙트로 자금을 송금할 때, 잔고가 차감되기 전에 상대방이 해당 출금 함수를 재귀적으로 다시 호출하여 잔고를 탈탈 털어가는 취약점 공격

## 핵심 통찰
- "성능 향상 시 보안 타협의 함정": 노드 수를 줄이거나 검증 단계를 단순화하여 TPS를 올리는 프라이빗 체인은 찰나의 중앙 관리자 권한 탈취로 전체 체인이 장악당할 수 있음
- 코드가 곧 법(Code is Law)의 이면: 블록체인은 한 번 배포된 스마트 컨트랙트를 수정할 수 없으므로(불변성), 사소한 코드 버그 하나가 수백억 원의 자산 증발로 이어짐
- 최종성(Finality)의 비즈니스적 중요도: 결제나 금융 거래에서는 확률적 최종성(PoW 6블록 대기)보다 BFT 계열 합의의 즉시 확정성(Instant Finality)이 필수적

## 이웃 토픽과 구분
- L1 확장(On-chain Sharding) vs L2 확장(Off-chain Rollup): L1 샤딩은 블록체인 메인 네트워크 자체를 여러 조각으로 쪼개어 병렬 검증 / L2 롤업은 메인넷은 보안과 최종 검증만 담당하고 연산은 외부 실행 레이어에 위임

## 문제·원인·대책
- 적용 상황: 글로벌 물류 대금 정산용 엔터프라이즈 블록체인 플랫폼 론칭
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 대규모 거래 유입 시 정산 처리 속도가 15 TPS로 급락하며 병목 발생 | 모든 노드가 모든 트랜잭션을 순차 실행하고 상태를 동기화하는 구조 | 모듈러 블록체인 아키텍처 도입 및 ZK-롤업 기반 오프체인 배치 실행 | 정산 처리 성능 2,000 TPS 이상 달성 |
| 배포된 자금 집행 스마트 컨트랙트에서 재진입 취약점 발견 | 잔고 차감 로직보다 자금 전송 로직이 먼저 실행되는 Checks-Effects-Interactions 패턴 위반 | ReentrancyGuard 뮤텍스 적용 및 Slither/Mythril 정적 분석 툴 CI/CD 연동 | 컨트랙트 보안 취약점 사전 차단율 100% |
| 노드 운영자 개인키 탈취로 인한 허위 정산 트랜잭션 서명 사고 | 단일 관리자 EOA(Externally Owned Account) 개인키 로컬 보관 | 하드웨어 보안 모듈(HSM) 및 3-of-5 다중서명(Multi-sig) 거버넌스 강제 | 단일 장애점(SPOF) 키 탈취 사고 방지 |

## 내 의견
- [모듈러 블록체인(Modular Blockchain) 설계를 통한 성능과 보안의 책임 분리] 단일 체인(Monolithic)에서 실행, 합의, 데이터 가용성(DA), 결제를 모두 처리하면 성능과 보안의 한계에 부딪힘 → 나라면: 실행(Execution)은 L2 롤업에 맡겨 초고속 연산을 보장하고, 합의 및 결제는 이더리움 L1에 맡겨 탈중앙 보안성을 계승하며, 데이터 가용성은 셀레스티아(Celestia) 등 전문 DA 계층을 활용하는 3단계 모듈러 분리 아키텍처를 도입하여 비용 90% 절감 및 수천 TPS 성능 달성
