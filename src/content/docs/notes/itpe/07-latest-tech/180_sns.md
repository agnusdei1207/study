## 연관 키워드

- 소셜네트워크서비스(SNS, Social Networking Service), 소셜 그래프(Social Graph), 팬아웃(Fan-out)
- 푸시 모델(Push Model), 풀 모델(Pull Model), 하이브리드 타임라인, 팬아웃 스톰(Fan-out Storm)
- 필터 버블(Filter Bubble), 탐색-활용 균형, 상호운용성(Interoperability), 데이터 이동권

## Ⅰ. 소셜네트워크서비스의 개요

- 핵심 요약 : 사용자 관계망인 소셜 그래프 위에서 콘텐츠가 생산·유통·소비되는 플랫폼으로, 팔로워 규모에 따라 피드 전파 방식을 달리하는 것이 핵심 설계.
- 개념 : 개인 프로필과 사용자 간 연결선으로 이루어진 **소셜 그래프** (Social Graph, 사용자와 관계를 노드와 간선으로 나타낸 구조) 위에서 글, 이미지, 영상을 주고받는 **소셜네트워크서비스** (SNS, Social Networking Service).
- 배경 및 필요성 : 팔로워가 수천만 명인 계정이 글을 올리면 모든 팔로워의 타임라인에 같은 글을 한꺼번에 복제해야 해 쓰기 부하가 급증함. 따라서 일반 계정과 유명 계정의 전파 방식을 나누는 **하이브리드 타임라인** 구조가 필요.
- 주요 목적 : 관계망 형성, 정보의 빠른 확산, 개인화된 피드 큐레이션, 소셜 커머스 같은 네트워크 기반 가치 창출.

## Ⅱ. 소셜네트워크서비스의 특징 및 장점

- 핵심 요약 : 관계 데이터의 그래프 저장, 비동기 전파, 개인화 랭킹이 결합되어 응답 속도와 피드 적합도를 함께 확보하는 구조.

1. 소셜 그래프 기반 연결 : 사용자 관계를 그래프 형태로 저장하고 조회 → 팔로우, 차단 같은 관계 질의를 빠르게 처리.
2. **팬아웃** (Fan-out, 게시물을 팔로워의 피드로 퍼뜨리는 작업) : 팔로워 수에 따라 쓰기 시점에 미리 나누거나 읽기 시점에 모아서 처리 → 피드 조회 지연과 쓰기 부하를 상황별로 조정.
3. 비동기 이벤트 처리 : 게시 이벤트를 메시지 큐로 넘겨 처리 → 글쓰기 응답 속도를 유지하고 전파 작업을 여러 워커로 분산.
4. 개인화 랭킹 : 친밀도, 콘텐츠 가중치, 최신성 신호로 피드를 정렬 → 이용자가 관심 있는 글을 먼저 보게 되어 체류 시간 향상 기대.
5. 연합형 구조 : 서로 다른 서버가 표준 프로토콜로 프로필과 게시물을 주고받음 → 특정 플랫폼 종속을 줄이고 **상호운용성** (Interoperability, 이종 시스템 간 데이터 교환 능력) 확보.

```text
[ 게시물 전파 흐름 ]

발행자
  ↓
API 게이트웨이
  ↓
게시물 서비스 → 게시물 저장소
  ↓ 팔로워 수 기준 분기
일반 계정: 쓰기 시점 팬아웃 (Push)
유명 계정: 읽기 시점 병합 (Pull)
```

```text
[ 피드 조회 흐름 ]

타임라인 서비스
  ↓
인메모리 캐시(푸시 결과) 조회
  ↓
유명 계정 게시물 동적 병합
  ↓
랭킹 모델 정렬
  ↓
클라이언트 피드 표출
```

## Ⅲ. 소셜네트워크서비스의 구조 및 구성 요소

- 핵심 요약 : 관계 저장소, 메시지 큐, 타임라인 캐시, 랭킹 엔진이 역할별로 나뉘어 피드 한 장을 만드는 파이프라인 구조.
- **그래프 데이터베이스** (Graph Database, 노드와 간선을 직접 저장하는 데이터베이스) : Neo4j, JanusGraph, Amazon Neptune 등을 써서 팔로우와 차단 관계를 고속으로 조회.
- **메시지 큐** (Message Queue) : Apache Kafka, RabbitMQ 같은 비동기 전달 체계로 게시 이벤트를 팬아웃 워커 풀에 분배.
- **인메모리 캐시** (In-memory Cache) : Redis, Memcached 같은 메모리 저장소에 사용자별 피드의 게시물 식별자를 **정렬 집합** (Sorted Set) 형태로 보관.
- **그래프 신경망** (GNN, Graph Neural Network) : 사용자와 콘텐츠의 연결 구조를 학습해 친밀도와 관심 신호를 추정하는 랭킹 모델 계열.

## Ⅳ. 팬아웃 방식의 비교

- 핵심 요약 : 쓰기 시점 전파는 읽기가 빠르고 쓰기가 무겁고, 읽기 시점 전파는 그 반대이므로 계정 규모에 따라 나눠 쓰는 것이 합리적.
- 비교 대상은 **팬아웃 온 라이트** (Fan-out on Write, 푸시 모델)와 **팬아웃 온 리드** (Fan-out on Read, 풀 모델).

| 비교 축 | 팬아웃 온 라이트 (푸시 모델) | 팬아웃 온 리드 (풀 모델) |
| --- | --- | --- |
| 처리 시점 | 작성 시점에 팔로워 피드에 복제 | 조회 시점에 팔로잉 게시물을 모아 병합 |
| 읽기 지연 | 짧음 (자기 캐시만 조회) | 길어짐 (여러 원천을 병합) |
| 쓰기 부하 | 팔로워 수에 비례해 증가 | 작성자 쪽 1회 쓰기로 충분 |
| 저장 공간 | 복제본 누적으로 낭비 가능 | 원본 위주로 최소화 |
| 유명 계정 적합성 | 팔로워 폭증 시 병목 | 쓰기 부하가 없어 유리 |
| 적합 대상 | 팔로워가 적은 일반 계정 | 팔로워가 매우 많은 유명 계정 |

- 선택 기준 : 계정별 팔로워 규모와 최근 접속 활성 사용자 비율을 기준으로 두 방식을 혼합하는 하이브리드 설계가 현실적.

## Ⅴ. 소셜네트워크서비스의 한계와 방안

- 핵심 요약 : 팬아웃 과부하, 알고리즘 편향, 플랫폼 종속, 자동화 봇을 전파 설계, 다양성 신호, 연합 프로토콜, 그래프 이상 탐지로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 유명 계정의 **팬아웃 스톰** (Fan-out Storm) | 대형 계정 게시 시 메시지 큐 포화와 캐시 쓰기 지연 | 팔로워 임계치로 전파 방식을 나누는 하이브리드 설계, 최근 접속 사용자에게만 선별 푸시 | 전파 완료 지연, 큐 적체량 |
| **필터 버블** (Filter Bubble)과 확증 편향 | 클릭률 극대화 알고리즘이 자극적 콘텐츠와 허위 정보를 상위에 노출 | **탐색-활용 균형** (Exploration-Exploitation)을 위해 멀티암드 밴딧 (MAB, Multi-Armed Bandit) 기법으로 새 주제 슬롯 확보, 출처 신뢰도와 사실 검증 신호를 랭킹에 반영 | 주제 다양성 지표, 검증 표시 노출률 |
| 플랫폼 종속과 데이터 사일로 | 폐쇄 플랫폼에서는 계정과 관계 데이터를 다른 서비스로 옮길 수 없음 | **연합형 프로토콜** (ActivityPub 등 W3C 표준 기반) 적용, **데이터 이동권** (Data Portability)을 보장하는 내보내기 API 제공 | 내보내기 성공률, 연동 서버 수 |
| 자동화 봇과 조작 계정 | 대량 생성된 계정이 팔로우와 게시를 반복해 여론을 왜곡 | **그래프 이상 탐지** (Graph Anomaly Detection)로 비정상 연결 패턴 식별, 행동 패턴 분석 병행 | 봇 탐지 정밀도, 차단 계정 수 |

## Ⅵ. 소셜네트워크서비스에 대한 기술사적 제언

- 핵심 요약 : 성능, 다양성, 상호운용, 신뢰 네 축을 운영 기준으로 삼아 SNS를 기능 경쟁이 아니라 신뢰 가능한 관계 인프라로 관리.

1. 플랫폼 운영 조직은 피드 지연을 평균값이 아니라 상위 백분위 지연 (P99, 99th Percentile) 기준으로 관리하고, 캐시 샤딩과 클라이언트 측 선로딩을 함께 설계할 필요가 있다.
2. 서비스 기획 조직은 알고리즘 성과를 클릭률 하나로 판단하지 않고, 다양성과 출처 신뢰도를 평가 항목에 포함하는 것이 바람직하다.
3. 정보보호 조직은 봇 탐지를 계정 단위 규칙에서 관계 그래프 전체의 이상 탐지로 넓히고, 탐지 기준을 주기적으로 재검토할 필요가 있다.
4. 사업 책임 조직은 연합 프로토콜과 데이터 이동권을 정책으로 채택해, 이용자가 떠날 때 관계와 콘텐츠를 가져갈 수 있는 환경을 보장하는 것이 필요하다.

## Ⅶ. 결론

- 핵심 요약 : 소셜네트워크서비스는 소셜 그래프 위에서 팬아웃과 랭킹을 조합해 정보를 전파하는 관계 인프라.
- 전파 속도보다 계정 규모별 설계의 균형과 이용자의 데이터 주권이 장기 신뢰를 좌우하므로, 이 두 축을 설계 기준으로 삼는 시각이 필요하다.
