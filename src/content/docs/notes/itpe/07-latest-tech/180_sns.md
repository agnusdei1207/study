## 30초 인출

- 본질: 사용자 간의 인적·관심사 관계망(Social Graph)을 데이터베이스화하여 실시간 콘텐츠 생성, 전파, 피드 구독 및 상호작용을 중계하는 대규모 분산 웹 플랫폼.
- 메커니즘: 노드-엣지 그래프 관계 형성 → 게시물 발행 → 팬아웃(Fan-out: 쓰기/읽기) 기반 타임라인 큐 배포 → GNN/추천 모델 랭킹 → 클라이언트 피드 렌더링.
- 통찰: 수천만 팔로워를 보유한 유명 계정 발행 시 쓰기 팬아웃 병목이 발생하므로 계정 영향력에 따라 푸시(Push)와 풀(Pull)을 동적 분기하는 하이브리드 타임라인 아키텍처 구축 필수.

<details><summary>핵심 용어</summary>

- **소셜 그래프(Social Graph) :** 사용자를 정점(Node), 친구·팔로우 관계를 간선(Edge)으로 표현하여 인간 관계망을 추상화한 데이터 모델.
- **팬아웃 온 라이트(Fan-out on Write) :** 사용자가 글을 작성하는 즉시 모든 팔로워의 타임라인 인메모리 캐시에 복제 삽입하는 푸시(Push) 방식.
- **팬아웃 온 리드(Fan-out on Read) :** 사용자가 피드를 조회하는 시점에 팔로잉 대상의 글들을 동적으로 질의·병합하는 풀(Pull) 방식.
- **척도 없는 네트워크(Scale-Free Network) :** 소수의 허브(Hub) 노드가 극단적으로 많은 연결선을 가지며 연결선 분포가 멱함수 법칙(Power-Law)을 따르는 네트워크.

</details>

## Ⅰ. 소셜네트워크서비스(SNS)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 웹과 모바일 환경에서 개인의 신원 프로필과 사용자 간의 연결선(소셜 그래프)을 기반으로 텍스트, 이미지, 비디오 등 콘텐츠를 생성·유통·소비하는 분산 소셜 플랫폼. |
| 목적 | 시공간을 초월한 관계망 형성, 정보의 바이럴(Viral) 확산, 개인화된 관심사 피드 큐레이션 및 소셜 커머스 등 네트워크 경제 가치 창출. |

## Ⅱ. SNS의 핵심 특징 및 네트워크 이론적 기반

### 1. SNS의 3대 핵심 특징

- **양방향 네트워크 효과(Network Effect) :** 사용자 수가 증가할수록 네트워크의 총 가치가 사용자 수의 제곱에 비례하여 증가(Metcalfe's Law).
- **소셜 그래프 기반 데이터 전파 :** 고정된 계층형 트리가 아닌 다대다(N:M) 분산 그래프 구조를 통한 기하급수적 정보 확산.
- **실시간 비동기 인터랙션 :** 수억 명의 동시 접속 환경에서 초당 수만 건의 피드 업데이트와 읽기 요청을 밀리초(ms) 단위 처리 요구.

### 2. 네트워크 과학 이론적 특성

- **척도 없는 네트워크(Scale-Free Network) :** 대부분의 노드는 적은 연결을 갖지만 극소수 인플루언서 노드가 수천만 연결을 독점하는 멱함수(Power-law) 분포 형성.
- **작은 세상 효과(Small-World Phenomenon) :** 평균 경로 길이(Average Path Length)가 매우 짧아 대략 6단계의 연결선만으로 전 세계 모든 사용자가 연결 가능.

## Ⅲ. 대규모 피드 배포 시스템 아키텍처 및 팬아웃(Fan-out)

### 1. 하이브리드 팬아웃 타임라인 아키텍처

```text
[발행자] ──► [API 게이트웨이] ──► [게시물 서비스] ──► [Post DB 저장]
                                        │
                                        ▼ (팔로워 수 판별 분기)
                 +----------------------+----------------------+
                 │ (팔로워 < 5만 명)                           │ (팔로워 >= 5만 명: 유명인)
                 ▼                                             ▼
     [Fan-out on Write (Push)]                    [Fan-out on Read (Pull)]
- 팔로워 목록 조회 (Graph DB)                - 사용자 타임라인 캐시 복제 생략
- 각 팔로워 Redis Inbox에 Post ID 복제       - 유명인 전용 Outbox 캐시에만 보관
                 │                                             │
                 └──────────────────────┬──────────────────────┘
                                        ▼
                                 [피드 조회 요청]
                                        │
        [타임라인 서비스: Redis Inbox 조회 + 유명인 Outbox 동적 병합]
                                        ▼
                        [ML 랭킹 모델: 최적 정렬]
                                        ▼
                               [클라이언트 피드 표출]
```

### 2. 세부 컴포넌트별 기술요소 및 역할

| 컴포넌트 | 핵심 기술 스택 | 엔지니어링 구현 역할 |
|---|---|---|
| **소셜 그래프 엔진** | Neo4j, JanusGraph, AWS Neptune | 팔로우, 맞팔로우, 차단, 그룹 관계의 정점/간선 초고속 인덱싱. |
| **메시지 큐** | Apache Kafka, RabbitMQ | 게시물 작성 이벤트를 비동기 분산 수신하여 팬아웃 워커 풀로 발행. |
| **인메모리 타임라인 캐시** | Redis Cluster, Memcached | 각 사용자의 피드 상위 800개 게시물 ID를 Sorted Set 구조로 저장. |
| **개인화 랭킹 엔진** | DLRM, GNN, XGBoost | 친밀도(Affinity), 콘텐츠 가중치(Weight), 최신성(Decay) 기반 정렬. |

## Ⅳ. 팬아웃 온 라이트(Push)와 팬아웃 온 리드(Pull) 비교

| 비교 항목 | 팬아웃 온 라이트 (Push Model) | 팬아웃 온 리드 (Pull Model) |
|---|---|---|
| **데이터 처리 시점** | 사용자가 게시물을 작성(Write)하는 시점 | 사용자가 타임라인을 조회(Read)하는 시점 |
| **읽기 성능 (Read Latency)** | 최고 (자신의 Redis Inbox만 단순 조회, <10ms) | 느림 (모든 팔로잉 대상의 글을 동적 쿼리 및 병합) |
| **쓰기 부하 (Write Load)** | 극단적으로 높음 (팔로워 N명에게 N번 복제 쓰기) | 매우 낮음 (작성자 테이블에 1회 쓰기만 수행) |
| **스토리지 낭비** | 심각 (휴면 사용자 Inbox에도 데이터 복제 누적) | 최소화 (게시물 원본 1벌만 저장) |
| **유명인 계정 취약성** | 치명적 병목 (팔로워 1억 명 발행 시 1억 회 쓰기 폭증) | 완벽 대응 (작성 시 부하 없음) |
| **최적 적용 대상** | 팔로워 수가 적은 일반 사용자 간의 피드 전파 | 팔로워 수만~수천만 이상의 슈퍼 인플루언서 계정 |

## Ⅴ. SNS 플랫폼의 엔지니어링 한계와 해결 방안

| 한계 | 방안 |
|---|---|
| **유명인(Celebrity) 게시물 발행 시 팬아웃 스톰(Storm) 발생**<br />- 수천만 팔로워를 가진 계정의 글 작성 시 메시지 큐 포화 및 타임라인 캐시 쓰기 지연. | **동적 하이브리드 분기 및 지연 평가(Lazy Evaluation)**<br />- 팔로워 임계치(예: 5만 명)를 기준으로 일반 사용자는 Push, 인플루언서는 Pull 모델 적용.<br />- 활성 사용자(최근 3일 내 접속)에게만 선별적 Push를 수행하여 캐시 낭비 제거. |
| **필터 버블(Filter Bubble) 및 확증 편향에 따른 유해 정보 증폭**<br />- 클릭률(CTR) 극대화 중심 알고리즘이 극단적 콘텐츠 및 가짜 뉴스를 상위 노출. | **탐색-활용(Exploration-Exploitation) 균형 및 다양성 페널티**<br />- 멀티암드 밴딧(MAB) 알고리즘을 도입하여 20%의 피드 슬롯에 새로운 주제 탐색 강제.<br />- 출처 신뢰도 점수 및 사실 검증(Fact-Check) 메타데이터를 랭킹 가중치에 차감 반영. |
| **서비스 사일로화 및 플랫폼 독점 종속(Lock-in)**<br />- 플랫폼 폐쇄성으로 인해 계정 이동 및 외부 플랫폼과의 데이터 연동 불가. | **탈중앙화 연합 소셜 프로토콜(ActivityPub, AT Proto) 도입**<br />- W3C 표준 ActivityPub을 적용하여 이종 서버 간 프로필 및 게시물 상호운용성 보장.<br />- 데이터 이동권(Data Portability) API를 제공하여 소셜 그래프 내보내기 지원. |

## Ⅵ. 견고한 대규모 SNS 플랫폼 운영을 위한 제언

소셜 그래프의 비대칭성을 고려한 인프라 분할 설계를 적용하고, 단순 참여도(Engagement) 중심 지표를 탈피하여 콘텐츠 안전성과 신뢰성을 통합 관리하는 책임 있는 플랫폼 아키텍처 구축 필수.

```text
[사용자 행동 계측] ──► [피드 백본 큐] ──► [하이브리드 캐싱] ──► [안전성/다양성 필터] ──► [최종 피드 렌더링]
- 비정상 어뷰징 탐지   - Kafka 파티셔닝     - Push/Pull 동적 분기    - 필터 버블 완화 알고리즘   - 서브 50ms 응답
```

| 운영 지표 | 목표 기준치 | 엔지니어링 관리 방안 |
|---|---|---|
| **피드 로딩 지연(P99)** | 50ms 미만 | Redis Cluster 샤딩 및 클라이언트 사이드 프리페칭(Pre-fetching) |
| **팬아웃 지연 시간** | 일반 계정 1초 미만 | 비동기 셀러리(Celery)/카프카 파티션 분산 병렬화 |
| **어뷰징 봇 탐지율** | 악성 자동화 계정 99% 차단 | 그래프 이상 탐지(Graph Anomaly Detection) 및 행동 패턴 분석 |
