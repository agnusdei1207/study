## Ⅰ. 배깅(Bagging)의 개요

- **개념** : 원본 데이터에서 복원 추출한 여러 부트스트랩 표본마다 고분산 약학습기(주로 과적합된 깊은 결정트리)를 독립적으로 병렬 학습시킨 후 결과를 집계(다수결 투표/평균)하는 앙상블 기법
- **배경 및 필요성** : 개별 결정트리 간 상관계수($\rho$)가 높을 경우 분산 감소 효과가 상쇄되므로 노드 분할 시 특성(Feature)을 무작위 추출하는 랜덤 포레스트(Random Forest) 기법의 병용 필수
- **핵심 목적** : 단일 결정트리의 과적합 및 높은 분산(Variance) 오류를 획기적으로 낮추어 일반화 성능과 예측 안정성 확보

## Ⅱ. 배깅(Bagging)의 핵심 아키텍처 및 동작 메커니즘

배깅은 크기 $N$의 원본 데이터에서 복원 추출하여 약 63.2%의 표본으로 $B$개의 독립 결정트리(Decision Tree)를 병렬 훈련하고, 약 36.8%의 미추출 데이터(OOB, Out-Of-Bag)로 모델을 자체 검증한 후 예측치 앙상블 집계 메커니즘을 기반으로 동작하며, 세부적인 아키텍처와 핵심 컴포넌트 간 상호작용 프로세스는 다음과 같음.

```text
┌────────────────────────────────────────────────────────────────────────┐
│             배깅 (Bootstrap Aggregating) 엔드투엔드 파이프라인          │
└────────────────────────────────────────────────────────────────────────┘
 [ 원본 학습 훈련 데이터셋 (Original Dataset: N개 샘플) ]
                          │
       ┌──────────────────┼──────────────────┐ 복원 추출 (Bootstrap)
       ▼ (중복 허용 N개)  ▼ (중복 허용 N개)  ▼ (중복 허용 N개)
 ┌───────────────┐  ┌───────────────┐  ┌───────────────┐
 │ Bootstrap D_1 │  │ Bootstrap D_2 │  │ Bootstrap D_B │
 └───────┬───────┘  └───────┬───────┘  └───────┬───────┘
         │ (독립 병렬)      │ (독립 병렬)      │ (독립 병렬)
         ▼                  ▼                  ▼
 ┌───────────────┐  ┌───────────────┐  ┌───────────────┐
 │ 개별 분류기 1 │  │ 개별 분류기 2 │  │ 개별 분류기 B │  (예: Fully Grown Tree)
 │ Model M_1     │  │ Model M_2     │  │ Model M_B     │
 └───────┬───────┘  └───────┬───────┘  └───────┬───────┘
         │                  │                  │
         └──────────────────┼──────────────────┘
                            │ 집계 (Aggregating)
                            ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 결합 집계 엔진 (Ensemble Aggregator)                                 │
 │  - 분류(Classification): 다수결 투표 (Majority Voting: Mode(y_1..y_B)) │
 │  - 회귀(Regression): 단순 산술 평균 (Averaging: (1/B) * Σ y_b)       │
 └──────────────────────────┬───────────────────────────────────────────┘
                            │
                            ▼
 [ 최종 일반화된 강건한 예측 결과 (Ensemble Prediction) ]
```

- **부트스트랩 미선택 확률** : $P(\text{Not Selected}) = \left(1 - \frac{1}{N}\right)^N \approx e^{-1} \approx 0.368$ - 데이터 크기 $N$이 충분히 클 때 약 36.8%의 데이터는 OOB로 남아 별도 검증셋으로 활용
- **앙상블 분산 감소 공식** : $\text{Var}\left(\frac{1}{B}\sum_{i=1}^B X_i\right) = \rho \sigma^2 + \frac{1 - \rho}{B} \sigma^2$ - 트리 수 $B \to \infty$로 증가 시 분산은 $\rho \sigma^2$로 수렴, 트리 간 상관계수 $\rho$를 낮추는 것이 핵심
- **편향-분산 트레이드오프** : $\text{Bias}(\text{Ensemble}) \approx \text{Bias}(\text{Base})$, $\text{Var} \ll \text{Var}(\text{Base})$ - 개별 모델의 편향(Bias)은 유지한 채 오직 분산(Variance)만을 독립적으로 대폭 감소

## Ⅲ. 배깅(Bagging)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 배깅 (Bagging - 본 토픽) | 부스팅 (Boosting) | 스태킹 (Stacking) |
|---|---|---|---|
| **학습 방식** | 병렬 독립 학습 (Parallel) | 순차적 직렬 학습 (Sequential) | 이종 모델 병렬 + 메타 모델 학습 |
| **오차 감소 초점** | 분산(Variance) 감소 (과적합 완화) | 편향(Bias) 감소 (과소적합 극복) | 예측력 극대화 (편향 및 분산 모두 감소) |
| **데이터 샘플링** | 복원 추출 (동일 가중치) | 이전 모델 오분류 데이터 가중치 부여 | 교차 검증 기반 예측값으로 메타 셋 생성 |
| **이상치(Outlier) 민감도** | 둔감함 (극소수 이상치 영향 희석) | 극도로 민감함 (이상치에 가중치 집중) | 중간 |

- 배깅은 상기 비교 지표를 바탕으로 비즈니스 요구사항과 운영 인프라 환경을 고려한 최적의 아키텍처를 선정하고, 확장성과 안정성을 균형 있게 확보해야 함.

## Ⅳ. 배깅(Bagging)의 주요 한계점 및 해결 방안

- **지배적 특성(Dominant Feature) 존재 시 트리 간 상관관계 증가 및 분산 감소 실패** :
  - **한계점** : 특정 강한 특성(Dominant Feature)이 존재할 경우 모든 부트스트랩 트리가 동일한 최상단 분할을 수행하여 트리 간 상관계수($\rho$)가 증가하고 분산 감소 실패.
  - **해결 방안** : 분할 노드마다 전체 $p$개 특성 중 무작위로 $m \approx \sqrt{p}$개만 선택하여 트리의 다양성을 강제 확보하는 랜덤 포레스트(Random Forest)로 전환.
- **수백 개 트리 앙상블로 인한 의사결정 경로의 시각적 설명가능성 상실** :
  - **한계점** : 수백 개의 결정트리를 앙상블함에 따라 단일 결정트리가 가지던 의사결정 경로의 시각적 설명가능성(Interpretability) 완전 상실.
  - **해결 방안** : SHAP(Shapley Additive Explanations) 및 순열 특성 중요도(Permutation Feature Importance) 기법을 결합하여 설명가능성(XAI) 보완.
- **고차원 희소 데이터에서 복원 추출 시 분산 감소 효과 미미 및 메모리 급증** :
  - **한계점** : 고차원 희소 데이터(텍스트 TF-IDF, 유전체 데이터)에서 복원 추출 시 분산 감소 효과가 미미하고 연산 메모리 급증.
  - **해결 방안** : 연속형 특징에 적합한 특성 서브스페이스 샘플링(Random Subspace Method) 병행 및 트리 깊이 사전 제한(Max Depth 규제) 적용.

## Ⅴ. 배깅(Bagging) 적용 및 발전을 위한 기술사적 제언

- **학습 소요 시간 최적화 및 신뢰성 확보 방안** : 수십 분 소요 (단일 노드 CPU 병목)를 선제적으로 구현하여 GPU 텐서 코어로 수 초 내 훈련 완료를 체계적으로 달성하고 실무 운영 안정성을 완성해야 함.
- **트리 수 결정 최적화 및 신뢰성 확보 방안** : 휴리스틱으로 고정(예: 500개)를 선제적으로 구현하여 OOB 에러 곡선 실시간 감시로 최적 수 자동 결정을 체계적으로 달성하고 실무 운영 안정성을 완성해야 함.
- **추론 레이턴시 최적화 및 신뢰성 확보 방안** : 트리 순회 연산으로 수 밀리초 지연을 선제적으로 구현하여 Treelite C-코드 컴파일로 마이크로초 달성을 체계적으로 달성하고 실무 운영 안정성을 완성해야 함.
