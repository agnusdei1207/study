## 연관 키워드

- 공간 컴퓨팅(Spatial Computing), 확장 현실(XR, Extended Reality), 증강 현실(AR, Augmented Reality), 가상 현실(VR, Virtual Reality)
- 공간 앵커(Spatial Anchor), 오클루전(Occlusion), SLAM(Simultaneous Localization and Mapping), 시선 추적(Eye Tracking)
- 공간 음향(Spatial Audio), 포비티드 렌더링(Foveated Rendering), 초점-조절 불일치(VAC), 시각유발 어지럼증(VIMS)

## Ⅰ. 공간 컴퓨팅(Spatial Computing)의 개요

- 핵심 요약 : 현실 공간의 좌표와 표면을 인식해 디지털 객체를 그 공간에 고정하고, 시선·손·음성으로 조작하는 기술 체계.
- 개념 : **공간 컴퓨팅** (Spatial Computing, 물리 공간의 3차원 좌표와 깊이 정보를 센서로 인식하고 디지털 콘텐츠를 같은 좌표계에 배치하는 기술)은 가상 객체를 현실 공간에 영속적으로 두고 상호작용하게 함. 가상 현실(VR, Virtual Reality)과 증강 현실(AR, Augmented Reality)을 포괄하는 확장 현실(XR, Extended Reality) 흐름의 한 축임.
- 배경 및 필요성 : 고정된 2차원 화면은 현실 맥락을 담기 어려움. 공간 인식을 위해 기기가 상시 주변을 센싱하므로 주변인의 프라이버시 침해 위험이 생기고, 장시간 착용 시 **시각유발 어지럼증** (VIMS, Visually Induced Motion Sickness, 시각 자극으로 생기는 멀미와 어지럼증)이 나타나므로, 온디바이스 처리와 인체공학적 경량 설계가 필수임.
- 주요 목적 : 화면 경계를 넘는 정보 표시, 현실 맥락 기반 작업 지원, 그리고 **자연 사용자 인터페이스** (NUI, Natural User Interface, 음성·제스처·시선처럼 자연스러운 입력으로 조작하는 방식) 제공.

## Ⅱ. 공간 컴퓨팅(Spatial Computing)의 특징 및 장점

- 핵심 요약 : 공간 인식, 자연 입력, 물리 일치 렌더링이 결합해 현실에 객체를 고정하고 몸으로 조작하게 하는 특성.

1. 공간 앵커링 : 벽면이나 테이블에 가상 객체를 고정하고 세션 사이에 위치를 복원 → 작업 공간을 현실에 영속적으로 배치.
2. **오클루전** (Occlusion, 실제 물체가 가상 객체를 가리는 처리) : 깊이 센싱으로 가구 뒤에 가상 객체가 숨도록 렌더링 → 현실감과 공간 일관성 확보.
3. 자연 입력 : **시선 추적** (Eye Tracking, 눈동자의 응시 위치를 실시간으로 계산하는 기술)으로 포인팅하고 손 핀치, 음성 명령을 조합 → 컨트롤러 없이 손을 쓴 채 조작 가능.
4. 공간 음향 : **HRTF** (Head-Related Transfer Function, 머리와 귀의 음향 전달 특성을 반영한 함수) 기반으로 음원 위치를 시뮬레이션 → 소리 방향감과 몰입감 향상.

## Ⅲ. 공간 컴퓨팅(Spatial Computing)의 구조 (흐름)

- 핵심 요약 : 센싱과 공간 인지, 입력 해석, 렌더링과 음향이 실시간 이벤트 스트림으로 이어지는 3계층 파이프라인.
- 센싱 계층 : **LiDAR** (Light Detection and Ranging, 레이저 펄스로 거리와 표면을 측정하는 센서)와 **IMU** (Inertial Measurement Unit, 가속도와 각속도를 측정하는 관성 측정 장치)으로 기기 위치와 주변 깊이를 얻음.
- 렌더링 : 시선이 머무는 영역만 고해상도로 그리는 **포비티드 렌더링** (Foveated Rendering, 시선 위치를 기준으로 해상도를 달리하는 기법)으로 연산 부담을 줄임.
- 위치 추정 : **SLAM** (Simultaneous Localization and Mapping, 자기 위치 추정과 지도 작성을 동시에 수행하는 기법)으로 **6자유도** (6DoF, Six Degrees of Freedom, 위치 3축과 회전 3축) 추적을 수행하고, 그 결과로 공간 메싱을 만듦.

```text
[센싱 및 공간 인지]
  카메라, LiDAR, IMU, 시선 추적기
        ↓ 공간 좌표계와 깊이 정보
[입력 해석]
  시선 포인팅, 손 추적, 제스처, 음성
        ↓ 이벤트 스트림
[렌더링 및 음향]
  저지연 패스스루, 오클루전, 공간 음향
```

```text
시선 추적 : 응시 지점으로 대상 선택
        ↓
손 추적 : 핀치 동작으로 확정
        ↓
이벤트 전달 : 객체 조작 명령 실행
```

## Ⅳ. 공간 컴퓨팅(Spatial Computing)과 2D 화면 컴퓨팅의 비교

- 핵심 요약 : 고정된 평면 화면 중심의 컴퓨팅에서 현실 공간을 작업 면으로 쓰는 컴퓨팅으로 전환.

| 비교 항목 | 전통적 2D 화면 컴퓨팅 | 공간 컴퓨팅 |
| --- | --- | --- |
| 디스플레이 영역 | 고정된 모니터와 스마트폰 화면 | 사용자 시야 전방의 3차원 물리 공간 |
| 좌표계 | 2차원 평면 픽셀 좌표계 (X, Y) | 현실과 결합된 3차원 월드 좌표계 |
| 입력 도구 | 키보드, 마우스, 터치스크린 | 시선, 손동작, 음성, 햅틱 |
| 객체 관계 | 가상 창의 단순 겹침 (Z-Order) | 실제 가구·벽과의 오클루전과 조명 일치 |
| 적용 영역 | 문서 작성, 2D 웹 브라우징 | 디지털 트윈 협업, 원격 지원, 공간 설계 |

- 선택 기준 : 문서 작성과 정형 입력이 많으면 2D 화면이, 현실 공간 맥락이 작업의 핵심이면 공간 컴퓨팅이 적합함.

## Ⅴ. 공간 컴퓨팅(Spatial Computing)의 한계와 방안

- 핵심 요약 : 사생활 침해, 시각 피로, 배터리와 중량 한계를 온디바이스 처리, 광학 보정, 연산 분산으로 통제해야 함.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 상시 카메라 센싱에 따른 프라이버시 침해 | 외부 카메라가 주변인의 얼굴과 사적 공간을 촬영·유출할 위험 | 온디바이스에서 특징점만 추출하고 원시 영상은 즉시 폐기, 외부 반출 금지 | 원시 영상 외부 전송 건수 |
| **초점-조절 불일치** (VAC, Vergence-Accommodation Conflict)에 따른 피로 | 가상 객체의 초점 거리와 실제 표시면 거리가 달라 두통과 어지럼증 유발 | 가변 초점 렌즈 검토, 저지연 패스스루 유지, 동공 간 거리(IPD, Interpupillary Distance) 자동 보정 | 연속 사용 시간 대비 불편 보고율 |
| 배터리와 중량 한계 | 고성능 칩과 다중 센서가 발열과 무게를 키워 장시간 착용이 어려움 | 배터리 분리 설계로 본체 무게 축소, 렌더링 일부를 엣지 서버로 오프로딩 | 연속 사용 시간, 본체 무게 |

## Ⅵ. 공간 컴퓨팅(Spatial Computing)에 대한 기술사적 제언

- 핵심 요약 : 입력 방식, 공간 이해 수준, 생태계 개방성을 함께 높여 공간 컴퓨팅을 실사용 플랫폼으로 정착시켜야 함.

1. 입력 체계는 전용 컨트롤러 중심에서 벗어나 시선, 손 제스처, 음성을 결합하는 방향으로 설계하고, AI 기반 공간 에이전트를 그 결합 위에 얹는 것이 바람직하다.
2. 공간 이해는 바닥과 벽 같은 평면 인식에서 물체의 속성과 3차원 형상까지 확장하는 시맨틱 3D 인식으로 발전시켜야 하며, 공간 데이터의 개인정보 보호 기준은 수집 단계부터 적용해야 한다.
3. 독립형 앱 생태계에 머물지 않도록 공간 운영체제와 **웹 기반 XR 표준** (WebXR, 웹 브라우저에서 확장 현실 기능을 쓰는 표준 API)을 함께 지원하여 개발자 접근성을 넓혀야 한다.

## Ⅶ. 결론

- 핵심 요약 : 공간 컴퓨팅은 현실 공간을 인터페이스로 바꾸는 기술 체계이며, 화면 경계를 넘는 만큼 프라이버시와 착용 피로를 함께 설계해야 함.
- 시사점 : 기기 성능보다 사회적 수용성과 인체공학이 보급 속도를 좌우하므로, 공간 데이터 보호와 피로 저감을 제품 기준으로 삼아야 함.
