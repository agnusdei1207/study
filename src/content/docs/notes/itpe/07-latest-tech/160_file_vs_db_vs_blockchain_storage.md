## 지식 로드맵 내 현재 위치

분산원장 → 데이터 저장 → 파일·DB·블록체인 비교

## 30초 인출

- 본질: 사진과 영상 같은 원본은 파일·오브젝트 저장소, 조회·갱신이 필요한 업무 데이터는 DB, 여러 주체가 검증할 필요가 있는 기록의 해시는 필요성을 따져 원장에 배치
- 메커니즘: 원본은 파일, 검색·갱신 상태는 DB, 다자 검증이 필요한 기록은 해시 원장에 배치
- 통찰: 한계: 원본까지 원장에 넣으면 삭제·비용·조회 요구를 맞추기 어렵다 → 방안: 원본은 파일, 상태는 DB, 다자 검증이 필요한 해시만 원장에 배치하고 연결 식별자를 검증한다.

<details><summary>핵심 용어</summary>

- **온체인:** 합의한 거래·기록을 블록체인 원장에 저장하는 방식
- **오프체인:** 원본을 외부에 보관하고 필요할 때 해시 등 검증 정보를 원장과 연결하는 방식

</details>

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 파일·DB·블록체인의 저장·조회·검증 특성 비교 |
| 목적 | 원본·업무 상태·다자 검증 기록의 적합한 배치 |

## Ⅱ. 저장 역할의 분리

```text
원본 파일 ──식별자·버전── DB의 검색·갱신 상태
    │                         │
    └── 원본 해시 ──────────────┴→ 다자 검증이 필요할 때만 원장 기록
```

- **목적:** 대용량 증빙의 저장, 빈번한 조회·정정, 기관 간 제출 이력 검증의 요구 분리.
- **구성:** 객체 저장소에 암호화된 원본 보관 → DB에 권한·버전·검색 인덱스 관리 → 필요 시 해시와 거래 식별자를 원장에 기록. 파일과 원장 기록의 연결은 식별자·버전·해시로 검증.

## Ⅲ. 저장 방식의 선택 기준

| 요구 | 파일·오브젝트 | DB | 블록체인 |
|---|---|---|---|
| 대용량 원본 | 적합 | 메타데이터 연결 | 원문 저장 부적합 |
| 빈번한 검색·정정 | 버전 원본 보관 | 거래·인덱스 관리 | 변경 비용·불변성 제약 |
| 다자 간 이력 검증 | 원본 해시 제공 | 식별자 연결 | 필요한 해시만 기록 |

## Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 원본까지 원장에 넣으면 삭제·비용·조회 요구를 맞추기 어렵다 | 원본은 파일, 상태는 DB, 다자 검증이 필요한 해시만 원장에 배치하고 연결 식별자를 검증한다 |

## Ⅴ. 제언

- 증빙의 삭제·정정이 필요한 업무부터 원본·상태·검증 기록의 저장 책임을 분리해 설계한다.
