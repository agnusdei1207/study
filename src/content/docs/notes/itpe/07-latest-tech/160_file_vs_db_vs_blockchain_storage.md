## 답안 골격
### 1교시 예상문제 (10점)
파일 저장소, 데이터베이스, 블록체인 저장 방식의 차이와 선택 기준을 설명하시오.

### 1교시 10점 답안
- **정의:** 파일 저장은 객체·경로 단위의 바이트 보관, DB는 스키마·인덱스와 질의를 통한 데이터 관리, 블록체인은 복수 참여자가 합의한 거래 이력의 공유 원장.
- **구조:** 원본 파일 → 객체 저장소, 검색·수정이 필요한 메타데이터 → DB, 참여자 간 사후 검증이 필요한 요약 해시 → 원장.
- **선택 기준:** 데이터 크기, 질의·갱신 빈도, 참여자 신뢰 구조, 개인정보·삭제 요구, 거래 비용과 지연.

### 2~4교시 예상문제 (25점)
기업의 디지털 증빙 시스템에서 세 저장 방식을 비교하고 하이브리드 저장 구조와 통제 방안을 제시하시오.

### 2~4교시 25점 답안
1. **목적:** 대용량 증빙의 저장, 빈번한 조회·정정, 기관 간 제출 이력 검증의 요구 분리.
2. **구성:** 객체 저장소에 암호화된 원본 보관 → DB에 권한·버전·검색 인덱스 관리 → 필요 시 해시와 거래 식별자를 원장에 기록. 파일과 원장 기록의 연결은 식별자·버전·해시로 검증.
3. **비교:** 파일은 비정형 데이터 처리와 저장 비용에 적합, DB는 트랜잭션·검색·수정에 적합, 블록체인은 다자 공유 이력의 변조 탐지에 적합. 어느 방식도 단독으로 접근 통제·진위 확인을 보장하지 않음.
4. **통제:** 개인정보 원문 온체인 배제, 키와 접근 권한 분리, 해시 재식별 가능성 검토, 삭제·보존 정책 및 복구 시험. 참여자 간 불신이 낮다면 서명된 중앙 감사 로그와의 비용 비교.

## 한 줄 본질
- 사진과 영상 같은 원본은 파일·오브젝트 저장소, 조회·갱신이 필요한 업무 데이터는 DB, 여러 주체가 검증할 필요가 있는 기록의 해시는 필요성을 따져 원장에 배치

## 핵심 용어
- 불변성(Immutability): 확정된 원장 기록의 변경을 어렵고 탐지 가능하게 하는 성질. 실제 보장은 합의 방식, 네트워크 지배 구조, 재구성 가능성에 따름
- 온체인(On-Chain) vs 오프체인(Off-Chain): 트랜잭션과 데이터를 블록체인 원장 내부(온체인)에 직접 기록하는 방식과, 대용량 데이터를 외부 파일/DB(오프체인)에 두고 해시값만 체인에 올리는 방식
- IPFS(InterPlanetary File System): 파일의 저장 위치(URL)가 아닌 파일 내용의 고유 해시값(CID: Content Identifier)을 주소로 사용하는 P2P 분산 파일 시스템

## 핵심 통찰
- 블록체인은 참여자 간 공통 기록·검증이 필요한 경우에 검토하며, 저장 비용과 처리량은 네트워크·구현·복제 정책에 따라 비교해야 함
- CRUD vs 기록 추가: DB도 권한·감사 로그·백업으로 변경을 통제할 수 있음. 블록체인에서는 기록을 추가해 상태를 갱신하며, 감사 가능성은 원장 외부 입력과 운영 통제까지 확인해야 함
- 최적의 공존 공식: 대용량 원본 파일(File/IPFS) + 비즈니스 처리 및 빠른 인덱스 검색(DB) + 무결성 검증용 무단 변조 방지 해시 앵커링(Blockchain)의 3단 결합

## 이웃 토픽과 구분
- 파일 vs DB vs 블록체인 저장소 핵심 비교:
| 구분 | 파일/오브젝트 스토리지 | 데이터베이스(RDBMS/NoSQL) | 블록체인 분산 원장 |
|---|---|---|---|
| 데이터 연산 | 파일·객체별 읽기/쓰기 | 질의·수정·삭제와 제품별 트랜잭션 | 거래 이력 추가와 상태 갱신·삭제 제약 |
| 검색 기능 | 파일명/경로 기반 단순 조회 | SQL/NoSQL 복합 인덱스 고속 검색 | 트랜잭션 해시/블록 번호 단순 검색 |
| 무결성 보장 | OS/스토리지 ACL 및 백업 의존 | DBMS 무결성 제약 및 로그 의존 | 분산 합의 및 암호학적 머클 트리 |
| 저장 비용 | 용량·요청·전송량에 따름 | 운영·복제·트랜잭션 요구에 따름 | 합의·복제·거래 수수료에 따름 |
| 탈중앙성 | 중앙 집중식 관리자 통제 | 중앙 집중식 관리자 통제 | 탈중앙 분산 P2P 합의 |

## 문제·원인·대책
- 적용 상황: 국가 공공 전자기록물 및 부동산 등기 시스템 구축
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 대용량 원본을 온체인에 직접 저장 | 복제·합의·수수료 부담을 고려하지 않음 | 원본은 접근 통제되는 외부 저장소에 두고 필요하면 해시를 앵커링 | 원본 보관·가용성과 해시 검증을 별도로 시험 |
| DB 관리자 계정 탈취 또는 내부자 변경 | 권한·감사 통제 부족 | 최소 권한, 변경 감사 로그와 독립 검증 경로 적용 | 권한 침해와 변경 이력의 탐지 가능성 확인 |
| 원장 기록의 복합 조건 조회가 어려움 | 체인의 실행·조회 구조와 업무 검색 요구 불일치 | 이벤트를 별도 인덱스·조회 DB에 동기화 | 인덱스 지연과 원장 기록의 일치 여부 확인 |

## 내 의견
- 개인정보는 원칙적으로 온체인 기록을 피하고, 오프체인 보존·삭제 정책과 해시의 재식별 가능성을 검토한다. 암호화 키 폐기만으로 법적 삭제 의무 충족이나 영구 삭제가 자동 보장되지는 않는다.
