## 지식 로드맵 내 현재 위치

분산원장 → 데이터 저장 → 파일·DB·블록체인 비교

## 30초 인출

- **본질:** 사진과 영상 같은 원본은 파일·오브젝트 저장소, 조회·갱신이 필요한 업무 데이터는 DB, 여러 주체가 검증할 필요가 있는 기록의 해시는 필요성을 따져 원장에 배치
- **메커니즘:** 원본은 파일, 검색·갱신 상태는 DB, 다자 검증이 필요한 기록은 해시 원장에 배치
- **답안 초점:** 파일 저장소, 데이터베이스, 블록체인 저장 방식의 차이와 선택 기준을 설명하시오.

<details><summary>핵심 용어</summary>

- **온체인:** 합의한 거래·기록을 블록체인 원장에 저장하는 방식
- **오프체인:** 원본을 외부에 보관하고 필요할 때 해시 등 검증 정보를 원장과 연결하는 방식

</details>

## 1교시 예상문제 (10점)

> 파일 저장소, 데이터베이스, 블록체인 저장 방식의 차이와 선택 기준을 설명하시오. (예상·10점)

---

## 1교시 10점 답안

| 구분 | 핵심 |
|---|---|
| 정의 | 파일·DB·블록체인의 저장·조회·검증 특성 비교 |
| 목적 | 원본·업무 상태·다자 검증 기록의 적합한 배치 |

- **구조:** 원본 파일 → 객체 저장소, 검색·수정이 필요한 메타데이터 → DB, 참여자 간 사후 검증이 필요한 요약 해시 → 원장.
- **선택 기준:** 데이터 크기, 질의·갱신 빈도, 참여자 신뢰 구조, 개인정보·삭제 요구, 거래 비용과 지연.

## 2~4교시 25점 답안

| 구분 | 핵심 |
|---|---|
| 정의 | 파일·DB·블록체인의 저장·조회·검증 특성 비교 |
| 목적 | 원본·업무 상태·다자 검증 기록의 적합한 배치 |

1. **목적:** 대용량 증빙의 저장, 빈번한 조회·정정, 기관 간 제출 이력 검증의 요구 분리.
2. **구성:** 객체 저장소에 암호화된 원본 보관 → DB에 권한·버전·검색 인덱스 관리 → 필요 시 해시와 거래 식별자를 원장에 기록. 파일과 원장 기록의 연결은 식별자·버전·해시로 검증.
3. **비교:** 파일은 비정형 데이터 처리와 저장 비용에 적합, DB는 트랜잭션·검색·수정에 적합, 블록체인은 다자 공유 이력의 변조 탐지에 적합. 어느 방식도 단독으로 접근 통제·진위 확인을 보장하지 않음.
4. **통제:** 개인정보 원문 온체인 배제, 키와 접근 권한 분리, 해시 재식별 가능성 검토, 삭제·보존 정책 및 복구 시험. 참여자 간 불신이 낮다면 서명된 중앙 감사 로그와의 비용 비교.
