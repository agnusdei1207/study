## 핵심 용어
- 불변성(Immutability): 블록체인 원장에 한 번 기록된 데이터는 이전 블록의 해시값과 암호학적으로 연결되어 관리자조차 사후 수정이나 삭제가 불가능한 특성
- 온체인(On-Chain) vs 오프체인(Off-Chain): 트랜잭션과 데이터를 블록체인 원장 내부(온체인)에 직접 기록하는 방식과, 대용량 데이터를 외부 파일/DB(오프체인)에 두고 해시값만 체인에 올리는 방식
- IPFS(InterPlanetary File System): 파일의 저장 위치(URL)가 아닌 파일 내용의 고유 해시값(CID: Content Identifier)을 주소로 사용하는 P2P 분산 파일 시스템

## 핵심 통찰
- "블록체인은 데이터베이스의 대체재가 아니다": 블록체인은 모든 노드가 동일한 데이터를 복제 저장하고 합의를 거쳐야 하므로, 1MB를 저장하는 비용이 DB 대비 수만 배 비쌈
- CRUD vs Append-only: DB는 Insert, Select, Update, Delete가 자유롭지만 내부자나 해커가 흔적 없이 위조할 수 있음 / 블록체인은 Update와 Delete가 불가능한 Write-Once 구조로 완전한 감사 추적성(Audit Trail)을 보장
- 최적의 공존 공식: 대용량 원본 파일(File/IPFS) + 비즈니스 처리 및 빠른 인덱스 검색(DB) + 무결성 검증용 무단 변조 방지 해시 앵커링(Blockchain)의 3단 결합

## 이웃 토픽과 구분
- 파일 vs DB vs 블록체인 저장소 핵심 비교:
| 구분 | 파일/오브젝트 스토리지 | 데이터베이스(RDBMS/NoSQL) | 블록체인 분산 원장 |
|---|---|---|---|
| 데이터 연산 | 단순 읽기/쓰기 (Over-write) | 완전한 CRUD (복합 트랜잭션) | Append-only (추가만 가능) |
| 검색 기능 | 파일명/경로 기반 단순 조회 | SQL/NoSQL 복합 인덱스 고속 검색 | 트랜잭션 해시/블록 번호 단순 검색 |
| 무결성 보장 | OS/스토리지 ACL 및 백업 의존 | DBMS 무결성 제약 및 로그 의존 | 분산 합의 및 암호학적 머클 트리 |
| 저장 비용 | 극히 저렴 (GB당 수십 원) | 보통 (인메모리/SSD 비용) | 극도로 고비용 (모든 노드 복제) |
| 탈중앙성 | 중앙 집중식 관리자 통제 | 중앙 집중식 관리자 통제 | 탈중앙 분산 P2P 합의 |

## 문제·원인·대책
- 적용 상황: 국가 공공 전자기록물 및 부동산 등기 시스템 구축
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 수십 MB 등기부 PDF 원본을 블록체인에 직접 저장하여 수수료 폭증 및 노드 동기화 실패 | 블록체인의 분산 복제 오버헤드와 블록 크기 제약 미고려 | 오프체인 IPFS/S3에 원본 저장 후 파일 SHA-256 해시값만 온체인 앵커링 | 가스비 99.9% 절감 및 처리 속도 100배 향상 |
| 기존 RDBMS 관리자 계정 탈취로 인한 부동산 소유권 정보 임의 변조 사고 | RDBMS의 내부자 수정 권한 무제한성 | 변경 이력 발생 시 블록체인 스마트 컨트랙트로 실시간 무결성 해시 검증 | 무단 변조 시도 즉시 탐지 및 차단 |
| 블록체인 온체인 데이터는 SQL 같은 복합 조건(지역별, 연도별) 검색 불가 | Key-Value 형태의 블록 데이터 저장 구조 한계 | The Graph 기반 온체인 이벤트 인덱싱 및 읽기 전용 CQRS NoSQL 동기화 | 밀리초 단위 복합 쿼리 조회 지원 |
