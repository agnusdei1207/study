## 연관 키워드

- 데이터 차원 축소, 차원의 저주, 특성 선택, 특성 추출
- 주성분 분석(PCA), 선형 판별 분석(LDA), t-SNE, UMAP, 오토인코더
- 다중공선성, 데이터 누수, Pipeline, 희소 PCA(Sparse PCA)

## Ⅰ. 데이터 차원 축소의 개요

- 핵심 요약 : 정보를 최대한 남기면서 변수 수를 줄여 학습 비용과 과적합을 함께 낮추는 전처리 기법.
- 개념 : 고차원 피처 공간의 분산과 구조를 가능한 한 보존하면서 저차원 표현으로 바꾸는 **데이터 차원 축소** (Dimensionality Reduction) 기법.
- 배경 및 필요성 : 변수가 늘어나면 **차원의 저주** (Curse of Dimensionality)로 표본 밀도가 떨어져 같은 성능을 얻는 데 더 많은 데이터와 연산이 필요함. 변수끼리 중복이 크면 계수 해석이 불안정해지므로, 변수 수를 줄이는 전처리 계층이 모델 앞단에 필요함.
- 주요 목적 : 연산 복잡도 감소, 다중공선성 완화, 과적합 억제, 고차원 데이터 시각화 지원.

## Ⅱ. 데이터 차원 축소의 특징 및 장점

- 핵심 요약 : 원본 변수를 고르는 방식과 새 축으로 변환하는 방식이 해석성과 표현력의 장단점을 나눔.

1. 특성 선택 (Feature Selection) : 원본 변수 중 유용한 것만 골라 남김 → 변수의 업무 의미가 그대로 남아 해석성 확보. Filter, Wrapper, Embedded 방식으로 구분.
2. **주성분 분석** (PCA, Principal Component Analysis) : 분산이 큰 방향으로 직교 투영 → 연산이 빠르고 신규 데이터에도 행렬 곱 하나로 적용 가능.
3. 비선형 매니폴드 학습 : t-SNE, **UMAP** (Uniform Manifold Approximation and Projection) 등이 이웃 관계를 보존 → 곡면 형태의 군집 구조를 시각화에 적합하게 드러냄.
4. 딥러닝 기반 추출 : **오토인코더** (Autoencoder)의 병목층 잠재 벡터로 비선형 압축 → 선형 방법으로 잡히지 않는 복합 패턴 표현.

## Ⅲ. 데이터 차원 축소의 구조 (흐름)

- 핵심 요약 : 분할 후 훈련 데이터로만 변환기를 학습하고, 같은 변환을 검증·테스트 데이터에 재적용하는 파이프라인 구조.

```text
[ 원본 고차원 데이터 ]
          ↓
[ 훈련 / 검증 / 테스트 분할 ]
          ↓
[ 훈련 데이터로만 변환기 학습 ]
          ↓
[ 같은 변환을 검증·테스트에 적용 ]
          ↓
[ 저차원 데이터로 모델 학습 ]
```

```text
차원 축소
  특성 선택 : 원본 변수 중 선별
  특성 추출 : 새 축으로 변환
    선형 : PCA, LDA
    비선형 : t-SNE, UMAP, Kernel PCA
    딥러닝 : 오토인코더
```

## Ⅳ. 데이터 차원 축소의 비교

- 핵심 요약 : 해석성을 우선하면 특성 선택, 연산 효율을 우선하면 선형 추출, 비선형 구조 탐색이 목적이면 매니폴드 기법을 고른다.

| 비교 항목 | 특성 선택 | 선형 특성 추출 (PCA) | 비선형 매니폴드 (UMAP, t-SNE) |
| --- | --- | --- | --- |
| 변수 의미 | 원본 변수 그대로 유지 | 변수들의 선형 결합이라 해석 난해 | 축의 의미가 소실되기 쉬움 |
| 연산 부담 | Filter는 낮고 Wrapper는 높음 | 공분산 행렬 분해 기반, 변수 수에 민감 | 대용량 데이터에서 부담이 큼 |
| 비선형 구조 | 모델에 따라 상호작용 반영 가능 | 선형 투영만 가능 | 곡면 구조 보존에 강함 |
| 신규 데이터 투영 | 즉시 적용 가능 | 행렬 곱으로 즉시 투영 | t-SNE는 재학습 필요, UMAP은 가능 |
| 주요 활용 | 업무 KPI 도출, 의사결정 모델 | 전처리, 다중공선성 해소 | 고차원 임베딩 시각화, 군집 탐색 |

## Ⅴ. 데이터 차원 축소의 한계와 방안

- 핵심 요약 : 전처리 누수, 분산 기준의 정보 손실, 해석 곤란을 파이프라인 격리와 지도 기법, 해석 도구로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| **데이터 누수** (Data Leakage) | 교차 검증 전에 전체 데이터로 PCA를 적합 → 검증 정보가 학습에 섞여 성능 과대평가 | Pipeline 객체로 각 폴드 내부에서만 변환기를 적합 | 폴드 간 성능 편차 |
| 분산 기준과 분류 신호의 불일치 | 분산이 큰 축이 타깃 분류에 유용하다는 보장이 없어 중요 정보 손실 | 지도 기법인 LDA 병용 또는 타깃 상관을 반영하는 PLS 적용 | 축소 전후 정확도 차이 |
| 주성분의 해석 난해성 | 잠재 축이 원본 변수의 혼합이라 현업에서 의미 전달이 어려움 | 희소 PCA(Sparse PCA) 적용, SHAP으로 원본 변수 기여도 역추적 | 현업 설명 검토 통과율 |

## Ⅵ. 데이터 차원 축소에 대한 기술사적 제언

- 핵심 요약 : 누수 방지를 개발 표준으로 고정하고, 전처리와 모델을 하나의 산출물로 배포하는 체계로 운영을 내재화.

1. 누수 통제 : 분석 조직은 전역 적합 호출을 금지하고 Pipeline 객체 사용을 코드 리뷰 기준으로 정해야 한다. 검증 단계에서 누수가 발견되면 성능 지표를 신뢰하지 않는 규칙을 함께 두는 것이 효과적이다.
2. 배포 일관성 : 정보시스템 부서는 전처리, 차원 축소기, 모델을 하나의 직렬화 파일로 묶는 MLOps(Machine Learning Operations) 배포 절차를 마련해야 한다. 학습과 추론에서 변환이 달라지는 문제를 구조적으로 막기 위함이다.
3. 차원 수 관리 : 데이터가 바뀔 때마다 주성분 수를 수작업으로 고치지 않도록, 설명 분산 비율 임계치 기준으로 차원 수를 자동 조정하는 정책을 둘 필요가 있다.

## Ⅶ. 결론

- 핵심 요약 : 데이터 차원 축소는 해석성과 정보 보존 사이에서 기법을 고르고, 누수 없는 파이프라인으로 운영하는 기술임.
- 시사점 : 기법 선택은 해석 필요성과 배포 빈도로 정하며, 학습과 추론에 같은 변환을 재현하는 것이 성능 신뢰의 전제 조건이다.
