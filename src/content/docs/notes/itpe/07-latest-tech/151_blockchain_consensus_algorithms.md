```text
 ┃
 ┣━ Ⅰ 개요 ───── 중앙 신뢰 기관이 없는 분산 P2P 환경에서 악의적 노드의 위조·변조(이중지불)를 방어하고 단일 분산 원장 상태에 합의할 메커니즘 필요
 ┣━ Ⅱ 요구조건 ── 안전성(Safety: 모든 정상 노드가 동일 값 합의) · 생존성(Liveness: 지연 없이 지속 진행) · 내결함성(Fault Tolerance: 배신자 노드 허용)
 ┣━ Ⅲ 유형 ───── 작업 기반(PoW) + 지분 기반(PoS, DPoS) + 투표 기반(PBFT, Raft) + 하이브리드(PoA, PoH)
 ┣━ Ⅳ 메커니즘 ─ PoW: 해시 퍼즐 연산 경쟁 / PoS: 지분 비례 검증 권한 및 슬래싱(Slashing) / PBFT: Pre-prepare → Prepare → Commit 3단계 투표 합의
 ┣━ Ⅴ 비교 ───── PoW vs PoS vs PBFT (연산자원소모/확률적최종성/낮은TPS vs 자본기반/슬래싱보안/중간TPS vs 통신메시지복잡도O(n^2)/즉각최종성/인가노드초고속)
 ┗━ Ⅵ 실무 ───── Nothing at Stake 문제 / 포크(Fork) 발생에 따른 최종성 지연 / 노드 수 증가에 따른 통신 오버헤드 폭증
```
- 필수 키워드: 합의 알고리즘(Consensus Algorithm) · Safety · Liveness · PoW · PoS · DPoS · PBFT · 슬래싱(Slashing) · 최종성(Finality)
- 출제 이력: 제122회 문항은 공식 Q-Net 원문 미수집으로 미확인. 아래 문항은 예상문제

## 한 줄 본질
- 블록체인 합의 알고리즘은 분산 노드가 거래·블록의 순서와 유효성을 공동 결정하는 규칙. 안전성·활성 보장은 장애 가정과 네트워크 조건에 따름

## 핵심 그림
```text
[대표적 3대 블록체인 합의 알고리즘 메커니즘 비교]

  [1. PoW (작업 증명)]        [2. PoS (지분 증명)]       [3. PBFT (실용적 비잔틴 결함)]
  ┌──────────────────┐       ┌──────────────────┐      ┌─────────────────────────┐
  │ Nonce 연산 경쟁   │       │ 코인 지분(Stake) │      │ Pre-prepare -> Prepare  │
  │ SHA-256 난이도목표│       │ 난수 추출 검증자 │      │ -> Commit (2/3+1 동의)  │
  └────────┬─────────┘       └────────┬─────────┘      └────────────┬────────────┘
           │                          │                             │
           ▼                          ▼                             ▼
    막대한 전기 소모           지분 독점/Nothing at Stake    통신량 O(N^2) (노드수 제한)
    (비트코인)                 (이더리움 PoS)                (일부 BFT 체인)
```

## 핵심 용어
- Safety(안전성): 시스템 내의 모든 정상적인 노드가 언제나 상충되지 않는 동일한 블록 상태에 도달함을 보장하는 속성 (잘못된 합의는 절대 발생하지 않음)
- Liveness(생존성): 시스템이 교착 상태(Deadlock)에 빠지지 않고 새로운 유효 트랜잭션을 담은 블록을 계속해서 생성하고 합의를 전진시키는 속성
- 슬래싱(Slashing): PoS 환경에서 이중 서명이나 악의적인 포크를 시도한 검증자의 예치 지분(Stake)을 시스템이 강제로 몰수·소각하는 페널티 메커니즘

## 핵심 통찰
- "자원 낭비(PoW)에서 경제적 지분(PoS)으로": 연간 국가 단위 전력을 소모하던 PoW의 치명적 환경 파괴를 막기 위해, 악행을 저지르면 자신의 돈이 날아가는 경제적 게임이론(Game Theory) 기반 PoS로 대전환
- FLP 불가능성 정리: 완전 비동기 네트워크에서 한 프로세스의 충돌 가능성만 있어도 결정적 합의 알고리즘이 모든 실행에서 종료를 보장할 수 없다는 결과. 안전성 자체가 불가능하다는 뜻은 아님
- 허가형 네트워크는 신원 확인된 노드 사이에서 BFT 또는 충돌 장애 허용 합의를 선택할 수 있음. Hyperledger Fabric은 Raft와 SmartBFT 정렬 서비스를 지원하며 지연·최종성은 구성별 측정 필요

## 이웃 토픽과 구분
- PoS는 지분을 이용해 검증자 선정·제재를 설계하는 방식이며, 모든 보유자가 직접 검증하는 것은 아님. DPoS는 대표 검증자를 투표로 선출하는 계열로 선출 수·운영 규칙은 구현별 차이

## 문제·원인·대책
- 아래 사례의 조건·수치는 가상 예시이며 실제 성과가 아님.
- 적용 상황: 글로벌 핀테크 소액 결제망에 블록체인 합의 엔진 구축
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| PoW 적용 시 결제 확정까지 6개 블록(약 60분) 대기 시간 발생 | 확률적 최종성(Probabilistic Finality)으로 인한 체인 재구성(Reorg) 위험 | PBFT 기반 Tendermint BFT 합의 엔진으로 전환 | 1개 블록 생성 즉시 1초 이내 거래 완결성 보장 |
| PoS 도입 초기 검증자들이 모든 포크 체인에 양다리 서명 시도 | 서명 시 연산 비용이 전혀 들지 않는 Nothing at Stake 구조 | 악의적 이중 서명 검증 시 스테이킹 자산을 즉각 소각하는 슬래싱(Slashing) 탑재 | 포크 공격 원천 무력화 및 네트워크 안정화 |
| 검증자 수가 늘어 합의 메시지·서명 처리 지연 증가 | 고전 PBFT의 정상 경로 메시지량은 노드 수에 대해 대체로 이차적으로 증가 | 서명 집계·위원회 축소 등의 설계가 신뢰 가정에 미치는 영향 검토 | 노드 수별 처리량·지연·장애 허용 범위 측정 |

## 1교시 예상문제 (10점)
- 블록체인 합의의 안전성과 활성 개념을 설명하시오.

## 1교시 10점 답안
- **안전성:** 정직한 참여자가 충돌하는 거래 이력을 최종 확정하지 않는 성질.
- **활성:** 허용된 조건에서 유효 거래의 처리가 계속 진행되는 성질.
- **방식:** PoW·PoS는 자원·지분과 경제적 가정을, BFT 계열은 위원회·장애 수와 네트워크 가정을 명시해 비교.

## 2~4교시 예상문제 (25점)
- 주요 합의 알고리즘의 원리와 안전성·활성 조건을 비교하시오.

## 2~4교시 25점 답안
### Ⅰ. 합의 목표
- 참여 노드가 거래 순서·상태에 합의하며 이중 지불·분기 충돌을 관리.
### Ⅱ. 방식 비교
| 계열 | 선택·확정 원리 | 검토 조건 |
|---|---|---|
| PoW | 작업량 기반 체인 선택 | 해시 자원 분포·확인 깊이 |
| PoS | 지분 기반 제안·투표 | 지분 집중·벌칙·최종성 규칙 |
| BFT | 위원회 메시지 교환 | 허용 장애 수·네트워크 동기 가정 |
### Ⅲ. 설계 쟁점
- 안전성과 활성은 네트워크 지연·분할 및 악의적 노드 가정에 좌우. 구현별 합의 프로토콜을 확인.
### Ⅳ. 운영
- 검증자 분산, 키 보관, 지연·포크·복구 시험으로 실제 최종성 평가.
