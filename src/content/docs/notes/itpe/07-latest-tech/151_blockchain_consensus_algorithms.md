## 30초 인출

- **본질:** 블록체인 합의 알고리즘은 분산 노드가 거래·블록의 순서와 유효성을 공동 결정하는 규칙. 안전성·활성 보장은 장애 가정과 네트워크 조건에 따름
- **메커니즘:** PoW의 작업량, PoS의 지분·투표, BFT의 위원회 메시지로 원장 상태 결정
- 통찰: 한계: 합의 방식 이름만으로 확정성과 장애 허용 범위를 판단하기 어려움 → 방안: 구현별 네트워크·악의적 노드 가정을 확인하고 분할·복구 시험
- **답안 초점:** 블록체인 합의의 안전성과 활성 개념을 설명하시오.

- **활성:** 허용된 장애·네트워크 조건에서 거래 처리와 합의가 진행되는 성질

## 2~4교시 25점 답안

## Ⅰ. 블록체인 합의 알고리즘의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 분산 노드가 거래 순서·유효성과 원장 상태를 공동 결정하는 규칙 |
| 목적 | 이중 지불과 분기 충돌을 관리하며 거래의 최종 확정 조건 제공 |

## Ⅱ. 거래 제안에서 원장 확정까지의 합의 구조

```text
거래 검증 → 블록 제안 → 노드 간 선택·투표 → 확정 조건 판단 → 원장 반영
                         │ PoW: 작업량    │
                         ├ PoS: 지분·투표  ┤ 방식별 장애·네트워크 가정
                         └ BFT: 위원회 메시지
```

## Ⅲ. PoW·PoS·BFT의 확정 조건 비교

| 계열 | 선택·확정 원리 | 검토 조건 |
|---|---|---|
| PoW | 작업량 기반 체인 선택 | 해시 자원 분포·확인 깊이 |
| PoS | 지분 기반 제안·투표 | 지분 집중·벌칙·최종성 규칙 |
| BFT | 위원회 메시지 교환 | 허용 장애 수·네트워크 동기 가정 |

## Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 네트워크 분할이나 악의적 노드가 가정을 넘으면 안전성·활성 저하 | 구현별 허용 장애 수와 동기화 조건을 문서화하고 분할·복구 시험 |
| 검증자 또는 해시 자원의 집중으로 원장 통제 위험 증가 | 참여 분포와 키 권한을 점검하고 최종성·포크 지표 감시 |

## Ⅴ. 제언

서비스가 요구하는 확정 시간과 장애 허용 범위를 먼저 정한 뒤 프로토콜별 실제 확정성을 비교.
