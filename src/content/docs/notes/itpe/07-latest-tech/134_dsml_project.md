## 핵심 용어
- PoC 트랩(PoC Trap): 주피터 노트북 환경에서는 95%의 놀라운 예측 정확도를 보였으나, 실제 레거시 IT 인프라 연동, 데이터 파이프라인 부재, 현업 부서의 외면으로 실서빙에 실패하고 폐기되는 현상
- CRISP-DM(Cross-Industry Standard Process for Data Mining): 비즈니스 이해 → 데이터 이해 → 데이터 준비 → 모델링 → 평가 → 배포의 6단계를 반복 순환하는 데이터 마이닝/DSML의 글로벌 표준 프로세스
- 숨은 기술 부채(Hidden Technical Debt): 머신러닝 시스템에서 순수 ML 코드는 전체 시스템의 5% 미만이며, 나머지 95%는 데이터 검증, 피처 추출, 인프라 서빙 등 방대한 주변 배관 코드(Glue Code)로 구성되어 유지보수 부채를 유발한다는 이론

## 핵심 통찰
- "정확도(Accuracy)에 취하지 말고 비즈니스 화폐 가치(Dollar)로 환산하라": 데이터 과학자는 AUC가 0.92에서 0.94로 올랐다고 기뻐하지만, 경영진은 "그래서 고객 이탈이 몇 명 줄어들고 얼마가 절감되는가?"를 묻기 때문에 두 지표의 가교 설계가 프로젝트의 생사를 가름
- 애자일(Agile)과 데이터 탐색의 융합: 머신러닝은 3개월 뒤에 어떤 모델이 최고일지 사전에 알 수 없으므로, 2주 단위 스프린트로 가설을 검증하고 가망 없는 아이디어는 빠르게 폐기(Fail-fast)하는 애자일 접근이 필수적임
- 크로스 펑셔널 팀(Cross-functional Team) 구성: 데이터 과학자(알고리즘) 혼자서는 배포를 못 하고, 데이터 엔지니어(파이프라인)와 ML 엔지니어(서빙), 현업 도메인 전문가가 첫날부터 원팀으로 결합해야 성공함

## 이웃 토픽과 구분
- 일반 IT 프로젝트 vs DSML 프로젝트: 일반 IT는 요구사항을 정하고 코드를 짜면 결과가 결정론적으로 나옴 / DSML은 데이터 품질에 따라 모델 성능이 확률적으로 요동치므로 가설 검증과 연구개발(R&D) 성격이 짙음
