## Ⅰ. DSML 프로젝트의 개요

- **개념** : 비즈니스 가치 창출을 목표로 정형·비정형 데이터 분석, 가설 수립, 탐색적 데이터 분석(EDA), 머신러닝 모델링, MLOps 기반 지속적 운영을 유기적으로 결합한 엔지니어링 라이프사이클.
- **배경 및 필요성** : 실험실(Jupyter) 중심의 모델 정확도 최적화에만 치중할 경우 기술 부채와 프로덕션 서빙 장애가 심화되므로 피처 스토어와 CI/CD/CT 기반의 자동화 파이프라인 체계 구축 필수.
- **핵심 목적** : 데이터 기반 의사결정 자동화, 고비용 수작업 프로세스 지능화, 비즈니스 ROI 입증 및 AI 기술 부채 최소화.

## Ⅱ. DSML 프로젝트의 핵심 아키텍처 및 동작 메커니즘

DSML 프로젝트는 신뢰할 수 있는 데이터 파이프라인과 고도화된 추론 메커니즘을 기반으로 동작하며, 세부적인 아키텍처와 핵심 컴포넌트 간 상호작용 프로세스는 다음과 같음.

```text
+-----------------------------------------------------------------------------------+
|                     엔터프라이즈 DSML 프로젝트 라이프사이클                       |
+-----------------------------------------------------------------------------------+
|  [1단계: 비즈니스 이해 및 가설 정의]                                              |
|    - 정량적 비즈니스 KPI 설정 (고객 이탈률 5% 감소, 사기 거래 차단율 95% 등)     |
|    - 예측 시점 제약 조건 및 추론 레이턴시(SLA) 정의                               |
+-----------------------------------------------------------------------------------+
                               │
                               ▼
+-----------------------------------------------------------------------------------+
|  [2단계: 데이터 파이프라인 및 피처 엔지니어링]                                    |
|    - 데이터 수집/정제, 결측치 대체, 범주형 인코딩, 스케일링                       |
|    - 피처 스토어(Feature Store) 등록: 온라인(Low Latency) 및 오프라인(Batch) 동기화 |
+-----------------------------------------------------------------------------------+
                               │
                               ▼
+-----------------------------------------------------------------------------------+
|  [3단계: 모델링, 실험 추적 및 PoC 오프라인 평가]                                  |
|    - 복수 알고리즘 벤치마크 (LightGBM, XGBoost, Deep Neural Network)               |
|    - 실험 추적(MLflow): 파라미터, 하이퍼파라미터, 지표, 아티팩트 자동 로깅        |
|    - 독립 테스트 셋 블라인드 평가 및 도메인 전문가 피드백 검증                    |
+-----------------------------------------------------------------------------------+
                               │
                               ▼
+-----------------------------------------------------------------------------------+
|  [4단계: MLOps 프로덕션 배포 및 지속적 훈련(CT)]                                  |
|    - Canary / Shadow 배포, A/B 테스트를 통한 실무 트래픽 점진적 검증              |
|    - 데이터 드리프트(Data Drift) 및 개념 드리프트(Concept Drift) 모니터링          |
|    - 임계치 초과 시 재학습(Retraining) 트리거 및 Model Registry 갱신              |
+-----------------------------------------------------------------------------------+
```

- **가설 기반 반복성** : 비결정론적(Probabilistic) 실험 순환 - 고정된 요구사항 명세서 대신 가설 수립 및 실험(Experimentation) 반복을 통한 성능 수렴.
- **데이터 종속성** : 데이터 품질에 따른 모델 성능 결정 - 코드 무결성뿐만 아니라 입력 데이터의 결측, 이상치, 클래스 불균형, 데이터 드리프트 상시 통제.
- **다학제 협업** : 비즈니스·데이터·인프라 융합 조직 - 현업 도메인 전문가, 데이터 과학자(DS), 머신러닝 엔지니어(MLE), 데이터 엔지니어(DE) 간 공조.
- **운영 복잡성** : 코드-데이터-모델 삼원 거버넌스 - 전통 소프트웨어의 소스 코드 버전 관리 외에 데이터셋 버전(DVC) 및 모델 가중치 계보 추적 일원화.

## Ⅲ. DSML 프로젝트의 세부 구성 요소 및 비교 분석

| 비교 항목 | 전통적 소프트웨어 개발 (Traditional SW) | DSML 프로젝트 (Data Science & ML) |
|---|---|---|
| **동작 결정성** | 결정론적(Deterministic: 동일 입력 시 동일 출력) | 비결정론적(Probabilistic: 확률적 추론 결과 산출) |
| **요구사항 확정** | 초기 요구분석 단계에서 기능 명세 동결 | 탐색적 분석(EDA) 및 실험 결과에 따른 동적 변경 |
| **핵심 자산** | 소스 코드 및 관계형 데이터베이스 스키마 | 데이터셋(버전), 피처 파이프라인, 모델 가중치 |
| **테스트 체계** | 단위 테스트, 통합 테스트, 시스템 테스트 | 오프라인 정밀도/재현율 평가, A/B 테스트, 드리프트 검출 |
| **유지보수 트리거** | 비즈니스 로직 변경 및 소프트웨어 버그 | 데이터 분포 변화(Data Drift) 및 성능 저하(Degradation) |

- DSML 프로젝트는 상기 비교 지표를 바탕으로 비즈니스 요구사항과 운영 인프라 환경을 고려한 최적의 아키텍처를 선정하고, 확장성과 안정성을 균형 있게 확보해야 함.

## Ⅳ. DSML 프로젝트의 주요 한계점 및 해결 방안

- **PoC 성공 후 프로덕션 배포 실패(PoC 무덤 현상)** :
  - **한계점** : 실험실 주피터 노트북 환경과 실제 운영 엔터프라이즈 인프라 간의 기술 격차로 상용화 좌초.
  - **해결 방안** : 초기 단계부터 MLOps 플랫폼(Kubeflow, Vertex AI) 기반 컨테이너화 파이프라인 표준화 및 모듈화된 코드베이스 강제.
- **학습-서빙 간 불일치(Training-Serving Skew) 및 데이터 누출** :
  - **한계점** : 학습 시점의 피처 추출 로직과 운영 서빙 시점의 로직 상이로 실전 추론 오류 발생.
  - **해결 방안** : 온라인-오프라인 통합 피처 스토어(Feast 등) 도입을 통한 단일 피처 연산 로직 강제 및 시계열 타임스탬프 기반 누출 차단.
- **개념 드리프트로 인한 운영 중 모델 급격한 성능 저하** :
  - **한계점** : 시장 환경 및 고객 행동 패턴 변화로 인해 배포 초기 우수했던 모델의 예측 정확도 급락.
  - **해결 방안** : 실시간 Kolmogorov-Smirnov 검정 기반 드리프트 감시 대시보드 구축 및 자동 재학습·배포(Continuous Training) 트리거 가동.

## Ⅴ. DSML 프로젝트 적용 및 발전을 위한 기술사적 제언

- **수행 주체 고도화 및 크로스펑셔널 팀 공조 추진** : 연구원 단독 주피터 노트북 모델링의 한계를 탈피하고, 크로스펑셔널 팀(DS + MLE + Biz Analyst) 공조를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- **코드 거버넌스 강화 및 신뢰성 확보 방안** : 개인 PC 내 소스 및 데이터 보관의 한계를 탈피하고, GitOps, DVC, Model Registry 통합 형상 관리를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- **배포 주기 고도화 및 CI/CD 파이프라인 기반 추진** : 연 1~2회 수동 배포 및 방치의 한계를 탈피하고, CI/CD 파이프라인 기반 주간/일간 자동 재학습 배포를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
