## 30초 인출
- 본질: 비즈니스 난제 해결을 위해 데이터 수집·가공, 탐색적 분석(EDA), 기계학습 모델링, PoC 검증 및 프로덕션 서빙과 MLOps 지속 운영까지 포괄하는 반복적 데이터 과학 수행 체계
- 메커니즘: 비즈니스 문제 정의 → 데이터 엔지니어링/피처 파이프라인 → 모델 학습/실험 추적(MLflow) → PoC 오프라인 평가 → MLOps 기반 서빙/배포 → 데이터·개념 드리프트 실시간 감시
- 통찰: 실험실(Jupyter) 중심의 모델 정확도 최적화에만 치중할 경우 기술 부채와 프로덕션 서빙 장애가 심화되므로 피처 스토어와 CI/CD/CT 기반의 자동화 파이프라인 체계 구축 필수

<details><summary>핵심 용어</summary>

- **DSML(Data Science and Machine Learning):** 정형·비정형 데이터 분석과 통계적 머신러닝/딥러닝 모델링을 결합하여 비즈니스 의사결정 및 자동화를 실현하는 프로젝트 체계
- **CRISP-DM:** 비즈니스 이해, 데이터 이해, 데이터 준비, 모델링, 평가, 배포의 6단계 반복 순환 구조를 가진 데이터 마이닝 표준 방법론
- **PoC(Proof of Concept):** 전면 도입 전 제한된 데이터셋과 환경에서 알고리즘의 비즈니스 타당성과 구현 가능성을 사전 검증하는 개념 실증 단계
- **피처 스토어(Feature Store):** 모델 학습과 실시간 추론 간 일관된 특성(Feature) 공유를 지원하고 데이터 누출(Data Leakage)을 방지하는 중앙 저장소
- **개념 드리프트(Concept Drift):** 시간 경과 및 외부 환경 변화에 따라 입력 변수와 예측 목표 변수 간의 통계적 상관관계가 변화하여 모델 성능이 저하되는 현상

</details>

## 2~4교시 25점 답안

## Ⅰ. DSML 프로젝트의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 비즈니스 가치 창출을 목표로 정형·비정형 데이터 분석, 가설 수립, 탐색적 데이터 분석(EDA), 머신러닝 모델링, MLOps 기반 지속적 운영을 유기적으로 결합한 엔지니어링 라이프사이클 |
| 목적 | 데이터 기반 의사결정 자동화, 고비용 수작업 프로세스 지능화, 비즈니스 ROI 입증 및 AI 기술 부채 최소화 |

## Ⅱ. DSML 프로젝트의 핵심 특징

| 특징 영역 | 주요 특성 | 상세 기술 및 관리 방안 |
|---|---|---|
| **가설 기반 반복성** | 비결정론적(Probabilistic) 실험 순환 | 고정된 요구사항 명세서 대신 가설 수립 및 실험(Experimentation) 반복을 통한 성능 수렴 |
| **데이터 종속성** | 데이터 품질에 따른 모델 성능 결정 | 코드 무결성뿐만 아니라 입력 데이터의 결측, 이상치, 클래스 불균형, 데이터 드리프트 상시 통제 |
| **다학제 협업** | 비즈니스·데이터·인프라 융합 조직 | 현업 도메인 전문가, 데이터 과학자(DS), 머신러닝 엔지니어(MLE), 데이터 엔지니어(DE) 간 공조 |
| **운영 복잡성** | 코드-데이터-모델 삼원 거버넌스 | 전통 소프트웨어의 소스 코드 버전 관리 외에 데이터셋 버전(DVC) 및 모델 가중치 계보 추적 일원화 |

## Ⅲ. DSML 프로젝트 단계별 프로세스 및 아키텍처

### 1. DSML 프로젝트 엔드투엔드 파이프라인
```text
+-----------------------------------------------------------------------------------+
|                     엔터프라이즈 DSML 프로젝트 라이프사이클                       |
+-----------------------------------------------------------------------------------+
|  [1단계: 비즈니스 이해 및 가설 정의]                                              |
|    - 정량적 비즈니스 KPI 설정 (고객 이탈률 5% 감소, 사기 거래 차단율 95% 등)     |
|    - 예측 시점 제약 조건 및 추론 레이턴시(SLA) 정의                               |
+-----------------------------------------------------------------------------------+
                               │
                               ▼
+-----------------------------------------------------------------------------------+
|  [2단계: 데이터 파이프라인 및 피처 엔지니어링]                                    |
|    - 데이터 수집/정제, 결측치 대체, 범주형 인코딩, 스케일링                       |
|    - 피처 스토어(Feature Store) 등록: 온라인(Low Latency) 및 오프라인(Batch) 동기화 |
+-----------------------------------------------------------------------------------+
                               │
                               ▼
+-----------------------------------------------------------------------------------+
|  [3단계: 모델링, 실험 추적 및 PoC 오프라인 평가]                                  |
|    - 복수 알고리즘 벤치마크 (LightGBM, XGBoost, Deep Neural Network)               |
|    - 실험 추적(MLflow): 파라미터, 하이퍼파라미터, 지표, 아티팩트 자동 로깅        |
|    - 독립 테스트 셋 블라인드 평가 및 도메인 전문가 피드백 검증                    |
+-----------------------------------------------------------------------------------+
                               │
                               ▼
+-----------------------------------------------------------------------------------+
|  [4단계: MLOps 프로덕션 배포 및 지속적 훈련(CT)]                                  |
|    - Canary / Shadow 배포, A/B 테스트를 통한 실무 트래픽 점진적 검증              |
|    - 데이터 드리프트(Data Drift) 및 개념 드리프트(Concept Drift) 모니터링          |
|    - 임계치 초과 시 재학습(Retraining) 트리거 및 Model Registry 갱신              |
+-----------------------------------------------------------------------------------+
```

         ▲                                           │
         │ (가설 미달 시 루프)                       ▼ (기준 충족 시)

## Ⅳ. 전통 SW 개발 프로젝트 대비 비교 및 CRISP-DM 방법론

### 1. 전통 SW 개발 프로젝트 vs DSML 프로젝트 비교
| 비교 항목 | 전통적 소프트웨어 개발 (Traditional SW) | DSML 프로젝트 (Data Science & ML) |
|---|---|---|
| **동작 결정성** | 결정론적(Deterministic: 동일 입력 시 동일 출력) | 비결정론적(Probabilistic: 확률적 추론 결과 산출) |
| **요구사항 확정** | 초기 요구분석 단계에서 기능 명세 동결 | 탐색적 분석(EDA) 및 실험 결과에 따른 동적 변경 |
| **핵심 자산** | 소스 코드 및 관계형 데이터베이스 스키마 | 데이터셋(버전), 피처 파이프라인, 모델 가중치 |
| **테스트 체계** | 단위 테스트, 통합 테스트, 시스템 테스트 | 오프라인 정밀도/재현율 평가, A/B 테스트, 드리프트 검출 |
| **유지보수 트리거** | 비즈니스 로직 변경 및 소프트웨어 버그 | 데이터 분포 변화(Data Drift) 및 성능 저하(Degradation) |

### 2. CRISP-DM 6대 단계별 핵심 활동
| 단계 | 명칭 | 주요 활동 및 산출물 |
|---|---|---|
| **1단계** | Business Understanding | 비즈니스 목표 설정, 데이터 과학 목표 변환, 프로젝트 계획서 |
| **2단계** | Data Understanding | 원천 데이터 수집, 데이터 속성 탐색, 결측치/이상치 파악 보고서 |
| **3단계** | Data Preparation | 데이터 정제, 피처 생성, 데이터셋 분할(Train/Val/Test) |
| **4단계** | Modeling | 모델링 기법 선정, 하이퍼파라미터 튜닝, 모델 앙상블 |
| **5단계** | Evaluation | 비즈니스 성공 기준 충족 여부 검토, 모델 성능 및 공정성 평가 |
| **6단계** | Deployment | 실시간 API/배치 서빙 구현, MLOps 파이프라인 구축, 운영 문서 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **PoC 성공 후 프로덕션 배포 실패(PoC 무덤 현상)**<br />실험실 주피터 노트북 환경과 실제 운영 엔터프라이즈 인프라 간의 기술 격차로 상용화 좌초 | 초기 단계부터 MLOps 플랫폼(Kubeflow, Vertex AI) 기반 컨테이너화 파이프라인 표준화 및 모듈화된 코드베이스 강제 |
| **학습-서빙 간 불일치(Training-Serving Skew) 및 데이터 누출**<br />학습 시점의 피처 추출 로직과 운영 서빙 시점의 로직 상이로 실전 추론 오류 발생 | 온라인-오프라인 통합 피처 스토어(Feast 등) 도입을 통한 단일 피처 연산 로직 강제 및 시계열 타임스탬프 기반 누출 차단 |
| **개념 드리프트로 인한 운영 중 모델 급격한 성능 저하**<br />시장 환경 및 고객 행동 패턴 변화로 인해 배포 초기 우수했던 모델의 예측 정확도 급락 | 실시간 Kolmogorov-Smirnov 검정 기반 드리프트 감시 대시보드 구축 및 자동 재학습·배포(Continuous Training) 트리거 가동 |

## Ⅵ. 제언

DSML 프로젝트의 성공적 안착을 위해서는 단순 모델 개발 중심에서 벗어나 비즈니스 가치 평가와 전주기 MLOps 거버넌스가 내재화된 운영 체계 확립 필수.

```text
[비즈니스 가치 평가 체계] ──> [DataOps (데이터 신선도 확보)] ──> [MLOps (지속적 학습/배포 CT)]
```

| 혁신 축 | 과거 DS 프로젝트 (사일로형) | 미래 엔터프라이즈 DSML (MLOps 통합형) |
|---|---|---|
| **수행 주체** | 연구원 단독 주피터 노트북 모델링 | 크로스펑셔널 팀(DS + MLE + Biz Analyst) 공조 |
| **코드 거버넌스** | 개인 PC 내 소스 및 데이터 보관 | GitOps, DVC, Model Registry 통합 형상 관리 |
| **배포 주기** | 연 1~2회 수동 배포 및 방치 | CI/CD 파이프라인 기반 주간/일간 자동 재학습 배포 |
