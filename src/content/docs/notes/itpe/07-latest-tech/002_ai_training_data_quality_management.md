## 큰 그림과 30초 인출

```text
[계획] → [획득] → [정제] → [가공·라벨링] → [검수·검증] → [활용·환류]
   │        │        │           │              │              │
 목적·기준  적법·대표성 형식·중복   정확·일관·완전   표본·모델검증   drift·오류환류

      원시데이터 → 원천데이터 → 라벨링데이터 → 학습/검증 dataset
```

- 본질: 파일 오류를 찾는 검수가 아니라 목표 AI의 사용 맥락에 맞는 데이터를 생명주기 전체에서 확보·측정·개선하는 체계
- 인출: `계-획-정-가-검-활`, 대상은 `원시-원천-라벨링`
- 품질: 적법성·대표성·다양성·정확성·완전성·일관성·유효성·추적성
- 검증: 규칙 기반 검사 + 표본검수 + 작업자 일치 + 모델 기반 활용성 평가

## 예상문제

> 인공지능 학습용 데이터의 특성과 생명주기, 품질관리 원칙·범위·활동을 설명하고 전통 데이터 품질관리와의 차이 및 실무 고려사항을 논하시오. (25점)

## Ⅰ. 모델의 일반화와 신뢰를 결정하는 AI 데이터 품질관리 개요

- 정의: **AI 학습용 데이터 품질관리**는 목표 AI의 학습·평가 목적에 적합하도록 데이터의 계획·획득·정제·가공·검증·활용 전 과정에서 품질 기준을 정하고 측정·개선·증명하는 활동
- 목적: 데이터 오류·편향·누수·권리 침해를 줄이고 모델의 일반화 성능과 안전·공정성·재현성 확보
- 필요성: 같은 데이터라도 사용 목적·모델·환경에 따라 적합성이 달라지며 라벨 오류나 분포 편향은 모델 출력에 확산

#### 한줄 요약

- AI 데이터 품질은 데이터 자체의 깨끗함과 목표 모델에서의 활용 적합성을 함께 판정함

## Ⅱ. 목적적합성·대표성·추적성을 요구하는 특성과 원칙

| 원칙 | 핵심 질문 | 대표 지표·증적 |
|---|---|---|
| **목적적합성** | 목표 task·population·환경을 반영하는가 | 요구사항-데이터 항목 추적표 |
| **적법·윤리성** | 수집·이용 권리와 개인정보 처리가 적정한가 | 동의·license·비식별 기록 |
| **대표·다양성** | 하위집단·edge case·환경 분포를 포함하는가 | class·attribute·scenario 분포 |
| **정확·일관성** | 값과 label이 실제 의미 및 가이드와 맞는가 | 오류율·작업자 간 일치도 |
| **완전·유효성** | 필수 항목·형식·범위가 충족되는가 | 결측·schema·range 검사 |
| **추적·재현성** | 원천·가공·version·분할을 재현 가능한가 | lineage·dataset version·hash |

#### 한줄 요약

- 품질 기준은 고정 목록이 아니라 AI 목적과 위해 가능성에서 역으로 도출해야 함

## Ⅲ. 원시·원천·라벨링 데이터와 관리체계 구조

```text
                    [품질관리 계획·기준]
                            │
          ┌─────────────────┼─────────────────┐
          ▼                 ▼                 ▼
     [원시데이터]       [원천데이터]      [라벨링데이터]
   수집 당시의 자료      정제·선별 완료     annotation 완료
   적법·대표·다양성      구문·유효·중복     의미·정확·일관
          └─────────────────┬─────────────────┘
                            ▼
             [자가점검 → 독립검증 → 활용성 평가]
                            ▼
                 품질 결과·재작업·승인 증적
```

| 관리요소 | 역할 | 대표 산출물 |
|---|---|---|
| **기준** | 품질 특성·지표·합격기준 정의 | 품질지표 기준서 |
| **조직** | 구축·검수·독립검증 역할 분리 | RACI·검수자 자격 |
| **절차** | 공정별 검사·부적합·재작업 통제 | 품질관리 계획/결과서 |
| **도구** | schema·중복·label·분포 자동 검사 | 검사 log·dashboard |
| **증적** | source부터 dataset까지 lineage 관리 | dataset card·version 이력 |

#### 한줄 요약

- 세 데이터 단계마다 품질 관점이 다르며 공통 기준·독립검증·lineage가 이를 하나의 체계로 묶음

## Ⅳ. 계획부터 활용 환류까지의 품질관리 절차

```text
① 목표·사용 맥락·위험에서 품질요구 도출
          ↓
② 수집원·권리·표본·분포 계획 수립
          ↓
③ 원시→원천 정제: schema·결측·중복·오염 검사
          ↓
④ labeling: 가이드·교육·gold sample·교차검수
          ↓
⑤ 표본/전수·독립 품질검증, 부적합 재작업
          ↓
⑥ train/validation/test 분리와 모델 활용성 평가
          ↓
⑦ 운영 오류·drift를 수집·기준·dataset에 환류
```

| 단계 | 실패 방지점 | 판정 방법 |
|---|---|---|
| **계획** | 목적과 무관한 대량 수집 | 요구사항·scenario coverage 검토 |
| **획득** | 편향·권리 불명확 | sampling·license·privacy 검증 |
| **정제** | 중복·누수·형식 오류 | duplicate·schema·split leakage 검사 |
| **가공** | 모호한 label·작업자 편차 | guideline·golden set·IAA |
| **검증** | 평균 품질만 보고 소수집단 누락 | 계층표본·subgroup·edge-case 검증 |
| **활용** | offline 품질과 운영환경 괴리 | benchmark·error slice·drift 분석 |

#### 한줄 요약

- 품질검증은 구축 종료 시 한 번 수행하는 행사가 아니라 공정별 부적합을 조기에 되돌리는 반복 절차임

## Ⅴ. 무결성 중심과 모델 적합성을 구분하는 비교

| 구분 | 전통 정형 데이터 품질 | AI 학습용 데이터 품질 |
|---|---|---|
| **주요 대상** | table·column·record | 비정형 원천·annotation·dataset split |
| **핵심 품질** | 정확·완전·일관·유일·유효 | 대표·다양·label 정확·공정·활용 적합 |
| **판정 근거** | schema·domain·업무규칙 | 사용 맥락·label guide·통계 분포·모델 오류 |
| **검증 방식** | profiling·rule·constraint | 자동검사+사람검수+모델 기반 slice 평가 |
| **변화 관리** | 원천 시스템 값·schema 변경 | 환경·population·label policy·model 변화 |
| **공통 기반** | 표준·책임·lineage·지속개선 | 표준·책임·lineage·지속개선 |

#### 한줄 요약

- 전통 품질이 값의 업무규칙 적합성을 묻는다면 AI 품질은 그 데이터로 목표 상황을 학습·평가할 수 있는지까지 묻음

## Ⅵ. 편향·오라벨·누수·운영괴리를 막는 실무 고려사항

| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| **하위집단 성능 저하** | 수집 분포가 실제 population과 불일치 | subgroup·scenario별 coverage 기준과 계층표본 검증 | 평균 성능 착시 방지 |
| **라벨 불일치** | 모호한 ontology·guide·작업자 교육 | golden set·교차검수·낮은 일치 항목 전문가 재판정 | 의미 정확성 향상 |
| **평가 누수** | 동일 객체·시간·사용자의 중복이 split 사이에 존재 | group/time 기준 split·near-duplicate 검사 | 일반화 성능 과대평가 방지 |
| **합성데이터 왜곡** | 생성모델 오류·privacy leakage·mode collapse | 실데이터 분포 비교·privacy attack·downstream 평가 | 보완 데이터의 적합성 확인 |
| **운영 drift** | 실제 입력·정책·환경이 구축 시점과 변화 | error sample 수집·drift 경보·dataset version 재구축 | 품질 기준 지속 갱신 |

#### 한줄 요약

- 데이터 건수보다 분포·label 의미·split 독립성·운영 오류 환류가 모델 신뢰성을 좌우함

## Ⅶ. 데이터-모델-서비스 추적성으로 완성하는 결론

- **[Data-Centric 품질 폐루프]**: 정적 검사 통과만으로 모델 적합성을 보장할 수 없으므로 dataset version과 모델·평가 slice·운영사고를 연결하여 원인 데이터까지 역추적
- 나라면: `요구사항 → 수집원 → 가공 이력 → 품질지표 → split → 모델 평가 → 운영 오류` lineage를 기준선으로 관리하고, 오류 slice가 임계치를 넘으면 해당 데이터 구간을 우선 재수집·재라벨링

#### 한줄 요약

- AI 데이터 품질의 완성 기준은 납품 검수 통과가 아니라 운영 오류가 데이터 개선으로 환류되는 추적 가능한 상태임

## 1교시 10점 답안 발췌

### 1. 정의

- AI 학습용 데이터 품질관리는 목표 AI의 학습·평가 목적에 적합하도록 데이터 생명주기 전반의 기준을 정의하고 측정·개선·증명하는 활동

### 2. 구조와 절차

```text
원시 → 정제 → 원천 → 가공 → 라벨링 → 검증 → 활용·환류
```

| 대상 | 핵심 품질 |
|---|---|
| 원시 | 적법성·대표성·다양성 |
| 원천 | 구문·유효성·중복·완전성 |
| 라벨링 | 의미 정확성·일관성·완전성 |

### 3. 차별화 제언

- 규칙검사·표본검수·IAA·모델 기반 slice 평가를 결합
- 요구사항부터 운영 오류까지 lineage를 연결하여 drift·오류를 재수집·재라벨링에 환류
