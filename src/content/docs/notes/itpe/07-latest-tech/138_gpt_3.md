## 연관 키워드

- GPT-3(Generative Pre-trained Transformer 3), 자기회귀 언어 모델(Autoregressive Language Model), 트랜스포머 디코더(Transformer Decoder)
- 인컨텍스트 러닝(In-context Learning), 퓨샷(Few-shot), 스케일링 법칙(Scaling Law)
- 환각(Hallucination), RLHF(Reinforcement Learning from Human Feedback), DPO(Direct Preference Optimization), RAG(Retrieval-Augmented Generation)

## Ⅰ. GPT-3의 개요

- 핵심 요약 : 1,750억 매개변수 규모의 디코더 기반 자기회귀 언어 모델로, 자연어 프롬프트만으로 여러 언어 과업을 수행하는 범용 생성 모델.
- 개념 : **GPT-3** (Generative Pre-trained Transformer 3, 1,750억 개의 매개변수를 가진 트랜스포머 디코더 기반 언어 모델)는 약 3,000억 토큰 규모의 텍스트로 사전 학습되어, 번역, 요약, 질의응답 같은 과업을 프롬프트 입력만으로 수행함.
- 배경 및 필요성 : 다음 토큰 예측은 그럴듯한 문장을 만들지만 사실 여부를 보장하지 않아 **환각** (Hallucination, 사실과 다른 내용을 그럴듯하게 생성하는 현상)이 생김. 또 사용자 의도와 어긋나는 응답이 많아, 외부 문서를 붙이는 **검색 증강 생성** (RAG, Retrieval-Augmented Generation)과 **인간 피드백 기반 강화학습** (RLHF, Reinforcement Learning from Human Feedback) 같은 정렬 기법이 함께 필요함.
- 주요 목적 : 과업별 파인튜닝 의존을 줄이고, 자연어 프롬프트 하나로 여러 작업을 처리하는 범용 인터페이스를 제공하는 것.

## Ⅱ. GPT-3의 특징 및 장점

- 핵심 요약 : 규모 확장, 인컨텍스트 러닝, 단일 텍스트 인터페이스가 결합되어 작업별 재학습 없이 여러 과업을 수행하는 것이 장점.

1. **인컨텍스트 러닝** (In-context Learning, 가중치를 바꾸지 않고 프롬프트 안의 예시만으로 과업을 수행하는 능력) : 예시를 프롬프트에 넣음 → 과업별 재학습 없이 새 작업에 즉시 적응.
2. **스케일링 법칙** (Scaling Law, 모델 크기, 데이터, 연산량이 늘수록 손실이 거듭제곱 형태로 줄어드는 경향) : 1,750억 매개변수 모델에서 이 경향을 실증 → 규모 확대가 성능 향상으로 이어진다는 근거 제시.
3. 단일 텍스트 인터페이스 : 분류, 개체명 인식, 대화를 텍스트 입력과 텍스트 출력 형식으로 통합 → 시스템 연동 방식 단순화.
4. 창발적 능력 : 명시적으로 학습하지 않은 3자리 덧셈 같은 연산을 일부 수행하는 사례가 보고됨 → 범용 활용 가능성 확대.

## Ⅲ. GPT-3의 구조 (흐름)

- 핵심 요약 : 토큰화와 임베딩을 거친 입력이 96개 디코더 층을 지나며, 다음 토큰을 하나씩 생성하는 자기회귀 흐름.
- 토큰화 : **BPE** (Byte-Pair Encoding, 자주 나오는 문자 쌍을 병합해 어휘를 만드는 토큰화 방식)를 사용하며, 어휘는 50,257개임.
- 디코더 층 : 96개 층이 **마스크드 자기 어텐션** (Masked Self-Attention, 미래 토큰을 가려 왼쪽 문맥만 참조하는 어텐션)과 피드포워드 네트워크를 반복함. 문맥 창은 2,048 토큰임.
- 샘플링 : 출력 확률 분포에서 온도(Temperature)와 Top-p 값으로 다음 토큰을 고름.

```text
[프롬프트 (지시문 + 예시 + 질의)]
        ↓
[BPE 토큰화 (어휘 50,257개)]
        ↓
[토큰 임베딩 + 위치 인코딩]
        ↓
[디코더 층 96개 반복]
  마스크드 자기 어텐션 → 정규화 → 피드포워드
        ↓
[다음 토큰 확률 분포 산출]
        ↓ 샘플링 후 다시 입력 (자기회귀)
[답변 완성]
```

```text
[지시문] 영어를 한국어로 번역하라
[예시 1] 입력 → 출력
[예시 2] 입력 → 출력
[질의] 입력 → 모델이 이어서 생성
```

## Ⅳ. GPT-3의 프롬프팅 방식 비교

- 핵심 요약 : 예시가 없을수록 토큰 비용은 낮지만 정확도는 떨어지고, 예시가 많을수록 정확도는 오르나 문맥 창과 비용을 소모함.
- 비교 대상 : 예시 없이 지시문만 주는 **제로샷** (Zero-shot), 예시 1개를 주는 **원샷** (One-shot), 예시를 여러 개 주는 **퓨샷** (Few-shot).

| 프롬프팅 방식 | 입력 구성 | 장점 | 한계 |
| --- | --- | --- | --- |
| 제로샷 | 지시문과 입력값만 제공 | 토큰 비용이 가장 적음 | 서식 요구나 복잡한 추론에서 정확도 저하 |
| 원샷 | 지시문과 입출력 예시 1개 | 과업 형식을 최소한으로 전달 | 도메인 특화 과업에서 정확도 부족 |
| 퓨샷 | 지시문과 입출력 예시 여러 개 | 재학습 없이 높은 성능 기대 | 문맥 창(2,048 토큰) 소모와 비용 증가 |

- 선택 기준 : 예시 작성 비용과 토큰 예산 대비 정확도 이득을 비교해 방식을 고르고, 응답 형식이 엄격하면 퓨샷부터 검토함.

## Ⅴ. GPT-3의 한계와 방안

- 핵심 요약 : 환각, 지시 불이행, 프롬프트 주입 취약점을 검색 결합, 정렬 학습, 가드레일로 통제해야 함.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 환각 | 다음 토큰 예측 특성상 통계적으로 그럴듯한 거짓 문장을 사실처럼 생성 | RAG로 외부 신뢰 소스 연계, 출처 인용 강제, 자기 일관성(Self-Consistency) 검증 | 근거 없는 응답 비율 |
| 지시 불이행 (정렬 문제) | 다음 토큰 예측 목표 때문에 지시를 따르기보다 문장을 이어 씀 | 지시 튜닝, RLHF, 직접 선호 최적화(DPO, Direct Preference Optimization)로 동작 개선 | 지시 준수율, 선호도 평가 |
| 프롬프트 주입과 보안 취약점 | 탈옥(Jailbreak) 프롬프트로 금지 응답이나 데이터 유출을 유도 | 입력 필터링, 시스템 지시와 사용자 입력의 분리, NeMo Guardrails 같은 가드레일 | 공격 차단율, 가드레일 우회 사례 |

- 구분 : InstructGPT 계열이 적용한 학습 절차는 RLHF이며, DPO는 이후 제안된 별도의 선호 최적화 기법이므로 둘을 같은 과정으로 묶지 않음.

## Ⅵ. GPT-3에 대한 기술사적 제언

- 핵심 요약 : 모델 구조, 추론 방식, 정렬 체계를 함께 발전시키되, 안전 기준을 측정 가능한 상태로 유지하는 것이 핵심.

1. 단일 밀집 모델에 의존하기보다, 멀티모달 입력을 처리하고 **혼합 전문가** (MoE, Mixture of Experts, 입력마다 일부 전문가 네트워크만 활성화하는 구조)를 결합하는 구조를 검토할 필요가 있다.
2. 추론 단계에서는 **사고의 연쇄** (CoT, Chain of Thought, 중간 추론 과정을 단계적으로 드러내는 프롬프팅 방식)와 외부 도구 호출을 결합해 복잡한 과업의 정확도를 높이는 방향이 바람직하다.
3. 정렬 학습의 효과는 사람이 평가하는 절차와 자동 평가를 함께 운영해 확인해야 하며, 모델을 교체할 때마다 안전 기준이 유지되는지 점검하는 체계를 갖춰야 한다.

## Ⅶ. 결론

- 핵심 요약 : GPT-3는 규모와 프롬프트 인터페이스로 범용 언어 과업의 가능성을 연 모델이지만, 환각과 정렬 한계를 함께 가진 기반 기술임.
- 시사점 : 이후 응용의 신뢰도는 모델 자체보다 검색 결합, 정렬, 가드레일을 어떻게 설계했는지에 따라 달라짐.
