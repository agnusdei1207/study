- FIPA-ACL, 조직 구조(계층형·연합형·시장형·P2P), 교착 상태, 라이브락, 워치독

## Ⅰ. 멀티에이전트 시스템(Multi-Agent System)의 개요

- 핵심 요약 : 자율적인 에이전트들이 협력, 조정, 경쟁, 협상을 통해 공동 목표를 달성하는 분산 인공지능 구조.
- 개념 : 자율성, 사회적 능력, 반응성, 능동성을 가진 여러 **지능형 에이전트** (Intelligent Agent)가 환경 안에서 상호작용하며, 분산된 지식과 기능으로 목표를 달성하는 **분산 인공지능** (DAI, Distributed Artificial Intelligence) 아키텍처.
- 배경 및 필요성 : 단일 거대 AI 시스템은 연산 복잡도, 단일 실패점(SPOF, Single Point of Failure), 모델 규모의 한계를 가지므로, 기능별로 모듈화한 에이전트의 병렬 협업이 요구됨.
- 주요 목적 : 복잡계 문제의 분산 해결, 결함 허용성(Fault Tolerance) 확보, 전문화된 하위 작업의 분업을 통한 효율 향상.

## Ⅱ. 멀티에이전트 시스템(Multi-Agent System)의 특징 및 장점

- 핵심 요약 : 개별 에이전트의 자율 판단과 표준 메시지 교환이 결합해 모듈화, 병렬성, 강건성을 함께 얻는 구조.

1. **BDI 아키텍처** (Belief-Desire-Intention, 신념·소망·의도 기반 판단 구조) : 환경에 대한 신념과 달성 목표로 실행 계획을 스스로 선택 → 상황 변화에 맞춘 자율 대응.
2. **계약망 프로토콜** (Contract Net Protocol, 과업 공고와 입찰로 작업을 배분하는 방식) : 적격 에이전트 간 경쟁 입찰로 최적 담당자 선정 → 작업 배분의 공정성과 효율 확보.
3. 전문화와 병렬 처리 : 설계, 코딩, 검증 에이전트가 동시에 움직임 → 전체 처리 시간 단축.
4. 결함 허용성 : 일부 에이전트가 실패해도 다른 에이전트가 역할을 넘겨받음 → 단일 장애로 인한 전체 중단 위험 축소.

## Ⅲ. 멀티에이전트 시스템(Multi-Agent System)의 구조 (흐름)

- 핵심 요약 : 매니저가 과업을 공고하고 에이전트가 입찰해 계약을 맺은 뒤, 공유 환경에서 결과를 합치는 흐름.

```text
[ 계약망 기반 작업 배분 ]

매니저 에이전트 (복합 목표 수신)
          ↓ 과업 공고
에이전트 A, B, C 입찰 제출
          ↓ 최적 입찰 선정
계약 체결 (Award)
          ↓
공유 환경 (블랙보드)에 결과 기록
          ↓
합의 또는 중재 후 결과 통합
```

- **블랙보드 시스템** (Blackboard System, 공유 공간에 부분 해결책을 기록하고 다른 에이전트가 이를 발전시키는 방식) : 직접 통신 없이 간접적으로 협업.
- **FIPA-ACL** (Agent Communication Language, 에이전트 발화 행위 기반 통신 언어) : 요청, 통보, 제안, 거절 등 의도를 구조화해 메시지 교환.

## Ⅳ. 멀티에이전트 시스템(Multi-Agent System)의 비교

- 핵심 요약 : 계층형은 책임이 명확하고, 연합형은 자율성이, 시장형은 자원 배분 효율이, P2P형은 강건성이 강점인 구조.

| 조직 구조 | 권한과 조정 | 장점 | 단점·병목 | 적용 분야 |
| --- | --- | --- | --- | --- |
| 계층형 (Hierarchical) | 상위 에이전트가 하위를 통제 | 책임 소재 명확, 충돌 해결 단순 | 상위 노드 병목, 유연성 부족 | 기업 업무 흐름, 지휘 체계 |
| 연합형 (Federation) | 중개 에이전트가 메시지를 라우팅 | 개별 자율성 보장, 확장 용이 | 중개자 장애 시 통신 마비 | 물류 연합망, 분산 전력망 |
| 시장형 (Market-based) | 경매와 입찰로 자원 배분 | 전역적 자원 배분, 동적 적응 | 통신 부담, 담합 등 교란 | 클라우드 자원 스케줄링 |
| 완전 분산형 (P2P Mesh) | 동등한 권한의 로컬 상호작용 | 단일 실패점 제거, 높은 내결함성 | 전역 합의 지연, 교착 위험 | 로봇 군집, 분산 원장 |

```text
[ 조직 구조별 통신 경로 ]

계층형: 상위 → 하위 명령 (단방향 통제)
        A
      ↙   ↘
    B       C

P2P형: 모든 노드가 직접 연결 (수평 협상)
    A ⇄ B
    ⇅   ⇅
    C ⇄ D
```

- 최근 LLM 기반 멀티에이전트(예: CrewAI, MetaGPT)는 계층형과 연합형을 혼합하는 형태가 주로 쓰임.

## Ⅴ. 멀티에이전트 시스템(Multi-Agent System)의 한계와 방안

- 핵심 요약 : 메시지 폭증, 부분 관측, 교착 상태를 브로커, 메커니즘 설계, 감시 에이전트로 해결.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 통신 메시지 폭증 | 에이전트 수가 늘면 대화 경로가 급증해 대역폭 고갈 | 발행-구독 방식의 메시지 브로커(Pub-Sub, 예: Kafka), 토픽 필터링, 메시지 빈도 제한 | 메시지 지연, 큐 적체량 |
| 부분 관측성에 따른 비효율 | 각자 지역 이익만 좇아 전체 최적에 도달하지 못함 | 메커니즘 디자인 설계, **CTDE** (Centralized Training with Decentralized Execution, 중앙 학습·분산 실행) 기반 MAPPO (Multi-Agent Proximal Policy Optimization) 학습 | 전역 목표 달성률 |
| 교착 상태와 라이브락 | 에이전트끼리 서로의 응답을 기다리며 시스템이 멈춤 | 타임아웃, 분산 락 회피 알고리즘, 전역 **워치독** (Watchdog, 정체를 감시하는 에이전트) 배치 | 대기 시간 분포, 정체 감지 건수 |

## Ⅵ. 멀티에이전트 시스템(Multi-Agent System)에 대한 기술사적 제언

- 핵심 요약 : 역할 규격화, 통합 추적, 승인 게이트를 설계의 기본 원칙으로 제시.

1. 역할 규격화 : 기획, 개발, 검토 에이전트의 책임 범위와 완료 조건을 시스템 프롬프트로 명시해, 에이전트 간 역할 중복과 누락을 줄임.
2. 통합 추적 체계 : 에이전트가 주고받은 메시지와 상태 전이를 하나의 세션으로 묶는 OpenTelemetry 기반 추적을 기본 설계에 포함함.
3. 고위험 행동의 승인 게이트 : 핵심 자원 변경이나 되돌릴 수 없는 실행 전에는 사람의 승인을 받도록 하는 HITL (Human in the Loop, 사람 개입) 게이트를 둠.

## Ⅶ. 결론

- 핵심 요약 : 멀티에이전트 시스템은 자율 에이전트의 분업과 협상을 표준 메시지 위에서 조율하는 분산 구조.
- 시사점 : 에이전트의 수보다 조직 구조, 종료 조건, 추적 체계의 설계가 시스템 안정성을 결정함.
