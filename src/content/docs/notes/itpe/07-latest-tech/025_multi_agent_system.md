## 답안 골격
```text
[멀티에이전트 시스템] ◀━━ 머리: Ⅶ 내 의견 (LangGraph 기반 상태 머신 제어와 역할별 최소 권한 분립 아키텍처)
 ┃
 ┣━ Ⅰ 개요 ───── 단일 LLM의 컨텍스트 윈도우 한계와 인지 과부하 → 전문화된 다중 에이전트의 역할 분업화
 ┣━ Ⅱ 특징 ───── 자율성(Autonomy) · 사회적 상호작용(협력/경쟁/협상) · 분산 문제 해결(DPS) · 창발성
 ┣━ Ⅲ 구조 ───── 에이전트 계층(기획/실행/비평) + 통신 채널(블랙보드/P2P) + 공유 메모리 + 툴킷(Tool)
 ┣━ Ⅳ 흐름 ───── ① 목표 수립(Planner) → ② 하위 작업 분할 → ③ 전문 에이전트 실행(Worker) → ④ 상호 검증(Critic)
 ┣━ Ⅴ 비교 ───── 단일 에이전트(Single Agent) vs 멀티에이전트(Multi-Agent, 계층형 vs 분산형)
 ┗━ Ⅵ 실무 ───── 에이전트 간 환각 증폭(Cascading Hallucination) / 무한 루프 / 토큰 소모량 급증
```
- 필수 키워드: 분산 인공지능(DAI) · 역할 분업(Planner/Worker/Critic) · 오케스트레이션 · LangGraph · 환각 증폭 · 블랙보드 패턴
- 기출: 139회 3교시 1번 `기업의 업무구조를 바꾸는 다중 에이전트 시스템(MAS)` → Ⅰ~Ⅵ 전반

## 한 줄 본질
- 하나의 모델에 모든 도메인 지식과 도구를 욱여넣는 모놀리식 AI 한계 → 기획자, 개발자, 검수자 등 전문 역할을 부여받은 다수 에이전트가 협업 프로토콜로 문제를 분할 해결 → 복합 워크플로우 수행 / 에이전트 간 의견 충돌 및 연쇄 오류 전파 위험

## 핵심 그림
```text
[계층형 멀티에이전트 시스템 (Hierarchical MAS) 구조]
                   +------------------------+
                   |  관리자/기획 에이전트   |
                   |  (Manager / Planner)   |
                   +------------------------+
                     /          |          \  작업 할당 (Task Dispatch)
                    v           v           v
          +-----------+   +-----------+   +-----------+
          | 리서치    |   | 코드 생성 |   | 데이터분석|
          | Worker    |   | Worker    |   | Worker    |
          +-----------+   +-----------+   +-----------+
                    \           |           /  결과 반환
                     v          v          v
                   +------------------------+
                   |   검증/비평 에이전트    | ===> 통과 시 사용자 보고
                   |   (Critic / Reviewer)  |      반려 시 Worker 재작업
                   +------------------------+
```

## 핵심 용어
- 분산 문제 해결(DPS, Distributed Problem Solving): 하나의 복잡한 전체 목표를 독립적인 여러 개의 하위 태스크로 나누어 여러 에이전트가 병렬 협력 처리하는 방식
- 비평가(Critic) 에이전트: 작업자(Worker) 에이전트가 생성한 결과물의 논리적 결함, 보안 취약점, 환각 여부를 독립적인 시각에서 반조(Reflection) 검증하는 에이전트
- 블랙보드 패턴(Blackboard Pattern): 에이전트들이 공용 공유 메모리(Blackboard) 공간에 중간 계산 결과와 상태를 기록하고 상호 참조하는 통신 아키텍처

## 핵심 통찰
- 단일 에이전트에 프롬프트를 길게 주는 것보다, "너는 프로그래머다", "너는 코드 리뷰어다"로 쪼개어 서로 대화(Debate)시키는 것이 최종 결과물 품질을 비약적으로 향상
- 에이전트가 자유롭게 대화하도록 방치하면 쓸데없는 인사말과 무한 동조 루프에 빠져 토큰이 급격히 소진됨 → 유향 비순환 그래프(DAG) 기반 상태 제어 필수
- 조직의 실제 업무 구조(R&R)를 소프트웨어 에이전트 토폴로지에 그대로 매핑하는 기업 업무 프로세스 자동화(Agentic Process Automation)로 진화 중

## 이웃 토픽과 구분
- 멀티에이전트 vs 단일 에이전트: 단일 에이전트는 하나의 컨텍스트 안에서 혼자 생각하고 행동(ReAct) / 멀티에이전트는 독립된 컨텍스트와 도구를 가진 다수 객체가 협업·토론·상호 감시

## 문제·원인·대책
- 적용 상황: 소프트웨어 자동 개발 멀티에이전트 시스템에서 에이전트 간 무한 수정 루프 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 코더와 리뷰어의 무한 핑퐁 대화 | 완료 조건(Stopping Criteria) 부재 및 모호한 검수 기준 | 최대 턴 수(Max Turns) 제한 및 통과 임계 점수(Score > 85) 강제 | 불필요한 토큰 낭비 방지 및 프로세스 완결 보장 |
| 한 에이전트의 오답이 전체 결론 오염 | 초기 기획 에이전트의 잘못된 가정이 하위 에이전트로 연쇄 전파 | 교차 검증(Cross-Verification) 및 다수결 투표(Majority Voting) 도입 | 환각 연쇄 전파(Cascading Hallucination) 조기 차단 |
| 에이전트 간 동시 파일 쓰기 충돌 | 비동기 병렬 실행 시 공유 자원 동시 접근 | 중앙 상태 머신(LangGraph State) 기반의 순차적 상태 전이 제어 | 상태 경합(Race Condition) 방지 및 일관성 확보 |
