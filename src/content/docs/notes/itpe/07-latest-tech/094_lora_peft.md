## 30초 인출

- 본질: **LoRA / PEFT** 는 수십~수천억 파라미터 기반 거대 언어모델(LLM)의 사전학습 가중치를 동결하고 극소수 저순위(Low-Rank) 매개변수만 추가 학습하여 특정 도메인 과업에 적응시키는 고효율 미세조정 기술
- 메커니즘: 거대 가중치 행렬의 갱신량 $\Delta W$를 두 개의 저랭크 행렬곱 $B \times A$ ($r \ll d$)로 분해하고 스케일링 계수 $\alpha/r$을 곱하여 기존 고정 가중치와 합산 추론
- 통찰: 과업별 어댑터 파편화로 인한 서빙 VRAM 낭비 및 추론 지연이 발생하므로 단일 베이스 모델 위에서 요청별 어댑터를 실시간 교체하는 S-LoRA 멀티 테넌트 서빙 체계 구축 필수

<details><summary>핵심 용어</summary>

- **PEFT (Parameter-Efficient Fine-Tuning)** : 기본 모델의 99% 이상 가중치를 고정하고 1% 미만의 파라미터만 학습하는 경량 적응 기술군.
- **LoRA (Low-Rank Adaptation)** : 모델의 내재적 차원(Intrinsic Dimension)이 작다는 원리를 이용해 가중치 갱신량을 저순위 분해 행렬로 학습하는 기법.
- **QLoRA (Quantized LoRA)** : 베이스 모델을 4-bit NormalFloat(NF4)로 양자화하고 이중 양자화 및 페이지드 옵티마이저를 결합한 극초경량 학습 기법.
- **내재적 랭크 (Rank, $r$)** : 저순위 행렬의 압축 차원으로 모델의 학습 용량과 연산 비용 간의 트레이드오프를 결정하는 핵심 하이퍼파라미터.
- **어댑터 병합 (Weight Merging)** : 서빙 시 학습된 저랭크 행렬곱($\Delta W$)을 기존 베이스 가중치($W_0$)에 직접 영구 가산하여 추론 레이턴시 증가를 0으로 만드는 기법.

</details>

## 2~4교시 25점 답안

## Ⅰ. LoRA / PEFT의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **LoRA (Low-Rank Adaptation)** 는 사전학습된 거대 신경망의 원본 가중치를 완전 동결하고 가중치 변화량($\Delta W$)만을 랭크 $r$의 저순위 분해 행렬($B \times A$)로 우회 학습하는 파라미터 효율적 미세조정(PEFT) 기술 |
| 목적 | 수십 GB 이상의 옵티마이저 메모리(Adam State) 오버헤드 절감 및 단일 GPU 기반 엔터프라이즈 LLM 맞춤화 실현 |

## Ⅱ. LoRA의 수학적 원리 및 파라미터 특성

| 수학적 원리 및 파라미터 | 수식 표현 및 동작 메커니즘 | 기술적 특징 및 공학적 의미 |
|---|---|---|
| **저순위 행렬 분해** | $h = W_0 x + \Delta W x = W_0 x + \frac{\alpha}{r} B A x$ | $d \times k$ 크기의 $\Delta W$를 $B(d \times r)$와 $A(r \times k)$로 분해 ($r \ll \min(d, k)$) |
| **가중치 초기화 규칙** | $A \sim \mathcal{N}(0, \sigma^2)$, $B = 0$ | 학습 시작 시점에 $\Delta W = 0$을 보장하여 초기 출력이 사전학습 모델과 100% 동일하게 출발 |
| **스케일링 계수 ($\alpha$)** | Scaling Factor $= \frac{\alpha}{r}$ | 랭크 $r$ 변경 시에도 학습률(Learning Rate)을 재조정하지 않도록 하이퍼파라미터 안정화 |
| **추론 시 무손실 병합** | $W_{serving} = W_0 + \frac{\alpha}{r} BA$ | 배포 시 두 행렬곱을 베이스 가중치에 덧셈 병합하여 추가적인 추론 레이턴시(No Latency Overhead) 배제 |

## Ⅲ. LoRA 및 QLoRA 학습 아키텍처

```text
┌────────────────────────────────────────────────────────────────────────┐
│             LoRA 및 QLoRA 신경망 순전파(Forward) 아키텍처              │
└────────────────────────────────────────────────────────────────────────┘
                    [ 입력 텐서 (Input Token Vector: x) ]
                                    │
                  ┌─────────────────┴─────────────────┐
                  ▼                                   ▼
   ┌─────────────────────────────┐     ┌─────────────────────────────┐
   │ 동결된 원본 가중치 (Frozen)  │     │ 저순위 다운프로젝션 행렬 A  │
   │ W_0 ∈ R^(d × k)             │     │ A ∈ R^(r × k)               │
   │ [QLoRA 시: 4-bit NF4 양자화]│     │ (가우시안 랜덤 초기화)      │
   └──────────────┬──────────────┘     └──────────────┬──────────────┘
                  │                                   │ (r 차원 축소 텐서)
                  │                                   ▼
                  │                    ┌─────────────────────────────┐
                  │                    │ 저순위 업프로젝션 행렬 B    │
                  │                    │ B ∈ R^(d × r)               │
                  │                    │ (0으로 초기화)              │
                  │                    └──────────────┬──────────────┘
                  │                                   │
                  │                                   ▼
                  │                    ┌─────────────────────────────┐
                  │                    │ 스케일링 계수 적용 (α / r)  │
                  │                    └──────────────┬──────────────┘
                  │                                   │
                  └─────────────────┬─────────────────┘
                                    ▼ (Vector Addition)
                     [ 출력 텐서 h = W_0 x + (α/r)BAx ]
```

| QLoRA 3대 혁신 기술 | 기술 상세 메커니즘 | 메모리 절감 효과 |
|---|---|---|
| **4-bit NormalFloat (NF4)** | 정규분포를 따르는 신경망 가중치 특성에 정보이론적으로 최적화된 비균등 양자화 | 16-bit FP 대비 가중치 메모리 75% 절감 |
| **이중 양자화 (Double Quant)** | 양자화 상수를 8-bit로 재양자화하여 파라미터당 0.37비트 추가 절감 | 65B 모델 기준 3GB 추가 VRAM 확보 |
| **페이지드 옵티마이저 (Paged Ops)** | CUDA 통합 메모리를 활용해 VRAM 급증 시 옵티마이저 상태를 CPU RAM으로 스왑 | OOM(Out of Memory) 크래시 원천 방지 |

## Ⅳ. PEFT 기법 유형 비교

| 비교 항목 | Full Fine-Tuning | Adapter Tuning | Prefix / Prompt Tuning | LoRA / QLoRA (본 토픽) |
|---|---|---|---|---|
| **학습 파라미터 비율** | 100% (전체 가중치) | 1~3% (계층 사이 삽입) | 0.01~0.1% (가상 토큰) | 0.05~0.5% (저순위 행렬) |
| **VRAM 메모리 부담** | 극도로 높음 (80GB x 8) | 중간 (단일 GPU 가능) | 낮음 | 매우 낮음 (24GB 단일 GPU) |
| **추론 지연 (Latency)** | 지연 없음 (원본 유지) | 순차 연산 추가로 지연 발생 | 입력 시퀀스 길이 단축 유발 | 가중치 병합으로 지연 전무 |
| **모델 서빙 유연성** | 과업별 전체 모델 복제 | 어댑터 분리 서빙 | 프롬프트 벡터 분리 | 단일 베이스 + 다중 LoRA 스왑 |
| **파인튜닝 표현력** | 최상 | 우수 | 다소 낮음 (복잡 과업 한계) | Full FT 대비 99% 이상 성능 달성 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 수십 개의 LoRA 어댑터를 동시 서빙할 때 매번 베이스 가중치에 병합/해제하는 과정에서 발생하는 지연과 메모리 단편화 | S-LoRA 및 Punica 기반 배치 추론 엔진을 도입하여 비병합 상태의 어댑터를 동일 GPU 텐서 코어에서 동적 멀티플렉싱 |
| 베이스 모델과 과업 복잡도에 최적화된 랭크 $r$과 스케일 $\alpha$ 탐색을 위한 반복 실험 비용 | 학습 중 유효 특이값을 자동 측정하여 계층별 최적 랭크를 동적으로 할당하는 AdaLoRA 알고리즘 적용 |
| QLoRA의 4-bit 양자화 오차로 인해 복잡한 코드 생성 및 정밀 수치 추론 태스크에서 성능 하락 발생 | 다운프로젝션과 업프로젝션 잔차를 16-bit로 보정하는 QDyLoRA 기법 및 핵심 계층(Attention Projections) 선택적 적용 |

## Ⅵ. 제언

단일 파운데이션 모델 인프라에서 수십 개의 기업 맞춤형 태스크를 실시간 처리하기 위해 S-LoRA 동적 어댑터 페이징 서빙 아키텍처 구축 권고.

```text
[ 사용자 API 요청: 태스크 식별자 태깅 (Task A, Task B, Task C) ]
                             │
                             ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ vLLM / S-LoRA 서빙 런타임                                             │
 │                                                                      │
 │  [ 동결된 단일 Llama-3-70B 베이스 모델 (Unified Base Weights) ]      │
 │                                                                      │
 │  ┌────────────────────────────────────────────────────────────────┐  │
 │  │ GPU Unified Paged Memory Pool                                  │  │
 │  │  ├─ Task A LoRA (금융 상담) ──> [ 배치 1 연산 통과 ]            │  │
 │  │  ├─ Task B LoRA (법률 요약) ──> [ 배치 2 연산 통과 ]            │  │
 │  │  └─ Task C LoRA (코딩 보조) ──> [ CPU RAM에서 필요 시 즉시 페이징 ]│
 │  └────────────────────────────────────────────────────────────────┘  │
 └──────────────────────────────────┬───────────────────────────────────┘
                                    │
                                    ▼
                      [ 지연 없는 실시간 응답 반환 ]
```

| 비교 항목 | 기존 모델별 개별 인스턴스 배포 | 제언: S-LoRA 통합 동적 서빙 체계 |
|---|---|---|
| **GPU 인프라 비용** | 과업 수 × 70B 모델 인스턴스 (수십 대 필요) | 70B 베이스 1대 + 어댑터 캐싱 (1~2대로 통합) |
| **모델 스왑 시간** | 모델 재로딩 시 수십 초~수 분 소요 | 수 밀리초(ms) 단위 CUDA 커널 스왑 |
| **스토리지 용량** | 과업당 수십 GB 중복 저장 | 과업당 수십 MB 어댑터 파일만 보관 |
| **운영 복잡도** | 파편화된 파이프라인 관리 | 중앙 집중형 단일 MLOps 게이트웨이 완결 |
