## 30초 인출

- 본질: **자연어 처리** (NLP: Natural Language Processing)는 인간이 일상적으로 사용하는 자연어 텍스트와 음성을 컴퓨터가 분석·이해(NLU)하고 목적에 부합하는 자연스러운 언어로 생성(NLG)하도록 하는 인공지능 핵심 분야
- 메커니즘: 형태소/서브워드 토큰화(BPE) → 트랜스포머 셀프 어텐션(Self-Attention) 기반 문맥 임베딩 → 다운스트림 태스크 미세조정(Fine-Tuning) 및 인간 가치 정렬(RLHF)
- 통찰: 생성 언어 모델(LLM)의 사실과 다른 거짓을 그럴듯하게 답하는 환각(Hallucination) 현상이 상용화의 최대 장애물이므로 검색 증강 생성(RAG)과 지식 그래프 결합 그라운딩 체계 구축 필요

<details><summary>핵심 용어</summary>

- **NLU (자연어 이해)** : 문장의 구문, 의도(Intent), 개체명(Entity), 감성, 문맥 관계를 파악하여 기계가 이해 가능한 의미 구조로 변환하는 기술.
- **NLG (자연어 생성)** : 정형 데이터나 프롬프트 컨텍스트를 바탕으로 인간이 읽을 수 있는 유창한 자연어 문장을 합성하는 기술.
- **트랜스포머 (Transformer)** : 순환(Recurrence)을 배제하고 셀프 어텐션 메커니즘만으로 문맥 내 모든 토큰 간의 상호작용을 병렬 학습하는 딥러닝 아키텍처.
- **환각 현상 (Hallucination)** : 대형 언어 모델이 학습되지 않은 사실이나 존재하지 않는 정보를 진실인 것처럼 그럴듯하게 왜곡 생성하는 현상.
- **RAG (검색 증강 생성)** : 생성 전 외부 공인 지식 베이스에서 관련 문서를 실시간 검색하여 프롬프트에 주입함으로써 답변의 정확도를 담보하는 기술.

</details>

## 2~4교시 25점 답안

## Ⅰ. 자연어 처리(NLP)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 인간의 언어적 의사소통(텍스트, 음성) 체계를 컴퓨터가 이해할 수 있는 수치적 벡터 공간으로 매핑하고, 의미 해석(NLU)과 텍스트 생성(NLG)을 수행하는 인공지능 융합 기술 |
| 목적 | 인간-컴퓨터 간 자연스러운 상호작용(HMI) 지원, 비정형 텍스트 지식 자동화 추출, 지능형 번역·요약·대화 에이전트 구현 |

## Ⅱ. 자연어 처리의 기술 진화 및 세대별 특징

| 세대 구분 | 대표 기술 및 모델 | 주요 특징 및 한계 |
|---|---|---|
| **1세대: 규칙 기반** | 정규표현식, 사전 매칭, 구문 분석(CFG) | 전문가가 언어학 규칙을 수기 작성, 신조어 및 문맥 예외 대응 불가 |
| **2세대: 통계적 모델** | N-gram, TF-IDF, Naive Bayes, HMM | 말뭉치 출현 빈도 기반 통계 추정, 단어 간 의미적 유사도 미반영 |
| **3세대: 신경망 임베딩** | Word2Vec, GloVe, LSTM, Seq2Seq | 단어를 밀집 벡터(Dense Vector)로 표현, 장기 의존성(Long-term Dependency) 한계 |
| **4세대: 초거대 모델** | Transformer, BERT, GPT-4, LLaMA | 사전학습-미세조정(Pre-train & Fine-tune) 및 인컨텍스트 학습(In-Context Learning) |

## Ⅲ. 트랜스포머 기반 엔드투엔드 NLP 파이프라인 아키텍처

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 트랜스포머 기반 현대 자연어 처리(NLP) 엔드투엔드 파이프라인 ]         │
└────────────────────────────────────────────────────────────────────────┘

  [ 비정형 원천 텍스트 (Raw Corpus) ]
                 │
                 ▼
  [ 1단계: 토큰화 및 수치화 (Tokenization & Embedding) ]
   ├── 서브워드 분절: Byte-Pair Encoding (BPE) / WordPiece
   └── 토큰 임베딩 + 회전 위치 임베딩 (RoPE: Rotational Position Embedding)
                 │
                 ▼
  [ 2단계: 심층 트랜스포머 인코더/디코더 레이어 (Transformer Backbone) ]
   ┌─────────────────────────────────────────────────────────────────┐
   │ [ Multi-Head Self-Attention ] ──> 토큰 간 전역 관계 가중치 계산 │
   │ [ Layer Normalization & Residual Connection ]                  │
   │ [ Feed-Forward Network (FFN / SwiGLU) ]                         │
   └────────────────────────────────┬────────────────────────────────┘
                                    │
         ┌──────────────────────────┴──────────────────────────┐
         ▼ (NLU 계층: 인코더 중심)                             ▼ (NLG 계층: 자기회귀 디코더)
  [ 의미 이해 태스크 (NLU) ]                           [ 텍스트 생성 태스크 (NLG) ]
   - 의도 분류 (Intent Classification)                  - 다음 토큰 확률 예측 ($P(w_t|w_{<t})$)
   - 개체명 인식 (NER / Sequence Labeling)              - 디코딩 전략 (Top-p Nucleus, Temperature)
   - 기계 독해 및 검색 (MRC / Dense Retrieval)          - 다국어 번역, 문서 요약, 대화 생성
```

| 파이프라인 단계 | 엔지니어링 수행 내용 | 핵심 알고리즘 및 기법 |
|---|---|---|
| **토큰화 (Tokenization)** | OOV(Out-Of-Vocabulary) 문제를 해결하기 위해 단어를 하위 단위로 분절 | BPE(Byte-Pair Encoding), SentencePiece |
| **위치 인코딩** | 어텐션의 위치 무관성(Permutation Invariance)을 보완하기 위해 위치 정보 주입 | Sinusoidal, RoPE(Rotary Position Embedding) |
| **어텐션 연산** | Query, Key, Value 벡터 내적을 통한 문맥 가중치 산출 | Scaled Dot-Product Attention |
| **정렬 (Alignment)** | 인간의 피드백을 반영하여 유해성 차단 및 유용성 극대화 | RLHF(PPO), DPO(Direct Preference Optimization) |

## Ⅳ. 자연어 이해(NLU) vs 자연어 생성(NLG) 비교

| 비교 항목 | 자연어 이해 (NLU: Understanding) | 자연어 생성 (NLG: Generation) |
|---|---|---|
| **기능 목적** | 텍스트로부터 숨겨진 의미, 감성, 의도 추출 | 의미적 아이디어를 유창하고 문법적인 문장으로 표현 |
| **입력과 출력** | 비정형 텍스트 $\rightarrow$ 정형 데이터 (라벨, JSON, 그래프) | 프롬프트 / 정형 데이터 $\rightarrow$ 비정형 텍스트 |
| **대표 아키텍처** | 양방향 인코더 (BERT, RoBERTa, DeBERTa) | 자기회귀 디코더 (GPT-4, Claude, LLaMA) |
| **핵심 평가 지표** | Accuracy, F1-Score, Exact Match (EM) | BLEU, ROUGE, METEOR, Perplexity (PPL) |
| **주요 난제** | 중의성(Ambiguity), 은유, 복합 다의어 해소 | 문맥 일관성 유지, 사실성 담보, 환각 억제 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 대규모 파라미터 기반 생성형 LLM이 사실과 다른 허위 정보를 사실처럼 출력하는 환각(Hallucination) 발생 | 공인 벡터 DB 기반 RAG(검색 증강 생성) 아키텍처 도입 및 지식 그래프(Knowledge Graph) 연계 팩트 체킹 검증기 구축 |
| 웹 크롤링 데이터 내 혐오 발언, 성별·인종 편향 및 개인 식별 정보(PII)의 무단 학습과 생성 노출 | 엄격한 데이터 필터링 파이프라인(NeMo Guardrails) 적용 및 DPO 기반 안전성 미세조정 정렬 |
| 트랜스포머의 어텐션 메커니즘이 입력 길이($N$)에 대해 $O(N^2)$의 메모리 및 연산 복잡도를 요구하여 긴 문서 처리 지연 | FlashAttention(SRAM 최적화), 선형 어텐션(Linear Attention) 및 Mamba(상태 공간 모델, SSM) 하이브리드 아키텍처 채택 |

## Ⅵ. 제언

산업 현장 내 신뢰 가능한 NLP 시스템 구축을 위해, 범용 파운데이션 모델에만 의존하지 않고 기업 내부 프라이빗 RAG와 소형 도메인 특화 모델(sLLM)을 결합한 하이브리드 서빙 아키텍처 구축 필요.

```text
[ 사용자 질의 (Query) ]
            │
            ▼
[ 질의 분석 및 프라이빗 하이브리드 라우터 ]
   ├── Step 1: PII 개인정보 마스킹 및 악성 프롬프트 인젝션 차단
   ├── Step 2: 하이브리드 검색 (BM25 키워드 + Dense Vector 임베딩)
   └── Step 3: 관련 내부 규정 문서 발췌 후 프롬프트 컨텍스트 결합 (Grounding)
            │
            ▼
[ 파인튜닝된 도메인 sLLM 추론 엔진 ] ──> [ 출력 가드레일 (환각/편향 검증) ] ──> [ 최종 답변 ]
```

| 구분 | 범용 퍼블릭 LLM 단독 호출 | 제언: 프라이빗 RAG + 도메인 sLLM |
|---|---|---|
| **정보 신뢰성** | 학습 시점 컷오프로 최신 정보 왜곡 및 환각 | 최신 사내 문서를 참조하여 출처 주석 제공 |
| **데이터 보안** | 외부 클라우드 전송에 따른 기밀 유출 위험 | 온프레미스/VPC 내 폐쇄망 구축으로 100% 보안 |
| **운영 비용** | API 토큰 호출 비용 종속성 발생 | 파라미터 경량화(7B~14B)로 로컬 서빙 비용 절감 |
| **도메인 특화** | 범용적인 답변 위주 생성 | 사내 전문 용어 및 업무 프로세스 완벽 대응 |
