<details>
<summary>핵심 용어</summary>

- **프롬프트 엔지니어링(Prompt Engineering)** : 입력 지시와 문맥을 구성해 모델 응답을 과업에 맞게 유도하는 방법
- **Zero-shot prompting** : 예시 없이 지시와 문맥으로 응답을 요청하는 방식
- **Few-shot prompting** : 소수의 입력·출력 예시로 기대 응답 패턴을 안내하는 방식
- **ReAct(Reasoning and Acting)** : 추론과 도구 실행을 번갈아 수행하고 관찰 결과를 다음 판단에 반영하는 패턴
- **프롬프트 인젝션(Prompt Injection)** : 신뢰할 수 없는 입력이 모델의 지시 처리에 개입해 의도하지 않은 동작을 유도하는 공격
</details>

## 2~4교시 25점 답안

### Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **프롬프트 엔지니어링(Prompt Engineering)** 은 입력 지시와 문맥을 설계해 모델 응답을 과업에 맞게 유도하는 방법 |
| 목적 | 과업 요구와 기대 출력에 맞는 응답 유도 |

### Ⅱ. 기본 설계 흐름

```text
과업·평가 기준
      ↓
지시·문맥·예시 구성
      ↓
모델 응답 생성
      ↓
대표 입력 평가
      ↓
프롬프트 개선
```

### Ⅲ. 주요 기법

| 기법 | 작동 방식 | 적용 관점 |
|---|---|---|
| **Zero-shot prompting** | 예시 없이 지시·문맥으로 요청 | 과업과 출력 조건이 명확한 경우 |
| **Few-shot prompting** | 입력·출력 예시로 패턴 제시 | 분류 기준·출력 형태를 구체화할 경우 |
| **ReAct(Reasoning and Acting)** | 추론과 도구 실행·관찰을 반복 | 외부 정보가 필요한 다단계 과업 |

### Ⅳ. 적용 한계와 통제

| 한계 | 대응 |
|---|---|
| 입력 표현에 따라 응답이 달라질 수 있음 | 대표 입력 묶음으로 회귀 평가 |
| **프롬프트 인젝션(Prompt Injection)** 으로 지시 경계가 흔들릴 수 있음 | 신뢰 경계를 분리하고 도구 권한·행위를 제한 |
| 형식 지시만으로 출력 구조가 보장되지 않음 | 스키마 검사와 후속 유효성 검증 |

### Ⅴ. 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 여러 과업이 같은 프롬프트 자원을 공유하면 변경 영향 확인이 어려움 | 영향 과업·대표 입력을 묶어 관리하고 배포 전 회귀 평가를 통과한 변경부터 순차 적용 |
