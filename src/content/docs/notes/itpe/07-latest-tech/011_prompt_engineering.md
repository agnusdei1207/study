```text
 ┃
 ┣━ Ⅰ 개요 ───── 모델 가중치 변경 없이 자연어 입력 설계만으로 LLM의 잠재 추론 역량을 극대화
 ┣━ Ⅱ 특징 ───── 비학습적 제어(In-Context Learning) · 즉각적 피드백 반영 · 모델 크기/지침 순응도 의존
 ┣━ Ⅲ 구조 ───── 역할(Role) + 지시문(Instruction) + 문맥(Context) + 입력(Input) + 출력 형식(Output Constraint)
 ┣━ Ⅳ 흐름 ───── ① 사용자 요구 분석 → ② 프롬프트 템플릿 설계 → ③ Few-shot/CoT 기법 결합 → ④ 출력 검증/튜닝
 ┣━ Ⅴ 비교 ───── Zero-shot vs Few-shot vs CoT vs 프롬프트 엔지니어링 vs 하네스 엔지니어링(Harness)
 ┗━ Ⅵ 실무 ───── 프롬프트 인젝션/탈옥(Jailbreak) / 모델 업데이트 시 출력 변동 / 긴 문맥 비용
```

## 한 줄 본질
- 수억 원의 모델 재학습(Fine-tuning) 비용 한계 → 시스템 지시문과 예시(In-Context)의 구조화된 설계를 통해 원하는 출력과 추론 경로를 유도 → 개발 민첩성 극대화 / 모델 버전 변경 시 비결정론적 응답 드리프트 위험

## 핵심 그림
```text
[프롬프트 5대 핵심 구성요소 구조]
+-------------------------------------------------------------------+
| [역할(Role)]      "당신은 10년 경력의 금융 컴플라이언스 전문가입니다."  |
| [문맥(Context)]   "다음은 2026년 개정된 개인정보보호법 조항입니다."   |
| [지시(Instruction)]"위 조항을 기준으로 주어진 처리 내역의 위반을 검토하세요"|
| [예시(Few-shot)]  "질의: ... -> 추론: ... -> 판단: 위반 없음"       |
| [입력(Input Data)]"처리 내역: 마케팅 목적 식별자 제3자 제공 건"      |
| [출력(Constraint)]"JSON 포맷으로 출력: {위반여부: bool, 사유: str}"  |
+-------------------------------------------------------------------+
```

## 핵심 용어
- CoT(Chain of Thought): "단계별로 생각해 봅시다(Let's think step by step)"와 같이 중간 추론 과정을 명시적으로 출력하도록 유도해 복합 추론 정답률을 높이는 기법
- ReAct(Reasoning + Acting): 추론(Thought)과 도구 호출(Action), 결과 관찰(Observation)을 번갈아 수행하도록 프롬프트를 구성해 외부 시스템과 상호작용하는 패턴
- 하네스 엔지니어링(Harness Engineering): 프롬프트 텍스트 자체뿐 아니라 LLM이 도구(API)를 호출하고 상태를 유지하며 안전하게 동작하도록 감싸는 런타임 샌드박스 및 평가 파이프라인

## 핵심 통찰
- 프롬프트 엔지니어링은 마법의 주문(Voodoo)이 아니라 소프트웨어 인터페이스 설계(API Specification)의 관점으로 접근해야 유지보수 가능
- 단순히 "자세히 설명해줘"라는 정성적 지시보다 "반드시 JSON 스키마를 준수하고 3문장 이내로 작성하라"는 형식 제약(Constraint)이 환각을 대폭 감소
- 단일 거대 프롬프트에 모든 지침을 넣는 것보다 여러 단계의 특화된 프롬프트로 체이닝(Chaining)하는 것이 추론 성공률 우수

## 이웃 토픽과 구분
- 프롬프트 엔지니어링 vs 하네스 엔지니어링: 프롬프트 엔지니어링은 LLM에 입력할 자연어 문구 최적화 중심 / 하네스 엔지니어링은 LLM의 입출력을 감싸는 컨텍스트 관리, 도구 바인딩, 회귀 테스트, 런타임 환경 통제 중심

## 문제·원인·대책
- 적용 상황: 고객 대상 LLM 챗봇이 악의적 프롬프트 입력에 의해 사내 비밀을 누설
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 시스템 지침 무력화(Prompt Injection) | 사용자 입력과 시스템 명령어가 동일한 컨텍스트 채널로 유입 | 입력 데이터 구분자(Delimiter) 분리 및 LLM Guardrails 적용 | 사용자 입력을 데이터로만 취급해 명령어 우회 방지 |
| 복합 수학/논리 문제의 연산 오류 | 한 번에 최종 정답만을 도출하도록 지시 | CoT(Chain-of-Thought) 적용 및 중간 추론 단계 출력 강제 | 단계적 논리 검증을 통한 복합 문제 정답률 대폭 향상 |
| 응답 포맷 불안정으로 파싱 실패 | 자연어 응답의 비결정론적 특성 | Structured Outputs(Pydantic/JSON 스키마 강제) 모드 적용 | 다운스트림 시스템과의 안정적 데이터 인터페이스 보장 |
