## 답안 골격
```text
[AI-Ready Data] ◀━━ 머리: Ⅶ 내 의견 (단순 원시 데이터 축적을 넘어 의미적 메타데이터·벡터 인덱싱·컴플라이언스를 일체화한 AI 가공 인프라 구축)
 ┃
 ┣━ Ⅰ 개요 ───── 기업 내 방대한 비정형 원시 데이터(Data Swamp) 방치 → AI 모델 및 RAG/에이전트가 즉시 소비 가능한 데이터 자산화 필요
 ┣━ Ⅱ 특징 ───── 기계 가독성(Machine Readability) · 풍부한 메타데이터(Contextualized) · 법적/윤리적 무결성(Compliance) · 품질 표준화
 ┣━ Ⅲ 구조 ───── 원천 수집 계층 + 정제/비식별화 파이프라인 + 청킹/임베딩 가공기 + 데이터 카탈로그/거버넌스 + 서빙 계층(Vector DB/Feature Store)
 ┣━ Ⅳ 흐름 ───── ① 비정형 원시 데이터 수집 → ② 노이즈 정제 및 PII 마스킹 → ③ 시맨틱 청킹 및 벡터화 → ④ 거버넌스 메타데이터 태깅 → ⑤ AI 파이프라인 즉시 서빙
 ┣━ Ⅴ 비교 ───── 원시 데이터(Raw) vs BI 분석용 데이터(OLAP) vs AI-Ready Data (비정형/무질서 vs 정형/집계 vs 임베딩·컨텍스트·의미 보존)
 ┗━ Ⅵ 실무 ───── 문서 내 표/이미지 정보 손실 / 개인정보 유출 리스크 / 데이터 최신성(Freshness) 유지 파이프라인 부재
```

- 필수 키워드: AI-Ready Data · 데이터 자산화 · 시맨틱 청킹(Semantic Chunking) · 데이터 거버넌스 · PII 비식별화 · 피처 스토어(Feature Store)
- 기출: 미출제. 예상: "기업 내 LLM 도입 및 AI 전환(AX) 가속화를 위한 AI-Ready Data의 개념, 필수 요건 및 데이터 정제·가공 파이프라인 구축 방안을 설명하시오." → Ⅰ~Ⅶ

## 한 줄 본질
- 사내에 수십 년간 쌓인 PDF, 이메일, 데이터베이스는 포맷이 제각각이고 개인정보가 섞여 있어 최신 AI 모델에 바로 넣을 경우 환각과 컴플라이언스 위반을 초래함 → 텍스트 추출, 시맨틱 청킹, 비식별화, 벡터 임베딩 및 계통(Lineage) 추적 체계를 거쳐 AI가 즉시 이해 가능한 형태로 표준화 → AI 도입 성공률 제고 / 데이터 가공 파이프라인 유지보수 비용 발생

## 핵심 그림
```text
[Raw Data에서 AI-Ready Data로의 전환 파이프라인]

  [원천 데이터]                  [AI 가공 파이프라인]                      [AI-Ready Data 자산]
┌──────────────┐          ┌──────────────────────────────────┐          ┌──────────────────────┐
│ 사내 PDF 문서 │          │ 1. 레이아웃 보존 파싱 (OCR/Docling│          │ 시맨틱 청크 & 임베딩 │
│ 사내 DB/ERP   │ ───────> │ 2. 개인정보(PII) 마스킹/비식별화 │ ───────> │ (Vector Database)    │
│ 이메일/채팅록 │          │ 3. 의미론적 청킹 (Semantic Chunk)│          │ 피처/지식 그래프     │
│ 오디오/비디오 │          │ 4. 출처/권한 메타데이터 바인딩   │          │ (Feature / Graph DB) │
└──────────────┘          └──────────────────────────────────┘          └──────────────────────┘
  (Data Swamp)                 (품질 검증 & 거버넌스)                        (AI 즉시 소비 가능)
```

## 핵심 용어
- 시맨틱 청킹(Semantic Chunking): 고정된 글자 수(예: 500자)로 문서를 무작정 자르지 않고, 문맥의 완결성과 문단 구조, 제목 계층을 보존하여 자르는 지능형 분할 기술
- 데이터 계통(Data Lineage): 특정 데이터 조각이 어떤 원천 파일에서 추출되어 어떤 변환 및 마스킹 과정을 거쳐 임베딩되었는지를 역추적할 수 있는 메타데이터 이력
- 피처 스토어(Feature Store): 머신러닝 및 AI 추론에 필요한 정제된 특성(Feature) 데이터를 일관된 API로 학습 및 실시간 서빙 환경에 제공하는 중앙 저장소

## 핵심 통찰
- "Garbage In, Garbage Out"의 법칙은 LLM 시대에 더욱 잔혹함: 모델의 파라미터가 아무리 커도 입력 데이터의 맥락이 찌그러져 있으면 고스란히 정교한 거짓말(Hallucination)로 증폭됨
- AI-Ready Data는 단순한 텍스트 파일이 아니라 "텍스트 + 구조 + 권한 메타데이터": 문서를 읽을 수 있는 권한(RBAC) 태그가 데이터에 붙어 있지 않으면 RAG 시스템에서 타 부서 기밀 문서가 일반 사원에게 유출되는 보안 사고 발생
- 원시 데이터 파싱의 최대 병목은 "표(Table)와 다이어그램": 단순 OCR로 표를 긁으면 행과 열의 관계가 붕괴되므로, 마크다운 표나 HTML 구조로 복원하는 멀티모달 파서가 AI-Ready 전환의 성패를 가름

## 이웃 토픽과 구분
- 데이터 레이크 vs AI-Ready Data: 데이터 레이크는 원시 데이터를 원본 그대로 대용량 보관 / AI-Ready Data는 AI 모델이 즉각 검색·학습할 수 있도록 임베딩, 정제, 메타데이터화가 완료된 정예 자산

## 문제·원인·대책
- 적용 상황: 금융사 규정집 기반 RAG 검색 챗봇 구축 프로젝트
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 복잡한 표 형태의 수수료 기준을 검색기가 엉뚱하게 조회하여 잘못된 답변 산출 | 고정 길이 청킹으로 인해 표의 헤더와 셀 데이터가 서로 다른 청크로 잘림 | Vision-Language 기반 문서 파서 및 마크다운 테이블 보존 청킹 적용 | 표 데이터 검색 정확도 40% 이상 향상 |
| 검색 답변 결과에 고객 주민등록번호 및 계좌번호가 그대로 노출 | 원천 데이터 비정형 텍스트에 포함된 민감정보 필터링 부재 | 정규식 및 NER 기반 실시간 PII 탐지·가명화 파이프라인 구축 | 개인정보 노출 사고 제로화 |
| 사내 규정이 개정되었음에도 챗봇이 과거 폐기된 규정을 사실처럼 안내 | 원천 문서 변경 시 벡터 DB 인덱스가 동기화되지 않는 라이프사이클 부재 | CDC(Change Data Capture) 기반 실시간 임베딩 갱신 파이프라인 구축 | 최신 규정 반영 지연 시간 1일 이내 단축 |
