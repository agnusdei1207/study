## 연관 키워드

- AI-Ready Data, RAG, 데이터 거버넌스, 계보(Lineage), 권한 인지, 환각
- GIGO, PII, 청킹, 메타데이터, ACL, CDC, 벡터 인덱스

## Ⅰ. AI-Ready Data의 개요

- 핵심 요약 : 학습과 추론, 검색 증강 생성이 바로 쓸 수 있도록 품질, 기계 가독성, 권한, 출처 추적성을 갖춘 정제 데이터 자산.
- 개념 : AI 모델의 학습·추론과 **RAG** (Retrieval-Augmented Generation, 외부 문서를 검색해 생성 모델의 답변 근거로 제공하는 방식)이 즉시 소비할 수 있도록 정확성, 기계 가독성, 메타데이터, 보안 권한, 출처 추적성을 확보한 **AI-Ready Data** 자산.
- 배경 및 필요성 : 정제되지 않은 원천 데이터를 투입하면 **GIGO** (Garbage In, Garbage Out, 입력 품질이 출력 품질을 결정하는 원리)가 발생하고 저작권과 개인정보 침해 위험도 커지므로, DAMA-DMBOK(Data Management Body of Knowledge) 같은 데이터 거버넌스 체계 아래 품질 게이트와 민감정보 자동 필터링을 두어야 함.
- 주요 목적 : 환각(Hallucination) 억제, 엔터프라이즈 데이터 보안과 라이선스 준수, AI 모델 성능 확보.

## Ⅱ. AI-Ready Data의 특징 및 장점

- 핵심 요약 : 기계 가독성, 맥락 보존, 권한 인지, 추적 가능성이 함께 갖춰져 AI 응답의 정확성과 통제 가능성을 높이는 속성.

1. **기계 가독성** (Machine-Readable) : 레이아웃 중심 문서를 OCR과 비전-언어 모델 기반 마크다운 등 구조화 형태로 변환 → 파서와 검색기가 내용을 정확히 이해.
2. **맥락 보존성** (Context Preservation) : 표, 다이어그램, 계층 구조가 청킹 과정에서 유실되지 않도록 보존 → 답변 근거의 의미가 손상되지 않음.
3. **권한 인지성** (Permission-Aware) : 사용자 보안 등급에 따라 검색될 수 있는 청크를 제한 → 기밀 문서가 답변으로 노출되는 것을 차단.
4. **추적 가능성** (Traceability) : 답변의 출처 문서, 위치, 버전을 계보(Lineage) 그래프로 역추적 → 검증과 감사가 가능.

## Ⅲ. AI-Ready Data의 구조 (흐름)

- 핵심 요약 : 원천 수집에서 정제, 청킹과 임베딩, 권한 태깅을 거쳐 거버넌스 게이트를 통과한 데이터만 AI 응용에 공급되는 파이프라인.
- **PII** (Personally Identifiable Information, 개인 식별 정보) : 수집 단계에서 가명화하거나 마스킹해야 하는 대상 정보.
- **ACL** (Access Control List, 접근 통제 목록) : 청크 단위로 붙이는 사용자 권한 메타데이터로, 검색 시 실시간 필터링 기준이 됨.

```text
[ 원천 데이터 (문서, DB, 로그) ]
            ↓
[ 수집과 파싱 (OCR, 마크다운 변환) ]
            ↓
[ 품질 정제 (중복 제거, 민감정보 마스킹) ]
            ↓
[ 청킹과 벡터 임베딩 ]
            ↓
[ 메타데이터와 ACL 태깅 ]
            ↓
[ 거버넌스 게이트 (라이선스, 편향 점검) ]
            ↓
[ AI 응용 (파인튜닝, RAG) ]
```

```text
[ 원천 데이터 변경 발생 ]
            ↓ 변경 데이터 캡처
[ 이벤트 스트림 (Kafka 등) ]
            ↓
[ 벡터 인덱스 증분 갱신 ]
            ↓
[ 계보 기록 (버전, 해시) ]
```

## Ⅳ. 전통적 빅데이터와 AI-Ready Data의 비교

- 핵심 요약 : 빅데이터는 양과 속도를 다루고 AI-Ready Data는 품질, 맥락, 권한을 다루므로, 전처리 목표와 보안 방식이 다름.

| 비교 축 | 전통적 빅데이터 | AI-Ready Data |
| --- | --- | --- |
| 핵심 초점 | 양, 속도, 다양성 | 품질, 맥락, 권한 |
| 처리 대상 | 정형 트랜잭션 로그와 테이블 | 텍스트, 코드, 이미지, 복합 레이아웃 문서 |
| 전처리 목표 | OLAP(Online Analytical Processing) 분석, BI(Business Intelligence) 집계 | LLM 토큰화, 임베딩, RAG 검색 |
| 품질 관리 중점 | 결측치, 이상치, 스키마 유효성 | 문맥 단절 방지, 환각 유발 노이즈 제거, 개인정보 통제 |
| 보안 및 권한 | 테이블과 뷰 단위의 정적 권한 | 청크 단위의 메타데이터 기반 동적 ACL |

- 선택 기준 : 분석과 집계가 목적이면 기존 빅데이터 체계를, 생성형 응답과 검색이 목적이면 AI-Ready Data 체계를 우선 검토함.

## Ⅴ. AI-Ready Data의 한계와 방안

- 핵심 요약 : 표 구조 붕괴, 민감정보 유출, 원천 변경의 인덱스 미반영을 레이아웃 분석, 수집 단계 가명화, 변경 데이터 캡처로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 표·다단 레이아웃 붕괴 | 텍스트로 단순 변환하면 셀 간 관계가 사라짐 | 비전 기반 레이아웃 분석 모델(LayoutLMv3), 표 전용 HTML·마크다운 파서 | 표 구조 보존 정확도 |
| 기밀·개인정보의 무단 임베딩 | 정제 없이 임베딩된 민감 정보가 RAG 답변으로 유출 | 수집 단계 PII 자동 가명화(Presidio), 질의 시 실시간 권한 필터링 | 민감정보 탐지 건수, 권한 외 노출 건수 |
| 원천 갱신의 인덱스 미반영 | 수정·삭제된 문서가 벡터 인덱스에 남아 구버전 답변 생성 | **CDC** (Change Data Capture, 변경 데이터 캡처)와 이벤트 스트림 기반 증분 동기화 | 인덱스 반영 지연 시간, 구버전 응답 비율 |

## Ⅵ. AI-Ready Data에 대한 기술사적 제언

- 핵심 요약 : 데이터 준비도를 승인 기준으로 쓰고, 버전과 권한을 함께 관리하는 거버넌스 체계로 AI 데이터를 운영하는 방향.

1. 데이터셋별 준비도 평가 기준(AI-Readiness Scorecard)을 만들어 학습과 검색 투입 전에 승인 기준으로 적용하는 것이 바람직함.
2. 데이터 레이크하우스와 피처 스토어를 결합하고, Apache Iceberg 같은 테이블 포맷으로 **데이터 버전 관리** 체계를 갖춰 재현성과 롤백 가능성을 확보하는 것이 필요함.
3. 보안, 법무, 데이터 조직이 함께 참여하는 정책을 정하여 권한 체계와 저작권 검토 절차를 운영 표준으로 삼는 것이 현실적임.

## Ⅶ. 결론

- 핵심 요약 : AI-Ready Data는 AI가 신뢰하고 사용할 수 있도록 품질과 권한, 출처를 갖춘 데이터 자산.
- 시사점 : AI 응답의 품질은 모델보다 데이터 준비 체계에서 먼저 결정되므로, 데이터 거버넌스가 AI 도입의 전제 조건이 됨.
