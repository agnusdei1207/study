## 연관 키워드

- AX(AI Transformation), AX 2.0, DX(Digital Transformation), 업무 프로세스 재설계(BPR)
- 생성형 AI(Generative AI), 에이전틱 AI(Agentic AI), RAG(Retrieval-Augmented Generation), MCP(Model Context Protocol)
- PoC 함정(PoC Trap), 기간계 연계, PII 마스킹, 환각(Hallucination), FinOps, 제로 트러스트

## Ⅰ. X+AI / AX 2.0의 개요

- 핵심 요약 : 도메인 데이터와 업무 로직에 생성형 AI와 에이전트를 결합해 업무 프로세스를 재설계하는 전사 AI 전환 전략.
- 개념 : 특정 산업 도메인(X)의 고유 데이터와 업무 로직에 생성형 AI와 자율 에이전트를 결합하여 프로세스 자동화와 신규 사업 모델을 만드는 **AX**(AI Transformation) 전략. 'AX 2.0'은 국내 기업이 쓰는 명칭으로, 업계 표준 정의로 확인되지는 않음.
- 배경 및 필요성 : 국내 기업들은 AX 전략을 내세워 현업 에이전트 도입을 추진하는 중이다(SK텔레콤이 2026년 6월 발표한 'AX Innovation 2.0' 보도 기준). 단순 챗봇 수준의 PoC에 머물면 실질적 투자 수익(ROI, Return on Investment)과 현업 채택이 이루어지지 않으므로, 기간계 시스템과의 API 연계와 데이터 거버넌스가 함께 필요하다.
- 주요 목적 : 개별 업무의 효율화를 넘어 조직 전반의 의사결정 속도를 높이고, 운영 비용을 줄이며, AI 중심으로 일하는 조직을 만드는 것.

```text
[ 전환 단계의 흐름 ]

DX (디지털 전환)
   ↓
AX 1.0 (분석·보조)
   ↓
AX 2.0 (에이전트·통합)
```

## Ⅱ. X+AI / AX 2.0의 특징 및 장점

- 핵심 요약 : 도메인 데이터 결합, 에이전트 실행, 업무 재설계, 통합 거버넌스가 맞물려 현업 성과로 이어지는 구조.

1. 도메인 데이터 결합 : 사내 ERP·CRM·MES 정형 데이터와 사규·기술문서 같은 비정형 지식을 함께 묶음 → 범용 답변보다 현업 질문에 근거 있는 응답.
2. 에이전트 실행 : 에이전트가 기간계 API를 직접 호출해 업무를 수행 → 사람이 옮기던 수작업 단계 축소.
3. 업무 프로세스 재설계 (BPR, Business Process Reengineering) : 기존 흐름을 AI를 전제로 다시 설계 → 자동화 수준을 넘어 조직 생산성 향상.
4. 거버넌스 통합 : 윤리·보안·환각 감사와 비용, KPI 통제를 하나의 체계로 묶음 → 전사 확산 시에도 통제 가능성 유지.

## Ⅲ. X+AI / AX 2.0의 구조 (흐름)

- 핵심 요약 : 데이터 플랫폼, AI 엔진, 업무 재설계, 거버넌스의 네 계층이 위에서 아래로 쌓이는 수직 구조.
- **RAG**(Retrieval-Augmented Generation) : 사내 문서를 검색해 모델 답변의 근거로 주입하는 방식. 도메인 데이터 계층과 AI 엔진 계층을 잇는 핵심 장치.
- **에이전틱 AI**(Agentic AI) : 목표를 받아 계획·도구 호출·결과 확인을 스스로 반복하는 AI. 업무 실행 주체가 사람에서 에이전트로 일부 이동.

```text
[ AX 2.0 전환 계층 ]

업무 전략·유즈케이스 발굴
   ↓
도메인 데이터 플랫폼
(정형 ERP·CRM·MES + 사내 문서)
   ↓
AI 엔진·에이전트 계층
(LLM·하이브리드 RAG·도구 연동)
   ↓
AI 네이티브 업무 재설계
(상담·심사·백오피스 프로세스)
   ↓
거버넌스 통제 (윤리·보안·비용·KPI)
```

## Ⅳ. X+AI / AX 2.0의 비교 분석

- 핵심 요약 : DX는 데이터 집계, AX 1.0은 예측 보조, AX 2.0은 에이전트의 실행과 기간계 통합으로 단계가 나뉨.

| 비교 항목 | DX (Digital Transformation) | AX 1.0 (분석·보조) | AX 2.0 (에이전트·통합) |
| --- | --- | --- | --- |
| 핵심 기술 | 클라우드, 웹, 모바일, RDBMS(Relational Database Management System) | 지도학습 ML(Machine Learning), 규칙 기반 챗봇 | 생성형 AI, LLM(Large Language Model), 에이전틱 AI |
| 데이터 활용 | 데이터 수집과 정형화 저장 | 정형 데이터 기반 예측 | 사내 비정형 문서와 멀티모달 통합 |
| 업무 수행 주체 | 사람이 시스템을 조작해 수행 | AI가 예측 점수를 주고 사람이 판단 | AI 에이전트가 실행하고 사람이 최종 책임 |
| 시스템 통합도 | 사일로별 DB 분리 | 특정 업무 전용 모델의 독립 운영 | 전사 기간계와 양방향 API 연동 |

- 선택 기준 : 업무가 판단 보조에 머무는지, 실행까지 맡길 수 있는지, 기간계와 실시간 연동이 필요한지에 따라 단계를 고른다.

## Ⅴ. X+AI / AX 2.0의 한계와 방안

- 핵심 요약 : 기간계 연계 실패, 데이터 유출, 비용과 환각 문제를 API 표준화, 사내 배포, 캐싱과 그라운딩으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| PoC 이후 전사 확산 실패 (PoC 함정) | 레거시 ERP·메인프레임과 연계 불가 → 확산 중단 | 표준 API 게이트웨이 선구축, MCP 기반 도구 표준화 | 운영 중 전환 과제 수 |
| 기밀·개인정보의 외부 LLM 유출 | 외부 상용 API 전송 → 컴플라이언스 위반 | 사내 배포형 모델 운영, PII 실시간 마스킹 프록시 | 마스킹 탐지 건수 |
| API 비용 급증과 환각 불신 | 무분별한 호출 → 토큰 비용 증가, 현업 기피 | 캐싱과 SLM(Small Language Model) 라우팅, 도메인 RAG 그라운딩 | 호출당 비용, 근거 인용률 |

## Ⅵ. X+AI / AX 2.0에 대한 기술사적 제언

- 핵심 요약 : 부서별 실험을 전사 공통 역량으로 묶고, 데이터와 책임 체계를 먼저 세우는 방향으로 AX를 상시 운영 체계로 전환.

1. 경영진이 AX 과제의 우선순위를 포트폴리오로 관리하고, 파일럿 성과를 근거로 확산 대상을 고르는 체계를 세운다.
2. 정보보호 부서가 사내 지식을 공유 자산으로 다루는 데이터 거버넌스 정책을 정비하여 부서 간 자료 공유 기준을 통일한다.
3. 법무·컴플라이언스 부서가 AI 사용 내규와 책임 분계를 계약서와 사내 규정에 명문화하여 현업이 안심하고 쓸 수 있는 틀을 만든다.

## Ⅶ. 결론

- 핵심 요약 : AX 2.0은 AI 도구의 도입이 아니라 업무 흐름과 책임 구조를 AI 전제로 다시 짜는 경영 과제.
- 시사점 : 기간계 연동과 거버넌스가 준비된 조직부터 에이전트의 실행 범위를 넓히는 것이 확산의 현실적 경로다.
