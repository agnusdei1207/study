## 30초 인출

- 본질: **AP2(Agent Payments Protocol)** 는 사용자를 대리하여 자율적으로 쇼핑과 결제를 수행하는 AI 에이전트에게 암호학적으로 서명된 위임장(Mandate)을 부여하고 판매자와 결제사가 이를 상호 검증하는 개방형 에이전트 결제 프로토콜
- 메커니즘: 신뢰 표면(Trusted Surface)에서 사용자 위임장 서명 → 에이전트가 특정 주문에 바인딩된 Checkout/Payment Mandate 생성 → 가맹점 및 결제 처리자의 다자간 독립 검증 → 서명된 영수증(Receipt) 수신
- 통찰: 에이전트의 프롬프트 탈옥으로 인한 무단 과금 위험이 존재하므로 금액 상한과 대상 가맹점이 명시된 스코프 한정 Mandate 및 장바구니 해시 결합 필수

<details><summary>핵심 용어</summary>

- **AP2(Agent Payments Protocol)** : AI 에이전트의 상거래 및 금융 결제 행위에 대해 사용자의 승인 범위와 위임 권한을 검증하는 글로벌 프로토콜.
- **위임장(Mandate)** : 사용자가 허용한 결제 금액, 기간, 구매 품목 제약 조건을 암호학적으로 전자서명한 디지털 권한 증명서.
- **신뢰 표면(Trusted Surface)** : 에이전트의 간섭 없이 사용자가 직접 화면을 보고 생체 인증이나 PIN을 입력하여 서명을 생성하는 안전 실행 영역.
- **Checkout Mandate** : 특정 판매자의 장바구니 품목과 금액이 사용자의 승인 조건과 일치함을 판매자가 검증하는 위임 데이터.
- **Payment Mandate** : 결제 카드사 및 PG사가 에이전트의 결제 자격 증명 사용 권한을 검증하고 승인하는 위임 데이터.

</details>

## 2~4교시 25점 답안

## Ⅰ. AP2의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **AP2(Agent Payments Protocol)** 는 AI 에이전트가 인간 사용자를 대신하여 자율적으로 구매 및 결제를 수행할 때, 암호학적 위임장(Mandate)을 기반으로 권한 범위와 거래 정당성을 다자간 검증하는 상거래 보안 표준 프로토콜 |
| 목적 | 에이전트의 권한 오남용 및 무단 과금 원천 차단, 사용자 의도(Intent)의 부인 방지 증명 확보 및 안전한 자율 상거래(Agentic Commerce) 생태계 조성 |

## Ⅱ. AP2의 핵심 특징

| 구분 | 주요 특징 | 기술적 설명 및 메커니즘 |
|---|---|---|
| **위임 검증성** | 암호학적 위임장 (Mandate) | 사용자의 개인키로 서명된 JSON-LD 형식의 위임장으로 금액, 유효기간, 가맹점 범위를 명시적 제한 |
| **인터페이스 분리**| 신뢰 표면 (Trusted Surface) | 에이전트가 변조할 수 없는 보안 디스플레이(TEE)에서 사용자에게 최종 결제 금액을 노출하고 직접 동의 획득 |
| **이원화 검증** | Checkout 및 Payment 분리 | 가맹점은 주문 무결성(Checkout Mandate)을 검증하고, 금융사는 결제 권한(Payment Mandate)을 독립 검증 |
| **부인 방지** | 상호 서명 영수증 (Receipts) | 가맹점과 결제사가 암호학적 서명이 포함된 영수증을 반환하여 사후 거래 분쟁 및 정산 감사 증적 제공 |

## Ⅲ. AP2 아키텍처 및 5대 참여자 결제 체계

```text
┌────────────────────────────────────────────────────────────────────────┐
│             [ AP2(Agent Payments Protocol) 결제 처리 및 다자간 검증 흐름 ]    │
└────────────────────────────────────────────────────────────────────────┘
 [ 사용자 (User) ]
        │ (1. 결제 의도 전달 및 Trusted Surface 생체 인증)
        ▼
 [ 신뢰 표면 (Trusted Surface) ] ──> 사용자 서명된 [ User Mandate ] 발급
        │
        ▼
 [ 쇼핑 에이전트 (Shopping Agent) ] ── 가맹점 탐색 및 장바구니(Cart) 구성
        │
        ├─────────────────────────────────────────────────┐
        ▼ (2. 주문 요청 + Checkout Mandate)                ▼ (3. 결제 요청 + Payment Mandate)
 [ 가맹점 (Merchant) ]                             [ 결제 처리자 (Payment Processor) ]
   ├── 장바구니 해시 일치 검증                       ├── 카드 발급사(Issuer)와 FIDO 검증
   ├── Checkout Mandate 서명 확인                    ├── 결제 토큰 유효성 및 한도 검증
   └── [ Checkout Receipt ] 서명 발행                └── [ Payment Receipt ] 서명 발행
        │                                                 │
        └────────────────────────┬────────────────────────┘
                                 ▼
                    [ 거래 체결 및 사후 감사 완료 ]
```

| 프로토콜 참여자 | 핵심 역할 및 책임 | 검증 및 산출물 |
|---|---|---|
| **User & Trusted Surface** | 구매 의도 확정 및 보안 영역 내 전자서명 | 서명된 User Mandate |
| **Shopping Agent** | 최적 상품 탐색, 체크아웃 구성 및 위임장 중계 | 결제 요청 페이로드 |
| **Merchant** | 상품 가격, 재고 및 장바구니 불변성 검증 | Checkout Receipt |
| **Credential Provider** | 결제 수단(토큰화 신용카드) 발급 및 관리 | Payment Token |
| **Payment Processor** | 결제 네트워크 전송 및 최종 금융 승인 처리 | Payment Receipt |

## Ⅳ. 전통 간편결제 vs AP2 에이전트 결제 비교

| 비교 항목 | 전통 간편결제 (Apple Pay, 카카오페이) | 에이전트 결제 프로토콜 (AP2) |
|---|---|---|
| **결제 행위 주체** | 인간 사용자가 화면을 보며 직접 승인 | AI 에이전트가 백그라운드에서 대리 결제 |
| **권한 위임 방식** | 세션 로그인 또는 고정된 정기 결제 승인 | 세부 조건이 암호화된 일회성/한정 Mandate |
| **거래 검증 구조** | 단말기 ↔ 결제사 간 1:1 단순 인증 | 사용자-에이전트-가맹점-결제사 4자 간 상호 검증 |
| **자율 수행 지원** | 매번 사용자의 클릭 및 생체 인증 필수 | 사전 위임 한도 내에서 Human-Not-Present 지원 |
| **재사용 공격 방지**| 일회용 암호문(Cryptogram) 사용 | 장바구니 해시(Cart Hash)와 결합된 서명 검증 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 에이전트가 탈옥(Jailbreak)되거나 적대적 프롬프트 공격을 받아 사용자가 의도하지 않은 상품이나 고액 결제를 임의로 승인할 위험 | Trusted Surface에서 결제 건당 최대 금액, 일일 누적 한도, 허용 가맹점 도메인 화이트리스트를 강제하는 스코프 한정 Mandate 발급 |
| 네트워크 전송 중 탈취된 Mandate를 공격자가 가로채어 다른 장바구니 거래에 재사용하는 리플레이 공격(Replay Attack) 위협 | Mandate 내부에 가맹점의 일회성 난수(Nonce)와 특정 주문 장바구니의 SHA-256 해시값을 바인딩하여 1회 사용 즉시 폐기 강제 |
| Human-Not-Present(완전 자율) 모드 실행 중 발생한 품절, 가격 변동, 오배송에 대한 법적 책임 소재 불명확 | 가맹점의 Checkout Receipt와 결제사의 Payment Receipt를 감사 로그로 영구 보존하고 사용자 사전 취소 골든타임 보장 |

## Ⅵ. 제언

신뢰 표면(Trusted Surface)의 FIDO 생체 서명과 스코프 한정 Mandate를 결합하고 실시간 결제 영수증 환류 체계를 갖춘 3계층 에이전트 결제 아키텍처 구축.

```text
[ 사용자 음성/텍스트 구매 지시 ]
             │
             ▼
[ 1단계: Trusted Surface 한도 검증 ] ── (최대 10만원, 특정 가맹점 한정 Mandate 서명)
             │
             ▼
[ 2단계: Shopping Agent 자율 구매 실행 ]
   ├── 최저가 상품 탐색 및 장바구니 구성
   └── 장바구니 해시와 결합된 Checkout/Payment Mandate 생성 및 전송
             │
             ▼
[ 3단계: 가맹점 및 결제사 다자간 독립 검증 ]
   ├── Merchant: 장바구니 무결성 검증 후 Checkout Receipt 발행
   └── Processor: 한도 초과 여부 확인 후 최종 승인 및 Payment Receipt 발행
             │
             ▼
[ 사용자 스마트폰으로 듀얼 서명 영수증 즉시 푸시 알림 ]
```

| 구분 | 단순 API 키 기반 에이전트 결제 | 제언: AP2 기반 암호학적 Mandate 결제 |
|---|---|---|
| **권한 통제** | 전체 결제 권한이 노출되어 과다 청구 위험 | 금액, 가맹점, 시간 단위로 정밀 통제 |
| **위조 방어** | API 키 탈취 시 전액 탈취 가능 | 장바구니 해시 결합으로 위변조 원천 차단 |
| **거래 증적** | 단순 PG사 승인 내역만 존재 | 가맹점·결제사 서명 영수증 기반 법적 증거력 |
