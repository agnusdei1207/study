## 연관 키워드

- AP2(Agent Payments Protocol), 에이전트 커머스(Agentic Commerce), 위임장(Mandate)
- Intent Mandate, Cart Mandate, Payment Mandate
- 사용자 부재 거래(Human-Not-Present), 부인 방지(Non-repudiation), 장바구니 무결성(Cart Integrity)
- 스코프 한정(Scope Limitation), 재전송 공격(Replay Attack), 감사 증적(Audit Trail)

## Ⅰ. AP2(Agent Payments Protocol)의 개요

- 핵심 요약 : AI 에이전트가 사용자를 대신해 구매하는 과정에서 서명된 위임장으로 권한 범위와 거래 내용을 검증하는 상거래 프로토콜.
- 개념 : AI 에이전트가 사용자를 대신해 상품을 고르고 결제까지 수행할 때, 암호학적으로 서명된 **위임장** (Mandate)으로 권한 범위와 거래 내용을 검증하도록 정한 **AP2** (Agent Payments Protocol) 상거래 프로토콜.
- 배경 및 필요성 : Google이 2025년 9월 16일 발표한 개방형 표준으로, 60여 개 이상의 launch partner가 참여했다고 공개되었다. 에이전트가 사용자의 실제 의도를 벗어나 결제를 승인하면 책임 소재가 불분명해지므로, 누가 무엇을 얼마까지 승인했는지를 증명하는 장치가 필요해졌다.
- 주요 목적 : 에이전트의 권한 오남용과 무단 결제를 막고, 사용자 의도의 **부인 방지** (Non-repudiation, 거래 사실을 사후에 부정하지 못하게 하는 특성)를 확보하여 안전한 **에이전트 커머스** (Agentic Commerce) 생태계를 만드는 것.

## Ⅱ. AP2(Agent Payments Protocol)의 특징 및 장점

- 핵심 요약 : 단계별 위임장과 서명 검증이 결합되어, 에이전트가 자율적으로 결제하더라도 권한 범위 밖의 거래를 차단하는 구조.

1. 단계별 위임장 : **Intent Mandate** (사용자가 사전에 정한 구매 의도와 한도), **Cart Mandate** (사용자가 확인한 최종 장바구니 서명), **Payment Mandate** (결제 네트워크와 발급사에 전달되는 결제 권한) → 각 단계의 권한을 분리해 한 단계가 뚫려도 전체 거래가 열리지 않음.
2. 암호학적 서명 : 위임장을 사용자 키로 서명 → 권한 범위와 거래 내용을 제3자도 검증 가능 → 사후 분쟁 시 증적으로 활용.
3. 사용자 부재 거래 지원 : 사전에 정한 조건 안에서 에이전트가 사용자 없이 결제를 수행 → 반복 구매와 가격 감시 같은 자율 상거래 확대.
4. 결제 수단 중립 : 특정 카드사나 결제 수단에 묶이지 않는 개방형 구조 → 여러 결제 생태계와 연동 가능.

## Ⅲ. AP2(Agent Payments Protocol)의 구조 (흐름)

- 핵심 요약 : 사용자의 위임장이 에이전트, 가맹점, 결제 처리자로 이어지며 단계마다 독립적으로 검증되는 흐름.
- **위임장 발급** : 사용자가 의도와 조건을 서명된 위임장으로 확정한다.
- **다자 검증** : 가맹점과 결제 처리자가 각자 위임장을 검증한 뒤 거래를 체결하고 증적을 남긴다.

```text
[ 사용자 ]
   ↓ 구매 의도와 한도 서명
[ Intent Mandate ]
   ↓
[ 쇼핑 에이전트 ] 상품 탐색·장바구니 구성
   ↓ 최종 장바구니 확인
[ Cart Mandate ]
   ↓
[ 결제 처리자 ] 결제 권한 검증
   ↓
[ Payment Mandate ] → 거래 체결과 감사 기록
```

```text
[ 권한 검증 분담 ]

[ 가맹점 ]
  장바구니 서명 확인
  주문 무결성 검증
        +
[ 결제 처리자 ]
  결제 권한과 한도 검증
        ↓
[ 거래 증적 보관 ]
```

## Ⅳ. AP2(Agent Payments Protocol)의 비교

- 핵심 요약 : 기존 간편결제는 사람이 매번 승인하는 1:1 인증이고, AP2는 사전 위임 범위 안에서 에이전트가 대리 결제하는 다자 검증 구조.

| 비교 축 | 전통 간편결제 | 에이전트 결제 프로토콜 (AP2) |
| --- | --- | --- |
| 결제 주체 | 사용자가 화면을 보며 직접 승인 | 에이전트가 사전 위임 범위에서 대리 결제 |
| 권한 위임 | 로그인 세션 또는 고정된 정기 결제 승인 | 조건이 명시된 서명 위임장 |
| 검증 구조 | 단말기와 결제사 간 1:1 인증 | 사용자, 에이전트, 가맹점, 결제 처리자 간 다자 검증 |
| 자율 수행 | 매 거래마다 사용자 인증 필요 | 사전 한도 내 사용자 부재 거래 지원 |

- 선택 기준 : 거래를 사람이 매번 확인해야 하는지, 사전 위임으로 자율 처리를 허용할 수 있는지에 따라 두 방식을 구분.

## Ⅴ. AP2(Agent Payments Protocol)의 한계와 방안

- 핵심 요약 : 프롬프트 공격에 의한 부정 결제, 위임장 재사용, 자율 거래의 책임 소재를 한도 설정, 장바구니 바인딩, 감사 증적으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 적대적 프롬프트에 의한 부정 결제 | 에이전트가 조작되어 의도하지 않은 상품이나 고액 결제를 승인할 위험 | 건당 금액, 일일 누적 한도, 허용 가맹점을 위임장 범위로 강제 | 한도 초과 시도 건수 |
| 위임장 탈취와 재사용 | 전송 중 가로챈 위임장을 다른 거래에 재사용할 위험 | 일회성 값과 장바구니 해시를 위임장에 묶어 1회 사용 후 폐기 | 재사용 차단 건수 |
| 자율 거래의 책임 소재 | 품절, 가격 변동, 오배송이 발생했을 때 책임 주체가 불분명 | 단계별 영수증을 감사 로그로 보존하고 취소 가능 시간을 사전 고지 | 분쟁 건수, 취소 처리 시간 |

## Ⅵ. AP2(Agent Payments Protocol)에 대한 기술사적 제언

- 핵심 요약 : 권한 설계, 위변조 방지, 증적 체계를 결제 인프라의 기본 요건으로 묶어 자율 상거래를 통제 가능한 영역에서 넓히는 접근.

1. 결제 사업부는 에이전트에 허용하는 거래 범위를 금액, 가맹점, 기간 단위로 나누어 위임장을 설계하고, 범위를 벗어난 요청은 기본적으로 거절되도록 정책을 짠다.
2. 정보보안 조직은 위임장 서명 키의 보관과 회전 절차를 표준화하고, 에이전트 플랫폼의 프롬프트 공격 대응을 결제 승인 경로와 분리된 검사 계층에서 수행하도록 한다.
3. 법무와 컴플라이언스 조직은 사용자 부재 거래의 책임 분담 기준을 약관과 감사 체계에 반영하고, 영수증과 위임장 기록의 보존 기간을 정해 분쟁 대응의 근거로 삼는다.

## Ⅶ. 결론

- 핵심 요약 : AP2는 AI 에이전트의 자율 결제를 서명된 위임장과 다자 검증으로 통제하려는 개방형 상거래 프로토콜이다.
- 시사점 : 자율 상거래의 확산은 기술 표준보다 권한 설계와 책임 체계가 얼마나 명확한지에 따라 속도가 정해진다.
