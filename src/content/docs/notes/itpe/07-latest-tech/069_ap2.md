## Ⅰ. AP2(Agent Payments Protocol)의 개요

- 개념 : AI(Artificial Intelligence) 에이전트가 인간 사용자를 대신하여 자율적으로 구매 및 결제를 수행할 때, **암호학적 위임장** (Mandate) 을 기반으로 권한 범위와 거래 정당성을 **다자간 검증** 하는 상거래 보안 표준 프로토콜
- 배경 및 필요성 : 에이전트의 프롬프트 탈옥으로 인한 무단 과금 위험이 존재하므로 금액 상한과 대상 가맹점이 명시된 **스코프 한정 Mandate** 및 **장바구니 해시** 결합 필수
- 핵심 목적 : 에이전트의 권한 오남용 및 무단 과금 원천 차단, 사용자 의도(Intent)의 **부인 방지** 증명 확보 및 안전한 **자율 상거래** (Agentic Commerce) 생태계 조성

## Ⅱ. AP2(Agent Payments Protocol)의 핵심 아키텍처 및 동작 메커니즘

AP2는 신뢰 표면(Trusted Surface)에서 사용자 위임장 서명 → 에이전트가 특정 주문에 바인딩된 Checkout/Payment Mandate 생성 → 가맹점 및 결제 처리자의 다자간 독립 검증 → 서명된 영수증(Receipt) 수신 메커니즘을 기반으로 동작하며, 세부적인 아키텍처와 핵심 컴포넌트 간 상호작용 프로세스는 다음과 같음.

```text
┌────────────────────────────────────────────────────────────────────────┐
│             [ AP2(Agent Payments Protocol) 결제 처리 및 다자간 검증 흐름 ]    │
└────────────────────────────────────────────────────────────────────────┘
 [ 사용자 (User) ]
        │ (1. 결제 의도 전달 및 Trusted Surface 생체 인증)
        ▼
 [ 신뢰 표면 (Trusted Surface) ] ──> 사용자 서명된 [ User Mandate ] 발급
        │
        ▼
 [ 쇼핑 에이전트 (Shopping Agent) ] ── 가맹점 탐색 및 장바구니(Cart) 구성
        │
        ├─────────────────────────────────────────────────┐
        ▼ (2. 주문 요청 + Checkout Mandate)                ▼ (3. 결제 요청 + Payment Mandate)
 [ 가맹점 (Merchant) ]                             [ 결제 처리자 (Payment Processor) ]
   ├── 장바구니 해시 일치 검증                       ├── 카드 발급사(Issuer)와 FIDO 검증
   ├── Checkout Mandate 서명 확인                    ├── 결제 토큰 유효성 및 한도 검증
   └── [ Checkout Receipt ] 서명 발행                └── [ Payment Receipt ] 서명 발행
        │                                                 │
        └────────────────────────┬────────────────────────┘
                                 ▼
                    [ 거래 체결 및 사후 감사 완료 ]
```

- 위임 검증성 : 암호학적 위임장 (Mandate) - 사용자의 개인키로 서명된 **JSON(JavaScript Object Notation)-LD** 형식의 위임장으로 금액, 유효기간, 가맹점 범위를 명시적 제한
- 인터페이스 분리 : **신뢰 표면** (Trusted Surface) - 에이전트가 변조할 수 없는 보안 디스플레이(TEE, Trusted Execution Environment)에서 사용자에게 최종 결제 금액을 노출하고 직접 동의 획득
- 이원화 검증 : **Checkout 및 Payment 분리** - 가맹점은 주문 무결성(Checkout Mandate)을 검증하고, 금융사는 결제 권한(Payment Mandate)을 독립 검증

## Ⅲ. AP2(Agent Payments Protocol)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 전통 간편결제 (Apple Pay, 카카오페이) | 에이전트 결제 프로토콜 (AP2) |
|---|---|---|
| **결제 행위 주체** | 인간 사용자가 화면을 보며 직접 승인 | AI 에이전트가 백그라운드에서 대리 결제 |
| **권한 위임 방식** | 세션 로그인 또는 고정된 정기 결제 승인 | 세부 조건이 암호화된 일회성/한정 Mandate |
| **거래 검증 구조** | 단말기 ↔ 결제사 간 1:1 단순 인증 | 사용자-에이전트-가맹점-결제사 4자 간 상호 검증 |
| **자율 수행 지원** | 매번 사용자의 클릭 및 생체 인증 필수 | 사전 위임 한도 내에서 Human-Not-Present 지원 |

- AP2는 상기 비교 지표를 바탕으로 비즈니스 요구사항과 운영 인프라 환경을 고려한 최적의 아키텍처를 선정하고, 확장성과 안정성을 균형 있게 확보해야 함.

## Ⅳ. AP2(Agent Payments Protocol)의 주요 한계점 및 해결 방안

- 에이전트 탈옥(Jailbreak) 및 적대적 프롬프트 공격에 의한 부정 결제 :
  - 한계점 : 에이전트가 탈옥(Jailbreak)되거나 적대적 프롬프트 공격을 받아 사용자가 의도하지 않은 상품이나 고액 결제를 임의로 승인할 위험.
  - 해결 방안 : Trusted Surface에서 결제 건당 최대 금액, 일일 누적 한도, 허용 가맹점 도메인 화이트리스트를 강제하는 스코프 한정 **Mandate** 발급.
- 네트워크 전송 중 Mandate 탈취 및 리플레이 공격(Replay Attack) :
  - 한계점 : 네트워크 전송 중 탈취된 Mandate를 공격자가 가로채어 다른 장바구니 거래에 재사용하는 리플레이 공격(Replay Attack) 위협.
  - 해결 방안 : Mandate 내부에 가맹점의 **일회성 난수** (Nonce) 와 특정 주문 장바구니의 SHA(Secure Hash Algorithm)-256 해시값을 바인딩하여 1회 사용 즉시 폐기 강제.
- 완전 자율 결제 시 품절·가격변동에 대한 법적 책임 소재 불명확 :
  - 한계점 : Human-Not-Present(완전 자율) 모드 실행 중 발생한 품절, 가격 변동, 오배송에 대한 법적 책임 소재 불명확.
  - 해결 방안 : 가맹점의 Checkout Receipt와 결제사의 Payment Receipt를 감사 로그로 영구 보존하고 사용자 사전 취소 골든타임 보장.

## Ⅴ. AP2(Agent Payments Protocol) 적용 및 발전을 위한 기술사적 제언

- 권한 통제 중심 엔터프라이즈 고도화 : 전체 결제 권한이 노출되어 과다 청구 위험의 한계를 탈피하고, 금액, 가맹점, 시간 단위로 정밀 통제를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- 위조 방어 중심 엔터프라이즈 고도화 : API(Application Programming Interface) 키 탈취 시 전액 탈취 가능의 한계를 탈피하고, 장바구니 해시 결합으로 위변조 원천 차단을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- 거래 증적 중심 엔터프라이즈 고도화 : 단순 PG(Payment Gateway)사 승인 내역만 존재의 한계를 탈피하고, 가맹점·결제사 서명 영수증 기반 법적 증거력을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
