- 메커니즘: Trusted Surface에서 mandate 승인 → 에이전트가 거래 요청 구성 → 판매자·결제 참여자가 각각 검증·영수증 반환

<details>
<summary>핵심 용어</summary>

- **AP2(Agent Payments Protocol)** : 사용자 위임 권한과 에이전트 결제를 검증하는 상거래 보안 프로토콜
- **Mandate** : 사용자가 승인한 의도·제약을 담아 서명·검증하는 권한 표현
- **Trusted Surface** : 사용자의 의도·동의를 확인하고 서명된 mandate를 만드는 신뢰된 인터페이스 역할
- **Checkout Mandate** : 판매자가 특정 checkout이 승인 범위에 맞는지 검증하도록 하는 권한 자료
- **Payment Mandate** : 결제 참여자가 에이전트의 특정 checkout 결제 권한을 검증하도록 하는 자료
- **Checkout Receipt·Payment Receipt** : 판매자·결제 처리자가 검증·처리 결과를 돌려주는 영수증 자료
- **Human Present·Human Not Present** : 거래별 직접 승인 방식과 사전 제약에 따른 자율 수행 방식

## 2~4교시 25점 답안

### Ⅰ. AP2의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **AP2(Agent Payments Protocol)** 는 에이전트 결제에서 사용자의 승인·거래 범위를 참여자별로 검증하도록 정한 프로토콜 |
| 목적 | 에이전트 구매가 사용자 승인에 맞는지 확인하고 거래 증거를 남기는 결제 보안 기반 |

### Ⅱ. 역할과 mandate 검증

```text
사용자 의도·제약
       │ Trusted Surface에서 동의·서명
       ▼
사용자 mandate
       │ 에이전트가 특정 checkout 구성
       ▼
Checkout·Payment mandate
       │ 판매자·결제 참여자별 검증
       ▼
거래 처리·검증 영수증
```

| 역할 | 책임 |
|---|---|
| Shopping Agent | 상품 탐색·checkout 구성·권한 자료 제시 |
| Trusted Surface | 사용자 동의 확인·서명 mandate 발급 |
| Merchant | 상품·가격·checkout 무결성과 Checkout Mandate 검증 |
| Credential Provider·Network | Payment Mandate와 자격 증명 범위 검증 |
| Merchant Payment Processor | 자격 증명이 해당 checkout에 승인됐는지 확인·처리 |

AP2는 결제 프로토콜 안에서 권한·checkout 검증을 다루며 상품 카탈로그 API와 상거래 통신 전체를 규정하지 않음.

### Ⅲ. 사용자 승인 방식

| 방식 | 승인 시점 | 검증 기준 |
|---|---|---|
| Human Present(Direct) | 사용자가 구체 checkout·결제를 확인·승인 | 닫힌 mandate의 사용자 서명·거래 일치 |
| Human Not Present(Autonomous) | 사용자가 사전 제약을 승인하고 에이전트가 거래를 구성 | 닫힌 거래가 열린 mandate의 제약을 충족하는지 |

두 방식 모두 검증자에게는 구체 거래에 묶인 닫힌 mandate가 제시되며, 사전 위임 범위와 서명 주체에 차이.

### Ⅳ. 보안·기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 에이전트가 위임된 범위를 넘는 구매를 시도할 수 있음 | 사용자 제약·유효기간을 제한하고 판매자·결제 참여자가 독립 검증 |
| mandate를 다른 checkout에 재사용할 위험 | mandate를 서명된 checkout 식별값에 묶고 해시·권한·만료 검증 |
| 검증 실패 뒤 일반 결제로 우회될 위험 | Checkout·Payment Receipt 오류를 기록하고 안전한 거절·사람 확인 경로 제공 |
