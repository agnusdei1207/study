## 30초 인출

- 본질: 인가형 네트워크에서 처리한 기록의 요약 해시를 공개 원장에 앵커링하는 방식은 하이브리드 설계의 한 예이며, 기밀성과 무결성은 참여자 권한·합의·원본 관리에 달림
- 메커니즘: 내부 거래 확정 → 기록 해시 집계 → 공개 원장 앵커 → 원본·증명 대조

## 2~4교시 25점 답안

## Ⅰ. 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 인가형 처리와 공개 검증 기능을 결합한 블록체인 설계 |
| 목적 | 기밀 거래 이력의 외부 변경 검증 |

## Ⅱ. 기밀 처리와 외부 검증

```text
기밀 문서 → 인가형 원장의 거래·해시
                  ↓ 머클 루트 집계
              공개 원장 앵커
                  ↓ 원본·증명 경로 대조
              사후 변경 여부 확인
```

- **요구:** 기밀 거래 내용은 인가 참여자에게만 공유하고, 제출된 이력의 사후 변경 여부는 외부 감사자가 확인할 수 있어야 하는 상황.
- **구조:** 인가형 원장에 권한·거래 식별자·내부 합의 기록, 오프체인 저장소에 기밀 문서, 공개 원장에는 주기적 루트 해시와 시각 기록.

## Ⅲ. 인가형 원장과 공개 앵커의 역할

| 구분 | 인가형 처리 | 공개 앵커 |
|---|---|---|
| 보관 대상 | 기밀 거래·권한·원본 연결 | 주기별 요약 해시·시각 |
| 검증 범위 | 승인 참여자의 거래 기록 | 앵커 이후 이력 변경 탐지 |

## Ⅳ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 공개 앵커는 입력의 진실성과 앵커 전 변경을 보장하지 못한다 | 내부 승인·원본 보존과 앵커 주기·증명 경로를 함께 감사한다 |

## Ⅴ. 제언

- 외부 감사가 필요한 이력부터 앵커 주기와 원본 보존 책임을 확정한 뒤 공개 원장 기록을 적용한다.

## 출제 이력과 검증 출처

위 문항은 예상문제이며, 해당 표제어의 공식 출제 원문과 대조하지 않았다.

- [Hyperledger Fabric 프라이빗 데이터](https://hyperledger-fabric.readthedocs.io/en/latest/private-data/private-data.html): 허가 참여자 간 원본 공유와 원장 해시 증빙
- [Ethereum Merkle Patricia Trie](https://ethereum.org/en/developers/docs/data-structures-and-encoding/patricia-merkle-trie/): 해시 기반 상태 검증의 원리
