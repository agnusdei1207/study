## 1교시 10점 답안

| 구분 | 핵심 |
|---|---|
| 정의 | 인가형 처리와 공개 검증 기능을 결합한 블록체인 설계 |
| 목적 | 기밀 거래 이력의 외부 변경 검증 |

- **흐름:** 내부 거래 확정 → 일정 구간의 거래 해시로 머클 루트 계산 → 공개 체인에 루트 기록 → 제3자가 원본·머클 증명·공개 기록 대조.
- **경계:** 공개 앵커는 앵커 이후 이력의 변경 탐지 수단이며, 입력 자료의 진실성이나 내부 참여자의 정직성을 자동 증명하지 않음.

## 2~4교시 25점 답안

| 구분 | 핵심 |
|---|---|
| 정의 | 인가형 처리와 공개 검증 기능을 결합한 블록체인 설계 |
| 목적 | 기밀 거래 이력의 외부 변경 검증 |

1. **요구:** 기밀 거래 내용은 인가 참여자에게만 공유하고, 제출된 이력의 사후 변경 여부는 외부 감사자가 확인할 수 있어야 하는 상황.
2. **구조:** 인가형 원장에 권한·거래 식별자·내부 합의 기록, 오프체인 저장소에 기밀 문서, 공개 원장에는 주기적 루트 해시와 시각 기록.
3. **검증:** 문서의 정규화·해시 산출 → 내부 블록의 머클 경로 검증 → 공개 원장의 앵커와 비교. 앵커 주기 안의 미확정 창과 체인 재편 가능성을 감사 범위에 명시.
4. **통제:** 키·접근권한, 내부 합의의 장애·악의적 참여자 가정, 앵커 지연 알림, 원본 보존·삭제, 브릿지 사용 시 별도 보안 평가.
