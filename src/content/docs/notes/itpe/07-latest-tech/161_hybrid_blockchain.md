## 답안 골격
### 1교시 예상문제 (10점)
하이브리드 블록체인의 개념과 프라이빗 거래 이력의 퍼블릭 앵커링 원리를 설명하시오.

### 1교시 10점 답안
- **정의:** 인가된 참여자의 내부 원장과 공개 원장의 검증 기능을 결합하는 설계.
- **흐름:** 내부 거래 확정 → 일정 구간의 거래 해시로 머클 루트 계산 → 공개 체인에 루트 기록 → 제3자가 원본·머클 증명·공개 기록 대조.
- **경계:** 공개 앵커는 앵커 이후 이력의 변경 탐지 수단이며, 입력 자료의 진실성이나 내부 참여자의 정직성을 자동 증명하지 않음.

### 2~4교시 예상문제 (25점)
기관 간 기밀 문서 공유에 하이브리드 블록체인을 적용할 때 구조, 검증 절차, 위험 통제를 설명하시오.

### 2~4교시 25점 답안
1. **요구:** 기밀 거래 내용은 인가 참여자에게만 공유하고, 제출된 이력의 사후 변경 여부는 외부 감사자가 확인할 수 있어야 하는 상황.
2. **구조:** 인가형 원장에 권한·거래 식별자·내부 합의 기록, 오프체인 저장소에 기밀 문서, 공개 원장에는 주기적 루트 해시와 시각 기록.
3. **검증:** 문서의 정규화·해시 산출 → 내부 블록의 머클 경로 검증 → 공개 원장의 앵커와 비교. 앵커 주기 안의 미확정 창과 체인 재편 가능성을 감사 범위에 명시.
4. **통제:** 키·접근권한, 내부 합의의 장애·악의적 참여자 가정, 앵커 지연 알림, 원본 보존·삭제, 브릿지 사용 시 별도 보안 평가.

```text

 ┃
 ┣━ Ⅰ 개요 ───── 퍼블릭 블록체인의 낮은 처리 속도 및 데이터 공개 위험과 프라이빗 블록체인의 폐쇄성 및 신뢰 부족을 상호 보완하기 위해 대두
 ┣━ Ⅱ 특징 ───── 이중화 거버넌스(인가형+비인가형) · 데이터 기밀성 보호 · 고속 트랜잭션 처리 · 퍼블릭 앵커링(Anchoring)을 통한 대외 신뢰 확보
 ┣━ Ⅲ 구조 ───── 프라이빗 영역(내부 트랜잭션, 기밀 비즈니스 로직) + 크로스체인 브릿지/릴레이(Cross-chain Bridge) + 퍼블릭 영역(해시 앵커링, 검증)
 ┣━ Ⅳ 메커니즘 ─ ① 인가 노드 간 선택한 합의 방식으로 거래 확정 → ② 주기적 머클 루트 계산 → ③ 공개 원장에 루트 해시 기록 → ④ 원본·머클 증명과 앵커를 대조해 앵커된 기록의 변경 여부 확인
 ┣━ Ⅴ 비교 ───── 공개 참여형 vs 인가 참여형 vs 연계형 원장: 접근 정책·합의 방식·공개 범위·비용이 설계별로 상이
 ┗━ Ⅵ 실무 ───── 브릿지(Bridge) 해킹 및 스마트 컨트랙트 락업 취약점 / 앵커링 주기 설정에 따른 가스비 비용 최적화 / 인터체인 표준화 부재
```

## 한 줄 본질
- 인가형 네트워크에서 처리한 기록의 요약 해시를 공개 원장에 앵커링하는 방식은 하이브리드 설계의 한 예이며, 기밀성과 무결성은 참여자 권한·합의·원본 관리에 달림

## 핵심 그림
```text
[하이브리드 블록체인의 내부 처리 및 퍼블릭 앵커링 메커니즘]

   [기업 내부 비즈니스 처리]
   ┌─────────────────────────────────────────────────────────────┐
   │ 인가형 원장 (예: Hyperledger Fabric)                         │
   │  - 허가된 참여자 간 거래 처리                                │
   │  - 상세 기록의 접근 권한과 보존 정책 적용                    │
   │  - 거래 내역 머클 트리(Merkle Tree) 구성 -> 머클 루트 생성  │
   └──────────────────────────────┬──────────────────────────────┘
                                  │ (주기적 해시 앵커링 전송)
                                  ▼
   ┌─────────────────────────────────────────────────────────────┐
   │ 인터체인 릴레이 / 브릿지 (Cross-Chain Relayer)              │
   └──────────────────────────────┬──────────────────────────────┘
                                  │
                                  ▼
   ┌─────────────────────────────────────────────────────────────┐
   │ 퍼블릭 블록체인 (Ethereum, Polygon 메인넷)                  │
   │  - 머클 루트 해시값만 스마트 컨트랙트에 영구 기록           │
   │  - 앵커링 시점의 해시와 후속 원본 대조 지원                   │
   └─────────────────────────────────────────────────────────────┘
```

## 핵심 용어
- 앵커링(Anchoring): 프라이빗 체인에서 발생한 수많은 블록의 해시값들을 머클 트리로 압축한 단 하나의 대표 해시(Merkle Root)를 퍼블릭 체인에 트랜잭션으로 영구 기록하는 기술
- 크로스체인 브릿지(Cross-Chain Bridge): 서로 다른 독립적인 블록체인 네트워크 간에 데이터, 자산, 상태 증명을 안전하게 상호 검증하고 전송할 수 있도록 돕는 연계 프로토콜
- 컨소시엄 블록체인(Consortium Blockchain): 단일 기업이 아닌 동일 산업군(금융, 물류 등)의 여러 기관이 노드로 참여하여 분산 거버넌스를 공유하는 인가형 블록체인 형태

## 핵심 통찰
- "엔터프라이즈의 두 가지 딜레마 극복": 기업은 영업 비밀과 고객 개인정보를 퍼블릭 체인에 올릴 수 없고, 그렇다고 자체 프라이빗 체인만 쓰면 외부 고객과 감사 기관이 원장 조작을 의심함
- 여러 기록을 묶어 앵커링하면 거래별 직접 기록에 비해 공개 체인 수수료를 줄일 수 있지만, 절감률은 거래량·앵커링 주기·체인 수수료에 따라 달라짐
- 개인정보 보존·삭제 요구는 프라이빗 원장에서도 별도 검토해야 하며, 공개 체인에 남기는 해시도 데이터와 연결될 수 있는지 평가해야 함

## 이웃 토픽과 구분
- 퍼블릭 vs 프라이빗 vs 하이브리드 블록체인:
| 구분 | 퍼블릭 블록체인 | 프라이빗 블록체인 | 하이브리드 블록체인 |
|---|---|---|---|
| 접근 권한 | 누구나 참여 가능 (익명) | 사전 승인된 인가 노드만 | 내부는 인가 노드, 외부는 대중 검증 |
| 처리 속도 | 네트워크·합의·구현에 따름 | 네트워크·합의·구현에 따름 | 내부 처리와 외부 앵커링 지연을 각각 측정 |
| 데이터 기밀성 | 공개 기록은 참여자가 볼 수 있음 | 권한·채널·암호화 설정에 따름 | 원본 접근 통제와 앵커 정보 노출을 각각 평가 |
| 신뢰 주체 | 수학적 분산 합의 (PoS/PoW) | 참여 기업 연합 (거버넌스) | 기업 연합 거버넌스 + 수학적 퍼블릭 증명 |

## 문제·원인·대책
- 적용 상황: 글로벌 전자 무역 선하증권(B/L) 발급 및 관세청 통관 하이브리드 체인 구축
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 무역 화물 단가와 바이어 정보의 노출 위험 | 공개 원장에 상세 거래를 기록 | 상세 기록은 인가형 저장소에서 접근 통제하고 검증 가능한 해시만 앵커링 | 원본 권한과 해시의 정보 노출 여부를 검증 |
| 인가형 원장 운영자들의 사후 변경 우려 | 소수 참여자의 거버넌스와 변경 권한 | 주기적 해시 앵커링과 독립 검증 절차 적용 | 앵커링 이후 기록 변경을 탐지할 수 있는지 시험 |
| 앵커링 전달자의 장애·변조 | 단일 릴레이에 대한 의존 | 재시도·서명 검증·복수 승인과 기록 대조 | 누락·중복·변조에 대한 복구 가능성 확인 |

## 내 의견
- 머클 루트 앵커링은 특정 시점의 기록 일치 여부를 검증할 뿐 거래의 적법성까지 증명하지 않는다. 별도 규칙 검증이 필요하며 영지식 증명을 쓰려면 증명 대상 규칙과 입력의 신뢰성을 먼저 정의해야 한다.
