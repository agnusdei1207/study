## 한 줄 본질
- 수십~수백억 파라미터 거대언어모델(LLM) 추론 시 VRAM 대역폭 한계로 인한 높은 서빙 비용과 지연시간 → 주요 연산에 민감한 극소수 이상치(Outlier)는 고정밀로 보존하고 대다수 일반 가중치는 4비트 이하로 극단적 압축 및 GPU 전용 연산 커널 융합 → 추론 지연과 메모리 70% 이상 감축 / 특화 커널 미지원 하드웨어에서 연산 오버헤드 발생

## 핵심 용어
- 이상치 보존(Outlier Preservation): LLM 레이어 깊은 곳에서 발생하는 특정 차원의 매우 큰 활성화 값(Outlier)을 저비트로 뭉개지 않고 FP16으로 따로 격리해 양자화 정확도 붕괴를 막는 기법
- 융합 행렬곱 커널(Fused GEMM): 메모리에서 압축된 저비트 가중치를 읽어온 뒤 레지스터 내부에서 즉시 역양자화 및 텐서코어 연산을 단일 파이프라인으로 수행하여 DRAM 왕복 병목을 제거하는 최적화 코드
- KV 캐시 양자화(KV Cache Quantization): 대화 문맥 길이가 길어질수록 VRAM을 잠식하는 Key-Value 캐시 행렬을 저비트(INT4/INT8)로 실시간 압축하여 동시 서빙 처리량을 확장하는 기술

## 핵심 통찰
- LLM 양자화의 성패는 "모든 가중치를 고르게 줄이는 것"이 아니라 "정보량이 90% 집중된 0.1%의 이상치를 얼마나 정교하게 고립시키는가"에 달려 있음
- 이론적인 비트 수 감소가 항상 속도 향상으로 이어지지 않음 → 저비트 데이터를 다시 고정밀로 변환하는 오버헤드가 크면 메모리는 줄어도 지연시간은 늘어남 → 하드웨어 텐서 코어와 1:1로 맞물린 전용 디코딩 커널이 결합되어야만 진정한 가속 달성
- 모델 파인튜닝 없이 사전학습 가중치만으로 수 분 내에 적용 가능한 PTQ(Post-Training Quantization) 방식이어야 상용 서비스 파이프라인에 즉시 배포 가능

## 이웃 토픽과 구분
- TurboQuant vs SmoothQuant: SmoothQuant는 활성화 이상치를 가중치 쪽으로 수학적으로 이관(Smoothing) / TurboQuant는 활성화와 가중치 이상치를 구조적으로 분리하여 하드웨어 가속 커널과 직접 융합

## 문제·원인·대책
- 적용 상황: 대규모 온프레미스 LLM 서빙 클러스터에서 GPU VRAM 부족으로 인한 동시 동접자 처리 한계
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| INT4 단순 양자화 시 한국어 및 코드 생성 성능 급격 저하(Perplexity 폭증) | 토큰 예측에 결정적인 레이어 간 이상치 채널이 잘려 나감(Clipping Distortion) | TurboQuant 이상치 임계값 분리 및 혼합 정밀도(FP16 Outlier + INT4 Base) 적용 | 원본 모델 대비 99.5% 이상의 생성 정확도 보존 |
| 양자화 적용 후 메모리는 줄었으나 토큰 생성 지연시간(TTFT) 증가 | GPU 레지스터와 SRAM 간 역양자화 메모리 복사 오버헤드 발생 | 커스텀 Fused Dequant-GEMM Triton 커널 적용 및 캐시 지역성 극대화 | 토큰당 생성 지연(Inter-token Latency) 40% 단축 |
| 다양한 엔비디아 GPU 세대(Ampere vs Hopper) 간 커널 호환성 오류 | 아키텍처별 텐서 코어 명령어 세트(DP4A vs WGMMA) 지원 차이 | JIT(Just-In-Time) 커널 컴파일러 도입 및 하드웨어 능력별 폴백 경로 구성 | 이종 GPU 환경 전반에서 안정적 서빙 달성 |
