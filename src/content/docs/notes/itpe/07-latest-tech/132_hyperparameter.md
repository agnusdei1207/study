## 30초 인출
- 본질: 데이터로부터 직접 학습되지 않고, 학습 알고리즘의 동작 방식과 신경망 구조의 용량을 제어하기 위해 훈련 시작 전 외부에서 설정하는 메타 제어 변수
- 메커니즘: 탐색 공간 정의 → HPO 알고리즘(Grid/Random/Bayesian Search) 후보 생성 → K-Fold 교차 검증 학습 → 성능 평가 및 Pruning(Hyperband) → 최적 조합 도출
- 통찰: 과도한 검증 셋 반복 평가 시 검증 데이터에 대한 과적합(Overfitting)과 데이터 누출(Data Leakage)이 발생하므로 독립된 테스트 셋 격리 및 통계적 교차 검증 체계 필수

<details><summary>핵심 용어</summary>

- **하이퍼파라미터(Hyperparameter):** 딥러닝 및 머신러닝 모델의 학습 프로세스(학습률, 배치 크기) 및 아키텍처(층 수, 노드 수)를 외생적으로 결정하는 설정값
- **HPO(Hyperparameter Optimization):** 주어진 탐색 공간과 컴퓨팅 예산 제약 내에서 모델의 일반화 성능을 극대화하는 최적 설정 조합을 자동 탐색하는 프로세스
- **그리드 탐색(Grid Search):** 사전에 정의된 모든 하이퍼파라미터 후보군들의 격자 조합을 전수 조사하여 전역 최적점을 탐색하는 방식
- **랜덤 탐색(Random Search):** 정의된 연속/이산 확률 분포 공간에서 무작위로 조합을 표본 추출하여 그리드 탐색 대비 적은 연산으로 고성능 구간을 탐색하는 기법
- **베이지안 최적화(Bayesian Optimization):** 과거의 하이퍼파라미터 탐색 이력을 기반으로 사후 확률 함수(가우시안 프로세스)를 갱신하고, 획득 함수를 통해 유망 지점을 지능적으로 선택하는 HPO 기법

</details>

## 2~4교시 25점 답안

## Ⅰ. 하이퍼파라미터의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 훈련 데이터로부터 가중치와 편향처럼 역전파로 도출되지 않고, 모델 구조 설계 및 학습 제어 메커니즘을 규정하기 위해 사용자가 사전에 정의하는 외부 설정 변수 |
| 목적 | 학습 수렴 속도 제어, 신경망 표현 용량 최적화, 편향-분산 트레이드오프(Bias-Variance Tradeoff) 조율 및 일반화 성능 극대화 |

## Ⅱ. 하이퍼파라미터의 유형별 분류 및 특징

| 분류 영역 | 주요 하이퍼파라미터 | 모델에 미치는 영향 및 특징 |
|---|---|---|
| **네트워크 구조** | 레이어 수(Depth), 은닉 노드 수(Width), 커널 크기, 어텐션 헤드 수 | 모델의 표현 용량(Capacity) 및 파라미터 수, 연산 복잡도(FLOPs) 결정 |
| **최적화 알고리즘** | 학습률(Learning Rate), 모멘텀 계수, 배치 크기(Batch Size), 옵티마이저 종류 | 손실 함수의 수렴 속도, 안장점(Saddle Point) 탈출 능력 및 학습 안정성 지배 |
| **정규화 및 일반화** | 드롭아웃 비율(Dropout Rate), L1/L2 가중치 감쇠(Weight Decay), 배치 정규화 모멘텀 | 모델의 복잡도를 인위적으로 제약하여 학습 데이터 암기(과적합) 방지 |
| **학습 제어 전략** | 학습률 스케줄러(Cosine, Step), 에포크 수, 조기 종료(Early Stopping) 허용 임계값 | 과소적합과 과적합 경계에서 훈련 종료 시점 및 국소 최적점 방지 제어 |

## Ⅲ. 하이퍼파라미터 최적화(HPO) 아키텍처 및 자동 탐색 파이프라인

### 1. HPO 자동화 아키텍처
```text
+-----------------------------------------------------------------------------------+
|                     하이퍼파라미터 자동 튜닝 (HPO) 시스템 프레임워크              |
+-----------------------------------------------------------------------------------+
|  [탐색 공간 정의 (Search Space Configuration)]                                    |
|    - lr: log-uniform[1e-5, 1e-1], batch_size: choice[16, 32, 64], dropout: [0.1, 0.5]|
+-----------------------------------------------------------------------------------+
                               │
                               ▼
+-----------------------------------------------------------------------------------+
|  [HPO 컨트롤러 엔진 (Optuna / Ray Tune)]                                          |
|    +-----------------------------+         +------------------------------------+ |
|    | 제안 알고리즘 (Sampler)     |         | 조기 중단 알고리즘 (Pruner)        | |
|    | - Bayesian (TPE, GP)        |         | - Hyperband / ASHA                 | |
|    | - Random / CMA-ES           |         | - Median Stopping Rule             | |
|    +-----------------------------+         +------------------------------------+ |
+-----------------------------------------------------------------------------------+
                               │ (후보 조합 할당)
                               ▼
+-----------------------------------------------------------------------------------+
|  [분산 학습 워커 클러스터 (Worker Pool)]                                          |
|    Worker 1 [lr=0.001, bs=32] ───> K-Fold 검증 학습 (Loss/Val Acc 측정)           |
|    Worker 2 [lr=0.01,  bs=64] ───> 성능 부진 시 조기 Pruning (자원 회수)          |
|    Worker 3 [lr=0.0001, bs=16] ──> 중간 지표 보고 후 완주                        |
+-----------------------------------------------------------------------------------+
                               │ (검증 지표 피드백)
                               ▼
+-----------------------------------------------------------------------------------+
|  [최적 모델 선정 및 독립 테스트셋 검증 (Final Evaluation)]                        |
|    - 최적 조합 확정 ──> 전체 Train 셋 재학습 ──> Test 셋 단 1회 블라인드 평가    |
+-----------------------------------------------------------------------------------+
```

### 2. 탐색 방식별 후보군 생성 프로세스 비교

```text
     O   O   O   O                 O       O                         . . . O O
     O   O   O   O                    O         O                   . . . O O O
     O   O   O   O               O        O                        . . . O O
     O   O   O   O                  O      O                             O
  (불필요 차원 낭비 심각)        (중요 차원 밀도 높은 탐색)     (성공 이력 기반 집중 탐색)
```

## Ⅳ. 주요 HPO 기법 비교 및 데이터 누출 방지

### 1. 주요 하이퍼파라미터 최적화(HPO) 기법 비교
| 비교 항목 | 그리드 탐색 (Grid Search) | 랜덤 탐색 (Random Search) | 베이지안 최적화 (Bayesian Opt) | 하이퍼밴드 (Hyperband) |
|---|---|---|---|---|
| **동작 방식** | 격자형 전수 조합 평가 | 균등/로그 분포 무작위 추출 | 가우시안 프로세스 기반 사후 확률 모델링 | 다중 무장 밴딧 기반 점진적 반감(Successive Halving) |
| **계산 비용** | 차원의 저주로 지수적 폭증 | 예산 범위 내 고정 연산 | 함수 평가 비용은 높으나 총 시도 수 절감 | 부진한 시도 조기 중단으로 연산 비용 극소화 |
| **탐색 유연성** | 연속형 변수 탐색에 취약 | 연속형/이산형 변수 모두 우수 | 고차원 복잡 곡면에서 최적점 발견 탁월 | 대규모 딥러닝 분산 학습 환경에 최적 |
| **대표 도구** | Scikit-learn GridSearchCV | Scikit-learn RandomizedSearchCV | BoTorch, Optuna (TPE) | Ray Tune, Optuna Hyperband |

### 2. HPO 수행 시 데이터 누출(Data Leakage) 방지 체계
| 누출 경로 | 누출 발생 원인 | 완전 차단 방안 |
|---|---|---|
| **전처리 통계 누출** | 전체 데이터에서 스케일러(Mean/Std) 산출 후 K-Fold 분할 | K-Fold 각 분할 루프 내부에서만 `fit_transform` 수행 (Pipeline 객체 강제) |
| **테스트 셋 오염** | HPO 탐색 중 Test 셋의 정확도를 피드백 지표로 사용 | Test 셋을 HPO 프로세스에서 완전 격리하고 Validation 셋만으로 탐색 |
| **시간 축 왜곡** | 시계열 데이터에서 미래 시점 데이터를 K-Fold 검증에 혼입 | TimeSeriesSplit(롤링 윈도우/확장 윈도우) 기법 적용하여 과거만으로 검증 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **탐색 공간(Search Space)의 폭발과 자원 고갈**<br />하이퍼파라미터 차원이 증가할수록 탐색에 필요한 GPU 시간 및 인프라 비용 기하급수적 증가 | 조기 가지치기(ASHA/Hyperband) 알고리즘 적용, 중요도가 낮은 파라미터는 기본값으로 고정하는 감도 분석(Sensitivity Analysis) 선행 |
| **검증 데이터셋에 대한 과적합(Overfitting to Validation)**<br />수천 회의 탐색 과정에서 모델이 특정 검증 셋의 노이즈까지 암기하여 실전 배포 시 성능 하락 | 중첩 교차 검증(Nested Cross-Validation: 외부 루프 평가, 내부 루프 HPO) 적용 및 정규화 제약 조건 병행 |
| **환경 재현성 결여**<br />하드웨어(GPU 아키텍처), 분산 통신 타이밍 및 라이브러리 버전에 따라 동일 하이퍼파라미터의 결과 편차 발생 | 결정론적 연산(Deterministic Mode) 활성화, 시드 고정, 전체 학습 환경을 도커(Docker) 컨테이너로 이미지화 관리 |

## Ⅵ. 제언

수동 튜닝과 단순 무작위 탐색을 넘어, 비용 대비 탐색 효율을 극대화하는 다중 충실도(Multi-fidelity) HPO 및 파운데이션 모델 미세조정(PEFT) 하이퍼파라미터 자동화 체계로의 고도화 필수.

```text
[소량 데이터 / 적은 에포크] (저비용 후보 필터링) ──> [전체 데이터 / 정밀 에포크] (최적해 확정)
                         ▲
                         └── 다중 충실도(Multi-fidelity) 지능형 파이프라인
```

| 접근 방식 | 과거 전통적 HPO | 최신 Multi-fidelity & AutoML HPO |
|---|---|---|
| **자원 할당** | 모든 후보 조합에 동일한 에포크·데이터 할당 | 저비용 프록시(Downsampled Data)로 선별 후 유망 후보에만 자원 집중 |
| **연동 범위** | 단일 머신러닝 라이브러리 스크립트 기반 | 쿠버네티스 기반 분산 스케줄러(Ray Tune, Kubeflow) 완전 자동화 |
| **메타 학습** | 이전 과업의 탐색 경험 폐기 및 초기화 | 메타 러닝(Meta-learning) 기반 타 데이터셋 학습 경험 전이로 탐색 가속 |
