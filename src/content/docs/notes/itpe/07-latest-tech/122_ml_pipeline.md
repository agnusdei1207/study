## 30초 인출
- **본질:** 머신러닝 파이프라인은 데이터에서 모델 산출물까지의 작업을 재현 가능한 단계로 연결한 실행 흐름.
- **메커니즘:** 입력·코드·설정을 기록하고 검증·학습·평가를 실행해 승인된 모델을 배포 단계로 전달.
- **운영:** 모니터링과 재학습은 성능·데이터 변화에 맞춘 별도 기준과 승인을 두어 연결.

<details><summary>핵심 용어</summary>

- **머신러닝 파이프라인(Machine Learning Pipeline):** 데이터 준비부터 모델 학습·평가·배포까지의 작업을 연결·자동화하는 실행 구조.
- **MLOps(Machine Learning Operations):** 머신러닝 모델의 개발·배포·운영·감시를 재현성 있게 관리하는 관행과 도구.
- **DAG(Directed Acyclic Graph, 방향성 비순환 그래프):** 작업을 노드와 선행관계로 나타낸 순환 없는 그래프 구조.
- **데이터 계보(Data Lineage):** 데이터와 변환 결과가 어디서 왔고 어떤 처리 단계를 거쳤는지 기록한 정보.
- **모델 레지스트리(Model Registry):** 모델 버전, 평가 결과, 승인·배포 상태를 추적하는 관리 저장소.
- **데이터 드리프트(Data Drift):** 운영 입력 데이터의 분포가 학습 데이터의 분포와 달라지는 현상.
- **훈련-서빙 스큐(Training-Serving Skew):** 학습 시점과 운영 추론 시점의 입력 처리 차이.
- **CT(Continuous Training, 지속적 학습):** 정해 둔 데이터·성능 조건에 따라 학습·평가를 반복하는 운영 접근.

</details>

## 2~4교시 25점 답안
## Ⅰ. 개요
| 구분 | 핵심 |
|---|---|
| 정의 | **머신러닝 파이프라인**은 데이터 준비부터 모델 산출까지의 작업을 재현 가능한 단계로 연결한 실행 구조 |
| 목적 | 모델 개발·배포 작업의 반복성과 변경 이력 관리 |

## Ⅱ. 수명주기 흐름
```text
데이터 수집·검증
       |
       v
변환·특성 생성
       |
       v
모델 학습
       |
       v
평가·승인
       |
       v
배포·운영 감시
```

선행 조건과 재시도 가능한 작업은 DAG 등으로 정의. 파이프라인 전체 자동화 여부와 단계별 승인 방식은 위험·운영 요건에 따라 결정.

## Ⅲ. 구성과 추적성
| 단계·자산 | 주요 관리 내용 |
|---|---|
| 입력 데이터 | 출처, 시점, 스키마, 품질 검사 결과 |
| 변환·학습 코드 | 버전, 의존성, 파라미터, 실행 로그 |
| 모델 산출물 | 평가 지표, 데이터·코드 계보, 모델 버전 |
| 배포·감시 | 승인자, 배포 환경, 운영 지표, 롤백 이력 |

```text
입력 데이터 버전 + 코드·설정 버전
                 |
                 v
          파이프라인 실행 기록
                 |
                 v
     모델 버전·평가·승인 정보
                 |
                 v
          배포·운영 결과
```

이력 연결은 장애 분석과 재현에 도움. 로그와 산출물에 개인정보·비밀 정보가 포함되지 않도록 접근·보존 기준도 설정.

## Ⅳ. 검증·배포 통제
| 통제 지점 | 판단 내용 |
|---|---|
| 입력 검증 | 스키마·결측·범위 등 학습 전제 확인 |
| 모델 평가 | 업무에 맞는 지표·기준선·검증 자료 확인 |
| 승인·배포 | 승인 조건 충족 여부와 배포 범위 확인 |
| 운영 감시 | 데이터 변화·오류·성능 저하의 재검토 여부 |

운영 입력 분포의 변화는 데이터 드리프트, 예측과 실제 목표 관계의 변화는 개념 드리프트로 구분. 모니터링 신호만으로 자동 재학습·배포를 정당화하지 않고 데이터 적합성·평가·승인 조건을 함께 확인.

## Ⅴ. 자동화 수준과 적용 고려
| 실행 방식 | 적합한 상황 | 주의점 |
|---|---|---|
| 수동 승인 중심 | 초기 구축, 저빈도 학습, 높은 영향의 업무 | 반복 작업·검토 부담 |
| 단계 자동화 | 반복 가능한 입력 검증·학습·평가 | 실패 복구와 이력 추적 |
| 조건부 재학습 | 데이터·성능 조건이 정해진 운영 모델 | 대표성·품질·안전 검증 뒤 배포 |

CT는 파이프라인의 필수 속성이 아니라 재학습을 언제 실행할지 정한 운영 정책. 학습 자동화와 무인 배포는 별도로 판단.

## Ⅵ. 기술사적 제언
| 한계 | 해결 방안 |
|---|---|
| 실행 자동화만 앞서면 부적합 데이터나 검증되지 않은 모델이 운영에 전달될 위험 | 위험도에 맞는 입력 검사·독립 평가·승인 단계를 두고, 실패 시 이전 모델로 복구할 절차까지 실제 배포 전 검증 |
