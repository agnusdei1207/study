## 연관 키워드

- 머신러닝 파이프라인(Machine Learning Pipeline), MLOps(Machine Learning Operations), DAG(Directed Acyclic Graph)
- 피처 스토어(Feature Store), 훈련-서빙 스큐(Training-Serving Skew), 데이터 드리프트(Data Drift), 개념 드리프트(Concept Drift)
- CT(Continuous Training), 카나리 배포(Canary Deployment), 모델 레지스트리(Model Registry), 실험 재현성(Reproducibility), 계보(Lineage)

## Ⅰ. 머신러닝 파이프라인의 개요

- 핵심 요약 : 데이터 수집부터 배포와 모니터링까지를 자동화된 그래프로 묶어 재현성과 반복 배포를 보장하는 실행 체계.
- 개념 : 원천 데이터의 수집과 가공, 모델 학습, 검증, 배포, 사후 모니터링 단계를 모듈화해 **방향성 비순환 그래프**(DAG, Directed Acyclic Graph, 순환 없이 단계 간 의존성을 표현한 구조)로 연결한 **머신러닝 파이프라인**(Machine Learning Pipeline). 이를 운영 전반에 적용하는 방식을 **MLOps**(Machine Learning Operations, 모델 개발과 운영을 연결하는 실행 체계)라고 한다.
- 배경 및 필요성 : 코드만 자동화해서는 학습 때와 서빙 때 피처 계산이 어긋나는 **훈련-서빙 스큐**(Training-Serving Skew)나, 시간이 지나며 입력 분포가 바뀌는 **데이터 드리프트**(Data Drift)로 인한 성능 저하를 막을 수 없다. 따라서 피처의 출처를 추적하는 계보(Lineage) 관리와 분포 변화를 감시하는 체계를 함께 갖춰야 한다.
- 주요 목적 : 데이터 과학자의 수작업 반복 실험을 줄이고, **실험 재현성**(Reproducibility, 같은 조건이면 같은 결과를 얻는 성질)을 확보하며, **지속적 통합·배포·학습**(CI(Continuous Integration)/CD(Continuous Delivery)/CT(Continuous Training))을 달성하는 것.

## Ⅱ. 머신러닝 파이프라인의 특징 및 장점

- 핵심 요약 : 데이터 검증, 피처 공유, 모델 등록, 점진 배포가 자동 관문으로 이어져 단계마다 품질을 걸러내는 구조.

1. **피처 스토어**(Feature Store, 학습과 서빙이 같은 피처 정의를 공유하는 중앙 저장소) : 온라인과 오프라인 피처를 한곳에서 관리 → 훈련-서빙 스큐 방지.
2. **데이터 검증**(Data Validation, 스키마 일치, 결측치, 이상치를 점검하는 단계) : 잘못된 데이터가 학습에 들어가기 전에 차단 → 모델 오염 예방.
3. **모델 레지스트리**(Model Registry, 학습된 모델의 버전과 평가 결과를 등록하는 저장소) : 승인된 모델만 배포 후보가 됨 → 배포 이력 추적 가능.
4. **카나리 배포**(Canary Deployment, 일부 트래픽만 새 모델로 보내며 점진 확대하는 배포) : 특정 집단의 성능 저하를 소량 트래픽에서 조기에 발견.

## Ⅲ. 머신러닝 파이프라인의 구조 (흐름)

- 핵심 요약 : 데이터, 학습, 배포, 모니터링이 순서대로 이어지고, 모니터링의 드리프트 감지가 재학습을 다시 시작시키는 순환 구조.
- **개념 드리프트**(Concept Drift, 입력과 정답의 관계 자체가 바뀌는 현상) : 입력 분포가 같아도 예측이 틀어지므로 정답 기반 성능 감시가 필요함.

```text
[ MLOps 엔드투엔드 파이프라인 ]

1단계 데이터 엔지니어링
   ↓ 피처 스토어 저장
2단계 모델 CI
   ↓ 코드 빌드, 단위 테스트, 데이터 검증
3단계 자동 학습과 하이퍼파라미터 탐색
   ↓ 분산 학습 DAG 실행
4단계 평가와 거버넌스
   ↓ 임계 성능 통과 시 레지스트리 승인
5단계 모델 CD
   ↓ 카나리 배포
6단계 모니터링과 CT 루프
```

```text
[ 지속적 학습 루프 ]

프로덕션 추론 로그 수집
   ↓ 통계적 드리프트 분석
드리프트 또는 정확도 하락 감지
   ↓ 재학습 DAG 자동 트리거
신규 데이터 결합 후 학습 재가동
   ↓ 평가 통과 시 카나리 배포
프로덕션 반영
```

## Ⅳ. 머신러닝 파이프라인의 비교

- 핵심 요약 : 전통적 소프트웨어 CI/CD는 코드 변경이 핵심이지만, 머신러닝은 데이터와 모델까지 변경 대상이 되어 운영 방식이 달라진다.

| 비교 축 | 전통적 소프트웨어 CI/CD | 머신러닝 CI/CD/CT |
| --- | --- | --- |
| 변경 관리 대상 | 소스코드 | 코드, 데이터, 모델 파라미터 |
| 테스트 범위 | 단위 테스트, 통합 테스트 | 데이터 스키마 검증, 성능 지표, 편향성 검사 |
| 배포 산출물 | 실행 파일 또는 컨테이너 이미지 | 모델 가중치, 전처리 로직, 서빙 런타임 |
| 품질 저하 원인 | 소프트웨어 결함, 인프라 장애 | 환경 변화에 따른 데이터 드리프트 |

- 선택 기준 : 데이터 변화가 잦은 서비스일수록 CT 루프와 드리프트 감시의 비중을 높이고, 변화가 드문 서비스는 레지스트리와 배포 통제에 집중한다.

## Ⅴ. 머신러닝 파이프라인의 한계와 방안

- 핵심 요약 : 훈련-서빙 불일치, 데이터 분포 변화, 재학습 모델의 세그먼트 급락을 피처 저장소, 통계 감시, 카나리 배포로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 훈련-서빙 스큐 | 학습 시 피처 계산 로직과 서빙 로직이 달라 예측 결과가 어긋남 | 온라인과 오프라인 피처 저장소를 일원화해 단일 원천을 강제 | 학습과 서빙 피처 값의 불일치율 |
| 데이터 드리프트 | 시장과 환경 변화로 입력의 통계 분포가 서서히 변함 | 콜모고로프-스미르노프(KS, Kolmogorov-Smirnov) 검정과 PSI(Population Stability Index)를 상시 감시하고, 임계치 초과 시 알림과 재학습 연계 | 검정 통계량, PSI 추이 |
| 재학습 모델의 세그먼트 급락 | 신규 모델이 특정 집단에서 성능이 폭락해 전면 배포 시 장애 발생 | 일부 트래픽만 라우팅하는 카나리 배포와, 이상 감지 시 이전 모델로 즉시 되돌리는 서킷 브레이커 | 세그먼트별 정확도, 롤백 소요 시간 |

## Ⅵ. 머신러닝 파이프라인에 대한 기술사적 제언

- 핵심 요약 : 모델 배포를 일회성 작업이 아닌 상시 운영 체계로 전환하는 것이 파이프라인 투자의 핵심.

1. 데이터 과학 조직은 실험 설정, 데이터 해시, 컨테이너 이미지를 함께 기록하는 규칙을 공통으로 따라, 누구든 같은 결과를 재현할 수 있도록 해야 한다.
2. 인프라 조직은 학습 클러스터와 서빙 환경을 표준 템플릿으로 제공해, 모델마다 배포 절차가 달라지지 않도록 해야 한다.
3. 운영 조직은 드리프트 감시 지표와 롤백 기준을 서비스 수준 목표로 정해, 장애가 난 뒤 수습하는 방식에서 벗어나야 한다.

## Ⅶ. 결론

- 핵심 요약 : 머신러닝 파이프라인은 데이터와 모델의 변화를 감시하고 재학습과 배포까지 잇는 MLOps의 실행 체계임.
- 시사점 : 장기 운영의 품질은 모델 정확도보다 재현성과 변화 감지 능력에서 갈리므로, 파이프라인을 기능이 아닌 운영 기반으로 설계해야 한다.
