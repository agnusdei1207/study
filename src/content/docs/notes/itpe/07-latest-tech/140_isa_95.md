 ┃
 ┣━ Ⅰ 개요 ───── 사무실의 전사적 자원관리(ERP)와 공장 바닥의 제조실행(MES) 간 데이터 포맷 및 통신 단절(IT-OT 갭) → 기업-제어 시스템 통합을 위한 ISA-95(IEC 62264) 태동

 ┣━ Ⅴ 비교 ───── ISA-88 vs ISA-95 (공장 내부 배치 설비 제어 및 레시피 표준 vs 공장 제어 시스템(MES)과 기업 경영(ERP) 간의 수직적 통합 인터페이스)
 ┗━ Ⅵ 실무 ───── 수직적 계층 구조에 따른 데이터 사일로 및 전송 지연 / 스마트 공장 IIoT 전환 시 통일 네임스페이스(UNS)와의 구조적 충돌

## 한 줄 본질
- 사무실의 ERP(월·주 단위 경영 계획)와 공장 기계의 PLC(밀리초 단위 모터 회전)는 말하는 언어와 시간 개념이 완전히 달라 대화가 안 됨 → 그 중간에 MES(분·초 단위 제조운영)를 두고 공장과 사무실이 표준 단어(B2MML)로 소통하도록 5개 계층으로 정리한 스마트 제조의 헌법 / 클라우드 IIoT 시대에는 다단계 계층이 병목

## 핵심 그림
```text
[ISA-95 / 퍼듀(Purdue) 모델 5계층 아키텍처 및 MOM 4대 운영 영역]

  [Level 4: 기업 경영 (Business Planning & Logistics)] - (수개월 ~ 수일)
   - ERP, SCM, CRM (생산 계획, 자재 발주, 고객 주문)
  ──────────────────────────────┬────────────────────────────── (B2MML 인터페이스)
  [Level 3: 제조 운영 관리 (MOM / MES)] - (수일 ~ 수분)
   ┌─────────────────────────────────────────────────────────┐
   │ ① 생산 운영 관리(Production)   ② 유지보수 관리(Maintenance) │
   │ ③ 품질 운영 관리(Quality)      ④ 재고 운영 관리(Inventory)   │
   └────────────────────────────┬────────────────────────────┘
  ──────────────────────────────┼────────────────────────────── (OPC UA / 산업용 이더넷)
  [Level 2: 감독 제어 (Supervisory Control)] - (수초 ~ 밀리초)
   - SCADA, HMI, DCS (실시간 프로세스 감시 및 화면 표출)
  ──────────────────────────────┼──────────────────────────────
  [Level 1: 단위 제어 (Sensing & Manipulation)] - (밀리초)
   - PLC, RTU, 센서, 서보모터 액추에이터
  ──────────────────────────────┼──────────────────────────────
  [Level 0: 물리 공정 (Physical Process)]
   - 실제 용접, 조립, 화학 반응, 컨베이어 이송 공정
```

## 핵심 용어
- 퍼듀 모델(Purdue Model): 산업 제어 시스템을 Level 0(물리 공정)부터 Level 4(기업 경영)까지 5개 계층으로 분리하고 계층 간 보안 경계와 데이터 흐름을 정의한 아키텍처
- B2MML(Business to Manufacturing Markup Language): ISA-95 객체·거래 모델을 XML 스키마로 구현한 규격. JSON 표현은 별도 구현으로 구분
- MOM(Manufacturing Operations Management): Level 3에 위치하며 생산(Production), 유지보수(Maintenance), 품질(Quality), 재고(Inventory)의 4대 필수 공장 운영 활동을 총괄하는 광의의 MES 프레임워크

## 핵심 통찰
- "시간 단위(Time Scale)의 불일치를 해소하는 버퍼": ERP는 '이번 달 1만 대 생산'을 기획하고, PLC는 '지금 10ms 동안 밸브를 열어라'를 명령함 → 이 거대한 시간 격차를 중간에서 '오늘 8시간 근무조 동안 A라인에서 200대 조립'으로 쪼개주는 완충 계층이 바로 ISA-95의 Level 3임
- ISA-95의 자원·운영 모델: 인력·장비·자재·공정 구간 등의 정보를 교환하는 모델을 정의. 실제 ERP·MES 항목 매핑은 시스템별 마스터 데이터 조정이 필요
- ISA-95 계층은 기능·정보 교환을 분류하는 모델이며 모든 데이터를 단계별로 중계해야 한다는 뜻은 아님. MQTT 기반 통합 네임스페이스는 별도의 통신 아키텍처로 설계 가능

## 이웃 토픽과 구분
- ISA-88 vs ISA-95: ISA-88은 단일 배치 반응기 설비 제어(수평적 배치 제어) / ISA-95는 공장 바닥의 제어 시스템과 상위 기업 IT(ERP) 간의 수직적 통합(Vertical Integration)

## 문제·원인·대책
- 아래 사례의 조건·수치는 가상 예시이며 실제 성과가 아님.
- 적용 상황: 글로벌 자동차 부품 공장의 SAP ERP와 공장 설비 PLC 간 실시간 데이터 연동
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| ERP 생산 지시가 현장 MES에 도달하지 못해 생산 실적 수기 집계 | 시스템 간 정보 모델과 식별자 불일치 | ISA-95 정보 모델에 맞춘 필드 매핑과 B2MML XML 스키마 기반 연계 검토 | 지시·실적의 누락률과 전송 지연 측정 |
| 현장 작업자가 유지보수를 위해 PLC 프로그램을 수정하다가 품질 검사 DB가 엉킴 | 생산(Production)과 유지보수(Maintenance) 운영 영역 간의 경계 침범 | ISA-95 MOM 4대 기능 분리 원칙에 따른 모듈화 및 작업 권한 격리 | 공정 간섭 에러 제로화 |
| 제어망(Level 2)의 랜섬웨어 감염이 기업 전산망(Level 4)으로 전파 | 계층 간 경계·접근 통제 부족 | 네트워크 구역·통신 경로를 정의하고 산업 보안 요구에 따라 DMZ·감시 통제 설계 | 전파 경로 축소와 복구 절차 검증 |

## 1교시 예상문제 (10점)
- ISA-95의 목적과 기업·제조 통합 계층을 설명하시오.

## 1교시 10점 답안
- **정의:** 기업 계획 시스템과 제조 운영 시스템 사이의 기능·정보 교환을 공통 모델로 정리한 표준.
- **계층:** 수준 4 기업 계획·물류, 수준 3 제조 운영 관리, 수준 2 이하 감독 제어·공정 제어.
- **정보:** 생산 일정·성과·자원·품질 정보를 업무 필요에 맞게 교환하며 특정 전송 순서를 강제하지 않음.

## 2~4교시 예상문제 (25점)
- ISA-95의 기능 계층과 정보 흐름을 설명하고 ISA-88과 비교하시오.

## 2~4교시 25점 답안
### Ⅰ. 통합 목적
- ERP의 계획과 MES/MOM의 현장 실행 사이 용어·책임·정보를 일치시키는 기준.
### Ⅱ. 계층과 기능
- 수준 4의 사업 계획·자원, 수준 3의 생산·품질·정비·재고 운영, 수준 2 이하의 설비 감독·제어.
### Ⅲ. 교환 정보
- 생산 요청과 일정, 자원 가용성, 생산 실적·품질 결과를 교환. B2MML은 이를 표현할 수 있는 XML 스키마의 한 구현.
### Ⅳ. ISA-88 비교
- ISA-95는 기업·제조 기능 통합, ISA-88은 배치 절차·레시피·설비 제어 중심. 시스템 경계·식별자·시간 기준의 매핑 검증.
