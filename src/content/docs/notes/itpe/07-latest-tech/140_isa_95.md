## Ⅰ. ISA-95 기업·제조 통합의 개요

- 개념 : **기업 비즈니스 계획 시스템** (ERP/SCM, Level 4)과 공장 현장 **제조 운영 관리 시스템** (MES/MOM, Level 3) 간의 기능 경계와 데이터 교환을 표준화한 **국제 규격** (IEC(International Electrotechnical Commission) 62264).
- 배경 및 필요성 : ERP(Enterprise Resource Planning)의 재무·계획 주기(배치/일 단위)와 MES(Manufacturing Execution System)의 현장 실시간 트랜잭션 간 시차로 재고 정합성 불일치가 발생하므로 **공통 객체 모델** (B2MML) 기반의 **이벤트 드리븐** 실시간 연계 및 조정(Reconciliation) 파이프라인 구축 필요.
- 핵심 목적 : IT(Information Technology) 영역과 OT(Operational Technology) 영역 간 정보 단절 해소, 이기종 시스템 통합 비용 절감 및 실시간 제조 가시성 확보.

## Ⅱ. ISA-95 기업·제조 통합의 핵심 아키텍처 및 동작 메커니즘

ISA(International Society of Automation)-95 기업·제조 통합은 신뢰할 수 있는 데이터 파이프라인과 고도화된 추론 메커니즘을 기반으로 동작하며, 세부적인 아키텍처와 핵심 컴포넌트 간 상호작용 프로세스는 다음과 같음.

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ ISA-95 기반 기업-제조 수직 통합 및 B2MML 메시지 파이프라인 ]         │
└────────────────────────────────────────────────────────────────────────┘

  [ Level 4: 전사 기업 시스템 (ERP / SCM) ]
   - 수주 관리, 생산 계획(MPS), 마스터 데이터(BOM, Routing), 전사 자재 발주
             │
             │  B2MML (Production Schedule / Material Requirement)
             ▼
  [ Level 3: 제조 운영 관리 (MES / MOM) ]
   ├── 생산 관리 (Production)  : 작업 지시 발행, 라인 디스패칭
   ├── 유지보수 (Maintenance) : 설비 예방점검, 고장 이력 관리
   ├── 품질 관리 (Quality)     : 인라인 검사, SPC, 부적합품 격리
   └── 재고 관리 (Inventory)   : 재공품(WIP) 추적, 로트(Lot) 추적성
             │
             │  OPC UA / 산업용 이더넷 (Process Parameter / State)
             ▼
  [ Level 0~2: 현장 제어 및 물리 설비 (DCS / SCADA / PLC / Sensor) ]
   - 연속/배치 공정 실행, 실시간 피드백 루프, 센서 텔레메트리 스트리밍
```

- **기능 계층 모델** (Functional Hierarchy) : Level 4(ERP), Level 3(MOM), Level 2(DCS/SCADA(Supervisory Control and Data Acquisition)), Level 1(PLC(Programmable Logic Controller)/센서), Level 0(물리 공정) - IT와 OT의 책임 경계를 명확히 분리하고 인터페이스 표준 제공.
- **MOM 4대 기능 범주** : 생산(Production), 유지보수(Maintenance), 품질(Quality), 재고(Inventory) - Level 3 내부에서 세부 일정 계획, 실행 지시, 데이터 수집 및 추적 수행.
- **제조 자원 4대 객체** : 인력(Personnel), 설비(Equipment), 자재(Material), 공정 세그먼트(Process Segment) - 제조에 투입되는 유무형 자원의 능력(Capability)과 실적(Actual)을 정형화.

## Ⅲ. ISA-95 기업·제조 통합의 세부 구성 요소 및 비교 분석

| 비교 항목 | ISA-95 (Enterprise-Control Integration) | ISA-88 (Batch Control) |
|---|---|---|
| **중점 목표** | 기업 업무(ERP)와 제조 현장(MES) 간 데이터 교환 표준화 | 현장 배치 설비 제어 로직 모듈화 및 레시피 실행 |
| **적용 계층** | 주로 Level 3(MOM)과 Level 4(ERP)의 경계 영역 | 주로 Level 1~2(PLC/DCS) 및 Level 3(배치 엔진) 영역 |
| **주요 모델** | 객체 모델(자재, 인력, 설비), 트랜잭션 메시지 모델 | 물리 모델, 절차 모델, 레시피 모델(Master/Control) |
| **데이터 표현** | B2MML (XML(Extensible Markup Language)/JSON(JavaScript Object Notation) 기반 구조화 메시지) | IEC 61131-3, SFC, 상태 전이도(State Machine) |
| **상호 연동** | Production Schedule을 ISA-88 측에 전달 | Production Schedule이 Master Recipe 구동 입력으로 변환되어 현장 실행 |

- ISA-95 기업·제조 통합은 상기 비교 지표를 바탕으로 비즈니스 요구사항과 운영 인프라 환경을 고려한 최적의 아키텍처를 선정하고, 확장성과 안정성을 균형 있게 확보해야 함.

## Ⅳ. ISA-95 기업·제조 통합의 주요 한계점 및 해결 방안

- 이종 시스템(ERP-MES) 간 데이터 동기화 주기 불일치 :
  - 한계점 : 배치 기반 ERP와 실시간 스트리밍 MES 간의 데이터 처리 주기 불일치로 WIP(Work in Progress) 재고 수량 오차 발생.
  - 해결 방안 : 카프카(Kafka) 기반 이벤트 드리븐 아키텍처(EDA, Electronic Design Automation) 도입 및 트랜잭션 아웃박스 패턴 기반 실시간 동기화.
- 레거시 PLC 프로토콜 및 데이터 모델 변환 오버헤드 :
  - 한계점 : 플랜트 현장의 수많은 레거시 PLC 및 비표준 프로토콜로 인해 ISA-95 표준 데이터 모델 변환 오버헤드 급증.
  - 해결 방안 : 에지 컴퓨팅 게이트웨이 도입 및 OPC(Open Platform Communications) UA(Unified Architecture) 정보 모델(Information Model) 기반의 데이터 가상화 계층 구축.
- IT-OT 융합에 따른 현장 제어 시스템 보안 위협 노출 :
  - 한계점 : IT-OT 네트워크 통합에 따른 현장 제어 시스템(Level 1~2)의 사이버 공격 노출 위험 증가.
  - 해결 방안 : IEC 62443 표준 기반의 DMZ(Zone & Conduit) 망 분리 및 일방향 보안 게이트웨이 적용.

## Ⅴ. ISA-95 기업·제조 통합 적용 및 발전을 위한 기술사적 제언

- 연계 구조 고도화 및 단일 메시지 브로커를 추진 : ERP ↔ MES ↔ SCADA 수직 계단식 인터페이스의 한계를 탈피하고, 단일 메시지 브로커(MQTT/Kafka)를 통한 Pub/Sub를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- 데이터 모델 고도화 및 ISA-95 기반 공통 추진 : 시스템마다 독자적인 테이블 구조 및 데이터 맵핑의 한계를 탈피하고, ISA-95 기반 공통 의미 구조(ISA-95 Hierarchy Namespace)를 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- 확장성 고도화 및 토픽 구독만으로 신규 추진 : 신규 설비 도입 시 상위 계층 전면 인터페이스 수정의 한계를 탈피하고, 토픽 구독만으로 신규 시스템 즉시 연동 가능을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
