## 30초 인출

- 본질: **버티컬 AI (Vertical AI)** 는 의료, 법률, 금융, 제조 등 특정 산업 도메인의 전문 지식, 독점 데이터셋 및 고유 업무 워크플로우에 완벽히 밀착하여 엔드투엔드 문제 해결을 제공하는 산업 특화형 AI 솔루션
- 메커니즘: 도메인 전문 비정형 데이터 정제 및 지식 그래프 구축 → 소형 도메인 특화 모델(SLM) 파인튜닝 및 고정밀 RAG 결합 → 기간계 레거시 시스템 연계 인터페이스를 통한 전문 작업 자동화
- 통찰: 범용 파운데이션 모델의 지속적 진화로 인한 도메인 해자(Moat) 잠식 위협이 존재하므로 독점 데이터 파이프라인 기반의 데이터 플라이휠과 전사 워크플로우 락인(Lock-in) 체계 구축 필수

<details><summary>핵심 용어</summary>

- **버티컬 AI (Vertical AI)** : 범용 다목적 모델과 대비되어 특정 산업군의 규제, 용어, 업무 프로세스에 깊게 특화된 인공지능 소프트웨어.
- **호라이즌탈 AI (Horizontal AI)** : 번역, 요약, 일반 검색 등 특정 산업에 구애받지 않고 전 산업에 걸쳐 범용적으로 쓰이는 수평적 AI.
- **데이터 플라이휠 (Data Flywheel)** : 사용자의 전문 업무 인터랙션 데이터가 솔루션으로 재유입되어 모델의 도메인 정확도를 지속적으로 복리 개선하는 선순환 구조.
- **도메인 특화 SLM (Specialized SLM)** : 법률, 의료 등 특정 영역의 코퍼스만을 집중 학습하여 경량 인프라에서 초고정밀 추론을 수행하는 소형 언어모델.
- **워크플로우 락인 (Workflow Lock-in)** : 단순 질의응답을 넘어 기업의 실제 기안, 승인, 시스템 입력 작업 전반을 자동화하여 교체 비용을 극대화하는 전략.

</details>

## 2~4교시 예상문제 (25점)

> 최근 범용 AI(Horizontal AI)의 한계를 극복하고 산업별 전문성을 무기로 급부상하는 버티컬 AI(Vertical AI)의 개념, 아키텍처 계층 구조 및 핵심 성공 요인을 설명하고, 호라이즌탈 AI와의 비교 및 기업 실무 적용 시 직면하는 엔지니어링 한계와 해결 방안을 논하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. 버티컬 AI의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **버티컬 AI** 는 특정 산업 및 직무(의료 진단, 판례 분석, 반도체 결함 검사 등)에 특화된 독점 데이터와 비즈니스 워크플로우를 결합하여 전문 과업을 종단간 해결하는 수직형 인공지능 시스템 |
| 목적 | 범용 LLM의 도메인 환각 및 규제 미준수 한계를 해소하고 고부가가치 전문 직무의 업무 생산성 극대화 |

## Ⅱ. 버티컬 AI의 핵심 계층 구조 및 특징

| 아키텍처 계층 | 세부 구성요소 | 도메인 특화 특징 |
|---|---|---|
| **도메인 데이터 계층** | 전자의무기록(EMR), 판결문, 금융 공시, CAD 도면 | 일반 웹 크롤링으로는 접근 불가능한 고품질 독점 데이터 파이프라인 구축 |
| **특화 모델 및 지식 계층** | 도메인 파인튜닝 SLM + 하이브리드 RAG + 온톨로지 | 의학 용어, 법률 조항 등 전문 어휘 사전 구축 및 지식 그래프 기반 추론 |
| **워크플로우 통합 계층** | ERP, CRM, 병원 HIS, 로펌 판례 검색기 연동 API | 단순 대화창을 넘어 현업 소프트웨어의 양방향 자동 입력 및 트랜잭션 완결 |
| **컴플라이언스·보안 계층** | HIPAA, GDPR, 금융망분리 규제 준수 모듈 | 데이터 암호화, PII 마스킹 및 전용 온프레미스/VPC 격리 서빙 |

## Ⅲ. 버티컬 AI의 엔드투엔드 도메인 지식 구축 및 서비스 체계

```text
┌────────────────────────────────────────────────────────────────────────┐
│             버티컬 AI (Vertical AI) 엔터프라이즈 솔루션 구조            │
└────────────────────────────────────────────────────────────────────────┘
 [ 특정 산업 독점 데이터 원천 (EMR, 사내 계약서, 정밀 계측기 로그) ]
                               │
                               ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 도메인 데이터 파이프라인 (Data Cleansing & Grounding)                 │
 │  - 전문 용어 토크나이저 구축, 비식별 조치, 도메인 온톨로지 구축      │
 └─────────────────────────────┬────────────────────────────────────────┘
                               │
                               ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 듀얼 하이브리드 추론 코어 (Dual Hybrid Engine Core)                   │
 │  ┌───────────────────────────────┐  ┌──────────────────────────────┐ │
 │  │ 도메인 파인튜닝 모델 (Specialized) │  │ 도메인 하이브리드 RAG (Knowledge)│ │
 │  │ - Llama-3-8B 의료/법률 LoRA   │  │ - 법령/약관/최신 지침 벡터 DB │ │
 │  └──────────────┬────────────────┘  └──────────────┬───────────────┘ │
 │                 │                                  │                 │
 │                 └────────────────┬─────────────────┘                 │
 │                                  ▼                                   │
 │                  [ 고신뢰 추론 및 초안 생성 ]                       │
 └──────────────────────────────────┬───────────────────────────────────┘
                                    │
                                    ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 현업 워크플로우 락인 계층 (In-Workflow Action)                        │
 │  - EMR 처방 자동 기표, 로펌 소장 자동 작성, 회계 ERP 분개 전표 생성  │
 └──────────────────────────────────┬───────────────────────────────────┘
                                    │ 사용자 피드백 (수정 내역)
                                    ▼
                 [ 데이터 플라이휠: 모델 지속적 재학습 순환 ]
```

| 운영 프로세스 단계 | 핵심 수행 내용 | 성공 판단 기준 |
|---|---|---|
| **독점 데이터 수집** | 외부 비공개 기업 내부 문서 및 전문 라이선스 DB 확보 | 데이터 독점성 및 저작권 적법성 |
| **특화 튜닝 및 RAG** | 도메인 특화 토크나이저 확장 및 사실 검증 검색 결합 | 도메인 벤치마크 정확도 95% 이상 |
| **인-워크플로우 임베딩** | 전문가가 매일 사용하는 업무 화면(UI) 내에 플러그인 통합 | 사용자 일일 활성 사용률(DAU) |
| **피드백 플라이휠** | 전문가의 수정/반려 내역을 DPO 선호 데이터로 자동 가공 | 주간/월간 모델 성능 자동 개선율 |

## Ⅳ. AI 솔루션 유형 비교 (호라이즌탈 AI vs 버티컬 AI)

| 비교 항목 | 호라이즌탈 AI (Horizontal AI) | 버티컬 AI (Vertical AI - 본 토픽) |
|---|---|---|
| **목표 시장** | 전 산업군, 일반 대중, 범용 직무 | 특정 산업 (의료, 법률, 금융, 건설 등) |
| **핵심 기술** | 초대형 범용 파운데이션 모델 (GPT-4) | 도메인 특화 경량 SLM + 전문 RAG |
| **데이터 원천** | 인터넷 공개 웹 문서, 공용 코퍼스 | 기업 내부 독점 데이터, 폐쇄형 전문 DB |
| **비즈니스 해자 (Moat)** | 막대한 자본력, 초거대 컴퓨팅 인프라 | 독점 데이터 파이프라인, 깊은 업무 락인 |
| **규제 대응** | 일반적 안전 가이드라인 | HIPAA, 금융보안원 가이드 등 엄격 규제 준수 |
| **가격 정책** | 토큰당 과금 또는 범용 월 구독제 | 사용자당 고가 B2B SaaS 라이선스 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 빅테크의 차세대 범용 파운데이션 모델 추론 성능 향상으로 인한 버티컬 솔루션의 기술적 우위 상실 위협 | 단순 프롬프트 래퍼(Wrapper)를 탈피하여 고객사의 기간계 DB와 깊게 연계된 복합 워크플로우 실행 에이전트 구축 |
| 산업별 전문가들의 높은 신뢰도 요구 수준 대비 간헐적 환각 발생 시 치명적 의료사고 및 법적 분쟁 초래 | 법조문 및 임상 가이드라인 원문 조항을 1:1로 하이라이트 매핑하는 설명가능한 근거 제시(Citation) 강제 |
| 폐쇄적인 산업 도메인 특성상 고객사들이 데이터 외부 반출을 극도로 꺼려 학습 데이터 확보 애로 | 연합학습(Federated Learning) 및 고객사 VPC 내 폐쇄형 온프레미스 인스턴스 배포 아키텍처 지원 |

## Ⅵ. 제언

범용 빅테크 모델의 공세를 방어하고 지속 가능한 해자(Moat)를 구축하기 위해 독점 데이터 플라이휠과 전사 업무 락인을 결합한 버티컬 풀스택(Full-Stack) 생태계 구축 권고.

```text
[ 버티컬 AI 솔루션 도입 고객사 ]
             │
             ▼
┌────────────────────────────────────────────────────────┐
│ 전사 업무 시스템 락인 (System of Record 침투)          │
│  - 진료 차트, 회계 장부, 법원 전자소송 시스템 직결    │
└────────────────────────────┬───────────────────────────┘
                             │
                             ▼
┌────────────────────────────────────────────────────────┐
│ 전문가 피드백 루프 (Expert-in-the-Loop)                │
│  - 전문의/변호사의 AI 생성물 검토 및 수정 클릭 스트림  │
└────────────────────────────┬───────────────────────────┘
                             │ 고품질 정답 레이블 자동 생성
                             ▼
┌────────────────────────────────────────────────────────┐
│ 지속적 모델 고도화 플라이휠 (Self-Improving Engine)     │
│  - 경쟁사가 절대 복제할 수 없는 독점 선호 데이터 축적 │
└────────────────────────────────────────────────────────┘
```

| 구분 | 단순 프롬프트 래퍼 서비스 | 제언: 버티컬 풀스택 솔루션 |
|---|---|---|
| **기술적 독자성** | 상용 LLM API 단순 호출 | 독점 파인튜닝 모델 + 특화 RAG |
| **고객 전환 비용** | 매우 낮음 (타 서비스 즉시 교체 가능) | 극도로 높음 (업무 프로세스 일체화) |
| **데이터 방어벽** | 공개 데이터 의존으로 해자 없음 | 전문가 수정 데이터의 지속적 축적 |
| **수익성** | API 재판매 마진 잠식 | 높은 B2B 엔터프라이즈 마진 확보 |
