## 30초 인출
- **본질:** 버티컬 AI는 특정 산업이나 전문 업무에 맞춰 데이터·기능·업무 흐름을 설계한 AI 제품·서비스를 뜻한다.
- **메커니즘:** 도메인 자료와 시스템을 연결하고, 현업 절차 안에서 결과를 검증·사용한다.
- **차별점:** 전문성은 모델만이 아니라 데이터 권리·품질, 업무 통합, 신뢰와 운영에서 나온다.

## 1교시 10점 답안
### 1. 정의·목적
정의: 버티컬 AI는 특정 산업이나 전문 업무에 맞춰 설계한 AI 제품·서비스다.
목적: 도메인 지식과 업무 흐름에 맞는 기능을 제공해 전문 과업을 지원한다.

### 2. 구성과 가치
| 구성 | 역할 |
|---|---|
| 도메인 데이터·지식 | 전문 용어와 업무 맥락 제공 |
| 모델·도구 | 분류·생성·검색 등 필요한 기능 수행 |
| 시스템·업무 절차 | 결과를 현업 작업과 검토에 연결 |
| 거버넌스 | 접근·품질·오류 책임을 관리 |

### 3. 도입 기준
특정 분야에 맞춘다는 사실만으로 정확성이나 법규 준수가 보장되지 않는다. 데이터 사용 권리와 품질, 실제 사용자 검토, 시스템 연계를 함께 확인한다.

**제언:** 모델 성능뿐 아니라 도메인 데이터 권리와 업무 적합성을 확인해 적용 범위를 정한다.

## 2~4교시 25점 답안
## Ⅰ. 개념과 범위
버티컬 AI는 특정 산업이나 전문 업무의 요구에 맞춘 AI 제품·서비스를 뜻한다. 범용 기반 모델을 활용할 수도 있고, 도메인 데이터·도구·업무 연계로 특화할 수도 있다. 반드시 별도 모델을 학습해야 하는 것은 아니다.

| 관점 | 호라이즌탈 AI | 버티컬 AI |
|---|---|---|
| 적용 범위 | 산업을 가로지르는 공통 과업 | 특정 산업·업무의 과업 |
| 설계 초점 | 범용 기능과 폭넓은 재사용 | 도메인 자료와 절차에 대한 적합성 |
| 평가 기준 | 다목적 성능·사용성 | 현업 정확성·통합성·위험 |

## Ⅱ. 구성 요소와 업무 연결
| 계층 | 주요 요소 | 연결 역할 |
|---|---|---|
| 도메인 기반 | 권리·품질을 확인한 데이터, 용어·규칙 | 업무 문맥과 근거 제공 |
| AI 기능 | 기반 모델, 검색, 도구, 필요한 특화 | 과업에 맞는 분석·생성 수행 |
| 업무 통합 | 현업 응용·기록 시스템, 사용자 화면 | 실제 작업 흐름에 결과 전달 |
| 운영·통제 | 접근 권한, 검토, 감사·모니터링 | 품질과 책임 관리 |

## Ⅲ. 차별화와 도입 과제
| 과제 | 고려사항 |
|---|---|
| 데이터 | 사용 권리, 민감 정보, 대표성, 최신성 |
| 정확성 | 도메인 평가셋, 근거 확인, 사람의 검토 |
| 통합 | 기존 업무 시스템, 데이터 형식, 장애 처리 |
| 운영 책임 | 오류 대응, 변경 관리, 감사 기록 |

버티컬 AI의 경쟁력은 독점 데이터만으로 결정되지 않는다. 신뢰할 수 있는 업무 통합과 현장 검증이 약하면 특화 모델도 실제 효용을 내기 어렵다.

## Ⅳ. 기술사적 제언
| 문제 | 해결 방안 |
|---|---|
| 특화 모델의 데모 성능이 실제 업무에서 재현되지 않거나 책임이 불명확함 | 현업 사례를 반영한 평가 기준과 데이터 권리 검토를 마련하고, 사용자 확인·기록·오류 대응을 갖춘 제한 적용부터 확대한다. |

- “버티컬 AI”는 산업별 AI 제품·서비스를 가리키는 시장 표현으로 사용하며, 단일 공식 아키텍처 정의는 전제하지 않았다.
