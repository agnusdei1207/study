## 연관 키워드

- 버티컬 AI(Vertical AI), 호라이즌탈 AI(Horizontal AI), 도메인 특화 모델, SLM(Small Language Model)
- RAG(Retrieval-Augmented Generation), 지식 그래프, 온톨로지, 데이터 플라이휠
- 워크플로우 락인(Lock-in), 도메인 해자(Moat), 연합학습(Federated Learning), 설명 가능한 근거 제시

## Ⅰ. 버티컬 AI의 개요

- 핵심 요약 : 특정 산업과 직무의 독점 데이터와 업무 흐름을 결합해 전문 과업을 끝까지 처리하는 수직형 AI 시스템.
- 개념 : 의료 진단, 판례 분석, 반도체 결함 검사처럼 특정 산업과 직무에 특화된 데이터와 워크플로우를 결합하여 전문 과업을 종단간으로 해결하는 **버티컬 AI**(Vertical AI).
- 배경 및 필요성 : 범용 파운데이션 모델의 성능이 계속 올라가면서 도메인 기업의 차별성이 잠식될 위험이 커졌다. 따라서 독점 데이터 파이프라인을 바탕으로 한 데이터 플라이휠과, 현업 시스템에 깊이 연결된 **워크플로우 락인**(Lock-in) 구조를 만드는 것이 필요하다.
- 주요 목적 : 범용 LLM의 도메인 환각과 규제 미준수 한계를 줄이고, 고부가가치 전문 직무의 생산성을 높이는 것.

## Ⅱ. 버티컬 AI의 특징 및 장점

- 핵심 요약 : 독점 데이터와 특화 모델, 현업 시스템 연동이 맞물려 대체하기 어려운 업무 결합력을 만드는 구조.

1. 독점 데이터 : 일반 웹에서 얻기 어려운 전자의무기록, 계약서, 계측 로그를 정제하여 학습과 검색에 사용 → 도메인 정확도 향상.
2. 특화 모델 : 소형 도메인 모델과 전문 RAG를 결합 → 범용 모델보다 낮은 비용으로 전문 용어와 규정을 다룸.
3. 워크플로우 통합 : 처방 기록, 전표, 판례 검색기 등 현업 소프트웨어에 직접 입력 → 대화창을 넘어 업무 완결 처리.
4. 피드백 순환 : 사용자가 고친 내역을 다시 학습 데이터로 축적 → 사용할수록 정확도가 높아지는 데이터 플라이휠.

```text
[ 데이터 플라이휠 ]

전문가 사용 (업무 실행)
   ↓
수정 내역 축적
   ↓
도메인 데이터 증가
   ↓
모델·검색 정확도 향상
   ↓
다시 전문가 사용
```

## Ⅲ. 버티컬 AI의 구조 (흐름)

- 핵심 요약 : 독점 데이터를 정제하는 파이프라인, 특화 모델과 지식 검색을 결합한 추론 코어, 현업 시스템에 결과를 기입하는 계층이 순환하는 구조.
- **지식 그래프**(Knowledge Graph) : 개체와 관계를 연결해 전문 용어와 규정 간 관계를 표현하는 구조. 추론의 근거 정리에 쓰인다.
- **온톨로지**(Ontology) : 도메인 개념과 속성의 체계를 정의한 것으로, 지식 그래프 구축의 기반이 된다.

```text
[ 독점 데이터 원천 ]
EMR, 계약서, 계측 로그
        ↓
도메인 데이터 파이프라인
(정제, 비식별, 온톨로지 구축)
        ↓
추론 코어
(특화 SLM + 도메인 RAG)
        ↓
워크플로우 계층
(EMR 기표, ERP 분개 전표)
        ↓
사용자 수정 내역 → 재학습
```

## Ⅳ. 버티컬 AI와 호라이즌탈 AI의 비교

- 핵심 요약 : 호라이즌탈 AI가 범용 능력으로 넓게 쓰인다면, 버티컬 AI는 독점 데이터와 깊은 업무 결합으로 특정 산업에서 해자를 쌓는다.

| 비교 항목 | 호라이즌탈 AI (Horizontal AI) | 버티컬 AI (Vertical AI) |
| --- | --- | --- |
| 목표 시장 | 전 산업, 일반 사용자, 범용 직무 | 의료, 법률, 금융, 건설 등 특정 산업 |
| 핵심 기술 | 대형 범용 파운데이션 모델 | 도메인 특화 SLM과 전문 RAG |
| 데이터 원천 | 공개 웹 문서, 공용 코퍼스 | 기업 내부 독점 데이터, 폐쇄형 전문 DB |
| 비즈니스 해자 | 자본력과 대규모 컴퓨팅 인프라 | 독점 데이터 파이프라인, 깊은 업무 락인 |
| 규제 대응 | 일반적 안전 지침 | 산업별 엄격 규제 준수 (예: 의료 정보 보호, 금융 보안 가이드) |

- 선택 기준 : 업무가 범용 질의응답인지, 산업 규제와 독점 데이터 활용이 필요한지에 따라 방식을 고른다.

## Ⅴ. 버티컬 AI의 한계와 방안

- 핵심 요약 : 범용 모델의 성능 추격, 전문 분야의 치명적 오류, 데이터 반출 기피를 업무 깊이 확보, 근거 인용, 연합 학습으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 범용 모델 성능 향상에 따른 우위 상실 | 단순 프롬프트 래퍼 구조 → 대체 용이 | 고객의 기간계 DB와 깊게 연계된 실행형 에이전트 구축 | 워크플로우 연동률 |
| 간헐적 환각에 따른 의료·법적 사고 | 전문가 신뢰 요구에 못 미치는 응답 → 사고와 분쟁 | 법조문·임상 지침 원문과 응답을 대응시키는 근거 인용 강제 | 근거 인용률, 전문가 수정률 |
| 데이터 반출 기피에 따른 학습 데이터 부족 | 고객사의 외부 반출 거부 → 학습 데이터 확보 곤란 | 연합학습 적용, 고객사 VPC 내 폐쇄형 배포 | 데이터 확보량, 배포 건수 |

## Ⅵ. 버티컬 AI에 대한 기술사적 제언

- 핵심 요약 : 범용 모델 호출에 머무르지 않고 독점 데이터와 업무 연동, 신뢰 체계를 쌓아 도메인 해자를 확보하는 방향.

1. 사업 부서가 고객사의 업무 흐름을 분석하여 대화 기능이 아닌 실제 기입과 완결까지 이어지는 과제를 우선 선정한다.
2. 데이터 조직이 고객사 승인 아래 전문가의 수정 이력을 체계적으로 축적하여 재학습에 쓰는 데이터 관리 정책을 세운다.
3. 법무·보안 조직이 산업별 규제 요건을 설계 단계에 반영하고, 폐쇄형 배포와 근거 추적을 기본 옵션으로 제공한다.

## Ⅶ. 결론

- 핵심 요약 : 버티컬 AI는 범용 모델의 능력을 특정 산업의 데이터와 업무 흐름에 맞춰 내재화한 수직형 시스템.
- 시사점 : 모델 성능보다 독점 데이터와 업무 결합의 깊이가 경쟁력을 결정하므로, 도입 기업은 데이터 접근권과 규제 준수 구조를 먼저 확보해야 한다.
