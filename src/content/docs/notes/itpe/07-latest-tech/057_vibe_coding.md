## 30초 인출

- 본질: **바이브 코딩(Vibe Coding)** 은 개발자가 로우 레벨 코드를 직접 한 줄씩 타이핑하지 않고 자연어로 고수준 의도(Vibe)와 요구사항을 제시하면 AI 에이전트가 코드 생성, 터미널 실행, 디버깅을 자율 수행하는 대화형 개발 패러다임
- 메커니즘: 자연어 의도 전달 → AI의 코드베이스 인덱싱 및 Diff 생성 → 터미널 샌드박스 자동 실행 및 에러 감지 → AI 자체 자가수정(Self-Debug) 루프 → 개발자 최종 검토 및 커밋
- 통찰: 구조적 이해 없는 맹목적 코드 수용은 기술 부채와 보안 취약점을 유발하므로 테스트 주도 개발(TDD) 기반 단위 테스트 통과 강제 및 자동화된 SAST 파이프라인 결합 필수

<details><summary>핵심 용어</summary>

- **바이브 코딩(Vibe Coding)** : 세부 문법보다 직관적인 분위기와 의도 지시에 집중하여 AI 에이전트와 페어 프로그래밍하는 새로운 개발 방식.
- **AI 코딩 에이전트(AI Coding Agent)** : 파일 읽기/쓰기, 터미널 명령어 실행, 코드 검색 도구를 갖추고 자율적으로 개발 태스크를 완수하는 인공지능.
- **에이전틱 루프(Agentic Loop)** : 문제 발생 시 AI가 에러 로그를 읽고 스스로 코드를 재수정하여 실행 성공할 때까지 반복하는 피드백 루프.
- **기술 부채(Technical Debt)** : 단기적 빠른 구현을 위해 아키텍처 원칙을 무시함으로써 향후 리팩토링 및 유지보수 비용이 급증하는 현상.
- **정적 애플리케이션 보안 테스트(SAST)** : 소스 코드를 실행하지 않고 잠재적 보안 취약점과 하드코딩된 자격증명을 탐지하는 자동화 검사.

</details>

## 2~4교시 25점 답안

## Ⅰ. 바이브 코딩(Vibe Coding)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **바이브 코딩(Vibe Coding)** 은 개발자가 세부적인 문법과 알고리즘 코드를 직접 작성하지 않고, LLM 기반 AI 에이전트에게 자연어로 의도(Vibe)와 제약 조건을 제시하며 AI가 작성·실행·디버깅한 결과를 반복 정제하는 소프트웨어 개발 패러다임 |
| 목적 | 전통적 코딩 문법 장벽 해소 및 개발 속도 극대화, 초고속 최소기능제품(MVP) 구현 및 개발자의 역할을 단순 코더에서 시스템 아키텍트·리뷰어로 전환 |

## Ⅱ. 바이브 코딩의 핵심 특징

| 구분 | 주요 특징 | 기술적 설명 및 메커니즘 |
|---|---|---|
| **상호작용** | 자연어 프롬프트 주도 | C, Java, Python 등 언어 문법 대신 자연어 요구사항과 설계 의도를 기반으로 소프트웨어 빌드 |
| **자율 실행** | 에이전틱 피드백 루프 | 코드를 작성한 후 샌드박스 터미널에서 컴파일·실행하고 에러 발생 시 로그를 분석해 자체 수정 |
| **맥락 인지** | 전사 코드베이스 RAG | 프로젝트 전체 디렉터리 구조, AST(추상 구문 트리), 종속성 그래프를 벡터화하여 프로젝트 일관성 유지 |
| **역할 전환** | 지휘관 겸 최종 검증자 | 개발자는 직접 타이핑 대신 아키텍처 방향 설정, 비즈니스 엣지 케이스 정의, 최종 PR 승인에 집중 |

## Ⅲ. 바이브 코딩의 아키텍처 및 에이전틱 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│             [ 바이브 코딩 에이전틱 자율 개발 및 검증 파이프라인 ]           │
└────────────────────────────────────────────────────────────────────────┘
      │
      ▼
 [ Step 1: 개발자 자연어 프롬프팅 ] ── "결제 모듈에 카카오페이 간편결제 연동 추가해줘"
      │
      ▼
 [ Step 2: 코드베이스 컨텍스트 RAG ] ─ 프로젝트 내 기존 결제 인터페이스 및 DB 스키마 검색
      │
      ▼
 [ Step 3: AI 코드 패치 생성 (Diff) ] ─ 신규 파일 생성 및 기존 컨트롤러/서비스 코드 수정
      │
      ▼
 [ Step 4: 로컬 샌드박스 터미널 실행 ] ─ `npm test` 또는 빌드 명령어 자동 트리거
      │
      ├─ 컴파일/테스트 에러 발생 시 ──┐
      │                               │ (에러 스택 트레이스 자동 수집)
      │                               ▼
      │                     [ 자가 디버깅 루프 (Self-Debug Loop) ]
      │                               │ (코드 수정 후 재실행)
      │                               ▲
      └─ 모든 테스트 통과 (Pass) ─────┘
      │
      ▼
 [ Step 5: 인간 검토 및 승인 (HITL) ] ─ 코드 변경점(Diff) 검토, 보안 스캔, Git Commit
```

| 프로세스 단계 | 엔지니어링 메커니즘 | 핵심 도구 및 기술 |
|---|---|---|
| **컨텍스트 수집** | 레포지토리 내 파일 트리 및 관련 심볼 임베딩 | Codebase Indexing, AST Parsing |
| **코드 생성·편집** | LLM 기반 Multi-File 일괄 패치 적용 | Cursor, Windsurf, Claude Code |
| **도구 실행(Tool-Use)** | CLI 쉘 권한을 통한 린트, 빌드, 테스트 자동화 | Local Subprocess Execution, Docker Sandbox |
| **자가 치유(Healing)** | 실패한 테스트 케이스를 프롬프트로 재투입 | Reflexion, Iterative Refinement |

## Ⅳ. 전통 개발, AI 어시스턴트, 바이브 코딩 비교

| 비교 항목 | 전통적 소프트웨어 개발 | AI 어시스턴트 (Copilot형) | 바이브 코딩 (Agentic형) |
|---|---|---|---|
| **코드 작성 주체** | 개발자가 100% 직접 수기 타이핑 | 개발자 타이핑 중 AI가 인라인 자동완성 | AI가 파일 단위 및 전체 프로젝트 작성 |
| **작업 단위** | 줄(Line) 및 함수 단위 | 함수(Function) 단위 자동 완성 | 기능(Feature) 및 프로젝트 전체 단위 |
| **디버깅 방식** | 개발자가 브레이크포인트 추적 | 개발자가 에러 검색 및 수정 | AI가 에러 터미널 로그 읽고 자체 수정 |
| **개발자 역할** | 구현자 (Coder) | 공동 작업자 (Pair Programmer) | 총괄 감독관 (Commander / Reviewer) |
| **개발 속도** | 기준선 (1x) | 1.5x ~ 2x 향상 | 5x ~ 10x 급속 프로토타이핑 |
| **기술 부채 위험** | 개발자의 숙련도에 따라 통제 | 비교적 통제 가능 | 검증 부재 시 스파게티 코드 급증 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| AI가 생성한 코드의 내부 구조를 인간이 파악하지 못해 장기적 유지보수가 불가능해지는 환각 및 기술 부채(Technical Debt) 누적 | 요구사항 작성 시 테스트 주도 개발(TDD)을 원칙으로 삼아 단위 테스트 코드를 먼저 AI에게 작성하게 하고 이를 통과한 코드만 머지 |
| 학습 데이터 내 취약점이나 검증되지 않은 오픈소스 라이브러리를 무비판적으로 인용하여 소프트웨어 공급망 보안 취약점(CWE/CVE) 노출 | CI/CD 파이프라인에 SonarQube, Snyk 등 SAST/SCA 검사를 연동하여 취약점 및 라이선스 위반 감지 시 빌드 자동 차단 |
| 대규모 멀티 모듈 시스템에서 파일 간 의존성 파악 실패로 인한 숨겨진 사이드 이펙트(Side Effect) 및 성능 저하 | 모듈별 인터페이스 계약(API Contract)을 명문화하고 E2E 통합 테스트 파이프라인을 통한 회귀 테스트(Regression Test) 필수 수행 |

## Ⅵ. 제언

자연어 생성력과 엄격한 공학적 품질 보증을 결합하기 위해 TDD(테스트 주도 개발)와 자동화된 SAST 보안 검증 게이트를 결합한 안전한 에이전틱 개발 거버넌스 아키텍처 구축.

```text
[ 개발자의 자연어 의도 ] ──> [ Step 1: 실패하는 단위 테스트 코드 작성 요구 (TDD) ]
                                      │
                                      ▼
                             [ Step 2: AI 에이전트의 구현 코드 작성 및 자가 디버깅 ]
                                      │
                                      ▼
                             [ Step 3: 단위/통합 테스트 100% 통과 확인 ]
                                      │
                                      ▼
                             [ Step 4: SAST 보안 정적 분석 & 라이선스 자동 스캔 ]
                                      │
                                      ▼
                             [ Step 5: 인간 아키텍트의 최종 리뷰 및 프로덕션 머지 ]
```

| 구분 | 무검증 단순 바이브 코딩 | 제언: TDD 결합 에이전틱 바이브 코딩 |
|---|---|---|
| **품질 검증** | "잘 동작하는 것 같음" (주관적 신뢰) | 엄격한 단위 테스트 케이스 100% 통과 |
| **보안 검사** | 취약점 존재 여부 무인지 | SAST/SCA 자동화 툴을 통한 취약점 0화 |
| **유지보수성** | 변경 시 사이드 이펙트로 시스템 붕괴 | 회귀 테스트를 통한 지속적 리팩토링 보장 |
