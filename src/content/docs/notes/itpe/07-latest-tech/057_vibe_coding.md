- 본질: **바이브 코딩(Vibe Coding)** 은 개발자가 자연어로 의도를 전달하고 AI가 제안한 코드를 실행 결과에 따라 반복 수정하는 개발 방식
- 메커니즘: 요구·제약 설명 → 코드 제안 → 실행·시험 → 결과 검토와 수정

<details>
<summary>핵심 용어</summary>

- **바이브 코딩(Vibe Coding)** : 개발자가 자연어 의도와 실행 결과에 집중해 AI와 코드를 반복 작성하는 방식
- **생성형 인공지능(Generative Artificial Intelligence, Generative AI)** : 입력을 바탕으로 새 콘텐츠·코드를 생성하는 AI 계열
- **코드 리뷰(Code Review)** : 변경 코드의 정확성·보안성·유지보수성을 검토하는 활동
- **회귀 시험(Regression Testing)** : 변경 뒤 기존 기능이 유지되는지 확인하는 시험
- **수용 기준(Acceptance Criteria)** : 기능이 요구를 충족했다고 판단하기 위한 확인 조건

### Ⅰ. 바이브 코딩의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **바이브 코딩(Vibe Coding)** 은 개발자가 자연어로 의도를 전달하고 AI가 제안한 코드를 실행 결과에 따라 반복 수정하는 개발 방식 |
| 목적 | 코드 작성의 반복을 줄이고 빠른 기능 탐색·시제품 구현 지원 |

### Ⅱ. 반복 개발 흐름

```text
개발자: 요구·제약·수용 기준 제시
                 │
생성형 AI: 코드 변경 제안
                 │
실행·시험 결과 검토
      │ 미충족       │ 충족
      └─ 수정 요청   └─ 리뷰·병합
```

실행 성공은 요구 충족이나 보안 적합성을 자동 보장하지 않으며, 변경 검토 책임은 개발 조직에 남음.

### Ⅲ. 품질·보안·유지보수 관리

| 관점 | 한계 | 대응 |
|---|---|---|
| 기능 품질 | 그럴듯하지만 요구와 다른 코드 생성 가능성 | 수용 기준에 따른 단위·통합·회귀 시험 |
| 보안 | 취약 코드·비밀정보·위험 의존성 유입 가능성 | 정적 분석·의존성·비밀정보 검사와 코드 리뷰 |
| 유지보수 | 구조를 이해하지 못한 변경이 누적될 우려 | 모듈 경계·설계 이유·변경 이력 기록 |

### Ⅳ. 조직 적용과 기술사적 제언

| 한계 | 해결 방안 |
|---|---|
| 조직 전체에 한꺼번에 적용하면 검토 책임과 품질 기준을 합의하기 어려움 | 테스트 작성·문서 초안 등 위험이 낮은 업무에서 시범 운영하고, 재작업·검토 시간·결함 지표로 적용 범위를 판단 |
