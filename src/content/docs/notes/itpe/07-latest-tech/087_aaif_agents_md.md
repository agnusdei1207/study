- 저장소 지침, 간접 프롬프트 주입, 샌드박스, 최소 권한, 컨텍스트 윈도우, 정적 분석

## Ⅰ. AAIF (Agentic AI Foundation)·AGENTS.md의 개요

- 핵심 요약 : 에이전트 생태계의 공용 기반을 중립 재단이 관리하고, 저장소 개발 지침을 AGENTS.md라는 공통 규격으로 전달하는 흐름.
- 개념 : 2025년 12월 Linux Foundation 산하에 설립된 **Agentic AI Foundation** (AAIF, 에이전트 AI 표준화 재단)과, 저장소의 빌드·테스트 명령과 코딩 규칙을 에이전트에 전달하는 마크다운 규격 **AGENTS.md**.
- 배경 및 필요성 : 벤더마다 지침 형식과 도구 연결 방식이 달라 프로젝트마다 설정이 중복되고 에이전트를 바꾸기 어려움. 다만 마크다운 지침에는 법적·기술적 강제력이 없어 **간접 프롬프트 주입** (Indirect Prompt Injection)에 노출되므로, 샌드박스 격리와 권한 통제를 함께 두어야 함.
- 주요 목적 : 벤더 종속(Lock-in) 완화, 프로젝트별 컨텍스트 파편화 해소, 에이전트가 일관된 규칙으로 코드를 변경하도록 보장.

## Ⅱ. AAIF (Agentic AI Foundation)·AGENTS.md의 특징 및 장점

- 핵심 요약 : 재단 초기 프로젝트 세 가지가 지침, 도구 연결, 실행 환경을 나눠 맡아 에이전트 작업의 표준 기반을 이룸.

1. AGENTS.md (OpenAI 기여) : 아키텍처 원칙, 코딩 컨벤션, 빌드·테스트 명령을 표준 마크다운에 기록 → 에이전트가 프로젝트 맥락을 바로 파악.
2. MCP (Model Context Protocol, Anthropic 기여) : 에이전트와 외부 도구, 데이터 소스를 잇는 표준 연결 규약 → 도구 연동을 한 번 구현해 여러 에이전트에서 재사용.
3. goose (Block 기여) : MCP를 지원하는 오픈소스 에이전트 프레임워크 → 개발자 로컬 환경에서 에이전트를 실행하고 확장.

## Ⅲ. AAIF (Agentic AI Foundation)·AGENTS.md의 구조 (흐름)

- 핵심 요약 : 저장소 지침 탐색에서 도구 호출, 런타임 정책 검증, 격리된 변경 집행으로 이어지는 파이프라인과 그 사이의 신뢰 경계.
- **샌드박스** (Sandbox) : 에이전트 실행을 호스트와 분리된 컨테이너에 가두어 파일 쓰기와 네트워크 접근 범위를 제한하는 격리 환경.
- **최소 권한** (Least Privilege) : 에이전트 계정에 작업 수행에 필요한 최소 권한만 부여하는 원칙.

```text
[ 저장소 루트 / 하위 경로 ]
            ↓ AGENTS.md 탐색과 병합
[ 에이전트 컨텍스트 구성 ]
            ↓ 계획 수립
[ 자율 에이전트 엔진 ]
            ↓ MCP 도구 호출
[ 런타임 정책 검증 ]
            ↓ 허용된 범위만 통과
[ 격리 환경 내 코드 변경 ]
```

```text
[ 신뢰 경계 ]

운영자 지침 (AGENTS.md, 시스템 설정)
            ↓ 지침으로 사용
[ 에이전트 판단 ]
            ↑ 데이터로만 취급 (지침 아님)
외부 입력 (이슈, PR 주석, 서드파티 코드)
```

## Ⅳ. AGENTS.md와 유사 지침 방식의 비교

- 핵심 요약 : AGENTS.md는 벤더 중립적인 저장소 내 파일이라는 점에서 벤더별 시스템 프롬프트나 IDE 전용 규칙과 구분됨.

| 비교 축 | AGENTS.md | 시스템 프롬프트 | Cursor Rules (.cursorrules) | MCP Resources |
| --- | --- | --- | --- | --- |
| 표준화 주체 | Linux Foundation 산하 AAIF | 각 모델 벤더의 독자 방식 | Cursor IDE의 독자 방식 | MCP 규약 (Anthropic 기여) |
| 저장 위치 | Git 저장소 루트 또는 하위 폴더 | API 파라미터 또는 챗 설정 | 프로젝트 루트 또는 사용자 설정 | 외부 MCP 서버 |
| 호환 범위 | 에이전트 엔진에 독립적 | 호출 클라이언트에 종속 | Cursor 환경에 제한 | MCP 지원 에이전트 |
| 표현 형식 | 마크다운 문서 | 자연어 텍스트 | 마크다운 또는 독자 형식 | 구조화된 JSON 데이터 |

- 선택 기준 : 저장소 단위로 팀 전체가 공유해야 하는 규칙이면 AGENTS.md, 실행 시점에 외부 데이터를 제공해야 하면 MCP 리소스를 우선 검토함.

## Ⅴ. AGENTS.md 적용의 한계와 방안

- 핵심 요약 : 지침의 강제력 부족, 간접 프롬프트 주입, 지침 비대화를 기계적 검증, 신뢰 경계 분리, 선택적 주입으로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 지침 강제력 부족 | 복잡한 규칙을 모델이 누락하거나 무시함 | Git 훅, CI(Continuous Integration) 린터, 정적 분석 도구로 규칙을 기계적으로 이중 검증 | 규칙 위반 탐지 건수 |
| 간접 프롬프트 주입 | 오염된 이슈, PR 주석, 서드파티 코드가 에이전트 행동을 조작 | 외부 입력과 시스템 지침의 신뢰 경계 분리, 격리 환경에서만 실행 | 샌드박스 이탈 시도 건수 |
| **컨텍스트 윈도우** 잠식 | 모노레포에서 지침이 길어져 작업에 쓸 입력 공간이 줄어듦 | 작업 경로와 관련된 지침만 선택 주입, 검색 기반 지침 조회 | 지침 토큰 사용량 |

## Ⅵ. AAIF·AGENTS.md에 대한 기술사적 제언

- 핵심 요약 : 지침을 코드와 같은 거버넌스 대상으로 다루고, 에이전트에 최소 권한과 격리 실행을 기본으로 적용하는 방향.

1. 전사 개발 표준에 AGENTS.md 템플릿을 포함하고, 지침 파일의 변경을 코드 리뷰 대상으로 관리하는 것이 필요함.
2. 에이전트 계정은 저장소 쓰기 범위와 배포 권한을 분리하여 발급하고, 외부 입력을 다루는 작업은 격리 환경에서만 실행하는 정책을 세우는 것이 바람직함.
3. 중장기적으로는 지침 유효성 검사와 에이전트 행위 감사 로그를 CI 파이프라인에 포함하여 규칙 준수를 상시 확인하는 체계를 마련하는 것이 현실적임.

## Ⅶ. 결론

- 핵심 요약 : AAIF와 AGENTS.md는 에이전트 개발 지침과 도구 연결을 벤더 중립 규격으로 묶으려는 표준화 흐름.
- 시사점 : 지침 문서 자체는 강제력이 없으므로, 표준 규격의 도입과 함께 권한 통제와 검증 자동화가 갖춰져야 실효가 있음.
