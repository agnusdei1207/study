## 한 줄 본질
- 에이전트가 소프트웨어 저장소나 시스템에 진입할 때 지켜야 할 코딩 규칙, 허용 도구, 접근 금지 영역을 자연어 프롬프트로 일일이 전달하기 어려움 → 저장소 루트에 표준화된 선언형 명세(AGENTS.md)를 배치하고 표준 기구(AAIF)를 통해 상호운용성을 규격화 → 에이전트 자율 작업의 안전성 확보 / 비준수 에이전트에 대한 강제력 한계

## 핵심 용어
- AGENTS.md: AI 코딩 에이전트 및 자율 에이전트에게 프로젝트 구조, 빌드 규칙, 테스트 지침, 보안 가드레일을 전달하기 위해 저장소 최상단에 배치하는 표준 마크다운 명세 문서
- AAIF(Agentic AI Foundation): 이종 AI 에이전트 간의 프로토콜 표준, 에이전트 행동 지침, 상호운용성 및 평가 기준을 수립하기 위해 발족한 오픈소스 표준화 연합
- 런타임 가드레일(Runtime Guardrail): AGENTS.md에 정의된 제약 조건을 실행 시점에 감시하여, 금지된 명령어 실행이나 민감 디렉터리 변조를 실시간 차단하는 보안 계층

## 핵심 통찰
- AGENTS.md는 "인간을 위한 README.md"의 "AI 에이전트용 버전": 인간 개발자의 온보딩 가이드를 에이전트가 1회 프롬프트 로드로 파싱할 수 있게 구조화하여 토큰 낭비와 환각을 최소화함
- 선언형 명세 자체는 보안 장벽이 아님: 웹의 robots.txt처럼 악의적 에이전트는 규칙을 무시할 수 있으므로, 에이전트 런타임 수준의 샌드박스와 권한 강제 엔진이 반드시 결합되어야 실효성이 있음
- 도구 연계(Tool Calling) 표준인 MCP와 AGENTS.md의 결합: AGENTS.md가 "어떤 상황에서 어떤 도구를 써야 하는지"의 정책을 선언하고, MCP가 "도구 실행 인터페이스"를 제공하는 상호보완적 계층 구조 형성

## 이웃 토픽과 구분
- AGENTS.md vs robots.txt: robots.txt는 웹 크롤러의 URL 접근 경로 허용/차단 / AGENTS.md는 AI 에이전트의 작업 지침, 프로젝트 아키텍처, 도구 사용법 및 코딩 표준 전반을 규정

## 문제·원인·대책
- 적용 상황: 사내 엔터프라이즈 코드베이스에 외부 AI 코딩 에이전트 연동 시 보안 위반 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 에이전트가 사내 레거시 프레임워크 대신 임의의 오픈소스 라이브러리를 설치하여 빌드 실패 | 프로젝트의 아키텍처 원칙 및 금지 패키지 지침이 프롬프트에 누락됨 | AGENTS.md에 금지 의존성 목록 및 표준 패키지 명세를 선언하고 프리커밋 훅 검증 | 비표준 라이브러리 도입 100% 방지 |
| 에이전트가 환경설정 파일(.env, API Key)을 커밋 메시지에 포함하거나 외부에 유출 | 에이전트의 파일 접근 권한 범위가 전역(Root)으로 열려 있음 | AGENTS.md 보안 섹션에 민감 경로 마스킹 및 TEE 기반 시크릿 격리 연계 | 시크릿 유출 원천 차단 |
| 수십 명의 개발자가 각자 다른 에이전트 프롬프트를 사용하여 코드 스타일 파편화 | 일관된 에이전트 지침 템플릿 부재 | AAIF 표준 기반 AGENTS.md를 중앙 템플릿화하여 모든 레포지토리에 배포 동기화 | 일관된 린트·포맷팅 규칙 준수 |
