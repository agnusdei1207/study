 ┣━ Ⅰ 개요 ───── ML 모델 단위 파이프라인(MLOps) 한계 → 기업 내 모든 AI/수학/규칙 모델의 전사적 통합 운영

## 한 줄 본질
- 데이터 과학자의 개별 ML 모델 개발 및 사후 방치 한계 → 머신러닝뿐 아니라 통계·규칙 등 전사 모든 의사결정 모델의 등록, 검증, 배포, 감사를 단일 거버넌스로 통제 → 전사 리스크 통제 및 비즈니스 가치 극대화 / 조직 간 R&R 조율 및 프로세스 오버헤드 발생

## 핵심 용어
- 모델 레지스트리(Model Registry): 개발된 모든 모델의 버전, 하이퍼파라미터, 의존성, 검증 메트릭, 승인 상태를 중앙 집중 기록하는 저장소
- 모델 드리프트(Model Drift): 운영 환경의 데이터 분포 변화나 실제 비즈니스 환경의 변화로 인해 모델의 예측력이 점진적으로 퇴화하는 현상
- 챔피언-챌린저(Champion-Challenger): 현재 운영 중인 최고 성능 모델(Champion)과 새로 개발된 후보 모델(Challenger)에 트래픽을 분할 서빙해 실시간 성능을 대조 검증하는 기법

## 핵심 통찰
- MLOps가 "데이터 과학자와 엔지니어의 파이프라인 자동화"에 초점을 맞춘다면, ModelOps는 "경영진과 컴플라이언스 조직의 전사적 리스크 관리와 ROI 창출"에 초점
- 모델을 배포하는 것(Day 1)보다 배포 이후 성능 퇴화, 데이터 왜곡, 법적 규제 준수를 수년간 감시하는 운영(Day 2) 비용이 10배 이상 큼
- 금융 사기, 공정 제어 등 고위험 영역에서는 순수 ML 모델뿐 아니라 하드코딩된 업무 규칙(Rule) 모델과의 복합 체인 통제가 필수적

## 이웃 토픽과 구분
- ModelOps vs MLOps: MLOps는 머신러닝 파이프라인 기술(CI/CD/CT) 중심 / ModelOps는 룰 엔진, 최적화 알고리즘까지 아우르는 엔터프라이즈 거버넌스 및 비즈니스 의사결정 중심

## 문제·원인·대책
- 적용 상황: 수백 개의 운영 모델을 보유한 보험사의 모델 감사 실패 및 리스크 누적
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 운영 중인 모델의 위치와 버전 파악 불가 | 부서별 개별 배포로 인한 섀도우 AI 모델 난립 | 전사 중앙 모델 레지스트리 등록 의무화 및 미등록 모델 트래픽 차단 | 전사 모델 자산의 100% 가시성 확보 |
| 금융감독원 모델 검증 감사 지적 | 모델 학습 데이터 출처 및 검증 보고서 이력 증적 부재 | 모델 혈통(Lineage) 추적 도구 및 메타데이터 자동 감사 로깅 구축 | 규제 기관 감사 증적의 무결성 입증 |
| 사기 탐지율 하락에도 방치 | 배포 후 상시 모니터링 및 자동 재학습 파이프라인 부재 | 실시간 성능 메트릭 알림 및 챔피언-챌린저 자동 승격 파이프라인 적용 | 최적 모델 성능의 상시 유지 |

## 이렇게 출제된다
- 제121회 1교시: "MLOps와 ModelOps의 개념을 비교 설명하시오." → 요구 포인트: Ⅴ 관리 대상, 관점, 목표, 조직 역할 비교
- 제128회 2교시: "엔터프라이즈 환경에서 인공지능 모델의 라이프사이클 관리를 위한 ModelOps 프레임워크를 설명하시오." → 요구 포인트: Ⅲ 구성요소 + Ⅳ 거버넌스 프로세스

## 내 의견
- [모델 메타데이터 카탈로그와 비즈니스 성과(KPI)의 직결 대시보드 구축] 데이터팀은 기술 지표(AUC, F1)에만 집중하여 경영진에게 실질적 비즈니스 기여도를 증명하지 못함 → 나라면: ModelOps 플랫폼에 모델별 추론 호출당 매출 기여액 및 절감 비용을 실시간 산출하는 비즈니스 대시보드를 연동하여, 성과 미달 모델은 자동으로 리팩토링 큐로 이관하는 ROI 기반 수명주기 통제 수립
