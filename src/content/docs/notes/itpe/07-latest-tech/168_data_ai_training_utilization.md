## 답안 골격
### 1교시 예상문제 (10점)
AI 학습 데이터의 생애주기와 데이터 중심 AI의 핵심 활동을 설명하시오.

### 1교시 10점 답안
- **정의:** 모델 구조만 바꾸는 대신 수집·라벨·표본 구성·평가 데이터의 품질을 관리하는 개발 접근.
- **생애주기:** 출처·권리 확인 → 수집·중복 제거 → 라벨링·품질 검수 → 학습/검증/시험 분리 → 오류 분석·갱신.
- **통제:** 개인정보·저작권·편향·오염 위험을 데이터 계보와 접근 권한, 별도 평가 집합으로 관리.

### 2~4교시 예상문제 (25점)
대규모 AI 학습 데이터 파이프라인의 품질·권리·오염 위험을 통제하는 방안을 설명하시오.

### 2~4교시 25점 답안
1. **입력 관리:** 출처, 수집 조건, 이용 허락, 개인 정보와 민감 정보의 처리 근거 및 보존 기간 기록.
2. **품질 관리:** 정규화·중복 제거·라벨 일치도, 하위 집단의 대표성, 오염·유출 탐지와 학습·평가 집합의 분리.
3. **합성 데이터:** 부족한 사례의 보완 수단으로 사용하되 실제 분포와의 차이, 반복 자기학습의 오류 증폭 가능성 평가.
4. **운영:** 데이터 버전·계보·삭제 요청 절차, 학습 결과의 집단별 성능과 오류 추적, 사람 검토를 통한 지속 개선.

```text
[데이터 (AI 학습·활용)] ◀━━ 머리: Ⅶ 내 의견 (데이터 고갈 위기 극복을 위한 합성 데이터 파이프라인과 저작권 침해 방지 데이터 거버넌스 프레임워크 구축)
 ┃
 ┣━ Ⅰ 개요 ───── AI 모델 경쟁력이 알고리즘에서 고품질 데이터 확보 역량으로 전이되는 데이터 중심 AI(Data-Centric AI) 패러다임 도래
 ┣━ Ⅱ 생애주기 ─ 데이터 수집(Web Scraping, IoT) → 정제/필터링(Deduplication, NSFW) → 가공/라벨링(Annotation) → 학습/평가 → 지속적 증강(Active Learning)
 ┣━ Ⅲ 당면과제 ─ 인간 생성 텍스트 고갈(Data Wall) · 저작권 및 TDM(텍스트·데이터 마이닝) 면책 분쟁 · 편향(Bias) 및 독성(Toxicity) · 데이터 오염(Poisoning)
 ┣━ Ⅳ 대응기술 ─ 합성 데이터(Synthetic Data) 생성 · 데이터 큐레이션(품질 필터링) · 중복 제거(MinHash) · 차등 프라이버시(Differential Privacy)
 ┣━ Ⅴ 비교 ───── 모델 중심 AI(Model-Centric) vs 데이터 중심 AI(Data-Centric) (데이터고정후코드튜닝/한계도달 vs 코드고정후데이터품질·라벨정제/비약적성능개선)
 ┗━ Ⅵ 실무 ───── 크롤링 방지 규약(robots.txt) 무단 위반 소송 / 합성 데이터 반복 학습에 따른 모델 붕괴(Model Collapse) / 다크웹 데이터 누출 위험
```
- 필수 키워드: 데이터 중심 AI(Data-Centric AI) · 데이터 고갈(Data Wall) · 합성 데이터(Synthetic Data) · 모델 붕괴(Model Collapse) · TDM 면책 · 중복 제거(MinHash) · 데이터 큐레이션
- 출제 이력: 공식 문제지 원문과 대조하지 않아 출제 여부를 단정하지 않음.

## 한 줄 본질
- 아무리 좋은 인공지능 엔진도 썩은 기름(저품질·오염 데이터)을 넣으면 망가지므로, 쓰레기 데이터를 걸러내고 부족한 데이터는 합성해 채우며 법적 저작권을 지키는 AI의 핵심 원유 관리 공정

## 핵심 용어
- 데이터 중심 AI(Data-Centric AI): 앤드류 응(Andrew Ng) 교수가 주창한 패러다임으로, 모델 코드를 고정한 상태에서 데이터의 품질, 일관성, 라벨 정확도를 체계적으로 개선하여 AI 성능을 올리는 접근법
- 합성 데이터(Synthetic Data): 실제 현실 세계에서 수집한 데이터가 아니라, 물리 엔진 시뮬레이션이나 생성형 AI 모델을 통해 디지털 환경에서 인위적으로 생성해 낸 고품질 학습 데이터
- 모델 붕괴(Model Collapse): 차세대 AI 모델들이 인간이 작성한 원본 데이터가 아닌 AI가 생성한 합성 데이터만을 반복적으로 학습할 때, 정보의 꼬리(다양성)가 잘려나가고 생성물이 횡설수설 퇴화하는 현상

## 핵심 통찰
- 고품질 학습 데이터의 이용 가능성은 권리·언어·도메인·중복 정도에 따라 달라지며 특정 연도의 완전 고갈을 확정할 근거 없음
- 데이터 품질과 규모의 효과는 모델·과제·평가 방법에 의존하므로 다른 모델의 토큰 수만으로 우열을 일반화하지 않음
- 학습 데이터의 저작권·개인정보 처리 기준은 관할 법령과 계약에 따라 달라지므로 일률적 TDM 면책을 전제하지 않음

## 이웃 토픽과 구분
- 모델 중심 AI vs 데이터 중심 AI: 모델 중심은 "데이터는 고정하고 최신 트랜스포머 알고리즘을 튜닝하자" / 데이터 중심은 "알고리즘은 표준을 쓰고 오라벨링과 노이즈 데이터를 깎아내자"

## 문제·원인·대책
- 적용 상황: 금융 도메인 특화 초거대 언어 모델 사전학습을 위한 10TB 금융 데이터 구축
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 수집 자료에 개인정보 포함 | 출처·내용 검토와 민감정보 탐지가 부족 | 수집 권한 확인과 탐지·가명처리·삭제 절차 적용 | 샘플 검토에서 잔여 노출과 재식별 위험 확인 |
| 유사 문서가 반복되어 학습 비중 왜곡 | 복제·재게시 문서가 중복 유입 | 해시·MinHash 등으로 중복 후보를 찾고 오탐 검토 | 제거율과 유용 문서 손실을 함께 측정 |
| 합성 데이터 반복 사용으로 다양성 저하 | 출처·생성 경로와 품질 관리 부족 | 원본·합성 자료의 계보를 관리하고 별도 검증 집합으로 평가 | 다양성·성능·편향의 변화를 추적 |

## 이렇게 출제된다
- 예상 문제: "생성형 AI 시대에 데이터가 모델 성능을 좌우하는 데이터 중심 AI(Data-Centric AI) 관점에서, AI 학습 데이터 생애주기, 데이터 고갈 문제의 대응 방안 및 데이터 저작권 쟁점을 설명하시오." → 요구 포인트: Ⅰ 패러다임 전환 배경 + Ⅱ 수집-정제-큐레이션 전주기 흐름 + Ⅳ 합성데이터 및 모델 붕괴 방지책

## 내 의견
- 학습 자료의 출처·권한·변경 이력을 관리하고 오염 의심 자료를 별도 검토 대상으로 격리. 문서 해시만으로 내용의 진실성이나 모델의 안전성을 증명할 수 없다는 점을 평가에 반영
