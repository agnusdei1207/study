## 30초 인출

- 본질: **AI 학습용 데이터 구축 및 활용** 은 인공지능 모델의 성능과 신뢰성을 결정짓는 핵심 원천으로서 데이터의 기획, 수집, 정제, 라벨링, 품질 검증, 계보 추적 및 법적 권리 보호를 전주기적으로 관리하는 데이터 엔지니어링 체계
- 메커니즘: 적법 수집 및 비식별화 → 중복 제거(MinHash) 및 필터링 → 고정밀 어노테이션 및 합성 데이터 증강 → TTA 품질 표준 검수 → DVC 기반 버전 관리 및 서빙
- 통찰: AI 생성 합성 데이터의 무분별한 재학습 시 모델이 점진적으로 멍청해지는 모델 붕괴(Model Collapse)와 벤치마크 오염이 발생하므로 고품질 인간 검증 원천 데이터의 비율 통제와 오염 탐지 파이프라인 구축 필요

<details><summary>핵심 용어</summary>

- **데이터 중심 AI (Data-Centric AI)** : 모델 아키텍처는 고정한 채 학습 데이터셋의 품질과 라벨 일관성을 반복 개선하여 성능을 끌어올리는 패러다임.
- **모델 붕괴 (Model Collapse)** : AI가 생성한 합성 데이터를 다음 세대 AI가 재귀적으로 학습할 때 원래 데이터의 꼬리 분포(희귀 정보)가 영구 소실되는 현상.
- **데이터 오염 (Data Contamination)** : 성능 평가를 위한 테스트 벤치마크 데이터가 사전학습 말뭉치에 혼입되어 평가 지표가 비정상적으로 부풀려지는 현상.
- **데이터 시트 (Datasheets for Datasets)** : 데이터셋의 구축 동기, 구성, 수집 프로세스, 전처리, 권장 용도 및 한계를 표준 양식으로 문서화한 명세서.
- **데이터 계보 (Data Lineage)** : 원천 수집처부터 변환, 정제, 라벨링, 모델 학습에 이르기까지 데이터의 전 라이프사이클 흐름을 추적하는 메타데이터.

</details>

## 2~4교시 25점 답안

## Ⅰ. AI 학습용 데이터 구축 및 활용의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 머신러닝·초거대 파운데이션 모델이 편향 없이 지식을 학습할 수 있도록 원천 비정형 데이터(텍스트, 이미지, 음성)를 정제·가공·검증하고, 저작권 및 개인정보보호 컴플라이언스를 준수하여 공급하는 전주기 데이터 공학 체계 |
| 목적 | "Garbage In, Garbage Out" 방지, 모델의 일반화 정확도 향상, 환각 감소, 데이터셋의 법적 리스크 사전 차단 및 재현성 확보 |

## Ⅱ. AI 학습 데이터의 4대 품질 요건 및 엔지니어링 특징

| 품질 요건 | 엔지니어링 검증 기준 | 주요 특징 및 결함 시 영향 |
|---|---|---|
| **정확성 (Accuracy)** | 실세계 사실(Ground Truth) 및 물리 법칙과의 부합성 | 라벨링 오류율 1% 증가 시 모델 정확도 최대 5% 급락 |
| **완전성 (Completeness)**| 결측치(Missing Value) 부재 및 필수 메타데이터 충족도 | 모달리티 누락 시 멀티모달 정렬 학습 수렴 실패 |
| **대표성 (Diversity)** | 도메인 인구통계, 방언, 희귀 엣지 케이스 포함 균형도 | 특정 집단에 대한 알고리즘적 차별 및 편향성 유발 |
| **일관성 (Consistency)**| 동일한 개체 및 상황에 대한 주석 기준의 통일성 | 다수 작업자 간 라벨 불일치 발생 시 손실 함수 진동 초래 |

## Ⅲ. AI 학습 데이터 구축·정제·검증 엔드투엔드 파이프라인

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ 고품질 AI 학습용 데이터 수집-정제-검증-계보 통합 엔지니어링 파이프라인 ]│
└────────────────────────────────────────────────────────────────────────┘

  [ 1. 원천 데이터 획득 (Ingestion & Copyright Gate) ]
   - 웹 크롤링 (Common Crawl), 공공 데이터셋, 기업 레거시 로그, 합성 데이터
                 │
                 ▼ (저작권/로봇 배제 표준 Robots.txt 검증 & PII 마스킹)
  [ 2. 대규모 정제 및 필터링 (Deduplication & Cleansing) ]
   ├── MinHash LSH: 대규모 중복 문서 및 유사 문장 클러스터링 제거
   ├── 휴리스틱 필터: 광고, 기계 번역 스팸, 특수문자 비정상 반복 제거
   └── 안전성 필터: 성인물, 폭력, 혐오 표현(Toxicity) 사전 차단
                 │
                 ▼
  [ 3. 데이터 가공 및 어노테이션 (Labeling & Augmentation) ]
   - Auto-labeling ──> 인간 전문가 검수(HITL) ──> 상호 일치도(Kappa) 검증
                 │
                 ▼
  [ 4. 데이터셋 품질 평가 및 벤치마크 오염 방지 (Quality Audit) ]
   - 훈련 데이터 vs 공인 벤치마크(MMLU, GSM8K) 13-gram 겹침 검사
                 │
                 ▼
  [ 5. 버전 관리 및 피처 스토어 카탈로그 (DVC & Feature Store) ]
   - <Datasheet, 데이터 해시, 변환 스크립트, 학습 모델 ID> 통합 계보 등록
```

| 파이프라인 단계 | 엔지니어링 처리 내용 | 적용 기술 및 도구 |
|---|---|---|
| **수집 및 비식별화**| 주민등록번호, 계좌번호, 전화번호 자동 정규식 및 NER 탐지 마스킹 | Presidio, spaCy PII Extractor |
| **대규모 중복 제거**| 테라바이트급 말뭉치에서 8-gram 단위 유사 문서 초고속 제거 | MinHash, Jaccard Similarity, LSH |
| **품질 검증** | 구문 문법성, 텍스트 품질 점수(Perplexity) 기반 저품질 토큰 제거 | FastText 품질 분류기, KenLM |
| **오염 필터링** | 평가 테스트셋과의 N-gram 중복을 탐지하여 사전학습 세트에서 삭제 | 13-gram Exact Match Checker |
| **계보 추적** | 원천 데이터의 변경 이력과 모델 가중치 체크포인트를 상호 바인딩 | DVC(Data Version Control), MLflow |

## Ⅳ. 실세계 원천 데이터 vs 인간 라벨링 데이터 vs AI 합성 데이터 비교

| 비교 항목 | 실세계 원천 데이터 (Raw Data) | 인간 라벨링 데이터 (Human Annotated) | AI 생성 합성 데이터 (Synthetic Data) |
|---|---|---|---|
| **구축 비용** | 낮음 (대량 웹 스크래핑) | 매우 높음 (인건비 및 시간 소모) | 매우 낮음 (GPU 연산만 소모) |
| **데이터 품질** | 낮음 (노이즈, 광고, 비속어 다수) | 매우 높음 (인간의 맥락 판정 반영) | 구조화 우수하나 모델 붕괴 위험 |
| **확장성** | 인터넷 텍스트 고갈 위기 직면 | 인력 한계로 무한 확장 불가 | 사실상 무한대 생성 확장 가능 |
| **주요 용도** | 파운데이션 모델 사전학습(Pre-train) | 지도학습 미세조정(SFT), RLHF | 엣지 케이스 증강, 로봇 시뮬레이션 |
| **핵심 위험** | 저작권 침해 소송, 개인정보 노출 | 라벨러 주관 편차, 휴먼 에러 | 꼬리 분포 소실, 환각 증폭 전이 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| AI가 생성한 합성 데이터를 다음 세대 모델이 반복 학습할 때 희귀 데이터 분포가 사라지고 출력이 획일화되는 모델 붕괴(Model Collapse) 발생 | 고품질 인간 저작 원천 데이터(Human-generated Data)를 핵심 앵커로 유지하고 합성 데이터 혼합 비율을 엄격히 제한(예: 20% 미만) |
| 사전학습 데이터에 공인 성능 평가 데이터셋(GSM8K, HumanEval 등)이 무단 혼입되어 모델의 실제 추론 능력이 왜곡되는 데이터 오염 발생 | 데이터 인제스천 단계에서 벤치마크 데이터와의 N-gram 및 임베딩 유사도 역대조 필터링 의무화 및 새로운 오프라인 평가셋 주기적 갱신 |
| 저작권자의 명시적 동의 없는 웹 콘텐츠(뉴스, 도서, 블로그) 무단 크롤링으로 인한 저작권 침해 집단 소송 및 규제 리스크 | AI 기본법 및 공정 이용(Fair Use) 가이드라인 준수, TDM(텍스트·데이터 마이닝) 면책 규정 입법화 및 옵트아웃(Opt-out) 프로토콜 보장 |

## Ⅵ. 제언

데이터의 신뢰성과 투명성을 제도적으로 입증하기 위해, 전사 데이터 카탈로그에 '데이터시트(Datasheets)'를 의무화하고 OpenLineage 기반의 엔드투엔드 데이터 계보 추적 체계 구축 필요.

```text
[ 데이터 수집 파이프라인 (Crawling / DB Dump) ]
                     │
                     ▼ (OpenLineage 메타데이터 이벤트 발행)
[ 중앙 메타데이터 거버넌스 플랫폼 (Marquez / Apache Atlas) ]
   ├── Step 1: 데이터 출처 및 라이선스(Apache, MIT, CC) 태깅
   ├── Step 2: 전처리 코드 Git 커밋 해시와 데이터셋 버전(DVC) 1:1 바인딩
   └── Step 3: 데이터 품질 지표(결측률, 중복률, PII 잔존율) 자동 기록
                     │
                     ▼ (표준 데이터시트 PDF 자동 렌더링)
[ AI 모델 레지스트리 연계 배포 (감사 추적성 및 규제 100% 대응) ]
```

| 구분 | 비표준 파편화 데이터 관리 | 제언: OpenLineage 기반 데이터 거버넌스 |
|---|---|---|
| **출처 추적** | 개발자 개인 기억 및 수기 문서 의존 | 원천 URL부터 모델 배포까지 자동 계보 추적 |
| **저작권 감사** | 법적 분쟁 발생 시 입증 곤란 | 라이선스 메타데이터를 통해 침해 데이터 즉시 격리 |
| **품질 감사** | 모델 배포 후 사후 결함 인지 | 인라인 파이프라인에서 품질 미달 데이터 자동 차단 |
| **재현성** | 1년 전 학습 데이터 재현 불가 | DVC 체크아웃을 통해 과거 데이터셋 100% 복원 |
