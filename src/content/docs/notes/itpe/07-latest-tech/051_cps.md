## 연관 키워드

- CPS(Cyber Physical System), 사이버 물리 시스템, 3C, 5C 아키텍처, 폐루프(Closed-Loop), 실시간 결정론
- TSN, OPC UA, IEC 62443, 기능 안전, 디지털 트윈, 임베디드 시스템

## Ⅰ. CPS(Cyber Physical System)의 개요

- 핵심 요약 : 물리 세계의 계측·제어와 사이버 공간의 연산·AI가 실시간 폐루프로 묶인 융합 제어 시스템.
- 개념 : 센서와 액추에이터로 물리 공간을 계측·제어하고, 연산·통신·AI를 담당하는 사이버 공간과 긴밀히 결합해 피드백 루프를 형성하는 융합 제어 시스템인 **사이버 물리 시스템** (CPS, Cyber Physical System).
- 배경 및 필요성 : 폐쇄형 임베디드 제어로는 장비 간 협업과 자율 판단에 필요한 실시간 정보를 얻지 못하고, 클라우드 중심의 **사물인터넷** (IoT, Internet of Things) 수집 구조는 제어 지연을 감당하지 못함. 이 한계를 넘기 위해 물리계와 디지털계를 실시간으로 묶는 계층 구조가 필요해짐.
- 주요 목적 : 밀리초 이하 수준의 **실시간 결정론**(Real-time Determinism) 확보, 이상 상황에서의 **자가 치유**(Self-Healing), 물리 시스템의 안전성과 생산 효율 향상.

## Ⅱ. CPS(Cyber Physical System)의 특징 및 장점

- 핵심 요약 : 3C 역량, 결정론적 통신, 폐루프, 기능 안전이 결합되어 물리 세계의 자율 제어를 가능하게 하는 구조.

1. **3C** (Computation·Communication·Control) : 임베디드 연산 결과를 통신으로 전달해 물리 액추에이션을 수행 → 사이버와 물리의 실시간 결합.
2. **시간 민감형 네트워킹** (TSN, Time-Sensitive Networking) : 표준 이더넷에서 전송 지연과 지터의 상한을 보장 → 제어 명령의 결정론 담보.
3. **폐루프** (Closed-Loop) : 센싱, 연산·AI 분석, 액추에이션이 사람의 개입 없이 완결 → 밀리초 단위 자율 대응.
4. **기능 안전** (Functional Safety) : 하드웨어와 소프트웨어를 이중화하여 고장 시 안전 상태로 전이 → 인명과 설비 피해 최소화.

## Ⅲ. CPS(Cyber Physical System)의 구조 (흐름)

- 핵심 요약 : 연결에서 설정까지 5개 계층이 쌓이고, 데이터는 위로 올라가며 제어 명령은 아래로 내려오는 양방향 구조.
- **5C 아키텍처** (Connection, Conversion, Cyber, Cognition, Configuration) : Lee 등이 제안한 계층형 참조 구조로, 각 계층이 데이터 가치를 한 단계씩 높임.

```text
[ CPS 5C 계층 구조 ]

  5. 자율 설정 (Configuration)
  4. 인지·의사결정 (Cognition)
  3. 사이버 가상화 (Cyber)
  2. 데이터 변환 (Conversion)
  1. 물리 연결 (Connection)

  데이터는 1 → 5로 상승, 제어 명령은 5 → 1로 하달
```

1. 연결 계층 : 스마트 센서, 액추에이터, IoT 디바이스가 물리 상태를 수집 → 원천 데이터 확보.
2. 변환 계층 : 센서 스트림의 정제, 특징 추출, 엣지 분석 → 의미 있는 상태 정보 생성.
3. 사이버 계층 : **디지털 트윈** (Digital Twin)으로 물리 자산을 복제하고 시계열 데이터를 집계 → 가상 공간의 상태 동기화.
4. 인지 계층 : AI 기반 이상 진단과 상태 예측 → 의사결정 지원.
5. 설정 계층 : 판단 결과를 액추에이터에 자율 제어 명령으로 하달 → 자가 치유.

```text
[ 사이버-물리 폐루프 ]

물리계 센싱 (센서 스트림)
         ↓
사이버계 연산·AI 분석
         ↓
물리계 액추에이션 (제어 명령)
         ↓
물리 상태 변화 → 다시 센싱
```

## Ⅳ. CPS(Cyber Physical System)와 인접 기술의 비교

- 핵심 요약 : 임베디드 시스템은 장치 내부 제어, IoT는 데이터 수집, CPS는 실시간 양방향 제어에 초점이 있음.

| 비교 축 | 전통적 임베디드 시스템 | 사물인터넷 (IoT) | 사이버 물리 시스템 (CPS) |
| --- | --- | --- | --- |
| 핵심 초점 | 독립 장치 내부의 고정 제어 | 사물 간 연결과 원격 데이터 모니터링 | 연산, 통신, 물리 액추에이션의 실시간 결합 |
| 통신 환경 | CAN, RS-485 등 폐쇄형 버스 | 인터넷 프로토콜 기반 전송 | TSN, 산업용 이더넷, 5G 특화망, **OPC UA** (OPC Unified Architecture) |
| 상호작용 구조 | 단방향 또는 국소 폐루프 | 클라우드로의 단방향 수집 위주 | 물리계와 사이버계 간 양방향 폐루프 |
| 실시간성 요구 | 높음 (단일 장치 마이크로초 제어) | 낮음 (수 초 단위 지연 허용) | 매우 엄격 (종단 간 결정론 보장) |
| 주요 적용 사례 | 자동차 ECU, 가전 마이컴 | 스마트 홈, 원격 검침 | 스마트 팩토리, 자율주행, 스마트 그리드 |

- IoT가 물리 세계의 데이터를 수집해 모니터링하는 데 중점을 둔다면, CPS는 분석 결과로 물리 세계를 실시간 능동 제어하는 데 방점을 둠.

## Ⅴ. CPS(Cyber Physical System)의 한계와 방안

- 핵심 요약 : 지연, 사이버 침해, 데이터 비표준화의 세 한계를 결정론 표준, 보안 규격, 공통 데이터 모델로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 실시간 결정론 붕괴 | 비결정론 IP 망의 패킷 지연 → 로봇 충돌, 전력망 주파수 불안정 | **IEEE 802.1 TSN** 표준 적용과 통신 지연 상한의 수학적 검증 | 종단 간 지연 상한 준수율 |
| 사이버-물리 보안 위협 | 악성코드의 설비 직접 조작 → 대표 사례인 스턱스넷(Stuxnet)처럼 설비 파괴 위험 | **IEC 62443** 산업 제어 시스템 보안 규격 준수, 단방향 보안 게이트웨이, PLC 펌웨어 전자서명 | 침해 탐지 건수, 펌웨어 서명 검증률 |
| 이기종 설비 데이터 표준화 결여 | 다수의 독점 필드버스 혼재 → 통합 데이터 분석 불가 | OPC UA 기반 데이터 모델링 표준화 | 표준 데이터 모델 적용률 |

## Ⅵ. CPS(Cyber Physical System)에 대한 기술사적 제언

- 핵심 요약 : 설계 단계의 안전 검증, 계층형 컴퓨팅 표준, IT와 제어 조직의 공동 보안 거버넌스로 CPS를 일회성 설비가 아닌 상시 운영 체계로 정착.

1. 설계 단계부터 물리 안전을 검증 대상으로 삼고, 가상 시운전과 기능 안전 규격 준수를 설비 도입의 승인 조건으로 묶어 운영한다.
2. 엣지와 클라우드의 역할 분담을 조직 표준으로 정하여, 설비 종류가 달라도 같은 데이터 모델과 제어 계층을 공유하도록 한다.
3. 보안을 운영 거버넌스로 격상하여 정보기술 조직과 설비 운영 조직이 침해 대응 절차와 펌웨어 관리 책임을 공동으로 갖도록 한다.

## Ⅶ. 결론

- 핵심 요약 : 계측, 연산, 제어를 실시간 폐루프로 묶어 물리 세계를 자율 제어하는 융합 시스템.
- 시사점 : 결정론적 통신, 기능 안전, 데이터 표준이 함께 갖춰질 때 CPS의 자율 제어가 산업 현장에서 신뢰를 얻음.
