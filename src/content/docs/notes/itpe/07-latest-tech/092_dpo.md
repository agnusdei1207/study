## Ⅰ. DPO (Direct Preference Optimization)의 개요

- 개념 : 강화학습 기반 **보상 모델** 훈련 없이 인간 선호 응답 쌍을 이용해 언어모델 정책을 직접 최적화하는 **폐쇄형 목적함수** 기반 **선호 정렬** 기술
- 배경 및 필요성 : 명시적 보상 모델은 생략되나 **참조 모델** 유지에 따른 GPU 메모리 부담과 분포 이탈 데이터에 대한 과적합 위험이 상존하므로 **LoRA** 결합 및 동적 **베타 계수** 스케줄링 적용 필수
- 핵심 목적 : 복잡한 **PPO** 파이프라인의 학습 불안정성 극복 및 GPU 메모리·연산 비용 절감을 통한 LLM 정렬 효율 극대화

## Ⅱ. DPO (Direct Preference Optimization)의 핵심 아키텍처 및 동작 메커니즘

DPO는 **브래들리-테리** (Bradley-Terry) 선호 모델의 최적 해를 수학적으로 재매개변수화하여 정책 모델과 고정 참조 정책 간의 **로그 확률 비율** 차이를 **이진 교차 엔트로피** 손실로 계산 후 역전파 메커니즘을 기반으로 동작하며, 세부적인 아키텍처와 핵심 컴포넌트 간 상호작용 프로세스는 다음과 같음.

```text
┌────────────────────────────────────────────────────────────────────────┐
│             DPO (Direct Preference Optimization) 학습 구조              │
└────────────────────────────────────────────────────────────────────────┘
 [ 프롬프트 x, 선호 응답 y_w, 비선호 응답 y_l ]
                        │
       ┌────────────────┴────────────────┐
       ▼                                 ▼
┌──────────────────────────────┐  ┌──────────────────────────────┐
│ 학습 대상 정책 모델 (π_θ)      │  │ 고정 참조 정책 모델 (π_ref)   │
│ (Active Policy Model)        │  │ (Frozen Reference SFT Model) │
└──────────────┬───────────────┘  └──────────────┬───────────────┘
               │                                 │
               ▼                                 ▼
┌──────────────────────────────┐  ┌──────────────────────────────┐
│ log π_θ(y_w|x)               │  │ log π_ref(y_w|x)             │
│ log π_θ(y_l|x)               │  │ log π_ref(y_l|x)             │
└──────────────┬───────────────┘  └──────────────┬───────────────┘
               │                                 │
               └────────────────┬────────────────┘
                                │
                                ▼
 ┌─────────────────────────────────────────────────────────────┐
 │ 암묵적 보상 마진 계산:                                       │
 │ Δr = β * [ log(π_θ(y_w)/π_ref(y_w)) - log(π_θ(y_l)/π_ref(y_l)) ] │
 └──────────────────────────────┬──────────────────────────────┘
                                │
                                ▼
 ┌─────────────────────────────────────────────────────────────┐
 │ DPO Loss 계산: L = - log σ(Δr)                              │
 └──────────────────────────────┬──────────────────────────────┘
                                │ Backpropagation (역전파)
                                ▼
                 [ π_θ 가중치 갱신 (Gradient Update) ]
```

- **수학적 재매개변수화** : $r(x, y) = \beta \log \frac{\pi_\theta(y \mid x)}{\pi_{ref}(y \mid x)}$ - 보상 함수 $r(x,y)$를 정책 모델과 참조 모델의 로그 우도 비율로 대수적 치환
- **DPO 손실 함수** : $\mathcal{L}_{DPO} = -\mathbb{E}\left[\log \sigma\left(\beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{ref}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{ref}(y_l \mid x)}\right)\right]$ - 선호 응답 $y_w$와 비선호 응답 $y_l$ 간의 암묵적 보상 차이를 시그모이드 교차 엔트로피로 최소화
- 보상 모델 생략 : 별도의 **Reward Model** (RM) 아키텍처 불필요 - RM 훈련 오차 전파 방지 및 학습 파이프라인의 단일 지도학습화

## Ⅲ. DPO (Direct Preference Optimization)의 세부 구성 요소 및 비교 분석

| 비교 항목 | RLHF (PPO) | DPO (본 토픽) | KTO (Kahneman-Tversky) | ORPO (Odds Ratio) |
|---|---|---|---|---|
| **보상 모델 유무** | 별도 RM 필수 | 불필요 (암묵적 보상) | 불필요 | 불필요 |
| **참조 모델 유무** | 필수 ($\pi_{ref}$) | 필수 ($\pi_{ref}$) | 필수 ($\pi_{ref}$) | 불필요 (SFT 손실과 통합) |
| **필요 데이터 형태** | 선호 쌍 $(y_w, y_l)$ | 선호 쌍 $(y_w, y_l)$ | 단일 응답 + 불리언(True/False) | 선호 쌍 $(y_w, y_l)$ |
| **학습 안정성** | 매우 낮음 (발산 빈번) | 높음 (지도학습과 유사) | 높음 | 매우 높음 |
| **GPU 메모리 요구** | 극도로 높음 (4개 모델 동시 로딩) | 중간 (2개 모델 로딩) | 중간 (2개 모델 로딩) | 낮음 (단일 모델 로딩) |

- DPO는 상기 비교 지표를 바탕으로 비즈니스 요구사항과 운영 인프라 환경을 고려한 최적의 아키텍처를 선정하고, 확장성과 안정성을 균형 있게 확보해야 함.

## Ⅳ. DPO (Direct Preference Optimization)의 주요 한계점 및 해결 방안

- 고정 참조 정책 모델 동시 상주에 따른 GPU VRAM 점유 한계 :
  - 한계점 : 고정 참조 정책 모델($\pi_{ref}$) 동시 상주로 인한 GPU VRAM 점유 및 단일 노드 학습 한계.
  - 해결 방안 : 참조 모델을 양자화(4-bit/8-bit)하여 고정하거나 LoRA 어댑터를 분리 장착하여 기본 베이스 모델 단일 공유.
- 분포 외(OOD) 선호 쌍 주입 시 손실 함수 포화 및 우도 폭락 :
  - 한계점 : 학습 데이터셋 내 분포 외(OOD) 선호 쌍 주입 시 손실 함수 포화 및 비선호 응답 우도 폭락 현상.
  - 해결 방안 : 선호 마진 기반 정규화 기법인 cDPO(Conservative DPO) 도입 및 라벨 노이즈 완화 정규화 항 추가.
- 하이퍼파라미터 $\beta$ 민감도로 인한 생성 다양성 저하 및 반복 출력 :
  - 한계점 : 하이퍼파라미터 $\beta$에 대한 높은 민감도로 인한 언어모델 생성 다양성 저하 및 반복 출력 발생.
  - 해결 방안 : 코사인 감쇠 기반 동적 $\beta$ 스케줄러 적용 및 평가 벤치마크 기반 조기 종료(Early Stopping) 구현.

## Ⅴ. DPO (Direct Preference Optimization) 적용 및 발전을 위한 기술사적 제언

- GPU 필요 사양 최적화 및 신뢰성 확보 방안 : 고사양 GPU 다수 필수를 선제적으로 구현하여 소수의 범용 GPU로 학습 가능을 체계적으로 달성하고 실무 운영 안정성을 완성해야 함.
- 모델 상주 개수 최적화 및 신뢰성 확보 방안 : 16-bit 모델 2벌 독립 로드를 선제적으로 구현하여 4-bit 기본 모델 1벌 + 수 MB LoRA 가중치를 체계적으로 달성하고 실무 운영 안정성을 완성해야 함.
- 학습 안정성 최적화 및 신뢰성 확보 방안 : 과적합 및 망각(Catastrophic Forgetting) 위험을 선제적으로 구현하여 기본 베이스 사전 지식 보존 및 안정적 수렴을 체계적으로 달성하고 실무 운영 안정성을 완성해야 함.
