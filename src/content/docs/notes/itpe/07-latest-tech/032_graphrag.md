## 연관 키워드

- GraphRAG, RAG(Retrieval-Augmented Generation), 지식 그래프(Knowledge Graph)
- 엔터티(Entity), 관계(Relationship), 커뮤니티 요약(Community Summary), Leiden 알고리즘
- 글로벌 검색(Global Search), 로컬 검색(Local Search), DRIFT 검색
- 다중 홉 추론(Multi-hop), 증분 인덱싱(Incremental Indexing), 엔터티 링킹(Entity Linking)

## Ⅰ. GraphRAG의 개요

- 핵심 요약 : 문서에서 지식 그래프와 커뮤니티 요약을 미리 만들어, 전체 주제 질의와 관계 추론 질의를 함께 처리하는 RAG 구조.
- 개념 : 비정형 텍스트에서 LLM(Large Language Model)으로 엔터티와 관계를 추출해 **지식 그래프** (Knowledge Graph)를 만들고, 그래프를 군집화한 뒤 각 커뮤니티를 요약해 두어 전체 코퍼스 질의와 세부 관계 질의를 모두 지원하는 **그래프 기반 RAG** (GraphRAG, Graph-based Retrieval-Augmented Generation).
- 배경 및 필요성 : 기존 벡터 기반 **나이브 RAG** (Naive RAG)는 유사한 텍스트 조각만 검색하므로, "이 자료 전체의 핵심 주제는 무엇인가"처럼 포괄적인 질의에 답하지 못하고 여러 문서에 걸친 연결을 추론하기 어렵다. 이 한계를 보완하기 위해 Microsoft 연구팀이 GraphRAG를 제안하고 오픈소스로 공개함.
- 주요 목적 : 코퍼스 전체의 주제 요약, 다단계 관계 추론, 환각 억제와 근거 추적.

## Ⅱ. GraphRAG의 특징 및 장점

- 핵심 요약 : 그래프와 커뮤니티 요약을 오프라인에서 미리 만드는 설계가 포괄 질의 품질과 근거 추적성으로 이어지는 방식.

1. 사전 커뮤니티 요약 : 군집별 요약문을 미리 생성·저장 → 전체 데이터셋을 훑는 질의에도 짧은 시간에 종합 답변 가능.
2. 관계 기반 검색 : 엔터티 이웃을 따라가며 근거를 모음 → 여러 문서에 흩어진 연결을 함께 추론.
3. 듀얼 검색 경로 : 포괄 질의는 글로벌 검색, 특정 대상 질의는 로컬 검색으로 분기 → 질의 유형에 맞는 근거 구성.
4. 근거 연결성 : 답변이 어떤 엔터티와 관계, 원문 조각에서 나왔는지 추적 가능 → 검증과 감사에 유리.

## Ⅲ. GraphRAG의 구조 (흐름)

- 핵심 요약 : 오프라인 인덱싱으로 그래프와 커뮤니티 요약을 만들고, 온라인에서 질의 유형에 따라 두 검색 경로 중 하나를 쓰는 구조.

```text
[ 1. 오프라인 인덱싱 ]

원시 문서 → 청킹
          ↓
LLM 엔터티·관계 추출
          ↓
지식 그래프 생성
          ↓ Leiden 군집화
계층적 커뮤니티 요약 (C0, C1, C2)
```

```text
[ 2. 온라인 검색 ]

사용자 질의
   ├─ 포괄 질의 → 글로벌 검색
   │    커뮤니티 요약 Map-Reduce
   └─ 특정 대상 질의 → 로컬 검색
        엔터티 이웃 탐색 + 원문 청크
          ↓
        LLM 답변 생성
```

- **Leiden 군집화** : 밀접하게 연결된 엔터티를 계층적 커뮤니티로 묶는 알고리즘.
- **커뮤니티 요약** (Community Summary) : 하위 커뮤니티 요약을 상위로 전달하며 만드는 계층형 보고서.
- **DRIFT 검색** : 커뮤니티 수준의 맥락으로 시작해 후속 질의로 로컬 검색을 확장하는 혼합 방식.

## Ⅳ. GraphRAG와 기존 RAG의 비교

- 핵심 요약 : 벡터 RAG는 빠르고 저렴하고, GraphRAG는 전체 조망과 다단계 추론에 강하지만 사전 비용이 크다.

| 비교 항목 | Vector RAG | 지식 그래프 (정형) | GraphRAG |
| --- | --- | --- | --- |
| 데이터 표현 | 임베딩 벡터 | RDF(Resource Description Framework)·OWL(Web Ontology Language) 트리플 | 그래프 + 커뮤니티 요약 + 원문 |
| 검색 방식 | 유사도 기반 Top-k 청크 | SPARQL(SPARQL Protocol and RDF Query Language), Cypher 질의 | 커뮤니티 Map-Reduce, 서브그래프 탐색 |
| 전체 코퍼스 요약 | 어려움 | 규칙 기반 질의 필요 | 글로벌 검색으로 지원 |
| 다단계 추론 | 청크 간 연결이 약함 | 경로 탐색에 강함 | 엔터티 이웃 탐색으로 강함 |
| 사전 구축 비용 | 낮음 (임베딩 연산) | 높음 (온톨로지 설계) | 높음 (LLM 추출·요약 토큰) |

- 단순 사실 질의에는 벡터 RAG가 효율적이고, 전체 주제 파악이나 복잡한 관계 분석에는 GraphRAG가 적합하다.

## Ⅴ. GraphRAG의 한계와 방안

- 핵심 요약 : 인덱싱 비용, 엔터티 중복, 인프라 이원화를 증분 갱신과 엔터티 정규화, 통합 DB로 통제.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 인덱싱 토큰 비용 | 모든 청크에 LLM 추출·요약 수행 → 초기 비용 큼 | 추출 단계에 소형 모델 적용, 변경 문서만 갱신하는 **증분 인덱싱** (Incremental Indexing) | 문서당 인덱싱 비용 |
| 엔터티 중복 | 같은 대상의 표기 차이로 노드가 갈라짐 → 관계 단절 | **엔터티 링킹** (Entity Linking)과 임베딩 기반 노드 병합 | 중복 노드 비율 |
| 인프라 이원화 | 그래프 DB와 벡터 DB 동기화 지연 | PostgreSQL(pgvector, Apache AGE) 같은 통합 DB 검토 | 동기화 지연 시간 |

## Ⅵ. GraphRAG의 기술사적 제언

- 핵심 요약 : 모든 질의를 GraphRAG로 처리하기보다, 질의 유형에 따라 벡터 RAG와 GraphRAG를 나누는 라우팅 구조가 비용 대비 효과가 크다.

1. 도메인 선별 도입 : 계약 검토, 법률 분쟁, 연구 문헌처럼 문서 간 관계 추적이 중요한 영역에 우선 적용한다.
2. 질의 라우터 설계 : 단순 사실 질의는 벡터 검색으로, 포괄 요약 질의는 글로벌 검색으로 분기하는 게이트웨이를 둔다.
3. 그래프 자산 관리 : 생성된 지식 그래프를 검색 전용 산출물로만 두지 않고, 사내 지식 탐색 화면과 연계해 재사용 가능한 자산으로 관리한다.

## Ⅶ. 결론

- 핵심 요약 : GraphRAG는 지식 그래프와 커뮤니티 요약으로 RAG의 포괄 질의와 관계 추론 한계를 보완하는 구조다.
- 시사점 : 효과는 그래프 품질과 인덱싱 비용 관리에 달려 있으므로, 질의 유형 분석을 먼저 수행해 적용 범위를 정해야 한다.
