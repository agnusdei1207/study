## 30초 인출

- 본질: **GraphRAG(Graph-based Retrieval-Augmented Generation)** 는 비정형 텍스트 코퍼스로부터 개체(Entity)와 관계(Relationship)를 추출하여 지식 그래프(Knowledge Graph)를 구축하고 계층적 커뮤니티 요약을 통해 전역적(Global) 추론 질의를 해결하는 차세대 RAG 아키텍처
- 메커니즘: LLM을 이용한 엔티티-관계 그래프 추출 후 Leiden 알고리즘으로 계층형 커뮤니티를 클러스터링하고, 질의 특성에 따라 세부 개체 탐색(Local Search) 또는 전역 요약(Global Search) 수행
- 통찰: 지식 그래프 구축 및 LLM 기반 커뮤니티 요약 시 막대한 토큰 비용과 인덱싱 지연이 발생하므로 증분(Incremental) 그래프 갱신 및 벡터-그래프 하이브리드 인덱싱 필수

<details><summary>핵심 용어</summary>

- **GraphRAG** : Microsoft Research가 제안한 지식 그래프 구조와 계층적 요약 기반의 고도화된 검색 증강 생성 기술.
- **지식 그래프 (Knowledge Graph)** : 문서 내 개체(노드), 개체 간 관계(엣지), 클레임(속성)을 그래프 데이터 모델로 정형화한 구조.
- **커뮤니티 감지 (Community Detection)** : 그래프 내에서 서로 밀접하게 연결된 노드 군집을 계층적으로 식별하는 알고리즘 (Leiden Algorithm).
- **Local Search** : 특정 엔티티와 직간접적으로 연결된 주변 이웃 노드 및 원본 청크를 집중 탐색하는 세부 사실 기반 검색.
- **Global Search** : 전체 문서 군집을 아우르는 상위 커뮤니티 요약 리포트를 맵리듀스(Map-Reduce) 방식으로 취합하여 전체 주제를 조망하는 검색.

</details>

## 2~4교시 예상문제 (25점)

> 대규모 문서 집합에 대한 전역적 질의 분석을 위한 'GraphRAG(Graph-based RAG)'의 개념과 기존 벡터 기반 RAG의 한계를 설명하고, 지식 그래프 인덱싱 파이프라인, Local Search와 Global Search 메커니즘 및 구축 비용 최적화 방안을 논하시오. (예상·25점)

## 2~4교시 25점 답안

## Ⅰ. GraphRAG의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **GraphRAG** 는 대규모 텍스트 데이터로부터 LLM을 활용해 엔티티, 관계, 주장을 자동으로 추출하여 지식 그래프(Knowledge Graph)를 구축하고, 계층적 커뮤니티 요약(Community Summary)을 통해 단편적 키워드 검색을 넘어 전체 코퍼스의 맥락적 종합 추론을 가능케 하는 검색 증강 기술 |
| 목적 | 전통적 벡터 RAG가 취약한 복합 관계 추적 및 코퍼스 전체 관점의 포괄적 질문("이 문서 전체의 핵심 테마 5가지는 무엇인가?") 해결 |

## Ⅱ. GraphRAG의 핵심 특징 및 벡터 RAG 대비 차별점

| 구분 | GraphRAG의 특징 | 세부 공학적 메커니즘 및 속성 |
|---|---|---|
| **구조적 관계 보존** | 엔티티 간 연결성 그래프 사상 | 청크 단위로 분절되지 않고 개체 간의 명시적 인과, 소속, 거래 관계를 엣지로 영구 보존 |
| **계층적 커뮤니티 요약** | Leiden 알고리즘 기반 클러스터링 | 그래프 토폴로지 상에서 밀접한 노드 집합을 C0(상위)부터 C3(하위)까지 계층별로 자동 요약 |
| **이원화된 질의 모드** | Local 및 Global 검색 지원 | 좁은 범위의 세부 사실(Factoid)과 넓은 범위의 종합 테마 요약(QFS)을 질의 의도에 맞게 선택 |
| **추론 연결성 (Multi-hop)** | 그래프 횡단(Graph Traversal) | A-B, B-C의 관계를 통해 A와 C 간의 은닉된 관계를 다단계 홉(Multi-hop)으로 자동 추론 |

## Ⅲ. GraphRAG 인덱싱 파이프라인 및 계층형 커뮤니티 구조

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ GraphRAG 오프라인 인덱싱 파이프라인 ]                 │
└────────────────────────────────────────────────────────────────────────┘
                                    │
 [ 1. 소스 텍스트 청킹 (Text Chunks) ] ──> 텍스트 청크 단위 분할 (기본 600 토큰)
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [ 2. 엔티티 및 관계 추출 (LLM Extraction) ]                             │
│  - 노드(사람, 조직, 장소, 기술) 및 엣지(관계 서술문), 클레임 추출      │
│  - 공통 엔티티 병합 및 지식 그래프(Knowledge Graph) 그래프 DB 적재      │
└────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [ 3. 계층형 커뮤니티 감지 (Hierarchical Community Detection) ]         │
│  - Leiden 알고리즘을 통한 서브그래프 군집화 (레벨 0: 광역 ~ 레벨 2: 국소)│
└────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [ 4. 커뮤니티 요약 리포트 생성 (Community Summarization) ]              │
│  - 각 커뮤니티별 핵심 발견점, 영향도, 대표 엔티티를 LLM으로 요약 생성   │
│  - 계층별 요약 리포트를 벡터 DB에 색인 ──> 온라인 질의 검색 준비 완료   │
└────────────────────────────────────────────────────────────────────────┘
```

| 파이프라인 단계 | 사용 알고리즘 및 도구 | 주요 산출물 |
|---|---|---|
| **엔티티 추출** | Few-Shot 프롬프트 기반 LLM 정보 추출 | 엔티티 목록, 관계 트리플 `(S, P, O)` |
| **커뮤니티 감지** | Leiden 알고리즘 (모듈러티 극대화) | 계층별 노드 군집 매핑 테이블 |
| **커뮤니티 요약** | 맵리듀스(Map-Reduce) 텍스트 요약 | 커뮤니티 리포트 (제목, 요약, 핵심 인사이트) |
| **임베딩 색인** | BGE-M3 / OpenAI 임베딩 | 엔티티 임베딩, 커뮤니티 리포트 벡터 인덱스 |

## Ⅳ. 전통적 벡터 RAG vs GraphRAG 비교

| 비교 항목 | 전통적 벡터 RAG (Vector RAG) | GraphRAG (Local Search) | GraphRAG (Global Search) |
|---|---|---|---|
| **검색 방식** | 청크 텍스트 코사인 유사도 | 지식 그래프 노드/엣지 탐색 | 커뮤니티 요약 리포트 맵리듀스 |
| **적합한 질의** | "X의 정의와 스펙은 무엇인가?" | "A와 B는 어떤 관계가 있는가?" | "이 문서군 전체의 주요 갈등은?" |
| **문맥 결손** | 청크 경계에서 문맥 단절 발생 | 엣지로 연결되어 문맥 보존 | 전체 요약으로 사각지대 완전 제거 |
| **인덱싱 비용** | 낮음 (단순 임베딩 1회) | 매우 높음 (LLM 추출 다단계) | 매우 높음 (LLM 요약 다단계) |
| **답변 포괄성** | 파편화된 상위 청크만 취합 | 연결된 엔티티 관계망 취합 | 전체 데이터셋의 종합 통찰 제공 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 수만 장의 대규모 문서에 대해 엔티티 추출과 커뮤니티 요약 시 수천만 토큰의 API 비용 및 시간 소모 | 소형 모델(sLLM: Mistral/Llama)로 개체 추출을 1차 오프로딩하고 핵심 상위 요약에만 고성능 LLM 투입 |
| 원본 문서가 1건 추가되거나 수정될 때 전체 그래프와 커뮤니티를 재계산해야 하는 비효율성 | 증분 인덱싱(Incremental Updating) 기술을 적용하여 변경된 노드의 로컬 서브그래프만 부분 갱신 |

## Ⅵ. 제언

질의 유형을 사전에 분류하여 단순 사실은 저비용 벡터 RAG로 처리하고, 복합 관계 및 전역 테마 질문에만 GraphRAG를 호출하는 하이브리드 라우팅 파이프라인 구축.

```text
[ 사용자 비즈니스 질의 인입 ]
               │
               ▼
[ 쿼리 인텐트 라우터 (Query Intent Router) ]
   ├── 단순 키워드/단일 사실 질문 ──> [ 기존 Dense/Sparse 하이브리드 벡터 RAG ]
   ├── 다중 개체 간 복합 관계 질문 ─> [ GraphRAG: Local Search (엔티티 그래프) ]
   └── 코퍼스 전체 테마/동향 요약 ──> [ GraphRAG: Global Search (커뮤니티 요약) ]
               │
               ▼
[ 최적 근거 컨텍스트 조합 및 비용 대비 정확도 극대화 응답 ]
```

| 구분 | 전체 GraphRAG 단독 운용 | 제언: 하이브리드 라우팅 운용 |
|---|---|---|
| **질의당 비용** | 모든 요청에 거대 그래프 횡단으로 고비용 | 80%의 단순 질의는 저비용 벡터 RAG로 해결 |
| **응답 지연(TTFT)**| 맵리듀스 취합으로 수초~수십초 지연 | 단순 질의는 1초 내 즉각 응답 반환 |
| **답변 완성도** | 특정 엔티티 세부 질의 시 과도한 요약 편향 | 질문 수준에 최적화된 맞춤형 컨텍스트 주입 |
