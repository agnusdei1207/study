## 30초 인출

- 본질: **XR (eXtended Reality, 확장현실)** 은 가상현실(VR), 증강현실(AR), 혼합현실(MR)을 모두 포괄하여 현실 세계와 가상 세계를 매끄럽게 연결하고 시각, 청각, 촉각을 아우르는 몰입형 인터랙션을 제공하는 공간 컴퓨팅(Spatial Computing) 기술의 총칭
- 메커니즘: 공간 센서(LiDAR/RGB 카메라) 및 6DoF 슬램(SLAM)으로 물리 환경을 매핑하고, GPU 렌더링 엔진으로 현실-가상 객체 정합(Registration)을 거쳐 광학/비디오 패스스루 디스플레이로 초저지연 표출
- 통찰: 기기 무게, 발열, 배터리 한계와 모션-투-포톤(MTP) 지연에 따른 사이버 멀미(Cyber Sickness)가 존재하므로 5G/6G MEC 기반 분산 렌더링과 시선 추적 기반 포비티드 렌더링(Foveated Rendering) 구축 필수

<details><summary>핵심 용어</summary>

- **XR (Extended Reality)** : VR, AR, MR 및 미래에 등장할 모든 가상융합 상호작용 기술을 아우르는 포괄적 상위 개념.
- **밀그램의 연속체 (Milgram's Reality-Virtuality Continuum)** : 순수 현실 환경(Real)부터 순수 가상 환경(Virtual)까지의 스펙트럼 상에 AR, MR, VR을 배치한 이론 모형.
- **6DoF (Six Degrees of Freedom)** : 전후·좌우·상하 이동(Translation)과 피치·요·롤 회전(Rotation)의 총 6가지 자유도를 추적하는 입체 추적 기술.
- **MTP 지연 (Motion-to-Photon Latency)** : 사용자의 머리 움직임이 센서에 감지된 후 디스플레이의 해당 픽셀 빛으로 갱신될 때까지의 총 지연시간 (20ms 이하 필수).
- **포비티드 렌더링 (Foveated Rendering)** : 사용자의 시선(Gaze)이 머무는 중심와 영역만 고해상도로 렌더링하고 주변 시야는 저해상도로 처리하여 GPU 부하를 70% 절감하는 기술.

</details>

## 2~4교시 25점 답안

## Ⅰ. XR의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **XR (eXtended Reality)** 은 컴퓨터 그래픽스로 구현된 디지털 가상 정보와 물리적 현실 세계를 융합하여 인간의 오감 상호작용과 공간적 몰입감을 극대화하는 VR, AR, MR 포괄 가상융합 기술 |
| 목적 | 2차원 평면 스크린의 정보 전달 한계를 극복하고 시공간 제약 없는 원격 협업, 고위험 모의훈련 및 제조·의료 현장의 생산성 혁신 달성 |

## Ⅱ. 밀그램의 현실-가상 연속체 및 XR 핵심 특징

| 구분 | 핵심 스펙트럼 및 기술 | 공학적 특징 |
|---|---|---|
| **현실 환경 (Real World)** | 아날로그 물리 세계 | 센서와 카메라로 디지털 캡처되는 원천 물리 공간 |
| **증강현실 (AR: Augmented)** | 현실 기반 + 가상 텍스트/객체 오버레이 | 스마트 글래스를 통해 현실 시야를 유지한 채 작업 가이드 표출 |
| **증강가상 (AV: Augmented Virtuality)** | 가상 기반 + 실시간 현실 객체 비디오 결합 | 가상 회의실 내에 실제 사용자 웹캠 비디오 스트림을 합성 |
| **가상현실 (VR: Virtual)** | 현실 차단 + 100% 디지털 합성 환경 | HMD(Head Mounted Display)로 외부 빛을 완전 차단한 몰입형 시뮬레이션 |
| **혼합현실 (MR / XR)** | 현실과 가상의 실시간 상호작용 (Occlusion) | 가상 공이 현실 테이블 뒤로 숨겨지는 차폐(Occlusion) 및 물리적 충돌 지원 |

## Ⅲ. XR 시스템의 센싱-컴퓨팅-렌더링-인터랙션 파이프라인

```text
┌────────────────────────────────────────────────────────────────────────┐
│             XR (eXtended Reality) 종단간 실시간 처리 파이프라인        │
└────────────────────────────────────────────────────────────────────────┘
 [ 물리 환경 & 사용자 움직임 (User Head/Hand Motion) ]
                         │
                         ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 1단계: 공간 인지 및 추적 계층 (Spatial Sensing & 6DoF Tracking)       │
 │  - Inside-out 카메라 + IMU 센서 ──> VIO(Visual Inertial Odometry)     │
 │  - 실시간 공간 3D 메쉬 생성: LiDAR 깊이 맵 + 공간 앵커(Spatial Anchor) │
 └───────────────────────┬──────────────────────────────────────────────┘
                         │ 6DoF 포즈 좌표 & 공간 메쉬 데이터
                         ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 2단계: 장면 계산 및 분산 렌더링 계층 (Compute & Split Rendering)      │
 │  - 5G/6G MEC 엣지 서버: 무거운 물리 엔진 연산 및 8K 가상 그래픽 렌더링 │
 │  - 시선 추적(Eye-tracking) 센서 연동 포비티드 렌더링(Foveated) 적용  │
 └───────────────────────┬──────────────────────────────────────────────┘
                         │ 인코딩된 비디오 스트림 전송
                         ▼
 ┌──────────────────────────────────────────────────────────────────────┐
 │ 3단계: 디스플레이 표출 계층 (Display & Time-Warp Correction)          │
 │  - 비동기 타임워프(ATW) / 스페이스워프(ASW)로 MTP 지연 15ms 이하 보정 │
 │  - 마이크로 OLED 패널 광학 투과 또는 비디오 패스스루(VST) 표출        │
 └───────────────────────┬──────────────────────────────────────────────┘
                         │ 시각 피드백
                         ▼
 [ 사용자 인지 및 핸드 트래킹/햅틱 피드백 상호작용 (Next Interaction) ]
```

| 파이프라인 단계 | 세부 동작 내용 | 핵심 성능 지표 |
|---|---|---|
| **공간 추적 (Tracking)** | 머리와 손의 6축 이동/회전 좌표를 1000Hz 주기로 추정 | 위치 추적 오차 < 1mm |
| **공간 정합 (Registration)** | 가상 객체의 3차원 좌표를 현실 가구 위에 고정 | 지터(Jitter) 방지 |
| **모션 보정 (Warping)** | 렌더링 지연 발생 시 최신 센서 데이터로 프레임을 왜곡 보정 | MTP Latency < 20ms |
| **광학 표출 (Optics)** | 팬케이크 렌즈를 통해 왜곡 없는 넓은 시야각(FOV) 제공 | FOV > 100도, PPD > 40 |

## Ⅳ. 실감형 인터페이스 비교 (VR vs AR vs MR vs XR)

| 비교 항목 | VR (가상현실) | AR (증강현실) | MR (혼합현실) | XR (확장현실 - 본 토픽) |
|---|---|---|---|---|
| **시야각 차폐** | 외부 시야 100% 완전 차단 | 현실 시야 유지 (광학 투과) | 현실 시야에 공간적 융합 | 사용 과업에 따라 가변 조절 |
| **공간 상호작용** | 가상 물체끼리만 상호작용 | 단순 현실 위 오버레이 | 현실 벽/테이블과 가상 상호작용 | 디지털 트윈 기반 물리-가상 동기화 |
| **주요 하드웨어** | Meta Quest, HTC Vive | 스마트 안경 (XREAL, HoloLens) | Apple Vision Pro (VST 방식) | 모든 차세대 공간 컴퓨팅 디바이스 |
| **핵심 기술** | 고해상도 HMD, 룸스케일 센서 | 웨이브가이드(Waveguide) 광학계 | 공간 음향, 실시간 깊이 센싱 | OpenXR 표준, 5G MEC 분산 처리 |
| **대표 유즈케이스** | 군사 모의훈련, 몰입형 게임 | 부품 조립 매뉴얼 가이드, 네비 | 원격 수술, 차량 3D 디자인 협업 | 메타버스, 가상융합 스마트 팩토리 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 신체 전정기관의 감각과 시각적 프레임 간의 시차(MTP Latency > 20ms)로 인해 어지럼증과 구토를 유발하는 사이버 멀미 | 비동기 타임워프(ATW) 알고리즘을 하드웨어 파이프라인에 내장하고 시선 추적 포비티드 렌더링으로 렌더링 지연을 15ms 이내로 단축 |
| 고화질 4K 패널 및 GPU 고속 연산에 따른 기기 발열, 무거운 무게(500g 이상) 및 짧은 배터리 지속 시간(2시간) | 배터리 및 무거운 렌더링 연산부를 허리 포켓이나 5G 초저지연 MEC 엣지 클라우드로 외재화하는 스플릿 렌더링(Split Rendering) 채택 |
| 기기 제조사(Meta, Apple, Google)별 독자 SDK 파편화로 인한 콘텐츠 개발 및 상호 호환성 비용 급증 | 크로노스 그룹의 개방형 표준 API인 OpenXR과 웹 표준 WebXR Device API 기반의 크로스 플랫폼 프레임워크 전면 준수 |

## Ⅵ. 제언

산업 현장 작업자의 착용성을 극대화하고 초저지연 몰입형 경험을 보장하기 위해 5G 특화망 MEC와 스플릿 렌더링 및 OpenXR 표준을 결합한 엔터프라이즈 XR 아키텍처 구축 권고.

```text
[ 현장 작업자: 초경량 XR 스마트 글래스 (150g 미만) ]
  - 센싱(6DoF SLAM + 손 추적) 및 디코딩/표출만 전담
                         │
                         ▲ 5G 특화망 초저지연 무선 전송 (URLLC: 지연 < 5ms)
                         │
┌────────────────────────┴───────────────────────────────┐
│ 공장 내 온프레미스 5G MEC 분산 렌더링 서버              │
│                                                        │
│  [ OpenXR 표준 런타임 레이어 (Unified API Core) ]      │
│  [ 언리얼/유니티 엔진: 8K 트윈 렌더링 + 피지컬 시뮬레이션]│
│  [ 고속 비디오 인코더 (H.266 / AV1 Ultra-Low Latency) ]│
└────────────────────────────────────────────────────────┘
```

| 구분 | 독립형 단독 구동 HMD (Stand-alone) | 제언: 5G MEC 분산 스플릿 XR 체계 |
|---|---|---|
| **기기 무게 및 발열** | 배터리/AP 일체형으로 무겁고 발열 심각 | 연산부 외재화로 초경량화(선글라스 형태) |
| **그래픽 충실도** | 모바일 GPU 수준의 저품질 그래픽 | 서버급 RTX GPU 활용으로 실사급 트윈 구현 |
| **배터리 지속력** | 1.5~2시간 (현장 교대근무 부적합) | 저전력 디코딩만 수행하여 6시간 이상 연속 작업 |
| **호환성** | 벤더 전용 OS에 종속 | OpenXR 표준 준수로 이종 기기 즉각 교체 가능 |
