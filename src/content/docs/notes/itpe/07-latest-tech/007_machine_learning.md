## 30초 인출

- 본질: **기계학습(Machine Learning)** 은 명시적인 규칙 코딩 없이 경험적 데이터(Experience)로부터 통계적 패턴과 내재된 함수 관계를 스스로 학습하여 특정 과업(Task)의 성능(Performance)을 점진적으로 향상시키는 인공지능의 핵심 분야
- 메커니즘: 목적 함수 및 손실 함수 정의 후 최적화 알고리즘(경사하강법)을 통해 가중치 파라미터를 반복 갱신하고, 독립된 검증 셋으로 일반화 오차 최소화
- 통찰: 데이터 누수(Data Leakage)와 과적합으로 실 배포 시 성능 급락이 빈번하므로 엄격한 시점 기준 데이터셋 분리 및 피처 엔지니어링 표준화 MLOps 파이프라인 결합 필수

<details><summary>핵심 용어</summary>

- **기계학습 (Machine Learning)** : 컴퓨터가 경험(E)을 통해 과업(T)에 대한 성능(P)을 개선하도록 알고리즘을 훈련하는 패러다임 (Tom Mitchell 정의).
- **손실 함수 (Loss Function)** : 모델의 예측값과 실제 타깃값 간의 오차를 수치화하는 목적 함수 (MSE, Cross-Entropy 등).
- **경사하강법 (Gradient Descent)** : 손실 함수의 기울기(Gradient) 반대 방향으로 모델 파라미터를 점진적으로 업데이트하여 최적해를 찾는 수치 최적화 기법.
- **편향-분산 트레이드오프 (Bias-Variance Tradeoff)** : 모델의 복잡도 변화에 따라 과소적합 오차(Bias)와 과적합 오차(Variance)가 상충하는 본질적 한계.
- **MLOps (Machine Learning Operations)** : 기계학습 모델의 데이터 수집, 학습, 검증, 배포, 모니터링 생애주기 전반을 자동화·안정화하는 엔지니어링 문화.

</details>

## 2~4교시 25점 답안

## Ⅰ. 기계학습의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **기계학습(Machine Learning)** 은 사람이 명시적인 규칙(Rule)을 직접 프로그래밍하지 않고, 대량의 데이터로부터 패턴과 통계적 관계를 스스로 학습하여 미지의 입력에 대해 유의미한 예측 및 판단을 수행하는 인공지능 핵심 기술 |
| 목적 | 복잡한 비선형 문제의 자동 해결, 데이터 기반의 객관적 의사결정 지원 및 환경 변화에 따른 모델 적응력 확보 |

## Ⅱ. 기계학습의 패러다임 특징 및 전통 프로그래밍 대비 속성

| 구분 | 전통적 프로그래밍 패러다임 | 기계학습 패러다임의 특징 |
|---|---|---|
| **입력 및 출력 구조** | `데이터(Data) + 규칙(Rules) ──> 정답(Answers)` | `데이터(Data) + 정답(Answers) ──> 규칙/모델(Model)` |
| **지식 획득 방식** | 도메인 전문가의 수작업 비즈니스 로직 if-else 하드코딩 | 데이터 내 특징(Feature) 간 수학적 가중치 자동 학습 |
| **복잡도 대응력** | 규칙 수 증가 시 조합 폭발 및 유지보수 불가능 | 고차원 비선형 특징 공간 최적화로 복잡계 대응 우수 |
| **적응성 (Adaptability)** | 환경 변화 시 소스코드 전면 수정 및 재배포 | 신규 데이터 인입에 따른 모델 파라미터 재학습 및 지속 개선 |

## Ⅲ. 기계학습 체계 및 엔드투엔드 파이프라인 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│               [ 엔드투엔드 기계학습(ML) 라이프사이클 프레임워크 ]          │
└────────────────────────────────────────────────────────────────────────┘
                                    │
 ┌──────────────────────────────────┴──────────────────────────────────┐
 │                                                                     │
 ▼                                                                     ▼
[ 데이터 엔지니어링 파이프라인 ]                          [ 모델 학습 및 검증 파이프라인 ]
1. 비즈니스 문제 정의 및 목표 수치 설정                   1. 알고리즘 선정 (선형, 트리, 신경망)
2. 원천 데이터 수집 (센서, 로그, DB)                     2. 손실 함수(Loss Function) 정의
3. 탐색적 데이터 분석 (EDA) 및 정제                     3. 옵티마이저 (SGD, Adam) 최적화
4. 피처 엔지니어링 (스케일링, 인코딩)                    4. 하이퍼파라미터 튜닝 (HPO)
5. 데이터 분할 (Train / Validation / Test)               5. 교차검증 (K-Fold Cross-Validation)
 └──────────────────────────────────┬──────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [ 배포 및 지속적 모니터링 파이프라인 ]                                  │
│  - CI/CD 파이프라인 결합, 모델 레지스트리(Model Registry) 등록         │
│  - 추론 서빙 (REST API / gRPC 스트리밍 / 엣지 온디바이스)               │
│  - 실시간 데이터 드리프트(PSI) 및 모델 성능(F1-Score) 감시              │
└────────────────────────────────────────────────────────────────────────┘
```

| 파이프라인 단계 | 핵심 공학적 활동 | 주요 산출물 및 통제 기준 |
|---|---|---|
| **데이터 준비** | 결측치 대체, 이상치 제거, 스케일링, 층화 분할 | 정제된 피처셋, 데이터셋 스키마 정의서 |
| **모델링·학습** | 손실 함수 역전파, 하이퍼파라미터 탐색(Optuna) | 체크포인트 가중치, 손실 곡선(Loss Curve) |
| **평가·검증** | 혼동행렬, ROC-AUC, 편향-분산 분해 분석 | 모델 성능 평가 보고서, 모델 카드 |
| **서빙·운영** | 컨테이너 패키징(Docker), A/B 테스트, 카나리 배포 | 실시간 추론 API, 드리프트 경보 시스템 |

## Ⅳ. 주요 기계학습 유형 비교

| 비교 항목 | 지도학습 (Supervised) | 비지도학습 (Unsupervised) | 강화학습 (Reinforcement) |
|---|---|---|---|
| **학습 데이터** | 입력 데이터 X와 타깃 라벨 Y 쌍 | 타깃 라벨 없는 순수 입력 데이터 X | 환경(Environment)의 상태와 피드백 |
| **학습 신호** | 예측 오차(Loss) 기반 가중치 수정 | 데이터 간 거리·밀도·유사도 통계 | 행동(Action)에 따른 보상(Reward) 신호 |
| **대표 알고리즘** | 선형회귀, 로지스틱, SVM, XGBoost | K-Means, DBSCAN, PCA, AutoEncoder | Q-Learning, DQN, PPO, SAC |
| **주요 적용 분야** | 이미지 분류, 질병 예측, 주가 예측 | 고객 군집화, 차원 축소, 이상 탐지 | 로봇 제어, 자율주행, 게임 AI, LLM 정렬 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 훈련 세트와 테스트 세트 간의 전처리 순서 오류로 인한 데이터 누수(Data Leakage) 발생 | Scikit-learn의 Pipeline/ColumnTransformer 객체를 활용하여 분할 전처리를 엄격히 캡슐화 |
| 서비스 운영 환경 변화로 인한 데이터 드리프트(Data Drift) 및 개념 드리프트(Concept Drift) 발생 | 인구통계 안정성 지수(PSI) 및 드리프트 모니터링 도구를 배포 파이프라인에 연결하여 임계치 초과 시 자동 재학습 파이프라인 트리거 |

## Ⅵ. 제언

실험 중심의 모델 개발에서 운영 중심의 MLOps 체계로 전환하고, 피처 스토어(Feature Store)와 모델 레지스트리를 연계한 재현성(Reproducibility) 보장 아키텍처 구축.

```text
[ 피처 엔지니어링 코드 ] ──> [ Feast 피처 스토어 (온/오프라인 동기화) ]
                                          │
                                          ▼
[ MLflow 실험 관리 ] ───────────> [ 분산 학습 파이프라인 ]
                                          │
                                          ▼
[ 사전 검증 완료 모델 ] ─────────> [ 모델 레지스트리 (승인 절차) ]
                                          │
                                          ▼
[ Triton/KServe 기반 서빙 ] ◄─── [ CI/CD 자동화 배포 ]
```

| 구분 | 초기 Ad-hoc 머신러닝 개발 | 제언: MLOps 기반 표준화 파이프라인 |
|---|---|---|
| **데이터 공유** | 데이터 과학자 로컬 CSV 파일 의존 | 중앙 집중식 Feature Store를 통한 단일 진실 공급원 |
| **실험 추적** | 노트북 파일명 수기 관리 (model_v2_final) | MLflow/WandB 기반 파라미터·메트릭·아티팩트 자동 로깅 |
| **배포 및 관리** | 모델 피클 파일 수동 복사 서빙 | 컨테이너 기반 CI/CD 파이프라인 및 자동 롤백 지원 |
