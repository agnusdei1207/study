## 답안 골격
### 1교시 예상문제 (10점)
스마트 계약의 실행 흐름과 가스·오라클의 역할을 설명하시오.

### 1교시 10점 답안
- **정의:** 온체인 트랜잭션 호출에 따라 미리 정한 코드를 실행하고 원장 상태를 변경하는 프로그램.
- **흐름:** 코드 배포 → 이용자 서명·호출 → EVM 실행과 가스 계산 → 합의된 상태 반영.
- **경계:** 가스는 계산 자원 측정·제한 수단, 오라클은 외부 데이터를 제공하는 연결점이며 원본 사실성의 자동 보장은 아님.

### 2~4교시 예상문제 (25점)
보험 스마트 계약의 구조와 재진입·오라클·업그레이드 위험 통제를 제시하시오.

### 2~4교시 25점 답안
1. **업무 구분:** 법률상 보험 계약과 온체인 지급 로직의 관계를 문서화하고 예외·분쟁 처리 절차 정의.
2. **구조:** 가입·지급 조건을 스마트 계약에 표현, 외부 사고 데이터는 출처가 검증된 오라클로 입력, 지급은 트랜잭션으로 기록.
3. **취약점:** 외부 호출 전 상태 갱신 누락의 재진입, 오류·조작된 오라클, 프록시 관리자 키 탈취와 로직 교체의 신뢰 위험.
4. **검증:** 불변식·단위·퍼즈·감사 시험, 다중 자료원 확인, 관리자 권한 분리·시간 지연·비상 중지와 모니터링.

 ┗━ Ⅵ 실무 ───── 배포 코드 변경의 제약과 프록시 업그레이드의 권한 위험 / 오라클 데이터의 출처·정확성 문제 / 재진입 공격

- 출제 이력: 117회·118회 공식 문제지 원문 미대조. 해당 회차의 실제 문항·표현 미확인

## 핵심 용어
- EVM(Ethereum Virtual Machine): 이더리움 스마트 계약 바이트코드의 실행 환경. 실행 클라이언트가 동일한 상태 전이를 검증하도록 규정한 가상머신
- 가스(Gas): 스마트 컨트랙트 실행 시 소모되는 연산 자원(CPU, 메모리, 스토리지)에 부과되는 실행 수수료로, 악의적인 무한 루프(DDoS) 공격을 방지하는 안전장치
- 오라클 문제(Oracle Problem): 스마트 컨트랙트는 블록체인 외부(오프체인)의 현실 세계 데이터(환율, 날씨, 스포츠 결과)를 스스로 읽어올 수 없으며, 데이터를 외부에서 주입할 때 그 출처의 조작 위험이 발생하는 난제

## 핵심 통찰
- 온체인 실행의 결정론성: 코드 실행 결과에 대한 신뢰 요구를 줄일 수 있지만 코드 결함, 관리자 권한, 키 탈취, 오라클 오류와 법적 분쟁 위험은 잔존
- 튜링 완전성과 가스(Gas) 메커니즘의 천재적 결합: 반복문(Loop)을 허용하는 순간 정지 문제(Halting Problem)로 인해 악의적 무한 루프 공격이 가능해지나, 바이트코드 연산마다 가스를 소모시켜 가스가 바닥나면 즉시 트랜잭션을 중단(Revert)시킴
- 배포 코드의 불변성과 업그레이드: 기존 주소의 배포 코드는 직접 변경하기 어려우나 프록시를 통한 로직 교체나 새 계약 이주가 가능하며, 업그레이드 관리자 권한을 별도로 통제할 필요

## 이웃 토픽과 구분
- 비트코인 스크립트 vs 이더리움 스마트 계약: 비트코인은 단순 서명 검증 위주의 튜링 불완전(Non-Turing complete, Loop 불가) 스크립트 / 이더리움은 튜링 완전 언어(Solidity)를 지원하여 임의의 복잡한 비즈니스 로직(DeFi, DAO) 구현 가능

## 문제·원인·대책
- 적용 상황: 글로벌 항공 지연 여행자 보험 스마트 컨트랙트 자동 보상 플랫폼 구축
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 배포 코드 취약점의 수정·이주 난항 | 배포 코드 자체는 직접 변경하기 어려움 | 프록시 업그레이드 또는 새 계약 이주와 관리자 권한·승인 절차 설계 | 복구 가능성과 권한 위험의 균형 검증 |
| 단일 외부 API 오류로 허위 결항 정보를 입력 | 소수 오라클·출처 의존 | 다중 출처 대조, 이상치 탐지, 분쟁·중지 절차 마련 | 오라클 오류 위험 저감 및 예외 대응 |
| 외부 호출 전 잔액 갱신 누락으로 재진입 | 상태 변경 순서 결함 | Checks-Effects-Interactions, 재진입 방지, 외부 호출·상속 경로 보안 검토 | 재진입 위험 완화와 회귀 시험 |
