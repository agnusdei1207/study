## 30초 인출
- 본질: 머신러닝 및 딥러닝 모델의 파라미터 최적화와 과업 수행 성능 평가를 위해 특정 도메인 요구사항에 맞추어 체계적으로 수집·정제·가공·검증된 정형·비정형 데이터 자산
- 메커니즘: 기획 및 데이터 설계 → 원천 데이터 수집/획득 → 데이터 정제 및 필터링 → 어노테이션(라벨링) → TTA 표준 기반 품질 검증 → 학습/검증/테스트 데이터셋 분할 및 계보 관리
- 통찰: 데이터셋의 평균 정확도 지표만 신뢰할 경우 롱테일 희소 환경에서의 성능 왜곡 및 편향이 누적되므로 데이터 계보(Lineage) 추적과 합성 데이터 기반의 능동형 불균형 완화 체계 필수

<details><summary>핵심 용어</summary>

- **인공지능 학습용 데이터(AI Training Data):** 알고리즘 모델의 가중치 학습, 하이퍼파라미터 튜닝 및 일반화 성능 평가를 목적으로 가공된 원천 및 어노테이션 데이터셋
- **TTAK.KO-10.1339:** TTA(한국정보통신기술협회)에서 제정한 지도학습용 데이터셋의 설계, 획득, 정제, 라벨링 단계별 품질 요건 및 검증 절차 표준
- **데이터 누출(Data Leakage):** 학습 데이터셋에 평가 또는 미래 시점의 정보가 혼입되어 평가 성능은 과대평가되나 실전 추론 시 성능이 급락하는 현상
- **데이터 계보(Data Lineage):** 데이터의 원천 출처, 정제 알고리즘, 라벨러 작업 이력, 변환 파이프라인의 전 라이프사이클을 추적하는 메타데이터 관리 체계
- **데이터 증강(Data Augmentation):** 회전, 크롭, 노이즈 주입 및 생성형 AI 기반 합성 데이터를 통해 데이터 다양성과 볼륨을 인위적으로 확장하는 기법

</details>

## 2~4교시 25점 답안

## Ⅰ. 인공지능 학습용 데이터의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | 인공지능 모델의 학습(Training), 검증(Validation), 시험(Test) 목적에 부합하도록 구조화된 메타데이터 및 정답 레이블을 포함한 고품질 데이터 자산 |
| 목적 | 알고리즘 가중치 최적화, 예측 성능 극대화, 편향성(Bias) 제거 및 실운영 환경에서의 일반화 능력(Generalization) 확보 |

## Ⅱ. 인공지능 학습용 데이터의 핵심 특징

| 특징 영역 | 주요 특성 | 상세 기술 및 품질 요건 |
|---|---|---|
| **도메인 대표성** | 실제 운영 환경 분포의 충실한 반영 | 엣지 케이스 및 롱테일(Long-tail) 데이터 포괄, 계층적 무작위 표본 추출 적용 |
| **라벨 정확성** | 지침 기반 일관된 어노테이션 품질 | 교차 검수(Cross-validation) 및 골드 스탠다드 셋 활용 라벨러 간 일치도(Cohen's Kappa) 확보 |
| **데이터 무결성** | 스키마 준수 및 결측/이상치 통제 | 정규화 규칙, 중복 데이터 제거, 인코딩 오류 방지 및 파일 포맷 무결성 보장 |
| **법적 적합성** | 저작권 및 개인정보보호 준수 | 가명·익명화 처리(비식별 조치), 이용 허락 라이선스 확보, AI 윤리 기준 준수 |

## Ⅲ. 인공지능 학습용 데이터 구축 라이프사이클 및 체계

### 1. 전주기 구축 라이프사이클 프로세스
```text
+-----------------------------------------------------------------------------------+
|               인공지능 학습용 데이터 엔드투엔드 라이프사이클 프레임워크           |
+-----------------------------------------------------------------------------------+
| [1. 기획/설계]                                                                    |
|   - 과업(Task) 정의 (분류, 탐지, 생성 등)                                         |
|   - 데이터 스키마, 수집 대상, 포맷(JSON, COCO 등) 및 저작권 검토                 |
|   - 라벨링 가이드라인(어노테이션 규칙) 수립                                       |
|                               │                                                   |
|                               ▼                                                   |
| [2. 수집/획득]                                                                    |
|   - 크롤링, 센서 로깅, 공공 데이터셋 수집, 오픈소스 라이브러리 연계               |
|   - 원천 데이터(Raw Data) 무결성 및 해시(SHA-256) 검증                           |
|                               │                                                   |
|                               ▼                                                   |
| [3. 정제/전처리]                                                                  |
|   - 노이즈 제거, 해상도 표준화, 이상치 필터링, 비식별화(개인정보 가명/익명 처리)   |
|   - 불균형 해소를 위한 규칙 기반 필터링                                           |
|                               │                                                   |
|                               ▼                                                   |
| [4. 가공/라벨링]                                                                  |
|   - 바운딩 박스, 폴리곤, 키포인트, 텍스트 토큰화, 시맨틱 세그멘테이션            |
|   - Auto-labeling (사전 학습 모델) + Human-in-the-loop (전문 라벨러 전수/표본 검수)|
|                               │                                                   |
|                               ▼                                                   |
| [5. 품질 검증 (TTA 표준)]                                                         |
|   - 원천 데이터 검증 (다양성, 분포, 파일 유효성)                                 |
|   - 라벨링 데이터 검증 (구문 정확성, 의미 정확성, 교차 일치도)                   |
|   - 모델 유효성 검증 (기준 모델 벤치마크 학습 및 성능 수렴성 확인)                |
|                               │                                                   |
|                               ▼                                                   |
| [6. 배포/관리]                                                                    |
|   - Train / Validation / Test 데이터셋 분할 (Data Leakage 완전 차단)              |
|   - DVC(Data Version Control) 기반 계보(Lineage) 및 카탈로그 관리                 |
+-----------------------------------------------------------------------------------+
```

### 2. 데이터 분할 구조 및 누출(Leakage) 방지
```text
전체 정제·검증 완료 데이터셋 (100%)
  ├── 학습용 데이터셋 (Train Set: 70~80%) ───────> 모델 파라미터(가중치/편향) 역전파 학습
  ├── 검증용 데이터셋 (Validation Set: 10~15%) ───> 하이퍼파라미터 튜닝 및 조기 종료(Early Stopping)
  └── 시험용 데이터셋 (Test Set: 10~15%) ─────────> 최종 배포 전 일반화 성능 단 1회 블라인드 평가
```

## Ⅳ. TTA 품질 검증 기준 및 일반 비정형 빅데이터와의 비교

### 1. TTA 표준(TTAK.KO-10.1339) 품질 검증 3대 체계
| 검증 영역 | 검증 항목 | 세부 측정 기준 및 검증 방법 |
|---|---|---|
| **원천 데이터 품질** | 데이터 적합성 | 수집 대상 환경 및 센서 스펙 준수, 파일 포맷 유효성 및 해상도 |
| | 데이터 다양성 | 클래스별 균등 분포, 환경적 조건(날씨, 조도, 연령 등) 포괄 비율 |
| **라벨링 데이터 품질** | 구문 정확성 | 어노테이션 포맷(JSON 스키마) 문법 오류, 필수 키값 누락 여부 전수 검증 |
| | 의미 정확성 | 경계 상자 오차(IoU >= 0.8), 분류 레이블 오분류율(통계적 표본 샘플링 검수) |
| **모델 유효성 품질** | 알고리즘 적합성 | 기준(Baseline) 모델 학습 후 목표 정확도(mAP, F1-Score, BLEU) 도달 검증 |
| | 일반화 유효성 | 테스트 셋 대상 추론 결과의 과적합(Overfitting) 발생 유무 확인 |

### 2. 일반 비정형 빅데이터 대비 비교
| 비교 항목 | 일반 비정형 빅데이터 | 인공지능 학습용 데이터 |
|---|---|---|
| **데이터 목적** | 비즈니스 통계 분석 및 패턴 모니터링 | 기계학습 모델의 최적 가중치 도출 및 추론 학습 |
| **구조화 수준** | 로그, 텍스트, 원본 이미지 등 원시 형태 | 정밀한 메타데이터 및 정답 레이블(Ground Truth) 결합 형태 |
| **품질 핵심** | 대용량 수집 볼륨 및 데이터 신선도 | 데이터 편향 배제, 라벨링 일관성 및 정밀도 |
| **관리 체계** | 데이터 레이크(Data Lake) 저장 중심 | DVC 기반 버전 관리, 계보 추적 및 데이터셋 스플릿 분리 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| **클래스 불균형 및 롱테일 데이터 부재**<br />특정 정상 클래스에 데이터가 편중되어 희귀 불량 및 위험 상황 인식 실패 발생 | Diffusion 및 GAN 기반 합성 데이터(Synthetic Data) 생성 기법 적용, 능동 학습(Active Learning)으로 불확실성 높은 희소 데이터 선별 수집 |
| **라벨러 주관성 개입에 따른 일관성 저하**<br />인력 중심 라벨링으로 인해 작업자 간 판정 기준 상이 및 노이즈 라벨 혼입 | 합의 기반 다중 라벨링(Majority Voting), 골드 스탠다드 검증 셋 주기적 삽입, 라벨러 숙련도 평가 메트릭 운영 |
| **저작권 및 개인정보 침해 리스크**<br />웹 크롤링 데이터 내 저작권 보호물 포함 및 초상권/식별자 유출로 법적 분쟁 초래 | 데이터 정제 단계에서 자동 블러링/마스킹 파이프라인 구축, TDM(텍스트·데이터 마이닝) 면책 규정 준수 및 저작권 클리어런스 프로세스 확립 |

## Ⅵ. 제언

인공지능 모델 중심(Model-centric)에서 고품질 데이터 중심(Data-centric) AI 패러다임으로의 전환이 필수적이며, 지속적인 MLOps/DataOps 통합 파이프라인 구축이 요구됨.

```text
[원천 데이터] ──> [DataOps 자동화] ──> [TTA 기준 품질 게이트] ──> [MLOps 학습 파이프라인]
       ▲                                                              │
       └────────────────── 피드백 루프 (Active Learning) ─────────────┘
```

| 패러다임 구분 | Model-Centric AI | Data-Centric AI |
|---|---|---|
| **접근 방식** | 데이터셋 고정 후 모델 아키텍처/하이퍼파라미터 튜닝 | 모델 아키텍처 고정 후 데이터 품질/라벨 노이즈 개선 |
| **품질 향상 수단** | 복잡한 딥러닝 앙상블 및 손실 함수 수정 | 데이터 정제, 일관된 라벨링 가이드, 결측 보정 |
| **현장 적용성** | 연구 환경 대비 실무 엣지 케이스 취약 | 실무 도메인 오차 원인 제거로 배포 안정성 극대화 |
