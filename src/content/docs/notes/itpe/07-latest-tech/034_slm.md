## 연관 키워드

- 소형 언어 모델(sLM, Small Language Model), 거대언어모델(LLM, Large Language Model)
- 지식 증류(Knowledge Distillation), 양자화(Quantization), GGUF, llama.cpp
- 온디바이스 AI(On-device AI), 엣지 추론, 프라이빗 RAG
- GQA(Grouped-Query Attention), 교과서 데이터(Textbook Data), 총소유비용(TCO)

## Ⅰ. 소형 언어 모델(Small Language Model, sLM)의 개요

- 핵심 요약 : 수 B(Billion) 규모의 파라미터로 특정 업무에 집중해, 단일 장비에서 구동 가능한 언어 모델.
- 개념 : 수백억~수조 개 파라미터의 거대언어모델과 달리, 약 1B~14B 파라미터 규모로 경량화하면서 고품질 데이터와 **지식 증류** (Knowledge Distillation)로 특정 업무에서 큰 모델에 근접한 정확도를 내도록 설계된 언어 모델.
- 배경 및 필요성 : 거대 모델은 GPU(Graphics Processing Unit) 서버 비용과 추론 지연이 크고, 기업 기밀을 외부 클라우드로 보내는 데 부담이 있다. 또한 스마트폰과 차량 같은 엣지 기기에서 오프라인으로 동작해야 하는 요구도 커졌다.
- 주요 목적 : 단일 장비에서의 저지연·저비용 추론, 사내망 안에서의 데이터 격리, 업무별 특화 성능 확보.

## Ⅱ. 소형 언어 모델(Small Language Model, sLM)의 특징 및 장점

- 핵심 요약 : 작은 규모와 특화 학습이 낮은 운영 비용과 데이터 보안으로 이어지는 구조.

1. 경량 구동 : 파라미터가 작아 단일 GPU나 NPU(Neural Processing Unit) 환경에서 실행 → 서버 투자 비용 절감.
2. 데이터 격리 : 사내망이나 기기 내부에서 추론 → 외부 전송에 따른 유출 위험 감소.
3. 저렴한 특화 : 소량의 사내 데이터로 미세 조정 가능 → 업무별 정확도를 낮은 비용으로 확보.
4. 교과서 데이터 학습 : 정제된 합성 교재형 데이터를 집중 투입 → 적은 파라미터로도 추론 능력 확보 시도.

## Ⅲ. 소형 언어 모델(Small Language Model, sLM)의 구조 (흐름)

- 핵심 요약 : 대형 모델의 지식을 증류하고 정제 데이터로 학습한 뒤, 양자화해 엣지 기기에 배포하는 3단계 구조.

```text
[ 프론티어 거대 LLM ]
          ↓ 지식 증류 / 교과서형 데이터 합성
[ 정제된 학습 데이터 ]
          ↓ 사전 학습 · SFT
[ 컴팩트 트랜스포머 (1B~14B) ]
          ↓ 양자화 · 포맷 변환
[ 엣지·온디바이스 런타임 ]
```

- 지식 증류 : 교사 모델의 출력 확률 분포를 학생 모델이 모사하도록 학습하는 방식.
- **GQA** (Grouped-Query Attention) : 여러 질의 헤드가 키·값 헤드를 공유해 KV(Key-Value) 캐시 메모리를 줄이는 구조.
- **양자화** (Quantization) : 16비트 부동소수점 가중치를 4비트 정수 등으로 줄여 메모리 요구를 낮추는 기법.

## Ⅳ. 초거대 LLM과 소형 언어 모델의 비교

- 핵심 요약 : 범용 지식은 거대 모델이, 비용과 보안은 소형 모델이 우위에 있어 업무 특성에 따라 나눠 쓴다.

| 비교 항목 | 초거대 LLM | 소형 언어 모델 (sLM) |
| --- | --- | --- |
| 파라미터 규모 | 수십B ~ 수조 개 | 약 1B ~ 14B |
| 인프라 요구 | 다수 GPU 클러스터 필요 | 단일 GPU 또는 온디바이스 NPU |
| 서빙 비용 | 토큰 과금 또는 고가 서버 임대 | 기존 서버 활용 가능, 낮음 |
| 보안 | 외부 전송에 따른 유출 리스크 | 사내망 격리 구동 가능 |
| 범용 지식 | 방대한 지식 보유 | 지식 용량 제한, RAG로 보완 |
| 도메인 특화 | 미세 조정 비용이 큼 | 소량 데이터로 저비용 특화 |

- 최근 기업 아키텍처는 모든 업무에 거대 모델을 쓰지 않고, 일상 업무는 sLM에 맡기고 복잡한 요청만 상용 LLM으로 넘기는 혼합 구성을 택하는 추세다.

## Ⅴ. 소형 언어 모델(Small Language Model, sLM)의 한계와 방안

- 핵심 요약 : 지식 용량, 다단계 추론, 지시 준수 능력의 한계를 검색 증강과 추론 특화, 추가 학습으로 보완.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 사실 지식 부족 | 파라미터 용량 제한 → 사실 오류와 환각 | 사내 문서를 벡터 DB에서 검색해 주입하는 **프라이빗 RAG** (RAG, Retrieval-Augmented Generation) | 근거 일치율 |
| 다단계 추론 한계 | 복잡한 증명·리팩토링에서 중간 단계 누락 | 추론 특화 증류 모델 도입, **CoT** (Chain of Thought) 단계별 검증 프롬프트 | 단계별 정답률 |
| 낯선 지시 대응 약함 | 학습되지 않은 형식의 지시에서 실패 | 사내 출력 스키마(**JSON** (JavaScript Object Notation)) 기준 추가 **SFT** (Supervised Fine-Tuning), 예시 제공 | 형식 준수율 |

## Ⅵ. 소형 언어 모델(Small Language Model, sLM)의 기술사적 제언

- 핵심 요약 : 업무별로 작은 모델을 분리해 운영하고, 복잡도에 따라 상용 모델과 나누는 라우팅 구조가 현실적이다.

```text
[ 요청 라우팅 흐름 ]

사용자 요청
      ↓ 복잡도·보안 등급 판별
      ├─ 단순·사내 업무 → sLM 처리
      └─ 복잡·범용 요청 → 상용 LLM 처리
```

1. 업무 단위 특화 : 요약, 코드 검토, 계약서 검토처럼 업무별로 소형 모델을 분리해 미세 조정하고, 각 업무의 성능 기준을 따로 관리한다.
2. 사내 엣지 서빙 표준화 : 고가 GPU가 없는 서버에서도 동작하도록 양자화 포맷과 경량 런타임을 표준으로 정한다.
3. 모델 라우터 도입 : 입력의 복잡도와 보안 등급을 판별해 sLM과 상용 LLM 중 어디로 보낼지 결정하는 게이트웨이를 둔다.

## Ⅶ. 결론

- 핵심 요약 : 소형 언어 모델은 작은 규모와 특화 학습으로 비용과 보안 요구를 충족하는 언어 모델이다.
- 시사점 : 범용 성능 경쟁과 별개로, 업무별 특화와 운영 구조 설계가 도입 성패를 가르므로 모델 크기보다 업무 적합성을 기준으로 선택해야 한다.
