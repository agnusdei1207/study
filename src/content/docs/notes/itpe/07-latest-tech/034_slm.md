```text
 ┃
 ┣━ Ⅰ 개요 ───── 수천억 파라미터 LLM의 천문학적 인프라 비용·지연 한계 → 1B~10B급 초경량 고효율 모델
 ┣━ Ⅱ 특징 ───── 고품질 정제 데이터 집중 학습 · 낮은 서빙 TCO · 온디바이스 탑재 가능 · 특정 도메인 특화
 ┣━ Ⅲ 구조 ───── 경량 트랜스포머 백본 + 양자화 계층(GGUF/AWQ) + 도메인 어댑터(LoRA/PEFT)
 ┣━ Ⅳ 흐름 ───── ① 고성능 LLM 교사 생성 → ② 지식 증류(Logit/Feature) → ③ 가중치 양자화 → ④ 도메인 파인튜닝
 ┣━ Ⅴ 비교 ───── 거대 언어모델(LLM) vs 소형 언어모델(sLM) (범용 추론/고비용 vs 특정 도메인/저지연)
 ┗━ Ⅵ 실무 ───── 환각(Hallucination) 취약성 / 복합 추론 한계 / 지식 용량 한계에 따른 RAG 연계 필요
```
- 필수 키워드: 매개변수 규모(1B~10B) · 지식 증류(Knowledge Distillation) · 파라미터 효율적 튜닝(PEFT/LoRA) · 양자화(Quantization) · 온디바이스 AI · TCO 절감
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 경량화 구조도 → Ⅴ LLM vs sLM 비교표 / 25점 = Ⅰ~Ⅶ 전개, 지식 증류 수식 원리와 도메인 프라이빗 서빙 아키텍처 집중
- 기출: 미출제. 예상: "최근 기업의 생성형 AI 도입 시 부각되는 sLM(Small Language Model)의 개념, 경량화 핵심 기술, LLM과의 차이점 및 비즈니스 활용 전략을 설명하시오."

## 한 줄 본질
- 수천억 개 파라미터 LLM의 막대한 GPU 인프라 비용과 데이터 유출 리스크 → 고품질 합성 데이터 학습과 지식 증류를 통해 10B 이하 크기로 축소 → 단일 GPU/온디바이스 구동과 폐쇄망 보안 확보 / 복합 상식 추론 용량의 축소

## 핵심 그림
```text
[sLM 구축 및 경량 서빙 파이프라인]
[대형 교사 모델 (LLM 70B~405B)]
              |
              | (1) 지식 증류 (Knowledge Distillation)
              v     - 로짓 분포(Soft Target) 및 중간 특성 전이
[소형 학생 모델 (sLM 1B~8B)] (예: LLaMA-3.2-3B, Phi-3.5, Qwen2.5)
              |
              | (2) 도메인 특화 파인튜닝 (LoRA / QLoRA)
              +---> [사내 지식/전문 데이터셋 주입]
              |
              | (3) 가중치 압축 및 양자화 (INT4/INT8, AWQ, GGUF)
              v
[초경량 엣지 / 온프레미스 단일 GPU 서빙 (VRAM < 8GB)]
```

## 핵심 용어
- 지식 증류(Knowledge Distillation): 거대 교사 모델의 연판정(Soft Target) 로짓 분포를 경량 학생 모델이 모사하도록 손실 함수를 설계해 압축하는 기법
- Textbooks Are All You Need: 마이크로소프트 Phi 시리즈가 입증한 원리로, 웹 크롤링 원시 텍스트 대신 고품질 교과서급 정제 합성 데이터로 학습하면 소형 파라미터로도 대형 모델 급 지능 달성 가능
- 양자화(Quantization): FP16/FP32 부동소수점 가중치를 INT8/INT4 정수형으로 변환해 연산 속도를 높이고 VRAM 요구량을 1/4 수준으로 압축하는 기술

## 핵심 통찰
- 파라미터 수가 지능을 결정한다는 "스케일링 법칙"의 맹점을 깨고, "데이터의 질(Data Quality)"이 모델의 크기 한계를 극복할 수 있음을 실증
- 기업 실무에서 범용 상식 추론(시 쓰기, 철학 논쟁)은 불필요하며, 특정 사내 규정이나 정형 API 호출 작업에는 잘 튜닝된 3B~8B sLM이 70B LLM보다 응답 속도와 비용 면에서 우세
- 지식 자체를 파라미터 가중치에 암기시키는 대신 외장 지식 베이스(RAG)를 참조하게 분리하면 sLM의 환각을 완벽히 통제 가능

## 이웃 토픽과 구분
- sLM vs 온디바이스 AI: sLM은 모델 파라미터 크기(Scale) 관점의 소프트웨어 아키텍처 분류 / 온디바이스 AI는 NPU·스마트폰 등 클라이언트 단말에서 실행되는 인프라·배치 관점의 개념

## 문제·원인·대책
- 적용 상황: 사내 금융 상담 챗봇 구축 시 단일 서버 기반 폐쇄망 운영 요구
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 사내 특수 금융 약관 질의 시 엉뚱한 오답(환각) 생성 | sLM 내부 파라미터 지식 용량 한계 및 최신 데이터 미반영 | 하이브리드 RAG(Vector+BM25) 파이프라인 연계 | 모델 가중치 암기 의존도 제거 및 답변 정확도 보장 |
| 소형화로 인한 다단계 추론(CoT) 및 연쇄 논리 결함 | 파라미터 축소에 따른 심층 추론 신경망 층수 부족 | DPO 기반 선호도 정렬 및 도메인 특화 Few-shot 템플릿 표준화 | 단계별 사고 유도 및 비즈니스 로직 준수율 제고 |
| 온디바이스 탑재 시 배터리 소모 및 지연시간 발생 | FP16 서빙 시 메모리 대역폭 한계 및 과도한 부동소수점 연산 | AWQ/GGUF 기반 4비트 양자화 및 NPU 전용 커널 가속 | VRAM 사용량 70% 절감 및 실시간 스트리밍 추론 구현 |

## 내 의견
- [도메인 지식 분리형 sLM + RAG 하이브리드 아키텍처] 수천억 파라미터 LLM을 사내에 직접 구축하려는 시도는 유지보수 비용과 GPU 감가상각으로 실패하기 쉬움 → 나라면: 오픈소스 기반 7B~8B sLM(Qwen/LLaMA)을 선정하여 AWQ 4비트 양자화를 거친 뒤 사내 단일 워크스테이션에 올리고, 지식 갱신은 파인튜닝이 아닌 사내 벡터 DB 기반 GraphRAG로 분리하는 경량 아키텍처를 도입하여 보안과 가성비 동시 확보
