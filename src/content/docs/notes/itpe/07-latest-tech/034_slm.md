## 30초 인출

- 본질: **소형 언어 모델(sLM, Small Language Model)** 은 수십억(1B~14B) 규모의 파라미터로 매개변수를 압축하여 온프레미스 서버나 엣지 온디바이스 환경에서 저비용·저지연으로 특정 도메인 과업을 고정밀 수행하는 경량화 언어모델
- 메커니즘: 거대 교사 모델의 지식 증류(Distillation), LoRA 기반 파라미터 효율 미세조정(PEFT), INT4/FP8 양자화(Quantization)를 거쳐 도메인 특화 RAG와 결합 추론
- 통찰: 범용 추론 능력 및 상식 지식의 축소로 복잡한 다단계 논리에서 오류가 발생하므로 도메인 맞춤 지식 증강(RAG)과 고난도 질의 발생 시 상용 LLM으로의 폴백 라우팅 결합 필수

<details><summary>핵심 용어</summary>

- **sLM (Small Language Model)** : 파라미터 크기 10B 이하 수준으로 단일 상용 GPU 또는 NPU에서 실시간 서빙이 가능한 경량 언어 모델 (Phi-3, Gemma-2, Llama-3-8B).
- **지식 증류 (Knowledge Distillation)** : 대형 교사 모델(Teacher)의 소프트 라벨 확률 분포를 소형 학생 모델(Student)이 모방 학습하도록 지도하는 압축 기법.
- **PEFT (Parameter-Efficient Fine-Tuning)** : 사전학습 가중치를 동결하고 0.1~1% 미만의 극소수 저순위 어댑터 가중치만 학습시키는 기법.
- **LoRA (Low-Rank Adaptation)** : 가중치 갱신 행렬 $\Delta W$를 두 개의 저순위 행렬 $A \times B$로 분해하여 GPU VRAM 요구량을 70% 이상 절감하는 PEFT 대표 기법.
- **양자화 (Quantization)** : 16비트 부동소수점(FP16) 파라미터를 8비트(INT8) 또는 4비트(INT4) 정수형으로 압축하여 메모리 대역폭과 연산 지연을 단축하는 기법 (AWQ, GPTQ).

</details>

## 2~4교시 25점 답안

## Ⅰ. 소형 언어 모델(sLM)의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **소형 언어 모델(sLM)** 은 100B 이상의 초거대 LLM 대비 매개변수 크기를 1B~14B 수준으로 경량화하면서도, 양질의 도메인 특화 데이터 학습과 압축 기술을 통해 특정 산업 도메인에서 대형 모델에 필적하는 정확도를 제공하는 실용적 인공지능 모델 |
| 목적 | 천문학적인 GPU 인프라 및 API 비용 절감, 데이터의 외부 유출 없는 온프레미스 완결, 모바일/PC 온디바이스 실시간 추론 실현 |

## Ⅱ. sLM의 핵심 특징 및 LLM 대비 4대 차별점

| 구분 | sLM의 핵심 특징 | 세부 공학적 메커니즘 및 속성 |
|---|---|---|
| **저비용 고효율 TCO** | 단일 상용 GPU 구동 | 고가의 8-Way H100 서버 없이 저렴한 단일 RTX 4090 또는 A10G 환경에서 초당 50토큰 이상 서빙 |
| **데이터 보안 완결성** | 완벽한 폐쇄망 에어갭 구축 | 민감한 금융 계정계, 의료 기록, 국방 기밀 데이터를 외부 클라우드 전송 없이 사내에서 100% 처리 |
| **초저지연 응답성 (Low Latency)** | 빠른 첫 토큰 생성 (TTFT) | 파라미터 경량화로 메모리 대역폭 병목을 탈피하여 실시간 음성 비서 및 엣지 로봇 제어에 최적화 |
| **도메인 특화 정밀성** | 버티컬 AI (Vertical AI) 최적화 | 범용 상식 지식을 덜어내고 특정 기업의 사내 용어, ERP 코드, 법률 서식에만 집중 학습하여 높은 업무 정확도 달성 |

## Ⅲ. sLM 경량화 및 도메인 적응 파이프라인 아키텍처

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ sLM 구축 및 온프레미스 서빙 파이프라인 ]              │
└────────────────────────────────────────────────────────────────────────┘
                                    │
 [ 1. 교사 모델 기반 지식 증류 ] ───► [ 2. 파라미터 효율 미세조정 (LoRA) ]
  - GPT-4 / Claude 고품질 합성 데이터 - 베이스 모델 가중치(W_0) 동결
  - Temperature 소프트 타깃 손실 전이 - 저순위 행렬 A, B (Rank r=8, 16)만 훈련
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [ 3. 하드웨어 맞춤형 양자화 (Quantization: AWQ / GPTQ) ]                │
│  - FP16 (16GB) ──> INT4 (4GB) 압축 (가중치 양자화 및 활성화 스케일링) │
│  - 정확도 손실 1% 미만 유지 및 메모리 75% 절감                         │
└────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [ 4. 엔터프라이즈 RAG 결합 및 vLLM 서빙 ]                               │
│  - 사내 Milvus 벡터 DB 하이브리드 검색 결합 ──> 최신 지식 보완          │
│  - PagedAttention 기반 연속 배치(Continuous Batching) 고속 서빙       │
└────────────────────────────────────────────────────────────────────────┘
```

| 엔지니어링 기술 | 핵심 메커니즘 | 공학적 효과 |
|---|---|---|
| **지식 증류 (Distillation)** | $\mathcal{L}_{\text{KD}} = \text{KL}(P_{\text{Teacher}} \parallel P_{\text{Student}})$ | 초대형 모델의 추론 논리와 지식을 작은 파라미터에 압축 전이 |
| **LoRA (PEFT)** | $W = W_0 + \Delta W = W_0 + B \cdot A$ ($B \in \mathbb{R}^{d \times r}, A \in \mathbb{R}^{r \times k}$) | 학습 파라미터 99% 감축으로 단일 GPU에서 수시간 내 파인튜닝 |
| **AWQ 양자화** | 중요 가중치 채널을 보존하는 Activation-aware 양자화 | INT4 정수화로 VRAM 점유율 1/4 감축 및 추론 처리량 3배 가속 |
| **vLLM 서빙 엔진** | OS의 가상 메모리 페이징을 모방한 PagedAttention | KV 캐시 메모리 단편화 0% 달성 및 다중 동시 접속 수용 |

## Ⅳ. 초대형 LLM vs 소형 sLM 비교

| 비교 항목 | 초대형 LLM (Frontier LLM: 100B+) | 소형 sLM (Small Language Model: 1B~14B) |
|---|---|---|
| **파라미터 규모** | 70B ~ 1T+ 파라미터 | 1.5B, 3B, 7B, 14B 파라미터 |
| **하드웨어 요구사항** | 멀티 노드 8x H100 클러스터 필수 | 단일 소비자용 GPU (RTX 4090) 또는 NPU |
| **배포 환경** | 퍼블릭 클라우드 전용 인프라 | 사내 온프레미스 폐쇄망, 모바일/노트북 엣지 |
| **학습 및 서빙 비용** | 수십억 원 이상의 초기 투자 및 토큰 과금 | 수백만 원대 하드웨어 구매로 고정 운영비화 |
| **추론 능력** | 복잡한 다단계 논리, 코딩, 철학, 번역 우수 | 도메인 특화 태스크(분류, 정보 추출, 질의응답) 우수 |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 파라미터 축소로 인해 복잡한 다단계 상식 추론 및 세계 지식 저장 용량의 한계 | 외부 사내 지식을 실시간 주입하는 RAG 파이프라인 결합 및 추론 전용 CoT(Chain-of-Thought) 프롬프팅 적용 |
| 지나친 4비트 양자화 적용 시 특정 코너 케이스에서 퍼플렉서티(Perplexity) 급증 및 성능 왜곡 | 양자화 민감도 분석을 통해 주요 어텐션 레이어는 FP16을 유지하고 나머지만 INT4로 변환하는 혼합 정밀도(Mixed-Precision) 채택 |

## Ⅵ. 제언

사내 모든 업무를 단일 모델로 처리하지 않고, 일상 업무 80%는 저비용 sLM으로 자체 처리하고 미해결 난제 20%만 상용 대형 LLM으로 에스컬레이션하는 2-Tier 스마트 라우팅 아키텍처 구축.

```text
[ 사내 임직원 업무 요청 인입 ]
               │
               ▼
[ 1차 처리: 사내 온프레미스 sLM (vLLM 구동) ]
   ├── Step 1: 사내 규정 조회, 이메일 초안, 정형 보고서 요약 즉시 처리
   ├── Step 2: sLM 자체 신뢰도 점수(Confidence Score) 산출
   └── Step 3: 신뢰도 85점 미만 또는 고난도 계약서 법률 검토 감지
               │
          ┌────┴─────────────────────────────┐
          ▼ (신뢰도 충족: 80% 트래픽)          ▼ (고난도 에스컬레이션: 20% 트래픽)
    [ 즉시 응답 완료 ]                  [ 외부 보안 전용망 대형 LLM API 호출 ]
```

| 구분 | 전면 상용 대형 LLM API 사용 | 제언: sLM 중심 2-Tier 스마트 라우팅 |
|---|---|---|
| **보안 노출** | 모든 사내 데이터가 외부 클라우드 전송 | 80%의 일상 데이터는 사내 폐쇄망에서 완결 |
| **토큰 비용** | 월 수천만 원 API 요금 지속 청구 | 사내 sLM 우선 활용으로 API 비용 80% 절감 |
| **응답 속도** | 외부 네트워크 호출로 지연 발생 | 사내 초고속 로컬 서빙으로 업무 생산성 극대화 |
