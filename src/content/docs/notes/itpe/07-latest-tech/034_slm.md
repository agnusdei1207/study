## Ⅰ. 소형 언어 모델(Small Language Model, sLM)의 개요

- 개념 : 수백억~수조 개 파라미터의 **거대언어모델** (LLM, Large Language Model)과 달리, 1B(10억)~14B(140억) 파라미터 내외의 경량화된 모델 크기를 유지하면서도 고품질 정제 데이터와 지식 증류(Knowledge Distillation)를 통해 특정 업무나 **온디바이스** 환경에서 거대 모델에 필적하는 정확도를 발휘하도록 최적화된 소형 고성능 언어 모델.
- 배경 및 필요성 : 초거대 LLM의 천문학적인 GPU(Graphics Processing Unit) **서빙 인프라 비용** (TCO, Total Cost of Ownership), 높은 추론 지연 시간, 기업 기밀 데이터 유출 위험, 스마트폰·차량·로봇 등 **엣지 디바이스** 에서의 오프라인 자율 구동 요구에 부응하여 급속도로 발전함.
- 핵심 목적 : 단일 상용 GPU/NPU(Neural Processing Unit) 기반 초저지연·저비용 추론, **기업 내부 인프라** (On-Prem) 완전 격리를 통한 보안 확보, 도메인 특화 태스크(코딩, 계약서 분석)의 초정밀화.

## Ⅱ. 소형 언어 모델(Small Language Model, sLM)의 핵심 아키텍처 및 동작 메커니즘

sLM은 대규모 파운데이션 모델로부터의 지식 증류, 교과서급 초고품질 합성 데이터 학습, 구조적 가중치 압축 파이프라인을 통해 완성됨.

```text
[ sLM 구축 및 경량화 서빙 엔지니어링 파이프라인 ]

  [ 프론티어 거대 LLM (GPT-4o, Claude 3.5) ]
                     │
         ┌───────────┴───────────┐
         │ 1. 교과서급 데이터 합성│ 2. 로짓 기반 지식 증류 (Distillation)
         ▼                       ▼
  +---------------------------------------------------------------+
  | 고품질 큐레이션 데이터셋 ("Textbooks Are All You Need")       |
  |  - 엄격히 필터링된 웹 텍스트, 합성된 CoT(Chain of Thought) 추론 데이터셋 |
  +--------------------------------┬------------------------------+
                                   │ 집중 사전학습 / SFT
                                   ▼
  +---------------------------------------------------------------+
  | 컴팩트 트랜스포머 아키텍처 (Compact Backbone: 1B ~ 14B)       |
  |  - RoPE (Rotary Position Embedding), GQA (Grouped-Query Attention) |
  |  - 깊고 좁은 레이어 구조 최적화 (Phi-3, Qwen 2.5, Llama 3 8B) |
  +--------------------------------┬------------------------------+
                                   │ 모델 압축 및 엣지 컴파일
                                   ▼
  +---------------------------------------------------------------+
  | 경량화 서빙 런타임 (Edge & On-Device Deployment)              |
  |  - AWQ / GPTQ INT4 양자화 ──► GGUF 포맷 변환 (llama.cpp)       |
  |  - NPU 하드웨어 가속기 직결 (온디바이스 초당 30+ TPS(Tokens Per Second) 달성) |
  +---------------------------------------------------------------+
```

- **GQA(Grouped-Query Attention)** : 멀티헤드 어텐션 대비 KV(Key-Value) 캐시 메모리 사용량을 1/4~1/8로 축소하여 메모리 대역폭 병목을 완화하고 배치 크기 확대.
- **지식 증류(Knowledge Distillation)** : 교사(Teacher) 거대 모델의 출력 확률 분포(Soft Label)를 학생(Student) 소형 모델이 모사 학습하여 추론 역량 전이.
- **합성 교과서 데이터 학습** : 무작위 인터넷 크롤링 데이터 대신 교육적 가치가 높은 합성 코딩 및 논리 교재 데이터를 집중 주입하여 적은 파라미터로도 높은 추론 능력 발현.
- **양자화(Quantization)** : FP16(16비트 부동소수점) 가중치를 INT4(4비트 정수)로 압축하여 정확도 손실을 최소화하며 VRAM(Video Random-Access Memory) 요구량을 대폭 절감.

## Ⅲ. 소형 언어 모델(Small Language Model, sLM)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 초거대 LLM (Frontier LLM) | 소형 언어 모델 (sLM) |
| --- | --- | --- |
| **파라미터 규모** | 70B ~ 수조 개 (거대 클러스터 필요) | 1B ~ 14B (단일 GPU / PC(Personal Computer) / 스마트폰 구동 가능) |
| **인프라 요구사항** | 멀티 노드 8x H100 클러스터 필수 | 단일 RTX 4090 (24GB) 또는 온디바이스 NPU |
| **서빙 비용 (TCO)** | 매우 높음 (토큰당 과금 또는 고가 서버 렌탈) | 극도로 낮음 (기존 사내 서버 활용 가능) |
| **보안 및 프라이버시** | 퍼블릭 클라우드 전송에 따른 유출 리스크 | 완벽한 사내망(Air-Gapped) 격리 구동 가능 |
| **범용 상식 추론** | 전 세계 모든 도메인에 대한 방대한 상식 암기 | 범용 상식 암기량 부족 (RAG(Retrieval-Augmented Generation) 보완 필수) |
| **도메인 특화 성능** | 파인튜닝 비용이 너무 커서 범용 사용 | 소량 사내 데이터로 저비용 고효율 도메인 특화 완결 |

- 최신 엔터프라이즈 아키텍처는 모든 업무에 거대 LLM을 사용하는 비효율을 탈피하고, 대부분의 일상 업무를 가벼운 sLM에 위임하는 하이브리드 구성을 표준으로 삼음.

## Ⅳ. 소형 언어 모델(Small Language Model, sLM)의 주요 한계점 및 해결 방안

- 파라미터 용량 한계로 인한 사실적 지식(Factual Knowledge) 암기량 부족 :
  - 한계점 : 모델 자체에 저장된 세계 지식이 적어 외부 지식 질의 시 사실적 오류나 환각 발생 가능성 상존.
  - 해결 방안 : **프라이빗 RAG** (검색 증강 생성) 아키텍처와 결합하여 사실 정보는 벡터 DB(Database)에서 검색하여 주입.
- 복합 다단계 추론(Complex Multi-hop Reasoning) 시 논리 전개 한계 :
  - 한계점 : 극도로 얽힌 수학 증명이나 긴 코드 리팩토링 시 중간 단계를 건너뛰거나 논리적 비약 발생.
  - 해결 방안 : DeepSeek-R1-Distill 계열의 추론 특화 sLM 도입 및 CoT(Chain of Thought) 단계별 검증 프롬프트 강제.
- 다양한 다운스트림 태스크에 대한 제로샷(Zero-shot) 적응력 부족 :
  - 한계점 : 학습되지 않은 새로운 형식의 지시문을 받았을 때 거대 모델 대비 지시 준수(Instruction Following) 실패율 높음.
  - 해결 방안 : 사내 표준 출력 스키마(JSON, JavaScript Object Notation)에 맞춘 추가 SFT(Supervised Fine-Tuning) 및 Few-shot 예시 프롬프트 제공.

## Ⅴ. 소형 언어 모델(Small Language Model, sLM) 적용 및 발전을 위한 기술사적 제언

- '1업무 1특화 sLM' 엔터프라이즈 아키텍처 전략 수립 : 콜센터 요약용, 코드 리뷰용, 계약서 검토용 등 업무별로 7B~14B sLM을 분리 미세조정하여 전문성 및 가용성 극대화.
- GGUF 및 llama.cpp 기반 사내 엣지 인프라 서빙 표준화 : 고가 GPU가 없는 일반 사내 x86 서버의 CPU(Central Processing Unit)와 통합 메모리 환경에서도 쾌적하게 동작하는 양자화 서빙 환경 구축.
- 지능형 모델 라우터(Router)를 통한 LLM-sLM 협업 파이프라인 구현 : 입력 프롬프트의 복잡도와 보안 등급을 자동 판별하여 sLM과 상용 LLM으로 동적 라우팅하는 지능형 게이트웨이 도입.
