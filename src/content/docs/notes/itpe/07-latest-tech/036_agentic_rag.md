## Ⅰ. 에이전틱 RAG(Agentic RAG)의 개요

- **개념** : 고정된 단방향 파이프라인(질의 ──► 벡터 검색 ──► 답변 생성)으로 동작하는 기존 나이브 RAG의 한계를 극복하고, 자율 에이전트(Agent)가 검색의 필요성 여부를 스스로 판단하며, 복합 질의를 다단계로 분해하고, 다양한 이기종 데이터 소스(SQL, Vector DB, Web)로 동적 라우팅하며, 검색된 문서의 적합성을 자체 평가(Self-Reflection)하여 부적절할 경우 쿼리를 재작성(Query Rewriting)하여 재검색하는 차세대 능동형 검색 증강 생성 아키텍처.
- **배경 및 필요성** : 기존 RAG는 사용자의 모호한 질의, 저품질 검색 청크 유입, 다중 문서 간 복합 비교 질의에 대해 잘못된 답변(환각)을 생성하는 취약점이 있어, 검색 과정 전반을 동적으로 제어하고 오류를 스스로 바로잡는 지능형 오케스트레이션이 요구됨.
- **핵심 목적** : 검색 정확도 및 답변 사실성 극대화, 모호한 질의의 자율 분해 및 정제, 오류 감지 시 자가 교정(Self-Correction)을 통한 무결점 엔터프라이즈 지식 응답 제공.

## Ⅱ. 에이전틱 RAG(Agentic RAG)의 핵심 아키텍처 및 동작 메커니즘

에이전틱 RAG는 질의 라우팅, 검색 및 문서 품질 평가(Corrective RAG), 자가 반성(Self-RAG), 최종 답변 합성의 폐루프(Closed-Loop) 구조로 동작함.

```text
[ 에이전틱 RAG의 자가 교정(Self-Correction) 피드백 루프 ]

                  [ 사용자 질의 (User Query) ]
                               │
                               ▼
            +-------------------------------------+
            | 1. 에이전트 라우터 (Agent Router)   |
            |  - 검색 필요 여부 판단 (No-Search?) |
            |  - 데이터 소스 결정 (Vector vs SQL) |
            +------------------┬------------------+
                               │ 최적 소스 질의 전송
                               ▼
            +-------------------------------------+
            | 2. 동적 검색 실행 (Retrieval Tool)  |
            |  - 하이브리드 검색 (BM25 + Dense)   |
            +------------------┬------------------+
                               │ 검색된 청크(Chunks) 반환
                               ▼
            +-------------------------------------+
            | 3. 문서 적합성 평가 (Document Grader)|
            |  - 질문과 문서 간 관련성 채점(Score)|
            +------------------┬------------------+
                               │
            ┌──────────────────┴──────────────────┐
     [부적합 판정 (Score < 임계치)]        [적합 판정 (Relevant)]
            │                                     │
            ▼                                     ▼
+-----------------------+             +-----------------------+
| 4. 쿼리 재작성        |             | 5. 답변 생성 및 검증  |
| (Query Rewriter)      |             | (Generate & Self-Check|
| - 키워드 확장/의도분해|             | - 근거성(Groundedness)|
+-----------┬-----------+             |   환각 자체 감사      |
            │                                     │
            └────────► [ 2단계로 재검색 ]         ▼
                                      [ 최종 신뢰성 검증 답변 ]
```

- **지능형 라우팅(Routing)** : 질의 유형에 따라 단순 인사말은 검색 없이 응답, 정형 통계 질문은 Text-to-SQL로 변환, 사내 매뉴얼 질문은 벡터 DB로 동적 분기.
- **문서 등급 평가자(Document Grader / CRAG)** : 검색된 각 청크가 사용자의 질문을 해결하는 데 실질적으로 도움이 되는지 경량 LLM으로 관련성(Binary Score) 판정.
- **쿼리 재작성(Query Rewriting)** : 검색 결과가 모두 부적합한 경우 사용자의 원래 질문을 재해석하여 더 나은 검색 키워드로 변환하거나 웹 검색으로 폴백.
- **생성물 자체 비평(Self-RAG Reflection)** : 생성된 답변이 검색된 문서에 명확히 근거하는지(Groundedness), 질문의 의도를 완벽히 충족하는지(Answer Relevance) 역검증.

## Ⅲ. 에이전틱 RAG(Agentic RAG)의 세부 구성 요소 및 비교 분석

| 비교 항목 | 나이브 RAG (Naive RAG) | 고급 RAG (Advanced RAG) | 에이전틱 RAG (Agentic RAG) |
| --- | --- | --- | --- |
| **흐름 제어 구조** | 고정된 선형 파이프라인 (단방향) | 전처리/후처리(리랭커) 추가된 선형 파이프라인 | 상태 머신 기반 순환 피드백 루프 (Cyclic Graph) |
| **검색 횟수** | 무조건 1회 검색 후 답변 생성 | 사전 최적화 후 1회 검색 | 조건 충족될 때까지 자율적 다회차 반복 검색 |
| **오류 수정 능력** | 없음 (검색 실패 시 환각 발생) | 제한적 (리랭킹으로 순위만 재조정) | 자체 교정(Self-Correction) 및 쿼리 재작성 수행 |
| **데이터 소스 선택** | 단일 벡터 DB에 고정 | 하이브리드 검색 (BM25 + Vector) | 벡터 DB, RDBMS(SQL), 웹 검색, 지식그래프 동적 선택 |
| **복합 다단계 질의** | 완전히 실패하거나 일부만 답변 | 문맥 윈도우 확장에 의존 | 질의를 하위 질문들로 분해(Sub-queries)하여 종합 |

- 나이브 RAG가 단순 오픈북 시험이라면, 에이전틱 RAG는 학생이 스스로 도서관의 여러 서가를 뒤지고 내용이 부족하면 다른 책을 찾아 검증한 뒤 논술하는 과정과 같음.

## Ⅳ. 에이전틱 RAG(Agentic RAG)의 주요 한계점 및 해결 방안

- **다단계 자체 평가 및 재검색 루프로 인한 응답 지연(Latency > 5~10초)** :
  - **한계점** : 문서 평가, 쿼리 재작성, 다회차 검색이 중첩되면서 실시간 챗봇 사용자 경험(UX) 저하.
  - **해결 방안** : 문서 평가 및 라우팅 단계에 1B~3B 초경량 특화 sLM 배치, 중간 단계 스트리밍 UI 피드백 제공.
- **에이전트의 잘못된 자가 평가로 인한 무한 재검색 루프(Looping)** :
  - **한계점** : 문서가 충분히 적합함에도 평가 모델이 오판하여 계속 쿼리를 재작성하며 헛도는 현상.
  - **해결 방안** : 최대 재검색 횟수(Max Retries = 2회) 강제 제한, 실패 시 가장 점수가 높은 청크를 바탕으로 폴백 생성.
- **다양한 이기종 데이터 소스 통합 시 보안 및 권한(RBAC) 통제 난제** :
  - **한계점** : 에이전트가 사용자 권한을 우회하여 비인가 SQL 테이블이나 보안 폴더를 조회할 위험.
  - **해결 방안** : 도구 호출 시 사용자의 JWT 토큰과 연동된 RBAC 메타데이터를 전파하여 검색 엔진 레벨에서 원천 필터링.

## Ⅴ. 에이전틱 RAG(Agentic RAG) 적용 및 발전을 위한 기술사적 제언

- **LangGraph 기반 유향 비순환 그래프(DAG) 구조의 상태 제어 프레임워크 구축** : 순환 루프와 조건부 엣지(Conditional Edge)를 명확한 상태 머신으로 구현하여 제어 가능성 확보.
- **RAG Triad(문맥 적합성, 근거성, 답변 유용성) 기반 자동화된 실시간 텔레메트리 관제** : Ragas 프레임워크를 프로덕션에 연동하여 각 단계별 점수를 실시간 대시보드로 모니터링.
- **사내 전사 지식 베이스(ERP + WIKI + 규정집) 통합 질의를 위한 에이전틱 RAG 우선 도입** : 단일 데이터 사일로를 탈피하고 인사, 회계, 법무 시스템을 유기적으로 연계하는 차세대 엔터프라이즈 포털 구축.
