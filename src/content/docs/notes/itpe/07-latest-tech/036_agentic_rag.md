## 30초 인출

- 본질: **에이전틱 RAG(Agentic RAG)** 는 고정된 선형 파이프라인(Retrieve-then-Generate)을 벗어나, 자율 에이전트가 질의 복잡도를 분석하여 검색 필요 여부를 판단하고, 다중 지식 소스를 동적 라우팅하며, 검색된 결과의 품질을 스스로 비평·보정(Self-Correction)하는 능동형 RAG 아키텍처
- 메커니즘: 질의 라우팅 후 검색 수행, 검색 문서의 관련성을 평가(Evaluator)하여 품질 미달 시 쿼리 재작성(Rewrite) 및 웹 검색 폴백(Fallback)을 수행한 후 최종 답변 도출
- 통찰: 검색 실패 판정 오류 시 무한 재검색 루프로 인해 지연시간과 토큰 비용이 폭증하므로 엄격한 재시도 횟수 제한(Max Retry=2) 및 불확실성 시 명시적 답변 거절 정책 결합 필수

<details><summary>핵심 용어</summary>

- **에이전틱 RAG (Agentic RAG)** : 에이전트의 추론, 도구 활용, 자기 반성 루프를 결합하여 동적 검색 흐름을 제어하는 차세대 RAG 프레임워크.
- **라우터 에이전트 (Router Agent)** : 질의 의도와 난이도를 파악하여 사내 벡터 DB, 웹 검색, SQL 데이터베이스 중 최적의 도구를 선택하거나 검색을 생략하는 디스패처.
- **CRAG (Corrective RAG)** : 검색된 문서의 적합성을 신뢰도(Correct, Ambiguous, Incorrect)로 판별하여 지식 정제 또는 외부 웹 검색으로 보정하는 기법.
- **Self-RAG (Self-Reflective RAG)** : 모델이 스스로 검색 필요성(`[Retrieve]`), 문서 관련성(`[IsRel]`), 답변 지지율(`[IsSup]`) 토큰을 생성하며 자기 채점하는 기법.
- **질의 재작성 (Query Rewriter)** : 검색 결과가 부실할 경우 모호한 사용자 질문의 키워드를 동의어나 구체적 하위 질의로 자동 변환하는 프롬프트 모듈.

</details>

## 2~4교시 25점 답안

## Ⅰ. 에이전틱 RAG의 개요

| 구분 | 핵심 |
|---|---|
| 정의 | **에이전틱 RAG(Agentic RAG)** 는 LLM 기반 에이전트가 사전에 고정된 단일 검색 파이프라인에 의존하지 않고, 질의 의도 파악, 검색 필요성 자가 판정, 다중 소스 동적 라우팅, 검색 결과 자체 평가 및 반복적 질의 보정을 자율적으로 수행하는 지능형 검색 증강 아키텍처 |
| 목적 | 단편적 1회성 검색에 따른 무관한 청크 주입(Noise) 방지, 복합 다단계 질문의 완벽한 분해 해결, 환각의 원천적 억제 및 응답 신뢰성 극대화 |

## Ⅱ. 에이전틱 RAG의 4대 핵심 패턴 및 정적 RAG 대비 특징

| 구분 | 4대 핵심 패턴 | 세부 공학적 메커니즘 및 속성 |
|---|---|---|
| **동적 라우팅 (Routing)** | 조건부 도구 선택 | 질의에 따라 사내 규정(Vector DB), 실시간 주가(Web API), 고객 정보(SQL DB)를 선별 호출 |
| **질의 계획 (Query Planning)** | 다단계 하위 질의 분해 | 복합 질문("A사 실적과 B사 실적 비교")을 2개의 단일 질의로 쪼개어 각각 병렬 검색 후 수합 |
| **자기 반성 (Self-Reflection)** | 검색 문서 적합성 평가 | 검색된 상위 5개 청크가 실제 질문에 답할 수 있는지 채점(Scoring)하여 품질 미달 시 폐기 |
| **능동적 보정 (Correction)** | 자동 질의 재작성 및 폴백 | 내부 지식 검색 실패 시 키워드를 재구성하여 재검색하거나 공용 웹 검색 엔진으로 자동 전환 |

## Ⅲ. 에이전틱 RAG 아키텍처 및 동적 검색·반성 루프 프로세스

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   [ 에이전틱 RAG 폐루프(Closed-Loop) 아키텍처 ]            │
└────────────────────────────────────────────────────────────────────────┘
                                    │
 [ 사용자 질문 인입 ] ──► [ 라우터 에이전트 (Router Agent) ]
                                    │
               ┌────────────────────┴────────────────────┐
               ▼ (일반 지식 충분)                          ▼ (사내 지식 필요)
       [ LLM 즉시 답변 생성 ]                       [ 1차 벡터/키워드 하이브리드 검색 ]
                                                         │
                                                         ▼
                                            [ 문서 평가기 (Doc Evaluator) ]
                                             - 질문과의 관련성(Relevance) 채점
                                                         │
               ┌─────────────────────────────────────────┴─────────────────────────────────────────┐
               ▼ (관련성 부족: Incorrect)                                                           ▼ (관련성 충분: Correct)
┌─────────────────────────────────────────┐                                       ┌─────────────────────────────────────────┐
│ [ 질의 재작성기 (Query Rewriter) ]      │                                       │ [ 컨텍스트 압축 및 답변 생성 ]          │
│  - 사용자 쿼리 의미 확장 및 재탐색      │                                       │  - 핵심 문맥 주입 후 LLM 추론           │
│  - (재검색 실패 시) ──> [ 웹 검색 폴백 ] │                                       └────────────────────┬────────────────────┘
└────────────────────┬────────────────────┘                                                            │
                     │                                                                                 ▼
                     └───────────────────► [ 재검색 루프 (최대 2회) ] ───────────► [ 환각 검증 (Hallucination Grader) ]
                                                                                                       │
                                                                                 ┌─────────────────────┴─────────────────────┐
                                                                                 ▼ (환각 없음: Grounded)                      ▼ (환각 감지 시)
                                                                           [ 최종 답변 출력 ]                          [ 답변 폐기 및 재생성 ]
```

| 프로세스 모듈 | 핵심 공학 활동 | 주요 판단 기준 및 산출물 |
|---|---|---|
| **Query Analyzer** | 질문 의도 분류 및 모호성 분석 | 검색 불필요, 단일 검색, 다단계 분해 결정 |
| **Document Grader** | 검색된 청크의 바이너리/스코어 채점 | `Score >= 0.7`: 채택 / `Score < 0.7`: 필터링 |
| **Query Rewriter** | HyDE(가상 문서 생성) 및 유의어 확장 | 재작성된 신규 쿼리 문자열 도출 |
| **Hallucination Grader** | 생성된 답변과 검색 문서 간 사실 대조 | 사실 불일치 감지 시 프롬프트 제약 강화 후 재시도 |

## Ⅳ. Naive RAG vs Advanced RAG vs 에이전틱 RAG 비교

| 비교 항목 | 전통적 Naive RAG | 고도화 Advanced RAG | 에이전틱 RAG (Agentic RAG) |
|---|---|---|---|
| **파이프라인 흐름** | 정적 단방향 (단일 순차) | 고정된 전/후처리 파이프라인 | 조건부 분기, 반복 루프, 자율 판단 |
| **검색 결정권** | 모든 입력에 무조건 검색 | 모든 입력에 무조건 검색 | 에이전트가 검색 필요성 자율 판정 |
| **검색 품질 실패 시** | 무관한 청크 기반 환각 출력 | Re-ranker로 완화하나 실패 시 노이즈 | 검색 실패 인지 후 쿼리 재작성·재검색 |
| **복합 질문 처리** | 단일 임베딩 검색으로 실패 | 하이브리드 검색으로 부분 대응 | 다단계 하위 질문으로 분해하여 병렬 해결 |
| **응답 지연시간** | 가장 빠름 (1~2초) | 보통 (2~3초) | 상대적 지연 (루프 발생 시 3~8초) |

## Ⅴ. 한계와 방안

| 한계 | 방안 |
|---|---|
| 검색 평가기(Grader)가 지속적으로 '부적합' 판정을 내려 질의 재작성과 재검색이 무한 반복되는 지연 및 비용 폭증 | 최대 재시도 한도(Max Retries=2)를 엄격히 강제하고 한도 초과 시 "보유한 문서에서 근거를 찾을 수 없습니다"로 조기 종료 |
| 매 단계마다 LLM 호출(라우팅, 문서 평가, 환각 검증)이 발생하여 단일 응답당 API 비용 4~5배 증가 | 라우팅 및 문서 평가 모듈에는 경량 sLLM(Phi-3, Llama-3-8B) 또는 초고속 Cross-Encoder 분류기 전담 배치 |

## Ⅵ. 제언

실무 엔터프라이즈 환경에서 지연시간과 비용을 통제하기 위해, LangGraph 기반의 상태 머신 워크플로우를 구축하고 평가 단계에 저비용 분류기를 결합한 하이브리드 CRAG 파이프라인 구축.

```text
[ 사용자 질의 ] ──> [ 경량 라우터 (RoBERTa 기반 초고속 분류) ]
                                │
                                ▼ (사내 지식 검색)
[ 고속 HNSW 벡터 검색 + BM25 ] ──> [ 상위 3개 청크 반환 ]
                                │
                                ▼
[ Cross-Encoder 기반 문서 채점 (지연 20ms) ]
   ├── 관련도 높음 (>= 0.8) ────> [ LLM 팩트 기반 최종 답변 생성 ]
   ├── 관련도 애매 (0.4 ~ 0.8) ──> [ 웹 검색 폴백 결합 후 답변 생성 ]
   └── 관련도 미달 (< 0.4) ─────> [ 1회 쿼리 재작성 후 재시도 (실패 시 답변 불가 고지) ]
```

| 구분 | 전체 거대 LLM 기반 순수 에이전트 | 제언: 경량 분류기 결합 하이브리드 CRAG |
|---|---|---|
| **단계별 지연** | 매 평가마다 LLM 호출로 5초 이상 소요 | Cross-Encoder 활용으로 0.2초 내 평가 완결 |
| **토큰 비용** | 평가 토큰 누적으로 비용 급증 | 분류기 활용으로 평가 비용 0원화 |
| **운영 안정성** | 프롬프트 환각으로 인한 무한 루프 위험 | 코드 기반 조건부 엣지로 100% 결정론적 제어 |
