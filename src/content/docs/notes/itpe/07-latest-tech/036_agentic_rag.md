## 연관 키워드

- 에이전틱 RAG(Agentic RAG), 검색 증강 생성(RAG), 나이브 RAG(Naive RAG), 고급 RAG(Advanced RAG)
- 지능형 라우팅, 문서 등급 평가(Document Grader), CRAG, 쿼리 재작성(Query Rewriting)
- 자가 교정(Self-Correction), Self-RAG, 근거성(Groundedness), RAG Triad
- 역할 기반 접근 통제(RBAC), 텍스트-투-SQL(Text-to-SQL)

## Ⅰ. 에이전틱 RAG(Agentic RAG)의 개요

- 핵심 요약 : 고정된 한 번의 검색 파이프라인을 넘어, 에이전트가 검색 여부와 경로를 스스로 판단하고 결과를 교정하는 능동형 검색 증강 생성 구조.
- 개념 : 고정된 단방향 흐름(질의, 벡터 검색, 답변 생성)으로 동작하는 **나이브 RAG** (Naive RAG)를 넘어, 자율 에이전트가 검색 필요성을 판단하고 복합 질의를 분해하며 여러 데이터 소스로 라우팅하고 검색 문서의 적합성을 평가해 재검색까지 수행하는 **에이전틱 RAG** (Agentic RAG).
- 배경 및 필요성 : 검색 증강 생성(RAG, Retrieval-Augmented Generation)은 모호한 질의, 부적합한 검색 청크, 여러 문서를 비교하는 복합 질의에서 환각이 발생하기 쉬워, 검색 과정 전반을 동적으로 제어하는 오케스트레이션이 요구됨.
- 핵심 목적 : 검색 정확도와 답변 사실성 향상, 모호한 질의의 자율 분해와 정제, 오류 감지 시 자가 교정을 통한 신뢰성 높은 응답 확보.

## Ⅱ. 에이전틱 RAG(Agentic RAG)의 특징 및 장점

- 핵심 요약 : 라우팅, 문서 평가, 쿼리 재작성이 폐루프로 연결되어 검색 실패를 답변 전에 바로잡는 구조.

1. **지능형 라우팅** (Intelligent Routing) : 질의 유형에 따라 검색 생략, 벡터 DB, 정형 DB 중 최적 소스를 선택 → 불필요한 검색과 오답 감소.
2. **문서 등급 평가** (Document Grader) : 검색된 각 청크가 질문 해결에 실질적으로 도움이 되는지 경량 모델로 판정 → 무관한 문서가 답변에 섞이는 현상 억제.
3. **쿼리 재작성** (Query Rewriting) : 검색 결과가 부적합하면 질문을 재해석해 검색어를 바꾸거나 웹 검색으로 대체 → 검색 실패 후 복구 가능.
4. **생성물 자체 비평** (Self-RAG Reflection) : 답변이 검색 문서에 **근거성** (Groundedness)을 갖는지 역으로 검증 → 근거 없는 답변 노출 감소.

## Ⅲ. 에이전틱 RAG(Agentic RAG)의 구조 (흐름)

- 핵심 요약 : 에이전트 라우터가 검색 경로를 정하고, 문서 평가 결과에 따라 재작성과 재검색을 도는 순환 구조.

```text
[ 에이전틱 RAG 피드백 루프 ]

  사용자 질의 (User Query)
        ↓
  에이전트 라우터 (검색 여부, 소스 결정)
        ↓
  동적 검색 실행 (벡터 · SQL · 웹)
        ↓
  문서 등급 평가 (관련성 점수)
```

```text
[ 평가 결과에 따른 분기 ]

  관련성 임계치 비교
     ↓ 부적합             ↓ 적합
  쿼리 재작성        답변 생성 및 자체 검증
     ↓                      ↓
  재검색 (횟수 상한 내)   최종 답변 출력
     └──► 다시 등급 평가
```

## Ⅳ. 에이전틱 RAG(Agentic RAG)의 비교

- 핵심 요약 : 나이브 RAG의 단일 검색 한계에서 고급 RAG의 전처리 보강을 거쳐, 에이전틱 RAG는 순환 제어와 자체 교정을 갖춤.

| 비교 항목 | 나이브 RAG (Naive RAG) | 고급 RAG (Advanced RAG) | 에이전틱 RAG (Agentic RAG) |
| --- | --- | --- | --- |
| 흐름 제어 구조 | 고정된 선형 파이프라인 | 전처리와 리랭커가 추가된 선형 구조 | 상태 기반 순환 그래프 |
| 검색 횟수 | 1회 검색 후 답변 생성 | 최적화된 1회 검색 | 조건 충족 때까지 다회 검색 |
| 오류 수정 능력 | 없음 (검색 실패 시 환각) | 리랭킹으로 순위만 조정 | 자체 교정과 쿼리 재작성 |
| 데이터 소스 | 단일 벡터 DB 고정 | 하이브리드 검색 (BM25 + 벡터) | 벡터 DB, RDBMS, 웹, 지식 그래프 선택 |
| 복합 질의 처리 | 일부만 답하거나 실패 | 문맥 창 확장에 의존 | 하위 질문으로 분해 후 종합 |

- 비유 : 나이브 RAG가 참고서 한 권만 보고 답하는 시험이라면, 에이전틱 RAG는 부족한 내용을 다른 서가에서 찾아 검증한 뒤 논술하는 과정에 가까움.

## Ⅴ. 에이전틱 RAG(Agentic RAG)의 한계와 방안

- 핵심 요약 : 응답 지연, 무한 재검색, 권한 우회를 경량 평가, 재검색 상한, 권한 메타데이터 전파로 관리.

| 한계 | 원인·영향 | 대응 방안 | 관리 지표 |
| --- | --- | --- | --- |
| 다단계 평가로 인한 응답 지연 | 평가, 재작성, 재검색이 중첩되어 실시간 응답 저하 | 평가와 라우팅에 경량 특화 소형 모델 배치, 중간 단계 진행 상태 스트리밍 | 첫 응답 시간, 단계별 소요 시간 |
| 잘못된 자가 평가에 따른 무한 재검색 | 적합한 문서를 부적합으로 오판해 재작성을 반복 | 재검색 횟수 상한 설정, 상한 도달 시 최고 점수 청크로 답변 생성 | 재검색 횟수 분포, 상한 도달률 |
| 이기종 소스의 권한 우회 | 에이전트가 허가되지 않은 테이블이나 폴더를 조회할 위험 | 사용자 토큰과 연동된 **역할 기반 접근 통제** (RBAC, Role-Based Access Control) 메타데이터를 검색 단계에서 필터링 | 비인가 접근 시도 건수 |

## Ⅵ. 에이전틱 RAG(Agentic RAG)에 대한 기술사적 제언

- 핵심 요약 : 흐름 제어 프레임워크, 품질 관제, 전사 지식 연계를 단계적으로 갖춘 뒤 확산하는 도입이 바람직함.

1. 순환 구조와 조건부 분기를 명시적 상태 머신으로 구현하는 그래프 기반 프레임워크를 채택하여 흐름을 통제 가능하게 만드는 것이 바람직함.
2. 문맥 적합성, 근거성, 답변 유용성으로 이루어진 **RAG Triad** (Context Relevance, Groundedness, Answer Relevance) 점수를 운영 단계에서 상시 측정하는 관제 체계를 둠.
3. 인사, 회계, 규정 등 흩어진 사내 지식을 권한 체계와 함께 묶어 질의하는 통합 지식 포털을 우선 도입 대상으로 삼음.

## Ⅶ. 결론

- 핵심 요약 : 에이전틱 RAG는 검색 과정을 스스로 판단하고 교정하는 능동형 지식 응답 아키텍처.
- 시사점 : 검색 품질 자체보다 흐름 제어와 권한 통제가 실무 신뢰성을 결정하므로, 두 요소를 설계의 중심에 둬야 함.
