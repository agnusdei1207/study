## 답안 골격
```text
[에이전틱 RAG] ◀━━ 머리: Ⅶ 내 의견 (라우팅·자가 반조 결합형 에이전틱 RAG 파이프라인을 통한 복합 질의 무환각 응답)
 ┃
 ┣━ Ⅰ 개요 ───── 단발성 1회 검색·생성(Naive RAG) 한계 → 자율 에이전트가 검색 필요성 판단·질의 재작성·다단계 탐색 수행
 ┣━ Ⅱ 특징 ───── 조건부 검색 라우팅 · 쿼리 재작성(Query Rewriting) · 검색 결과 품질 평가(Corrective) · 다중 소스 병합
 ┣━ Ⅲ 구조 ───── 라우터(Router) + 검색기(Retrieval Tools) + 문서 평가기(Document Grader) + 생성기(Generator)
 ┣━ Ⅳ 흐름 ───── ① 사용자 질문 수신 → ② 검색 필요성 및 소스 판단 → ③ 쿼리 변환/검색 → ④ 문서 적합성 평가 → ⑤ 생성 및 자가 검증
 ┣━ Ⅴ 비교 ───── 전통 RAG(Naive RAG) vs 고급 RAG(Advanced RAG) vs 에이전틱 RAG(Agentic RAG)
 ┗━ Ⅵ 실무 ───── 반복 검색에 따른 지연시간(Latency) 증가 / API 호출 비용 폭증 / 판단 오류 시 엉뚱한 도구 호출
```
- 필수 키워드: 에이전틱 RAG · 쿼리 변환(Query Transformation) · 자기 수정(Self-Correction/CRAG) · 적응형 라우팅(Adaptive Routing) · 검색 평가기(Grader) · LangGraph

## 한 줄 본질
- 정적 1회 벡터 검색에 의존해 모호하거나 복합적인 질의에 엉뚱한 문서를 가져오던 한계 → LLM 에이전트가 질문을 분석하여 검색 전략을 동적으로 분기하고 문서의 적합성을 평가해 검색을 반복하는 지능형 검색 체계 구축 → 복합 질문 해결력과 신뢰도 극대화 / 지연시간 및 토큰 비용 증가

## 핵심 그림
```text
[에이전틱 RAG의 적응형 제어 흐름]
                      [ 사용자 질의 (Query) ]
                                 |
                                 v
                 +-------------------------------+
                 |   에이전트 라우터 (Router)    |
                 +---------------+---------------+
                                 |
           +---------------------+---------------------+
           | (검색 불필요: 인사 등)                    | (검색 필요)
           v                                           v
    [ 직접 답변 생성 ]                       [ 쿼리 변환기 (Query Rewriter) ]
                                                       |
                                                       v
                                            [ 다중 검색 (Vector/Web/Graph) ]
                                                       |
                                                       v
                                            +-------------------------------+
                                            |  문서 적합성 평가 (Grader)    |
                                            +---------------+---------------+
                                                            |
                             +------------------------------+------------------------------+
                             | (부적합 / 정보 부족)                                        | (적합)
                             v                                                             v
                  [ 질의 재작성 후 재검색 ]                                       [ 답변 생성 (Generator) ]
                                                                                           |
                                                                                           v
                                                                                  [ 환각 여부 자가 검증 ]
                                                                                           |
                                                                                           v
                                                                                  [ 최종 검증된 응답 ]
```

## 핵심 용어
- 쿼리 변환(Query Rewriting / Decomposition): 사용자의 모호한 단일 질문을 검색 엔진이 색인하기 좋은 정밀 키워드로 바꾸거나, 복합 질문을 2~3개의 하위 질문으로 쪼개는 기술
- 문서 적합성 평가(Document Grading): 검색된 문서 청크(Chunk)가 사용자의 질문 의도와 실제 관련이 있는지를 경량 모델(sLM)을 통해 이진 판정(Relevant / Irrelevant)하는 절차
- CRAG(Corrective RAG): 검색 결과가 부적합할 경우 자동으로 웹 검색 엔진으로 폴백(Fallback)하거나 질의를 수정해 올바른 지식을 다시 찾는 자기 교정 메커니즘

## 핵심 통찰
- 모든 질문에 무조건 벡터 검색을 돌리는 것은 계산 낭비이자 오답 유발의 원인 → 에이전트가 "검색 여부" 자체를 먼저 결정해야 함
- 벡터 유사도(Cosine Similarity)가 높다고 해서 반드시 질문에 대한 "정답 정보"를 담고 있는 것은 아니므로, 생성 직전 문서 내용을 검증하는 평가기(Grader)가 필수
- 상태 머신(State Machine) 기반 프레임워크(LangGraph 등)를 통해 검색 루프의 최대 반복 횟수를 강제하지 않으면 응답 지연이 10초 이상으로 치솟음

## 이웃 토픽과 구분
- 에이전틱 RAG vs Naive RAG: Naive RAG는 `질문 → 임베딩 검색 → 단일 생성`의 일방통행 고정 파이프라인 / 에이전틱 RAG는 질문에 따라 검색 소스를 고르고, 결과를 검토해 재검색하거나 웹 검색으로 우회하는 분기·반복형 파이프라인

## 문제·원인·대책
- 적용 상황: 기업 기술 문서 기반 에이전틱 RAG 지원 챗봇 운영 중 응답 지연 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 사용자 응답 대기 시간이 8초 이상 지연 | 문서 부적합 판정에 따른 다단계 재검색 및 대형 LLM 호출 누적 | 경량 모델(sLM) 기반 Grader 배치 및 캐싱 계층(Semantic Cache) 적용 | Grader 판정 시간 80% 단축 및 중복 질의 즉시 반환 |
| 쿼리 재작성을 반복하며 원본 질문 의도 왜곡 | 질의 변환 시 원본 사용자 컨텍스트 소실 | 원본 질문 고정 보존 및 변환 질의와의 앙상블 검색(Multi-Query) 적용 | 의도 왜곡 방지 및 검색 회수율(Recall) 향상 |
| 사내 비공개 문서와 공개 웹 정보 혼재 | 라우터의 권한 및 도메인 지식 분기 규칙 미비 | 역할 기반 접근 제어(RBAC) 메타데이터 필터링 및 소스 우선순위 라우팅 | 보안 데이터 유출 방지 및 공신력 있는 사내 지식 우선 인용 |
