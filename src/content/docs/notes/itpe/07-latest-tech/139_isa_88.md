## Ⅰ. ISA-88 배치 제어의 개요

- **개념** : 화학·제약·식품 등 배치(Batch) 생산에서 설비의 물리적 구조와 제조 절차(레시피)를 분리하여 모듈 단위로 표준화한 국제 배치 제어 규격(IEC 61512).
- **배경 및 필요성** : 다품종 소량 생산 전환 시 레시피 파라미터와 현장 PLC/DCS 설비 제어 모듈 간 태그 매핑 오류로 배치 재현성 저하가 발생하므로 마스터 레시피 버전 동기화와 전자 배치 기록(EBR) 기반 실시간 추적 체계 구축 필요.
- **핵심 목적** : 제조 공정과 설비 제어 로직의 결합도 분리를 통한 다품종 유연 생산 지원, 엔지니어링 비용 절감 및 배치 품질 재현성 확보.

## Ⅱ. ISA-88 배치 제어의 핵심 아키텍처 및 동작 메커니즘

ISA-88 배치 제어는 신뢰할 수 있는 데이터 파이프라인과 고도화된 추론 메커니즘을 기반으로 동작하며, 세부적인 아키텍처와 핵심 컴포넌트 간 상호작용 프로세스는 다음과 같음.

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [ ISA-88 기반 배치 제어 아키텍처 및 레시피 구동 체계 ]                 │
└────────────────────────────────────────────────────────────────────────┘

  [ 레시피 모델 (Recipe Model) ]            [ 물리 모델 (Physical Model) ]
  ┌─────────────────────────┐              ┌─────────────────────────┐
  │ General / Site Recipe   │              │ Process Cell            │
  └────────────┬────────────┘              └────────────┬────────────┘
               ▼                                        ▼
  ┌─────────────────────────┐  유닛 자원 할당  ┌─────────────────────────┐
  │ Master Recipe           │ ────────────>│ Unit                    │
  └────────────┬────────────┘              └────────────┬────────────┘
               ▼ 배치 인스턴스 생성                     ▼
  ┌─────────────────────────┐  명령·상태 피드백┌─────────────────────────┐
  │ Control Recipe          │ <───────────>│ Equipment Module        │
  │ (Procedure/Phase)       │              │ (Heater, Agitator 등)   │
  └────────────┬────────────┘              └────────────┬────────────┘
               │ Phase 명령 실행                        ▼
               ▼                           ┌─────────────────────────┐
  ┌─────────────────────────┐              │ Control Module          │
  │ 전자 배치 기록 (EBR)    │ <─────────── │ (Valve, Sensor, Motor)  │
  │ (감사 추적 및 품질 데이터)│    실측 데이터 └─────────────────────────┘
  └─────────────────────────┘
```

- **물리 모델 (Physical Model)** : Enterprise → Site → Area → Process Cell → Unit → Equipment Module → Control Module - 공장 전체 자산을 7개 계층으로 구조화, Unit 단위로 독립적인 제어 경계 설정.
- **절차 모델 (Procedural Model)** : Procedure → Unit Procedure → Operation → Phase - 생산 절차를 4단계로 모듈화, Phase가 Equipment Module/Phase와 직접 통신 수행.
- **레시피 모델 (Recipe Model)** : General Recipe → Site Recipe → Master Recipe → Control Recipe - 제품 사양에서 공장별·설비별 세부 파라미터로 구체화되는 4단계 계층 관리 체계.

## Ⅲ. ISA-88 배치 제어의 세부 구성 요소 및 비교 분석

| 비교 항목 | ISA-88 (Batch Control) | ISA-95 (Enterprise-Control System Integration) |
|---|---|---|
| **표준 성격** | ANSI/ISA-88, IEC 61512 | ANSI/ISA-95, IEC 62264 |
| **주요 영역** | 레벨 1~2(제어·센서) 및 레벨 3(배치 실행) 중심 | 레벨 3(MES/MOM)과 레벨 4(ERP/SCM) 인터페이스 중심 |
| **핵심 목적** | 배치 설비 제어 모듈화 및 레시피 실행 표준화 | 비즈니스 업무와 제조 운영 시스템 간 트랜잭션 표준화 |
| **데이터 모델** | 물리·절차·레시피 모델, Phase 상태 머신 | 자원(Personnel, Material, Equipment), 생산 일정·성과 모델 |
| **상호 관계** | ISA-95 B2MML(Business To MES Markup Language)을 통해 상위 생산 오더를 수신하여 ISA-88 제어 레시피로 분해 구동 |

- ISA-88 배치 제어는 상기 비교 지표를 바탕으로 비즈니스 요구사항과 운영 인프라 환경을 고려한 최적의 아키텍처를 선정하고, 확장성과 안정성을 균형 있게 확보해야 함.

## Ⅳ. ISA-88 배치 제어의 주요 한계점 및 해결 방안

- **이기종 PLC/DCS 상태 머신 파편화 및 연동 지연** :
  - **한계점** : PLC/DCS 벤더별 상태 머신(State Model) 구현 파편화로 이기종 설비 간 Phase 연동 지연 및 락 경합 발생.
  - **해결 방안** : PackML(PackTags) 및 OPC UA 정보 모델 기반의 장비 인터페이스 표준화로 벤더 중립적 제어 통신 규격 적용.
- **레시피 버전 변경 시 현장 태그 불일치 및 오투입 위험** :
  - **한계점** : 마스터 레시피 버전 변경 시 현장 PLC 태그와의 불일치로 인한 오투입 및 배치 폐기 위험.
  - **해결 방안** : 레시피 라이프사이클 관리(RLM) 및 전자 서명(21 CFR Part 11) 기반의 변경 승인·배포 자동 검증 파이프라인 수립.
- **다중 공유 유닛 환경에서의 교착 상태(Deadlock) 위험** :
  - **한계점** : 비선형 공정 및 다중 공유 유닛(Shared Units) 환경에서 교착 상태(Deadlock) 발생 위험.
  - **해결 방안** : 동적 자원 예약 알고리즘 및 유닛 점유 매트릭스 사전 시뮬레이션 기반 자동 예외 처리 로직 결합.

## Ⅴ. ISA-88 배치 제어 적용 및 발전을 위한 기술사적 제언

- **레시피 변경 고도화 및 마스터 레시피 파라미터 추진** : PLC 로직 수기 하드코딩 재작업의 한계를 탈피하고, 마스터 레시피 파라미터 변경만으로 즉시 적용을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- **설비 재사용성 고도화 및 표준화된 Phase 모듈 추진** : 설비 변경 시 제어 로직 전면 재개발의 한계를 탈피하고, 표준화된 Phase 모듈 재조립으로 즉각 대응을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
- **품질 검증 강화 및 신뢰성 확보 방안** : 공정 종료 후 수기 배치 기록 검토의 한계를 탈피하고, 실시간 EBR 기반 이상치 예외 검토(Review by Exception)을 체계적으로 추진하여 실무 운영 효율성과 엔지니어링 신뢰성을 극대화해야 함.
