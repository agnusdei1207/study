```text
[RSA] ◀━━ 머리: Ⅶ 내 의견 (소인수분해 난제 기반 공개키의 한계 극복 → 2048비트 이상 유지 및 양자 컴퓨팅 대비 PQC 하이브리드 전환)
 ┃
 ┣━ Ⅰ 개요 ───── 큰 두 소수의 곱을 구하는 연산은 쉬우나 이를 다시 두 소수로 분해하는 것은 극도로 어렵다는 '소인수분해의 수학적 난제'에 기반하여 암복호화와 전자서명을 모두 제공하는 최초의 상용 공개키 암호 알고리즘
 ┣━ Ⅱ 특징 ───── 암호화와 전자서명 겸용 가능 · 비대칭키 구조(공개키 $e$, 개인키 $d$) · 대칭키 암호 대비 수백 배 느린 연산 속도 · 오일러 파이 함수와 모듈러 역원 기반
 ┣━ Ⅲ 구조 ───── 두 소수 $p, q$ + 모듈러스 $n=pq$ + 공개 지수 $e$ + 비밀 지수 $d$ ($ed \equiv 1 \pmod{\phi(n)}$)
 ┣━ Ⅳ 흐름 ───── 키 생성($p, q \rightarrow n, \phi(n), e, d$) → 암호화($C = M^e \pmod n$) → 복호화($M = C^d \pmod n$) / 서명($S = H(M)^d \pmod n$) → 검증($H(M) = S^e \pmod n$)
 ┣━ Ⅴ 비교 ───── RSA(소인수분해 난제, 암복호화/서명 겸용, 공개키 연산 $e=65537$ 적용 시 검증 고속) vs DSA(이산대수 난제, 서명 전용, 서명 생성 고속, 검증 지연)
 ┗━ Ⅵ 실무 ───── 단순 RSA(Textbook)의 곱셈 동형성 취약점 / 1024비트 이하 키의 인수분해 취약 / 쇼어(Shor) 알고리즘을 악용한 양자 컴퓨터 해독 위험
```

## 한 줄 본질
- 사전에 대칭키를 안전하게 나눠줄 수 없는 키 배송 병목 → 큰 소수의 곱셈과 소인수분해 간의 계산 복잡도 비대칭을 이용해 공개키로 암호화하고 개인키로 복호화 → 전 세계 안전한 키 교환 및 전자서명 실현 / 대칭키 대비 막대한 CPU 연산 비용 발생

## 핵심 그림
```text
[RSA 암호화 및 전자서명의 수학적 메커니즘]

[1. 키 생성 단계]
  - 두 개의 큰 소수 $p, q$ 선택 ──> $n = p \times q$, $\phi(n) = (p-1)(q-1)$
  - 공개키 $e$ 선택 ($1 < e < \phi(n)$, $\gcd(e, \phi(n)) = 1$)
  - 개인키 $d$ 계산 ($ed \equiv 1 \pmod{\phi(n)}$, 확장 유클리드 호제법)
  ─────────────────────────────────────────────────────────────
  - 공개키: $(e, n)$  /  개인키: $(d, n)$

[2. 기밀성 암복호화 흐름]           [3. 전자서명 및 검증 흐름]
     [송신자]          [수신자]          [서명자]          [검증자]
        │                 │                 │                 │
     (평문 M)          (암호문 C)        (원문 M)          (원문 M, 서명 S)
        │                 │                 │                 │
   $C = M^e \pmod n$ $M = C^d \pmod n$ $S = H(M)^d \pmod n$ $H(M) = S^e \pmod n$
   (수신자 공개키로) (수신자 개인키로) (자신의 개인키로) (서명자 공개키로)
```

## 핵심 용어
- 소인수분해 난제 (IFP, Integer Factorization Problem): 충분히 큰 두 소수 $p, q$의 곱 $n$이 주어졌을 때, 다항식 시간 내에 $n$으로부터 $p$와 $q$를 찾아내는 효율적인 고전 알고리즘이 존재하지 않는다는 수학적 복잡도
- RSA-OAEP (Optimal Asymmetric Encryption Padding): 평문에 무작위 난수를 섞는 2단계 Feistel 네트워크 구조를 적용하여 Textbook RSA의 결정론적 결함을 제거하고 IND-CCA2 안전성을 보장하는 국제 표준 패딩

## 핵심 통찰
- Textbook RSA(패딩 없는 순수 RSA)는 절대로 프로덕션에 쓰면 안 됨 → $C_1 \times C_2 = (M_1 \times M_2)^e \pmod n$이라는 곱셈 동형성(Multiplicative Homomorphism) 때문에 공격자가 암호문 조작만으로 평문을 변조할 수 있음
- 공개 지수 $e$는 보통 $65537(2^{16}+1)$이라는 고정값을 씀 → 1의 비트 수가 2개뿐이라 모듈러 거듭제곱 시 쉬프트와 덧셈 몇 번으로 고속 연산이 가능하여 "암호화 및 서명 검증이 초고속"으로 끝남
- RSA는 양자 컴퓨터 앞에서 무력함 → 큐비트 수가 충분한 양자 컴퓨터에서 쇼어(Shor) 알고리즘을 구동하면 소인수분해가 다항식 시간($O((\log n)^3)$)에 풀려 개인키가 즉각 노출됨

## 이웃 토픽과 구분
- RSA vs DSA: RSA = 소인수분해 난제 기반, 데이터 암복호화 및 전자서명 겸용, 검증 연산 고속 / DSA = 이산대수 난제(ElGamal) 기반, 오직 전자서명만 가능, 서명 생성 고속 및 검증 지연

## 문제·원인·대책
- 사례: 오래된 레거시 시스템에서 1024비트 RSA 키를 사용하다가 클러스터 컴퓨팅을 통한 소인수분해 위험에 노출된 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 컴퓨팅 성능 향상으로 인한 1024비트 RSA 키 무력화 | 소인수분해 연산 알고리즘(GNFS) 발전 및 클라우드 연산 파워 증가 | RSA 키 길이를 최소 2048비트(권장 3072비트 이상)로 강제 상향 | 2030년 이후까지 고전 컴퓨팅 해독 공격에 대한 안전성 확보 |
| 선택 암호문 공격(CCA)을 통한 RSA 복호화 오라클 침해 | PKCS#1 v1.5 패딩 처리 에러 메시지의 시간차 노출(Bleichenbacher 공격) | 안전성이 증명된 최신 RSA-OAEP 및 RSA-PSS 패딩 모드로 교체 | 에러 정보 누출 차단 및 IND-CCA2 수학적 증명 획득 |

## 이렇게 출제된다
- 제126회 4교시 5번: "RSA(Rivest-Shamir-Adleman)알고리즘과 DSA(Digital Signature Algorithm)을 비교하여 설명하시오." → 요구 포인트: Ⅰ RSA/DSA 수학적 난제 + Ⅲ 알고리즘 키 생성 및 서명 흐름 + Ⅴ 난제, 용도, 키 길이, 연산 속도(서명/검증) 종합 비교표

## 내 의견
- [RSA에서 ECC 및 PQC로의 단계적 마이그레이션] RSA 2048비트가 요구하는 대역폭과 연산 부하는 모바일 단말과 IoT 환경에서 심각한 배터리 소모와 성능 저하를 유발함 → 나라면: 신규 웹/앱 서비스의 기본 TLS 및 서명 알고리즘을 256비트 타원곡선(ECDSA/Ed25519)으로 전면 교체하고, 장기 보존이 필요한 금융/공공 인프라는 미국 NIST 표준 양자내성암호(ML-KEM, ML-DSA)를 RSA와 결합하는 '하이브리드 암호화' 파이프라인을 구축
