## 한 줄 본질
- 시스템 운용 및 프로그램 실행 과정에서 자동으로 생성되는 파생 흔적 → 운영체제 내부 구조체 파싱을 통해 사용자의 과거 행위와 공격자의 실행 궤적 복원 → 침해 행위 과학적 입증 / 시간 위변조 조작 가능성 상존

## 핵심 용어
- 프리패치(Prefetch): 응용프로그램의 빠른 로딩을 위해 윈도우가 생성하는 캐시 파일로, 실행 횟수, 최초/최종 실행 시각, 로드된 DLL 목록 보관
- 타임스톰핑(Timestomping): 침해 흔적을 은폐하기 위해 파일의 생성·수정 일시(MACB)를 정상 시스템 파일 시각으로 조작하는 안티포렌식 기법

## 핵심 통찰
- 공격자가 악성코드 실행 파일을 삭제하더라도 Prefetch와 Amcache에 프로그램 명칭, 해시(SHA-1), 최초 실행 시각이 고스란히 남아 있음
- 파일 탐색기에서 보이는 시간 정보($STANDARD_INFORMATION)는 타임스톰핑으로 조작하기 쉬우나, MFT 레코드 내부의 $FILE_NAME 속성 및 $UsnJrnl 저널 로그는 수정하기 어려워 교차 대조 시 위변조 적발 가능
- USB 등 이동식 저장장치 연결 흔적은 USBSTOR 레지스트리와 setupapi.dev.log를 대조하여 디바이스 고유 시리얼 번호와 최초/최종 연결 시각을 완벽히 특정할 수 있음

## 이웃 토픽과 구분
- 아티팩트 vs 이벤트 로그: 이벤트 로그 = 사전에 로깅 설정된 이벤트만 구조화하여 기록 / 아티팩트 = 운영체제가 시스템 성능 최적화 및 상태 유지를 위해 자동으로 생성하는 모든 부산물

## 문제·원인·대책
- 사례: 137회 기출 내부 정보 유출자가 악성코드 파일 타임스탬프를 조작(Timestomping)하여 포렌식 추적을 회피한 사건
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 파일 생성 시각 조작으로 침해 시점 분석 교란 | $STANDARD_INFORMATION 속성만 수정 도구로 변경 | $FILE_NAME 타임스탬프 및 $UsnJrnl 트랜잭션 저널 대조 분석 | 조작된 타임스탬프 적발 및 실제 실행 시점 규명 |
| 안티포렌식 도구로 프리패치 일괄 삭제 | 아티팩트 삭제를 통한 행위 증거 인멸 | VSS(Volume Shadow Copy) 백업 본에서 과거 삭제 시점의 .pf 파일 복원 | 삭제된 실행 흔적 복원 및 인멸 행위 자체 입증 |
