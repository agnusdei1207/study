## 답안 골격
```text
[식별·인증·인증 요소] ◀━━ 머리: Ⅶ 내 의견 (단순 2단계 인증(2FA) 탈피 → 컨텍스트 기반 적응형 다중인증(Adaptive MFA) 및 무자각 지속인증으로 진화)
 ┃
 ┣━ Ⅰ 개요 ───── 정보자산 접근통제의 출발점 → 주체의 신원 주장(식별)과 진위 확인(인증)을 통해 비인가 접근을 원천 차단하는 핵심 메커니즘
 ┣━ Ⅱ 특징 ───── IAAA(식별·인증·인가·책임추적성) 4단계 체계 · 인증 요소의 다변화(지식/소유/존재/행위/위치) · 다중요소인증(MFA) 강제
 ┣━ Ⅲ 구조 ───── 식별자(ID, 사번) · 인증 메커니즘(패스워드, OTP, 생체인증) · 접근권한 부여(Authorization) · 감사로그(Accountability)
 ┣━ Ⅳ 흐름 ───── ① 주체 신원 주장(식별, ID 입력) → ② 증명 정보 제시(인증, PW/OTP/지문) → ③ 인증 성공 시 권한 토큰 발급(인가) → ④ 활동 기록 보관(감사)
 ┣━ Ⅴ 비교 ───── 식별(Identification: "내가 누구다" 주장) vs 인증(Authentication: 주장의 "진위 여부 증명") vs 인가(Authorization: "수행할 수 있는 권한 부여")
 ┗━ Ⅵ 실무 ───── 동일 범주의 2가지 수단(2-Step)을 2요소(2FA)로 오인 / SMS 인증의 SIM 스와핑 취약성 / 피싱 저항성 FIDO2 MFA 도입
```

- 필수 키워드: 식별(Identification) · 인증(Authentication) · IAAA · 인증 4대 요소(지식·소유·존재·행위) · MFA · 적응형 인증 · FIDO
- 배점 전략: 10점 = Ⅰ 정의 및 IAAA 체계 → Ⅲ 인증 4대 요소 분류 도식 → Ⅴ 식별 vs 인증 vs 인가 비교 / 25점 = Ⅰ~Ⅶ 전개, 인증 요소별 장단점 및 Ⅵ 피싱 저항성 다중인증(MFA) 실무 구현 대책 집중
- 기출: KPC 120회/128회 `식별과 인증의 개념, 인증의 4대 요소 및 다중요소인증(MFA) 구현 방안` → Ⅰ IAAA + Ⅲ 인증 4대 요소 + Ⅵ MFA 실무

## 한 줄 본질
- 주체의 신원 사칭과 비인가 자원 접근으로 인한 보안 침해 병목 → 식별자 제시 후 서로 다른 독립된 인증 요소(지식/소유/생체)를 조합해 본인 여부를 엄격히 검증 → 신원 도용 차단 / 사용자 로그인 번거로움 및 인증 인프라 관리 비용 발생

## 핵심 그림
```text
[IAAA 접근통제 4단계 및 4대 인증 요소(Factor)]

 [1. 식별 (Identification)]  ──> [2. 인증 (Authentication)] ──> [3. 인가 (Authorization)] ──> [4. 책임추적성 (Accountability)]
  - 주체 신원 주장              - 신원 진위 여부 증명         - 최소 권한 자원 매핑        - 감사 로그 및 부인방지
  - ID, 사번, 이메일            - [ 4대 인증 요소 조합 ]       - RBAC / ABAC 역할 정책       - SIEM 감사 기록

 ┌────────────────────────────────────────────────────────┐
 │ * 4대 인증 요소 (Authentication Factors)               │
 │  1. 지식 기반 (Something You Know) : 비밀번호, PIN     │
 │  2. 소유 기반 (Something You Have) : OTP, 스마트카드   │
 │  3. 존재/생체 (Something You Are)  : 지문, 홍채, 안면  │
 │  4. 행위/위치 (Something You Do)   : 타이핑 리듬, GPS  │
 └────────────────────────────────────────────────────────┘
```

## 핵심 용어
- IAAA 체계: 보안 접근통제의 기본 4단계로 식별(Identification), 인증(Authentication), 인가(Authorization), 책임추적성(Accountability)을 의미
- 진정한 다중요소인증(True MFA): 서로 다른 2개 이상의 범주(Factor)를 결합한 인증(예: 지식 + 소유). 동일 범주 2개(예: ID/비번 + 질문 답변)는 2단계 인증(2-Step)일 뿐 MFA가 아님

## 핵심 통찰
- 사용자가 비밀번호를 입력하고 이어서 2차 비밀번호를 입력하는 것은 '지식 + 지식'이므로 2FA가 아님 → 두 번째 비밀번호도 유출될 위험에 똑같이 노출되어 있음
- 소유 기반 인증 중 SMS와 ARS는 피싱 사이트 프록시(Evilginx)나 SIM 스와핑 공격에 쉽게 가로채이므로 현대 보안 표준(NIST SP 800-63B)에서는 '제한적 허용'으로 격하됨
- 미래 인증의 지향점은 '무자각 지속인증(Continuous Authentication)'임 → 로그인 시점에만 1회 검증하고 끝내는 것이 아니라, 세션 유지 중 사용자의 마우스 움직임, 타이핑 습관, 네트워크 위치를 AI로 상시 감시해 탈취된 세션을 즉시 차단함

## 이웃 토픽과 구분
- 인증(Authentication) vs 인가(Authorization): 인증 = "당신이 홍길동 본인이 맞는가?"(신원 검증) / 인가 = "홍길동이 재무 DB의 결제 승인 버튼을 누를 권한이 있는가?"(권한 부여)

## 문제·원인·대책
- 사례: 패스워드와 SMS 인증번호를 조합한 2단계 인증을 사용했으나, 피싱 사이트에 접속한 사용자가 두 정보를 실시간으로 입력하여 계정을 탈취당한 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| SMS/OTP 번호를 실시간 가로채는 역방향 프록시 피싱 | 소유 기반 인증 수단이 도메인에 암호학적으로 결속되지 않음 | 피싱 저항성 FIDO2(WebAuthn/패스키) 기반 MFA 적용 | 피싱 사이트 접속 시 챌린지 서명 실패로 침해 원천 차단 |
| 로그인 성공 후 세션 토큰 탈취에 의한 측면 이동 | 세션 수립 후 지속적인 사용자 신원 검증 부재 | 사용자의 접속 IP 급변, 기기 지문 변경 탐지 시 강제 재인증(적응형 MFA) | 탈취된 세션 쿠키 악용 실시간 차단 |

## 이렇게 출제된다
- 제128회 기출: "식별과 인증의 개념을 정의하고, 사용자 인증의 4대 요소 및 다중요소인증(MFA) 구축 시 고려사항을 설명하시오." → 요구 포인트: Ⅰ IAAA 및 식별/인증/인가 비교 + Ⅲ 4대 인증 요소 특성 + Ⅵ 실무 MFA 구축 방안

## 내 의견
- [보안성과 사용자 경험(UX)의 제로섬 착각] 인증 단계를 무작정 3개, 4개로 늘리면 사용자가 메모지에 비번을 적어두거나 인증 절차를 우회하는 섀도우 IT를 초래함 → 나라면: 평소 신뢰된 기기와 사내망에서는 FIDO 지문 인식 1회만으로 통과시키는 패스워드리스를 적용하고, 평소와 다른 낯선 환경 접속 시에만 단계적 추가 인증을 요구하는 '위험 기반 적응형 인증(Context-Aware Adaptive MFA)' 구축
