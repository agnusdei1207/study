```text
 ┃
 ┣━ Ⅰ 개요 ───── 운영 단계 보안 패치의 천문학적 비용(Boehm 법칙) → 소프트웨어 개발 생명주기(SDLC) 구현 단계 취약점 원천 배제
 ┣━ Ⅱ 특징 ───── 행정안전부 7대 취약점 분류 · CWE/SANS Top 25 준수 · 정적/동적 코드 진단 · 개발자 보안 습관화
 ┣━ Ⅲ 구조 ───── 7대 보안 약점(입력데이터 검증·보안기능·시간및상태·에러처리·코드오류·캡슐화·API악용)
 ┣━ Ⅳ 흐름 ───── ① 보안 코딩 규칙 수립 → ② 소스코드 구현 → ③ 정적 분석(SAST) 진단 → ④ 결함 조치 및 빌드
 ┣━ Ⅴ 비교 ───── SAST(정적 분석, 화이트박스, 코드 레벨) vs DAST(동적 분석, 블랙박스, 런타임 공격 시뮬레이션)
 ┗━ Ⅵ 실무 ───── 오탐(False Positive) 정리에 따른 개발 지연 / AI 생성 코드 보안 결함 검증 / 레거시 코드 리팩토링
```
- 필수 키워드: 행정안전부 7대 보안약점 · CWE · SAST · DAST · Boehm의 결함 수정 비용 곡선 · 파라미터화 쿼리
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 행안부 7대 보안약점 표 → Ⅴ SAST vs DAST 비교 / 25점 = Ⅰ~Ⅶ 전개, Ⅳ DevSecOps 연동 절차와 Ⅵ 개발 생산성 저하 방지 대책 집중

## 한 줄 본질
- 소프트웨어 개발 초기부터 보안 약점을 사전에 제거하여 해킹 공격에 악용될 소지를 원천 봉쇄하는 개발 기법 → 운영 단계 장애 및 사고 복구 비용 극적 절감 / 개발 기간 증가 및 도구 오탐 처리 비용 수반

## 핵심 용어
- 보안 약점(Weakness) vs 보안 취약점(Vulnerability): 보안 약점(CWE) = 소프트웨어 버그나 결함 자체 / 보안 취약점(CVE) = 보안 약점이 실제 공격에 악용될 수 있는 상태
- 정적 응용프로그램 보안 테스트(SAST): 컴파일 또는 실행 없이 소스코드의 구문 트리(AST)와 데이터 흐름(Taint Analysis)을 추적해 결함을 찾는 도구

## 핵심 통찰
- 배포 후 운영 단계에서 취약점을 발견해 긴급 패치하는 비용은 설계·구현 단계에서 시큐어 코딩으로 제거하는 비용의 30배에서 100배에 달함 (Boehm의 법칙)
- 시큐어 코딩은 개발자의 코딩 규약 준수만으로는 달성하기 어려우며, 형상관리(Git) 커밋 시 자동으로 빌드를 차단하는 게이트웨이가 필수적임
- 최근 GitHub Copilot 등 AI가 생성한 소스코드에서 SQL 인젝션 및 하드코딩된 암호화 키 등 보안 약점이 다량 포함되는 사례가 급증함

## 이웃 토픽과 구분
- 시큐어 코딩 vs WAF(웹 방화벽): WAF = 취약한 코드가 있더라도 외부 공격 트래픽을 네트워크 단에서 차단하는 사후 대책 / 시큐어 코딩 = 코드 자체의 결함을 제거하는 근본 대책

## 문제·원인·대책
- 사례: 125회 기출 문자열 연결 방식으로 SQL 쿼리를 생성하여 고객 계정 전수 노출된 SQL 인젝션 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 사용자 입력값이 SQL 쿼리 구조로 직접 실행 | 동적 SQL 쿼리 문자열 결합(String Concat) 사용 | 파라미터화된 쿼리(PreparedStatement) 강제 및 ORM 안전 모드 적용 | 입력값이 무조건 데이터 리터럴로 처리되어 인젝션 원천 차단 |
| 수천 건의 SAST 오탐으로 개발팀 검토 거부 | 문맥을 고려하지 않는 단순 키워드 매칭 정적 룰 | Taint Analysis(오염 경로 추적) 엔진 도입 및 전사 룰셋 최적화 | 실질적 크리티컬 약점 90% 이상 집중 조치 |
