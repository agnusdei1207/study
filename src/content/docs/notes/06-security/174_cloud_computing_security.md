# 클라우드 컴퓨팅 보안(Cloud Security)

## 핵심 개념
- 온디맨드 형태로 제공되는 클라우드 환경(IaaS, PaaS, SaaS)에서 데이터, 애플리케이션, 인프라를 외부 침해 및 내부 오남용으로부터 보호하기 위한 보안 아키텍처와 기술·관리적 통제 체계.
- 클라우드 서비스 제공자(CSP)와 이용자(Customer) 간의 명확한 역할과 의무를 규정하는 '책임 공유 모델(Shared Responsibility Model)'을 기반으로 작동.

```
+-------------------------------------------------------------+
|                      클라우드 보안 핵심 축                     |
+-------------------------------------------------------------+
| 1. 책임 공유 모델 | CSP(인프라 보안) vs 고객(데이터/접근제어 보안)   |
| 2. 형상/설정 관리 | 클라우드 잘못된 설정(Misconfiguration) 자동 점검 |
| 3. 아이덴티티 통제| IAM 최소 권한 원칙, 임시 자격증명(STS) 활용     |
| 4. 클라우드 네이티브| 컨테이너, 서버리스, 워크로드 전 주기 보호(CNAPP) |
+-------------------------------------------------------------+
```

---

## 서비스 모델별 책임 공유 모델 (Shared Responsibility Model)

```
[ 계 층 ]             [ IaaS ]            [ PaaS ]            [ SaaS ]
+------------------+-------------------+-------------------+-------------------+
| 데이터 및 분류   |    고객 책임      |    고객 책임      |    고객 책임      |
+------------------+-------------------+-------------------+-------------------+
| 클라이언트/계정  |    고객 책임      |    고객 책임      |    고객 책임      |
+------------------+-------------------+-------------------+-------------------+
| 애플리케이션     |    고객 책임      |    고객 책임      |    CSP 책임       |
+------------------+-------------------+-------------------+-------------------+
| 런타임/미들웨어  |    고객 책임      |    CSP 책임       |    CSP 책임       |
+------------------+-------------------+-------------------+-------------------+
| 운영체제 (OS)    |    고객 책임      |    CSP 책임       |    CSP 책임       |
+------------------+-------------------+-------------------+-------------------+
| 하이퍼바이저/가상|    CSP 책임       |    CSP 책임       |    CSP 책임       |
+------------------+-------------------+-------------------+-------------------+
| 물리 인프라/시설 |    CSP 책임       |    CSP 책임       |    CSP 책임       |
+------------------+-------------------+-------------------+-------------------+
```

- **CSP의 책임 (Security OF the Cloud)**: 전산 센터의 물리적 보안, 전력/공조, 하드웨어 호스트, 가상화 하이퍼바이저 및 네트워크 시설의 보안.
- **고객의 책임 (Security IN the Cloud)**: 가상 머신 OS 패치, 방화벽(보안 그룹) 설정, 네트워크 라우팅, IAM 계정 권한 부여, 저장/전송 데이터 암호화.

---

## 클라우드 주요 보안 위협 (CSA Top Threats)

### 1. 보안 설정 오류 (Cloud Misconfiguration)
- AWS S3 버킷의 퍼블릭 읽기 권한 방치, 과도하게 개방된 보안 그룹 포트(0.0.0.0/0 SSH/RDP 허용)로 인한 무단 데이터 유출.

### 2. 과도한 권한 및 부적절한 IAM 관리
- 하드코딩된 장기 API 액세스 키(Access Key)의 GitHub 공개 유출, 루트 계정 일상적 사용 및 과도한 와일드카드(`*`) 관리자 권한 부여.

### 3. 멀티테넌시 취약점 및 측면 이동
- 하이퍼바이저 탈출(Hypervisor Escape) 결함을 악용하여 동일 물리 서버를 공유하는 다른 고객의 가상머신 메모리에 접근.

## 최신 클라우드 네이티브 보안 도구 체계 (CNAPP)

```
+-------------------------------------------------------------+
|              CNAPP (클라우드 네이티브 애플리케이션 보호 플랫폼)     |
+-------------------------------------------------------------+
| 1. CSPM (Cloud Security Posture Management)                 |
|    - 클라우드 리소스 설정 오류 감시, 규제 준수(CIS Benchmark) 자동 점검 |
|                                                             |
| 2. CWPP (Cloud Workload Protection Platform)                |
|    - VM, 컨테이너, 서버리스 런타임 악성코드 및 이상 행위 실시간 방어 |
|                                                             |
| 3. CIEM (Cloud Infrastructure Entitlement Management)       |
|    - 클라우드 계정/역할 간 불필요한 과도 권한 탐지 및 최소 권한 강제 |
|                                                             |
| 4. KSPM (Kubernetes Security Posture Management)            |
|    - 쿠버네티스 클러스터 설정, RBAC, 네트워크 정책 취약점 분석       |
+-------------------------------------------------------------+
```

## 국내 클라우드 보안 규제: CSAP (클라우드 보안인증)

- **정의**: 공공기관에 민간 클라우드 서비스를 제공하기 위해 KISA가 클라우드 서비스의 안전성과 신뢰성을 평가·인증하는 제도.
- **등급제 개편**:
  - **상등급**: 국가 안보, 외교, 국방, 수사 등 민감 정보를 다루는 시스템 (논리적·물리적 망분리 엄격 적용).
  - **중등급**: 비공개 업무 및 대민 행정 시스템 (논리적 망분리 허용).
  - **하등급**: 개인정보를 포함하지 않는 공개 데이터 시스템 (논리적 망분리 허용, 해외 CSP 진입 허용).

## 결론 및 실무 시사점
- 클라우드 침해 사고의 95% 이상은 CSP의 인프라 결함이 아닌 고객 측의 '설정 오류(Misconfiguration)'와 IAM 권한 관리 부실에서 발생함.
- 개발 단계부터 IaC(Infrastructure as Code) 보안 스캐닝을 적용하고, CSPM 및 CIEM을 연동하여 클라우드 형상 변경을 지속적으로 자동 감사하는 DevSecOps 체계를 확립해야 함.
