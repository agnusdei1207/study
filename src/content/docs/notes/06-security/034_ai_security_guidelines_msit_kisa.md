## 답안 골격
```text
[AI 보안 안내서] ◀━━ 머리: Ⅶ 내 의견 (형식적 체크리스트 탈피 → AI 라이프사이클 전주기 MLOps 보안 파이프라인 실무 적용)
 ┃
 ┣━ Ⅰ 개요 ───── 생성형 AI 확산에 따른 데이터 유출 및 신종 보안 위협 대응 → 정부(과기정통부·KISA) 차원의 종합 보안 실무 가이드라인
 ┣━ Ⅱ 특징 ───── AI 생애주기 전주기(기획·설계·개발·배포·운영) 통제 · 개발자/운영자/이용자 역할별 수칙 · 공격 기법별 대응책 제시
 ┣━ Ⅲ 구조 ───── 4대 생애주기별 보안 요구사항(학습데이터 수집/가공, 모델 개발/학습, 서비스 배포/운영, 사용자 활용)
 ┣━ Ⅳ 흐름 ───── ① 데이터 적법 수집/정제 → ② 모델 무결성 검증/적대적 훈련 → ③ 배포 전 레드티밍 → ④ 런타임 입출력 모니터링
 ┣━ Ⅴ 비교 ───── AI 보안 안내서(기술적 보안 위협 방어 중심) vs AI 윤리 기준(공정성, 투명성, 인권 등 가치 중심)
 ┗━ Ⅵ 실무 ───── 학습데이터 오염(Data Poisoning) 방지 / 프롬프트 인젝션 및 모델 전도 방어 / 사내 기밀 유출 차단
```
- 필수 키워드: 과기정통부·KISA · AI 생애주기 보안 · 데이터 중독 · 모델 추출(Model Extraction) · 레드티밍 · 입출력 가드레일
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ AI 생애주기별 4단계 보안 통제 도식 → Ⅴ 보안 안내서 vs 윤리 기준 비교 / 25점 = Ⅰ~Ⅶ 전개, 생애주기별 핵심 위협 대응표와 Ⅵ 기업 내 생성형 AI 도입 거버넌스 집중
- 기출: 미출제. 예상: "과기정통부와 KISA가 발표한 '생성형 AI 서비스 보안 안내서'의 생애주기별 주요 보안 위협과 단계별 보안 대책을 설명하시오."

## 한 줄 본질
- AI 서비스의 기획부터 학습 데이터 수집, 모델 개발, 배포 및 운영 전 과정에서 발생할 수 있는 보안 위협을 식별하고 기술적·관리적 보호대책을 제시한 국가 표준 실무 안내서 → 안전한 AI 도입 및 비즈니스 리스크 최소화 / 개발 파이프라인의 보안 검증 비용 증가

## 핵심 용어
- 모델 전도 공격(Model Inversion Attack): 모델의 출력값(확률 분포)을 반복적으로 질의하고 분석하여 모델 훈련에 사용되었던 민감한 학습 데이터(예: 얼굴 사진, 환자 기록)를 역추적해 복원해내는 공격
- AI 레드티밍(AI Red Teaming): AI 모델을 실제 서비스에 배포하기 전에 윤리적 해커들이 프롬프트 인젝션, 탈옥, 유해 정보 생성 등을 고의로 시도하여 취약점을 사전에 찾아내는 전문 평가 활동

## 핵심 통찰
- 이 안내서는 전통적 소프트웨어 보안(OWASP Top 10)과 달리 데이터와 모델 자체의 무결성을 보호하는 MLOps 보안(SecMLOps)을 핵심으로 다룸
- 기업 임직원이 ChatGPT 등 공개 생성형 AI에 사내 소스코드나 회의록을 입력하여 기밀이 외부 학습 데이터로 전용되는 정보 유출 사고를 방지하기 위한 이용자 수칙을 구체적으로 규정함
- 모델 개발 단계에서 외부 허브(Hugging Face 등)에서 다운로드한 사전 학습 모델(Pre-trained Model) 파일 내부에 악성코드가 직렬화(Pickle 취약점)되어 있을 위험을 경고함

## 이웃 토픽과 구분
- AI 보안 안내서 vs NIST AI RMF: AI 보안 안내서 = 기술적 보안 위협과 침해 방어 통제에 집중한 실무서 / NIST AI RMF = 거버넌스(Govern), 매핑(Map), 측정(Measure), 관리(Manage) 중심의 프레임워크

## 문제·원인·대책
- 사례: 사내 개발자가 미공개 반도체 회로 소스코드를 최적화하기 위해 공개 LLM 서비스에 복사해 넣어 데이터가 외부 유출된 사건
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 상용 LLM 프롬프트 입력을 통한 기업 핵심 IP 유출 | 사내 AI 활용 보안 가이드라인 부재 및 프롬프트 DLP 미적용 | 엔터프라이즈 프라이빗 LLM 도입 및 프롬프트 DLP 솔루션 연동 | 외부 AI 모델 학습 데이터 전용 원천 차단 |
| 다운로드한 오픈소스 모델 가중치 실행 중 RCE 악성코드 감염 | 검증되지 않은 Pickle 포맷 모델 파일 무검증 로드 | Safetensors 안전 포맷 강제 및 모델 파일 해시 무결성 검증 | 가중치 역직렬화 공격 사전 차단 |

## 내 의견
- [가이드라인 배포 후 사내 전파 및 이행 점검의 부재] 정부 가이드라인이 발표되어도 사내 보안 규정에 반영하지 않고 방치하여 임직원의 비인가 섀도우 AI(Shadow AI) 사용으로 인한 정보 유출 지속 → 나라면: 안내서의 핵심 요구사항을 사내 취약점 점검 표준에 즉시 이식하고, 사내 프라이빗 LLM 게이트웨이를 구축해 모든 임직원의 AI 사용 트래픽을 단일 통제선으로 유도
