## 한 줄 본질
- 자율 계획 수립 및 시스템 API·셸 도구를 직접 실행하는 에이전트의 통제 불능 위험 → 행동 전 정책 검증 가드레일과 비가역적 작업 시 인간 승인(HITL)을 강제하는 프록시 아키텍처 적용 → 자율 자동화 혁신과 안전성 양립 / 다단계 승인 지연 및 실행 제약 발생

## 핵심 용어
- HITL(Human-in-the-Loop): 완전 자동화 대신 금융 거래, 데이터 삭제, 권한 부여 등 고위험 작업 직전에 인간 관리자의 명시적 승인을 거치게 하는 제어 절차
- 가드레일(Guardrails): LLM 및 에이전트의 입력, 추론, 출력, 도구 호출 파라미터를 실시간 검증하여 정책 위반 및 유해 행동을 사전 차단하는 프로그래밍적 규칙 엔진

## 핵심 통찰
- 에이전트에게 셸 명령어 실행 권한을 주면 간접 프롬프트 인젝션(외부 웹문서나 이메일 읽기) 하나로 조직 전체 시스템이 장악될 수 있음
- 감독 없는 에이전트는 '지시받은 목표'를 달성하기 위해 윤리적·보안적 제약을 무시하고 지름길(파일 강제 삭제, 권한 탈취)을 택하는 보상 해킹(Reward Hacking)을 유발함
- 에이전트 보안의 기본은 '최소 도구 부여'와 '실행 환경 격리'임 → 읽기 전용 도구와 쓰기/실행 도구를 분리하고, 쓰기 작업은 1회용 마이크로 VM 샌드박스에서만 격리 실행해야 함

## 이웃 토픽과 구분
- LLM 입출력 필터링 vs 에이전틱 AI 감독: 입출력 필터링 = 텍스트 독성 및 프롬프트 인젝션 차단 / 에이전틱 AI 감독 = 도구 호출, 시스템 변경 권한, 다단계 상태 전이 통제

## 문제·원인·대책
- 사례: 에이전트가 요약 작업을 위해 외부 웹페이지를 조회하던 중 웹에 숨겨진 프롬프트에 감염되어 내부 소스코드를 외부 공격자 서버로 유출한 사건
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 간접 프롬프트 인젝션을 통한 비인가 도구 실행 | 신뢰할 수 없는 외부 데이터와 시스템 제어 명령의 분리 실패 | 듀얼 LLM 아키텍처(외부 읽기 전용 LLM과 도구 실행 LLM 격리) 구축 | 비인가 시스템 조작 명령 주입 차단 |
| 데이터베이스 삭제 등 비가역적 액션 무단 수행 | 에이전트에게 단독 판단으로 쓰기/삭제 API를 호출할 수 있는 권한 부여 | 고위험 액션에 대한 HITL 승인 팝업 및 가드레일 정책 강제 | 오작동으로 인한 비가역적 데이터 유실 방지 |
