## 답안 골격
```text
[패스키(Passkey)] ◀━━ 머리: Ⅶ 내 의견 (비밀번호 없는 사회(Passwordless) 구현 → FIDO2 패스키 도입 및 기기 분실 대비 계정 복구 체계 표준화)
 ┃
 ┣━ Ⅰ 개요 ───── 기억하기 어렵고 유출·피싱에 취약한 전통 비밀번호 체계 종식 → FIDO2/WebAuthn 표준 기반 공개키 암호화 및 동기화 자격증명
 ┣━ Ⅱ 특징 ───── 피싱 원천 차단(도메인 바인딩) · 서버에 비밀정보 미보관 · 생체인증 결합(간편성) · 클라우드 키체인 간 다기기 동기화
 ┣━ Ⅲ 구조 ───── 클라이언트(사용자 단말 생체센서) · 브라우저/OS(WebAuthn API) · FIDO2 인증서버 · 공개키 쌍(단말 개인키, 서버 공개키)
 ┣━ Ⅳ 흐름 ───── ① 사용자 등록 시 단말에서 비대칭 키쌍 생성 → ② 서버에 공개키만 등록 → ③ 로그인 시 서버가 난수(Challenge) 전송 → ④ 생체인증 후 개인키로 서명 반환 및 검증
 ┣━ Ⅴ 비교 ───── 패스워드(서버 유출 시 전면 노출, 피싱 취약) vs 기존 FIDO 하드웨어 키(기기 종속, 분실 시 복구 불가) vs 패스키(클라우드 안전 동기화, 피싱 불가능)
 ┗━ Ⅵ 실무 ───── 단말 분실 시 계정 복구(Recovery) 난제 / 기업 인프라(사설망) 연동 호환성 / 생태계(애플/구글/MS) 간 키 이전 제약
```
- 필수 키워드: 패스키(Passkey) · FIDO2 · WebAuthn · 패스워드리스(Passwordless) · 도메인 바인딩 · 비대칭키 · 클라우드 키체인 동기화
- 배점 전략: 10점 = Ⅰ 정의 및 등장 배경 → Ⅲ WebAuthn 등록/인증 도식 → Ⅴ 패스워드 대비 보안성 비교 / 25점 = Ⅰ~Ⅶ 전개, 피싱 저항성 메커니즘과 Ⅵ 단말 분실 복구 및 엔터프라이즈 도입 고려사항 집중
- 기출: 미출제. 예상: "패스워드의 보안 한계를 극복하기 위해 글로벌 빅테크가 주도하는 패스키(Passkey)의 기술적 원리, 핵심 특징 및 전통적 인증 체계 대비 장단점을 설명하시오."

## 한 줄 본질
- 서버 DB 유출과 피싱 사이트에 속수무책인 문자열 비밀번호의 구조적 병목 → 공개키 암호학(WebAuthn)을 웹 표준으로 구현하고 단말기 간 안전한 클라우드 동기화를 결합 → 피싱 불가능한 초간편 패스워드리스 인증 / 단말 분실 시 복구 복잡도 및 플랫폼 종속성 발생

## 핵심 그림
```text
[패스키(Passkey) WebAuthn 인증 흐름 및 피싱 차단 원리]

 [사용자 단말 (스마트폰/PC)]                    [서비스 제공자 서버]
  ┌────────────────────────┐                   ┌────────────────────────┐
  │ 1. 생체인증 (FaceID 등) │                   │                        │
  │    - 단말 개인키 잠금해제│                   │                        │
  │ 2. 도메인 바인딩 검증: │ <──(Challenge)─── │ 로그인 요청 난수 발급  │
  │    - 현재 URL 자동 확인│                   │                        │
  │ 3. 챌린지 서명 생성   │ ──(Signed Data)─> │ 공개키로 전자서명 검증 │
  └────────────────────────┘                   └───────────┬────────────┘
                                                           │ (인증 성공)
 * 피싱 사이트 차단 원리:                                   ▼
   공격자가 만든 가짜 도메인(phishing-bank.com)에서는        [ 세션 생성 ]
   단말기가 저장된 정식 도메인(bank.com)의 키를 절대
   내주지 않으므로 피싱이 원천 불가능함!
```

## 핵심 용어
- WebAuthn(Web Authentication): W3C와 FIDO 얼라이언스가 제정한 표준 웹 API로 브라우저가 사용자 단말의 하드웨어 보안 키(생체인증기)와 직접 통신할 수 있게 지원
- 도메인 바인딩(Domain Binding): 패스키 개인키가 특정 정규 도메인(RP ID)에 암호학적으로 귀속되어 주소창의 도메인이 1글자라도 다르면 브라우저가 서명을 거부하는 성질

## 핵심 통찰
- 패스키는 "비밀번호를 입력하는 새로운 방법"이 아니라, 서버에서 비밀번호라는 개념 자체를 삭제하는 암호학적 혁신임 → 서버가 털려도 공격자가 얻는 것은 암호학적 공개키뿐이므로 크리덴셜 스터핑이 불가능함
- 사용자가 가짜 피싱 웹사이트에 속아 아이디와 비번을 직접 타이핑할 위험을 브라우저가 하드웨어 레벨에서 차단(피싱 저항성, Phishing-resistant)함
- 초기 FIDO의 실패 원인은 '스마트폰을 바꾸면 로그인을 못 한다'는 점이었으나, 패스키는 애플 키체인, 구글 비밀번호 관리자 등 E2EE(종단간 암호화) 클라우드 동기화를 지원해 실용성을 확보함

## 이웃 토픽과 구분
- SMS/OTP MFA vs 패스키: SMS/OTP = 여전히 피싱 프록시(Evilginx)로 가로채기 가능 / 패스키 = 도메인 바인딩으로 어떠한 피싱 프록시도 우회 불가

## 문제·원인·대책
- 사례: 피싱 메일을 통해 정교하게 모방된 피싱 페이지로 유도하여 OTP 번호까지 실시간으로 탈취해 계정을 침해한 중간자(MitM) 피싱 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| OTP/SMS 2단계 인증을 가로채는 피싱 키트(Evilginx) | OTP 생성값이 특정 웹사이트 도메인에 암호학적으로 결속되지 않음 | WebAuthn 기반 패스키(Passkey) 인증 강제 | 피싱 사이트 접속 시 개인키 서명 거부로 침해 원천 방지 |
| 사용자의 스마트폰 분실 시 계정 잠김 위험 | 로컬 하드웨어 칩셋에만 개인키가 단독 보관됨 | 클라우드 계정(iCloud, Google) 종단간 암호화(E2EE) 패스키 동기화 | 신규 기기 로그인 시 클라우드 복원 지원 |

## 이렇게 출제된다
- 미출제. 예상: "패스워드의 보안 한계를 극복하기 위해 글로벌 빅테크가 주도하는 패스키(Passkey)의 기술적 원리, 핵심 특징 및 전통적 인증 체계 대비 장단점을 설명하시오." → 요구 포인트: Ⅰ 패스워드 취약성 및 등장 배경 + Ⅲ WebAuthn 동작 구조 및 피싱 저항성 + Ⅵ 실무 도입 전략

## 내 의견
- [특정 빅테크 에코시스템 종속성 탈피 필요] 패스키가 애플과 구글의 OS 생태계에 갇혀 안드로이드폰에서 아이폰으로 기기 변경 시 패스키 이전이 어려운 상호운용성 한계 상존 → 나라면: FIDO 얼라이언스의 'CXP(Credential Exchange Protocol)' 표준 규격을 지원하는 독립 패스워드 관리자(1Password, Bitwarden 등)와의 연동을 권장하고, 비상 복구용 백업 이메일/FIDO 보안키 다중 등록 절차 가이드라인 수립
