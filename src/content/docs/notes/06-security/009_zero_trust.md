## 답안 골격
```text
[제로트러스트] ◀━━ 머리: Ⅶ 내 의견 (단일 솔루션 도입 지양 → 신원 중심 PDP/PEP 기반 마이크로 세그멘테이션 단계적 적용)
 ┃
 ┣━ Ⅰ 개요 ───── 경계 기반 방화벽 모델의 붕괴(내부망 침투 시 무방비) → "절대 믿지 말고, 항상 검증하라"는 패러다임 전환
 ┣━ Ⅱ 특징 ───── 최소 권한 부여 · 명시적이고 지속적인 검증 · 침해 가정(Assume Breach) · 마이크로 세그멘테이션
 ┣━ Ⅲ 구조 ───── 제어 평면(PDP: 정책 엔진 PE, 정책 관리자 PA) · 데이터 평면(PEP: 정책 시행 지점)
 ┣━ Ⅳ 흐름 ───── ① 접속 요청 → ② 신원/기기상태 신호 수집 → ③ PDP 실시간 위험 평가 → ④ PEP 동적 세션 터널 허용
 ┣━ Ⅴ 비교 ───── 경계 기반 보안(Perimeter) vs 제로트러스트 보안(Zero Trust)
 ┗━ Ⅵ 실무 ───── 레거시 인프라 연동 병목 / 단일 인증 실패 시 가용성 저하 / NIST SP 800-207 및 국내 가이드라인 2.0 적용
```
- 필수 키워드: NIST SP 800-207 · PDP(정책결정점) · PEP(정책시행점) · 마이크로 세그멘테이션 · 명시적 검증 · SDP
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ PDP/PEP 논리 구조도 → Ⅴ 경계 기반 vs 제로트러스트 / 25점 = Ⅰ~Ⅶ 전개, Ⅳ 세션 인가 절차와 Ⅵ 제로트러스트 성숙도 모델(CISA) 적용 방안 집중
- 기출: 135회 4교시 6번 `경계 기반 보안 vs 제로트러스트 성숙도 2.0` → Ⅰ·Ⅴ·Ⅵ / 136회 4교시 4번 `제로트러스트 기반 공급망 보안` → Ⅲ·Ⅳ

## 한 줄 본질
- 내부망에 접속한 사용자와 단말을 무조건 신뢰하는 경계 보안의 한계 → 모든 접근 요청을 의심하고 신원·단말·위치 정보를 바탕으로 세션별 최소 권한만 동적 부여 → 측면 이동 피해 최소화 / 정책 복잡도 및 인증 지연 증가

## 핵심 그림
```text
[NIST SP 800-207 제로트러스트 논리 아키텍처 (PDP / PEP)]

                    [ 제어 평면 (Control Plane) ]
                   ┌───────────────────────────────┐
                   │    정책 결정 지점 (PDP)       │
                   │  ┌──────────┐   ┌──────────┐  │
                   │  │ 정책 엔진│   │정책 관리자│  │
                   │  │   (PE)   │<─>│   (PA)   │  │
                   │  └──────────┘   └──────────┘  │
                   └───────▲───────────────┬───────┘
  위협 인텔리전스,        │               │ 제어 신호
  PKI, 신원 관리          │ 동적 평가     ▼
                   ┌───────┴───────────────┴───────┐
 [ 주체 (Subject) ]│ ───> [ 정책 시행 지점 (PEP) ] │ ───> [ 엔터프라이즈 리소스 ]
 (사용자/단말)     │          (동적 암호화 터널)   │      (데이터/애플리케이션)
                   └───────────────────────────────┘
                    [ 데이터 평면 (Data Plane) ]
```

## 핵심 용어
- PDP(Policy Decision Point): 주체의 신원, 단말 상태, 위험 인텔리전스를 종합하여 리소스 접근 허용 여부를 최종 결정하는 논리적 주체
- PEP(Policy Enforcement Point): PDP의 결정에 따라 주체와 리소스 간의 통신 세션을 실제로 활성화, 차단 또는 종료시키는 게이트웨이

## 핵심 통찰
- 제로트러스트는 특정 소프트웨어나 방화벽 제품이 아니라 전사 자산에 적용되는 보안 아키텍처 철학임
- 최초 로그인 시 한 번 인증하고 세션을 유지하는 것은 제로트러스트가 아님 → 이상 행위나 단말 위험 점수 변경 시 실시간으로 세션을 차단하는 지속적 검증(Continuous Adaptive Risk and Trust Assessment)이 핵심
- 네트워크 전체를 한 번에 전환할 수 없으므로 중요 데이터 자산 주변부터 마이크로 세그멘테이션으로 격리하는 점진적 성숙도 접근이 필수적임

## 이웃 토픽과 구분
- 제로트러스트 vs VPN: VPN = 외부에서 내부망으로 들어오는 관문을 통과하면 내부망 전체에 접근 허용 / 제로트러스트 = 내부망에 들어와 있어도 인가된 개별 애플리케이션 단 하나만 연결

## 문제·원인·대책
- 사례: 135회 기출 VPN 계정 탈취 후 사내 전산망 전체로 랜섬웨어가 측면 이동(Lateral Movement)한 금융사 침해 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 단일 VPN 계정으로 전사 내부 서버 무제한 접근 | 경계 통과 후 내부망 무검증 신뢰 모델 운영 | SDP(Software Defined Perimeter) 도입해 앱 단위 1:1 세션만 노출 | 공격자의 내부 네트워크 스캐닝 및 측면 이동 차단 |
| 단말이 악성코드에 감염된 상태로 사내 접속 | 계정 ID/PW 인증만 확인하고 기기 무결성 검증 생략 | mTLS 및 단말 상태 점검(EDR 위생 상태 확인) 결합 조건부 접근 강제 | 감염된 단말의 사내 시스템 접근 원천 배제 |

## 이렇게 출제된다
- 제135회 4교시 6번: "경계 기반 보안(Perimeter Security)과 제로 트러스트(Zero Trust) 성숙도모델 2.0에 대하여 비교 설명하고, 제로 트러스트 아키텍처 도입 시 고려사항을 설명하시오." → 요구 포인트: Ⅰ 패러다임 전환 + Ⅴ 비교 + Ⅵ CISA 5대 기둥별 도입 전략
- 제131회 2교시 4번: "제로 트러스트 보안(Zero Trust Security)모델의 보안원리, 핵심원칙, 적용분야를 트러스트 보안(Trust Security)모델과 비교하여 설명하시오." → 요구 포인트: Ⅱ 핵심원칙 + Ⅲ 아키텍처

## 내 의견
- [빅뱅 방식 전면 교체로 인한 비즈니스 중단 사고] 기존 방화벽과 VPN을 일시에 걷어내고 제로트러스트 게이트웨이를 강제 적용했다가 레거시 ERP 및 생산 설비 통신이 마비되는 혼란 발생 → 나라면: CISA 제로트러스트 성숙도 모델에 따라 1단계 클라우드 SaaS 및 원격근무자 IAM/MFA 강화부터 시작해, 2단계 중요 DB 세그멘테이션, 3단계 레거시 망으로 확산하는 3개년 로드맵을 수립
