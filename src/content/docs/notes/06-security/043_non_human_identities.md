## 한 줄 본질
- 마이크로서비스·CI/CD 자동화로 인해 시스템 간 통신용 자격증명(NHI)이 폭증했으나 사람과 달리 MFA를 걸 수 없음 → 하드코딩·과도한 권한의 방치로 공격자의 은밀한 측면 이동 통로로 악용 → 자동화된 비밀 회전 및 수명주기 통제 필수 / 시크릿 갱신 시 서비스 중단 위험 관리 비용 발생

## 핵심 용어
- 비인간 신원(NHI, Non-Human Identities): 사람이 아닌 애플리케이션, 서비스 계정, 컨테이너, 워크로드, 스크립트 등에 부여되어 시스템 자원에 접근하는 디지털 신원
- 고스트 시크릿(Ghost Secret): 생성 후 서비스가 종료되었거나 담당자가 퇴사했음에도 폐기되지 않고 영구 유효한 상태로 방치된 API 키나 토큰

## 핵심 통찰
- 기업 내 NHI 수는 인간 직원 수보다 20~40배 이상 많으나, 90% 이상의 조직이 NHI 목록(인벤토리)조차 파악하지 못하고 있음
- 인간 신원은 퇴사 시 SSO 계정을 잠그면 차단되지만, NHI는 소스코드나 환경변수에 박혀 수년 동안 권한을 유지하며 침투된 인프라의 영구 백도어로 악용됨
- NHI 보안의 열쇠는 '영구 비밀(Long-lived secret)의 박멸'임 → Vault 등을 이용해 1회성 또는 단기 임시 토큰(Just-In-Time)을 발행하고 수명 만료 시 자동 소멸시켜야 함

## 이웃 토픽과 구분
- IAM vs NHI PAM: 기존 IAM = 사람 중심의 직원 계정 인증 및 접근 통제 / NHI PAM = 워크로드, 파이프라인, 서비스 계정의 시크릿 수명주기 관리

## 문제·원인·대책
- 사례: 공개 GitHub 리포지토리에 AWS IAM 액세스 키가 커밋되어 수 시간 만에 대규모 암호화폐 채굴 인스턴스가 생성된 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 소스코드 및 CI/CD 스크립트 내 API 키 하드코딩 | 개발 편의성 우선 및 시크릿 관리 인프라 부재 | Git 사전 커밋(Pre-commit) 훅 기반 비밀 검사기(TruffleHog 등) 강제 | 외부 저장소로의 시크릿 커밋 원천 차단 |
| 수년째 갱신되지 않는 만료 기한 없는 서비스 토큰 | 자격증명 갱신 시 운영 중단(Downtime) 우려로 수동 갱신 기피 | 시크릿 매니저 기반 자동 회전(Automated Secret Rotation) 파이프라인 구축 | 토큰 유출 시 유효 시간 최소화로 피해 차단 |
