## 한 줄 본질
- 여러 사이트에 동일한 ID/비밀번호를 재사용하는 이용자 습관 병목 → 다크웹 유출 자격증명을 대량 자동화 봇넷으로 무차별 대입하여 정상 로그인으로 위장 침투 → 계정 소유권 탈취 / 봇 차단 인프라 및 정상 고객 불편 완화 비용 발생

## 핵심 용어
- 크리덴셜 스터핑(Credential Stuffing): 타 사이트 침해사고로 유출된 대량의 사용자 계정 자격증명(ID/PW) 목록을 특정 웹사이트에 자동화 도구로 무차별 대입하는 공격
- 브라우저 핑거프린팅(Browser Fingerprinting): IP 주소 변경에 대응하여 Canvas, WebGL, 폰트, 오디오 컨텍스트 등 단말 환경의 고유 특성값을 조합해 공격 봇 단말을 추적하는 기법

## 핵심 통찰
- 이 사고는 쿠팡 내부 데이터베이스가 해킹된 것이 아니라, '정상적인 로그인 창구'가 자동화 공격 도구에 뚫린 것임 → 방화벽만으로는 정상 HTTP 트래픽으로 위장한 로그인을 막을 수 없음
- 정적인 IP 기반 차단(Rate Limiting)은 수천 개의 분산 프록시와 주거용 IP(Residential Proxy)를 동원하는 현대 봇넷 앞에서 무력화됨
- 근본적인 해법은 패스워드 체계 자체를 없애는 것임 → FIDO2 기반 패스키(Passkey)를 도입하면 서버에 비밀번호가 없으므로 크리덴셜 스터핑 공격이 성립하지 않음

## 이웃 토픽과 구분
- 무차별 대입(Brute Force) vs 크리덴셜 스터핑: 무차별 대입 = 무작위 문자열 대입 / 크리덴셜 스터핑 = 이미 유출된 실제 계정 쌍(ID/PW)을 대입하여 성공률 극대화

## 문제·원인·대책
- 사례: 대형 e-커머스 플랫폼에서 수천만 건의 계정 탈취 및 등록 카드/포인트 무단 결제 시도 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 분산 주거용 IP를 경유한 대규모 자동 로그인 시도 | 단순 IP 기반 요청 횟수 제한(Rate Limit) 우회 | JA3 TLS 지문 및 클라이언트 마우스/키보드 행위 기반 봇 감지 솔루션 적용 | 자동화 공격 트래픽 99% 이상 인라인 차단 |
| 로그인 성공 후 개인정보 대량 스크래핑 | 인증 후 API 호출 권한에 대한 세부 모니터링 부재 | 평소 행동 패턴과 다른 비정상 조회 탐지 시 MFA 재인증 요구 | 계정 탈취 성공 시에도 대량 정보 반출 방지 |

## 내 의견
- [사후 공지만 반복하는 수동적 컴플라이언스 한계] 법적 처벌을 피하기 위해 사고 후 '비밀번호 변경 권고' 공지만 띄우고 본질적인 인증 체계 개편을 미루는 관행 지적 → 나라면: 알려진 유출 비밀번호(Have I Been Pwned DB 등)와의 대조 API를 회원가입 및 비밀번호 변경 시 의무화하고, 장기적으로 SMS 인증을 폐지하고 WebAuthn 패스키 인증을 기본값으로 전환
