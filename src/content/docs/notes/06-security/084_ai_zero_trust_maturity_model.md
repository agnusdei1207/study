## 답안 골격
```text
[AI 제로트러스트 성숙도 모델] ◀━━ 머리: Ⅶ 내 의견 (AI 보안의 단계적 진화 완성 → CISA 제로트러스트 모델 기반 AI 수명주기 5대 영역 성숙도 로드맵 수립)
 ┃
 ┣━ Ⅰ 개요 ───── AI 파이프라인(데이터-모델-인프라-사용자)의 모든 구성요소를 잠재적 침해 상태로 간주하고 지속적으로 검증하는 단계별 보안 성숙도 평가 모델
 ┣━ Ⅱ 특징 ───── 절대 신뢰 배제(Never Trust, Always Verify) · AI 수명주기 전반 통제 · 정량적 성숙도 평가(전통적-초기-고급-최적화) · 위협 노출의 동적 억제
 ┣━ Ⅲ 구조 ───── 5대 핵심 기둥(신원, 디바이스/인프라, AI 데이터, AI 모델/알고리즘, 애플리케이션) + 3대 공통 기능(가시성/분석, 자동화/오케스트레이션, 거버넌스)
 ┣━ Ⅳ 흐름 ───── 1단계(전통적: 정적 키, 사후 점검) → 2단계(초기: RBAC, 데이터 암호화) → 3단계(고급: 컨텍스트 인가, 실시간 가드레일) → 4단계(최적화: 자율 격리, 동적 위험 평가)
 ┣━ Ⅴ 비교 ───── AI 제로트러스트 성숙도(AI 모델 변조·데이터 중독·프롬프트 인젝션 통제) vs 전통 CISA ZTMM(네트워크 패킷, 사용자 단말, 서버 계정 중심 통제)
 ┗━ Ⅵ 실무 ───── 한 번에 최적화 단계 도입 시 업무 마비 초래 / 단계적 로드맵 수립을 통한 데이터 무결성 검증부터 모델 거버넌스로의 점진적 확장
```
- 필수 키워드: AI 제로트러스트 · 성숙도 모델(Maturity Model) · Never Trust, Always Verify · 5대 기둥 · 지속적 검증 · CISA ZTMM
- 배점 전략: 10점 = Ⅰ AI 제로트러스트 필요성 → Ⅲ 5대 기둥 및 4단계 성숙도 매트릭스 도식 → Ⅵ 단계적 전환 로드맵 / 25점 = Ⅰ~Ⅶ 전개, AI 데이터 중독(Poisoning) 및 공급망 변조 방어를 위한 기둥별 상세 기술 요건과 CISA 가이드라인 연계
- 기출: 미출제. 제로트러스트 가이드라인 2.0과 AI 보안 결합 문제로 출제 유력 예상

## 한 줄 본질
- AI 모델 내부와 학습 데이터 파이프라인을 맹목적으로 신뢰하여 데이터 중독 및 모델 백도어에 무방비로 노출되는 병목 → AI 전 생애주기에 걸쳐 신원, 데이터, 모델, 인프라의 신뢰를 지속 검증하는 4단계 성숙도 체계 적용 → 체계적 AI 보안 로드맵 확보 / 단계별 도입 비용 및 운영 복잡성 관리 필요

## 핵심 그림
```text
[AI 제로트러스트 성숙도 모델(ZTMM) 4단계 발전 로드맵]

  [성숙도 단계]     전통적(Traditional) ──> 초기(Initial) ──> 고급(Advanced) ──> 최적화(Optimal)
  ─────────────────────────────────────────────────────────────────────────────
  1. AI 신원      │ 정적 API Key        │ 역할 기반 RBAC   │ 에이전트 전용 IAM │ 동적 컨텍스트 인가
  (Identity)     │ (공유 계정 사용)    │ (사용자별 분리)  │ (단기 토큰 위임)  │ (비정상 행위 즉시 차단)
  ─────────────────────────────────────────────────────────────────────────────
  2. AI 데이터    │ 비암호화 저장       │ 전송/저장 암호화 │ 민감정보 자동 마스킹│ 합성데이터/동형암호
  (Data)         │ (출처 검증 부재)    │ (기본 해시 검증) │ (차분 프라이버시) │ (데이터 계보 실시간 추적)
  ─────────────────────────────────────────────────────────────────────────────
  3. AI 모델      │ 미검증 모델 배포    │ 체크포인트 서명  │ 실시간 가드레일   │ AI 레드티밍 자동화
  (Model)        │ (블랙박스 운영)     │ (SBOM 목록화)    │ (탈옥/인젝션 탐지)│ (자가 치유 및 모델 격리)
  ─────────────────────────────────────────────────────────────────────────────
  4. 인프라      │ 평문 GPU 메모리     │ VPC 네트워크 격리│ 기밀 컴퓨팅(TEE)  │ 제로트러스트 마이크로
  (Infra)        │ (단일 망 구성)      │ (접근제어 적용)  │ (vGPU 메모리 암호)│ 세그멘테이션 전면화
```

## 핵심 용어
- 지속적 검증(Continuous Verification): 한 번 인증을 통과했더라도 신뢰를 영구 부여하지 않고, 데이터 조회 및 모델 추론이 일어날 때마다 실시간으로 위험 점수를 재평가하는 제로트러스트 핵심 원칙
- 기밀 컴퓨팅(Confidential Computing): 하드웨어 기반 신뢰 실행 환경(TEE)을 통해 GPU 및 메모리 내부에서 AI 모델 연산이 수행되는 동안에도 외부 OS나 클라우드 관리자가 데이터를 엿볼 수 없도록 암호화하는 기술

## 핵심 통찰
- 일반 시스템의 제로트러스트는 '네트워크'와 '단말'에 집중하지만, AI 제로트러스트는 '데이터 계보(Data Lineage)'와 '가중치 무결성(Model Integrity)'이 핵심 기둥임
- 초기 단계 기업이 처음부터 최적화(Optimal) 수준의 복잡한 기밀 컴퓨팅이나 동형암호를 도입하려 하면 개발이 중단됨 → "1단계: 데이터 암호화 및 API Key 제거"부터 시작하는 현실적 로드맵이 중요함
- 모델이 외부 웹을 검색하거나 플러그인을 호출하는 모든 아웃바운드 트래픽 역시 잠재적 공격 통로로 보고 검증해야 완결된 AI 제로트러스트가 됨

## 이웃 토픽과 구분
- AI 제로트러스트 vs 전통 제로트러스트: AI 제로트러스트 = 비결정론적 모델 추론 및 학습 데이터 변조 방어에 특화 / 전통 제로트러스트 = 사용자 단말, 네트워크 패킷, 정적 서버 인가에 집중

## 문제·원인·대책
- 사례: 사내 프라이빗 AI 모델에 연구원 계정으로 악의적인 오염 데이터가 업로드되어 모델의 보안 필터가 영구 무력화된 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 미검증 학습 데이터 유입을 통한 AI 모델 중독(Poisoning) | 내부 연구원 계정의 데이터를 무조건 신뢰하는 경계형 신뢰 관행 | AI ZTMM 3단계(데이터 계보 추적 및 전자서명 검증) 적용 | 데이터 공급망 투명성 확보 및 무인가 변조 차단 |
| GPU 서버 메모리에 남아있는 파인튜닝 가중치 및 프롬프트 탈취 | 다중 테넌트 클라우드 환경에서 vGPU 메모리 보호 기제 부재 | TEE 기반 GPU 기밀 컴퓨팅(Confidential Computing) 도입 | 메모리 덤프를 통한 AI 가중치 및 기밀 유출 원천 차단 |
