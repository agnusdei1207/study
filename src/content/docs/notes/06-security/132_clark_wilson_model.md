## 답안 골격
```text
[클라크-윌슨(Clark-Wilson) 무결성 모델] ◀━━ 머리: Ⅶ 내 의견 (직접 데이터 조작 금지 → 주체-TP-CDI 3원소 통제와 직무 분리 기반의 상업용 무결성 아키텍처 강제)
 ┃
 ┣━ Ⅰ 개요 ───── 군사용 기밀성 모델(BLP)의 한계를 극복하고, 금융·상거래 등 상업적 환경에서 데이터의 부정 변조 방지와 무결성(Integrity) 유지를 위해 고안된 정형화된 트랜잭션 및 직무 분리 중심의 보안 모델
 ┣━ Ⅱ 특징 ───── 데이터에 대한 직접 접근 금지(프로시저 경유 강제) · 정형화된 트랜잭션(Well-Formed Transaction) · 직무 분리(Separation of Duties) · 무결성 검증 프로시저(IVP) 내장
 ┣━ Ⅲ 구조 ───── 4대 핵심 구성요소: CDI(통제 데이터) + UDI(비통제 데이터) + TP(변환 절차) + IVP(무결성 검증 절차) + 접근 3원소(주체, 프로그램, 객체)
 ┣━ Ⅳ 흐름 ───── 시스템 기동 시 IVP 무결성 검증 → 사용자(주체)가 TP 실행 요청 → 접근 통제 목록 검증 → TP를 경유하여 CDI 안전한 갱신 → 변경 이력 감사로그 기록
 ┣━ Ⅴ 비교 ───── BLP(군사용, 기밀성 최우선, No Read Up/No Write Down) vs Biba(무결성 계층화, No Read Down/No Write Up) vs Clark-Wilson(상업용 무결성, 직무 분리, TP 경유)
 ┗━ Ⅵ 실무 ───── 트랜잭션 절차화에 따른 시스템 유연성 저하 / 직무 분리를 위한 최소 인력 확보 부담 / UDI에서 CDI로의 데이터 변환(입력값 검증) 누락
```
- 필수 키워드: Clark-Wilson · CDI(Constrained Data Item) · UDI · TP(Transformation Procedure) · IVP · 정형화된 트랜잭션 · 직무 분리(Separation of Duties) · 접근 3원소
- 배점 전략: 10점 = Ⅰ 클라크-윌슨 모델 정의 및 목적 → Ⅲ 4대 구성요소 및 접근 3원소 도식 → Ⅴ BLP/Biba 비교표 / 25점 = Ⅰ~Ⅶ 전개, 제127회 기출(접근 통제 보안 모델) 완벽 대응, 5대 인증 규칙(Certification)과 4대 강제 규칙(Enforcement), 현대 ERP/금융 시스템과의 1:1 매핑 사례 심층 상술

## 한 줄 본질
- 내부 직원이 데이터베이스에 직접 접속해 숫자를 마음대로 뜯어고치는 횡령 및 부정 변조 병목 → 주체가 데이터에 직접 접근하지 못하게 차단하고 오직 검증된 프로그램(TP)과 승인된 2인 분리 결재(직무 분리)로만 갱신을 허용 → 완벽한 상업적 데이터 무결성 보장 / 결재선 증가 및 업무 절차 경직

## 핵심 그림
```text
[클라크-윌슨(Clark-Wilson) 모델의 접근 3원소 및 데이터 무결성 변환 구조]

┌───────────────────┐
│ 사용자 (주체)     │
└─────────┬─────────┘
          │ (1. 사용자는 데이터에 '직접 접근' 불가!)
          ▼
┌───────────────────┐
│ 변환 절차 (TP)    │ <─── [직무 분리 규칙 적용] (발주 담당자와 결제 승인자 분리)
│ (정형화 트랜잭션) │
└─────────┬─────────┘
          │ (2. 승인된 프로시저를 통해서만 데이터 수정 가능)
          ▼
┌───────────────────┐               ┌───────────────────┐
│ 통제 데이터 (CDI) │ <───(검증)─── │ 검증 절차 (IVP)   │
│ (은행 잔고, 원장) │               │ (장부 총계 대조)  │
└───────────────────┘               └───────────────────┘
          ▲
          │ (3. UDI 유효성 검사 통과 시 변환)
┌───────────────────┐
│ 비통제 데이터(UDI)│ (사용자의 키보드 입력 등 외부 미검증 데이터)
└───────────────────┘
```

## 핵심 용어
- CDI (Constrained Data Item): 시스템 내에서 무결성이 엄격하게 보존되어야 하는 핵심 데이터 자산(예: 은행 계좌 잔고, 증권 보유 수량)으로 오직 TP를 통해서만 수정될 수 있음
- TP (Transformation Procedure): CDI의 무결성을 깨뜨리지 않고 오직 유효한 상태에서 다른 유효한 상태로만 데이터를 변경하는 검증된 정형 트랜잭션 함수(예: 출금 프로시저)
- 직무 분리 (Separation of Duties): 사기 및 횡령을 방지하기 위해 핵심 비즈니스 프로세스(예: 구매 요청과 대금 지급)를 단일 인물이 완결하지 못하도록 다수의 주체에게 권한을 쪼개어 분산하는 원칙

## 핵심 통찰
- 군대에서는 "비밀이 적에게 새어나가는 것(기밀성, BLP)"이 가장 무섭지만, 은행과 기업에서는 "직원이 장부 숫자를 몰래 고치는 것(무결성, Clark-Wilson)"이 가장 무서움
- Biba 모델은 단순히 "낮은 등급의 사람은 높은 등급 문서를 못 고친다"는 수학적 계층화에 머물렀지만, 현실의 기업은 사장이라고 해서 회계 DB를 직접 쿼리로 고치지 않음
- 클라크-윌슨은 '주체(User) - 프로그램(TP) - 객체(CDI)'라는 '접근 3원소(Access Triple)' 개념을 최초로 도입하여 현대 소프트웨어 공학의 3-Tier 아키텍처(사용자-애플리케이션-DB)의 사상적 기초를 놓음

## 이웃 토픽과 구분
- Clark-Wilson vs Biba 모델: Biba = 정보의 무결성 등급(상/하)에 기반한 상태 머신 모델(NRD/NWU) / Clark-Wilson = 직무 분리, 감사 추적, 정형화된 트랜잭션 절차를 정의한 실무 상업용 규칙 모델

## 문제·원인·대책
- 사례: 금융사 내부 직원이 관리자 DB 계정으로 직접 콘솔에 접속하여 본인의 계좌 잔액 컬럼 값을 수동 조작해 횡령한 사건
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 직원이 데이터베이스에 직접 접속해 계좌 잔액 무단 수정 | 주체에게 DB 직접 쓰기(Direct Update) 권한 부여 | Clark-Wilson 접근 3원소 강제(DB 직접 접근 차단, 오직 결재된 TP만 허용) | 사용자 단독의 임의 데이터 조작 원천 차단 |
| 단일 관리자가 허위 발주서를 작성하고 본인이 스스로 대금 지급 승인 | 업무 프로세스 내 직무 분리(Separation of Duties) 결여 | 역할 기반 상호 견제 결재선 강제(발주자 $\neq$ 승인자) | 1인 독단에 의한 기업 횡령 및 부정 승인 사전 예방 |
