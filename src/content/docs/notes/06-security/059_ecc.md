## 한 줄 본질
- 소인수분해 기반 RSA의 3072비트 이상 거대 키 길이로 인한 모바일·임베디드 장치 연산 지연 병목 → 유한체 타원곡선 점들의 스칼라 배연산 역산 불가능성(ECDLP)을 활용해 256비트의 짧은 키로 동등한 보안성 제공 → 초경량·고속 암호 연산 / 양자컴퓨터 쇼어 알고리즘에 의해 RSA와 동일하게 해독될 위험 상존

## 핵심 그림
```text
[타원곡선 상의 점 덧셈(Point Addition) 및 스칼라 배연산 원리]

      y ^                y^2 = x^3 + ax + b
        │         . : * : .
        │       :           :
        │     .               .
        │    :        P        :
        │───:─────────*─────────:───>
        │   .        /          .    x
        │    :      /  Q       :
        │     .    /───*──────.
        │       : /         :
        │         * : . : .
        │        / R'
        │       /
        │      *  R = P + Q  (R'를 x축에 대칭시킨 점)

 * 스칼라 곱연산: Q = k * G (G를 k번 더함)
   - k와 G를 알면 Q를 구하기 쉬움 (공개키 생성)
   - Q와 G를 알아도 스칼라 k를 역산하는 것은 불가능 (ECDLP 난제)
```

## 핵심 용어
- ECDLP(Elliptic Curve Discrete Logarithm Problem): 타원곡선 상의 기준점 $G$와 결과점 $Q = kG$가 주어졌을 때 정수 스칼라 $k$를 알아내는 것이 계산적으로 불가능하다는 수학적 난제
- ECDSA(Elliptic Curve Digital Signature Algorithm): ECC 기반의 전자서명 알고리즘으로 비트코인, 이더리움 및 TLS 인증서의 핵심 서명 표준

## 핵심 통찰
- 암호학적 보안 강도 128비트를 만족하려면 RSA는 3,072비트 키가 필요하지만, ECC는 단 256비트면 충분함 → 대역폭과 메모리가 극도로 제약된 IoT, 스마트카드, 스마트폰에서 독보적 우위
- 키 길이가 짧기 때문에 TLS 핸드셰이크 시 서버의 CPU 부하가 RSA 대비 수십 배 이상 절감되어 현대 인터넷 트래픽(TLS 1.3)의 90% 이상이 ECDHE 키 교환을 채택
- 주의할 점은 '양자컴퓨팅 앞에서는 RSA나 ECC나 똑같이 붕괴'한다는 것임 → 쇼어(Shor) 알고리즘은 소인수분해뿐만 아니라 이산대수(ECDLP)도 다항 시간 내에 풀 수 있으므로 장기적으로 PQC로 넘어가야 함

## 이웃 토픽과 구분
- RSA vs ECC: RSA = 큰 소수의 곱을 분해하기 어렵다는 난제 / ECC = 타원곡선에서 점을 수억 번 튕겨 더했을 때 몇 번 튕겼는지 맞히기 어렵다는 난제

## 문제·원인·대책
- 사례: 하드웨어 지갑에서 트랜잭션 서명 시 전력 소모량을 측정하여 타원곡선 개인키를 역산해 낸 부채널 공격(Side-Channel Attack) 사례
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 스칼라 곱셈 시 전력 소모 및 실행 시간 차이 노출 | 비밀키 $k$의 비트 값(0 또는 1)에 따라 덧셈 연산 수행 여부가 갈림 | 몽고메리 래더(Montgomery Ladder) 등 상수 시간(Constant-time) 연산 구현 | 타이밍/전력 분석 부채널 공격 차단 |
| 난수(k) 재사용으로 인한 개인키 완전 노출 | ECDSA 서명 시 동일한 난수 $k$를 두 번 이상 사용 | RFC 6979 결정론적(Deterministic) 서명 생성 방식 적용 | 난수 발생기 취약점으로 인한 서명 개인키 유출 방지 |

## 내 의견
- [NIST 곡선(P-256) 백도어 불신과 모던 곡선 전환] 미국 NSA가 표준화에 관여한 secp256r1(NIST P-256)의 매개변수 생성 근거 불투명성으로 인한 백도어 우려 지속 → 나라면: 오픈소스 진영 및 최신 TLS/SSH 표준에서 안전성이 검증된 단 바stein의 Curve25519(Ed25519, X25519)를 조직 내 기본 암호화 곡선으로 채택하여 성능과 투명성을 동시 확보
