## 답안 골격
```text
[벨라파듈라 모델(BLP)] ◀━━ 머리: Ⅶ 내 의견 (단순 기밀성 통제 한계 극복 → 비바(Biba) 무결성 모델 및 은닉 채널(Covert Channel) 방어 결합)
 ┃
 ┣━ Ⅰ 개요 ───── 군사적 보안 요구를 충족하기 위해 제안된 최초의 수학적 접근통제 모델로 기밀성(Confidentiality) 보장을 최우선으로 설계된 강제적 접근통제(MAC) 모델
 ┣━ Ⅱ 특징 ───── 기밀성 중심 · 상태 전이 모델(State Machine) · 주체와 객체의 보안 레이블 매핑 · 정보의 상향 유출 원천 차단
 ┣━ Ⅲ 구조 ───── 단순 보안 속성(No Read Up, NRU) · 스타(*) 보안 속성(No Write Down, NWD) · 자율적 보안 속성(ds-property, 접근 행렬)
 ┣━ Ⅳ 흐름 ───── ① 주체 보안 인가 등급(Clearance) 및 객체 보안 분류 등급(Classification) 정의 → ② 접근 요청 발생 → ③ NRU 및 NWD 규칙 검증 → ④ 허용 또는 차단
 ┣━ Ⅴ 비교 ───── 벨라파듈라 모델(BLP: 기밀성 보장, NRU / NWD) vs 비바 모델(Biba: 무결성 보장, NRD / NWU, 반대 규칙)
 ┗━ Ⅵ 실무 ───── 고위직 관리자의 낮은 등급 보고서 작성 불가 불편 / 무결성 훼손 방치 / 은닉 채널(Covert Channel)을 통한 정보 유출
```
- 필수 키워드: 벨라파듈라(BLP) · 기밀성(Confidentiality) · MAC(강제적 접근통제) · NRU(No Read Up) · NWD(No Write Down) · *-속성 · 은닉 채널
- 배점 전략: 10점 = Ⅰ 정의 및 설계 목적 → Ⅲ 2대 핵심 규칙(NRU, NWD) 도식 → Ⅴ Biba 모델과의 비교 / 25점 = Ⅰ~Ⅶ 전개, BLP 수학적 상태 전이 공리와 Ⅵ 은닉 채널 취약점 및 신뢰 주체(Trusted Subject) 예외 처리 집중
- 기출: KPC 127회 `보안 모델 중 벨라파듈라(Bell-LaPadula) 모델과 비바(Biba) 모델의 원리 및 규칙 비교` → Ⅰ~Ⅴ 전반

## 한 줄 본질
- 군사 기밀이 하위 등급 인가자에게 노출되거나 트로이 목마를 통해 하위 문서로 유출되는 병목 → 상위 문서 읽기 금지(NRU)와 하위 문서 쓰기 금지(NWD)라는 엄격한 2대 규칙 적용 → 완벽한 기밀성 유지 / 상위 등급자가 하위 등급으로 데이터 전송 불가 및 무결성 훼손 취약점 발생

## 핵심 그림
```text
[벨라파듈라(BLP) 모델의 기밀성 보장 2대 규칙 구조]

   [ Top Secret (극비) ]
            │
            ▼ (읽기 허용: Read Down)
    ┌───────────────┐
    │ 주체 (Subject)│ ────(읽기 금지: No Read Up, NRU)────> [ 객체: Top Secret ]
    │  (등급: Secret)│
    │               │ ────(쓰기 금지: No Write Down, NWD)──> [ 객체: Unclassified ]
    └───────────────┘
            │
            ▼ (쓰기 허용: Write Up)
   [ Top Secret (극비) ]

 * 1. 단순 보안 속성 (Simple Security Property): NRU (No Read Up)
      - 주체는 자신보다 높은 등급의 객체를 읽을 수 없음
 * 2. 스타(*) 보안 속성 (*-Property): NWD (No Write Down)
      - 주체는 자신보다 낮은 등급의 객체에 쓸 수 없음 (기밀 유출 방지)
```

## 핵심 용어
- 단순 보안 속성(Simple Security Property): 주체는 자신보다 높은 보안 등급의 객체를 읽을 수 없다(No Read Up, NRU). 즉, 읽기는 자신과 같거나 낮은 등급만 가능(Read Down)
- 스타 보안 속성(*-Property): 주체는 자신보다 낮은 보안 등급의 객체에 정보를 쓸 수 없다(No Write Down, NWD). 즉, 쓰기는 자신과 같거나 높은 등급만 가능(Write Up)

## 핵심 통찰
- BLP의 핵심 천재성은 NRU가 아니라 'NWD(No Write Down)'에 있음 → 상위 기밀을 읽은 장군이 실수로 일반 평사원 게시판에 글을 쓰거나, 장군 PC에 잠입한 악성코드가 기밀을 복사해 공개 폴더에 저장하는 유출 경로를 수학적으로 차단함
- BLP는 '기밀성'만을 위한 모델이므로 '무결성(Integrity)'은 완전히 무시됨 → 하위 등급자가 상위 등급 객체에 쓰기(Write Up)를 할 수 있으므로, 평사원이 사장님의 기밀 문서 내용을 쓰레기 데이터로 덮어써도 BLP 모델 상으로는 합법임
- NWD 규칙은 현실 업무에서 엄청난 불편을 초래함 (기밀 취급자가 하위 부서에 지시문서를 못 씀) → 현실에서는 '신뢰 주체(Trusted Subject)'라는 특수 권한자에게만 NWD 예외를 허용해 해결함

## 이웃 토픽과 구분
- BLP vs Biba: BLP = "비밀이 새어나가지 않게 하라"(기밀성 최우선, NRU/NWD) / Biba = "데이터가 더럽혀지지 않게 하라"(무결성 최우선, NRD/NWU)

## 문제·원인·대책
- 사례: 군사 기밀망에서 상위 등급 주체에 잠입한 트로이 목마가 시스템 자원 잠금(락) 시간 차이를 이용해 하위 프로세스로 정보를 빼돌린 은닉 채널(Covert Channel) 사건
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 공유 자원(CPU, 파일 잠금)을 매개로 한 은닉 타이밍 채널 유출 | BLP 모델이 직접적인 데이터 읽기/쓰기 외의 부채널 통신 미통제 | 은닉 채널 대역폭 분석 및 시스템 클록 지터(Jitter) 난수화 | 시간차 기반 정보 유출 채널 무력화 |
| 상위 인가자의 하위 부서 정상 업무 연락 차단(NWD의 경직성) | 엄격한 NWD 규칙으로 하위 객체 생성 불가 | 신뢰 주체(Trusted Subject) 정의 및 검증된 게이트웨이 경유 통제 | 보안 정책 준수 하에 합법적 업무 소통 보장 |

## 이렇게 출제된다

## 내 의견
- [상용 엔터프라이즈 환경에서의 BLP 적용 한계] BLP는 냉전 시대 군사 기밀 격리용으로 설계되어 데이터의 수정과 협업이 빈번한 현대 기업 비즈니스에는 지나치게 경직됨 → 나라면: 기밀성이 극도로 요구되는 방위산업·국방 시스템에 한해 SELinux/MLS 커널 모듈 형태로 BLP를 강제하고, 일반 엔터프라이즈는 역할과 속성을 유연하게 결합한 ABAC(속성기반접근통제) 기반으로 다계층 보안 구현

## 찾아볼 것
- BLP 모델의 특수 예외 처리: 신뢰 주체(Trusted Subject)와 탈분류(Declassification) 절차
