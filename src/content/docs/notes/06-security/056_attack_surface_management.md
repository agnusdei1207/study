## 답안 골격
```text
[공격표면관리(ASM)] ◀━━ 머리: Ⅶ 내 의견 (내부 등록 자산 관리 탈피 → 공격자 관점의 인터넷 노출 자산 전수 탐지(EASM) 및 자동 격리)
 ┃
 ┣━ Ⅰ 개요 ───── 멀티클라우드·원격근무 확산으로 조직이 인지하지 못하는 인터넷 노출 자산(섀도우 IT) 급증 → 외부 공격표면의 지속적 발견·위험 평가·축소 체계
 ┣━ Ⅱ 특징 ───── 에이전트리스(Agentless) 외부 스캔 · 공격자 시선 자산 정찰 · 미관리 자산 자동 발견 · 지속적 노출점 모니터링
 ┣━ Ⅲ 구조 ───── 외부 공격표면관리(EASM) · 사이버 자산 공격표면관리(CAASM) · 디지털 리스크 보호(DRPS)
 ┣━ Ⅳ 흐름 ───── ① 조직 도메인/IP 범위 기반 자산 자율 정찰 → ② 서브도메인·개방포트·클라우드 스토리지 자산 인벤토리화 → ③ 취약 노출점 위험 평가 → ④ 취약 자산 격리 및 패치
 ┣━ Ⅴ 비교 ───── 내부 취약점 스캐너(에이전트/내부 IP 기반, 알려진 자산 대상) vs ASM(공격자 관점, 등록되지 않은 미관리 자산까지 인터넷 전수 탐색)
 ┗━ Ⅵ 실무 ───── 서브도메인 테이크오버(Subdomain Takeover) / 방치된 개발 서버 포트 개방 / 잘못 설정된 S3 버킷 공개 / 공급망 자산 모니터링
```
- 필수 키워드: 공격표면관리(ASM) · EASM · CAASM · 섀도우 IT · 미관리 자산 · 자산 인벤토리 · 위험 우선순위화
- 배점 전략: 10점 = Ⅰ 정의 및 배경 → Ⅲ EASM/CAASM 구조도 → Ⅴ 전통 자산관리 대비 차이점 / 25점 = Ⅰ~Ⅶ 전개, 외부 공격표면 탐색 4단계 흐름과 Ⅵ 섀도우 IT 및 서브도메인 테이크오버 실무 대응 집중
- 기출: 미출제. 예상: "클라우드 및 재택근무 환경에서 사이버 침해 경로를 선제적으로 차단하기 위한 공격표면관리(Attack Surface Management, ASM)의 개념, 핵심 기술 요소 및 운영 절차를 설명하시오."

## 한 줄 본질
- 수동 등록된 자산 목록(CMDB)과 실제 인터넷에 노출된 자산 사이의 괴리(섀도우 IT) 병목 → 에이전트 없이 공격자의 외부 시선에서 인터넷 전체를 스캔하여 미관리 자산과 설정 오류를 상시 발견·조치 → 공격 침투 거점 선제 제거 / 외부 스캔 비용 및 동적 IP 추적 관리 복잡도 발생

## 핵심 용어
- EASM(External Attack Surface Management): 조직 외부(인터넷)에서 공격자가 볼 수 있는 모든 디지털 자산(서버, 인증서, 클라우드 자원)을 에이전트 없이 스캔해 취약점을 식별하는 솔루션
- CAASM(Cyber Asset Attack Surface Management): 사내 여러 보안 도구(EDR, IAM, 클라우드 콘솔)의 API를 연동하여 내부 자산의 가시성 공백을 통합 해결하는 솔루션

## 핵심 통찰
- 방어자는 모든 문을 지켜야 하지만 공격자는 방치된 뒷문 하나만 찾으면 됨 → 실제 침해사고의 70% 이상은 보안팀이 "그런 서버가 있는지도 몰랐던" 섀도우 IT에서 발생
- 아무리 강력한 EDR을 사내에 깔아도, 3년 전 마케팅 부서가 이벤트용으로 AWS에 임시 개설했다가 방치한 웹서버에는 에이전트가 설치되어 있지 않음
- ASM의 가치는 '스캔'이 아니라 '맥락(Context)'임 → 단순히 열린 포트 1,000개를 뱉어내는 도구는 쓰레기통으로 가며, "이 IP가 우리 회사 결제망과 연결되어 있는가?"를 판별해 주어야 함

## 이웃 토픽과 구분
- 취약점 스캐너 vs ASM: 취약점 스캐너 = 사전에 IP 목록을 넣어주어야 스캔 / ASM = 회사 이름만 넣으면 인터넷 전체를 뒤져 숨겨진 자산 자체를 스스로 찾아냄

## 문제·원인·대책
- 사례: 클라우드 마이그레이션 후 DNS 레코드가 남아있던 과거 서브도메인을 공격자가 가로채 피싱 사이트로 악용한 서브도메인 테이크오버 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 미관리 서브도메인을 탈취당하는 서브도메인 테이크오버 | 사용 종료된 CNAME 레코드 삭제 누락(Dangling DNS) | ASM 기반 상시 DNS 불일치 스캔 및 미사용 레코드 자동 정리 | 도메인 탈취 및 브랜드 신뢰도 훼손 방지 |
| 개발용 인스턴스의 원격 데스크톱(RDP) 포트 외부 노출 | 인프라 방화벽 인바운드 규칙 관리 미흡 | EASM 자동 감시를 통한 3389/22 포트 노출 감지 시 보안그룹 즉시 차단 | 랜섬웨어 침투 주요 경로(RDP 브루트포스) 사전 제거 |

## 내 의견
- [도구 도입 후 사후 조치 실패로 인한 자원 낭비] EASM 솔루션을 도입해 수백 개의 취약 노출점을 발견하고도 인프라 담당 부서의 협조 부재로 조치율이 20%에 그치는 관행 만연 → 나라면: 클라우드 CSP 인프라의 보안그룹(Security Group) 변경 API와 ASM 엔진을 SOAR로 연동하여, 비인가 외부 개방 포트 발견 시 알림 후 1시간 내 응답이 없으면 방화벽 규칙을 자동 격리하는 '폐쇄 루프 자동화' 구축
