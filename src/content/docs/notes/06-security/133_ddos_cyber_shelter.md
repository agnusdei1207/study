## 답안 골격
```text
[DDoS 사이버대피소] ◀━━ 머리: Ⅶ 내 의견 (중소기업 자력 디도스 방어 한계 극복 → Anycast 스크러빙 센터 기반 트래픽 우회 및 평시 모니터링 연계 지원)
 ┃
 ┣━ Ⅰ 개요 ───── 자체적인 고가의 디도스 방어 장비 구축이 어려운 중소·영세기업 및 비영리단체를 대상으로, 대규모 디도스(DDoS) 공격 발생 시 웹 트래픽을 정부(KISA) 스크러빙 센터로 우회시켜 유해 트래픽을 정제한 후 정상 트래픽만 전달하는 무료 보안 방어 서비스
 ┣━ Ⅱ 특징 ───── 중소기업 무료 지원(KISA 운영) · DNS CNAME 기반 긴급 우회 라우팅 · 테라급 대용량 공격 트래픽 흡수 · L4(볼류메트릭) 및 L7(웹 자원고갈) 다층 정제
 ┣━ Ⅲ 구조 ───── 고객사 원본 웹서버 + DNS 관리 체계 + KISA 사이버대피소(대용량 스크러빙 센터, Anti-DDoS 필터, 웹 프록시) + 공격자 및 정상 사용자
 ┣━ Ⅳ 흐름 ───── 디도스 공격 발생 → 대피소 긴급 입소 신청 → DNS CNAME 레코드를 대피소 IP로 변경 → 유해 패킷 필터링(스크러빙) → 정상 트래픽만 원본 서버 전달
 ┣━ Ⅴ 비교 ───── 자체 구축형 안티디도스 장비(수억 원 비용, 회선 대역폭 초과 시 무력화) vs 상용 CDN/스크러빙(고비용) vs 정부 사이버대피소(무료 공공 지원, 신속 우회)
 ┗━ Ⅵ 실무 ───── DNS 캐시 전파 지연(TTL)으로 인한 우회 지연 / 웹 트래픽(HTTP/HTTPS) 중심 지원 한계 / 원본 서버 IP 노출 시 직접 타격 위험
```
- 필수 키워드: DDoS 사이버대피소 · 한국인터넷진흥원(KISA) · 스크러빙 센터(Scrubbing Center) · DNS CNAME 우회 · L4/L7 디도스 방어 · 트래픽 세척 · 중소기업 무료 지원
- 배점 전략: 10점 = Ⅰ 사이버대피소 개념 및 지원 대상 → Ⅲ DNS 우회 및 스크러빙 흐름도 도식 → Ⅵ 핵심 운영 절차 / 25점 = Ⅰ~Ⅶ 전개, KPC 기출 반영, L4 대역폭 고갈(SYN/UDP Flood)과 L7 애플리케이션 공격(Slowloris, HTTP Flooding)에 대한 스크러빙 필터링 기술, 원본 IP 은닉 및 BGP Anycast 연계 방안 심층 상술

## 한 줄 본질
- 영세 중소기업의 인터넷 회선 대역폭(100Mbps~1Gbps)을 가볍게 초과하는 수십 Gbps급 디도스 공격의 회선 포화 병목 → DNS를 조작해 공격 트래픽을 정부의 대용량 클라우드 세척 센터(스크러빙)로 우회시켜 찌꺼기 패킷을 걸러냄 → 서비스 연속성 무상 보장 / DNS 변경 지연 및 원본 서버 IP 노출 위험

## 핵심 그림
```text
[KISA DDoS 사이버대피소의 트래픽 우회(DNS CNAME) 및 세척(Scrubbing) 흐름]

[1. 평상시 접속 흐름]
  [사용자] ──────────────(직접 접속: www.company.com)─────────────> [중소기업 웹서버]

[2. 디도스 공격 및 대피소 적용 후]
  [공격자 봇넷] ──(수십 Gbps 디도스 폭격)──┐
                                          ├─> [DNS CNAME 우회: 대피소로 집중!]
  [정상 사용자] ──────────────────────────┘           │
                                                      ▼
                           ┌──────────────────────────────────────────────┐
                           │          KISA DDoS 사이버대피소               │
                           │  - 대용량 백본 회선으로 패킷 흡수           │
                           │  - L4 방어: SYN Cookie, 비정상 UDP/ICMP 차단│
                           │  - L7 방어: HTTP GET/POST, Slowloris 필터링  │
                           └──────────────────────┬───────────────────────┘
                                                  │ (세척된 깨끗한 패킷만 전송)
                                                  ▼
                                       [중소기업 원본 웹서버]
                                       (정상 서비스 무중단 유지!)
```

## 핵심 용어
- 스크러빙 센터 (Scrubbing Center): 수십~수백 Gbps 이상의 대규모 디도스 트래픽을 수용할 수 있는 초고속 백본 회선과 고성능 안티디도스 장비를 갖추고, 혼합된 트래픽에서 악성 패킷만 분리·폐기하는 중앙 세척 센터
- DNS CNAME 우회: 기업 웹서버의 도메인 DNS 레코드를 대피소 도메인(예: `company.kisa-shelter.or.kr`)으로 변경하여, 전 세계 인터넷 사용자의 접속 트래픽이 원본 서버 대신 대피소 프록시 IP로 향하도록 강제 라우팅하는 기술

## 핵심 통찰
- 디도스 공격 방어는 "기술의 싸움"이 아니라 "대역폭(체급)의 싸움"임 → 중소기업이 아무리 좋은 방화벽을 사두어도 회사로 들어오는 인터넷 회선이 1Gbps인데 해커가 10Gbps를 쏟아부으면 통신사 국사 레벨에서 회선이 포화되어 셧다운됨
- 따라서 공격 트래픽은 반드시 "체급이 큰 대용량 방어 거점(대피소 백본)"에서 받아내야 함
- 취약점은 '원본 서버의 실제 IP'가 드러나는 경우임 → 해커가 DNS 우회를 무시하고 과거에 알아낸 원본 웹서버의 공인 IP로 직접 패킷을 쏘면 대피소를 거치지 않아 즉시 마비되므로, 원본 서버는 오직 대피소 IP 대역의 인바운드만 허용하도록 방화벽 화이트리스트를 걸어야 함

## 이웃 토픽과 구분
- 사이버대피소 vs 상용 클라우드flare/아카마이: 사이버대피소 = 중소기업 대상 무료 공공 인프라, 국내 공격 중심 / 상용 글로벌 CDN = 전 세계 Anycast 엣지 보유, 고비용, 글로벌 지연 시간 단축 병행

## 문제·원인·대책
- 사례: 디도스 협박(랜섬 디도스)을 받은 중소 쇼핑몰이 사이버대피소에 입소했으나 여전히 다운된 상황
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 대피소 입소 후에도 공격자가 원본 IP로 직접 디도스 공격 지속 | 기존 도메인 히스토리 검색을 통한 원본 서버 공인 IP 노출 | 원본 웹서버의 공인 IP 즉각 교체 및 대피소 프록시 IP만 인바운드 허용 | 우회 경로 없는 직접 타격 원천 차단 |
| 대피소 적용 시 DNS 전파 시간 동안 접속 장애 지속 | 도메인의 DNS 캐시 유지 시간(TTL)이 길게 설정됨 | 비상 대응 매뉴얼에 따라 평시 DNS TTL을 300초(5분) 이하로 단축 | 입소 결정 즉시 5분 이내 전 세계 트래픽 대피소 우회 완료 |

## 내 의견
- [중소기업 원클릭 대피소 사전 연동제(Pre-Registration) 활성화] 공격이 터지고 나서 허둥지둥 사업자등록증을 찾고 KISA에 전화해 입소 신청을 하면 DNS 전파까지 수 시간이 소요되어 이미 비즈니스는 파탄 남 → 나라면: 국내 호스팅사(카페24, 가비아 등)와 KISA API를 연동하여, 호스팅 가입 시 '사이버대피소 사전 대기 모드'를 기본 옵션으로 제공하고, 디도스 감지 시 버튼 클릭 한 번으로 1분 내 자동 CNAME 스위칭이 이뤄지는 자동화 파이프라인을 구축
