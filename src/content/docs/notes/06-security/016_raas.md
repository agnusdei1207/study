## 답안 골격
```text
[RaaS] ◀━━ 머리: Ⅶ 내 의견 (단순 백신 탐지 탈피 → 위협 인텔리전스(TI) 기반 초기 침투 브로커(IAB) 차단 체계 수립)
 ┃
 ┣━ Ⅰ 개요 ───── 랜섬웨어 공격의 산업화·분업화 → 악성코드 개발자와 유포자(어필리에이트) 간 구독형 범죄 생태계 확산
 ┣━ Ⅱ 특징 ───── 서비스형 모델(SaaS 구조) · 공격 진입장벽 급감 · 다크웹 기반 수익 분배 · 다중 협박 포털 운영
 ┣━ Ⅲ 구조 ───── RaaS 운영자(개발/인프라/협상포털) · 어필리에이트(침투/유포) · IAB(초기접근권한판매자) · 희생자
 ┣━ Ⅳ 흐름 ───── ① RaaS 등록/빌더 생성 → ② IAB로부터 기업 접근권한 구매 → ③ 악성코드 유포 및 암호화 → ④ 몸값 수익 배분
 ┣━ Ⅴ 비교 ───── 전통적 독립형 랜섬웨어(단일 해커, 수작업) vs RaaS 생태계(분업화, 자동화 빌더, 24/7 협상 지원)
 ┗━ Ⅵ 실무 ───── IAB(Initial Access Broker) 모니터링 / 유출 계정 실시간 폐기 / 에어갭 백업 및 불변 스토리지
```

## 한 줄 본질
- 악성코드 제작 기술이 없는 비전문가도 다크웹 플랫폼에서 랜섬웨어를 빌드하고 유포할 수 있는 서비스형 사이버 범죄 모델 → 공격 규모 및 빈도 폭증 / 유출 계정 기반 침투 차단 시 방어 가능

## 핵심 그림
```text
[RaaS(Ransomware as a Service) 4자 분업 생태계 및 수익 배분 구조]

 ┌─────────────────────────────────────────────────────────────┐
 │                    다크웹 RaaS 플랫폼                       │
 │  [ RaaS 운영자 (Operator) ]                                │
 │  - 랜섬웨어 엔진 개발, 난독화 빌더 제공                     │
 │  - C2 인프라 및 다크웹 유출/협상 사이트 운영                │
 └──────────────┬──────────────────────────────┬───────────────┘
                │ 빌더/C2 제공                 │ 몸값 수익 배분 (20~30%)
                ▼                              ▼
 ┌─────────────────────────────┐        ┌─────────────────────────────┐
 │  어필리에이트 (Affiliate)   │ <────> │    비트코인/모네로 지갑     │
 │  - 실제 기업 침투 및 실행   │        └──────────────┬──────────────┘
 └──────────────┬──────────────┘                       │ 몸값 지불
                ▲ 접근 권한 구매                       │
 ┌──────────────┴──────────────┐        ┌──────────────┴──────────────┐
 │ IAB (초기 접근 브로커)      │        │      피해 기업 (Victim)     │
 │ - VPN/RDP 탈취 계정 판매    │        │  - 데이터 암호화/유출 피해  │
 └─────────────────────────────┘        └─────────────────────────────┘
```

## 핵심 용어
- 어필리에이트(Affiliate): RaaS 운영자가 제공한 랜섬웨어 바이너리를 구매하거나 제휴를 맺고, 실제 표적 기업에 침투하여 감염시키는 유포 파트너
- IAB(Initial Access Broker): 피싱, 인포스틸러, 취약점 스캔을 통해 사내망 접근 권한(VPN, RDP)을 미리 확보한 뒤 다크웹에서 어필리에이트에게 판매하는 브로커

## 핵심 통찰
- RaaS의 등장은 사이버 공격의 성격을 '기술적 해킹'에서 '비즈니스 모델'로 전환시켰으며, 전문 고객센터 채팅창까지 운영하며 협상 프로세스를 표준화함
- 어필리에이트는 직접 제로데이를 찾지 않고 IAB로부터 수십~수백 달러에 구매한 유출 사내 VPN 계정을 통해 합법적 세션으로 침투하므로 기존 시그니처 백신을 무력화함
- RaaS 브랜드가 사법기관에 소탕(Takedown)되더라도 핵심 개발진과 어필리에이트는 다른 이름으로 재결성(Rebranding)하여 공격을 지속함

## 이웃 토픽과 구분
- RaaS vs CaaS(Cybercrime as a Service): CaaS = 디도스, 피싱, 스팸 등 모든 사이버 범죄 인프라를 서비스화한 상위 개념 / RaaS = 랜섬웨어 암호화 및 갈취에 특화된 하위 버티컬 서비스

## 문제·원인·대책
- 사례: 138회 기출 다크웹 IAB로부터 구매한 원격 데스크톱(RDP) 자격증명을 통해 RaaS 어필리에이트가 내부망에 침투한 사건
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| IAB를 통한 임직원 계정 구매 후 즉각 사내망 침투 | 외부 노출 RDP 포트 운영 및 단일 패스워드 인증 | 외부 노출 원격 포트 폐쇄 및 방화벽 앞단 MFA 강제 | 자격증명만으로 사내망 침투하는 경로 원천 봉쇄 |
| RaaS 빌더로 생성된 맞춤형 변종 악성코드 미탐지 | 파일 서명 기반 전통적 백신의 탐지 한계 | 행위 기반 EDR 및 대량 파일 수정 프로세스 감시 룰 적용 | 신종 변종 랜섬웨어의 암호화 행위 즉각 격리 |

## 이렇게 출제된다
- 제138회 4교시 5번: "최근 기업과 개인을 대상으로 한 랜섬웨어(Ransomware) 피해가 지속적으로 발생하고 있으며, 이를 서비스 형태로 제공하는 RaaS(Ransomware as a Service)의 등장으로 진입 장벽이 낮아지고 있다. 다음 내용을 설명하시오." → 요구 포인트: Ⅰ 산업화 배경 + Ⅲ 분업 생태계 구조 + Ⅵ IAB 차단 전략
- 제128회 1교시 12번: "랜섬웨어(Ransomware)와 RaaS(Ransomware as a Service)를 설명하시오." → 요구 포인트: Ⅱ 특징 + Ⅳ 공격 및 수익 프로세스

## 내 의견
- [악성코드 파일 차단에만 집중된 방어 전략의 맹점] 많은 기업이 파일 검사에만 매달려 정작 IAB가 다크웹에서 자사 VPN 계정을 버젓이 거래하고 있는 정황을 전혀 인지하지 못함 → 나라면: 다크웹 위협 인텔리전스(CTI) 모니터링 서비스를 도입해 사내 도메인 계정 유출 시 실시간으로 강제 패스워드 리셋을 수행하고, 관리자 원격 접속 시 전용 점프 호스트(Bastion Host)를 강제
