## 답안 골격
```text
[LLM 보안 위험] ◀━━ 머리: Ⅶ 내 의견 (입력 가드레일 + 도구 호출 최소권한 격리 다층 방어 구축)
 ┃
 ┣━ Ⅰ 개요 ───── 확률적 텍스트 생성 특성 → 전통적 경계 보안을 무력화하는 신종 인젝션·탈취 위협 대두
 ┣━ Ⅱ 특징 ───── 비결정론적 출력 · 자연어 명령 실행 · 광범위한 시스템 연동 권한 · 학습데이터 오염 취약
 ┣━ Ⅲ 구조 ───── 입력단(프롬프트) · 모델단(가중치/추론) · 연동단(RAG/도구호출) · 출력단(응답/실행)
 ┣━ Ⅳ 흐름 ───── 악의적 프롬프트 주입 → 시스템 가드레일 우회 → 비정상 도구 호출 실행 → 민감 데이터 유출
 ┣━ Ⅴ 비교 ───── 전통 웹 취약점(OWASP Top 10) vs LLM 애플리케이션 취약점(OWASP LLM Top 10)
 ┗━ Ⅵ 실무 ───── 간접 프롬프트 주입 방어 / RAG 벡터 DB 접근통제 / 모델 탈옥(Jailbreak) 탐지
```
- 필수 키워드: 프롬프트 인젝션 · 데이터 중독 · 모델 도난 · 간접 주입 · 도구 과잉 권한 · AI 가드레일
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 공격 접점 계층 도식 → Ⅴ 주요 위협 대응표 / 25점 = Ⅰ~Ⅶ 전개, OWASP LLM 10대 위협 매핑 및 Ⅵ 실무 방어 체계 제시
- 기출: 136회 2교시 3번 `LLM 도입 보안 위험 3가지 및 대응` → Ⅲ·Ⅵ / 136회 4교시 5번 `OWASP LLM Top 10` → Ⅴ 비교

## 한 줄 본질
- 자연어 입력을 그대로 명령어로 해석하는 메커니즘 → 명령과 데이터의 경계가 무너져 악의적 지시 실행 및 민감 정보 노출 유발 → 자연어 처리 자율성 획득 / 입력 통제 불가 시 시스템 장악 위험

## 핵심 그림
```text
[LLM 애플리케이션 계층별 보안 위협 접점 및 방어선]

 [사용자/외부 입력] ──> [ 가드레일 필터 ] ──> [ LLM 추론 엔진 ] ──> [ 도구/DB 연동 (MCP) ]
         │                     │                      │                       │
      위협:                 방어:                  위협:                   위협:
  직접 인젝션            정규식/분류기           간접 인젝션             과도한 권한 실행
  탈옥(Jailbreak)       입력 길이 제한         시스템 프롬프트 탈취     비인가 데이터 유출
```

## 핵심 용어
- 간접 프롬프트 주입(Indirect Prompt Injection): 웹 검색 결과나 외부 문서에 숨겨진 악성 지시어가 모델 추론 시 시스템 명령으로 둔갑해 실행되는 공격
- AI 가드레일(AI Guardrails): 입출력 텍스트를 실시간 검사해 악성 명령, PII(개인식별정보), 유해 콘텐츠를 사전에 차단하는 보안 프록시 계층

## 핵심 통찰
- LLM에서 코드와 데이터의 물리적 분리는 불가능함 → 전통적 파라미터 바인딩 방식이 통하지 않으므로 외부 가드레일 기반 검증이 필수적임
- 모델 가중치는 블랙박스이므로 내부 추론 결과를 100% 신뢰할 수 없음 → LLM이 호출하는 외부 도구(Tool Call)에 엄격한 최소 권한(Least Privilege)을 부여해야 함
- RAG 파이프라인에서 벡터 DB 인덱스에 권한 메타데이터가 없으면 문서 검색 과정에서 권한 없는 내부 기밀이 LLM 컨텍스트로 무단 유입됨

## 이웃 토픽과 구분
- LLM 보안 위험 vs 전통 애플리케이션 보안: 전통 보안 = 엄격한 문법과 정적 코드 취약점 통제 / LLM 보안 = 비결정론적 자연어 해석 및 런타임 프롬프트 조작 대응

## 문제·원인·대책
- 사례: 136회 기출 엔터프라이즈 AI 챗봇의 내부 인사·급여 데이터 비인가 조회 사고
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| RAG 검색 시 타 부서 기밀 문서 유출 | 벡터 DB 청크에 사용자 역할 기반 접근통제(RBAC) 미적용 | 청크 메타데이터에 ACL 태그 부여 및 검색 쿼리 시 필터링 강제 | 권한 없는 문서의 LLM 컨텍스트 로딩 원천 차단 |
| 공격자의 시스템 프롬프트 탈취 | "이전 지시를 무시하라"는 탈옥 패턴에 대한 방어 미흡 | 입력 가드레일(NeMo Guardrails 등) 도입 및 이중 점검 모델 배치 | 악의적 프롬프트 조작 패턴 탐지 및 응답 거부 |

## 이렇게 출제된다
- 제136회 2교시 3번: "AI 기반 소프트웨어 개발에서 LLM(Large Language Model)을 도입할 때, 고려해야 할 보안 위험을 3가지 이상 쓰고 각 대응 방안을 설명하시오." → 요구 포인트: Ⅲ 위협 분류 3가지 + Ⅵ 아키텍처 관점 대응책
- 제136회 4교시 5번: "대형언어모델(LLM, Large Language Model)의 활용이 급격히 증가함에 따라 그와 관련된 보안 위협이 새롭게 대두되고 있다. OWASP에서는 2025년 버전의 LLM 애플리케이션을 위한 Top 10 보안 위협 목록을 제시하였다..." → 요구 포인트: Ⅴ OWASP LLM 핵심 항목과 기술 통제 방안

## 내 의견
- [가드레일 없는 LLM API 직결 배포의 위험성] 사내 시스템에 LLM을 연동하면서 API 키와 DB 접근 권한을 LLM 에이전트에 통째로 위임해 SQL 인젝션과 유사한 데이터 삭제 사고 위험 노출 → 나라면: LLM과 실행 환경 사이에 읽기 전용 샌드박스를 두고, 트랜잭션 유발 도구 호출 시 사람의 승인(Human-in-the-loop)을 거치는 2단계 검증 게이트를 구축
