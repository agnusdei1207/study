## 답안 골격
```text
[해시 함수] ◀━━ 머리: Ⅶ 내 의견 (단순 해시 사용 금지 → 솔트(Salt) + 키 스트레칭(Argon2) 기반 비밀번호 저장)
 ┃
 ┣━ Ⅰ 개요 ───── 가변 길이 메시지를 고정 길이 다이제스트로 압축 → 데이터 무결성 검증 및 인증 기초 제공
 ┣━ Ⅱ 특징 ───── 역상 저항성(일방향성) · 제2역상 저항성(약한 충돌 회피) · 충돌 저항성(강한 충돌 회피) · 눈사태 효과
 ┣━ Ⅲ 구조 ───── Merkle-Damgard 구조(MD5, SHA-1, SHA-2) vs 스펀지 구조(Sponge Construction, SHA-3)
 ┣━ Ⅳ 흐름 ───── ① 입력 메시지 패딩 → ② 블록 분할 → ③ 압축 함수 반복 연산 → ④ 고정 출력(Digest) 생성
 ┣━ Ⅴ 비교 ───── 암호학적 해시(SHA-2/SHA-3) vs 패스워드 해시(PBKDF2/Bcrypt/Argon2) vs 비암호학적 해시(Murmur/xxHash)
 ┗━ Ⅵ 실무 ───── 생일 역설(Birthday Paradox) 충돌 공격 대응 / 레인보우 테이블 무력화 / 길이 확장 공격(Length Extension) 방어
```
- 필수 키워드: 일방향성 · 제2역상 저항성 · 충돌 저항성 · 눈사태 효과(Avalanche Effect) · Merkle-Damgard · 스펀지 구조
- 배점 전략: 10점 = Ⅰ 개요 → Ⅱ 암호학적 3대 보안 특성 표 → Ⅲ Merkle-Damgard 도식 / 25점 = Ⅰ~Ⅶ 전개, SHA-2와 SHA-3 구조 차이 및 Ⅵ 패스워드 크래킹 방어 집중
- 기출: 138회 4교시 2번 `단방향 해시 함수의 특성과 알고리즘` → Ⅰ·Ⅱ·Ⅲ / 120회 1교시 `해시 함수 요구조건` → Ⅱ·Ⅴ

## 한 줄 본질
- 가변 길이 입력에 대해 복호화가 불가능한 고정 크기 고유 지문을 생성하는 일방향 압축 함수 → 데이터 변경 시 지문이 완전히 바뀌는 특성으로 무결성 보증 / 비둘기집 원리로 인한 잠재적 충돌 불가피

## 핵심 그림
```text
[Merkle-Damgard 구조 (SHA-2) vs 스펀지 구조 (SHA-3 / Keccak)]

 1. Merkle-Damgard 구조 (SHA-256)
     [블록 1]       [블록 2]       [블록 n]
        │              │              │
  IV ─> [압축 함수] ──> [압축 함수] ──> [압축 함수] ──> [최종 Digest (256-bit)]
       (길이 확장 공격에 취약할 수 있음)

 2. 스펀지 구조 (SHA-3)
      흡수 단계 (Absorbing)           착즙 단계 (Squeezing)
     [블록 1]  [블록 2]               [출력 1]  [출력 2]
        │         │                      ▲         ▲
  0 ─> [  f  ] ─> [  f  ] ───────────> [  f  ] ─> [  f  ] ...
        (비트 레이트 r + 용량 c 상태 유지, 길이 확장 공격 원천 차단)
```

## 핵심 용어
- 역상 저항성(Preimage Resistance): 주어진 해시값 $y$에 대해 $h(x) = y$를 만족하는 원본 $x$를 찾는 것이 계산적으로 불가능해야 하는 성질
- 충돌 저항성(Collision Resistance): $h(x_1) = h(x_2)$를 만족하는 서로 다른 임의의 두 입력 $x_1, x_2$를 찾는 것이 계산적으로 불가능해야 하는 성질

## 핵심 통찰
- 출력 길이가 $n$비트일 때 역상 저항성을 깨는 복잡도는 $2^n$이지만, 생일 역설(Birthday Attack)로 인해 충돌 저항성을 깨는 복잡도는 $2^{n/2}$로 급감함 (SHA-256의 실질 충돌 안전성은 128비트)
- Merkle-Damgard 구조의 해시 함수는 메시지 끝에 데이터를 덧붙여 새로운 유효 해시를 만드는 길이 확장 공격(Length Extension Attack)에 취약함 → SHA-3 스펀지 구조 채택 또는 HMAC 사용 필요
- 단순 SHA-256은 GPU 기반 무차별 대입(Brute-force) 연산 속도가 초당 수십억 번에 달해 패스워드 단독 해싱용으로는 부적합함

## 이웃 토픽과 구분
- 암호학적 해시 vs 암호화 알고리즘: 해시 = 복호화 키가 존재하지 않는 일방향 압축 / 암호화 = 복호화 키를 이용해 평문으로 복원 가능한 양방향 변환

## 문제·원인·대책
- 사례: 138회 기출 단순 SHA-256으로 해싱된 사용자 패스워드 DB가 유출되어 레인보우 테이블로 90% 이상 역추적된 사건
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 유출된 해시값의 사전 대입 및 초고속 역추적 | 솔트 미적용 및 단일 라운드 고속 해시 사용 | 솔트(Salt) 무작위 부여 + 메모리 집약적 해시(Argon2id) 적용 | 레인보우 테이블 사전 무력화 및 GPU 병렬 크래킹 지연 |
| 서명 검증 로직에서 길이 확장 공격 발생 | Merkle-Damgard 기반 단순 해시(H(secret || msg)) 사용 | HMAC(H((K ^ opad) || H((K ^ ipad) || M))) 표준 적용 | 내부 상태 노출 기반 위조 방지 |
