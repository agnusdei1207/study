## 답안 골격
```text
[SOAR] ◀━━ 머리: Ⅶ 내 의견 (단순 룰 기반 자동화 탈피 → 플레이북 표준화 및 보안관제 인력 협업 중심 운영)
 ┃
 ┣━ Ⅰ 개요 ───── 관제 경보 폭증(Alert Fatigue)과 보안 인력 부족 → 이기종 보안 솔루션 오케스트레이션 및 자동 대응 플랫폼
 ┣━ Ⅱ 특징 ───── 보안 오케스트레이션(SO) · 자동화(SA) · 위협 대응(SR) · 플레이북(Playbook) 기반 워크플로우
 ┣━ Ⅲ 구조 ───── 오케스트레이션 엔진 · 플레이북 엔진 · 팁(TIP, 위협인텔리전스) 연동 모듈 · 대시보드 및 협업 콘솔
 ┣━ Ⅳ 흐름 ───── ① 경보 수집/정규화 → ② 위협 인텔리전스(TI) 상관분석 → ③ 플레이북 자동 실행(IP 차단 등) → ④ 사후 티켓팅
 ┣━ Ⅴ 비교 ───── SIEM(로그 수집/상관분석/탐지 중심) vs SOAR(이기종 장비 연동/자동화/조치 대응 중심)
 ┗━ Ⅵ 실무 ───── 자동 차단 오탐으로 인한 서비스 장애 / 플레이북 유지보수 부담 / 레거시 장비 API 연동 부재
```
- 필수 키워드: 보안 오케스트레이션(SO) · 보안 자동화(SA) · 플레이북(Playbook) · SIEM 연계 · MTTR(평균대응시간) 단축 · TIP

## 한 줄 본질
- 수많은 보안 장비의 방대한 경보로 인해 관제 인력이 마비되는 현상(Alert Fatigue) 극복 → 사전 정의된 플레이북에 따라 이기종 장비 간 API를 오케스트레이션해 탐지부터 차단까지 자동화 → 침해 대응 시간(MTTR)을 수시간에서 초 단위로 단축 / 오탐 시 정상 트래픽 차단 위험

## 핵심 용어
- 보안 오케스트레이션(Security Orchestration): 방화벽, EDR, 메일 보안, 위협 인텔리전스 등 서로 다른 벤더의 보안 도구들을 API를 통해 단일 콘솔에서 유기적으로 연동·제어하는 기술
- 플레이북(Playbook): 피싱 메일, 악성코드 감염, 비인가 접근 등 특정 보안 사고 유형별 대응 절차와 조건을 코드로 작성한 표준 대응 자동화 시나리오

## 핵심 통찰
- SIEM은 "사고가 발생했다"는 사실을 탐지하고 알려주는 시스템이며, SOAR는 그 알림을 받아 "방화벽에서 차단하고 호스트를 격리하라"고 실제 행동을 취하는 시스템임
- 100% 전자동화(Full Automation)는 정상적인 비즈니스 트래픽을 오탐으로 차단할 위험이 크므로, 중요 서비스 영역은 사람의 최종 확인을 거치는 반자동(Semi-Automation) 구조가 필수적임
- SOAR의 성패는 도입한 솔루션의 기능보다 조직 내부의 인시던트 대응 표준 운영 절차(SOP)가 얼마나 정교하게 플레이북으로 코드화되어 있는지에 달려 있음

## 이웃 토픽과 구분
- SOAR vs SIEM: SIEM = 대용량 로그를 수집·상관분석하여 경보를 생성하는 탐지 레이어 / SOAR = 생성된 경보를 받아 분석·격리·차단을 자동 수행하는 조치 레이어

## 문제·원인·대책
- 사례: 135회 기출 SOAR 자동화 플레이북이 핵심 CDN IP를 악성 C2로 오인하여 방화벽에서 전면 차단해 대규모 서비스 장애가 발생한 사건
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 오탐으로 인한 핵심 비즈니스 서버 차단 | 평판 점수(Reputation Score) 단독 기준 자동 차단 룰 적용 | 화이트리스트 검증 로직 강제 및 중요 서버 차단 시 관제 담당자 수동 승인 게이트 배치 | 정상 서비스 오차단 방지 및 서비스 가용성 보장 |
| 보안 장비 펌웨어 업데이트 후 연동 중단 | 벤더별 비표준 REST API 인터페이스 변경 | 오픈 보안 아키텍처(OASIS OpenC2) 표준 프로토콜 준수 및 모듈형 커넥터 분리 | API 변경 시에도 플레이북 무중단 유지보수 |
