## 답안 골격
```text
[바이오정보 분산관리] ◀━━ 머리: Ⅶ 내 의견 (단일 저장소 유출 위험 해소 → 비밀분산(Shamir) 기반 2분할 저장 및 FIDO 연계)
 ┃
 ┣━ Ⅰ 개요 ───── 바이오정보(지문·안면)의 평생 불변성 → 유출 시 재발급 불가능한 치명적 프라이버시 위협 방지
 ┣━ Ⅱ 특징 ───── 템플릿 분할 저장 · 단독 정보로는 복원 불가 · 분산 인증(매칭) 메커니즘 · 금융 결제 표준 준수
 ┣━ Ⅲ 구조 ───── 사용자 단말(스마트폰) · 금융회사 서버 · 분산관리센터(금융결제원 등) · 비밀분산 알고리즘
 ┣━ Ⅳ 흐름 ───── ① 바이오 특징점 추출 → ② 조각 분할(Share A, Share B) → ③ 분산 저장 → ④ 인증 시 실시간 결합·매칭
 ┣━ Ⅴ 비교 ───── 중앙 집중 저장(유출 시 전면 노출) vs FIDO(단말 로컬 저장) vs 바이오정보 분산관리(조각 분산 분할 저장)
 ┗━ Ⅵ 실무 ───── 네트워크 레이턴시로 인한 결제 지연 / 단말 변경 시 재등록 / 특징점 추출 오차(FRR/FAR) 절충
```
- 필수 키워드: 비밀분산(Secret Sharing) · Shamir 기법 · 특징점 분할 · 바이오정보 분산관리센터 · 금융결제원 · FIDO
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 분산 저장/인증 아키텍처 도식 → Ⅴ 중앙집중 vs 분산관리 비교 / 25점 = Ⅰ~Ⅶ 전개, Ⅳ 2단계 분할 및 인증 알고리즘과 Ⅵ 금융권 안면인식 결제 적용 방안 집중
- 기출: 138회 1교시 5번 `안면인식 결제 서비스와 바이오정보 분산관리` → Ⅰ·Ⅲ / 120회 2교시 1번 `바이오정보 분산관리 기술 가이드라인` → Ⅲ·Ⅳ·Ⅵ

## 한 줄 본질
- 지문이나 안면 정보는 유출 시 비밀번호처럼 변경할 수 없는 영구적 치명성 존재 → 특징점 템플릿을 암호학적으로 2개 이상의 조각으로 분할해 서로 다른 기관에 분산 저장 → 단일 기관 해킹 시에도 원본 복원 불가 / 인증 시 결합 지연 발생

## 핵심 그림
```text
[바이오정보 분산관리 등록 및 인증 메커니즘 (금융결제원 분산관리 모델)]

 1. 등록 단계
  [ 사용자 단말 ]
   - 안면/지문 스캔 ──> [ 특징점 추출 ] ──(비밀분산)──> [ 조각 A ] ──> [ 금융회사 서버 저장 ]
                                                     └──> [ 조각 B ] ──> [ 분산관리센터 저장 ]
                                                     (어느 한쪽만으로는 원본 복원 불가)

 2. 인증 단계
  [ 사용자 단말 ]
   - 인증 요청 (실시간 스캔)
         │
         ├── 조각 A 요청 ──> [ 금융회사 서버 ]
         └── 조각 B 요청 ──> [ 분산관리센터 ]
                                    │
                                    ▼ (안전한 채널 결합)
                         [ 실시간 매칭 검증 ] ──> [ 인증 성공/실패 반환 ]
```

## 핵심 용어
- 샤미르 비밀분산(Shamir's Secret Sharing): 다항식 보간법을 이용해 비밀 $S$를 $n$개의 조각으로 나누고, 그 중 최소 $k$개($k \le n$)의 조각이 모여야만 원래 비밀을 복원할 수 있는 암호학적 기법
- 템플릿(Template): 지문, 홍채, 안면 등의 생체 원본 이미지에서 융선, 골, 특징점 간의 거리·각도 등을 수치화하여 추출한 바이오 특징 데이터

## 핵심 통찰
- 바이오정보 분산관리는 원본 사진을 쪼개는 것이 아니라, 특징점 벡터(템플릿)를 수학적 파편으로 분할하여 저장하는 기술임
- 금융회사와 분산관리센터(금융결제원)가 각각 1조각씩 보유하므로, 한쪽 기관의 데이터베이스가 통째로 털리더라도 공격자는 아무런 바이오정보를 획득할 수 없음
- 인증 시 조각을 결합하여 메모리에서 즉시 매칭하고 검증 직후 결합 데이터를 지체 없이 파기(In-Memory Zeroization)해야 완벽한 안전성이 담보됨

## 이웃 토픽과 구분
- 바이오정보 분산관리 vs FIDO: FIDO = 바이오정보가 단말의 보안 영역(SE/TEE)을 절대 벗어나지 않음 / 바이오정보 분산관리 = 단말이 바뀌어도 서버 간 분산 조각을 결합하여 인증을 수행할 수 있음

## 문제·원인·대책
- 사례: 138회 기출 오프라인 간편 안면인식 결제 키오스크 도입 시 대량 생체정보 유출 우려 민원 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 결제 단말기 해킹으로 고객 안면 템플릿 탈취 위험 | 단말 로컬 스토리지에 인증 템플릿 저장 | Shamir 알고리즘으로 분할 후 금융결제원 분산관리센터와 2분할 보관 | 단말기 탈취 시 무의미한 암호 파편만 노출 |
| 결합 인증 시 네트워크 레이턴시로 결제 실패 발생 | 분산관리센터와의 실시간 소켓 통신 지연 | 전용 VPN 암호화 고속 회선 구축 및 영지식 매칭(조각 전송 없는 검증) 도입 | 결제 응답 속도 0.5초 이내 단축 및 트랜잭션 보장 |

## 이렇게 출제된다
- 제138회 1교시 5번: "안면인식 결제 서비스 확산에 따른 바이오정보(Biometric Information) 분산관리 기술 및 안전성 확보조치를 설명하시오." → 요구 포인트: Ⅰ 영구불변성 문제 + Ⅲ 분산관리 체계
- 제120회 2교시 1번: "바이오정보 분산관리 표준 가이드라인에 따른 바이오인식 정보의 분할·저장·인증 메커니즘을 설명하시오." → 요구 포인트: Ⅲ 아키텍처 + Ⅳ Shamir 분산 절차

## 내 의견
- [중앙 집중식 생체인증의 시한폭탄 위험] 고객 편의성만을 앞세워 수천만 명의 안면 특징점 DB를 단일 클라우드 버킷에 모아두는 것은 대형 침해사고의 시한폭탄임 → 나라면: 개인정보보호위원회 바이오정보 가이드라인을 엄격히 적용해 금융사-결제원 분산관리 2분할을 강제하고, 모바일 환경에서는 단말 보안 칩셋(SE) 내 FIDO2 인증을 최우선으로 유도
