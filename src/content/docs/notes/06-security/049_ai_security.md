## 답안 골격
```text
[AI 보안] ◀━━ 머리: Ⅶ 내 의견 (단순 사후 정렬 탈피 → 데이터 수집부터 모델 배포까지 전 수명주기 AI 레드팀 및 가드레일 내재화)
 ┃
 ┣━ Ⅰ 개요 ───── 고성능 AI 모델 확산에 따른 신종 위협(적대적 공격, 탈옥, 정보 유출, 오남용) 증대 → AI 수명주기 전반의 신뢰성과 안전성 보장 체계
 ┣━ Ⅱ 특징 ───── 비결정적 출력 · 데이터 의존성 · 새로운 공격 표면(프롬프트, 가중치, 임베딩) · 사회적 파급력
 ┣━ Ⅲ 구조 ───── 수명주기 4단계(데이터 수집/가공 → 학습/파인튜닝 → 모델 배포/서빙 → 운영/모니터링)별 보안 통제
 ┣━ Ⅳ 흐름 ───── ① 학습 데이터 독성/포이즈닝 검증 → ② 적대적 훈련 및 안전 정렬(RLHF) → ③ 배포 시 가드레일 적용 → ④ 상시 레드티밍 및 감사
 ┣━ Ⅴ 비교 ───── 전통 SW 보안(결정론적 코드 버그, 메모리 결함 패치) vs AI 보안(확률론적 모델, 데이터 편향, 적대적 섭동 및 프롬프트 탈옥 방어)
 ┗━ Ⅵ 실무 ───── 모델 역추론(Model Inversion)을 통한 학습 데이터 복원 / 데이터 포이즈닝 / 적대적 섭동(FGSM) / 가드레일 오탐
```
- 필수 키워드: AI 보안 · AI 수명주기 · 데이터 포이즈닝 · 적대적 공격 · 모델 탈취 · 프롬프트 인젝션 · AI 레드티밍 · 가드레일
- 배점 전략: 10점 = Ⅰ 개요 및 위협 유형 → Ⅲ AI 수명주기별 보안 통제 도식 → Ⅴ 전통 SW 보안 대비 차이점 / 25점 = Ⅰ~Ⅶ 전개, 주요 공격 기법별 대응 메커니즘과 Ⅵ AI 안전 거버넌스 프레임워크 집중
- 기출: 140회 2교시 6번 `AI 모델의 성능이 좋아지면서 고성능 AI 모델로 인한 위협도 증가하는 상황이다. AI 보안에 대해 다음을 설명하시오.` → Ⅰ~Ⅶ 전 영역 포괄

## 한 줄 본질
- 소프트웨어 코드 규칙이 아닌 확률적 가중치와 대규모 데이터로 동작하는 AI의 불투명성 병목 → 학습 데이터 검증부터 모델 정렬, 서빙 가드레일, 상시 레드티밍을 포괄하는 전 수명주기 통제 적용 → AI 안전성 확보 / 모델 추론 지연 및 학습 정렬 비용 발생

## 핵심 그림
```text
[AI 전 수명주기(Lifecycle) 보안 위협 및 방어 체계]

 1. 데이터 수집/정제       2. 모델 학습/튜닝         3. 배포 및 서빙
 ┌───────────────────┐    ┌───────────────────┐    ┌───────────────────┐
 │ [데이터 포이즈닝] │ ─> │ [백도어 삽입]     │ ─> │ [탈옥/인젝션]     │
 │ [개인정보 오염]   │    │ [모델 가중치 탈취]│    │ [모델 역추론]     │
 └─────────┬─────────┘    └─────────┬─────────┘    └─────────┬─────────┘
           ▼                        ▼                        ▼
 [데이터 무결성 검증]    [적대적 훈련(RLHF)]      [입출력 가드레일]
 [차분 프라이버시]        [가중치 암호화/워터마크] [AI 방화벽/HITL]
```

## 핵심 용어
- 데이터 포이즈닝(Data Poisoning): 모델 학습 단계에서 공격자가 악의적으로 오염된 데이터나 백도어 트리거를 주입하여 특정 조건에서 오작동을 유도하는 공격
- 적대적 훈련(Adversarial Training): 모델 학습 시 의도적으로 노이즈(적대적 섭동)를 주입한 예제를 함께 학습시켜 적대적 왜곡 공격에 대한 모델의 복원력을 높이는 기법

## 핵심 통찰
- 전통적인 침해사고는 시스템을 '다운'시키지만, AI 공격은 시스템을 '정상 동작하는 척 오작동'하게 만들어 잘못된 의사결정을 유도함
- 모델 파라미터가 수천억 개에 달할수록 설명 가능성(Explainability)이 떨어져 백도어나 탈옥 트리거의 사전 발견이 기하급수적으로 어려워짐
- 안전 정렬(Safety Alignment)만으로는 한계가 명확함 → 모델 외부에서 입출력 트래픽을 감시하고 제어하는 'AI 안전 게이트웨이(Guardrails)' 계층이 반드시 독립적으로 존재해야 함

## 이웃 토픽과 구분
- 시큐어 코딩 vs AI 보안: 시큐어 코딩 = 소스코드 내 취약점(CWE) 제거 / AI 보안 = 학습 데이터 신뢰성, 확률적 모델 출력 제어, 지적재산권 보호

## 문제·원인·대책
- 사례: 이미지 분류 AI 모델에 육안으로 보이지 않는 미세 노이즈를 추가하여 자율주행 차량이 정지 표지판을 속도제한 표지판으로 오인식하게 만든 실험
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 미세 섭동(Perturbation)에 의한 모델 오인식 | 딥러닝 모델 결정 경계면의 고차원 선형 취약성 | FGSM/PGD 적대적 예제를 포함한 적대적 훈련(Adversarial Training) 적용 | 적대적 노이즈 공격에 대한 분류 정확도 복원력 확보 |
| LLM 서비스 대상 프롬프트 인젝션 및 탈옥 | 시스템 프롬프트와 사용자 입력 데이터의 동일 컨텍스트 처리 | 네임스페이스 격리 및 LLM Guard 기반 입력 의미론적 유해성 검사기 배치 | 시스템 지침 무력화 및 악성 지시 실행 차단 |

## 이렇게 출제된다
- 제140회 2교시 6번: "AI 모델의 성능이 좋아지면서 고성능 AI 모델로 인한 위협도 증가하는 상황이다. AI 보안에 대해 다음을 설명하시오." → 요구 포인트: Ⅰ AI 보안 등장 배경 + Ⅲ 생애주기별 위협과 방어 기술 + Ⅵ 안전 거버넌스 및 고려사항

## 내 의견
- [출시 일정에 쫓겨 생략되는 안전 검증] 생성형 AI 서비스 런칭 시 비즈니스 기능 개발에만 몰두하여 레드티밍(Red Teaming)을 형식적 테스트로 치부하는 문제 만연 → 나라면: 배포 파이프라인에 자동화된 AI 레드팀 도구(PyRIT, Garak 등)를 필수 테스트 단계로 통합하여 탈옥 성공률 1% 미만 검증 시에만 프로덕션 배포가 가능하도록 품질 게이트 강제
