## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **테스트 커버리지(Test Coverage / 화이트박스 구조적 검증)**: 작성된 테스트 케이스 스위트(Test Suite)가 소스 코드의 제어 흐름 그래프(Control Flow Graph) 상에 존재하는 실행 가능한 문장(Statement), 분기 결정(Branch/Decision), 개별 조건식(Condition), 복합 조건 경로를 얼마나 충실하게 실행(Execution)했는지를 백분율(%)로 정량화한 소프트웨어 테스트 완성도 척도.
- **높은 구문 커버리지의 착시 및 복합 조건 마스킹 결함(Coverage Illusion & Condition Masking Defect)**: 모든 소스코드 줄을 한 번씩 훑었다는 구문 커버리지(Statement Coverage) 100%만 달성하고 안심했으나, `else` 분기가 누락되었거나 `if (A || (B && C))`와 같은 복합 조건문에서 개별 조건의 단독 결함이 상위 조건에 의해 가려지는(Masking) 현상을 놓쳐 상용 배포 후 시스템 크래시가 발생하는 구조적 결함.

</details>

- 정의/개념: 테스트가 실행한 코드 구조의 비율을 재는 **커버리지 지표**
- 배경/필요성: 화이트박스 테스트 수행 시 모든 소스코드 줄을 1회 실행했다는 단순 구문 커버리지($C_0$) 100% 달성에만 안심할 경우, 미실행된 `else` 분기나 복합 조건식(`A || (B && C)`) 내에서 개별 조건의 결함이 상위 조건에 의해 가려지는 조건 마스킹(Condition Masking) 현상을 탐지하지 못해 상용 배포 후 시스템 크래시가 발생하는 치명적 결함이 발생함에 따라, 제어 흐름 계층 포섭 관계($C_0 \subset C_1 \subset \text{MC/DC} \subset C_2$)에 기반하여 구문, 분기, 조건, 그리고 수정 조건/결정 커버리지(MC/DC: Modified Condition/Decision Coverage)를 단계별로 적용하는 구조적 테스트 커버리지 체계를 도입하여 **미실행 제어 경로의 전수 가시화, $N+1$개 테스트 케이스를 통한 개별 조건의 독립 영향(Independent Effect) 수학적 입증 및 기능안전 국제 표준(DO-178C Level A, ISO 26262 ASIL D)의 엄격한 충족**을 달성할 필요

#### 한줄 요약
- 테스트 커버리지는 소스코드 제어 흐름의 실행 정도를 정량화하며, 미션 크리티컬 환경에서는 MC/DC를 통해 복합 조건의 독립성을 검증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **커버리지 포섭 관계 (Subsumption Hierarchy)**:
  - 상위 수준의 커버리지를 100% 만족하면, 하위 수준의 커버리지는 수학적으로 자동 100% 만족되는 포함 관계.
  - $\text{Statement } (C_0) \subset \text{Branch/Decision } (C_1) \subset \text{Condition/Decision} \subset \text{MC/DC} \subset \text{Multiple Condition } (C_2)$.

</details>

- 미실행 분기·예외 경로를 찾는 **구조적 사각지대 가시화**
- $N+1$개 쌍으로 조건 영향을 밝히는 **MC/DC**
- 목표 미달 빌드를 차단하는 **CI/CD 품질 게이트**

#### 한줄 요약
- 계층적 포섭 관계, 미실행 사각지대 가시화, MC/DC의 $N+1$ 효율성, CI/CD 품질 게이트 자동 차단을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **주요 4대 테스트 커버리지 기준 및 정의**:
  1. **구문 커버리지 ($C_0$, Statement)**: 전체 실행 가능한 문장 중 테스트된 문장의 비율 ($C_0 = \frac{\text{실행된 문장 수}}{\text{전체 문장 수}} \times 100\%$).
  2. **분기/결정 커버리지 ($C_1$, Branch/Decision)**: 전체 조건문의 True/False 분기 중 테스트된 분기 비율 ($C_1 = \frac{\text{실행된 분기 수}}{\text{전체 분기 수}} \times 100\%$).
  3. **조건 커버리지 (Condition)**: 복합 조건식 내 각 개별 조건의 True/False가 최소 1회씩 실행된 비율.
  4. **수정 조건/결정 커버리지 (MC/DC)**: 다른 모든 조건이 고정된 상태에서, 관심 대상 개별 조건의 참/거짓 변경만으로 전체 결정식의 결과가 반드시 반전됨을 입증하는 테스트 쌍.

</details>

```text
[테스트 커버리지 포섭 계층]
├── [복합 조건 커버리지 (C2)] 2^N 조합
│   └── [수정 조건/결정 커버리지 (MC/DC)] N+1 조합
│       └── [조건/결정 커버리지]
│           └── [분기/결정 커버리지 (C1)]
│               └── [구문 커버리지 (C0)]
└── [MC/DC 독립 영향 검증 원리]
    ├── 관심 조건의 값 반전 (True ↔ False)
    ├── 타 조건의 고정 (Masking 배제)
    └── 전체 결정식 결과의 반전 입증
```

- 선들의 의미:
  - `──`: 포섭 계층 및 검증 연계
  - `├──`, `└──`: 하위 커버리지 및 검증 요건 분기

| 구성요소 | 책임 |
|:---|:---|
| 구문 커버리지 | 실행 문장의 C0 비율 측정 |
| 분기 커버리지 | 참·거짓 분기의 C1 비율 측정 |
| MC/DC | 개별 조건의 독립 영향 입증 |
| 복합 조건 커버리지 | 모든 2^N 조합 실행 |

#### 한줄 요약
- 상위 커버리지가 하위를 포섭하므로 측정 기준은 하나만 고르면 되지만 케이스 수는 조건 수에 따라 $N+1$과 $2^N$으로 갈라지고, MC/DC는 독립 영향 테스트 쌍만 남겨 복합 조건의 조합 폭증 비용을 피하면서 조건별 판정 기여를 입증한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **커버리지 기반 품질 통제 5단계 수명주기**:
  1. 소프트웨어 안전성 등급(ASIL, SIL, DAL)에 따른 목표 커버리지(예: ASIL D $\rightarrow$ MC/DC 100%) 확정
  2. 컴파일러 또는 바이트코드 레벨에서 제어 흐름 추적 프로브(Probe) 자동 주입(Instrumentation)
  3. CI 파이프라인에서 단위/통합 테스트 자동 실행 및 실행 트레이스 수집
  4. 커버리지 리포트 생성 및 미도달 분기/조건에 대한 갭 분석(Gap Analysis)
  5. 미도달 경로에 대한 테스트 케이스 추가 작성 또는 도달 불가 코드(Dead Code) 제거 후 배포 승인

</details>

```text
[Safety Level & Target Setup] (① ASIL D/SIL 등급별 커버리지 목표(MC/DC 100%) 확정)
└── [Code Instrumentation] (② GCC/LLVM 계측 컴파일 및 분기/조건 카운터 프로브 자동 삽입)
    └── [Automated Test Execution] (③ 테스트 스위트 및 HIL 시뮬레이션 실행, 실행 로그(.gcda) 생성)
        └── [Coverage Gap Analyzer] (④ 구문·분기·MC/DC 측정 및 조건 마스킹 미도달 경로 식별)
            └── [Test Vector Augmentation & Gate] (⑤ 누락 테스트 쌍 추가 또는 Dead Code 제거 후 릴리스 승인)

- 분기 결과: 목표 커버리지(MC/DC 100%) 충족 시 품질 게이트 통과 및 릴리스 승인, 미달 시 빌드 차단 및 테스트 보강
```

#### 한줄 요약
- 안전 등급에 맞춰 목표를 세우고 계측 시험 후 미도달 분기를 보강하여 품질 게이트를 통과시킨다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **구조적 테스트 커버리지 3대 기준 상세 비교**:
  - 구문 커버리지 (C0): 모든 라인 1회 실행 (최소 기본 요건).
  - 분기 커버리지 (C1): 모든 조건문 True/False 1회 실행 (표준 상용 시스템).
  - MC/DC 커버리지: 개별 조건의 독립 영향 증명 (미션 크리티컬 안전 필수).

</details>

| 비교 항목 | 구문 커버리지 | 분기 커버리지 | MC/DC |
|:---|:---|:---|:---|
| 적용 기준 | 모든 문장 실행 확인 | 모든 참·거짓 분기 확인 | 조건별 독립 영향 확인 |
| 마스킹 검출 | 검출 불가 | 검출 불가 | 독립 영향 쌍으로 검출 |
| 테스트 수 | 문장 실행의 최소 집합 | 분기 실행의 최소 집합 | 조건 $N$개의 $N+1$개 쌍 |
| 한계/비용 | 분기 누락 식별 불가 | 조건 마스킹 식별 불가 | 테스트 쌍 설계 비용 증가 |

#### 한줄 요약
- 구문(C0)은 기본 라인 검증, 분기(C1)는 참/거짓 검증, MC/DC는 복합 조건의 독립 영향을 보증한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **돌연변이 테스트(Mutation Testing)**: 소스코드에 인위적 결함(변이체)을 주입하여 테스트 스위트가 이를 감지하고 탈락시키는지 평가하는 시험 기법.
- **도달 불가 코드(Dead Code)**: 제어 흐름 구조상 어떠한 입력 조합으로도 도달하여 실행될 수 없는 불필요한 코드.
- **테스트 오라클(Test Oracle)**: 테스트 케이스 실행 결과가 예상 결과와 일치하는지 여부를 검증하고 단언(Assertion)하는 판정 메커니즘.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 실행만 하는 테스트로 허위 커버리지 발생 | 결함 주입 기반 돌연변이 테스트 병행 | 오라클 결함 검출력 실질 검증 |
| 도달 불가 코드로 목표 커버리지 미달 | 정적 분석 근거 검토 후 제외 승인 | 지표 왜곡 방지 및 정합성 유지 |
| 조건 중첩으로 MC/DC 설계 복잡도 증가 | 복합 조건식 분리 및 순환 복잡도 제한 | 테스트 쌍 설계 단순화 및 유지보수성 향상 |

#### 한줄 요약
- 돌연변이 테스트로 허위 통과를 막고, 도달 불가 코드를 예외 처리하며, 리팩토링으로 MC/DC 설계를 간소화한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **MC/DC(Modified Condition/Decision Coverage)**: 복합 조건식 내 각 조건이 다른 모든 조건과 독립적으로 결정 결과에 영향을 미침을 입증하는 구조적 커버리지.
- **돌연변이 테스트(Mutation Testing)**: 소스코드 변이를 통해 테스트 케이스의 결함 탐지율과 단언문 유효성을 측정하는 품질 검증 기법.
- **DO-178C Level A / ISO 26262 ASIL D**: 항공 및 자동차 분야에서 치명적 재난을 방지하기 위해 MC/DC 100% 달성을 요구하는 최상위 기능안전 표준.

</details>

- **기술 위상/발전**: DO-178C Level A 및 ISO 26262 ASIL D 기반 구조적 테스트 및 MC/DC 커버리지 표준 확립
- **실무 적용/통제**: 돌연변이 테스트(Mutation Testing) 병행, 미션 크리티컬 MC/DC 100% 강제 및 Dead Code 격리

#### 한줄 요약
- 위험도에 따라 구문, 분기, MC/DC 커버리지를 차등 적용하여 테스트 완전성과 안전 표준을 체계적으로 충족한다.
