## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **공동 책임 모델**: 서비스 모델에 따라 CSP와 이용자의 보안·운영 책임을 나눈 체계.
- **CSPM**: 클라우드 자원의 구성 오류와 보안 태세를 지속 탐지하는 도구.
- **출구 전략**: 계약 종료 시 서비스·데이터를 안전하게 이전·삭제하는 계획.

</details>

- 정의/개념: CSP와 이용자의 책임 영역을 증거로 검증하는 **클라우드 전문 감리**
- 배경/필요성: 클라우드 컴퓨팅 환경 전환 시 클라우드 서비스 제공자(CSP)의 보안 인증서(ISO 27017/27018, CSAP 등)에만 맹목적으로 의존할 경우, 공동 책임 모델(Shared Responsibility Model) 하에서 이용자(Customer)의 책임 영역인 IAM 권한 오설정, 공개 S3 버킷 방치, 고객 관리 키(KMS) 통제 부재 및 벤더 종속(Lock-in)에 따른 출구 전략(Exit Strategy) 부재로 인해 대규모 데이터 유출과 복구 불가 재난이 초래되는 구조적 한계가 발생함에 따라, 서비스 모델(IaaS, PaaS, SaaS)별 책임 분계선을 명확히 확정하고 클라우드 보안 태세 관리(CSPM) 및 코드형 인프라(IaC) 드리프트를 정밀 검증하는 클라우드 서비스 감리 체계를 도입하여 **이용자 보안 설정의 객관적 실증 실사, Multi-AZ 기반 고가용성 복원력 보증 및 데이터 암호학적 영구 삭제와 안전한 이관을 보장하는 출구 거버넌스**를 달성할 필요

#### 한줄 요약
- 클라우드 감리는 공동 책임 경계와 이용자 설정·복원력·출구 전략을 검증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **IaC 드리프트(IaC Drift)**: Terraform 등 코드형 인프라에 선언된 구성과 실제 클라우드 콘솔에서 수동 변경된 인프라 상태 간의 불일치.
- **KMS 봉투 암호화(Envelope Encryption)**: 데이터를 데이터 암호화 키(DEK)로 암호화하고, 해당 DEK를 상위 키 암호화 키(KEK)로 다시 암호화하는 다계층 키 보호 기법.
- **간접 감사(Indirect Audit)**: 이용자가 직접 실사할 수 없는 CSP의 물리적 데이터센터 및 하이퍼바이저 통제를 제3자 공인 인증 보고서(SOC 2, ISO 27017)로 대체 확인하는 방식.

</details>

- IaaS·PaaS·SaaS별 **공동 책임 분계**
- API로 자원 설정을 확인하는 **CSPM 전수 실사**
- 선언 코드와 실행 상태를 비교하는 **IaC 드리프트 검증**
- 고객 관리 키로 통제하는 **KMS 봉투 암호화**
- 인증 보고서로 CSP 통제를 보는 **간접 감사**
- 장애 주입으로 확인하는 **Multi-AZ 복원력**
- 이관과 파기를 포함하는 **출구 전략**

#### 한줄 요약
- 책임 분계, CSPM, IaC, 고객 키, 복원력, 출구 전략이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Multi-AZ 복원력**: 특정 가용 영역(AZ)의 전면 장애 시에도 타 가용 영역으로 트래픽을 즉시 절체하여 연속성을 보장하는 고가용성 설계.
- **암호학적 영구 파기(Crypto-shredding)**: 대용량 클라우드 스토리지 데이터를 물리적으로 덮어쓰는 대신, 복호화에 필요한 마스터 암호화 키를 파기하여 복원을 불가능하게 만드는 기술.
- **VPC(Virtual Private Cloud)**: 퍼블릭 클라우드 인프라 내에서 고객 전용으로 완전히 격리된 가상 네트워크 환경.

</details>

```text
[클라우드 감리 체계]
├── [책임·거버넌스]
│   ├── 서비스 모델
│   ├── RACI 및 SLA
│   └── 제3자 인증 보고서
├── [IAM·네트워크]
│   ├── 최소 권한 및 MFA
│   └── VPC 및 보안그룹 통제
├── [데이터·형상]
│   ├── KMS 봉투 암호화
│   └── IaC 및 드리프트 관리
└── [복원력·출구]
    ├── Multi-AZ 복원력
    ├── 백업 및 무중단 이관
    └── 암호학적 영구 파기
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 책임·거버넌스 | CSP·이용자 책임과 SLA 확정 |
| IAM·네트워크 | 접근 권한과 통신 경계 통제 |
| 데이터·형상 | 암호화 키와 IaC 일치성 검증 |
| 복원력·출구 | 장애 복구와 이전·파기 가능성 검증 |

#### 한줄 요약
- 책임·거버넌스 영역이 맨 앞에서 CSP와 이용자의 분계를 확정해야 뒤의 세 영역에서 무엇을 직접 실사하고 무엇을 인증 보고서로 갈음할지가 정해지며, 복원력·출구 영역은 계약 종료 시점에야 드러나는 종속 비용을 사전 검증으로 앞당긴다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **CSPM(Cloud Security Posture Management)**: 클라우드 API를 통해 가상머신, 스토리지, IAM 등의 보안 설정 오류와 컴플라이언스 위반을 지속 점검하는 보안 도구.

</details>

```text
[클라우드 서비스 감리 프로세스] (① 책임경계확정 ➔ ② CSP인증검증 ➔ ③ 설정권한실사 ➔ ④ IaC복원력시험 ➔ ⑤ 출구전략검증)
├── 1. 서비스 모델·책임 경계 확정 (IaaS/PaaS/SaaS 모델별 CSP와 이용자 간 RACI 및 SLA 확정)
├── 2. CSP 인증·SLA 검증 (ISO 27017/27018 및 SOC 보고서 범위·유효기간 간접 확인)
├── 3. 이용자 설정·권한 실사 (CSPM 도구 연동 ➔ IAM 최소 권한·VPC 보안그룹·S3 버킷 공개 전수 실사)
├── 4. IaC·KMS·복원력 시험 (코드형 인프라 드리프트 탐지 + 고객 관리 키 봉투 암호화 + Multi-AZ 절체 실측)
└── 5. 데이터 이관·파기 검증 (표준 형식 데이터 추출·백업 실증 ➔ 암호학적 영구 파기 절차 확인)
```

- 분기 결과: 이용자 책임 영역 무결성 및 출구 전략 실증 시 감리 승인, 보안 오설정 및 종속 위험 식별 시 개선권고 발행

#### 한줄 요약
- CSP 통제는 인증 보고서로 간접 확인하고 이용자 설정은 API 전수 실사로 직접 확인하는 지점에서 갈리며, 보고서의 범위와 예외를 짚지 않으면 감사 불가 영역이 사고 후 책임 공방 비용으로 되돌아온다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **BYOK(Bring Your Own Key)**: CSP의 기본 암호화 키 대신 고객이 직접 온프레미스 HSM 등에서 생성하고 통제하는 마스터 키를 클라우드로 가져와 사용하는 방식.

</details>

| 비교 항목 | IaaS 감리 | PaaS 감리 | SaaS 감리 |
|:---|:---|:---|:---|
| 이용자 책임 | **가장 넓은 범위** | 애플리케이션·데이터 중심 | 계정·데이터 중심 |
| 주요 대상 | OS·VPC·스토리지 | 런타임·관리형 DB·API | 권한·테넌트·데이터 |
| 설정 위험 | 패치·포트·버킷 공개 | 플랫폼 파라미터·인증 | 과도 권한·격리 실패 |
| 암호화 통제 | 볼륨·객체의 고객 키 | 관리형 저장소의 고객 키 | BYOK 지원 여부 |
| 출구 난도 | 이미지·데이터 이전 | 런타임·DB 변환 | **전용 형식 종속** |

#### 한줄 요약
- 서비스 추상화가 높을수록 이용자 책임은 줄고 출구 통제는 중요해진다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **GitOps**: 인프라와 애플리케이션의 모든 설정을 Git 저장소에 코드로 관리하고 변경 사항을 클라우드에 자동 동기화하는 운영 패러다임.
- **벤더 종속(Vendor Lock-in)**: 특정 CSP의 독점 API나 전용 서비스에 과도하게 의존하여 타 클라우드로 전환할 때 천문학적인 비용과 기술적 장벽이 발생하는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| CSP 인증을 이용자 보안까지 확대 해석 | 책임 경계별 **통제 소유자** 확인 | **책임 혼선** 방지 |
| 공개 스토리지·과도한 IAM 권한 | CSPM 기반 **설정 전수 점검** | **설정 결함** 차단 |
| 콘솔 변경에 따른 IaC 불일치 | GitOps 기반 **드리프트 탐지·복구** | **형상 정합성** 유지 |
| 고객 키의 권한 집중과 복구 불가 | 키 분리·백업·회전의 **KMS 통제** | **암호 키** 가용성 |
| 독점 API·데이터 형식의 종속 | 표준 형식의 **이관·복원 훈련** | **벤더 종속** 탈피 |

#### 한줄 요약
- 책임 소유, CSPM, 드리프트, 키 관리, 이관 훈련으로 위험을 통제한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **ISO/IEC 27017**: 클라우드 서비스 제공자(CSP)와 이용자(CSC) 각각에 요구되는 정보보호 통제 항목을 정의한 국제 클라우드 보안 표준.
- **Policy-as-Code**: 인프라 보안 수칙과 아키텍처 규칙을 코드로 작성하여 배포 파이프라인에서 자동으로 위반 여부를 검증하는 기술.
- **출구 전략(Exit Strategy)**: 서비스 계약 만료 또는 벤더 장애 발생 시 데이터와 워크로드를 안전하게 회수하여 타 인프라로 이전하기 위한 사전 대책.

</details>

- **기술 위상/발전**: CSP와 이용자 간 공동 책임을 명확히 분계하고 이용자 통제 영역의 보안·복원력·데이터 주권을 객관적으로 검증하는 **클라우드 전문 감리 표준**으로 확립되었으며, Policy-as-Code 기반 자동화 및 멀티 클라우드 지속적 감사로 진화 중
- **실무 적용/통제**: CSP 인증서 맹신을 탈피한 **API 기반 CSPM 전수 실사**, IaC 템플릿과 런타임 자원 간 형상 불일치(Drift) 차단, 벤더 종속(Lock-in) 탈출을 위한 **표준 데이터 이관 및 암호학적 영구 파기(Crypto-shredding)** 출구 전략 검증 필수

#### 한줄 요약
- CSP 인증과 별개로 고객 설정·키·복구·출구 능력을 입증해야 한다.
