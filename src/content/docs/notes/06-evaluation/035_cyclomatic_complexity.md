## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **매케이브 순환 복잡도(McCabe's Cyclomatic Complexity, $V(G)$)**: 프로그램의 제어 흐름 그래프(CFG: Control Flow Graph) 상에서 선형적으로 독립적인 실행 경로(Linearly Independent Paths)의 개수를 측정하여, 소프트웨어 모듈의 논리적 복잡도(Complexity), 유지보수 난이도, 그리고 모든 기본 경로를 100% 검증하기 위해 요구되는 최소한의 화이트박스 단위 테스트 케이스 수를 정량화하는 구조적 코드 품질 지표.
- **제어 경로 폭증에 따른 스파게티 코드 및 회귀 결함(Control Explosion & Untestable Code Defect)**: 수십 개의 `if-else`, `switch-case`, `for/while` 반복문이 5단계 이상 깊게 중첩되어 프로그램의 실행 경로가 수천 개로 폭증함으로써, 개발자가 테스트 케이스를 설계할 수 없어 잠재 버그가 은폐되고 코드 수정 시마다 연쇄적인 회귀 장애(Regression Bug)가 발생하는 구조적 결함.

</details>

- 정의/개념: CFG의 독립 경로 수를 재는 **순환 복잡도 $V(G)$** 지표
- 배경/필요성: 단순 코드 라인 수(LOC) 지표는 동일한 길이의 코드라도 다중 중첩 `if-else`, `switch-case`, 반복문으로 인해 실행 제어 경로가 기하급수적으로 폭증하는 논리적 난이도를 측정하지 못하여, 단위 테스트 케이스의 최소 필요 수량을 예측하지 못하고 스파게티 코드로 인한 잠재 결함 은폐 및 극심한 유지보수 비용을 초래하는 구조적 한계가 발생함에 따라, 토마스 매케이브의 그래프 이론에 기반하여 제어 흐름 그래프(CFG)의 선형 독립 경로 수를 수식($V(G) = E - N + 2P = \pi + 1$)으로 도출하는 순환 복잡도(Cyclomatic Complexity)를 도입하여 **화이트박스 기본 경로 테스팅(Basis Path Testing)에 요구되는 최소 테스트 케이스 수 정량화, 고복잡도 모듈($V(G) > 10$)의 사전 식별 및 메서드 분할 리팩토링 기준 확립**을 달성할 필요

#### 한줄 요약
- 순환 복잡도 $V(G)$는 제어 흐름의 독립 경로 수를 산출하여 화이트박스 기본 경로 테스트 케이스 수와 리팩토링 기준을 제시한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **선형 독립 경로(Linearly Independent Path)**: 기존에 식별된 경로들에서는 한 번도 통과하지 않았던 새로운 간선(Edge)을 최소한 1개 이상 포함하는 고유한 실행 궤적 (다른 경로들의 선형 결합으로 표현 불가).
- **기본 경로 집합(Basis Path Set)**: 프로그램 내의 모든 실행 가능한 경로를 선형 결합으로 만들어낼 수 있는 최소한의 독립 경로들의 기저(Basis) 집합 (크기 $= V(G)$).

</details>

- 노드·간선·분기점으로 산출하는 **그래프 기반 복잡도**
- 독립 경로 수와 일치하는 **기본 경로 테스트 하한**
- 복잡도가 높을수록 커지는 **유지보수·결함 위험**

#### 한줄 요약
- 그래프 위상수학 기반, 기본 경로 테스트 케이스 하한선 제시, $V(G) \le 10$ 품질 임계치 관리, 결함 밀도 예측을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **순환 복잡도 $V(G)$ 3대 산출 공식**:
  1. **간선과 노드 공식**: $V(G) = E - N + 2P$ ($E$: 간선 수, $N$: 노드 수, $P$: 연결 성분/함수 수, 단일 함수 $P=1$ 시 $V(G) = E - N + 2$).
  2. **조건 분기점(Predicate Node) 공식**: $V(G) = \pi + 1$ ($\pi$: 2방향 조건 분기점의 수).
  3. **평면 그래프 닫힌 영역(Region) 공식**: $V(G) = R$ ($R$: CFG 평면 분할 영역의 수 = 닫힌 영역 수 + 외부 영역 1개).

</details>

```text
[순환 복잡도 V(G) 산정 체계]
├── [3대 산출 공식]
│   ├── [간선·노드] V(G) = E - N + 2P
│   ├── [분기점] V(G) = π + 1
│   └── [평면 영역] V(G) = R
├── [기본 경로 테스팅]
│   └── V(G)개 선형 독립 경로 도출
└── [위험 등급 및 관리 기준]
    ├── 1 ~ 10 (안정적 구조, 권장)
    ├── 11 ~ 20 (보통 복잡, 리팩토링 권고)
    ├── 21 ~ 50 (고위험, 즉시 함수 분할)
    └── > 50 (테스트 불가, 전면 재작성)
```

- 선들의 의미:
  - `──`: 지표 체계 및 연계
  - `├──`, `└──`: 산출 공식 및 관리 기준 분기

| 구성요소 | 책임 |
|:---|:---|
| 기본 블록 노드 $N$ | 분기 없는 순차 코드 블록 표현 |
| 제어 전이 간선 $E$ | 노드 사이의 제어 이동 표현 |
| 조건 분기점 $\pi$ | 참·거짓의 분기 수 산출 |
| 연결 성분 $P$ | 독립된 CFG 개수 반영 |
| 평면 영역 $R$ | CFG의 독립 영역 수 산출 |

#### 한줄 요약
- 세 공식이 같은 $V(G)$를 간선·분기점·평면 영역에서 도출하며, 산출된 수치는 기본 경로 테스트 케이스 수와 리팩토링 위험 등급 판정에 직결된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **기본 경로 테스팅 및 복잡도 리팩토링 5단계 프로세스**:
  1. 정적 분석 도구(SonarQube, ESLint)를 통해 함수별 CFG 및 순환 복잡도 $V(G)$ 자동 계측
  2. 도출된 $V(G)$ 수치에 따라 선형 독립 경로 집합(Basis Path Set) 3~5개 정의
  3. 각 독립 경로를 최소 1회 관통하는 단위 테스트 케이스(JUnit) 작성
  4. $V(G) > 10$을 초과하는 고위험 복합 함수에 대해 메서드 추출(Extract Method) 리팩토링 수행
  5. 리팩토링 후 $V(G) \le 10$ 달성 및 기존 단위 테스트 100% 통과(회귀 방어) 검증

</details>

```text
[CFG AST Generation] (① AST 파싱 및 기본 블록 노드(N), 제어 간선(E), 분기점(π) 도출)
└── [Complexity Calculator] (② V(G) = E - N + 2P = π + 1 수식 연산 및 복잡도 판정)
    └── [Basis Path Set Derivation] (③ V(G)개 선형 독립 실행 경로 집합 도출)
        └── [Unit Test Case Designer] (④ 독립 경로 100% 관통 입력 데이터 세트 구성 및 실행)
            └── [Refactoring Governance] (⑤ V(G) > 10 초과 시 단일 책임 원칙(SRP) 기반 함수 분할 리팩토링)

- 분기 결과: V(G) <= 10 충족 시 품질 게이트 통과, V(G) > 10 초과 시 메서드 추출(Extract Method) 분할 후 재측정
```

#### 한줄 요약
- CFG 파싱 후 $V(G)$를 계산해 기본 경로 테스트 스위트를 도출하고, 복잡도 초과 모듈은 메서드 분할로 리팩토링한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **코드 복잡도 3대 평가 지표 비교**:
  - 매케이브 순환 복잡도 (Cyclomatic): 선형 독립 경로 수 (화이트박스 테스트 설계용).
  - 소나 인지 복잡도 (Cognitive): 인간이 코드를 이해하기 난해한 정도 (가독성/리팩토링용).
  - 할스테드 소프트웨어 과학 (Halstead): 연산자와 피연산자의 수량 (코드 볼륨/노력 측정).

</details>

| 비교 항목 | 순환 복잡도 | 인지 복잡도 | 할스테드 복잡도 |
|:---|:---|:---|:---|
| 적용 기준 | 독립 테스트 경로 산정 | 코드의 인지 난이도 판단 | 코드의 토큰 볼륨 측정 |
| 측정 요소 | CFG의 노드·간선 수 | 제어문의 중첩 깊이 | 연산자 및 피연산자 수 |
| 주요 활용 | 기본 경로 테스트 설계 | 가독성 중심 리팩토링 | 개발 노력의 상대 비교 |
| 지표 한계 | 중첩 인지 부하 반영 부족 | 테스트 경로 수 산출 불가 | 제어 흐름 구조 반영 부족 |

#### 한줄 요약
- 순환 복잡도는 기계적 독립 테스트 경로 수, 인지 복잡도는 가독성 인지 부하, 할스테드는 토큰 볼륨을 측정한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **인지 복잡도(Cognitive Complexity)**: 코드의 중첩 깊이와 분기 흐름을 바탕으로 개발자가 코드를 읽고 이해하는 데 드는 인지 부하를 수치화한 지표.
- **응집도(Cohesion)**: 단일 함수나 모듈 내부의 구성 요소들이 하나의 책임과 목적을 위해 집중되어 있는 정도.
- **골든 마스터 테스트(Golden Master Testing)**: 리팩토링 전 시스템의 출력 결과를 기준 스냅샷(Master)으로 삼고, 코드 구조 변경 후 동일한 출력이 나오는지 대조하는 회귀 방어 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 수치만 낮춘 분할로 결합도 증가 | 인지 복잡도 및 응집도 교차 검증 | 의미 있는 단위의 분할 유지 |
| 복합 조건 누락으로 V(G) 과소평가 | 논리 연산자(&&, \|\|)별 분기점 분해 | 기본 경로 누락 방지 |
| 테스트 없는 분할로 회귀 결함 발생 | 골든 마스터 테스트 구축 후 점진 분할 | 기존 비즈니스 동작 무결성 보존 |

#### 한줄 요약
- 인지 복잡도 교차 검증으로 형식적 분할을 막고, 복합 연산자를 분해하며, 골든 마스터 테스트 후 리팩토링한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **순환 복잡도(McCabe's Cyclomatic Complexity, V(G))**: 제어 흐름 그래프(CFG)에서 선형 독립적인 경로 수를 나타내며 최소 테스트 케이스 수를 결정하는 지표.
- **기본 경로 테스팅(Basis Path Testing)**: 순환 복잡도에 상응하는 독립 경로 집합을 도출하여 화이트박스 테스트를 체계적으로 설계하는 방법론.
- **단일 책임 원칙(Single Responsibility Principle, SRP)**: 객체나 함수는 단 하나의 책임만을 가져야 하며, 변경의 이유도 단 하나여야 한다는 소프트웨어 설계 원칙.

</details>

- **기술 위상/발전**: McCabe V(G) 및 기본 경로 테스팅 기반 구조적 복잡도 통제 표준 확립
- **실무 적용/통제**: V(G) <= 10 품질 게이트 관리, 인지 복잡도 교차 검증 및 SRP 기반 메서드 추출 리팩토링

#### 한줄 요약
- 순환 복잡도 계측과 기본 경로 테스팅을 통해 테스트 케이스 하한을 확보하고 구조적 리팩토링을 완성한다.
