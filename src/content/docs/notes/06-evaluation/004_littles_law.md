## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **리틀의 법칙(Little's Law / John D.C. Little 1961)**: 시스템이 정상적인 안정 상태(Steady State)에 있을 때, 시스템 내부에 머무르는 평균 작업 수($L$, 재공량/동시성)는 작업의 평균 유입·처리율($\lambda$, Throughput)과 작업이 시스템 내에 머무르는 평균 체류 시간($W$, Response Time)의 곱($L = \lambda W$)과 항상 일치한다는 대기행렬 수리 법칙.
- **동시성 및 스레드 풀 과소·과대 사이징 결함(Concurrency Mismatch Defect)**: 목표 TPS와 평균 응답시간 간의 수리적 상관관계를 고려하지 않고 임의의 수치로 WAS 스레드 풀이나 부하 시험 가상 사용자(VUser)를 설정하여, 락(Lock) 경합으로 인한 CPU 낭비 또는 스레드 고갈로 인한 요청 누락을 초래하는 구조적 결함.
- **분포 비의존성(Distribution-free Invariance)**: 유입되는 요청의 도착 간격 분포(Poisson, Burst, Long-tail)나 서버의 서비스 시간 분포와 상관없이, 시스템이 작업 유실 없는 안정 상태(Steady State)를 유지하기만 하면 $L = \lambda W$ 관계가 항상 엄밀하게 성립하는 수리적 특성.

</details>

- 정의/개념: 안정 상태에서 평균 작업 수를 **$L=\lambda W$**로 구하는 대기행렬 법칙
- 배경/필요성: 목표 처리량과 체류시간 간의 수리적 관계를 무시한 자원 설정은 스레드 고갈이나 락 경합을 유발하므로, $L = \lambda W$ 항등식에 기반하여 도착·서비스 분포와 무관하게 정확한 동시 작업 수를 산출하고 **Think Time**을 반영한 VUser 및 자원 풀 사이징을 달성할 필요

#### 한줄 요약
- 리틀의 법칙은 안정 상태 시스템에서 평균 작업 수(L)가 처리율(λ)과 체류시간(W)의 곱(L=λW)과 일치함을 규명

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **리틀의 법칙 3대 핵심 구성 변수**:
  - **평균 재공량 ($L$, Work In Process / Concurrency)**: 시스템 내부에서 대기 중이거나 실제 연산 처리 중인 평균 작업(요청) 수.
  - **평균 처리율 ($\lambda$, Throughput / Arrival Rate)**: 단위 시간(초)당 시스템으로 유입되어 처리를 완료하고 배출되는 평균 트랜잭션 수 (TPS).
  - **평균 체류시간 ($W$, Response Time / Lead Time)**: 요청이 큐에 진입한 순간부터 처리가 완료되어 응답을 반환할 때까지의 총 경과 시간.

</details>

- 도착·서비스 분포와 무관한 **분포 비의존성**
- 두 변수로 나머지를 구하는 **상호 역산**
- 응답·생각 시간을 반영한 **VUser** 산정

#### 한줄 요약
- 분포 비의존적 성립, 3대 변수 상호 역산, 성능 시험 VUser 및 자원 풀 사이징 근거 제공

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **리틀의 법칙 3대 적용 영역 및 파생 공식**:
  1. **시스템 전체 레벨**: $L_{sys} = \lambda \times W_{sys}$ (큐 대기 작업 + 서버 연산 작업).
  2. **대기열(Queue) 레벨**: $L_q = \lambda \times W_q$ (순수 큐 대기 작업 수와 대기 시간).
  3. **서비스(Server) 레벨**: $L_s = \lambda \times W_s = \frac{\lambda}{\mu} = \rho$ (서버 가동률/비지 상태 서버 수).

</details>

```text
[리틀의 법칙 수리 체계]
  │
  ├─ [평균 재공량 (L)]
  │   ├─ 시스템 전체 작업 수 (L_sys)
  │   └─ 큐 대기 작업 수 (L_q)
  │
  ├─ [평균 처리율 (λ)]
  │   ├─ 단위 시간당 유입율 (Arrival Rate)
  │   └─ 시스템 배출 처리량 (Throughput)
  │
  └─ [평균 체류시간 (W)]
      ├─ 총 응답시간 (W_sys)
      └─ 큐 대기시간 (W_q)
```

- 선의 의미: 상하 인터페이스 연결(`│`) 및 리틀의 법칙 변수 세부 소속 관계(`├─`, `└─`)를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 평균 작업 수 $L$ | 경계 내부의 **재공량** 표현 |
| 평균 처리율 $\lambda$ | 단위 시간당 완료되는 **처리량** 표현 |
| 평균 체류시간 $W$ | 진입부터 완료까지의 **체류시간** 표현 |

#### 한줄 요약
- 세 파생 공식은 같은 항등식의 적용 경계만 바꾼 것이므로 체류시간 증가가 큐 대기에서 왔는지 서버 연산에서 왔는지를 명확히 분리

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **정상 안정 상태 검증**: 단위 시간당 유입량과 배출량이 통계적으로 균형을 이루어 내부 대기열 길이가 무한 발산하지 않는지 확인하는 선행 단계.
- **Think Time 모델링**: 가상 사용자가 시스템 응답 수신 후 다음 요청을 전송하기까지 대기하는 시간을 반영해 동시성($L$)을 VUser로 변환하는 절차.

</details>

```text
[동시성 및 자원 풀 산정 경로] (진행 ①→④, 관측 역산 및 파라미터 확정)
  │
  ├─ [안정 상태 모니터] (① 유입률과 배출률 평형 상태 검증)
  │
  ├─ [지표 계측기] (② 동일 경계 기준 처리율 λ 및 체류시간 W 측정)
  │
  ├─ [수리 연산 모듈] (③ L=λW 항등식 기반 내부 동시 작업 수 산출)
  │
  └─ [자원 풀 제어기] (④ Think Time 반영 VUser 및 스레드 풀 사이징)
```

분기 결과: 안정 상태에서 L=λW로 최적 스레드 풀 도출하나, 유입률 초과 비안정 상태에서는 큐 적체로 체류시간 W가 발산하므로 부하 제어 선행 필요

#### 한줄 요약
- 같은 처리율에서도 스레드 풀은 체류시간만 반영한 L로, VUser는 생각 시간까지 합산한 값으로 산정해야 자원 낭비와 대기열 폭주 방지

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **성능 엔지니어링 3대 핵심 수리 법칙 비교**:
  - 리틀의 법칙 (Little's Law): 동시성, 처리율, 체류시간 간의 대기행렬 균형 법칙 ($L = \lambda W$).
  - 암달의 법칙 (Amdahl's Law): 병렬 프로세서 확장에 따른 가속 한계 예측 법칙 ($S(N) = \frac{1}{(1-p) + \frac{p}{N}}$).
  - 유니버설 스케일링 법칙 (USL: Universal Scalability Law): 경합과 일관성 오버헤드를 포함한 확장성 한계 법칙.

</details>

| 성능 법칙 | 리틀의 법칙 | 암달의 법칙 | USL |
|:---|:---|:---|:---|
| 적용 기준 | 동시성·체류시간 산정 | 고정 작업의 병렬 가속 산정 | 노드 증설의 확장성 산정 |
| 핵심 특징 | **$L=\lambda W$** 기반 대기열 균형 | **직렬 비율** 기반 가속 상한 | **경합·일관성** 비용 반영 |
| 한계 | 비안정 상태에서 적용 제약 | 통신·동기화 비용 미반영 | 회귀 기반 모수 추정 필요 |

#### 한줄 요약
- 리틀의 법칙은 대기열 동시성, 암달의 법칙은 병렬 가속 한계, USL은 분산 클러스터 확장 한계 모델링에 적용

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **생각 시간(Think Time)**: 사용자가 한 화면의 응답을 수신한 후 다음 요청을 보내기까지 정보를 읽거나 입력하며 머무르는 대기 시간으로, 실제 동시 사용자(VUser) 수 산정 시 필수적인 변수이다.
- **가상 사용자(VUser, Virtual User)**: 성능 부하 시험기에서 실제 사용자의 행동 패턴을 시뮬레이션하여 대상 시스템에 트래픽을 인입시키는 가상의 부하 발생 스레드이다.
- **비안정 상태(Unsteady State)**: 유입률이 처리율을 지속적으로 초과하여 대기열이 무한히 증가하거나 시스템 장애로 평형이 깨진 상태로, 리틀의 법칙 가정 조건이 성립하지 않는다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 생각 시간 누락으로 **VUser** 과소 산정 | 사용자 로그로 **Think Time** 반영 | 실제 동시 사용자 부하 재현 |
| 유입이 배출을 넘는 **비안정 상태** | 평형 구간만 추출해 법칙 적용 | 대기열 발산에 따른 오판 방지 |
| TPS와 ms의 **시간 단위** 불일치 | 응답시간을 초로 환산 | 동시 작업 수 계산 오류 방지 |

#### 한줄 요약
- Think Time 모델링으로 부하를 모사하고, 안정 구간 필터링으로 오판을 막으며, 단위 정합성으로 계산 오류 배제

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **스레드 풀(Thread Pool)**: 미리 생성해 둔 작업 처리 스레드들의 집합으로, 요청마다 스레드를 생성/파괴하는 오버헤드를 줄이고 시스템 내부 동시 작업 수($L$)를 직접 제어한다.
- **정상 안정 상태(Steady State)**: 시스템으로 들어오는 평균 유입률과 나가는 평균 배출률이 동일하여 내부 대기열 길이가 통계적으로 일정하게 유지되는 평형 상태이다.

</details>

- 확률 분포에 구애받지 않고 동시성·처리량·체류시간의 대기행렬 균형을 규명하는 리틀의 법칙은 컨테이너 동시성과 스레드 풀 최적화의 핵심 **수리 엔지니어링 법칙**으로 정착
- 실무 엔지니어는 사용자 행동 로그 기반의 **Think Time**을 반영해 실전형 VUser를 산정하고, 큐 대기($W_q$)와 서버 연산($W_s$)의 계층별 분리 역산을 통해 자원 경합을 방어하는 공학적 설계 기준 수립

#### 한줄 요약
- 리틀의 법칙을 통해 시스템 동시성과 체류시간을 정밀 모델링하고 최적의 스레드 풀 및 VUser 산정 기준 확립
