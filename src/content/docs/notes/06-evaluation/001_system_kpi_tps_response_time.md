## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **시스템 성능 지표(System Performance Key Performance Indicators, System KPI)**: IT 인프라 및 소프트웨어 시스템이 주어진 워크로드 환경에서 비즈니스 요구사항을 충족하며 안정적으로 동작하는지 평가하기 위해 처리 능력(TPS/처리량), 지연 속도(응답시간/레이턴시), 서비스 연속성(가용성/신뢰성)을 정량화한 핵심 평가 척도.
- **평균값의 함정 및 꼬리 지연 은폐 결함(Flaw of Averages & Tail Latency Defect)**: 대규모 분산 환경에서 평균 응답시간(Average Latency)만을 성능 지표로 관리할 경우, 95% 이상의 정상 트래픽에 가려진 상위 1%~5% 사용자(p95, p99)의 극심한 지연(Tail Latency)과 자원 경합에 의한 포화(Saturation) 현상을 조기에 식별하지 못해 대형 장애로 이어지는 구조적 결함.

</details>

- 정의/개념: 처리 용량·지연·연속성을 정량화하는 **시스템 성능 지표** 평가 체계
- 배경/필요성: 대규모 분산 트랜잭션 환경에서 평균 응답시간만을 단일 지표로 관측할 경우 상위 1%~5% 사용자의 극심한 **꼬리 지연**과 자원 경합에 의한 시스템 포화가 은폐되어 서비스 장애로 직결되므로, 처리량(TPS)·지연 백분위수·오류율·가용성을 다차원으로 연계 계측해 에러 예산 기반의 서비스 안정성을 확보할 필요

#### 한줄 요약
- 평균 하나만 계측하면 꼬리 지연과 피크 장애가 은폐되므로, 지표를 다차원으로 확장하는 비용이 사후 장애 수습 비용보다 절감

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- 성능 평가 4대 핵심 축:
  - **TPS (Transactions Per Second)**: 단위 시간(1초)당 비즈니스 거래(DB Commit 완료 기준)를 완수한 건수.
  - **응답시간 (Response Time / Latency)**: 클라이언트가 요청을 송신한 시점부터 최종 응답 바이트를 수신할 때까지의 경과 시간.
  - **처리량 (Throughput)**: 단위 시간당 시스템이 처리하여 전송한 총 데이터량(Bytes/sec) 또는 API 요청 수(RPS).
  - **가용성 (Availability)**: 전체 약정 운영 시간 중 정상적인 서비스 처리가 가능했던 시간의 백분율 ($Availability = \frac{MTBF}{MTBF + MTTR} \times 100\%$).
- **SLI(Service Level Indicator)**: 요청 성공률·p99 지연처럼 서비스 수준을 판정하기 위해 실제로 관측한 계량값으로, SLO 목표치와 비교해 달성 여부와 에러 예산 소진량을 산출한다.

</details>

- 백분위수로 자원 경합에 따른 **꼬리 지연** 추적
- 업무 거래 **TPS**와 단순 호출 RPS를 분리해 왜곡 방지
- 관측치 **SLI**를 SLO·SLA 판정과 에러 예산에 연계

#### 한줄 요약
- 세 특징은 모두 계측 항목 하나를 더 두는 대신 왜곡 하나를 지우는 교환이며, 분리·백분위·계층 연계를 생략하면 지표는 싸지지만 판정이 낙관으로 왜곡

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **SLO(Service Level Objective)**: SLI가 일정 기간 유지해야 할 목표치(예: 월간 요청 성공률 99.9%)로, 운영 팀이 릴리스·증설 판단의 내부 기준으로 삼는 값.
- **SLA(Service Level Agreement)**: SLO 가운데 고객과 계약으로 약정한 수준과 위반 시 배상·크레딧 조건을 묶은 문서로, 통상 내부 SLO보다 완화된 수치로 정해 위약 여유를 둔다.

</details>

```text
[성능 평가 체계]
  │
  ├─ [측정 경계]
  │   ├─ 업무 트랜잭션 정의
  │   └─ 시스템 계층별 측정 범위
  │
  ├─ [핵심 지표]
  │   ├─ TPS 및 처리량 (Throughput)
  │   ├─ 응답시간 및 백분위수 (Latency)
  │   └─ 가용성 (Availability)
  │
  └─ [서비스 수준]
      ├─ 관측 지표 및 목표 (SLI·SLO)
      └─ 고객 약정 및 에러 예산 (SLA)
```

- 선의 의미: 상하 인터페이스 연결(`│`) 및 세부 측정 지표·수준의 소속 관계(`├─`, `└─`)를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 측정 경계 | 업무와 계층별 측정 범위 정의 |
| 핵심 지표 | **TPS**·**응답시간**·**처리량**·**가용성** 산출 |
| 서비스 수준 | **SLI**·**SLO**·**SLA** 달성 여부 판정 |

#### 한줄 요약
- 측정 경계가 지표 산출 앞에 놓여 업무 트랜잭션과 시스템 계층을 갈라 주지 않으면 RPS가 TPS를 대신해 성능이 부풀고, 서비스 수준 계층은 그 관측치를 SLO 달성률로 환산해 사후 SLA 위약 확인을 사전 에러 예산 소진 관리로 대체

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **부하 발생기(Load Generator)**: 대상 시스템에 가상의 동시 사용자와 트랜잭션 부하를 주입하는 성능 시험 도구(JMeter, Locust 등).
- **포화점(Saturation Point)**: 시스템 자원 사용률이 한계에 도달해 요청 증가 시 처리량 증가는 멈추고 큐 대기로 지연만 급증하는 변곡점.

</details>

```text
[시스템 성능 측정 경로] (진행 ①→④, 부하 주입 및 지표 관측 결과 반환)
  │
  ├─ [부하 발생기] (① 목표 동시성 부하 및 트랜잭션 주입)
  │
  ├─ [APM·계측 에이전트] (② 트랜잭션 구간 지연·처리량 실시간 수집)
  │
  ├─ [지표 분석 엔진] (③ p95·p99 꼬리 지연 백분위 분포 산출)
  │
  └─ [SLO 거버넌스 제어기] (④ 목표치 대비 달성률 및 에러 예산 판정)
```

분기 결과: SLO 판정 충족 시 측정 결과를 확정해 용량 계획에 반영하나, 꼬리 지연 위반 시 병목 격리 및 부하 재시험 사이클 비용 추가 발생

#### 한줄 요약
- 평균 지연이 목표를 지켜도 p95·p99 꼬리에서 위반이 잡히면 병목 개선과 재시험 비용을 한 사이클 더 치르므로, 판정 갈래는 평균이 아니라 분포의 꼬리에서 결정

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **MTBF(Mean Time Between Failures)**: 고장 복구 후 다음 고장까지 정상 가동한 시간의 평균으로, 총 가동 시간을 고장 횟수로 나눠 구하며 값이 클수록 고장이 드물다.
- **MTTR(Mean Time To Repair)**: 고장 발생부터 복구 완료까지 걸린 시간의 평균으로, 총 수리 시간을 고장 횟수로 나눠 구하며 가용률 분모의 손실 시간을 결정한다.

</details>

| 비교 항목 | 처리량 / TPS (Capacity) | 응답시간 / 레이턴시 (Speed) | 가용성 / 신뢰성 (Reliability) |
|:---|:---|:---|:---|
| 평가 관점 | 시스템 처리 역량 | 사용자 체감 품질 | 비즈니스 연속성 |
| 핵심 척도 | **TPS**·RPS·bps | 평균·p95·p99 | 가용률·**MTBF**·**MTTR** |
| 측정 공식 | 완료 거래 수를 시간으로 나눈 **TPS** | 대기시간과 서비스시간의 합 | **MTBF**를 고장 주기로 나눈 비율 |
| 주요 한계 | 지연과 오류율 은폐 가능 | 평균 사용 시 **꼬리 지연** 누락 | 단기 측정 시 신뢰성 왜곡 |
| 병목 징후 | 부하 증가에도 TPS 포화 | p95·p99 지연 급증 | **MTTR**·에러 예산 증가 |

#### 한줄 요약
- 세 축은 상충 관계를 형성하므로, 어느 축의 위반이 비즈니스에 가장 큰 피해를 주는지에 따라 우선순위 결정

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Google SRE 4대 황금 신호 (Golden Signals)**: 레이턴시(Latency), 트래픽(Traffic), 오류(Errors), 포화도(Saturation) 네 지표를 서비스마다 우선 계측해 사용자 체감 장애를 빠짐없이 포착하는 모니터링 기본 집합.
- **에러 예산(Error Budget)**: SLO가 허용하는 실패 비율(1−SLO)을 기간 단위 소진량으로 환산해, 잔여분이 남아 있으면 릴리스를 진행하고 소진되면 배포를 동결해 신뢰성과 변경 속도를 맞바꾸는 관리 장치.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| RPS·TPS 혼용으로 DB 부하 과소평가 | 거래 기준 **TPS**·RPS 분리 측정 | 실제 처리 용량 검증 |
| 평균값이 상위 요청의 **꼬리 지연** 은폐 | p95·p99를 **황금 신호** 지연 **SLI**로 등록 | 극단 지연 조기 식별 |
| 평균 가용률이 피크 중단 피해 은폐 | 피크 가중치와 **에러 예산** 적용 | 핵심 시간대 릴리스 통제 |

#### 한줄 요약
- 세 대책은 계측 항목을 하나 더 두는 비용으로 낙관적 오판 하나를 지우는 교환이며, 도입 순서는 은폐된 피해가 어디서 가장 비싼지로 결정

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **OpenTelemetry**: 분산 시스템의 추적(Traces), 지표(Metrics), 로그(Logs)를 벤더 중립적으로 수집하고 내보내는 CNCF 오픈소스 관찰성(Observability) 프레임워크.
- **AIOps (Artificial Intelligence for IT Operations)**: 빅데이터와 머신러닝 알고리즘을 IT 운영 데이터에 적용하여 이상 징후를 자동 탐지하고 근본 원인을 분석하는 지능형 운영 체계.
- **SLM (Service Level Management)**: 서비스 제공자와 수용자 간에 합의된 서비스 수준(SLA)을 유지하고 개선하기 위해 모니터링, 리포팅, 보상 절차를 체계적으로 관리하는 활동.

</details>

- 처리 용량·지연·연속성을 다차원으로 계측하는 시스템 성능 평가는 평균값의 왜곡을 방어하고 상위 꼬리 지연을 관리하는 엔터프라이즈 **SRE 서비스 수준 지표**의 핵심 엔지니어링 표준으로 정착
- 실무 엔지니어는 단순 RPS가 아닌 DB 커밋 기준 **순수 TPS**를 엄격히 분리 계측하고, p99 지연 기반 SLI와 에러 예산 소진율에 따른 배포 자동 동결 정책을 결합한 통합 거버넌스 체계 확립

#### 한줄 요약
- 지표 선택 시 단순 평균을 지양하고 p99 꼬리 지연과 에러 예산을 결합한 다차원 성능 관리 체계 확립
