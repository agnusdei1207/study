## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **성능 테스트 4대 핵심 유형(Performance Testing Types)**: 소프트웨어 시스템이 운영 환경에서 직면할 수 있는 다양한 트래픽 조건(정상 피크, 한계 초과, 장시간 가동, 순간 폭주)을 인위적으로 모사하여 처리량(TPS), 응답시간(p99 지연), 파괴점(Break Point), 자원 누수(Memory Leak), 그리고 장애 복원력(Resilience)을 입체적으로 검증하는 성능 엔지니어링 방법론.
- **단일 부하 시험 편향에 따른 잠재 결함 은폐 결함(Single Load Test Blind Spot Defect)**: 1~2시간 동안의 단순 부하 테스트(Load Test)만을 통과한 후 상용 배포했을 때, 며칠 뒤 메모리 누수로 서버가 다운(Soak 미수행)되거나 대규모 이벤트 시 순간 트래픽 폭증으로 오토스케일링이 반응하기도 전에 클러스터 전체가 연쇄 붕괴(Spike/Stress 미수행)되는 구조적 결함.

</details>

- 정의/개념: 부하 강도와 지속시간별 **용량·한계** 검증 시험 및 장기 부하와 순간 폭주에 대한 **내구성·복원력** 종합 검증 체계
- 배경/필요성: 단순 부하 테스트만 통과 후 배포할 경우 장시간 누적되는 메모리 누수나 순간 폭주 트래픽에 의한 클러스터 붕괴를 사전에 방어하지 못하므로, 부하 강도와 지속시간을 축으로 부하·스트레스·소크·스파이크를 결합해 **피크 용량(SLO)**과 파괴점 및 장애 복원력을 종합 검증할 필요

#### 한줄 요약
- 성능 테스트는 부하, 스트레스, 소크, 스파이크 시험을 통해 용량과 복원력을 종합 검증

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **4대 성능 테스트 핵심 목적 및 부하 프로파일**:
  - **부하 테스트 (Load Testing)**: 예상되는 최대 피크 트래픽 환경에서 SLO(예: 3,000 TPS, p99 < 500ms) 충족 여부 확인.
  - **스트레스 테스트 (Stress Testing)**: 시스템이 견딜 수 있는 최대 한계(Knee Point)와 완전 붕괴(Break Point) 지점 탐색.
  - **소크 테스트 (Soak / Endurance Testing)**: 24시간~72시간 동안 일정 부하를 연속 주입하여 메모리/커넥션 누수 색출.
  - **스파이크 테스트 (Spike Testing)**: 0에서 피크의 3~5배 부하를 수 초 만에 인가하여 서킷 브레이커 및 복구력 검증.

</details>

- 강도·지속시간 조합으로 구분하는 **4대 부하 프로파일**
- 처리량 둔화와 오류 급증을 구분하는 **Knee·Break Point**
- 폭주 종료 후 정상 응답 복귀를 측정하는 **복원력**

#### 한줄 요약
- 부하·스트레스·소크·스파이크의 다각적 조합, 한계 파괴점 식별, 자가 회복력 검증 제공

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **성능 테스트 4대 아키텍처 및 부하 곡선 패턴**:
  1. **Load Test Curve**: 점진적 증가(Ramp-up) $\rightarrow$ 피크 부하 유지(Plateau) $\rightarrow$ 종료.
  2. **Stress Test Curve**: 한계 도달 시까지 지속적 계단식 증가(Step-up) $\rightarrow$ 붕괴 관측.
  3. **Soak Test Curve**: 기준 부하(70~80%)로 장시간(24~72시간) 플랫(Flat) 유지.
  4. **Spike Test Curve**: 평시 부하 $\rightarrow$ 수직 상승(Spike) $\rightarrow$ 급강하 $\rightarrow$ 정상 회복 관측.

</details>

```text
[성능 테스트 4대 유형 체계]
  │
  ├─ [용량 검증 (Load)]
  │   └─ 피크 트래픽 환경 및 목표 SLO 충족 검증
  │
  ├─ [한계 탐색 (Stress)]
  │   └─ 계단식 과부하 및 Knee / Break Point 식별
  │
  ├─ [내구성 검증 (Soak)]
  │   └─ 24~72시간 지속 부하 및 메모리 누수 탐지
  │
  └─ [복원력 검증 (Spike)]
      └─ 순간 폭주 트래픽 및 오토스케일링·복구력 검증
```

- 선의 의미: 상하 인터페이스 연결(`│`) 및 4대 테스트 유형 세부 소속 관계(`├─`, `└─`)를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 부하 테스트 | 예상 피크에서 **SLO** 충족 여부 검증 |
| 스트레스 테스트 | 처리 한계와 **붕괴 지점** 탐색 |
| 소크 테스트 | 장시간 **자원 누수**와 성능 저하 탐지 |
| 스파이크 테스트 | 순간 폭주 대응과 **정상 복귀** 검증 |

#### 한줄 요약
- 네 시험은 부하 곡선의 강도 축과 지속시간 축을 다르게 설계하므로, 두 축을 모두 검증해야 장기 누수와 순간 장애 방어 가능

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Knee Point(무릎점)**: 부하 증가 시 처리량 증가율이 둔화되고 응답 지연이 급격히 늘어나기 시작하는 자원 포화 변곡점.
- **Break Point(파괴점)**: 시스템이 과부하를 견디지 못하고 프로세스 충돌, 커넥션 단절, 에러율 급증과 함께 서비스가 중단되는 붕괴 한계점.

</details>

```text
[성능 테스트 수행 경로] (진행 ①→④, 부하 프로파일 인가 및 위험 검증)
  │
  ├─ [부하 시험기] (① 목표 피크 부하 주입 및 SLO 충족 검증)
  │
  ├─ [스트레스 인젝터] (② 계단식 과부하 인가로 Knee·Break Point 탐색)
  │
  ├─ [소크 모니터] (③ 24~72시간 지속 부하 주입 및 메모리 누수 감지)
  │
  └─ [스파이크 시험기] (④ 순간 폭주 부하 인가 및 서킷 브레이커 복원력 측정)
```

분기 결과: 피크 검증만으로 출시 시 장시간 누수와 순간 폭주에 무방비 노출되므로, 네 가지 부하 프로파일을 입체적으로 연계해 파괴점과 복원력 동시 확보

#### 한줄 요약
- 목표 성능·처리 한계·장기 누수·순간 복구 중 검증할 위험에 따라 4대 시험 프로파일을 단계별 적용

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **성능 테스트 4대 유형 비교**:
  - Load: 목표 SLA 검증 (적합성 확인).
  - Stress: 한계 및 붕괴점 탐색 (강인성 확인).
  - Soak: 장시간 자원 누수 검증 (내구성 확인).
  - Spike: 트래픽 급증 및 복원력 검증 (탄력성 확인).

</details>

| 비교 항목 | 부하 테스트 | 스트레스 테스트 | 소크 테스트 | 스파이크 테스트 |
|:---|:---|:---|:---|:---|
| 적용 목적 | **목표 SLO** 충족 확인 | **Knee·Break Point** 탐색 | **자원 누수** 탐지 | **탄력적 복원** 검증 |
| 부하 형태 | **예상 피크** 부하 유지 | 한계까지 **계단식 증가** | **안정 부하** 장시간 유지 | **순간 극한 부하** 인가 |
| 판정 지표 | **TPS·p99 응답시간** | **처리량·오류율** | **메모리·연결 수** 추이 | **정상 회복시간·오류 격리** |

#### 한줄 요약
- 부하는 목표 적합성, 스트레스는 파괴 한계, 소크는 장기 내구성, 스파이크는 순간 복원력을 입증

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **트랜잭션 믹스(Transaction Mix)**: 실제 운영 환경에서 발생하는 조회, 등록, 수정, 삭제 등 다양한 업무 트랜잭션의 발생 비율을 시험 시나리오에 동일하게 조합한 모델이다.
- **부하 발생기(Load Generator)**: 대상 시스템에 가상의 동시 사용자와 트래픽을 주입하는 시험 도구로, 도구 자체의 CPU/네트워크 포화로 인한 측정 왜곡을 방지해야 한다.
- **데이터 볼륨(Data Volume)**: 성능 시험 DB에 적재된 데이터의 총량으로, 운영 환경과 동급 규모를 구성해야 실제 인덱스 트리 깊이와 디스크 I/O 병목을 재현할 수 있다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단일 API 반복으로 **트랜잭션 경합** 누락 | 운영 로그 기반 **트랜잭션 믹스** 재현 | **운영 병목** 식별 |
| 부하 발생기 포화로 **측정 왜곡** 발생 | 발생기 자원과 **주입률** 동시 감시 | **대상 병목**과 분리 |
| 축소 데이터로 **I/O 지연** 과소평가 | 운영 동급 **데이터 볼륨** 구성 | **인덱스·I/O** 검증 |

#### 한줄 요약
- 트랜잭션 믹스로 실 부하를 모사하고, 부하 도구 포화를 방어하며, 운영 동급 데이터 볼륨으로 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **카오스 엔지니어링(Chaos Engineering)**: 운영 환경이나 스테이징 환경에 인위적으로 인프라 장애나 지연을 주입하여 시스템의 복원력과 결함 허용성을 사전에 검증하는 기법이다.
- **서킷 브레이커(Circuit Breaker)**: 외부 서비스 장애나 지연 발생 시 연쇄 장애를 막기 위해 호출을 즉시 차단하고 사전에 정의된 대체 로직을 반환하는 격리 패턴이다.
- **복구 시간(Recovery Time)**: 스파이크 등의 과부하나 일시 장애 상황이 해소된 후 정상적인 응답시간과 처리량으로 복귀하는 데 걸리는 시간이다.

</details>

- 다양한 트래픽 조건과 극한 부하 환경을 사전에 시뮬레이션하여 용량 한계와 복원력을 입증하는 성능 테스트는 품질 게이트 자동화의 핵심 **품질 엔지니어링 표준**으로 정착
- 실무 엔지니어는 운영 로그 기반의 **트랜잭션 믹스**를 재현하고, 24시간 이상 소크 테스트를 통한 누수 검증과 스파이크 인가 후 서킷 브레이커 정상 복귀 시간 평가를 결합한 종합 검증 체계 확립

#### 한줄 요약
- 4대 성능 테스트 유형의 입체적 연계를 통해 시스템 처리 용량과 장애 복원력을 체계적으로 확보
