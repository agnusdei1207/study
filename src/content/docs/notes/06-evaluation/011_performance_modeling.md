## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **성능 모델링(Performance Modeling / Capacity Planning & Architecture Evaluation)**: 시스템을 실제로 구현하거나 대규모 하드웨어를 구매하기 전에, 소프트웨어 컴포넌트의 동작 구조, 자원 요구량, 트래픽 워크로드를 수학적 수식(분석적 모델) 또는 컴퓨터 시뮬레이션(이산 사건 시뮬레이션)으로 추상화하여, 다양한 아키텍처 설계 대안별 처리량(TPS), 응답시간(Latency), 자원 가동률, 병목 지점을 정량적으로 사전 예측하는 성능 엔지니어링 기법.
- **사후 병목 발견에 따른 아키텍처 전면 재작성 결함(Post-deployment Redesign Defect)**: 시스템 구축 완료 후 상용 배포 단계에서 뒤늦게 구조적 락(Lock) 경합이나 대역폭 병목에 의한 SLA 위반을 발견하여, 하드웨어 증설로도 해결되지 않아 전체 시스템 아키텍처를 수십억 원을 들여 재설계해야 하는 구조적 결함.

</details>

- 정의/개념: 아키텍처 설계 단계에서 성능 리스크를 선제 제거하기 위해 **워크로드 프로파일링 $\rightarrow$ 분석적 큐잉 네트워크(QN/LQN) 또는 이산 사건 시뮬레이션(DES) 모델 구축 $\rightarrow$ 실측치 기반 모형 보정(Model Calibration) $\rightarrow$ 가상 부하 시나리오별 대안 성능 예측 $\rightarrow$ 민감도 분석(Sensitivity Analysis) 기반 최적 아키텍처 및 자원 스펙 확정** 을 집행하는 **선제적 성능 예측 공학 체계**
- 배경/필요성: 시스템 구축 완료 후 상용 배포 단계에서 뒤늦게 소프트웨어 내부의 락(Lock) 경합, 스레드 풀 고갈, 네트워크 대역폭 병목에 의한 심각한 응답 지연을 발견할 경우 단순 하드웨어 증설만으로는 해결되지 않아 수십억 원의 아키텍처 전면 재설계 비용이 발생하는 구조적 결함이 발생함에 따라, 큐잉 네트워크(QN/LQN) 기반의 분석적 모델(Analytical Model)과 이산 사건 시뮬레이션(DES)을 융합하는 성능 모델링 체계를 도입하여 **구현 전 아키텍처 대안별 처리량(TPS)과 p99 지연시간의 정밀 사전 예측, What-If 시나리오 기반 소프트웨어·하드웨어 경합 사전 해소 및 인프라 투자 비용 최적화**를 달성할 필요

#### 한줄 요약
- 성능 모델링은 큐잉 네트워크와 시뮬레이션을 통해 시스템 구축 전 처리량과 지연시간을 수학적으로 예측한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **성능 모델링 2대 핵심 접근 방식**:
  - **분석적 모델 (Analytical Models)**: 큐잉 이론(MVA, 잭슨 네트워크)을 기반으로 폐쇄형/개방형 수식을 통해 평균 성능 상태를 신속하게 계산.
  - **시뮬레이션 모델 (Simulation Models)**: 이산 사건 시뮬레이션(DES)을 통해 시간의 흐름에 따른 큐의 동적 변화, 버스트 트래픽, 분기 조건을 정밀 모사.

</details>

- 구현 전에 확장 한계와 병목을 찾는 **사전 검증성**
- 자원 변경 효과를 비교하는 **What-If 분석**
- 소프트웨어·하드웨어 경합을 표현하는 **LQN**

#### 한줄 요약
- 사전 병목 검증, What-If 시나리오 분석, 계층형 큐잉 모델(LQN), 분석/시뮬레이션 상호보완을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **성능 모델링 4대 핵심 아키텍처 컴포넌트**:
  1. **Workload Model (부하 모델)**: 트랜잭션 종류별 도착률($\lambda$), 사용자 생각시간($Z$), 트랜잭션 믹스(Mix).
  2. **Software Contention Model (LQN)**: 프로세스, 스레드 풀, DB Lock, 세마포어 등 논리적 자원 모델.
  3. **Hardware Platform Model**: CPU 코어, 메모리 대역폭, 스토리지 IOPS, 네트워크 레이턴시.
  4. **Solver & Calibration Engine**: MVA 수식 풀이 엔진, 이산 사건 시뮬레이터, 오차 보정기.

</details>

```text
[성능 모델링 체계]
├── [부하 모델 (Workload Model)]
│   └── 트랜잭션 도착률 · 생각시간 · 업무 믹스
├── [소프트웨어 경합 모델 (LQN)]
│   └── 스레드 풀 · 커넥션 풀 · DB 락(Lock)
├── [하드웨어 플랫폼 모델]
│   └── CPU 코어 · 메모리 · 스토리지 IOPS · 대역폭
└── [해석 및 보정 엔진 (Solver)]
    └── MVA 수식 풀이 · DES 시뮬레이션 · 오차 보정
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| Workload Model | 도착률·생각시간·트랜잭션 믹스 정의 |
| Software Contention Model | 스레드·연결 풀·락의 논리 경합 표현 |
| Hardware Platform Model | CPU·메모리·IOPS·네트워크 자원 표현 |
| Solver·Calibration Engine | MVA·DES 해석과 실측 오차 보정 |

#### 한줄 요약
- 하드웨어 모델만으로는 CPU·IOPS에 여유가 있는데도 스레드 풀과 락에서 막히는 정체를 설명하지 못해 그 사이에 소프트웨어 경합 모델이 끼어들며, 이 경합을 모델에서 빠뜨리면 병목은 준공 후 실부하에서야 드러난다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **성능 모델링 및 아키텍처 평가 5단계 엔지니어링 프로세스**:
  1. 목표 비즈니스 요구사항 및 시스템 아키텍처 블록 다이어그램 분석
  2. 소프트웨어 컴포넌트별 소요 시간($t_{service}$) 및 워크로드 파라미터 도출
  3. LQN 계층형 큐잉 모델 구축 및 MVA 수식 해석을 통한 초기 성능 예측
  4. 핵심 프로토타입 실측 데이터와 대조하여 모델 변수 보정(Model Calibration)
  5. 다양한 아키텍처 대안(캐시 도입, DB 샤딩)에 대한 What-If 시뮬레이션 및 최적안 확정

</details>

```text
[요구사항 분석] (목표 TPS 및 SLA 응답시간 정의)
 └── [원단위 계측] (① 컴포넌트별 소요시간 및 워크로드 프로파일링)
      └── [모델링 구축] (② LQN 소프트웨어 경합 및 하드웨어 모델 생성)
           └── [MVA/DES 해석] (③ 수식 해석 및 이산 사건 시뮬레이션 실행)
                └── [What-If 분석] (④ 아키텍처 대안별 병목 식별 및 보정)
                     └── [아키텍처 확정] (⑤ 실측 프로토타입 보정치 기반 스펙 승인)
```

- 분기 결과: 모델 해석치 오차 5% 이내 충족 시 최적 아키텍처 확정, 병목 식별 시 비동기 큐 전환 등 구조 개선안 재모델링.

#### 한줄 요약
- 병목이 외부 결제 PG의 동기 대기일 때 코어를 2배로 늘린 개선안 A는 6,500 TPS로 4.8% 개선에 그치고 비동기로 분리한 B는 12,500 TPS에 이르므로, 갈래는 자원 증설이 아니라 대기 자체를 없앴는지에서 갈린다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **성능 모델링 2대 접근 방식 비교**:
  - 분석적 모델 (Analytical Model: QN, MVA, LQN): 수식 기반 (신속한 처리, 평균 상태 중심).
  - 시뮬레이션 모델 (Simulation Model: DES, Petri-Net): 사건 기반 모사 (정밀, 롱테일 및 동적 상태 중심).

</details>

| 비교 항목 | 분석적 모델 (Analytical Models) | 시뮬레이션 모델 (Simulation Models) |
|:---|:---|:---|
| 핵심 기법 | **큐잉 네트워크 (QN), MVA, LQN** | **이산 사건 시뮬레이션 (DES), 페트리넷** |
| 모델 구축 비용 | **낮음 (수식 및 블록 다이어그램 기반)** | 높음 (전용 시뮬레이션 코드 작성 필요) |
| 연산 실행 시간 | **초 단위 (즉각적인 실시간 해석)** | 수 분 ~ 수 시간 (대량 이벤트 실행 필요) |
| 정밀도 및 범위 | **평균값(Mean) 중심 해석, 분포 단순화** | **백분위수(p99) 및 버스트 트래픽 정밀 모사** |
| 장점 | 수백 개 설계 대안의 신속한 스크리닝 | 복잡한 비선형 로직 및 과도 상태 분석 |
| 단점 | 복잡한 조건 분기 및 롱테일 반영 한계 | 모델 구축 오버헤드 및 디버깅 복잡성 |
| 실무 적용 단계 | **초기 아키텍처 설계 및 대안 비교 단계** | **최종 아키텍처 상세 검증 및 극한 내구 분석** |

#### 한줄 요약
- 분석적 모델은 초기 빠른 대안 스크리닝에, 시뮬레이션 모델은 복잡한 동적 롱테일 정밀 검증에 특화된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **평균값 분석(MVA, Mean Value Analysis)**: 큐잉 네트워크에서 상태 확률을 직접 계산하지 않고 리틀의 법칙을 반복 적용하여 평균 체류시간, 평균 큐 길이, 처리량을 효율적으로 구하는 알고리즘이다.
- **이산 사건 시뮬레이션(DES, Discrete Event Simulation)**: 시간의 연속적 흐름 대신 특정 사건(요청 도착, 서비스 완료)이 발생하는 시점마다 시스템 상태를 갱신해 나가는 시뮬레이션 기법이다.
- **계층형 큐잉 네트워크(LQN, Layered Queueing Networks)**: 클라이언트-서버 간 다계층(Web-WAS-DB) 소프트웨어 호출 구조와 스레드/락 등의 소프트웨어 자원 경합을 하드웨어 자원과 결합하여 모델링하는 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단순 지수분포 가정으로 **롱테일 지연 누락** | MVA 해석 후 **이산 사건 시뮬레이션(DES)** 병행 | **버스트·꼬리 지연** 예측력 확보 |
| 컴포넌트 소요시간 오차로 **50% 이상 괴리** | 핵심 로직 단위 **프로토타입 실측 보정** | **모델 예측 오차** 최소화 |
| HW만 반영하여 **소프트웨어 락 병목 누락** | 논리 자원 경합을 모델링하는 **LQN 강제** | **스레드·락 고갈** 선제 규명 |

#### 한줄 요약
- DES 병행으로 롱테일을 잡고, 프로토타입 실측으로 보정하며, LQN으로 소프트웨어 병목을 식별한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **디지털 트윈(Digital Twin)**: 물리적 시스템이나 소프트웨어 아키텍처의 디지털 복제본을 구성하여 가상의 트래픽을 주입하고 성능 및 장애 복원력을 실시간 시뮬레이션하는 기술이다.
- **What-If 분석**: "만약 트래픽이 3배 증가하거나 특정 노드가 다운된다면?"과 같은 다양한 가상 시나리오를 설정하고 아키텍처 변경의 영향을 사전에 정량적으로 평가하는 분석 방법이다.
- **모델 보정(Calibration)**: 초기 수리 모델의 예측치와 실제 프로토타입 또는 운영 환경의 실측값 간의 오차를 분석하여 모델 파라미터를 역보정하는 튜닝 과정이다.

</details>

- **기술 위상/발전**: 구현 전 소프트웨어·하드웨어 경합과 용량을 수리적으로 검증하는 **선제적 성능 예측 공학 표준**으로 안착, 디지털 트윈 기반 클라우드 시뮬레이션 및 AI 용량 최적화로 확장
- **실무 적용/통제**: 성능 모델링 수행 시 **MVA 기반 신속한 대안 스크리닝과 DES 시뮬레이션 병행**, 스레드 경합을 표현하는 **LQN 계층형 모델 적용** 및 **프로토타입 실측치 기반 모형 보정(Calibration)** 필수

#### 한줄 요약
- 분석적 MVA 모델과 시뮬레이션 DES의 융합을 통해 구축 전 아키텍처 병목을 선제적으로 해소해야 한다.
