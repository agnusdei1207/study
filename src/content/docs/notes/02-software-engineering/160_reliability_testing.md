## 답안 골격
```text
[신뢰성 테스트] ◀━━ 머리: Ⅶ 내 의견 (장기 내구성(Soak) 테스트와 카오스 엔지니어링을 결합한 클라우드 탄력성 검증)
 ┃
 ┣━ Ⅰ 개요 ───── 단기 기능 시험 통과 후 장기 운영 시 메모리 누수·자원 고갈로 다운되는 한계 → 명시된 조건과 기간 동안 고장 없이 동작함을 검증
 ┣━ Ⅱ 특징 ───── ISO/IEC 25010 신뢰성(Reliability) 특성 기반 · 장기 연속 시험 · 고장 허용(Fault Tolerance) 및 복구성(Recoverability) 검증
 ┣━ Ⅲ 구조 ───── 4대 세부 시험 활동: 성숙성(Maturity) / 결함 허용성(Fault Tolerance) / 복구성(Recoverability) / 가용성(Availability)
 ┣━ Ⅳ 흐름 ───── 신뢰도 목표 설정(MTBF, 가용률 99.99%) → 고장 시나리오 설계 → 장기 부하 주입(Soak Test) 및 장애 주입 → 지표 측정 및 검증
 ┣━ Ⅴ 비교 ───── 신뢰성 테스트(장기 무고장 운용) vs 성능 테스트(응답속도/처리량) vs 스트레스 테스트(한계 임계치 파괴)
 ┗━ Ⅵ 실무 ───── 테스트 시간 부족으로 장기 시험 생략 위험 / 복구 시간(MTTR) 단축 / 카오스 몽키(Chaos Monkey) 연계
```
- 필수 키워드: 신뢰성 테스트 · ISO/IEC 25010 · 성숙성 · 결함 허용성 · 복구성(Recoverability) · 가용성 · MTBF · MTTR · 내구성 테스트(Soak Test)
- 배점 전략: 10점 = Ⅰ 정의 → Ⅲ ISO 25010 4대 세부 신뢰성 활동 도식 → Ⅴ 신뢰성 vs 성능 vs 스트레스 비교 / 25점 = Ⅰ~Ⅶ 전개, 133회 기출 테스트 종류 및 신뢰성 테스트 세부 활동 4가지 상세, 정량 지표 산정식(MTBF, MTTR, MTTF)
- 기출: 133회 4교시 2번: "정보시스템 개발과 운영 단계에서 수행되는 소프트웨어 테스트의 종류를 쓰고, 이 중 신뢰성 테스트와 이식성 테스트의 세부 활동에 대하여 각각 설명하시오." → Ⅰ~Ⅵ

## 한 줄 본질
- 1회성 기능 테스트에서는 정상이지만 며칠 동안 가동하면 메모리 누수, 커넥션 풀 고갈, 쓰레드 락으로 시스템이 멈추는 잠재 결함 병목 → 지정된 운영 조건 하에서 시스템이 규정된 기간 동안 무고장으로 서비스를 지속할 수 있는지 검증하는 비기능 테스팅 / 긴 테스트 소요 시간

## 핵심 그림
```text
+-------------------------------------------------------------------------+
|                  ISO/IEC 25010 신뢰성 테스트 4대 세부 활동 및 지표      |
+-------------------------------------------------------------------------+
|                                                                         |
|                          [ 신뢰성 테스트 (Reliability) ]                 |
|                                       │                                 |
|         ┌──────────────────┬──────────┴──────────┬──────────────────┐   |
|         v                  v                     v                  v   |
|  [ 1. 성숙성 시험 ]  [ 2. 결함허용성 시험 ] [ 3. 복구성 시험 ] [ 4. 가용성 ]|
|  - 장기 내구성(Soak) - 하드웨어/SW 결함 시  - 비정상 중단 후    - 서비스     |
|  - 메모리 누수 점검    시스템 계속 가동      데이터 복구 및     가동 시간    |
|  - 누적 결함률 측정  - 이중화 절체(Failover) 서비스 재개 시간    비율(%)      |
|                                                                         |
|  [ 3대 신뢰성 핵심 정량 지표 ]                                          |
|    - MTTF (Mean Time To Failure) : 가동 후 첫 고장까지의 평균 시간      |
|    - MTTR (Mean Time To Repair)  : 고장 발생 후 복구까지 걸리는 평균 시간|
|    - MTBF (Mean Time Between Failures) = MTTF + MTTR                    |
|    * 가용률 (Availability) = MTTF / (MTTF + MTTR) = MTTF / MTBF         |
+-------------------------------------------------------------------------+
```

## 핵심 용어
- 내구성 테스트(Soak/Endurance Testing): 일반적인 부하 수준을 24시간~72시간 이상 중단 없이 지속적으로 주입하여 메모리 누수, 파일 디스크립터 고갈, 버퍼 누적 등 장기적 결함을 탐지하는 시험
- 결함 허용성(Fault Tolerance): 시스템의 일부 컴포넌트나 네트워크 회선에 장애가 발생하더라도, 전체 시스템이 멈추지 않고 저하된 수준(Graceful Degradation)으로 서비스를 유지하는 능력

## 핵심 통찰
- 신뢰성 테스트는 단순히 소프트웨어를 "오래 켜두는 것"이 아니라, 정상 가동 상태에서 인위적으로 DB 연결을 끊거나 파드를 강제 종료시키는 "장애 주입(Fault Injection)"을 병행하여 복구 메커니즘을 때려보는 활동임
- 고장을 100% 막는 것(MTTF 증가)은 한계가 있으므로, 현대 클라우드 아키텍처에서는 고장이 나더라도 몇 초 만에 자동으로 컨테이너를 재기동하여 복구하는 "MTTR(평균 복구 시간) 최소화"가 신뢰성 시험의 핵심 관점으로 이동함
- 넷플릭스 주도의 카오스 엔지니어링(Chaos Engineering)은 이 신뢰성 테스트를 테스트 환경에 국한하지 않고 운영 환경에서 상시 무작위로 실행하여 시스템의 회복 탄력성(Resilience)을 실증함

## 이웃 토픽과 구분
- 신뢰성 테스트 vs 가용성 테스트: 신뢰성 = 고장 없이 연속으로 동작할 수 있는 지속 시간(MTBF 중심) / 가용성 = 전체 계획된 운영 시간 중 사용자가 시스템을 사용할 수 있는 시간 비율(가용률 99.99% 중심)
