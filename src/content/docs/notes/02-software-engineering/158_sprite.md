## 답안 골격
```text
[스프라이트(Sprite)] ◀━━ 머리: Ⅶ 내 의견 (CSS 스프라이트 자동화 빌드 파이프라인과 WebP·SVG 아이콘 폰트 전환을 통한 웹 성능 최적화)
 ┃
 ┣━ Ⅰ 개요 ───── 수십 개의 개별 아이콘 요청으로 인한 HTTP 왕복 지연(RTT) 및 오버헤드 → 복수 이미지를 한 장의 큰 시트로 병합
 ┣━ Ⅱ 특징 ───── HTTP 요청 수 최소화(단일 전송) · 네트워크 왕복 시간(RTT) 단축 · CSS 좌표 기반(`background-position`) 슬라이싱
 ┣━ Ⅲ 구조 ───── 스프라이트 시트(Sprite Sheet: 통합 이미지) + 좌표 정의(X, Y 오프셋) + 컨테이너 크기(Width, Height)
 ┣━ Ⅳ 흐름 ───── 개별 아이콘 에셋 수집 → 단일 텍스처 아틀라스(스프라이트 시트) 패킹 → CSS 클래스별 오프셋 매핑 → 브라우저 캐싱 렌더링
 ┣━ Ⅴ 비교 ───── CSS 스프라이트(단일 비트맵) vs SVG 스프라이트(벡터 심볼) vs 아이콘 폰트(Icon Font)
 ┗━ Ⅵ 실무 ───── 수작업 좌표 관리의 비효율 / 이미지 변경 시 전체 캐시 무효화 / 빌드 도구(webpack-spritesmith) 자동화
```
- 필수 키워드: 스프라이트 · CSS 스프라이트 · 스프라이트 시트 · HTTP 요청 감소 · RTT 단축 · `background-position` · 텍스처 아틀라스 · WebP
- 배점 전략: 10점 = Ⅰ 정의 → Ⅲ 스프라이트 시트 및 CSS 좌표 매핑 도식 → Ⅴ CSS 스프라이트 vs SVG 스프라이트 비교 / 25점 = Ⅰ~Ⅶ 전개, 122회 기출 스프라이트 기술 메커니즘, HTTP/1.1 vs HTTP/2 환경에서의 성능 영향 및 현대적 전환
- 기출: 122회 1교시 `웹 성능 최적화를 위한 이미지 스프라이트(Image Sprite)의 개념 및 동작 원리` → Ⅰ~Ⅵ

## 한 줄 본질
- 웹 페이지에서 수십 개의 작은 버튼, 아이콘, 로고 이미지를 각각 개별 HTTP 요청으로 다운로드하여 발생하는 네트워크 대기 시간(RTT) 병목 → 수많은 조각 이미지를 하나의 커다란 스프라이트 시트 이미지로 병합하고 CSS 좌표를 통해 필요한 부분만 잘라 보여주는 웹 성능 최적화 기법 / 유지보수 시 수작업 수정 오버헤드

## 핵심 그림
```text
+-------------------------------------------------------------------------+
|                  CSS 스프라이트(Image Sprite) 매핑 메커니즘             |
+-------------------------------------------------------------------------+
|                                                                         |
|  [ 단일 스프라이트 시트 이미지 (icons.png) ]                             |
|  (0,0)                                                                  |
|    +-------------+-------------+                                        |
|    | [ 홈 아이콘 ]| [ 검색 아이콘]                                      |
|    | (32 x 32)   | (32 x 32)   |                                        |
|    +-------------+-------------+                                        |
|    | [ 마이페이지]| [ 설정 아이콘]                                      |
|    +-------------+-------------+                                        |
|                                                                         |
|  [ CSS 좌표 지정 렌더링 ]                                               |
|    .icon-home {                                                         |
|      width: 32px; height: 32px;                                         |
|      background: url('icons.png') 0 0 no-repeat;                        |
|    }                                                                    |
|    .icon-search {                                                       |
|      width: 32px; height: 32px;                                         |
|      background: url('icons.png') -32px 0 no-repeat;                     |
|    }                                                                    |
|                                                                         |
|  * 효과: 4번의 개별 HTTP 요청 ──> 단 1번의 HTTP 요청으로 압축          |
+-------------------------------------------------------------------------+
```

## 핵심 용어
- 텍스처 아틀라스(Texture Atlas): 게임 및 컴퓨터 그래픽스에서 복수의 작은 2D 텍스처나 프레임 애니메이션을 하나의 큰 이미지 맵에 바둑판처럼 묶어 렌더링 드로우 콜(Draw Call)을 줄이는 원천 기술
- RTT(Round Trip Time): 웹 브라우저가 서버에 HTTP 요청을 보내고 응답의 첫 바이트를 수신할 때까지 걸리는 패킷 왕복 시간

## 핵심 통찰
- HTTP/1.1 환경에서는 도메인당 동시 연결 수(6개 내외) 제한과 요청-응답 직렬 처리(HoL 블로킹) 때문에 스프라이트 기법이 페이지 로딩 시간을 절반 이상 줄여주는 필수 기술이었음
- HTTP/2 및 HTTP/3에서는 단일 TCP/QUIC 연결 내에서 수백 개의 요청을 병렬 다중화(Multiplexing)할 수 있으므로 요청 수 감소의 효과는 과거보다 다소 줄었으나, 이미지 헤더 압축 및 단일 TCP 슬로우 스타트 회피 관점에서는 여전히 유효함
- 스프라이트의 최대 단점은 "아이콘 1개만 바꿔도 전체 스프라이트 시트 파일이 변경되어 브라우저 캐시가 100% 무효화"된다는 점이므로, 변경 주기가 잦은 이미지와 불변의 시스템 아이콘을 분리해야 함

## 이웃 토픽과 구분
- CSS 스프라이트(비트맵) vs SVG 스프라이트(벡터): CSS 스프라이트 = PNG/WebP 비트맵 기반으로 고해상도(레티나)에서 픽셀 깨짐 발생 / SVG 스프라이트 = XML 벡터 기반(`use` 태그)으로 해상도와 무관하게 선명하며 CSS 색상 제어 가능

## 문제·원인·대책
- 적용 상황: 대규모 포털 메인 화면 초기 로딩 성능 최적화
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 초기 진입 시 80개의 작은 아이콘을 다운로드하느라 브라우저 연결 한도 초과 및 화면 렌더링 지연 | 개별 이미지 호출로 인한 TCP 핸드셰이크 및 HTTP 요청 오버헤드 누적 | 웹팩(webpack-spritesmith) 기반 CSS 스프라이트 자동화 및 단일 이미지 번들링 | HTTP 요청 수 80회에서 1회로 감소 및 로딩 속도 60% 개선 |
| 아이콘 하나를 수정할 때마다 포토샵으로 좌표를 일일이 계산하느라 개발자 생산성 저하 | 수작업 이미지 편집 및 CSS 좌표 하드코딩 방식의 유지보수 부채 | 빌드 시 SVG 파일을 읽어 최적 심볼 시트로 자동 생성하는 SVGO 스프라이트 파이프라인 구축 | 수작업 좌표 계산 100% 제거 및 벡터 품질 유지 |

## 이렇게 출제된다
