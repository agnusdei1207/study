## 답안 골격
```text
[동등 분할] ◀━━ 머리: Ⅶ 내 의견 (유효/무효 클래스 균형 설계 및 경계값 분석과의 필수 결합)
 ┃
 ┣━ Ⅰ 개요 ───── 무한한 입력값 전수 테스트 불가능 → 동일한 출력을 내는 동등 영역으로 분할 검증
 ┣━ Ⅱ 특징 ───── 대표값 추출 원칙 · 유효(Valid) 및 무효(Invalid) 클래스 분리 · 테스트 케이스 최소화
 ┣━ Ⅲ 구조 ───── 입력 도메인 → 유효 동등 클래스군(정상 처리) / 무효 동등 클래스군(에러 처리)
 ┣━ Ⅳ 흐름 ───── ① 입력 명세 분석 → ② 입력 도메인 파티셔닝 → ③ 대표값 1개씩 선정 → ④ 테스트 케이스 작성
 ┣━ Ⅴ 비교 ───── 동등 분할(영역 내 대표값) vs 경계값 분석(영역 경계의 극단값)
 ┗━ Ⅵ 실무 ───── 무효 클래스 조합 시 결함 마스킹 발생 / 1-to-1 무효 클래스 매핑 규칙
```
- 필수 키워드: 블랙박스 기법 · 입력 도메인 파티셔닝 · 유효 동등 클래스 · 무효 동등 클래스 · 대표값 추출 · 결함 마스킹(Masking)
- 배점 전략: 10점 = Ⅰ 정의 → Ⅲ 파티셔닝 도식 → Ⅴ 경계값 분석과의 상호보완 / 25점 = Ⅰ~Ⅶ 전개, 명세 기반 동등 클래스 표 및 테스트 케이스 설계 실습
- 기출: 137회 2교시 `동적 테스트 및 테스트 케이스 작성` → Ⅲ·Ⅳ / 139회 3교시 `소프트웨어 테스트 기법` → Ⅳ·Ⅵ

## 한 줄 본질
- 모든 입력 조합을 테스트하는 완전 시험(Exhaustive Testing)의 물리적 불가능성 병목 → 입력 도메인을 결과가 같을 것으로 기대되는 상호 배타적 동등 클래스로 나누고 대표값 하나만 시험 → 최소한의 테스트 케이스로 전체 입력 영역 커버 / 클래스 내부의 미세한 예외 결함 누락 위험

## 핵심 그림
```text
   [ 입력 도메인: 점수 0 ~ 100 ]
     무효 클래스 1           유효 클래스           무효 클래스 2
   (Score < 0)        (0 <= Score <= 100)      (Score > 100)
  <------------)      [-----------------]      (------------>
    대표값: -10           대표값: 75             대표값: 150
    (Error 처리)          (정상 처리)            (Error 처리)
```

## 핵심 용어
- 유효 동등 클래스(Valid Equivalence Class): 프로그램의 정상적인 입력 조건을 만족하는 유효한 입력값들의 집합
- 무효 동등 클래스(Invalid Equivalence Class): 오류 처리 루틴을 유발해야 하는 비정상적이거나 잘못된 입력값들의 집합
- 결함 마스킹(Defect Masking): 하나의 테스트 케이스에 여러 무효 입력값을 동시에 넣었을 때, 한 결함으로 인해 다른 결함이 가려져 발견되지 않는 현상

## 핵심 통찰
- 동등 분할의 전제 조건은 "동일 클래스 내의 한 원소가 결함을 유발하면 나머지 모든 원소도 결함을 유발하고, 한 원소가 통과하면 나머지도 통과한다"는 가정임
- 유효 클래스는 하나의 테스트 케이스에 가능한 한 많은 유효 조건을 결합해도 되지만, 무효 클래스는 반드시 하나의 테스트 케이스에 오직 하나의 무효 조건만 넣어야 함(결함 마스킹 방지)
- 동등 분할만으로는 경계 지점(Boundary)의 1 차이로 발생하는 오프바이원(Off-by-one) 오류를 잡을 수 없으므로 항상 경계값 분석과 1:1 쌍으로 적용해야 함

## 이웃 토픽과 구분
- 동등 분할 vs 경계값 분석: 동등 분할 = 파티션 내부의 전형적인 중간 대표값 선택 / 경계값 분석 = 파티션의 시작과 끝 경계값 선택

## 문제·원인·대책
- 사례: 137회 기출 정수 입력 검증 모듈 [10 미만 or 100 초과: Fail, 10~100: Pass, 비정수: Invalid] 테스트 케이스 도출
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 음수와 문자열 입력 시 시스템 예외 크래시 발생 | 정상 범위(10~100)만 집중 검증하고 무효 클래스(비정수, 범위 외) 도출 누락 | 유효 1개(10~100)와 무효 3개(미만, 초과, 데이터타입 불일치) 동등 클래스 체계적 도출 | 모든 에러 핸들링 경로 100% 검증 |
| 다중 에러 입력 시 두 번째 에러 처리 루틴 미작동 발견 불가 | 테스트 케이스 1개에 '범위 초과'와 '비정수 입력'을 동시에 주입해 결함 마스킹 발생 | 무효 동등 클래스는 1개 케이스당 1개 무효 조건만 할당하는 원칙 준수 | 개별 예외 처리 로직의 독립적 무결성 검증 |

## 내 의견
- [경계만 챙기고 중간 대표값을 생략하는 과오] 경계값 분석만 신경 쓰느라 파티션 한가운데에서 발생하는 비즈니스 계산식 오류(예: 누진세 구간 계산 공식 오류)를 놓치는 사례 목격 → 나라면: 동등 분할로 전체 비즈니스 도메인 파티션을 먼저 완성한 뒤, 각 파티션의 정중앙값(동등분할)과 양 끝값(경계값)을 자동으로 매핑해 케이스를 생성하는 테스트 설계 템플릿 운영
