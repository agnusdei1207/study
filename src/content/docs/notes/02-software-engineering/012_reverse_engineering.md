## 답안 골격
```text
[역공학] ◀━━ 머리: Ⅶ 내 의견 (정적·동적 분석 자동화와 합법적 클린룸 리버스 엔지니어링 준수)
 ┃
 ┣━ Ⅰ 개요 ───── 문서 부재 레거시의 유지보수 불가 → 하위 산출물(코드/바이너리)에서 상위 설계 복원
 ┣━ Ⅱ 특징 ───── 추상화 수준 상승 · 분석적 접근 · 소스코드 역공학 vs 바이너리 역공학
 ┣━ Ⅲ 구조 ───── 어휘 분석 → 구문 트리(AST) 생성 → 제어 흐름 그래프(CFG) → 상위 모델(UML/ERD) 추출
 ┣━ Ⅳ 흐름 ───── ① 대상 산출물 수집 → ② 역컴파일/디스어셈블리 → ③ 데이터/제어 흐름 분석 → ④ 상위 설계서 생성
 ┣━ Ⅴ 비교 ───── 정적 역공학(코드/바이너리 비실행 분석) vs 동적 역공학(런타임 디버깅/패킷 분석)
 ┗━ Ⅵ 실무 ───── 난독화 및 지적재산권 침해 위험 / 클린룸 기법(Clean Room) 및 자동 분석 도구
```
- 필수 키워드: 설계 복원 · 추상화 · 디컴파일 · 디스어셈블리 · AST · 정적/동적 분석 · 클린룸
- 배점 전략: 10점 = Ⅰ 정의 → Ⅲ 계층별 복원 도식 → Ⅴ 정적/동적 비교 / 25점 = Ⅰ~Ⅶ 전개, 재공학(3R) 연계 및 보안/컴플라이언스 이슈 대응
- 기출: 137회 1교시 `역공학과 재공학` → Ⅰ·Ⅲ·Ⅴ / 138회 2교시 `유지보수를 위한 재공학과 역공학` → Ⅲ·Ⅵ

## 한 줄 본질
- 원 개발자의 퇴사와 설계 문서 유실로 코드의 동작 원리를 알 수 없는 블랙박스화 병목 → 소스코드 또는 컴파일된 바이너리를 구문 분석하고 추상화하여 아키텍처 모델과 비즈니스 로직을 복원 → 레거시 유지보수 및 보안 취약점 식별 가능 / 난독화 극복 난이도 및 저작권 침해 분쟁 위험

## 핵심 그림
```text
  [ 추상화 레벨 상승 ]
  Level 3: 요구사항 / 비즈니스 규칙    ^
             ^                         |
             | [ 역공학 (추상화) ]     |
  Level 2: 소프트웨어 아키텍처 / UML   |
             ^                         |
             |                         |
  Level 1: 소스코드 / DB 스키마        |
             ^                         |
  Level 0: 실행 바이너리 (Machine Code)|
```

## 핵심 용어
- 디컴파일러(Decompiler): 기계어나 바이트코드(바이너리)를 고수준 프로그래밍 언어(C, Java 등) 소스코드로 역변환하는 도구
- 클린룸 역공학(Clean Room Reverse Engineering): 저작권 침해 소송을 피하기 위해 한 팀이 역공학으로 명세서만 작성하고, 완전히 격리된 다른 팀이 그 명세서만 보고 순공학으로 신규 구현하는 합법적 기법

## 핵심 통찰
- 역공학은 코드를 눈으로 읽는 수동 작업이 아니라, AST(추상 구문 트리)와 호출 그래프(Call Graph)를 생성하는 정적 분석 도구의 자동화 역량에 의존함
- 소스코드가 있는 소프트웨어 역공학은 유지보수성 향상이 목적이나, 바이너리 역공학은 악성코드 분석 및 취약점 탐색(모의해킹) 분야의 핵심 기술임
- 현대 컴파일러의 코드 최적화와 상용 난독화 도구(코드 가상화, 제어 흐름 평탄화)는 역공학의 복원율을 떨어뜨리는 핵심 장애 요인임

## 이웃 토픽과 구분
- 역공학 vs 재공학: 역공학 = 코드에서 설계를 추출하는 단방향 분석 / 재공학 = 역공학된 결과를 바탕으로 시스템을 전면 재구축하는 전체 순환 주기

## 문제·원인·대책
- 사례: 138회 기출 레거시 시스템 현대화 및 악성코드 침해사고 포렌식 역공학
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 타사 상용 솔루션 호환 모듈 개발 시 저작권 침해 피소 | 원본 소스코드 열람 및 직접 복제로 인한 라이선스 위반 | 클린룸(Clean Room) 설계 기법 및 블랙박스 인터페이스 명세화 | 법적 분쟁 위험 제로화 및 호환성 확보 |
| 안티 디버깅 및 난독화로 바이너리 분석 불가 | 패커(Packer) 압축 및 제어 흐름 평탄화(Control Flow Flattening) | 메모리 덤프 기반 언패킹(Unpacking) 및 심볼릭 실행 도구 적용 | 제어 흐름 복원 및 악성 행위 시그니처 적출 |

## 이렇게 출제된다
- 제137회 1교시 11번: "소프트웨어 역공학과 재공학을 설명하시오." → 요구 포인트: Ⅰ 역공학 개념 + Ⅲ 추상화 수준별 역공학 대상 + Ⅴ 재공학과의 관계
- 제138회 2교시 5번: "소프트웨어 유지보수를 위한 재공학(Re-engineering)과 역공학(Reverse-engineering)에 대하여 다음 내용을 설명하시오." → 요구 포인트: Ⅲ 정적/동적 역공학 기법 + Ⅳ 설계 복원 절차 + Ⅵ 법적 고려사항

## 내 의견
- [레거시 분석 시 사람 눈에만 의존하는 비효율] 수백만 라인의 레거시 코드를 개발자 수십 명이 투입되어 수개월간 분석하다 프로젝트 일정이 파탄 나는 사례 다발 → 나라면: 소나큐브(SonarQube) 및 AST 기반 정적 분석 파이프라인을 구축해 패키지 간 순환 의존성과 사용되지 않는 죽은 코드(Dead Code)를 자동 식별하고 의존성 다이어그램을 선제 도출
