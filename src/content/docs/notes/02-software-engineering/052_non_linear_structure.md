## 한 줄 본질
- 원소들이 일렬로 나열되는 선형 구조로는 계층적 디렉터리나 상호 연결된 소셜 네트워크의 복잡성을 표현할 수 없는 한계 병목 → 노드(Node)와 간선(Edge)을 이용해 1:N(트리) 또는 N:M(그래프)의 다차원 연결 관계를 모델링 → 복합 관계의 직관적 표현 및 고속 탐색 달성 / 순회 알고리즘의 복잡도 및 메모리 포인터 오버헤드 대가

## 핵심 그림
```text
[ 트리 (Tree: 1:N 계층 구조) ]           [ 그래프 (Graph: N:M 네트워크 구조) ]
            ( A: Root )                             ( A ) ------ ( B )
           /           \                             |  \        /  |
        ( B )         ( C )                          |   \      /   |
        /   \             \                          |    ( C )     |
      ( D ) ( E )         ( F )                      |   /      \   |
  * 사이클 없음, 루트 단일                     ( D ) ------ ( E )
  * 부모-자식 종속 관계                      * 사이클 존재 가능, 루트 없음
```

## 핵심 용어
- 비선형 자료구조(Non-Linear Data Structure): 데이터 항목들이 연속적으로 배열되지 않고, 하나의 데이터 뒤에 여러 개의 데이터가 연결될 수 있는 구조(트리, 그래프)
- DAG(Directed Acyclic Graph): 방향성은 있지만 순환(사이클)이 없는 그래프로, 작업 스케줄링이나 블록체인, 빌드 파이프라인 의존성 모델링에 사용됨

## 핵심 통찰
- 트리는 특수한 형태의 그래프임: "루트 노드가 존재하고, 사이클이 없으며, $N$개의 노드가 정확히 $N-1$개의 간선으로 연결된 연결 그래프"가 바로 트리임
- 데이터베이스의 인덱스가 선형 배열이 아닌 B-Tree 계열의 비선형 트리를 채택한 이유는 디스크 I/O 횟수를 트리의 높이($O(\log_M N)$)만큼 극적으로 줄이기 위함임
- 소셜 네트워크나 지식 관계망처럼 고차원 연결성이 핵심인 도메인에서는 관계형 DB의 복잡한 JOIN 연산 대신 네이티브 그래프 데이터베이스(Neo4j)를 활용함

## 이웃 토픽과 구분
- 비선형 구조 vs 선형 구조: 비선형 = 하나의 원소 뒤에 여러 원소 연결(트리, 그래프) / 선형 = 앞뒤 원소가 1:1로만 연결(배열, 리스트, 스택, 큐)

## 문제·원인·대책
- 사례: 125회 기출 작업 의존성(Workflow) 분석 시 순환 참조로 인한 무한 루프
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 빌드 파이프라인에서 작업 A와 B가 상호 참조하여 영구 정지 | 의존성 그래프 내 사이클(Cycle) 존재로 인한 교착 | 위상 정렬(Topological Sort) 및 타잔(Tarjan) 알고리즘으로 사이클 사전 검출 | 순환 의존성 오류 100% 조기 차단 |
| 딥러닝 지식 그래프 검색 시 관계 탐색 깊이 증가로 쿼리 지연 폭증 | RDBMS의 다중 JOIN 연산으로 인한 기하급수적 디스크 I/O | 인메모리 그래프 DB 도입 및 인덱스 없는 인접성(Index-free Adjacency) 탐색 | 그래프 순회 속도 10배 이상 향상 |

## 내 의견
- [계층 구조 데이터를 관계형 DB에 억지로 구겨 넣는 비효율] 파일 시스템이나 조직도 같은 계층 트리를 RDBMS 단일 테이블에 `parent_id`로만 저장했다가, 하위 조직 전체 조회 시 재귀 SQL(CONNECT BY) 남발로 DB CPU를 태우는 사례 빈발 → 나라면: 계층형 데이터는 클로저 테이블(Closure Table) 패턴이나 전용 그래프 DB를 검토하고, 변경이 적은 카테고리 데이터는 인라인 경로(Materialized Path) 방식을 적용해 단일 인덱스 스캔으로 최적화
