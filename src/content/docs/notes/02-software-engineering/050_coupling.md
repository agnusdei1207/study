## 한 줄 본질
- 하나의 모듈을 수정했을 때 그 모듈을 참조하는 다른 수십 개 모듈이 연쇄적으로 깨지는 스파게티 코드 병목 → 모듈 간에 주고받는 정보를 단순한 원시 데이터 값(자료 결합도)으로 제한하고 인터페이스로 격리 → 모듈의 독립적 교체 및 유지보수 유연성 확보 / 인터페이스 추상화 계층 증가 대가

## 핵심 용어
- 내용 결합도(Content Coupling): 한 모듈이 다른 모듈의 내부 데이터나 로직을 직접 참조하거나 수정하는 가장 나쁜 형태의 결합도
- 자료 결합도(Data Coupling): 모듈 간에 오직 필요한 원시 데이터 값만을 파라미터로 주고받아 한 모듈의 변경이 다른 모듈에 일체 영향을 주지 않는 가장 이상적인 결합도
- 스탬프 결합도(Stamp Coupling): 모듈 간에 배열이나 레코드(객체) 전체를 전달하여, 호출받은 모듈이 쓰지도 않는 불필요한 필드까지 알게 되는 결합도

## 핵심 통찰
- 실무에서 가장 흔히 저지르는 결합도 오류는 '스탬프 결합도'임: 단지 고객의 나이만 필요한 메서드에 `Customer` 전체 객체를 파라미터로 넘겨 불필요한 의존성을 만듦
- 제어 결합도(Control Coupling)는 상위 모듈이 하위 모듈에게 `boolean isSpecial` 같은 플래그를 넘겨 하위 모듈의 내부 분기 로직을 지시할 때 발생하며, 이는 전략 패턴으로 제거해야 함
- 결합도를 낮추는 가장 강력한 현대적 도구는 '의존성 주입(DI)'과 '비동기 이벤트 메시징(Event-driven)'임

## 이웃 토픽과 구분
- 결합도 vs 응집도: 결합도 = 모듈 '외부'의 다른 모듈과의 관계(낮을수록 좋음) / 응집도 = 모듈 '내부' 요소들 간의 관련성(높을수록 좋음)
