## 한 줄 본질
- 다양한 문자열 형식 검증을 조건문으로 직접 작성할 때 발생하는 코드 비대화와 오류 병목 → 형식 언어 이론의 정규 문법에 기반하여 메타 문자로 텍스트 패턴을 압축 기술하는 기법 / 과도한 중첩 수식어 사용 시 파국적 백트래킹(Catastrophic Backtracking) 위험

## 핵심 그림
```text
+-------------------------------------------------------------------------+
|                정규 표현식 엔진 동작 및 ReDoS 파국적 백트래킹            |
+-------------------------------------------------------------------------+
|  [ 패턴 ] : ^(a+)+$   (중첩된 수식어 구조)                               |
|  [ 입력 ] : "aaaaaaaaaaaaaaaaaaaaX"  (끝에 불일치 문자 존재)            |
|                                                                         |
|  1. 첫 번째 (a+)가 "aaaaaaaaaaaaaaaaaaaa"를 탐욕적(Greedy) 매칭         |
|  2. 끝의 'X'와 '$' 불일치 발생!                                         |
|  3. 엔진이 한 글자 양보하고 가능한 모든 분할 조합을 탐색 (백트래킹 시작) |
|     - (a)(a...a), (aa)(a...a), (aaa)(a...a) ...                          |
|  4. 경우의 수가 O(2^n) 지수 함수로 폭증하여 CPU 100% 점유 (장애 발생)    |
|                                                                         |
|  [ 해결책 ] : 비백트래킹 엔진(RE2) 사용, 수유적 수식어(Possessive `++`)   |
+-------------------------------------------------------------------------+
```

## 핵심 용어
- 탐욕적 수량자(Greedy Quantifier): 가능한 한 가장 긴 문자열과 매칭을 시도하는 기본 동작 방식 (`*`, `+`, `{n,m}`)
- 파국적 백트래킹(Catastrophic Backtracking): 불일치가 발생했을 때 이전 상태로 돌아가 다른 경로를 탐색하는 과정이 지수 함수적으로 증가하는 현상

## 핵심 통찰
- 정규 표현식은 프로그래밍 언어 내부에서 문자열 리터럴로 파싱될 때마다 구문 분석과 오토마타 변환 오버헤드가 발생하므로, 반드시 정적 객체로 사전 컴파일(`Pattern.compile()`)하여 재사용해야 함
- 파이썬, 자바, 자바스크립트 등의 표준 정규식 엔진은 대부분 NFA 기반 백트래킹 엔진을 사용하므로 복잡한 전방/후방 탐색(Lookahead/Lookbehind)을 지원하는 대신 ReDoS 공격에 노출됨
- 보안 입력 검증 목적으로 정규식을 쓸 때는 화이트리스트(허용 목록) 방식을 취해야 하며, 중첩된 반복 그룹(`(a+)+`, `([a-zA-Z]+)*`)을 반드시 제거해야 함

## 이웃 토픽과 구분
- 정규 표현식(RegEx) vs 글로브(Glob): 정규 표현식 = 정규 문법 전체를 지원하는 정밀 텍스트 패턴 매칭 / 글로브 = 파일 시스템 경로 탐색에 사용되는 단순 와일드카드(`*`, `?`) 매칭

## 문제·원인·대책
- 적용 상황: API 게이트웨이 유입 파라미터 유효성 검증 필터
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 특정 악의적 페이로드 수신 시 게이트웨이 스레드 풀 고갈 및 서비스 마비 | 이메일 유효성 검증 정규식에 중첩 반복 패턴이 포함되어 파국적 백트래킹 발생 | 정규식 패턴 단순화 및 타임아웃 제한이 내장된 선형 탐색 엔진(RE2) 적용 | ReDoS 서비스 거부 공격 차단 및 지연 방지 |
| 트래픽 증가 시 문자열 검증 구간에서 과도한 GC(가비지 컬렉션) 및 CPU 병목 | 루프문 내부에서 정규식 객체를 매번 새로 생성(`String.matches()`) | 정적 클래스 변수로 `Pattern` 인스턴스 1회 컴파일 후 캐싱 재사용 | 객체 생성 오버헤드 제거 및 처리 속도 10배 개선 |
