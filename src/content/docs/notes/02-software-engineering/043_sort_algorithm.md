## 한 줄 본질
- 정렬되지 않은 데이터셋에서 원하는 항목을 찾을 때 선형 탐색($O(N)$)을 강제당하는 병목 → 비교 및 교환, 분할 정복 메커니즘을 통해 데이터를 순서대로 재배열하여 이진 탐색($O(\log N)$)을 가능하게 함 → 검색 및 집계 성능 극대화 / 정렬 연산 시 CPU 계산량 및 추가 메모리 소모 대가

## 핵심 용어
- 안정 정렬(Stable Sort): 정렬 기준 키 값이 동일한 원소들이 정렬 전의 상대적 순서를 정렬 후에도 그대로 유지하는 성질(삽입, 병합, 팀소트 등)
- 제자리 정렬(In-place Sort): 입력 배열 이외에 추가적인 메모리 공간을 거의 쓰지 않고($O(1)$ 또는 $O(\log N)$) 내부에서 원소를 교환하는 정렬(퀵, 힙, 선택 등)

## 핵심 통찰
- 비교 기반 정렬 알고리즘의 수학적 하한선은 결정 트리(Decision Tree)의 높이 한계에 의해 $\Omega(N \log N)$을 넘을 수 없음
- 퀵 정렬은 최악의 경우 $O(N^2)$이지만 캐시 지역성(Cache Locality)이 가장 우수하여 실무 평균 속도가 가장 빠름
- 실무 표준인 Python과 Java의 기본 정렬 알고리즘은 퀵 정렬이 아니라, 삽입 정렬과 병합 정렬을 결합하여 실제 데이터의 부분 정렬성을 극대화한 '팀소트(Timsort)'임

## 이웃 토픽과 구분
- 병합 정렬 vs 퀵 정렬: 병합 정렬 = $O(N)$ 추가 메모리 필요, 항상 $O(N \log N)$ 보장, 안정 정렬 / 퀵 정렬 = 제자리 정렬, 최악 $O(N^2)$, 불안정 정렬

| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 이미 정렬된 데이터에 퀵 정렬 수행 시 OutOfMemory / CPU 100% | 고정 첫 번째 원소를 피벗으로 선택하여 최악의 $O(N^2)$ 분기 퇴보 | Median-of-Three 피벗 선택 또는 인트로소트(Introsort) 전환 | 최악의 경우에도 힙 정렬로 전환하여 $O(N \log N)$ 강제 보장 |

## 내 의견
- [원시적 알고리즘을 실무에 직접 구현하는 만용 금지] 알고리즘 시험을 공부했다고 해서 프로덕션 코드에 직접 퀵 정렬을 손코딩했다가 피벗 편향으로 스택 오버플로우를 내는 사고를 목격 → 나라면: 수십 년간 엔지니어링 검증을 거친 표준 라이브러리의 듀얼 피벗 퀵소트(기본형 타입)와 팀소트(객체 참조 타입)를 신뢰하여 사용하고, 대용량 외장 정렬 시에는 외부 병합 정렬(External Merge Sort) 청크 파이프라인 설계에 집중
