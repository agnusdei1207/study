## 답안 골격
```text
[화이트박스 테스트] ◀━━ 머리: Ⅶ 내 의견 (위험도 기반 커버리지 기준 수립 및 CI 연계 강제)
 ┃
 ┣━ Ⅰ 개요 ───── 블랙박스로 확인 불가한 내부 결함 및 미실행 코드 존재 → 소스 구조 기반 논리 경로 검증
 ┣━ Ⅱ 특징 ───── 내부 로직 가시성 확보 · 제어 흐름 및 데이터 흐름 분석 · 높은 커버리지 요구
 ┣━ Ⅲ 구조 ───── 제어 흐름 그래프(CFG) · 분기 노드 · 실행 경로(Path) · 커버리지 측정 지표
 ┣━ Ⅳ 흐름 ───── 구문 커버리지 → 결정(분기) 커버리지 → 조건 커버리지 → 조건/결정 커버리지 → MC/DC
 ┣━ Ⅴ 비교 ───── 제어 흐름 테스트 vs 데이터 흐름 테스트
 ┗━ Ⅵ 실무 ───── 모든 경로 검증 시 경로 폭증(Path Explosion) / 맥케이브 순환복잡도 기반 독립 경로 한정
```
- 필수 키워드: 구조 기반 · 제어 흐름 그래프(CFG) · 구문 커버리지 · 분기 커버리지 · 조건 커버리지 · MC/DC · 경로 폭증
- 배점 전략: 10점 = Ⅲ 제어 흐름 그래프 도식 → Ⅳ 커버리지 기준 5단계 계층 표 / 25점 = Ⅰ~Ⅶ 전개, MC/DC 도출 사례 및 안전 필수 시스템 적용
- 기출: 129회 1교시 `화이트박스와 블랙박스 테스트 비교` → Ⅰ·Ⅲ·Ⅴ / 134회 3교시 `소프트웨어 테스트` → Ⅲ·Ⅳ·Ⅵ

## 한 줄 본질
- 정상적인 입력에 대한 출력만으로는 소스코드 내부의 미실행 데드 코드와 잠재적 논리 오류를 탐지할 수 없는 병목 → 제어 흐름 그래프(CFG)를 기반으로 구문, 분기, 복합 조건을 단계별로 통과하는 테스트 케이스 설계 → 코드 내부 결함 및 메모리 누수 조기 제거 / 모든 경로 검증 시 테스트 케이스 폭증 비용

## 핵심 그림
```text
      [ 노드 1: 조건 A and B ]
            /          \
      (True)            (False)
        v                  v
   [ 노드 2: 실행 ]     [ 노드 3: 실행 ]
        \                  /
         v                v
      [ 노드 4: 후속 처리 ]
```

## 핵심 용어
- MC/DC(Modified Condition/Decision Coverage): 각 개별 조건이 다른 조건의 영향 없이 전체 결정문의 결과를 독립적으로 바꿀 수 있음을 검증하는 고신뢰성 커버리지 기준
- 순환 복잡도(Cyclomatic Complexity): 제어 흐름 그래프에서 선형 독립 경로의 수를 정량화하여 최소 테스트 케이스 수를 산출하는 지표(V(G) = E - N + 2)

## 핵심 통찰
- 구문 커버리지 100%를 달성해도 빈 분기문(if-else의 else 누락)이 있으면 결함을 놓치므로 최소한 결정(분기) 커버리지 이상을 요구해야 함
- 조건 커버리지와 결정 커버리지는 서로를 완벽히 포함하지 않으므로, 이 둘을 결합한 조건/결정 커버리지나 안전 분야 표준인 MC/DC가 필요함
- 화이트박스 테스트는 요구사항 명세 자체의 누락(Omission 결함)은 원천적으로 발견할 수 없으므로 블랙박스 테스트와의 상호보완이 필수적임

## 이웃 토픽과 구분
- 구문 커버리지 vs 분기 커버리지: 구문 커버리지 = 모든 실행 문장을 최소 1회 실행 / 분기 커버리지 = 모든 조건문의 True/False 분기 경로를 최소 1회 실행

## 문제·원인·대책
- 사례: 134회 기출 미션 크리티컬 제어 소프트웨어의 분기 누락으로 인한 런타임 예외
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 복합 조건문에서 특정 서브 조건 오류로 비정상 분기 | 단순 분기 커버리지에만 의존하여 복합 조건의 조합 미검증 | ISO 26262/DO-178C 표준에 부합하는 MC/DC 테스트 기법 적용 | N+1개 테스트 케이스로 2^N개 조합 수준의 결함 검출 |
| 루프와 중첩 if문으로 인한 선형 독립 경로 수백 개 폭증 | 리팩토링 없는 스파게티 코드로 순환 복잡도 과대 | 맥케이브 순환 복잡도 기반 모듈 분할 및 경계값 루프 테스트(0, 1, 최대) | 테스트 케이스 수를 독립 경로 수(V(G)) 이내로 최적화 |

## 이렇게 출제된다

- 제134회 3교시 2번: "소프트웨어 테스트에 대하여 설명하시오." → 요구 포인트: Ⅲ 정적/동적 테스트 중 화이트박스 커버리지 기준 + Ⅵ 커버리지 측정 도구 및 자동화

## 내 의견
- [맹목적인 라인 커버리지 100% 달성 집착의 함정] 복잡한 분기 로직은 검증하지 않은 채 단순 DTO나 게터/세터만 호출해 커버리지 수치만 인위적으로 90% 넘기는 의미 없는 테스트 코드 양산 목격 → 나라면: 단순 라인(구문) 커버리지가 아닌 브랜치(분기) 커버리지를 80% 이상으로 강제하고, 크리티컬 금융/결제 모듈에 대해서는 돌연변이 테스트(Mutation Testing)를 병행하여 테스트 코드의 실질 결함 적출력 검증
