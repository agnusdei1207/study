## 한 줄 본질
- 오픈소스 소프트웨어를 무분별하게 차용할 때 발생하는 기업 영업비밀 소스코드 강제 공개(GPL 전염) 및 소송 위험 병목 → 라이선스별 권리와 의무(저작권 고지, 소스 공개 범위, 특허 조항)를 체계적으로 분류하고 파이프라인에서 자동 검증 → 법적 안전성 확보 하에 개발 생산성 극대화 / 컴플라이언스 감사 비용

## 핵심 그림
```text
[ 소스코드 공개 의무 강도에 따른 오픈소스 라이선스 스펙트럼 ]
   <--- 약함 (Permissive)                        강함 (Strong Copyleft) --->
+--------------------+---------------------+--------------------+--------------------+
|  MIT / BSD         |  Apache 2.0         |  LGPL / MPL        |  GPL / AGPL        |
|  - 단순 고지 의무  |  - 특허 라이선스    |  - 라이브러리 수정 |  - 파생 저작물     |
|  - 소스 공개 불필요|    권리 명시        |    부분만 공개     |    전체 소스 공개  |
+--------------------+---------------------+--------------------+--------------------+
   * 클라우드 벤더 방어용 신규 라이선스: SSPL(네트워크 서비스 시 인프라 코드까지 공개), BSL
```

## 핵심 용어
- 카피레프트(Copyleft): 소프트웨어의 자유로운 사용·수정·배포를 보장하되, 이를 수정한 2차적 저작물도 동일한 라이선스로 소스코드를 공개하도록 강제하는 원칙
- SSPL(Server Side Public License): 클라우드 대기업(AWS 등)이 오픈소스를 패키징해 SaaS로 판매하며 기여하지 않는 행위를 막기 위해, 서비스를 제공하는 전체 관리 소프트웨어 코드 공개를 강제하는 라이선스

## 핵심 통찰
- GPL의 '전염성'은 동적 링크(Dynamic Linking)냐 정적 링크(Static Linking)냐, 또는 별도 프로세스 간 IPC 통신이냐에 따라 법적 해석과 소스 공개 범위가 달라짐
- 최근 Redis, MongoDB, Elastic 등이 허용적 라이선스에서 SSPL/BSL로 전환한 것은 오픈소스 철학의 후퇴가 아니라, 클라우드 거대 벤더의 무임승차(Free-riding)로부터 비즈니스를 지키기 위한 상업적 생존 전략임
- 생성형 AI 코딩 도구가 출력하는 코드가 GPL 코드를 학습하여 복제한 경우, 기업의 독자적 상용 소프트웨어에 의도치 않은 카피레프트 오염(License Tainting)이 발생할 수 있음

## 이웃 토픽과 구분
- GPL vs AGPL: GPL = 소프트웨어를 바이너리 형태로 '배포'할 때만 소스 공개 의무 발생 / AGPL = 배포 없이 네트워크 통신(SaaS 서비스)으로 제공할 때도 소스 공개 의무 발생

| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 상용 독점 서비스의 전체 백엔드 소스코드 공개 위기 직면 | 내부 개발자가 AGPL-3.0 라이브러리를 무단으로 백엔드 서버에 임베딩 | SCA(FOSSID, BlackDuck 등) 도구로 소스 의존성 전수 스캔 및 모듈 분리 | GPL/AGPL 라이선스 컴포넌트 완전 격리 및 독점 코드 보호 |

## 이렇게 출제된다
- 제134회 3교시 6번: "일부오픈소스라이선스가개방형(예: MIT,BSD등)에서폐쇄형(예: SSPL(ServerSide PublicLicense),BSL(BusinessSourceLicense)등)으로변화하고있다.이러한오픈소스 라이선스정책변경의배경및소프트웨어산업에미치는영향에대하여설명하시오." → 요구 포인트: Ⅰ 라이선스 변천 배경(클라우드 벤더 독점 견제) + Ⅲ 라이선스 비교 + Ⅵ 산업계 파급 효과
- 제140회 2교시 2번: "AI 생성 소스코드 및 오픈웨이트(Open-weight) 모델 활용 시 발생하는 오픈소스 라이선스 리스크와 컴플라이언스 대응 방안에 대하여 다음을 설명하시오." → 요구 포인트: 저작권/카피레프트 오염 리스크 + SBOM 및 SCA 기반 거버넌스 프레임워크

## 내 의견
- [오픈소스 무료라는 착각이 낳은 거액의 합의금] 라이선스 확인 없이 인터넷에서 코드를 긁어와 상용 제품에 탑재했다가 미국 시장 진출 직전 저작권 침해 경고장을 받고 수억 원의 라이선스 비용을 지불하는 기업 다수 발생 → 나라면: CI 파이프라인에 SBOM(Software Bill of Materials) 자동 생성 도구를 연동해 빌드 시마다 모든 오픈소스의 라이선스를 화이트리스트(MIT, Apache만 자동 통과)와 대조하고, AGPL/GPL은 전사 오픈소스 심의위원회(OSRB) 승인 없이는 빌드 자체를 차단
