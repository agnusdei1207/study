## 답안 골격
```text
[HAZOP] ◀━━ 머리: Ⅶ 내 의견 (가이드워드 정량화 및 사이버물리시스템(CPS) 안전 분석 자동화)
 ┃
 ┣━ Ⅰ 개요 ───── 공정/시스템 설계 의도에서 벗어난 잠재 위험 식별 → 가이드워드 기반 브레인스토밍
 ┣━ Ⅱ 특징 ───── 팀 기반 정성적 분석 · 표준 가이드워드 적용 · 원인-결과-대책 도출
 ┣━ Ⅲ 구조 ───── 설계 의도(Design Intent) + 가이드워드(Guide Word) = 이탈(Deviation) 식별
 ┣━ Ⅳ 흐름 ───── ① 분석 절점(Node) 선정 → ② 매개변수 선정 → ③ 가이드워드 조합 → ④ 원인/결과 규명 → ⑤ 대책 수립
 ┣━ Ⅴ 비교 ───── HAZOP(귀납적 정성분석) vs FTA(연역적 정량 트리) vs FMEA(단일 고장 모드 영향)
 ┗━ Ⅵ 실무 ───── 소프트웨어 제어 로직 적용 시 이탈 폭증 / CHAZOP(Computer HAZOP) 가이드워드 특화
```
- 필수 키워드: 가이드워드(Guide Word) · 설계 의도(Design Intent) · 이탈(Deviation) · 매개변수(Parameter) · CHAZOP · 안전성 분석
- 배점 전략: 10점 = Ⅰ 정의 → Ⅲ 가이드워드 매트릭스 도식 → Ⅴ FTA/FMEA 비교 / 25점 = Ⅰ~Ⅶ 전개, SW 특화 가이드워드(Early, Late 등) 적용 사례
- 기출: 123회 1교시 `HAZOP` → Ⅰ·Ⅱ·Ⅲ / 131회 3교시 `소프트웨어 안전성 분석 기법` → Ⅲ·Ⅴ

## 한 줄 본질
- 시스템 설계자가 예상하지 못한 미세한 운전 조건의 변동이 대형 재난으로 번지는 위험 병목 → 가이드워드(No, More, Less, As Well As 등)를 시스템 매개변수에 결합해 모든 잠재적 이탈을 전수 도출 → 위험 조기 식별 및 방호 대책 수립 / 분석가의 경험 의존성 및 회의 공수 비용

## 핵심 그림
```text
[ 설계 의도 (Design Intent) ]  +  [ 가이드워드 (Guide Words) ]
  * 유량, 압력, 속도, 시간         * No (설계 의도와 반대/결여)
                                   * More / Less (양적 증가/감소)
                                   * As Well As (부가 기능 수행)
                                   * Part Of (일부 기능만 수행)
                                   * Reverse (역방향 동작)
                                   * Other Than (완전 다른 동작)
                                   * Early / Late (시간적 선후 불일치)
                                          |
                                          v
                              [ 이탈 (Deviation) 규명 ]
                                          |
                   +----------------------+----------------------+
                   v                                             v
          [ 원인 (Cause) 분석 ]                         [ 결과 (Consequence) ]
                   \                                             /
                    +--------> [ 안전 대책 (Safeguards) ] <------+
```

## 핵심 용어
- 가이드워드(Guide Word): 설계 의도로부터의 가능한 이탈을 체계적으로 유도하기 위해 매개변수에 적용하는 표준 정형 단어
- CHAZOP(Control/Computer HAZOP): 화학·플랜트 중심의 전통 HAZOP을 컴퓨터 제어 시스템 및 소프트웨어 통신·타이밍 분석에 맞게 확장한 기법

## 핵심 통찰
- 전통적인 물리 플랜트 HAZOP의 매개변수는 유량, 압력, 온도지만, 소프트웨어 HAZOP(CHAZOP)의 매개변수는 데이터 전달, 신호 타이밍(Early/Late), 메시지 순서로 전환됨
- HAZOP은 근본 원인을 파헤치는 연역적 기법이 아니라 "만약 이 값이 너무 많아지면 어떻게 되는가?"를 묻는 상향식 귀납적 위험 발견 도구임
- 소프트웨어 안전(ISO 26262, IEC 61508)에서는 하드웨어 고장뿐 아니라 소프트웨어의 잘못된 명령 전달을 가이드워드로 점검하는 것이 필수 규제 요건임

## 이웃 토픽과 구분
- HAZOP vs FMEA: HAZOP = 가이드워드를 통한 시스템 공정 '이탈' 중심 분석 / FMEA = 부품 및 컴포넌트의 단일 '고장 모드' 중심 분석

## 문제·원인·대책
- 사례: 자율주행 센서 제어 모듈의 소프트웨어 안전성 분석
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 제동 신호가 제동 시점보다 2초 늦게 전달되어 충돌 위험 | 통신 버스 과부하로 인한 메시지 큐잉 지연(Late 가이드워드 이탈) | CAN FD/이더넷 QoS 우선순위 큐 적용 및 워치독 타이머 도입 | 제동 신호의 정시성(Real-time Deadline) 100% 보장 |
| 센서 데이터 유실 시 시스템 정지 | 데이터 입력 결여(No/None 가이드워드 이탈)에 대한 기본값 처리 부재 | 센서 퓨전(LiDAR + Camera) 기반 페일오버 및 안전 모드(Limp-home) 진입 | 단일 센서 단절 시에도 최소 안전 주행 유지 |

## 내 의견
- [회의실 브레인스토밍에만 그치는 형식적 HAZOP] 엑셀 시트에 가이드워드 채우기 식의 요식 행위로 진행되어 실제 런타임 제어 소프트웨어의 타이밍 이슈를 한 건도 걸러내지 못하는 한계 다발 → 나라면: 모델 기반 시스템 공학(MBSE) 도구와 연계하여 SysML 시뮬레이션 모델에 가이드워드 결함 주입(Fault Injection)을 자동화함으로써 소프트웨어 이탈 검증을 정량화
