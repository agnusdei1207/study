## 한 줄 본질
- 코드 분기가 많아질수록 잠재 결함 위험과 테스트 작성 비용이 기하급수적으로 늘어나는 병목 → 제어 흐름 그래프 상의 독립 경로 수($V(G)$)를 수학적으로 산출해 리팩토링 임계치(10 초과)를 강제 → 최소 테스트 케이스 상한선 확정 / 데이터 흐름의 복잡성은 반영하지 못하는 한계

## 핵심 그림
```text
[ 코드 예시: if (A && B) { X; } else { Y; } ]
                  |
                  v
       [ 제어 흐름 그래프 (CFG) ]
                ( 1: 시작 )
                /         \
          ( 2: A 판정 )   |
          /          \    |
    ( 3: B 판정 )     \   |
     /         \       \  |
( 4: X 실행 ) ( 5: Y 실행 )
     \         /
      ( 6: 종료 )
--------------------------------------------------
* 노드(N) = 6, 간선(E) = 8, 분기조건(P) = 2
* 공식 1: V(G) = E - N + 2 = 8 - 6 + 2 = 4 (단일 컴포넌트)
* 공식 2: V(G) = P + 1 = 3 (단, 복합조건 && 분리 시 4)
* 공식 3: V(G) = 폐쇄 영역(R) + 1 = 3 + 1 = 4
```

## 핵심 용어
- 선형 독립 경로(Linearly Independent Path): 기존에 식별된 경로들에 포함되지 않은 새로운 간선(Edge)을 적어도 하나 이상 포함하는 제어 흐름 경로
- 기저 경로 집합(Basis Set): 프로그램 내의 모든 문장(Statement)과 분기(Branch)를 최소 1회 이상 통과하도록 보장하는 선형 독립 경로들의 최소 집합

## 핵심 통찰
- 맥케이브 순환복잡도는 "테스트 케이스를 최소 몇 개 작성해야 모든 분기를 커버할 수 있는가"에 대한 하한선을 수학적으로 제공함
- 복합 조건문(`if (A && B)`)에서 단락 평가(Short-circuit Evaluation)가 발생하면 내부적으로 분기가 2개로 쪼개지므로, 복잡도 계산 시 복합 조건을 단순 조건으로 분해해야 함
- 순환복잡도가 10을 초과하면 결함 발생률이 급증하며, 50을 넘어가면 어떤 테스트 기법으로도 결함 예방이 불가능하므로 즉각적인 함수 분할이 필수적임

## 이웃 토픽과 구분
- 순환복잡도 vs 인지복잡도(Cognitive Complexity): 순환복잡도 = 기계적 제어 경로의 수(테스트 케이스 수 산출) / 인지복잡도 = 중첩 깊이를 가중하여 인간이 코드를 읽고 이해하는 난이도 정량화
