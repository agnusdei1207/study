 ┃
 ┣━ Ⅰ 개요 ───── 정렬되지 않은 데이터셋을 순차 삽입하여 이진 탐색 트리 구축 후 중위 순회로 정렬 완료하는 내부 정렬 알고리즘

## 한 줄 본질
- 원시 배열을 이진 탐색 트리의 왼쪽(작은 값)·오른쪽(큰 값) 분기 규칙으로 삽입한 뒤 Left-Root-Right 순서로 훑어내는 트리 기반 정렬 기법 / 편향 트리 방어와 포인터 메모리 오버헤드 제어

## 핵심 그림
```text
[ 원시 배열: { 5, 2, 8, 1, 4 } ]
                │
                ▼ [ 1단계: 이진 탐색 트리(BST) 순차 삽입 ]
                    ( 5 ) ◀── Root
                   ／    ＼
               ( 2 )      ( 8 )
              ／   ＼
           ( 1 )   ( 4 )

                │
                ▼ [ 2단계: 중위 순회 (In-order Traversal : Left -> Root -> Right) ]
           1 (방문) ──> 2 (방문) ──> 4 (방문) ──> 5 (방문) ──> 8 (방문)
                │
                ▼ [ 정렬 결과 출력: { 1, 2, 4, 5, 8 } ]
```

## 핵심 용어
- 이진 탐색 트리(BST, Binary Search Tree): 모든 노드가 '왼쪽 서브트리 키 < 부모 노드 키 < 오른쪽 서브트리 키' 규칙을 만족하는 이진 트리
- 중위 순회(In-order Traversal): 트리 노드를 Left Child → Root → Right Child 순서로 재귀 방문하는 방식으로, BST에서 수행 시 오름차순 정렬 데이터가 생성됨
- 편향 트리(Skewed Tree): 이미 정렬된 데이터가 순서대로 삽입될 때 트리가 한쪽으로 치우쳐 링크드 리스트처럼 전락하는 현상 (탐색 및 삽입 O(n) 소요)
- 레드-블랙 트리(Red-Black Tree): 노드 색상(Red/Black)과 회전 연산을 통해 트리의 높이 균형을 O(log n)으로 유지하는 자가 균형 이진 탐색 트리

## 핵심 통찰
- 트리 정렬의 성능은 순수하게 '트리의 높이(h)'에 종속됨
- 단순 BST를 사용할 경우 이미 정렬된 배열(`[1, 2, 3, 4, 5]`)이 들어오면 깊이가 n이 되어 총 시간복잡도가 $O(n^2)$으로 급격히 퇴화함
- AVL 트리 또는 Red-Black 트리를 기반으로 구현할 경우 최악의 경우에도 높이가 $O(\log n)$으로 보장되어 $O(n \log n)$ 안정성을 확보할 수 있음
- 힙 정렬(Heap Sort) 대비 연속된 배열 공간이 아닌 동적 노드 포인터(Left, Right)를 유지해야 하므로 캐시 지역성(Cache Locality)이 낮고 메모리 소모가 큼

## 이웃 토픽과 구분
| 비교 항목 | 트리 정렬(Tree Sort) | 힙 정렬(Heap Sort) | 퀵 정렬(Quick Sort) |
| :--- | :--- | :--- | :--- |
| **기반 자료구조** | 이진 탐색 트리 (BST / 자가 균형 BST) | 완전 이진 트리 (Max/Min Heap) | 1차원 연속 배열 (In-place Partition) |
| **평균 시간복잡도** | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ |
| **최악 시간복잡도** | $O(n^2)$ (균형 트리 적용 시 $O(n \log n)$) | $O(n \log n)$ | $O(n^2)$ (최악 피벗 선택 시) |
| **공간 복잡도** | $O(n)$ (추가 노드 및 포인터 할당) | $O(1)$ (배열 내부 제자리 정렬) | $O(\log n)$ (재귀 호출 스택) |
| **캐시 지역성** | 매우 낮음 (동적 포인터 참조) | 보통 (인덱스 점프 연산) | 매우 높음 (연속 메모리 순차 접근) |

## 문제·원인·대책
| 문제상황 | 원인 | 기술적 대책 |
| :--- | :--- | :--- |
| **기 정렬 데이터 입력 시 O(n^2) 성능 폭락** | 입력 순서가 이미 정렬되어 트리가 한쪽 방향으로만 뻗는 편향 트리(Skewed Tree) 형성 | 삽입 시 회전(Rotation) 연산을 자동 수행하는 AVL 트리나 Red-Black 트리 기반 구현체 적용 |
| **동적 메모리 오버헤드 및 단편화** | 노드당 키 값 외에 좌/우 자식 포인터(각 8바이트)를 별도 힙 메모리에 동적 할당 | 고정 크기 배열 기반 완전 이진 트리(힙 정렬)를 대체 사용하거나 메모리 풀(Pool) 사전 할당 |
| **캐시 미스로 인한 실측 성능 저하** | 노드들이 메모리상에 무작위로 분산되어 CPU 캐시 라인(L1/L2 Cache) 적중률 급감 | 대용량 단순 정렬 시 제자리 정렬(In-place Sort)인 퀵 정렬 또는 인라인화된 인덱스 트리 채택 |

## 내 의견
- 트리 정렬은 단순히 정렬만을 목적으로 사용하기에는 포인터 오버헤드와 캐시 미스 때문에 제자리 정렬(Quick Sort, Heap Sort)에 비해 실무적 경쟁력이 낮음
- 그러나 데이터가 스트리밍 형태로 지속 유입되면서 '동적 삽입과 동시에 정렬된 상태를 항상 유지해야 하는 실시간 인덱싱 환경'에서는 BST/B-Tree 형태의 트리 정렬 접근이 매우 강력한 효용을 가짐
- 실무 구현 시에는 최악 시간복잡도 방어와 높이 균형을 위해 Java의 `TreeSet`(Red-Black Tree 기반)이나 C++ STL의 `std::map`/`std::set`과 같이 검증된 자가 균형 라이브러리를 적극 활용해야 함
