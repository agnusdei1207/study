## 답안 골격
```text
[스택] ◀━━ 머리: Ⅶ 내 의견 (스택 오버플로우 방지를 위한 재귀 제거 및 메모리 풀 모니터링)
 ┃
 ┣━ Ⅰ 개요 ───── 역순 복귀 및 임시 상태 보존 필요 → 후입선출(LIFO) 단방향 제한 입출력 구현
 ┣━ Ⅱ 특징 ───── LIFO(Last-In First-Out) · 단일 입출력 창구(Top) · O(1) 삽입/삭제 속도
 ┣━ Ⅲ 구조 ───── Top 포인터 · Push 연산 · Pop 연산 · Peek 연산 · 배열/연결리스트 기반
 ┣━ Ⅳ 흐름 ───── ① IsFull 검사 → ② Top 1 증가 → ③ 데이터 저장(Push) / ① IsEmpty 검사 → ② 데이터 반환(Pop) → ③ Top 1 감소
 ┣━ Ⅴ 비교 ───── 스택(LIFO) vs 큐(FIFO) vs 덱(Deque, 양방향)
 ┗━ Ⅵ 실무 ───── 호출 스택(Call Stack) 고갈로 인한 시스템 크래시 / 꼬리 재귀 및 명시적 루프 변환
```
- 필수 키워드: LIFO · Top 포인터 · Push/Pop · Call Stack · Overflow/Underflow · 수식 파싱
- 배점 전략: 10점 = Ⅰ 정의 → Ⅲ 구조도 및 연산 알고리즘 → Ⅴ 선형 자료구조 비교 / 25점 = Ⅰ~Ⅶ 전개, OS 메모리 구조 및 시스템 스택 오버플로우 방어 전략
- 기출: 132회 2교시 `스택, 큐, 리스트의 입출력 원리` → Ⅲ·Ⅴ / 138회 2교시 `OS 메모리 4대 영역과 스택` → Ⅵ

## 한 줄 본질
- 함수 호출이나 작업 취소처럼 가장 최근에 들어간 상태를 먼저 꺼내 복구해야 하는 상태 보존 병목 → 한쪽 끝(Top)에서만 삽입과 삭제가 일어나는 후입선출(LIFO) 메커니즘 적용 → O(1)의 일정한 상태 복원 보장 / 고정 크기 할당 시 메모리 오버플로우 위험

## 핵심 그림
```text
      |       |
      |   C   |  <--- Top (가장 최근에 삽입됨)  --- [ Pop: C 추출 ]
      |   B   |
      |   A   |                                 --- [ Push: D 삽입 시 Top 상승 ]
      +-------+
       [Stack]   (Bottom: 먼저 들어온 A는 C와 B가 나가야 추출 가능)
```

## 핵심 용어
- Top 포인터: 스택의 가장 위에 있는 최신 데이터를 가리키며, 삽입과 삭제의 유일한 기준 위치가 되는 포인터
- 스택 오버플로우(Stack Overflow): 고정된 스택 용량을 초과하여 추가 데이터(Push)를 시도할 때 메모리 범위를 벗어나 발생하는 런타임 예외

## 핵심 통찰
- 프로그램 실행 시 함수의 매개변수, 로컬 변수, 복귀 주소(Return Address)는 OS의 스택 세그먼트에 저장되므로 재귀 깊이가 통제되지 않으면 프로세스가 강제 종료됨
- 괄호 짝 맞추기, 후위 표기법 수식 계산, 브라우저 뒤로 가기, DFS(깊이 우선 탐색)의 근본 메커니즘은 모두 스택의 LIFO 성질을 활용함
- 배열 기반 스택은 구현이 단순하고 캐시 친화적이나 크기가 고정되며, 연결리스트 기반 스택은 동적 확장이 가능하나 포인터 오버헤드가 발생함

## 이웃 토픽과 구분
- 스택 vs 큐: 스택 = 후입선출(LIFO), 되돌리기/역순 처리 / 큐 = 선입선출(FIFO), 작업 대기열/순차 버퍼링

## 문제·원인·대책
- 사례: 138회 기출 운영체제 실행 중 재귀 함수 호출로 인한 프로세스 비정상 크래시
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 대용량 계층형 조직도 순회 시 StackOverflowError 발생 | 종료 조건 누락 또는 지나치게 깊은 재귀 호출로 OS 스택 영역 고갈 | 재귀를 꼬리 재귀(Tail Recursion)로 변환하거나 힙 메모리 명시적 스택 루프로 전환 | 스택 깊이 무관 안정적 루프 실행 |
| 빈 스택에서 데이터 추출 시도시 시스템 크래시 | Pop/Peek 호출 전 IsEmpty 조건 검증 누락(Stack Underflow) | 연산 호출 전 가드 조건(Guard Condition) 및 Optional 래퍼 적용 | 널 포인터 및 언더플로우 결함 방지 |
