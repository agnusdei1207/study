## 한 줄 본질
- 반복적인 CRUD 화면 개발과 인프라 설정에 전문 개발자의 고급 리소스가 낭비되는 생산성 병목 → 표준 UI와 공통 로직은 시각적 드래그 앤 드롭으로 자동 생성하고, 복잡한 비즈니스 규칙만 코드로 작성 → 개발 주기 수개월에서 수주일로 단축 / 플랫폼 벤더 종속 및 생성 코드 최적화 한계 대가

## 핵심 용어
- LCDP(Low-Code Development Platform): GUI 인터페이스를 통해 최소한의 코딩으로 애플리케이션을 신속하게 설계, 개발, 배포할 수 있는 통합 개발 플랫폼
- 하이브리드 개발(Hybrid Development): 표준 컴포넌트는 플랫폼의 시각 도구로 만들고, 기업 고유의 핵심 알고리즘은 전문 개발자가 직접 코딩하여 결합하는 방식

## 핵심 통찰
- 로우코드는 비전공자를 위한 툴이 아니라, 시니어 개발자가 불필요한 보일러플레이트(Boilerplate) 코드를 작성하는 시간을 없애기 위한 고생산성 도구임
- 노코드와 달리 외부 데이터베이스와의 복잡한 트랜잭션 처리, 커스텀 CSS/JS 삽입, 레거시 시스템 API 연동이 자유로움
- 플랫폼이 자동 생성하는 백엔드 소스코드의 품질(가독성, 리팩토링 가능 여부)이 떨어지면 플랫폼 이탈 시 전체 시스템을 다시 짜야 하는 대참사가 발생함

## 이웃 토픽과 구분
- 로우코드 vs 노코드: 로우코드 = 전문 개발자가 커스텀 코드로 기능 무한 확장 가능 / 노코드 = 코딩 불가, 플랫폼이 제공하는 기능 범위에 엄격히 제한

## 문제·원인·대책
- 사례: 138회 기출 기업 신규 기간계 시스템 구축에 로우코드 플랫폼 도입 시나리오
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 특정 로우코드 플랫폼 벤더의 라이선스 비용 300% 인상 시 대안 부재 | 벤더 고유의 폐쇄형 런타임 엔진에 전사 비즈니스 로직 종속 | 표준 Java/Spring 또는 React 소스코드를 추출(Export)할 수 있는 오픈형 LCDP 선정 | 벤더 락인 해소 및 독자적 유지보수 권한 확보 |
| 생성된 자동 코드가 성능 병목을 유발해 대규모 트래픽 처리 실패 | 플랫폼의 일반화된 ORM 쿼리 생성으로 인한 N+1 및 비효율적 풀 스캔 | 핵심 트랜잭션 구간은 로우코드 컴포넌트를 우회하고 네이티브 마이크로서비스로 직접 호출 | 목표 TPS 달성 및 응답 속도 보장 |
