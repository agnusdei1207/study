## 답안 골격
```text
[모델링] ◀━━ 머리: Ⅶ 내 의견 (목적 지향적 추상화와 코드와의 양방향 동기화를 통한 모델 생명력 확보)
 ┃
 ┣━ Ⅰ 개요 ───── 복잡한 현실 세계 문제의 직접 구현 불가 → 본질적 특징 중심의 추상화·단순화·명확화
 ┣━ Ⅱ 특징 ───── 3대 특징(추상화, 단순화, 명확화) · 의사소통 표준화 · 가시화 및 검증 가능성
 ┣━ Ⅲ 구조 ───── 기능 모델링(DFD, UseCase) · 정적/구조 모델링(ERD, Class) · 동적/행위 모델링(State, Sequence)
 ┣━ Ⅳ 흐름 ───── 현실 세계 문제 분석 → 핵심 엔터티/프로세스 추상화 → 모델 표현(UML/ERD) → 구현 및 검증
 ┣━ Ⅴ 비교 ───── 구조적 모델링(데이터와 처리 분리) vs 객체지향 모델링(데이터와 행위 결합)
 ┗━ Ⅵ 실무 ───── 모델링과 구현 코드의 괴리(동기화 실패) / 모델 주도 아키텍처(MDA) 및 코드 자동화
```
- 필수 키워드: 추상화(Abstraction) · 단순화(Simplification) · 명확화(Clarity) · 기능/정적/동적 모델링 · MDA · 4+1 View
- 배점 전략: 10점 = Ⅱ 3대 특성 → Ⅲ 3대 관점(기능, 구조, 행위) 매핑 표 / 25점 = Ⅰ~Ⅶ 전개, 소프트웨어 아키텍처 및 데이터 모델링 연계 발전 방안
- 기출: 133회 3교시 `소프트웨어 모델링 및 요구공학` → Ⅰ·Ⅲ / 128회 1교시 `기계학습 모델링과 모델옵스` → Ⅳ·Ⅵ

## 한 줄 본질
- 소프트웨어 시스템의 규모와 복잡도가 인간의 인지 한계를 초과하여 설계 오류가 폭증하는 병목 → 세부 구현을 배제하고 핵심 도메인 규칙과 구조만을 추상화·단순화·명확화하여 시각적으로 표현 → 시스템 청사진 확립 및 이해관계자 소통 일치 / 과도한 추상화로 인한 현실 왜곡 대가

## 핵심 그림
```text
  [ 현실 세계 복잡성 (Reality) ]
                 |
                 v  (추상화: 핵심만 추출 / 단순화: 군더더기 제거 / 명확화: 애매함 배제)
  +-------------------------------------------------------------+
  |               [ 소프트웨어 3대 모델링 관점 ]                 |
  |                                                             |
  |  1. 기능 모델링 (What)    : 유스케이스 다이어그램, DFD      |
  |  2. 정적/구조 모델링 (Who): 클래스 다이어그램, ERD          |
  |  3. 동적/행위 모델링 (How): 시퀀스 다이어그램, 상태 다이어그램|
  +-------------------------------------------------------------+
                 |
                 v  (구현 및 자동화)
  [ 실행 소프트웨어 코드 및 데이터베이스 ]
```

## 핵심 용어
- 추상화(Abstraction): 복잡한 현실에서 특정 관심사(관점)에 필요한 핵심 요소만을 선별하고 불필요한 세부사항을 과감히 생략하는 작업
- 모델 주도 아키텍처(MDA, Model Driven Architecture): 플랫폼 독립 모델(PIM)을 먼저 작성하고, 변환 규칙을 통해 플랫폼 종속 모델(PSM)과 코드를 자동 생성하는 기술

## 핵심 통찰
- "모든 모델은 틀렸다, 그러나 어떤 모델은 유용하다(George Box)": 모델은 현실의 100% 복제가 아니라 목적에 맞게 왜곡하고 축약한 결과물임
- 모델링의 3대 축인 기능(What), 정적(Structure), 동적(Behavior) 관점 중 하나라도 빠지면 설계에 맹점이 생김
- 코드가 진실이고 모델이 거짓이 되는 순간 모델링은 비용 낭비로 전락하므로, 모델과 코드가 양방향 동기화(Round-trip Engineering)되거나 모델 자체가 코드가 되어야 함

## 이웃 토픽과 구분
- 모델링 vs 아키텍처: 모델링 = 시스템의 특정 관점을 표현하는 기법과 도구 / 아키텍처 = 시스템의 근본적인 구조적 결정과 원칙 그 자체
