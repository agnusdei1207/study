## 답안 골격
```text
[AI 네이티브 개발 플랫폼] ◀━━ 머리: Ⅶ 내 의견 (코드 생성을 넘어선 SDLC 전 주기 자율 에이전트와 보안 검증 가드레일)
 ┃
 ┣━ Ⅰ 개요 ───── 단순 코드 자동완성(Copilot) 한계 극복 → 소프트웨어 생애주기(SDLC) 전반의 AI 네이티브 전환
 ┣━ Ⅱ 특징 ───── 맥락 인식(Context-Aware) · 멀티 에이전트 협업 · 코드베이스 RAG · 자율 디버깅 및 배포
 ┣━ Ⅲ 구조 ───── 코드 지식 그래프(Codebase Graph) · 에이전트 오케스트레이터 · 샌드박스 실행기 · 보안 가드레일
 ┣━ Ⅳ 흐름 ───── 요구사항 프롬프트 입력 → 에이전트 계획 수립 → 코드 작성/테스트 실행 → 오류 시 자율 수정 → PR 생성
 ┣━ Ⅴ 비교 ───── 1세대 AI 코딩(단순 LLM 완성) vs 2세대 AI 네이티브 플랫폼(자율 다중 에이전트 및 환경 통합)
 ┗━ Ⅵ 실무 ───── 환각(Hallucination) 및 라이선스/보안 취약점 주입 / 결정론적 테스트 및 격리 샌드박스
```
- 필수 키워드: AI 네이티브 · 자율 코딩 에이전트 · 코드베이스 RAG · SDLC 자동화 · 가드레일 · Devin/Cursor
- 배점 전략: 10점 = Ⅰ 진화 배경 → Ⅲ 플랫폼 4대 아키텍처 도식 → Ⅴ 1세대 vs 2세대 비교 / 25점 = Ⅰ~Ⅶ 전개, 전사 소프트웨어 개발 생산성 혁신 및 보안 거버넌스 프레임워크
- 기출: 미출제. 예상: AI 네이티브 소프트웨어 개발 플랫폼의 개념, 핵심 구성요소, 전통적 개발 생애주기(SDLC)의 변화 및 도입 시 리스크 대응 방안을 설명하시오.

## 한 줄 본질
- 개발자가 복잡한 아키텍처 문맥을 일일이 프롬프트로 복사해 LLM에 넣고 결과를 수동으로 검증·수정해야 하는 단절 병목 → 코드베이스 전체를 지식 그래프로 인덱싱하고 다중 AI 에이전트가 코딩, 빌드, 테스트, 디버깅을 자율 폐루프(Closed-loop)로 수행 → 소프트웨어 개발 속도 수배 향상 / 비결정론적 코드 생성 및 보안 취약점 대가

## 핵심 그림
```text
  [ Developer (요구사항 정의 & 최종 승인) ]
                     | (자연어 이슈 티켓)
                     v
+--------------------------------------------------------------------+
|  [ AI 네이티브 개발 플랫폼 (AI-Native Dev Platform) ]              |
|                                                                    |
|  [ Agent Orchestrator ] <----> [ Codebase Knowledge Graph / RAG ]  |
|  (Planner / Coder / Reviewer)   (의존성, AST, Git 히스토리 인덱싱) |
|           |                                                        |
|           v (코드 생성 및 터미널 명령 실행)                        |
|  [ Isolated Sandbox Execution Environment ]                        |
|  - 자동 빌드(Build) -> 단위 테스트 실행 -> 에러 로그 자율 디버깅   |
|           |                                                        |
|           v (검증 완료된 Pull Request 생성)                        |
|  [ Security & Compliance Guardrail ]                               |
|  - SAST/DAST 스캔, 오픈소스 라이선스 검증, 시크릿 유출 차단       |
+--------------------------------------------------------------------+
```

## 핵심 용어
- 코드베이스 RAG(Codebase RAG): 프로젝트의 전체 소스코드, 디렉터리 구조, AST(추상구문트리), 커밋 히스토리를 벡터 DB 및 지식 그래프로 색인하여 AI가 프로젝트 전체 문맥을 이해하게 하는 기술
- 폐루프 자율 디버깅(Closed-loop Self-debugging): AI가 생성한 코드를 가상 샌드박스에서 직접 컴파일하고 테스트를 돌려 에러 로그를 확인한 뒤, 오류를 스스로 수정할 때까지 반복하는 메커니즘

## 핵심 통찰
- AI 네이티브 플랫폼은 개발자의 타이핑 속도를 빠르게 해주는 도구가 아니라, "기능 요구사항을 주면 테스트를 통과하는 PR을 스스로 만들어 올리는 주니어 엔지니어" 역할을 수행함
- AI 코딩의 성패는 모델의 크기(파라미터 수)보다 프로젝트의 아키텍처 규칙과 비즈니스 도메인을 AI에게 얼마나 정밀하게 주입하는가(Context Engineering)에 달려 있음
- AI가 짠 코드는 인간이 짠 코드보다 읽기 어렵고 책임을 묻기 어려우므로, "인간의 코드 리뷰"와 "자동화된 엄격한 회귀 테스트 스위트"가 필수적 안전장치가 됨

## 이웃 토픽과 구분
- AI 어시스턴트(Copilot) vs AI 네이티브 플랫폼: 어시스턴트 = IDE 내 단순 라인/함수 단위 자동완성 / AI 네이티브 플랫폼 = 전체 프로젝트를 스스로 읽고 다중 파일 수정 및 빌드·배포까지 완결

## 문제·원인·대책
- 적용 상황: 대규모 엔터프라이즈의 레거시 현대화 및 신규 기능 개발에 AI 에이전트 도입
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| AI가 존재하지 않는 가짜 라이브러리를 import하여 패키지 중독(Poisoning) 위험 | LLM의 환각(Hallucination) 현상 및 사내 승인 패키지 목록 인지 부재 | 사내 사설 패키지 저장소(Nexus/Artifactory) 화이트리스트 가드레일 강제 | 악성 패키지 주입 및 빌드 오류 100% 차단 |
| AI 생성 코드의 오픈소스 저작권 침해 및 하드코딩된 API 키 노출 | 공개 코드 무단 복제 및 보안 취약점 필터링 누락 | PR 생성 전 시크릿 스캐너(TruffleHog) 및 라이선스 SCA 자동 감사 연동 | 법적 분쟁 방지 및 보안 무결성 확보 |

## 이렇게 출제된다
- 미출제. 예상: "최근 생성형 AI 기술의 발전으로 주목받고 있는 AI 네이티브 개발 플랫폼(AI-Native Development Platform)의 개념, 전통적 개발 생애주기(SDLC)의 변화, 핵심 아키텍처 요소 및 엔터프라이즈 도입 시 고려해야 할 보안·품질 리스크 대응 방안을 설명하시오." → 요구 포인트: Ⅰ 패러다임 전환 + Ⅲ 핵심 컴포넌트(에이전트, RAG, 샌드박스) + Ⅵ 보안 거버넌스

## 내 의견
- [AI에게 코딩을 맡겨놓고 방관하는 개발자의 직무유기] AI가 생성한 수천 줄의 코드를 제대로 읽어보지도 않고 머지했다가, 운영 환경에서 원인을 알 수 없는 동시성 버그가 터져 수습하지 못하는 사례 경계 → 나라면: AI 네이티브 플랫폼 도입의 전제 조건으로 테스트 주도 개발(TDD)을 강제하여, 개발자는 엄격한 '테스트 명세서' 작성과 아키텍처 가드레일 수립에 집중하고 AI는 그 테스트를 통과하는 구현 코드 작성을 전담하는 공학적 분업 체계 구축
