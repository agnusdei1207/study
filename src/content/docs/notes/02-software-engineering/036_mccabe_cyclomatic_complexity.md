## 답안 골격
```text
[순환복잡도] ◀━━ 머리: Ⅶ 내 의견 (정적 분석 파이프라인에서 복잡도 10 초과 시 리팩토링 강제)
 ┃
 ┣━ Ⅰ 개요 ───── 코드 제어 흐름의 복잡성 정량화 및 화이트박스 테스트를 위한 선형 독립 경로 수 산출
 ┣━ Ⅱ 특징 ───── 토마스 맥케이브 정립 · 그래프 이론 기반 · 프로그램 오류 가능성 및 테스트 비용 예측
 ┣━ Ⅲ 구조 ───── 제어 흐름 그래프(CFG): 노드(N), 간선(E), 분기 판정 노드(P), 닫힌 영역(R)
 ┣━ Ⅳ 흐름 ───── 소스코드 작성 → 제어 흐름 그래프 변환 → 복잡도 계산 공식 적용 → 독립 경로 집합 도출
 ┣━ Ⅴ 비교 ───── $V(G) = E - N + 2P$ vs $V(G) = P + 1$ vs $V(G) = R$ 3대 산출 공식
 ┗━ Ⅵ 실무 ───── 중첩 조건문 남발로 인한 복잡도 폭증 / 조기 반환(Guard Clause) 및 다형성 리팩토링
```
- 필수 키워드: 토마스 맥케이브 · 제어 흐름 그래프(CFG) · 선형 독립 경로 · $V(G) = E - N + 2P$ · $P + 1$ · 기저 경로 테스트(Basis Path Testing)
- 배점 전략: 10점 = Ⅰ 정의 → Ⅲ CFG 그래프 도식 및 3가지 계산 공식 / 25점 = Ⅰ~Ⅶ 전개, 실제 코드 예시를 통한 CFG 도출 및 테스트 케이스 설계
- 기출: 139회 1교시 `맥케이브 순환복잡도(McCabe’s Cyclomatic Complexity)` → Ⅰ·Ⅲ·Ⅴ

## 한 줄 본질
- 소프트웨어 내부 제어 로직이 얼마나 복잡한지 주관적 인상에만 의존해 결함 위험과 필요한 테스트 양을 측정할 수 없는 병목 → 제어 흐름 그래프의 간선, 노드, 분기점 수를 바탕으로 실행 가능한 선형 독립 경로의 수($V(G)$)를 수학적으로 정량화 → 최소 테스트 케이스 상한선 제시 및 코드 분할 기준 수립 / 복합 데이터 흐름의 복잡성은 반영하지 못하는 한계

## 핵심 그림
```text
  [ 제어 흐름 그래프 (CFG) ]
         ( 1 )  <--- 시작 노드
         /   \
       ( 2 ) ( 3 )
         \   /
         ( 4 )  <--- 분기 합류
           |
         ( 5 )  <--- 종료 노드
  * 간선 수 (E) = 5
  * 노드 수 (N) = 5
  * 분기 판정 노드 수 (P) = 1 (노드 1)
  * 순환 복잡도 V(G) = E - N + 2 = 5 - 5 + 2 = 2 (또는 P + 1 = 1 + 1 = 2)
  * 독립 경로: Path 1: 1->2->4->5 / Path 2: 1->3->4->5
```

## 핵심 용어
- 선형 독립 경로(Independent Path): 제어 흐름 그래프에서 적어도 하나의 새로운 간선(Edge)을 포함하는 실행 경로
- 기저 경로 테스팅(Basis Path Testing): 산출된 순환 복잡도 $V(G)$만큼의 독립 경로 집합을 도출하여 모든 실행 문장과 분기를 최소 1회 이상 검증하는 화이트박스 기법

## 핵심 통찰
- 맥케이브 공식에서 단일 진입/단일 진출 프로그램의 경우 $V(G) = P + 1$ (단순 분기문 수 + 1)로 암산이 가능하여 코드 리뷰에서 즉시 활용할 수 있음
- 복합 조건문(`if (A && B)`)은 분기 노드가 2개로 쪼개지므로 단일 if문이라도 복잡도가 2가 됨
- SEI 및 전산학 통계에 따르면 $V(G)$가 1~10이면 안정적이고 구조가 단순하지만, 11~20은 위험도 중간, 21~50은 복잡하고 오류 가능성 높음, 50 초과는 테스트가 불가능한 코드로 분류됨

## 이웃 토픽과 구분
- 순환 복잡도 vs 인지 복잡도(Cognitive Complexity): 순환 복잡도 = 테스트 경로 수 산출용 수학적 분기 측정 / 인지 복잡도 = 중첩(Nesting) 구조에 가중치를 두어 인간의 코드 가독성 난이도 측정

## 문제·원인·대책
- 사례: 139회 기출 복잡한 할인 정책 계산 모듈의 잦은 런타임 오류
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 단일 메서드에 5중 if문이 중첩되어 복잡도 $V(G)=35$ 초과 | 신규 예외 정책이 추가될 때마다 else if문을 덧붙인 스파게티 코드 | 가드 절(Guard Clauses) 조기 반환 및 전략(Strategy) 패턴 객체 분할 | 메서드 복잡도를 5 이하로 낮추고 테스트 용이성 확보 |
| 테스트 코드를 작성했음에도 특정 할인 분기에서만 지속 결함 발생 | 선형 독립 경로의 수보다 적은 테스트 케이스 작성으로 분기 누락 | 기저 경로 테스팅 기법을 적용하여 정확히 $V(G)$개 독립 경로 케이스 작성 | 코드 내부 분기 커버리지 100% 달성 |
