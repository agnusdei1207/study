## 답안 골격
```text
[FTA] ◀━━ 머리: Ⅶ 내 의견 (최소 컷셋 기반의 크리티컬 경로 제거 및 FMEA와의 양방향 안전성 검증)
 ┃
 ┣━ Ⅰ 개요 ───── 시스템 치명적 사고(Top Event) 원인 추적 → 불 대수 기반 하향식·연역적 안전성 분석
 ┣━ Ⅱ 특징 ───── 하향식(Top-Down) · 연역적(Deductive) · 정성적(최소 컷셋) 및 정량적(고장 확률) 분석 병행
 ┣━ Ⅲ 구조 ───── 정상 사상(Top Event) / 중간 사상 / 기본 사상(Basic Event) / 논리 게이트(AND, OR)
 ┣━ Ⅳ 흐름 ───── 대상 시스템 정의 → Top 사상 선정 → 결함수 트리 전개 → 불 대수 간소화 → 최소 컷셋 도출 및 확률 계산
 ┣━ Ⅴ 비교 ───── FTA(하향식, 연역적, 사고 원인 분석) vs FMEA(상향식, 귀납적, 부품 고장 영향 분석) vs HAZOP(공정/가이드단어)
 ┗━ Ⅵ 실무 ───── 시스템 대형화로 인한 트리 복잡도 폭증 / MOCUS 알고리즘 자동화 및 임베디드 기능안전(ISO 26262) 적용
```
- 필수 키워드: 결함 수 분석 · 하향식(Top-Down) · 연역적 · 정상 사상(Top Event) · 기본 사상 · 논리 게이트(AND/OR) · 최소 컷셋(MCS)
- 배점 전략: 10점 = Ⅰ 정의 → Ⅲ 결함수 다이어그램 및 게이트 기호 도식 → Ⅴ FTA vs FMEA 비교 / 25점 = Ⅰ~Ⅶ 전개, 불 대수 간소화를 통한 최소 컷셋(Minimal Cut Set) 산출 수학적 예시
- 기출: 131회 1교시 `소프트웨어 안전성 분석 기법인 FTA의 개념, 절차, 최소 컷셋` → Ⅰ~Ⅴ / 108회 1교시 `FTA 기호 및 분석 방법` → Ⅲ·Ⅳ

## 한 줄 본질
- 시스템 고장이 발생했을 때 어떤 복합 결함들이 겹쳐서 사고를 유발했는지 상향식으로는 역추적하기 어려운 병목 → 최상위 사고(Top Event)에서 출발하여 논리 게이트(AND/OR)로 원인 결함들을 연역적 트리로 분해 → 최소 컷셋(Minimal Cut Set) 도출을 통한 약점 제거 / 대규모 시스템의 트리 작성 비용 과다

## 핵심 그림
```text
+-------------------------------------------------------------------+
|               FTA (Fault Tree Analysis) 다이어그램 구조           |
+-------------------------------------------------------------------+
|                  [ 정상 사상 (Top Event) : 시스템 정지 ]          |
|                                     |                             |
|                                  [ OR ]                           |
|                    +----------------+----------------+            |
|                    |                                 |            |
|          [ 중간 사상 : 전원 상실 ]         [ 중간 사상 : SW 크래시 ] |
|                    |                                 |            |
|                 [ AND ]                            ( O ) 기본사상 |
|          +---------+---------+                      (메모리 누수) |
|          |                   |                                    |
|       ( X1 )              ( X2 )                                  |
|   (상용 전원 단전)    (UPS 배터리 방전)                           |
|                                                                   |
| * 컷셋(Cut Set) : {X1, X2}, {SW크래시}                            |
| * 최소 컷셋(MCS): 시스템 고장을 일으키는 최소 기본 사상들의 조합 |
+-------------------------------------------------------------------+
```

## 핵심 용어
- 정상 사상(Top Event): 결함수 트리의 최상단에 놓이는, 분석 대상이 되는 가장 바람직하지 않은 시스템 전체의 치명적 사고 또는 고장
- 최소 컷셋(Minimal Cut Set, MCS): 그 안에 포함된 모든 기본 사상이 동시에 발생할 때 반드시 Top Event를 일으키는 기본 사상들의 '최소한의 부분집합'

## 핵심 통찰
- OR 게이트 아래의 기본 사상은 단 하나만 터져도 시스템 전체를 죽이는 단일 장애점(SPOF)이므로, 아키텍처 개선 시 OR 게이트를 AND 게이트(이중화)로 바꾸는 것이 핵심임
- 불 대수(Boolean Algebra)의 흡수 법칙($A + AB = A$)과 분배 법칙을 사용하여 결함수를 간소화함으로써, 시스템을 무너뜨리는 가장 취약한 경로(MCS)를 수학적으로 특정함
- 소프트웨어 FTA(Soft-FTA)는 하드웨어 부품 고장뿐 아니라 소프트웨어의 무한 루프, 버퍼 오버플로우, 교착상태(Deadlock)를 기본 사상으로 정의하여 기능안전을 입증함

## 이웃 토픽과 구분
- FTA vs FMEA: FTA = "비행기 추락(결과)"에서 출발하여 무엇이 원인인지 파고 내려가는 '하향식·연역적' 분석 / FMEA = "볼트 하나 풀림(부품 고장)"에서 출발하여 시스템에 어떤 영향이 갈지 파악하는 '상향식·귀납적' 분석

## 문제·원인·대책
- 사례: 131회 기출 자율주행 제어 SW에서 단일 센서 오류로 인한 급제동 사고 분석
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 카메라 센서 하나에 햇빛이 반사되어 전방 차량 오인식 및 비상 제동 | 카메라 인식 모듈이 단일 OR 게이트로 제동 시스템에 직결된 아키텍처 | LiDAR, Radar 융합 다중화 및 2-out-of-3 다수결 AND 판정 게이트 전환 | 단일 센서 오작동으로 인한 사고 발생 확률 $10^{-6}$ 이하로 격하 |
| 복잡한 철도 신호 제어 시스템의 FTA 트리가 너무 방대하여 수작업 분석 불가 | 500개 이상의 컴포넌트 간 상호작용으로 컷셋 계산 한계 | MOCUS(Method for Obtaining Cut Sets) 알고리즘 기반 FTA 자동화 도구 도입 | 수만 개 결함 경로 중 최소 컷셋(MCS) 5개 즉각 추출 |

## 이렇게 출제된다
- 제131회 1교시: "소프트웨어 안전성 분석 기법인 결함 수 분석(FTA, Fault Tree Analysis)의 개념, 연역적 분석 절차 및 불 대수(Boolean Algebra) 기반 최소 컷셋(Minimal Cut Set)" → 요구 포인트: Ⅰ 정의 + Ⅲ 기호(Top/기본/AND/OR) + Ⅳ 절차 + 최소 컷셋 산출 원리
- 제108회 1교시: "소프트웨어 안전성 분석을 위한 FTA 기법" → 요구 포인트: 정성적 분석(MCS)과 정량적 분석(고장 확률 계산)의 차이점

## 내 의견
- [사고가 난 뒤에야 면피용 보고서로 그리는 사후약방문식 FTA] 시스템을 다 개발해 놓고 인증 심사를 통과하기 위해 형식적으로 결함수 트리를 거꾸로 끼워 맞추는 문서주의 만연 → 나라면: 아키텍처 상세 설계 단계에서 소프트웨어 FTA를 선행 수행하여 OR 게이트로 연결된 단일 결함 실패 지점을 전수 식별하고, 회로 차단기(Circuit Breaker)와 워치독 타이머를 소프트웨어 설계에 강제 반영하는 선제적 안전 엔지니어링 수행
