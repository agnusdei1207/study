## 답안 골격
```text
[노코드(No Code)] ◀━━ 머리: Ⅶ 내 의견 (비즈니스 민첩성과 섀도우 IT 통제를 위한 거버넌스 수립)
 ┃
 ┣━ Ⅰ 개요 ───── 개발 인력 부족 및 비즈니스 변화 속도 대응 지연 → GUI 블록 기반 비전문가 앱 개발
 ┣━ Ⅱ 특징 ───── 드래그 앤 드롭 UI · 사전 정의 템플릿 · 제로 코딩 · 빠른 MVP 검증
 ┣━ Ⅲ 구조 ───── Visual Builder · Workflow Engine · Data Model Connector · Prebuilt Integrations
 ┣━ Ⅳ 흐름 ───── ① 템플릿 선택 → ② 드래그 앤 드롭 UI 배치 → ③ 워크플로 트리거 연결 → ④ 즉시 배포
 ┣━ Ⅴ 비교 ───── 노코드(시민 개발자, 완전 비코딩) vs 로우코드(전문 개발자 생산성 증대, 커스텀 코드 허용)
 ┗━ Ⅵ 실무 ───── 벤더 락인 및 섀도우 IT 보안 위험 / 플랫폼 표준화 및 API 게이트웨이 연계
```
- 필수 키워드: 시민 개발자(Citizen Developer) · 드래그 앤 드롭 · 워크플로 엔진 · 섀도우 IT · 벤더 락인 · 로우코드 비교
- 배점 전략: 10점 = Ⅰ 정의 → Ⅲ 시각적 컴포넌트 구조 → Ⅴ 로우코드 비교 / 25점 = Ⅰ~Ⅶ 전개, Ⅵ 거버넌스 및 엔터프라이즈 보안 체계
- 기출: 130회 1교시 `노코드` → Ⅰ·Ⅱ·Ⅲ / 138회 3교시 `로우코드 플랫폼 적용` → Ⅴ 비교 및 Ⅵ 도입 고려사항

## 한 줄 본질
- 전문 개발자 공급 부족과 현업 요구사항의 긴 대기시간(Backlog) 병목 → 시각적 컴포넌트 조립과 사전 구축된 API 연동으로 코딩 없이 현업이 직접 소프트웨어 구축 → 시장 진입 시간(TTM) 획기적 단축 / 복잡한 비즈니스 로직 구현 불가 및 벤더 종속성 대가

## 핵심 그림
```text
[ Citizen Developer (현업) ]
          | (Drag & Drop)
```

## 핵심 용어
- 시민 개발자(Citizen Developer): 전문 프로그래밍 지식이 없으나 노코드 도구를 활용해 업무용 애플리케이션을 직접 개발하는 현업 사용자
- 섀도우 IT(Shadow IT): 중앙 IT 부서의 승인이나 보안 통제 없이 현업 조직에서 독자적으로 도입·운영하는 시스템 및 소프트웨어

## 핵심 통찰
- 노코드는 전문 개발자를 대체하는 기술이 아니라, 단순 사내 양식·승인 업무를 현업으로 이관해 개발자가 핵심 코어 비즈니스에 집중하도록 돕는 탈중앙화 수단임
- 플랫폼 내부 데이터 저장소에 데이터가 갇히면(Silo) 기업 전체 데이터 파이프라인과 단절되어 장기적인 분석 자산화가 불가능해짐
- 비즈니스 로직이 조금이라도 복잡해지면 노코드 플랫폼 내부의 규칙 엔진 한계에 부딪혀 결국 로우코드나 프로코딩(Pro-code)으로 재개발해야 함

## 이웃 토픽과 구분
- 노코드 vs 로우코드: 노코드 = 프로그래밍 언어 배제, 현업 업무 자동화 중심 / 로우코드 = 스크립트·확장 코드 허용, 전문 개발자의 엔터프라이즈 앱 구축 가속

## 문제·원인·대책
- 사례: 138회 기출 신규 정보시스템 개발 시 로우코드/노코드 플랫폼 적용 시나리오
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 현업 제작 앱의 사내 보안 규정 미준수로 민감정보 유출 | 중앙 IT 부서의 보안 검수 체계 밖에서 생성되는 섀도우 IT | 플랫폼 단의 SSO 연동, RBAC 인가 통제 및 중앙 승인 워크플로 구축 | 규제 준수 및 접근 제어 무결성 확보 |
| 플랫폼 벤더 비용 인상 및 서비스 중단 시 대안 부재 | 특정 상용 노코드 SaaS의 독점적 런타임 종속(Vendor Lock-in) | OpenAPI/표준 JSON 인터페이스 강제 및 데이터 백업 주기 수립 | 시스템 전환 및 비즈니스 연속성 위험 완화 |

- 제138회 3교시 2번: "A사는 신규 정보시스템 개발 프로젝트에 로우코드(Low Code)플랫폼을 적용하고자 한다. 다음 내용을 설명하시오." → 요구 포인트: Ⅴ 로우코드/노코드 비교 + Ⅵ 엔터프라이즈 아키텍처 연계 및 한계점 극복 방안

## 내 의견
- [통제 없는 노코드 확산이 부른 사내 보안 구멍] 마케팅·영업 부서에서 독자적으로 노코드 툴을 사용해 고객 개인정보를 외부 SaaS DB에 저장하고 방치하는 보안 사고 빈번 → 나라면: 전사 노코드 플랫폼 사용 가이드를 제정하고, 사내 API 게이트웨이를 통과하지 않는 외부 DB 직접 연결을 원천 차단하며, 생성된 앱의 6개월 주기 사용성 감사 및 휴면 앱 자동 폐기 정책 시행
