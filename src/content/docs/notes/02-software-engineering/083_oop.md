## 한 줄 본질
- 전역 변수와 함수가 따로 놀아 어디서 데이터가 오염됐는지 추적할 수 없는 절차지향의 스파게티 병목 → 데이터(상태)와 이를 조작하는 함수(행위)를 단일 객체로 묶고 메시지를 통해 협력 → 코드 재사용성과 유지보수성 극대화 / 초기 객체 모델링 설계 비용과 런타임 간접 호출 비용

## 핵심 그림
```text
+-------------------------------------------------------------------+
|               객체지향(OOP) 4대 핵심 메커니즘                     |
+-------------------------------------------------------------------+
| 1. 추상화 (Abstraction) : 공통 특성과 행위를 추출하여 클래스 정의  |
| 2. 캡슐화 (Encapsulation): 데이터 은닉 및 메서드를 통한 안전한 접근|
| 3. 상속성 (Inheritance)  : 부모 클래스의 속성/행위를 자식이 재사용|
| 4. 다형성 (Polymorphism) : 동일한 메시지에 대해 객체별 다르게 반응 |
+-------------------------------------------------------------------+
                                  |
                                  v (협력 방식)
    [ 객체 A ] ------(메시지 전송: order.pay())------> [ 객체 B ]
```

## 핵심 용어
- 다형성(Polymorphism): 하나의 인터페이스나 추상 클래스를 통해 여러 다른 형태의 구체 클래스들이 각자의 방식으로 동작할 수 있는 능력(오버라이딩, 오버로딩)
- 메시지 패싱(Message Passing): 객체가 다른 객체의 상태를 직접 변경하지 않고, 공개된 메서드를 호출하여 협력을 요청하는 상호작용 방식

## 핵심 통찰
- OOP의 본질은 '클래스를 상속받는 것'이 아니라, '책임을 가진 자율적인 객체들이 메시지를 주고받으며 협력하는 네트워크'를 구성하는 것임
- 무분별한 클래스 상속(Inheritance)은 부모와 자식 간의 강한 결합을 낳으므로, 현대 OOP에서는 "상속보다는 조합(Composition over Inheritance)"을 원칙으로 삼음
- 상태를 보호하지 않고 단순히 모든 필드에 Getter/Setter를 열어두는 것은 절차지향 데이터 구조체와 다를 바 없는 '빈약한 도메인 모델(Anemic Domain Model)' 안티패턴임

## 이웃 토픽과 구분
- OOP vs 절차지향(POP): POP = 데이터(Data)와 처리(Function)가 분리되어 순차적 알고리즘 흐름을 따름 / OOP = 데이터와 처리가 하나로 묶인 객체(Object) 간의 메시지 협력 흐름을 따름

## 문제·원인·대책
- 사례: 125회 기출 레거시 C언어 기반 시스템의 유지보수 한계로 인한 Java OOP 차세대 전환
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 전역 구조체 변수를 수백 개 함수가 공유하여 한 곳 수정 시 연쇄 결함 폭발 | 절차지향(POP) 방식의 전역 데이터 노출 및 캡슐화 부재 | 데이터와 연관 비즈니스 로직을 객체 내부로 캡슐화(private 필드화) | 데이터 오염 원천 차단 및 모듈 독립성 확보 |
| 신규 업무 추가 시마다 수천 줄짜리 거대 switch-case 문을 수정 | 다형성 없는 절차적 분기문 남발 | 공통 인터페이스 추출 및 다형적(Polymorphic) 구현체 위임 구조 전환 | 분기문 제거 및 신규 업무 클래스 추가만으로 확장 |

## 내 의견
- [객체지향과 함수형 프로그래밍의 맹목적 이분법 탈피] 객체지향은 구식이고 함수형(Functional)만이 정답이라는 식의 극단적 유행주의 경계 → 나라면: 도메인의 상태와 비즈니스 불변식은 풍부한 객체지향(OOP) 엔티티로 캡슐화하고, 데이터 변환과 스트림 연산(Stream API, Lambda)은 순수 함수형 기법을 결합하는 '실용적 객체-함수형 하이브리드 아키텍처' 채택
