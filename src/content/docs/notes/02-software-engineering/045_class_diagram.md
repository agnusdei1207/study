## 답안 골격
```text
[클래스 다이어그램] ◀━━ 머리: Ⅶ 내 의견 (집약·합성의 엄격한 생명주기 구분과 도메인 주도 설계(DDD) 모델링 연계)
 ┃
 ┣━ Ⅰ 개요 ───── 객체지향 시스템의 정적 구조를 정의하고 클래스 간의 관계를 시각화하는 핵심 다이어그램
 ┣━ Ⅱ 특징 ───── 정적 구조 모델링 · 속성과 메서드의 캡슐화 표현 · 관계의 다형성(연관, 집약, 합성, 상속, 실체화)
 ┣━ Ⅲ 구조 ───── 3단 박스(이름, 속성, 오퍼레이션) + 가시성(+, -, #, ~) + 5대 관계 표기법
 ┣━ Ⅳ 흐름 ───── 클래스 식별 → 속성/오퍼레이션 정의 → 다중성(Multiplicity) 및 관계선 연결 → 인터페이스 실체화
 ┣━ Ⅴ 비교 ───── 집약 관계(Aggregation, 빈 마름모, 느슨한 결합) vs 합성 관계(Composition, 채운 마름모, 강한 결합)
 ┗━ Ⅵ 실무 ───── 상속 남용으로 인한 결합도 증대 / 합성(Composition) 우선 원칙 적용
```
- 필수 키워드: 정적 모델링 · 3단 구획 · 가시성(+,-,#) · 다중성(1..*) · 연관 · 일반화(상속) · 집약(Aggregation) · 합성(Composition)
- 배점 전략: 10점 = Ⅲ 클래스 3단 표기 및 관계선 심볼 도식 → Ⅴ 집약 vs 합성 비교 / 25점 = Ⅰ~Ⅶ 전개, 126회 기출 주사위 게임 시나리오 기반 클래스 다이어그램 모델링
- 기출: 126회 2교시 `주사위 게임 시퀀스 및 클래스 다이어그램 작성` → Ⅲ·Ⅳ / 122회 4교시 `학생과 수강신청 관계 기반 클래스 다이어그램 작성` → Ⅲ·Ⅴ

## 한 줄 본질
- 시스템을 구성하는 클래스들의 속성과 행위, 그리고 상호 의존 관계를 파악하지 못해 발생하는 구조적 결함 병목 → 클래스 박스와 표준 관계 기호(연관, 일반화, 의존, 집약, 합성)를 통해 정적 아키텍처 청사진을 정의 → 객체지향 설계의 청사진 확립 및 데이터 무결성 보장 / 런타임 동적 상호작용 표현 불가 대가

## 핵심 그림
```text
+-----------------------+                    +-----------------------+
| <<interface>>         |                    | ClassName             |
| RemoteControl         |                    +-----------------------+
+-----------------------+                    | - privateField: int   |
| + turnOn(): void      |                    | # protectedField: str |
+-----------------------+                    | + publicField: boolean|
          ^                                  +-----------------------+
          | (실체화: 점선+삼각형)            | + publicMethod(): void|
+-----------------------+                    +-----------------------+
| Television            |                               |
+-----------------------+                               | 1
          | 1                                           | (연관)
          |                                             |
          * (합성: 채운마름모)                           v 0..*
+-----------------------+                    +-----------------------+
| Screen (생명주기 종속) |                    | OrderItem             |
+-----------------------+                    +-----------------------+
```

## 핵심 용어
- 집약(Aggregation, 공유 집합): '전체(Whole)'와 '부분(Part)'의 관계이나, 전체 객체가 소멸해도 부분 객체는 독립적으로 생존 가능한 약한 결합(빈 마름모 `◇`)
- 합성(Composition, 복합 집합): '전체'가 '부분'의 생명주기를 완전히 소유하여 전체 객체가 소멸하면 부분 객체도 함께 소멸하는 강한 결합(채운 마름모 `◆`)

## 핵심 통찰
- 일반화(Generalization, 상속)는 코드 재사용 목적이 아니라 다형성(Polymorphism)을 통한 대체 가능성(LSP 원칙)을 보장할 때만 사용해야 함
- 실무 모델링에서 가장 자주 혼동하는 표기는 집약과 합성임: 자동차와 타이어는 타이어를 떼어내 다른 차에 쓸 수 있으므로 '집약'이지만, 컴퓨터와 CPU/마더보드는 '합성'으로 해석됨
- 도메인 주도 설계(DDD)의 애그리게잇 루트(Aggregate Root)와 내부 엔터티 간의 관계는 정확히 UML의 '합성(Composition)' 관계와 1:1로 일치함

## 이웃 토픽과 구분
- 의존(Dependency) vs 연관(Association): 의존 = 메서드 인자나 로컬 변수로 일시적 참조(점선 화살표) / 연관 = 클래스의 인스턴스 멤버 변수로 영구적 참조(실선 화살표)
