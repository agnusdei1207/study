## 답안 골격
```text
[재공학] ◀━━ 머리: Ⅶ 내 의견 (빅뱅 재개발 지양 및 스트랭글러 패턴 기반 점진적 재공학)
 ┃
 ┣━ Ⅰ 개요 ───── 레거시 시스템 노후화 및 유지보수 한계 → 기존 자산 분석·재구조화로 수명 연장
 ┣━ Ⅱ 특징 ───── 3R(Reverse, Re-structure, Re-use) 통합 · 위험 및 비용 최소화 · 비즈니스 연속성
 ┣━ Ⅲ 구조 ───── 분석(Analysis) → 재구성(Restructuring) → 역공학(Reverse) → 순공학(Forward)
 ┣━ Ⅳ 흐름 ───── ① 레거시 소스 분석 → ② 상위 설계 모델 추출(역공학) → ③ 신규 아키텍처 재설계 → ④ 재구현(순공학)
 ┣━ Ⅴ 비교 ───── 신규 개발(Greenfield) vs 재공학(Re-engineering) vs 유지보수(Maintenance)
 ┗━ Ⅵ 실무 ───── 기존 비즈니스 룰 누락 및 전환 리스크 / 스트랭글러 피그(Strangler Fig) 패턴
```
- 필수 키워드: 3R · 역공학 · 재구조화 · 순공학 · 소프트웨어 수명주기 · 스트랭글러 패턴
- 배점 전략: 10점 = Ⅰ 정의 → Ⅲ 4단계 활동 및 3R 개념도 → Ⅴ 신규 개발 대비 비교 / 25점 = Ⅰ~Ⅶ 전개, 역공학과 순공학의 연계 및 단계적 마이그레이션
- 기출: 137회 1교시 `역공학과 재공학` → Ⅲ·Ⅴ / 138회 2교시 `유지보수를 위한 재공학과 역공학` → Ⅲ·Ⅵ

## 한 줄 본질
- 수십 년간 누적된 레거시 시스템을 전면 폐기하고 새로 개발할 때 따르는 천문학적 비용과 실패 위험 병목 → 기존 시스템의 소스와 데이터를 역공학하여 설계를 복원하고 현대적 아키텍처로 재구축(순공학) → 시스템 유지보수성 회복 및 자산 재활용 / 숨겨진 비즈니스 룰 유실 위험

## 핵심 그림
```text
  [ 기존 레거시 시스템 ]                           [ 재공학된 신규 시스템 ]
+----------------------+                       +-----------------------+
|  요구사항 / 명세서   | ====================> |   신규 요구 / 명세    |
+----------------------+                       +-----------------------+
          ^                                                |
          | (역공학: 추상화)                               | (순공학: 구체화)
+----------------------+                       +-----------------------+
|   상세 설계 모델     | -- (재구조화/개선) -> |   개선된 설계 모델    |
+----------------------+                       +-----------------------+
          ^                                                |
          | (분석)                                         v (구현)
+----------------------+                       +-----------------------+
|    기존 소스코드     |                       |    현대적 소스코드    |
+----------------------+                       +-----------------------+
```

## 핵심 용어
- 3R: 소프트웨어 유지보수 비용 절감을 위한 핵심 3대 기술인 역공학(Reverse Engineering), 재구조화(Restructuring), 재사용(Re-use)
- 스트랭글러 피그(Strangler Fig) 패턴: 노후된 레거시 시스템의 외곽 기능부터 신규 마이크로서비스로 하나씩 이전하여 점진적으로 교체하는 재공학 전략

## 핵심 통찰
- 재공학의 본질은 코드를 단순히 최신 언어로 바꾸는 것이 아니라, 문서화되지 않은 채 코드 속에 묻힌 비즈니스 규칙(Dark Logic)을 발굴하는 데 있음
- 빅뱅(Big-bang) 방식의 전면 재구축은 80% 이상의 프로젝트가 납기 지연이나 실패로 끝나므로, 재공학을 통한 점진적 전환이 엔터프라이즈의 표준 전략임
- 역공학 없는 재공학은 불가능하며, 정적/동적 분석 도구를 통한 아키텍처 복원이 선행되어야 함

## 이웃 토픽과 구분
- 재공학 vs 역공학: 재공학 = 역공학을 포함하여 시스템을 전체적으로 새롭게 재구축하는 전체 프로세스 / 역공학 = 코드로부터 설계를 추출하는 분석 기법

## 문제·원인·대책
- 사례: 138회 기출 금융권 메인프레임 코볼 시스템의 클라우드 자바 재공학 사업
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 소스코드 변환 후 연말정산 등 특정 조건 정산 오차 발생 | 주석 없는 예외 분기문 및 코드 내부 암묵적 비즈니스 룰 누락 | 역공학 정적 분석 도구로 비즈니스 룰 엔진 분리 추출 및 병렬 검증 | 기존 금융 업무 정산 무결성 100% 보장 |
| 구시스템과 신시스템 간 데이터 불일치 및 동기화 실패 | 전면 전환 시 대량 트랜잭션 마이그레이션 실패 | CDC(Change Data Capture) 기반 듀얼 라이트 및 단계적 트래픽 전환 | 데이터 유실 제로 및 장애 시 즉시 롤백 보장 |

## 이렇게 출제된다
- 제137회 1교시 11번: "소프트웨어 역공학과 재공학을 설명하시오." → 요구 포인트: Ⅰ 각 개념 + Ⅲ 상호 관계도 + Ⅴ 차이점
- 제138회 2교시 5번: "소프트웨어 유지보수를 위한 재공학(Re-engineering)과 역공학(Reverse-engineering)에 대하여 다음 내용을 설명하시오." → 요구 포인트: Ⅲ 3R 체계 + Ⅳ 4단계 프로세스 + Ⅵ 엔터프라이즈 마이그레이션 전략

## 내 의견
- [문서 없는 레거시 전면 재개발의 오만] 기존 시스템이 낡았다고 무작정 폐기하고 새로 짜겠다고 덤볐다가, 지난 10년간 패치된 수만 가지 현업 예외 규칙을 구현하지 못해 오픈 당일 서비스가 마비되는 참사를 목격 → 나라면: 스트랭글러 패턴을 채택하여 게이트웨이 레벨에서 트래픽을 5% 단위로 신규 서비스로 넘기며 듀얼 런(Dual Run)으로 입출력 일치 여부를 매일 교차 검증
