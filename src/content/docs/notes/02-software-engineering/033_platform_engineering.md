## 한 줄 본질
- DevOps의 "You Build It, You Run It" 원칙으로 인해 개발자가 쿠버네티스, 테라폼, 네트워크, 보안 설정까지 도맡으면서 본업인 코딩에 집중하지 못하는 인지 부하 병목 → 인프라의 복잡성을 내부 개발자 플랫폼(IDP) 뒤로 추상화하고 셀프서비스 템플릿(황금 경로)을 제공 → 개발자 경험(DevEx) 극대화 및 배포 표준화 / 플랫폼 전담 엔지니어링 팀 구성 비용


## 핵심 용어
- 내부 개발자 플랫폼(IDP, Internal Developer Platform): 개발자가 인프라 지식 없이도 애플리케이션 실행 환경을 자율적으로 구성·배포할 수 있도록 지원하는 셀프서비스 도구 모음
- 황금 경로(Golden Path / Paved Road): 플랫폼 팀이 보안, 가용성, 모니터링 모범 사례를 미리 통합해 놓아 개발자가 가장 쉽고 안전하게 따를 수 있는 표준 템플릿 경로

## 핵심 통찰
- 플랫폼 엔지니어링은 DevOps의 실패가 아니라, DevOps가 대규모 엔터프라이즈로 확장되면서 발생한 개발자 피로(Developer Burnout)를 해결하기 위한 자연스러운 진화임
- 플랫폼 팀은 "명령하고 통제하는 인프라 관리자"가 아니라, 사내 개발자를 고객으로 삼아 플랫폼을 개선하는 "제품 관리 팀(Product Team)"으로 행동해야 함
- 황금 경로는 강제 규정이 아니라, 개발자가 스스로 "직접 쿠버네티스 야믈(YAML)을 짜는 것보다 플랫폼을 쓰는 게 훨씬 편하다"고 느껴 자발적으로 선택하게 만들어야 성공함

## 이웃 토픽과 구분
- DevOps vs 플랫폼 엔지니어링: DevOps = 개발과 운영의 장벽을 허무는 문화적 원칙 / 플랫폼 엔지니어링 = 그 원칙을 실현하기 위해 개발자에게 제공하는 구체적 플랫폼 인프라 제품

## 문제·원인·대책
- 적용 상황: 수십 개 마이크로서비스 개발팀을 보유한 대규모 클라우드 네이티브 기업
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 신규 서비스 개발 시 인프라 생성 및 배포 파이프라인 구성에만 2주 소요 | 팀마다 쿠버네티스 매니페스트와 CI 스크립트를 밑바닥부터 수작업 복제 | Backstage 기반 IDP에 표준 스프링/노드 서비스 템플릿(Golden Path) 탑재 | 신규 서비스 온보딩 시간 2주에서 10분으로 단축 |
| 인프라 설정 오류로 인한 보안 그룹 오설정 및 클라우드 비용 낭비 | 개별 개발자의 인프라 지식 편차 및 중앙 보안 통제 부재 | 플랫폼 오케스트레이터에 정책 기반 코드(OPA/Kyverno) 자동 내재화 | 컴플라이언스 100% 자동 충족 및 유휴 자원 자동 회수 |

## 이렇게 출제된다
- 미출제. 예상: "클라우드 네이티브 환경에서 개발자 경험(DevEx) 향상과 인지 부하 경감을 위한 플랫폼 엔지니어링(Platform Engineering)의 등장 배경, 핵심 구성요소인 내부 개발자 플랫폼(IDP), 그리고 성공적 정착 방안을 설명하시오." → 요구 포인트: Ⅰ DevOps의 한계와 인지 부하 + Ⅲ IDP 4계층 아키텍처 + Ⅵ 플랫폼 팀의 제품 관리 거버넌스

## 내 의견
- [또 하나의 사내 관료주의 툴을 만드는 실수] 플랫폼 팀이 현업 개발자의 니즈는 묻지도 않고 거대한 사내 포털을 만들어 강제로 쓰라고 강요했다가, 개발자들이 플랫폼을 우회해 사설 클라우드 계정을 파는 섀도우 IT 재발 목격 → 나라면: 플랫폼 팀에 제품 책임자(Product Manager)를 배치하고, 사내 개발자 NPS(만족도)와 리드타임을 핵심 지표로 측정하며, 초기 2~3개 파일럿 팀과의 밀착 협업을 통해 검증된 기능만 플랫폼으로 흡수
