## Ⅰ. 개요

- **정의**: 원격 호스트의 CPU 및 운영체제 커널의 개입 없이 네트워크 인터페이스 카드(RNIC)가 호스트 메모리 데이터를 네트워크상에서 직접 읽고 쓰는 고성능 제로카피 통신 기술
- **배경 및 필요성**: 전통적 TCP 소켓 통신은 데이터 송수신 시마다 사용자 공간과 커널 공간 간의 다중 메모리 복사, 빈번한 CPU 인터럽트 및 문맥 교환(Context Switching) 오버헤드를 유발하여 AI 분산 학습 시 통신 병목을 초래함에 따라, 사용자 버퍼를 물리 메모리에 직접 고정(Pinning) 등록하고 하드웨어가 직접 메모리 간 전송을 수행하여 CPU 부하를 제거하고 전송 지연을 극소화할 필요성 대두

## Ⅱ. 특징

- 운영체제 커널을 경유하지 않는 커널 바이패스(Kernel Bypass) 및 제로카피(Zero-Copy) 메모리 전송
- 원격 노드 CPU 개입 없이 원격 메모리를 직접 읽고 쓰는 단측(One-Sided) RDMA 지원
- 보호 영역(PD) 및 메모리 키(L_Key/R_Key) 기반의 하드웨어 수준 메모리 격리 및 접근 제어

## Ⅲ. 구조 및 구성요소

```text
[RDMA 전송 아키텍처]
├── [소프트웨어 API 인터페이스 계층]
│   └── [RDMA 동사 인터페이스 (Verbs API - libibverbs)]
├── [메모리 보호 및 보안 제어 계층]
│   ├── [보호 영역 (Protection Domain - PD)]
│   └── [등록 메모리 및 키 (Memory Region - MR / L_Key, R_Key)]
└── [하드웨어 통신 큐 계층]
    ├── [작업 큐 페어 (Queue Pair - Send/Receive QP)]
    └── [완료 큐 (Completion Queue - CQ)]
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

| 구분 | 구성요소 | 기능 설명 |
|:---|:---|:---|
| 프로그래밍 인터페이스 | Verbs API | OS 소켓을 대체하여 큐 페어 생성, 메모리 등록 및 작업 요청(Post Send)을 제어하는 표준 인터페이스 |
| 보안 격리 | 보호 영역(PD) | 큐 페어(QP)와 등록 메모리(MR)를 동일 도메인으로 바인딩하여 타 프로세스의 비인가 접근 차단 |
| 가상 메모리 고정 | 메모리 영역(MR) | 전송 버퍼의 가상-물리 주소를 하드웨어에 고정(Pinning)하고 로컬(L_Key) 및 원격(R_Key) 접근 키 발급 |
| 전송 파이프라인 | 큐 페어(QP) | 송신 큐(SQ)와 수신 큐(RQ)로 구성되어 비동기 작업 요청(WQE)을 순차 디스패치하는 통신 종단점 |
| 이벤트 통지 | 완료 큐(CQ) | 네트워크 어댑터가 전송 또는 수신을 완료한 작업 결과(CQE)를 비동기 폴링할 수 있도록 기록 |

## Ⅳ. 흐름도

```text
[송신 애플리케이션] (① 버퍼 메모리를 어댑터에 등록하여 L_Key/R_Key 발급 및 사전 키 교환)
│
▼
[작업 요청 게시 (Post)] (② 송신 큐(SQ)에 대상 원격 주소와 R_Key가 포함된 RDMA Write 요청 등록)
│
▼
[로컬 RNIC 어댑터] (③ 호스트 메모리 버퍼에서 직접 DMA 인출 후 네트워크 패킷 생성 및 전송)
│
▼
[원격 RNIC 어댑터] (④ 원격 CPU 개입 없이 패킷 내 R_Key를 검증하고 지정된 물리 메모리에 즉각 DMA 기록)
│
▼
[완료 큐 (CQ) 통지] (⑤ 전송 완료 이벤트를 CQ에 기록하고 송신 애플리케이션에 비동기 완료 반환)
```

- 분기 결과: 정상 키 검증 시 원격 CPU 개입 없이 제로카피 완료되며, R_Key 불일치 또는 접근 권한 위반 시 즉각 작업 에러 CQE를 생성하고 연결 리셋

## Ⅴ. 종류 및 비교

| 비교 항목 | 단측 RDMA (One-Sided) | 양측 RDMA (Two-Sided) | 전통적 소켓 (TCP/IP) |
|:---|:---|:---|:---|
| 지원 연산 | RDMA Read, RDMA Write, Atomic | Send, Receive | send(), recv(), read(), write() |
| 원격 CPU 개입 여부 | 전혀 개입하지 않음 (완전 오프로드) | 원격 CPU가 Receive 버퍼 사전 준비 | 송수신 양측 CPU 인터럽트 및 복사 발생 |
| 메모리 주소 인지 | 송신자가 원격 메모리 주소를 직접 지정 | 송신자는 원격 주소를 모르고 메시지만 송신 | IP/포트 기반 소켓 버퍼로 전달 |
| 주요 활용 워크로드 | 대규모 분산 모델 파라미터 동기화 | 분산 RPC 메시징, 제어 신호 교환 | 범용 웹 서비스, 표준 네트워크 통신 |
| 프로그래밍 복잡도 | 높음 (사전 주소/키 교환 및 동기화 필요) | 중간 (기존 메시지 큐 방식과 유사) | 낮음 (표준 POSIX 소켓 API) |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 전송마다 발생하는 메모리 동적 등록(ibv_reg_mr)의 커널 페이징 오버헤드 | 메모리 풀링(Memory Pooling) 기법으로 거대 버퍼를 사전에 일괄 등록 재사용 | 런타임 메모리 등록 지연 배제 및 처리 속도 향상 |
| 원격 메모리 접근 키(R_Key) 탈취로 인한 메모리 임의 조작 위험 | 작업 단위별 세부 주소 윈도우(Memory Window) 동적 바인딩 및 짧은 유효기간 적용 | 비인가 접근 방지 및 테넌트 간 메모리 격리 보장 |
| 비동기 CQ 폴링 지연으로 인한 완료 큐 버퍼 오버플로우(CQ Exhaustion) | 이벤트 기반 인터럽트 대신 전용 스레드 기반 무지연 논블로킹 폴링 루틴 적용 | 작업 요청 정체 방지 및 파이프라인 처리량 극대화 |

## Ⅶ. 결론

- **기술 위상/발전**: 커널 공간 메모리 복사와 CPU 인터럽트를 원천 배제한 제로카피 초저지연 통신 기술로서, HPC 인피니밴드에서 출발하여 RoCEv2(이더넷) 및 GPUDirect RDMA로 확장되며 현대 생성형 AI 분산 인프라의 필수 불가결한 백본 통신 규격으로 자리매김
- **실무 적용/통제**: 대규모 AI 분산 학습의 올리듀스 집합 통신에는 단측 RDMA Write를 우선 채택하고, 메모리 등록 오버헤드를 완화하기 위해 사전 할당 메모리 풀과 메모리 윈도우 기반 R_Key 보안 통제 체계를 엄격히 구현할 것 권장
