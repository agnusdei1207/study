## Ⅰ. 개요

- **정의**: 거대 언어 모델을 자율 에이전트로 활용하여 복합 질의를 하위 작업으로 분해하고, 동적 도구 라우팅, 검색 결과 자체 평가(Reflection), 자율적 쿼리 재작성을 반복 수행하는 차세대 RAG 아키텍처
- **배경 및 필요성**: 1회성 정적 검색에 의존하는 기존 Naive RAG의 복합 다단계 추론(Multi-step Reasoning) 처리 불가, 검색 실패 시 복구 능력 부재, 상충되는 정보에 대한 맹목적 환각 생성을 해결하고, 능동적 검증과 자기 교정(Self-Correction)을 통해 답변 완성도를 극대화하기 위해 도입

## Ⅱ. 특징

- **자율적 계획 및 질의 분해**: 복잡한 다중 의도 질의를 실행 가능한 단위 하위 질의(Sub-queries)로 동적 분해
- **동적 도구 라우팅**: 벡터 검색, 웹 검색 엔진, SQL 데이터베이스, 계산기 등 최적의 도구를 자율 선택 호출
- **자기 성찰 및 반추 (Reflection)**: 검색된 문서의 관련성, 충분성, 모순 여부를 자체 평가(CRAG, Self-RAG)하여 부족 시 쿼리 재작성
- **안전 제어 루프 및 예산 통제**: 무한 루프를 방지하기 위해 최대 홉 수(Max Hops), 토큰/API 호출 예산 강제

## Ⅲ. 구조 및 구성요소

```text
[Agentic RAG 시스템]
├── [에이전트 제어 루프 계층]
│   ├── [작업 계획기 (Planner)]
│   └── [도구 라우터 (Tool Router)]
├── [동적 도구 및 검색 계층]
│   ├── [내부 벡터 저장소 (Vector DB)]
│   ├── [관계형 데이터베이스 (Text-to-SQL)]
│   └── [외부 웹 검색기 (Web Search API)]
└── [평가 및 성찰 계층]
    ├── [근거 평가기 (Reflector / Evaluator)]
    ├── [상태 메모리 (State & History)]
    └── [비용/루프 정책 통제기 (Budget Guard)]
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

| 구성요소 | 책임 |
|:---|:---|
| 작업 계획기 | 사용자 복합 질의 분석, 하위 태스크 분해 및 실행 순서 수립 |
| 도구 라우터 | 태스크 성격에 따라 벡터 검색, SQL, 웹 검색 등 적응형 도구 호출 |
| 근거 평가기 | 수집된 정보의 질문 적합성, 충분성 및 모순 여부를 자율적으로 판정 |
| 상태 메모리 | 다단계 실행 과정의 중간 결과, 도구 응답 및 남은 목표 상태 추적 |
| 정책 통제기 | 최대 반복 횟수(Max Iteration), API 호출 비용 한도 및 중단 규칙 강제 |

## Ⅳ. 흐름도

```text
[에이전틱 RAG 실행 흐름] (진입: 사용자 복합 질의 접수)
│
▼
[목표 분해] (① 질문 분석 후 복수의 하위 질의 및 완료 조건 수립)
│
▼
[도구 라우팅] (② 서브 태스크에 적합한 도구(Vector DB/SQL/Web) 선별 및 조회)
│
▼
[근거 성찰] (③ 검색 청크의 관련성 및 정보 충족도 자체 평가)
│
▼
[반복/교정 분기] (④ 정보 부족 시 쿼리 재작성 후 재탐색, 충분 시 답변 생성 단계 이동)
│
▼
[종합 생성] (⑤ 수집된 다중 근거를 통합하여 논리적 최종 답변 및 인용 생성)
│
▼
[완료] (반환: 자기 검증을 거친 고신뢰도 복합 추론 답변 제공)
```

- 분기 결과: 근거가 충분할 경우 **최종 종합 답변을 생성**하고, 정보가 부족하거나 왜곡된 경우 **쿼리 재작성(Query Rewrite) 및 대체 도구 폴백**을 실행함

## Ⅴ. 종류 및 비교

| 구분 | 단순 RAG (Naive RAG) | 고급 RAG (Advanced RAG) | 에이전틱 RAG (Agentic RAG) |
|:---|:---|:---|:---|
| 검색 흐름 | 단일 턴 정적 검색 (1회) | 사전/사후 정제 포함 정적 파이프라인 | 동적 다단계 자율 루프 (Multi-turn) |
| 도구 활용 | 단일 벡터 검색 엔진 고정 | 하이브리드 검색 및 Reranker 고정 | Vector DB, SQL, Web 등 복수 도구 자율 선택 |
| 오류 복구 | 불가 (검색 실패 시 환각 발생) | 제한적 (Reranking 점수 의존) | 자체 반추(Self-Correction)를 통한 재검색 |
| 지연 시간 | 가장 짧음 (1회 추론) | 중간 (재순위 연산 추가) | 다소 긺 (다단계 에이전트 루프) |
| 비용/토큰 | 낮음 | 중간 | 에이전트 반복 호출로 상대적 높음 |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 근거 불충분 판정 반복에 따른 무한 루프 발생 | 최대 반복 횟수(Max Hops 3~5회) 및 타임아웃 강제 | 시스템 자원 낭비 차단 및 응답 시간 보장 |
| 부적절한 도구 호출로 인한 오류 누적 | 명확한 도구 스키마(JSON Schema) 정의 및 폴백 경로 수립 | 도구 호출 정확도 향상 및 실행 안정성 확보 |
| 다단계 LLM 호출로 인한 지연 시간 및 토큰 비용 폭증 | 하위 질의 병렬 실행(Map-Reduce) 및 캐싱 레이어 결합 | 사용자 체감 레이턴시 단축 및 API 비용 절감 |

## Ⅶ. 결론

- **기술 위상/발전**: 정적인 단발성 RAG를 넘어 스스로 계획하고 오류를 복구하는 **Agentic RAG 기술**은 Corrective RAG(CRAG)와 Self-RAG를 흡수하며 차세대 기업용 지능형 시스템의 표준으로 진화
- **실무 적용/통제**: 질의 복잡도에 따라 단순 질의는 **고정 RAG**로 바이패스하고 복합 추론 질의만 **Agentic Loop**로 라우팅하는 하이브리드 아키텍처를 채택하여 성능과 비용의 최적 균형 달성
