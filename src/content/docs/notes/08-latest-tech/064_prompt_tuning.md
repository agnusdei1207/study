## Ⅰ. 개요

- **정의**: 사전학습된 기반 모델의 모든 내부 가중치를 동결(Freeze)한 채, 입력 텍스트 임베딩 앞단에 결합되는 연속적인 가상 토큰(Soft Prompt) 벡터만을 역전파로 최적화하는 비침습적 PEFT 기법
- **배경 및 필요성**: 자연어 하드 프롬프트(Hard Prompt)의 표현력 한계와 이산적 탐색 난이도를 극복하고, 모델 내부 구조 수정이나 대용량 체크포인트 관리 없이 수십 KB 크기의 가상 토큰 벡터만을 교체하여 단일 LLM 인스턴스에서 멀티태넌트 서빙 효율을 극대화하기 위해 도입

## Ⅱ. 특징

- **연속 임베딩(Soft Prompt) 최적화**: 자연어 단어가 아닌 고차원 연속 벡터 공간에서 경사하강법을 통해 과업 지시 표현 직접 갱신
- **비침습적 파라미터 효율성**: 원본 모델 파라미터를 100% 보존하며 전체 파라미터의 0.01% 미만(수천~수만 파라미터)만 학습
- **모델 스케일링 수렴성**: 모델 파라미터 규모가 10B 이상으로 커질수록 완전 미세조정(Full FT)과의 성능 격차가 완전히 소멸하는 특성
- **문맥 윈도우 점유 트레이드오프**: 가상 토큰 길이(보통 20~100 토큰)만큼 사용자의 유효 프롬프트 컨텍스트 윈도우를 소비

## Ⅲ. 구조 및 구성요소

```text
[Prompt Tuning 구조]
├── [입력 구성 계층]
│   ├── [소프트 프롬프트 (가상 토큰 임베딩)]
│   └── [실제 입력 텍스트 토큰 임베딩]
├── [결합 및 투영 계층]
│   └── [임베딩 결합기 (Concatenator)]
└── [모델 연산 계층]
    ├── [동결 백본 모델 (Frozen LLM)]
    └── [과업 손실기 및 역전파 경로]
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

| 구성요소 | 책임 |
|:---|:---|
| 소프트 프롬프트 | 과업 지시 정보를 담은 연속 벡터(Virtual Tokens) 저장 및 갱신 |
| 실제 입력 임베딩 | 사용자가 입력한 프롬프트 토큰의 정적 고차원 벡터 표현 |
| 임베딩 결합기 | 가상 토큰 벡터와 실제 토큰 임베딩을 단일 시퀀스로 병합 결합 |
| 동결 백본 모델 | 가중치 고정 상태에서 결합된 입력을 처리하여 다운스트림 예측 산출 |
| 과업 손실기 | 정답 레이블과의 오차를 계산하여 소프트 프롬프트 임베딩만 경사 갱신 |

## Ⅳ. 흐름도

```text
[Prompt Tuning 흐름] (진입: 다운스트림 과업 데이터 유입)
│
▼
[초기화] (① 가상 토큰 길이 N 설정 및 클래스 레이블/사전학습 토큰 임베딩 초기화)
│
▼
[시퀀스 결합] (② 소프트 프롬프트 벡터와 사용자 입력 임베딩을 선두 결합)
│
▼
[순전파 연산] (③ 동결된 Transformer 백본을 통과시켜 태스크 예측 확률 산출)
│
▼
[가상 토큰 갱신] (④ 모델 가중치 역전파는 차단하고 소프트 프롬프트만 경사 갱신)
│
▼
[경량 배포] (⑤ 과업별 수십 KB의 가상 벡터만 저장 및 멀티테넌트 서비스 배포)
│
▼
[완료] (반환: 비침습적 다중 태스크 프롬프트 서빙 가동)
```

- 분기 결과: 단순 텍스트 분류·생성은 **단일 입력단 Prompt Tuning**을 채택하고, 복잡한 문맥 제어가 요구되는 다단계 추론은 **전 계층 Key/Value 접두어를 튜닝하는 Prefix Tuning**으로 확장함

## Ⅴ. 종류 및 비교

| 구분 | 하드 프롬프트 (In-Context) | Prompt Tuning | Prefix Tuning |
|:---|:---|:---|:---|
| 제어 위치 | 자연어 텍스트 입력 | 입력 임베딩 레이어 선두 | 전체 Transformer 계층 K, V 접두어 |
| 최적화 방식 | 수작업 작성 및 프롬프트 엔지니어링 | 연속 임베딩 역전파 최적화 | 다층 접두어 MLP 역전파 최적화 |
| 학습 파라미터 | 0개 (무학습) | 극소수 (가상 토큰 수 × 임베딩 차원) | 소수 (층수 × 토큰 수 × 차원) |
| 문맥 점유 | 프롬프트 길이에 비례 | 가상 토큰 수만큼 고정 점유 | 가상 토큰 점유 및 KV 캐시 증가 |
| 모델 크기 민감도 | 모델 능력에 전적 의존 | 대형 모델(10B+)에서 급격한 성능 발현 | 중소형 모델에서도 안정적 성능 발휘 |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 소프트 프롬프트의 컨텍스트 윈도우 잠식 | 태스크 난이도별 가상 토큰 길이(20~50) 최적화 | 입력 문맥 예산 확보 및 추론 효율 유지 |
| 중소형 모델에서의 학습 불안정 및 수렴 실패 | 클래스 레이블 텍스트 임베딩으로 초기화 및 Prefix Tuning 전환 | 수렴 속도 단축 및 과업 적응력 극대화 |
| 연속 벡터화에 따른 해석 불가능성(Black-box) | 토큰 어휘집 근접 투영 분석 및 주의집중 맵 시각화 | 가상 토큰 학습 패턴 분석 및 디버깅 가능 |

## Ⅶ. 결론

- **기술 위상/발전**: 모델 내부 가중치를 전혀 수정하지 않는 비침습적 특성을 통해 단일 LLM 인스턴스에서 극대화된 멀티태스크 서빙 밀도를 달성한 **Prompt Tuning 기술**은 초거대 모델 시대로 진입할수록 높은 파라미터 효율성을 입증
- **실무 적용/통제**: 10B 이상의 초대형 백본에는 **경량 Prompt Tuning**을 우선 검토하고, 정밀한 생성 제어가 필요한 중소형 백본에는 **Prefix Tuning 또는 LoRA**를 선택 적용하여 서빙 인프라 비용과 품질 간 최적 균형 달성
