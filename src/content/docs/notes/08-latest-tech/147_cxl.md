## Ⅰ. 개요

- **정의**: 고성능 이기종 컴퓨팅 환경에서 CPU, GPU, 가속기, 메모리 장치 간에 PCIe 물리 계층을 기반으로 하드웨어 수준의 캐시 일관성(Cache Coherency)과 메모리 확장/공유(Memory Pooling)를 제공하는 개방형 표준 고속 인터커넥트 기술
- **배경 및 필요성**: AI 초거대 모델 및 인메모리 데이터베이스의 용량 폭증으로 인해 CPU 소켓당 DDR 슬롯 핀 수 한계와 메모리 격납(Stranded Memory) 문제가 심화되고 기존 PCIe 버스는 장치 간 캐시 일관성을 지원하지 않아 OS 드라이버 기반의 무거운 메모리 복사 지연을 초래함에 따라, PCIe 물리 계층 상에서 메모리 의미론(Memory Semantics)을 직접 지원하여 나노초 단위의 초저지연 캐시 일관성을 보장하고 랙 단위 메모리 풀링을 통한 TCO 절감을 실현할 필요성 대두

## Ⅱ. 특징

- PCIe 5.0/6.0 물리 계층 공유를 통한 기존 마더보드 인프라 활용 및 전송 호환성 확보
- 3가지 하위 프로토콜(CXL.io, CXL.cache, CXL.mem)의 선택적 조합을 통한 장치 유연성
- CXL 스위치 패브릭을 통한 다중 호스트 간 동적 메모리 풀링(Pooling) 및 공유(Sharing) 지원

## Ⅲ. 구조 및 구성요소

```text
[CXL Architecture]
├── [호스트 CPU 및 루트 복합체]
│   ├── [호스트 캐시 및 홈 에이전트 (Home Agent)]
│   └── [CXL 호스트 브리지 (Host Bridge)]
├── [CXL 다중 프로토콜 계층]
│   ├── [입출력 프로토콜 (CXL.io - Discovery/DMA)]
│   ├── [캐시 프로토콜 (CXL.cache - Device Caching)]
│   └── [메모리 프로토콜 (CXL.mem - Host Access to Device Memory)]
└── [CXL 장치 및 패브릭 계층]
    ├── [CXL 엔드포인트 장치 (Type-1, Type-2, Type-3)]
    └── [CXL 스위치 패브릭 (Multi-host Pooling Fabric)]
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

| 구분 | 구성요소 | 기능 설명 |
|:---|:---|:---|
| 호스트 제어 | 홈 에이전트(HA) | 호스트와 CXL 장치 간 글로벌 스누프(Snoop) 필터 및 캐시 일관성 디렉터리 관리 |
| I/O 프로토콜 | CXL.io | PCIe 기반 링크 초기화, 장치 검색(Discovery), 구성(Configuration) 및 레거시 DMA 전송 |
| 캐시 프로토콜 | CXL.cache | 가속기 장치가 호스트 메인 메모리를 D2H/H2D 트랜잭션으로 나노초 단위 직접 캐싱 허용 |
| 메모리 프로토콜 | CXL.mem | 호스트 CPU가 장치에 부착된 DRAM을 로컬 주소 공간처럼 Load/Store 명령으로 직접 접근 |
| 패브릭 인프라 | CXL 스위치 | 단일 메모리 풀을 다수의 서버 호스트에 물리적 재배선 없이 동적 슬라이싱 및 공유 분배 |

## Ⅳ. 흐름도

```text
[호스트 CPU & 가속기] (① PCIe 5.0/6.0 물리 계층에서 링크 훈련 및 CXL 동작 모드 협상)
│
▼
[CXL.io 채널] (② CXL.io를 통해 장치 디스크립터 탐색 및 장치 유형(Type-1/2/3) 프로토콜 바인딩)
│
▼
[호스트 브리지] (③ 장치 메모리를 호스트 물리 주소 공간(HPA)에 NUMA 노드로 연속 매핑)
│
▼
[CXL.cache / CXL.mem] (④ 일관성 캐시 스누프 교환 및 OS 개입 없는 하드웨어 Load/Store 직접 트랜잭션)
│
▼
[CXL 스위치 풀] (⑤ 다중 호스트 간 미사용 메모리 블록을 동적 회수 및 재할당하여 풀링 최적화)
```

- 분기 결과: 로컬 캐시 히트 시 즉각 반환되며, 미스 발생 시 CXL.mem 트랜잭션을 통해 확장 메모리 풀로 분기하여 데이터를 인출하고 일관성 유지

## Ⅴ. 종류 및 비교

| 비교 항목 | Type-1 (가속기) | Type-2 (범용 가속기) | Type-3 (메모리 확장기) |
|:---|:---|:---|:---|
| 지원 프로토콜 | CXL.io + CXL.cache | CXL.io + CXL.cache + CXL.mem | CXL.io + CXL.mem |
| 로컬 장치 메모리 | 없음 (호스트 메모리만 캐싱) | 있음 (DDR/HBM 장착) | 있음 (대용량 DDR5 장착) |
| 주 활용 분야 | SmartNIC, 보안/압축 엔진 | GPU, FPGA 딥러닝 훈련 가속기 | 메모리 용량 확장, 인메모리 DB, LLM 풀링 |
| 캐시 일관성 방향 | 장치가 호스트 캐시를 참조 | 호스트와 장치가 상호 메모리 일관성 유지 | 호스트가 장치 메모리를 로컬처럼 참조 |
| 대표적 하드웨어 | 네트워크 가속 카드 | 하이브리드 AI 프로세서 | CXL 메모리 확장 카드(E3.S / PCIe 폼팩터) |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 로컬 DDR 대비 CXL.mem 링크 경유에 따른 접근 지연시간(약 150~200ns) 증가 | 계층형 메모리 관리(Tiered Memory) 및 접근 빈도 기반 페이지 자동 마이그레이션 적용 | 핫 데이터 로컬 유지 및 전체 애플리케이션 지연시간 열화 방지 |
| 다중 호스트 간 CXL 스위치 공유 시 오류 확산 및 보안 격리 취약점 | CXL 3.0 하드웨어 보안 모듈(IDE) 암호화 및 테넌트별 가상 계층(vPPB) 엄격 분리 | 인접 호스트 장애 전파 차단 및 멀티테넌트 데이터 기밀성 보장 |
| NUMA 노드 증가로 인한 OS 스케줄러의 비효율적 스레드-메모리 배치 | CXL 인식 NUMA 바인딩 정책(`numactl`) 적용 및 인메모리 캐시 전용 노드 지정 | 원격 메모리 불필요 접근 억제 및 워크로드 처리량 극대화 |

## Ⅶ. 결론

- **기술 위상/발전**: 서버 단위를 넘어 랙/데이터센터 차원의 메모리 분리(Disaggregation) 및 컴포저블 인프라를 가능케 하는 핵심 인터커넥트 표준으로 자리매김하였으며, CXL 2.0 풀링 상용화를 거쳐 CXL 3.1 패브릭 스위치와 CXL-PIM 결합 구조로 급속히 발전 중
- **실무 적용/통제**: 인메모리 데이터베이스와 초대형 LLM KV 캐시 확장에 Type-3 메모리 확장을 우선 도입하고, 핫/콜드 데이터 접근 패턴을 지속 프로파일링하여 OS 커널 레벨의 자동 계층화(Tiering) 정책을 체계적으로 수립할 것 권장
