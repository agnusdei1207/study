## Ⅰ. 개요

- **정의**: 배포된 머신러닝 모델의 실제 예측 성능과 확률 보정(Calibration)이 데이터 분포 변화, 비즈니스 개념 변화, 또는 서빙 파이프라인 결함으로 인해 학습 시점 대비 점진적 또는 급격하게 저하되는 복합 현상
- **배경 및 필요성**: 운영 중 모델 성능 저하 발생 시 원인이 입력 데이터 드리프트($P(X)$), 개념 드리프트($P(Y \mid X)$), 또는 전처리 버그/임계값 오류(Configuration Drift)인지 분리하지 못하면 무의미한 모델 재학습으로 인프라 비용만 낭비하므로, 원인별 계층적 진단과 최적 대응(수정/재학습/롤백) 체계 구축이 필수적임

## Ⅱ. 특징

- **복합적 원인 귀속(Multi-root Cause)**: 데이터 분포 변화, 실세계 비즈니스 개념 변화, 서빙 전처리 로직 왜곡 등 다중 요인에 의해 유발
- **성능 및 보정 오차(Calibration Error) 동시 발생**: 단순 정확도/F1-Score 하락뿐만 아니라 모델이 산출한 예측 확률값과 실제 발현 빈도 간의 괴리 심화
- **다차원 세그먼트 편차**: 전체 통합 집계 성능은 정상으로 보이나 특정 하위 그룹(Subgroup)이나 특정 시간대에서만 국소적 붕괴 발생
- **원인 맞춤형 조치 분기**: 단순 재학습이 아닌 상류 파이프라인 버그 패치, 윈도우 기반 지속적 학습(CT), 또는 서빙 설정 롤백 등 차별화된 대응 요구

## Ⅲ. 구조 및 구성요소

### 1. 모델 드리프트 종합 진단 아키텍처

```text
[Model Drift Diagnosis System]
├── [기준선 및 계보 계층]
│   ├── [성능 기준선 (Performance Baseline)]
│   └── [모델·버전·설정 계보 (Model Lineage)]
├── [운영 관측 및 피드백 계층]
│   ├── [추론 관측 저장소 (Telemetry Store)]
│   └── [정답 결합기 (Ground Truth Joiner)]
└── [진단 및 복구 계층]
    └── [진단·복구기 (Remediation Engine)]
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

### 2. 세부 구성요소

| 계층 구분 | 세부 항목 | 핵심 역할 |
|:---|:---|:---|
| 기준선 및 계보 계층 | 성능/분포 기준선 | 검증 데이터셋의 F1-Score, ROC-AUC, 예측 확률 분포 및 정상 임계치 보관 |
| | 모델 아티팩트 계보 | Git 커밋, 전처리 파이프라인 버전, 추론 임계값, 피처 스토어 뷰 버전 추적 |
| 운영 관측 계층 | 추론 텔레메트리 | 실시간 입력 피처, 모델 출력 확률, 추론 지연 시간, 서버 에러율 수집 |
| | 지연 정답 결합기 | 비즈니스 결과 확정 시 추론 로그와 실제 정답을 이벤트 ID로 시각 정합 |
| 진단 및 복구 계층 | 원인 분해 엔진 | 입력 분포 검정, 정답 조건부 검정, 코드 변경점 대조를 통한 근본 원인 규명 |
| | 조치 오케스트레이터 | 파이프라인 버그 수정(Fix), 가중치 적응 재학습(CT), 서빙 설정 롤백(Rollback) 실행 |

## Ⅳ. 흐름도

```text
[추론 로그 및 정답 수집] (① 실시간 예측 데이터와 사후 도착한 실제 레이블 매핑)
  │
  ▼
[성능 지표 종합 평가] (② 실시간 F1-Score, Brier Score, ECE(보정 오차) 산출)
  │
  ▼
[원인 분해 심층 진단] (③ 데이터 분포 vs 조건부 확률 vs 파이프라인 변경점 비교)
  │
  ▼
[최적 복구 조치 결정] (④ 진단 결과에 따라 파이프라인 패치, 재학습, 설정 롤백 분기)
  │
  ▼
[섀도우 검증 및 승격] (⑤ 개선된 모델/파이프라인을 섀도우 배포로 검증 후 프로덕션 승격)
```

- 분기 결과: 데이터 분포 변화 시 신규 데이터 추가 후 재학습(CT), 개념 변화 시 적응형 윈도우 재학습, 전처리/설정 오류 시 이전 안정 버전으로 즉각 롤백

## Ⅴ. 종류 및 비교

| 비교 항목 | 데이터 드리프트 (Data Drift) | 개념 드리프트 (Concept Drift) | 구성 드리프트 (Configuration Drift) |
|:---|:---|:---|:---|
| 주요 원인 | 사용자 인구통계 변화, 환경 변화 | 고객 행동 패턴 변화, 사기 수법 진화 | 전처리 로직 버그, 추론 임계값 변경 |
| 변화 감지 대상 | 입력 특성 분포: $P(X)$ | 조건부 확률 관계: $P(Y \mid X)$ | 소프트웨어 코드, 피처 엔지니어링 파이프라인 |
| 정답 라벨 필요성 | 불필요 (입력 데이터만으로 감지) | 필수 (실제 결과 확인 필요) | 불필요 (형상 관리 및 단위 테스트로 감지) |
| 모델 성능 영향 | 간접적 영향 (성능 저하 가능성) | 직접적이고 치명적인 예측 성능 하락 | 즉각적이고 인위적인 모델 예측 왜곡 |
| 표준 대응 조치 | 신규 분포 데이터 추가 수집 및 재학습 | 슬라이딩 윈도우 기반 지속 학습(CT) | 소프트웨어 버그 픽스 및 설정 롤백 |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 입력 분포 경보만으로 성급한 모델 재학습 수행 | 지연 정답 도착 시 실제 비즈니스 KPI 및 오차율 영향 검증 후 조치 | 불필요한 GPU 학습 비용 낭비 방지 및 파이프라인 안정성 확보 |
| 전체 평균 지표에 은폐된 서브그룹(Subgroup) 성능 붕괴 | 고객군, 지역, 채널별 다차원 세그먼트 슬라이싱 및 ECE 보정 오차 관제 | 국소적 품질 저하 조기 격리 및 특정 사용자층 이탈 방지 |
| 서빙 전처리 로직 버그를 데이터/개념 드리프트로 오진 | 모델, 전처리 코드, 피처 스토어 정의의 완전한 계보(Lineage) 대조 | 소프트웨어 설정 결함을 즉각 식별하고 원터치 롤백으로 장애 해결 |
| 지연 라벨 확정 시점까지의 장시간 성능 열화 방치 | 신뢰도 점수(Confidence) 분포 및 불확실성(Uncertainty) 모니터링 결합 | 정답 부재 환경에서도 모델의 예측 신뢰도 저하 징후 선제적 감지 |

## Ⅶ. 결론

- **기술 위상/발전**: 머신러닝 서빙 환경에서 발생하는 성능 열화를 단일 증상이 아닌 데이터-개념-인프라 복합 장애로 접근하여 정확한 처방을 내리는 MLOps 지속적 관측성(Observability) 및 자율 복구의 핵심 표준으로 확립됨
- **실무 적용/통제**: 지연 정답 정합 파이프라인 구축, 원인별(데이터/개념/구성) 자동 진단 분기 수립, 서브그룹 슬라이싱 분석을 결합하여 프로덕션 모델의 장기적 신뢰성과 비용 효율성 극대화 필요
