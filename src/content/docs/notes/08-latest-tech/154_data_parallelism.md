## Ⅰ. 개요

- **정의**: 전체 딥러닝 모델 파라미터를 다수의 연산 장치(GPU)에 동일하게 복제하고, 전체 데이터셋을 고유한 마이크로 배치로 샤딩 분할하여 각 장치가 독립적으로 순전파/역전파를 수행한 뒤 그래디언트를 All-Reduce로 전역 동기화하는 분산 학습 기법
- **배경 및 필요성**: 대규모 데이터셋 기반 모델 훈련 시 단일 GPU의 메모리 및 배치 처리량 한계로 인해 학습 완료까지 수개월 이상의 시간이 소요되는 문제가 발생함에 따라, 연산 장치 수에 비례하여 처리량을 확장(Scale-out)하고 역전파 연산과 그래디언트 통신을 비동기로 중첩(Overlap)하여 전체 훈련 소요 시간을 획기적으로 단축할 필요성 대두

## Ⅱ. 특징

- GPU 장치 증가에 따라 학습 데이터 처리량이 비례 증가하는 선형적 스케일아웃(Linear Scaling)
- 역전파 계산 완료 즉시 단계별로 통신을 개시하는 비동기 그래디언트 버케팅 및 계산-통신 중첩
- ZeRO(Zero Redundancy Optimizer) 및 FSDP와의 결합을 통한 옵티마이저/파라미터 분할 저장 및 메모리 절감

## Ⅲ. 구조 및 구성요소

```text
[데이터 병렬화 아키텍처]
├── [데이터 샤딩 및 샘플러 계층]
│   └── [분산 데이터 샘플러 (Distributed Sampler)]
├── [로컬 연산 및 모델 계층]
│   ├── [모델 파라미터 복제본 (Model Replica / FSDP Shard)]
│   └── [로컬 순전파/역전파 엔진 (Forward/Backward Engine)]
└── [기울기 동기화 및 옵티마이저 계층]
    ├── [All-Reduce 동기화 버킷 (NCCL Gradient Bucket)]
    └── [옵티마이저 가중치 갱신 엔진 (Optimizer Step Engine)]
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

| 구분 | 구성요소 | 기능 설명 |
|:---|:---|:---|
| 데이터 공급 | 분산 데이터 샘플러 | 전체 데이터셋을 랭크 수만큼 중복과 누락 없이 고유 인덱스로 분할 배정 |
| 모델 저장 | 모델 복제본 (Replica) | 각 GPU에 동일한 모델 가중치를 적재하거나 FSDP/ZeRO 방식으로 레이어 단위 분할 보유 |
| 로컬 연산 | 로컬 훈련 엔진 | 할당된 로컬 미니배치에 대해 독립적으로 순전파 손실 계산 및 역전파 그래디언트 도출 |
| 통신 버퍼 | 그래디언트 버킷 | 계산 완료된 파라미터 기울기를 순차 패킹하여 비동기 All-Reduce 전송 트리거 |
| 파라미터 갱신 | 옵티마이저 갱신 엔진 | 전역 평균화된 그래디언트를 바탕으로 AdamW 등 옵티마이저를 통해 동일 가중치 동시 업데이트 |

## Ⅳ. 흐름도

```text
[분산 데이터 샘플러] (① 전체 배치 데이터를 각 GPU 랭크별 독립 로컬 배치로 중복 없이 샤딩)
│
▼
[로컬 순전파/역전파] (② 각 GPU가 독립적으로 로컬 배치에 대한 손실 및 레이어별 그래디언트 계산)
│
▼
[비동기 버킷 패킹] (③ 역전파 진행 중 먼저 계산된 레이어 기울기부터 수십 MB 단위 버킷으로 자동 패킹)
│
▼
[All-Reduce 통신] (④ NCCL 패브릭을 통해 링/트리 방식으로 타 GPU와 전역 평균 그래디언트 교환)
│
▼
[옵티마이저 가중치 갱신] (⑤ 모든 GPU가 동일한 전역 그래디언트를 적용하여 파라미터를 동기화 갱신)
```

- 분기 결과: 단일 GPU 메모리에 모델 전체 수용 가능 시 순수 DDP로 진행하고, 모델 크기가 VRAM 초과 시 FSDP(ZeRO-3) 파라미터 분할 수집 파이프라인으로 전환

## Ⅴ. 종류 및 비교

| 비교 항목 | 데이터 병렬화 (DDP) | 텐서 병렬화 (TP) | 파이프라인 병렬화 (PP) |
|:---|:---|:---|:---|
| 분할 대상 | 학습 데이터 배치 (Batch Dimension) | 단일 레이어 내 가중치 행렬 (Tensor Dimension) | 모델의 깊이 레이어 그룹 (Layer Dimension) |
| 통신 발생 시점 | 매 스텝 역전파 완료 후 1회 (버킷 중첩) | 매 트랜스포머 레이어 순전파/역전파마다 발생 | 파이프라인 마이크로배치 경계 간 순차 전송 |
| 통신 패브릭 요구 | 노드 간 InfiniBand/RoCE 네트워크 적합 | 초고속 노드 내 NVLink 필수 (지연 민감) | 노드 간 일반 고속 네트워크 수용 가능 |
| 주요 제약 사항 | 모델 파라미터가 단일 GPU VRAM에 적재 가능해야 함 | 통신 빈도가 극도로 높아 단일 노드(8 GPU)로 제한 | 파이프라인 버블(Bubble) 유휴 시간 발생 |
| 대표적 프레임워크 | PyTorch DDP, DeepSpeed, FSDP | Megatron-LM, vLLM | Megatron-LM, DeepSpeed Pipeline |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| GPU 증설에 따른 전역 배치(Global Batch) 과대화로 학습 수렴 실패 및 일반화 성능 저하 | 선형 학습률 웜업(Linear LR Scaling & Warmup) 및 LARS/LAMB 적응형 옵티마이저 적용 | 대규모 배치 환경에서 수렴 안정성 확보 및 검증 정확도 유지 |
| 대규모 클러스터에서 단일 노드 성능 저하 시 전체 All-Reduce 동결(Straggler 병목) | NCCL 텔레메트리 기반 이상 GPU 실시간 모니터링 및 그래디언트 누적(Gradient Accumulation) 분할 | 통신 지연 평준화 및 클러스터 연산 효율 극대화 |
| 모델 크기 증가로 단일 GPU VRAM에 옵티마이저 상태 및 파라미터 적재 불가 | FSDP(Fully Sharded Data Parallel) 또는 ZeRO-3 단계적 파라미터 샤딩 적용 | 단일 GPU 메모리 제약 탈피 및 초거대 모델 데이터 병렬화 지원 |

## Ⅶ. 결론

- **기술 위상/발전**: 분산 딥러닝 훈련의 가장 기본적이면서 연산 효율(MFU)이 가장 뛰어난 핵심 기법으로서, PyTorch DDP에서 출발하여 옵티마이저/파라미터 중복을 배제하는 ZeRO 및 FSDP로 진화하였으며, 현대 LLM 3D 병렬화(TP+PP+DP)의 스케일아웃 최외곽 축으로 확고히 정립
- **실무 적용/통제**: 모델이 단일 GPU에 적재되는 경우 기본 DDP를 적용하고, 메모리 한계 도달 시 FSDP를 활성화하며, GPU 노드 확장에 따른 전역 배치 증가 시 선형 학습률 스케일링 규칙과 25~50MB 그래디언트 버킷 최적화를 반드시 병행할 것 권장
