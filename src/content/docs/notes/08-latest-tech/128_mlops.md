## Ⅰ. 개요

- **정의**: 머신러닝 모델의 개발(Dev)과 운영(Ops)을 통합하여 데이터 수집, 학습, 검증, 배포, 모니터링 및 재학습에 이르는 전 생애주기를 재현 가능하고 신뢰성 있게 자동화하는 엔지니어링 실천 체계
- **배경 및 필요성**: 전통적 DevOps는 소스 코드 형상 관리에 국한되어 데이터 분포 변화(Data Drift), 특징 가공 왜곡(Train-Serving Skew), 모델 성능 저하(Concept Drift) 등 ML 고유의 복합적 요소를 수용하지 못하므로, 지속적 학습(CT)과 모델 레지스트리 기반 승격 게이트를 결합한 MLOps 체계 도입이 필수적임

## Ⅱ. 특징

- **CI/CD/CT 3대 파이프라인**: 전통적 코드 빌드/배포(CI/CD)에 더하여 데이터 및 모델 자동 재학습(CT) 루프 내재화
- **실험 및 아티팩트 재현성(Reproducibility)**: 코드, 학습 데이터, 특징(Feature), 하이퍼파라미터 및 모델 메타데이터의 엔드투엔드 계보(Lineage) 추적
- **학습-서빙 일관성 보장**: 피처 스토어(Feature Store)를 도입하여 오프라인 배치 학습과 온라인 실시간 추론 간 특징 불일치 원천 제거
- **지속적 성능 관측 및 피드백**: 운영 추론 데이터의 드리프트 감지(PSI, KS-검정) 시 자동 재학습 트리거 및 롤백 수행

## Ⅲ. 구조 및 구성요소

### 1. MLOps 아키텍처

```text
[MLOps Architecture]
├── [오케스트레이션 및 파이프라인]
│   ├── [파이프라인 오케스트레이터]
│   └── [데이터 파이프라인 (Data Pipeline)]
├── [메타데이터 및 모델 자산 관리]
│   ├── [메타데이터 저장소 (Metadata Store)]
│   └── [모델 레지스트리 (Model Registry)]
└── [서빙 및 지속적 관측 계층]
    └── [서빙·모니터링 플랫폼 (Serving & Monitor)]
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

### 2. 세부 구성요소

| 계층 구분 | 세부 항목 | 핵심 역할 |
|:---|:---|:---|
| 오케스트레이션 계층 | 파이프라인 오케스트레이터 | Kubeflow, Airflow 기반 워크플로우 의존성 관리 및 DAG 스케줄링 |
| | 피처 스토어 (Feature Store) | Feast 기반 오프라인/온라인 특징 정의, 서빙 및 학습-서빙 일관성 유지 |
| 자산 관리 계층 | 메타데이터 저장소 | MLflow 기반 실험 파라미터, 평가 메트릭, 실행 환경 계보 기록 |
| | 모델 레지스트리 | 훈련된 모델 아티팩트 버전 관리, 스테이징/프로덕션 승격 게이트 통제 |
| 서빙 및 관측 계층 | 추론 서빙 엔진 | Triton, TorchServe 기반 고성능 모델 서빙 및 카나리/섀도우 배포 |
| | 드리프트 모니터링 | Evidently 기반 입력 데이터 분포(Data Drift) 및 예측 성능 저하 실시간 감지 |

## Ⅳ. 흐름도

```text
[데이터 수집 및 검증] (① 원천 데이터 수집, 데이터 유효성 검사 및 피처 추출)
  │
  ▼
[자동화 학습 및 튜닝] (② 오케스트레이터를 통한 분산 모델 학습 및 하이퍼파라미터 탐색)
  │
  ▼
[모델 평가 및 검증] (③ 사전 정의된 성능 임계치 통과 여부 및 편향성 자동 검증)
  │
  ▼
[모델 레지스트리 등록] (④ 승인된 모델 버전 등록 및 스테이징 환경 승격)
  │
  ▼
[카나리/섀도우 서빙 배포] (⑤ 무중단 점진적 트래픽 전환 및 실시간 추론 개시)
  │
  ▼
[지속적 드리프트 감지] (⑥ 데이터/개념 드리프트 감지 시 자동 재학습(CT) 피드백)
```

- 분기 결과: 운영 중 모델 성능 저하 또는 데이터 드리프트 임계치 초과 감지 시 신규 데이터셋 기반 자동 재학습(CT) 파이프라인 작동 또는 직전 안정 모델로 즉각 롤백

## Ⅴ. 종류 및 비교

| 비교 항목 | MLOps (머신러닝 운영) | DevOps (소프트웨어 운영) | LLMOps (대형 언어 모델 운영) |
|:---|:---|:---|:---|
| 핵심 관리 대상 | 데이터, 코드, 모델 아티팩트 | 애플리케이션 소스 코드 및 인프라 | 프롬프트, 파인튜닝 가중치, RAG 파이프라인 |
| 지속성 요소 | CI / CD / CT (Continuous Training) | CI / CD (Continuous Integration/Delivery) | CI / CD / Continuous Evaluation & Guardrail |
| 성능 저하 원인 | 데이터 분포 변화 및 개념 드리프트 | 소프트웨어 버그 및 인프라 장애 | 모델 환각(Hallucination) 및 지식 진부화 |
| 핵심 인프라 도구 | Feature Store, Model Registry | Git, Jenkins, Docker, K8s | Vector DB, Prompt Engine, LLM-as-a-Judge |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 학습 환경과 서빙 환경의 특징 불일치(Skew) | 중앙 집중식 피처 스토어(Feature Store) 단일 소스 구축 | 오프라인 배치 특징과 온라인 실시간 특징의 무결성 보장 |
| 실험 결과 및 모델 아티팩트 재현 불가 | 코드, 데이터 버전(DVC), 파라미터를 메타데이터 저장소에 바인딩 | 언제든 과거 특정 모델의 100% 동일한 재학습 및 감사 지원 |
| 미검증 모델의 프로덕션 무단 배포 | 모델 레지스트리 기반 자동화된 승격 게이트 및 섀도우 배포 적용 | 기존 챔피언 모델 대비 성능 우수성 검증 후 안전 전환 |
| 불필요하거나 왜곡된 빈번한 자동 재학습 | 통계적 드리프트 유의수준(p-value) 설정 및 배치성 재학습 윈도우 통제 | 인프라 비용 낭비 방지 및 불량 데이터 학습으로 인한 모델 붕괴 예방 |

## Ⅶ. 결론

- **기술 위상/발전**: 머신러닝 PoC 수준의 연구 성과를 엔터프라이즈 프로덕션 환경의 지속가능한 비즈니스 가치로 실현하는 표준 아키텍처로 정착되었으며, 최근에는 생성형 AI 확산에 발맞추어 LLMOps 및 복합 에이전트 운영 파이프라인으로 진화 중
- **실무 적용/통제**: MLOps 성숙도(Level 0~2) 단계적 접근을 기반으로 파이프라인 오케스트레이션, 피처 스토어, 모델 레지스트리를 유기적으로 연계하고, 통계적 드리프트 감지 기반의 무중단 CT 및 롤백 체계 확립 필요
