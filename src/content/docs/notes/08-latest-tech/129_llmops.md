## Ⅰ. 개요

- **정의**: 대규모 언어 모델(LLM) 기반 애플리케이션의 개발과 운영을 위해 프롬프트 엔지니어링, RAG 파이프라인, 모델 파인튜닝, 분산 트레이싱, 안전성 가드레일 및 비용 관리를 체계화한 엔지니어링 운영 프레임워크
- **배경 및 필요성**: 정형 데이터 지도학습 중심의 전통적 MLOps로는 비결정론적 텍스트 생성, 파운데이션 모델 환각(Hallucination), RAG 지식 진부화, 토큰 비용 폭증 및 프롬프트 인젝션 등의 생성형 AI 고유 위험을 통제할 수 없으므로, 프롬프트-RAG-모델 복합 구성을 버전화하고 다축 평가(충실성, 관련성, 안전성)를 자동화하는 LLMOps 체계 도입이 필수적임

## Ⅱ. 특징

- **복합 구성 버전 관리(Configuration Bundling)**: 모델 가중치뿐만 아니라 프롬프트 템플릿, RAG 청킹/임베딩 파라미터, 외부 도구 스키마를 단일 아티팩트로 묶어 버전 관리
- **엔드투엔드 분산 트레이싱(Observability)**: 사용자 프롬프트 입력부터 RAG 검색 컨텍스트, 모델 추론, 도구 호출, 출력 생성까지의 전 과정과 토큰/지연 시간 기록 (LangSmith, Phoenix)
- **다축 자동 평가(Multi-dimensional Evaluation)**: 정답 라벨 부재 환경에서 RAG 3대 지표(Faithfulness, Answer Relevance, Context Precision) 및 LLM-as-a-Judge 기반 실시간 품질 검증
- **런타임 보안 및 비용 통제**: 인바운드 프롬프트 인젝션 필터링, 아웃바운드 PII 마스킹(AI 가드레일), 지능형 LLM 라우팅 기반 토큰 비용 최적화

## Ⅲ. 구조 및 구성요소

### 1. LLMOps 아키텍처

```text
[LLMOps Architecture]
├── [형상 및 자산 관리 계층]
│   └── [구성 레지스트리 (Config Registry)]
├── [파이프라인 및 서빙 계층]
│   ├── [RAG 파이프라인 (RAG Pipeline)]
│   ├── [모델 게이트웨이 (Model Gateway)]
│   └── [평가 하네스 (Evaluation Harness)]
└── [관측 및 피드백 계층]
    └── [추적·피드백 저장소 (Tracing & Feedback)]
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

### 2. 세부 구성요소

| 계층 구분 | 세부 항목 | 핵심 역할 |
|:---|:---|:---|
| 자산 관리 계층 | 프롬프트/구성 레지스트리 | 프롬프트 버전 관리, A/B 테스트 템플릿 배포 및 롤백 제어 |
| 파이프라인 및 서빙 계층 | RAG 파이프라인 | 문서 청킹, 임베딩 생성, 벡터 DB 색인 라이프사이클 관리 |
| | 모델 게이트웨이 | 다중 LLM 라우팅(비용/지연 최적화), Rate Limiting, API 키 통합 관리 |
| | 평가 하네스 (Harness) | Ragas, DeepEval 기반 오프라인 회귀 테스트 및 LLM-as-a-Judge 채점 |
| 관측 및 피드백 계층 | 분산 트레이싱 엔진 | LangSmith, OpenInference 기반 스텝별 지연, 입출력, 토큰 추적 |
| | 가드레일 및 인간 피드백 | NeMo Guardrails 기반 유해 입력/환각 차단 및 사용자 피드백(RLHF) 수집 |

## Ⅳ. 흐름도

```text
[구성 번들링] (① 프롬프트 템플릿, 임베딩 모델, 서빙 파라미터 결합 버전 생성)
  │
  ▼
[오프라인 다축 평가] (② 골든 데이터셋 대상 RAG 지표 및 안전성 자동 평가)
  │
  ▼
[승격 및 게이트웨이 배포] (③ 평가 임계치 통과 시 모델 게이트웨이에 카나리 배포)
  │
  ▼
[런타임 가드레일 및 추론] (④ 입출력 필터링 통과 후 LLM 스트리밍 서빙)
  │
  ▼
[분산 트레이싱 및 비용 감시] (⑤ 스텝별 토큰/지연 로깅 및 인간 피드백 수집)
```

- 분기 결과: 런타임 평가 결과 환각률 또는 PII 유출 감지 시 가드레일이 응답 즉시 차단(Fallback 메시지 반환), 운영 품질 저하 시 이전 승인 구성으로 즉시 롤백

## Ⅴ. 종류 및 비교

| 비교 항목 | LLMOps (생성형 AI 운영) | MLOps (전통 머신러닝 운영) |
|:---|:---|:---|
| 핵심 관리 대상 | 프롬프트, 파인튜닝 가중치, RAG 벡터 색인, 도구 | 훈련 데이터셋, 특징(Feature), 모델 가중치 아티팩트 |
| 훈련/튜닝 방식 | 프롬프트 엔지니어링, PEFT/LoRA, Few-Shot 튜닝 | 전체 파라미터 분산 지도/비지도 학습, 하이퍼파라미터 튜닝 |
| 평가 메커니즘 | RAG 3대 지표, LLM-as-a-Judge, 의미론적 유사도 | 정확도, F1-Score, ROC-AUC, RMSE 등 명확한 정량 지표 |
| 모니터링 초점 | 환각(Hallucination), 안전성/편향, 토큰 비용(TPM) | 데이터 분포 드리프트, 개념 드리프트, 지연 시간(Latency) |
| 개발 주기 | 수시간 내 신속한 프롬프트/검색 파라미터 반복 | 수일~수주의 장시간 데이터 전처리 및 모델 학습 파이프라인 |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 프롬프트 변경 시 기존 응답 품질의 예측 불가능한 퇴보 | CI/CD 파이프라인에 골든 데이터셋 기반 자동 회귀 평가 하네스 구축 | 프롬프트 및 파라미터 수정 시 품질 하락 조기 탐지 및 방지 |
| LLM-as-a-Judge 평가 모델의 편향 및 채점 일관성 결여 | 다중 평가자(Multi-Judge) 교차 검증 및 고위험 응답 인간 평가 병행 | 자동 평가의 신뢰도 제고 및 잘못된 모델 승격 원천 차단 |
| RAG 검색 실패와 모델 자체 추론 실패의 원인 분리 곤란 | 분산 트레이싱(Tracing)을 통해 검색 청크 관련성과 생성 충실성 분리 추적 | 파이프라인 단계별(검색 vs 생성) 장애 원인 신속 식별 및 개선 |
| 복합 에이전트 다단계 호출에 따른 토큰 비용 폭증 | 게이트웨이 수준의 세션별 토큰 버짓 강제 및 저비용 SLM 라우팅 결합 | 인프라 비용 예측 가능성 확보 및 무제한 자원 소비 차단 |

## Ⅶ. 결론

- **기술 위상/발전**: 단순 래퍼 애플리케이션을 넘어 엔터프라이즈급 고신뢰성 생성형 AI 및 자율 에이전트를 안정적으로 운영하기 위한 차세대 MLOps의 핵심 표준으로 정착되었으며, 소형 언어 모델(SLM) 파인튜닝과 복합 에이전트 오케스트레이션으로 진화 중
- **실무 적용/통제**: 프롬프트-RAG-모델 결합 버전 관리, Ragas 기반 지속적 다축 평가, 런타임 가드레일 및 분산 트레이싱을 유기적으로 통합하여 고품질·저비용 생성형 AI 서비스 생태계 구축 필요
