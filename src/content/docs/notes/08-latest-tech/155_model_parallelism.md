## Ⅰ. 개요

- **정의**: 단일 연산 장치(GPU)의 물리적 메모리(VRAM) 한계를 초과하는 거대 인공신경망의 파라미터, 연산 그래프, 활성화 상태를 여러 장치에 분할 배치하여 상호 협력 실행하는 분산 컴퓨팅 기법
- **배경 및 필요성**: 수천억~수조 개 파라미터를 갖는 최신 LLM은 가중치(FP16), 그래디언트, 옵티마이저 상태(Adam FP32) 및 활성화 텐서 용량이 수백 GB~수 TB에 달해 단일 GPU에 적재가 불가능한 메모리 벽(Memory Wall)에 직면함에 따라, 모델의 가중치 행렬을 나누는 텐서 병렬화(TP)와 레이어 단계를 나누는 파이프라인 병렬화(PP)를 결합하여 단일 GPU 메모리 제약을 극복할 필요성 대두

## Ⅱ. 특징

- 모델 레이어 가중치 행렬을 행/열로 분할(TP)하거나 네트워크 깊이별 스테이지로 분할(PP)
- 연산 경계마다 중간 활성화값(Activation) 및 부분 합산 결과를 교환하는 빈번한 노드 간 통신 수반
- 하드웨어 인터커넥트(노드 내 NVLink vs 노드 간 InfiniBand)의 대역폭 계층을 인지한 하이브리드 배치 필수

## Ⅲ. 구조 및 구성요소

```text
[모델 병렬화 아키텍처]
├── [토폴로지 및 병렬화 계획기]
│   └── [3D 병렬화 스케줄러 (Megatron-LM Engine)]
├── [공간적 분할 계층 (Intra-layer)]
│   ├── [텐서 병렬 그룹 (Tensor Parallel Group - TP)]
│   └── [시퀀스 병렬 모듈 (Sequence Parallel Module - SP)]
└── [시간적 분할 계층 (Inter-layer)]
    ├── [파이프라인 스테이지 (Pipeline Stages - PP)]
    └── [1F1B 스케줄러 (One-Forward-One-Backward)]
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

| 구분 | 구성요소 | 기능 설명 |
|:---|:---|:---|
| 제어 및 분할 | 3D 병렬화 스케줄러 | 모델 크기 및 클러스터 하드웨어 토폴로지를 분석하여 TP, PP, DP 차원 최적 배정 |
| 레이어 내 분할 | 텐서 병렬 그룹(TP) | 트랜스포머 어텐션 및 MLP 계층의 가중치 행렬을 열(Column)과 행(Row)으로 분할 연산 |
| 시퀀스 분할 | 시퀀스 병렬 모듈(SP) | 긴 문맥 입력 시 드롭아웃 및 레이어 정규화 구간의 활성화 텐서를 시퀀스 축으로 분할 |
| 레이어 간 분할 | 파이프라인 스테이지(PP) | 수십 개의 트랜스포머 레이어를 순차 그룹으로 묶어 여러 노드에 나누어 배치 |
| 마이크로 스케줄링 | 1F1B 스케줄러 | 순전파 1회 후 즉각 역전파 1회를 교차 실행하여 활성화 메모리 피크와 파이프라인 버블 최소화 |

## Ⅳ. 흐름도

```text
[입력 마이크로배치] (① 배치 데이터를 파이프라인 첫 번째 스테이지 GPU로 공급)
│
▼
[텐서 병렬 연산 (TP)] (② 노드 내 8개 GPU가 NVLink All-Reduce를 통해 어텐션/MLP 부분 합산 완료)
│
▼
[P2P 활성화 전송] (③ 계산된 히든 스테이트(Hidden State) 활성화값을 다음 파이프라인 스테이지로 전달)
│
▼
[역전파 기울기 전파] (④ 최종 출력 손실로부터 역방향으로 파이프라인 스테이지를 거슬러 올라가며 전파)
│
▼
[1F1B 인터리빙 완료] (⑤ 파이프라인 버블을 최소화하며 전체 마이크로배치의 가중치 그래디언트 산출 완료)
```

- 분기 결과: 동일 노드 내부 연산은 초고속 NVLink 텐서 병렬 경로를 따르고, 노드 간 경계 통과 시 InfiniBand P2P 파이프라인 스테이지 전송으로 분기

## Ⅴ. 종류 및 비교

| 비교 항목 | 텐서 병렬화 (TP) | 파이프라인 병렬화 (PP) | 데이터 병렬화 (DDP) |
|:---|:---|:---|:---|
| 분할 대상 축 | 레이어 내부 가중치 행렬 | 모델 깊이(레이어 순서) | 입력 데이터 배치 |
| 통신 특성 | 매 레이어마다 All-Reduce (초고빈도) | 스테이지 경계 간 P2P 전송 (저빈도) | 역전파 완료 후 그래디언트 All-Reduce |
| 권장 네트워크 | 노드 내 고대역폭 NVLink 필수 | 노드 간 고속 InfiniBand/이더넷 수용 가능 | 노드 간 InfiniBand/이더넷 수용 가능 |
| 주요 오버헤드 | 통신 대역폭 포화 (8 GPU 초과 시 급감) | 파이프라인 버블(유휴 시간) 및 활성화 적재 | 모델 전체 크기가 GPU VRAM에 맞아야 함 |
| 메모리 절감 대상 | 파라미터, 그래디언트, 활성화 텐서 | 레이어 수에 비례한 파라미터 분할 | 메모리 절감 없음 (FSDP 제외) |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 텐서 병렬화 그룹 확장(>8) 시 NVLink 외부 대역폭 병목으로 통신 지연 폭증 | TP 크기는 단일 노드(8 GPU) 내부로 엄격히 제한하고 노드 간은 파이프라인(PP) 확장 | 초고속 NVLink 패브릭 완전 활용 및 인터 노드 통신 오버헤드 억제 |
| 파이프라인 병렬화 단계 간 의존성으로 인한 GPU 유휴(Bubble) 시간 발생 | 1F1B 인터리빙 스케줄링 적용 및 마이크로배치 수($m \ge 4 \times p$) 대규모 편성 | 버블 비율 최소화 및 클러스터 연산 장치 가동률(MFU) 극대화 |
| 긴 시퀀스 길이로 인한 어텐션 레이어 활성화 텐서의 VRAM 고갈 | 시퀀스 병렬화(SP) 및 활성화 체크포인팅(Activation Checkpointing) 기법 결합 | 시퀀스 차원 메모리 분산 및 재계산을 통한 활성화 메모리 절감 |

## Ⅶ. 결론

- **기술 위상/발전**: 단일 하드웨어의 물리적 메모리 한계를 원천적으로 돌파하여 수천억~수조 단위 파라미터의 프론티어 파운데이션 모델을 탄생시킨 결정적 분산 컴퓨팅 아키텍처이며, 텐서 병렬화, 파이프라인 병렬화, 데이터 병렬화가 결합된 3D 병렬화로 완성
- **실무 적용/통제**: 노드 내부 8개 GPU 간에는 텐서 병렬화(TP)를 배치하고 멀티 노드 간에는 파이프라인 병렬화(PP)와 FSDP를 결합하는 계층적 3D 병렬화 설계를 채택하며, 1F1B 스케줄링과 활성화 체크포인팅을 통해 연산 가동률(MFU)을 50% 이상으로 유지할 것 권장
