## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **장문맥 대규모 언어 모델(Long Context Large Language Model, Long Context LLM)**: 확장된 컨텍스트 윈도우에서 멀리 떨어진 토큰의 관계와 근거를 함께 처리하는 언어 모델이다.
- **장거리 의존성**: 시퀀스에서 멀리 떨어진 정보들이 의미나 판단에 서로 영향을 주는 관계.

</details>

- 정의/개념: 확장 문맥에서 **장거리 의존성**을 처리하는 LLM
- 배경/필요성: 기존의 짧은 컨텍스트 윈도우(2K~8K 토큰) 환경에서는 수백 페이지의 도서, 방대한 코드베이스, 법률 판례집 등 장문 문서를 처리하기 위해 문서를 임의 조각(Chunk)으로 분할해야 했고, 이로 인해 문서 전체에 걸쳐 흩어진 장거리 의존성(Long-range Dependency)과 거시적 인과 관계가 단절되는 RAG 검색의 구조적 한계가 발생함에 따라, 수십만~수백만 토큰(32K~1M+)을 단일 프롬프트로 직접 수용하는 장문맥 대규모 언어 모델(Long Context LLM) 기술을 도입하여 **문서 분할 없는 원문 전체의 전역적 문맥 이해 및 다중 추론(Multi-hop Reasoning) 역량 확보, RoPE 위치 보간(PI/YaRN) 및 FlashAttention 기반의 장문 인프라 최적화, 건초더미 속 바늘 찾기(NIAH) 전 구간에서의 정밀한 정보 회수율 달성**을 달성할 필요

#### 한줄 요약
- 창을 넓히면 **장거리 의존성•근거**를 분할 없이 잇지만 KV 메모리와 지연이 길이에 비례해 늘고 중간 구간 활용도는 떨어지므로, 긴 문맥과 검색은 대체가 아니라 병용 대상이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **위치 표현 확장**: 학습한 길이 밖에서도 토큰의 순서와 거리를 해석하도록 위치 규칙을 조정하는 기법이다.
- **회전 위치 임베딩(Rotary Position Embedding, RoPE)**: Q•K 회전으로 상대적 거리를 반영하는 기법.
- **희소 어텐션(Sparse Attention)**: 선택된 토큰 관계만 계산하여 비용을 줄이는 방식이다.
- **윈도우 어텐션(Window Attention)**: 일정 범위 안의 토큰 관계만 계산하는 방식.
- **유효 문맥 길이**: 최대 입력 한도 중 모델이 실제로 근거를 정확히 회수하고 결합할 수 있는 범위로 정의된다.

</details>

![문맥 길이에 따른 어텐션 상호작용 증가 개념도](/study/diagrams/long-context-attention-growth.svg)

> 파란 전체 어텐션 선은 문맥 길이의 제곱으로 증가하지만 붉은 고정 윈도우 선은 선형 증가하며, 정규화한 가정값이지 실측값은 아니다.

- **위치 표현 확장**: 학습 범위 밖 토큰 순서 해석
- **희소 어텐션**: 선택된 토큰 관계만 계산
- **윈도우 어텐션**: 일정 범위의 지역 관계 계산
- **유효 문맥 길이**: 위치별 근거 회수•결합 범위

#### 한줄 요약
- 최대 길이보다 **유효 문맥 길이•근거 회수율** 중시

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **위치 보간(Position Interpolation)**: 긴 위치 인덱스를 학습된 범위 안으로 비례 압축하여 입력 길이를 확장하는 기법.
- **프리필(Prefill)**: 장문 입력의 어텐션 상태를 먼저 계산하는 처리.
- **키-값 캐시(Key-Value Cache, KV Cache)**: 계산한 상태를 후속 토큰 생성에서 재사용하는 메모리이다.

</details>

```text
[장문맥 LLM(Long Context LLM) 아키텍처]
├── [장문 학습 데이터 (Long-Context Data)]
│   ├── 대용량 장문 말뭉치 (Book, Code, Docs)
│   └── 합성 장거리 추론 및 질의응답 데이터
├── [위치 표현 계층 (Positional Scaling)]
│   ├── RoPE 위치 보간 (Linear / NTK-aware PI)
│   └── 주파수 스케일링 (YaRN / LongRoPE)
├── [효율적 어텐션 계층 (Efficient Attention)]
│   ├── 하드웨어 가속 어텐션 (FlashAttention)
│   └── 블록/희소/윈도우 어텐션 (Sparse Attention)
├── [메모리 및 서빙 계층 (Memory & Serving)]
│   ├── 분산 KV Cache 관리 (PagedAttention)
│   └── 청크 기반 프리필 (Chunked Prefill)
└── [장문맥 평가 계층 (Evaluation & Benchmark)]
    ├── 건초더미 바늘 찾기 (NIAH 벤치마크)
    └── 장거리 다중 근거 추론 평가 (Multi-hop QA)
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 장문맥 LLM 아키텍처의 계층 분할 및 세부 기술 모듈 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 장문 학습 데이터 | 수만~수백만 토큰 장거리 문맥 데이터셋 및 다중 추론 과업 제공 |
| 위치 표현 계층 | RoPE 위치 보간(PI/YaRN)을 통해 학습 범위를 초과하는 위치 좌표 확장 |
| 효율적 어텐션 계층 | FlashAttention 및 희소/윈도우 어텐션으로 $O(N^2)$ 연산 부하 완화 |
| 메모리 및 서빙 계층 | PagedAttention 및 청크 프리필로 초장문 KV Cache 메모리 파편화 방지 |
| 장문맥 평가 계층 | NIAH 및 Multi-hop QA 벤치마크로 위치별 정보 회수율 및 품질 검증 |

#### 한줄 요약
- **위치•어텐션•캐시•평가** 동시 확장

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **컨텍스트 윈도우(Context Window)**: 한 번의 추론에서 모델이 입력과 출력으로 처리할 수 있는 최대 토큰 범위.
- **장거리 근거 회수**: 긴 입력의 여러 위치에서 질문과 관련된 정보를 찾아 생성 문맥에 반영하는 과정.
- **장문 입력 구성**: 지시•원문•출력 여유를 컨텍스트 윈도우 안에 배치하는 절차.
- **장거리 관계 계산**: 전체 또는 희소•윈도우 범위에서 관련 토큰의 정보를 결합하는 절차.
- **프리필•KV Cache 생성**: 장문 입력을 병렬 계산하고 후속 생성용 상태를 저장하는 절차이다.
- **장거리 근거 회수•결합**: 긴 입력의 관련 정보를 찾아 하나의 응답 근거로 통합하는 절차이다.

</details>

```text
[대용량 장문 원문 및 질의 입력]
       │
       ▼
[위치 인코딩 확장 (RoPE/YaRN)] (① 긴 위치 인덱스에 맞춘 주파수 스케일링 적용)
       │
       ▼
[청크 단위 프리필 및 FlashAttention] (② GPU 메모리 한도 내 분할 프리필 및 온칩 가속)
       │
       ▼
[PagedAttention 기반 KV 캐시 적재] (③ 불연속 물리 메모리 블록에 초장문 캐시 효율적 배치)
       │
       ▼
[전역 장거리 의존성 분석 및 근거 회수] (④ 문맥 전반에서 다중 홉(Multi-hop) 추론 수행)
       │
       ▼
[답변 토큰 자기회귀 생성] (⑤ 통합된 전역 문맥을 기반으로 정확한 결과 도출)
```

- 분기 결과: 생성 결과 반환 후 다음 쿼리를 위한 장문 접두사 KV 캐시 보존 또는 메모리 반환 완료

#### 한줄 요약
- **위치 확장•관계 계산•KV Cache** 기반 근거 결합

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **직접 장문 입력**: 원문 전체를 하나의 넓은 컨텍스트에 넣어 전역 관계를 모델이 직접 처리하는 방식.
- **검색 증강 생성(Retrieval-Augmented Generation, RAG)**: 질의와 관련된 외부 문서 조각을 검색해 모델 입력에 근거로 제공하는 방식.

</details>

- 전역 관계 분석과 선택 검색 범위에 따른 방식 구분

| 구분 | 직접 장문 입력 | RAG |
|:---|:---|:---|
| 적용 기준 | 전체 문서 전역 관계 분석 | 대규모•갱신 지식 선택 검색 |
| 핵심 특징 | 원문 전체 단일 문맥 처리 | 관련 문서 조각 검색 후 주입 |
| 한계 | 프리필•KV 캐시 비용과 중간 근거 손실 | 검색 누락•문서 관계 단절 |

#### 한줄 요약
- 전역 관계는 **직접 장문 입력**, 선택 근거는 **RAG**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **건초더미 속 바늘 찾기(Needle in a Haystack, NIAH)**: 긴 문맥의 여러 위치에 숨긴 특정 근거를 얼마나 정확히 회수하는지 확인하는 평가.
- **접두사 캐싱(Prefix Caching)**: 여러 요청이 공유하는 입력 앞부분의 프리필 결과를 저장해 재사용하는 기법이다.
- **동적 배치(Dynamic Batching)**: 도착 시점과 길이가 다른 요청을 실행 중에 묶어 연산 자원 사용률을 높이는 방식이다.
- **민감정보 마스킹(Data Masking)**: 입력의 개인정보나 비밀값을 제거하거나 대체값으로 가려 노출을 줄이는 보호 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 이차 어텐션 계산 비용 폭증 | FlashAttention 타일링 및 슬라이딩 윈도우/희소 어텐션 적용 | GPU 연산 복잡도 완화 및 프리필 지연 시간 단축 |
| 문맥 중간 정보 회수율 저하(NIAH 한계) | 위치별 균등 NIAH 평가 및 멀티홉 QA 검증 벤치마크 수행 | 유효 문맥 길이 정확도 측정 및 근거 누락 방지 |
| 초장문 프리필 지연 및 KV 캐시 메모리 압박 | 청크 프리필(Chunked Prefill) 및 접두사 캐싱(Prefix Caching) 도입 | GPU 메모리 파편화 방지 및 서빙 동시 처리량 증대 |
| 대용량 문서 내 미인가 민감정보 노출 | 입력 단계 테넌트 권한 격리 및 민감정보 마스킹 파이프라인 연계 | 초장문 프롬프트 내 개인정보 및 보안 데이터 유출 차단 |

#### 한줄 요약
- **회수율•지연•메모리•권한** 통합 평가

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **장문 처리 방식 선택 기준**: 전역 의존성에는 직접 장문 입력을, 일부 최신 근거에는 RAG를 적용하는 기준이다.

</details>

- **기술 위상/발전**: 방대한 문서와 전체 코드베이스를 단일 공간에 수용하는 **차세대 인지 컴퓨팅의 표준 백본**이며, 1M~10M 토큰급 초장문 모델과 RAG의 하이브리드 결합으로 진화
- **실무 적용/통제**: 초장문 서빙 시 발생하는 지연과 메모리 병목을 극복하기 위해 **FlashAttention 및 PagedAttention/접두사 캐싱**을 연계하고, 위치별 NIAH 검증을 필수로 수행

#### 한줄 요약
- **전역 의존성•근거 갱신 범위** 대상 따라 처리 방식 결정
