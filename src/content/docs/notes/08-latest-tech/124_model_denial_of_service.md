## Ⅰ. 개요

- **정의**: 거대 언어 모델(LLM) 및 생성형 AI 인프라를 대상으로 입력 문맥 길이 증폭, 장문 생성 유도, 재귀 도구 호출을 유발하여 GPU 연산량, KV 캐시 메모리, 외부 API 비용을 고갈시켜 정상 서비스 가용성을 마비시키는 자원 고갈 공격 기법
- **배경 및 필요성**: 전통적 HTTP 요청 건수(RPM) 기반 제한은 단일 요청으로 수천 배의 GPU 연산과 메모리를 소모하는 Sponge Examples 공격이나 에이전트 무한 루프 공격을 차단하지 못하므로, OWASP LLM Top 10(LLM10: Unbounded Consumption) 대응을 위해 입력/출력 토큰(TPM), 동시 실행 수, 에이전트 호출 예산을 다차원 계량하고 테넌트별 자원을 격리하는 방어 체계 구축이 필수적임

## Ⅱ. 특징

- **다차원 자원 소모**: 단순 네트워크 대역폭이 아닌 GPU 연산량, KV 캐시 메모리, 입출력 토큰 수, 외부 API 요금 고갈 유발
- **비대칭 비용 구조**: 공격자의 경량 프롬프트 주입 대비 서빙 시스템의 막대한 GPU 추론 연산 및 메모리 점유 발생
- **정상 요청 가용성 마비**: 고비용 악의적 요청의 실행 슬롯 및 KV 캐시 독점으로 대기열 지연, 서빙 타임아웃, OOM(Out of Memory) 유발
- **다계층 통제 요구**: 인입 게이트웨이의 토큰/요청 다차원 제한, 스케줄러의 공정 큐잉, 서빙 엔진의 동적 KV 캐시 축출 결합 필요

## Ⅲ. 구조 및 구성요소

### 1. 방어 아키텍처

```text
[Model DoS Defense System]
├── [인입 및 계량 계층]
│   ├── [요청 게이트웨이 (Request Gateway)]
│   └── [작업량 계량기 (Resource Meter)]
├── [스케줄링 및 큐 계층]
│   └── [대기열·스케줄러 (Queue & Scheduler)]
└── [실행 및 격리 계층]
    ├── [추론 실행기 (Inference Executor)]
    └── [도구 실행기 (Tool Runner)]
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

### 2. 세부 구성요소

| 구성요소 | 세부 항목 | 핵심 역할 |
|:---|:---|:---|
| 인입 및 계량 계층 | 요청 게이트웨이 | 주체 인증, API 키 식별 및 다차원 접근 한도 판정 |
| | 작업량 계량기 | 요청별 입력 토큰, 예상 출력 토큰, 외부 도구 호출량 실시간 누적 |
| 스케줄링 및 큐 계층 | 공정 큐 (Fair Queue) | 테넌트별 격리 큐 기반 공정 스케줄링 및 동시성 제어 |
| | 지능형 스케줄러 | GPU 메모리 점유율 기반 우선순위 스케줄링 및 선점(Preemption) |
| 실행 및 격리 계층 | 추론 실행기 | PagedAttention 기반 KV 캐시 관리, OOM 방지 및 생성 토큰 제한 |
| | 도구 실행기 | 에이전트 재귀 도구 호출 제한, 타임아웃 및 서킷 브레이커 강제 |

## Ⅳ. 흐름도

```text
[공격 인입] (① 공격자의 고비용 프롬프트 및 긴 문맥 요청 제출)
  │
  ▼
[게이트웨이 검증] (② API 키 식별 및 RPM/TPM 다차원 한도 검사)
  │
  ▼
[대기열 스케줄링] (③ 테넌트별 독립 실행 풀 배정 및 공정 큐잉)
  │
  ▼
[추론 및 도구 실행] (④ PagedAttention KV 캐시 할당 및 에이전트 스텝 제어)
  │
  ▼
[예산 모니터링] (⑤ 토큰 상한/시간 초과 시 즉각 중단 및 정상 가용성 보존)
```

- 분기 결과: 허용 한도(TPM/RPM/Max Steps) 초과 시 HTTP 429(Too Many Requests) 반환 및 GPU 추론 즉시 중단, 정상 요청은 격리된 슬롯에서 지연 없이 완료

## Ⅴ. 종류 및 비교

| 공격 및 자원 소모 경로 | 입력 길이 증폭 (Input Sponge) | 출력 길이 증폭 (Output Bloat) | 도구·에이전트 반복 (Agent Loop) |
|:---|:---|:---|:---|
| 주요 공격 메커니즘 | 방대한 컨텍스트 및 패딩 주입 | 무한 생성 유도 프롬프트 주입 | 재귀적 도구 호출 유도 프롬프트 |
| 자원 고갈 대상 | 입력 연산량 및 KV 캐시 메모리 | 순차 생성 시간 및 GPU 슬롯 독점 | 외부 API 비용 및 백엔드 시스템 부하 |
| 핵심 방어 기법 | 최대 입력 토큰 제한 및 청킹 | Max Tokens 강제 및 Early Stopping | 최대 스텝 수 제한 및 서킷 브레이커 |
| 통제 한계 | 출력 생성 단계의 자원 통제 불가 | 입력 단계의 연산 폭증 방어 불가 | 외부 API 자체의 DoS 방어 연계 필요 |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 적은 요청 수 기반의 긴 토큰 점유 | API 키/사용자별 RPM 및 TPM 다차원 동시 제한 | 단일 요청을 통한 GPU 연산 및 메모리 독점 원천 차단 |
| 에이전트 및 외부 도구 무한 재귀 호출 | 최대 실행 스텝(Max Steps), 타임아웃, 도구 호출 예산 강제 | 무한 루프로 인한 인프라 장애 및 클라우드 비용 폭증 방지 |
| 고비용 요청의 공유 대기열 독점 | 테넌트별 독립 실행 풀 할당 및 PagedAttention 선점 적용 | 악의적 요청 발생 시에도 정상 사용자의 응답 가용성 보존 |

## Ⅶ. 결론

- **기술 위상/발전**: 생성형 AI 및 에이전트 환경에서 GPU 컴퓨팅 인프라를 악의적 자원 고갈 및 금융 비용 폭탄 공격(Denial of Wallet)으로부터 방어하는 필수 보안 표준(OWASP LLM10)으로 자리 잡았으며, vLLM 등 고성능 서빙 엔진의 PagedAttention 및 동적 선점 기법과 결합하여 진화 중
- **실무 적용/통제**: AI API 게이트웨이 도입 시 RPM/TPM 다차원 계량, 에이전트 실행 단계 제한, GPU 메모리 임계치 기반 서킷 브레이커를 결합한 계층적 방어선 구축이 필수적
