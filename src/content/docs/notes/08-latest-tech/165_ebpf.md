## Ⅰ. 개요

- **정의**: 리눅스 커널 소스 코드를 직접 수정하거나 커널 모듈을 재컴파일하지 않고도, 커널 내부의 격리된 샌드박스에서 정적 검증(Verifier)을 통과한 바이트코드를 안전하고 동적으로 실행하여 커널 기능을 확장하는 기술
- **배경 및 필요성**: 전통적인 리눅스 커널 모듈(LKM)은 작은 버그 하나로도 커널 패닉을 유발할 위험이 있고, 사용자 공간 에이전트는 잦은 시스템 콜과 메모리 복사로 인한 심각한 오버헤드를 야기하므로, 정적 검증을 통한 커널 안정성을 담보하면서도 커널 공간 내 네이티브 속도로 네트워크 가속, 보안 통제, 관측성을 제공할 필요성 대두

## Ⅱ. 특징

- **무결점 런타임 안전성**: 커널 내부 정적 검증기(Verifier)가 프로그램 적재 전 종료 가능성(무한 루프 방지), 유효하지 않은 메모리 접근 및 포인터 연산을 엄격히 검증
- **JIT 컴파일 기반 고성능**: 바이트코드를 호스트 CPU 아키텍처 네이티브 기계어로 실시간 변환하여 제로 카피 및 마이크로초 단위 초저지연 실행
- **다양한 커널 훅 포인트**: XDP(네트워크 드라이버 레벨), TC, Kprobe, Tracepoint, 소켓 계층 등 커널의 전 실행 경로에 비침습적 부착 가능
- **eBPF Map 기반 상태 공유**: 커널과 사용자 공간 간에 해시 테이블, 배열, 링 버퍼 등 고성능 데이터 구조를 통해 양방향 상태 및 통계 교환

## Ⅲ. 구조 및 구성요소

```text
[eBPF 아키텍처]
├── [사용자 공간 (User Space)] ── 로더(libbpf), eBPF 프로그램 소스(C/Rust), CLI 도구(bpftool)
├── [커널 검증 및 컴파일] ────── In-Kernel Verifier (안전성 검사), JIT Compiler (네이티브 변환)
├── [커널 이벤트 훅 (Hooks)] ──── XDP, TC, Kprobes/Kretprobes, Tracepoints, Socket Layer
├── [상태 공유 및 통신] ─────── eBPF Maps (Hash, Array, Ring Buffer), Helper Functions
└── [이식성 보장 체계] ──────── CO-RE (Compile Once - Run Everywhere), BTF (BPF Type Format)
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

| 구성요소 | 설명 | 주요 역할 |
|:---|:---|:---|
| 사용자 공간 로더 | libbpf 기반 프로그램 관리 라이브러리 | eBPF ELF 바이너리를 파싱하여 bpf() 시스템 콜을 통해 커널에 적재하고 훅에 바인딩 |
| In-Kernel Verifier | 적재 전 실행 안전성 정적 분석기 | 모든 실행 경로의 도달 가능성, 루프 제한, 메모리 경계 검사를 수행하여 커널 크래시 차단 |
| JIT Compiler | 바이트코드 네이티브 변환 엔진 | 검증을 마친 eBPF 바이트코드를 x86_64, ARM64 기계어로 즉시 변환하여 인터프리터 오버헤드 제거 |
| 커널 훅(Hooks) | 커널 내부 이벤트 트리거 지점 | XDP(패킷 수신 최단 경로), TC(트래픽 제어), Kprobe(함수 진입점) 등에서 이벤트 발생 시 코드 구동 |
| eBPF Maps | 커널-사용자 공간 양방향 메모리 채널 | 네트워크 필터링 규칙, 메트릭 집계, 분산 추적 데이터를 효율적으로 공유하는 인메모리 저장소 |
| CO-RE & BTF | 커널 버전 독립적 이식성 프레임워크 | BPF Type Format을 통해 대상 커널의 구조체 오프셋을 런타임에 자동 재배치하여 단일 바이너리 배포 지원 |

## Ⅳ. 흐름도

```text
[eBPF 바이트코드 컴파일] (① Clang/LLVM을 통해 C/Rust 소스를 eBPF 바이트코드로 컴파일)
│
▼
[커널 주입 및 안전성 검증] (② bpf() 시스템 콜로 커널에 적재 후 Verifier가 루프 및 메모리 안전성 검사)
│
▼
[JIT 네이티브 기계어 변환] (③ JIT 컴파일러가 검증된 바이트코드를 호스트 CPU 네이티브 명령어로 변환)
│
▼
[커널 훅 포인트 부착] (④ XDP, Kprobe, 소켓 계층 등 지정된 커널 이벤트 훅에 바이트코드 바인딩)
│
▼
[이벤트 감지 및 인커널 실행] (⑤ 패킷 인입 또는 시스템 콜 호출 시 커널 컨텍스트에서 제로 카피로 즉시 실행)
│
▼
[eBPF Map 데이터 동기화] (⑥ Ring Buffer/Map을 통해 사용자 공간 애플리케이션과 통계 및 이벤트 공유)
```

- 분기 결과: 검증 실패 시 EINVAL 에러 반환 및 적재 거부, 훅 실행 중 패킷 드롭(XDP_DROP) 또는 통과(XDP_PASS) 즉시 판정

## Ⅴ. 종류 및 비교

| 구분 | eBPF | 리눅스 커널 모듈 (LKM) | 사용자 공간 에이전트 |
|:---|:---|:---|:---|
| 안전성 보장 | Verifier 정적 검증으로 커널 크래시 원천 방지 | 단일 포인터 결함으로도 커널 패닉 유발 | 프로세스 격리로 호스트 안전 (비정상 종료 한정) |
| 실행 성능 | JIT 네이티브 실행 및 제로 카피 (매우 빠름) | 커널 네이티브 속도 (매우 빠름) | 잦은 컨텍스트 스위칭 및 메모리 복사로 상대적 저하 |
| 개발/배포 편의 | 소스 재컴파일 없이 동적 적재 및 갱신 | 커널 버전마다 재빌드 및 insmod 필요 | 일반적인 사용자 프로세스 빌드 및 배포 |
| 기능 표현력 | Verifier 제약(명령어 수, 도움 함수 한정) | 커널 내부 모든 함수 및 메모리 임의 접근 | 표준 POSIX API 및 시스템 콜에 국한 |

## Ⅵ. 실무 고려사항 및 대책

| 문제점 | 대책 | 효과 |
|:---|:---|:---|
| 커널 버전 업데이트 시 구조체 오프셋 변경으로 오류 발생 | CO-RE(Compile Once - Run Everywhere) 및 BTF 표준 채택 | 다종 리눅스 커널 환경에서 무재컴파일 단일 바이너리 구동 |
| 패킷 인입량 폭증 시 eBPF Map 경합으로 CPU 지연 유발 | BPF_MAP_TYPE_PERCPU_* 맵 또는 Lockless Ring Buffer 사용 | CPU 코어 간 락 경합 완전 제거 및 초고속 이벤트 파이프라인 구축 |
| 악의적 사용자의 eBPF 프로그램 적재를 통한 커널 탈취 | CAP_BPF 최소 권한 분리 및 서명된 BPF 프로그램만 허용 | 비인가 프로그램 적재 차단 및 커널 보안 무결성 확보 |

## Ⅶ. 결론

- **기술 위상/발전**: 리눅스 커널을 프로그래밍 가능한(Programmable) 인프라 플랫폼으로 재탄생시키며 Cilium(CNI/Service Mesh), Tetragon(런타임 보안), Parca(프로파일링) 등 차세대 클라우드 네이티브의 핵심 기술로 자리매김
- **실무 적용/통제**: CO-RE 및 BTF를 기본 아키텍처로 채택하여 커널 파편화를 극복하고, 고빈도 네트워크 경로에는 Lockless Ring Buffer와 XDP 드라이버 모드를 결합한 초저지연 인프라 설계 필수
