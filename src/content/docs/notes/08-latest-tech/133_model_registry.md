## Ⅰ. 개요

- **정의**: 훈련 완료된 머신러닝/딥러닝 모델의 아티팩트, 하이퍼파라미터, 성능 평가 지표 및 계보(Lineage)를 중앙에서 불변(Immutable) 상태로 등록·관리하고 배포 라이프사이클을 통제하는 전용 거버넌스 저장소
- **배경 및 필요성**: 수많은 실험 과정에서 생성되는 모델 바이너리를 단순 스토리지에 보관할 경우 학습 데이터/코드와의 추적성 결여, 미검증 모델의 프로덕션 무단 배포, 장애 시 신속한 롤백 불가 등의 위험이 발생하므로, 엄격한 승격 게이트(Promotion Gate)와 논리적 별칭(Alias) 기반의 모델 수명주기 통제 허브가 필수적임

## Ⅱ. 특징

- **불변 모델 아티팩트 및 해시 검증**: 등록 시점의 모델 가중치 바이너리에 암호학적 체크섬(SHA-256)을 부여하여 사후 변조 원천 차단
- **엔드투엔드 모델 계보(Lineage) 추적**: 훈련에 사용된 원천 데이터 버전(DVC), 소스 코드 Git 커밋 해시, 실행 환경(Docker), 하이퍼파라미터 완전 바인딩
- **원자적 별칭(Atomic Alias) 라우팅**: 프로덕션 서빙 환경에 물리적 버전 번호 대신 논리적 별칭(e.g., `@champion`, `@challenger`)을 부여하여 1초 미만 즉각 롤아웃 및 롤백 지원
- **규제 준수 모델 카드(Model Card) 연동**: 모델 의도, 성능 벤치마크, 공정성/편향성 평가 결과 및 보안 취약점 점검 증적을 표준 양식으로 자동 생성

## Ⅲ. 구조 및 구성요소

### 1. 모델 레지스트리 아키텍처

```text
[Model Registry Architecture]
├── [모델 네임스페이스 계층]
│   └── [모델 이름 (Model Namespace)]
├── [버전 및 아티팩트 계층]
│   ├── [불변 버전 (Immutable Version)]
│   └── [계보 정보 (Lineage Metadata)]
└── [거버넌스 및 배포 상태 계층]
    ├── [상태·별칭 (Stage & Alias)]
    └── [승인 정책 (Promotion Gate)]
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

### 2. 세부 구성요소

| 계층 구분 | 세부 항목 | 핵심 역할 |
|:---|:---|:---|
| 네임스페이스 계층 | 등록 모델 네임스페이스 | 프로젝트 및 비즈니스 과업별 논리적 모델 단위 정의 |
| 버전 및 아티팩트 계층 | 불변 버전 (Model Version) | 증가형 정수 버전 번호, 가중치 아티팩트 저장소(S3/GCS) URI 및 해시 관리 |
| | 계보 메타데이터 저장소 | MLflow Tracking 연계 학습 파라미터, 메트릭, 소스 코드/데이터셋 버전 기록 |
| 거버넌스 및 배포 계층 | 라이프사이클 스테이지/별칭 | Staging, Production, Archived 상태 및 논리적 트래픽 타깃 별칭 관리 |
| | 승격 게이트 (Promotion Gate) | 정량적 성능 임계치 및 보안/컴플라이언스 승인 기반 프로덕션 전환 통제 |

## Ⅳ. 흐름도

```text
[모델 학습 완료] (① 분산 학습 파이프라인에서 체크포인트 및 평가 지표 도출)
  │
  ▼
[레지스트리 등록] (② 모델 레지스트리에 아티팩트 불변 등록 및 계보 메타데이터 바인딩)
  │
  ▼
[승격 게이트 심사] (③ 스테이징 환경에서 오프라인 벤치마크 및 보안 취약점 자동 검증)
  │
  ▼
[원자적 별칭 승격] (④ 승인 완료 시 프로덕션 별칭(@champion)을 신규 버전으로 전환)
  │
  ▼
[운영 관측 및 롤백] (⑤ 성능 저하 또는 이상 감지 시 이전 안정 버전으로 별칭 즉시 원복)
```

- 분기 결과: 승격 심사 기준 미달 시 배포 차단 및 반려 알림 전송, 운영 중 이상 징후 발생 시 서빙 시스템 재배포 없이 별칭 맵핑만 변경하여 무중단 롤백 완료

## Ⅴ. 종류 및 비교

| 비교 항목 | 모델 레지스트리 (Model Registry) | 범용 아티팩트 저장소 (Artifactory) | 실험 추적 도구 (Experiment Tracking) |
|:---|:---|:---|:---|
| 주요 목적 | ML 모델의 전 생애주기 거버넌스 및 배포 통제 | 소프트웨어 바이너리, 패키지(JAR/Wheel) 보관 | 수많은 실험 실행(Run)의 파라미터/결과 비교 |
| 관리 단위 | 모델 네임스페이스 및 정제된 정수 버전 | 경로 기반 파일 아티팩트 및 해시 | 개별 파라미터 탐색 실행(Experiment Run) |
| 배포 통제 | 스테이지 전환, 논리적 별칭, 모델 승격 게이트 | 단순 다운로드 및 패키지 릴리스 저장 | 배포 상태 관리 기능 부재 (연구 목적) |
| 대표 도구 | MLflow Registry, Kubeflow, W&B Registry | JFrog Artifactory, Nexus, AWS CodeArtifact | Weights & Biases, MLflow Tracking, Neptune |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 평가 단계 모델과 프로덕션 배포 바이너리 불일치 | 등록 시점 암호학적 SHA-256 해시 생성 및 서빙 전 무결성 자동 검증 | 모델 가중치 무단 변조 및 잘못된 아티팩트 배포 원천 차단 |
| 수작업 설정 오류로 인한 미검증 모델 배포 사고 | RBAC 기반 승인 워크플로우 및 원자적 별칭(Atomic Alias) 전환 적용 | 품질 기준 통과 모델에 한정한 안전한 프로덕션 승격 보장 |
| 배포 후 운영 장애 발생 시 복구 지연 | 서빙 인프라가 레지스트리 별칭(@champion)을 동적 참조하도록 구성 | 장애 발생 시 1초 내 즉각 롤백(Zero-Downtime Rollback) 달성 |
| 규제 감사 시 모델 생성 이력 및 데이터 출처 소명 불가 | 모델 카드(Model Card) 자동 렌더링 및 SBOM(소프트웨어 자재명세서) 바인딩 | EU AI Act 등 글로벌 AI 거버넌스 규제 감사 완벽 대응 |

## Ⅶ. 결론

- **기술 위상/발전**: 머신러닝 연구 실험과 프로덕션 서빙 환경을 신뢰성 있게 연결하는 MLOps 거버넌스의 핵심 중앙 통제 허브로 정착되었으며, 최근에는 대형 파운데이션 모델(LLM) 가중치 및 LoRA 어댑터 수명주기 관리로 영역 확장 중
- **실무 적용/통제**: MLflow, Kubeflow 등 검증된 도구를 통해 코드-데이터-모델 삼위일체 계보를 확립하고, 엄격한 승격 게이트 및 논리적 별칭 기반 라우팅을 구축하여 무결점 모델 배포 달성 필요
