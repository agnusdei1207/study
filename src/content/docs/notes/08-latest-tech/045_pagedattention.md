## Ⅰ. 개요

- **정의**: 운영체제의 가상 메모리 페이징(Paging) 원리를 LLM 서빙에 적용하여, 가변 길이의 **KV 캐시(Key-Value Cache)**를 고정 크기의 비연속 물리 메모리 블록에 동적 할당하고 논리-물리 주소를 매핑하는 메모리 관리 최적화 기술.
- **배경 및 필요성**:
  - **메모리 과예약 낭비 완화**: 기존 연속 메모리 할당 방식의 최대 시퀀스 길이 사전 예약으로 인한 VRAM 낭비(60~80%) 극복.
  - **단편화(Fragmentation) 제거**: 고정 크기 블록(16/32 토큰) 단위 동적 할당으로 외부 단편화를 근본적으로 차단하고 내부 단편화를 4% 미만으로 최소화.
  - **메모리 공유 및 처리량 극대화**: 병렬 샘플링, 빔 서치, 프롬프트 접두사(Prefix) 공유 시 쓰기 시 복사(Copy-on-Write) 메커니즘을 지원하여 동시 서빙 배치 크기 확장.

## Ⅱ. 핵심 특징

- **비연속 물리 블록 매핑**: 가상 주소 공간의 논리 블록을 GPU VRAM 상의 비연속 물리 블록과 1:1 대응.
- **온디맨드 동적 할당**: 토큰이 실제 생성되는 시점에 필요한 만큼만 물리 블록을 풀(Pool)에서 인출하여 할당.
- **쓰기 시 복사(Copy-on-Write)**: 동일 프롬프트나 접두사를 공유하는 요청 간 물리 메모리를 공유하고, 분기 발생 시점에만 신규 블록 복제.
- **전용 Paged 커널**: 비연속적으로 분산된 물리 블록 주소를 블록 테이블을 참조하여 연속 주소처럼 어텐션을 병렬 계산.

## Ⅲ. 구조 및 구성요소

```text
[PagedAttention 서빙 메모리 아키텍처]
├── [논리 KV 블록 계층 (Logical Blocks)]
│   ├── 시퀀스 토큰 순서의 연속 가상 주소 공간
│   └── 고정 크기 블록(16/32 토큰) 단위 분할 구조
├── [블록 매핑 테이블 (Block Table)]
│   ├── 논리 블록 번호 ↔ 물리 블록 주소 변환
│   └── 블록별 참조 카운트(Reference Count) 관리
├── [물리 블록 풀 (Physical Block Pool)]
│   ├── GPU VRAM 내 비연속 고정 블록 풀 관리
│   └── 온디맨드 동적 할당 및 완료 시 즉시 회수
└── [어텐션 실행 및 커널 (Paged Kernel & COW)]
    ├── 비연속 블록 인출 PagedAttention 연산 커널
    └── 쓰기 시 복사(Copy-on-Write) 기반 분기 처리
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 PagedAttention 메모리 관리 체계의 상위 계층과 세부 구성요소 간 계층적 포함 관계를 나타낸다.

| 구성요소 | 역할 및 세부 기능 |
|:---|:---|
| 논리 KV 블록 | 토큰 시퀀스 순서에 따른 가상 연속 캐시 주소 공간 제공 |
| 블록 매핑 테이블 | 논리 블록 번호와 물리 메모리 블록 간의 주소 변환 및 참조 카운트 추적 |
| 물리 블록 풀 | GPU VRAM 내 고정 크기 물리 블록들의 동적 할당 및 반납 생명주기 제어 |
| Paged 커널 | 블록 테이블을 참조하여 비연속 물리 메모리 블록에서 직접 어텐션을 수행하는 GPU 커널 |

## Ⅳ. 흐름도

```text
[요청 수신 및 프롬프트 인출] (① 사용자 프롬프트 입력 및 필요 논리 블록 크기 계산)
       │
       ▼
[물리 블록 할당 및 매핑] (② 물리 블록 풀에서 고정 블록 할당 후 블록 테이블에 주소 등록)
       │
       ▼
[Paged 어텐션 연산 수행] (③ 블록 테이블을 참조하여 비연속 메모리에서 토큰 단위 생성 및 캐시 저장)
       │
       ▼
[블록 분기 및 동적 확장] (④ 신규 토큰 생성 시 블록 가득 참 여부에 따라 신규 블록 추가 할당 및 COW 적용)
       │
       ▼
[요청 완료 및 블록 회수] (⑤ 추론 종료 시 참조 카운트 감소 후 0 도달 블록을 물리 풀로 즉시 반납)
```

- 분기 결과: 신규 토큰 공간 부족 시 물리 풀에서 추가 블록 동적 바인딩, 세션 종료 시 참조 카운트 0 도달 블록은 즉시 재사용 풀로 환원.

## Ⅴ. 종류 및 비교

| 비교 항목 | 연속 KV 캐시 할당 | PagedAttention |
|:---|:---|:---|
| 할당 방식 | 요청별 최대 길이(Max Seq) 연속 공간 사전 예약 | 고정 크기 블록(16/32 토큰) 단위 온디맨드 비연속 할당 |
| 메모리 단편화 | 심각한 외부 단편화 및 내부 낭비 발생(60~80%) | 외부 단편화 제거, 내부 단편화 4% 미만 억제 |
| 메모리 공유 | 세션 간 캐시 공유 불가(개별 독립 복제) | Prefix Caching 및 Copy-on-Write 통한 완벽 공유 |
| 서빙 처리량 | 메모리 낭비로 동시 배치 크기 제한적 | 메모리 효율화로 동시 배치 처리량 수배 향상 |
| 주소 계산 비용 | 포인터 연산 단순(오버헤드 제로) | 블록 테이블 조회 간접 참조 비용(전용 커널 최적화로 상쇄) |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 블록 크기 불일치로 내부 단편화 발생 | 워크로드 문맥 길이 분포에 맞춘 블록 크기(16 vs 32 토큰) 벤치마크 튜닝 | 미사용 패딩 최소화 및 메모리 가용성 극대화 |
| 미세 블록 분할 시 주소 변환 오버헤드 | 전용 GPU Paged 커널 최적화 및 공유 메모리 캐싱 적용 | 간접 참조 지연 상쇄 및 높은 서빙 연산 처리량 확보 |
| 공유 블록의 동시성 경합 및 참조 오류 | 블록 참조 카운트의 원자적(Atomic) 갱신 및 COW 정밀 제어 | 세션 간 메모리 침범 방지 및 조기 반납 버그 차단 |

## Ⅶ. 결론

- **기술 위상/발전**: 가상 메모리 페이징 기법을 GPU 인프라에 성공적으로 이식하여 vLLM, SGLang, TensorRT-LLM 등 최신 고성능 추론 엔진의 핵심 표준 아키텍처로 정립
- **실무 적용/통제**: 대규모 LLM 프로덕션 서빙 시 프롬프트 접두사 캐싱(Prefix Caching) 활성화와 청크 프리필(Chunked Prefill)을 결합하여 GPU 메모리 밀도 극대화 및 지연 시간 단축 실현
