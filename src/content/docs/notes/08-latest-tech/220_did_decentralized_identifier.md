## Ⅰ. 개요

- **정의**: 중앙 등록기관이나 공인인증기관에 종속되지 않고 신원 주체가 직접 생성·소유하며, 분산 원장 상에서 암호학적으로 검증 가능한 W3C 표준 URI 형식의 탈중앙화 식별자
- **배경 및 필요성**: 중앙화된 신원 공급자(IdP) 체계의 대규모 개인정보 유출 위험, 계정 삭제 시 신원 상실(플랫폼 종속), 사용자 동의 없는 무차별적 크로스 추적에 의한 프라이버시 침해를 극복하고, 신원 주체가 자신의 공개키와 인증 수단을 스스로 통제하는 자기주권 신원(Self-Sovereign Identity, SSI)을 실현하기 위해 도입됨

## Ⅱ. 특징

- **탈중앙화 및 영속성(Decentralized & Persistent)**: 중앙 발급 기관 없이 블록체인 또는 분산 네트워크 상에서 주체가 직접 생성하며, 중앙 기관의 일방적 삭제나 중단 불가
- **암호학적 제어 및 입증(Cryptographically Verifiable)**: 공개키 암호 기술을 기반으로 DID 소유자가 개인키 서명을 통해 식별자에 대한 소유권과 제어권을 제3자에게 수학적으로 증명
- **식별자와 신원 정보 분리**: DID 자체는 순수한 식별 문자열(`did:method:specific-id`)일 뿐 주민번호 등 개인식별정보(PII)를 일절 포함하지 않아 프라이버시 보호

## Ⅲ. 구조 및 구성요소

```text
[분산 식별자 DID 아키텍처]
├── [신원 주체 계층]
│   └── [DID 주체]
├── [메서드 해석 계층]
│   ├── [DID 메서드]
│   └── [DID 리졸버]
└── [메타데이터 계층]
    └── [DID 문서]
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

| 계층 | 구성요소 | 핵심 역할 |
|:---|:---|:---|
| 신원 주체 | DID 주체 (Subject) 및 제어자 (Controller) | DID가 식별하는 대상(사람, 사물 등)과 DID 문서를 수정·비활성화할 수 있는 권한을 가진 주체 |
| 신원 주체 | 사용자 지갑 (DID Wallet) | 주체의 개인키를 기기 내 안전 영역(SE/TEE)에 안전하게 저장하고 인증 서명 수행 |
| 메서드 해석 | DID 메서드 (Method) | 특정 블록체인(did:ion, did:indy 등) 상에서 DID의 CRUD 생명주기를 정의하는 프로토콜 규격 |
| 메서드 해석 | DID 리졸버 (Universal Resolver) | DID 문자열을 입력받아 해당 메서드 규칙에 따라 분산 저장소에서 최신 DID 문서를 조회·반환 |
| 메타데이터 | DID 문서 (DID Document) | 공개키 세트(Verification Methods), 인증 프로토콜, 서비스 엔드포인트 URL을 담은 JSON-LD 데이터 |

## Ⅳ. 흐름도

```text
[DID 생성 및 등록] (① 사용자 지갑에서 키 쌍 생성 후 블록체인에 DID 및 DID 문서 등록)
       │
       ▼
[검증자 DID 해석 요청] (② 서비스 이용 시 검증자가 주체의 DID 문자열을 리졸버에 전달)
       │
       ▼
[DID 메서드 해석] (③ 리졸버가 메서드 식별 후 해당 블록체인에서 최신 DID 문서 조회)
       │
       ▼
[검증 방법 및 공개키 추출] (④ 반환된 DID 문서 내 서명 검증용 공개키와 상태 확인)
       │
       ▼
[챌린지 서명 검증] (⑤ 검증자가 보낸 챌린지 난수에 대한 주체의 전자서명 일치 여부 판정)
```

- 분기 결과: DID 문서의 키로 전자서명이 완벽히 검증되고 비활성화 상태가 아니면 신원 인증을 인가하며, 서명 불일치 또는 폐기된 DID인 경우 즉시 인증 거부

## Ⅴ. 종류 및 비교

| 구분 | 분산 식별자 (DID) | DID 문서 (DID Document) | 검증 가능 자격증명 (VC) |
|:---|:---|:---|:---|
| 핵심 개념 | 주체를 가리키는 고유 URI 문자열 | 식별자의 암호학적 검증 메타데이터 | 발급자가 보증하는 주체의 속성/자격 정보 |
| 데이터 내용 | `did:method:specific-id` | 공개키, 인증 프로토콜, 서비스 엔드포인트 | 발급자 DID, 주체 DID, 학력/면허 속성, 전자서명 |
| 저장 위치 | 블록체인 분산 원장 또는 지갑 | 블록체인 또는 분산 스토리지(IPFS) | 사용자 로컬 단말기 지갑 (오프체인 보관) |
| 개인정보 포함 여부 | 일절 미포함 (단순 난수 문자열) | 일절 미포함 (공개키 및 메타데이터만 존재) | 신원 속성 포함 (단, ZKP로 선택적 공개 가능) |
| 신뢰의 주체 | 분산 합의 네트워크 | DID 제어자 (개인키 소유자) | 신뢰할 수 있는 발급 기관 (정부, 대학, 기업 등) |

## Ⅵ. 실무 고려사항 및 대책

| 문제점 | 대책 | 기대효과 |
|:---|:---|:---|
| 사용자 모바일 단말기 분실 또는 파손 시 DID 제어용 개인키 영구 상실 위험 | 소셜 복구(Social Recovery) 및 Shamir 비밀 공유 기반의 다중 서명 복구 메커니즘 구축 | 중앙 백업 서버 없이도 분실된 개인키의 안전한 복구 보장 |
| 동일한 DID를 서로 다른 온라인 서비스에서 반복 사용할 경우 서비스 간 상관분석(Correlation)으로 개인 추적 위험 | 서비스 접점마다 서로 다른 일회용/페어와이즈(Pairwise-pseudonymous) DID 동적 생성 적용 | 활동 기록 간 연계 차단 및 완벽한 익명성 보장 |
| 블록체인 상에 DID 문서를 직접 저장할 경우 발생하는 높은 온체인 가스비와 조회 지연 | 비트코인 기반 L2 사이드체인(Sidetree 프로토콜/ION) 및 KERI(Key Event Receipt Infrastructure) 도입 | 초당 수만 건의 DID 갱신 처리량 확보 및 온체인 수수료 제거 |

## Ⅶ. 결론

- **기술 위상/발전**: 분산 식별자(DID)는 빅테크 기업에 종속되었던 신원 주권을 개인에게 돌려주는 자기주권 신원(SSI)과 Web3 디지털 사회의 가장 핵심적인 기초 프로토콜이자 W3C 국제 표준으로 확립되었으며, 모바일 신분증, 금융 인증, 탈중앙 자율조직(DAO), AI 에이전트 간 신뢰 상호인증으로 전면 확장되는 추세
- **실무 적용/통제**: 실무 DID 시스템 아키텍처 설계 시에는 개인정보의 온체인 저장 금지 원칙(GDPR 잊힐 권리 준수)을 엄수하여 식별자(DID)와 자격증명(VC)을 철저히 분리하고, 페어와이즈 DID 및 소셜 키 복구 프로토콜을 결합하여 프라이버시 보호와 사용자 편의성의 균형을 확보 필요
