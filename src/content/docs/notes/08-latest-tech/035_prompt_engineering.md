## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **프롬프트 엔지니어링(Prompt Engineering)**: 모델이 의도한 과업을 수행하도록 지시•문맥•예시•출력 형식을 설계하고 평가로 검증하는 기법이다.
- **출력 계약(Output Contract)**: 모델 응답이 따라야 할 필드•자료형•근거•오류 처리 규칙.

</details>

- 정의/개념: 지시•문맥•예시로 행동을 유도하는 **프롬프트 엔지니어링**
- 배경/필요성: 사전학습된 거대 언어 모델(LLM)에 자연어 질의를 직접 입력할 경우, 모델의 확률적 생성 특성으로 인해 지시 불이행, 환각(Hallucination), 비정형 출력 및 악성 프롬프트 주입(Prompt Injection) 취약성 등 엔터프라이즈 환경에서 수용하기 어려운 품질 편차가 발생하는 문제가 존재함에 따라, 모델 파라미터의 재학습 없이도 명확한 역할 정의, 맥락 정보, 소수 예시(Few-shot), 구조화된 출력 계약(Output Schema) 및 안전 제약조건을 체계적으로 설계하는 프롬프트 엔지니어링(Prompt Engineering) 방법론을 도입하여 **모델의 출력 확률 분포를 의도한 비즈니스 규칙과 형식으로 정밀하게 유도, ReAct/CoT 등 다단계 추론 패턴과의 결합을 통한 문제 해결 역량 극대화, 회귀 평가 세트(Regression Set) 기반의 결정론적 품질 통제 및 보안 거버넌스 확립**을 달성할 필요

#### 한줄 요약
- **지시•문맥•예시•출력 계약**은 학습 비용 없이 품질을 올리지만 요청마다 토큰으로 다시 지불되므로, 같은 지시가 반복되면 프롬프트가 아니라 미세조정으로 옮길 시점이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **시스템 지시(System Instruction)**: 모델의 역할•행동 범위•우선 규칙을 사용자 입력보다 높은 권한으로 설정하는 지시.
- **제로샷(Zero-shot)**: 예시 없이 지시만 제공하여 과업을 수행하는 방식이다.
- **퓨샷(Few-shot)**: 소수의 입출력 예시로 기대 응답 패턴을 제공하는 방식.
- **도구 호출(Tool Calling)**: 모델이 검색•계산•외부 기능을 정해진 구조로 요청하도록 연결하는 방식.
- **프롬프트 주입(Prompt Injection)**: 비신뢰 데이터에 숨은 악성 지시로 상위 지시와 통제를 우회하려는 공격이다.

</details>

- **시스템 지시**: 행동 범위와 우선 규칙 명시
- **역할•목표•제약**: 성공 조건과 금지 사항 명시
- **제로샷**: 예시 없이 지시만으로 수행
- **퓨샷**: 소수 예시로 기대 응답 패턴 제공
- **도구 호출**: 외부 기능 요청 구조화
- **회귀 평가**: 품질 저하와 프롬프트 주입 검증

#### 한줄 요약
- 고정 평가 세트로 **품질•안전 회귀** 반복 검증

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **성공 조건**: 과업 완료 여부를 관찰•검증할 수 있는 기준이다.
- **역할•목표**: 역할과 과업•성공 조건을 명확히 한 지시 요소이다.
- **지시•제약**: 절차•금지 사항•권한•범위로 행동 경계를 정하는 요소이다.
- **문맥•예시**: 근거와 입출력 사례로 과업 해석을 구체화하는 요소이다.
- **문맥 경계**: 신뢰 지시와 외부 데이터를 구분하는 경계이다.
- **프롬프트 버전**: 지시•예시•출력 계약과 호환 모델의 변경 상태를 재현할 수 있게 식별한 값.

</details>

```text
[프롬프트 엔지니어링 아키텍처]
├── [역할 및 페르소나 (Role & Persona)]
│   ├── 시스템 역할 정의 (System Persona)
│   └── 작업 범위 및 도메인 전문성 지정
├── [지시 및 안전 제약 (Instructions & Constraints)]
│   ├── 단계별 수행 지침 (Step-by-step Rules)
│   └── 네거티브 제약 및 주입 방어 가드레일
├── [문맥 및 소수 예시 (Context & Few-shot)]
│   ├── 참조 지식/검색 문맥 주입 (RAG Context)
│   └── 입출력 모범 예시 (Few-shot Examples)
├── [출력 스키마 계약 (Output Contract)]
│   ├── 구조화 포맷 정의 (JSON Schema / YAML)
│   └── 오류 응답 코드 및 필수 필드 명세
└── [평가 및 버전 거버넌스 (Evaluation & Versioning)]
    ├── 회귀 평가 세트 (Golden Dataset)
    └── 모델 변경 추적 및 지표 벤치마킹
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 프롬프트 엔지니어링 아키텍처의 계층 분할 및 세부 구성요소 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 역할 및 페르소나 | 모델의 행동 주체 설정 및 도메인별 성공 조건 정의 |
| 지시 및 제약 | 수행 단계별 알고리즘 제시 및 금지 사항·보안 가드레일 확립 |
| 문맥 및 예시 | 신뢰 참조 데이터 주입 및 퓨샷(Few-shot) 기반 패턴 유도 |
| 출력 스키마 계약 | 정형화된 JSON Schema 등 기계 판독 가능한 출력 규격 강제 |
| 평가 및 거버넌스 | 회귀 평가 세트 기반 품질 계측 및 프롬프트 버전 관리 |

#### 한줄 요약
- **역할•지시•문맥•출력 계약•평가** 버전 관리

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **회귀 평가(Regression Evaluation)**: 프롬프트나 모델 변경 뒤 기존 과업의 품질 저하 여부를 고정 평가 세트로 확인하는 절차이다.
- **후보 프롬프트 설계**: 목표•지시•예시•출력 계약을 하나의 시험 버전으로 구성하는 절차이다.
- **회귀 평가 세트 구성**: 정상•경계•공격 입력과 성공 기준을 고정하는 절차로 정의된다.
- **품질•안전 결함 판정**: 기준 버전과 비교해 품질 회귀와 안전 통제 취약성을 식별하는 절차이다.
- **수정•버전 승인**: 결함을 보완한 프롬프트 조합과 변경 이력을 확정하는 절차이다.
- **검증 버전 배포**: 승인된 프롬프트•모델•출력 계약 조합을 운영에 반영하는 절차.
- **공격 입력**: 프롬프트 주입이나 경계 우회로 통제 실패를 시험하는 입력이다.

</details>

```text
[요구사항 정의 및 프롬프트 초안 설계] (① 역할, 지시, 예시, JSON 출력 스키마 정의)
       │
       ▼
[골든 데이터셋 회귀 평가 실행] (② 정상, 경계, 주입 공격 입력 테스트)
       │
       ▼
[출력 검증 및 품질 계측] (③ 스키마 정합성, 환각 여부, 안전 가드레일 평가)
       │
       ▼
[프롬프트 버전 확정 및 레지스트리 등록] (④ 프롬프트 템플릿과 모델 매핑 버전 고정)
       │
       ▼
[운영 게이트웨이 배포] (⑤ 실시간 런타임 추론 파이프라인에 적용)
```

- 분기 결과: 평가 기준 통과 시 운영 레지스트리에 자동 등록 및 배포, 미달 시 실패 사례 기반 프롬프트 템플릿 재설계 피드백 루프 진입

#### 한줄 요약
- **정상•경계•공격 입력** 통과한 버전만 배포

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **미세조정(Fine-Tuning)**: 도메인 데이터로 사전학습 모델의 가중치를 추가 갱신하여 반복 행동을 내재화한다.

</details>

| 모델 적응 방식 | 프롬프트 엔지니어링 | 미세조정 |
|:---|:---|:---|
| 적용 기준 | 과업 지시•형식의 빠른 변경 | 반복되는 도메인 행동 내재화 |
| 핵심 특징 | 가중치 없이 입력 시점 행동 유도 | 학습 데이터로 모델 가중치 갱신 |
| 한계 | 입력 토큰 증가•지시 민감성 | 학습 비용•데이터•모델 회귀 |

#### 한줄 요약
- 빠른 지시 변경은 **프롬프트 엔지니어링**, 행동 내재화는 **미세조정**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **업무 규칙 검증**: 출력 구조가 유효한지와 별개로 값의 의미와 업무 제약을 충족하는지 확인하는 절차.
- **도구 권한 제한**: 모델이 요청할 수 있는 자원•행동•인자를 최소 범위로 제한하여 오판의 피해를 줄이는 통제.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 지시의 모호성으로 인한 환각 발생 | 성공 조건, 제약사항, 명확한 입출력 예시 명시 | 응답 편차 축소 및 지시 이행률 향상 |
| 비정형 응답으로 인한 다운스트림 파싱 오류 | JSON Schema 강제 및 출력 계약 기반 사후 유효성 검증 | 구조적 오류 방지 및 백엔드 API 연동 안정성 확보 |
| 사용자 입력 기반 프롬프트 주입 공격 | XML/Markdown 기반 문맥 경계 격리 및 도구 권한 최소화 | 악성 지시어 무력화 및 시스템 지시 탈취 차단 |
| 모델 업그레이드 시 예기치 못한 출력 회귀 | CI/CD 파이프라인 연계 골든 데이터셋 자동 회귀 테스트 | 배포 전 성능 저하 및 안전 결함 사전 차단 |

#### 한줄 요약
- **구조•업무 의미•안전** 분리하여 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **모델 적응 방식 선택 기준**: 변경이 잦은 과업에는 프롬프트 엔지니어링을, 반복 행동 내재화에는 미세조정을 적용하는 기준.

</details>

- **기술 위상/발전**: 범용 사전학습 LLM을 비즈니스 로직에 맞춤화하는 **생성형 AI 소프트웨어 엔지니어링의 핵심 인터페이스 규약**이며, DSPy 등 자동 최적화 프레임워크로 발전
- **실무 적용/통제**: 백엔드 API 연동을 위한 JSON Schema 출력 강제, 외부 데이터 분리를 위한 구분자 격리, **골든 데이터셋 기반 CI/CD 회귀 평가**를 구축하여 운영 안정성 극대화

#### 한줄 요약
- **변경 빈도•행동 반복성** 대상 따라 모델 적응 방식 결정
