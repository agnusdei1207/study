## Ⅰ. 개요

- **정의**: 온프레미스 및 멀티 클라우드에 분산된 이기종 데이터 자산을 물리적으로 복제하지 않고, 활성 메타데이터(Active Metadata)와 지식 그래프를 활용하여 데이터 발견·통합·거버넌스를 자동화하는 지능형 데이터 아키텍처
- **배경 및 필요성**: 하이브리드 멀티 클라우드 환경에서 발생하는 데이터 사일로 심화, 포인트 투 포인트(Point-to-Point) ETL 스파게티로 인한 유지보수 한계, 수작업 거버넌스의 위험을 극복하고, 데이터 가상화와 머신러닝 기반 메타데이터 분석을 통해 데이터 복제 없이 실시간 통합 쿼리와 정책 자동 집행을 실현하기 위해 도입

## Ⅱ. 특징

- **활성 메타데이터 (Active Metadata)**: 정적인 메타데이터 조회를 넘어 쿼리 로그, 데이터 계보, 사용 패턴을 실시간 분석하여 데이터 파이프라인 자동 생성 및 최적화 추천 수행
- **시맨틱 지식 그래프 (Semantic Knowledge Graph)**: 데이터 자산 간의 의미론적 관계, 비즈니스 용어, 도메인 맥락을 그래프 구조로 시각화 및 자동 탐색
- **데이터 가상화 (Data Virtualization)**: 원천 데이터를 중앙 저장소로 대량 이동하지 않고 인플레이스(In-place) 상태에서 실시간 연계 질의 수행

## Ⅲ. 구조 및 구성요소

```text
[데이터 패브릭 아키텍처]
├── [시맨틱 및 지식 계층 (Semantic & Knowledge Layer)]
│   └── [지식 그래프 (시맨틱 모델, 데이터 계보, 연관 관계)]
├── [지능형 제어 평면 (Intelligent Control Plane)]
│   ├── [활성 메타데이터 엔진 (머신러닝 기반 패턴 분석 및 추천)]
│   └── [자동화 거버넌스 엔진 (Policy as Code, 동적 마스킹)]
├── [통합 및 전달 계층 (Integration & Delivery Layer)]
│   ├── [데이터 가상화 엔진 (분산 질의 푸시다운, 분산 캐싱)]
│   └── [동적 오케스트레이션 (자동화된 데이터 파이프라인 생성)]
└── [분산 데이터 소스 계층 (Distributed Data Sources)]
    └── [RDBMS, Data Lakehouse, NoSQL, SaaS Cloud Storage]
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

| 계층 | 구성요소 | 역할 및 세부기능 |
|:---|:---|:---|
| 지식 계층 | 시맨틱 지식 그래프 | 비즈니스 어휘집(Glossary)과 데이터 스키마를 매핑하여 데이터 계보(Lineage) 및 관계 추적 |
| 제어 평면 | 활성 메타데이터 엔진 | 지속적 관측(Continuous Observability)을 통해 사용량, 오류 패턴, 데이터 신선도를 능동 분석 |
| 제어 평면 | 자동화 거버넌스 엔진 | 데이터 분류(Classification) 및 민감 정보(PII) 자동 식별, 동적 접근 제어(ABAC) 집행 |
| 통합 계층 | 데이터 가상화 엔진 | 원천 데이터의 물리적 이동 없이 단일 엔드포인트(SQL/API)로 이기종 데이터 실시간 페더레이션 |
| 통합 계층 | 동적 오케스트레이션 | 분석된 쿼리 부하에 따라 캐시 생성, 임시 데이터 마트 구성 및 파이프라인 자동 튜닝 |

## Ⅳ. 흐름도

```text
[메타데이터 자동 수집] (① 분산 데이터 소스의 스키마, 쿼리 로그, 실행 통계를 지속적 수집)
│
▼
[지식 그래프 관계 구축] (② AI 엔진이 자산 간의 계보 및 비즈니스 연관 관계를 그래프로 연결)
│
▼
[활성 메타데이터 분석] (③ 빈번한 조인 패턴 및 데이터 품질 이상 징후를 감지하여 최적화 권고)
│
▼
[동적 통합 및 가상화] (④ 사용자 쿼리 요청 시 가상화 엔진이 최적 실행 계획 수립 및 원천 푸시다운)
│
▼
[보안 정책 자동 집행] (⑤ 사용자 권한에 맞춘 PII 마스킹 및 행/열 단위 필터링 후 결과 전달)
```

- 분기 결과: 정상 권한 및 검증 완료 시 가상화된 통합 결과 반환, 비인가 접근 또는 컴플라이언스 위반 감지 시 인라인 마스킹 또는 차단

## Ⅴ. 종류 및 비교

| 구분 | 데이터 패브릭 (Data Fabric) | 데이터 메시 (Data Mesh) | 전통적 데이터 웨어하우스/레이크 |
|:---|:---|:---|:---|
| 핵심 해결 방식 | AI/메타데이터 중심의 기술적 통합 자동화 | 조직 R&R 및 비즈니스 도메인 중심 거버넌스 | 대규모 데이터의 물리적 중앙 집중 적재 |
| 데이터 위치 | 원천 위치 보존 (가상화 및 필요 시 동적 복제) | 각 도메인 소유의 분산 저장소 | 단일 중앙 집중식 스토리지 |
| 메타데이터 활용 | 능동적 활용 (Active: 파이프라인 자동화/추천) | 수동적 활용 (Passive: 데이터 계약/카탈로그) | 카탈로그 및 스키마 검증 중심 |
| 상호 보완 관계 | 데이터 메시의 셀프서비스 플랫폼을 기술적으로 구현 | 데이터 패브릭에 명확한 비즈니스 도메인 소유권 부여 | 데이터 패브릭의 기반 원천 데이터 소스로 활용 |

## Ⅵ. 실무 고려사항 및 대책

| 문제점 | 대책 | 효과 |
|:---|:---|:---|
| 데이터 가상화 쿼리 시 원천 시스템 I/O 부하 및 네트워크 지연 | 인텔리전트 캐싱(Caching) 레이어 및 자주 사용되는 뷰의 동적 머티리얼라이즈(Materialization) | 원천 시스템 충격 방지 및 복합 쿼리 응답 성능 극대화 |
| 메타데이터 수집 품질 저하로 인한 AI 추천 및 영향도 분석 오류 | 메타데이터 신뢰도 스코어링 도입 및 중요 변경에 대한 사람 검토(Human-in-the-Loop) | 자동화 오작동 방지 및 데이터 거버넌스 신뢰성 확보 |
| 특정 패브릭 상용 솔루션의 독점 메타데이터 모델에 대한 벤더 종속 | Apache Atlas, OpenMetadata 등 오픈 표준 메타데이터 포맷 및 개방형 REST API 채택 | 메타데이터 이식성 확보 및 멀티 툴 확장성 보장 |

## Ⅶ. 결론

- **기술 위상/발전**: 가트너 선정 핵심 전략 기술로서 분산 데이터 환경의 기술적 복잡성을 해소하는 표준 아키텍처로 자리 잡았으며, 데이터 메시(Data Mesh)와 대립하지 않고 메시의 셀프서비스 인프라를 지능화하는 핵심 기술로 상호 융합되는 추세
- **실무 적용/통제**: 전사 데이터를 무리하게 중앙 집중화하기보다 활성 메타데이터와 지식 그래프를 우선 구축하여 데이터 가시성을 확보하고, 가상화와 캐싱을 결합한 하이브리드 파이프라인을 구축하여 비용 효율적인 데이터 통합 완성 필요
