## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **ReAct 패턴(Reasoning and Acting)**: 대규모 언어 모델이 추론(Thought)을 바탕으로 외부 도구 행동(Action)을 수행하고, 관찰(Observation) 결과를 다음 추론에 반영하는 폐루프(Closed-loop) 에이전트 패턴.
- **자율 에이전트(Autonomous Agent)**: 고정된 프롬프트 응답을 넘어 실시간 웹 검색, API 호출, DB 조회를 자율적으로 조합하여 복합 문제를 해결하는 지능형 시스템.

</details>

- 개념: 외부 관찰을 다음 추론에 반영하는 **ReAct 패턴**
- 배경/필요성: 거대언어모델이 내부 파라미터 지식에만 의존해 답변을 생성하는 순수 추론(Reasoning-only, CoT) 방식은 실시간 최신 정보 부재, 계산 오류, 치명적인 환각(Hallucination)을 유발하고, 반대로 추론 없이 외부 도구만 호출하는 순수 행동(Action-only) 방식은 복합 목표 분해와 예외 처리가 불가능한 결함이 존재함에 따라, 사고(Thought)와 외부 도구 행동(Action), 그리고 실행 결과 관찰(Observation)을 교차 반복하는 ReAct(Reasoning and Acting) 폐루프 패턴을 도입하여 **추론과 행동의 상호 보완을 통한 환각 현상 극복, 실시간 외부 데이터 기반의 사실성(Factuality) 및 근거성(Groundedness) 확보, 동적 오류 감지 및 실행 경로 자율 수정**을 달성할 필요

#### 한줄 요약
- **추론·행동 폐루프**는 관찰로 사실 오류를 줄이는 대신 단계마다 도구 지연과 토큰 비용을 더하므로, 외부 상태가 자주 바뀌는 과업일수록 그 교환이 이득이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **관찰(Observation)**: 외부 도구가 반환한 데이터, 상태값, 에러 메시지를 다음 추론 단계의 새로운 입력 컨텍스트로 통합하는 메커니즘.
- **대규모 언어 모델(Large Language Model, LLM)**: 목표 분석, 정보 공백 파악, 최적 도구 선택 및 인자 생성을 전담하는 중앙 추론 엔진.
- **도구 인터페이스(Tool API)**: 계산기, 검색 엔진, 코드 인터프리터 등 외부 환경과 상호작용하기 위해 정의된 표준 함수 계약.
- **선택 및 관찰 축(Selection & Observation Axes)**: 가설 수립(추론)과 실측 데이터 획득(행동/관찰)을 상호 보완적으로 교차 반복하는 2축 구조.

</details>

- **선택 축**: 정보 공백 기반 도구•인자 결정
- **관찰 축**: 결과•오류 기반 가설 평가와 행동 수정
- **통제 축**: 반복•근거•비용 기반 루프 종료

#### 한줄 요약
- **결과**•**오류** 활용 다음 추론에 반영하는 폐루프

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Thought-Action-Observation 루프**: LLM이 사고(Thought)로 계획을 세우고, 행동(Action)으로 도구를 호출하며, 관찰(Observation)로 결과를 받아 다음 단계를 결정하는 반복 구조이다.
- **최종 답변(Final Answer)**: 충분한 근거가 확보되어 루프를 종료하고 사용자에게 반환하는 최종 출력이다.

</details>

```text
[ReAct 아키텍처 체계] ── [추론·행동 폐루프 엔진]
├── [추론 및 정책 (Thought)]
│   ├── 정보 공백 분석 및 가설 수립
│   └── 최적 도구 및 인자 선택
├── [행동 실행기 (Action)]
│   ├── API 스키마 검증 및 권한 확인
│   └── 외부 도구 실행 위임
├── [관찰 처리기 (Observation)]
│   ├── 결과 출처 및 정상성 검증
│   └── 오류 피드백 및 상태 갱신
└── [루프 제어기 (Control)]
    ├── 최대 반복 횟수 및 비용 통제
    └── 완료 판정 및 Final Answer
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 ReAct 패턴의 처리 계층과 세부 제어 요소 간의 계층적 포함 관계를 나타냄

| 구성요소 | 책임 |
|:---|:---|
| 추론·정책 | 정보 공백 분석, 다음 행동 가설 수립 및 최적 도구 선택 |
| 행동 실행기 | 도구 API 스키마 정합성 검증 및 외부 시스템 실행 위임 |
| 관찰 처리기 | 실행 결과의 출처·정상성 검증 및 후속 추론 문맥 반영 |
| 루프 제어기 | 최대 반복 횟수, 비용 상한 및 완료 조건 기반 루프 종료 판정 |

#### 한줄 요약
- **추론•실행•관찰•제어** 기반 판단 구조

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **추론 생성(Thought Generation)**: 현재 상태를 분석하고 다음 필요한 정보와 행동 목표를 자연어로 사고하는 단계.
- **행동 호출(Action Execution)**: 사전 정의된 도구 스키마에 맞춰 구조화된 함수 호출을 수행하는 단계.
- **결과 관찰(Observation Intake)**: 도구 반환값을 수신하고 오류 유무 및 정보 적합성을 확인하는 단계.
- **피드백 반영(Feedback Loop)**: 관찰 결과를 기존 가설과 대조하여 최종 답변 생성 또는 다음 루프를 지속하는 단계.

</details>

```text
[사고 Thought] (① 문제 상황 분석, 정보 공백 식별 및 다음 단계 행동 가설 수립)
       │
       ▼
[행동 Action] (② 대상 도구 선택, API 호출 스키마 검증 및 권한 정책 확인)
       │
       ▼
[실행 Execution] (③ 외부 검색, 계산기, DB 등 격리 환경 내 도구 호출 실행)
       │
       ▼
[관찰 Observation] (④ 도구 실행 결과 수신, 데이터 신뢰성 검증 및 컨텍스트 통합)
       │
       ▼
[평가/종료] (⑤ 목표 달성 판정 시 Final Answer 반환, 근거 부족 시 Thought 단계 환류)
```

- 분기 결과: 충분한 근거 확보 시 최종 답변 출력 및 루프 종료, 오류 또는 정보 미흡 시 다음 Thought로 재귀 호출

#### 한줄 요약
- 추론·행동·관찰·판정의 폐루프를 반복한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **사고 사슬(Chain of Thought, CoT)**: 외부 환경과 상호작용 없이 내부 지식만으로 단계별 추론을 전개하여 환각(Hallucination)에 취약한 방식.
- **ReAct 패턴(Reasoning and Acting)**: 외부 도구 관찰을 추론 사슬에 지속 피드백하여 최신성, 정확성, 검증 가능성을 보장하는 방식.

</details>

| 구분 | ReAct | 표준 프롬프팅 | 사고 사슬(CoT) |
|:---|:---|:---|:---|
| 적용 기준 | 외부 정보 조회 및 계산 폐루프 | 단순 질의 응답 및 문맥 요약 | 다단계 논리·수학 추론 |
| 핵심 특징 | 도구 호출 관찰과 추론의 상호 순환 | 단발성 즉시 출력 생성 | 내부 지식 기반 단계별 사고 전개 |
| 한계 | 도구 지연 및 API 토큰 비용 누적 | 외부 상태 및 최신 정보 반영 불가 | 외부 상호작용 부재로 환각 취약 |

#### 한줄 요약
- 외부 상태는 **ReAct**, 내부 논리는 **CoT** 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **최대 반복 횟수 제한(Max Iterations Safeguard)**: 무한 루프 진입으로 인한 API 비용 폭증과 응답 지연을 방지하기 위해 최대 호출 횟수(예: 5~10회) 강제 설정.
- **도구 호출 오류 복구(Tool Error Recovery)**: API 호출 실패나 JSON 파싱 에러 발생 시 오류 메시지를 관찰로 넘겨 자율 재시도 유도.
- **컨텍스트 윈도우 관리(Context Window Optimization)**: 루프 반복 시 누적되는 토큰 수를 제어하기 위해 중간 관찰 요약(Summarization) 적용.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 잘못된 관찰의 연쇄 오류 | 출처·시점 검증 및 오류 메시지 피드백 재호출 | 오류 전파 차단 및 신뢰성 확보 |
| 반복 루프의 비용 폭증 | 최대 반복 횟수 설정 및 조기 종료 규칙 적용 | API 비용 상한 보장 및 지연 방지 |
| 변경 도구의 영향 범위 확대 | 조회와 변경 권한 분리 및 다단계 승인 적용 | 부작용 범위 격리 및 안전 통제 |

#### 한줄 요약
- **최대 반복 횟수•근거 충분성** 기반 종료 통제

## Ⅶ. 결론

- **기술 위상/발전**: ReAct 패턴은 언어 모델의 환각을 외부 도구 관찰로 극복하고 동적 환경 적응성을 보장하는 **에이전트 제어 루프의 표준 아키텍처**
- **실무 적용/통제**: 표준 API 스키마 기반 도구 연동, 관찰값 신뢰성 필터링, **최대 반복 횟수(Max Iterations) 및 비용 조기 종료** 가드레일 적용 필수

#### 한줄 요약
- **외부 의존성•근거 충분성** 대상 따라 패턴과 종료 결정
