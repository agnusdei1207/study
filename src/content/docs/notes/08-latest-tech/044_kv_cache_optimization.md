## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **키-값 캐시(Key-Value Cache, KV Cache)**: 이전 토큰의 K•V 벡터를 저장하여 다음 토큰의 어텐션에서 재사용하는 메모리다.
- **자기회귀 생성(Autoregressive Generation)**: 앞서 생성한 토큰을 문맥에 포함해 다음 토큰을 하나씩 만드는 방식.

</details>

- 정의: 키•값 재사용과 저장•회수로 메모리를 관리하는 **KV Cache 최적화**
- 배경/필요성: 트랜스포머 기반 대규모 언어 모델(LLM)의 자기회귀(Autoregressive) 토큰 디코딩 과정에서 이전 토큰들의 Key/Value 벡터 재계산을 방지하기 위해 KV Cache를 사용하지만, 문맥 시퀀스 길이와 동시 요청(Concurrent Batches) 수가 증가함에 따라 KV Cache가 차지하는 GPU VRAM 용량이 모델 파라미터 자체보다 커져 메모리 고갈(OOM) 및 서빙 처리량 저하를 유발하는 극심한 메모리 바운드(Memory-bound) 병목이 발생함에 따라, 멀티 쿼리/그룹 쿼리 어텐션(MQA/GQA), 저정밀도 양자화(INT8/INT4/FP8), 동적 페이징 및 캐시 공유/오프로딩 기법을 포괄하는 KV Cache 최적화(KV Cache Optimization) 아키텍처를 도입하여 **디코딩 시점의 중복 연산 완전 제거, 쿼리 헤드 간 KV 헤드 공유(GQA) 및 저비트 표현을 통한 메모리 풋프린트 수배 절감, 고동시성 LLM 서빙 환경에서의 배치 크기(Batch Size) 및 총 처리량(Tokens/Sec) 극대화**를 달성할 필요

#### 한줄 요약
- **키•값 재사용**은 재계산 비용을 메모리 비용으로 바꾼 거래이므로, 최적화의 초점은 계산을 더 줄이는 쪽이 아니라 그렇게 산 캐시를 얼마나 오래 어떤 정밀도로 붙들지에 놓인다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **키-값 헤드(Key-Value Head, KV Head)**: 어텐션에서 토큰별 키(Key, K)•밸류(Value, V) 벡터를 생성하고 캐시에 저장하는 헤드다.
- **캐시 용량**: 모델 층•KV 헤드•토큰•배치 수•수치 정밀도에 비례해 필요한 메모리 크기다.
- **디코드 재계산 제거**: 저장한 과거 K•V를 재사용하여 매 토큰 생성 때 이전 문맥을 다시 계산하지 않는 효과다.
- **그룹 쿼리 어텐션(Grouped-Query Attention, GQA)**: Q 그룹별로 K•V 헤드를 공유하는 구조다.
- **멀티 쿼리 어텐션(Multi-Query Attention, MQA)**: 모든 Q 헤드가 단일 K•V 헤드를 공유하는 구조다.

</details>

![Observable Plot으로 그린 문맥 길이•KV 헤드 수별 캐시 메모리 이론값](/study/diagrams/kv-cache-memory.svg)

> 문맥이 길어질수록 세 선은 비례 증가하지만 KV 헤드를 공유하는 GQA•MQA의 기울기가 MHA보다 작으며, 32층•BF16 가정의 이론값이다.

- **디코드 재계산 제거**: 과거 키•값 재사용
- **캐시 용량**: 층•KV Head•토큰•배치•정밀도에 비례
- **GQA**: Q 그룹별 K•V 공유로 캐시 절감
- **MQA**: 단일 K•V 공유로 캐시 최소화
- **양자화**: 저정밀 표현으로 캐시 용량 축소
- **페이징**: 블록 할당으로 단편화 완화

#### 한줄 요약
- **문맥•KV Head**와 배치•정밀도에 비례한 캐시 증가

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **블록 할당기**: 요청별 캐시 공간을 작은 블록 단위로 동적 배정하고 종료 후 반납하는 구성요소다.
- **캐시 레이아웃**: 계층•헤드•토큰별 키•값을 메모리에 배치하고 논리 순서와 실제 주소를 연결하는 구조다.
- **압축 계층**: 키•값의 정밀도•헤드•토큰 보존 범위를 줄여 캐시 용량과 대역폭을 절감하는 구성요소다.
- **접두사 공유**: 여러 요청의 동일 입력 앞부분에 대한 K•V 캐시를 함께 참조하여 중복 저장과 계산을 줄이는 방식이다.
- **GPU(Graphics Processing Unit)**: KV Cache 연산과 저장을 가속하는 병렬 처리장치다.
- **CPU(Central Processing Unit)**: 오프로딩 캐시를 보관할 수 있는 범용 처리장치다.
- **오프로딩(Offloading)**: 캐시 일부를 GPU 메모리에서 CPU 메모리 같은 하위 계층으로 이동하는 방법.
- **캐시 스케줄러**: 요청 우선순위•가용 메모리•재사용 가능성을 바탕으로 할당•축출•오프로딩을 조정하는 구성요소다.

</details>

```text
[KV Cache 최적화 아키텍처]
├── [아키텍처 레벨 축소 (Head Sharing)]
│   ├── 멀티 쿼리 어텐션 (MQA: 1개 KV 헤드 공유)
│   └── 그룹 쿼리 어텐션 (GQA: 그룹별 KV 헤드)
├── [표현 정밀도 압축 (Precision Quantization)]
│   ├── 저비트 KV 양자화 (FP8 / INT8 / INT4)
│   └── 이상치 보존 및 채널별 스케일링
├── [동적 메모리 관리 (Paged Allocation)]
│   ├── PagedAttention 기반 비연속 블록 매핑
│   └── 내부/외부 단편화 제거 및 가상 메모리
└── [캐시 수명 및 스케줄링 (Cache Lifecycle)]
    ├── 프롬프트 캐싱 (RadixTree 접두사 공유)
    ├── 계층형 오프로딩 (GPU VRAM ↔ Host RAM)
    └── 선점 및 축출 제어
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 KV Cache 최적화 아키텍처의 계층 분할 및 세부 기술 모듈 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 헤드 공유 계층 | MQA/GQA 설계를 통해 K/V 헤드 수 자체를 줄여 캐시 발생량 원천 축소 |
| 정밀도 압축 계층 | FP8/INT8/INT4 양자화로 토큰당 K/V 벡터의 바이트 크기 최소화 |
| 동적 메모리 관리자 | 가상 메모리 페이징 기법으로 물리 블록 동적 할당 및 메모리 단편화 제거 |
| 캐시 수명 스케줄러 | RadixTree 접두사 공유, 호스트 RAM 오프로딩 및 LRU 기반 선점·축출 제어 |

#### 한줄 요약
- **레이아웃•할당**과 압축•회수•스케줄링 구성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **프리필 캐시**: 입력 토큰 전체를 병렬 처리하여 생성 전에 구성한 초기 K•V 상태다.
- **캐시 회수**: 요청 종료나 선점 뒤 더 이상 참조하지 않는 블록을 반납하여 가용 메모리를 복원하는 과정.

</details>

```text
[요청 인입 및 프리필 연산]
       │
       ▼
[프롬프트 캐시 적재 및 접두사 매칭] (① RadixTree 기반 중복 프리필 생략 및 재사용)
       │
       ▼
[Paged 블록 동적 할당 및 양자화] (② 고정 크기 물리 블록 매핑 및 FP8/INT8 압축 저장)
       │
       ▼
[자기회귀 디코딩 시 과거 K·V 참조] (③ 매 스텝 신규 생성 토큰 K·V 갱신 및 결합 어텐션)
       │
       ▼
[토큰 생성 완료 및 블록 즉시 회수] (④ EOS 도달 시 물리 메모리 블록 반환 및 단편화 해소)
```

- 분기 결과: 정상 디코딩 완료 시 GPU 메모리 풀로 블록 즉시 반환, VRAM 부족 감지 시 호스트 RAM 계층 오프로딩 또는 LRU 기반 선점 축출 수행

#### 한줄 요약
- **용량 산정•블록 할당** 후 키•값 추가•회수

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **멀티 헤드 어텐션 캐시(Multi-Head Attention Cache, MHA Cache)**: 쿼리 헤드마다 독립 K•V를 저장하여 표현력은 높지만 캐시 용량이 크다.
- **그룹 쿼리 어텐션 캐시(Grouped-Query Attention Cache, GQA Cache)**: Q 그룹별로 K•V 헤드를 공유하여 캐시를 줄인다.
- **멀티 쿼리 어텐션 캐시(Multi-Query Attention Cache, MQA Cache)**: 모든 Q 헤드가 단일 K•V를 공유하여 캐시를 최소화한다.
- **양자화 키-값 캐시(Quantized Key-Value Cache, Quantized KV Cache)**: K•V를 낮은 비트로 저장하여 장문•고동시성의 메모리 사용을 추가로 줄인다.

</details>

- 표현력과 메모리 절감 수준에 따른 캐시 방식 구분

| 구분 | MHA 캐시 | GQA•MQA 캐시 | 양자화 KV 캐시 |
|:---|:---|:---|:---|
| 적용 기준 | 표현력 우선 | 생성 메모리 및 대역폭 절감 | 장문 및 고동시성 추가 압축 |
| 핵심 특징 | 헤드별 독립 키•값 저장 | 키•값 헤드의 그룹/전체 공유 | 낮은 비트의 키•값 양자화 표현 |
| 한계 | 최대 캐시 용량 점유 | 공유에 따른 미세 품질 저하 가능 | 양자화 오차 및 변환 오버헤드 |

#### 한줄 요약
- **헤드 공유•양자화 수준** 기반 메모리와 품질 절충

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **메모리 단편화**: 빈 영역이 흩어져 새 요청의 연속 공간을 배정하기 어려운 현상이다.
- **페이징(Paging)**: 고정 크기 블록으로 캐시를 비연속 할당하여 단편화를 줄이는 방식.
- **오프로딩 지연**: GPU와 하위 메모리 계층 사이의 캐시 이동 때문에 토큰 생성이 늦어지는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 장문 및 고동시성 요청 시 VRAM OOM | GQA 기반 백본 도입 및 FP8 KV 캐시 양자화 적용 | 캐시 용량 4~8배 절감 및 동시 서빙 세션 증대 |
| 불연속 메모리 할당에 따른 단편화 | vLLM PagedAttention 가상 메모리 블록 매핑 도입 | 메모리 낭비율 4% 미만 억제 및 가용성 극대화 |
| 저비트 양자화 시 어텐션 왜곡 | 채널별/토큰별(Per-token) 동적 스케일링 기법 적용 | PPL 및 벤치마크 정확도 손실 1% 미만 통제 |
| VRAM 부족 시 오프로딩 지연 급증 | 청크 단위 프리필(Chunked Prefill) 및 캐시 축출(LRU) | PCIe 병목 완화 및 토큰 생성 속도(TPOT) 유지 |

#### 한줄 요약
- **압축 품질•오프로딩 지연** 동시 측정

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **키-값 캐시 최적화 기준**: 모델 아키텍처 수준의 GQA 적용, 런타임 수준의 PagedAttention, 데이터 수준의 FP8 양자화를 계층적으로 결합하는 기준.

</details>

- **기술 위상/발전**: LLM 추론 서빙 인프라의 처리량(Throughput)과 메모리 효율을 결정짓는 **서빙 프레임워크의 핵심 최적화 계층**이며, FlashInfer 및 하드웨어 가속 어텐션 커널과 융합되어 발전
- **실무 적용/통제**: 모델 아키텍처 수준의 **GQA 적용**, 런타임의 **PagedAttention 메모리 풀링**, 서빙 단계의 **FP8/INT4 양자화**를 결합하여 GPU 메모리 병목을 극복하고 서빙 경제성 극대화

#### 한줄 요약
- **병목 원인**에 따라 헤드 공유•페이징•압축 결정
