## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **샌드박스(Sandbox)**: 신뢰할 수 없는 코드와 도구를 격리된 환경에서 실행하여 호스트 자원에 미치는 영향을 제한하는 보안 경계이다.
- **최소 권한(Least Privilege)**: 실행 주체에 작업 수행에 필요한 자원과 행동만 제한된 시간 동안 허용하는 원칙으로 정의된다.

</details>

- 정의: 비신뢰 코드의 권한•자원•통신을 격리하는 **샌드박스**
- 배경/필요성: 코드 생성 에이전트나 데이터 분석 에이전트가 LLM이 생성한 동적 스크립트(Python, Bash 등)를 호스트 환경에서 직접 실행할 경우, 악성 코드 삽입, 호스트 파일 시스템 파괴, 내부 네트워크 무단 탐색 및 무한 루프에 의한 컴퓨팅 자원 고갈 등의 심각한 호스트 침해 사고가 발생함에 따라, 실행 프로세스의 시스템 호출, 네트워크 통신, 파일 접근 및 리소스를 완벽히 격리하는 에이전트 샌드박스(Agent Sandbox) 계층을 도입하여 **Seccomp 및 비특권 네임스페이스 기반의 호스트 커널 접근 차단, 일회성(Ephemeral) 컨테이너/MicroVM 환경을 통한 실행 후 상태 잔존 방지, 아웃바운드 네트워크 통제(Egress Allowlist)를 통한 민감 데이터 유출 원천 봉쇄**를 달성할 필요

#### 한줄 요약
- **격리 경계•최소 권한**은 피해를 경계 안에 가두는 대신 정상 작업이 필요로 하는 자원 접근까지 막으므로, 격리 강도는 허용 실패율과 작업 성공률이 만나는 지점에서 정한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **일회성 환경(Ephemeral Environment)**: 작업마다 새로 만들고 결과 반출 뒤 폐기하여 이전 실행 상태가 남지 않게 하는 환경이다.
- **자원 할당량(Resource Quota)**: 연산•메모리•저장공간•실행 시간에 강제하는 사용 상한.
- **중앙처리장치(Central Processing Unit, CPU)**: 명령을 해석하고 연산을 수행하는 처리장치.

</details>

- **일회성 환경**: 작업마다 비특권 경계 생성•폐기
- **자원 할당량**: CPU•메모리•저장•시간 상한
- **최소 권한**: 시스템 호출•통신•파일 접근 제한
- **결과 검증**: 허용 산출물 반출 후 환경 폐기

#### 한줄 요약
- **시스템 호출•통신**과 파일•자원•반출 통제

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **보안 컴퓨팅 모드(Secure Computing Mode, Seccomp)**: 프로세스의 리눅스 시스템 호출을 정책으로 필터링하는 커널 기능으로 정의된다.
- **외부 통신 통제(Egress Control)**: 샌드박스에서 나가는 통신의 목적지•프로토콜•포트를 허용 목록으로 제한하는 통제이다.
- **비특권 프로세스(Unprivileged Process)**: 관리자 권한 없이 실행되어 침해 시 호스트에 행사할 수 있는 권한을 줄인 프로세스이다.

</details>

```text
[에이전트 샌드박스(Sandbox) 아키텍처]
├── [환경 격리 및 런타임]
│   ├── 일회성 컨테이너/MicroVM 격리
│   ├── 비특권 네임스페이스 분리
│   └── Seccomp 시스템 호출 필터링
├── [자원 및 네트워크 통제]
│   ├── cgroups 기반 자원 할당량
│   ├── 타임아웃 킬러 (Watchdog)
│   └── Egress 네트워크 차단(Allowlist)
└── [데이터 입출력 경계]
    ├── 읽기 전용 입력 볼륨 마운트
    ├── 격리된 임시 작업 디렉터리
    └── 산출물 보안 검증 및 폐기
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 최상위 에이전트 샌드박스 아키텍처에서 환경 격리 및 런타임, 자원 및 네트워크 통제, 데이터 입출력 경계 계층으로 이어지는 구조적 포함 관계를 나타냄

| 구성요소 | 책임 |
|:---|:---|
| 의존성 관리 | 최소 이미지와 패키지 버전 고정 |
| 실행 격리 | Seccomp•비특권 프로세스 기반 호스트 접근 제한 |
| 데이터 경계 | 읽기 전용 입력과 검증 출력 분리 |
| 네트워크 통제 | 외부 통신 통제•허용 목록 적용 |
| 자원 관리자 | 자원 할당량•환경 폐기 관리 |

#### 한줄 요약
- **실행•데이터**와 통신•자원 경계에서 검증 결과만 반출

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **위험 기반 격리(Risk-based Isolation)**: 코드의 신뢰도와 예상 부작용에 따라 컨테이너•가상머신 같은 격리 수준을 선택하는 방식이다.
- **결과 검증(Result Verification)**: 산출물의 형식•악성 내용•민감정보를 검사하여 허용된 결과만 격리 경계 밖으로 반출하는 절차.
- **일회성 폐기(Ephemeral Teardown)**: 실행 완료 직후 컨테이너나 가상머신을 파기해 호스트 잔존 상태를 제거하는 과정.

</details>

```text
[실행 요청 및 위험도 평가] (① 에이전트가 생성한 스크립트의 언어, 시스템 의존성, 신뢰도 분석)
│
▼
[일회성 샌드박스 프로비저닝] (② 격리 수준(컨테이너/MicroVM), Seccomp 프로파일, 리소스 Quota 설정)
│
▼
[읽기 전용 마운트 및 격리 실행] (③ 입력 데이터를 읽기 전용으로 주입하고 Egress 허용목록 통제 하에 비특권 실행)
│
▼
[산출물 보안 검증] (④ 생성된 파일, 표준 출력 내 악성 패턴, 민감정보, 비인가 네트워크 시도 검사)
│
▼
[결과 반환 및 샌드박스 폐기] (⑤ 검증 통과 결과물만 호스트로 반출하고 임시 컨테이너/MicroVM 즉시 삭제)
```

- 분기 결과: 정상 검증 통과 시 산출물 반출 및 환경 즉시 파기, 타임아웃/격리 탈출 시도 감지 시 프로세스 강제 킬(Watchdog) 및 호스트 알람 발송

#### 한줄 요약
- 실행 전 **위험 기반 격리**, 실행 후 결과 검증•폐기

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **컨테이너(Container)**: 호스트 커널을 공유하면서 네임스페이스와 cgroup으로 프로세스•자원을 격리하는 방식이다.
- **마이크로 가상머신(Micro Virtual Machine, MicroVM)**: 경량 게스트 커널을 별도로 실행하여 컨테이너보다 강한 커널 격리 경계를 제공하는 방식.

</details>

- 격리 방식 유형별 비교

| 격리 방식 | 컨테이너 | MicroVM |
|:---|:---|:---|
| 적용 기준 | 낮은 위험•고빈도 실행 시 | 비신뢰 코드•강한 격리 시 |
| 핵심 특징 | 호스트 커널 공유로 고밀도 달성 | 게스트 커널 분리로 경계 강화 |
| 한계 | 커널 취약점의 호스트 영향 | 시작 지연•자원 오버헤드 |

> 요약: 고밀도 실행은 **컨테이너**, 강한 커널 격리는 **MicroVM** 적용

#### 한줄 요약
- **위험•실행 밀도**에 따라 컨테이너•MicroVM 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **격리 탈출(Sandbox Escape)**: 샌드박스 안의 코드가 취약점을 이용해 격리 경계를 넘어 호스트 권한이나 자원에 접근하는 공격이다.
- **피해 반경(Blast Radius)**: 침해나 오작동이 영향을 미칠 수 있는 시스템•데이터•사용자의 최대 범위로 정의된다.
- **공급망 확산(Supply Chain Spread)**: 악성 산출물이 후속 시스템이나 배포 과정에 전달되어 샌드박스 밖으로 피해가 이어지는 현상이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공유 커널 취약점의 격리 탈출 | 위험도에 따른 MicroVM•비특권 사용자 적용 | 호스트까지의 피해 반경 축소 |
| 외부 통신을 통한 정보 유출 | 외부 통신 통제와 목적지 허용 목록 | 비밀정보 무단 반출 방지 |
| 무한 실행에 따른 자원 고갈 | 자원 할당량으로 CPU•메모리•시간 제한 | 서비스 가용성 보호 |
| 악성 출력의 후속 감염 | 결과 검증 후 결과만 반출 | 샌드박스 밖 공급망 확산 차단 |

#### 한줄 요약
- 읽기 전용 입력•**외부 통신 통제** 기반 정보 유출 방지

## Ⅶ. 결론

- **기술 위상/발전**: 비신뢰 동적 코드 실행 위험을 물리적·논리적 경계 안에 가두는 에이전트 안전 실행 핵심 계층으로 정착
- **실무 적용/통제**: 위험도별 격리 수준(MicroVM/컨테이너) 차등화, cgroups/Seccomp 기반 자원·시스템콜 통제 및 일회성(Ephemeral) 폐기 수명주기 필수

#### 한줄 요약
- **코드 신뢰도•부작용**에 따라 격리 수준 결정
