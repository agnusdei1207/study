## Ⅰ. 개요

- **정의**: 머신러닝 및 딥러닝 모델의 훈련 데이터셋 수집·라벨링 과정에 미세하게 변조된 악성 데이터(Poison Samples)를 주입하여 모델의 결정 경계를 왜곡하고 예측 성능 저하 또는 특정 표적 오작동을 유발하는 적대적 데이터 파이프라인 공격
- **배경 및 필요성**: 웹 크롤링, 크라우드소싱, 오픈소스 데이터셋 등 외부 개방형 소스로부터 대규모 데이터를 비인가 검증 상태로 수집하는 관행으로 인해, 데이터 공급망 단계에서의 악성 변조 유입 시 배포 후 재학습 및 서비스 장애에 막대한 비용이 발생하므로 데이터 무결성 검증 체계 필수

## Ⅱ. 특징

- 정상 데이터와 육안상 구별하기 어려운 미세 변조(Clean-label Poisoning) 기법 활용
- 전체 모델 정확도를 파괴하는 가용성(Availability) 공격과 특정 입력군에만 오판을 일으키는 무결성(Integrity) 표적 공격으로 양분
- 데이터 수집 출처 인증(Provenance), 특징 공간 이상치 필터링(Data Sanitization), DP-SGD 기반 강건 학습(Robust Training) 등 다계층 방어 필요

## Ⅲ. 구조 및 구성요소

```text
Data_Poisoning_Defense_Architecture
├── Provenance_Lineage (데이터 출처 인증 및 암호학적 해시 계보 관리)
├── Feature_Sanitization (특징 공간 통계적 이상치 분석 및 스펙트럼 필터)
├── Quarantine_Repository (미검증 의심 데이터셋 격리 및 샌드박스 보관)
└── Robust_Trainer (차등 프라이버시 학습 및 섀도우 모델 회귀 검증)
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

| 구성요소 | 세부 항목 | 핵심 역할 |
|:---|:---|:---|
| 데이터 계보 추적기 | W3C PROV, SHA-256 서명, 기여자 인증 | 데이터 수집 경로, 변환 이력 및 기여자별 기여도 이력 감사 추적 |
| 데이터 정제기 | Spectral Signature, Isolation Forest, K-NN 잔차 분석 | 특징 벡터 공간 상에서 정상 데이터 군집과 이격된 악성 오염 표본 탐지 |
| 격리 저장소 | 미검증 데이터 쿼런틴, 버전 태그 관리 | 검증을 통과하지 않은 원시 데이터를 학습 풀에서 분리하여 안전 보관 |
| 강건 학습 엔진 | DP-SGD, R-loss 정규화, 섀도우 모델 벤치마크 | 악성 표본이 유입되더라도 개별 데이터 포인트의 가중치 기여도 상한 제한 |

## Ⅳ. 흐름도

```text
[외부 소스로부터 원시 데이터 수집] (① 크롤링 및 서드파티 데이터셋 인입)
│
▼
[데이터 출처 및 디지털 서명 검증] (② 기여자 인증 및 계보 무결성 확인)
│
▼
[특징 공간 이상치 분석 및 클렌징] (③ 표현 벡터의 통계적 분포 분석을 통해 오염 표본 탐지)
│
▼
[격리 샌드박스 내 섀도우 학습 평가] (④ 의심 데이터셋을 분리하여 모델 예측 행동 차이 검증)
│
▼
[승인 데이터셋 학습 및 모델 배포] (⑤ 무결성 검증 완료 후 메인 학습 파이프라인 승격)
```

- 분기 결과: 이상치 분석 및 섀도우 모델 평가에서 성능 저하나 백도어 트리거가 식별되지 않으면 메인 학습 파이프라인에 반영하고, 오염 의심 표본 탐지 시 즉시 배치 격리 및 폐기

## Ⅴ. 종류 및 비교

| 구분 | 가용성 오염 공격 (Availability) | 표적 무결성 오염 (Targeted Integrity) | 백도어 오염 공격 (Backdoor/Trojan) |
|:---|:---|:---|:---|
| 공격 목적 | 모델의 전반적인 분류 정확도 및 신뢰도 파괴 | 특정 인물이나 특정 입력 그룹에 대해서만 오판 유도 | 평상시 정상 동작하다가 특정 트리거 패턴 입력 시 악성 출력 |
| 서비스 영향 | 전체 시스템 서비스 불능 (DoS) 유발 | 특정 트랜잭션의 승인/거절 등 표적 조작 | 공격자가 원하는 시점에만 백도어 발동 (탐지 극히 곤란) |
| 오염 데이터 비율 | 상대적으로 높은 비율(5~20% 이상) 필요 | 극소수(0.1~1% 미만)의 정밀 조작 표본으로 가능 | 특정 트리거 패턴이 합성된 소수 표본(1% 내외) 주입 |
| 주요 방어 기술 | 이상치 제거, 통계적 트리밍, DP-SGD | 클린 라벨 검증, 잔차 분석, 기여자별 가중치 제한 | 뉴런 활성화 분석(Activation Clustering), 모델 리버스 엔지니어링 |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 특정 외부 기여자 데이터셋의 급격한 유입으로 인한 분포 왜곡 | 소스별 데이터 주입 상한 쿼터제 및 기여자 신뢰도 가중치 부여 | 특정 세력에 의한 훈련 데이터 지배 원천 차단 |
| 정상 라벨을 유지하며 특징 공간에만 교묘히 침투하는 클린 라벨 오염 | 스펙트럴 시그니처(Spectral Signature) 기반 잔차 고유벡터 분석 | 육안 검증을 통과한 미세 변조 데이터의 수학적 탐지 |
| 오염 데이터 유입 후 모델 배포 시 시스템 장애 복구 곤란 | 데이터셋-모델 체크포인트 연동 버전 관리 및 검증 데이터 즉각 롤백 | 오염 사고 발생 시 신속한 무결점 안전 버전 복구 |

## Ⅶ. 결론

- **기술 위상/발전**: 오픈 웹 크롤링 기반 파운데이션 모델 및 대규모 AI 학습 환경에서 훈련 무결성을 위협하는 **AI 데이터 공급망 보안의 최우선 방어 과제**
- **실무 적용/통제**: 데이터 출처의 **암호학적 계보(Lineage) 관리**와 학습 전 **특징 공간 스펙트럼 이상치 필터링**, 학습 시 **DP-SGD 강건 알고리즘**을 결합한 다층 방어 체계 수립 필요
