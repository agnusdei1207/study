## Ⅰ. 개요

- **정의**: 운영체제(OS) 스레드와 1:1 매핑되지 않고, 자바 가상 머신(JVM)이 수백만 개의 사용자 모드 스레드를 생성 및 스케줄링하여 소수의 OS 캐리어 스레드에 다중화 실행하는 경량 동시성 모델
- **배경 및 필요성**: 전통적인 1:1 OS 플랫폼 스레드 모델은 스레드당 약 1MB의 큰 메모리 스택 점유와 커널 컨텍스트 스위칭 비용으로 인해 동시성이 수천 개 수준으로 제한되고, 리액티브 프로그래밍은 콜백 체인으로 인한 코드 복잡성과 디버깅 난도를 야기하므로, 동기식 명령형 코드 스타일을 유지하면서도 수백만 동시 연결을 지원할 필요성 대두

## Ⅱ. 특징

- **초경량 메모리 점유**: 플랫폼 스레드(1MB)와 달리 수백 바이트 수준의 작은 힙 메모리만 점유하여 수백만 개 동시 생성 가능
- **I/O 블로킹 시 자동 양보(Yield)**: 네트워크 소켓 대기 시 OS 스레드를 블로킹하지 않고 가상 스레드를 언마운트(Unmount)하여 캐리어 반환
- **명령형 Thread-per-Request 유지**: 복잡한 Reactive Streams API 없이 전통적인 순차 동기 코드로 높은 처리량 달성
- **기존 생태계 100% 호환**: 기존 Java 디버거, JFR(Java Flight Recorder), 프로파일러 및 표준 라이브러리와 원활한 상호작용

## Ⅲ. 구조 및 구성요소

```text
[Virtual Thread 런타임 아키텍처]
├── [가상 스레드 계층] ── VirtualThread (Continuation 기반 힙 메모리 스택 관리)
├── [JVM 스케줄러 계층] ─ ForkJoinPool (FIFO Work-Stealing 스케줄러)
├── [OS 실행 계층] ────── Carrier Thread (플랫폼 OS 스레드 풀)
├── [입출력 중단/재개] ── Continuation (I/O 블로킹 시 Unmount, 완료 시 Mount)
└── [보조 동시성 체계] ── Structured Concurrency, Scoped Values, Semaphore 제어
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

| 구성요소 | 설명 | 주요 역할 |
|:---|:---|:---|
| VirtualThread | JVM 힙 영역에 관리되는 경량 스레드 객체 | 개별 요청의 실행 흐름을 캡슐화하고 실행 스택을 힙 메모리에 탄력적으로 저장 |
| ForkJoinPool | 가상 스레드 전용 JVM 스케줄러 | CPU 코어 수 기반의 캐리어 스레드 풀을 관리하며 워크 스틸링(Work-Stealing) 스케줄링 수행 |
| Carrier Thread | 실제 CPU 연산을 수행하는 OS 플랫폼 스레드 | 마운트된 가상 스레드의 바이트코드를 실제로 실행하는 물리적 실행 주체 |
| Continuation | 실행 일시 중단 및 재개 메커니즘 | 블로킹 I/O 발생 시 호출 스택을 힙에 보존하고 실행 권한을 스케줄러에 반환 |
| Scoped Values | ThreadLocal을 대체하는 경량 컨텍스트 전달자 | 수백만 개 가상 스레드 환경에서 불변 데이터를 안전하고 메모리 효율적으로 공유 |

## Ⅳ. 흐름도

```text
[작업 요청 및 스케줄링] (① 가상 스레드 생성 후 ForkJoinPool 작업 큐에 등록)
│
▼
[캐리어 스레드 마운트] (② 사용 가능한 플랫폼 OS 스레드(Carrier)에 가상 스레드 마운트 및 실행)
│
▼
[I/O 블로킹 발생 감지] (③ Socket Read/Write, 파일 I/O 등 블로킹 시스템 콜 진입 감지)
│
▼
[Continuation 언마운트] (④ 가상 스레드 스택 프레임을 힙에 저장하고 캐리어 스레드 즉각 양보)
│
▼
[I/O 완료 및 통지 수신] (⑤ OS 비동기 I/O 이벤트 감지 후 가상 스레드를 실행 준비 큐에 재등록)
│
▼
[캐리어 스레드 재마운트] (⑥ 가용 캐리어 스레드에 힙 상태 복원 후 다음 명령어부터 실행 재개)
```

- 분기 결과: I/O 완료 시 대기 중인 다른 가용 캐리어 스레드에 즉각 스케줄링되어 중단된 지점부터 연산 속행

## Ⅴ. 종류 및 비교

| 구분 | 가상 스레드 (Virtual Thread) | 플랫폼 스레드 (Platform Thread) | 비동기 리액티브 (WebFlux) |
|:---|:---|:---|:---|
| 구현 주체 | 자바 가상 머신 (JVM 사용자 공간) | 운영체제 커널 (OS 커널 스레드) | 프레임워크 이벤트 루프 (Netty) |
| 메모리 크기 | 수백 바이트 ~ 수 KB (동적 힙) | 약 1MB 고정 (OS 스택) | 매우 작음 (이벤트 객체 수준) |
| 생성 가능 수량 | 수백만 개 동시 생성 가능 | 수천 개 수준으로 제한됨 | 수만 ~ 수십만 개 동시 연결 |
| 프로그래밍 모델 | 전통적인 동기식 명령형 코드 | 전통적인 동기식 명령형 코드 | 비동기 함수형 파이프라인 (Mono/Flux) |
| 주 병목 요인 | Carrier Pinning (네이티브/락 점유) | 컨텍스트 스위칭 및 메모리 고갈 | 디버깅 난이도 (스택 트레이스 소실) |

## Ⅵ. 실무 고려사항 및 대책

| 문제점 | 대책 | 효과 |
|:---|:---|:---|
| synchronized 블록 또는 JNI 호출 시 캐리어 스레드 피닝(Pinning) 발생 | ReentrantLock으로 락 구조 전환 및 JFR로 피닝 이벤트 모니터링 | 캐리어 스레드 독점 방지 및 워크 스틸링 정상 동작 |
| 가상 스레드 폭증으로 하류 DB 커넥션 풀 및 외부 API 과부하 | 가상 스레드 풀링 대신 세마포어(Semaphore) 기반 동시성 제한 적용 | 데이터베이스 커넥션 고갈 방지 및 하류 시스템 보호 |
| 수백만 가상 스레드에 대형 ThreadLocal 객체 누적으로 힙 OOM | Scoped Values 도입 및 요청 종료 시 ThreadLocal 명시적 제거 | 불필요한 메모리 누수 원천 방지 및 GC 압력 완화 |

## Ⅶ. 결론

- **기술 위상/발전**: 복잡한 리액티브 라이브러리 없이도 전통적인 Thread-per-Request 모델로 C10K를 넘어 C1000K를 달성하는 차세대 자바 동시성 표준으로 안착
- **실무 적용/통제**: CPU 집약적 연산이 아닌 I/O 집약적 마이크로서비스 백엔드에 집중 적용하고, synchronized 블록 제거 및 세마포어를 통한 하류 시스템 인입 제어 체계 확립 필수
