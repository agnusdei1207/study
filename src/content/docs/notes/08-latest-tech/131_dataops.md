## Ⅰ. 개요

- **정의**: 데이터 분석 및 AI 모델의 신뢰성을 보장하기 위해 데이터 파이프라인의 설계, 빌드, 테스트, 배포 및 모니터링 수명주기 전반에 애자일(Agile) 개발 방식과 DevOps 자동화 원칙을 결합한 데이터 엔지니어링 실천 체계
- **배경 및 필요성**: 분산 데이터 레이크하우스와 실시간 분석 환경에서 소스 스키마의 무단 변경이나 불량 데이터 유입으로 인해 다운스트림 BI 대시보드와 머신러닝 파이프라인 전체에 침묵의 데이터 장애(Data Downtime)가 전파되는 사고가 급증함에 따라, 데이터 계약(Data Contract)과 엔드투엔드 데이터 계보(Lineage) 기반의 품질 자동화 체계 구축이 필수적임

## Ⅱ. 특징

- **데이터 계약 기반 품질 게이트(Data Contract)**: 데이터 생산자와 소비자 간 스키마, 데이터 타입, 허용 임계치에 대한 명시적 계약을 코드화하여 위반 시 배포 차단
- **엔드투엔드 데이터 계보(Data Lineage)**: 원천 데이터 수집부터 최종 마트까지 컬럼 레벨(Column-level) 데이터 흐름과 종속성을 실시간 시각화 및 추적 (OpenLineage)
- **파이프라인 멱등성(Idempotency) 보장**: 장애 발생 시 언제든 특정 일자나 파티션을 재처리(Backfilling)해도 데이터 중복이나 왜곡이 발생하지 않는 원자적 처리
- **지속적 데이터 옵저버빌리티(Observability)**: 신선도(Freshness), 완전성(Completeness), 스키마 변경, 분포 이상치를 실시간 모니터링하여 데이터 사고 조기 경보

## Ⅲ. 구조 및 구성요소

### 1. DataOps 아키텍처

```text
[DataOps Architecture]
├── [오케스트레이션 및 통제 계층]
│   └── [오케스트레이터 (Pipeline Orchestrator)]
├── [품질 및 형상 관리 계층]
│   ├── [버전 저장소 (Version Repository)]
│   ├── [품질 게이트 (Quality Gate)]
│   └── [메타데이터 계보 (Metadata Lineage)]
└── [데이터 관측 계층]
    └── [데이터 관측 (Data Observability)]
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

### 2. 세부 구성요소

| 계층 구분 | 세부 항목 | 핵심 역할 |
|:---|:---|:---|
| 오케스트레이션 계층 | 파이프라인 오케스트레이터 | Airflow, Dagster 기반 DAG 의존성 스케줄링, 실패 시 자동 재시도 및 멱등 실행 |
| 품질 및 형상 계층 | 데이터 형상 관리 (Git) | dbt, SQL 모델 코드, 스키마 마이그레이션 스크립트 및 테스트 정의 버전 관리 |
| | 자동화 품질 게이트 | Great Expectations, Soda 기반 데이터 유효성 검사 및 CI 단계 승격 차단 |
| | 메타데이터 및 계보 저장소 | OpenLineage, Marquez 연계 데이터셋 간 의존 관계 및 변경 영향도 추적 |
| 데이터 관측 계층 | 데이터 옵저버빌리티 엔진 | Monte Carlo, Datadog 기반 데이터 파이프라인 지연, 볼륨 급변, 스키마 드리프트 감지 |

## Ⅳ. 흐름도

```text
[파이프라인 코드 변경] (① 데이터 변환 SQL 및 스키마 변경 커밋/PR 생성)
  │
  ▼
[CI 데이터 계약 검증] (② 가상 스테이징 환경에서 스키마 계약 및 무결성 자동 테스트)
  │
  ▼
[자동화 배포 및 스케줄링] (③ 품질 게이트 통과 시 프로덕션 파이프라인 무중단 승격)
  │
  ▼
[멱등적 변환 실행] (④ 오케스트레이터를 통한 배치/스트리밍 데이터 가공 및 계보 수집)
  │
  ▼
[실시간 옵저버빌리티] (⑤ 신선도, 볼륨, 분포 이상 감지 시 다운스트림 알림 및 백필 트리거)
```

- 분기 결과: CI 테스트 중 데이터 계약 위반(Breaking Change) 감지 시 파이프라인 배포 즉각 차단, 런타임 이상 발생 시 데이터 계보 기반 영향받는 하류 테이블 자동 동결 및 알림

## Ⅴ. 종류 및 비교

| 비교 항목 | DataOps (데이터 운영) | DevOps (소프트웨어 운영) | MLOps (머신러닝 운영) |
|:---|:---|:---|:---|
| 주요 산출물 | 신뢰할 수 있는 데이터셋, 마트, 계보 | 애플리케이션 바이너리, 마이크로서비스 | 훈련된 ML 모델 아티팩트 및 추론 API |
| 핵심 품질 기준 | 정확성, 완전성, 신선도, 스키마 일관성 | 가용성, 기능성, 성능, 에러율 | 예측 정확도, F1-Score, 드리프트 내성 |
| 변경 유발 요인 | 원천 비즈니스 데이터의 동적 변화 및 스키마 변경 | 비즈니스 로직 요구사항 및 코드 버그 수정 | 실세계 개념 드리프트 및 학습 데이터 분포 변화 |
| 핵심 도구 생태계 | dbt, Airflow, Great Expectations, Monte Carlo | Git, Jenkins, Terraform, Kubernetes | Feast, MLflow, Kubeflow, Evidently |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 소스 시스템의 무단 스키마 변경으로 인한 파이프라인 다운 | 생산자-소비자 간 선제적 데이터 계약(Data Contract) 강제 | 스키마 브레이킹 변경 사전 탐지 및 하류 데이터 파괴 방지 |
| 과거 데이터 누락 또는 로직 수정 시 백필(Backfill) 정합성 왜곡 | 파티션 덮어쓰기(Overwrite) 기반 멱등적(Idempotent) 파이프라인 설계 | 중복 적재 없는 안전하고 일관된 과거 데이터 재처리 보장 |
| 오류 발생 시 하류 의존 데이터 및 대시보드 파악 불가 | 컬럼 레벨 데이터 계보(Lineage) 그래프 자동 추출 및 연계 | 장애 영향 범위 신속 격리 및 관련 도메인 담당자 즉각 통보 |
| 침묵의 데이터 오염(Data Silent Failure) 장기 방치 | 신선도 및 볼륨 지표 대상 통계적 이상 탐지 알림 상시화 | 데이터 누락 및 적재 지연 사고를 수시간 내 조기 발견 및 대응 |

## Ⅶ. 결론

- **기술 위상/발전**: AI 및 비즈니스 인텔리전스를 지탱하는 엔터프라이즈 데이터 공급망의 신뢰성과 민첩성을 담보하는 현대 데이터 스택(MDS)의 핵심 표준으로 정착되었으며, 최근에는 분산 도메인 중심의 데이터 메시(Data Mesh)와 융합 중
- **실무 적용/통제**: 데이터 계약을 CI 파이프라인에 통합하여 스키마 변경을 사전 검증하고, 파이프라인의 멱등성을 보장하며, 컬럼 레벨 계보와 데이터 옵저버빌리티를 유기적으로 결합한 고신뢰 데이터 생태계 구축 필요
