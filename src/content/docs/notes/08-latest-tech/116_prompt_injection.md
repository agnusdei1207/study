## Ⅰ. 개요

- **정의**: 악의적으로 조작된 자연어 프롬프트를 LLM에 주입하여 기존 개발자의 시스템 지침(System Instructions)과 안전 가드레일을 무력화하고 공격자가 의도한 비인가 명령을 강제 실행시키는 보안 공격 기법
- **배경 및 필요성**: LLM이 개발자의 시스템 지시문과 사용자의 입력 데이터를 단일 컨텍스트 토큰 스트림으로 통합 처리하는 구조적 특성(지시-데이터 혼재)으로 인해, 텍스트 입력만으로도 모델의 실행 흐름을 장악하고 외부 도구(API) 오용 및 데이터 유출 피해를 유발하므로 근본적 방어 통제 구축 필수

## Ⅱ. 특징

- 제어 코드와 비신뢰 데이터가 단일 채널로 결합되는 폰 노이만 구조 취약점과 유사한 인젝션 구조
- 직접 입력(Direct)뿐 아니라 웹 페이지, 이메일, 문서 등 외부 RAG 컨텍스트를 통한 간접(Indirect) 유입 지원
- 단순 프롬프트 방어문구 작성만으로는 우회가 쉬워 엄격한 권한 분리 및 이중 LLM(Dual LLM) 격리 필요

## Ⅲ. 구조 및 구성요소

```text
Prompt_Injection_Defense_Architecture
├── Input_Isolation (신뢰 시스템 프롬프트 및 비신뢰 데이터 XML 태깅 격리)
├── Guardrail_Filter (유해 키워드 탐지 및 시맨틱 인젝션 분류기)
├── Privilege_Broker (최소 권한 도구 호출 브로커 및 인자 검증기)
└── Execution_Gateway (고위험 행동 차단 및 HITL 인간 승인 게이트)
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

| 구성요소 | 세부 항목 | 핵심 역할 |
|:---|:---|:---|
| 입력 격리 계층 | XML/JSON 구조화 태깅, 구분자 마스킹 | 시스템 지시문과 외부 비신뢰 데이터를 명확히 분리하여 명령어 승격 차단 |
| 가드레일 필터 | Llama Guard, NeMo Guardrails | 사용자 입력 및 검색 컨텍스트 내 악성 인젝션 패턴 사전 검사 및 필터링 |
| 권한 브로커 | 도구 허용 목록, API 호출 스코프 통제 | 모델이 제안한 도구 실행 요청의 매개변수 유효성 및 권한 범위 독립 검증 |
| 실행 게이트웨이 | 샌드박스 실행기, 인간 개입(HITL) 승인 창구 | 이메일 발송, DB 삭제 등 비가역적 고위험 액션의 최종 실행 통제 |

## Ⅳ. 흐름도

```text
[사용자 입력 및 외부 컨텍스트 수신] (① 비신뢰 텍스트 및 외부 검색 문서 수집)
│
▼
[입력 가드레일 및 인젝션 검사] (② 시맨틱 분류기를 통해 탈옥 및 인젝션 패턴 탐지)
│
▼
[구조적 태깅 및 컨텍스트 격리] (③ `<user_data>` 태그로 외부 텍스트 감싸서 프롬프트 주입 방지)
│
▼
[LLM 응답 생성 및 도구 호출 제안] (④ 모델이 분석 결과 및 실행할 API 요청 생성)
│
▼
[권한 브로커 검증 및 인간 승인] (⑤ API 파라미터 유효성 검사 및 고위험 액션 시 관리자 승인)
```

- 분기 결과: 입력 가드레일 검사를 통과하고 도구 호출 파라미터가 유효하면 결과를 실행 및 반환하고, 인젝션 패턴 탐지 또는 권한 초과 시 즉시 요청을 차단하고 경고 로그 기록

## Ⅴ. 종류 및 비교

| 구분 | 직접 프롬프트 인젝션 (Direct) | 간접 프롬프트 인젝션 (Indirect) |
|:---|:---|:---|
| 공격 진입점 | 사용자가 챗봇 입력창에 직접 악성 명령 입력 | 외부 웹페이지, 이메일 본문, PDF, RAG 검색 DB |
| 주요 공격 목적 | 시스템 프롬프트 탈취, 가드레일 우회, 비인가 답변 생성 | 백그라운드 데이터 유출, 외부 API 무단 호출, 피싱 유도 |
| 공격자 인지 여부 | 공격자가 직접 모델과 대화하며 결과 즉시 확인 | 사용자는 일반 질문을 수행하나 검색된 문서에 의해 무의식적 피습 |
| 주요 방어 대책 | 시스템 프롬프트 강화, 입출력 가드레일 필터링 | 이중 LLM(격리 처리), 신뢰 경계 분리, 도구 권한 최소화 |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 자연어 프롬프트 지시문 강조만으로 발생하는 인젝션 우회 | 구조화된 XML 태그 구분자 적용 및 이중 LLM(데이터 전용 모델) 분리 | 비신뢰 텍스트의 명령어 승격 원천 차단 |
| 모델 탈취 시 연결된 외부 API 및 도구의 무단 실행(Tool Abuse) | 권한 브로커(Privilege Broker) 기반 화이트리스트 및 파라미터 스키마 검증 | 인젝션 성공 시에도 실환경 파급 피해 원천 격리 |
| 개인정보 유출 및 대량 이메일 발송 등 비가역적 피해 발생 | 고위험 액션 실행 직전 인간 개입(HITL) 2차 인증 게이트웨이 의무화 | 치명적 사고 발생 방지 및 컴플라이언스 준수 |

## Ⅶ. 결론

- **기술 위상/발전**: 생성형 AI 및 LLM 애플리케이션 보안 분야에서 가장 치명적이고 빈번하게 발생하는 **OWASP Top 10 for LLM 제1위 보안 위협**이자 제로 트러스트 AI 아키텍처 구축의 핵심 과제
- **실무 적용/통제**: 자연어 프롬프트 방어에 의존하지 않고 **XML 구조적 격리, 이중 LLM 패턴, 도구 최소 권한 브로커 및 HITL 승인 게이트**를 유기적으로 결합한 심층 다층 방어 체계 구축 필요
