## Ⅰ. 개요

- **정의**: 최초 토큰 수신 이후 전체 응답 출력이 완료될 때까지 생성되는 토큰 하나당 평균 소요 시간(Time per Output Token / Inter-Token Latency).
- **배경 및 필요성**:
  - **스트리밍 생성 유창성 보장**: 첫 응답 이후 텍스트가 끊김 없이 출력되는 사용자 체감 독해 속도(초당 15~20+ 토큰)를 정량적으로 관리.
  - **디코딩 메모리 병목 감지**: 자기회귀(Autoregressive) 생성 단계의 핵심 제약인 GPU VRAM 메모리 대역폭 한계(Memory-bound)를 직접 측정.
  - **동시 서빙 튜닝 기준 확립**: 배치 크기 증가에 따른 성능 저하와 KV 캐시 압축(GQA, 양자화)의 실질적 가속 효과를 평가하는 벤치마크 메트릭으로 활용.

## Ⅱ. 핵심 특징

- **평균 생성 간격 측정**: 전체 디코딩 소요 시간을 생성된 출력 토큰 수로 나누어 산출 ($TPOT = \frac{\text{총 디코딩 시간}}{\text{생성 토큰 수}}$).
- **속도와의 역비례 관계**: TPOT이 낮을수록 초당 생성 토큰 수(Tokens Per Second, TPS)가 선형적으로 증가.
- **메모리 대역폭 지배적**: 연산 집약적인 프리필(TTFT)과 달리, 가중치 및 KV 캐시를 매 토큰마다 인출해야 하는 메모리 바운드 특성.
- **연속 배치(Continuous Batching) 민감도**: 동시 디코딩 슬롯이 늘어날수록 GPU 대역폭 경합으로 개별 요청의 TPOT이 증가하는 트레이드오프 존재.

## Ⅲ. 구조 및 구성요소

```text
[TPOT(토큰당 출력 지연) 계측 아키텍처]
├── [디코드 스케줄러 (Decode Scheduler)]
│   ├── 반복 레벨 연속 배치(Iteration-level Batching)
│   └── 활성 디코딩 슬롯 및 토큰 생성 주기 제어
├── [KV 캐시 매니저 (KV Cache Manager)]
│   ├── GPU HBM으로부터 과거 K/V 벡터 고속 인출
│   └── 신규 생성 토큰 K/V 블록 메모리 갱신
├── [자기회귀 디코딩 엔진 (Autoregressive Engine)]
│   ├── 단일 토큰 순전파 및 차기 로짓(Logit) 산출
│   └── 메모리 대역폭 바운드(Memory-bound) 연산 수행
└── [샘플러 및 스트리머 (Sampler & Streaming Egress)]
    ├── 온도/Top-p 기반 차기 토큰 확률적 선택
    └── 토큰 간 도착 시간(Inter-token Latency) 실시간 계측
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 TPOT 계측 및 디코딩 파이프라인의 상위 계층과 세부 구성요소 간 계층적 포함 관계를 나타낸다.

| 구성요소 | 역할 및 세부 기능 |
|:---|:---|
| 디코드 스케줄러 | 활성 요청 간 연속 배치 스케줄링을 제어하고 매 반복마다 연산 슬롯 동적 할당 |
| KV 캐시 매니저 | GPU HBM 메모리 버스를 통해 과거 K/V 텐서를 로드하고 신규 캐시 블록 동기화 |
| 자기회귀 디코딩 엔진 | 단일 토큰 단위 순전파 연산을 통해 다음 어휘에 대한 로짓 분포 도출 |
| 샘플러 및 스트리머 | 샘플링 알고리즘으로 토큰을 확정하고 클라이언트로 패킷 전송 및 토큰 간격 로깅 |

## Ⅳ. 흐름도

```text
[배치 슬롯 편성] (① 디코드 스케줄러가 활성 상태의 요청들을 묶어 단일 반복 배치 구성)
       │
       ▼
[KV 캐시 인출] (② HBM 메모리에서 각 시퀀스의 과거 K/V 벡터를 캐시 엔진으로 로드)
       │
       ▼
[단일 토큰 순전파] (③ 모델 가중치와 인출된 캐시를 결합하여 차기 토큰 로짓 연산)
       │
       ▼
[토큰 샘플링 및 캐시 갱신] (④ 차기 토큰을 최종 선택하고 신규 K/V 벡터를 캐시 블록에 추가)
       │
       ▼
[스트리밍 전송 및 간격 계측] (⑤ 클라이언트로 토큰 송신 후 직전 토큰과의 시간 간격(ITL) 기록 및 반복 판단)
```

- 분기 결과: 문장 종료 토큰(EOS) 또는 최대 생성 길이에 도달하면 디코딩 종료, 미도달 시 차기 토큰 생성을 위한 캐시 로드 단계로 재귀 반복.

## Ⅴ. 종류 및 비교

| 비교 항목 | TPOT (Time per Output Token) | TTFT (Time to First Token) | Throughput (Tokens/Sec) |
|:---|:---|:---|:---|
| 핵심 측정 대상 | 토큰당 평균 디코딩 생성 지연 | 최초 응답 토큰 도착까지의 지연 | 단위 시간당 전체 서버 처리 토큰 수 |
| 시스템 병목 자원 | GPU HBM 메모리 대역폭 (Memory-bound) | 큐 대기열 및 연산 코어 처리량 (FLOPs-bound) | 전체 GPU 클러스터의 종합 컴퓨팅 자원 |
| 주 사용자 체감 | 텍스트 스트리밍 출력의 끊김 없는 유창성 | 질의 입력 후 첫 반응의 신속성 | 시스템 전반의 동시 사용자 수용 능력 |
| 최적화 방안 | GQA, FP8 KV 캐시 양자화, Speculative Decoding | Prefix Caching, Chunked Prefill | Continuous Batching, Tensor Parallelism |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| KV 캐시 인출로 인한 HBM 메모리 대역폭 포화 | GQA(Grouped Query Attention) 및 FP8 KV 캐시 양자화 적용 | 캐시 로드 데이터 전송량 감소 및 디코딩 속도 2~3배 향상 |
| 과도한 동시 배치로 인한 토큰 생성 지연 증가 | 지연 시간 SLO 기반 동적 배치 크기 상한 설정 및 부하 분산 | 꼬리 지연(P95 ITL) 방어 및 안정적 응답 유창성 확보 |
| 불규칙한 토큰 정지(Stuttering) 발생 | 단순 평균 TPOT 외에 P95 토큰 간 간격(ITL) 편차 집중 모니터링 | 스트리밍 끊김 현상의 조기 탐지 및 스케줄러 즉각 튜닝 |

## Ⅶ. 결론

- **기술 위상/발전**: LLM 추론 서빙에서 사용자 대화 유창성과 GPU 메모리 대역폭 활용 효율을 평가하는 핵심 디코딩 품질 지표로 확립
- **실무 적용/통제**: 50ms 미만(초당 20토큰 이상)의 안정적 TPOT 유지를 위해 FP8 KV 캐시 양자화와 추측 디코딩(Speculative Decoding)을 결합 적용하고 P95 토큰 간 간격을 집중 통제
