## Ⅰ. 개요

- **정의**: 질의(Query), 문맥(Context), 응답(Answer), 기준 정보(Ground Truth)를 구조화하여 RAG 시스템의 검색 및 생성 품질을 자동 계측하는 프레임워크인 **RAGAS(Retrieval Augmented Generation Assessment)**
- **배경 및 필요성**: RAG 파이프라인 구성요소 튜닝 시 사람이 직접 정답 레이블을 라벨링하고 채점하는 방식은 시간과 비용이 과다하게 소요되고 주관적 편차로 인해 지속적인 회귀 테스트가 불가능한 한계가 존재함에 따라, LLM을 판정관(Judge)으로 활용하여 정답 레이블 없이도(Reference-free) 검색 정밀도/재현율과 생성 충실성/관련성을 객관적으로 자동 채점하고 지식 기반 합성 테스트셋 생성을 지원하여 초고속 RAG 튜닝 및 CI/CD 품질 파이프라인을 확립하기 위해 필요

## Ⅱ. 특징

- **4대 핵심 지표 분리**: 검색 차원(Context Precision, Context Recall)과 생성 차원(Faithfulness, Answer Relevance)의 독립 정량화
- **무참조 평가 지원**: 기준 정답(Ground Truth)이 없는 프로덕션 환경에서도 LLM 기반 사실성 및 관련도 채점 가능
- **재현 가능한 실행 조건**: 평가 판정 모델, 프롬프트 템플릿, 온도(Temperature=0), 재시도 정책의 엄격한 버전 고정

## Ⅲ. 구조 및 구성요소

```text
[RAGAS System]
├── [입력/데이터 계층]
│   └── [평가 데이터셋 (Evaluation Dataset)]
├── [평가 정의 계층]
│   ├── [지표 모음 (Metrics Suite)]
│   └── [평가 모델 (Judge/Embedding LLM)]
└── [실행/결과 계층]
    ├── [평가 실행기 (Evaluation Runner)]
    └── [결과 저장소 (Result Store)]
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

| 구성요소 | 책임 |
|:---|:---|
| 평가 데이터셋 | 질의, 문맥 청크, 모델 응답, 기준 정답 스키마 데이터 관리 |
| 지표 모음 | Context Precision/Recall, Faithfulness 등 점수 산출 로직 정의 |
| 평가 모델 | 판정 LLM(LLM-as-a-Judge) 및 벡터 임베딩 모델 기반 점수 연산 |
| 평가 실행기 | 비동기 배치 실행, 프롬프트 버전 제어, API 재시도 통제 |
| 결과 저장소 | 표본별 지표 점수, 토큰 비용, 평가 메타데이터 보존 |

## Ⅳ. 흐름도

```text
[평가 관리자] (① 평가 대상 지표 모음 선정 및 표본 스키마 정의)
│
▼
[평가 실행기] (② 판정 모델·프롬프트 버전 고정 및 데이터셋 배치 평가 실행)
│
▼
[평가 모델 (Judge)] (③ 검색 문맥 대비 충실성 및 질의 대응 관련성 점수 연산)
│
▼
[결과 저장소/검증자] (④ 점수 분포 집계 및 대표 표본 인간 검증 교차 분석)
```

- 분기 결과: 4대 핵심 지표 합격 기준 달성 시 프로덕션 배포 파이프라인 승인, 미달 시 검색 청킹 또는 프롬프트 재조정 리포트 발행

## Ⅴ. 종류 및 비교

| 구분 | LLM 기반 지표 (LLM-based) | 비LLM 기반 지표 (Non-LLM) | 인간 평가 (Human Eval) |
|:---|:---|:---|:---|
| 적용 기준 | 의미적 관련성, 사실 충실성 판정 | 문자열 완전 일치, 통계적 유사도 | 고위험 업무 최종 적합성 검증 |
| 핵심 특징 | 판정 LLM 프롬프트 기반 유연한 의미 추론 | BLEU, ROUGE, Exact Match 등 결정론적 연산 | 도메인 전문가 지침에 따른 수작업 채점 |
| 한계 | 비결정성, 판정 LLM 편향 및 API 비용 | 문맥적 의미 파악 불가, 어휘 변형 취약 | 시간·비용 과다, 평가자 간 주관적 편차 |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 지표별 필수 스키마 누락 | 평가 실행 전 데이터셋 필드 유효성(Schema Validation) 사전 검증 | 평가 연산 중단 및 무효 점수 오류 방지 |
| 판정 모델 변경 시 기준 이동 | 판정 LLM 버전 및 평가 프롬프트 템플릿 코드화 관리 | 시계열 회귀 테스트 결과의 비교 가능성 확보 |
| LLM 판정의 비결정성 및 편향 | Temperature=0 설정, 다회 실행 평균화 및 인간 평가 상관계수 실측 | 자동 점수 신뢰 구간 확보 및 편향 보정 |

## Ⅶ. 결론

- **기술 위상/발전**: RAG 파이프라인의 검색 및 생성 품질을 표준화된 4대 핵심 지표로 자동 정량화하여 글로벌 RAG 평가 방법론의 사실상 표준으로 자리매김한 오픈소스 프레임워크
- **실무 적용/통제**: 판정 LLM 프롬프트 버전 고정, 합성 테스트셋 연계, 정기적인 전문가 일치도 검증을 병행하여 객관적이고 민첩한 **RAGAS** 평가 체계 확립
