## Ⅰ. 개요

- **정의**: 대규모 데이터셋에 대해 동일 연산을 병렬 적용하기 위해 다수의 가벼운 연산 코어를 집적하고 단일 명령 다중 스레드(SIMT) 방식으로 처리량을 극대화한 병렬 처리 가속 컴퓨팅 프로세서
- **배경 및 필요성**: 복잡한 분기 제어와 순차 처리에 최적화된 전통적 CPU는 코어당 거대한 캐시 및 독립 제어 유닛 구조로 인해 수천 개의 동시 연산이 요구되는 3D 그래픽 래스터라이제이션 및 딥러닝 텐서(Tensor) 연산 처리 시 처리량 한계에 직면함에 따라, 수천 개의 연산 코어가 단일 명령어를 공유 실행하는 SIMT 아키텍처를 도입하여 동일 실리콘 면적 내 연산기 집적도를 극대화하고 워프(Warp) 초고속 컨텍스트 스위칭을 통해 메모리 접근 지연을 은닉할 필요성 대두

## Ⅱ. 특징

- 워프 단위 SIMT(Single Instruction Multiple Threads) 데이터 병렬 실행
- 준비된 워프 간 무비용 컨텍스트 스위칭을 통한 메모리 지연 은닉(Latency Hiding)
- 병합 접근(Coalescing) 및 공유 메모리 타일링을 통한 외부 VRAM 대역폭 병목 최소화

## Ⅲ. 구조 및 구성요소

```text
[GPU Architecture]
├── [실행 클러스터 계층]
│   └── [스트리밍 멀티프로세서 (SM)]
├── [스케줄링 계층]
│   └── [워프 스케줄러 (Warp Scheduler)]
├── [연산 코어 계층]
│   └── [산술·텐서 유닛 (ALU & Tensor Core)]
└── [메모리 서브시스템 계층]
    ├── [온칩 메모리 계층 (Register/Shared Memory/L1·L2 Cache)]
    └── [VRAM 제어기 (HBM/GDDR Controller)]
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

| 구분 | 구성요소 | 기능 설명 |
|:---|:---|:---|
| 실행 클러스터 | 스트리밍 멀티프로세서(SM) | 스레드 블록 수용, 공유 메모리 및 연산 코어 자원 관리 |
| 스케줄링 | 워프 스케줄러 | 32개 스레드로 구성된 준비 상태 워프 선별 및 사이클당 명령어 디스패치 |
| 연산 코어 | ALU 및 Tensor Core | 정수/부동소수점 스칼라·벡터 연산 및 저정밀도(FP8/FP4) 4x4 행렬 곱셈·누산(MMA) 가속 |
| 메모리 서브시스템 | 온칩 메모리 계층 | 레지스터 파일, L1 데이터 캐시, 프로그래머블 공유 메모리를 통한 고속 데이터 재사용 |
| 메모리 인터페이스 | VRAM 제어기 | 고대역폭 메모리(HBM/GDDR) 채널 인터리빙 제어 및 전역 메모리 트랜잭션 최적화 |

## Ⅳ. 흐름도

```text
[호스트 CPU] (① 호스트 메모리에서 VRAM으로 커널 및 텐서 데이터 복사 요청)
│
▼
[VRAM 제어기] (② 대규모 입력 데이터를 전역 메모리에 적재 및 SM으로 타일 블록 디스패치)
│
▼
[워프 스케줄러] (③ 32개 스레드 단위 워프 편성 및 실행 가능 워프 명령어 발행)
│
▼
[산술·텐서 코어] (④ SIMT 병렬 연산 수행 및 메모리 대기 시 타 워프로 즉각 전환)
│
▼
[메모리 제어기 및 호스트] (⑤ 최종 계산 결과 전역 VRAM 기록 후 호스트 DMA 전송 반환)
```

- 분기 결과: 연산 중 스레드 간 분기 발산(Divergence) 발생 시 각 실행 경로를 직렬화하여 순차 처리하고, 전 스레드 완료 후 단일 경로로 재수렴

## Ⅴ. 종류 및 비교

| 비교 항목 | GPU | CPU | AI ASIC (TPU 등) |
|:---|:---|:---|:---|
| 핵심 구조 | 대규모 SIMT 코어 배열 | 소수 고성능 코어 + 거대 캐시 | 전용 시스톨릭 어레이(Systolic Array) |
| 처리 대상 | 규칙적 대규모 데이터 병렬 연산 | 복잡한 제어 및 순차 의존 연산 | 고정된 텐서 데이터플로우 행렬 연산 |
| 분기 제어 능력 | 분기 발산 시 직렬화 페널티 발생 | 정교한 분기 예측기로 지연 극소화 | 제한적이거나 호스트 프로세서에 의존 |
| 전력 효율성 | 범용성 대비 우수하나 소비 전력 큼 | 대량 연산 대비 전력 효율 낮음 | 고정 연산 최적화로 와트당 연산력 극대화 |
| 프로그래밍 생태계 | CUDA, Triton, OpenCL 등 표준화 | C/C++, Java 등 범용 언어 전 영역 | 전용 컴파일러(XLA 등) 의존성 높음 |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 워프 내 조건 분기로 인한 SIMT 직렬화(Divergence) 발생 | 동일 실행 흐름을 갖는 스레드끼리 워프 그룹 재편성 및 데이터 기반 마스킹 적용 | 워프 비활성 스레드 유휴 시간 제거 및 하드웨어 연산 유닛 가동률 극대화 |
| 불연속 메모리 참조로 인한 VRAM 비병합(Non-coalesced) 접근 병목 | 메모리 정렬 및 연속 주소 접근 패턴 강제, 공유 메모리 기반 타일링 기법 적용 | 글로벌 메모리 트랜잭션 횟수 대폭 감축 및 메모리 버스 대역폭 포화 방지 |
| 호스트와 GPU 장치 간 PCIe 전송 오버헤드로 인한 파이프라인 정체 | 피닝 메모리(Pinned Memory) 및 스트림(CUDA Stream) 비동기 전송 파이프라이닝 구축 | 연산 실행과 데이터 전송의 완전 중첩을 통한 엔드투엔드 파이프라인 처리 지연 은닉 |

## Ⅶ. 결론

- **기술 위상/발전**: 초창기 그래픽 렌더링 파이프라인에서 출발하여 GPGPU 및 생성형 AI 인프라의 핵심 엔진으로 진화하였으며, 트랜스포머 전용 하드웨어 가속기(FP8/FP4 지원)와 초고속 NVLink 스위치 패브릭 연계를 통해 스케일업 초거대 AI 가속 표준으로 확고히 자리매김
- **실무 적용/통제**: 분기 발산을 최소화하는 데이터 정렬, 공유 메모리 타일링 및 병합 메모리 접근 설계를 준수하고, 복잡한 비정형 제어는 CPU에, 고밀도 행렬 곱셈은 GPU에 분담시키는 이기종 협력 파이프라인 구축 권장
