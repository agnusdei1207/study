## Ⅰ. 개요

- **정의**: 개발자가 인프라 및 운영 팀에 대한 티켓 요청 없이 애플리케이션 개발, 배포, 운영에 필요한 리소스와 환경을 셀프서비스로 프로비저닝하고 관리할 수 있도록 지원하는 내부 제품(Internal Product)
- **배경 및 필요성**: 수십 개의 개발팀이 개별적으로 인프라, K8s 매니페스트, CI/CD, 모니터링을 중복 구성함에 따라 도구 파편화와 인지 부하가 가중되고 티켓 승인 병목으로 배포 리드타임이 지연되는 문제를 해결하기 위해, 검증된 골든 패스(Golden Path)와 서비스 카탈로그가 통합된 단일 셀프서비스 포털 제공 필요

## Ⅱ. 특징

- 단일 웹 UI, CLI, 선언적 명세(Score 등)를 통해 제공되는 일관된 플랫폼 API 계약
- 보안, 인프라, 아키텍처 모범 사례가 기본값으로 내장된 골든 패스(Golden Path) 템플릿
- 조직 전체의 마이크로서비스 소유권, 문서, API 명세를 통합 시각화하는 중앙 집중식 서비스 카탈로그
- 인프라 프로비저닝 요청 시 보안 가드레일을 사전 검증하는 Policy-as-Code 자동화

## Ⅲ. 구조 및 구성요소

```text
[내부 개발자 플랫폼 아키텍처]
├── 진입 인터페이스 계층 ── 개발자 포털 UI(Backstage), CLI 도구, 플랫폼 API
├── 카탈로그 거버넌스 계층 ── 서비스 카탈로그, 골든 패스 템플릿, OPA 정책 엔진
└── 오케스트레이션 실행 계층 ── 워크플로우 엔진, IaC/GitOps 드라이버, 관측 파이프라인
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

| 계층 | 핵심 구성요소 | 주요 역할 및 책임 |
|:---|:---|:---|
| 진입 인터페이스 계층 | Backstage Developer Portal | 플러그인 기반 오픈소스 UI로 서비스 카탈로그 및 셀프서비스 요청 인터페이스 통합 |
| 진입 인터페이스 계층 | Platform API & CLI | 터미널 작업과 CI 파이프라인 연동을 위한 표준화된 플랫폼 기능 접점 |
| 카탈로그 거버넌스 계층 | Software Catalog | 시스템 아키텍처, 서비스 소유자, API 의존성, 런타임 상태 메타데이터 보관 |
| 카탈로그 거버넌스 계층 | Golden Path Software Templates | 프로젝트 스캐폴딩, 리포지토리 생성, CI/CD 템플릿 파라미터 바인딩 |
| 카탈로그 거버넌스 계층 | Policy Engine (OPA) | 규정 준수 여부(네트워크 정책, 태깅, 보안 그룹)를 요청 시점에 자동 심사 |
| 오케스트레이션 실행 계층 | Infrastructure Orchestrator | Terraform, Crossplane, ArgoCD 워크플로우를 트리거하여 인프라 실체화 |
| 오케스트레이션 실행 계층 | Observability & Telemetry | 프로비저닝 성공률, 환경 배포 리드타임, 플랫폼 자원 사용량 지표 수집 |

## Ⅳ. 흐름도

```text
[개발자 포털 접속 및 템플릿 선택] (① Backstage UI에서 골든 패스 기반 마이크로서비스 템플릿 선택)
│
▼
[입력 파라미터 및 스키마 검증] (② 환경 설정 값 입력 및 OPA 정책 엔진을 통한 보안/컴플라이언스 검증)
│
▼
[IDP 오케스트레이터 구동] (③ Git 리포지토리 생성, CI/CD 파이프라인 등록, Secret 주입 자동화)
│
▼
[인프라 프로비저닝 및 GitOps 배포] (④ Terraform/Crossplane을 통한 클라우드 리소스 생성 및 ArgoCD 동기화)
│
▼
[서비스 카탈로그 등록 및 모니터링] (⑤ 서비스 메타데이터 등록, TechDocs 생성, 대시보드 URL 반환)
```

- 분기 결과: 템플릿 파라미터 및 정책 검증 통과 시 전용 개발 환경이 수 분 내 즉시 생성되며, 정책 위반(미승인 인스턴스 타입, 태그 누락 등) 시 명확한 에러 사유와 수정 가이드가 즉각 반환됨

## Ⅴ. 종류 및 비교

| 구분 | IDP (내부 개발자 플랫폼) | 개발자 포털 (Developer Portal) | 상용 클라우드 콘솔 (AWS/Azure) |
|:---|:---|:---|:---|
| 정의 | 셀프서비스 기능 전체 시스템 | 사용자 접점 포털 UI 레이어 | CSP 제공 원시 관리 콘솔 |
| 주 역할 | 템플릿 실행, 오케스트레이션, 정책 자동화 | 서비스 카탈로그 및 문서 시각화 | 개별 클라우드 리소스 직접 제어 |
| 인지부하 | 골든 패스를 통해 복잡성 완전 은닉 | 백엔드 실행 엔진 없이는 기능 한계 | 수백 개의 클라우드 서비스 설정 학습 필요 |
| 대표 솔루션 | Port, Humanitec, 자체 구축 플랫폼 | Spotify Backstage, Cortex | AWS Management Console |

## Ⅵ. 실무 고려사항 및 대책

| 문제점 | 대책 | 효과 |
|:---|:---|:---|
| 개발자 수요를 반영하지 못한 복잡한 템플릿으로 골든 패스 외면 | 개발팀 심층 인터뷰 및 파일럿 프로젝트를 거친 필수 기본 경로 위주 설계 | 골든 패스 자발적 채택률 극대화 |
| 지나친 추상화로 프로비저닝 실패 시 개발자 원인 분석 불가 | 오케스트레이션 단계별 실시간 로그 및 에러 트레이스를 포털 UI에 투명하게 노출 | 디버깅 자립성 향상 및 플랫폼 팀 지원 요청 감소 |
| 환경 무제한 프로비저닝으로 인한 유휴 클라우드 비용 폭증 | 개발/테스트 환경의 자동 TTL(Time-To-Live) 만료 및 야간 자동 정지 스케줄링 | 클라우드 인프라 낭비 방지 및 FinOps 통제 달성 |

## Ⅶ. 결론

- **기술 위상/발전**: 플랫폼 엔지니어링의 핵심 산출물이자 개발자 경험(DevEx) 혁신의 중심 축으로 Spotify Backstage 기반 오픈소스 생태계를 중심으로 표준화 진행
- **실무 적용/통제**: 표준 경로가 우회로보다 매력적이도록 골든 패스를 고도화하고, 내부 고객(개발자) 피드백 기반 지속적 개선과 함께 디버깅 투명성을 위한 실행 로그 및 탈출 경로(Escape Hatch) 확보
