## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **에이전트 권한 제어(Agent Authorization & Control)**: 에이전트가 위임받은 범위 안에서만 자원과 도구를 사용하도록 인증•인가•승인을 강제하는 통제 체계이다.
- **인증(Authentication)**: 접근을 요청하는 사용자•에이전트•도구의 신원을 확인하는 절차로 정의된다.
- **인가(Authorization)**: 인증된 주체가 특정 자원에 어떤 행동을 할 수 있는지 결정하는 절차.
- **최소 권한(Least Privilege)**: 업무 수행에 필요한 최소 범위와 시간으로 권한을 제한하여 부여하는 원칙이다.

</details>

- 정의: 위임 범위 안에서 자원•도구 행동을 제한하는 **권한 제어**
- 배경/필요성: 자율 AI 에이전트에게 데이터베이스, 클라우드 인프라, 금융 API 등에 대한 광범위한 고정 권한(Broad Static Privilege)을 부여할 경우, 프롬프트 주입이나 모델 환각으로 인한 오작동 한 번으로 엔터프라이즈 시스템 전체가 파괴되거나 민감 데이터가 유출되는 치명적인 보안 결함이 발생함에 따라, 주체·환경 속성과 작업 목적에 따라 접근을 동적으로 평가하고 강제하는 권한 제어(Agent Authorization & Control) 프레임워크를 구축하여 **최소 권한 원칙(Least Privilege) 기반의 단기 권한 위임(Scoped Delegation), 정책 결정점(PDP)과 정책 집행점(PEP) 분리를 통한 도구 호출 전 동적 인가, 비가역적 고위험 행동에 대한 인간 개입(HITL) 통제 확립**을 달성할 필요

#### 한줄 요약
- 작업별 **최소 권한•승인 경계**는 피해 반경을 줄이는 대신 권한 요청과 승인 대기로 자동화 속도를 깎으므로, 되돌릴 수 없는 행동에 한해 경계를 촘촘히 두는 편이 합리적이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **권한 위임(Delegation)**: 사용자가 에이전트에게 수행할 행동의 범위와 기간을 정해 권한을 넘기는 행위.
- **정책 결정점(Policy Decision Point, PDP)**: 정책과 주체•자원•환경 속성을 평가하여 접근 허용 여부를 판단하는 지점이다.
- **정책 집행점(Policy Enforcement Point, PEP)**: PDP의 결정을 도구 호출 직전에 허용이나 거부로 강제하는 지점.
- **인간 개입(Human-in-the-Loop, HITL)**: 고위험 행동을 사람이 검토하고 승인하는 통제 방식이다.

</details>

- **인증**: 사용자•에이전트•도구 신원 확인
- **권한 위임**: 대리 행동의 범위•기간 제한
- **PDP**: 주체•자원•환경 속성으로 허용 판단
- **PEP**: 정책 판단을 도구 호출 전에 강제
- **최소 권한**: 최소 실행 권한 부여를 통한 잠재 피해 범위 제한
- **HITL**: 고위험 행동을 사람 승인으로 제한

#### 한줄 요약
- **열람•변경 권한** 분리와 고위험 행동 재확인

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **정책 관리(Policy Management)**: 역할•속성•금지 규칙과 정책 버전을 정의하고 변경하는 기능.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 에이전트가 외부 기능을 요청하는 호출 경계로, PEP가 정책을 집행하는 지점.

</details>

```text
[에이전트 권한 제어(Control) 체계]
├── [신원 및 위임 계층]
│   ├── 사용자/에이전트 인증 (Authentication)
│   └── 스코프 기반 단기 위임 (Scoped Token)
├── [정책 결정 및 관리]
│   ├── ABAC/RBAC 정책 저장소 (Policy Store)
│   └── 정책 결정점 (PDP)
└── [정책 집행 및 거버넌스]
    ├── 정책 집행점 (PEP: 도구 인터셉터)
    ├── 고위험 행위 HITL 승인 게이트
    └── 인가 이벤트 감사 로그 (Audit Trail)
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 최상위 에이전트 권한 제어 체계에서 신원 및 위임, 정책 결정 및 관리, 정책 집행 및 거버넌스 계층으로 이어지는 구조적 포함 관계를 나타냄

| 구성요소 | 책임 |
|:---|:---|
| 인증•위임 | 사용자•에이전트의 신원•대리 범위 확인 |
| 정책 관리 | 역할•속성•금지 규칙을 정책 관리로 정의 |
| 정책 결정점 | 주체•자원•환경에 따른 허용 여부 판단 |
| 정책 집행점 | API 호출 전 허용•거부 강제 |
| 승인•감사 | 고위험 행동의 HITL 승인•결과 기록 |

#### 한줄 요약
- 모델 제안을 **PDP•PEP**와 HITL 계층이 통제

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **정책 질의(Policy Query)**: PEP가 요청의 주체•자원•행동•환경 정보를 PDP에 전달하여 허용 여부를 묻는 과정.
- **추가 승인(Additional Approval)**: 정책상 고위험으로 분류된 행동을 실행하기 전에 사용자에게 최종 결정을 요청하는 절차이다.
- **정책 집행점(Policy Enforcement Point, PEP)**: 정책 결정에 따라 실제 API 호출 여부를 물리적으로 차단 또는 통과시키는 지점.

</details>

```text
[스코프 기반 위임 토큰 발급] (① 사용자가 에이전트에게 최소 범위·기한의 단기 위임 자격증명 부여)
│
▼
[도구 호출 인터셉트] (② 에이전트가 외부 API 호출 시 정책 집행점(PEP)이 요청 매개변수 가로챔)
│
▼
[동적 정책 질의 및 평가] (③ PEP가 주체, 자원, 작업, 환경 속성을 정책 결정점(PDP)에 전달하여 인가 여부 판정)
│
▼
[고위험 행동 식별 및 HITL 승인] (④ 비가역적 액션 또는 금전 거래 감지 시 사용자 승인 게이트웨이 호출)
│
▼
[도구 실행 허용 및 감사 로깅] (⑤ 승인 통과 시에만 도구 API 실행을 중계하고 불변 감사 추적 로그 기록)
```

- 분기 결과: 정상 승인 시 도구 실행 및 결과 반환, 정책 위반 또는 승인 거부 시 실행 차단 및 위반 이벤트 로깅

#### 한줄 요약
- **PDP 판단•PEP 집행•HITL 승인** 후 도구 실행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **역할 기반 접근통제(Role-Based Access Control, RBAC)**: 직무 역할에 권한을 묶고 사용자나 에이전트에 역할을 할당하는 방식이다.
- **속성 기반 접근통제(Attribute-Based Access Control, ABAC)**: 주체•자원•행동•환경 속성을 정책으로 평가하여 접근을 결정하는 방식.

</details>

- 접근통제 모델별 비교

| 접근통제 | RBAC | ABAC |
|:---|:---|:---|
| 적용 기준 | 직무별 권한이 안정적일 때 | 상황별 동적 판단이 필요할 때 |
| 핵심 특징 | 역할에 권한 결합 | 주체•자원•환경 속성 평가 |
| 한계 | 역할 폭증•세밀성 부족 | 정책 복잡•판단 추적 부담 |

> 요약: 안정적 역할은 **RBAC**, 동적 속성 통제는 **ABAC** 적용

#### 한줄 요약
- **RBAC**•**ABAC** 기반 단일 도구와 조합 행동 통제

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **단기 자격증명(Short-term Credential)**: 작업이 끝나거나 정해진 시간이 지나면 자동 만료되어 권한 잔존을 줄이는 인증 정보.
- **권한 상승(Privilege Escalation)**: 허용된 여러 도구를 조합하여 본래 위임 범위를 넘는 행동이 가능해지는 현상.
- **책임 추적성(Accountability)**: 권한을 요청•판단•승인•실행한 주체와 결과를 연결하여 사후 책임을 확인하는 성질이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 장기 토큰에 따른 권한 잔존 | 작업별 단기 자격증명과 자동 만료 | 위임 종료 후 접근 차단 |
| 도구 조합에 따른 권한 상승 | 전체 행동 경로의 정책 평가 | 연쇄 호출의 우회 실행 방지 |
| 고위험 행동의 자동 실행 | 금액•대상•외부 전송별 HITL 요구 | 비가역적 부작용 통제 |
| 정책 결정의 책임 공백 | 책임 추적성을 위한 결정•결과 연결 | 권한 사용 추적성 확보 |

#### 한줄 요약
- **송신 권한•수신 도메인** 분리로 무단 전송 차단

## Ⅶ. 결론

- **기술 위상/발전**: 비결정론적 모델 실행을 제로 트러스트 기반 인가 및 PEP/PDP 구조로 통제하는 핵심 보안 표준으로 정착
- **실무 적용/통제**: RBAC/ABAC 하이브리드 정책, 단기 토큰(STS) 발급, 비가역 액션 사전 HITL 및 Egress 허용목록 통제 필수

#### 한줄 요약
- **권한 안정성•행동 위험도**에 따라 통제 방식 결정
