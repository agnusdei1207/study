## Ⅰ. 개요

- **정의**: 호스트 프로세서와 메모리 간의 대규모 데이터 이동을 최소화하기 위해 DRAM 뱅크 또는 버퍼 다이 내부에 연산 코어(ALU/MAC)를 직접 집적하여 제자리에서 데이터를 처리하는 컴퓨팅 기술
- **배경 및 필요성**: LLM 생성 토큰 디코딩, 추천 시스템 임베딩 룩업, 그래프 분석 등 메모리 집약적 워크로드는 연산 강도(FLOP/Byte)가 낮아 데이터 전송에 시스템 에너지의 70% 이상이 소모되는 폰 노이만 병목(Von Neumann Bottleneck)에 직면함에 따라, 메모리 내부의 초광폭 뱅크 레벨 병렬성(BLP)을 활용하여 내부 데이터 전송 대역폭을 극대화하고 에너지 낭비를 획기적으로 감축할 필요성 대두

## Ⅱ. 특징

- 메모리 셀-연산기 간 초단거리 내부 버스를 활용한 데이터 이동 전력 및 지연시간 극소화
- 수백~수천 개의 뱅크 내부 연산기 동시 가동을 통한 초광폭 뱅크 레벨 병렬성(Bank-level Parallelism)
- 기존 표준 DRAM 커맨드 시퀀스(FPK 명령어 등) 확장 및 호스트 메모리 인터페이스와의 호환성 유지

## Ⅲ. 구조 및 구성요소

```text
[PIM Architecture]
├── [호스트 제어 및 런타임 계층]
│   ├── [워크로드 분석기 (Workload Profiler)]
│   └── [PIM 커맨드 디스패처 (Command Dispatcher)]
├── [인메모리 연산 엔진 계층]
│   ├── [코어 DRAM 뱅크 배열 (DRAM Bank Arrays)]
│   └── [인뱅크 연산 블록 (In-Bank ALU/MAC Engine)]
└── [일관성 및 인터페이스 계층]
    ├── [내부 레지스터 및 버퍼 (Weight/Accumulator Buffer)]
    └── [호스트 메모리 버스 (CXL / HBM Interface)]
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 계층적 하위 관계를 의미함

| 구분 | 구성요소 | 기능 설명 |
|:---|:---|:---|
| 소프트웨어 스택 | 워크로드 분석기 | 연산 강도(Arithmetic Intensity)를 기반으로 호스트 연산과 PIM 오프로딩 대상을 분류 |
| 커맨드 제어 | 커맨드 디스패처 | 표준 메모리 제어 신호에 PIM 전용 연산 지시자(FPK 등)를 인코딩하여 DRAM으로 송출 |
| 저장 서브시스템 | DRAM 뱅크 배열 | 대용량 가중치 및 테이블 데이터를 저장하며 뱅크 단위 독립적 행(Row) 접근 보장 |
| 연산 가속기 | 인뱅크 ALU/MAC | 뱅크 I/O 라인에 직접 연결되어 16비트 부동소수점(FP16/Bfloat16) 벡터 곱셈·누산 고속 수행 |
| 데이터 전송 | 로컬 버퍼 및 CXL 버스 | 부분 누산(Partial Accumulation) 결과 임시 보관 및 CXL/메모리 채널을 통한 최종 축약값 반환 |

## Ⅳ. 흐름도

```text
[호스트 CPU/GPU] (① 연산 강도가 낮은 메모리 바운드 연산 식별 및 PIM 오프로딩 결정)
│
▼
[메모리 제어기] (② 표준 메모리 버스를 통해 PIM 제어 명령 및 오프로딩 매개변수 전송)
│
▼
[DRAM 뱅크 내부] (③ DRAM 셀 행 활성화(Activation) 후 내부 비트라인을 통해 텐서 데이터를 연산기로 공급)
│
▼
[인뱅크 MAC 유닛] (④ 호스트 전송 없이 뱅크 내부에서 벡터 내적, 원소별 덧셈 및 활성화 함수 병렬 연산)
│
▼
[호스트 버스 반환] (⑤ 수 테라바이트의 중간 데이터 대신 최종 축약(Reduction) 결과만 호스트로 전송)
```

- 분기 결과: 연산 강도가 임계값 미만인 경우 PIM 뱅크 병렬 경로를 실행하고, 연산 집약적 GEMM 유입 시 호스트 GPU 텐서 코어로 즉각 바이패스

## Ⅴ. 종류 및 비교

| 비교 항목 | 인뱅크 PIM (In-Bank PIM) | 버퍼다이 PNM (Processing-Near-Memory) | 범용 가속기 (GPU + HBM) |
|:---|:---|:---|:---|
| 연산기 위치 | 개별 DRAM 뱅크 내부 | HBM 베이스 다이 또는 CXL 컨트롤러 다이 | 분리된 호스트 GPU 다이 내부 |
| 내부 대역폭 | 극도로 높음 (뱅크 내부 수천 개 버스 활용) | 매우 높음 (다이 간 TSV/인터포저 대역폭) | HBM 인터페이스 대역폭에 제한됨 |
| 연산기 복잡도 | 극히 단순 (면적 제약으로 단순 ALU/MAC) | 중간 (RISC-V 코어 또는 전용 텐서 엔진 집적) | 극도로 복잡 (거대 SIMT 코어 및 텐서 코어) |
| 실리콘 공정 | DRAM 메모리 공정 (로직 집적 난이도 높음) | 표준 첨단 로직 공정 (TSMC/삼성 4nm 등) | 최첨단 고성능 로직 공정 |
| 적합 워크로드 | LLM 디코딩, 추천 임베딩 검색, 벡터 유사도 | 그래프 연산, 스파스 텐서, 조인(Join) 연산 | 대규모 모델 프리트레이닝, Dense GEMM |

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 호스트 CPU 캐시와 PIM 갱신 데이터 간 캐시 일관성(Coherence) 불일치 | PIM 전용 주소 영역을 Uncacheable 또는 CXL.mem 하드웨어 일관성 프로토콜 매핑 | 데이터 오염 방지 및 호스트-PIM 간 무결성 유지 |
| DRAM 공정 특성상 복잡한 로직 집적 시 면적 손실 및 메모리 용량 감소 | 연산 유닛을 뱅크 공유 방식으로 단순화하거나 3D 스택의 베이스 다이(PNM)로 분리 | 단위 웨이퍼당 메모리 용량 유지 및 공정 수율 확보 |
| 커스텀 PIM 컴파일러 및 프레임워크 부재로 인한 소프트웨어 개발 장벽 | PyTorch 런타임 확장 패키지 및 TVM 기반 자동 오프로딩 그래프 패스 도입 | 기존 딥러닝 애플리케이션 코드 수정 없이 PIM 가속 실현 |

## Ⅶ. 결론

- **기술 위상/발전**: 메모리와 프로세서가 분리된 전통적 폰 노이만 아키텍처의 한계를 탈피하여 메모리 자체가 연산기가 되는 인메모리 컴퓨팅의 시대를 열었으며, 최근 HBM-PIM, LPDDR-PIM 및 CXL 기반 PNM 솔루션과 결합되어 생성형 AI 추론 인프라의 TCO 절감 핵심 기술로 부상
- **실무 적용/통제**: 연산 집약적인 거대 행렬 곱셈(Dense GEMM)은 GPU 텐서 코어에 할당하고, 메모리 바운드 성격이 짙은 LLM KV 캐시 디코딩과 추천 시스템 임베딩 연산에 PIM/PNM을 집중 배치하는 이기종 계층형 하이브리드 파이프라인 구축 권장
