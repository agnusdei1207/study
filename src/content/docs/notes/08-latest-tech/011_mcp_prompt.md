## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **모델 컨텍스트 프로토콜 프롬프트(Model Context Protocol Prompt, MCP Prompt)**: 서버가 제공한 작업 양식에 사용자가 값을 채우고 검토한 뒤 모델에 전달하는 재사용 기능.
- **모델 컨텍스트 프로토콜(Model Context Protocol, MCP)**: 인공지능 애플리케이션과 외부 서버가 컨텍스트와 기능을 교환하는 표준 프로토콜.

</details>

- 정의: 서버 작업 양식을 사용자가 선택•검토해 모델에 전달하는 **MCP Prompt**
- 배경/필요성: 다양한 AI 호스트 애플리케이션에서 특정 업무(코드 리뷰, 번역, SQL 생성 등)에 최적화된 프롬프트 템플릿을 개별적으로 하드코딩할 경우, 비즈니스 변경 시마다 클라이언트를 매번 재배포해야 하고 비인가된 악성 프롬프트 주입(Prompt Injection)이 사용자 검토 없이 모델에 직접 주입되는 보안 위험이 발생함에 따라, 서버가 동적으로 매개변수화된 프롬프트 템플릿(prompts/list)과 완성된 메시지(prompts/get)를 제공하고 사용자가 이를 명시적으로 검토·승인하여 모델에 전달하는 MCP Prompt 메커니즘을 구축하여 **서버 중심의 표준 프롬프트 템플릿 재사용성 확보, 사용자 제어(User-in-the-Loop) 기반의 안전한 프롬프트 주입 통제 및 텍스트·이미지·임베디드 리소스가 결합된 복합 프롬프트 메시지 표준화**를 달성할 필요

#### 한줄 요약

- 사용자가 **작업 양식•인자**를 골라 전달하는 구조는 자동화 정도를 낮추는 대신, 서버가 보낸 지시가 사용자 확인을 건너뛰고 모델에 닿는 경로를 막는다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **사용자 제어(User-controlled)**: 프롬프트 선택과 모델 전달 여부를 사용자가 결정하는 제어 방식이다.
- **프롬프트 메시지(PromptMessage)**: 역할과 텍스트•이미지•내장 리소스 등의 콘텐츠를 묶은 메시지로 정의된다.
- **내장 리소스(Embedded Resource)**: 프롬프트 메시지 안에 직접 포함된 문서나 코드 같은 컨텍스트.

</details>

- **사용자 제어**: 템플릿 선택•모델 전달 여부 결정
- **생성 축**: 인자값으로 역할별 메시지 생성
- **프롬프트 메시지**: 역할•텍스트•이미지•리소스 구성

#### 한줄 요약

- 서버는 메시지 생성, 사용자는 **전달 여부 결정**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **프롬프트 기술자(Prompt Descriptor)**: 템플릿의 이름•설명과 입력할 인자 목록을 제공하는 구성요소이다.
- **인자 정의(Argument Definition)**: 템플릿에 채울 값의 이름•설명•필수 여부를 정한 계약.
- **콘텐츠 블록(Content Block)**: 프롬프트 메시지 안에서 텍스트•이미지•리소스를 구분해 담는 단위로 정의된다.
- **사용자 인터페이스(User Interface, UI)**: 사용자가 프롬프트를 탐색•입력•검토하는 클라이언트 화면.

</details>

```text
[MCP Prompt 템플릿 아키텍처]
├── [프롬프트 명세 (prompts/list)]
│   ├── 프롬프트 이름 및 설명
│   └── 인자(Arguments) 정의 (필수/선택)
├── [메시지 생성 (prompts/get)]
│   ├── 역할별 메시지 생성 (User/Assistant)
│   └── 복합 콘텐츠 블록 (Text/Image/Resource)
└── [클라이언트 UI 및 사용자 제어]
    ├── 인자 입력 UI 렌더링
    ├── 최종 프롬프트 사용자 검토 및 수정
    └── 모델 컨텍스트(Context) 주입 승인
```

- 선들의 의미: 실선(──)과 가지선(├──, └──)은 최상위 템플릿 아키텍처에서 프롬프트 명세, 메시지 생성, 클라이언트 제어로 이어지는 계층 구조를 나타냄

| 구성요소 | 책임 |
|:---|:---|
| 프롬프트 기술자 | 프롬프트 기술자 이름•설명과 인자 목록 제공 |
| 인자 정의 | 인자 정의 기반 인자명•설명•필수 여부 명시 |
| 프롬프트 메시지 | 역할별 콘텐츠 블록 구성 |
| 클라이언트 UI | UI 기반 탐색•입력•검토•전달 지원 |

#### 한줄 요약

- 서버는 **양식•인자 정의**, 클라이언트는 선택•검토

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **프롬프트 목록(prompts/list)**: 서버가 제공하는 프롬프트의 이름•설명•인자를 조회하는 요청이다.
- **프롬프트 조회(prompts/get)**: 프롬프트 이름과 인자를 보내 완성된 메시지를 받는 요청으로 정의된다.
- **모델 문맥(Model Context)**: 모델이 응답을 생성할 때 함께 참고하는 지시와 입력 정보로 정의된다.
- **사용자 승인(User Approval)**: 렌더링된 최종 프롬프트를 사람이 검토하고 전달 여부를 결정하는 통제 과정.

</details>

```text
[프롬프트 목록 요청] (① 클라이언트가 prompts/list 호출하여 사용 가능한 템플릿 계약 확인)
│
▼
[서버 템플릿 반환] (② 프롬프트 이름, 설명, 인자 정의 목록을 클라이언트에 응답)
│
▼
[사용자 인자 입력] (③ 클라이언트 UI가 양식을 렌더링하고 사용자가 필요한 파라미터 입력)
│
▼
[완성 메시지 요청] (④ 입력된 인자를 매개변수로 서버에 prompts/get 요청 전송)
│
▼
[서버 메시지 빌드] (⑤ 역할별 메시지와 텍스트·이미지·임베디드 리소스를 조합해 생성 반환)
│
▼
[사용자 검토 및 승인] (⑥ Human-in-the-loop 기반 최종 프롬프트 내용 확인 및 필요 시 수정)
│
▼
[모델 컨텍스트 주입] (⑦ 승인된 프롬프트 메시지만 LLM 추론 컨텍스트로 안전하게 전달)
```

- 분기 결과: 정상 승인 시 LLM 추론 실행, 검토 거부 또는 수정 요청 시 모델 전달 차단 및 파라미터 재입력

#### 한줄 요약

- **목록•완성 메시지 조회** 후 사용자 승인 메시지만 모델에 전달

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Resource**: 애플리케이션이 제공하고 모델이 문맥으로 읽는 데이터.
- **Tool**: 모델이 구조화된 인자로 호출해 외부 행동을 수행하는 기능.
- **Prompt**: 사용자가 선택해 작업 메시지와 입력 틀을 만드는 기능.
- **URI(Uniform Resource Identifier)**: 리소스를 식별하고 조회하는 주소.

</details>

- Resource•Tool 및 Prompt를 문맥•행동•작업 지시로 구분

| MCP 기능 | Resource | Tool | Prompt |
|:---|:---|:---|:---|
| 적용 기준 | Resource 기반 문맥 데이터 제공 | Tool 기반 외부 기능 실행 | Prompt 기반 작업 지시 틀 제공 |
| 핵심 특징 | 앱 제어•URI 조회 | 모델 제어•스키마 호출 | 사용자 제어•메시지 생성 |
| 한계 | 직접 행동 수행 불가 | 부작용•권한 위험 | 사용자 선택•입력 필요 |

> 요약: 문맥은 **Resource**, 행동은 **Tool**, 작업 지시는 **Prompt** 적용

#### 한줄 요약

- 문맥은 **Resource**, 행동은 **Tool**, 작업 틀은 Prompt

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **악성 지시(Malicious Instruction)**: 사용자의 의도와 달리 모델 행동을 바꾸려고 템플릿에 숨겨 넣은 명령이다.
- **마스킹(Masking)**: 비밀정보의 일부나 전부를 가려 노출을 제한하는 처리.
- **작업 재현성(Task Reproducibility)**: 같은 템플릿과 입력에서 일관된 작업 결과를 다시 얻을 수 있는 성질로 정의된다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 서버 템플릿의 악성 지시 혼입 | 출처 표시와 전달 전 전체 검토 | 비신뢰 지시의 모델 문맥 유입 차단 |
| 인자에 비밀정보를 넣는 정보 노출 | 인자별 민감도 설정 및 마스킹 | 템플릿 재사용 중 최소 정보 공개 |
| 템플릿 변경에 따른 결과 비일관성 | 버전 및 변경 이력 승인본 고정 | 여러 클라이언트의 작업 재현성 확보 |

#### 한줄 요약

- **작업 재현성**을 위한 출처•버전•민감 인자 관리

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **사용자 검토(User Review)**: 완성된 메시지의 출처와 인자값을 사람이 확인한 뒤 모델 전달을 승인하는 통제로 정의된다.

</details>

- **기술 위상/발전**: 서버 중심 프롬프트 템플릿 표준화 및 텍스트·임베디드 리소스 결합 인터페이스로 확고히 안착
- **실무 적용/통제**: 인자 정의 선언과 사용자 최종 검토(HITL) 및 템플릿 시맨틱 버전 관리를 결합한 거버넌스 수립 필수

#### 한줄 요약

- 반복 지시는 **Prompt**, 민감 인자는 **사용자 검토** 후 전달
