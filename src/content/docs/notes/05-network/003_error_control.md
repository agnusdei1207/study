## 답안 골격
```text
[오류제어] ◀━━ 머리: Ⅶ 내 의견 (망 지연 특성에 따른 ARQ·FEC 하이브리드 HARQ 적용)
 ┃
 ┣━ Ⅰ 개요 ───── 전송선로 잡음·왜곡 비트 오류 → 검출 부호화 및 복구 기제
 ┣━ Ⅱ 특징 ───── 무결성 보장, 신뢰성 제어, 잉여도(Redundancy) 오버헤드 절충
 ┣━ Ⅲ 구조 ───── 오류 검출(Parity·CRC·Checksum) + 오류 정정(ARQ·FEC·HARQ)
 ┣━ Ⅳ 흐름 ───── ① 송신측 검출부호 생성 → ② 전송 → ③ 수신측 검증 → ④ 패킷 수용 or 재전송 요청
 ┣━ Ⅴ 비교 ───── ARQ vs FEC (재전송 피드백 기반 vs 수신측 자체 정정 비트 부가)
 ┗━ Ⅵ 실무 ───── 고지연 위성망 재전송 지연 / 무선 채널 버스트 에러 / 프로세싱 부하
```
- 필수 키워드: 패리티 검사 · CRC · 체크섬 · 해밍 코드 · ARQ · FEC · HARQ
- 배점 전략: 10점 = Ⅰ → Ⅲ 분류 체계 표 → Ⅴ ARQ/FEC 비교 / 25점 = Ⅰ~Ⅶ, 138회 논술에 맞춰 검출 알고리즘과 복구 기제 상세 서술
- 기출: 107회 `오류 검출과 정정 기법 비교` → Ⅲ·Ⅴ, 138회 `신뢰성 전송을 위한 오류 제어 기술` → Ⅰ~Ⅵ

## 한 줄 본질
- 물리 전송 매체의 감쇠·잡음으로 발생하는 비트 오류 → 송신 데이터에 잉여 비트를 추가해 수신측 검출 후 재전송(ARQ)하거나 직접 복구(FEC) → 전송 신뢰성 확보 / 재전송 왕복 지연 시간 증가 또는 부호화 대역폭 손실

## 핵심 그림
```text
[ 오류 제어 체계 ]
           +-------------------------------+
           |     오류 제어 (Error Control)  |
           +---------------+---------------+
                           |
       +-------------------+-------------------+
       |                                       |
       v                                       v
[ 1. 오류 검출 (Detection) ]            [ 2. 오류 복구/정정 (Recovery) ]
- 패리티 검사 (1비트 오류)              - 역방향 오류 정정 (BEC / ARQ)
- 블록 합 검사 (2차원 패리티)            * Stop-and-Wait ARQ
- 검사합 (Checksum, 인터넷 L3/L4)        * Go-Back-N ARQ
- CRC (순환중복검사, 다항식 기반)        * Selective Repeat ARQ
                                       - 순방향 오류 정정 (FEC)
                                         * 해밍 코드 (단일 비트 정정)
                                         * 리드-솔로몬 (RS Code)
                                         * LDPC / Polar Code (5G/6G 채널)
                                       - 복합 방식 (HARQ: ARQ + FEC)
```

## 핵심 용어
- 해밍 거리(Hamming Distance): 두 부호어 사이에서 서로 다른 비트의 개수. 최소 해밍 거리 $d$에 대해 $d-1$개 검출, $\lfloor (d-1)/2 \rfloor$개 정정 가능
- CRC(Cyclic Redundancy Check): 생성 다항식을 이용해 2진 나눗셈의 나머지를 프레임 체크 시퀀스(FCS)로 붙여 집단 오류를 검출하는 L2 표준 기법
- FEC(Forward Error Correction): 수신측이 오류를 발견하면 송신측 재전송 요청 없이 자체 잉여 비트로 비트 오류를 직접 정정하는 기법

## 핵심 통찰
- 왕복 지연 시간(RTT)이 매우 긴 심우주·위성 통신 환경에서는 ARQ의 재전송 대기 비용이 치명적 → 대역폭 낭비를 감수하더라도 FEC 적용이 필수
- 유선 인터넷은 오류율이 매우 낮으므로($10^{-9}$ 이하) 오버헤드가 적은 단순 검출(CRC)과 상위 계층 재전송(TCP ARQ)의 조합이 전체 처리량에 유리
- 이동통신(LTE/5G)은 무선 채널 변동성이 심하므로 채널 상태가 좋을 때는 고속 ARQ, 나쁠 때는 FEC 정합 강도를 높이는 HARQ로 동적 균형 유지

## 이웃 토픽과 구분
- 오류제어 vs 흐름제어: 오류제어는 패킷 내용의 손상·유실 여부를 감지해 복구 / 흐름제어는 송수신측 처리 속도 차이로 인한 버퍼 오버플로를 방지

## 문제·원인·대책
- 적용 상황: 고속 무선 환경(도심 밀집 지역) 패킷 전송 손실
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 버스트 에러로 인한 반복 재전송 및 처리량 급감 | 다중 경로 페이딩 및 순시 전파 차단 | 인터리빙(Interleaving) 결합 및 HARQ Chace Combining 적용 | 연속 비트 오류를 분산시켜 FEC 정정 한계 내 흡수 |
| 고지연 링크에서 ARQ 대기 시간 폭증 | 긴 RTT 환경에서 Stop-and-Wait 동작 | 선택적 재전송(Selective Repeat) ARQ 및 대용량 윈도우 적용 | 오류 프레임만 단독 재전송하여 대역폭 효율성 보존 |

## 이렇게 출제된다
- 제107회 1교시: "데이터 통신의 오류 제어 방식 중 오류 검출 방식과 오류 정정 방식을 비교하여 설명하시오." → 요구 포인트: Ⅲ 분류 트리 + Ⅴ ARQ/FEC 비교표
- 제138회 4교시 4번: "데이터 통신에서 신뢰성 있는 전송을 보장하기 위한 오류 제어(Error Control) 기술에 대하여 다음 내용을 설명하시오." → 요구 포인트: Ⅰ~Ⅵ 전반 (검출 원리, ARQ 3종, FEC 기법, 5G HARQ)

## 내 의견
- [모바일 환경의 불필요한 TCP 레벨 재전송 중복] L2 무선 링크(MAC 계층) HARQ가 이미 오류를 복구 중인데 상위 TCP RTO 타이머가 먼저 만료되어 중복 재전송 발생 → 나라면: L2 링크 계층 재전송 타이머와 TCP RTO 간 인터랙션을 모니터링하고 BBR 혼잡제어처럼 손실이 아닌 RTT 기반 프로토콜을 도입해 불필요한 재전송 패킷 낭비 차단
