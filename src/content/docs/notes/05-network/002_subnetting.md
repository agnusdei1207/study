## 답안 골격
```text
[서브네팅] ◀━━ 머리: Ⅶ 내 의견 (CIDR·VLSM 기반 IP 주소 계획 및 자동 할당 도구 결합)
 ┃
 ┣━ Ⅰ 개요 ───── 클래스풀 주소 낭비·브로드캐스트 폭풍 → 호스트 비트 분할
 ┣━ Ⅱ 특징 ───── 브로드캐스트 도메인 격리, 보안성 강화, 주소 할당 효율화
 ┣━ Ⅲ 구조 ───── Network ID + Subnet ID (차용한 비트) + Host ID
 ┣━ Ⅳ 흐름 ───── ① 호스트 수 결정 → ② 필요 비트($2^n - 2$) 계산 → ③ 마스크 적용 및 대역 산출
 ┣━ Ⅴ 비교 ───── 서브네팅 vs 슈퍼네팅 (호스트 비트 차용 vs 네트워크 비트 병합)
 ┗━ Ⅵ 실무 ───── 고정 마스크로 인한 내부 단편화 / 주소 오할당 충돌 / 라우팅 엔트리 증가
```
- 필수 키워드: 서브넷 마스크 · CIDR · 호스트 비트 차용 · 브로드캐스트 도메인 · 유효 호스트 수($2^h - 2$) · VLSM
- 배점 전략: 10점 = Ⅰ → Ⅲ 비트 분할 도식 → Ⅳ 계산 수식 / 25점 = Ⅰ~Ⅶ, 139회 기출 계산 풀이 Ⅳ~Ⅵ에 상세 전개
- 기출: 130회 `클래스풀 한계와 서브네팅 원리` → Ⅰ·Ⅲ, 139회 `500명 대상 4개 VLSM 서브넷 계산` → Ⅳ·Ⅵ

## 한 줄 본질
- 클래스풀(Classful) IP 주소 체계의 대규모 주소 낭비와 브로드캐스트 과부하 → 호스트 ID 비트의 상위를 네트워크 영역으로 차용해 다수 소형 네트워크로 분할 → IP 활용률 극대화 / 서브넷마다 네트워크·브로드캐스트용 2개 주소 소모

## 핵심 그림
```text
기존 C 클래스 (24비트 Network, 8비트 Host):
[ Network ID (24비트)               ] [ Host ID (8비트)                  ]
 11111111 . 11111111 . 11111111     .  00000000   (255.255.255.0 /24)

서브네팅 적용 (/26, 2비트 차용 시 4개 서브넷 생성):
[ Network ID (24비트)               ] [ Subnet ID (2b) ] [ Host ID (6b)  ]
 11111111 . 11111111 . 11111111     .  11                000000  (255.255.255.192 /26)
                                       |
                                       +--> 서브넷 4개 생성 (00, 01, 10, 11)
                                            각 서브넷당 유효 호스트: 2^6 - 2 = 62개
```

## 핵심 용어
- 서브넷 마스크(Subnet Mask): 연속된 1의 비트로 네트워크 영역을 가리고 0의 비트로 호스트 영역을 구분하는 32비트 이진 마스크
- 유효 호스트 수: 호스트 비트 전부가 0(네트워크 식별자)인 주소와 전부가 1(브로드캐스트)인 주소를 제외한 실제 장비 할당 가능 주소 개수 ($2^h - 2$)
- CIDR(Classless Inter-Domain Routing): 클래스 경계를 없애고 `/N` 접두사 표기로 유연하게 라우팅 주소를 통합하거나 쪼개는 규격

## 핵심 통찰
- 서브넷을 잘게 쪼갤수록 브로드캐스트 트래픽 격리 효과는 상승 → 그러나 매 서브넷마다 버려지는 주소(네트워크 주소 1개 + 브로드캐스트 주소 1개 = 2개) 비율이 증가하는 트레이드오프 발생
- 단일 고정 서브넷 마스크(FLSM)는 부서별 인원 격차를 수용하지 못해 내부 단편화 초래 → 조직 규모별 가변 길이 서브넷 마스크(VLSM) 설계 필수
- 라우팅 관점에서 서브네팅은 내부 라우팅 테이블 크기를 키우므로 코어 라우터 경계에서는 다시 슈퍼네팅(요약 라우팅)으로 묶어야 성능 저하 방지

## 이웃 토픽과 구분
- 서브네팅 vs 슈퍼네팅: 서브네팅은 하나의 큰 네트워크를 쪼개 브로드캐스트를 축소 / 슈퍼네팅(CIDR 요약)은 여러 작은 블록을 묶어 라우팅 테이블 크기를 축소

## 문제·원인·대책
- 적용 상황: 139회 기출 500명 개발팀 대상 4개 서브넷 분할
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 단일 /23 대역 사용 시 ARP 브로드캐스트 폭증 | 500대 호스트가 단일 L2 도메인에 묶여 트래픽 경합 | /25 또는 /26 가변 서브넷(VLSM) 4개 분할 | L2 브로드캐스트 도메인 분리로 단말 간 패킷 간섭 억제 |
| 서브넷 간 비인가 접근 발생 | 평면 네트워크 구조로 경계 보안 통제 불가 | L3 스위치 서브넷 경계에 ACL 및 VLAN 정책 적용 | 개발·운영·테스트 환경 간 침해 사고 횡적 이동 차단 |
