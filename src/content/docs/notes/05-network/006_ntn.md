## 답안 골격
```text
[NTN] ◀━━ 머리: Ⅶ 내 의견 (3GPP Rel-17/18 준수 스마트폰-위성 직접 통신(D2D) 표준화 채택)
 ┃
 ┣━ Ⅰ 개요 ───── 지상망 커버리지 한계(국토 면적의 20%만 수용) → 비지상 우주·공중망 표준 통합
 ┣━ Ⅱ 특징 ───── 전 지구 광역 커버리지, 표준 5G NR 호환성, 재난 복원력, 초공간 3차원 확장
 ┣━ Ⅲ 구조 ───── 우주 플랫폼(GEO·LEO) + 공중 플랫폼(HAPS) + 게이트웨이(SAN) + 코어(5GC)
 ┣━ Ⅳ 흐름 ───── ① 단말 GNSS 동기화 → ② 위성 빔 스캔 및 접속 요청 → ③ 지상 관제국 코어망 인증
 ┣━ Ⅴ 비교 ───── 투명(Transparent) 위성 모드 vs 재생(Regenerative) 위성 모드
 ┗━ Ⅵ 실무 ───── 긴 RTT(20~500ms)로 인한 HARQ 타임아웃 / 고속 공전 도플러 천이 / 핸드오버 폭증
```
- 필수 키워드: 3GPP Rel-17 · 5G NR-NTN · 투명 페이로드 · 재생 페이로드 · 타이밍 어드밴스(TA) · 도플러 주파수 보상
- 배점 전략: 10점 = Ⅰ → Ⅲ 아키텍처 2개 모드 도식 → Ⅵ 지연/도플러 대책 / 25점 = Ⅰ~Ⅶ, 3GPP 표준 진화(Rel-17 IoT-NTN → Rel-18 NR-NTN) 비교
- 기출: 미출제. 3GPP 표준화 동향 및 6G 연계 25점 서술형 출제 유력

## 한 줄 본질
- 지구 표면의 80%에 달하는 해양·산간·공중 지역의 지상 기지국 부재 → 인공위성과 HAPS를 3GPP 5G NR 무선 인터페이스 규격으로 표준화하여 지상 코어망에 직결 → 전 지구적 통신 음영 해소 / 장거리 전파 전파 지연과 초고속 궤도 이동에 따른 도플러 주파수 천이 발생

## 핵심 그림
```text
[ 투명 페이로드 (Transparent, 구부러진 파이프) ]
  단말 (UE) <---(서비스 링크)---> LEO 위성 (RF 주파수만 변환/증폭)
                                       |
                                (피더 링크)
                                       v
                                지상 게이트웨이 + 지상 gNB 기지국 ---> 5G Core

[ 재생 페이로드 (Regenerative, 탑재 기지국) ]
  단말 (UE) <---(서비스 링크)---> LEO 위성 (gNB 기지국 직접 탑재, 온보드 처리)
                                       |
                                (ISL 레이저 링크)
                                       v
                                 인접 LEO 위성 ---> 지상 게이트웨이 ---> 5G Core
```

## 핵심 용어
- 투명 페이로드(Transparent Payload): 위성이 신호의 복조/복호화 없이 주파수 변환과 RF 증폭만 수행하여 지상 기지국으로 꺾어 전달하는 방식(Bent-pipe)
- 재생 페이로드(Regenerative Payload): 위성 본체에 5G 기지국(gNB) 및 L2/L3 스위치를 탑재해 위성 상공에서 직접 패킷을 복조·라우팅하는 방식
- 타이밍 어드밴스(Timing Advance, TA): 긴 전파 지연으로 인해 발생하는 상향링크 패킷 충돌을 막기 위해 단말이 송신 시점을 사전 앞당겨 쏘는 메커니즘

## 핵심 통찰
- 일반 5G NR의 물리 계층 타이머를 그대로 위성에 적용하면 HARQ 피드백 대기 시간이 초과되어 전체 연결 단절 → 3GPP Rel-17에서 NTN 전용 타이머 확장 및 HARQ 프로세스 수 증설 규격화
- 위성 탑재체의 중량·전력 제약(SWaP)으로 인해 초기 상용망은 투명(Transparent) 모드로 출발하되, 향후 위성 간 레이저 링크(ISL)를 갖춘 재생형 기지국 탑재 모델로 전이
- 지상 단말의 GPS(GNSS) 위치 정보를 활용해 단말 스스로 궤도 이동 위성과의 상대 속도를 계산하고 도플러 주파수 편차를 사전 보상(Pre-compensation)

## 이웃 토픽과 구분
- NTN vs SATIN: NTN은 3GPP 표준화 기구에서 정의한 비지상 무선망 기술 규격 명칭 / SATIN은 위성·공중·지상을 하나의 메쉬망으로 묶는 네트워크 계층 아키텍처 모델

## 문제·원인·대책
- 적용 상황: 저궤도 위성(고도 600km) 통신 접속 시 상향링크 패킷 동기화 실패
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 상향링크 프레임 충돌 및 수신 오류 | 위성-단말 간 수천 km 거리에 따른 긴 전파 지연 차이 | GNSS 기반 공통 및 개별 타이밍 어드밴스(TA) 사전 적용 | 기지국 수신 윈도우 내 상향링크 슬롯 정렬 완성 |
| 반송파 주파수 오차로 복조 실패 | 저궤도 위성의 초속 7.5km 공전에 의한 심각한 도플러 편차 | 궤도력(Ephemeris) 데이터 기반 주파수 옵셋 사전 천이 계산 | 기지국 수신 주파수 대역 내 안정적 튜닝 유지 |
