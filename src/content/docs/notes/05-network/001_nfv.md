## 답안 골격
```text
[NFV] ◀━━ 머리: Ⅶ 내 의견 (DPDK·SR-IOV 가속 기반 단계적 VNF 전환)
 ┃
 ┣━ Ⅰ 개요 ───── 전용 어플라이언스 종속·고비용 → COTS 서버 위 SW 인스턴스화
 ┣━ Ⅱ 특징 ───── CapEx·OpEx 절감, 탄력적 오케스트레이션, 표준 x86 범용성
 ┣━ Ⅲ 구조 ───── NFVI(컴퓨트·스토리지·네트워크) + VNF + MANO(NFVO·VNFM·VIM)
 ┣━ Ⅳ 흐름 ───── ① 템플릿 정의(VNFD) → ② VIM 자원 할당 → ③ 인스턴스 기동 및 서비스 체이닝
 ┣━ Ⅴ 비교 ───── NFV vs SDN (기능 소프트웨어화 vs 제어·데이터 평면 분리)
 ┗━ Ⅵ 실무 ───── I/O 성능 저하 / 단일 장애점(SPOF) / 레거시 연동 규격
```
- 필수 키워드: NFVI · VNF · MANO · NFVO · VNFM · VIM · 서비스 체이닝
- 배점 전략: 10점 = Ⅰ → Ⅲ 아키텍처 다이어그램 → Ⅵ 한 행 / 25점 = Ⅰ~Ⅶ, 앞 1/3에 MANO 구조 명시
- 기출: 120회·126회 `아키텍처 및 구성요소` → Ⅲ, 133회 `5G 특화망 인프라 고려사항` → Ⅵ

## 한 줄 본질
- 전용 통신 하드웨어 증설의 고비용과 배포 지연 → x86 범용 서버 가상화 계층 위에 라우터·방화벽 기능을 소프트웨어로 구동 → 인프라 민첩성 확보 / 가상화 오버헤드로 인한 패킷 처리 지연 발생

## 핵심 용어
- MANO(Management and Orchestration): 가상 자원 할당부터 서비스 체인 라이프사이클까지 전 주기를 제어하는 관제 중추
- VIM(Virtualized Infrastructure Manager): OpenStack·Kubernetes처럼 NFVI의 물리·가상 컴퓨팅·스토리지·네트워크 자원을 직접 할당하는 모듈
- SFC(Service Function Chaining): 방화벽→DPI→라우터 순서로 패킷이 가상 기능을 거치도록 트래픽 경로를 프로그래밍하는 기법

## 핵심 통찰
- 전용 박스 교체 주기(3~5년)를 소프트웨어 패치 배포 주기(수 분~수 일)로 단축 → 하드웨어 투자(CapEx) 중심에서 운영비용(OpEx) 최적화로 체질 전환
- 일반 커널 네트워크 스택을 그대로 쓰면 패킷 복사 오버헤드로 통신사 요구 100Gbps 회선 처리 불가 → DPDK 및 SR-IOV 커널 바이패스 필수 수반
- SDN과 NFV는 상호 의존적이지 않으나 결합 시 파급력 극대화 → NFV로 기능을 띄우고 SDN으로 기능 간 트래픽 체인 경로를 제어

## 이웃 토픽과 구분
- NFV vs SDN: NFV는 네트워크 장비(기능)를 소프트웨어로 전환 / SDN은 네트워크 제어권(Control Plane)과 데이터 전달(Data Plane)을 분리

## 문제·원인·대책
- 적용 상황: 통신사 vEPC 코어망 구축 시 패킷 처리 성능 저하
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 패킷 인터럽트 과다로 CPU 포화 | 커널 스페이스 콘텍스트 스위칭 및 메모리 복사 발생 | DPDK(Data Plane Development Kit) 폴링 드라이버 적용 | 유저 영역 제로 카피로 초당 수천만 패킷 처리 보장 |
| 가상화 NIC I/O 병목 | 하이퍼바이저 가상 스위치 에뮬레이션 지연 | SR-IOV(Single Root I/O Virtualization) 하드웨어 직결 | 물리 NIC 대역폭 전송 지연을 베어메탈 수준으로 단축 |

## 내 의견
- [통신사 VNF의 CNF(Containerized Network Function) 진화] 가상머신 기반 VNF는 무거운 OS 이미지로 인해 장애 복구 및 오케스트레이션 기동 시간이 수 분 소요 → 나라면: 마이크로서비스 구조의 경량 컨테이너(CNF)로 단계적 리팩토링을 수행하고, K8s 기반 CNI 플러그인과 하드웨어 오프로딩 카드를 결합해 기동 시간을 초 단위로 단축하여 고가용성 확보
