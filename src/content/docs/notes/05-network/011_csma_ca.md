## 답안 골격
```text
[CSMA/CA] ◀━━ 머리: Ⅶ 내 의견 (OFDMA 스케줄링 전환으로 밀집 환경 CSMA/CA 경합 병목 극복)
 ┃
 ┣━ Ⅰ 개요 ───── 무선 반이중 특성상 충돌 감지(CD) 불가 → 충돌 회피(Collision Avoidance) 채택
 ┣━ Ⅱ 특징 ───── 반송파 감지, IFS(Inter-Frame Space) 대기, 랜덤 백오프 슬롯, RTS/CTS 제어
 ┣━ Ⅲ 구조 ───── 물리적 감지(CCA) + 가상 감지(NAV) + 시간 간격(SIFS/PIFS/DIFS) + Contention Window
 ┣━ Ⅳ 흐름 ───── ① DIFS 유휴 확인 → ② 랜덤 백오프 카운트다운 → ③ RTS 전송 → ④ CTS 수신 후 데이터 송신
 ┣━ Ⅴ 비교 ───── CSMA/CD vs CSMA/CA (유선 이더넷 충돌 즉시 중단 vs 무선 충돌 사전 회피)
 ┗━ Ⅵ 실무 ───── 숨은 노드(Hidden Node) 문제 / 노출 노드(Exposed Node) 문제 / 백오프 지연
```
- 필수 키워드: 반송파 감지 · IFS(DIFS/SIFS) · 랜덤 백오프 · NAV(가상 반송파 감지) · RTS/CTS · 숨은 노드
- 배점 전략: 10점 = Ⅰ → Ⅲ 타이밍 다이어그램(DIFS, 백오프, SIFS, ACK) → Ⅴ CSMA/CD 대조 / 25점 = Ⅰ~Ⅶ, 140회 3교시 4번 무선 3종 프로토콜(가. CSMA/CA) 비교 전개

## 한 줄 본질
- 자신의 송신 신호 세기가 수신 신호보다 수만 배 강해 무선 환경에서는 전송 중 충돌 감지가 불가능한 한계 → 매체가 비었더라도 DIFS 시간과 무작위 백오프를 대기하고 RTS/CTS로 채널을 사전 예약 → 패킷 충돌 손실 최소화 / 제어 프레임 오버헤드와 경합 대기 시간 증가

## 핵심 그림
```text
매체 상태 (Busy)       DIFS     Contention Window (랜덤 백오프)
==============+-----+--------+-----+-----+-----+-----+
              | 감지| 대기   |Slot1|Slot2|Slot3|Slot4| ===> 데이터 전송 시작!
==============+-----+--------+-----+-----+-----+-----+

[ RTS / CTS 핸드셰이크 흐름 (숨은 노드 해결) ]
송신 단말 A            수신 AP B            인접 단말 C (숨은 노드)
    |                      |                      |
    |---- RTS 전송 ------->|                      | (RTS 미도달)
    |                      |---- CTS 브로드캐스트-->| (CTS 수신!)
    |                      |                      | [ NAV 설정: 전송 억제 ]
    |<--- SIFS 대기 후 ----|                      |
    |==== DATA 전송 ======>|                      |
    |<=== SIFS + ACK ======|                      |
    |                      |                      |
```

## 핵심 용어
- 숨은 노드 문제(Hidden Node Problem): 서로 전파가 닿지 않는 두 단말이 동시에 같은 수신 AP로 데이터를 전송하여 AP 위치에서 패킷 충돌이 발생하는 현상
- RTS/CTS(Request/Clear to Send): 송신측이 채널 예약 요청(RTS)을 보내고 수신측이 승인 응답(CTS)을 브로드캐스트하여 주변 모든 단말의 송신을 잠재우는 4방향 핸드셰이크
- NAV(Network Allocation Vector): CTS 프레임에 적힌 전송 예정 시간을 수신한 다른 단말들이 카운터를 설정하고 그 시간 동안 채널이 사용 중인 것으로 간주하는 가상 반송파 감지 기제

## 핵심 통찰
- CSMA/CD(유선)는 "말하면서 귀를 열어 충돌 즉시 멈춤"이지만, CSMA/CA(무선)는 "충돌을 들을 수 없으므로 무조건 조심스럽게 속삭이고 기다림"
- RTS/CTS는 숨은 노드 충돌을 완벽히 방지하지만, 작은 크기의 패킷(수십 바이트 IoT)에서는 배보다 배꼽이 큰 심각한 대역폭 낭비 초래 → 임계값(RTS Threshold) 이상의 대형 패킷에만 선택 적용
- 단말 수가 급증하는 밀집 환경에서는 백오프 충돌 확률이 기하급수적으로 증가하여 전체 무선 처리량이 바닥으로 추락 → Wi-Fi 6의 결정론적 OFDMA 스케줄링 도입의 직접적 배경

## 이웃 토픽과 구분
- CSMA/CD vs CSMA/CA: CSMA/CD는 유선 이더넷(802.3)에서 전압 변화로 충돌을 감지해 Jam 신호 발송 / CSMA/CA는 무선랜(802.11)에서 사전 대기와 ACK 확인으로 충돌을 회피

## 문제·원인·대책
- 적용 상황: 대규모 회의실 무선랜 단말 밀집 시 접속 먹통 현상
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 단말 수 증가 시 무선 처리량 급감 | CSMA/CA 백오프 충돌로 경합 윈도우(CW) 지수 증가 및 대기 무한 반복 | Wi-Fi 6/7 OFDMA 기반 AP 중앙 스케줄링 전환 | 무작위 경합을 제거하고 서브캐리어 직교 분할 전송 |
| 숨은 노드로 인한 연속 패킷 유실 | 벽체·기둥으로 인해 단말 상호 간 전파 차폐 발생 | RTS/CTS Threshold 하향 조정 및 파워 컨트롤 최적화 | 가상 캐리어 센싱(NAV) 강제로 AP 수신 충돌 차단 |

## 내 의견
- [무분별한 RTS/CTS 활성화의 트래픽 병목] 현장 엔지니어가 패킷 유실을 막으려고 RTS Threshold를 너무 낮춰 설정하면 제어 패킷이 공중을 장악해 전체 속도 저하 → 나라면: 전파 분석 도구로 패킷 재전송률을 실시간 계측하여 재전송률이 15%를 초과하는 고밀도 AP에만 동적으로 RTS 임계값을 적용하고, 일반 구역은 비활성화하여 오버헤드 최소화
