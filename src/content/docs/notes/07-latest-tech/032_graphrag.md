## 답안 골격
```text
[GraphRAG] ◀━━ 머리: Ⅶ 내 의견 (벡터 검색과 지식 그래프 커뮤니티 요약을 결합한 하이브리드 RAG 아키텍처)
 ┃
 ┣━ Ⅰ 개요 ───── 청크 기반 벡터 검색의 전역 요약 불가 한계 → 지식 그래프(KG) 기반 다단계 관계 추론 및 전역 질의 해결
 ┣━ Ⅱ 특징 ───── 전역 질의(Global Search) 지원 · 지식 그래프 기반 다단계 추론(Multi-hop) · 계층적 커뮤니티 요약
 ┣━ Ⅲ 구조 ───── 엔티티/관계 추출기 + 지식 그래프(KG) + 커뮤니티 탐지(Leiden) + 계층 요약 생성기 + 쿼리 엔진
 ┣━ Ⅳ 흐름 ───── ① 텍스트 엔티티/관계 추출 → ② 그래프 군집화(Leiden) → ③ 커뮤니티별 계층 요약 → ④ 전역/국소 쿼리 라우팅
 ┣━ Ⅴ 비교 ───── 전통 벡터 RAG(Baseline RAG) vs GraphRAG (국소 키워드 매칭 vs 구조화된 전역 관계망 분석)
 ┗━ Ⅵ 실무 ───── 그래프 구축 시 LLM 추출 비용 폭증 / 빈번한 데이터 업데이트 시 그래프 재구축 부하
```
- 필수 키워드: 지식 그래프(Knowledge Graph) · 엔티티/관계 추출 · Leiden 알고리즘 · 커뮤니티 요약 · Global Search · Local Search
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 지식 그래프 인덱싱 파이프라인 구조도 → Ⅴ 전통 RAG vs GraphRAG 비교 / 25점 = Ⅰ~Ⅶ 전개, 커뮤니티 탐지 메커니즘과 Global vs Local 쿼리 차별화 집중
- 기출: 미출제. 예상: "기존 벡터 검색 기반 RAG의 한계를 극복하기 위해 등장한 GraphRAG의 개념, 지식 그래프 구축 파이프라인, 그리고 Global Search와 Local Search 동작 방식을 설명하시오."

## 한 줄 본질
- 벡터 유사도 검색만으로는 전체 데이터셋을 아우르는 거시적 주제 파악과 복합 연결 관계 추적 불가 → 엔티티와 관계를 지식 그래프로 추출하고 군집별 커뮤니티 요약을 계층화 → 전역적(Global) 거시 질문과 다단계 추론 완벽 지원 / 그래프 추출 시 막대한 LLM 토큰 비용 수반

## 핵심 그림
```text
[GraphRAG 인덱싱 및 2대 검색 아키텍처]
[ 원시 문서 청크 ]
        |
        v  (LLM 엔티티 및 관계 추출)
[ 지식 그래프 (Knowledge Graph) ]
        |
        v  (Leiden 알고리즘 커뮤니티 탐지)
[ 계층적 커뮤니티 요약 (Community Summaries) ]
        |
        +-----------------------------------+
        |                                   |
        v (전역 질의: "전체 테마 요약")      v (국소 질의: "A와 B의 관계")
[ Global Search ]                   [ Local Search ]
- 커뮤니티 요약 대상 Map-Reduce     - 특정 엔티티 주변 서브그래프 및 청크 검색
- 종합적 거시 인사이트 도출          - 정밀한 사실 관계 추적
```

## 핵심 용어
- Leiden 알고리즘: 대규모 네트워크 그래프에서 상호 연결 밀도가 높은 노드 그룹을 계층적으로 빠르고 정확하게 찾아내는 최신 커뮤니티 탐지 알고리즘
- Global Search: 특정 키워드와 직접적인 텍스트 유사도가 없더라도, 사전 생성된 계층적 커뮤니티 요약본들을 Map-Reduce 기법으로 종합하여 코퍼스 전체의 주제를 답하는 방식
- Local Search: 질문 속 특정 인물, 제품 등의 엔티티를 포착하여 그와 직접 연결된 이웃 노드와 원본 청크를 결합해 상세한 팩트를 추적하는 방식

## 핵심 통찰
- 전통 벡터 RAG에 "이 소설 전체의 핵심 갈등 요인이 무엇인가?"를 물으면 몇 개 챕터의 파편 청크만 주워와 엉뚱한 답변을 하지만, GraphRAG는 전체 커뮤니티 요약을 취합해 완벽히 답변
- GraphRAG의 최대 병목은 검색이 아니라 "초기 그래프 인덱싱 비용" → 모든 문장에서 엔티티와 관계를 LLM으로 파싱해야 하므로 초기 토큰 비용이 벡터 임베딩 대비 수십 배 이상 소요
- 자주 변경되는 실시간 트랜잭션 데이터보다는 규정집, 사내 기술 문서, 소송 판례 등 정적이고 관계가 얽힌 지식 베이스에 가장 이상적

## 이웃 토픽과 구분
- GraphRAG vs 전통 Vector RAG: 전통 RAG는 텍스트를 청크 단위로 잘라 임베딩 공간의 거리를 측정(단편적) / GraphRAG는 개념 간의 유기적 관계망을 그래프 토폴로지로 구조화하여 전역 질의 지원

## 문제·원인·대책
- 적용 상황: 수만 건의 제약 바이오 논문 코퍼스에서 화합물 간 부작용 관계 종합 분석
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 전체 논문을 관통하는 부작용 테마 질의 실패 | 전통 벡터 RAG의 국소 유사도 검색 한계 | GraphRAG Global Search(커뮤니티 요약 Map-Reduce) 적용 | 전역적 주제 종합 분석 답변 성공 |
| 초기 그래프 구축 시 토큰 비용 수천만 원 발생 | 모든 청크마다 고비용 상용 LLM으로 엔티티 추출 수행 | 엔티티 추출 전용 경량 sLM(Fine-tuned 8B)으로 전처리 오프로딩 | 그래프 인덱싱 비용 80% 절감 |
| 동일 엔티티의 이름 표기 차이로 노드 파편화 | "삼성전자", "SEC", "Samsung" 등 동의어 처리 부재 | 엔티티 해소(Entity Resolution) 및 정규화 파이프라인 결합 | 지식 그래프 내 중복 노드 통합 및 연결성 복원 |

## 이렇게 출제된다
- 미출제. 예상: "기존 RAG의 전역 정보 검색 한계를 극복하기 위한 GraphRAG의 구조와 작동 원리를 설명하시오." → 요구 포인트: Ⅰ 기존 RAG 한계 + Ⅲ 지식 그래프/Leiden 커뮤니티 탐지 + Ⅳ Global vs Local Search
