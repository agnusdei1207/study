## 답안 골격
```text
[CRAG] ◀━━ 머리: Ⅶ 내 의견 (검색 품질 평가 기반의 동적 폴백과 지식 정제로 RAG의 저품질 문서 오염을 차단하는 자가 교정 프레임워크)
 ┃
 ┣━ Ⅰ 개요 ───── 전통적 RAG의 저품질/무관 문서 검색 시 생성 모델의 환각 증폭 → 검색 적합도 평가 및 외부 웹 폴백을 결합한 교정형 RAG
 ┣━ Ⅱ 특징 ───── 검색 평가자(Retrieval Evaluator) · 3단계 신뢰도 판정(Correct/Incorrect/Ambiguous) · 지식 정제(Refinement) · 웹 검색 보정
 ┣━ Ⅲ 구조 ───── 경량 검색 평가자(Evaluator) + 지식 분해/필터링 모듈(Knowledge Strips) + 웹 검색기(Web Search) + 생성 모델(LLM)
 ┣━ Ⅳ 흐름 ───── ① 문서 검색 → ② 적합도 채점(Correct/Incorrect/Ambiguous) → ③ 올바름: 정제 후 생성 / 틀림: 웹 검색 대체 / 모호: 결합 보정 → ④ 최종 생성
 ┣━ Ⅴ 비교 ───── Naive RAG vs Self-RAG vs CRAG (무조건 생성 vs 토큰별 반성 토큰 vs 검색 품질 평가 및 외부 검색 폴백)
 ┗━ Ⅵ 실무 ───── 평가기 추론 지연시간 추가 / 외부 웹 검색 API 비용 및 레이턴시 / 지식 조각 분해 시 문맥 손실
```
- 필수 키워드: CRAG(Corrective RAG) · 검색 평가자(Retrieval Evaluator) · 3단계 신뢰도 판정 · 지식 정제(Knowledge Refinement) · 웹 검색 폴백 · 환각 방지
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ CRAG 평가 및 교정 파이프라인 흐름도 → Ⅴ RAG 진화 모델 비교표 / 25점 = Ⅰ~Ⅶ 전개, 검색 신뢰도 3단계 분기 로직 및 Knowledge Strip 정제 알고리즘 집중
- 기출: 미출제. 예상: "검색 증강 생성(RAG)의 검색 품질 한계를 극복하기 위한 Corrective RAG(CRAG)의 개념, 동작 매커니즘 및 기존 RAG 대비 차별점을 설명하시오." → Ⅰ~Ⅶ

## 한 줄 본질
- 검색기가 엉뚱한 문서를 가져오면 생성 모델이 이를 맹신하여 정교한 거짓말을 만들어냄 → 경량 평가기가 검색 문서의 적합도를 채점하여 올바르면 노이즈를 깎아내고, 틀리면 과감히 버린 뒤 웹 검색으로 대체 → RAG 환각 대폭 억제 / 검색 평가 단계 추가로 인한 종단 간 지연 증가

## 핵심 그림
```text
[CRAG(Corrective RAG)의 3단계 신뢰도 평가 및 동적 교정 분기]

                  [사용자 질의 (Query)]
                            │
                            ▼
                    [문서 검색 (Retrieval)]
                            │
                            ▼
              ┌─────────────────────────────┐
              │ 검색 평가자 (Evaluator)     │
              │  - 적합도 점수 계산         │
              └──────────────┬──────────────┘
                             │
         ┌───────────────────┼───────────────────┐
         ▼ (신뢰도 높음)      ▼ (신뢰도 모호)      ▼ (신뢰도 낮음)
    [Correct]           [Ambiguous]          [Incorrect]
         │                   │                   │
         ▼                   ▼                   ▼
  [지식 조각 정제]    [정제 지식 + 웹 검색]   [검색 문서 폐기 후]
  (노이즈 문장 제거)  (내외부 지식 결합)      [외부 웹 검색 수행]
         │                   │                   │
         └───────────────────┼───────────────────┘
                             │
                             ▼
                    [LLM 최종 답변 생성]
```

## 핵심 용어
- 검색 평가자(Retrieval Evaluator): 훈련된 경량 언어 모델(T5 등)을 사용하여 검색된 각 문서가 사용자 질문에 실제로 답을 제공할 수 있는지 0과 1 사이의 신뢰도 점수를 부여하는 컴포넌트
- 지식 스트립(Knowledge Strips): 검색된 긴 문서를 문장 단위의 미세 조각으로 쪼갠 뒤, 질문과 관련 없는 서론이나 노이즈 문장을 잘라내어 알짜 정보만 남기는 정제 기법
- 웹 폴백(Web Search Fallback): 사내 지식 베이스 검색 결과가 완전히 틀렸다고 판정된 경우, 모델 생성을 중단하고 공용 검색 엔진(Google/Bing API)으로 전환하여 최신 사실을 확보하는 메커니즘

## 핵심 통찰
- "잘못된 정보를 주는 것은 정보를 아예 안 주는 것보다 나쁘다": CRAG의 철학은 검색 결과가 틀렸을 때 이를 LLM에 억지로 집어넣지 않고 과감하게 폐기(Discard)하는 데 있음
- 문서 전체를 프롬프트에 넣지 않고 "정제(Refinement)"하는 이유: 검색된 문서 안에도 정답과 무관한 노이즈 문장이 70% 이상 포함되어 있으며, 이 노이즈가 LLM의 주의(Attention)를 분산시켜 환각을 유발함
- Self-RAG와의 차이점: Self-RAG는 LLM 자체를 파인튜닝하여 특수 반성 토큰을 출력하게 하므로 모델 종속적이지만, CRAG는 외부에 플러그인 가능한 평가 모듈을 두어 상용 LLM(GPT-4 등)과 자유롭게 결합 가능

## 이웃 토픽과 구분
- CRAG vs Self-RAG: CRAG는 검색 평가자가 문서를 평가하고 웹 검색으로 교정 / Self-RAG는 모델 내부 반성 토큰([Retrieve], [IsRel])을 통해 능동적 검색과 생성을 통제

## 문제·원인·대책
- 적용 상황: 고객 기술 지원 Q&A 시스템에서 비정형 매뉴얼 검색 시 오답 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 검색기가 질문 키워드만 겹치고 내용이 완전히 다른 구버전 매뉴얼을 반환 | 어휘 유사도 기반 검색의 의미 파악 실패 | CRAG 평가기를 도입하여 신뢰도 임계값 미달 시 문서 폐기 및 대체 질의 재생성 | 무관 문서 기반 오답 생성 92% 차단 |
| 지식 스트립으로 분해하는 과정에서 대명사("그것")가 앞 문맥과 끊겨 의미 왜곡 | 무조건적인 문장 단위 하드 컷 분할 | 상호참조해결(Coreference Resolution) 적용 및 3문장 슬라이딩 윈도우 정제 | 지식 파편화로 인한 오독 방지 |
| 평가기 추론과 웹 검색이 중첩되면서 전체 응답 지연시간이 3초 이상 증가 | 모든 문서에 대해 무거운 평가 모델을 직렬 실행 | 양자화된 초경량 교차 엔코더(Cross-Encoder) 비동기 병렬 평가 적용 | 평가 레이턴시를 100ms 이내로 단축 |

## 이렇게 출제된다
- 미출제. 예상: "검색 증강 생성(RAG) 환경에서 저품질 검색 문서로 인한 환각을 방지하기 위한 Corrective RAG(CRAG)의 구조, 3단계 평가 분기 및 지식 정제 방안을 설명하시오." → 요구 포인트: Ⅰ 기존 RAG 한계 + Ⅲ CRAG 분기 메커니즘 + Ⅴ Naive RAG 대비 이점

## 내 의견
- [엔터프라이즈 환경에 맞춘 보안 격리형 CRAG 파이프라인 구성] 일반 웹 검색 폴백은 사내 기밀 질문이 외부 상용 검색 엔진으로 유출될 수 있는 치명적 보안 위반을 야기함 → 나라면: 신뢰도 평가 결과 'Incorrect' 판정 시 외부 공용 웹 검색으로 나가지 않고, 사내 백업 데이터웨어하우스(DW)에 대한 SQL 생성 쿼리 또는 담당 부서 에이전트 티켓팅으로 라우팅하는 'Closed-Loop CRAG' 보안 정책을 수립
