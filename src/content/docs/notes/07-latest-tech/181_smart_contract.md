## 핵심 용어
- EVM(Ethereum Virtual Machine): 이더리움 블록체인에 배포된 스마트 컨트랙트 바이트코드를 모든 풀 노드에서 동일한 결과로 실행하도록 격리된 튜링 완전(Turing-complete) 가상머신
- 가스(Gas): 스마트 컨트랙트 실행 시 소모되는 연산 자원(CPU, 메모리, 스토리지)에 부과되는 실행 수수료로, 악의적인 무한 루프(DDoS) 공격을 방지하는 안전장치
- 오라클 문제(Oracle Problem): 스마트 컨트랙트는 블록체인 외부(오프체인)의 현실 세계 데이터(환율, 날씨, 스포츠 결과)를 스스로 읽어올 수 없으며, 데이터를 외부에서 주입할 때 그 출처의 조작 위험이 발생하는 난제

## 핵심 통찰
- "신뢰가 필요 없는 신뢰(Trustless Trust)의 실현": 계약 상대방이 사기를 칠지 말지 고민할 필요 없이, 코드가 모든 노드에서 강제로 실행되므로 중개 기관의 개입 비용과 사기 리스크를 0으로 만듦
- 튜링 완전성과 가스(Gas) 메커니즘의 천재적 결합: 반복문(Loop)을 허용하는 순간 정지 문제(Halting Problem)로 인해 악의적 무한 루프 공격이 가능해지나, 바이트코드 연산마다 가스를 소모시켜 가스가 바닥나면 즉시 트랜잭션을 중단(Revert)시킴
- 불변성(Immutability)의 치명적 독: 배포된 코드는 절대 수정할 수 없으므로, 코드에 1줄의 버그(The DAO 해킹 사건)만 있어도 해커가 수백억 원을 탈취해가는 것을 뻔히 보면서도 코드를 고치지 못하는 딜레마 발생

## 이웃 토픽과 구분
- 비트코인 스크립트 vs 이더리움 스마트 계약: 비트코인은 단순 서명 검증 위주의 튜링 불완전(Non-Turing complete, Loop 불가) 스크립트 / 이더리움은 튜링 완전 언어(Solidity)를 지원하여 임의의 복잡한 비즈니스 로직(DeFi, DAO) 구현 가능

## 문제·원인·대책
- 적용 상황: 글로벌 항공 지연 여행자 보험 스마트 컨트랙트 자동 보상 플랫폼 구축
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 배포된 보험 컨트랙트에서 치명적 자금 인출 취약점 발견 시 핫픽스 패치 불가 | 블록체인 코드의 영구 불변성(Immutability) 특성 | 프록시 패턴(Upgradeable Proxy: ERC-1967) 적용을 통한 로직 컨트랙트 분리 업그레이드 | 무중단 컨트랙트 보안 패치 지원 |
| 단일 기상청 API 서버 해킹으로 허위 결항 정보를 스마트 컨트랙트에 입력 | 중앙 집중형 단일 오라클(Oracle) 데이터 소스의 위변조 취약성 | 체인링크 탈중앙 오라클 네트워크(DON) 기반 다중 노드 데이터 수집 및 중간값 합의 | 데이터 위변조 위험 원천 차단 |
| 계약 실행 함수를 재귀 호출하여 보험 보상금을 중복 수령하는 재진입 공격 발생 | 상태 변수(지급 완료) 변경 전에 송금 함수를 먼저 호출하는 코딩 결함 | Checks-Effects-Interactions 패턴 준수 및 ReentrancyGuard 뮤텍스 락 적용 | 중복 탈취 취약점 100% 방어 |

## 내 의견
- [형식 검증(Formal Verification)을 통한 스마트 컨트랙트 수학적 무결성 증명 의무화] 스마트 컨트랙트는 사후 패치가 극도로 어렵기 때문에 단순한 단위 테스트나 화이트박스 코드 리뷰만으로는 해킹을 막을 수 없음 → 나라면: 수십억 원 이상의 자금을 다루는 금융 디파이(DeFi) 및 공공 스마트 컨트랙트 배포 파이프라인에 Z3 SMT 솔버 기반의 형식 검증(Formal Verification) 단계를 필수로 삽입하여, 모든 가능한 상태 공간에서 자금 잠김(Lockup)이나 재진입이 발생하지 않음을 수학적 논리로 100% 증명한 코드만 메인넷에 배포하도록 강제
