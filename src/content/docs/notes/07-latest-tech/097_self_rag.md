## 답안 골격
```text
[Self-RAG] ◀━━ 머리: Ⅶ 내 의견 (반성 토큰 기반의 적응형 검색과 사후 검증으로 불필요한 검색 오버헤드와 근거 없는 환각을 동시 차단하는 자가 성찰 RAG)
 ┃
 ┣━ Ⅰ 개요 ───── 모든 질문에 맹목적으로 문서를 검색하는 기존 RAG의 비효율 및 무검증 답변 생성 → 모델 스스로 검색 필요성을 판단하고 생성 문장을 자가 평가
 ┣━ Ⅱ 특징 ───── 적응형 검색(Adaptive Retrieval) · 4대 반성 토큰(Reflection Tokens) · 토큰 확률 기반 빔 서치(Beam Search) · 환각 자가 억제
 ┣━ Ⅲ 구조 ───── 생성자 모델(Generator) + 검색기(Retriever) + 4대 특수 반성 토큰([Retrieve], [IsRel], [IsSup], [IsUse])
 ┣━ Ⅳ 흐름 ───── ① [Retrieve] 토큰으로 검색 필요 여부 능동 결정 → ② 필요 시 문서 검색 → ③ [IsRel]로 문서 관련성 평가 → ④ 문장 생성 및 [IsSup] 지지 여부 검증 → ⑤ [IsUse] 유용성 채점으로 최적 경로 선택
 ┣━ Ⅴ 비교 ───── Naive RAG vs Modular RAG vs Self-RAG (정적 무조건 검색 vs 외부 모듈 파이프라인 vs 모델 내부 반성 토큰 기반 엔드투엔드 자가 통제)
 ┗━ Ⅵ 실무 ───── 반성 토큰 학습을 위한 특수 파인튜닝 비용 / 빔 서치 적용 시 디코딩 지연시간 증가 / 독점 상용 LLM 적용 제약
```
- 필수 키워드: Self-RAG · 반성 토큰(Reflection Tokens) · 적응형 검색(Adaptive Retrieval) · `[Retrieve]` · `[IsRel]` · `[IsSup]` · `[IsUse]`
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 4대 반성 토큰 구조 및 동작 흐름 → Ⅴ 기존 RAG 대비 차별성 비교표 / 25점 = Ⅰ~Ⅶ 전개, 반성 토큰 학습 방식(Critic/Generator) 및 빔 서치 확률 최적화 수식 집중
- 기출: 미출제. 예상: "거대 언어 모델의 검색 증강 생성에서 적응형 검색과 자가 반성을 결합한 Self-RAG의 개념, 4가지 반성 토큰의 역할 및 동작 원리를 설명하시오." → Ⅰ~Ⅶ

## 한 줄 본질
- "오늘 날씨 어때?"나 "1+1은?" 같은 단순 질의에도 무조건 벡터 DB를 뒤지는 고정형 RAG의 낭비와 출처 왜곡을 극복하기 위해, 모델 스스로 "검색이 필요한가?", "가져온 문서가 맞는가?", "내 답변이 문서에 근거하는가?"를 특수 토큰으로 검증하며 생성하는 능동형 RAG / 오픈소스 모델 파인튜닝 필수

## 핵심 그림
```text
[Self-RAG의 4대 반성 토큰(Reflection Tokens) 기반 생성 파이프라인]

  [사용자 입력 x] ──> [모델 생성 시작]
                            │
                            ▼
              ┌───────────────────────────┐
              │ 1. [Retrieve] 토큰 생성?   │
              └─────────────┬─────────────┘
                            │
         ┌──────────────────┴──────────────────┐
         ▼ (No: 검색 불필요)                    ▼ (Yes: 외부 지식 필요)
   [일반 텍스트 생성]                   [외부 문서 검색 수행 (Retrieval)]
                                               │
                                               ▼
                                 ┌───────────────────────────┐
                                 │ 2. [IsRel]: 문서 관련성?  │
                                 └─────────────┬─────────────┘
                                               │
                                               ▼
                                 ┌───────────────────────────┐
                                 │ 3. 문장 생성 및 [IsSup]    │
                                 │    (문서가 답변을 지지?)  │
                                 └─────────────┬─────────────┘
                                               │
                                               ▼
                                 ┌───────────────────────────┐
                                 │ 4. [IsUse]: 답변 유용성?  │
                                 └─────────────┬─────────────┘
                                               │
                                               ▼
                                      [최적 문장 경로 확정]
```

## 핵심 용어
- `[Retrieve]`: 모델이 텍스트를 생성하다가 외부 사실 검색이 필요한 순간에 스스로 출력하는 토큰(`yes`, `no`, `continue`)
- `[IsRel]`(Is Relevant): 검색된 문서가 현재 질문과 생성 문맥에 실제로 유관한지 판별하는 반성 토큰(`relevant`, `irrelevant`)
- `[IsSup]`(Is Supported): 모델이 생성한 문장의 내용이 검색된 문서에 명시된 사실에 의해 뒷받침되는지 검증하는 토큰(`fully supported`, `partially supported`, `no support`)
- `[IsUse]`(Is Useful): 생성된 전체 응답이 사용자 질문에 대해 얼마나 유용하고 가치 있는지 1~5점 척도로 채점하는 토큰

## 핵심 통찰
- "무조건적 검색의 함정 탈피": 상식 질문이나 창작 요청에 RAG를 강제하면 엉뚱한 문서가 끼어들어 오히려 모델의 원래 성능을 망침 → Self-RAG는 검색이 필요할 때만 선별적으로 검색하여 연산 비용을 50% 이상 절감
- 팩트체크를 모델 내재화: 별도의 사후 검증 모듈을 두지 않고, 다음 토큰을 예측하는 디코딩 과정에서 `[IsSup]` 토큰의 로그 확률값을 직접 계산하여 허위 사실 생성을 즉각 폐기
- 서빙 시 유연한 제약 조건 조절: 사용자가 "엄격한 사실 기반 답변"을 원하면 `[IsSup=fully supported]` 가중치를 높이고, "창의적 답변"을 원하면 낮추는 식의 런타임 제어가 가능

## 이웃 토픽과 구분
- Self-RAG vs CRAG: Self-RAG는 모델 자체가 반성 토큰을 생성하도록 파인튜닝된 단일 모델 솔루션 / CRAG는 외부의 검색 평가자와 웹 검색기를 파이프라인으로 엮은 프레임워크

## 문제·원인·대책
- 적용 상황: 법률 및 판례 검색 챗봇에서 환각 방지를 위한 Self-RAG 모델 구축
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 검색된 판례에 없는 가짜 법조항을 모델이 마치 판례에 있는 것처럼 인용 | 모델의 근거성 판별 능력 결여 | `[IsSup=fully supported]` 확률이 0.9 미만인 생성 후보를 빔 서치에서 자동 가지치기 | 판례 왜곡 및 환각 문장 95% 차단 |
| 모든 토큰마다 반성 토큰을 판별하고 빔 서치를 수행하여 응답 지연 4배 증가 | 지나치게 세밀한 문장 단위 다중 경로 탐색 오버헤드 | 문단 단위 반성 토큰 트리거 및 Top-K 빔 크기 2로 압축 | 추론 레이턴시 60% 단축 |
| 상용 API 모델(GPT-4 등)을 사용할 수 없어 오픈소스 모델 호스팅 인프라 필요 | 독점 API 모델은 내부 특수 토큰 파인튜닝 불가 | 오픈소스 Llama-3 기반 특화 Self-RAG 가중치를 vLLM으로 사내 프라이빗 호스팅 | 데이터 주권 확보 및 반성 토큰 네이티브 지원 |
