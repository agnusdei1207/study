## 답안 골격
```text
[LoRA / PEFT] ◀━━ 머리: Ⅶ 내 의견 (베이스 모델 동결과 저차원 행렬 분해로 파인튜닝 비용을 99% 절감하고 서빙 시 가중치 병합으로 지연시간 0을 달성하는 효율화 표준)
 ┃
 ┣━ Ⅰ 개요 ───── 수백억 파라미터 LLM의 전체 파인튜닝(Full Fine-Tuning) 시 메모리 폭증 및 스토리지 낭비 → 파라미터 효율적 미세조정(PEFT) 태동
 ┣━ Ⅱ 특징 ───── 원본 가중치 동결(Freeze) · 저차원 랭크 분해(Low-Rank Decomposition) · 학습 파라미터 99% 절감 · 추론 지연시간 0(가중치 병합)
 ┣━ Ⅲ 구조 ───── 사전학습 가중치 행렬($W_0$) + 다운 프로젝션 행렬($A$) + 업 프로젝션 행렬($B$) + 스케일링 계수($\alpha / r$)
 ┣━ Ⅳ 흐름 ───── ① 원본 $W_0$ 동결 → ② 입력 $x$를 $W_0$와 저차원 어댑터($BA$)에 병렬 입력 → ③ 순전파 시 출력 합산 ($h = W_0 x + \frac{\alpha}{r}BAx$) → ④ 역전파 시 $A, B$만 갱신 → ⑤ 배포 시 $W_0 + \Delta W$ 영구 병합
 ┣━ Ⅴ 비교 ───── Full Fine-tuning vs Prefix Tuning vs LoRA vs QLoRA (전체 가중치 갱신 vs 가상 토큰 추가 vs 저차원 분해 vs 4비트 양자화 결합)
 ┗━ Ⅵ 실무 ───── 랭크($r$) 및 알파($\alpha$) 선정 트레이드오프 / 멀티 어댑터 동시 서빙 시 동적 스와핑 오버헤드 / 과적합 발생
```
- 필수 키워드: PEFT · LoRA(Low-Rank Adaptation) · 저차원 행렬 분해 · QLoRA · 랭크($r$) · 가중치 병합(Weight Merging) · 파라미터 효율화
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ LoRA 수학적 분해 아키텍처 도식 → Ⅴ PEFT 핵심 기법 4종 비교표 / 25점 = Ⅰ~Ⅶ 전개, 역전파 메모리 절감 수식 원리 및 QLoRA 3대 기술(NF4, 이중 양자화, 페이징) 집중
- 기출: 미출제. 예상: "대규모 언어 모델(LLM)의 효율적 도메인 특화를 위한 PEFT(Parameter-Efficient Fine-Tuning)의 개념과 LoRA(Low-Rank Adaptation)의 동작 원리 및 QLoRA를 설명하시오." → Ⅰ~Ⅶ

## 한 줄 본질
- 수십~수백 기가바이트의 파라미터를 전부 다시 학습하면 GPU 메모리가 기하급수적으로 소모되고 태스크마다 거대 모델 파일을 따로 저장해야 함 → 원본 가중치를 얼리고 두 개의 매우 작은 저차원 행렬($B \times A$)만 학습시켜 파라미터 수를 0.1% 이하로 압축 → 단일 GPU로 미세조정 실현 / 랭크 축소에 따른 극한의 복잡 태스크 표현력 한계

## 핵심 그림
```text
[LoRA(Low-Rank Adaptation)의 저차원 행렬 분해 연산 구조]

                  입력 벡터 x (차원 d)
                 ┌─────────┴─────────┐
                 │                   │
                 ▼                   ▼
     ┌───────────────────────┐   ┌──────────────────────┐
     │ 원본 가중치 W_0       │   │ 다운 프로젝션 행렬 A │ (d × r 차원)
     │ (동결: Gradient 없음) │   │ (N(0, σ²) 초기화)    │
     │ 차원: d × k           │   └──────────┬───────────┘
     └──────────┬────────────┘              ▼
                │                ┌──────────────────────┐
                │                │ 업 프로젝션 행렬 B   │ (r × k 차원)
                │                │ (0으로 초기화)       │
                │                └──────────┬───────────┘
                │                           │
                │  h_base = W_0 · x         │ Δh = (α/r) · B · A · x
                │                           │
                └───────────┬───────────────┘
                            ▼
                    최종 출력 h = h_base + Δh
          (배포 시: W_merged = W_0 + (α/r)·BA 로 합쳐져 오버헤드 0)
```

## 핵심 용어
- 저차원 랭크($r$, Rank): 분해된 행렬 $A$와 $B$의 중간 압축 차원 수(보통 8, 16, 32, 64)로, 작을수록 학습 파라미터와 메모리가 줄어들고 클수록 표현력이 증가함
- 스케일링 계수($\alpha$, Alpha): 저차원 업데이트 $\Delta W$가 원본 가중치 $W_0$에 미치는 영향력을 조절하는 상수로, 통상 $\alpha = 2r$ 수준으로 설정하여 학습 안정성을 유지
- QLoRA(Quantized LoRA): 원본 베이스 모델을 4비트 NormalFloat(NF4)로 극단적 압축하고, 메모리 페이징과 이중 양자화를 결합하여 24GB 일반 GPU 1장에서 65B LLM 파인튜닝을 가능하게 한 기술

## 핵심 통찰
- "변화량의 본질적 차원(Intrinsic Rank)은 생각보다 매우 작다": 에드워드 후(Edward Hu) 등은 LLM이 새로운 태스크를 배울 때 필요한 가중치 변화량($\Delta W$)의 유효 계수(Rank)가 원본 가중치 차원(수천~수만)에 비해 수십(8~64)에 불과함을 입증함
- 추론 지연시간(Latency)의 완전한 제거: 프롬프트 튜닝이나 어댑터 방식은 추론 시 네트워크 계층이 늘어나 지연이 생기지만, LoRA는 서빙 전 $W_{new} = W_0 + \Delta W$로 단순 행렬 덧셈을 해버리면 원본 모델과 물리적으로 동일한 단일 행렬이 됨
- 단일 베이스 모델로 수백 개의 멀티 테넌트 서빙 가능: RAM에 70B 베이스 모델 하나만 올려두고, 고객사나 업무 도메인별로 수십 MB짜리 LoRA 가중치 파일만 런타임에 동적으로 교체(Hot-swapping)하여 서빙 비용 극소화

## 이웃 토픽과 구분
- LoRA vs Full Fine-tuning: Full Fine-tuning은 모든 가중치를 갱신하여 막대한 VRAM 소모 / LoRA는 원본 동결 후 0.1% 미만의 저차원 행렬만 갱신하여 VRAM을 70% 이상 절감

## 문제·원인·대책
- 적용 상황: 사내 단일 A100(80GB) 서버에서 도메인 특화 70B 모델 미세조정 시 메모리 부족 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| LoRA를 적용했음에도 옵티마이저 상태(Adam) 메모리로 인해 여전히 VRAM 초과(OOM) | 옵티마이저가 FP32 상태를 유지하며 80GB 한계 도달 | 4비트 양자화와 Paged Optimizer를 결합한 QLoRA 프레임워크 적용 | VRAM 사용량 48GB 이하로 안정화 |
| 특정 도메인 데이터셋 훈련 후 범용적인 상식 대화 및 코딩 능력이 급격히 상실(Catastrophic Forgetting) | 랭크 $r$이 너무 크거나 에포크가 과도하여 원본 표현 공간 침범 | 랭크를 $r=16$으로 축소하고 베이스 사전학습 데이터 5%를 리플레이(Replay) 혼합 | 망각 현상 억제 및 도메인 정답률 35% 향상 |
| 수십 개의 고객사별 LoRA 어댑터를 동시 서빙할 때 스와핑 시마다 응답 지연 발생 | 매 요청마다 GPU VRAM으로 어댑터 가중치를 복사하는 버스 병목 | 멀티 테넌트 동적 서빙 엔진(S-LoRA, Punica) 기반 배치 연산 도입 | 어댑터 교체 지연 0ms 수준 달성 및 동시 처리량 4배 증대 |

## 이렇게 출제된다

## 내 의견
- [S-LoRA 기반의 엔터프라이즈 멀티 어댑터 통합 서빙 아키텍처 구현] 각 부서별로 수십 개의 개별 LLM을 띄우는 것은 엄청난 GPU 낭비임 → 나라면: 사내 중앙 AI 게이트웨이에 공유 베이스 파운데이션 모델(Llama-3-70B 등) 1세트만 배포하고, 인사·법무·개발 등 부서별 업무는 S-LoRA를 적용하여 요청 헤더의 태그에 따라 마이크로 어댑터를 VRAM 내 통합 풀에서 즉각 결합하는 아키텍처를 도입하여, GPU 인프라 비용을 80% 절감하고 서비스 확장성을 달성
