## 핵심 용어
- TTFT(Time To First Token): 사용자가 프롬프트를 보낸 후 첫 번째 토큰이 생성될 때까지 걸리는 지연시간(사용자 체감 지연 지표)
- 시맨틱 캐싱(Semantic Caching): 기존 질의와 의미적으로 유사한 과거 질문이 들어오면 LLM을 다시 호출하지 않고 캐시된 답변을 즉시 반환하는 비용 절감 기법
- vLLM: PagedAttention 기술을 활용해 GPU VRAM 파편화를 제거하고 LLM 서빙 처리량(Throughput)을 수 배 향상시키는 오픈소스 엔진

## 핵심 통찰
- 모든 업무에 초거대 모델(GPT-4 등)을 쓸 필요가 없으며, 80%의 단순 요약·분류 업무는 7B~14B급 경량 sLM으로도 충분히 처리 가능
- LLM 프로젝트 총 소유비용(TCO)의 대부분은 초기 모델 도입비가 아니라 지속적인 토큰 사용료와 GPU 인프라 전력·냉각 비용임
- 기업 도입의 성패는 "모델 자체의 성능"보다 사내 비정형 문서(PDF, HWP, 위키)의 정제 및 벡터 인덱싱 품질에 달려 있음

## 이웃 토픽과 구분
- LLM 도입 아키텍처 vs 전통 웹 아키텍처: 웹은 확정적 입출력과 상태 비저장(Stateless) API 중심 / LLM 아키텍처는 비결정론적 긴 컨텍스트 메모리 관리, 스트리밍 토큰 전송, 고비용 GPU 추론 서빙 중심

## 문제·원인·대책
- 적용 상황: 사내 업무 지원 LLM 챗봇 오픈 후 토큰 비용 급증 및 응답 지연
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 월간 API 호출 비용 예산 초과 | 모든 질의를 고비용 최상위 상용 LLM으로 일괄 라우팅 | 스마트 라우터(경량 sLM 1차 분류 후 복합 질의만 상용 API 전달) | API 호출 비용 60% 이상 절감 |
| 사용자 체감 응답 지연 심화(10초 대기) | 문서 전체를 매번 질의에 포함하여 프롬프트 토큰 과다 | 시맨틱 캐싱 적용 및 스트리밍(Server-Sent Events) 응답 구현 | TTFT 1초 이내 단축 및 동일 질의 즉각 반환 |
| 임직원 주민등록번호/계좌번호 유출 | 가드레일 없는 프롬프트 입력 및 외부 전송 | 엔터프라이즈 게이트웨이에 PII 탐지 마스킹 필터 구축 | 개인정보 외부 유출 원천 차단 및 컴플라이언스 준수 |
