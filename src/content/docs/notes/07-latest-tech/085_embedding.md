## 한 줄 본질
- 텍스트나 범주형 데이터를 컴퓨터가 이해하도록 원-핫(One-hot) 벡터로 변환할 때 발생하는 차원의 저주와 단어 간 의미적 직교(유사도 0) 문제 → 방대한 말뭉치로부터 단어가 쓰인 주변 문맥을 신경망으로 학습하여 저차원 연속 공간의 실수 벡터(Dense Vector)로 사상 → 단어 간 의미적 유사도를 코사인 각도로 계산하고 벡터 덧셈·뺄셈 연산 실현 / 문맥에 따른 다의어 분리에는 추가 트랜스포머 레이어 필요

## 핵심 그림
```text

1. 원-핫 인코딩 (희소 벡터, 직교)             2. 밀집 임베딩 (의미적 거리 보존)
   단어 수 V = 100,000차원                    저차원 D = 300차원 실수 벡터
   "사과" = [1, 0, 0, 0, ..., 0]             
   "배"   = [0, 1, 0, 0, ..., 0]                    (과일 군집)
   "차량" = [0, 0, 1, 0, ..., 0]              [사과] *      * [배]
                                                     \      /
   * 모든 단어 벡터 간 내적 = 0                      \    / 유사도 높음
   * "사과"와 "배"가 유사함을 모름                   \  /
```

## 핵심 용어
- 분산 표현(Distributed Representation): 단어의 의미가 특정 차원 하나에 일대일로 대응되지 않고, 수백 개의 잠재 차원 전체에 걸쳐 확률적 가중치 형태로 분산되어 저장되는 방식
- 임베딩 룩업 테이블(Embedding Lookup Table): 단어 인덱스를 행 번호로 삼아 해당 행의 가중치 벡터를 그대로 뽑아내는 $V \times D$ 크기의 파라미터 행렬로, 수학적으로는 원-핫 벡터와 가중치 행렬의 곱셈과 동일
- 코사인 유사도(Cosine Similarity): 두 임베딩 벡터 간의 사잇각 코사인 값($\frac{\mathbf{A} \cdot \mathbf{B}}{\|\mathbf{A}\|\|\mathbf{B}\|}$)으로, 벡터의 크기와 무관하게 의미적 방향성이 얼마나 일치하는지를 -1에서 1 사이로 측정하는 표준 척도

## 핵심 통찰
- "단어의 의미는 그 단어가 함께 어울려 쓰이는 주변 단어들에 의해 결정된다"(J.R. Firth의 분포 가설): "사과를 먹었다", "배를 먹었다"처럼 비슷한 문맥에 자주 등장하는 단어들은 벡터 공간에서 물리적으로 가까운 좌표를 갖게 됨
- 임베딩의 마법은 "기하학적 벡터 연산(Vector Arithmetic)": $\vec{v}(\text{King}) - \vec{v}(\text{Man}) + \vec{v}(\text{Woman}) \approx \vec{v}(\text{Queen})$ 처럼 성별, 시제, 수도 관계 등의 추상적 개념이 벡터 공간의 방향 벡터로 표현됨
- 정적 임베딩(Word2Vec)의 한계는 "동음이의어": "금융기관 은행"과 "나무 은행"이 동일한 하나의 벡터를 가짐 → 이를 해결한 것이 문맥에 따라 동적으로 벡터가 달라지는 트랜스포머 기반 문맥 임베딩(Contextual Embedding)

## 이웃 토픽과 구분
- 정적 임베딩(Word2Vec/GloVe) vs 문맥 임베딩(BERT/LLM): 정적 임베딩은 단어 하나당 고정된 단 하나의 벡터 할당 / 문맥 임베딩은 주변 문장에 따라 동일한 단어도 매번 다른 좌표 벡터로 동적 생성

## 문제·원인·대책
- 적용 상황: 고객 상품 리뷰 감성 분석 파이프라인에서 Word2Vec 임베딩 적용 시 오류 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| "배송이 빠르다"와 "배송이 느리다"의 두 반의어가 벡터 공간에서 매우 유사하게 배치 | "배송이"라는 동일한 주변 문맥을 공유하여 분포 가설의 반의어 왜곡 발생 | 감성 라벨 지도학습 손실을 결합한 지도형 임베딩(FastText + 분류 손실) 적용 | 긍정/부정 극성 분리 정확도 22% 향상 |
| 학습 데이터에 없던 신조어 및 오타 입력 시 OOV(Out of Vocabulary) 에러 발생 | 단어 단위(Word-level) 고정 사전 룩업 방식의 태생적 한계 | 문자 N-gram(FastText) 또는 서브워드(BPE) 단위 임베딩 분해 기법 도입 | 미등록 신조어 및 오타에 대한 강건한 벡터 생성 |
| 대규모 검색용 벡터 DB에 수천만 건 임베딩 저장 시 메모리 초과 발생 | 1,536차원 부동소수점(FP32) 벡터의 막대한 RAM 점유(건당 6KB) | 스칼라/곱 양자화(Product Quantization, PQ) 및 이진 임베딩(Binary Embedding) 적용 | 벡터 인덱스 메모리 95% 절감 및 탐색 속도 5배 가속 |

## 내 의견
- [RAG 및 벡터 검색 고도화를 위한 Matryoshka 표현 학습(MRL) 임베딩 도입] 1,536차원 이상의 고차원 임베딩은 벡터 유사도 계산(HNSW) 시 연산 비용을 급증시킴 → 나라면: 벡터의 앞선 64~128차원만 잘라 써도 원본 전체 차원 성능의 98%를 유지하도록 학습시키는 마트료시카(Matryoshka) 임베딩 모델을 구축하여, 1차 후보군 검색은 64차원으로 초고속 필터링하고 상위 50건만 전체 차원으로 정밀 검증하는 계층형 벡터 인덱싱 체계 구현
