## 핵심 용어
- 테스트 하네스(Test Harness): 본래 소프트웨어 공학에서 프로그램을 테스트하기 위해 작성된 드라이버(Driver)와 스텁(Stub)의 모음으로, AI에서는 모델 성능을 정량 평가하기 위한 벤치마크 프레임워크
- 가드레일(Guardrails): LLM의 비정상적인 발화, 프롬프트 인젝션 공격, 비즈니스 규칙 위반을 런타임에 탐지하여 차단하는 입출력 방어벽(예: NeMo Guardrails, Guardrails AI)
- 구조화된 출력(Structured Outputs): 모델이 자유 텍스트가 아닌 사전에 정의된 JSON 스키마 규격을 100% 만족하는 바이트 시퀀스만 출력하도록 제약하는 문법 샘플링 기법

## 핵심 통찰
- 프롬프트 엔지니어링이 "자연어 프롬프트 텍스트를 다듬는 글짓기 기법"이라면, 하네스 엔지니어링은 "불안정한 확률론적 모델을 믿을 수 있는 소프트웨어 컴포넌트로 만드는 시스템 공학"
- 프로덕션 환경의 AI 장애 중 80%는 모델의 성능 부족이 아니라, 출력 포맷 불일치나 컨텍스트 누락 같은 "하네스 결함"에서 발생
- 언어 모델 자체를 신뢰할 수 없는 외부 컴포넌트로 간주하고, 모든 입출력 경계에 엄격한 타입 체킹과 검증 로직을 배치하는 제로 트러스트 소프트웨어 설계 철학의 반영

## 이웃 토픽과 구분
- 하네스 엔지니어링 vs 프롬프트 엔지니어링: 프롬프트 엔지니어링은 컨텍스트 창에 들어갈 단어와 Few-shot 예시를 설계하는 작업 / 하네스 엔지니어링은 프롬프트 조립, 도구 호출, 스키마 검증, 에러 복구 전체를 감싸는 소프트웨어 외피(Scaffolding)를 구축하는 작업

## 문제·원인·대책
- 적용 상황: LLM 기반 자동 SQL 생성 및 보고서 작성 시스템 운영 중 결함 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 모델 출력이 JSON 형식을 깨뜨려 백엔드 파서 다운 | 생성 확률 분포에 따른 자유 텍스트 주석 혼입 | 문법 기반 샘플링(Grammar-based Decoding) 및 JSON Schema 강제 | 파싱 에러 0% 달성 및 백엔드 안전성 보장 |
| 악의적 사용자의 프롬프트 인젝션으로 시스템 프롬프트 유출 | 모델 자체의 지시어 해석 우선순위 혼란 | 입력 하네스에 다층 보안 필터 및 독립 인젝션 탐지기 배치 | 탈옥 공격 방어율 99% 달성 |
| 배포 후 모델 업데이트 시 기존 업무 정확도 회귀(Regression) | 체계적인 회귀 검증 데이터셋 및 하네스 부재 | CI/CD 파이프라인 내 Evals 벤치마크 하네스(Promptfoo) 자동화 | 기능 퇴화 조기 감지 및 품질 통제 |
