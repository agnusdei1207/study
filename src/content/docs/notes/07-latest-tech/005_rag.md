## 답안 골격
```text
[RAG] ◀━━ 머리: Ⅶ 내 의견 (하이브리드 검색과 리랭커(Re-ranker) 기반 환각 최소화 파이프라인 구축)
 ┃
 ┣━ Ⅰ 개요 ───── 모델 지식 컷오프 및 환각(Hallucination) 한계 → 외부 지식 검색 후 생성 결합
 ┣━ Ⅱ 특징 ───── 실시간 최신성 확보 · 출처 명시를 통한 설명성 보장 · 파인튜닝 대비 저비용 구축
 ┣━ Ⅲ 구조 ───── 인덱싱(청킹/임베딩/벡터DB) + 검색(Dense/Sparse/하이브리드) + 생성(프롬프트 결합/LLM)
 ┣━ Ⅳ 흐름 ───── ① 사용자 질의 → ② 질의 임베딩/검색 → ③ 관련 문서 리랭킹 → ④ 컨텍스트 주입 및 응답 생성
 ┣━ Ⅴ 비교 ───── Naive RAG vs Advanced RAG vs Modular RAG (단순 검색 vs 전·후처리 vs 모듈형 라우팅)
 ┗━ Ⅵ 실무 ───── 무관 청크 유입(Noise) / 검색 누락(Recall 저하) / 컨텍스트 윈도우 초과
```
- 필수 키워드: 벡터 DB · 청킹(Chunking) · 임베딩(Embedding) · 하이브리드 검색 · 리랭킹(Re-ranking) · 환각 완화
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ RAG 3단계 파이프라인 구조도 → Ⅵ 핵심 대책 / 25점 = Ⅰ~Ⅶ 전개, Ⅴ 발전 단계(Naive/Advanced/Modular)와 Ⅵ 환각 방지 전략 집중
- 기출: 134회 1교시 13번 `RAG(Retrieval Augmented Generation)` → Ⅰ·Ⅲ, 139회 1교시 3번 `Advanced RAG와 Modular RAG 비교` → Ⅴ

## 한 줄 본질
- LLM의 폐쇄형 파라미터 지식 한계와 환각 위험 → 외부 지식 베이스에서 관련 문서를 실시간 검색해 프롬프트 컨텍스트로 결합 주입 → 최신성 및 근거 기반 응답 보장 / 검색 품질에 종속되는 가비지 인 가비지 아웃(GIGO) 위험

## 핵심 그림
```text
[RAG 파이프라인 및 고도화 흐름]
+-------------------------------------------------------------------+
| 1. 데이터 인덱싱: 문서 분할(청킹) -> 임베딩 모델 -> 벡터DB 저장   |
+-------------------------------------------------------------------+
                                  ^
                                  | 검색 (Dense + Sparse)
+---------------+      +----------+----------+      +---------------+
| 사용자 질의    | ---> | 질의 변환 / 확장     | ---> | 리랭커 (Rerank)|
+---------------+      +---------------------+      +-------+-------+
                                                            | Top-K 문서
                                                            v
+---------------+      +---------------------+      +-------+-------+
| 최종 답변 생성 | <--- | LLM (거대 언어모델)  | <--- | 프롬프트 증강 |
+---------------+      +---------------------+      +---------------+
```

## 핵심 용어
- 청킹(Chunking): 긴 문서를 의미적 일관성을 유지하도록 고정 길이 또는 구문 단위의 작은 조각으로 분할하는 기법
- 하이브리드 검색(Hybrid Search): 의미적 유사도를 찾는 Dense(임베딩) 검색과 키워드 일치를 찾는 Sparse(BM25) 검색의 결합
- 리랭커(Re-ranker): 1차 벡터 검색으로 추출된 후보 문서군에 대해 교차 어텐션(Cross-Encoder)을 적용해 질문 관련성 순위를 재배열하는 모듈

## 핵심 통찰
- 파인튜닝은 모델에 문체·어조·특정 태스크 형식을 학습시키는 데 최적이며, 팩트 기반 최신 지식 업데이트는 RAG가 압도적으로 효율적
- 단순히 Top-K 문서를 LLM에 많이 넣으면 Lost in the Middle 현상으로 문맥 중간의 핵심 정보를 무시하는 역효과 발생
- 검색 결과 품질이 전체 RAG 신뢰도의 80%를 결정 → 질의 변환(Query Rewriting)과 리랭커 도입 유무가 상용 품질을 좌우

## 이웃 토픽과 구분
- RAG vs 파인튜닝: RAG는 외부 문서를 동적으로 참조해 팩트 정확성을 높이는 방식 / 파인튜닝은 모델 파라미터 가중치를 직접 변경해 특정 도메인 스타일과 태스크 수행력을 내재화

## 문제·원인·대책
- 적용 상황: 사내 규정 Q&A 챗봇 구축 후 엉뚱한 부서 규정을 인용하는 답변 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 질문과 무관한 청크 검색 유입 | 의미적 유사도만 고려하는 단순 코사인 유사도 검색 한계 | BM25 결합 하이브리드 검색 및 BGE-Reranker 도입 | 키워드 일치와 의미 연관성 동시 확보로 Top-3 정확도 개선 |
| 표(Table) 및 도표 정보 해석 실패 | 텍스트 평탄화(Flattening)로 인한 2차원 구조 정보 유실 | 멀티모달 파서(LlamaParse 등) 및 마크다운 테이블 청킹 적용 | 표 구조 보존을 통한 수치 질의 정답률 확보 |
| 검색된 내용과 다른 거짓 답변 생성 | LLM의 파라미터 사전 지식과 검색 컨텍스트 충돌(환각) | 프롬프트에 "주어진 컨텍스트 내에서만 답변할 것" 제약 및 출처 링크 명시 | 환각 답변 억제 및 사용자 신뢰도 제고 |

## 내 의견
- [단순 벡터 검색을 넘어선 지식 그래프 기반 GraphRAG 도입] 전통 청킹 기반 RAG는 문서 간 전역적(Global) 관계 요약이나 복합 질의(Multi-hop Reasoning)에 구조적 취약점 존재 → 나라면: 엔티티와 관계를 추출해 지식 그래프(Knowledge Graph)를 구축하고 커뮤니티 요약을 제공하는 GraphRAG를 결합하여 전사적 복합 의사결정 질의 지원
