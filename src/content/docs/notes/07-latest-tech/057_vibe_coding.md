```text
 ┣━ Ⅱ 특징 ───── 자연어 의도 기반 지시 · 개발자의 아키텍트/감독관 전환 · 폭발적 프로토타이핑 속도 · AI 에이전트 전권 구현

 ┣━ Ⅴ 비교 ───── 전통적 코딩 vs AI 자동완성(Copilot) vs 바이브 코딩(Vibe Coding) (수작업 문법 vs 한 줄 추천 vs 완전 위임)
```

## 한 줄 본질
- 세부 문법, 라이브러리 API 문서를 검색하고 타이핑하는 전통적 코딩의 시간 소모 → 개발자가 자연어 대화와 직관적 의도(Vibe)만 던지고 AI 에이전트가 파일 수정과 디버깅을 전담 수행 → 초고속 프로토타이핑 달성 / 개발자가 코드를 완벽히 이해하지 못하는 기술 부채 및 보안 취약점 누적

```text
|  - 자연어 의도 제시: "이 API에 JWT 인증 붙이고, 결제 실패 시 재시도 로직 추가해줘" |

```

## 핵심 용어
- 바이브 코딩(Vibe Coding): AI 연구자 안드레이 카파시가 명명한 개념으로, 개발자가 코드 한 줄 한 줄을 직접 검토하고 작성하는 대신 자연어로 대화하며 "느낌(Vibe)과 의도"만 전달해 소프트웨어를 완성하는 방식
- 에이전틱 IDE(Agentic IDE): 단순 코드 자동완성을 넘어, 터미널 실행, 다중 파일 동시 편집, 린트 오류 자동 교정 권한을 가진 자율 코딩 에이전트 통합 개발 환경(예: Cursor, Windsurf)
- 코드 블라인드니스(Code Blindness): AI가 작성한 방대한 양의 코드를 개발자가 세부적으로 읽고 검증하지 않아, 시스템이 어떻게 동작하는지 내부 구조를 아무도 알지 못하는 위험 상태

## 핵심 통찰
- 바이브 코딩은 단순한 "게으른 코딩"이 아니라, 프로그래밍 언어의 추상화 계층이 기계어 → 어셈블리어 → 고수준 언어(C/Java)를 거쳐 "자연어(Natural Language)"로 진화한 역사적 필연
- 코드를 작성하는 비용이 0에 수렴함에 따라, 개발자의 핵심 역량은 "신택스 암기력"에서 "시스템 아키텍처 설계력, 요구사항 명세력, 테스트 검증력"으로 완전히 전이
- 작성된 코드의 신뢰성을 인간의 육안 검수에 의존할 수 없으므로, AI가 통과해야 할 "엄격한 테스트 스위트(TDD/BDD)"를 선제 구축하는 것이 유일한 안전장치

## 이웃 토픽과 구분
- 바이브 코딩 vs Copilot: Copilot은 개발자가 코드를 치는 도중 다음 단어나 함수 한 줄을 보조 추천(Assistant) / 바이브 코딩은 자연어 지시만으로 여러 파일의 생성, 수정, 테스트, 커밋까지 에이전트가 주도(Agent)

## 문제·원인·대책
- 적용 상황: 스타트업에서 바이브 코딩으로 1주일 만에 상용 MVP 출시 후 운영 단계 진입
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 장애 발생 시 사내 어떤 개발자도 원인 코드를 디버깅하지 못함 | 코드베이스에 대한 인간의 멘탈 모델 부재(Code Blindness) | 아키텍처 문서화(ADR) 자동 생성 및 모듈별 코드 리뷰 강제 | 코드베이스 가독성 및 유지보수성 확보 |
| 생성된 코드 내 하드코딩된 API 키 노출 및 SQL 인젝션 취약점 | AI 모델이 기능 동작에만 치중하여 방어적 코딩 누락 | CI/CD 파이프라인 내 SAST/DAST 정적 보안 스캔(SonarQube) 의무화 | 보안 취약점 배포 전 원천 차단 |
| 에이전트가 기존 잘 동작하던 다른 모듈을 임의 수정해 사이드 이펙트 발생 | 다중 파일 수정 시 영향도 분석 미흡 | 테스트 주도 개발(TDD) 하네스 적용: 테스트 통과 시에만 커밋 허용 | 기존 기능 회귀(Regression) 방지 |
