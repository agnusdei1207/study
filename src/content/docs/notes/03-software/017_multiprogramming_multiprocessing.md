## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **다중프로그래밍(Multiprogramming)**: 단일 CPU에서 여러 프로그램을 메모리에 적재하고 I/O 대기 시 타 작업으로 전환하는 시분할 동시성 기법.
- **다중처리(Multiprocessing)**: 2개 이상의 물리 CPU/코어를 사용하여 복수의 명령어를 동일 시점에 물리적으로 병렬 실행하는 기법.

</details>

- 정의/개념: 단일 코어 I/O 유휴 중첩으로 CPU 이용률을 높이는 **다중프로그래밍**과 복수 코어로 물리적 병렬 연산하는 **다중처리** 체계
- 배경/필요성: 단일 작업 순차 처리 시의 I/O 대기 구간 CPU 유휴 낭비 및 **단일 코어의 물리적 연산 성능 한계(Power Wall)**

#### 한줄 요약
- 단일 CPU 시분할 인터리빙(다중프로그래밍)과 멀티코어 물리적 동시 실행(다중처리)을 비교한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **동시성(Concurrency)**: 단일 코어 상에서 여러 작업이 짧은 시간 단위로 번갈아 실행되어 동시에 진행되는 것처럼 보이는 논리적 성질.
- **병렬성(Parallelism)**: 여러 물리 코어 상에서 여러 작업이 정확히 동일한 시각에 동시 실행되는 물리적 성질.

</details>

- **다중프로그래밍**: 단일 CPU에서 I/O 발생 시 즉각 문맥 전환하는 **인터리빙 기반 동시성(Concurrency)**
- **다중처리**: 복수 물리 코어에서 독립 파이프라인을 구동하는 **하드웨어 레벨 병렬성(Parallelism)**
- 다중처리는 코어 간 공유 메모리 동기화, **캐시 일관성(Cache Coherence)** 및 버스 대역폭 관리 필수

#### 한줄 요약
- 다중프로그래밍은 논리적 동시성을, 다중처리는 물리적 병렬성을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **대칭형 다중처리(Symmetric Multiprocessing, SMP)**: 모든 CPU 코어가 단일 공유 메모리를 대등하게 접근하고 동일 OS가 제어하는 대칭형 다중처리 구조.
- **암달의 법칙(Amdahl's Law)**: 병렬화 불가능한 직렬 구간($s$)의 비율로 인해 코어 수를 무한히 늘려도 최대 속도 향상비($1/s$)에 한계가 존재한다는 법칙.

</details>

```text
[다중 실행 모델 체계]
  │
  ├─ [다중프로그래밍 모델] (단일 코어 인터리빙)
  │     ├─ [작업 준비 큐] (I/O 대기 시 전환)
  │     └─ [단일 CPU 코어] (시간 분할 유휴 방지)
  │
  └─ [다중처리 모델] (멀티코어 물리적 병렬 실행)
        ├─ [글로벌 스케줄러] (코어별 작업 분배)
        ├─ [물리 CPU 코어군] (동시 기계어 실행)
        └─ [SMP 공유 버스] (MESI 캐시 일관성)
```

선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 작업 준비 큐 | 메모리에 적재되어 CPU 디스패치를 기다리는 프로세스 풀 관리 |
| 커널 스케줄러 | 스케줄링 알고리즘에 따라 작업을 단일 코어 시분할 또는 멀티코어 병렬 할당 |
| 물리 CPU 코어 | 할당된 기계어 명령어를 인출(Fetch)·해독·실행하는 하드웨어 연산 유닛 |
| SMP 공유 버스 | 멀티코어 환경에서 메모리 및 L3 캐시를 공유하며 **캐시 일관성(MESI)** 유지 |

#### 한줄 요약
- 다중프로그래밍은 하나의 코어에서 시간을 나누고 다중처리는 코어 자체를 늘리므로, 같은 동시성이라도 해소하는 병목의 종류가 다르다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **인터리빙(Interleaving)**: CPU가 단일 작업에 묶이지 않고 여러 작업 조각을 교대로 실행하여 유휴 시간을 없애는 기법.

</details>

```text
[다중프로그래밍 흐름] (단일 코어, 진행 ①→③, A의 I/O 완료 인터럽트 후 문맥 전환으로 프로세스 A 실행 재개)
  │
  ├─ [프로세스 A 실행] (① I/O 요청 발생)
  │
  ├─ [문맥 전환] (② 프로세스 B로 전환)
  │
  └─ [프로세스 B 실행] (③ CPU 유휴 방지)

[다중처리 흐름] (멀티코어, 진행 ①→③, 동일 시점에 물리적으로 동시 병렬 실행)
  │
  ├─ [프로세스 A, B 동시 진입] (① 두 프로세스 동시 투입)
  │
  ├─ [코어 1: A 실행] (② 코어 1 할당)
  │
  └─ [코어 2: B 실행] (③ 코어 2 할당)
```

분기 결과: 병목이 I/O 대기라면 다중프로그래밍이 문맥 전환 비용으로 유휴를 메우고, 병목이 연산이라면 다중처리가 하드웨어 비용으로 동시 실행을 얻는다.

#### 한줄 요약
- 다중프로그래밍은 문맥 전환 비용을 치르고 유휴를 메우며 다중처리는 하드웨어 비용을 치르고 동시 실행을 얻으므로, 병목이 대기인지 연산인지가 선택을 가른다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **멀티태스킹 vs 멀티스레딩**: 멀티태스킹은 OS 차원의 프로세스 시분할이고, 멀티스레딩은 단일 프로세스 내 스레드 간 자원 공유 병렬 처리.

</details>

| 비교 항목 | 다중프로그래밍 (Multiprogramming) | 시분할/멀티태스킹 (Multitasking) | 다중처리 (Multiprocessing) | 멀티스레딩 (Multithreading) |
|:---|:---|:---|:---|:---|
| 핵심 목적 | CPU 유휴 시간 최소화 | 대화형 응답성 극대화 | **연산 처리량(Throughput) 극대화** | 자원 공유 및 경량 병렬화 |
| 코어 자원 | **단일 코어 (I/O 전환)** | 단일/멀티 코어 (타임 퀀텀) | **복수 물리 코어/CPU 필수** | 단일/멀티 코어 내 스레드 |
| 동시성 특성 | 시분할 동시성 (Concurrency) | 시분할 동시성 (Concurrency) | **물리적 병렬성 (Parallelism)** | 논리 동시성 및 물리 병렬성 |
| 주 병목 요인 | I/O 대기 및 메모리 부족 | 문맥 전환 오버헤드 | **캐시 일관성, 메모리 버스 경합** | 임계 구역 동기화 락 경합 |

#### 한줄 요약
- 유휴 방지는 다중프로그래밍, 응답성은 멀티태스킹, 처리량 극대화는 다중처리가 담당한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **거짓 공유(False Sharing)**: 서로 다른 코어가 독립 변수를 수정하는데 두 변수가 동일한 64바이트 캐시 라인에 걸쳐 있어 캐시 무효화 트래픽이 폭증하는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 다중프로그래밍 정도(DOM) 과다로 인한 메모리 부족 | 워킹 셋 기반 **수용 제어(Admission Control)** | 스레싱 방지 및 CPU 유효 가동률 유지 |
| 멀티코어 환경에서 독립 변수 갱신 시 **거짓 공유(False Sharing)** | 캐시 라인(64B) 패딩 및 **`@Contended` 어노테이션** 적용 | 불필요한 캐시 라인 무효화 버스 트래픽 제거 |
| 코어 수 증가에도 불구하고 직렬 구간으로 성능 정체(**Amdahl**) | **락 프리(Lock-Free) 알고리즘** 및 작업 분할 최적화 | 병렬 확장성(Scalability) 한계 극복 |
| NUMA 멀티소켓 환경에서 원격 메모리 접근 지연 | **NUMA-Aware 스케줄링 및 로컬 메모리 바인딩** | 메모리 대역폭 병목 해소 및 레이턴시 단축 |

#### 한줄 요약
- 다중프로그래밍은 유휴 시간을, 다중처리는 처리량 한계를 겨냥하므로, 병목이 I/O 대기면 수용 제어로 동시 작업 수를 조절하고 병목이 연산이면 캐시 라인 패딩·NUMA 바인딩으로 병렬 확장을 막는 공유를 걷어낸다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **비균일 메모리 접근 인지(NUMA-Aware)**: 각 프로세스와 스레드를 메모리가 물리적으로 인접한 CPU 소켓 노드에 바인딩하여 인터커넥트 병목을 최소화하는 아키텍처.
- **락 프리 알고리즘(Lock-Free Algorithm)**: 임계 구역 동기화 블로킹 없이 하드웨어 원자 연산으로 다중 코어 간 직렬화 병목을 제거하는 병렬 프로그래밍 기법.

</details>

- 현대 하드웨어는 수십~수백 코어 스케일업 환경으로 확장됨에 따라 소켓 간 메모리 지역성을 극대화하는 **비균일 메모리 접근 인지(NUMA-Aware)** 스케줄링 및 이종 가속기 연계 다중처리로 진화 추세
- 고성능 연산 병목 구간에서는 거짓 공유 방지를 위한 캐시 라인 패딩과 **락 프리 알고리즘**을 도입하여 암달의 법칙에 의한 병렬 확장성 한계를 선제적으로 극복하는 아키텍처적 결단 필요

#### 한줄 요약
- NUMA 인지 스케줄링으로 원격 메모리 지연을 줄이고 캐시 패딩과 락 프리 구조로 암달의 법칙 한계를 돌파해야 한다.
