## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Saga 패턴**: 각 마이크로서비스의 독립 DB 환경에서 2PC 없이 로컬 트랜잭션을 순차 실행하고, 실패 시 역순으로 보상 트랜잭션을 수행하는 패턴.
- **보상 트랜잭션(Compensating Transaction)**: 이미 커밋된 이전 로컬 트랜잭션의 상태 변경을 비즈니스적으로 상쇄/취소(Undo)하는 반대 작업.

</details>

- 정의/개념: 분산 환경에서 전역 잠금 대신 **로컬 트랜잭션** 순차 커밋과 실패 시 **보상 트랜잭션(Compensating Transaction)** 으로 최종 일관성을 보장하는 패턴
- 배경/필요성: Database-per-Service 환경에서 2단계 커밋(2PC)이 초래하는 **분산 전역 락 블로킹, 단일 장애점(SPOF) 및 처리량 급락 한계**

#### 한줄 요약
- 로컬 트랜잭션을 순차 실행하고, 오류 발생 시 보상 트랜잭션으로 상태를 정합화한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Choreography vs Orchestration**: 이벤트 발행/구독으로 자율 진행하는 코레오그래피와 중앙 오케스트레이터가 흐름을 통제하는 오케스트레이션.
- **ACD 특성**: Saga는 원자성(Atomicity), 일관성(Consistency), 영속성(Durability)은 보장하나 중간 커밋으로 인해 격리성(Isolation)이 배제됨.

</details>

- 2PC 전역 락을 배제하여 **시스템 처리량(Throughput) 및 가용성 극대화**
- 비동기 분산 자율형 **코레오그래피(Choreography)** 와 중앙 통제형 **오케스트레이션(Orchestration)** 방식
- 중간 상태 커밋으로 인한 **격리성(Isolation) 부재 보완을 위한 시맨틱 락(Semantic Lock)** 필요

#### 한줄 요약
- 사가는 전역 락을 없애 확장성을 얻는 대신 중간 상태 노출과 보상 로직 작성을 감수하므로, 원자성을 최종 일관성으로 바꾼 거래가 된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **시맨틱 락(Semantic Lock)**: 격리성 부재로 인한 Dirty Read를 방지하기 위해 레코드 상태를 `PENDING`으로 표시하여 타 트랜잭션 수정을 차단하는 기법.

</details>

```text
[Saga 분산 트랜잭션 체계]
  │
  ├─ [사가 오케스트레이터]
  │     ├─ [상태 저장소] (진행 상태 영속화·트랜잭션 이력)
  │     ├─ [실행 디스패처] (단계별 커맨드 순차 발행)
  │     └─ [보상 관리자] (실패 시 역순 보상 트랜잭션 트리거)
  │
  ├─ [메시지 브로커] (Kafka/RabbitMQ 신뢰적 메시지 중계)
  │
  └─ [참여 마이크로서비스]
        ├─ [로컬 트랜잭션] (서비스별 독점 DB 원자적 커밋)
        └─ [보상 트랜잭션] (실패 시 상태 취소/상쇄 실행)
```
- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 사가 오케스트레이터 | 흐름 추적과 **역순 보상 지시** |
| 사가 상태 저장소 | 진행 상태의 **원자적 기록** |
| 참여 서비스 | 로컬 커밋과 **상쇄 트랜잭션 수행** |
| 메시지 브로커 | 명령·이벤트의 **신뢰성 전달** |

#### 한줄 요약
- 오케스트레이터가 트랜잭션 상태를 외부에 두고 관리하므로 참여 서비스는 서로를 몰라도 되지만, 그 상태 저장소가 새로운 단일 실패점이 된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Pivot Transaction(피벗 트랜잭션)**: 이 단계가 성공하면 이후 단계는 롤백 없이 무조건 전진 완료(Go-Forward)되는 분기점 트랜잭션.

</details>

```text
[정방향 실행] : [주문 생성] ──► [결제 승인] ──► [재고 차감 시도: 실패 발생]
                                                        │
[역방향 보상] : [주문 취소] ◄── [결제 환불] ◄───────────┘
                (상태 원복)     (보상 완료)
```

#### 한줄 요약
- 정방향 진행과 역방향 보상은 대칭이 아니어서 이미 외부에 노출된 중간 상태는 되돌릴 수 없으므로, 보상이 가능한 지점까지만 사가로 묶어야 한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **코레오그래피 vs 오케스트레이션 vs 2PC**: 이벤트 중심 분산 자율, 중앙 상태 머신 통제, 동기식 분산 락 프로토콜.

</details>

| 비교 항목 | 코레오그래피 (Choreography) | 오케스트레이션 (Orchestration) | 2단계 커밋 (2PC) |
|:---|:---|:---|:---|
| 제어 방식 | **이벤트 발행/구독 분산 자율** | **중앙 오케스트레이터 명령/응답** | 분산 코디네이터 전역 동기화 |
| 적합한 규모 | 2~4개 이하 단순 워크플로우 | **5개 이상 복잡한 엔터프라이즈** | 단일 도메인 강한 ACID 필수 |
| 결합도 / 추적성 | 결합도 낮음 / 흐름 추적 어려움 | **가시성 높음 / 상태 추적 용이** | 결합도 극도로 높음 |
| 시스템 처리량 | **최고 (비동기 병렬 확장)** | 우수 (상태 저장 오버헤드) | 최악 (전역 락 블로킹) |

#### 한줄 요약
- 단순 이벤트 연계는 코레오그래피, 복잡한 비즈니스 워크플로우는 오케스트레이션을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **멱등성(Idempotency)**: 네트워크 재전송으로 동일한 보상 트랜잭션이 여러 번 인입되어도 결과가 최초 1회와 동일함을 보장하는 성질.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 중간 커밋 노출로 인한 Dirty Read (**격리성 부재**) | 레코드 상태를 `PENDING`으로 두고 **시맨틱 락(Semantic Lock)** 설정 | 미완료 데이터에 대한 타 프로세스 수정 차단 |
| 네트워크 유실로 인한 보상 트랜잭션 미전달 | **트랜잭셔널 아웃박스(Transactional Outbox) 및 재시도** | 메시지 발행의 100% 원자성 보장 |
| 메시지 중복 전달로 인한 이중 환불 발생 | 고유 트랜잭션 ID 기반 **컨슈머 멱등성(Idempotency) 검증** | 중복 결제 취소 원천 차단 |
| 보상 트랜잭션 자체의 영구 실패 | **데드 레터 큐(DLQ) 적재 및 운영자 수동 정합 콘솔** | 분산 데이터 불일치 잔존 방지 |

#### 한줄 요약
- 사가는 전역 잠금을 없애는 대신 중간 상태 노출과 보상 로직 작성 비용을 떠안으므로, 시맨틱 락으로 노출 구간을 좁히고 아웃박스·멱등성으로 보상 자체의 신뢰성을 확보한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **영속적 실행 엔진(Durable Execution Engine)**: 서버 장애나 네트워크 단절 시에도 프로세스의 실행 상태와 변수를 영속화하여 중단된 시점부터 정확히 재개하는 분산 오케스트레이션 엔진(예: Temporal, Camunda).
- **데드 레터 큐(Dead Letter Queue, DLQ)**: 최대 재시도 횟수를 초과하거나 치명적 결함으로 처리에 실패한 보상 트랜잭션 이벤트를 격리 보관하는 메시지 큐.
- **최종 일관성(Eventual Consistency)**: 분산 시스템에서 데이터 갱신 후 즉각적인 정합성은 일시 결여될 수 있으나, 시스템에 추가 변경이 없을 경우 결국 모든 노드가 일관된 상태로 수렴하는 모델.

</details>

- **차세대 발전 전망**: 상태를 투명하게 보존하는 **영속적 실행 엔진(Durable Execution Engine)** 및 이벤트 스트리밍 인프라와 결합되어, 복잡한 보상 분기 로직을 일반 코드처럼 기술하고 장애 시 중단 지점부터 투명하게 복원하는 방향으로 진화 추세.
- **실무 공학적 통찰**: 비즈니스 워크플로우 복잡도에 따라 오케스트레이션과 코레오그래피를 선별 채택하고, 보상 실패 시 영구 정합 파괴를 방지하기 위한 **데드 레터 큐(DLQ)** 연계 및 운영자 수동 조정 콘솔 거버넌스 확립 필요.

#### 한줄 요약
- Saga 패턴은 영속적 실행 엔진과 결합하여 분산 데이터 정합성을 투명하게 수렴시키되, 시맨틱 락과 DLQ 기반 수동 보상 거버넌스 확보가 시스템 신뢰성의 핵심이다.
