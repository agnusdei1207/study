## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **ISO/IEC/IEEE 29119**: IEEE 829, BS 7925 등 분산된 테스트 표준들을 하나로 통합한 소프트웨어 테스팅 국제 표준.
- **Part 4 테스트 설계 기법**: 명세 기반(블랙박스), 구조 기반(화이트박스), 경험 기반 테스트 설계 기법을 체계화한 규격.

</details>

- 정의/개념: 소프트웨어 테스팅 표준화를 위해 **위험 기반(RBT) 프로세스와 명세·구조·경험 기반 설계 기법(Part 4)** 을 정형화한 국제 표준
- 배경/필요성: 테스팅 표준 파편화와 서식 중심 접근에 따른 **설계 기법 비표준화, 주관적 결함 검출 편차 및 요구사항-테스트 간 추적성 단절 한계**

#### 한줄 요약
- 테스트는 완전 검증이 원리적으로 불가능한 활동이므로, ISO 29119는 커버리지를 균일하게 올리는 대신 유한한 시험 공수를 위험도가 높은 영역에 몰아주는 배분 규칙을 택한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **5대 Part 구성**: Part 1(개념), Part 2(프로세스), Part 3(문서 양식), Part 4(설계 기법), Part 5(키워드 주도 테스팅).
- **4단계 설계 절차**: Test Basis $\to$ Test Condition $\to$ Test Case $\to$ Test Procedure (Coverage Item 도출).

</details>

- IEEE 829, BS 7925 등 기존 분산 표준을 하나로 통합한 **국제 단일 테스트 프레임워크**
- 시스템 위험도에 따라 테스트 강도를 차등화하는 **위험 기반 테스팅(RBT) 원칙 적용**
- 요구사항(SRS)부터 테스트 케이스 및 실행 결과까지의 **완전한 양방향 추적성(Traceability) 보장**

#### 한줄 요약
- RBT 위험 분석과 4단계 정형 설계 절차로 테스트 커버리지와 신뢰성을 극대화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명세/구조/경험 기반 기법**: 요구사항 기반(EP, BVA 등), 소스코드 기반(구문, 분기, MC/DC), 테스터 직관 기반(오류추정).

</details>

```text
[ISO 29119-4 테스트 설계 체계]
  │
  ├─ [1. 명세 기반 기법] (블랙박스)
  │     ├─ [동등 분할 / 경계값 분석] (EP / BVA)
  │     └─ [의사결정표 / 상태 전이] (Decision Table / FSM)
  │
  ├─ [2. 구조 기반 기법] (화이트박스)
  │     ├─ [구문 / 분기 커버리지] (C0 / C1)
  │     └─ [조건 / MC/DC 커버리지] (C2 / 안전 표준)
  │
  └─ [3. 경험 기반 기법] (테스터 직관)
        ├─ [오류 추정] (Error Guessing)
        └─ [탐색적 테스팅] (Exploratory Testing)
```
- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 명세 기반 기법 | 요구·입력 경계의 **기능 결함 검출** |
| 구조 기반 기법 | 코드 제어 흐름의 **커버리지 검증** |
| 경험 기반 기법 | 정형 기법 밖의 **돌발 결함 보완** |
| 추적성 매트릭스 | 요구와 테스트의 **1:1 검증 추적** |

#### 한줄 요약
- 명세, 구조, 경험 기반 기법으로 케이스를 도출하고 추적 매트릭스로 완결성을 검증한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Test Basis(테스트 베이시스)**: 테스트 설계의 기초가 되는 요구사항 명세서, 아키텍처 문서, 위험 분석서 일체.

</details>

```text
[ISO 29119 테스트 설계 흐름] (진행 ①→⑤, 테스트 프로시저(스크립트) 작성으로 종료)
  │
  ├─ [테스트 베이시스 분석] (① 요구사항 정의서(SRS)·유스케이스 명세 수집)
  │
  ├─ [테스트 조건 도출] (② '무엇을 검증할 것인가' Test Condition 식별)
  │
  ├─ [커버리지 항목 도출] (③ Part 4 기법(경계값·분기 등) 적용해 테스트 대상 항목 선정)
  │
  ├─ [테스트 케이스 설계] (④ 입력 데이터·사전 조건·기대 결과(Expected Result) 정의)
  │
  └─ [테스트 절차 생성] (⑤ 케이스 실행 순서·환경 설정 기술, 프로시저(스크립트) 작성)
```

분기 결과: 산출물이 베이시스에서 프로시저로 내려갈수록 구현 정도가 갈래를 가르며, 케이스·절차까지 내려가면 실행 가능성을 얻는 대신 생성·유지 공수가 커지고, 변경이 잦은 영역을 조건 수준에 머물게 하면 변경 대응 비용은 낮추되 실행 명세가 부족해진다

#### 한줄 요약
- 테스트 산출물은 베이시스에서 절차로 내려갈수록 구체화되는 대신 요구 변경에 취약해지므로, 변경이 잦은 영역은 테스트 조건 수준에 머무르고 안정된 영역만 절차까지 고정하는 것이 유지 비용을 낮춘다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **IEEE 829 vs ISO 29119**: 산출물 서식만 규정해 기법 선택을 조직에 떠넘긴 IEEE 829와, 그 공백에서 발생한 품질 편차를 프로세스·설계 기법·위험 기반 배분까지 규정해 흡수한 ISO 29119의 구분.

</details>

| 비교 항목 | IEEE 829 표준 (구 표준) | ISO/IEC/IEEE 29119 표준 (현행 표준) |
|:---|:---|:---|
| 표준화 범위 | **단순 테스트 산출물 서식 (Documentation)** | **프로세스, 문서 양식, 설계 기법, RBT 전면 통합** |
| 설계 기법 정의 | 미포함 (기법 가이드라인 부재) | **Part 4에 명세/구조/경험 기법 공식 규정** |
| 위험 관리 사상 | 단순 일정/자원 위험 고려 | **위험 기반 테스팅(RBT)을 핵심 프로세스로 채택** |
| 애자일 적응력 | 폭포수 문서 중심 (무거움) | 애자일/키워드 주도 테스팅(Part 5) 지원 |

#### 한줄 요약
- IEEE 829는 서식에 치중했으나, ISO 29119는 프로세스, 서식, 설계 기법을 종합 통합했다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Test Tailoring(테스트 테일러링)**: 프로젝트 규모와 위험도에 맞추어 표준 산출물과 검증 기법을 합리적으로 축소/조정하는 활동.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 방대한 표준 문서 작성으로 프로젝트 일정 지연 | **프로젝트 위험도(RBT)에 따른 산출물 테일러링(Tailoring)** | 불필요한 서류 작업 제거 및 개발 민첩성 확보 |
| 요구사항 변경 시 테스트 케이스 불일치 및 추적 단절 | **ALM 도구(Jira/Xray)와 연동한 TTM(추적 매트릭스) 자동화** | 요구사항-테스트 간 양방향 추적성 100% 보장 |
| 테스터의 주관적이고 부실한 테스트 케이스 작성 | **Part 4 정형 기법(경계값, 의사결정테이블) 템플릿 의무화** | 케이스 결함 검출력 30% 이상 향상 |
| 테스트 종료 시점의 모호성 | **정량적 테스트 완료 기준(Exit Criteria: 분기 100%) 수립** | 정량 지표 기반 객관적 릴리즈 판정 |

#### 한줄 요약
- 프로세스 테일러링, ALM TTM 자동화, Part 4 정형 기법 템플릿, 정량 완료 기준으로 실효성을 극대화한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **위험 기반 테스팅(Risk-Based Testing, RBT)**: 기능별 장애 발생 가능성과 비즈니스 치명도를 평가하여 한정된 테스트 자원을 고위험 영역에 집중 투입하는 기법.
- **테스트 추적 매트릭스(Test Traceability Matrix, TTM)**: 사용자 요구사항과 설계 명세, 테스트 케이스 및 검출 결함 간의 관계를 1:1로 매핑하여 검증 누락을 방지하는 추적 체계.

</details>

- **AI 주도 테스트 케이스 생성 및 지속적 테스팅 연계 진화**: ISO/IEC/IEEE 29119 표준 체계는 생성형 AI 기반 테스트 시나리오 자동 합성 및 CI/CD 파이프라인의 회귀 테스트 자동화와 결합하여, Part 4의 정형 설계 기법(경계값 분석, 상태 전이, 조합 테스팅)을 코드 커밋 즉시 무인 생성·수행하는 방향으로 고도화 추세.
- **위험 기반 자원 차등 배분과 양방향 추적성(TTM) 거버넌스 결단**: 문서 과잉에 따른 프로젝트 병목을 방지하기 위해 **위험 기반 테스팅(RBT)** 사상으로 산출물을 경량 테일러링하되, 생명·금융 등 핵심 도메인에 대해서는 ALM 도구 연동 **테스트 추적 매트릭스(TTM)** 100% 양방향 추적성을 입증하는 공학적 품질 거버넌스 확보 필요.

#### 한줄 요약
- ISO 29119는 AI 자동화 및 CI/CD 지속적 테스팅으로 진화하고 있으며, RBT 기반 위험도 차등 집중과 TTM 양방향 추적성 확보가 핵심이다.
