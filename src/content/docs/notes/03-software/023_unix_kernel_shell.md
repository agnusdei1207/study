## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **UNIX 3대 구성요소**: 명령 해석기(Shell), 하드웨어 제어 및 스케줄링 핵심(Kernel), 모든 자원을 계층 구조로 추상화하는 파일 시스템(File System).
- **시스템 콜(System Call)**: 사용자 모드 프로그램이 커널 모드의 특권 서비스(I/O, 프로세스 제어)를 호출하기 위한 소프트웨어 인터럽트 인터페이스.

</details>

- 정의/개념: 사용자 명령을 해석하는 **쉘(Shell)** 과 하드웨어를 제어하는 **커널(Kernel)** 및 **파일 시스템**으로 구성된 UNIX 아키텍처
- 배경/필요성: 애플리케이션의 물리 하드웨어 직접 제어 시 발생하는 **하드웨어 종속성, 메모리 침범 및 시스템 충돌 취약성 한계**

#### 한줄 요약
- 사용자 인터페이스(쉘), 핵심 자원 통제(커널), 통합 데이터 추상화(파일 시스템)의 3계층 구조를 확립한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Everything is a File**: 일반 파일, 디렉터리, 하드웨어 디바이스, 네트워크 소켓, 파이프를 모두 파일 디스크립터(FD)로 일원화하는 UNIX 철학.
- **파이프와 필터(Pipe & Filter)**: 한 프로그램의 표준 출력을 다음 프로그램의 표준 입력으로 연결(`|`)하여 작은 도구들을 조합하는 모듈형 설계.

</details>

- 사용자 공간(User Space)과 커널 공간(Kernel Space)의 엄격한 **이중 모드(Dual Mode)** 분리
- **Everything is a File** 철학 기반의 장치, 소켓, IPC 파일 디스크립터(FD) 단일 인터페이스
- **파이프(`|`) 및 표준 입출력(stdin/stdout/stderr)** 기반의 모듈식 명령 조합

#### 한줄 요약
- 이중 모드 분리는 시스템 호출마다 전환 비용을 치르는 대신 응용의 오류가 커널을 무너뜨리지 못하게 하므로, 안정성은 그 경계를 넘는 값으로 지불된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **이식 가능 운영체제 인터페이스 표준(Portable Operating System Interface, POSIX)**: IEEE가 제정한 유닉스 계열 운영체제 간 애플리케이션 이식성을 보장하는 표준 API 규격.

</details>

```text
[UNIX 시스템 계층 체계]
  │
  ├─ [사용자 공간 Ring 3] (User Space)
  │     ├─ [사용자 애플리케이션] (유틸리티)
  │     └─ [명령 쉘] (bash·zsh 명령 파싱)
  │
  ├─ [시스템 콜 인터페이스] (POSIX Syscall)
  │
  ├─ [커널 공간 Ring 0] (하드웨어 제어)
  │     ├─ [프로세스 관리자] (스케줄러·IPC)
  │     ├─ [메모리 관리자] (가상 메모리·MMU)
  │     └─ [디바이스 드라이버] (네트워크 스택)
  │
  └─ [파일 시스템 계층] (통합 자원 추상화)
        ├─ [VFS 추상화] (모든 자원 FD 처리)
        └─ [물리 블록 매핑] (ext4·ZFS 영속화)
```

선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 쉘 | 명령 파싱과 **fork·exec 실행** |
| 시스템 콜 인터페이스 | 사용자 공간의 **커널 모드 진입** |
| 커널 | CPU·메모리·인터럽트·장치 제어 |
| 파일 시스템 | 파일·장치·소켓의 **VFS 추상화** |

#### 한줄 요약
- 시스템 콜이 사용자 공간과 커널 공간을 가르는 유일한 통로이므로, 쉘을 포함한 모든 응용의 권한은 이 경계에서 검증된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **fork() / exec() / wait()**: 쉘이 프로세스를 복제(`fork`)하고 새 바이너리로 덮어쓴 뒤(`exec`), 종료 코드를 대기(`wait`)하는 기본 수명주기.

</details>

```text
[쉘 명령 실행 흐름] (진행 ①→⑤, 파이프 원소 수만큼 fork·exec 반복 후 wait 회수)
  │
  ├─ [쉘 파싱] (① 명령어 입력 파싱 및 파이프(`|`) IPC 채널 생성)
  │
  ├─ [fork()] (② 자식 프로세스 복제 생성)
  │
  ├─ [execve()] (③ 자식 프로세스를 새 바이너리 이미지로 교체 실행)
  │
  ├─ [커널 디스패치] (④ CPU·메모리·파일 디스크립터 할당 후 실행)
  │
  └─ [wait()] (⑤ 자식 exit() 종료 시 부모 쉘이 종료 코드 회수)
```

분기 결과: **fork() / exec() / wait()** 경로는 복제 후 즉시 교체하므로 복제 비용이 프로세스당 고정으로 붙고, 파이프가 여러 개면 원소마다 이 복제·교체를 반복하되 그 사이에 파일 디스크립터만 조작하면 되므로 IPC 채널 연결 비용은 명령 수에 비례해 누적된다

#### 한줄 요약
- fork와 exec 사이의 짧은 구간에서만 파일 디스크립터를 조작할 수 있으므로, 쉘의 파이프·리다이렉션 기능이 전부 이 지점에 몰린다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **모놀리식 vs 마이크로커널**: 모든 OS 서비스를 단일 커널 공간에 포함하는 모놀리식(Linux)과 핵심 스케줄링만 남기고 서버로 분리한 마이크로커널(Mach/QNX).

</details>

| 비교 항목 | 쉘 (Shell) | 커널 (Kernel) | 파일 시스템 (File System) |
|:---|:---|:---|:---|
| 동작 모드 | **사용자 모드 (Ring 3)** | **특권 커널 모드 (Ring 0)** | 커널 공간 내 VFS 모듈 |
| 주요 역할 | 대화형 명령 해석 및 스크립팅 | **하드웨어 제어 및 스케줄링** | 데이터 및 장치 파일 추상화 |
| 고장 영향도 | 쉘 크래시 시 해당 쉘만 종료 | **커널 패닉(Kernel Panic) 시 시스템 정지** | 파일 손상 시 I/O 에러 발생 |
| 통신 수단 | 표준 입출력(stdio), 파이프 | **시스템 콜(Syscall), 인터럽트** | VFS 함수 포인터 (vnodeops) |

#### 한줄 요약
- 쉘은 사용자 접점, 커널은 시스템의 심장, 파일 시스템은 모든 자원의 추상 인터페이스다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **포크 폭탄(Fork Bomb)**: 재귀적으로 무한 fork()를 호출하여 시스템의 프로세스 테이블(PID)을 고갈시켜 OS를 마비시키는 DoS 공격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 웹 애플리케이션에서 사용자 입력 미검증으로 **쉘 인젝션(Shell Injection)** | 인자 전달 시 쉘 경유 금지 및 **API 파라미터 바인딩(`execFile`)** | 악성 쉘 명령어 실행 원천 방어 |
| 악성 스크립트에 의한 프로세스 무한 복제 **포크 폭탄(Fork Bomb)** | `/etc/security/limits.conf` 내 **`nproc` 상한(ulimit)** 설정 | PID 고갈 방지 및 시스템 가용성 보호 |
| 쉘 스크립트 실행 중 예기치 않은 오류 무시 지속 실행 | 스크립트 상단에 **`set -euo pipefail`** 옵션 강제 | 오류 발생 시 즉시 중단 및 사이드 이펙트 방지 |
| 루트 권한 프로세스 탈옥 시 커널 장악 위험 | **User Namespaces 및 최소 권한 원칙(Principle of Least Privilege)** | 권한 상승 공격 차단 |

#### 한줄 요약
- 커널·셸 분리는 이식성과 보호를 시스템 호출 경계의 전환 비용으로 사는 구조이므로, 그 경계를 넘는 입력은 파라미터 바인딩과 최소 권한으로 검증하고 자원은 ulimit로 상한을 건다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **사용자 네임스페이스(User Namespaces)**: 컨테이너 내부의 루트 사용자를 호스트의 일반 사용자로 매핑하여 권한 상승 탈옥 공격을 무력화하는 리눅스 격리 기술.
- **확장 버클리 패킷 필터(Extended Berkeley Packet Filter, eBPF)**: 커널 소스 코드 수정 없이 커널 샌드박스에서 고속 패킷 처리 및 시스템 추적 프로그램을 실행하는 기술.

</details>

- 유닉스의 3계층 아키텍처는 클라우드 네이티브 컨테이너 격리와 결합하는 한편, 커널 영역을 안전하게 프로그래밍하는 **확장 버클리 패킷 필터(eBPF)** 기술을 통해 재해석 및 고도화 추세
- 시스템 침해를 방어하기 위해 **사용자 네임스페이스** 기반 최소 권한 격리를 강제하고 쉘 스크립트에는 `set -euo pipefail` 방어적 실행을 상시화하는 아키텍처적 결단 필요

#### 한줄 요약
- UNIX의 계층 철학 위에 eBPF 프로그래머블 커널과 사용자 네임스페이스 격리를 결합하여 현대 클라우드 보안과 유연성을 완성해야 한다.
