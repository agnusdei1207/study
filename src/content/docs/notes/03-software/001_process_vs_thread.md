## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **프로세스(Process)**: 독립된 가상 메모리 공간(MMU 페이지 테이블)과 파일 디스크립터를 독점 할당받아 실행되는 OS 자원 격리 단위.
- **스레드(Thread)**: 프로세스 내부의 코드·데이터·힙 메모리를 공유하며 자체 TCB(PC, 스택)만으로 실행되는 CPU 스케줄링 최소 단위.

</details>

- 정의/개념: 운영체제(OS)의 다중 작업(Multitasking) 환경에서 프로그램의 안전한 실행과 동시성을 관리하기 위해, 독립된 가상 주소 공간과 시스템 자원을 독점 소유하는 **프로세스(Process)**와 프로세스 자원을 공유하며 CPU 연산 스케줄링을 전담하는 **스레드(Thread)**로 계층화된 운영체제 핵심 실행 단위 모델
- 배경/필요성: 프로세스 단위 멀티태스킹은 전환마다 가상 주소 공간(CR3) 교체·TLB 플러시를, 통신마다 커널 경유 IPC 복사를 치르므로, 주소 공간을 공유하는 스레드를 프로세스 안에 두어 전환·통신 비용을 줄이는 계층 분리가 필요

#### 한줄 요약
- 장애 격리가 필요하면 프로세스, 고속 동시 처리가 필요하면 스레드를 선택한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **가상 주소 공간(Virtual Address Space)**: 커널이 프로세스마다 독립 할당하여 타 프로세스의 메모리 무단 접근을 차단하는 보호 경계.
- **문맥 전환 비용(Context Switching Overhead)**: CPU가 프로세스 간 전환 시 레지스터 보존, MMU 페이지 테이블 교체 및 TLB 플러시로 인해 발생하는 지연.
- **동기화(Synchronization)**: 공유 메모리에 접근하는 스레드 순서를 뮤텍스·세마포어 같은 락으로 직렬화해 데이터 경쟁을 막는 제어.

</details>

- 프로세스별 독립 **가상 주소 공간**을 통한 결함 및 보안 격리 경계 제공
- 스레드 간 힙 공유로 데이터 교환과 **문맥 전환 비용** 절감
- 공유 메모리 접근 경쟁을 제어하는 **동기화** 필요

#### 한줄 요약
- 스레드가 얻는 전환·통신 속도는 결함 격리를 포기한 대가이므로, 두 단위의 차이는 성능이 아니라 무엇을 나눠 갖느냐에서 나온다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **프로세스 제어 블록(Process Control Block, PCB)**: 프로세스의 가상 주소 공간 기술자, 파일 디스크립터, 스케줄링 상태를 보관하는 커널 자료구조.
- **스레드 제어 블록(Thread Control Block, TCB)**: 스레드의 프로그램 카운터(PC), 범용 레지스터, 스택 포인터를 보관하는 경량 커널 자료구조.

</details>

```text
[운영체제 실행 체계]
  │
  ├─ [프로세스] (OS 자원 격리 단위)
  │     ├─ [PCB] (가상 메모리·FD·상태 관리)
  │     ├─ [공유 메모리 영역] (코드·데이터·공유 힙)
  │     └─ [IPC 채널] (프로세스 간 파이프·소켓 통신)
  │
  └─ [스레드] (CPU 스케줄링 실행 단위)
        ├─ [TCB] (PC·레지스터 문맥 관리)
        └─ [독립 스택] (함수 호출 프레임·지역변수)
```

선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| PCB | 주소 공간·파일 테이블·스케줄링 상태 보관 |
| 공유 메모리 영역 | 동일 프로세스 스레드가 공유하는 힙 영역 |
| TCB | 스레드별 PC·레지스터·독립 스택 관리 |
| IPC 채널 | 프로세스 사이 파이프·소켓·공유 메모리 연결 |

#### 한줄 요약
- 프로세스 경계는 PCB와 주소 공간이 함께 갈리는 지점이고 스레드 경계는 TCB와 스택만 갈리므로, 무엇을 복제하고 무엇을 공유하느냐가 격리 강도와 전환 비용을 동시에 결정한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **임계 구역(Critical Section)**: 다중 스레드가 동시에 공유 자원에 접근하면 데이터 경쟁이 발생하는 코드 구간.

</details>

```text
[작업 분배 및 동시성 처리 경로] (진행 ①→②, 격리·공유 요구 판정에 따라 프로세스 분리와 스레드 분기로 분기, 완료 후 결과는 공통 경로로 반환)
  │
  ├─ [작업 분배 판정] (① 요청 성격에 따라 장애 격리·보안 분리 필요 여부와 고속 데이터 공유 우선 여부 판정)
  │
  ├─ [프로세스 분리] (② 격리 필요 판정 시 IPC 직렬화 및 페이지 테이블 교체 수행)
  │
  └─ [스레드 분기] (② 공유 우선 판정 시 공유 힙 메모리 접근 및 임계 구역 뮤텍스 동기화 수행)
```

분기 결과: 프로세스 분리는 IPC마다 커널 경유 복사와 전환마다 CR3 교체가 발생하고, 스레드 분기는 **임계 구역**에서만 뮤텍스 대기가 발생한다.

#### 한줄 요약
- 두 경로는 같은 작업 분배 요청에서 갈리지만 프로세스 경로는 IPC 직렬화와 페이지 테이블 교체를, 스레드 경로는 동기화 대기를 비용으로 치르므로 격리 요구가 없으면 후자가 항상 싸다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **페이지 테이블 교체(Page Table Switch)**: 프로세스 전환 시 CPU CR3 레지스터를 변경하여 TLB 캐시가 무효화되는 고비용 동작.

</details>

| 실행 단위 | 프로세스 | 스레드 | 가상 스레드 |
|:---|:---|:---|:---|
| 적용 기준 | 결함 격리가 필요한 작업 | 고빈도 I/O·연산 병렬화 작업 | 대규모 동시 연결 I/O 서버 |
| 핵심 특징 | 독립 가상 메모리와 **PCB** 기반 격리 | 힙 공유와 **TCB** 기반 경량 제어 | JVM 사용자 공간 스케줄링 |
| 한계 | **페이지 테이블 교체**·IPC 비용 | 스레드 장애의 프로세스 전파 | CPU 연산의 처리량 개선 제한 |

#### 한줄 요약
- 결함 격리는 프로세스, 고속 멀티태스킹은 스레드, 대규모 동시 I/O는 가상 스레드를 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **스레드 풀(Thread Pool)**: 스레드를 미리 생성하여 큐에 대기시킴으로써 생성/소멸 오버헤드를 제거하고 최대 동시 실행 수를 제한하는 패턴.
- **데이터 레이스(Data Race)**: 두 스레드가 동기화 없이 같은 메모리에 동시에 쓰거나 읽고 써서 결과가 실행 순서에 따라 달라지는 결함.
- **뮤텍스(Mutex)**: 임계 구역 진입 전 소유권 잠금을 획득하고 실패한 스레드를 대기시켜 한 번에 하나만 접근하도록 하는 상호 배제 락.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공유 자원 동시 접근 시 **데이터 레이스** | **뮤텍스** 잠금 적용 | 데이터 무결성 유지·락 경합 완화 |
| 스레드 결함으로 프로세스 중단 | 민감 구간을 워커 프로세스로 분리 | 장애 영향을 워커 범위로 격리 |
| 요청별 생성으로 스택 메모리 고갈 | **스레드 풀**·워커 큐 도입 | 생성 지연 제거·메모리 상한 통제 |
| 멀티프로세스의 IPC 직렬화 병목 | 공유 메모리·세마포어 적용 | 메모리 복사 제거·통신 지연 단축 |

#### 한줄 요약
- 스레드 공유가 주는 성능 이득은 동기화 비용과 장애 전파 위험을 대가로 하므로, 무결성이 중요한 구간은 워커 프로세스로 격리하고 처리량이 중요한 구간은 스레드 풀로 상한을 두어 나눈다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **가상 스레드(Virtual Thread)**: 운영체제 커널 스레드와 N:M 매핑되어 사용자 공간에서 대규모 동시 실행을 지원하는 런타임 관리 경량 스레드.
- **컨테이너(Container)**: 호스트 OS 커널 공간을 공유하며 cgroups와 네임스페이스 기반으로 프로세스 수준의 격리 경계를 제공하는 가상화 기술.

</details>

- 클라우드 네이티브 환경에서 결함·보안 격리를 위한 **컨테이너** 프로세스 구조와 고밀도 I/O 처리를 위한 **가상 스레드** 런타임 아키텍처가 결합되는 방향으로 진화 추세
- 무조건적인 멀티스레드 확장을 지양하고 강한 격리가 필요한 업무는 프로세스 경계로 분리하며 동시성 처리량 극대화 영역은 경량 런타임 스레드를 배치하는 공학적 절충 필요

#### 한줄 요약
- 결함 격리는 컨테이너 프로세스로 담보하고 대규모 동시 I/O는 가상 스레드로 처리하는 계층적 분리 아키텍처 수립이 핵심이다.
