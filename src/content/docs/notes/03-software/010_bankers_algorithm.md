## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **은행원 알고리즘(Banker's Algorithm)**: 자원 요청 시 가상 할당을 해보고 안전 상태가 유지될 때만 실제 할당하는 데드락 회피(Avoidance) 알고리즘.
- **안전 순서열(Safe Sequence)**: 시스템 내 모든 프로세스가 최대 자원을 요구하더라도 교착 없이 모두 완료될 수 있는 프로세스 실행 순서.

</details>

- 정의/개념: 프로세스의 최대 자원 요구량을 사전에 선언받고 가상 할당 후 **안전 순서열(Safe Sequence)** 을 검증하여 할당하는 교착상태 회피 알고리즘
- 배경/필요성: 교착상태 사후 복구의 데이터 손실·폐기 비용 및 단순 할당 거절에 따른 **자원 낭비와 비효율 한계**

#### 한줄 요약
- 가상 할당 시뮬레이션으로 안전 순서열이 존재할 때만 자원을 할당하여 교착상태를 회피한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Available / Max / Allocation / Need**: 가용 자원 벡터($1 \times m$), 최대 요구 행렬($n \times m$), 현재 할당 행렬($n \times m$), 잔여 요구 행렬($\text{Need}=\text{Max}-\text{Alloc}$).

</details>

- 프로세스 생성 시 **최대 자원 요구량(Max Claim)** 의 사전 확정 선언 필수 전제
- **Available(가용), Max(최대), Allocation(할당), Need(잔여)** 4대 장부 자료구조 기반 추적
- 가상 할당 후 $O(m \times n^2)$ 복잡도의 **안전성 알고리즘(Safety Algorithm)** 시뮬레이션 수행

#### 한줄 요약
- 안전 상태만 허용하는 보수성은 교착을 원천 차단하는 대신 실제로는 문제없을 요청까지 미루므로, 안전성을 자원 이용률로 지불하는 구조다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Work / Finish 벡터**: 안전성 검사 시 임시 가용 자원을 시뮬레이션하는 Work 벡터와 프로세스 완료 여부를 추적하는 Finish 불리언 배열.

</details>

```text
[은행원 알고리즘 체계]
  │
  ├─ [자원 관리 장부] (4대 추적 행렬·벡터)
  │     ├─ [Available 벡터] (현재 가용 수량)
  │     ├─ [Max 행렬] (프로세스별 최대 요구량)
  │     ├─ [Allocation 행렬] (현재 점유 할당량)
  │     └─ [Need 행렬] (잔여 요구량 Max-Alloc)
  │
  ├─ [자원 요청 검증기] (요청량과 잔여·가용 비교)
  │
  └─ [안전성 시뮬레이터] (가상 할당 및 안전 순서열 탐색)
        ├─ [Work 벡터] (임시 가용 자원 시뮬레이션)
        └─ [Finish 벡터] (완료 가능 여부 추적 불리언)
```

선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| Available 벡터 | 자원 유형별 현재 가용 수량 보관 |
| Max 행렬 | 프로세스별 최대 요구량 보관 |
| Allocation 행렬 | 프로세스별 현재 할당량 보관 |
| Need 행렬 | **Max - Allocation** 잔여 요구량 보관 |
| 자원 요청 검증기 | 요청량과 Need·Available 한도 비교 |
| 안전성 시뮬레이터 | 가상 할당의 **안전 순서열** 존재 판정 |

#### 한줄 요약
- 4대 행렬은 현재 할당이 아니라 최대 요구량까지 담아 미래를 판단하는 장부이므로, 선언된 최대치의 정확도가 곧 안전성 판정의 정확도가 된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **가상 할당(Speculative Allocation)**: 자원을 실제로 주기 전에 장부 상에서만 차감하여 안전성을 시험해보는 가상 트랜잭션.

</details>

```text
[은행원 알고리즘 자원 할당 흐름] (진행 ①→③, 한도 위반은 오류·안전 순서열 존재 시 실제 할당·불안전 판정 시 롤백 대기)
  │
  ├─ [자원 요청 검증기] (① Request_i ≤ Need_i 및 Request_i ≤ Available 대조, 한도 위반 시 오류 반환)
  │
  ├─ [가상 할당] (② 한도 통과 시 장부 상 Available 차감·Allocation 증가·Need 차감 후 시뮬레이션)
  │
  └─ [안전성 시뮬레이터] (③ Work·Finish 벡터로 안전 순서열 존재 여부 판정)
        ├─ [안전 상태] (③ 안전 판정 시 가상 할당을 실제 할당으로 승인)
        └─ [불안전 상태] (③ 불안전 판정 시 가상 할당 롤백 후 프로세스 대기 전환)
```

분기 결과: 한도 검증은 벡터 비교에 그쳐 값싸지만, **안전 순서열** 판정은 한 건의 요청에 전체 프로세스를 훑는 $O(m \times n^2)$ 시뮬레이션 비용을 치러 요청 하나가 끝나기까지 오래 걸리고, 불안전 판정 갈래는 할당을 거절해 자원을 남기므로 안전성은 곧 자원 이용률과 요청 지연으로 지불된다

#### 한줄 요약
- 안전성 검사를 통과하지 못한 요청은 거절이 아니라 대기로 되돌아가므로, 자원이 남아 있어도 진행을 미루는 보수성이 이 알고리즘이 안전을 사는 실제 값이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **불안전 상태(Unsafe State)**: 안전 순서열이 존재하지 않는 상태로, 향후 프로세스 요청 패턴에 따라 교착상태로 전이될 위험이 있는 상태.

</details>

| 시스템 상태 | 안전 상태 (Safe State) | 불안전 상태 (Unsafe State) | 교착상태 (Deadlock State) |
|:---|:---|:---|:---|
| 상태 정의 | **안전 순서열이 1개 이상 존재** | 안전 순서열 부재 (데드락 위험 내포) | 프로세스 상호 점유 무한 대기 (동결) |
| 자원 할당 결정 | 즉시 자원 할당 승인 | **자원 할당 거절 (요청 프로세스 대기)** | 할당 불가, 프로세스 강제 종료 필요 |
| 시스템 진행성 | 선언 한도 내 완료 순서 존재 | 요청 패턴에 따라 완료 또는 교착 | 관련 프로세스의 진행 중단 |

#### 한줄 요약
- 안전 상태는 완료 순서가 있고, 불안전 상태는 교착 위험을 내포한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Max Claim 사전 선언**: 프로세스 시작 시점에 사용할 자원의 최대치를 미리 확정하여 등록해야 하는 제약 조건.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 동적 분기 프로그램의 **최대 요구량(Max Claim) 사전 예측 곤란** | 정적 코드 분석 기반 보수적 최대 자원 프로파일링 적용 | 런타임 한도 초과 오류 방지 및 회피 기법 적용 |
| 매 자원 요청 시 $O(m \times n^2)$ 계산으로 인한 CPU 오버헤드 | 자원 풀 클러스터링 및 증분 안전성 검사(Incremental Check) | 검사 오버헤드 축소 및 실시간 트랜잭션 지연 완화 |
| 프로세스 변화에 따른 자원 행렬 갱신 경합 | **스냅샷 기반 안전성 검사**와 갱신 락 분리 | 검사 일관성과 갱신 경합 완화 |

#### 한줄 요약
- 은행원 알고리즘의 안전성은 매 요청마다 전 프로세스를 훑는 검사 비용을 치르고 얻는 것이므로, 최대 요구량 프로파일링과 증분 검사로 검사 범위를 좁혀야 실사용 규모에서 성립한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **회피 기법(Avoidance Mechanism)**: 자원 할당 전 시스템의 안전 상태(Safe State)를 동적으로 시뮬레이션하여 교착상태 발생 가능성을 사전에 차단하는 제어 방식.
- **증분 안전성 검사(Incremental Safety Check)**: 전체 자원 행렬을 전수 재계산하지 않고 변경된 할당량과 국소 조건만을 검증하여 오버헤드를 줄이는 최적화 기법.

</details>

- 임베디드 제어 및 정적 작업 파이프라인 등 자원 상한 예측이 가능한 분야에서 수학적 무결성을 증명하는 교착 **회피 기법**의 이론적 표준으로 유지 추세
- 동적 클라우드 환경에서는 $O(m \cdot n^2)$ 검사 지연과 최대 요구량 불확실성을 고려하여, 락 순서화 예방 및 사후 탐지·복구 기법으로 전환하는 공학적 절충 필요

#### 한줄 요약
- 임베디드 정적 환경은 은행원 알고리즘으로 회피하고 대규모 동적 시스템은 락 순서화와 탐지·복구로 절충 제어해야 한다.
