## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **DAST(Dynamic Application Security Testing)**: 실행 중인 웹 애플리케이션을 대상으로 외부 공격자 관점에서 악의적인 페이로드를 전송하여 취약점을 탐지하는 블랙박스 테스팅.
- **Active Scanning**: SQL Injection, XSS, SSRF 등 실제 공격 문자열을 파라미터에 주입하여 서버의 에러 응답과 비정상 반응을 검증하는 기법.

</details>

- 정의/개념: 구동 중인 웹 애플리케이션에 **블랙박스 모의 침투 및 액티브 스캐닝(Active Scanning)** 을 수행하여 런타임 보안 취약점을 탐지하는 기법
- 배경/필요성: 정적 분석(SAST)만으로는 파악하기 어려운 **웹서버 설정 결함, 런타임 인증·인가 우회 및 실제 공격 페이로드 악용 취약점 미검증 한계**

#### 한줄 요약
- 실행 중인 애플리케이션에 외부 공격을 시뮬레이션하여 실제 악용 가능한 취약점을 검증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **False Positive**: 응답 기반 검증으로 오탐을 줄이지만 탐지 규칙에 따라 남을 수 있는 오경보.
- **Language Agnostic(언어 독립성)**: 대상 서버가 Java, Python, Go, Node.js 등 어떤 기술 스택으로 작성되었든 HTTP/REST 인터페이스만으로 진단 가능.

</details>

- 소스 코드 열람이 불필요한 **블랙박스(Black-Box) 기반 외부 해커 관점 검증**
- HTTP 인터페이스를 기준으로 하는 **언어 독립적 스캔**
- 응답과 PoC를 근거로 **오탐을 줄이고 악용 가능성** 확인

#### 한줄 요약
- 동적 분석은 실행 맥락 덕에 오탐이 적은 대신 크롤러가 도달한 범위까지만 볼 수 있으므로, 정확도를 검사 커버리지로 지불한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **스파이더/크롤러(Crawler)**: 대상 웹사이트의 모든 링크, HTML Form, REST API 엔드포인트를 자동으로 탐색하여 공격 표면(Attack Surface)을 수집하는 모듈.

</details>

```text
[DAST 동적 분석 체계]
  │
  ├─ [공격 대상 엔드포인트] (실행 중인 Web App/API)
  │
  ├─ [공격 표면 수집기] (스파이더/크롤러·OpenAPI 파싱)
  │
  ├─ [인증 세션 관리자] (JWT/OAuth/쿠키 세션 자동 갱신)
  │
  ├─ [페이로드 주입기]
  │     ├─ [Passive] (비침습적 헤더/암호 스위트 점검)
  │     └─ [Active] (침습적 SQLi/XSS 공격 페이로드)
  │
  └─ [취약점 판정 엔진] (응답 분석·PoC 생성·오탐 필터링)
```
- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 스파이더 | 링크·폼·API의 **공격 표면** 수집 |
| 인증 관리자 | 세션·토큰 갱신과 권한별 탐색 지원 |
| 페이로드 주입기 | SQLi·XSS 등 **공격 입력** 전송 |
| 응답 분석기 | 상태·헤더·지연으로 취약 후보 판정 |

#### 한줄 요약
- 크롤러가 확보한 공격 표면이 곧 검사 범위의 상한이므로, 인증 세션 유지에 실패한 영역은 그대로 검사되지 않은 채 남는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **PoC(Proof of Concept)**: 취약점이 실제로 존재함을 증명하는 재현 가능한 HTTP 요청/응답 패킷 증적.

</details>

```text
[DAST 동적 스캔 흐름] (진행 ①→⑤, PoC 생성 시 심각도 기반 리포트 발행)
  │
  ├─ [대상 등록] (① 진단 URL·OpenAPI(Swagger) 명세 등록)
  │
  ├─ [탐색] (② 스파이더가 웹 UI·API 경로 순회, 파라미터 공격 표면 수집)
  │
  ├─ [인증] (③ 관리자·일반 사용자 계정 로그인, 세션/JWT 획득)
  │
  ├─ [공격 주입] (④ 파라미터에 OWASP Top 10 페이로드(예: ' OR 1=1--, script 태그) 주입)
  │
  ├─ [응답 검증] (⑤ SQL 에러 출력·스크립트 실행 확인 여부 판정)
  │
  ├─ [취약점 증명 PoC 생성] (⑤ 확인 시 심각도 기반 리포트 발행)
  │
  └─ [미탐·추가 검사] (⑤ 미확인 시 다른 입력과 경로 검증)
```

분기 결과: 공격 응답에서 취약 흔적이 확인되는지가 갈래를 가르며, PoC 경로는 재현 증적 확보에 드는 검증 시간을 치르고 확정된 취약점 리포트를 얻고, 미탐 경로는 확인 이득 없이 추가 입력·경로 탐색 비용을 들여 검사 커버리지를 넓힌다

#### 한줄 요약
- 인증 세션 확보에 실패하면 그 뒤 단계는 로그인 이후 영역을 전혀 보지 못하므로, 공격 표면 탐색의 성패가 검사 결과의 신뢰도를 사실상 결정한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SAST vs DAST vs IAST**: 정적 코드 분석(SAST), 외부 모의 침투(DAST), 런타임 에이전트 결합 하이브리드(IAST).

</details>

| 비교 항목 | 정적 분석 (SAST: SonarQube) | 동적 분석 (DAST: OWASP ZAP) | 대화형 분석 (IAST: Contrast Security) |
|:---|:---|:---|:---|
| 진단 시점 | **개발/빌드 단계 (컴파일 시)** | **스테이징/운영 단계 (런타임)** | QA/자동화 테스트 실행 단계 |
| 진단 방식 | 화이트박스 (소스코드 분석) | **블랙박스 (외부 HTTP 공격)** | **하이브리드 (내부 에이전트 + 외부 공격)** |
| 오탐 원인 | 실행 문맥 부재 | **응답 판정 규칙 오류** | 에이전트·테스트 경로 누락 |
| 장점 | 소스 코드 라인 단위 피드백 | **웹서버 설정 및 런타임 인증 검증** | 정확한 소스 라인과 실제 악용성 동시 확인 |
| 단점 | 런타임 설정 결함 탐지 불가 | 소스 코드 정확한 수정 라인 미제공 | 에이전트 탑재에 따른 성능 오버헤드 |

#### 한줄 요약
- SAST는 코드 내부를, DAST는 외부 실행 환경을, IAST는 에이전트로 두 장점을 융합 검증한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Data Pollution(데이터 오염)**: DAST 도구가 자동 회원가입, 결제, 삭제 API를 무차별 호출하여 DB가 더럽혀지거나 실제 결제가 발생하는 위험.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 운영 DB 오염과 결제·삭제 요청 발생 | **격리 Staging·테스트 데이터** 사용 | 운영 데이터와 서비스 영향 방지 |
| SPA 렌더링 미지원에 따른 경로 누락 | **헤드리스 브라우저 크롤링** | 동적 DOM과 API 경로 탐색 확대 |
| 전체 DAST 스캔 시간 과다로 CI/CD 배포 지연 | **PR 배포 시 Baseline 빠른 스캔 + 야간 정기 Full 스캔 분리** | 배포 파이프라인 속도 유지 및 심층 진단 양립 |
| WAF(웹 방화벽) 차단으로 인한 진단 실패 | **DAST 점검용 IP를 WAF 화이트리스트에 사전 등록** | 실제 애플리케이션 취약점 정밀 탐지 |

#### 한줄 요약
- 동적 분석은 실행 맥락 덕에 오탐이 적은 대신 크롤러가 닿지 못한 경로는 통째로 놓치므로, 스테이징 격리 환경과 인증 세션으로 스캔 범위를 먼저 확보해야 결과를 신뢰할 수 있다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **동적 애플리케이션 보안 테스팅(Dynamic Application Security Testing, DAST)**: 구동 중인 웹 애플리케이션에 실제 공격 페이로드를 전송하여 런타임 결함과 서버 설정 취약점을 탐지하는 블랙박스 테스팅.
- **대화형 애플리케이션 보안 테스팅(Interactive Application Security Testing, IAST)**: 애플리케이션 서버 내부의 바이트코드 계측 에이전트를 활용하여 외부 공격 패킷의 내부 실행 경로와 취약 코드 라인을 즉각 식별하는 하이브리드 테스팅.

</details>

- **API 주도 아키텍처 및 IAST 하이브리드 결합 진화**: 현대 **동적 애플리케이션 보안 테스팅(DAST)**은 OpenAPI/Swagger 사양 기반 자동 엔드포인트 수집 및 헤드리스 브라우저를 통한 싱글 페이지 애플리케이션(SPA) 크롤링으로 진화하고 있으며, 런타임 에이전트와 연계된 **대화형 애플리케이션 보안 테스팅(IAST)**과의 결합을 통해 오탐을 줄이고 취약 코드 위치를 정밀 추적하는 추세.
- **환경 격리와 CI/CD 스캔 분리 거버넌스 결단**: 파괴적 공격 시도로 인한 데이터 오염과 트랜잭션 부작용을 원천 차단하기 위해 격리된 전용 스테이징 환경을 구축하고, CI 파이프라인의 고속 베이스라인 스캔과 야간 정밀 풀 스캔을 이원화하는 공학적 운영 거버넌스 확보 필요.

#### 한줄 요약
- DAST는 API 사양 연동 및 IAST 하이브리드 체계로 고도화되고 있으며, 운영 데이터 오염 방지를 위한 테스트 격리와 CI/CD 스캔 이원화 전략이 필수적이다.
