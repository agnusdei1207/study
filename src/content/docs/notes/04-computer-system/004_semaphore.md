```text
[세마포어] ◀━━ 머리: Ⅶ 내 의견 (휴먼 에러로 인한 데드락 방지를 위해 모니터/고수준 동기화 래핑 강제)
 ┃
 ┣━ Ⅰ 개요 ───── 임계 구역 동시 진입 시 경쟁 상태 발생 → 원자적 카운터 기반 n개 자원 접근 제어
 ┣━ Ⅱ 특징 ───── 원자적 P·V 연산 · 카운팅/이진 지원 · 대기 큐 기반 블로킹 · 소유권 없음
 ┣━ Ⅲ 구조 ───── 정수형 변수 S · 프로세스 대기 큐(Wait Queue) · P 연산(wait) · V 연산(signal)
 ┣━ Ⅳ 흐름 ───── ① P(S) 호출(S 감소) → ② S < 0 이면 큐 대기(Sleep) → ③ 작업 완료 → ④ V(S) 호출(S 증가 및 Wakeup)
 ┣━ Ⅴ 비교 ───── 세마포어 vs 뮤텍스 vs 모니터
 ┗━ Ⅵ 실무 ───── P-V 연산 순서 오류 / 우선순위 역전(Priority Inversion) / 바쁜 대기(Spinlock)
```

## 한 줄 본질
- 공유 자원에 복수 프로세스가 무제한 접근할 때 발생하는 경쟁 상태(Race Condition) → 정수형 카운터 S와 원자적 P/V 연산으로 사용 가능한 자원 개수를 관리하고 부족 시 대기 큐로 재움 → 동시 접근 통제 및 동기화 보장 / 개발자의 P/V 호출 순서 실수 시 교착상태 유발

## 핵심 그림
```text
[ 초기 자원 카운트: S = 2 ]

Process A: P(S) ──> S=1 (즉시 통과) ──> [ 임계 구역 (Critical Section) ] ──> V(S) ──> S 증가
Process B: P(S) ──> S=0 (즉시 통과) ──> [ 임계 구역 (Critical Section) ] ──> V(S) ──> S 증가
                                                    │
Process C: P(S) ──> S=-1 (자원 없음)                │
                         │                          │ (V 호출 시)
                         v                          v
             [ 대기 큐: Sleep(Process C) ] ──────> Wakeup(Process C)
```

## 핵심 용어
- P 연산(Proberen/Wait): 자원 카운트 S를 1 감소시키고, S가 음수이면 해당 프로세스를 대기 큐에 넣고 수면(Block) 상태로 전환
- V 연산(Verhogen/Signal): 자원 카운트 S를 1 증가시키고, 대기 큐에 프로세스가 있으면 하나를 깨워(Wakeup) 준비 큐로 이동

## 핵심 통찰
- 이진 세마포어(Binary Semaphore)와 뮤텍스는 유사하나 본질적 차이가 있음 → 뮤텍스는 '락을 획득한 스레드만 해제'할 수 있는 소유권(Ownership)이 있으나, 세마포어는 신호(Signal) 기제이므로 한 프로세스가 P를 하고 다른 프로세스가 V를 호출할 수 있음
- 바쁜 대기(Busy Waiting) 방식의 스핀락 세마포어는 임계 구역이 매우 짧고 멀티코어일 때 문맥 교환 비용을 아끼지만, 단일 코어나 긴 작업에서는 극심한 CPU 사이클 낭비 초래
- 개발자가 P-P(중복 대기)나 V 누락을 범하면 시스템 전반의 교착상태로 직결되므로 최신 언어는 세마포어를 날것으로 쓰지 않고 모니터나 락 가드로 감싸서 제공함

## 이웃 토픽과 구분
- 세마포어 vs 모니터: 세마포어 = P/V 연산을 개발자가 수동 제어하는 저수준 동기화 / 모니터 = 언어·컴파일러 레벨에서 상호배제를 자동 보장하는 객체 지향적 고수준 캡슐화

## 문제·원인·대책
- 사례: 139회 기출 프로세스 동기화 및 화성 탐사선 패스파인더호의 우선순위 역전 장애
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 저순위 작업이 락을 쥔 상태에서 고순위 작업이 블로킹되어 실시간 마감 초과 | 중간 우선순위 작업이 저순위 작업을 선점하여 V 연산 지연 (우선순위 역전) | 우선순위 상속 프로토콜(Priority Inheritance Protocol) 적용 | 락을 쥔 저순위 작업의 우선순위를 고순위로 임시 승격시켜 빠른 해제 유도 |
| 특정 스레드의 예외 발생으로 V 연산 미호출에 따른 영구 교착 | 예외 처리 블록(Catch/Finally) 누락으로 자원 카운트 미반납 | RAII 패턴 기반 스코프 락(Lock Guard) 및 Auto-closeable 적용 | 함수 스코프 이탈 시 자동 자원 반납 보장 |

## 내 의견
- [저수준 세마포어 직접 사용 지양 및 동시성 컬렉션 채택] 수작업 P/V 배치는 코드 규모가 커질수록 교착상태와 경쟁 상태를 추적하기 불가능에 가까움 → 나라면: 애플리케이션 개발 시 `java.util.concurrent`나 언어 표준 세마포어 직접 호출을 코드 리뷰 규칙으로 제한하고, 고수준의 채널(Channel), 액터(Actor) 모델 또는 블로킹 큐(BlockingQueue)로 추상화하여 휴먼 에러 원천 차단
