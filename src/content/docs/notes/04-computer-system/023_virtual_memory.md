## 답안 골격
```text
[가상 메모리] ◀━━ 머리: Ⅶ 내 의견 (Huge Page 적용과 정밀한 페이지 부재(PFF) 제어를 통한 MMU 오버헤드 최소화)
 ┃
 ┣━ Ⅰ 개요 ───── 물리 메모리(RAM) 용량 한계 및 주소 공간 충돌 → 보조기억장치를 활용한 논리적 주소 확장
 ┣━ Ⅱ 특징 ───── 주소 공간 격리(보안) · 불연속 메모리 적재 · 프로세스별 4GB/128TB 가상 공간 · 요구 페이징
 ┣━ Ⅲ 구조 ───── MMU + 페이지 테이블(Page Table) + TLB(고속 변환 캐시) + 스왑 영역(Swap Space)
 ┣━ Ⅳ 흐름 ───── ① 가상 주소 생성 → ② TLB 조회(Hit/Miss) → ③ 페이지 테이블 참조 → ④ 필요 시 페이지 부재(Page Fault) 인터럽트 및 스왑 인
 ┣━ Ⅴ 비교 ───── 페이징(Paging: 고정) vs 세그멘테이션(Segmentation: 가변) vs 단편화(내부 vs 외부)
 ┗━ Ⅵ 실무 ───── 페이지 부재 빈발에 따른 스래싱(Thrashing) / TLB 캐시 미스 오버헤드 / OOM Killer 동작
```
- 필수 키워드: MMU(Memory Management Unit) · TLB · 페이징 · 페이지 테이블 · 페이지 부재(Page Fault) · 요구 페이징(Demand Paging)
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 주소 변환 아키텍처 도식 → Ⅴ 페이징 vs 세그멘테이션 비교 / 25점 = Ⅰ~Ⅶ 전개, Ⅳ 페이지 부재 핸들링 6단계와 Ⅵ 대용량 메모리 환경 Huge Page 최적화
- 기출: 139회 4교시 `가상메모리(개념, 필요성, 주소변환 메커니즘, 스래싱 해결방안)`

## 한 줄 본질
- 물리 RAM 크기를 초과하는 대규모 프로그램 실행 불가 및 프로세스 간 물리 주소 충돌 위험 → MMU 하드웨어와 페이지 테이블을 통해 논리 가상 주소를 물리 RAM 및 디스크 스왑 영역으로 동적 매핑 → 메모리 보호 및 무한에 가까운 가상 주소 공간 제공 / 주소 변환(TLB Miss) 오버헤드 및 페이지 부재 시 디스크 I/O 지연 발생

## 핵심 그림
```text
[ CPU 가상 주소: Virtual Address (VPN | Offset) ]
                      │
                      ├─(1. TLB 고속 캐시 조회)──[ TLB Hit: 즉시 물리 주소 PFN 결합 ]
                      │
                      v (TLB Miss 시)
+─────────────────────────────────────────────────────────────+
|             페이지 테이블 (Page Table in RAM)               |
|   VPN (Page #)  │ PFN (Frame #) │ 유효 비트 (Valid/Invalid) |
|  ───────────────┼───────────────┼────────────────────────── |
|      Page 0     │    Frame 5    │ 1 (RAM 적재됨)            |
|      Page 1     │       -       │ 0 (디스크 스왑에 존재)    |──> (Page Fault 발생!)
+─────────────────────────────────────────────────────────────+
                                                                     │
            ┌────────────────────────────────────────────────────────┘
            v (OS 커널의 Page Fault 핸들러)
[ 디스크 스왑 영역(Swap Space)에서 빈 프레임으로 Page 로딩 및 테이블 갱신 ]
```

## 핵심 용어
- MMU(Memory Management Unit): CPU 내부에 탑재되어 가상 주소를 물리 메모리 주소로 하드웨어 레벨에서 고속 변환하고 메모리 접근 권한을 검사하는 장치
- TLB(Translation Lookaside Buffer): 최근에 변환된 가상 페이지-물리 프레임 매핑 정보를 보관하는 초고속 하드웨어 연관 캐시(TLB Hit 시 1클록 변환)
- 요구 페이징(Demand Paging): 프로그램 실행 시 전체를 메모리에 올리지 않고, 실제로 CPU가 접근하여 페이지 부재가 발생하는 순간에만 메모리로 적재하는 지연 로딩(Lazy Loading) 기법

## 핵심 통찰
- 가상 메모리의 핵심은 '메모리 크기의 환상'뿐만 아니라 '프로세스 간의 완벽한 메모리 격리(Memory Protection)'임 → 각 프로세스는 자신이 시스템 전체 메모리를 독점한다고 착각하며, 남의 주소 공간에 절대 접근 불가
- 64비트 시스템에서 가상 주소 공간은 128TB에 달하지만 다단계 페이지 테이블(Multi-level Page Table)을 사용하여 실제로 사용하는 페이지에 대해서만 테이블 엔트리를 동적 할당하므로 메모리 낭비가 없음
- RAM이 부족해져 페이지 교체(Page Replacement)가 너무 잦아지면 CPU가 실제 연산은 못 하고 페이징 I/O만 수행하는 '스래싱(Thrashing)'에 빠지므로, 워킹셋(Working Set) 유지가 필수적임

## 이웃 토픽과 구분
- 페이징 vs 세그멘테이션: 페이징 = 메모리를 고정 크기(4KB) 블록으로 분할(외부 단편화 해결, 내부 단편화 존재) / 세그멘테이션 = 논리적 의미 단위(코드, 데이터, 스택)로 가변 크기 분할(내부 단편화 해결, 외부 단편화 발생)
