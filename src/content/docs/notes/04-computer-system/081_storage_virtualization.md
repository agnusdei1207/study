## 한 줄 본질
- 서로 다른 제조사의 외장 스토리지를 따로 운영하면 특정 장비는 용량이 부족하고 다른 장비는 남아도는 파편화가 발생함 → 여러 물리 스토리지를 소프트웨어 계층에서 단일 거대 가상 풀(Pool)로 묶어 호스트에 논리 볼륨을 동적 할당 → 자원 활용률 극대화 및 무중단 데이터 이전 / 가상화 계층 경유에 따른 미세한 I/O 지연 및 장애 포인트 집중 위험

## 핵심 용어
- 씬 프로비저닝(Thin Provisioning): 가상 볼륨 생성 시 실제 물리 디스크를 미리 할당하지 않고, 애플리케이션이 실제로 데이터를 기록할 때만 물리 블록을 실시간 동적 할당하는 기술
- 인밴드(In-Band) 가상화: 호스트와 물리 스토리지 사이의 데이터 경로 상에 가상화 장비가 직접 위치하여 모든 I/O와 메타데이터를 직접 제어하는 방식
- 아웃오브밴드(Out-of-Band) 가상화: 제어 경로(메타데이터)와 실제 데이터 전송 경로를 분리하여, 호스트가 메타데이터 서버로부터 주소만 받고 실제 I/O는 스토리지와 직접 수행하는 방식

## 핵심 통찰
- 스토리지 가상화의 꽃은 '무중단 마이그레이션'임 → 노후화된 스토리지를 신규 스토리지로 교체할 때 서비스를 내리지 않고도 가상 볼륨 매핑만 슬그머니 변경하여 백그라운드 데이터 복제를 수행함
- 가상화가 없으면 디스크 낭비율이 60%에 달함 → '혹시 몰라서' 넉넉하게 할당해 둔 팻 프로비저닝(Thick) 공간을 씬 프로비저닝으로 회수하여 스토리지 구매 예산을 절반 이하로 줄임
- 현대의 스토리지 가상화는 곧 'SDS(Software-Defined Storage)'임 → 비싼 전용 하드웨어 SAN 스토리지 대신 범용 x86 서버들에 Ceph, vSAN을 깔아 분산 스토리지 풀로 묶는 소프트웨어 중심 패러다임으로 완전 전환됨

## 이웃 토픽과 구분
- 서버 가상화 vs 스토리지 가상화: 서버 가상화 = 하이퍼바이저가 CPU/RAM을 가상머신 단위로 분할 / 스토리지 가상화 = 컨트롤러/소프트웨어가 이기종 물리 블록 디스크들을 단일 LUN 풀로 통합

## 내 의견
- [쿠버네티스 CSI 표준과 연동된 클라우드 네이티브 SDS 가상화 표준화] 하드웨어 박스 기반의 네트워크 스토리지 가상화는 멀티 클라우드 및 컨테이너 환경에서 유연성이 떨어짐 → 나라면: 오픈소스 Ceph/Rook 기반의 소프트웨어 정의 스토리지(SDS)를 표준 백본으로 채택하고, 쿠버네티스 CSI(Container Storage Interface) 드라이버를 통해 파드 생성 시 블록, 파일, 오브젝트 가상 볼륨이 1초 만에 자동 생성·바인딩되는 선언적 스토리지 파이프라인 구축
