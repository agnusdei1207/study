## 답안 골격
```text
[은행가 알고리즘] ◀━━ 머리: Ⅶ 내 의견 (동적 클라우드 환경의 최대 요구량 예측 불가 극복을 위한 준정적 풀링 격리)
 ┃
 ┣━ Ⅰ 개요 ───── 교착상태 예방의 자원 낭비·탐지의 롤백 비용 → 안전상태 검증 기반 동적 회피
 ┣━ Ⅱ 특징 ───── 안전 순서열 보장 · 가상 할당 시뮬레이션 · Need <= Work 조건 검사
 ┣━ Ⅲ 구조 ───── Available[m] · Max[n][m] · Allocation[n][m] · Need[n][m]
 ┣━ Ⅳ 흐름 ───── ① 자원 요청(Request <= Need) → ② 가상 할당 → ③ 안전성 알고리즘 검사 → ④ 승인 또는 대기
 ┣━ Ⅴ 비교 ───── 자원 할당 그래프(단일 자원) vs 은행가 알고리즘(다중 자원)
 ┗━ Ⅵ 실무 ───── 프로세스 최대 자원량 사전 고정 불가능 / 자원 수 가변 환경의 오버헤드
```
- 필수 키워드: 교착상태 회피(Avoidance) · 안전상태(Safe State) · 안전 순서열 · Need 행렬 · Available 벡터
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 4대 자료구조와 Need 계산식 → Ⅳ 안전성 판정 절차 / 25점 = Ⅰ~Ⅶ 전개, Ⅳ 매트릭스 계산 예시와 Ⅵ 현대 OS 미적용 이유 분석

## 한 줄 본질
- 상호배제·점유대기 등 4대 조건을 깨는 교착상태 예방(Prevention)의 심각한 자원 이용률 저하 → 자원 요청마다 가상으로 할당해 본 뒤 모든 프로세스가 종료 가능한 안전 순서열이 존재하는지 검사 → 교착상태 없는 안전성 보장 / 모든 프로세스의 최대 자원 요구량을 사전에 알아야만 동작 가능

## 핵심 그림
```text
[ 자원 요청: Request_i ]
        │
        ├─> (Request_i <= Need_i ?  No ──> 오류: 최대 요구량 초과)
        │
        ├─> (Request_i <= Available ? No ─> 대기: 자원 부족)
        │
        v [ 가상 할당 (시뮬레이션) ]
        Available  = Available - Request_i
        Allocation = Allocation + Request_i
        Need       = Need - Request_i
        │
        v [ 안전성 알고리즘 검사 (Safety Algorithm) ]
        모든 i에 대해 Need_i <= Work 만족하는 Finish[i]=false 탐색
        │
        ├── (안전 순서열 발견: Safe) ───> 실제 할당 확정
        └── (불안전 상태: Unsafe)  ───> 가상 할당 롤백 및 프로세스 대기
```

## 핵심 용어
- 안전상태(Safe State): 시스템이 각 프로세스에 최대 자원을 할당할 수 있고 교착상태를 발생시키지 않는 '안전 순서열'이 1개 이상 존재하는 상태
- Need 행렬: 각 프로세스가 향후 요청할 수 있는 잔여 자원량 ($Need[i][j] = Max[i][j] - Allocation[i][j]$)

## 핵심 통찰
- 불안전 상태(Unsafe State)가 곧 교착상태(Deadlock)는 아님 → 교착상태는 불안전 상태의 진부분집합이며, 은행가 알고리즘은 교착 위험이 조금이라도 있으면 요청을 거절하므로 자원 활용률이 보수적으로 제한됨
- 프로세스 수와 자원 종류가 많은 현대 분산 시스템에서는 $O(m \times n^2)$ 계산 복잡도로 인해 매 요청마다 알고리즘을 수행하는 비용이 너무 큼
- 현대 범용 OS(Linux, Windows)가 은행가 알고리즘 대신 교착상태를 무시하는 타조 알고리즘(Ostrich Algorithm)을 택한 이유는 최대 자원 소요량을 런타임 전에 선언할 수 없기 때문임

## 이웃 토픽과 구분
- 은행가 알고리즘 vs 자원 할당 그래프(RAG): RAG의 사이클 검출은 자원 인스턴스가 1개일 때만 회피/탐지에 사용 가능 / 은행가 알고리즘은 동일 자원이 여러 개(Multi-Instance)일 때 매트릭스 연산으로 회피 수행

## 문제·원인·대책
- 사례: 138회 기출 교착상태 회피 및 고신뢰 임베디드 실시간 제어 시스템의 자원 경합
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 런타임 스레드의 동적 메모리 요구로 Max 값 산출 불가 | 사용자 입력 및 트래픽에 따라 메모리 할당량이 가변적임 | 고정 슬롯 기반 정적 메모리 풀(Pool) 사전 할당 정책 적용 | 최대 자원량을 고정하여 안전성 판정 조건 충족 |
| 안전성 검사 루프 반복으로 인한 트랜잭션 지연 | 자원 요청 시마다 전체 프로세스 행렬 대상 반복 스캔 | 우선순위 기반 자원 할당 한도(Quota) 격리 및 세마포어 타임아웃 | 검사 오버헤드 없이 임계 구간 블로킹 차단 |
