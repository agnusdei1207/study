## 한 줄 본질
- 특정 클라우드 사업자(AWS, Azure, GCP) 종속에 따른 가격 협상력 상실과 리전 단위 단일 장애점(SPOF) 위험 → 2개 이상의 이기종 퍼블릭 클라우드 자원을 CMP와 컨테이너 추상화 계층으로 통합 관리 → 서비스 연속성 및 최적 서비스 선택권 확보 / 클라우드 간 데이터 전송(Egress) 비용 폭증 및 보안 정책 파편화

## 핵심 용어
- CMP(Cloud Management Platform): 이기종 클라우드 인프라의 자원 할당, 비용 분석, 보안 규제 준수를 단일 대시보드에서 오케스트레이션하는 통합 관리 솔루션
- 데이터 이그레스(Egress Fee): 클라우드 내부에서 외부 인터넷이나 타 클라우드로 데이터를 전송할 때 부과되는 기가바이트당 통신 요금

## 핵심 통찰
- 멀티 클라우드의 동기는 단순 백업이 아니라 'Best-of-Breed(특화 기능 조합)'임 → 분석/AI는 GCP(BigQuery/TPU), 엔터프라이즈 통합은 Azure, 대규모 범용 컴퓨팅은 AWS를 조합하여 경쟁력 극대화
- 그러나 인프라를 무작정 쪼개면 CSP 간 데이터 동기화로 인해 천문학적인 이그레스 비용이 발생하고 지연 시간이 수십 ms 증가하므로, 데이터베이스는 주 리전에 두고 연산만 분산하는 트래픽 토폴로지 설계가 선행되어야 함
- 멀티 클라우드의 성공 열쇠는 '클라우드 중립적 기술 스택'임 → 각 사의 고유 PaaS(예: DynamoDB, Cloud Spanner)를 남용하면 멀티 클라우드가 불가능해지며, 컨테이너(K8s)와 오픈소스 표준(PostgreSQL, Kafka) 중심의 패키징이 필수적임

## 이웃 토픽과 구분
- 멀티 클라우드 vs 하이브리드 클라우드: 멀티 클라우드 = 서로 다른 2개 이상의 퍼블릭 CSP를 결합 / 하이브리드 클라우드 = 온프레미스(프라이빗) 데이터센터와 퍼블릭 클라우드를 연계

## 문제·원인·대책
- 사례: 135회 기출 멀티 클라우드 운영 시 클라우드 간 데이터 전송 비용 폭증 및 보안 감사 실패
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 매월 수억 원의 클라우드 간 데이터 복제 이그레스(Egress) 비용 청구 | 이기종 클라우드 간 빈번한 원시 데이터 실시간 동기화 | 분산 캐시 계층 도입 및 데이터 중복제거/압축 배치 전송, DCI 전용선 연계 | 클라우드 간 트래픽 60% 이상 절감 |
| AWS와 Azure 간 서로 다른 보안 그룹(SG) 설정으로 침해 사고 발생 | CSP별 보안 모델 및 권한 체계(IAM)의 파편화 | 클라우드 보안 태세 관리(CSPM) 및 코드형 보안(Policy-as-Code, OPA) 일원화 | 이기종 인프라의 단일 보안 컴플라이언스 기준 강제 |

## 내 의견
- [멀티 클라우드 환상 경계: 복잡도 비용(Complexity Cost)의 냉정한 산정] 벤더 락인을 피하려다 이기종 클라우드 관리 인력 분산과 운영 복잡도 증가로 배보다 배꼽이 더 커지는 기업이 속출 → 나라면: 초기에는 단일 CSP의 풍부한 매니지드 서비스를 적극 활용하여 비즈니스 출시를 가속화하되, 컨테이너 패키징과 테라폼 코드 모듈화를 통해 '이동 가능성(Portability)'만 확보하고, 실제 2차 클라우드 확장은 규제 요건(DR 의무화)이나 뚜렷한 단가 절감 타당성이 입증될 때 단계적으로 추진
