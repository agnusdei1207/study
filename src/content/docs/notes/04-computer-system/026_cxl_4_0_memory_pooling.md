## 한 줄 본질
- 서버 섀시마다 갇혀 있는 유휴 메모리 낭비(Stranded Memory, 전체의 30~50%)와 CPU 소켓당 메모리 슬롯 물리적 확장 한계 → PCIe 물리 계층 위에서 하드웨어 기반 캐시 일관성을 제공하는 CXL 프로토콜을 통해 수백 대 서버가 공유하는 거대한 외부 메모리 풀(Pool) 구축 → 메모리 이용률 극대화 및 대규모 AI 인메모리 처리 지원 / 로컬 DDR 대비 50~100ns 추가 접근 지연 발생

## 핵심 용어
- 스트랜디드 메모리(Stranded Memory): CPU 코어는 이미 100% 포화되었으나 할당되지 못하고 특정 서버 안에 갇혀 낭비되는 유휴 메모리
- CXL.mem: 호스트 CPU가 원격 CXL 메모리 디바이스를 표준 로컬 메모리 읽기/쓰기(Load/Store) 명령어로 직접 접근할 수 있도록 해주는 메모리 전용 프로토콜
- GFAM(Global Fabric Attached Memory): CXL 3.0 이상에서 정의된 패브릭 부착형 공유 메모리로, 여러 호스트가 단일 메모리 영역을 네트워크 복사 없이 직접 동시 공유

## 핵심 통찰
- CXL의 혁명성은 '스토리지(파일/블록)처럼 취급되던 외부 네트워크를 CPU가 포인터(메모리 주소)로 직접 역참조(Deref)할 수 있게 만든 것'임 → RDMA의 소프트웨어 스택 오버헤드를 걷어내고 순수 하드웨어 나노초 통신 구현
- CXL 메모리는 로컬 메모리(Near Memory)보다 지연이 약 50~100ns 길기 때문에, OS 커널이 핫 데이터는 CPU 직결 DDR5에 두고 콜드 데이터는 CXL 풀로 자동 이동시키는 '계층형 메모리 관리(Auto-tiering)'가 병행되어야 함
- 초거대 LLM 추론 시 수백 기가바이트의 모델 가중치와 KV 캐시를 고가의 GPU HBM에 전량 올리지 않고 CXL 공유 메모리 풀로 오프로딩함으로써 AI 인프라 비용을 극적으로 낮춤

## 이웃 토픽과 구분
- CXL 메모리 풀링 vs RDMA: RDMA = 네트워크 인터페이스(NIC)를 거치는 메시지 패킷 통신(마이크로초 지연) / CXL = PCIe 버스 수준의 하드웨어 캐시 일관성 로드/스토어 통신(나노초 지연)

## 문제·원인·대책
- 사례: 초대규모 클라우드 가상화 데이터센터에서 메모리 단편화 및 VM 프로비저닝 실패
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 특정 호스트의 메모리 고갈로 신규 고용량 VM 생성 실패 (타 호스트는 메모리 유휴) | 노드 간 메모리 공유가 불가능한 전통적 셰어드 낫싱(Shared Nothing) 구조 | CXL 4.0 스위치 기반 메모리 풀링 어플라이언스 도입 | 서버 간 메모리 유연 동적 대여로 유휴 메모리 80% 회수 |
| CXL 원격 메모리 접근 시 지연시간 증가로 인한 애플리케이션 처리 지연 | 비일관적 메모리 접근 및 NUMA 원격 노드 패널티 누적 | 커널 레벨의 자동 메모리 티어링(AutoNUMA / TPP) 적용 | 핫 데이터 로컬 유지로 성능 저하 5% 이내 억제 |
