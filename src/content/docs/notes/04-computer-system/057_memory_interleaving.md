## 한 줄 본질
- DRAM은 셀을 읽은 뒤 재충전(Precharge)하는 데 수십 사이클이 걸려 연속 읽기 시 CPU가 대기해야 함 → 연속된 물리 메모리 주소를 여러 개의 독립된 메모리 뱅크에 번갈아 분산 배치 → 이전 뱅크가 충전되는 동안 다음 뱅크에서 데이터를 읽어 지연을 은폐 / 동일 뱅크 연속 접근 시 뱅크 충돌 발생

## 핵심 그림
```text
[ 상위 인터리빙 vs 하위 인터리빙 주소 구조 및 뱅크 배치 ]

(1) 하위 인터리빙 (Low-Order Interleaving: 성능 지향, 연속 주소 병렬화)
 주소 비트: [       뱅크 내 주소 (상위 비트)       | 뱅크 번호 (하위 비트) ]
                                                            │
    Bank 0 (주소 0, 4, 8, 12...) <──────────────────────────┤ (00)
    Bank 1 (주소 1, 5, 9, 13...) <──────────────────────────┤ (01)  ==> 연속 주소 접근 시
    Bank 2 (주소 2, 6, 10, 14..) <──────────────────────────┤ (10)      4개 뱅크가 동시 병렬 동작!
    Bank 3 (주소 3, 7, 11, 15..) <──────────────────────────┘ (11)

(2) 상위 인터리빙 (High-Order Interleaving: 모듈 단위 확장, 장애 격리)
 주소 비트: [   뱅크 번호 (상위 비트)   |        뱅크 내 주소 (하위 비트)       ]
                      │
    Bank 0 (주소 0 ~ 1023) ───── 한 뱅크가 가득 차면 다음 뱅크로 이동 (병렬성 없음)
```

## 핵심 용어
- 메모리 뱅크(Memory Bank): 독립적으로 읽기/쓰기 동작과 프리차지(Precharge)를 수행할 수 있는 DRAM 내부의 물리적 하위 저장 단위
- 뱅크 충돌(Bank Conflict): 이미 행 활성화(Row Active) 또는 프리차지 중인 동일한 뱅크에 다시 접근 요청이 발생하여 I/O 파이프라인이 정지(Stall)되는 현상
- 멀티 채널(Multi-Channel): 메모리 컨트롤러와 DIMM 사이에 64비트 데이터 버스를 2개(듀얼), 4개(쿼드), 8개(옥타)로 독립 구성하여 물리적 대역폭을 배수로 확장하는 기술

## 핵심 통찰
- 하위 인터리빙은 '공간적 국소성'의 친구임 → CPU가 캐시 라인(64바이트)을 채우기 위해 연속 주소를 요청하거나 배열을 순차 순회할 때 하위 비트가 계속 바뀌므로 모든 뱅크가 쉬지 않고 파이프라인으로 데이터를 뿜어냄
- 단일 뱅크 지연시간 자체는 1나노초도 줄어들지 않음 → 메모리 칩 하나의 물리적 응답 시간은 그대로이지만, 여러 칩의 지연 시간을 시간 축에서 겹치게(Overlap) 만듦으로써 시스템 전체의 '처리량(대역폭)'을 올리는 구조임
- 메모리를 홀수로 꽂으면 인터리빙이 깨짐 → 듀얼 채널 슬롯에 램 1개만 꽂거나 용량이 다른 램을 비대칭으로 장착하면 인터리빙 대역폭이 절반으로 추락(Flex Mode)하므로 반드시 동일 규격 쌍(Pair) 배치가 필수적임

## 이웃 토픽과 구분
- 메모리 인터리빙 vs 디스크 스트라이핑(RAID 0): 인터리빙 = 나노초 단위 DRAM 버스에서 하드웨어 컨트롤러가 주소 비트로 뱅크 파이프라이닝 / 스트라이핑 = 밀리초/마이크로초 단위 스토리지에서 블록 단위 I/O 병렬화
