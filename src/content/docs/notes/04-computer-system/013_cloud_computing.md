## 답안 골격
```text
[클라우드 컴퓨팅] ◀━━ 머리: Ⅶ 내 의견 (클라우드 네이티브 아키텍처 전환과 FinOps 기반 비용 가시성 확보)
 ┃
 ┣━ Ⅰ 개요 ───── 온프레미스 하드웨어 선투자(CapEx) 한계 → 인터넷 경유 온디맨드 IT 자원 풀링(OpEx)
 ┣━ Ⅱ 특징 ───── 주문형 셀프서비스 · 광대역 네트워크 접근 · 자원 풀링 · 신속한 탄력성 · 측정 서비스 (NIST 5대 특성)
 ┣━ Ⅲ 구조 ───── 서비스 모델(IaaS, PaaS, SaaS) + 배포 모델(Public, Private, Hybrid, Community)
 ┣━ Ⅳ 흐름 ───── ① 자원 요청(API/콘솔) → ② 오케스트레이터 가상 자원 프로비저닝 → ③ 서비스 소비 → ④ 실시간 미터링·과금
 ┣━ Ⅴ 비교 ───── IaaS vs PaaS vs SaaS (관리 책임 영역 비교: Shared Responsibility Model)
 ┗━ Ⅵ 실무 ───── 클라우드 비용 폭증(FinOps 필요) / 벤더 락인 / 데이터 주권 및 정보보호 규제
```
- 필수 키워드: NIST 5대 특징 · IaaS/PaaS/SaaS · 온디맨드 · 자원 풀링 · 공유 책임 모델(Shared Responsibility)
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 서비스/배포 모델 매트릭스 → Ⅴ 관리 책임 모델 / 25점 = Ⅰ~Ⅶ 전개, NIST 5대 특징 구체화 및 Ⅵ 엔터프라이즈 클라우드 전환 전략
- 기출: 139회 1교시 `엣지 컴퓨팅과 클라우드 컴퓨팅 차이점`, 이전 기출 `NIST 클라우드 정의 및 서비스 모델`

## 한 줄 본질
- 서버 조달에 수 주~수 개월이 소요되는 물리 인프라 구축의 경직성과 막대한 초기 자본 투자(CapEx) → 인터넷 기반의 대규모 가상화 풀에서 컴퓨팅·스토리지·네트워크를 주문형(On-demand)으로 즉시 할당받고 사용량만큼만 지불(OpEx) → 사업 출시 속도 극대화 및 탄력적 확장 / 네트워크 의존성 심화 및 클라우드 비용 통제 난항

## 핵심 용어
- 주문형 셀프서비스(On-demand Self-service): 사용자가 CSP 담당자와의 인적 상호작용 없이 웹 콘솔이나 API를 통해 필요할 때 서버·스토리지 자원을 즉시 프로비저닝하는 특성
- 공유 책임 모델(Shared Responsibility Model): 클라우드 보안에 있어 물리 보안과 인프라는 CSP가 책임지고, 게스트 OS, 데이터, 애플리케이션 보안은 고객이 분담하는 보안 책임 체계

## 핵심 통찰
- 클라우드의 본질은 '남의 컴퓨터를 빌려 쓰는 것'이 아니라 '인프라를 코드로 다루는 소프트웨어적 민첩성(Agility)'에 있음 → 레거시 서버를 그대로 클라우드 VM으로 옮기는 단순 Lift-and-Shift는 비용만 30% 이상 증가
- 클라우드 전환 후 기업이 겪는 가장 큰 위기는 '비용 충격'임 → 개발자가 리소스를 클릭 한 번으로 무제한 띄울 수 있어 방치된 유휴 자원으로 인한 월말 요금 폭탄이 일상화되므로 FinOps 조직과 자동 태깅 거버넌스가 필수
- 보안 사고의 95% 이상은 CSP 결함이 아닌 '고객의 잘못된 설정(Misconfiguration)'에서 발생함 → 공개된 S3 버킷, 루트 계정 키 유출 등 고객 책임 영역에 대한 지속적 보안 감시(CSPM) 필요

## 이웃 토픽과 구분
- IaaS vs PaaS: IaaS = OS와 네트워크를 직접 제어하는 가상 인프라 / PaaS = 개발자가 코드와 데이터만 올리면 실행 환경 전체를 플랫폼이 알아서 관리
