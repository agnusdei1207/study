## 한 줄 본질
- 빅데이터 및 AI 파이프라인은 태스크 간 선후 의존성(DAG) 때문에 선행 작업이 끝나길 기다리는 동안 대규모 컴퓨팅 자원이 놀게 됨 → 임계 경로 상의 핵심 작업을 위한 슬롯 예약을 보장하면서 남는 빈 시간대에 다른 독립 태스크를 끼워 넣어(Backfill) 실행 → 파이프라인 전체 완료 시간(Makespan) 단축 / 태스크 간 의존성 계산 복잡도 증가

## 핵심 그림
```text
[ 워크플로 DAG 의존성 그래프(좌) 및 백필링을 통한 유휴 슬롯 채우기(우) ]

[ 워크플로 의존 관계 (DAG) ]             [ 시간-자원 공간의 백필 스케줄링 ]
        [ Task A ] (대형 작업)
       /          \                      자원 (Slots)
 [ Task B ]    [ Task C ] (소형)          ▲
       \          /                  100  │┌──────────────────┐
        [ Task D ] (최종 합류)            ││ Task A (80 슬롯) │  ┌─────────────────┐
                                          ││ (임계 경로 예약) │  │ Task D (100 슬롯)│
                                      20  │└────────┬─────────┘  │ (예약 완료 후)   │
                                          │ [유휴]  │ Task C     └─────────────────┘
                                          │ 20슬롯  │ (백필 실행!)
                                       0  └─────────┴─┴──────────┴─────────────────> 시간
                                                      T1         T2
    * Task A가 끝나기 전 남는 20개 슬롯에 독립적인 Task C를 끼워 넣어 전체 완료 시간 단축!
```

## 핵심 용어
- DAG(Directed Acyclic Graph): 태스크들 간의 방향성과 선후 의존 관계를 정의하되, 무한 루프(Cycle)가 존재하지 않는 워크플로 표현 그래프
- HEFT(Heterogeneous Earliest Finish Time): 이기종 분산 노드 환경에서 각 태스크의 예상 완료 시간을 계산하여 가장 빨리 끝나는 노드에 우선 배정하는 대표적 정적 스케줄링 알고리즘
- 메이크스팬(Makespan): 워크플로의 첫 번째 태스크가 실행을 시작한 시점부터 마지막 최종 태스크가 완료될 때까지 걸린 총 소요 시간

## 핵심 통찰
- 의존성 그래프와 자원 스케줄링의 결합 → 단순 HPC 백필은 독립 작업들 간의 시간 끼워넣기이지만, 워크플로 백필은 상위 노드의 출력을 기다리는 '의존성 대기 시간'을 파악하여 다른 분기의 독립 태스크를 유휴 자원에 배치하는 고차원 최적화임
- 임계 경로(Critical Path)를 건드리면 망함 → 워크플로의 메이크스팬을 결정하는 가장 긴 작업 체인(임계 경로) 상의 태스크는 단 1초도 지연되어서는 안 되므로, 백필되는 태스크는 반드시 임계 경로 작업의 착수 예정 시각 이전에 끝나야만 함
- 데이터 엔지니어링에서의 재처리(Backfill) 의미 포섭 → 아파치 에어플로우(Airflow) 같은 현대 워크플로 엔진에서는 과거의 특정 날짜 구간 데이터를 소급 적용하여 DAG 파이프라인을 재실행하는 행위 역시 '백필'로 명명함

## 이웃 토픽과 구분
- 일반 백필 vs 워크플로 백필: 일반 백필 = 독립 작업 간 유휴 자원 채우기 / 워크플로 백필 = DAG 의존성 제약과 임계 경로 지연 금지를 동시에 만족시키는 복합 스케줄링
