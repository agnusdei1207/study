## 답안 골격
```text
[스레드] ◀━━ 머리: Ⅶ 내 의견 (스레드 풀링 및 락-프리 자료구조를 통한 문맥 교환과 동기화 비용 최적화)
 ┃
 ┣━ Ⅰ 개요 ───── 프로세스 생성·문맥 교환의 무거운 비용 한계 → 프로세스 내 자원 공유형 경량 실행 단위
 ┣━ Ⅱ 특징 ───── 자원 공유(Code·Data·Heap) · 독립 스택·PC · 빠른 문맥 교환 · 동기화 위험
 ┣━ Ⅲ 구조 ───── 공유 영역(Code/Data/Heap/Files) + 독립 영역(Thread ID/PC/Registers/Stack) + TCB
 ┣━ Ⅳ 흐름 ───── ① 스레드 생성(pthread_create) → ② TCB 등록 및 스택 할당 → ③ 동시 실행 → ④ join/종료
 ┣━ Ⅴ 비교 ───── 프로세스 vs 스레드 / 사용자 레벨 스레드(ULT) vs 커널 레벨 스레드(KLT)
 ┗━ Ⅵ 실무 ───── 스레드 안전성(Thread Safety) / 경쟁 상태(Race Condition) / C10K 스레드 오버헤드
```
- 필수 키워드: 경량 프로세스(LWP) · TCB(Thread Control Block) · 스택 독립 · 힙/데이터 공유 · 문맥 교환(Context Switching) · 스레드 풀
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 프로세스 내 스레드 메모리 공유 도식 → Ⅴ 프로세스 vs 스레드 비교 / 25점 = Ⅰ~Ⅶ 전개, Ⅳ TCB 문맥 교환과 Ⅵ 멀티스레드 동기화(Thread Safe) 기법
- 기출: 140회 1교시 `스레드 및 프로세스 메모리 관리`, 이전 107·116회 `멀티스레딩 모델 및 동기화`

## 한 줄 본질
- 프로세스 간 통신(IPC)의 높은 오버헤드와 프로세스 문맥 교환 시 가상 메모리 매핑(TLB) 플러시 비용 → 프로세스의 주소 공간(Code, Data, Heap)을 공유하면서 독립적인 PC 레지스터와 스택만 갖는 경량 실행 단위 구현 → 동시성 처리량 극대화 및 문맥 교환 지연 단축 / 단일 스레드의 메모리 오염이나 예외 발생 시 전체 프로세스 강제 종료 위험

## 핵심 그림
```text
+---------------------------------------------------------------+
|                      프로세스 주소 공간 (Process)             |
|  +---------------------------------------------------------+  |
|  | 코드 영역 (Code) / 데이터 영역 (Data) / 힙 영역 (Heap)  |  |
|  | 열린 파일 디스크립터 (Open Files) / 시스템 자원         |  |
|  +---------------------------------------------------------+  |
|        │                        │                        │    |
|        v                        v                        v    |
|  +------------+           +------------+           +------------+
|  | Thread 1   |           | Thread 2   |           | Thread 3   |
|  | - PC Reg   |           | - PC Reg   |           | - PC Reg   |
|  | - Stack    |           | - Stack    |           | - Stack    |
|  | - TCB 1    |           | - TCB 2    |           | - TCB 3    |
|  +------------+           +------------+           +------------+
+---------------------------------------------------------------+
```

## 핵심 용어
- TCB(Thread Control Block): 스레드 ID, 프로그램 카운터(PC), 레지스터 세트, 스택 포인터 등 스레드 문맥 교환에 필요한 최소한의 상태 정보를 담는 커널 자료구조
- 스레드 안전(Thread-Safe): 멀티스레드 환경에서 여러 스레드가 동일 함수나 전역 변수를 동시 호출해도 의도한 대로 오류 없이 올바르게 동작하는 성질

## 핵심 통찰
- 스레드 문맥 교환이 프로세스 문맥 교환보다 월등히 빠른 핵심 이유는 'MMU 페이지 테이블(CR3 레지스터)과 TLB(Translation Lookaside Buffer)를 플러시하지 않기 때문'임
- 멀티스레드가 항상 성능을 보장하지 않음 → 코어 수 이상의 과도한 스레드를 생성하면 스레드 스케줄링 및 문맥 교환 비용이 실제 연산 비용을 압도하는 스레드 스래싱(Thread Thrashing) 발생
- I/O 바운드 워크로드에서 수천~수만 개의 스레드를 유지하는 것은 1스레드당 기본 1MB가량의 스택 메모리를 점유하므로 C10K/C1000K 문제를 유발 → 경량 논블로킹 이벤트 루프(Node.js) 또는 가상 스레드(Java 21 Virtual Thread)로의 전환 가속

## 이웃 토픽과 구분
- 프로세스 vs 스레드: 프로세스 = OS로부터 자원을 할당받는 독립적 실행 단위(격리성 우수, 생성 비용 높음) / 스레드 = 프로세스 내에서 CPU 스케줄링을 받는 실행 단위(자원 공유, 동기화 제어 필수)

## 문제·원인·대책
- 사례: 140회 기출 멀티스레드 기반 웹 서버의 대량 접속 시 Out of Memory(OOM) 장애 및 데이터 불일치
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 요청 급증 시 스레드 수천 개 생성으로 메모리 고갈 및 CPU 100% 점유 | 스레드 무제한 동적 생성 (Thread-per-request 모델) | 스레드 풀(Thread Pool, ExecutorService) 및 워커 스레드 상한 제한 | 자원 예측성 확보 및 문맥 교환 오버헤드 통제 |
| 멀티스레드가 공유 객체 갱신 중 원자성 훼손으로 비정상 잔액 산출 | 임계 구역에 대한 상호배제(Mutual Exclusion) 결여 | Atomic 변수(CAS 연산), ReadWriteLock, 불변 객체(Immutable) 적용 | 락 경합 최소화 및 스레드 세이프 보장 |
