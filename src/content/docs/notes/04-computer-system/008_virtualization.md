## 한 줄 본질
- 단일 서버에 단일 OS만 운영되던 하드웨어의 낮은 이용률(10~15%)과 물리적 확장 한계 → 하이퍼바이저나 컨테이너 엔진 계층을 통해 물리 자원을 논리적 단위로 추상화하고 독립 격리 환경 제공 → 자원 통합 집적도 향상 및 신속한 배포 / 추상화 계층 경유로 인한 성능 오버헤드 및 단일 장애점(SPOF) 위험

## 핵심 그림
```text
  [ Type 1: 베어메탈 가상화 ]                 [ Type 2: 호스트형 가상화 ]
+-------------------------------+       +-------------------------------+
|  Guest OS 1   |  Guest OS 2   |       |  Guest OS 1   |  Guest OS 2   |
+---------------+---------------+       +---------------+---------------+
| Hypervisor (KVM, ESXi, Xen)   |       | Hypervisor (VMware Workstation)|
+-------------------------------+       +-------------------------------+
|  Bare-metal 물리 하드웨어      |       |  Host OS (Linux, Windows)     |
|  (CPU, Memory, Disk, NIC)     |       +-------------------------------+
+-------------------------------+       |  물리 하드웨어                |
                                        +-------------------------------+
```

## 핵심 용어
- 하이퍼바이저(Hypervisor/VMM): 단일 물리 컴퓨터에서 여러 개의 게스트 운영체제를 동시에 독립적으로 구동할 수 있도록 가상화 자원을 중계·통제하는 소프트웨어
- 전가상화(Full Virtualization): 게스트 OS 수정 없이 바이너리 변환(Binary Translation)이나 CPU 하드웨어 지원(Intel VT-x, AMD-V)을 통해 특권 명령을 완벽 에뮬레이션하는 기법
- 반가상화(Para-virtualization): 게스트 OS의 커널을 일부 수정하여 하이퍼바이저에 직접 시스템 콜(Hypercall)을 호출함으로써 에뮬레이션 오버헤드를 줄이는 기법

## 핵심 통찰
- 하이퍼바이저의 핵심 난제는 게스트 OS가 스스로를 최고 특권(Ring 0)이라 믿고 실행하는 '민감 명령어(Sensitive Instruction)'를 트랩하여 호스트 시스템을 보호하는 것임 → 현대 CPU(Intel VT-x)는 하드웨어 루트(Non-root mode)를 지원하여 오버헤드를 5% 미만으로 억제
- 가상화의 영역은 서버(Compute)에 머물지 않고 스토리지 가상화(SDS), 네트워크 가상화(SDN/NFV)로 확장되어 데이터센터 전체가 소프트웨어로 정의되는 SDDC(Software-Defined Data Center)의 근간이 됨
- 완전한 보안 격리와 커널 독립성이 필요한 레거시·멀티테넌트 워크로드는 가상머신(VM)이 필수적이며, 고밀도 패키징과 빠른 확장이 필요한 마이크로서비스는 컨테이너가 주류로 분업화됨

## 이웃 토픽과 구분
- 가상머신(VM) vs 컨테이너: VM = 하이퍼바이저 위에서 게스트 OS 커널을 독립적으로 완전히 부팅(수 GB, 수 분) / 컨테이너 = 호스트 OS 커널을 공유하며 cgroups와 네임스페이스로 프로세스만 격리(수십 MB, 수 초)

## 문제·원인·대책
- 사례: 129회 기출 대규모 가상화 클러스터 운영 시 브로드컴 VMware 라이선스 정책 급변 및 I/O 노이지 네이버(Noisy Neighbor) 문제
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 특정 VM의 디스크 I/O 폭주로 동일 물리 노드 내 타 VM 성능 저하 | 하이퍼바이저 스토리지 큐 자원 경합 (Noisy Neighbor) | 스토리지 I/O 제어(Storage I/O Control, SIOC) 및 vCPU 쿼터 제한 | VM별 공평한 I/O 대역폭 보장 |
| 상용 가상화 솔루션 라이선스 비용 수 배 폭증 | 벤더 종속(VMware) 및 CPU 코어 기반 구독 요금제 강제 전환 | 오픈소스 기반 KVM, OpenStack, KubeVirt 클러스터 마이그레이션 | 운영 비용 통제 및 오픈 표준 인프라 주권 확보 |
