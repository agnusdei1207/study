## 핵심 그림
```text
+-------------------- [ 생성형 AI 산출물 워터마킹 기술 체계 ] --------------------+
|                                                                                 |
|  [ 1. 가시적 표시 (Visible) ]                                                   |
|  - 이미지/영상 우하단 "AI Generated" 텍스트 또는 공식 심볼 오버레이             |
|  - 음성/오디오 도입부 또는 주기적 비프음·안내 멘트 삽입                         |
|                                                                                 |
|  [ 2. 비가시적 표시 (Invisible) ]                                               |
|  +-----------------------------+  +------------------------------------------+  |
|  |   주파수/픽셀 영역 변조     |  |       잠재공간/토큰 변조 (SynthID 등)    |  |
|  | - DCT, DWT 변환 영역에      |  | - LLM 생성 토큰 확률 분포에 특정 패턴     |  |
|  |   인간 시각 비민감 신호 삽입|  |   의사난수(Pseudo-random) 서명 각인      |  |
|  +-----------------------------+  +------------------------------------------+  |
|                                                                                 |
|  [ 3. 콘텐츠 출처 표준 (C2PA: Coalition for Content Provenance and Authenticity)]|
|  - 생성 도구, 모델명, 생성 일시를 X.509 인증서 기반 디지털 서명 후 JUMBF로 결합 |
+---------------------------------------------------------------------------------+
```

## 핵심 용어
- C2PA(Coalition for Content Provenance and Authenticity): 어도비, MS, 인텔 등이 주도하는 오픈 기술 표준으로 콘텐츠의 생성·수정 이력을 위변조 방지 매니페스트로 증명
- SynthID: 구글 딥마인드가 개발한 기술로, 텍스트·이미지·오디오의 품질을 저하시키지 않고 AI 생성 토큰 분포나 고주파 영역에 비가시적 식별 신호를 주입하는 기술
- 재인코딩 공격(Re-encoding Attack): 이미지를 캡처하거나 JPEG 압축률을 극단적으로 변경하여 비가시적 워터마크 데이터를 손상시키는 회피 기법

## 핵심 통찰
- 화면에 로고만 박는 가시적 워터마크는 포토샵의 생성형 채우기(Inpainting)나 단순 크롭으로 1초 만에 제거되므로 단독 대책이 될 수 없음
- 따라서 "육안 고지(가시적)"와 "알고리즘 검출(비가시적)" 및 "암호학적 출처 증명(C2PA)"의 3중 레이어 방어가 필수적임
- 폐쇄형 API(OpenAI, Google)는 워터마크 주입을 강제할 수 있으나, 가중치가 공개된 오픈소스 모델(Llama, Stable Diffusion)은 소스코드 수정으로 워터마크 모듈을 제거할 수 있는 구조적 맹점이 존재함

## 이웃 토픽과 구분
- 워터마킹 vs 저작권 침해 방지: 워터마킹 = "이것이 AI 생성물임"을 증명하는 출처 투명성 기법 / 저작권 보호 = 원작자의 지적재산권 무단 도용을 탐지하고 막는 DRM 기법

## 문제·원인·대책
- 사례: 소셜 미디어 상의 선거 관련 정치가 합성 딥페이크 영상 유포 사건
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| SNS 업로드 과정에서 메타데이터 삭제로 출처 상실 | 플랫폼 서버의 이미지 압축·최적화 시 EXIF/C2PA 데이터 일괄 제거 | SNS 플랫폼의 C2PA 매니페스트 보존 표준 프로토콜 적용 | 배포 후에도 AI 생성 라벨 유지 |
| 오픈소스 모델을 악용한 무표시 딥페이크 대량 생성 | 로컬 구동 모델에 대한 워터마킹 강제 불가 | AI 생성물 판별 탐지기(Deepfake Detector) 모델 플랫폼 필터링 배포 | 유포 단계에서의 자동 차단 |

## 이렇게 출제된다
- 미출제. 예상: "생성형 AI 산출물 표시 의무화에 따른 투명성 가이드라인의 주요 내용과 가시적·비가시적 워터마킹 기술의 원리 및 한계를 설명하시오." → 요구 포인트: Ⅰ 표시 의무 배경 + Ⅲ C2PA 및 비가시적 알고리즘 원리 + Ⅵ 우회 공격과 기술적 극복 방안

## 내 의견
- [워터마크 강제 규제의 오픈소스 우회 한계와 플랫폼 차단 필터링 연계] 생성기(Generator) 단계에서만 워터마크를 강제하면 악의적 해커가 워터마크를 제거한 로컬 모델을 배포할 때 완전히 무력화됨 → 나라면: 생성 단계 워터마킹과 함께 유튜브, X, 인스타그램 등 배포 플랫폼(Distributor) 단계에서 주파수 잔차(Frequency Artifact)를 분석하는 AI 판별 필터를 법적으로 의무화하여 미표시된 AI 생성물을 업로드 즉시 격리하는 공급-유통 양방향 통제 아키텍처를 도입
