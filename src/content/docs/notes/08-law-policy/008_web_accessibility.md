## 답안 골격
```text
[웹 접근성] ◀━━ 머리: Ⅶ 내 의견 (WAI-ARIA 표준 적용 및 프론트엔드 CI/CD 접근성 자동 검사 도입)
 ┃
 ┣━ Ⅰ 개요 ───── 정보 취약계층의 디지털 차별 해소 및 법적 의무 준수(장애인차별금지법)
 ┣━ Ⅱ 특징 ───── 보편적 설계(Universal Design) · 4대 원칙(KWCAG 2.2) · 스크린리더/키보드 완결
 ┣━ Ⅲ 구조 ───── 인식의 용이성 + 운용의 용이성 + 이해의 용이성 + 견고성 (4대 원칙 24개 항목)
 ┣━ Ⅳ 흐름 ───── 요구 분석 → 시맨틱 마크업 설계 → WAI-ARIA 적용 → 자동/수동 진단 → 품질마크 획득
 ┣━ Ⅴ 비교 ───── 웹 접근성(취약계층 접근) vs 웹 호환성(크로스브라우징) vs 웹 표준(W3C 문법 준수)
 ┗━ Ⅵ 실무 ───── SPA 환경 초점 유실 / 이미지 대체 텍스트 누락 / 복잡한 차트·캔버스 음성 미지원
```
- 필수 키워드: 장애인차별금지법 · KWCAG 2.2 · 4대 원칙 · 인식의 용이성 · 운용의 용이성 · WAI-ARIA · 명도대비(4.5:1)
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ KWCAG 4대 원칙 트리 → Ⅴ 3대 웹 품질 비교 / 25점 = Ⅰ~Ⅶ 전개, Ⅲ 24개 세부 지침과 Ⅵ SPA 동적 컴포넌트 접근성 해결책 상세화
- 기출: 126회 3교시 `설계기준 7가지와 웹접근성, 호환성, 개방성, 최적화` → Ⅲ·Ⅴ, 133회 2교시 `디지털정부서비스 UI/UX 가이드라인 준수사항` → Ⅲ·Ⅳ

## 한 줄 본질
- 신체적·환경적 제약과 무관하게 모든 사용자가 웹 콘텐츠를 동등하게 인식하고 조작하도록 보장하는 기술 규격 → 디지털 포용 및 법적 리스크 해소 / 동적 UI 구현 시 개발 공수 증가

## 핵심 그림
```text
+------------------- [ 한국형 웹 콘텐츠 접근성 지침 (KWCAG 2.2) 4대 원칙 ] -------------------+
|                                                                                               |
|  [ 1. 인식의 용이성 ] (Perceivable)           [ 2. 운용의 용이성 ] (Operable)                |
|  - 텍스트 아닌 콘텐츠 대체 텍스트(alt)        - 모든 기능을 키보드로 사용 보장               |
|  - 멀티미디어 자막 제공                       - 키보드 트랩 방지 및 논리적 초점 이동         |
|  - 텍스트와 배경 명도 대비 4.5:1 이상         - 시간 제한 조절(로그인 연장 기능)            |
|  - 콘텐츠 간 구분 및 선형 구조화              - 초당 3~50회 번쩍임 차단 (발작 방지)          |
|                                                                                               |
|  [ 3. 이해의 용이성 ] (Understandable)        [ 4. 견고성 ] (Robust)                         |
|  - 기본 언어 명시 (html lang="ko")            - 마크업 오류(열고 닫는 태그 누락) 방지        |
|  - 예측 가능한 UI 동작 (초점 이동 시 미실행)  - 웹 애플리케이션 접근성(WAI-ARIA) 속성 준수   |
|  - 입력 오류 방지 및 정정 안내                - 보조기술(스크린리더)과의 완벽한 호환성       |
+-----------------------------------------------------------------------------------------------+
```

## 핵심 용어
- KWCAG 2.2: W3C의 WCAG를 한국 실정에 맞춰 국가표준(KS X 2061)으로 제정한 웹 접근성 지침
- WAI-ARIA(Accessible Rich Internet Applications): 동적 웹 애플리케이션(React, Vue)에서 스크린리더가 UI 상태(role, state, property)를 인식할 수 있게 돕는 W3C 기술 규격
- 스킵 네비게이션(Skip Navigation): 반복되는 대메뉴를 건너뛰고 본문 영역으로 바로 이동할 수 있도록 제공하는 키보드 접근성 링크

## 핵심 통찰
- 웹 접근성은 단순 장애인 배려가 아니라 고령화 사회에서 모든 사용자의 사용성을 끌어올리는 품질 표준임
- 마크업에 `alt=""`를 기계적으로 채우는 형식적 준수는 이미지의 맥락 정보를 전달하지 못해 스크린리더 사용자에게 무용지물임
- React 등 최신 SPA(Single Page Application)에서 라우팅 변경 시 포커스가 바디 상단으로 튀거나 모달 팝업 뒤로 포커스가 빠지는 "키보드 트랩"이 가장 빈번한 감점 요인임

## 이웃 토픽과 구분
- 웹 접근성 vs 웹 호환성: 웹 접근성 = 장애인·고령자 등 사용자 관점의 평등한 접근 보장 / 웹 호환성 = Chrome, Safari, Edge 등 브라우저·OS 환경과 무관한 동일 기능 제공

## 문제·원인·대책
- 사례: 133회 기출 디지털 정부 공공 웹 포털 구축 프로젝트 접근성 인증 심사 탈락
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 모달 팝업 실행 시 배경 콘텐츠로 초점 유출 | 초점 가두기(Focus Trap) 및 aria-modal 속성 누락 | 모달 오픈 시 내부 첫 요소로 포커스 강제 이동 및 Tab 순환 스크립트 적용 | 키보드 조작 무결성 보장 |
| 동적 주식 시세 차트의 시각장애인 인식 불가 | HTML5 Canvas 그래픽 요소 내 텍스트 정보 부재 | 숨김 텍스트 표(`aria-hidden="true"`와 대응 테이블) 병행 렌더링 | 스크린리더 대체 정보 제공 |

## 이렇게 출제된다
- 제126회 3교시 2번: "전자정부 웹사이트 UI/UX 설계기준 7가지와 웹접근성, 웹호환성, 웹개방성, 웹최적화에 대하여 설명하시오." → 요구 포인트: Ⅲ 4대 원칙 + Ⅴ 품질 지표 간 차이점 명확화
- 제133회 2교시 2번: "‘디지털정부서비스 UI/UX 가이드라인’... 사용성 및 접근성 준수사항을 설명하시오." → 요구 포인트: Ⅲ KWCAG 핵심 조항 + 모바일/반응형 웹 접근성 조치

## 내 의견
