## 답안 골격
```text
[마이데이터] ◀━━ 머리: Ⅶ 내 의견 (스크래핑 원천 금지 이후 표준 API 트래픽 제어와 세분화 동의 UX 구현)
 ┃
 ┣━ Ⅰ 개요 ───── 기업이 독점하던 개인정보 주권을 정보주체에게 환원 → 개인 주도 데이터 전송
 ┣━ Ⅱ 특징 ───── 정보주체 중심 · 표준 API 강제(스크래핑 금지) · 금융에서 전 분야(의료·통신) 확산
 ┣━ Ⅲ 구조 ───── 정보주체 + 정보제공자 + 마이데이터 사업자 + 마이데이터 중계기관(표준 API/OAuth 2.0)
 ┣━ Ⅳ 흐름 ───── 정보주체 본인인증/동의 → 사업자가 전송요구서 전달 → 제공자가 API로 데이터 암호화 전송
 ┣━ Ⅴ 비교 ───── 마이데이터(표준 API) vs 스크린 스크래핑(비인가 계정 크롤링)
 ┗━ Ⅵ 실무 ───── API 호출 과금 부담 / 이종 데이터 규격 불일치 / 다크패턴을 통한 포괄적 동의 유도
```
- 필수 키워드: 개인정보 전송요구권 · 표준 API · 스크래핑 금지 · OAuth 2.0 · 본인신용정보관리업 · 전 분야 마이데이터
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 아키텍처 및 4대 참여자 도식 → Ⅴ 스크래핑 대비 장점 / 25점 = Ⅰ~Ⅶ 전개, Ⅲ API 연계 보안 규격과 Ⅳ 전송요구 흐름 상세화
- 기출: 120회 2교시 `마이데이터 산업의 개념과 기술요소` → Ⅰ·Ⅲ, 128회 2교시 `데이터 3법과 마이데이터 사업 연계` → Ⅲ·Ⅵ

## 한 줄 본질
- 정보주체가 자기 데이터의 이동 경로를 직접 통제하여 기업의 데이터 독점을 깨고 표준 API로 맞춤형 혁신 서비스를 창출하는 데이터 주권 제도 → 개인화 서비스 편익 극대화 / 대규모 데이터 집적에 따른 단일 침해 위험(SPOF) 수반

       |                                                    ^
       | 2. 전송요구권 행사                                 | 4. 데이터 응답

       v                                                    |

## 핵심 용어
- 개인정보 전송요구권: 정보주체가 본인에 관한 개인정보를 본인 또는 제3자에게 전송하도록 요구할 수 있는 법적 권리
- 스크린 스크래핑(Screen Scraping): 사용자의 공인인증서·비밀번호를 저장해 웹 화면을 긁어오던 구방식으로, 보안 취약으로 전면 금지됨
- mTLS(Mutual TLS): 클라이언트와 서버가 서로의 디지털 인증서를 양방향으로 검증하여 통신 암호화와 상호 인증을 동시에 보장하는 프로토콜

## 핵심 통찰
- 마이데이터의 기술적 핵심은 "데이터 저장"이 아니라 "표준화된 파이프라인(REST API)"으로 데이터를 실시간 이동시키는 능력임
- 스크래핑을 금지하고 표준 API를 강제한 것은 사용자 인증정보(비밀번호) 탈취 위험을 제거하고 트래픽 과부하를 통제하기 위한 공학적 결단임
- 전 분야 마이데이터 확산 시 데이터 표준화(데이터 사전, JSON 스키마)가 선행되지 않으면 이종 데이터 연계 비용이 비즈니스 수익을 초과함

## 이웃 토픽과 구분
- 마이데이터 vs 오픈뱅킹: 오픈뱅킹 = 결제·송금 및 계좌 조회 중심 금융 인프라 / 마이데이터 = 금융을 넘어 통신·유통·의료 등 개인 전 라이프사이클 데이터를 자산화하는 데이터 주권 제도

## 문제·원인·대책
- 사례: 128회 기출 마이데이터 정식 오픈 직후 대량 트래픽 집중에 따른 금융기관 API 응답 지연
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 정기 전송 트래픽 폭증으로 정보제공자 시스템 다운 | 마이데이터 사업자들의 무분별한 실시간 전체 동기화 요청 | 야간 배치 분산 호출 및 API 호출 속도 제한(Rate Limiting) | 인프라 가용성 안정 확보 |
| 이용자 동의 과정에서 불필요한 정보 과다 수집 | 포괄적 일괄 동의를 유도하는 UI 다크패턴 잔존 | 전송 항목별 선택적 세분화 동의 UI 가이드라인 강제 | 개인정보 최소 수집 원칙 준수 |

## 이렇게 출제된다
- 제120회 2교시 2번: "마이데이터(MyData) 산업의 개념, 기술적 요구사항 및 보안 고려사항을 설명하시오." → 요구 포인트: Ⅰ 개념 + Ⅲ 아키텍처 및 OAuth 2.0 / mTLS 보안
- 제128회 2교시 4번: "데이터 3법과 마이데이터 사업의 상호 연계 방안 및 데이터 경제 활성화 전략을 설명하시오." → 요구 포인트: Ⅲ 신용정보법상 마이데이터 의무화 + Ⅵ 이종 데이터 융합

## 내 의견
- [대량 실시간 동기화로 인한 트래픽 비용 전가 해소 방안] 마이데이터 사업자가 변경 없는 데이터까지 매일 전수 호출하여 제공 기관의 서버 비용이 기하급수적으로 증가 → 나라면: 변경분만 전송하는 증분(Delta) API 규격을 표준화하고, 웹훅(Webhook) 기반 이벤트 드리븐 전송 아키텍처를 적용하여 불필요한 네트워크 트래픽과 서버 컴퓨팅 비용을 80% 이상 절감
