## 답안 골격
```text
[터크만 사다리 모델] ◀━━ 머리: Ⅶ 내 의견 (형성기·폭풍기 조기 통과를 위한 그라운드 룰 제정과 성과기 자율 스프린트 보장)
 ┃
 ┣━ Ⅰ 개요 ───── 집단이 고성과 팀으로 진화하는 과정의 필연적 갈등 통제 → 브루스 터크만(Bruce Tuckman)의 팀 발달 모델
 ┣━ Ⅱ 특징 ───── 5단계 선형·순환적 발달 · 폭풍기(Storming) 갈등의 불가피성 인정 · 단계별 PM 상황적 리더십 매핑
 ┣━ Ⅲ 구조 ───── 팀 발달 5단계 (형성기 Forming ➔ 폭풍기 Storming ➔ 규범기 Norming ➔ 성과기 Performing ➔ 해산기 Adjourning)
 ┣━ Ⅳ 흐름 ───── ① 팀원 배정 및 목표 공유(지시) → ② 기술·역할 주도권 다툼(코칭) → ③ 협업 규칙 합의(지원) → ④ 자율 고성과(위임) → ⑤ 회고 및 종료
 ┣━ Ⅴ 비교 ───── 단계별 팀 특성 vs PM 권장 리더십 스타일 (지시형 Directing vs 코칭형 Coaching vs 지원형 Supporting vs 위임형 Delegating)
 ┗━ Ⅵ 실무 ───── 폭풍기 갈등 방치로 인한 조기 인력 이탈 / 신규 팀원 투입 시 형성기/폭풍기로의 퇴행(Regression) / 원격 환경의 규범 형성 난항
```

## 한 줄 본질
- 낯선 전문가들이 모여 하나의 프로젝트 팀을 이룰 때 피할 수 없는 마찰과 혼돈(폭풍기)을 거쳐 자율적 고성과(성과기)에 도달하는 5단계 발달 경로를 규명하고 각 단계에 최적화된 리더십을 제시하는 팀 빌딩 이론 → 갈등의 생산적 전환 및 팀 생산성 극대화 / 구성원 교체 시 하위 단계로 퇴행하는 가변성

```text

│        ▲                                                                                │
│        │                                                        [ 4. 성과기 ]           │
│        │                                                        (Performing)            │
│        │                                                        • 시너지 및 자율 수행   │
│        │                                 [ 3. 규범기 ]          • 리더십: 위임형        │
│        │                                 (Norming)                                      │

│        │                                                                • 프로젝트 종료 │

```

## 핵심 용어
- 폭풍기(Storming): 업무 방식, 기술 스택, 리더십 주도권을 둘러싸고 팀원 간의 반목과 충돌이 표면화되는 단계로, 회피하지 않고 건전하게 통과해야만 팀 결속이 완성됨
- 팀 규범(Ground Rules): 팀원들이 상호 신뢰 속에서 협업하기 위해 명문화한 일하는 방식, 의사소통 원칙, 회의 규칙, 코드 리뷰 기준
- 팀 퇴행(Team Regression): 성과기 단계에 도달한 팀이라도 핵심 구성원이 퇴사하거나 신규 인력이 대거 투입되면 다시 형성기나 폭풍기로 되돌아가는 현상

## 핵심 통찰
- 폭풍기는 실패가 아니라 '팀 성장의 필수 과정'임 → 갈등이 전혀 없는 팀은 조화로운 것이 아니라 문제를 은폐하고 있는 것이며, 폭풍기를 거치지 않은 팀은 결코 성과기(Performing)에 도달하지 못함
- 인력 추가는 팀을 무조건 폭풍기로 퇴행시킴 → 브룩스의 법칙(Brooks's Law)처럼 지연된 프로젝트에 인력을 추가하면 신규 인력과 기존 인력 간의 의사소통 마찰로 형성기·폭풍기가 재발하여 일정이 더 늦어짐
- 단계마다 리더의 말이 달라져야 함 → 형성기에는 "이렇게 하세요(지시)"라고 명확한 가이드를 주어야 불안이 해소되고, 성과기에는 "알아서 하세요(위임)"라고 권한을 넘겨야 생산성이 폭발함

## 이웃 토픽과 구분
- 터크만 모델 vs 갈등 해결 전략(토마스-킬만): 터크만 모델 = 시간에 따른 팀 전체의 유기적 발달 단계 / 토마스-킬만 = 특정 시점의 대인 간 갈등 상황에서 취하는 5대 대응 스타일(협력, 타협, 경쟁, 회피, 수용)

## 문제·원인·대책
- 적용 상황: 대규모 금융 SI 프로젝트 착수 후 2개월 차 폭풍기 갈등 발생
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 프론트엔드와 백엔드 개발자 간 API 규격 다툼으로 개발 진척 0% | 역할 분담 및 기술 의사결정 체계(RACI) 미흡 | PM의 중재 하에 API 우선(API-First) 설계 규범 제정 및 팀 협약서 작성 | 폭풍기 극복 및 2주 만에 규범기 안착 |
| 프로젝트 중반 핵심 아키텍트 교체 후 팀 생산성 50% 급감 | 신규 구성원 유입으로 인한 팀 형성기/폭풍기 퇴행 | 버디 프로그램(1:1 페어링) 및 온보딩 위키 자동화로 지식 전수 가속 | 1주일 내 성과기 복귀 |
