## 답안 골격
```text
[액티브-액티브 이중화·스토리지 DR] ◀━━ 머리: Ⅶ 내 의견 (3-Site DR 아키텍처와 GSLB 헬스체크 연동 무중단 자동 절체 구현)
 ┃
 ┣━ Ⅰ 개요 ───── 단일 IDC 전원 차단으로 인한 국가 행정망 전면 마비 극복 → 다중지역 동시 가동(Active-Active) 및 스토리지 무손실 DR 구축
 ┣━ Ⅱ 특징 ───── 다중 리전 동시 트래픽 처리 · RPO=0/RTO=0 지향 · 스토리지 실시간 동기화 · 분산 합의(Quorum) 기반 스플릿 브레인 방지
 ┣━ Ⅲ 구조 ───── 글로벌 트래픽 계층(GSLB/Anycast) ↔ 앱 계층(컨테이너 분산) ↔ 데이터/스토리지 계층(동기/비동기 하이브리드)
 ┣━ Ⅳ 흐름 ───── ① 사용자 요청 수신 → ② GSLB 최적 리전 라우팅 → ③ 앱 처리 및 로컬 스토리지 기록 → ④ 원격지 스토리지 양방향 복제
 ┣━ Ⅴ 비교 ───── Active-Active vs Active-Standby / 동기식 복제(Sync) vs 비동기식 복제(Async) / 2-Site DR vs 3-Site DR
 ┗━ Ⅵ 실무 ───── 원거리 네트워크 지연으로 인한 트랜잭션 병목 / 스플릿 브레인(Split-Brain) 데이터 오염 / 2배 이상의 인프라 비용
```
- 필수 키워드: 다중지역 액티브-액티브 · 스토리지 DR · GSLB · 동기식 복제(Sync) · 비동기식 복제(Async) · 3-Site DR · 스플릿 브레인(Split-Brain)
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 다중지역 액티브-액티브 구조도 → 동기/비동기 복제 비교 / 25점 = Ⅰ~Ⅶ 전개, Ⅲ 3-Site 아키텍처와 Ⅵ 스플릿 브레인 방지 집중
- 기출: 137회 3교시 `다중지역 동시 가동방식(Multi-Region Active-Active) 재해복구시스템` → Ⅰ·Ⅲ·Ⅵ

## 한 줄 본질
- 주 센터가 화재나 침수로 완전히 전소되었을 때 스탠바이 센터 기동 지연으로 수 시간 동안 서비스가 중단되는 사태 방지 → 지리적으로 수백 km 떨어진 둘 이상의 센터가 라이브 트래픽을 동시에 분담 처리하고 스토리지를 실시간 동기화 → 단일 센터 붕괴 시에도 가용성 100% 무중단 유지 / 네트워크 왕복 지연 및 분산 합의 비용 발생

## 핵심 그림
```text
┌───────────────────────────────── [ 3-Site 복합 스토리지 DR 아키텍처 ] ─────────────────────────────────┐
│                                                                                                         │

│                                    ┌──────────────┴──────────────┐                                      │
│                                    ▼                             ▼                                      │
│      [ 제1센터 (수도권 본센터) ] ◄──(초고속 전용선 동기 복제)──► [ 제2센터 (수도권 백업: <40km) ]      │
│      - Active 노드 트래픽 처리     (Metro Sync: RPO=0)           - Active 노드 트래픽 처리              │
│      - 고성능 올플래시 스토리지                                  - 고성능 올플래시 스토리지             │
│                      │                                                           │                      │
│                      └───────────────────────┐   ┌───────────────────────────────┘                      │
│                                              ▼   ▼                                                      │
│                               (광역 비동기 복제: Geo Async: RPO < 수초)                                  │
│                                              │                                                          │
│                                              ▼                                                          │
│                                [ 제3센터 (영남/호남 원격지: >200km) ]                                   │
│                                - 광역 대규모 재난 대비 3차 백업 센터 (Standby/DR)                        │
│                                - 분산 쿼럼(Witness) 서버 운영 (스플릿 브레인 방지)                      │

```

## 핵심 용어
- 3-Site DR: 근거리 2개 센터 간에는 초고속 동기식 복제(Metro Sync)를 적용해 RPO=0을 달성하고, 200km 이상 떨어진 제3센터에는 비동기 복제(Geo Async)를 엮어 전쟁·지진 등 광역 재난까지 방어하는 최상위 DR 모델
- 스플릿 브레인(Split-Brain): 두 센터 간 네트워크 단절 시, 양쪽 센터가 상대방이 죽었다고 판단하고 각자 독자적으로 쓰기 트랜잭션을 수용하여 데이터가 비가역적으로 오염·분기되는 치명적 현상
- 쿼럼 위트니스(Quorum Witness): 제3의 독립된 위치에서 양 센터의 생존 여부를 투표로 판정하여 과반수(Quorum)를 확보한 단 한쪽 센터만 쓰기를 지속하도록 보장하는 중재자

## 핵심 통찰
- 완벽한 액티브-액티브는 데이터베이스의 '다중 마스터 쓰기 충돌'을 해결하지 못하면 성립할 수 없음 → 양쪽에서 동시에 동일 행(Row)을 수정할 경우 발생하는 충돌을 방지하기 위해 사용자 세션별 지역 고정(Geo-affinity) 라우팅이 필수적임
- 물리적 거리와 빛의 속도 한계로 인해 100km가 넘는 원거리 간 동기식 스토리지 미러링은 트랜잭션 커밋 지연(Latency)을 초래해 운영 시스템을 마비시킴
- 국정자원 후속 대책의 핵심은 대전 본원과 광주 센터 간에 무조건 동기 복제를 거는 것이 아니라, 3-Site 구조를 통해 성능과 안전성의 균형점을 찾는 엔지니어링 타협임

## 이웃 토픽과 구분
- Active-Standby vs Multi-Region Active-Active: Active-Standby = 한쪽만 켜놓고 장애 시 수동 절체(RTO 발생) / Active-Active = 양 센터를 50:50으로 상시 가동하다가 한쪽 전소 시 잔여 센터가 100% 트래픽을 즉시 무중단 승계(RTO≈0)

## 문제·원인·대책
- 사례: 137회 기출 데이터센터 간 전용 회선 단절 사고 시 양쪽 센터가 동시에 마스터로 승격되어 계좌 잔액 불일치 및 데이터 충돌이 발생한 사례
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 양 센터 간 쓰기 충돌 및 스플릿 브레인 발생 | 센터 간 통신 장애 시 중재 메커니즘 부재 | 제3지역 클라우드에 쿼럼 위트니스(Witness) 배치 및 Raft 합의 알고리즘 적용 | 과반수 미달 센터 자동 격리로 데이터 무결성 보수 |
| 원거리 동기 복제로 인한 DB 쓰기 성능 50% 저하 | 150km 광케이블 왕복 시간(RTT 5ms) 누적 | 계좌/원장만 동기식 복제, 일반 조회/로그는 비동기식 CDC(카프카) 스트리밍 분리 | 시스템 성능 유지 및 핵심 데이터 무손실 달성 |

## 이렇게 출제된다
- 제137회 3교시 3번: "다중지역 동시 가동방식(Multi-Region Active-Active) 재해복구시스템의 개념, 구성요소, 데이터 동기화 기법 및 구축 시 고려사항을 설명하시오." → 요구 포인트: Ⅰ 개념 + Ⅲ GSLB 및 스토리지 복제 계층도 + Ⅳ Metro-Sync/Geo-Async 복제 기법 + Ⅵ 스플릿 브레인 방지

## 내 의견
- [단순 스토리지 레벨 복제를 넘어선 분산 클라우드 DB(Spanner/CockroachDB) 네이티브 전환] 전통적인 고가 외산 SAN 스토리지 간 미러링 방식은 라이선스 비용이 천문학적이고 장애 절체 시 스토리지 락 이슈가 빈번함 → 나라면: 인프라 계층의 하드웨어 스토리지 복제에 의존하지 않고, 애플리케이션 계층에서 구글 스패너(Spanner)나 칵로치DB(CockroachDB) 같은 Raft 기반 분산 트랜잭션 데이터베이스를 도입하여 소프트웨어적으로 리전 간 합의와 무중단 페일오버를 달성하는 차세대 클라우드 네이티브 DR 체계로 전환
