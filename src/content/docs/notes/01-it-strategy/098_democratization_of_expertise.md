## 핵심 용어
- 시민 개발자(Citizen Developer): 공식 IT 부서 소속 프로그래머가 아니면서 조직에서 승인한 LCNC 도구를 이용해 자신이나 부서의 업무 애플리케이션을 직접 개발하는 일반 임직원
- AutoML(Automated Machine Learning): 데이터 전처리, 특성 공학, 알고리즘 선택, 하이퍼파라미터 튜닝의 전 과정을 자동화하여 비전문가도 머신러닝 모델을 생성할 수 있게 하는 기술
- 섀도우 IT(Shadow IT): 중앙 IT 부서의 공식 검토, 승인, 통제를 거치지 않고 현업 부서가 임의로 도입하거나 개발해 사용하는 하드웨어, 소프트웨어, 클라우드 서비스

## 핵심 통찰
- 민주화는 전문 개발자의 소멸이 아니라 '역할의 상향 재배치'임 → 단순 화면 개발이나 데이터 집계는 현업이 처리하고, 전문 개발자는 분산 인프라, 보안 프레임워크, 고성능 코어 아키텍처에 집중함
- 무조건적인 권한 부여는 '기술적 부채의 쓰나미'를 부름 → 현업이 만든 수백 개의 스파게티 로우코드 앱은 담당자가 퇴사하면 아무도 수정할 수 없는 블랙박스 시한폭탄이 됨
- 생성형 AI가 전문성의 민주화의 최종 완성재 역할을 수행함 → 과거에는 드래그 앤 드롭 문법이라도 배워야 했으나, 이제는 자연어 프롬프트 지시만으로 SQL 쿼리와 파이썬 스크립트가 자동 생성되는 초민주화 단계로 진입함

## 이웃 토픽과 구분
- 전문성의 민주화 vs IT 아웃소싱: IT 아웃소싱 = 전문성을 외부 공급 업체로부터 조달하여 비용 절감 / 전문성의 민주화 = 내부 현업 사용자에게 직접 기술 도구를 부여하여 비즈니스 즉시성 확보

## 문제·원인·대책
- 적용 상황: 제조 대기업 현업 부서의 로우코드 앱 및 자체 데이터 파이프라인 무분별 개발
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 현업 직원이 만든 노코드 앱을 통해 고객 개인정보가 외부에 유출됨 | 중앙 IT의 보안 검토 없는 섀도우 IT 확산 | LCNC 플랫폼에 DLP(데이터 유출 방지) 및 IAM 권한 제어 가드레일 내장 | 보안 위반 사고 0건 달성 |
| 현업 담당자 퇴사 후 자체 제작한 발주 시스템 오류로 공장 가동 중단 | 아키텍처 표준화 및 인수인계 문서화 부재 | 전사 CoE 조직 신설을 통한 핵심 시민 개발 앱의 중앙 자산화 및 감리 | 시스템 지속가능성 확보 |

## 내 의견
- [시민 개발자를 위한 '중앙 CoE 주도 샌드박스 라이프사이클' 의무화] 현업의 자율성을 무작정 억압하면 비즈니스 혁신이 질식하고, 무작정 방치하면 보안 침해가 발생하는 딜레마 직면 → 나라면: 전사 로우코드/AI 도구를 중앙 IT가 관리하는 '엔터프라이즈 샌드박스' 환경에만 허용하고, 개인 사용 단계(Level 1) → 부서 공유 단계(Level 2, 보안 검증 필수) → 전사 운영 단계(Level 3, 전문 IT 부서 이관 및 유지보수)로 승격되는 '3단계 앱 승격 거버넌스'를 정착시킴
