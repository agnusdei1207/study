## 답안 골격
```text
[EVM] ◀━━ 머리: Ⅶ 내 의견 (단순 엑셀 집계를 넘어선 자동화된 CPI/SPI 추적 및 프로젝트 최종 비용(EAC) 조기 경보)
 ┃
 ┣━ Ⅰ 개요 ───── 일정과 예산을 분리 관리하여 발생하는 진척 왜곡 극복 → 작업 성과(EV)를 화폐 가치로 통합 측정하는 프로젝트 통제 기법
 ┣━ Ⅱ 특징 ───── 3대 기본값(PV/EV/AC) 통합 · 객관적 성과 측정 · 미래 완료 원가(EAC) 과학적 예측 · 조기 경보 체계
 ┣━ Ⅲ 구조 ───── 기본값(PV, EV, AC) ──> 성과 차이(CV, SV) ──> 성과 지수(CPI, SPI) ──> 예측값(EAC, ETC, VAC)
 ┣━ Ⅳ 흐름 ───── ① WBS 작업별 PV 배정 → ② 실제 투입 원가(AC) 집계 → ③ 완성된 산출물 가치(EV) 측정 → ④ CPI/SPI 계산 및 EAC 예측
 ┣━ Ⅴ 비교 ───── 전통적 진척 관리 vs EVM 기반 성과 관리 / CPI/SPI 4분면 프로젝트 상태 매트릭스
 ┗━ Ⅵ 실무 ───── EV(획득가치) 측정의 주관적 왜곡(90% 신드롬) / 공수 투입(AC) 집계 지연 / 프로젝트 후반 SPI의 신뢰도 저하
```
- 필수 키워드: 획득가치관리 · PV(계획가치) · EV(획득가치) · AC(실제원가) · CV/SV · CPI/SPI · EAC(최종예상치) · 0-100 법칙
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 기본 공식 요약 표 → CPI/SPI 4분면 해석도 / 25점 = Ⅰ~Ⅶ 전개, Ⅲ 계산 산식 완결과 Ⅵ 실무 계산 문제 대응 집중
- 기출: 125회 2교시 `EVM 기본값(EV 500만, PV 600만, AC 450만)에 대한 CV/SV/CPI/SPI 계산 및 상태 분석` → Ⅲ·Ⅳ

## 한 줄 본질
- 예산 집행률(AC/PV)만 보고 프로젝트가 잘 진행되고 있다고 착각하다가 납기일에 시스템 미완성으로 파탄 나는 비극 방지 → 실제 완성된 작업의 객관적 가치(EV)를 측정하여 일정과 비용 성과를 단일 기준으로 정량 통제 → 프로젝트 최종 원가 및 납기일의 과학적 조기 예측 / EV 산정 기준의 주관성 개입 위험

## 핵심 그림
```text
┌───────────────────────────────── [ EVM 핵심 지표 산식 및 4분면 상태 판정 ] ─────────────────────────────────┐

│  [ 3대 기본 척도 ]                                 [ 편차 지표 (차이) ]         [ 효율 지수 (비율) ]         │

│   예산절감 │ [ 2사분면: 일정지연 / 예산절감 ]           [ 1사분면: 일정단축 / 예산절감 (최상) ]             │

│   (CPI < 1)│ (원인: 재작업 빈발, 프로젝트 좌초 위기)    (원인: 일정 만회를 위한 야근/돌격작업)              │
```

## 핵심 용어
- EAC(Estimate At Completion): 프로젝트 완료 시점에 최종적으로 소요될 것으로 예상되는 총비용(현재의 비용 효율이 지속될 경우 $EAC = BAC / CPI$)
- TCPI(To-Complete Performance Index): 정해진 예산(BAC)을 지키기 위해 앞으로 남은 작업에서 달성해야만 하는 필수 비용 효율 지수($TCPI = (BAC - EV) / (BAC - AC)$)
- 90% 신드롬: 개발자들이 작업 착수 직후 90% 완료했다고 보고한 뒤, 나머지 10%의 디버깅에 프로젝트 전체 시간의 절반을 소모하는 전형적인 진척률 왜곡 현상

## 핵심 통찰
- "돈을 계획대로 썼는가(AC vs PV)"는 프로젝트 성공과 아무런 상관이 없음 → "쓴 돈만큼 실제 가치 있는 산출물을 만들어냈는가(EV vs AC)"가 유일한 진실임
- SPI(일정성과지수)는 프로젝트 후반부(종료 임박)가 되면 완료 작업이 늘어나 지연 여부와 상관없이 무조건 1.0으로 수렴하는 수학적 한계가 있음 → 일정 분석에는 Earned Schedule(ES) 기법을 보완해야 함
- 0-100 법칙(작업이 100% 검수 완료되기 전까지는 EV를 0으로 잡음)을 적용해야 개발자의 주관적 희망 회로에 의한 진척 왜곡을 원천 차단할 수 있음

## 이웃 토픽과 구분
- 전통적 진척 관리 vs EVM: 전통 관리 = 계획 예산(PV) 대비 집행액(AC)만 비교하여 돈을 덜 쓰면 잘하고 있다고 착각 / EVM = 실제 완성 가치(EV)를 제3의 축으로 두어 돈을 덜 쓴 게 아니라 일을 안 해서 진척이 밀린 것임을 즉시 적발

## 문제·원인·대책
- 기출 계산 예시 (125회 2교시): PV=600만원, EV=500만원, AC=450만원
  - $CV = 500 - 450 = +50만원$ (예산 50만원 절감 상태)
  - $SV = 500 - 600 = -100만원$ (일정 100만원어치 지연 상태)
  - $CPI = 500 / 450 = 1.11$ (> 1, 비용 투입 효율 양호)
  - $SPI = 500 / 600 = 0.83$ (< 1, 계획 대비 83% 공정만 진행되어 일정 지연)
  - 판정: 2사분면(일정 지연 / 예산 절감). 현재 투입 인력이 적어 돈은 덜 썼으나 납기 지연 위험이 있으므로 추가 인력 투입(Crashing) 검토 필요
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 개발자의 자의적 90% 진척 보고로 위기 은폐 | 작업 단위의 완료 기준(DoD) 모호 | 0-100 법칙 또는 50-50 법칙 엄격 적용 및 단위 테스트 통과 기준 EV 인정 | 진척률 거품 제거 |
| 실제 공수 투입 집계 지연으로 사후 약방문 | 외주 인력의 타임시트(Time Sheet) 월말 일괄 정산 | 주간 단위 타임시트 마감 및 Git 커밋 연동 실시간 실측 집계 | CPI/SPI 조기 경보 기능 복원 |
