## 답안 골격
```text
[POP] ◀━━ 머리: Ⅶ 내 의견 (스마트 팩토리 IIoT·엣지 컴퓨팅 기반 초저지연 데이터 파이프라인으로 현대화)
 ┃
 ┣━ Ⅰ 개요 ───── 생산 현장 수작업 집계로 인한 데이터 지연·왜곡 → 생산 시점 실시간 데이터 자동 집계 체계
 ┣━ Ⅱ 특징 ───── 실시간성(Real-time) · 현장 중심성 · 양방향 데이터 연계 · 자동 인식 기술(바코드, RFID, 센서)
 ┣━ Ⅲ 구조 ───── 현장 장비/센서/단말 계층 ↔ 데이터 수집/변환 미들웨어 ↔ POP 서버 ↔ MES / ERP 연계
 ┣━ Ⅳ 흐름 ───── ① 작업 지시 수신 → ② 실시간 실적 집계(가동·불량·재고) → ③ 공정 이상 감지 → ④ 상위 MES/ERP 전송
 ┣━ Ⅴ 비교 ───── POP vs MES (현장 데이터 수집 및 시점 관리 vs 공정 제어·추적 및 생산 실행 총괄)
 ┗━ Ⅵ 실무 ───── 이기종 PLC 인터페이스 불일치 / 현장 작업자 입력 누락 / 네트워크 단절 시 버퍼링
```
- 필수 키워드: 생산시점관리 · 실시간 데이터 수집 · 바코드/RFID/PLC · MES/ERP 연계 · 공정 가시성 · 불량 추적
- 배점 전략: 10점 = Ⅰ 개요 → Ⅲ 계층 구조도 → Ⅴ POP vs MES 비교 / 25점 = Ⅰ~Ⅶ 전개, 스마트공장 IIoT 센서 및 엣지 계층 연계
- 기출: KPC 124회 `POP 시스템의 개념 및 구축 방안`, KPC 128회 `스마트 제조 환경에서 POP와 MES의 역할 비교` → Ⅲ·Ⅴ

## 한 줄 본질
- 제조 현장의 수작업 전표 집계로 인해 발생하는 재고 왜곡과 생산 진척 파악 지연 해소 → 생산 시점(발생 현장)에서 단말·센서·바코드로 작업 실적과 설비 가동 데이터를 실시간 자동 수집·제공 → 공정 가시성 확보 및 생산성 극대화 / 현장 환경에 따른 센서 오작동 및 통신 불안정 리스크

## 핵심 용어
- 설비 인터페이스(PLC 통신): 생산 라인의 PLC(Programmable Logic Controller)로부터 설비 가동 시간, 가동률, 에러 코드를 직접 추출하는 프로토콜 연계 기술
- 작업 실적 자동 피드백: 작업자가 수기로 마감하던 작업 완료량 및 불량 수량을 센서 계측값 기반으로 상위 시스템에 즉시 전송하는 메커니즘

## 핵심 통찰
- POP는 상위 ERP의 계획 데이터와 하위 공장 설비의 물리적 현실 사이를 잇는 '가장 낮은 층위의 신경망'임
- 데이터 수집의 자동화율이 시스템 성패를 결정함 → 작업자 터치 패널 입력에 의존할수록 실시간성이 무너지고 불량률 데이터 왜곡이 발생하므로 PLC·비전 센서 기반 비접촉 수집으로 전환해야 함
- 최신 스마트공장 관점에서 POP는 독립 시스템이 아니라 MES의 데이터 수집 모듈 또는 엣지 컴퓨팅 노드로 흡수 통합되는 추세임

## 이웃 토픽과 구분
- POP vs MES: POP = 생산 현장의 시점 데이터 '수집·모니터링'에 특화 / MES = 수집된 데이터를 바탕으로 공정 제어, 스케줄링, 품질 추적, 자원 배분을 실행하는 상위 '제조 실행' 시스템

## 문제·원인·대책
- 적용 상황: 전자부품 조립 라인의 실시간 수율 모니터링
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 야간 교대 근무 시 실적 데이터 누락 | 작업자의 수기 바코드 스캔 누락 및 조작 실수 | 광학 센서 및 비전 카메라 기반 통과 수량 자동 카운팅 도입 | 인적 개입 배제 및 데이터 정합성 100% 확보 |
| 통신 장애 시 공정 데이터 유실 | 네트워크 일시 단절 및 POP 단말 메모리 한도 초과 | 엣지 게이트웨이 로컬 SQLite 큐잉 및 Store-and-Forward 적용 | 단절 복구 후 데이터 무손실 전송 |

## 이렇게 출제된다
- 제124회 KPC: "생산시점관리(POP) 시스템의 개념과 주요 구성요소 및 구축 시 고려사항을 설명하시오." → 요구 포인트: Ⅰ 개념 + Ⅲ 아키텍처 계층도 + Ⅵ 구축 시 실무 대책
- 제128회 KPC: "스마트 팩토리 환경에서 POP(Point of Production)와 MES(Manufacturing Execution System)의 역할을 비교하여 설명하시오." → 요구 포인트: Ⅴ 비교표 및 연계 흐름

## 내 의견
- [레거시 POP의 산업용 사물인터넷(IIoT) 엣지 아키텍처로의 전환] 노후 생산 현장의 RS-232/485 직렬 통신 기반 POP 단말은 데이터 처리 지연과 잦은 단선으로 현대적 AI 품질 예지보전에 부적합 → 나라면: 공정 설비에 Modbus/OPC-UA 프로토콜 변환 엣지 디바이스를 부착하고, MQTT 경량 프로토콜을 통해 중앙 데이터 레이크로 초당 수천 건의 센서 시계열 데이터를 무손실 적재하는 아키텍처로 개선
