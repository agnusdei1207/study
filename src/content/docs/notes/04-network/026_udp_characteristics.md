## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **UDP (User Datagram Protocol)**: 전송 계층(L4)에서 연결 수립 및 상태 관리 없이 8바이트 고정 헤더로 데이터그램을 즉시 송출하는 비연결형 프로토콜 (RFC 768).
- **Datagram (데이터그램)**: 이전이나 이후의 패킷과 연결 상태를 공유하지 않고 독립적으로 라우팅되는 PDU 전송 단위.

</details>

- 정의/개념: 사전 연결 설정 없이 **8바이트 고정 헤더와 메시지 경계 보존을 통해 저지연 데이터그램을 송수신하는 L4 비연결형 전송 프로토콜**
- 배경/필요성: TCP의 3-Way Handshake 연결 수립 오버헤드, 단일 패킷 유실 시 전체 스트림이 정체되는 선두 차단(HoL Blocking) 현상 및 가변 헤더 처리 지연으로 인해 실시간 음성/화상(VoIP, WebRTC), DNS 질의, 온라인 게이밍 및 대규모 브로드캐스트/멀티캐스트 환경의 엄격한 저지연 요구사항을 충족할 수 없는 한계를 극복하기 위해, 연결 상태 관리와 흐름/혼잡 제어 오버헤드를 걷어내고 8바이트 최소 헤더와 메시지 경계(Message Boundary)를 보존하는 비연결형 UDP 프로토콜을 도입하여 **패킷 처리 지연 최소화와 응용 계층 주도의 유연한 전송 제어(QUIC 기반 차세대 전송 확장)**를 달성할 필요

#### 한줄 요약
- 비연결성과 8바이트 최소 헤더를 활용하여 전송 지연을 최소화하고 유실 복구는 응용 계층에서 제어해야 한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Message Boundary (메시지 경계)**: 송신 측의 단일 `send()` 크기 그대로 수신 측의 `recv()`로 1:1 보존되는 특성 (TCP 스트림과 대비).
- **Pseudo Header (의사 헤더)**: UDP 체크섬 계산 시 IP 스푸핑 및 오라우팅을 방지하기 위해 출발지/목적지 IP와 프로토콜 번호를 가상 결합하는 12B 헤더.

</details>

- 사전 핸드셰이크 없이 즉시 패킷을 송출하는 **비연결성(Connectionless) 및 저지연**
- 응용 계층이 전달한 패킷의 크기를 그대로 유지하는 **메시지 경계(Message Boundary) 보존**
- 1:1 유니캐스트뿐 아니라 **1:N 멀티캐스트 및 1:전체 브로드캐스트 전송 지원**

#### 한줄 요약
- 비연결성, 8바이트 고정 헤더, 메시지 경계 보존, 멀티캐스트/브로드캐스트 지원을 체계적으로 구현해야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **UDP 8바이트 고정 헤더**: Source Port(2B), Destination Port(2B), Length(2B), Checksum(2B).

</details>

```text
[UDP 데이터그램 구조]
  │
  ├─ [고정 헤더] ── 8바이트 최소 오버헤드
  │     ├─ [출발지 포트 Source Port] (16-bit)
  │     ├─ [목적지 포트 Destination Port] (16-bit)
  │     ├─ [전체 길이 Length] (16-bit, 헤더+페이로드)
  │     └─ [오류 검출 Checksum] (16-bit, 의사헤더 결합)
  │
  └─ [응용 페이로드] ── Application Data
        ├─ [메시지 경계 보존] (No-Stream, 단일 버퍼)
        └─ [응용 계층 제어] (신뢰성/혼잡제어 직접 구현)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 출발지 포트 | 송신 프로세스 **식별·응답 경로 지정** |
| 목적지 포트 | 수신 호스트의 **응용 서비스 식별** |
| 전체 길이 | 헤더·페이로드의 **전체 바이트 길이 표시** |
| 체크섬 | 의사 헤더를 포함한 **비트 오류 검출** |

#### 한줄 요약
- 8바이트 최소 헤더로 프로토콜 오버헤드를 줄이고 메시지 단위 전송을 보장해야 한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **UDP 무상태 전송 4단계**: 소켓 생성 및 `sendto()` $\to$ 8바이트 헤더 캡슐화 $\to$ IP 비연결 포워딩 $\to$ 수신단 체크섬 검증 및 `recvfrom()` 인계.

</details>

```text
[UDP 데이터그램 송수신 흐름] (진행 ①→⑤, 송신에서 진입, 수신 ④ 체크섬 판정으로 인계·폐기 분기)
  │
  ├─ [송신 응용 소켓] (① sendto() 호출로 메시지 경계 보존 송출 요청)
  │
  ├─ [UDP 헤더 조립기] (② 출발지·목적지 포트와 길이 기록 후 의사헤더 기반 체크섬 산출)
  │
  ├─ [IP 계층] (③ 핸드셰이크 없이 데이터그램을 즉시 비연결 포워딩)
  │
  ├─ [수신 체크섬 검증기] (④ 수신단에서 체크섬 재계산 판정)
  │
  └─ [수신 응용 소켓] (⑤ 정상이면 recvfrom()으로 응용 큐에 1:1 인계)
```

분기 결과: 수신 체크섬 검증 결과 정상이면 recvfrom()을 통해 응용 소켓으로 인계 분기되고, 오류 발생 시 알림 없이 폐기(Drop)되어 응용 계층 처리로 분기된다.

#### 한줄 요약
- 체크섬 검증 통과 데이터그램만 응용으로 인계하고 오류 패킷은 조용히 폐기하여 상위 계층 처리에 위임해야 한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **UDP vs TCP**: 비연결 데이터그램 저지연 전송(UDP)과 연결형 바이트 스트림 신뢰성 전송(TCP).

</details>

| 비교 항목 | 사용자 데이터그램 프로토콜 (UDP) | 전송 제어 프로토콜 (TCP) |
|:---|:---|:---|
| 연결 지향성 | **비연결형 (Connectionless, No Handshake)** | **연결 지향형 (3-Way Handshake 수립)** |
| 전송 단위 및 경계 | **데이터그램 (메시지 경계 보존)** | **바이트 스트림 (경계 없음, 분할/합성)** |
| 헤더 오버헤드 | **8 바이트 고정** | 20 ~ 60 바이트 가변 |
| 신뢰성 보장 | **미보장 (패킷 유실/순서 역전 허용)** | **보장 (시퀀스 번호, ACK, 타임아웃 재전송)** |
| 흐름 및 혼잡 제어 | **미지원 (네트워크 대역폭 무관 송출)** | **지원 (Sliding Window, AIMD 혼잡 제어)** |
| 주요 대표 서비스 | **DNS, DHCP, SNMP, WebRTC, QUIC (HTTP/3)**| **HTTP/1.1, HTTP/2, HTTPS, FTP, SSH, DB** |

#### 한줄 요약
- 실시간성과 단순 전달에는 UDP를 채택하고, 데이터 정합성과 신뢰성이 필요한 곳에는 TCP를 적용해야 한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **UDP Amplification DDoS**: 공격자가 출발지 IP를 피해자 IP로 스푸핑하여 공개 DNS/NTP/SNMP 서버에 쿼리를 보내 수십~수백 배 커진 응답 트래픽을 피해자로 집중시키는 반사 공격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 출발지 IP 위조를 통한 UDP 반사 증폭 디도스(DNS/NTP) 공격 | **개방형 리졸버 차단, `RRL(Response Rate Limiting)` 및 BCP 38 적용** | 증폭 반사 트래픽 차단 및 가용성 수호 |
| 대용량 UDP 전송 시 IP 단편화 발생 및 단일 조각 유실 시 전체 폐기 | **응용 계층 페이로드 크기를 `Path MTU(통상 1,472B 이하)`로 제한** | IP 단편화 방지 및 전송 성공률 향상 |
| 패킷 유실 및 지터(Jitter)로 인한 실시간 영상/음성 품질 저하 | **응용 계층에 `FEC(전방 오류 정정)` 및 `지터 버퍼(Jitter Buffer)` 구현** | 재전송 대기 없는 자체 복원 및 연속 재생 |
| UDP 패킷 무단 폭주로 인한 백본 네트워크 대역폭 고갈 | **애플리케이션 계층 `토큰 버킷(Token Bucket) 레이트 리미팅` 강제** | 공정 대역폭 공유 및 네트워크 붕괴 방어 |

#### 한줄 요약
- RRL/BCP 38 적용, Path MTU 제한, FEC 지터 버퍼링, 토큰 버킷 레이트 리미팅을 체계적으로 적용해야 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **Jitter Buffer (지터 버퍼)**: 네트워크 전송 지연 변이(지터)로 인해 패킷 도착 간격이 불규칙해지는 현상을 완화하기 위해 수신단에서 패킷을 잠시 완충 보관 후 순차 재생하는 버퍼.

</details>

- 단순한 DNS/DHCP 인프라 질의와 실시간 음성/영상 스트리밍을 넘어, TCP의 커널 종속성과 HoL 지연을 극복하기 위해 UDP 상단에 암호화와 멀티스트리밍을 결합한 차세대 표준 프로토콜 QUIC(HTTP/3)의 기반 전송 계층으로 전면 재조명받고 있음.
- 실무 시스템 구현 시에는 IP 단편화를 방지하는 Path MTU(1,472B 이하) 준수, 패킷 유실 시 무지연 복구를 위한 전방 오류 정정(FEC) 및 지터 버퍼(Jitter Buffer) 구성, UDP 반사 증폭 DDoS 공격을 차단하는 RRL(Response Rate Limiting)과 토큰 버킷 속도 제한을 결합하여 저지연과 가용성을 동시에 완성.

#### 한줄 요약
- UDP는 8바이트 최소 헤더와 메시지 경계 보존을 통해 저지연 전송을 실현하며, QUIC과 FEC를 결합하여 차세대 인터넷 전송을 선도해야 한다.
