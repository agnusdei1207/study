## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SIEM (Security Information and Event Management)**: 전사 보안 장비와 서버의 이종 로그를 수집·정규화하고 상관 분석하여 위협을 탐지하는 통합 관제 플랫폼.
- **Correlation Analysis (상관 분석)**: 시간 윈도우, IP, 계정을 축으로 단일 장비에서 놓치기 쉬운 다단계 APT 공격의 인과 관계를 교차 검증하는 기법.

</details>

- 정의/개념: 이종 로그를 정규화·분석하는 **통합 보안관제 플랫폼**
- 배경/필요성: 방화벽, IPS, WAF, EDR, 서버 및 클라우드 등 수십 종의 이종 보안 인프라가 제각각의 로그 포맷과 독립된 콘솔에서 하루 수천만 건의 경보를 쏟아내는 사일로(Silo) 환경에서, 관제 요원이 개별 장비를 수동으로 교차 대조하는 방식은 다단계 지능형 지속 위협(APT)의 전체 공격 체인(Kill Chain)을 추적할 수 없고 심각한 경보 피로도(Alert Fatigue)로 인해 실제 침해 사고를 놓치는 한계를 노출함에 따라, 이종 보안 로그를 단일 스키마(CEF/ECS)로 수집·정규화하고 위협 인텔리전스(TI) 보강 및 시계열 상관 분석(Correlation)을 수행하는 빅데이터 통합 보안관제 플랫폼인 SIEM을 도입하여 **전사 보안 가시성 일원화, 복합 다단계 공격의 조기 탐지 및 침해 사고 조사 시간(MTTD) 단축**을 달성할 필요

#### 한줄 요약
- 이종 로그 수집, 표준 스키마 정규화, 위협 인텔리전스 결합, 시계열 상관 분석을 통해 복합 APT 공격을 탐지한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **CEF / ECS (Common Event Format / Elastic Common Schema)**: 제조사마다 제각각인 로그 필드명을 단일 글로벌 표준 필드로 통일하는 정규화 스키마.
- **Enrichment (맥락 보강)**: 원시 IP/도메인 로그에 Geo-IP 위치, 내부 자산 중요도, 외부 최신 위협 인텔리전스(TI) 정보를 결합하여 분석 가치를 높이는 과정.

</details>

- **로그 정규화**: 이종 포맷을 **CEF/ECS 스키마**로 통일
- **시계열 상관 분석**: 시간 창의 이벤트를 **인시던트로 승격**
- **경보 집약**: 위험 점수로 **Alert Fatigue** 완화

#### 한줄 요약
- 이종 로그 표준화, 시계열 상관 분석, 위험 점수 기반 알람 집약을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Log Collector & Pipeline**: Syslog, Kafka, 에이전트를 통해 초당 수십만 이벤트(EPS)를 무손실 버퍼링 및 수집하는 스트리밍 파이프라인.

</details>

```text
[SIEM 관제 플랫폼]
  │
  ├─ [수집 파이프라인] ── Collection Pipeline
  │     └─ [로그 수집기] (Syslog·API 로그 수집과 완충)
  ├─ [데이터 전처리] ── Preprocessing
  │     └─ [정규화 파서] (CEF/ECS 공통 스키마 변환)
  ├─ [정보 보강] ── Enrichment
  │     └─ [맥락 보강기] (자산·Geo-IP·TI 결합)
  └─ [분석 및 저장] ── Analysis-Storage
        ├─ [상관 분석기] (시간 창 기반 복합 공격 탐지)
        └─ [로그 저장소] (실시간 검색과 장기 보존)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 로그 수집기 | **Syslog·API** 로그 수집과 완충 |
| 정규화 파서 | **CEF/ECS** 공통 스키마 변환 |
| 맥락 보강기 | 자산·Geo-IP·**TI** 결합 |
| 상관 분석기 | 시간 창 기반 **복합 공격 탐지** |
| 로그 저장소 | 실시간 검색과 **장기 보존** |

#### 한줄 요약
- 정규화 파서가 벤더별 로그 형식 차이를 앞에서 흡수하므로, 상관 분석 엔진은 로그 출처를 구분하지 않고 동일한 필드 기준으로 시계열을 잇는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Incident Escalation (인시던트 승격)**: 개별 단순 알람이 복합 상관 룰 조건(예: 5분 내 100회 브루트포스 실패 후 1회 로그인 성공 및 DB 대량 덤프)을 만족할 때 공식 침해 사고로 전환하는 절차.

</details>

```text
[SIEM 로그 처리·탐지 흐름] (진행 ①→④, 수집에서 진입, 상관 분석 ④에서 단순 이벤트는 저장·복합 침해만 인시던트 승격)
  │
  ├─ [로그 수집기] (① Syslog·Kafka·에이전트로 이종 로그 무손실 수집)
  │
  ├─ [정규화 파서] (② 벤더별 로그를 CEF/ECS 공통 스키마로 변환)
  │
  ├─ [맥락 보강기] (③ 자산 중요도·Geo-IP·위협 인텔리전스 결합)
  │
  ├─ [상관 분석기] (④ 시간 윈도우·IP·계정 축 교차 검증)
  │
  ├─ [단순 이벤트 저장] (④ 단일 이벤트 갈래: 로그 저장소 보존 후 종료)
  │
  └─ [인시던트 승격] (④ 복합 침해 갈래: Incident Escalation 절차로 전환·SOAR 연계)
```

분기 결과: 상관 분석 결과가 갈리며, 단순 이벤트 갈래는 저장소 적재 비용만 치르고 관제 화면에 올리지 않아 분석가 자원을 소모하지 않으나 개별 탐지로는 복합 공격 체인이 보이지 않고, 복합 침해 갈래는 **Correlation Analysis** 연산과 인시던트 처리·대응 자원을 지불하는 대신 다단계 APT 체인을 한 건으로 승격시키므로, 위험 점수 임계를 낮출수록 탐지 누락은 줄지만 **Alert Fatigue**를 대가로 지불한다.

#### 한줄 요약
- 위험 점수 임계에서 인시던트 발행과 보류가 갈리며, 임계를 낮추면 탐지 누락은 줄지만 분석가 피로도를 대가로 지불한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **1세대 룰 기반** vs **차세대 AI/UEBA** vs **클라우드 네이티브 SaaS**.

</details>

| 비교 항목 | 1세대 룰 기반 SIEM | 차세대 AI/UEBA SIEM | 클라우드 네이티브 SIEM (SaaS) |
|:---|:---|:---|:---|
| 분석 메커니즘 | **IF-THEN 규칙** | **UEBA 행위 분석** | 클라우드 AI·분산 검색 |
| 탐지 대상 | 알려진 공격·무차별 대입 | **내부자·계정 탈취·변종 공격** | 멀티클라우드 감사 로그 |
| 오탐률·유지보수 | 높고 지속적 규칙 튜닝 | 기준선 학습으로 **오탐 감소** | TI 자동 갱신 |
| 인프라 확장성 | 온프레미스 용량 한계 | 대규모 연산 자원 필요 | **서버리스 탄력 확장** |
| 대표 솔루션 | Splunk·ArcSight | Exabeam·QRadar | Sentinel·Chronicle |

#### 한줄 요약
- 1세대는 정적 룰 탐지, 차세대는 AI 기반 이상 행위 분석, 클라우드 네이티브는 탄력적 확장성을 제공한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Alert Fatigue (관제 피로도)**: 일일 수만 건의 단순 보안 알람이 쏟아져 관제 요원의 주의력이 분산되고 실제 치명적인 위협을 놓치게 되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 시계 불일치로 **공격 인과관계 역전** | **NTP/PTP 동기화**와 수집 시각 검증 | 타임라인 증적 신뢰성 확보 |
| 과도한 경보로 **Alert Fatigue** | **위험 점수 집약**과 노이즈 필터 | MTTR 단축과 핵심 경보 집중 |
| EPS 폭증으로 **로그 유실** | **Kafka 완충 계층** 배치 | 무손실 수집과 가용성 확보 |
| 장기 보관으로 **저장 비용 증가** | **Hot-Warm-Cold 계층화** | 비용 절감과 보존 규정 준수 |

#### 한줄 요약
- NTP 동기화로 타임라인을 일치시키고, 위험 점수로 피로도를 완화하며, Kafka로 로그 유실을 방어한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **SOC (Security Operations Center)**: 조직의 정보 자산을 보호하기 위해 보안 위협을 24x365 실시간 모니터링, 탐지, 대응하는 통합 보안관제센터.
- **SOAR (Security Orchestration, Automation, and Response)**: 이종 보안 솔루션의 경보를 단일 워크플로우로 연계하여 반복적 분석 및 대응 작업을 자동화하는 플랫폼.
- **Hot-Warm-Cold 계층화**: 로그의 접근 빈도와 경과 시간에 따라 고성능 SSD(Hot), 대용량 HDD(Warm), 저비용 클라우드 아카이브(Cold)로 스토리지 티어를 분리 저장하는 아키텍처.

</details>

- 엔터프라이즈 및 보안관제센터(SOC)의 사일로화된 보안 데이터를 단일 화면으로 통합하는 **전사 위협 탐지 및 침해 사고 분석의 가장 핵심적인 중추 플랫폼**으로 확고히 정립.
- 단순 룰 기반 탐지를 넘어 머신러닝 기반 이상 행위 분석(UEBA), 클라우드 네이티브 SaaS SIEM(Sentinel/Chronicle) 및 자동 대응 플랫폼인 SOAR와의 결합으로 진화하는 가운데, 실무 SIEM 운영 시에는 **수집 타임라인 인과관계를 보증하는 전 장비 NTP/PTP 정밀 시각 동기화**, **초당 수십만 이벤트(EPS) 폭증 시 로그 유실을 방지하는 Kafka 수집 완충 파이프라인**, **관제 피로도(Alert Fatigue)를 완화하는 위험 점수(Risk Score) 집약 및 노이즈 필터링**, **검색 성능과 스토리지 비용을 최적화하는 Hot-Warm-Cold 수명주기 관리**를 결합하여 보안관제 분석 역량을 고도화해야 한다.

#### 한줄 요약
- SIEM은 대용량 로그 정규화와 시계열 상관 분석을 통해 복합 사이버 위협을 실시간 탐지하도록 전사 보안 인프라와 유기적으로 연계해야 한다.
