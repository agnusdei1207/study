## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Edge Computing (엣지 컴퓨팅)**: 데이터가 생성되는 말단 디바이스(센서, PLC, 카메라) 자체에서 즉시 연산·제어하는 극초단 분산 컴퓨팅.
- **Fog Computing (포그 컴퓨팅)**: 엣지 장치와 중앙 클라우드 사이의 로컬 네트워크 장비(게이트웨이, 스위치)에서 데이터 집계와 프로토콜 변환을 수행하는 다계층 확장 아키텍처 (IEEE 1934).

</details>

- 정의/개념: 대규모 IoT 및 스마트 인프라의 데이터 처리 효율을 향상하기 위해, 데이터 생성 단말 자체에서 저지연 실시간 연산을 수행하는 **엣지(Edge)**와 로컬 네트워크 계층에서 다중 기기 데이터 집계 및 프로토콜 변환을 담당하는 **포그(Fog)**를 물리적 배치 위치와 연산 범위 관점에서 유기적으로 연계하는 **다계층 분산 컴퓨팅 아키텍처**
- 배경/필요성: 모든 원시 데이터를 원거리 중앙 클라우드로 집중 전송하는 구조에서 발생하는 백홀 네트워크 대역폭 고갈, 전송 지연 누적 및 상위망 단선 시 설비 마비(SPOF) 위험을 초래하는 한계를 극복하기 위해, 말단 엣지의 즉시 제어와 포그 계층의 로컬 집계·변환으로 처리를 분산 배치하는 다계층 분산 컴퓨팅 아키텍처를 도입하여 백홀 부하 절감, 저지연 현장 제어 및 장애 독립성을 달성할 필요

#### 한줄 요약
- 엣지는 말단 즉시 제어를, 포그는 로컬 네트워크 집계 및 중계를, 클라우드는 전역 분석을 분담해야 한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **OpenFog SCALE Principles**: Security(보안), Cognition(인지), Agility(민첩성), Latency(지연), Efficiency(효율성)의 5대 핵심 설계 원칙.
- **Autonomous Operation (장애 독립성)**: 상위 백홀망이 단선되어도 엣지/포그 계층이 로컬 캐시와 제어 로직으로 무중단 단독 가동되는 능력.

</details>

- **엣지 컴퓨팅의 저지연 결정론성**: 데이터 수집 지점에서 1~5ms 내 즉각적 추론 및 액추에이터 제어
- **포그 컴퓨팅의 계층적 클러스터링**: 이종 통신 프로토콜(Modbus, BLE, CAN)을 수용하여 표준 IP로 변환 및 로컬 분산 저장
- **백본 대역폭 및 클라우드 부하 절감**: 원시 데이터를 현장에서 정제하여 중앙망 전송 트래픽 절감

#### 한줄 요약
- 말단 즉시 제어, 포그 계층의 프로토콜 변환 및 데이터 정제, 계층 간 자율 운영성을 확보해야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **IEEE 1934 OpenFog Reference Architecture**: 엣지 디바이스부터 포그 노드, 클라우드 데이터센터에 이르는 분산 계층을 표준화한 레퍼런스 모델.

</details>

```text
[계층형 분산 컴퓨팅 아키텍처]
  │
  ├─ [단말 엣지 계층] ── Edge Devices
  │     ├─ [IoT 센서 및 액추에이터] (원시 신호 계측)
  │     ├─ [On-Device 초경량 연산] (저지연 즉시 제어)
  │     └─ [현장 단독 자율 가동] (Autonomous Operation)
  │
  ├─ [로컬 포그 계층] ── Fog Nodes (IEEE 1934)
  │     ├─ [산업용 게이트웨이] (이종 프로토콜 변환)
  │     ├─ [로컬 클러스터링] (다중 엣지 데이터 요약)
  │     └─ [동적 연산 오프로딩] (인접 포그 간 부하 분산)
  │
  └─ [중앙 클라우드 계층] ── Central Cloud
        ├─ [빅데이터 통합 저장소] (장기 시계열 축적)
        ├─ [대규모 AI 모델 학습] (글로벌 예측 모델 생성)
        └─ [전역 오케스트레이션] (포그/엣지로 모델 배포)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| **엣지 계층** | 원시 신호 처리와 현장 제어 |
| **포그 계층** | 다중 엣지 집계와 프로토콜 변환 |
| **클라우드 계층** | 전역 분석·학습·장기 저장 |

#### 한줄 요약
- 엣지, 포그, 클라우드 계층의 역할을 명확히 분담하여 백홀 부하와 왕복 지연을 절감해야 한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Computation Offloading (동적 연산 오프로딩)**: 엣지 디바이스의 CPU/배터리 자원이 부족할 때 연산 작업을 인접 포그 노드로 위임 처리하는 기법.

</details>

```text
[다계층 데이터 수집·정제 흐름] (진행 ①→⑤, ① 이상 감지 및 제어 분기)
  │
  ├─ [엣지 센서·액추에이터] (① 고주파 계측 후 이상 감지 시 1ms 내 즉시 제어)
  │
  ├─ [포그 게이트웨이] (② 이종 프로토콜 변환, ③ 노이즈 필터링 및 요약 집계)
  │     └─ (자원 부족 시 Computation Offloading으로 인접 포그 위임)
  │
  ├─ [중앙 클라우드] (④ 정제된 메타데이터만 백홀 수신 후 전역 저장 및 재학습)
  │
  └─ [모델 배포기] (⑤ 재학습된 AI 가중치를 포그·엣지로 하향 배포)
```

분기 결과: ① 이상 감지 여부에 따라 엣지에서 즉시 제어하는 경로와, ③ 포그 정제 후 중앙 클라우드로 전송되는 분석 경로로 분기되며, 각각의 지연 요구조건에 최적화된 처리 경로로 귀결된다.

#### 한줄 요약
- 현장 긴급 제어는 엣지에서 즉시 처리하고 정제된 데이터는 포그를 거쳐 클라우드로 전달하여 재학습해야 한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Data Residency (데이터 상주성)**: 국가 규제나 보안상의 이유로 데이터가 사업장 물리적 경계 내에 상주해야 하는 보안 요건.

</details>

| 비교 항목 | 엣지 컴퓨팅 (Edge Computing) | 포그 컴퓨팅 (Fog Computing) | 중앙 클라우드 (Central Cloud) |
|:---|:---|:---|:---|
| 배치 위치 | 데이터 발생 장치 | 로컬 게이트웨이·서버 | 원격 데이터센터 |
| 네트워크 범위 | 장치·직결 링크 | LAN·사이트 | WAN·리전 |
| 연산 자원 | 제한된 임베디드 자원 | 중간 규모 분산 자원 | 대규모 공유 자원 |
| 처리 목적 | **현장 즉시 제어** | **집계·변환·로컬 분석** | 전역 분석·학습·저장 |
| 단절 대응 | 로컬 기능 범위에서 가능 | 사이트 기능 범위에서 가능 | 연결 의존 서비스 제한 |

#### 한줄 요약
- 엣지는 장치 내 저지연 제어를, 포그는 로컬 네트워크 데이터 중계를, 클라우드는 전역 연산을 전담해야 한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **IEEE 1588 PTP (Precision Time Protocol)**: 분산된 센서와 포그 노드 간의 내부 클록 오차를 마이크로초(㎲) 이하로 정밀 동기화하는 네트워크 시각 표준.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 엣지 디바이스 연산 자원 고갈로 인한 지연 및 패킷 드롭 | 태스크 복잡도 기반 포그 계층 동적 연산 오프로딩(Offloading) | 엣지 과부하 방지 및 전체 서비스 SLA 유지 |
| 상위 포그 노드 단선 시 하위 엣지 디바이스의 연쇄 장애(SPOF) | 엣지 노드 내 로컬 캐시 및 상태 머신 기반 장애 독립성 구현 | 상위망 단선 시에도 현장 공정 무중단 유지 |
| 분산 노드 간 시간 불일치로 인한 시계열 분석 데이터 왜곡 | L2/L3 네트워크 전반에 **IEEE 1588 PTP** / TSN 정밀 시각 동기화 | 마이크로초 단위 시계열 데이터 정합성 보장 |
| 분산 배치된 포그 게이트웨이에 대한 비인가 기기 침해 위협 | 노드 간 통신에 mTLS 상호 인증 및 하드웨어 TPM 키 격리 | 중간자 공격 차단 및 보안성 강화 |

#### 한줄 요약
- 동적 오프로딩, 장애 독립성, PTP 시각 동기화, mTLS 및 TPM 보안을 적용하여 분산 컴퓨팅의 신뢰성을 확보해야 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **Industry 4.0 (인더스트리 4.0)**: 사물인터넷, 클라우드, AI를 융합하여 스마트 팩토리와 무인 자동화를 실현하는 차세대 제조업 패러다임.

</details>

- 데이터의 수명주기와 지연 민감도에 따라 작업을 분배하는 스마트 시티, 인더스트리 4.0 및 대규모 분산 IoT 인프라의 표준 다계층 컴퓨팅 패러다임으로 확립.
- 실무 아키텍처 구현 시에는 **디바이스 부하에 따른 포그 계층 동적 연산 오프로딩(Computation Offloading)**, **상위망 단선 시 로컬 단독 가동을 보장하는 장애 독립성(Autonomous Operation) 설계**, **시계열 데이터 정합성을 위한 IEEE 1588 PTP 시각 동기화**, **노드 간 mTLS 및 TPM 하드웨어 보안**을 결합하여 안정적인 분산 제어 환경을 완성.

#### 한줄 요약
- 엣지-포그-클라우드 다계층 연계를 통해 저지연 현장 제어와 전역 빅데이터 분석을 조화롭게 달성해야 한다.
