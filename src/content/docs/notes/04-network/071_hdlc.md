## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **HDLC (High-Level Data Link Control)**: 동기식 직렬 링크 상에서 신뢰성 있는 프레임 전송을 수행하는 ISO 표준(ISO 13239) 비트 지향 데이터 링크 프로토콜.
- **Bit-Oriented Protocol**: 특정 문자셋에 구애받지 않고 임의의 이진 비트열을 플래그(`01111110`)로 프레임화하여 전송하는 프로토콜.

</details>

- 정의/개념: 고유 플래그(`01111110`)와 비트 채움(Bit Stuffing)으로 데이터 투명성을 보장하고 슬라이딩 윈도우 및 CRC 제어를 수행하는 ISO 표준 L2 프로토콜
- 배경/필요성: 초기 문자 지향 프로토콜(BSC: Binary Synchronous Communication)은 특정 문자셋(ASCII/EBCDIC)에 종속되어 제어 문자(STX, ETX 등)와 동일한 바이너리 데이터가 유입될 때 프레임 경계를 오인하는 데이터 투명성 결여 문제가 발생하고, 반이중(Half-Duplex) 통신으로 인한 전송 효율 저하를 노출함에 따라, 프레임의 시작과 끝을 고유 플래그(`01111110`)로 정의하고 5연속 '1' 발생 시 '0'을 삽입하는 비트 스터핑(Bit Stuffing) 및 슬라이딩 윈도우 기반의 비트 지향 L2 프로토콜 표준인 **HDLC**(ISO 13239)를 도입하여 문자셋 무관 데이터 투명성 보장, I/S/U 프레임을 통한 엄격한 전이중 흐름·오류 제어 및 점대점/점대다 동기 직렬 통신 신뢰성을 달성할 필요

#### 한줄 요약
- 프레임 경계 판정을 문자셋에서 비트 패턴으로 옮겨 비트 채움 연산을 지불하되, 데이터 투명성을 확보해야 한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Bit Stuffing (비트 스터핑)**: 데이터 페이로드 내에 연속된 5개의 '1'이 발생하면 하드웨어가 자동으로 '0'을 삽입하여 플래그 오인식을 방지하는 기법.
- **Piggybacking (피기배킹)**: 수신 확인(ACK)을 전송할 때 별도의 ACK 프레임을 보내지 않고 전송할 데이터(I-Frame) 헤더의 $N(R)$ 필드에 얹어 보내는 기법.

</details>

- 데이터 투명성(**Bit Stuffing**): 5연속 '1' 발생 시 '0'을 강제 삽입하여 플래그(`01111110`) 오인식 방지
- I/S/U 프레임 다중 제어 체계: 정보 전송(I), 감시 및 흐름 제어(S), 링크 수립 및 무번호 제어(U) 분리
- 피기배킹(**Piggybacking**) 기반 고효율 전송: 데이터 프레임 전송 시 수신 확인 번호 $N(R)$을 함께 실어 대역폭 절감

#### 한줄 요약
- 비트 스터핑 투명성, I/S/U 프레임 분리 제어, 피기배킹을 통한 대역폭 최적화를 제공해야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Control Field (제어부)**: 프레임 유형(I/S/U)을 구분하고 순서 번호 $N(S)$, $N(R)$, P/F 비트를 탑재하여 흐름 제어를 집행하는 8/16비트 필드.
- **FCS (Frame Check Sequence)**: CRC-16/32 다항식으로 선로 상의 비트 반전 오류를 검출하는 검사 필드.

</details>

```text
[HDLC 프레임]
  │
  ├─ [동기화] ── Synchronization
  │     └─ [Flag(플래그)] (8비트 고유 패턴 01111110으로 프레임 시작과 종료 경계 동기화)
  ├─ [식별/제어] ── Identification/Control
  │     ├─ [Address(주소부)] (다중점 링크 환경에서 종국(Secondary)의 식별 주소 지정)
  │     └─ [Control(제어부)] (I/S/U 프레임 유형 판별 및 순서 번호 기반 흐름 제어)
  ├─ [데이터] ── Data
  │     └─ [Information(정보부)] (상위 계층에서 전달된 순수 데이터 페이로드 수용, I-프레임 전용)
  └─ [오류검출] ── Error Detection
        └─ [FCS(검사부)] (CRC-16/32 다항식을 통한 전송 선로 비트 오류 무결성 검증)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| **Flag (플래그)** | 8비트 고유 패턴(`01111110`)으로 프레임 시작과 종료 경계 동기화 |
| **Address (주소부)** | 다중점 링크 환경에서 종국(Secondary)의 식별 주소 지정 |
| **Control (제어부)** | I/S/U 프레임 유형 판별 및 송수신 순서 번호($N(S), N(R)$) 기반 흐름 제어 |
| Information (정보부) | 상위 계층에서 전달된 순수 데이터 페이로드 수용 (I-프레임 전용) |
| **FCS (검사부)** | CRC-16/32 다항식을 통한 전송 선로 비트 오류 무결성 검증 |

#### 한줄 요약
- Flag가 프레임 경계 표시를 전담하고 Control 필드가 I/S/U 역할을 갈라놓으므로, 데이터 내용과 무관하게 동일한 프레이밍 규칙이 적용된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **I-Frame vs S-Frame vs U-Frame**: 정보 전송(I), 감시/ACK/재전송(S), 링크 수립/해제(U).

</details>

```text
[HDLC 링크 수립·전송 흐름] (진행 ①→⑤, 수립에서 진입, ①→② 데이터 전송, ③ 검증, ④ FCS 판정 분기, ⑤ 회신)
  │
  ├─ [U-프레임 링크 수립부] (① SABM 송출 후 UA 응답으로 링크 개통)
  │
  ├─ [비트 스터핑·I-프레임 송신기] (② 5연속 '1' 뒤 '0' 삽입 후 **I-Frame** 데이터 송출)
  │
  ├─ [수신 디스터핑·FCS 검증기] (③ 삽입된 '0' 제거 후 CRC 무결성 검증)
  │
  ├─ [FCS 판정기] (④ CRC 계산값과 수신 FCS 비교)
  │
  └─ [S-Frame 회신부] (⑤ 정상 시 **S-Frame** RR로 윈도우 전진, 오류 시 REJ로 Go-Back-N 재전송 유발)
```

분기 결과: ④ FCS 판정에서 갈라져 정상이면 ⑤ RR 회신으로 윈도우가 전진하고 오류면 REJ가 Go-Back-N 재전송을 일으키는데, REJ는 수신 버퍼를 아끼는 대신 이후 전체 재전송을 지불하고 SREJ로 바꾸면 오류 프레임 1개만 되받는 대신 수신 버퍼를 내준다.

#### 한줄 요약
- FCS 판정에서 정상 수신과 재전송 요구로 갈리며, SREJ는 오류 프레임 1개만 되받는 대신 수신 버퍼를, REJ는 버퍼를 아끼는 대신 이후 전체 재전송을 지불한다.

## Ⅴ. 종류 및 비교


| 비교 항목 | 정규 응답 모드 (NRM) | 비동기 응답 모드 (ARM) | 비동기 균형 모드 (ABM) |
|:---|:---|:---|:---|
| 국(Station) 구조 | 주국(Primary) - 종국(Secondary) | 주국(Primary) - 종국(Secondary) | 복합국(Combined) - 대등 관계 |
| 링크 제어 권한 | 주국 중심 통제 (폴링/선택) | 주국 통제 하 종국 자발 전송 | **양단이 대등하게 독립 제어** |
| 종국 전송 권한 | 주국의 폴링(Poll) 허가 시 전송 | 허가 없이 자발적 전송 가능 | 상시 양방향 전이중(Full-Duplex) |
| 적용 토폴로지 | 점대다(Point-to-Multipoint) | 점대다 특수 환경 | 점대점(Point-to-Point) 전용선 |
| 대표 활용 사례 | IBM SNA / SDLC 단말 통신 | 구형 멀티드롭 센서망 | X.25 (LAPB), ISDN (LAPD), PPP |

#### 한줄 요약
- NRM은 주국 허가 기반, ARM은 종국 자발 전송 기반, ABM은 대등한 1:1 전이중 통신 모드이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Extended Control Field**: 고속·고지연 위성 전용선에서 3비트 순서 번호($0\sim 7$)의 조기 소진을 방지하기 위해 7비트 순서 번호($0\sim 127$)로 확장하는 규격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 데이터 페이로드 내 01111110 우연 발생 시 조기 종료 오인식 | 송신단 비트 채움(Bit Stuffing: 5연속 '1' 뒤 '0' 삽입) 의무화 | 프레임 경계 오탐 방지 및 데이터 투명성 확보 |
| 송수신 장비 간 동작 모드(NRM vs ABM) 불일치로 링크 수립 불가 | 초기화 시 U-프레임(SABM/SNRM) 교환을 통한 모드 자동 협상 | 이종 모드 충돌 방지 및 정상 데이터 링크 개통 |
| 고속 고지연 링크에서 3비트 제어 필드 순서 번호 고갈 및 지연 | 확장 제어 필드(**Extended Control Field**: 7비트 N(S)/N(R)) 적용 | 슬라이딩 윈도우 확대로 링크 대역폭 활용률 향상 |
| 잡음이 심한 선로에서 REJ로 인한 불필요한 전체 프레임 재전송 | 선택적 거부(SREJ: Selective Reject) ARQ 모드 활성화 | 손실된 특정 프레임만 단독 재전송하여 전송 효율 보존 |

#### 한줄 요약
- Bit Stuffing, U-프레임 협상, 확장 제어 필드, SREJ 모드를 통해 데이터 링크 안정성을 확보해야 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **PPP (Point-to-Point Protocol)**: HDLC 프레임 형식을 기반으로 LCP와 NCP를 결합하여 이기종 프로토콜 전송과 인증을 지원하는 데이터 링크 프로토콜.
- **LAPB (Link Access Procedure, Balanced)**: X.25 패킷망의 데이터 링크 계층에서 HDLC ABM 모드를 채택하여 구현한 신뢰성 높은 링크 제어 프로토콜.

</details>

- 초기 WAN 및 전용선 인프라에서 시작하여 X.25(LAPB), ISDN(LAPD), GSM(LAPDm) 및 인터넷 표준인 PPP(Point-to-Point Protocol)의 모태가 됨으로써 현대 데이터 링크 계층(L2) 프레이밍 및 흐름 제어 아키텍처의 이론적 기반이자 글로벌 표준으로 확립되었다.
- 고속 이더넷과 광통신망 중심 환경에서도 산업용 직렬 제어망과 위성 텔레메트리 링크에서 여전히 필수적으로 활용되는 가운데, 실무 직렬 링크 구축 시에는 **프레임 조기 종료 오탐을 방지하는 하드웨어 비트 스터핑 필수 적용**, **대등 1:1 전이중 통신을 위한 ABM(Asynchronous Balanced Mode) 채택**, **고지연 위성 링크 대역폭 활용 최적화를 위한 7비트 확장 제어 필드 및 SREJ(선택 재전송) ARQ 연동**을 결합하여 안정적인 데이터 링크 무결성을 달성해야 한다.

#### 한줄 요약
- HDLC는 비트 스터핑과 I/S/U 프레임 제어 체계를 준수하여 안정적인 데이터 링크 계층 통신을 보장해야 한다.
