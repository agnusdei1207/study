## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **IDS (Intrusion Detection System)**: 트래픽 미러링(SPAN/TAP)을 통해 네트워크 침입을 수동 모니터링하고 경보(Alert)를 발송하는 수동형 시스템.
- **IPS (Intrusion Prevention System)**: 네트워크 경로 상에 인라인(Inline)으로 배치되어 악성 패킷을 실시간 탐지하고 즉각 폐기(Drop)하는 능동형 보안 시스템.

</details>

- 정의/개념: L4~L7 DPI와 시그니처 및 이상 징후 분석을 통해 **침입 행위를 모니터링·경보하는 IDS와 실시간 인라인 패킷을 차단하는 IPS**
- 배경/필요성: 전통적인 L3/L4 방화벽이 허용한 정상적인 80/443 포트를 통해 침투하는 L7 웹 애플리케이션 취약점(SQL Injection, XSS), 원격 코드 실행(RCE), 버퍼 오버플로우 및 제로데이 익스플로잇 위협을 헤더 검사만으로는 식별 및 차단할 수 없는 한계를 극복하기 위해, L4~L7 페이로드 심층 패킷 검사(DPI)를 바탕으로 CVE 시그니처 대조(오용 탐지)와 비정상 행위 프로파일링(이상 탐지)을 수행하고, 무지연 모니터링(IDS 미러링)과 실시간 능동 차단(IPS 인라인)으로 대응하는 침입 탐지·방지 시스템을 도입하여 **지능형 네트워크 공격에 대한 실시간 방어력과 심층 침해 가시성**을 달성할 필요

#### 한줄 요약
- 미러링 기반 경보(IDS)와 인라인 실시간 차단(IPS)을 통해 네트워크 심층 위협을 방어한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Signature Detection (오용 탐지)**: 알려진 공격 패턴 지문(CVE 취약점 시그니처)과 일치 여부를 대조하는 방식 (낮은 오탐률, 제로데이 불가).
- **Anomaly Detection (이상 탐지)**: 정상 트래픽 기준선(Baseline)을 학습하고 통계적/행위적 임계치 초과 변칙을 식별하는 방식 (신종 공격 탐지, 오탐 주의).

</details>

- **IDS(경로 외, Out-of-band)**: 원본 패킷 전달 지연이 전무하며 SPAN/TAP 포트로 수동 감시 수행
- **IPS(경로 상, Inline)**: 실시간 패킷 검사 후 즉각 폐기(Drop) 및 TCP Reset 전송으로 능동 차단
- **시그니처 탐지(오용 탐지)**와 **이상 징후 탐지(행위 기반)** 기법의 혼합 적용을 통한 탐지율 향상

#### 한줄 요약
- Out-of-band 무지연 감시(IDS)와 Inline 실시간 능동 차단(IPS)을 시그니처 및 이상 탐지와 결합하여 운용해야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Session Normalization (세션 정규화)**: 단편화된 패킷을 재조립하고 인코딩을 디코딩하여 공격자의 우회 기법(Evasion)을 무력화하는 전처리 엔진.
- **Hardware Bypass (Fail-Open)**: IPS 장비 장애 또는 전원 차단 시 트래픽 단절을 방지하기 위해 물리적 릴레이 스위치로 회선을 직결시키는 모듈.

</details>

```text
[IDS/IPS 침입 탐지 및 방지 아키텍처]
  │
  ├─ [트래픽 전처리부] (Session Normalization)
  │     ├─ [패킷 조각 재조립] (IP 단편화 우회 공격 무력화)
  │     └─ [프로토콜 디코딩] (URL/Base64/난독화 정규화)
  │
  ├─ [심층 탐지 엔진] (Detection Engine)
  │     ├─ [오용 탐지] (Signature 기반 CVE 취약점 패턴 대조)
  │     └─ [이상 탐지] (Behavior 기반 정상 베이스라인 이탈 감지)
  │
  ├─ [대응 및 차단 제어부] (Response Controller)
  │     ├─ [IDS 수동 모니터링] (Alert 경보 및 로그 기록)
  │     └─ [IPS 능동 차단] (Drop 패킷 폐기 및 TCP RST 주입)
  │
  └─ [가용성 보장 모듈] (High Availability)
        └─ [하드웨어 바이패스] (장비 장애 시 Fail-Open 물리 직결)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 세션 정규화기 | 패킷 재조립 및 디코딩을 통한 우회 공격(Evasion) 무력화 |
| 탐지 엔진 | 시그니처 기반 오용 탐지 및 행위 기반 이상 징후 분석 |
| 정책 판정 엔진 | 위협 수준별 경보(Alert) 및 실시간 차단(Drop) 정책 결정 |
| 대응 실행기 | 인라인 패킷 폐기(Drop), TCP RST 주입 및 관리자 알림 집행 |
| 하드웨어 바이패스 | IPS 장비 장애 또는 전원 상실 시 회선을 물리 직결(Fail-Open) |

#### 한줄 요약
- 세션 정규화기로 우회 시도를 차단하고 탐지 엔진과 바이패스 모듈로 보안성과 가용성을 동시에 확보해야 한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **TCP RST 주입**: 탐지된 악성 TCP 세션을 강제 종료시키기 위해 공격자와 피해자 양측으로 위조된 TCP RST 플래그 패킷을 송출하는 기법.

</details>

```text
[IDS·IPS 탐지·대응 흐름] (진행 ①→④, 전처리 검사에서 진입, ④ 탐지 판정 결과로 대응 분기)
  │
  ├─ [트래픽 수집부] (① TAP·SPAN 미러링(IDS) 또는 인라인 직렬 수신(IPS))
  │
  ├─ [세션 정규화기] (② 패킷 재조립·디코딩으로 단편화·난독화 우회 무력화)
  │
  ├─ [탐지 엔진] (③ CVE 시그니처 룰셋 대조와 정상 베이스라인 이탈 프로파일링)
  │
  ├─ [IDS 경보기] (④ 악성 식별 시 Alert 전송 및 SIEM 원시 증적 보존)
  │
  └─ [IPS 차단기] (④ 악성 식별 시 Drop 폐기 및 TCP RST 주입으로 세션 강제 종료)
```

분기 결과: 탐지 판정 결과 정상 트래픽은 통과하고, 악성 트래픽은 IDS 환경에서는 경보 및 로그 기록으로 분기되며, IPS 환경에서는 패킷 폐기 및 TCP RST 주입을 통한 강제 종료로 분기된다.

#### 한줄 요약
- 악성 트래픽 판정 시 IDS는 경보 및 증적 보존으로 분기하고, IPS는 패킷 폐기 및 세션 강제 종료로 분기해야 한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **False Positive (오탐)** vs **False Negative (미탐)**: 정상 트래픽을 공격으로 오인하여 차단하는 오류(오탐)와 실제 공격을 놓치는 오류(미탐).

</details>

| 비교 항목 | 침입 탐지 시스템 (IDS) | 침입 방지 시스템 (IPS) |
|:---|:---|:---|
| 네트워크 배치 방식 | **경로 외 (Out-of-band / SPAN, TAP 미러링)**| **경로 상 (Inline / 물리적 직렬 연결)** |
| 서비스 가용성 영향 | **지연 전무 (Zero Latency), 장애 시 영향 없음** | **패킷 검사 지연 발생, 장비 장애 시 망 단절 위험** |
| 위협 대응 메커니즘 | 사후 분석, 관리자 경보, PCAP 증적 저장 | **실시간 인라인 패킷 차단(Drop), TCP RST 세션 파기** |
| 오탐(False Positive) 영향 | 경보 피로(Alert Fatigue) 유발에 그침 | **정상 고객 비즈니스 서비스 차단 장애 유발** |

#### 한줄 요약
- 비즈니스 영향도를 고려하여 무지연 감시에는 IDS를, 실시간 능동 방어에는 IPS를 구분 적용해야 한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Fail-Open (Bypass)**: IPS 장애 시 트래픽을 차단하지 않고 무조건 통과시켜 가용성을 보장하는 모드.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 과도한 오탐(False Positive)으로 인한 정상 비즈니스 서비스 차단 장애 | **초기 `IDS 모드(Alert-only) 검증` 후 단계적 인라인 IPS 전환** | 오탐 차단 방지 및 룰셋 신뢰도 확보 |
| 패킷 분할/변조를 통한 침입 탐지 우회(Evasion Attack) 시도 | **`세션 정규화(Normalization)` 및 재조립 타임아웃 튜닝** | 파편화 우회 공격 무력화 |
| 인라인 IPS 장비의 전원/하드웨어 고장 시 전체 네트워크 마비 | **광/구리선 `하드웨어 바이패스(Hardware Bypass / Fail-Open)` 장착** | 장비 장애 시에도 물리 링크 직결 가용성 보증 |
| 암호화(HTTPS) 트래픽 급증으로 L7 악성 페이로드 탐지 불가 | **IPS 전단에 `SSL 가시성 어플라이언스(SSL Offloader)` 연동** | 암호화 트래픽 복호화 및 위협 가시성 확보 |

#### 한줄 요약
- 단계적 IDS/IPS 전환, 세션 정규화, 하드웨어 바이패스, SSL 가시성 연동을 체계적으로 적용해야 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **NDR (Network Detection and Response)**: 네트워크 전반의 원시 트래픽과 플로우 데이터를 머신러닝 기반으로 상시 분석하여 지능형 위협을 탐지하고 자동 대응하는 보안 솔루션.

</details>

- 방화벽 후단에서 심층 페이로드를 실시간 분석하여 취약점 공격을 차단하는 엔터프라이즈 네트워크 경계 및 호스트 방어의 핵심 능동 보안 인프라로 확립.
- 최근에는 단일 하드웨어 어플라이언스를 넘어 머신러닝 기반 이상 징후 탐지와 클라우드 NDR 및 XDR 플랫폼으로 진화하고 있으며, 실무 구축 시에는 오탐 방지를 위한 초기 IDS(Alert-Only) 검증 후 단계적 IPS 전환, 망 단절을 방지하는 하드웨어 바이패스(Fail-Open), 암호화 위협 가시성을 위한 SSL/TLS 복호화 연동을 결합하여 고가용성 능동 방어 체계를 완성.

#### 한줄 요약
- DPI 및 시그니처·이상 탐지 기반 위협 차단과 하드웨어 바이패스 및 SSL 가시성 연동을 결합하여 무중단 능동 보안을 구현해야 한다.
