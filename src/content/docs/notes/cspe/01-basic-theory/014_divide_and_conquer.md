## 답안 골격
```text
[분할 정복] ◀━━ 머리: Ⅶ 내 의견 (멀티코어 확장성 극대화를 위한 작업 훔치기 기반 Fork-Join 프레임워크 결합)
 ┃
 ┣━ Ⅰ 개요 ───── 단일 거대 문제 해결 한계 → 동일한 유형의 독립된 작은 하위 문제로 쪼개어 해결하는 설계 패러다임
 ┣━ Ⅱ 3단계 ──── 분할(Divide: 문제 축소) → 정복(Conquer: 재귀적 해결) → 결합(Combine: 부분해 취합)
 ┣━ Ⅲ 수식 ───── 마스터 정리 $T(n) = aT(n/b) + f(n)$ 기반 점근적 시간 복잡도 판정
 ┣━ Ⅳ 흐름 ───── 병합 정렬(Merge Sort) 및 이진 탐색의 분할-정복-결합 처리 메커니즘
 ┣━ Ⅴ 비교 ───── 분할 정복(D&C) vs 동적 계획법(DP) (독립적 부분 문제 vs 중복 부분 문제 메모이제이션)
 ┗━ Ⅵ 실무 ───── 고속 푸리에 변환(FFT) · 스트라센 행렬 곱셈 · Fork-Join 멀티코어 병렬화
```
- 필수 키워드: 분할(Divide) · 정복(Conquer) · 결합(Combine) · 마스터 정리(Master Theorem) · Fork-Join · 부분 문제 독립성
- 배점 전략: 10점 = Ⅰ 개요 → Ⅱ 3단계 메커니즘 도식 → Ⅲ 마스터 정리 수식 → Ⅴ 동적 계획법과의 차이점

## 한 줄 본질
- 하나의 거대한 문제를 직접 풀기 어려울 때 동일한 구조의 독립된 작은 문제들로 분할 → 최소 단위(기저 사례)까지 쪼개어 각각 해결 후 결과를 역으로 병합 → 병렬 처리 용이성 / 재귀 호출 스택 및 병합 연산 비용

## 핵심 통찰
- 분할 정복의 성공 조건은 분할된 하위 문제들이 상호 의존하지 않는 "독립성(Independence)"이며, 만약 하위 문제가 겹친다면 분할 정복 대신 동적 계획법을 써야 함
- 마스터 정리($T(n) = aT(n/b) + f(n)$)에서 분할 재귀 연산의 증가율($n^{\log_b a}$)과 결합 비용($f(n)$) 중 어느 쪽이 지배적인가에 따라 전체 시간 복잡도가 결정됨
- 하위 문제 간 데이터 공유가 없으므로 멀티코어 CPU 및 분산 클러스터 환경에서 MapReduce나 Fork-Join 형태의 비공유(Shared-Nothing) 병렬 처리에 매우 적합함

## 이웃 토픽과 구분
- 분할 정복 vs 동적 계획법:
| 비교 항목 | 분할 정복 (Divide & Conquer) | 동적 계획법 (Dynamic Programming) |
|---|---|---|
| 하위 문제 특성 | 상호 독립적 (Non-overlapping) | 중복 및 상호 의존 (Overlapping) |
| 처리 기법 | 재귀적 분할 후 결과 병합 | 이전 계산 결과 저장(메모이제이션/타뷸레이션) |
| 대표 사례 | 퀵 정렬, 병합 정렬, 이진 탐색 | 벨만-포드, 플로이드-워셜, 최장 공통 부분수열(LCS) |

## 문제·원인·대책
- 적용 상황: 대규모 수치 행렬 연산 및 분산 데이터 정렬 시스템
| 문제 | 원인 | 대책 | 효과 |
|---|---|---|---|
| 미세한 분할로 인한 재귀 오버헤드 폭증 | 기저 사례 임계값이 너무 작아 함수 호출 프레임 비용이 실제 연산 비용을 초과 | 분할 크기가 임계값($N \le 16$) 이하로 떨어지면 순차 직접 알고리즘으로 전환 | 재귀 호출 오버헤드 차단 |
| 결합 단계(Combine)에서 병목 발생 | 부분해를 병합하는 과정이 단일 스레드로 직렬화되어 전체 병렬성 저하 | 결합 알고리즘 자체를 병렬화(Parallel Merge)하거나 제자리(In-place) 결합 설계 | 결합 처리 시간 단축 |

## 내 의견
- [멀티코어 확장성 극대화를 위한 작업 훔치기 기반 Fork-Join 프레임워크 결합] 분할 정복 알고리즘을 멀티 스레드로 단순 매핑하면 하위 작업의 처리 시간 불균형으로 인해 특정 코어만 놀고 다른 코어는 정체되는 부하 불균형이 발생함 → 나라면: 각 스레드가 자신만의 데크(Deque)를 소유하고 유휴 스레드가 다른 스레드의 꼬리에서 작업을 가로채는 작업 훔치기(Work-Stealing) 스케줄링을 Fork-Join 풀과 결합하여 코어 가동률을 극대화
