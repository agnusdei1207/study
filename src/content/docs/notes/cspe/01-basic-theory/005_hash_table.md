## 답안 골격
```text
[해시 테이블] ◀━━ 머리: 해시 함수 사상 기반 O(1) 초고속 조회 및 체이닝·개방주소법 충돌 해결
 ┃
 ┣━ Ⅰ 개요 ───── 순차/이진 탐색의 $O(n), O(\log n)$ 한계 → 해시 함수를 통해 키를 배열 인덱스로 즉각 사상
 ┣━ Ⅱ 수식 ───── 인덱스 $h(k) = k \pmod m$ · 비둘기집 원리에 의한 해시 충돌(Collision)의 필연성
 ┣━ Ⅲ 구조 ───── Key $\to$ 해시 함수 $\to$ Hash Code $\to$ 버킷 배열(Bucket Array) 인덱스 매핑
 ┣━ Ⅳ 충돌해결 ─ 분리 연결법(Chaining: 외부 리스트) vs 개방 주소법(Open Addressing: 내부 빈 슬롯 조사)
 ┣━ Ⅴ 비교 ───── 선형 조사(Linear) vs 이차 조사(Quadratic) vs 이중 해싱(Double Hashing)
 ┗━ Ⅵ 실무 ───── 적재율(Load Factor $\alpha = n/m$) 관리 · 동적 재해싱(Rehashing) · 보안 취약점(Hash DoS)
```
- 필수 키워드: 해시 함수 · 해시 충돌(Collision) · 체이닝(Chaining) · 개방 주소법 · 군집화(Clustering) · 적재율(Load Factor)

## 한 줄 본질
- 가변 길이의 키를 고정 크기의 정수 인덱스로 변환해 메모리 주소에 직접 접근함으로써 평균 $O(1)$의 탐색 속도를 보장 → 최고 속도의 데이터 조회 / 해시 충돌 및 최악의 경우 $O(n)$ 성능 퇴보

## 핵심 그림
```text
[Key]           [해시 함수 h(k)]        [버킷 배열 (Bucket Array)]
"apple"  ====>  h("apple") = 1 ======> [ 0 ]
                                       [ 1 ] -> ["apple", Val1] -> ["kiwi", Val3] (체이닝)
"banana" ====>  h("banana") = 3 =====> [ 2 ]
                                       [ 3 ] -> ["banana", Val2]
"kiwi"   ====>  h("kiwi") = 1   (충돌!)
```

## 핵심 통찰
- 비둘기집 원리에 의해 키 공간이 버킷 수보다 크면 해시 충돌은 수학적으로 불가피하며, 테이블의 적재율(Load Factor)이 일정 수준(보통 $0.75$)을 넘으면 버킷 배열을 2배로 확장하고 재해싱해야 성능이 유지됨
- 개방 주소법의 선형 조사는 연속된 슬롯에 데이터가 뭉치는 1차 군집화(Primary Clustering)를 유발하므로, 충돌 시 두 번째 해시 함수로 건너뛰는 이중 해싱(Double Hashing)이 가장 효과적임

## 이웃 토픽과 구분
- 체이닝 vs 개방 주소법:
| 비교 항목 | 분리 연결법 (Chaining) | 개방 주소법 (Open Addressing) |
|---|---|---|
| 충돌 저장 위치 | 버킷 외부의 연결 리스트/트리 | 버킷 배열 내부의 빈 다른 슬롯 |
| 메모리 관리 | 노드 동적 할당 오버헤드 존재 | 추가 메모리 없이 고정 배열 활용 |
| 적재율 허용치 | $\alpha > 1$ 가능 (테이블 크기 초과 가능) | $\alpha < 1$ 엄격 제한 (빈 슬롯 필수) |
| 캐시 효율성 | 포인터 체이싱으로 캐시 미스 발생 | 연속 메모리 배치로 캐시 지역성 우수 |
