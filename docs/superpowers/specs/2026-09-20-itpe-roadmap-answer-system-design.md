# ITPE 로드맵·실전답안 체계 개편 설계

## 1. 목적

`src/content/docs/notes/itpe/`를 단순 키워드 백과사전이 아니라 정보관리기술사 필기시험에서 제한 시간 안에 답안을 인출하고 작성하기 위한 학습 체계로 개편한다.

사용자가 제공한 11개 도메인 로드맵 이미지를 분석해 과목별 큰 그림, 핵심 키워드, 출제 중요도 참고값, 답안 작성 구조를 Markdown으로 보존한다. 모든 과목 시작 페이지에는 세부 토픽보다 먼저 큰 그림을 배치한다.

전체 정본 토픽 수는 1,000개를 상한으로 하고, 가능하면 850~950개로 축약한다. 삭제되는 중복 용어는 모(母)토픽의 하위 키워드와 별칭으로 보존하여 검색 누락을 방지한다.

## 2. 성공 기준

1. ITPE 루트와 8개 과목 인덱스에서 큰 그림을 가장 먼저 볼 수 있다.
2. 제공 이미지의 모든 키워드는 `정본 토픽`, `하위 키워드`, `타 과목 연결`, `현행 제외/보정` 중 하나로 추적된다.
3. 전체 정본 토픽은 1,000개 이하이며 목표 범위는 850~950개다.
4. 각 정본 토픽에는 `기초` 또는 `코어` 배지가 하나만 표시된다.
5. 1과목 전체 노트가 새 작성법을 따른다.
6. 기출·유관시험·모의·트렌드가 서로 구분되고, 근거 없는 수치나 출처가 기출처럼 표시되지 않는다.
7. Astro 검사와 빌드가 통과하고 내부 링크가 유효하다.
8. 기존 사용자의 2과목 작업을 덮어쓰지 않는다.

## 3. 토픽 풀 정책

### 3.1 정본 수

- 상한: 1,000개
- 권장 목표: 850~950개
- 현재 파일 수를 그대로 목표 수로 간주하지 않는다.
- 동일 문항에서 함께 설명되는 개념, 단독 답안성이 낮은 세부 용어, 동일 개념의 한영·구판 명칭은 하나의 모토픽으로 통합한다.
- 기존 파일을 제거할 때는 키워드가 사라지지 않도록 모토픽의 `딸려 나오는 키워드`에 원 번호와 명칭을 기록한다.

### 3.2 `기초`와 `코어`

두 배지는 난이도보다 학습 역할을 나타낸다.

- `기초`: 정의·원리·분류를 이해해야 다른 토픽을 설명할 수 있는 기반 개념. 단독 출제빈도가 낮아도 기본 체계에 필요할 수 있다.
- `코어`: 실제 정보관리기술사 기출, 반복 출제, 최신 출제기준, 복수 영역 연결성 또는 10/25점 답안성이 높은 집중 학습 토픽.

분류 우선순위는 `공식 기출과 출제기준 > 답안 확장성 > 인접 토픽 연결성 > 교재 중요도`다. 제공 이미지의 상·중·하는 참고 자료이며 공식 출제확률로 사용하지 않는다.

기존 A/B/C는 작성·이관 과정에서만 내부 참고값으로 사용하고 사용자 화면에서는 `기초/코어`로 단순화한다. 기본 변환은 A·B를 코어 후보, C를 기초 후보로 하되 위 기준으로 재검토한다.

## 5. 큰 그림의 배치 구조

### 5.1 ITPE 루트

루트 인덱스에는 다음 전과목 흐름을 둔다.

```text
경영·전략·법제
      ↓
조달·요구·SW 개발 ── 데이터
      ↓                 ↓
컴퓨터시스템 ── 네트워크 ── 보안
      ↓
운영·서비스·유지보수
      ↓
AI·클라우드·융합·최신기술
```

### 5.2 과목 인덱스

각 과목 `index.md`는 다음 순서를 강제한다.

1. `## 과목 큰 그림`
2. `## 세부 도메인 로드맵`
3. `## 코어 키워드`
4. `## 기초 키워드`
5. `## 인접 과목 연결`
6. `## 출제 질문 유형`
7. `## 30초 인출 체크리스트`

큰 그림은 한 화면에서 계층과 흐름을 읽을 수 있는 Markdown 텍스트 도식으로 만든다. 세부 도메인은 표로 정리하고 실제 노트 링크를 연결한다.

## 6. 이미지 내용의 현행화 원칙

이미지는 분류 체계를 얻기 위한 참고 자료로 사용하고 오래된 명칭을 현재 정답으로 복사하지 않는다.

예시:

- ITIL 3.0 → ITIL 4와 생애주기/SVS 차이 병기
- ISO 9126 → ISO/IEC 25010 계열로 보정
- ISO 17799 → ISO/IEC 27001·27002 계열로 보정
- IPv4 클래스 기반 주소 → CIDR/VLSM 중심으로 보정
- Wi-Fi 6/7 → 현행 Wi-Fi 7 및 차기 표준 동향과 구분
- DES → 역사적 기초, AES·현대 암호 중심으로 위치 조정
- Web OS, 타임서버 등 단독 답안성이 낮은 항목 → 관련 모토픽의 하위 키워드로 흡수

교재의 Page 열은 제거하고 사이트 내부 링크로 대체한다.

## 7. 개별 토픽 작성 템플릿

### 7.1 화면 상단

- 제목
- `기초` 또는 `코어` 배지
- 출처 상태: `공식기출`, `유관시험`, `모의`, `트렌드`, `기본이론`
- 공식 기출 회차 및 원문 링크가 있을 때만 기출로 표시
- 검증 상태와 검토일

### 7.2 답안 영역

```markdown
## 딸려 나오는 키워드

## 10점형 실전 답안
### Ⅰ. 정의 및 등장 배경
### Ⅱ. 30초 핵심 그림
### Ⅲ. 핵심 요소·비교·시사점

## 25점형 확장 골격

## 문제 유형별 변형

## 보충 학습

## 검증 출처
```

10점형은 시험장에서 직접 옮겨 쓸 수 있는 분량과 표현으로 제한한다. 그림은 약 15~30초 안에 재현할 수 있도록 7~12개 노드, 짧은 라벨, 단방향 흐름을 원칙으로 한다.

25점형은 문제의 요구 동사에 따라 다음 골격 중 하나를 선택한다.

- 개념·분류: 정의 → 분류도 → 유형별 특징 → 적용
- 구성·동작: 정의 → 구성도 → 동작 절차 → 병목·대책
- 비교: 공통 정의 → 동일 비교축 → 선택 기준
- 문제·대책: 현상 → 원인 → 기술·관리·제도 대책 → 기대효과
- 법·정책: 목적·대상 → 의무·절차 → 영향 → 대응
- 계산·알고리즘: 전제·수식 → 계산/절차 → 복잡도·해석

상세 설명은 실전 답안 뒤에 배치하여 답안 인출과 학습 해설을 분리한다.

## 8. 1과목 적용 범위

`01-it-strategy`를 첫 완성 과목으로 삼는다.

1. 인덱스 최상단에 이미지 1 기반 큰 그림을 추가한다.
2. 현재 81개 정본 토픽의 중복과 범위를 재점검한다.
3. 각 토픽을 기초/코어로 분류한다.
4. 81개 노트를 새 작성 템플릿에 맞춘다.
5. 근거 없는 정량 효과는 공식 근거가 없으면 정성 효과 또는 측정 KPI로 바꾼다.
6. 기출 회차와 출처 유형을 분리한다.
7. 기존 하위 키워드 흡수 이력을 유지한다.

1과목의 기존 정본 81개는 이미 통합이 진행된 상태이므로 추가 축약은 실제 중복이 명확할 때만 수행한다.

## 10. 자동 검증

콘텐츠 검증 스크립트가 다음을 확인한다.

- 정본 토픽 총수 1,000개 이하
- 모든 토픽의 `기초/코어` 분류
- 허용된 출처 상태만 사용
- 코어 토픽의 실전답안·30초 그림·검증 출처 존재
- 중복 제목과 깨진 내부 링크
- 과목 인덱스의 큰 그림 존재
- 실제 파일 수와 진행 현황 문서 숫자 일치
- 근거 없이 단정한 정량 효과 후보 보고

검증 명령은 최소 `npm run check`, `npm run build`, 콘텐츠 감사 스크립트 실행을 포함한다.

## 11. Git 처리

- 현재 작업 트리에 존재하는 사용자의 2과목 변경은 수정·복원·커밋하지 않는다.
- 이 작업에서 변경한 파일만 명시적으로 스테이징한다.
- 구현과 검증이 모두 끝난 후 하나 이상의 의미 있는 커밋으로 정리한다.
- 원격 상태와 브랜치를 확인하고 비파괴적인 방식으로 `main`에 푸시한다.
- 원격 변경으로 푸시가 거부되면 강제 푸시하지 않고 중단 사유를 보고한다.

## 12. 제외 범위

- 제공 이미지 파일 자체를 저장하거나 재배포하지 않는다.
- 원본 교재의 페이지 번호·디자인·로고를 복제하지 않는다.
- 이번 사이클에서 2~8과목의 모든 개별 노트를 전면 재작성하지 않는다.
- 출처를 확인하지 못한 항목을 공식 기출로 승격하지 않는다.
